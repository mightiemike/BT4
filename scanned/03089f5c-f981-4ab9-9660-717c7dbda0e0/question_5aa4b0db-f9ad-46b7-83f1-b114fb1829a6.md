Preconditions: parent tenure has 3+ Nakamoto blocks; attacker's new tenure-start block sets `parent_block_id` to the LAST block of the parent tenure (correct) but the query path must specifically walk back to the tenure's founding VRF proof, not any cached intermediate value. Equality: proof returned by `get_parent_vrf_proof(chainstate_conn, parent_block_id, ...)` == the VRF proof from the parent TENURE's founding coinbase, invariant to how many blocks are appended after it. Impact: Critical if two nodes at different sync depths (one having only the tenure-founding block indexed, another having all blocks) compute different proofs for the same `parent_block_id`, causing STATE ROOT/tenure verdict divergence.
