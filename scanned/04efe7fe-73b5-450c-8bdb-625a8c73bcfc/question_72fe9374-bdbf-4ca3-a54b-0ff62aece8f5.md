[shadow.rs -> NakamotoBlockHeader::is_shadow_block_version] An unprivileged miner submits a normal (non-shadow) Nakamoto block over P2P/RPC whose header.version byte has the high bit (0x80) set, matching is_shadow_block_version's `version & 0x80 != 0` test. Preconditions: attacker has won or forged a valid-looking tenure at some burn height; tip is a normal (non-shadow) tenure. Call sequence: is_shadow_block() -> true -> validate_shadow_against_burnchain() is invoked instead of the normal path, which explicitly skips VRF-proof and miner-signature verification ('unlike normal blocks, we do not need to verify the VRF proof or miner signature'). Equality broken: VRF-winner-on-node-A == VRF-winner-on-node-B is never checked, so a block lacking a valid VRF proof/miner sig can pass validate_shadow_against_burnchain if downstream gating (has_shadow_nakamoto_block_with_index_hash) is not actually reached first. Impact: Critical - a block accepted that should be invalid, network-wide state divergence. Proof idea: Rust integration test booting a chainstate, submitting a block with version|=0x80 and a bogus/absent VRF proof through the normal block-acceptance entrypoint, asserting it is rejected (not merely deferred to the shadow path) and comparing node A/B verdicts.
