[shadow.rs -> NakamotoChainState::validate_shadow_parent_burnchain] Validates block_commit.parent_vtxindex == 0 and u64::from(block_commit.parent_block_ptr) == parent_sn.block_height only when the parent header is a shadow block. Attacker action: submit their own block-commit (fully attacker-controlled fields: vtxindex, parent_vtxindex, parent_block_ptr) that sets parent_vtxindex=0 and parent_block_ptr to an unrelated but numerically matching non-parent sortition's block_height, then submit a Nakamoto block whose parent_block_id points at a shadow-tenure block. Preconditions: at least one shadow tenure with a known block_height exists on-chain; attacker mines/wins a sortition later at the same block_height coincidentally (or crafts parent_block_ptr = that height regardless of true ancestry). Call sequence: validate_shadow_parent_burnchain only checks the numeric height equality, not the specific consensus_hash of parent_sn's neighbors, so any block-commit at a matching height passes even if it does not truly descend from that exact shadow tenure. Equality broken: tenure-of-block == tenure-authorized-by-block's-own-sortition (a numeric height match is substituted for full ancestry proof). Impact: Critical - a block accepted whose tenure lineage does not match its authorizing sortition, enabling a chain split. Proof idea: integration test with two distinct sortitions sharing (by construction) the same block_height value in a regtest burnchain fork, crafting a block-commit that mismatches consensus_hash but matches height, and asserting validate_shadow_parent_burnchain incorrectly returns Ok(()).
