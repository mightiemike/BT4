Preconditions: council previously signed and had inserted `(H, M_old)`; council later intends `(H, M_new)` to supersede at the same L2 height via a different transaction; attacker has captured the original `(H, M_old)` signed body. Call sequence: `run_l1_block` -> `batch_proof_method_id.body.activation_l2_height (H) <= last_activation_height` — if `last_activation_height` is still `< H` (M_new not yet applied), attacker's replay of `(H, M_old)` is accepted first via `verify_method_id_security_council` (still valid signatures) -> `BatchProofMethodIdAccessor::insert(H, M_old, ...)` sets `last_activation_height = H`; the later-arriving `(H, M_new)` now fails `H <= H`. Binding: the method id in the accessor at height H == the last one the council intended for H, but replay of an old still-valid signature set lets the attacker lock in `M_old` and make `M_new` permanently unappliable at H. Impact: Critical, a true council-intended upgrade at height H becomes permanently unprovable.
