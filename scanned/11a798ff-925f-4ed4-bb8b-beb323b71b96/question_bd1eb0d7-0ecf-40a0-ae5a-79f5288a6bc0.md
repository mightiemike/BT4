Target: `NakamotoStagingBlocksConnRef::get_shadow_tenure_start_block` and `is_shadow_tenure` (stackslib/src/chainstate/nakamoto/shadow.rs). Attacker action: submit two staging blocks for the same `consensus_hash` — one via the normal download path (`NakamotoBlockObtainMethod::Downloaded`) and one via a crafted shadow-header block claiming the same tenure — racing which lands first in `nakamoto_staging_blocks` on two different nodes. Preconditions: an as-yet-empty tenure consensus hash (no blocks staged for it on either node). Call sequence: `store_block`'s check `is_shadow_tenure(consensus_hash)? && !block.is_shadow_block()` only rejects a normal block if a shadow block is *already* stored; if the normal block lands first on node A and the shadow block lands first on node B, both blocks pass their respective node's gate. Equality that breaks: the accepted block for a given `consensus_hash` tenure on node A (normal block) == accepted block on node B (shadow block) — an ordering-dependent tenure classification. Impact: Critical — a shadow block promoted into the canonical chain on one node while a normal block is canonical on another is a permanent chain split with irreconcilable state roots. Proof idea: two-node harness: submit the shadow block to node A first and the normal block to node B first for the identical fresh consensus hash, and assert both nodes converge to the same accepted block type after full sync (not two different tenure histories).
