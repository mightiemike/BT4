Target: `verify_system_tx` (crates/evm/src/evm/executor.rs). Attacker action: send a non-system-signer EVM transaction whose `input()` first 4 bytes equal `BitcoinLightClientContract::setBlockInfoCall::SELECTOR` but which is submitted as an ordinary user transaction rather than a genuine `SYSTEM_SIGNER` call, hoping `verify_system_tx` is invoked on it during block processing regardless of sender. Preconditions: sequencer or full node executing `L2Block` module call path that reaches `verify_system_tx` for any tx matching the selector, not gated by sender identity within this function itself. Call sequence: `verify_system_tx` decodes `BitcoinLightClientContract::setBlockInfoCall`, fetches `(last_l1_height, prev_hash)` via `get_last_l1_height_and_hash_in_light_client`, and calls `shp_provider.get_and_verify_short_header_proof_by_l1_hash`; if the caller-authority check for `setBlockInfo` (that it is a genuine `SYSTEM_SIGNER`-only call) lives elsewhere and is bypassable, an attacker-supplied `_blockHash`/`_witnessRoot`/`_coinbaseDepth` could still pass short-header verification for an unrelated but real L1 block, advancing the light client's `next_l1_height` counter out of turn. Binding: the caller of `setBlockInfoCall` accepted by the contract == `SYSTEM_SIGNER`, the sole authority for `AUTHORITY`. Impact: Critical — an unauthorised advance of the light client's L1 height/hash chain corrupts the anchor all future batch proofs rely on. Proof idea: cargo test in evm/src/tests/sys_tx_tests.rs sending a `setBlockInfoCall`-selector transaction from a non-system signer address through the full L2 block-processing path and asserting the transaction is rejected before `verify_system_tx` even runs, or if it is not, that `get_last_l1_height_and_hash_in_light_client` state is unchanged.
