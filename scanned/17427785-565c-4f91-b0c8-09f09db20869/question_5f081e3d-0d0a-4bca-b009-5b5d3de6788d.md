Target: `TxInfo::l1_fee` field marked `#[allow(unused)]` (crates/evm/src/evm/handler.rs:92-96) vs its actual use later in `CitreaHandler::output` (`evm.ctx().chain().set_tx_info(TxInfo { l1_diff_size: diff_size, l1_fee })`) and consumption in `crates/evm/src/call.rs` where only `tx_info.l1_diff_size` is read (line 117), never `tx_info.l1_fee`. Attacker action: none required to trigger the field mismatch itself, but an attacker can exploit any future divergence between the `l1_fee` value set in `TxInfo` (computed as `U256::from(l1_fee_rate) * U256::from(diff_size)` at execution time inside `output`) and the `l1_fee` the receipt/API surfaces to users via `eth_getTransactionReceipt`'s `l1FeeRate`/`l1DiffSize` fields (per `test_get_transaction_receipt` in bin/citrea tests) which are recomputed from `l1_diff_size * block.l1_fee_rate` rather than stored `TxInfo::l1_fee` directly, by sending a transaction at a block boundary where `l1_fee_rate` changes between simulation/execution and the value read back by RPC. Preconditions: sequential L2 blocks with differing `l1_fee_rate` (set via Bitcoin Light Client system tx). Call sequence: `CitreaHandler::output` sets `TxInfo::l1_fee` using the *current* block's `l1_fee_rate`; only `l1_diff_size` propagates into the persisted receipt; RPC layer independently recomputes fee as `l1_diff_size * l1_fee_rate_of_block`. Binding: `l1_diff_size * l1_fee_rate` recomputed at query time by any client == the actual `l1_fee` amount debited from the caller's balance via `decrease_caller_balance` during that transaction's execution. Impact: Critical if these diverge, since it means the amount of cBTC actually moved out of a user's account (visible to `ProverStorage`/state root) doesn't match what the receipt / any downstream fee-accounting party (including a claim within `BatchProofCircuitOutput` about total L1 fees collected, if computed from receipts rather than replaying `decrease_caller_balance`) reports. Proof idea: cargo test executing a tx, capturing debited caller balance via `account_info`, comparing against `receipt.l1_diff_size * block.l1_fee_rate`, asserting exact equality across a fee-rate change between two blocks.
