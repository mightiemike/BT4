Target: handle_poison_microblock (stackslib/src/chainstate/stacks/db/transactions.rs). Attacker action: an unprivileged participant submits two PoisonMicroblock transactions in the same block from different senders, each claiming a different (mblock_header_1.sequence) for the same pubkh, relying on 'if mblock_header_1.sequence < seq' to determine which report wins, when both transactions are processed within the same Clarity block execution and thus read get_microblock_poison_report before either write commits (a classic same-block read-your-own-write ordering hazard). Preconditions: microblock pubkey hash height within MINER_REWARD_MATURITY of current height; two poison reports submitted in the same block with different tx ordering possible depending on mempool/mining choice (attacker cannot control final order but can submit both). Call sequence: handle_poison_microblock processes tx #1 (no prior report) inserts (sender1, seq1); tx #2 in the same block reads the just-inserted report and compares seq2 to seq1. Equality that breaks: the winning (reporter, sequence) recorded in get_poison_microblock_report(height) must be identical regardless of which of two valid orderings a miner chooses to include the transactions in - if the eventual coinbase-commission recipient differs by tx-inclusion order between two miners' otherwise-equally-valid blocks, reward-paid depends on miner choice rather than a canonical rule, and two competing blocks both 'valid' pay different parties. Impact: High (bounded to the poison-commission fraction of one coinbase, not the whole reward) - reward mis-payment bounded to a single tenure's coinbase fraction, with a chain-split risk only if the two orderings are both signable and one is later orphaned. Proof idea: integration test submitting two conflicting poison reports for the same pubkh in a single block on two different miner orderings, asserting resulting recipient/sequence is a deterministic function of transaction order that all nodes replay identically (not merely that some order wins).
