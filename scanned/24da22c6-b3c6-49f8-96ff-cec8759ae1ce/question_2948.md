# Q2948: accrue-and-cache via collateral-remove-redeem: absorb a sub-step failure into a fold flag and proceed on 

## Question
Does `collateral-remove-redeem` (mainnet/contracts/market/v0-4-market.clar:1211) let an unprivileged attacker who controls `amount` used for BOTH the collateral removal and the share redemption reach `accrue-and-cache` (mainnet/contracts/market/v0-4-market.clar:245) in a state where it absorb a sub-step failure into a fold flag and proceed on partial state? Given that it keys `index-cache` on `{timestamp: stacks-block-time, aid}` and returns the cached record forever after, with no invalidation when the vault later moves, the invariant that when a multi-step entry point aborts, no value is stranded and no identifier survives breaks and the result is protocol insolvency through uncollateralised debt.
