## Question

Given that it pulls the underlying from a named account, the invariant that when a multi-step entry point aborts, no value is stranded and no identifier survives breaks and the result is permanent freezing of a position that can never be closed.

- Exploit idea: `receive-underlying` pulls the underlying from a named account. Reach it through `liquidate-redeem` and pass a health check and then change, in the same transaction, the quantity it checked.
