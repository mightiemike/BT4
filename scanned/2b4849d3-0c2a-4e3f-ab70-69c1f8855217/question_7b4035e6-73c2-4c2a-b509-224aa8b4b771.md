Target: `verify_system_tx` (crates/evm/src/evm/executor.rs) selector check `function_selector == BitcoinLightClientContract::setBlockInfoCall::SELECTOR`. Attacker action: send an ordinary EVM transaction to the `BitcoinLightClientContract` address whose first 4 input bytes accidentally or deliberately collide with `setBlockInfoCall::SELECTOR` (any unprivileged caller can craft arbitrary calldata to any address). Preconditions: attacker is not `SYSTEM_SIGNER`, transaction admitted as a normal user tx (not a system tx slot) but routed through the same `verify_system_tx` gate if that gate is reachable for non-system-signer calls. Call sequence: `verify_system_tx` decodes `_blockHash`, `_witnessRoot`, `_coinbaseDepth` from attacker-controlled calldata -> calls `shp_provider.get_and_verify_short_header_proof_by_l1_hash` with attacker-chosen `l1_block_hash`. Binding: the `l1_block_hash` value that ends up recorded via `take_last_queried_hash` (later reported as `last_l1_hash_on_bitcoin_light_client_contract`) == a hash genuinely produced by `setBlockInfoCall::SELECTOR` invoked by the true `SYSTEM_SIGNER`. Impact: Critical, if `verify_system_tx` is reachable for non-system-signer senders, an unprivileged attacker can inject an arbitrary `l1_block_hash` query that, if it happens to match a queued short header proof, gets recorded as the queried/verified hash, corrupting the batch proof's L1 anchor -> AUTHORITY and PROOF_SOUNDNESS break. Proof idea: cargo test in crates/evm/src/tests/sys_tx_tests.rs sending a `setBlockInfoCall`-selector-prefixed transaction from a non-`SYSTEM_SIGNER` address and asserting it is rejected before reaching `get_and_verify_short_header_proof_by_l1_hash`.
