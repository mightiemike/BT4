Can an unprivileged attacker submit a block whose `signer_signature` vector contains two distinct raw signature byte strings that both recover (via `Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s`) to the SAME compressed public key (e.g. by negating S per the `test_high_s_single_signature` low-S non-enforcement), such that `total_weight_signed` sums `signer.weight` twice for one signer? Impact: Critical — if achieved, a block reaches `threshold` with fewer than the real distinct-signer weight, i.e. `total_weight_signed >= threshold` while true distinct weight < threshold, causing acceptance of an under-signed block network-wide.
