Target: get_pending_block_env (crates/evm/src/query.rs) used only for RPC preview (eth_call, eth_estimateGas, mempool admission via simulate_tx_l1_fee) versus the actual block_env passed into Evm::execute_call during real block production, both ultimately keyed off the same EvmChainConfig::base_fee_params set at genesis. Attacker action: submit a transaction via eth_sendRawTransaction timed so that get_pending_block_env's heuristic `time_diff` (assume timestamp will increment the same between last block and the one before that) mispredicts the actual timestamp the sequencer uses for block N+1, causing calculate_next_block_base_fee to diverge between the RPC-estimated base fee and the block's real base_fee_per_gas. Preconditions: sequencer under variable block-time load so consecutive L2 blocks have non-uniform time gaps. Call sequence: CitreaTransactionValidator::validate_transaction -> simulate_tx_l1_fee -> get_pending_block_env computes block_env.basefee via calculate_next_block_base_fee using a *guessed* timestamp; this basefee is only used to decide mempool admission (Overdraft check), never written to the committed chain. Binding: this specific value never enters the committed ReadWriteLog, so it cannot break ProverStorage/ZkStorage root equality by itself; the binding tested here is that the *real* block's base_fee_per_gas set in Header (as read from EvmChainConfig::base_fee_params and prior block header, deterministic function of chain history only) computed natively == computed in the circuit. Impact: High - an attacker cannot move funds via this path since it only affects the best-effort mempool admission heuristic (explicitly documented as best-effort in tx_validator.rs), but a mispriced admission-time estimate could reject transactions from honest users, which is out of scope (DoS excluded) -- however if any code path mistakenly persisted the pending/estimated base fee into committed state instead of the real header base_fee_per_gas, that would break EXECUTION AGREEMENT. Proof idea: cargo test asserting Header::base_fee_per_gas committed for L2 block N depends only on Header::base_fee_per_gas, gas_used, gas_limit of block N-1 (calculate_next_block_base_fee inputs), and never on get_pending_block_env's heuristic time_diff, by fuzzing block timestamps and confirming committed base fee is a pure deterministic function of prior header.
