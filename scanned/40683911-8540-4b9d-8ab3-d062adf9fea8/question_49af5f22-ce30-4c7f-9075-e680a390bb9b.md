Preconditions: attacker observes a valid moveTx broadcast/confirmed on Bitcoin (or its future light client inclusion) before the depositor or Clementine's aggregator submits it to the sequencer. Call sequence: attacker calls `citrea_sendRawDepositTransaction` first with the identical bytes -> `make_deposit_tx_from_data` + `eth_call` succeeds (any caller can submit any bytes) -> `add_deposit_tx` inserts attacker-submitted deposit into `accepted_deposit_txs` -> depositor's/aggregator's later identical submission returns `Ok(false)`. Binding: cBTC credited by the deposit == a Bitcoin-side deposit that actually happened, counted exactly once — the binding technically still holds (cBTC still credited to the correct recipient encoded in the moveTx witness since `from`/recipient is derived from moveTx contents, not the RPC caller), so this is not a custody break by itself, but demonstrates any unprivileged caller can be the one whose bytes occupy `pending_deposits`/get included, controlling *timing* and potential reordering ahead of other queued deposits. Impact: High, no fund loss, but establishes an unauthenticated race primitive over `fetch_deposits` FIFO ordering usable to amplify the poison-deposit head-of-line attacks in other questions.
