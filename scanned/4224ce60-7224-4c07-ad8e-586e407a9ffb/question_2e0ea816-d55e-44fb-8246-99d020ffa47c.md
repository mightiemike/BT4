Attacker action: none needed from an unprivileged party for construction (shadow blocks require tooling), but attacker submits a *normal* NakamotoBlock whose `parent_block_id` claims to descend from a shadow block while supplying a block-commit with nonzero `parent_vtxindex`. Impact: Critical — a bug in this parity check that some nodes evaluate differently (e.g. because they haven't yet loaded the shadow tenure's `NakamotoStagingBlocksConnRef`) rejects a valid block on one node while another accepts it, splitting the network. Proof idea: two-node test where one node has the shadow block loaded before validating the child and the other doesn't yet; assert both reach the same Ok/Err verdict.
