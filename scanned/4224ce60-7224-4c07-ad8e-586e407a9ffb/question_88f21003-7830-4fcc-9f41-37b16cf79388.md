Target: `NakamotoChainState::append_block` VRF-proof check via `check_block_commit_vrf_seed` (scope: staged block descends from invalid/unavailable parent). Attacker action: submit a tenure-start block whose VRF proof is valid for the block-commit's seed but whose *parent* block-commit (used to derive the expected seed) is unavailable on one node (still downloading) while cached on another. Preconditions: parent tenure block-commit exists on Bitcoin but hasn't fully synced everywhere. Call sequence: `append_block` -> `is_new_tenure` branch -> `check_block_commit_vrf_seed`. Equality: VRF-seed verification verdict using recomputed seed == verdict on every node once each has the same block-commit data (i.e., must not silently accept when parent commit is missing). Impact: Critical — a node that accepts B before verifying VRF-seed continuity against the true parent, and a node that rejects because it can't yet fetch the parent commit, disagree on B's validity, producing a temporary/permanent tip mismatch. Proof idea: integration test delaying delivery of the parent block-commit to node B only, submitting B to both nodes, and asserting reject-until-available rather than divergent accept.
