Target: `TxInfo::l1_fee` (`crates/evm/src/evm/handler.rs`) set via `CitreaChainExt::set_tx_info` and consumed by mempool-admission `Evm::simulate_tx_l1_fee`, but the *actual* enforcement/deduction happens later in `CitreaHandler::output`'s `decrease_caller_balance(evm.ctx(), l1_fee)`. Attacker action: send an EVM transaction whose execution result depends on account balance mutation ordering, e.g. one that reads its own balance mid-execution via a `SELFBALANCE`/`BALANCE` opcode within the same transaction after a nested call that spends gas, right after the L1 fee has already been speculatively simulated with `l1_fee_rate = 0` in `simulate_tx_l1_fee`. Preconditions: attacker's contract branches its logic on `address(this).balance` such that the branch taken with a zero L1 fee differs from the branch taken with the real `l1_fee_rate` applied post-execution. Call sequence: `CitreaTransactionValidator::validate_transaction` -> `simulate_tx_l1_fee` (rate=0, only for admission decision) -> tx admitted -> later, real execution passes through `sealed_block_to_block_env`'s real `l1_fee_rate` -> `CitreaHandler::output` deducts real `l1_fee` from caller *after* the frame result is already computed, so `SELFBALANCE` reads during execution never see the L1 fee deduction. Binding: the `ResultAndState` (specifically any state read depending on caller balance) computed natively for L2 block N == the `ResultAndState` computed in the guest replay of L2 block N, given the L1 fee is deducted strictly post-frame in both cases. Scoped impact: Critical, EXECUTION_AGREEMENT - since both native and circuit deduct `l1_fee` identically post-frame via the same `CitreaHandler::output` code path, this specific vector is *not* exploitable, but confirms the invariant that no in-frame opcode ever observes the fee before it's charged; a regression that moved the deduction earlier (pre-frame) while only fixing one of native/circuit would break this. Proof idea: cargo test deploying a contract that logs `SELFBALANCE` before and after a `CALL`, asserting the recorded value is bit-identical whether obtained from native execution or replayed via `ZkStorage`+witness.
