LruCache::evict_lru (stacks-common/src/util/lru_cache.rs) removes node.key from self.cache via self.cache.remove(&node.key) but returns Ok(self.capacity) as a no-op sentinel when the list is empty (index == self.capacity), which is indistinguishable from evicting index 0 == capacity by coincidence only when capacity==0, guarded against in LruCache::new. However insert_with_dirty's capacity branch always calls evict_lru and unconditionally treats its Ok(index) as a valid reusable node without checking it isn't the sentinel; if self.cache.len() == self.capacity is true while self.tail == self.capacity (structural corruption from an unbalanced attach_as_head/detach_node sequence), tail_node = self.order.get_mut(index) mutates the wrong node, silently corrupting an unrelated cached (key,value). Equality: cache.get(key) after this sequence == the value last legitimately insert_with_dirty'd for that key. Impact: Critical if this occurs in a hypothetical consensus-critical cache (e.g., sortition winner memoization keyed by burn block hash) — node A serves a corrupted stale winner while node B recomputes fresh, breaking SORTITION winner == deterministic burn-weight/VRF winner across nodes.
