Function: transactions.rs transaction processing entrypoint that writes STX balances/nonces keyed by principal, feeding MARF::insert via clarity_vm marf.rs. Attacker action: submit a StacksTransaction whose sender PrincipalData serializes to a MARF key string ambiguous with another principal's key (e.g., contract-principal vs standard-principal string collision in the key-hashing scheme). Preconditions: booted chainstate at some tip, attacker controls only their own account. Call sequence: process_transaction -> key construction for account nonce/balance -> TrieHash::from_key -> MARF::insert_leaf -> commit -> root computed. Equality: the (key,value) pair actually committed under root R == the (key,value) pair produced when any honest node reconstructs the trie path from the same principal encoding. Impact: Critical -- a trie path collision from ambiguous key encoding causes divergent root computation across nodes, i.e., a state root not reproducible. Proof idea: integration test constructing two distinct principals whose to_string()/serialization forms hash to the same TrieHash path, insert both in one block, assert two independent MARF instances produce identical roots and that get_by_key resolves the correct owner's balance, not the colliding one.
