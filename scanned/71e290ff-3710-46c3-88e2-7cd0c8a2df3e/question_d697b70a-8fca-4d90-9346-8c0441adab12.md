Target: `NakamotoBlock::validate_transactions_static`'s `self.txs.is_empty()` guard versus `StacksBlock::validate_transactions_unique(&self.txs)`. Attacker action: submit a block containing two byte-identical transactions (same txid) crafted so that a node's mempool-level deduplication (unrelated data structure) has already dropped one copy on relay ingestion for node A but not for node B before the block-level `validate_transactions_unique` check runs, if any code path constructs `self.txs` from a node-local, previously-seen-transaction cache rather than strictly from the block's wire bytes. Preconditions: block gossip via P2P push; nodes with different local mempool/dedup states. Call sequence: `NakamotoBlock` deserialization -> `validate_transactions_static` -> `StacksBlock::validate_transactions_unique(&self.txs)`. Equality broken: `self.txs` as validated by `validate_transactions_unique` on node A == `self.txs` as validated on node B, both required to be exactly the block's wire-encoded transaction list with no node-local substitution. Impact: Critical -- if `self.txs` is ever built from anything other than the raw deserialized block bytes, `validate_transactions_unique`'s verdict becomes node-local, producing a chain split when a duplicate-tx block is accepted by one node and rejected by another. Proof idea: integration test that deserializes the exact same block bytes independently on two chainstate instances (no shared mempool) and asserts `block.txs` and `validate_transactions_static` results are bit-for-bit identical, i.e. `block.txs == block.txs` structurally is the only input, never touching a mempool cache.
