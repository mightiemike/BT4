Target: `NakamotoChainState::check_tenure_continuity` invoked from `append_block` (stackslib/src/chainstate/nakamoto/mod.rs) for non-tenure-start blocks. Attacker action: attacker who won a single sortition mines two conflicting continuation blocks within the same tenure at the same chain_length but with different tx sets, getting each signed by disjoint minority signer subsets, and relays them to different halves of the network. Preconditions: attacker is the legitimate tenure's miner (a minority position, one miner slot). Call sequence: accept_block (no is_new_tenure) -> check_tenure_continuity (chainstate_tx, parent_ch, header) -> append_block chain_length equality check. Equality that breaks: the accepted continuation block on nodeA == the accepted continuation block on nodeB for the same (consensus_hash, chain_length) pair, since `store_block_if_better` will keep whichever variant first reaches sufficient (or merely first-seen equal) signing_weight per node. Scoped impact: Critical, a chain split within a single tenure caused solely by a rogue-but-legitimately-selected miner double-mining without needing majority signers. Proof idea: two-node test where the same miner produces two same-height children with distinct minority-signed sets, deliver A-then-B to node1 and B-then-A to node2, assert `get_nakamoto_tip_block_id` differs.
