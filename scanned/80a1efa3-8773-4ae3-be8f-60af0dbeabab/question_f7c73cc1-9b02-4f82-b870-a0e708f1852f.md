Target: `NakamotoStagingBlocksConnRef::is_burn_block_processed` / `set_burn_block_processed` denormalization (stackslib/src/chainstate/nakamoto/staging_blocks.rs). Attacker action: attacker submits a block for a consensus_hash whose burn block is marked `burn_attachable=1` on node A (because node A processed the burn block earlier) but not yet on node B, then quickly follows with a child block that depends on the parent being burn_attachable to be marked attachable itself. Preconditions: nodes differ in which burn blocks they've processed by at least one block, a routine but attacker-exploitable timing gap. Call sequence: store_block -> `is_burn_block_processed` -> sets `burn_attachable` on insert -> `set_block_processed`'s cascading `UPDATE ... SET burn_attachable=1 WHERE parent_block_id=?` for children. Equality that breaks: the set of attachable blocks on node A == the set of attachable blocks on node B for the identical staged block set, since attachability is a per-node denormalized flag driven by each node's independent burn-block processing order. Scoped impact: High, temporary tip disagreement (staging-only, resolves once both nodes process the same burn blocks) unless a downstream reward-maturity decision is made off the transiently-attachable state, in which case Critical. Proof idea: two-node test delaying burn-block relay to node B, submit parent+child Nakamoto blocks to both, and assert `find_next_staging_block`-equivalent candidate sets differ transiently, then re-converge; verify no reward matured during the divergent window.
