Target: `CitreaCallExt::is_system_caller` in crates/evm/src/evm/handler.rs, which checks `SYSTEM_SIGNER == self.ctx_ref().tx().caller()`. Attacker action: submit a normal EIP-1559 EVM transaction via `eth_sendRawTransaction` whose ECDSA signature happens to be `PrimitiveSignature::new(U256::ZERO, U256::ZERO, false)` (the `SYSTEM_SIGNATURE` constant), so that `Recovered<TransactionSigned>::try_from` in crates/evm/src/evm/conversions.rs maps it to `SYSTEM_SIGNER` via `Self::new_unchecked(tx, SYSTEM_SIGNER)`. Preconditions: public sequencer RPC accepting raw transactions, no r/s-nonzero signature validation before this check. Call sequence: RPC decode -> `TryFrom<RlpEvmTransaction> for Recovered<TransactionSigned>` -> `evm.is_system_caller()` returns true in `CitreaHandler::validate_tx_against_state`/`deduct_caller`/`output`. Binding: caller field the code treats as SYSTEM_SIGNER == the party who actually holds the SYSTEM_SIGNER private key (should never be true for user-submitted signatures). Impact: Critical - an ordinary attacker escapes L1 fee and base fee deduction (CUSTODY equality: fees paid by tx senders == fees credited to vaults breaks) by mimicking the zero signature.
