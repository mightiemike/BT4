Target: `NakamotoStagingBlocksConnRef::get_shadow_tenure_start_block` (stackslib/src/chainstate/nakamoto/shadow.rs). Attacker action: submit a normal Nakamoto block whose `parent_block_id` points at a shadow tenure's *non-final* block (not the one returned by `ORDER BY height DESC LIMIT 1`), attempting to fork off a shadow tenure at a lower height than the recognized shadow tenure tip. Preconditions: shadow tenure has multiple staged blocks (unusual but structurally possible since shadow blocks are inserted per-height); attacker references an earlier one as parent. Call sequence: `validate_shadow_parent_burnchain` only checks that `parent_header.is_shadow_block()` is true and validates block-commit `parent_vtxindex`/`parent_block_ptr` against `parent_sn` derived from `parent_header.consensus_hash` -- it does not verify the parent is the *tenure-final* shadow block via `get_shadow_tenure_start_block`. Equality that must hold: the parent shadow block referenced by a new normal block == the unique canonical (highest) shadow block of that tenure on every node. Scoped impact: Critical if two attacker-submitted normal children can each legally reference a different non-final shadow block as parent, since both would separately pass `validate_shadow_parent_burnchain`, letting two nodes select different children as canonical depending on which they process first. Proof idea: integration test staging two normal blocks with `parent_block_id` pointing at two different shadow-tenure heights, assert only the one referencing the true tenure-tip shadow block (per `get_shadow_tenure_start_block`) is ever treated as canonical, identically on all nodes.
