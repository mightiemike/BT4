# Q0298: calc-liq-factor-exp via liquidate-multi: reuse one price and index snapshot across a batch that mut

## Question
Entering through `liquidate-multi` (mainnet/contracts/market/v0-4-market.clar:1593) while controlling how many entries share one price snapshot (price-feeds is passed as none), can an unprivileged attacker make `calc-liq-factor-exp` (mainnet/contracts/market/v0-4-market.clar:708) reuse one price and index snapshot across a batch that mutates state between entries? `calc-liq-factor-exp` uses `(/ exp BPS)` as an integer exponent for `pow` and falls back to `sqrti` below BPS, so the invariant that every second of elapsed time is charged exactly once, to one index, in one direction would fail, yielding direct theft of user funds at rest or in motion.

- Entrypoint: `liquidate-multi` (`mainnet/contracts/market/v0-4-market.clar:1593`), unprivileged and publicly callable

- Exploit idea: `calc-liq-factor-exp` uses `(/ exp BPS)` as an integer exponent for `pow` and falls back to `sqrti` below BPS. Reach it through `liquidate-multi` and reuse one price and index snapshot across a batch that mutates state between entries.

- Expected Immunefi impact: Critical - direct theft of user funds at rest or in motion
