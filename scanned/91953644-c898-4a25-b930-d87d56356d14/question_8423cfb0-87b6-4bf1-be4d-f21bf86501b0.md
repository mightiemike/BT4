Target: `ChunkAccessor::insert`/`get` (accessors.rs). Attacker action: inscribe a Bitcoin transaction (reveal-prefixed) whose payload is a legitimate-looking proof chunk, with a wtxid that the light-client's aggregation logic will later look up when reconstructing an aggregated batch proof. Preconditions: attacker can freely choose the content (and thus wtxid) of their own inscribed tx; light-client-prover indexes exclusively by wtxid with no separate authenticity check inside this accessor. Call sequence: `ChunkAccessor::insert(wtxid, body, ws)` stores attacker body under attacker-chosen wtxid; if the downstream aggregator locates chunks by a derived reference rather than strictly verifying provenance of `wtxid`, attacker chunk gets spliced into an aggregated proof reconstruction. Binding: the chunk set retrieved via `ChunkAccessor::get` for an aggregated proof == the exact chunk set the batch prover published on Bitcoin for that proof, in the same content. Impact: Critical — DA-integrity violation, injecting attacker-controlled bytes into a proof-aggregation blob set that honest full nodes act on differently. Proof idea: cargo test inserting an attacker chunk under a wtxid distinct from the legitimate one and asserting the light-client circuit's aggregation logic rejects it (fails to match the real batch proof's structure/hash) rather than silently accepting a partial or substituted proof body.
