Target: `CitreaSequencer::calculate_txs_merkle_root` / `compute_tx_hashes` (runner.rs) applied uniformly to system and user transactions in `signed_txs`. Attacker action: submit an EVM transaction with an oversized or specially crafted payload designed to produce an RLP encoding that collides (under the merkle root's hashing scheme) with the encoding of a system transaction produced by `signed_system_transaction`, aiming to have `compute_tx_merkle_root` accept a substituted transaction list without changing the header's `tx_merkle_root`. Preconditions: attacker controls arbitrary transaction bytes via `eth_sendRawTransaction`. Call sequence: `encode_and_sign_evm_txs_into_sov_txs` batches all `txs_to_run` (including prior system txs already applied) into one `CallMessage`/blob -> `calculate_txs_merkle_root(&signed_txs, ...)` hashes the *outer* sov-sdk transactions (one blob for system txs, one for user txs), not each inner EVM tx individually. Binding: the `tx_merkle_root` stored in the committed `L2Header` == `compute_tx_merkle_root` of the exact `signed_txs` vector that was passed to `stf.apply_l2_block_txs` and whose execution produced `l2_block_result`, with no reordering or substitution between hashing and application. Impact: Critical - a mismatch would let a full node re-executing the block observe a different transaction set than what the header commits to, splitting honest nodes on the resulting state root (EXECUTION AGREEMENT binding), and could hide an unauthorized mint/withdrawal from proof verification. Proof idea: cargo test independently recomputing `compute_tx_merkle_root` from the transactions actually stored via `ledger_db.commit_l2_block` and asserting equality with the header's `tx_merkle_root` for a block containing both system and user transactions.
