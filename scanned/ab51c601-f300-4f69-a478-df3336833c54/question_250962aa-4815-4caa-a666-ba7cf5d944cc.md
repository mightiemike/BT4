Target: `TriePtr.back_block` semantics (node.rs) overloaded for both real backpointers (`is_backptr(id)`) and squash annotations (inline ptr with nonzero back_block, `set_inline_back_block`). Attacker action: none needed from an external attacker's block content, but a node operator running the (in-scope) squash feature could, through ordinary chain replay via `node_copy_update_ptrs`, misinterpret an inline squash-annotated `back_block` as a real backpointer during `write_consensus_bytes`, feeding the wrong 32-byte block hash into the hash instead of zero bytes. Preconditions: MARF has been squashed (`squash_to_path`) and later extended by ordinary block processing. Call sequence: `TrieNode::write_consensus_bytes` -> `is_backptr(self.id())` branch decides zero-fill vs `get_block_hash_caching(self.back_block())`. Equality broken: `squash_root_node_hash/archival_marf_root_hash == root computed via MARF replay after squash+extend`. Impact: Critical — a node that squashes and one that stays archival compute different state roots for the same logical block, a chain split between squash-enabled and archival nodes. Proof idea: `test_deep_extension_hash_equality`-style test (already exists) but adversarially crafted with children whose `chr()` collides across the promotion boundary between Node48/Node256, asserting `archival.get_root_hash_at(bh) == squashed.get_root_hash_at(bh)` for every extension block.
