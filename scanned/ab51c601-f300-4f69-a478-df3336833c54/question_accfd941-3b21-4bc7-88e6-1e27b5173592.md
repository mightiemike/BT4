Target: `finalize_shared_blob_offsets`/`persist_squash_metadata` and `SquashInfo.archival_marf_root_hash` vs `squash_root_node_hash` (squash.rs, storage.rs). Attacker action: none from an external attacker (squashing is a local operator action) but this is in-scope as a mechanism that could make an operator's node diverge from an archival peer through ordinary use, since the file explicitly claims 'hash-preserving squash' and any bug here is a real chain-split vector once squash-enabled nodes reach majority use. Preconditions: an operator squashes at height H, then the node is queried for blocks at or below H via `getblockbyheight.rs` and its state root compared against a peer that never squashed. Call sequence: `MARF::squash_to_path` -> `remap_child_ptrs` rewrites `(block_id, offset)` to sequential indices and stores `back_block = block_id_map[child_block_id]` -> later `get_root_hash_at` for historical heights reads `archival_marf_root_hash`/`marf_squashed_blocks.marf_root_hash` from SQL rather than recomputing from the trie. Equality broken: `root read from marf_squashed_blocks for height H == root an archival node recomputes by replaying block H's trie`, which is only checked by test-only helper `read_root_to_block_table` and targeted unit tests, not by any runtime consensus check when serving `/v3/blocks/height/H`. Impact: Critical — if `remap_child_ptrs`' `source_to_idx` mapping ever collides or drops an entry silently (e.g. duplicate `(block_id, offset)` keys from a compressed vs uncompressed write), the squashed node serves/attests to a different `state_root` for the same historical block than an archival peer, causing permanent, silent divergence for anyone relying on this RPC.
