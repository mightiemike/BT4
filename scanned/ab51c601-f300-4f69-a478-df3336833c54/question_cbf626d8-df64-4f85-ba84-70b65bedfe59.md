Target: `MARF::check_ancestor_block_hash` (marf.rs ~254-292), the fork-membership check that opens `bhh` then restores `cur_block_hash`. Attacker action: submit a block referencing a parent via `bhh` that is genuinely on a different fork but whose height and `get_block_at_height`-resolved hash momentarily match due to a race between two concurrent calls to `check_ancestor_block_hash` on a shared connection (the function does `conn.open_block(bhh)` then unconditionally restores `cur_block_hash`, but if this connection is shared and reentered — e.g. via a nested Clarity `contract-call?` chain triggering another MARF read — the restore could target the wrong tip). Preconditions: nested/reentrant MARF reads within a single block's transaction processing that share one `TrieStorageConnection`. Call sequence: `check_ancestor_block_hash` -> `MARF::get_block_height`/`get_block_at_height` -> compare `bhh != &actual_block_at_height` -> `Err(NonMatchingForks)` on failure, else `conn.open_block(bhh)` test-open then restore. Equality broken: `the block the connection is left pointing to after check_ancestor_block_hash == cur_block_hash captured at entry`, which if violated by reentrancy would leave the connection open to the wrong block for the *next* caller's hash computation, corrupting that caller's root. Impact: Critical if reentrancy is reachable (a single node then computes an internally-inconsistent root for one block while another node, without the race, computes the correct root). Proof idea: multi-threaded/reentrant integration test invoking `check_ancestor_block_hash` from two logically nested calls sharing one connection and asserting `get_cur_block()` after both calls always equals the outer caller's original tip.
