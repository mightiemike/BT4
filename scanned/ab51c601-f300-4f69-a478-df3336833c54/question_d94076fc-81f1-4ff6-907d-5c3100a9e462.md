Target: `TrieCursor` / `MARF::node_child_copy` and `TrieCowPtr` (marf.rs ~778-835, node.rs). Attacker action: submit a block that triggers a copy-on-write of a deeply backpointer-chained node during `node_child_copy`, where `storage.open_block_maybe_id(&cur_block_hash, cur_block_id)` is called between reading the child from an ancestor block and writing it into the current block; craft transactions so the two `open_block_maybe_id` calls straddle a point where `storage`'s internal `cur_block_id` cache (`BlockHashCache`) could resolve to a *different* physical block ID than intended if two blocks happen to briefly share a `T::sentinel()`/default value during a re-org replay. Preconditions: a re-org replay path re-executes several blocks in sequence, reusing a single `TrieStorageConnection`. Call sequence: `node_child_copy` reads `child_node` at ancestor -> `storage.open_block_maybe_id(&cur_block_hash, cur_block_id)` restores context -> `node_copy_update` -> `storage.write_nodetype(child_array_ptr, &child_node, child_hash)`. Equality broken: `child_hash written == hash of the actual ancestor node identified by child_backptr`, not a stale node left over from a previous `open_block` call in the same connection during replay. Impact: Critical — a node that replays blocks during a reorg computes a different state root than a node that processed them fresh, causing that single node to diverge from the rest of the network on tip re-derivation. Proof idea: integration test that forces a chainstate reorg-replay (e.g. via `MARF::begin`/`commit` sequences interleaved with `open_block` calls simulating reorg unwind/rewind) and asserts the resulting root equals a from-scratch build of the same final block on a second, freshly opened MARF instance.
