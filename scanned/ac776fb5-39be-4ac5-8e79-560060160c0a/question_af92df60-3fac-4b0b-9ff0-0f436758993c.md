Target: `StacksChainState::calculate_miner_reward` (accounts.rs) poison-microblock branch coinbase punishment. An attacker files a PoisonMicroblock report but is also the `poison_reporter_opt` recipient while simultaneously being a `participant.miner` on the *same* block (self-report). Preconditions: attacker mines a block and, in the same or later block, submits a PoisonMicroblock transaction naming themself (or a sybil-controlled address they still spend from) as reporter. Call sequence: in the punished branch, `(child_address, child_recipient, coinbase_reward, punished) = (reporter_address.clone(), reporter_address.to_account_principal(), poison_microblock_commission(coinbase_reward), true)`; there is no check that `reporter_address != participant.address`, so a miner can report their own forked microblocks to claim `poison_microblock_commission` on top of, or instead of, ordinary block rewards without losing net STX in a way consistent with the punishment's intent. Equality: total STX paid for a punished tenure == poison_microblock_commission(coinbase) once, paid to a party distinct from the offending miner; self-reporting collapses that distinction while still consuming the 'once' allotment, effectively giving the miner a choice to underpay other honest recipients. Impact: High (bounded to a single tenure's coinbase, not a state-root or fork break). Proof idea: integration test where the same principal is both block miner and PoisonMicroblock reporter, assert whether the code path allows this and what is actually credited to whom.
