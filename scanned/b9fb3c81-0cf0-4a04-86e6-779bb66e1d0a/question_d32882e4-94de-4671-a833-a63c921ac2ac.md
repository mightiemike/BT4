In NakamotoBlockHeader::verify_signer_signatures (stackslib/src/chainstate/nakamoto/mod.rs), signers_by_pk is built as a HashMap<PublicKey,(Signer,Index)> and each recovered public key is removed via signers_by_pk.remove(&public_key_bytes) before its weight is added to total_weight_signed. Can an unprivileged attacker who controls only their own signer key submit two distinct byte-level signatures (e.g. high-S vs low-S variants) that both recover to the *same* public key but are treated by recover_to_pubkey_without_validating_low_s as producing two different iterations, so that a single signer's weight is summed twice via total_weight_signed.checked_add(signer.weight), making total_weight_signed >= threshold when the distinct-signer weight actually held is below threshold? Equality broken: SIGNING - distinct valid signer weight on an accepted block >= threshold, from that cycle's reward set. Impact: Critical - a block accepted by one node's relayed copy and rejected as insufficient by a node that re-derives distinctness differently causes a chain split.
