Target: `MARF::do_insert_leaf`'s `update_skiplist` flag divergence (marf.rs 1184-1213) between `Trie::update_root_hash` and `Trie::update_root_node_hash`. Attacker action: submit a sequence of multiple stacking transactions within a single block so that all-but-the-last insert use `update_skiplist=false` (`update_root_node_hash`) while only the final insert uses `update_skiplist=true` (`update_root_hash`) — if any code path incorrectly toggles this flag for a non-final insert (e.g. due to a batching/heuristic optimization keyed off transaction count that differs between mining and validating nodes), the ancestor skiplist gets mixed in at the wrong point. Preconditions: block with >=2 MARF-touching transactions. Call sequence: `do_insert_leaf` -> `Trie::add_value` -> conditional `update_root_hash` vs `update_root_node_hash`. Equality broken: state root committed == state root every node recomputes. Impact: Critical — a mining node and a validating node disagreeing on which insert is 'final' (and thus which triggers skiplist mixing) commit/recompute different final roots for the identical block. Proof idea: integration test with a block containing exactly two independent MARF writes, verifying that both the miner's committed root and the validator's independently recomputed root are identical regardless of internal insert batching order.
