Target: `TrieMerkleProof::verify_segment_proof`'s `get_segment_proof_hash` (proofs.rs 927-938) for `Node4`/`Node16`/`Node48`/`Node256` variants. Attacker action: submit a proof for a `Node48` where the supplied `hashes` array has fewer entries than the node's actual arity (48) but the verifier's arity-aware reconstruction pads missing entries with `TrieHash::EMPTY`, allowing an attacker to substitute a real sibling's hash slot with the empty-hash default and still reach the correct parent hash if the omitted sibling itself happens to hash to `TrieHash::EMPTY` in the real trie (e.g. sibling never had a child written, an easily attacker-discoverable condition by probing a testnet-equivalent local chainstate). Preconditions: attacker needs a real committed `Node48`/`Node256` with at least one genuinely empty child slot adjacent to the target leaf. Call sequence: `verify_segment_proof` -> `get_segment_proof_hash(node, hash, chr, hashes, N)` reconstructing full child-hash array to feed `get_node_hash`. Equality broken: verifiable proof == (key, value) actually committed. Impact: High-to-Critical bounded to nodes with a genuinely-empty sibling slot — enables proof forgery for a decoy key sharing the parent with an empty slot. Proof idea: construct such a `Node48` in a test MARF, generate a legitimate proof, tamper with one non-empty-adjacent hash entry, and check whether `verify_proof` still accepts for a fabricated leaf value.
