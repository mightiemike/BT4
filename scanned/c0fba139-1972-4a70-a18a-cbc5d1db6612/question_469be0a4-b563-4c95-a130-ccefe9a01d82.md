Target: BitcoinVerifier::verify_transactions coinbase commitment scan `coinbase_tx.output.iter().rposition(...)` combined with MINIMUM_WITNESS_COMMITMENT_SIZE and WITNESS_COMMITMENT_PREFIX. Attacker action: as a miner (or via a permissionless op_return spender) insert two witness-commitment-shaped outputs into the coinbase transaction they mine, one malformed (short) at a higher output index and one correct at a lower index, matching BIP-141's requirement that only the highest index counts. Preconditions: regtest, block being mined with attacker-controlled coinbase (attacker runs their own miner against shared mempool). Call sequence: verify_transactions uses rposition to pick the highest-index candidate; the native da_block_handler must independently reconstruct the same commitment-selection logic when validating segwit commitment size/prefix before calling parse_relevant_transaction. Binding: the commitment_idx selected in-circuit == the commitment_idx an honest full node uses to validate the same coinbase. Scoped impact: Critical, split in DA_INTEGRITY / commitment validation causing an IncorrectWitnessCommitment on one side and Ok on the other for block B. Proof idea: adapt test_malicious_multiple_witness_commitments in bin/citrea/tests/bitcoin/bitcoin_verifier.rs to assert both native scan and verify_transactions select output index N, and that malformed prefix-matching outputs at lower index never override it.
