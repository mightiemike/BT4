Attacker action: submit a commit at a `block_height` exactly at an epoch transition boundary where the local epoch table on two nodes (e.g. one still syncing PoX-waterfall configuration) might disagree about which `StacksEpochId` governs that height. Impact: Critical -- disagreement on the epoch for a given height changes whether PoX or PoB rules govern the commit, causing one node to accept a commit the other rejects, splitting the burn distribution and the sortition winner. Proof idea: integration test pinning `SortitionDB` epoch tables slightly differently across two node instances at the transition height and confirming (or disproving) that `check`'s result diverges for the identical commit tx.
