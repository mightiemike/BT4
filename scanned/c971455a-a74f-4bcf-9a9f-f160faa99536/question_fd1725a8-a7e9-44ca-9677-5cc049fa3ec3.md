`process_complete_proof` (crates/light-client-prover/src/circuit/mod.rs) only checks `BlockHashAccessor::<S>::exists(batch_proof_output.last_l1_hash_on_bitcoin_light_client_contract(), working_set)` and `Z::verify(proof, &batch_proof_method_id.into(), network_to_dev_mode(network))`, without any check that the underlying DA bytes for `proof` were sent by `batch_prover_da_public_key`—that check is only applied to the wrapping `DataOnDa::Complete`/`DataOnDa::Aggregate` blob, not to the reconstructed chunk-concatenated bytes for an aggregate. Can an unprivileged attacker who controls a `DataOnDa::Aggregate` blob's `wtxids` field (their own inscribed reveal, whose `sender()` is checked to equal `batch_prover_da_public_key` only for the *outer* aggregate transaction, not for the referenced chunks) point to chunks they themselves inscribed, so the reconstructed proof body is entirely attacker-authored while the outer aggregate wrapper appears to "come from" the batch prover only because the attacker cannot forge that sender check — i.e. is there any code path where the attacker does NOT need `batch_prover_da_public_key` because they instead inject via `DataOnDa::Chunk` alone, with a later legitimate aggregate accidentally referencing their poisoned wtxid? Preconditions: batch prover's real aggregate wtxids array is public before confirmation (mempool visibility) or predictable (deterministic wtxid derivation from known chunk bytes+chunk index). Call sequence: attacker inscribes `DataOnDa::Chunk` at the exact position expected -> real `DataOnDa::Aggregate` from batch prover (sender check passes because outer tx really is signed by batch prover) references wtxids that include the attacker's poisoned chunk -> `ChunkAccessor::get` returns attacker bytes -> `process_complete_proof` verifies a body that is a hybrid of honest+attacker bytes. Binding: `process_complete_proof`'s verified proof bytes == exactly the bytes `batch_prover_da_public_key`'s holder chunked and signed, with no substitution. Impact: Critical — hybrid/forged proof body accepted under the batch prover's authority despite the batch prover never producing those exact bytes. Proof idea: cargo test where an aggregate's `wtxids` list is constructed to include one wtxid from an attacker-controlled `DataOnDa::Chunk` transaction alongside honest ones, and assert whether `run_l1_block` treats the resulting concatenation as authorized purely because the wrapping Aggregate blob passed the sender check.
