Target: `write_path_to_bytes` (used by both `ProofTrieNode::write_consensus_bytes` in `proofs.rs` and node consensus hashing in `bits.rs`) applied to a `path` field whose byte length can vary (0..32). Can an attacker craft two distinct logical trie paths — one of length L and one of length L+1 whose extra byte happens to equal a byte that `write_path_to_bytes` would otherwise emit as a length/count marker — such that the encoded byte streams collide, causing `get_node_hash`/`write_consensus_bytes` to produce the same hash for two structurally different nodes, and thus a `verify_proof` call built against one node validates successfully against the other's (different) child data? Preconditions: attacker controls the exact key set inserted to produce a path-length collision at a node boundary. Equality broken: every value verified via `verify_proof` == a `(key,value)` actually committed under the claimed root (i.e. `write_path_to_bytes` must be a length-prefixed, collision-free encoding). Impact: Critical, forged Merkle proof accepted for an uncommitted value. Proof idea: integration test constructing two paths engineered for a length/byte-marker collision, computing both `get_node_hash` outputs, and asserting they differ (fuzz over path lengths 0..32).
