Target: `BlockSnapshot::get_miner_commit_carryover`'s `AtcRational::frac(block_burn_total, windowed_median_burns)` divides two `u64` values converted with `Uint256::from_u64`; an attacker mining consecutively can manipulate `windowed_median_burns` (their own historical median) to be extremely small (e.g., 1) in an early window, then in the target block commit a large `block_burn_total`, forcing `block_burn_total >= windowed_median_burns` and clamping ATC to `AtcRational::one()` (no null-miner risk) even though relative to the network's overall commitment the attacker's real economic weight is minority — this doesn't break determinism per se, but demonstrates that `windowed_median_burns` is entirely self-referential per-miner (each `BurnSamplePoint`'s own historical chain), so `get_miner_commit_carryover`'s intended purpose (deterring flash/MEV block-stuffing) can be trivially satisfied by an attacker who mined a single cheap commit earlier to set their own low median baseline. Preconditions: attacker mines an initial cheap commit (median-setting) then a later expensive one within `MINING_COMMITMENT_WINDOW`. Call sequence: `make_snapshot_in_epoch` -> `state_transition.windowed_median_burns()` -> `get_miner_commit_carryover` -> `atc=one()`, `null_active=false` -> null-miner check skipped entirely. Equality broken: the null-miner defense's intended guarantee (ATC reflects genuine commit consistency) == actual enforcement when the miner's own median baseline is self-manipulated. Impact: High — this only affects whether the null-miner mechanism activates for one miner's own commit-history, is bounded to that miner's own sortition attempts (fee/reward-scoped), not a state-root or split issue by itself. Proof idea: integration test where a single low-burn commit is placed early in the window, then a much larger commit later, asserting `null_active` remains false despite the large jump relative to network-wide commitments.
