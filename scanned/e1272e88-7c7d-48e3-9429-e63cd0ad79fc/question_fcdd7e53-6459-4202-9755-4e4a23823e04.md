`Bridge.sol::withdraw`/`batchWithdraw` and the withdrawal `PSBT`-based dutch auction flow described in `docs/bridge-contract.md` allow a user to burn cBTC and later have a `Clementine` operator complete the PSBT. Since the attacker cannot compromise a Clementine operator, can an unprivileged attacker instead call `withdraw()` or `batchWithdraw()` MULTIPLE times reusing the SAME dust UTXO input across multiple separate withdrawal requests recorded in the public `withdrawalUTXOs` array (since the dust UTXO itself, being 'financially irrelevant, or even 0 sat,' may not be tracked for uniqueness by the Bridge contract, only by the eventual Bitcoin-side PSBT double-spend), so that `count(cBTC_burned_withdrawal_requests) != count(dust_UTXOs_actually_available_to_settle)`? Impact: Critical, if the contract records multiple pending withdrawal entries against a single reusable dust UTXO, an operator could only ever fulfill one, permanently freezing the other burned cBTC's corresponding BTC claim. Proof idea: cargo test calling `withdraw()` twice with the identical dust UTXO reference and distinct depositAmount burns, asserting whether the contract rejects the second call or records two entries in `withdrawalUTXOs` for one spendable UTXO.
