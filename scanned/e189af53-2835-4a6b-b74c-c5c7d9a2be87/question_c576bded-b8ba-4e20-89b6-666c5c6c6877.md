Attacker action: submit exactly enough headers to complete the currently-partial interval with a lower-work tail than what a competing honest fork would supply, timed so the node's total_work_after computed in-memory looks sufficient (>= total_work_before) at acceptance time, but the persisted chain_work table (used by every *subsequent* call to get_chain_work/update_chain_work, including the one another node performs independently) never recorded that specific partial-interval total. Precondition: node mid-interval, insert_height inside a partial chunk. Impact: Critical, node B ends up with a strictly-less canonical chain_work row than its own true header set implies, so a subsequent fork comparison on node B measures the wrong baseline and can accept an attacker's lower-work fork against that stale baseline.
