Target: `execute_multiple_tx` (crates/evm/src/evm/executor.rs) `should_be_end_of_sys_txs` mutable flag threading via `citrea_evm::call`. Attacker action: submit a raw transaction from the `SYSTEM_SIGNER` address (`0xdeaDDeADDEaDdeaDdEAddEADDEAdDeadDEADDEaD`) directly to the public sequencer RPC via `eth_sendRawTransaction`. Preconditions: attacker cannot actually sign as `SYSTEM_SIGNER` (no private key exists for this address since its signature `PrimitiveSignature::new(U256::ZERO, U256::ZERO, false)` is fixed/invalid for ECDSA recovery), so this specific spoof fails signature recovery; however `CitreaMempool::add_external_transaction` (crates/sequencer/src/mempool.rs) explicitly checks `transaction.transaction().signer() == SYSTEM_SIGNER` and rejects with 'system transactions from rpc are not allowed'. Binding: the set of txs with signer `SYSTEM_SIGNER` accepted from RPC == empty set, matching the set the batch circuit expects the sequencer to have placed only at block-start. Impact: Critical if this check is ever bypassed, since a user-injected fake system tx could hit `verify_system_tx`'s BitcoinLightClient selector matching and forge L1 state info, or a non-selector-matching system tx would skip `verify_system_tx` entirely (its `// TODO: should we check for other system txs?` comment) and execute as an ungated privileged call with the system caller's gas-exemption (`validate_tx_against_state`/`deduct_caller`/`reimburse_caller` skip normal EVM economics) — but since ECDSA cannot recover to SYSTEM_SIGNER for any attacker-chosen signature and the pool-level check exists as defense-in-depth, exploitation requires an actual signature-recovery bug elsewhere.
