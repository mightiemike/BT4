Target: `StateReaderAndWriter::set_value`/`get_value` generic helpers in scratchpad.rs, used by every system-contract-adjacent state map (e.g. Bridge deposit tracking analog on the sov-modules side, chunk/method-id accessors in the light client circuit which use the same trait). Attacker action: inscribe a Bitcoin transaction whose wtxid carries the reveal prefix and whose body borsh-deserializes to `DataOnDa::Chunk(attacker_bytes)` with no signature at all (chunks are explicitly unauthenticated per `circuit/mod.rs` comment 'No need to check sender for chunk'). Preconditions: regtest bitcoind, ability to mine/inscribe any tx matching `reveal_tx_prefix`. Call sequence: light client circuit `run_l1_block` -> `DataOnDa::Chunk(chunk)` branch -> `ChunkAccessor::insert(blob.wtxid(), chunk, &mut working_set)` -> internally calls `WorkingSet::set_value` (scratchpad.rs) storing attacker bytes keyed by `wtxid`. Binding: the chunk bytes stored via `set_value` for a given `wtxid` == chunk bytes that will later be validated as part of a batch prover's actual proof once aggregated - but no authority check ties `wtxid` to the real batch prover. Impact: Critical - an attacker can pollute the chunk JMT namespace with unlimited unauthenticated chunks under wtxids they mine, and if any subsequently-aggregated proof references one of the attacker's `wtxid`s (collision or reuse scenario) the `Aggregate` accessor will assemble attacker bytes into what should be prover-only data, potentially causing all honest light client provers to either agree on a corrupted assembled proof (determinism preserved but wrong data admitted) or diverge if timing of chunk insertion differs. Proof idea: cargo test using `NativeCircuitRunner::insert_random_chunk` pattern to insert an attacker-chosen chunk body under a chosen `wtxid`, then feed an `Aggregate` blob referencing that `wtxid` from a non-batch-prover sender, asserting whether `process_complete_proof` accepts assembled bytes it should reject since Aggregate's own sender check (`blob.sender().as_ref() != batch_prover_da_public_key`) is the only guard and chunks themselves are never sender-checked.
