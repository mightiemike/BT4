Attacker action: force a fork where the same parent/child tenure pair is processed on two distinct forks (e.g. by broadcasting a competing Nakamoto block for the same burn view causing a temporary two-fork race), each fork independently calling `insert_matured_child_miner_reward`/`insert_matured_parent_miner_reward` for the same `(parent_block_id, child_block_id)` key but with a different attacker as recipient. Preconditions: minority attacker can extend a fork past the tip momentarily before reorg. Call sequence: `find_mature_miner_rewards` -> `insert_matured_child_miner_reward` on fork A credits recipient X; then, without a global chain reorg first invalidating fork A's matured_rewards row, fork B (canonical) computes a competing reward tuple and calls `inner_insert_matured_miner_reward`, which only rejects reinsertion if `rw == reward` (asserted via `assert_eq!`) but otherwise silently accepts if the (parent,child) key differs across forks. Equality that breaks: STX credited as block reward for a tenure == coinbase+fees for that tenure paid exactly once network-wide; if both forks' matured_rewards rows survive under different index_block_hash keys pointing to the same underlying coinbase, effectively both branches pay. Impact: Critical, double-payment across a fork. Proof idea: two-fork Rust harness mining a common ancestor then diverging for MINER_REWARD_MATURITY blocks with different coinbase recipients, then reconverging via reorg and asserting sum of credited STX across the reorged chain equals a single coinbase+fees, not two.
