Target: `BatchProverRpcServerImpl::create_circuit_input` (crates/batch-prover/src/rpc.rs) combined with `set_commitments`. Attacker calls `set_commitments` to insert a self-crafted `SequencerCommitment{merkle_root, index, l2_end_block_number}` into `ledger_db`, then calls `create_circuit_input(index_start, index_end, mode)`, which fetches `commitments = ledger_db.get_commitment_by_range(...)` and forwards them via `ProverRequest::CreateInput` unchanged. Binding: the `commitment.merkle_root` used to build the circuit input == the `merkle_root` inscribed in a `DataOnDa::SequencerCommitment` transaction signed by `sequencer_da_public_key`. Precondition: no other layer cross-checks `ledger_db` commitments against DA before `create_circuit_input` runs. Impact: Critical -- a circuit input can be created (and, if the operator subsequently proves it, submitted to DA) whose `sequencer_commitment_hashes` never existed on Bitcoin, i.e., a false state transition made provable. Proof idea: `cargo test` inserting an unauthenticated commitment via `set_commitments`, calling `create_circuit_input`, deserializing the base64 output, and asserting the commitment hash inside equals a hash with no matching signed DA inscription.
