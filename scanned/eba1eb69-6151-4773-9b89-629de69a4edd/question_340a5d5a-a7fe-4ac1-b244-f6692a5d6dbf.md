Target: `SortitionDB::get_consumed_leader_keys` (stackslib/src/chainstate/burn/db/sortdb.rs) called once per sortition to find keys consumed by *all* candidate block-commits in a burn block, panicking via `unwrap_or_else(|| panic!(...))` if a candidate's leader key is missing rather than treating it as invalid ('FATAL: no leader key for accepted block commit'). Attacker action: submit a block-commit whose (key_block_ptr, key_vtxindex) references a leader key that existed on a *different, now-orphaned* burnchain fork at the time of commit construction, then trigger a reorg such that at sortition-processing time on this fork the referenced key never existed, forcing the panic path instead of a clean rejection. Preconditions: attacker registers a key on fork A, the network reorgs to fork B before the attacker's commit (submitted referencing fork-A coordinates) is processed as a sortition candidate on fork B. Call sequence: reorg -> new sortition winner selection on fork B includes attacker's stale commit as a *candidate* (its `check()` may have already passed against fork A's view) -> `get_consumed_leader_keys` -> `get_leader_key_at(..., &parent_tip.sortition_id)` returns None on fork B -> `panic!`. Equality broken: every block-commit accepted as a sortition *candidate* on a given fork must have its referenced leader key resolvable on that exact fork (parent_tip.sortition_id) before reaching `get_consumed_leader_keys`; if candidacy is determined on a different, stale fork view, this equality fails, crashing the node process. Impact: Critical — this is not mere DoS but a crash-induced liveness/consensus divergence: a node that panics stalls while peers continue, and if the panic path differs by node timing this produces effective chain-split-by-crash bounded to nodes that raced the reorg. Proof idea: Rust two-node reorg harness where node A observes fork A then B, node B observes only B directly, both fed the same stale-referencing block-commit, and assert neither panics and both reach the same SORTITION verdict — DETERMINISM: verdict on node A == verdict on node B, with no unwrap-panic on either.
