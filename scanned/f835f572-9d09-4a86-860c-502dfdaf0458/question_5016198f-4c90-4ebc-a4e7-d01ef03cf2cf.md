Target: bitcoin_da::verifier::BitcoinVerifier::verify_transactions coinbase commitment_idx = coinbase_tx.output.iter().rposition(...). Attacker (miner or anyone who can construct a block template, e.g. via their own regtest/solo mining) inserts two outputs matching WITNESS_COMMITMENT_PREFIX and length >= MINIMUM_WITNESS_COMMITMENT_SIZE in the coinbase, where the first (lower index) encodes the true sha256(sha256(merkle_root||witness_reserved_value)) commitment and the second (highest index) is garbage. Preconditions: attacker mines a block on a network where they can produce blocks (regtest/testnet only - relevant since this is a testable scenario, not requiring majority hashrate). Call sequence: verify_transactions picks commitment_idx via rposition (highest index) == the garbage output, computes commitment from witness_reserved_value at coinbase_tx.input[0].witness, compares against script_pubkey[6..38] of the highest-index output, fails with ValidationError::IncorrectWitnessCommitment even though a bitcoind-standard validator (BIP-141: highest-index commitment is the valid one) would also reject it since the true commitment isn't at the highest index. Binding: the witness-commitment output index selected by verify_transactions's rposition == the witness-commitment output index selected by an honest Bitcoin full node applying BIP-141 to compute the same block's validity. Impact: Critical - if these two selections diverge for any block accepted by real Bitcoin consensus (segwit valid), the circuit rejects a block that Bitcoin itself would relay/accept as containing valid segwit data, making the blobs in that block permanently unprovable (a true DA event becomes unprovable).
