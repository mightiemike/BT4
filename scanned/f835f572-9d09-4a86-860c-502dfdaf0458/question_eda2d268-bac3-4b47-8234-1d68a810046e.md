Target: bitcoin_da::helpers::parsers::get_script and parse_relevant_transaction. Attacker constructs a P2TR script-path spend reveal transaction with more than one input, where input[0] carries a valid Complete-kind reveal script but a later input (input[1]) also independently satisfies reveal_tx_prefix requirements on the tx's overall wtxid (since wtxid depends on all inputs/witnesses). Preconditions: unprivileged tx crafter paying their own fees. Call sequence: get_script(tx) only ever inspects tx.input[0].witness.tapscript() - any data placed in input[1]'s witness is never examined by parse_relevant_transaction, yet it still contributes to the tx's wtxid used for the reveal_tx_prefix match and for calculate_wtxid comparison in verify_transactions. Binding: the content parsed from tx.input[0] and pushed into blobs == the entire semantic content an honest full node's mempool/relay logic associates with that wtxid; specifically, any data hidden in non-zero-index inputs is invisible to both native and circuit, so this must be symmetric - the DA payload content is fully captured by input[0] alone for both sides. Impact: High (not Critical, since no funds move and both native and circuit agree in ignoring input[1] - included for completeness of the audit but should be confirmed non-Critical) - unless a future code path (e.g. chunk reassembly in crates/bitcoin-da/src/service.rs verify_chunk_order) inspects a different input index than get_script, in which case the DA_INTEGRITY binding (blob set circuit derives == blob set native full node acted on) breaks.
