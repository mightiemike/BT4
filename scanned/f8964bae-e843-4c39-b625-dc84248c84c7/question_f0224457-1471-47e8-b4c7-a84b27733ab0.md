Target: `BitcoinVerifier::verify_transactions`, header check `block_header.tx_count as usize != inclusion_proof.wtxids.len()`. Attacker action: none needed on-chain; instead exploit the boundary where `tx_count == 1` (single coinbase-only block, e.g. an early empty block an attacker can mine on regtest/signet). Preconditions: block contains exactly the coinbase tx, `block_header.txs_commitment` field supplied by the DA reader. Call sequence: verifier hits `if block_header.tx_count == 1 && block_header.txs_commitment != [0;32] { return Err(InvalidSegWitCommitment) }`; separately, native `calculate_witness_root` (crates/bitcoin-da/src/service.rs) also special-cases `if tx_count == 1 { return [0u8;32] }`. Binding: txs_commitment_the_verifier_expects_for_a_1-tx_block == txs_commitment_the_native_reader_computes_for_the_same_block. Impact: Critical DA integrity — if the native `HeaderWrapper`/short-header-proof construction (used to populate `block_header.txs_commitment` fed into the circuit) ever computes a non-zero commitment for a genuinely coinbase-only block (e.g. because it forgot the tx_count==1 special case somewhere else, such as `BitcoinHeaderShortProof::verify` in crates/bitcoin-da/src/spec/short_proof.rs), an honest full node accepts the block's absence of blobs while the circuit's short header proof verification fails, splitting DA views.
