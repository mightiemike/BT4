Target: NakamotoChainState::calculate_scheduled_tenure_reward (stackslib/src/chainstate/nakamoto/tenure.rs), which reads accumulated_rewards from SortitionDB::get_block_snapshot_consensus(...).accumulated_coinbase_ustx for the block's own consensus_hash. Attacker action: an unprivileged miner deliberately lets several of their own sortition wins go 'missed' (no block produced) by broadcasting a valid winning block-commit but withholding the block, causing accumulated_coinbase_ustx to roll forward onto a later sortition the same miner also wins, then claims the compounded coinbase in one block. Preconditions: attacker controls burn-fee bidding across consecutive sortitions so their own commit wins repeatedly with minimal broadcast latency. Call sequence: repeated missed sortitions accumulate coinbase in the BlockSnapshot chain -> attacker's later winning tenure's calculate_scheduled_tenure_reward reads total_coinbase = coinbase_at_block + accumulated_rewards -> make_scheduled_miner_reward schedules the full sum to the attacker. Equality that breaks: TENURE/REWARD - reward paid to a miner for tenure T must equal coinbase(T)+fees(T); intentionally-missed tenures let one address claim multiple tenures' coinbases while only one tenure-change / VRF proof / signer-approved block was ever produced, i.e. reward paid does not correspond 1:1 with canonical tenures actually authored. Impact: High (bounded to accumulated per-cycle coinbase, not a fork) since this is within protocol design intent for missed-sortition accumulation, but if paired with a subsequent reorg that also invalidates the accumulation snapshot read by a stale node, it becomes Critical via double-accrual across two forks. Proof idea: Rust integration test forcing several consecutive missed sortitions from the same miner key, then confirming a claimed block, and cross-checking the resulting MinerPaymentSchedule.coinbase against an independently recomputed sum of per-sortition accumulated_coinbase_ustx from SortitionDB on two separately-synced nodes, asserting equality holds identically on both.
