### Title
Stale return data persists across `push`/`pop` instruction-frame transitions, letting a program's return data outlive its own call frame - (File: `transaction-context/src/transaction.rs`)

### Summary
`TransactionContext::push` and `TransactionContext::pop` never clear `transaction_frame.return_data_pubkey` / `return_data_bytes`, so return data set by one instruction (including a CPI that later fails and is unwound) remains visible to subsequent, unrelated instructions that never call `set_return_data`. A caller that trusts "current return data" to reflect only the immediately preceding successfully executed instruction can be fed forged/stale data.

### Finding Description
`set_return_data` writes `program_id` and `data` into `self.transaction_frame` / `self.return_data_bytes`: [1](#0-0) 

`push`, which is invoked every time a new instruction (top-level or CPI) frame is entered, does bookkeeping for the instruction stack/trace but contains no reset of `return_data_pubkey`/`return_data_bytes`: [2](#0-1) 

Likewise `pop`, which unwinds the frame (including the unwind path taken when a nested CPI returns an error), also does not clear the return data: [3](#0-2) 

`get_return_data` simply returns whatever is currently stored, with no association to which frame produced it beyond the `program_id` field written by the last caller of `set_return_data`: [4](#0-3) 

Exploit flow: an attacker's own program (1) invokes a nested CPI to a program (could be attacker-controlled) that calls `set_return_data(program_id=X, data=forged)`, (2) that CPI is made to return an `InstructionError` so `pop()` runs the unwind/error path shown above, discarding the failed instruction but leaving `return_data_pubkey`/`return_data_bytes` untouched, (3) the attacker's program then performs a second, legitimate-looking CPI into a victim program that never calls `set_return_data` itself. When the outer instruction or a downstream consumer calls `sol_get_return_data`/`get_return_data()` afterward, it still observes the stale `(X, forged)` pair left over from the failed, unwound nested call, even though no successful instruction in the current call chain actually produced it. Programs that rely on "return data present == the callee I just invoked produced it" (a common pattern for reading price-oracle, decode-account or approval outputs from a CPI) can be tricked into consuming forged/replayed data because nothing in `push`/`pop` invalidates return data across frame boundaries or on error unwind.

No existing check in `push` or `pop` clears or scopes return data to the frame that produced it; the only mutation site is `set_return_data`.

### Impact Explanation
If a caller program's logic branches on `get_return_data()` to authorize a state transition (e.g., accepting a computed price, an approved amount, or a computed decision from a called program), an attacker can arrange for that call to be skipped/erred while a forged return payload with an arbitrary attacker-chosen `program_id` lingers from an earlier, already-unwound nested call, and have it consumed as if freshly produced. Depending on how the victim protocol consumes return data, this can enable state manipulation without the resource owner's consent, matching a Loss-of-Funds category if exploited against a program that gates fund transfers on trusted return-data content.

### Likelihood Explanation
The attacker only needs to deploy an unprivileged SBF program that performs ordinary CPIs, sets return data, forces a nested CPI to fail, and lets it unwind — all standard, permissionless operations available to any transaction sender. No special privileges, feature flags, or validator/node access are required, and the sequence is fully reproducible by controlling instruction nesting and CPI success/failure.

### Recommendation
Clear the transaction-level return data (`transaction_frame.return_data_pubkey = Pubkey::default()`, `return_data_bytes.clear()`, and reset `return_data_scratchpad` length to 0) at the start of `TransactionContext::push`, so each new instruction frame begins with no return data, matching the invariant that return data is scoped to (and only visible immediately after) the instruction that produced it.

### Proof of Concept
1. Build a `TransactionContext` with three configured instructions: top-level `A`, nested CPI `B` (invoked by `A`), and a second nested CPI `C` (invoked by `A`, after `B`).
2. `push()` `A`; `push()` `B`; call `set_return_data(program_id_B, b"forged")`; `pop()` `B` with an injected `InstructionError` (simulate the unwind path).
3. Assert immediately after `pop()` that `get_return_data()` still returns `(program_id_B, b"forged")` (demonstrates the bug — stale data survives unwind).
4. `push()` `C` (which never calls `set_return_data`); assert that `get_return_data()` returns `(Pubkey::default(), &[])` — this assertion currently **fails** against the unpatched code (it still returns `(program_id_B, b"forged")`), proving stale return data leaks into an unrelated later frame.
5. After applying the fix (clearing return data in `push`), re-run step 4 and confirm the assertion passes.

    /// Pushes the next instruction
    pub fn push(&mut self) -> Result<(), InstructionError> {
        let nesting_level = self.get_instruction_stack_height();
        if !self.instruction_stack.is_empty() && self.accounts.get_lamports_delta() != 0 {
            return Err(InstructionError::UnbalancedInstruction);
        }
        {
            let instruction = self
                .instruction_trace
                .last_mut()
                .ok_or(InstructionError::CallDepth)?;
            instruction.nesting_level = nesting_level as u16;
        }

        if self.number_of_called_instructions_in_trace() >= self.instruction_trace_capacity {
            return Err(InstructionError::MaxInstructionTraceLengthExceeded);
        }

        let (index_in_trace, current_top_level_instruction) = if self.instruction_stack.is_empty() {
            let index = self.next_top_level_instruction_index;
            self.next_top_level_instruction_index =
                self.next_top_level_instruction_index.saturating_add(1);
            (index, index)
        } else {
            let index = self.get_instruction_trace_length();
            self.transaction_frame.number_of_cpis_in_trace = self
                .transaction_frame
                .number_of_cpis_in_trace
                .saturating_add(1);
            self.instruction_trace.push(InstructionFrame::default());
            (
                index,
                self.next_top_level_instruction_index.saturating_sub(1),
            )
        };

        if nesting_level >= self.instruction_stack_capacity {
            return Err(InstructionError::CallDepth);
        }
        self.transaction_frame.current_executing_instruction = index_in_trace as u16;
        self.instruction_stack.push(index_in_trace);
        if let Some(index_in_transaction) = self.find_index_of_account(&instructions::id()) {
            let mut mut_account_ref = self.accounts.try_borrow_mut(index_in_transaction)?;
            if mut_account_ref.owner() != &solana_sdk_ids::sysvar::id() {
                return Err(InstructionError::InvalidAccountOwner);
            }
            instructions::store_current_index_checked(
                mut_account_ref.data_as_mut_slice(),
                current_top_level_instruction as u16,
            )?;
        }
        Ok(())
    }

    /// Pops the current instruction
    pub fn pop(&mut self) -> Result<(), InstructionError> {
        if self.instruction_stack.is_empty() {
            return Err(InstructionError::CallDepth);
        }
        // Verify (before we pop) that the total sum of all lamports in this instruction did not change
        let detected_an_unbalanced_instruction =
            self.get_current_instruction_context()
                .and_then(|instruction_context| {
                    // Verify all executable accounts have no outstanding refs
                    self.accounts
                        .try_borrow_mut(
                            instruction_context.get_index_of_program_account_in_transaction()?,
                        )
                        .map_err(|err| {
                            if err == InstructionError::AccountBorrowFailed {
                                InstructionError::AccountBorrowOutstanding
                            } else {
                                err
                            }
                        })?;
                    Ok(self.accounts.get_lamports_delta() != 0)
                });
        // Always pop, even if we `detected_an_unbalanced_instruction`
        self.instruction_stack.pop();
        if let Some(instr_idx) = self.instruction_stack.last() {
            self.transaction_frame.current_executing_instruction = *instr_idx as u16;
        }
        if detected_an_unbalanced_instruction? {
            Err(InstructionError::UnbalancedInstruction)
        } else {
            Ok(())
        }
    }

    /// Set the return data of the current instruction
    pub fn set_return_data(
        &mut self,
        program_id: Pubkey,
        data: Vec<u8>,
    ) -> Result<(), InstructionError> {
        self.transaction_frame.return_data_pubkey = program_id;
        self.transaction_frame
            .return_data_scratchpad
            .set_len(data.len() as u64);
        self.return_data_bytes = data;
        Ok(())
    }
