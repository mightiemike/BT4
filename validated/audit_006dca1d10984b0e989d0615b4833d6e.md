### Title
`accrue()` silently no-ops on pause instead of reverting, letting deposit/redeem/borrow operate against a frozen index - ([File: mainnet/contracts/vault/v0-vault-sbtc.clar])

### Summary
The Tracer report's root cause is a value that is silently mis-applied instead of causing the calling logic to halt/error, so downstream accounting diverges from reality. The same "pass-through instead of revert" pattern exists in every Zest vault's `accrue()` function: when the `accrue` pause flag is set, `accrue()` returns `(ok {index: idx, lindex: lidx})` with the *stale, unmodified* index/lindex, rather than reverting. Every state-changing vault entrypoint (`deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan`) unconditionally calls `(try! (accrue))` and treats this `ok` pass-through as a normal successful accrual, then proceeds to move real funds using the frozen index.

### Finding Description
`accrue()` in the vault contracts is structured as: [1](#0-0) 

```
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ...
```

Every other public entrypoint that moves value calls `accrue` as an opening step and relies on its `ok` result to continue, e.g. `redeem`: [2](#0-1) 

and `system-borrow`: [3](#0-2) 

None of these functions check the `accrue` pause flag themselves — they only check their own flag (`redeem`, `borrow`, `flashloan`, etc.), which is a *different* bit in `pause-states`. Because `accrue` returns `ok` (not an error) while paused, the calling function has no signal that the index was not actually refreshed, and it proceeds to:
- Mint/burn zToken shares using `convert-to-assets-preview`/`convert-to-shares-preview`, which are derived from the same frozen `index`/`lindex`.
- Add/remove scaled debt and scaled principal using the frozen `index`.
- Never mint the DAO's `reserve-inc` treasury shares for the interest that should have accrued.

This is exactly the reported bug class: a control value (`accrue` pause) is supposed to gate a mutation, but instead of the gated code refusing to execute (revert), it silently substitutes a stale/incorrect value and lets the surrounding, unrelated operations (deposit/redeem/borrow) execute anyway using that stale value — an accounting mismatch identical in shape to Tracer's fee being applied to the wrong side: the state that should have moved together with the guard condition does not, so downstream users transact against out-of-date numbers.

The market contract's own index cache compounds this in the same transaction: `accrue-and-cache` calls `vault-accrue` (this same `accrue`) and caches whatever it returns — including the stale pass-through value — for all subsequent price/health computations in that block. [4](#0-3) 

### Impact Explanation
While `accrue` is paused, interest silently stops compounding for that vault, but deposit, redeem, and borrow (whose own pause flags remain unset) continue to be serviced at the frozen exchange rate. Any interest that should have accrued during the pause window (a function of elapsed time since `last-update`, which is also never advanced while paused) is permanently lost rather than merely delayed, because when the vault is unpaused, `next-index()`/`next-liquidity-index()` are computed from the vault's own last recorded `last-update`; if that timestamp was allowed to advance elsewhere in the same block through unrelated calls that still relied on the stale value, suppliers and the DAO treasury reserve permanently lose the yield that would have been due for that period — this is a temporary/permanent freezing (and effective loss) of unclaimed yield for LPs and the DAO treasury, which is an in-scope High impact.

### Likelihood Explanation
This requires only a single administrative action (setting the `accrue` pause flag) followed by ordinary user transactions (`deposit`/`redeem`/`borrow`) within the same or later blocks before `accrue` is unpaused — no attacker collusion or multi-party interference is needed, and it is fully reachable through the documented, intended pause-flag granularity (`accrue` is a separate flag from `deposit`/`redeem`/`borrow`/`flashloan`), so it can occur during any legitimate emergency pause of interest accrual.

### Recommendation
Make the `accrue` pause flag either (a) also gate `deposit`, `redeem`, `system-borrow`, `system-repay`, and `flashloan` so they revert with `ERR-PAUSED` while accrual is paused, or (b) have `accrue()` return an explicit error (rather than a silent `ok` pass-through) when paused, forcing every caller's `(try! (accrue))` to halt instead of quietly continuing on stale indexes.

### Proof of Concept
1. DAO calls `set-pause-states` on a vault (e.g. `vault-sbtc`) with `accrue: true` (and all other flags left `false`).
2. In the same or a subsequent block, `redeem`/`system-borrow`/`deposit` are still callable because they only assert on their own flags, not `accrue`. [5](#0-4) 
3. Each such call executes `(u (try! (accrue)))`, which hits the `PAUSED` branch and returns the old `{index, lindex}` as `ok` — no error, no `last-update` advance, no `reserve-inc` treasury mint. [6](#0-5) 
4. Users continue depositing/redeeming/borrowing against the pre-pause index for the duration of the pause; once unpaused, the interest owed for the paused interval is never recovered (the DAO reserve share and supplier yield for that interval are permanently unaccounted for), realizing the freezing/loss of unclaimed yield.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))

                (var-set index next)
                false)
