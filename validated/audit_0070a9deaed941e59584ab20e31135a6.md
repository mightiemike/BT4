### Title
`accrue()` "pause pass-through" lets `system-borrow`/`system-repay`/`deposit`/`redeem` proceed on stale interest indexes when accrual is paused, allowing debt/interest mis-accounting - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
The Boba report's root cause is a value (`ETHAmount`) that keeps advancing/being trusted across a batch even though the underlying invariant it depends on can silently break. The closest in-scope Clarity analog is the `accrue` pause path in the vault contracts (`v0-vault-stx.clar`, and identically in `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`): when the `accrue` pause flag is set, `accrue()` does not revert and does not recompute the index - it returns the **stale, currently-stored** `index`/`lindex` as if they were fresh, and every caller (`deposit`, `redeem`, `system-borrow`, `system-repay`, `socialize-debt`, and via `market.clar`'s `accrue-and-cache`, borrow/repay/liquidate) treats that stale-but-"ok" response as an authoritative up-to-date index.

### Finding Description
`accrue()` in `mainnet/contracts/vault/v0-vault-stx.clar:835-863` reads the pause flag and branches: [1](#0-0) 

When `(get accrue states)` is true, it takes the `;; PAUSED: Pass-through without reverting` branch and simply returns `(ok { index: idx, lindex: lidx })` using the **currently stored** `idx`/`lidx` — it never calls `next-index`/`next-liquidity-index`, never updates `var-get index`/`lindex`, and never updates `last-update`. Critically, it still returns `ok`, not an error.

Every state-changing entry point in the vault (`deposit`, `redeem`, `system-borrow`, `system-repay`) unconditionally calls `(try! (accrue))` first and then proceeds with whatever index/lindex value is in scope: [2](#0-1) [3](#0-2) 

Because `accrue()` returns success even while paused, none of these downstream functions know that the index they are using to convert `amount` to `scaled-amount`/`principal-scaled` (in `system-borrow`) or to `principal-reduction`/`interest-paid` (in `system-repay`) is stale. Time (and thus real accrued interest) can pass — deposits, borrows, and repayments can continue to execute — while the interest index used for share/debt accounting is frozen at whatever value it had when the pause was toggled on.

This same stale value is then propagated one level up: `market.clar`'s `accrue-and-cache` (`local-testing/contracts/market/market.clar:253-265`, mirrored in `mainnet/contracts/market/v0-4-market.clar:245-257`) calls `vault-accrue` and caches its result keyed only by `{ timestamp: stacks-block-time, aid }`. Since the vault-level "pass-through" already reports success with the stale index, the market-level cache faithfully stores and reuses that stale index for all borrow/repay/liquidate calls in the same timestamp window — the health-check math (`get-notional-evaluation`, `is-healthy`, `borrow`'s `debt-post-increased`) is computed on the frozen index while collateral valuation and debt origination continue to be written to storage as though it were current.

### Impact Explanation
This lands on **temporary freezing of funds / protocol insolvency risk** in the Critical/High band: while `accrue` is paused (an operational lever the DAO can flip, e.g., during an incident), user-facing debt/share accounting silently decouples from the true interest schedule instead of halting. Borrowers can `borrow`/`repay` and depositors can `deposit`/`redeem` at a frozen index, meaning interest that should accrue to lenders is not reflected in `principal-scaled`/`index`, and once accrual resumes, the sudden index jump can misprice all positions transacted during the pause window — this is loss of unclaimed yield for lenders and can push borrower positions into insolvency territory undetected by the health check that trusted the frozen index.

### Likelihood Explanation
Likelihood is **conditional but realistic**: it requires the DAO/ops to have set the `accrue` bit of `pause-states` to `true` (a supported, documented pause lever, not a compromise), and for user transactions to continue flowing through `deposit`/`redeem`/`system-borrow`/`system-repay`/`borrow`/`repay` during that window. Since pausing `accrue` is intended to be a safety mechanism (e.g., to pause interest during an oracle/market incident) while other operations may remain unpaused independently (pause flags are itemized per-action), this is a plausible operational sequence, not a purely theoretical one.

### Recommendation
Decide the intended semantics of the `accrue` pause flag and enforce it consistently:
- If `accrue` being paused is meant to also **halt** state-changing operations that depend on a fresh index (`deposit`, `redeem`, `system-borrow`, `system-repay`), make `accrue()` return an error (e.g., `ERR-PAUSED`) instead of a fabricated `ok` with stale values, so `(try! (accrue))` aborts those calls.
- If instead the intent is that other operations should still work using a "frozen" index by design, document this explicitly and ensure the market-level cache (`accrue-and-cache`) and all consumers are aware the index may be stale, and disallow operations that assume real-time interest is being applied.

### Proof of Concept
1. DAO/ops sets `pause-states` on `v0-vault-stx.clar` with `accrue: true` (other flags such as `borrow`/`repay`/`deposit` left `false`) via `set-pause-states`.
2. Time advances by many blocks/timestamps so that `next-index()`/`next-liquidity-index()` would normally have grown substantially.
3. A borrower calls `market.clar`'s `borrow`, which calls `accrue-and-cache` → vault `accrue()`. Because `accrue` is paused, `accrue()` returns `(ok { index: idx, lindex: lidx })` with the old, un-grown index rather than erroring.
4. `borrow` proceeds: `vault-system-borrow` executes (its own `borrow` pause flag is unpaused), and `debt-add-scaled` records `scaled-debt-added` computed against the stale `index`.
5. Meanwhile a lender calls `deposit`/`redeem`; conversions (`convert-to-shares-preview`/`convert-to-assets-preview`) also use the stale index/lindex, so shares are minted/burned at the wrong exchange rate relative to true accrued interest.
6. When the DAO later unpauses `accrue`, the next `accrue()` call jumps `index`/`lindex` all at once to reflect the full elapsed period, retroactively revealing that all intervening `borrow`/`deposit`/`redeem` operations were mispriced — lenders who deposited during the pause got shares priced without the interest that should have accrued, and debt recorded during the pause understates true interest owed, i.e., yield that should have belonged to existing lenders is diluted/lost.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-public (system-borrow (amount uint) (receiver principal))
  (let (
      (states (var-get pause-states))
      (u (try! (accrue)))
      (CAP-DEBT (var-get cap-debt))
      (available-assets (get-available-assets))
      (scaled-principal (var-get principal-scaled))
      (idx (var-get index))
      (debt (total-debt))
      (scaled-amount (mul-div-up amount INDEX-PRECISION idx))
      (updated-scaled-principal (+ scaled-principal scaled-amount)))

    (try! (check-caller-auth))
    (asserts! (not (get borrow states)) ERR-PAUSED)
    (asserts! (> amount u0) ERR-AMOUNT-ZERO)
    (asserts! (<= amount available-assets) ERR-INSUFFICIENT-VAULT-LIQUIDITY)
    (asserts! (<= (+ debt amount) CAP-DEBT) ERR-DEBT-CAP-EXCEEDED)

    (var-set principal-scaled updated-scaled-principal)
    (var-set total-borrowed (+ (var-get total-borrowed) amount))
    (try! (send-underlying amount receiver))

    (print {
      action: "system-borrow",
      caller: contract-caller,
      data: {
        receiver: receiver,
        amount: amount,
        scaled-amount: scaled-amount,
        principal-scaled: updated-scaled-principal,
        total-borrowed: (var-get total-borrowed),
        index: idx
      }
    })

    (ok true)))
