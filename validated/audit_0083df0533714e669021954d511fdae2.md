### Title
Unbounded VotesStore scan in Wallet.countVote causes O(#voters) CPU/allocation cost per paginated witness-list request regardless of requested `limit` - (File: framework/src/main/java/org/tron/core/Wallet.java)

### Summary
`Wallet.getPaginatedNowWitnessList(offset, limit)` calls a private `countVote(VotesStore)` helper that fully iterates every entry in `VotesStore` and populates a `HashMap` for every old/new vote before applying pagination. Because this scan runs on every call to the public, unauthenticated `GetPaginatedNowWitnessList` HTTP/gRPC endpoint irrespective of the caller-supplied `limit` (even `limit=1`), an attacker who inflates `VotesStore` with many distinct voter entries within a maintenance epoch can make each cheap read request cost O(#voters).

### Finding Description
`Wallet.getPaginatedNowWitnessList` at [1](#0-0)  fetches `witnessCapsuleList`, then calls `countVote(votesStore)` before any pagination (`skip(offset).limit(limit)`) is applied. The `countVote` implementation at [2](#0-1)  iterates the *entire* `VotesStore` via `votesStore.iterator()` and updates a `HashMap` for each old/new vote entry, with cost proportional to the number of distinct voter addresses that have voted in the current epoch — not to the requested `limit`.

This endpoint is exposed unauthenticated over gRPC via `RpcApiService.WalletApi`/`WalletSolidityApi.getPaginatedNowWitnessList` [3](#0-2)  and over HTTP via `GetPaginatedNowWitnessListServlet.doGet/doPost` [4](#0-3) , both reachable by any client without special privileges.

`VotesStore` accumulates one `VotesCapsule` entry per distinct voter address after `VoteWitnessActuator.countVoteAccount` persists it during transaction execution [5](#0-4) . These entries are only cleared during the maintenance cycle by `MaintenanceManager.countVote`, which deletes each entry as it iterates [6](#0-5) . So within a single maintenance epoch (before the store is cleared), an attacker who submits valid `VoteWitnessContract` transactions from N distinct funded/staked accounts can grow `VotesStore` to N entries, and every call to the read-only paginated witness list endpoint during that window costs O(N) regardless of the tiny `limit` requested.

`VoteWitnessActuator.validate()` requires each voter to have TRX Power backing the requested vote count (`sum > tronPower` check) [7](#0-6) , but this only bounds vote weight per account, not the number of distinct accounts an attacker can create and use to vote — there is no limit on the number of distinct addresses contributing entries to `VotesStore`. Existing protections (signature validation, permission checks, `DecodeUtil.addressValid`, fee accounting) all gate individual vote transactions but do nothing to bound the aggregate cost of the downstream read query.

### Impact Explanation
This is a DoS via RPC-API: the cost of a nominally cheap paginated read request (`offset=0, limit=1`) scales with the total number of distinct voters that have cast votes in the current epoch rather than with the requested page size. A node under sustained flood of this endpoint while `VotesStore` is large will consume disproportionate CPU/allocation per request, degrading latency for this and potentially other RPC calls sharing the same worker threads.

### Likelihood Explanation
The attacker needs many distinct funded/staked accounts (to obtain nonzero TRON Power) submitting `VoteWitnessContract` transactions within a single maintenance epoch, and the ability to call the public witness-list endpoint — both of which are default, unprivileged capabilities. The cost to the attacker is proportional to however many `VotesStore` entries they want to create (account creation + minimal freeze per account + transaction fees), which is a real but bounded on-chain cost; once created, the read-side amplification (many cheap requests each costing O(N)) is free to repeat.

### Recommendation
Restructure `getPaginatedNowWitnessList`/`countVote` so that the vote-count aggregation cost does not scale with the full `VotesStore` size on every call, e.g., cache/maintain per-witness vote deltas incrementally as votes are cast (instead of recomputing from a full store scan per RPC call), or bound/paginate the `VotesStore` scan, or gate this expensive computation behind stricter rate limiting tied to actual computational cost rather than request count.

  public WitnessList getPaginatedNowWitnessList(long offset, long limit) throws
      MaintenanceUnavailableException {
    if (limit <= 0 || offset < 0) {
      return null;
    }
    if (limit > WITNESS_COUNT_LIMIT_MAX) {
      limit = WITNESS_COUNT_LIMIT_MAX;
    }

    /*
      In the maintenance period, the VoteStores will be cleared.
      To avoid the race condition of VoteStores deleted but Witness vote counts not updated,
      return retry error.
      Only apply to requests that rely on the latest block,
      which means the normal fullnode requests with HEAD cursor.
    */
    boolean isMaintenance = chainBaseManager.getDynamicPropertiesStore().getStateFlag() == 1;
    if (isMaintenance && !Args.getInstance().isSolidityNode() && getCursor() == Cursor.HEAD) {
      String message =
          "Service temporarily unavailable during maintenance period. Please try again later.";
      throw new MaintenanceUnavailableException(message);
    }
    // It contains the final vote count at the end of the last epoch.
    List<WitnessCapsule> witnessCapsuleList = chainBaseManager.getWitnessStore().getAllWitnesses();
    if (offset >= witnessCapsuleList.size()) {
      return null;
    }

    VotesStore votesStore = chainBaseManager.getVotesStore();
    // Count the vote changes for each witness in the current epoch, it is maybe negative.
    Map<ByteString, Long> countWitness = countVote(votesStore);

    // Iterate through the witness list to apply vote changes and calculate the real-time vote count
    witnessCapsuleList.forEach(witnessCapsule -> {
      long voteCount = countWitness.getOrDefault(witnessCapsule.getAddress(), 0L);
      witnessCapsule.setVoteCount(witnessCapsule.getVoteCount() + voteCount);
    });

    // Use the same sorting logic as in the Maintenance period
    WitnessStore.sortWitnesses(witnessCapsuleList,
        chainBaseManager.getDynamicPropertiesStore().allowWitnessSortOptimization());

    List<WitnessCapsule> sortedWitnessList = witnessCapsuleList.stream()
        .skip(offset)
        .limit(limit)
        .collect(Collectors.toList());

    WitnessList.Builder builder = WitnessList.newBuilder();
    sortedWitnessList.forEach(witnessCapsule ->
        builder.addWitnesses(witnessCapsule.getInstance()));

    return builder.build();
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }
