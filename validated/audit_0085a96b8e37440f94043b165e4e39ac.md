## Analog Found

The external report's core bug class — a protocol trusting a contract's "implementation" (class/logic) that can change without validation, breaking downstream invariants — has a direct analog in this repo's `replace_class` syscall handling, where the Starknet OS's Cairo implementation is missing a declared-class check that the Rust `blockifier` execution enforces.

### Title
Starknet OS `execute_replace_class` omits declared-class-hash validation performed by blockifier, enabling state root divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
Any contract can call the `replace_class` syscall to swap its own class hash — Starknet's built-in "upgradeable proxy" primitive, directly analogous to a TUSD-style implementation swap. `blockifier`'s Rust syscall handler requires the target class to be declared before allowing the swap, but the Starknet OS's Cairo re-implementation of the same syscall — used to independently re-execute/prove blocks — does not perform this check.

### Finding Description
In blockifier, the `replace_class` syscall handler explicitly reads the compiled class first, which fails if the class is undeclared, before permitting the class-hash write: [1](#0-0) 

This is also validated in tests, both for deprecated and current syscalls, confirming "is not declared" errors are enforced for undeclared class hashes: [2](#0-1) [3](#0-2) 

However, the Starknet OS Cairo implementation of the same syscall — used for independent re-execution/proving of the block (Cairo 1 path) — writes the new `StateEntry` with the requested `class_hash` directly into `contract_state_changes`, with an explicit developer TODO acknowledging the missing check: [4](#0-3) 

The deprecated (Cairo 0) syscall path in the OS has the identical gap — no declared-class verification before the class hash is committed to the state diff: [5](#0-4) 

Because `execute_replace_class` is reachable from any account/contract's `__execute__` via a normal invoke transaction (both Cairo 0 and Cairo 1 dispatch tables route `REPLACE_CLASS_SELECTOR` here): [6](#0-5) [7](#0-6) 

any unprivileged transaction sender can trigger the code path where the OS's re-execution logic and blockifier's node-level execution logic diverge in their acceptance criteria for the very same syscall.

### Impact Explanation
This is the Cairo-language protocol counterpart of the reported bug class: a contract's "implementation" (class hash) can be swapped, and the piece of the system responsible for validating that swap (the OS, analogous to the "protocol" trusting the token's proxy) fails to re-verify that the new implementation is legitimately declared. Since the Starknet OS is the component that independently re-derives and attests to the correctness of a block's state transition (feeding the state/root commitment that is ultimately proven and accepted), a gap here means the OS's model of "valid replace_class execution" is broader than blockifier's, i.e. honest-node (blockifier) semantics and OS semantics for the identical syscall are not aligned. This directly maps to the "wrong committed root" / "honest-node divergence" impact category: state resulting from OS-driven verification can admit contract class assignments that blockifier itself would never permit as a state transition.

### Likelihood Explanation
The syscall is trivially reachable — no special privilege, no external dependency, just a `replace_class_syscall(class_hash)` call from ordinary Cairo contract code, and the gap is explicitly documented in-code via a `TODO(Yoni, 1/1/2026)` comment confirming the check is intentionally deferred rather than accidentally missing, i.e. it is a known, currently-unaddressed gap in the shipped OS logic for both Cairo 0 and Cairo 1 execution paths.

### Recommendation
Add the same "is the target class hash declared" verification in the Cairo OS's `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that `blockifier`'s Rust `replace_class` handler performs (i.e., assert existence/success of a compiled-class lookup for `request.class_hash`/`syscall_ptr.class_hash` before writing the new `StateEntry`), so that OS re-execution and blockifier execution enforce identical acceptance criteria for this syscall.

### Proof of Concept
1. Deploy any Cairo 1 contract exposing a function that calls `replace_class_syscall(UNDECLARED_CLASS_HASH)` where `UNDECLARED_CLASS_HASH` has never been declared on-chain.
2. Submit an ordinary invoke transaction from any account calling this function.
3. Observe that blockifier rejects/reverts the call with `"is not declared"` (per `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
4. Trace the equivalent Cairo OS execution path (`execute_replace_class` in `syscall_impls.cairo`/`deprecated_execute_syscalls.cairo`): no equivalent existence check is present before `dict_update` commits the new `StateEntry.class_hash`, confirming the OS would accept a state transition that blockifier's canonical execution logic does not.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
