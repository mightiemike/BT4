### Title
Unauthenticated, fee-free, unlimited class declarations via the `BOOTSTRAP` declare bypass path - ([File: crates/blockifier/src/transaction/account_transaction.rs], [File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/transaction_impls.cairo], [File: crates/starknet_api/src/executable_transaction.rs])

### Summary
Both the blockifier and the Starknet OS contain a special "bootstrap declare" fast path intended for chain genesis: a `Declare` transaction whose `sender_address` equals the magic constant `'BOOTSTRAP'`, whose `nonce == 0`, and whose fee is zero is executed with **no `__validate_declare__` call, no fee charge, and no nonce increment**. Because the gate is purely a data-comparison on attacker-controlled transaction fields (sender address, nonce, resource bounds) rather than a genuine "only once, only at genesis" state check, any unprivileged transaction sender can repeatedly construct such transactions to declare arbitrary new classes for free, indefinitely, bypassing the protocol's fee and resource-accounting model — the same root-cause pattern as the Derby bug (a state check using a value, here "nonce 0 / no-fee sender", that is valid both for the legitimate one-time initial case and for arbitrary repeated abuse).

### Finding Description
`DeclareTransaction::is_bootstrap_declare` treats any V3 declare as a bootstrap declare purely based on request-controlled fields: [1](#0-0) 

`bootstrap_address()` is a publicly known constant (`felt` of the ASCII string `'BOOTSTRAP'`), not an address protected by any private key or deployment check — so any external actor can set `sender_address` to this value in a transaction they craft themselves.

In the blockifier, when `is_bootstrap_declare` is true, `AccountTransaction::execute_raw` skips `perform_pre_validation_stage` (nonce/fee checks), skips `run_validate`, and skips fee handling entirely, running only the class-declaration side effect: [2](#0-1) 

The Starknet OS mirrors this exact bypass at the Cairo level in `execute_declare_transaction`: it checks `sender_address == 'BOOTSTRAP' and tx_info.nonce == 0 and tx_info.version == 3` and `max_possible_fee == 0`, then updates the class dictionary and explicitly skips `check_and_increment_nonce`: [3](#0-2) 

Because the nonce for the `BOOTSTRAP` sender is never incremented, the account's nonce remains permanently `0`. This is explicitly acknowledged in code comments and tests: the same bootstrap tx nonce (0) can always be resubmitted, and successful execution does not remove the transaction from the mempool the normal way: [4](#0-3) [5](#0-4) 

The only per-class protection is the Cairo dict's `prev_value=0` assertion, which prevents *re-declaring the same class hash* twice, but does nothing to prevent declaring a *new, distinct* class hash from the same `BOOTSTRAP` sender at nonce 0 in a subsequent block, since nothing marks the bootstrap mechanism as "used up" after genesis: [6](#0-5) 

Test coverage confirms the mechanics: a bootstrap declare with `resource_bounds` all zero and no signature is accepted and produces a state diff with only `compiled_class_hashes`/`declared_contracts` changes — no fee transfer, no nonce bump: [7](#0-6) 

### Impact Explanation
Any unprivileged party can, at any point (not only genesis), submit `Declare` transactions with `sender_address = bootstrap_address()`, `nonce = 0`, and zero resource bounds, and have arbitrary Sierra classes declared and compiled by the sequencer/OS for **zero fee**. This breaks the protocol's fee and resource-accounting invariant (all state-changing, resource-consuming transactions must pay for their resource usage), letting an attacker force the sequencer/prover to compile and store arbitrary classes (a non-trivial, gas-metered operation under normal circumstances) at no cost, on an ongoing basis for the lifetime of the chain — not just at chain start-up. This is a fee/resource-accounting bypass reachable purely from a submitted transaction, matching the allowed category of "fee and resource accounting" and "bouncer weights" bugs, and can be used to degrade sequencer throughput/cost economics or to grief the declared-class storage without paying for it.

### Likelihood Explanation
Likelihood is high: constructing the transaction requires no special privilege — only knowledge of the public `bootstrap_address()` constant, a valid Sierra class with a self-consistent class hash/compiled-class hash pair, and setting `resource_bounds` so `compute_max_possible_fee == 0`. All of this is fully attacker-controlled and requires no signature (validation is explicitly skipped). The mempool's per-account single-pending-nonce restriction only throttles the rate (roughly one new class every couple of blocks, since the address's nonce never advances and the previously-included tx is evicted after failing on resubmission), but does not prevent unbounded repeated abuse over time.

### Recommendation
Gate the bootstrap-declare fast path on genuine chain state rather than solely on attacker-supplied transaction fields:
- Restrict the bypass to a specific, verifiable bootstrap window (e.g., only accepted while a dedicated "bootstrap not yet completed" flag/marker in state is unset, and clear that marker permanently after first use), rather than relying on the sender's nonce staying at 0 forever.
- Alternatively, require the bootstrap declare mechanism to be gated by block number (e.g., only valid in block 0) or by an explicit one-time consensus/admin action, so it cannot be reused arbitrarily by any external transaction sender after genesis.
- Ensure both the blockifier (`account_transaction.rs`) and Starknet OS (`transaction_impls.cairo`) enforce this the same way, since the OS re-execution must independently reject bootstrap declares outside the legitimate window to preserve state-root consistency.

### Proof of Concept
1. Craft a `DeclareTransactionV3` with:
   - `sender_address = ContractAddress::from(0x424f4f545354524150_u128)` (`'BOOTSTRAP'`, per `crates/starknet_api/src/executable_transaction.rs:260-263`).
   - `nonce = Nonce(Felt::ZERO)`.
   - `resource_bounds` such that `compute_max_possible_fee == 0` (e.g., `ValidResourceBounds::create_for_testing_no_fee_enforcement()`, as used in `generate_bootstrap_declare` at `crates/mempool_test_utils/src/starknet_api_test_utils.rs:585-595`).
   - `class_hash`/`compiled_class_hash` for any valid, self-consistent Sierra/CASM class the attacker wants declared.
   - No signature (validation is skipped).
2. Submit it through the gateway; `is_bootstrap_declare` returns true, so `execute_raw` skips pre-validation, `__validate_declare__`, and fee charging (`crates/blockifier/src/transaction/account_transaction.rs:899-912`), and the class is declared for free.
3. Because the nonce is never incremented, repeat with a different `class_hash` (still `nonce = 0`) in a subsequent block once the mempool has evicted the prior bootstrap tx, and the new arbitrary class is declared again for free — with no fee ever charged and no requirement that this only happens once at genesis.

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.

        // A felt representation of the string 'BOOTSTRAP'.

        // meet the following conditions.
        // This flow is used for the sequencer to bootstrap a new system.
        // Note: The absence of any account-related action leads to some unintuitive but expected
        // behavior:
        // - After the transaction is executed successfully, the batcher does not notify the mempool
        //   about its inclusion in a block. As a result, the transaction remains in the mempool.
        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.
        // - The transaction will then be marked as rejected, the mempool will be notified, and the
        //   transaction will be removed from the mempool.
        if let Transaction::Declare(tx) = &self.tx {

                    tx_context.clone(),
                    self.execution_flags.charge_fee,

                assert!(res.is_none(), "Declare execute should not result in a CallInfo.");

fn test_bootstrap_declare(
    block_context: BlockContext,
    #[case] declare_tx: DeclareTransaction,
    #[case] hash_version: HashVersion,
) {
    let class_info = calculate_class_info_for_testing(
        FeatureContract::Empty(CairoVersion::Cairo1(RunnableCairo1::Casm)).get_class(),
    );
    let contract_class = class_info.contract_class();
    let mut executable_declare = ApiExecutableDeclareTransaction {
        tx: declare_tx.clone(),
        tx_hash: TransactionHash::default(),
        class_info,
    };

    // Update compiled_class_hash in V3 declare txs to match the contract class with the given hash
    // version.
    if let DeclareTransaction::V3(tx) = &mut executable_declare.tx {
        if let ContractClass::V1((casm, _)) = &contract_class {
            tx.compiled_class_hash = casm.hash(&hash_version);
        }
    }
    let compiled_class_hash = executable_declare.tx.compiled_class_hash();
    let declare_account_tx = AccountTransaction::new_for_sequencing(
        ApiExecutableTransaction::Declare(executable_declare),
    );

    let mut state = CachedState::from(DictStateReader::default());
    let res = declare_account_tx.execute(&mut state, &block_context).unwrap();

    // Check declaration.
    assert_eq!(
        state.get_compiled_class_hash(declare_tx.class_hash()).unwrap(),
        compiled_class_hash
    );

    // Ensure the only change is the class declaration: no fees, nonce bump, etc.
    assert_eq!(res, TransactionExecutionInfo::default());
    assert_eq!(
        state.to_state_diff().unwrap().state_maps,
        StateMaps {
            compiled_class_hashes: HashMap::from([(declare_tx.class_hash(), compiled_class_hash)]),
            declared_contracts: HashMap::from([(declare_tx.class_hash(), true)]),
            ..Default::default()
        }
    );
}
