### Title
Unit-inconsistent `queryDelegatableResource` estimate diverges from `DelegateResourceProcessor`/`DelegateResourceActuator` enforcement, causing DoS-by-revert for TVM contracts - (File: `actuator/src/main/java/org/tron/core/vm/utils/FreezeV2Util.java`)

### Summary
`FreezeV2Util.queryDelegatableResource()` is an estimation/query helper (exposed to TVM contracts through a native/precompiled contract path, per `PrecompiledContracts.java` and `Repository`/`RepositoryImpl` references) that computes "how much frozen balance an account can currently delegate." The real enforcement of this cap lives in `DelegateResourceActuator.validate()` and `DelegateResourceProcessor.validate()`. These two code paths compute the "used" portion of the resource with different formulas/units, so the estimate returned by the query function can overstate what is actually delegatable, exactly analogous to the reported `max_flashloan` bug where an estimation function ignored a cap enforced elsewhere.

### Finding Description
In the enforcement path (`DelegateResourceActuator.validate()`, mirrored in `DelegateResourceProcessor.validate()`), the "used" resource is explicitly rescaled from bandwidth/energy usage units into TRX-equivalent frozen-balance units before being subtracted from the frozen balance: [1](#0-0) 

```
long accountNetUsage = ownerCapsule.getNetUsage();
...
long netUsage = (long) (accountNetUsage * TRX_PRECISION * ((double)
    (dynamicStore.getTotalNetWeight()) / dynamicStore.getTotalNetLimit()));
long v2NetUsage = getV2NetUsage(ownerCapsule, netUsage, this.disableJavaLangMath());
if (ownerCapsule.getFrozenV2BalanceForBandwidth() - v2NetUsage < delegateBalance) {
  throw new ContractValidateException(
      "delegateBalance must be less than or equal to available FreezeBandwidthV2 balance");
}
``` [2](#0-1) 

The scaling factor `TRX_PRECISION * (totalWeight / totalLimit)` converts "bandwidth points used" into "TRX (sun) equivalent frozen balance consumed", which is required because `frozenV2Resource` (a TRX balance) and raw bandwidth/energy usage (a points count) are not directly comparable.

By contrast, `queryDelegatableResource()` — the function a TVM contract calls to estimate the delegatable amount before issuing a delegate call — uses the raw usage value from `getAccountNetUsageBalanceAndRestoreSeconds`/`getAccountEnergyUsageBalanceAndRestoreSeconds` directly, without applying that same TRX_PRECISION/weight-ratio rescaling: [3](#0-2) 

```
long frozenV2Resource = accountCapsule.getFrozenV2BalanceForBandwidth();
Pair<Long, Long> usagePair =
    repository.getAccountNetUsageBalanceAndRestoreSeconds(accountCapsule);
...
long usage = usagePair.getLeft();
...
long v2NetUsage = getV2NetUsage(accountCapsule, usage, VMConfig.disableJavaLangMath());
return max(0L, frozenV2Resource - v2NetUsage, VMConfig.disableJavaLangMath());
```

Both call the shared helper `getV2NetUsage`/`getV2EnergyUsage` in `FreezeV2Util.java`: [4](#0-3) 

but the input `netUsage`/`energyUsage` passed to it differs in units between the query path (raw usage) and the enforcement path (usage rescaled by `TRX_PRECISION * totalWeight/totalLimit`). This is the same root-cause pattern as the external report: an amount-estimation function omits a factor (there: the PSP22Capped cap; here: the TRX_PRECISION/weight ratio conversion) that the actual state-transition/validation logic enforces, so the value returned by the estimator is not trustworthy for driving a subsequent state-changing call.

### Impact Explanation
A smart contract (or off-chain caller relying on this exposed native/precompiled query) that reads `queryDelegatableResource` and then issues a `DelegateResourceContract`/native `delegateResource` call for the returned amount can have that call rejected by `ContractValidateException` in `DelegateResourceActuator.validate()`/`DelegateResourceProcessor.validate()`, because the actual enforced cap (computed with the correct unit conversion) is smaller than the value reported by the query function. This is a functional-correctness/DoS-by-revert issue for any contract logic built on top of this "trusted" on-chain estimate — consuming energy/fees for a transaction that is guaranteed to fail, and breaking composability of TVM contracts that rely on the query result to size their delegate calls.

### Likelihood Explanation
This is reachable by any account or contract triggering a `TriggerSmartContract` that calls the delegatable-resource query opcode/precompile and then chains a `delegateResource` call, or by any external tooling built on the exposed RPC/precompile that surfaces `queryDelegatableResource`. No privileged role is required — it is triggerable by an ordinary broadcast transaction. However, whether the discrepancy manifests depends on whether `accountNetUsage`/`energyUsage` is non-zero at query time (when usage is 0, both formulas return the same frozen balance), so the practical trigger rate depends on account resource-consumption history.

### Recommendation
Align `queryDelegatableResource()` in `FreezeV2Util.java` with the exact formula used in `DelegateResourceActuator.validate()` / `DelegateResourceProcessor.validate()`: rescale the raw usage returned from `getAccountNetUsageBalanceAndRestoreSeconds`/`getAccountEnergyUsageBalanceAndRestoreSeconds` by `TRX_PRECISION * (totalNetWeight/totalNetLimit)` (or the energy equivalent) before passing it into `getV2NetUsage`/`getV2EnergyUsage`, so that the value returned to callers matches the value the enforcement path will actually accept. Add a regression test asserting `queryDelegatableResource(...) <= actual max amount accepted by DelegateResourceActuator.validate()` for an account with non-zero bandwidth/energy usage.

  public static long queryDelegatableResource(byte[] address, long type, Repository repository) {
    if (!VMConfig.allowTvmFreezeV2()) {
      return 0L;
    }

    AccountCapsule accountCapsule = repository.getAccount(address);
    if (accountCapsule == null) {
      return 0L;
    }

    if (type == 0) {
      // self frozenV2 resource
      long frozenV2Resource = accountCapsule.getFrozenV2BalanceForBandwidth();

      // total Usage.
      Pair<Long, Long> usagePair =
          repository.getAccountNetUsageBalanceAndRestoreSeconds(accountCapsule);
      if (usagePair == null || usagePair.getLeft() == null) {
        return frozenV2Resource;
      }

      long usage = usagePair.getLeft();
      if (usage <= 0) {
        return frozenV2Resource;
      }

      long v2NetUsage = getV2NetUsage(accountCapsule, usage, VMConfig.disableJavaLangMath());
      return max(0L, frozenV2Resource - v2NetUsage, VMConfig.disableJavaLangMath());
    }

    if (type == 1) {
      // self frozenV2 resource
      long frozenV2Resource = accountCapsule.getFrozenV2BalanceForEnergy();

      // total Usage.
      Pair<Long, Long> usagePair =
          repository.getAccountEnergyUsageBalanceAndRestoreSeconds(accountCapsule);
      if (usagePair == null || usagePair.getLeft() == null) {
        return frozenV2Resource;
      }

      long usage = usagePair.getLeft();
      if (usage <= 0) {
        return frozenV2Resource;
      }

      long v2EnergyUsage = getV2EnergyUsage(accountCapsule, usage, VMConfig.disableJavaLangMath());
      return max(0L, frozenV2Resource - v2EnergyUsage, VMConfig.disableJavaLangMath());
    }

    return 0L;
  }

  public static long getV2NetUsage(AccountCapsule ownerCapsule, long netUsage, boolean
      disableJavaLangMath) {
    long v2NetUsage= netUsage
        - ownerCapsule.getFrozenBalance()
        - ownerCapsule.getAcquiredDelegatedFrozenBalanceForBandwidth()
        - ownerCapsule.getAcquiredDelegatedFrozenV2BalanceForBandwidth();
    return max(0, v2NetUsage, disableJavaLangMath);
  }

  public static long getV2EnergyUsage(AccountCapsule ownerCapsule, long energyUsage, boolean
      disableJavaLangMath) {
    long v2EnergyUsage= energyUsage
          - ownerCapsule.getEnergyFrozenBalance()
          - ownerCapsule.getAcquiredDelegatedFrozenBalanceForEnergy()
          - ownerCapsule.getAcquiredDelegatedFrozenV2BalanceForEnergy();
    return max(0, v2EnergyUsage, disableJavaLangMath);
  }
