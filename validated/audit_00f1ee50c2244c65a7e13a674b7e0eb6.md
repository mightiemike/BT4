### Title
Missing declared-class check in Starknet OS `execute_replace_class` allows OS trace to diverge from Blockifier execution - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall does not verify that the target `class_hash` corresponds to a declared class before updating a contract's class pointer in `contract_state_changes`. The Rust/Blockifier execution path (used by the sequencer to actually produce state diffs) *does* enforce this check. This mirrors the reported bug class: a state-mutating operation ("migration" of a contract's class pointer) that is missing a safeguard its own code comments/other implementations say must exist, creating an inconsistency between the two components that must agree bit-for-bit on the resulting state.

### Finding Description
The `replace_class` syscall lets any deployed contract change which class hash its address points to, reachable from any unprivileged invoke transaction. In Blockifier (the component that actually executes transactions and produces the canonical state diff), the syscall handler explicitly checks that the class is declared before updating storage: [1](#0-0) 

and the Cairo1 native/VM implementation similarly delegates to `base.replace_class`, which is exercised by unit tests confirming an "is not declared" error is raised for undeclared class hashes: [2](#0-1) 

In contrast, the Starknet OS's own Cairo implementation of the same syscall, `execute_replace_class` (used during OS re-execution/proving of the block), explicitly skips this validation, marked with an open TODO: [3](#0-2) 

The same gap exists in the deprecated (Cairo0) execution path of the OS: [4](#0-3) 

Because the Starknet OS is the component that re-executes/proves the block and independently derives `contract_state_changes` (which becomes part of the committed state diff / Patricia tree update and block hash/commitment computation), any semantic difference between what Blockifier accepts/rejects and what the OS accepts/rejects is a divergence risk in the pipeline that is specifically responsible for proving state-transition correctness.

### Impact Explanation
If Blockifier and the OS ever disagree on whether a given `replace_class` call is valid (e.g., due to a difference in timing of class declaration visibility, differing class-hash version handling, or any code path where the OS's hint-driven state read `GetContractAddressStateEntry` and the Blockifier's actual `get_compiled_class` check are not perfectly synchronized), the OS could silently accept a state transition that Blockifier would have reverted, or vice versa. This is a state/commitment divergence bug class: the OS is meant to be the source of truth that proves the sequencer's claimed state transition is correct; a missing invariant check in the OS means the OS's proof does not actually enforce "target class exists," unlike the real execution engine. This can result in a contract's class hash being set to an undeclared/nonexistent value in the committed state (permanently bricking or redirecting a contract to no-code) being accepted by the proving pipeline, or in an honest-node divergence between different implementations of the OS/Blockifier pair regarding what states are valid, undermining the trustworthiness of the committed state root.

### Likelihood Explanation
The `replace_class` syscall is trivially reachable by any contract from any unprivileged invoke transaction, so the missing check is on a directly attacker-triggerable syscall path, not a privileged/operator-only path. The check's absence is also self-acknowledged in the code via a `TODO` comment, confirming this is a real gap in the OS logic rather than an intentional design choice. Exploitability, however, depends on finding a concrete scenario in which the OS accepts an undeclared class hash that Blockifier would have rejected — this specific triggering condition (i.e., how the OS's `%{ GetContractAddressStateEntry }` hint and the wider proof-input construction guarantee or fail to guarantee that only Blockifier-validated `contract_state_changes` reach the OS) could not be fully confirmed from the available code; it depends on hint/prover harness code and on how state changes are packaged as OS input, which is outside the indexed Cairo/hint files reviewed here.

### Recommendation
Add the same declared-class-hash check to the OS's `execute_replace_class` (and the deprecated syscalls equivalent) that Blockifier performs, i.e., verify (via a hint and corresponding assertion in Cairo) that a compiled class fact exists for `class_hash` before writing the new `StateEntry`. Add explicit OS-level tests (analogous to `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`) covering replace-class with an undeclared class hash, to ensure the OS rejects (or provably-cannot represent) any state diff that Blockifier itself would not have produced.

### Proof of Concept
Not independently verified end-to-end (would require running the OS re-execution harness against a crafted block containing a `replace_class` syscall to an undeclared class hash). The static code evidence establishing the root cause is:
1. Blockifier enforces the check and reverts: [5](#0-4) 
2. OS `execute_replace_class` performs no such check and contains an explicit TODO acknowledging the gap: [6](#0-5)

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
