### Title
Unbounded, unpaginated prefix-scan-and-sort in `DelegatedResourceAccountIndexStore.getWithPrefix` combined with cost-unaware rate limiting enables RPC-API DoS - ([File: chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java])

### Summary
`getWithPrefix()` performs two full LevelDB/RocksDB prefix scans and in-memory `Comparator`-based sorts synchronously inside the servlet/gRPC handler thread, with no limit on the number of entries returned or processed. Because the node's rate limiters (`GlobalRateLimiter`, `RateLimiterServlet`) are strictly request-count/QPS based and have no notion of per-request computational cost, an attacker who has first inflated one address's delegation index (via repeated cheap `delegateResource`/`unDelegateResource` calls) can issue a burst of `getdelegatedresourceaccountindexv2`/`GetDelegatedResourceAccountIndex` requests that each cost far more CPU/I/O than an average request, exhausting the handler thread pool while staying within nominal QPS limits.

### Finding Description
The query path is: `GetDelegatedResourceAccountIndexServlet.doGet/doPost` and `GetDelegatedResourceAccountIndexV2Servlet.doGet/doPost` call `wallet.getDelegatedResourceAccountIndex(V2)` [1](#0-0) [2](#0-1) , which reaches `DelegatedResourceAccountIndexStore.getIndex`/`getV2Index`, both delegating to `getWithPrefix` [3](#0-2) .

`getWithPrefix` runs `this.prefixQuery(key).values()` (a full underlying key-prefix scan of the DB), wraps the result in a new `ArrayList`, and sorts it with `Comparator.comparing(...)` twice — once for the "to" list and once for the "from" list — entirely synchronously on the calling request-handling thread, with no cap on the number of returned entries and no pagination [4](#0-3) .

The servlets extend `RateLimiterServlet`, and the platform-wide rate limiting is implemented purely as QPS counters: a global QPS limiter, a per-IP QPS limiter, and per-endpoint QPS limiter, all configured under `rate.limiter` in `reference.conf`/`config.conf` [5](#0-4)  and enforced by `GlobalRateLimiter.tryAcquire/acquire`, which simply calls Guava `RateLimiter.tryAcquire()`/`acquire()` per request without any weighting for scan size or response cost [6](#0-5) . There is no mechanism anywhere in this path that limits the number of delegation index entries an address may accumulate, nor any pagination/result-size cap on the read API — `GetCanDelegatedMaxSizeServlet`/`getCanDelegatedMaxSize` bounds delegatable *resource amount*, not delegation *record count*, so it does not mitigate this. As a result, requests against an address with a large delegation index consume proportionally more CPU (scan + sort) and heap (materializing the full result list) than a "normal" request, but are billed identically by the QPS-based limiter — i.e., cost amplification defeats the rate limiter's intended fairness guarantee.

### Impact Explanation
This is a DoS-via-RPC-API vector (matches TRON bounty's "DoS via RPC-API" impact class): a burst of full-cost, unpaginated prefix-scan+sort requests against a pre-inflated address can occupy HTTP/gRPC handler threads and drive up CPU/heap usage disproportionately to the attacker's rate-limited request count, degrading or stalling `GetDelegatedResourceAccountIndex(V2)` (and potentially the shared thread pool) for other unprivileged clients. It does not cause consensus divergence, asset loss, or key leakage — impact is confined to node/API availability.

### Likelihood Explanation
Preconditions are default-config only: default `rate.limiter` settings are request-count/QPS based (`global.qps=50000`, `global.ip.qps=10000`, `global.api.qps=1000`, no cost-aware or payload-size-aware strategy configured by default) [7](#0-6) . The attacker needs no privileged role — only the ability to broadcast delegate/undelegate transactions from a funded account (covered by the related question) and to send anonymous HTTP/gRPC read requests, both of which are default unprivileged capabilities. Repeatability is high since the expensive index persists in the store until explicitly cleaned up (undelegate removes entries but building it up again is cheap), and each read request is independent and repeatable at will.

### Recommendation
- Add pagination (offset/limit) and an enforced maximum result size to `getWithPrefix`/`getIndex`/`getV2Index` so a single request cannot force scanning/sorting an unbounded number of entries.
- Consider capping or streaming the prefix scan instead of materializing/sorting the full result set in memory on the handler thread.
- Extend rate limiting/QPS accounting to account for response size or backing store scan cost (e.g., a cost-aware or token-bucket-with-weight strategy) for these endpoints, or apply a stricter per-endpoint concurrency limit (`GlobalPreemptibleAdapter`) to `GetDelegatedResourceAccountIndexServlet`/`V2Servlet` and the corresponding gRPC methods by default.

```java
// JUnit-style load test against DelegatedResourceAccountIndexStore
@Test
public void testUnboundedPrefixScanCost() {
  byte[] victim = new ECKey().getAddress();
  // Precondition: attacker inflates the index (see related finding) by
  // repeatedly calling delegateV2()/unDelegateV2() with N unique counterparties
  for (int i = 0; i < 100_000; i++) {
    byte[] to = new ECKey().getAddress();
    delegatedResourceAccountIndexStore.delegateV2(victim, to, i);
  }

  ExecutorService pool = Executors.newFixedThreadPool(50);
  long start = System.nanoTime();
  List<Future<?>> futures = new ArrayList<>();
  for (int i = 0; i < 200; i++) {
    futures.add(pool.submit(() ->
        delegatedResourceAccountIndexStore.getV2Index(victim)));
  }
  for (Future<?> f : futures) f.get();
  long elapsed = System.nanoTime() - start;

  // Assert: elapsed time scales with attacker-controlled N (100k entries),
  // not bounded by any pagination/result cap, demonstrating that each
  // QPS-limited request consumes disproportionate CPU/heap.
  assertTrue(elapsed > TimeUnit.SECONDS.toNanos(1)); // scales with N, unbounded
}
```

```java
  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }
```

```java
  public static boolean tryAcquire(RuntimeData runtimeData) {
    String ip = runtimeData.getRemoteAddr();
    if (!Strings.isNullOrEmpty(ip)) {
      RateLimiter r = loadIpLimiter(ip);
      if (r == null || !r.tryAcquire()) {
        return false;
      }
    }
    return rateLimiter.tryAcquire();
  }

  public static boolean acquire(RuntimeData runtimeData) {
    String ip = runtimeData.getRemoteAddr();
    if (!Strings.isNullOrEmpty(ip)) {
      RateLimiter r = loadIpLimiter(ip);
      if (r == null) {
        return false;
      }
      r.acquire();
    }
    rateLimiter.acquire();
    return true;
  }
```
