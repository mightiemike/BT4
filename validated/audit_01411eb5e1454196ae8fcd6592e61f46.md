## Title
Unbounded recursion in compiled-class bytecode-segment hashing/structuring enables stack-exhaustion DoS from a single Declare transaction - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`, `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`)

### Summary
`bytecode_hash_node` (compiled_class_hash.rs) and `create_bytecode_segment_structure_inner` (starknet_os utils.rs) recursively walk a `NestedIntList`/`bytecode_segment_lengths` tree with **no depth bound**, mirroring the CVE-2019-9903 pattern (`Dict::find`/`markObject` recursing without a limit on attacker-controlled nesting, causing stack exhaustion). Here the nesting depth is derived from a `CasmContractClass.bytecode_segment_lengths` field embedded in a compiled class, which is produced when compiling an attacker-declared Sierra program via `SierraCompiler::compile` [1](#0-0) .

### Finding Description
`bytecode_hash_node` recurses once per nesting level of the `HashableNestedIntList` tree with no depth check: [2](#0-1) 

It is invoked from `hash_inner`, which is the compiled-class hash routine used for every `ContractClass::V1` (`ContractClass::compiled_class_hash`) and from `SierraCompiler::compile` immediately after Sierra→CASM compilation of a **declarer-submitted** class: [3](#0-2) [1](#0-0) 

The equivalent structure-building routine used by the Starknet OS / re-execution path is likewise recursive with no bound: [4](#0-3) 

Contrast this with the blockifier's own equivalent builder (`NestedFeltCounts::new_inner`), which explicitly restricts segmentation depth to at most 1 via an `assert!`: [5](#0-4) 
This assert shows the developers are aware that unbounded segmentation depth is a hazard elsewhere in the codebase, but the OS hint helper (`create_bytecode_segment_structure_inner`) and the shared `bytecode_hash_node` in `starknet_api` carry no such guard.

Unlike Cairo/Sierra execution (calldata, entry-point calls), which is protected by `RecursionDepthGuard` and step/gas metering [6](#0-5) , this hashing/structuring code runs **outside** the VM's resource-accounting loop — it executes once per declare (during compilation/hashing, before/at admission) and once per OS re-execution of any block containing that declare, with no equivalent step counter or recursion-depth cap.

### Impact Explanation
If a class declarer can craft a `CasmContractClass` (via the normal Sierra→CASM compilation flow, or directly if `bytecode_segment_lengths` metadata can be influenced/round-tripped through storage) whose `bytecode_segment_lengths` nests to a depth sufficient to exhaust the thread stack, then:
- Every full node/sequencer computing the compiled-class hash for that declare (gateway ingestion, class manager, mempool/blockifier hashing, and later Starknet OS re-execution/proving of the block that includes the declare) will recurse to that depth.
- A stack overflow in this shared, non-gas-metered code path aborts the process (or corrupts execution), producing a crash of the sequencer/prover process handling that transaction — i.e., a network unable to process/confirm the block containing the malicious declare, and a divergence risk between nodes that crash vs. survive due to differing stack limits (similar to the `RUST_MIN_STACK` tuning already present for entry-point recursion, showing stack size is a known fragile parameter) [7](#0-6) .
- This satisfies the "network unable to confirm new transactions" / crash-DoS bar for a Medium-severity analog, reachable purely from a normal declare submitted by an unprivileged account.

### Likelihood Explanation
Likelihood is **uncertain and only partially confirmed**: I was not able to verify within the available tool budget (1) whether `bytecode_segment_lengths` produced by the actual Cairo compiler used here (`cairo_lang_starknet_classes`) can be made arbitrarily deep from a Sierra program of bounded size that also passes `max_contract_bytecode_size` / `max_contract_class_object_size` gateway checks [8](#0-7) , and (2) whether the compiler enforces any internal cap on segmentation depth before emitting this field. Since each nesting level in `NestedIntList::Node` requires at least one felt of bytecode/metadata, achieving stack-overflow depth (typically tens of thousands of frames) may require a very large program, which the size checks above could mitigate — but no explicit recursion-depth limit was found in the reachable Rust code that consumes this structure. This uncertainty means the finding should be treated as a **potential/plausible** analog requiring practical depth-vs-size verification against the real compiler, not a confirmed exploit.

### Recommendation
Add an explicit recursion-depth (or iterative, worklist-based) implementation for `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs`) and `create_bytecode_segment_structure_inner` (`crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`), enforcing the same kind of bound already applied in `NestedFeltCounts::new_inner` (`crates/blockifier/src/execution/contract_class.rs`), and reject/compile-fail any `bytecode_segment_lengths` tree exceeding that bound at class-declaration/compilation time (in `SierraCompiler::compile` or `ClassManager::add_class`) rather than only at hashing time.

### Proof of Concept
Not independently constructed/verified — would require confirming, against the concrete `cairo_lang_starknet_classes` compiler version vendored in this repo, that a Sierra program within the enforced `max_contract_bytecode_size`/`max_contract_class_object_size` limits can produce a `bytecode_segment_lengths` `NestedIntList` nested to a depth sufficient to overflow the default thread stack when passed through `bytecode_hash_node`/`create_bytecode_segment_structure_inner`. This step could not be completed with the available code-search tools.

```rust
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}
```

```rust
/// Computes the compiled class hash for a given hashable class using the specified hash algorithm.
fn hash_inner<H, EH, NL>(hashable_class: &impl HashableCompiledClass<EH, NL>) -> CompiledClassHash
where
    H: StarkHash,
    EH: EntryPointHashable,
    NL: HashableNestedIntList,
{
    let external_funcs_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_external_entry_points());
    let l1_handlers_hash = entry_point_hash::<H, EH>(hashable_class.get_hashable_l1_entry_points());
    let constructors_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_constructor_entry_points());

    let bytecode_hash = bytecode_hash::<H, NL>(
        &hashable_class.get_bytecode(),
        &*hashable_class.get_bytecode_segment_lengths(),
    );

    // Compute total hash by hashing each component on top of the previous one.
    CompiledClassHash(H::hash_array(&[
        *COMPILED_CLASS_V1,
        external_funcs_hash,
        l1_handlers_hash,
        constructors_hash,
        bytecode_hash,
    ]))
}
```

```rust
pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}
```

```rust
// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
```
