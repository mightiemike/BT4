### Title
Any single snapshot-generation error unconditionally halts the entire AccountsBackgroundService, permanently blocking accounts cleaning/shrinking for the whole node - (File: runtime/src/accounts_background_service.rs)

### Summary
The Sherlock finding describes a pattern where a single failure tied to one participant (a blacklisted creditor) is allowed to unconditionally abort a batch operation that should otherwise complete for everyone else, with no fallback path, forcing the whole protocol into an unrecoverable/degraded state. The same "single point of failure blocks the whole batch, no fallback" pattern exists in Agave's `AccountsBackgroundService` main loop: any `Err(SnapshotError)` returned while handling a snapshot request is treated as fatal and stops all future accounts cleaning, shrinking, and snapshotting for the node.

### Finding Description
`AccountsBackgroundService::new` runs a single loop that both handles snapshot requests and drives `clean_accounts`/`shrink_candidate_slots` for the entire validator: [1](#0-0) 

When `handle_snapshot_requests` returns `Some(Err(err))`, the loop unconditionally logs a fatal message, sets `exit` and `break`s out — there is no retry, no isolation of the failing request, and no fallback/escrow-style continuation for the rest of the node's account maintenance: [2](#0-1) 

`SnapshotError` is a broad enum that includes variants that can be triggered by state tied to a single account or a single storage file, e.g. `AccountsFileError`, `Serialize`/`SerializeWincode`, `MismatchedCapitalization`, and `RebuildStorages`: [3](#0-2) 

`handle_snapshot_request` itself calls `bank.clean_accounts()`, `bank.shrink_candidate_slots()`, and builds the `SnapshotPackage` (which computes `accounts_lt_hash`/capitalization over the account set) before returning `Ok`/`Err`: [4](#0-3) 

Because this single `Err` return path is wired to permanently stop the ABS thread (`exit.store(true, ...); break;`), any transient or account-specific issue that surfaces only during snapshot serialization/archiving (I/O error writing one AppendVec, a capitalization mismatch surfaced by one bad/edge-case account, etc.) has the effect of stopping *all* future `clean_accounts`/`shrink_candidate_slots`/snapshot generation for the node — exactly the "one bad actor blocks recovery for everyone, no escrow/fallback" root cause pattern flagged in the Sherlock report, just relocated from a token transfer loop to the accounts-background snapshot/clean/shrink loop.

### Impact Explanation
Once the ABS thread exits, `clean_accounts` and `shrink_candidate_slots` never run again on that node (Bank drop, dead-slot purging, and further snapshot generation are effectively disabled). Storage keeps growing without bound (dirty/dead AppendVecs are no longer reclaimed), and no new full/incremental snapshots can be produced, degrading and eventually forcing a restart of that validator — a disproportionate, irrecoverable-without-restart storage/CPU cost triggered by a single transient failure, analogous to a single blacklisted creditor forcing default with no escrow recovery path.

### Likelihood Explanation
This is reachable on any honest node whenever `handle_snapshot_request` returns an `Err` for reasons unrelated to fundamental corruption — e.g., a transient filesystem I/O error while archiving one snapshot, or any of the listed `SnapshotError` variants. Given the loop already documents that "archiving the snapshot package is not allowed to fail" (as `clean_accounts()` calls downstream depend on it succeeding), the code path is a known, designed hard-stop rather than a hypothetical edge case, making triggering conditions (disk I/O hiccups, serialization edge cases) realistic under normal operational stress.

### Recommendation
Distinguish between errors that indicate unrecoverable corruption (which should legitimately halt the node) and errors that are transient/local to a single snapshot attempt (I/O errors, one-off serialization failures). For the latter class, retry the snapshot request or skip/re-enqueue it while allowing `clean_accounts`/`shrink_candidate_slots` to continue running for the rest of the node's account state, rather than unconditionally calling `exit.store(true, ...); break;` on every `SnapshotError` variant.

### Proof of Concept
1. Instrument or trigger a transient failure inside `serialize_snapshot`/`archive_snapshot_package` (e.g., simulate an `io::Error` on one AppendVec file) so `handle_snapshot_request` returns `Err(SnapshotError::Io(..))`.
2. Observe in `AccountsBackgroundService::new`'s loop that the `Err` arm at [5](#0-4)  unconditionally sets `exit` and breaks, regardless of whether the underlying condition was transient.
3. Confirm that subsequent calls to `clean_accounts`/`shrink_candidate_slots`/snapshot generation never occur again for the life of the process, causing unbounded account storage growth until the validator is manually restarted.

    fn handle_snapshot_request(
        &self,
        non_snapshot_time_us: u128,
        snapshot_request: SnapshotRequest,
        snapshot_kind: SnapshotKind,
    ) -> Result<Slot, SnapshotError> {
        info!("handling snapshot request: {snapshot_request:?}, {snapshot_kind:?}");
        let mut total_time = Measure::start("snapshot_request_receiver_total_time");
        let SnapshotRequest {
            snapshot_root_bank,
            status_cache_slot_deltas,
            request_kind: _,
            enqueued: _,
        } = snapshot_request;

        if snapshot_kind.is_full_snapshot() {
            // The latest full snapshot slot is what accounts-db uses to properly handle
            // zero lamport accounts.  We are handling a full snapshot request here, and
            // since taking a snapshot is not allowed to fail, we can update accounts-db now.
            snapshot_root_bank
                .rc
                .accounts
                .accounts_db
                .set_latest_full_snapshot_slot(snapshot_root_bank.slot());
        }

        let mut flush_accounts_cache_time = Measure::start("flush_accounts_cache_time");
        // Forced cache flushing MUST flush all roots <= snapshot_root_bank.slot().
        // That's because `snapshot_root_bank.slot()` must be root at this point,
        // and contains relevant updates because each bank has at least 1 account update due
        // to sysvar maintenance. Otherwise, this would cause missing storages in the snapshot
        snapshot_root_bank.force_flush_accounts_cache();
        // Ensure all roots <= `self.slot()` have been flushed.
        // Note `max_flush_root` could be larger than self.slot() if there are
        // `> MAX_CACHE_SLOT` cached and rooted slots which triggered earlier flushes.
        assert!(
            snapshot_root_bank.slot()
                <= snapshot_root_bank
                    .rc
                    .accounts
                    .accounts_db
                    .accounts_cache
                    .fetch_max_flush_root()
                    .expect("Roots have been flushed")
        );
        flush_accounts_cache_time.stop();

        let mut clean_time = Measure::start("clean_time");
        snapshot_root_bank.clean_accounts();
        clean_time.stop();

        let (_, shrink_ancient_time_us) = measure_us!(snapshot_root_bank.shrink_ancient_slots());

        let mut shrink_time = Measure::start("shrink_time");
        snapshot_root_bank.shrink_candidate_slots();
        shrink_time.stop();

        // Snapshot the bank and send over a snapshot package
        let mut snapshot_time = Measure::start("snapshot_time");
        let snapshot_package = SnapshotPackage::new(
            snapshot_kind,
            &snapshot_root_bank,
            snapshot_root_bank.get_snapshot_storages(None),
            status_cache_slot_deltas,
        );
        self.pending_snapshot_packages
            .lock()
            .unwrap()
            .push(snapshot_package);
        snapshot_time.stop();
        info!(
            "Handled snapshot request. snapshot kind: {:?}, slot: {}, bank hash: {}",
            snapshot_kind,
            snapshot_root_bank.slot(),
            snapshot_root_bank.hash(),
        );

        total_time.stop();

        datapoint_info!(
            "handle_snapshot_requests-timing",
            (
                "flush_accounts_cache_time",
                flush_accounts_cache_time.as_us(),
                i64
            ),
            ("shrink_time", shrink_time.as_us(), i64),
            ("clean_time", clean_time.as_us(), i64),
            ("snapshot_time", snapshot_time.as_us(), i64),
            ("total_us", total_time.as_us(), i64),
            ("non_snapshot_time_us", non_snapshot_time_us, i64),
            ("shrink_ancient_time_us", shrink_ancient_time_us, i64),
        );
        Ok(snapshot_root_bank.slot())
    }
