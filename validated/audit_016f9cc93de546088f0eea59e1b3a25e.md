### Title
Uncaught NullPointerException in `UpdateAssetActuator.execute()` when account's `AssetIssuedID` is empty under `AllowSameTokenName==0` - (`actuator/src/main/java/org/tron/core/actuator/UpdateAssetActuator.java`)

### Summary
`UpdateAssetActuator.execute()` unconditionally looks up `assetIssueV2Store` using `accountCapsule.getAssetIssuedID()` before checking `dynamicStore.getAllowSameTokenName()`, while `validate()` only checks the V1 `assetIssueStore` by `AssetIssuedName` when `AllowSameTokenName == 0`. An account that issued an asset without a populated `AssetIssuedID` (empty `ByteString`) can pass `validate()` but hit a null `assetIssueCapsuleV2` in `execute()`, causing an uncaught `NullPointerException` that is not caught by the actuator's `try/catch(InvalidProtocolBufferException)` block.

### Finding Description
In `validate()` [1](#0-0) , when `dynamicStore.getAllowSameTokenName() == 0`, only `account.getAssetIssuedName()` and `assetIssueStore` (V1) are checked; `account.getAssetIssuedID()` and `assetIssueV2Store` are not validated at all in this branch.

In `execute()`, however, the code unconditionally performs the V2 lookup and immediately dereferences the result before checking the `AllowSameTokenName` flag: [2](#0-1) 

If `accountCapsule.getAssetIssuedID()` is empty (e.g. a legacy account whose asset was issued before the code path that populates `AssetIssuedID` was in effect, or any account for which only the V1 name field was ever set), `assetIssueV2Store.get(emptyBytes)` returns `null`. The very next line, `assetIssueCapsuleV2.setFreeAssetNetLimit(newLimit)`, throws a `NullPointerException`. The actuator's `catch` clause only catches `InvalidProtocolBufferException`, so the `NullPointerException` propagates uncaught out of `execute()`.

This is reachable by any account holder who has a valid, previously-issued V1 asset and submits a normally-signed `UpdateAssetContract` transaction (via `UpdateAssetServlet.doPost` → broadcast → actuator dispatch), no special privileges required.

### Impact Explanation
An uncaught `NullPointerException` thrown from an actuator's `execute()` during block/transaction processing is not a normal control-flow exception (`ContractExeException`/`ContractValidateException`) that the transaction pipeline is designed to handle gracefully; it propagates as a runtime error. This can crash or abort the transaction-processing/block-application code path for the node handling that transaction, causing a denial-of-service on that specific transaction processing flow, potentially affecting consensus-critical block application for all nodes that apply the same block.

### Likelihood Explanation
Preconditions are narrow but realistic: (1) `dynamicStore.getAllowSameTokenName() == 0` (a real historical chain state before the same-token-name feature is activated), and (2) an account whose `AssetIssuedID` was never populated despite having a valid `AssetIssuedName`/V1 asset. Whether such accounts exist in practice depends on asset-issuance code paths not fully traced here (e.g., whether `AssetIssueActuator` always sets both `AssetIssuedName` and `AssetIssuedID` together). The existing unit test `createAssertBeforSameTokenNameActive` in `UpdateAssetActuatorTest.java` explicitly always sets `accountCapsule.setAssetIssuedID(...)` alongside `AssetIssuedName` [3](#0-2) , meaning current test coverage does not exercise the empty-`AssetIssuedID` case, and it is not confirmed from the code read here whether the asset-issuance code guarantees `AssetIssuedID` is always non-empty in the `AllowSameTokenName==0` regime.

### Recommendation
In `UpdateAssetActuator.execute()`, mirror the same branching logic used in `validate()`: only perform the `assetIssueV2Store` lookup and null-check its result before use, and gate the V1 vs. V2 primary lookup on `dynamicStore.getAllowSameTokenName()` exactly as `validate()` does, throwing `ContractExeException` (not an NPE) if the expected capsule is missing.

### Proof of Concept
```java
@Test
public void updateAssetWithEmptyAssetIssuedIdBeforeSameTokenNameActive() {
  dbManager.getDynamicPropertiesStore().saveAllowSameTokenName(0);

  AccountCapsule accountCapsule = new AccountCapsule(
      ByteString.copyFrom(ByteArray.fromHexString(OWNER_ADDRESS)),
      ByteString.copyFromUtf8(OWNER_ADDRESS_ACCOUNT_NAME),
      Protocol.AccountType.Normal);

  AssetIssueCapsule assetIssueCapsule = new AssetIssueCapsule(getAssetIssueContract());
  dbManager.getAssetIssueStore().put(assetIssueCapsule.createDbKey(), assetIssueCapsule);
  // Note: AssetIssuedID intentionally left unset/empty on the account,
  // only AssetIssuedName + V1 store entry are populated.
  accountCapsule.setAssetIssuedName(assetIssueCapsule.createDbKey());
  accountCapsule.addAsset(assetIssueCapsule.createDbKey(), TOTAL_SUPPLY);

  dbManager.getAccountStore().put(ByteArray.fromHexString(OWNER_ADDRESS), accountCapsule);

  TransactionResultCapsule ret = new TransactionResultCapsule();
  UpdateAssetActuator actuator = new UpdateAssetActuator();
  actuator.setChainBaseManager(dbManager.getChainBaseManager())
      .setAny(getContract(OWNER_ADDRESS, DESCRIPTION, URL, 500L, 8000L));

  try {
    actuator.validate(); // expected to PASS (no AssetIssuedID check in this branch)
  } catch (ContractValidateException e) {
    Assert.fail("validate() unexpectedly failed: " + e.getMessage());
  }

  try {
    actuator.execute(ret); // expected: should NOT throw uncaught NullPointerException
  } catch (NullPointerException npe) {
    Assert.fail("Uncaught NullPointerException in execute(): " + npe);
  } catch (ContractExeException e) {
    // acceptable graceful failure after fix
  }
}
```
Currently this test reproduces an uncaught `NullPointerException` at `assetIssueCapsuleV2.setFreeAssetNetLimit(newLimit)` in `UpdateAssetActuator.execute()`.
