### Title
Unbounded, unauthenticated `HandleLegacyUserMessage` flooding causes premature eviction of legitimate pending callbacks in `pruneCallbacks`, dropping responses (DoS) - (`core/services/gateway/handlers/capabilities/handler.go`)

### Summary
`handler.HandleLegacyUserMessage` accepts legacy trigger messages with no allowlist or per-user rate limiting (explicitly marked with `// TODO: apply allowlist and rate-limiting here`), and stores every accepted message's callback in the shared `h.savedCallbacks` map keyed by `msg.Body.MessageId`. Because `pruneCallbacks` evicts strictly by `createdAt` age/oldest-half once `len(savedCallbacks) > MaxSavedCallbacks`, an attacker who can reach this endpoint can insert enough distinct `MessageId`s within a `CallbackPruneIntervalSec` window to force eviction of older, still-pending, legitimate callbacks before their DON response arrives.

### Finding Description
`HandleLegacyUserMessage` performs payload decoding, timestamp/staleness checks, and method validation, but no sender allowlist/rate-limit check (unlike the sibling `functions.handler.functions.go` handler, which enforces `h.allowlist.Allow(sender)` and `h.userRateLimiter.Allow(msg.Body.Sender)` before accepting a request): [1](#0-0) 

Every valid-looking message (only requiring a well-formed `TriggerRequestPayload`, a fresh `Timestamp`, and `MethodWebAPITrigger`) unconditionally inserts an entry into the shared map: [2](#0-1) 

`pruneCallbacks` runs on a timer (`CallbackPruneIntervalSec`, default 30s) and, after removing age-expired entries, if the map still exceeds `MaxSavedCallbacks` (default 20000), sorts remaining entries by `createdAt` and deletes the oldest half — regardless of whether those callbacks are still awaiting a legitimate DON response: [3](#0-2) 

Because there is no per-sender quota, allowlist, or rate limit gating entry into `savedCallbacks`, an attacker with access to the same unauthenticated user-message endpoint (`gateway.ProcessRequest` → `h.HandleLegacyUserMessage`) as legitimate callers can flood the map with distinct `MessageId`s to inflate its size past `MaxSavedCallbacks` before the next prune cycle, causing legitimate, older, still-pending entries (including those belonging to other unrelated users) to be evicted by `pruneCallbacks` without ever having `handleWebAPITriggerMessage` invoke `savedCb.SendResponse`, so their `Callback.Wait` in `gateway.ProcessRequest` will only resolve via timeout — appearing to the caller as a dropped/failed response. [4](#0-3) 

### Impact Explanation
This is a capability-routing denial-of-service: an unprivileged attacker can cause legitimate DON trigger responses for arbitrary other users to be silently discarded (evicted from `savedCallbacks`) before their asynchronous DON response arrives, forcing those users' requests to fail via request timeout instead of receiving the real response. This matches a "denial of response delivery" / gateway DoS impact rather than fund loss or key compromise.

### Likelihood Explanation
The precondition explicitly noted in the code itself (`// TODO: apply allowlist and rate-limiting here`) confirms there is currently no authentication/allowlist/rate-limit gate on this code path, so any client capable of reaching the gateway's user HTTP endpoint for a legacy DON can repeatedly call `HandleLegacyUserMessage` with distinct `MessageId`s. Achieving `MaxSavedCallbacks` (20000 by default) worth of entries within one `CallbackPruneIntervalSec` (30s default) requires only moderate request throughput, well within reach of a scripted flood, making this reliably repeatable.

### Recommendation
Add per-sender/IP allowlisting and rate limiting to `HandleLegacyUserMessage` (mirroring `functions.handler.functions.go`'s `allowlist.Allow` / `userRateLimiter.Allow` checks) before inserting into `savedCallbacks`, and/or change `pruneCallbacks` eviction policy to prioritize evicting entries from over-quota senders rather than blind oldest-first eviction, and consider capping the number of pending callbacks per sender independently of the global cap.

### Proof of Concept
Add an integration test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Configure the handler with a small `MaxSavedCallbacks` (e.g., 10) and `CallbackPruneIntervalSec` set to a short interval.
2. Call `HandleLegacyUserMessage` once with a legitimate signed trigger message (`legitMsg`), capturing its callback `legitCb`, and record its `savedCallbacks` entry as "old" (createdAt in the past).
3. Flood the handler with `> MaxSavedCallbacks` additional `HandleLegacyUserMessage` calls, each using a unique valid signed message with distinct `MessageId`s and newer `createdAt`.
4. Manually invoke `handler.pruneCallbacks()` (or wait for the ticker).
5. Assert that `legitMsg.Body.MessageId` is no longer present in `handler.savedCallbacks`, and that calling `handler.HandleNodeMessage` with the corresponding DON response for `legitMsg` no longer triggers `legitCb.SendResponse` (i.e., `legitCb.Wait` times out), demonstrating the legitimate response was silently dropped due to attacker-induced eviction.

func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}

	// If there are still too many callbacks, sort them by creation time and remove the oldest ones.
	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {
			return entries[i].createdAt.Before(entries[j].createdAt)
		})
		// Trim to maxSize/2 to avoid sorting the list too frequently.
		for _, e := range entries[:len(entries)-maxSize/2] {
			delete(h.savedCallbacks, e.id)
			evicted++
		}
	}
