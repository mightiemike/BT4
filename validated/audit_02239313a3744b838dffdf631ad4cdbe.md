## Analysis

Both `parseSendFundsEvent` and `parseOutboundObservationEvent` in the SVM event parser only validate a log line via `strings.HasPrefix(log, "Program data: ")` before decoding it as a gateway event [1](#0-0) [2](#0-1) . The same shallow check is used upstream in `determineEventType` to classify the log by its discriminator bytes [3](#0-2) .

Neither function verifies which program actually emitted the `Program data: ...` line. In `processSignatureBatch`, the listener fetches full transactions via `GetSignaturesForAddress(gatewayAddr, ...)` — a Solana RPC call that returns any transaction merely *referencing* the given address in its account list (not necessarily invoking it) — and then iterates over the transaction's entire flattened `tx.Meta.LogMessages`, feeding every "Program data:" line to `ParseEvent` regardless of which instruction/program produced it [4](#0-3) .

This means an unprivileged attacker can:
1. Build a transaction on the source SVM chain that references the configured gateway address (e.g., as an unused readonly account in one instruction) — satisfying the `GetSignaturesForAddress` filter.
2. In the same transaction, invoke their own attacker-deployed program that calls `sol_log_data` with a payload whose first 8 bytes match a known discriminator (`send_funds`, `finalize_universal_tx`, `revert_universal_tx`, `funds_rescued`) and whose remaining bytes encode an arbitrary sender, recipient, token, amount, or gas fields.

Since parsing is fully deterministic over immutable on-chain transaction data, every honest universal validator independently fetching that transaction will parse and store the same forged `store.Event` — no malicious validator, TSS signer, or relayer is required, satisfying the in-scope "forged inbound ... state accepted through user-reachable flows with honest validators and honest nodes" criterion.

By contrast, the EVM parser relies on `types.Log.Topics`/`Data`, which are bound to the emitting contract address as enforced by the EVM's log filtering (`eth_getLogs` by address), so the equivalent forgery is not available there [5](#0-4) .

I was not able to trace how the stored `store.Event` records flow further into ballot/vote submission logic in the scoped code available to me within this pass (e.g. the vote/ballot construction in `x/` or the observer pipeline), so I cannot fully confirm the on-chain fund-movement consequence (e.g., that a forged `send_funds` event actually results in unauthorized minting on Push Chain) without further tracing. This uncertainty affects the materiality/impact severity but not the existence of the parsing flaw itself.

### Title
Forgeable Solana gateway events via unauthenticated `Program data:` log source — (File: universalClient/chains/svm/event_parser.go, universalClient/chains/svm/event_listener.go)

### Summary
The SVM event parser accepts any `Program data: ...` log line matching a known discriminator without verifying it was emitted by the actual configured gateway program, and the listener retrieves logs from full transactions that merely reference the gateway address rather than being invoked by it.

### Finding Description
`determineEventType` and `parseSendFundsEvent`/`parseOutboundObservationEvent` treat every `Program data:` line in a transaction's `Meta.LogMessages` as if it originated from the gateway program, based solely on prefix matching and an 8-byte discriminator decoded from attacker-controlled base64 data [6](#0-5) [7](#0-6) . `processSignatureBatch` obtains candidate transactions through `GetSignaturesForAddress`, a Solana RPC method that matches any transaction referencing the address in its account key list, not just ones where the gateway program is invoked, and then walks the transaction's entire log stream without attributing individual log lines to a specific "Program X invoke ... success" block [8](#0-7) . An attacker who deploys their own Solana program can co-locate it in a transaction that references the gateway address, and emit a crafted `sol_log_data` payload that is indistinguishable, at the parser level, from a genuine gateway-emitted event.

### Impact Explanation
If downstream ballot/finalization logic trusts the `store.Event` records produced from this path without an independent program-origin check, an attacker could fabricate inbound `send_funds` events (claiming an arbitrary deposit amount/token/recipient without any real transfer) or fabricate outbound observation events (`finalize_universal_tx`, `revert_universal_tx`, `funds_rescued`) with attacker-chosen `sub_tx_id`, `universal_tx_id`, and `gas_used` values. Because all honest UVs deterministically parse the same immutable on-chain data, they would converge on the same forged record, potentially leading to unauthorized minting/release of funds or corrupted gas/refund accounting.

### Likelihood Explanation
Deploying and invoking an arbitrary program on a permissionless SVM chain is trivial for any unprivileged actor, and crafting the transaction so that it is returned by `GetSignaturesForAddress` for the gateway address is straightforward. The main uncertainty is whether later stages (ballot construction/voting in `x/`) impose additional authenticity checks (e.g., re-deriving the event from a strict per-program log slice, or cross-checking `log.Address`/program-invoke boundaries) that would neutralize this before any fund-affecting state change — this could not be fully verified in this pass.

### Recommendation
When parsing SVM transaction logs, associate each `Program data:` line with the specific `Program <id> invoke [...]` / `Program <id> success` block it falls within, and only accept lines emitted while the gateway program ID is the currently executing program. Reject any log line whose enclosing invocation frame does not match the configured `gatewayAddress`.

### Proof of Concept
1. Attacker deploys program `M` on the target SVM chain.
2. Attacker submits a transaction with: (a) an instruction referencing the configured gateway address as an account (to be returned by `GetSignaturesForAddress`), and (b) an instruction invoking `M`, which calls `sol_log_data(discriminator_send_funds || fake_sender || fake_recipient || fake_token || fake_amount || ...)`.
3. The universalClient's `EventListener.processSignatureBatch` fetches this transaction, iterates `tx.Meta.LogMessages`, finds the `Program data:` line from `M`, and `determineEventType`/`ParseEvent` accept it as a genuine `send_funds` event with attacker-controlled fields, storing it via `InsertEventIfNotExists`. func parseSendFundsEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	if len(decoded) < 8 {
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing sendFunds event")

	// Create store.Event
	event := &store.Event{
		EventID:           eventID,
		BlockHeight:       slot,
		Type:              store.EventTypeInbound, // Gateway events from external chains are INBOUND
		Status:            store.StatusPending,
		ExpiryBlockHeight: 0, // Will be set based on confirmation type if needed
	}

	// Parse event data from this log
	parseUniversalTxEvent(event, decoded, logIndex, chainID, logger)

	return event

func (el *EventListener) processSlotRange(
	ctx context.Context,
	fromSlot, toSlot uint64,
) error {
	// Parse gateway address
	gatewayAddr, err := solana.PublicKeyFromBase58(el.gatewayAddress)
	if err != nil {
		return fmt.Errorf("invalid gateway address: %w", err)
	}

	// Per-page streaming so memory stays bounded on long bootstraps. Termination
	// and cursor use min(slot) of the batch — per
	// https://github.com/solana-labs/solana/issues/22456 in-page order is not
	// guaranteed descending, so batch[len-1] would risk an early break.
	var beforeSig solana.Signature
	var processedInRange uint64
	for page := 0; ; page++ {
		batch, err := el.rpcClient.GetSignaturesForAddress(ctx, gatewayAddr, beforeSig)
		if err != nil {
			return fmt.Errorf("failed to get signatures (page %d): %w", page, err)
		}
		if len(batch) == 0 {
			break
		}

		processed, err := el.processSignatureBatch(ctx, batch, fromSlot, toSlot)
		if err != nil {
			return err
		}
		processedInRange += processed
		if processedInRange >= largePollWarnThreshold {
			el.logger.Warn().
				Uint64("processed_in_range", processedInRange).
				Uint64("threshold", largePollWarnThreshold).
				Uint64("from_slot", fromSlot).
				Uint64("to_slot", toSlot).
				Int("pages", page+1).
				Msg("large signature backlog being processed; if this is unexpected, " +
					"restart with EventStartFrom set to -1 (latest) or a recent slot, " +
					"and verify the RPC tier can sustain the request volume")
		}

		minSlot := batch[0].Slot
		minSig := batch[0].Signature
		for _, s := range batch[1:] {
			if s.Slot < minSlot {
				minSlot = s.Slot
				minSig = s.Signature
			}
		}

		if minSlot < fromSlot {
			break
		}
		beforeSig = minSig
	}

	return nil
}

// Processes in-range sigs from `batch`, returns how many. `continue` on both
// bounds so it tolerates any in-page order.
func (el *EventListener) processSignatureBatch(
	ctx context.Context,
	batch []*solanarpc.TransactionSignature,
	fromSlot, toSlot uint64,
) (uint64, error) {
	var processed uint64
	for _, sig := range batch {
		if sig.Slot < fromSlot {
			continue
		}
		if sig.Slot > toSlot {
			continue
		}
		processed++

		// Get transaction details
		tx, err := el.rpcClient.GetTransaction(ctx, sig.Signature)
		if err != nil {
			el.logger.Error().
				Err(err).
				Str("signature", sig.Signature.String()).
				Msg("failed to get transaction")
			continue
		}

		// Process each log in the transaction
		if tx != nil && tx.Meta != nil && len(tx.Meta.LogMessages) > 0 {
			for logIndex, log := range tx.Meta.LogMessages {
				// Determine event type based on discriminator
				eventType := el.determineEventType(log)
				if eventType == "" {
					continue
				}

				// Parse gateway event from individual log
				event := ParseEvent(log, sig.Signature.String(), sig.Slot, uint(logIndex), eventType, el.chainID, el.logger)

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

func ParseEvent(log *types.Log, eventType string, chainID string, logger zerolog.Logger) *store.Event {
	if len(log.Topics) == 0 {
		return nil
	}

	switch eventType {
	case EventTypeSendFunds:
		return parseSendFundsEvent(log, chainID, logger)
	case EventTypeExecuteUniversalTx, EventTypeRevertUniversalTx, EventTypeFinalizeUniversalTx, EventTypeFundsRescued:
		// All share the same topic layout: Topics[1]=txID, Topics[2]=universalTxID.
		return parseOutboundObservationEvent(log, chainID, logger)
	default:
		logger.Debug().
			Str("event_type", eventType).
			Str("tx_hash", log.TxHash.Hex()).
			Msg("unknown event type, skipping")
		return nil
	}
}
