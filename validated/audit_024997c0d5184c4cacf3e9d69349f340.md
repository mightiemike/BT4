### Title
Open redirect via unauthenticated `exitIframe` query parameter is not restricted to the app's own origin - ([File: packages/apps/shopify-app-remix/src/server/authenticate/admin/authenticate.ts])

### Summary
The reported Solidity bug is a validation function (`makeOffer`) that checks an address is not `0x0` but forgets to also reject the contract's own address, letting funds be trapped/misdirected to an address the check-writer didn't intend. The analogous class in `shopify-app-js` is a URL-safety check that validates *format* (protocol, no `file://`, no whitespace) but never validates that the destination belongs to the app itself, letting attacker-supplied redirect targets be honored even though the surrounding code and docs assume the destination is “the app”.

### Finding Description
`shopifyApp(...).authenticate.admin` handles the `exit-iframe` bounce path before any session/shop validation occurs: [1](#0-0) 

`respondToExitIframeRequest` reads the `exitIframe` query-string parameter directly off the incoming (unauthenticated) request and passes it straight into `renderAppBridge`:

```
const destination = url.searchParams.get('exitIframe')!;
throw renderAppBridge({config, logger, api}, request, {url: destination});
```

`renderAppBridge` sanitizes that value with `sanitizeRedirectUrl` and then embeds it verbatim in an HTML page that performs a top-level `window.open`: [2](#0-1) 

The “safety” check, however, only validates URL *shape* — it forbids `file://` URIs, whitespace, double-slash relative paths, and non-`http(s)` protocols — but it never checks that the resulting URL is same-origin with `config.appUrl` (the app itself): [3](#0-2) 

This mirrors the underlying Marketplace flaw exactly: a guard exists (`_affiliate == 0x0`) to stop one specific bad case (funds trapped in the contract) but the guard is not comprehensive (it doesn't stop `_affiliate == address(this)`), so a "safe-looking" parameter can still redirect value/flow to an unintended place. Here, `isSafe()` blocks obviously dangerous schemes but not arbitrary external `https://` origins, even though the whole `exit-iframe` mechanism exists specifically to safely exit *back into the app's own flow* (e.g., `${config.auth.path}?shop=...`), as shown by `redirectWithExitIframe`, which always sets `exitIframe` to `config.auth.path` under legitimate use: [4](#0-3) 

The existing test suite only proves that a `file://` URL and a non-string are rejected; it never asserts that a cross-origin `https://` URL is rejected on the `exit-iframe` route: [5](#0-4) [6](#0-5) 

Because the `/auth/exit-iframe` route is checked **before** `validateShopAndHostParams`, session-token retrieval, and any authentication strategy, this is reachable by a completely anonymous, unauthenticated HTTP GET request.

### Impact Explanation
An attacker can craft a link such as `https://<merchant-app-domain>/auth/exit-iframe?exitIframe=https%3A%2F%2Fattacker.example&shop=any-shop.myshopify.com` and send it to a merchant (e.g., via email, ad, or embedded-admin deep link). Because the URL's host is the legitimate, trusted app domain (and it renders the real Shopify App Bridge script), the merchant is likely to trust it. Visiting the link causes the app's own server to serve a page whose script performs `window.open(attackerUrl, "_top")`, breaking the merchant out of the Shopify Admin iframe and top-level-navigating them to an attacker-controlled site — a textbook open-redirect usable for phishing (fake reauth/OAuth consent pages) or credential/session theft. This is the JS/web analog to the audited contract's "funds diverted because the whitelist/self-check missed a valid-looking address" problem.

### Likelihood Explanation
High. The route path (`config.auth.exitIframePath`, default `/auth/exit-iframe`) is public and unauthenticated by design (it exists to run before a session exists), requires no secrets, no privileged actor, and no race conditions — a single crafted URL sent to any user is sufficient. It works out of the box for any `shopify-app-remix`/`shopify-app-react-router` app using default configuration, since `sanitizeRedirectUrl` never enforces same-origin.

### Recommendation
- Short term: In `sanitizeRedirectUrl`/`isSafe`, additionally require that the resolved URL's origin matches `domain` (the app's own `config.appUrl`) whenever the caller doesn't explicitly opt into cross-origin redirects (e.g., add a `sameOriginOnly` option defaulted to `true`, and set it to `true` specifically for the `exit-iframe`/bounce-page code paths).
- Long term: Treat the `exitIframe` query parameter as untrusted input coming straight from an anonymous request and validate it against an allow-list of internal paths (e.g., only allow relative paths or `config.auth.path`) rather than any syntactically valid `http(s)` URL, mirroring the auditor's long-term recommendation of requiring active, verified control before honoring an address/URL.

### Proof of Concept
```
GET /auth/exit-iframe?exitIframe=https%3A%2F%2Fattacker.example&shop=any-shop.myshopify.com HTTP/1.1
Host: <legitimate-app-domain>
```
Expected (per current code): HTTP 200 response containing
```html
<script data-api-key="..." src="https://cdn.shopify.com/shopifycloud/app-bridge.js"></script>
<script>window.open("https://attacker.example/", "_top")</script>
```
served from the trusted app origin with no authentication, no shop-installed check, and no same-origin restriction on the destination, as traced through `respondToExitIframeRequest` → `renderAppBridge` → `sanitizeRedirectUrl`/`isSafe`.

```typescript
function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
```

```typescript
import {redirect} from '@remix-run/server-runtime';

import type {BasicParams} from '../../../types';

export function redirectWithExitIframe(
  params: BasicParams,
  request: Request,
  shop: string,
): never {
  const {api, config} = params;
  const url = new URL(request.url);

  const queryParams = url.searchParams;

  const host = api.utils.sanitizeHost(queryParams.get('host')!);

  queryParams.set('shop', shop);

  let destination = `${config.auth.path}?shop=${shop}`;

  if (host) {
    queryParams.set('host', host);
    destination = `${destination}&host=${host}`;
  }
  queryParams.set('exitIframe', destination);

  throw redirect(`${config.auth.exitIframePath}?${queryParams.toString()}`);
```
