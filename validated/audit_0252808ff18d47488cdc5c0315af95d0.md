### Title
Missing parent-tenure linkage check in `check_nakamoto_tenure` Extended-cause branch allows a tenure-extend to be validated against a stale (already-superseded) tenure - ([File: stackslib/src/chainstate/nakamoto/tenure.rs])

### Summary
`check_nakamoto_tenure`'s `BlockFound` branch explicitly requires `parent_tenure.tenure_id_consensus_hash == tenure_payload.prev_tenure_consensus_hash`, but the parallel `Extended`/`Extended*` branch never compares `tenure_payload.tenure_consensus_hash` (or `prev_tenure_consensus_hash`) against `parent_tenure.tenure_id_consensus_hash` — it only checks the payload's internal self-consistency. This omission means the function can return `Ok(Some(parent_tenure))` (i.e., treat the tenure-extend as valid) for a payload whose declared tenure consensus hash does not match the tenure that the actual parent block belongs to.

### Finding Description
The broken equality is:
`parent_tenure.tenure_id_consensus_hash` (derived from `get_ongoing_tenure(block_header.parent_block_id)`, i.e., the *real* tenure of the block's actual parent) is never checked against `tenure_payload.tenure_consensus_hash` / `tenure_payload.prev_tenure_consensus_hash` in the `Extended` cause branch.

Code path:
- [1](#0-0)  shows the cause-validation `match`. The `BlockFound` arm enforces `parent_tenure.tenure_id_consensus_hash != tenure_payload.prev_tenure_consensus_hash` and rejects on mismatch [2](#0-1) . The `Extended*` arm only checks `tenure_payload.tenure_consensus_hash != tenure_payload.prev_tenure_consensus_hash` (payload self-consistency) — it never touches `parent_tenure` at all [3](#0-2) .
- `parent_tenure` itself is fetched from the *actual* parent block (`block_header.parent_block_id`), which is required to equal `tenure_payload.previous_tenure_end` [4](#0-3) , via `get_ongoing_tenure` [5](#0-4) . If the parent block truly resides in tenure Y (a later `BlockFound` tenure), `parent_tenure.tenure_id_consensus_hash == Y`, but the function still proceeds to accept an `Extended` payload declaring `tenure_consensus_hash == prev_tenure_consensus_hash == X` (a stale, already-finished tenure), and returns `Ok(Some(parent_tenure))` at line 826 without ever having verified `X == Y`.

Root cause: an inconsistent/incomplete port of the `BlockFound` linkage check to the `Extended` cause arm.

Mitigating factor found during review: immediately after the cause `match`, the code computes `tenure_len = get_nakamoto_tenure_length(headers_conn.sqlite(), &block_header.parent_block_id)` and requires it to equal `tenure_payload.previous_tenure_blocks` [6](#0-5) . Since `tenure_len` is computed from the parent block's *real* tenure (Y), while a replayed payload carries `previous_tenure_blocks` from the old tenure X, these values will generically differ and this check will reject the replay in the common case. Exploitation therefore requires the attacker to locate/craft a parent block position in Y's chain where the cumulative block count happens to coincide with the stale payload's `previous_tenure_blocks` value — not impossible, but a nontrivial additional precondition that the question's proof idea does not address.

Additionally, for the malicious block to be accepted network-wide it must still receive signer threshold signatures (via the standard block-proposal validation path), and this same `check_nakamoto_tenure` logic is what signers/nodes use to validate proposals, so the gap is a shared-code-path defect rather than something a lone miner can bypass purely client-side — but it is not gated by requiring majority signer collusion; it's a shared validation bug.

### Impact Explanation
If the `tenure_len` coincidence is engineered, an Extended tenure-change block referencing a finished, non-ongoing tenure X could pass `check_nakamoto_tenure`, causing `advance_nakamoto_tenure` to call `insert_nakamoto_tenure` with a payload keyed to X's consensus hash rather than the actual ongoing tenure Y [7](#0-6) . This can corrupt the `nakamoto_tenures` table's notion of the "ongoing"/"highest" tenure, potentially causing two honest nodes (or a node vs. signers) to disagree about which tenure is canonical — a chain-state divergence consistent with the Critical category (chain split / invalid block accepted).

### Likelihood Explanation
Requires: (1) tenure X to have finished and been superseded by a `BlockFound` tenure Y — attacker-observable public chain state; (2) the attacker to find or construct a parent block in Y whose `get_nakamoto_tenure_length` value exactly matches the stale payload's `previous_tenure_blocks`; (3) the resulting block to still obtain valid signer signatures, since the same flawed check is what signers rely on during proposal validation, but signers may reject on other unrelated grounds (burn view, VRF, timing) not analyzed here. Feasibility is plausible but not trivially "any replay works" — the `tenure_len` check is a real, if incomplete, backstop. This is not a majority-stake attack: it only requires being a single miner able to construct and propose a block, matching the in-scope actor.

### Recommendation
Add an explicit linkage check in the `Extended`/`Extended*` arm of `check_nakamoto_tenure`, mirroring the `BlockFound` arm:
```rust
if parent_tenure.tenure_id_consensus_hash != tenure_payload.tenure_consensus_hash {
    warn!("Invalid tenure-change extension: does not extend the ongoing tenure");
    return Ok(None);
}
```
This directly enforces that an Extended payload can only apply to the tenure that the actual parent block belongs to, closing the gap regardless of whether `tenure_len` happens to collide.

### Proof of Concept
Rust integration test plan (nakamoto test harness, e.g. `stackslib/src/chainstate/nakamoto/tests/node.rs` style):
1. Build a two-tenure chain: tenure X (`BlockFound`), extend X once (`Extended`, recording X's `previous_tenure_blocks` count `n_x`), then finish X and start tenure Y via a new `BlockFound`.
2. Mine additional blocks in Y until `get_nakamoto_tenure_length(parent_block_id)` for some Y block equals `n_x` (the old X extend's `previous_tenure_blocks`).
3. Construct a `NakamotoBlockHeader` with `parent_block_id` set to that Y block, `consensus_hash = X`, and a `TenureChangePayload` with `cause = Extended`, `tenure_consensus_hash = prev_tenure_consensus_hash = X`, `previous_tenure_end = <Y block id>`, `previous_tenure_blocks = n_x`.
4. Call `NakamotoChainState::check_nakamoto_tenure` directly with this header/payload.
5. Assert (pre-fix) it returns `Ok(Some(parent_tenure))` with `parent_tenure.tenure_id_consensus_hash == Y`, demonstrating `tenure_payload.tenure_consensus_hash (X) != parent_tenure.tenure_id_consensus_hash (Y)` was never checked.
6. After applying the recommended fix, assert the same call returns `Ok(None)`.

    pub(crate) fn advance_nakamoto_tenure<SH: SortitionHandle>(
        headers_tx: &mut StacksDBTx,
        handle: &mut SH,
        block: &NakamotoBlock,
        parent_coinbase_height: u64,
        do_not_advance: bool,
    ) -> Result<u64, ChainstateError> {
        let Some(tenure_payload) = block.get_tenure_tx_payload() else {
            // no new tenure
            return Ok(parent_coinbase_height);
        };

        let coinbase_height = match tenure_payload.cause {
            TenureChangeCause::BlockFound => {
                // tenure height advances
                parent_coinbase_height
                    .checked_add(1)
                    .expect("FATAL: too many tenures")
            }
            TenureChangeCause::Extended
            | TenureChangeCause::ExtendedRuntime
            | TenureChangeCause::ExtendedReadCount
            | TenureChangeCause::ExtendedReadLength
            | TenureChangeCause::ExtendedWriteCount
            | TenureChangeCause::ExtendedWriteLength => {
                // tenure height does not advance
                parent_coinbase_height
            }
        };

        if Self::check_nakamoto_tenure(headers_tx, handle, &block.header, tenure_payload)?.is_none()
        {
            return Err(ChainstateError::InvalidStacksTransaction(
                "Invalid tenure tx".into(),
                false,
            ));
        };

        if do_not_advance {
            return Ok(coinbase_height);
        }
        Self::insert_nakamoto_tenure(headers_tx, &block.header, coinbase_height, tenure_payload)?;
        return Ok(coinbase_height);
