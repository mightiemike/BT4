### Title
Hardcoded 5% slippage on spot-priced QuoterV2 swaps allows price-manipulation loss of user/protocol funds during gas-abstraction deposits and gas refunds - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
Every autoswap path in `x/uexecutor` (gas-abstraction deposits, gas-and-payload deposits, and post-outbound gas refunds) derives its slippage-protection bound from a single, un-cached spot-price quote obtained via `Keeper.GetSwapQuote` (Uniswap V3 `QuoterV2.quoteExactInputSingle`) and then hardcodes the tolerance at exactly 5% (`minPCOut = quote * 95 / 100`). There is no user-configurable slippage, no TWAP, and no check that the pool has not just been manipulated. This mirrors the reported `FlashloanLiquidator.executeOperation` issue: a fixed swap-output bound computed from a manipulable, single-block price oracle.

### Finding Description
`Keeper.GetSwapQuote` calls the Uniswap V3 `QuoterV2` contract with `commit=false`, which reflects the pool's *current* spot price/tick state rather than a time-weighted average: [1](#0-0) 

This quote is used, unmodified except for a fixed 5% haircut, to build the `minPCOut` slippage bound in three independent call sites:

1. `ExecuteInboundGas` (GAS inbound fee-abstraction swap): [2](#0-1) 

2. `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound): [3](#0-2) 

3. `applyGasRefund` (excess-gas refund on outbound finalization): [4](#0-3) 

In all three cases the flow is: fetch spot quote → apply fixed 95% factor → immediately execute the swap on-chain via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, which route into `UniversalCore.depositPRC20WithAutoSwap` / `refundUnusedGas` on the Uniswap V3 pool. Both the quote fetch and the swap execution happen within the same Cosmos SDK transaction/block (during ballot finalization or outbound-vote EndBlocker processing), and the deposit/refund is triggered deterministically once honest-validator quorum is reached — an unprivileged external actor can observe the pending inbound/outbound (it is public mempool/chain state) and, in the same block, execute an ordinary swap against the same Uniswap V3 PRC20/WPC pool used by `UniversalCore` to move the spot price. Since 5% is a generous, non-adaptive tolerance and the quote itself is taken from the manipulated pool state, the attacker can:
- Push the pool price down before the module's deposit-autoswap executes, causing the recipient UEA to receive close to 5% less native PC than fair value while the attacker captures the difference by reversing their manipulation afterward (classic sandwich), or
- Manipulate price to sit just inside the 5% band repeatedly, extracting value from every gas-abstraction deposit and every gas refund that pass through the pool.

This is architecturally identical to the reported Aave flashloan liquidator bug: a fixed percentage slippage tolerance computed from a spot-price oracle that the attacker can move within the same transaction context, resulting in the user/protocol receiving materially less value than intended, with no way to configure a tighter/safer tolerance.

### Impact Explanation
Users bridging gas or funds via `TxType_GAS` / `TxType_GAS_AND_PAYLOAD`, and any outbound with excess gas fee refund, can have their received PC systematically reduced by up to 5% (bounded loss per tx, but repeatable across every affected inbound/refund), with the difference extractable by an unprivileged attacker via ordinary sandwich transactions against the on-chain Uniswap V3 pool. This corrupts native/PRC20 asset accounting and refund accounting (`PcRefundExecution`, deposit amount landing at UEA) without requiring any privileged validator, relayer, or TSS compromise — it is reachable purely from default inbound/outbound flows plus ordinary EVM transactions against the pool.

### Likelihood Explanation
Likelihood is moderate-to-high: any user can submit ordinary swap transactions against the same Uniswap V3 pool `UniversalCore` uses, PRC20/WPC pools on a nascent chain are likely to have thin liquidity (cheap to move price 5%+), and the deposit-swap/refund-swap execution is triggered deterministically and observably (once ballot quorum or outbound quorum is reached), giving attackers a predictable window to front-run.

### Recommendation
- Replace the single-block spot quote with a manipulation-resistant price source (e.g., Uniswap V3 TWAP over a meaningful window, or a Chainlink-style external price feed) before computing `minPCOut`.
- Make the slippage tolerance a bounded, tunable governance/module parameter instead of a hardcoded 95% constant duplicated across `execute_inbound_gas.go`, `execute_inbound_gas_and_payload.go`, and `outbound.go`.
- Consider fetching the quote and executing the swap atomically against a guarded price (e.g., checking current spot price against the TWAP within a max-deviation bound) to reject execution when the pool appears to have been recently manipulated.

### Proof of Concept
1. Attacker monitors pending `MsgVoteInbound` votes for a `GAS` or `GAS_AND_PAYLOAD` inbound (or a pending outbound gas refund) that will trigger `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` against the PRC20/WPC Uniswap V3 pool.
2. Once quorum is one vote away, attacker submits a large ordinary swap on the same pool in the same block to move the spot price against the upcoming module swap (still within the 5% band computed off the now-manipulated quote via `GetSwapQuote`, since `minPCOut` is derived from that same manipulated quote, not a pre-manipulation baseline).
3. Attacker submits/allows the final vote to land, triggering `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`/`applyGasRefund`, which calls `GetSwapQuote` (returns manipulated price) then swaps at `minPCOut = quote*95/100` — succeeding at a bad rate.
4. Attacker reverses their swap in the same or next block, capturing the spread; the recipient UEA / refund recipient receives up to ~5% less PC than fair market value.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}
```
