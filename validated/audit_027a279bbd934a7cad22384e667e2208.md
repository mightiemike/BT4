### Title
Nakamoto block signature verification accepts zero signatures when a PoX-4 reward cycle's signer set floors to empty - (File: stackslib/src/chainstate/nakamoto/mod.rs)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` treats a reward set whose `signers()` returns `Some(vec![])` (present but empty) as valid, computing a required signature weight threshold of `0`. A completely unsigned Nakamoto block (`signer_signature = []`) then satisfies `total_weight_signed (0) >= threshold (0)` and is accepted. This state is reachable in practice because the PoX-4 signer-set builder, `StacksChainState::make_signer_set`, can legitimately return `Some(vec![])` (as opposed to `None`) when every individual stacker's floor-divided weight is `0`, and the PoX-4 reward-cycle computation path writes this empty signer set to `.signers` without any emptiness guard (unlike the PoX-5 path, which explicitly rejects an empty signer set).

### Finding Description
`verify_signer_signatures` in [1](#0-0)  only rejects when `reward_set.signers()` is `None`:
```
let Some(signers) = reward_set.signers() else {
    return Err(ChainstateError::InvalidStacksBlock("No signers in the reward set".to_string()));
};
```
It does not reject an empty-but-`Some` signer list. `total_weight` is then computed from that (possibly empty) list via `RewardSet::total_signing_weight` [2](#0-1) , which folds to `0` for an empty vector. The threshold is derived purely from `total_weight`: [3](#0-2) 
```
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    ...
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
```
With `total_weight = 0`, this returns `0`. Back in `verify_signer_signatures`, with an empty `self.signer_signature` the loop over signatures never executes, so `total_weight_signed` stays `0`, and the final check [4](#0-3) 
```
if total_weight_signed < threshold { ... }
return Ok(total_weight_signed);
```
`0 < 0` is `false`, so the function returns `Ok(0)` — success — for a block carrying zero signer signatures.

The empty-but-`Some` signer set is directly producible: `StacksChainState::make_signer_set` filters out any stacker whose floor-divided weight is `0` and returns `Some(signer_set)` (never `None`) as long as the input `entries` slice was non-empty: [5](#0-4) 
If every stacker's `stacked_amt / threshold` floors to `0` (which happens under low participation, since the threshold is scaled by `liquid_ustx / POX_MAXIMAL_SCALING` rather than strictly by actual participation — see `get_reward_threshold_and_participation` [6](#0-5) ), the returned `Vec` is empty, giving `RewardSet::V0` a `signers: Some(vec![])`.

Crucially, the PoX-4 path that builds and commits this reward set to `.signers` has no guard against this empty case: [7](#0-6) 
```
let reward_set = StacksChainState::make_reward_set(threshold, reward_slots, StacksEpochId::Epoch30);
...
let events = Self::update_signers(
    clarity, reward_cycle,
    reward_set.signers().unwrap_or(&empty_signers),
    signers_contract,
    participation > 0,
    ...
)?;
Ok(SignerCalculation { events, reward_set })
```
It writes the (possibly empty) `signer_set` whenever `participation > 0`. By contrast, the PoX-5 path explicitly checks for this and aborts: [8](#0-7) 
```
let Pox5SignerSetOutput { signer_set, pox_ustx_threshold } = Self::pox_5_make_signer_set(&mut entries, pox_constants)?;
if signer_set.is_empty() {
    error!("Fatal network condition: reward set computed with an empty signer set. Cannot continue producing blocks");
    return Err(ChainstateError::PoxNoRewardCycle);
}
```
No equivalent guard exists on the PoX-4 (`RewardSet::V0`) path.

### Impact Explanation
This breaks the core consensus equality that a Nakamoto block must be endorsed by ≥70% of signer weight. When a reward cycle's computed signer set floors to empty (a low-participation PoX-4 cycle, entirely reachable without any majority collusion — it is a property of the deterministic threshold-scaling formula applied to whatever stackers happen to have participated), the required threshold collapses to `0`, and *any* miner can produce and have accepted a block with zero signer signatures. Because the reward set is deterministically derived by all nodes from on-chain PoX-4 stacking state, every node independently arrives at the same empty signer set and same zero threshold, so this is not merely a local anomaly — it is a network-wide acceptance of an effectively unsigned block, i.e., an invalid (unsigned) block being accepted network-wide. This is Critical impact per the scope's definition ("an invalid block accepted ... network-wide").

### Likelihood Explanation
Reaching this condition requires only a PoX-4 reward cycle with non-zero but low/fragmented participation such that every individual stacker's floor-divided weight is `0` — no majority, no privileged access, and no cooperation from any signer is needed; the attacking miner simply needs to notice (or wait for) such a cycle and produce an unsigned block. The scaling formula in `get_reward_threshold_and_participation` explicitly protects against low-participation cycles by inflating the threshold relative to actual stacked amounts, which is precisely the mechanism that can drive every individual weight to `0`.

### Recommendation
- Short term: In `verify_signer_signatures`, explicitly reject (or treat as `InvalidStacksBlock`) reward sets whose `signers()` list is empty, in addition to the existing `None` check. Additionally, add the same `is_empty()` guard used in `pox_5_compute_and_update_signers` to the PoX-4 path (`pox_4_compute_and_update_signers`), so an empty signer set can never be committed as a cycle's active reward set.
- Long term: Ensure `compute_voting_weight_threshold` cannot return `0` for a nonzero-participation cycle, and add an invariant/test asserting that any committed `RewardSet` with `signers = Some(v)` never has `v.is_empty()` when `participation > 0`.

### Proof of Concept
1. Arrange a PoX-4 reward cycle where total stacking participation is small relative to `liquid_ustx / POX_MAXIMAL_SCALING`, so `get_reward_threshold_and_participation` computes a `threshold` larger than every individual stacker's `amount_stacked` (achievable simply by having sparse/small stacking in that cycle).
2. `StacksChainState::make_reward_set` → `make_signer_set` floors every stacker's weight to `0` and filters them all out, yielding `RewardSet::V0 { signers: Some(vec![]), ... }`.
3. `pox_4_compute_and_update_signers` commits this reward set (guarded only by `participation > 0`, which holds) — no empty-set rejection occurs.
4. A miner produces a `NakamotoBlockHeader` for this reward cycle with `signer_signature = vec![]` (no signatures at all).
5. Any node calls `header.verify_signer_signatures(&reward_set, epoch_id)`: `signers = Some(&[])` passes the `None` check; `total_weight = 0`; `threshold = compute_voting_weight_threshold(0) = 0`; loop over zero signatures leaves `total_weight_signed = 0`; `0 < 0` is `false`, so the function returns `Ok(0)` — the block is accepted as validly signed despite having no signer participation whatsoever.

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

    pub fn get_reward_threshold_and_participation(
        pox_settings: &PoxConstants,
        addresses: &[RawRewardSetEntry],
        liquid_ustx: u128,
    ) -> (u128, u128) {
        let participation = addresses
            .iter()
            .fold(0, |agg, entry| agg + entry.amount_stacked);

        assert!(
            participation <= liquid_ustx,
            "CORRUPTION: More stacking participation than liquid STX"
        );

        // set the lower limit on reward scaling at 25% of liquid_ustx
        //   (i.e., liquid_ustx / POX_MAXIMAL_SCALING)
        let scale_by = cmp::max(participation, liquid_ustx / POX_MAXIMAL_SCALING);

        let reward_slots = u128::try_from(pox_settings.reward_slots())
            .expect("FATAL: unreachable: more than 2^128 reward slots");
        let threshold_precise = scale_by / reward_slots;
        // compute the threshold as nearest 10k > threshold_precise
        let ceil_amount = match threshold_precise % POX_THRESHOLD_STEPS_USTX {
            0 => 0,
            remainder => POX_THRESHOLD_STEPS_USTX - remainder,
        };
        let threshold = threshold_precise + ceil_amount;
        info!(
            "PoX participation threshold is {}, from {} + {} ({}), participation is {}",
            threshold, threshold_precise, ceil_amount, scale_by, participation
        );
        (threshold, participation)
    }
