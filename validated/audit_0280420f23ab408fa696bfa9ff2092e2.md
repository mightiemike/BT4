## Finding [1](#0-0) 

### Title
`TransactionOutput::ensure_match_transaction_info` silently skips state/hot-state/position checkpoint-hash verification, letting replay-verify accept a divergent state root as valid - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the authenticated-comparison routine used by replay/verification tooling (`storage/db-tool/src/replay_on_archive.rs`, `aptos-move/aptos-debugger/src/aptos_debugger.rs`, `aptos-move/cli/src/commands.rs`) to confirm that re-executing a historical transaction against a state view reproduces exactly the committed `TransactionInfo`. It checks status, gas, write-set hash, and event-root hash, but explicitly does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`. When `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (or hot-state root) is active, a re-execution that produces a different state/position root than what was actually committed on-chain will still be reported by the comparator as "matched," because the field is never compared.

### Finding Description
`ensure_match_transaction_info` builds `expected_txn_status`, compares `gas_used`, `write_set_hash`, and `event_root_hash` against the corresponding fields of `txn_info: &TransactionInfo`: [2](#0-1) 

It never reads or compares `txn_info.state_checkpoint_hash()`, `txn_info.hot_state_checkpoint_hash()`, or `txn_info.position_state_checkpoint_hash()`. The code contains its own acknowledgment of the gap: [3](#0-2) 

This method is the sole state-commitment integrity check used by `storage/db-tool/src/replay_on_archive.rs`'s `execute_and_verify`, which re-executes archived transactions and calls `ensure_match_transaction_info` against the archived `TransactionInfo`: [4](#0-3) 

The `compute_trading_native_state_roots` on-chain config gates whether the executor computes and binds the "trading-native" position-state root into `TransactionInfoV1.position_state_checkpoint_hash`, requiring `transaction_info_v1` and `hotness_in_epilogue` to also be enabled: [5](#0-4) 

Once that root is computed and stored as part of `TransactionInfoV1` at commit time (`execution/executor/src/workflow/do_ledger_update.rs`, `do_state_checkpoint.rs`), the accumulator leaf hash for a transaction is a function of these checkpoint hashes. If a replay/verify path recomputes a *different* checkpoint hash from a divergent local execution or storage bug, `ensure_match_transaction_info` will not catch it — it only verifies the write-set and event hashes, which say nothing about the state tree/position tree root actually committed.

### Impact Explanation
Any consumer relying on `ensure_match_transaction_info` for state-commitment integrity checking (db-tool replay-verify, aptos-debugger, aptos CLI) can be fooled into reporting a clean replay even though the locally recomputed state checkpoint root (or, once enabled, the position-state root used for "trading-native" state) diverges from the one actually committed to the ledger/accumulator. This is a proof/commitment-verification gap: the very tool whose job is to catch state divergence between execution and committed ledger state has a blind spot in exactly the field that identifies such divergence (state root). Practically this masks execution/storage bugs, corrupted replicas, or (in the worst case) a consensus-bug-induced fork from being detected by replay-verify tooling, undermining confidence in "verified" archives and any downstream trust decisions (e.g., fast-sync trust anchors, audit tooling) based on a "verify succeeded" result.

### Likelihood Explanation
The path is real and reachable today for the `state_checkpoint_hash`/`hot_state_checkpoint_hash` fields on any historical replay (V1 TransactionInfo, hot-state feature), and the `position_state_checkpoint_hash` field is gated behind the not-yet-widely-enabled `compute_trading_native_state_roots` feature flag (defaults off). The comment in the code confirms the authors are aware this must be closed "before enabling COMPUTE_TRADING_NATIVE_STATE_ROOTS," which indicates the gap is currently open and unaddressed, and is on the direct path to being exercised as that feature rolls out. No malicious actor is required — a routine execution/storage divergence is sufficient to be silently accepted.

### Recommendation
Extend `ensure_match_transaction_info` to also compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and (when `compute_trading_native_state_roots` is enabled) `position_state_checkpoint_hash` between the locally computed output and the `TransactionInfo` under verification, returning an error on any mismatch, exactly as already done for `write_set_hash` and `event_root_hash`. This should be landed before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled on any network.

### Proof of Concept
1. Enable `hotness_in_epilogue` + `transaction_info_v1` (+ eventually `compute_trading_native_state_roots`) so `TransactionInfoV1.state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` are populated at commit.
2. Take an archived chunk of transactions/`TransactionInfo`s from backup storage.
3. Run `storage/db-tool/src/replay_on_archive.rs`'s `Verifier::verify` -> `execute_and_verify` against a state view whose state tree or "trading-native" position tree diverges from the one used when the chunk was originally committed (e.g., a storage restore bug or execution bug that only affects checkpoint hashing, not the write set or events of any single transaction).
4. Observe `ensure_match_transaction_info` returns `Ok(())` because it never compares the checkpoint hash fields, and the tool reports the replay as verified even though the ledger's actual accumulator leaf/state root would differ from the locally recomputed one.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
