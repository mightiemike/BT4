### Title
Unbounded Gzip Decompression of User-Submitted Legacy `DeprecatedContractClass.compressed_program` Causes Memory Exhaustion DoS - ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
The `decompress_program` function used to convert a user-submitted legacy (Cairo 0) `DeprecatedContractClass` into the internal `starknet_api` representation performs unbounded gzip decompression with no size or time limit, unlike the equivalent Sierra program decompression path elsewhere in the codebase which explicitly enforces a `max_size` bound. A single `starknet_addDeclareTransaction` (legacy V0/V1 declare) submission containing a highly compressible `compressed_program` payload can force the RPC/gateway process to allocate unbounded memory, mirroring the reported PDFME `DecodeStream`/`FlateStream` decompression-bomb bug class (CWE-409).

### Finding Description
`decompress_program` reads the base64-decoded gzip stream fully into memory with no cap: [1](#0-0) 

```rust
pub(crate) fn decompress_program(
    base64_compressed_program: &String,
) -> Result<Program, ErrorObjectOwned> {
    base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    let compressed_data =
        base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    // TODO(dan): add time and size limits.
    let mut decoder = GzDecoder::new(compressed_data.as_slice());
    let mut decompressed = Vec::new();
    decoder.read_to_end(&mut decompressed).map_err(internal_server_error)?;
    serde_json::from_reader(decompressed.as_slice()).map_err(internal_server_error)
}
```

This is invoked from `user_deprecated_contract_class_to_sn_api`, which converts the caller-supplied `DeprecatedContractClass.compressed_program` (a base64-encoded, gzip-compressed JSON program) sent as part of a legacy declare transaction into a `starknet_api::deprecated_contract_class::ContractClass`: [2](#0-1) 

The `decoder.read_to_end` loop will keep growing the `Vec<u8>` buffer without any ceiling — exactly the "doubles with no upper bound" pattern described in the external report, just implemented via `flate2`'s `GzDecoder` and Rust's `Vec` growth instead of a hand-rolled `ensureBuffer`.

This is in stark contrast to the rest of the codebase, which explicitly hardens all other gzip/zstd decompression paths against decompression bombs:
- `decompress_with_size_limit` / `decode_and_decompress_with_size_limit` in `starknet_api::compression_utils`, which cap decoder output via `.take(max_size + 1)` and reject oversized results: [3](#0-2) 
- `DeprecatedGatewaySierraContractClass::convert_to_sierra_contract_class`, which uses that size-limited helper for the HTTP gateway's declare-v3 Sierra path: [4](#0-3) 
- `apollo_storage::compression_utils::decompress`, bounded by `MAX_DECOMPRESSED_SIZE` (256 MB): [5](#0-4) 

The `decompress_program` function in `apollo_rpc` was evidently missed when these bounds were added elsewhere — its own `TODO(dan)` comment acknowledges the gap.

### Impact Explanation
An unauthenticated remote caller of the JSON-RPC write API (`starknet_addDeclareTransaction` for a V0/V1 legacy Cairo 0 class) can submit a `compressed_program` value with a very high compression ratio (e.g., gzip of a large run of null bytes). The node will decompress it fully in-process with no size limit before any other validation runs, driving unbounded heap growth and either crashing the RPC/gateway node process (OOM) or severely degrading it — a denial-of-service on the node offering that RPC endpoint. Because this touches the gateway ingestion path from a single submitted transaction, it satisfies the "network unable to confirm new transactions" criterion if it runs on the sequencer's gateway-facing RPC service or degrades availability of the node serving RPC/declare submission.

### Likelihood Explanation
Reachability requires only crafting one legacy declare transaction JSON payload with an oversized/compressible `compressed_program` field and submitting it via the standard write RPC — no special privileges, no validator/prover access, and no reliance on cooperating nodes. This matches the "gateway validation" reachable-path category and needs only a single transaction submission to trigger.

### Recommendation
Apply the same bounded decompression pattern already used elsewhere in the codebase (`decompress_with_size_limit` / `MAX_DECOMPRESSED_SIZE`-style capping) to `decompress_program` in `crates/apollo_rpc/src/v0_8/api/mod.rs`: wrap the `GzDecoder` read with a `.take(max_size)` limit and reject the request if the decompressed size exceeds the configured maximum contract bytecode/class size (mirroring `StatelessTransactionValidatorConfig::max_contract_bytecode_size` / `max_contract_class_object_size` limits already enforced for Sierra classes), before attempting `serde_json::from_reader`.

### Proof of Concept
1. Generate a gzip-compressed JSON program body of e.g. 100 MB of repeated bytes (~1000:1 compression ratio), base64-encode it.
2. Submit a JSON-RPC `starknet_addDeclareTransaction` request with a V0/V1 `DECLARE_TXN` whose `contract_class.program` (mapped internally to `compressed_program`) is set to that base64 string.
3. Observe the RPC node's `decompress_program` fully decompress the payload into memory with no bound, causing large/unbounded allocation and potential OOM crash — before any subsequent class-size validation is reached, since the size check happens only after decompression/parsing succeeds (unlike the size-limited path used for Sierra classes elsewhere in the codebase).

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}

// The maximum size of the decompressed data.
// TODO(Dvir): consider defining this for each type separately and pass it as an argument to the
// decompress function.
pub(crate) const MAX_DECOMPRESSED_SIZE: usize = 1 << 28; // 256 MB
// The compression level to use. Higher levels are slower but compress better.
const COMPRESSION_LEVEL: i32 = zstd::DEFAULT_COMPRESSION_LEVEL;

/// Returns the compressed data in a vector.
///
/// # Arguments
/// * data - bytes to compress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn compress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::compress(data, COMPRESSION_LEVEL)
}

/// Serialized and then compress object.
///
/// # Arguments
/// * object - the object to serialize and compress.
///
/// # Errors
/// Returns [`StorageSerdeError`] if any error is encountered in the serialization or compression.
pub fn serialize_and_compress(object: &impl StorageSerde) -> Result<Vec<u8>, StorageSerdeError> {
    let mut buf = Vec::new();
    object.serialize_into(&mut buf)?;
    Ok(compress(buf.as_slice())?)
}

/// Decompress data and returns it as bytes in a vector.
///
/// # Arguments
/// * data - bytes to decompress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn decompress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::decompress(data, MAX_DECOMPRESSED_SIZE)
}
