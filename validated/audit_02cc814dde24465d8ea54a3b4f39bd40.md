Based on my investigation, `TransferToGasKeyAction` has no actor-permission restriction (unlike `AddKey`/`DeleteKey`, which are typically self-only): `validate_transfer_to_gas_key_action` in `runtime/runtime/src/action_validation.rs` only checks the `GasKeys` protocol feature is enabled and performs no receiver/predecessor identity check, and `action_transfer_to_gas_key` in `runtime/runtime/src/access_keys.rs` unconditionally adds `action.deposit` to the target gas key's `GasKeyInfo.balance` for whatever `account_id`/`public_key` pair is named, with no check that the caller is the account owner.

### Title
Anyone can grief gas-key/account deletion by pushing `GasKeyInfo.balance` over the fixed 1 NEAR burn threshold - (File: `runtime/runtime/src/access_keys.rs`)

### Summary
`GasKeyInfo::MAX_BALANCE_TO_BURN` is a fixed 1 NEAR threshold used by `delete_gas_key` and `action_delete_account` to decide whether a gas key's prepaid balance can be silently burned during deletion. `action_transfer_to_gas_key` lets *any* account send a receipt that funds *any other account's* gas key, with no ownership/actor check, analogous to the reported Curve-pool issue where an unprivileged party can push an exact/threshold-based check just over the line with a trivial deposit, breaking the intended operation.

### Finding Description
`delete_gas_key` (`runtime/runtime/src/access_keys.rs:93-111`) rejects deletion with `GasKeyBalanceTooHigh` whenever `gas_key_info.balance > GasKeyInfo::MAX_BALANCE_TO_BURN` (1 NEAR, `core/primitives-core/src/account.rs:886-888`). `action_delete_account` (`runtime/runtime/src/actions.rs:370-379`) applies the same fixed threshold to the *sum* of all gas-key balances on the account before allowing account deletion.

The only way to fund a gas key is `action_transfer_to_gas_key` (`runtime/runtime/src/access_keys.rs:257-288`), which looks up the key by `account_id` + `public_key` and does `gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit)` with **no check that the predecessor/signer is the account owner**. `validate_transfer_to_gas_key_action` (`runtime/runtime/src/action_validation.rs:453-459`) only gates on the `GasKeys` protocol feature being enabled — it performs no receiver/actor-identity validation, unlike privileged self-only actions such as `AddKey`/`DeleteKey`/`DeployContract`. Since this action can be included in a receipt sent by anyone (targeting the victim's account and a `public_key` for one of the victim's existing gas keys, learnable from chain state), an attacker can top up 1 yoctoNEAR (or any amount) onto a victim's gas key whose balance sits at or below the 1 NEAR threshold, pushing it strictly above `MAX_BALANCE_TO_BURN`.

### Impact Explanation
This is a griefing/denial-of-service vector: it permanently blocks the victim from deleting that specific gas key (`GasKeyBalanceTooHigh` on `DeleteKey`) and, if the victim relies on gas-key balances staying at or under 1 NEAR in aggregate, blocks `DeleteAccount` entirely (`action_delete_account` griefed the same way). Because the deposit is attacker-funded and gets permanently locked in the gas key (only withdrawable via `action_withdraw_from_gas_key`, which the victim *can* still call to bring the balance back down), the practical severity is bounded — the victim can call `WithdrawFromGasKey` to drain the excess and restore deletability, provided that action itself isn't blocked (e.g. by `RejectWithdrawFromGasKeyInDelegate` restrictions in delegated contexts). This differs from the original Curve report where the check was *unrecoverably* impossible to satisfy; here it is a temporary DoS unless withdrawal is also obstructed.

### Likelihood Explanation
Likelihood is high given the primitive is trivially reachable: any account can submit a transaction with a `TransferToGasKeyAction` targeting a known victim account and public key, at negligible cost (1 yoctoNEAR deposit suffices to cross the threshold if the balance is already at exactly 1 NEAR).

### Recommendation
Restrict `TransferToGasKeyAction` to self-only receipts (require `predecessor_id == account_id`, matching the pattern used for other privileged self-actions like `AddKey`/`DeleteKey`), or otherwise stop the burn-threshold check from being griefable by third-party deposits.

### Proof of Concept
1. Victim account has a gas key with `GasKeyInfo.balance == Balance::from_near(1)` (at the exact `MAX_BALANCE_TO_BURN` threshold — a normal, expected state, cf. `test_delete_gas_key_balance_at_threshold`, `runtime/runtime/src/access_keys.rs:1258-1288`).
2. Attacker (unrelated account) submits a transaction/receipt containing `Action::TransferToGasKey(TransferToGasKeyAction { public_key: <victim's gas key>, deposit: Balance::from_yoctonear(1) })` with `receiver_id` = victim account.
3. `action_transfer_to_gas_key` executes with no actor check, raising the balance to `1 NEAR + 1 yoctoNEAR`.
4. Victim's subsequent `DeleteKey` for that public key now fails with `ActionErrorKind::GasKeyBalanceTooHigh` (mirrors `test_delete_gas_key_balance_too_high`, `runtime/runtime/src/access_keys.rs:1218-1256`), and if this pushes the account's total gas-key balance over 1 NEAR, `DeleteAccount` fails the same way (`runtime/runtime/src/actions.rs:370-379`). pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}
