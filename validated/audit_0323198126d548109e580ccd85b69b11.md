### Title
Debug/Format string representations of proto messages ignore `debug_redact` field option, disclosing sensitive field values in logs - ([File: internal/msgfmt/format.go])

### Summary
The `google.protobuf.FieldOptions.debug_redact` (and `EnumValueOptions.debug_redact`) descriptor option exists specifically so that schema authors can mark fields containing "sensitive credentials" as excluded from debug/text output [1](#0-0) . However, protobuf-go's human-readable formatting code path (`internal/msgfmt`), which backs `protocmp.Message.String()` and `protopath.Values.String()`, never consults this option and unconditionally emits every field's value.

### Finding Description
`appendMessage` in `internal/msgfmt/format.go` walks every populated field via `order.RangeFields` and appends its name and value with no check of `FieldDescriptor().Options().(*descriptorpb.FieldOptions).GetDebugRedact()`: [2](#0-1) 

This formatter is exposed as the `String()`/debug representation for two commonly used developer-facing types:
- `testing/protocmp.Message.String()` calls `msgfmt.Format(m)` directly for "human debugging" output: [3](#0-2) 
- `reflect/protopath.Values.String()` calls `msgfmt.FormatValue(...)` to render `"(path) = value"` strings, again with no redaction check: [4](#0-3) 

The descriptor option is fully modeled and generated (`GetDebugRedact()` accessor exists on `FieldOptions` and `EnumValueOptions`) [5](#0-4) , and it is even wired into the `protoreflect.SourcePath` field-name resolver [6](#0-5) , confirming the option is a recognized, load-bearing part of the schema model — yet no marshaler/formatter in this codebase actually enforces the redaction semantics it promises ("Indicate that the field value should not be printed out when using debug formats, e.g. when the field contains sensitive credentials").

This is structurally analogous to the NiFi report: a documented mechanism intended to prevent sensitive values from reaching debug/log output silently fails to do so, and the value is written into a log/trace/diff output through a standard, unprivileged code path (any developer calling `%v`/`.String()`/`cmp.Diff` on a message populated from ordinary request data that a schema author marked `debug_redact`).

### Impact Explanation
Any application that (a) defines a proto field with `[debug_redact = true]` to protect a credential/secret/PII value, and (b) logs, diffs, or error-wraps the containing message via `protocmp.Message.String()`, `cmp.Diff`, or `protopath.Values.String()` — all standard, documented usages for debugging/testing — will have the "protected" value written out in cleartext. This is a confidentiality violation (CWE-532: Insertion of Sensitive Information into Log File) matching the referenced NiFi advisory's bug class, mediated purely by normal application code exercising a documented debug-formatting API on data that already flows through the process on an unprivileged path.

### Likelihood Explanation
`protocmp.Message` is the standard helper recommended for comparing/diffing protobuf messages in tests and is also commonly reached via `cmp.Diff`/`cmp.Equal` failure output that gets logged by test frameworks and CI systems; `protopath.Values.String()` is used by range/mutation utilities for diagnostic messages. No attacker interaction, elevated privilege, or unusual configuration is required — only a schema that uses `debug_redact` (as the protobuf compiler/authors' documentation invites) and a caller that formats the message for debugging, which is the exact intended use of these APIs.

### Recommendation
In `internal/msgfmt/format.go`'s `appendMessage`/`appendValue`, check `fd.Options()` for the `FieldOptions.debug_redact` (and the enum-value `debug_redact`) setting before appending a field's value, and substitute a redacted placeholder (e.g. `"[REDACTED]"`) when set, mirroring the intent already implemented in upstream `prototext`/`protojson`'s redaction logic for equivalent field annotations, if present. Apply the same check to `appendEnum`. Add regression tests asserting that a message with a `debug_redact` field does not leak its value through `protocmp.Message.String()`, `cmp.Diff`, and `protopath.Values.String()`.

### Proof of Concept
```go
package poc

import (
	"fmt"

	"google.golang.org/protobuf/testing/protocmp"
	"google.golang.org/protobuf/types/descriptorpb"
	// assume a message type M with field `secret` annotated:
	//   optional string secret = 1 [debug_redact = true];
)

func Demo(m *M) {
	// m.Secret = "super-secret-token"
	pm := protocmp.Message(map[string]interface{}{"secret": m.GetSecret()})
	fmt.Println(pm.String()) // prints: {secret:"super-secret-token"}
	// Same leak occurs via cmp.Diff(m1, m2, protocmp.Transform()) test failure output,
	// and via protopath.Values.String() when ranging over the message.
}
```
Because `appendMessage` in `internal/msgfmt/format.go` never inspects `fd.Options().(*descriptorpb.FieldOptions).GetDebugRedact()` before writing `fd.TextName()` and the field value, the `secret` field's value is written to stdout/logs verbatim despite being marked `debug_redact = true` in the `.proto` schema.

```go
func appendMessage(b []byte, m protoreflect.Message) []byte {
	if b2 := appendKnownMessage(b, m); b2 != nil {
		return b2
	}

	b = append(b, '{')
	order.RangeFields(m, order.IndexNameFieldOrder, func(fd protoreflect.FieldDescriptor, v protoreflect.Value) bool {
		b = append(b, fd.TextName()...)
		b = append(b, ':')
		b = appendValue(b, v, fd)
		b = append(b, delim()...)
		return true
	})
	b = appendUnknown(b, m.GetUnknown())
	b = bytes.TrimRight(b, delim())
	b = append(b, '}')
	return b
}
```

```go
func (m Message) String() string {
	switch {
	case m == nil:
		return "<nil>"
	case !m.ProtoReflect().IsValid():
		return "<invalid>"
	default:
		return msgfmt.Format(m)
	}
```

```go
// String returns a humanly readable representation of the path and last value.
// Do not depend on the output being stable.
//
// For example:
//
//	(path.to.MyMessage).list_field[5].map_field["hello"] = {hello: "world"}
func (p Values) String() string {
	n := p.Len()
	if n == 0 {
		return ""
	}

	// Determine the field descriptor associated with the last step.
	var fd protoreflect.FieldDescriptor
	last := p.Index(-1)
	switch last.Step.kind {
	case FieldAccessStep:
		fd = last.Step.FieldDescriptor()
	case MapIndexStep, ListIndexStep:
		fd = p.Index(-2).Step.FieldDescriptor()
	}

	// Format the full path with the last value.
	return fmt.Sprintf("%v = %v", p.Path[:n], msgfmt.FormatValue(last.Value, fd))
}
```
