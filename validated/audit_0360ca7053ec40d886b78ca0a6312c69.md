### Title
`SYSTEM_SIGNATURE` equality check in `Recovered<TransactionSigned>` conversion allows forging `SYSTEM_SIGNER` identity without ECDSA verification - (`crates/evm/src/evm/conversions.rs`)

### Summary
The conversion from a raw RLP transaction to a `Recovered<TransactionSigned>` short-circuits ECDSA recovery whenever the transaction's on-wire signature bytes equal the fixed public constant `SYSTEM_SIGNATURE = (r=0, s=0, v=false)`, assigning `caller = SYSTEM_SIGNER` via `new_unchecked` with no cryptographic check. Because `SYSTEM_SIGNATURE` is a compile-time public constant and RLP decoding never validates that `r`/`s` are non-zero valid scalars, any party able to submit a raw transaction with that literal signature triggers this path, and `CitreaHandler::validate_tx_against_state`/`deduct_caller`/`reward_beneficiary`/`output` in `crates/evm/src/evm/handler.rs` then treat it as a privileged, fee-exempt system call.

### Finding Description
The broken binding: `number_of_system_signer_txs_created_by_signed_system_transaction(block N)` should equal `number_of_txs_with_caller==SYSTEM_SIGNER_in_executed_block(N)`. The code that is supposed to guarantee this equality is: [1](#0-0) 

which checks `tx.signature() == &SYSTEM_SIGNATURE` and, if true, calls `Recovered::new_unchecked(tx, SYSTEM_SIGNER)` — bypassing `tx.try_into_recovered()` (the actual ecrecover-based verification) entirely.

`SYSTEM_SIGNATURE` is defined as a fixed, publicly known constant: [2](#0-1) 

`(r=0, s=0, yParity=false)` is not a value that any legitimate ECDSA signing process can produce, but nothing in `TransactionSigned::decode_2718` (standard RLP/2718 decode) enforces that `r`/`s` are non-zero valid secp256k1 scalars — that validation normally only happens inside `try_into_recovered()`/`recover_signer`, which this code path deliberately skips when the signature matches the constant.

Once `caller() == SYSTEM_SIGNER`, `CitreaCallExt::is_system_caller` returns true: [3](#0-2) 

and the handler waives the normal balance check, gas deduction, base-fee reward, and L1 fee deduction: [4](#0-3) [5](#0-4) [6](#0-5) 

Attacker's exact transaction: any RLP-encoded EVM transaction (e.g. EIP-1559) whose signature field is serialized as `r=0, s=0, yParity=false`, submitted via `eth_sendRawTransaction`. Only nonce correctness (matching `SYSTEM_SIGNER`'s on-chain nonce) is enforced; no balance, gas fee, or L1 fee is charged, and the call executes with `msg.sender == SYSTEM_SIGNER`, which is the identity trusted by privileged system contracts such as `BitcoinLightClient` and `BridgeWrapper`.

I was unable to fully verify, within the available tool budget, whether the sequencer's mempool ingress logic (`crates/sequencer/src/mempool.rs`, `crates/sequencer/src/deposit_data_mempool.rs` — both of which contain references to `SYSTEM_SIGNER`/`is_system_caller`) independently rejects transactions whose recovered/forced signer is `SYSTEM_SIGNER` before they can be queued and included in a block via `CallMessage::txs`. If such a guard exists and is applied prior to any use of the vulnerable `TryFrom` conversion, it would block this specific ingress path; if it does not, or if it itself relies on the same short-circuited conversion, the exploit as described is directly reachable from `eth_sendRawTransaction`.

### Impact Explanation
If unmitigated at the mempool layer, an attacker gains an unauthenticated way to execute EVM calls as `SYSTEM_SIGNER` — a caller identity relied upon by supply-affecting system contracts (`BitcoinLightClient`, `BridgeWrapper`) and fee-vault-affecting handler logic (`BASE_FEE_VAULT`/`L1_FEE_VAULT` skips). This is repeatable per block (bounded only by `SYSTEM_SIGNER`'s nonce sequencing) and would let an attacker's transaction execute without holding any balance and without paying gas/L1 fees, matching a Critical severity category (state mutation/supply accounting bypass through a forged privileged identity) if the ingress path is not blocked elsewhere.

### Likelihood Explanation
Preconditions: mainnet fork active, standard sequencer/full-node harness, attacker only needs the ability to submit a raw transaction to a public RPC endpoint — no privileged key required, since the "signature" the code accepts is a fixed public constant rather than a real cryptographic secret. Feasibility hinges entirely on whether `crates/sequencer/src/mempool.rs` (or an equivalent gate before `CallMessage::txs`) already filters out transactions that decode/recover to `SYSTEM_SIGNER`; this could not be confirmed with the tools available in this session.

### Recommendation
Do not rely on signature-byte equality to assign the `SYSTEM_SIGNER` identity to arbitrary externally-supplied `RlpEvmTransaction`s. Restrict the `SYSTEM_SIGNATURE` shortcut in `crates/evm/src/evm/conversions.rs` to transactions produced internally via `create_system_transactions`/`signed_system_transaction` (e.g. by carrying an explicit "is system tx" flag through the pipeline rather than inferring it from signature bytes), and add an explicit rejection in the mempool/RPC ingress and in `CallMessage::txs` handling for any externally-submitted transaction whose signature equals `SYSTEM_SIGNATURE` or whose recovered/forced caller equals `SYSTEM_SIGNER`.

    fn deduct_caller(&self, evm: &mut Self::Evm) -> Result<(), Self::Error> {
        if evm.is_system_caller() {
            // System caller doesn't spend gas.

            let context = evm.ctx();

            let is_call = context.tx().kind().is_call();
            let caller = context.tx().caller();

            // Load caller's account.
            let mut caller_account = context.journal().load_account(caller)?;

            // Bump the nonce for calls. Nonce for CREATE will be bumped in `handle_create`.
            if is_call {
                // Nonce is already checked
                caller_account.info.nonce = caller_account.info.nonce.saturating_add(1);
            }

            // Touch account so we know it is changed.
            caller_account.mark_touch();

            return Ok(());
        }
        self.mainnet.deduct_caller(evm)
    }
