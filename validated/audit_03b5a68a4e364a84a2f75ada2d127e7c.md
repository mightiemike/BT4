### Title
Missing declared-class existence check in Starknet OS `execute_replace_class` causes sequencer/OS state divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall sets a contract's class hash without verifying that a class with that hash was actually declared, unlike the blockifier (sequencer) implementation of the same syscall, which performs this check.

### Finding Description
In the sequencer's blockifier, `replace_class` explicitly calls `self.state.get_compiled_class(class_hash)?` to ensure the target class hash is declared (and additionally rejects non-Cairo1 classes) before updating the contract's class hash [1](#0-0) . If the class is undeclared, `get_compiled_class` returns `StateError::UndeclaredClassHash`, causing the syscall — and the transaction — to fail, as confirmed by the test `undeclared_class_hash` [3](#0-2) .

In contrast, the Starknet OS's `execute_replace_class` in `syscall_impls.cairo` directly overwrites `state_entry.class_hash` with the requested `class_hash` with no existence check at all — the code contains an explicit acknowledgment of the gap: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` [4](#0-3) . The same missing check exists in the deprecated OS syscall path `execute_replace_class` in `deprecated_execute_syscalls.cairo` [5](#0-4) .

The Starknet OS re-executes the same block that the blockifier already executed, and is expected to produce an identical state diff/commitment as a correctness proof of the sequencer's execution. Because the blockifier rejects `replace_class` calls with undeclared class hashes (transaction reverts/fails), while the OS accepts and commits them unconditionally, any contract that triggers `replace_class` with an undeclared class hash will be handled differently by the two components:
- Sequencer (blockifier): the call reverts, transaction execution outcome/state diff reflects a revert.
- Starknet OS: the call succeeds, silently writing the undeclared class hash into `contract_state_changes`, which flows into the OS-computed state commitment/output.

This is reachable by any unprivileged account contract invoking the `replace_class` syscall with an attacker-chosen (undeclared) class hash from within a normal `__execute__`/entry point call — no special privileges are required.

### Impact Explanation
This produces a state root divergence between the sequencer's actual committed state (via blockifier execution) and the Starknet OS's re-execution proof of the same block. Since the OS's computed state commitment is meant to attest to the correctness of the block the sequencer committed, an undeclared-class-hash write accepted only by the OS (but rejected by the blockifier) breaks the invariant that OS re-execution matches sequencer execution, which can cause the OS/prover to produce a state commitment/output inconsistent with the sequencer-committed state, or an inability to generate a valid proof for a block containing such a transaction — i.e., honest-node divergence in the OS proving pipeline for a legitimate transaction pattern. This maps to a critical class of bug: wrong committed root / honest-node divergence caused by inconsistent validation logic between components that are supposed to agree bit-for-bit.

### Likelihood Explanation
Any account contract can trigger `replace_class` with an arbitrary felt as class hash via a simple Cairo1 contract call (as demonstrated by the existing test harness `test_replace_class` in the feature contracts) [6](#0-5) . No special permissions, staking, or privileged role is needed — a single ordinary transaction is sufficient to exercise the divergent path. The TODO comment explicitly acknowledges the check is not yet implemented, indicating this is a known, currently-open gap rather than a hypothetical one.

### Recommendation
Add a check in the Starknet OS's `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` path) that the given `class_hash` corresponds to a class that was actually declared (mirroring the blockifier's `get_compiled_class` check), and fail/revert consistently with the blockifier's behavior when the class is undeclared.

### Proof of Concept
1. Deploy a Cairo1 account/contract exposing `test_replace_class(class_hash)` which calls `replace_class_syscall(class_hash)`.
2. Submit a transaction invoking `test_replace_class` with an arbitrary, never-declared `class_hash` (e.g., `felt!(1234_u16)`).
3. On the sequencer, the blockifier's `replace_class` calls `get_compiled_class`, which fails with `StateError::UndeclaredClassHash`, causing the syscall/transaction to fail — matching the existing test `undeclared_class_hash` [3](#0-2) .
4. When the same block is re-executed by the Starknet OS, `execute_replace_class` in `syscall_impls.cairo` performs no existence check and unconditionally writes the undeclared class hash into `contract_state_changes`, producing a different state diff/commitment than the blockifier's execution of the same transaction [4](#0-3) .

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
