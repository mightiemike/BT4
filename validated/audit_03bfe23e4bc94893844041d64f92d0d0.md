**Reasoning:** The premise of the exploit doesn't hold given how the bytecode format and verifier work.

`StructHandle.type_parameters` is the single, authoritative declaration of a struct's type parameters (including `is_phantom` flags), and it is indexed positionally. Field types within the struct definition reference type parameters exclusively via `TypeParameter(idx)` tokens that index directly into this same array [1](#0-0) . There is no separate, independently-ordered "field declaration order" that the `type_parameters` array could desynchronize from — the index *is* the binding between a field's use of a type parameter and its phantom/ability metadata in the handle.

For `StructInstantiation` in `check_ty`, the verifier zips `handle.type_parameters` with the instantiation's `ty_args` positionally and derives `required_abilities` from `ty_param.is_phantom` directly from that same authoritative array [2](#0-1) . Since `ty_args` is defined to correspond positionally to `type_parameters` by the format itself, there's no alternate ordering to spoof.

Separately, `verify_struct_def`/`verify_fields_of_struct` explicitly checks that phantom type parameters are only used in phantom positions inside field types via `check_phantom_params`, rejecting any struct where a `TypeParameter` marked phantom appears in a non-phantom position with `StatusCode::INVALID_PHANTOM_TYPE_PARAM_POSITION` [3](#0-2) [4](#0-3) . This directly guards against the "mismatched phantom flags versus field usage" scenario the question describes, independent of the `check_ty`/`StructInstantiation` logic. Any module attempting to craft such a mismatch is rejected by the bytecode verifier before it can be loaded or executed, so it cannot reach global storage operations or corrupt committed state.

/// Helper function to check if a type contains phantom type parameters in non-phantom positions.
///
/// Time complexity: `O(size_of_type)`
fn check_phantom_params(
    struct_handles: &[StructHandle],
    context: &[StructTypeParameter],
    is_phantom_pos: bool,
    ty: &SignatureToken,
) -> PartialVMResult<()> {
    use SignatureToken::*;

    match ty {
        Vector(ty) => check_phantom_params(struct_handles, context, false, ty)?,
        Function(args, result, _) => {
            for ty in args.iter().chain(result) {
                check_phantom_params(struct_handles, context, false, ty)?
            }
        },
        StructInstantiation(idx, type_arguments) => {
            let sh = &struct_handles[idx.0 as usize];
            for (i, ty) in type_arguments.iter().enumerate() {
                check_phantom_params(
                    struct_handles,
                    context,
                    sh.type_parameters[i].is_phantom,
                    ty,
                )?;
            }
        },
        TypeParameter(idx) => {
            if context[*idx as usize].is_phantom && !is_phantom_pos {
                return Err(
                    PartialVMError::new(StatusCode::INVALID_PHANTOM_TYPE_PARAM_POSITION)
                        .with_message(
                            "phantom type parameter cannot be used in non-phantom position"
                                .to_string(),
                        ),
                );
            }
        },

        Struct(_) | Reference(_) | MutableReference(_) | Bool | U8 | U16 | U32 | U64 | U128
        | U256 | I8 | I16 | I32 | I64 | I128 | I256 | Address | Signer => {},
    }

    Ok(())
}
