### Title
`execute_replace_class` in the Starknet OS Cairo program omits the "class is declared" check enforced by the blockifier — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The blockifier's Rust implementation of the `replace_class` syscall requires that the target `class_hash` already be a declared class before rewriting a contract's class pointer. The Starknet OS Cairo re-implementation of the same syscall (used for proof generation / re-execution of the block) does not perform this check — it contains an explicit `TODO` acknowledging the check is missing — and unconditionally updates `contract_state_changes` with the new class hash.

### Finding Description
In the blockifier (the component that actually executes transactions in the sequencer and decides whether a transaction succeeds/reverts), `replace_class` explicitly reads the compiled class before allowing the state update: [1](#0-0) 
The same guard exists in the deprecated (Cairo0) syscall handler: [2](#0-1) 
This behavior is unit-tested and explicitly expected to fail with "is not declared" for an undeclared class hash: [3](#0-2) 

However, the equivalent syscall implementation inside the Starknet OS Cairo program — which re-executes transactions to produce the state diff/commitment that is proven and posted as the canonical block output — does not perform this check at all. The function directly updates the contract's `state_entry.class_hash` from the syscall request without verifying the class was ever declared, and this omission is explicitly called out in a `TODO` comment: [4](#0-3) 

Root cause: the enforcement of "target class must be declared" is only implemented in the blockifier execution path (which decides success/revert during block building) but not in the Cairo OS execution path (which recomputes/verifies the resulting state and is the basis for the committed root and the proof). This is directly analogous to the reported `placeMagnet` bug: one privileged code path enforces a precondition (ownership of the planet / declaration of the class) while another reachable execution path that performs the same state-mutating action omits it.

### Impact Explanation
Because the missing check is only a `TODO` and no other guard exists elsewhere in the Cairo OS execution flow (the search for "is not declared" / declared-class validation logic in `.cairo` files under `apollo_starknet_os_program` returned no results, confirming no compensating check exists in the OS program), the two execution engines — blockifier (native Rust, used to decide inclusion/success of a transaction in a block) and the Starknet OS (Cairo, used to compute/verify the committed state and generate proofs) — can, in principle, disagree on whether a `replace_class` syscall targeting an undeclared class hash is valid. If the OS is ever driven with hints/execution info that reach `execute_replace_class` for an undeclared class hash (e.g., via any path where the OS independently derives or accepts a class hash not gated by the same declaration check blockifier enforces), the OS would silently accept an invalid class hash into `contract_state_changes`, producing a state diff/commitment that the blockifier itself would have rejected. This can manifest as a wrong committed root/state diff relative to what the sequencer's execution engine considers valid, i.e., an honest-node/engine divergence between the two independent implementations of the same protocol rule.

### Likelihood Explanation
Likelihood is constrained by the fact that in the normal block-production flow the OS re-executes transactions that already succeeded under blockifier's stricter rules, so a transaction with an undeclared class hash would ordinarily never reach the OS in the first place (blockifier would revert it first). The risk materializes specifically when the OS's independent enforcement is relied upon as the source of truth (e.g., in verification, proving, or any scenario where OS execution parameters are not perfectly identical to what blockifier validated), given that the check is asymmetric between the two engines. The presence of an explicit, unresolved `TODO` in production Cairo OS code confirms this is a known, currently-unpatched gap rather than a speculative issue.

### Recommendation
Add a declared-class check inside `execute_replace_class` in `syscall_impls.cairo`, mirroring the blockifier logic: before updating `contract_state_changes` with the new `class_hash`, verify that the class hash corresponds to a class that has already been declared (e.g., look up the class hash in the OS's declared-classes dictionary/`contract_class_changes` structure and fail/`assert` if absent), exactly as the `TODO` at line 902 suggests, so that the OS and blockifier enforce identical preconditions for this syscall.

### Proof of Concept
Not independently reproducible from static analysis alone — the Cairo OS is invoked via the SNOS re-execution/proving pipeline rather than a directly callable entry point from this repo's test harness. Concretely, the code demonstrating the gap is:
- Blockifier check (present): [1](#0-0) 
- OS check (absent, with acknowledging TODO): [4](#0-3) 

Confirming end-to-end reachability/exploitability (i.e., constructing a concrete transaction and OS execution trace that reaches this path with an undeclared class hash and produces a divergent commitment) would require running the SNOS test harness (`starknet_os_flow_tests`) with a custom contract invoking `replace_class_syscall` with an undeclared class hash and comparing blockifier vs. OS outputs — this was not executable within the current read-only investigation.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
