### Title
Zero-value Uniswap quote silently disables slippage protection on GAS-abstraction deposits and gas refunds, enabling MEV extraction of bridged/refund funds - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund` all compute a slippage-protection bound as `minPCOut = quote * 95 / 100` from a live on-chain Uniswap V3 `QuoterV2.quoteExactInputSingle` result, then pass that `minPCOut` straight into `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` with `withSwap=true`. None of these call sites validate that `quote` (and hence `minPCOut`) is non-zero before using it as the swap's minimum-output guard.

### Finding Description
In `x/uexecutor/keeper/execute_inbound_gas.go`, the swap flow is: [1](#0-0) 
`quote` comes directly from `GetSwapQuote` (`QuoterV2.quoteExactInputSingle`), and `minPCOut` is derived purely by multiplying and integer-dividing it: [2](#0-1) . The identical unguarded pattern repeats in the GAS_AND_PAYLOAD path [3](#0-2)  and in the excess-gas-refund path, `applyGasRefund`, which also feeds an unguarded quote into `CallUniversalCoreRefundUnusedGas(..., withSwap=true, fee, minPCOut)`: [4](#0-3) .

For a small enough `amount`/`refundAmount` relative to the pool's price/tick spacing (dust deposits, or a gas-fee excess of only a few wei-equivalent units — which routinely happens per the `gas_fee_refund_test.go` fixtures using values like `61`), Uniswap V3's constant-product math can return `quote == 0` due to integer truncation on-chain. When that happens, `minPCOut = 0*95/100 = 0`, which is passed as the swap's minimum-acceptable-output parameter. A `minPCOut` of `0` means the AMM swap executed inside `depositPRC20WithAutoSwap` / `refundUnusedGas` has no slippage protection at all — it will accept any non-negative output, including near-zero output if the pool is sandwiched. Nowhere in the Go keeper or in the referenced flow is there a check rejecting `quote == 0` or `minPCOut == 0` before proceeding with the swap (confirmed: no `Sign()`/`IsZero()` guard on these values in the keeper package). This mirrors the reported `adjustedRectangle == 0` bug class exactly: a computed intermediate value silently degenerating to zero disables the very protection/accounting mechanism (`excessSCX` deduction there, slippage bound here) that the surrounding code depends on, with no error raised and normal execution proceeding.

### Impact Explanation
An unprivileged attacker who observes a pending GAS/GAS_AND_PAYLOAD inbound execution or a pending outbound gas refund (both are protocol-module-originated `DerivedEVMCall`s hitting the on-chain Uniswap pool) can sandwich the swap: push the pool price against the swap immediately before it executes and revert it back immediately after, since `minPCOut=0` accepts any output. Value that should have landed at the depositor's UEA (bridged principal) or at the refund recipient (excess gas) is instead extracted by the attacker as MEV, permanently depriving the user/protocol of those funds. This affects protocol- and user-controlled PRC20/native asset accounting on the gas-abstraction and refund paths, satisfying the "stealing/draining/permanent loss of user or protocol-controlled funds" impact category.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a deposit/refund amount small enough, or pool liquidity thin enough, for the Uniswap V3 quoter to truncate to zero, and (b) attacker capability to sandwich the specific module-originated swap transaction within the same block (mempool visibility / block-proposer collusion is not required if the attacker can simply front-run/back-run via ordinary transaction submission before the swap is included). Given gas-refund amounts are frequently small (dust-level excess gas is normal), and no code path anywhere validates `quote`/`minPCOut` non-zero, this is a reachable, unprivileged, and repeatable condition rather than a rare edge case.

### Recommendation
Add an explicit guard immediately after computing `quote`/`minPCOut` in all three call sites (`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, `applyGasRefund`/`getSwapQuoteForRefund`): reject (fall back to the no-swap direct-deposit path, exactly like the existing fallback already used in `applyGasRefund`) whenever `quote.Sign() <= 0` or the computed `minPCOut.Sign() <= 0`, rather than silently proceeding with a zero-bound swap. This is analogous to inserting the `require(adjustedRectangle != 0)` mitigation recommended in the original report.

### Proof of Concept
1. Craft (or wait for) an inbound `GAS` or `GAS_AND_PAYLOAD` transaction, or an outbound whose `gasFee - gasFeeUsed` excess, that is small enough that `QuoterV2.quoteExactInputSingle` returns `0` for the given `fee` tier and pool state (realistic for low-liquidity pools or dust amounts, as seen in `gas_fee_refund_test.go` using `gasFeeUsed="50"` against `gasFee="111"`, i.e., an excess of `61`).
2. Observe `minPCOut := quote * 95 / 100` evaluate to `0` in `execute_inbound_gas.go` line 144-145 or `outbound.go` line 220-221.
3. As an ordinary chain user, submit a transaction immediately before the module's `depositPRC20WithAutoSwap`/`refundUnusedGas` call that moves the pool price unfavorably, then submit a transaction immediately after that moves it back, capturing the difference as MEV since the swap's `minPCOut=0` cannot reject the resulting bad execution price.
4. Confirm on-chain that the depositor's UEA balance or the refund recipient's balance reflects a swap output far below fair value, with the difference captured by the attacker's sandwich transactions.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
