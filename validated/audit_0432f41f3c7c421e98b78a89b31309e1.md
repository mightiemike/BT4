## Finding

### Title
Front-runnable AMM swap with fixed 5% slippage tolerance in gas-abstraction inbound execution allows sandwich-attack theft of user funds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The gas-abstraction inbound flow (`ExecuteInboundGas`) swaps a user's bridged gas-token deposit for PC through a live Uniswap-V3-style pool, using a spot quote (`GetSwapQuote`) fetched immediately before the swap and protected only by a fixed 5% slippage tolerance. Because the swap is triggered deterministically by the finalizing `MsgVoteInbound` transaction — a transaction that is publicly visible before inclusion and whose outcome (2/3 quorum reached) is predictable once 2-of-N votes are already recorded — an unprivileged attacker can sandwich the pool around that transaction and extract value from the user's swap, up to the full 5% margin, on every gas-abstraction inbound.

### Finding Description
`ExecuteInboundGas` at [1](#0-0)  performs the following steps atomically inside a single message execution:
1. Fetches the current pool quote via `GetSwapQuote`, which calls `QuoterV2.quoteExactInputSingle` against the live on-chain Uniswap pool state [2](#0-1) .
2. Computes `minPCOut = quote * 95 / 100` — a hardcoded 5% slippage tolerance [3](#0-2) .
3. Executes `CallPRC20DepositAutoSwap`, which performs the real deposit+swap through `DerivedEVMCall` with `commit=true` [4](#0-3) .

While steps 1–3 are atomic with respect to *other module logic*, the pool price they read is **not** protected from manipulation by ordinary EVM transactions submitted by third parties on Push Chain in blocks/txs immediately preceding the `MsgVoteInbound` that finalizes the ballot. The finalizing vote is a standard, publicly broadcast Cosmos transaction (`MsgVoteInbound` from a Universal Validator) that becomes predictable once quorum is nearly reached (e.g., 2 of 3 required votes already recorded and visible via `PendingInbounds`/mempool, per `RecordInboundVote` at [5](#0-4) ). An attacker watching for this state can submit an ordinary EVM transaction just before the finalizing vote lands to shift the WPC/PRC20 pool price unfavorably, then swap back immediately after, capturing the difference — a classic sandwich attack. The 5% slippage tolerance is generous enough that a large fraction of the trade's economic value can be extracted from the bridging user without ever causing the guarded transaction to revert, since `minPCOut` only guards against a full 5% adverse move, not against MEV extraction within that margin.

This is a structural analog of the reported bonding-curve race condition: an attacker observes a predictable, imminent state-changing transaction on a price-sensitive AMM-like mechanism and profits by transacting around it, at the expense of the legitimate actor (here, the bridging user, and indirectly the protocol's PC liquidity).

### Impact Explanation
Every user who bridges a native gas token from an external chain through the gas-abstraction inbound path (`TxType_GAS` handled by `ExecuteInboundGas`) is exposed to this MEV extraction. The 5% slippage window is fixed regardless of trade size, so larger gas-abstraction bridges lose proportionally more value to sandwich attackers. This constitutes unauthorized draining of user-controlled funds through a user-reachable, unprivileged flow (an ordinary attacker submitting standard EVM swap transactions), which is in scope per "stealing, draining ... of user or protocol-controlled funds" and "corruption of ... gas fee accounting ... token mapping."

### Likelihood Explanation
Likelihood is moderate to high in an environment with a public mempool: the inbound's parameters (amount, source token) are known once the first UV votes are recorded and visible, and the finalizing vote is a normal broadcast transaction subject to standard transaction ordering/MEV dynamics. No validator or admin collusion is required — only an external actor monitoring `PendingInbounds` state / mempool traffic and capital to manipulate the specific WPC/PRC20 pool, both of which fall within "ordinary unprivileged user actions."

### Recommendation
- Replace the fixed 5% slippage tolerance with a tighter, dynamically computed bound (e.g., based on trade size relative to pool depth, or a much smaller fixed bound), and/or use a TWAP-based reference price instead of a spot `quoteExactInputSingle` call for `minPCOut`.
- Consider executing the swap with commit-reveal or batching to remove predictability of the exact block in which the swap executes.
- Alternatively, route the swap through a protected execution path (e.g., private/relayed submission) so the finalizing vote and swap cannot be front-run by public mempool observers.
- Document and cap the maximum acceptable price impact per gas-abstraction swap, and consider failing safe (reverting the inbound rather than executing at a bad price) beyond a much lower threshold than 5%.

### Proof of Concept
1. Attacker monitors `x/uexecutor` `PendingInbounds`/mempool and observes a `GAS`-type inbound close to quorum (2 of 3 needed UV votes already recorded, per `RecordInboundVote`).
2. Attacker predicts the finalizing `MsgVoteInbound` will trigger `ExecuteInboundGas` → `GetSwapQuote` → `CallPRC20DepositAutoSwap` for a known `amount` of the source gas token.
3. Attacker submits a large swap on the same WPC/PRC20 pool (front-run) to move the price against the pending swap, timed to land in the block immediately before the finalizing vote's block.
4. The finalizing vote executes `ExecuteInboundGas`; the swap fills at the worse price still within the 5% `minPCOut` band and therefore does not revert.
5. Attacker submits a back-run swap to restore the pool price, realizing profit equal to the price impact they induced, extracted from the value that should have gone to the bridging user as PC. [1](#0-0) [2](#0-1) [5](#0-4)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
