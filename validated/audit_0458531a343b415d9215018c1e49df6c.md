### Title
Slippage protection for module-driven PRC20→WPC auto-swaps relies solely on a manipulable spot quote, enabling sandwich extraction of bridged user funds - ([File: x/uexecutor/keeper/evm.go])

### Summary
`x/uexecutor` computes `minPCOut` slippage bounds for `depositPRC20WithAutoSwap` and `refundUnusedGas` swaps by calling `QuoterV2.quoteExactInputSingle` — an instantaneous, current-block Uniswap V3 spot quote — and applying a fixed 5% haircut. There is no independent, manipulation-resistant reference price (e.g., TWAP) anywhere in the codebase. Because the quote and the swap execution read the same live pool state, an attacker who moves the pool price in a preceding transaction of the same block can force the module's auto-swap to execute at an attacker-favorable rate, then reverse the price in a following transaction to capture the value the deposit/refund swap gave up — a classic sandwich attack. This is the direct analog of the `Seer` finding: relying on a single, unprotected price without pairing it against a safer bound lets an attacker skew the price the protocol accepts.

### Finding Description
`GetSwapQuote` in [1](#0-0)  performs a read-only `CallEVM` to `QuoterV2.quoteExactInputSingle`, which returns the output amount at the pool's *current* `sqrtPriceX96`/reserves — there is no TWAP averaging window, and `SqrtPriceLimitX96` is hardcoded to `0` (no limit).

That quote is used to derive `minPCOut` with a flat 5% slippage tolerance in three call sites:
- `ExecuteInboundGas` (GAS route): [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD route): [3](#0-2) 
- `applyGasRefund` (outbound excess-gas refund): [4](#0-3) 

The actual swap is then executed on-chain via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, both of which call into the same `UniversalCore`/Uniswap V3 pool state: [5](#0-4) [6](#0-5) .

Because the "protection" and the "execution" are read from and applied against the *same* manipulable spot price, `minPCOut` is not an independent floor — it merely tracks whatever price an attacker has already pushed the pool to. An attacker can:
1. Submit a large swap against the PRC20/WPC pool on Push Chain to push the pool price so that PRC20→WPC output is artificially depressed.
2. Wait for (or race, via gas-price/ordering) the validator-triggered `MsgVoteInbound`/`MsgVoteOutbound` finalization that invokes `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`/`applyGasRefund` for a pending bridged deposit or gas refund — this call quotes and swaps within the manipulated pool state, yielding far less WPC/PC than a fair price would.
3. Reverse the initial swap in a following transaction in the same block, capturing the value the module's swap gave up as arbitrage profit.

This directly corrupts PRC20/native accounting: the user's bridged/refunded value is siphoned to the attacker via AMM sandwiching, matching the in-scope impact "corruption of PRC20 or native asset accounting" and "stealing/draining ... loss of user or protocol-controlled funds," triggered entirely by an unprivileged external actor through ordinary transaction submission (no validator, relayer, or admin compromise required).

### Impact Explanation
Every bridged GAS / GAS_AND_PAYLOAD deposit and every excess-gas refund routes user funds through this unprotected swap. The pool that backs WPC/PRC20 pairs is a standard Uniswap V3 pool deployed on Push Chain itself (see e2e setup deploying `v3-core`/`v3-periphery`/`QuoterV2`), so its liquidity is whatever third parties provide — it can be shallow, especially for less-common gas tokens, making it more susceptible to price-impact manipulation. A successful sandwich directly reduces the PC amount credited to the victim's UEA or the refund recipient, i.e., real user fund loss.

### Likelihood Explanation
Medium-High: no privileged access is required — any address can submit ordinary swap transactions against the pool. The main constraint is whether the attacker can predict/order transactions around the specific block in which the finalizing `MsgVoteInbound`/`MsgVoteOutbound` lands, which is a well-established MEV technique on public mempools/block construction, and is easier here because the swap amount and target chain/token are often knowable in advance (e.g., watching pending inbound votes). Shallow liquidity for niche gas tokens increases the attacker's ability to move price cheaply.

### Recommendation
Do not derive the slippage floor from the same live pool state that will execute the swap. Use an independent, manipulation-resistant reference (e.g., a Uniswap V3 TWAP `observe()` over a sufficiently long window, or a Chainlink/oracle-module reference price such as `ChainMeta`), and additionally set a conservative maximum-price-impact bound (using the pool's own configured slippage vs the TWAP, not vs. its own spot). If a TWAP oracle is unavailable, at minimum, gate execution on a maximum acceptable deviation between successive quotes across blocks, or route through a governance-set fixed conversion rate with a circuit breaker.

### Proof of Concept
1. Deploy/observe the PRC20↔WPC Uniswap V3 pool used by `UniversalCore` (e.g., the pool for a bridged gas token).
2. Attacker submits Tx A: a large `exactInputSingle` swap of PRC20 into the pool, or WPC out of the pool, to depress the PRC20→WPC exchange rate.
3. A pending inbound (already voted by 2/3+ UVs) is finalized in the same block by `MsgVoteInbound`, invoking `k.ExecuteInboundGas`, which calls `GetSwapQuote` (reads the now-depressed price), computes `minPCOut = quote*95/100`, and calls `CallPRC20DepositAutoSwap`, which executes the deposit-swap at the depressed price — see [2](#0-1) .
4. Attacker submits Tx C in the same block reversing Tx A, restoring the pool price and capturing the WPC/PC that the module's swap gave up due to the depressed execution price.
5. Victim's UEA receives materially less PC than a fair-price swap would have produced; attacker profits the difference minus pool fees.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

func (k Keeper) CallUniversalCoreRefundUnusedGas(

	gasToken common.Address,
	amount *big.Int,
	recipient common.Address,
	withSwap bool,

	minPCOut *big.Int,

	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err

		return nil, err
