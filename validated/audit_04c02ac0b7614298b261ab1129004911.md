## Finding: Replay-verify comparator silently skips checkpoint-hash validation, letting a corrupted state root pass as "verified" - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the function used by db-tool's `replay-verify` (`storage/db-tool/src/replay_on_archive.rs`) and by the chunk-replayer path to confirm that locally re-executed transaction output matches the archived/expected `TransactionInfo` for a version. Its own doc comment admits it does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` — only status, gas, write-set hash, and event root hash are compared. [1](#0-0) 

### Finding Description
`ensure_match_transaction_info` explicitly enumerates the fields it checks and stops short of the checkpoint hashes, with a TODO acknowledging the gap: [2](#0-1) 

This function is invoked by `replay_on_archive.rs`'s `execute_and_verify`, which re-executes archived transactions with `AptosVMBlockExecutor` and then calls `ensure_match_transaction_info` against the `expected_txn_infos` pulled from the backup/archive, treating success as proof the replay matches the historical, signed ledger state: [3](#0-2) 

Because the state (and hot-state / position-state) checkpoint hash is never re-derived and compared, a state root divergence introduced anywhere in the state-checkpoint / Merkle-commit path (e.g., an incorrect `state_checkpoint_hash` baked into a stored `TransactionInfo`, or a local execution bug that changes committed state without changing the write-set hash or events) will not be detected by this tool. The real proof binding still exists in the transaction-accumulator (`TransactionInfo::hash()` includes `state_checkpoint_hash` per `TransactionInfoV0`/`V1` field lists, see `types/src/transaction/mod.rs:2402-2461`), but `replay-verify` never recomputes/compares the checkpoint hash locally — it only compares the write-set hash and events, then trusts the archived `TransactionInfo`'s checkpoint hash as-is.

### Impact Explanation
This is a proof/verification-tooling integrity gap, not a consensus-committing bug: it does not corrupt any committed ledger data, and the accumulator/ledger-info itself is unaffected. Its concrete effect is that an operator running `db-tool replay-verify` (or any caller of `ensure_match_transaction_info`) can receive a **false "replay matches" result** even when the locally recomputed state-checkpoint root diverges from the archived/authenticated one, because that specific field is skipped in the comparator. This weakens the guarantee that replay-verify tooling would catch a state-root divergence (e.g., from a hard fork bug, an execution non-determinism, or a tampered backup), since only write-set-hash and event equality are enforced, not the state Merkle root equality.

### Likelihood Explanation
Likely to manifest whenever `replay-verify` is used to audit archives/backups after a protocol change involving state-checkpoint hashing (state Merkle root, hot-state root, or the new "position" state root), given the TODO explicitly calls out `COMPUTE_TRADING_NATIVE_STATE_ROOTS` as the trigger for enabling checkpoint-hash validation but it's not enabled by default. Since checkpoint hashes are only computed periodically (per-block, not per-txn), most day-to-day replay-verify runs would already skip most of these checks even if enabled, but currently there is no code path at all that performs this comparison — it's a systemic gap in the verifier rather than intermittent.

### Recommendation
Extend `ensure_match_transaction_info` to recompute the state checkpoint hash (and hot-state/position-state checkpoint hash, when features are enabled) from local execution and compare against `txn_info.state_checkpoint_hash()` / `hot_state_checkpoint_hash()` / `position_state_checkpoint_hash()`, mirroring how `write_set_hash` and `event_root_hash` are already validated. Until `COMPUTE_TRADING_NATIVE_STATE_ROOTS`-style support is implemented, `replay-verify` output should be documented/labeled as **not** validating state-root equivalence.

### Proof of Concept
1. Take an archived block backup where `TransactionInfo.state_checkpoint_hash` is deliberately wrong/stale relative to the real historical state root (or comes from a differently-configured node with a diverging state-checkpoint computation), while write-set and events for that version are unchanged.
2. Run `db-tool replay-on-archive` (`storage/db-tool/src/replay_on_archive.rs::Verifier::verify`) against this backup.
3. `execute_and_verify` re-executes the block and calls `ensure_match_transaction_info`, which only checks status, gas, write-set hash and event root hash — the divergent `state_checkpoint_hash` is never inspected.
4. The tool reports the chunk as **successfully verified** even though the state root would not match a correct implementation, demonstrating the comparator's blind spot. [1](#0-0) [4](#0-3) 

---
Note: I was not able to fully trace whether `execution/executor/src/chunk_executor/mod.rs`'s use of `ensure_match_transaction_info` (in the `ReplayChunkVerifier`/state-sync replay path) has an independent state-root check elsewhere in that file that would compensate for this gap — the file is large and I only confirmed the import, not the full call-site context, due to iteration limits. This should be verified before treating the chunk-executor replay path as equally affected; the `db-tool replay_on_archive.rs` path is confirmed and independent of that concern.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())

    fn execute_and_verify(
        &self,
        executor: &AptosVMBlockExecutor,
        current_version: &mut Version,
        cur_txns: &mut Vec<Transaction>,
        cur_persisted_aux_info: &mut Vec<PersistedAuxiliaryInfo>,
        expected_txn_infos: &mut Vec<TransactionInfo>,
        expected_events: &mut Vec<Vec<ContractEvent>>,
        expected_writesets: &mut Vec<WriteSet>,
    ) -> Result<Option<Error>> {
        if cur_txns.is_empty() {
            return Ok(None);
        }
        let txns = cur_txns
            .iter()
            .map(|txn| SignatureVerifiedTransaction::from(txn.clone()))
            .collect::<Vec<_>>();
        let txns_provider = DefaultTxnProvider::new(
            txns,
            cur_persisted_aux_info
                .iter()
                .map(|info| AuxiliaryInfo::new(*info, None))
                .collect(),
        );
        let executed_outputs = executor
            .execute_block(
                &txns_provider,
                &self
                    .arc_db
                    .state_view_at_version(current_version.checked_sub(1))?,
                BlockExecutorConfigFromOnchain::new_no_block_limit(), // TODO(HotState): will need to incorporate some features.
                TransactionSliceMetadata::Chunk {
                    begin: *current_version,
                    end: *current_version + cur_txns.len() as u64,
                },
            )
            .map(BlockOutput::into_transaction_outputs_forced)?;
        assert_eq!(executed_outputs.len(), cur_txns.len());

        for idx in 0..cur_txns.len() {
            let version = *current_version;
            *current_version += 1;

            if let Err(err) = executed_outputs[idx].ensure_match_transaction_info(
                version,
                &expected_txn_infos[idx],
                Some(&expected_writesets[idx]),
                Some(&expected_events[idx]),
            ) {
                cur_txns.drain(0..idx + 1);
                cur_persisted_aux_info.drain(0..idx + 1);
                expected_txn_infos.drain(0..idx + 1);
                expected_events.drain(0..idx + 1);
                expected_writesets.drain(0..idx + 1);

                return Ok(Some(err));
            }
        }

        cur_txns.clear();
        cur_persisted_aux_info.clear();
        expected_txn_infos.clear();
        expected_events.clear();
        expected_writesets.clear();

        Ok(None)
    }
