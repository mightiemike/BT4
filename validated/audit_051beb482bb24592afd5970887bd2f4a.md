### Title
Unbounded growth of `DelegatedResourceAccountIndexCapsule.fromAccounts`/`toAccounts` list allows free, permissionless denial-of-service on delegate/undelegate resource processing - ([File: actuator/src/main/java/org/tron/core/actuator/FreezeBalanceActuator.java])

### Summary
When `FreezeBalanceContract` is used to delegate bandwidth/energy resource, and the network has not enabled the `AllowDelegateOptimization` feature (i.e. the legacy index format is still in use), `FreezeBalanceActuator.delegateResource()` appends the counterparty address into an in-memory `List<ByteString>` stored inside a single `DelegatedResourceAccountIndexCapsule` record, guarded only by a linear `contains()` scan, with no upper bound on list size. Any address can be made the target ("receiver") of an unbounded number of delegations from distinct owner accounts, causing that victim's `fromAccounts` list (and the analogous `toAccounts` list on the owner side) to grow without limit, exactly analogous to `MultiRangeHook.poolLpTokens` growing without limit in the external report.

### Finding Description
`FreezeBalanceActuator.delegateResource()` maintains the legacy delegation index as follows: [1](#0-0) 

This mirrors the reported pattern precisely:
- `createRange()` permissionlessly `push`es into `poolLpTokens[poolId]` with no cap; here, any account can permissionlessly cause `addToAccount()` / `addFromAccount()` to append to `DelegatedResourceAccountIndexCapsule` lists with no cap, guarded only by an O(n) `contains()` check before insertion.
- The reported `afterSwap()` then iterates the entire unbounded array on every ordinary swap; here, every subsequent `FreezeBalanceContract` delegation to the same receiver, and any later `UnfreezeBalanceActuator` unwind of a delegation involving that receiver, must load, linearly scan/rebuild, and re-serialize the entire unbounded list: [2](#0-1) 

To grow a victim's `fromAccounts` list, an attacker only needs many distinct owner accounts (sybils, trivially and cheaply created) each freezing the network minimum TRX amount and delegating to the same victim address. Because `FreezeBalanceActuator.calcFee()` returns 0, this costs the attacker only bandwidth points (regenerating for free) plus temporarily-locked TRX that is fully recoverable after the freeze period, not a real fee. As the list grows to thousands of entries, every future `contains()` check, `ArrayList` remove/rebuild, and full protobuf re-serialization of the capsule (`delegatedResourceAccountIndexStore.put(...)`) becomes progressively more expensive, degrading block-validation throughput for every node that must re-execute these transactions — a direct DoS on ordinary resource-delegation transactions, not merely on the attacker's own account.

The codebase's own newer path (`supportAllowDelegateOptimization()` → `delegate()`/`delegateV2()` using per-pair DB keys with a `V2_FROM_PREFIX`/`V2_TO_PREFIX` prefix scheme instead of an in-memory list) demonstrates that the project itself later engineered away from this exact list-based design — analogous to Paladin's post-hoc "max 5 ranges" fix for `MultiRangeHook`. However, that optimization is a committee-activated proposal parameter; the vulnerable legacy code path (`FreezeBalanceActuator.delegateResource()`'s `else` branch operating on `DelegatedResourceAccountIndexStore` list fields) remains present and reachable whenever that parameter has not been activated (e.g. fresh/private-chain deployments using this codebase, or historically on TRON mainnet prior to activation of the optimization proposal): [3](#0-2) [4](#0-3) 

### Impact Explanation
Repeated, cheap (near-zero net cost, only temporarily locked capital) creation of sybil delegations toward a single target address causes an unbounded, attacker-controlled `DelegatedResourceAccountIndexCapsule` list to be created and stored on-chain. All future transactions that touch that list (new delegations to/from the target, or any unfreeze/undelegate touching that pair) incur O(n) cost to read, scan, mutate, and rewrite the entire serialized list. This degrades transaction execution time during block validation for every full node in the network processing such transactions — a resource-exhaustion / denial-of-service condition on resource-delegation processing, reachable purely from unprivileged, broadcastable `FreezeBalanceContract`/`UnfreezeBalanceContract` transactions.

### Likelihood Explanation
Exploitability requires only the ability to broadcast `FreezeBalanceContract` transactions from many accounts and delegate resource to a single target address — no privileged role, no leaked keys, and no P2P/node compromise. The main constraints are (a) needing to fund many sybil accounts with the minimum freezable TRX amount (fully recoverable) and (b) the vulnerable legacy path only being active while the `AllowDelegateOptimization` feature is not yet enabled by governance. Given that constraint is outside this analysis's ability to confirm for any specific deployment's current on-chain state, likelihood is assessed as present-but-conditional on feature-flag state, mirroring the Paladin report's own acknowledgment that a similar residual risk (actor creating all ranges before others) remains even after their fix.

### Recommendation
- Deprecate/remove the legacy list-based `DelegatedResourceAccountIndexStore` code path entirely (rather than leaving it reachable when the optimization flag is unset), or enforce it as always-on for new/default configurations.
- If the legacy path must remain for backward compatibility, impose a hard cap on the number of entries permitted in `toAccounts`/`fromAccounts` per `DelegatedResourceAccountIndexCapsule`, rejecting further delegations once the cap is reached, mirroring the "maximum of five ranges per pool" fix adopted for `MultiRangeHook`.
- Ensure `ContractValidateException` is thrown in `FreezeBalanceActuator.validate()` (not just `execute()`) once a configurable per-address delegation-index size limit is exceeded.

### Proof of Concept
1. Deploy/operate a java-tron node/network where `DynamicPropertiesStore`'s delegate-optimization flag has not been activated (default/legacy state).
2. From N distinct funded accounts, broadcast `FreezeBalanceContract` transactions each freezing the minimum allowed TRX amount and delegating bandwidth to the same fixed `receiverAddress` (the victim), invoking `FreezeBalanceActuator.execute()` → `delegateResource()`.
3. Observe `DelegatedResourceAccountIndexCapsule` for `receiverAddress` growing unbounded (`fromAccountsList` size == N) as shown at [5](#0-4) .
4. Measure the increasing per-transaction execution latency of subsequent delegate/undelegate operations touching `receiverAddress` as N grows (linear scan + full-list rewrite + full protobuf re-serialization cost), demonstrating degraded transaction-processing throughput analogous to the reported `afterSwap()` out-of-gas DoS.

*Note: I could not verify from the indexed code whether `AllowDelegateOptimization` defaults to enabled on any currently-deployed mainnet-equivalent configuration in this repository (the default value assignment for this dynamic property was not found in the indexed portion of `DynamicPropertiesStore.java`); this affects the real-world likelihood assessment and would need to be confirmed in a live/full checkout.*

  private long delegateResource(byte[] ownerAddress, byte[] receiverAddress, boolean isBandwidth,
      long balance, long expireTime) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicPropertiesStore = chainBaseManager.getDynamicPropertiesStore();
    DelegatedResourceStore delegatedResourceStore = chainBaseManager.getDelegatedResourceStore();
    DelegatedResourceAccountIndexStore delegatedResourceAccountIndexStore = chainBaseManager
        .getDelegatedResourceAccountIndexStore();
    byte[] key = DelegatedResourceCapsule.createDbKey(ownerAddress, receiverAddress);
    //modify DelegatedResourceStore
    DelegatedResourceCapsule delegatedResourceCapsule = delegatedResourceStore
        .get(key);
    if (delegatedResourceCapsule != null) {
      if (isBandwidth) {
        delegatedResourceCapsule.addFrozenBalanceForBandwidth(balance, expireTime);
      } else {
        delegatedResourceCapsule.addFrozenBalanceForEnergy(balance, expireTime);
      }
    } else {
      delegatedResourceCapsule = new DelegatedResourceCapsule(
          ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
      if (isBandwidth) {
        delegatedResourceCapsule.setFrozenBalanceForBandwidth(balance, expireTime);
      } else {
        delegatedResourceCapsule.setFrozenBalanceForEnergy(balance, expireTime);
      }

    }
    delegatedResourceStore.put(key, delegatedResourceCapsule);

    //modify DelegatedResourceAccountIndexStore
    if (!dynamicPropertiesStore.supportAllowDelegateOptimization()) {

      DelegatedResourceAccountIndexCapsule ownerIndexCapsule =
          delegatedResourceAccountIndexStore.get(ownerAddress);
      if (ownerIndexCapsule == null) {
        ownerIndexCapsule = new DelegatedResourceAccountIndexCapsule(
            ByteString.copyFrom(ownerAddress));
      }
      List<ByteString> toAccountsList = ownerIndexCapsule.getToAccountsList();
      if (!toAccountsList.contains(ByteString.copyFrom(receiverAddress))) {
        ownerIndexCapsule.addToAccount(ByteString.copyFrom(receiverAddress));
      }
      delegatedResourceAccountIndexStore.put(ownerAddress, ownerIndexCapsule);

      DelegatedResourceAccountIndexCapsule receiverIndexCapsule
          = delegatedResourceAccountIndexStore.get(receiverAddress);
      if (receiverIndexCapsule == null) {
        receiverIndexCapsule = new DelegatedResourceAccountIndexCapsule(
            ByteString.copyFrom(receiverAddress));
      }
      List<ByteString> fromAccountsList = receiverIndexCapsule
          .getFromAccountsList();
      if (!fromAccountsList.contains(ByteString.copyFrom(ownerAddress))) {
        receiverIndexCapsule.addFromAccount(ByteString.copyFrom(ownerAddress));
      }
      delegatedResourceAccountIndexStore.put(receiverAddress, receiverIndexCapsule);

    } else {
      // modify DelegatedResourceAccountIndexStore new
      delegatedResourceAccountIndexStore.convert(ownerAddress);
      delegatedResourceAccountIndexStore.convert(receiverAddress);
      delegatedResourceAccountIndexStore.delegate(ownerAddress, receiverAddress,
          dynamicPropertiesStore.getLatestBlockHeaderTimestamp());
    }

  public void delegate(byte[] from, byte[] to, long time) {
    byte[] fromKey = Bytes.concat(FROM_PREFIX, from, to);
    DelegatedResourceAccountIndexCapsule toIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(to));
    toIndexCapsule.setTimestamp(time);
    this.put(fromKey, toIndexCapsule);

    byte[] toKey = Bytes.concat(TO_PREFIX, to, from);
    DelegatedResourceAccountIndexCapsule fromIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(from));
    fromIndexCapsule.setTimestamp(time);
    this.put(toKey, fromIndexCapsule);
  }

  public void delegateV2(byte[] from, byte[] to, long time) {
    byte[] fromKey = Bytes.concat(V2_FROM_PREFIX, from, to);
    DelegatedResourceAccountIndexCapsule toIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(to));
    toIndexCapsule.setTimestamp(time);
    this.put(fromKey, toIndexCapsule);

    byte[] toKey = Bytes.concat(V2_TO_PREFIX, to, from);
    DelegatedResourceAccountIndexCapsule fromIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(from));
    fromIndexCapsule.setTimestamp(time);
    this.put(toKey, fromIndexCapsule);
  }

  public void unDelegate(byte[] from, byte[] to) {
    byte[] fromKey = Bytes.concat(FROM_PREFIX, from, to);
    this.delete(fromKey);
    byte[] toKey = Bytes.concat(TO_PREFIX, to, from);
    this.delete(toKey);
  }
