### Title
Unbounded, fee-free `UniversalPayload.Data` in gasless `MsgExecutePayload` lets an unprivileged user grief validator CPU/mempool resources with near-zero cost — ([File: x/uexecutor/types/universal_payload.go], [File: app/txpolicy/gasless.go], [File: app/ante/fee.go])

### Summary
`MsgExecutePayload` is in Push Chain's gasless whitelist, meaning `DeductFeeDecorator` unconditionally skips fee collection for it. Its `UniversalPayload.Data` field has no size cap in `ValidateBasic`, only a hex-validity check. Every node that admits, re-broadcasts, or processes such a message must hex-decode and ABI-encode the entire attacker-supplied blob (`NewAbiUniversalPayload`/`types.ParseUeaABI` path) before any EVM gas metering begins, and the tx costs the submitter nothing in Cosmos fees.

### Finding Description
This is a structural analog of the `SpecificActionERC20TransferBatchEnforcer` bug: an attacker fully controls the size of a payload that a third party (there, the delegate paying gas; here, Push Chain validators and full nodes) must process before any meaningful validation/authorization check fails, and the attacker pays disproportionately little for that cost.

- `UniversalPayload.ValidateBasic()` ( [1](#0-0) ) only checks that `Data` is valid hex — there is no upper bound on `len(p.Data)`.
- `MsgExecutePayload` is included in the gasless message whitelist ( [2](#0-1) ), and `DeductFeeDecorator.AnteHandle` short-circuits fee collection entirely for any tx classified as gasless ( [3](#0-2) ), before the SDK's normal fee-based gas economics apply.
- On the processing path, `ExecutePayload` first calls `types.NewAbiUniversalPayload(universalPayload)` to hex-decode and ABI-encode the payload "early (fast-fail before EVM work)" ( [4](#0-3) ), and `NewAbiUniversalPayload` performs `utils.HexToBytes(proto.Data)` over the full attacker-controlled blob with no length guard ( [5](#0-4) ).
- This work — hex decode, allocation, ABI re-encoding for the eventual `DerivedEVMCall` — happens in plain Go computation inside `CheckTx`/`DeliverTx`, outside the SDK `GasMeter` (the meter only tracks operations that explicitly call `ConsumeGas`), and before the EVM's own calldata-gas accounting is engaged (`CallUEAExecutePayload` → `DerivedEVMCall`, [6](#0-5) ).
- Even in the failure case (attacker doesn't own the target UEA's key, so the on-chain UEA signature check reverts, per `x/uexecutor/README.md`'s "contract-only binding" authorization model, [7](#0-6) ), all of that CPU work is already spent by every node that validates/re-executes the tx (`CheckTx` in the mempool of every node, `DeliverTx`/re-execution during block sync), while the attacker paid **zero** Cosmos transaction fee.

### Impact Explanation
An unprivileged external attacker can submit a stream of `MsgExecutePayload` transactions with maximal-size `UniversalPayload.Data` (bounded only by the Cosmos SDK/Tendermint max tx/block size, which is orders of magnitude larger and unrelated to fee economics), each processed for free by every full node's mempool (`CheckTx`) and by every validator during block execution, causing sustained CPU/memory overhead disproportionate to the fee paid (none). This degrades throughput/responsiveness of honest, unprivileged-reachable nodes — a compute-cost griefing DoS reachable purely through the default `MsgExecutePayload` submission path, matching the "denial of service...not network-level...reachable without privileged control" allowed-impact category.

### Likelihood Explanation
High reachability: `MsgExecutePayload` explicitly allows "any" signer (`x/uexecutor/README.md`: `MsgExecutePayload | any | yes | Execute a payload...`), is gasless by design, and requires no bonded/privileged role. No mint/burn/fund-drain impact is present (the UEA's on-chain signature check protects funds), so this is scoped purely to the resource-exhaustion/gas-griefing analog of the reported bug, not a funds-loss finding.

### Recommendation
- Add an explicit maximum length check on `UniversalPayload.Data` (and any other unbounded string/byte fields reachable from gasless message types) in `UniversalPayload.ValidateBasic()`.
- Consider charging a minimal, size-proportional Cosmos gas/fee for gasless message types even when the fee is ultimately refunded/subsidized, so `ante`-stage CPU cost tracks a metered budget (`ConsumeGas` for decode/ABI-encode work) rather than being fully exempt.
- Cap the total payload size accepted by `CheckTx`/mempool admission for gasless message types specifically, independent of the general max-tx-size limit.

### Proof of Concept
No PoC was executed against a live node (out of scope for this analysis mode); the finding is derived from static code tracing:
1. Craft `MsgExecutePayload{Signer: attacker, UniversalAccountId: victim_or_arbitrary, UniversalPayload: {To: any_addr, Data: "0x" + <near-max-tx-size hex blob>, ...}, VerificationData: "0x00"}`.
2. Submit repeatedly; `IsGaslessTx` returns true (message type is whitelisted), so `DeductFeeDecorator` never charges a fee.
3. Every node's `CheckTx` calls `ValidateBasic` → `UniversalPayload.ValidateBasic` (only a hex check, no size cap) and, on delivery, `ExecutePayload` → `NewAbiUniversalPayload` performs full hex-decode/ABI-encode over the blob before the (inevitably failing) UEA signature check reverts the tx — all for zero fee.

```go
// ValidateBasic does the sanity check on the UniversalPayload fields.
func (p UniversalPayload) ValidateBasic() error {
	// Validate 'to' address
	if strings.TrimSpace(p.To) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "to address cannot be empty")
	}
	if !utils.IsValidAddress(p.To, utils.HEX) {
		return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid to address format: %s", p.To)
	}

	// Validate 'data' is a valid hex string
	if len(p.Data) > 0 {
		if _, err := hex.DecodeString(strings.TrimPrefix(p.Data, "0x")); err != nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid hex data")
		}
	}
```

```go
// CallUEAExecutePayload executes a universal payload through UEA
func (k Keeper) CallUEAExecutePayload(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	universal_payload *types.UniversalPayload,
	verificationData []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiUniversalPayload, err := types.NewAbiUniversalPayload(universal_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	gasLimit := new(big.Int)
	gasLimit, ok := gasLimit.SetString(universal_payload.GasLimit, 10)
	if !ok {
		return nil, fmt.Errorf("invalid gas limit: %s", universal_payload.GasLimit)
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		gasLimit,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"executeUniversalTx",
		abiUniversalPayload,
		verificationData,
	)
}
```

```markdown
#### Why this is safe under `Signer ≠ Owner`

An attacker submitting `MsgExecutePayload` with their own `Signer` and a victim's `UniversalAccountId` produces no exploitable outcome:

- The factory resolves the victim's UEA address from the embedded `UniversalAccountId` — correct.
- `evmFrom` (derived from `Signer`) becomes the EVM-level `msg.sender` of the call to the UEA. Since `evmFrom != UNIVERSAL_EXECUTOR_MODULE` (`0x14191Ea54B4c176fCf86f51b0FAc7CB1E71Df7d7`), the contract enforces the signature check.
- The attacker cannot forge `VerificationData` that recovers to the victim's owner key.
- The contract reverts → the keeper returns an error → the Cosmos transaction reverts in full.
- Net effect: zero state change. No EVM gas is charged to the victim UEA (the deduction is rolled back with the rest of the transaction). The submission costs the attacker nothing on chain (gasless), but also achieves nothing.
```
