### Title
Unhandled `Option::unwrap()` panic on attacker-controlled Sierra classes in `SierraToNativeCompiler::compile` - ([File: crates/apollo_compile_to_native/src/compiler.rs])

### Summary
`SierraToNativeCompiler::compile` invokes the external `cairo-native` compiler binary in a resource-limited subprocess (mirroring the isolated `SierraToCasmCompiler::compile` flow), but after the subprocess succeeds it unconditionally calls `.unwrap()` on the `Option` returned by `AotContractExecutor::from_path`, assuming the executor is always present on a successful compile. This is the same bug class as the TensorFlow Grappler advisory: an assumption ("if compilation succeeded, the artifact is present/well-formed") that is not actually enforced by the type system (`Result<Option<Self>, _>`) and can be falsified by an attacker-crafted, otherwise-valid Sierra program, turning a recoverable compilation-failure into a hard `panic!`.

### Finding Description
`SierraToNativeCompiler::compile` runs the `cairo-native` compiler binary out-of-process with CPU/memory limits, then reads back the produced artifact: [1](#0-0) 

Only the outer `Result` from `AotContractExecutor::from_path` is mapped to a `CompilationUtilError`; the inner `Option` is force-unwrapped, so any successful-but-degenerate compilation output where `from_path` legitimately returns `Ok(None)` panics inside this call, in-process, with no isolation (unlike the Sierra→CASM path where a similar `CHECK`/abort would just be reported as `CompilationUtilError::CompilationError`, as demonstrated by the "process terminated by signal 6" regression test for the CASM compiler).

This function is reached from `NativeClassManager`, which drives native compilation for every accepted Cairo1 declare, either synchronously on the transaction/block-processing thread, or asynchronously on a dedicated single compilation-worker thread: [2](#0-1) [3](#0-2) 

- In `CairoNativeMode::WaitOnCompilation`, the panic happens directly on the thread handling the declare/transaction, which is the block-building/execution path.
- In `CairoNativeMode::LazyCompilation`, the panic kills the single compilation worker thread. Once that worker thread is gone, the channel's receiver is dropped, and every subsequent attempt to enqueue a compilation request hits the disconnected-channel branch, which itself panics on the *calling* thread: [4](#0-3) 

So a single malicious declare transaction can either directly crash the block-processing thread, or permanently disable native compilation and cause every subsequent Cairo1 declare to panic the caller as well.

### Impact Explanation
A single declare transaction submitted by any unprivileged sender can trigger an unhandled Rust panic on the sequencer's execution/block-building path (or on the native-compilation worker thread, followed by cascading panics on the caller for every later declare). If the sequencer binary is built with `panic = "abort"` (a common production setting for such services), this aborts the whole process, halting block production — matching the "network unable to confirm new transactions" impact bar. Even with unwind semantics, repeatedly killing/poisoning the shared compilation channel constitutes a persistent denial of service for native-class compilation and, in `WaitOnCompilation` mode, for block building itself.

### Likelihood Explanation
Reachability requires only a standard declare transaction (Cairo1 class) accepted by the gateway/mempool — no special privileges. It further requires that the deployment has Cairo-native compilation enabled (`CairoNativeMode` != `Off`), which is a supported production configuration path (`ContractClassManagerConfig`, `apollo_node_config`). Whether `AotContractExecutor::from_path` can actually return `Ok(None)` for a crafted-but-otherwise-successfully-compiling Sierra program depends on internals of the external `cairo-native`/`cairo_native::executor` crate that are outside this repository's index; this cannot be fully confirmed from the sequencer codebase alone, so likelihood is assessed as reachable-but-unconfirmed at the boundary condition.

### Recommendation
Replace the `.unwrap()` in `SierraToNativeCompiler::compile` with a proper error path: treat `Ok(None)` from `AotContractExecutor::from_path` as a `CompilationUtilError::CompilationError` (or a dedicated variant), exactly as the sibling `SierraToCasmCompiler` treats subprocess/deserialization failures, so malformed-but-"successful" native compilation results cannot panic the calling thread. Additionally, harden `NativeClassManager::send_compilation_request` and the worker loop so that a panic inside `process_compilation_request` (e.g., via `catch_unwind` around the compile call, or restarting the worker thread) cannot permanently poison the compilation channel and cascade into panics on unrelated future transactions.

### Proof of Concept
1. Deploy/operate a sequencer node with `CairoNativeMode::LazyCompilation` (or `WaitOnCompilation`) enabled.
2. Submit a declare transaction for a Cairo1 class whose Sierra program is crafted such that the `cairo-native` binary exits successfully (writes an output file) but the resulting artifact causes `cairo_native::executor::AotContractExecutor::from_path` to return `Ok(None)` (boundary condition in the underlying `cairo_native` crate, not verifiable from this repo's index).
3. Observe the `.unwrap()` in `SierraToNativeCompiler::compile` (`crates/apollo_compile_to_native/src/compiler.rs:58-60`) panics: in `WaitOnCompilation` this panics the block-processing thread directly; in `LazyCompilation` this kills the compilation worker thread, after which every subsequent declare transaction's call to `send_compilation_request` panics on `TrySendError::Disconnected` (`crates/blockifier/src/state/native_class_manager.rs:218-220`).

```rust
    fn send_compilation_request(
        &self,
        request: CompilationRequest,
    ) -> Result<(), ContractClassManagerError> {
        let sender = self.sender.as_ref().expect("Compilation channel not available.");
        // TODO(Avi, 15/12/2024): Check for duplicated requests.
        sender.try_send(request).map_err(|err| match err {
            TrySendError::Full((class_hash, _, _)) => {
                log::debug!(
                    "Compilation request channel is full (size: {}). Compilation request for \
                     class hash {:#066x} was not sent.",
                    self.cairo_native_run_config.channel_size,
                    class_hash.0
                );
                ContractClassManagerError::TrySendError(TrySendError::Full(class_hash))
            }
            TrySendError::Disconnected(_) => {
                panic!("Compilation request channel is closed.")
            }
        })
    }
```

```rust
fn run_compilation_worker(
    class_cache: RawClassCache,
    receiver: Receiver<CompilationRequest>,
    compiler: Arc<SierraToNativeCompiler>,
    panic_on_compilation_failure: bool,
) {
    log::info!("Compilation worker started.");
    for compilation_request in receiver.iter() {
        process_compilation_request(
            class_cache.clone(),
            compiler.clone(),
            compilation_request,
            panic_on_compilation_failure,
        )
        .unwrap_or(());
    }
    log::info!("Compilation worker terminated.");
}
```
