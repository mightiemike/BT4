## Finding: Gas fee floor-division bug lets sub-1-`upc` base fees zero out `CalculateGasCost`

This is a solid analog to the Neptune policy-fee report: a Dec→integer conversion that truncates instead of rounding correctly, but here the direction is worse — it can zero out real gas fee accounting for legitimately executed `MsgExecutePayload` / UEA transactions.

### Title
Floor-division of `baseFee` in `CalculateGasCost` truncates sub-1-`upc` base fees to zero, allowing free EVM execution via `DeductGasFeesFromReceipt` — (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` converts the feemarket's `LegacyDec` `baseFee` (18-decimal fixed-point) to a whole-`upc` integer with plain integer division (`baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`), rather than rounding up (`Ceil`), which is the pattern used elsewhere in the same codebase for identical Dec→Coin conversions. [1](#0-0) 

### Finding Description
`DeductGasFeesFromReceipt` is invoked after every `MsgExecutePayload`-driven UEA EVM execution to charge the recipient the gas actually consumed: [2](#0-1) 

It reads the current dynamic `baseFee` from the feemarket module and calls `CalculateGasCost`, which floors the `baseFee` down to whole `upc` before multiplying by `gasUsed`: [3](#0-2) 

Because `upc` is treated as the atomic/smallest denomination, whenever `baseFee < 1e18` (i.e., less than 1 whole `upc` in the 18-decimal `LegacyDec` encoding), `baseFeeBig.Div(..., 1e18)` truncates to `0`. `effectiveGasPrice` becomes `0`, so `gasCost = effectiveGasPrice * gasUsed = 0` regardless of how much gas was actually used. `DeductGasFeesFromReceipt` then short-circuits on `gasCost.Sign() <= 0` and skips fee deduction entirely — the EVM execution (real state mutation: PRC20 mint/burn, UEA calls, etc.) proceeds and is billed nothing.

This is the same class of bug as the reported policy-fee floor issue: an integer-rounding decision silently biases the computed value away from correctness. Elsewhere in this exact codebase, the correct convention for Dec→Coin fee conversion is to round up (`Ceil().RoundInt()`), specifically to avoid ever under-charging: [4](#0-3) [5](#0-4) 

`CalculateGasCost` deviates from that convention and floors instead, which — unlike the ante-handler fee checks that merely gate a minimum acceptable *offer* — directly determines the amount *burned* from the user's UEA balance for actual EVM work already performed.

The feemarket's dynamic base fee is not floor-protected against dropping below 1 `upc`: it adjusts up/down block-by-block based on ordinary gas utilization (standard EIP-1559-style mechanics), which is influenced purely by ordinary, unprivileged user transaction volume — no privileged actor or governance action is required to push it into the sub-1-`upc` range over a sequence of low-utilization blocks.

### Impact Explanation
When `baseFee` decays below `1 upc` (a state reachable by ordinary network activity/idleness, not a privileged action), every `MsgExecutePayload` execution routed through `DeductGasFeesFromReceipt` is billed `0 upc` no matter how much EVM gas was actually consumed. This corrupts gas fee accounting (an explicitly in-scope impact: "corruption of ... gas fee accounting") and lets unprivileged UEA users execute arbitrary payloads without paying for the compute/state resources consumed, effectively causing a loss of protocol-expected fee revenue and enabling free-of-charge EVM execution at scale (spam/resource exhaustion via repeated free execution) once the condition is hit.

### Likelihood Explanation
Likelihood is real but conditional: it requires the feemarket's dynamic base fee to fall under 1 whole `upc` (10^18 in the internal `LegacyDec` representation), which depends on chain configuration/genesis defaults and sustained low block utilization. Genesis configs observed in this repo mostly seed very high base fees (1e6–1e9 `upc`), making the condition unlikely under current default parameters, but nothing in `CalculateGasCost` itself, nor a documented feemarket param floor, structurally prevents the dynamic base fee from eventually decaying into the sub-1-`upc` range through ordinary market dynamics over time.

### Recommendation
Round the `baseFee`-to-`upc` conversion up (`Ceil`) rather than truncating with integer `Div`, consistent with `app/cosmos/min_gas_price.go` and `app/ante/validator_tx_fee.go`, so that `effectiveGasPrice` is never silently rounded down to `0` when a positive fractional base fee exists. At minimum, treat a `0 < baseFee < 1e18` remainder as `effectiveGasPrice = 1` rather than `0` to guarantee non-zero billing whenever `gasUsed > 0` and `baseFee > 0`.

### Proof of Concept
1. Drive (or configure via test harness) `feemarketKeeper.GetBaseFee` to return a `LegacyDec` value less than `1e18` (e.g., `500000000000000000` = 0.5 `upc`), reachable in principle through sustained low-utilization blocks under the dynamic fee mechanism.
2. Submit a `MsgExecutePayload` with `maxFeePerGas >= 0` (trivially satisfies the check since `baseFeeBig` floors to `0`) that causes non-trivial `gasUsed` in the target UEA.
3. Observe `CalculateGasCost` returns `gasCost = 0`, and `DeductGasFeesFromReceipt` returns early without transferring/burning any `upc` from the recipient's balance, despite `receipt.GasUsed > 0`.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
