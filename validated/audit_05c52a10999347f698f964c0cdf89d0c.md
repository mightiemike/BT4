There is no code path reachable purely from an unprivileged caller of `table::new_table_handle` that causes the constant itself to change or causes historical replay to pick a different gas schedule than what was committed — the constant is uniform, unconditionally applied at every feature version unless explicitly re-gated, exactly like the other undated constants in the same file (`add_box_base`, `borrow_box_base`, etc.).
