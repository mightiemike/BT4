### Title
Gateway CORS wildcard-origin check uses unanchored suffix match, allowing attacker-controlled domains to bypass allowlist - (File: core/services/gateway/network/httpserver.go)

### Summary
`httpServer.isAllowedOrigin` validates the `Origin` header against `CORSAllowedOrigins` entries, including wildcard entries like `*.example.com`. For wildcard entries it strips the `*.` prefix and then checks `strings.HasSuffix(originHost, allowedHost)` with no label-boundary check, exactly the same bug class as the ENS `DNSSECImpl.verifySignature` finding, which compared a signer's packed name against a zone name using unanchored containment instead of comparing label-by-label.

### Finding Description
The relevant code: [1](#0-0) 

```go
// check for wildcard host match (e.g., *.remix.com)
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if strings.HasSuffix(originHost, allowedHost) {
        return true
    }
}
```

`strings.HasSuffix(originHost, allowedHost)` treats `allowedHost` as a plain string suffix rather than a DNS label boundary. If an operator configures `CORSAllowedOrigins = ["https://*.example.com"]`, the check strips it to `example.com` and then accepts any `originHost` ending in the literal characters `example.com` — with no requirement that the preceding character be a `.` label separator. An attacker who registers `evil-example.com` (or `notexample.com`) satisfies `strings.HasSuffix("evil-example.com", "example.com") == true`, so the request's `Origin` header is accepted as if it were a legitimate subdomain of `example.com`.

This is structurally identical to the reported ENS bug: `rrset.signerName.equals(0, name, name.length - rrset.signerName.length)` accepted `xample.eth.` as a valid signer for `e\x05xample.eth.` because it checked raw substring containment instead of verifying a proper DNS label boundary. Here, `strings.HasSuffix` plays the same unanchored-containment role for hostnames.

### Impact Explanation
`isAllowedOrigin` gates whether the gateway echoes back `Access-Control-Allow-Origin: <origin>` and enables cross-origin browser access to the gateway's HTTP JSON-RPC endpoint: [2](#0-1) 

If the CORS allowlist is misconfigured with a wildcard entry (a documented, supported pattern per `sample_config.toml`/`sample_config_tls.toml` and exercised by `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards`), an unprivileged external attacker can register a domain that merely ends with the allowed suffix and host malicious JavaScript there. A victim's browser visiting that attacker-controlled origin would then be allowed to make authenticated cross-origin requests to the gateway on the victim's behalf, with the response readable by the attacker page — a CORS-bypass leading to unauthorized cross-origin request/response exposure against the gateway's node-facing API.

### Likelihood Explanation
Exploitability requires an operator to configure a wildcard CORS allowlist entry (`*.domain.tld`), which is an explicitly supported and documented configuration option (present in `core/scripts/gateway/sample_config.toml` and covered by dedicated wildcard tests). Given that, exploitation only requires registering a domain string containing the allowed suffix as a trailing substring (e.g., `evil-example.com` vs. allowed `*.example.com`), which is trivial and inexpensive for an attacker — unlike the ENS DNSSEC case, which required crafting DNS-label-packed names satisfying strict length/encoding constraints that the original reporters and the ENS maintainer agreed made real-world exploitation implausible. This Chainlink CORS analog has no equivalent packing constraint, making it more directly exploitable whenever a wildcard entry is configured.

### Recommendation
Anchor the wildcard suffix match to a label boundary instead of a raw string suffix, e.g. require that either `originHost == allowedHost` or `originHost` ends with `"." + allowedHost`:

```go
if strings.HasPrefix(allowedHost, "*.") {
    allowedHost = allowedHost[2:]
    if originHost == allowedHost || strings.HasSuffix(originHost, "."+allowedHost) {
        return true
    }
}
```

### Proof of Concept
1. Operator configures the gateway with `CORSAllowedOrigins = ["https://*.example.com"]`.
2. Attacker registers `https://evil-example.com` and hosts a malicious page there.
3. A victim's browser (already authenticated to the gateway or performing a request with implicit credentials) loads the attacker page, which issues a cross-origin `fetch`/`XMLHttpRequest` to the gateway with `Origin: https://evil-example.com`.
4. `isAllowedOrigin` computes `allowedHost = "example.com"` and evaluates `strings.HasSuffix("evil-example.com", "example.com")`, which is `true`, so the gateway responds with `Access-Control-Allow-Origin: https://evil-example.com`.
5. The browser permits the attacker page's script to read the cross-origin response, defeating the intended origin restriction, as demonstrated by the accepted-match logic exercised in `TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards` at [3](#0-2)  (note this test only checks legitimate subdomains; it does not cover the `evil-example.com`-style bypass since no such negative case is verified for the wildcard branch).

func (s *httpServer) handleRequest(w http.ResponseWriter, r *http.Request) {
	if s.config.CORSEnabled {
		origin := r.Header.Get("Origin")
		if s.isAllowedOrigin(origin) {
			w.Header().Set("Access-Control-Allow-Origin", origin)
			w.Header().Set("Access-Control-Allow-Methods", "GET, POST, OPTIONS")
			w.Header().Set("Access-Control-Allow-Headers", "Content-Type")
		}

		// handle preflight requests
		if r.Method == http.MethodOptions {
			w.WriteHeader(http.StatusNoContent)
			return
		}
	}

func TestHTTPServer_HandleRequest_CORSEnabled_FromAllowedOriginWildcards(t *testing.T) {
	t.Parallel()
	_, handler, url := startNewServer(t, 100_000, 100_000, true,
		[]string{"https://*.ethereum.org", "https://*.valid.domain.com", "http://*.gov"})

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin := "https://remix.ethereum.org"
	resp, respBytes := sendRequest(t, url, []byte("0123456789"), http.MethodPost, &origin)
	require.Equal(t, http.StatusOK, resp.StatusCode)
	require.Equal(t, []byte("response"), respBytes)
	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))

	handler.On("ProcessRequest", mock.Anything, mock.Anything, mock.Anything).Return([]byte("response"), 200)

	origin = "https://another.valid.domain.com"

	require.Equal(t, http.StatusOK, resp.StatusCode)
	require.Equal(t, []byte("response"), respBytes)
	require.Equal(t, origin, resp.Header.Get("Access-Control-Allow-Origin"))
	require.Equal(t, "GET, POST, OPTIONS", resp.Header.Get("Access-Control-Allow-Methods"))
	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))

	require.Equal(t, "Content-Type", resp.Header.Get("Access-Control-Allow-Headers"))
}
