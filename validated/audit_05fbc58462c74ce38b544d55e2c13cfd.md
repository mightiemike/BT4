### Title
CPU exhaustion DoS via unbounded query-parameter repetition in app proxy HMAC normalization - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
`authenticateAppProxyFactory` (used by both `shopify-app-remix` and `shopify-app-react-router`) validates every incoming request to the app's proxy endpoint by calling `api.utils.validateHmac(searchParams, {signator: 'appProxy'})` with a `URLSearchParams` built directly from the raw, unauthenticated request URL. Before the signature is even checked, `normalizeQuery` in `hmac-validator.ts` iterates over every query-string entry and, for any repeated non-reserved parameter, repeatedly re-concatenates a growing string. Because the app proxy path is a public HTTP endpoint that anyone can hit directly (the whole point of the HMAC check is to reject requests that didn't originate from Shopify), an attacker can submit a URL with many repeated instances of the same arbitrary parameter name and force quadratic-time string building purely to normalize the query, well before authentication is decided — mirroring the referenced report's pattern of unbounded, attacker-triggered work performed ahead of/during an authorization decision.

### Finding Description
The public entry point is `authenticateAppProxyFactory`: [1](#0-0) 

`validateAppProxyHmac` builds a `URLSearchParams` straight from the raw request URL and passes it to `api.utils.validateHmac`. That function calls `normalizeQuery`, which for `URLSearchParams` input has this loop: [2](#0-1) 

Only four "security" keys (`hmac`, `shop`, `signature`, `timestamp`) are protected against repetition: [3](#0-2) 

Any other parameter name can be repeated an arbitrary number of times, and each repetition executes `normalizedQuery[key] = `${existingValue},${value}``, which allocates a new string equal to the length of everything accumulated so far. This is confirmed intentional/allowed behavior by the existing test that expects repeated non-reserved params ("consentGiven") to be concatenated rather than rejected: [4](#0-3) 

Because string concatenation of an ever-growing value is `O(n)` per operation, `N` repeats of the same key produce `O(N²)` total work — all of it happening before the eventual (and inevitable) signature mismatch is detected, so the request is never "authenticated" but still consumes disproportionate CPU.

### Impact Explanation
Node.js request handling is effectively single-threaded for CPU-bound work; a handful of concurrent requests carrying many repeated query parameters targeted at the app-proxy route can occupy the event loop for extended periods, delaying or blocking all other requests the app is trying to serve — a denial-of-service of the request-authentication handler itself. This falls squarely into "DoS of an auth handler," one of the explicitly accepted analog categories, and directly parallels the referenced bug class: attacker-controlled input size driving unbounded work inside a security-check code path before any authorization/verification succeeds.

### Likelihood Explanation
The app-proxy endpoint is, by design, a normal public HTTP route on the merchant's app (Shopify's own proxying is what the HMAC check is meant to enforce, not what protects the endpoint from being reached directly). Any unauthenticated actor can send a crafted GET request with a long query string of repeated arbitrary parameter names — no credentials, secrets, or privileged access are required. The remaining constraint is the maximum URL/query length accepted by the deployment's HTTP server or edge platform, which still typically allows tens of thousands of characters, enough to produce a meaningful quadratic blow-up.

### Recommendation
- In `normalizeQuery` (`packages/apps/shopify-api/lib/utils/hmac-validator.ts`), cap the total number of query parameters and/or the total accumulated size for any single key before performing normalization, rejecting requests early (e.g., with a 400) instead of concatenating unboundedly.
- Alternatively, collect repeated values into an array and join once at the end (`values.join(',')`) instead of repeated string concatenation, and additionally enforce a hard maximum count/size for any given key regardless of algorithmic approach.
- Consider validating overall query-string length/parameter count as the very first step of `authenticateAppProxyFactory`/`validateAppProxyHmac`, before constructing `URLSearchParams` or invoking `validateHmac` at all.

### Proof of Concept
1. Deploy an app using `shopify-app-remix` (or `shopify-app-react-router`) with the app-proxy route configured, per `authenticateAppProxyFactory`.
2. As an anonymous client (no Shopify signature needed to trigger the cost — only to pass it), send:
   `GET /apps/proxy?shop=x&timestamp=<now>&signature=irrelevant&dup=1&dup=1&dup=1&...` repeating `dup=1` tens of thousands of times up to the server's URL-length limit.
3. Observe that `validateAppProxyHmac` → `api.utils.validateHmac` → `normalizeQuery` spends significant CPU time building the concatenated `dup` value via the loop at [5](#0-4)  before ultimately failing the signature check — demonstrating that the cost is paid regardless of whether the request is legitimate, and scales quadratically with the number of repeated parameters the attacker chooses to send.

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}
