### Title
Webhook HMAC does not bind to `X-Shopify-Shop-Domain`, enabling cross-shop replay to force session/data deletion - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
This is a direct structural analog of the reported Forwarder "missing domain separator" issue: a signature is verified without binding it to the identifier that is later used to scope trust/authorization. In the Forwarder, the EIP-712 domain separator's `chainId` isn't checked against the executing chain, so a valid signature can be replayed on the wrong chain. Here, the webhook HMAC is computed and verified over `rawBody` only [1](#0-0)  and the `X-Shopify-Shop-Domain` header is never included in the signed material, only parsed separately after HMAC success [2](#0-1) .

### Finding Description
`validateFactory` first calls `validateHmacFromRequestFactory`, which validates the `hmac` header strictly against `rawBody` [3](#0-2) , and only afterward extracts `domain` from the (unsigned) `X-Shopify-Shop-Domain` header via `checkWebhookHeaders`/`checkWebhooksHeaders` [4](#0-3) . Because the app's client secret is shared across every shop that has the app installed, any merchant who has installed the app can capture a legitimate webhook body+HMAC that Shopify sent to their own store, then replay that exact `rawBody`/`X-Shopify-Hmac-Sha256` pair directly to the app's webhook endpoint while substituting an arbitrary victim shop domain in `X-Shopify-Shop-Domain`. The HMAC check still succeeds because it never considered the domain, so `check.domain` (attacker-controlled) is trusted downstream.

In `shopify-app-express`, this `domain` is passed straight into the `APP_UNINSTALLED` handler as `shop`, which is used by `deleteAppInstallationHandler` to call `AppInstallations.delete(shop)` [5](#0-4) , deleting **every** stored session for that shop [6](#0-5) . The same `check.domain` value flows into the `shopify-app-remix`/`shopify-app-react-router` webhook context as `shop`, which is used to call `ensureValidOfflineSession(params, check.domain)` and build the `admin`/`session` context for arbitrary app-defined topic handlers [7](#0-6) .

### Impact Explanation
A malicious merchant of a multi-tenant app can force a Denial of Service against any other merchant of the same app by replaying an `APP_UNINSTALLED` webhook body they legitimately received, with the domain header rewritten to the victim shop — causing the victim's offline (and online) session records to be deleted, effectively "uninstalling" them from the app's perspective without the victim's consent or Shopify's involvement. For topics beyond `APP_UNINSTALLED`, any app-specific webhook handler that trusts `shop`/`domain` to select a session or perform per-tenant side effects is similarly exposed to being invoked against the wrong tenant.

### Likelihood Explanation
Exploitation only requires being (or briefly becoming) a legitimate merchant installer of the target app — an unprivileged, anonymous-to-the-victim actor — capturing one real Shopify webhook delivery, and replaying it directly to the app's public webhook URL with a modified header. No secrets need to be leaked and no MITM is required, since domains are never part of the signed payload.

### Recommendation
Bind the shop identity into the verified material: either include the shop domain (and ideally topic/webhook ID) in the HMAC computation, or independently corroborate `X-Shopify-Shop-Domain` against a trusted source (e.g., only proceed if a session already exists for that domain and was created via a real OAuth/token-exchange flow, and require idempotent/webhook-ID tracking) before performing any per-tenant mutation such as session deletion in `AppInstallations.delete`.

### Proof of Concept
1. Install the app on `attacker-shop.myshopify.com`; capture the real `APP_UNINSTALLED` webhook Shopify sends, including its raw body and `X-Shopify-Hmac-Sha256` header.
2. POST that exact body and HMAC header to the app's webhook endpoint, but set `X-Shopify-Shop-Domain: victim-shop.myshopify.com`.
3. `validateHmacFromRequestFactory` succeeds because it only checks `rawBody` against the HMAC [8](#0-7) ; `checkWebhooksHeaders` returns `domain: 'victim-shop.myshopify.com'` as valid [9](#0-8) .
4. In `shopify-app-express`, `deleteAppInstallationHandler` is invoked with `shop = 'victim-shop.myshopify.com'` and deletes all of that shop's sessions [5](#0-4) , denying the victim service until they reinstall/reauthenticate.

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };

function checkWebhooksHeaders(
  headers: Headers,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };
