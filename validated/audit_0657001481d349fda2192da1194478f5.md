### Title
Uniswap V3 spot-price quote used as unprotected slippage reference for module-driven PRC20→PC auto-swaps enables value extraction from user deposits - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
For `GAS` and `GAS_AND_PAYLOAD` inbound routes, and for excess-gas refunds, the `uexecutor` module auto-swaps a user's PRC20 into native PC via `UniversalCore.depositPRC20WithAutoSwap`. The `minPCOut` slippage floor passed into that swap is computed from `GetSwapQuote`, which calls `QuoterV2.quoteExactInputSingle` — a function that simulates the swap against the pool's *current* on-chain reserves/spot price, not a time-weighted or externally verified price. Because the reference price and the executed swap price are drawn from the same manipulable pool state, an attacker who moves the pool price immediately before the module's swap executes can force user deposits to swap at a degraded rate while the 5%-slippage check still passes (since it is checked against the same skewed price), extracting value from the swap.

### Finding Description
The relevant flow is:
1. `GetUniversalCoreQuoterAddress`, `GetUniversalCoreWPCAddress`, `GetDefaultFeeTierForToken` fetch static config [1](#0-0) .
2. `GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` on the live pool, returning `amountOut` based on the pool's current reserves/sqrt price [2](#0-1) .
3. `minPCOut` is derived as `quote * 95 / 100`, then passed straight into `CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap`, which performs the real swap in the same or immediately following EVM call [3](#0-2) .
4. The exact same pattern repeats for `GAS_AND_PAYLOAD` in `gasAndPayloadDepositAutoSwap` [4](#0-3)  and for gas-fee refunds in `applyGasRefund`/`getSwapQuoteForRefund` [5](#0-4) .

Unlike the reported `MagicLpAggregator` bug where a *view-only oracle* fed downstream lending/borrowing logic, here the manipulable "oracle" (the QuoterV2 spot quote) is used as the *sole* slippage reference for a real swap executed by the protocol on behalf of the user, with no comparison against an independent price feed, no TWAP window, and no minimum liquidity/deviation check. An attacker who can execute a swap against the same WPC/PRC20 Uniswap V3 pool in a transaction ordered before the module's inbound-processing transaction within the same block (or across sequential blocks, since inbound processing timing is deterministic/predictable from public inbound votes) can shift the pool's spot price so that both the quote and the actual swap execute at an unfavorable rate for the depositing user, while technically satisfying the 5% slippage bound derived from the same skewed price.

### Impact Explanation
This directly causes loss of user funds: a user's bridged PRC20 gas token is swapped into fewer native PC tokens than fair market value, with the difference captured by whoever manipulated the pool. This falls within the explicit in-scope impact "unauthorized ... state transitions in universal execution flows" and "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" caused by an unprivileged external attacker interacting only with the public AMM pool and ordinary inbound submission — no malicious validator, relayer, or privileged actor is required.

### Likelihood Explanation
Likelihood depends on pool liquidity depth for each PRC20/WPC pair and on the attacker's ability to get a manipulating swap ordered adjacent to the module's auto-swap execution. Push Chain's inbound processing is driven by validator votes on public source-chain events, so an attacker can observe an inbound in flight and time a pool-price manipulation transaction on Push Chain to land in the same or preceding block before the module executes `depositPRC20WithAutoSwap`. Thinly liquid PRC20/WPC pools (as seeded in the e2e setup script with small amounts, e.g. `pool_token_amount="1"`, `pool_wpc_amount="4"`) make this materially easier and cheaper to execute [6](#0-5) .

### Recommendation
Do not derive the slippage floor solely from the same pool's instantaneous spot quote. Options:
- Use a TWAP-based quote (e.g., `observe`/`secondsAgo` over the pool's oracle observations) instead of `quoteExactInputSingle`'s spot simulation.
- Cross-check the QuoterV2 quote against an independent reference price (e.g., the chain-meta gas-price oracle or a configured expected exchange rate) and reject/clamp the swap if the deviation exceeds a bounded threshold, mirroring the external report's recommended sanity-check pattern.
- Enforce a minimum pool liquidity/TVL requirement before allowing auto-swap routes for a given PRC20, falling back to non-swap deposit (`depositPRC20Token`) when liquidity is too thin to resist manipulation.

### Proof of Concept
1. Deploy/observe a low-liquidity PRC20/WPC Uniswap V3 pool on Push Chain (as configured for e2e testing).
2. Submit or await a legitimate `GAS`/`GAS_AND_PAYLOAD` inbound for that PRC20; its presence becomes visible via validator votes before finalization.
3. Immediately before the block that will execute `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, execute a large swap against the same pool to push the PRC20→WPC spot price down.
4. When the module calls `GetSwapQuote` then `CallPRC20DepositAutoSwap`, both the quote and the swap execute against the manipulated price; `minPCOut = quote*95/100` still passes because it was computed from the same skewed state.
5. Reverse the manipulating swap afterward to realize profit from the value extracted from the user's deposit, all without any privileged access to the protocol.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
