### Title
Empty PBFT signature list bypasses quorum check and forges finalized block/epoch commit data - (File: framework/src/main/java/org/tron/core/net/messagehandler/PbftDataSyncHandler.java)

### Summary
`PbftDataSyncHandler.validPbftSign` only performs the 2/3+1 quorum/signature validation when `srSignList.size() != 0`; if the list is empty, the function falls through to `return true` at the end, treating a signature-less commit as valid. This is reachable directly from an unprivileged P2P peer sending a crafted `PbftCommitMessage`.

### Finding Description
`processMessage` decodes any incoming `PbftCommitMessage` from a peer with no authentication of the sender or content beyond `allowPBFT()` being true, and simply caches it by `viewN`/`epoch`: [1](#0-0) 

Later, `processPBFTCommitData` (invoked internally on new block processing) pulls the cached message and calls `processPBFTCommitMessage`, which calls `validPbftSign(raw, pbftCommitMessage.getPBFTCommitResult().getSignatureList(), chainBaseManager.getWitnesses())`: [2](#0-1) 

The vulnerable validation function only runs the quorum/signature-address checks inside an `if (srSignList.size() != 0)` block; when the signature list is empty, none of the checks execute and the function reaches `return true` unconditionally: [3](#0-2) 

Since `PbftCommitMessage` and its underlying `PbftSignCapsule` are constructed directly from raw peer-supplied bytes with no independent signature-count enforcement at the message/decoding layer (`PbftCommitMessage(byte[] data)` just wraps the bytes into a `PbftSignCapsule`), an attacker-controlled peer can send a `PBFTCommitResult` with `getSignatureList()` empty. `validPbftSign` then returns `true`, and `processPBFTCommitMessage` proceeds to call `pbftSignDataStore.putBlockSignData(raw.getViewN(), pbftCommitMessage.getPbftSignCapsule())` (or `putSrSignData` for `DataType.SRL`), persisting attacker-forged "PBFT commit" data with zero valid witness signatures, as long as no prior value already exists for that key (`pbftSignDataStore.getBlockSignData(raw.getViewN()) == null`).

I confirmed this matches the existing project's own unit test `PbftDataSyncHandlerTest.testProcessMessage`, which constructs a `PbftSignCapsule` with an empty signature list (`new ArrayList<>()`) and successfully exercises `processMessage`/`processPBFTCommitData` without any signature validation failure, corroborating that the code path accepts empty signature lists. [4](#0-3) 

### Impact Explanation
If exploited, `pbftSignDataStore` (backing `getBlockSignData`/`getSrSignData`, `chainbase/src/main/java/org/tron/core/db/PbftSignDataStore.java`) would contain forged "PBFT-finalized" proof data for a block/epoch that was never actually agreed upon by 2/3+1 super representatives. Any downstream consumer (e.g., other peers/light clients, or external bridge/exchange integrations) that treats presence of PBFT sign data as proof of irreversible finality could be misled into treating an unconfirmed or even non-existent state as finalized, which is the exact scoped impact described (mis-accounting of deposits reliant on PBFT finality proofs). The write only happens when the store slot is currently empty (`getBlockSignData(raw.getViewN()) == null`), so it forges a first, otherwise-missing finality record rather than overwriting existing correct data — but the empty slot is precisely the case where an honest quorum hasn't yet (or won't) commit, so the forged record actively creates false-positive finality.

### Likelihood Explanation
Preconditions are minimal and match unprivileged-peer capability: attacker only needs an active P2P connection with `allowPBFT()` enabled (a protocol-wide flag, not attacker-controlled but a normal live-network condition), and can send an arbitrary `PbftCommitMessage` at any time for a `viewN`/`epoch` value of their choosing that is not already populated in the store. No cryptographic material, private keys, or SR privileges are required to trigger `validPbftSign` returning `true`, making this trivially and repeatably exploitable by any connected peer.

### Recommendation
In `validPbftSign`, treat an empty (or otherwise insufficient) `srSignList` as an immediate validation failure rather than an implicit pass-through. Restructure the function so the size check enforces `srSignSet.size() >= Param.getInstance().getAgreeNodeCount()` unconditionally (including the zero case), returning `false` when the signature list does not meet quorum, instead of only validating inside the `if (srSignList.size() != 0)` branch.

### Proof of Concept
Java unit test (extending the existing `PbftDataSyncHandlerTest` pattern):
1. Build a `Protocol.PBFTMessage.Raw` for `DataType.BLOCK` with a given `viewN`.
2. Build `PbftSignCapsule` with `raw.toByteString()` and an **empty** `List<ByteString>` signature list, wrap into `PbftCommitMessage`.
3. Mock `ChainBaseManager` with `allowPBFT()` returning `true`, `getWitnesses()` returning a non-empty witness list, and a real (or spy) `PbftSignDataStore` (not fully mocked, or verify `putBlockSignData` invocation via Mockito).
4. Call `pbftDataSyncHandler.processMessage(null, pbftCommitMessage)` then directly invoke the private `processPBFTCommitMessage` (via reflection) or drive it through `processPBFTCommitData`.
5. Assert `pbftSignDataStore.getBlockSignData(viewN)` is non-null / `putBlockSignData` was invoked, despite the signature list being empty — demonstrating that zero valid signatures produced a persisted "finalized" record.

  private void processPBFTCommitMessage(PbftCommitMessage pbftCommitMessage) {
    try {
      PbftSignDataStore pbftSignDataStore = chainBaseManager.getPbftSignDataStore();
      Raw raw = Raw.parseFrom(pbftCommitMessage.getPBFTCommitResult().getData());
      if (!validPbftSign(raw, pbftCommitMessage.getPBFTCommitResult().getSignatureList(),
          chainBaseManager.getWitnesses())) {
        return;
      }
      if (raw.getDataType() == DataType.BLOCK
          && pbftSignDataStore.getBlockSignData(raw.getViewN()) == null) {
        pbftSignDataStore.putBlockSignData(raw.getViewN(), pbftCommitMessage.getPbftSignCapsule());
        logger.info("Save the block {} pbft commit data", raw.getViewN());
      } else if (raw.getDataType() == DataType.SRL
          && pbftSignDataStore.getSrSignData(raw.getEpoch()) == null) {
        pbftSignDataStore.putSrSignData(raw.getEpoch(), pbftCommitMessage.getPbftSignCapsule());
        logger.info("Save the srl {} pbft commit data", raw.getEpoch());
      }
    } catch (InvalidProtocolBufferException e) {
      logger.error("", e);
    }
  }

  private boolean validPbftSign(Raw raw, List<ByteString> srSignList,
      List<ByteString> currentSrList) {
    //valid sr list
    if (srSignList.size() != 0) {
      Set<ByteString> srSignSet = new ConcurrentSet();
      srSignSet.addAll(srSignList);
      if (srSignSet.size() < Param.getInstance().getAgreeNodeCount()) {
        logger.error("sr sign count {} < sr count * 2/3 + 1 == {}", srSignSet.size(),
            Param.getInstance().getAgreeNodeCount());
        return false;
      }
      byte[] dataHash = Sha256Hash.hash(true, raw.toByteArray());
      Set<ByteString> srSet = Sets.newHashSet(currentSrList);
      List<Future<Boolean>> futureList = new ArrayList<>();
      for (ByteString sign : srSignList) {
        futureList.add(executorService.submit(
            new ValidPbftSignTask(raw.getViewN(), srSignSet, dataHash, srSet, sign)));
      }
      for (Future<Boolean> future : futureList) {
        try {
          if (!future.get()) {
            return false;
          }
        } catch (Exception e) {
          logger.error("", e);
        }
      }
      if (srSignSet.size() != 0) {
        return false;
      }
    }
    return true;
  }
