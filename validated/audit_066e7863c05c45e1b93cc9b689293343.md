## Finding

### Title
Unbounded `PendingInbounds.Walk` scan on every ballot termination causes O(n·m) consensus-critical work, DoS analog to the Expo.sol expired-lock iteration bug - (File: `x/uexecutor/keeper/ballot_hooks.go`)

### Summary
The external report describes a bug where `Expo.sol`'s `transfer()`/`send()`/`burn()`/`transferWithLock()` iterate over **all** of a user's locks — including already-expired ones — on every call, wasting gas and, in the worst case, exceeding the per-transaction gas limit and freezing the user's own transfers. The direct analog in Push Chain is `afterInboundBallotTerminal` in `x/uexecutor/keeper/ballot_hooks.go`, which performs a full unindexed `Walk` over the entire `PendingInbounds` collection (and every variant inside each entry) every single time *any* inbound ballot reaches a terminal state — instead of doing an O(1) lookup keyed by the ballot ID it already knows.

### Finding Description
`RecordInboundVote` (`x/uexecutor/keeper/inbound.go:27-88`) creates one `PendingInboundEntry` per unique `utx_key = sha256(source_chain:tx_hash:log_index)`, and each entry can accumulate multiple `InboundVariant`s (one per distinct ballot ID observed by validators). Nothing bounds how many `PendingInboundEntry` records or variants can exist concurrently — an unprivileged actor only needs to produce many distinct source-chain transactions (deposits/inbound events across chains or even the same cheap L2/testnet chain) to grow this set arbitrarily.

`x/uvalidator/keeper/ballot.go` runs `ExpireBallotsBeforeHeight` (called on every block from the module's `EndBlock`, per `x/uvalidator/keeper/ballot.go:320-364`), which iterates all `ActiveBallotIDs` whose expiry height has passed and calls `MarkBallotExpired` for each one. `MarkBallotExpired` (`x/uvalidator/keeper/ballot.go:126-151`) fires `fireBallotTerminalHook`, which invokes `BallotHooks.AfterBallotTerminal` → `afterInboundBallotTerminal` (`x/uexecutor/keeper/ballot_hooks.go:72-143`).

That handler explicitly documents the anti-pattern: [1](#0-0) 
It walks the *entire* `PendingInbounds` map — including entries totally unrelated to the terminating ballot — scanning every variant of every entry, purely to reverse-map a non-reversible ballot ID back to its owning `utx_key`. This mirrors Expo.sol's mistake of scanning every lock (including irrelevant/expired ones) instead of maintaining a direct index.

Because ballot expiry is driven consensus-wide in `EndBlock` (not a user-paid, gas-metered transaction), the cost is worse than the original Expo.sol bug: if `M` ballots expire in the same block (attacker times many cheap cross-chain inbound submissions to expire together) and `N` entries are concurrently pending, the node does O(M·N) work inside `EndBlock` for every validating node in the network, with no gas ceiling to bound it. [2](#0-1) [3](#0-2) 

### Impact Explanation
This is a denial-of-service surface reachable by an ordinary, unprivileged external actor: submit large numbers of distinct low-value cross-chain deposit/inbound events (cheap especially on low-fee source chains) that validators observe but that don't reach quorum before expiry, so many `PendingInboundEntry` records accumulate and expire in overlapping blocks. Each expiry then triggers a full linear scan of the (now large) `PendingInbounds` collection inside the block-processing hot path shared by all validating nodes, degrading block production or, at extreme entry counts, materially slowing/stalling `EndBlock` execution across the network. This is not a network-level DoS (e.g., packet flooding) — it is caused entirely by ordinary transaction submission via the documented user-reachable inbound-voting flow, which is in-scope per the allowed-impact gate ("denial of service only when it is not network-level and is reachable without privileged control").

### Likelihood Explanation
Medium. The code comment itself ("the pending set is small and transient") shows the design assumption that this scan is cheap, but nothing in the code actually enforces a cap on the number of concurrent `PendingInboundEntry` records or on how many ballots may expire in the same block. An attacker only needs to fund enough cheap source-chain transactions (or reuse a low-fee chain) to grow the pending set faster than validators can finalize/expire entries, then let a batch expire together.

### Recommendation
Replace the reverse `PendingInbounds.Walk` scan with a direct index: maintain a secondary map from `ballot_id -> utx_key` (populated in `RecordInboundVote` alongside the variant append, and removed when the entry is deleted) so `afterInboundBallotTerminal` can do an O(1) lookup instead of an O(n) walk. Additionally, consider bounding the number of concurrently pending inbound entries/variants (or batching/rate-limiting `ExpireBallotsBeforeHeight` per block) to prevent the entry set from growing unboundedly under attacker-controlled submission volume.

### Proof of Concept
1. Repeatedly submit distinct cross-chain deposit transactions on a low-fee source chain such that validators begin voting on them via `MsgVoteInbound` but quorum is not reached quickly (e.g., submit faster than validators can finalize, or from many distinct source addresses/log indices to avoid natural dedup).
2. Each distinct `(source_chain, tx_hash, log_index)` produces a new `PendingInboundEntry` via `RecordInboundVote` (`x/uexecutor/keeper/inbound.go:27-88`), growing `PendingInbounds` to N entries.
3. Once the ballots' `BlockHeightExpiry` is reached, `ExpireBallotsBeforeHeight` (`x/uvalidator/keeper/ballot.go:320-364`) expires many ballots in one or nearby blocks; each `MarkBallotExpired` call triggers `afterInboundBallotTerminal`'s full `PendingInbounds.Walk` (`x/uexecutor/keeper/ballot_hooks.go:86-94`), so total `EndBlock` work scales with (expiring ballots) × (pending entries) rather than remaining O(1) per ballot.
4. Measure `EndBlock` latency/CPU growth as N increases to confirm the unbounded scan cost, analogous to the unbounded lock iteration in the referenced Expo.sol report.

Note: I was not able to directly inspect `x/uvalidator/module.go`'s `EndBlock` wiring in this pass to visually confirm `ExpireBallotsBeforeHeight` is invoked there every block (tool budget exhausted), but this is strongly implied by the function's own name/doc comments and the surrounding test suite (`ballot_test.go`, `ballot_voting_test.go`) exercising exactly this expiry path; a Devin session with full repo access should confirm the exact `EndBlock` call site before finalizing severity/remediation.

func (k Keeper) MarkBallotExpired(ctx context.Context, id string) error {
	ballot, err := k.Ballots.Get(ctx, id)
	if err != nil {
		return err
	}

	k.Logger().Debug("marking ballot as expired",
		"ballot_id", id,
		"expiry_height", ballot.BlockHeightExpiry,
	)

	if err := k.ActiveBallotIDs.Remove(ctx, id); err != nil {
		return err
	}
	if err := k.ExpiredBallotIDs.Set(ctx, id); err != nil {
		return err
	}

	ballot.Status = types.BallotStatus_BALLOT_STATUS_EXPIRED
	if err := k.Ballots.Set(ctx, id, ballot); err != nil {
		return err
	}

	k.fireBallotTerminalHook(ctx, ballot.Id, ballot.BallotType, types.BallotStatus_BALLOT_STATUS_EXPIRED)
	return nil
}

// ExpireBallotsBeforeHeight checks active ballots and marks expired ones.
// It uses a two-phase approach: first collect IDs to expire, then mutate,
// to avoid modifying the ActiveBallotIDs collection during iteration.
func (k Keeper) ExpireBallotsBeforeHeight(ctx context.Context, currentHeight int64) error {
	iter, err := k.ActiveBallotIDs.Iterate(ctx, nil)
	if err != nil {
		return err
	}

	// Phase 1: collect IDs to expire
	var toExpire []string
	for ; iter.Valid(); iter.Next() {
		id, err := iter.Key()
		if err != nil {
			iter.Close()
			return err
		}

		ballot, err := k.Ballots.Get(ctx, id)
		if err != nil {
			iter.Close()
			return err
		}

		if ballot.BlockHeightExpiry <= currentHeight {
			toExpire = append(toExpire, id)
		}
	}

	// Close iterator explicitly before mutation phase to release the IAVL snapshot
	iter.Close()

	if len(toExpire) > 0 {
		k.Logger().Debug("expiring stale ballots", "count", len(toExpire), "current_height", currentHeight)
	}

	// Phase 2: expire collected ballots (safe — iterator is closed)
	for _, id := range toExpire {
		if err := k.MarkBallotExpired(ctx, id); err != nil {
			return err
		}
	}

	return nil
}
