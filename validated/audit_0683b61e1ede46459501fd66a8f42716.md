## Finding

### Title
Fixed 5% slippage tolerance on module-driven PRC20→WPC swaps allows sandwich/frontrunning value extraction from users - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
When Push Chain auto-swaps a deposited PRC20 (or excess gas fee) into native PC via the on-chain Uniswap V3 pool, the module fetches a spot quote from `QuoterV2.quoteExactInputSingle` and applies a hardcoded 5% slippage band (`minPCOut = quote * 95 / 100`) before executing the swap. Because the underlying pool is a normal, publicly tradeable Uniswap V3 pool, any unprivileged external user can move the pool's spot price with an ordinary trade immediately before the module's swap is committed (front-running the `MsgVoteInbound`/`MsgVoteOutbound` transaction that triggers it), then reverse the trade afterward (back-run) to extract value. The fixed, non-configurable, non-liquidity-aware 5% tolerance is exactly the class of missing slippage protection described in the referenced report — except here it's a *constant* bound rather than *no* bound, so it caps rather than eliminates the risk, but for a shallow/newly-launched pool 5% of a cross-chain deposit is a large, guaranteed, extractable value for an attacker at the depositing user's expense.

### Finding Description
Three call sites in `x/uexecutor` compute a swap quote and immediately execute a swap using that quote, with no protection against the quote itself being manipulated by a preceding attacker transaction in the same or an adjacent block:

- `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:126-152`) — GAS inbound route: fetches fee tier, calls `GetSwapQuote`, computes `minPCOut = quote*95/100`, and calls `CallPRC20DepositAutoSwap`. [1](#0-0) 

- `gasAndPayloadDepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:348-379`) — GAS_AND_PAYLOAD inbound route: identical pattern. [2](#0-1) 

- `applyGasRefund` (`x/uexecutor/keeper/outbound.go:213-234`) — outbound gas-refund route: same pattern, refunding excess relayer gas fee back to the user via a swap. [3](#0-2) 

The underlying primitives:
- `GetSwapQuote` performs a static call to `QuoterV2.quoteExactInputSingle` against the live pool state at execution time. [4](#0-3) 
- `CallPRC20DepositAutoSwap` and `CallUniversalCoreRefundUnusedGas` pass `minPCOut` straight through to the `UniversalCore` contract's `depositPRC20WithAutoSwap`/`refundUnusedGas`, with `deadline=0` (contract default). [5](#0-4) 

The `UniversalCore` contract is initialized with a real `uniswapV3Factory_`/`uniswapV3SwapRouter_`/`uniswapV3Quoter_`, i.e. the WPC/PRC20 pools are ordinary public Uniswap V3 pools that any Push Chain user can trade against directly via normal `MsgEthereumTx` transactions. [6](#0-5) 

Because the vote transaction that finalizes an inbound/outbound (and thus triggers the swap) is a normal, publicly observable transaction competing for block inclusion like any other, an attacker can:
1. Observe a pending `MsgVoteInbound`/`MsgVoteOutbound` transaction that will reach quorum and trigger an auto-swap.
2. Submit a swap on the same WPC/PRC20 pool ahead of it in the same block (or in an earlier block if using a longer time horizon) to push the pool price so that `quoteExactInputSingle` returns a worse (but still 95%-compliant) rate.
3. Let the module's swap execute at this manipulated rate — it will still pass the `minPCOut` check since the quote itself was computed post-manipulation.
4. Reverse the price move afterward, capturing the difference as arbitrage profit.

The 5% band is a fixed constant independent of the actual pool depth, trade size, or oracle-observed price — it provides no real protection when the pool is thin (which is expected at chain/token launch) or when an attacker is willing to move price up to (and slightly under) 5%.

### Impact Explanation
This directly corrupts native/PRC20 asset accounting: users depositing native gas tokens (e.g., ETH/BNB) that get auto-swapped to PC, and users receiving gas-refund swaps, can systematically receive up to ~5% less PC value than fair market price, with the difference extracted by an unprivileged attacker. This occurs on the default, most common inbound path (`GAS` and `GAS_AND_PAYLOAD`) and on every outbound gas refund — a broad, repeatable drain of user value, matching the "corruption of PRC20 or native asset accounting" and "unauthorized ... refund of user ... funds" impact categories.

### Likelihood Explanation
Likelihood is high in early chain life (thin liquidity pools make 5% price impact cheap to induce) and moderate generally, since the attack requires no privileged role — only capital to move the pool and the ability to observe/front-run public vote transactions, which is a normal MEV-style capability on any chain with a public mempool/block-builder.

### Recommendation
- Do not rely on a flat percentage computed from a spot quote fetched in the same transaction that executes the swap. Instead, base `minPCOut` on a manipulation-resistant reference (e.g., a TWAP from the pool, or an off-chain price oracle already trusted by the protocol for gas pricing), and/or make the tolerance proportional to trade size relative to pool liquidity.
- Consider adding a circuit breaker/cap so that if the computed slippage would exceed some absolute value threshold, the deposit/refund falls back to the no-swap PRC20 delivery path instead of accepting the loss.
- Track and rate-limit realized slippage per block/pool to detect and mitigate systematic sandwich extraction.

### Proof of Concept
1. Attacker monitors the Push Chain mempool/mid-block state for a `MsgVoteInbound` (or `MsgVoteOutbound`) transaction that will reach quorum on validator N-of-M votes for a `GAS`/`GAS_AND_PAYLOAD` inbound (or gas refund) involving PRC20 X → WPC swap.
2. Attacker submits their own swap on the WPC/PRC20-X Uniswap V3 pool (public pool, no permission needed) that shifts the pool price unfavorably for the module's forthcoming swap, ensuring it lands in the same or an earlier block.
3. The finalizing vote executes `gasAndPayloadDepositAutoSwap`/`ExecuteInboundGas`/`applyGasRefund`, calling `GetSwapQuote` against the now-manipulated pool state, computing `minPCOut = quote*95/100`, and executing `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas`, which succeeds because it only needs to satisfy the (already degraded) 95% bound. [7](#0-6) 
4. Attacker reverses their swap, pocketing the price-impact profit; the deposited user's UEA/recipient balance in PC is up to ~5% lower than a fair-price execution would have produced.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
