The SecondSwap bug's root cause is a **fixed decimal-based price floor**: `pricePerUnit` is an integer expressed in the payment token's smallest unit, so a stablecoin with 6 decimals can't represent prices below 0.000001. This mechanism doesn't have a structural analog in java-tron's `MarketSellAssetActuator` / `MarketUtils` order-book design.

Key differences I verified:
- java-tron's TRC10 exchange market represents price as a **ratio of two arbitrary int64 quantities** (`sell_token_quantity` / `buy_token_quantity`), not as a fixed-decimal price against a payment-token unit. [1](#0-0) [2](#0-1) 
- The price key is normalized via GCD reduction of the two int64 quantities, which actually gives finer, non-decimal-bound granularity rather than a fixed floor tied to a payment token's decimals. [3](#0-2) 
- Order matching uses `multiplyAndDivide` (floor division) to compute fill quantities; when a match would round down to zero, the code gracefully returns the remaining sell tokens to the user rather than reverting or misaccounting funds. [4](#0-3) [5](#0-4) 

This truncation-to-zero handling is an intentional, benign edge case (not a mispriced/underpriced-work, accounting, or settlement bug) — it simply prevents a fill and refunds the taker, which does not map to any of the required impact categories (auth, accounting, replay, settlement, invalid-state/divergence/halt, or underpriced-public-work). The `ExchangeCapsule`/`ExchangeProcessor` bonding-curve pools (`ExchangeInjectActuator`, `ExchangeWithdrawActuator`) are also ratio-based rather than fixed-decimal-price-based, so they don't reproduce the SecondSwap root cause either. [6](#0-5) 

No qualifying, unprivileged-user-reachable analog with the required concrete impact exists in this codebase for the reported bug class.

   * In order to avoid the difference between the data of same key stored and fetched by hashMap and

   * sellTokenQuantity and buyTokenQuantity.

  public static byte[] createPairPriceKey(byte[] sellTokenId, byte[] buyTokenId,
      long sellTokenQuantity, long buyTokenQuantity) {

    byte[] sellTokenQuantityBytes;
    byte[] buyTokenQuantityBytes;

    // cal the GCD
    long gcd = findGCD(sellTokenQuantity, buyTokenQuantity);
    if (gcd == 0) {
      sellTokenQuantityBytes = ByteArray.fromLong(sellTokenQuantity);
      buyTokenQuantityBytes = ByteArray.fromLong(buyTokenQuantity);
    } else {
      sellTokenQuantityBytes = ByteArray.fromLong(sellTokenQuantity / gcd);
      buyTokenQuantityBytes = ByteArray.fromLong(buyTokenQuantity / gcd);
    }

    return doCreatePairPriceKey(sellTokenId, buyTokenId,
        sellTokenQuantityBytes, buyTokenQuantityBytes);
  }

  public static long multiplyAndDivide(long a, long b, long c, boolean disableMath) {
    try {
      long tmp = multiplyExact(a, b, disableMath);
      return floorDiv(tmp, c, disableMath);
    } catch (ArithmeticException ex) {
      // do nothing here, because we will use BigInteger to compute again
    }

    BigInteger aBig = BigInteger.valueOf(a);
    BigInteger bBig = BigInteger.valueOf(b);
    BigInteger cBig = BigInteger.valueOf(c);

    return aBig.multiply(bBig).divide(cBig).longValue();
  }
