## Finding: Uncontrolled recursion depth in compiled-class-hash computation over attacker-supplied bytecode segment structure

### Title
Unbounded recursion in `bytecode_hash_node` when hashing a declared class's CASM bytecode segments can crash the sequencer (stack overflow) - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
CVE-2024-45778 describes grub2 crashing from a stack overflow caused by an uncontrolled loop while parsing an attacker-crafted BFS filesystem tree. The sequencer has an analogous unbounded-recursion pattern: computing a compiled class's hash recursively walks a `NestedIntList` bytecode-segment tree (`bytecode_hash_node`) whose nesting depth is derived from the Sierra→CASM compilation of an attacker-submitted contract, with no depth limit enforced before/while hashing.

### Finding Description
`SierraCompiler::compile` in [1](#0-0)  compiles a submitted Sierra class into CASM inside a resource-limited subprocess (`self.compiler.compile(class)?`, bounded by `max_cpu_time`/`max_memory_usage`/`max_bytecode_size`, see [2](#0-1) ), but immediately afterwards computes `executable_class.hash(&HashVersion::V2)` **in the class manager's own process, outside the sandbox**.

`hash()` calls `hash_inner`, which calls `bytecode_hash`, which recursively descends the `HashableNestedIntList` (`NestedIntList`) bytecode-segment structure via `bytecode_hash_node`: [3](#0-2) 

Each internal node causes a recursive call for each child (`node.iter_children().map(|child| bytecode_hash_node(...))`), with no explicit bound on tree depth — only the overall `max_bytecode_size` (80 KiB felts by default, see [4](#0-3) ) constrains the *total* bytecode, not the recursion depth. A contract whose Sierra program is structured (via many nested function/branch boundaries) to produce a maximally-unbalanced, deeply-nested segment tree (e.g., a long chain of singleton inner nodes) can make the recursion depth approach the bytecode size limit — tens of thousands of stack frames — which is more than sufficient to overflow the thread stack and crash the process performing the hash.

The identical unbounded-recursion pattern also exists in the Starknet OS hint implementation used to build OS inputs, `BytecodeSegmentNode::hash` [5](#0-4) , and is mirrored in the in-VM Cairo hash implementations (`bytecode_hash_node`/`bytecode_hash_internal_node`) which recurse per segment: [6](#0-5) .

This computation is reached directly from an unprivileged, single submitted declare transaction: `TransactionConverter::convert_rpc_tx_to_internal` calls `class_manager_client.add_class(...)`, which invokes `SierraCompiler::compile` including the vulnerable hash step [7](#0-6) , and it is also invoked whenever a declare transaction is validated/executed (`check_compile_class_hash_v2_declaration` in [8](#0-7) ) and again during Starknet OS re-execution.

### Impact Explanation
A crafted Sierra class submitted as a `Declare` transaction can crash the process performing the compiled-class-hash computation (the class manager/gateway component, and later the block-building/OS re-execution component, since the hash is recomputed at multiple points: gateway ingestion, mempool/blockifier declare execution, and OS proving). Because this hashing runs outside the compilation subprocess sandbox that bounds CPU/memory, there is no existing mitigation against a stack-overflow crash. Repeated submission of such a declare transaction is a denial-of-service vector against sequencer components (a network unable to confirm new transactions if the crash affects transaction-processing components broadly), matching the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Likelihood is limited by whether the cairo_lang Sierra-to-CASM compiler's bytecode-segmentation algorithm (an external dependency, `cairo_lang_starknet_classes`, not visible in this repo) can actually be steered by program structure into a maximally-unbalanced/deep segment tree within the 80 KiB bytecode-size bound. Given segmentation follows function/branch boundaries and Cairo/Sierra programs support deep nested control flow and function-call chains, constructing a program that yields a long, thin chain of nested segments (rather than a balanced tree) appears plausible, though this would need to be validated empirically against the actual compiler's segmentation heuristic.

### Recommendation
- Add an explicit, enforced maximum recursion/nesting depth check on the `NestedIntList` structure before or during `bytecode_hash_node`/`bytecode_hash` traversal in `crates/starknet_api/src/contract_class/compiled_class_hash.rs`, rejecting classes whose segment tree exceeds a safe depth.
- Convert the recursive traversal to an explicit iterative (heap-allocated stack) algorithm to remove the native call-stack dependency entirely, as is already done for the analogous iterative Patricia-trie traversal in `crates/starknet_committer/src/db/trie_traversal.rs`.
- Apply the same bound/iterative approach to `BytecodeSegmentNode::hash` in `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`.
- Consider performing the hash computation for untrusted, newly-declared classes inside the same resource-limited subprocess/sandbox used for compilation, rather than in the class manager's main process.

### Proof of Concept
Conceptual PoC (requires access to the `cairo_lang_starknet_classes` compiler internals to confirm segment-tree shaping, not verifiable purely from this repo):
1. Author a Sierra/Cairo1 contract whose control-flow graph is engineered to force the CASM bytecode-segmentation algorithm into producing a long chain of singleton nested segments (e.g., many sequential small functions/branches each becoming its own nested segment) up to the `max_bytecode_size` (80 * 1024 felts) limit.
2. Submit it as a `Declare` V3 transaction via `POST /add_transaction`.
3. `TransactionConverter::convert_rpc_tx_to_internal` → `ClassManager::add_class` → `SierraCompiler::compile` compiles it inside the sandboxed subprocess (succeeds, within CPU/memory/size limits), then calls `executable_class.hash(&HashVersion::V2)` in-process, recursing into `bytecode_hash_node` for each nested segment, exhausting the stack and crashing the class-manager process.

```rust
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}
```

```rust
impl BytecodeSegmentNode {
    pub(crate) fn hash<H: HashFunction>(&self) -> StarkHash {
        match self {
            BytecodeSegmentNode::Leaf(leaf) => H::hash_array(&leaf.data),
            BytecodeSegmentNode::InnerNode(inner_node) => {
                let flatten_input: Vec<_> = inner_node
                    .segments
                    .iter()
                    .flat_map(|segment| [Felt::from(segment.length), segment.node.hash::<H>()])
                    .collect();
                H::hash_array(&flatten_input) + Felt::ONE
            }
        }
    }
```

```text
func bytecode_hash_node{range_check_ptr}(
    data_ptr: felt*, data_length: felt, full_contract: felt
) -> felt {
    alloc_locals;

    local is_leaf;

    %{ IsLeaf %}

    // Guess if the bytecode is a leaf or an internal node in the tree.
    if (is_leaf != FALSE) {
        // If the bytecode is a leaf, it must be loaded into memory. Compute its hash.
        let (hash) = encode_felt252_data_and_calc_blake_hash(data_len=data_length, data=data_ptr);
        return hash;
    }

    %{ AssignBytecodeSegments %}

    // Initialize Blake2s hash state for internal node.
    let hash_state: HashState = hash_init();
    with hash_state {
        bytecode_hash_internal_node(
            data_ptr=data_ptr, data_length=data_length, full_contract=full_contract
        );
    }

    let segmented_hash = hash_finalize(hash_state=hash_state);

    // Add 1 to segmented_hash to avoid collisions with the hash of a leaf (domain separation).
    return segmented_hash + 1;
}
```

```rust
    /// Verifies that the compiled class hash field in the declare tx,
    /// is compiled_class_hash_v2 of the compiled contract.
    pub fn check_compile_class_hash_v2_declaration(&self) -> Result<(), StarknetApiError> {
        let compiled_class = &self.class_info.contract_class;
        let compiled_class_hash_v2 = match &compiled_class {
            ContractClass::V0(_) => return Ok(()),
            ContractClass::V1((casm, _)) => casm.hash(&HashVersion::V2),
        };
        let compiled_class_hash = self.compiled_class_hash();
        if compiled_class_hash_v2 != compiled_class_hash {

                hash: self.class_hash(),
                actual: compiled_class_hash,
                expected: compiled_class_hash_v2,
            };
            return Err(StarknetApiError::DeclareTransactionCasmHashMissMatch(Box::new(err_var)));
        }
        Ok(())
    }
```
