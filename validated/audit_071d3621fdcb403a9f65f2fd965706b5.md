### Title
Unrestricted `BOOTSTRAP`-Sender Declare Bypass Allows Free, Unvalidated Class Declaration by Any Transaction Sender - (File: `crates/starknet_api/src/executable_transaction.rs`, `crates/blockifier/src/transaction/account_transaction.rs`)

### Summary
`DeclareTransaction::is_bootstrap_declare` grants a special "no validate / no fee / no account required" execution path whenever `sender_address == bootstrap_address()` (`0x424f4f545354524150`, i.e. the literal string `'BOOTSTRAP'`), `nonce == 0`, and `charge_fee` is false. Whether `charge_fee` is false is determined purely from the transaction's own resource bounds via `enforce_fee(&tx, false)` when the sequencer converts an incoming `Declare` into an `AccountTransaction` for sequencing — this is exactly the same conversion path (`AccountTransaction::new_for_sequencing`) used for ordinary, externally submitted transactions. There is no additional gating (e.g., "genesis block only", "operator-only", "block number == 0") tying this bypass to a privileged bootstrap phase.

### Finding Description
The bootstrap-declare mechanism is intended to let the sequencer bootstrap a brand-new chain by declaring the initial account/ERC20 classes without needing a funded account or a `__validate_declare__` call: [2](#0-1)  The condition is `sender_address == bootstrap_address() && nonce == 0 && !charge_fee`.

`charge_fee` is not an operator-only/privileged flag reserved for genesis processing — it is computed generically for *every* transaction that goes through the normal sequencing path via `AccountTransaction::new_for_sequencing`: [4](#0-3)  `charge_fee: enforce_fee(&tx, false)`, i.e. it is derived from the transaction's resource-bounds fields, which are fully attacker-controlled at submission time (this is confirmed by the test `test_fee_enforcement`, which shows that setting all resource bounds to zero makes `enforce_fee` return `false`: [5](#0-4) ).

Consequently, in `execute_raw`, any submitted `Declare` transaction with `sender_address` set to the fixed constant `bootstrap_address()`, `nonce == 0`, and zero resource bounds enters the bootstrap branch, which skips `perform_pre_validation_stage` (nonce/fee checks), skips `__validate_declare__` execution, and skips fee transfer entirely, directly writing the class hash into state: [6](#0-5) 

This mirrors the reported bug class exactly: a privileged/special action (`mintNFT` was meant to be owner-only; here, "declare without fee/validation" is meant to be bootstrap-phase-only) is reachable by any unprivileged caller because the guarding condition (`onlyOwner` vs. "genesis-only") is based on data the caller fully controls (the `sender_address` field and resource bounds of a self-authored transaction) rather than a real identity/phase check.

The Starknet OS re-execution path (`execute_declare_transaction` in `transaction_impls.cairo`) implements the analogous check independently and is even looser — it only requires `sender_address == 'BOOTSTRAP' && nonce == 0 && version == 3 && max_possible_fee == 0`, again all attacker-suppliable fields: [7](#0-6) 

### Impact Explanation
If nothing else in the gateway/mempool stack independently rejects a `nonce == 0`, zero-resource-bound Declare transaction from an arbitrary sender that happens to collide with the reserved `bootstrap_address()`, an attacker can:
- Declare arbitrary classes for free, with no `__validate_declare__` check and no fee payment, bypassing the fee market entirely (mempool/DoS abuse — free resource consumption).
- More critically, `dict_update{...}(key=[class_hash_ptr], prev_value=0, new_value=compiled_class_hash)` in the OS asserts `prev_value=0`, meaning it silently no-ops/fails only if the class was already declared; for undeclared classes, this succeeds unconditionally, allowing state mutation (class declaration) without going through the normal fee/validate contract that the STARK proof and block hash are supposed to attest to. If the OS's independent bootstrap condition (based on `max_possible_fee == 0`, not `charge_fee`) diverges from the sequencer's/blockifier's condition in any edge case (e.g., a transaction where resource bounds compute to zero possible fee under one Fee model but `enforce_fee` uses a different rounding/threshold), this is a source of **honest-node divergence** between block execution and OS re-execution — one of the explicitly in-scope impacts.
- At minimum this is unauthorized declare/class-registration action performed by an unprivileged sender that was intended to be restricted to a one-time genesis bootstrap event, analogous to unrestricted minting.

### Likelihood Explanation
Reaching `bootstrap_address()` requires knowing/using the exact constant address (public in source code) as `sender_address`, and submitting nonce `0` with zero resource bounds — all of which are values any transaction sender can set without needing a private key for that specific account, since `is_bootstrap_declare` skips `__validate_declare__` entirely (no signature over that account is required). The primary open question (which limits certainty of full exploitability) is whether the gateway's `stateless_tx_validator` or `stateful_tx_validator_config` (e.g. `min_gas_price`, minimum resource bounds enforcement) independently rejects zero-resource-bound declare transactions before they reach `AccountTransaction::new_for_sequencing`/`execute_raw`. This gating logic was not fully inspected within the available context, so likelihood should be treated as **Medium** pending confirmation of whether stateless/stateful validation in the gateway blocks zero-fee declares from non-genesis blocks (e.g., via block-number/one-time-use tracking). If no such additional check exists, likelihood is High.

### Recommendation
- Gate `is_bootstrap_declare` (and its OS counterpart) on an explicit, non-attacker-controlled condition, e.g., only allow it when the current block number is the genesis block (`block_number == 0`), rather than solely on transaction-supplied fields (`sender_address`, `nonce`, and a fee-derived boolean).
- Ensure the sequencer/blockifier and Starknet OS use the exact same bootstrap-eligibility condition (currently `charge_fee` vs. `max_possible_fee == 0`) to eliminate divergence risk.
- Add an explicit stateless/stateful gateway check that rejects any `Declare` transaction whose `sender_address == bootstrap_address()` unless the node is actively in genesis-bootstrapping mode.

### Proof of Concept
1. Craft an `RpcTransaction::Declare` (V3) with:
   - `sender_address = ContractAddress::from(0x424f4f545354524150)` (the `bootstrap_address()` constant),
   - `nonce = 0`,
   - `resource_bounds` set so all `max_amount`/`max_price_per_unit` are zero (as in `generate_bootstrap_declare()` used in tests: [8](#0-7) ),
   - a valid, previously-undeclared `class_hash`/`compiled_class_hash` pair.
2. Submit through the gateway's `add_tx` path (unless independently blocked by stateless/stateful validators, which would need to be confirmed).
3. Once sequenced, `AccountTransaction::new_for_sequencing` computes `charge_fee = enforce_fee(&tx, false) = false` due to zero resource bounds.
4. `execute_raw` hits `is_bootstrap_declare` → `true`, skips `perform_pre_validation_stage`, `__validate_declare__`, and fee transfer, and directly declares the class — as demonstrated by the existing test `test_bootstrap_declare` in `account_transactions_test.rs` ( [9](#0-8) ), which confirms the exact state diff produced (`compiled_class_hashes`/`declared_contracts` updated, no fee, no nonce bump) for a `sender_address = bootstrap_address()` transaction with no special privilege proof beyond knowing the public constant.

**Uncertainty note:** I could not conclusively verify from the indexed context whether the gateway's stateless/stateful transaction validators independently reject zero-resource-bound declare transactions or reserved sender addresses before reaching this code path, which would fully block real-world exploitability. This would need to be confirmed by examining `StatelessTransactionValidatorConfig`/`StatefulTransactionValidatorConfig` validation logic in `apollo_gateway` in more depth than the available index allowed.

        // This flow is used for the sequencer to bootstrap a new system.

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }

fn test_bootstrap_declare(
    block_context: BlockContext,
    #[case] declare_tx: DeclareTransaction,
    #[case] hash_version: HashVersion,
) {
    let class_info = calculate_class_info_for_testing(
        FeatureContract::Empty(CairoVersion::Cairo1(RunnableCairo1::Casm)).get_class(),
    );
    let contract_class = class_info.contract_class();
    let mut executable_declare = ApiExecutableDeclareTransaction {
        tx: declare_tx.clone(),
        tx_hash: TransactionHash::default(),
        class_info,
    };

    // Update compiled_class_hash in V3 declare txs to match the contract class with the given hash
    // version.
    if let DeclareTransaction::V3(tx) = &mut executable_declare.tx {
        if let ContractClass::V1((casm, _)) = &contract_class {
            tx.compiled_class_hash = casm.hash(&hash_version);
        }
    }
    let compiled_class_hash = executable_declare.tx.compiled_class_hash();
    let declare_account_tx = AccountTransaction::new_for_sequencing(
        ApiExecutableTransaction::Declare(executable_declare),
    );

    let mut state = CachedState::from(DictStateReader::default());
    let res = declare_account_tx.execute(&mut state, &block_context).unwrap();

    // Check declaration.
    assert_eq!(
        state.get_compiled_class_hash(declare_tx.class_hash()).unwrap(),
        compiled_class_hash
    );

    // Ensure the only change is the class declaration: no fees, nonce bump, etc.
    assert_eq!(res, TransactionExecutionInfo::default());
    assert_eq!(
        state.to_state_diff().unwrap().state_maps,
        StateMaps {
            compiled_class_hashes: HashMap::from([(declare_tx.class_hash(), compiled_class_hash)]),
            declared_contracts: HashMap::from([(declare_tx.class_hash(), true)]),
            ..Default::default()
        }
    );
}
