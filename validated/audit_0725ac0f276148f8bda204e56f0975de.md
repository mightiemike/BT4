Confirmed: `validateHmacFromRequestFactory` in `packages/apps/shopify-api/lib/utils/hmac-validator.ts` computes the HMAC exclusively over `rawBody`, and never incorporates `X-Shopify-Shop-Domain`, `X-Shopify-Topic`, or any other header into the signed data. [1](#0-0) 

### Title
Webhook shop-domain header is unauthenticated and trusted for cross-tenant session/token access - (File: packages/apps/shopify-app-remix/src/server/authenticate/webhooks/authenticate.ts)

### Summary
`validateHmacFromRequestFactory` computes and verifies the webhook HMAC over `rawBody` only, never binding the `X-Shopify-Shop-Domain` (or topic) header to the signature. `authenticateWebhookFactory` then takes `check.domain` — the raw, unauthenticated header value — as the shop identity, using it to load/create an offline session and mint an admin client via `ensureValidOfflineSession`/`createOrLoadOfflineSession`. Any actor holding one valid `(rawBody, HMAC)` pair (e.g. from a webhook legitimately delivered to their own installed shop) can replay it to the app's shared webhook endpoint with the domain header swapped to a different, victim shop, and the request will pass HMAC validation while being processed as if it came from the victim shop.

### Finding Description
In `authenticate.ts`, `authenticateWebhookFactory` calls `api.webhooks.validate({rawBody, rawRequest: request})`, which internally runs `validateHmacFromRequestFactory` — this only checks `safeCompare(hmac, localHmac)` where `localHmac = HMAC-SHA256(apiSecretKey, rawBody)`. [2](#0-1)  After HMAC succeeds, `checkWebhooksHeaders` simply reads `domain`/`topic` straight from request headers with no cryptographic tie to the HMAC. [3](#0-2) 

Back in `authenticateWebhookFactory`, `check.domain` (attacker-controlled header) is passed directly into `ensureValidOfflineSession(params, check.domain)`, and also placed into the returned `shop` field of the webhook context. [4](#0-3)  `ensureValidOfflineSession` calls `createOrLoadOfflineSession(params, shop)`, which loads the offline session for that shop from `config.sessionStorage` (or returns a static custom-app token). [5](#0-4)  If a session exists for the spoofed shop, `authenticateWebhookFactory` attaches a live `admin` client built from that victim shop's real access token. [6](#0-5) 

Because the app's `apiSecretKey` is shared across all shop installs, any single unprivileged merchant who installs the app on their own store can capture a genuine webhook (valid `rawBody` + HMAC) delivered by Shopify to their own endpoint, then replay that exact body/HMAC to the app's public webhook URL while overwriting only the `X-Shopify-Shop-Domain` header to point at a different, victim shop domain. HMAC validation still succeeds (it never inspected the domain header), and the library treats the forged domain as authoritative shop identity — driving both the webhook business logic (`shop`/`topic` given to the app's handler) and the `admin` API client toward the victim tenant.

### Impact Explanation
This breaks the invariant that shop identity must be bound to the verified signature, enabling a cross-tenant webhook action: the attacking merchant can trigger the app's webhook-handling logic (and, where a session exists, the returned `admin` GraphQL/REST client) as if the event originated from a targeted victim shop, without ever needing the victim's credentials or the app's secret. Depending on what the host app's webhook handler does with `shop`/`admin`, this can result in unauthorized data access/mutation against the victim's store, corrupting per-shop counters, incorrectly enqueuing/de-provisioning resources, or performing state changes on a shop the attacker does not own.

### Likelihood Explanation
Feasible for a single unprivileged merchant: install the app on a shop they control, trigger any subscribed webhook (e.g. `app/uninstalled`, `orders/create`), capture the resulting `(rawBody, HMAC)` from their own endpoint logs, then POST it to the shared webhook route with the domain header replaced with a target shop's `myshopify.com` domain that has also installed the app. No secret, MITM, or elevated role is required, and the replay is fully repeatable for any topic/body the attacker can legitimately obtain for their own shop.

### Recommendation
Do not treat the `X-Shopify-Shop-Domain`/topic headers as authenticated shop identity based on body-only HMAC. Cross-check the header-derived shop against a value embedded in and covered by the signed payload where available (e.g., the shop domain inside the webhook JSON payload), or additionally verify that the resolved offline session's `shop` matches an expected value tied to the webhook subscription/registration rather than blindly trusting the header for both routing and session lookup. At minimum, document this as an inherent limitation of Shopify's webhook signing model and require host apps to independently validate `shop` against business records before performing sensitive mutations.

// packages/apps/shopify-app-remix/src/server/authenticate/webhooks/__tests__/authenticate.spoof.test.ts
import {MemorySessionStorage} from '@shopify/shopify-app-session-storage-memory';
import {shopifyApp} from '../../..';
import {APP_URL, TEST_SHOP, getHmac, testConfig} from '../../../__test-helpers';

const VICTIM_SHOP = 'victim-shop.myshopify.com';

it('accepts a webhook whose shop-domain header does not match the HMAC-signed body origin', async () => {
  const sessionStorage = new MemorySessionStorage();
  // seed an offline session for the victim shop, simulating a real merchant install
  await sessionStorage.storeSession({
    id: `offline_${VICTIM_SHOP}`,
    shop: VICTIM_SHOP,
    state: 'state',
    isOnline: false,
    accessToken: 'victim-real-token',
  } as any);

  const shopify = shopifyApp(testConfig({sessionStorage}));
  const body = JSON.stringify({some: 'data'});
  const hmac = getHmac(body); // HMAC only ever covers rawBody

  const result = await shopify.authenticate.webhook(
    new Request(`${APP_URL}/webhooks`, {
      method: 'POST',
      body,
      headers: {
        'X-Shopify-Shop-Domain': VICTIM_SHOP, // attacker-controlled, unsigned
        'X-Shopify-Topic': 'APP_UNINSTALLED',
        'X-Shopify-API-Version': '2023-01',
        'X-Shopify-Webhook-Id': '1234567890',
        'X-Shopify-Hmac-Sha256': hmac, // still valid because HMAC ignores headers
      },
    }),
  );

  // Library trusts the spoofed header as shop identity and hands back
  // a live admin client bound to the victim's real access token.
  expect(result.shop).toBe(VICTIM_SHOP);
  expect(result.session?.accessToken).toBe('victim-real-token');
  expect(result.admin).toBeDefined();
});

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };

import {AppDistribution, BasicParams} from '../types';

export async function createOrLoadOfflineSession(
  {api, config, logger}: BasicParams,
  shop: string,
) {
  if (config.distribution === AppDistribution.ShopifyAdmin) {
    logger.debug('Creating custom app session from configured access token', {
      shop,
    });
    return api.session.customAppSession(shop);
  } else {
    logger.debug('Loading offline session from session storage', {shop});
    const offlineSessionId = api.session.getOfflineId(shop);
    const session = await config.sessionStorage!.loadSession(offlineSessionId);

    return session;
  }
