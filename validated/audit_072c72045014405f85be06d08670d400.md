## Analysis

I investigated the "missing input validation before consuming an entity as if type-compatible" bug class (the Spartan `Synth.realise(pool)` issue: an unvalidated parameter is used to mutate protocol state without checking it belongs to an expected, restricted set). The closest reachable analog in this Starknet sequencer repo is the `replace_class` syscall implementation inside the **Starknet OS (SNOS)** Cairo re-execution code, where the class-hash-declared check that the real execution engine (`blockifier`) enforces is missing.

### Title
Starknet OS `execute_replace_class` accepts undeclared class hashes, diverging from blockifier's validated `replace_class` semantics - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Rust execution engine (`blockifier`) validates, on every `replace_class` syscall, that the target `class_hash` is actually declared (and is a Cairo1 class) before mutating a contract's class-hash mapping. The Starknet OS's Cairo implementation of the same syscall — used for re-executing/proving blocks — performs no such check at all, updating the contract's class hash unconditionally.

### Finding Description
In `blockifier`, `SyscallHandlerBase::replace_class` explicitly reads the compiled class to ensure it is declared and rejects Cairo0 classes: [1](#0-0) 

The equivalent deprecated syscall handler in `blockifier` performs the same declaration check via `get_compiled_class`: [2](#0-1) 

However, the Starknet OS's own Cairo implementation of `replace_class` (used during OS re-execution to independently recompute/verify state transitions for the STARK proof) has no such validation. The "new syscalls" implementation contains an explicit TODO acknowledging the missing check: [3](#0-2) 

The deprecated-syscalls OS path (`execute_replace_class` in `deprecated_execute_syscalls.cairo`) is even more permissive — it updates the class-hash state entry with zero validation whatsoever: [4](#0-3) 

Tests in the Rust blockifier confirm that an undeclared class hash is expected to be rejected at execution time (`"is not declared"`, `"Cannot replace V1 class hash with V0 class hash"`): [5](#0-4) 

This is the same bug class as the reported `Synth.realise(pool)` issue: an entity (`pool` there / `class_hash` here) is consumed to mutate protected state (LP burn / contract class binding) without validating it satisfies the required precondition (matching token / being a declared, correctly-versioned class). The OS is meant to independently re-derive and enforce all the same state-transition rules blockifier enforces as part of proof soundness; here it silently drops one of those rules.

### Impact Explanation
Because the OS accepts an undeclared (or otherwise invalid) class hash for `replace_class` while blockifier does not, a produced STARK proof could attest to a state transition — a contract's class hash being replaced by an arbitrary/never-declared class hash — that the canonical execution semantics (enforced by every honest full node running `blockifier`) would never allow. This creates:
- Honest-node divergence: full nodes executing the same block via `blockifier` would reject/revert the transaction, while a block whose proof was generated by exploiting this OS gap could commit a different resulting state root.
- Wrong committed root / potential permanent state corruption: a contract's class hash binding (used for every subsequent call into that contract) could be set to an unvalidated value, undermining account logic and contract identity guarantees enforced elsewhere in the stack.

### Likelihood Explanation
Exploiting this requires control over the values fed into the OS's execution trace for the `replace_class` syscall (i.e., a block/proof producer providing a `class_hash` that was never declared), since the OS's Cairo circuit is the one deciding provability, not `blockifier`'s Rust checks. The OS is explicitly in-scope as a reachable component ("Starknet OS re-execution"), and the check is missing in *both* the current and deprecated syscall implementations (marked as a known-missing TODO in the code itself), indicating this is a real, currently-unaddressed gap rather than a hypothetical one.

### Recommendation
Add the same declared-class (and version) validation performed by `blockifier`'s `replace_class`/`SyscallHandlerBase::replace_class` to the OS's Cairo `execute_replace_class` implementations in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, i.e., look up the class hash in the declared-classes state (via the appropriate dict/tree read) and assert its presence (and version compatibility) before updating `contract_state_changes`.

### Proof of Concept
1. Compare `blockifier`'s guarded implementation (`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`) against the OS's unguarded implementation (`crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo:881-920`, explicitly annotated `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`).
2. The deprecated OS syscall path (`crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/deprecated_execute_syscalls.cairo:307-329`) similarly writes the new `class_hash` into `contract_state_changes` with no lookup/assertion of declaration at all.
3. A block/proof-generation flow that feeds `execute_replace_class` an undeclared `class_hash` will pass OS re-execution and commit, whereas the same call in `blockifier`'s real transaction execution would fail with `"is not declared"` (as asserted in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`), demonstrating the semantic divergence between the two "sources of truth."

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
