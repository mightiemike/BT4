This confirms `MsgExecutePayload` and `MsgMigrateUEA` are the gasless message types reachable by *any* unprivileged account (unlike the vote messages, which require bonded UV status), and `AccountInitDecorator` unconditionally creates a permanent `BaseAccount` (`NewAccountWithAddress` + `SetAccount`) for any never-before-seen signer address on such a tx, before the message itself is even executed.

### Title
Zero-Cost Unbounded On-Chain Account Creation via Gasless-Whitelist Bypass in `AccountInitDecorator` — ([File: app/ante/account_init_decorator.go])

### Summary
`app/ante/account_init_decorator.go`'s `AccountInitDecorator.AnteHandle` permanently creates a new `BaseAccount` in state for any signer address that submits a gasless-whitelisted message (`MsgExecutePayload`, `MsgMigrateUEA` are reachable by *any* unprivileged account per `app/txpolicy/gasless.go` and `x/uexecutor/README.md`), regardless of whether the underlying message subsequently succeeds. Because gasless transactions skip both the minimum-gas-price check (`MinGasPriceDecorator`) and fee deduction (`DeductFeeDecorator`), an unprivileged attacker can generate an unlimited number of fresh keypairs, sign a trivial (even guaranteed-to-fail) `MsgExecutePayload` for each, and permanently grow on-chain account state at zero monetary cost — mirroring the RaptorCast pattern of an uncapped, per-input resource allocation with no cleanup for "incomplete"/failed attempts.

### Finding Description
`AccountInitDecorator.AnteHandle` ( [1](#0-0) ) runs for every gasless tx (`txpolicy.IsGaslessTx`, whose whitelist includes `MsgExecutePayload` — reachable by "any" account per [2](#0-1)  and [3](#0-2) ). If `!aid.ak.HasAccount(ctx, newAccAddr)`, it verifies a signature against `account_number=0, sequence=0`, then unconditionally calls `aid.ak.NewAccountWithAddress` + `aid.ak.SetAccount`, and returns `(ctx, nil)` **without invoking `next`**, short-circuiting the rest of the ante chain (skipping `SetPubKeyDecorator`, sig-count, sig-gas-consume, and normal `SigVerificationDecorator`) — see the comment at [4](#0-3) .

Combined with the gasless chain (`app/ante/ante_cosmos.go`), which for a gasless tx skips `MinGasPriceDecorator`'s check and `DeductFeeDecorator`'s fee deduction ( [5](#0-4) ), the only real cost the attacker pays is the block-gas-limit-bounded `ConsumeGasForTxSizeDecorator` charge — no PC (native fee token) is required at all. `AccountInitDecorator` itself contains no per-block/per-IP/per-key rate limit and no bound on the total number of accounts it will create; each successful call is a permanent, unbounded write to the `x/auth` account store (analogous to RaptorCast's `pending_message_cache: LruCache::unbounded()`), and there is no cleanup path for accounts whose triggering message later fails deep inside `ExecutePayload` (e.g. "UEA is not deployed", invalid `UniversalPayload`, or a `verifyEd25519`/ECDSA signature-verification revert in the UEA contract — see [6](#0-5) ). AnteHandler-level state changes commit independently of message-execution failure, so the created account persists forever even when the wrapped `MsgExecutePayload` reverts.

### Impact Explanation
An unprivileged external attacker (no validator/UV status, no token holdings) can repeatedly:
1. Generate a fresh keypair.
2. Sign a `MsgExecutePayload` (with intentionally-invalid `UniversalPayload`/`VerificationData` so downstream execution reverts cheaply, e.g., failing the early validation in `types.NewAbiUniversalPayload` at [7](#0-6) ) against `account_number=0, sequence=0`.
3. Submit it as a completely fee-free transaction.

Each submission permanently commits one new `BaseAccount` to state — unbounded, uncapped, free of charge. Sustained over time this grows on-chain state size (larger IAVL tree, larger snapshots, slower state sync/iteration for full/validator nodes), which is the same "unbounded cache × repeated cheap trigger × no cleanup" shape as the RaptorCast report, applied to Push Chain's account store rather than a decoder cache. This is a non-network-level, state-storage denial-of-service concern reachable purely through the default `MsgExecutePayload` submission path.

### Likelihood Explanation
High. No privileged role, no stake, and no PC balance is required — gasless whitelisting is explicitly designed to let "any account" call `MsgExecutePayload" ( [8](#0-7) ). Generating keypairs and Amino/proto signatures is computationally trivial and can be scripted at scale; the only throttle is per-block gas from `ConsumeGasForTxSizeDecorator`, which bounds the rate but not the total achievable growth over time.

### Recommendation
1. Rate-limit or fee-gate first-time account creation for gasless transactions (e.g., cap accounts created per block/epoch, or require the new account to already hold a nonzero balance/funding evidence before permanent creation).
2. Only persist the new account after the wrapped message has been confirmed to succeed (defer `SetAccount` until post-execution, or use a bounded, time-limited pending-account structure with automatic eviction).
3. Add monitoring/alerting on abnormal rates of first-time-signer gasless transactions.

### Proof of Concept
1. Loop N times: generate a new secp256k1/ed25519 keypair; construct a `MsgExecutePayload` with `Signer` = the new address, an intentionally invalid `UniversalPayload` (or a `UniversalAccountId` whose UEA is undeployed/unfunded so `ExecutePayload` fails fast at [9](#0-8) ); sign it over `account_number=0, sequence=0`.
2. Broadcast each as a zero-fee tx (gas price 0, since `MinGasPriceDecorator`/`DeductFeeDecorator` are skipped for gasless txs).
3. Observe: `AccountInitDecorator` creates and commits a `BaseAccount` for each new address regardless of the subsequent `ExecutePayload` failure; repeat indefinitely to grow `x/auth` account state without bound and without spending any PC.

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}
