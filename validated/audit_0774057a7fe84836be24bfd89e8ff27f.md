### Title
Interest-free borrow/repay possible within the same Stacks block due to per-block index caching - (File: `mainnet/contracts/vault/v0-vault-stx.clar`, `mainnet/contracts/market/v0-4-market.clar`)

### Summary
Each vault contract (`v0-vault-stx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`) computes interest accrual once per block via `accrue`, and only advances the `last-update` clock when the computed index actually changes. Because interest growth is a function of elapsed time since `last-update` (using `stacks-block-time`), a borrow and a full repay executed within the same block accrue zero interest, mirroring the analog reported in the external report for `_updateGlobalInterest()`.

### Finding Description
The `accrue` function in every vault contract only updates state when not paused, computing `next-index`/`next-liquidity-index` from the current `index`/`lindex` and the elapsed time since the cached `last-update` value: [1](#0-0) 

Critically, `last-update` is only re-armed to `stacks-block-time` when the newly computed index differs from the currently stored one: [2](#0-1) 

`system-borrow` calls `accrue` first, reads the (possibly unchanged) `index`, and scales the borrowed amount using that index: [3](#0-2) 

`system-repay` likewise calls `accrue` first and computes principal/interest split against the current `index`/`total-borrowed`: [4](#0-3) 

Both operations are reachable from the market entrypoints `borrow` and `repay`, which route through `vault-system-borrow` / `vault-system-repay` to the vault's `accrue`-gated `system-borrow` / `system-repay`: [5](#0-4) [6](#0-5) 

Because `next-index`/`next-liquidity-index` derive rate accrual from `stacks-block-time - last-update` (the same "once per block" pattern flagged in the original Solidity report's `_updateGlobalInterest`), if `borrow` and `repay` for the same principal occur within the same block (same `stacks-block-time`), the elapsed interval is zero. The index therefore does not move, `last-update` is not re-armed, and the scaled-debt conversion in `system-repay` nets exactly back to the borrowed principal — meaning the loan accrued no interest for the duration it was outstanding within that block.

### Impact Explanation
This allows a well-capitalized borrower (backed by sufficient collateral in `market.clar`) to repeatedly borrow and repay large amounts within a single block, extracting the utility of capital (e.g., for arbitrage, or to occupy vault liquidity/daily borrow limits) without paying any interest to liquidity providers. Repeated over many blocks, this is a systematic loss of unclaimed interest yield that would otherwise accrue to LPs and the protocol treasury (`treasury-lp` minting in `accrue`), landing on the **theft of unclaimed yield** impact class.

### Likelihood Explanation
Likelihood is bounded by the same economic factors noted in the original report — the attacker needs sufficient collateral to borrow a meaningful amount and must pay transaction fees to execute borrow+repay within one block/timestamp window, repeating this over time to accumulate meaningful yield loss. On Stacks, multiple transactions can land in the same block (same `stacks-block-time`), making the same-block precondition straightforward to satisfy for a motivated, capitalized actor.

### Recommendation
Accrue interest based on a monotonically-increasing minimum granularity independent of "index changed" (e.g., always update `last-update` on every `accrue` call regardless of whether `index`/`lindex` changed), or introduce a minimum borrow fee applied at `system-borrow` time so that same-block flash-style borrow/repay cycles cannot be entirely interest-free.

### Proof of Concept
1. In `mainnet/contracts/market/v0-4-market.clar`, call `borrow` for asset X; this invokes `vault-system-borrow` → vault's `system-borrow`, which calls `accrue` (index computed from `stacks-block-time - last-update`, unchanged within the block) and mints scaled debt at the current `index`. [7](#0-6) 
2. In the same block/timestamp, call `repay` for the same amount; this invokes `vault-system-repay` → vault's `system-repay`, which again calls `accrue` (still zero elapsed time, `index` unchanged), and computes `principal-repaid`/`interest-paid` from the unchanged `index`/`total-borrowed`. [4](#0-3) 
3. Because `index` did not move between steps 1 and 2, `interest-paid` computed in `system-repay` is zero (or negligible), demonstrating the loan was interest-free for the block duration it was outstanding.

(define-public (repay (ft <ft-trait>) (amount uint) (on-behalf-of (optional principal)))
  (let ((address (contract-of ft))
        (asset (try! (get-asset address)))
        (asset-id (get id asset))
        ;; defaults to payer (contract-caller) if not specified
        (account (match on-behalf-of behalf behalf contract-caller))
        
        ;; Step 1: Get position WITHOUT resolving prices
        (position (try! (get-position account)))
        (mask (get mask position))
        
        ;; Step 2: Accrue user's positions (populates cache for ztokens)
        (u-debt (accrue-user-debts (get debt position)))
        
        (borrow-index (get index (unwrap-panic (get-cached-indexes asset-id))))
        
        ;; Step 3: Get account debt FIRST to enable safe amount capping
        (account-scaled-debt (get-account-scaled-debt account asset-id))
        
        ;; Step 4: Calculate max repayable amount (actual debt in token), mul-div-up for safe upper bound
        (max-repay-tokens (mul-div-up account-scaled-debt borrow-index INDEX-PRECISION))
        
        ;; Step 5: Cap input amount at actual debt - prevents overflow in scaled calculation
        (safe-amount (min amount max-repay-tokens))
        
        ;; Step 6: Convert to scaled debt (amount is bounded)
        (scaled-debt-repayment (mul-div-down safe-amount INDEX-PRECISION borrow-index))

        (repaid-scaled-debt (min account-scaled-debt scaled-debt-repayment))
        (amount-to-repay (mul-div-up repaid-scaled-debt borrow-index INDEX-PRECISION))
        
        ;; Check if repaying ALL debt for this asset
        (repaying-all (is-eq repaid-scaled-debt account-scaled-debt)))
