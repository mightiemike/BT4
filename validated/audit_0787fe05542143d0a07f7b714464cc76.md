## Analog Found: Unauthenticated "Bootstrap Declare" bypass has no restriction to genesis, remains exploitable after initial chain setup

### Title
Missing genesis-only gating on the bootstrap declare path allows any sender to bypass `__validate_declare__`, nonce and fee enforcement indefinitely - ([File: crates/starknet_api/src/executable_transaction.rs])

### Summary
The sequencer implements a special "bootstrap declare" transaction flow, intended only for the very first system-bootstrapping step (declaring the account/ERC20 classes before any account exists). The gate for this privileged flow, `DeclareTransaction::is_bootstrap_declare`, only checks `sender_address == bootstrap_address()`, `nonce == 0`, and `!charge_fee` [1](#0-0) . It contains **no check that the chain is actually still in its genesis/bootstrap state** (e.g., no check on current block number or that no blocks have been produced yet). Because no signature validation is required for this special address, any unprivileged transaction sender can submit a `Declare` transaction using the fixed `bootstrap_address()` felt (`'BOOTSTRAP'`), nonce 0, and zero-fee resource bounds, at **any point** in the chain's life, not just at genesis.

### Finding Description
`bootstrap_address()` is a compile-time-known constant (`0x424f4f545354524150`, the ASCII encoding of "BOOTSTRAP") [2](#0-1) . It requires no private key — nobody "owns" this address in the normal account sense; the sequencer simply special-cases it.

In `AccountTransaction::execute_raw`, if `tx.is_bootstrap_declare(charge_fee)` returns true, the sequencer **skips `perform_pre_validation_stage`, `__validate_declare__`, nonce increment, and fee charging entirely**, and just executes the declare's constructor-less body directly: [3](#0-2) 

The equivalent Starknet OS Cairo path (used for re-execution/proving) implements the identical unconditional check with no block-height/genesis gate: [4](#0-3) 

The only "protection" mentioned by the code comment is a side effect of `prev_value=0` in the class-hash dict update, which merely prevents declaring the exact same class hash twice — it does not prevent *new* free declarations by different callers/classes at any later block [5](#0-4) .

Searching the gateway/mempool admission path (`apollo_gateway/src/gateway.rs`, `apollo_gateway/src/stateful_transaction_validator.rs`) turns up no additional restriction tied to `bootstrap_address()` or to "genesis-only" enforcement — the `check_declare_permissions` and `block_declare` config gate unrelated declare policies (e.g., blocking all declares, limiting concurrent compilations), not the bootstrap sender specifically [6](#0-5) . The `SyncStateReaderFactory` only special-cases genesis for *state reading* convenience when no blocks exist yet, but this does not block the bootstrap-declare code path once blocks do exist [7](#0-6) .

This matches the reported bug class precisely: functionality meant to exist only for "initial setup" (chain bootstrap) has no authentication and is **left exposed after initial setup is completed**, because the exposed check depends only on transaction fields the attacker fully controls (sender address, nonce, fee), not on any actual state indicating bootstrap is still in progress.

### Impact Explanation
Any unprivileged party can submit an unsigned, fee-free `Declare` V3 transaction with `sender_address = bootstrap_address()`, `nonce = 0`, and zero-fee resource bounds, at any block height, and have the sequencer declare an arbitrary class of the attacker's choosing without paying any fee and without any signature check. This is a genuine authentication bypass for a normally-gated operation (declare requires `__validate_declare__` and fee payment for every other sender). Effects:
- Free, unauthenticated, unlimited-class-hash declare transactions can be spammed post-genesis, bypassing the fee market and consuming batcher/compiler/storage resources (declare transactions are explicitly rate-limited elsewhere via `declare_compilation_semaphore`/`max_concurrent_declare_compilations`, indicating declares are recognized as an expensive resource that should always be paid for) [8](#0-7) .
- Because the bootstrap path skips `perform_pre_validation_stage` (which normally enforces nonce/fee correctness) and never increments a nonce, these transactions are also never removed from the mempool on success and get resubmitted every block until the class-hash collision causes rejection, per the code's own documented "unintuitive but expected" behavior [9](#0-8) , creating a persistent, cost-free entry point into mempool/batcher processing for a value that should be authenticated.

This satisfies "unauthorized account action" (unauthenticated privileged state mutation — declaring a class without fee/signature) reachable from a single submitted transaction with no operator/prover/peer involvement.

### Likelihood Explanation
High likelihood of exploitability: this only requires constructing a standard V3 `Declare` transaction with a known constant sender address, nonce 0, and a `no_fee_enforcement` resource bound — exactly what the test helper `generate_bootstrap_declare()` in `mempool_test_utils` already demonstrates is producible with default signature and no fee [10](#0-9) . Nothing in the gateway, mempool, or blockifier gates this to genesis specifically.

### Recommendation
Restrict `is_bootstrap_declare` (and the corresponding OS Cairo check) to be valid only when the chain has not yet produced blocks (e.g., require `block_number == 0` / an explicit "chain not yet bootstrapped" flag persisted in state), or remove the special-case path entirely after the genesis block is committed. Additionally, consider gating the bootstrap path at the gateway/mempool admission layer so it is rejected outright once the sequencer is running in steady state.

### Proof of Concept
1. After the chain has been running normally for any number of blocks, craft a V3 `Declare` transaction with:
   - `sender_address = DeclareTransaction::bootstrap_address()` (`0x424f4f545354524150`)
   - `nonce = 0`
   - `resource_bounds` configured so `charge_fee` evaluates to `false` (e.g., via `ValidResourceBounds::create_for_testing_no_fee_enforcement()`, mirroring `generate_bootstrap_declare()`)
   - `class_hash`/`compiled_class_hash` for any class of the attacker's choosing, with default/empty `signature`.
2. Submit via the gateway's `add_tx`. No `check_declare_permissions` or stateful validator rejects it based on chain height.
3. In `AccountTransaction::execute_raw`, `tx.is_bootstrap_declare(charge_fee)` returns true, skipping `__validate_declare__`, nonce checks, and fee charging, and the class is declared for free [11](#0-10) .
4. Repeat with new class hashes to continue declaring classes for free indefinitely, well after "initial setup" (genesis) has completed.

    // In this case, no account-related actions should be made besides the declaration.

        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;

        // meet the following conditions.
        // This flow is used for the sequencer to bootstrap a new system.
        // Note: The absence of any account-related action leads to some unintuitive but expected
        // behavior:
        // - After the transaction is executed successfully, the batcher does not notify the mempool
        //   about its inclusion in a block. As a result, the transaction remains in the mempool.
        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.
        // - The transaction will then be marked as rejected, the mempool will be notified, and the
        //   transaction will be removed from the mempool.
        if let Transaction::Declare(tx) = &self.tx {
            if tx.is_bootstrap_declare(self.execution_flags.charge_fee) {
                let mut context = EntryPointExecutionContext::new_invoke(
                    tx_context.clone(),
                    self.execution_flags.charge_fee,
                    SierraGasRevertTracker::new(GasAmount::default()),
                );
                let mut remaining_gas = 0;
                let res = tx.run_execute(state, &mut context, &mut remaining_gas)?;
                assert!(res.is_none(), "Declare execute should not result in a CallInfo.");

                return Ok(TransactionExecutionInfo::default());
            }
