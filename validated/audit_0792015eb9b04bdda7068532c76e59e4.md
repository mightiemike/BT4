### Title
Attacker-controlled `PRC20` field in `RescueFundsOnSourceChain` event lets rescue outbounds misroute the wrong token/asset mapping - (File: x/uexecutor/keeper/create_outbound.go)

### Summary
`AttachRescueOutboundFromReceipt` builds a `RESCUE_FUNDS` outbound entirely from attacker-controlled event fields without verifying that the `PRC20` (and gas parameters) in the `RescueFundsOnSourceChain` event actually match the asset that was locked in the original, stuck `UniversalTx`. This is the same root-cause class as the `recoverERC20()` report: a fund-recovery/rescue code path accepts an unconstrained token identifier instead of binding recovery strictly to the legitimate, originally-locked asset.

### Finding Description
`AttachRescueOutboundFromReceipt` [1](#0-0)  scans logs from a Push-Chain-side transaction to `UNIVERSAL_GATEWAY_PC` for the `RescueFundsOnSourceChain` event and decodes it via `DecodeRescueFundsOnSourceChainFromLog` [2](#0-1) . This event carries a fully caller-controlled `PRC20` address (topic-indexed, supplied by whoever calls the gateway contract), plus attacker-controlled `GasFee`, `GasPrice`, and `GasLimit` data fields [3](#0-2) .

The keeper then:
1. Validates only that the referenced `originalUtx` (looked up by `event.UniversalTxId`) is in a rescue-eligible state (CEA deposit failed, or non-CEA inbound-revert already `REVERTED`) [4](#0-3) .
2. Resolves `tokenCfg` by looking up `event.PRC20` — the attacker-supplied token — against the *original UTX's source chain*, with no check that this PRC20 equals the PRC20/asset that was actually part of `originalUtx.InboundTx` [5](#0-4) .
3. Builds the `RESCUE_FUNDS` outbound using `ExternalAssetAddr: tokenCfg.Address` (derived from the attacker-chosen PRC20) but `Amount: originalUtx.InboundTx.Amount` (denominated in the *original* token's units/decimals), plus the attacker-supplied `GasFee`/`GasPrice`/`GasLimit` [6](#0-5) .

Nowhere in this path is `event.PRC20` checked against `originalUtx.InboundTx.AssetAddr` / the PRC20 actually associated with the stuck inbound. An unprivileged caller can therefore trigger a rescue outbound whose `ExternalAssetAddr`/token-decimal semantics belong to a completely different (but registry-whitelisted) token than the one that is actually locked for that UTX, while the numeric `Amount` still comes from the original inbound. This breaks the registry/accounting invariant that token mapping and asset semantics attached to an outbound must correspond to the actual escrowed asset.

### Impact Explanation
Because honest Universal Validators/TSS act on the `ExternalAssetAddr`/`Amount` pair as constructed by this keeper code, a mismatched token mapping can cause the outbound to instruct release/refund of the wrong asset/denomination amount on the source chain relative to what is actually escrowed — corrupting PRC20/native asset accounting and token-mapping invariants for the rescue path, and potentially causing incorrect fund movement (misrouted value) or a failed/incorrect release against the vault. This matches the "Registry and accounting path" and "unauthorized release ... of user or protocol-controlled funds" impact categories in scope.

### Likelihood Explanation
The trigger is a normal, unprivileged call to the public gateway contract (`UniversalGatewayPC`) that emits `RescueFundsOnSourceChain` with attacker-chosen `PRC20`/gas fields, requiring only that the referenced `originalUtx` be in the rescue-eligible state — a state reachable by ordinary users whose inbound failed or was reverted. No validator, node, or admin collusion is required.

### Recommendation
Validate `event.PRC20` against the actual asset recorded on `originalUtx.InboundTx` (e.g., its `AssetAddr`/PRC20 field) before building the rescue outbound, rejecting the rescue if they don't match. Similarly, do not trust attacker-supplied `GasFee`/`GasPrice`/`GasLimit` verbatim for the rescue outbound — recompute or bound them from protocol-controlled parameters, analogous to how the original report recommends binding legitimate-token identification to an explicit data structure rather than accepting caller-supplied token identifiers unchecked.

### Proof of Concept
1. Attacker finds (or creates) a `UniversalTx` that is rescue-eligible (CEA deposit `FAILED`, or non-CEA `INBOUND_REVERT` outbound `REVERTED`) — this state is reachable via normal inbound failure flows.
2. Attacker calls the `UniversalGatewayPC` rescue entry point on Push Chain, supplying `universalTxId` = that UTX's ID but `prc20` = a different, unrelated whitelisted PRC20 address for the same source chain (and arbitrary `gasFee`/`gasPrice`/`gasLimit`).
3. `AttachRescueOutboundFromReceipt` passes eligibility checks (which don't check `PRC20`) and builds a `RESCUE_FUNDS` outbound with `ExternalAssetAddr` from the unrelated token but `Amount` from the original inbound, plus attacker-chosen gas parameters [7](#0-6) .
4. The mismatched outbound proceeds toward TSS signing/finalization with an asset/amount pairing that does not correspond to reality.

// RescueFundsOnSourceChainEvent holds decoded data from the RescueFundsOnSourceChain
// event emitted by UniversalGatewayPC when a user initiates a rescue on the source chain.
type RescueFundsOnSourceChainEvent struct {
	UniversalTxId  string   // 0x-prefixed bytes32 — the original UTX whose funds are stuck
	PRC20          string   // 0x-prefixed address — PRC20 token whose counterpart is locked
	ChainNamespace string   // source chain namespace (e.g. "eip155")
	Sender         string   // 0x-prefixed address — user who initiated the rescue
	TxType         TxType   // always TxType_RESCUE_FUNDS
	GasFee         *big.Int // gas fee charged (in gas-token units)
	GasPrice       *big.Int // gas price on the source chain
	GasLimit       *big.Int // gas limit used for the rescue execution
}

func DecodeRescueFundsOnSourceChainFromLog(log *evmtypes.Log) (*RescueFundsOnSourceChainEvent, error) {
	if len(log.Topics) < 4 {
		return nil, fmt.Errorf("RescueFundsOnSourceChain: need 4 topics, got %d", len(log.Topics))
	}
	if strings.ToLower(log.Topics[0]) != strings.ToLower(RescueFundsOnSourceChainEventSig) {
		return nil, fmt.Errorf("not a RescueFundsOnSourceChain event")
	}

	event := &RescueFundsOnSourceChainEvent{
		UniversalTxId: log.Topics[1], // bytes32 as 0x-prefixed hex
		PRC20:         common.HexToAddress(log.Topics[2]).Hex(),
		Sender:        common.HexToAddress(log.Topics[3]).Hex(),
	}

	stringType, _ := abi.NewType("string", "", nil)
	uint8Type, _ := abi.NewType("uint8", "", nil)
	uint256Type, _ := abi.NewType("uint256", "", nil)

	arguments := abi.Arguments{
		{Type: stringType},  // chainNamespace
		{Type: uint8Type},   // txType
		{Type: uint256Type}, // gasFee
		{Type: uint256Type}, // gasPrice
		{Type: uint256Type}, // gasLimit
	}

	values, err := arguments.Unpack(log.Data)
	if err != nil {
		return nil, fmt.Errorf("failed to unpack RescueFundsOnSourceChain data: %w", err)
	}
	if len(values) != 5 {
		return nil, fmt.Errorf("RescueFundsOnSourceChain: unexpected value count %d", len(values))
	}

	event.ChainNamespace = values[0].(string)
	event.TxType = SolidityTxTypeToProto(values[1].(uint8))
	event.GasFee = values[2].(*big.Int)
	event.GasPrice = values[3].(*big.Int)
	event.GasLimit = values[4].(*big.Int)
