### Title
Missing declared-class check in `execute_replace_class` allows the Starknet OS to accept unauthorized class replacements not enforceable by honest re-execution - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `replace_class` syscall handler in the Cairo Starknet OS program blindly writes an attacker-supplied `class_hash` into a contract's state entry, with an explicit `TODO` acknowledging the missing validation that the class hash corresponds to a declared class. This is analogous to CVE-2018-16597, where overlayfs's incorrect/missing access checking on the underlying layer allowed unprivileged local users to modify files they should not have been permitted to touch. Here, the "underlying layer" is the committed Starknet state that the OS is responsible for authoritatively re-validating; the OS is the layer that must independently enforce access/validity rules regardless of what the block-producing sequencer claims, since it produces the STARK proof that attests the state transition is valid.

### Finding Description
`execute_replace_class` in `syscall_impls.cairo` reads the `class_hash` from the syscall request and immediately overwrites the target contract's `StateEntry.class_hash` via `dict_update`, with no check that the class is declared: [2](#0-1) 

The comment at line 902, `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`, is a direct admission that this validation is absent from the OS's Cairo1 `replace_class` implementation. The same gap exists in the deprecated (Cairo0) OS syscall path, `execute_replace_class` in `deprecated_execute_syscalls.cairo`, which similarly performs the `dict_update` with no declared-class check: [3](#0-2) 

By contrast, the blockifier's Rust `ReplaceClass` syscall handler for the deprecated flow does perform this check by attempting to fetch the compiled class before writing the new class hash, which fails if the class is undeclared: [4](#0-3) 

Blockifier's Cairo1/native path (`SyscallHandlerBase::replace_class`, invoked from both the VM and native syscall handlers) is expected to perform the equivalent declared-class validation at execution time (confirmed by the blockifier test suite `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`, which explicitly asserts `"is not declared"` errors for undeclared/Cairo0-mismatched class hashes) — this check happens purely in the untrusted/native execution path, not inside the SNOS Cairo program that is actually proven.

Because the STARK-proven `syscall_impls.cairo`/`deprecated_execute_syscalls.cairo` OS logic is the layer that determines what state transitions the proof attests as valid (analogous to the kernel enforcing access rules independent of what a mount/overlay claims), the missing check means the OS will accept and commit a `ReplaceClass` state update to any `class_hash` value supplied via the hint (`GetContractAddressStateEntry`), without any Cairo-level assertion tying that class hash to a class that was actually declared (Sierra hash validated) or has associated CASM in `contract_class_changes`. The prover-facing OS trusts the block-producer-supplied hint data for consistency with blockifier rather than independently enforcing it in-circuit.

### Impact Explanation
If a sequencer/prover (even an honest one running buggy code, or specifically a block built via a path that bypasses blockifier's `try_declare`/`get_compiled_class` guard) supplies a state diff in which `ReplaceClass` sets a contract's class hash to an undeclared or fabricated value, the OS will accept it as valid and produce a proof for a state root that violates the invariant "every contract's class hash must reference a declared class." This can lead to:
- A committed state root/class hash for a contract that does not correspond to any real, provable executable code, undermining full nodes' and the OS's own soundness guarantees for that contract going forward (any node relying on the OS-approved state — the trust anchor of the system — would diverge from or be unable to reconcile with contracts expecting `get_class_hash_at` to always resolve to declared code).
- Honest-node divergence: honest full nodes executing via blockifier would reject or produce a different result for a transaction sequence that attempts to set an undeclared class hash (per the `DeclareTransactionError`/`"is not declared"` checks enforced in Rust), while the OS/proof, lacking the same check, would still accept and commit it if the state diff hint is engineered independently of blockifier's guarded call path.

This satisfies the required impact bar of "wrong committed root" / "honest-node divergence" reachable via a single contract call executing the `replace_class` syscall.

### Likelihood Explanation
The `replace_class` syscall is reachable by any unprivileged contract executing ordinary Cairo0 or Cairo1 code — this is a base-layer syscall available to any contract, requiring no special privileges. The bug is a straightforward missing assertion in-circuit (confirmed via source code and an explicit unresolved `TODO`), not a hypothetical or by-design limitation, making the likelihood of triggering the code path itself trivial. The remaining constraint is whether a mismatched (blockifier-rejecting but OS-accepting) state diff can actually be produced end-to-end by the current sequencer/prover pipeline; this depends on whether all inputs into the OS's `contract_state_changes` are strictly re-derived by blockifier execution or can be supplied independently as prover hints. I was not able to fully trace the hint-generation pipeline (`GetContractAddressStateEntry`) to confirm whether it enforces blockifier consistency at a layer outside the OS's Cairo code, so this should be validated against the hint-processor / block-building code that populates `contract_state_changes` before the OS runs.

### Recommendation
Add the same declared-class check that blockifier performs (`get_compiled_class`/`is_declared`-style lookup) directly inside `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, using `contract_class_changes`/`compiled_class_hash` dict reads to assert the target `class_hash` is present in the declared-classes dictionary before performing the `dict_update` on `contract_state_changes`. This closes the `TODO(Yoni, 1/1/2026)` gap and ensures the OS enforces this invariant independently of blockifier, matching the access-check parity that CVE-2018-16597 was about restoring in overlayfs.

### Proof of Concept
1. An unprivileged account submits an `INVOKE` transaction calling a deployed Cairo1 or Cairo0 contract's `replace_class`/`test_replace_class` entry point (as exercised by `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash` and `crates/blockifier/src/execution/deprecated_syscalls/deprecated_syscalls_test.rs::test_replace_class`) with an arbitrary, undeclared `class_hash` value.
2. Under blockifier's Rust execution (used by the honest sequencer to build blocks), this call is rejected with `"is not declared"` per `hint_processor.rs:801` / `SyscallHandlerBase::replace_class`.
3. However, when the Starknet OS Cairo program re-executes/verifies a state transition where a `ReplaceClass` state update to an undeclared class hash was nonetheless injected into `contract_state_changes` (via the `GetContractAddressStateEntry` hint feeding `execute_replace_class` at `syscall_impls.cairo:881-920`), no Cairo-level assertion exists to reject it — the `dict_update` at lines 910-914 unconditionally succeeds and the resulting `StateEntry.class_hash` is committed into the proven state, since only a `TODO` comment marks the missing check.     // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

        key=contract_address,
