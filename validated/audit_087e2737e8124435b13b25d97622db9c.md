Based on my research, I found a concrete analog to the AgentDAO "score inflation via spamming" bug class: the `AccountInitDecorator` in the gasless-transaction ante pipeline lets any unprivileged actor mint on-chain accounts for free and unboundedly, by exploiting the fact that account creation is gated only by "does this signature verify for a fresh account_number=0/sequence=0", not by any real cost, deposit, or authorization tied to the underlying gasless message actually succeeding.

### Title
Unbounded free on-chain account creation via gasless-tx allowlist enables state-bloat spam - (File: `app/ante/account_init_decorator.go`)

### Summary
The `AccountInitDecorator` auto-creates a brand-new Cosmos account for any signer of a whitelisted "gasless" message type [1](#0-0) , and the paired `DeductFeeDecorator` unconditionally skips fee collection for the same whitelist [2](#0-1) . Because `MsgExecutePayload` is in the gasless allowlist and, per the module's own documentation, "Any account may submit the message" [3](#0-2) , an attacker can generate an unlimited number of fresh keypairs, sign one `MsgExecutePayload` per keypair (with arbitrary/garbage `UniversalAccountId`/payload content that will fail downstream), and have the chain persist a brand-new `BaseAccount` for every single one of them — at zero fee and without holding any balance, stake, or prior relationship to the protocol.

### Finding Description
The gasless allowlist in `app/txpolicy/gasless.go` includes `MsgExecutePayload`, `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, and `MsgVoteFundMigration` [4](#0-3) . The intent (per `app/README.md`) is to let Universal Validators vote without holding gas tokens, and to let third parties gaslessly relay owner-signed `MsgExecutePayload` calls [5](#0-4) .

For the vote messages (`MsgVoteInbound`, `MsgVoteOutbound`, etc.), the actual "is this a legitimate Universal Validator" check happens inside the `msgServer` handler, *after* the ante chain has already run — e.g. `IsBondedUniversalValidator` / `IsTombstonedUniversalValidator` are checked in `VoteInbound`/`VoteOutbound` message-server methods [6](#0-5) . But `MsgExecutePayload` has **no such gate at all** — `ms.k.ExecutePayload` is called directly with whatever signer/UniversalAccountId is supplied [7](#0-6) , and the module explicitly documents that `Signer != Owner` is by design and not restricted [8](#0-7) .

Because the ante pipeline places `NewAccountInitDecorator` before signature/sequence verification and before `MsgServiceRouter` dispatch [9](#0-8) , the new account is created and persisted the moment a valid ed25519/secp256k1 signature over account_number=0/sequence=0 is produced — regardless of whether `ExecutePayload` will later fail (e.g., bad `UniversalAccountId`, missing UEA balance, invalid `VerificationData`). The decorator's own logic shows this clearly: it verifies the signature, then unconditionally calls `aid.ak.NewAccountWithAddress` and `SetAccount`, and short-circuits the ante chain, returning success *before* the message is ever routed to the handler [10](#0-9) .

Combined with `DeductFeeDecorator` skipping fee deduction entirely for any gasless tx [2](#0-1) , an attacker pays **nothing** — no gas fee, no minimum balance, no staking, no prior relationship — for each such account creation.

### Impact Explanation
This is a permanent, unbounded state-growth primitive controlled entirely by an unprivileged external actor: every fresh keypair used to sign a single (even guaranteed-to-fail) `MsgExecutePayload` results in one new `BaseAccount` object permanently written to the `auth` module's account store, at zero cost to the attacker. This directly parallels the AgentDAO bug class — a permissionless, cost-free action (submitting a dummy proposal / here, a dummy `MsgExecutePayload`) causes a persistent state mutation (`score++` / here, `NewAccountWithAddress` + `SetAccount`) that is supposed to be gated by an implicit cost (holding voting weight / here, paying transaction fees or being a legitimate protocol participant) but isn't. At scale this is a state-bloat denial-of-service vector against Push Chain's account store and a way to inflate on-chain account_number allocation without any economic cost, which is explicitly in-scope ("denial of service only when it is not network-level and is reachable without privileged control").

### Likelihood Explanation
High. No special access, staking, or existing funds are required — anyone can generate arbitrary keypairs off-chain, sign a `MsgExecutePayload` (or any other gasless-whitelisted message with a syntactically valid but otherwise garbage payload) and broadcast it. The `AccountInitDecorator` only requires a valid signature over account_number=0/sequence=0, which any freshly generated key satisfies trivially [11](#0-10) .

### Recommendation
Do not allow arbitrary unauthenticated parties to trigger `NewAccountWithAddress`/`SetAccount` purely by virtue of "message type is in the gasless allowlist." Either: (1) restrict the gasless account-auto-init path to message types whose signer is cryptographically or structurally tied to a bonded Universal Validator or a real UEA owner *before* account creation (i.e., move the `IsBondedUniversalValidator`/ownership check earlier, into the ante decorator, for the specific message being processed), or (2) require a minimal anti-spam cost (e.g., a tiny non-zero fee, or a rate limit per IP/session at the mempool level) for account auto-initialization regardless of gaslessness, or (3) do not auto-create the account inside the ante handler for message types like `MsgExecutePayload` where "any account may submit," and instead let normal account creation semantics (funded account triggers creation) apply.

### Proof of Concept
Conceptual sequence (pseudocode against the exposed gRPC/Tx interfaces):
```go
for i := 0; i < N; i++ {
    priv := secp256k1.GenPrivKey()          // fresh, unfunded keypair, cost: free
    addr := sdk.AccAddress(priv.PubKey().Address())

    msg := &uexecutortypes.MsgExecutePayload{
        Signer:             addr.String(),
        UniversalAccountId: &uexecutortypes.UniversalAccountId{ /* garbage/unowned values */ },
        UniversalPayload:   &uexecutortypes.UniversalPayload{ /* arbitrary */ },
        VerificationData:   "0x00", // will fail verification downstream — irrelevant to account creation
    }

    tx := buildAndSignTx(priv, msg, /*fee=*/ sdk.NewCoins(), /*gas=*/ 200_000)
    broadcastTx(tx) // AccountInitDecorator creates `addr` as a BaseAccount for free
                     // before ExecutePayload's later failure is ever reached
}
```
Each iteration persists a new `BaseAccount` in state at zero fee cost, regardless of the eventual (expected) failure of `ExecutePayload` itself, demonstrating the free/unbounded state-growth primitive.

```go
func (aid AccountInitDecorator) verifySignatureForNewAccount(ctx sdk.Context, tx sdk.Tx, simulate bool) error {
	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	// stdSigs contains the sequence number, account number, and signatures.
	// When simulating, this would just be a 0-length slice.
	sigs, err := sigTx.GetSignaturesV2()
	if err != nil {
		return err
	}

	signers, err := sigTx.GetSigners()
	if err != nil {
		return err
	}

	// check that signer length and signature length are the same
	if len(sigs) != len(signers) {
		return errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "invalid number of signer;  expected: %d, got %d", len(signers), len(sigs))
	}

	newAccAddr := sdk.AccAddress(signers[0])
	for _, sig := range sigs {
		pubKey := sig.PubKey
		if pubKey == nil {
			return errorsmod.Wrap(sdkerrors.ErrInvalidPubKey, "pubkey is not provided in signature")
		}

		// retrieve signer data
		chainID := ctx.ChainID()
		var accSequence uint64 = 0
		var accNum uint64 = 0

		// no need to verify signatures on recheck tx
		if !simulate && !ctx.IsReCheckTx() && ctx.IsSigverifyTx() {
			anyPk, _ := codectypes.NewAnyWithValue(pubKey)

			signerData := txsigning.SignerData{
				Address:       newAccAddr.String(),
				ChainID:       chainID,
				AccountNumber: accNum,
				Sequence:      accSequence,
				PubKey: &anypb.Any{
					TypeUrl: anyPk.TypeUrl,
					Value:   anyPk.Value,
				},
			}
			adaptableTx, ok := tx.(authsigning.V2AdaptableTx)
			if !ok {
				return fmt.Errorf("expected tx to implement V2AdaptableTx, got %T", tx)
			}
			txData := adaptableTx.GetSigningTxData()
			ctx.Logger().Debug("account init decorator: verifying signature for new account",
				"address", newAccAddr.String(),
				"chain_id", chainID,
				"acc_num", accNum,
				"sequence", accSequence,
			)
			err = authsigning.VerifySignature(ctx, pubKey, signerData, sig.Data, aid.signModeHandler, txData)
			if err != nil {
				var errMsg string
				if OnlyLegacyAminoSigners(sig.Data) {
					// If all signers are using SIGN_MODE_LEGACY_AMINO, we rely on VerifySignature to check account sequence number,
					// and therefore communicate sequence number as a potential cause of error.
					errMsg = fmt.Sprintf("signature verification failed; please verify account number (%d), sequence (%d) and chain-id (%s)", accNum, accSequence, chainID)
				} else {
					errMsg = fmt.Sprintf("signature verification failed; please verify account number (%d) and chain-id (%s): (%s)", accNum, chainID, err.Error())
				}
				ctx.Logger().Debug("account init decorator: signature invalid for new account",
					"address", newAccAddr.String(),
					"chain_id", chainID,
				)
				return errorsmod.Wrap(sdkerrors.ErrUnauthorized, errMsg)

			}
		} else {
			ctx.Logger().Debug("account init decorator: skipping signature verification",
				"address", newAccAddr.String(),
				"simulate", simulate,
				"is_recheck_tx", ctx.IsReCheckTx(),
				"is_sigverify_tx", ctx.IsSigverifyTx(),
			)
		}
	}
	return nil
```

```markdown
### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.
```

```markdown
#### Why this is safe under `Signer ≠ Owner`

An attacker submitting `MsgExecutePayload` with their own `Signer` and a victim's `UniversalAccountId` produces no exploitable outcome:

- The factory resolves the victim's UEA address from the embedded `UniversalAccountId` — correct.
- `evmFrom` (derived from `Signer`) becomes the EVM-level `msg.sender` of the call to the UEA. Since `evmFrom != UNIVERSAL_EXECUTOR_MODULE` (`0x14191Ea54B4c176fCf86f51b0FAc7CB1E71Df7d7`), the contract enforces the signature check.
- The attacker cannot forge `VerificationData` that recovers to the victim's owner key.
- The contract reverts → the keeper returns an error → the Cosmos transaction reverts in full.
- Net effect: zero state change. No EVM gas is charged to the victim UEA (the deduction is rolled back with the rest of the transaction). The submission costs the attacker nothing on chain (gasless), but also achieves nothing.
```

```markdown
### Transaction Pipeline — Gasless Support

Push Chain extends the Cosmos AnteHandler with three custom decorators that together enable **gasless transactions** for Universal Validators and UEA users. Without this, every Universal Validator would need to hold and manage gas tokens just to vote — defeating the point of having a permissioned UV set.

**The gasless whitelist** (`app/txpolicy/gasless.go`) — only these message types qualify:

```
/uexecutor.v1.MsgExecutePayload
/uexecutor.v1.MsgVoteInbound
/uexecutor.v1.MsgVoteOutbound
/uexecutor.v1.MsgVoteChainMeta
/utss.v1.MsgVoteTssKeyProcess
/utss.v1.MsgVoteFundMigration
```

A tx is gasless only if **every** message (including those nested inside `authz.MsgExec`) is in the whitelist.

**Custom decorators**

| Decorator | File | Behavior on gasless tx |
|---|---|---|
| `MinGasPriceDecorator` | `app/cosmos/min_gas_price.go` | Skips the FeeMarket minimum-fee check entirely |
| `DeductFeeDecorator` | `app/ante/fee.go` | Skips fee deduction (no balance required) |
| `AccountInitDecorator` | `app/ante/account_init_decorator.go` | If signer has no on-chain account yet, creates it mid-pipeline with `account_number=0, sequence=0`, verifies the signature against those values, and short-circuits the rest of the ante chain |

The third decorator is what lets a freshly-keygen'd Universal Validator hot key vote on its very first tx, without anyone first having to fund it.
```
