### Title
Reserved OS contract addresses (`ALIAS_CONTRACT_ADDRESS`, `RESERVED_CONTRACT_ADDRESS`) are not protected from user-controlled deployment in the Blockifier execution path - ([File: crates/blockifier/src/execution/syscalls/syscall_base.rs])

### Summary
The Starknet OS (Cairo) enforces that a contract can never be deployed to the three OS-reserved addresses (`BLOCK_HASH_CONTRACT_ADDRESS=0x1`, `ALIAS_CONTRACT_ADDRESS=0x2`, `RESERVED_CONTRACT_ADDRESS=0x3`), which are internal "system files" used by the protocol for the block-hash table and stateful-compression aliasing. This check exists only in the Cairo OS (`deploy_contract.cairo`) and in `ContractAddress::validate()` it is incomplete: `validate()` only rejects addresses `<= 0x1`, letting `0x2` and `0x3` pass. I could not find an equivalent reserved-address guard in the Rust `blockifier` deploy syscall implementation, which is the path actually used by the sequencer/proposer to build and execute blocks. This mirrors the NTFS bug class: an internal, driver-maintained metadata region ("system file") that must be immutable to external writers is left reachable through one interface (blockifier) while only protected on another (SNOS/OS), risking corruption of that region and/or a proof/execution divergence.

### Finding Description
Reserved addresses are declared in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/constants.cairo:56-63` [1](#0-0) , and are used by the OS's `aliases.cairo` module to maintain the alias counter/mapping for stateful compression [2](#0-1) .

The Cairo `deploy_contract` function explicitly rejects deployment to `ORIGIN_ADDRESS`, `BLOCK_HASH_CONTRACT_ADDRESS`, `ALIAS_CONTRACT_ADDRESS`, or `RESERVED_CONTRACT_ADDRESS` via a multiplicative zero-check: [3](#0-2) 

This is the only complete enforcement of the "system address" restriction that I could locate. The generic Rust-side guard, `ContractAddress::validate()`, only excludes addresses `<= BLOCK_HASH_TABLE_ADDRESS (0x1)`: [4](#0-3) 

This means `0x2` (`ALIAS_CONTRACT_ADDRESS`) and `0x3` (`RESERVED_CONTRACT_ADDRESS`) both satisfy `validate()`. The blockifier's actual `deploy` syscall handler (used by the sequencer when executing real transactions to build a block) computes the deployed address via `calculate_contract_address` and immediately proceeds to `execute_deployment`, with no reserved-address rejection analogous to the Cairo OS check: [5](#0-4) 

Because `deploy_from_zero` is supported, the deployer component of the address hash can be forced to zero, making the resulting address depend only on `salt`, `class_hash`, and `constructor_calldata` — all attacker-controlled and brute-forceable to target `0x2` or `0x3`.

### Impact Explanation
If a transaction sender can get the sequencer's `blockifier` to deploy a contract to `ALIAS_CONTRACT_ADDRESS` (`0x2`), that address's class hash, nonce, and storage become externally attacker-controlled in the state actually committed by the node — including the `ALIAS_COUNTER_STORAGE_KEY` and alias-mapping slots that the OS's stateful-compression logic in `aliases.cairo` assumes are exclusively OS-managed. Two outcomes are both critical:
- The block built by the sequencer diverges from what the Starknet OS (SNOS) can re-execute, since the OS's `deploy_contract` rejects the same deployment — a proof/execution divergence that can halt block confirmation/proving (network unable to confirm new blocks/transactions).
- If the attacker-controlled contract subsequently manipulates the alias counter/mapping storage in ways the OS's aliasing algorithm does not expect, it can corrupt the stateful-compression state diff computation used for the committed state root, leading to wrong committed roots / honest-node divergence.

Either outcome satisfies the "wrong committed root or block hash" / "network unable to confirm new transactions" impact criteria, and is reachable purely from an unprivileged sender issuing a deploy (or deploy_account) transaction/syscall.

### Likelihood Explanation
Deploying to an attacker-chosen felt-valued address only requires brute-forcing `salt` (or using `deploy_from_zero=true` to eliminate the deployer term) until `calculate_contract_address` yields `0x2` or `0x3` — a a computation feasible off-chain before submission. No special privileges, staking, or protocol-internal access are required; a normal `invoke`/`deploy_account` transaction from any account is sufficient to reach the `deploy` syscall path in blockifier.

### Recommendation
Add the same reserved-address exclusion enforced by the Cairo OS (`deploy_contract.cairo`) to the Rust `blockifier` deploy path — either by extending `ContractAddress::validate()` to reject all OS-reserved addresses (`0x1`–`0x3`, sourced from `OsContractAddresses`), or by adding an explicit check in `crates/blockifier/src/execution/syscalls/syscall_base.rs::deploy` (and the deprecated-syscalls deploy handler) that rejects `deployed_contract_address` values equal to `block_hash_contract_address`, `alias_contract_address`, or `reserved_contract_address` before calling `execute_deployment`.

### Proof of Concept
1. Submit a `deploy_account` or `invoke` transaction (calling the `deploy` syscall) with `deploy_from_zero = true`, an arbitrary `class_hash`/`constructor_calldata`, and iterate `contract_address_salt` off-chain until `calculate_contract_address(salt, class_hash, calldata, ContractAddress::default())` equals `0x2` (`ALIAS_CONTRACT_ADDRESS`).
2. Submit the transaction to the sequencer. `crates/blockifier/src/execution/syscalls/syscall_base.rs::deploy` computes the same address and, absent a reserved-address check, proceeds to `execute_deployment`, successfully deploying attacker-controlled code/storage at `0x2` in the block the sequencer builds.
3. When SNOS re-executes/proves the same block, `deploy_contract.cairo`'s `assert_not_zero` on the reserved-address product fails for this transaction, causing the OS to reject/diverge from the sequencer's committed block — or, absent detection, the attacker's contract can subsequently write to alias-counter/alias-mapping storage slots that the aliasing algorithm relies on being OS-exclusive, corrupting future stateful-compression state diffs.

impl ContractAddress {
    /// Validates the contract address is in the valid range for external access.
    /// The lower bound is above the special saved addresses and the upper bound is congruent with
    /// the storage var address upper bound.
    pub fn validate(&self) -> Result<(), StarknetApiError> {
        let value = self.0.0;
        let l2_address_upper_bound = Felt::from(*L2_ADDRESS_UPPER_BOUND);
        if (value > BLOCK_HASH_TABLE_ADDRESS.0.0) && (value < l2_address_upper_bound) {
            return Ok(());
        }

        Err(StarknetApiError::OutOfRange { string: format!("[0x2, {l2_address_upper_bound})") })
    }

    pub fn deploy(
        &mut self,
        class_hash: ClassHash,
        contract_address_salt: ContractAddressSalt,
        constructor_calldata: Calldata,
        deploy_from_zero: bool,
        remaining_gas: &mut u64,
    ) -> SyscallResult<(ContractAddress, CallInfo)> {
        self.increment_syscall_linear_factor_by(
            &SyscallSelector::Deploy,
            constructor_calldata.0.len(),
        );
        let versioned_constants = &self.context.tx_context.block_context.versioned_constants;
        if should_reject_deploy(
            versioned_constants.disable_deploy_in_validation_mode,
            self.context.execution_mode,
        ) {
            self.reject_syscall_in_validate_mode("deploy")?;
        }

        let deployer_address = self.call.storage_address;
        let deployer_address_for_calculation = match deploy_from_zero {
            true => ContractAddress::default(),
            false => deployer_address,
        };
        let deployed_contract_address = calculate_contract_address(
            contract_address_salt,
            class_hash,
            &constructor_calldata,
            deployer_address_for_calculation,
        )?;

        let ctor_context = ConstructorContext {
            class_hash,
            code_address: Some(deployed_contract_address),
            storage_address: deployed_contract_address,
            caller_address: deployer_address,
        };
        let call_info = execute_deployment(
            self.state,
            self.context,
            ctor_context,
            constructor_calldata,
            remaining_gas,
        )?;
        Ok((deployed_contract_address, call_info))
    }
