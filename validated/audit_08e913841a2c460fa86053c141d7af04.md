`TransactionOutput::ensure_match_transaction_info` ignores position/hot-state checkpoint roots, allowing replay-verify tooling to accept a diverged authenticated state root - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the sole authenticity check used by replay/debugging tools (`storage/db-tool/src/replay_on_archive.rs`, `aptos-move/aptos-debugger/src/aptos_debugger.rs`, `aptos-move/cli/src/commands.rs`) to confirm that a locally re-executed transaction output matches the trusted, committed `TransactionInfo`. The function checks status, gas used, write-set hash (`state_change_hash`), and event root hash, but does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`. This gap is explicitly acknowledged in a code comment as a known limitation to be closed "before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`."

### Finding Description
`ensure_match_transaction_info` at [1](#0-0)  validates only:
- `status` vs `txn_info.status()`
- `gas_used` vs `txn_info.gas_used()`
- `write_set_hash` vs `txn_info.state_change_hash()`
- `event_root_hash` vs `txn_info.event_root_hash()`

It explicitly does not compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`, as documented directly in the code: [2](#0-1) 

These checkpoint hashes are precisely the Merkle roots that authenticate the *state* resulting from a batch of transactions — they are committed into the on-chain `TransactionInfo` (part of the transaction accumulator, see `TransactionInfoV1` fields at [3](#0-2) ) and are consumed elsewhere as the trust anchor for fast-sync/state-sync of the native position state, e.g. `expected_snapshot_root` in the state-sync bootstrapper uses `position_state_checkpoint_hash()` directly as the expected root to verify incoming state chunks: [4](#0-3) .

`ensure_match_transaction_info` is used as the pass/fail gate in `storage/db-tool/src/replay_on_archive.rs`'s `execute_and_verify`, where a re-executed transaction output is checked against the archived, ledger-committed `TransactionInfo`: [5](#0-4) . Because the comparator omits the checkpoint-hash fields, a locally computed position state root (or hot-state/state checkpoint root) that diverges from the committed root will not be detected — the replay tool will report success even though the authenticated proof-bearing root for that ledger version is wrong.

### Impact Explanation
This breaks the "committed state that differs from the correct VM result... accepted as valid" and "authenticated API or state-view output bound to the wrong version, object, or proof context" integrity gates: any correctness bug in the native-position/hot-state Merkle-tree computation (in the executor or `aptosdb`, e.g. `position_summary_at_commit` or `merklize_main_state`) would not be caught by replay-verify tooling that operators and auditors rely on to confirm that a full/archive node correctly reproduces the canonical chain state. Since `position_state_checkpoint_hash` is also the value trusted as-is by state-sync fast-sync bootstrapping (`expected_snapshot_root`), a wrong root that slips through replay verification could propagate as the authenticated basis for syncing peers, without any tool flagging the divergence — a hard-fork-class silent state divergence.

### Likelihood Explanation
The comment states this is a deliberate, temporary gap, gated behind a feature flag `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (referenced in `types/src/on_chain_config/aptos_features.rs`) that is not yet enabled. As long as that feature (native position/trading state roots) is disabled, `position_state_checkpoint_hash`/`hot_state_checkpoint_hash` are `None` for all transactions and the gap has no practical effect. The severity is therefore contingent on that feature being enabled while this comparator remains unfixed — I was not able to confirm from the available index whether the feature is currently active on mainnet or still fully gated off; this should be verified before treating the finding as immediately exploitable.

### Recommendation
Extend `ensure_match_transaction_info` to compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present) between the locally computed output and the trusted `TransactionInfo`, and ensure this fix lands before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled in production, matching the TODO's own stated precondition.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn expected_snapshot_root(&mut self, kind: StateKind) -> Result<HashValue, Error> {
        let transaction_output_to_sync = self.get_transaction_output_to_sync()?;
        let target_transaction_info = transaction_output_to_sync

            .proof
            .transaction_infos

            })?;
        match kind {

                .ensure_state_checkpoint_hash()
                .map_err(|error| {

                        error
                    ))
                }),
            StateKind::Position => target_transaction_info
                .position_state_checkpoint_hash()
                .ok_or_else(|| Error::UnexpectedError("Missing position state root!".into())),
