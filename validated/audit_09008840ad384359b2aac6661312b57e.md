### Title
Automatic PRC20→PC swaps use an unprotected same-block spot quote with a fixed 5% slippage floor, enabling sandwich extraction of user/protocol funds - ([File: x/uexecutor/keeper/execute_inbound_gas.go], [File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go], [File: x/uexecutor/keeper/outbound.go], [File: x/uexecutor/keeper/evm.go])

### Summary
The Bunni report's underlying flaw is that a swap-adjacent protection mechanism (surge fee) is derived from a value that can be manipulated by an unprivileged actor right before the protected action executes, and the check is not robust enough to catch every path where that value can move. Push Chain has a structurally identical pattern in its own automated deposit-and-swap and gas-refund-and-swap flows: `GetSwapQuote` fetches a live spot quote from the internal Uniswap-V3-style AMM at the moment of execution, and the resulting `minPCOut` is simply `quote * 95/100`, with no TWAP, no surge/circuit-breaker, and no check for recent price movement. An unprivileged attacker who trades against the same pool immediately before the module-originated swap executes can force the "fair" quote itself to be computed off a manipulated price, then reverse the trade afterward, extracting value that should have gone to the depositor or to the gas-refund recipient.

### Finding Description
Three call sites compute `minPCOut` the same way, all via `k.GetSwapQuote(...)` immediately before calling `k.CallPRC20DepositAutoSwap` / `k.CallUniversalCoreRefundUnusedGas`:

- `ExecuteInboundGas` (GAS inbound route): quote fetched right before swap, `minPCOut = quote*95/100`. [1](#0-0) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD route): identical pattern. [2](#0-1) 
- `applyGasRefund` (outbound excess-gas refund route): identical pattern. [3](#0-2) 

The quote itself is a pure spot-price read from the AMM's `QuoterV2.quoteExactInputSingle`, taken at the exact block/state the module's `DerivedEVMCall` executes in: [4](#0-3) 

Because the quote and the swap execution both read/act on the pool's *current* reserves with no reference to a prior committed price, an external time-weighted price, or a maximum allowed deviation from a recent baseline, this is functionally the same gap the Bunni report describes: the "fair value" check (here, `minPCOut`) is derived from the same manipulable state it is supposed to protect against, at the same instant. There is no analog of Bunni's cross-check ("has anything moved unexpectedly?") — the 5% band is a static, generous tolerance applied to an already-corrupted number.

An unprivileged user can:
1. Observe a pending `MsgVoteInbound` (or the conditions that will trigger `applyGasRefund` on `MsgVoteOutbound` finalization) in the mempool.
2. Submit an ordinary swap against the same PRC20↔WPC pool used by `GetSwapQuote`/`CallPRC20DepositAutoSwap`, moving the pool price so that `GetSwapQuote` returns a depressed output estimate for the module's forthcoming swap.
3. Let the module's swap execute at (or just above) the manipulated `minPCOut` floor — a legitimate, non-reverting execution because the floor was computed from the same manipulated state.
4. Immediately reverse the first swap, capturing the value that should have accrued to the depositor (less PC minted into their UEA) or to the gas-refund recipient (less PC refunded).

This requires no validator, relayer, or admin privilege — any account able to submit ordinary EVM transactions against the pool can perform it, and it is reachable purely through the default inbound-deposit and outbound-gas-refund paths that ordinary users trigger.

### Impact Explanation
This directly reduces the amount of PC a legitimate user receives from a bridged deposit or from an unused-gas refund, transferring value to an unprivileged attacker at the expense of user/protocol-controlled funds — squarely within the "stealing ... user or protocol-controlled funds" and "corruption of ... gas fee accounting, refund accounting" impact categories in scope. Every GAS, GAS_AND_PAYLOAD inbound, and every outbound with an excess-gas refund is exposed, so the blast radius is the default, most common transaction paths in the system, not an edge case.

### Likelihood Explanation
Likelihood is medium-to-high: the attack requires only ordinary EVM transaction submission against a known, whitelisted PRC20/WPC pool, standard sandwich tooling, and observation of pending validator votes (inbound/outbound observations are public on-chain messages before finalization). The 5% slippage band is wide enough to make many sandwich attempts profitable after gas costs, especially for larger deposits/refunds. No malicious validator, relayer, or admin action is needed.

### Recommendation
Do not derive `minPCOut` purely from a spot quote taken at the moment of execution. Options:
- Use a time-weighted average price (TWAP) from the AMM (or an external oracle) as the reference price instead of `quoteExactInputSingle`'s instantaneous quote.
- Bound the acceptable deviation between the current spot price and a recent TWAP/oracle price before allowing the auto-swap to proceed (reject or fall back to no-swap deposit if the deviation exceeds a small threshold), mirroring the intent of Bunni's surge-fee "has anything unexpected moved" check.
- Tighten (or make configurable/governance-controlled) the fixed 95% slippage floor, and apply the same guard consistently across `ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund`.

### Proof of Concept
1. Attacker monitors the mempool/chain for a `MsgVoteInbound` that is about to reach the 2/3 threshold for a GAS or GAS_AND_PAYLOAD inbound (or an `MsgVoteOutbound` that will trigger `applyGasRefund`).
2. Attacker submits a swap against the PRC20↔WPC pool (the same pool `GetSwapQuote`/`CallPRC20DepositAutoSwap` will use) to move the pool's spot price unfavorably for the upcoming module swap.
3. The finalizing vote executes `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`/`applyGasRefund`, which calls `GetSwapQuote` against the now-manipulated pool state and computes `minPCOut = quote*95/100` [5](#0-4) , then executes `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` at that depressed price without reverting (since the floor itself was computed post-manipulation).
4. Attacker reverses their initial swap, extracting the price impact they created — profit taken directly from the value that should have gone to the depositor/refund recipient.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
