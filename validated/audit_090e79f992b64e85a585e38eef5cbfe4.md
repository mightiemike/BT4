This is a confirmed, explicitly-tested-and-documented design decision (not an accidental bug): `isCEA` inbounds intentionally skip the `INBOUND_REVERT` path on deposit/swap failure, as shown consistently across `execute_inbound_funds_and_payload.go`, `execute_inbound_gas_and_payload.go`, `handle_failed_inbound_validation.go`, and confirmed by multiple integration tests explicitly asserting `"no INBOUND_REVERT outbound should be created for isCEA inbound"` [1](#0-0) . This matches the Votium bug-class (a swap/deposit precondition failure that stops the "reinvestment"/deposit flow) but here it's a deliberate, tested product behavior, not an oversight.

### Title
Dust/slippage-triggered swap failure permanently strands bridged funds for isCEA GAS_AND_PAYLOAD inbounds with no revert path - (File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go)

### Summary
For `TxType_GAS_AND_PAYLOAD` inbounds with `IsCEA=true`, `ExecuteInboundGasAndPayload` calls `gasAndPayloadDepositAutoSwap`, which fetches a Uniswap-style quote (`GetSwapQuote`) and computes a `minPCOut` slippage bound before calling `CallPRC20DepositAutoSwap` [2](#0-1) . If this deposit+swap call reverts — which can happen for small/dust amounts where the swap output falls below `minPCOut`, or the quote/fee-tier lookup fails — the code explicitly takes the "isCEA failures never create an INBOUND_REVERT outbound" branch and just records a FAILED `PCTx`, returning `nil` without ever reverting or redelivering the funds [3](#0-2) .

### Finding Description
The observation/ballot layer has already finalized the inbound and recorded the `UniversalTx` by the time `ExecuteInboundGasAndPayload` runs; the corresponding external asset was already locked/consumed on the source chain gateway (that is precisely why the non-isCEA path builds an `INBOUND_REVERT` outbound via `buildRevertOutbound` to give it back) [4](#0-3) . For the isCEA branch, deposit+autoswap failure is deliberately excluded from that same recovery mechanism [5](#0-4) . Any unprivileged external attacker (or ordinary user) can trigger this simply by sending a GAS_AND_PAYLOAD inbound with `IsCEA=true` and an amount small enough, or under market conditions volatile enough, that the on-chain swap's `minPCOut` slippage check fails — exactly the "amount less than X" precondition described in the source Votium report.

### Impact Explanation
When this failure occurs, the user's bridged asset is neither delivered as PRC20 to the recipient (deposit/swap reverted) nor returned to the source chain (no revert outbound is built for isCEA). The funds are permanently stranded — the `UniversalTx` is finalized with a FAILED `PcTx` and no further automatic recovery path exists, matching the "permanent freezing of user or protocol-controlled funds" impact category.

### Likelihood Explanation
Triggering requires only submitting/observing a normal isCEA GAS_AND_PAYLOAD inbound with a small amount (or timing it during volatile swap pricing) — no privileged access, malicious validator, or malicious relayer needed; this is reachable via the ordinary user-facing inbound submission and voting flow.

### Recommendation
For isCEA GAS_AND_PAYLOAD (and isCEA FUNDS_AND_PAYLOAD) deposit/swap failures, either (a) build and attach an `INBOUND_REVERT` outbound the same way the non-isCEA path does, or (b) fall back to a plain deposit without autoswap when the swap leg fails (mirroring the Votium mitigation of removing the hard minimum / adding a fallback path), instead of silently leaving the `UniversalTx` in a terminal FAILED state with no fund-recovery mechanism.

### Proof of Concept
1. Register a token config and chain config enabling inbound/outbound as in `test/integration/uexecutor/vote_inbound_validation_test.go`.
2. Submit an isCEA `TxType_GAS_AND_PAYLOAD` inbound with recipient = a deployed UEA and `Amount` set small enough that the computed `minPCOut` (95% of quote) cannot be satisfied by the pool (or mock the quote/fee-tier lookup to fail), reproducing the `depositAutoSwap failed` error path at [6](#0-5) .
3. Vote the inbound to quorum as in the existing test helpers.
4. Observe the resulting `UniversalTx` has a FAILED `PcTx` and `utx.OutboundTx` is empty (no `INBOUND_REVERT`), analogous to the assertions already made in `test/integration/uexecutor/vote_inbound_validation_test.go:243-310` for the FUNDS_AND_PAYLOAD isCEA case — confirming funds are stuck with no recovery outbound.
