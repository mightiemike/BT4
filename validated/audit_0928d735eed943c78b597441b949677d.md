## Analysis: Spot-Price-Based Gas Autoswap Quote Used As Its Own Slippage Protection

The external report's core defect — using live spot AMM state both to *compute* an expected value and to *validate* it, with no time-lagged/TWAP reference — has a direct analog in Push Chain's gas-abstraction autoswap path.

### Title
Self-referential spot-price slippage check in PRC20→WPC gas autoswap enables sandwich extraction of user/protocol funds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
When a `GAS`, `GAS_AND_PAYLOAD` inbound is finalized, or when unused gas is refunded on outbound, the keeper fetches a Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote and derives its own slippage floor (`minPCOut = quote * 95 / 100`) from that same spot quote, then immediately executes the swap in the same atomic call. Because the "protection" value is computed from the manipulable spot price at the exact moment of execution, it protects against nothing but block-to-block drift — an attacker who moves the on-chain WPC/PRC20 pool price in the same block (a classic sandwich) can force the module-driven autoswap to execute at an attacker-favorable price, extracting value from the user's deposited gas token / the protocol's refund at the depositor's expense.

### Finding Description
`GetSwapQuote` calls the pool's `quoteExactInputSingle` view function using current (spot) reserves [1](#0-0) . Immediately afterward, `minPCOut` is derived from that identical spot value with a flat 5% tolerance and passed into the same-block deposit/swap call: [2](#0-1) 

The same pattern recurs for `GAS_AND_PAYLOAD` inbounds [3](#0-2)  and for unused-gas refunds on outbound finalization [4](#0-3) .

There is no TWAP, no oracle cross-check, and no separation in time between "get expected price" and "execute at that price" — both happen in the identical EVM call context, driven by the module account via `DerivedEVMCall` [5](#0-4) . The swap itself is triggered synchronously and deterministically as soon as the finalizing `MsgVoteInbound` reaches quorum, inside the very same state-machine execution: `VoteInbound` → `ExecuteInbound` → `ExecuteInboundGas` [6](#0-5) , [7](#0-6) .

Since the triggering event is a public transaction (the quorum-completing `MsgVoteInbound`, or, for refunds, an `MsgVoteOutbound`), an unprivileged attacker observing the mempool can:
1. Submit a large swap against the internal WPC/PRC20 Uniswap V3 pool to push the pool price in a favorable direction, ordered immediately before the finalizing vote transaction in the same block.
2. Let the module-driven autoswap execute at the manipulated spot price — the 5% tolerance is measured against the manipulated price itself, so it does not detect the manipulation.
3. Reverse the manipulation trade afterward in the same block, extracting the difference at the expense of the depositing user (who receives fewer PC-denominated proceeds than fair value) or the protocol-held gas-refund pool.

### Impact Explanation
This corrupts PRC20/native asset accounting for the gas-abstraction flow: a user's cross-chain gas-token deposit (or the refund of their unused gas) is converted at an attacker-manipulated exchange rate instead of a fair one, resulting in fund loss to the user/protocol and profit to the attacker — matching the in-scope impact of "corruption of PRC20 or native asset accounting" and unauthorized value extraction from protocol/user-controlled funds, entirely reachable by an ordinary unprivileged user submitting default transactions/deposits (no validator or governance privilege required to execute the sandwich itself).

### Likelihood Explanation
Likelihood depends on available liquidity depth of the WPC/PRC20 pool(s) used internally and MEV/mempool visibility of the finalizing vote transactions, similar to the original Notional report where the auditors and maintainers agreed the finding was valid but debated severity due to cost-of-manipulation vs. gain. Here the attack is somewhat easier than the Notional case because the "protection" (`minPCOut`) is derived from the exact same manipulated quote rather than an independent parameter — so any manipulation that succeeds automatically evades the check, unlike Notional's scenario, which still required no direct trade validation. This makes exploitation feasible whenever pool liquidity is thin relative to the attacker's capital, which is realistic for a newly bootstrapped chain's internal AMM pools.

### Recommendation
Do not derive the slippage bound from the same spot quote used to execute the trade. Use a TWAP (time-weighted average price) over a window prior to execution, or an externally supplied/validated reference price with a governance-set maximum deviation, to compute `minPCOut` independently of the instantaneous pool state read immediately before the swap. Alternatively, cap the fraction of pool liquidity that can be swapped in a single autoswap call and/or add circuit breakers when observed spot price deviates significantly from a longer-window average.

### Proof of Concept
1. Push Chain operates an internal Uniswap V3 pool between a PRC20 gas token and WPC, used by `GetSwapQuote`/`CallPRC20DepositAutoSwap` [8](#0-7) .
2. Attacker observes a pending `MsgVoteInbound` transaction from the last required validator that will finalize quorum for a `GAS` or `GAS_AND_PAYLOAD` inbound (public mempool/consensus visibility).
3. Attacker submits a large swap into the pool ahead of that vote transaction in the same block, moving the spot price of WPC relative to the gas PRC20 unfavorably for the incoming deposit.
4. The finalizing vote transaction executes `ExecuteInboundGas`, which calls `GetSwapQuote` against the now-manipulated pool and computes `minPCOut = quote*95/100` from that manipulated quote [9](#0-8) ; the autoswap proceeds because the "check" is satisfied by construction.
5. Attacker reverses their manipulation trade in the same block, capturing the value difference extracted from the victim depositor/protocol.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
