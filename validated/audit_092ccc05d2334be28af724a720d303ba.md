## Title
Spot-price Uniswap V3 quote used as slippage bound for protocol-executed autoswaps allows unprivileged sandwich attacks that reduce a depositor's PC payout - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The MuteBond report's root cause is that a value used to bound/execute a user's transaction (`maxPurchaseAmount()`) is read from **live, attacker-influenceable state at execution time** instead of a value fixed at intent-formation time, letting an unprivileged actor worsen the price/amount the victim actually receives. The same pattern exists in Push Chain's GAS/GAS_AND_PAYLOAD/refund autoswap paths: `k.GetSwapQuote()` [1](#0-0)  pulls a **spot** Uniswap V3 `quoteExactInputSingle` price at the exact moment the deposit-executing keeper call runs, then derives `minPCOut = quote * 95 / 100` and immediately performs the swap in the same call [2](#0-1) . Because the quote is a spot AMM price rather than a value bound to what the source-chain depositor actually intended/locked, and the "protection" is only a flat 5% band around that same manipulable price, an unprivileged actor can sandwich the swap and steal part of the depositor's payout.

### Finding Description
Three code paths compute `minPCOut` from a live spot quote and then execute a real swap against Push Chain's embedded Uniswap V3 pool in the very next call:

1. `ExecuteInboundGas` — GAS inbound route: fetches `quote` via `GetSwapQuote`, computes `minPCOut = quote*95/100`, then calls `CallPRC20DepositAutoSwap` [3](#0-2) .
2. `gasAndPayloadDepositAutoSwap` — GAS_AND_PAYLOAD route: same pattern [4](#0-3) .
3. `applyGasRefund` — outbound gas-fee-refund route: same pattern, refunding excess destination-chain gas back to the user via swap [5](#0-4) .

`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `commit=false` against the current pool state [1](#0-0) , i.e. it reads whatever the pool's price is *at the instant the finalizing vote transaction is processed*. This is the direct analog of `maxPurchaseAmount()` in the MuteBond report: a value substituted for what the user actually specified/intended, computed from mutable on-chain state that any unprivileged party can move immediately beforehand.

The execution trigger (`ExecuteInboundGas`/`ExecuteInboundGasAndPayload`/`applyGasRefund`) fires deterministically the moment a `MsgVoteInbound`/`MsgVoteOutbound` quorum-finalizing transaction is included in a block — that transaction (and its future block inclusion) is publicly visible in the mempool before it lands, exactly like the "till the tx is included in the blockchain" window described in the original report. An unprivileged trader can:
1. Observe the pending finalizing vote transaction (public mempool/gasless tx broadcast) for a large GAS/GAS_AND_PAYLOAD inbound or gas refund.
2. Front-run it with a swap on the PRC20↔WPC pool that pushes the spot price against the upcoming autoswap direction.
3. Let the finalizing transaction execute: `GetSwapQuote` now returns the manipulated (low) price, `minPCOut` is only 95% of that already-bad price, so the swap still "succeeds" but pays out far less PC than fair value to the recipient UEA/refund recipient.
4. Back-run to restore the price and pocket the difference extracted from the victim's deposit/refund.

The 5% band only bounds slippage *relative to the manipulated spot price at execution time*, not relative to any price known/committed at deposit-intent time (i.e., when the user made their source-chain deposit) — this is structurally identical to the MuteBond flaw where `max_buy` used whatever `maxPurchaseAmount()` happened to be at inclusion time instead of validating it against the state the user actually observed when forming their transaction.

### Impact Explanation
This falls under "corruption of ... native asset accounting" and effectively "unauthorized ... refund accounting" / value extraction from protocol-executed swaps reachable via ordinary unprivileged trading. A depositor bridging GAS/GAS_AND_PAYLOAD inbounds, or a user receiving an unused-gas refund, can receive materially less native PC than the fair-value of their deposited/refunded PRC20 amount, with the difference captured by an unprivileged sandwiching trader. This is a direct, repeatable fund-loss vector against ordinary users with no privileged access required, matching "reduced payout for the buyer" (Impact B) from the original report.

### Likelihood Explanation
Likelihood is moderate-to-high on any deployment where the relevant PRC20/WPC Uniswap V3 pool has real, tradable liquidity that isn't extremely deep relative to typical inbound/refund sizes: gasless `MsgVoteInbound`/`MsgVoteOutbound` finalizing transactions are broadcast and visible pre-inclusion, the swap trigger is fully deterministic, and sandwiching AMM spot-price-derived slippage bounds is a well-known, low-cost MEV technique requiring no privileged role — only capital to trade against the pool.

### Recommendation
Do not derive the slippage floor purely from a spot quote taken atomically before the swap. Options:
- Use a TWAP-based reference price (or a price bound set independently of the same-block spot state) instead of `quoteExactInputSingle`'s instantaneous quote for computing `minPCOut`.
- Cap the maximum single-block price impact the module will accept, and/or widen protections so a manipulated spot price cannot itself become the baseline for the "protection" band.
- Consider routing protocol-originated autoswaps through a mechanism resistant to same-block sandwiching (e.g., commit-reveal style execution, off-chain fair-price attestation from Universal Validators, or capping amounts routed through thin pools with pre-configured safe price bounds rather than a fixed percentage of the live quote).

### Proof of Concept
1. Attacker monitors the Push Chain mempool for a `MsgVoteInbound` (or `MsgVoteOutbound`) transaction that will finalize quorum for a large GAS/GAS_AND_PAYLOAD inbound (or trigger `applyGasRefund`) for a token/pool with limited liquidity.
2. Attacker submits (with higher gas/priority) a swap on the same PRC20↔WPC Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`, moving the spot price so that a subsequent `quoteExactInputSingle` for the victim's token/amount returns a depressed `amountOut`.
3. The finalizing vote transaction lands; `k.GetSwapQuote(...)` in `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:135`) returns the manipulated quote; `minPCOut` is computed as 95% of that manipulated value [6](#0-5) ; `CallPRC20DepositAutoSwap` executes and succeeds because it only needs to clear the already-depressed `minPCOut` floor.
4. Attacker reverses their initial trade, realizing profit equal to the value extracted from the victim's deposit/refund, which now received PC well below fair market value.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
