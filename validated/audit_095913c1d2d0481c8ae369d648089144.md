This is a real vulnerability. `depositPRC20` requires `GetTokenConfig(ctx, sourceChain, assetAddr)` to succeed for the mint to happen [1](#0-0) , but a forged event's `Token`/`bridge_token` field decodes to an attacker-controlled Solana pubkey string that could be crafted to match any **already-registered** token config on that chain (token registration is public data, not secret), so this lookup is not a meaningful barrier — it only stops attackers from inventing a brand-new token address, not from spoofing sender/recipient/amount/token using a legitimate registered token.

### Title
Forged Solana log lines with a valid discriminator are accepted as gateway events without verifying CPI origin - (File: `universalClient/chains/svm/event_parser.go`)

### Summary
`EventListener.determineEventType` and `parseSendFundsEvent`/`parseOutboundObservationEvent` classify and parse a Solana transaction log purely by string-matching `"Program data: "` and comparing the first 8 decoded bytes against a discriminator map [2](#0-1) . Neither this function nor `parseSendFundsEvent` [3](#0-2)  checks that the log line was emitted inside a CPI/invoke frame belonging to the actual configured gateway program ID.

### Finding Description
`processSlotRange` fetches signatures via `GetSignaturesForAddress(gatewayAddr)` [4](#0-3) . Solana's `getSignaturesForAddress` RPC indexes any transaction that references an address as *any* account key in the message — not only transactions that invoke it as a program. An attacker can craft a transaction that lists the real gateway program ID as a harmless/unused account reference while actually invoking their own attacker-owned program.

`processSignatureBatch` then fetches the full transaction and iterates flatly over `tx.Meta.LogMessages` [5](#0-4) , without tracking the Solana log "invoke stack" (`Program <id> invoke [n]` / `Program <id> success`) to bind a given `Program data:` line to the program that actually emitted it. The attacker's own program can emit `msg!("Program data: {base64}")` (or use Anchor's `emit!` machinery) with the first 8 bytes crafted to match the public `send_funds` discriminator — Anchor discriminators (`sha256("event:<Name>")[:8]` or similar) are deterministic and public, not secret.

Because `parseSendFundsEvent` and `decodeUniversalTxEvent` [6](#0-5)  then decode arbitrary attacker-supplied bytes into `sender`, `recipient`, `bridge_token`, `bridge_amount`, `revert_recipient` with no cross-check against the real gateway program's state (e.g., no verification the vault actually received funds, no signature/authority check), the stored `store.Event` — and ultimately the `Inbound` message an honest UV submits via `VoteInbound` — is entirely attacker-controlled data.

Critically, this is **not** a malicious-validator scenario: since the forged data is genuinely on-chain (in a real Solana transaction, just emitted by a non-gateway program), every honest UV running this identical listener code independently observes the same fake log and derives the same `Inbound` payload, so they converge on quorum and finalize the ballot legitimately per `VoteInbound`/`VoteOnInboundBallot` [7](#0-6) . The only missing control is authenticating that the log came from the real gateway program's CPI.

### Impact Explanation
Once the forged inbound reaches quorum, `ExecuteInboundFundsAndPayload`/`depositPRC20` mints PRC20 to an attacker-chosen recipient [8](#0-7) , using attacker-chosen amount and (if it matches an existing registered token's address string) attacker-chosen token. This is unauthorized minting of value not backed by any real deposit into the Solana gateway/vault — a direct value-creation/theft vector against protocol solvency, and it also corrupts `RevertFundRecipient`/`revert_recipient` used for future revert/refund routing.

### Likelihood Explanation
Requires only submitting an ordinary, unprivileged Solana transaction that (a) references the real gateway program's address as an account key (to pass the `GetSignaturesForAddress` filter) and (b) invokes an attacker-deployed program that logs a `Program data:` line with the correct 8-byte discriminator prefix and Borsh-encoded payload matching the expected `send_funds` layout. No validator, relayer, or TSS compromise needed.

### Recommendation
When parsing SVM logs, track the "Program X invoke [depth]" / "Program X success" stack per transaction and only accept `Program data:` lines that occur within an invoke frame whose program ID equals the configured `gatewayAddress` (top-level or via CPI actually rooted at the gateway program). Reject any log line whose enclosing program frame cannot be attributed to the real gateway program ID.

### Proof of Concept
1. Construct a `solanarpc.GetTransactionResult` whose `Meta.LogMessages` includes:
   - `"Program <attackerProgramID> invoke [1]"`
   - `"Program data: <base64(discriminator_send_funds || attacker_sender || attacker_recipient || attacker_token || attacker_amount || ...)>"`
   - `"Program <attackerProgramID> success"`
   and whose transaction signature is returned by a mocked `GetSignaturesForAddress` for the real `gatewayAddress` (simulating an account-key reference, not an invocation).
2. Feed it through `EventListener.processSignatureBatch` → `determineEventType` → `ParseEvent`/`parseSendFundsEvent`.
3. Observe that a `store.Event` of type `EventTypeInbound` with attacker-controlled `Sender`/`Recipient`/`Token`/`Amount` is produced and stored via `InsertEventIfNotExists`, identical to what a real gateway-emitted event would produce — confirming no verification that the log originated from a CPI made by the real gateway program.

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

func decodeUniversalTxEvent(data []byte, logger zerolog.Logger) (*common.UniversalTx, error) {
	if len(data) < 120 {
		logger.Warn().
			Int("data_len", len(data)).
			Msg("data might be too short for complete TxWithFunds event")
	}

	offset := 8
	payload := &common.UniversalTx{}

	// Parse sender (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for sender")
	}
	sender := solana.PublicKey(data[offset : offset+32])
	// Convert sender to hex format
	senderHex, err := base58ToHex(sender.String())
	if err != nil {
		logger.Warn().Err(err).Msg("failed to convert sender to hex, using base58")
		payload.Sender = sender.String()
	} else {
		payload.Sender = senderHex
	}
	offset += 32

	// Parse recipient (20 bytes - byte20 format)
	if len(data) < offset+20 {
		return nil, fmt.Errorf("not enough data for recipient")
	}
	// Convert 20 bytes to hex string (0x + 40 hex chars)
	recipientBytes := data[offset : offset+20]
	payload.Recipient = "0x" + hex.EncodeToString(recipientBytes)
	offset += 20

	// Parse bridge_token (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for bridge_token")
	}
	bridgeToken := solana.PublicKey(data[offset : offset+32])
	payload.Token = bridgeToken.String()
	offset += 32

	// Parse bridge_amount (8 bytes)
	if len(data) < offset+8 {
		return nil, fmt.Errorf("not enough data for bridge_amount")
	}
	bridgeAmount := binary.LittleEndian.Uint64(data[offset : offset+8])
	payload.Amount = fmt.Sprintf("%d", bridgeAmount)
	offset += 8
