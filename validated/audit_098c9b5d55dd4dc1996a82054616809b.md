**Analysis:** The `ValidatorPerformances` struct in `types/src/validator_performances.rs` is a plain serializable data structure with no verification logic itself [1](#0-0) . Any resource value, including this one, is only ever accepted into a restored state tree via the Jellyfish Merkle restore path, which cryptographically binds leaf values to the target root hash before any write occurs.

Specifically, `JellyfishMerkleRestore::verify_chunk` hashes each incoming `(key, value)` pair, appends it to the accumulated leaves, and calls `self.verify(proof)` against the expected root hash for the *target version* before `commit_chunk` writes anything to storage [2](#0-1) . The `StateSnapshotRestore::add_chunk` wrapper enforces the same sequencing — verify proof, then write to `state_kv_db`, then commit to `state_merkle_db` — so nothing lands in storage without passing proof verification first [3](#0-2) . At a higher level, `StateSnapshotRestoreController::run_impl` also independently verifies the `TransactionInfoWithProof` against the `LedgerInfoWithSignatures` and checks that the manifest's `root_hash` matches the state-checkpoint hash before any receiver is even constructed with that root [4](#0-3) .

Because the leaf hash is a function of the actual serialized `ValidatorPerformances` bytes, substituting an epoch-N value into a chunk claimed to belong to epoch N+1 changes the computed leaf hash. This altered hash will not reconstruct the accumulator/Merkle path to the epoch N+1 root that was already authenticated via the `LedgerInfoWithSignatures`/`TransactionInfoWithProof` chain, so `verify_chunk`/`verify` will reject the chunk deterministically — this is the intended security property of Merkle/sparse-merkle range proofs, not a bug. There is no code path here that accepts a mismatched leaf/root pairing; the restore logic is a standard cryptographic binding between root hash and leaf content, and the described splice does not correspond to any actual bypass in the reviewed logic.

    /// Verifies a chunk and stages frozen nodes in memory; call [`Self::commit_chunk`] to
    /// flush. On error, in-memory state is partially updated — abort the restore rather
    /// than calling again.
    pub fn verify_chunk(
        &mut self,
        mut chunk: Vec<(&K, HashValue)>,
        proof: SparseMerkleRangeProof,
    ) -> Result<()> {
        if self.finished {
            info!("State snapshot restore already finished, ignoring entire chunk.");
            return Ok(());
        }

        if let Some(prev_leaf) = &self.previous_leaf {
            let skip_until = chunk
                .iter()
                .find_position(|(key, _hash)| key.hash() > *prev_leaf.account_key());
            chunk = match skip_until {
                None => {
                    info!("Skipping entire chunk.");
                    return Ok(());
                },
                Some((0, _)) => chunk,
                Some((num_to_skip, next_leaf)) => {
                    info!(
                        num_to_skip = num_to_skip,
                        next_leaf = next_leaf,
                        "Skipping leaves."
                    );
                    chunk.split_off(num_to_skip)
                },
            }
        };
        if chunk.is_empty() {
            return Ok(());
        }

        for (key, value_hash) in chunk {
            let hashed_key = key.hash();
            if let Some(ref prev_leaf) = self.previous_leaf {
                ensure!(
                    &hashed_key > prev_leaf.account_key(),
                    "State keys must come in increasing order.",
                )
            }
            self.previous_leaf.replace(LeafNode::new(
                hashed_key,
                value_hash,
                (key.clone(), self.version),
            ));
            self.add_one(key, value_hash);
            self.num_keys_received += 1;
        }

        // Verify what we have added so far is all correct.
        self.verify(proof)?;
        Ok(())
