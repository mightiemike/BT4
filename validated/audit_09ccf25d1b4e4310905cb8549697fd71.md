### Title
Witness reward permanently lost when a cycle's recorded vote-count is zero at Vi accumulation - (File: `chainbase/src/main/java/org/tron/core/store/DelegationStore.java`)

### Summary
`MortgageService.payReward()` credits block/transaction-fee rewards into `DelegationStore` keyed only by `(cycle, witnessAddress)`, independent of that witness's vote count for the cycle. Reward attribution to voters is performed later via a per-share accumulator (`Vi`, analogous to `rewardPerToken` in `StakingRewards.sol`). When the recorded vote count for that cycle is `0`, `DelegationStore.accumulateWitnessVi()` simply forwards the previous `Vi` value and drops the reward — exactly the "reward earned while total stake is zero is never rolled forward" pattern described in the external report.

### Finding Description
Rewards are paid unconditionally into the per-cycle bucket: [1](#0-0) 

They are later converted into a per-vote index (`Vi`), which only increases when both `reward` and `voteCount` are non-zero for that cycle: [2](#0-1) 

This accumulation is invoked once per cycle for every witness during maintenance, using the vote-count value that was snapshotted for that witness at the *start* of the cycle: [3](#0-2) 

Because per-block rewards (`payBlockReward`/`payTransactionFeeReward`) are credited to `delegationStore.addReward(cycle, witnessAddress, value)` throughout the cycle regardless of the vote-count value recorded for that same cycle, any reward accrued for a cycle in which the witness's stored vote count happens to be `0` (e.g., right after a witness enters the active/standby set before a full cycle's vote snapshot has been recorded, or any other timing/edge condition producing a zero-vote cycle record) is silently discarded: `accumulateWitnessVi` takes the "forward previous Vi" branch, so the `deltaVi` for that reward is never computed and never added to any future cycle's `Vi`. The exact same "skip when totalVote==0" logic also exists in the legacy (pre-Vi) reward path: [4](#0-3) 

In both the old and new reward algorithms, once a cycle's reward is dropped because voteCount was 0 at accumulation time, there is no mechanism anywhere in `DelegationStore`, `MortgageService`, `VoteRewardUtil`, or `RewardViCalService` that reclaims or re-injects that specific reward amount into a later cycle's `Vi`/reward pool — it is definitionally excluded from every future `computeReward`/`getNewRewardAlgorithmReward` calculation, which only ever look at `deltaVi = endVi - beginVi`.

### Impact Explanation
This mirrors the disputed-but-accepted judgment in the source report: value is "leaked" from the protocol's reward-distribution accounting — TRX that was credited to a witness's reward bucket for a given cycle becomes permanently unattributable to any voter once that cycle's snapshot vote count is zero, with no sweep or rollover path. This is an accounting-corruption bug in the DPoS reward system (`org.tron.consensus.dpos` / `org.tron.core.store.DelegationStore`), which underlies every witness/voter reward query and withdrawal (`GetRewardServlet`, `withdrawbalance` actuator paths, and the TVM `VoteRewardUtil` precompiled behavior).

### Likelihood Explanation
Likelihood is moderate-to-low: it requires a cycle boundary where a witness's `getWitnessVote(cycle, address)` value is `0` at the moment `accumulateWitnessVi` runs, while a non-zero reward was already recorded for that same `(cycle, address)` key. This can plausibly occur for freshly-created or freshly re-activated witnesses, or under any timing skew between per-block reward crediting and the once-per-cycle vote-count snapshot taken in `MaintenanceManager.doMaintenance()`. It is a protocol-level (non-privileged, non-malicious-actor) condition reachable purely through normal witness/voting activity, not requiring any special access.

### Recommendation
When `accumulateWitnessVi` (and the legacy `computeReward`) encounters `reward > 0` with `voteCount == 0` for a cycle, do not silently drop the reward. Instead, carry the un-attributable amount forward — e.g., re-credit it into the next cycle's reward bucket via `DelegationStore.addReward(cycle + 1, address, reward)` before that cycle's `Vi` is computed — so it is eventually distributed once the witness has non-zero votes, rather than being permanently excluded from all `Vi` deltas.

### Proof of Concept
1. A witness is paid a block/transaction-fee reward at cycle `N` via `MortgageService.payBlockReward`/`payTransactionFeeReward`, which calls `payReward` and unconditionally does `delegationStore.addReward(N, witnessAddress, value)`.
2. At the maintenance boundary for cycle `N`, `MaintenanceManager.doMaintenance()` calls `delegationStore.accumulateWitnessVi(N, witness, witness.getVoteCount())` with a `voteCount` of `0` for that witness at that snapshot.
3. `DelegationStore.accumulateWitnessVi` takes the `voteCount == 0` branch and simply forwards `preVi` — the `reward` value added in step 1 is never converted into `deltaVi`.
4. All subsequent voter reward queries (`MortgageService.computeReward`, `VoteRewardUtil.computeReward`) compute rewards strictly from `deltaVi = endVi - beginVi` across cycles; since `Vi` never changed to reflect the step-1 reward, no voter can ever claim it, and no later `addReward`/accumulation step re-injects it.

```java
  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }
```

```java
  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }
```
