### Title
Chain-fork signature replay in the `ValidateMultiSign` precompile due to missing chain/domain binding - (`actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

### Summary
The `ValidateMultiSign` TVM precompiled contract lets any smart contract verify off-chain signatures against an account's `Permission` weights. The hash that signers actually sign is built purely from the target `address`, `permissionId`, and caller-supplied `data` — it never incorporates any chain-specific domain separator (TRON's closest analog to Ethereum's `chainId` is the genesis block hash returned by the `CHAINID` opcode, itself immutable across a post-genesis hard fork) or an expiration/nonce. This mirrors exactly the LooksRareExchange bug class: a signature meant to authorize an action is verifiable indefinitely and identically on any chain that shares the same account/permission state, so it can be replayed across chain forks (or across any two deployments sharing that state) to re-trigger the authorized action.

### Finding Description
`ValidateMultiSign.execute` computes the signed hash as: [1](#0-0) 

```
byte[] address = words[0].toTronAddress();
int permissionId = words[1].intValueSafe();
byte[] data = words[2].getData();
byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
byte[] hash = Sha256Hash.hash(..., combine);
```

No chain identifier, verifying-contract address, or expiration is folded into `combine`. Signatures are then ECDSA-recovered and weighed against the account's `Permission` via `TransactionCapsule.getWeight`: [2](#0-1) 

The precompile is invoked from arbitrary TVM contract code (e.g. custodial/multisig withdrawal contracts implemented in Solidity on TRON) triggered by an ordinary `TriggerSmartContract` transaction — a fully unprivileged, externally reachable code path.

Contrast this with TRON's genuine native replay protection: ordinary transaction signatures are bound to a TAPOS reference block hash and a short expiration window baked into the signed raw data itself, as seen in `TransactionCapsule.validateSignature`/`checkWeight`, which hash the full `raw_data` (including `ref_block_hash` and `expiration`): [3](#0-2) [4](#0-3) 

That mechanism naturally invalidates old signatures after ~60 seconds and after the reference block ages out, giving native transactions fork-replay resistance that `ValidateMultiSign` deliberately lacks. TRON's own chain-id analog for TVM contracts is the `CHAINID` opcode, which just returns the genesis block hash and is therefore static across a post-genesis hard fork exactly like Ethereum's `chainid`: [5](#0-4) [6](#0-5) 

`ValidateMultiSign` does not even use this value, so contracts relying on it for off-chain multisig authorization (withdrawal approvals, bridge releases, threshold-signed operations) get zero fork/domain isolation.

### Impact Explanation
Any contract that uses `ValidateMultiSign` (address `0x0000...67` style precompile call) to gate a state-changing action — e.g. releasing funds once N-of-M permission-key holders sign off — can have that same signed authorization replayed:
- On a hard-forked chain that shares genesis and the same account/permission state (both chains recognize the same signers and weights).
- Indefinitely, since there is no expiration/nonce field in the signed payload, unlike native TRON transactions.

This allows an attacker (or the acting party) to reuse a single signed approval to drain/duplicate the authorized action on both branches of a fork, causing asset/accounting corruption in any contract relying on this precompile for authorization, which is a concrete unauthorized-operation/asset-corruption impact.

### Likelihood Explanation
Reaching the vulnerable code only requires deploying/using a contract that calls the `ValidateMultiSign` precompile (a normal, documented TVM feature for multisig/permission verification) and sending a `TriggerSmartContract` transaction — fully unprivileged and externally reachable. The precondition (a hard fork sharing genesis state) is an environmental circumstance rather than an attacker capability, matching the "Medium/analog" nature of the original report; the root cause (missing chain-domain binding in the signed hash) is unconditionally present in the code today.

### Recommendation
Include a chain-specific and contract-specific domain separator in the hash signed for `ValidateMultiSign` — e.g. fold in the genesis block hash (TRON's `CHAINID` equivalent) and/or the calling contract address, plus an expiration or nonce, analogous to EIP-712's `chainId`/`verifyingContract` fields. Document for TVM developers that `ValidateMultiSign`-based authorization is not chain/fork-bound and encourage callers to include their own chain id and expiry in `data`.

### Proof of Concept
1. Deploy a contract `C` on TRON mainnet that calls the `ValidateMultiSign` precompile to check N-of-M signatures over `(address, permissionId, data)` before releasing funds, per `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java:1052-1119`.
2. Off-chain, the required signers sign `sha256(address || permissionId || data)` once to authorize a withdrawal of amount `X`.
3. Submit the authorization via `TriggerSmartContract` on mainnet — `C` calls `ValidateMultiSign`, weight threshold is met, funds released.
4. Ethereum-style hard fork occurs: TRON network forks into chain A and chain B sharing identical genesis/account/permission state at the fork block (both retain the same `CHAINID`/genesis hash per `actuator/src/main/java/org/tron/core/vm/OperationActions.java:536-541`).
5. On chain B, replay the exact same signature bytes and `data` from step 2 in a new `TriggerSmartContract` call to `C` (present on chain B too, e.g. via identical deployment/state). `ValidateMultiSign` recomputes the same hash (no chain binding), recovers the same signer addresses, meets the threshold, and authorizes the withdrawal again — duplicating the payout across both forks.

  public static long checkWeight(Permission permission, List<ByteString> sigs, byte[] hash,
      List<ByteString> approveList)
      throws SignatureException, PermissionException, SignatureFormatException {
    long currentWeight = 0;
    if (sigs.size() > permission.getKeysCount()) {
      throw new PermissionException(
          "Signature count is " + (sigs.size()) + " more than key counts of permission : "
              + permission.getKeysCount());
    }
    HashMap addMap = new HashMap();
    for (ByteString sig : sigs) {
      if (sig.size() < 65) {
        throw new SignatureFormatException(
            "Signature size is " + sig.size());
      }
      String base64 = TransactionCapsule.getBase64FromByteString(sig);
      byte[] address = SignUtils
          .signatureToAddress(hash, base64, CommonParameter.getInstance().isECKeyCryptoEngine());
      long weight = getWeight(permission, address);
      if (weight == 0) {
        throw new PermissionException(
            ByteArray.toHexString(hash) + " is signed by " + encode58Check(address)
                + " but it is not contained of permission.");
      }
      if (ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)) {
        base64 = encode58Check(address);
      }
      if (addMap.containsKey(base64)) {
        throw new PermissionException(encode58Check(address) + " has signed twice!");
      }
      addMap.put(base64, weight);
      if (approveList != null) {
        approveList.add(ByteString.copyFrom(address)); //out put approve list.
      }
      currentWeight += weight;
    }
    return currentWeight;
  }

  public static boolean validateSignature(Transaction transaction,
      byte[] hash, AccountStore accountStore, DynamicPropertiesStore dynamicPropertiesStore)
      throws PermissionException, SignatureException, SignatureFormatException {
    Transaction.Contract contract = transaction.getRawData().getContractList().get(0);
    int permissionId = contract.getPermissionId();
    byte[] owner = getOwner(contract);
    AccountCapsule account = accountStore.get(owner);
    Permission permission = null;
    if (account == null) {
      if (permissionId == 0) {
        permission = AccountCapsule.getDefaultPermission(ByteString.copyFrom(owner));
      }
      if (permissionId == 2) {
        permission = AccountCapsule
            .createDefaultActivePermission(ByteString.copyFrom(owner), dynamicPropertiesStore);
      }
    } else {
      permission = account.getPermissionById(permissionId);
    }
    if (permission == null) {
      throw new PermissionException("permission isn't exit");
    }
    checkPermission(permissionId, permission, contract);
    long weight = checkWeight(permission, transaction.getSignatureList(), hash, null);
    if (weight >= permission.getThreshold()) {
      return true;
    }
    return false;
  }
