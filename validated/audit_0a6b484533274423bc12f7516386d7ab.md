### Title
Panic (Denial of Service) in `l1_handler_message_hash` on Empty Calldata - (File: `crates/starknet_api/src/hash.rs`)

### Summary
`L1HandlerTransaction::calc_msg_hash` calls `l1_handler_message_hash`, which unwraps `calldata.0.split_first()` with `.expect("Invalid calldata, expected at least from_address")`. `Calldata`/`L1HandlerTransaction` have no non-empty invariant enforced at the type level and derive `Deserialize`, so a transaction with empty calldata is constructible from untrusted input, and calling this function on it panics the process instead of returning an error.

### Finding Description
`l1_handler_message_hash` unconditionally destructures the calldata to extract `from_address` via `.split_first().expect(...)`: [1](#0-0) . This is invoked from `L1HandlerTransaction::calc_msg_hash` [2](#0-1) .

The codebase itself documents that this data structure has no non-empty invariant: a test in `starknet_api` explicitly notes "`Calldata` has no non-empty invariant and `L1HandlerTransaction` derives `Deserialize`, so an empty calldata is constructible" and was added to fix a related underflow bug in `payload_size()` [3](#0-2) . That fix hardened `payload_size()` against empty calldata, but `l1_handler_message_hash`/`calc_msg_hash` was not similarly hardened and still panics via `.expect()`.

`calc_msg_hash` is called from multiple production code paths, including `apollo_l1_events` (`l1_events_provider.rs`, `l1_scraper.rs`) and the RPC server (`apollo_rpc/src/v0_8/api/api_impl.rs`), based on grep matches for `calc_msg_hash` in those files. I was not able to fully trace, within the remaining tool budget, the exact untrusted-input path in `api_impl.rs` that feeds an attacker-controlled `L1HandlerTransaction` (e.g., an L1 handler transaction with empty calldata reconstructed from state/DB or from a JSON-RPC request) directly into `calc_msg_hash`. This is the key remaining uncertainty.

### Impact Explanation
If reachable with attacker-influenced empty-calldata `L1HandlerTransaction` data (e.g., via a JSON-RPC endpoint that accepts/reconstructs transaction objects, or via deserialization of state data derived from such an object), calling `calc_msg_hash` panics the calling thread. Depending on whether this runs inside a `catch_unwind` boundary (like the blockifier's worker pool does for execution threads via `AbortIfPanic`/`catch_unwind` in `crates/blockifier/src/concurrency/worker_pool.rs`) or in an unprotected async task/RPC handler thread, this could crash the RPC server process or a sequencer component, denying service to legitimate requests — directly analogous to the hapi CORS header panic causing process-level DoS.

### Likelihood Explanation
Medium-to-High if the RPC/API call path can be driven with an empty-calldata `L1HandlerTransaction` from external input; the type system does not prevent constructing such a value (as explicitly documented by the codebase's own regression test), and `Deserialize` is derived without a non-empty validator. However, I could not confirm within this session whether the specific `api_impl.rs` call sites are reachable with fully attacker-controlled empty calldata, or whether calldata is always guaranteed non-empty by the time it reaches those call sites (e.g., due to upstream validation when L1 handler transactions are scraped from real Ethereum logs, which always prepend a `from_address`).

### Recommendation
Harden `l1_handler_message_hash` to return a `Result`/handle the empty-calldata case explicitly instead of using `.expect()`, mirroring the fix already applied to `payload_size()`. Additionally, verify whether `apollo_rpc`'s call sites for `calc_msg_hash` can receive attacker-supplied `L1HandlerTransaction` objects with empty calldata (as opposed to only transactions that have already passed through the L1 scraper stack, which always prepends a `from_address`), and add explicit calldata length validation at the deserialization boundary (`RpcL1HandlerTransaction`/`Calldata`) if so.

```rust
pub fn l1_handler_message_hash(
    contract_address: &ContractAddress,
    nonce: Nonce,
    entry_point_selector: &EntryPointSelector,
    calldata: &Calldata,
) -> L1L2MsgHash {
    let (from_address, payload) =
        calldata.0.split_first().expect("Invalid calldata, expected at least from_address");

    let mut encoded = Vec::new();
    encoded.extend(from_address.to_bytes_be());
    encoded.extend(contract_address.0.key().to_bytes_be());
    encoded.extend(nonce.to_bytes_be());
    encoded.extend(entry_point_selector.0.to_bytes_be());

    let payload_length_as_felt =
        Felt::from(u64::try_from(payload.len()).expect("usize should fit in u64"));
    encoded.extend(payload_length_as_felt.to_bytes_be());
```
