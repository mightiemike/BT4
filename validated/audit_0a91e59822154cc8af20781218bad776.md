### Title
Contract address validation permits deployment onto OS-reserved addresses (Alias/Reserved contract) - ([File: crates/starknet_api/src/core.rs])

### Summary
`ContractAddress::validate` in `starknet_api` — the check used to bound valid L2 contract addresses during transaction/deploy processing — only excludes address `0x1` (`BLOCK_HASH_TABLE_ADDRESS`). It does not exclude `0x2` (`ALIAS_CONTRACT_ADDRESS`) or `0x3` (`RESERVED_CONTRACT_ADDRESS`), even though the Starknet OS Cairo program explicitly forbids constructor execution at any of these three reserved addresses. [1](#0-0) 

### Finding Description
The OS reserved contract addresses `BLOCK_HASH_CONTRACT_ADDRESS` (0x1), `ALIAS_CONTRACT_ADDRESS` (0x2), and `RESERVED_CONTRACT_ADDRESS` (0x3) are treated as protected storage areas by the protocol: the block-hash-mapping mechanism and the stateful-compression alias mechanism write directly into the storage of addresses 0x1 and 0x2 via privileged, non-syscall code paths (`allocate_aliases_in_storage`/`AliasUpdater::set_alias_in_storage`, `read_block_hash_from_storage`). [2](#0-1) [3](#0-2) 

The Starknet OS Cairo code that performs contract deployment (`deploy_contract`) contains an explicit guard rejecting deployment to any of `BLOCK_HASH_CONTRACT_ADDRESS`, `ALIAS_CONTRACT_ADDRESS`, or `RESERVED_CONTRACT_ADDRESS`: [4](#0-3) 

However, the generic address-range validator used elsewhere in the sequencer/gateway pipeline for contract addresses, `ContractAddress::validate`, only rejects `value <= BLOCK_HASH_TABLE_ADDRESS` (i.e. only excludes `0x0` and `0x1`) and accepts any value up to `L2_ADDRESS_UPPER_BOUND`, meaning `0x2` and `0x3` pass this check: [5](#0-4) 

This is structurally analogous to the reported bug class: a protected/reserved storage area (here, the OS-managed alias contract at `0x2`, which is the equivalent of RocketStorage's protected withdrawal-address mapping) is guarded by an access-control check in one code path (the Cairo OS deploy guard) but not consistently enforced in a sibling code path used earlier in the pipeline (the Rust-side address validator). If any Rust-side flow relies on `ContractAddress::validate` as its sole gate before accepting/executing a deploy (rather than an independent, duplicated reserved-address check mirroring the Cairo assertion), a discrepancy between what the sequencer's blockifier considers valid and what the OS accepts is possible.

### Impact Explanation
If a transaction could deploy a contract to `0x2` in the blockifier execution path (bypassing an equivalent Rust-side reserved-address guard because `ContractAddress::validate` doesn't check it), the resulting state diff would have a user-controlled contract class in the same storage domain (`contract_address = 0x2`) that the protocol's stateful-compression subsystem treats as the alias table. Subsequent alias allocation/replacement (`allocate_aliases_in_storage`, `AliasCompressor`) reads and writes into that same address's storage assuming it holds only alias-counter/alias-mapping data. This is the same class of "shared/protected storage area writable by an unprivileged party" issue as the original RocketStorage report, and could lead to either: (a) OS re-execution/proving failure for a block the sequencer already built and committed (since the Cairo OS `deploy_contract` explicitly asserts against these addresses), producing an honest-node/prover divergence and halting block confirmation, or (b) corruption of the stateful-compression alias mapping, affecting state-diff compression correctness for the whole block.

### Likelihood Explanation
This requires confirming there is no separate, always-executed Rust-side reserved-address check duplicating the Cairo OS assertion at the actual deploy syscall execution site in `blockifier` (I was not able to fully inspect `crates/blockifier/src/execution/syscalls/deploy.rs`'s address-computation/validation logic within the available iterations, nor `calculate_contract_address` in `starknet_api/src/core.rs`, before running out of tool calls). If such a duplicate check exists and is applied before/at deploy execution, this finding reduces to a benign inconsistency in a general-purpose validator rather than an exploitable gap. This uncertainty should be resolved by directly reading `crates/starknet_api/src/core.rs` (`calculate_contract_address`) and the deploy syscall execution implementation in `crates/blockifier/src/execution/syscalls/`.

### Recommendation
Regardless of whether an independent guard currently exists, align `ContractAddress::validate` (and any other Rust-side address acceptance checks) with the Cairo OS's reserved-address list by excluding `0x1`, `0x2`, and `0x3` (or, better, referencing a single shared constant/config for "OS reserved addresses" used by both the Rust sequencer code and the Cairo OS program) so the two enforcement points cannot drift out of sync.

### Proof of Concept
Not constructed — this report identifies a validator/enforcement discrepancy between `ContractAddress::validate` (Rust) and `deploy_contract`'s reserved-address assertion (Cairo OS); confirming exploitability requires verifying the exact call path used by blockifier's deploy syscall handling, which could not be completed within the available tool budget.

// The block hash table is stored in address 0x1,
// this is a special address that is not used for contracts.
pub const BLOCK_HASH_TABLE_ADDRESS: ContractAddress = ContractAddress(PatriciaKey(StarkHash::ONE));

#[derive(
    Debug,
    Default,
    Copy,
    Clone,
    derive_more::Display,
    Eq,
    PartialEq,
    Hash,
    Deserialize,
    Serialize,
    PartialOrd,
    Ord,
    derive_more::Deref,
    SizeOf,
)]
pub struct ContractAddress(pub PatriciaKey);

impl ContractAddress {
    /// Validates the contract address is in the valid range for external access.
    /// The lower bound is above the special saved addresses and the upper bound is congruent with
    /// the storage var address upper bound.
    pub fn validate(&self) -> Result<(), StarknetApiError> {
        let value = self.0.0;
        let l2_address_upper_bound = Felt::from(*L2_ADDRESS_UPPER_BOUND);
        if (value > BLOCK_HASH_TABLE_ADDRESS.0.0) && (value < l2_address_upper_bound) {
            return Ok(());
        }

        Err(StarknetApiError::OutOfRange { string: format!("[0x2, {l2_address_upper_bound})") })
    }
}

impl<'a, S: State> AliasUpdater<'a, S> {
    fn new(state: &'a mut S, alias_contract_address: ContractAddress) -> StateResult<Self> {
        let stored_counter =
            state.get_storage_at(alias_contract_address, ALIAS_COUNTER_STORAGE_KEY)?;
        Ok(Self {
            state,
            is_alias_inserted: false,
            next_free_alias: if stored_counter == Felt::ZERO { None } else { Some(stored_counter) },
            alias_contract_address,
        })
    }

    fn set_alias_in_storage(&mut self, alias_key: AliasKey, alias: Alias) -> StateResult<()> {
        self.state.set_storage_at(self.alias_contract_address, alias_key, alias)
    }

    /// Inserts the alias key to the updates if it's not already aliased.
    fn insert_alias(&mut self, alias_key: &AliasKey) -> StateResult<()> {
        if alias_key.0 >= MIN_VALUE_FOR_ALIAS_ALLOC
            && self.state.get_storage_at(self.alias_contract_address, *alias_key)? == Felt::ZERO
        {
            let alias_to_allocate = self.next_free_alias.unwrap_or(INITIAL_AVAILABLE_ALIAS);
            self.set_alias_in_storage(*alias_key, alias_to_allocate)?;
            self.is_alias_inserted = true;
            self.next_free_alias = Some(alias_to_allocate + Felt::ONE);
        }
        Ok(())
    }

// Verifies that the block hash for the given block number equals the expected block hash,
// by adding a read entry to the contract_state_changes dict with it.
func read_block_hash_from_storage{contract_state_changes: DictAccess*}(
    block_number: felt, expected_block_hash: felt
) {
    // Fetch the block hash contract state.
    tempvar state_entry: StateEntry*;
    // Fetch a state_entry in this hint. Validate it in the update that comes next.
    %{ GetBlockHashMapping %}

    // Read from storage.
    tempvar storage_ptr = state_entry.storage_ptr;
    assert [storage_ptr] = DictAccess(
        key=block_number, prev_value=expected_block_hash, new_value=expected_block_hash
    );
    let storage_ptr = storage_ptr + DictAccess.SIZE;

    // Update the state.
    dict_update{dict_ptr=contract_state_changes}(
        key=BLOCK_HASH_CONTRACT_ADDRESS,
        prev_value=cast(state_entry, felt),
        new_value=cast(
            new StateEntry(
                class_hash=state_entry.class_hash, storage_ptr=storage_ptr, nonce=state_entry.nonce
            ),
            felt,
        ),
    );

    return ();
}
