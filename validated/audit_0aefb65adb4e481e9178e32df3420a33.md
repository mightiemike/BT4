### Title
Missing declared-class existence check in Starknet OS `execute_replace_class` causes state divergence from the Blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handler in the Blockifier (Rust) enforces that a class hash must be declared before a contract's class is replaced, via a call to `get_compiled_class` prior to `set_class_hash_at` [1](#0-0) . The equivalent re-execution logic in the Starknet OS Cairo program, `execute_replace_class`, has an explicit `TODO` marking that this existence check is missing, and unconditionally writes the new (possibly undeclared/non-existent) class hash into `contract_state_changes` without ever validating it [2](#0-1) .

### Finding Description
This mirrors the reported bug class: a "delegatecall"/class-swap style operation is performed against an implementation reference (`class_hash`) without checking that the referenced code actually exists/is declared, allowing silent success where a revert is expected.

In the Blockifier, `replace_class` is implemented to first read the compiled class (`state.get_compiled_class(request.class_hash)?`), which fails with `StateError::UndeclaredClassHash` if the class was never declared, and only then updates the class hash at the calling contract's address via `set_class_hash_at` [1](#0-0) . This is verified by the test `undeclared_class_hash`, which asserts the syscall reverts with "is not declared" when passed an undeclared class hash [3](#0-2) , and by the negative-flow assertion in `test_replace_class` [4](#0-3) .

In contrast, the Starknet OS's Cairo re-implementation of the same syscall for both the current and deprecated syscall paths performs no such check:
- `execute_replace_class` in `syscall_impls.cairo` contains the comment `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` immediately before unconditionally writing `class_hash = request.class_hash` into the contract's state entry [2](#0-1) .
- `execute_replace_class` in `deprecated_execute_syscalls.cairo` (used for the deprecated `REPLACE_CLASS_SELECTOR` path) similarly performs no check before writing the new class hash [5](#0-4) .

Since the Starknet OS program is used to re-execute the block and verify the sequencer's claimed state transition, any discrepancy between what the Blockifier accepts/rejects and what the OS accepts/rejects is a correctness-critical divergence, analogous to the report's core concern that `delegatecall`-style operations to non-existent code silently succeed instead of reverting.

### Impact Explanation
If a transaction invoking `replace_class` with an undeclared/non-existent class hash is submitted:
- The Blockifier (used for block building and execution) reverts the transaction as invalid, consistent with the "Ensure the class is declared" check.
- The Starknet OS (used for proving/re-execution of the same block) has no such check and would accept the class-hash write unconditionally, producing a different state transition than the Blockifier did for the same transaction/block content.

This produces exactly the kind of state root / re-execution divergence the validation criteria calls out ("wrong committed root or block hash, honest-node divergence"), because the OS's accounting of `contract_state_changes` (which ultimately feeds into the committed state diff and root) would not match what the Blockifier actually committed if this code path is ever exercised identically in OS re-execution versus Blockifier execution of the same call. It also reproduces the underlying risk from the reported issue: a contract can have its class pointer set to a hash for which no compiled/declared class exists, causing any subsequent call to that contract to behave unpredictably.

### Likelihood Explanation
The `replace_class` syscall is reachable by any contract with permission to call it (typically account/proxy contracts implementing upgradability), i.e., directly from a normal transaction sender, matching the requirement that the analog be reachable from a single submitted transaction. The missing check is explicitly marked with a `TODO` in the source, confirming it is a known gap rather than a hypothetical, and is not gated behind any special role (no malicious-operator/prover assumption needed) — it only requires calling a syscall with an arbitrary `class_hash` argument.

### Recommendation
Add the same declared-class existence check that exists in the Blockifier's `replace_class` handler to both `execute_replace_class` implementations in the Starknet OS Cairo program (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`), i.e., verify that a compiled class exists for `request.class_hash`/`syscall_ptr.class_hash` before updating `contract_state_changes`, and fail/abort re-execution (mirroring the Blockifier's revert) otherwise, resolving the outstanding `TODO(Yoni, 1/1/2026)`.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
