# Title
Unauthenticated Program-Data Log Spoofing Lets an Attacker Forge Gateway Inbound/Outbound Events on SVM Chains - (File: universalClient/chains/svm/event_listener.go)

### Summary
The SVM `EventListener.determineEventType` classifies a transaction log purely by matching the first 8 bytes of any `"Program data: "` line against the configured Anchor discriminators, without ever verifying which program actually emitted that log line. Combined with how signatures are discovered, an unprivileged attacker can craft a Solana transaction that is picked up by the listener and injects a forged `send_funds` / `finalize_universal_tx` event with fully attacker-controlled payload data into every honest node's `chainStore`, from which it flows into the vote/finalization pipeline as if it were a real gateway event.

### Finding Description
`processSlotRange` discovers candidate transactions via `GetSignaturesForAddress(gatewayAddr, ...)` [1](#0-0) , which (per Solana RPC semantics) returns any transaction that merely *references* the gateway address as an account key — it does not require that the gateway program actually be invoked as a CPI target in that transaction.

For every log line in such a transaction, `processSignatureBatch` calls `determineEventType(log)` and, if a type is found, immediately calls `ParseEvent` and stores the result via `InsertEventIfNotExists`, with no additional binding check [2](#0-1) .

`determineEventType` itself only:
1. Requires the line to start with `"Program data: "`.
2. Base64-decodes it.
3. Hex-encodes the first 8 bytes and looks it up in `discriminatorToEventType` (built from `registryConfig.GatewayMethods`, i.e. public, known Anchor discriminators) [3](#0-2) .

There is no check tying that particular `"Program data:"` log line to an actual CPI frame belonging to the configured gateway program (e.g. matching it against the surrounding `"Program <gatewayAddress> invoke"` / `"Program <gatewayAddress> success"` bracket, or cross-checking the instruction that produced it against the transaction's instruction/account list). Anchor discriminators are public (`sha256("global:<method>")[:8]`), and `Program data:` logs are simply `msg!`/`sol_log_data` output any program invoked in the same transaction can freely emit.

As a result, an attacker can:
1. Build a transaction that references the real gateway address as an (unused) account (to satisfy `GetSignaturesForAddress`).
2. Invoke their own attacker-controlled program in the same transaction, which emits `sol_log_data(discriminator_bytes || arbitrary_payload)` where `discriminator_bytes` matches, e.g., the `send_funds` discriminator, and `arbitrary_payload` encodes an attacker-chosen sender, recipient (Push-chain address), token, and amount.
3. Because the parsing logic (`parseSendFundsEvent`/`decodeUniversalTxEvent`) never validates the payload against actual gateway/vault state, the resulting `store.Event` is a `EventTypeInbound` `UniversalTx` with fabricated fields [4](#0-3) .

Because this transaction and its logs are public, deterministic data on Solana, every honest node's universalClient independently runs the same vulnerable parsing logic and will converge on the identical forged event — satisfying honest-validator quorum without needing any malicious/colluding validator.

### Impact Explanation
A forged `send_funds` inbound event that never actually locked real funds in the gateway's vault can be voted "PASSED" by honest UVs and finalized into a `UniversalTx`, which then triggers minting/crediting of value on Push Chain to an attacker-chosen recipient — i.e., unauthorized mint / fund creation without any corresponding deposit. This is a critical, in-scope impact per the review's "unauthorized mint... of user or protocol-controlled funds" and "forged... inbound... state accepted through user-reachable flows with honest validators" criteria.

### Likelihood Explanation
The attack requires only an unprivileged Solana account able to submit an ordinary transaction that (a) references the gateway program's public address as an account key and (b) invokes an attacker-deployed program that logs a matching 8-byte discriminator plus a crafted payload. No validator, TSS, or admin compromise is needed; the discriminators are public constants derived from the method name.

### Recommendation
Bind discriminator matching to the actual gateway program invocation: only accept `Program data:` logs that fall within the log bracket for `Program <gatewayAddress> invoke [...] Program <gatewayAddress> success`, or parse the transaction's inner instructions and verify that the CPI producing the log data was actually a call into `gatewayAddress`. Reject any log whose emitting program cannot be cryptographically/structurally tied to the configured gateway address.

### Proof of Concept
1. Deploy a minimal attacker Solana program that calls `sol_log_data(discriminator || fake_universal_tx_payload)` where `discriminator` equals the configured `send_funds` Anchor discriminator (`sha256("global:send_funds")[:8]`, a public value).
2. Submit a single transaction that includes the real gateway address as a (read-only, unused) account and invokes the attacker program.
3. The universalClient's `processSlotRange` → `GetSignaturesForAddress` picks up this transaction (it references the gateway address).
4. `processSignatureBatch` iterates the log lines; `determineEventType` matches the forged discriminator and returns `EventTypeSendFunds` [3](#0-2) .
5. `ParseEvent`/`parseSendFundsEvent` decodes the attacker-chosen sender/recipient/amount into a `store.Event{Type: store.EventTypeInbound, ...}` and it is inserted into `chainStore` [5](#0-4) , ready to be voted on by every honest UV that independently observes the same public transaction.

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

func parseSendFundsEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	if len(decoded) < 8 {
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing sendFunds event")

	// Create store.Event
	event := &store.Event{
		EventID:           eventID,
		BlockHeight:       slot,
		Type:              store.EventTypeInbound, // Gateway events from external chains are INBOUND
		Status:            store.StatusPending,
		ExpiryBlockHeight: 0, // Will be set based on confirmation type if needed
	}

	// Parse event data from this log
	parseUniversalTxEvent(event, decoded, logIndex, chainID, logger)

	return event
