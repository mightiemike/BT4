### Title
External Initiator credentials created via edit-role user can trigger runs on ANY webhook job, with no job-to-initiator scoping enforced - ([File: core/web/pipeline_runs_controller.go])

### Summary
An `edit`-role user can call `POST /v2/external_initiators` (guarded only by `auth.RequiresEditRole`) to mint a brand-new External Initiator Access Key/Secret pair. That credential authenticates via `auth.AuthenticateExternalInitiator`, which unconditionally sets the session user to `UserRoleRun`, and `PipelineRunsController.Create` performs no check binding the specific External Initiator to a specific job before invoking `App.RunJobV2` for any integer job ID supplied in the URL.

### Finding Description
`POST /v2/external_initiators` is registered under `auth.RequiresEditRole(eia.Create)` [1](#0-0) . `ExternalInitiatorsController.Create` generates a fresh `auth.Token` (AccessKey/Secret) via `auth.NewToken()`, persists it as an `ExternalInitiator` row, and returns the raw secret to the caller with no ownership/scoping metadata tying it to a particular job [2](#0-1) .

The run-trigger endpoint `POST /v2/jobs/:ID/runs` is registered in the `userOrEI` group, reachable via `auth.AuthenticateExternalInitiator` OR session/token auth, guarded by `auth.RequiresRunRole` [3](#0-2) .

`AuthenticateExternalInitiator` looks up the `ExternalInitiator` purely by AccessKey/Secret and, on success, sets the authenticated "user" in context to a synthetic `&clsessions.User{Role: clsessions.UserRoleRun}` — with no reference back to which job(s) this specific initiator is permitted to trigger [4](#0-3) .

`PipelineRunsController.Create` then only checks `isUser, _ := auth.GetAuthenticatedUser(c)` to decide whether to accept an integer job ID and call `prc.App.RunJobV2(ctx, jobID, nil)` for that ID — but since the EI authentication path stores a synthetic `User` object under the same `SessionUserKey`, `isUser` evaluates true for EI-authenticated callers exactly the same as for real session/token users [5](#0-4) . There is no lookup or comparison against a job's own external-initiator identity anywhere in this path — indeed, no `ExternalInitiatorSpec` type/field exists anywhere in the current codebase (confirmed via repo-wide search returning zero matches), meaning the legacy per-job external-initiator binding this invariant assumes has been removed/never enforced in this handler.

As a result, any `ExternalInitiator` credential minted by an edit-role user is functionally a global run-any-job (by integer ID) bearer token, not scoped to any particular webhook job.

### Impact Explanation
This is a privilege-escalation and unauthorized-execution finding: an `edit`-role, non-admin user can escalate their own capability to trigger arbitrary job runs across the entire node (any job addressable by an integer ID accepted by `RunJobV2`), including jobs they do not own, by minting a durable External Initiator credential that is treated identically to a full run-role bearer credential. This maps to Chainlink's "unauthorized transaction or workflow execution" bounty impact category, since triggering pipeline runs can result in unauthorized on-chain transactions, unwanted external adapter calls, or resource exhaustion depending on job composition.

### Likelihood Explanation
High likelihood: this only requires an `edit` role — a role level below admin that is commonly granted to operational users — and two straightforward, unauthenticated-from-EI-perspective HTTP calls (`POST /v2/external_initiators` then `POST /v2/jobs/:ID/runs`). No secrets need to be guessed; the flow uses the credential exactly as designed by the API. The vulnerability is fully repeatable and requires no race conditions or timing dependencies.

### Recommendation
Bind each `ExternalInitiator` to the specific job(s) it is permitted to trigger (re-introduce or enforce a job-to-external-initiator association), and modify `PipelineRunsController.Create` (or `AuthenticateExternalInitiator`) to verify that the authenticated `ExternalInitiator` (`auth.GetAuthenticatedExternalInitiator(c)`) is actually referenced by the target job's spec before calling `RunJobV2`. Additionally, distinguish EI-authenticated requests from real user sessions rather than reusing `SessionUserKey`/`UserRoleRun` for both, so route logic like `isUser` checks in `PipelineRunsController.Create` can apply EI-specific authorization instead of treating them as equivalent to logged-in run-role users.

### Proof of Concept
Integration test plan (Go, using `cltest` helpers similar to existing `external_initiators_controller_test.go` and `pipeline_runs_controller_test.go`):
1. Start an app with `ExternalInitiatorsEnabled = true` and two webhook jobs, `jobA` and `jobB`, neither referencing any external initiator specifically (or referencing a *different* EI than the one that will be created).
2. Using an HTTP client authenticated as an `edit`-role user, `POST /v2/external_initiators` with `{"name":"attacker-ei"}`, and capture returned `AccessKey`/`Secret` from `presenters.ExternalInitiatorAuthentication`.
3. Using a fresh HTTP client with headers `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` set to the captured values (no session/token), issue `POST /v2/jobs/<jobB.ID>/runs` where `jobB` has no relation to `attacker-ei`.
4. Assert current (vulnerable) behavior: response is `201 Created` with a `pipelineRun` resource, proving the EI credential triggered a run on an unrelated job.
5. Expected behavior after fix: response should be `401/403 Unauthorized`/`Forbidden` unless `jobB`'s spec references `attacker-ei`, and the test should be updated to assert rejection.

// Create builds and saves a new external initiator
func (eic *ExternalInitiatorsController) Create(c *gin.Context) {
	ctx := c.Request.Context()
	eir := &bridges.ExternalInitiatorRequest{}
	if !eic.App.GetConfig().JobPipeline().ExternalInitiatorsEnabled() {
		err := errors.New("The External Initiator feature is disabled by configuration")
		jsonAPIError(c, http.StatusMethodNotAllowed, err)
		return
	}

	eia := auth.NewToken()
	if err := c.ShouldBindJSON(eir); err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	ei, err := bridges.NewExternalInitiator(eia, eir)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	if err := ValidateExternalInitiator(ctx, eir, eic.App.BridgeORM()); err != nil {
		jsonAPIError(c, http.StatusBadRequest, err)
		return
	}
	if err := eic.App.BridgeORM().CreateExternalInitiator(ctx, ei); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	eic.App.GetAuditLogger().Audit(audit.ExternalInitiatorCreated, map[string]any{
		"externalInitiatorID":   ei.ID,
		"externalInitiatorName": ei.Name,
		"externalInitiatorURL":  ei.URL,
	})

	resp := presenters.NewExternalInitiatorAuthentication(*ei, *eia)
	jsonAPIResponseWithStatus(c, resp, "external initiator authentication", http.StatusCreated)

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionExternalInitiatorKey, ei)

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}

func (prc *PipelineRunsController) Create(c *gin.Context) {
	ctx := c.Request.Context()
	respondWithPipelineRun := func(jobRunID int64) {
		pipelineRun, err := prc.App.PipelineORM().FindRun(ctx, jobRunID)
		if err != nil {
			jsonAPIError(c, http.StatusInternalServerError, err)
			return
		}
		res := presenters.NewPipelineRunResource(pipelineRun, prc.App.GetLogger())
		jsonAPIResponse(c, res, "pipelineRun")
	}

	idStr := c.Param("ID")

	// Webhook runs used external job UUIDs; that job type has been removed.
	if _, err := uuid.Parse(idStr); err == nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, fmt.Errorf("cannot run job of type %q: %w", job.Webhook, job.ErrJobTypeRemoved))
		return
	}

	_, isUser := auth.GetAuthenticatedUser(c)
	// only users are allowed to run jobs using int IDs - EIs not allowed
	if isUser {
		// Is it an int32? Then process it regardless of type
		var jobID int32
		jobID64, err := strconv.ParseInt(idStr, 10, 32)
		if err == nil {
			jobID = int32(jobID64)
			jobRunID, err := prc.App.RunJobV2(ctx, jobID, nil)
			if err != nil {
				jsonAPIError(c, http.StatusInternalServerError, err)
				return
			}
			respondWithPipelineRun(jobRunID)
			return
		}
	}

	jsonAPIError(c, http.StatusUnprocessableEntity, errors.New("bad job ID"))
}
