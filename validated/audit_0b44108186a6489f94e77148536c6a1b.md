### Title
Silent loss of zero-lamport tombstones during ancient-slot squash relies on an unenforced invariant, risking stale account resurrection across incremental snapshots - ([File: accounts-db/src/ancient_append_vecs.rs])

### Summary
The ancient-append-vec "squash" path (`combine_ancient_slots_packed` → `finish_combine_ancient_slots_packed_internal`) assumes, but never actually checks, that every slot it combines is older than the latest full snapshot slot. That assumption is what allows the squash code to skip carrying forward zero-lamport "tombstone" bytes — bytes that exist specifically so an incremental snapshot can still tell a downstream node that an account's balance dropped to zero. The invariant is only guarded by a `debug_assert!`, which is compiled out in release builds, and `latest_full_snapshot_slot` is never referenced anywhere in `ancient_append_vecs.rs`.

### Finding Description
`AccountsDb::shrink_collect` (via `load_accounts_index_for_shrink`) decides, per zero-lamport single-ref account, whether it is safe to fully purge the account's bytes or whether it must retain them as a "tombstone" so a subsequent incremental snapshot can propagate the deletion: [1](#0-0) 

This is gated by `can_purge_zero_lamport_single_ref_after_shrink(slot)`, which is tied to `latest_full_snapshot_slot` — only slots at or before the latest full snapshot are allowed to have their zero-lamport tombstones dropped, exactly analogous to how the Curve V2 report required an explicit flag (`use_eth`) to be set correctly for the right asset-handling path to be taken. Here, the "flag" is effectively "is this slot old enough that dropping the tombstone is safe," and it must be evaluated correctly at every call site that removes storage.

The ancient-squash finishing routine, however, does not evaluate this flag at all. It only asserts (via `debug_assert!`, not a real `assert!`) that any given ancient-squash target has no tombstones to carry forward, based purely on the comment-only claim that "Ancient squash only runs on slots far older than the latest full snapshot, where tombstones are purgeable": [2](#0-1) 

Grepping the entire ancient-append-vec module confirms `latest_full_snapshot_slot` is never consulted there — the invariant that justifies dropping tombstones silently (rather than carrying them forward like `shrink_storage` does) is not enforced in the code path that relies on it; it is only enforced (if at all) by external scheduling logic outside this file, and only diagnosed via a debug-only assertion. Contrast this with the non-ancient shrink path, which explicitly carries tombstones forward into the new storage: [3](#0-2) 

If, for any reason (misconfigured `ancient_append_vec_offset`/`max_ancient_storages` tuning, a scheduling race between snapshot-slot advancement and the background ancient-combine job, or a future refactor that changes when `combine_ancient_slots_packed` is invoked), an ancient-squash target slot is newer than `latest_full_snapshot_slot` while holding a zero-lamport single-ref account, `shrink_collect` will correctly identify it as not-yet-purgeable and produce a non-empty `tombstones_to_carry_forward` list — but the ancient-squash write path has no code to actually write those tombstone bytes into the new packed storage. The `debug_assert!` would fire and panic in a debug build, but in a release validator build the check is a no-op, and the bytes are simply not written; `remove_old_stores_shrink` then drops the old storage entirely.

### Impact Explanation
If this invariant is ever violated in a release binary, the zero-lamport deletion marker for the affected pubkey is silently lost from disk. Any subsequent incremental snapshot taken relative to the still-valid (older) full snapshot will therefore no longer contain a record that the account went to zero lamports. When a node (or any peer) rebuilds its `AccountsDb` from full + incremental snapshot, the full snapshot's stale, non-zero-lamport version of the account "wins" because the incremental snapshot no longer carries the offsetting deletion. This is a concrete stale/wrong-version account load and a silent, incorrect balance resurrection exactly analogous to the reported bug class (an asset accounting path silently reverting to a stale/incorrect state because a required flag/invariant wasn't actually enforced at the call site that needed it), and would manifest as a hash/capitalization divergence and honest-node snapshot-vs-replay mismatch between nodes that took the incremental snapshot at different rebuild points.

### Likelihood Explanation
Likelihood is difficult to fully establish from static reading alone within the available exploration budget: I was not able to trace every caller that decides which slots are handed to `combine_ancient_slots_packed`/`combine_ancient_slots_packed_internal` to confirm whether an external, always-correct guard against `latest_full_snapshot_slot` exists elsewhere (e.g., in `accounts_background_service.rs` or bank/snapshot scheduling code) that would make this scenario unreachable in practice. The existing extensive test suite for the sibling non-ancient shrink path (`test_shrink_converts_zero_lamport_single_ref_account_to_tombstone`, `test_incremental_snapshots_handle_tombstones`) suggests the team is well aware of and has hardened the general tombstone-vs-incremental-snapshot hazard, but I found no equivalent test exercising the ancient-squash tombstone-carry-forward path, and the reliance on a debug-only assertion (rather than a hard runtime check or explicit code path) for what is described as a correctness-critical invariant is itself a risk indicator. This should be treated as a code-hygiene/defense-in-depth gap with a plausible but unconfirmed reachability, not a demonstrated end-to-end exploit.

### Recommendation
Replace the `debug_assert!` in `finish_combine_ancient_slots_packed_internal` with either (a) an explicit runtime check tying ancient-squash slot eligibility to `latest_full_snapshot_slot` before a slot is ever added to `sorted_slots`/`accounts_to_combine`, or (b) actual tombstone-carry-forward handling in the ancient-squash write path (mirroring `shrink_storage`'s `store_tombstones` call) so that even if the invariant is violated, correctness is preserved rather than silently broken. At minimum, promote the debug assertion to a real `assert!` so any violation fails loudly instead of silently dropping data in release builds.

    /// finish shrink operation on slots where a new storage was created
    /// drop root and storage for all original slots whose contents were combined into other storages
    fn finish_combine_ancient_slots_packed_internal(
        &self,
        accounts_to_combine: AccountsToCombine<'_>,
        mut write_ancient_accounts: WriteAncientAccounts,
        metrics: &mut SquashStatsSub,
    ) {
        let mut dropped_roots = Vec::with_capacity(accounts_to_combine.accounts_to_combine.len());
        for shrink_collect in accounts_to_combine.accounts_to_combine {
            let slot = shrink_collect.slot;

            // Ancient squash only runs on slots far older than the latest full snapshot, where
            // tombstones are purgeable and `shrink_collect` drops them rather than carrying them
            // forward. The squash write path has no tombstone handling, so a non-empty list here
            // would be silently lost; assert the invariant at the point that loss would occur.
            debug_assert!(
                shrink_collect.tombstones_to_carry_forward.is_empty(),
                "ancient squash reached a carry-forward tombstone at slot {slot}",
            );

            let shrink_in_progress = write_ancient_accounts.shrinks_in_progress.remove(&slot);

            let mut reopen = false;
            if shrink_in_progress.is_none() {
                dropped_roots.push(slot);
            } else {
                // Remember that we need to 'reopen' the storage for this
                // 'slot'. Note that it is not *safe* to reopen the storage for
                // the 'slot' here, because 'shrink_in_progress' is still alive.
                // Storage map may still point to the old storage and will be
                // updated to point to the new storage, after we drop
                // 'shrink_in_progress'.
                reopen = true;
            }

            self.remove_old_stores_shrink(
                &shrink_collect,
                &self.shrink_ancient_stats.shrink_stats,
                shrink_in_progress,
                true,
            );

    /// Test that the full tombstone path works end to end across snapshots.
    /// Here's the scenario:
    ///
    /// slot 1:
    ///     - fund Account1 (from Account2) to bring it to life
    ///     - take a full snapshot, capturing Account1 with a non-zero balance
    /// slot 2:
    ///     - drain Account1 back to zero lamports (send to Account2)
    ///     - root and flush so slot 2's storage (holding the zero-lamport Account1) is written
    /// slot 3:
    ///     - update Account2 again so its slot-2 version dies, giving slot 2 dead bytes
    ///     - root, flush, and clean so the slot-1 (funded) version of Account1 is removed, leaving
    ///       the zero-lamport account at slot 2 as the lone reference
    ///     - shrink slot 2 into a tombstone: Account1 is removed from the index, its bytes retained
    ///     - take an incremental snapshot, which must carry the tombstone
    ///     - ensure deserializing from full + incremental is equal to this bank
    ///     - ensure Account1 hasn't come back from the dead
    ///
    /// The full snapshot is older than slot 2, so shrink must NOT purge the zero-lamport account; it
    /// has to retain the bytes as a tombstone. The incremental snapshot then carries that tombstone
    /// so that rebuilding from full + incremental overrides the still-funded full-snapshot version
    /// and the account ends up deleted. If the tombstone were dropped during shrink, the rebuild
    /// would resurrect Account1 from the full snapshot and the checks below would fail.
    #[test]
    fn test_incremental_snapshots_handle_tombstones() {
        let key1 = Keypair::new();
        let key2 = Keypair::new();

        let (_tmp_dir, accounts_dir) = create_tmp_accounts_dir_for_tests();
        let bank_snapshots_dir = tempfile::TempDir::new().unwrap();
        let full_snapshot_archives_dir = tempfile::TempDir::new().unwrap();
        let incremental_snapshot_archives_dir = tempfile::TempDir::new().unwrap();
        let snapshot_config = snapshot_config_for_tests(
            &bank_snapshots_dir,
            &full_snapshot_archives_dir,
            &incremental_snapshot_archives_dir,
        );

        let GenesisConfigInfo {
            mut genesis_config,
            mint_keypair,
            ..
        } = create_genesis_config_with_leader(
            1_000_000 * LAMPORTS_PER_SOL,
            &Pubkey::new_unique(),
            1_000_000 * LAMPORTS_PER_SOL,
        );
        // test expects 0 transaction fee
        genesis_config.fee_rate_governor = solana_fee_calculator::FeeRateGovernor::new(0, 0);

        let lamports_to_transfer = 123_456 * LAMPORTS_PER_SOL;
        let (bank0, bank_forks) =
            Bank::new_with_paths_for_tests(&genesis_config, None, vec![accounts_dir.clone()], None)
                .wrap_with_bank_forks_for_tests();
        let leader = *bank0.leader();
        bank0
            .transfer(lamports_to_transfer, &mint_keypair, &key2.pubkey())
            .unwrap();
        bank0.fill_bank_with_ticks_for_tests();

        let full_snapshot_slot = 1;
        let bank1 = Bank::new_from_parent_with_bank_forks(
            bank_forks.as_ref(),
            bank0,
            leader,
            full_snapshot_slot,
        );
        bank1
            .transfer(lamports_to_transfer, &key2, &key1.pubkey())
            .unwrap();
        bank1.fill_bank_with_ticks_for_tests();
        bank1.set_block_id(Some(Hash::default()));
        let full_snapshot_archive_info =
            bank_to_full_snapshot_archive(&snapshot_config, &bank1).unwrap();

        let zeroed_slot = full_snapshot_slot + 1;
        let bank2 =
            Bank::new_from_parent_with_bank_forks(bank_forks.as_ref(), bank1, leader, zeroed_slot);
        bank2
            .transfer(lamports_to_transfer, &key1, &key2.pubkey())
            .unwrap();
        assert_eq!(
            bank2.get_balance(&key1.pubkey()),
            0,
            "Ensure Account1's balance is zero"
        );
        bank2.fill_bank_with_ticks_for_tests();
        bank2.set_block_id(Some(Hash::default()));
        // root and flush so slot 2's storage holding the zero-lamport Account1 is written
        bank2.squash();
        bank2.force_flush_accounts_cache();

        let slot = zeroed_slot + 1;
        let bank3 = Bank::new_from_parent_with_bank_forks(bank_forks.as_ref(), bank2, leader, slot);
        bank3
            .transfer(lamports_to_transfer, &mint_keypair, &key2.pubkey())
            .unwrap();
        bank3.fill_bank_with_ticks_for_tests();
        bank3.set_block_id(Some(Hash::default()));

        // flush and clean so slot 1's funded Account1 is removed, leaving the zero-lamport account
        // at slot 2 as the lone reference
        bank3.squash();
        bank3.force_flush_accounts_cache();
        bank3.clean_accounts();

        let accounts_db = &bank3.rc.accounts.accounts_db;
        // full snapshot is older than slot 2, so shrink keeps the tombstone instead of purging
        accounts_db.set_latest_full_snapshot_slot(full_snapshot_slot);
        assert_eq!(
            accounts_db
                .accounts_index
                .ref_count_from_storage(&key1.pubkey()),
            1,
            "Ensure Account1 is a zero-lamport single-ref in the index before shrink"
        );

        // shrink converts the zero-lamport single-ref into a tombstone
        accounts_db.shrink_all_slots(false, None);
        assert_eq!(
            accounts_db
                .accounts_index
                .ref_count_from_storage(&key1.pubkey()),
            0,
            "Ensure shrink removed the tombstoned account from the index"
        );
        assert!(
            !accounts_db
                .get_storages(zeroed_slot..zeroed_slot + 1)
                .0
                .is_empty(),
            "Ensure the zeroed slot's storage is retained so the tombstone survives for the \
             incremental snapshot"
        );

        let incremental_snapshot_archive_info =
            bank_to_incremental_snapshot_archive(&snapshot_config, &bank3, full_snapshot_slot)
                .unwrap();

        let deserialized_bank = bank_from_snapshot_archives(
            slice::from_ref(&accounts_dir),
            &full_snapshot_archive_info,
            Some(&incremental_snapshot_archive_info),
            &snapshot_config,
            &genesis_config,
            &RuntimeConfig::default(),
            None,
            None, // leader_for_tests
            None,
            false,
            false,
            false,
            ACCOUNTS_DB_CONFIG_FOR_TESTING,
            None,
            Arc::default(),
        )
        .unwrap();
        assert_eq!(
            deserialized_bank, *bank3,
            "Ensure rebuilding from full + incremental (with the tombstone) matches the live bank"
        );
        assert!(
            deserialized_bank
                .get_account_modified_slot(&key1.pubkey())
                .is_none(),
            "Ensure Account1 has not been brought back from the dead"
        );
    }
