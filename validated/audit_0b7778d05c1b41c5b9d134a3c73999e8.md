## Analysis

The CVE describes QPDF's `QPDFObjectHandle`/`QPDF_Dictionary` recursively parsing nested dictionary objects with no depth limit, causing stack exhaustion. The sequencer contains a directly analogous unbounded-recursion pattern in the Starknet OS's bytecode-segment-structure builder.

### The analog

`create_bytecode_segment_structure_inner` recursively walks a `NestedIntList` (`bytecode_segment_lengths`) taken directly from a declared contract's compiled CASM class, with **no depth limit or recursion guard at all**: [1](#0-0) 

It is invoked from the OS hint extension that processes every compiled class touched by a block during Starknet OS re-execution/proving: [2](#0-1) 

Contrast this with the blockifier's equivalent structure walker, `NestedFeltCounts::new_inner`, which explicitly asserts `segmentation_depth <= 1` — evidence the team is aware that deeper nesting is possible/unsupported, yet the OS hint path (used for re-execution/proving, run by every node/prover reproducing the block) has no such guard: [3](#0-2) 

`bytecode_segment_lengths` is produced by the Sierra→CASM compiler as a function of the contract's Sierra code structure (function/branch segmentation), which is fully attacker-controlled via the Sierra program submitted in a declare transaction. The only external limits are on total bytecode size (`max_contract_bytecode_size`, `max_bytecode_size`), not nesting depth: [4](#0-3) 

### Title
Unbounded recursion in Starknet OS bytecode-segment-structure builder allows stack-exhaustion DoS via a declared class - (File: `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`)

### Summary
`create_bytecode_segment_structure_inner` recurses over the `NestedIntList` describing a compiled class's bytecode segmentation with no depth bound, matching the QPDF CVE-2018-9918 bug class ("nesting in direct objects is not restricted"). A declarer who crafts a Cairo1 contract whose Sierra program compiles to a deeply/recursively-nested segment structure (e.g., via deeply nested control flow up to the bytecode-size limit) can cause unbounded stack growth when the Starknet OS re-executes/proves any block that touches this class.

### Finding Description
`create_bytecode_segment_structure_inner` pattern-matches on `NestedIntList::Node(lengths)` and recurses into each child with no depth counter or limit, unlike the analogous blockifier function `NestedFeltCounts::new_inner`, which explicitly asserts depth ≤ 1. The `NestedIntList` is derived from `compiled_class.get_bytecode_segment_lengths()` — a structural property of the compiled CASM produced by the (trusted) Sierra→CASM compiler, but whose shape is a direct function of the attacker-supplied Sierra program's control-flow/function structure. The only bound in the system is on the *total size* of the bytecode (`max_contract_bytecode_size`/`max_bytecode_size`), not on the nesting depth of the segmentation tree, so an attacker can trade breadth for depth (e.g., long chains of nested branches/functions) to build an arbitrarily deep segment tree within the size budget, then declare that class.

### Impact Explanation
This code path executes during Starknet OS hint processing (`load_classes_and_create_bytecode_segment_structures`), which runs for every compiled class referenced in a block whenever the OS/prover re-executes that block. A deeply nested structure would exhaust the process stack and crash the OS/prover execution — a deterministic, reproducible failure for every honest node/prover attempting to re-execute or prove that block, i.e., a network unable to confirm/prove new blocks once such a class is declared and invoked. This satisfies the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Reachable from a single, unprivileged declare transaction (declaring a class with sufficiently nested code) followed by any invocation that causes the block to be re-executed/proven by the Starknet OS. No special privileges are required; the compiler itself performs no depth restriction on the segmentation tree it emits, and the OS hint code performs no defensive bound either.

### Recommendation
Add an explicit recursion-depth limit (mirroring the blockifier's `assert!(segmentation_depth <= 1, ...)`) inside `create_bytecode_segment_structure_inner`, returning a graceful `OsHintError` instead of unbounded recursion, or convert the recursive walk to an iterative one bounded by an explicit stack/queue with a maximum depth check consistent with what the compiler is expected to emit.

### Proof of Concept
1. Craft a Cairo1 contract whose source produces deeply nested basic-block/segment structure in the compiled CASM (e.g., thousands of nested `if`/`else` or nested function scopes), sized to stay within `max_contract_bytecode_size`/`max_bytecode_size`.
2. Submit a `DECLARE` transaction for this class; it passes gateway size checks since those only bound total bytecode size, not nesting depth.
3. Invoke the class so it is included and executed in a block.
4. When the Starknet OS/prover re-executes the block, `load_classes_and_create_bytecode_segment_structures` calls `create_bytecode_segment_structure` → `create_bytecode_segment_structure_inner`, which recurses once per nesting level with no bound, exhausting the stack and crashing the re-execution/proving process.

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }

        match bytecode_segment_lengths {

            NestedIntList::Node(segments_vec) => {

                let mut segments = Vec::with_capacity(segments_vec.len());

                        segment,

                        segmentation_depth + 1,

                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
