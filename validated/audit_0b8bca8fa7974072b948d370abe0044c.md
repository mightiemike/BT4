### Title
Unbounded recursion in `get_recursive_transaction_results` causes RPC-node stack overflow via deep receipt chains - (File: `chain/chain/src/chain.rs`)

### Summary
`Chain::get_recursive_transaction_results` walks the receipt tree produced by a transaction by recursing once per receipt, with no depth limit, unlike the analogous `ReceiptToTx` lookup which enforces `MAX_DEPTH = 1000`. An attacker who submits a single transaction that spawns a sufficiently deep chain of receipts (via recursive cross-contract calls, e.g. the pattern demonstrated by the `max_self_recursion_delay`/`recurse` test contracts) can cause any RPC node that later serves a `tx`/`tx_status` query for that transaction to recurse to the same depth and overflow its stack, crashing the serving process/thread. This mirrors the CVE-2024-36760 Rhai class of bug: unbounded recursive evaluation of an attacker-controlled tree causes a stack overflow, here triggered by an untrusted transaction reachable to any RPC caller.

### Finding Description
`get_recursive_transaction_results` recurses over every receipt spawned transitively by a transaction, one stack frame per receipt, with no depth cap: [1](#0-0) 

This is invoked by `get_final_transaction_result`, the code path backing the JSON-RPC `tx`/`tx_status` endpoints exposed to any RPC caller: [2](#0-1) 

`ViewClientActor::get_tx_status`, which handles the `TxStatus` message dispatched from the JSON-RPC layer's `tx_status_common`/`tx_status_fetch`, ultimately reaches this recursive walk through `chain.get_partial_transaction_result_option` / `chain.get_transaction_result_with_receipt`: [3](#0-2) [4](#0-3) 

Contrast this with the sibling `ReceiptToTx` lookup, which the codebase explicitly bounds with `MAX_DEPTH = 1000` and returns a `DepthExceeded` error rather than recursing unboundedly: [5](#0-4) 

The depth of the receipt tree that `get_recursive_transaction_results` must walk is controlled by whoever submits the original transaction: a contract can chain arbitrarily many cross-contract-call receipts limited only by available gas (the test contract's `max_self_recursion_delay`/`recurse` functions demonstrate exactly this self-recursive receipt-chaining pattern, which real contracts can replicate to build very deep receipt chains): [6](#0-5) 

Once such a transaction executes and its outcomes are persisted, *any* unprivileged RPC caller — not just the submitter — can trigger the unbounded recursive walk simply by querying `tx`/`tx_status` for that transaction hash. Each recursive Rust call frame here is nontrivial (it borsh/JSON-converts an `ExecutionOutcome`, does vector indexing, etc.), so the safe recursion depth before native stack exhaustion is far lower than for a minimal frame, making the attack cheap to reach in terms of the number of chained receipts needed.

### Impact Explanation
A crafted transaction can force any RPC-serving node (including validator nodes that also serve RPC) to crash its `ViewClientActor` thread/process when a client queries `tx`/`tx_status` for that transaction — a transaction-triggered denial of service reachable purely from RPC callers and an unprivileged transaction submitter, with no privileged actor required. This matches the "transaction-triggered halt" impact category.

### Likelihood Explanation
High: an unprivileged account can author a self-calling contract (mirroring `max_self_recursion_delay`) that builds a receipt chain hundreds/thousands of hops deep, bounded only by gas budget and cross-shard routing, then anyone (including the attacker) can invoke the standard, unauthenticated `tx`/`tx_status` JSON-RPC method to trigger the crash. No special privileges, timing races, or validator cooperation are required.

### Recommendation
Bound `get_recursive_transaction_results` the same way `ReceiptToTx` traversal is bounded: convert it to an iterative (worklist/queue) traversal, or add an explicit `MAX_DEPTH`/`MAX_OUTCOMES` cap that fails gracefully (e.g., returns an error analogous to `DepthExceeded`) instead of recursing without bound.

### Proof of Concept
1. Deploy a contract exposing a self-recursive function analogous to `internal_recurse`/`max_self_recursion_delay`, which on each invocation issues a new `FunctionCall` promise to itself, chaining a new receipt at each hop.
2. Submit one transaction invoking this function with enough prepaid gas to chain N receipts, where N is large enough to exceed the safe native stack recursion depth for `get_recursive_transaction_results` (each frame does non-trivial work, so N well under `ReceiptToTx`'s 1000-hop bound may already suffice).
3. Once the transaction and its receipt chain have executed and outcomes are persisted, issue a JSON-RPC `tx` or `tx_status` request for the original transaction hash against any node serving that shard.
4. `ViewClientActor::get_tx_status` → `Chain::get_final_transaction_result` → `get_recursive_transaction_results` recurses N times with no depth check, overflowing the native stack and crashing the serving thread/process.

        &self,
        outcomes: &mut Vec<ExecutionOutcomeWithIdView>,
        id: &CryptoHash,
        require_all_outcomes: bool,
    ) -> Result<(), Error> {

        };
        outcomes.push(ExecutionOutcomeWithIdView::from(outcome));
        let outcome_idx = outcomes.len() - 1;
        for idx in 0..outcomes[outcome_idx].outcome.receipt_ids.len() {
            let id = outcomes[outcome_idx].outcome.receipt_ids[idx];
            self.get_recursive_transaction_results(outcomes, &id, require_all_outcomes)?;
        }
        Ok(())
    }

/// Handler-level: write synthetic ReceiptToTx rows forming chain of 1001
/// FromReceipt entries (exceeds MAX_DEPTH=1000). Verify DepthExceeded
/// returned with originally queried receipt_id.
#[test]
fn test_receipt_to_tx_depth_exceeded() {
    init_test_logger();

    let mut env = TestLoopBuilder::new().epoch_length(EPOCH_LENGTH).track_all_shards().build();

    let store = env.validator().store();
    let mut store_update = store.store_update();

    // Chain of 1002 receipt IDs: receipt_0 → receipt_1 → ... → receipt_1001.
    // receipt_0..receipt_1000 are FromReceipt → next. receipt_1001 is
    // FromTransaction (terminal — never reached).
    let chain_len = 1002usize;
    let receipt_ids: Vec<CryptoHash> =
        (0..chain_len).map(|i| CryptoHash::hash_bytes(&(i as u32).to_le_bytes())).collect();

    // Terminal node: receipt_1001 → tx.
    store_update.insert_ser(
        DBCol::ReceiptToTx,
        receipt_ids[chain_len - 1].as_ref(),
        &ReceiptToTxInfo::V1(ReceiptToTxInfoV1 {
            origin: ReceiptOrigin::FromTransaction(ReceiptOriginTransaction {
                tx_hash: CryptoHash::hash_bytes(b"tx"),
                sender_account_id: "sender".parse().unwrap(),
            }),
            receiver_account_id: "receiver".parse().unwrap(),
            shard_id: ShardId::new(0),
        }),
    );

    // Intermediates: receipt_i → receipt_{i+1}.
    for i in 0..chain_len - 1 {
        store_update.insert_ser(
            DBCol::ReceiptToTx,
            receipt_ids[i].as_ref(),
            &ReceiptToTxInfo::V1(ReceiptToTxInfoV1 {
                origin: ReceiptOrigin::FromReceipt(ReceiptOriginReceipt {
                    parent_receipt_id: receipt_ids[i + 1],
                    parent_predecessor_id: "system".parse().unwrap(),
                }),
                receiver_account_id: "receiver".parse().unwrap(),
                shard_id: ShardId::new(0),
            }),
        );
    }

    store_update.commit();

    // Query receipt_0 — needs 1001 hops, exceeds MAX_DEPTH=1000.
    let handle = env.node_datas[0].view_client_sender.actor_handle();
    let view_client: &mut near_client::ViewClientActor = env.test_loop.data.get_mut(&handle);
    let result = view_client.handle(receipt_to_tx_req(receipt_ids[0]));

    match result {
        Err(GetReceiptToTxError::DepthExceeded { receipt_id, limit }) => {
            assert_eq!(receipt_id, receipt_ids[0], "error reports originally queried receipt");
            assert_eq!(limit, 1000, "limit == MAX_DEPTH=1000");
        }
        other => panic!("expected DepthExceeded error, got: {other:?}"),
    }

/// Delay completion of the receipt for as long as possible through self cross-contract calls.
///
/// This contract keeps the recursion depth and returns it when less than 5Tgas remains, which is
/// most likely is no longer sufficient for another cross-contract call.
///
/// This is a stable alternative to yield/resume proposal at the time of writing.
#[unsafe(no_mangle)]
pub unsafe fn max_self_recursion_delay() {
    input(0);
    let mut bytes = [0u8; 4];
    read_register(0, bytes.as_mut_ptr());
    let recursion = u32::from_be_bytes(bytes);
    let available_gas = prepaid_gas() - used_gas();
    if available_gas < 5_000_000_000_000 {
        return value_return(4, bytes.as_ptr() as u64);
    }
    current_account_id(1);
    let method_name = "max_self_recursion_delay";
    let promise_idx = promise_batch_create(u64::MAX, 1);
    let amount = 1u128;
    let gas_fixed = 0;
    let gas_weight = 1;
    let argument_bytes = recursion.saturating_add(1).to_be_bytes();
    promise_batch_action_function_call_weight(
        promise_idx,
        method_name.len() as u64,
        method_name.as_ptr() as u64,
        argument_bytes.len() as u64,
        argument_bytes.as_ptr() as u64,
        &amount as *const u128 as u64,
        gas_fixed,
        gas_weight,
    );
    promise_return(promise_idx);
}
