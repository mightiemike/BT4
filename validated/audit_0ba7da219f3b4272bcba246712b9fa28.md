### Title
Started contract readers/writers leak on `pluginOracleCreator.Create` mid-initialization failure - (File: core/capabilities/ccip/oraclecreator/plugin.go)

### Summary
`pluginOracleCreator.Create` starts contract readers and chain writers via `createReadersAndWriters` (calling `cr.Start`/`cw.Start`) before any of the subsequent steps (`getChainAccessorsAndContractTransmittersFromProviders`, `createFactoryAndTransmitter`, `libocr3.NewOracle`) run. If any of these later steps return an error, `Create` returns early with `nil, err` without ever building the `closers` slice or calling `newWrappedOracle`, so the already-started readers/writers are never closed [1](#0-0) .

### Finding Description
`createReadersAndWriters` iterates over `i.relayers`, and for each chain calls `cr.Start(chainCtx)` and `cw.Start(chainCtx)` before adding them to the local `contractReaders`/`chainWriters` maps, which it returns on success [2](#0-1) . Back in `Create`, these maps are only assembled into the `closers` slice, and only after `libocr3.NewOracle` succeeds, at the very end of the function [3](#0-2) . Between the successful return of `createReadersAndWriters` (line 213) and that final block, several fallible calls occur: `getChainAccessorsAndContractTransmittersFromProviders` (line 216) and `createFactoryAndTransmitter` (line 249). `createFactoryAndTransmitter` fails with `unsupported Plugin type %d` when `config.Config.PluginType` is neither `PluginTypeCCIPCommit` nor `PluginTypeCCIPExec` [4](#0-3) . On any of these errors, `Create` returns `nil, fmt.Errorf(...)` directly (lines 223-224, 265-267), discarding `contractReaders` and `chainWriters` without calling `.Close()` on any of them and without invoking `newWrappedOracle`, so `wrappedOracle.Close` (which drives `services.CloseAll(o.closableResources...)`) never executes [5](#0-4) .

Since `config.Config.PluginType` is part of the on-chain `OCR3ConfigWithMeta` sourced from CCIPHome/CapabilitiesRegistry, an attacker who can register/update a CCIP DON config observed by the home chain reader can set an invalid/unsupported `PluginType` value while chain selector/offramp address are otherwise valid enough to let reader/writer creation for the relayer chains succeed, deterministically triggering this leak path on every `Create` call for that DON config.

### Impact Explanation
Each triggering call leaks started `io.Closer` resources (contract readers/writers per relayer chain) — these typically hold open RPC subscriptions/connections and background goroutines. Repeated triggering (e.g., via repeated config updates observed by the launcher, or across multiple DONs) causes unbounded resource accumulation (goroutines, file descriptors, RPC subscriptions) in the node process, leading to resource exhaustion and process-level denial of service. This matches a scoped "resource exhaustion / DoS on the node process" bounty impact category rather than fund loss or transaction tampering.

### Likelihood Explanation
Requires only that the attacker can get an `OCR3ConfigWithMeta` with an invalid `PluginType` (or another config combination that lets readers/writers start but fails later) observed by the plugin/launcher via CCIPHome/CapabilitiesRegistry — no node-operator privileges are needed per the stated precondition. The bug is deterministic given such a config: `createReadersAndWriters` succeeds while `createFactoryAndTransmitter` fails at the `else` branch unconditionally for any `PluginType` outside the two known enum values. Repeatability is high since the launcher will re-invoke `Create` whenever it re-evaluates DON configs.

### Recommendation
In `pluginOracleCreator.Create`, wrap the resource acquisition and factory/oracle-construction steps so that any error path after `createReadersAndWriters` succeeds explicitly closes the already-collected `contractReaders`, `chainWriters`, and `ccipProviders` (e.g., via a `defer`-based cleanup guarded by a "success" flag, or by moving the `closers` slice construction immediately after `createReadersAndWriters`/`createCCIPProviders` and deferring `services.CloseAll` unless `Create` succeeds).

### Proof of Concept
Unit test plan in `core/capabilities/ccip/oraclecreator/create_test.go`:
1. Construct a `pluginOracleCreator` with mock relayers whose `MultiChainRW.GetChainReader`/`GetChainWriter` return mock `types.ContractReader`/`types.ContractWriter` implementations wrapping `io.Closer` mocks (e.g., using `mocks.ContractReader`/`mocks.ContractWriter` with `Close()` expectations set via `.On("Close").Return(nil)`).
2. Build an `OCR3ConfigWithMeta` with a valid `ChainSelector`/`OfframpAddress` (so `createReadersAndWriters` binds and starts successfully) but `Config.PluginType` set to a value other than `PluginTypeCCIPCommit`/`PluginTypeCCIPExec` (e.g., `255`).
3. Call `pluginOracleCreator.Create(ctx, donID, config)`.
4. Assert `Create` returns an error containing `"unsupported Plugin type"`.
5. Assert on the mock reader/writer that `Close()` was never called (`AssertNotCalled(t, "Close")`), proving the started resources are never closed — demonstrating the leak.

func (o *wrappedOracle) Close() error {
	errs := make([]error, 0)

	if err := o.baseOracle.Close(); err != nil {
		errs = append(errs, fmt.Errorf("close base oracle: %w", err))
	}

	errs = append(errs, services.CloseAll(o.closableResources...))
