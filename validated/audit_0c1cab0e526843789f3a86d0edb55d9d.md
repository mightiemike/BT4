### Title
`DelegateResourceActuator`/`UnDelegateResourceActuator` mutate frozen/TronPower state without settling vote rewards first, unlike every analogous resource/vote actuator - (File: `actuator/src/main/java/org/tron/core/actuator/DelegateResourceActuator.java`, `actuator/src/main/java/org/tron/core/actuator/UnDelegateResourceActuator.java`)

### Summary
Every other actuator in java-tron that mutates an account's frozen balance, delegated balance, or votes (which determine TronPower and therefore vote-reward eligibility) explicitly calls `mortgageService.withdrawReward(ownerAddress)` before changing that state, so that rewards accrued up to the mutation point are correctly settled into `allowance` under the old TronPower/vote snapshot. `DelegateResourceActuator` and `UnDelegateResourceActuator`, which mutate the owner's frozen-for-bandwidth/energy V2 balances (and therefore the derived TronPower), never call `mortgageService.withdrawReward` at all. This mirrors the Venus `healAccount` bug class: a state-mutating operation that changes the debt/collateral snapshot underlying reward accrual, while skipping the reward-settlement hook that sibling operations always invoke first.

### Finding Description
`MortgageService.withdrawReward` / `VoteRewardUtil.withdrawReward` computes a vote reward for the `[beginCycle, currentCycle)` window using the account's vote list snapshot at the time reward is withdrawn, and only then updates `beginCycle`/`endCycle` and stores a new snapshot (`delegationStore.setAccountVote`) [1](#0-0) . Because reward computation is snapshot-based and keyed to when `withdrawReward` is invoked, every actuator that changes an account's frozen balance or votes calls it first so the reward accrued under the *old* balance/vote configuration is not lost or miscalculated when the configuration changes:

- `UnfreezeBalanceActuator.execute` calls `mortgageService.withdrawReward(ownerAddress)` before shrinking the frozen balance [2](#0-1) .
- `UnfreezeBalanceV2Actuator.execute` does the same before modifying `FrozenV2`/tron power [3](#0-2) .
- `VoteWitnessActuator.countVoteAccount` calls it before clearing/rewriting the vote list [4](#0-3) .
- `WithdrawBalanceActuator.execute` calls it before touching balance/allowance [5](#0-4) .
- TVM-native equivalents (`UnfreezeBalanceProcessor`, `UnfreezeBalanceV2Processor`, `VoteWitnessProcessor`, `Program.suicide`/`suicide2` via `withdrawRewardAndCancelVote`) all call `VoteRewardUtil.withdrawReward` before mutating frozen balance, votes, or destroying the account [6](#0-5) [7](#0-6) [8](#0-7) .

By contrast, `DelegateResourceActuator.execute` directly mutates `ownerCapsule`'s `FrozenV2BalanceForBandwidth`/`FrozenV2BalanceForEnergy` and `DelegatedFrozenV2Balance...` fields and persists the account with no call to `mortgageService.withdrawReward` anywhere in the method [9](#0-8) . `UnDelegateResourceActuator.execute` likewise mutates both the owner's and receiver's delegated/acquired frozen V2 balances and bandwidth/energy usage without ever calling `mortgageService.withdrawReward` [10](#0-9) . A repo-wide search of `actuator/src/main/java/org/tron/core/actuator/*.java` confirms `withdrawReward` is only referenced in `UnfreezeBalanceActuator`, `UnfreezeBalanceV2Actuator`, `VoteWitnessActuator`, and `WithdrawBalanceActuator` — `DelegateResourceActuator` and `UnDelegateResourceActuator` are conspicuously absent from that list.

Because `AccountCapsule` derives TronPower (and thus voting capacity and reward eligibility) from delegated/frozen balances, mutating those balances via delegate/undelegate transactions changes the effective staking snapshot an account is voting with, while the pending, already-accrued reward for the prior cycle window is never flushed into `allowance` at that boundary. This is structurally identical to the Venus `healAccount` finding: the state change that should trigger reward settlement (analogous to `market.healBorrow` clearing debt) bypasses the hook (analogous to `preSeizeHook`) that sibling operations reliably invoke.

### Impact Explanation
If reward computation/eligibility is sensitive to the account's vote/TronPower snapshot at the moment it changes, an account that repeatedly delegates/undelegates resources without an intervening `withdrawReward`-triggering transaction (unfreeze, vote, or withdraw-balance) accrues rewards under snapshots that are never correctly checkpointed at the delegate/undelegate boundary. This can lead to under- or mis-accounted voter rewards for the affected address, i.e. resource/reward accounting corruption reachable purely through ordinary `DelegateResourceContract`/`UnDelegateResourceContract` broadcast transactions — no privileged role required.

### Likelihood Explanation
Delegate/undelegate resource transactions are a routine, frequently used unprivileged feature (`DelegateResourceContract`/`UnDelegateResourceContract`) available to any account holder, making the missing-hook code path trivially and repeatedly reachable in normal operation.

### Recommendation
Add `mortgageService.withdrawReward(ownerAddress)` (and, where the receiver's TronPower/votes could also be implicated, the receiver as well) at the start of `DelegateResourceActuator.execute` and `UnDelegateResourceActuator.execute`, mirroring the pattern already used in `UnfreezeBalanceActuator`, `UnfreezeBalanceV2Actuator`, and `VoteWitnessActuator`, so that any reward accrued under the pre-mutation TronPower/vote snapshot is settled before the frozen/delegated balances are changed.

### Proof of Concept
Not independently reproduced with a live TronVM test in this analysis; the finding is derived from static comparison of `DelegateResourceActuator`/`UnDelegateResourceActuator` against the four sibling actuators/processors that all call `mortgageService.withdrawReward`/`VoteRewardUtil.withdrawReward` before an equivalent state mutation. A concrete PoC would require confirming (via `AccountCapsule.getTronPower`/`getAllTronPower`, not fully retrievable in this session due to index size limits) that `FrozenV2BalanceForBandwidth/Energy` and `DelegatedFrozenV2Balance...` feed into the TronPower value used by `VoteRewardUtil.computeReward`'s snapshot window, and then constructing a sequence of `DelegateResourceContract`/`VoteWitnessContract`/maintenance-cycle transactions that demonstrates a reward-accounting discrepancy. Recommend a Devin session with full repo/test access to write and run such a test in `framework/src/test/java/org/tron/core/actuator/DelegateResourceActuatorTest.java` or `UnDelegateResourceActuatorTest.java`.

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }

    final long unDelegateBalance = unDelegateResourceContract.getBalance();
    byte[] ownerAddress = unDelegateResourceContract.getOwnerAddress().toByteArray();
    byte[] receiverAddress = unDelegateResourceContract.getReceiverAddress().toByteArray();

    AccountCapsule receiverCapsule = accountStore.get(receiverAddress);

    long transferUsage = 0;
    // modify receiver Account
    if (receiverCapsule != null) {
      long now = chainBaseManager.getHeadSlot();
      switch (unDelegateResourceContract.getResource()) {
        case BANDWIDTH:
          BandwidthProcessor bandwidthProcessor = new BandwidthProcessor(chainBaseManager);
          bandwidthProcessor.updateUsageForDelegated(receiverCapsule);

          if (receiverCapsule.getAcquiredDelegatedFrozenV2BalanceForBandwidth()
              < unDelegateBalance) {
            // A TVM contract suicide, re-create will produce this situation
            receiverCapsule.setAcquiredDelegatedFrozenV2BalanceForBandwidth(0);
          } else {
            // calculate usage
            long unDelegateMaxUsage = (long) ((double) unDelegateBalance / TRX_PRECISION
                * ((double) (dynamicStore.getTotalNetLimit()) / dynamicStore.getTotalNetWeight()));
            transferUsage = (long) (receiverCapsule.getNetUsage()
                * ((double) (unDelegateBalance) / receiverCapsule.getAllFrozenBalanceForBandwidth()));
            transferUsage = min(unDelegateMaxUsage, transferUsage);

            receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(-unDelegateBalance);
          }

          long newNetUsage = receiverCapsule.getNetUsage() - transferUsage;
          receiverCapsule.setNetUsage(newNetUsage);
          receiverCapsule.setLatestConsumeTime(now);
          break;
        case ENERGY:
          EnergyProcessor energyProcessor = new EnergyProcessor(dynamicStore, accountStore);
          energyProcessor.updateUsage(receiverCapsule);

          if (receiverCapsule.getAcquiredDelegatedFrozenV2BalanceForEnergy()
              < unDelegateBalance) {
            // A TVM contract receiver, re-create will produce this situation
            receiverCapsule.setAcquiredDelegatedFrozenV2BalanceForEnergy(0);
          } else {
            // calculate usage
            long unDelegateMaxUsage = (long) ((double) unDelegateBalance / TRX_PRECISION
                * ((double) (dynamicStore.getTotalEnergyCurrentLimit()) / dynamicStore.getTotalEnergyWeight()));
            transferUsage = (long) (receiverCapsule.getEnergyUsage()
                * ((double) (unDelegateBalance) / receiverCapsule.getAllFrozenBalanceForEnergy()));
            transferUsage = min(unDelegateMaxUsage, transferUsage);

            receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForEnergy(-unDelegateBalance);
          }

          long newEnergyUsage = receiverCapsule.getEnergyUsage() - transferUsage;
          receiverCapsule.setEnergyUsage(newEnergyUsage);
          receiverCapsule.setLatestConsumeTimeForEnergy(now);
          break;
        default:
          //this should never happen
          break;
      }
      accountStore.put(receiverCapsule.createDbKey(), receiverCapsule);
    }

    // transfer lock delegate to unlock
    delegatedResourceStore.unLockExpireResource(ownerAddress, receiverAddress,
        dynamicStore.getLatestBlockHeaderTimestamp());

    byte[] unlockKey = DelegatedResourceCapsule
        .createDbKeyV2(ownerAddress, receiverAddress, false);
    DelegatedResourceCapsule unlockResource = delegatedResourceStore
        .get(unlockKey);

    // modify owner Account
    AccountCapsule ownerCapsule = accountStore.get(ownerAddress);
    switch (unDelegateResourceContract.getResource()) {
      case BANDWIDTH: {
        unlockResource.addFrozenBalanceForBandwidth(-unDelegateBalance, 0);

        ownerCapsule.addDelegatedFrozenV2BalanceForBandwidth(-unDelegateBalance);
        ownerCapsule.addFrozenBalanceForBandwidthV2(unDelegateBalance);

        BandwidthProcessor processor = new BandwidthProcessor(chainBaseManager);

        long now = chainBaseManager.getHeadSlot();
        if (Objects.nonNull(receiverCapsule) && transferUsage > 0) {
          processor.unDelegateIncrease(ownerCapsule, receiverCapsule,
              transferUsage, BANDWIDTH, now);
        }
      }
      break;
      case ENERGY: {
        unlockResource.addFrozenBalanceForEnergy(-unDelegateBalance, 0);

        ownerCapsule.addDelegatedFrozenV2BalanceForEnergy(-unDelegateBalance);
        ownerCapsule.addFrozenBalanceForEnergyV2(unDelegateBalance);

        EnergyProcessor processor = new EnergyProcessor(dynamicStore, accountStore);

        long now = chainBaseManager.getHeadSlot();
        if (Objects.nonNull(receiverCapsule) && transferUsage > 0) {
          processor.unDelegateIncrease(ownerCapsule, receiverCapsule, transferUsage, ENERGY, now);
        }
      }
      break;
      default:
        //this should never happen
        break;
    }

    if (unlockResource.getFrozenBalanceForBandwidth() == 0
        && unlockResource.getFrozenBalanceForEnergy() == 0) {
      delegatedResourceStore.delete(unlockKey);
      unlockResource = null;
    } else {
      delegatedResourceStore.put(unlockKey, unlockResource);
    }

    byte[] lockKey = DelegatedResourceCapsule
        .createDbKeyV2(ownerAddress, receiverAddress, true);
    DelegatedResourceCapsule lockResource = delegatedResourceStore
        .get(lockKey);
    if (lockResource == null && unlockResource == null) {
      //modify DelegatedResourceAccountIndexStore
      delegatedResourceAccountIndexStore.unDelegateV2(ownerAddress, receiverAddress);
    }

    accountStore.put(ownerAddress, ownerCapsule);

    ret.setStatus(fee, code.SUCESS);

    return true;
  }
