### Title
Missing declared-class validation in Starknet OS `execute_replace_class` diverges from Blockifier's enforcement, breaking OS proof soundness for `replace_class_syscall` - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS's own Cairo implementation of the `replace_class` syscall never verifies that the target `class_hash` corresponds to a class that was actually declared, while the Blockifier (the component that actually executes transactions to build/validate blocks) enforces exactly this check before allowing the same state mutation. This is the same bug shape as the Craft CMS advisory: one code path (the "source" gate — Blockifier's real execution) enforces the necessary authorization/validity check, while the parallel path that ultimately produces the committed/attested result (the "destination" gate — the OS's state-transition function used to build the proof) omits it, letting an operation succeed in the weaker path that the stronger path would have rejected.

### Finding Description
When a Cairo1 (or Cairo0) contract invokes the `replace_class` syscall, the Blockifier's syscall handler independently confirms the target class hash is declared before mutating state: [1](#0-0) 

Same enforcement exists in the deprecated (Cairo0) syscall handler: [2](#0-1) 

However, the Starknet OS's own Cairo re-implementation of this syscall — the code that is actually arithmetized and proven, and which is supposed to be an independent, self-contained specification of valid state transitions — has an explicit acknowledged gap: [3](#0-2) 

The comment at line 902, `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`, confirms the check is known to be missing. The same omission exists in the legacy (Cairo0) OS syscall implementation: [4](#0-3) 

Additionally, the Rust-side SNOS syscall executor for `replace_class` is a complete no-op that performs no validation and simply returns success: [5](#0-4) 

Because Cairo's execution model relies on hints to *suggest* values and on explicit `assert`/constraint code to *enforce* correctness, the absence of an assertion tying `class_hash` to an actually-declared class means the OS's `contract_state_changes` dict can be updated to any prover-supplied class hash felt, without the OS itself ever verifying that value against the declared-class set (`contract_class_changes`/class hash tree). This makes the OS's accepted state-transition rules for `replace_class` strictly weaker than the Blockifier's, which is precisely the "destination check is weaker than the source check" pattern from the advisory.

### Impact Explanation
The Starknet OS is the ground-truth state-transition specification executed inside the STARK proof that is ultimately verified and whose output (new state root) is committed. If the OS's internal rules for a given syscall are laxer than the Blockifier's rules that honest sequencer/validator nodes actually enforce during block building and re-execution, the OS can be made to attest as valid a state transition (assigning a contract to an arbitrary, undeclared class hash) that the Blockifier itself would have rejected as reverted. This is a wrong-committed-root / honest-node-divergence class of issue: the value the network's execution layer considers invalid can be presented to and accepted by the proving layer, undermining the integrity guarantee that the L1-committed root faithfully reflects protocol-valid execution of the block's transactions.

### Likelihood Explanation
Exploiting the OS-side gap requires supplying the OS with a hint (`GetContractAddressStateEntry`) that claims a `replace_class` call "succeeded" with an undeclared class hash, which does not occur during ordinary honest execution because Blockifier reverts such calls before they ever occur. Reaching this divergence in practice requires control over the execution trace fed to the OS (i.e., the block/proof-input construction), rather than being triggerable by an ordinary end user through a single transaction alone. This tempers the likelihood, but the missing check remains a genuine soundness bug in the OS specification for a syscall directly reachable via a plain `INVOKE` transaction executing `replace_class_syscall`, and the code explicitly documents the gap as an open TODO rather than an intentional design decision.

### Recommendation
Add an explicit assertion in `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo`) that the supplied `class_hash` exists in `contract_class_changes` (i.e., has been declared, mirroring the check present in `contract_class_changes` lookups elsewhere in the OS) before performing the `dict_update` on `contract_state_changes`, matching the guarantee already enforced in `crates/blockifier/src/execution/syscalls/syscall_base.rs::replace_class` and `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs::replace_class`. Also implement real validation logic in `crates/starknet_os/src/hint_processor/snos_syscall_executor.rs::replace_class` instead of the current no-op.

### Proof of Concept
1. Deploy a Cairo1 contract that calls `replace_class_syscall(arbitrary_undeclared_class_hash)`.
2. Under normal Blockifier execution, the call reverts with "is not declared" (verified by tests in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
3. If the same execution trace/hints are instead supplied directly to the Starknet OS state-transition function (`execute_replace_class` in `syscall_impls.cairo`), it accepts the undeclared class hash and updates `contract_state_changes` with no validation, since the only check that would prevent this is marked as an unimplemented TODO at line 902 of `syscall_impls.cairo`.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
