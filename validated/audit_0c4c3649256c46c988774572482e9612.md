### Title
`getEmbeddedAppUrl`/`buildEmbeddedAppUrl` validate a stripped hostname but embed the raw (CRLF-containing) decoded host in the returned URL - (File: `packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts`)

### Summary
`buildEmbeddedAppUrl` validates the `host` query parameter with `sanitizeHost`, then independently re-decodes the same base64 `host` value with `decodeHost` and interpolates that raw decoded string directly into the returned URL. Because `sanitizeHost` validates the hostname through `new URL()` (which silently strips ASCII tab/CR/LF from the entire input before parsing per the WHATWG URL spec), while the value actually embedded in the output URL is the un-stripped `atob()` decode, an attacker can craft a base64 `host` value whose decoded bytes contain `\r`/`\n`/`\t` that get invisibly removed during validation but are preserved in the final `https://${decodedHost}/apps/${apiKey}` string.

### Finding Description
- `buildEmbeddedAppUrl` in `packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts` does:
  - `sanitizeHost(config)(host, true)` — throws only if invalid.
  - `const decodedHost = decodeHost(host);` — decodes the *same* raw `host` param again.
  - `return \`https://${decodedHost}/apps/${config.apiKey}\`;` [1](#0-0) 

- Inside `sanitizeHost` (`packages/apps/shopify-api/lib/utils/shop-validator.ts`), the base64 string is decoded and passed through `new URL(...)`, and only the resulting `hostname` field is checked against the allow-listed domain regex: [2](#0-1) 

  `new URL()` (WHATWG URL parser) strips all ASCII tab/CR/LF from the entire input string before parsing, so a decoded value like `test.myshop\r\nify.com` is normalized to `test.myshopify.com` for the purposes of the `hostRegex` check — it passes validation.

- `decodeHost` is a trivial `atob(host)` with no stripping: [3](#0-2) 

- Because the `host` param is only constrained to the base64 alphabet (`^[0-9a-zA-Z+/]+={0,2}$`) before decoding, its decoded bytes can be arbitrary, including `\r`, `\n`, `\t`. The value used in `sanitizeHost`'s check (parsed/stripped `hostname`) and the value embedded in the final returned URL (raw `decodeHost(host)`) are therefore inconsistent — the validated string and the used string are not the same string. This breaks the stated invariant that "the embedded app URL host is verified."
- Result: `buildEmbeddedAppUrl`/`getEmbeddedAppUrl` can return a string such as `https://test.myshop\r\nify.com/apps/test_key` despite `sanitizeHost` having "approved" the host.

The `applyDomainTransformations` function itself in `domain-transformer.ts` is not directly reachable with attacker-controlled CRLF in this path — it is only invoked from `sanitizeShop`, not from `sanitizeHost`/`buildEmbeddedAppUrl`, and it only substitutes previously-matched regex groups, so it does not independently introduce CRLF. The actual embedded-URL injection root cause is the double-decode/validate-vs-use mismatch in `get-embedded-app-url.ts` described above, which is the closest concretely reachable variant of the reported issue. [4](#0-3) 

### Impact Explanation
This allows injection of control characters (tab/CR/LF) into a URL string that the library asserts has a "verified" host, which is subsequently used by consumers (e.g. `shopify-app-express`'s `redirectToShopifyOrAppRoot` calling `res.redirect(redirectUrl)`) as a redirect target. On a standard Node `http`/Express server, `res.redirect`/`setHeader` performs its own header-character validation (`ERR_INVALID_CHAR`) and will throw rather than emit a split header — so on Node this degrades to an unhandled exception (denial of service) in the redirect middleware rather than full response splitting. On runtimes/adapters that do not perform the same header validation, the same primitive could enable true HTTP response splitting (injected headers/body) in the redirect response, which is the open-redirect/header-injection class relevant to Shopify's HackerOne scope.

### Likelihood Explanation
The attacker only needs to be an unprivileged party able to send a crafted `host` query parameter on any request that triggers `getEmbeddedAppUrl`/`buildEmbeddedAppUrl` (or the `redirectToShopifyOrAppRoot`/`ensure-installed-on-shop` middlewares that call it) — no secrets, no prior authentication, and no non-default configuration are required. Constructing a valid base64 string whose decoded bytes normalize (after CRLF/tab stripping) to an allow-listed `*.myshopify.com`-style hostname is straightforward and fully attacker-controlled.

### Recommendation
Make `buildEmbeddedAppUrl` use the exact value that was validated, instead of re-decoding the raw `host` param a second time. Concretely, have `sanitizeHost` return the decoded/sanitized hostname (the same string it validated via `new URL()`) and have `buildEmbeddedAppUrl` build the final URL from that returned, already-stripped value, rather than calling `decodeHost(host)` independently. Additionally, explicitly reject any decoded host containing control characters (`\r`, `\n`, `\t`, or other C0 controls) rather than relying on `URL`'s silent stripping behavior for validation.

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/auth/__tests__/get-embedded-app-url.test.ts

test('CRLF survives sanitizeHost validation into the built URL', async () => {
  const shopify = shopifyApi(testConfig());

  // decoded value normalizes (after CR/LF stripping by URL parsing) to
  // "test.myshopify.com/admin", so sanitizeHost's hostname check passes,
  // but the raw decoded bytes still contain \r\n.
  const rawHost = 'test.myshop\r\nify.com/admin';
  const base64Host = Buffer.from(rawHost, 'utf-8').toString('base64');

  const req = {
    method: 'GET',
    url: `?shop=test.myshopify.com&host=${base64Host}`,
    headers: {host: 'test.myshopify.com'},
  };

  const url = await shopify.auth.getEmbeddedAppUrl({rawRequest: req as any});

  // The returned "verified" URL still contains raw CR/LF bytes.
  expect(url).toContain('\r\n');
});
```
Expected result: the assertion passes, demonstrating that `sanitizeHost`'s validation (which "approves" the host) and the actual string returned by `buildEmbeddedAppUrl` diverge, with the latter retaining injected `\r\n` bytes.

```typescript
export function buildEmbeddedAppUrl(
  config: ConfigInterface,
): BuildEmbeddedAppUrl {
  return (host: string): string => {
    sanitizeHost(config)(host, true);
    const decodedHost = decodeHost(host);

    return `https://${decodedHost}/apps/${config.apiKey}`;
  };
}
```

```typescript
export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
```

```typescript
export function applyDomainTransformations(
  shopUrl: string,
  config: ConfigInterface,
): string | null {
  if (
    !config.domainTransformations ||
    config.domainTransformations.length === 0
  ) {
    return shopUrl;
  }

  for (const transformation of config.domainTransformations) {
    const regex =
      typeof transformation.match === 'string'
        ? new RegExp(transformation.match)
        : transformation.match;

    const matches = shopUrl.match(regex);

    if (!matches) {
      continue;
    }

    if (typeof transformation.transform === 'function') {
      return transformation.transform(matches);
    }

    let result = transformation.transform;
    matches.forEach((match, index) => {
      result = result.replace(new RegExp(`\\$${index}`, 'g'), match || '');
    });

    return result;
  }

  return shopUrl;
}
```
