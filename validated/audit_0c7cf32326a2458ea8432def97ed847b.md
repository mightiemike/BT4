### Title
`library_call`/`library_call_l1_handler` syscalls omit the `block_direct_execute_call` guard applied to `call_contract`, allowing a bypassed direct invocation of `__execute__` - (File: `crates/blockifier/src/execution/syscalls/hint_processor.rs`, `crates/blockifier/src/execution/native/syscall_handler.rs`, `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`)

### Summary
The protocol explicitly forbids contracts from directly invoking another contract's `__execute__` entry point through the `call_contract` syscall. This restriction is implemented as a selector check (`selector == EXECUTE_ENTRY_POINT_NAME`) inside the `call_contract` handler in every execution backend (VM syscalls, Native syscalls, deprecated Cairo0 syscalls) and mirrored in the Starknet OS Cairo code. However, the semantically equivalent `library_call`/`library_call_l1_handler` handlers, which also let a contract invoke an arbitrary entry point of an arbitrary declared class by selector, never perform this check. This is directly analogous to the reported `SettV3.transferFrom` bug, where a security guard (`_blockLocked`) was enforced on one function (`transfer`) but not on the alternate code path (`transferFrom`) that achieves the same effect, letting an attacker bypass the intended protection.

### Finding Description
The guard is defined in `maybe_block_direct_execute_call` and invoked only from the `call_contract` implementations: [1](#0-0) 

Both the VM and Native `call_contract` handlers call this guard (or an equivalent inline check) before dispatching the inner call: [2](#0-1) [3](#0-2) 

The deprecated (Cairo0) syscall path does the same: [4](#0-3) 

By contrast, none of the `library_call` implementations check the selector against `EXECUTE_ENTRY_POINT_NAME`/`EXECUTE_ENTRY_POINT_SELECTOR` at all: [5](#0-4) [6](#0-5) [7](#0-6) [8](#0-7) 

The Starknet OS Cairo re-execution logic reproduces the same asymmetry: `CALL_CONTRACT_SELECTOR` handling explicitly asserts the selector is not `EXECUTE_ENTRY_POINT_SELECTOR`, while `LIBRARY_CALL_SELECTOR` handling performs no such assertion: [9](#0-8) [10](#0-9) 

Because `library_call` preserves the current call's `caller_address` and `storage_address` (delegate-call semantics — "the call context remains the same in a library call"), a contract's `__execute__` (already invoked by the OS with `caller_address == 0`) can invoke `library_call_syscall(class_hash=<self or any declared class>, selector=EXECUTE_ENTRY_POINT_SELECTOR, ...)`. This re-enters the `__execute__` logic of the target class while keeping the inherited `caller_address` value from the outer call (which is `0` at the top level), satisfying any `assert(get_caller_address().is_zero())`-style guard that account contracts use to detect "am I the top-level entry point" — exactly the condition `block_direct_execute_call` is meant to prevent from being reachable other than through the OS's own top-level dispatch.

### Impact Explanation
`block_direct_execute_call` was introduced (see `blockifier_versioned_constants.rs` flag `block_direct_execute_call`, tests `test_direct_execute_call`/`test_call_execute_directly`) specifically to prevent contracts from re-entering or externally triggering another account's `__execute__` entry point outside of the OS's controlled top-level transaction dispatch flow. Bypassing it via `library_call` breaks the invariant that `__execute__` can only run once, as the single top-level call driven by the OS after `__validate__` and nonce/fee accounting. A contract able to recursively/directly re-invoke `__execute__` logic through `library_call` can:
- Re-run execution logic multiple times within a single transaction without incurring additional nonce increments or fee charges tied to that logic (since nonce/fee handling happens once, outside the call graph),
- Potentially confuse other contracts relying on the "no direct `__execute__` calls" invariant for their own security assumptions (e.g., accounts assuming `__execute__` cannot be invoked as a sub-call by third parties),
- Cause honest-node/consensus-safe but semantically incorrect execution since the OS's protective invariant ("it is forbidden to call the `__execute__` function") is only enforced for `CALL_CONTRACT_SELECTOR`, not `LIBRARY_CALL_SELECTOR`, in both the sequencer's blockifier and the Starknet OS re-execution program, so the bypass is consistent and reproducible by any node re-executing the block — not a divergence bug, but a genuine circumvention of a stated security control reachable from a single ordinary invoke transaction.

### Likelihood Explanation
The bypass requires only a single account-abstraction transaction: any contract that can call `library_call_syscall` with an attacker-chosen `class_hash` (its own class, or any declared class implementing `__execute__`) and selector `__execute__` can trigger this path. No special privileges, sequencer/operator control, or multi-transaction coordination are needed — it is directly reachable by any contract call within a submitted transaction's execution, making this a High-likelihood, unprivileged-transaction-sender-reachable issue.

### Recommendation
Apply the same `block_direct_execute_call`/`EXECUTE_ENTRY_POINT_SELECTOR` check inside `library_call` and `library_call_l1_handler` in all three execution backends (`crates/blockifier/src/execution/syscalls/hint_processor.rs`, `crates/blockifier/src/execution/native/syscall_handler.rs`, `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`), and add the corresponding `assert_not_equal(..., EXECUTE_ENTRY_POINT_SELECTOR)` to the `LIBRARY_CALL_SELECTOR` handling in the Starknet OS Cairo program (`deprecated_execute_syscalls.cairo` and `syscall_impls.cairo`), mirroring the existing `call_contract` guard, so the invariant "calling `__execute__` directly is not allowed" holds uniformly across all call-dispatch syscalls.

### Proof of Concept
1. Deploy (or use) an account contract `Victim` whose `__execute__` performs privileged/side-effecting logic and internally checks `assert(get_caller_address().is_zero(), ...)` to ensure it is only invoked as the top-level call.
2. Deploy an attacker contract `Attacker` that, from within its own `__execute__` (invoked normally by the OS with `caller_address == 0`), calls:
   `library_call_syscall(class_hash: Victim's class hash, function_selector: selector!("__execute__"), calldata: [...])`
3. Because `library_call` preserves the current call context's `caller_address` (still `0`, inherited from the OS's top-level dispatch) and does not check the selector against `EXECUTE_ENTRY_POINT_SELECTOR` (unlike `call_contract`, which would reject this with `DirectExecuteCall`/`InvalidSyscallInExecutionMode`), the call succeeds and `Victim`'s `__execute__` logic runs in `Attacker`'s storage context, with `get_caller_address()` returning `0` — satisfying the top-level-only check that `block_direct_execute_call` is designed to prevent from being spoofed.
4. Contrast with the existing test `test_direct_execute_call` (`crates/blockifier/src/execution/syscalls/syscall_tests/call_contract.rs:277-345` and `crates/blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo:449-471`), which confirms `call_contract` with selector `__execute__` is rejected with `Invalid argument` when `block_direct_execute_call` is on — no equivalent test or rejection exists for `library_call` with the same selector.

            ),
        })?;

pub fn execute_library_call(
    syscall_handler: &mut DeprecatedSyscallHintProcessor<'_>,
    vm: &mut VirtualMachine,
    class_hash: ClassHash,
    code_address: Option<ContractAddress>,
    call_to_external: bool,
    entry_point_selector: EntryPointSelector,
    calldata: Calldata,
) -> DeprecatedSyscallResult<ReadOnlySegment> {
    let entry_point_type =
        if call_to_external { EntryPointType::External } else { EntryPointType::L1Handler };
    let entry_point = CallEntryPoint {
        class_hash: Some(class_hash),
        code_address,
        entry_point_type,
        entry_point_selector,
        calldata,
        // The call context remains the same in a library call.
        storage_address: syscall_handler.storage_address,
        caller_address: syscall_handler.caller_address,
        call_type: CallType::Delegate,
        initial_gas: syscall_handler.context.gas_costs().base.default_initial_gas_cost,
    };

    execute_inner_call(entry_point, vm, syscall_handler).map_err(|error| {
        error.as_lib_call_execution_error(
            class_hash,
            syscall_handler.storage_address,
            entry_point_selector,
        )
    })
}

func execute_call_contract{
    range_check_ptr,
    syscall_ptr: felt*,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    revert_log: RevertLogEntry*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, caller_execution_context: ExecutionContext*) {
    let request = cast(syscall_ptr + RequestHeader.SIZE, CallContractRequest*);
    let (success, remaining_gas) = reduce_syscall_base_gas(
        specific_base_gas_cost=CALL_CONTRACT_GAS_COST, request_struct_size=CallContractRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }
    if (request.selector == EXECUTE_ENTRY_POINT_SELECTOR) {
        write_failure_response(remaining_gas=remaining_gas, failure_felt=ERROR_INVALID_ARGUMENT);
        return ();
    }

    tempvar contract_address = request.contract_address;
    let (state_entry: StateEntry*) = dict_read{dict_ptr=contract_state_changes}(
        key=contract_address
    );

    // Prepare execution context.
    // TODO(Yoni, 1/1/2026): change ExecutionContext to hold calldata_start, calldata_end.
    tempvar calldata_start = request.calldata_start;
    tempvar caller_execution_info = caller_execution_context.execution_info;
    tempvar caller_address = caller_execution_info.contract_address;
    tempvar execution_context: ExecutionContext* = new ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=state_entry.class_hash,
        calldata_size=request.calldata_end - calldata_start,
        calldata=calldata_start,

            block_info=caller_execution_info.block_info,
            tx_info=caller_execution_info.tx_info,
            caller_address=caller_address,
            contract_address=contract_address,
            selector=request.selector,
        ),
        deprecated_tx_info=caller_execution_context.deprecated_tx_info,
    );

    // Since we process the revert log backwards, entries before this point belong to the caller.
    assert [revert_log] = RevertLogEntry(selector=CHANGE_CONTRACT_ENTRY, value=caller_address);
    let revert_log = &revert_log[1];

    contract_call_helper(
        remaining_gas=remaining_gas,
        block_context=block_context,
        execution_context=execution_context,
    );

    // Entries before this point belong to the callee.
    assert [revert_log] = RevertLogEntry(
        selector=CHANGE_CONTRACT_ENTRY, value=request.contract_address
    );
    let revert_log = &revert_log[1];

    return ();
}
