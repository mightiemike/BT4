## Analog Found: Sandwichable Spot-Price AMM Swaps in Inbound Gas-Abstraction and Outbound Gas-Refund Flows

### Title
Unprivileged sandwich attack on `ExecuteInboundGas` / `applyGasRefund` auto-swaps via manipulable spot-price `QuoterV2.quoteExactInputSingle` with fixed 5% slippage — (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The Malt report's root cause is a permissionless, price-triggered protocol action (`stabilize`) that reads a manipulable spot price and moves value, letting an attacker sandwich it for profit at the expense of protocol/investor funds. Push Chain has a structurally identical pattern: `ExecuteInboundGas` (autoswap on gas-abstracted deposits) and `applyGasRefund` (excess-gas refund on outbound completion) both fetch a **live spot-price quote** from Uniswap `QuoterV2.quoteExactInputSingle` and immediately execute a swap bounded only by a fixed 5% slippage tolerance, with no TWAP or manipulation resistance [1](#0-0) . Because the swap is triggered as a side effect of the quorum-completing `MsgVoteInbound`/`MsgVoteOutbound` transaction — a transaction visible in the public mempool before it lands — an unprivileged attacker can sandwich it: push the PRC20/WPC pool price down immediately before the triggering vote lands, let the module's swap execute against the depressed price (still within the loose 5% band), then reverse the price afterward, extracting the difference at the expense of the depositing/refunded user.

### Finding Description
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `commit=false`, i.e., a read against the pool's current reserves at the moment of execution [2](#0-1) . Both consumers of this quote compute `minPCOut` as a flat 5% slippage bound and pass it straight into the same-block swap call:

- `ExecuteInboundGas` (runs when `MsgVoteInbound` reaches quorum, driven by an ordinary user's cross-chain gas-abstracted deposit): fetches `quote` then immediately calls `CallPRC20DepositAutoSwap` with `minPCOut = quote * 95 / 100` [3](#0-2) .
- `applyGasRefund` (runs when `MsgVoteOutbound` observes a completed outbound, refunding unused gas): does the same via `getSwapQuoteForRefund` → `CallUniversalCoreRefundUnusedGas` with an identical 95/100 slippage bound [4](#0-3) .

Both flows are reachable purely from ordinary, unprivileged usage: any user submitting a cross-chain `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` deposit, or any outbound completion, triggers the autoswap/refund path automatically [5](#0-4) . The triggering messages (`MsgVoteInbound`, `MsgVoteOutbound`) are also part of the gasless allowlist and pass through the ordinary CometBFT mempool [6](#0-5) , meaning the exact block/moment the swap will execute is visible to anyone watching the mempool for the quorum-completing vote. An attacker can:
1. Watch the mempool for the 2/3-quorum `MsgVoteInbound`/`MsgVoteOutbound` transaction that will trigger the autoswap/refund.
2. Front-run it with a large swap on the PRC20↔WPC pool, moving the spot price down (but within any single-swap price-impact bound the pool imposes, well inside the protocol's tolerated 5%).
3. Let the module's deposit-autoswap or gas-refund swap execute at the manipulated price — the module accepts it because `minPCOut` is computed from the *same* manipulated quote, not an independent, manipulation-resistant reference price.
4. Back-run by reversing the price, capturing the spread. The depositing/refunded user's PRC20/native accounting is short-changed relative to a fair market swap; the attacker profits without holding any prior balance in the PRC20/WPC pool beyond the capital used for the sandwich (which can itself be a flash-loan-style same-tx borrow via any DEX/lending precompile or flashswap on the AMM the pool lives on, mirroring the Malt PoC).

The failure mode is exactly the report's class: a permissionless, price-sensitive protocol action is gated by a self-referential spot-price check instead of a manipulation-resistant oracle, so it can be sandwiched to redirect value from the intended party (the user's UEA balance in `ExecuteInboundGas`, or the refund recipient in `applyGasRefund`) to an unrelated MEV actor.

### Impact Explanation
This corrupts PRC20/native asset accounting for the deposited/refunded amount — the user's UEA or refund recipient receives less than fair value while an unprivileged attacker captures the difference, which is "unauthorized...refund" / "corruption of PRC20 or native asset accounting" per the allowed impact gate. Because these flows execute automatically for every gas-abstracted inbound deposit and every outbound gas refund, the surface is broad and recurring, not a one-off edge case.

### Likelihood Explanation
Medium-High: the attack requires no privileged role — only mempool visibility (public in CometBFT) and capital to move the pool within the accepted 5% band, both of which are freely available to any external actor. The main constraint is pool liquidity depth/gas timing, same as the original Malt report's judged severity (Medium, per the report itself).

### Recommendation
Replace the same-block spot-price `quoteExactInputSingle` reference with a manipulation-resistant reference (e.g., TWAP oracle, or a validator-attested/median price analogous to the existing `GasPrice`/`ChainMeta` median-of-votes mechanism already used elsewhere in `x/uexecutor/keeper/chain_meta.go`), and/or tighten and dynamically compute slippage bounds instead of a static 5%, and consider requiring the quote to be fetched in a prior block/committed state rather than the same execution as the swap.

### Proof of Concept
1. Attacker monitors the CometBFT mempool for the third/quorum-completing `MsgVoteInbound` for a pending `GAS_AND_PAYLOAD` inbound (or `MsgVoteOutbound` for a pending outbound with excess gas).
2. Attacker submits a large swap on the PRC20/WPC Uniswap pool ahead of that transaction in the same block, depressing the PRC20→WPC price within the pool's normal single-block price-impact range (up to but not exceeding the protocol's own 5% tolerance).
3. The quorum vote lands and executes `ExecuteInboundGas`/`applyGasRefund`, which calls `GetSwapQuote` against the now-depressed pool and computes `minPCOut = quote*95/100` from that depressed quote [7](#0-6) , then executes `depositPRC20WithAutoSwap`/`refundUnusedGas` against the depressed pool, delivering fewer PC/WPC to the UEA/recipient than a fair-price swap would.
4. Attacker submits a reversing swap immediately after, restoring the price and net profiting from the temporary price dislocation at the expense of the deposit/refund recipient.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
