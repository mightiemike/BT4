### Title
JSON/Text pretty-printers emit O(n²) depth-proportional indentation for deeply-nested trusted-schema messages, enabling output-size amplification DoS - ([File: internal/encoding/json/encode.go])

### Summary
`protojson.MarshalOptions{Indent: ...}` / `Multiline: true` (and the analogous `prototext.MarshalOptions`) pretty-print a decoded message by re-emitting the full current indentation prefix before every field, array element, or object member. The indentation buffer (`Encoder.indents`) grows by `len(indent)` at every nesting level and is copied into the output in full at each entry within that level, so for a message tree of depth *n* the indentation bytes alone sum to O(n²) — exactly the same amplification pattern as the `league/commonmark` `XmlRenderer` advisory (GHSA-mj63-m3rc-8ppr), just in JSON/text-proto form instead of XML.

### Finding Description
The core encoder logic lives in `internal/encoding/json/encode.go`'s `prepareNext`: [1](#0-0) 
On every `objectOpen`/`arrayOpen` it appends `e.indent` to the cumulative `e.indents` slice, and on every subsequent scalar/name/close it re-copies the entire `e.indents` slice into `e.out`. Because `e.indents` length is proportional to current depth, and it's written once per entry at that depth, total indentation output for a depth-*n* tree is O(n²).

`encoding/protojson/encode.go` wires this in directly: `MarshalOptions.Indent`/`Multiline` is a first-class, commonly-used option for human-readable JSON output. [2](#0-1) 

The identical pattern exists in the text-format encoder used by `prototext.MarshalOptions.Indent`/`Multiline`: [3](#0-2) [4](#0-3) 

Depth of the in-memory message tree that feeds these encoders is bounded only by the decoder's recursion limit (`protowire.DefaultRecursionLimit`, referenced from `proto.Unmarshal`/`UnmarshalOptions`): [5](#0-4) 
This limit bounds *depth* but does nothing to bound the *quadratic* indentation cost once that depth is reached — mirroring the commonmark advisory's own observation that `max_nesting_level` "does not constrain" the amplification, only caps how deep the parser will go before erroring.

### Impact Explanation
An application that decodes an attacker-supplied message with a recursive/self-referential message field (a normal, trusted-schema construct — e.g. tree-shaped domain models, `google.protobuf.Struct`/`Value`, or any proto with a repeated/optional field of its own message type) and then re-serializes it with `protojson.MarshalOptions{Indent: ...}` (a very common pattern for pretty JSON API responses/logs) or `prototext.MarshalOptions{Multiline: true}` will produce output whose size grows quadratically with input-controlled nesting depth. This causes disproportionate CPU/memory/output-size consumption relative to the request size — an availability impact, matching CWE-405, with no confidentiality/integrity impact, consistent with a Medium-severity finding.

### Likelihood Explanation
Reaching this requires: (1) a schema with recursive/self-referential message nesting reachable from an unprivileged request (common for tree/list structures and well-known types like `Struct`/`Value`/`ListValue`), and (2) the application choosing an indented/multiline pretty-print path for that message — an opt-in output mode, exactly as in the original advisory. Because pretty-printed JSON output is extremely common in Go services using `protojson.MarshalOptions{Indent: "  "}`, likelihood is plausible but conditioned on the app exposing this rendering path, not universal.

### Recommendation
- Bound the depth of the in-memory message tree more conservatively when the message is going to be re-rendered with indentation (lower `proto.UnmarshalOptions.RecursionLimit`).
- Cap total output size / streaming size when serializing untrusted-content-derived messages with `Indent`/`Multiline` set.
- Consider changing `prepareNext` in both `internal/encoding/json/encode.go` and `internal/encoding/text/encode.go` to write indentation incrementally (e.g., track depth and emit indent characters directly without repeatedly copying an ever-growing buffer) so cost stays O(n) rather than O(n²).
- Where indentation is only for human consumption (debugging), prefer compact (non-multiline) output for machine-to-machine paths handling untrusted data.

### Proof of Concept
```go
package main

import (
	"fmt"

	"google.golang.org/protobuf/encoding/protojson"
	"google.golang.org/protobuf/proto"
	"google.golang.org/protobuf/types/known/structpb"
)

func main() {
	// Build (or decode from attacker-controlled bytes) a deeply nested
	// google.protobuf.Value / Struct — a normal, trusted well-known type
	// that permits arbitrary nesting via ListValue/Struct fields.
	depth := 5000
	var v *structpb.Value = structpb.NewNullValue()
	for i := 0; i < depth; i++ {
		v = structpb.NewListValue(&structpb.ListValue{Values: []*structpb.Value{v}})
	}

	// A service that pretty-prints responses/logs (a common, opt-in pattern):
	out, err := protojson.MarshalOptions{Indent: "  "}.Marshal(v.ProtoReflect().Interface().(proto.Message))
	if err != nil {
		panic(err)
	}
	fmt.Println("output size:", len(out)) // grows ~O(depth^2)
}
```
Doubling `depth` roughly quadruples `len(out)`, demonstrating the same O(n²) indentation-driven amplification as the `league/commonmark` `XmlRenderer` advisory, reachable through the standard `protojson.MarshalOptions` pretty-print path.

func (o MarshalOptions) marshal(b []byte, m proto.Message) ([]byte, error) {
	if o.Multiline && o.Indent == "" {
		o.Indent = defaultIndent
	}
	if o.Resolver == nil {
		o.Resolver = protoregistry.GlobalTypes
	}

	internalEnc, err := json.NewEncoder(b, o.Indent)
	if err != nil {
		return nil, err
	}

	// Treat nil message interface as an empty message,
	// in which case the output in an empty JSON object.
	if m == nil {
		return append(b, '{', '}'), nil
	}

	enc := encoder{internalEnc, o}
	if err := enc.marshalMessage(m.ProtoReflect(), ""); err != nil {
		return nil, err
	}
	if o.AllowPartial {
		return enc.Bytes(), nil
	}
	return enc.Bytes(), proto.CheckInitialized(m)
}

// prepareNext adds possible space and indentation for the next value based
// on last encType and indent option. It also updates e.lastType to next.
func (e *Encoder) prepareNext(next encType) {
	defer func() {
		e.lastType = next
	}()

	// Single line.
	if len(e.indent) == 0 {
		// Add space after each field before the next one.
		if e.lastType&(scalar|messageClose) != 0 && next == name {
			e.out = append(e.out, ' ')
			// Add a random extra space to make output unstable.
			if detrand.Bool() {
				e.out = append(e.out, ' ')
			}
		}
		return
	}

	// Multi-line.
	switch {
	case e.lastType == name:
		e.out = append(e.out, ' ')
		// Add a random extra space after name: to make output unstable.
		if detrand.Bool() {
			e.out = append(e.out, ' ')
		}

	case e.lastType == messageOpen && next != messageClose:
		e.indents = append(e.indents, e.indent...)
		e.out = append(e.out, '\n')
		e.out = append(e.out, e.indents...)

	case e.lastType&(scalar|messageClose) != 0:
		if next == messageClose {
			e.indents = e.indents[:len(e.indents)-len(e.indent)]
		}
		e.out = append(e.out, '\n')
		e.out = append(e.out, e.indents...)
	}
}

func (o MarshalOptions) marshal(b []byte, m proto.Message) ([]byte, error) {
	var delims = [2]byte{'{', '}'}

	if o.Multiline && o.Indent == "" {
		o.Indent = defaultIndent
	}
	if o.Resolver == nil {
		o.Resolver = protoregistry.GlobalTypes
	}

	internalEnc, err := text.NewEncoder(b, o.Indent, delims, o.EmitASCII)
	if err != nil {
		return nil, err
	}

	// Treat nil message interface as an empty message,
	// in which case there is nothing to output.
	if m == nil {
		return b, nil
	}

	enc := encoder{internalEnc, o}
	err = enc.marshalMessage(m.ProtoReflect(), false)
	if err != nil {
		return nil, err
	}
	out := enc.Bytes()
	if len(o.Indent) > 0 && len(out) > 0 {
		out = append(out, '\n')
	}
	if o.AllowPartial {
		return out, nil
	}
	return out, proto.CheckInitialized(m)
}
