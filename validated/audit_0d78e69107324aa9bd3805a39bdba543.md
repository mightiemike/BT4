## Analysis

The external report's bug class — deriving a security-critical value from a manipulable on-chain source (AMM/vault price) and using it as a bound that gates fund movement/minting — has a concrete analog in Push Chain's `x/uexecutor` gas-refund and gas-swap flow.

### Where it maps

`ExecuteInboundGas` (the routine invoked once an inbound ballot passes quorum and mints/settles bridged gas tokens) computes a `minPCOut` slippage floor directly from a live Uniswap V3 `QuoterV2.quoteExactInputSingle` call, then immediately uses that same floor to gate the real swap: [1](#0-0) 

The quote itself is fetched via `GetSwapQuote`, a plain read (`commit=false`) against whatever pool state exists on-chain at that instant — not a TWAP, not an external oracle: [2](#0-1) 

That `quote` is then multiplied by 95% and passed straight into `CallPRC20DepositAutoSwap`, which performs the actual on-chain swap of the bridged gas-token PRC20 into WPC/native PC for the recipient's UEA: [3](#0-2) 

The identical pattern is reused for outbound gas refunds via `getSwapQuoteForRefund` / `applyGasRefund`: [4](#0-3) 

The chain-meta upgrade notes confirm this quote-derived slippage bound replaced a prior "0-slippage" call, i.e., it's the sole protection on these swaps: [5](#0-4) 

### Why this is the same bug class

Just as the Vault report's `additionalOwnedAssets()` call returns a manipulable LP valuation that the yield manager trusts to authorize excess minting, `GetSwapQuote` returns a spot-pool valuation that the module trusts to authorize the acceptable output of a real value-moving swap. Both cases derive an economic bound from the very same manipulable market state that the actual value-moving action (mint / swap) will execute against, in the same transaction/block window, with no independent price source or monotonicity guarantee. An unprivileged actor who can move the pool (a normal swap transaction, no privileged role required) immediately before the module's `depositPRC20WithAutoSwap`/`refundUnusedGas` call executes can depress the quote, causing `minPCOut` to be computed off the manipulated price and then sandwiched, extracting value from the bridged user funds that the module swaps on the user's behalf.

### Caveat

I did not find code that would guarantee `GetSwapQuote` and the subsequent swap call are protected against reordering by an external actor within the same block (e.g., no TWAP config, no oracle fallback visible in what I could inspect). Confirming exact exploitability (mempool ordering guarantees, whether these on-chain pools have meaningful external liquidity/manipulation cost, and whether `deadline=0` further weakens protection) would need deeper review of the Uniswap system-contract deployment and `x/uregistry` fee-tier configuration, which I did not fully trace given index/time constraints.

### Title
Gas-swap `minPCOut` derived from unprotected spot AMM quote enables sandwich extraction of bridged funds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`ExecuteInboundGas` and `applyGasRefund` compute the slippage floor `minPCOut` for auto-swapping bridged PRC20 gas tokens into PC by directly reading `QuoterV2.quoteExactInputSingle` against the live on-chain pool, then pass `95% of that same quote` into the real swap call performed on the user's behalf.

### Finding Description
`GetSwapQuote` [2](#0-1)  is a non-committing spot read of the deployed Uniswap V3 quoter, reflecting whatever pool reserves exist at call time. `ExecuteInboundGas` [6](#0-5)  uses this single spot read, with no TWAP or external oracle, to derive `minPCOut = quote * 95 / 100` and immediately spends it as the slippage bound on the real `depositPRC20WithAutoSwap` call. The same unguarded pattern recurs in the outbound gas-refund path [4](#0-3) . Because both the quote read and the value-moving swap consume the same manipulable pool state, an attacker who moves the pool immediately before the module's call executes can force `minPCOut` down to whatever floor benefits a subsequent sandwich, then back-run to recapture the spread — extracting value from the bridged user funds without needing any privileged role.

### Impact Explanation
The swapped amount funds the recipient UEA's PC balance from bridged gas-token deposits and funds gas refunds back to users; both are protocol/user-controlled value. A depressed floor lets an attacker's sandwich siphon the difference between fair value and the manipulated floor, i.e., theft of user/protocol funds through the auto-swap and refund-swap paths — squarely in the "unauthorized... funds" impact category.

### Likelihood Explanation
Triggering this requires only an ordinary, unprivileged transaction against the Uniswap pool that Push Chain's system contracts use — no validator, TSS, or governance compromise is needed. It depends on transaction-ordering opportunities (e.g., seeing a pending inbound/outbound that is about to trigger the swap) and on the depth/manipulability of the specific pool, which I was not able to fully verify from the indexed code (pool liquidity, whether execution order gives attackers a reliable front-run window, and fee-tier/registry configuration are outside what I could confirm).

### Recommendation
Do not derive `minPCOut` from a single spot quote taken immediately before the swap it bounds. Use a TWAP-based quote, a registry-configured maximum-deviation check against a reference/oracle price, or a fixed conservative slippage tolerance independent of the live pool read, consistent with the "monotonically increasing" / oracle-based mitigations Aragon applied to the analogous Vault issue.

### Proof of Concept
1. Attacker observes an inbound (or outbound-refund) awaiting the 2/3 quorum vote that will trigger `ExecuteInboundGas`/`applyGasRefund`.
2. Immediately before (or interleaved with) the module's `GetSwapQuote` + `CallPRC20DepositAutoSwap` execution, attacker submits a swap against the same Uniswap V3 pool to depress the `TokenIn -> WPC` price.
3. `GetSwapQuote` returns the manipulated (low) price; `minPCOut` is computed as 95% of that manipulated quote.
4. The module's `depositPRC20WithAutoSwap`/`refundUnusedGas` swap executes within the manipulated pool state, satisfying the depressed `minPCOut` floor while yielding far less PC to the recipient than fair value.
5. Attacker back-runs to restore the pool and captures the value difference extracted from the bridged deposit/refund.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
