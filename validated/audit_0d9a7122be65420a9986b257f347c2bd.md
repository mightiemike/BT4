### Title
`ensure_match_transaction_info` omits checkpoint-hash validation, masking authenticated position/state-root divergence during replay-verify - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` in [1](#0-0)  validates status, gas, write-set hash, and event root hash against a `TransactionInfo`, but never checks `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`. This function is the sole correctness gate used by `storage/db-tool`'s `replay_on_archive` verifier [2](#0-1)  and by `aptos-move/cli`'s transaction-replay command [3](#0-2) .

### Finding Description
The function's own in-code TODO documents the gap: [4](#0-3)  states that ignoring checkpoint hashes means "replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution." Concretely, if locally-recomputed execution produces a different `state_checkpoint_hash` / `hot_state_checkpoint_hash` / `position_state_checkpoint_hash` than what is committed in the archived `TransactionInfo`, `ensure_match_transaction_info` still returns `Ok(())` because it only compares `status`, `gas_used`, `write_set_hash` (`state_change_hash`), and `event_root_hash`.

### Impact Explanation
If this comparator were relied upon while `compute_trading_native_state_roots` (gated by the `COMPUTE_TRADING_NATIVE_STATE_ROOTS` feature) is active, a divergence between the authenticated on-chain state/position root and independently-recomputed execution would go undetected by replay-verify tooling — exactly the "wrong accumulator root / proof accepted as valid" and "authenticated output bound to wrong version/root" classes called out in the state-integrity gate. That said, I could not confirm from the available index whether this feature flag is presently enabled on mainnet; if it is not yet active, this is a pre-existing, self-acknowledged gap in dormant code rather than an exploitable mainnet issue today.

### Likelihood Explanation
Low-to-unknown without confirming feature-flag activation status. The gap is deterministic and always present in the comparator's logic (not a race or edge case), but its real-world trigger condition depends entirely on whether `compute_trading_native_state_roots`/`COMPUTE_TRADING_NATIVE_STATE_ROOTS` is turned on for the relevant network, which I was unable to verify.

### Recommendation
Extend `ensure_match_transaction_info` to also compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` between the locally-produced `TransactionOutput`-derived checkpoint hashes and the `txn_info` fields, as the existing TODO comment recommends, before any reliance on `COMPUTE_TRADING_NATIVE_STATE_ROOTS`.

### Proof of Concept
Not independently verifiable via static index review alone — the divergence path requires exercising replay against an archive where `compute_trading_native_state_roots` is enabled and a locally-recomputed checkpoint hash differs from the committed one, which would need a live/test environment (Devin session with repo access) to confirm whether the feature path is reachable on mainnet today.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
