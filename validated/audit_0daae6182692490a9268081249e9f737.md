### Title
Free, fee-less account creation via `FreezeBalanceProcessor` resource delegation (bypasses the standard new-account storage fee) - ([File: actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceProcessor.java])

### Summary
Every other path in java-tron that can create a new `AccountCapsule` as a side effect of a normal transaction charges the `CreateNewAccountFeeInSystemContract` (or `CreateAccountFee`) to compensate for the added state/storage cost. `FreezeBalanceProcessor.validate()`, which backs the TVM-callable `freezeBalance`/`delegateResource` native contract, creates a brand-new receiver account with `repo.createNormalAccount(receiverAddress)` and never deducts any fee for it.

### Finding Description
`CreateAccountActuator.execute` charges `calcFee()` (mapped to `getCreateNewAccountFeeInSystemContract()`) whenever a new account row is created: [1](#0-0) 

`TransferActuator` and `TransferAssetActuator` likewise add `dynamicStore.getCreateNewAccountFeeInSystemContract()` to the fee whenever the `toAddress` account doesn't exist and gets implicitly created: [2](#0-1) [3](#0-2) 

However, `FreezeBalanceProcessor.validate()` (the validation logic for the resource-delegation native contract reachable from a `TriggerSmartContract`/`freezeBalanceV2` style call, i.e. anonymous/broadcast transaction path), creates the `receiverAddress` account for free when it doesn't yet exist and is different from the owner: [4](#0-3) 

No fee (`getCreateNewAccountFeeInSystemContract` / `getCreateAccountFee`) is charged anywhere in `execute()` either — only the delegated resource bookkeeping and owner balance deduction for the frozen amount occur: [5](#0-4) 

This mirrors the reported bug class exactly: an account-registration code path that omits the storage/creation fee that every sibling code path enforces, allowing unaccounted growth of the account store.

### Impact Explanation
An attacker can repeatedly call the freeze/delegate-resource native contract with fresh, never-before-seen `receiverAddress` values (each only 1 TRX of frozen balance, refundable later) to create arbitrary numbers of new `AccountCapsule` entries in the account store at zero marginal creation cost, unlike every other account-creating path in the codebase. This is a state-bloat / storage-DoS vector: it grows chain state (and thus long-term node disk/memory footprint and sync time) without the compensating fee that the protocol's fee model assumes for every new account, mirroring the original report's "unaccounted storage costs" bug class.

### Likelihood Explanation
The only precondition is a 1 TRX frozen balance and an owner-vs-receiver address mismatch — both trivially satisfiable by any account holder issuing a normal signed transaction, no special privileges required. High likelihood given the low cost per created account (the frozen TRX is not spent, only locked).

### Recommendation
In `FreezeBalanceProcessor.validate()`/`execute()`, when a new receiver account must be created for delegation, charge the same `getCreateNewAccountFeeInSystemContract()` (or equivalent) fee applied by `CreateAccountActuator`/`TransferActuator`/`TransferAssetActuator`, deducting it from the owner's balance and routing it to the black-hole/burn address exactly as those actuators do.

### Proof of Concept
1. Send a `freezeBalanceV2`/delegate-resource transaction (`FreezeBalanceParam` with `resourceType=BANDWIDTH` or `ENERGY`) where `frozenBalance = 1_000_000` (1 TRX) and `receiverAddress` is a brand-new address never seen on-chain, and `ownerAddress != receiverAddress`.
2. `FreezeBalanceProcessor.validate()` hits `repo.getAccount(receiverAddress) == null` and calls `repo.createNormalAccount(receiverAddress)` at [6](#0-5) , persisting a new account with no fee charged.
3. Repeat with new addresses in a loop; each iteration only locks (not spends) 1 TRX and creates one new permanent account entry, unlike `TransferActuator`/`TransferAssetActuator`/`CreateAccountActuator` which all charge `getCreateNewAccountFeeInSystemContract()` for the same effect.

  public void execute(FreezeBalanceParam param,  Repository repo) {
    // calculate expire time
    DynamicPropertiesStore dynamicStore = repo.getDynamicPropertiesStore();
    long nowInMs = dynamicStore.getLatestBlockHeaderTimestamp();
    long expireTime = nowInMs + param.getFrozenDuration() * FROZEN_PERIOD;

    byte[] ownerAddress = param.getOwnerAddress();
    byte[] receiverAddress = param.getReceiverAddress();
    long frozenBalance = param.getFrozenBalance();
    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    // acquire or delegate resource
    if (param.isDelegating()) { // delegate resource
      switch (param.getResourceType()) {
        case BANDWIDTH:
          delegateResource(ownerAddress, receiverAddress,
              frozenBalance, expireTime, true, repo);
          accountCapsule.addDelegatedFrozenBalanceForBandwidth(frozenBalance);
          break;
        case ENERGY:
          delegateResource(ownerAddress, receiverAddress,
              frozenBalance, expireTime, false, repo);
          accountCapsule.addDelegatedFrozenBalanceForEnergy(frozenBalance);
          break;
        default:
          logger.debug("Resource Code Error.");
      }
    } else { // acquire resource
      switch (param.getResourceType()) {
        case BANDWIDTH:
          accountCapsule.setFrozenForBandwidth(
              frozenBalance + accountCapsule.getFrozenBalance(),
              expireTime);
          break;
        case ENERGY:
          accountCapsule.setFrozenForEnergy(
              frozenBalance + accountCapsule.getAccountResource()
                  .getFrozenBalanceForEnergy()
                  .getFrozenBalance(),
              expireTime);
          break;
        default:
          logger.debug("Resource Code Error.");
      }
    }

    // adjust total resource
    switch (param.getResourceType()) {
      case BANDWIDTH:
        repo.addTotalNetWeight(frozenBalance / TRX_PRECISION);
        break;
      case ENERGY:
        repo.addTotalEnergyWeight(frozenBalance / TRX_PRECISION);
        break;
      default:
        //this should never happen
        break;
    }

    // deduce balance of owner account
    long newBalance = accountCapsule.getBalance() - frozenBalance;
    accountCapsule.setBalance(newBalance);
    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
  }
