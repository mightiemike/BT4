### Title
Uncaught `DOMException` from `atob()` in `decodeHost`/`sanitizeHost` causes unhandled exception instead of clean `InvalidHostError` - ([File: packages/apps/shopify-api/lib/auth/decode-host.ts])

### Summary
`sanitizeHost` validates the `host` query parameter with a regex that accepts base64 strings whose length is not a multiple of 4 (e.g. a single character with no padding), then immediately calls `decodeHost`, which is a bare `atob(host)` call with no error handling. Node's `atob` throws a `DOMException` for such malformed input, so the exception propagates out of `sanitizeHost` and `buildEmbeddedAppUrl` instead of the intended clean `InvalidHostError`.

### Finding Description
`sanitizeHost` only checks the `host` value against `base64regex = /^[0-9a-zA-Z+/]+={0,2}$/` before calling `decodeHost(sanitizedHost)` to extract the hostname for domain validation: [1](#0-0) 

This regex matches any alphanumeric+`+/` sequence of any length followed by 0–2 `=`. It does not enforce that the base64 payload length is a multiple of 4 (mod padding rules). `decodeHost` is a trivial passthrough to the platform `atob`: [2](#0-1) 

Node's `atob` implements the WHATWG forgiving-base64 decode algorithm, which throws a `DOMException` (`InvalidCharacterError`) when the input length modulo 4 equals 1 (e.g. a single character like `"A"`, or 5/9/13-character strings without padding). Such strings pass `base64regex` (they contain only allowed characters and no invalid trailing `=`), so `sanitizeHost` calls `decodeHost` on them and the `atob` call throws before the function can return `null`/throw the clean `InvalidHostError`.

The exception is not caught anywhere in `sanitizeHost`, nor in `buildEmbeddedAppUrl`, which also calls `decodeHost(host)` a second, entirely unguarded time after `sanitizeHost`: [3](#0-2) 

The reachable, pre-authentication path is `getEmbeddedAppUrl`, which reads `host` directly from the request's query string with no other validation before calling `buildEmbeddedAppUrl`: [4](#0-3) 

So an anonymous client can send a request like `GET /?host=A` (or `host=AAAAA`) to any route that calls `shopify.auth.getEmbeddedAppUrl`, and the library will throw an unhandled `DOMException` instead of the documented `InvalidHostError`.

### Impact Explanation
This is a robustness/availability bug rather than a data-exposure bug: it breaks the expected error-handling contract for `sanitizeHost`/`buildEmbeddedAppUrl`/`getEmbeddedAppUrl`, causing an unhandled `DOMException` to surface instead of `ShopifyErrors.InvalidHostError`. Depending on the host framework's error handling for synchronous throws inside a request handler, this can manifest as an unhandled 500 error (if the framework wraps route handlers) or, in the worst case for frameworks/adapters that don't catch synchronous throws in async functions properly, an unhandled promise rejection. This matches a low/DoS-class availability impact on the embedded-app URL resolution path, which is reachable pre-authentication (no session, no HMAC required to reach `getEmbeddedAppUrl`).

### Likelihood Explanation
Trivial to trigger: any unauthenticated caller can supply `?host=A` or any base64-alphabet string whose length ≡ 1 mod 4 with no padding. No secrets, sessions, or special configuration are required. This is 100% repeatable.

### Recommendation
Wrap the `atob` call in `decodeHost` (or the call sites in `sanitizeHost`/`buildEmbeddedAppUrl`) in a `try/catch`, converting any decode failure into the existing `InvalidHostError` (or returning `null` for non-throwing callers), and/or tighten `base64regex` to require a length that is a multiple of 4 (`/^(?:[0-9a-zA-Z+/]{4})*(?:[0-9a-zA-Z+/]{2}==|[0-9a-zA-Z+/]{3}=)?$/`) before invoking `atob`.

```ts
// packages/apps/shopify-api/lib/utils/__tests__/shop-validator.test.ts
import {shopifyApi} from '../..';
import {testConfig} from '../../__tests__/test-config';

test('sanitizeHost should not throw an uncaught DOMException for malformed base64', () => {
  const shopify = shopifyApi(testConfig());

  // 'A' matches base64regex (/^[0-9a-zA-Z+/]+={0,2}$/) but has length % 4 === 1,
  // which is invalid for atob and throws DOMException instead of returning null
  // or throwing InvalidHostError.
  expect(() => shopify.utils.sanitizeHost('A')).not.toThrow(DOMException);
});
```
Expected (current buggy) result: the test fails because `atob('A')` throws `DOMException: The string to be decoded is not correctly encoded.` instead of `sanitizeHost` returning `null`.

Equivalent HTTP PoC: `GET /some-route-that-calls-getEmbeddedAppUrl?host=A` triggers the same unhandled exception inside `buildEmbeddedAppUrl`/`getEmbeddedAppUrl`.

export function getEmbeddedAppUrl(config: ConfigInterface): GetEmbeddedAppUrl {
  return async ({...adapterArgs}: GetEmbeddedAppUrlParams): Promise<string> => {
    const request = await abstractConvertRequest(adapterArgs);

    if (!request) {
      throw new ShopifyErrors.MissingRequiredArgument(
        'getEmbeddedAppUrl requires a request object argument',
      );
    }

    if (!request.url) {
      throw new ShopifyErrors.InvalidRequestError(
        'Request does not contain a URL',
      );
    }

    const url = new URL(request.url, `https://${request.headers.host}`);
    const host = url.searchParams.get('host');

    if (typeof host !== 'string') {
      throw new ShopifyErrors.InvalidRequestError(
        'Request does not contain a host query parameter',
      );
    }

    return buildEmbeddedAppUrl(config)(host);
  };
}

export function buildEmbeddedAppUrl(
  config: ConfigInterface,
): BuildEmbeddedAppUrl {
  return (host: string): string => {
    sanitizeHost(config)(host, true);
    const decodedHost = decodeHost(host);

    return `https://${decodedHost}/apps/${config.apiKey}`;
  };
}
