### Title
Silently ignored `mark_locally_accepted` error lets a globally-rejected block still be broadcast/pushed to the node - (File: stacks-signer/src/v0/signer.rs)

### Summary
`BlockInfo::mark_locally_accepted` returns a `Result<(), String>` that encodes the signer-DB's state-machine invariant that `GloballyRejected`/`GloballyAccepted` are terminal states [1](#0-0) . In `store_and_process_block_signature` this return value is checked, but on failure the code only logs (and only conditionally) and then unconditionally continues to persist the block and broadcast it, exactly analogous to the reported Solidity pattern of checking a `call()`'s boolean success flag and then proceeding anyway.

### Finding Description
`mark_locally_accepted` calls `move_to(BlockState::LocallyAccepted)`, which is rejected by `check_state` whenever the block's current state is already `GloballyRejected` or `GloballyAccepted`: [2](#0-1) 

In `store_and_process_block_signature`, after tallying acceptance-signature weight and deciding the 70% threshold has been crossed, the code calls `mark_locally_accepted(true)`, examines the `Result`, but the error branch is a no-op unless `!block_info.has_reached_consensus()`: [3](#0-2) 

If this block was already moved to `GloballyRejected` by an earlier call to `store_and_process_block_rejection` (triggered once rejection weight makes 70% acceptance "impossible" at that point in time - see the 30%-blocking-minority logic there) [4](#0-3) , then:
- `mark_locally_accepted(true)` fails (`GloballyRejected` is terminal per `check_state`),
- `block_info.has_reached_consensus()` is true (the block already reached a *global* verdict), so the warning is even suppressed,
- execution nevertheless falls through to `self.signer_db.insert_block(block_info)` and then unconditionally to `self.broadcast_signed_block(...)`, which pushes the block to the stacks-node via `handle_post_block`.

Because rejections are explicitly documented as "revocable" while accumulated signatures keep counting toward the 70% threshold ("the block must keep counting") [5](#0-4) , it is entirely possible for a signer to first cross the rejection-side threshold (mark the block `GloballyRejected` and broadcast a rejection) and later, as more/updated signatures arrive, cross the 70% acceptance-side threshold on the very same block. At that point the ignored error means the signer's own DB record stays state-inconsistent (still `GloballyRejected`, even though `signed_group` timestamp gets set by the mutation preceding `move_to`), yet the signer proceeds to broadcast the block for adoption by the node - contradicting its own recorded, terminal verdict.

### Impact Explanation
This breaks the intended equality "a signer's broadcast action matches its own recorded validation verdict." A signer that has already told the network the block is rejected can still push it to its node for adoption, producing exactly the class of bug called out in scope: "a validation verdict two nodes [or the same node's state vs. its actions] disagree on." Depending on how many signers hit this same race and whether the node happens to also gather the needed weight elsewhere, this can create a temporary tip disagreement across the signer set/network (some signers holding the rejected record, one or more nodes receiving and adopting the pushed block), matching the High-severity category "a minority-triggerable ... static-validation divergence ... temporary tip disagreement."

### Likelihood Explanation
This requires no majority collusion and no operator/admin key - it is purely a function of signature/rejection timing among the existing signer set: a blocking-minority-sized set of rejections crosses the local `GloballyRejected` threshold first, and later-arriving or revised signatures (from the same or other signers, which the code explicitly still counts) cross the 70% acceptance threshold on the same block. Because rejections are deliberately kept "revocable" while signatures are deliberately kept "counted forever," this ordering is a foreseeable, minority-triggerable race rather than a contrived edge case.

### Recommendation
Treat the `Err` result of `mark_locally_accepted` as fatal to this code path exactly like the sibling code does for `insert_block`'s `Err`: if `mark_locally_accepted` fails because the block already reached a terminal global state, `return` immediately without inserting or broadcasting, instead of falling through unconditionally. i.e., mirror the pattern already used for other calls in this file (`unwrap_or_else(|e| panic!(...))` / early `return`) rather than swallowing the error with a conditional `warn!` only.

### Proof of Concept
1. Configure a signer set where a blocking-minority (~just under 30% by weight) rejects a proposed block first; `store_and_process_block_rejection` observes `total_reject_weight.saturating_add(min_weight) > total_weight`, calls `mark_globally_rejected()`, transitioning `BlockInfo.state` to `GloballyRejected`, and broadcasts a rejection.
2. Subsequently, enough of the *same or other* signers' acceptance signatures for that identical block hash arrive (signatures are never invalidated by a later rejection, so they still accumulate) such that `store_and_process_block_signature` computes `total_signature_weight >= min_weight` (≥70%).
3. `mark_locally_accepted(true)` is called: `move_to(BlockState::LocallyAccepted)` returns `Err` because `check_state` disallows leaving `GloballyRejected`.
4. Because `block_info.has_reached_consensus()` is `true` (state is `GloballyRejected`), the `warn!` is skipped entirely; the error is fully discarded.
5. `self.signer_db.insert_block(block_info)` persists the block (with `signed_group` now set, but `state` unchanged at `GloballyRejected`), and `self.broadcast_signed_block(...)` is called unconditionally, pushing the block to the stacks-node for adoption - directly contradicting the signer's own already-broadcast rejection verdict.

    /// Mark this block as valid and the appropriate timestamps if they aren't already set, and attempt to mark it as locally accepted.
    pub fn mark_locally_accepted(&mut self, group_signed: bool) -> Result<(), String> {
        if group_signed {
            self.signed_group.get_or_insert(get_epoch_time_secs());
        } else {
            self.valid = Some(true);
            self.approved_time.get_or_insert(get_epoch_time_secs());
            self.signed_self.get_or_insert(get_epoch_time_secs());
        }
        self.move_to(BlockState::LocallyAccepted)
    }

    /// Mark this block's signed group time if not already set and attempt to mark it as globally accepted.
    pub fn mark_globally_accepted(&mut self) -> Result<(), String> {
        self.signed_group.get_or_insert(get_epoch_time_secs());
        self.move_to(BlockState::GloballyAccepted)
    }

    /// Mark this block as invalid and attempt to mark it as locally rejected
    pub fn mark_locally_rejected(&mut self) -> Result<(), String> {
        self.valid = Some(false);
        self.move_to(BlockState::LocallyRejected)
    }

    /// Attempt to mark the block as globally rejected
    pub fn mark_globally_rejected(&mut self) -> Result<(), String> {
        self.move_to(BlockState::GloballyRejected)
    }

    /// Return the block's signer signature hash
    pub fn signer_signature_hash(&self) -> Sha512Trunc256Sum {
        self.block.header.signer_signature_hash()
    }

    /// Check if the block state transition is valid
    fn check_state(&self, state: BlockState) -> bool {
        let prev_state = &self.state;
        if *prev_state == state {
            return true;
        }
        match state {
            BlockState::Unprocessed => false,
            BlockState::LocallyAccepted | BlockState::LocallyRejected => !matches!(
                prev_state,
                BlockState::GloballyRejected | BlockState::GloballyAccepted
            ),
            BlockState::GloballyAccepted => !matches!(prev_state, BlockState::GloballyRejected),
            BlockState::GloballyRejected => !matches!(prev_state, BlockState::GloballyAccepted),
            BlockState::PreCommitted => matches!(prev_state, BlockState::Unprocessed),
        }
    }
