## Analog Found: Gas Fee Under-Collection from Premature `BaseFee` Truncation in `CalculateGasCost`

### Title
Truncating `baseFee` to a whole `upc` integer *before* multiplying by `gasUsed` silently drops fractional gas-price precision, causing systemic gas-fee under-collection - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` truncates the fee-market `baseFee` (a `LegacyDec`, 18-decimal fixed point) down to a whole-`upc` integer via `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` *before* multiplying by `gasUsed`, instead of performing the multiplication in `Dec` precision and rounding only the final result. This is the same bug class as the reported `AprPremium` issue: a ratio/rate value is truncated to a coarser unit before being combined with a scaling factor, discarding fractional value on every calculation and producing a systematically lower result than the mathematically correct one.

### Finding Description [1](#0-0) 

```go
func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// ... base fee is always a whole number of upc -- no fractional upc exists.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
	...
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)
	...
	return gasCost, nil
}
```

`baseFee.BigInt()` returns the raw internal representation of the `LegacyDec` (value × 1e18). The code then does an integer `Div` by `1e18` to "unwrap" it back to a plain `upc` amount, relying on the inline comment's assumption that the fee-market `baseFee` is *always* a whole number of `upc`. That assumption only holds if the fee-market's adaptive base-fee algorithm (external `x/feemarket` module, invoked every block in `BeginBlock`/`EndBlock` to adjust `baseFee` by a ratio of `gasUsed`/`gasTarget`) always yields exact-integer results. Standard EIP-1559-style adaptive base-fee formulas multiply/divide by ratios (e.g. `baseFee * (1 ± gasUsedDelta/gasTarget/denominator)`), which routinely produce non-integer `Dec` values (e.g. `1000000000.125...`). Any such fractional component is silently discarded by the truncating `Div` **before** the value is multiplied by `gasUsed` in `DeductGasFeesFromReceipt`, rather than being preserved through the multiplication and rounded only once at the end. ### Impact Explanation
Because the fractional `upc` component of `baseFee` is dropped *before* being scaled by `gasUsed` (which can be in the hundreds of thousands for contract calls), the resulting undercharge is `fractionalPart(baseFee) * gasUsed` `upc` per transaction — potentially a nontrivial amount, not merely 1 wei-level dust. This is protocol-fee accounting corruption: gas fees that should be deducted and burned from user accounts are systematically under-collected on every EVM-executing universal transaction whenever the fee-market's computed `baseFee` is not an exact integer multiple of `1e18`. This directly matches the in-scope impact category of "corruption of ... gas fee accounting, refund accounting" reachable via ordinary user transaction submission with no privileged actor involved.

### Likelihood Explanation
This triggers automatically and deterministically whenever the fee-market's adaptive base-fee value is non-integer, which is the normal/expected behavior of dynamic EIP-1559-style fee markets under fluctuating block gas usage — it does not require any attacker action beyond submitting ordinary universal transactions that cause EVM execution. No malicious validator, relayer, or privileged role is needed.

### Recommendation
Perform the multiplication in `Dec` precision (`baseFee.Mul(sdkmath.LegacyNewDecFromInt(gasUsedBig))`, or equivalently work with `big.Rat`/scaled integers) and only convert to a whole-`upc` `big.Int` (with explicit ceiling, matching the "round up" convention used elsewhere for gas pricing, e.g. `app/cosmos/min_gas_price.go`'s `fee.Ceil().RoundInt()`) once, on the final gas-cost result — not on the intermediate `baseFee` value before it is multiplied by `gasUsed`.

### Proof of Concept
1. Suppose the fee-market's `BeginBlock` adaptive algorithm updates `baseFee` to `1_000_000_000.5` `upc` (a `LegacyDec` value, perfectly valid output of a ratio-based fee adjustment formula).
2. A user submits a `MsgExecutePayload` that results in an EVM call consuming `gasUsed = 200,000`.
3. `CalculateGasCost` computes `baseFeeBig.Div(baseFeeBig, 1e18)` → truncates `1_000_000_000.5` to `1_000_000_000`, discarding the `.5` `upc` fractional part.
4. `gasCost = 1_000_000_000 * 200_000 = 200_000_000_000_000` `upc`.
5. Correct value (Dec-precision multiplication then round): `1_000_000_000.5 * 200_000 = 200_000_000_100_000` `upc`.
6. Every such transaction under-burns `100,000 upc` versus the mathematically correct fee — a systemic under-collection repeated on every universal-execution transaction while `baseFee` carries a fractional component.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
```
