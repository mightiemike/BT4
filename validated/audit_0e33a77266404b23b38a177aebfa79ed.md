### Title
Starknet OS `execute_replace_class` syscall handlers omit the "class must be declared" check enforced by Blockifier, causing honest-node/OS-vs-Blockifier execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Blockifier's Rust implementation of the `replace_class` syscall requires that the target `class_hash` correspond to an already-declared class before it will retarget a contract's class hash. The Starknet OS's Cairo re-implementation of the same syscall (used to independently re-derive/attest the block's execution for proving) omits this check entirely, in both the current and deprecated syscall handlers. A transaction that calls `replace_class_syscall` with an undeclared class hash is therefore rejected/reverted by Blockifier but accepted by the OS, producing two different state diffs for the same transaction and state.

### Finding Description
Blockifier's syscall handler for `replace_class` explicitly reads the compiled class to enforce declaration before mutating state: [1](#0-0) 

The Starknet OS Cairo implementation of the same syscall (current syscall path) sets the new class hash directly with only a `TODO` acknowledging the missing check: [2](#0-1) 

The deprecated (Cairo0) syscall path in the OS has the identical omission, with no check and no TODO at all: [3](#0-2) 

This is confirmed as intentional Blockifier behavior by the corresponding Rust unit test, which asserts that replacing to an undeclared class hash fails with "is not declared": [4](#0-3) [5](#0-4) 

Because the Starknet OS is meant to independently re-execute the exact same transactions in Cairo to attest that the sequencer's committed state diff is correct, any place where the OS's semantics differ from Blockifier's is a soundness gap: the OS will accept and commit a state transition that Blockifier itself would reject.

### Impact Explanation
An `INVOKE` transaction from any unprivileged account/contract that calls `replace_class_syscall` with a class hash that was never declared will:
- In Blockifier (the sequencer's actual execution engine): fail inside the entry point call, causing the invoke transaction to revert (the `replace_class` effect is not persisted).
- In the Starknet OS (used to re-derive/prove the block): succeed, applying the class-hash replacement to `contract_state_changes` with no declaration check.

This produces a state-diff/commitment mismatch between what Blockifier actually committed and what the OS would derive/prove for the same block and transaction — i.e., honest-node divergence and a wrong committed state root from the OS's perspective, undermining the trustworthiness of the block's proof and the "every deployed class must be declared" invariant that the rest of the system (declare/deploy paths) otherwise strictly enforces.

### Likelihood Explanation
Any account contract can trigger `replace_class_syscall` with an arbitrary (undeclared) class hash via a single ordinary invoke transaction — no special privileges, staking, or operator access are required. The bug is present in both the modern and legacy (Cairo0) syscall paths in the OS, making it broadly reachable regardless of contract version.

### Recommendation
Add the same "class must be declared" check to the OS's `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` that Blockifier already performs (i.e., verify the given `class_hash` has a corresponding entry in `contract_class_changes` / declared classes before applying the `StateEntry` update), so that OS semantics match Blockifier's for this syscall.

### Proof of Concept
1. Deploy/declare a normal Cairo1 account/contract (e.g., `TestContract`).
2. From that contract, submit an invoke transaction calling `test_replace_class` (or directly `replace_class_syscall`) with a `class_hash` that has never been declared, e.g. `felt!(1234_u16)` as used in the existing test: [6](#0-5) 
3. Observe that Blockifier execution fails with "is not declared" and the transaction reverts, so no class-hash change is persisted.
4. Trace the equivalent Cairo execution path in the OS (`execute_replace_class` in `syscall_impls.cairo` / `deprecated_execute_syscalls.cairo`): there is no analogous declared-class check before `dict_update` writes the new `StateEntry` with the undeclared `class_hash`, so the OS would compute a different (accepted) result for the same call.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
