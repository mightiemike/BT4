### Title
Attached deposit permanently consumed when `register` is called with an eth-implicit account ID — (`runtime/near-wallet-contract/implementation/address-registrar/src/lib.rs`)

### Summary
`AddressRegistrar::register` is `#[payable]` but silently retains any attached deposit when the caller passes an eth-implicit account ID. The NEAR runtime does not auto-refund deposits on a normal return, so the deposit is irrecoverably locked in the contract.

### Finding Description
`register` checks `is_eth_implicit` first and returns `None` early if true. [1](#0-0) 

No refund promise is issued on this path. The `Entry::Occupied` branch shows the correct pattern: `env::promise_batch_create` + `env::promise_batch_action_transfer` before returning `None`. [3](#0-2) 

The eth-implicit path lacks this, so any deposit attached to such a call is consumed by the contract with no recourse.

### Impact Explanation
Any caller who attaches a deposit (e.g., 1 NEAR) and passes an eth-implicit account ID loses that deposit permanently. The contract balance increases by the deposit amount and no transfer-back action is ever scheduled. This is a direct, demonstrable loss of funds for the caller.

### Likelihood Explanation
Low-to-moderate. A user could reasonably attach a deposit when calling `register` (since the function is `#[payable]` and the non-eth-implicit path requires a deposit), and mistakenly supply an eth-implicit account ID. Wallets or scripts that do not pre-validate the account type before attaching a deposit would trigger this silently.

### Recommendation
Mirror the `Entry::Occupied` refund pattern in the eth-implicit early-return branch:

```rust
if is_eth_implicit(&account_id) {
    env::log_str(&format!("Refuse to register eth-implicit account {account_id}"));
    let deposit = env::attached_deposit();
    if deposit.as_yoctonear() > 0 {
        let refund = env::promise_batch_create(&env::predecessor_account_id());
        env::promise_batch_action_transfer(refund, deposit);
    }
    return None;
}
```

### Proof of Concept
Call `register` with account ID `0x8fd379246834eac74b8419ffda202cf8051f7a03` and `deposit = 1 NEAR`. Record the caller's balance before and after. The post-call balance will be `pre_balance - gas_cost - 1 NEAR` (not just `pre_balance - gas_cost`), confirming the deposit was consumed. No refund receipt will appear in the execution outcome.
