### Title
Missing replay protection allows duplicate DON-wide execution of a captured `web_api_trigger` message - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`handler.HandleLegacyUserMessage` only checks message staleness via `payload.Timestamp` against `MaxAllowedMessageAgeSec`, and uses `msg.Body.MessageId` solely as a key in `savedCallbacks` for routing the *response* back to the caller, not as a used-message registry. A previously captured, still-valid, correctly signed `MethodWebAPITrigger` message can therefore be resubmitted verbatim any number of times before it expires, and each submission is broadcast to every DON member again.

### Finding Description
In `HandleLegacyUserMessage` [1](#0-0) , the checks performed on an incoming message are: JSON payload decoding, a non-zero `Timestamp`, and a staleness check comparing `payload.Timestamp` to `time.Now()` minus `MaxAllowedMessageAgeSec` [2](#0-1) . Signature verification happens earlier in `gateway.ProcessRequest` via `msg.Validate()` [3](#0-2) , but `Validate()` verifies the signature is well-formed/matches the sender, not that the message hasn't been seen before.

After validation, `HandleLegacyUserMessage` stores the callback keyed by `msg.Body.MessageId` in `h.savedCallbacks` and unconditionally overwrites any existing entry for that key, then broadcasts the request to every DON member: [4](#0-3) 

There is no check of "has this `MessageId` (or signature) already been processed/broadcast" before performing the loop over `h.donConfig.Members` and calling `don.SendToNode`. Because `savedCallbacks` entries are only pruned by age/size (`pruneCallbacks`) and deleted only when a *response* to that particular MessageId arrives from a node (`handleWebAPITriggerMessage`, lines 148-162), an attacker who resends the identical signed message before expiry passes every check exactly as the original submission did, causing the gateway to send the trigger to all DON members again. Since `MethodWebAPITrigger` messages ultimately fire workflow executions on receiving nodes, this results in duplicate/unintended workflow trigger executions across the DON for a single legitimately-issued (but replayed) request.

### Impact Explanation
Attacker-controlled repetition of a captured signed trigger causes duplicate privileged workflow executions to be dispatched to the entire DON within the message's validity window (`MaxAllowedMessageAgeSec`, config-driven, default not shown here but typically short-lived). This matches the "unauthorized/duplicate transaction or workflow execution" bounty category — each replay is indistinguishable from a legitimate new trigger request to the DON members, and any downstream side effects (e.g., contract writes, external calls) invoked by the triggered workflow could be executed multiple times.

### Likelihood Explanation
Feasibility depends on the attacker being able to capture a valid signed message before it expires — e.g., via network observation of the (non-mTLS-protected at this layer) gateway traffic, replaying webhook/event logs, or observing publicly logged workflow trigger submissions. No node-operator or key-leak privilege is required; the attacker only needs bytes of a previously sent request. Repeatability is bounded only by the freshness window, but nothing prevents many replays within that window, and no rate limiting/nonce tracking exists at this handler layer (`// TODO: apply allowlist and rate-limiting here` comment confirms this gap is a known, unaddressed limitation, line 384).

### Recommendation
Add a used-message-id (or used-signature) registry, analogous to `savedCallbacks` but persisted for the full `MaxAllowedMessageAgeSec` window and consulted before broadcasting: if `msg.Body.MessageId` (or a hash of `Body`+`Signature`) has already been seen and not yet expired, reject the request with a duplicate/replay error instead of re-broadcasting to `don.SendToNode`. This should be checked atomically under `h.mu` alongside insertion into `savedCallbacks`.

### Proof of Concept
Integration/unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `HandlerConfig` with `MaxAllowedMessageAgeSec` large enough to remain valid for the whole test.
2. Build a valid signed `api.Message` with `Method = MethodWebAPITrigger` and a fixed `Timestamp`.
3. Set up a mock `handlers.DON` (as already done in existing tests) with N members and a `SendToNode` mock that increments a counter.
4. Call `handler.HandleLegacyUserMessage(ctx, msg, callback1)`, then call it again with the identical `msg` object (same `Body`, same `Signature`) and a second callback, both before the timestamp exceeds `MaxAllowedMessageAgeSec`.
5. Assert: current (buggy) behavior — `don.SendToNode` call count == `2 * len(members)` (broadcast happened twice), demonstrating the missing replay guard. Expected/fixed behavior — the second call should be rejected before reaching `don.SendToNode`, keeping the call count at `1 * len(members)`.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {
		h.lggr.Errorw("stale message")
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.HandlerError),
				"stale message",
				nil,
			),
			ErrorCode: api.HandlerError,
		})
	}
	// TODO: apply allowlist and rate-limiting here
	if msg.Body.Method != MethodWebAPITrigger {
		h.lggr.Errorw("unsupported method", "method", body.Method)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UnsupportedMethodError),
				"invalid method "+msg.Body.Method,
				nil,
			),
			ErrorCode: api.UnsupportedMethodError,
		})
	}
	req, err := common.ValidatedRequestFromMessage(msg)
	if err != nil {
		h.lggr.Errorw(ErrTransformingMessageToRequest)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrTransformingMessageToRequest,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	h.mu.Lock()
	h.savedCallbacks[msg.Body.MessageId] = &savedCallback{id: msg.Body.MessageId, createdAt: time.Now(), Callback: callback}
	don := h.don
	h.mu.Unlock()

	// Send original request to all nodes
	for _, member := range h.donConfig.Members {
		err = errors.Join(err, don.SendToNode(ctx, member.Address, req))
	}
	return err
}
