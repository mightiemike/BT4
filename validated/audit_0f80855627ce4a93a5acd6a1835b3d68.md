### Title
Auto-Swap Min-Output Derived from Manipulable Spot Quote (No TWAP) - ([File: x/uexecutor/keeper/evm.go])

### Summary
The external report flags a Maverick pool created with an unsafely short (30s) TWAP lookback for `createPermissioned`, allowing an attacker to skew the TWAP with limited capital and manipulate the price the protocol relies on. Push Chain's analogous fund-moving flow goes further: it doesn't use a TWAP at all. `GetSwapQuote` calls Uniswap V3 `QuoterV2.quoteExactInputSingle`, which reports the **current spot price** of the pool, and the resulting quote is used to derive the enforced minimum-output (`minPCOut = quote * 95 / 100`) for a real on-chain swap of user-deposited funds.

### Finding Description
`GetSwapQuote` [1](#0-0)  queries the Uniswap V3 `QuoterV2` contract for `quoteExactInputSingle`, which reflects the pool's instantaneous price at the current block — there is no lookback window, no TWAP `observe()`/`consult()` call, and no reference to `ChainMetaOracle`/median-based price aggregation anywhere in this path (confirmed no `TWAP`/`observe(`/`consult(` usage exists in the repo outside of unrelated gas-price oracle code).

This spot quote directly determines the slippage-protection bound used to authorize a real, fund-moving swap of user-deposited assets:
- `ExecuteInboundGas` (GAS inbound) fetches the quote and computes `minPCOut = quote*95/100` before calling `CallPRC20DepositAutoSwap` [2](#0-1) .
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound) does the same [3](#0-2) .
- `applyGasRefund` (outbound gas refund path) does the same for refund swaps [4](#0-3) .

In all three cases, the "quote → 95% floor → swap" sequence happens back-to-back inside the same keeper call, using whatever the pool's spot price is at execution time. An unprivileged attacker who can move the pool price immediately before finalization of the triggering ballot (e.g., a large swap in the same or preceding block against a thin-liquidity PRC20/WPC pool) can depress the quoted `amountOut`, causing `minPCOut` to be set far below fair value. The protocol-driven swap then executes at that same depressed spot price, and the attacker unwinds their price-moving trade afterward — a classic sandwich, except the "victim" here is protocol-controlled user funds (the depositor's principal being auto-swapped) rather than a user-submitted trade with attacker-chosen slippage.

This is a native structural analog to the reported bug class: reliance on an easily-manipulable short/absent-lookback price observation to gate a value-transferring operation. The external report's fix (extend the lookback) doesn't even have an equivalent lever here because no lookback/TWAP mechanism exists at all — the flat 95% tolerance is the only guard, and it is computed from the same manipulable spot price it is meant to protect against.

### Impact Explanation
This falls within the "corruption of PRC20 or native asset accounting" and "unauthorized ... release" impact categories: an attacker can extract value from the protocol-controlled auto-swap of a legitimate depositor's funds by manipulating the pool price around the block in which the swap executes, causing the depositor (and ultimately the protocol/liquidity providers) to receive systematically worse execution than fair market price, up to the full 5% slippage band per swap, repeatable across every GAS / GAS_AND_PAYLOAD inbound and every gas-refund-with-swap outbound.

### Likelihood Explanation
Triggering requires only: (1) an ordinary unprivileged inbound deposit of a supported gas/PRC20 token routed through the auto-swap path (reachable by any external-chain user), and (2) the ability to move the price of the specific PRC20/WPC Uniswap V3 pool shortly before/at the block the honest UV threshold finalizes and executes that inbound. Because pool liquidity for newer/less-liquid PRC20 pairs may be thin, and because the quote-then-swap sequence uses the same spot read with no time-weighting, this is realistically exploitable without any privileged or malicious-validator/relayer assumption — ordinary honest UV finalization is sufficient for the attacker's manipulated price to be picked up.

### Recommendation
Do not derive `minPCOut` purely from an instantaneous `QuoterV2.quoteExactInputSingle` call taken at swap time. Use a manipulation-resistant reference, e.g.:
- Consult the pool's TWAP via `IUniswapV3Pool.observe()` over a sufficiently long window (analogous to widening the lookback the external report recommends), and/or
- Cross-check the quote against `ChainMeta`/oracle-reported price bounds and reject/clamp swaps whose spot price deviates too far from the TWAP or a governance-configured reference price, and/or
- Cap deposit-triggered swap size per block/pool or require multi-block price confirmation for auto-swap execution.

### Proof of Concept
1. Attacker identifies a low-liquidity PRC20↔WPC Uniswap V3 pool used by `GetSwapQuote`/`GetDefaultFeeTierForToken`.
2. Attacker submits a source-chain deposit that will be routed through `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` (ordinary unprivileged action — ballot finalization only requires honest UV votes, no privileged access needed).
3. Immediately before/at the block where UV votes reach threshold and the keeper executes the auto-swap, the attacker (via a separate EVM transaction they control) swaps a large amount into the pool to depress the PRC20-denominated price of WPC.
4. `GetSwapQuote` returns a depressed `amountOut`; `minPCOut = quote*95/100` is computed from this depressed value [5](#0-4) .
5. `CallPRC20DepositAutoSwap` executes the swap at (or above) this depressed floor, converting the depositor's PRC20 into far less WPC than fair value.
6. Attacker reverses their price-moving trade, capturing the spread extracted from the depositor's principal — with no privileged role, malicious validator, or protocol key compromise required.

Note: I was unable to inspect the deployed Uniswap V3 pool/handler contract source (`UniversalCore`/`QuoterV2` Solidity) directly in this index to confirm pool liquidity assumptions or any external mitigations that might exist at the contract layer; if such protections exist there, they would need to be verified against this on-chain keeper logic before treating this as fully unmitigated.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
