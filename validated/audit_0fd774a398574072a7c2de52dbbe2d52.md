### Title
Undeclared Cairo0 Class Execution via Stale Global Contract Class Cache Skipping Declared-State Verification - (File: crates/blockifier/src/state/state_reader_and_contract_manager.rs)

### Summary
The Yarn TOCTOU advisory describes a cache whose integrity hash is validated once at write time and never re-validated on read, allowing a stale/poisoned cache entry to be served as trusted. The sequencer has a structurally identical pattern in the global contract-class cache: `StateReaderAndContractManager::get_compiled_from_class_manager` explicitly re-validates that a cached class is still `is_declared` in current state for Cairo1/Native classes on every cache hit, but it deliberately skips that re-validation for Cairo0 (`RunnableCompiledClass::V0`) classes.

### Finding Description
`get_compiled_from_class_manager` fetches a runnable class from the process-global `ContractClassManager` cache (`RawClassCache` / `GlobalContractCache`, keyed only by `ClassHash`). This cache persists across the whole node's lifetime, independent of any single block's or state root's commit status: [1](#0-0) 

The code's own comment states the risk explicitly: a cache hit "does not guarantee [the class is declared] (it might contain a declared class from a reverted block, for example)" — and for that reason a `state_reader.is_declared(class_hash)` check is performed on every Cairo1/Native cache hit. However, for `RunnableCompiledClass::V0` (Cairo0) the branch is a no-op (`{}`), so no equivalent re-validation against the authoritative state happens before the cached class is returned and executed: [2](#0-1) 

The cache is populated by `set_and_compile` whenever any speculative/aborted transaction execution reads and compiles a class during concurrent block building (`WorkerExecutor::execute_tx` runs transactions optimistically, and only `apply_writes` state (not the global class cache) is versioned/rolled back on abort or validation failure): [3](#0-2) 

Because the global class cache is not part of the versioned/rollback-aware state (`VersionedState`/`CachedState`), any class hash that gets cached as a side effect of a speculative execution (e.g., of a transaction later aborted, re-ordered, or belonging to a re-orged/never-committed block) remains resident in the cache for the life of the process. For Cairo1 classes this is explicitly mitigated by re-checking `is_declared` against the authoritative state on every cache hit; for Cairo0 classes it is not.

### Impact Explanation
If a Cairo0 class becomes cached as a side effect of speculative/aborted execution without ever being validly declared in the committed state (or its declaration is later reverted), a subsequent, unrelated request for the same `class_hash` (e.g., another concurrent worker or a later block) can receive the class body from the stale cache and execute it as if declared, bypassing the "is declared" state check that would otherwise reject execution of an undeclared class. Because the global cache's population order depends on each node's local, non-deterministic concurrent scheduling of transactions (thread interleaving, worker count, abort/retry timing), different honest nodes can end up with different local cache states for the same class hash at the same logical point in time. This can lead to some nodes executing/allowing an undeclared class while others correctly reject it, producing execution/state-root divergence between otherwise-honest nodes — the exact "honest-node divergence" class of impact this scan is scoped to accept.

### Likelihood Explanation
Exploitation does not require a privileged operator: any account/contract deployer or transaction sender can trigger the declare/deploy/invoke sequences that populate the global class cache via ordinary concurrent block-building, and the vulnerable code path (`RunnableCompiledClass::V0(_) => {}`) is on the hot path of every Cairo0 class read in `get_compiled_class`. That said, actually engineering a case where a *specific* invalid/undeclared Cairo0 class gets cached and later returned to a legitimate caller without ever having been validly declared requires a specific interleaving of concurrent execution/validation-abort events; I could not fully trace, within the available tool budget, a concrete minimal transaction sequence that reliably forces this precise divergence in this codebase (e.g., I did not verify whether upstream callers of `get_compiled_class` for Cairo0 always separately re-check `get_class_hash_at`/`declared_contracts` in a way that would make the omitted check redundant). This should be verified with dynamic testing/fuzzing of the concurrent executor before treating this as a fully confirmed, exploitable bug rather than a design-inconsistency risk.

### Recommendation
Apply the same `is_declared` verification currently done for Cairo1/Native classes to Cairo0 (`RunnableCompiledClass::V0`) cache hits in `get_compiled_from_class_manager`, removing the special-cased no-op branch, so that every cache hit — regardless of Cairo version — is re-validated against the authoritative state before being trusted and executed, mirroring the fix pattern used by Yarn (recomputing/re-validating integrity at read time rather than trusting a write-time-only check).

    fn execute_tx(&self, tx_index: TxIndex) {
        let mut tx_versioned_state = self.state.pin_version(tx_index);
        // TODO(Yoni): is it necessary to use a transactional state here?
        let mut transactional_state =
            TransactionalState::create_transactional(&mut tx_versioned_state);
        let concurrency_mode = true;
        let tx = self.tx_at(tx_index);
        let execution_start = Instant::now();
        let execution_result =
            tx.execute_raw(&mut transactional_state, &self.block_context, concurrency_mode);
        let run_time = execution_start.elapsed();

        // Update the versioned state and store the transaction execution output.
        let execution_output_inner = match execution_result {
            Ok(_) => {
                let tx_reads_writes = transactional_state.cache.take();
                let state_diff = tx_reads_writes.to_state_diff().state_maps;
                let contract_classes = transactional_state.class_hash_to_class.take();
                tx_versioned_state.apply_writes(&state_diff, &contract_classes);
                ExecutionTaskOutput {
                    reads: tx_reads_writes.initial_reads,
                    state_diff,
                    contract_classes,
                    run_time,
                    result: execution_result,
                }
            }
            Err(_) => ExecutionTaskOutput {
                reads: transactional_state.cache.take().initial_reads,
                // Failed transaction - ignore the writes.
                state_diff: StateMaps::default(),
                contract_classes: HashMap::default(),
                run_time,
                result: execution_result,
            },
        };
        self.execution_outputs.insert(tx_index, execution_output_inner);
