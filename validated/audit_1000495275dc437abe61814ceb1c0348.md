### Title
Missing pubkey-to-address binding in `AccountInitDecorator` allows signature-identity forgery for first-use gasless accounts - (File: `app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator` bootstraps on-chain accounts for gasless transactions (UV votes, `MsgExecutePayload`, `MsgMigrateUEA`, etc.) the first time an address is used. Its signature check verifies that the provided signature is valid for `(account_number=0, sequence=0, chainID)` under the attacker-supplied `pubKey`, but it never verifies that `pubKey`'s derived address actually equals the claimed signer address (`msg.Signer`). This is the exact binding check the standard SDK `SetPubKeyDecorator` performs and that this decorator skips while also short-circuiting the rest of the ante chain.

### Finding Description
`AccountInitDecorator.AnteHandle` [1](#0-0)  only runs for gasless transactions and only when the tx has a single signer whose account does not yet exist. It calls `verifySignatureForNewAccount`, which builds `SignerData{Address: newAccAddr.String(), ...}` from the message's declared signer address and verifies the signature against that `SignerData` using the *attacker-supplied* `pubKey` taken directly from `sig.PubKey`: [2](#0-1) .

Nowhere in this function is there a check equivalent to the standard SDK's `pubKey.Address() == newAccAddr` binding (the check performed by `x/auth/ante.SetPubKeyDecorator` in the normal pipeline, which this decorator otherwise bypasses since it never calls `next()` after creating the account) [3](#0-2) . Because the message's `Signer`/voter field (e.g. `MsgVoteInbound.Signer`) is just a bech32 string chosen by the transaction author, and `GetSigners()` merely parses that string [4](#0-3) , an attacker can:

1. Pick any target address `V` that is gasless-eligible and has never sent a transaction (`!HasAccount`) — e.g. a freshly keygen'd Universal Validator hot key, which the module docs explicitly acknowledge can vote before ever being funded [5](#0-4) .
2. Craft a `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta`/`MsgVoteTssKeyProcess`/`MsgVoteFundMigration` message with `Signer = V`.
3. Sign the tx with the attacker's *own* keypair (not V's).
4. Submit it as a gasless tx — it is in the allowlist checked by `IsGaslessTx` [6](#0-5) .

Because `verifySignatureForNewAccount` never checks that the signature's public key hashes to `V`, the forged signature validates, the decorator creates account `V` on-chain, and short-circuits the ante chain (`return ctx, nil`) so the message executes downstream as if authored by `V`. The downstream module logic (e.g. `Keeper.VoteInbound`) trusts the `universalValidator`/`Signer` string taken from the message, not a cryptographically re-derived identity [7](#0-6) , so the forged vote is recorded and counted toward ballot finalization exactly as if the real UV `V` had voted.

### Impact Explanation
This breaks the "Admission and cryptographic path" invariant explicitly in scope: an unprivileged attacker turns forged input into accepted authorization for a first-use gasless account. Concretely, it lets an attacker inject a single fraudulent vote attributed to any not-yet-active gasless-eligible address into the ballot machine used for inbound/outbound/chain-meta observation and TSS/fund-migration voting — directly touching honest-validator finalization convergence (`x/uvalidator` ballot machine) and, via `MsgVoteInbound`, `UniversalTx` creation/execution. Depending on ballot thresholds and how many not-yet-used UV addresses exist at a given time (e.g., during a `KEYGEN`/quorum-change rollout when new UV hot keys are provisioned but haven't voted yet), this can skew ballot outcomes (forcing a `REJECTED` state via injected NO votes, or contributing toward a fraudulent `PASSED` state) without compromising any real validator key — a state-machine-divergence / wrong-ballot-outcome class impact.

### Likelihood Explanation
The attack requires only that the target address is: (a) in the gasless allowlist (any of the six whitelisted message types), and (b) has never posted a transaction on-chain. This window is realistic and even encouraged by design — the decorator's stated purpose is to let brand-new UV hot keys transact before being funded, meaning there is a routine period where legitimate UV addresses exist in this exact vulnerable state (freshly onboarded via `KEYGEN`/`QUORUM_CHANGE`, before their first vote). No privileged access, validator collusion, or key compromise is required — only knowledge of the target's bech32 address, which is public (it is emitted/registered in `x/uvalidator` state during `AddUniversalValidator`/TSS process events).

### Recommendation
In `verifySignatureForNewAccount`, after extracting `pubKey` from the signature, enforce that `sdk.AccAddress(pubKey.Address()) == newAccAddr` before proceeding to `authsigning.VerifySignature`, mirroring the check performed by the standard `x/auth/ante.SetPubKeyDecorator`. Reject the transaction (do not create the account, do not short-circuit) if the derived address does not match the claimed signer.

### Proof of Concept
1. Identify a Universal Validator address `V` that was just added via `MsgAddUniversalValidator`/`KEYGEN` and has not yet sent any transaction (`HasAccount(V) == false`).
2. As attacker, generate your own keypair `(pk_a, sk_a)`.
3. Construct `MsgVoteInbound{ Signer: V, Inbound: <attacker-chosen fake inbound data> }` (or any other gasless-whitelisted vote message).
4. Sign the transaction with `sk_a` using `account_number=0, sequence=0` (matching what `verifySignatureForNewAccount` expects for a new account).
5. Submit the tx. `AccountInitDecorator.AnteHandle` detects `!HasAccount(V)`, calls `verifySignatureForNewAccount`, which validates the signature under `pk_a` against `SignerData{Address: V, AccountNumber: 0, Sequence: 0}` — passing, since no `pk_a.Address() == V` check exists.
6. The decorator creates account `V` and returns `ctx, nil`, bypassing further signature checks; the `MsgVoteInbound` executes with `universalValidator = V`, recording a vote attributed to `V` even though `V`'s real private key never signed anything. [8](#0-7)

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}

	ctx.Logger().Debug("account init decorator: existing account on gasless tx, passing to next handler",
		"address", sdk.AccAddress(newAccAddr).String(),
	)
	return next(ctx, tx, simulate)

func (aid AccountInitDecorator) verifySignatureForNewAccount(ctx sdk.Context, tx sdk.Tx, simulate bool) error {
	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	// stdSigs contains the sequence number, account number, and signatures.
	// When simulating, this would just be a 0-length slice.
	sigs, err := sigTx.GetSignaturesV2()
	if err != nil {
		return err
	}

	signers, err := sigTx.GetSigners()
	if err != nil {
		return err
	}

	// check that signer length and signature length are the same
	if len(sigs) != len(signers) {
		return errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "invalid number of signer;  expected: %d, got %d", len(signers), len(sigs))
	}

	newAccAddr := sdk.AccAddress(signers[0])
	for _, sig := range sigs {
		pubKey := sig.PubKey
		if pubKey == nil {
			return errorsmod.Wrap(sdkerrors.ErrInvalidPubKey, "pubkey is not provided in signature")
		}

		// retrieve signer data
		chainID := ctx.ChainID()
		var accSequence uint64 = 0
		var accNum uint64 = 0

		// no need to verify signatures on recheck tx
		if !simulate && !ctx.IsReCheckTx() && ctx.IsSigverifyTx() {
			anyPk, _ := codectypes.NewAnyWithValue(pubKey)

			signerData := txsigning.SignerData{
				Address:       newAccAddr.String(),
				ChainID:       chainID,
				AccountNumber: accNum,
				Sequence:      accSequence,
				PubKey: &anypb.Any{
					TypeUrl: anyPk.TypeUrl,
					Value:   anyPk.Value,
				},
			}
			adaptableTx, ok := tx.(authsigning.V2AdaptableTx)
			if !ok {
				return fmt.Errorf("expected tx to implement V2AdaptableTx, got %T", tx)
			}
			txData := adaptableTx.GetSigningTxData()
			ctx.Logger().Debug("account init decorator: verifying signature for new account",
				"address", newAccAddr.String(),
				"chain_id", chainID,
				"acc_num", accNum,
				"sequence", accSequence,
			)
			err = authsigning.VerifySignature(ctx, pubKey, signerData, sig.Data, aid.signModeHandler, txData)
			if err != nil {
				var errMsg string
				if OnlyLegacyAminoSigners(sig.Data) {
					// If all signers are using SIGN_MODE_LEGACY_AMINO, we rely on VerifySignature to check account sequence number,
					// and therefore communicate sequence number as a potential cause of error.
					errMsg = fmt.Sprintf("signature verification failed; please verify account number (%d), sequence (%d) and chain-id (%s)", accNum, accSequence, chainID)
				} else {
					errMsg = fmt.Sprintf("signature verification failed; please verify account number (%d) and chain-id (%s): (%s)", accNum, chainID, err.Error())
				}
				ctx.Logger().Debug("account init decorator: signature invalid for new account",
					"address", newAccAddr.String(),
					"chain_id", chainID,
				)
				return errorsmod.Wrap(sdkerrors.ErrUnauthorized, errMsg)

			}
		} else {
			ctx.Logger().Debug("account init decorator: skipping signature verification",
				"address", newAccAddr.String(),
				"simulate", simulate,
				"is_recheck_tx", ctx.IsReCheckTx(),
				"is_sigverify_tx", ctx.IsSigverifyTx(),
			)
		}
	}
	return nil

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
