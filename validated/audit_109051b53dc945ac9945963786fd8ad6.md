## Analysis

The Badger Citadel report describes a classic "quote-then-execute-in-same-transaction" sandwich: a value-increasing action (`mintAndDistribute`) is computed and applied atomically, but because the resulting price move is predictable and reachable by ordinary depositors/withdrawers, an attacker can bracket it to extract value from other participants, with the fix being out-of-band submission (flashbots).

Push Chain has a structurally identical pattern in its own on-chain AMM interaction: the `x/uexecutor` module fetches a live spot quote from the protocol's own Uniswap V3 `QuoterV2` and immediately executes a swap against that price with only a fixed 5% slippage bound — no TWAP, no attacker-independent price reference, and no execution-time protection beyond `quote * 95/100`.

### Title
Wide fixed 5% slippage tolerance on protocol-executed PRC20↔PC swaps enables MEV sandwich extraction from user deposits and gas refunds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
For `GAS` / `GAS_AND_PAYLOAD` inbound deposits and for outbound gas refunds, the module fetches a spot quote from `UniversalCore`'s Uniswap V3 `QuoterV2` via `GetSwapQuote` and then executes `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` with `minPCOut = quote * 95 / 100` — a fixed 5% slippage tolerance computed and consumed in the same flow with no other price protection. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`GetSwapQuote` performs a static (`commit=false`) call to `QuoterV2.quoteExactInputSingle` to read the current pool price, and the resulting `minPCOut` is derived purely as `quote * 95 / 100`: [4](#0-3) 

This quote-and-swap sequence is triggered deterministically by the *third* `MsgVoteInbound` (or `MsgVoteOutbound`) that finalizes a ballot — i.e., by a **public, unprivileged, user-observable transaction** broadcast by a Universal Validator. Because `MsgVoteInbound`/`MsgVoteOutbound` are gasless and whitelisted, they are ordinary mempool-visible transactions: [5](#0-4) 

Any unprivileged actor watching the mempool for the finalizing vote can:
1. Front-run it with a large swap on the same `UniversalCore` Uniswap V3 pool to push the PRC20→PC price down,
2. Let the protocol's deposit-autoswap or gas-refund-autoswap execute against the manipulated price (still within the loose 5% band, so it doesn't revert),
3. Back-run to restore the pool price, capturing the difference.

This is functionally the same primitive as the cited Badger Citadel bug: a state-changing, value-moving operation (`mintAndDistribute` there, `depositPRC20WithAutoSwap`/`refundUnusedGas` here) is computed from a price/exchange-rate at execution time with no MEV protection, and the trigger transaction (mint call / vote-finalizing tx) is publicly visible before inclusion, enabling a deposit-before/extract-after (or price-push-before/reap-after) sandwich.

### Impact Explanation
A successful sandwich directly reduces the PRC20 or PC amount actually credited to the depositor's UEA, or the amount refunded to the gas-refund recipient, by up to ~5% of the swapped amount — i.e. a **partial, unauthorized loss of user-controlled funds** on every GAS/GAS_AND_PAYLOAD inbound and every outbound gas-fee refund, extracted by an unprivileged attacker with no validator or admin privilege required. This falls squarely under "stealing ... permanent loss ... of user or protocol-controlled funds" and "corruption of PRC20 or native asset accounting ... gas fee accounting ... refund accounting."

### Likelihood Explanation
Likelihood is bounded by the same economics BadgerDAO's own team raised for the original finding: the attacker needs enough capital to move the specific PRC20/WPC pool by up to 5% and back, and needs to win transaction ordering around the finalizing vote (achievable via searcher/builder relationships or same-block bundling, without needing to compromise any validator). No collusion with Universal Validators or admins is required — only observation of public gasless vote transactions and the ability to trade against the same on-chain pool. The wide, fixed 5% tolerance (vs. typical <1% DEX aggregator tolerances) meaningfully increases the attacker's available margin compared to a tighter bound.

### Recommendation
- Replace the fixed 5% slippage with a much tighter, config-driven tolerance, and/or derive `minPCOut` from a manipulation-resistant reference (e.g., TWAP over several blocks) rather than a single spot `quoteExactInputSingle` call taken immediately before execution.
- Consider decoupling quote computation from the same transaction/block as execution, or applying a commit-reveal / randomized-delay design so the exact execution point cannot be reliably front-run from mempool observation of the finalizing vote.
- Cap the acceptable price impact from the swap versus a longer-window oracle price, not just the two numbers computed back-to-back in the same call.

### Proof of Concept
1. Monitor the Push Chain mempool for a pending `MsgVoteInbound` (or `MsgVoteOutbound`) that will be the 2/3-quorum-finalizing vote for a `GAS_AND_PAYLOAD` inbound or an outbound gas refund — this is public because gasless whitelisted messages are ordinary broadcast transactions [6](#0-5) .
2. Submit a transaction ahead of it that swaps a large amount of PRC20 into the `UniversalCore` Uniswap V3 pool used by `GetSwapQuote`/`CallPRC20DepositAutoSwap`, pushing the pool price down within the tolerance the protocol will still accept (`quote*95/100`) [7](#0-6) .
3. Let the finalizing vote land, triggering `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, which fetches the now-depressed quote and executes `CallPRC20DepositAutoSwap` against it, delivering a below-fair-value amount of PC to the victim's UEA [8](#0-7) .
4. Submit a back-run transaction restoring the pool price, capturing the spread as profit — the same "deposit-before/extract-after" mechanic described in the source Citadel finding, applied to Push Chain's own protocol-mediated swap instead of a staking share price.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
