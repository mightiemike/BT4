### Title
Unbounded, un-removable growth of `WitnessStore` allows `doMaintenance()` to become an unbounded-cost loop executed on every maintenance cycle - ([File: consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java])

### Summary
Analogous to the Holdefi `marketsList`, java-tron's `WitnessStore` list of witness candidates can be grown without limit by any funded account via `WitnessCreateActuator`, and there is no corresponding "remove witness" action that shrinks the underlying store. `MaintenanceManager.doMaintenance()` fully iterates `consensusDelegate.getAllWitnesses()` (backed by `WitnessStore.getAllWitnesses()`) on every maintenance cycle as part of normal block processing, performing per-witness store reads/writes. Because the source list can grow indefinitely and cheaply, the cost of this mandatory, deterministic, per-cycle operation grows unbounded over time.

### Finding Description
`WitnessCreateActuator.validate()`/`execute()` allow **any account** to register as a witness candidate by paying `dynamicStore.getAccountUpgradeCost()`, with no cap on the total number of witnesses that can be created: [1](#0-0) [2](#0-1) 

Each created witness is stored permanently in `WitnessStore`, and the only bulk read API is `getAllWitnesses()`, which iterates the *entire* underlying LevelDB/RocksDB collection with no bound: [3](#0-2) 

There is no witness-removal contract analogous to `removeMarket` in the report; a witness candidate, once created, stays in `WitnessStore` forever (it can at most fail to be re-elected into the *active* set, which is separately capped, but the underlying candidate list itself is never trimmed).

This unbounded `getAllWitnesses()` result is fully iterated inside `MaintenanceManager.doMaintenance()`, which runs deterministically once per maintenance cycle as part of `processBlock()`: [4](#0-3) [5](#0-4) 

Each iteration performs a store read (`consensusDelegate.getWitness`), potential DB writes (`consensusDelegate.saveWitness`, `delegationStore.setBrokerage`/`setWitnessVote`), and additional lookups in `newWitnessAddressList`. This whole loop is invoked from `Manager.processBlock()`'s maintenance branch, which every full node executes as part of accepting a block: [6](#0-5) 

Unlike the *active* witness set, which is explicitly capped at `MAX_ACTIVE_WITNESS_NUM` when selecting winners (`DposService.updateWitness`): [7](#0-6) 
the *candidate* list held in `WitnessStore` that feeds `doMaintenance()` has no such cap, so the cost of maintenance grows linearly with the number of witnesses ever created, and that number can never decrease.

### Impact Explanation
This mirrors the Holdefi bug class precisely: an unprivileged, cheaply repeatable action (paying `AccountUpgradeCost`, not an admin-only fee) creates entries in a list that (a) has no size limit and (b) has no removal path, and that list is then iterated in full inside a mandatory, deterministic, block-processing code path (`doMaintenance()`, invoked from `Manager.processBlock()` at every maintenance cycle boundary). As the candidate set grows, the per-cycle cost (extra DB reads/writes, comparator/list operations across the codebase such as `sortWitness`, `getWitnessStandby`, and `newWitnessAddressList` construction) grows without bound, threatening the ability of nodes to complete block/maintenance processing within the network's fixed block interval, which is a consensus liveness/availability risk (chain slow-down or halt) rather than a merely cosmetic issue - directly analogous to the "clearing debts" out-of-gas scenario described in the report.

### Likelihood Explanation
Creating a witness only requires normal account balance ≥ `AccountUpgradeCost` (a fixed, configurable network fee, not proposal/governance-gated); there is no rate limit or cap on the number of distinct witness candidates that can be created over time, and nothing ever removes an entry from `WitnessStore`. An attacker or group of unprivileged accounts could therefore incrementally grow the candidate set over an extended period. I was not able to fully verify (within this analysis) whether `MAX_ACTIVE_WITNESS_NUM` or `WITNESS_STANDBY_LENGTH` constants impose any indirect bound on `WitnessStore` size itself, nor did I get to inspect `Parameter.java`/`NodeConfig.java` contents for the exact numeric cost of `AccountUpgradeCost` or any hidden governance parameter that might mitigate this in practice — a background engineering session with full file access should confirm these values and whether any additional guard exists before treating this as exploitable at scale.

### Recommendation
Introduce an explicit cap on the number of witness candidates that can exist simultaneously (e.g., reject `WitnessCreateContract` once `WitnessStore` size reaches a configurable maximum), and/or add a witness-deregistration mechanism (e.g., allow a witness with zero votes for N cycles to be pruned from `WitnessStore`) so `doMaintenance()`'s per-cycle cost remains bounded regardless of how long the network has been running.

### Proof of Concept
1. Fund N distinct accounts, each with balance ≥ `dynamicStore.getAccountUpgradeCost()`.
2. For each account, broadcast a `WitnessCreateContract` (see `WitnessCreateActuator.execute`/`createWitness`), which unconditionally succeeds as long as the account is not already a witness and has sufficient balance — no global cap check exists.
3. Repeat over time (or via many accounts in parallel) to grow `WitnessStore` to an arbitrarily large size; none of these entries can ever be removed.
4. Observe that every maintenance cycle, `MaintenanceManager.doMaintenance()` (triggered from `Manager.processBlock()`) iterates `consensusDelegate.getAllWitnesses()` — now proportional to the attacker-inflated candidate count — performing DB reads/writes for each entry, increasing the wall-clock cost of block/maintenance processing for every full node on the network without bound.

  private void createWitness(final WitnessCreateContract witnessCreateContract)
      throws BalanceInsufficientException {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    WitnessStore witnessStore = chainBaseManager.getWitnessStore();
    //Create Witness by witnessCreateContract
    final WitnessCapsule witnessCapsule = new WitnessCapsule(
        witnessCreateContract.getOwnerAddress(),
        0,
        witnessCreateContract.getUrl().toStringUtf8());

    logger.debug("createWitness,address[{}]", witnessCapsule.createReadableString());
    witnessStore.put(witnessCapsule.createDbKey(), witnessCapsule);
    AccountCapsule accountCapsule = accountStore
        .get(witnessCapsule.createDbKey());
    accountCapsule.setIsWitness(true);
    if (dynamicStore.getAllowMultiSign() == 1) {
      accountCapsule.setDefaultWitnessPermission(dynamicStore);
    }
    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    long cost = dynamicStore.getAccountUpgradeCost();
    adjustBalance(accountStore, witnessCreateContract.getOwnerAddress().toByteArray(), -cost);
    if (dynamicStore.supportBlackHoleOptimization()) {
      dynamicStore.burnTrx(cost);
    } else {
      adjustBalance(accountStore, accountStore.getBlackhole(), +cost);
    }
    dynamicStore.addTotalCreateWitnessCost(cost);
  }

  public void doMaintenance() {
    VotesStore votesStore = consensusDelegate.getVotesStore();

    tryRemoveThePowerOfTheGr();

    DynamicPropertiesStore dynamicPropertiesStore = consensusDelegate.getDynamicPropertiesStore();
    DelegationStore delegationStore = consensusDelegate.getDelegationStore();
    if (dynamicPropertiesStore.useNewRewardAlgorithm()) {
      long curCycle = dynamicPropertiesStore.getCurrentCycleNumber();
      consensusDelegate.getAllWitnesses().forEach(witness -> {
        delegationStore.accumulateWitnessVi(curCycle, witness.createDbKey(), witness.getVoteCount());
      });
    }

    Map<ByteString, Long> countWitness = countVote(votesStore);
    if (!countWitness.isEmpty()) {
      List<ByteString> currentWits = consensusDelegate.getActiveWitnesses();

      List<ByteString> newWitnessAddressList = new ArrayList<>();
      consensusDelegate.getAllWitnesses()
          .forEach(witnessCapsule -> newWitnessAddressList.add(witnessCapsule.getAddress()));

      countWitness.forEach((address, voteCount) -> {
        byte[] witnessAddress = address.toByteArray();
        WitnessCapsule witnessCapsule = consensusDelegate.getWitness(witnessAddress);
        if (witnessCapsule == null) {
          logger.warn("Witness capsule is null. address is {}", Hex.toHexString(witnessAddress));
          return;
        }
        AccountCapsule account = consensusDelegate.getAccount(witnessAddress);
        if (account == null) {
          logger.warn("Witness account is null. address is {}", Hex.toHexString(witnessAddress));
          return;
        }
        witnessCapsule.setVoteCount(witnessCapsule.getVoteCount() + voteCount);
        consensusDelegate.saveWitness(witnessCapsule);
        logger.info("address is {} , countVote is {}", witnessCapsule.createReadableString(),
            witnessCapsule.getVoteCount());
      });
