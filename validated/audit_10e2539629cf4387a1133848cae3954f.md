### Title
Uncontrolled recursion in `sort_json_value` during deprecated (Cairo 0) class hash computation can crash Starknet OS re-execution - (File: `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs`)

### Summary
`compute_cairo_hinted_class_hash` in `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs` deserializes an attacker-controlled Cairo 0 (deprecated) contract class into `CairoContractDefinition`, whose `abi` field is an untyped, unbounded `serde_json::Value`, then calls `sort_json_value` to recursively sort every nested JSON object/array before hashing. [1](#0-0) [2](#0-1) 

`sort_json_value` recurses once per nesting level of the JSON value with no depth limit, directly analogous to the ammonia DOM-serialization recursion bug (CVE-2019-15542): an attacker can submit a class whose `abi` (or `identifiers`/`reference_manager`/`hints` fields, which are also raw `serde_json::Value`) contains deeply nested arrays/objects to trigger unbounded native-stack recursion. [3](#0-2) 

### Finding Description
This function is invoked from two paths that are both reachable from a declared class:
1. `compute_deprecated_class_hash`, called to compute the deprecated compiled-class hash. [4](#0-3) 
2. `LoadCairoObject::load_into` for `ContractClass` (deprecated), used to compute the `hinted_class_hash` while loading the deprecated compiled class into the Starknet OS Cairo VM during transaction re-execution of a Declare transaction. [5](#0-4) 

The Starknet OS `execute_declare_transaction` flow computes/validates class hashes for declared classes as part of block re-execution/proving preparation. [6](#0-5) 

Since `sort_json_value` recurses per level of JSON nesting with no depth cap, and the `abi` field accepts arbitrary attacker-controlled JSON with `#[serde(deny_unknown_fields)]` only constraining top-level shape (not nesting depth), a maliciously crafted Cairo 0 class declaration with e.g. hundreds of thousands of nested arrays in its ABI can exhaust the native call stack and crash the process executing this code path (stack overflow is not a recoverable Rust panic — it aborts the process).

### Impact Explanation
A stack overflow abort during Starknet OS re-execution of a Declare transaction (Cairo 0 class) crashes the OS/re-execution process handling that block, rather than yielding a rejected transaction or a caught error. This can:
- Halt block re-execution/proving for the block containing the malicious declare transaction, since the process aborts rather than returning an error.
- Cause honest-node divergence if the crash is intermittent/hardware-stack-size dependent across different nodes/environments, or a persistent inability to progress past that block if deterministic — matching "a network unable to confirm new transactions" outcome required by the validation criteria.

This satisfies High-severity criteria analogous to the original ammonia advisory (a single attacker-crafted input causing uncontrolled recursion / process abort), since it is reachable by any class declarer submitting a single Declare (V0/V1 Cairo0) transaction.

### Likelihood Explanation
Likelihood is High: any account can submit a Declare transaction for a Cairo 0 class with an oversized/deeply-nested ABI JSON blob. Gas/resource metering on the gateway/mempool bounds computational steps but does not necessarily bound native recursion depth of a JSON traversal performed in native Rust code outside the Cairo VM's step-based accounting — this recursion happens in `hinted_class_hash.rs`, a plain Rust function, not inside metered Cairo execution. As long as the class satisfies size/format checks and passes serialization/deserialization, the recursive traversal executes unconditionally when the OS computes the hinted hash.

Note: I could not fully verify (within available tool budget) whether the gateway/mempool enforces an ABI JSON depth or overall size limit before this stage, or whether class size limits (e.g., `DEFAULT_MAX_SIERRA_PROGRAM_SIZE`-like limits) indirectly bound nesting depth. This is an area of uncertainty that should be confirmed — if a strict max class size is enforced early (e.g., a few hundred KB) it may still allow enough nesting depth (JSON like `[[[[...]]]]` needs only 2 bytes per nesting level) to overflow a typical thread stack, since the RUST_MIN_STACK is only explicitly increased for `native_blockifier`'s config, not necessarily for `starknet_os` re-execution/proving processes.

### Recommendation
- Convert `sort_json_value` to an iterative, explicit-stack (worklist) algorithm instead of native recursion, removing dependence on call-stack depth.
- Alternatively, impose and enforce an explicit maximum JSON nesting depth for the deprecated class `abi`/`identifiers`/`hints`/`reference_manager` fields at class validation/ingestion time (gateway or class manager), rejecting classes that exceed the limit before they reach OS re-execution.
- Add a fuzz/regression test that declares a Cairo 0 class with deeply nested ABI JSON (e.g., 100k+ levels) and asserts graceful error rather than process abort.

### Proof of Concept
1. Construct a Cairo 0 (`DeclareV1`) contract class JSON where the `abi` field is a deeply nested JSON array, e.g. `"[" * N + "]" * N` for large N (e.g., 500,000), keeping the rest of the class (`program`, `entry_points_by_type`) minimally valid.
2. Submit this class via a Declare transaction (V0/V1) to the gateway; it passes basic structural validation since `abi: serde_json::Value` accepts arbitrary JSON shapes.
3. When the transaction reaches Starknet OS re-execution (`execute_declare_transaction` → `LoadCairoObject::load_into` for the deprecated `ContractClass`, or class-hash computation path `compute_deprecated_class_hash`), `compute_cairo_hinted_class_hash` is called: [7](#0-6) 
4. `sort_json_value` recurses N times over the nested array, exhausting the native stack and aborting the process handling block re-execution/proving for that block.

/// Recursively sorts all JSON objects by their keys.
/// This ensures deterministic serialization regardless of the `preserve_order` feature in
/// serde_json.
fn sort_json_value(value: serde_json::Value) -> serde_json::Value {
    match value {
        serde_json::Value::Object(map) => {
            let sorted: BTreeMap<String, serde_json::Value> =
                map.into_iter().map(|(k, v)| (k, sort_json_value(v))).collect();
            serde_json::Value::Object(sorted.into_iter().collect())
        }
        serde_json::Value::Array(arr) => {
            serde_json::Value::Array(arr.into_iter().map(sort_json_value).collect())
        }
        other => other,
    }
}

pub fn compute_deprecated_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    let hinted_class_hash = compute_cairo_hinted_class_hash(contract_class)?;
    let contract_definition_vec = serde_json::to_vec(contract_class)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let FlatEntryPointFelts { external, l1_handler, constructor } =
        get_flat_entry_point_felts(&contract_definition.entry_points_by_type);
    let builtins = ascii_strs_as_felts(&contract_definition.program.builtins);
    let bytecode = hex_strs_as_felts(&contract_definition.program.data);

    let mut hash_state = HashState::<Pedersen>::new();
    hash_state.update_single(&DEPRECATED_COMPILED_CLASS_VERSION);
    hash_state.update_with_hashchain(&external);
    hash_state.update_with_hashchain(&l1_handler);
    hash_state.update_with_hashchain(&constructor);
    hash_state.update_with_hashchain(&builtins);
    hash_state.update_single(&hinted_class_hash);
    hash_state.update_with_hashchain(&bytecode);
    Ok(hash_state.finalize())
