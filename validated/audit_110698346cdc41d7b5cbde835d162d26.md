### Title
Missing rate limit on gasless-tx account creation and message admission enables unbounded free spam / state-bloat DoS - (File: app/ante/account_init_decorator.go)

### Summary
The external report's bug class ("missing application-level rate limit exposing the app to brute force and DoS") has a concrete analog in Push Chain's gasless transaction admission path. `IsGaslessTx` [1](#0-0)  allows any unprivileged account to submit `MsgExecutePayload`, `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, or `MsgVoteFundMigration` without paying any fee, and `AccountInitDecorator` will silently create a brand-new on-chain account for any never-before-seen signer as long as the tx is gasless, at zero cost [2](#0-1) . Neither of these paths has any per-account, per-IP, or global throttle.

### Finding Description
`NewCosmosAnteHandler` wires `NewAccountInitDecorator` right before signature verification, specifically to let a "freshly-keygen'd Universal Validator hot key vote on its very first tx, without anyone first having to fund it" [3](#0-2) . For `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta`/`MsgVoteTssKeyProcess`/`MsgVoteFundMigration` this is bounded by the `IsBondedUniversalValidator` check inside the message handlers, so only bonded UVs benefit in practice.

However, `MsgExecutePayload` is explicitly documented as callable by "any" account, gasless, since "the UEA itself authenticates the request" [4](#0-3) . Its `ValidateBasic` only checks bech32 well-formedness, non-nil payload, and hex-decodability of `VerificationData` — it never validates that the verification data actually authorizes anything [5](#0-4) .

Because `MsgExecutePayload` is in the gasless whitelist, an attacker can:
1. Generate an arbitrary new keypair/address (never used on-chain).
2. Sign a syntactically valid but semantically meaningless `MsgExecutePayload` with account_number=0, sequence=0 using that key.
3. Submit it. `AccountInitDecorator.AnteHandle` sees `!aid.ak.HasAccount(ctx, newAccAddr)` is true, calls `verifySignatureForNewAccount` — which only checks that the signature is valid for account_number=0/sequence=0 (trivially satisfiable by the attacker, since they hold the private key) — then unconditionally calls `aid.ak.NewAccountWithAddress(ctx, newAccAddr)` and persists it via `SetAccount`, bypassing the rest of the ante chain (fee deduction, gas-for-tx-size, min-gas-price) entirely [6](#0-5) .
4. The message itself may later fail in `ExecutePayloadV2` (e.g., because the payload doesn't resolve to a real UEA or verification fails on the EVM side), but the account record has already been created and committed to state before the message handler even runs.

There is no cap on how many distinct never-used addresses a single attacker can generate and submit gasless `MsgExecutePayload` transactions for. Each is processed with negligible attacker cost (no fee, no gas billed at the Cosmos layer — `DeductFeeDecorator` and `MinGasPriceDecorator` both skip gasless txs [7](#0-6) [8](#0-7) ), only the cost of key generation and signing off-chain. This is the same "missing rate limit -> brute force / DoS" class as the cited report, but native to Push Chain's gasless admission control rather than a generic authentication endpoint.

### Impact Explanation
An unprivileged attacker can flood the mempool and block space with an unbounded stream of free `MsgExecutePayload` transactions from freshly generated addresses, each of which:
- consumes CheckTx/DeliverTx processing time and mempool slots without paying fees (since fee/min-gas-price checks are skipped for gasless txs),
- permanently grows the auth module's account state (new `BaseAccount` records are written for every unique attacker-generated address, regardless of whether the underlying payload succeeds),
- can crowd out legitimate gasless UV votes and legitimate user `MsgExecutePayload` traffic, since there is no isolation between users of the shared gasless lane.

This is an application-layer denial-of-service / resource-exhaustion vector reachable by any unprivileged external actor with no funds and no special access, matching the "denial of service... reachable without privileged control" allowed impact.

### Likelihood Explanation
Likelihood is high in terms of ease of execution — generating keypairs and valid account_number=0/sequence=0 signatures is trivial and requires no chain state knowledge or timing — but the resulting damage is bounded by standard CometBFT/Cosmos mempool limits (max txs, max mempool bytes, per-peer rate limiting at the P2P layer) and by validators' ability to tune `min-gas-prices`/mempool config, which don't apply here specifically because these are gasless. The most durable damage is the permanent, unbounded growth of on-chain account state, which is not self-healing.

### Recommendation
- Introduce an application-level cap on gasless account creation and/or gasless message submission, e.g.: a maximum number of new-account creations via `AccountInitDecorator` per block or per proposer window, a bonded-UV-only restriction analogous to the vote messages for `MsgExecutePayload`-triggered account creation, or a lightweight proof-of-work/deposit-and-refund requirement for first-time gasless senders.
- Alternatively, require `MsgExecutePayload`'s `Signer` to already have an existing account (reject gasless account auto-creation for this message type), since the actual authorization is enforced inside the UEA contract anyway and the account init fast-path was designed for UV hot keys, not arbitrary payload relayers.
- Add metrics/alerting on the rate of new account creation via the gasless path so anomalous spamming can be detected and mitigated operationally.

### Proof of Concept
1. Generate N distinct new Cosmos keypairs, none of which have ever transacted on Push Chain.
2. For each keypair, construct a `MsgExecutePayload` with `Signer` = the new address, an arbitrary (even bogus) `UniversalAccountId`/`UniversalPayload`, and any hex string for `VerificationData` (only needs to hex-decode, per `ValidateBasic`).
3. Sign the transaction envelope for account_number=0, sequence=0 with the new keypair's private key.
4. Submit repeatedly with new keypairs; observe: (a) no fee is required (`IsGaslessTx` = true), (b) `AccountInitDecorator` creates and persists a new `BaseAccount` for each address before the message handler runs, (c) the underlying `ExecutePayloadV2` call may fail without affecting the already-created account, and (d) there is no cap preventing repeating this indefinitely from a single attacker machine generating fresh keys.

Note: I was not able to fully verify from the indexed code whether there is any additional mempool-level throttling (e.g., CometBFT `mempool.max-txs-bytes`, IP-based rate limiting in `config.toml`) that might partially mitigate raw transaction volume — such settings are operational/config-level rather than application code, and are out of scope for this repository-code-based finding. The account-state-bloat consequence, however, is independent of mempool config and persists once a transaction is included in a block.

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}

func (msg *MsgExecutePayload) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate universal payload
	if msg.UniversalPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal payload cannot be nil")
	}

	// Validate verificationData
	if len(msg.VerificationData) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "verificationData cannot be empty")
	}
	if _, err := hex.DecodeString(strings.TrimPrefix(msg.VerificationData, "0x")); err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid verificationData hex")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate universal payload structure
	if err := msg.UniversalPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universal payload")
	}

	return nil
}
