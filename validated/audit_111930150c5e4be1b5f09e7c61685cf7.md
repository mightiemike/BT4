## Analysis

The Berachain report is about a duration expressed as a **slot/block count** silently drifting in real time because block time is not constant. Agave--011 now has a directly analogous situation: `runtime/src/slot_params.rs` introduces feature-gated slot-time reduction (`reduce_slot_time_to_350ms/300ms/250ms/200ms`), meaning `ns_per_slot` is **not constant** across the life of a cluster — exactly like Berachain's variable block time.

Agave's accounts-db "ancient storage" subsystem, however, still expresses its aging/packing boundary purely as a **slot count** that was calibrated assuming a fixed, legacy slot duration, with no wall-clock correction.

### Title
Ancient-AppendVec packing threshold is defined in slots, not wall-clock time, so agave slot-time-reduction features silently change its real-world cadence - (File: accounts-db/src/accounts_db.rs)

### Summary
`ANCIENT_APPEND_VEC_DEFAULT_OFFSET` and `get_oldest_non_ancient_slot`/`get_oldest_non_ancient_slot_from_slot` define the "ancient" cutoff purely in terms of `slots_per_epoch` and a fixed slot offset, with the comment describing this as "the number of slots in an epoch." [1](#0-0)  This design implicitly assumes a fixed slot duration (historically 400ms), giving the ancient boundary a roughly fixed real-time span. Agave--011's `runtime/src/slot_params.rs`, however, defines multiple `SlotParams` regimes (`LEGACY_SLOT_PARAMS` at 400ms down to `SLOT_PARAMS_200MS` at 200ms) that are activated by cluster features and change `ns_per_slot` over the life of the chain. [2](#0-1)  `SlotParamsArchive` explicitly computes exact wall-clock durations for slot ranges because slot duration is no longer assumed constant elsewhere in the runtime. [3](#0-2) 

### Finding Description
`get_oldest_non_ancient_slot_from_slot` computes the ancient boundary as `max_root - (slots_per_epoch - 1) - ancient_append_vec_offset`, purely in slot units: [4](#0-3)  This is documented as intending to keep roughly "one epoch" of recent, non-packed storage available before slots become eligible for ancient packing/squashing, as also reflected in the CLI help text: "AppendVecs that are older than (slots_per_epoch - SLOT-OFFSET) are squashed together." [5](#0-4) 

Because `slots_per_epoch` is a fixed, epoch-schedule constant, the wall-clock span this boundary represents is directly proportional to `ns_per_slot`. Before slot-time-reduction features existed, `ns_per_slot` was effectively fixed, so this boundary always represented roughly the same amount of real time. With `reduce_slot_time_to_350ms/300ms/250ms/200ms` now live features in this codebase, `ns_per_slot` can drop from 400ms to 200ms over the life of a cluster (as modeled and tested in `runtime/src/bank/tests.rs::test_reduce_slot_time_range_duration`). [6](#0-5)  Since the number of slots per epoch does not change when these features activate, the real-world time spanned by "one epoch" of slots — and hence by the ancient-storage boundary and shrink/clean cadence keyed off it — silently halves as slot time is reduced, without any corresponding adjustment to `ANCIENT_APPEND_VEC_DEFAULT_OFFSET` or `slots_per_epoch`. This mirrors the Berachain report precisely: a duration parameter tuned in "block/slot units" under an assumed constant unit time, whose real duration drifts once the underlying unit time changes.

### Impact Explanation
As slot time reduces, storage that used to remain "modern" (not yet ancient) for roughly a fixed calendar duration becomes eligible for ancient packing/squashing markedly sooner in wall-clock terms, since the same slot count now corresponds to less real time. This increases the frequency of the potentially expensive ancient-storage combining/shrink work relative to what operators provisioned for, producing disproportionate CPU and disk I/O cost on validators as slot times are progressively reduced by network-wide feature activation — with no code path re-deriving the ancient offset or epoch length from the current `SlotParams`.

### Likelihood Explanation
This is deterministic and cluster-wide once a `reduce_slot_time_to_*` feature activates: every validator running this codebase experiences the same shift in real time-per-epoch, and the ancient-storage/shrink logic reacts identically. No adversarial input is needed — it is triggered purely by the intended feature rollout that the codebase itself implements and tests.

### Recommendation
Compute the ancient-storage/shrink cadence (and any other slot-count-based duration heuristics in accounts-db that are meant to approximate a fixed calendar duration) from wall-clock time using the `SlotParamsArchive`/`slot_range_duration_nanos` machinery already introduced in `runtime/src/slot_params.rs`, rather than from a static slot count, so that the real-world packing/shrink cadence remains stable regardless of which slot-time regime is active.

### Proof of Concept
Not directly exploitable by an external attacker; it is a deterministic consequence of the codebase's own feature-gated slot-time reduction (`reduce_slot_time_to_350ms/300ms/250ms/200ms`) interacting with a slot-count-only ancient/shrink boundary:
1. Cluster activates `reduce_slot_time_to_200ms`, halving `ns_per_slot` from 400ms to 200ms per `runtime/src/slot_params.rs`.
2. `slots_per_epoch` in `EpochSchedule` is unchanged, so `get_oldest_non_ancient_slot_from_slot` still treats the same slot count as "one epoch old." [7](#0-6) 
3. The real-world time before storage is eligible for ancient packing/squashing halves, doubling the frequency of ancient-storage combining relative to pre-activation behavior, with no compensating configuration change.

    /// get the oldest slot that is within one epoch of the highest known root.
    /// The slot will have been offset by `self.ancient_append_vec_offset`
    fn get_oldest_non_ancient_slot(&self, epoch_schedule: &EpochSchedule) -> Slot {
        self.get_oldest_non_ancient_slot_from_slot(epoch_schedule, self.max_root())
    }

    /// get the oldest slot that is within one epoch of `max_root`.
    /// The slot will have been offset by `self.ancient_append_vec_offset`
    fn get_oldest_non_ancient_slot_from_slot(
        &self,
        epoch_schedule: &EpochSchedule,
        max_root: Slot,
    ) -> Slot {
        let mut result = max_root;
        if let Some(offset) = self.ancient_append_vec_offset {
            result = Self::apply_offset_to_slot(result, offset);
        }
        result = Self::apply_offset_to_slot(
            result,
            -((epoch_schedule.slots_per_epoch as i64).saturating_sub(1)),
        );
        result.min(max_root)
    }

    /// Returns the exact wall-clock duration in nanoseconds for
    /// `start_slot..=end_slot`.
    pub(crate) fn slot_range_duration_nanos(&self, start_slot: Slot, end_slot: Slot) -> u128 {
        if start_slot > end_slot {
            return 0;
        }

        let mut cursor = start_slot;
        let mut params = self.params_at_slot(start_slot);
        let mut duration = 0u128;

        for (&effective_slot, &effective_params) in self
            .param_transitions
            .range((Excluded(start_slot), Included(end_slot)))
        {
            duration = duration.saturating_add(
                u128::from(effective_slot.saturating_sub(cursor))
                    .saturating_mul(params.ns_per_slot()),
            );
            cursor = effective_slot;
            params = effective_params;
        }

        let remaining_slots = u128::from(end_slot.saturating_sub(cursor)) + 1;
        duration.saturating_add(remaining_slots.saturating_mul(params.ns_per_slot()))
    }

#[test]
fn test_reduce_slot_time_range_duration() {
    const SLOTS_PER_EPOCH: Slot = 32;
    let bank_for_activations = |activations: &[(Pubkey, Slot)]| {
        let (mut genesis_config, _) = create_genesis_config_with_legacy_hashes(1_000_000);
        genesis_config.epoch_schedule =
            EpochSchedule::custom(SLOTS_PER_EPOCH, SLOTS_PER_EPOCH, false);
        let mut bank = Bank::new_for_tests(&genesis_config);
        let mut feature_set = FeatureSet::default();
        for (feature_id, activation_slot) in activations {
            feature_set.activate(feature_id, *activation_slot);
        }
        bank.feature_set = Arc::new(feature_set);
        bank.refresh_slot_params();
        bank
    };

    let ordered_activations = slot_time_feature_gates()
        .into_iter()
        .zip([1, 33, 65, 97])
        .map(|((feature_id, _), activation_slot)| (feature_id, activation_slot))
        .collect::<Vec<_>>();
    let bank = bank_for_activations(&ordered_activations);

    let expected_duration = [
        (SLOTS_PER_EPOCH, LEGACY_SLOT_PARAMS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_350MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_300MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_250MS),
        (SLOTS_PER_EPOCH, SLOT_PARAMS_200MS),
    ]
    .into_iter()
    .map(|(slots, params)| slots as f64 / params.slots_per_year())
    .sum::<f64>();

    assert_eq!(
        bank.slot_range_duration_in_years(0, SLOTS_PER_EPOCH * 5)
            .to_bits(),
        expected_duration.to_bits()
    );
