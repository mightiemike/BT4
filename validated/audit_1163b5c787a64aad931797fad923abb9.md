### Title
Unbounded Growth of Shop→SessionId Index Enables Storage-Based Denial-of-Service - ([File: packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts])

### Summary
The Radiant Capital bug describes an unbounded, attacker/user-triggerable array (`userEarnings`) that grows without limit due to repeated legitimate low-cost actions, eventually bricking interactions that must read the whole array. The `KVSessionStorage` adapter has an analogous unbounded-array pattern: every call to `storeSession` appends the session id to a shop-keyed index array with no deduplication and no bound, and this array is later read in full by `findSessionsByShop`, which is on the hot path of the token-exchange/OAuth session-authentication flow.

### Finding Description
`KVSessionStorage.storeSession` unconditionally calls `addShopIds`, which reads the existing `shop:<shop>` index array and appends the new id(s) with a plain spread, without checking whether the id is already present: [1](#0-0) [2](#0-1) 

Compare this with the Redis adapter, which does check `idKeysArray.includes(idKey)` before pushing, preventing duplicate growth for the same session id: [3](#0-2) 

`storeSession` is called repeatedly as part of normal, unprivileged session-authentication flows — specifically the token-exchange strategy that is invoked whenever a session is missing or near expiry (an offline/online session refresh path reachable on essentially every authenticated app request): [4](#0-3) [5](#0-4) 

Because the offline/online session ids are deterministic (`getOfflineId(shop)` / `shop_sub`), each refresh re-stores a session with the *same* id, yet `addShopIds` in the KV adapter has no deduplication, so the `shop:<shop>` array grows by one entry every time this path executes — with no upper bound.

This index array is later read in full by `findSessionsByShop`, which loads every listed session id via `Promise.all`: [6](#0-5) 

`findSessionsByShop`/`deleteSessions` are used by `AppInstallations.includes`/`delete`, which run during the OAuth-callback / app-install and `APP_UNINSTALLED` webhook processing paths: [7](#0-6) 

As the index array grows unbounded, each `findSessionsByShop` call has to fan out a growing number of KV reads (`Promise.all` over `sessionIds.map`), and the JSON-serialized index itself grows unbounded in the KV store. This mirrors the reported bug class: an attacker/user can cheaply and repeatedly trigger a code path that appends to an array with no size cap, and a downstream function that must process the whole array (`findSessionsByShop`) degrades to the point of failure/timeout — denying app installation checks, webhook handling, and session lookups for that shop.

### Impact Explanation
Once the `shop:<shop>` KV entry accumulates a very large number of duplicate id entries, any call to `findSessionsByShop` becomes progressively slower and eventually can time out or exceed request/serverless execution limits (Cloudflare Workers, which is the `KVSessionStorage` target runtime, has strict CPU/time budgets). This blocks `AppInstallations.includes`/`delete`, breaking `APP_UNINSTALLED` webhook processing and OAuth install-check logic for the affected shop — a DoS of an auth-adjacent handler reachable via normal session-refresh traffic, not requiring any privileged action.

### Likelihood Explanation
Any authenticated merchant/customer session naturally triggers repeated calls into `performTokenExchange`/`TokenExchangeStrategy.authenticate` whenever the offline/online session is missing or close to expiry (e.g., cleared session storage entries, expired tokens, or repeated re-authentication flows in embedded apps). Each such event appends a new — but duplicate — id string to the shop's KV array with no cap, so likelihood of eventual degradation is high for any active shop over time, and it can also be accelerated deliberately by an app user simply forcing repeated re-authentications (e.g., by clearing cookies / triggering many token-exchange calls), which does not require elevated privileges.

### Recommendation
In `KVSessionStorage.addShopIds` (and `removeShopIds`), deduplicate before writing (`Set`-based union) exactly as the Redis adapter does, and consider capping/pruning the per-shop id list (e.g., pruning expired session ids on write) to prevent unbounded growth.

### Proof of Concept
1. Configure a Cloudflare Workers app using `KVSessionStorage` with `useOnlineTokens: false` (offline session refresh flow).
2. As a normal authenticated user, repeatedly force the token-exchange/session-refresh path to execute for the same shop (e.g., delete/expire the stored offline session between requests, or repeatedly hit the app URL with an expired or removed session cookie) so that `TokenExchangeStrategy.authenticate` → `config.sessionStorage!.storeSession(offlineSession)` runs many times.
3. Because `KVSessionStorage.storeSession` → `addShopIds` appends the (identical) offline-session id every time without checking for duplicates, the `shop:<shop>` KV value grows by one array entry per refresh, unbounded.
4. After sufficient iterations, call `findSessionsByShop(shop)` (e.g., via the `APP_UNINSTALLED` webhook handler or app-install check) and observe increasing latency/timeouts as the `Promise.all` loop fans out over the bloated, duplicate-laden id array.

  public async findSessionsByShop(shop: string): Promise<Session[]> {
    const sessionIds = await this.namespace.get<string[]>(
      this.getShopSessionIdsKey(shop),
      {type: 'json'},
    );

    if (!sessionIds) {
      return [];
    }

    return Promise.all(
      sessionIds.map(async (id) => (await this.loadSession(id))!),
    );
  }

  private async addShopIds(shop: string, ids: string[]) {
    const key = this.getShopSessionIdsKey(shop);
    const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
    await this.namespace.put(key, JSON.stringify([...shopIds, ...ids]));
  }

  private async addKeyToShopList(session: Session) {
    const shopKey = session.shop;
    const idKey = this.client.generateFullKey(session.id);
    const idKeysArrayString = await this.client.get(shopKey);

    if (idKeysArrayString) {
      const idKeysArray = JSON.parse(idKeysArrayString);

      if (!idKeysArray.includes(idKey)) {
        idKeysArray.push(idKey);
        await this.client.set(shopKey, JSON.stringify(idKeysArray));
      }

      await this.client.set(shopKey, JSON.stringify([idKey]));

  async includes(shopDomain: string): Promise<boolean> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      for (const session of shopSessions) {
        if (session.accessToken) return true;
      }
    }
    return false;
  }

  async delete(shopDomain: string): Promise<void> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      await this.sessionStorage.deleteSessions!(
        shopSessions.map((session: Session) => session.id),
      );
    }
  }
