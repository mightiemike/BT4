### Title
State mutation before fee deduction in `AccountPermissionUpdateActuator.execute()` allows a fee-bypassing permission update to persist on a FAILED transaction - (File: actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java)

### Summary
`execute()` calls `account.updatePermissions(...)` and `accountStore.put(ownerAddress, account)` before calling `adjustBalance(accountStore, ownerAddress, -fee)`, which can throw `BalanceInsufficientException`. Because `validate()` never checks that the owner's balance is sufficient to pay `getUpdateAccountPermissionFee()`, an account with balance below the fee can have its new permission set written to `AccountStore` even though the transaction result is ultimately marked `FAILED` and no fee is charged.

### Finding Description
In `execute()`: [1](#0-0) 
the sequence is: read the account, call `account.updatePermissions(...)`, `accountStore.put(ownerAddress, account)`, and only afterwards `adjustBalance(accountStore, ownerAddress, -fee)`. If the balance is insufficient, `adjustBalance` throws `BalanceInsufficientException`, which is caught, `result.setStatus(fee, code.FAILED)` is set, and a `ContractExeException` is re-thrown: [2](#0-1) 
The permission-store mutation performed via `accountStore.put` at line 52 has already been committed to the store's write path before the exception is thrown, and the catch block does not undo it (no compensating `accountStore.put` with the pre-mutation `AccountCapsule` snapshot).

Critically, `validate()` contains no balance-sufficiency check against `calcFee()`/`getUpdateAccountPermissionFee()`: [3](#0-2) 
so a transaction from an account whose balance is below the fee is not rejected in `validate()` and reaches `execute()`, where the permission write happens unconditionally before the balance check that can fail.

### Impact Explanation
This is a value-conservation / accounting-integrity bug: the fee that is supposed to gate the (deliberately expensive) permission-update operation is not collected, yet the state change (new owner/active/witness permission keys and thresholds) is persisted into `AccountStore`. Any client, exchange, or explorer relying on the reported transaction result (`FAILED`) to determine whether an on-chain state change actually took effect will be misled: the permission set is changed for free despite an apparently failed transaction. This maps to unauthorized/inconsistent state change and fee-bypass accounting corruption.

### Likelihood Explanation
Precondition is simple and fully attacker-controlled: any account (not privileged) can broadcast a valid, signed `AccountPermissionUpdateContract` for itself while holding a balance below `getUpdateAccountPermissionFee()`. No signature-check bypass, no fork gate, no privileged role is required — `multi sign` merely needs to be enabled (`AllowMultiSign == 1`), which is a normal on-chain configuration, not a non-default node setting. The attack is fully repeatable per affected account.

### Recommendation
Reorder `execute()` so that the fee is deducted (and any exception thrown) before the permission mutation is written to the store, e.g.:
```java
adjustBalance(accountStore, ownerAddress, -fee);
account.updatePermissions(...);
accountStore.put(ownerAddress, account);
```
Alternatively, add an explicit balance-sufficiency check in `validate()` (comparing `accountCapsule.getBalance()` against `calcFee()`) so insufficient-balance transactions are rejected before `execute()` runs at all, consistent with other fee-charging actuators.

### Proof of Concept
```java
@Test
public void updatePermissionWithInsufficientBalanceShouldNotPersist() throws Exception {
  // Arrange: account with balance < dynamicStore.getUpdateAccountPermissionFee()
  AccountCapsule owner = new AccountCapsule(ByteString.copyFrom(OWNER_ADDRESS),
      ByteString.copyFromUtf8("owner"), AccountType.Normal);
  owner.setBalance(0); // balance below fee
  accountStore.put(OWNER_ADDRESS, owner);
  AccountCapsule preSnapshot = accountStore.get(OWNER_ADDRESS).cloneOrDeepCopy();

  AccountPermissionUpdateContract contract = AccountPermissionUpdateContract.newBuilder()
      .setOwnerAddress(ByteString.copyFrom(OWNER_ADDRESS))
      .setOwner(newOwnerPermissionWithAttackerKey())
      .addActives(newActivePermissionWithAttackerKey())
      .build();

  AccountPermissionUpdateActuator actuator = new AccountPermissionUpdateActuator();
  actuator.setChainBaseManager(chainBaseManager);
  actuator.setAny(Any.pack(contract));

  TransactionResultCapsule ret = new TransactionResultCapsule();
  try {
    actuator.execute(ret);
    fail("expected ContractExeException");
  } catch (ContractExeException e) {
    // expected: FAILED
  }

  assertEquals(code.FAILED, ret.getInstance().getRet());
  // Bug: this assertion fails because permissions were already persisted
  AccountCapsule postState = accountStore.get(OWNER_ADDRESS);
  assertEquals(preSnapshot.getOwnerPermission(), postState.getOwnerPermission());
  assertEquals(preSnapshot.getActivePermissionList(), postState.getActivePermissionList());
}
```
Expected (correct) behavior: `postState` equals `preSnapshot` exactly since the fee-paying operation failed. Actual behavior per code trace above: `postState` reflects the attacker-controlled/new permission set because `accountStore.put` at line 52 executes and is not rolled back before the exception at line 54/62-66.

  @Override
  public boolean validate() throws ContractValidateException {

    if (chainBaseManager == null) {
      throw new ContractValidateException(ActuatorConstant.STORE_NOT_EXIST);
    }

    if (this.any == null) {
      throw new ContractValidateException(ActuatorConstant.CONTRACT_NOT_EXIST);
    }

    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();

    if (dynamicStore.getAllowMultiSign() != 1) {
      throw new ContractValidateException("multi sign is not allowed, "
          + "need to be opened by the committee");
    }
    if (!this.any.is(AccountPermissionUpdateContract.class)) {
      throw new ContractValidateException(
          "contract type error,expected type [AccountPermissionUpdateContract],real type["
              + any.getClass() + "]");
    }
    final AccountPermissionUpdateContract accountPermissionUpdateContract;
    try {
      accountPermissionUpdateContract = any.unpack(AccountPermissionUpdateContract.class);
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }
    byte[] ownerAddress = accountPermissionUpdateContract.getOwnerAddress().toByteArray();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("invalidate ownerAddress");
    }
    AccountCapsule accountCapsule = accountStore.get(ownerAddress);
    if (accountCapsule == null) {
      throw new ContractValidateException("ownerAddress account does not exist");
    }

    if (!accountPermissionUpdateContract.hasOwner()) {
      throw new ContractValidateException("owner permission is missed");
    }

    if (accountCapsule.getIsWitness()) {
      if (!accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("witness permission is missed");
      }
    } else {
      if (accountPermissionUpdateContract.hasWitness()) {
        throw new ContractValidateException("account isn't witness can't set witness permission");
      }
    }

    if (accountPermissionUpdateContract.getActivesCount() == 0) {
      throw new ContractValidateException("active permission is missed");
    }
    if (accountPermissionUpdateContract.getActivesCount() > 8) {
      throw new ContractValidateException("active permission is too many");
    }

    Permission owner = accountPermissionUpdateContract.getOwner();
    Permission witness = accountPermissionUpdateContract.getWitness();
    List<Permission> actives = accountPermissionUpdateContract.getActivesList();

    if (owner.getType() != PermissionType.Owner) {
      throw new ContractValidateException("owner permission type is error");
    }
    checkPermission(owner);
    if (accountCapsule.getIsWitness()) {
      if (witness.getType() != PermissionType.Witness) {
        throw new ContractValidateException("witness permission type is error");
      }
      checkPermission(witness);
    }
    for (Permission permission : actives) {
      if (permission.getType() != PermissionType.Active) {
        throw new ContractValidateException("active permission type is error");
      }
      checkPermission(permission);
    }
    return true;
  }
