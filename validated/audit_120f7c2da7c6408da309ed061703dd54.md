### Title
`getIndex()` silently drops active V2 delegations when a stale legacy plain-address-key record exists for the same address - ([File: chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java])

### Summary
`DelegatedResourceAccountIndexStore.getIndex(address)`, which backs the public API `Wallet.getDelegatedResourceAccountIndex`, returns the first non-null legacy plain-key record via `get(address)` and never merges it with the V1/V2 prefix-keyed records from `getWithPrefix`. Because legacy plain-key records are only migrated (`convert()`) when an account participates in a new `FreezeBalanceActuator` transaction, and `FreezeBalanceActuator` becomes permanently unusable once `supportUnfreezeDelay()` (freeze v2 / resource-delegation-optimization) is enabled network-wide, an address that has an old un-migrated legacy record and later receives fresh V2 delegations via `DelegateResourceActuator` will have its real, active V2 delegations completely hidden from the public query API.

### Finding Description
`getIndex()` implements a short-circuit: [1](#0-0) 

It is reached directly from the public gRPC/HTTP query surface: [2](#0-1) 
(exposed via `RpcApiService.getDelegatedResourceAccountIndex` and `GetDelegatedResourceAccountIndexServlet`).

Legacy plain-key records (written by `put(ownerAddress, ...)`/`put(receiverAddress, ...)`) are only produced by the old `FreezeBalanceActuator.delegateResource()` branch guarded by `!dynamicPropertiesStore.supportAllowDelegateOptimization()`: [3](#0-2) 

Once `supportAllowDelegateOptimization()` is enabled, the same code path calls `convert()` before writing new V1-prefixed records, and `convert()` migrates and deletes the plain-key entry: [4](#0-3) 

However, `FreezeBalanceActuator.validate()` unconditionally rejects the transaction once freeze v2 is active: [5](#0-4) 

and `DelegateResourceActuator` (the sole way to create new V2 delegations, via `delegatedResourceAccountIndexStore.delegateV2(...)`) never calls `convert()` for either owner or receiver: [6](#0-5) 

Consequently, once a network activates freeze v2 (a historical, already-occurred upgrade on live TRON networks), any account that still carries a stale plain-key legacy record from before the upgrade has no remaining code path that will ever call `convert()` for it — `FreezeBalanceActuator` is permanently disabled and `DelegateResourceActuator` does not migrate legacy data. If that same account later becomes a party (owner or receiver) to a brand-new V2 delegation via `DelegateResourceActuator`, `getIndex()` will forever return only the stale legacy snapshot and silently omit the real, currently-active V2 delegation from the API response.

### Impact Explanation
The public query `getDelegatedResourceAccountIndex` (and the gRPC/HTTP servlet built on it) can permanently misreport an account's delegated-resource relationships, showing stale/incomplete "to"/"from" account lists that omit real, currently active delegations. Third-party consumers (block explorers, settlement/liquidation bots, resource marketplaces) that rely on this API to compute delegation state can act on materially incorrect data — e.g., failing to recognize that a receiver currently holds delegated bandwidth/energy from an owner, or vice versa. Note `getDelegatedResourceAccountIndexV2` (which queries only the V2 prefix and does not have this short-circuit) exists as an unaffected alternative, but the legacy/default `getDelegatedResourceAccountIndex` API remains broken for affected addresses.

### Likelihood Explanation
This requires only ordinary, permissionless transactions: (1) an address must have an old-style delegated `FreezeBalanceContract` record dating to before the network enabled freeze-v2/`supportAllowDelegateOptimization`, and (2) that address must subsequently participate (as owner or receiver) in a new `DelegateResourceContract` V2 delegation. Both conditions are trivially satisfiable by any unprivileged user on a live/already-upgraded network holding pre-upgrade delegation history, and the resulting inconsistency is permanent (no further trigger exists to fix it) rather than a narrow race window.

### Recommendation
Change `getIndex()` to merge results instead of short-circuiting: always compute `getWithPrefix(FROM_PREFIX, TO_PREFIX, address)` and `getWithPrefix(V2_FROM_PREFIX, V2_TO_PREFIX, address)` (or at minimum V1+legacy) and union/merge the `to`/`from` account lists with the plain-key legacy record before returning, so no active delegation record (legacy, V1, or V2) is ever dropped from the response.

### Proof of Concept
```java
// framework/src/test/java/org/tron/core/db/DelegatedResourceAccountIndexStoreTest.java

@Test
public void testGetIndexDropsV2DuringMigrationWindow() {
  byte[] owner = ByteArray.fromHexString(owner1);
  byte[] receiverLegacy = "legacyReceiver".getBytes();
  byte[] receiverV2 = "v2Receiver".getBytes();

  // 1. Simulate a stale pre-migration legacy plain-key record for `owner`
  DelegatedResourceAccountIndexCapsule legacyCapsule =
      new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(owner));
  legacyCapsule.setAllToAccounts(
      Collections.singletonList(ByteString.copyFrom(receiverLegacy)));
  delegatedResourceAccountIndexStore.put(owner, legacyCapsule);

  // 2. Simulate a brand-new, currently-active V2 delegation for the same owner
  //    (what DelegateResourceActuator.delegateResource() does)
  delegatedResourceAccountIndexStore.delegateV2(owner, receiverV2, 100L);

  // 3. Call the public-API-backing method
  DelegatedResourceAccountIndexCapsule result =
      delegatedResourceAccountIndexStore.getIndex(owner);

  // 4. The real, active V2 delegation to receiverV2 is silently dropped
  Assert.assertFalse(
      result.getToAccountsList().contains(ByteString.copyFrom(receiverV2)));
  // Only the stale legacy entry is returned
  Assert.assertTrue(
      result.getToAccountsList().contains(ByteString.copyFrom(receiverLegacy)));
}
```
Expected result confirms the bug: the assertion that the V2 delegation is missing from `getIndex()`'s result passes, while `getV2Index(owner)` (calling `getWithPrefix(V2_FROM_PREFIX, V2_TO_PREFIX, owner)` directly) would correctly show `receiverV2`, proving the discrepancy is caused by the short-circuit in `getIndex()`.

  public void convert(byte[] address) {
    DelegatedResourceAccountIndexCapsule indexCapsule = this.get(address);
    if (indexCapsule == null) {
      // convert complete or have no delegate
      return;
    }
    // convert old data
    List<ByteString> toList = indexCapsule.getToAccountsList();
    for (int i = 0; i < toList.size(); i++) {
      // use index as the timestamp, just to keep index in order
      this.delegate(address, toList.get(i).toByteArray(), i + 1L);
    }

    List<ByteString> fromList = indexCapsule.getFromAccountsList();
    for (int i = 0; i < fromList.size(); i++) {
      // use index as the timestamp, just to keep index in order
      this.delegate(fromList.get(i).toByteArray(), address, i + 1L);
    }
    this.delete(address);
  }

  private void delegateResource(byte[] ownerAddress, byte[] receiverAddress, boolean isBandwidth,
                                long balance, boolean lock, long lockPeriod) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicPropertiesStore = chainBaseManager.getDynamicPropertiesStore();
    DelegatedResourceStore delegatedResourceStore = chainBaseManager.getDelegatedResourceStore();
    DelegatedResourceAccountIndexStore delegatedResourceAccountIndexStore = chainBaseManager
        .getDelegatedResourceAccountIndexStore();

    // 1. unlock the expired delegate resource
    long now = chainBaseManager.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    delegatedResourceStore.unLockExpireResource(ownerAddress, receiverAddress, now);

    //modify DelegatedResourceStore
    long expireTime = 0;
    if (lock) {
      expireTime = now + lockPeriod * BLOCK_PRODUCED_INTERVAL;
    }
    byte[] key = DelegatedResourceCapsule.createDbKeyV2(ownerAddress, receiverAddress, lock);
    DelegatedResourceCapsule delegatedResourceCapsule = delegatedResourceStore.get(key);
    if (delegatedResourceCapsule == null) {
      delegatedResourceCapsule = new DelegatedResourceCapsule(ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
    }

    if (isBandwidth) {
      delegatedResourceCapsule.addFrozenBalanceForBandwidth(balance, expireTime);
    } else {
      delegatedResourceCapsule.addFrozenBalanceForEnergy(balance, expireTime);
    }
    delegatedResourceStore.put(key, delegatedResourceCapsule);

    //modify DelegatedResourceAccountIndexStore
    delegatedResourceAccountIndexStore.delegateV2(ownerAddress, receiverAddress,
        dynamicPropertiesStore.getLatestBlockHeaderTimestamp());

    //modify AccountStore for receiver
    AccountCapsule receiverCapsule = accountStore.get(receiverAddress);
    if (isBandwidth) {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(balance);
    } else {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForEnergy(balance);
    }
    accountStore.put(receiverCapsule.createDbKey(), receiverCapsule);
  }
