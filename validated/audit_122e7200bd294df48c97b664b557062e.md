### Title
Missing declared-class validation in OS `replace_class` syscall causes blockifier/OS execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
This is analogous to the BabySwap bug class: an unprivileged, attacker-controlled parameter (a "factory"/reference address, here a `class_hash`) is trusted and used directly for a critical state update without validating it against the canonical registry (declared classes), while the parallel/trusted execution path (blockifier) does perform that validation.

### Finding Description
Any contract can invoke the `replace_class` syscall with an arbitrary, attacker-chosen `class_hash` as part of a normal `INVOKE` transaction. The blockifier's execution path (`SyscallHandlerBase::replace_class` in `crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`) calls `self.state.get_compiled_class(class_hash)?`, which returns `StateError::UndeclaredClassHash` if the class was never declared, and further rejects the operation if the class is Cairo 0 (`ForbiddenClassReplacement`). This is confirmed by tests such as `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29` and `test_replace_class` in `crates/blockifier/src/execution/deprecated_syscalls/deprecated_syscalls_test.rs:375-391`, both of which assert the transaction fails with "is not declared" when the class hash is not registered.

The Starknet OS's Cairo implementation of the same syscall (used for proof generation / OS re-execution, reachable from the identical unprivileged transaction), `execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo:881-920`, contains an explicit TODO acknowledging the gap ("Check that there is a declared contract class with the given hash") and proceeds to unconditionally overwrite the contract's `class_hash` in `contract_state_changes` regardless of whether the class was ever declared. The deprecated OS syscall handler (`deprecated_execute_syscalls.cairo:307-329`) has the same unconditional behavior.

### Impact Explanation
Because the sequencer's execution engine (blockifier) rejects a `replace_class` call to an undeclared class hash (reverting the transaction or failing the call), while the OS accepts and commits it, the OS's view of the resulting state/class assignment for the contract can diverge from what the blockifier actually executed and committed. Since the OS is the component whose execution is proven and used to attest the correctness of the block (Starknet OS re-execution), any divergence between what the sequencer committed and what the OS considers valid constitutes an honest-node/execution divergence, potentially resulting in an incorrect committed root or class assignment for the contract, or an inability for the OS to reproduce the sequencer's committed state for that block.

### Likelihood Explanation
The `replace_class` syscall is reachable by any external contract as part of a standard `__execute__` invocation — no special privilege is required, matching the BabySwap trust-boundary pattern where an unprivileged party supplies an untrusted reference (there: factory address; here: class hash) that is used authoritatively without validation. The TODO comment in the source directly acknowledges the missing check is intentional/pending, indicating high confidence this gap currently exists in the OS Cairo code as read.

### Recommendation
Add the same "class must be declared" (and Cairo version) check to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` in the Starknet OS program, mirroring the check already performed in blockifier's `SyscallHandlerBase::replace_class`, to ensure execution parity between the sequencer and the OS.

### Proof of Concept
1. Deploy or invoke any contract as the `sender_address` in a normal `INVOKE` transaction.
2. From within `__execute__`, call the `replace_class` syscall with a `class_hash` that has never been declared on-chain.
3. In the blockifier, the transaction execution fails/reverts with `StateError::UndeclaredClassHash` (per `replace_class.rs:17-29`).
4. When the same transaction is re-executed/proven by the Starknet OS (`syscall_impls.cairo:execute_replace_class`), no declared-class check is performed; the OS unconditionally records the new (undeclared) `class_hash` for the contract in `contract_state_changes`, producing a different outcome than the sequencer's actual execution — a concrete honest-node divergence.

Note: I could not fully verify whether an additional guard exists elsewhere in the OS pipeline (e.g., a separate later validation pass) that might catch this before commitment, since the index does not expose every call site consuming `contract_state_changes` in the OS commitment flow. If such a guard exists outside the files examined, it would need to be confirmed via a full repository checkout.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
