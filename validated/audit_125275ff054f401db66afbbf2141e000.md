## Finding

### Title
Starknet OS `replace_class` Syscall Skips Declared-Class Verification, Diverging From Blockifier's Enforcement - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall unconditionally overwrites a contract's class hash without verifying that the target class hash was actually declared, while the Rust `blockifier` execution engine enforces this exact check. This produces a soundness gap between the two implementations of the same protocol rule.

### Finding Description
Any contract can invoke the `replace_class` syscall to change its own `class_hash` in storage. In the Rust `blockifier`, this is gated by an explicit declared-class check: [1](#0-0) 

and analogously in the Cairo-native syscall handler, which delegates to the same `base.replace_class` check: [2](#0-1) 

Tests confirm the Blockifier actively rejects `replace_class` to an undeclared class hash with an `"is not declared"` error: [3](#0-2) 

However, the Starknet OS's Cairo re-execution logic for `replace_class` — used to generate the STARK proof of block execution that is ultimately what gets verified/trusted for settlement — omits this check entirely. The function directly overwrites the `StateEntry.class_hash` field with the caller-supplied `class_hash` with only a `TODO` acknowledging the missing check: [4](#0-3) 

The same omission exists in the deprecated syscall path used for Cairo0 contracts: [5](#0-4) 

This is directly analogous to the reported bug class: a state-mutating operation reachable by an unprivileged caller (any contract, triggered by any account's invoke transaction) that is missing an authorization/validity check in one code path (`PUT /channels/.../recipients/...` lacking membership verification) while a parallel/expected enforcement point exists elsewhere (the group-membership check that should gate the mutation). Here, the "membership" analog is "is this class hash actually declared" — enforced by the Blockifier but missing in the OS's Cairo implementation of the identical syscall.

### Impact Explanation
The Starknet OS program is the trusted computation whose correct execution is what the STARK proof attests to; the resulting proof is ultimately what backs the committed state root. If the OS's enforcement of protocol invariants diverges from the Blockifier's, a transaction (or crafted witness/trace) that the Blockifier would reject can still be represented as valid inside OS re-execution/proving, because the OS's `execute_replace_class` does not independently verify that the class hash exists as a declared class before mutating `contract_state_changes`. This breaks the invariant that a contract's class can only ever be set to a previously-declared class, and creates a discrepancy between what the sequencer's actual execution accepts and what the OS is willing to prove/re-execute as valid — a wrong-committed-state-root / honest-node-divergence class of issue.

### Likelihood Explanation
`replace_class` is a standard, permissionless syscall callable from any Cairo1/Cairo0 contract in a normal invoke transaction — no privileged role, staking key, or operator access is required to reach this code path. The only barrier to exploitation is whatever process feeds transaction traces/hints into the OS program (e.g., re-execution, benchmarking, or any workflow that doesn't itself re-derive the check from the Blockifier's canonical enforcement).

### Recommendation
Add the same declared-class verification the Blockifier performs (analogous to `state.get_compiled_class(request.class_hash)?` in `hint_processor.rs`) to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, resolving the outstanding `TODO(Yoni, 1/1/2026)` before the class hash is written into `contract_state_changes`.

### Proof of Concept
1. A contract calls `replace_class_syscall(class_hash)` with a `class_hash` that has never been declared on-chain.
2. In the Rust `blockifier` path, `state.get_compiled_class(request.class_hash)` fails and the syscall returns an error (verified by `undeclared_class_hash` test in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
3. In the Starknet OS Cairo execution path (`execute_replace_class` in `syscall_impls.cairo`), no equivalent check exists — the function directly performs `dict_update` to set the new (undeclared) `class_hash` into `contract_state_changes` for the contract address, with only a `TODO` comment noting the missing verification. // Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
