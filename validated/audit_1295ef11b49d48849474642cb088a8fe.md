Based on my review of the wasm-contract preparation and validation pipeline (the closest nearcore analog to SuiteCRM's "parse contract code, then check the parsed tokens against a blacklist" ModuleScanner logic), I don't find a matching vulnerability class here.

The SuiteCRM bug is specifically about a *blacklist-based static analysis bypass*: `token_get_all` parses the PHP source into tokens, and the resulting token stream is checked against a denylist of forbidden functions/constructs, but alternate syntactic forms slip through the blacklist matcher. nearcore's contract preparation does not use this pattern at all — `prepare_contract` in [1](#0-0)  feeds the WASM bytes into `prepare_v3::prepare_contract`, which relies on `wasmparser`'s structural `Validator` (a full WASM-spec type/structure checker) rather than any denylist over syntactic tokens [2](#0-1) . Restrictions such as "imports only from `env`", memory/table/function count limits, and feature gating (SIMD, threads, multi-value, etc., verified in `wasm_validation.rs`) are enforced by walking the fully-parsed module structure exhaustively, not by matching specific opcodes/names against a blacklist that could be evaded via alternate encodings [3](#0-2) .

Similarly, host-function access restrictions (e.g., `ProhibitedInView`) are enforced per-call inside `VMLogic` methods themselves (e.g. `signer_account_id`, `promise_create`, `storage_write` each check `is_view()`), not via a pre-scan blacklist of forbidden call sequences that malformed/obfuscated bytecode could dodge [4](#0-3) . Because WASM validation here is a complete grammar/type-checker (reject-by-default, not permit-by-default-unless-blacklisted), there's no structurally equivalent "alternate syntax construction bypasses the denylist" bug class reachable by a contract deployer or caller.

No vulnerability found for this question.

```rust
pub(crate) fn prepare_contract(
    original_code: &[u8],
    features: crate::features::WasmFeatures,
    config: &Config,
    kind: VMKind,
) -> Result<Vec<u8>, PrepareError> {
    let lightly_steamed = PrepareContext::new(original_code, features, config).run()?;

    let analysis = finite_wasm_6::Analysis::new()
        .with_stack(SimpleMaxStackCfg)
        .with_gas(SimpleGasCostCfg {
            regular: u64::from(config.regular_op_cost),
            linear_base: config.linear_op_base_cost,
            linear_unit: config.linear_op_unit_cost,
        })
        .analyze(&lightly_steamed)
        .map_err(|err| {
            tracing::error!(target: "vm", ?err, ?kind, "analysis failed");
            PrepareError::Deserialization
        })?;
```
