### Title
Stale `index-cache` entry can be read after `socialize-debt` mutates `lindex` within the same block — (File: `local-testing/contracts/market/market.clar` / `mainnet/contracts/market/v0-4-market.clar`, function `accrue-and-cache`)

### Summary
`accrue-and-cache` memoizes each vault's `{index, lindex}` pair in the `index-cache` map keyed by `{timestamp: stacks-block-time, aid}` [1](#0-0) . This is a persistent contract map, not a transaction-local variable, so a cache entry written by one transaction remains a cache HIT for any other transaction executed later in the same block (same `stacks-block-time`) [2](#0-1) . The cache is only ever populated/read via `vault-accrue`/`accrue-and-cache`; it assumes the vault's `index`/`lindex` cannot change except through time-based accrual. However, `socialize-debt` in every vault contract (`vault-stx.clar`, `vault-sbtc.clar`, etc.) writes `lindex` directly — outside of `accrue`/`next-liquidity-index` — as a write-down proportional to bad-debt loss [3](#0-2) . This mutation does not touch or invalidate `market.clar`'s `index-cache` map.

### Finding Description
1. Within block at timestamp `T`, Transaction 1 calls `market.borrow` (or any path through `collateral-add`/`repay`) for asset `aid=X`, which calls `accrue-and-cache(X)` [4](#0-3) . This is a cache MISS, so `vault-accrue` is invoked, and the resulting `{index, lindex}` is written to `index-cache` at key `{timestamp: T, aid: X}` [1](#0-0) .
2. Later in the same block (still timestamp `T`), the market's `liquidate` flow triggers `vault-socialize-debt` on vault `X` for a bad-debt position, which calls the vault's `socialize-debt`, directly writing a reduced `lindex` (`new-lindex`) to reflect the loss in `total-assets`, bypassing `accrue`/`next-liquidity-index` entirely [5](#0-4) . This is the "source" of the cached value moving.
3. Transaction 3, still in the same block/timestamp `T`, performs any operation (`collateral-add`, `borrow`, `collateral-remove`) touching asset `X` (e.g., a zToken collateral valued via `X`'s `lindex`). It calls `accrue-and-cache(X)` again; this is a cache HIT against the stale entry from step 1, returning the pre-socialization `lindex` instead of querying the vault's now-reduced `lindex` [2](#0-1) .
4. The stale (higher) `lindex` inflates the notional value of zToken collateral backed by vault `X` in `get-notional-evaluation`/`get-asset-value`, letting a user borrow more or avoid liquidation using overvalued collateral, or a liquidator/health check to make decisions on outdated economics — within a single block, no re-entrancy or cross-user assumption required.

### Impact Explanation
This directly inflates the reported value of zToken collateral for any further health check, borrow, or liquidation processed in the same block after a `socialize-debt` event, which can let borrowers extract more debt than their true (post-loss) collateral backs, or evade liquidation that should otherwise trigger — a form of theft/insolvency risk (High/Critical class: temporary-to-permanent freezing/insolvency risk from mispriced collateral).

### Likelihood Explanation
Requires `socialize-debt` (an authorized system call typically triggered from a liquidation with bad-debt socialization, see `market.clar`'s bad-debt socialization flow at `local-testing/contracts/market/market.clar:1557-1583`) to occur in the same block as a subsequent market action touching the same vault/aid, which is plausible in busy blocks with multiple liquidations/borrows on the same asset, and requires no privileged access — just transaction ordering within a block, consistent with the "cached value not invalidated when its source moves" analog class.

### Recommendation
Invalidate or bypass the `index-cache` entry for an asset whenever `socialize-debt` (or any vault operation that mutates `index`/`lindex` outside of normal time-based `accrue`) is called, e.g., by having `vault-socialize-debt` return updated indexes and having `market.clar` overwrite the corresponding `index-cache` entry, or by removing the persistent map-based cache in favor of a call-scoped (non-persisted) memoization.

```text
(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
```

```text
(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
```
