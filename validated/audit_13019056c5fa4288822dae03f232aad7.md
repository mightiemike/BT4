## Analog Found

### Title
Missing declared-class validation in the Starknet OS `replace_class` syscall causes state-transition divergence from the Blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The reported bug class is a "safe" function name that actually implements the unsafe/unchecked variant (`safeMint` calling `_mint` instead of `_safeMint`, skipping a validation the name implies). The Starknet sequencer contains a structurally identical pattern: the `replace_class` syscall is fully validated in the Rust `blockifier` (the component that actually executes and prices transactions), but the parallel Cairo implementation of the same syscall inside the Starknet OS (SNOS) — which is re-executed to produce the proof that ultimately anchors the committed state root — omits that same validation, with an explicit unresolved `TODO` marking the gap.

### Finding Description
In the blockifier, `replace_class` is only accepted after confirming the target class hash is declared and is a Cairo1 class: [1](#0-0) 

The deprecated (Cairo0) syscall path enforces the identical check: [2](#0-1) 

Both paths reject an undeclared class hash before ever calling `state.set_class_hash_at`, as demonstrated by the tests explicitly asserting the errors `"is not declared"` and `"Cannot replace V1 class hash with V0 class hash"`: [3](#0-2) 

However, the Starknet OS's own Cairo implementation of the same syscall — used to independently re-execute every transaction and produce the state diff/proof that is ultimately committed — performs no such check. The `TODO` comment confirms the check was never implemented: [4](#0-3) 

The deprecated (Cairo0) OS syscall handler has the exact same gap — it reads/updates the state entry without verifying the class hash is declared: [5](#0-4) 

Because both the blockifier and the OS independently interpret the same contract bytecode (they don't merely replay a pre-computed diff — they each dispatch and execute the `replace_class_syscall` invocation from the calling contract), any contract that calls `replace_class_syscall` with an undeclared class hash and inspects the `Result`/error branch (a completely ordinary, unprivileged usage pattern, e.g. `match syscalls::replace_class_syscall(class_hash) { Ok(_) => ..., Err(_) => ... }`) will take the **error branch** under the blockifier (syscall fails, no state change) but the **success branch** under the OS (syscall succeeds, state is updated to point at a non-existent/undeclared class).

### Impact Explanation
This produces an honest-node divergence and a wrong committed state root:
- The RPC/mempool-facing execution (blockifier) reports one outcome (syscall failure, specific retdata/events, no class-hash state change) for a transaction.
- The OS re-execution used to generate the proof that is ultimately verified/committed on L1 computes a different outcome: the contract's class hash is unconditionally overwritten with an undeclared/garbage class hash, and the calling contract executes its "success" code path (potentially with entirely different subsequent side effects, storage writes, or emitted events).
- Since class hash lookups for CASM/Sierra compiled code require the class to be declared, permanently pointing a contract's `class_hash` state entry at an undeclared hash makes the contract uncallable/bricked going forward — any assets or logic gated behind that contract become permanently unreachable (loss/freezing of funds), and the block's state root, computed via the OS/proof path, will not match what any node running only the blockifier would compute — a form of state/consensus divergence and wrong committed root.

### Likelihood Explanation
The trigger requires nothing privileged: any account can deploy a contract that calls `replace_class_syscall` with an attacker-chosen (undeclared) class hash and branches on the result — a completely standard defensive coding pattern. No malicious sequencer/operator/prover behavior is needed; the divergence exists purely because the two independent syscall implementations (Rust blockifier vs. Cairo OS) enforce different rules for the exact same operation.

### Recommendation
Port the exact validation performed in `crates/blockifier/src/execution/syscalls/syscall_base.rs::replace_class` (declared-class read + Cairo1-type check) into `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, so the OS asserts (via a hint-verified read of `contract_class_changes`/declared-class table) that the target class hash is declared and of the correct version before performing the `dict_update` on `contract_state_changes`. Resolve the `TODO(Yoni, 1/1/2026)` marker as part of this fix.

### Proof of Concept
1. Declare a normal Cairo1 contract `Victim` whose external function wraps the syscall:
   ```
   match starknet::replace_class_syscall(class_hash) {
       Ok(_) => set_flag_success(),
       Err(_) => set_flag_error(),
   }
   ```
2. Deploy `Victim`, then invoke it with `class_hash = <some undeclared felt>`.
3. Under the blockifier (RPC simulate/execute, sequencer transaction execution): `replace_class_syscall` returns `Err` (per `syscall_base.rs::replace_class` and the negative-flow test in `replace_class.rs::undeclared_class_hash`), so `set_flag_error()` runs and `Victim`'s class hash is unchanged.
4. Under the Starknet OS re-execution of the identical transaction (same calldata, same block): `execute_replace_class` in `syscall_impls.cairo` performs no declared-class check, so the syscall "succeeds", `set_flag_success()` runs, and `Victim`'s `class_hash` state entry is overwritten to the undeclared hash in `contract_state_changes` — producing a state diff/commitment that differs from the one the blockifier computed for the same transaction.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,

    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    let revert_log = &revert_log[1];
