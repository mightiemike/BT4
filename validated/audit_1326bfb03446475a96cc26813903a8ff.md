### Title
Meta-transaction `DelegateAction` signature omits any chain/network-specific binding, enabling cross-chain (fork) replay - (File: `core/primitives/src/action/delegate.rs`)

### Summary
The NEP-366 meta-transaction signing scheme (`DelegateAction`/`DelegateActionV2`, verified via `SignedDelegateAction::verify` / `VersionedSignedDelegateAction::verify`) hashes only a NEP-based message discriminant plus the action fields (`sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, `public_key`). Unlike the "Forwarder" domain-separator issue in the report, there is no chain identifier, genesis hash, or any other network-binding value included in the signed payload.

### Finding Description
`SignedDelegateAction::verify` computes the signed hash purely from `get_nep461_hash`, which wraps the action in `SignableMessage { discriminant, msg }` and hashes it [1](#0-0) . The `MessageDiscriminant` only encodes a NEP number/message type (NEP-366 or NEP-611), not any chain or network identifier [2](#0-1) . The `DelegateAction`/`DelegateActionV2` structs themselves contain no `block_hash`, genesis hash, or chain ID field — only `sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, `public_key` [3](#0-2) [4](#0-3) .

By contrast, an ordinary `SignedTransaction` is bound to a specific chain history through a recent `block_hash` field that must reference a block within a short validity window, which effectively prevents replay across independent chains (two chains would need an identical block hash, astronomically unlikely absent an actual shared history/fork). The inner `DelegateAction`, however, has no equivalent binding — its only temporal bound is `max_block_height`, an upper bound with no lower bound or chain-specific salt.

At application time, `apply_delegate_action` only checks the signature validity, `max_block_height`, and that the receiver matches the declared sender, then proceeds to validate/advance the access-key nonce [5](#0-4) ; nonce and permission checks are all chain-state-relative in `validate_delegate_action_key`, not chain-identity-relative [6](#0-5) .

Consequently, if the same account (same `sender_id`, same access key/public key, same nonce state) exists on two different NEAR-protocol networks — e.g., a network fork/hard fork, a "shadow" or migrated chain sharing the same genesis/state, or any two deployments where account state coincides — a `DelegateAction` signed for use on chain A can be wrapped in a fresh outer `SignedTransaction` (which only needs a valid recent block hash on chain B, trivially obtainable by any relayer on chain B) and replayed on chain B, executing the user's delegated actions there without their consent for that specific chain.

This is the direct structural analog of the reported bug: the Forwarder's domain separator lacked chain-ID binding in signature verification; NEAR's meta-transaction (`DelegateAction`) signing scheme similarly lacks any chain-specific binding, relying only on the NEP discriminant and action fields.

### Impact Explanation
If exploited on two networks with matching account/key/nonce state (a realistic scenario after a contentious hard fork, where both chains initially share identical genesis state and validators/relayers may operate on both), an attacker relayer could replay a user's signed meta-transaction — moving funds or performing account actions on the un-intended chain — without the user's consent for that chain. This is unauthorized value movement / invalid state transition acceptance for that network, categorized High per the reachable meta-transaction sender/relayer threat model.

### Likelihood Explanation
Exploitation requires two coexisting NEAR-protocol networks with coincident account state (same `sender_id`, same public key registered, same access-key nonce not yet advanced) — most plausible immediately following a chain fork/split where state is duplicated. It is not exploitable under normal single-chain operation, so likelihood is contingent on a fork event, but when such an event occurs, no on-chain mechanism in the current code prevents the replay (compare with `SignedTransaction`'s implicit protection via recent, chain-specific `block_hash`).

### Recommendation
Include a chain-specific value (e.g., the genesis hash or a NEAR chain ID) inside the `SignableMessage`/`DelegateAction` payload used for `get_nep461_hash`, so the domain of the signature is bound to a specific network. This mirrors the fix recommended in the reference report: validate/derive the chain identity as part of the message hash rather than relying solely on NEP/message-type discriminants and block-height bounds.

### Proof of Concept
Conceptual (cannot be executed without two live coincident-state networks):
1. On chain A, a user signs a `DelegateAction` (`sender_id=alice.near`, `receiver_id=bob.near`, `actions=[Transfer]`, `nonce=N`, `max_block_height=H`) using `VersionedSignedDelegateAction::sign` [7](#0-6) .
2. Chain A and chain B fork from a common point such that `alice.near`'s access key and nonce state are identical on both chains at height < H.
3. A relayer submits the identical `SignedDelegateAction`/`VersionedSignedDelegateAction` bytes wrapped in a new outer `SignedTransaction` (with a fresh, valid recent `block_hash` from chain B) to chain B.
4. `apply_delegate_action` on chain B accepts it: `signed_delegate_action.verify()` succeeds (no chain binding to fail), `max_block_height` check passes, sender/receiver match, and `validate_delegate_action_key` accepts the nonce since it hasn't advanced on chain B [8](#0-7) , so the transfer executes on chain B without the user ever signing anything intended for chain B.

impl SignedDelegateAction {
    pub fn verify(&self) -> bool {
        let delegate_action = &self.delegate_action;
        let hash = delegate_action.get_nep461_hash();
        let public_key = &delegate_action.public_key;

        self.signature.verify(hash.as_ref(), public_key)
    }

    pub fn sign(singer: &Signer, delegate_action: DelegateAction) -> Self {
        let signature = singer.sign(delegate_action.get_nep461_hash().as_bytes());
        Self { delegate_action, signature }
    }
}

impl<'a, T: BorshSerialize> SignableMessage<'a, T> {
    pub fn new(msg: &'a T, ty: SignableMessageType) -> Self {
        let discriminant = ty.into();
        Self { discriminant, msg }
    }

    pub fn sign(&self, signer: &Signer) -> Signature {
        let bytes = borsh::to_vec(&self).expect("Failed to deserialize");
        let hash = hash(&bytes);
        signer.sign(hash.as_bytes())
    }

pub(crate) fn apply_delegate_action(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    action_receipt: &VersionedActionReceipt,
    sender_id: &AccountId,
    signed_delegate_action: VersionedSignedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    // The inner delegate signature is verified below, here on the receiver shard.
    // Meter its verification compute against this shard's `compute_limit`; the gas
    // for it was already burnt at tx conversion on the signer shard. Without the
    // fix the compute is instead mis-charged on the signer shard (which never runs
    // this verify), letting the work escape the receiver shard's budget. See
    // `signature_verification_cost`.
    if apply_state.config.wasm_config.fix_ml_dsa_cost_charging {
        let verify_compute = delegate_signature_verification_compute(
            &apply_state.config.fees,
            signed_delegate_action.delegate_action().public_key(),
        );
        result.compute_usage = safe_add_compute(result.compute_usage, verify_compute)?;
    }
    if !signed_delegate_action.verify() {
        result.result = Err(ActionErrorKind::DelegateActionInvalidSignature.into());
        return Ok(());
    }
    let delegate_action = signed_delegate_action.delegate_action();
    if apply_state.block_height > delegate_action.max_block_height() {
        result.result = Err(ActionErrorKind::DelegateActionExpired.into());
        return Ok(());
    }
    if delegate_action.sender_id().as_str() != sender_id.as_str() {
        result.result = Err(ActionErrorKind::DelegateActionSenderDoesNotMatchTxReceiver {
            sender_id: delegate_action.sender_id().clone(),
            receiver_id: sender_id.clone(),
        }
        .into());
        return Ok(());
    }

    validate_delegate_action_key(state_update, apply_state, delegate_action, result)?;
    if result.result.is_err() {
        // Validation failed. Need to return Ok() because this is not a runtime error.
        // "result.result" will be return to the User as the action execution result.
        return Ok(());
    }

fn validate_delegate_action_key(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    delegate_action: VersionedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let sender_id = delegate_action.sender_id();
    let public_key = delegate_action.public_key();
    // 'sender_id' account existence must be checked by a caller
    let mut access_key = match get_access_key(state_update, sender_id, public_key)? {
        Some(access_key) => access_key,
        None => {
            result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                InvalidAccessKeyError::AccessKeyNotFound {
                    account_id: sender_id.clone(),
                    public_key: public_key.clone().into(),
                },
            )
            .into());
            return Ok(());
        }
    };

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
    };

    if delegate_nonce.nonce() <= current_nonce {
        result.result = Err(ActionErrorKind::DelegateActionInvalidNonce {
            delegate_nonce: delegate_nonce.nonce(),
            ak_nonce: current_nonce,
        }
        .into());
        return Ok(());
    }
