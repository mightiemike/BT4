### Title
Missing declared-class check in OS `execute_replace_class` allows the Starknet OS to diverge from Blockifier's `replace_class` validation - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS's implementation of the `replace_class` syscall unconditionally updates a contract's `class_hash` in `contract_state_changes` without verifying that the given `class_hash` corresponds to a declared class — a check that is explicitly marked as missing with a `TODO`, and a check that Blockifier's own `replace_class` handler *does* perform before committing the change.

### Finding Description
In the OS (Cairo) implementation: [1](#0-0) 
`execute_replace_class` reads `request.class_hash`, and immediately writes it into the contract's `StateEntry.class_hash` via `dict_update` on `contract_state_changes`, with the comment: "TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash." No lookup against `contract_class_changes` (the declared-classes dictionary) or any other declared-class commitment is performed before accepting the new class hash.

By contrast, Blockifier's native execution path enforces this check by reading the compiled class before updating state: [2](#0-1) 
`syscall_handler.state.get_compiled_class(request.class_hash)?;` errors out (causing the call/transaction to revert) if the class hash was never declared, as directly demonstrated in the Blockifier unit test: [3](#0-2) 
where replacing with an undeclared class hash `1234` yields the error "is not declared" and the transaction reverts, leaving state unchanged.

The deprecated OS syscall path exhibits the identical gap: [4](#0-3) 
`execute_replace_class` there also performs `dict_update` on `contract_state_changes` with the caller-supplied `class_hash`, with zero declared-class validation of any kind.

This is structurally analogous to the reported Deno bug: a security-relevant check (declared/allowed) is applied on one representation of an identifier (`request.class_hash` as validated by Blockifier's real execution against the declared-classes set), but the value that is actually committed into state by the re-execution/proving layer (the OS) is accepted without re-validating it against the same set — i.e., the "resolved" value used for the actual state mutation bypasses the check that the reference execution engine performs.

### Impact Explanation
If a transaction's `class_hash` argument for `replace_class` is not independently re-validated by the OS against declared classes, the OS's re-execution of a block could produce a different resulting state (and therefore a different state root / block hash) than Blockifier's actual execution whenever this code path is reachable with a genuinely undeclared class hash that Blockifier would have rejected (reverted). Any honest-node divergence between the sequencer's real execution (Blockifier) and the OS's re-execution/proof of that same block is a critical correctness property violation for a system whose block hash and state commitment must be provably consistent with the OS trace — it can lead to an incorrect committed state root/block hash or an unprovable/incorrectly-proved block.

### Likelihood Explanation
The likelihood of this specific divergence firing depends on exactly how the OS's `contract_state_changes` state entries are populated (via hints, from Blockifier's already-computed state diff, vs. independently derived pure-Cairo logic) — a detail I could not fully verify with certainty in the remaining investigation. If, as is common in Starknet OS design, the `contract_state_changes` dict entries fed via hints already encode the *post-Blockifier-execution* result (i.e., a revert already erased any invalid `replace_class` effect before the OS ever sees it), then this specific code path may not be independently reachable by an attacker to produce divergence, and the missing check would be a proving-only correctness gap rather than an externally triggerable divergence. I was not able to confirm from the available Cairo source how `GetContractAddressStateEntry` and the transaction-level revert log interact with an undeclared-class `replace_class` call, so exploitability confidence here is moderate, not certain.

### Recommendation
Add a declared-class check to `execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo` (and the deprecated variant in `deprecated_execute_syscalls.cairo`), mirroring Blockifier's `get_compiled_class` check: look up `class_hash` in `contract_class_changes` (or the relevant declared-classes commitment) and fail/revert the call if the class hash is not declared, before performing the `dict_update` on `contract_state_changes`. Resolve the existing `TODO(Yoni, 1/1/2026)` comment as part of this fix, and add a Starknet-OS-level regression test analogous to `deprecated_syscalls_test.rs::test_replace_class` that exercises an undeclared class hash and asserts the OS rejects/reverts identically to Blockifier.

### Proof of Concept
Not independently verifiable within the scope of this investigation: reaching this exact divergence requires understanding precisely how the OS's re-execution hints (`GetContractAddressStateEntry`) source the "declared" status of a class for a `replace_class` call originating from within the same block (e.g., a `declare` in one call followed by `replace_class` in another, or with a nonexistent class hash entirely), and whether the transaction-level revert mechanism already filters out invalid outcomes before this Cairo code executes. I recommend a Devin session with the ability to build/run the Starknet OS test harness (`starknet_os_flow_tests`) to construct a transaction that calls `replace_class` with an undeclared class hash and confirm whether the OS proof succeeds where Blockifier would revert.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
