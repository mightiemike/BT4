## Title
Uniswap V3 auto-swap paths (gas refund, gas deposit, gas+payload deposit) rely on a same-block spot quote and a fixed 5% slippage band, letting an unprivileged actor sandwich the swap and skim protocol/user funds - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
The Sherlock report's root cause is a pricing oracle assuming a favorable/fixed exchange rate without validating the actual, attacker-influenceable market execution path. Push Chain has a structurally identical pattern: whenever the protocol needs to convert a gas token to PC (gas refunds) or a PRC20 to PC (gas-abstraction deposits), it fetches a *live spot quote* from `UniswapV3 QuoterV2` and immediately executes the swap against the same on-chain AMM pool with only a static 5% slippage tolerance, inside a deterministic, publicly-observable transaction (a `MsgVoteInbound`/`MsgVoteOutbound` reaching quorum). Because the quote and the swap happen back-to-back but are not protected from price manipulation between the two calls (or generally from a thin/manipulated pool at execution time), an unprivileged attacker can sandwich these protocol-initiated swaps to extract value, exactly mirroring the external report's core flaw: "no validation of market conditions or slippage during redemption/execution."

### Finding Description
Three code paths compute `minPCOut` from a live `QuoterV2.quoteExactInputSingle` call and then immediately execute a real swap via `UniversalCore`, with the slippage tolerance hardcoded at 5%:

1. `GetSwapQuote` fetches the spot quote: [1](#0-0) 
2. `ExecuteInboundGas` (gas-abstraction inbound) uses the quote to compute `minPCOut = quote * 95/100` and immediately swaps: [2](#0-1) 
3. `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound) does the identical quote→95%→swap sequence: [3](#0-2) 
4. `applyGasRefund` (outbound gas refund) does the same for the gas-token → PC swap-back leg: [4](#0-3) 

All three are triggered by ordinary, unprivileged user-reachable flows (a user sending funds cross-chain, or a relayer/UV submitting `MsgVoteOutbound` once quorum is reached — both of which are publicly visible before they land). Because Cosmos SDK transactions execute deterministically once included in a block, and inclusion/ordering is externally observable (mempool visibility, predictable quorum-reaching vote), an attacker can:
- Observe that a quorum-triggering vote (or an inbound funds+gas message) is about to land.
- Submit a swap against the same WPC/gasToken Uniswap V3 pool immediately before it (pushing the pool price against the protocol) and immediately after (reverting the price), i.e., a classic sandwich.
- The protocol's `minPCOut` calculation is only 5% below the *momentarily manipulated* quote, so the attacker can safely push the price by up to that band and pocket the difference, while the protocol/user still nominally "succeeds" (no revert), silently receiving less PC than a fair, unmanipulated execution would produce.

This is aggravated by the fact that at least in local/E2E environments, these pools are explicitly documented as thin: [5](#0-4) . Thin liquidity means a 5% price swing is cheap to engineer, unlike the report's caution around "low liquidity" DEX paths.

### Impact Explanation
This directly corrupts native/PRC20 asset accounting and gas-fee/refund accounting invariants: the amount of PC minted to the user (deposit-with-autoswap) or refunded to the user (gas refund swap-back) can be systematically reduced by an attacker who repeatedly sandwiches these deterministic swap executions, draining value from users/protocol-controlled liquidity into the attacker's pocket — squarely within the "corruption of ... gas fee accounting, refund accounting ... token mapping" and "stealing / draining ... of user or protocol-controlled funds" allowed impacts. Every GAS, GAS_AND_PAYLOAD inbound and every successful/failed outbound with excess gas triggers this code path, so the exposure is not a one-off edge case but a recurring, exploitable pattern across the protocol's gas-abstraction and refund lifecycle.

### Likelihood Explanation
Likelihood is meaningful but not "trivial for every tx": it requires the attacker to (a) monitor the chain for pending quorum-completing votes / inbound gas messages, and (b) have the ability to place swap transactions immediately before/after the triggering tx within the same or adjacent block. On a Cosmos chain without private mempools or MEV protections, this is achievable by an ordinary unprivileged user with no special access, especially given documented thin liquidity in the WPC/gas-token pools. The fixed, non-adaptive 5% band (rather than something computed from real depth/TWAP or capped notional) means the attack is economically viable whenever the swapped amount and pool depth make a 5% price move cheap to engineer.

### Recommendation
- Replace the fixed 5% slippage constant with either a TWAP-based reference price (resistant to single-block manipulation) or a maximum absolute swap size relative to pool depth.
- Consider batching/aggregating swaps or routing them through a private/committed execution path so the quote and swap cannot be sandwiched between separately observable transactions.
- Add a circuit breaker / fallback to the no-swap PRC20 path (already present in `applyGasRefund`'s fallback) whenever quoted slippage from a longer-window reference exceeds a safety threshold, rather than only falling back on outright call failure.

### Proof of Concept
Conceptual attack sequence:
1. Attacker monitors mempool/state and observes a `MsgVoteOutbound` about to reach quorum, or a `GAS`/`GAS_AND_PAYLOAD` inbound about to be finalized, both of which will trigger an on-chain Uniswap V3 swap against the gasToken/WPC pool via `GetSwapQuote` → `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`.
2. Attacker front-runs with a large swap in the same direction the protocol's swap will need liquidity from, moving the pool price unfavorably for the protocol swap by up to ~5% (within the tolerated `minPCOut` band computed in `applyGasRefund`/`gasAndPayloadDepositAutoSwap`, see [6](#0-5) ).
3. The protocol's swap executes at the manipulated price but still satisfies `minPCOut`, so it succeeds without reverting, and the user/refund recipient receives up to 5% less PC than fair value.
4. Attacker back-runs with an opposing swap to restore the pool price and capture the spread.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
