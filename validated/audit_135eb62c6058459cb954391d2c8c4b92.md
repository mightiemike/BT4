## Analysis

The external referral-griefing report models attacker-supplied address fields that "consume" protocol value flows but route to an address nobody can act on, permanently destroying value that was meant to remain useful. In Push Chain, the direct analog is the unvalidated `RevertInstructions.FundRecipient` field on `Inbound`/`OutboundTx`, which comes straight from attacker-controlled cross-chain call data and is later blindly converted with `common.HexToAddress` when protocol code re-mints/refunds bridged funds.

### Title
Unvalidated `RevertInstructions.FundRecipient` lets an attacker permanently burn bridged funds during revert/refund/rescue flows - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/types/inbound.go`)

### Summary
`Inbound.RevertInstructions.FundRecipient` is fully attacker-controlled (part of the source-chain event data that Universal Validators vote on verbatim) and is never validated as a well-formed address anywhere in the inbound validation pipeline. It is only lenient-canonicalized (trimmed/whitespace-normalized), never format-checked or rejected. When a revert, gas-refund, or rescue path later needs to pay this address, the string is passed straight into `common.HexToAddress(...)`, which silently maps any non-hex/garbage input to the zero address instead of erroring.

### Finding Description
`Inbound.ValidateBasic()` only requires `Sender` to be non-empty and never inspects `RevertInstructions` at all. [1](#0-0) 

`Inbound.ValidateForExecution()` validates `Recipient` with `utils.IsValidAddress(p.Recipient, utils.HEX)` for `FUNDS`/`GAS` types, but at no point validates `RevertInstructions.FundRecipient` for any tx type. [2](#0-1) 

`Canonicalize()` only trims and lenient-canonicalizes `FundRecipient`; the helper is explicitly "lenient (unparseable values are kept trimmed, never rejected)". [3](#0-2) 

The ballot key digest (`GetInboundBallotKey`) also just hashes the raw string without validating it, so honest UVs converge on quorum for a ballot carrying a malformed `FundRecipient`. [4](#0-3) 

Downstream, whenever a revert/refund/rescue actually pays out, the unvalidated string is converted with `common.HexToAddress`, which — per go-ethereum semantics — silently returns the zero address for any string that isn't valid hex, rather than returning an error:
- `handleFailedOutbound` re-mints bridged PRC20 tokens to `common.HexToAddress(recipient)` where `recipient` comes directly from `outbound.RevertInstructions.FundRecipient`. [5](#0-4) 
- `applyGasRefund` computes `recipientAddr := common.HexToAddress(refundRecipient)` from the same unvalidated field and calls `CallUniversalCoreRefundUnusedGas` with it. [6](#0-5) 
- `buildRevertOutbound` and `AttachRescueOutboundFromReceipt` both propagate the same unvalidated `FundRecipient` value into the eventual on-chain payout recipient with no format check. [7](#0-6) [8](#0-7) 

### Impact Explanation
An unprivileged attacker who initiates a bridge/inbound event on any supported source chain fully controls the `revert_instructions.fund_recipient` bytes that Universal Validators observe and vote on. By setting this field to a malformed value (e.g., a non-hex string, wrong length, or anything `common.HexToAddress` cannot parse into a meaningful address), the attacker forces any later revert, excess-gas refund, or rescue-funds flow for that inbound/outbound to silently re-mint or refund the bridged PRC20/native tokens to the EVM zero address — an address nobody controls. This is a permanent, unrecoverable loss of user- and protocol-mediated funds (equivalent in effect to the referenced report's unclaimable-referral-address griefing, but here it destroys the very funds under protection rather than merely diverting a fee), reachable purely through the attacker's own honestly-processed inbound with no validator or admin collusion required.

### Likelihood Explanation
The trigger is a single crafted field in a normal cross-chain deposit/message that any external, unprivileged user can submit; no elevated privileges, malicious validators, or race conditions are required. The only precondition is that the inbound later needs a revert, gas refund, or rescue (e.g., payload execution fails, or an outbound observation is negative), which are ordinary, attacker-triggerable execution outcomes (e.g., submitting a payload designed to revert). Because validation never checks `FundRecipient`'s format at any stage of the pipeline, this is deterministically reachable, not probabilistic.

### Recommendation
Validate `RevertInstructions.FundRecipient` with the same rigor as `Recipient` (e.g., `utils.IsValidAddress(..., utils.HEX)` for EVM-bound funds, or the chain-appropriate address format) inside `Inbound.ValidateForExecution()` and in the equivalent validation path for `OutboundTx.RevertInstructions`. If validation fails, treat it the same way an invalid `Recipient` is treated — fail execution/produce a failed `PCTx`/abort with manual intervention — and never allow `common.HexToAddress` (or the SVM/Borsh equivalent) to silently coerce an invalid string into the zero address for any fund-moving call.

### Proof of Concept
1. Attacker deposits funds on a source chain via the gateway, emitting an inbound event with `tx_type = FUNDS_AND_PAYLOAD` and a payload designed to revert deterministically (e.g., calls an invalid selector on a contract with no fallback, as shown to be achievable in `test/integration/uexecutor/vote_inbound_validation_test.go` "inbound with invalid payload records failed PCTx").
2. Attacker sets `revert_instructions.fund_recipient = "not-a-hex-address"` (or any string `common.HexToAddress` cannot parse).
3. Universal Validators observe and vote the inbound to quorum via `MsgVoteInbound`; `ValidateBasic`/`ValidateForExecution`/`Canonicalize` never reject the malformed `fund_recipient`.
4. Payload execution fails; `handleFailedOutbound` (or the direct inbound-revert path via `buildRevertOutbound`) computes `recipient := outbound.RevertInstructions.FundRecipient` and calls `k.CallPRC20Deposit(ctx, prc20, common.HexToAddress(recipient), amount)`.
5. `common.HexToAddress("not-a-hex-address")` resolves to `0x0000000000000000000000000000000000000000`; the bridged token amount is minted to the zero address and is permanently unrecoverable.

// Canonicalize normalizes encoding-variant fields in place (per source-chain
// namespace) so the same event from any observer is byte-identical across
// ballot keys, UTX keys and registry lookups. Lenient (unparseable values are
// kept trimmed, never rejected) because the vote path must always record a
// UTX — execution-level validation rejects malformed inbounds later.
func (p *Inbound) Canonicalize() {
	p.SourceChain = strings.TrimSpace(p.SourceChain)
	p.TxHash = utils.LenientCanonicalizeTxHash(p.SourceChain, p.TxHash)
	p.Sender = utils.LenientCanonicalizeAddress(p.SourceChain, p.Sender)
	p.AssetAddr = utils.LenientCanonicalizeAddress(p.SourceChain, p.AssetAddr)
	// Recipient lives on Push Chain (EVM) regardless of source chain.
	p.Recipient = utils.LenientCanonicalizeEVMAddress(p.Recipient)
	p.LogIndex = strings.TrimSpace(p.LogIndex)
	p.Amount = strings.TrimSpace(p.Amount)
	p.RawPayload = utils.CanonicalizeHexBlob(p.RawPayload)
	p.VerificationData = utils.CanonicalizeHexBlob(p.VerificationData)
	if p.RevertInstructions != nil {
		// Refunds return to the source chain.
		p.RevertInstructions.FundRecipient = utils.LenientCanonicalizeAddress(p.SourceChain, p.RevertInstructions.FundRecipient)
	}

// ValidateBasic does minimal sanity checks needed to accept a vote.
// Only fields required to identify the inbound and create a UTX key are validated here.
// Execution-level validation (amount, addresses, payload, recipient) is deferred to
// ValidateForExecution so that invalid inbounds still produce an on-chain UTX record
// (with a failed PCTx / revert) instead of silently dropping the vote and leaving
// user funds stuck in the gateway.
func (p Inbound) ValidateBasic() error {
	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)
	if chain == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}
	if !strings.Contains(chain, ":") {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain must be in CAIP-2 format <namespace>:<reference>")
	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")
	}

	// Validate sender — needed for revert recipient fallback
	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	// Validate log_index — needed for UTX key
	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}

	// Validate tx_type enum — needed to route execution
	if _, ok := TxType_name[int32(p.TxType)]; !ok || p.TxType == TxType_UNSPECIFIED_TX {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid tx_type: %v", p.TxType)
	}

	return nil
}

func GetInboundBallotKey(inbound Inbound) (string, error) {
	chain := strings.TrimSpace(inbound.SourceChain)

	// nil RevertInstructions and an empty FundRecipient are semantically
	// identical (revert falls back to sender) — digest them identically.
	fundRecipient := ""
	if inbound.RevertInstructions != nil {
		fundRecipient = utils.LenientCanonicalizeAddress(chain, inbound.RevertInstructions.FundRecipient)
	}

	return hashFields(
		InboundBallotDomain,
		chain,
		utils.LenientCanonicalizeTxHash(chain, inbound.TxHash),
		strings.TrimSpace(inbound.LogIndex),
		utils.LenientCanonicalizeAddress(chain, inbound.Sender),
		// Recipient lives on Push Chain (EVM) regardless of source chain.
		utils.LenientCanonicalizeEVMAddress(inbound.Recipient),
		strings.TrimSpace(inbound.Amount),
		utils.LenientCanonicalizeAddress(chain, inbound.AssetAddr),
		fmt.Sprintf("%d", inbound.TxType),
		utils.CanonicalizeHexBlob(inbound.VerificationData),
		fundRecipient,
		fmt.Sprintf("%t", inbound.IsCEA),
		utils.CanonicalizeHexBlob(inbound.RawPayload),
		// universal_payload intentionally excluded (derived, ignored on-chain).
	), nil
}
