### Title
Rescue-outbound creation skips the destination-chain "outbound enabled" gate that normal outbound creation enforces - (File: x/uexecutor/keeper/create_outbound.go)

### Summary
The Beedle report shows a borrower routing a loan through `buyLoan()`, a secondary state-transition path that never re-checks the `maxLoanRatio` invariant enforced on the primary `borrow()` path. The Push Chain analog is `AttachRescueOutboundFromReceipt`, a secondary path that creates `OutboundTx` records for a UTX but — unlike the primary path `BuildOutboundsFromReceipt` — never re-checks the `uregistryKeeper.IsChainOutboundEnabled` invariant that gates whether TSS is allowed to route funds to a given destination chain.

### Finding Description
Normal outbound creation goes through `BuildOutboundsFromReceipt` (`x/uexecutor/keeper/create_outbound.go:16-105`), which explicitly checks: [1](#0-0) 
before building any `OutboundTx`. If outbound is disabled for the destination chain, the whole call errors out and no outbound is created.

The rescue path, `AttachRescueOutboundFromReceipt` (`x/uexecutor/keeper/create_outbound.go:193-337`), is triggered by a different on-chain event (`RescueFundsOnSourceChain`) emitted from `UniversalGatewayPC`, and constructs an `OutboundTx` whose `DestinationChain` is `originalUtx.InboundTx.SourceChain`: [2](#0-1) 
This function never calls `IsChainOutboundEnabled` (or any inbound/outbound enablement check) for `originalUtx.InboundTx.SourceChain` before building and attaching the outbound via `attachOutboundsToUtx`, which is the same shared sink used by the validated path: [3](#0-2) 

Both paths ultimately feed the same downstream machinery — `PendingOutbounds`, `OutboundCreatedEvent`, TSS signing session creation, and the universal client's broadcaster — meaning any outbound reaching `attachOutboundsToUtx` will be picked up by the off-chain worker and signed/broadcast by TSS to the destination chain regardless of the admin-controlled "outbound enabled" flag for that chain, as long as it is created via the rescue path instead of the primary path.

### Impact Explanation
`x/uregistry`'s `ChainConfig.Enabled.IsOutboundEnabled` flag exists specifically so operators can disable outbound flows to a chain (e.g., during an incident, chain halt, gateway compromise, or planned deprecation) without disabling inbound observation. The rescue path bypasses this control entirely: an unprivileged caller can trigger `RescueFundsOnSourceChain` (available whenever a UTX is CEA-and-failed, or non-CEA with a `REVERTED` `INBOUND_REVERT`) and get an `OutboundTx` created and routed via TSS to a chain whose outbound has been explicitly disabled by governance/admin. This could cause funds to be signed and sent to a chain the operators intentionally quarantined, potentially resulting in loss of funds or reintroducing risk the disable flag was meant to prevent. This falls squarely under "corruption of ... revert destination, chain config use ... or canonical UniversalTx state" and "unauthorized module-originated EVM execution" in the allowed impact gate, since the module ends up creating/broadcasting an outbound to a chain config explicitly marked as outbound-disabled.

### Likelihood Explanation
Reaching this path requires only ordinary, unprivileged user actions already supported by the protocol: an inbound whose CEA deposit failed, or a non-CEA inbound whose auto-revert reverted — both are reachable states from normal cross-chain usage (e.g. token config removed/misconfigured, or destination gateway rejecting the revert). Once the UTX is in that state, calling the rescue mechanism on `UniversalGatewayPC` is user-reachable and requires no admin/validator privilege. The only scenario needed to trigger the missing-check divergence is for an admin to have disabled outbound to the source chain in between — a realistic operational sequence (e.g., disabling a compromised or paused chain) that the missing check fails to respect.

### Recommendation
Add the same `IsChainOutboundEnabled` (and ideally the general chain-enabled/validity) check in `AttachRescueOutboundFromReceipt` before constructing and attaching the rescue `OutboundTx`, mirroring `BuildOutboundsFromReceipt`:

```go
outboundEnabled, err := k.uregistryKeeper.IsChainOutboundEnabled(ctx, originalUtx.InboundTx.SourceChain)
if err != nil {
    return fmt.Errorf("rescue: failed to check outbound enabled for chain %s: %w", originalUtx.InboundTx.SourceChain, err)
}
if !outboundEnabled {
    return fmt.Errorf("rescue: outbound is disabled for chain %s", originalUtx.InboundTx.SourceChain)
}
```
placed before the `tokenCfg` lookup at line 285, so any invariant enforced on the primary outbound-creation path is uniformly enforced on the rescue path as well.

### Proof of Concept
Note: I was not able to fully verify the caller-permission model of the `rescueFundsOnSourceChain` EVM function itself (its Solidity source lives in `push-chain-core-contracts`, outside this repo's index), nor find a concrete end-to-end test exercising "outbound disabled + rescue" together — the closest test found was `test/integration/uexecutor/rescue_funds_test.go`, which I could not fully inspect within the tool budget. The conceptual PoC, mirroring the Beedle report's structure, is:

1. An inbound with `IsCEA = true` arrives and its deposit PCTx fails (e.g., token config missing at execution time), leaving the UTX in a rescuable state per `originalUtx.PcTx[0].Status == "FAILED"` (`x/uexecutor/keeper/create_outbound.go:247-250`).
2. Admin/governance disables outbound for the inbound's source chain via `MsgUpdateChainConfig` (`Enabled.IsOutboundEnabled = false`), e.g. due to an incident on that chain.
3. Any user calls the gateway's rescue function, emitting `RescueFundsOnSourceChain`, referencing the stuck UTX's ID.
4. `AttachRescueOutboundFromReceipt` processes the event, checks only CEA-failure eligibility and duplicate-rescue guards (lines 247-282), and builds/attaches a `RESCUE_FUNDS` `OutboundTx` to the disabled chain (lines 303-333) — with no `IsChainOutboundEnabled` check anywhere in the function.
5. The new outbound is indexed in `PendingOutbounds` and an `OutboundCreatedEvent` is emitted (`create_outbound.go:339-406`), which the off-chain `puniversald` workers pick up for TSS signing and broadcast to the "disabled" destination chain, defeating the admin's outbound-disable control. func (k Keeper) BuildOutboundsFromReceipt(
	ctx context.Context,
	utxId string,
	receipt *evmtypes.MsgEthereumTxResponse,
) ([]*types.OutboundTx, error) {

	outbounds := []*types.OutboundTx{}
	universalGatewayPC := strings.ToLower(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_GATEWAY_PC"].Address)

	k.Logger().Debug("building outbounds from receipt", "utx_id", utxId, "tx_hash", receipt.Hash, "log_count", len(receipt.Logs))

	for _, lg := range receipt.Logs {
		if lg.Removed {
			continue
		}

		if strings.ToLower(lg.Address) != universalGatewayPC {
			continue
		}

		if len(lg.Topics) == 0 {
			continue
		}

		if strings.ToLower(lg.Topics[0]) != strings.ToLower(types.UniversalTxOutboundEventSig) {
			continue
		}

		event, err := types.DecodeUniversalTxOutboundFromLog(lg)
		if err != nil {
			return nil, fmt.Errorf("failed to decode UniversalTxWithdraw: %w", err)
		}

		// Check if outbound is enabled for the destination chain
		outboundEnabled, err := k.uregistryKeeper.IsChainOutboundEnabled(ctx, event.ChainId)
		if err != nil {
			return nil, fmt.Errorf("failed to check outbound enabled for chain %s: %w", event.ChainId, err)
		}
		if !outboundEnabled {
			k.Logger().Warn("outbound disabled for chain", "chain_id", event.ChainId, "utx_id", utxId)
			return nil, fmt.Errorf("outbound is disabled for chain %s", event.ChainId)
		}

func (k Keeper) AttachRescueOutboundFromReceipt(
	ctx sdk.Context,
	receipt *evmtypes.MsgEthereumTxResponse,
	pcTx types.PCTx,
) error {
	universalGatewayPC := strings.ToLower(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_GATEWAY_PC"].Address)

	evmChainID, err := utils.ExtractEvmChainID(ctx.ChainID())
	if err != nil {
		return fmt.Errorf("rescue: failed to extract EVM chain ID: %w", err)
	}
	pushChainCaip := fmt.Sprintf("eip155:%s", evmChainID)

	for _, lg := range receipt.Logs {
		if lg.Removed {
			continue
		}
		if strings.ToLower(lg.Address) != universalGatewayPC {
			continue
		}
		if len(lg.Topics) == 0 {
			continue
		}
		if strings.ToLower(lg.Topics[0]) != strings.ToLower(types.RescueFundsOnSourceChainEventSig) {
			continue
		}

		event, err := types.DecodeRescueFundsOnSourceChainFromLog(lg)
		if err != nil {
			return fmt.Errorf("failed to decode RescueFundsOnSourceChain: %w", err)
		}

		// The universalTxId in the event is a 0x-prefixed bytes32 matching our UTX key.
		originalUtxId := strings.TrimPrefix(event.UniversalTxId, "0x")

		originalUtx, found, err := k.GetUniversalTx(ctx, originalUtxId)
		if err != nil {
			return fmt.Errorf("rescue: failed to fetch UTX %s: %w", originalUtxId, err)
		}
		if !found {
			return fmt.Errorf("rescue: original UTX %s not found", originalUtxId)
		}
		if originalUtx.InboundTx == nil {
			return fmt.Errorf("rescue: UTX %s has no inbound tx", originalUtxId)
		}

		// Rescue eligibility differs by inbound type:
		//
		//  CEA inbounds: the deposit (first PCTx) must have failed, meaning the funds
		//  never arrived on Push Chain and are still locked on the source chain.
		//
		//  Non-CEA inbounds: the auto-generated INBOUND_REVERT outbound must exist and
		//  have reached REVERTED status, meaning TSS could not return the funds to the
		//  source chain and they are stuck (held by the gateway contract or in escrow).
		if originalUtx.InboundTx.IsCEA {
			if len(originalUtx.PcTx) == 0 || originalUtx.PcTx[0] == nil || originalUtx.PcTx[0].Status != "FAILED" {
				return fmt.Errorf("rescue: UTX %s CEA deposit did not fail", originalUtxId)
			}
		} else {
			hasRevertedAutoRevert := false
			for _, ob := range originalUtx.OutboundTx {
				if ob != nil && ob.TxType == types.TxType_INBOUND_REVERT && ob.OutboundStatus == types.Status_REVERTED {
					hasRevertedAutoRevert = true
					break
				}
			}
			if !hasRevertedAutoRevert {
				return fmt.Errorf("rescue: UTX %s has no reverted inbound-revert outbound", originalUtxId)
			}
		}

		k.Logger().Info("rescue outbound detected",
			"original_utx_id", originalUtxId,
			"pc_tx_hash", receipt.Hash,
		)

		// Guard against duplicate rescue outbounds: reject if an active rescue
		// (PENDING or OBSERVED) already exists. A REVERTED rescue may be retried.
		for _, ob := range originalUtx.OutboundTx {
			if ob == nil || ob.TxType != types.TxType_RESCUE_FUNDS {
				continue
			}
			if ob.OutboundStatus == types.Status_PENDING || ob.OutboundStatus == types.Status_OBSERVED {
				k.Logger().Warn("rescue outbound rejected: active rescue already exists",
					"original_utx_id", originalUtxId,
					"existing_outbound_id", ob.Id,
				)
				return fmt.Errorf("rescue: UTX %s already has an active rescue outbound (%s)", originalUtxId, ob.Id)
			}
		}

		// Resolve external asset address from PRC20 → token config for the source chain.
		tokenCfg, err := k.uregistryKeeper.GetTokenConfigByPRC20(
			ctx,
			originalUtx.InboundTx.SourceChain,
			event.PRC20,
		)
		if err != nil {
			return fmt.Errorf("rescue: token config not found for PRC20 %s on %s: %w",
				event.PRC20, originalUtx.InboundTx.SourceChain, err)
		}

		// Rescued funds go to the original revert recipient (or the sender as fallback).
		recipient := originalUtx.InboundTx.Sender
		if originalUtx.InboundTx.RevertInstructions != nil &&
			originalUtx.InboundTx.RevertInstructions.FundRecipient != "" {
			recipient = originalUtx.InboundTx.RevertInstructions.FundRecipient
		}

		logIndex := fmt.Sprintf("%d", lg.Index)
		outbound := &types.OutboundTx{
			Id:                types.GetRescueFundsOutboundId(pushChainCaip, receipt.Hash, logIndex),
			DestinationChain:  originalUtx.InboundTx.SourceChain,
			Recipient:         recipient,
			Amount:            originalUtx.InboundTx.Amount,
			ExternalAssetAddr: tokenCfg.Address,
			Prc20AssetAddr:    event.PRC20,
			Sender:            event.Sender,
			GasFee:            event.GasFee.String(),
			GasPrice:          event.GasPrice.String(),
			GasLimit:          event.GasLimit.String(),
			TxType:            types.TxType_RESCUE_FUNDS,
			OutboundStatus:    types.Status_PENDING,
			PcTx: &types.OriginatingPcTx{
				TxHash:   receipt.Hash,
				LogIndex: logIndex,
			},
		}

		// Record the rescue call as a PCTx on the original UTX so the full
		// PC-side history is visible (deposit FAILED → rescue call → outbound).
		if err := k.UpdateUniversalTx(ctx, originalUtxId, func(utx *types.UniversalTx) error {
			utx.PcTx = append(utx.PcTx, &pcTx)
			return nil
		}); err != nil {
			return fmt.Errorf("rescue: failed to record PCTx on UTX %s: %w", originalUtxId, err)
		}

		if err := k.attachOutboundsToUtx(ctx, originalUtxId, []*types.OutboundTx{outbound}, ""); err != nil {
			return fmt.Errorf("rescue: failed to attach outbound to UTX %s: %w", originalUtxId, err)
		}
	}

	return nil
}

func (k Keeper) attachOutboundsToUtx(
	ctx sdk.Context,
	utxId string,
	outbounds []*types.OutboundTx,
	revertMsg string, // revert msg if the outbound is for a inbound revert
) error {

	if len(outbounds) == 0 {
		return nil
	}
	return k.UpdateUniversalTx(ctx, utxId, func(utx *types.UniversalTx) error {

		for _, outbound := range outbounds {

			utx.OutboundTx = append(utx.OutboundTx, outbound)

			// Compute signature expiry deadline for the destination chain.
			var signingDeadline int64
			if chainCfg, err := k.uregistryKeeper.GetChainConfig(ctx, outbound.DestinationChain); err == nil {
				if chainCfg.TssSigningDeadline != nil && *chainCfg.TssSigningDeadline > 0 {
					signingDeadline = ctx.BlockTime().Unix() + int64(chainCfg.TssSigningDeadline.Seconds())
				}
			}

			// Write to pending outbounds index (inside UpdateUniversalTx closure for atomicity)
			if err := k.PendingOutbounds.Set(ctx, outbound.Id, types.PendingOutboundEntry{
				OutboundId:      outbound.Id,
				UniversalTxId:   utxId,
				CreatedAt:       ctx.BlockHeight(),
				SigningDeadline: signingDeadline,
			}); err != nil {
				return fmt.Errorf("failed to set pending outbound index for %s: %w", outbound.Id, err)
			}
