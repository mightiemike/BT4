### Title
`Bank::run_final_hash_calc()` silently discards the accounts lt-hash verification result - ([File: runtime/src/bank.rs])

### Summary
`Bank::run_final_hash_calc()` calls `self.verify_accounts(None)` — a `#[must_use]` function that returns `true` only "if all is good" — and immediately discards the boolean with `_ = ...` [1](#0-0) . This is the same bug class as the reported ERC20 issue: a function's success/failure return value is computed but never checked, so a failure (here, an accounts lattice-hash mismatch) is silently swallowed instead of being surfaced.

### Finding Description
`verify_accounts` recomputes the accounts lt hash from the accounts index (or uses a precomputed value) and compares it against the bank's recorded `accounts_lt_hash`, returning `false` and logging an `error!` when the hashes diverge [2](#0-1) . The function is explicitly annotated `#[must_use]`, signaling to callers that the boolean result must be inspected. However `run_final_hash_calc` — documented as running "a final hash calculation once all ledger replay has completed" — ignores this result entirely via `_ = self.verify_accounts(None);` [3](#0-2) . This mirrors the ERC20 analog exactly: a boolean "did this succeed" signal is computed, but the caller proceeds as if it always succeeded, so any true divergence between the account state built via replay and the accounts lattice hash is never propagated to the caller.

### Impact Explanation
If accounts state and the accounts lt hash diverge (e.g., due to a replay bug, an accounts-db corruption, or an inconsistency introduced elsewhere in the storage/index/lattice-hash pipeline), `run_final_hash_calc` will log an `error!` line but return normally with no error indication. `blockstore_processor.rs` and `ledger-tool/src/main.rs` invoke this after full ledger replay [4](#0-3) , so a caller relying on this function to validate the final accounts/ledger state has no way to detect that the check failed except by grepping logs. This is a genuine "honest-node snapshot-vs-replay mismatch is silently accepted" class of issue: the tool meant to catch a capitalization/hash divergence after full replay does not fail loudly when it detects one.

### Likelihood Explanation
This is reached deterministically whenever `run_final_hash_calc` is invoked (post-replay verification path in ledger-tool / blockstore_processor) and whenever accounts state actually diverges from the recorded lt hash — which is precisely the scenario this function exists to catch. The likelihood of the divergence occurring is separate from this bug; the bug itself guarantees that if it occurs, it is silently ignored by this call path.

### Recommendation
Do not discard the `#[must_use]` result. `run_final_hash_calc` should propagate failure to its callers, e.g. return `bool`/`Result<()>` and have `blockstore_processor.rs` / `ledger-tool` abort or report an error (analogous to using `SafeERC20`-style "always check success") instead of silently continuing when `verify_accounts` returns `false`.

### Proof of Concept
1. Corrupt or force a divergence between the bank's recorded `accounts_lt_hash` and the actual account state visible to `calculate_accounts_lt_hash_at_startup_from_index` (e.g., an accounts-db bug that leaves the index representation inconsistent with the true state before finalization).
2. Call `Bank::run_final_hash_calc()` (as done by ledger replay tooling) [3](#0-2) .
3. Observe `verify_accounts` logs `"Verifying accounts failed: accounts lattice hashes do not match"` [5](#0-4)  yet `run_final_hash_calc` returns `()` with no error — the caller has no signal that verification failed and will proceed as though the ledger replay produced a correct/consistent state.

    fn verify_accounts(&self, calculated_accounts_lt_hash: Option<&AccountsLtHash>) -> bool {
        let accounts_db = &self.rc.accounts.accounts_db;

        fn check_lt_hash(
            expected_accounts_lt_hash: &AccountsLtHash,
            calculated_accounts_lt_hash: &AccountsLtHash,
        ) -> bool {
            let is_ok = calculated_accounts_lt_hash == expected_accounts_lt_hash;
            if !is_ok {
                let expected = expected_accounts_lt_hash.0.checksum();
                let calculated = calculated_accounts_lt_hash.0.checksum();
                error!(
                    "Verifying accounts failed: accounts lattice hashes do not match, expected: \
                     {expected}, calculated: {calculated}",
                );
            }
            is_ok
        }

        info!("Verifying accounts...");
        let start = Instant::now();
        let expected_accounts_lt_hash = self.accounts_lt_hash.lock().unwrap().clone();
        let is_ok = if let Some(calculated_accounts_lt_hash) = calculated_accounts_lt_hash {
            check_lt_hash(&expected_accounts_lt_hash, calculated_accounts_lt_hash)
        } else {
            let calculated_accounts_lt_hash =
                accounts_db.calculate_accounts_lt_hash_at_startup_from_index(&self.ancestors);
            check_lt_hash(&expected_accounts_lt_hash, &calculated_accounts_lt_hash)
        };
        info!("Verifying accounts... Done in {:?}", start.elapsed());
        is_ok
    }
