Based on the investigation, the key facts are:

- `Accounts::lock_accounts` calls `validate_account_locks` **before** any locking occurs, and this function rejects the entire transaction with `TransactionError::AccountLoadedTwice` if *any* duplicate pubkey exists anywhere in the (post-ALT-resolved) `account_keys()` list, regardless of whether it's writable or read-only. [1](#0-0) [2](#0-1) 

- `AccountLocks` internally stores counts per unique `Pubkey` in a `write_locks: AHashMap<Pubkey, u64>`, but this structure is only ever populated *after* `validate_account_locks` has already succeeded — meaning by construction it can never receive duplicate writable keys from a single transaction's `account_keys()` in the first place. [3](#0-2) [4](#0-3) 

- `CostModel::get_write_lock_cost` multiplies `WRITE_LOCK_UNITS` by `num_write_locks`, which comes from `transaction.num_write_locks()` on the same (post-ALT) resolved message that `account_keys()`/`is_writable()` expose to `Accounts::lock_accounts`. [5](#0-4) [6](#0-5) 

- The existing test `test_lock_accounts_with_duplicates` confirms a transaction containing the same pubkey twice in `account_keys` is rejected outright with `AccountLoadedTwice`, never reaching execution or being included in a block. [7](#0-6) 

Since a transaction with duplicate account keys (post-ALT resolution) is unconditionally rejected during sanitization/locking before it can be executed or costed against real bank state, there is no reachable path where `num_write_locks` (used by the cost model) and the actual number of unique locks taken by `AccountLocks` can diverge for an included transaction. The premise of the question — that duplicate writable keys "collapse" into fewer unique lock slots while cost is still charged per raw count — cannot occur on mainnet because such a transaction never gets past `validate_account_locks`. The known, intentional exception (demoted write locks, e.g., write-locking the system program gets demoted to read-only) is explicitly tested and accepted behavior (cost is charged as if the lock were taken, by design), not a metering bypass. [8](#0-7)

pub fn validate_account_locks(
    account_keys: AccountKeys,
    tx_account_lock_limit: usize,

    if account_keys.len() > tx_account_lock_limit {
        Err(TransactionError::TooManyAccountLocks)
    } else if has_duplicates(account_keys) {
        Err(TransactionError::AccountLoadedTwice)

        Ok(())
