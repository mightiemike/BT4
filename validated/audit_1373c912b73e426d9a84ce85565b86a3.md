### Title
Missing `block_direct_execute_call` Enforcement in `library_call` Syscall Allows Bypass of `__execute__` Direct-Invocation Restriction - ([File: crates/blockifier/src/execution/syscalls/hint_processor.rs])

### Summary
The `block_direct_execute_call` security restriction, which forbids invoking a contract's `__execute__` entry point through an inner syscall (so that `__execute__` can only ever run as the single, top-level, validated call of a transaction), is enforced for the `call_contract` syscall but is **not** enforced for the semantically-equivalent `library_call` syscall. This inconsistency exists consistently across the live blockifier execution engine (VM and Native) and the Starknet OS (SnOS) re-execution program, so an unprivileged contract/account can reach the restricted entry point through the unguarded path.

### Finding Description
Starting from Starknet version 0.14.0, the protocol enforces `block_direct_execute_call` to prevent any inner call from directly invoking an account's `__execute__` entry point (this exists so `__execute__` can only be triggered once, as the top-level entry point of a validated transaction). This is implemented as `maybe_block_direct_execute_call`/inline selector checks that reject the call when `selector == EXECUTE_ENTRY_POINT_NAME`.

This check is present in the `call_contract` handlers: [1](#0-0) [2](#0-1) 

and in the corresponding Starknet OS Cairo1 `call_contract` implementation: [3](#0-2) 
as well as the deprecated (Cairo0) OS path: [4](#0-3) 

However, the `library_call` handlers in all four of these locations contain **no equivalent check** against `EXECUTE_ENTRY_POINT_NAME`/`EXECUTE_ENTRY_POINT_SELECTOR`:
- Blockifier VM: [5](#0-4) 
- Blockifier Native: [6](#0-5) 
- Starknet OS Cairo1: [7](#0-6) 
- Starknet OS Cairo0 (deprecated): [8](#0-7) 

This mirrors the reported bug class exactly: a protected resource/action (invoking `__execute__` outside the top-level transaction flow) has its access-control check correctly enforced on one path (`call_contract`, analogous to "direct project members") but is silently missing on an alternate, reachable path (`library_call`, analogous to "indirect project members") that leads to the same protected resource.

### Impact Explanation
The `block_direct_execute_call` protection exists because Starknet account contracts generally assume `__execute__` can only ever be invoked once, as the outermost call of a transaction that has already passed `__validate__`, with calldata bound by the transaction hash and signature. Many account implementations (multisig, session-key, spending-limit, transaction-guard accounts) rely on this invariant and do not independently re-verify the caller or re-enforce single-execution semantics inside `__execute__` itself, since the protocol was supposed to guarantee it structurally.

Because `library_call` is unguarded, any contract reachable during a transaction (the account's own `__execute__` logic, or any inner-called contract) can invoke `library_call(class_hash=<victim_or_own_account_class>, selector=__execute__, calldata=<attacker_chosen>)`. This lets an attacker:
- Trigger a second, unauthorized invocation of an account's `__execute__` logic with attacker-chosen calldata that was never part of the signed/hashed transaction, breaking the "single validated execution" invariant assumed by security-sensitive account implementations (e.g., re-triggering fund transfers, bypassing session-key scoping, or re-entering execution logic to defeat one-time authorization checks).
- Fully undermine the purpose of `block_direct_execute_call`, since the exact same restricted capability that was closed off via `call_contract` remains open via `library_call`.

This constitutes unauthorized account action / bypass of an explicit protocol-level authorization boundary, reachable by any ordinary transaction sender with no special privileges.

### Likelihood Explanation
The bug requires only a standard `invoke` transaction from any account whose class (or a class it interacts with) issues a `library_call_syscall` targeting `selector!("__execute__")` on any declared class hash — a syscall available to every Cairo contract. No special permissions, staking, or node-operator access is needed; this is directly reachable through blockifier execution and would be faithfully re-executed the same way by the Starknet OS, so it does not cause node divergence but does reliably bypass the intended restriction for every node.

### Recommendation
Add the same `block_direct_execute_call` check used in `call_contract` to all `library_call` handlers:
- `crates/blockifier/src/execution/syscalls/hint_processor.rs::library_call` — call `syscall_handler.base.maybe_block_direct_execute_call(request.function_selector)` before constructing the `CallEntryPoint`.
- `crates/blockifier/src/execution/native/syscall_handler.rs::library_call` — add the equivalent check.
- `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs::library_call`/`library_call_l1_handler` — add the equivalent check (mirroring the deprecated `call_contract` handler).
- `crates/apollo_starknet_os_program/.../execution/syscall_impls.cairo::execute_library_call` and `crates/apollo_starknet_os_program/.../execution/deprecated_execute_syscalls.cairo::execute_library_call_syscall` — add `assert_not_equal(request.selector/function_selector, EXECUTE_ENTRY_POINT_SELECTOR)` consistent with the `call_contract` path, gated on the `block_direct_execute_call` versioned constant where applicable.

### Proof of Concept
1. Deploy an attacker-controlled contract (or use logic inside the attacker's own account's `__execute__`) that issues:
   ```
   library_call_syscall(class_hash: <target_account_class_hash>, function_selector: selector!("__execute__"), calldata: <arbitrary calldata>)
   ```
2. Submit this as an ordinary `invoke` transaction (e.g., from the attacker's own funded account calling this helper logic during its own `__execute__`, or from any contract reachable in the call graph of a transaction).
3. Observe that, unlike the identical attempt via `call_contract_syscall` (which reverts with `Invalid argument` when `block_direct_execute_call` is enabled, as demonstrated by the existing test `test_direct_execute_call` in `crates/blockifier/src/execution/syscalls/syscall_tests/call_contract.rs:277-345` and `crates/starknet_os_flow_tests/src/tests.rs:2737-2775`), the `library_call` variant succeeds and executes the target class's `__execute__` entry point, demonstrating the bypass of the intended restriction.

    fn library_call(
        request: LibraryCallRequest,
        vm: &mut VirtualMachine,
        syscall_handler: &mut Self,
        remaining_gas: &mut u64,
    ) -> Result<LibraryCallResponse, Self::Error> {
        let entry_point = CallEntryPoint {
            class_hash: Some(request.class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: request.function_selector,
            calldata: request.calldata,
            // The call context remains the same in a library call.
            storage_address: syscall_handler.storage_address(),
            caller_address: syscall_handler.caller_address(),
            call_type: CallType::Delegate,
            // NOTE: this value might be overridden later on.
            initial_gas: *remaining_gas,
        };

        let retdata_segment = execute_inner_call(entry_point, vm, syscall_handler, remaining_gas)
            .map_err(|error| match error {
            SyscallExecutionError::Revert { .. } => error,
            _ => error.as_lib_call_execution_error(
                request.class_hash,
                syscall_handler.storage_address(),
                request.function_selector,
            ),
        })?;

        Ok(LibraryCallResponse { segment: retdata_segment })
    }

    fn library_call(
        &mut self,
        class_hash: Felt,
        function_selector: Felt,
        calldata: &[Felt],
        remaining_gas: &mut u64,
    ) -> SyscallResult<Vec<Felt>> {
        self.pre_execute_syscall(
            remaining_gas,
            self.gas_costs().syscalls.library_call.base_syscall_cost(),
            SyscallSelector::LibraryCall,
        )?;

        let class_hash = ClassHash(class_hash);

        let wrapper_calldata = Calldata(Arc::new(calldata.to_vec()));

        let selector = EntryPointSelector(function_selector);

        let entry_point = CallEntryPoint {
            class_hash: Some(class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector,
            calldata: wrapper_calldata,
            // The call context remains the same in a library call.
            storage_address: self.base.call.storage_address,
            caller_address: self.base.call.caller_address,
            call_type: CallType::Delegate,
            initial_gas: *remaining_gas,
        };

        let error_wrapper_function =
            |e: SyscallExecutionError,
             class_hash: ClassHash,
             storage_address: ContractAddress,
             selector: EntryPointSelector| {
                e.as_lib_call_execution_error(class_hash, storage_address, selector)
            };

        Ok(self
            .execute_inner_call(entry_point, remaining_gas, class_hash, error_wrapper_function)?
            .0)
    }
