## Title
Gas-token deposit auto-swap and refund swap use a self-referential Uniswap V3 spot quote as the slippage bound, enabling sandwich-attack fund loss on inbound gas-abstraction and refund flows - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Every path that performs a gas-token/PRC20 → WPC swap on behalf of a user (inbound gas abstraction, inbound gas+payload, and outbound gas refund) computes its "slippage protection" (`minPCOut`) as 95% of a quote fetched from the same on-chain Uniswap V3 `QuoterV2.quoteExactInputSingle` spot state that the actual swap will execute against, moments later, in the same block. Because the bound is derived from the manipulable spot price rather than a TWAP/oracle-anchored reference, an unprivileged attacker can move the pool price with an ordinary EVM transaction immediately before the module-originated swap executes, causing the deposit or refund to be swapped at an attacker-favorable rate and captured via a sandwich, at the expense of the depositing/refunded user.

### Finding Description
`Keeper.GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) calls the on-chain `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96: 0`, which reads the pool's current (spot) sqrt price: [1](#0-0) 

All three callers immediately compute the slippage bound from that same quote and pass it straight into the real swap call with no independent reference price:

- `ExecuteInboundGas` (gas abstraction on plain gas-only inbound): [2](#0-1) 

- `gasAndPayloadDepositAutoSwap` (gas+payload inbound): [3](#0-2) 

- `applyGasRefund` (outbound leftover-gas refund swap): [4](#0-3) 

In each case:
```go
quote, execErr = k.GetSwapQuote(...)
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
receipt, execErr = k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
``` [5](#0-4) 

The quote and the swap execution both read the same `x/vm` EVM state in the same block/height via `CallEVM`/`DerivedEVMCall`, so `minPCOut` only bounds the *swap's own price impact*, not external manipulation of the pool that occurred in a preceding transaction within the same block. This is the exact bug class from the Panoptic report: an instantaneous, unprotected on-chain price is used to size a fund-moving operation, with the "protection" itself derived from that same manipulable price.

Since Push Chain's inbound/outbound gas-abstraction pipeline processes inbounds deterministically as part of normal block execution (module-originated `DerivedEVMCall`s in `x/uexecutor`), and the underlying Uniswap V3 pools (prc20/WPC) are ordinary pools reachable by any address, an unprivileged attacker can:
1. Observe (or predict, since inbound processing is deterministic once voted/finalized) that a `depositPRC20WithAutoSwap` or `refundUnusedGas` swap for a given PRC20/WPC pair will execute in an upcoming block.
2. Submit a large swap in that pool to push the spot price against the direction that will hurt the victim swap.
3. Let the module's `GetSwapQuote` be computed against the now-manipulated price, producing a `minPCOut` that is 95% of an already-bad, attacker-inflated/deflated number.
4. Let the module's real swap execute against the still-manipulated pool at the bad rate (it will pass since `minPCOut` was set relative to the same manipulated price).
5. Reverse the initial swap, extracting the difference — a classic sandwich — at the expense of the depositing user's PC output or the refund recipient's refunded amount.

### Impact Explanation
This corrupts gas fee/refund accounting and PRC20→native (PC) conversion outcomes for ordinary users going through the gas-abstraction inbound path or receiving an outbound gas refund — both are default, unprivileged user flows reachable via a normal deposit/transaction. Because the fee tier and pool are fixed per token (`GetDefaultFeeTierForToken`), and the same pool is repeatedly used for many users' inbound gas swaps, this represents a systemic, per-transaction value-extraction vector rather than a one-off edge case, matching the "corruption of ... gas fee accounting, refund accounting ... or canonical UniversalTx state" and "unauthorized ... unauthorized refund of user or protocol-controlled funds" impact categories in scope.

### Likelihood Explanation
Likelihood is elevated relative to the original Panoptic finding because here the manipulation/extraction is not a one-time deployer action but occurs on every inbound gas-swap and every outbound gas refund for a given PRC20 — i.e., routine, ongoing user traffic. Any address with capital to move the specific PRC20/WPC pool (likely low liquidity relative to major DEX pools, since these are Push Chain's own token-launch pools) can execute this without any privileged role, purely by racing ordinary transactions into the same block/height as validator-driven inbound execution.

### Recommendation
Do not derive the slippage bound (`minPCOut`) from the same spot quote used to execute the swap. Instead:
- Use a TWAP-based or otherwise time-delayed reference price (e.g., Uniswap V3 `observe`/TWAP oracle) independent of the immediately preceding block's spot state to compute `minPCOut`.
- Alternatively, cap the maximum allowed single-block price deviation for the pool, or add a circuit breaker that reverts (falls back to the no-swap PRC20 deposit path, which already exists as a fallback in `applyGasRefund`) when the spot price deviates significantly from a recent TWAP.
- Consider limiting swap size relative to available pool liquidity, since capping notional exposure also bounds attacker profit from any single sandwich.

### Proof of Concept
1. Attacker observes a pending inbound event (already vote-finalized, about to be executed at the next block) that will deposit PRC20 `X` and trigger `ExecuteInboundGas` → `depositPRC20WithAutoSwap`.
2. In the same block (or immediately preceding block if execution timing allows), attacker submits a large `X → WPC` swap on the same Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetSwapQuote`, pushing the spot price so that a subsequent `X → WPC` quote is inflated.
3. Push Chain's block execution runs `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`), which returns the manipulated quote; `minPCOut` is set to 95% of that manipulated quote (`x/uexecutor/keeper/execute_inbound_gas.go:142-146`).
4. `CallPRC20DepositAutoSwap` executes the real swap against the still-manipulated pool, succeeding because `minPCOut` was computed from the same manipulated state, and the victim's deposit is converted to less PC (native) than a fair/TWAP price would have given.
5. Attacker reverses their initial swap in the same or the next transaction, capturing the price difference as profit, extracted from the value that should have gone to the depositing user (or, in the `applyGasRefund` case, the refund recipient).

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
