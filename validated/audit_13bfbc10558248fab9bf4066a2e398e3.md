## Finding

### Title
Unbounded JSON nesting depth in JSON-RPC request parsing causes stack-overflow node crash — ([File: chain/jsonrpc-primitives/src/message.rs])

### Summary
The NEAR JSON-RPC server accepts an arbitrary JSON body on `POST /` and deserializes it into `near_jsonrpc_primitives::message::Message` using `serde_json`'s recursive-descent deserializer, with no limit on JSON array/object nesting depth. A crafted deeply-nested JSON payload can drive the parser to blow the call stack before any JSON-RPC-level or application-level validation ever runs, aborting the node process. This is directly analogous to the reported `opcua` CVE-2022-25903 issue, where unbounded `ExtensionObject`/`Variant` nesting caused stack overflow — here the unbounded nesting is in the outer JSON envelope rather than in an OPC UA binary structure, but the root cause class (recursive parser with no depth cap, reachable from an untrusted network peer) is the same.

### Finding Description
`rpc_handler()` in `chain/jsonrpc/src/lib.rs` accepts the HTTP body (capped only by byte size via `RequestBodyLimitLayer::new(limits_config.json_payload_max_size)`, default 10MB, see `chain/jsonrpc/src/lib.rs:3120` and `RpcLimitsConfig::default` at `chain/jsonrpc/src/lib.rs:145-148`) and calls into `near_jsonrpc_primitives::message::from_slice`/`from_str` (`chain/jsonrpc-primitives/src/message.rs:269-271`) to parse it into a `Message`.

`Message`, `Request`, `Notification`, and `Response` all derive `serde::Deserialize` and carry a `params`/`result` field typed as `serde_json::Value` (`chain/jsonrpc-primitives/src/message.rs:51-57`, `:138-143`). `serde_json::Value`'s `Deserialize` implementation is naturally recursive: every `[` or `{` encountered pushes a new stack frame. There is no `recursion_limit` guard (e.g. no `serde_stacker` wrapping, no explicit depth counter) anywhere in this parsing path.

Because the body size limit is purely byte-count based (10MB), an attacker can submit a payload consisting of millions of nested `[` characters (`"[[[[[[..."`), each byte adding one level of nesting, well within the 10MB cap. Parsing this will recurse until the OS thread stack is exhausted. A stack overflow in Rust is not a catchable `panic!` — it triggers `SIGSEGV`/abort and takes down the entire process, not just the async task or connection handling it.

### Impact Explanation
Any unauthenticated RPC caller who can reach the node's JSON-RPC port (default `0.0.0.0:3030`, exposed on RPC nodes and validators that also serve RPC) can crash the node with a single HTTP POST request, with no valid signature, transaction, or account required. On a validator, this is a remotely triggerable denial-of-service that halts block production/validation for that node; broadly deployed it can be aimed at many public RPC endpoints simultaneously. This meets "a transaction-triggered halt" (more precisely, request-triggered) criterion.

### Likelihood Explanation
High likelihood: the entry point requires only an HTTP POST to the standard, publicly documented JSON-RPC endpoint (`/`), no credentials, no gas expenditure, no on-chain transaction, and no interaction with consensus logic. The payload is trivial to construct (repeated `[` characters) and stays within the default 10MB body-size limit.

### Recommendation
- Wrap the top-level `Message`/`Value` deserialization with a bounded-recursion deserializer (e.g. `serde_stacker::maybe_grow`, or a dedicated iterative/recursion-limited JSON parser) before calling into `serde_json` for untrusted request bodies in `chain/jsonrpc-primitives/src/message.rs::from_slice`.
- Alternatively/additionally, enforce an explicit maximum JSON nesting depth check on the raw bytes prior to full deserialization, and reject requests exceeding it with a `-32700` parse error.
- Apply the same protection to the Rosetta RPC server's `Json<...>` extractor path (`chain/rosetta-rpc/src/lib.rs`) and any other place accepting attacker-controlled `serde_json::Value` from the network (e.g. `chain/jsonrpc/src/api/mod.rs::Params::parse`).

### Proof of Concept
```
POST / HTTP/1.1
Host: <node>:3030
Content-Type: application/json
Content-Length: <~9_999_999>

[[[[[[[[[[[[[[[[[[[[ ... (millions of '[' characters, well under 10MB) ...
```
Sending this body to the JSON-RPC endpoint causes `near_jsonrpc_primitives::message::from_slice` (invoked from `rpc_handler()`) to recurse through `serde_json`'s `Value` deserializer for each `[`, exhausting the stack and crashing the node process before any `Message`/`Request` validation, method routing, or authentication occurs.
