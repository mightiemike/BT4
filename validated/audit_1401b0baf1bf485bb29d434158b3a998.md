### Title
`accrue` silently returns stale indexes when paused instead of reverting, allowing borrow/repay/liquidation to proceed on stale interest data - (File: `local-testing/contracts/vault/vault-stx.clar`)

### Summary
When a vault's `accrue` sub-flag is paused, `accrue` does not revert; it passes through and returns the last-known `index`/`lindex` as if they were current. Every public entrypoint (`redeem`, `system-borrow`, `deposit`, etc.) calls `(u (try! (accrue)))` expecting either a genuine `ok` with fresh values or a hard failure — but a paused accrual returns `ok` with stale values, so all downstream debt/liquidity math in that same transaction silently uses outdated indexes while behaving as if nothing is wrong.

### Finding Description
`accrue` reads the current pause-state map and, if the `accrue` sub-flag is set, returns `(ok { index: idx, lindex: lidx })` using the **currently stored** `index`/`lindex` values without recomputing `next-index`/`next-liquidity-index`, and — critically — without emitting any error or event indicating staleness: [1](#0-0) 

This is the "health check followed by a call that changes what it checked" / "pause that passes through instead of reverting" pattern: callers such as `system-borrow`, `redeem`, `deposit`, and `market.clar`'s `borrow`/`liquidate`/`collateral-add` flows treat `(try! (accrue))` as a guarantee that indexes are fresh, then immediately use `(var-get index)` and cached index values from `get-cached-indexes`/`accrue-and-cache` for interest, debt-cap, and health calculations in the very same call: [2](#0-1) 

Because `accrue-and-cache` in `market.clar` caches whatever `vault-accrue` (which calls this `accrue`) returns for the rest of the block/transaction, a paused-accrual vault poisons the market's per-timestamp cache with stale indexes for every subsequent operation in that same transaction/block: [3](#0-2) 

This mirrors the reported bug class exactly: a value (`index`/`lindex`, analogous to the NFT "shares" snapshot) is read and treated as authoritative by a subsequent check (health/borrow-cap check, analogous to `closeDistribution`'s funding check), but the source (real accrual) was silently bypassed by an administrative pause flag rather than being invalidated — the check is manipulated to pass on stale data instead of failing loudly.

### Impact Explanation
If `accrue` is paused on a vault while debt continues to exist, borrowers can `system-borrow` (via `market.borrow`) against a debt cap (`CAP-DEBT`) and health computations that use a frozen, understated `index`, letting debt accrue interest-free and letting the debt cap be bypassed relative to true outstanding debt; symmetrically, liquidations and repayments computed off the stale index misstate real debt/collateral value. This can result in temporary freezing of funds or lost interest/yield accounting (protocol reserve/treasury under-minting since `reserve-inc`/`treasury-lp` are never computed while paused), placing it in the High impact tier (temporary freezing of funds / theft of unclaimed yield/royalties to the treasury).

### Likelihood Explanation
This requires the `accrue` pause sub-flag to be set (an operator/admin action, not a DAO registry compromise), after which any ordinary user calling `borrow`, `repay`, `redeem`, or `liquidate` in the normal flow triggers the silent pass-through automatically — no attacker coordination or malicious input is needed, only the pre-existing pause state and a normal transaction.

### Recommendation
Make `accrue` fail loudly (return an error) when the `accrue` sub-flag is paused, rather than returning `ok` with stale values, so that all callers (`market.clar`, other vault entrypoints) are forced to halt rather than silently operate on outdated indexes; alternatively, gate the *specific* operations relying on freshness (`system-borrow`, `liquidate`-related calls) behind an explicit staleness check instead of trusting `try!` on `accrue` to guarantee freshness.

### Proof of Concept
1. Admin pauses only the `accrue` sub-flag on `vault-stx` (via `pause-states`) while leaving `borrow` unpaused.
2. Block time advances, so `next-index`/`next-liquidity-index` would normally increase debt owed.
3. A borrower calls `market.borrow` for `STX`; `market.clar`'s `accrue-and-cache` calls `vault-accrue` → `vault-stx.accrue`, which detects the `accrue` pause and returns the stale `{index: idx, lindex: lidx}` as `ok` [4](#0-3) .
4. `market.clar` caches this stale index for the rest of the transaction/block and uses it for the `CAP-DEBT` check inside `system-borrow` and for all health/notional calculations [5](#0-4) .
5. The debt cap and collateral health checks pass using understated debt, permitting a borrow that would fail (or be flagged unhealthy) under the true, unpaused index — analogous to how a mis-timed NFT-share update lets `closeDistribution`'s funding check pass on stale numbers.
