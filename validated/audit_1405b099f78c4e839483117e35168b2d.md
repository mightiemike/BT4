### Title
Missing input validation in `sanitizeHost` allows an unhandled exception (DoS) in unauthenticated auth-flow handlers via crafted `host` query parameter - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost` is meant to validate a Base64-encoded `host` parameter and return `null` (or optionally throw a controlled `InvalidHostError`) when the value is invalid. However, the function unconditionally decodes the Base64 payload and passes it directly into `new URL()` *before* the `throwOnInvalid` gate is evaluated. If the decoded content is not a syntactically valid URL/hostname (e.g., contains a space or other disallowed character), the native `URL` constructor throws an uncontrolled `TypeError`, bypassing the intended validation contract entirely — even for callers that explicitly pass (or default to) `throwOnInvalid = false` expecting a graceful `null` return.

### Finding Description [1](#0-0) 

```ts
export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;
    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`); // <-- unguarded throw
      ...
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }
    return sanitizedHost;
  };
}
```

`decodeHost` is a thin `atob()` wrapper [2](#0-1) . The Base64 regex only restricts the *character set* of the input, not the semantic validity of the decoded string. An attacker can supply a `host` value that is valid Base64 (passes the regex) but decodes to a string that is not a legal URL/hostname (e.g., containing a space, backslash, or other reserved character). `new URL('https://' + decoded)` then throws a raw `TypeError`, which is never caught inside `sanitizeHost` — completely independent of the `throwOnInvalid` flag.

This function is called from multiple **unauthenticated** request-processing code paths that only guard against a `null` return, not an exception:
- `validateShopAndHostParams` in the Remix admin auth flow, invoked at the very start of `ensureInstalledOnShop` for any document request with a `shop`/`host` query string, before any session/auth check [3](#0-2) 
- `redirectToShopifyOrAppRoot` (Remix) and the equivalent Express middleware, called right after OAuth callback [4](#0-3) [5](#0-4) 
- `redirectWithExitIframe` (Remix) [6](#0-5) 
- `clientSideRedirect` in Express `redirectToAuth` [7](#0-6) 
- `buildEmbeddedAppUrl` / `getEmbeddedAppUrl` [8](#0-7) 

None of these call sites wrap the `sanitizeHost` invocation in a `try/catch`; they only check `if (!host)`. None of the existing unit tests exercise a Base64 string that decodes to an invalid hostname (only strings that fail the regex or fail the origin allow-list are tested) [9](#0-8) , so this gap is not currently caught by test coverage.

This is structurally analogous to ASA-2024-003: input that "looks" superficially acceptable (passes a shallow format check) is allowed to flow into logic that assumes stronger invariants, producing an unhandled failure/crash in code paths that other components rely on behaving safely (there, `GetModuleAccount`/`BeginBlock`; here, `authenticate.admin`/OAuth handlers).

### Impact Explanation
An anonymous request (no session, no prior authentication) that hits the app's OAuth/admin-auth entry points with a crafted `host` query parameter can trigger an uncaught `TypeError` deep in library code that request-handling code does not expect and does not catch. Depending on the runtime adapter (Express, Remix loader, Cloudflare Worker, etc.), this manifests as an unhandled exception/rejected promise in the request pipeline — a Denial-of-Service condition against the app's authentication handler for that request, and in adapters without global error boundaries it can produce 500s or process-level unhandled rejection warnings/crashes rather than the intended clean `400`/redirect response.

### Likelihood Explanation
High reachability: the `host` parameter is attacker-controlled and read directly from the URL query string on unauthenticated routes (`/auth`, `/`, the exit-iframe/bounce-page routes) before any session exists. Constructing a Base64 string that decodes to an invalid hostname (e.g., containing a space) is trivial and requires no special privileges.

### Recommendation
Wrap the `new URL(...)` construction in `sanitizeHost` in a `try/catch`, treating a parse failure the same as a regex mismatch (`sanitizedHost = null`), and only then apply the `throwOnInvalid` gate for `InvalidHostError`. Add regression tests using Base64-encoded strings whose decoded value is not a valid URL/hostname (e.g., containing spaces or backslashes) to ensure `sanitizeHost` degrades to `null`/`InvalidHostError` instead of leaking a raw `TypeError`.

### Proof of Concept
1. Compute a Base64 string whose decoded value is not a valid hostname, e.g. `Buffer.from('hello world/admin').toString('base64')` → `aGVsbG8gd29ybGQvYWRtaW4=`.
2. Send an unauthenticated request to the app's admin entry route with this value, e.g.:
   `GET /?shop=my-shop.myshopify.com&host=aGVsbG8gd29ybGQvYWRtaW4=`
3. This reaches `validateShopAndHostParams` → `api.utils.sanitizeHost(...)` → `new URL('https://hello world/admin')`, which throws a `TypeError` that propagates uncaught out of `ensureInstalledOnShop`/the Remix loader instead of the expected `400`/login redirect.

```typescript
export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }

    return sanitizedHost;
  };
}
```

```typescript
export function validateShopAndHostParams(
  params: BasicParams,
  request: Request,
) {
  const {api, config, logger} = params;

  if (config.isEmbeddedApp) {
    const url = new URL(request.url);
    const shop = api.utils.sanitizeShop(url.searchParams.get('shop')!);
    if (!shop) {
      logger.debug('Missing or invalid shop, redirecting to login path', {
        shop,
      });
      throw redirectToLoginPath(request, params);
    }

    const host = api.utils.sanitizeHost(url.searchParams.get('host')!);
    if (!host) {
      logger.debug('Invalid host, redirecting to login path', {
        shop,
        host: url.searchParams.get('host'),
      });
      throw redirectToLoginPath(request, params);
    }
  }
```
