### Title
Unauthenticated `batchProver_setCommitments` and `batchProver_submitFakeProof` JSON-RPC methods allow arbitrary mutation of the batch prover's node state - (File: crates/batch-prover/src/rpc.rs)

### Summary
The `MSCProposeHelper.proposeSetConsensusTargetRate` bug class is "an externally-callable, state-mutating function with no access-control modifier." The closest reachable analog in this repository is the batch prover's JSON-RPC surface: `batchProver_setCommitments` and `batchProver_submitFakeProof` are registered as regular RPC methods with no caller restriction, while Citrea's own RPC `Auth` middleware only gates three unrelated methods (`backup_create`, `backup_validate`, `backup_info`).

### Finding Description
`BatchProverRpc::set_commitments` is implemented to directly overwrite ledger-DB sequencer commitments with attacker-supplied `merkle_root`, `index`, and `l2_end_block_number` values, bypassing every validation that the normal DA-ingestion path performs (sender/public-key check, ordering, dependency checks): [1](#0-0) 

Compare this to the legitimate path in `da_block_handler.rs`, where a `SequencerCommitment` is only accepted after checking it was signed by the sequencer's DA public key and that it doesn't conflict with an existing/pending entry: [2](#0-1) 

`submit_fake_proof` similarly lets any caller force the node to fabricate a `BatchProofCircuitOutput`, wrap it in a risc0 `FakeReceipt`, and broadcast it to the DA layer as a `DaTxRequest::ZKProof`: [3](#0-2) 

Both methods are declared in the same `#[rpc(...)]` trait as all other unauthenticated batch-prover endpoints: [4](#0-3) 

The RPC-wide `Auth` middleware only protects three backup-related method names and passes every other method straight through: [5](#0-4) 

### Impact Explanation
If the batch prover's RPC endpoint is reachable (no `api_key` configured, or the operator did not firewall the port — the code provides no default protection for these methods), any unauthenticated caller can:
- Overwrite the batch prover's local record of sequencer commitments (`put_commitment_by_index`) with attacker-chosen data, corrupting the local view used to select proving ranges and answer RPC queries (`getCommitmentIndicesByL1`, `getProvingJobOfCommitment`, etc.).
- Trigger `submitFakeProof`, which spends the operator's DA wallet funds to broadcast a bogus proof transaction to Bitcoin.

This does not break the cross-repo `equality` for a **false state transition proved** — a `FakeReceipt` is not a real STARK/RISC0 proof, so the Light Client Proof circuit's method-ID verification (`BatchProofMethodIdAccessor`/proof verification in `LightClientProofCircuit::run_l1_block`) will reject it, and the light-client's `SequencerCommitmentAccessor` state is populated only from DA-signed sequencer commitments, not from the prover's local ledger DB, so the injected fake commitment cannot itself corrupt the proved L2 root. Thus the worst confirmed effect is state corruption/resource waste on the batch prover's own node (an "unauthenticated JSON-RPC call that mutates node state," High-tier per the rubric), not a Critical bridge-value or consensus-root compromise.

### Likelihood Explanation
Likelihood depends entirely on RPC exposure, which is deployment-specific (`rpc_config.api_key`, `bind_host`). All reference configs found in this repo's `resources/configs/**` bind to loopback-style hosts by default, and exposing the batch prover's RPC unauthenticated to the public internet would be a deployment/configuration choice, not a code defect forced by this repo. Per the validation rules, "analogs that depend on a deployment ignoring the documented configuration" are out of scope for a Critical finding; I could not find code-level evidence that the endpoints are enforced to be restricted (unlike the three `PROTECTED_METHODS`), which is a legitimate defense-in-depth gap but not a certain, code-forced exploit path in typical deployments.

### Recommendation
Add `batchProver_setCommitments`, `batchProver_submitFakeProof`, and other state-mutating debug/ops RPC methods (`pauseProving`, `prove`, `retryProvingJob`) to the `PROTECTED_METHODS` list in `crates/common/src/rpc/auth.rs`, or otherwise gate them behind the existing `api_key` mechanism, so they require authentication like `backup_create`/`backup_validate`/`backup_info` do today.

### Proof of Concept
Given a batch prover node with RPC reachable and no `api_key` configured, an unauthenticated client can call:
```
curl -X POST http://<batch-prover-rpc>:<port> \
  -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"batchProver_setCommitments","params":[[{"merkleRoot":"0x00..","index":"0x5","l2EndBlockNumber":"0x64"}]]}'
```
This overwrites the ledger-DB commitment for index 5 with arbitrary attacker-supplied data via [1](#0-0)  with no signature or authorization check, unlike the DA-sourced ingestion path in [2](#0-1) .

                commitment.l2_end_block_number,
                l1_height,
            );

            self.context
                .ledger_db
                .put_commitment_by_index(&commitment)
                .map_err(internal_rpc_error)?;
            // This might cause some duplicate commitment indices appear in l1 -> index table which is ok
            self.context
                .ledger_db
                .put_commitment_index_by_l1(SlotNumber(l1_height), commitment.index)
                .map_err(internal_rpc_error)?;
            self.context
                .ledger_db
                .put_prover_pending_commitment(commitment.index)
                .map_err(internal_rpc_error)?;
        }

        Ok(())
    }

    async fn submit_fake_proof(
        &self,
        index_start: u32,
        index_end: u32,
    ) -> RpcResult<BatchProofResponse> {
        info!(
            "Submitting fake proof for commitment index range [{},{}]",
            index_start, index_end
        );

        let ledger_db = &self.context.ledger_db;

        if index_start > index_end {
            return Err(internal_rpc_error("Invalid index range"));
        }
        // don't allow first commitment index to be called through this rpc as it requires extra handling
        if index_start <= 1 {
            return Err(internal_rpc_error(
                "submitFakeProof rpc supports only index_start > 1",
            ));
        }

        let previous_commitment = ledger_db
            .get_commitment_by_index(index_start - 1)
            .map_err(internal_rpc_error)?
            .ok_or_else(|| internal_rpc_error("Missing previous commitment index"))?;

        let commitments = ledger_db
            .get_commitment_by_range(index_start..=index_end)
            .map_err(internal_rpc_error)?;
        if commitments.len() as u32 != index_end - index_start + 1 {
            return Err(internal_rpc_error(
                "Missing some commitment indices from the range",
            ));
        }

        let last_commitment = commitments.last().expect("Already ensured");
        let last_l2_block = ledger_db
            .get_l2_block_by_number(&L2BlockNumber(last_commitment.l2_end_block_number))
            .map_err(internal_rpc_error)?
            .ok_or_else(|| internal_rpc_error("Not synced up to latest L2 block yet"))?;

        let initial_state_root = ledger_db
            .get_l2_state_root(previous_commitment.l2_end_block_number)
            .map_err(internal_rpc_error)?
            .expect("Initial L2 state root must exist");

        let mut start_l2_height = previous_commitment.l2_end_block_number + 1;
        let mut sequencer_commitment_hashes = Vec::with_capacity(commitments.len());
        let mut state_roots = Vec::with_capacity(commitments.len() + 1);
        state_roots.push(initial_state_root);

        let mut cumulative_state_diff = CumulativeStateDiff::new();
        for commitment in commitments.iter() {
            let end_l2_height = commitment.l2_end_block_number;

            for l2_height in start_l2_height..=end_l2_height {
                let state_diff = ledger_db
                    .get_l2_state_diff(L2BlockNumber(l2_height))
                    .map_err(internal_rpc_error)?
                    .expect("L2 state diff must exist");
                cumulative_state_diff.extend(state_diff);
            }

            sequencer_commitment_hashes.push(commitment.serialize_and_calculate_sha_256());

            let end_state_root = ledger_db
                .get_l2_state_root(end_l2_height)
                .map_err(internal_rpc_error)?
                .expect("L2 state root must exist");
            state_roots.push(end_state_root);

            start_l2_height = end_l2_height + 1;
        }

        let storage = self
            .context
            .storage_manager
            .create_storage_for_l2_height(last_l2_block.height + 1);
        let last_l1_hash_on_contract = get_last_l1_hash_on_contract::<DefaultContext>(
            Default::default(),
            storage,
            &mut Default::default(),
            [0; 32],
        );

        let output = BatchProofCircuitOutput::V3(BatchProofCircuitOutputV3 {
            state_roots,
            final_l2_block_hash: last_l2_block.hash,
            state_diff: cumulative_state_diff,
            last_l2_height: last_l2_block.height,
            sequencer_commitment_hashes,
            sequencer_commitment_index_range: (index_start, index_end),
            last_l1_hash_on_bitcoin_light_client_contract: last_l1_hash_on_contract,
            previous_commitment_index: Some(previous_commitment.index),
            previous_commitment_hash: Some(previous_commitment.serialize_and_calculate_sha_256()),
        });

        let output_serialized = borsh::to_vec(&output).expect("Output serialization cannot fail");

        let spec_id = fork_from_block_number(last_l2_block.height).spec_id;
        let method_id: [u32; 8] = self
            .context
            .code_commitments
            .get(&spec_id)
            .expect("Spec for L2 block must exist")
            .clone()
            .into();

        let claim = MaybePruned::Value(ReceiptClaim::ok(method_id, output_serialized));
        let fake_receipt = FakeReceipt::new(claim);
        // Receipt with verifiable claim
        let receipt = InnerReceipt::Fake(fake_receipt);
        let proof = bincode::serialize(&receipt).expect("Receipt serialization cannot fail");

        let tx_id = self
            .context
            .da_service
            .send_transaction(DaTxRequest::ZKProof(proof.clone()))
            .await
            .map_err(internal_rpc_error)?;

        Ok(BatchProofResponse {
            l1_tx_id: Some(tx_id.into()),
            proof,
            proof_output: StoredBatchProofOutput::from(output).into(),
            info: None,
        })
    }

const PROTECTED_METHODS: [&str; 3] = ["backup_create", "backup_validate", "backup_info"];

#[derive(Debug, Clone)]
pub struct Auth<S> {
    service: S,
    api_key: Option<String>,
}

impl<S> Auth<S> {
    pub fn new(service: S, api_key: Option<String>) -> Self {
        Self { service, api_key }
    }
}

impl<'a, S> RpcServiceT<'a> for Auth<S>
where
    S: RpcServiceT<'a> + Send + Sync + Clone + 'a,
{
    type Future = BoxFuture<'a, MethodResponse>;

    fn call(&self, req: Request<'a>) -> Self::Future {
        let method = req.method_name();
        let service = self.service.clone();
        let api_key = self.api_key.clone().map(Value::from);

        if !PROTECTED_METHODS.contains(&method) {
            return Box::pin(service.call(req));
