### Title
`check_microblock_header_signer` and the PoisonMicroblock header-equality check compare raw struct equality (including the non-semantic `signature` field) instead of `tx_merkle_root`, allowing a re-signed (not re-forked) microblock header pair to be accepted as a valid equivocation proof - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`StacksChainState::check_microblock_header_signer` (stackslib/src/chainstate/stacks/db/transactions.rs:686-713) only asserts that both headers recover to the same public key hash; it never compares `tx_merkle_root` or otherwise asserts semantic divergence. The upstream codec-level guard against duplicate headers (exercised by the `tx_stacks_transaction_payload_microblock_poison` test in stacks-codec/src/transaction.rs:3776-3842) only rejects headers that are *byte-for-byte identical*, including the `signature` field, which is not semantically meaningful to the equivocation claim.

### Finding Description
The equality that should hold to preserve "no genuine equivocation ⇒ no valid slash" is:

`same_sequence && (tx_merkle_root_1 == tx_merkle_root_2) ⇒ PoisonMicroblock must be rejected`

But the code actually enforces only:

`mblock_hdr_1 == mblock_hdr_2 (full struct incl. signature) ⇒ reject as "headers match"`
`pkh1 == pkh2 ⇒ accept as valid poison` [1](#0-0) 

Because `StacksMicroblockHeader::sign` (stacks-codec/src/transaction.rs:2570-2583) recomputes an ECDSA signature over the digest with the signature field zeroed, and ECDSA signing is not guaranteed to be deterministic across separate signing calls (nonce reuse is not enforced), signing the *same* header content twice (e.g., re-signing on resend, or a network relay that re-serializes and re-signs the identical microblock) yields two headers that are:
- Identical in `version`, `sequence`, `prev_block`, `tx_merkle_root`
- Different only in `signature` bytes
- Both recoverable to the same `pkh` via `check_recover_pubkey` (stacks-codec/src/transaction.rs:2598-2616), because `check_recover_pubkey` strips the signature field itself before hashing and only uses it to recover the key [2](#0-1) 

Such a pair passes the codec-level "headers match" rejection (struct equality fails due to differing signature bytes), passes fork-identification since `sequence` is identical, and passes `check_microblock_header_signer`'s `pkh1 == pkh2` check — despite there being no genuine divergent commitment (`tx_merkle_root_1 == tx_merkle_root_2`). `handle_poison_microblock` (stackslib/src/chainstate/stacks/db/transactions.rs:722-804) then proceeds to record a poison report and eventually penalizes the miner's reward at maturity, with no additional check anywhere in this path that verifies the two `tx_merkle_root` values actually differ. [3](#0-2) 

The test suite only validates: (1) a genuine fork (different `tx_merkle_root`, different `signature`, same `sequence`) is accepted; (2) fully identical headers (including identical signature) are rejected; (3) inconsistent sequence/prev_block combos are rejected as not identifying a fork. None of the existing tests cover the case of identical `tx_merkle_root`/`prev_block`/`sequence` with merely a different `signature`, so this gap is not caught by existing guards. [4](#0-3) 

### Impact Explanation
Because the deserialization/validation logic is fully deterministic and applied identically by every node, both honest nodes and the attacker's node reach the same (wrong) verdict — this does **not** produce a chain split or state-root divergence. It does, however, allow an attacker (any account, not requiring majority stake) to submit a PoisonMicroblock transaction that falsely proves equivocation against a miner who never actually created two divergent microblock forks, but merely had a header re-signed (network relay malleability, resend after a benign restart, etc.). This causes the targeted miner's future coinbase/microblock reward to be wrongfully forfeited once the poison report matures — a real, but fee/reward-bounded, mis-payment. This matches the "High — a poison or reward mis-payment bounded to fees" category, not Critical (no chain split, no invalid block acceptance, no double payment).

### Likelihood Explanation
Exploitation requires only: (1) observing two independently-signed wire copies of the same logical microblock header content (obtainable by any network participant who relays microblocks, or by simply resending/re-serializing one's own microblock with a fresh non-deterministic signature), and (2) submitting a `PoisonMicroblock` transaction referencing both. No majority stake, no signer key compromise, and no privileged role are needed — a minority/unprivileged actor can trigger it. The main precondition is that the target miner's signing implementation does not produce deterministic (RFC6979-style) ECDSA signatures for identical digests across separate `sign()` invocations, which is plausible for any resend/re-issuance path that re-runs `StacksMicroblockHeader::sign`.

### Recommendation
In `check_microblock_header_signer` (or in `handle_poison_microblock` immediately after it), add an explicit assertion that `mblock_header_1.tx_merkle_root != mblock_header_2.tx_merkle_root` (or, more generally, that the two headers commit to different transaction sets) when `sequence` values are equal, rejecting the PoisonMicroblock transaction as invalid if the merkle roots match despite the headers otherwise differing only in `signature`. This restores the intended semantics that a poison-microblock proof must show a genuine content-level equivocation, not merely two syntactically-distinct signed byte strings.

```rust
// stackslib/src/chainstate/stacks/db/transactions.rs (test module)
#[test]
fn poison_microblock_false_positive_on_resign() {
    let privk = StacksPrivateKey::new();
    let pubk = StacksPublicKey::from_private(&privk);
    let pkh = Hash160::from_node_public_key(&pubk);

    let base_header = StacksMicroblockHeader {
        version: 0,
        sequence: 5,
        prev_block: BlockHeaderHash([0x11; 32]),
        tx_merkle_root: Sha512Trunc256Sum::from_data(&[1,2,3]),
        signature: MessageSignature::empty(),
    };

    // Sign the SAME content twice -- simulates resend / relay re-signing.
    let mut header_1 = base_header.clone();
    header_1.sign(&privk).unwrap();

    let mut header_2 = base_header.clone();
    header_2.sign(&privk).unwrap();

    // Assert both sides of the claimed equality:
    assert_eq!(header_1.tx_merkle_root, header_2.tx_merkle_root); // no genuine fork
    assert_ne!(header_1.signature, header_2.signature);           // differ only in sig (non-deterministic ECDSA)

    // This should be REJECTED because there is no genuine equivocation,
    // but with current code it is ACCEPTED because pkh1 == pkh2.
    let result = StacksChainState::check_microblock_header_signer(&header_1, &header_2);
    assert!(result.is_err(), "expected rejection: identical tx_merkle_root is not a genuine equivocation, but check_microblock_header_signer accepted it");
}
```
This test currently fails (the call succeeds and returns `Ok(pkh)`) with the existing implementation, confirming the false-positive poison acceptance path.

```rust
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {

                format!("Failed to recover public key: {:?}", &e),
                false,
            )

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
```

```rust
    pub fn check_recover_pubkey(&self) -> Result<Hash160, AuthError> {
        let mut bytes = vec![];
        self.serialize(&mut bytes, true)
            .expect("BUG: failed to serialize to a vec");
        let digest = Sha512Trunc256Sum::from_data(&bytes[..]);

        let mut pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            digest.as_bytes(),
            &self.signature,
        )
        .map_err(|_ve| {
            AuthError::VerifyingError(
                "Failed to verify signature: failed to recover public key".to_string(),
            )
        })?;

        pubk.set_compressed(true);
        Ok(Hash160::from_node_public_key(&pubk))
    }
```
