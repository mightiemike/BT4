Self-referential quote-then-swap slippage protection allows MEV/sandwich extraction on gas top-up auto-swaps - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Push Chain's `x/uexecutor` module executes `GAS`/`GAS_AND_PAYLOAD` inbound top-ups and excess-gas refunds by swapping a user's bridged PRC20 into native PC via the UniversalCore/UniswapV3 `depositPRC20WithAutoSwap` path. The "slippage protection" (`minPCOut = quote * 95 / 100`) is derived from a spot quote (`QuoterV2.quoteExactInputSingle`) fetched from the same pool in the very same keeper call, immediately before the swap executes with `commit=true`. Because the bound is computed from the same manipulable, single-block price source it is meant to protect against, an unprivileged attacker can move the pool price right before this internal call lands (sandwich), causing the protocol's own swap to execute against a temporarily-depressed price while still satisfying its self-generated 5% tolerance — exactly the missing-slippage-protection bug class in the referenced report, just realized as a "cosmetic" bound instead of a hardcoded 0.

### Finding Description
The relevant call chain is:
- `k.GetUniversalCoreQuoterAddress` / `GetUniversalCoreWPCAddress` / `GetDefaultFeeTierForToken` — static reads.
- `k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)` [1](#0-0)  calls `QuoterV2.quoteExactInputSingle` via `CallEVM` (a static, non-committing simulation against current chain-tip state).
- The result is immediately turned into `minPCOut = quote * 95 / 100` and passed straight into `CallPRC20DepositAutoSwap`, which performs the real, state-committing swap in the same function invocation: [2](#0-1) 

The identical pattern is repeated for `GAS_AND_PAYLOAD` inbounds: [3](#0-2) 

And again for excess-gas refunds on outbound finalization: [4](#0-3)  using `getSwapQuoteForRefund` [5](#0-4) .

In every one of these three call sites, the "min output" used to bound the swap is computed from the *exact same pool query* used moments later to execute the swap, within a single Cosmos transaction/block. There is no independent price reference (TWAP, external oracle, chain-meta price, or governance-set band) — the quote is a live spot price read of a Uniswap-V3-style pool that the module itself does not control liquidity for. This is architecturally the same failure mode the external report describes: an attacker (any ordinary EVM user submitting transactions against the same pool, e.g. a large swap in the same block or via priority-fee ordering ahead of the validator-triggered inbound finalization) can push the pool's spot price down immediately before this code runs, causing `GetSwapQuote` to return a depressed `quote`. The subsequent `minPCOut = quote * 95%` is depressed in lockstep, so the real swap still "succeeds" against the manipulated price and the attacker captures the difference by reversing their position after the module's swap executes (classic sandwich). Because inbound finalization is deterministic and driven by quorum votes reaching the ballot threshold on `MsgVoteInbound`, an attacker watching the mempool/ballot state can predict the exact block in which this swap will fire and time the sandwich precisely — this requires no validator, TSS, or admin privilege, only ordinary EVM transaction submission against the pool referenced by `uniswapV3Quoter`/`defaultFeeTier`.

This directly maps to the "Registry and accounting path" and "Universal execution path" invariants in scope: it corrupts PRC20/native asset accounting and can result in unauthorized value extraction from a user- and protocol-controlled swap that is supposed to deliver PC to a user's UEA (gas top-up) or back to the sender (refund).

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound, and every outbound excess-gas refund with a non-zero `GasToken`, routes bridged value through this quote-then-swap pattern. A successful sandwich siphons value out of the swap that would otherwise have gone to the recipient (the user's UEA for gas top-ups, or the sender/fund-recipient for refunds), constituting a loss of user-controlled funds reachable purely through the default inbound/outbound execution path — no privileged actor is required. Because `defaultFeeTier`/pool liquidity is presumably shallow for at least some PRC20/gas tokens (illiquid bridged assets), the achievable extraction as a percentage of swap size can be significant, up to the full 5% tolerance per swap, repeatable on every inbound/outbound that triggers the auto-swap path.

### Likelihood Explanation
Likelihood is high for an economically motivated attacker: no special access is needed, only the ability to submit ordinary EVM transactions against the referenced Uniswap pool and observe/predict when `MsgVoteInbound`/`MsgVoteOutbound` quorum will be reached (public chain state). This is the same MEV/sandwich risk class explicitly called out in the source report (referencing Jito on Solana); on an EVM-compatible Cosmos chain the equivalent is mempool-visible transaction ordering/front-running, which is a well-established and continuously exploited pattern on similar chains.

### Recommendation
Do not derive the slippage bound from the same instantaneous quote that will immediately execute the swap. Instead:
- Use a manipulation-resistant reference price (e.g., a TWAP from the pool's observation window, or the chain-meta/oracle gas price already tracked by `x/uexecutor`) to bound `minPCOut`, independent of the spot quote used to size the trade.
- Alternatively, widen the effective protection by capping per-swap notional value and/or routing only through pools with governance-vetted minimum liquidity, and add a maximum allowed price-impact check comparing the quoted price against a recent moving average.
- Consider allowing configurable, tighter slippage tolerance (not hardcoded 5%) tunable per token via governance, and emit/verify that `sqrtPriceX96After` from the quote does not deviate excessively from a trusted reference before committing the swap.

### Proof of Concept
1. Monitor pending `MsgVoteInbound` transactions for a `GAS`/`GAS_AND_PAYLOAD` inbound (or watch ballot vote counts via `x/uvalidator` queries) to predict the block in which quorum will be reached and `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` will fire.
2. Immediately before that block, submit a large swap on the referenced Uniswap V3 pool (`prc20AssetAddr` → `WPC`) to depress the spot price, using a fee-competitive transaction to land ahead of/alongside the finalizing vote.
3. When the module executes, `GetSwapQuote` [1](#0-0)  returns a depressed `quote`; `minPCOut = quote*95/100` is computed from this depressed value [6](#0-5) , so `CallPRC20DepositAutoSwap` executes the real swap at the manipulated price without reverting.
4. Immediately after, reverse the initial swap to restore the pool price, realizing a profit equal to the price impact extracted from the protocol-initiated swap, at the expense of the recipient UEA/sender who receives less PC than fair value.

Note: I could not verify from the indexed code alone whether `MsgVoteInbound`/`MsgVoteOutbound` execution ordering within a block gives an attacker deterministic control over transaction ordering relative to their own sandwich transactions (this depends on the underlying Cosmos-EVM mempool/block-building rules, which were not fully covered by the available index). If block proposers process transactions in strict submission/priority-fee order (typical for cosmos-evm chains), the PoC as described is directly reachable by an unprivileged actor; a Devin session should confirm mempool ordering guarantees to fully validate exploitability degree.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
