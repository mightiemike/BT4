## Analysis

The external report describes a classic AMM-price-manipulation bug: a strategy fetches a spot exchange rate from a Curve pool and immediately uses that same (manipulable) rate to bound a deposit/withdraw, letting a same-transaction/flash-loan actor skew the pool and extract value before the price reverts.

Push Chain's `x/uexecutor` GAS and GAS_AND_PAYLOAD inbound routes contain the same pattern, but sourced from a Uniswap V3 pool on Push Chain's own EVM instead of Curve.

### Title
Unprotected spot-price slippage bound in `depositPRC20WithAutoSwap` allows AMM price manipulation to drain the protocol's Uniswap V3 PRC20/WPC pool - (File: `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
When processing a `GAS` or `GAS_AND_PAYLOAD` inbound, `x/uexecutor` computes `minPCOut` — the slippage floor for an on-chain autoswap of the bridged PRC20 asset into WPC — directly from a live `QuoterV2.quoteExactInputSingle` call against the same Uniswap V3 pool that the swap itself will execute against, with no TWAP or external price reference. [1](#0-0) [2](#0-1) 

### Finding Description
`ExecuteInboundGas` (and the equivalent `gasAndPayloadDepositAutoSwap` helper for `GAS_AND_PAYLOAD`) resolves the swap parameters as follows:
1. `GetUniversalCoreQuoterAddress` / `GetUniversalCoreWPCAddress` / `GetDefaultFeeTierForToken` fetch the pool's Uniswap V3 quoter, WPC address, and fee tier.
2. `GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96 = 0`, which simulates the swap against the **current** pool state (spot price, no TWAP).
3. `minPCOut` is derived as `quote * 95 / 100` — a 5% slippage tolerance computed from that same spot quote.
4. `CallPRC20DepositAutoSwap` then performs the actual `depositPRC20WithAutoSwap` call using this `minPCOut`. [3](#0-2) [4](#0-3) 

Both the "reference price" and the "protection bound" are computed from the identical manipulable pool state, immediately before executing a real swap against that same pool. An unprivileged actor can:
1. Submit large swaps against the PRC20/WPC Uniswap V3 pool on Push Chain (e.g., dump WPC for PRC20 or vice versa) to skew the spot price shortly before the inbound's finalizing vote is processed.
2. Because `VoteInbound` execution is triggered by the last-needed Universal Validator's `MsgVoteInbound`, whose exact block/ordering is externally observable, the attacker can time their manipulation to land in the same or an adjacent block relative to `ExecuteInboundGas`'s quote+swap sequence.
3. `GetSwapQuote` reflects the manipulated price, `minPCOut` is derived from that same manipulated price (self-referential, not an independent bound), so the on-chain autoswap executes at the skewed rate with no defense.
4. The attacker then reverses their manipulating trade, extracting the difference from the protocol-funded Uniswap V3 pool at the expense of the recipient (who receives less WPC than fair value) or the pool liquidity itself.

This is architecturally identical to the reported bug class: a DeFi routine trusts a same-pool, same-transaction spot price as its own safety bound instead of using an independent, time-weighted, or externally-validated price.

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound that routes through `CallPRC20DepositAutoSwap` is exposed. Value is extracted from the Uniswap V3 pool (and/or from the intended recipient's expected WPC proceeds), which is a form of unauthorized fund drain reachable from an ordinary, unprivileged attacker performing default swap transactions on the pool plus normal cross-chain deposit submission — squarely in scope under "corruption of PRC20 or native asset accounting ... reachable from ordinary user deposits ... alone."

### Likelihood Explanation
Likelihood is high for any pool with moderate-to-thin liquidity: the attacker needs no privileged role, no validator collusion, and no cross-chain flash loan — only capital to move the Push Chain-native Uniswap V3 pool and the ability to submit or observe a GAS/GAS_AND_PAYLOAD inbound landing near their manipulation. The 5% band derived from the same manipulated quote provides essentially no protection against this class of attack, unlike a true external/TWAP-based bound.

### Recommendation
Do not derive the slippage floor from the same instantaneous quote used to execute the swap. Use a TWAP price (Uniswap V3 `observe`), an independent oracle, or a validator-attested/median price similar to the existing `ChainMeta` gas-price median mechanism, and validate the realized swap output against that independent reference rather than a self-referential same-pool quote.

### Proof of Concept
Conceptual sequence (no live PoC executed, based on code trace):
1. Attacker holds/acquires PRC20 and WPC and executes a large swap against the Uniswap V3 pool referenced by `UniversalCore.uniswapV3Quoter`/`WPC`, skewing the pool price.
2. Attacker (or an accomplice) submits or triggers finalization of a `GAS`/`GAS_AND_PAYLOAD` inbound so that `ExecuteInboundGas` runs `GetSwapQuote` → `minPCOut = quote*95/100` → `CallPRC20DepositAutoSwap` while the pool is still skewed. [5](#0-4) 
3. The autoswap executes at the manipulated price (bounded only by the same manipulated quote), producing fewer WPC tokens for the recipient / a worse rate for the protocol-held pool than an honest spot price would.
4. Attacker reverses their initial swap, restoring the pool and capturing the price-impact spread as profit, funded by the pool's liquidity or the shortfall imposed on the recipient.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
