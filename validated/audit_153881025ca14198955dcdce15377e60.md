## Finding

### Title
`TransactionOutput::ensure_match_transaction_info` never checks the state/hot-state/position checkpoint root hashes, letting replay-verification tools accept corrupted state roots as valid - (File: `types/src/transaction/mod.rs`)

### Summary
The bug-class analog here is "a verification step that is supposed to gate acceptance of a derived/committed value silently omits the one invariant that actually protects state integrity, letting a corrupted value pass as verified." In the Aave report this was the cooldown-window check; the Aptos-native analog is the transaction-info/replay verification helper that omits checking the Merkle state-checkpoint root.

### Finding Description
`TransactionOutput::ensure_match_transaction_info` is the function used to assert that a freshly (re-)computed `TransactionOutput` matches an already-authenticated `TransactionInfo` (the object committed into the transaction accumulator and covered by `LedgerInfo` signatures). It checks status, gas used, write-set hash (`state_change_hash`), and event root hash, but it explicitly does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` — the fields that summarize the entire Sparse-Merkle-Tree/world-state root at that version: [1](#0-0) 

The code itself documents the gap: [2](#0-1) 

This function is the *only* correctness check performed by `storage/db-tool/src/replay_on_archive.rs`, a tool whose entire purpose is to replay archived transactions through the VM and confirm the result matches the authenticated on-chain record: [3](#0-2) 

Unlike the main chunk-executor pipeline (`execution/executor/src/chunk_executor/mod.rs`), which routes execution output through `DoStateCheckpoint::run`/`get_state_checkpoint_hashes` and explicitly compares the locally-recomputed SMT root against the `known_state_checkpoints`/`known_hot_state_checkpoints`/`known_position_state_checkpoints` taken from the trusted `TransactionInfo`s: [4](#0-3) [5](#0-4) 

`replay_on_archive.rs` calls `executor.execute_block(...)` directly and only compares outputs via `ensure_match_transaction_info` — it never constructs a `StateCheckpointOutput`/`DoStateCheckpoint` pass, so the state-checkpoint root comparison in `get_state_checkpoint_hashes` never runs for this tool at all.

### Impact Explanation
Because `ensure_match_transaction_info` never inspects `state_checkpoint_hash` (nor the hot-state/position-state variants), `replay_on_archive` can report a transaction range as "successfully replayed/verified" even when the recomputed world-state root (Sparse Merkle Tree root, hot-state root, or position-state root) diverges from the value bound into the authenticated `TransactionInfo`/`LedgerInfo`. Since this tool exists specifically to validate that archived/committed ledger data matches independent VM re-execution (a restore/audit-integrity flow), a real state-computation or storage bug (e.g., in JMT/hot-state/position-state root derivation, or in tampered archive data) that changes only the state root while leaving write-set bytes, gas, status, and events unchanged would go completely undetected — the tool would falsely certify state that differs from the correct VM result as valid. This is a state-commitment/proof-integrity gap in a restore/verification pathway, not a consensus-halting bug, but it defeats the one tool meant to catch exactly this class of corruption.

### Likelihood Explanation
The gap is unconditional and always present in `ensure_match_transaction_info` — it requires no attacker interaction to trigger, only that a genuine state-root divergence exists somewhere in the state-checkpoint computation for the chunk being replayed. Any bug in the periodic checkpoint/state-summary logic (hot state, position state “trading native” roots, JMT updates, etc.) or any corruption of archived data that leaves write-sets/events/status intact but changes the checkpoint root will silently pass through `replay_on_archive`'s verification. The TODO comment in the code confirms the authors are aware this must be fixed before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled, but the check is also missing for the ordinary `state_checkpoint_hash`/`hot_state_checkpoint_hash` fields today, not just the position-state case.

### Recommendation
Extend `ensure_match_transaction_info` to accept and compare the recomputed `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when applicable) against `txn_info`'s values, or require `replay_on_archive`/any other caller of this function to additionally run the `DoStateCheckpoint` computation and assert equality against the trusted `TransactionInfo` checkpoint hashes before declaring a replay verified.

### Proof of Concept
1. Run `storage/db-tool/src/replay_on_archive.rs` against a version range where the write set, events, gas, and status recomputed by the VM match the archived `TransactionInfo`, but the actual global state (e.g., due to a bug in JMT/hot-state/position-state summary derivation, or a corrupted/forked archive snapshot) diverges — i.e., re-applying the identical write set to a subtly different base state tree yields a different `state_checkpoint_hash`.
2. Observe that `execute_and_verify` (`storage/db-tool/src/replay_on_archive.rs:349-416`) calls `ensure_match_transaction_info`, which returns `Ok(())` because it never inspects `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash`.
3. The tool reports the chunk as verified/replayed successfully, even though the authenticated state root differs from the one produced by local re-execution.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn execute_and_verify(
        &self,
        executor: &AptosVMBlockExecutor,
        current_version: &mut Version,

        cur_persisted_aux_info: &mut Vec<PersistedAuxiliaryInfo>,

        expected_writesets: &mut Vec<WriteSet>,

        if cur_txns.is_empty() {
            return Ok(None);
        }
        let txns = cur_txns
            .iter()

            .collect::<Vec<_>>();

            txns,

                .iter()
                .map(|info| AuxiliaryInfo::new(*info, None))

        );
        let executed_outputs = executor
            .execute_block(
                &txns_provider,
                &self
                    .arc_db

                    begin: *current_version,
                    end: *current_version + cur_txns.len() as u64,
                },
            )
            .map(BlockOutput::into_transaction_outputs_forced)?;

                cur_txns.drain(0..idx + 1);
                cur_persisted_aux_info.drain(0..idx + 1);
                expected_txn_infos.drain(0..idx + 1);

                expected_writesets.drain(0..idx + 1);

    fn get_state_checkpoint_hashes(
        execution_output: &ExecutionOutput,
        known_state_checkpoints: Option<Vec<Option<HashValue>>>,
        computed_last_checkpoint_hash: HashValue,
        label: &str,
    ) -> Result<Vec<Option<HashValue>>> {
        let _timer = OTHER_TIMERS.timer_with(&[&format!("get_{label}_checkpoint_hashes")]);

        let num_txns = execution_output.to_commit.len();
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();

        if let Some(known) = known_state_checkpoints {
            ensure!(
                known.len() == num_txns,
                "Bad number of known {label} hashes. {} vs {}",
                known.len(),
                num_txns,
            );
            if let Some(idx) = last_checkpoint_index {
                ensure!(
                    known[idx] == Some(computed_last_checkpoint_hash),
                    "{label} root hash mismatch with known hashes passed in. {:?} vs {:?}",
                    known[idx],
                    Some(computed_last_checkpoint_hash),
                );
            }
            Ok(known)
        } else {
            if !execution_output.is_block {
                // We should enter this branch only in test.
                execution_output.to_commit.ensure_at_most_one_checkpoint()?;
            }

            let mut out = vec![None; num_txns];
            if let Some(index) = last_checkpoint_index {
                out[index] = Some(computed_last_checkpoint_hash);
            }
            Ok(out)
        }
    }
