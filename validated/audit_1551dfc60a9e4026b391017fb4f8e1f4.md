### Title
Per-IP fairness in `GlobalRateLimiter` is trivially bypassed by IP rotation, letting a single attacker consume the entire shared global QPS budget - ([File: framework/src/main/java/org/tron/core/services/ratelimiter/GlobalRateLimiter.java])

### Summary
`GlobalRateLimiter.loadIpLimiter(String)` keys a `RateLimiter` cache purely on `RuntimeData.getRemoteAddr()`, with no normalization, allow-listing, or address-family accounting. [1](#0-0)  An unprivileged remote client that can present a large or unbounded pool of distinct source addresses (e.g. rotating IPv6 addresses within a /64, or using many source hosts) causes a brand-new `RateLimiter.create(IP_QPS)` to be minted for every request, each starting with a full burst allowance, so the per-IP throttle never actually limits that logical attacker. [2](#0-1)  Because the per-IP check is only a gate before the single shared `rateLimiter` (`QPS`) is consumed, the attacker can funnel effectively unmetered load onto that shared budget, starving all other unprivileged clients who *are* correctly throttled per-IP. [3](#0-2) 

### Finding Description
- `GlobalRateLimiter.tryAcquire`/`acquire` first obtain a per-IP `RateLimiter` via `loadIpLimiter(ip)`, then (only if that succeeds) call the single static `rateLimiter.tryAcquire()`/`acquire()`, which is shared across *all* callers of the HTTP and gRPC services. [3](#0-2) 
- The per-IP key is the raw client IP: `HttpServletRequest.getRemoteAddr()` for HTTP or the gRPC transport remote address for RPC, with no header sanitization/allow-listing. [4](#0-3) 
- Both `RateLimiterServlet.service` (HTTP) and `RateLimiterInterceptor.interceptCall` (gRPC) invoke `GlobalRateLimiter.acquirePermit(runtimeData)` on every request/call, meaning every distinct IP maps to a brand-new Guava `RateLimiter` (which grants an initial burst) the first time it's seen. [5](#0-4) [6](#0-5) 
- The cache is bounded to `maximumSize(10000)` and `expireAfterWrite(1, TimeUnit.HOURS)`, so an attacker generating more than 10000 distinct IPs also forces continual eviction and reload (`CacheLoader` re-execution of `RateLimiter.create(IP_QPS)`), but this is a secondary/minor overhead compared to the main issue: the fairness invariant the per-IP limiter is meant to enforce (bound each source's share of the shared `QPS` budget) is defeated whenever the source identity is attacker-controlled and cheap to rotate. [7](#0-6) 
- No other check in the reachable path mitigates this: there is no session/account binding, no proof-of-work, and no IP-block/CIDR based aggregation before the per-IP cache lookup.

### Impact Explanation
Because `rateLimiter` (the global `QPS` limiter) is a single static instance shared by every client of the node's HTTP/gRPC surface, an attacker who defeats the per-IP fairness layer can consume up to the entire global QPS budget by themselves, denying that budget to all other unprivileged clients. This is a DoS-via-RPC-API class issue: it doesn't crash the node, but it degrades/exhausts a shared, finite resource (global request throughput) that legitimate clients depend on, matching the "DoS via RPC-API" bounty category referenced in the rules.

### Likelihood Explanation
Feasibility depends entirely on the attacker's ability to cheaply present many distinct source IPs to the node's HTTP/gRPC listener. This is realistic for an attacker with an IPv6 allocation (a /64 gives an effectively unlimited pool of addresses that many ISPs/cloud providers grant to ordinary unprivileged customers) or one who runs many cheap outbound-IP virtual machines - no privileged role, MITM, or non-default configuration is required, matching the "unprivileged attacker" constraint. The attack is fully repeatable and only limited by the attacker's own connection/address churn rate, not by any defense in this code path.

### Recommendation
- Aggregate IP-based limiting by network block (e.g., normalize IPv6 to a /64 or /56 prefix, IPv4 to /24) rather than exact address, to blunt cheap address-rotation.
- Consider making the shared global `rateLimiter` fairness-aware (e.g., weighted fair queuing per source group, or per-source caps that persist independent of cache eviction) instead of a single shared token bucket that any single (possibly rotating) source can dominate.
- Reduce/eliminate the "fresh IP = full burst" property, e.g., initialize new per-IP `RateLimiter`s with zero stored permits, or require warmup, so first-seen IPs don't get an initial free burst.
- Add a distinct-new-IP-per-time-window meter to detect and flag/deprioritize rapid IP churn from what is likely a single attacker.

### Proof of Concept
```java
// framework/src/test/java/org/tron/core/services/ratelimiter/GlobalRateLimiterBypassTest.java
// Illustrative PoC (requires access to package-private/reflection to reset static QPS for test):
@Test
public void singleAttackerWithRotatingIpsConsumesGlobalBudget() throws Exception {
  // Assume IP_QPS and QPS are set small via config for the test, e.g. IP_QPS=1, QPS=100.
  int attackerRequests = 0;
  for (int i = 0; i < 1000; i++) {
    String rotatingIp = "2001:db8:" + Integer.toHexString(i) + "::1"; // simulate /64 rotation
    RuntimeData rd = mock(RuntimeData.class);
    when(rd.getRemoteAddr()).thenReturn(rotatingIp);
    if (GlobalRateLimiter.tryAcquire(rd)) {
      attackerRequests++;
    }
  }
  // Expect: attackerRequests approaches the full global QPS budget (~100),
  // despite IP_QPS=1 supposedly limiting each "client" to ~1 req in the window,
  // because each IP is fresh and never throttled by the per-IP limiter.
  assertTrue("attacker consumed most of global QPS via IP rotation",
      attackerRequests > 50); // i.e., far more than a fairly-shared allocation would permit
}
```
Note: `GlobalRateLimiter`'s fields (`QPS`, `IP_QPS`, `cache`, `rateLimiter`) are `private static` with no test seams, so an actual JUnit PoC requires either reflection to lower `QPS`/`IP_QPS` for a fast test, or driving it through `RateLimiterServlet`/`RateLimiterInterceptor` with a mocked `HttpServletRequest`/`ServerCall` supplying rotating remote addresses, as shown in the existing `GlobalRateLimiterTest.java`.   private static RateLimiter loadIpLimiter(String ip) {
    try {
      // cache.get is atomic: only one loader executes per key under concurrent requests,
      // preventing multiple RateLimiter instances from being created for the same IP.
      return cache.get(ip, () -> RateLimiter.create(IP_QPS));
    } catch (Exception e) {
      logger.warn("Failed to load IP rate limiter for {}, denying request: {}",
          ip, e.getMessage());
      return null;
    }
  }
