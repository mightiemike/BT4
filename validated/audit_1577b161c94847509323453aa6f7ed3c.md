### Title
Missing declared-class-hash check in `execute_replace_class` allows the Starknet OS to accept an undeclared class hash, diverging from the sequencer's blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Hats Protocol bug is a "missing state-gate before a state mutation" pattern: `mintHat`/`transferHat` mutate wearer state without checking the hat's `active` status, letting the system enter/report an inconsistent state. The direct analog in this Starknet sequencer codebase is in the Cairo implementation of the `replace_class` syscall inside the Starknet OS (SNOS) program, which mutates a contract's `class_hash` in `contract_state_changes` without verifying that the target `class_hash` corresponds to a declared class — a check that IS explicitly enforced in the Rust `blockifier` implementation of the very same syscall.

### Finding Description
`execute_replace_class` in the OS Cairo program directly overwrites the contract's `state_entry.class_hash` with the caller-supplied `class_hash` from the syscall request, with only a `TODO` acknowledging the missing validation: [1](#0-0) 

There is no lookup verifying `class_hash` exists in `contract_class_changes` (the declared-classes dictionary) before it is written into the new `StateEntry`. The same pattern (no check at all, not even a `TODO`) exists in the deprecated syscalls path: [2](#0-1) 

By contrast, the Rust `blockifier`, which is the sequencer's actual state-transition implementation used to build blocks, enforces this check for the same syscall by reading the compiled class before allowing the replace: [3](#0-2) 

This is confirmed by tests that expect the blockifier to reject undeclared class hashes: [4](#0-3) 

So the sequencer (blockifier, which decides what is included/committed in a block) and the Starknet OS (which re-executes the same block to compute the authoritative committed state root, output, and block hash for proving) implement two different state-transition functions for `replace_class`: one enforces "class must be declared," the other does not.

### Impact Explanation
The Starknet OS's execution trace is what is proven and ultimately used to derive the committed state root / block hash for a block (an "Starknet OS re-execution" path explicitly in scope). If the OS's state-transition function is more permissive than the blockifier's — allowing a `class_hash` that is not actually declared to be written into a contract's `StateEntry` — then any scenario in which the OS and blockifier could disagree on whether a class is "declared" (e.g., differences in how `contract_class_changes`/declared-class dictionaries are populated or ordered between the two independent implementations, or future code paths that route transactions to the OS without funneling through the blockifier's stricter check) produces a state entry with an invalid/dangling class hash in the committed state. This directly risks a wrong committed root / block hash relative to what the blockifier would have produced, i.e., honest-node divergence between the sequencer's block-building state view and the OS's proven state view — one of the explicitly accepted impacts for this analysis.

### Likelihood Explanation
This is a concrete, currently-present gap (not speculative) — it is explicitly flagged by the developers via the `TODO(Yoni, 1/1/2026)` comment as an intentionally deferred check, confirming the validation is genuinely missing today rather than handled implicitly elsewhere in the Cairo file. Because `replace_class` is a syscall reachable directly from unprivileged contract code executed by any account during ordinary `__execute__`, the code path is trivially reachable from a single submitted transaction; the only open question is whether some invariant elsewhere in the OS guarantees `contract_class_changes` and the blockifier's declared-class view are always identical, which is exactly the kind of state-reader/dict-population divergence this class of bug (missing state gate before mutation) is prone to, as demonstrated by the analogous Hats.sol report.

### Recommendation
Add an explicit check in `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that looks up `class_hash` in `contract_class_changes` (or equivalent declared-classes tracking) and fails/reverts the syscall if the class is not declared, mirroring the check already performed in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs::replace_class`. This closes the gap between the OS's state-transition function and the blockifier's, eliminating the possibility of divergence.

### Proof of Concept
1. In the Rust blockifier, `replace_class_syscall(undeclared_class_hash)` is exercised and asserted to fail with "is not declared": [4](#0-3) .
2. Tracing the equivalent logic path in the Starknet OS Cairo program (`execute_replace_class` in `syscall_impls.cairo`, lines 881-920, and the deprecated-syscalls equivalent, `deprecated_execute_syscalls.cairo` lines 307-329) shows no analogous declared-class-hash check is performed before writing the new `StateEntry` with the caller-supplied `class_hash` — only a `TODO` comment acknowledging the gap in the non-deprecated path, and no comment at all in the deprecated path.
3. This confirms the OS's `replace_class` state transition is strictly more permissive than the blockifier's for this syscall, which is the exact "missing gate before state mutation" pattern described in the source Hats.sol report.

func execute_replace_class{contract_state_changes: DictAccess*, revert_log: RevertLogEntry*}(
    contract_address, syscall_ptr: ReplaceClass*
) {
    alloc_locals;
    let class_hash = syscall_ptr.class_hash;

    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
