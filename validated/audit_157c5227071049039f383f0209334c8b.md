## Finding

### Title
Unbounded, fee-free `UniversalPayload.GasLimit`/`Data` in the gasless `MsgExecutePayload` path enables cost-free EVM resource exhaustion - (File: `x/uexecutor/types/universal_payload.go`, `x/uexecutor/keeper/evm.go`, `app/txpolicy/gasless.go`)

### Summary
The HAL-27 analog in this codebase is `MsgExecutePayload`, which is both (a) on the gasless whitelist (`app/txpolicy/gasless.go`) and (b) validated only for *format*, never for *size or magnitude*. `UniversalPayload.Data` and `UniversalPayload.GasLimit` accept arbitrarily large hex/uint256 strings, and `GasLimit` is parsed straight into the internal EVM call's gas limit (`CallUEAExecutePayload` in `x/uexecutor/keeper/evm.go`) with no upper bound check, while the outer Cosmos transaction pays no fee at all.

### Finding Description
`UniversalPayload.ValidateBasic()` [1](#0-0)  only checks that `Data` is valid hex and that numeric fields (`Value`, `GasLimit`, etc.) parse as non-negative `big.Int` — there is no cap on string/byte length for `Data`, and no upper bound on `GasLimit`.

`MsgExecutePayload.ValidateBasic()` likewise only checks presence/format, not size [2](#0-1) .

`MsgExecutePayload` is a gasless message type — the sender pays no Cosmos fee and, if the account doesn't exist yet, `AccountInitDecorator` creates it mid-pipeline with zero balance for the first tx [3](#0-2) [4](#0-3) . `DeductFeeDecorator` and `MinGasPriceDecorator` both explicitly skip fee/min-gas-price checks for gasless txs [5](#0-4) [6](#0-5) .

At execution, `CallUEAExecutePayload` parses `universal_payload.GasLimit` as an unbounded `big.Int` and passes it directly as the gas limit of a real `DerivedEVMCall` into the target UEA contract [7](#0-6) . This inner EVM gas limit is attacker-controlled and independent of whatever Cosmos-level `gas` value was declared on the outer tx (which is what `ConsumeGasForTxSizeDecorator`/`GasWantedDecorator` actually meter). There is no ceiling tying `GasLimit` to the node's configured EVM/block gas limit before the call is dispatched.

Combined, an unprivileged, unfunded attacker can:
1. Submit `MsgExecutePayload` with an arbitrarily large `UniversalPayload.Data` blob (no length cap) and an arbitrarily large `GasLimit` string.
2. Pay zero fee (gasless whitelist) and need no pre-funded account (`AccountInitDecorator` bootstraps it).
3. Have this drive a real `DerivedEVMCall` into the UEA/target contract whose computational cost is gated only by whatever the EVM/contract execution actually enforces, not by anything checked up front in `ValidateBasic`.

This is the direct structural analog of HAL-27: an externally reachable relay/execution entry point that accepts attacker-controlled payload size and numeric magnitude without sanitization or limits, enabling resource-exhaustion abuse at effectively zero cost to the attacker.

### Impact Explanation
Because `MsgExecutePayload` is free to submit (gasless) and unbounded in payload size/declared gas, an attacker can flood validators with computationally heavy, storage-heavy transactions without needing to hold or spend PC tokens, repeatedly forcing full EVM dispatch (`CallUEAExecutePayload`/`DerivedEVMCall`) and CacheContext execution per submission. This degrades node performance/availability for legitimate UV voting and payload execution traffic — a reachable, non-network-level DoS vector triggered purely by ordinary (if abusive) user transaction submission, not by any privileged or malicious-validator behavior.

### Likelihood Explanation
Any external account can construct and broadcast `MsgExecutePayload` with a large `Data` field and large `GasLimit`; no special role, key compromise, or validator collusion is required. The gasless whitelist and `AccountInitDecorator` specifically remove the normal economic friction (fees, pre-funded balance) that would otherwise throttle this kind of spam, so likelihood of an attacker discovering and exploiting this path is moderate-to-high once the message type and gasless status are known (both are documented in `app/README.md`).

### Recommendation
- Enforce a maximum byte length on `UniversalPayload.Data` (and `RawPayload`/`VerificationData`) in `ValidateBasic`.
- Enforce a sane upper bound on `UniversalPayload.GasLimit` (e.g., capped to the chain's configured max EVM call gas) before it is ever passed to `CallUEAExecutePayload`/`DerivedEVMCall`.
- Consider rate-limiting or requiring minimal non-zero cost (e.g., a bonded minimum) for gasless `MsgExecutePayload` submissions from freshly created accounts, in addition to the existing mempool/CometBFT `max_tx_bytes` bound, since that generic limit is not payload-aware and does not protect against maliciously large `GasLimit` values with small overall tx byte size.

### Proof of Concept
1. Create (or let `AccountInitDecorator` auto-create) a fresh, zero-balance Cosmos account.
2. Build `MsgExecutePayload{ Signer: <fresh account>, UniversalAccountId: <any UEA>, UniversalPayload: { To: <valid addr>, Data: "0x" + <e.g. hundreds of KB of hex>, GasLimit: "<huge decimal string>", ... }, VerificationData: "0x1234" }`.
3. Submit repeatedly as a standalone gasless tx (matches the whitelist in `app/txpolicy/gasless.go`) — no fee, no pre-funded balance required.
4. Observe that `ValidateBasic` (both `MsgExecutePayload` and `UniversalPayload`) accepts it regardless of `Data` length or `GasLimit` magnitude, and that `CallUEAExecutePayload` forwards the parsed `GasLimit` directly into `DerivedEVMCall` [7](#0-6) , with the entire submission costing the attacker nothing.

// ValidateBasic does the sanity check on the UniversalPayload fields.
func (p UniversalPayload) ValidateBasic() error {
	// Validate 'to' address
	if strings.TrimSpace(p.To) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "to address cannot be empty")
	}
	if !utils.IsValidAddress(p.To, utils.HEX) {
		return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid to address format: %s", p.To)
	}

	// Validate 'data' is a valid hex string
	if len(p.Data) > 0 {
		if _, err := hex.DecodeString(strings.TrimPrefix(p.Data, "0x")); err != nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid hex data")
		}
	}

// ValidateBasic does a sanity check on the provided data.
func (msg *MsgExecutePayload) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate universal payload
	if msg.UniversalPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal payload cannot be nil")
	}

	// Validate verificationData
	if len(msg.VerificationData) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "verificationData cannot be empty")
	}
	if _, err := hex.DecodeString(strings.TrimPrefix(msg.VerificationData, "0x")); err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid verificationData hex")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate universal payload structure
	if err := msg.UniversalPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universal payload")
	}

	return nil
}
