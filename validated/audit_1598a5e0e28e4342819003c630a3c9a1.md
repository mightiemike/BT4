## Analysis

The described mechanics are accurate to the code. In both `gasAndPayloadDepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:348-379`) and the analogous `ExecuteInboundGas` swap step (`x/uexecutor/keeper/execute_inbound_gas.go:104-153`) and `applyGasRefund` (`x/uexecutor/keeper/outbound.go:213-237`), the keeper:

1. Calls `GetSwapQuote`, which is a plain `CallEVM(commit=false)` read of `QuoterV2.quoteExactInputSingle`, i.e. a **spot-price** read of the live Uniswap V3 pool reserves [1](#0-0) .
2. Immediately derives `minPCOut = quote * 95 / 100` — a fixed 5% band computed purely from that just-fetched spot quote, with no TWAP, no external slippage parameter, and no oracle cross-check [2](#0-1) .
3. Passes that `minPCOut` straight into `CallPRC20DepositAutoSwap`, which executes the real swap via `depositPRC20WithAutoSwap` on the `UNIVERSAL_CORE` contract [3](#0-2) .

This confirms the upgrade note describing the change from a "0-slippage call" to "QuoterV2... minPCOut (quote × 95%)" [4](#0-3) .

The quote-fetch and the swap execution are two separate EVM calls from the module account, executed sequentially inside one keeper invocation, which itself runs inside whatever Cosmos transaction triggers inbound finalization (e.g., the `MsgVoteInbound` that crosses quorum). Nothing in this path binds `minPCOut` to a time-weighted or otherwise manipulation-resistant price — it is a same-block spot price with a static percentage buffer. An unprivileged attacker who can predict (or race) the block containing the finalizing transaction can submit an ordinary swap against the same on-chain Uniswap V3 pool immediately before it to push the spot price against the depositor, and unwind it immediately after to capture the resulting slippage — a standard sandwich against a fixed, non-TWAP slippage bound. No malicious validator, UV, TSS signer, or admin is required: the attacker only needs ordinary swap transactions against a public AMM pool and ordinary visibility of pending inbound votes/transactions, both of which are unprivileged, user-reachable actions.

This satisfies the in-scope impact category "corruption of PRC20 or native asset accounting" and "unauthorized ... state transitions in universal execution flows," since the UEA ends up credited with less WPC/PC than a fair-price execution would produce, and the difference is extractable by the attacker through the sandwich round-trip.

### Title
Spot-price-only `minPCOut` (5% fixed slippage, no TWAP) in auto-swap deposit path enables sandwich extraction against inbound depositors - (File: `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`)

### Summary
`gasAndPayloadDepositAutoSwap`, the `ExecuteInboundGas` swap step, and `applyGasRefund` all compute the auto-swap's slippage floor as `GetSwapQuote(...) * 95 / 100` using the current spot price from `QuoterV2.quoteExactInputSingle`, then immediately execute the swap via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`. Because the reference price is a manipulable, same-moment spot quote rather than a TWAP or externally-supplied slippage bound, an unprivileged attacker can sandwich the pool around the block/transaction that triggers this quote-then-swap sequence to force the swap to execute at a degraded rate and capture the difference.

### Finding Description
- `GetSwapQuote` performs a `commit=false` read of `QuoterV2.quoteExactInputSingle` against the live pool state at execution time [1](#0-0) .
- The resulting `minPCOut` is derived solely as 95% of that quote, with no other bound, oracle check, or caller-supplied tolerance [5](#0-4) [6](#0-5) [7](#0-6) .
- `CallPRC20DepositAutoSwap` then executes the actual `depositPRC20WithAutoSwap` swap against the same pool, crediting the resulting WPC/PC amount to the UEA [3](#0-2) .
- Since quote-fetch and swap-execution are ordinary on-chain calls against a Uniswap V3 pool reachable by any user's swap transaction, an attacker can push the pool price adversarially before this sequence executes and reverse it afterward, extracting value equal to the difference between the fair price and the 5%-degraded execution price — bounded above by the static 5% band, but real and attacker-directed rather than fair-market slippage.
- This requires no malicious validator, UV, TSS signer, relayer, or admin — only ordinary swap transactions against the public pool and ordinary observation of pending inbound finalization, both of which are unprivileged user actions.

### Impact Explanation
Depositors going through the GAS/GAS_AND_PAYLOAD auto-swap path (and gas-refund-with-swap path) can be credited fewer WPC/PC tokens than a fair-price swap would yield, with the shortfall extracted by the attacker. This is fund-loss/accounting-corruption impact on the UEA's credited balance, scoped to the size of the swap and the depth/manipulability of the specific pool at the time.

### Likelihood Explanation
Feasibility depends on pool liquidity depth relative to attacker capital and on the attacker's ability to predict/observe which block will contain the finalizing transaction for a given inbound (or refund) and place transactions immediately around it. This is realistic on chains with public mempools and priority-fee-based ordering, though it is bounded by the fixed 5% band (the attacker cannot extract more than ~5% per swap) and by available liquidity.

### Recommendation
Replace the same-moment spot quote with a manipulation-resistant reference price (e.g., a TWAP over several blocks, or a protocol-configured maximum price-impact/oracle cross-check) before computing `minPCOut`, and/or reduce the static 5% band to a value tuned to realistic pool depth, and consider batching or randomizing execution timing so the exact finalization block is not predictable to a griefing/sandwiching party.

### Proof of Concept
Conceptually: (1) observe an inbound reach voting quorum destined for `gasAndPayloadDepositAutoSwap`/`ExecuteInboundGas`; (2) submit an ordinary large swap against the same Uniswap V3 pool immediately before the finalizing transaction to depress `quoteExactInputSingle`'s spot output; (3) let the module's swap execute at the depressed `minPCOut` floor; (4) submit a reverse swap immediately after to restore price and realize profit equal to the captured slippage. A Go/property test could stub `GetSwapQuote` to return a manipulated value at call time and assert the resulting `minPCOut`/credited UEA balance falls below a fair-value bound computed from the pre-manipulation quote.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
