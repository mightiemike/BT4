Based on my investigation, I found a concrete analog in the account-deletion cleanup path.

### Title
`DeleteAccount` action removes an account without clearing its PromiseYield state, letting stale yield entries be resumed after deletion - ([File: core/store/src/utils/mod.rs])

### Summary
`remove_account` (`core/store/src/utils/mod.rs:504-575`), invoked by `action_delete_account` (`runtime/runtime/src/actions.rs:330-406`), only removes the `Account` record, `ContractCode`, all `AccessKey`/gas-key-nonce entries, and `ContractData`. It never touches `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, or `DataIdToYieldId` entries, even though `core/primitives/src/trie_key.rs:89-102` explicitly lists all four as account-id-keyed columns (`COLUMNS_WITH_ACCOUNT_ID_IN_KEY`). This mirrors the reported bug class exactly: a "removal" function clears the top-level record but leaves derived state that other code paths use as an existence oracle, breaking the invariant that "no PromiseYield state exists without a live account."

### Finding Description
An account can call `promise_yield_create` from within a `FunctionCall` receipt, which stores a `PromiseYieldReceipt` (and, since `YieldWithId`, a `YieldIdToDataId`/`DataIdToYieldId` pair) keyed by `(receiver_id, data_id)`, plus a global `PromiseYieldTimeout` queue entry `{account_id, data_id, expires_at}` (`core/store/src/utils/mod.rs:181-198`, `runtime/runtime/src/receipt_manager.rs:149-166`). In a later, independent receipt, the same account can execute `DeleteAccountAction` as its final action. `action_delete_account` only checks storage usage recorded on the `Account` record and gas-key balances (`runtime/runtime/src/actions.rs:342-379`) before calling `remove_account`, which removes the account and access keys but never enumerates or removes `PromiseYieldReceipt`/`PromiseYieldStatus`/`YieldIdToDataId`/`DataIdToYieldId` rows for that account (`core/store/src/utils/mod.rs:504-575`). [1](#0-0) [2](#0-1) 

The global `PromiseYieldTimeout` queue is unaffected by account deletion. When its `expires_at` is reached, `resolve_promise_yield_timeouts` (`runtime/runtime/src/lib.rs:3113-3209`) checks `state_update.contains_key(&promise_yield_key)` where `promise_yield_key = TrieKey::PromiseYieldReceipt{receiver_id: queue_entry.account_id, data_id}` — this returns **true** because the entry was never cleaned up — and it synthesizes and forwards a `PromiseResume` receipt addressed to the now-deleted `account_id`. [3](#0-2) 

When that `PromiseResume` is later processed, `process_receipt`'s `PromiseResume` arm (`runtime/runtime/src/lib.rs:1554-1616`) again finds the stale `PromiseYieldReceipt` via `get_promise_yield_receipt`, removes it, writes `ReceivedData`, and calls `apply_action_receipt` on the parked yield receipt — i.e., it executes an action receipt whose `receiver_id` is an account that no longer exists in the trie. `apply_action_receipt` reads `get_account(state_update, account_id)` and explicitly tracks `account_did_not_exist` (`runtime/runtime/src/lib.rs:907-908`), so per-action dispatch runs `check_account_existence`, which for most actions (including the ones a yield-triggered callback would carry) returns `AccountDoesNotExist`. The receipt is nonetheless fully processed against a *phantom* target, consuming compute/gas and producing execution outcomes/receipts (e.g., refunds) for an account identity that has been deleted — and if the same `account_id` string is later reused by a brand-new (unrelated) account, this stale timeout-driven mechanism can inject a spurious receipt into that new account's queue as well, since the trie key is keyed purely by `account_id`/`data_id`, not by any incarnation counter. [4](#0-3) [5](#0-4) 

### Impact Explanation
This is a state-cleanup/invariant violation reachable by a single ordinary account owner (two of their own transactions: one that yields, one that deletes the account), exactly analogous to the reported `removeCategoryGroup` issue where downstream code trusts a stale existence mapping. Concretely it causes: (1) permanently orphaned trie state for `PromiseYieldReceipt`/`PromiseYieldStatus`/`YieldIdToDataId`/`DataIdToYieldId` that nobody pays storage stake for (since `remove_account`'s deletion already released the account's storage-usage), i.e. unaccounted state growth; and (2) the runtime creating and executing genuine `PromiseResume` receipts against a deleted (or later-recreated) account identity, an execution-layer state transition the protocol's `check_account_existence` model was not designed to encounter via this path. Because every honest node runs the identical deterministic logic, this does not itself cause state-root divergence, but it is an instance of "invalid state transition acceptance" — the runtime accepts and executes receipts referencing an account that the account model says does not exist, and does so unconditionally for every account that ever yields before self-deleting.

### Likelihood Explanation
High reachability, low required privilege: any account holder can trigger it with two of their own actions (`promise_yield_create` via a contract call, followed later by `DeleteAccountAction`), no cross-account permission or validator role needed. The only friction is that the account's contract must expose a yield-creating method, which is common in async/callback patterns (cross-contract calls, promise combinators) — well within reach of a normal dApp user.

### Recommendation
Extend `remove_account` (`core/store/src/utils/mod.rs`) to also iterate and remove `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, and `DataIdToYieldId` entries for the account being deleted (mirroring how it already iterates access-key/gas-key-nonce prefixes and contract-data keys), and additionally reject/skip stale `PromiseYieldTimeout` queue entries in `resolve_promise_yield_timeouts` whose target account no longer exists, so a deleted account's outstanding yields cannot resurface as executable receipts.

### Proof of Concept
1. Account `alice` deploys/calls a contract method that invokes `promise_yield_create`, producing a `PromiseYieldReceipt`/`PromiseYieldTimeout` entry keyed to `alice` with some `data_id` and `expires_at = H`.
2. In a subsequent transaction (before the yield is resumed or times out), `alice` submits `DeleteAccountAction`. `action_delete_account` succeeds because storage/gas-key checks only look at the `Account` record and access keys, not at yield state (`runtime/runtime/src/actions.rs:330-406`); `remove_account` deletes the account but leaves `PromiseYieldReceipt`/`PromiseYieldTimeout` for `alice`'s `data_id` in the trie (`core/store/src/utils/mod.rs:504-575`).
3. At block height `H`, `resolve_promise_yield_timeouts` finds the queue entry, calls `contains_key` on the still-present `PromiseYieldReceipt`, and forwards a synthetic `PromiseResume{data: None}` receipt to `alice` (`runtime/runtime/src/lib.rs:3129-3202`).
4. That receipt is processed by `process_receipt`'s `PromiseResume` branch, which fetches the stale `PromiseYieldReceipt`, removes it, and calls `apply_action_receipt` targeting the deleted `alice` account (`runtime/runtime/src/lib.rs:1554-1616`, `826-915`) — demonstrating that a deleted account's parked promise state is not cleaned up and is later re-executed by the runtime, confirming the root cause traced above.

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,

    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}
