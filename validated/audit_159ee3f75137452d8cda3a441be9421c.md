### Title
Manipulable spot-price AMM quote used as its own slippage bound in auto-swap deposit/refund flows — ([File: x/uexecutor/keeper/evm.go])

### Summary
`GetSwapQuote` and `CallPRC20DepositAutoSwap` implement the "fix" pattern recommended by the external Uniswap V3 report (replace `amountOutMinimum: 0` with a computed minimum), but the computed minimum is derived from a live, single-pool spot-price call (`QuoterV2.quoteExactInputSingle`) taken from the exact same AMM pool that the swap itself executes against, in the same atomic keeper call. Because the "protection" price and the execution price come from the same manipulable pool state, an attacker can move the pool price immediately before the inbound/refund swap executes and still stay inside the 5% band, extracting value from the user's bridged deposit — the same economic bug class as the original report (unprotected AMM swap execution), just relocated from a fixed `0` to a self-referential, still-manipulable bound.

### Finding Description
`GetSwapQuote` fetches `amountOut` via a non-committing `CallEVM` to `QuoterV2.quoteExactInputSingle` against the live pool state: [1](#0-0) 

That quote is immediately turned into `minPCOut = quote * 95 / 100` and passed straight into the real, committing swap in the very next call, `CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap` on `UniversalCore`: [2](#0-1) 

This quote→swap sequence runs inside a single keeper call, itself invoked synchronously from `ExecuteInboundGas` the moment `MsgVoteInbound` crosses the 2/3 ballot threshold — no separate transaction, no delay, no oracle independent of the pool: [3](#0-2) [4](#0-3) 

The identical pattern is duplicated for `GAS_AND_PAYLOAD` inbounds: [5](#0-4) 

and for the excess-gas refund swap path (`applyGasRefund` → `getSwapQuoteForRefund` → `CallUniversalCoreRefundUnusedGas` with `withSwap=true`): [6](#0-5) 

`quoteExactInputSingle` on Uniswap V3's `QuoterV2` returns the current spot price of the pool (it is not a time-weighted average). Because the value used to bound slippage is read from, and immediately consumed against, the same instantaneous pool state, any actor who can move that pool's price in a transaction that lands before the inbound/refund execution (a normal user-submitted swap on the same DEX pool, broadcast via the public CometBFT mempool before the `MsgVoteInbound`/finalizing vote is included, or in the immediately preceding block) can set the "reference" price itself. The subsequent 95%-of-quote floor then simply legitimizes whatever manipulated price the attacker created, and the deposit's PRC20→WPC swap executes against that manipulated pool, extracting value from the user's bridged principal (for `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`) or from the relayer's gas refund (for `applyGasRefund`). The upgrade changelog itself documents this as the fix for the "0-slippage" issue, but the design just substitutes a manipulable self-quote for the previous `0`: [7](#0-6) 

This is the same invariant break as the external report's "amountOutMinimum: 0" bug — swap execution lacks a price reference that is independent of the pool being traded against — mapped onto Push Chain's own asset accounting (PRC20 deposit → native PC conversion) rather than a vault contract.

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound, and every outbound gas refund with `withSwap=true`, routes user/relayer funds through this quote-then-swap sequence. An attacker who can manipulate the relevant PRC20/WPC pool price for the single block in which the deposit-swap executes can cause the user to receive PC valued materially below (up to the full 5% band, and potentially more depending on pool depth/liquidity) fair market value for their bridged gas top-up, with the difference extractable by the attacker via a back-run trade. This is a direct, repeatable loss of user-controlled funds during ordinary bridging activity — no privileged role is required, matching the "unauthorized ... unauthorized release ... corruption of ... gas fee accounting" allowed-impact categories.

### Likelihood Explanation
Likelihood is high for any liquidity-constrained PRC20/WPC pool: the attacker only needs to observe pending `MsgVoteInbound` traffic (or simply predict the routine, frequent bridging activity) and submit an ordinary swap transaction on the target Uniswap V3 pool ahead of the ballot-finalizing vote/execution in the same or preceding block. No validator, TSS, or admin collusion is needed — this is reachable purely through normal DEX interaction by an unprivileged external actor, and the 5% slippage window is exactly sized to make small-to-medium manipulations profitable while appearing to be "protected."

### Recommendation
Do not derive the slippage floor from the same pool being traded against at swap time. Use either: (1) a manipulation-resistant reference such as a Uniswap V3 TWAP (time-weighted average over a meaningful window) instead of `quoteExactInputSingle`'s instantaneous spot price, or (2) an external/oracle price feed independent of the executing pool, as the original report's own remediation guidance recommends, combined with sanity bounds (e.g., reject if quote deviates too far from a trusted external reference) and, ideally, minimum liquidity/TWAP-deviation checks before allowing the auto-swap path at all, falling back to the no-swap deposit path when checks fail (this fallback already exists as `depositPRC20Token` and could be used more defensively).

### Proof of Concept
1. Push Chain has a live PRC20↔WPC Uniswap V3 pool used by `UniversalCore.depositPRC20WithAutoSwap` (as configured via `GetDefaultFeeTierForToken`/`GetUniversalCoreQuoterAddress`).
2. Attacker monitors the mempool for a pending `MsgVoteInbound` that will finalize a `GAS`/`GAS_AND_PAYLOAD` inbound for a sizeable `amount` (or simply times a large routine bridging deposit).
3. Attacker submits a large swap into the same pool (buying WPC / selling PRC20, or vice versa) in the block immediately preceding the finalizing vote, moving the pool's spot price.
4. When the ballot finalizes, `GetSwapQuote` (x/uexecutor/keeper/evm.go:500-538) returns the manipulated spot price; `minPCOut = quote*95/100` is computed from it (x/uexecutor/keeper/execute_inbound_gas.go:142-146) and passed to `CallPRC20DepositAutoSwap`, which executes the real swap against the still-manipulated pool.
5. Attacker immediately reverses their initial swap, realizing profit equal to the value siphoned from the user's bridged deposit (bounded above by the 5% band, but effectively unlocked by the attacker's own price-setting action).

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
