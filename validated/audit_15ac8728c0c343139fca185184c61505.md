### Title
Anyone can permanently and repeatedly abuse the "BOOTSTRAP" declare bypass to declare classes for free, at any block, not just at genesis - (File: `crates/blockifier/src/transaction/account_transaction.rs`)

### Summary
The blockifier and the Starknet OS both implement a special-cased "bootstrap declare" path meant to let a new system be bootstrapped (declare the very first account/class before any real account exists). The gate for this privileged path is purely a function of transaction *content* the sender fully controls (a hard-coded sender address, `nonce == 0`, `version == 3`, and zero resource bounds) — not of chain state, block height, or any one-time flag. Because this fixed sender's nonce is never incremented by this code path, the "gate" never closes: any unprivileged user can submit such a declare transaction at any point in the chain's life to declare an arbitrary class while completely skipping `__validate__`, signature checks, nonce bump, and fee charging.

### Finding Description
`DeclareTransaction::bootstrap_address()` returns a fixed, public, keyless constant (`ContractAddress::from(0x424f4f545354524150_u128)`, the ASCII encoding of `'BOOTSTRAP'`), and `is_bootstrap_declare` defines the bypass condition purely from tx fields: [1](#0-0) 

In `AccountTransaction::execute_raw`, if a `Declare` transaction satisfies `is_bootstrap_declare`, the account-related pipeline (pre-validation nonce/fee check, `__validate__`, fee charging) is entirely skipped; only the class declaration side-effect runs and a default (empty) execution info is returned: [2](#0-1) 

The identical bypass exists in the Starknet OS Cairo re-execution path, with the same unconditional check on `sender_address`, `nonce`, `version`, and `max_possible_fee`: [3](#0-2) 

Whether `charge_fee` (i.e., whether the fee/enforcement gate is on) is decided solely by `enforce_fee`, which derives from the *sender-supplied* resource bounds — an attacker simply sets all resource bounds/prices to zero (as the test helper `new_unlimited_gas_no_fee_enforcement` demonstrates) to make `enforce_fee` return `false`: [4](#0-3) [5](#0-4) 

Crucially, because the `BOOTSTRAP` sender is never deployed and this code path returns before `check_and_increment_nonce`/before any account-nonce write, its nonce remains `0` forever — there is no state transition that "closes" the bootstrap window after first use. This is explicitly acknowledged by the codebase's own comment and test: [6](#0-5) [7](#0-6) 

The only real restriction preventing repeated abuse for the *same* class is the `prev_value=0` check when writing `contract_class_changes` (a class hash can only be declared once), enforced both in the Cairo OS and in `try_declare`: [8](#0-7) [9](#0-8) 

That restriction is per-class-hash, not per-system: an attacker can craft an unbounded number of distinct classes (even trivial permutations) and declare every one of them for free, at any block height, forever. This mirrors the reported bug class exactly: a privileged/one-time initialization gate ("start the auction" / "bootstrap the system") whose guard condition collapses to a default/never-changing state value (`epoch_start == 0` there; `nonce == 0` here) that any unprivileged caller can trivially satisfy at any time, not just during the intended one-time initialization window.

### Impact Explanation
Any unprivileged L2 transaction sender can submit declare transactions from the well-known `BOOTSTRAP` address (no private key/signature required, since `__validate__` is skipped) with zero fee and zero resource bounds, and have them accepted by the blockifier (and independently re-validated as such by the Starknet OS), permanently:
- Bypassing fee enforcement/resource accounting for an operation (class declaration) that is normally metered and paid for, allowing free consumption of declare-related sequencer/prover resources (class compilation, hashing, storage) — an economic/resource-accounting bypass reachable from a single submitted transaction.
- Performing an "unauthorized account action": declaring contract classes without any account, signature, or fee, using a flow intended to be exercised once by the network operator at genesis.
- Because the gate never closes (the BOOTSTRAP nonce is never bumped), this is not a one-time bootstrap artifact but a standing, permanently exploitable bypass for the lifetime of the chain.

### Likelihood Explanation
High. No special privileges, keys, or timing window are required — the sender address, nonce, version, and zero-fee condition are all public, well-known, and directly attacker-controlled fields of an ordinary `DECLARE` v3 transaction. The bypass condition is checked purely against transaction content, with no dependency on block height/genesis state, so it is trivially reachable at any point after chain launch by anyone able to submit a transaction to the gateway/mempool.

### Recommendation
Gate the bootstrap-declare bypass on protocol/chain state rather than solely on attacker-controlled transaction fields — e.g., only allow it while the chain is still at/near genesis (a specific, checked block-number condition validated against consensus-agreed state), and/or enforce a hard, state-tracked one-time-use flag for the `BOOTSTRAP` sender (so a second use, even for a different class hash, is rejected) instead of relying on the per-class `prev_value=0` declare-uniqueness check as the only limiter.

### Proof of Concept
1. After genesis (at any subsequent block), craft a `DeclareTransaction::V3` with `sender_address = DeclareTransaction::bootstrap_address()`, `nonce = Nonce(Felt::ZERO)`, `resource_bounds` all zero-priced (e.g., `AllResourceBounds::new_unlimited_gas_no_fee_enforcement()`), and an empty/default `signature`.
2. Submit it through the gateway; because `enforce_fee`/`charge_fee` evaluates to `false` from the zero resource bounds, and `is_bootstrap_declare` matches, the transaction bypasses `__validate__`, nonce increment, and fee charging in `AccountTransaction::execute_raw` (see `crates/blockifier/src/transaction/account_transaction.rs:899-911`), and the OS re-execution path takes the identical `SkipTx` branch.
3. The class gets declared for free. Repeat with a new class each time — the `BOOTSTRAP` sender's nonce is never incremented, so the same crafted transaction pattern (with a fresh class hash each time) remains valid indefinitely, letting an unprivileged actor declare unlimited classes for free at any point in the chain's operation, not only at genesis.

        // - This time, execution will fail because the contract has already been declared.

/// Attempts to declare a contract class by setting the contract class in the state with the
/// specified class hash.
fn try_declare<S: State>(
    tx: &DeclareTransaction,
    state: &mut S,
    class_hash: ClassHash,
    compiled_class_hash: Option<CompiledClassHash>,
) -> TransactionExecutionResult<()> {
    match state.get_compiled_class(class_hash) {
        Err(StateError::UndeclaredClassHash(_)) => {
            // Class is undeclared; declare it.
            state.set_contract_class(class_hash, tx.contract_class().try_into()?)?;
            if let Some(compiled_class_hash) = compiled_class_hash {
                state.set_compiled_class_hash(class_hash, compiled_class_hash)?;
            }
            Ok(())
        }
        Err(error) => Err(error)?,
        Ok(_) => {
            // Class is already declared, cannot redeclare.
            Err(TransactionExecutionError::DeclareTransactionError { class_hash })
        }
    }
}
