### Title
Starknet OS `execute_replace_class` accepts undeclared/zero class hashes, unlike the blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handling differs between the two execution engines that must agree on Starknet block semantics: the Rust `blockifier` (used by the sequencer to actually build blocks) validates that the target class hash is declared and is a Cairo-1 class before allowing the replacement, while the Starknet OS Cairo implementation used for re-execution/proving performs no such check at all — a gap the code itself flags as an open TODO.

### Finding Description
In the Rust blockifier, `replace_class` explicitly reads the compiled class for the requested `class_hash` (which errors if undeclared) and rejects Cairo-0 targets before writing the new class hash into contract state: [1](#0-0) 

The deprecated syscall handler enforces the same guarantee via `get_compiled_class(request.class_hash)?` prior to `set_class_hash_at`: [2](#0-1) 

Tests confirm this is intentional, security-relevant behavior — replacing with an undeclared hash must fail with "is not declared", and replacing a Cairo-1 contract with a Cairo-0 class hash must also fail: [3](#0-2) 

In contrast, the Starknet OS's Cairo implementation of the same syscall writes the new (unchecked) class hash directly into `contract_state_changes` with **no lookup or validation** that the class hash is declared: [4](#0-3) 

The comment at line 902 is explicit about the missing check: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The same unchecked pattern exists in the deprecated Cairo syscall path: [5](#0-4) 

This is structurally the same bug class as the reported issue: a value obtained from (or bypassing) a lookup that can legitimately be zero/undeclared is used downstream without validation in one code path, while the parallel/authoritative code path (the blockifier) does perform the validation. In the Augur case this caused unclear reverts; here it causes semantic divergence between the two engines that are both supposed to compute the exact same state transition for the same transaction trace.

### Impact Explanation
The Starknet OS re-execution is the mechanism that recomputes/validates the state transition and commitments for a block (an explicitly in-scope path per the rules: "Starknet OS re-execution"). Because the OS silently accepts a `replace_class` syscall with an undeclared (including the zero) class hash while the blockifier would reject/revert the identical call, the two engines can disagree about whether a given transaction is valid and about what the resulting contract's class hash is. This is a "honest-node divergence" / "wrong committed root" class of impact: if the OS's Cairo VM path is ever relied upon as the source of truth for a given execution mode (or is used to independently verify blocks), a state entry written with an unchecked class hash by the OS would not match what real clients calling that contract will observe, and any of that contract's subsequent execution will read a class hash for which no compiled class exists, causing wrong results, unrecoverable panics, or a corrupted state commitment for that contract downstream.

### Likelihood Explanation
This is reachable by any account contract executing `replace_class_syscall` with an attacker-chosen `class_hash`, including a class hash that has never been declared (e.g. `0x0`, or garbage). This requires nothing more than an ordinary transaction from a deployed account. The bug is explicitly acknowledged as an outstanding TODO in the code, confirming the omission is real and currently unaddressed rather than compensated for elsewhere in the file I inspected.

### Recommendation
Add the same declared-class and Cairo-version validation used in the blockifier's `replace_class` (`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`) to the OS Cairo implementations of `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, i.e., look up `contract_class_changes`/declared-class state for `class_hash` and fail the syscall (consistent with how the blockifier fails it) if it is not present or not the expected Cairo version, before writing the new `StateEntry`.

### Proof of Concept
1. Deploy an account contract that exposes a function calling `replace_class_syscall(class_hash)` with an arbitrary, undeclared `class_hash` (e.g., `0xdeadbeef` or `0x0`).
2. Submit this transaction to a sequencer using the blockifier — the transaction reverts with "... is not declared", as shown by the existing test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`.
3. Feed the same transaction trace/syscall sequence to the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo:881-920`), which contains no equivalent check (see the TODO at line 902) — the OS accepts the class-hash write into `contract_state_changes` unconditionally, producing a state update the blockifier would never have committed.

I could not fully verify, within the available tooling, whether some later/overall consistency pass (e.g., during final class-commitment-tree construction, in `os.cairo` or `state.cairo`) independently re-validates that every class hash appearing in `contract_state_changes` was actually declared, which could mitigate or fully absorb this gap. I was unable to locate such a check in `state.cairo` via search, but a complete manual review of `os.cairo`'s final consistency/output-generation logic would be needed to conclusively rule this out.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
