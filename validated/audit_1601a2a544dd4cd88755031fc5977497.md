### Title
Missing Declared-Class Verification in Starknet OS `execute_replace_class` Causes OS/Blockifier Divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall writes an unverified, caller-supplied `class_hash` directly into the contract's `StateEntry` used for state-root computation, without checking that the class hash corresponds to a declared class. This mirrors the reported bug class (an externally supplied identifier/address is used to mutate account/contract state without verifying it references a legitimate, previously-registered entity), but here the affected consumer is the Starknet OS re-execution/state-commitment path rather than a Solidity contract.

### Finding Description
In the OS's execution of the `replace_class` syscall, the code reads the `class_hash` from the syscall request and immediately builds a new `StateEntry` with that class hash, updating `contract_state_changes` — with an explicit acknowledgment that the required validation is missing: [2](#0-1) 

The comment `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` confirms there is no verification that `class_hash` exists in the contract-class tree (`contract_class_changes`) or was ever declared before the OS commits it into the contract's state entry.

By contrast, the blockifier's Rust implementation, which is the reference/normative execution engine, enforces this check on every `replace_class` call by reading the compiled class before writing the new class hash: [3](#0-2) 

This is validated by tests that exercise both VM and Native runnable Cairo1 contracts and assert the operation fails with `"is not declared"` when the class hash was never declared: [4](#0-3) 

The `StateEntry.class_hash` value produced by the OS's (unchecked) `execute_replace_class` flows directly into the contract-state commitment computation that determines the global state root: [5](#0-4) 

Because the blockifier enforces the "declared class" invariant but the OS program (used to prove/re-execute the same transactions and compute the committed state root) does not, the two components can disagree about whether a given `replace_class` invocation is legal, and about what class hash ends up recorded for a contract in the committed contract-state tree.

### Impact Explanation
The contract-state tree is expected to only ever contain class hashes that are backed by an entry in the declared-class tree; downstream logic (e.g., `get_class_hash_at`, `library_call`/`call_contract` dispatch, account-version checks such as `is_v1_bound_account_cairo0`) assumes this invariant holds. If the OS's state-commitment computation can embed an undeclared/invalid class hash for a contract address (whereas the blockifier's execution semantics reject such a call), this is a soundness gap between execution and proving/re-execution: the state root computed by the OS need not match what a fully-validated execution would have produced, i.e., a wrong committed contract-state root / class-tree divergence, and potentially unauthorized contract behavior once the trie contains a state entry that cannot be backed by any valid compiled class.

### Likelihood Explanation
`replace_class` is reachable directly from any Cairo1 contract using `replace_class_syscall`, i.e., from any unprivileged transaction sender who deploys or calls a contract that invokes it — no operator/prover/peer privilege is required. The vulnerable code path (`execute_replace_class` in `syscall_impls.cairo`) is part of the OS's general syscall-handling logic used whenever the OS re-executes transactions to build the committed state diff, so any transaction exercising this syscall exercises the unchecked path. The severity is bounded by whatever additional validation happens elsewhere in the OS pipeline (e.g. whether the OS separately cross-checks declared classes against the class-tree during finalization) that this investigation did not fully trace end-to-end within the available iterations; the TODO comment in the source, however, is explicit that the intended check is not yet implemented.

### Recommendation
Add a check in `execute_replace_class` (in `syscall_impls.cairo`) mirroring the blockifier's `get_compiled_class` check — verify that `class_hash` has a corresponding, non-zero entry in `contract_class_changes` (i.e., it was declared) before writing the new `StateEntry`, and reject/fault the syscall otherwise, consistent with the blockifier's behavior and matching Cairo-version compatibility rules (the blockifier also forbids replacing a V1 class hash with a V0 hash, as seen in the `SyscallExecutionError::ForbiddenClassReplacement` check) so that the OS's contract-state commitment logic never accepts undeclared or incompatible class hashes.

### Proof of Concept
1. An attacker deploys or interacts with a Cairo1 contract that exposes `test_replace_class(class_hash)`, calling `replace_class_syscall(class_hash)` with an arbitrary, never-declared `class_hash` value (analogous to test flow in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash`, which the blockifier correctly rejects with `"is not declared"`).
2. During Starknet OS re-execution of the same transaction trace (`execute_replace_class` in `syscall_impls.cairo`), no equivalent "declared class" check is performed — the OS updates `contract_state_changes` with the unverified `class_hash` regardless.
3. This state entry feeds into `compute_contract_state_commitment`/`calculate_global_state_root` (`commitment.cairo`), meaning the OS-computed committed root can embed a contract whose class hash was never declared, diverging from the invariant enforced by the blockifier's normal execution path. // Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
