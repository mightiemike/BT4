### Title
Unvalidated array-length felt in deprecated (Cairo0) syscall request parsing enables attacker-controlled oversized memory-range read — ([File: crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs])

### Summary
The Cairo0 ("deprecated") syscall request parser reads array lengths (`keys_len`, `data_len`, `calldata_len`, `payload_size`, etc.) directly as an attacker-controlled felt from VM memory and converts it to a `usize` with no upper-bound validation before using it to pull that many felts out of the VM's memory segments. This mirrors the CVE-2019-14934 pattern of trusting an unvalidated size field for a subsequent allocation/read, and is reachable from any Cairo0 contract that a transaction sender can declare and invoke.

### Finding Description
`read_felt_array` in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs` reads the array size directly as a felt from syscall-segment memory and immediately casts it to `usize` with no cap, then forwards it to `felt_range_from_ptr`, which calls `vm.get_integer_range(ptr, size)`: [1](#0-0) 

Compare with the *non-deprecated* (Cairo1/Sierra) syscall array reader, which instead derives the size from the difference between a validated start/end pointer pair (already bounded by the Sierra compiler's `SIERRA_ARRAY_LEN_BOUND` checks emitted into user code): [2](#0-1) 

For deprecated (Cairo0) syscalls there is no such compiler-enforced bound: the array length felt is read verbatim from the syscall request segment. Since Cairo0 contract bytecode is written directly by the contract author (there is no Sierra-level safety net forcing calldata/array lengths to be non-negative and bounded before syscalls like `EmitEvent`, `SendMessageToL1`, `CallContract`, `LibraryCall`, or `Deploy` are invoked), a malicious Cairo0 contract can place an arbitrary large felt in the length slot of the syscall request buffer it constructs, e.g.: [3](#0-2) [4](#0-3) 

and `read_calldata`/`read_call_params`, used by `CallContractRequest::read`, `LibraryCallRequest::read`, and `DeployRequest::read`, funnel through the same unvalidated `read_felt_array`: [5](#0-4) 

The resulting size is passed straight to `felt_range_from_ptr`, which calls `vm.get_integer_range(ptr, size)`: [6](#0-5) 

`get_integer_range` (cairo-vm) allocates a buffer sized by the caller-supplied `size` before it can determine whether that many cells actually exist in the segment. Feeding it an attacker-chosen huge value (bounded only by `usize::try_from` succeeding, i.e., up to `usize::MAX` on 64-bit hosts) drives an oversized allocation attempt deep in the syscall-parsing hot path, before any gas-based cost accounting for the array length has been applied (gas costs proportional to array/calldata length are computed only after the request is fully parsed).

### Impact Explanation
Any account can declare and invoke a Cairo0 (deprecated-class) contract; this is a normal, permissionless operation. A contract deliberately writing a huge value into an array-length slot of a syscall request (`EmitEvent`, `SendMessageToL1`, `CallContract`, `LibraryCall`, `Deploy`) forces every node re-executing that transaction (all sequencers/full nodes, including during Starknet OS re-execution) through the same unvalidated code path. If this triggers an allocation failure/panic rather than a clean `Result` error, it aborts the process deterministically on all honest nodes processing that transaction, which can prevent the network from confirming new transactions — one of the explicitly in-scope impacts. At minimum it is a deterministic, attacker-triggerable oversized-allocation attempt inside execution that every honest node performs identically, independent of any operator/proposer misbehavior.

### Likelihood Explanation
High reachability: this only requires declaring a Cairo0 class (still supported via `DeclareTransaction::V0`/`V1`) with custom raw Cairo assembly that writes a crafted syscall request segment, then invoking it — fully within reach of a single unprivileged transaction sender / contract deployer, with no special permissions needed.

### Recommendation
In `read_felt_array` (deprecated_syscalls/hint_processor.rs), validate the decoded `array_size` felt against a strict upper bound (e.g., the maximum calldata/array length already enforced elsewhere, such as `SIERRA_ARRAY_LEN_BOUND` or the resource-bounded max calldata length) and return a `DeprecatedSyscallExecutorBaseError` before calling `felt_range_from_ptr`/`vm.get_integer_range`, mirroring the bound already enforced implicitly for Cairo1/Sierra call data.

### Proof of Concept
1. Author raw Cairo0 assembly for a contract whose external function directly constructs an `EmitEvent` (or `SendMessageToL1`/`CallContract`) syscall request in the syscall segment, setting `keys_len` (or `data_len`/`payload_size`/`calldata_len`) to a very large felt (e.g., close to `usize::MAX`) while leaving the actual backing data pointer/segment small.
2. Declare this class via a standard `DECLARE` transaction (V0/V1) and deploy/invoke it via a standard `INVOKE` transaction that triggers the crafted external function.
3. During execution, `CallContractRequest::read`/`EmitEventRequest::read`/`SendMessageToL1Request::read` call `read_felt_array`, which converts the crafted felt to `usize` and calls `felt_range_from_ptr` → `vm.get_integer_range(ptr, huge_size)`, forcing an oversized allocation attempt in every executing node (block builder and re-executing nodes) for that transaction.

pub fn read_felt_array<TErr>(vm: &VirtualMachine, ptr: &mut Relocatable) -> Result<Vec<Felt>, TErr>
where
    TErr: From<StarknetApiError>
        + From<VirtualMachineError>
        + From<MemoryError>
        + From<MathError>
        + From<TryFromBigIntError<BigUint>>,
{
    let array_size = felt_from_ptr(vm, ptr)?;
    // An empty array's data pointer may be a felt-zero null (`cast(0, felt*)`) rather than a real
    // segment.
    if array_size == Felt::ZERO {
        *ptr = (*ptr + 1)?;
        return Ok(vec![]);
    }
    let array_data_start_ptr = vm.get_relocatable(*ptr)?;
    *ptr = (*ptr + 1)?;

    Ok(felt_range_from_ptr(vm, array_data_start_ptr, usize::try_from(array_size.to_biguint())?)?)
}

pub fn read_felt_array<TErr>(vm: &VirtualMachine, ptr: &mut Relocatable) -> Result<Vec<Felt>, TErr>
where
    TErr: From<StarknetApiError> + From<VirtualMachineError> + From<MemoryError> + From<MathError>,
{
    // If the start and end pointers are the same, the array is empty.
    // This check is necessary to handle the case where both pointers are zero, and thus are not
    // relocatable values.
    let array_start = vm.get_maybe(&*ptr);
    if array_start.is_some() && array_start == vm.get_maybe(&(*ptr + 1_usize)?) {
        *ptr = (*ptr + 2)?;
        return Ok(vec![]);
    }

    let array_data_start_ptr = vm.get_relocatable(*ptr)?;
    *ptr = (*ptr + 1)?;
    let array_data_end_ptr = vm.get_relocatable(*ptr)?;
    *ptr = (*ptr + 1)?;
    let array_size = (array_data_end_ptr - array_data_start_ptr)?;

    Ok(felt_range_from_ptr(vm, array_data_start_ptr, array_size)?)

pub fn felt_range_from_ptr(
    vm: &VirtualMachine,
    ptr: Relocatable,
    size: usize,
) -> Result<Vec<Felt>, VirtualMachineError> {
    let values = vm.get_integer_range(ptr, size)?;
    // Extract values as `Felt`.
    let values = values.into_iter().map(|felt| *felt).collect();
    Ok(values)
}
