### Title
PoisonMicroblock accepted for a single, non-conflicting microblock header (duplicated header) - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`handle_poison_microblock` and its sole guard `check_microblock_header_signer` only verify that `mblock_header_1` and `mblock_header_2` recover to the same public-key-hash; neither this function nor the mempool-level pre-check verifies that the two headers are actually distinct or conflicting (different `block_hash()`, `tx_merkle_root`, or signature). An attacker can take any single, legitimately-published microblock header from an honest miner, duplicate it as both `mblock_header_1` and `mblock_header_2`, and have the transaction accepted as valid proof of equivocation.

### Finding Description
The claimed equality is: **reward paid == exactly one valid double-signature (two distinct, conflicting microblock headers)**. The code breaks this equality on both the consensus path and the mempool path:

- `check_microblock_header_signer` at [1](#0-0)  recovers `pkh1` and `pkh2` via `check_recover_pubkey()` and only asserts `pkh1 != pkh2` fails, i.e. it rejects only when the keys *differ*. It never asserts `mblock_header_1 != mblock_header_2`, nor checks `tx_merkle_root`, `prev_block`, or `block_hash()` distinctness.
- `handle_poison_microblock` at [2](#0-1)  calls only `check_microblock_header_signer` before proceeding to load the microblock pubkey-hash height and register a poison report via `env.global_context.database.insert_microblock_poison(...)` at [3](#0-2) .
- The mempool-level sanity check in `blocks.rs` similarly checks `sequence`, `prev_block`, `version` equality and `pkh1 == pkh2`, but never checks that the headers are non-identical: [4](#0-3) . Ironically the rejection variant is named `PoisonMicroblocksDoNotConflict`, implying the intent was to require an actual conflict, but the implemented checks are satisfied trivially when `mblock_header_1 == mblock_header_2` bit-for-bit.

Exploit flow: an attacker observes any legitimately signed microblock header `H` broadcast by an honest miner (public network data, no private key needed). They construct `TransactionPayload::PoisonMicroblock(H.clone(), H.clone())`, sign it with their own (attacker) key as a normal `StacksTransaction`, and submit it. Since `H.check_recover_pubkey() == H.check_recover_pubkey()` trivially, `check_microblock_header_signer` returns `Ok(pkh)` for the honest miner's real pubkey hash. `handle_poison_microblock` then finds `get_microblock_pubkey_hash_height(&pubkh)` (a real, previously-registered honest miner) and calls `insert_microblock_poison`, marking that miner's block as containing a slashable equivocation — despite the miner never having produced two conflicting microblocks at that sequence number.

### Impact Explanation
Per the code comments in `handle_poison_microblock` ("entitled to a commission of the punished miner's coinbase"), a successful poison report affects the coinbase reward maturation/payment for the targeted miner's block, redirecting/reducing the reward to the attacker/reporter. This is block-reward theft/mis-payment against an honest miner who never equivocated, triggerable by any single unprivileged network participant, and repeatable against every historical microblock header (bounded by `MINER_REWARD_MATURITY`).

### Likelihood Explanation
No special privilege, stake, or majority position is required. The attacker only needs: (1) any publicly-broadcast, legitimately-signed microblock header from a target miner (trivially obtainable from the network), and (2) the ability to submit an ordinary signed transaction (fee can be `0`, as demonstrated in the test at [5](#0-4) ). This is fully repeatable against any miner whose microblock pubkey hash is still within the maturity window.

### Recommendation
In `check_microblock_header_signer` (or immediately in `handle_poison_microblock`), explicitly enforce that the two headers are distinct and genuinely conflicting: assert `mblock_header_1.block_hash() != mblock_header_2.block_hash()` (or equivalently, that signatures/`tx_merkle_root` differ) in addition to the existing sequence/prev_block/version/pkh equality checks. Apply the same fix to the mempool-level `PoisonMicroblocksDoNotConflict` check in `blocks.rs`.

### Proof of Concept
Rust integration test plan in `stackslib/src/chainstate/stacks/db/transactions.rs`:
1. Set up a `TestChainstateBuilder` chainstate and register an honest miner's microblock pubkey hash via `StacksChainState::insert_microblock_pubkey_hash`, mirroring the setup in `process_poison_microblock_multiple_same_block` at [6](#0-5) .
2. Instead of creating two distinct microblocks (`mblock_1 != mblock_2` as in the existing test), construct a single signed microblock `mblock = make_signed_microblock(&block_privk, &privk, BlockHeaderHash([0x11; 32]), 123)` and clone its header into both slots: `TransactionPayload::PoisonMicroblock(mblock.header.clone(), mblock.header.clone())`.
3. Assert equality on both sides of the broken invariant before tracing: `assert_eq!(mblock.header, mblock.header.clone())` (headers are bit-identical — not a fork).
4. Sign and submit via `StacksChainState::process_transaction`.
5. Assert that processing **currently succeeds** (`.unwrap()` does not error) and that `StacksChainState::get_poison_microblock_report` returns `Some((reporter_addr, 123))` — proving a non-existent equivocation was registered against the honest miner, which should instead return `Err(Error::InvalidStacksTransaction(..))` once the missing distinctness check is added.

        mblock_hdr_1: &StacksMicroblockHeader,

    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {

                format!("Failed to recover public key: {:?}", &e),
                false,
            )

                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
