### Title
OAuth state-nonce cookie's server-side validation never enforces its own `expires` deadline - (File: `packages/apps/shopify-api/runtime/http/cookies.ts`)

### Summary
The Shopify OAuth flow issues a short-lived, HMAC-signed `STATE_COOKIE_NAME` nonce cookie with a 60-second `expires` value, intending to bound the window in which an OAuth authorization can be completed. However, the cookie-signature verification logic that later accepts this cookie in the callback never inspects or enforces that `expires` value — exactly mirroring the LPDA bug class where a deadline field (`endTime`) is set on state but never checked at the point of use.

### Finding Description
`begin()` in `packages/apps/shopify-api/lib/auth/oauth/oauth.ts` sets the CSRF-protection state cookie with a hard 60-second lifetime: [1](#0-0) 

When the merchant/browser returns to `/auth/callback`, the cookie is retrieved and validated purely via signature check: [2](#0-1) 

That validation delegates to `Cookies.getAndVerify` → `Cookies.isSignedCookieValid`: [3](#0-2) 

This routine checks cookie existence, non-empty value, and HMAC signature match against `this.keys`, but at no point reads or compares the parsed `expires` field of the received cookie (`CookieData.expires`, populated by `Cookies.parseCookies` at lines 100-107 of the same file) against the current time. The `maxAge`/`expires` metadata that is set when the cookie is issued (`begin()`, and similarly the long-lived `SESSION_COOKIE_NAME` cookie set in `callback()` at lines 219-230) is therefore purely advisory to the client — the server-side acceptance logic treats a correctly-signed cookie as valid indefinitely, regardless of how stale it is, in the same way the LPDA contract stored `endTime` but never gated `buy()` on it.

### Impact Explanation
The intended security property — that the OAuth CSRF nonce cookie (and, by the same code path, the online-session cookie for non-embedded apps) is only usable within its declared TTL — is not actually enforced by the app. Enforcement depends entirely on browsers honoring `Expires`/`Max-Age`. Any situation where a previously-valid signed cookie is replayed to the server after its intended expiry (stale browser cache/tab restore, cookie jars in non-standard HTTP clients used against the callback endpoint, cookie persisted by a proxy/service worker, or simple non-browser replay of a captured `Cookie` header) will be accepted as if freshly issued. For the OAuth state cookie this widens the window during which a CSRF-style authorization-code injection can be completed using an old nonce; for the online-session cookie this extends acceptance of a session token past its intended online-access-token lifetime window as enforced by the app layer (the underlying Shopify access token itself will still eventually be rejected by Shopify's API, limiting the blast radius, but the app's own defense-in-depth check is missing).

### Likelihood Explanation
Exploitation does not require any privileged access — it only requires the ability to (re)present a previously-issued, correctly-signed cookie value to the callback/session-lookup endpoints, which are reachable by any anonymous/merchant-initiated HTTP request in the OAuth flow. The severity is bounded because the signature itself is still required and the cookie value would need to have been legitimately issued at some point (this is not a full nonce-forgery bug), so likelihood is moderate rather than trivial, similar to how the original LPDA finding was rated Medium.

### Recommendation
Add an explicit expiry check inside `Cookies.isSignedCookieValid` (or `getAndVerify`) in `packages/apps/shopify-api/runtime/http/cookies.ts`: parse the cookie's `expires` field from `receivedCookieJar` and reject (return `false`/`undefined` and delete the cookie) if `Date.now()` is past that timestamp, mirroring the recommended `require(block.timestamp <= endTime)` pattern from the referenced report — i.e., enforce the deadline at the point of validation rather than relying solely on the value set at issuance/client-side honoring.

### Proof of Concept
Conceptual PoC (cannot be executed here, but demonstrates the gap):
1. Start OAuth (`shopify.auth.begin`) to receive a `Set-Cookie: shopify_app_state=<nonce>; shopify_app_state.sig=<hmac>; expires=<+60s>`.
2. Capture the raw `Cookie` header value before it expires.
3. Wait more than 60 seconds (simulating a delayed/replayed callback request), then send `GET /auth/callback?...&state=<nonce>&hmac=...` with the captured `Cookie` header attached directly (bypassing any browser expiry enforcement, e.g. via `curl` or a test harness).
4. `cookies.getAndVerify(STATE_COOKIE_NAME)` in `oauth.ts` (lines 168-176) still returns the nonce because `isSignedCookieValid` in `cookies.ts` only checks the HMAC signature, never the `expires` timestamp — the callback proceeds as if the cookie were still fresh. [1](#0-0) [4](#0-3)

    this.updateHeader();

  async setAndSign(
    name: string,
    value: string,
    opts: Partial<CookieData> = {},
  ): Promise<void> {
    if (!this.canSign) {
      throw Error('No keys provided for signing.');
    }
    this.set(name, value, opts);
    const sigName = `${name}.sig`;
    const signature = await createCookieSignature(this.keys[0], value);
    this.set(sigName, signature, opts);
    this.updateHeader();
  }

  async isSignedCookieValid(cookieName: string): Promise<boolean> {
    const signedCookieName = `${cookieName}.sig`;
    if (
      !this.cookieExists(cookieName) ||
      !this.cookieExists(signedCookieName)
    ) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }
    const cookieValue = this.get(cookieName);
    const signature = this.get(signedCookieName);

    if (!cookieValue || !signature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    const allCheckSignatures = await Promise.all(
      this.keys.map((key) => createCookieSignature(key, cookieValue)),
    );

    const validSignature = allCheckSignatures.some((checkSignature) =>
      safelyCompareSignatures(checkSignature, signature),
    );

    if (!validSignature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    return true;
  }
