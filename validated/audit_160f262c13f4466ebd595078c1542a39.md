### Title
Spot-price AMM quote with fixed 5% slippage in protocol-executed PRC20→PC swaps is sandwichable by unprivileged users - ([File: x/uexecutor/keeper/evm.go], [File: x/uexecutor/keeper/execute_inbound_gas.go], [File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go], [File: x/uexecutor/keeper/outbound.go])

### Summary
The external report's bug class is: an individual, unprivileged actor's action (a variable-side withdrawal) forces a shared, price/yield-generating resource (the Lido stake) to be drawn down using a value that depends on real-time state, unpredictably degrading the outcome for others sharing that resource. The Push Chain analog is the module's use of a live Uniswap V3 `QuoterV2` **spot** quote (`GetSwapQuote`) as the pricing basis for protocol-executed PRC20↔PC swaps (`depositPRC20WithAutoSwap`, `refundUnusedGas`). Because the quote is fetched from current pool reserves rather than a manipulation-resistant/TWAP source, and the accepted slippage band is a fixed 5% around that already-current spot price, an unprivileged external actor who trades against the same on-chain AMM pool immediately before a Universal Validator vote finalizes an inbound/outbound can shift the "expected" conversion rate that every other user of that pool implicitly relies on, extracting value from the protocol-controlled swap while still passing the 5% slippage check.

### Finding Description
Two code paths perform protocol-originated (module-signed) AMM swaps using a Quoter-based spot price with a fixed 5% tolerance band:

1. Inbound `GAS` / `GAS_AND_PAYLOAD` deposits: `GetSwapQuote` is fetched, then `minPCOut = quote * 95/100` is computed and passed to `CallPRC20DepositAutoSwap`. [1](#0-0) [2](#0-1) 

2. Outbound excess-gas refunds: the same pattern is used in `applyGasRefund`, fetching a quote via `getSwapQuoteForRefund` and using it (with 5% slippage) to swap the gas token back to PC before crediting the sender. [3](#0-2) 

The quote itself is obtained via `QuoterV2.quoteExactInputSingle`, a direct read of current pool state (`SqrtPriceLimitX96: 0`), i.e., an instantaneous spot price rather than a TWAP or otherwise manipulation-resistant oracle: [4](#0-3) 

Because the pool backing `prc20`/WPC (or gas token/WPC) conversions is a normal, publicly tradable Uniswap V3 pool seeded during setup (see local pool creation script referencing `pool-manager.js create-pool`), any unprivileged user can move the pool's reserves before a pending inbound/outbound vote is finalized. Since UV votes (`MsgVoteInbound`/`MsgVoteOutbound`) are public mempool/chain activity and the swap quote is fetched fresh at execution time inside the same Cosmos transaction that also performs the swap, the only manipulation window an attacker needs is *before* that transaction executes (front-run the whole vote-finalizing tx), not inside it. This mirrors the Sherlock report's core issue: an individual actor's ordinary action against a shared, price-bearing resource (there: the Lido stake; here: the AMM reserve) degrades the expected value delivered to other participants of that shared resource (there: other variable stakers; here: other GAS/GAS_AND_PAYLOAD depositors and outbound-refund recipients whose conversion executes with attacker-skewed pricing), and the existing guard (5% slippage) does not protect against the underlying price already being manipulated at quote time.

### Impact Explanation
This falls under "corruption of PRC20 or native asset accounting" and "gas fee accounting" in the allowed impact gate: an attacker can degrade the PC amount minted to users during `GAS`/`GAS_AND_PAYLOAD` inbound execution, and degrade the PC amount refunded during excess-gas refunds, capturing the difference via a classic sandwich against the module-signed swap. The loss is bounded by the 5% band per individual swap, but is systematically extractable against every protocol-executed swap that touches a given pool, and the attacker is an ordinary unprivileged trader — no validator or relayer compromise is required.

### Likelihood Explanation
Medium. It requires the attacker to identify low-liquidity PRC20/WPC pools (increasing price-impact-per-dollar) and to predict/observe an impending large protocol swap (visible once a quorum of UV votes accumulates or is about to be cast, since these are on-chain public transactions). This is analogous in likelihood to any MEV/sandwich opportunity against a DEX without TWAP protection, which is a well-established and repeatedly-exploited attack pattern.

### Recommendation
Use a manipulation-resistant price source (TWAP over multiple blocks, or an off-chain aggregated price with deviation checks against the on-chain spot) instead of `QuoterV2`'s instantaneous quote when computing `minPCOut` for `depositPRC20WithAutoSwap` and `refundUnusedGas`. Alternatively, tighten protections by capping per-transaction price impact directly in the pool interaction, or by giving depositors/refund recipients the option to specify their own acceptable `minPCOut` rather than having the protocol compute it unilaterally from a spot quote fetched moments before execution.

### Proof of Concept
1. Attacker observes a pending `Inbound` of `TxType_GAS_AND_PAYLOAD` accumulating UV votes (public on-chain), or observes an `OutboundTx` about to receive its quorum `MsgVoteOutbound` with `gasFeeUsed < gasFee`.
2. Immediately before the finalizing vote transaction is included, attacker submits a large swap on the same `prc20AddressHex`/WPC (or `gasToken`/WPC) Uniswap V3 pool referenced by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`, pushing the pool price against PC.
3. The finalizing vote transaction executes `gasAndPayloadDepositAutoSwap` (or `applyGasRefund`), calling `GetSwapQuote` which now returns a worse rate, computes `minPCOut = quote*95/100` from that already-degraded price, and calls `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas`, which happily executes within the 5% band of the already-bad price. [5](#0-4) 
4. Attacker reverses the swap afterward, capturing the spread; the depositor/refund recipient receives less PC than fair market value would have provided.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
