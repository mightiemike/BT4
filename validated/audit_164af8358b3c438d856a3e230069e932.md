## Title
Missing binding of client-side proving `proof_facts`/`proof` to the executing transaction's identity (sender, calldata, nonce) allows account-takeover-style bypass of `__validate__` - (File: `crates/blockifier/src/transaction/account_transaction.rs`)

### Summary
The reported CVE-class bug is: a signed authentication artifact (Apple ID token) is accepted after checking its signature, but the *claims that bind it to a specific principal/audience/time* (`sub`, `aud`, `exp`) are never validated, so a token issued for one context can be replayed to authenticate as a different account/app. The sequencer's client-side-proving feature for Invoke V3 transactions (`proof_facts` / `proof`) has the same structural shape: a cryptographically checked artifact (a SNARK proof over a "virtual OS" run) is accepted based on checking *provenance* facts (program hash, proof version, base block hash, OS config hash) but the on-chain validators never check that the proof's payload is bound to the specific transaction currently being processed (its sender, calldata/entry point, or nonce).

### Finding Description
`AccountTransaction::validate_proof_facts` [1](#0-0)  and the OS-side `check_proof_facts` [2](#0-1)  only validate:
- the proof version and virtual-OS program hash are on an allow-list,
- the referenced base block number/hash actually correspond to a stored block hash,
- the OS config hash matches.

None of these checks (nor `VirtualOsOutputHeader`, which only carries `output_version, base_block_number, base_block_hash, starknet_os_config_hash, n_l2_to_l1_messages` [3](#0-2) ) tie the proof to the sender address, calldata, entry point, or nonce of the transaction it is attached to. The proof-manager cache/lookup itself is keyed only by `proof_facts.hash()` [4](#0-3)  and the gateway's proof-side check is only structural consistency (`has_proof_facts == has_proof`) plus size limits [5](#0-4) .

This mirrors the CVE's root cause precisely: signature/proof validity is checked, but the claims that would scope the credential to *this* principal/context (`aud`, `sub` equivalent) are not checked at the point of use.

### Impact Explanation
If `proof_facts`/`proof` are meant to let the sequencer skip or shortcut the expensive `__validate__` re-execution (the comment on `run_validate` states it "is responsible for signature verification" [6](#0-5) ), then absence of a binding check between the accepted proof and the actual sender/calldata/nonce means a proof legitimately produced for one account's off-chain-validated invoke could be replayed to satisfy validation for a transaction issued against a *different* sender address or with *different* calldata, provided it references a still-fresh stored block hash and the same OS config/program hash. That is a `__validate__`-bypass / signature-check bypass, i.e., unauthorized account action — matching "Accept only ... unauthorized account action" in the validation criteria.

I was not able to fully trace (within the tool budget) the exact code path in `transaction_impls.cairo`/blockifier that determines *whether the presence of valid `proof_facts` actually skips or shortens `run_validate`/signature verification* versus merely being informational/fee-related. The snippets found (`transaction_impls.cairo` lines 271-360) show `check_proof_facts` is called and then `run_validate` still executes unconditionally in the flow shown [7](#0-6) , which would mean `__validate__` is *not* actually skipped in the current build and the vulnerability's practical exploitability (full validate bypass) is unconfirmed. This is a material open question that a background agent with full repository access should resolve before treating this as exploitable.

### Likelihood Explanation
Reaching this code requires only submitting a standard Invoke V3 transaction with `client-side proving` enabled (`allow_client_side_proving` config) with attacker-controlled `proof_facts`/`proof` referencing a real, previously-stored block hash — i.e., it is reachable by any unprivileged transaction sender, satisfying the reachability requirement. However, exploitation additionally requires obtaining a validly-signed proof for the target program hash/OS config from the real proving pipeline (via `starknet_proof_verifier::verify_proof`), which is a non-trivial precondition, and — pending the confirmation noted above — depends on `proof_facts` actually being able to substitute for or bypass `__validate__`'s account-contract signature check.

### Recommendation
Bind the proof facts cryptographically to the specific transaction they are meant to authorize (e.g., include `sender_address`, `calldata`/entry-point hash, and `nonce` inside the `VirtualOsOutputHeader`/`ProofFactsVariant` and assert equality against the actual transaction fields in both `AccountTransaction::validate_proof_facts` and `check_proof_facts`), analogous to validating `aud`/`sub` claims against the current request context rather than trusting only the underlying proof's cryptographic validity.

### Proof of Concept
Not constructible with current tooling/context — a concrete PoC would require confirming (1) whether `proof_facts` validity actually short-circuits `run_validate`/signature checking anywhere in `transactions_impls.cairo` or `account_transaction.rs`, and (2) obtaining/crafting a real proof accepted by `starknet_proof_verifier::verify_proof` for a program hash on the `allowed_virtual_os_program_hashes` list. Given the reasoning-effort and tool budget constraints of this session, I could not fully verify point (1); this should be validated in a follow-up session with full codebase access (e.g., tracing `has_client_side_proof`, `run_validate`, and how `proof_facts` participate in the OS's decision to invoke or skip `__validate__`) before treating this finding as confirmed exploitable rather than a structural analog concern.

    fn validate_proof_facts(
        &self,
        block_context: &BlockContext,
        state: &mut dyn State,
    ) -> TransactionPreValidationResult<()> {
        // Only Invoke V3 transactions can carry proof facts.
        let Transaction::Invoke(invoke_tx) = &self.tx else {
            return Ok(());
        };
        if invoke_tx.version() < TransactionVersion::THREE {
            return Ok(());
        }

        // Parse proof facts.
        let proof_facts = invoke_tx.proof_facts();
        let snos_proof_facts = match ProofFactsVariant::try_from(&proof_facts)
            .map_err(|e| TransactionPreValidationError::InvalidProofFacts(e.to_string()))?
        {
            ProofFactsVariant::Empty => return Ok(()),
            ProofFactsVariant::Snos(snos_proof_facts) => snos_proof_facts,
        };
        let os_constants = &block_context.versioned_constants.os_constants;

        if !os_constants.allowed_proof_versions.contains(&snos_proof_facts.proof_version.as_felt())
        {
            return Err(TransactionPreValidationError::InvalidProofFacts(format!(
                "Proof version {} is not allowed under this protocol version.",
                snos_proof_facts.proof_version
            )));
        }

        // Validate the program hash.
        let allowed = &os_constants.allowed_virtual_os_program_hashes;
        if !allowed.contains(&snos_proof_facts.program_hash) {
            return Err(TransactionPreValidationError::InvalidProofFacts(format!(
                "Virtual OS program hash {} is not allowed",
                snos_proof_facts.program_hash
            )));
        }

        // Validate the block hash and block number.
        let proof_block_hash = snos_proof_facts.block_hash.0;
        let proof_block_number = snos_proof_facts.block_number.0;
        Self::validate_proof_block_number(
            proof_block_number,
            block_context.block_info.block_number,
        )?;
        Self::validate_proof_block_hash(proof_block_hash, proof_block_number, os_constants, state)?;

        // Validate the config hash.
        let virtual_os_config_hash = block_context.virtual_os_config_hash();
        let proof_config_hash = snos_proof_facts.config_hash;
        if virtual_os_config_hash != proof_config_hash {
            return Err(TransactionPreValidationError::InvalidProofFacts(format!(
                "Virtual OS config hash mismatch. Computed virtual OS config hash: \
                 {virtual_os_config_hash}, expected virtual OS config hash: {proof_config_hash}."
            )));
        }

        Ok(())
    }

// Validates that the proof facts of an invoke transaction are of a valid virtual OS run.
func check_proof_facts{range_check_ptr, contract_state_changes: DictAccess*}(
    proof_facts_size: felt,
    proof_facts: felt*,
    current_block_number: felt,
    virtual_os_config_hash: felt,
) {
    if (proof_facts_size == 0) {
        return ();
    }

    assert_le(ProofHeader.SIZE + VirtualOsOutputHeader.SIZE, proof_facts_size);

    // Validate the proof header.
    static_assert ProofHeader.SIZE == 3;
    let proof_header = cast(proof_facts, ProofHeader*);
    assert proof_header.proof_variant = VIRTUAL_SNOS;
    assert is_program_hash_allowed(proof_header.program_hash) = TRUE;
    // Only proof version V1 is accepted.
    with_attr error_message("Unsupported proof version") {
        assert proof_header.proof_version = PROOF_VERSION_V1;
    }

    // Validate the virtual OS output header.
    let os_output_header = cast(&proof_facts[ProofHeader.SIZE], VirtualOsOutputHeader*);

    with_attr error_message("Virtual OS output version is not supported") {
        assert os_output_header.output_version = VIRTUAL_OS_OUTPUT_VERSION;
    }

    // Validate that the proof facts block number is not too recent.
    // (This is a sanity check - the following non-zero check ensures that the block hash is
    // not trivial).
    assert_nn_le(
        os_output_header.base_block_number, current_block_number - STORED_BLOCK_HASH_BUFFER
    );
    // Not all block hashes are stored in the contract; Make sure the requested one is not trivial.
    assert_not_zero(os_output_header.base_block_hash);

    // validate that the proof facts block hash is the true hash of the proof facts block number.
    read_block_hash_from_storage(
        block_number=os_output_header.base_block_number,
        expected_block_hash=os_output_header.base_block_hash,
    );

    // validate that the proof facts config hash is the true hash of the OS config.
    assert os_output_header.starknet_os_config_hash = virtual_os_config_hash;

    return ();
}
