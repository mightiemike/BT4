### Title
Stale cached vault index/lindex after `socialize-debt` bypasses the market's per-block accrual cache - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
The market contract memoizes each vault's accrual result (`index`/`lindex`) in a per-block cache (`index-cache`) keyed by `{timestamp: stacks-block-time, aid}` so that repeated `accrue-user-debts` / `accrue-user-collateral` calls within the same block reuse a single read instead of re-invoking the vault. However, `socialize-debt` on the vault contracts mutates `lindex` directly — without calling `accrue` and without any interaction with the market's `index-cache` — so a `liquidate` call that triggers bad-debt socialization leaves the market's cached `lindex` stale for the rest of the block.

### Finding Description
`accrue-and-cache` in the market contract caches the vault's `{index, lindex}` the first time it is queried in a block and serves every subsequent call from the cache for the remainder of that block: [1](#0-0) 

`accrue-user-debts` / `accrue-user-collateral` fold over a user's positions and call `accrue-and-cache` (via `unwrap-panic`) purely for its caching side effect before the market uses the vault's index/lindex values to value collateral/debt: [2](#0-1) 

Separately, when a liquidation results in bad debt, the market routes to `vault-socialize-debt`, which calls the vault's public `socialize-debt`: [3](#0-2) 

`socialize-debt` on the vault writes `lindex` down directly to reflect the loss, but does **not** call `accrue` first and has no path to invalidate or update the market's `index-cache`: [4](#0-3) 

Because the market's cache key is only `{timestamp, aid}` (i.e., valid for the whole block) and `socialize-debt` bypasses the cache entirely, any market-side computation in the *same block*, *after* the socialization but that re-uses the cached `lindex` (because the cache was already warmed earlier in the block for that `aid`), will use the pre-socialization (higher) `lindex` instead of the corrected, written-down value. The vault's own `lindex`/`index` state variables are correct, but the market contract's mirrored cache is not synchronized with that mutation.

### Impact Explanation
`lindex`/`index` values gate valuation of zToken collateral and outstanding debt used by the market for solvency checks in `borrow`, `collateral-remove`, and subsequent `liquidate` calls within the same block. If a liquidation socializes bad debt (writing `lindex` down) and a later transaction in the same block relies on the market's stale cached `lindex` for that asset, debt/collateral USD values computed by the market will be inflated relative to the true, post-loss-absorption value. This can let a borrower whose position should now be under-collateralized (post-socialization) avoid liquidation, or let another liquidator/borrower extract value based on stale collateral valuation — a temporary mispricing that can result in funds being extracted or frozen incorrectly for other users of the same vault, i.e. temporary freezing/theft of unclaimed value tied to the affected positions for that block.

### Likelihood Explanation
This requires: (1) at least one earlier transaction in the block that warms the market's `index-cache` for the affected `aid` (any borrow/collateral touch), (2) a `liquidate` call in the same block that triggers `socialize-debt` for that same `aid`, and (3) a further transaction in that block relying on the now-stale cached value for the same asset. All three steps are ordinary user-triggered interactions (no privileged access, no oracle manipulation, no DAO action) and are only constrained by transaction ordering within a single block, which is realistic to construct/target.

### Recommendation
Invalidate or refresh the market's `index-cache` entry for an asset whenever `socialize-debt` is invoked on the corresponding vault (e.g., have `vault-socialize-debt`/`socialize-debt` return the updated `{index, lindex}` and have the market overwrite `index-cache` with it), or remove the per-block cache and always read live vault state for any downstream valuation used in the same transaction chain as a liquidation.

### Proof of Concept
1. In block N, Alice (or anyone) triggers `borrow`/`collateral-add` for asset X, which calls `accrue-user-debts`/`accrue-user-collateral` → `accrue-and-cache(X)`, populating `index-cache[{timestamp: T, aid: X}]` with the current `{index, lindex}`.
2. Later in the same block N, a `liquidate` call on a different borrower with bad debt in asset X invokes `vault-socialize-debt(X, amount)` → vault's `socialize-debt`, which directly `var-set`s the vault's `lindex` to a lower value, without touching `index-cache`. [5](#0-4) 
3. Still in block N, another transaction touching asset X (e.g., a further `borrow`, `collateral-add/remove`, or `liquidate` check) calls `accrue-user-debts`/`accrue-user-collateral` → `accrue-and-cache(X)`. Because `index-cache[{timestamp: T, aid: X}]` already exists, the cache-HIT branch returns the pre-socialization `lindex`, not the vault's real, written-down value. [1](#0-0) 
4. This transaction's solvency/health computations for positions in asset X use the stale, higher `lindex`, mispricing collateral/debt relative to the true post-loss-socialization state.

Note: I could not directly trace, within the token budget available, the exact downstream consumers of `accrue-and-cache`'s returned `{index, lindex}` values beyond `accrue-user-debts`/`accrue-user-collateral` (e.g., the precise health-factor/USD valuation functions in `v0-4-market.clar`). This part of the exploit chain is inferred from the caching mechanism and would need to be confirmed by inspecting the full valuation logic that consumes these cached values — I'd recommend starting a Devin session to trace this exact call path in full before treating this as fully confirmed.

```text
(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
```

```text
(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
```
