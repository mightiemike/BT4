## Finding Analysis

### Title
Unvalidated `profile` path parameter allows path-traversal within the internal LOOP debug/pprof forwarding request - (`core/web/loop_registry.go`)

### Summary
`pluginPPROFHandler` builds the forwarded pprof request by directly concatenating the raw, unsanitized `gc.Param("profile")` value into the destination URL's path segment before calling `fmt.Sprintf`, with no allow-list of valid pprof profile names (`cmdline`, `profile`, `symbol`, `trace`, `heap`, `goroutine`, etc.). This lets a caller of this endpoint control the destination path on the internal LOOP debug server rather than being confined to `/debug/pprof/*`.

### Finding Description
In `core/web/loop_registry.go`:
```go
pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
``` [1](#0-0) 

`gc.Param("profile")` is spliced directly into the format string before it is passed to `fmt.Sprintf` and is never validated against the fixed set of pprof endpoints. The only check performed before this line is `l.registry.Get(pluginName)`, which validates that `name` corresponds to a registered plugin [2](#0-1)  — it does not constrain `profile` in any way. The resulting URL is passed unmodified to `l.doRequest`, which performs an outbound `http.NewRequestWithContext` / `http.DefaultClient.Do` call [3](#0-2) .

Because the host and port (`l.loopHostName`, `p.EnvCfg.PrometheusPort`) are supplied as separate `%s`/`%d` verbs that are resolved *before* the attacker-controlled string is appended, the attacker cannot redirect the authority (host/port) portion of the URL — only the path suffix after `/debug/pprof/` is influenced. This means the "SSRF-like" concern in the question is real for reaching *arbitrary paths on the same host:port* (the LOOP plugin's own diagnostic HTTP server, which also serves `/metrics` on the identical port per `pluginMetricHandler`), but it does **not** allow redirecting the request to an arbitrary unrelated internal host, since the authority is fixed by the plugin registry entry, not by user input.

### Impact Explanation
An attacker who can reach this endpoint (with a valid, already-registered plugin `name`) can supply a `profile` value such as `../metrics` or other path-traversal/arbitrary-suffix strings to make the forwarded request target unintended paths on the LOOP plugin's internal HTTP server, rather than only the documented `/debug/pprof/*` set. Because Go's `net/http.ServeMux` (used by the pprof/metrics server) canonicalizes `..` segments via `path.Clean` and typically issues a redirect rather than serving unintended handlers directly, and because host/port cannot be attacker-redirected, the practically exploitable surface is limited to endpoints already exposed on that same internal port (e.g., `/metrics`), not arbitrary internal services or hosts. This is a real input-validation gap and violates the intended invariant that only pprof sub-paths should be reachable via this route, but it does not itself constitute full arbitrary-host SSRF, secret disclosure of unrelated services, or node compromise.

### Likelihood Explanation
Reaching this handler requires knowledge of a valid, currently-registered LOOP plugin name (enforced by `LoopRegistry.Get`) [2](#0-1) . I was unable to confirm, within the available tool budget, whether the route registered for `pluginPPROFHandler` in `core/web/router.go` sits behind session/authentication middleware or is otherwise exposed without authentication — this is a material precondition that could not be fully verified from the code paths inspected. If the route requires authenticated node-operator/admin session (which is typical for chainlink diagnostic endpoints), the scoped impact described here (reachable by an "authenticated-but-low-privilege or session-less caller") would not apply, since diagnostics endpoints on chainlink nodes are generally admin-only.

### Recommendation
Validate `gc.Param("profile")` against an explicit allow-list of known pprof profile names (`cmdline`, `profile`, `symbol`, `trace`, `heap`, `goroutine`, `threadcreate`, `block`, `mutex`, `allocs`) before constructing `pluginURL`, rejecting any other value with a 400 response, and use `url.URL{}` construction (via `path.Join`/`url.JoinPath`) instead of raw string concatenation with `fmt.Sprintf`.

### Proof of Concept
Unit test `pluginPPROFHandler` with a registered plugin and `gc.Param("profile") = "../metrics"` (or similar traversal string), then assert on the outbound request captured by a mock `http.RoundTripper`/test server that `req.URL.Path` is either rejected (400) or falls within an allow-listed `/debug/pprof/{cmdline,profile,symbol,trace,heap,goroutine,threadcreate,block,mutex,allocs}` set — currently no such assertion/check exists in `doRequest` or `pluginPPROFHandler`.

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

func (l *LoopRegistryServer) doRequest(gc *gin.Context, method string, url string, body io.Reader, timeout time.Duration, pluginName string) {
	ctx, cancel := context.WithTimeout(gc.Request.Context(), timeout)
	defer cancel()
	req, err := http.NewRequestWithContext(ctx, method, url, body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin pprof request: %s", err))
		return
	}
	res, err := http.DefaultClient.Do(req)
	if err != nil {
		msg := "plugin pprof handler failed to post plugin url " + html.EscapeString(url)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
```

func (m *LoopRegistry) Get(id string) (*RegisteredLoop, bool) {
	m.mu.Lock()
	defer m.mu.Unlock()

	p, exists := m.registry[id]
	return p, exists
}
