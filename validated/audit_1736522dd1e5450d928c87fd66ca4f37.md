### Title
Reward-per-vote (`Vi`) accounting in `MaintenanceManager`/`MortgageService` credits an entire maintenance-cycle's SR reward to votes cast a single block before the cycle boundary, letting an unprivileged voter capture disproportionate rewards with no minimum holding period - (File: `consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java`)

### Summary
TRON's Stake 2.0/voting reward system distributes block and transaction-fee rewards to voters of Super Representatives (SRs) using a "reward-per-vote" index (`Vi`), updated once per maintenance cycle (~6 hours). The divisor used to compute `Vi` for a cycle is the SR's vote count *fixed at the start of that cycle*, while a user's payout is `userVoteCount * deltaVi` using the user's *current* vote snapshot taken at cycle end. Because vote changes made during the cycle are only applied to the divisor for the *next* cycle, a voter who casts (or increases) a large vote in the very last block before the maintenance boundary is retroactively credited with that entire cycle's `Vi` delta — i.e., the full cycle's reward-per-vote — multiplied by their newly-cast vote amount. This is the point-in-time-balance-reward flaw described in the external report, applied to TRON's vote reward mechanism instead of a Solidity `TroveManager`.

### Finding Description
In `MaintenanceManager.doMaintenance()`, the new Vi is computed before the current cycle's vote deltas are applied to the SR's vote count: [1](#0-0) 

`accumulateWitnessVi` divides the reward accumulated over the whole cycle by the vote count passed in: [2](#0-1) 

The vote count parameter is `witness.getVoteCount()` taken **before** `countVote(votesStore)` (which aggregates all vote changes cast during the just-finished cycle) is applied to the witness object: [3](#0-2) 

So `Vi[curCycle]` = (reward accrued over the whole `curCycle`) / (vote count that existed **before** `curCycle` even started). Any votes an attacker casts during `curCycle` do not dilute this divisor at all — they only affect the divisor used for `curCycle+1`.

Meanwhile, per-user rewards are computed with `computeReward`, which multiplies the *entire cycle's* `deltaVi` (from `beginCycle-1` to `endCycle-1`) by the vote count stored in the account's snapshot for that cycle: [4](#0-3) 

Rewards are continuously accumulated into the per-cycle pool block-by-block: [5](#0-4) 

Casting a vote is a normal, unprivileged, single-transaction actuator with no delay, cooldown, or minimum holding period. `VoteWitnessActuator`/`VoteWitnessProcessor` settle any pending reward for old votes and then immediately record the new vote, whose snapshot becomes the multiplier used against the *entire* just-elapsed cycle's `Vi` delta the next time the account's reward is realized: [6](#0-5) [7](#0-6) 

An attacker who already controls large TRON Power (frozen/staked TRX, obtainable without any lock-up delay for existing stakers, or via already-unfrozen power reused across many SRs) can, one block before a maintenance boundary, vote a large amount for a target SR. Because:
1. The divisor for that cycle's `Vi` was fixed before the attacker's vote existed, and
2. The attacker's payout is computed as `theirVoteCount * fullCycleDeltaVi` with no time-weighting,

the attacker captures a reward share vastly disproportionate to the (near-zero) time they actually held the vote, at the direct expense of voters who held their position the entire cycle. Immediately after the maintenance transition, the attacker can redirect/withdraw their vote (`VoteWitnessActuator`/`WithdrawBalanceActuator`/`WithdrawRewardProcessor`) to realize the reward and repeat the attack against another SR/cycle, with no minimum holding period enforced anywhere in this pipeline.

### Impact Explanation
This allows any account with vote-eligible TRON Power to systematically siphon the majority of a cycle's SR voting rewards intended for long-term voters, directly corrupting the protocol's reward/resource accounting (an unprivileged asset/accounting corruption in the consensus reward layer, reachable purely through normal `VoteWitnessContract` broadcast transactions — no privileged role, leaked key, or malicious peer required).

### Likelihood Explanation
The attack requires only standard TRON Power and a normally-broadcast `VoteWitnessContract` transaction timed near a maintenance boundary (maintenance timing is deterministic/public via `getNextMaintenanceTime`), making it easily and repeatedly executable by any sufficiently-staked account, with no special network position needed.

### Recommendation
Compute `Vi`'s divisor and a voter's reward multiplier using time-weighted vote-seconds within the cycle (checkpoint vote changes at the block they occur, and integrate reward accrual against the then-current total vote count) rather than crediting an entire cycle's reward to whatever vote snapshot exists at the cycle boundary. Alternatively, require a minimum number of cycles held before a vote change is eligible for that cycle's reward.

### Proof of Concept
1. Attacker holds/acquires large TRON Power without needing to freeze new TRX for the first time (already-staked TRX can be reused).
2. Wait until the block immediately preceding `getNextMaintenanceTime()`.
3. Broadcast `VoteWitnessContract` allocating a large vote to SR `W` (`VoteWitnessActuator.countVoteAccount`, `VoteWitnessProcessor.execute`).
4. Maintenance runs (`MaintenanceManager.doMaintenance`): `Vi[curCycle]` for `W` is computed using the vote count from *before* the attacker's vote was counted (`accumulateWitnessVi` called prior to `countVote` update), so the attacker's stake doesn't dilute the divisor for the cycle it earns from.
5. On the next `withdrawReward`/`queryReward` call, `computeReward` multiplies the attacker's freshly-cast vote count by the whole cycle's `deltaVi`, crediting a reward disproportionate to their near-zero holding duration.
6. Attacker withdraws the reward and reassigns votes to repeat against the next SR/cycle.

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }

    int brokerage = delegationStore.getBrokerage(cycle, witnessAddress);
    double brokerageRate = (double) brokerage / 100;
    long brokerageAmount = (long) (brokerageRate * value);

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }

  private void countVoteAccount(VoteWitnessContract voteContract) {

    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());

  public void execute(VoteWitnessParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getVoterAddress();
    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);

    VotesCapsule votesCapsule = repo.getVotes(ownerAddress);
    if (votesCapsule == null) {
      votesCapsule = new VotesCapsule(ByteString.copyFrom(ownerAddress),
          accountCapsule.getVotesList());
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    Map<ByteString, Long> voteMap = new HashMap<>();
    Iterator<Protocol.Vote> iterator = param.getVotes().iterator();
    try {
      long sum = 0;
      while (iterator.hasNext()) {
        Protocol.Vote vote = iterator.next();

        byte[] witnessAddress = vote.getVoteAddress().toByteArray();
        /*
          Already covered while doing maintenance in MaintenanceManager.java, for tvm performance,
          we remove the account check
         */
//        if (repo.getAccount(witnessAddress) == null) {
//          throw new ContractValidateException(
//              ACCOUNT_EXCEPTION_STR + StringUtil.encode58Check(witnessAddress) + NOT_EXIST_STR);
//        }
        if (repo.getWitness(witnessAddress) == null) {
          throw new ContractExeException(
              WITNESS_EXCEPTION_STR + StringUtil.encode58Check(witnessAddress) + NOT_EXIST_STR);
        }

        long voteCount = vote.getVoteCount();
        if (voteCount < 0) {
          throw new ContractExeException("Vote count must not be less than 0");
        } else if (voteCount == 0) {
          iterator.remove();
        } else {
          sum = LongMath.checkedAdd(sum, voteCount);
          // merge vote for same witness
          voteMap.put(vote.getVoteAddress(),
              LongMath.checkedAdd(voteMap.getOrDefault(vote.getVoteAddress(), 0L), voteCount));
        }
      }

      long tronPower;
      if (repo.getDynamicPropertiesStore().supportUnfreezeDelay()
          && repo.getDynamicPropertiesStore().supportAllowNewResourceModel()) {
        tronPower = accountCapsule.getAllTronPower();
      } else {
        tronPower = accountCapsule.getTronPower();
      }
      sum =  LongMath.checkedMultiply(sum, TRX_PRECISION);
      if (sum > tronPower) {
        throw new ContractExeException(
            "The total number of votes[" + sum + "] is greater than the tronPower[" + tronPower
                + "]");
      }
    } catch (ArithmeticException e) {
      throw new ContractExeException(e.getMessage());
    }

    for (Map.Entry<ByteString, Long> entry : voteMap.entrySet()) {
      accountCapsule.addVotes(entry.getKey(), entry.getValue());
      votesCapsule.addNewVotes(entry.getKey(), entry.getValue());
    }
    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
    repo.updateVotes(ownerAddress, votesCapsule);
  }
