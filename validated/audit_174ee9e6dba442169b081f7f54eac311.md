CVE-2022-43045 describes a segmentation fault in GPAC's C-based `gf_dump_vrml_sffield` debug/dump routine caused by a native memory-safety bug (null/invalid pointer dereference) when dumping malformed VRML scene data. This is a C-specific memory-corruption bug class that does not map onto protobuf-go, which is written in memory-safe Go and cannot suffer from segmentation violations of this kind.

The closest analog considered was `encoding/prototext`'s unknown-field dumping routine, `marshalUnknown`, which parses raw bytes similarly to a "dump" function [1](#0-0) . However, this function explicitly documents that it "assumes proper encoding in the given []byte" [2](#0-1) , and the unknown-field bytes it consumes originate from `proto.Unmarshal`'s wire-format decoding, which already validates tag/wire-type structure before storing bytes as unknown fields — this is the trusted-schema, already-validated-input precondition specified in the rules. Even in a worst case, any failure mode here would be a Go panic (recoverable, no unsafe-memory effect), not a memory-corruption segfault, and does not constitute a confidentiality/integrity violation per the threat model. No reachable unprivileged request path exhibits the same broken invariant (dumping unvalidated/attacker-controlled malformed data leading to unsafe memory access) as the original GPAC bug.
