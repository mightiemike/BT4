### Title
Universal outbound gas fee accounting uses stale ChainMeta gas price with no freshness check at consumption time - (File: `x/uexecutor/keeper/gas_fee.go`)

### Summary
The external report describes AfEth's `price()` calling `ethPerCvx(false)`, which bypasses Chainlink staleness/validity checks, so a stale price feeds directly into mint-amount accounting. Push Chain's `ChainMeta` gas-price oracle has an analogous split: the vote-aggregation path (`x/uexecutor/keeper/chain_meta.go`) explicitly filters "fresh" votes using `chainMetaVoteStalenessSeconds`, but the *consumption* path — `GetOutboundTxGasAndFees` / `GetGasPriceByChain` in `x/uexecutor/keeper/gas_fee.go` and `x/uexecutor/keeper/evm.go` — reads the on-chain `gasPriceByChainNamespace` value with zero freshness validation, exactly mirroring the `ethPerCvx(false)` pattern where validation logic exists elsewhere in the codebase but is never applied at the point of use.

### Finding Description
`VoteChainMeta` (`x/uexecutor/keeper/chain_meta.go:62-189`) computes a median gas price only from votes that are still "fresh" (`age <= chainMetaVoteStalenessSeconds`, i.e. 300 seconds): [1](#0-0) 
If a chain never accumulates fresh votes in a given block (e.g., a low-traffic chain, temporary RPC issues for that chain, or simply an interval gap), `VoteChainMeta` returns early without writing to `CallUniversalCoreSetChainMeta`, leaving the previously-applied value stored on the `UniversalCore` EVM contract with **no expiry, no staleness marker, and no on-chain timestamp**: [2](#0-1) 

Every consumer of this value reads it back through `gasPriceByChainNamespace` without any check against `LastAppliedChainHeight`/`StoredAts` or elapsed time: [3](#0-2) [4](#0-3) 

This `GasFeeInfo.GasPrice` is used directly to compute `gasFee` that gets deducted from a user's PRC20 balance when building an outbound (bridge-out) transaction, and to populate `OutboundTx.GasPrice`/`GasFee` fields that gate how much excess gas is later refunded: [5](#0-4) [6](#0-5) 

Because the off-chain median logic already models "staleness" as a first-class concept (`chainMetaVoteStalenessSeconds`, `StoredAts`), but that concept is discarded once the value is written to the EVM contract, the gas price ultimately consumed by fee-accounting logic can be arbitrarily old relative to the real external-chain gas price — precisely the class of bug in the external report: a validation/freshness mechanism exists in the codebase but is not applied where the price is actually used to compute a monetary amount.

### Impact Explanation
When the true external gas price has risen since the last successful vote-quorum update (e.g., the observed chain had low UV traffic, was recently onboarded, or its fresh-vote count dipped below quorum for a period), any ordinary user submitting a cross-chain payload/withdrawal is charged a `gasFee` computed from the outdated (lower) price via `getOutboundTxGasAndFees`. The TSS/universal-client subsystem must still broadcast the actual outbound transaction at the real (higher) destination-chain gas price, so the protocol/relayer absorbs the shortfall — an unauthorized reduction of protocol-controlled funds directly caused by an ordinary, non-privileged user's default withdrawal/outbound submission. Conversely, if the real price has fallen, users are systematically overcharged, corrupting gas fee/refund accounting (`applyGasRefund`) in the other direction. This falls under "corruption of ... gas fee accounting, refund accounting ... token mapping" in the allowed-impact gate.

### Likelihood Explanation
No malicious validator or governance action is required. Any chain with intermittent Universal Validator RPC availability, low vote frequency, or a recently-added token/chain config can end up with a `gasPriceByChainNamespace` value that is stale for an extended, unbounded period, since there's no cap tying the *use* of the value to how recently it was refreshed on-chain (unlike the vote-aggregation staleness window). An ordinary user only has to submit a normal outbound/bridge-out transaction while the chain's on-chain gas price happens to be outdated to trigger the underfunded-fee condition — no adversarial validator behavior is assumed.

### Recommendation
Store and propagate the chain-meta freshness metadata (e.g., `LastAppliedChainHeight` / an on-chain "last updated" timestamp) into the `UniversalCore` contract alongside `gasPriceByChainNamespace`, and have `GetOutboundTxGasAndFees` / outbound-creation logic reject or fall back safely (e.g., revert / require re-vote) when the stored gas price exceeds a defined staleness bound, mirroring the same staleness window already enforced in `x/uexecutor/keeper/chain_meta.go`.

### Proof of Concept
1. Onboard/observe a chain whose Universal Validators intermittently fail to submit fresh `MsgVoteChainMeta` votes within `chainMetaVoteStalenessSeconds` (300s) — e.g., due to transient RPC outages, not malicious behavior.
2. `VoteChainMeta` keeps returning early at `len(fresh) == 0` (`x/uexecutor/keeper/chain_meta.go:145-154`), so `gasPriceByChainNamespace` on `UniversalCore` remains pinned at its last-applied (now stale) value indefinitely.
3. Meanwhile, the real gas price on that external chain rises materially.
4. An ordinary user submits a normal cross-chain payload/withdrawal; `BuildOutboundsFromReceipt` records `GasFee`/`GasPrice` computed from the stale, understated value (`x/uexecutor/keeper/create_outbound.go:69-91`), so the user is charged less than the actual cost of broadcasting the outbound transaction.
5. When the Universal Client actually broadcasts the transaction at the real (higher) gas price, the deficit is paid by the protocol/relayer — an unauthorized loss of protocol-controlled funds triggered purely by a default user action, with no privileged or malicious actor involved.

// GetGasPriceByChain reads the gas price for a chain from the UniversalCore contract.
func (k Keeper) GetGasPriceByChain(ctx sdk.Context, chainNamespace string) (*big.Int, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, abi, ueModuleAccAddress, handlerAddr, false, nil, "gasPriceByChainNamespace", chainNamespace)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call gasPriceByChainNamespace")
	}

	results, err := abi.Methods["gasPriceByChainNamespace"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack gasPriceByChainNamespace result")
	}

	return results[0].(*big.Int), nil
}

// GetOutboundTxGasAndFees calls UniversalCore.getOutboundTxGasAndFees(prc20, gasLimitWithBaseLimit)
// to get gasToken, gasFee, protocolFee, gasPrice, and chainNamespace.
// Pass gasLimitWithBaseLimit=0 to use the contract's baseLimit.
func (k Keeper) GetOutboundTxGasAndFees(ctx sdk.Context, prc20 common.Address, gasLimitWithBaseLimit *big.Int) (*GasFeeInfo, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
}
