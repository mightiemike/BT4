## Title
`ensure_match_transaction_info` never validates state/hot-state/position checkpoint hashes, so replay-verify tooling accepts a corrupted or divergent state root as authentic — (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the canonical check used to confirm that a locally-produced `TransactionOutput` matches the authenticated `TransactionInfo` committed to the ledger accumulator. It validates status, gas, write-set hash (`state_change_hash`), and event root hash, but explicitly and admittedly skips validating the `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` fields carried by `TransactionInfoV1`. [1](#0-0) 

### Finding Description
`TransactionInfoV1` (gated by the `TRANSACTION_INFO_V1` feature) carries per-checkpoint state roots that are consensus-authenticated: the base state root, the hot-state root (`HOT_STATE_ROOT_IN_TXN_INFO`), and — when `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled — the native-position tree root (`position_state_checkpoint_hash`), all computed in `DoStateCheckpoint::run`/`compute_position_checkpoint`. [2](#0-1) 

`ensure_match_transaction_info` checks execution status, gas, write-set hash, and event root hash against the `TransactionInfo`, but has an explicit `TODO(trading-native)` acknowledging it never compares the state/hot-state/position checkpoint hashes before returning `Ok(())`. [3](#0-2) 

This function is used by `db-tool`'s `replay_on_archive`, `aptos-debugger`, the CLI replay command, and the chunk executor as the pass/fail gate for "did local re-execution reproduce the authenticated ledger": [4](#0-3) [5](#0-4) 

Because the state-root fields are silently excluded from the comparison, any divergence between the state actually committed to durable storage/accumulator and what local re-execution produces — whether from a genuine consensus bug, a storage corruption, or (most concretely here) the new position-state pipeline's dual code paths — will not be flagged by this integrity check. This is not merely theoretical: the storage layer itself has two different ways of producing the position-state root depending on `COMPUTE_TRADING_NATIVE_STATE_ROOTS`. When the flag is off, `aptosdb_writer.rs`'s `commit_native_position` locally recomputes the position summary via `position_summary_at_commit` (extending the buffered tip from write-set iteration) rather than using the value produced by execution's checkpoint logic: [6](#0-5) [7](#0-6) 

If these two computation paths (execution-time checkpoint vs. storage-recomputed-at-commit) ever diverge — e.g. due to ordering/hash differences in how pending position slots are folded, a bug in `extend_on_base`, or a race between the persisted base and buffered tip — the resulting `position_state_checkpoint_hash` mismatch would go completely undetected by `ensure_match_transaction_info`, since that field is never compared. The same blind spot applies to the primary state and hot-state checkpoint hashes.

### Impact Explanation
This breaks the "Authenticated API and proof-bearing responses must stay bound to the right ledger version, root, and object" and "Committed state that differs from the correct VM result... must not go undetected" invariants required by the scope. `ensure_match_transaction_info` is the primary safety net used by archival replay-verification (`replay_on_archive`), debugger replay, and chunk-executor consistency checks to catch exactly this class of divergence. With the state-root fields excluded, an operator (or an automated CI/monitoring job) running replay-verify over the entire chain history to detect state-root corruption or non-determinism would get a false "PASS" even though the authenticated `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` differs from what local re-execution computes. This is a high-severity integrity gap: it defeats the detection mechanism for state-commitment divergence — the very tool meant to catch a bad accumulator/state root before it is trusted or before a hard fork investigation would be triggered.

### Likelihood Explanation
This code path is unconditionally reached whenever `ensure_match_transaction_info` is invoked (replay tooling, debugger, chunk executor sanity checks) — there is no feature gate protecting the missing checks themselves; the gap exists today even though `TRANSACTION_INFO_V1`/`COMPUTE_TRADING_NATIVE_STATE_ROOTS` may not yet be broadly enabled on mainnet. The comment in the code is itself an admission by the maintainers that this must be fixed "before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`," confirming the maintainers are aware this is unsafe once that feature ships. Given the dual computation paths already present in `aptosdb_writer.rs` for the position summary, the risk of an undetected divergence is concrete rather than purely hypothetical.

### Recommendation
Extend `ensure_match_transaction_info` to compare `state_checkpoint_hash`, `hot_state_checkpoint_hash` (when `TransactionInfoV1`/`HOT_STATE_ROOT_IN_TXN_INFO` is set), and `position_state_checkpoint_hash` (when `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is set) against locally computed values before returning `Ok(())`, mirroring the existing write-set-hash and event-root-hash checks. This should be landed and enforced prior to (or gated together with) enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, exactly as the existing TODO specifies.

### Proof of Concept
1. Enable `TRANSACTION_INFO_V1` and `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (plus prerequisites) so `TransactionInfoV1::position_state_checkpoint_hash` is populated and consensus-authenticated via `DoStateCheckpoint::compute_position_checkpoint`. [8](#0-7) 
2. Introduce (or trigger via a latent bug) a divergence between the execution-time position summary and the storage-side recomputation path in `position_summary_at_commit`, causing the on-disk/committed position root to differ from what a clean re-execution would produce. [7](#0-6) 
3. Run `db-tool replay-on-archive` (or `aptos-debugger`) over the affected version range; the tool calls `ensure_match_transaction_info` to validate replay output against the archived `TransactionInfo`. [4](#0-3) 
4. Because `ensure_match_transaction_info` never compares `position_state_checkpoint_hash` (or the other checkpoint hashes), the replay is reported as successful/matching despite the authenticated position state root differing from local execution — silently masking the state-commitment divergence. [9](#0-8)

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn position_summary_at_commit(
        &self,
        chunk: &ChunkToCommit,
    ) -> Result<PositionLedgerStateWithSummary> {
        let bundle = self
            .position
            .as_ref()
            .expect("called only when position is present");
        let store = bundle
            .state_store
            .as_ref()
            .expect("called only when state_store is present");
        let persisted_base = bundle
            .persisted
            .as_ref()
            .expect("persisted present when state_store is")
            .get();

        let (mut latest, mut last_checkpoint) = {
            let state = store.current_state();
            let current = state.lock();
            (current.latest().clone(), current.last_checkpoint().clone())
        };

        let chunk_first = chunk.first_version;
        let chunk_last_inclusive = chunk_first + chunk.transaction_outputs.len() as Version - 1;
        let checkpoint_within_chunk = chunk
            .state
            .last_checkpoint()
            .version()
            .filter(|v| (chunk_first..=chunk_last_inclusive).contains(v));

        let mut pending: HashMap<HashValue, PositionSlot> = HashMap::new();
        let extend_on_base = |latest: &PositionStateWithSummary,
                              version: Version,
                              updates: Vec<(HashValue, PositionSlot)>|
         -> Result<PositionStateWithSummary> {
            let proof_reader = PositionProofReader {
                merkle_db: bundle.merkle_db.clone(),
                version: persisted_base.version(),
            };
            latest.extend(version, updates, persisted_base.summary(), &proof_reader)
        };

        for (i, output) in chunk.transaction_outputs.iter().enumerate() {
            let version = chunk_first + i as Version;
            for (key, op) in output.write_set().native_position_iter() {
                let value_hash = op.as_write_op().as_state_value_opt().map(CryptoHash::hash);
                pending.insert(key.hash(), PositionSlot {
                    state_key: key.clone(),
                    value_hash,
                    value: None,
                });
            }
            if Some(version) == checkpoint_within_chunk && !pending.is_empty() {
                let updates: Vec<_> = std::mem::take(&mut pending).into_iter().collect();
                latest = extend_on_base(&latest, version, updates)?;
                last_checkpoint = latest.clone();
            }
        }
        if !pending.is_empty() {
            let updates: Vec<_> = pending.into_iter().collect();
            latest = extend_on_base(&latest, chunk_last_inclusive, updates)?;
        }

        Ok(
            PositionLedgerStateWithSummary::from_latest_and_last_checkpoint(
                latest,
                last_checkpoint,
            ),
        )
    }
