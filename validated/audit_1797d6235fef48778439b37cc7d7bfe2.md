## Title
Front-running/sandwich of the deposit-autoswap (`depositPRC20WithAutoSwap`) slippage bound because `minPCOut` is derived from a same-transaction spot quote — (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The external report concerns `finalize()`/`returnFunds()` executing a withdrawal at whatever price the pool happens to hold at execution time, with no caller-enforced minimum, letting a front-runner force an unfavorable trade. Push Chain's native analog is the PRC20→native-PC autoswap performed by `x/uexecutor` as part of inbound (bridge) execution: the module computes a "protective" `minPCOut` from an **on-chain spot quote fetched in the same call path** as the swap itself, so the bound is derived from — and moves together with — whatever price an attacker has just set.

### Finding Description
For `GAS` and `GAS_AND_PAYLOAD` inbound routes, when a bridged PRC20 asset must be auto-swapped into native PC inside the recipient's UEA, the keeper:
1. Calls `GetSwapQuote` (a static `CallEVM` to Uniswap V3 `QuoterV2.quoteExactInputSingle`) to get the current pool's expected output [1](#0-0) .
2. Derives `minPCOut = quote * 95 / 100` (a flat 5% slippage tolerance around that same spot quote) [2](#0-1) [3](#0-2) .
3. Immediately commits the swap via `CallPRC20DepositAutoSwap` → `DerivedEVMCall("depositPRC20WithAutoSwap", ...)` using that bound [4](#0-3) .

This whole flow runs synchronously inside the message handler that finalizes an inbound (2/3 UV quorum reached on `MsgVoteInbound`), which is itself an ordinary transaction placed in a block like any other. Because Push Chain's mempool/block ordering is visible pre-confirmation, an unprivileged attacker can submit an ordinary swap on the same Uniswap V3 WPC/PRC20 pool that lands **earlier in the block** than the validator's finalizing transaction, moving the pool's spot price. When the module then calls `GetSwapQuote`, it reads the *already-manipulated* price, and `minPCOut` is computed as 95% of that same manipulated quote — so the "protection" is proportional to the poisoned price rather than to any independent reference, and offers no real defense. The attacker then reverses the trade after the module's swap executes, extracting the spread while the depositor's UEA receives materially less PC than the fair, unmanipulated price would have produced.

### Impact Explanation
This directly corrupts native-asset/PRC20 accounting for bridged inbound funds — the exact "PRC20 or native asset accounting ... token mapping" invariant in scope. A normal, unprivileged user (no validator, no governance, no key compromise) can extract value from every depositor's autoswap by sandwiching the module's swap, causing depositors to receive less PC than the fair-market amount for the bridged asset. This is a real, repeatable value-extraction/fund-loss vector, most exploitable against pools with thin liquidity or during inbound of larger amounts.

### Likelihood Explanation
The attack requires no privileged role — it is a standard MEV/sandwich pattern requiring only mempool visibility and a swap on the same Uniswap V3 pool used by `UniversalCore`. Since `MsgVoteInbound` finalization (and the resulting autoswap) is an ordinary, publicly observable transaction, and the module's own protective bound is derived from the same manipulable spot price, the attack is straightforward to execute repeatedly whenever a `GAS`/`GAS_AND_PAYLOAD` inbound triggers an autoswap.

### Recommendation
- Do not derive `minPCOut` solely from an instantaneous spot quote taken in the same transaction as the swap. Use a time-weighted average price (TWAP) from the Uniswap V3 oracle (or an externally supplied/attested reference price) with a bounded maximum deviation check against the spot quote, rejecting execution (and instead deferring/retrying, or falling back to a plain `depositPRC20Token` without swap) if the spot price has moved beyond a safe threshold from the TWAP.
- Alternatively, cap the swap size or add a circuit breaker so that pools with low liquidity cannot be cheaply manipulated within a single block window relative to the deposit size.

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` transaction (from the last needed UV) in the mempool that will finalize a `GAS_AND_PAYLOAD` inbound and trigger `gasAndPayloadDepositAutoSwap` for a sizeable PRC20 amount.
2. Attacker submits (and gets included earlier in the same block, e.g. via higher gas price) a large swap on the WPC/PRC20 Uniswap V3 pool used by `UniversalCore`, pushing the PRC20→WPC price down.
3. The validator's `MsgVoteInbound` executes; `GetSwapQuote` returns the now-depressed quote; `minPCOut` is computed as 95% of that depressed value [5](#0-4) ; `CallPRC20DepositAutoSwap` executes at the manipulated price, and the depositor's UEA receives far less PC than fair value.
4. Attacker reverses the earlier trade, restoring the pool and pocketing the difference extracted from the depositor's proceeds.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
