### Title
Floor-division in `induced_gas_costs` under-prices proving-gas per Cairo primitive, letting proving-gas capacity be exceeded relative to its intended per-primitive budget - (File: crates/blockifier/src/bouncer.rs)

### Summary
`BuiltinInstanceLimits::induced_gas_costs` derives the block-wide per-instance proving-gas cost of each Cairo builtin/opcode as `floor(proving_gas / limit)`, always rounding down, analogous to the reported Omnipool `_exchangeRate()` bug where using a single rounding direction for both "buy" and "sell" sides of a resource-to-cost conversion benefits the payer at the expense of the total pool.

### Finding Description
`induced_gas_costs` computes, per builtin, `cost = proving_gas.0 / limit.get()` using integer (floor) division: [1](#0-0) 

This per-primitive `cost` is later used both (a) to derive the *intended per-instance-limit budget* (i.e., the config author's intent that `limit` instances of the builtin should exactly consume `block_max_capacity.proving_gas`) and (b) to *charge* transactions' proving-gas usage via `proving_gas_from_cairo_primitives_and_sierra_gas`, which the bouncer then compares against `block_max_capacity.proving_gas` to decide whether the block is full (`try_update` / `within_max_capacity_or_err`).

Because the division always floors, `cost * limit <= proving_gas`, with the shortfall potentially reaching up to `limit - 1` gas units per builtin (worse for builtins with large `limit`, e.g. `range_check` at ~66.6M or `bitwise` at ~10.5M). This means the *effective* proving-gas capacity of the block, as actually chargeable through builtin usage, is systematically smaller than the configured `block_max_capacity.proving_gas` by design — but more importantly, since the same floored cost is used for every transaction's accounting, `n` instances of a builtin are always charged `n * floor(proving_gas/limit)`, which is strictly less than or equal to the "fair" continuous cost `n * proving_gas/limit`. A block builder can therefore pack `limit` instances of a cheap-per-unit builtin and consume a full multiple of `limit` instances while paying strictly less proving-gas than the nominal per-block budget intends, systematically under-charging proving-gas relative to the configured cap and allowing more real prover work to be admitted into a block than the `block_max_capacity.proving_gas` bound was calibrated for.

This mirrors the ERC4626 rounding bug's structure: a single "exchange rate" (gas-cost-per-instance) computed with one rounding direction is reused for what is effectively a "spend" operation (converting builtin usage into proving-gas cost charged against the bounded resource), where the safe direction would be to round up (ceiling) to guarantee `n` instances of the builtin never cost less than their fair share of the capacity.

### Impact Explanation
This is a resource-accounting/DoS-adjacent issue affecting how much real per-block proving work (Cairo builtin invocations) can be admitted before the bouncer declares the block full via `try_update`/`within_max_capacity_or_err`: [2](#0-1) [3](#0-2) 

If exploited by packing many transactions that maximize a specific builtin's usage, a proposer/batcher could build blocks whose actual prover cost (STARK proving time) systematically exceeds the operator's intended `proving_gas` cap, which is explicitly the mechanism meant to bound block proving time. This is a resource/weight-only miscalculation (bounded, deterministic, and only reachable by whoever controls block building), not a fund-loss or consensus-divergence bug, and the note in the code ("Keep proving_gas at the default value so the induced builtin gas costs stay in a sane range") suggests awareness that the derivation is approximate.

### Likelihood Explanation
Reaching this path requires only ordinary transaction submission (invoking Cairo code that uses builtins/opcodes); no privileged role is needed to trigger `induced_gas_costs`/`try_update` on the honest sequencer's own block-building path. However, the per-unit shortfall (`limit - 1` out of `proving_gas` values in the billions) is a small percentage per builtin (fractions of a percent for the default limits shown in the test snapshot), so the aggregate over-admission is bounded and requires deliberately maximizing usage of high-`limit` builtins across many transactions to have a measurable effect.

### Recommendation
Round the per-instance induced cost up (`ceiling`) rather than down when deriving `BuiltinGasCosts` from `BuiltinInstanceLimits`, e.g. `cost = proving_gas.0.div_ceil(limit.get())`, so that no combination of builtin usage can be charged less than its fair share of `block_max_capacity.proving_gas`. This is the "round in favor of the protocol/bound" direction, consistent with how `checked_div_ceil` and the `*_round_up` conversions elsewhere in the fee/gas code are deliberately used to avoid under-charging (e.g. `to_discounted_l1_gas`, `sierra_gas_to_l1_gas_amount_round_up`): [4](#0-3) [5](#0-4) 

### Proof of Concept
Using the existing regression test's numbers as an illustration: at `proving_gas = 6_000_000_000` and default `range_check` limit `66_666_666`, `induced_gas_costs` yields `range_check: 90` gas per instance (floor of `6_000_000_000 / 66_666_666 = 90.0000015`), effectively free-riding by `0.0000015` gas per instance: [6](#0-5) 
For a builtin whose true fractional cost is larger (e.g. constructed as in `test_bouncer_try_update_gas_based`, where `range_check` limit is deliberately set to `range_check_count = 2` against the full default `proving_gas` capacity so that `induced cost = proving_gas / 2`), any remainder from the division is discarded, so `range_check_count` instances of the builtin are always charged `range_check_count * floor(proving_gas / range_check_count) <= proving_gas`, never more — i.e., it is impossible for exactly-at-capacity builtin usage to be flagged as exceeding the bound even when the true (fractional) proving cost would exceed it: [7](#0-6)

impl BuiltinInstanceLimits {
    /// Induces the per-instance proving-gas cost of each Cairo primitive from its per-block
    /// instance limit: `cost = floor(proving_gas / limit)`.
    pub fn induced_gas_costs(&self, proving_gas: GasAmount) -> BuiltinGasCosts {
        let derive = |limit: NonZeroU64| -> u64 { proving_gas.0 / limit.get() };
        BuiltinGasCosts {
            pedersen: derive(self.pedersen),
            range_check: derive(self.range_check),
            range_check96: derive(self.range_check96),
            poseidon: derive(self.poseidon),
            ecdsa: derive(self.ecdsa),
            ecop: derive(self.ecop),
            bitwise: derive(self.bitwise),
            keccak: derive(self.keccak),
            add_mod: derive(self.add_mod),
            mul_mod: derive(self.mul_mod),
            blake: derive(self.blake),
        }
    }

pub fn to_discounted_l1_gas(
    l1_gas_price: NonzeroGasPrice,
    l1_data_gas_price: GasPrice,
    l1_gas: GasAmount,
    l1_data_gas: GasAmount,
) -> GasAmount {
    let l1_data_gas_fee = l1_data_gas.checked_mul(l1_data_gas_price).unwrap_or_else(|| {
        panic!(
            "Discounted L1 gas cost overflowed: multiplication of L1 data gas ({l1_data_gas}) by \
             L1 data gas price ({l1_data_gas_price}) resulted in overflow."
        );
    });
    let l1_data_gas_in_l1_gas_units =
        l1_data_gas_fee.checked_div_ceil(l1_gas_price).unwrap_or_else(|| {
            panic!(
                "Discounted L1 gas cost overflowed: division of L1 data fee ({l1_data_gas_fee}) \
                 by regular L1 gas price ({l1_gas_price}) resulted in overflow."
            );
        });
    l1_gas.checked_add(l1_data_gas_in_l1_gas_units).unwrap_or_else(|| {
        panic!(
            "Overflow while computing discounted L1 gas: L1 gas ({l1_gas}) + L1 data gas in L1 \
             gas units ({l1_data_gas_in_l1_gas_units}) resulted in overflow."
        )
    })
}

fn test_bouncer_try_update_gas_based(#[case] scenario: &'static str, block_context: BlockContext) {
    let state = &mut test_state(&block_context.chain_info, Fee(0), &[]);
    let mut transactional_state = TransactionalState::create_transactional(state);

    let range_check_count = 2;
    let builtin_counters = match scenario {
        "proving_gas_block_full" => {
            cairo_primitive_counter_map([(BuiltinName::range_check, range_check_count)])
        }
        // Use a minimal or empty map.
        "ok" | "sierra_gas_block_full" => {
            cairo_primitive_counter_map([(BuiltinName::range_check, range_check_count - 1)])
        }
        _ => panic!("Unexpected scenario: {scenario}"),
    };

    // Derive sierra_gas from scenario
    let sierra_gas = match scenario {
        "sierra_gas_block_full" => GasAmount(11), // Exceeds capacity
        "ok" | "proving_gas_block_full" => GasAmount(1), // Within capacity
        _ => panic!("Unexpected scenario: {scenario}"),
    };

    // Pick a range_check instance limit such that exactly `range_check_count` ops fill the
    // default block proving-gas budget (induced cost = proving_gas / range_check_count).
    let builtin_instance_limits = BuiltinInstanceLimits {
        range_check: NonZeroU64::new(u64_from_usize(range_check_count))
            .expect("range_check_count must be > 0"),
        ..BuiltinInstanceLimits::default()
    };
    let proving_gas_max_capacity = BouncerWeights::default().proving_gas;

    let block_max_capacity = BouncerWeights {
        l1_gas: 20,
        message_segment_length: 20,
        n_events: 20,
        state_diff_size: 20,
        n_txs: 20,
        sierra_gas: GasAmount(20),
        proving_gas: proving_gas_max_capacity,
        receipt_l2_gas: GasAmount(20),
    };
    let bouncer_config = BouncerConfig { block_max_capacity, builtin_instance_limits };

    let bouncer_weights = BouncerWeights {
        l1_gas: 10,
        message_segment_length: 10,
        n_events: 10,
        state_diff_size: 10,
        sierra_gas: GasAmount(10),
        n_txs: 10,
        proving_gas: GasAmount(10),
        receipt_l2_gas: GasAmount(0),
    };
    let accumulated_weights = TxWeights { bouncer_weights, ..Default::default() };

    let mut bouncer = Bouncer { accumulated_weights, bouncer_config, ..Bouncer::empty() };

    // Prepare the resources to be added to the bouncer.
    let execution_summary = ExecutionSummary::default();
    let tx_resources = TransactionResources {
        computation: ComputationResources { sierra_gas, ..Default::default() },
        ..Default::default()
    };
    let tx_state_changes_keys = transactional_state.to_state_diff().unwrap().state_maps.keys();

    let result = bouncer.try_update(
        &transactional_state,
        &tx_state_changes_keys,
        &execution_summary,
        &cairo_primitive_counter_map(builtin_counters),
        &tx_resources,
        &block_context.versioned_constants,
        GasAmount::ZERO,
    );

    match scenario {
        "ok" => assert_matches!(result, Ok(())),
        "proving_gas_block_full" | "sierra_gas_block_full" => {
            assert_matches!(result, Err(TransactionExecutorError::BlockFull))
        }
        _ => panic!("Unexpected scenario: {scenario}"),
    }
}
