### Title
Zero-Weight Reward Set Can Produce a Zero Signature Threshold, Bypassing Signer Approval - (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` computes the minimum required signing weight from `RewardSet::total_signing_weight()` and `compute_voting_weight_threshold()`. If a `RewardSet` ends up with a `signers` field of `Some(vec![])` — an explicitly present but empty signer list, as opposed to `None` — the total weight is `0`, the computed threshold is also `0`, and a block with zero signer signatures passes verification. This mirrors the external report's root cause: a required-signer quantity (`signNum` in the report, the signing-weight threshold here) that defaults/degrades to `0`, permitting an action (fund withdrawal there, block acceptance here) with no signer approval whatsoever.

### Finding Description
`compute_voting_weight_threshold` computes:
```
threshold = ceil(total_weight * 70 / 100)
``` [1](#0-0) 
When `total_weight == 0`, this yields `threshold == 0`.

`verify_signer_signatures` then checks `total_weight_signed < threshold` to reject a block; with `threshold == 0` and no signatures gathered (`total_weight_signed == 0`), the check `0 < 0` is false, so the block is accepted: [2](#0-1) 

The `total_weight` itself is derived from `RewardSet::total_signing_weight()`, which sums the `weight` field over `self.signers()`. Crucially, this function only errors if `signers()` returns `None` — it happily returns `Ok(0)` for `Some(vec![])` (a non-`None`, but empty, signer list): [3](#0-2) 

The legacy `StacksChainState::make_signer_set` (the reward-set construction path used for non pox-5 cycles) can produce exactly this `Some(vec![])` outcome: it returns `None` only when the raw `entries` slice is empty or when entries don't carry signing keys; otherwise it builds a `BTreeMap`, computes `weight = stacked_amt / threshold` per signer, and filters out any entry whose computed `weight == 0`. If every signer's stacked amount floors to `0` under the given `threshold` (e.g., because per-signer stacked amounts are all smaller than the reward-slot `threshold`), every entry is filtered and the function still returns `Some(empty_vec)`, not `None`: [4](#0-3) 

This is confirmed by the existing regression test `weight_zero_entries_are_filtered`, which demonstrates that whole signers can be dropped to zero weight when their stake is small relative to the threshold — the newer `pox_5_make_signer_set` was specifically rewritten (via a Hare/largest-remainder allocation) to prevent the entire signer set from collapsing to empty/zero, precisely because the naive floor-based `make_signer_set` had this failure mode: [5](#0-4) 

Once such a reward set (`signers: Some(vec![])`, effective `total_weight == 0`) is committed for a reward cycle, `verify_signer_signatures` — the function that enforces the core Nakamoto consensus invariant "≥70% signer weight must approve a block" — degrades to requiring zero signatures, exactly as `AccountManage.withdrawComputingFee()` degraded to requiring zero co-signers when `signNum` was left at its default zero value.

### Impact Explanation
If reached, this breaks the core equality that block acceptance requires signer-weight ≥ 70% threshold. A block with an empty `signer_signature` vector would pass `verify_signer_signatures`, meaning a miner could produce and have accepted a block with **no signer approval at all**. This is a Critical-class issue per the rules ("an invalid block accepted... network-wide") because it defeats the entire signer-set security model for that reward cycle, potentially enabling arbitrary/malicious block content to be accepted without any signer consensus.

### Likelihood Explanation
This requires the reward-set construction for a given cycle to collapse every stacker's floor-weight to zero under the legacy `make_signer_set` threshold-division scheme — a data/threshold-dependent condition (e.g., very small per-signer stacked amounts relative to the reward-slot threshold), not requiring any majority collusion or privileged access; it is a property of the stacking distribution for that cycle, which is influenced by ordinary (minority) stackers' choices, not by any single attacker's controlled action needing signer keys. However, whether current/live reward cycles actually produce this degenerate distribution in practice is not verifiable purely from static code reading; it depends on real-world stacking amount distributions and which reward-set-construction code path (`make_signer_set` vs. `pox_5_make_signer_set`) is active for a given epoch/cycle.

### Recommendation
- In `RewardSet::total_signing_weight()` (`stackslib/src/chainstate/stacks/boot/mod.rs`), treat an empty (but `Some`) signer list the same as `None` — return an error (e.g., `NoRegisteredSigners`) rather than `Ok(0)`.
- In `verify_signer_signatures` (`stackslib/src/chainstate/nakamoto/mod.rs`), explicitly reject blocks when `total_weight == 0` or `signers.is_empty()`, independent of the threshold computation, so a zero-weight reward set can never yield a zero-signature-required threshold.
- Consider migrating any remaining callers of the legacy floor-based `StacksChainState::make_signer_set` to the corrected Hare/largest-remainder allocation (`pox_5_make_signer_set`) that guarantees a non-empty, non-zero-weight signer set whenever there is any locked stake.

2. Confirm `make_signer_set` returns `Some(vec![])` for such inputs (as opposed to `None`), and store this into a `RewardSet` with `signers: Some(vec![])`.
3. Call `reward_set.total_signing_weight()` — observe it returns `Ok(0)` rather than an error, per [7](#0-6) .

Build a `NakamotoBlockHeader` with `signer_signature: vec![]` (no signatures) and call `header.verify_signer_signatures(&reward_set, epoch_id)`; per the logic at [8](#0-7) , `threshold = compute_voting_weight_threshold(0) = 0`, and `total_weight_signed (0) < threshold (0)` is `false`, so the function returns `Ok(0)` — the block passes signature verification with zero signer approvals.

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Return the total `weight` of all signers in the reward set.
    /// If there are no reward set signers, a ChainstateError is returned.
    pub fn total_signing_weight(&self) -> Result<u32, String> {
        let Some(signers) = self.signers() else {
            return Err("Unable to calculate total weight - No signers in reward set".to_string());
        };
        Ok(signers.iter().map(|s| s.weight).fold(0, |s, acc| {
            acc.checked_add(s)
                .expect("FATAL: Total signer weight > u32::MAX")
        }))
    }

    /// Return a reference to the signers list.
    /// V0 returns `None` if the signers field is `None`;
    /// Waterfall always has signers.
    pub fn signers(&self) -> Option<&Vec<NakamotoSignerEntry>> {
        match self {
            RewardSet::V0(v0) => v0.signers.as_ref(),
            RewardSet::Waterfall(wf) => Some(&wf.signers),
        }
    }

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
    }

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );
}
