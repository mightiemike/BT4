## Title
Auto-swap `minPCOut` slippage protection is derived from a manipulable same-block spot quote, allowing sandwich extraction of user gas-swap and gas-refund funds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The Derby report's root cause is that a slippage/minimum-output bound was derived without protection against price movement between quote and execution, letting an attacker (via front-running) force execution at an unfavorable price. Push Chain's `uexecutor` module reproduces the same pattern natively: `GetSwapQuote` [1](#0-0)  fetches a fresh spot quote from the on-chain Uniswap V3 `QuoterV2` contract, and the caller immediately derives a fixed 5% slippage bound (`minPCOut = quote * 95 / 100`) from that same-block quote before performing the real swap via `CallPRC20DepositAutoSwap` [2](#0-1) .

### Finding Description
There are three call sites that follow this "quote-then-swap-in-same-tx" pattern with no TWAP or external price reference:

1. Gas-only inbound auto-swap: `ExecuteInboundGas` fetches `GetSwapQuote` and computes `minPCOut` at 95% of the quote immediately before calling `CallPRC20DepositAutoSwap` [3](#0-2) .
2. Gas+payload inbound auto-swap: `gasAndPayloadDepositAutoSwap` does the identical quote → 95% minPCOut → swap sequence [4](#0-3) .
3. Outbound gas refund: `applyGasRefund` computes `minPCOut` the same way before calling `CallUniversalCoreRefundUnusedGas` [5](#0-4) .

All three read the pool state at the moment `MsgVoteInbound` (or the outbound-observation message) is processed within a block. Because the quote and the swap are both executed inside a single `DeliverTx` of a validator-submitted message, an unprivileged attacker cannot alter price *between* the quote and swap calls within that transaction — but they *can* alter the underlying Uniswap V3 pool's price *before* that transaction executes, by submitting their own swap transaction against the same low-liquidity PRC20↔WPC pool and paying to have it ordered earlier in the same block (or simply by transacting whenever pool liquidity is thin, since anyone can call the pool permissionlessly). Since the 5% band is fixed and derived only from the current (attacker-influenced) spot price rather than any external reference or TWAP, the tolerance offers no real protection against this manipulation — mirroring exactly the Derby M-4 pattern where an "unprotected" slippage bound let an attacker force execution at an artificially bad price. The upgrade log confirms this mechanism was only recently introduced, replacing a "0-slippage call" with a quote-derived 5% band [6](#0-5) , without any accompanying anti-manipulation safeguard (e.g., TWAP oracle, deadline enforcement, external price feed).

### Impact Explanation
A depositor's inbound gas-abstraction swap (real bridged funds being converted from PRC20 to native PC) or a relayer's excess-gas refund swap can be executed at a manipulated price, up to the full 5% slippage band, with the difference captured by whoever manipulated the pool immediately beforehand. This is a direct loss of user/protocol-controlled funds during the auto-swap step of `depositPRC20WithAutoSwap` and `refundUnusedGas`, matching the "corruption of PRC20 or native asset accounting" / fund-loss impact category, and is triggerable purely by an ordinary user with capital to move a thinly-liquid pool and by paying for transaction priority — no validator or TSS privilege is required.

### Likelihood Explanation
Likelihood depends on the liquidity depth of each PRC20↔WPC pool relative to attacker capital, and on the attacker's ability to get their manipulation transaction ordered immediately before the target `MsgVoteInbound`/outbound-observation transaction in the same block (feasible via gas-price bidding on a permissionless mempool). For newly listed or low-volume PRC20 tokens this is realistically exploitable; the fixed 5% band caps the exploitable amount per swap but is uniformly applied regardless of pool depth or trade size, so it is a meaningful and repeatable value-extraction vector rather than a purely theoretical one.

### Recommendation
Do not derive the slippage bound solely from a spot quote fetched at execution time. Use a manipulation-resistant reference price (e.g., a time-weighted average price over multiple blocks, or an external oracle) to bound `minPCOut`, and/or cap per-swap trade size relative to available pool liquidity, and/or require a deadline plus a maximum acceptable price-impact check independent of the same-block quote so that an attacker cannot move the reference price and the execution price with a single coordinated block of transactions.

### Proof of Concept
1. Identify a PRC20↔WPC Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetDefaultFeeTierForToken` with shallow liquidity.
2. Front-run: submit (with sufficiently high gas/priority) a large swap against that pool to push the spot price in the direction that will worsen the amount a subsequent PRC20→WPC swap receives.
3. Ensure this transaction lands in the same block before a pending `MsgVoteInbound` (or outbound-observation) transaction that will trigger `ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap` / `applyGasRefund` for that same PRC20.
4. When the target's transaction executes, `GetSwapQuote` reads the manipulated pool state, `minPCOut` is computed at 95% of that already-degraded quote, and `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes within that band — the depositor/refund recipient receives up to 5% less PC than fair value.
5. Back-run: reverse the initial swap to restore the pool and realize the captured value, completing a sandwich extracting value from the user's bridged deposit or gas refund.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
