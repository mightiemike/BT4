**Rationale:**

The `Claim` struct in [1](#0-0)  is a pure deserialization wrapper for an already-committed Move event (`aptos_token::token_transfers::Claim`), used only by the indexer's V2→V1 event translation logic at [2](#0-1) . It performs no validation because it isn't supposed to — the accessors just expose fields already committed to the ledger by consensus-executed VM output; they don't participate in write-set construction, proof binding, or authenticated response binding.

The actual semantics of `account == to_address` are determined entirely by the Move module logic in [3](#0-2) . `claim()` emits `Claim{ account: sender, to_address: signer::address_of(receiver), ... }` reflecting exactly what happened: tokens moved from `sender`'s `PendingClaims` table to `receiver`. If a user genuinely offers a token to themselves via `offer()` and then claims it, `account == to_address` correctly and faithfully represents that real on-chain state transition — it is not data corruption, since nothing in the write set, transaction output, event log, or proof material is misrepresented relative to VM execution. [4](#0-3) 

The question itself concedes the impact is limited to "derived claim-history state (not the ledger's write set)" via an off-chain indexer/API aggregation layer. That is explicitly out of scope per the review's decision standard, which requires corruption of committed state, proof material, or misbinding of an authenticated response bound to ledger version/root — none of which occurs here. Whether an indexer chooses to flag or exclude self-claims from "transfer volume" statistics is an application-level business-logic/presentation choice, not a state-integrity defect in the core protocol, storage, proof, or restore paths.

        {
            let object_resource: PendingClaimsResource = bcs::from_bytes(&state_value_bytes)?;
            let key = *object_resource.claim_events().key();
            let sequence_number =
                engine.get_next_sequence_number(&key, object_resource.claim_events().count())?;
            (key, sequence_number)

            // If the PendingClaims resource is not found, we skip the event translation to

            *claim.to_address(),
            claim.token_id().clone(),

        Ok(ContractEventV1::new(
            key,
            sequence_number,
            TOKEN_CLAIM_EVENT_TYPE.clone(),

    public fun offer(
        sender: &signer,
        receiver: address,
        token_id: TokenId,
        amount: u64,
    ) acquires PendingClaims {
        let sender_addr = signer::address_of(sender);
        if (!exists<PendingClaims>(sender_addr)) {
            initialize_token_transfers(sender)
        };

        let pending_claims =
            &mut PendingClaims[sender_addr].pending_claims;
        let token_offer_id = create_token_offer_id(receiver, token_id);
        let token = token::withdraw_token(sender, token_id, amount);
        if (!pending_claims.contains(token_offer_id)) {
            pending_claims.add(token_offer_id, token);
        } else {
            let dst_token = pending_claims.borrow_mut(token_offer_id);
            token::merge(dst_token, token);
        };

        event::emit(
            Offer {
                account: sender_addr,
                to_address: receiver,
                token_id,
                amount,
            }
        );
    }

    public fun claim(
        receiver: &signer,
        sender: address,
        token_id: TokenId,
    ) acquires PendingClaims {
        assert!(exists<PendingClaims>(sender), ETOKEN_OFFER_NOT_EXIST);
        let pending_claims =
            &mut PendingClaims[sender].pending_claims;
        let token_offer_id = create_token_offer_id(signer::address_of(receiver), token_id);
        assert!(pending_claims.contains(token_offer_id), error::not_found(ETOKEN_OFFER_NOT_EXIST));
        let tokens = pending_claims.remove(token_offer_id);
        let amount = token::get_token_amount(&tokens);
        token::deposit_token(receiver, tokens);

        event::emit(
            Claim {
                account: sender,
                to_address: signer::address_of(receiver),
                token_id,
                amount,
            }
        );
    }
