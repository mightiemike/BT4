### Title
Zero-total-weight signer set makes `verify_signer_signatures` accept a Nakamoto block with **no signatures at all** - (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` rejects a block only when `total_weight_signed < threshold`. If the reward-cycle's signer list is non-`None` but has zero total weight, `compute_voting_weight_threshold` returns `0`, so an empty `signer_signature` vector (`total_weight_signed == 0`) satisfies `0 < 0 == false` and the block is treated as validly signed. This is the same bug class as the OpenClaw advisory (empty approver list silently becomes "everyone/anyone approved") applied to the Nakamoto signer-weight gate.

### Finding Description
`verify_signer_signatures` computes the required threshold purely from `total_weight`: [1](#0-0) [2](#0-1) 

and the threshold function itself: [3](#0-2) 

`compute_voting_weight_threshold(0)` evaluates `(0 * 7) % 10 == 0` → `ceil = 0`, so it returns `0`. Back in `verify_signer_signatures`, when the reward set's `signers()` is `Some(&[])` (a non-`None`, but empty, vector), `total_signing_weight()` returns `0` (fold over empty iterator), and with zero submitted signatures `total_weight_signed` stays `0`. The check `total_weight_signed < threshold` becomes `0 < 0`, which is `false`, so the function returns `Ok(0)` — the block is accepted as if a supermajority had signed it, even though **zero** signers actually signed.

The precondition — a `RewardSet` whose `signers()` is `Some(empty vec)` rather than `None` — is directly reachable through `StacksChainState::make_signer_set`: [4](#0-3) 

`make_signer_set` only returns `None` when the **input entries list** is empty (line 1024-1027) or when entries lack signing keys (1035-1037). If entries are non-empty and carry signing keys, but every entry's `stacked_amt / threshold` floors to `0` (e.g., many small stackers each below the per-slot PoX threshold), the `filter_map` at lines 1053-1064 drops every entry, and the function still returns `Some(signer_set)` with `signer_set` empty (line 1071) — this is the "empty approver list" state. That `Some(vec![])` is stored directly into `RewardSetV0.signers` (line 1188 of the same file) and surfaces through `RewardSet::signers()`: [5](#0-4) [6](#0-5) 

Contrast this with the newer PoX-5 signer-set construction, which explicitly guards against the all-zero-weight/empty-signer-set outcome: [7](#0-6) 

and with a companion regression test that fixed the exact same "entire set zeroed" failure mode for the Hare-round scheme used in `pox_5_make_signer_set`: [8](#0-7) 

No equivalent guard exists in the PoX-4 path, `pox_4_compute_and_update_signers`, which happily forwards `reward_set.signers().unwrap_or(&empty_signers)` to `update_signers` regardless of whether the computed set is empty: [9](#0-8) 

The consuming block-validation callers (`check_nakamoto_block_signer_signature` in P2P, and the Nakamoto chainstate append/staging path) treat any `Ok(weight)` from `verify_signer_signatures` as "signed": [10](#0-9) 

None of these callers separately check that `total_weight > 0`; they rely entirely on the `total_weight_signed < threshold` comparison, which — as shown — degenerates to a vacuous truth when `total_weight == 0`.

### Impact Explanation
This breaks the core consensus equality "a block is valid only if signer weight ≥ 70% threshold." With a zero-weight (but non-`None`) signer set, the equality collapses to `0 ≥ 0`, meaning a Nakamoto block with an **empty** `signer_signature` vector is accepted by every node evaluating that reward cycle — no signer approval, no attacker-controlled signature forgery, and no majority collusion required. Any miner able to produce a tenure in a reward cycle whose signer set degenerated to empty could push blocks through without any signer sign-off, which is a High/Critical-severity divergence from intended protocol behavior (a signer-approval gate that is supposed to require supermajority weight instead requiring none). This maps to the "invalid block accepted network-wide" impact category, since every honest node runs the identical (broken) equality and would accept the same signature-less block.

### Likelihood Explanation
The trigger condition — a PoX-4-computed signer set whose distinct stackers all individually fall under the per-slot threshold while collectively contributing enough participation to avoid the "not enough participation → burn" fallback — is a specific but not exotic combination of stacking amounts; it is exactly the failure mode that the PoX-5 code explicitly hardened against (see the `equal_stakes_exceeding_reward_slots_are_not_all_zeroed` regression test and the `signer_set.is_empty()` guard in `pox_5_compute_and_update_signers`), while the older PoX-4 path (`StacksChainState::make_signer_set` / `pox_4_compute_and_update_signers`) still lacks that guard. No privileged or majority-controlled action is needed to reach the empty-weight state; it only requires that stackers organize their commitments in this pattern.

### Recommendation
Add an explicit `total_weight == 0` (or `signers` empty) check inside `verify_signer_signatures` and reject the block outright (independent of the number of signatures), mirroring the guard already present in `pox_5_compute_and_update_signers`. Additionally, apply the same "reject/refuse to activate an empty-or-zero-weight signer set" protection to the PoX-4 signer-set computation path (`StacksChainState::make_signer_set` / `pox_4_compute_and_update_signers`) so a degenerate reward set is never persisted or used for signature verification in the first place.

### Proof of Concept
1. Construct PoX-4 stacker entries such that every individual stacker's `amount_stacked / threshold` floors to `0` (e.g., many small stackers whose cumulative participation still clears `enough_participation`, but each falls below the per-slot `threshold`).
2. `StacksChainState::make_signer_set(threshold, &entries)` returns `Some(vec![])` (all entries filtered out by the `weight == 0` check at `stackslib/src/chainstate/stacks/boot/mod.rs:1056-1058`).
3. This becomes `RewardSetV0.signers = Some(vec![])`, so `RewardSet::signers()` returns `Some(&[])` (non-`None`) and `total_signing_weight()` returns `0`.
4. A miner builds a `NakamotoBlockHeader` with `signer_signature = vec![]` for this reward cycle.
5. `header.verify_signer_signatures(&reward_set, epoch_id)` computes `threshold = compute_voting_weight_threshold(0) = 0`, `total_weight_signed = 0`, and `0 < 0` is `false`, so it returns `Ok(0)` — the header is accepted as validly signed despite having zero signatures, confirmed by tracing `stackslib/src/chainstate/nakamoto/mod.rs:1097-1190` and the threshold arithmetic at `1194-1207`.

    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );

    /// Check the signature of a NakamotoBlock against its sortition's reward cycle.
    /// The reward cycle must be recent. `epoch_id` is the epoch of the block's

    pub(crate) fn check_nakamoto_block_signer_signature(

        epoch_id: StacksEpochId,
        nakamoto_block: &NakamotoBlock,
    ) -> bool {
        let Some(rc_data) = self.current_reward_sets.get(&reward_cycle) else {
            info!(
                "{:?}: Failed to validate Nakamoto block {}/{}: no reward set for cycle {reward_cycle}",
                self.get_local_peer(),
                &nakamoto_block.header.consensus_hash,
                &nakamoto_block.header.block_hash(),
            );
            return false;
        };
        let Some(reward_set) = rc_data.reward_set() else {
            info!(
                "{:?}: No reward set for reward cycle {}",
                self.get_local_peer(),
                reward_cycle
            );
            return false;
        };

        if let Err(e) = nakamoto_block
            .header
            .verify_signer_signatures(reward_set, epoch_id)
        {
            info!(
                "{:?}: signature verification failure for Nakamoto block {}/{} in reward cycle {}: {:?}", self.get_local_peer(), &nakamoto_block.header.consensus_hash, &nakamoto_block.header.block_hash(), reward_cycle, &e
            );
            return false;
        }
        true
    }
