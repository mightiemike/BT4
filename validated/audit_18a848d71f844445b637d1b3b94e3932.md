## Finding

### Title
`VoteWitnessActuator` fails to merge duplicate witness addresses in a single vote transaction, unlike the TVM-native `VoteWitnessProcessor` - (File: `actuator/src/main/java/org/tron/core/actuator/VoteWitnessActuator.java`)

### Summary
The legacy `VoteWitnessActuator.countVoteAccount` appends every `Vote` entry from a broadcast `VoteWitnessContract` directly to `accountCapsule` and `votesCapsule` without first merging duplicate witness addresses, whereas the newer TVM-native `VoteWitnessProcessor.execute` explicitly builds a `Map<ByteString, Long> voteMap` to merge votes for the same witness before applying them [1](#0-0) . This is structurally analogous to the reported `RegistryFactory.addAttester` bug class: an entity that should enforce uniqueness accepts an unvalidated, duplicate-laden list and persists it as-is.

### Finding Description
`VoteWitnessActuator.validate()` iterates `contract.getVotesList()` and only checks each vote's address validity, existence, and that the **sum** of vote counts does not exceed the voter's tronPower [2](#0-1) . It never checks that vote addresses are unique.

`countVoteAccount()` then iterates the raw (unmerged) vote list and calls `votesCapsule.addNewVotes(...)` and `accountCapsule.addVotes(...)` once per `Vote` entry, including duplicates for the same witness address [3](#0-2) .

By contrast, the equivalent TVM-native path `VoteWitnessProcessor.execute()` explicitly merges votes for the same witness into a `voteMap` before writing them to the account/votes capsules, with an inline comment `// merge vote for same witness` [4](#0-3) . This shows the intended, correct behavior includes deduplication/merging by witness address — behavior the older, more widely used actuator path lacks.

As a result, a normal `VoteWitnessContract` transaction (reachable directly via broadcast from any account, no privilege required) can end up with multiple separate `Vote` entries for the identical witness address stored in `AccountCapsule.votes` and `VotesCapsule.newVotes`, instead of one merged entry — mirroring the report's core defect: a caller-controlled list that is supposed to be deduplicated/normalized before being persisted for downstream accounting logic, but is not.

### Impact Explanation
Whether this causes concrete on-chain harm depends on how every downstream consumer of `AccountCapsule.getVotesList()` / `VotesCapsule.getNewVotes()` handles duplicate entries for the same witness address:
- `MaintenanceManager.countVote()` iterates votes and aggregates into a `Map<ByteString, Long>` keyed by address, so duplicate entries are correctly summed there [5](#0-4) .
- `PrecompiledContracts.VoteCount`/`UsedVoteCount` also iterate and sum matching entries, so totals remain correct even with duplicates [6](#0-5) .

Because I was blocked from completing the final tool calls (index/tool budget exhausted) I could not fully confirm the exact byte-level semantics of `AccountCapsule.addVotes` / `VotesCapsule.addNewVotes` (whether they append raw entries or already internally merge by address). All evidence gathered (the actuator's forEach-append pattern versus the TVM processor's explicit map-merge with an inline comment referencing exactly this fix) strongly suggests the legacy actuator does not merge, but I could not directly inspect the capsule method bodies to rule out an internal merge step there. Without that confirmation, I cannot assert a concrete state-corruption, consensus-divergence, or DoS impact with certainty — the places I *could* verify (`countVote`, vote-count precompiles) tolerate duplicate entries via address-keyed aggregation, which limits impact even if duplicates are persisted.

### Likelihood Explanation
Reachability is high: any account can trigger this by broadcasting a `VoteWitnessContract` with the same `voteAddress` repeated across multiple `Vote` entries within the same transaction, entirely unprivileged. However, without confirming that `addVotes`/`addNewVotes` actually persist unmerged duplicates (rather than merging internally), the practical severity is unproven.

### Recommendation
Verify `AccountCapsule.addVotes` and `VotesCapsule.addNewVotes` implementations directly. If they append raw `Vote` entries without merging by address, apply the same fix already present in `VoteWitnessProcessor`: merge votes by witness address into a map before writing to `AccountCapsule`/`VotesCapsule` in `VoteWitnessActuator.countVoteAccount`, and reject (or dedupe) contracts containing duplicate vote addresses during `validate()`, matching the safer, sorted/deduplicated pattern established for `RegistryFactory`-style attester lists in the reported analog.

### Proof of Concept
Not fully verifiable without confirming `AccountCapsule.addVotes`/`VotesCapsule.addNewVotes` semantics; conceptually:
1. Freeze balance to obtain tronPower.
2. Broadcast a `VoteWitnessContract` with two `Vote` entries both pointing to the same witness address (e.g. counts 5 and 3, sum 8 ≤ tronPower).
3. Inspect resulting `AccountCapsule.getVotesList()` / `VotesCapsule.getNewVotes()` to check whether two separate entries for the same witness persist instead of one merged entry (compare against `VoteWitnessProcessor`'s merged behavior for the TVM-native vote path). [7](#0-6) [8](#0-7)

  private void countVoteAccount(VoteWitnessContract voteContract) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] data) {
      if (data == null || data.length != 2 * WORD_SIZE) {
        return Pair.of(true, longTo32Bytes(0L));
      }

      DataWord[] words = DataWord.parseArray(data);
      byte[] address = words[0].toTronAddress();
      AccountCapsule accountCapsule = this.getDeposit().getAccount(address);

      long voteCount = 0;
      if (accountCapsule != null && !accountCapsule.getVotesList().isEmpty()) {
        ByteString witness = ByteString.copyFrom(words[1].toTronAddress());
        for (Protocol.Vote vote : accountCapsule.getVotesList()) {
          if (witness.equals(vote.getVoteAddress())) {
            voteCount += vote.getVoteCount();
          }
        }
      }

      return Pair.of(true, longTo32Bytes(voteCount));
    }
  }
