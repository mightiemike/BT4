### Title
Cross-origin credential disclosure via unchecked `domain` parameter in RemoteActorCredentialSharing - (File: chrome/browser/password_manager/remote_actor/remote_actor_credential_sharing_impl.cc)

### Summary
The `RemoteActorCredentialSharing` Mojo interface only origin-checks the *calling* frame (must be `gemini.google.com` or the pre-prod sandbox host) before binding, but never verifies that the caller-supplied `domain` argument matches the calling frame's own origin. This lets the allowed origin request password-store lookups and cross-origin credential sharing for *any* domain, analogous to Pickle Finance's `swapExactJarForJar`, which authenticated the caller but never whitelisted/validated the target "jar" being swapped against.

### Finding Description
`RemoteActorCredentialSharingImpl::BindReceiver` only checks that the frame's committed origin is on an allowlist via `IsRemoteActorCredentialSharingAllowedForOrigin` before binding the interface: [1](#0-0) 

`RequestAgentAuthentication` then validates only that the request comes from the primary main frame, has a user gesture, and passes `ChildProcessSecurityPolicy::CanAccessDataForOrigin` for the *frame's own* origin — it never checks that the attacker-supplied `domain` string equals or is affiliated with that same origin: [2](#0-1) 

The unchecked `domain` is then used directly to build a `PasswordFormDigest` and query the profile/account password stores for credentials matching that (arbitrary) domain: [3](#0-2) 

Matching credentials (including PSL/affiliated matches) are then handed to a selection dialog and, upon user selection and device re-authentication, shared to the `RemoteActorCredentialSharingService` with `web_origin` derived from the attacker-supplied `domain`, not from the requesting page's real origin: [4](#0-3) [5](#0-4) 

This is structurally the same bug class as the Pickle Finance exploit: the Controller correctly checked *who* was allowed to call `swapExactJarForJar`, but never checked *which* Jar was the legitimate target of the swap, letting an authorized caller redirect funds from an arbitrary victim jar. Here, the browser correctly checks *which origin* may call the credential-sharing API, but never checks *which domain's* stored credentials that call is permitted to pull, letting the whitelisted origin (`gemini.google.com`) fetch and route to itself credentials for any other origin the user has saved (e.g. a bank).

### Impact Explanation
Any page served from the whitelisted origin can request credentials for an arbitrary third-party domain and, if a matching credential exists in the profile/account password store, present it in a native selection dialog and (post device re-auth) exfiltrate the underlying `sync_pb::PasswordSpecificsData` to a remote actor service tagged with the attacker-chosen `web_origin`. This is a cross-origin disclosure of the user's saved passwords for sites unrelated to the calling page — a serious confidentiality violation. The whitelisted status of the origin does not imply it should be trusted with arbitrary users' credentials for other sites, only for its own domain.

### Likelihood Explanation
The bug requires the page to be served under the hardcoded allowed host (`gemini.google.com` or the sandbox host), which is only reachable if that origin is compromised via XSS/supply-chain, or if the feature is later relaxed. It also requires a transient user gesture, and the user must click through the native selection dialog and complete device re-authentication (fingerprint/PIN) — this is a real friction point, but the dialog only shows the target `credential_domain` string (attacker-controlled, taken from `pending_request_->domain`), which can be spoofed as a plausible relying-party name, making a convincing security-UI-style deception plausible. The underlying `IsRemoteActorCredentialSharingAllowedForOrigin` check and the `domain` field are entirely renderer-supplied except for the origin check, so no flags or extensions are needed — this is reachable purely via script from an allowed page.

### Recommendation
In `ValidateRequestPreconditions` (or immediately in `RequestAgentAuthentication`), verify that `domain` is equal to (or a PSL-affiliated match of) `target_frame.GetLastCommittedOrigin()`'s host, and call `receiver_.ReportBadMessage(...)` otherwise, mirroring the existing `CanAccessDataForOrigin` check. Alternatively, derive the queried domain entirely from `GetLastCommittedOrigin()` server-side rather than trusting the IPC argument, eliminating the possibility of specifying a foreign domain.

### Proof of Concept
1. Load a page on the whitelisted origin `https://gemini.google.com` (feature `kRemoteActorCredentialSharing` enabled).
2. From a user-gesture handler, call:
```js
chrome.requestAgentAuthentication(
  currentUserGaiaId,        // must equal the signed-in primary account's gaia id
  'victim-bank.com',        // arbitrary target domain, unrelated to gemini.google.com
  'task_id_123',
  (success) => { /* result */ }
);
```
3. If the profile/account password store has a saved credential for `victim-bank.com`, `OnAllLoginsRetrieved` shows a native selection dialog labeled with `credential_domain = "https://victim-bank.com"`.
4. User completes device re-authentication (unaware the requesting page is `gemini.google.com`, not `victim-bank.com`).
5. `ProceedWithCredential` shares the `victim-bank.com` password specifics to the `RemoteActorCredentialSharingService` with `web_origin` set to `https://victim-bank.com`, fully controlled by the calling script's `domain` argument — cross-origin credential exfiltration achieved without ever having navigated to `victim-bank.com`.

void RemoteActorCredentialSharingImpl::BindReceiver(
    mojo::PendingAssociatedReceiver<chrome::mojom::RemoteActorCredentialSharing>
        receiver,
    content::RenderFrameHost* rfh) {
  if (!rfh->IsInPrimaryMainFrame()) {
    return;
  }
  if (!IsRemoteActorCredentialSharingAllowedForOrigin(
          rfh->GetLastCommittedOrigin())) {
    rfh->GetProcess()->ShutdownForBadMessage(
        content::RenderProcessHost::CrashReportMode::GENERATE_CRASH_DUMP);
    return;
  }

  auto* impl =
      RemoteActorCredentialSharingImpl::GetOrCreateForCurrentDocument(rfh);
  impl->Bind(std::move(receiver));
}

void RemoteActorCredentialSharingImpl::OnAllLoginsRetrieved() {
  if (!pending_request_) {
    return;
  }

  if (pending_request_->credentials.empty()) {
    LogResult(RemoteActorCredentialSharingResult::kNoPasswordsFound);
    std::move(pending_request_->callback).Run(false);
    pending_request_.reset();
    return;
  }

  content::WebContents* web_contents =
      content::WebContents::FromRenderFrameHost(&render_frame_host());
  if (!web_contents) {
    LogResult(RemoteActorCredentialSharingResult::kOtherError);
    std::move(pending_request_->callback).Run(false);
    pending_request_.reset();
    return;
  }

  std::string credential_domain =
      base::StrCat({"https://", pending_request_->domain});

  std::vector<std::unique_ptr<PasswordForm>> credentials_ptr;
  for (PasswordForm& form : pending_request_->credentials) {
    credentials_ptr.push_back(std::make_unique<PasswordForm>(std::move(form)));
  }

  auto dialog_callback =
      base::BindOnce(&RemoteActorCredentialSharingImpl::OnDialogResult,
                     weak_ptr_factory_.GetWeakPtr());

  dialog_controller_ =
      dialog_factory_.Run(web_contents, std::move(credentials_ptr),
                          credential_domain, std::move(dialog_callback));
  dialog_controller_->Show();
}

bool RemoteActorCredentialSharingImpl::ValidateRequestPreconditions(
    const std::string& gaia_id,
    const std::string& domain,
    const std::string& task_id) {
  content::RenderFrameHost& target_frame = render_frame_host();

  if (!target_frame.IsInPrimaryMainFrame()) {
    receiver_.ReportBadMessage(
        "RemoteActorCredentialSharing: Request from subframe");
    return false;
  }

  if (!target_frame.HasTransientUserActivation()) {
    receiver_.ReportBadMessage(
        "RemoteActorCredentialSharing: Request without user gesture");
    return false;
  }

  auto* policy = content::ChildProcessSecurityPolicy::GetInstance();
  if (!policy->CanAccessDataForOrigin(
          target_frame.GetProcess()->GetID().GetUnsafeValue(),
          target_frame.GetLastCommittedOrigin())) {
    receiver_.ReportBadMessage(
        "RemoteActorCredentialSharing: Process cannot access origin");
    return false;
  }

  if (gaia_id.length() >= kMaxArgumentLength ||
      domain.length() >= kMaxArgumentLength ||
      task_id.length() >= kMaxArgumentLength) {
    receiver_.ReportBadMessage(
        "RemoteActorCredentialSharing: Argument length limit exceeded");
    return false;
  }

  return true;
}

void RemoteActorCredentialSharingImpl::QueryPasswordStores(
    Profile* profile,
    const std::string& gaia_id,
    const std::string& domain,
    const std::string& task_id,
    RequestAgentAuthenticationCallback callback) {
  CHECK(!pending_request_);
  dialog_controller_.reset();

  auto* sync_service = SyncServiceFactory::GetForProfile(profile);
  const bool is_password_sync_active =
      sync_service &&
      sync_util::IsSyncFeatureActiveIncludingPasswords(sync_service);
  // We only query stores that contain credentials synced to the Google Account.
  // - If password sync is active (sync-the-feature), the profile store contains
  //   the synced credentials.
  // - If sync is inactive but account storage is active (sync-the-transport),
  //   the account store contains the account-scoped credentials.
  // Local-only credentials (profile store when sync is inactive) are excluded
  // from sharing.
  std::vector<PasswordStoreInterface*> stores;
  if (is_password_sync_active) {
    auto profile_store = ProfilePasswordStoreFactory::GetForProfile(
        profile, ServiceAccessType::EXPLICIT_ACCESS);
    CHECK(profile_store);
    stores.push_back(profile_store.get());
  } else if (sync_service &&
             features_util::IsAccountStorageActive(sync_service)) {
    auto account_store = AccountPasswordStoreFactory::GetForProfile(
        profile, ServiceAccessType::EXPLICIT_ACCESS);
    CHECK(account_store);
    stores.push_back(account_store.get());
  }

  if (stores.empty()) {
    LogResult(RemoteActorCredentialSharingResult::kNoSyncOrAccountStorage);
    RespondWithError(std::move(callback));
    return;
  }

  pending_request_ = PendingRequest{
      .gaia_id = gaia_id,
      .domain = domain,
      .task_id = task_id,
      .callback = std::move(callback),
      .expected_callbacks = static_cast<int>(stores.size()),
  };

  PasswordFormDigest digest(PasswordForm::Scheme::kHtml,
                            base::StrCat({"https://", domain, "/"}),
                            GURL(base::StrCat({"https://", domain})));

  for (PasswordStoreInterface* store : stores) {
    store->GetLogins(digest, weak_ptr_factory_.GetWeakPtr());
  }
