### Title
Unbounded persistent class-manager storage growth via unpaid Declare transactions - ([File: crates/apollo_transaction_converter/src/transaction_converter.rs])

### Summary
The Gateway calls `class_manager_client.add_class(tx.contract_class)` for every `Declare` transaction *before* stateful fee/balance/nonce validation is performed, and the class is persisted to `ClassManager`'s permanent, unbounded on-disk `FsClassStorage` regardless of whether the transaction is subsequently rejected. [1](#0-0)  This mirrors the CMP `extraCerts` bug class: untrusted data is unconditionally cached/stored by a long-lived server-side component before the request is validated, and never expunged if the request is later rejected.

### Finding Description
In `GenericGateway::add_tx_inner`, the order of operations is:
1. Stateless validation only (format checks, no state access). [2](#0-1) 
2. `convert_rpc_tx_to_internal_and_executable_txs`, which calls `transaction_converter.convert_rpc_tx_to_internal_rpc_tx(tx)`. [3](#0-2) 
3. Only *after* that does `extract_state_nonce_and_run_validations` run stateful validation (balance, nonce, fee, signature-against-state, etc). [4](#0-3) 

Inside `convert_rpc_tx_to_internal`, for `RpcTransaction::Declare`, the Sierra contract class is unconditionally sent to `self.class_manager_client.add_class(tx.contract_class)` before any stateful check has run: [5](#0-4) 

`ClassManager::add_class` persists the class permanently: it compiles the Sierra to CASM and calls `self.classes.set_class(...)`, which writes the class to `S: ClassStorage` (the filesystem-backed `FsClassStorage`, an unbounded persistent store), in addition to populating the small fixed-size LRU caches (`class_cache_size`/`deprecated_class_cache_size`, default 10–128 entries). [6](#0-5) [7](#0-6) 

Unlike the in-memory LRU caches (`GlobalContractCache`, `CachedClassStorage`'s in-memory maps) which are bounded and evict on capacity, the underlying `FsClassStorage`/`ClassHashStorage` is a persistent, unbounded store (backed by an mdbx database with a configured max size on the order of 1 TB). [8](#0-7)  There is no code path shown that removes a class from this persistent storage if the Declare transaction that introduced it is subsequently rejected by stateful validation, fails fee/balance checks, is later rejected by the mempool, or is never actually included in a block. Because class hash is derived purely from the contract's Sierra content (`sierra_class.calculate_class_hash()`), an attacker can trivially generate unique, syntactically-valid Sierra classes to avoid the `class_cached` short-circuit and force fresh storage/compilation on every submission. [9](#0-8) 

### Impact Explanation
Any unprivileged transaction sender (subject only to `authorized_declarer_accounts` gating, if configured) can submit a stream of Declare transactions with unique valid Sierra bytecode and an account that will ultimately fail stateful validation (e.g., insufficient balance, wrong nonce/signature) or fail to ever be included in a block. Each submission forces the gateway to compile the class and persist it to the class manager's on-disk storage before validation completes, and the storage is never cleaned up on rejection. Repeated abuse drives unbounded disk growth on gateway/class-manager nodes, eventually leading to storage exhaustion and node failure/DoS — a resource-allocation-without-limits condition analogous to CWE-770 in the referenced CVE.

### Likelihood Explanation
The attack requires only the ability to submit RPC transactions to the gateway (no special privileges), and generating unique valid Sierra programs that pass stateless validation but fail later state checks is straightforward. The existing `max_concurrent_declare_compilations` semaphore and per-class object size limits bound CPU/compilation concurrency and per-class size, but do not bound the *total number* of distinct classes persisted over time, so the growth is only rate-limited, not capacity-limited.

### Recommendation
Defer or gate the call to `class_manager_client.add_class` until after stateful validation succeeds (or at minimum until the Declare transaction is admitted to the mempool), and/or add an explicit cleanup/expiry mechanism in `ClassManager`/`FsClassStorage` to remove classes that were added but whose corresponding Declare transaction was rejected or never committed within a bounded time window, mirroring the fix pattern used for the CMP `extraCerts` cache (purge added state on rejection).

### Proof of Concept
Not independently executable from static analysis alone; the code path is demonstrated via the read call chain: `Gateway::add_tx` → `add_tx_inner` (stateless validation, then conversion) → `convert_rpc_tx_to_internal_and_executable_txs` → `TransactionConverter::convert_rpc_tx_to_internal` → `class_manager_client.add_class(tx.contract_class)` (persisted) → stateful validation runs afterward and can reject the transaction, with no observed rollback of the class-manager write. [10](#0-9) [1](#0-0) 

**Uncertainty note**: I was not able to fully trace the `ClassManagerClient`/`add_class` RPC boundary or confirm the exact backing implementation used in production deployments (whether all deployments use `FsClassStorage` or an alternative `ClassStorage` implementation), nor could I locate any deferred-cleanup, TTL, or garbage-collection logic elsewhere in the repository for classes added by unconfirmed Declare transactions — the index/search did not surface one. If such a mechanism exists outside the indexed portions of the codebase, this finding's severity should be reassessed accordingly.

    #[instrument(skip(self, class), ret, err)]
    pub async fn add_class(&mut self, class: RawClass) -> ClassManagerResult<ClassHashes> {
        let sierra_class = SierraContractClass::try_from(&class)?;
        let class_hash = sierra_class.calculate_class_hash();
        if let Ok(Some(executable_class_hash_v2)) =
            self.classes.get_executable_class_hash_v2(class_hash)
        {
            // Class already exists.
            return Ok(ClassHashes { class_hash, executable_class_hash_v2 });
        }

        let compilation_start_time = Instant::now();
        let (raw_executable_class, executable_class_hash_v2) =
            self.compiler.compile(class.clone()).await.map_err(|err| match err {
                SierraCompilerClientError::SierraCompilerError(error) => {
                    ClassManagerError::SierraCompiler { class_hash, error }
                }
                SierraCompilerClientError::ClientError(error) => {
                    ClassManagerError::Client(error.to_string())
                }
            })?;
        debug!(
            %class_hash,
            compiled_class_hash = %executable_class_hash_v2,
            compilation_elapsed_ms = compilation_start_time.elapsed().as_millis(),
            class_size_bytes =
                class.size().map_or("Failed to get class size".to_owned(), |size| size.to_string()),
            casm_size_bytes =
                raw_executable_class.size().map_or("Failed to get casm size".to_owned(), |size| size.to_string()),
            "Finished compiling class."
        );

        self.validate_class_length(&raw_executable_class)?;
        Self::validate_class_version(&sierra_class)?;
        self.classes.set_class(
            class_hash,
            class,
            executable_class_hash_v2,
            raw_executable_class,
        )?;

        let class_hashes = ClassHashes { class_hash, executable_class_hash_v2 };
        Ok(class_hashes)
    }

    #[instrument(skip(self, class, executable_class), level = "debug", ret, err)]
    fn set_class(
        &mut self,
        class_id: ClassId,
        class: RawClass,
        executable_class_hash_v2: ExecutableClassHash,
        executable_class: RawExecutableClass,
    ) -> Result<(), Self::Error> {
        if self.class_cached(class_id) {
            return Ok(());
        }

        self.storage.set_class(
            class_id,
            class.clone(),
            executable_class_hash_v2,
            executable_class.clone(),
        )?;

        increment_n_classes(CairoClassType::Regular);
        record_class_size(ClassObjectType::Sierra, &class);
        record_class_size(ClassObjectType::Casm, &executable_class);

        // Cache the class.
        // Done after successfully writing to storage as an optimization;
        // does not require atomicity.
        self.classes.set(class_id, class);
        self.executable_classes.set(class_id, executable_class);
        // Cache the executable class hash last; acts as an existence marker.
        self.executable_class_hashes_v2.set(class_id, executable_class_hash_v2);

        Ok(())
    }
