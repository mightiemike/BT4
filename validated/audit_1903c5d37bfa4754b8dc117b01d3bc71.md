### Title
Floor-rounded 70% agreement/30% disagreement thresholds in `GlobalStateEvaluator` diverge from the ceiling-rounded block-approval threshold, letting sub-quorum signer weight be treated as consensus - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement` / `reached_disagreement` compute the 70%/30% signer-weight thresholds with plain floor integer division, while the analogous chain-critical threshold used to actually validate a Nakamoto block's aggregate signature, `NakamotoBlockHeader::compute_voting_weight_threshold`, deliberately rounds *up* to guarantee the true percentage is met. When `total_weight` is not a multiple of 10, these two computations diverge, so a signer can conclude that "global agreement" (on burn view, current miner, protocol version, or tx replay set) has been reached with strictly less than 70% of signer weight, and can conclude "disagreement" has been reached with slightly more than 30% weight in some boundary cases.

### Finding Description
`NakamotoBlockHeader::compute_voting_weight_threshold` is the reference implementation for what "70% of signer weight" means for block acceptance, and it explicitly adds a `ceil` term so the required weight is always rounded up: [1](#0-0) 

Test vectors confirm this rounds up (e.g. total weight 511 → threshold 358, i.e. `ceil(511*7/10)`): [2](#0-1) 

By contrast, `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` in `libsigner` — used by the `stacks-signer` binary to decide when signers have reached a common view of the burn chain tip, the current miner, the active signer-protocol version, and the transaction-replay set — use plain floor division with no ceiling correction: [3](#0-2) 

Because `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7` (giving `total_weight * 7 / 10`), this expression is *not* generally exact — it only produces a value with no remainder when `total_weight` is a multiple of 10. For any `total_weight` not divisible by 10, `total_weight * 7 / 10` floors down, so `reached_agreement` accepts a `vote_weight` that represents strictly less than 70% of `total_weight` (e.g. `total_weight = 13`: floor gives 9, and `9/13 ≈ 69.2%` < 70%, yet `reached_agreement(9)` returns `true`). The same asymmetry exists on the disagreement side.

This means the equality "signer state is only treated as agreed when weight ≥ true 70% quorum" is broken for the codepaths that rely on `GlobalStateEvaluator` (burn-view/miner-view/protocol-version/tx-replay-set consensus used by `stacks-signer` to decide tenure/miner recognition and transaction-replay behavior), even though the block-signature-validation codepath (`compute_voting_weight_threshold`, used in `verify_signer_signatures`) correctly enforces the stricter ceiling-based threshold: [4](#0-3) 

The result is two different, disagreeing definitions of "70% signer weight" living in the same trust boundary: one governs what a signer's local process treats as the network's agreed state, the other governs actual block acceptance. A minority coalition holding just under the true 70%/above true 30% (but crossing the floor-rounded boundary) can cause `GlobalStateEvaluator` to register spurious agreement/disagreement that would not be reached under the stricter, chain-consensus-grade rounding rule.

### Impact Explanation
This is a signer-weight-threshold divergence bounded to the signer coordination layer rather than a full chain split: it can cause a subset of signers to prematurely treat a burn view, current-miner selection, or transaction-replay set as globally agreed (or globally rejected) with less than the intended supermajority weight, in cases where `total_weight` is not a clean multiple of 10 (i.e., for the vast majority of real reward-cycle signer-set weight totals). This falls under the "signer weight below threshold" category and can manifest as temporary tip/miner-recognition disagreement among signers (High), though it does not by itself forge an invalid block signature since `compute_voting_weight_threshold` (correctly ceiling-rounded) still gates actual block acceptance.

### Likelihood Explanation
Any signer set whose total weight is not an exact multiple of 10 (the common case, since weights derive from reward-slot counts) triggers this floor-vs-ceiling mismatch — no privileged action or majority coalition is required, only a minority sized to land in the rounding gap between the floor and ceiling values.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use the same ceiling-rounding semantics as `NakamotoBlockHeader::compute_voting_weight_threshold` (or call that function directly), e.g.:
```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let threshold = NakamotoBlockHeader::compute_voting_weight_threshold(self.total_weight)
        .unwrap_or(self.total_weight);
    vote_weight >= threshold
}
```
so both codepaths agree on exactly what constitutes 70%/30% of signer weight.

### Proof of Concept
For `total_weight = 13`:
- True 70% requirement: `ceil(13 * 7 / 10) = ceil(9.1) = 10`.
- `compute_voting_weight_threshold(13)` → 10 (correct, ceiling).
- `reached_agreement(9)` in `GlobalStateEvaluator` → `9 >= 13*7/10 = 9` → `true`, despite `9/13 ≈ 69.2%` being below the true 70% quorum required elsewhere in the same system. [5](#0-4) [6](#0-5)

```rust
    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
```

```rust
    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
```
