## Analysis: TWAP-less spot price used for slippage protection in gas-swap deposit flows

The AFiOracle bug is about using a manipulable price source (too-short TWAP window) to compute a `minAmountOut` protecting a swap. Push Chain has a direct, and actually more severe, analog: the `GetSwapQuote` function does not use any time-weighted average at all — it queries `QuoterV2.quoteExactInputSingle` for the **current spot price** in the same call/transaction that immediately executes the swap. [1](#0-0) 

This quote is used to build `minPCOut` with a flat, hardcoded 5% slippage tolerance in three separate flows: normal GAS inbound deposits, GAS_AND_PAYLOAD deposits, and outbound gas-fee refunds: [2](#0-1) [3](#0-2) [4](#0-3) 

### Title
Spot-price (no TWAP) QuoterV2 quote used to bound swap slippage in inbound-gas and gas-refund auto-swap flows - (File: x/uexecutor/keeper/evm.go)

### Summary
`GetSwapQuote` fetches an instantaneous `quoteExactInputSingle` price from the Uniswap V3 `QuoterV2` and the caller immediately derives `minPCOut = quote * 95 / 100` before calling `depositPRC20WithAutoSwap` / `refundUnusedGas` in the same call chain, with no delay and no time-weighted averaging. This is the same bug class as the reported AFiOracle issue (manipulable, too-short-window price feed used to bound swap output), except here there is zero time-averaging — the reference price and the executed swap occur essentially atomically, in the same EVM state transition.

### Finding Description
`GetSwapQuote` calls the quoter with `commit=false` and returns whatever the AMM pool's current tick/liquidity state implies at that exact moment: [5](#0-4) 

The result feeds directly into a fixed 5% slippage bound, computed and consumed within the same function/flow with no intervening delay or independent price check: [6](#0-5) 

This pattern repeats for `gasAndPayloadDepositAutoSwap` and for `applyGasRefund`'s swap-based refund path, which also queries the quoter and applies the same 95% bound immediately before calling `CallUniversalCoreRefundUnusedGas`: [4](#0-3) 

Because these deposit/refund executions are triggered deterministically once Universal Validator votes finalize an inbound/outbound observation (a publicly-visible, predictable on-chain event), an unprivileged actor can manipulate the relevant Uniswap V3 pool's spot price (e.g., via a large swap) immediately before the finalizing transaction lands, causing `GetSwapQuote` to return a manipulated price. The subsequent `depositPRC20WithAutoSwap`/`refundUnusedGas` call then executes against that same manipulated pool state, bounded only by 5% slippage off the *manipulated* quote rather than any fair/historical reference price — the classic sandwich pattern the TWAP recommendation exists to prevent, except here there isn't even a short TWAP window to begin with (window = 0).

### Impact Explanation
An attacker can sandwich the auto-swap executed on behalf of users during GAS/GAS_AND_PAYLOAD inbound deposits and gas-fee refunds, extracting value from the PRC20→WPC conversion that is supposed to credit the user/UEA with native PC tokens. This directly corrupts PRC20/native asset accounting and can drain value from user deposits and protocol-controlled refund flows, matching the "corruption of PRC20 or native asset accounting" and fund-drain impact categories in scope.

### Likelihood Explanation
The triggering event (an inbound/outbound vote finalizing) is observable in the validator's broadcast transaction before it lands, and Uniswap V3 pools on the destination gas token/WPC pair can plausibly be manipulated with a flash-loan-funded swap by any unprivileged actor, requiring no validator or admin privilege — only capital and mempool visibility.

### Recommendation
Replace the instantaneous `QuoterV2.quoteExactInputSingle` reference price with a manipulation-resistant reference (e.g., a TWAP over a sufficiently long window from the pool's oracle, or a bound derived from the chain-meta gas-price oracle / an independent price feed) before computing `minPCOut`, and/or increase the slippage-tolerance computation to account for worst-case single-block manipulation, consistent with the TWAP-window fix applied to the referenced AFiOracle bug.

### Proof of Concept
1. Attacker monitors the mempool/consensus for the Universal Validator vote transaction that will finalize a pending GAS or GAS_AND_PAYLOAD inbound (or an outbound success vote triggering `applyGasRefund`).
2. Immediately before that transaction is included, attacker submits a large swap on the relevant PRC20↔WPC Uniswap V3 pool to move the spot price unfavorably for the upcoming auto-swap direction.
3. The validator's finalizing transaction executes `GetSwapQuote` → `quoteExactInputSingle`, which reads the now-manipulated pool state, producing a depressed `quote`; `minPCOut = quote * 95 / 100` is computed off this manipulated value.
4. `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` executes the real swap against the still-manipulated pool, delivering far less PC than fair value to the user/UEA, while still satisfying the (also depressed) `minPCOut` check.
5. Attacker reverses their initial swap in a following transaction, capturing the price difference as profit at the expense of the user/protocol.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
