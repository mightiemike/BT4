### Title
Unbounded growth of DelegatedResourceAccountIndexCapsule fromAccounts/toAccounts via unmetered 1-TRX delegations - ([File: chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java])

### Summary
`DelegatedResourceActuator.delegateResource` calls `DelegatedResourceAccountIndexStore.delegateV2` for every delegate transaction, and `getV2Index`/`getWithPrefix` performs an unbounded `prefixQuery` over all `V2_FROM_PREFIX`/`V2_TO_PREFIX` keys for an address, building lists with no size cap. [1](#0-0) [2](#0-1)  Any unprivileged account can freeze 1 TRX (the minimum allowed) and delegate it to N distinct freshly created receiver accounts, each delegation adding one more `to`/`from` index entry with no per-owner cap. [3](#0-2) 

### Finding Description
`delegateResource` (called from `DelegateResourceActuator.execute`) invokes `delegatedResourceAccountIndexStore.delegateV2(ownerAddress, receiverAddress, timestamp)` for every successful `DelegateResourceContract`. [4](#0-3)  `delegateV2` simply writes a new key-value pair per (from,to) combination using `V2_FROM_PREFIX`/`V2_TO_PREFIX` concatenated with addresses, with no check on how many distinct receivers/senders an address already has. [5](#0-4) 

When an index is later read via `getV2Index`, `getWithPrefix` performs a `prefixQuery` scan over all keys with that prefix+address, collects every matching capsule into a list, sorts it, and rebuilds the `toAccounts`/`fromAccounts` lists dynamically at read time — the size of this in-memory structure grows linearly with the number of distinct counterparties the address has ever delegated to/from, with no cap or pagination. [6](#0-5)  This index is exposed via RPC/HTTP handlers (`GetDelegatedResourceAccountIndexServlet`/`GetDelegatedResourceAccountIndexV2Servlet`, `RpcApiService`) that any anonymous client can query for any address.

`FreezeBalanceV2Actuator.validate()` enforces only a minimum of 1 TRX (`TRX_PRECISION`) per freeze operation and no cap on the number of freeze/delegate operations per account, so an attacker with modest TRX and the ability to create many receiver accounts (also cheap — new/activated accounts) can call freeze+delegate thousands of times to distinct receivers. [3](#0-2)  No actuator-level validate() check in `DelegateResourceActuator` limits the number of distinct receivers per owner; validation only checks address validity, receiver-not-contract, and lock-period bounds. [7](#0-6) 

### Impact Explanation
This matches TRON's "DoS via RPC-API" impact class: a node serving `getDelegatedResourceAccountIndex`/V2 queries for an attacker-controlled address must scan and construct a list proportional to the number of distinct delegate relationships, which is attacker-controlled and unbounded. At scale (tens of thousands of receivers) this creates elevated CPU (prefix scan + sort) and memory (list + protobuf serialization) cost per RPC/HTTP query, degrading node responsiveness for legitimate API clients — a repeatable, low-cost resource-exhaustion vector against a single node's query-serving capacity, not against consensus/state integrity.

### Likelihood Explanation
Preconditions are minimal and require no privileged role: the attacker only needs enough TRX to freeze 1 TRX per receiver and enough TRX to activate each new receiver account. Each freeze+delegate pair costs a full transaction (bandwidth/fee), so building 10k+ entries requires funding thousands of transactions, but there is no protocol-level cap preventing it and cost is linear and attacker-affordable relative to potential query-side cost imposed on the node. This is a genuine but moderate-severity issue since the attacker bears real (though small) per-entry transaction cost, while the victim (any RPC client / the serving node) bears repeated read-side cost each time the index is queried.

### Recommendation
Introduce a maximum cap on the number of distinct `fromAccounts`/`toAccounts` entries tracked per address in `DelegatedResourceAccountIndexStore.delegateV2`/`getWithPrefix` (e.g., reject or evict oldest beyond a fixed limit), and/or add pagination/limit parameters to the `getDelegatedResourceAccountIndex`/V2 RPC and HTTP handlers so a single query cannot force unbounded list construction and serialization.

```java
// Illustrative JUnit-style PoC using DelegatedResourceAccountIndexStore directly
@Test
public void testUnboundedIndexGrowth() {
  byte[] owner = ByteArray.fromHexString(OWNER_ADDRESS);
  int N = 20000;
  for (int i = 0; i < N; i++) {
    byte[] receiver = randomAddress(); // freshly generated
    delegatedResourceAccountIndexStore.delegateV2(owner, receiver, i);
  }
  long start = System.nanoTime();
  DelegatedResourceAccountIndexCapsule idx =
      delegatedResourceAccountIndexStore.getV2Index(owner);
  long elapsed = System.nanoTime() - start;
  // Assert list size grows unbounded and read cost scales with N
  Assert.assertEquals(N, idx.getToAccountsList().size());
  // No cap enforced -> demonstrates DoS surface when exposed via
  // GetDelegatedResourceAccountIndexV2Servlet / RpcApiService for arbitrary N
}
```
Expected result today: the test passes with `idx.getToAccountsList().size() == N` for arbitrarily large `N`, showing no bound is enforced, and read latency/memory scale linearly with `N` when queried repeatedly via the RPC/HTTP endpoint.

                                long balance, boolean lock, long lockPeriod) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicPropertiesStore = chainBaseManager.getDynamicPropertiesStore();
    DelegatedResourceStore delegatedResourceStore = chainBaseManager.getDelegatedResourceStore();
    DelegatedResourceAccountIndexStore delegatedResourceAccountIndexStore = chainBaseManager
        .getDelegatedResourceAccountIndexStore();

    // 1. unlock the expired delegate resource
    long now = chainBaseManager.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    delegatedResourceStore.unLockExpireResource(ownerAddress, receiverAddress, now);

    //modify DelegatedResourceStore
    long expireTime = 0;
    if (lock) {
      expireTime = now + lockPeriod * BLOCK_PRODUCED_INTERVAL;
    }
    byte[] key = DelegatedResourceCapsule.createDbKeyV2(ownerAddress, receiverAddress, lock);
    DelegatedResourceCapsule delegatedResourceCapsule = delegatedResourceStore.get(key);
    if (delegatedResourceCapsule == null) {
      delegatedResourceCapsule = new DelegatedResourceCapsule(ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
    }

    if (isBandwidth) {
      delegatedResourceCapsule.addFrozenBalanceForBandwidth(balance, expireTime);
    } else {
      delegatedResourceCapsule.addFrozenBalanceForEnergy(balance, expireTime);
    }
    delegatedResourceStore.put(key, delegatedResourceCapsule);

    //modify DelegatedResourceAccountIndexStore
    delegatedResourceAccountIndexStore.delegateV2(ownerAddress, receiverAddress,
        dynamicPropertiesStore.getLatestBlockHeaderTimestamp());

  public DelegatedResourceAccountIndexCapsule getV2Index(byte[] address) {
    return getWithPrefix(V2_FROM_PREFIX, V2_TO_PREFIX, address);

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }
