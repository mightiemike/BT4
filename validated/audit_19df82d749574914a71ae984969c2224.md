## Title
Vote reward reallocation lets a user claim a share of an already-accrued witness reward pool using a stale total-vote denominator, minting `allowance` from nothing - (File: `chainbase/src/main/java/org/tron/core/service/MortgageService.java`, `consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java`)

### Summary
The GLP report describes a share/asset accounting bug: a shared pool's "price" (accounted balance) is computed *before* pending value (unclaimed rewards) is folded in, letting an attacker mint disproportionate shares by depositing right before that value is realized, then redeeming after. java-tron's DPoS voting-reward accounting (`Vi`-based reward-per-vote algorithm) has the same class of flaw: a voter's personal reward snapshot is credited using their *full, freshly cast* vote weight against a per-cycle reward rate (`deltaVi`) that was computed from a **stale total-vote denominator which excludes that very vote**. This lets a user who votes right before a maintenance/cycle boundary claim reward for the whole cycle as if they had held their vote the entire time, on top of what the pre-existing voters already fully claim from the same fixed reward pot — over-allocating (minting) `allowance`/TRX-equivalent value that was never actually earned for that cycle.

### Finding Description
Witness rewards accrue per cycle via `MortgageService.payReward` into `delegationStore.addReward(cycle, witnessAddress, value)` [1](#0-0) . At each maintenance/cycle boundary, `MaintenanceManager.doMaintenance()` converts this accrued reward into a per-vote index `Vi` for the cycle that is ending, **using the witness's vote count as it stood before this maintenance's vote-delta aggregation**, and only afterward applies newly cast votes to the witness's total and publishes that new total as the vote count for the *next* cycle:

```java
if (dynamicPropertiesStore.useNewRewardAlgorithm()) {
  long curCycle = dynamicPropertiesStore.getCurrentCycleNumber();
  consensusDelegate.getAllWitnesses().forEach(witness -> {
    delegationStore.accumulateWitnessVi(curCycle, witness.createDbKey(), witness.getVoteCount());
  });
}
Map<ByteString, Long> countWitness = countVote(votesStore); // folds in this cycle's new votes
...
delegationStore.setWitnessVote(nextCycle, witness.createDbKey(), witness.getVoteCount());
``` [2](#0-1) 

`accumulateWitnessVi` computes `Vi(cycle) = Vi(cycle-1) + reward(cycle)/oldVoteCount` [3](#0-2) , i.e. the reward-per-vote rate for the closing cycle is fixed using a total-vote denominator that has **not yet included votes cast during that very cycle**.

Meanwhile, when a user calls `VoteWitnessActuator`/`VoteWitnessProcessor`, the actuator first settles past reward via `mortgageService.withdrawReward(ownerAddress)` (which resets `beginCycle = currentCycle`, sets `endCycle = currentCycle+1`, and snapshots the account's **new** vote list into `delegationStore.setAccountVote(endCycle, address, accountCapsule)`), then records the new votes into `accountCapsule` [4](#0-3)  and [5](#0-4) .

When this reward is later withdrawn, `computeReward(beginCycle, endCycle, account)` multiplies the **snapshotted full new vote count** by `deltaVi = Vi(endCycle-1) - Vi(beginCycle-1)`, i.e. exactly the just-computed rate for the cycle the user voted late in:

```java
BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
BigInteger deltaVi = endVi.subtract(beginVi);
long userVote = vote.getValue();
reward += deltaVi.multiply(BigInteger.valueOf(userVote)).divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
``` [6](#0-5) 

The identical mechanism exists in the TVM-exposed vote/withdraw precompiles (`vote`, `withdrawReward` opcodes), so this is reachable purely through unprivileged smart-contract calls, not just wallet transactions [7](#0-6) [8](#0-7) [9](#0-8) .

Because `reward(cycle)` for a witness is a fixed, already-collected pot (from block/tx-fee rewards) fully distributable among the *old* voters at the old total-vote weight, any late voter who is credited full-weight reward for that same cycle is extracting value that was never actually earned proportionally by them — the sum of all claims for that cycle can exceed `reward(cycle)`, functioning as an accounting divergence that mints `allowance` (later convertible to real TRX balance via `WithdrawBalanceActuator`/`WithdrawRewardProcessor`) from nothing [10](#0-9) [11](#0-10) .

### Impact Explanation
This is a direct accounting/state-divergence bug: unprivileged accounts (or smart contracts) can extract reward value disproportionate to the time/weight their vote actually contributed, funded by the fixed witness reward pool rather than by proportional dilution of other voters. Repeated exploitation (voting a large already-frozen stake right before each maintenance cycle across many witnesses) can systematically drain/inflate reward allowances beyond what `payReward` actually credited, which is a real-value TRX leak once withdrawn.

### Likelihood Explanation
Exploitation only requires calling the public `VoteWitnessContract`/TVM `vote` opcode with sufficient TRON Power (frozen balance) timed just before a maintenance cycle boundary (maintenance cadence and next-maintenance time are publicly readable on-chain), which is achievable by any account holding frozen TRX. No privileged role is required. The main constraint is that TRON Power still requires prior freezing of TRX (subject to freeze-duration rules), so the capital isn't flash-loanable in a single atomic transaction, but the same frozen stake can be repeatedly re-voted at each cycle boundary to and from different witnesses to repeat the exploit.

### Recommendation
Compute `Vi`/reward-rate for a closing cycle only from votes that were locked in for the *entire* cycle (i.e., fold in newly cast votes only for the *next* cycle's numerator as already done for the denominator), or require that a newly cast vote's personal reward snapshot for the cycle in which it is cast start counting from `currentCycle + 1` rather than `currentCycle`, consistent with how the witness's total-vote denominator is only updated for `nextCycle`. This keeps the per-voter accounting and the total-vote accounting consistently in-sync with the same point in time.

### Proof of Concept
1. Observe the on-chain `nextMaintenanceTime` (public dynamic property) to know when the current cycle `N` is about to end.
2. Ensure a large amount of TRX is already frozen (TRON Power available).
3. Just before `nextMaintenanceTime`, submit `VoteWitnessContract` (or call the TVM `vote` opcode) casting the full available TRON Power for witness `W`. This calls `mortgageService.withdrawReward` first (settling and resetting `beginCycle = N`), then records the full new vote weight into `accountCapsule` and snapshots it via `delegationStore.setAccountVote(N+1, address, accountCapsule)`.
4. At maintenance, `MaintenanceManager.doMaintenance()` computes `Vi(N)` for witness `W` using the **old** total vote count (excluding the just-cast vote), then folds the new vote into the total for cycle `N+1`.
5. Once cycle advances to `N+1`, call `WithdrawBalanceContract`/`withdrawReward`. `MortgageService.computeReward(beginCycle=N, endCycle=N+1, account)` credits `reward = userVoteCount_full * (Vi(N) - Vi(N-1))`, granting a full cycle's reward share for a vote that was live for only moments before the cycle ended, in addition to what the pool's pre-existing voters already collect from the same fixed `reward(N)` pot.

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }

  public static void withdrawReward(byte[] address, Repository repository) {
    if (!VMConfig.allowTvmVote()) {
      return;
    }
    AccountCapsule accountCapsule = repository.getAccount(address);
    long beginCycle = repository.getBeginCycle(address);
    long endCycle = repository.getEndCycle(address);
    long currentCycle = repository.getDynamicPropertiesStore().getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = repository.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = repository.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account, repository);
        adjustAllowance(address, reward, repository);
        reward = 0;
      }
      beginCycle += 1;
    }
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      repository.updateBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule, repository);
      adjustAllowance(address, reward, repository);
    }
    repository.updateBeginCycle(address, endCycle);
    repository.updateEndCycle(address, endCycle + 1);
    repository.updateAccountVote(address, endCycle, accountCapsule);
  }

  public void execute(VoteWitnessParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getVoterAddress();
    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);

    VotesCapsule votesCapsule = repo.getVotes(ownerAddress);
    if (votesCapsule == null) {
      votesCapsule = new VotesCapsule(ByteString.copyFrom(ownerAddress),
          accountCapsule.getVotesList());

    votesCapsule.clearNewVotes();

    Map<ByteString, Long> voteMap = new HashMap<>();
    Iterator<Protocol.Vote> iterator = param.getVotes().iterator();
    try {
      long sum = 0;
      while (iterator.hasNext()) {
        Protocol.Vote vote = iterator.next();

        byte[] witnessAddress = vote.getVoteAddress().toByteArray();
        /*
          Already covered while doing maintenance in MaintenanceManager.java, for tvm performance,
          we remove the account check
         */
//        if (repo.getAccount(witnessAddress) == null) {

//              ACCOUNT_EXCEPTION_STR + StringUtil.encode58Check(witnessAddress) + NOT_EXIST_STR);
//        }
        if (repo.getWitness(witnessAddress) == null) {
          throw new ContractExeException(
              WITNESS_EXCEPTION_STR + StringUtil.encode58Check(witnessAddress) + NOT_EXIST_STR);

        long voteCount = vote.getVoteCount();
        if (voteCount < 0) {
          throw new ContractExeException("Vote count must not be less than 0");

        tronPower = accountCapsule.getAllTronPower();
      } else {
        tronPower = accountCapsule.getTronPower();
      }
      sum =  LongMath.checkedMultiply(sum, TRX_PRECISION);

        throw new ContractExeException(

      }
    } catch (ArithmeticException e) {
      throw new ContractExeException(e.getMessage());
    }

      votesCapsule.addNewVotes(entry.getKey(), entry.getValue());

  public long execute(WithdrawRewardParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getOwnerAddress();

    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    long oldBalance = accountCapsule.getBalance();
    long allowance = accountCapsule.getAllowance();
    long newBalance = 0;

    try {
      newBalance = LongMath.checkedAdd(oldBalance, allowance);
    } catch (ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractExeException(e.getMessage());
    }

    // If no allowance, do nothing and just return zero.
    if (allowance <= 0) {
      return 0;
    }

    accountCapsule.setInstance(accountCapsule.getInstance().toBuilder()
        .setBalance(newBalance)
        .setAllowance(0L)
        .setLatestWithdrawTime(param.getNowInMs())
        .build());

    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
    return allowance;
  }
