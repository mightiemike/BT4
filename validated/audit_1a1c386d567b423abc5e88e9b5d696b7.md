### Title
`check_microblock_header_signer` accepts a single re-signed microblock as "two conflicting headers" via ECDSA signature malleability - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`)

### Summary
The poison-microblock equivocation proof relies on `h1 == h2` (full struct equality, including the raw `MessageSignature` bytes) in the codec deserializer, combined with `check_microblock_header_signer` only checking that both headers recover to the same pubkey hash. Because ECDSA/secp256k1 recoverable signatures are malleable — `(r, s, v)` and `(r, n-s, v⊕1)` both verify against the same message and recover to the same public key — an attacker can take a single honestly-signed microblock header, derive a second, byte-distinct header purely by flipping `s` and the recovery id, and pass both the codec's "must differ" check and the semantic "same signer" check without the miner ever having produced two distinct microblocks.

### Finding Description
The claimed equality is:
`pkh1 = recover(mblock_header_1.signature, msg_hash_1)` and `pkh2 = recover(mblock_header_2.signature, msg_hash_2)`, asserted equal at [1](#0-0) .

This equality is supposed to prove "same signer, two distinct microblocks," but nothing in the code path enforces that the *content* being signed differs beyond raw struct inequality. The codec-level anti-duplication guard is purely structural: [2](#0-1) 

`h1 == h2` compares the entire `StacksMicroblockHeader`, including the `signature: MessageSignature` field. Since `(r, n-s)` with a flipped recovery id is a different 65-byte encoding for the *same* message hash and the *same* signer, `h1 != h2` trivially holds even though `version`, `sequence`, `prev_block`, `tx_merkle_root`, and `timestamp` are all identical to the original, single, honestly-produced microblock. The `sequence`/`prev_block` fork-identification check at line 2917 is satisfied automatically since the sequence numbers are literally the same value from the same underlying microblock.

Then `StacksChainState::check_microblock_header_signer` at [3](#0-2)  only checks `pkh1 != pkh2` — it recovers the same pubkey hash for both malleated signatures (they are valid signatures over the same message by the same key), so the check passes.

`handle_poison_microblock` then treats this as proof of equivocation and proceeds to slash the miner's key/reward at `pubkh`, per the doc comment describing its return value ("contains the block height of the block with the slashed microblock public key hash... the sequence number at which the fork occurred") at [4](#0-3) .

Root cause: the anti-duplicate-header guard checks *encoding equality* of the whole header (which includes an attacker-malleable field, the signature) instead of checking that the semantically meaningful, signed content differs (e.g., differing `tx_merkle_root` at the same `sequence`). No existing guard (`check_tenure_tx`, `verify_signer_signatures`, `validate_vrf_seed`, MARF hashing, maturation window) applies to this Clarity-level poison-microblock path — those guards are unrelated to `PoisonMicroblock` transaction validation.

Attacker's exact input: one legitimately broadcast `StacksMicroblockHeader` (public information, observable by any network participant) — no miner key is needed, only public-key ECDSA signature malleability, which is a purely mathematical transformation on the public `(r,s,v)` tuple.

### Impact Explanation
This does not cause a chain split or non-reproducible MARF state — both honest nodes deterministically recover the same pubkey hash from a malleated signature, so validation is consistent network-wide. The impact is a mis-payment: an honest, non-equivocating miner has their microblock-signing key wrongfully flagged as having double-signed, causing `handle_poison_microblock`'s downstream reward-forfeiture/reporter-payment logic to execute against a miner who committed no fork. This matches the rubric's High category: "a poison or reward mis-payment bounded to fees." It is repeatable against any observed microblock and requires no signer/miner privilege beyond broadcasting a single transaction containing the crafted `PoisonMicroblock` payload.

### Likelihood Explanation
Preconditions: attacker needs to observe exactly one broadcast, validly signed `StacksMicroblockHeader` (trivial — these are gossiped publicly), and be able to submit a standard Stacks transaction with a `TransactionPayload::PoisonMicroblock` payload (no special stake, no majority, no privileged role required — any unprivileged participant can submit transactions). Signature malleation (`s' = n - s`, `v' = v XOR 1`) is a cheap, deterministic elliptic-curve operation requiring no private key. This makes the attack low-cost and repeatable against every miner's every microblock, bounded only by the fee cost of submitting the poison transaction.

### Recommendation
Change the codec-level duplication guard in `TransactionPayload::consensus_deserialize` (and/or `check_microblock_header_signer`) to reject headers that are malleated re-signatures of the same content. Concretely: require that `h1` and `h2` differ in at least one of the *signed, non-malleable* fields (`tx_merkle_root`, or `version`/`timestamp` combined with `prev_block`) rather than differing merely in raw struct/signature bytes, and/or canonicalize signatures (reject high-S / non-canonical `(r,s)` at parse time, and additionally verify the two message hashes being signed are distinct) before accepting a `PoisonMicroblock` transaction as proof of equivocation.

#[test]
fn poison_microblock_malleated_signature_bypasses_equivocation_check() {
    // 1. Construct one legitimate StacksMicroblockHeader `h1` and sign it with a test private key.
    let privk = StacksPrivateKey::new();
    let mut h1 = StacksMicroblockHeader {
        version: 1,
        sequence: 0,
        prev_block: BlockHeaderHash([0u8; 32]),
        tx_merkle_root: Sha512Trunc256Sum([1u8; 32]),
        signature: MessageSignature::empty(),
    };
    h1.sign(&privk).unwrap();

    // 2. Derive h2 by malleating ONLY the signature: s' = n - s, v' = v ^ 1,
    //    leaving version/sequence/prev_block/tx_merkle_root/timestamp identical.
    let h2 = malleate_signature(&h1); // helper: parses h1.signature, negates s, flips recovery id

    // Equality-under-test BEFORE fix:
    assert_ne!(h1, h2); // passes the codec's "must differ" guard (bug: only signature bytes differ)
    assert_eq!(h1.sequence, h2.sequence); // "fork" guard trivially satisfied

    let pkh1 = h1.check_recover_pubkey().unwrap();
    let pkh2 = h2.check_recover_pubkey().unwrap();
    assert_eq!(pkh1, pkh2); // check_microblock_header_signer's guard is satisfied

    // 3. Feed (h1, h2) through TransactionPayload::consensus_deserialize / build a
    //    PoisonMicroblock tx and run it through StacksChainState::check_microblock_header_signer.
    let result = StacksChainState::check_microblock_header_signer(&h1, &h2);
    assert!(result.is_ok()); // BUG: accepted as proof of equivocation from a single microblock

    // Expected fix: this should return Err because h1 and h2 encode identical
    // signed content (same tx_merkle_root/prev_block/sequence), not a genuine fork.
}

                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
