### Title
Public getPaginatedNowWitnessList query cost is O(VotesStore + WitnessStore size) regardless of requested `limit`, enabling attacker-controlled amplification of full-node CPU work - (File: framework/src/main/java/org/tron/core/Wallet.java)

### Summary
`Wallet#getPaginatedNowWitnessList`, reachable unauthenticated via `GetPaginatedNowWitnessListServlet` (`/wallet/getpaginatednowwitnesslist`) and the gRPC `WalletSolidity.GetPaginatedNowWitnessList`, always loads the entire `WitnessStore`, fully iterates the entire `VotesStore` via `countVote`, and fully sorts all witnesses via `WitnessStore.sortWitnesses` before applying `skip(offset).limit(limit)`. The per-call cost is proportional to the number of witnesses and the number of outstanding vote records, not to the caller-supplied `limit`, so an attacker who cheaply grows `VotesStore` can make every subsequent public call to this endpoint perform full-store work.

### Finding Description
`Wallet#getPaginatedNowWitnessList(offset, limit)` (framework/src/main/java/org/tron/core/Wallet.java:770-822) does:
1. `chainBaseManager.getWitnessStore().getAllWitnesses()` — loads **all** witnesses.
2. `countVote(votesStore)` (Wallet.java:842-872) — iterates **every** entry of `VotesStore` and aggregates old/new vote deltas into a map, unconditionally, unaffected by `limit`.
3. Applies vote deltas to every witness in the full list.
4. `WitnessStore.sortWitnesses(witnessCapsuleList, ...)` (chainbase/src/main/java/org/tron/core/store/WitnessStore.java:58-63) — sorts the **entire** witness list (O(N log N), with a string-comparator path via `createReadableString` when `allowWitnessSortOptimization` is enabled).
5. Only after all of this does it `skip(offset).limit(limit)`.

`limit` is capped at `WITNESS_COUNT_LIMIT_MAX` but that cap only bounds the *output size*, not the *input work* — the witness list size and `VotesStore` size are unbounded by the caller.

`VotesStore` entries are created/updated by `VoteWitnessActuator.execute` → `countVoteAccount` for every `VoteWitnessContract` transaction, keyed per voter address (`createDbKey`). `VoteWitnessActuator.calcFee()` returns `0` (actuator/src/main/java/org/tron/core/actuator/VoteWitnessActuator.java:198-201), so casting a vote costs no chain fee beyond normal bandwidth/energy consumption; the only real constraint is that `validate()` requires `sum(voteCount) * TRX_PRECISION <= tronPower`, i.e., the voter needs freezable/staked TRX power ≥ 1 TRX to cast a valid nonzero vote (VoteWitnessActuator.java:129-143). An attacker can therefore create many funded accounts, each freezing a minimal amount of TRX, and issue one cheap `VoteWitnessContract` per account, each producing a distinct `VotesStore` entry that persists until the next maintenance epoch (when `MaintenanceManager.countVote` drains and deletes `VotesStore`, consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java:165-192).

Between maintenance windows, every call to `GetPaginatedNowWitnessListServlet` (framework/src/main/java/org/tron/core/services/http/GetPaginatedNowWitnessListServlet.java:21-51) — a public, unauthenticated HTTP endpoint — triggers this full O(N) scan+sort inside `Wallet#getPaginatedNowWitnessList`, even for `limit=1`. The only mitigating control is `RateLimiterServlet` (framework/src/main/java/org/tron/core/services/http/RateLimiterServlet.java), which throttles requests-per-second per endpoint/IP but does **not** reduce the per-request computational cost; it only bounds call frequency, so the aggregate CPU cost still scales with `(N inflated by attacker) × (calls permitted by rate limiter)`.

### Impact Explanation
This is a public-API cost/DoS-amplification issue on full nodes and solidity nodes (both `WalletSolidityApi.getPaginatedNowWitnessList` implementations delegate to the same `Wallet` method). An attacker who inflates `VotesStore`/`WitnessStore` size can force disproportionate CPU consumption (full map iteration + full list sort) on every subsequent low-`limit` request, degrading query-serving capacity for legitimate users of this and other node HTTP/RPC workers if thread pools are shared. It does not enable unauthorized execution, value theft, or consensus divergence — the impact is scoped to CPU-cost underpricing of a public read-only query, not fund loss.

### Likelihood Explanation
- Feasible with only unprivileged inputs: funded accounts + `VoteWitnessContract` broadcasts (no SR/admin privilege needed).
- Cost to attacker is bounded by needing minimal frozen TRX per account (to satisfy the `tronPower` check) plus normal account-creation/bandwidth costs — not free, but cheap relative to the resulting server-side amplification, since one vote transaction creates one persistent `VotesStore` record.
- The effect resets at each maintenance cycle (`MaintenanceManager.countVote` clears `VotesStore`), so the attacker must continuously replenish votes to sustain the effect, but this is a repeatable, automatable process within one epoch.
- HTTP rate limiting reduces the number of hits per second but does not neutralize per-request cost, so amplification (`N inflated size × repeated free calls`) is still real, just capped by the rate limiter's QPS ceiling.

### Recommendation
Bound the per-request work to be proportional to `offset + limit` rather than the full store sizes:
- Maintain a maintained/cached sorted witness ranking (already periodically computed at maintenance) and apply only the incremental, bounded vote deltas relevant to the requested page instead of scanning all of `VotesStore` for every call.
- Alternatively, cache the full "current epoch" vote-delta map with a short TTL (recomputed at most once per block or a time budget) so repeated identical queries within the same block do not each re-scan `VotesStore` and `WitnessStore`.
- Consider imposing a hard ceiling on `VotesStore` iteration cost per request, or precomputing/updating aggregated vote counts incrementally when each `VoteWitnessContract` is applied, rather than deferring all aggregation to query time.

```java
@Test
public void testGetPaginatedNowWitnessList_CostScalesWithVotesStoreSize() throws Exception {
  dbManager.getChainBaseManager().getDynamicPropertiesStore().saveStateFlag(0);

  // Baseline: small VotesStore
  long t0 = System.nanoTime();
  wallet.getPaginatedNowWitnessList(0, 1);
  long baseline = System.nanoTime() - t0;

  // Inflate VotesStore with N synthetic vote records (simulating N funded
  // accounts each broadcasting a cheap VoteWitnessContract)
  int n = 200_000;
  for (int i = 0; i < n; i++) {
    VotesCapsule vc = new VotesCapsule(
        ByteString.copyFromUtf8("voter_" + i), new ArrayList<>());
    vc.addNewVotes(ByteString.copyFromUtf8(WITNESS_ADDRESS), 1L);
    chainBaseManager.getVotesStore().put(vc.createDbKey(), vc);
  }

  long t1 = System.nanoTime();
  wallet.getPaginatedNowWitnessList(0, 1); // still limit=1
  long inflated = System.nanoTime() - t1;

  // Assert cost grows with N, not with limit (which is unchanged at 1)
  Assert.assertTrue("Per-call latency should scale with VotesStore size, "
      + "violating O(limit) expectation for a paginated public query",
      inflated > baseline * 50);

  // cleanup
  for (int i = 0; i < n; i++) {
    chainBaseManager.getVotesStore().delete(
        ByteString.copyFromUtf8("voter_" + i).toByteArray());
  }
}
```

```java
  public WitnessList getPaginatedNowWitnessList(long offset, long limit) throws
      MaintenanceUnavailableException {
    if (limit <= 0 || offset < 0) {
      return null;
    }
    if (limit > WITNESS_COUNT_LIMIT_MAX) {
      limit = WITNESS_COUNT_LIMIT_MAX;
    }

    /*
      In the maintenance period, the VoteStores will be cleared.
      To avoid the race condition of VoteStores deleted but Witness vote counts not updated,
      return retry error.
      Only apply to requests that rely on the latest block,
      which means the normal fullnode requests with HEAD cursor.
    */
    boolean isMaintenance = chainBaseManager.getDynamicPropertiesStore().getStateFlag() == 1;
    if (isMaintenance && !Args.getInstance().isSolidityNode() && getCursor() == Cursor.HEAD) {
      String message =
          "Service temporarily unavailable during maintenance period. Please try again later.";
      throw new MaintenanceUnavailableException(message);
    }
    // It contains the final vote count at the end of the last epoch.
    List<WitnessCapsule> witnessCapsuleList = chainBaseManager.getWitnessStore().getAllWitnesses();
    if (offset >= witnessCapsuleList.size()) {
      return null;
    }

    VotesStore votesStore = chainBaseManager.getVotesStore();
    // Count the vote changes for each witness in the current epoch, it is maybe negative.
    Map<ByteString, Long> countWitness = countVote(votesStore);

    // Iterate through the witness list to apply vote changes and calculate the real-time vote count
    witnessCapsuleList.forEach(witnessCapsule -> {
      long voteCount = countWitness.getOrDefault(witnessCapsule.getAddress(), 0L);
      witnessCapsule.setVoteCount(witnessCapsule.getVoteCount() + voteCount);
    });

    // Use the same sorting logic as in the Maintenance period
    WitnessStore.sortWitnesses(witnessCapsuleList,
        chainBaseManager.getDynamicPropertiesStore().allowWitnessSortOptimization());

    List<WitnessCapsule> sortedWitnessList = witnessCapsuleList.stream()
        .skip(offset)
        .limit(limit)
        .collect(Collectors.toList());

    WitnessList.Builder builder = WitnessList.newBuilder();
    sortedWitnessList.forEach(witnessCapsule ->
        builder.addWitnesses(witnessCapsule.getInstance()));

    return builder.build();
  }
```

```java
  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }
```

```java
  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
```
