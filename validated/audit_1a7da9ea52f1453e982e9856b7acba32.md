### Title
Missing declared-class precondition check in `execute_replace_class` allows the Starknet OS to commit a `ReplaceClass` state change for an undeclared class hash - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `ReplaceClass` syscall lets a contract change its own `class_hash`. In the Rust `blockifier` implementation (used for actual block execution), this operation explicitly checks that the target `class_hash` is declared before allowing the change: `syscall_handler.state.get_compiled_class(request.class_hash)?` is called and must succeed before `set_class_hash_at` is applied. [1](#0-0) 

The Starknet OS Cairo re-implementation of the same syscall, `execute_replace_class`, does not perform this check. It simply reads the (hinted) `state_entry`, unconditionally overwrites `class_hash` with the value supplied in the syscall request, and records the change — with an explicit TODO acknowledging the missing check. [2](#0-1) 

The same gap exists in the deprecated (Cairo0) syscall path as well. [3](#0-2) 

### Finding Description
This mirrors the report's bug class: a state-mutating operation (`rebalance()`/here, `replace_class`) is executed without validating a precondition that a companion function (`initManagement()`/here, class declaration) is supposed to establish first.

In the blockifier's native execution path, `replace_class` is gated on `get_compiled_class(class_hash)` succeeding, i.e. the class must have actually been declared (its compiled class must exist in state). This is the authoritative execution used to build/validate blocks.

The Starknet OS re-executes the same transaction traces (via hints) to produce a STARK-provable trace of the block, and is expected to be functionally equivalent to blockifier for state transitions. However, `execute_replace_class` in `syscall_impls.cairo` (and its deprecated counterpart) skips the "is declared" check entirely — it directly trusts the hint-supplied `state_entry` and writes the caller-supplied `class_hash` into `contract_state_changes` with no assertion that this class hash was ever declared/exists in `contract_class_changes`. The comment `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` confirms this is a known, currently-unenforced precondition.

Because the OS's final state commitment (Patricia tree over `contract_state_changes`) directly encodes whatever `class_hash` ends up in the `StateEntry`, and because the class-hash committment leaf mechanics in `commitment.cairo` do not appear to cross-validate that every referenced `class_hash` corresponds to an actually-declared class in `contract_class_changes`, this allows the OS commitment to accept and prove an arbitrary/undeclared `class_hash` value for a contract, so long as the hint program supplies a consistent `state_entry`.

### Impact Explanation
This is a potential root-cause for state-root/commitment divergence between the “ground truth” blockifier execution (which rejects `replace_class` to an undeclared class) and the Starknet OS's provable re-execution (which does not reject it). If the hint layer that feeds `GetContractAddressStateEntry` in the OS is not perfectly constrained to only reflect states blockifier actually produced, this missing check is a latent soundness gap in the OS's state-transition function: the OS's Cairo program alone does not enforce that only correctly-declared classes can be committed via `replace_class`, meaning the OS could, in principle, be tricked (e.g., via a malformed/attacker-influenced hint or a divergent execution path) into committing a wrong class hash into the state root — i.e., a wrong committed root / block hash, which is one of the explicitly accepted severities for this analysis.

### Likelihood Explanation
Likelihood is Medium: this requires a discrepancy between the untrusted hint-supplied intermediate state and what the OS itself independently verifies. Since the OS relies heavily on hints for state reads (`%{ GetContractAddressStateEntry %}`) and does not itself independently assert the class-declaration precondition (unlike blockifier), any bug or divergence upstream (in the hint-generation/execution-helper layer) that supplies an inconsistent `state_entry`/`class_hash` pairing for a `replace_class` request would not be caught by the OS itself — since blockifier already enforces this in the reference execution, exploiting this in a production flow would require finding a path where blockifier's execution and the OS's hint-derived data diverge, but the OS having zero enforcement of this critical invariant is a real, cited soundness gap (explicitly TODO'd by the developers) rather than a defense-in-depth nice-to-have.

### Recommendation
Add an explicit assertion in `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that the target `class_hash` is present in `contract_class_changes` (i.e., has been declared) before allowing the state-entry update, matching the check already performed by `blockifier`'s `replace_class` implementation. This closes the parity gap between the OS's provable execution and the reference execution, and removes reliance on hint-supplied data for this security-critical invariant.

### Proof of Concept
1. In `blockifier`, calling the `ReplaceClass` syscall with an undeclared class hash is explicitly checked and rejected: see `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29` (`undeclared_class_hash` test expects `"is not declared"`). [4](#0-3) 
2. In the OS Cairo implementation, `execute_replace_class` performs no equivalent check — it directly writes `class_hash` into `contract_state_changes` from the syscall request, with a TODO acknowledging the missing validation: [5](#0-4) 
3. This asymmetry means the OS's Cairo program, taken in isolation, does not itself enforce that replaced class hashes are declared — a soundness gap relative to the reference blockifier semantics that the OS is meant to faithfully re-execute and prove.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
