### Title
Missing/zeroed swap deadline plus fixed 5% slippage on protocol-initiated PRC20→WPC swaps enables sandwich extraction from inbound gas deposits and outbound gas refunds - (File: `x/uexecutor/keeper/evm.go`)

### Summary
`x/uexecutor` performs Uniswap-V3-style swaps on behalf of users whenever a `GAS`/`GAS_AND_PAYLOAD` inbound is executed (`CallPRC20DepositAutoSwap`) or whenever unused destination-chain gas is refunded (`CallUniversalCoreRefundUnusedGas`/`refundUnusedGas`). The deadline argument passed to `depositPRC20WithAutoSwap` is hardcoded to `0` [5](#0-4) , and `refundUnusedGas` exposes no deadline parameter whatsoever [6](#0-5) . Both paths protect solely with a fixed `minPCOut = quote * 95 / 100` slippage band derived from a `QuoterV2.quoteExactInputSingle` read [7](#0-6) .

### Finding Description
This is the direct Push Chain analog of the Derby `Swap.swapTokensMulti` finding: swap-based value conversions execute with no meaningful expiration protection, relying only on a generic percentage-based slippage tolerance rather than a value tied to actual, current market conditions at execution time. On Push Chain the swap legs are:

- `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` call `GetSwapQuote` then immediately `CallPRC20DepositAutoSwap`, passing `deadline = 0` to the on-chain `depositPRC20WithAutoSwap` function of the `UNIVERSAL_CORE` system contract [8](#0-7) .
- `applyGasRefund`/`getSwapQuoteForRefund` compute a quote and call `refundUnusedGas`, which has no deadline field in its ABI at all [4](#0-3) [6](#0-5) .

Both swap legs are unprivileged-attacker-reachable: any external party can trigger a `GAS`/`GAS_AND_PAYLOAD` inbound (any deposit on a supported source chain) or cause a gas refund (any outbound with `gas_fee_used < gas_fee`) as part of ordinary, honest-validator vote finalization — no privileged action is required. The only economic guardrail is the flat 5% slippage tolerance computed from `defaultFeeTier` + `quoteExactInputSingle` at execution time [9](#0-8) . Because the quote-then-swap sequence executes against the live on-chain Uniswap V3 pool for WPC/PRC20 pairs, an external actor observing the pending `MsgVoteInbound`/`MsgVoteOutbound` that will finalize the ballot (and thus trigger the swap) in the Push Chain mempool can push the pool price against the swap direction just before it lands, letting the swap consume the full 5% band, then reverse the price move immediately after — a textbook sandwich attack. Since neither swap path enforces an actual time-bounded deadline, an attacker also has no upper bound forcing the swap to revert if conditions deteriorate further; the swap will execute at whatever price exists at inclusion time, capturing up to the entire slippage allowance as attacker profit on every gas-top-up deposit and every gas refund.

### Impact Explanation
The extractable value is bounded by 5% of the swapped amount, but it recurs on every `GAS`/`GAS_AND_PAYLOAD` inbound (i.e., every user gas top-up) and on every outbound gas refund, systematically degrading the PC amount credited to depositors/UEAs and the refund amount returned to senders — a direct, repeatable value leak from protocol/gas-fee accounting paths (`CallPRC20DepositAutoSwap`, `CallUniversalCoreRefundUnusedGas`) that are explicitly in scope under "corruption of ... gas fee accounting, refund accounting."

### Likelihood Explanation
High: no privileged access is required — the trigger is any ordinary cross-chain deposit or any outbound whose relayer underspends the pre-paid gas fee, both of which are attacker-controllable inputs on the "honest validator" happy path. The only requirement is MEV capability against the Push Chain WPC/PRC20 Uniswap V3 pool, which is an ordinary external-actor capability, not a validator/relayer/TSS compromise.

### Recommendation
Thread a real, bounded deadline (e.g., current block time + a short window such as 1–2 minutes given Push Chain's block time) into `depositPRC20WithAutoSwap` instead of `big.NewInt(0)`, and add a deadline parameter to `refundUnusedGas`'s swap leg on the `UniversalCore` contract. Additionally, consider tightening the slippage tolerance below a flat 5%, or making it configurable per token/chain-meta so it can be reduced as liquidity conditions warrant, consistent with the original report's recommendation to let governance adjust the value over time.

### Proof of Concept
1. Attacker monitors the Push Chain mempool/UV vote stream for a `MsgVoteInbound` (or `MsgVoteOutbound`) that will reach quorum and trigger `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` (or `applyGasRefund`).
2. Immediately before that transaction lands, attacker submits a swap on the same WPC/PRC20 Uniswap V3 pool used by `CallPRC20DepositAutoSwap`/`refundUnusedGas`, moving the pool price so the pending `quoteExactInputSingle`-derived `minPCOut` (95% of a now-manipulated quote) is easy to satisfy while still being worse than the pre-manipulation market price.
3. The quorum-triggering vote executes `depositPRC20WithAutoSwap`/`refundUnusedGas` with `deadline = 0` (no expiration enforcement) and the manipulated `minPCOut`, executing the swap at the attacker-favorable price.
4. Attacker immediately reverses their initial swap, capturing the difference (up to ~5% of the swapped notional) as profit, funded by the depositor/refund recipient receiving less PC than the true market rate would have provided.

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
