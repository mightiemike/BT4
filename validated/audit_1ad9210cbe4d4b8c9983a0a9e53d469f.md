### Title
Webhook HMAC does not bind the `X-Shopify-Shop-Domain`/topic identifier, enabling cross-tenant webhook spoofing - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
The webhook validation path computes and checks the `X-Shopify-Hmac-Sha256` signature over the raw request body only, and separately, independently reads `X-Shopify-Shop-Domain`, `X-Shopify-Topic`, and `X-Shopify-Webhook-Id` from unauthenticated headers. None of these identifying values are included in the signed data, so the library cannot detect if they've been tampered with, even though `domain` is subsequently trusted to load and act on a specific shop's offline session.

### Finding Description
`validateHmacFromRequestFactory` in [1](#0-0)  validates the webhook HMAC using only `rawBody` as the signed payload: it fetches the HMAC header and compares it against `createSHA256HMAC(config.apiSecretKey, rawBody, ...)` — the shop domain, topic, and webhook ID headers play no part in this computation.

`validateFactory` in [2](#0-1)  calls this HMAC check and then, separately, calls `checkWebhookHeaders`/`checkWebhooksHeaders` ( [3](#0-2) ), which only verifies these headers are *present*, not that they are cryptographically tied to the signed body.

The `domain` value extracted this way is then used directly to load the shop's offline access-token session and construct an authenticated Admin API client, e.g. in [4](#0-3)  (`ensureValidOfflineSession(params, check.domain)` → `adminClientFactory({params, session, ...})`), and the identical pattern exists in `shopify-app-react-router`.

Because Shopify's app client secret (`apiSecretKey`) is shared across *all* shops that install a given public app (it is not per-shop), any merchant who installs the app can trigger a genuine webhook for their own store and thereby legitimately obtain a `(rawBody, hmac)` pair that is valid under the app's single shared secret. Since `domain`/`topic`/`webhookId` are not part of the signed content, that same attacker can replay the captured body+HMAC to the app's webhook endpoint while substituting the `X-Shopify-Shop-Domain` header for a victim shop the attacker does not control. The HMAC check still passes (it only checks the body), the header-presence check still passes, and the webhook handler is invoked with `shop = victim-shop`, loading the victim's offline session/access token to process the (attacker-controlled) payload.

This mirrors the reported bug class exactly: a value that should be included in the "identifier" used to validate the message (here, the shop domain and topic, analogous to `startSqrtPriceX96` in the battle key) is left out of the cryptographic binding, letting an unprivileged actor substitute their own arbitrary value post-verification.

### Impact Explanation
An attacker who is merely a normal merchant that installs the target public app can forge webhook deliveries "as" any other shop that also has the app installed (shop names are typically discoverable/guessable, e.g. `*.myshopify.com`), causing the app's webhook handler to execute app logic using the **victim's** offline session/access token and (forged) attacker-chosen `topic`/payload. Depending on what webhook handlers do (e.g. `APP_UNINSTALLED` cleanup, order/fulfillment processing, GDPR handlers, billing-related topics), this can lead to unauthorized state changes performed against the victim's store data, denial of service (e.g., spoofing `APP_UNINSTALLED` to wipe the victim's stored session), or corruption of victim data — a cross-tenant confused-deputy condition triggered from a single, unprivileged app installer.

### Likelihood Explanation
Exploitation requires only that the attacker install the target app on any shop they control (a normal, unprivileged action for a public app) and be able to send a crafted HTTP POST with forged headers to the app's known webhook URL — no secret material, MITM, or privileged Shopify access is required. This is straightforward to automate.

### Proof of Concept
1. Attacker installs the target public app on `attacker-shop.myshopify.com`.
2. Attacker performs any store action that triggers a webhook for a topic they wish to abuse (e.g. update a product), and captures the resulting `rawBody` and its valid `X-Shopify-Hmac-Sha256` value from their own webhook delivery logs/ngrok capture.
3. Attacker replays that exact `rawBody` + `X-Shopify-Hmac-Sha256` to the app's webhook endpoint, but sets `X-Shopify-Shop-Domain: victim-shop.myshopify.com` (and, if desired, a different `X-Shopify-Topic`, since that header is also unauthenticated).
4. `validateFactory` ( [5](#0-4) ) validates the HMAC successfully (it only checks the body against the shared secret) and header presence succeeds.
5. `authenticateWebhookFactory` proceeds to `ensureValidOfflineSession(params, check.domain)` with `check.domain = 'victim-shop.myshopify.com'` ( [6](#0-5) ), loading the victim's real offline session and invoking the app's webhook handler as though the event legitimately originated from the victim shop.

Note: I was not able to fully verify within the index whether any webhook-processing layer (e.g. `shopify-app-express`'s `process.ts`) additionally cross-checks `domain` against the topic/subscription registration in a way that would block this; the `shopify-app-remix`/`shopify-app-react-router` authenticate paths shown above do not perform such a check before using `domain` to load the session.

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };
}

export function validateFactory(config: ConfigInterface) {
  return async function validate({
    rawBody,
    ...adapterArgs
  }: WebhookValidateParams): Promise<WebhookValidation> {
    const request: NormalizedRequest =
      await abstractConvertRequest(adapterArgs);

    const webhookType = detectWebhookType(request.headers);

    const validHmacResult = await validateHmacFromRequestFactory(config)({
      type: HmacValidationType.Webhook,
      rawBody,
      webhookType,
      ...adapterArgs,
    });

    if (!validHmacResult.valid) {
      if (validHmacResult.reason === ValidationErrorReason.InvalidHmac) {
        const log = logger(config);
        await log.debug(
          "Webhook HMAC validation failed. Please note that events manually triggered from a store's Notifications settings will fail this validation. To test this, please use the CLI or trigger the actual event in a development store.",
        );
      }
      return validHmacResult;
    }

    return checkWebhookHeaders(request.headers, webhookType);
  };
}

function checkWebhooksHeaders(
  headers: Headers,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };

  const name = getHeader(headers, headerNames.name);
  if (name) fields.name = name;

  const triggeredAt = getHeader(headers, headerNames.triggeredAt);
  if (triggeredAt) fields.triggeredAt = triggeredAt;

  const eventId = getHeader(headers, headerNames.eventId);
  if (eventId) fields.eventId = eventId;

  return {valid: true, ...fields};
}
