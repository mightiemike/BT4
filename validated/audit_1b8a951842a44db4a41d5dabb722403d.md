I found a concrete "pause pass-through instead of reverting" analog in the vault `accrue` functions, which is precisely one of the allowed mechanism classes in the rules.

### Title
`accrue` silently passes through stale indexes when paused instead of reverting, allowing operations to bypass interest-based collateral/debt updates - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Every vault's `accrue` function (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`) checks the `accrue` pause flag and, when paused, returns the **stale cached** `index`/`lindex` wrapped in `(ok ...)` instead of reverting with `ERR-PAUSED`. Every downstream caller (`market.clar`/`v0-4-market.clar` via `accrue-and-cache`, and vault-internal `system-borrow`/`system-repay`/`deposit`/`redeem`) treats this `ok` response as a legitimate, fresh index and proceeds to mutate debt/collateral state and cache the stale value for the rest of the block.

### Finding Description
The `accrue` function in each vault is structured as:
```
(if (get accrue states)
    ;; PAUSED: Pass-through without reverting
    (ok { index: idx, lindex: lidx })
    ;; NOT PAUSED: normal accrual...)
``` [1](#0-0) 

This is a pause that passes through instead of reverting: rather than blocking the caller, the paused branch returns a successful `(ok ...)` result carrying the old, un-updated `index`/`lindex`, `total-borrowed`, and `principal-scaled`. Because `accrue` returns `ok` unconditionally regardless of pause state, `try!`-based callers never see an error.

The market contract's `accrue-and-cache` calls `vault-accrue` and unconditionally caches whatever it returns, keyed only by `stacks-block-time`:
```
(let ((indexes (try! (vault-accrue aid))))
  (map-set index-cache cache-key indexes)
  (ok indexes))
``` [2](#0-1) 

Because the "PAUSED" branch of `accrue` never fails, `market.clar`'s borrow/repay/liquidation flows continue operating on this vault's debt/collateral notional values using the stale index as if it were current, and the vault's own `system-borrow`/`system-repay`/`deposit`/`redeem` functions (which all call `(try! (accrue))` first) proceed with debt caps, available-liquidity checks, and share conversions computed against outdated indexes, e.g.: [3](#0-2) 

The guard that is supposed to stop the vault (`accrue` pause) is bound to a value (`{index, lindex}`) that is not invalidated to an error — it is silently substituted with the last cached values — and the later use (borrow/repay/deposit/redeem/liquidation math across the whole market) treats it as valid, current data.

### Impact Explanation
This lands on **temporary freezing/mispricing of funds**: while `accrue` is paused for a given vault, interest that should accrue to depositors is silently dropped and the market and vault continue to allow borrows, repayments, deposits, and redemptions priced off a frozen index, distorting scaled-debt/collateral valuations, health checks, and reserve fee (treasury) accrual for as long as the pause is active. This does not require any other user's interference — it's a direct code-path consequence of a paused accrual being treated as a successful, fresh accrual.

### Likelihood Explanation
Likelihood depends on the DAO actually invoking the `accrue` pause (set via `pause-states`), which is an administrative action; once paused, the flawed pass-through activates automatically on every subsequent vault operation without requiring precise timing or capital from an attacker — any user calling borrow/repay/deposit/redeem during the pause window triggers it.

### Recommendation
When `(get accrue states)` is true, `accrue` should return an error (e.g., `ERR-PAUSED`) instead of `(ok {index: idx, lindex: lidx})`, and all callers (`market.clar`/`v0-4-market.clar`'s `accrue-and-cache`, and each vault's `system-borrow`/`system-repay`/`deposit`/`redeem`) should propagate that failure via `try!` rather than silently continuing with stale indexes.

### Proof of Concept
1. DAO calls `set-pause-states` (or equivalent) to pause `accrue` on `v0-vault-usdc.clar`.
2. A user calls `market.borrow` for USDC; `accrue-and-cache` calls `vault-accrue` which returns `(ok {index: idx, lindex: lidx})` with the last cached (stale) values [2](#0-1) .
3. `market.clar`'s `borrow` function proceeds to compute debt/collateral notional values and calls `vault-system-borrow`, which internally also calls `(try! (accrue))` and receives the same stale-but-`ok` result, then checks `CAP-DEBT`/`available-assets` against outdated totals [4](#0-3) .
4. The borrow succeeds and is recorded using the frozen index, even though the vault operator explicitly intended to halt interest accrual — no revert occurs anywhere in the call chain.

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
