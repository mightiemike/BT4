## Analysis

The external report concerns `gulp`-style functions that fetch a live swap quote and pass a slippage-derived `minAmountOut` to an on-chain trade in the same call, which is vulnerable to sandwich manipulation of the AMM pool used for pricing. Push Chain's `x/uexecutor` module implements the structurally identical pattern for gas-abstraction auto-swaps.

### Title
Sandwichable spot-price quoting in `GetSwapQuote`/`CallPRC20DepositAutoSwap` lets an unprivileged attacker steal value from gas-abstraction inbound deposits and gas refunds - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Every code path that auto-swaps a bridged gas/PRC20 asset into WPC (native gas-abstraction deposits, `GAS_AND_PAYLOAD` deposits, and excess-gas refunds on outbound finalization) derives its slippage bound directly from a spot-price call to Uniswap V3's `QuoterV2.quoteExactInputSingle`, taken immediately before the real swap executes, with no TWAP/oracle anchor. This reproduces the exact bug class from the external report: the slippage protection is computed from the same manipulable liquidity state that the trade itself consumes, so it constrains nothing against sandwich attacks.

### Finding Description
`GetSwapQuote` calls the QuoterV2 contract with `commit=false` to obtain a live, current-block quote for `prc20 → wpc`: [1](#0-0) 

That quote is then converted into `minPCOut = quote * 95 / 100` and passed straight into the same-transaction swap call:
- Inbound `GAS` deposits: [2](#0-1) 
- Inbound `GAS_AND_PAYLOAD` deposits: [3](#0-2) 
- Outbound excess-gas refunds (`applyGasRefund`): [4](#0-3) 

In all three call sites, the quote-fetch and the swap-execute happen back-to-back inside a single keeper invocation triggered synchronously during processing of `MsgVoteInbound` / `MsgVoteOutbound`. There is no moving-average or oracle-anchored price check anywhere in the module — a repo-wide search for TWAP/moving-average logic in swap pricing returns no results. The 5% band is measured against the manipulable spot price of the pool at execution time, not against any external reference.

Because `MsgVoteInbound`/`MsgVoteOutbound` transactions from Universal Validators are broadcast to and visible in the public mempool before block inclusion, an unprivileged actor can observe an impending gas-abstraction swap and, within the same block (via higher gas price/priority ordering) or across adjacent blocks, trade against the WPC/PRC20 Uniswap V3 pool deployed on Push Chain's embedded EVM to move the spot price. Since `minPCOut` is recomputed from that same manipulated state, the check "passes" against an already-bad price, and the depositor's auto-swap executes at the attacker-favorable rate. The attacker then reverses the position, capturing the value lost by the depositor/protocol.

### Impact Explanation
This directly causes loss of user-controlled funds: depositors using gas-abstraction (`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`) and the protocol's own gas-refund flow (`applyGasRefund`) receive a manipulated, worse-than-fair amount of native PC/WPC for their bridged assets, with the difference extracted by the sandwiching attacker. This falls under "corruption of PRC20 or native asset accounting" and "unauthorized... permanent loss... of user or protocol-controlled funds" per the allowed-impact gate, and is reachable purely through ordinary user deposit/gas-refund flows without any validator, relayer, or TSS compromise.

### Likelihood Explanation
Any user submitting a normal cross-chain gas deposit or triggering a gas refund exposes themselves to this attack; the trigger (a pending `MsgVoteInbound`/`MsgVoteOutbound`) is publicly observable in mempool before execution, and the AMM pool being manipulated (WPC/PRC20 on Push Chain's own embedded EVM) is directly reachable by any account able to submit ordinary EVM transactions. No privileged access, validator collusion, or external-chain compromise is required — only mempool visibility and capital to move the pool, matching the "unprivileged external attacker" threat model.

### Recommendation
Anchor `minPCOut` to a manipulation-resistant reference price rather than a single spot quote taken in the same transaction as the trade — e.g., use a Uniswap V3 TWAP (`observe`) over a meaningful window, or an independent price oracle, and bound the accepted spot price to a tolerance around that reference (as the external report's alternative recommendation suggests), accepting that stale/lagging prices are the tradeoff. Alternatively, restrict `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` fee/slippage parameters so they cannot be fully determined by a quote fetched atomically with the trade.

### Proof of Concept
1. Attacker monitors the Push Chain mempool for a `MsgVoteInbound` that will finalize a `GAS` or `GAS_AND_PAYLOAD` inbound (visible once a quorum-completing vote is broadcast).
2. Attacker submits a large swap against the WPC/PRC20 Uniswap V3 pool (deployed on Push Chain's embedded EVM) with a higher gas price to land before the victim's finalizing vote is processed, pushing the pool's spot price unfavorably for `prc20 → wpc`.
3. `ExecuteInboundGas` (or `gasAndPayloadDepositAutoSwap`) calls `k.GetSwapQuote` at `x/uexecutor/keeper/evm.go:502-538`, which returns the now-manipulated spot quote; `minPCOut` is computed as 95% of this bad quote at `x/uexecutor/keeper/execute_inbound_gas.go:142-146`.
4. `CallPRC20DepositAutoSwap` executes the real swap against the still-manipulated pool, succeeding because `minPCOut` was derived from the same distorted price.
5. Attacker reverses their initial trade in a following transaction, extracting the value lost by the victim's auto-swap (or by the protocol's gas-refund swap in `outbound.go`'s `applyGasRefund`).

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
