### Title
Disabled-API gate in `isDisabled` can be bypassed for any operator-disabled endpoint via extra non-cancelling path segments before the final `..` collapse - ([File: framework/src/main/java/org/tron/core/services/filter/HttpApiAccessFilter.java])

### Summary
`isDisabled` normalizes the request path with `URI.create(endpoint).normalize()` but then extracts the API name using a fixed split index (`endpoint.split("/")[2]`) instead of the last path segment. Whenever the normalized path retains more than one segment ahead of the API name (i.e., the `..` segments don't fully cancel every extra directory), index `[2]` resolves to an unrelated segment (e.g., `"a"`) instead of the real API name, so `disabledApiList.contains(...)` never matches and the disabled endpoint is treated as enabled. This is already proven for one hand-picked case in `HttpApiAccessFilterTest#testIsDisabled` and generalizes to an entire class of inputs.

### Finding Description

The bug is structural: `URI.normalize()` correctly collapses `x/..` pairs pairwise from left to right, but it does **not** guarantee the resulting path has exactly 3 segments (`""`, `"wallet"`, `apiName`). Whenever the number of literal segments minus the number of cancelling `..` before the final API name is `>= 2`, the normalized path looks like `/wallet/seg1/seg2/.../apiName`, and `split("/")[2]` returns `seg1`, not `apiName`. The existing unit test already demonstrates exactly this:
- `/wallet/a/../b/../getnowblock` → normalizes to `/wallet/getnowblock` (both `a` and `b` are fully cancelled) → `split[2] == "getnowblock"` → correctly disabled.
- `/wallet/a/b/../getnowblock` → normalizes to `/wallet/a/getnowblock` (only `b` is cancelled, `a` remains) → `split[2] == "a"` → check incorrectly reports **not disabled**. [3](#0-2) 

This is not specific to `getnowblock`; the same flaw applies to **any** entry in `disabledApiList`, including sensitive execution/settlement endpoints (e.g. `triggerconstantcontract`, `triggersmartcontract`, `estimateenergy`, `freezebalancev2`, `delegateresource`) registered under `/wallet/*` in `FullNodeHttpApiService` and `/walletsolidity/*` in `SolidityNodeHttpApiService`. The filter is the sole gate for the "disabled via config" feature — no other check re-validates the API name — so any input path `P` where `URI.create(P).normalize()` ends in `/wallet/X` but has `>=2` un-cancelled leading segments will cause `isDisabled` to return `false` for a disabled `X`.

### Impact Explanation
An operator who disables a specific JSON-RPC/HTTP wallet API via `disabledApiList` (a documented security control to shut off sensitive endpoints such as contract-triggering or resource/balance operations) can have that control silently defeated by any caller who appends one extra non-cancelling path segment before the trailing API name. This converts an intended "unavailable due to config" 404 into full access to the underlying servlet logic, undermining the only enforcement point for this feature.

### Likelihood Explanation
The flaw is deterministic and requires no privileges — it is purely a matter of crafting the request path (e.g., `GET /wallet/a/getnowblock/../getnowblock`-style or `/wallet/a/b/../getnowblock`), reachable by any unauthenticated HTTP client hitting the node's public API port. It is 100% reproducible and already partially confirmed by the repo's own unit test.

### Recommendation
Fix `isDisabled` to use the last normalized path segment instead of a fixed split index, e.g. derive the API name via `Paths.get(normalizedEndpoint).getFileName()` or split-then-take-last (`parts[parts.length - 1]`), so the disabled-check semantics match `URI.normalize()` semantics regardless of how many segments preceded the API name.

### Proof of Concept
Generalize `HttpApiAccessFilterTest#testIsDisabled` into a property-based test:

```java
@Test
public void testIsDisabledGeneralizedBypass() throws Exception {
  List<String> list = new ArrayList<>();
  list.add("getnowblock");
  CommonParameter.getInstance().setDisabledApiList(list);
  Method privateMethod = httpApiAccessFilter.getClass()
      .getDeclaredMethod("isDisabled", String.class);
  privateMethod.setAccessible(true);

  Random rnd = new Random(42);
  for (int trial = 0; trial < 1000; trial++) {
    int segCount = 1 + rnd.nextInt(5);   // extra literal segments
    int cancelCount = rnd.nextInt(segCount + 1); // ".." pairs appended

    StringBuilder sb = new StringBuilder("/wallet");
    for (int i = 0; i < segCount; i++) {
      sb.append("/s").append(i);
    }
    for (int i = 0; i < cancelCount; i++) {
      sb.append("/..");
    }
    sb.append("/getnowblock");

    String path = sb.toString();
    String expectedNormalized = URI.create(path).normalize().toString();
    boolean expectedDisabled = expectedNormalized.endsWith("/wallet/getnowblock");

    boolean actual = (boolean) privateMethod.invoke(httpApiAccessFilter, path);

    // Property: isDisabled must match true normalization semantics.
    Assert.assertEquals("path=" + path + " normalized=" + expectedNormalized,
        expectedDisabled, actual);
  }
}
```

Running this against the current implementation fails whenever `segCount - cancelCount >= 2` (i.e., at least two un-cancelled leading segments remain), confirming the bypass generalizes beyond the two hand-picked cases in the existing test and applies to any configured disabled API name.

  private boolean isDisabled(String endpoint) {
    boolean disabled = false;

    try {
      endpoint = URI.create(endpoint).normalize().toString();
      List<String> disabledApiList = CommonParameter.getInstance().getDisabledApiList();
      if (!disabledApiList.isEmpty()) {
        disabled = disabledApiList.contains(endpoint.split("/")[2].toLowerCase(Locale.ROOT));
      }
    } catch (Exception e) {
      logger.warn("check isDisabled except, endpoint={}, {}", endpoint, e.getMessage());
    }

    return disabled;
  }
