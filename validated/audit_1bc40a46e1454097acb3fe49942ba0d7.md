### Title
Unauthenticated `signer_signature` vector allows a single garbage `MessageSignature` to abort validation of an otherwise threshold-clearing block - (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` recovers a public key for every entry in `signer_signature` and propagates the very first unrecoverable-signature error via `?`, instead of skipping the bad entry and continuing to tally weight from the remaining valid signatures. Because the `signer_signature` list is not covered by the block's own signing hash (`signer_signature_hash`), an unprivileged relayer can append one malformed entry to an otherwise fully, validly signed block before rebroadcasting it, causing any node that receives the tampered copy to reject a block that would otherwise clear the signer weight threshold.

### Finding Description
The claimed broken equality is: `verdict(N valid sigs + 1 garbage sig) == verdict(N valid sigs alone)` whenever `N` alone satisfies `total_weight_signed >= threshold`. `verify_signer_signatures` walks `self.signer_signature.iter()` and calls `Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(message.bits(), signature)`, mapping any recovery failure straight to `Err(ChainstateError::InvalidStacksBlock(...))` and returning immediately, rather than logging/skipping the one bad entry and continuing to accumulate weight from subsequent, otherwise-valid signatures.

Because the `signer_signature` field is data appended *after* the block header/content is finalized and is not itself part of the message (`signer_signature_hash`) that each signer signs over, it is not authenticated by any consensus-critical hash. A network participant who is neither a signer nor the block's miner — merely a P2P relay/gossip participant, which is within the allowed unprivileged attacker capabilities — can take a legitimately, fully-signed `NakamotoBlock` observed on the wire and splice in one syntactically-malformed `MessageSignature` (e.g., non-recoverable bytes) at the front of the vector, then rebroadcast this mutated block. Any downstream node that processes this tampered copy before (or instead of) the pristine copy will hit the first bad entry and reject the entire block via `InvalidStacksBlock`, even though the remaining N genuine signatures alone would have cleared `total_weight_signed >= threshold`.

No existing guard restores the equality: `verify_signer_signatures` has no fallback to continue past a single malformed signature, there is no consensus-level hash covering the exact contents of `signer_signature` that would let a node detect/reject the tampered variant as a different, invalid object versus simply discard the bad element, and no other function (`check_tenure_tx`, `validate_*_static`, `common_validate_against_burnchain`) intercepts this specific mutation before signature verification runs.

### Impact Explanation
Nodes that receive the tampered block (with garbage signature prepended) diverge from nodes that receive the pristine, fully-signed block from the honest miner/relay path — the former reject it outright, the latter accept it. This is a network-visible, minority-triggerable static-validation divergence causing temporary tip disagreement among honest nodes, matching the High severity category. Impact is bounded/repeatable: the honest miner or any other relay can resend the untampered block, and the attacker gains only transient disruption/delay, not funds or permanent state divergence.

### Likelihood Explanation
The attack requires no signer key, no miner slot, and no elevated stake — only the ability to observe a legitimately signed Nakamoto block in flight over P2P (a normal relay capability available to any node) and rebroadcast a byte-mutated copy with one extra malformed `MessageSignature` prepended to the `signer_signature` vector. This is cheap, requires no BTC spend, and is repeatable against any block as it propagates, as long as the attacker can win a race to deliver the mutated copy to some subset of peers before the genuine copy arrives.

### Recommendation
Change `verify_signer_signatures` to treat a single unrecoverable/invalid signature as a per-entry failure rather than a whole-function failure: log and skip entries that fail `recover_to_pubkey_without_validating_low_s` (or fail signer-membership/ordering checks), and only return `Err` if, after processing all entries, the accumulated `total_weight_signed` still fails to reach the required threshold. This restores the intended equality that adding a garbage entry to an already-sufficient valid signature set cannot flip acceptance to rejection.

### Proof of Concept
Rust integration test plan (in `stackslib/src/chainstate/nakamoto/tests/mod.rs`, extending existing `verify_signer_signatures` tests):
1. Build a `RewardSet` with signers `s0..sK` and weights such that any subset of size `N < K` still exceeds `threshold`.
2. Construct a valid `NakamotoBlockHeader` and have `N` signers sign `signer_signature_hash()`, producing `signer_signature = [sig_0, ..., sig_{N-1}]`; call `verify_signer_signatures(&reward_set)` and assert `Ok(())` — this is side A of the equality.
3. Clone the header, and construct `signer_signature' = [MessageSignature::empty(), sig_0, ..., sig_{N-1}]` (garbage entry prepended) — same N valid signatures, same reward set, same threshold.
4. Call `verify_signer_signatures(&reward_set)` on the mutated header and assert the result; per current code, this asserts `Err(ChainstateError::InvalidStacksBlock(_))`, demonstrating divergence from step 2's `Ok(())` despite identical valid-signature weight satisfying threshold in both cases — proving side A != side B under current implementation.
5. (Optional, to justify High impact rather than pure DoS) Add a two-node harness where node A receives the header from step 2 (accepts, advances tip) and node B receives the mutated header from step 3 (rejects, stalls at prior tip), demonstrating temporary tip disagreement between honest nodes from the same underlying valid block.
