## Finding [1](#0-0) 

### Title
Unlimited fee-free class declarations via the hardcoded `BOOTSTRAP` sender address while `validate_resource_bounds` is disabled - (File: `crates/blockifier/src/transaction/account_transaction.rs`, `crates/starknet_api/src/executable_transaction.rs`, `crates/apollo_gateway/src/stateful_transaction_validator.rs`)

### Summary
The sequencer has a special-cased "bootstrap declare" execution path that completely skips `__validate_declare__` and fee charging for any `Declare` transaction whose `sender_address` equals a fixed, public, non-secret constant (`bootstrap_address()`), whose `nonce` is `0`, and whose `charge_fee` is `false`. Whether `charge_fee` is `false` is itself derived purely from attacker-supplied resource bounds (`enforce_fee`), and the gateway-level guard that would normally reject a zero-fee transaction (`validate_resource_bounds`) is a global, network-wide config flag that is explicitly turned off during the chain's bootstrap period. During that window, any unprivileged sender who crafts a `Declare` transaction with `sender_address = bootstrap_address()`, `nonce = 0`, and zero resource bounds bypasses `__validate_declare__`, nonce checks, and fee charging entirely, and can repeat this for an unlimited number of distinct classes.

### Finding Description
The bootstrap bypass is defined in `DeclareTransaction::is_bootstrap_declare`: [1](#0-0) 

The address is a hardcoded constant, computed from the literal ASCII string `'BOOTSTRAP'` (`0x424f4f545354524150`) — it is not a secret, not derived from any private key, and is publicly known from the codebase.

In `AccountTransaction::execute_raw`, when `is_bootstrap_declare` is true, the sequencer skips `perform_pre_validation_stage` (nonce/fee checks), skips `run_or_revert` (which normally invokes `__validate_declare__`), and skips `handle_fee`: [2](#0-1) 

The exact same bypass exists in the Starknet OS Cairo re-execution path used for state-transition proving, meaning both the sequencer and the OS agree on skipping validation/fee for this address: [3](#0-2) 

The `charge_fee` flag that gates this bypass is derived from the transaction's own resource bounds via `enforce_fee`, which is attacker-controlled: [4](#0-3) [5](#0-4) 

Normally, submitting a transaction with zero resource bounds is rejected by the gateway's `validate_resource_bounds` check, which enforces that the tx's L2 gas price meets a percentage of the previous block's gas price: [6](#0-5) [7](#0-6) 

However, `validate_resource_bounds` is a single global boolean config parameter, documented as intended to be disabled network-wide during the chain's bootstrap phase: [8](#0-7) [9](#0-8) 

Test code confirms that with this flag disabled, zero-resource-bound transactions are freely admitted into the mempool's priority queue instead of being rejected: [10](#0-9) 

Because nonce is never incremented for a bootstrap-declare (the "account-related action" — nonce bump and fee charge — is entirely skipped), and the only state check performed is `prev_value=0` on the *class_hash key* (i.e. that specific class hasn't been declared yet), an attacker can submit an unbounded number of distinct `Declare` transactions, each with a different (self-chosen) class, all using `sender_address = BOOTSTRAP`, `nonce = 0`, zero resource bounds, and no signature — each one is accepted, skips validate, and is executed for free.

### Impact Explanation
This is analogous to the Shardeum finding: a global, time-boxed "bootstrap mode" flag (`numActiveNodes < minActiveNodesForStaking` in Shardeum vs. `validate_resource_bounds = false` here) is intended to be applied narrowly (only to a legitimate, privileged bootstrap flow) but in fact removes protections network-wide for the duration of the bootstrap window, letting an unprivileged actor forge requests that satisfy the loosened bootstrap conditions. Here, that means:
- Fee bypass: unlimited free `Declare` transactions consuming sequencer/prover/state resources and Cairo1 CASM compilation work with zero fee payment (direct loss of expected transaction fee revenue / consumption of network resources without payment).
- Unauthorized "account action": transactions are executed as if issued by `sender_address = BOOTSTRAP`, an address that is not owned by any account contract, has no signature check, and no `__validate_declare__` invocation, effectively granting anyone the account's execution privileges for the declare flow.
- Since class declarations are otherwise deduplicated only by `class_hash`, an attacker can flood the state with attacker-chosen classes for free, for the entire bootstrap window, at no cost — an availability/resource-abuse vector during the most sensitive period of the chain's life.

### Likelihood Explanation
The precondition (`validate_resource_bounds = false`) is not a hypothetical edge case — it is a documented, intended operational configuration ("It should be set to false during a system bootstrap") applied at genesis/bootstrap of a real deployment, exactly mirroring the "first N cycles" window in the Shardeum report. The `bootstrap_address()` constant is hardcoded and discoverable directly from the open-source repository; no secret material or privileged access is required to construct a qualifying transaction. The only skill required is crafting a valid `Declare` v3 transaction with the specific sender address, nonce 0, and zero resource bounds — all fields fully controlled by the transaction sender via the public gateway RPC.

### Recommendation
- Do not gate the bootstrap-declare bypass on a network-wide flag (`validate_resource_bounds`) that also disables fee/gas-price checks for arbitrary transactions from any sender. Restrict the bypass check itself (`is_bootstrap_declare`) so it can only be satisfied by a transaction that the node/operator explicitly injects (e.g., only accept it directly from a local/admin-only interface, or require it to appear only as the very first transaction of the very first block, keyed off block number rather than an unbounded/global flag).
- Decouple `validate_resource_bounds` from the correctness of `enforce_fee`/`is_bootstrap_declare`: even while `validate_resource_bounds` is disabled for legitimate bootstrap purposes, the gateway should still reject any `Declare` transaction using `bootstrap_address()` that did not originate from the trusted bootstrap process (e.g., verify it is only accepted once, at genesis height, from a privileged source).
- Consider requiring a unique, cryptographically-bound one-time credential (rather than a fixed public constant) for legitimate bootstrap declarations.

### Proof of Concept
Conceptually (a background engineer can implement and run this as an integration test against a devnet with `validate_resource_bounds=false`, mirroring `apollo_integration_tests/tests/bootstrap_declare.rs` and `generate_bootstrap_declare()`):
1. Start a sequencer with `gateway_config.stateful_tx_validator_config.validate_resource_bounds = false` (the documented bootstrap configuration), as done via `allow_bootstrap_txs` in `crates/apollo_integration_tests/src/utils.rs` (lines 363-364).
2. As an unprivileged client (no account, no funds), submit a `Declare` v3 RPC transaction with:
   - `sender_address = DeclareTransaction::bootstrap_address()` (`0x424f4f545354524150`)
   - `nonce = 0`
   - `resource_bounds` all zero (`ValidResourceBounds::create_for_testing_no_fee_enforcement()`-equivalent)
   - a self-chosen valid Sierra/CASM class pair
   - empty/default signature.
3. Observe the transaction is admitted by the gateway (skips `validate_resource_bounds` check since it is globally disabled) and enters the mempool priority queue (as shown by `test_add_bootstrap_tx_depends_on_config` in `crates/apollo_mempool/src/fee_mempool_test.rs`).
4. Observe at execution (`AccountTransaction::execute_raw`) that `is_bootstrap_declare` returns true, skipping `__validate_declare__` and fee charging, and the class is declared with zero fee paid.
5. Repeat with a different `class_hash` each time (nonce remains 0 since it's never incremented on this path) to declare an unlimited number of classes for free during the bootstrap window.

    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }

    // TODO(Arni): Consider running this validation for all gas prices.
    fn validate_tx_l2_gas_price_within_threshold(
        &self,
        tx_resource_bounds: ValidResourceBounds,
        previous_block_l2_gas_price: NonzeroGasPrice,
    ) -> StatefulTransactionValidatorResult<()> {
        match tx_resource_bounds {
            ValidResourceBounds::AllResources(tx_resource_bounds) => {
                let tx_l2_gas_price = tx_resource_bounds.l2_gas.max_price_per_unit;
                let gas_price_threshold_multiplier =
                    Ratio::new(self.config.min_gas_price_percentage.into(), 100_u128);
                let threshold = (gas_price_threshold_multiplier
                    * previous_block_l2_gas_price.get().0)
                    .to_integer();
                if tx_l2_gas_price.0 < threshold {
                    return Err(StarknetError {
                        // We didn't have this kind of an error.
                        code: StarknetErrorCode::UnknownErrorCode(
                            "StarknetErrorCode.GAS_PRICE_TOO_LOW".to_string(),
                        ),
                        message: format!(
                            "Transaction L2 gas price {tx_l2_gas_price} is below the required \
                             threshold {threshold}.",
                        ),
                    });
                }
            }
            ValidResourceBounds::L1Gas(_) => {
                // No validation required for legacy transactions.
            }
        }
        Ok(())
    }
