However, there's a key gap: the bootstrap-declare special-case only checks `sender_address == BOOTSTRAP`, `nonce == 0`, and `max_possible_fee == 0` — it never verifies that the system is actually still in its genesis phase (e.g., no blocks yet / no prior declares). ### Title
Unrestricted zero-fee, unvalidated class declaration via the BOOTSTRAP sender address bypass - (File: crates/blockifier/src/transaction/account_transaction.rs)

### Summary
The blockifier's `execute_raw` for `AccountTransaction::Declare` special-cases a magic constant sender address (`ContractAddress::from(0x424f4f545354524150)`, i.e. `'BOOTSTRAP'`) to allow fee-less, validation-less class declarations intended only for chain genesis bootstrapping [1](#0-0) . The gate to enter this branch is purely `sender_address == BOOTSTRAP && nonce == 0 && !charge_fee` (and `max_possible_fee == 0`), with no genesis/height/state check, and by default the gateway config does not restrict who may submit declare transactions from this address [2](#0-1) .

### Finding Description
`AccountTransaction::execute_raw` checks `tx.is_bootstrap_declare(self.execution_flags.charge_fee)` and, if true, runs only `tx.run_execute(...)` — skipping `perform_pre_validation_stage` (nonce increment, fee-bound checks), the `__validate_declare__` account entry point, and fee charging entirely, then returns a default `TransactionExecutionInfo` [3](#0-2) . The corresponding Starknet OS Cairo code implements the identical bypass: it skips `check_and_increment_nonce`, `__validate_declare__`, and `charge_fee`, and just writes the class hash into `contract_class_changes` guarded only by `prev_value=0` (i.e., "not already declared") [4](#0-3) .

The only gating condition is `is_bootstrap_declare`, which merely checks the sender address constant, nonce zero, and no fee — there is no accompanying invariant enforcing this can only occur once, at genesis, or from a privileged party [5](#0-4) . Because nonce is never incremented for this special sender, the transaction's identity/nonce state never advances, meaning any external, unauthenticated party can construct and submit as many of these bootstrap-declare transactions as they want at any block height, each declaring a brand-new (not-yet-declared) class for free, with no signature verification of ownership over the `BOOTSTRAP` address (there is no key associated with it — it's a protocol constant, not an account).

Gateway-side, `check_declare_permissions` only restricts declares via the optional `authorized_declarer_accounts` allowlist, which defaults to `None` (unrestricted) in `GatewayStaticConfig::default()` [6](#0-5) , and is entirely orthogonal to genesis/bootstrap status — it does not prevent post-genesis submission of a "bootstrap" declare with the magic sender address.

### Impact Explanation
This allows any unprivileged transaction submitter to declare arbitrary new classes on the network for free, completely bypassing the fee market, account validation, and nonce-based replay protections that are core to Starknet's DoS-resistance model for the mempool/gateway layer. Since a fresh unique class hash can always be produced (attacker fully controls the source code/class), this provides an unbounded, cost-free way to force the sequencer to perform Sierra→CASM compilation and store new declared classes indefinitely — a spam/resource-exhaustion vector at the gateway/compilation and state-growth layer, sidestepping the very fee-based resource-accounting model the sequencer otherwise enforces on all declare transactions.

### Likelihood Explanation
Likelihood is high given default configuration: no signature is required (no `__validate__` call occurs), `authorized_declarer_accounts` is `None` by default, and the check is a simple constant match on `sender_address`, `nonce`, and fee bounds computed entirely from attacker-supplied `resource_bounds` in the RPC declare transaction body — fully reachable from a single, unprivileged `starknet_addDeclareTransaction` submission.

### Recommendation
Restrict the bootstrap-declare bypass so it is only honored when the chain has no prior blocks/declared classes (true genesis condition verified against actual state, not just the nonce field), and/or require that `authorized_declarer_accounts`/an explicit genesis-authority check gates the `BOOTSTRAP` sender address specifically, independent of the general declarer allowlist. Alternatively, remove magic-address-based bootstrapping in favor of an explicit, out-of-band genesis initialization path that is not reachable via the ordinary transaction-submission gateway once the chain is live.

### Proof of Concept
1. Deploy/target a live sequencer instance with default `GatewayStaticConfig` (`authorized_declarer_accounts = None`).
2. Craft an RPC `DECLARE` V3 transaction with `sender_address = 0x424f4f545354524150` ("BOOTSTRAP"), `nonce = 0`, `resource_bounds` set so `max_possible_fee() == 0` (e.g., via `ValidResourceBounds::create_for_testing_no_fee_enforcement()`, mirrored by `generate_bootstrap_declare` in test utils [7](#0-6) ), a fresh, never-declared `class_hash`/`compiled_class_hash`, and an arbitrary (unchecked) signature.
3. Submit via `starknet_addDeclareTransaction`. It bypasses `check_declare_permissions` (if no allowlist configured), passes stateless/stateful nonce checks trivially since `nonce==0` and there's no `__validate_declare__` call, and `execute_raw` declares the class hash directly for free.
4. Repeat with a new class hash and the same `BOOTSTRAP` sender/nonce=0 combination — this succeeds again for every new, unique class hash indefinitely, since the sender's nonce never advances and each new class hash passes the `prev_value=0` uniqueness check.

    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

        // - This time, execution will fail because the contract has already been declared.
