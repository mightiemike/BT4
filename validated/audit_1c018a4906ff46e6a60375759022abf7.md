### Title
Vault RequestReplayGuard resets its `seen` digest map on every process restart, allowing replay of previously-authorized requests before their expiry - ([File: core/capabilities/vault/request_replay_guard.go])

### Summary
`RequestReplayGuard` is meant to prevent an already-processed Vault JSON-RPC request (identified by its digest) from being re-submitted and re-executed while its authorization is still valid. Its state is held purely in an in-process map that is (re)initialized empty every time `NewRequestReplayGuard()`/`NewAuthorizer()` runs, which happens once per process lifetime with no persistence. This mirrors the reported `LivenessGuard` bug class: a guard whose protective state is supposed to persist across (re)deployments/restarts is instead reset to a "nothing has happened yet" baseline whenever it is reinstantiated, silently defeating the guard's purpose.

### Finding Description
`RequestReplayGuard.seen` is a `map[string]int64` created fresh by `NewRequestReplayGuard()`: [1](#0-0) 

It is instantiated exactly once, inside `NewAuthorizer`, and wired into the single `authorizer` struct used by `GatewayHandler`/`GatewayVaultRequestProcessor` for the lifetime of that process: [2](#0-1) 

`AuthorizeRequest` relies entirely on this in-memory `seen` map to reject a digest that was already recorded and not yet expired: [3](#0-2) 

The comment in `request_replay_guard.go` explicitly documents that this is the sole replay-protection mechanism shared by both the allowlist-based and JWT-based auth flows: "Used by both the AllowListBasedAuth flow and the JWTBasedAuth flow to ensure that a given request digest is only accepted once." There is no persistence to a database or durable store backing `seen` — the map lives only in process memory, exactly analogous to `LivenessGuard.lastLive` being re-populated from scratch in the constructor instead of being carried over from the prior deployment.

`GatewayHandler` (which owns the `authorizer`) is constructed once at node/gateway startup via `NewGatewayHandler`, which in turn calls `NewAuthorizer` when no override authorizer is supplied: [4](#0-3) 

Any time this process restarts — a routine node/gateway pod restart, an upgrade/redeploy, or a crash/recovery — a brand-new, empty `RequestReplayGuard` is created. All digests that were previously recorded (and whose `expiresAt` had not yet passed) are forgotten. If an attacker or an eavesdropper that captured a still-valid, previously-used signed/authorized Vault request (allowlist digest with a future `ExpiryTimestamp`, or a JWT-bound `request_digest` claim with a future `exp` + validation leeway) resubmits that exact request after such a restart, `CheckAndRecord` will treat it as never-before-seen and accept it, because the map no longer contains the digest.

### Impact Explanation
Successful replay of an already-authorized Vault request lets an unprivileged actor who obtained (via network capture, logs, or a previously-processed transcript) a still-valid authorized request re-execute privileged Vault operations such as `vault.secrets.create`/`vault.secrets.delete`/`vault.secrets.list` a second time, bypassing the "only accepted once" guarantee that the rest of the authorization pipeline depends on. Because the replay window is bounded only by the original request's expiry (which can be minutes) and a restart can be triggered by routine node operations (upgrades, crash recovery, redeploys), this converts what is intended to be a hard single-use guarantee into a guarantee that only holds "as long as the gateway process doesn't restart," undermining the request-integrity model the vault gateway pipeline is built on (`GatewayVaultRequestProcessor` documents the replay guard as one of its pipeline invariants).

### Likelihood Explanation
This will occur any time the process hosting the `authorizer`/`GatewayHandler` restarts while a previously-authorized, not-yet-expired request digest exists that an attacker can resubmit — which is a routine, frequent operational event (deploys, upgrades, crash/restart), not a rare edge case. No special privilege is needed by the replaying party beyond having captured one previously valid request.

### Recommendation
Persist the `seen` digest→expiry state (or at minimum its high-water/expiry information) outside process memory (e.g., in the node's database or a shared durable store) so that a restart of the gateway/authorizer does not erase previously-recorded digests. Alternatively, when reinitializing `RequestReplayGuard` on startup, seed it from a persisted store of not-yet-expired digests, analogous to seeding `LivenessGuard.lastLive` from the prior guard's, rather than always starting from an empty map.

### Proof of Concept
1. Node/gateway is running with a `GatewayHandler` created via `NewGatewayHandler` → `NewAuthorizer` → `NewRequestReplayGuard()`.
2. A legitimate client sends an authorized Vault request (allowlisted or JWT-authorized) with `ExpiresAt` several minutes in the future; `authorizer.AuthorizeRequest` records its digest via `replayGuard.CheckAndRecord`, and the request is processed.
3. An attacker who captured this exact request (e.g., from network traffic, logs, or a compromised intermediary) attempts to resubmit it immediately — it is correctly rejected with `ErrRequestAlreadySeen` (as shown in `TestAuthorizer_RejectsJWTReplay` / `TestAuthorizer_RejectsAllowListBasedAuthReplay`).
4. The gateway/node process restarts (upgrade, crash, redeploy) before the request's `ExpiresAt` has passed. A brand-new `authorizer`/`RequestReplayGuard` with an empty `seen` map is created.
5. The attacker resubmits the identical captured request. Because the new `seen` map has no record of the digest, `CheckAndRecord` succeeds and the privileged Vault operation is executed a second time.

```go
type RequestReplayGuard struct {
	mu      sync.Mutex
	seen    map[string]int64 // digest → unix expiry timestamp
	nowFunc func() time.Time // injectable for testing

// NewRequestReplayGuard creates a replay guard for authorized Vault requests.
func NewRequestReplayGuard() *RequestReplayGuard {
	return &RequestReplayGuard{
		seen:    make(map[string]int64),
		nowFunc: time.Now,
	}
}
```

```go
func (a *authorizer) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	authResult, err := a.authorizeRequest(ctx, req)
	if err != nil {
		return nil, err
	}
	if authResult == nil {
		err = errors.New("auth mechanism returned nil auth result")
		a.lggr.Errorw("auth mechanism returned nil auth result", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "")
		return nil, err
	}
	if err := a.replayGuard.CheckAndRecord(authResult.Digest(), authResult.ExpiresAt()); err != nil {
		a.lggr.Debugw("replay guard rejected request", "method", req.Method, "requestID", req.ID, "owner", authResult.AuthorizedOwner(), "digest", authResult.Digest(), "expiresAt", authResult.ExpiresAt(), "hasAuth", req.Auth != "", "error", err)
		return nil, err
	}
```

```go
func NewGatewayHandler(
	secretsService vaulttypes.SecretsService,
	connector gatewayConnector,
	workflowRegistrySyncer workflowsyncerv2.WorkflowRegistrySyncer,
	lggr logger.Logger,
	limitsFactory limits.Factory,
	authorizer Authorizer,
	auth0 *Auth0Config,
) (*GatewayHandler, error) {
	var jwtAuthService services.Service
	var jwtBasedAuth Authorizer
	if auth0 != nil {
		var err error
		jwtAuthService, err = NewJWTBasedAuth(JWTBasedAuthConfig{
			IssuerURL: auth0.IssuerURL,
			Audience:  auth0.Audience,
			TenantID:  auth0.TenantID,
		}, limitsFactory, lggr)
		if err != nil {
			return nil, fmt.Errorf("failed to create JWTBasedAuth: %w", err)
		}
		jwtBasedAuth = jwtAuthService.(Authorizer)
	}

	if authorizer == nil {
		allowListBasedAuth := NewAllowListBasedAuth(lggr, workflowRegistrySyncer)
		authorizer = NewAuthorizer(allowListBasedAuth, jwtBasedAuth, lggr)
	}

	requestValidator, err := NewRequestValidatorFromLimitsFactory(limitsFactory)
	if err != nil {
		return nil, fmt.Errorf("failed to create request validator: %w", err)
	}

	metrics, err := newMetrics()
	if err != nil {
		return nil, fmt.Errorf("failed to create metrics: %w", err)
	}

	requestProcessor, err := NewGatewayVaultRequestProcessor(requestValidator, authorizer, true, lggr)
	if err != nil {
		return nil, fmt.Errorf("failed to create gateway vault request processor: %w", err)
	}
```
