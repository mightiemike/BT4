### Title
Panic (out-of-bounds slice / index) when converting an attacker-influenced CASM class into `CompiledClassV1` — `NestedFeltCounts::new` — (File: `crates/blockifier/src/execution/contract_class.rs`)

### Summary
`TryFrom<VersionedCasm> for CompiledClassV1` unconditionally calls `NestedFeltCounts::new(&class.get_bytecode_segment_lengths(), &class.bytecode)` [1](#0-0) . That function recursively slices the raw `bytecode` array using the lengths declared in `bytecode_segment_lengths` (`&bytecode[..*len]`) before ever checking that the declared lengths agree with the actual bytecode length [2](#0-1) . If `bytecode_segment_lengths` describes a total length larger than `bytecode.len()`, the slice indexing panics with an out-of-bounds error instead of returning a `Result`. This mirrors the CVE-2018-7642 bug class: a crafted/malformed binary-class artifact (there, an ELF; here, a CASM contract class) causes an unchecked structural assumption to be violated, crashing the process instead of gracefully erroring.

### Finding Description
`CasmContractClass.bytecode_segment_lengths` is an `Option<NestedIntList>` that is serialized/deserialized independently of the `bytecode` `Vec` — nothing in the type system ties their lengths together [3](#0-2) . `NestedFeltCounts::new_inner` walks this structure and, for every `NestedIntList::Leaf(len)`, immediately does `&bytecode[..*len]` and only *afterwards* asserts that consumed length matches (`assert_eq!(consumed_felts, bytecode.len())` in the top-level `new`, which never gets reached if the slice already panicked) [4](#0-3) . This function is invoked from the core `VersionedCasm -> CompiledClassV1` conversion, which is the exact code path used whenever a Cairo1 class is turned into a runnable/hashable class object — including from state read paths that deserialize a `CasmContractClass` from storage/state-sync JSON and feed it directly into this constructor without any structural pre-validation, e.g. `SyncStateReader::get_compiled_classes` (`CompiledClassV1::try_from(casm_contract_class)?`) [5](#0-4) , and `apollo_rpc_execution`'s `get_contract_class`/`get_compiled_class` which call `CompiledClassV1::try_from((casm, sierra_version))` on data pulled straight from storage or pending-block class caches [6](#0-5) [7](#0-6) .

### Impact Explanation
A single crafted CASM artifact with a mismatched `bytecode_segment_lengths` field, once it reaches any of these `TryFrom` call sites, panics the executing thread. Because `CompiledClassV1::try_from` is used on the read-side (deserializing storage/class-manager/pending-class data) rather than only immediately after trusted compilation, this is reachable by any component that re-derives a runnable class from persisted or synced data (batcher's block-building state reader, RPC execution, re-execution/replay tooling). A deterministic panic on a specific declared class means every honest node that later needs to load/execute that class (to serve RPC calls, to include it in a block, or during Starknet-OS re-execution) crashes identically, which can manifest as repeated block-building/service failures — a liveness issue rather than a memory-safety compromise. Severity is bounded because it requires the malformed structural relationship to actually reach storage (normally only compiler output populates this field), so the practical likelihood of a live attacker injecting such a mismatch depends on whether any code path lets an externally influenced value populate `bytecode_segment_lengths` without going through the trusted Sierra→CASM compiler subprocess.

### Likelihood Explanation
The `bytecode_segment_lengths` on the normal declare path is always produced by the internal `SierraToCasmCompiler`, which invokes an audited external `cairo-lang` binary and deserializes its JSON stdout as `CasmContractClass` [8](#0-7) . I could **not** find, within the scope of this analysis, a concrete path where an unprivileged transaction sender/declarer can directly control `bytecode_segment_lengths` independently of the compiler output (e.g., no evidence of a raw/uncompiled CASM upload endpoint reachable from a declare transaction). This significantly weakens likelihood versus a directly-exploitable analog, and I flag this as **unverified** rather than proven: it would require either (a) a bug in the trusted compiler that produces internally-inconsistent `CasmContractClass` output for some adversarial Sierra program, or (b) another ingestion path (e.g. a JSON-RPC endpoint or state-sync deserialization of an untrusted CASM blob) that bypasses the compiler. Neither could be confirmed with the available tools.

### Recommendation
Harden `NestedFeltCounts::new`/`new_inner` in `crates/blockifier/src/execution/contract_class.rs` to return a `Result` instead of panicking: validate that segment lengths never exceed the remaining bytecode length before slicing (use `bytecode.get(..*len)` and propagate an error on `None`), and propagate this error through `TryFrom<VersionedCasm> for CompiledClassV1` as a `ProgramError` variant instead of allowing an unchecked panic. Additionally, audit every call site that constructs `CompiledClassV1` from data that did not just come out of the local Sierra→CASM compiler process (`SyncStateReader::get_compiled_classes`, `apollo_rpc_execution::execution_utils::get_contract_class`, `apollo_rpc_execution::state_reader::get_compiled_class`) to confirm whether any of them can be reached with attacker-influenced bytes, and add explicit structural validation of `CasmContractClass` immediately after deserialization from any external/storage source.

### Proof of Concept
Could not be constructed with certainty because the exact untrusted-input ingestion point for a mismatched `bytecode_segment_lengths` (bypassing the trusted compiler subprocess) was not found in the available code index. A concrete PoC would need to:
1. Identify a code path where a `CasmContractClass` payload (JSON) is deserialized from data that is not produced by `SierraToCasmCompiler::compile` (e.g., directly from state-sync/storage or an RPC upload) yet is subsequently trusted for `CompiledClassV1::try_from`.
2. Construct such a payload where `bytecode_segment_lengths` sums to a value greater than `bytecode.len()`.
3. Trigger the read/execution path (e.g., `SyncStateReader::get_compiled_classes` or `apollo_rpc_execution`'s `get_contract_class`) to observe the panic (`range end index out of range for slice`).

Given the uncertainty about attacker reachability confirmed above, this should be treated as a defense-in-depth/robustness finding pending further investigation into ingestion paths, rather than a confirmed exploitable vulnerability with a verified single-transaction trigger.

impl NestedFeltCounts {
    /// Builds a nested structure matching `layout`, consuming values from `bytecode`.
    #[allow(unused)]
    pub fn new(bytecode_segment_lengths: &NestedIntList, bytecode: &[BigUintAsHex]) -> Self {
        let (base_node, consumed_felts) = Self::new_inner(bytecode_segment_lengths, bytecode, 0);
        assert_eq!(consumed_felts, bytecode.len());
        base_node
    }

    /// Recursively builds the nested structure and returns it with the number of items consumed.
    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
    }

pub(crate) fn get_contract_class(
    txn: &StorageTxn<'_, RO>,
    class_hash: &ClassHash,
    state_number: StateNumber,
) -> Result<Option<RunnableCompiledClass>, ExecutionUtilsError> {
    match txn.get_state_reader()?.get_class_definition_block_number(class_hash)? {
        Some(block_number) if state_number.is_before(block_number) => return Ok(None),
        Some(_block_number) => {
            let (Some(casm), Some(sierra)) = txn.get_casm_and_sierra(class_hash)? else {
                return Err(ExecutionUtilsError::CasmTableNotSynced);
            };
            let sierra_version =
                sierra.get_sierra_version().map_err(ExecutionUtilsError::SierraValidationError)?;
            return Ok(Some(RunnableCompiledClass::V1(CompiledClassV1::try_from((
                casm,
                sierra_version,
            ))?)));
        }
        None => {}
    };

    let Some(deprecated_class) =
        txn.get_state_reader()?.get_deprecated_class_definition_at(state_number, class_hash)?
    else {
        return Ok(None);
    };
    Ok(Some(RunnableCompiledClass::V0(
        CompiledClassV0::try_from(deprecated_class).map_err(ExecutionUtilsError::ProgramError)?,
    )))
}

    /// tokio::spawn_blocking() thread, because of the blocking code.
    fn get_compiled_class(&self, class_hash: ClassHash) -> StateResult<RunnableCompiledClass> {
        if let Some(pending_classes) =
            self.maybe_pending_data.as_ref().map(|pending_data| &pending_data.classes)
        {
            if let Some(api_contract_class) = pending_classes.get_class(class_hash) {
                match api_contract_class {
                    ApiContractClass::ContractClass(sierra) => {
                        if let Some(pending_casm) = pending_classes.get_compiled_class(class_hash) {
                            let sierra_version = sierra.get_sierra_version()?;
                            let runnable_compiled_class = RunnableCompiledClass::V1(
                                CompiledClassV1::try_from((pending_casm, sierra_version))
                                    .map_err(StateError::ProgramError)?,
                            );
                            return Ok(runnable_compiled_class);
                        }
                    }
                    ApiContractClass::DeprecatedContractClass(pending_deprecated_class) => {
                        return Ok(RunnableCompiledClass::V0(
                            CompiledClassV0::try_from(pending_deprecated_class)
                                .map_err(StateError::ProgramError)?,
                        ));
                    }
                }
            }
        }

        if let Some((class_manager_client, run_time_handle)) = &self.class_manager_handle {
            let contract_class = run_time_handle
                .block_on(class_manager_client.get_executable(class_hash))
                .map_err(|e| StateError::StateReadError(e.to_string()))?
                .ok_or(StateError::UndeclaredClassHash(class_hash))?;

            return match contract_class {
                ContractClass::V1(casm_contract_class) => {
                    let is_declared = is_contract_class_declared(
                        &self.storage_reader.begin_ro_txn().map_err(storage_err_to_state_err)?,

                        self.state_number,

                    .map_err(|e| StateError::StateReadError(e.to_string()))?;

                    if is_declared {
                        Ok(RunnableCompiledClass::V1(casm_contract_class.try_into()?))
                    } else {
                        Err(StateError::UndeclaredClassHash(class_hash))
                    }
                }
                // TODO(shahak): Verify cairo0 as well after get_class_definition_block_number is
                // fixed.
                ContractClass::V0(deprecated_contract_class) => {
                    Ok(RunnableCompiledClass::V0(deprecated_contract_class.try_into()?))
                }
            };
