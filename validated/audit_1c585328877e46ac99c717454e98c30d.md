### Title
Zero-cost builtin instances from floor division in `induced_gas_costs` let a transaction escape bouncer proving-gas accounting - ([File: crates/blockifier/src/bouncer.rs])

### Summary
`BuiltinInstanceLimits::induced_gas_costs` derives each Cairo builtin's per-instance proving-gas cost with a plain floor division, `proving_gas / limit`, before that per-unit cost is ever multiplied by a transaction's usage count. This is structurally the same bug class as the UniswapV3 report: a division is performed too early, so a value that should be a small-but-nonzero fixed-point cost truncates to `0` whenever the numerator is smaller than the denominator. Any builtin whose induced cost floors to zero then contributes **zero weight** to `proving_gas` regardless of how many times it is used in a transaction, letting a transaction sender consume unbounded real proving resources while the bouncer's accounting reports no cost for that resource.

### Finding Description
`BuiltinInstanceLimits::induced_gas_costs` computes, per builtin, `cost = floor(proving_gas / limit)`: [1](#0-0) 

This per-unit cost is derived once per block from `BouncerConfig::builtin_gas_costs`, which calls `induced_gas_costs` with the configured `block_max_capacity.proving_gas`: [2](#0-1) 

The resulting per-builtin cost is later used as a straight multiplier against the number of times a Cairo primitive/builtin is invoked in a transaction, with no floor/zero guard: [3](#0-2) 

This feeds directly into `proving_gas_from_cairo_primitives_and_sierra_gas` and `compute_proving_gas`, which sum into the `proving_gas` field of the per-transaction `BouncerWeights` used by `get_tx_weights`, which then gets checked against `block_max_capacity` via `has_room`/`within_max_capacity_or_err`: [4](#0-3) [5](#0-4) [6](#0-5) 

Exactly like the UniswapV3 `sqrtPriceX96` bug — where `(token0Price * 10**18) / token1Price` truncates to `0` whenever `token1Price` is disproportionately larger, silently zeroing a value that should be nonzero and cascading into a systematically wrong (and here, one-sided) valuation — `proving_gas.0 / limit.get()` truncates to `0` whenever the configured `proving_gas` budget for the block is smaller than a given builtin's per-block instance limit (`limit`). Because the division happens *before* any multiplication by transaction usage, the truncation is baked into the constant that is reused for every subsequent transaction in the block, rather than being a per-transaction rounding error.

### Impact Explanation
If any builtin's induced proving-gas cost floors to `0` (e.g., due to a `block_max_capacity.proving_gas` value smaller than that builtin's `BuiltinInstanceLimits` entry, which is possible since these are two independently configured values with no cross-validation enforced in `BouncerConfig`), a transaction sender can invoke that builtin an arbitrary number of times without increasing the transaction's `proving_gas` weight at all. The bouncer's `has_room`/`within_max_capacity_or_err` checks — the sequencer's sole mechanism for keeping a block's real proving workload within provable limits — would then admit transactions/blocks whose actual proving cost for that builtin is unbounded while their accounted weight is zero. This can produce blocks that cannot actually be proven within the intended resource budget (a form of resource-accounting corruption reachable directly from a single submitted transaction that repeatedly invokes the affected builtin), which is exactly the "wrong valuation → wrong admission decision" failure mode described in the source report, transposed from token pricing to block-resource accounting.

### Likelihood Explanation
Exploitability is conditional on the deployed `BouncerConfig` (specifically the relationship between `block_max_capacity.proving_gas` and each entry in `builtin_instance_limits`), which I could not fully confirm from the indexed JSON resources for the currently deployed production bouncer configuration — only fixture/test values were retrievable (e.g. `BuiltinInstanceLimits::default()` combined with a `6_000_000_000` proving-gas budget in tests, which does not floor to zero). Because I was unable to verify the exact production `proving_gas` capacity against all builtin limits directly from the index, I cannot confirm with certainty that a zero-cost condition is reachable under current mainnet constants; this should be verified against the live `BouncerConfig`/versioned-constants values (or via a Devin session with full repo access) before treating it as immediately triggerable. The root-cause arithmetic flaw itself, however, is confirmed directly in the code.

### Recommendation
Guard `induced_gas_costs` against floor-to-zero results — e.g. round up (`div_ceil`) instead of floor division, or return an explicit configuration error when `proving_gas / limit == 0` for any builtin, so that a builtin can never have an effective per-instance proving-gas cost of `0`. Additionally, validate at config-load time that `block_max_capacity.proving_gas` is not smaller than any configured `BuiltinInstanceLimits` entry, preventing this degenerate case from being reachable in the first place.

### Proof of Concept
1. Assume/configure a `BouncerConfig` where `block_max_capacity.proving_gas.0 < builtin_instance_limits.<some_builtin>.get()` (e.g., a smaller proving-gas budget than the keccak instance limit).
2. `BouncerConfig::builtin_gas_costs()` calls `induced_gas_costs`, and for that builtin, `derive(limit) = proving_gas.0 / limit.get() = 0` (integer floor division): [7](#0-6) 
3. A transaction sender crafts a transaction that repeatedly invokes the affected builtin (e.g., many `keccak_builtin` calls).
4. `cairo_primitives_to_gas` multiplies the `0` per-unit cost by the (large) usage count, yielding `0` contribution to `proving_gas`: [8](#0-7) 
5. `get_tx_weights`/`compute_proving_gas` propagate this `0` into `BouncerWeights.proving_gas`, and `BouncerConfig::has_room` reports the transaction/block as within capacity even though the builtin was invoked an unbounded number of times: [5](#0-4) 
6. The sequencer admits the transaction/block, having under-accounted the true proving workload for that builtin — the resource-accounting analog of the report's "liquidity all assumed to be amount0" misvaluation.

impl BuiltinInstanceLimits {
    /// Induces the per-instance proving-gas cost of each Cairo primitive from its per-block
    /// instance limit: `cost = floor(proving_gas / limit)`.
    pub fn induced_gas_costs(&self, proving_gas: GasAmount) -> BuiltinGasCosts {
        let derive = |limit: NonZeroU64| -> u64 { proving_gas.0 / limit.get() };
        BuiltinGasCosts {
            pedersen: derive(self.pedersen),
            range_check: derive(self.range_check),
            range_check96: derive(self.range_check96),
            poseidon: derive(self.poseidon),
            ecdsa: derive(self.ecdsa),
            ecop: derive(self.ecop),
            bitwise: derive(self.bitwise),
            keccak: derive(self.keccak),
            add_mod: derive(self.add_mod),
            mul_mod: derive(self.mul_mod),
            blake: derive(self.blake),
        }
    }
}

pub fn cairo_primitives_to_gas(
    cairo_primitives_counters: &CairoPrimitiveCounterMap,
    // NOTE: 'blake' is currently the only supported opcode, by being included in the
    // builtin_gas_costs.
    cairo_primitives_gas_costs: &BuiltinGasCosts,
) -> GasAmount {
    let cairo_primitives_gas =
        cairo_primitives_counters.iter().fold(0u64, |accumulated_gas, (name, &count)| {
            let cairo_primitive_weight =
                cairo_primitives_gas_costs.get_cairo_primitive_gas_cost(name).unwrap();
            cairo_primitive_weight
                .checked_mul(u64_from_usize(count))
                .and_then(|builtin_gas| accumulated_gas.checked_add(builtin_gas))
                .unwrap_or_else(|| {
                    panic!(
                        "Overflow while converting cairo primitives counters to gas.\nCairo \
                         primitive: {name:?}, Weight: {cairo_primitive_weight}, Count: {count}, \
                         Accumulated gas: {accumulated_gas}"
                    )
                })
        });

    GasAmount(cairo_primitives_gas)
}
