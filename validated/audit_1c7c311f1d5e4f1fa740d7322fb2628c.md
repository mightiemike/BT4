## Analysis

The reported jsPDF bug is a classic CWE‑116 "Improper Encoding/Escaping of Output" issue: an attacker-controlled string is spliced into a structured text format using naive string operations that don't account for the format's escaping rules, letting the attacker "break out" of the intended field and inject content that a downstream parser interprets differently than intended.

A directly analogous pattern exists in the sequencer's computation of the legacy (Cairo 0) **hinted class hash**, which is fully reachable by an unprivileged class declarer. [1](#0-0) 

`compute_cairo_hinted_class_hash` serializes the contract's `CairoContractDefinition` to a JSON byte buffer and then, for classes without a `compiler_version` (i.e. Cairo 0 / deprecated classes), post-processes the *raw serialized JSON text* with regexes rather than manipulating the structured `serde_json::Value`: [2](#0-1) 

`add_backward_compatibility_space` uses `"value"\s*:\s*"(.*?)"` to locate `AttributeScope.value` strings inside the raw JSON text. `AttributeScope.value` is a fully attacker-controlled `String` field of a Cairo 0 contract's `program.attributes`: [3](#0-2) 

The regex `.*?` is not escape-aware: it treats any literal `"` byte as the closing delimiter, even when that `"` is actually an escaped quote (`\"`) that is part of the JSON string's content, not its terminator. A class declarer can therefore craft an `attributes[].value` string that embeds a `\"` sequence followed by decoy `(key: value)`-like text. The regex will stop matching at the first `"` it encounters (mistaking the escaped quote for a real terminator), causing `add_backward_compatibility_space` to transform a different — and attacker-influenced — substring than the one a spec-compliant/structurally-aware implementation would transform. This changes the final byte sequence that is fed into `KeccakWriter`/`truncated_keccak`, producing a `hinted_class_hash` (and consequently a `deprecated_class_hash`, since `compute_deprecated_class_hash` folds the hinted hash into the Pedersen hash chain) that may not match the value computed by the canonical Starknet class-hashing algorithm or by other implementations that don't share this regex-based escaping bug. [4](#0-3) 

### Title
Regex-based, escape-unaware JSON text mangling in deprecated (Cairo 0) hinted class hash computation can yield a class hash that diverges from the canonical algorithm - (File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs)

### Summary
`add_backward_compatibility_space`, used when computing the Keccak-based "hinted class hash" of legacy Cairo 0 contract classes, applies regex substitutions directly on the raw serialized JSON text instead of operating on structured JSON values. The regex used for the `"value"` field (`"value"\s*:\s*"(.*?)"`) has no knowledge of JSON backslash-escaping, so an attacker-supplied `program.attributes[].value` string containing an escaped quote (`\"`) can cause the regex to terminate its match prematurely at the wrong byte offset. This is architecturally the same flaw class as the jsPDF advisory: raw, unsanitized/uninterpreted user string content is spliced into (and here, matched against) a structured serialization using naive text operations that don't respect the format's own escaping rules.

### Finding Description
`compute_cairo_hinted_class_hash` ( [1](#0-0) ) builds the byte string that is Keccak-hashed to derive the hinted class hash. For Cairo 0 classes (`compiler_version.is_none()`), it calls `add_backward_compatibility_space` on the raw JSON text to reinsert spaces around colons inside `cairo_type`/`value` tuple-type strings, matching legacy formatting behavior.

The `value_regex` (`"value"\s*:\s*"(.*?)""#`) is designed to capture the content of the `"value"` JSON field so it can rewrite `(a:felt)`-style substrings into `(a : felt)`. Because `.*?` matches arbitrary bytes and the regex engine has no concept of JSON escape sequences, any `"` byte inside the captured region — including one that is really part of an escaped `\"` inside the JSON string — is treated as the field's closing quote. `AttributeScope.value` is a free-form `String` fully controlled by whoever supplies the Cairo 0 program artifact for a `DECLARE` transaction; there is no validation constraining its content beyond being a valid JSON string, so an attacker can embed `\"` plus adversarial text designed to make the regex substitution operate on unintended byte ranges.

### Impact Explanation
Since the hinted class hash directly feeds `compute_deprecated_class_hash` ( [4](#0-3) ), a crafted Cairo 0 class can cause this sequencer implementation to compute a class hash that differs from the value produced by a canonical/structurally-correct implementation (or by other node software that doesn't reproduce this exact escaping bug). A class hash is a consensus-critical value: it determines contract identity, is stored in state, is checked by the Starknet OS during re-execution, and factors into the committed state root and block hash. A divergent class hash for the same submitted class artifact between honest nodes (or between this sequencer and the canonical Starknet OS reference) results in state-root/block-hash divergence — an honest-node-divergence condition that can halt block confirmation or produce an unprovable/invalid state transition.

### Likelihood Explanation
Reachable directly by any class declarer submitting a Cairo 0 (`compiler_version` absent) contract class via a normal `DECLARE` transaction — no privileged access is required. The attacker only needs to control the `program.attributes[].value` string content of the submitted artifact, which is not semantically validated against real compiler output before this hashing routine runs.

### Recommendation
Replace the regex-based raw-text post-processing in `add_backward_compatibility_space` with an escape-aware transformation that operates on the parsed JSON string value (e.g., transform `AttributeScope.value`/`cairo_type` fields as decoded Rust `String`s before re-serialization, using JSON-aware string handling), or make the regex properly escape-aware (e.g., match using a state machine that tracks `\` escape sequences) so that embedded escaped quotes cannot be mistaken for field delimiters. Cross-check the output against the canonical Starknet hashing reference implementation with fuzzed/adversarial `attributes[].value` inputs (embedded quotes, backslashes, parentheses, colons) to confirm equivalence.

### Proof of Concept
1. Construct a Cairo 0 `ContractClass` (no `compiler_version`) whose `program.attributes` includes an entry with:
   `value: "(a: felt) \" (malicious: injected)"`
2. Serialize via `compute_cairo_hinted_class_hash`; the emitted JSON will contain
   `"value": "(a: felt) \" (malicious: injected)"`.
3. `value_regex` (`"value"\s*:\s*"(.*?)"`) matches non-greedily and stops at the first literal `"` — i.e., at the escaped quote — capturing only `"(a: felt) \"` instead of the full intended string, and leaving `(malicious: injected)"` unprocessed/outside the substitution.
4. The resulting byte buffer fed to Keccak differs from what a spec-correct, escape-aware transformer would produce for the identical logical `value` field, yielding a class hash for this contract that a reference/canonical implementation would compute differently — demonstrating the divergence.

pub fn compute_cairo_hinted_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    // Serialize to Value, sort all objects by keys for deterministic output, then to bytes.
    // The sorting is necessary because serde_json with `preserve_order` feature enabled
    // maintains insertion order instead of sorting keys.
    // TODO(Meshi): Compute hinted hashes when loading serialized contracts from storage, before
    // deserializing, to avoid back-and-forth serde.
    let contract_value = serde_json::to_value(contract_class)?;
    let sorted_contract_value = sort_json_value(contract_value);
    let contract_definition_vec = serde_json::to_vec(&sorted_contract_value)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let mut string_buffer = vec![];

    let mut ser = serde_json::Serializer::with_formatter(&mut string_buffer, PythonJsonFormatter);
    contract_definition.serialize(&mut ser)?;

    let mut raw_json_output = String::from_utf8(string_buffer)?;
    if contract_definition.program.compiler_version.is_none() {
        add_backward_compatibility_space(&mut raw_json_output);
    }

    let mut keccak_writer = KeccakWriter::default();
    keccak_writer
        .write_all(raw_json_output.as_bytes())
        .expect("writing to KeccakWriter never fails");

    let KeccakWriter(hash) = keccak_writer;
    Ok(truncated_keccak(<[u8; 32]>::from(hash.finalize())))
}

/// Adds space before the colon when formatting named tuple types.
/// This should be used for backward compatibility in the contract hash computation in versions
/// before 0.10.0.
/// For example, use "(a : felt)" instead of "(a: felt)".
pub fn add_backward_compatibility_space(input: &mut String) {
    let cairo_regex = Regex::new(r#""cairo_type"\s*:\s*"\(([^"]*)\)""#).unwrap();
    let value_regex = Regex::new(r#""value"\s*:\s*"(.*?)""#).unwrap();
    let paren_regex = Regex::new(r"\(([^()]+)\)").unwrap();
    let pair_regex = Regex::new(r"([^:\s,]+):\s*([^,\s)]+)").unwrap();

    // Fix cairo_type, which must be a single type (either a simple type or a tuple).
    *input = cairo_regex
        .replace_all(input, |caps: &regex::Captures<'_>| {
            let inner = &caps[1];
            let fixed = pair_regex.replace_all(inner, "$1 : $2");
            format!("\"cairo_type\": \"({fixed})\"")
        })
        .into_owned();

    // Fix only (key: value) pairs inside (...) in "value".
    *input = value_regex
        .replace_all(input, |caps: &regex::Captures<'_>| {
            let raw_value = &caps[1];
            let fixed = paren_regex
                .replace_all(raw_value, |paren_caps: &regex::Captures<'_>| {
                    let inner = &paren_caps[1];
                    let fixed_inner = pair_regex.replace_all(inner, "$1 : $2");
                    format!("({fixed_inner})")
                })
                .into_owned();
            format!("\"value\": \"{fixed}\"")
        })
        .into_owned();
}

pub fn compute_deprecated_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    let hinted_class_hash = compute_cairo_hinted_class_hash(contract_class)?;
    let contract_definition_vec = serde_json::to_vec(contract_class)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let FlatEntryPointFelts { external, l1_handler, constructor } =
        get_flat_entry_point_felts(&contract_definition.entry_points_by_type);
    let builtins = ascii_strs_as_felts(&contract_definition.program.builtins);
    let bytecode = hex_strs_as_felts(&contract_definition.program.data);

    let mut hash_state = HashState::<Pedersen>::new();
    hash_state.update_single(&DEPRECATED_COMPILED_CLASS_VERSION);
    hash_state.update_with_hashchain(&external);
    hash_state.update_with_hashchain(&l1_handler);
    hash_state.update_with_hashchain(&constructor);
    hash_state.update_with_hashchain(&builtins);
    hash_state.update_single(&hinted_class_hash);
    hash_state.update_with_hashchain(&bytecode);
    Ok(hash_state.finalize())
}
