### Title
Unbounded per-shop session-ID list traversal causes DoS of the install-check/uninstall auth handlers - (File: `packages/apps/session-storage/shopify-app-session-storage-redis/src/redis.ts`)

### Summary
`RedisSessionStorage.findSessionsByShop` (and the equivalent KV storage list) keeps an unbounded per-shop index array (`idKeysArray`) that is only ever appended to, with no cap, similar to the un-capped `vouchees` traversal in the Union Finance report. Every call to `findSessionsByShop` walks that list end-to-end, and in the Redis adapter it does so with a sequential `await` per element rather than a bounded/parallel/paginated read. [1](#0-0) 

### Finding Description
`addKeyToShopList` pushes a new key onto the shop's Redis list on every `storeSession` call, with no upper bound and no deduplication cap: [2](#0-1) 

For non-embedded apps, each new online-token OAuth exchange creates a session with a freshly-generated `crypto.randomUUID()` id (rather than a deterministic `shop_userId` id used for embedded apps), so repeating the OAuth flow indefinitely for the same shop keeps adding distinct, never-colliding entries to that list: [3](#0-2) 

`findSessionsByShop` is then invoked from unprivileged/merchant-triggered auth paths: `AppInstallations.includes`/`delete`, which back both `ensureInstalledOnShop` (evaluated on every embedded-app page load / OAuth begin check) and the `APP_UNINSTALLED` webhook handler: [4](#0-3) [5](#0-4) 

Because `findSessionsByShop` in the Redis adapter loops sequentially and awaits a network round trip per stored key, a shop whose list has been inflated (via repeated non-embedded OAuth logins, which is something a single unprivileged actor completing the OAuth flow repeatedly can do) will make every subsequent call to this function (on install checks and on uninstall webhook processing) proportionally slower, exactly mirroring the "unbounded array traversal" root cause in the referenced report, just replacing gas exhaustion with request-latency/connection exhaustion.

### Impact Explanation
Because `ensureInstalledOnShop` (via `AppInstallations.includes`) runs on the OAuth/installation-check path for every request to an unauthenticated storefront/app route, and the `APP_UNINSTALLED` webhook handler (via `AppInstallations.delete`) processes it for uninstall events, a sufficiently inflated per-shop key list turns each of these calls into a large sequential fan-out of Redis round trips. This can materially degrade or stall the install-check and uninstall-webhook auth handlers for that shop, a functional DoS of authentication-adjacent request handling, without requiring any credential compromise.

### Likelihood Explanation
The growth path for non-embedded apps requires only repeatedly completing the standard OAuth authorization flow for the same shop; no privileged access or secret leakage is needed, and the code has no cap analogous to Union Finance's `maxVouchers` check. However, this only meaningfully affects the non-embedded-app configuration (`isEmbeddedApp: false`), and it requires an operator to be using the `RedisSessionStorage` (or `KVSessionStorage`) package rather than a SQL-backed store, which limits applicability. It also requires the attacker/merchant to drive many OAuth round trips, which is rate-limited in practice by Shopify's own OAuth flow overhead.

### Recommendation
- Cap the number of entries retained per shop in `addKeyToShopList`/`addShopIds` (e.g., prune or dedupe by evicting the oldest/expired sessions) instead of growing the list unconditionally.
- For non-embedded apps, avoid minting a brand-new `randomUUID()` per login when an active online session for the same user already exists, to prevent unbounded list growth.
- Change `findSessionsByShop` in the Redis adapter to batch-fetch (e.g., `MGET`) or paginate instead of a sequential per-key `await` loop, bounding worst-case latency.

### Proof of Concept
1. Configure `shopify-app-express` (or another framework package) with `isEmbeddedApp: false` and `RedisSessionStorage` as the session storage backend.
2. As the shop's own merchant/admin (a single unprivileged actor, no secret required), repeatedly complete the standard OAuth online-token authorization flow for the same shop many times (each completion is a legitimate, HMAC-verified OAuth callback). Each run creates a new session with a fresh `crypto.randomUUID()` id per `create-session.ts` lines 33-40, and `addKeyToShopList` appends the id to the shop's Redis list indefinitely.
3. Trigger any code path that calls `findSessionsByShop` for that shop — e.g., load an app page that runs `ensureInstalledOnShop` (`AppInstallations.includes`) or send an `APP_UNINSTALLED` webhook (`AppInstallations.delete`).
4. Observe that `findSessionsByShop`'s `for (const idKey of idKeysArray)` loop performs one sequential Redis round trip per accumulated key, so the install-check/uninstall handler's latency scales linearly with the number of prior OAuth logins, eventually causing timeouts for that shop's requests.   public async findSessionsByShop(shop: string): Promise<Session[]> {
    await this.ready;

    const idKeysArrayString = await this.client.get(shop);
    if (!idKeysArrayString) return [];

    const idKeysArray = JSON.parse(idKeysArrayString);
    const results: Session[] = [];
    for (const idKey of idKeysArray) {
      const rawResult = await this.client.get(idKey, false);
      if (!rawResult) continue;

      const session = Session.fromPropertyArray(JSON.parse(rawResult), true);
      results.push(session);
    }

    return results;
  }

  private async addKeyToShopList(session: Session) {
    const shopKey = session.shop;
    const idKey = this.client.generateFullKey(session.id);
    const idKeysArrayString = await this.client.get(shopKey);

    if (idKeysArrayString) {
      const idKeysArray = JSON.parse(idKeysArrayString);

      if (!idKeysArray.includes(idKey)) {
        idKeysArray.push(idKey);
        await this.client.set(shopKey, JSON.stringify(idKeysArray));
      }
    } else {
      await this.client.set(shopKey, JSON.stringify([idKey]));
    }
  }

  async includes(shopDomain: string): Promise<boolean> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      for (const session of shopSessions) {
        if (session.accessToken) return true;
      }
    }
    return false;
  }

  async delete(shopDomain: string): Promise<void> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      await this.sessionStorage.deleteSessions!(
        shopSessions.map((session: Session) => session.id),
      );
    }
  }
