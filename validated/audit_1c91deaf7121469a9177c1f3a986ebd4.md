### Title
Unrelated STRK/USD oracle deviation permanently freezes valid transactions via the gateway's L2-gas-price threshold check - (File: crates/apollo_gateway/src/stateful_transaction_validator.rs)

### Summary
The Ubiquity report describes a DoS where redemptions are blocked by a hard threshold check against a price feed that can be moved by events unrelated to the guarded asset (USDT/USDC depeg moving a 3CRV price used to gate uAD redemption). The structural analog in this sequencer is `validate_tx_l2_gas_price_within_threshold`, which hard-rejects any transaction whose `max_price_per_unit` for L2 gas falls below `min_gas_price_percentage * previous_block_l2_gas_price`, where `previous_block_l2_gas_price` is itself derived from an external STRK/USD oracle feed via `compute_fee_target`/`compute_fee_proposal`.

### Finding Description
`validate_resource_bounds` in `crates/apollo_gateway/src/stateful_transaction_validator.rs:223-243` reads `previous_block_l2_gas_price` from the last committed block and calls `validate_tx_l2_gas_price_within_threshold` (lines 358-390), which computes a hard `threshold = min_gas_price_percentage/100 * previous_block_l2_gas_price` and rejects (`GAS_PRICE_TOO_LOW`) any transaction whose `l2_gas.max_price_per_unit` is below it: [1](#0-0) 

`previous_block_l2_gas_price` (the "fee_actual"/"fee_proposal" for the block) is not derived purely from on-chain L2 demand; it is computed each block from an external STRK/USD exchange-rate oracle via `compute_fee_target`, and then clamped by a geometric margin around the previous fee in `compute_fee_proposal`/`fee_proposal_bounds`: [2](#0-1) 

The default `min_gas_price_percentage` is `100` (i.e., the check requires the tx's max L2 gas price to be at least the *full* previous block's L2 gas price, not a fraction), per config defaults: [3](#0-2) 

Because the oracle-driven `l2_gas_price` clamp is multiplicative and geometric ("fee can shrink/grow by `1+margin` per round"), a sequence of adverse oracle readings (e.g., a legitimate but sharp STRK/USD price move, or a stale/faulty oracle feed causing the rate to be quoted inconsistently across queries) can ratchet `l2_gas_price` upward round after round. Since every honest sequencer runs the identical deterministic formula, the required `previous_block_l2_gas_price` rises network-wide, not just for one node. Wallets and users who set `max_price_per_unit` based on the last known fair price will have their transactions rejected at the gateway with `GAS_PRICE_TOO_LOW` until they resubmit with an ever-higher bound, exactly mirroring the Ubiquity pattern where an unrelated price movement (of a component asset in a shared price feed) hard-blocks user-facing operations (redemption there, transaction submission here) via a threshold check with no fallback/tolerance band tied to the actual condition being protected against.

### Impact Explanation
This is a gateway-level admission control gate reachable by any unprivileged transaction sender. If the derived `l2_gas_price` deviates due to oracle noise/lag unrelated to genuine L2 demand, legitimate transactions with fair resource bounds are rejected network-wide (all sequencers apply the same deterministic threshold), degrading to "network unable to confirm new (correctly-priced) transactions" until users repeatedly increase their bounds to chase the moving threshold — a temporary, but potentially recurring/systemic, submission DoS driven purely by an external, unrelated price input.

### Likelihood Explanation
Medium: the `compute_fee_proposal` clamp is geometrically bounded per round (`margin_ppt`), so a single-block spike is limited, but sustained/successive oracle deviations (oracle lag, feed volatility, or degraded oracle behavior as anticipated by `L1GasPriceProviderError`/oracle-failure handling in the codebase) can compound across blocks. The check is unconditionally applied when `validate_resource_bounds` is enabled (the production default), and `min_gas_price_percentage=100` leaves no slack for the tx price to trail the computed on-chain price by even a small margin, so any transient overshoot in the oracle-derived price directly translates into rejected user transactions.

### Recommendation
Add a tolerance/deadband or fallback path in `validate_tx_l2_gas_price_within_threshold` so that oracle-driven price swings unrelated to genuine congestion do not hard-block valid transactions — e.g., cap the rate of threshold increase independently of the fee-proposal's own margin, allow transactions within a wider band during detected oracle instability, or decouple L2 gas price threshold enforcement from the external STRK/USD rate feed used purely for fee-target computation.

### Proof of Concept
Not independently reproducible from static analysis alone (requires simulating consecutive blocks with adverse STRK/USD oracle rates through `compute_fee_target`/`compute_fee_proposal` and observing the compounding effect on `previous_block_l2_gas_price` feeding `validate_tx_l2_gas_price_within_threshold`); the existing test `validate_resource_bounds` in `crates/apollo_gateway/src/stateful_transaction_validator_test.rs:229-328` demonstrates the exact rejection mechanics (`GAS_PRICE_TOO_LOW`) that would trigger once `previous_block_l2_gas_price` is pushed up by oracle-driven fee computation. /// Compute the fee target from STRK/USD price and a USD cost target.
///
/// `target_atto_usd_per_l2_gas` is in atto-USD (atto = 10⁻¹⁸; so a value of
/// `3_000_000_000` means 3·10⁻⁹ USD = 3 nanodollars per L2 gas unit).
/// `strk_usd_rate` is the STRK/USD price as USD per STRK with 18 decimals (from the oracle);
/// a rate of `0` returns `None` (treat as oracle failure: callers freeze at `fee_actual`).
/// Returns the target in FRI; the multiplicative margin clamp in `compute_fee_proposal`
/// keeps the published proposal bounded relative to `fee_actual`.
pub fn compute_fee_target(
    target_atto_usd_per_l2_gas: u128,
    strk_usd_rate: u128,
) -> Option<GasPrice> {
    if strk_usd_rate == 0 {
        return None;
    }
    // floor_fri = target_atto_usd_per_l2_gas * 10^18 / strk_usd_rate
    let numerator = U256::from(target_atto_usd_per_l2_gas) * U256::from(FRI_DECIMALS_SCALE);
    let floor = numerator / U256::from(strk_usd_rate);
    Some(GasPrice(u128::try_from(floor).unwrap_or(u128::MAX)))
}

/// Compute the fee_proposal an honest proposer should publish.
/// - If oracle failed (`fee_target` is `None`): freeze at `fee_actual`.
/// - Otherwise: clamp `fee_target` into the geometric bounds returned by `fee_proposal_bounds`.
pub fn compute_fee_proposal(
    fee_target: Option<GasPrice>,
    fee_actual: GasPrice,
    margin_ppt: u128,
) -> GasPrice {
    let Some(fee_target) = fee_target else {
        return fee_actual;
    };
    let (lower, upper) = fee_proposal_bounds(fee_actual, margin_ppt);
    GasPrice(fee_target.0.clamp(lower, upper))
}

/// Geometric bounds for fee_proposal: returns `(lower, upper)` where
/// - `upper = fee_actual * (1 + margin)` (multiplicative widening), and
/// - `lower = fee_actual / (1 + margin)` (the reciprocal — multiplicative narrowing),
///
/// with `margin = margin_ppt / PPT_DENOMINATOR`.
///
/// The asymmetry is intentional: bounds are geometrically symmetric (the same
/// multiplicative factor in either direction), so a sequence of consecutive proposals
/// can grow by `(1 + margin)` per round or shrink by the same factor per round. Both
/// proposer and validator use this helper to ensure they agree on what's in-range.
///
/// Uses `U256` internally to keep the arithmetic mathematically correct regardless of
/// `fee_actual` and `margin_ppt`. On the practically-unreachable overflow, the upper
/// bound saturates to `u128::MAX` and the lower bound saturates to `0`.
pub(crate) fn fee_proposal_bounds(fee_actual: GasPrice, margin_ppt: u128) -> (u128, u128) {
    let denom = U256::from(PPT_DENOMINATOR);
    let scaled = denom + U256::from(margin_ppt);
    let fee_actual_u256 = U256::from(fee_actual.0);
    let upper = u128::try_from(fee_actual_u256 * scaled / denom).unwrap_or(u128::MAX);
    let lower = u128::try_from(fee_actual_u256 * denom / scaled).unwrap_or(0);
    (lower, upper)
}
