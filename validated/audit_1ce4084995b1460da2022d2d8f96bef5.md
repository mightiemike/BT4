## Title
Hardcoded 5% slippage tolerance computed from a manipulable spot-price quoter enables sandwich-style value extraction from gas-abstraction swaps - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The external report describes mint/burn orders that lack user-defined slippage bounds, letting an attacker manipulate pool price around order execution and extract value from the victim's fill. Push Chain has a structurally identical pattern in `x/uexecutor`'s gas-abstraction auto-swap logic: whenever the protocol swaps a bridged PRC20 token for PC on behalf of a user (`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and the outbound gas-refund path `applyGasRefund`), it fetches a live spot-price quote from `QuoterV2.quoteExactInputSingle` and derives `minPCOut` as a hardcoded 95% of that quote — there is no user-supplied minimum-output or deadline, and the "protection" bound itself is computed from the same manipulable on-chain price used for the swap.

### Finding Description
Three call sites compute the swap floor identically: [1](#0-0) [2](#0-1) [3](#0-2) 

In all three, `GetSwapQuote` is a static call to `QuoterV2.quoteExactInputSingle`, i.e., the current spot price of the pool at execution time, not a TWAP or user-approved bound: [4](#0-3) 

`minPCOut` is then always `quote * 95 / 100` — a protocol-hardcoded 5% tolerance, never influenced by the user who initiated the inbound deposit/gas top-up, and with no deadline/expiry check on the quote-to-execution window. Because the quote is fetched and the swap executed within the same keeper call inside the same Push Chain block (triggered synchronously the moment UV votes reach quorum on `MsgVoteInbound`/`MsgVoteOutbound`), an attacker who can land a transaction that moves the pool price immediately before this call executes (ordinary, unprivileged EVM swap transactions on Push Chain's own AMM) can force the quote itself to reflect the manipulated price. The module then accepts any output within 5% of that already-manipulated quote, and the attacker reverses their price-moving trade afterward, capturing the spread at the expense of the crosschain depositor/refund recipient. This mirrors the report's exploit exactly: attacker manipulates price around an order with no user-controlled bound, then reverses it to extract value from the victim's execution.

### Impact Explanation
This lets an unprivileged attacker extract value (up to the 5% band, and potentially more since the "protection" moves with the manipulated price rather than an independent reference) from ordinary users who submit `GAS`/`GAS_AND_PAYLOAD` crosschain deposits or who are due an unused-gas refund on outbound completion. It is a direct value-drain from user/protocol-controlled swap flows reachable through default deposit and outbound-refund paths — squarely in scope under "corruption of ... gas fee accounting, refund accounting" and "stealing ... funds" for an unprivileged attacker with no reliance on malicious validators.

### Likelihood Explanation
Every `GAS`/`GAS_AND_PAYLOAD` inbound and every outbound with unused-gas refund goes through this exact same code path, so the attack surface is broad and continuously reachable by any user submitting ordinary crosschain transactions. The only requirement is the ability to move the underlying Uniswap-V3-style pool price via a normal swap transaction timed just before the module's swap executes in the same block — a standard MEV/sandwich primitive, not a privileged action.

### Recommendation
Replace the hardcoded 5%-of-spot-quote bound with either (a) a TWAP-based reference price resistant to same-block manipulation, or (b) a genuinely user-supplied `minPCOut`/deadline carried in the inbound/outbound payload and enforced at execution, consistent with the external report's short-term recommendation. At minimum, source the quote from a time-weighted oracle rather than the same-block spot quoter used for execution, and add tests that simulate price manipulation immediately before execution to confirm the swap reverts rather than silently accepting a manipulated rate.

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` (TxType `GAS_AND_PAYLOAD`) that will trigger `gasAndPayloadDepositAutoSwap` for victim's PRC20→PC deposit once quorum is reached.
2. In the same block, attacker submits a large swap against the same PRC20/WPC Uniswap V3 pool via `UniversalCore`, moving the spot price down.
3. The quorum vote lands; `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-537`) calls `quoteExactInputSingle` and returns the manipulated (depressed) quote; `minPCOut = quote * 95/100` is computed from that manipulated value (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:369-379`).
4. `CallPRC20DepositAutoSwap` executes the victim's swap at the manipulated price, satisfying `minPCOut` trivially.
5. Attacker reverses their initial swap, restoring the pool price and pocketing the spread extracted from the victim's swap output.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
