### Title
Unauthenticated amplification of outbound Shopify Admin API calls via `ensureInstalled` non-embedded path - ([File: packages/apps/shopify-app-express/src/middlewares/ensure-installed-on-shop.ts])

### Summary
The `ensureInstalledOnShop` middleware calls `sessionHasValidAccessToken` → `hasValidAccessToken` (which issues a live GraphQL request to Shopify's Admin API) on every request that has a valid `shop` query parameter, an existing offline session, and `embedded !== '1'`. This path requires no authentication (no session token, no HMAC, no cookie) beyond a syntactically valid shop domain, so an unauthenticated client can force the app to burn its own Admin API rate-limit budget on demand.

### Finding Description
In `ensureInstalledOnShop` (`packages/apps/shopify-app-express/src/middlewares/ensure-installed-on-shop.ts`), the only gating on the request is `getRequestShop`, which merely calls `api.utils.sanitizeShop(req.query.shop)` — a format/domain check, not an authentication check [1](#0-0) . When the legacy (non-token-exchange) flow is active and a session already exists in storage for that shop, the middleware branches on `embedded !== '1'` and calls `sessionHasValidAccessToken(api, config, session)` [2](#0-1) . That function, if the session is "active" per scopes, immediately calls `hasValidAccessToken(api, session)` [3](#0-2) , which constructs a live GraphQL client using the session's access token and issues a real `TEST_GRAPHQL_QUERY` request to Shopify's Admin API on every single invocation with no caching, memoization, debounce, or backoff [4](#0-3) . Since `embedded` and `shop` are attacker-controlled query parameters and no session token/HMAC is verified before this call, any anonymous client can repeatedly trigger it by sending `GET /?shop=<installed-shop>` without `embedded=1`.

### Impact Explanation
Each unauthenticated request forces one outbound authenticated Admin API call using the app's own access token for the targeted shop. Because Shopify enforces per-app/per-shop Admin API rate limits (bucket/cost-based throttling), an attacker can flood this unauthenticated endpoint to exhaust the app's Admin API quota for that shop, degrading or denying legitimate app functionality for that merchant (DoS via outbound API rate-limit exhaustion), and this happens purely from an unauthenticated inbound request path with no session-token or HMAC gate. This matches "DoS in an authentication handler" in the accepted impact classes.

### Likelihood Explanation
Precondition is simply that a shop has an existing offline session in storage — a common, default state for any previously installed shop. No secret, no privileged role, and no non-default configuration is required (this is the default, non-token-exchange embedded-app flow). The attacker needs only to know or guess a valid installed shop's `*.myshopify.com` domain and send repeated `GET` requests omitting `embedded=1`; this is trivially scriptable and fully repeatable.

### Recommendation
Rate-limit or cache the result of `hasValidAccessToken` per session/shop (e.g., short TTL cache, or only perform the check once per some interval), and/or require some proof of legitimacy (e.g., valid `host`/session-token presence) before triggering the outbound validation call from an otherwise-unauthenticated code path in `ensureInstalledOnShop`.

function getRequestShop(
  api: Shopify,
  config: AppConfigInterface,
  req: Request,
  res: Response,
): string | undefined {
  if (typeof req.query.shop !== 'string') {
    config.logger.error(
      'ensureInstalledOnShop did not receive a shop query argument',
      {shop: req.query.shop},
    );

    res.status(400);
    res.send('No shop provided');
    return undefined;
  }

  const shop = api.utils.sanitizeShop(req.query.shop);

  if (!shop) {
    config.logger.error(
      'ensureInstalledOnShop did not receive a valid shop query argument',
      {shop: req.query.shop},
    );

    res.status(422);
    res.send('Invalid shop provided');
    return undefined;
  }

  return shop;
}

async function sessionHasValidAccessToken(
  api: Shopify,
  config: AppConfigInterface,
  session: Session | undefined,
): Promise<boolean> {
  if (!session) {
    return false;
  }

  try {
    return (
      session.isActive(api.config.scopes) &&
      (await hasValidAccessToken(api, session))
    );
  } catch (error) {
    config.logger.error(`Could not check if session was valid: ${error}`, {
      shop: session.shop,
    });
    return false;
  }
}

export async function hasValidAccessToken(
  api: Shopify,
  session: Session,
): Promise<boolean> {
  try {
    const client = new api.clients.Graphql({session});
    await client.request(TEST_GRAPHQL_QUERY);
    return true;
  } catch (error) {
    if (error instanceof HttpResponseError && error.response.code === 401) {
      // Re-authenticate if we get a 401 response
      return false;
    } else {
      throw error;
    }
  }
}
