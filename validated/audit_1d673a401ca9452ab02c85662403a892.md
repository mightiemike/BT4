### Title
Global-contract "AccountId" owner can permanently brick every account that references their contract, freezing state and funds behind unreachable logic - (File: `runtime/runtime/src/global_contracts.rs`)

### Summary
The Sherlock report describes a malicious lender that defines an `onRepay` callback which always reverts, permanently blocking a borrower's ability to repay and thus freezing their assets. The reachable nearcore analog is `GlobalContractDeployMode::AccountId`: an untrusted, unprivileged account that deploys a global contract "by account id" retains unilateral, ongoing control over the code executed on behalf of every other account that references it via `UseGlobalContractByAccountId`. The referencing accounts pin no hash — they trust the owner's account id — so the owner can redeploy broken/always-panicking code at any time and permanently disable every dependent account.

### Finding Description
`GlobalContractDeployMode::AccountId` is documented to let "the owner update the contract for all its users" [1](#0-0) [2](#0-1) .

When another account calls `UseGlobalContractAction` with `GlobalContractIdentifier::AccountId(id)`, the runtime only checks that a global contract currently exists under that owner's identifier, then binds the caller's account to `AccountContract::GlobalByAccount(id)` — it does not pin the code hash: [3](#0-2) 

Redeployment by the owner (`action_deploy_global_contract` → `initiate_distribution` → `apply_distribution_current_shard`) simply overwrites the same `TrieKey::GlobalContractCode { identifier: AccountId(...) }` trie slot with new code, with no restriction preventing the owner from doing this after other accounts have already bound to it: [4](#0-3) 

At execution time, the runtime resolves `AccountContract::GlobalByAccount(id)` by looking up whatever code is *currently* stored under that owner's identifier — resolution is late-bound, not pinned to the code that existed when the caller opted in: [5](#0-4) [6](#0-5) 

Consequently, an account (the "owner") that other accounts have chosen to depend on via `UseGlobalContractByAccountId` — exactly analogous to a lender whose `onRepay` callback code other users must call into — can unilaterally replace their globally-referenced code with code that unconditionally panics (or burns all attached gas). Every account bound to `AccountContract::GlobalByAccount(owner)` then has all `FunctionCall` receipts against it fail forever, since the runtime always fetches the owner's live code rather than a hash the dependent committed to.

### Impact Explanation
Any account that references a third party's contract via `UseGlobalContractByAccountId` (e.g., lightweight vault/instance accounts spawned from a shared template, as demonstrated by the sharded-contract "spread" pattern using `GlobalContractIdentifier::AccountId`) is at the mercy of that owner continuing to serve non-malicious code. If the owner (who need not be privileged in any way — any unprivileged account can call `DeployGlobalContractAction` with `AccountId` mode) redeploys broken code, every dependent account's stored state and any balances whose sole access path is through that account's contract logic become permanently unusable/frozen, since dependents never pinned an immutable code hash and have no protocol mechanism to force detachment from a hostile owner. This matches "permanently frozen funds" from the Validate criteria, reached purely through an ordinary sequence of `DeployGlobalContractAction`/`UseGlobalContractAction`/`FunctionCall` transactions.

### Likelihood Explanation
Reaching this requires only: (1) an attacker deploying a global contract in `AccountId` mode, (2) a victim account choosing to reference it via `UseGlobalContractByAccountId` (a documented, intended usage pattern, e.g. for cheaply spawning many contract instances that share upgradeable code), and (3) the attacker later redeploying malicious/always-reverting code to the same identifier. All three steps use only standard, unprivileged transactions available to any signer, and are exercised in existing tests (`test_global_contract_by_account_id_rpc_calls`, `test_use_global_contract_by_account_id_delegate`) confirming the live-binding behavior is by design rather than an edge case.

### Recommendation
Give dependents a way to protect themselves from a hostile/careless `AccountId`-mode owner: e.g., allow `UseGlobalContractByAccountId` callers to optionally pin the code hash observed at bind time and fail future calls if it changes, or provide a way to migrate/detach from a `GlobalByAccount` reference without needing a full-balance/full-key transaction, or clearly document that `AccountId`-mode global contracts must only be referenced by accounts that fully trust the owner in perpetuity, and provide the immutable `CodeHash` mode as the recommended pattern for shared, trust-minimized templates.

### Proof of Concept
1. Attacker (`owner.near`) deploys a global contract in `AccountId` mode with a benign method, e.g. `main()` returning success: `Action::DeployGlobalContract { deploy_mode: AccountId, code }` [7](#0-6) .
2. Victim account calls `UseGlobalContractAction { contract_identifier: AccountId(owner.near) }`, binding to `AccountContract::GlobalByAccount(owner.near)` [8](#0-7) .
3. Victim's function calls succeed while the owner's code is honest.
4. Attacker submits a new `DeployGlobalContractAction` with `AccountId` mode and code that unconditionally panics, overwriting the same trie slot [9](#0-8) .
5. All subsequent `FunctionCall`s to the victim account resolve to the new, always-panicking code via `RuntimeContractIdentifier::resolve` [10](#0-9) , permanently disabling the victim account's contract functionality with no way for the victim to detach short of another privileged action against their own account.

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };
    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract).or_inconsistent_state(account_id)?;
    Ok(())
}

            code_hash,
        ));
    }

    pub(crate) fn resolve(
        account_id: &AccountId,
        account_contract: AccountContract,
        state_update: &TrieUpdate,
        chain_id: &str,
        access: AccessOptions,
    ) -> Result<Self, StorageError> {
        let local_hash = match GlobalContractIdentifier::try_from(account_contract) {
            Ok(gci) => {
                let code_hash = gci.clone().hash(state_update, access)?;
                return Ok(RuntimeContractIdentifier::Global { code_hash, identifier: gci });
            }
            Err(ContractIsLocalError::NotDeployed) => return Ok(RuntimeContractIdentifier::None),
            Err(ContractIsLocalError::Deployed(local_hash)) => local_hash,
        };

        if account_id.get_account_type() == AccountType::EthImplicitAccount {
            // Accounts that look like eth implicit accounts and have existed prior to the
            // eth-implicit accounts protocol change (these accounts are discussed in the
            // description of #11606) may have something else deployed to them. Only return
            // something here if the accounts have a wallet contract hash. Otherwise use the
            // regular path to grab the deployed contract.
            if LegacyEthWallet::resolve(local_hash).is_some() {
                // ETH implicit wallet accounts use global contracts, including
                // those created in old protocol versions.
                let global_hash = eth_wallet_global_contract_hash(chain_id);
                return Ok(RuntimeContractIdentifier::Global {
                    code_hash: global_hash,
                    identifier: GlobalContractIdentifier::CodeHash(global_hash),
                });
            }
        }

        Ok(RuntimeContractIdentifier::AccountLocal {
            code_hash: local_hash,
            account_id: account_id.clone(),
        })
    }

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =
            store.get_ref(&key, KeyLookupMode::MemOrFlatOrTrie, access)?.ok_or_else(|| {
                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }
