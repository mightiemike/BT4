### Title
Gas-price oracle consumed for outbound fee/refund accounting without any staleness check on the ChainMeta timestamp - (File: x/uexecutor/keeper/gas_fee.go, x/uexecutor/keeper/outbound.go)

### Summary
The GMX report flags that Chainlink `latestRoundData()` prices are consumed while the `timestamp` return value is discarded, so stale prices silently drive PnL/liquidation logic. Push Chain has a structurally analogous oracle: the `ChainMeta` gas-price oracle (`x/uexecutor/keeper/chain_meta.go`) records a per-vote `StoredAts` timestamp and correctly applies a staleness window (`chainMetaVoteStalenessSeconds = 300`) when *aggregating new votes* into a median [1](#0-0) . However, once a median is written on-chain via `CallUniversalCoreSetChainMeta`, later *consumers* of that stored price never re-check freshness. The `UniversalCore` contract exposes a `timestampObservedAtByChainNamespace` view function precisely for this purpose [2](#0-1) , but this function is never called anywhere in the Go keeper code — it only appears in the ABI definition, with zero call sites in `x/uexecutor/keeper`.

### Finding Description
`GetGasPriceByChain` reads `gasPriceByChainNamespace` from `UniversalCore` with no timestamp check [3](#0-2) . This value feeds `GetOutboundTxGasAndFees`, which is the single source of gas price/gas fee/gas limit used to construct every outbound transaction (relayer payment, gas-token selection, refund sizing) [4](#0-3) . The same stale gas price also underlies `applyGasRefund`, which computes `refundAmount = gasFee - gasFeeUsed` and swaps/deposits it back to the user on both successful and failed outbounds [5](#0-4) .

If the `ChainMeta` oracle stops receiving fresh votes for a given `observed_chain_id` (e.g., all Universal Validators lose RPC connectivity to that external chain, or the chain is temporarily de-configured), `LastAppliedChainHeight` and the on-chain `gasPriceByChainNamespace`/`timestampObservedAtByChainNamespace` values simply freeze at whatever was last written — there is no on-chain or off-chain guard rejecting consumption of an arbitrarily old price. Every ordinary user's outbound-creating transaction (a normal bridge/withdraw call) continues to be priced off that frozen value indefinitely, with no error or fallback.

This differs from the vote-aggregation staleness check, which only protects *how the median is computed while votes are still arriving* — it does nothing to protect *readers of the already-committed value* from consuming data that is arbitrarily out of date once voting activity for that chain ceases.

### Impact Explanation
Stale gas-price data used in `GetOutboundTxGasAndFees` and `applyGasRefund` corrupts gas-fee/refund accounting for every user-triggered outbound and refund path — this squarely matches the "Registry and accounting path" and "corruption of ... gas fee accounting, refund accounting" impact category. A large divergence between the real external-chain gas price and the frozen on-chain value would cause the protocol to either under-collect (protocol/relayer loses funds) or over-collect (user overpays and is under-refunded) gas fees on every outbound transaction routed to the affected chain, with no cap on how stale the value can become. This is reachable purely through ordinary/unprivileged user transactions (any inbound leading to an outbound) — no privileged actor or malicious validator/relayer assumption is required to trigger the *consumption* of the stale value, only an external condition (interrupted validator observation) causing the *feed* to go stale, which is exactly the scenario the referenced report calls out.

### Likelihood Explanation
Likelihood is moderate: it requires the `ChainMeta` vote pipeline for a specific chain to go quiet for an extended period (RPC outage, chain config disabled then re-enabled, chain added but thinly monitored, etc.), which is a plausible operational condition rather than an attacker-crafted one. Because there is no staleness assertion anywhere in the read path (`GetGasPriceByChain`/`GetOutboundTxGasAndFees`/`applyGasRefund`), the bug is silent and would only surface as gradually incorrect fee/refund amounts, matching the "insufficiently validated, no freshness check" pattern in the source report rather than a one-shot exploit.

### Recommendation
Add a staleness check symmetric to the one already used in `x/uexecutor/keeper/chain_meta.go` (`chainMetaVoteStalenessSeconds`) at the *consumption* boundary: call `timestampObservedAtByChainNamespace` (already present in the ABI) from `GetGasPriceByChain`/`GetOutboundTxGasAndFees`, and reject or fall back to a safe default when `block.timestamp - observedAt` exceeds a configured threshold, mirroring the recommendation in the referenced report ("add a staleness threshold ... and ensure the price fetched is within that time range").

### Proof of Concept
Conceptual (no live-network PoC possible from static review):
1. Configure/observe chain `eip155:X` normally; `ChainMeta` bootstraps and `gasPriceByChainNamespace` is written on-chain with `LastAppliedChainHeight = H0`.
2. All Universal Validators stop successfully voting `VoteChainMeta` for `eip155:X` (RPC outage, chain de-prioritized, etc.) — no code path forces re-votes or expires the stored value; `chainMetaVoteStalenessSeconds` only discards stale votes from the *median computation*, it never invalidates the already-committed on-chain price.
3. A user still submits a normal cross-chain transaction with `eip155:X` as the destination. `ExecuteInboundGas...`/outbound-creation flow calls `GetOutboundTxGasAndFees` → `GetGasPriceByChain`, which returns the frozen `H0`-era gas price with no timestamp check [6](#0-5) .
4. The outbound and any subsequent `applyGasRefund` are computed and executed using this arbitrarily stale price, silently under/over-charging gas fees for the user and the relayer/protocol.

**Uncertainty note:** I could not inspect the Solidity source of `UniversalCore` (it lives outside the indexed Go/keeper code, likely as a precompiled/predeployed contract), so I cannot confirm whether `timestampObservedAtByChainNamespace` enforces any staleness internally at the contract level. If the contract itself rejects reads/writes beyond a staleness window, this finding would be neutralized; based on the fully-indexed Go code, however, no such check exists at any call site, and the report should be reviewed against the actual Solidity contract to be certain.

// GetGasPriceByChain reads the gas price for a chain from the UniversalCore contract.
func (k Keeper) GetGasPriceByChain(ctx sdk.Context, chainNamespace string) (*big.Int, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, abi, ueModuleAccAddress, handlerAddr, false, nil, "gasPriceByChainNamespace", chainNamespace)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call gasPriceByChainNamespace")
	}

	results, err := abi.Methods["gasPriceByChainNamespace"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack gasPriceByChainNamespace result")
	}

	return results[0].(*big.Int), nil
}

// to get gasToken, gasFee, protocolFee, gasPrice, and chainNamespace.
// Pass gasLimitWithBaseLimit=0 to use the contract's baseLimit.
func (k Keeper) GetOutboundTxGasAndFees(ctx sdk.Context, prc20 common.Address, gasLimitWithBaseLimit *big.Int) (*GasFeeInfo, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
