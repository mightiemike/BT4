### Title
Auto-Swap `minPCOut` Derived from Manipulable Spot-Price Quote Enables Sandwich Extraction of Gas/Deposit Swap Value - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
The external report's root cause is that a protocol computes a mint/exchange amount from a live, attacker-influenceable balance (`balanceOf(address(this))`) instead of an internally tracked, manipulation-resistant accounting value. Push Chain's native analog is `GetSwapQuote`, which computes the expected swap output for gas-token → PC auto-swaps directly from Uniswap `QuoterV2.quoteExactInputSingle` — an instantaneous pool-price read — and then derives `minPCOut` as a flat 95% of that single quote, with no TWAP or price-deviation safeguard anywhere in the call path.

### Finding Description
`GetSwapQuote` at [1](#0-0)  calls the Uniswap-style Quoter's `quoteExactInputSingle`, which returns an amount computed from the pool's current `sqrtPriceX96`/reserves — a value any unprivileged actor can move by executing swaps against that same pool.

This quote is consumed directly by three independent production flows, all following the same pattern: fetch a spot quote, then compute `minPCOut = quote * 95 / 100` and immediately execute the real swap at that bound:
- `ExecuteInboundGas` (gas-only inbound swap path): [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (gas+payload inbound swap path): [3](#0-2) 
- `applyGasRefund` (unused-gas refund swap-back path): [4](#0-3) 

In each, `minPCOut` is set to 95% of the just-fetched spot quote with `k.CallPRC20DepositAutoSwap(...)` executing the real swap immediately after inside `DerivedEVMCall`, using the on-chain Uniswap pool: [5](#0-4) . There is no TWAP oracle, no cross-reference against `GetGasPriceByChain`/chain-meta gas price, and no deviation cap between the fetched quote and any independent reference price anywhere in this path — confirmed by the absence of any such guard near the swap-quote logic.

An unprivileged attacker who controls sufficient capital relative to the pool's liquidity can push the pool price against the protocol's swap direction in a transaction ordered immediately before the block containing the validator-finalizing `MsgVoteInbound` transaction that triggers this quote+swap sequence, then reverse the price afterward (classic sandwich). Because `minPCOut` is derived from the same manipulated instantaneous price rather than a robust, longer-window reference, the protocol's on-behalf-of-user swap executes at the manipulated price and still satisfies its own slippage floor — the floor moved with the manipulation instead of protecting against it.

### Impact Explanation
This corrupts native/PRC20 asset accounting and gas-fee/refund accounting for ordinary users: a user's inbound gas-token deposit gets swapped into fewer PC tokens than fair value, and the unused-gas refund-with-swap path can similarly under-deliver, with the value difference captured by the attacker via the sandwich. This falls squarely under the in-scope impact of "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting... token mapping" and results in a partial, silent loss of user/protocol-controlled funds on every affected inbound/refund swap, reachable purely through ordinary unprivileged transaction submission on the underlying DEX pool plus a normal user deposit — no privileged or malicious-validator assumption is required.

### Likelihood Explanation
Likelihood is moderate-to-high wherever the underlying Uniswap pool for a given PRC20/gas token has thin liquidity relative to attacker capital, which is plausible for newly onboarded chains/tokens. The 5% slippage band is a large, static target for a sandwich actor to profit within, and the flow triggers automatically on every user-submitted gas-bearing inbound or gas refund — no coordination with validators or governance is needed, only ordinary DEX transactions timed around the known, permissionless quorum-finalization event.

### Recommendation
Replace or supplement the instantaneous `quoteExactInputSingle` spot quote with a manipulation-resistant reference (e.g., a TWAP over a sufficient window, or a cap derived from the independently-tracked chain-meta/gas-price oracle already present in `x/uregistry`), and/or tighten and dynamically adjust the slippage tolerance based on observed pool depth rather than a flat 5%, so `minPCOut` cannot be pinned to an attacker-manipulated price within the same window used to execute the swap.

### Proof of Concept
1. Identify a PRC20/gas-token ↔ WPC Uniswap pool used by `GetUniversalCoreQuoterAddress`/`GetSwapQuote` with modest liquidity.
2. Submit a large swap in the pool to move the spot price against the direction the protocol's forthcoming auto-swap will take.
3. Wait for / ensure a pending inbound (gas or gas+payload) reaches quorum and its `MsgVoteInbound` executes `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` in the same or next block, which calls `GetSwapQuote` (evm.go:500-537) then `CallPRC20DepositAutoSwap` (evm.go:542-593) with `minPCOut` fixed at 95% of the manipulated quote.
4. Reverse the initial swap immediately after the protocol's swap executes, extracting the price-impact spread as profit — the user/protocol received PC (or refunded gas token) at the manipulated, worse rate, all within the flat 5% band that both bounds passed as "valid" slippage.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
