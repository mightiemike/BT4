### Title
Attacker-chosen `isCEA` recipient permanently locks bridged funds with no revert path - (File: `x/uexecutor/keeper/execute_inbound_funds_and_payload.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/handle_failed_inbound_validation.go`)

### Summary
The external report's root cause is "no way to cancel/refund a bridge message once submitted, so fees/funds are permanently unretrievable." Push Chain has largely built an analog mitigation (automatic `INBOUND_REVERT` outbounds on deposit/validation failure, plus the admin escape hatch `MsgRevertStuckInbound`), but this refund path is explicitly and intentionally skipped whenever the inbound is marked `IsCEA` (Contract-Owned External Account / arbitrary recipient path). `IsCEA` and `Recipient` are attacker-controlled fields carried in the `Inbound` observed from the user's own source-chain gateway call, so an ordinary unprivileged user (or a griefer targeting another user's deposit shape) can create an inbound that deterministically fails PRC20 delivery/execution while producing a `UniversalTx` that can never receive a revert outbound and can never be recovered by `RevertStuckInbound` either (since the UTX already exists once the ballot passes).

### Finding Description
`Inbound.ValidateForExecution` at [1](#0-0)  only requires that, when `IsCEA` is true, `Recipient` be a syntactically valid hex address — it performs no check that the recipient is a real UEA, a working contract, or otherwise capable of receiving/executing the call. `IsCEA` and `Recipient` come straight from the observed inbound (i.e., attacker-supplied fields on the source-chain deposit), are only lightly canonicalized in `Canonicalize()` [2](#0-1) , and are never checked at the point of the honest UV vote (only `ValidateBasic`, which doesn't look at `IsCEA`/`Recipient`, is invoked there).

Once the inbound ballot passes (honest validators simply attest to what actually happened on the source chain — an ordinary, protocol-conformant deposit with an attacker-chosen `isCEA=true` and `Recipient` set to, e.g., an address that isn't a deployed UEA and isn't a smart contract with a working `executeUniversalTx`, or one whose `depositPRC20`/`gasAndPayloadDepositAutoSwap` call reverts), the execution keeper enters the `IsCEA` branch:

- In `ExecuteInboundFundsAndPayload`, comment/code explicitly state: *"isCEA failures never create an INBOUND_REVERT outbound."* [3](#0-2) 
- Same pattern in `ExecuteInboundGasAndPayload` [4](#0-3)  and at the post-deposit-failure branch [5](#0-4) .
- Even generic execution-validation failures caught later route through `handleFailedInboundValidation`, which explicitly skips building a revert outbound for `IsCEA` inbounds: *"isCEA failures never create an INBOUND_REVERT outbound (consistent with execute_inbound_funds_and_payload.go)."* [6](#0-5) 

The only remaining recovery mechanism in the codebase, `RevertStuckInbound`/`MsgRevertStuckInbound`, requires (a) the ballot to be `EXPIRED` and (b) **no UniversalTx already existing** for that inbound key [7](#0-6) . In this scenario the ballot already reached `PASSED` (honest validators simply observed and voted on the real deposit) and a `UniversalTx` was already created before hitting the `IsCEA` failure branch — so `RevertStuckInbound` is inapplicable; it errors with "universal tx already exists for this inbound."

Net result: the bridged funds are locked on the source chain (or minted nowhere on Push Chain, if deposit itself failed), the UTX is permanently in a `FAILED` PCTx state with no `OutboundTx` entries, and there is no on-chain path — user-driven or admin-driven — to recover them. This is the direct functional analog of the Kakarot M-03 finding: a message/transaction that cannot be executed successfully has no cancellation/refund mechanism, so the underlying value is permanently lost — except here the amount at risk is the full bridged principal, not merely a fee.

### Impact Explanation
This falls squarely within the allowed impact gate: "permanent loss ... of user or protocol-controlled funds" reachable "from ordinary user deposits ... or default transaction submission paths alone," with honest validators and honest nodes. An unprivileged user (the depositor themselves, by misconfiguring `isCEA`/`recipient`, or by pointing at a contract that later becomes non-functional/reverting between deposit and execution) permanently loses their bridged principal with zero avenue for recovery — neither self-service nor via the documented admin escape hatch, because that hatch's precondition (`ballot EXPIRED`, `no existing UTX`) can never be met once the inbound has already been voted and executed.

### Likelihood Explanation
High. No collusion or privileged access is required — a single ordinary depositor choosing `isCEA=true` with a recipient that is not (or is no longer, e.g. self-destructed/upgraded) a valid UEA/working contract, or whose `depositPRC20`/autoswap call fails for any of several transient/permanent reasons (e.g., invalid token config lookup, EVM call revert), reliably reproduces the stuck state. Honest UVs will still vote and finalize the ballot because they only attest to what happened on the source chain, not whether the destination-side call will succeed.

### Recommendation
- Remove the blanket "isCEA failures never revert" behavior; build an `INBOUND_REVERT` outbound for `IsCEA` deposit/validation/execution failures just as is done for the non-CEA path, refunding to `RevertInstructions.FundRecipient` or the original sender.
- If a design reason exists for the current asymmetry (e.g., avoiding conflicting authority with a contract-controlled recipient), at minimum extend `RevertStuckInbound`'s precondition to also cover "UTX exists but has a FAILED PCTx with no OutboundTx entries and no successful execution," so a manual escape hatch remains available even after the ballot already reached PASSED.
- Add stricter pre-execution or pre-vote validation for `isCEA` deposits (e.g., simulate `executeUniversalTx`/deposit before finalizing an irrevocable state) to reduce the odds of entering the unrecoverable branch at all.

### Proof of Concept
1. Attacker (or an ordinary user) submits a gateway deposit on the source chain of `TxType_FUNDS_AND_PAYLOAD` (or `GAS_AND_PAYLOAD`) with `isCEA = true` and `recipient` set to a syntactically valid hex address that is neither a deployed UEA nor a working smart contract (e.g., a plain EOA with no code, or a contract whose fallback intentionally reverts / has since been destroyed).
2. Honest UVs observe the real deposit and submit `MsgVoteInbound`; quorum is reached, ballot status becomes `PASSED`, and a `UniversalTx` is created with `InboundTx` populated [8](#0-7) .
3. `ExecuteInboundFundsAndPayload` (or `ExecuteInboundGasAndPayload`) runs; because `IsCEA=true`, on any failure in the deposit/execute path, `execErr` is recorded as a `FAILED` PCTx but no revert outbound is attached [9](#0-8) .
4. Attempting the admin escape hatch fails: `RevertStuckInbound` returns `"universal tx ... already exists for this inbound"` because the UTX/ballot already reached a terminal `PASSED` state [10](#0-9) .
5. The bridged funds are permanently unrecoverable: no PRC20 was successfully delivered (deposit failed) or, if delivered but payload execution failed, the funds are locked at an address that has no way to invoke `executeUniversalTx`/further recovery; either way, no `OutboundTx`/refund is ever created for this UTX.

func (k Keeper) RevertStuckInbound(ctx context.Context, inbound types.Inbound) (utxId, outboundId string, err error) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Same canonical form as the vote path, so the admin-supplied payload
	// derives the same ballot key / UTX key the votes did.
	inbound.Canonicalize()

	if vErr := inbound.ValidateBasic(); vErr != nil {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, vErr.Error())
	}

	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, fmt.Sprintf("failed to derive ballot key: %s", err))
	}

	ballot, err := k.uvalidatorKeeper.GetBallot(ctx, ballotKey)
	if err != nil {
		return "", "", errors.Wrap(sdkErrors.ErrNotFound, fmt.Sprintf("ballot for inbound not found (key=%s): %s", ballotKey, err))
	}

	if ballot.Status != uvalidatortypes.BallotStatus_BALLOT_STATUS_EXPIRED {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest,
			fmt.Sprintf("ballot %s status is %s; admin revert requires EXPIRED (use MsgRecomputeBallotQuorum to drive a stuck pending ballot to EXPIRED)",
				ballotKey, ballot.Status.String()))
	}

	universalTxKey := types.GetInboundUniversalTxKey(inbound)
	if has, hErr := k.HasUniversalTx(ctx, universalTxKey); hErr != nil {
		return "", "", fmt.Errorf("failed to check utx existence: %w", hErr)
	} else if has {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest,
			fmt.Sprintf("universal tx %s already exists for this inbound", universalTxKey))
	}

package keeper

import (
	"context"

	sdk "github.com/cosmos/cosmos-sdk/types"
	"github.com/pushchain/push-chain-node/x/uexecutor/types"
	uvalidatortypes "github.com/pushchain/push-chain-node/x/uvalidator/types"
)

func (k Keeper) VoteOnInboundBallot(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	inbound types.Inbound,
) (isFinalized bool,
	isNew bool,
	err error) {
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return false, false, err
	}

	universalValidatorSet, err := k.uvalidatorKeeper.GetEligibleVoters(ctx)
	if err != nil {
		return false, false, err
	}

	// number of validators
	totalValidators := len(universalValidatorSet)

	// votesNeeded = ceil(2/3 * totalValidators)
	// >2/3 quorum similar to tendermint
	votesNeeded := (types.VotesThresholdNumerator*totalValidators)/types.VotesThresholdDenominator + 1

	k.Logger().Debug("voting on inbound ballot",
		"ballot_key", ballotKey,
		"validator", universalValidator.String(),
		"total_validators", totalValidators,
		"votes_needed", votesNeeded,
	)

	// Convert []sdk.ValAddress → []string
	universalValidatorSetStrs := make([]string, len(universalValidatorSet))
	for i, v := range universalValidatorSet {
		universalValidatorSetStrs[i] = v.IdentifyInfo.CoreValidatorAddress
	}

	// Step 2: Call VoteOnBallot for this inbound synthetic
	_, isFinalized, isNew, err = k.uvalidatorKeeper.VoteOnBallot(
		ctx,
		ballotKey,
		uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
		universalValidator.String(),
		uvalidatortypes.VoteResult_VOTE_RESULT_SUCCESS,
		universalValidatorSetStrs,
		int64(votesNeeded),
		int64(types.DefaultExpiryAfterBlocks),
	)
	if err != nil {
		return false, false, err
	}

	if isNew {
		k.Logger().Debug("inbound ballot created", "ballot_key", ballotKey)
	}
	if isFinalized {
		k.Logger().Info("inbound ballot finalized", "ballot_key", ballotKey, "source_chain", inbound.SourceChain)
	}

	return isFinalized, isNew, nil
