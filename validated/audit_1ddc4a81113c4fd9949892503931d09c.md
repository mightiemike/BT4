## Title
`settle-rewards` unconditionally advances a below-threshold signer's reward-settlement snapshot, causing STX-only reward mis-payment - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
In PoX-5, `settle-rewards` is meant to freeze a signer's earned rewards and record the reward-per-token snapshot it was paid up to. When a signer's `signer-shares-staked-for-cycle` is `0` (i.e., the signer is below `SIGNER_SET_MIN_USTX` and not a genuine participant for that cycle's STX-only reward pool), the function correctly skips updating `signer-rewards-per-token-for-cycle` [1](#0-0)  — but it still unconditionally overwrites `signer-rewards-per-token-settled-for-cycle` with the *current* global rate [2](#0-1) . This snapshot mismatch lets a below-threshold signer's un-entitled window get folded into staker payout accounting, letting an unprivileged staker collect (or a co-staker retain) STX-only rewards for a cycle in which their signer never actually qualified for the reward set.

### Finding Description
`settle-rewards` computes `shares`, the global `rewards-per-token`, and `earned` for `(signer, reward-cycle, bond-index)`: [3](#0-2) 

It then does three writes:
1. `signer-unclaimed-rewards-for-cycle := earned` (unconditional)
2. `signer-rewards-per-token-settled-for-cycle := rewards-per-token` (unconditional)
3. `signer-rewards-per-token-for-cycle := rewards-per-token`, but **only if `shares > 0`** [4](#0-3) 

Write #3's guard exists precisely because a signer with `shares == 0` never earned anything and must not have the per-signer reward-per-token curve advanced on its behalf (that curve is what `settle-staker-rewards` later reads to compute individual staker earnings, via `get-signer-rewards-per-token-for-cycle`) [5](#0-4) . But write #2 has no such guard: it moves the "settled" watermark forward for the below-threshold signer regardless. `settle-rewards` is called as a side effect of ordinary, unprivileged staking operations — `add-staker-to-signer-for-cycle` (join) and `remove-staker-from-signer-for-cycle` (leave/unstake) — both of which run `settle-rewards signer cycle none` before mutating share state [6](#0-5) [7](#0-6) , as well as from the reward-claim path (`update-claimable-rewards`/bond-claim flow) which is triggerable by anyone processing rewards for a cycle. Because a below-threshold signer's own membership crossings and any co-claim on an unrelated bond index route through the same `settle-rewards` helper, an attacker (or even an innocuous sequence of unprivileged stake/unstake/claim calls) can force this snapshot to advance for a signer/cycle pair that was never a legitimate member of the STX-only reward set for that cycle, corrupting the bookkeeping used to determine what stakers under that signer are later paid.

This is precisely the scenario captured by the existing regression test in the repo, which documents the corrupted invariant directly in its assertions and comments: [8](#0-7) 

### Impact Explanation
This breaks the equality "a staker's realized reward share must equal `shares * (rewards-per-token at settlement - rewards-per-token at last settlement)` for cycles in which their signer was actually a member of the reward set." Corrupting the settled snapshot for a non-member signer/cycle can let a staker retain or accrue rewards they never earned, i.e., reward mis-payment bounded to the sBTC/STX reward pool for that cycle — matching the "High" impact bucket (reward mis-payment bounded to fees/pool funds) rather than a chain-split, since it does not affect block validity, sortition, or consensus state roots.

### Likelihood Explanation
The trigger requires only unprivileged, ordinary actions: staking below `SIGNER_SET_MIN_USTX`, unstaking, or claiming bond/STX rewards for a cycle — no special key, admin role, or majority collusion is required. Any staker/signer pair that dips below the STX-only membership threshold and participates in the normal stake/unstake/claim lifecycle can trigger the corrupted snapshot, as demonstrated by the existing repo test using entirely standard `stake`, `setupBond`, `registerForBond`, and `claimRewards` calls from ordinary user accounts (`alice`, `bob`, `charlie`) [9](#0-8) .

### Recommendation
Guard the `signer-rewards-per-token-settled-for-cycle` write in `settle-rewards` the same way the `signer-rewards-per-token-for-cycle` write is guarded (i.e., only advance the settled snapshot when `shares > 0`, or otherwise leave it at its prior value / the value at which the signer last had nonzero shares), so that a below-threshold signer's watermark cannot be advanced past a window it was not a real participant in: [10](#0-9) 

### Proof of Concept
The repo already contains a concrete PoC as a unit test: [11](#0-10) 

Steps, unprivileged throughout:
1. `signer1` registers; `bob` registers for a protocol bond under `signer1` with a tiny uSTX backing (below `SIGNER_SET_MIN_USTX`).
2. `alice` STX-only stakes to `signer1` with an amount that, combined with bob's bond uSTX, still keeps `signer1` below `SIGNER_SET_MIN_USTX` for cycle 1 (`isSignerInCycle(signer1, 1) == false`, `getSignerSharesStakedForCycle(signer1,1,none) == 0`).
3. `signer2` (an independent, above-threshold signer) stakes so the global STX-only `rewards-per-token` for cycle 1 actually advances.
4. sBTC funding + `calculateRewards([0])` runs; `signer1`'s STX-only earned remains `0` and `alice`'s earned remains `0` (both correct so far).
5. `claimRewards([0], 1)` is called for the bond — this triggers `settle-rewards` for `signer1`'s STX-only entry (`bond-index: none`) with `shares == 0`, unconditionally advancing `signer-rewards-per-token-settled-for-cycle` for `(signer1, cycle1, none)` to the global rate.
6. The test's final assertion (`getEarnedStakerRewards(alice, 1, null)` must stay `0`) is the witness check for the corrupted snapshot — it is written explicitly to fail on the unfixed code path, per the inline comment "Fails on the unfixed code because the snapshot was advanced past a window signer1 didn't earn in."

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
