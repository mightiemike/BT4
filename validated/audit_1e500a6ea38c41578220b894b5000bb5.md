## Finding: Backup restore accepts `WriteSet`s without verifying them against the proof-committed `state_change_hash` [1](#0-0) 

### Summary
Aptos's transaction-backup restore path deserializes `(Transaction, PersistedAuxiliaryInfo, TransactionInfo, Events, WriteSet)` records from the backup blob, but only the `Transaction`/`Events`/`TransactionInfo` are cryptographically bound to the accumulator proof via `TransactionListWithProofV2::verify`. The `WriteSet` — even though `TransactionInfo` carries a dedicated `state_change_hash` field that is supposed to *commit* to that exact write set — is never checked against it anywhere in the restore/kv-replay pipeline before being written to durable storage and folded into the JellyfishMerkle state.

### Finding Description
In `LoadedChunk::load`, each record is parsed and its `write_set` pushed into a separate `Vec<WriteSet>` [2](#0-1) . The verification call that follows only operates on a `TransactionListWithProofV2` built from `txns`, `event_vecs`, and `TransactionInfoListWithProof` — the `write_sets` vector is completely outside that struct and outside the call: [3](#0-2) 

`TransactionInfoListWithProof::verify` only checks that the hashes of the *provided* `TransactionInfo`s are consistent with the `TransactionAccumulatorRangeProof` and the (waypoint-anchored) `LedgerInfo`: [4](#0-3) 

`TransactionInfo.state_change_hash` is exactly `CryptoHash::hash(write_set)` when the info is originally assembled at execution time: [5](#0-4) 

But nowhere in the restore/kv-replay code path is `CryptoHash::hash(&loaded_write_set) == txn_info.state_change_hash()` re-checked. The kv-only replay path takes these unverified write sets straight into storage: [6](#0-5) 

which calls `RestoreHandler::save_transactions_and_replay_kv`, landing in `save_transactions_impl`, which persists the write set verbatim via `WriteSetDb::put_write_set` and, when `kv_replay` is set, feeds it into `state_store.calculate_state_and_put_updates` to derive the new state root — again with no check against `txn_info.state_checkpoint_hash()`: [7](#0-6) 

Progress markers (`LedgerCommitProgress`, `OverallCommitProgress`) are then advanced unconditionally, treating this unverified data as canonical committed ledger state: [8](#0-7) 

### Impact Explanation
Anyone who can tamper with the backup archive/transport (e.g., a compromised or malicious backup storage backend, CDN, or man-in-the-middle on the backup transfer — a substantially weaker trust assumption than compromising consensus or a validator key) can substitute an arbitrary `WriteSet` for a transaction while leaving its `Transaction`, `Events`, and `TransactionInfo` untouched. Because only those three are checked against the (correctly, waypoint-rooted) accumulator proof, the tampered write set is silently accepted, written to the `WriteSetDb`, and (in `kv_replay` mode) folded into the derived JellyfishMerkle state — producing durable, committed ledger/state data that diverges from the actual VM-executed result, with no error raised anywhere in the pipeline. Any subsequent authenticated state reads or state-value proofs served by that restored node would then authenticate the forged values as if they were the real historical state.

### Likelihood Explanation
This requires control over the backup source (backup storage bucket, mirror, or the transport to it) rather than a validator/consensus compromise, which is a plausible and commonly-discussed threat surface for backup/restore tooling (`storage/backup/backup-cli`). The restore code path is a straightforward, always-taken sequence — no special timing or race condition is needed, unlike the front-running scenario in the external report.

### Recommendation
Before writing any `WriteSet` to storage in `LoadedChunk::load` / `save_transactions_impl` / `save_transactions_and_replay_kv`, verify `CryptoHash::hash(&write_set) == txn_info.state_change_hash()` for every transaction, rejecting the chunk on mismatch, exactly as `TransactionInfo`/`Transaction`/`Events` are already checked against the accumulator proof. Additionally, in `kv_replay`, verify the newly computed state root (`LedgerState`) matches `txn_infos.last().state_checkpoint_hash()` (or the relevant checkpoint's hash) before persisting `LedgerCommitProgress`/`OverallCommitProgress`.

### Proof of Concept
1. Take a legitimate backup transaction chunk (real `Transaction`, `TransactionInfo`, `Events`, accumulator proof, and `LedgerInfoWithSignatures` anchored to a valid waypoint/epoch).
2. Replace the `WriteSet` bytes for one record with an attacker-chosen write set (e.g., crediting an arbitrary account) while leaving `txn_info` (and thus `state_change_hash`) untouched.
3. Point a fullnode/backup-restore operator at this tampered chunk with `--replay-transactions-from-version` and `--kv-only-replay true`.
4. `LoadedChunk::load` parses the record, `txn_list_with_proof.verify(...)` succeeds (it never inspects `write_sets`), and `replay_kv` → `save_transactions_and_replay_kv` → `save_transactions_impl` writes the forged write set to `WriteSetDb` and folds it into the state via `calculate_state_and_put_updates`, advancing `LedgerCommitProgress`/`OverallCommitProgress` with no error — silently corrupting the restored node's durable ledger state under an otherwise "verified" `TransactionInfo`.

    async fn load(
        manifest: TransactionChunk,
        storage: &Arc<dyn BackupStorage>,
        epoch_history: Option<&Arc<EpochHistory>>,
    ) -> Result<Self> {
        let mut file = BufReader::new(storage.open_for_read(&manifest.transactions).await?);
        let mut txns = Vec::new();
        let mut persisted_aux_info = Vec::new();
        let mut txn_infos = Vec::new();
        let mut event_vecs = Vec::new();
        let mut write_sets = Vec::new();

        while let Some(record_bytes) = file.read_record_bytes().await? {
            let (txn, aux_info, txn_info, events, write_set): (
                _,
                PersistedAuxiliaryInfo,
                _,
                _,
                WriteSet,
            ) = match manifest.format {
                TransactionChunkFormat::V0 => {
                    let (txn, txn_info, events, write_set) = bcs::from_bytes(&record_bytes)?;
                    (
                        txn,
                        PersistedAuxiliaryInfo::None,
                        txn_info,
                        events,
                        write_set,
                    )
                },
                TransactionChunkFormat::V1 => bcs::from_bytes(&record_bytes)?,
            };
            txns.push(txn);
            persisted_aux_info.push(aux_info);
            txn_infos.push(txn_info);
            event_vecs.push(events);
            write_sets.push(write_set);
        }

        ensure!(
            manifest.first_version + (txns.len() as Version) == manifest.last_version + 1,
            "Number of items in chunks doesn't match that in manifest. first_version: {}, last_version: {}, items in chunk: {}",
            manifest.first_version,
            manifest.last_version,
            txns.len(),
        );

        let (range_proof, ledger_info) = storage
            .load_bcs_file::<(TransactionAccumulatorRangeProof, LedgerInfoWithSignatures)>(
                &manifest.proof,
            )
            .await?;
        if let Some(epoch_history) = epoch_history {
            epoch_history.verify_ledger_info(&ledger_info)?;
        }

        // make a `TransactionListWithProof` to reuse its verification code.
        let txn_list_with_proof =
            TransactionListWithProofV2::new(TransactionListWithAuxiliaryInfos::new(
                TransactionListWithProof::new(
                    txns,
                    Some(event_vecs),
                    Some(manifest.first_version),
                    TransactionInfoListWithProof::new(range_proof, txn_infos),
                ),
                persisted_aux_info,
            ));
        txn_list_with_proof.verify(ledger_info.ledger_info(), Some(manifest.first_version))?;
        // and disassemble it to get things back.
        let (txn_list_with_proof, persisted_aux_info) = txn_list_with_proof.into_parts();
        let txns = txn_list_with_proof.transactions;
        let range_proof = txn_list_with_proof
            .proof
            .ledger_info_to_transaction_infos_proof;
        let txn_infos = txn_list_with_proof.proof.transaction_infos;
        let event_vecs = txn_list_with_proof.events.expect("unknown to be Some.");

        Ok(Self {
            manifest,
            txns,
            persisted_aux_info,
            txn_infos,
            event_vecs,
            range_proof,
            write_sets,
        })
    }
