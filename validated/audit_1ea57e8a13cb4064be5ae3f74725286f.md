### Title
Starknet OS `execute_replace_class` omits the "class is declared" check enforced by blockifier, allowing execution divergence on `replace_class` — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall lets a contract change its own class hash. In the Rust `blockifier` (the sequencer's actual execution engine), `replace_class` is only permitted if the target class hash is declared — it reads the compiled class first and errors out (`is not declared`) otherwise. The Cairo re-implementation of this same syscall inside the Starknet OS (SNOS, used for re-execution/proving) does **not** perform this check at all — it is marked with an explicit `TODO` acknowledging the gap.

### Finding Description
The blockifier's `replace_class` handler explicitly enforces class declaration before mutating state: [1](#0-0) 
and this is validated in tests (`"is not declared"` error for undeclared class hashes) both for the deprecated and current syscall paths: [2](#0-1) [3](#0-2) 

However, the Starknet OS's own Cairo implementation of `execute_replace_class` (used by the SNOS/prover re-execution path, both cairo1 and deprecated cairo0 flows) performs the state dictionary update unconditionally, with no check that `class_hash` corresponds to a declared class: [4](#0-3) 
The comment on line 902 explicitly states: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The deprecated (cairo0) syscall path has the identical omission: [5](#0-4) 

Because the OS is the component responsible for independently re-executing every transaction to compute the committed contract-class tree and global state root (see `state_update` / `compute_class_commitment` in `state.cairo`), any place where its execution semantics diverge from blockifier's is a real correctness bug, not merely a style nit — an unprivileged contract call is enough to reach it (any contract can invoke `replace_class(class_hash)` with an attacker-chosen, undeclared class hash via a single `INVOKE` transaction).

### Impact Explanation
If a transaction calls `replace_class` with an undeclared class hash:
- Blockifier (real sequencer execution) rejects it — `get_compiled_class` returns `StateError::UndeclaredClassHash`, causing the call/transaction to fail or revert.
- The Starknet OS's Cairo implementation performs no such check and unconditionally writes the new (possibly bogus/undeclared) class hash into `contract_state_changes`, which subsequently feeds into `compute_contract_state_commitment` and the global state root computation.

This produces execution/state divergence between the sequencer's block execution and the OS's independent re-execution/proof generation for the same block — i.e., a wrong committed root relative to what blockifier actually computed, or an inability for the OS to reproduce the sequencer's committed state (honest-node divergence at the OS/proof layer). Given state root correctness underlies the entire L2→L1 finality/proof pipeline, this qualifies as High severity under the given scope (wrong committed root / honest-node divergence).

### Likelihood Explanation
High likelihood of reachability: `replace_class` is a standard permissionless syscall callable by any contract via any `INVOKE` transaction with attacker-controlled `class_hash` argument (as demonstrated in existing test helpers `test_replace_class`). No special privilege, proposer, or operator access is required — an ordinary user transaction triggers the syscall path in both blockifier and, upon proving/re-execution, the OS.

### Recommendation
Add the same "class is declared" verification in the Cairo OS implementation of `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` path) that blockifier performs — i.e., before writing the new state entry, assert that `class_hash` exists in `contract_class_changes` (or is otherwise proven declared), mirroring the Rust `get_compiled_class(request.class_hash)?` check, and resolve the outstanding `TODO(Yoni, 1/1/2026)` comment.

### Proof of Concept
1. Deploy any contract `A` with an `__execute__`/entry point that calls the `replace_class` syscall with an arbitrary, never-declared `class_hash` value (as in `test_replace_class` in `blockifier_test_utils/resources/feature_contracts/cairo0/test_contract.cairo`, lines 319-323, and `cairo1/test_contract.cairo`).
2. Submit an `INVOKE` transaction from an unprivileged account calling this entry point with an undeclared `class_hash`.
3. In blockifier, this call fails with `"... is not declared"` (see `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs` lines 17-29).
4. When the Starknet OS re-executes the equivalent Cairo syscall trace via `execute_replace_class` (`syscall_impls.cairo` lines 881-920), no declaration check is performed, so if this code path is ever reached independent of, or inconsistently with, the blockifier's guard (e.g., due to any future decoupling of OS execution from blockifier-validated traces, or a bug allowing the hint-provided state entry to diverge), the OS would commit a state update inconsistent with the sequencer's actual execution, corrupting the contract-class/state commitment trees.

*Note: I could not fully verify whether current OS driving code strictly forces the same failure path as blockifier before reaching `execute_replace_class` (e.g., via prior hint-level validation) — the search for `is_declared`/`UndeclaredClassHash` patterns in the `.cairo` sources found no matches, suggesting no additional declared-check exists elsewhere in the OS Cairo code for this syscall. This should be confirmed with deeper tracing of how `LoadClassesAndBuildBytecodeSegmentStructures` and the `contract_class_changes` dict are populated/validated relative to `GetContractAddressStateEntry`, which the available indexed context did not fully resolve.*

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
