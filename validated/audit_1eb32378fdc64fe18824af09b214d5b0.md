### Title
GAS-abstraction and gas-refund auto-swaps derive `minPCOut` from a manipulable spot-price quote, not a protected reference price - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Every autoswap performed by the `uexecutor` module (GAS inbound processing, GAS_AND_PAYLOAD inbound processing, and excess-gas refunds on outbound finalization) computes its slippage floor as `minPCOut = quote * 95 / 100`, where `quote` comes from `Keeper.GetSwapQuote`, a live call to Uniswap V3 `QuoterV2.quoteExactInputSingle` against the current pool state [1](#0-0) . This is structurally identical to the referenced Curve finding: the "expected" amount is fetched from the AMM itself at the moment of execution, so it already reflects whatever price the pool currently exposes — including a price an attacker manipulated moments earlier. Subtracting a fixed 5% from that already-corrupted number gives no protection against price manipulation, only a fixed discount on top of it.

### Finding Description
The GAS inbound flow fetches a quote and immediately computes the slippage floor from it in the same call chain: `GetSwapQuote` → `minPCOut = quote*95/100` → `CallPRC20DepositAutoSwap` [2](#0-1) . The identical pattern is used for GAS_AND_PAYLOAD inbounds [3](#0-2)  and for excess-gas refunds on outbound finalization [4](#0-3) .

All three call sites are reached automatically once honest validators finalize a ballot for an unprivileged user's ordinary deposit — this is triggered by `VoteInbound` → `ExecuteInbound` → `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` [5](#0-4) [6](#0-5) , and for outbounds via `handleSuccessfulOutbound`/`handleFailedOutbound` → `applyGasRefund` [7](#0-6) .

Because the quote and the swap execution both read the same live, unprotected Uniswap V3 pool state, an unprivileged attacker can:
1. Submit an ordinary bridging deposit (GAS or GAS_AND_PAYLOAD) that will trigger the module's auto-swap of a PRC20 gas token into WPC/PC.
2. In a prior or same-block transaction, cheaply move the price of the relevant PRC20/WPC pool (these are newly-listed, often thin-liquidity pools) via a normal swap — no special privilege required, just capital and pool access.
3. When the validator vote finalizes and `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` runs, `GetSwapQuote` returns the manipulated price, and `minPCOut` is only 5% below that already-bad price, so `CallPRC20DepositAutoSwap` still succeeds while returning far less PC/WPC than a fair market rate would produce.

The same logic drives `applyGasRefund`'s `getSwapQuoteForRefund` / `CallUniversalCoreRefundUnusedGas` refund path, so excess-gas refunds are equally exposed.

### Impact Explanation
The module (acting on behalf of users) swaps user-deposited PRC20 gas tokens for PC/WPC, and separately swaps refund tokens back to PC. Both operations move protocol-mediated user funds through an AMM whose spot price is directly manipulable by an unprivileged actor. Since the slippage floor is derived from the very price that was manipulated, the check provides essentially no economic protection beyond a flat 5% haircut, allowing value extraction from users/protocol beyond what a fair execution would yield — this falls under "corruption of ... gas fee accounting, refund accounting ... token mapping" and "unauthorized ... state transitions in universal execution flows" from the in-scope impact list, since ordinary user deposits/refunds alone (combined with unprivileged pool manipulation) can be steered into an unfair, attacker-favorable settlement.

### Likelihood Explanation
Reachable purely through unprivileged user actions: any address can submit a normal cross-chain deposit that hits the GAS-abstraction code path, and any address can perform a swap against the same underlying Uniswap V3 pool to move its price beforehand. No validator, relayer, or admin collusion is needed. Newly bridged PRC20 tokens are especially likely to have thin liquidity, making manipulation cheap. The likelihood is bounded only by pool liquidity/attacker capital, not by any protocol-level control.

### Recommendation
Do not derive the slippage floor solely from a same-block/time spot quote of the same pool being swapped against. Use a manipulation-resistant reference price instead, e.g.:
- Use a TWAP (time-weighted average price) from the Uniswap V3 pool observation buffer rather than `quoteExactInputSingle`'s instantaneous quote, with a sanity bound against the spot price.
- Or source an independent reference price (e.g., a validated oracle) to compute `minPCOut`, and treat the QuoterV2 quote only as an execution-path check, not as the basis of the slippage floor.
- Enforce a maximum allowed deviation between the reference price and the pool's instantaneous price before allowing the auto-swap to proceed, otherwise skip the swap/fallback to direct PRC20 deposit as already implemented for the failure path.

### Proof of Concept
1. Attacker identifies a newly configured PRC20↔WPC Uniswap V3 pool with modest liquidity (created for a newly onboarded chain/token).
2. Attacker submits a large swap into/out of that pool in a transaction ordered immediately before the validator's finalizing `MsgVoteInbound` (or in the block right before quorum is reached), pushing the pool's spot price to an unfavorable rate for the upcoming auto-swap.
3. A victim's ordinary GAS inbound (or GAS_AND_PAYLOAD inbound) reaches ballot quorum; `ExecuteInboundGas` calls `GetSwapQuote` [1](#0-0) , which returns the manipulated price.
4. `minPCOut := quote*95/100` [8](#0-7)  is computed from this manipulated quote and passed to `CallPRC20DepositAutoSwap`, which executes successfully at the bad rate since the "protection" check never referenced an undistorted price.
5. Attacker reverses their price-moving position afterward (e.g., in the same or next block), realizing the difference at the expense of the protocol/deposit value routed through the swap.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

func (k Keeper) handleSuccessfulOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {

		"utx_id", utxId,

}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}
