### Title
Starknet OS `execute_replace_class` accepts a `replace_class` syscall for an undeclared class hash — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
In the Cairo Starknet OS program, the `execute_replace_class` function updates a contract's `class_hash` in `contract_state_changes` for the `replace_class` syscall without ever validating that the supplied `class_hash` corresponds to a declared class, unlike the blockifier's Rust implementation of the same syscall, which explicitly checks declaration and Cairo version before mutating state.

This mirrors the reported bug class exactly: a validity precondition ("symbol/class must be valid/declared") that is enforced on one code path but silently skipped on a structurally similar path that reuses the same state-mutation logic (here, the Starknet OS's Cairo re-execution of the same transaction that the blockifier already executed on-chain).

### Impact Explanation
The Starknet OS is the component that re-executes every block's transactions inside the STARK-provable Cairo program to produce the state commitment/root that is ultimately submitted on L1. If the OS's `execute_replace_class` accepts an undeclared (or wrong-version) class hash where the blockifier would have rejected it, the OS's computed state transition (and thus the state root / block hash it commits to) can diverge from the sequencer's actual execution result produced by the blockifier. This is exactly the kind of "wrong committed root" / "honest-node divergence" impact called out as in-scope: the OS is meant to be a faithful re-execution of the blockifier's semantics, and any semantic gap between the two is a soundness bug in the proving pipeline, potentially allowing a contract to end up pointing at storage/state entries backed by a nonexistent (undeclared) compiled class in the proven state, or causing the OS to produce output inconsistent with the blockifier-computed state diff for the same block.

### Likelihood Explanation
Reachability requires only a single unprivileged contract call: any contract executing `replace_class_syscall(class_hash)` with an undeclared `class_hash` (or, depending on further validation elsewhere, a Cairo0 class hash) triggers this code path inside the OS's per-transaction re-execution, exactly mirroring how a normal user transaction reaches `PartyBFacetImpl` child-quote creation in the original report without any privileged actor involved. Since `contract_state_changes` StateEntry.class_hash values are trusted for constructing execution contexts (e.g., `update_class_hash_in_execution_context`) for subsequent calls to that contract, an undeclared class hash written here could also cause the OS to be unable to locate the corresponding compiled class fact when later attempting to execute that contract, producing an inconsistency between the OS's guessed/loaded compiled classes and the actual state.

### Recommendation
Add an explicit check in `execute_replace_class` (Cairo) that a compiled-class fact exists for `class_hash` (and, to match blockifier semantics, that it is a Cairo1/V1 class) before performing the `dict_update` on `contract_state_changes`, mirroring the `state.get_compiled_class(class_hash)?` / `is_cairo1` checks already present in `crates/blockifier/src/execution/syscalls/syscall_base.rs`. This closes the semantic gap between the blockifier and the OS's re-execution and prevents divergence in the committed state root.

### Proof of Concept
1. In a transaction, invoke a contract's `test_replace_class` entry point (present in `blockifier_test_utils` feature contracts) with a `class_hash` for a class that was never declared.
2. In the actual sequencer (blockifier) execution, this correctly fails with "is not declared" as shown in the existing test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`.
3. When the same transaction/block is re-executed by the Starknet OS (`execute_replace_class` in `syscall_impls.cairo`), no such rejection occurs — the OS only pulls a `StateEntry` via the `GetContractAddressStateEntry` hint and writes the new (unchecked) `class_hash` into `contract_state_changes`, per the code cited above. This is a direct semantic difference between the two independently-maintained implementations of the identical syscall, matching the pattern flagged in the source report (validity check present at one entry point, absent on a structurally equivalent path that mutates the same state).

Note: I could not fully trace whether some other, later stage of OS execution (e.g., `validate_compiled_class_facts`) would incidentally catch this by failing to find a compiled-class fact for the bogus class hash when the contract is next invoked; this would need to be verified by running the OS test suite against a `replace_class` call with an undeclared class hash, which requires code execution I do not have access to in this ask-only session.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
