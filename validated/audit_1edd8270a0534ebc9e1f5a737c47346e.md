## Title
`TransactionOutput::ensure_match_transaction_info` omits state/hot-state/position checkpoint hash verification, allowing `replay_on_archive` to certify a corrupted or divergent ledger state as valid — (File: `types/src/transaction/mod.rs`)

## Summary
`TransactionOutput::ensure_match_transaction_info`, the function used by the offline replay-verification tooling to check that locally re-executed transaction outputs match archived, ledger-accumulator-authenticated `TransactionInfo` records, only compares status, gas, write-set hash and event-root hash. It never compares `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`. This is a self-acknowledged gap in the code, and it means the tool can report a "successful" verification of an archive whose committed state/position roots do not match what local execution actually produces.

## Finding Description
`ensure_match_transaction_info` is the authoritative comparator between a freshly-executed `TransactionOutput` and the `TransactionInfo` retrieved from a backup/archive (itself proven against a signed `LedgerInfo`). It checks:
- `status`
- `gas_used`
- `write_set` hash vs `txn_info.state_change_hash()`
- event root hash vs `txn_info.event_root_hash()` [1](#0-0) 

It explicitly does **not** check the checkpoint hashes that were added with `TransactionInfoV1` (`state_checkpoint_hash`, `hot_state_checkpoint_hash`, `position_state_checkpoint_hash`), and the code says so directly: [2](#0-1) 

This function is the sole correctness check used by `storage/db-tool/src/replay_on_archive.rs`'s `Verifier::execute_and_verify`, which re-executes transactions read from a backup archive via `AptosVMBlockExecutor::execute_block` and calls `ensure_match_transaction_info` directly on the raw `BlockOutput` — it never routes through `DoStateCheckpoint` (the component that actually computes and checks `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` against known values during normal block/chunk execution): [3](#0-2) 

By contrast, in the normal chunk-executor commit path, `DoStateCheckpoint::run` does compute and validate these checkpoint hashes (`get_state_checkpoint_hashes`, `compute_position_checkpoint`) against `known_state_checkpoints`/`known_position_state_checkpoints` derived from the trusted `TransactionInfo`s: [4](#0-3) 

So the checkpoint-root binding is enforced during consensus/state-sync replay, but the *offline archive replay-verification tool* (used to independently audit historical mainnet data, including the trading-native/position feature once `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled) has no such check. `AptosCli`'s single-transaction replay path (`aptos-move/cli/src/commands.rs`) uses the same weak comparator.

## Impact Explanation
This breaks the "authenticated API/proof-bearing response must stay bound to the right ledger version, root, and object" invariant for the specific verification tool designed to catch exactly this class of corruption. If an archived `TransactionInfo` (or the DB it was derived from) has a `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` that diverges from what correct re-execution computes — whether due to a storage bug, DB corruption, an execution non-determinism bug in the position/state-checkpoint path, or a malicious archive provider — `replay_on_archive`/`replay-verify` will still report success, because the divergent field is simply never inspected. This directly undermines the guarantee that "committed state that differs from the correct VM result... must be caught during replay," which is precisely the class of impact requested (hard-fork-only divergence during replay/proof verification going undetected). Given `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/native-position is a newly introduced subsystem in this codebase, undetected divergence in `position_state_checkpoint_hash` is the most concrete manifestation.

## Likelihood Explanation
This is not a hypothetical edge case — the gap is baked into the primary code path of the replay-verification tool, is deterministic (always skipped, not race-dependent), and is called out by name in a code comment as a known, un-remediated omission ("Validate the checkpoint hashes here before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`"). Any operator running `replay_on_archive`/`replay-verify` against an archive today would fail to detect a checkpoint-root divergence, including one in the trading-native/position subsystem this repository is actively integrating.

## Recommendation
Extend `ensure_match_transaction_info` to recompute and compare `state_checkpoint_hash`, `hot_state_checkpoint_hash` (when populated), and `position_state_checkpoint_hash` (when populated) against the values carried in `txn_info` (via `TransactionInfo::state_checkpoint_hash()`/`hot_state_checkpoint_hash()`/`position_state_checkpoint_hash()`), or otherwise route `replay_on_archive`/CLI replay through the same `DoStateCheckpoint` logic used by the chunk executor so checkpoint roots are always independently re-derived and checked before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (or `HOT_STATE_ROOT_IN_TXN_INFO`) is enabled on mainnet.

## Proof of Concept
1. Enable `TRANSACTION_INFO_V1` and `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (plus `HOTNESS_IN_EPILOGUE`) so `TransactionInfoV1::position_state_checkpoint_hash` is populated in the ledger.
2. Introduce (or simulate, for the PoC) a divergence between the persisted `position_state_checkpoint_hash` in an archived `TransactionInfo` and what local re-execution of the same transaction actually computes (e.g., due to a storage bug in `position_summary_at_commit` at [5](#0-4)  producing a different tree than execution-time `compute_position_checkpoint`).
3. Run `storage/db-tool/src/replay_on_archive.rs`'s `Verifier::verify` against that archive; `execute_and_verify` calls `ensure_match_transaction_info` at [6](#0-5) , which never inspects `position_state_checkpoint_hash`, so the mismatch is silently ignored and the tool reports the archive as verified/consistent despite the actual position (or hot-state/state) root diverging from the authenticated ledger data.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

    /// Computes the position summary at commit time by extending the in-memory
    /// tip with this chunk's position writes, freezing on the persisted base.
    /// Used only when `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is off (otherwise the
    /// summary comes from execution on the chunk).
    fn position_summary_at_commit(
        &self,
        chunk: &ChunkToCommit,
    ) -> Result<PositionLedgerStateWithSummary> {
        let bundle = self
            .position
            .as_ref()
            .expect("called only when position is present");
        let store = bundle
            .state_store
            .as_ref()
            .expect("called only when state_store is present");
        let persisted_base = bundle
            .persisted
            .as_ref()
            .expect("persisted present when state_store is")
            .get();

        let (mut latest, mut last_checkpoint) = {
            let state = store.current_state();
            let current = state.lock();
            (current.latest().clone(), current.last_checkpoint().clone())
        };

        let chunk_first = chunk.first_version;
        let chunk_last_inclusive = chunk_first + chunk.transaction_outputs.len() as Version - 1;
        let checkpoint_within_chunk = chunk
            .state
            .last_checkpoint()
            .version()
            .filter(|v| (chunk_first..=chunk_last_inclusive).contains(v));

        let mut pending: HashMap<HashValue, PositionSlot> = HashMap::new();
        let extend_on_base = |latest: &PositionStateWithSummary,
                              version: Version,
                              updates: Vec<(HashValue, PositionSlot)>|
         -> Result<PositionStateWithSummary> {
            let proof_reader = PositionProofReader {
                merkle_db: bundle.merkle_db.clone(),
                version: persisted_base.version(),
            };
            latest.extend(version, updates, persisted_base.summary(), &proof_reader)
        };

        for (i, output) in chunk.transaction_outputs.iter().enumerate() {
            let version = chunk_first + i as Version;
            for (key, op) in output.write_set().native_position_iter() {
                let value_hash = op.as_write_op().as_state_value_opt().map(CryptoHash::hash);
                pending.insert(key.hash(), PositionSlot {
                    state_key: key.clone(),
                    value_hash,
                    value: None,
                });
            }
            if Some(version) == checkpoint_within_chunk && !pending.is_empty() {
                let updates: Vec<_> = std::mem::take(&mut pending).into_iter().collect();
                latest = extend_on_base(&latest, version, updates)?;
                last_checkpoint = latest.clone();
            }
        }
        if !pending.is_empty() {
            let updates: Vec<_> = pending.into_iter().collect();
            latest = extend_on_base(&latest, chunk_last_inclusive, updates)?;
        }

        Ok(
            PositionLedgerStateWithSummary::from_latest_and_last_checkpoint(
                latest,
                last_checkpoint,
            ),
        )
    }
