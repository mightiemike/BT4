### Title
Unbounded recursion in `sort_json_value` when computing the hinted class hash of a declared Cairo‑0 (deprecated) contract class - (File: `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs`)

### Summary
`compute_cairo_hinted_class_hash` / `compute_deprecated_class_hash`, used by the Starknet OS to (re‑)derive the class hash of a Cairo‑0 contract declared via a `DECLARE` transaction, calls `sort_json_value` to canonicalize the untyped `abi`, `program.identifiers`, `program.reference_manager`, and `program.hints` JSON blobs before hashing. [1](#0-0) 
`sort_json_value` recurses once per level of JSON nesting with no depth bound, mirroring the class of bug in CVE‑2019‑13103 (unbounded recursion driven entirely by attacker‑supplied structure depth, not by a resource metric the runtime tracks). [2](#0-1) 

### Finding Description
`CairoContractDefinition`/`CairoProgram` deliberately model `abi`, `program.identifiers`, `program.reference_manager`, and each entry of `program.hints` as raw `serde_json::Value` because their shape is not fixed by the protocol. [3](#0-2) 
Any contract declarer fully controls the content of the program JSON that becomes the class body for a Cairo‑0 (`DECLARE V0/V1`) transaction. Because these fields accept arbitrary JSON, a declarer can nest arrays/objects (e.g. `[[[[...]]]]`) to essentially any depth allowed by the JSON text length.

`compute_cairo_hinted_class_hash` runs `sort_json_value` over the entire serialized contract value before hashing it:
```
let contract_value = serde_json::to_value(contract_class)?;
let sorted_contract_value = sort_json_value(contract_value);
``` [4](#0-3) 
`sort_json_value` itself recurses into every nested `Object`/`Array` with no depth limit and no iterative fallback: [5](#0-4) 

`compute_deprecated_class_hash` (which computes the actual compiled-class hash, consumed by the OS's `SetComponentHashes` hint in `execute_declare_transaction`, and by `try_declare` flows more generally when Cairo0 classes are (re)hashed) itself calls `compute_cairo_hinted_class_hash` first, so it inherits the same unbounded recursion. [6](#0-5) 

This is analogous to CVE‑2019‑13103: a self‑referential/deeply-nested structure supplied by an untrusted party (there, a DOS partition table; here, a declared class's JSON program) drives a recursive parser with no depth cap, exhausting the call stack.

### Impact Explanation
A crafted Cairo‑0 `DECLARE` transaction with deeply nested JSON in `abi`, `program.identifiers`, `program.reference_manager`, or `program.hints` can cause `sort_json_value` to recurse until the stack is exhausted, crashing (or corrupting) the process that performs this computation — the Starknet OS/re‑execution path and any node deriving/verifying the deprecated class hash. Because the OS's per‑class-hash computation feeds into `finalize_class_hash`/`SetComponentHashes`, which is asserted against the transaction's declared `class_hash`, a stack overflow here on a validating/proving/re‑executing node can crash that node or cause honest-node divergence between nodes that succeed to parse (e.g. with larger stack limits) vs. those that crash, potentially halting block production/proving for the affected class or causing a network unable to confirm new transactions if the crash occurs during required OS re-execution.

### Likelihood Explanation
Likelihood is High for a single unprivileged sender: submitting a Cairo‑0 declare transaction with an oversized/deeply-nested JSON `program`/`abi` field requires no special privileges, no fee bypass and no cooperation from operators — it is a normal transaction constructed by any account. The only mitigations that could reduce likelihood are size limits on the class enforced elsewhere in the gateway (`validate_class_length` was observed only for Sierra/RPC declare paths, not confirmed for the legacy Cairo‑0 JSON body), so the exact bound on program size for Cairo‑0 declares was not fully confirmed in this review.

### Recommendation
Rewrite `sort_json_value` (and any other recursive JSON canonicalizer touching untrusted declared-class content) as an explicit iterative traversal using a work-stack, or enforce a hard recursion/nesting depth limit before recursing, rejecting the class with a validation error instead of overflowing the stack. Apply the same safeguard to any other recursive traversal of user-controlled `serde_json::Value` trees in the declare/class-hash path.

### Proof of Concept
1. Construct a Cairo‑0 contract class JSON body where the `abi` (or `program.identifiers` / `program.reference_manager` / a `program.hints` entry) is a deeply nested JSON array, e.g. `["a", ["a", ["a", ... N times ... ]]]` with N large enough to exceed the thread's stack size when each level allocates a `sort_json_value` stack frame.
2. Submit this class as the contract class of a `DECLARE` (V0/V1) transaction.
3. When a node computes/re-verifies the hinted class hash via `compute_cairo_hinted_class_hash`/`compute_deprecated_class_hash` (e.g. during OS re-execution or class-hash validation), `sort_json_value` recurses N times and overflows the stack, crashing the process.

Note: I could not fully confirm within this review whether the gateway enforces an early, tight upper bound on the raw Cairo‑0 `program`/`abi` JSON size/depth that would prevent reaching a sufficient nesting depth before this code path is reached; this should be verified against `apollo_gateway`'s stateless validation for legacy (`DeclareV1Transaction`) bodies specifically.

/// Recursively sorts all JSON objects by their keys.
/// This ensures deterministic serialization regardless of the `preserve_order` feature in
/// serde_json.
fn sort_json_value(value: serde_json::Value) -> serde_json::Value {
    match value {
        serde_json::Value::Object(map) => {
            let sorted: BTreeMap<String, serde_json::Value> =
                map.into_iter().map(|(k, v)| (k, sort_json_value(v))).collect();
            serde_json::Value::Object(sorted.into_iter().collect())
        }
        serde_json::Value::Array(arr) => {
            serde_json::Value::Array(arr.into_iter().map(sort_json_value).collect())
        }
        other => other,
    }
}

pub fn compute_cairo_hinted_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    // Serialize to Value, sort all objects by keys for deterministic output, then to bytes.
    // The sorting is necessary because serde_json with `preserve_order` feature enabled
    // maintains insertion order instead of sorting keys.
    // TODO(Meshi): Compute hinted hashes when loading serialized contracts from storage, before
    // deserializing, to avoid back-and-forth serde.
    let contract_value = serde_json::to_value(contract_class)?;
    let sorted_contract_value = sort_json_value(contract_value);
    let contract_definition_vec = serde_json::to_vec(&sorted_contract_value)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let mut string_buffer = vec![];

    let mut ser = serde_json::Serializer::with_formatter(&mut string_buffer, PythonJsonFormatter);
    contract_definition.serialize(&mut ser)?;

    let mut raw_json_output = String::from_utf8(string_buffer)?;
    if contract_definition.program.compiler_version.is_none() {
        add_backward_compatibility_space(&mut raw_json_output);
    }

    let mut keccak_writer = KeccakWriter::default();
    keccak_writer
        .write_all(raw_json_output.as_bytes())
        .expect("writing to KeccakWriter never fails");

    let KeccakWriter(hash) = keccak_writer;
    Ok(truncated_keccak(<[u8; 32]>::from(hash.finalize())))
}

pub fn compute_deprecated_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    let hinted_class_hash = compute_cairo_hinted_class_hash(contract_class)?;
    let contract_definition_vec = serde_json::to_vec(contract_class)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let FlatEntryPointFelts { external, l1_handler, constructor } =
        get_flat_entry_point_felts(&contract_definition.entry_points_by_type);
    let builtins = ascii_strs_as_felts(&contract_definition.program.builtins);
    let bytecode = hex_strs_as_felts(&contract_definition.program.data);

    let mut hash_state = HashState::<Pedersen>::new();
    hash_state.update_single(&DEPRECATED_COMPILED_CLASS_VERSION);
    hash_state.update_with_hashchain(&external);
    hash_state.update_with_hashchain(&l1_handler);
    hash_state.update_with_hashchain(&constructor);
    hash_state.update_with_hashchain(&builtins);
    hash_state.update_single(&hinted_class_hash);
    hash_state.update_with_hashchain(&bytecode);
    Ok(hash_state.finalize())
}
