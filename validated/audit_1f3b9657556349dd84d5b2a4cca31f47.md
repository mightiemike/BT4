### Title
Zero-share `settle-rewards` snapshot advance lets stakers of a below-threshold signer claim phantom STX-only rewards for a cycle they never joined - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`pox-5.clar`'s bond-claim path calls a per-cycle `settle-rewards` routine that advances the global STX-only `rewards-per-token-for-cycle` snapshot for a signer, even when that signer's staked shares for the cycle are `u0` because the signer never crossed `SIGNER_SET_MIN_USTX` and was therefore never included in the reward/signer set for that cycle. This lets STX-only stakers who staked under that non-participating signer later claim non-zero rewards for a cycle in which their signer earned nothing and was not a member of the active signer set, breaking the invariant "a staker's claimable reward reflects a signer/cycle window the signer actually earned in."

### Finding Description
`pox-5.clar` tracks staking rewards per signer/cycle via `signer-rewards-per-token-for-cycle`, gated by `get-total-shares-staked-for-cycle` [1](#0-0) . Signer membership and voting/reward weight for a reward cycle is computed from staked uSTX against a `SIGNER_SET_MIN_USTX`-derived threshold, analogous to `pox_5_make_signer_set` in `stackslib/src/chainstate/nakamoto/signer_set.rs` which apportions `weight` from `stacked_amt / threshold` and drops any signer whose weight floors to `0` [2](#0-1) . When a signer's STX-only staked amount stays below this admission threshold for a cycle (i.e., it is not a member of that cycle's signer set), a bond-claim on a different bond index still triggers `settle-rewards` for that signer's STX-only cycle bucket with `shares == 0`. The regression test in this repo's Clarity test-suite demonstrates exactly this: signer1 never crosses `SIGNER_SET_MIN_USTX` for cycle 1 (`isSignerInCycle({signer: signer1, cycle: 1n})` is `false`, and `getSignerSharesStakedForCycle(signer1, 1n, null)` is `0n`), yet triggering `testSigner.claimRewards([0n], 1n)` on the bond causes `settle-rewards` to run on signer1's STX-only cycle-1 bucket with `shares = 0` and advances/corrupts `signer-rewards-per-token-for-cycle` for that signer/cycle, after which Alice (a staker under signer1) becomes eligible for STX-only rewards for a cycle her signer never participated in [3](#0-2) .

The root cause mirrors the LPFarming report's bug class but manifests as a wrong-party payment rather than a locked balance: an epoch/cycle boundary condition (zero participants/shares at settlement time) is not special-cased, so the accounting function silently treats a "before-participation" state as if it were a valid reward-earning window, and downstream reward math (`get-earned`, staker reward claims) uses that corrupted snapshot to credit a party that broke no equality of actual participation.

### Impact Explanation
This is a reward mis-payment bounded to the funds circulating through `pox-5`'s reward-per-token accounting: an attacker-controlled staker set can cause STX-only rewards, meant only for cycles/signers that actually met the participation threshold, to be paid to stakers under a signer that never joined the reward set for that cycle. This falls under the "High" bucket defined by the rules: a reward mis-payment bounded to the pool's funds, triggered without needing majority control, admin privileges, or another party's key — any user staking under an under-threshold signer combined with any other user's bond claim on the same signer index can trigger it.

### Likelihood Explanation
Reachable by a single, unprivileged actor: stake a small amount to a signer that will not cross `SIGNER_SET_MIN_USTX` for a cycle, then claim rewards on any bond associated with that signer (`testSigner.claimRewards`) once the cycle closes. No majority of stakers or signers is required, and no admin/owner action is needed — this matches the "minority-triggerable, unprivileged" scope requirement.

### Recommendation
In the `settle-rewards`/bond-claim path of `pox-5.clar`, skip (or no-op) the STX-only rewards-per-token snapshot advance for a signer/cycle bucket whenever `get-total-shares-staked-for-cycle` for that signer/cycle is `u0`, i.e., only advance `signer-rewards-per-token-for-cycle` for signer/cycle pairs where the signer was actually part of the reward/signer set (had nonzero admitted weight) for that cycle. Any surplus that would have gone to that phantom bucket should instead route to the reserve, consistent with how `calculate-rewards` already folds unallocated staker cuts into the reserve when `cycle-staked-ustx` is `u0` [4](#0-3) .

### Proof of Concept
The existing regression test in this repo already reproduces the issue end-to-end and asserts the (currently failing without a fix) invariant: [5](#0-4) 

1. Register `signer1` and `signer2`; set up bond 0 with `bob` as the sole participant under `signer1`, sized so `signer1`'s bonded uSTX alone is far below `SIGNER_SET_MIN_USTX`.
2. Have `alice` stake STX-only under `signer1`, sized so `alice`'s stake plus `bob`'s bond uSTX together still stay below `SIGNER_SET_MIN_USTX` — confirmed via `expect(aliceStake + bobBondUstx).toBeLessThan(pox5.constants.SIGNER_SET_MIN_USTX)`.
3. Have `charlie` stake enough STX-only under `signer2` to push the global STX-only rewards-per-token for cycle 1 to advance.
4. Confirm pre-conditions: `isSignerInCycle({signer: signer1, cycle: 1n})` is `false`, `getSignerSharesStakedForCycle(signer1, 1n, null)` is `0n`.
5. Fund and run `calculateRewards`, then call `testSigner.claimRewards([0n], 1n)` to trigger bond 0's claim, which runs `settle-rewards` on `signer1`'s STX-only cycle-1 bucket with `shares = 0`.
6. Observe the bug: `testSigner.getEarnedStakerRewards(alice, 1n, null)` becomes nonzero even though `signer1` never earned anything and was never a cycle-1 signer-set member — the assertion `expect(...).toBe(0n)` at the end of the test is the one that fails on unfixed code per the test's own comment.

        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
