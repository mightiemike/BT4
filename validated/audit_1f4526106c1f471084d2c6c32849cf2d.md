### Title
Protocol fee (fee-reserve) can be permanently avoided by repeatedly calling `accrue()` with small time deltas that round the treasury cut to zero - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
The vault's `accrue()` function computes the interest that has accumulated since `last-update`, splits a portion of it to the treasury as `reserve-inc`/`treasury-lp`, and only advances `last-update` when the index actually changed. Any caller can invoke `accrue()` (directly, or indirectly via `deposit`/`redeem`/`system-borrow`/`system-repay`) at very short intervals, and Clarity's integer division rounds the treasury fee down to zero on each call while the underlying index still advances (crediting the interest to depositors instead). This lets an attacker drain the protocol's fee share from interest that borrowers already pay, mirroring the referenced `HoneyLocker`/`HoneyQueen::computeFees` rounding-to-zero fee-avoidance bug class.

### Finding Description
`accrue()` in every vault (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`) computes: [1](#0-0) 

```clarity
(let ((next (next-index))
      (nliq (next-liquidity-index))
      (scaled-principal (var-get principal-scaled))
      (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
      (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
      (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
      (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
      (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
  (if (not (is-eq idx next)) (var-set index next) false)
  (if (not (is-eq lidx nliq)) (var-set lindex nliq) false)
  (if (> treasury-lp u0) (try! (ft-mint? zft treasury-lp .dao-treasury)) false)
  (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
      (var-set last-update stacks-block-time)
      false)
  ...)
``` [2](#0-1) 

`reserve-inc` and `treasury-lp` are both computed with `mul-div-down`, which truncates (rounds toward zero). `debt-delta` is bounded by how much interest has accrued since the *last time the index moved*, which is itself governed by `last-update`, a value that is only advanced when `idx`/`lindex` actually change: [3](#0-2) 

Because `last-update` is a clock that is only advanced on change, an attacker (or even an ordinary heavy user) can call `accrue()` — a public function — on nearly every block. Each call produces a tiny `debt-delta` (interest accrued over one block instead of over a long idle period). With `fee-reserve` expressed in BPS (max 10000), any `debt-delta` below `BPS / fee-reserve` truncates `reserve-inc` to `0`, and thus `treasury-lp` to `0`, skipping the `ft-mint? zft treasury-lp .dao-treasury` call entirely for that call. Because the index itself (`idx`→`next`) still advances on that same call (the borrower interest is real and gets reflected in `total-assets`/depositor share price), `last-update` is bumped forward, resetting the window for the next accrual and permanently preventing that slice of interest from ever being counted toward `reserve-inc` in a future call with a larger `debt-delta`.

This is the same rounding-down fee-avoidance root cause described in the external report (`amount * fee / 10000` truncating to zero for small `amount`), analogously applied here to the protocol's own interest-fee skim (`debt-delta * fee-reserve / BPS`), and enabled by a "clock advanced only on change" pattern (`last-update` only bumped when `idx`/`lindex` change) that removes any incentive to wait for delta accumulation before it is again zeroed by the small per-call time window.

### Impact Explanation
The treasury (protocol) permanently loses its cut of interest income — this interest is not "unclaimed yield still sitting in the vault" that could later be swept; it is skipped every time `accrue()` fires with a small delta, and the corresponding value instead flows entirely to depositors via the unchanged share price growth. This is a permanent loss of the treasury's fee (unclaimed protocol royalty/yield), landing under **High — permanent freezing/loss of unclaimed yield or royalties** for the protocol treasury.

### Likelihood Explanation
Likelihood is Medium: `accrue()` is a plain `define-public` function with no access control, callable by anyone, and it is also triggered by ordinary `deposit`/`redeem`/`system-borrow`/`system-repay` calls. An attacker only needs to submit transactions calling `accrue()` (or any of those) frequently (e.g., once per block) on a vault with low utilization/interest rate, so that each block's `debt-delta` is small enough to be truncated by `mul-div-down(debt-delta, fee-reserve, BPS)`. Gas/transaction costs on Stacks are the main friction, similar to the original report's caveat about gas costs limiting profitability on typical tokens — but for high-value/low-decimal assets or over long campaigns it remains exploitable, and does not require any privileged access.

### Recommendation
Round the treasury fee calculation up (or track a fee-debt remainder) so that the treasury's basis-point share of interest is never truncated to zero: use a `mul-div-up`-style computation for `reserve-inc`/`treasury-lp`, or accumulate a running fractional remainder across `accrue()` calls (accrual-debt carry) instead of resetting `last-update` whenever the index moves. Alternatively, decouple `last-update` from `idx`/`lindex` changes and only advance it once accumulated interest since the last treasury mint exceeds the rounding granularity, ensuring the treasury eventually receives its accrued dust.

### Proof of Concept
1. Attacker (or any actor) identifies a vault (e.g., `v0-vault-stx.clar`) with `fee-reserve` set such that `BPS / fee-reserve` is large relative to per-block interest accrual (e.g., `fee-reserve = 1000` bps ⇒ any `debt-delta < 10` truncates `reserve-inc` to 0).
2. Attacker calls `accrue()` (public, unauthenticated) once per block instead of letting interest accumulate over a longer interval.
3. Each call: `next-index()` computes a slightly higher `idx`, so `debt-delta > 0` and `idx != next`, satisfying `(var-set index next)` and `(var-set last-update stacks-block-time)` — the "clock" resets.
4. However `reserve-inc = mul-div-down(debt-delta, fee-reserve, BPS) = 0` because `debt-delta` for one block is too small, so `treasury-lp = 0` and the `ft-mint? zft treasury-lp .dao-treasury` branch is skipped.
5. Because `last-update` was already advanced in step 3, the next block's `accrue()` call again starts from a tiny window and again truncates the treasury fee to zero — repeating indefinitely.
6. Over the campaign, borrowers' interest fully lands in the depositors' share price (`total-assets`) while the treasury's `fee-reserve` cut of that same interest is never minted, resulting in a systematic, permanent loss of protocol fee revenue.
