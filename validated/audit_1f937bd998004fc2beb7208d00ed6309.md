## Analysis

Tracing the call path `MsgExecutePayload` → `msgServer.ExecutePayload` → `Keeper.ExecutePayload` → `CallUEAExecutePayload` → `DerivedEVMCall("executeUniversalTx", ...)` confirms the exploit pattern is real and reachable by any unprivileged account.

**Cost-asymmetry mechanics:**

1. `MsgExecutePayload` is in the gasless allowlist [1](#0-0) , so both `MinGasPriceDecorator` and `DeductFeeDecorator` explicitly skip fee/min-gas-price enforcement for it [2](#0-1) [3](#0-2) .

2. `AccountInitDecorator` lets a brand-new, zero-balance account submit a gasless tx for free — it creates the account mid-pipeline and verifies the signature against `account_number=0, sequence=0` before short-circuiting the rest of the ante chain [4](#0-3) . This means an attacker never needs funded keys — a fresh keypair is sufficient for every submission.

3. Once accepted, `Keeper.ExecutePayload` performs real work: it fetches chain config, resolves the UEA address via a real EVM `staticcall` (`CallFactoryToGetUEAAddressForOrigin`), and — if the UEA is deployed — invokes `CallUEAExecutePayload` → `DerivedEVMCall("executeUniversalTx", ..., verificationData)` [5](#0-4) , which is a **committed, real EVM transaction** with an attacker-supplied `gasLimit` [6](#0-5) . Inside the UEA contract, this reaches ECDSA recovery or the Ed25519 `usigverifier` precompile (documented in `x/uexecutor/README.md`) before reverting on an invalid signature — real CPU/EVM computation performed for a payload the node can never accept.

4. Regardless of success/failure, `DeductGasFeesFromReceipt` attempts to charge gas from the **target UEA's balance**, not the attacker's [7](#0-6) ; on signature failure the whole message is rolled back by the baseapp's per-message cache, so the attacker pays nothing and the UEA loses nothing — but the CPU work already happened.

This confirms sustained, cost-free gasless `MsgExecutePayload` spam with syntactically valid but cryptographically bogus `VerificationData` (targeting either a nonexistent owner, which is rejected slightly earlier at the balance check in step 3, or an existing funded/deployed UEA, which reaches the full EVM signature-verification path) forces real, uncompensated EVM/CPU work onto every honest node that processes the block. The chief mitigating factor is that block gas limits still bound per-block inclusion (the declared `Gas` field is still consumed by `ConsumeGasForTxSizeDecorator`/`GasWantedDecorator`), but that budget is consumed by an attacker who pays nothing, crowding out legitimate gas-paying users at zero cost.

### Title
Gasless `MsgExecutePayload` allows free EVM signature-verification spam with zero attacker cost - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/msg_execute_payload.go`, `app/txpolicy/gasless.go`)

### Summary
`MsgExecutePayload` is whitelisted as a gasless message type and is explicitly documented as callable by "any" signer. Combined with `AccountInitDecorator`'s free account-creation-on-first-tx behavior, an attacker with zero funds and zero fees can repeatedly submit `MsgExecutePayload` with syntactically valid but cryptographically invalid `VerificationData`, forcing every processing node to perform real EVM computation (UEA address resolution and, for deployed/funded UEAs, a full `executeUniversalTx` call including ECDSA recovery or the Ed25519 `usigverifier` precompile) before the transaction reverts and rolls back with no cost recovered from the attacker.

### Impact Explanation
This is a genuine cost-to-node-cost asymmetry: legitimate throughput must compete for block gas space against free, always-revertable spam. This degrades effective throughput and wastes validator CPU on work the protocol will never accept, without requiring any privileged role, matching the in-scope "denial of service only when it is not network-level and is reachable without privileged control" criterion.

### Likelihood Explanation
High. No special access is required — any address (even freshly generated, unfunded ones enabled via `AccountInitDecorator`) can submit these messages. Producing syntactically valid but cryptographically wrong `VerificationData` (arbitrary bytes of the correct length) is trivial and free for the attacker.

### Recommendation
Introduce an explicit rate limit or minimum resource cost for gasless `MsgExecutePayload` submissions independent of the Cosmos fee market — e.g., require a lightweight, cheaply verifiable pre-check (cheap ECDSA/Ed25519 pre-validation before any EVM call is issued), cap the number of gasless `MsgExecutePayload` per signer/block, or require a bonded/staked relationship (similar to the UV-only gating already applied to vote messages) before the expensive `CallUEAExecutePayload` EVM path is reached.

### Proof of Concept
1. Generate an arbitrary new Cosmos keypair with zero balance.
2. Submit `MsgExecutePayload` with a `UniversalAccountId` pointing at an existing, funded, deployed UEA and a `VerificationData` byte string of correct length but random/incorrect signature bytes.
3. `AccountInitDecorator` creates the account and passes ante checks without requiring any balance; `MinGasPriceDecorator`/`DeductFeeDecorator` skip fee enforcement because the tx is gasless.
4. The message handler resolves the UEA address and issues a real, committed EVM call into `executeUniversalTx`, triggering ECDSA/Ed25519 verification, which fails and reverts — all state (including any attempted gas deduction) rolls back, costing the attacker nothing while consuming real node CPU/EVM execution time.
5. Repeat with a new zero-balance keypair each time to bypass sequence-based rate limiting, sustaining a stream of free spam.

// CallUEAExecutePayload executes a universal payload through UEA
func (k Keeper) CallUEAExecutePayload(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	universal_payload *types.UniversalPayload,
	verificationData []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiUniversalPayload, err := types.NewAbiUniversalPayload(universal_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	gasLimit := new(big.Int)
	gasLimit, ok := gasLimit.SetString(universal_payload.GasLimit, 10)
	if !ok {
		return nil, fmt.Errorf("invalid gas limit: %s", universal_payload.GasLimit)
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		gasLimit,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"executeUniversalTx",
		abiUniversalPayload,
		verificationData,
	)
}
