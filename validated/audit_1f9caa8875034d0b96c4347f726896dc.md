## Finding: `ensure_match_transaction_info` silently skips checkpoint-hash verification, masking state divergence during replay/restore verification

### Title
Replay/restore verification accepts diverged state-checkpoint roots because `ensure_match_transaction_info` never compares them - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the authoritative comparator used to confirm that a freshly-computed (replayed) transaction output matches the transaction info recorded/authenticated by the ledger. It checks status, gas used, write-set hash, and event root hash, but explicitly does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` — the very fields that summarize the resulting world-state root after a transaction.

### Finding Description
The comparator is defined at [1](#0-0) . It verifies:
- transaction status vs. `txn_info.status()` [2](#0-1) 
- gas used [3](#0-2) 
- write-set hash vs. `txn_info.state_change_hash()` [4](#0-3) 
- event root hash [5](#0-4) 

It then returns `Ok(())` without ever comparing the locally-computed state/hot-state/position-state checkpoint hashes to the ones carried by the archived `TransactionInfo`, a gap the code itself documents: [6](#0-5) 

This function is the sole point where a replayed execution result is validated against the historically-persisted/authenticated `TransactionInfo` in several tools: [7](#0-6)  (chunk-based replay-verify loop feeding `expected_txn_infos`), plus call sites in `aptos-move/aptos-debugger/src/aptos_debugger.rs`, `aptos-move/cli/src/commands.rs`, and `execution/executor/src/chunk_executor/mod.rs`.

Because `TransactionInfo`'s cryptographic hash (used for the transaction accumulator, `TransactionInfo::hash()`) *does* include `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` as struct fields [8](#0-7) , the accumulator-level proof check (`verify_extends_ledger`, `ensure_transaction_infos_match`, seen in [9](#0-8) ) only confirms that the *previously persisted* `TransactionInfo` objects are self-consistent with a signed `LedgerInfo`. It does **not** confirm that a **freshly-replayed** execution reproduces the same state checkpoint hash — that comparison is exactly what `ensure_match_transaction_info` was supposed to, but fails to, perform.

### Impact Explanation
Replay-verify / `replay-on-archive` is the mechanism operators and CI rely on to catch state-divergent bugs (the class of bug that historically causes hard forks) before they reach production. Because the state/hot-state/position-state checkpoint hash is skipped in the equality check, a local execution bug that produces a **different, wrong Merkle/Jellyfish state root** than the one recorded in the authenticated backup will still be reported as "successful replay" as long as status/gas/write-set-hash/events happen to match (or the divergent computation isn't reflected in those fields at all — checkpoint hashes are computed periodically, separately from the per-txn write set). This defeats the primary detection mechanism for state-commitment/proof integrity regressions, i.e., exactly the "hard-fork-only divergence during commit/replay/restore/proof verification" impact category in scope.

### Likelihood Explanation
This is not a hypothetical: the gap is admitted in-code via the `TODO(trading-native)` comment, explicitly warning that `replay_on_archive` "can report a successful replay even when the authenticated position state root diverges from local execution." Any bug in state-checkpoint/state-root computation logic (JMT commit, position-state tree, hot-state tree) introduced elsewhere in the codebase would go unnoticed by this verification path with no attacker interaction required — it's a latent detection gap rather than an externally triggerable exploit, so likelihood of the *underlying* divergence occurring depends on other bugs, but the detection failure itself is deterministic and always present.

### Recommendation
Extend `ensure_match_transaction_info` to compare `self`-derived (or externally supplied) state checkpoint hash, hot-state checkpoint hash, and position-state checkpoint hash against `txn_info.state_checkpoint_hash()` / `.hot_state_checkpoint_hash()` / `.position_state_checkpoint_hash()` whenever those fields are `Some` on either side, before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS` or relying on `replay_on_archive`/`replay-verify` results as a state-integrity guarantee.

### Proof of Concept
1. Persist a backup/archive where `TransactionInfo` records a correct `state_checkpoint_hash` H1 for version V.
2. Introduce (or exploit an existing) divergence in state-checkpoint computation so that replaying transaction V locally yields checkpoint hash H2 ≠ H1, while status/gas/write-set-hash/events remain identical (checkpoint hashes are computed periodically, decoupled from the per-txn write set).
3. Run `storage/db-tool/src/replay_on_archive.rs`'s `Verifier::execute_and_verify` path, which calls `ensure_match_transaction_info` per the loop in [10](#0-9) .
4. Observe the tool reports success (no error added to `total_failed_txns`) despite H1 ≠ H2, because the function never inspects checkpoint hash fields.

**Caveat / uncertainty:** I was unable to fully trace, within the remaining tool budget, whether `execution/executor/src/chunk_executor/mod.rs`'s call to `ensure_match_transaction_info` sits on a live state-sync/fast-sync commit path (which would elevate this from "verification tooling gap" to "wrong state can be durably committed on a syncing node") versus only the offline `TransactionReplayer`/backup-verify flows. This should be confirmed before finalizing severity — if it is reachable from the live state-sync replayer that commits to a node's durable DB, the impact rises to direct committed-state corruption rather than only defeating an audit tool.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    // Execute the verify one valid range
    pub fn verify(&self, start: Version, limit: u64) -> Result<Vec<Error>> {
        let mut total_failed_txns = Vec::with_capacity(limit as usize);
        let txn_iter = self
            .backup_handler
            .get_transaction_iter(start, limit as usize)?;
        let mut cur_txns = Vec::with_capacity(limit as usize);
        let mut cur_persisted_aux_info = Vec::with_capacity(limit as usize);
        let mut expected_events = Vec::with_capacity(limit as usize);
        let mut expected_writesets = Vec::with_capacity(limit as usize);
        let mut expected_txn_infos = Vec::with_capacity(limit as usize);
        let mut chunk_start_version = start;
        let executor = AptosVMBlockExecutor::new();
        for item in txn_iter {
            // timeout check
            if let Some(duration) = self.timeout_secs {
                if self.replay_stat.get_elapsed_secs() >= duration {
                    bail!(
                        "Verify timeout: {}s elapsed. Deadline: {}s. Failed txns count: {}",
                        self.replay_stat.get_elapsed_secs(),
                        duration,
                        total_failed_txns.len(),
                    );
                }
            }

            let (
                input_txn,
                persisted_aux_info,
                expected_txn_info,
                expected_event,
                expected_writeset,
            ) = item?;
            let is_epoch_ending = expected_event.iter().any(ContractEvent::is_new_epoch_event);
            cur_txns.push(input_txn);
            cur_persisted_aux_info.push(persisted_aux_info);
            expected_txn_infos.push(expected_txn_info);
            expected_events.push(expected_event);
            expected_writesets.push(expected_writeset);
            if is_epoch_ending || cur_txns.len() >= self.chunk_size {
                let cnt = cur_txns.len();
                while !cur_txns.is_empty() {
                    // verify results
                    let failed_txn_opt = self.execute_and_verify(
                        &executor,
                        &mut chunk_start_version,
                        &mut cur_txns,
                        &mut cur_persisted_aux_info,
                        &mut expected_txn_infos,
                        &mut expected_events,
                        &mut expected_writesets,
                    )?;
                    // collect failed transactions
                    total_failed_txns.extend(failed_txn_opt);
                }
                self.replay_stat.update_cnt(cnt as u64);
                self.replay_stat.print_tps();
            }
        }
        // verify results
        let fail_txns = self.execute_and_verify(
            &executor,
            &mut chunk_start_version,
            &mut cur_txns,
            &mut cur_persisted_aux_info,
            &mut expected_txn_infos,
            &mut expected_events,
            &mut expected_writesets,
        )?;
        total_failed_txns.extend(fail_txns);
        Ok(total_failed_txns)
    }
