## Finding

### Title
Excess attached deposit is never refunded on successful registration in `AddressRegistrar::register` - ([File: runtime/near-wallet-contract/implementation/address-registrar/src/lib.rs])

### Summary
The `AddressRegistrar::register` function only checks that `attached_deposit >= required_deposit` (a `>=` check, exactly the pattern flagged in the source report) but only refunds the caller's deposit on the *failure* path (address collision). On the success path (new address registered), any amount attached above the exact storage cost is silently absorbed by the contract with no way for the caller, or anyone else, to reclaim it.

### Finding Description
`register` computes the exact storage cost needed and compares it against the caller's attached deposit: [1](#0-0) 

If `given_deposit < required_deposit` it panics (this correctly rejects underpayment). But if `given_deposit > required_deposit` the call proceeds normally and the entry is inserted: [2](#0-1) 

Note that on this `Entry::Vacant` (success) branch there is no promise/transfer to refund the difference `given_deposit - required_deposit`. Compare this with the `Entry::Occupied` (collision/failure) branch a few lines below, which explicitly refunds the entire attached deposit back to the caller: [3](#0-2) 

The contract exposes no other method (`new`, `register`, `lookup`, `get_address` are the only public entry points) that could later withdraw or redistribute this excess balance: [4](#0-3) 

This is precisely the bug class described in the external report: the `>=`/insufficient-deposit check does not enforce an exact amount, and unlike NEAR's protocol-level deposit handling elsewhere (e.g. `settle_state_init_deposit` in `runtime/runtime/src/deterministic_account_id.rs:73-115`, or the gas-refund/deposit-refund machinery in `runtime/runtime/src/lib.rs:1284-1419`, which always refund exact excess amounts), this application-level contract keeps the whole surplus with no recovery path.

### Impact Explanation
Any account calling `AddressRegistrar::register` (this is the contract used by the ETH-implicit wallet contract flow to register a NEAR account name for an address, reachable directly via a standard `FunctionCall` transaction/RPC call, or indirectly through the wallet-contract's cross-contract call path shown in `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`) that attaches more NEAR than the exact storage cost permanently loses the excess — the funds become stuck in the `AddressRegistrar` contract's balance with no method to reclaim them. This is a concrete "permanently frozen funds" outcome reachable from a single unprivileged transaction/contract call.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: callers computing `required_deposit` off-chain (e.g. rounding up, or reusing a fixed/rough NEAR amount like `NearToken::from_near(1)`) will commonly overpay, since `bytes_to_store` depends on the variable-length `account_id`. Every overpaying, successful `register` call causes an unrecoverable loss for that caller.

### Recommendation
On the success (`Entry::Vacant`) path, compute and refund the excess (`given_deposit - required_deposit`) back to `env::predecessor_account_id()` via a transfer promise, exactly as already done on the collision path. Alternatively, require an exact match (or refund any surplus at the end of the method regardless of branch outcome).

### Proof of Concept
1. Caller invokes `register(account_id)` on the deployed `AddressRegistrar` contract, attaching a deposit `D` where `D > required_deposit = storage_byte_cost * (20 + len(account_id))`.
2. Since `given_deposit >= required_deposit`, the `given_deposit < required_deposit` panic guard does not trigger.
3. `address` is not already registered (`Entry::Vacant`), so the mapping is inserted and `Some(address)` is returned; no transfer/refund promise is scheduled.
4. The full `D` (not just `required_deposit`) remains credited to the `AddressRegistrar` contract's account balance permanently; no method exists on the contract to move it back out to the original caller or anyone else. [5](#0-4)

    #[payable]
    pub fn register(&mut self, account_id: AccountId) -> Option<String> {
        // It is not allowed to register eth-implicit accounts because the purpose
        // of the registry is to allow looking up the named account associated with
        // an address obtained via hashing, but eth-implicit accounts are already
        // parsable as addresses.
        if is_eth_implicit(&account_id) {
            let log_message = format!("Refuse to register eth-implicit account {account_id}");
            env::log_str(&log_message);
            return None;
        }

        // Must store the address and the account id
        let bytes_to_store = 20 + (account_id.len() as u128);
        let required_deposit =
            NearToken::from_yoctonear(env::storage_byte_cost().as_yoctonear() * bytes_to_store);
        let given_deposit = env::attached_deposit();
        // The caller must pay for the storage cost of registering.
        if given_deposit < required_deposit {
            let message = format!(
                "Insufficient deposit to cover storage cost. Given={} Expected={}",
                given_deposit.as_yoctonear(),
                required_deposit.as_yoctonear(),
            );
            env::panic_str(&message);
        }

        let address = account_id_to_address(&account_id);

        match self.addresses.entry(address) {
            Entry::Vacant(entry) => {
                let address = format!("0x{}", hex::encode(address));
                let log_message = format!("Added entry {} -> {}", address, account_id);
                entry.insert(account_id);
                env::log_str(&log_message);
                Some(address)
            }
            Entry::Occupied(entry) => {
                let log_message = format!(
                    "Address collision between {} and {}. Keeping the former.",
                    entry.get(),
                    account_id
                );
                env::log_str(&log_message);
                // Transfer the deposit back to the caller since no storage was updated.
                let refund_promise = env::promise_batch_create(&env::predecessor_account_id());
                env::promise_batch_action_transfer(refund_promise, given_deposit);
                None
            }
        }
    }
