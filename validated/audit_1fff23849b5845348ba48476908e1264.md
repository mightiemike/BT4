## Finding [1](#0-0) 

The `apollo_router` advisory root cause was a cache-retrieval bug: a shared cache could return an entry belonging to a *different, prior* logical request, letting the router unknowingly execute a stale/mismatched query plan. I found a directly analogous pattern in the sequencer's compiled-class caching layer.

### Title
Stale/undeclared Cairo0 class served from process-wide `ContractClassManager` cache after a block revert, bypassing the declared-class check - (File: `crates/blockifier/src/state/state_reader_and_contract_manager.rs`)

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` re-validates a cache hit against the authoritative state reader (`is_declared`) only for non-V0 (Cairo1/Native) classes, but explicitly skips this check for V0 (deprecated Cairo0) classes:

```rust
match &runnable_class {
    RunnableCompiledClass::V0(_) => {}
    _ => {
        if !self.state_reader.is_declared(class_hash)? {
            return Err(StateError::UndeclaredClassHash(class_hash));
        }
    }
}
``` [2](#0-1) 

The developers' own comment acknowledges the exact hazard this check is meant to guard against: "existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)" [3](#0-2) , but the guard is not applied to the V0 branch.

### Finding Description
The `contract_class_manager` (`RawClassCache`/`GlobalContractCache`) is a long-lived, process-wide LRU cache keyed only by `ClassHash`, populated whenever a class is compiled from the underlying `StateReader` [4](#0-3) . It is not invalidated when the persistent storage state is rolled back. Storage explicitly supports reverting a committed block's state diff (deleting declared classes) via `revert_state_diff` [5](#0-4) , and tests confirm a reverted class is no longer "declared" afterward [6](#0-5) .

Because the in-memory contract-class cache is separate from committed storage and is never rolled back in lockstep with `revert_state_diff`, once a V0 class hash is cached (from processing a block/transaction that later gets reverted), it remains permanently "resolvable" via `get_compiled_class`/`get_compiled_from_class_manager` without ever re-checking against the canonical `is_declared` state.

This affects both directions reachable by an ordinary transaction sender:
- `try_declare` (used for every `DeclareTransaction`) first calls `state.get_compiled_class(class_hash)`, and only proceeds to declare if it returns `Err(UndeclaredClassHash)` [7](#0-6) . A stale cache hit will make it wrongly conclude the class is "already declared" and reject a legitimate `Declare`.
- Any `Invoke`/`DeployAccount` referencing that class hash will succeed in fetching a "runnable" compiled class and execute it, even though the class is not actually declared in the canonical/committed state (and thus not reflected in the Patricia class commitment).

### Impact Explanation
This is a cache-key/validity bug of the same class as CVE-2024-32971 (CWE-440, "Expected Behavior Violation" via stale/incorrect cache retrieval): the sequencer can execute an operation using state that does not correspond to the current canonical state. Concretely:
- A sequencer node with the stale cache entry can execute a contract call against bytecode that is not canonically declared, or reject a `Declare` that other nodes accept — producing different state diffs/fee charges/call results than an honest node without the stale entry (freshly started, cache evicted, or that never processed the reverted block).
- This is a correctness/consensus-relevant divergence: different honest sequencers/full nodes replaying the same transaction sequence can compute different state transitions and therefore different state roots/block hashes for Starknet OS re-execution, satisfying the "honest-node divergence / wrong committed root" impact bar.

### Likelihood Explanation
Block reverts are an anticipated, non-malicious occurrence in this codebase (explicit `revert_state_diff` support and tests). Any unprivileged user only needs to submit a Cairo0 `Declare` transaction (or trigger its compilation, e.g., via any tx referencing that class hash) that ends up in a block that is later reverted, then submit any follow-up transaction (Declare/Invoke/DeployAccount) referencing the same class hash. No special privileges, staking, or node control are required to construct the triggering transactions themselves — although the divergence outcome depends on cache state that differs opportunistically across nodes.

### Recommendation
Apply the same `is_declared` re-validation to the `RunnableCompiledClass::V0` branch in `get_compiled_from_class_manager` as is done for Cairo1/Native classes, or invalidate/evict the relevant `contract_class_manager` cache entries whenever the underlying storage undergoes `revert_state_diff` for the affected block range.

### Proof of Concept
1. Node executes block B containing a Cairo0 `Declare` for `class_hash = X` (via `try_declare` → `state.set_contract_class`), populating `contract_class_manager`'s `RawClassCache` with `CompiledClasses::V0` for `X`.
2. Block B is reverted (via `revert_state_diff`), removing `X` from the declared-classes storage table, but `contract_class_manager`'s in-process cache for `X` is untouched.
3. An unprivileged user submits a new transaction (e.g., `Invoke`/`DeployAccount`) referencing class hash `X`. On the node with the stale cache, `get_compiled_from_class_manager` hits the V0 branch, skips `is_declared`, and returns `Ok(runnable_class)`, letting the transaction execute using bytecode that is not canonically declared.
4. Simultaneously, a fresh/other honest node without the stale cache entry queries `state_reader` directly, gets `UndeclaredClassHash`, and rejects the same transaction — producing a state/result divergence between honest nodes for the identical transaction and block context.

impl<S: FetchCompiledClasses> StateReaderAndContractManager<S> {
    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }
        self.increment_cache_miss_metric();

        let compiled_class = self.state_reader.get_compiled_classes(class_hash)?;
        self.contract_class_manager.set_and_compile(class_hash, compiled_class.clone());
        // Access the cache again in case the class was compiled.
        let runnable_class = self
            .contract_class_manager
            .get_runnable(&class_hash, &self.native_classes_whitelist)
            .unwrap_or_else(|| {
                // Edge case that should not be happen if the cache size is big enough.
                // TODO(Yoni): consider having an atomic set-and-get.
                log::error!("Class is missing immediately after being cached.");
                compiled_class.to_runnable()
            });
        self.update_native_metrics(&runnable_class);
        Ok(runnable_class)
    }

    /// Locks the cache for atomic access. Although conceptually shared, writing to this cache is

    pub fn lock(&self) -> LockedClassCache<'_, T> {
        self.0.lock().expect("Global contract cache is poisoned.")

        self.lock().cache_get(class_hash).cloned()

        self.lock().cache_set(class_hash, contract_class);

        // TODO(yair): Consider reverting the compiled classes in their own module.
        let compiled_classes_table = self.open_table(&self.tables.casms)?;
        let compiled_class_hash_v2_table =
            self.open_table(&self.tables.stateless_compiled_class_hash_v2)?;
        let deployed_contracts_table = self.open_table(&self.tables.deployed_contracts)?;
        let nonces_table = self.open_table(&self.tables.nonces)?;
        let storage_table = self.open_table(&self.tables.contract_storage)?;
        let state_diffs_table = self.open_table(&self.tables.state_diffs)?;
        let compiled_class_hash_table = self.open_table(&self.tables.compiled_class_hash)?;

        let current_state_marker = self.get_state_marker()?;

        // Reverts only the last state diff.
        let Some(next_block_number) = block_number
            .next()
            .filter(|next_block_number| *next_block_number == current_state_marker)
        else {
            debug!(
                "Attempt to revert a non-existing / old state diff of block {}. Returning without \
                 an action.",
                block_number
            );
            return Ok((self, None));
        };

        let thin_state_diff = self
            .get_state_diff(block_number)?
            .unwrap_or_else(|| panic!("Missing state diff for block {block_number}."));
        markers_table.upsert(&self.txn, &MarkerKind::State, &block_number)?;
        let classes_marker = markers_table.get(&self.txn, &MarkerKind::Class)?.unwrap_or_default();
        if classes_marker == next_block_number {
            markers_table.upsert(&self.txn, &MarkerKind::Class, &block_number)?;
        }
        let compiled_classes_marker =
            markers_table.get(&self.txn, &MarkerKind::CompiledClass)?.unwrap_or_default();
        if compiled_classes_marker == next_block_number {
            markers_table.upsert(&self.txn, &MarkerKind::CompiledClass, &block_number)?;
        }
        let deleted_class_hashes = delete_declared_classes_block(
            &self.txn,
            &thin_state_diff,
            &declared_classes_block_table,
            block_number,
        )?;
