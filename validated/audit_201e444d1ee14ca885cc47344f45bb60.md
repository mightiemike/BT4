### Title
Webhook HMAC Validation Does Not Bind the Signature to the `X-Shopify-Shop-Domain` Header, Allowing Cross-Tenant Webhook Domain Spoofing - ([File: packages/apps/shopify-api/lib/utils/hmac-validator.ts])

### Summary
Shopify webhook authentication in `@shopify/shopify-api` verifies the HMAC signature solely over the raw request body, but the shop-identifying header (`X-Shopify-Shop-Domain`) that downstream handlers trust to select which tenant/session to act on is never included in that signature. This mirrors the reported `CredibleAccountModule::validateUserOp()` bug class: a validating function accepts and processes state-changing input without authenticating the identity ("sender"/tenant) that the state change is attributed to.

### Finding Description
Webhook signature verification is performed by `validateHmacFromRequestFactory`, which computes the HMAC exclusively over `rawBody`: [1](#0-0) 

and compares it against the `X-Shopify-Hmac-Sha256` header value: [2](#0-1) 

`validateFactory` (the entry point exposed as `shopify.webhooks.validate`) runs this HMAC check and, only if it passes, separately extracts the `domain`, `topic`, `apiVersion`, and `webhookId` fields straight from the (unauthenticated) request headers via `checkWebhookHeaders`: [3](#0-2) [4](#0-3) 

Because none of these header values are part of the signed content, the HMAC only proves "this body was signed with the app's shared `apiSecretKey`" — it proves nothing about which shop sent it. The `domain` field returned from a *valid* check is then used directly to select the tenant's session and drive app logic: [5](#0-4) 

The same pattern exists in the react-router equivalent (`authenticateWebhookFactory`): [6](#0-5) 

Since `apiSecretKey` is a single value shared by the app across **every** shop that installs it (not a per-shop secret), any merchant who has installed the app — even briefly, even a free/trial install — is a legitimate recipient of correctly-HMAC-signed webhook requests. Such a merchant can capture one legitimately-signed webhook request they received for their own store, then resend the identical `rawBody`/`X-Shopify-Hmac-Sha256` pair while substituting the `X-Shopify-Shop-Domain` (and/or `X-Shopify-Topic`, `X-Shopify-Webhook-Id`) header with an arbitrary victim shop's domain. `validateHmacFromRequestFactory` will still report the request as valid because it never looked at those headers, and `checkWebhookHeaders` will happily report `domain: <victim-shop>` as an authenticated fact.

### Impact Explanation
- The attacker (a single, unprivileged merchant who installed the app) can make the app believe an arbitrary webhook event originated from a different shop's domain of their choosing.
- `ensureValidOfflineSession(params, check.domain)` will load the **victim's** stored offline session and hand it (with a live admin API client) to the webhook callback, using attacker-controlled body content and topic.
- App-level webhook handlers commonly perform tenant-scoped side effects keyed off `shop`/`domain` (data writes, GDPR/compliance webhook processing, uninstall cleanup, order/inventory syncs, billing state changes). An attacker can trigger these for shops they do not own, corrupting or exfiltrating cross-tenant state, or forging events such as `app/uninstalled` against a victim to disrupt their integration.
- This is a cross-tenant authentication bypass consistent with "accepted forged Shopify request" in the scope rules — analogous to the `validateUserOp` bug where the function trusted attacker-supplied identity data instead of cryptographically binding it to the caller.

### Likelihood Explanation
High for any actor who can install the target app on any shop (including a free trial/dev store) — a very low bar for an "unprivileged single merchant." No secret leakage or MITM is required: the attacker only needs one legitimately-delivered webhook (which they receive as a normal side effect of installing the app) and the ability to send raw HTTP POSTs with custom headers to the app's public webhook endpoint.

### Recommendation
Bind the shop/topic/webhook identity into the authenticated material before trusting it:
- Include `X-Shopify-Shop-Domain` (and ideally `X-Shopify-Topic`/`X-Shopify-Webhook-Id`) in the HMAC-covered payload, or
- After a passing signature check, independently verify that `domain` corresponds to a shop with an active session/installation for this app (reject unknown/mismatched domains), and/or
- Enforce webhook idempotency/replay protection (e.g., dedupe by `X-Shopify-Webhook-Id` plus a timestamp/nonce check) so a captured signed body cannot be resent with different header metadata.

### Proof of Concept
1. Attacker installs the target Shopify app on `attacker-shop.myshopify.com` and triggers any webhook topic (e.g. updates a product to fire `products/update`).
2. Attacker intercepts the resulting POST to their app's webhook endpoint and records `rawBody` and the `X-Shopify-Hmac-Sha256` header value (both valid/legitimate).
3. Attacker resends the exact same POST body and HMAC header to the app's webhook endpoint, but replaces `X-Shopify-Shop-Domain` with `victim-shop.myshopify.com` (and optionally a different `X-Shopify-Topic`).
4. `shopify.webhooks.validate` returns `{valid: true, domain: 'victim-shop.myshopify.com', ...}` because `validateHmacFromRequestFactory` only checked `rawBody` against the HMAC.
5. `authenticateWebhookFactory` loads `victim-shop.myshopify.com`'s offline session via `ensureValidOfflineSession` and invokes the registered webhook handler as if the event genuinely came from the victim shop.

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };

export function validateFactory(config: ConfigInterface) {
  return async function validate({
    rawBody,
    ...adapterArgs
  }: WebhookValidateParams): Promise<WebhookValidation> {
    const request: NormalizedRequest =
      await abstractConvertRequest(adapterArgs);

    const webhookType = detectWebhookType(request.headers);

    const validHmacResult = await validateHmacFromRequestFactory(config)({
      type: HmacValidationType.Webhook,
      rawBody,
      webhookType,
      ...adapterArgs,
    });

    if (!validHmacResult.valid) {
      if (validHmacResult.reason === ValidationErrorReason.InvalidHmac) {
        const log = logger(config);
        await log.debug(
          "Webhook HMAC validation failed. Please note that events manually triggered from a store's Notifications settings will fail this validation. To test this, please use the CLI or trigger the actual event in a development store.",
        );
      }
      return validHmacResult;
    }

    return checkWebhookHeaders(request.headers, webhookType);
  };

  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
