## Analysis

The report's bug class — two code paths meant to enforce the *same* threshold instead enforcing subtly different ones, letting a party satisfy the weaker one while failing the stronger one — has a concrete analog in how the 70% Nakamoto signer-approval threshold is computed in two different places.

### The two computations

**Canonical/consensus threshold** — used by `NakamotoBlockHeader::compute_voting_weight_threshold`, which is what `verify_signer_signatures` enforces network-wide when validating a Nakamoto block's signer signatures: [1](#0-0) 

This rounds **up** (ceiling): for `total_weight = 511`, it returns `358` (confirmed by the existing unit test). [2](#0-1) 

And it is enforced as the hard pass/fail gate for signature verification: [3](#0-2) 

**Signer state-machine agreement threshold** — `GlobalStateEvaluator::reached_agreement`, used by signers to decide when they've reached "global agreement" on the supported protocol version, the global burn view, and the active-miner state machine (including tx replay set): [4](#0-3) 

This uses plain integer division with **no** ceiling correction. For `total_weight = 511`: `511 * 7 / 10 = 357` (floor), one less than the canonical `358`.

### Where the discrepancy is consumed

`reached_agreement` gates the determination of: the latest supported signer protocol version, the global burn view, and the full global state machine (current active miner + tx replay set): [5](#0-4) [6](#0-5) 

Because both `reached_agreement` (loose, floor) and `compute_voting_weight_threshold` (strict, ceil) are meant to represent "70% of signing weight," but round differently, there exist `total_weight` values (any not evenly divisible by 10) where a coalition can hold exactly `floor(0.7*total)` weight — enough for `reached_agreement` to declare "global state agreement reached" — while that same weight is *insufficient* to ever produce a validly-signed Nakamoto block under `compute_voting_weight_threshold`/`verify_signer_signatures`.

This is a genuine analog of the report's bug class: two nominally-equal thresholds (both "70%") are computed with different rounding rules in two different consensus-adjacent code paths, so a minority (below the real signing quorum) can force signer-side "agreement" outcomes — e.g. asserting a particular miner/tenure or burn view as the network's agreed state — that the actual block-acceptance rule would reject. This is not something that requires a majority; a coalition holding exactly `floor(0.7*total)` (as low as one weight-unit under the real threshold) is enough, is fully unprivileged, and can be reproduced deterministically for any `total_weight` not a multiple of 10.

Where I'm less certain: I did not find a case where this specific off-by-one flips *block acceptance* on-chain (that check always goes through the strict `compute_voting_weight_threshold`/`verify_signer_signatures`), so the concrete blast radius is limited to signer-side state-machine consensus (which miner signers currently treat as active, burn-view agreement, tx-replay-set agreement, protocol-version agreement) rather than a chain-split via an accepted invalid block. That keeps this in the "temporary tip/state disagreement among signers" category rather than "chain split," per the scoring rubric.

### Title
Off-by-one rounding mismatch between `GlobalStateEvaluator::reached_agreement` and `NakamotoBlockHeader::compute_voting_weight_threshold` lets a sub-quorum coalition force false signer-state agreement - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`libsigner/src/v0/signer_state.rs`'s `reached_agreement`/`reached_disagreement` compute the 70%/30% signer-weight thresholds with truncating integer division, while the consensus-enforced `NakamotoBlockHeader::compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs` rounds up. For any `total_weight` not a multiple of 10, the two thresholds differ by one weight unit, so a coalition holding weight equal to the floor value is treated by the signer state machine as having reached "global agreement" (on active miner, burn view, protocol version, tx replay set) even though that same weight can never satisfy the real block-signing quorum enforced on-chain.

### Finding Description
`compute_voting_weight_threshold` (`stackslib/src/chainstate/nakamoto/mod.rs:1192-1207`) computes `ceil(total_weight * 7 / 10)` and is the threshold enforced by `verify_signer_signatures` (`mod.rs:1180-1187`), the consensus rule every node uses to accept/reject a Nakamoto block's signer signatures.

`GlobalStateEvaluator::reached_agreement` (`libsigner/src/v0/signer_state.rs:169-175`) computes `floor(total_weight * 7 / 10)` (no ceiling correction) and is used by every signer to decide protocol-version agreement, burn-view agreement, and the entire global state-machine/tx-replay-set agreement (`signer_state.rs:56-158`).

These two "70%" computations diverge whenever `total_weight % 10 != 0`. E.g., for `total_weight = 511`, the canonical threshold is `358`, but `reached_agreement` is satisfied at `357`.

### Impact Explanation
A coalition of signers holding exactly the floor-rounded weight (one unit below the real quorum) is unprivileged and does not require majority weight to trigger this. It can cause the signer network to treat a state (active miner, burn view, protocol version, replay set) as "globally agreed" while that same coalition could never actually produce a validly-signed block under the real 70% rule. This is a minority-triggerable divergence between the signer-side consensus view and the on-chain enforced quorum, producing temporary state/tip disagreement among signers.

### Likelihood Explanation
Triggerable whenever the reward-cycle's `total_weight` is not a multiple of 10 (common, since weight is derived from stacked-STX proportions), requiring only that a coalition control the floor-rounded weight rather than the true ceiling-rounded quorum — no privileged access or majority needed.

### Recommendation
Make `reached_agreement`/`reached_disagreement` in `libsigner/src/v0/signer_state.rs` use the same rounding rule as `NakamotoBlockHeader::compute_voting_weight_threshold` (ideally call that function directly, or replicate its ceiling logic) so the signer state-machine agreement threshold and the consensus-enforced block-signing threshold can never diverge.

### Proof of Concept
1. Configure a reward cycle so `reward_set.total_signing_weight() == 511` (achievable via stacked-amount proportions).
2. `NakamotoBlockHeader::compute_voting_weight_threshold(511)` returns `358` (per the existing test at `stackslib/src/chainstate/nakamoto/tests/mod.rs:4118-4122`) — the real quorum needed to sign/accept a block.
3. A coalition of signers controlling `357` weight submits matching `StateMachineUpdate`s.
4. `GlobalStateEvaluator::reached_agreement(357)` evaluates `357 >= 511*7/10 = 357` → `true`, so `determine_global_state`/`determine_global_burn_view`/`determine_latest_supported_signer_protocol_version` all report agreement reached at weight `357`.
5. That same `357`-weight coalition cannot produce a validly-signed Nakamoto block (`verify_signer_signatures` requires `358`), demonstrating the signer-side "agreement" is reached below the real on-chain quorum.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {

                continue;

            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,

                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());

            *entry += weight;

                found_replay_set = Some(tx_replay_set);

                break;
            }
