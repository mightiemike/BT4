### Title
Poison-microblock proof accepts a self-malleated signature pair instead of requiring two genuinely conflicting microblocks, enabling repeatable per-tenure coinbase theft - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`StacksChainState::check_microblock_header_signer` (and thus `handle_poison_microblock`) only verifies that two supplied `StacksMicroblockHeader`s recover to the *same* public-key hash; it never checks that the two headers actually represent a genuine equivocation (e.g., differing `tx_merkle_root`/`prev_block` at the same sequence, or duplicate-parent forking). Because ECDSA signatures are malleable (`s' = n - s`, recovery bit flipped) and recovery is done with `recover_to_pubkey_without_validating_low_s` (no low-S enforcement), an attacker can take a single, honestly-broadcast microblock header and derive a second, byte-distinct header with a malleated signature that recovers to the identical pubkey hash - without any real double-signing having occurred. Since the poison record and reward payout are tracked independently per `mblock_pubk_height` (one per tenure/height), this forged "fork" proof can be repeated once per honest tenure, each time draining a coinbase commission from an honest miner who never actually forked a microblock stream.

### Finding Description
Broken equality: **total coinbase paid out for real work by honest miners across the chain == total coinbase actually earned by those miners**. The exploit lets an attacker extract `poison_microblock_commission(coinbase)` (`stackslib/src/chainstate/stacks/db/accounts.rs:795-797,872-886`) once per tenure with zero actual microblock forks.

Path:
1. Honest miner N produces one legitimate microblock per tenure, signed with its microblock key, and the pubkey hash/height is recorded via `insert_microblock_pubkey_hash_height` (`clarity/src/vm/database/clarity_db.rs:1561-1569`).
2. Attacker observes the broadcast header `H1` (public data) and computes `H2 = malleablize_signature(H1)`: same `version/sequence/prev_block/tx_merkle_root`, only the signature bytes differ (negated `s`, flipped recovery bit) - a technique already implemented and named in this very codebase for a different purpose at `stackslib/src/chainstate/nakamoto/tests/node.rs:274-299`.
3. Attacker submits `PoisonMicroblock(H1, H2)`. In `handle_poison_microblock` (`stackslib/src/chainstate/stacks/db/transactions.rs:722-856`), the only content check is `check_microblock_header_signer` (`transactions.rs:686-713`), which does:
   ```
   pkh1 = mblock_hdr_1.check_recover_pubkey()
   pkh2 = mblock_hdr_2.check_recover_pubkey()
   if pkh1 != pkh2 { reject }
   ```
   Both `H1` and `H2` recover to the same pubkey hash by construction, so this passes. There is no check that `H1 != H2` in any meaningful sense (different `tx_merkle_root`, different `prev_block`, duplicate sequence with distinct content, etc.) - the exact structural checks that legitimate fork detection uses elsewhere (`validate_parent_microblock_stream` / `check_block_parent_microblock_link`, `stackslib/src/chainstate/stacks/db/blocks.rs:2992-3016` and `1376-1412`) are never re-applied inside `handle_poison_microblock`.
4. `mblock_pubk_height` is looked up per-height and the maturity window check (`height + MINER_REWARD_MATURITY < current_height`) only bounds *when* the report is valid, not *whether* it is a real fork.
5. `insert_microblock_poison` records the attacker as reporter for that height (`clarity_db.rs:1576-1607`); at maturity, `calculate_miner_reward` (`accounts.rs:804-905`) redirects `poison_microblock_commission(coinbase_reward)` to the attacker's address instead of the miner, and destroys the remainder.
6. Because `get_microblock_pubkey_hash_height` / poison records are keyed independently per block height, this can be repeated for every tenure where the honest miner produces a microblock, with no cross-tenure state deduplicating or rate-limiting the trick.

Existing guards that do NOT stop this: `check_tenure_tx`, `verify_signer_signatures` and `validate_vrf_seed` are Nakamoto-block-header/tenure checks unrelated to this legacy PoisonMicroblock payload; they never run on `TransactionPayload::PoisonMicroblock`. The maturity window (`MINER_REWARD_MATURITY`) only gates timing, not the validity of the equivocation evidence. No MARF or state-root divergence occurs between nodes since all nodes apply the same (flawed) rule deterministically - the corruption is in the reward accounting, not in consensus disagreement.

### Impact Explanation
This is block-reward theft: an unprivileged attacker (no miner key, no stake) redirects a fraction (`POISON_MICROBLOCK_COMMISSION_FRACTION`/100) of every honest miner's coinbase to itself, for every tenure in which it can observe one broadcast microblock header - with the remainder of that coinbase burned/destroyed rather than paid to the honest miner. This is deterministic across all nodes (no fork/state-root divergence), but it is a genuine, cumulative, repeatable fund-loss vector matching "block-reward theft/double-payment/loss," scaling linearly with the number of tenures targeted. Funds at risk: every honest miner's coinbase reward, network-wide.

### Likelihood Explanation
Preconditions are minimal and cheap: the attacker needs no stake, no miner slot, and no signer key - only the ability to observe one publicly-broadcast microblock header per targeted tenure and to submit a standard `PoisonMicroblock` transaction before that height's `MINER_REWARD_MATURITY` window closes. Computing the malleated signature is a pure elliptic-curve arithmetic operation (subtract `s` from curve order, flip recovery bit), requiring no private key material. This is trivially repeatable across every tenure of every honest miner that produces microblocks, making it a persistent, low-cost, high-frequency drain rather than a one-off exploit.

### Recommendation
Strengthen `check_microblock_header_signer` (or `handle_poison_microblock`) to reject proofs where `mblock_hdr_1` and `mblock_hdr_2` do not represent a genuine equivocation: require that the two headers differ in `tx_merkle_root` and/or `prev_block` at the same sequence (or duplicate-parent condition), matching the same structural fork criteria already enforced in `validate_parent_microblock_stream`/`microblock_stream_has_fork` (`blocks.rs:2992-3016`, `1376-1412`). Additionally, enforce low-S canonicalization on microblock signature recovery (reject malleated/high-S signatures) instead of using `recover_to_pubkey_without_validating_low_s`, closing the malleability vector at the signature level as well.

### Proof of Concept
Rust integration test plan (extending existing tests in `stackslib/src/chainstate/stacks/db/transactions.rs` around `process_poison_microblock_multiple_same_block`):
1. For a single tenure: mine one legitimate microblock `H1` with miner key `sk`. Compute `H2 = H1` with signature replaced by its malleated form (negate `s`, flip recovery bit) leaving `sequence/prev_block/tx_merkle_root` identical.
2. Assert `H1.check_recover_pubkey() == H2.check_recover_pubkey()` (malleation succeeds) and `H1 != H2` (bytes differ only in signature).
3. Submit `TransactionPayload::PoisonMicroblock(H1.header, H2.header)` via `StacksChainState::process_transaction`; assert it succeeds (`Ok`) and `get_poison_microblock_report` returns the attacker as reporter - demonstrating the equivocation check is bypassed for a non-fork.
4. Repeat steps 1-3 for `N` independent tenures/heights, each with its own honestly-mined single microblock and its own `mblock_pubk_height`.
5. Assert: `sum(attacker_balance_after_maturity) == N * poison_microblock_commission(coinbase)` while `sum(actual_microblock_forks_detected_by_load_descendant_staging_microblock_stream_with_poison) == 0`, proving `total_reward_paid != total_coinbase_earned_by_honest_miners` (the broken equality) purely from N applications of the single-microblock malleation trick.
