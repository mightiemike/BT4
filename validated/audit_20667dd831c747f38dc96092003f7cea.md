### Title
`accrue` pause pass-through combined with `last-update` skip in `set-pause-states` permanently discards interest/yield accrued during a DAO-initiated accrue pause - (File: `mainnet/contracts/vault/v0-vault-stx.clar`, mirrored in `v0-vault-sbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`)

### Summary
`accrue` returns the *stale* cached `index`/`lindex` without reverting whenever the `accrue` pause flag is set, instead of blocking the caller. Every hot-path function (`deposit`, `redeem`, `system-borrow`, `system-repay`) still calls `(try! (accrue))` unconditionally and proceeds using this stale index, meaning debt/interest keeps changing state (`principal-scaled`, `total-borrowed`, `assets`) using outdated interest indexes while accrue is paused. When the DAO unpauses, `set-pause-states` force-jumps `last-update` to the current `stacks-block-time`, permanently discarding any interest that should have accrued for the entire paused window.

### Finding Description
`accrue` is guarded by a pass-through instead of a revert: [1](#0-0) 
```
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ...
```
This is intentionally called from `deposit`, `redeem`, `system-borrow`, and `system-repay` before any economic action is taken: [2](#0-1) [3](#0-2) 

Critically, `borrow`/`repay`/`deposit`/`redeem` each check their *own* independent pause bit (`ERR-PAUSED`), not the `accrue` bit. So the DAO can pause `accrue` alone (e.g. via `set-pause-states` while leaving `deposit`/`redeem`/`borrow`/`repay` unpaused), and users can continue to borrow, repay, deposit, and redeem freely while `accrue` silently no-ops and returns stale indexes.

When `accrue` is later unpaused, `set-pause-states` does not replay/backfill the missed interest — it simply resets the clock: [4](#0-3) 
```
;; When unpausing accrue, jump last-update to now to skip paused period
(if (and was-paused (not now-paused))
    (var-set last-update stacks-block-time)
    false)
```
Since `next-index`/`next-liquidity-index` compute interest strictly as a function of elapsed time since `last-update`, jumping `last-update` to "now" means the entire paused interval's interest is mathematically erased — it can never be recovered by any subsequent `accrue` call, because the elapsed-time base used for the calculation no longer includes that window.

### Impact Explanation
Any interest that accrues on outstanding debt during the pause window (protocol fee-reserve share for `dao-treasury` and the yield owed to depositors/LPs via the liquidity index) is permanently and irrecoverably lost the moment `accrue` is unpaused, because the time base for interest calculation is reset forward. Depositors who held zTokens through the pause window are permanently deprived of the yield they should have earned for that period; the treasury permanently loses its `fee-reserve` cut for that period. This is a permanent freezing/loss of unclaimed yield (High impact), not merely a temporary delay, since the lost interval can never be recomputed after `last-update` is overwritten.

### Likelihood Explanation
This requires the DAO to invoke `set-pause-states` with `accrue: true` while leaving `deposit`/`redeem`/`borrow`/`repay` active (a plausible partial-pause configuration, e.g. to freeze interest during an oracle incident or migration while still allowing withdrawals), followed later by an `accrue: false` transition. This is a single privileged action combined with normal user activity in between and does not require any external attacker; the loss occurs automatically as a side effect of the intended pause/unpause sequence, making it likely to occur whenever this specific pause combination is used operationally.

### Recommendation
Do not silently skip the elapsed period on unpause. Instead, when unpausing `accrue`, run the normal interest-accrual computation using the elapsed time from the original `last-update` to `stacks-block-time` (i.e., accrue for the full paused interval) before resetting the clock, or alternatively make `accrue` revert (rather than pass through) while paused so state-mutating functions (`deposit`, `redeem`, `system-borrow`, `system-repay`) cannot proceed and silently accumulate un-accrued debt/supply changes during the pause.

### Proof of Concept
1. DAO calls `set-pause-states` on `v0-vault-stx` with `{accrue: true, borrow: false, repay: false, deposit: false, redeem: false, flashloan: false}` — `accrue` is paused, other flows remain live (`mainnet/contracts/vault/v0-vault-stx.clar:723-737`).
2. Time passes (many blocks). Users call `system-borrow` / `system-repay` / `deposit` / `redeem` normally; each calls `(try! (accrue))` which returns the stale `{index, lindex}` unchanged (`accrue`, lines 835-845), so state mutations (`principal-scaled`, `total-borrowed`, `assets`) happen without any interest being reflected in `index`/`lindex` for the elapsed time.
3. DAO calls `set-pause-states` again with `accrue: false`. `set-pause-states` detects `was-paused && not now-paused` and sets `(var-set last-update stacks-block-time)`, jumping the clock forward to "now" (lines 733-736).
4. The next `accrue` call computes `next-index`/`next-liquidity-index` using elapsed time from the *new* `last-update`, meaning the entire paused duration contributes zero interest — it is permanently unrecoverable. Any zToken holder who held shares through that window has permanently lost the yield for that period, and `dao-treasury` permanently lost its `fee-reserve` cut for that period.

(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))

    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      ;; When pausing accrue, accrue first to capture pending interest
