### Title
Unbounded, attacker-inflatable `PendingInbounds` map linearly scanned on every inbound-ballot finalization — DoS analog to Nomad's `Queue.contains()` - (File: `x/uexecutor/keeper/ballot_hooks.go`)

### Summary
The Nomad bug is a classic "attacker cheaply inflates an unbounded queue, protocol code does a full linear scan of it on the hot path" DoS. Push Chain's `x/uexecutor` module has the same shape: every unprivileged, honestly-observed source-chain inbound event creates an entry in the `PendingInbounds` collection, ballot expiry is effectively disabled (`DefaultExpiryAfterBlocks = 100_000_000`, ~19 years), and `afterInboundBallotTerminal` performs a full `Walk` over the *entire* `PendingInbounds` map on every single inbound-ballot termination to find the matching variant.

### Finding Description
`x/uexecutor/types/constants.go` sets: [1](#0-0) 
Ballot expiry is intentionally disabled ("effectively disable expiry ... without an escape hatch for stuck pending items"). Any inbound ballot that never reaches the 2/3 quorum (e.g. because validators split on data, or a variant simply never accumulates enough votes) sits `PENDING` in `PendingInbounds` essentially forever.

`RecordInboundVote` creates a new `PendingInboundEntry`/`InboundVariant` keyed by `utx_key = sha256(source_chain:tx_hash:log_index)` (from `GetInboundUniversalTxKey`) on the first vote for any inbound observation, with variants keyed by `GetInboundBallotKey` (a hash over sender/recipient/amount/asset/tx-type/verification-data/raw-payload): [2](#0-1) [3](#0-2) 

Every one of these entries is created purely from honestly-relayed observations of real source-chain events — i.e., an unprivileged external attacker fully controls the *volume* of `PendingInbounds` entries simply by generating many distinct, cheap source-chain transactions (dust deposits) or by causing many small variant divergences (any field difference in the observed payload becomes a new variant key). There is no cap, rate limit, or bond/fee requirement gating how many entries this collection can hold.

Then, whenever *any* inbound ballot (including completely unrelated, legitimate ones) reaches a terminal state, `AfterBallotTerminal` → `afterInboundBallotTerminal` performs a **full linear scan** of `PendingInbounds` to locate the entry containing the terminal ballot ID, explicitly because "Ballot IDs are one-way canonical digests (not reversible)": [4](#0-3) 

The comment justifying this ("the pending set is small and transient") is contradicted by the code's own disabled-expiry design: because expiry is turned off, the set is neither small nor transient once an attacker starts feeding it entries that fail to reach quorum (variant divergence, or just enough concurrent volume that quorum lags). This is functionally identical to Nomad's `Queue.contains()` — an unbounded, attacker-fed collection walked in full on every hot-path state transition — except here the "queue" (`PendingInbounds`) additionally never self-prunes because expiry is disabled.

This hook fires on every terminal transition of every inbound ballot in the system (`MarkBallotFinalized` → `fireBallotTerminalHook`), meaning the cost of processing legitimate `MsgVoteInbound` transactions from honest Universal Validators grows linearly with the size of the attacker-inflated `PendingInbounds` map, and that cost is paid repeatedly (once per finalizing vote) — an O(n) scan per finalization, and O(n) finalizations, i.e. quadratic total work as an attacker keeps growing n.

### Impact Explanation
This is an unprivileged, non-network-level DoS vector reachable purely through ordinary user actions (sending inbound bridge transactions on external chains that honest UVs will faithfully observe and vote on): an attacker can grow `PendingInbounds` without bound (no expiry, no cap) and thereby degrade — and given enough volume, potentially stall — processing of `MsgVoteInbound` for every Universal Validator, since every finalization does a full table scan. Because `MsgVoteInbound` is gasless (per `x/uexecutor/README.md`), the cost of processing these votes is not paid for by the votes' senders, and Push Chain (the consuming validator/hub) absorbs the CPU cost of the growing scan on each finalization, directly threatening availability of the universal-execution consensus finalization path — the same "impact availability of the protocol" concern flagged in the original Nomad report.

### Likelihood Explanation
Moderate-to-high. An attacker only needs to generate many distinct, cheap external-chain transactions that Universal Validators will honestly relay (e.g., dust deposits on a low-fee chain), or induce enough transient variant divergence, to keep the `PendingInbounds` set large. Because expiry is deliberately disabled with no compensating cap, the set is a strict monotonic ratchet under adversarial pressure — unlike Nomad's queue, this one cannot even be pruned by waiting, compounding the severity over time.

### Recommendation
- Do not rely on a full-table `Walk` to reverse a ballot ID to its owning `PendingInboundEntry`. Add a secondary index `Map[ballotID -> utxKey]` maintained alongside `RecordInboundVote`, so `afterInboundBallotTerminal` can do an O(1) lookup instead of an O(n) scan.
- Reintroduce a bounded, enforced expiry (or a cap on total `PendingInbounds` size / per-source-chain rate limiting) so the collection cannot grow unboundedly under adversarial cheap-transaction pressure, with a proper escape-hatch/refund flow for entries that expire without reaching quorum (as the code comments indicate was the original intent before expiry was disabled).

### Proof of Concept
Conceptual (cannot be executed without a live testnet/devnet):
1. Attacker repeatedly submits many small/dust deposit transactions on a supported low-fee external chain (e.g., Solana or a cheap L2) to the gateway contract, each with a unique `tx_hash:log_index`.
2. Honest Universal Validators observe and relay each as `MsgVoteInbound`; each creates a new `PendingInboundEntry`/variant via `RecordInboundVote` (`x/uexecutor/keeper/inbound.go:27-88`).
3. Because `DefaultExpiryAfterBlocks = 100_000_000` (`x/uexecutor/types/constants.go:48`), any entries that lag behind quorum (network delay, validator downtime, minor variant divergence) never expire and accumulate permanently.
4. As `PendingInbounds` grows to thousands/millions of entries, every subsequent legitimate inbound-ballot finalization triggers `afterInboundBallotTerminal`'s full `Walk` over the entire map (`x/uexecutor/keeper/ballot_hooks.go:86-94`), so the per-finalization cost — and hence the cost of processing `MsgVoteInbound` transactions network-wide — grows linearly with attacker-controlled state size, with no fee to offset it since the message is gasless.

func (k Keeper) RecordInboundVote(
	ctx context.Context,
	inbound types.Inbound,
	voter string,
	ballotID string,
) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	height := uint64(sdkCtx.BlockHeight())
	utxKey := types.GetInboundUniversalTxKey(inbound)

	entry, err := k.PendingInbounds.Get(ctx, utxKey)
	if err != nil && !errors.Is(err, collections.ErrNotFound) {
		return err
	}
	if errors.Is(err, collections.ErrNotFound) {
		entry = types.PendingInboundEntry{
			UtxKey:          utxKey,
			CreatedAtHeight: height,
		}
	}

	// Find or create the variant for this ballot.
	variantIdx := -1
	for i, v := range entry.Variants {
		if v.BallotId == ballotID {
			variantIdx = i
			break
		}
	}
	if variantIdx < 0 {
		entry.Variants = append(entry.Variants, types.InboundVariant{
			BallotId:           ballotID,
			Inbound:            &inbound,
			Voters:             []string{voter},
			FirstVotedAtHeight: height,
			LastVotedAtHeight:  height,
			TerminalStatus:     uvalidatortypes.BallotStatus_BALLOT_STATUS_PENDING,
		})
	} else {
		v := &entry.Variants[variantIdx]
		// Idempotent voter add.
		already := false
		for _, x := range v.Voters {
			if x == voter {
				already = true
				break
			}
		}
		if !already {
			v.Voters = append(v.Voters, voter)
		}
		v.LastVotedAtHeight = height
	}

	k.Logger().Debug("inbound vote recorded",
		"utx_key", utxKey,
		"ballot_id", ballotID,
		"voter", voter,
		"variant_count", len(entry.Variants),
	)
	return k.PendingInbounds.Set(ctx, utxKey, entry)
}

// GetInboundUniversalTxKey: UTX identity from canonical (source_chain, tx_hash,
// log_index). Canonicalizes locals; caller's inbound is not mutated.
func GetInboundUniversalTxKey(inbound Inbound) string {
	chain := strings.TrimSpace(inbound.SourceChain)
	txHash := utils.LenientCanonicalizeTxHash(chain, inbound.TxHash)
	logIndex := strings.TrimSpace(inbound.LogIndex)
	data := fmt.Sprintf("%s:%s:%s", chain, txHash, logIndex)
	hash := sha256.Sum256([]byte(data))
	return hex.EncodeToString(hash[:]) // hash[:] converts [32]byte → []byte
}

// hashFields = sha256( hex(sha256(domain)) : hex(sha256(f0)) : ... ). Per-field
// hashing makes it injective — a sub-hash can't contain ':', so no field value
// can shift a boundary and collide with a different tuple.
func hashFields(domain collections.Prefix, parts ...string) string {
	hashed := make([]string, 0, len(parts)+1)
	d := sha256.Sum256(domain.Bytes())
	hashed = append(hashed, hex.EncodeToString(d[:]))
	for _, p := range parts {
		sum := sha256.Sum256([]byte(p))
		hashed = append(hashed, hex.EncodeToString(sum[:]))
	}
	final := sha256.Sum256([]byte(strings.Join(hashed, ":")))
	return hex.EncodeToString(final[:])
}

// GetInboundBallotKey: versioned canonical digest over every execution-
// relevant field (so quorum implies agreement on the outcome), excluding
// universal_payload (recomputed on-chain from raw_payload). Self-canonicalizes,
// so any caller gets one ballot per logical event.
func GetInboundBallotKey(inbound Inbound) (string, error) {
	chain := strings.TrimSpace(inbound.SourceChain)

	// nil RevertInstructions and an empty FundRecipient are semantically
	// identical (revert falls back to sender) — digest them identically.
	fundRecipient := ""
	if inbound.RevertInstructions != nil {
		fundRecipient = utils.LenientCanonicalizeAddress(chain, inbound.RevertInstructions.FundRecipient)
	}

	return hashFields(
		InboundBallotDomain,
		chain,
		utils.LenientCanonicalizeTxHash(chain, inbound.TxHash),
		strings.TrimSpace(inbound.LogIndex),
		utils.LenientCanonicalizeAddress(chain, inbound.Sender),
		// Recipient lives on Push Chain (EVM) regardless of source chain.
		utils.LenientCanonicalizeEVMAddress(inbound.Recipient),
		strings.TrimSpace(inbound.Amount),
		utils.LenientCanonicalizeAddress(chain, inbound.AssetAddr),
		fmt.Sprintf("%d", inbound.TxType),
		utils.CanonicalizeHexBlob(inbound.VerificationData),
		fundRecipient,
		fmt.Sprintf("%t", inbound.IsCEA),
		utils.CanonicalizeHexBlob(inbound.RawPayload),
		// universal_payload intentionally excluded (derived, ignored on-chain).
	), nil
}

func (h BallotHooks) afterInboundBallotTerminal(
	ctx context.Context,
	ballotID string,
	status uvalidatortypes.BallotStatus,
) error {
	// Ballot IDs are one-way canonical digests (not reversible), so locate
	// the owning audit-trail entry by scanning PendingInbounds for the
	// variant carrying this ballot ID. The pending set is small and
	// transient, and this hook only fires on terminal transitions.
	var (
		utxKey string
		entry  types.PendingInboundEntry
		found  bool
	)
	err := h.k.PendingInbounds.Walk(ctx, nil, func(key string, e types.PendingInboundEntry) (bool, error) {
		for _, v := range e.Variants {
			if v.BallotId == ballotID {
				utxKey, entry, found = key, e, true
				return true, nil
			}
		}
		return false, nil
	})
	if err != nil {
		return err
	}
