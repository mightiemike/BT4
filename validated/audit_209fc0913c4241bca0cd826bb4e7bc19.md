## Title
Builtin proving-gas cost floors to zero via integer division, allowing bouncer's proving-gas capacity check to be bypassed - (File: `crates/blockifier/src/bouncer.rs`)

### Summary
`BuiltinInstanceLimits::induced_gas_costs()` derives the per-instance proving-gas cost of each Cairo builtin/opcode by floor division: `cost = proving_gas / limit`. If the configured per-builtin instance limit is greater than (or comparable to) the block's total `proving_gas` budget, this integer division truncates to `0`. Any per-instance cost of `0` means that no matter how many instances of that builtin a transaction sender uses, the bouncer's proving-gas accounting for that primitive stays at zero — precisely the same "value * rate / large_denominator = 0" division-precision loss pattern as the Surge Protocol interest bug, applied here to Starknet's block-capacity/prover-cost accounting instead of interest.

### Finding Description
`BuiltinInstanceLimits::induced_gas_costs` computes, for each builtin, `cost = floor(proving_gas / limit)`: [1](#0-0) 

These derived costs (`BuiltinGasCosts`) are the "proving" weights used to convert a transaction's Cairo-primitive usage counters into gas via `cairo_primitives_to_gas`, which simply multiplies the (possibly-zero) per-unit weight by the usage count and accumulates: [2](#0-1) 

This proving-gas figure feeds `compute_proving_gas` → `get_tx_weights` → `Bouncer::try_update`, which is the mechanism that enforces the block's `proving_gas` capacity limit and rejects (`BlockFull`) transactions/blocks once the accumulated proving-gas budget is exhausted: [3](#0-2) [4](#0-3) 

If `derive(limit)` truncates to `0` for a given builtin (whenever `limit > proving_gas` budget for that config), then any transaction — submitted by any unprivileged sender — that uses that builtin heavily contributes **zero** proving-gas to the bouncer's accounting, exactly mirroring the reported bug: `interest = totalDebt * borrowRate * timeDelta / (365 days * 1e18)` truncating to zero when the numerator is small relative to the denominator. Here the "numerator" is the block-wide `proving_gas` budget and the "denominator" is the per-builtin instance limit; a legitimate (non-malicious) parameter combination in `BouncerConfig`/`BuiltinInstanceLimits` (analogous to the original report's legitimate pool decimals/rate combination) can zero out the derived weight.

The existing regression test only checks the default configuration, where all derived costs happen to be non-zero, but it does not guard against configurations where a limit exceeds the proving-gas budget: [5](#0-4) 

### Impact Explanation
`proving_gas` is the metric intended to bound the real cost of proving a block (SHARP/STWO). If a builtin's induced cost floors to zero, an unprivileged transaction sender can pack unbounded instances of that builtin into transactions/blocks without the bouncer ever accounting for the true proving cost of that resource. This defeats the block-capacity ("block full") safety mechanism for that resource, letting a sequencer build a block that is legitimately too expensive/large to prove even though the bouncer reports it fits within `block_max_capacity`. This can result in a block that cannot be proven, causing block/production failure and an inability of the network to progress on that block — matching the accepted impact category of "a network unable to confirm new transactions."

### Likelihood Explanation
Reachability requires no special privilege: any account can submit ordinary transactions that heavily exercise a specific builtin (e.g., `range_check`, `pedersen`, `keccak`, etc.) via normal contract calls. The triggering condition depends on the deployed `BouncerConfig`/`BuiltinInstanceLimits` values relative to the configured `proving_gas` budget — the same class of dependency the original report relied on (specific but legitimate parameter combinations), not on an attacker controlling protocol constants. Given that `induced_gas_costs` performs unchecked floor division with no minimum-cost floor (unlike other fee-computation paths in this codebase, e.g. `to_discounted_l1_gas`/`calculate_resource_gas_cost`, which explicitly use `checked_div_ceil`/`.ceil()` to round up and avoid exactly this class of truncation), this is a real latent gap in the bouncer's resource-weight derivation logic.

### Recommendation
- In `BuiltinInstanceLimits::induced_gas_costs`, use ceiling division (`div_ceil`) instead of floor division, or enforce a minimum derived cost of `1` per builtin, mirroring the ceiling-based approach already used elsewhere in the codebase (`Fee::checked_div_ceil`, `calculate_resource_gas_cost`, `sierra_gas_to_l1_gas_amount_round_up`).
- Add a validation/assertion at `BouncerConfig` construction/deserialization time that rejects (or logs/rejects) any configuration where a builtin's instance limit exceeds the block's `proving_gas` capacity, preventing a derived weight of zero.
- Extend the bouncer test suite to cover configurations where `limit >= proving_gas`, asserting the derived cost is never `0`.

### Proof of Concept
1. Configure (or, on a network using non-default `BouncerConfig`, observe) a `BuiltinInstanceLimits` value for some builtin `B` such that `limit_B >= block_max_capacity.proving_gas` (this is not attacker-controlled but is a plausible sequencer/network configuration analogous to the original report's plausible pool-parameter combination).
2. `BuiltinInstanceLimits::induced_gas_costs` computes `cost_B = proving_gas.0 / limit_B.get() == 0` — see the floor-division derivation at `crates/blockifier/src/bouncer.rs:456-457`.
3. Submit ordinary transactions (as any unprivileged sender) that each invoke builtin `B` many times (e.g., heavy `range_check`/`pedersen`/`keccak` usage in Cairo contract calls).
4. `cairo_primitives_to_gas` multiplies `cost_B (=0)` by the count of `B` uses, contributing `0` proving-gas for that builtin regardless of how many instances are used (`crates/blockifier/src/bouncer.rs:812-835`).
5. `Bouncer::try_update`'s `proving_gas` accumulator never reflects the true proving cost of builtin `B`, so the `has_room` capacity check (`crates/blockifier/src/bouncer.rs:671`) never triggers `BlockFull` for that resource, allowing the sequencer to keep adding transactions until the block is far larger (in real prover-cost terms) than `block_max_capacity.proving_gas` intends.

impl BuiltinInstanceLimits {
    /// Induces the per-instance proving-gas cost of each Cairo primitive from its per-block
    /// instance limit: `cost = floor(proving_gas / limit)`.
    pub fn induced_gas_costs(&self, proving_gas: GasAmount) -> BuiltinGasCosts {
        let derive = |limit: NonZeroU64| -> u64 { proving_gas.0 / limit.get() };
        BuiltinGasCosts {
            pedersen: derive(self.pedersen),
            range_check: derive(self.range_check),
            range_check96: derive(self.range_check96),
            poseidon: derive(self.poseidon),
            ecdsa: derive(self.ecdsa),
            ecop: derive(self.ecop),
            bitwise: derive(self.bitwise),
            keccak: derive(self.keccak),
            add_mod: derive(self.add_mod),
            mul_mod: derive(self.mul_mod),
            blake: derive(self.blake),
        }
    }

pub fn cairo_primitives_to_gas(
    cairo_primitives_counters: &CairoPrimitiveCounterMap,
    // NOTE: 'blake' is currently the only supported opcode, by being included in the
    // builtin_gas_costs.
    cairo_primitives_gas_costs: &BuiltinGasCosts,
) -> GasAmount {
    let cairo_primitives_gas =
        cairo_primitives_counters.iter().fold(0u64, |accumulated_gas, (name, &count)| {
            let cairo_primitive_weight =
                cairo_primitives_gas_costs.get_cairo_primitive_gas_cost(name).unwrap();
            cairo_primitive_weight
                .checked_mul(u64_from_usize(count))
                .and_then(|builtin_gas| accumulated_gas.checked_add(builtin_gas))
                .unwrap_or_else(|| {
                    panic!(
                        "Overflow while converting cairo primitives counters to gas.\nCairo \
                         primitive: {name:?}, Weight: {cairo_primitive_weight}, Count: {count}, \
                         Accumulated gas: {accumulated_gas}"
                    )
                })
        });

    GasAmount(cairo_primitives_gas)
}
