## Analysis Summary

The dYdX `AutoTrader` bug class is: **a value-determining computation is fetched from a source the attacker can influence, and then immediately consumed to move real funds, with no protection against manipulation between "read" and "use."** The closest native analog in this Push Chain scope is the auto-swap slippage protection used during inbound GAS/GAS_AND_PAYLOAD execution: `GetSwapQuote` reads a live, spot-price AMM quote and `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` immediately consume that same manipulable quote as the floor (`minPCOut`) for an irreversible on-chain swap of user funds. ### Title
Sandwichable spot-price oracle used as slippage floor for inbound PRC20 auto-swaps enables value extraction from user deposits - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/evm.go)

### Summary
`ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap` compute `minPCOut` for a PRC20→WPC auto-swap by calling the Uniswap V3 `QuoterV2.quoteExactInputSingle` against the pool's *current* on-chain reserves, then apply a flat 95% slippage tolerance and immediately execute `depositPRC20WithAutoSwap` with that value as the floor: [3](#0-2) 

This mirrors the AutoTrader flaw structurally: an attacker-influenceable value (here, the AMM spot price at the moment the quote/swap executes) is trusted as the ground truth for how much of the user's value is protected, with no TWAP, oracle deviation check, or external reference price.

### Finding Description
`GetSwapQuote` (in `x/uexecutor/keeper/evm.go`) performs a static `quoteExactInputSingle` call against the live Uniswap V3 pool reserves at the time of execution: [4](#0-3) 

The resulting `quote` is discounted by a fixed 5% and passed straight into `CallPRC20DepositAutoSwap`, which performs the actual swap in the same message-handling call, with the pool state unchanged from the quote step: [5](#0-4) 

Because the quote and the swap read/consume the *same* momentary pool state, protection against price movement between "fetch" and "use" doesn't exist — the risk instead is state prior to both calls. An unprivileged attacker, seeing that a validator's `MsgVoteInbound` (which will push the tally past quorum and trigger inbound finalization/auto-swap in the current block) is about to land, can submit their own ordinary swap transaction against the same Uniswap V3 pool with higher gas/priority to be included immediately before it in the same block. This shifts the pool's spot price. The subsequent `GetSwapQuote` call then reflects the *already-manipulated* price, so the "5% slippage protection" computed off that quote provides no real protection — the deposited PRC20 is swapped into PC at the attacker-manipulated rate, and the attacker profits by unwinding their position after the swap executes (a classic sandwich). The same pattern is reused for the gas-refund path: [6](#0-5) 

This satisfies the "AutoTrader" bug class: a value the attacker can move (pool spot price, analogous to `getTradeCost()`) is trusted for an on-chain fund-moving action, and the mitigation (5% band) is a static, quote-derived tolerance rather than an independent reference.

### Impact Explanation
This corrupts PRC20/native asset accounting during the auto-swap leg of inbound execution — victims (any user whose inbound deposit routes through GAS or GAS_AND_PAYLOAD with autoswap) receive less PC than the true fair-market rate for their deposited asset, with the delta captured by the attacker via a sandwich, and the same applies to the excess-gas refund swap path. This falls under the allowed impact of "corruption of PRC20 or native asset accounting ... refund accounting" and is triggerable purely via ordinary, unprivileged transaction submission (no validator or governance privilege needed) against a pool whose liquidity the attacker can move relative to the deposit size.

### Likelihood Explanation
Practical exploitability depends on the depth/liquidity of the specific Uniswap V3 pool used for a given PRC20 token and on the attacker's ability to land a transaction immediately before the finalizing vote in the same block — a standard MEV/sandwich capability, not a privileged one. For newly listed or thin-liquidity PRC20 pools this is straightforward; for deep pools the 5% band may absorb realistic single-block price impact, reducing (but not eliminating) practical severity.

### Recommendation
Do not derive the slippage floor purely from the same spot-price call that immediately precedes the swap. Use a time-weighted average price (TWAP) from the pool (or an independent oracle) as the reference price for computing `minPCOut`, and/or bound the deviation between the spot price and a longer-window reference before allowing the auto-swap to proceed, reverting (or falling back to the no-swap PRC20 deposit path) if the deviation exceeds a safe threshold.

### Proof of Concept
1. Attacker identifies a pending `MsgVoteInbound` in the mempool that will push an inbound (GAS or GAS_AND_PAYLOAD, autoswap route) to quorum/finalization in the next block.
2. Attacker submits a swap transaction against the same PRC20/WPC Uniswap V3 pool with sufficient size/priority to land in the same block, immediately before the finalizing vote transaction, shifting the pool's spot price unfavorably for sellers of the victim's PRC20.
3. The finalizing vote transaction triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, which calls `GetSwapQuote` — reading the now-manipulated price — computes `minPCOut = quote * 0.95`, and immediately calls `CallPRC20DepositAutoSwap`, swapping the victim's deposited PRC20 into PC at the manipulated rate.
4. Attacker reverses their swap in a following transaction (same or next block) to restore the pool price, realizing the delta extracted from the victim's auto-swap as profit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
