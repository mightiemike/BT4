### Title
Starknet OS `replace_class` syscall omits declared-class validation performed by blockifier, causing execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall (`execute_replace_class`, used both in the Cairo1 syscall path and the deprecated Cairo0 syscall path) unconditionally overwrites a contract's `class_hash` in `contract_state_changes` without ever checking that the requested `class_hash` corresponds to a declared class. The equivalent Rust blockifier logic that actually executes transactions when building a block explicitly performs this check and rejects the syscall otherwise. This is the same bug class as the external report: a state-mutating operation is allowed to "succeed" against a target (here, a class hash) that was never proven to exist/be valid, and downstream state is updated as if the operation succeeded.

### Finding Description
`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378` implements `replace_class` for Cairo1 execution: [1](#0-0) 
which calls `self.state.get_compiled_class(class_hash)?` to ensure the class is declared, and additionally rejects non-Cairo1 classes. The deprecated (Cairo0) syscall path performs the analogous check in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:795-807`: [2](#0-1) 
`syscall_handler.state.get_compiled_class(request.class_hash)?;` — if the class hash is undeclared, this returns an error and the transaction reverts (as demonstrated by the test at `crates/blockifier/src/execution/deprecated_syscalls/deprecated_syscalls_test.rs:375-391`, which asserts the error message contains "is not declared").

In contrast, the Starknet OS's own Cairo implementation, which independently re-executes the same transaction to build the STARK proof of the state transition, does not perform this check: [3](#0-2) 
The code contains an explicit acknowledgment of the gap: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` immediately before it unconditionally writes the new `class_hash` into `contract_state_changes` via `dict_update`. The deprecated syscall variant in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/deprecated_execute_syscalls.cairo:307-329` has the identical omission (no declared-class check at all).

### Impact Explanation
Because the blockifier (used to actually execute transactions and build the committed block/state diff) rejects `replace_class` calls targeting an undeclared class hash — reverting the inner call — while the OS's Cairo re-implementation of the same syscall silently accepts it and mutates `contract_state_changes`, the two execution engines can compute different results for the identical transaction. Since the OS is the trusted component that re-executes transactions to produce the proof attesting to the correctness of the sequencer's claimed state transition, any divergence between what the blockifier actually committed and what the OS proves constitutes a soundness break: the OS could construct a state transition/proof that does not match the block the blockifier actually produced (wrong committed state root), or, if a malicious/buggy path could otherwise legitimately reach `replace_class` with an undeclared class hash without reverting first in blockifier, the OS would silently accept a contract class replacement to a hash with no compiled code, which the OS treats as if it succeeded. This falls under "wrong committed root" / "honest-node divergence" between the transaction-execution engine and the block-proving engine.

### Likelihood Explanation
Any contract that calls the `replace_class` syscall with an attacker-chosen class hash is fully reachable by an unprivileged transaction sender through a normal `INVOKE` transaction — no special privileges are required, only a contract capable of invoking `replace_class_syscall` (Cairo1) or the deprecated `replace_class` syscall (Cairo0). Supplying an undeclared class hash is trivial and deterministic to trigger.

### Recommendation
Add the missing declared-class existence check to both OS syscall implementations, mirroring the blockifier's logic exactly:
1. In `execute_replace_class` in `syscall_impls.cairo`, before writing `new_state_entry`, verify that `class_hash` corresponds to a class present in `contract_class_changes` / the declared-classes structure the OS tracks, and fail the syscall (writing a failure response, consistent with how other syscalls in this file handle failure) if not declared.
2. Apply the same fix to `execute_replace_class` in `deprecated_execute_syscalls.cairo`.
3. Additionally confirm parity with the Cairo1-only restriction enforced in blockifier (`is_cairo1(&compiled_class)` in `syscall_base.rs:373`), since the OS should reject replacement with a V0 class hash exactly as blockifier does (per the test in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:31-53`, "Cannot replace V1 class hash with V0 class hash").

### Proof of Concept
1. Deploy (or use an existing) Cairo1 contract exposing a function that calls `replace_class_syscall(class_hash)` with an attacker-supplied `class_hash` value that is never declared on-chain (e.g., an arbitrary constant such as `0x11bca11000c1`, as already used for undeclared-class scenarios in `crates/blockifier_test_utils/resources/feature_contracts/cairo1/fuzz_revert.cairo:232-237`).
2. Submit an `INVOKE` transaction calling this function.
3. In the blockifier (actual sequencer execution), `syscall_base.rs::replace_class` calls `get_compiled_class(class_hash)` which fails with "... is not declared", causing the inner call (and syscall) to fail/revert; the contract's class hash in the real committed state diff is unchanged.
4. When the Starknet OS re-executes the identical transaction (e.g., during proving/re-execution, as exercised by `crates/starknet_os_flow_tests/src/tests.rs`), `execute_replace_class` in `syscall_impls.cairo`/`deprecated_execute_syscalls.cairo` performs no declared-class check and unconditionally updates `contract_state_changes` with the bogus `class_hash`, producing a state diff for that contract that differs from the one actually committed by the blockifier — a concrete divergence between the two execution engines for the same transaction and inputs.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
