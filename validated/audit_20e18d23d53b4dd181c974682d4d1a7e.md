### Title
Webhook HMAC does not bind the `X-Shopify-Shop-Domain` header, enabling cross-tenant webhook replay - ([File: packages/apps/shopify-api/lib/webhooks/validate.ts])

### Summary
The webhook HMAC is computed only over the raw request body and the shared app secret; the `domain` (shop) header that determines which tenant's session the payload is applied to is read out-of-band and is never part of the signed data. This mirrors the reported EIP-2612 issue: a value that determines the "context" the signature is valid for (chainID/domain separator there, shop domain here) is excluded from what is actually verified, so a signature/HMAC that is valid in one context can be replayed in another.

### Finding Description
`validateHmacFromRequestFactory` verifies the webhook by hashing only `rawBody` with the app's `apiSecretKey` and comparing it against the `X-Shopify-Hmac-Sha256` (or events-equivalent) header: [1](#0-0) 

After the HMAC check passes, `checkWebhookHeaders`/`checkWebhooksHeaders` reads the tenant-identifying `domain` header directly from the (unsigned) headers and returns it as `check.domain`, without any cryptographic linkage between that value and the HMAC that was just verified: [2](#0-1) 

That `domain` field is then trusted downstream to select which merchant's session to load and act on: [3](#0-2) [4](#0-3) 

Because the `apiSecretKey` used for HMAC computation is the single shared secret for the whole app (identical for every installed shop), a valid `(rawBody, hmac)` pair captured from any one shop's genuine webhook delivery remains cryptographically valid regardless of which `X-Shopify-Shop-Domain` header value accompanies it. An attacker who can obtain one legitimately-signed webhook payload (e.g., from their own store's app installation, or by intercepting/replaying a delivery) can resubmit the same body+HMAC with an arbitrary `X-Shopify-Shop-Domain` header pointing at a victim shop. `validate()` will report `valid: true` with the attacker-controlled `domain`, and the webhook handler will then load the victim's offline session and process the (attacker's own, but structurally valid) payload as if it originated from the victim shop.

This is directly analogous to the report's root cause: the domain-separator/chainID value that scopes a signature to a particular context is not itself covered by the signature check, so a signature valid in context A is accepted in context B.

### Impact Explanation
If a webhook handler uses the payload contents (e.g., ids, state changes) together with the trusted `domain`/`shop` value to mutate app-side, per-tenant data (e.g., marking an order paid, updating billing state, disabling a feature, writing audit records) without re-validating that the payload actually belongs to that shop, an attacker with a valid app installation on their own store can inject that (self-controlled) but validly-HMAC'd payload into another tenant's context, causing cross-tenant data confusion/corruption using only a genuine webhook subscription they control plus a forged HTTP header on the resend.

### Likelihood Explanation
Requires only unauthenticated HTTP access to the app's webhook endpoint and a previously captured/valid HMAC+body pair signed with the app's (shared, not per-shop) secret — no privileged access to the target shop is needed. Likelihood is limited by how strongly individual webhook handlers cross-check body content against the `domain`/shop before acting (which this codebase does not enforce at the framework layer), so actual exploitability depends on handler implementation, but the framework itself provides no binding between signature and tenant.

### Recommendation
Include the shop domain (and ideally webhook id / timestamp) in the data that is HMAC-verified, or cross-check the `X-Shopify-Shop-Domain` header against a shop identifier embedded in the payload/session before trusting `check.domain` to select a tenant session. Document to app developers that `webhookId`/`domain` headers are not covered by the HMAC and should not be solely relied upon to establish tenant identity for sensitive operations.

### Proof of Concept
1. App is installed on Shop A (attacker-controlled) and Shop B (victim), sharing the same `apiSecretKey`.
2. Attacker's shop legitimately triggers a webhook (e.g. `PRODUCTS_CREATE`), Shopify computes `hmac = HMAC-SHA256(apiSecretKey, rawBody)` and sends headers including `X-Shopify-Shop-Domain: shop-a.myshopify.com`.
3. Attacker captures `(rawBody, hmac)` and resends the identical POST to the app's webhook endpoint, replacing the header with `X-Shopify-Shop-Domain: shop-b.myshopify.com`.
4. `validateHmacFromRequestFactory` recomputes the HMAC over the same `rawBody` with the same shared secret and it matches, so `validHmacResult.valid === true`. [5](#0-4) 
5. `checkWebhookHeaders` returns `domain: 'shop-b.myshopify.com'` taken straight from the forged header. [6](#0-5) 
6. `authenticateWebhookFactory` loads Shop B's offline session via `ensureValidOfflineSession(params, check.domain)` and invokes the app's handler as though the payload came from Shop B. [7](#0-6)

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };

export function validateFactory(config: ConfigInterface) {
  return async function validate({
    rawBody,
    ...adapterArgs
  }: WebhookValidateParams): Promise<WebhookValidation> {
    const request: NormalizedRequest =
      await abstractConvertRequest(adapterArgs);

    const webhookType = detectWebhookType(request.headers);

    const validHmacResult = await validateHmacFromRequestFactory(config)({
      type: HmacValidationType.Webhook,
      rawBody,
      webhookType,
      ...adapterArgs,
    });

    if (!validHmacResult.valid) {
      if (validHmacResult.reason === ValidationErrorReason.InvalidHmac) {
        const log = logger(config);
        await log.debug(
          "Webhook HMAC validation failed. Please note that events manually triggered from a store's Notifications settings will fail this validation. To test this, please use the CLI or trigger the actual event in a development store.",
        );
      }
      return validHmacResult;
    }

    return checkWebhookHeaders(request.headers, webhookType);
  };
}

function getRequiredHeader(
  headers: Headers,
  headerName: string,
  missingHeaders: string[],
): string | undefined {
  const value = getHeader(headers, headerName);
  if (!value) {
    missingHeaders.push(headerName);
  }
  return value;
}

function checkWebhookHeaders(
  headers: Headers,
  webhookType: WebhookTypeValue,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  if (webhookType === WebhookType.Webhooks) {
    return checkWebhooksHeaders(headers);
  }
  return checkEventsHeaders(headers);
}

function checkWebhooksHeaders(
  headers: Headers,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };

  const name = getHeader(headers, headerNames.name);
  if (name) fields.name = name;

  const triggeredAt = getHeader(headers, headerNames.triggeredAt);
  if (triggeredAt) fields.triggeredAt = triggeredAt;

  const eventId = getHeader(headers, headerNames.eventId);
  if (eventId) fields.eventId = eventId;

  return {valid: true, ...fields};
}
