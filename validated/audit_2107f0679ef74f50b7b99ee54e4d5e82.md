### Title
Factory Proxy `initialize(owner)` Is Never Called at Genesis, Allowing Any Unprivileged Account to Front-Run Ownership of the UEA Factory - ([File: x/uexecutor/keeper/genesis.go])

### Summary
The external report describes `L2EthToken.initialize()` being callable by anyone because the privileged `msg.sender` who should own the call is never enforced at contract level. Push Chain has the same bug class in its own genesis wiring: `x/uexecutor`'s `InitGenesis` deploys the UEA Factory proxy/implementation via raw bytecode + storage-slot injection but never calls (or otherwise locks) the Factory's `initialize(address initialOwner)` entry point, leaving the `owner` slot of the live Factory contract unset after genesis on a real chain.

### Finding Description
`x/uexecutor/keeper/genesis.go`'s `deployFactoryEA` deploys three EVM accounts directly by writing account/code/storage state instead of issuing real contract calls: [1](#0-0) 

- `deployProxyAdminContract` explicitly writes the `ProxyAdmin`'s `Ownable.owner` slot with `SetState`: [2](#0-1) 
- `deployFactoryImplContract` and `deployFactoryProxy`, however, only install bytecode and the EIP-1967 admin/implementation slots — **no code path writes an `owner` value for the Factory contract itself**: [3](#0-2) 

The Factory's `FactoryV1ABI` exposes exactly the pattern from the external report — an `initialize(address initialOwner)` function with no visible caller restriction embedded in the module code, plus `owner`-gated administrative functions (`setUEAProxyImplementation`, and likely `registerNewChain`/`registerUEA`): [4](#0-3) 

`InitGenesis` for `x/uexecutor` deploys the factory bytecode/state at fresh genesis but never invokes `initialize` as part of that flow — it is completely absent from `deployFactoryEA`/`InitGenesis`: [5](#0-4) 

The only place in the repository that calls `initialize(owner)` on the Factory is test scaffolding (`test/utils/contracts_setup.go`), which calls it as an ordinary EVM transaction from an arbitrary signer: [6](#0-5) 

Because the genesis path never sets the Factory's owner slot and never calls `initialize` itself, the Factory contract on a freshly launched chain sits in an "uninitialized" state exactly like the L2EthToken analog: whichever account's `initialize(owner)` call against `FACTORY_PROXY_ADDRESS_HEX` lands first — which any unprivileged external account can submit as a normal EVM transaction the moment the chain starts producing blocks — becomes the permanent Factory `owner`.

### Impact Explanation
Once an attacker wins the race and becomes Factory `owner`, they can call `setUEAProxyImplementation` to point every subsequently deployed Universal Executor Account (UEA) at a malicious implementation contract. Since `x/uexecutor` deploys UEAs on demand via `CallFactoryToDeployUEA`/`DeployUEAV2` whenever a new user address needs one, this would let the attacker control execution logic (including `executeUniversalTx` signature checks and asset custody) for every UEA created after the takeover — i.e., unauthorized UEA execution and potential draining of user/protocol-controlled funds routed through those UEAs. This falls squarely into the "unauthorized UEA or CEA execution" and "unauthorized module-originated EVM execution" impact categories, triggered by an ordinary unprivileged account and no malicious validator/node/relayer assumption required.

### Likelihood Explanation
This requires no privileged access, no validator collusion, and no cryptographic break — only submitting a single, cheap, unauthenticated EVM transaction (`initialize(anyAddress)`) against a well-known, hardcoded proxy address (`FACTORY_PROXY_ADDRESS_HEX`) as early as possible after genesis/chain launch. This is a straightforward front-running race any bot watching mempool/genesis could win.

### Recommendation
Have `deployFactoryEA` (or the broader `InitGenesis`) atomically set the Factory's `owner` storage slot directly via `SetState` at genesis — the same way `deployProxyAdminContract` already does for the ProxyAdmin — rather than relying on a subsequent, unauthenticated `initialize` call. Alternatively/additionally, ensure the on-chain `Factory` implementation disables/locks `initialize` after construction (OpenZeppelin `_disableInitializers`) and have the module deterministically call `initialize` with the intended owner (e.g., the `uexecutor` module account or governance authority) as part of the same genesis transaction that deploys the bytecode, so no window exists for an external caller to win the race.

### Proof of Concept
1. Bring up a fresh chain; `x/uexecutor.InitGenesis` runs `deployFactoryEA`, installing the Factory proxy/implementation bytecode at `FACTORY_PROXY_ADDRESS_HEX` with no owner set.
2. Immediately after the chain accepts transactions, an attacker submits a normal `MsgEthereumTx` calling `initialize(attackerAddress)` on `FACTORY_PROXY_ADDRESS_HEX` (mirroring exactly what `test/utils/contracts_setup.go`'s `setupFactoryContract` does with a legitimate owner).
3. The attacker's transaction is accepted (no `msg.sender` restriction enforced by module code or genesis state), making `attackerAddress` the Factory `owner`.
4. Attacker calls `setUEAProxyImplementation(maliciousImpl)`; all UEAs deployed thereafter via `DeployUEAV2`/`CallFactoryToDeployUEA` now proxy to attacker-controlled logic.

func deployFactoryProxy(ctx context.Context, evmKeeper types.EVMKeeper) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	proxyAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)
	proxyAdminOwner := common.HexToAddress(types.PROXY_ADMIN_ADDRESS_HEX)
	factoryImplAddress := common.HexToAddress(types.FACTORY_IMPL_ADDRESS_HEX)

	// Compute the code hash from the runtime bytecode
	codeHash := crypto.Keccak256(types.ProxyRuntimeBytecode)

	// Create the EVM account object
	evmAccount := statedb.Account{
		Nonce:    1,             // to prevent tx nonce=0 conflicts
		Balance:  new(uint256.Int), // zero balance by default
		CodeHash: codeHash,      // link to deployed code
	}

	// Set the EVM account with the factory proxy contract
	err := evmKeeper.SetAccount(sdkCtx, proxyAddress, evmAccount)
	if err != nil {
		panic("failed to set factory proxy contract account: " + err.Error())
	}

	// Store the runtime bytecode linked to the code hash
	evmKeeper.SetCode(sdkCtx, codeHash, types.ProxyRuntimeBytecode)

	// Update proxyAdmin Slot with the proxyAdmin owner address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_ADMIN_SLOT, common.LeftPadBytes(proxyAdminOwner.Bytes(), 32))

	// Update proxyImplementation Slot with the factory implementation address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_IMPLEMENTATION_SLOT, common.LeftPadBytes(factoryImplAddress.Bytes(), 32))
}

func (k *Keeper) InitGenesis(ctx context.Context, data *types.GenesisState) error {

	if err := data.Params.ValidateBasic(); err != nil {
		return err
	}

	// Only deploy factory contracts on fresh genesis, not on import from export.
	// Re-deploying on import would overwrite existing EVM state or cause nonce collisions.
	if !data.Exported {
		deployFactoryEA(ctx, k.evmKeeper)

func setupFactoryContract(
	t *testing.T,
	app *app.ChainApp,
	ctx sdk.Context,
	factoryABI abi.ABI,
	opts AppSetupOptions,
	accounts TestAccounts,
) error {
	factoryAddr := opts.Addresses.FactoryAddr
	owner := common.BytesToAddress(accounts.DefaultAccount.GetAddress().Bytes())

	// Check initial factory owner
	ownerResult, err := app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after genesis: %s", common.BytesToAddress(ownerResult.Ret).Hex())

	// Initialize factory with owner
	_, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "initialize", owner)
	require.NoError(t, err)

	// Verify owner is set
	ownerResult, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after initialization: %s", common.BytesToAddress(ownerResult.Ret).Hex())
