### Title
`KVSessionStorage` allows duplicate session IDs to accumulate in a shop's session-ID list, corrupting `findSessionsByShop()` results - (File: `packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`)

### Summary
`KVSessionStorage.storeSession()` calls a private helper `addShopIds()` that appends the session id to the per-shop list of session ids on every store, without checking whether that id is already present in the list. [1](#0-0) [2](#0-1)  This is directly analogous to the reported `SwingTraderManager.swingTraders()` bug: an array/mapping that is supposed to represent a set of unique entities (`traderContract` there, session id here) is instead allowed to grow with duplicates because no membership check is performed before appending.

### Finding Description
Every implementation of `SessionStorage.storeSession` is expected to be idempotent for a given `Session.id` — calling it repeatedly with the same session (e.g. re-running the OAuth flow) should not duplicate that session in `findSessionsByShop()`. The `RedisSessionStorage` implementation correctly guards against this by checking `if (!idKeysArray.includes(idKey))` before pushing. [3](#0-2)  `KVSessionStorage.addShopIds`, however, unconditionally concatenates the new id(s) onto the existing array and persists it, with no de-duplication:
```ts
private async addShopIds(shop: string, ids: string[]) {
  const key = this.getShopSessionIdsKey(shop);
  const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
  await this.namespace.put(key, JSON.stringify([...shopIds, ...ids]));
}
``` [2](#0-1) 

`storeSession()` is invoked once per completed OAuth callback (an unprivileged, merchant/customer-reachable code path, reached after HMAC/state validation completes) for both offline and online sessions: [4](#0-3) [5](#0-4) 

Because offline session ids are deterministic (`offline_${shop}`), and online sessions are re-created every time a user's token expires or an embedded app session is re-established, `storeSession()` is expected to be called repeatedly with the *same* session id over the lifetime of an install. Each such call appends another copy of that id into the `shop:${shop}` KV list rather than replacing/deduping it. Every `findSessionsByShop(shop)` call then re-loads and returns the same session object once per duplicate entry:
```ts
public async findSessionsByShop(shop: string): Promise<Session[]> {
  const sessionIds = await this.namespace.get<string[]>(...);
  ...
  return Promise.all(sessionIds.map(async (id) => (await this.loadSession(id))!));
}
``` [6](#0-5) 

### Impact Explanation
This corrupts consumers of `findSessionsByShop`, mirroring the "duplicate share/balance counted twice" impact of the original finding. In `shopify-app-express`, `AppInstallations.includes()`/`.delete()` rely on `findSessionsByShop` to enumerate and delete all sessions for a shop; growing duplicate entries mean uninstall cleanup and the "app installed" check iterate/delete far more (stale/duplicate) ids than actually exist. [7](#0-6)  More importantly, the `shop:${shop}` KV value grows unboundedly and without limit as long as OAuth is repeated (an action any user/merchant can trigger without special privilege), which can eventually hit Cloudflare KV's per-value size limits and break `findSessionsByShop` for that shop entirely — a denial-of-service of the session-storage/auth-cleanup path.

### Likelihood Explanation
High reachability: `storeSession` is invoked on every successful (unprivileged) OAuth callback completion, which a single merchant/customer can trigger repeatedly (re-authenticating, refreshing an online token, or reopening an embedded app that re-establishes an online session). No special privileges or attacker-controlled data beyond normal app usage are required to keep appending duplicate ids.

### Recommendation
In `KVSessionStorage.addShopIds` (and symmetrically in `removeShopIds`), deduplicate before persisting, e.g. use a `Set` or the same `includes` check the Redis implementation uses:
```ts
private async addShopIds(shop: string, ids: string[]) {
  const key = this.getShopSessionIdsKey(shop);
  const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
  const merged = Array.from(new Set([...shopIds, ...ids]));
  await this.namespace.put(key, JSON.stringify(merged));
}
```

### Proof of Concept
1. Complete OAuth for a shop, which calls `storeSession(session)` with `session.id = offline_${shop}`. `addShopIds` sets `shop:${shop} = ["offline_shop"]`.
2. Trigger the OAuth callback again for the same shop (e.g. merchant re-installs/re-authenticates, or `useOnlineTokens` flow re-runs offline+online exchange) — `storeSession` is called again with the same id.
3. `addShopIds` reads `["offline_shop"]`, concatenates, and writes back `["offline_shop", "offline_shop"]` — no de-duplication.
4. `findSessionsByShop(shop)` now loads and returns the same `Session` object twice; repeating steps 2–3 causes unbounded duplication in the KV value.
