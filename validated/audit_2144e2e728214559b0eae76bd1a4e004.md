### Title
Stale `ContractStateCapsule` (energy_factor/energy_usage/update_cycle) survives self-destruct and is inherited by a CREATE2-redeployed contract at the same address - ([File: actuator/src/main/java/org/tron/core/vm/repository/RepositoryImpl.java])

### Summary
`ContractStateCapsule` tracks per-address dynamic-energy pricing state (`energy_usage`, `energy_factor`, `update_cycle`) and is looked up/updated purely by contract address via `RepositoryImpl.getContractState`/`updateContractState`. Nothing in the self-destruct (`suicide`/`suicide2`) or account-deletion path clears the corresponding entry in `ContractStateStore`, so a contract that is destroyed and later redeployed at the same address (a standard CREATE2 "metamorphic contract" pattern, which the codebase itself implements and tests) inherits the previous instance's energy pricing state instead of getting a fresh/default one.

### Finding Description
`ContractStateCapsule` stores `energy_usage`, `energy_factor`, and `update_cycle`, and is keyed only by contract address: [1](#0-0) 

State is read/updated purely by `byte[] address` with no notion of "contract instance" or creation transaction: [2](#0-1) 

The dynamic-energy pricing update path (`Program.updateContextContractFactor`) fetches this state by address and, if a value already exists, simply calls `catchUpToCycle` on it — it never checks whether the contract at that address is newly (re)deployed: [3](#0-2) 

There is a separate `isNewContract`/`putNewContract` mechanism in the repository (used e.g. by `suicide2` to special-case brand-new contracts created and destroyed within the same transaction), but this flag is never consulted by `updateContextContractFactor`/`addContextContractUsage` to decide whether to reset `ContractStateCapsule`: [4](#0-3) [5](#0-4) 

Self-destruct only marks the address for deletion in `ProgramResult`; the account's balance/tokens/frozen resources are transferred, but nothing here touches `ContractStateStore`: [6](#0-5) 

Redeployment at the same address is explicitly supported by CREATE2 in `createContractImpl`, which only rejects redeployment if an account/contract is currently considered to "already exist" (i.e., has not yet been removed): [7](#0-6) 

This CREATE2-destroy-redeploy ("metamorphic contract") flow is a recognized and tested pattern in this codebase (factory deploying at a deterministic address, later destroying and redeploying), e.g. in `FreezeTest.testCreate2SuicideToBlackHole`/`testCreate2SuicideToAccount`, which exercise deploy → freeze/use → `suicideWithException`/`suicideToAccount` → subsequent reuse of the same predicted address: [8](#0-7) 

None of the reachable code paths (`suicide`, `suicide2`, `createContractImpl`, `RepositoryImpl`) delete or reset the `ContractStateCapsule` entry keyed by the reused address. As a result, once the address becomes available again for a new deployment, the first energy-sensitive call to the new contract instance (`updateContextContractFactor`) will fetch the old `ContractStateCapsule` from `ContractStateStore` (via `getContractState`) and continue evolving it via `catchUpToCycle`, rather than starting from a fresh `reset()`ed state (which is only used when `contractStateCapsule == null` or `lastCycle == 0`/`lastCycle > newCycle`).

### Impact Explanation
An attacker who fully controls a CREATE2 factory contract can pre-condition the energy-factor state at a target address (drive `energy_usage`/`energy_factor` to an artificially low or high value), self-destruct the contract, and redeploy new logic at the identical address. The new contract instance inherits the stale `energy_factor`/`update_cycle`, giving it an artificially cheap (or artificially expensive) dynamic energy price for subsequent calls, until the on-chain `catchUpToCycle` decay/increase math converges back to a "normal" value over several energy cycles. This directly affects the TVM's per-contract dynamic energy pricing accounting invariant (energy price should be scoped to the live contract instance, not the address slot), and can be used to bias the effective gas cost of a redeployed contract used in fee-sensitive or arbitrage-sensitive flows for a bounded window of cycles after redeployment.

### Likelihood Explanation
Preconditions: `allowTvmConstantinople` (CREATE2) and the dynamic energy model (`VMConfig.getDynamicEnergyThreshold()` etc.) must be enabled — both are standard mainnet features exercised by the repo's own tests (`Create2Test`, `FreezeTest`). The attacker only needs to be an unprivileged contract deployer who can (1) deploy a CREATE2 factory, (2) deploy/drive/destroy a contract at the deterministic address, and (3) redeploy at the same address — all via ordinary `TriggerSmartContract`/`CreateSmartContract` transactions. This is fully repeatable and requires no special privileges, matching the CREATE2 "destroy and redeploy" pattern already validated as functional by `FreezeTest`.

### Recommendation
When a contract address is reused for a new deployment (in `createContractImpl`/`VMActuator.create()`), explicitly reset or delete the `ContractStateCapsule` entry for that address (e.g., call `contractState.updateContractState(newAddress, new ContractStateCapsule(currentCycle))` or delete the `ContractStateStore` entry) before the new contract can accrue energy usage. Alternatively, tie `ContractStateCapsule` to `isNewContract`/contract creation metadata so that `updateContextContractFactor` resets state whenever the underlying contract instance (not just the address slot) is new.

### Proof of Concept
Integration test plan (extends `VMTestBase`/pattern from `FreezeTest`/`Create2Test`):
1. Deploy a CREATE2 factory contract `Factory` and use it to deploy `Victim` at deterministic address `addr = create2(factory, salt, initcode)`.
2. Repeatedly trigger `Victim` energy-consuming calls across several `dynamic energy cycle` boundaries (advance `DynamicPropertiesStore.getCurrentCycleNumber()`) until `chainBaseManager.getContractStateStore().get(addr)` shows a non-default `energyFactor`/`updateCycle` (e.g., factor > 0).
3. Call `Victim.destroy()` (selfdestruct) via `TvmTestUtils.triggerContractAndReturnTvmTestResult`, and commit the transaction so the account is removed.
4. From the `Factory`, redeploy new bytecode at the identical `addr` via CREATE2 (same salt, same or different initcode producing the same address per EIP-1014 semantics, i.e., same factory+salt+codehash).
5. Assert: `chainBaseManager.getContractStateStore().get(addr)` is either `null` or has `energyFactor == 0 && updateCycle == currentCycle` immediately after redeployment (expected/fixed behavior), but in the current code it will instead show the inherited nonzero `energyFactor`/`updateCycle` from the destroyed instance (actual/buggy behavior), demonstrating the accounting-scope violation.

  @Override
  public ContractStateCapsule getContractState(byte[] address) {
    Key key = Key.create(address);
    if (contractStateCache.containsKey(key)) {
      return new ContractStateCapsule(contractStateCache.get(key).getValue());
    }

    ContractStateCapsule contractStateCapsule;
    if (parent != null) {
      contractStateCapsule = parent.getContractState(address);
    } else {
      contractStateCapsule = getContractStateStore().get(address);
    }

    if (contractStateCapsule != null) {
      contractStateCache.put(key, Value.create(contractStateCapsule));
    }
    return contractStateCapsule;
  }

  public void suicide(DataWord obtainerAddress) {

    byte[] owner = getContextAddress();
    byte[] obtainer = obtainerAddress.toTronAddress();

    if (VMConfig.allowTvmVote()) {
      withdrawRewardAndCancelVote(owner, getContractState());
    }

    long balance = getContractState().getBalance(owner);

    if (logger.isDebugEnabled()) {
      logger.debug("Transfer to: [{}] heritage: [{}]",
          Hex.toHexString(obtainer),
          balance);
    }

    increaseNonce();

    InternalTransaction internalTx = addInternalTx(null, owner, obtainer, balance, null,
        "suicide", nonce, getContractState().getAccount(owner).getAssetMapV2());

    int ADDRESS_SIZE = VMUtils.getAddressSize();
    if (FastByteComparisons.compareTo(owner, 0, ADDRESS_SIZE, obtainer, 0, ADDRESS_SIZE) == 0) {
      // if owner == obtainer just zeroing account according to Yellow Paper
      getContractState().addBalance(owner, -balance);
      byte[] blackHoleAddress = getContractState().getBlackHoleAddress();
      if (VMConfig.allowTvmTransferTrc10()) {
        getContractState().addBalance(blackHoleAddress, balance);
        MUtil.transferAllToken(getContractState(), owner, blackHoleAddress);
      }
    } else {
      createAccountIfNotExist(getContractState(), obtainer);
      try {
        MUtil.transfer(getContractState(), owner, obtainer, balance);
        if (VMConfig.allowTvmTransferTrc10()) {
          MUtil.transferAllToken(getContractState(), owner, obtainer);
        }
      } catch (ContractValidateException e) {
        if (VMConfig.allowTvmConstantinople()) {
          throw new TransferException(
              "transfer all token or transfer all trx failed in suicide: %s", e.getMessage());
        }
        throw new BytecodeExecutionException("transfer failure");
      }
    }
    if (VMConfig.allowTvmFreeze()) {
      byte[] blackHoleAddress = getContractState().getBlackHoleAddress();
      if (FastByteComparisons.isEqual(owner, obtainer)) {
        transferDelegatedResourceToInheritor(owner, blackHoleAddress, getContractState());
      } else {
        transferDelegatedResourceToInheritor(owner, obtainer, getContractState());
      }
    }
    if (VMConfig.allowTvmFreezeV2()) {
      byte[] Inheritor =
          FastByteComparisons.isEqual(owner, obtainer)
              ? getContractState().getBlackHoleAddress()
              : obtainer;
      long expireUnfrozenBalance = transferFrozenV2BalanceToInheritor(owner, Inheritor, getContractState());
      if (expireUnfrozenBalance > 0 && internalTx != null) {
        internalTx.setValue(internalTx.getValue() + expireUnfrozenBalance);
      }
    }
    getResult().addDeleteAccount(this.getContractAddress());
  }

  public long updateContextContractFactor() {
    ContractStateCapsule contractStateCapsule =
        contractState.getContractState(getContextAddress());

    if (contractStateCapsule == null) {
      contractStateCapsule = new ContractStateCapsule(
          contractState.getDynamicPropertiesStore().getCurrentCycleNumber());
      contractState.updateContractState(getContextAddress(), contractStateCapsule);
    } else {
      if (contractStateCapsule.catchUpToCycle(
          contractState.getDynamicPropertiesStore().getCurrentCycleNumber(),
          VMConfig.getDynamicEnergyThreshold(),
          VMConfig.getDynamicEnergyIncreaseFactor(),
          VMConfig.getDynamicEnergyMaxFactor(),
          VMConfig.allowStrictMath(),
          VMConfig.disableJavaLangMath())) {
        contractState.updateContractState(getContextAddress(), contractStateCapsule
        );
      }
    }
    contextContractFactor = contractStateCapsule.getEnergyFactor()
        + Constant.DYNAMIC_ENERGY_FACTOR_DECIMAL;
    return contextContractFactor;
  }
