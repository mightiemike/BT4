### Title
Bond-stake accrual bypasses `settle-rewards`, allowing retroactive reward mis-payment - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary
`add-staker-to-bond-for-cycle` (and its sibling `remove-staker-from-bond-for-cycle`) mutate `total-shares-staked-for-cycle` / `signer-shares-staked-for-cycle` for a bond directly, without first calling `settle-rewards`. Every other place in the contract that changes a signer's staked-shares for a cycle (`add-staker-to-signer-for-cycle`, `remove-staker-from-signer-for-cycle`, `unstake-sats-from-bond-cycle`) explicitly calls `settle-rewards` first, and the contract's own doc-comment states this call "MUST be called before any update to `signer-shares-staked-for-cycle`, because changes to that state will effect rewards calculations." [1](#0-0) 

### Finding Description
The reward accounting in pox-5 is a Synthetix-style accumulator: `earned = shares * (rpt_current - rpt_settled)` [2](#0-1) . `rpt` (rewards-per-token) only advances via `calculate-bond-rewards`, while `shares` (`signer-shares-staked-for-cycle` / `staker-shares-staked-for-cycle`) is mutated whenever stake is added or removed. Because `earned` is computed lazily the *next* time `settle-rewards`/`settle-staker-rewards` runs, any function that changes `shares` **must** first call `settle-rewards` to snapshot `earned` at the old share amount, before changing `shares` to the new amount — otherwise the next settle call will (incorrectly) apply the *new* share count retroactively to the entire unsettled `(rpt_current - rpt_settled)` interval.

The contract observes this invariant everywhere except for bond registration:
- `add-staker-to-signer-for-cycle` (STX-only path) settles first: [3](#0-2) 
- `unstake-sats-from-bond-cycle` (partial bond removal) settles first: [4](#0-3) 
- `remove-staker-from-signer-for-cycle` (STX-only removal) settles first: [5](#0-4) 

But `add-staker-to-bond-for-cycle`, which increases `total-shares-staked-for-cycle` and `signer-shares-staked-for-cycle` for a bond, has **no** `settle-rewards` call before those `map-set`s: [6](#0-5) . It only snapshots the *staker's* own settled marker to the signer's current `rewards-per-token-for-cycle` (line 1854-1862), which does not fix the signer-level unsettled interval. Likewise, `remove-staker-from-bond-for-cycle` decrements shares without settling first: [7](#0-6) .

This is structurally identical to the reported `pauseReward`/`updatePoolRate` bug: a state variable that feeds a reward-rate calculation (`shares`) is mutated by a function that omits the mandatory "settle/update the rate first" step that all its sibling functions perform.

### Impact Explanation
Because `rpt` (the accumulator) is a monotonically increasing cycle-wide value driven by `calculate-bond-rewards`, and `earned = shares * (rpt_current - rpt_settled)` is only evaluated when `settle-rewards` finally runs, an unprivileged bond staker who registers/increases a bond mid-cycle via `add-staker-to-bond-for-cycle` inflates `signer-shares-staked-for-cycle`/`total-shares-staked-for-cycle` immediately, but the signer's `rewards-per-token-settled` snapshot is not refreshed for that signer at the old (pre-increase) share count. The next time `settle-rewards` runs for that signer/cycle/bond, it will compute `earned` using the *increased* share count against the *entire* unsettled `rpt` delta — including the portion of the cycle before the stake increase occurred. This retroactively over-credits sBTC rewards to the signer/staker who just staked, at the expense of the shared reward pool (and other bond participants), bounded by `stake_increase * (rpt_current - rpt_settled) / PRECISION`. This is a minority-triggerable reward mis-payment bounded to the reward pool, matching the "High" impact bucket (reward mis-payment bounded to fees/pool funds).

### Likelihood Explanation
Medium-to-High: this triggers any time a staker calls the bond registration path (`register-for-bond` / equivalent) that reaches `add-staker-to-bond-cycles` → `add-staker-to-bond-for-cycle` while the signer already has unsettled rewards accrued (i.e., `rpt_current > rpt_settled`), which is the normal steady-state once `calculate-bond-rewards` has run at least once for that cycle. No special privilege, timing race, or majority collusion is required — a single staker acting alone can trigger the mis-accrual.

### Recommendation
Add a `(settle-rewards signer reward-cycle (some bond-index))` call at the start of `add-staker-to-bond-for-cycle` (and `remove-staker-from-bond-for-cycle`), mirroring the pattern already used in `unstake-sats-from-bond-cycle` and the STX-only staking helpers, so that the signer's unsettled rewards are snapshotted at the pre-mutation share count before `signer-shares-staked-for-cycle`/`total-shares-staked-for-cycle` are updated.

### Proof of Concept
1. Signer `S` has `signer-shares-staked-for-cycle = X` sats for `(cycle, bond-index)`.
2. `calculate-bond-rewards` runs, advancing `rewards-per-token-for-cycle` for `(cycle, bond-index)` from `rpt0` to `rpt1`, without anyone calling `settle-rewards` for `S` yet (`rpt_settled` for `S` is still `rpt0`).
3. A new staker registers a bond delegating to `S`, invoking `add-staker-to-bond-cycles` → `add-staker-to-bond-for-cycle`, which bumps `signer-shares-staked-for-cycle` for `S` from `X` to `X + Y` with **no** `settle-rewards` call. [8](#0-7) 
4. Later, any operation that finally calls `settle-rewards signer cycle (some bond-index)` computes `earned = (X + Y) * (rpt1 - rpt0) / PRECISION` instead of the correct `X * (rpt1 - rpt0) / PRECISION`, over-crediting `Y * (rpt1 - rpt0) / PRECISION` in sBTC rewards that were never actually staked during that interval. [9](#0-8)

;; Update all earned-but-unclaimed rewards for a signer, and update the snapshot
;; (signer-rewards-per-token-settled-for-cycle) for the signer.
;;
;; This MUST be called before any update to `signer-shares-staked-for-cycle`,
;; because changes to that state will effect rewards calculations.
(define-private (settle-rewards
        (signer principal)
        (reward-cycle uint)
        (bond-index (optional uint))
    )
    (let (
            (shares (get-signer-shares-staked-for-cycle signer reward-cycle bond-index))
            (rewards-per-token (get-rewards-per-token-for-cycle reward-cycle bond-index))
            (earned (compute-earned-rewards
                shares
                rewards-per-token
                (get-signer-rewards-per-token-settled-for-cycle signer reward-cycle bond-index)
                (get-signer-unclaimed-rewards-for-cycle signer reward-cycle bond-index)
            ))
        )
