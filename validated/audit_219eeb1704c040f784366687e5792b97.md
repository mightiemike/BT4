I have enough evidence to write up this finding. The vulnerability pattern is confirmed: `GetSwapQuote` fetches a spot price from Uniswap V3's `QuoterV2` immediately before the actual swap executes, both within the same atomic keeper call, with a fixed 5% slippage tolerance applied on top of that (already potentially manipulated) spot quote.

### Title
Sandwichable auto-swap: on-chain spot quote used as its own slippage bound lets attackers extract value from inbound gas-token swaps and gas refunds - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`GetSwapQuote` queries Uniswap V3's `QuoterV2.quoteExactInputSingle` for the *current* spot price of the internal PRC20/WPC pool, and the caller immediately derives `minPCOut = quote * 95 / 100` from that same value before executing the real swap via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`. Because the "protection" bound is derived from the manipulable spot price itself rather than an independent, attacker-resistant reference (e.g., a TWAP or externally supplied minimum), an unprivileged EVM user on Push Chain can move the pool price with an ordinary swap transaction immediately before the quote is read, letting the module compute `minPCOut` against the already-skewed price, then reverse the manipulation immediately after, extracting value from the deposited/refunded PRC20 amount at the expense of the depositing user / protocol.

### Finding Description
Three flows on Push Chain automatically swap a user- or protocol-controlled PRC20 amount for native PC/WPC through the internal Uniswap V3 pool, using a "quote-then-swap" pattern that looks like slippage protection but is not:

1. `ExecuteInboundGas` (GAS-only inbound deposits): fetches `quote` via `k.GetSwapQuote`, computes `minPCOut := quote*95/100`, and calls `k.CallPRC20DepositAutoSwap` with that bound. [1](#0-0) 

2. `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound): identical pattern. [2](#0-1) 

3. `applyGasRefund` (excess gas fee refund on outbound finalization): identical pattern, swapping the leftover gas token back to PC via `CallUniversalCoreRefundUnusedGas`. [3](#0-2) 

All three rely on `GetSwapQuote`, which performs a non-committing (`commit=false`) call to `quoteExactInputSingle` and returns whatever the pool's current spot state reports: [4](#0-3) 

The actual swap is then executed by `CallPRC20DepositAutoSwap`, a `DerivedEVMCall` with `commit=true` using the module account, in the same keeper invocation: [5](#0-4) 

The upgrade handler comments confirm this was intentionally added as the fix for a previous 0-slippage swap, describing it as "Uniswap V3 QuoterV2 ... to obtain an on-chain swap quote and pass minPCOut (quote × 95%)": [6](#0-5) 

The flaw is that both the quote read and the swap execution reference the *same, current, on-chain* pool state. Nothing anchors `minPCOut` to a manipulation-resistant reference price (no TWAP, no external oracle, no user-supplied minimum). An attacker who can submit ordinary EVM transactions against Push Chain's internal Uniswap V3 pool (the same pool used for `WPC`/gas-token pairs) can:
- Predict that an inbound GAS/GAS_AND_PAYLOAD deposit or an outbound gas refund will be processed in an upcoming block (these are triggered deterministically once honest validators finalize the corresponding ballot/vote — a process entirely reachable by any user simply depositing on an external chain or having their outbound observed).
- Submit a transaction immediately before the module's deposit/refund-processing transaction that shifts the pool price unfavorably against the impending swap direction.
- Let the module's `GetSwapQuote` read the now-skewed price and compute `minPCOut` from it (still "protecting" 5% relative to the *skewed* price, not the fair price).
- Submit a back-running transaction that reverses the price manipulation, capturing the value the skewed swap extracted from the deposited/refunded amount.

This is the exact bug class in the referenced report: computing a "minimum output" from the same manipulable state the swap itself will execute against provides no real sandwich protection — the attacker manipulates the reference price, not just the execution price.

### Impact Explanation
This corrupts PRC20/native asset accounting for every GAS and GAS_AND_PAYLOAD inbound deposit, and every outbound gas-fee refund that takes the swap path. The victim user (the entity whose funds are deposited via `depositPRC20WithAutoSwap` targeting their UEA, or whose refund is computed via `refundUnusedGas`) receives less native PC than the fair-market swap would have produced, with the difference captured by the attacker. Because these flows execute in module-owned EVM calls with real value movement, and are reachable purely from ordinary unprivileged deposit/withdrawal usage (no validator, relayer, or TSS compromise required), this falls within scope: "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting ... token mapping."

### Likelihood Explanation
Reachable by any unprivileged user who can submit EVM transactions on Push Chain (front-run/back-run around the internal Uniswap V3 pool) combined with a normal, honestly-finalized inbound deposit or outbound observation for any other user. No malicious validator, node, relayer, or TSS participant assumption is required — only ordinary transaction submission and observation of the mempool/impending block containing the module's own swap-triggering call. Profitability depends on the internal pool's liquidity depth relative to the 5% band, which is plausible for lower-liquidity PRC20/gas-token pairs.

### Recommendation
Do not derive `minPCOut` solely from a spot quote fetched immediately before the swap. Options:
- Use a time-weighted average price (TWAP) from the Uniswap V3 pool (observed over a window resistant to single-block manipulation) as the reference price for computing `minPCOut`.
- Bound the maximum allowed single-block price deviation and revert (rather than execute) if the spot price deviates too far from a longer-window reference.
- For refunds/deposits where value is user-owned, consider letting the original transaction (deposit event, outbound registration) carry an attacker-independent minimum-output parameter set at submission time on the source chain, rather than computed retroactively by the module.

### Proof of Concept
1. Attacker observes an inbound `GAS` deposit event on a supported source chain (or their own outbound gas refund is imminent) that will be processed via `ExecuteInboundGas` / `applyGasRefund`.
2. Immediately before the block containing the finalizing vote/observation is processed, attacker submits a large swap against the internal Uniswap V3 pool (PRC20 ↔ WPC) in the direction that will make the pending auto-swap execute unfavorably (e.g., pushes WPC price down before a PRC20→WPC swap).
3. `k.GetSwapQuote` is called by the module and returns the now-skewed price; `minPCOut = quote*95/100` is computed from this skewed value, still leaving headroom for up to just under the manipulated deviation.
4. `k.CallPRC20DepositAutoSwap` executes the swap at the skewed price, producing less WPC/PC for the depositing/refunded user than fair value.
5. Attacker submits a back-running trade reversing their initial swap, realizing a profit equal to the value extracted from the victim's deposit/refund, minus pool fees.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
