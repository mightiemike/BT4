The reported issue (CVE-2019-16774) is a PHP-specific "object injection" flaw: PHP's `unserialize()` can instantiate arbitrary classes from attacker-controlled data and invoke magic methods (`__wakeup`, `__destruct`, `__toString`), which the cookie driver in phpfastcache exposed by deserializing untrusted cookie content instead of enforcing JSON.

This bug class has no structural analog in `protobuf-go`. Go's `proto.Unmarshal` and `protojson.Unmarshal` never instantiate arbitrary types from serialized data — they only populate fields of a message whose concrete Go type is already known and linked into the binary at compile time [1](#0-0) . Go has no equivalent to PHP's magic methods that execute attacker-influenced logic purely as a side effect of type construction/deserialization.

The closest structural pattern — `Any` type resolution via `FindMessageByURL`/`UnmarshalNew` in `protojson` and `anypb` — resolves a `type_url` string to a message type, but only among types already registered in the trusted, compile-time-linked global registry; it cannot instantiate or execute code for an attacker-supplied class that isn't already part of the trusted schema [2](#0-1) [3](#0-2) . This matches the stated precondition of a trusted schema and excludes attacker-supplied descriptors/resolvers, so there is no reachable "object injection" analog in scope. [4](#0-3)
