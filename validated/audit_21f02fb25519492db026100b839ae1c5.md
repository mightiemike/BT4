### Title
Signer global-state agreement threshold uses floor division while block-approval threshold uses ceiling, letting a sub-supermajority coalition force signer-set consensus - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` computes the 70% supermajority bar with **integer floor** division, while `NakamotoBlockHeader::compute_voting_weight_threshold`, the function that actually gates Nakamoto block-signature acceptance, computes the same nominal 70% bar with **ceiling** division. The two "70%" thresholds are supposed to represent the same supermajority requirement but silently diverge whenever `total_weight * 7` is not a multiple of 10, exactly the class of off-by-rounding bug described in the reference report (a threshold quietly rounds in the attacker's favor, letting less-than-intended stake force an outcome).

### Finding Description
Block signature verification requires a **ceiling**-rounded 70% of signer weight: [1](#0-0) 

But the signer-network's `GlobalStateEvaluator`, which determines the network-wide agreed active miner, burn view, protocol version, and transaction-replay set, uses **floor**-rounded division for the same nominal threshold: [2](#0-1) 

These two functions are meant to enforce the identical "supermajority" invariant, but they don't: for any `total_weight` where `total_weight * 7 % 10 != 0`, `compute_voting_weight_threshold` requires strictly more absolute weight than `reached_agreement`. For example, with `total_weight = 11`: `compute_voting_weight_threshold(11) = 8` (ceil(7.7)), but `reached_agreement` only requires `vote_weight >= 7` (floor(7.7)). A weight of exactly `7/11 ≈ 63.6%` therefore satisfies the signer-set's notion of "global agreement" on the current miner / burn view / tx replay set / protocol version (used throughout `determine_global_state`, `determine_global_burn_view`, `determine_latest_supported_signer_protocol_version`, and `find_majority_prefix_replay_set`), even though that same weight is below what the codebase's own block-signature-threshold function considers a valid 70% supermajority.

Since `reached_agreement` is a pure, deterministic function of `(vote_weight, total_weight)`, every signer computes the identical (wrong) answer, so this isn't a node-disagreement bug — it's a systemic under-enforcement of the supermajority requirement for signer-set global-state coordination, decoupled from the codebase's own stricter definition of "70%" used for actual block approval.

### Impact Explanation
A coalition holding weight in the gap `[floor(0.7*N), ceil(0.7*N))` — below the true supermajority the protocol intends and below what's needed to actually co-sign a block header — can unilaterally force the entire signer network's `GlobalStateEvaluator` to converge on:
- a specific "current miner" / tenure view (`determine_global_state`),
- a specific burn-chain view (`determine_global_burn_view`),
- a specific transaction-replay set (`get_global_tx_replay_set` / `find_majority_prefix_replay_set`),
- a specific signer protocol version (`determine_latest_supported_signer_protocol_version`).

This is a real divergence between the intended "signers agree" invariant and the actual weight required, which can steer signer coordination (miner selection, transaction-replay enforcement) using a bloc that would not qualify as a supermajority under the codebase's own ceiling-based definition used for block signature verification. This maps to the in-scope "signer weight below threshold" class.

### Likelihood Explanation
This does not require a majority (>50%) attacker and does not need any privileged role — any signer coalition whose combined weight happens to land in the floor/ceil gap (which occurs for the majority of `total_weight` values, since only multiples of 10 avoid it) triggers the divergence automatically as part of normal signer-set operation, not via a crafted edge case.

### Recommendation
Make `reached_agreement` (and `reached_disagreement`, which has the analogous issue on the complementary side) use the same ceiling-rounding convention as `NakamotoBlockHeader::compute_voting_weight_threshold`, ideally by sharing a single threshold-computation routine between `libsigner` and `stackslib` so the two can never drift apart again.

### Proof of Concept
1. Construct a `GlobalStateEvaluator` with `total_weight = 11` (e.g., 11 signers of weight 1, or any weight assignment summing to 11), mirroring `evaluator_with_total_weight` in [3](#0-2) .
2. Compute `NakamotoBlockHeader::compute_voting_weight_threshold(11)` → returns `8` (per the ceiling logic and the existing unit test pattern in [4](#0-3) ).
3. Call `evaluator.reached_agreement(7)` → returns `true` (per the floor logic in `reached_agreement`), even though `7 < 8`, the amount of weight actually required to co-sign a valid Nakamoto block per `compute_voting_weight_threshold`.
4. A coalition controlling weight `7` out of `11` can therefore push arbitrary `StateMachineUpdate`s (miner selection, burn view, tx replay set, protocol version) that the rest of the signer set's `GlobalStateEvaluator` will accept as "globally agreed," despite falling short of the ceiling-rounded 70% supermajority the codebase enforces everywhere else.

```rust
    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
```

```rust
    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
```
