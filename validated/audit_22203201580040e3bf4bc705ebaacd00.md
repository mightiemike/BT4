### Title
Gas-abstraction auto-swap slippage protection is derived from a manipulable AMM spot quote, enabling value extraction from bridging users - (File: `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
`ExecuteInboundGas` computes a "slippage-protected" minimum output for the PRC20→WPC auto-swap by taking a live Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote and multiplying it by 95%, then passes that `minPCOut` straight into the swap call. This is the same anti-pattern as the reported `getPriceFromAMM`/`getAmountsOut` issue: because the "minimum acceptable output" bound is derived from the *same* instantaneous AMM state that determines the *actual* swap output, an attacker who moves the pool price before this module-originated swap executes can force the auto-swap through at an attacker-favorable price while the computed slippage floor still "passes" (since it's 95% of the manipulated price, not 95% of a fair/TWAP price).

### Finding Description
In `x/uexecutor/keeper/execute_inbound_gas.go` (`ExecuteInboundGas`), step 4 does: [1](#0-0) 

1. `k.GetSwapQuote(...)` calls `QuoterV2.quoteExactInputSingle` on the live pool (spot state) to get `quote` — the analog of `getAmountsOut`: [2](#0-1) 
2. `minPCOut := quote * 95 / 100` is computed directly from that same spot quote.
3. `k.CallPRC20DepositAutoSwap(...)` is then invoked with this `minPCOut` as the slippage bound, executing the actual on-chain swap in the same or a very close block.

Because `minPCOut` is a percentage of the *quote itself* rather than a percentage of a manipulation-resistant reference price (e.g., a TWAP, an oracle price, or a governance-set expected rate), the "slippage protection" only protects against price movement *between* the quote call and the swap call — it provides zero protection against the pool price already being pushed to an unfavorable level by an attacker prior to (or in the same block as) this module-originated call. This is executed as a `DerivedEVMCall` from the `uexecutor` module account against a public, ordinary Uniswap V3 pool (`uniswapV3Quoter`/pool for PRC20↔WPC) that is reachable by any unprivileged EVM user, since anyone can trade against that pool with ordinary transactions or, if liquidity is thin, with a single large capital swap.

An unprivileged attacker can:
1. Observe an inbound bridging transaction is about to be finalized/executed for a given PRC20 token (inbounds are public, votes and pending-inbound state are queryable).
2. Submit an ordinary EVM transaction that swaps a large amount into/out of the PRC20/WPC pool to push the spot price in their favor, timed to land in the same block just before the module's `ExecuteInboundGas` call executes (block proposers/relative tx ordering within a block make this a standard sandwich setup).
3. When `ExecuteInboundGas` runs, `GetSwapQuote` reads the now-manipulated pool state, `minPCOut` is computed as 95% of this bad price, and `CallPRC20DepositAutoSwap` executes the deposit-and-swap at the manipulated rate — succeeding rather than reverting, because the floor was derived from the same corrupted price.
4. The attacker reverses their initial swap (or captures the value directly as swap counterparty), extracting value that should have gone to the bridging user's UEA in WPC.

This directly corrupts "PRC20 or native asset accounting" and "gas fee accounting"/"UniversalTx state" for the affected `UniversalTx`, causing the bridging user to receive up to ~5%-or-more less WPC than fair value (bounded loosely by the 5% band plus however far the attacker can move price within it, and worse if pool liquidity is thin since the quote itself can be pushed far beyond a "fair" 5% band before the floor even engages).

### Impact Explanation
This causes unauthorized loss of user-controlled funds during universal execution of the gas-abstraction inbound flow: the bridging user's inbound funds are swapped to WPC at an attacker-manipulated rate and the difference is captured by the attacker, with no revert or recourse because the slippage check is self-referential to the manipulated price. This falls squarely under "corruption of PRC20 or native asset accounting ... revert destination ... canonical UniversalTx state" and "stealing/draining/permanent loss ... of user or protocol-controlled funds" in the allowed-impact gate, reachable purely from an ordinary user's inbound deposit combined with an unprivileged attacker's own ordinary swap transactions — no privileged or validator-side compromise required.

### Likelihood Explanation
Likelihood depends on the depth/liquidity of the specific PRC20↔WPC Uniswap V3 pool and on the attacker's ability to get a transaction ordered immediately before the module's derived EVM call within the same block (or across blocks if the inbound execution is delayed by ballot finalization, giving even more manipulation window). For newly listed or low-liquidity PRC20 tokens this is straightforward and requires only moderate capital; for deep, high-liquidity pools it becomes capital-intensive, matching the "reduced but not eliminated" characterization from the source report itself.

### Recommendation
Do not derive the slippage floor from the same live quote used for the swap. Options:
- Use a manipulation-resistant reference price (TWAP over a meaningful window, e.g. Uniswap V3's built-in `observe`/oracle cardinality-based TWAP) to compute `minPCOut`, independent from the instantaneous `quoteExactInputSingle` call.
- Alternatively, bound the acceptable deviation between the spot quote and a longer-window TWAP, and revert (or route to a non-swap deposit) if the deviation exceeds a safe threshold, rather than always proceeding with a 95%-of-spot floor.
- Consider capping the maximum single-block price impact this auto-swap path is willing to accept regardless of the nominal slippage percentage, and/or route large-amount inbounds through a non-AMM path or require a governance-configured minimum liquidity check before permitting the auto-swap.

### Proof of Concept
Conceptual PoC (cannot be executed here, but the mechanism is deterministic from the code path):
1. Attacker monitors the mempool/PC block builder for a pending `PendingInbound`/vote finalization that will trigger `ExecuteInboundGas` for token `PRC20_X` swapping into `WPC` via the pool at fee tier from `GetDefaultFeeTierForToken`.
2. Attacker submits `swap(PRC20_X -> WPC, largeAmount)` on the same pool in a transaction ordered before the module's derived call in the same block, pushing the pool's spot price so that `quoteExactInputSingle` for `amount` (the bridging inbound amount) returns a materially reduced `quote`.
3. `ExecuteInboundGas` computes `minPCOut = quote*95/100` from this manipulated quote and calls `CallPRC20DepositAutoSwap`, which succeeds because the floor tracks the manipulated price rather than a fair price — see: [3](#0-2) 
4. Attacker reverses their initial swap (`swap(WPC -> PRC20_X)`) in a following transaction in the same or next block, realizing the difference in value at the bridging user's expense, while the bridging user's UEA receives WPC at the manipulated (bad) rate. [4](#0-3)

// GetUniversalCoreQuoterAddress reads the uniswapV3Quoter address stored in UniversalCore.
func (k Keeper) GetUniversalCoreQuoterAddress(ctx sdk.Context) (common.Address, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return common.Address{}, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, abi, ueModuleAccAddress, handlerAddr, false, nil, "uniswapV3Quoter")
	if err != nil {
		return common.Address{}, errors.Wrap(err, "failed to call uniswapV3Quoter")
	}

	results, err := abi.Methods["uniswapV3Quoter"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return common.Address{}, errors.Wrap(err, "failed to unpack uniswapV3Quoter result")
	}

	return results[0].(common.Address), nil
}

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
