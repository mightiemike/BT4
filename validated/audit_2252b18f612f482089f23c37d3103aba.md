### Title
Non-fair `Semaphore` in `GlobalPreemptibleStrategy` permits attacker retry-storms to starve legitimate callers of rate-limited RPC permits - (File: framework/src/main/java/org/tron/core/services/ratelimiter/strategy/GlobalPreemptibleStrategy.java)

### Summary
`GlobalPreemptibleStrategy` backs `GlobalPreemptibleAdapter`, which is used by `RateLimiterInterceptor` to gate public gRPC endpoints (e.g. `broadcastTransaction`, `getAccount`) configured with `GlobalPreemptibleAdapter` in `reference.conf`/`config.conf`. The semaphore is created via the non-fair constructor `new Semaphore(permits)`, so waiting threads have no FIFO ordering guarantee and can be perpetually "barged" by newly-arriving threads under sustained contention.

### Finding Description
`GlobalPreemptibleStrategy` constructs its semaphore with `sp = new Semaphore((Integer) mapParams.get(STRATEGY_PARAM_PERMIT).value);` [1](#0-0)  — this uses the single-arg `Semaphore(int)` constructor, which per the JDK is non-fair (barging) by default. `acquire()` calls `sp.tryAcquire(DEFAULT_ACQUIRE_TIMEOUT, TimeUnit.SECONDS)` with a fixed 2-second timeout per attempt and, on timeout/failure, simply returns `false` without any queueing or backoff bookkeeping. [2](#0-1) 

This is reached from unprivileged, unauthenticated gRPC clients through `RateLimiterInterceptor.interceptCall`, which calls `rateLimiter.acquirePermit(runtimeData)` (routed to `GlobalPreemptibleAdapter.acquire`) before allowing `next.startCall`. [3](#0-2)  Endpoints are wired to `GlobalPreemptibleAdapter` via reflective construction driven by config (`cName.equals("GlobalPreemptibleAdapter")`). [4](#0-3) 

Because the underlying `java.util.concurrent.Semaphore` is non-fair, when many attacker threads repeatedly call `tryAcquire(timeout)` in a tight retry loop, newly-arriving attacker threads can repeatedly acquire the permit ahead of a legitimate caller that has already been waiting in the queue — this is an inherent, documented characteristic of non-fair semaphores under sustained contention, not a logic bug introduced by custom code, but the code makes no attempt to mitigate it (no fairness flag, no request queuing/prioritization, no per-caller quota).

There is no accounting, auth, or fairness guard anywhere in this path that would prevent this: `acquirePermit`/`release` treat all callers identically regardless of identity, and the semaphore is shared globally per RPC method across all clients.

### Impact Explanation
For any RPC method configured with `GlobalPreemptibleAdapter` and a small `permit` value (e.g. `permit=1` for `broadcastTransaction`-style methods, per `reference.conf`/`config.conf` wiring), an attacker running many concurrent unauthenticated retry threads can statistically dominate the semaphore acquisition ahead of legitimate callers, degrading availability (livelock/DoS) of that specific endpoint for legitimate low-rate callers. This is limited to endpoint-level throughput/availability degradation — it does not grant unauthorized execution, value theft, or state corruption.

### Likelihood Explanation
Feasibility depends on: (1) the targeted RPC method actually being configured with `GlobalPreemptibleAdapter` and a low permit count, (2) the attacker being able to sustain a much higher retry rate than the legitimate caller, and (3) the JVM's actual non-fair `Semaphore` barging behavior manifesting statistically favorable outcomes for the flood of retrying threads over long-standing waiters — which is a probabilistic/architectural property of `java.util.concurrent.Semaphore`, not a guaranteed permanent-denial bug. It's a real starvation risk under load but "indefinite" total denial is not deterministic; it is a statistical DoS/throughput degradation rather than a hard livelock guarantee.

### Recommendation
Construct the semaphore with fairness enabled: `new Semaphore(permits, true)` in `GlobalPreemptibleStrategy`'s constructor, to give FIFO ordering to waiting callers and eliminate barging-based starvation. Additionally, consider per-IP/per-client sub-limits (already partially present via `IPQPSRateLimiterAdapter`) layered in front of the global preemptible limiter to bound any single caller's share of retry attempts.

### Proof of Concept
```java
// framework/src/test/java/org/tron/core/services/ratelimiter/strategy/GlobalPreemptibleStrategyFairnessTest.java
package org.tron.core.services.ratelimiter.strategy;

import static org.junit.Assert.assertTrue;

import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;
import java.util.concurrent.atomic.AtomicInteger;
import org.junit.Test;

public class GlobalPreemptibleStrategyFairnessTest {

  @Test
  public void legitimateCallerStarvedByAttackerRetryStorm() throws InterruptedException {
    // permit=1 mirrors a tightly rate-limited public endpoint (e.g. broadcast).
    GlobalPreemptibleStrategy strategy = new GlobalPreemptibleStrategy("permit=1");

    AtomicInteger legitimateSuccesses = new AtomicInteger();
    AtomicInteger attackerSuccesses = new AtomicInteger();
    final int DURATION_MS = 5000;
    long deadline = System.currentTimeMillis() + DURATION_MS;

    // Legitimate caller: low-rate, single thread.
    Thread legit = new Thread(() -> {
      while (System.currentTimeMillis() < deadline) {
        if (strategy.acquire()) {
          legitimateSuccesses.incrementAndGet();
          strategy.release();
        }
        try {
          Thread.sleep(50); // realistic client pacing
        } catch (InterruptedException ignored) {
        }
      }
    });

    // Attacker: many threads retrying as fast as possible.
    ExecutorService attackerPool = Executors.newFixedThreadPool(50);
    for (int i = 0; i < 50; i++) {
      attackerPool.submit(() -> {
        while (System.currentTimeMillis() < deadline) {
          if (strategy.acquire()) {
            attackerSuccesses.incrementAndGet();
            strategy.release();
          }
        }
      });
    }

    legit.start();
    legit.join();
    attackerPool.shutdownNow();

    // Expected assertion demonstrating the issue: legitimate caller's success
    // share collapses far below its fair proportional share under non-fair
    // semaphore + retry storm (this assertion is expected to FAIL on current
    // non-fair implementation, and PASS once fairness is enabled).
    double legitShare = (double) legitimateSuccesses.get()
        / (legitimateSuccesses.get() + attackerSuccesses.get() + 1e-9);
    assertTrue("legitimate caller starved: share=" + legitShare, legitShare > 0.05);
  }
}
```
Run this test against the current `new Semaphore(permits)` (non-fair) implementation and again after changing to `new Semaphore(permits, true)`; expect a materially higher `legitimateSuccesses` share with fairness enabled, confirming the starvation risk and the fix's effectiveness.
