## Title
Gas fee for universal payload/CEA execution is silently rounded to zero due to redundant `/1e18` division in `CalculateGasCost` - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`x/uexecutor/keeper/fees.go`'s `CalculateGasCost` double-divides the network base fee by `1e18` before computing `effectiveGasPrice * gasUsed`. This mirrors the reported `FarmKeeper` bug class: an incorrect scaling constant causes integer division to truncate the result to zero under realistic values, permanently losing the fee that should have been collected — except here the effect is systemic (near-total) rather than edge-case, because production `base_fee` values are configured well below `1e18`.

### Finding Description
`CalculateGasCost` in [1](#0-0)  does:

```go
baseFeeBig := baseFee.BigInt()
// @dev: ... This division unwraps the LegacyDec encoding back to the actual upc amount.
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
```

`sdkmath.LegacyDec.BigInt()` already returns the whole-number value the `Dec` represents (it internally "chops precision" by dividing the raw fixed-point integer by `10^18`) — it does **not** need a second `/1e18` to "unwrap" anything. The comment's premise ("1 upc = 1e18 in the LegacyDec representation" requiring this extra division) is incorrect for how `Dec.BigInt()` behaves.

Genesis/params configs across the repo set `base_fee` to values far below `1e18`, e.g. `"1000000000.000000000000000000"` (1e9) in [2](#0-1)  and [3](#0-2) . For any such value, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates `1e9 / 1e18` to `0` via Go integer division. `effectiveGasPrice` then becomes `0`, so `gasCost := effectiveGasPrice * gasUsed` is always `0`.

The only place this doesn't zero out is the manual test harness in [4](#0-3) , which artificially sets `baseFee` to exactly `1e18` — a value chosen (deliberately or not) to survive the extra division and produce `effectiveGasPrice = 1`, masking the bug in most integration tests.

This gas cost feeds `DeductGasFeesFromReceipt` in [5](#0-4) , which explicitly no-ops when `gasCost.Sign() <= 0`:

```go
if gasCost.Sign() <= 0 {
    return nil
}
```

This function is the sole gas-fee-collection mechanism for EVM execution triggered by inbound universal payloads (`FUNDS_AND_PAYLOAD`, `GAS_AND_PAYLOAD` inbound types), reachable via `ExecuteInboundGasAndPayload` [6](#0-5) .

### Impact Explanation
With any realistic `base_fee` (all shipped genesis/params configs use values well under `1e18`), `CalculateGasCost` always returns `0`. Consequently `DeductGasFeesFromReceipt` never burns any `upc` for the EVM gas consumed by a recipient's universal payload execution, regardless of `receipt.GasUsed`. Any unprivileged attacker submitting inbound `FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` events can drive arbitrary EVM execution on Push Chain (module-originated `DerivedEVMCall`) while paying zero gas fee — a systemic and permanent loss of protocol fee/gas-accounting integrity, matching the "corruption of gas fee accounting" allowed-impact category. This is not a narrow edge case (as in the original low-decimal-token report) but the default behavior for any chain configured with the documented/example base fee values.

### Likelihood Explanation
High. No privileged access is required — any external user submitting an inbound event with a `UniversalPayload` that gets voted in by honest validators triggers this code path. The bug is deterministic given standard configuration values already present in the repository's own genesis/test setup scripts.

### Recommendation
Remove the redundant `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` step — `baseFee.BigInt()` already yields the correct whole-`upc` value. Add a regression test that sets `base_fee` to a realistic value (e.g. `1e9`, matching production genesis defaults) and asserts `CalculateGasCost` returns a non-zero, correctly-scaled gas cost for non-zero `gasUsed`.

### Proof of Concept
1. Configure the fee market with `base_fee = "1000000000.000000000000000000"` (1e9), matching production/genesis defaults (see [3](#0-2) ).
2. Submit an inbound `FUNDS_AND_PAYLOAD` (or `GAS_AND_PAYLOAD`) event with a `UniversalPayload` targeting a contract that consumes non-trivial gas; get it voted in by validators.
3. Observe `k.CalculateGasCost(baseFee, ...)` [7](#0-6)  compute `effectiveGasPrice = int(1e9)/int(1e18) = 0`, hence `gasCost = 0`.
4. `DeductGasFeesFromReceipt` skips fee burning entirely [8](#0-7) , confirming the recipient's payload executed real gas-consuming EVM code for zero `upc` fee.

```go
func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
```

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
```
