### Title
Race condition in concurrent class writes causes permanent class-manager storage corruption / DoS - (File: crates/apollo_class_manager/src/class_storage.rs)

### Summary
`FsClassStorage::set_class` / `set_deprecated_class` are reachable concurrently for the same `class_id` because `ClassManager` runs behind a `ConcurrentLocalComponentServer` that clones the component and spawns a new task per inbound `AddClass`/`AddClassAndExecutableUnsafe` request. The underlying filesystem write path (`write_class_atomically` → `rename_to_persistent_dir`) is not designed for concurrent execution against the same `class_id`, similar in nature to the QEMU 9p `v9fs_wstat` race during file renaming (CVE-2018-19489), where concurrent operations on the same path lead to an unrecoverable/inconsistent state.

### Finding Description
`ConcurrentLocalComponentServer::process_requests` clones `ClassManager` and spawns a fresh `tokio::spawn` task per request (`crates/apollo_infra/src/component_server/local_component_server.rs:306-354`), so multiple `AddClass` requests carrying the *same* Sierra class (same resulting `class_hash`) — e.g. two duplicate `DECLARE` transactions, or a declare arriving via both `apollo_central_sync`/`apollo_p2p_sync` and the gateway/mempool path — can invoke `ClassManager::add_class` in parallel on independent clones of `CachedClassStorage<FsClassStorage>` (`crates/apollo_class_manager/src/class_manager.rs:70-113`).

Both concurrent calls perform the same non-atomic sequence in `FsClassStorage::set_class` (`crates/apollo_class_manager/src/class_storage.rs:506-522`):
1. `contains_class(class_id)` check (reads `class_hash_storage` marker) — TOCTOU race, both may observe "not present".
2. `write_class_atomically` → `create_tmp_dir` → writes files to a fresh temp dir → `rename_to_persistent_dir`.
3. `rename_to_persistent_dir` (`crates/apollo_class_manager/src/class_storage.rs:487-500`) checks `persistent_dir.exists()`, and if so calls `std::fs::remove_dir_all(&persistent_dir)` before `std::fs::rename(tmp_dir, persistent_dir)`.

Because two threads can interleave between the `exists()` check, `remove_dir_all`, and `rename` calls, one thread's freshly-renamed persistent directory can be deleted by the other thread's "orphan recovery" logic immediately after being created, or a `rename` can race against a `remove_dir_all` targeting the same destination, producing `ENOTEMPTY`/`NotFound` I/O errors. The code comment at `crates/apollo_class_manager/src/class_storage.rs:480-486` documents that `std::fs::rename` fails with `ENOTEMPTY` and "permanently wedges sync on the class" — this recovery logic assumes single-writer semantics per `class_id`, which the `ConcurrentLocalComponentServer` invalidates.

Because `mark_class_id_as_existent` (the durable existence marker write in `class_hash_storage`) only happens after the file rename succeeds (`crates/apollo_class_manager/src/class_storage.rs:518-519`), an error at this stage returns `FsClassStorageError::IoError`, propagating to `ClassManagerResponse::AddClass`/`AddClassAndExecutableUnsafe` as an error. If the same `class_id` continually retries (e.g. re-broadcast declare transactions or repeated sync attempts across multiple sources), this can repeatedly wedge, similar to the documented ENOTEMPTY permanent-wedge scenario, which the "orphan recovery" code was specifically written to work around for the *sequential*, non-concurrent case but does not fully solve for concurrent writers.

### Impact Explanation
A repeatedly failing/wedged class write on the class-manager filesystem storage can make a node unable to persist a declared class, causing the executable/sierra for that `class_id` to be permanently unavailable or inconsistent (missing `sierra`/`casm` file despite an existence marker, or vice versa), which is a state-storage corruption/denial-of-service condition — the class manager can become unable to serve `GetSierra`/`GetExecutable` for that class, and downstream execution (`blockifier`) relying on `get_compiled_from_class_manager` (`crates/blockifier/src/state/state_reader_and_contract_manager.rs:65-104`) would then fail to fetch the class, potentially causing that node to diverge from other honest nodes when processing declare/invoke transactions that depend on the affected class.

### Likelihood Explanation
The race requires two class-manager requests for the same `class_id` to be admitted and processed concurrently by the `ConcurrentLocalComponentServer` (up to 128 concurrent tasks by default, per `components.class_manager.local_server_config.max_concurrency` = 128 in `crates/apollo_node/resources/config_schema.json:782-786`). This is plausible in normal operation without any privileged access: duplicate/resubmitted `DECLARE` transactions for the same class, or overlapping calls from `apollo_central_sync` (`crates/apollo_central_sync/src/lib.rs:514-523`) and other declare paths, can trigger concurrent `set_class` calls for the same `class_id` under ordinary network conditions, not requiring a malicious operator.

### Recommendation
Serialize writes per `class_id` in `FsClassStorage` (e.g., a per-class-id lock or a global write mutex around `write_class_atomically`/`rename_to_persistent_dir`), or make `rename_to_persistent_dir`'s orphan-recovery truly idempotent/concurrency-safe (e.g., using a content hash comparison before `remove_dir_all`, and treating `ENOTEMPTY`/rename races as success rather than a hard error, similar to the pattern already used in `apollo_proof_manager/src/proof_storage.rs:124-137`).

### Proof of Concept
1. Submit (or replay via two independent ingestion paths) two `AddClass` requests carrying the identical Sierra class to the `class_manager` component within the same short window.
2. Both are dispatched to separate cloned `ClassManager` instances by `ConcurrentLocalComponentServer` (`crates/apollo_infra/src/component_server/local_component_server.rs:337-351`).
3. Both pass the `contains_class` check as "not present" and proceed to `write_class_atomically` → `rename_to_persistent_dir` for the identical `class_id`.
4. One thread's `rename` succeeds, populating the persistent directory; concurrently the other thread's `persistent_dir.exists()` check (racing right after) sees the just-created directory, calls `remove_dir_all` on it, then attempts its own `rename`, potentially failing with `ENOTEMPTY`/`NotFound` if timing interleaves further, or silently deleting the sibling thread's just-written data before the marker (`mark_class_id_as_existent`) is committed — leaving the class permanently missing/orphaned on disk with no automatic remediation available for the concurrent case.     /// Atomically moves the staged class directory `tmp_dir` into its content-addressed persistent
    /// directory.
    ///
    /// Recovers from a previous partial write: a crash between this rename and committing the
    /// existence marker (see `FsClassStorage::set_class`) can leave an orphaned, non-empty
    /// persistent directory. `std::fs::rename` refuses to replace a non-empty directory and fails
    /// with `ENOTEMPTY`, which permanently wedges sync on the class. Callers reach this only when
    /// the existence marker is absent, and the directory is named by the class hash, so an existing
    /// directory holds the same class; removing it lets the rename proceed and the marker get
    /// written, restoring filesystem/marker consistency.
    fn rename_to_persistent_dir(
        &self,
        tmp_dir: PathBuf,
        class_id: ClassId,
    ) -> FsClassStorageResult<()> {
        let persistent_dir = self.get_persistent_dir_with_create(class_id)?;
        if persistent_dir.exists() {
            warn!("Recovering orphaned class dir from a prior partial write: {persistent_dir:?}");
            std::fs::remove_dir_all(&persistent_dir)?;
        }
        std::fs::rename(tmp_dir, persistent_dir)?;

        Ok(())
    }

    async fn process_requests(&mut self) {
        let component_name = short_type_name::<Component>();
        info!(
            "Starting to process requests in the component {component_name} concurrent local \
             server",
        );

        let RequestProcessingMembers {
            component,
            mut high_rx,
            mut normal_rx,
            metrics,
            processing_time_warning_threshold_ms,
        } = self.local_component_server.get_processing_inner_members();

        let task_limiter = Arc::new(Semaphore::new(self.max_concurrency));

        tokio::spawn(async move {
            loop {
                // TODO(Tsabary): add a test for the queueing time metric.
                let (request, tx, request_id) = get_next_request_for_processing(
                    &mut high_rx,
                    &mut normal_rx,
                    &component_name,
                    metrics,
                )
                .await;

                // Acquire a permit to run the task.
                let permit = task_limiter.clone().acquire_owned().await.unwrap();

                // Clone the component for concurrent request processing.
                let mut cloned_component = component.clone();
                tokio::spawn(async move {
                    process_request(
                        &mut cloned_component,
                        request,
                        request_id,
                        tx,
                        metrics,
                        processing_time_warning_threshold_ms,
                    )
                    .await;
                    // Drop the permit to allow more tasks to be created.
                    drop(permit);
                });
            }
        });
    }

    pub async fn add_class(&mut self, class: RawClass) -> ClassManagerResult<ClassHashes> {
        let sierra_class = SierraContractClass::try_from(&class)?;
        let class_hash = sierra_class.calculate_class_hash();
        if let Ok(Some(executable_class_hash_v2)) =
            self.classes.get_executable_class_hash_v2(class_hash)
        {
            // Class already exists.
            return Ok(ClassHashes { class_hash, executable_class_hash_v2 });
        }

        let compilation_start_time = Instant::now();
        let (raw_executable_class, executable_class_hash_v2) =
            self.compiler.compile(class.clone()).await.map_err(|err| match err {
                SierraCompilerClientError::SierraCompilerError(error) => {
                    ClassManagerError::SierraCompiler { class_hash, error }
                }
                SierraCompilerClientError::ClientError(error) => {
                    ClassManagerError::Client(error.to_string())
                }
            })?;
        debug!(
            %class_hash,
            compiled_class_hash = %executable_class_hash_v2,
            compilation_elapsed_ms = compilation_start_time.elapsed().as_millis(),
            class_size_bytes =
                class.size().map_or("Failed to get class size".to_owned(), |size| size.to_string()),
            casm_size_bytes =
                raw_executable_class.size().map_or("Failed to get casm size".to_owned(), |size| size.to_string()),
            "Finished compiling class."
        );

        self.validate_class_length(&raw_executable_class)?;
        Self::validate_class_version(&sierra_class)?;
        self.classes.set_class(
            class_hash,
            class,
            executable_class_hash_v2,
            raw_executable_class,
        )?;

        let class_hashes = ClassHashes { class_hash, executable_class_hash_v2 };
        Ok(class_hashes)
    }
