### Title
Fulfillment-service HMAC validator performs no shop/tenant binding, enabling cross-tenant session hijack via the unauthenticated `X-Shopify-Shop-Domain` header - ([File: packages/apps/shopify-api/lib/fulfillment-service/validate.ts])

### Summary
`validate()` in `fulfillment-service/validate.ts` checks only that `HMAC-SHA256(apiSecretKey, rawBody)` matches the `X-Shopify-Hmac-Sha256` header; it accepts no shop identifier and performs no tenant binding whatsoever. Because the shared `apiSecretKey` is identical for every shop that has installed a given public app, any valid `(rawBody, hmac)` pair captured from one shop's legitimate fulfillment-service traffic remains valid when replayed verbatim against the same multi-tenant deployment. Downstream callers (`shopify-app-remix`/`shopify-app-react-router` `authenticate.fulfillmentService`) then trust the unsigned `X-Shopify-Shop-Domain` request header to select which tenant's offline session/access token to hand back, so an attacker who owns any shop on the app can pivot the same valid HMAC pair to obtain another shop's admin session.

### Finding Description
`validate()` delegates directly to `validateHmacFromRequestFactory`, which computes validity purely from `rawBody` and the `Hmac` header via `validateHmacString` — no `shop` parameter exists in `ValidateParams`/`AdapterArgs`, and none is consulted: [1](#0-0) [2](#0-1) 

The apiSecretKey used to sign this HMAC is the app's single client secret, shared across every shop that installs the app (confirmed by the test using `shopify.config.apiSecretKey`, a single config value, not a per-shop secret): [3](#0-2) 

The tenant is only determined downstream, in the framework-level `authenticate.fulfillmentService` handlers, which read the shop straight from the unsigned `X-Shopify-Shop-Domain` header and use it to fetch/refresh that shop's offline session: [4](#0-3) 

Because the header is not part of the HMAC input, any `(rawBody, hmac)` pair valid for Shop A is equally valid for a forged request declaring `X-Shopify-Shop-Domain: shop-b.myshopify.com`. `validate()` returns `valid: true` in both cases, and `ensureValidOfflineSession(params, shop)` then loads Shop B's real offline session/access token for the attacker-controlled request: [5](#0-4) 

No component in this chain (`validate()`, `validateHmacFromRequestFactory`, or `authenticate.fulfillmentService`) cryptographically binds the shop domain to the signed payload, so the "sessions are tenant-isolated" invariant is violated at the point where the untrusted header is trusted for session selection.

### Impact Explanation
This allows cross-tenant session/access-token exposure inside an app process: a request that appears to be validated fulfillment-service traffic for Shop A can be replayed to obtain and act with Shop B's offline admin session, matching Shopify's bounty "cross-tenant data/state access" and "stolen or injected access token" impact classes. Actual data-level impact is bounded by whatever the replayed payload references (e.g., fulfillment order IDs from Shop A won't resolve against Shop B), but the session/token itself is genuinely handed to an unauthenticated/cross-tenant caller, and any app logic that acts generically on the returned `admin` client (not solely on payload-embedded IDs) is fully exploitable cross-tenant.

### Likelihood Explanation
Preconditions match a realistic multi-tenant public-app deployment (one shared `apiSecretKey`, no shop check added by the host app). The attacker only needs to be a merchant who installs the app and configures/observes their own legitimate fulfillment-service callback traffic (which they can trivially capture, since it's delivered to an endpoint they operate) — no secret theft, no MITM, no privileged role required. The replay is a simple crafted POST with a substituted `X-Shopify-Shop-Domain` header, fully repeatable against any other tenant of the same deployment.

### Recommendation
Bind the shop to the HMAC-validated request instead of trusting an unsigned header: e.g., require callers to pass the expected shop explicitly to `validate()`/`validateHmacFromRequestFactory` and fail closed if it doesn't match an independently-verified identifier (such as one already tied to a known, pre-registered fulfillment-service/shop mapping), or cross-check `X-Shopify-Shop-Domain` against the shop for which the offline session was originally established before returning an authenticated `admin` client.

```ts
// packages/apps/shopify-api/lib/fulfillment-service/__tests__/fulfillment-service.test.ts (extension)
it('validate() succeeds identically regardless of which shop the request claims to be for', async () => {
  const shopify = shopifyApi(testConfig());
  const payload = {field: 'value'};
  const rawBody = JSON.stringify(payload);
  const hmac = await createSHA256HMAC(shopify.config.apiSecretKey, rawBody, HashFormat.Base64);

  const reqForShopA: NormalizedRequest = {
    method: 'GET',
    url: 'https://my-app.my-domain.io',
    headers: {
      [ShopifyHeader.Hmac]: hmac,
      [ShopifyHeader.Domain]: 'shop-a.myshopify.com',
    },
  };
  const reqForShopB: NormalizedRequest = {
    method: 'GET',
    url: 'https://my-app.my-domain.io',
    headers: {
      [ShopifyHeader.Hmac]: hmac, // same captured pair, replayed verbatim
      [ShopifyHeader.Domain]: 'shop-b.myshopify.com', // different tenant
    },
  };

  const resultA = await shopify.fulfillmentService.validate({rawBody, rawRequest: reqForShopA});
  const resultB = await shopify.fulfillmentService.validate({rawBody, rawRequest: reqForShopB});

  // Both succeed identically: validate() has no notion of "shop" at all.
  expect(resultA).toMatchObject({valid: true});
  expect(resultB).toMatchObject({valid: true});
});
```
Combined with `authenticateFulfillmentServiceFactory`, submitting the second (Shop-B-labelled) HTTP request against a live multi-tenant deployment causes `ensureValidOfflineSession(params, 'shop-b.myshopify.com')` to return Shop B's real offline session/access token to the caller, even though the HMAC pair originated from Shop A's traffic.

```typescript
import {BasicParams} from '../types';

import {createOrLoadOfflineSession} from './create-or-load-offline-session';
import {ensureOfflineTokenIsNotExpired} from './ensure-offline-token-is-not-expired';

export async function ensureValidOfflineSession(
  params: BasicParams,
  shop: string,
) {
  const session = await createOrLoadOfflineSession(params, shop);

  if (!session) return undefined;

  return ensureOfflineTokenIsNotExpired(session, params, shop);
}
```
