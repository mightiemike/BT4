## Title
Missing zero-address validation on `RevertInstructions.FundRecipient` allows attacker-controlled inbound events to burn refunded principal on revert - (File: `x/uexecutor/keeper/build_revert_outbound.go`)

### Summary
The external report's bug class — "functions that take an address as an argument do not validate the address is not `0`" — has a direct analog in Push Chain's inbound-revert flow. The `Inbound.RevertInstructions.FundRecipient` field, which is fully attacker-controlled (it is populated from the user's own source-chain deposit/payload data relayed by honest Universal Validators), is never checked against the zero address anywhere in the validation pipeline before it is used as the destination for a refund outbound.

### Finding Description
`Inbound.ValidateBasic()` and `Inbound.ValidateForExecution()` in [1](#0-0)  validate `Sender`, `Amount`, `AssetAddr`, and `Recipient` (for `FUNDS`/`GAS`/CEA payload types), but at no point validate `RevertInstructions.FundRecipient`. The only processing applied to it is format canonicalization: [2](#0-1) .

When inbound execution fails (e.g., an intentionally malformed/failing payload, disabled chain, or any other validation failure that routes to the revert path), `buildRevertOutbound` computes the refund recipient directly from this unchecked, attacker-supplied field: [3](#0-2) 

If `FundRecipient` is set to `EvmZeroAddress` ("0x0000000000000000000000000000000000000000", defined at [4](#0-3) ) or any other unspendable/burn address, this value passes straight through into the created `OutboundTx.Recipient`, which becomes a `PendingOutbounds` entry, gets picked up by Universal Validators, TSS-signed, and broadcast to the external chain — sending the refunded principal to an address nobody controls.

Unlike `Recipient` (checked with `utils.IsValidAddress` for `FUNDS`/`GAS`/CEA types at [5](#0-4) ), `FundRecipient` has no equivalent check at all — not even a hex-format check, let alone a zero-address rejection. I was unable to inspect `utils.IsValidAddress`'s implementation directly to confirm whether it explicitly excludes the zero address; if it doesn't, the `Recipient` field carries the identical unpatched risk for the non-revert `FUNDS`/`GAS` direct-payout path.

### Impact Explanation
This satisfies the "permanent freezing"/"permanent loss" allowed-impact bucket: honest validators and honest nodes faithfully execute the protocol's revert logic exactly as designed, but the destination address supplied by an ordinary unprivileged user is never checked, so the refunded value is irrecoverably burned once broadcast to the external chain. This is reachable purely through a default inbound submission path (an inbound event whose payload is engineered to fail, combined with a zero `FundRecipient`), with no privileged actor or malicious validator/relayer required.

### Likelihood Explanation
Medium. The trigger requires the attacker to deliberately (or accidentally) set `RevertInstructions.FundRecipient` to the zero address in their own deposit transaction, and to cause the inbound to fail so the revert path executes. Both conditions are entirely within an unprivileged user's control and require no coordination with validators or governance.

### Recommendation
Add an explicit check in `Inbound.ValidateForExecution()` (or immediately before use in `buildRevertOutbound`) rejecting `RevertInstructions.FundRecipient` when it equals `types.EvmZeroAddress` (case-insensitively), matching the existing pattern already used for the `Recipient` field. Apply the same zero-address exclusion to `utils.IsValidAddress` checks on `Recipient` if that helper does not already reject it.

### Proof of Concept
1. Attacker submits a deposit on the source chain gateway with `RevertInstructions.FundRecipient = "0x0000000000000000000000000000000000000000"` and a payload crafted to fail validation/execution (e.g., malformed universal payload).
2. Honest Universal Validators observe and vote the inbound via `MsgVoteInbound`; ballot finalizes normally.
3. Execution fails per design, `buildRevertOutbound` is invoked and sets `Recipient = FundRecipient = 0x0...0` with no rejection [6](#0-5) .
4. The `INBOUND_REVERT` outbound is queued, TSS-signed, and broadcast to the source chain, sending the refunded principal to the unspendable zero address — permanent loss of the funds that should have been returned.

func (p Inbound) ValidateBasic() error {
	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)
	if chain == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}
	if !strings.Contains(chain, ":") {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain must be in CAIP-2 format <namespace>:<reference>")
	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")
	}

	// Validate sender — needed for revert recipient fallback
	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	// Validate log_index — needed for UTX key
	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}

	// Validate tx_type enum — needed to route execution
	if _, ok := TxType_name[int32(p.TxType)]; !ok || p.TxType == TxType_UNSPECIFIED_TX {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid tx_type: %v", p.TxType)
	}

	return nil
}

// ValidateForExecution checks fields that are required for actual execution of the inbound.
// Called after ballot finalization, before ExecuteInbound. Failures here produce a failed
// PCTx and (for non-isCEA) a revert outbound, rather than dropping the vote.
func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}

func (k Keeper) buildRevertOutbound(sdkCtx sdk.Context, inbound *types.Inbound) *types.OutboundTx {
	recipient := inbound.Sender
	if inbound.RevertInstructions != nil && inbound.RevertInstructions.FundRecipient != "" {
		recipient = inbound.RevertInstructions.FundRecipient
	}

	outbound := &types.OutboundTx{
		DestinationChain:  inbound.SourceChain,
		Recipient:         recipient,
		Amount:            inbound.Amount,
		ExternalAssetAddr: inbound.AssetAddr,
		Sender:            inbound.Sender,
		TxType:            types.TxType_INBOUND_REVERT,
		OutboundStatus:    types.Status_PENDING,
		Id:                types.GetOutboundRevertId(inbound.SourceChain, inbound.TxHash, inbound.LogIndex),
	}
