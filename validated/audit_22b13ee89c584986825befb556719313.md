### Title
Naive regex-based text substitution on JSON-serialized Cairo0 contract program during hinted class hash computation can corrupt attacker-controlled string content, mirroring the log4j unescaped-forbidden-character bug class - ([File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs])

### Summary
The Log4j1XmlLayout advisory describes a class of bugs where user-controlled data is written into a structured format (XML) without properly handling characters that have special meaning in that format, corrupting the output and causing downstream consumers to silently misinterpret or drop data. The Starknet OS's deprecated (Cairo0) class-hash computation contains an analogous pattern: it re-serializes a declarer-controlled contract program to JSON and then performs **regex-based text surgery on the raw JSON string** (rather than manipulating structured values) to achieve backward-compatible formatting before hashing it with Keccak.

### Finding Description
`compute_cairo_hinted_class_hash` in [1](#0-0)  serializes a `CairoContractDefinition` (built from an attacker-supplied, declared Cairo0 `ContractClass`, including its `program.attributes` with free-form `name`/`value` string fields) into a JSON string using a custom `PythonJsonFormatter`, and — when no `compiler_version` is present — passes the resulting raw JSON text through `add_backward_compatibility_space`: [2](#0-1) 

This function operates on the JSON **as plain text** using regexes such as:
- `"cairo_type"\s*:\s*"\(([^"]*)\)"` — captures content up to the first `"` after `(`.
- `"value"\s*:\s*"(.*?)"` — a non-greedy match that stops at the first `"`.

Neither pattern accounts for JSON string escaping (e.g., a value containing an escaped quote `\"`, or characters that coincidentally form a `key: value` pattern once matched by `pair_regex`/`paren_regex`). Since `AttributeScope.name` and `AttributeScope.value` are attacker-controlled strings coming directly from a declared Cairo0 program's `attributes` section (part of `program.debug_info`/`attributes`, which is user-supplied when declaring a class), a declarer can craft attribute `value`/`name` strings containing quote or parenthesis characters that are not properly escaped-aware by these regexes. This can cause the regex substitutions to match/replace the wrong span of text (e.g., spanning across a legitimate string boundary into adjacent JSON), corrupting the exact byte sequence that is subsequently hashed with Keccak in `compute_cairo_hinted_class_hash` and consumed by `compute_deprecated_class_hash` in [3](#0-2) .

Because the hinted class hash and the resulting deprecated class hash feed directly into `class_hash` verification for Cairo0 declared classes (checked against the value the declarer supplied, and ultimately relied upon by consensus-critical class-hash bookkeeping), any divergence between the intended canonical serialization and what this regex-based sanitizer actually produces is a case of "malformed structured output silently consumed downstream" — the same root cause class as the Log4j1XmlLayout bug (CWE-116: Improper Encoding or Escaping of Output).

### Impact Explanation
If a crafted attribute value can shift what the regex captures/replaces, the computed hinted/deprecated class hash for a declared Cairo0 contract could:
- Diverge from the hash any other correct/reference implementation of the same algorithm would compute for the identical program, causing honest-node/implementation divergence on the class hash for that specific class, or
- Be computed inconsistently depending on subtle differences in attacker-supplied byte sequences, undermining the hash's role as a canonical, collision-resistant identifier of the program bytes.

This falls in the "state reads/aliasing" and "Starknet OS re-execution" reachable-path category, since Cairo0 class declaration and hashing occurs during Starknet OS processing of an attacker-submitted `Declare` transaction (a single class declarer's contribution).

### Likelihood Explanation
Exploitability depends on constructing a `program.attributes[].value`/`name` string whose embedded characters (quotes/parentheses/colons) cause the regex engine to select an unintended substring or corrupt an adjacent JSON token — this requires precise crafting and is not guaranteed to be trivially achievable for every input, and I was not able to fully trace whether this hinted/deprecated class hash code path is actually wired into a hint invoked during live OS execution versus only reachable from the standalone functions exercised by the unit tests I found (`crates/starknet_os/src/hints/class_hash/hinted_class_hash_test.rs`, `crates/starknet_os/src/hints/hint_implementation/deprecated_compiled_class/class_hash.rs`, `crates/starknet_os_flow_tests/src/utils.rs`). Given the tool budget was exhausted before I could confirm the hint registration/dispatch site that calls `compute_deprecated_class_hash` during actual OS transaction execution, I cannot state with full confidence that this is reachable from a live, unprivileged `Declare` transaction in production block building — this should be verified directly in the codebase.

### Recommendation
Replace the regex-based, string-level "backward compatibility space" fix-up with a proper JSON-value-level transformation (operate on parsed `serde_json::Value`/typed fields for `cairo_type`/`value`, inserting the space only inside known structural tokens, not via generic regex matching over arbitrary escaped string content). This removes the escaping-ambiguity class of bug entirely, analogous to how the Log4j fix moved from ad hoc string emission to escaping-aware serialization.

### Proof of Concept
Not independently verified due to tool/time constraints — a concrete PoC would declare a Cairo0 contract whose `program.attributes` contain a `value` string with an embedded, unescaped-looking quote/parenthesis sequence (e.g. `"a\": \"(b: felt)"`) and compare the `compute_cairo_hinted_class_hash` output before/after minor byte-level variations of that string to confirm the regex mis-captures span boundaries, corrupting the hashed bytes. This proof-of-concept and confirmation of the hint's reachability from a submitted `Declare` transaction should be completed with codebase access/tests (e.g., extending `hinted_class_hash_test.rs`).

pub fn compute_cairo_hinted_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    // Serialize to Value, sort all objects by keys for deterministic output, then to bytes.
    // The sorting is necessary because serde_json with `preserve_order` feature enabled
    // maintains insertion order instead of sorting keys.
    // TODO(Meshi): Compute hinted hashes when loading serialized contracts from storage, before
    // deserializing, to avoid back-and-forth serde.
    let contract_value = serde_json::to_value(contract_class)?;
    let sorted_contract_value = sort_json_value(contract_value);
    let contract_definition_vec = serde_json::to_vec(&sorted_contract_value)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let mut string_buffer = vec![];

    let mut ser = serde_json::Serializer::with_formatter(&mut string_buffer, PythonJsonFormatter);
    contract_definition.serialize(&mut ser)?;

    let mut raw_json_output = String::from_utf8(string_buffer)?;
    if contract_definition.program.compiler_version.is_none() {
        add_backward_compatibility_space(&mut raw_json_output);
    }

    let mut keccak_writer = KeccakWriter::default();
    keccak_writer
        .write_all(raw_json_output.as_bytes())
        .expect("writing to KeccakWriter never fails");

    let KeccakWriter(hash) = keccak_writer;
    Ok(truncated_keccak(<[u8; 32]>::from(hash.finalize())))
}

/// Adds space before the colon when formatting named tuple types.
/// This should be used for backward compatibility in the contract hash computation in versions
/// before 0.10.0.
/// For example, use "(a : felt)" instead of "(a: felt)".
pub fn add_backward_compatibility_space(input: &mut String) {
    let cairo_regex = Regex::new(r#""cairo_type"\s*:\s*"\(([^"]*)\)""#).unwrap();
    let value_regex = Regex::new(r#""value"\s*:\s*"(.*?)""#).unwrap();
    let paren_regex = Regex::new(r"\(([^()]+)\)").unwrap();
    let pair_regex = Regex::new(r"([^:\s,]+):\s*([^,\s)]+)").unwrap();

    // Fix cairo_type, which must be a single type (either a simple type or a tuple).
    *input = cairo_regex
        .replace_all(input, |caps: &regex::Captures<'_>| {
            let inner = &caps[1];
            let fixed = pair_regex.replace_all(inner, "$1 : $2");
            format!("\"cairo_type\": \"({fixed})\"")
        })
        .into_owned();

    // Fix only (key: value) pairs inside (...) in "value".
    *input = value_regex
        .replace_all(input, |caps: &regex::Captures<'_>| {
            let raw_value = &caps[1];
            let fixed = paren_regex
                .replace_all(raw_value, |paren_caps: &regex::Captures<'_>| {
                    let inner = &paren_caps[1];
                    let fixed_inner = pair_regex.replace_all(inner, "$1 : $2");
                    format!("({fixed_inner})")
                })
                .into_owned();
            format!("\"value\": \"{fixed}\"")
        })
        .into_owned();
}

pub fn compute_deprecated_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    let hinted_class_hash = compute_cairo_hinted_class_hash(contract_class)?;
    let contract_definition_vec = serde_json::to_vec(contract_class)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let FlatEntryPointFelts { external, l1_handler, constructor } =
        get_flat_entry_point_felts(&contract_definition.entry_points_by_type);
    let builtins = ascii_strs_as_felts(&contract_definition.program.builtins);
    let bytecode = hex_strs_as_felts(&contract_definition.program.data);

    let mut hash_state = HashState::<Pedersen>::new();
    hash_state.update_single(&DEPRECATED_COMPILED_CLASS_VERSION);
    hash_state.update_with_hashchain(&external);
    hash_state.update_with_hashchain(&l1_handler);
    hash_state.update_with_hashchain(&constructor);
    hash_state.update_with_hashchain(&builtins);
    hash_state.update_single(&hinted_class_hash);
    hash_state.update_with_hashchain(&bytecode);
    Ok(hash_state.finalize())
}
