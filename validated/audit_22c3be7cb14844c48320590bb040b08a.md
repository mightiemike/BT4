## Analysis

The external report's bug class is **order-of-operations precision loss**: performing a division before a multiplication truncates a value that would otherwise be non-zero once multiplied by a larger factor. I looked for an analog in Push Chain's gas fee accounting path (in scope per "corruption of ... gas fee accounting").

The clearest analog is `CalculateGasCost` in `x/uexecutor/keeper/fees.go`, used by `DeductGasFeesFromReceipt` to charge users for module-originated (`DerivedEVMCall`) EVM execution triggered from universal-payload inbound processing. [1](#0-0) 

### Title
Premature truncating division of `baseFee` before multiplying by `gasUsed` can zero out gas fee accounting - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` converts the feemarket's `LegacyDec` base fee to an integer "upc" amount via `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` **before** multiplying by `gasUsed`: [2](#0-1) 

### Finding Description
The code assumes (per its own comment) that the feemarket's `baseFee` (a `sdkmath.LegacyDec`) is "always a whole number of upc," so dividing its raw internal representation by `1e18` is claimed to be lossless. This assumption is not enforced or verified anywhere in this repository — `FeeMarketKeeper.GetBaseFee` is an external interface implemented by the vendored `cosmos/evm`/feemarket module, whose EIP-1559-style base-fee adjustment arithmetic operates on `Dec` values and is not guaranteed to always land on an exact multiple of `1e18` (fractional-upc base fees are a normal intermediate state of such adjustment algorithms as the fee moves up/down with block gas usage).

If `baseFee`'s raw `Dec` value ever falls strictly between `0` and `1e18` (i.e., a fractional "upc" base fee, which can arise organically from sustained low block-gas utilization since EIP‑1559 base fee decreases are proportional and can produce non-integer intermediate values), `baseFeeBig.Div(..., 1e18)` truncates to integer `0`. The function's later multiplication, `gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)`, then always evaluates to `0` — regardless of how large `gasUsed` is — because the precision was already destroyed by the premature division. Correct behavior (matching the reported fix pattern) would multiply full-precision `baseFee.MulInt64(gasUsed)` first and truncate/round to an integer "upc" amount only at the very end.

Downstream, `DeductGasFeesFromReceipt` treats `gasCost.Sign() <= 0` as "nothing to charge" and returns `nil` without calling `DeductAndBurnFees`: [3](#0-2) 

This means module-originated EVM execution (`DerivedEVMCall`, universal payload execution) proceeds with real gas consumption while the resulting fee is silently zeroed and never burned from the recipient account.

### Impact Explanation
This corrupts the gas-fee accounting invariant explicitly called out in scope ("gas fee accounting ... must not misroute value"): execution work is performed and gas is consumed, but the corresponding fee is truncated to zero and never deducted/burned, instead of the correct non-zero (if small) amount. This is a systemic under-charging bug rather than an isolated rounding-to-zero-on-dust case, because it can occur even when `gasUsed` is large (e.g., a full smart-contract call), as long as the base fee's raw fractional component sits below `1e18`.

### Likelihood Explanation
This is **conditional on the external feemarket keeper's actual base-fee value never being fractional**, an assumption I could not verify or falsify from within this repository since `FeeMarketKeeper` is only declared as an interface here (`x/uexecutor/types/expected_keepers.go`) and its concrete implementation lives in the vendored `cosmos/evm` module, which is outside this repo's indexed code. I could not locate the feemarket module's genesis parameters or base-fee adjustment implementation in this repository to confirm whether it can produce a non-integer-upc `Dec` value under honest-validator, ordinary-usage conditions. This uncertainty is material: if the assumption in the code comment holds by construction elsewhere in the stack, this is not exploitable; if it does not, it is a low-cost, unprivileged-attacker-reachable fee-bypass (an attacker only needs to interact during a period of naturally low network congestion to benefit from a fractional base fee).

### Recommendation
Do not rely on an unverified invariant about the external feemarket's `Dec` precision. Change the order of operations to multiply before truncating, e.g.:
```go
gasCostDec := baseFee.MulInt64(int64(gasUsed))
gasCost := gasCostDec.QuoInt64(1e18).TruncateInt().BigInt() // or RoundInt, matching desired rounding policy
```
This mirrors the report's recommended fix (multiply by the larger factor first, then divide/truncate once at the end) and ensures fee charged is proportional to `gasUsed` even when the base fee is fractional.

### Proof of Concept
Given the code as written:
```go
baseFeeBig := baseFee.BigInt()       // e.g. 5*10^17 (i.e. 0.5 "upc" worth, raw Dec int)
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18)) // => 0 (integer division truncates)
...
effectiveGasPrice := new(big.Int).Set(baseFeeBig) // == 0
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig) // == 0, even if gasUsed = 10,000,000
```
`DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns without charging any fee, while the corresponding EVM execution already consumed real gas. [4](#0-3) 

**Caveat**: I could not confirm within this repository whether the upstream feemarket implementation can actually produce a fractional (non-multiple-of-1e18) `LegacyDec` base fee under normal honest-validator operation — that logic lives in the external `cosmos/evm` feemarket module, not in indexed code here. If that module structurally guarantees base fee is always an integer number of upc, this finding is not exploitable and the code comment's assumption holds; that guarantee would need to be verified by inspecting the vendored feemarket module directly, which requires a full repository checkout beyond what the index covers.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
