This is a native analog of the reported issue: an on-chain-computed swap quote is used both as the "expected" reference and to derive the slippage tolerance, and both quote and execution happen atomically on the same manipulable AMM state, so an attacker can move the pool price beforehand to force the module's protocol-owned swap through at a bad rate.

### Title
Autoswap slippage baseline derived entirely from a manipulable on-chain quoter, allowing attacker-controlled sandwich extraction from protocol-initiated deposit/refund swaps - (File: `x/uexecutor/keeper/evm.go`)

### Summary
The `GetSwapQuote` helper reads a live spot quote from a Uniswap-V3-style `QuoterV2.quoteExactInputSingle` call [1](#0-0) , and every caller derives its slippage floor (`minPCOut`) as a fixed 95% of that same quote [2](#0-1) [3](#0-2) [4](#0-3) . Like `calcImpact()` in the external report, this quote is a same-block, on-chain "simulation" of the swap outcome computed from live pool state, and it is used to bound the very swap it is about to authorize on the identically manipulable state.

### Finding Description
Whenever an inbound `GAS` or `GAS_AND_PAYLOAD` deposit needs an auto-swap into native PC, or an outbound gas refund needs to swap the leftover gas token back to PC, `x/uexecutor` performs two sequential, module-initiated EVM calls against the same `UniversalCore` handler and the same underlying Uniswap V3 pool within one keeper execution:

1. `GetSwapQuote` — a `commit=false` static call to `QuoterV2.quoteExactInputSingle`, reading the pool's current price/liquidity [5](#0-4) .
2. `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` — a `commit=true` `DerivedEVMCall` that executes `depositPRC20WithAutoSwap`/`refundUnusedGas` on the handler, passing `minPCOut = quote * 95/100` as the only slippage protection [6](#0-5) [7](#0-6) .

Both calls execute against the same pool state at essentially the same point in the block (no external transaction can interleave between them). An unprivileged attacker can therefore move the Uniswap V3 pool's price in a preceding transaction in the same block (a classic sandwich/spot-price manipulation, not requiring any privileged role — only capital or a flashloan), so that by the time these two calls run, both the "expected" quote and the actual swap execute on the attacker-manipulated pool. Because the quote and the real trade come from the same corrupted state, the 5% tolerance offers no real protection: the manipulated quote simply certifies whatever bad rate the attacker has engineered, and the swap proceeds. This directly parallels the report's core defect — using an easily-manipulated on-chain "simulation" as the authoritative baseline for a swap's acceptability, rather than an attacker-independent reference or a validator/user-supplied bound.

Unlike the external report's DoS framing (baseline too high → permanent revert), the Push Chain instance is exploitable in the value-extraction direction: the manipulated low quote is accepted as "fair," and the protocol-owned deposit/refund swap executes at the attacker-engineered rate, directly reducing the PRC20/native amount credited to the user's UEA (`ExecuteInboundGas`/`ExecuteInboundGasAndPayload`) or the amount refunded to the sender (`applyGasRefund`) [8](#0-7) .

### Impact Explanation
This corrupts PRC20/native asset accounting for ordinary inbound `GAS`/`GAS_AND_PAYLOAD` deposits and for outbound gas refunds: users receive less minted/refunded value than the honest market rate, with the shortfall extractable by the attacker who manipulated the pool. This falls under "corruption of PRC20 or native asset accounting" and value drain from user-controlled funds in the allowed-impact gate, triggered purely by an unprivileged actor manipulating a public AMM pool — no relayer, validator, or admin compromise is required.

### Likelihood Explanation
Medium. It requires the attacker to have capital (or a flashloan) to move the specific Uniswap V3 pool used for the relevant PRC20↔WPC pair, and favorable transaction ordering within the block containing the inbound/outbound execution. Both are realistic for an external, unprivileged actor, especially on lower-liquidity PRC20 pools, and the fixed 5% band is a static, quote-derived tolerance rather than an attacker-independent check (e.g., TWAP, external oracle, or governance-set floor).

### Recommendation
Do not derive both the reference price and the acceptance tolerance from the same instantaneous on-chain quote. Use a manipulation-resistant reference (e.g., a TWAP over multiple blocks, or a registry-configured price/rate ceiling per token) to bound `minPCOut`, or widen the trust boundary by capping the maximum single-block price deviation the quoter can report before it's used for `minPCOut` computation in `execute_inbound_gas.go`, `execute_inbound_gas_and_payload.go`, and `outbound.go`'s `applyGasRefund`/`getSwapQuoteForRefund`.

### Proof of Concept
1. Attacker identifies the Uniswap V3 pool used for a given PRC20↔WPC pair (looked up via `GetUniversalCoreQuoterAddress`/`GetDefaultFeeTierForToken`) [9](#0-8) .
2. Attacker submits a large swap transaction to move the pool's spot price downward (increasing PRC20 price relative to WPC, or vice versa depending on desired direction) and times it to land in the same block, immediately before validators' `MsgVoteInbound`/`MsgVoteOutbound` transaction that triggers the module's `ExecuteInboundGas`/`applyGasRefund` flow.
3. `GetSwapQuote` reads the manipulated pool state and returns a depressed quote; `minPCOut` is computed as 95% of that depressed quote [2](#0-1) .
4. `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes on the still-manipulated pool, succeeding because the accepted floor was itself computed from the corrupted price.
5. Attacker reverses their initial swap (or lets arbitrageurs restore price), pocketing the difference between the fair rate and the rate the protocol's swap executed at, at the expense of the user's deposited/refunded value.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
