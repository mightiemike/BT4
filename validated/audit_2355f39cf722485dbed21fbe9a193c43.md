### Title
Auto-swap `minPCOut` slippage guard is derived from a manipulable Uniswap V3 spot quote (`QuoterV2.quoteExactInputSingle`), not a TWAP — (File: `x/uexecutor/keeper/evm.go`)

### Summary
Push Chain's inbound gas-deposit auto-swap flow (GAS and GAS_AND_PAYLOAD routes) computes the `minPCOut` slippage floor for `depositPRC20WithAutoSwap` using `GetSwapQuote`, which calls Uniswap V3 `QuoterV2.quoteExactInputSingle` — a spot/instantaneous-price quote — and then applies a flat 5% tolerance. This is the same category of flaw as the referenced Yield finding: using an unprotected, manipulable current-price source instead of a time-weighted average price (TWAP) to bound a swap that moves real user/protocol value.

### Finding Description
`GetSwapQuote` in `x/uexecutor/keeper/evm.go` queries the Uniswap V3 QuoterV2 contract for the current-block expected output amount: [1](#0-0) 

This quote is then used to derive the slippage floor with a fixed 5% haircut: [2](#0-1)  and identically in [3](#0-2) , and again for outbound gas refunds in [4](#0-3) .

The upgrade note itself documents that this replaced a 0-slippage call, confirming the quote is treated as the pricing reference for a real on-chain swap: [5](#0-4) 

`quoteExactInputSingle` reflects the Uniswap V3 pool's instantaneous reserves/tick, exactly the "wrong prices" pattern flagged in the Yield report — it is not equation-5.5 TWAP-derived. Because the WPC/PRC20 pool is a permissionless AMM, any unprivileged actor can move the pool's spot price with an ordinary swap transaction immediately before the module's `depositPRC20WithAutoSwap` executes (or in the same block, depending on tx ordering), then reverse the position afterward (classic sandwich). The quote fetched by `GetSwapQuote` will reflect the manipulated price, and the subsequent swap executed by `CallPRC20DepositAutoSwap` — [6](#0-5)  — is only protected down to 95% of that already-manipulated quote, not 95% of the fair/TWAP price. The attacker captures the difference between the fair price and the manipulated execution price, at the expense of the depositing user (who receives less PRC20/WPC than the true market rate) and/or the protocol accounting that treats the swap outcome as canonical.

### Impact Explanation
This directly corrupts PRC20/native asset accounting during the universal execution deposit-and-swap path: an unprivileged attacker can extract value from ordinary user deposits (GAS / GAS_AND_PAYLOAD inbound routes) and from outbound gas-fee refunds, both of which are triggered by default user transaction/deposit flows with no privileged actor involved. This falls squarely in the allowed impact bucket "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting... canonical UniversalTx state" and can constitute "stealing... of user or protocol-controlled funds" via sandwiching.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: it requires only a normal, permissionless swap on the WPC/PRC20 Uniswap V3 pool, something any external actor can do without compromising validators, TSS, or governance. The size of extractable value scales with swap size and pool liquidity/depth, and is bounded only by the fixed 5% slippage tolerance, which is generous enough to make many pools economically attackable.

### Recommendation
Replace or supplement the spot `QuoterV2.quoteExactInputSingle` call with a TWAP-based reference price (e.g., using the pool's `observe`/cumulative-tick mechanism as recommended in the original report) to bound `minPCOut`, or tighten/derive the slippage tolerance dynamically from a manipulation-resistant price source, and consider capping single-block price impact or requiring the executed price to be consistent with a longer observation window before accepting the swap outcome into canonical `UniversalTx`/`OutboundTx` state.

### Proof of Concept
1. Attacker identifies the WPC/PRC20 pool used by `UniversalCore` for a given gas token (`GetUniversalCoreQuoterAddress` / `GetUniversalCoreWPCAddress`).
2. Attacker submits a large swap to skew the pool's spot price just before (or in the same block ordering window as) a pending inbound GAS/GAS_AND_PAYLOAD deposit that will trigger `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`.
3. When the module calls `GetSwapQuote` → `CallPRC20DepositAutoSwap`, the quote and the executed swap both reflect the skewed price; `minPCOut` is only 95% of this skewed value, well within the manipulated range.
4. Attacker reverses their position (sells back) after the module's swap executes, capturing the price-impact differential at the expense of the depositing user/protocol.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
