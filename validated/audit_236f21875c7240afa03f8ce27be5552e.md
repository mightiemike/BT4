### Title
Unbounded Memory Allocation from Attacker-Controlled Array Length Before Gas Validation in Syscall Request Parsing - (File: crates/blockifier/src/execution/syscalls/vm_syscall_utils.rs)

### Summary
Analogous to CVE-2021-36374 (Apache Ant allocating memory based on an untrusted ZIP length field before validating it against actual constraints), the blockifier's syscall request parsing reads a length-prefixed felt array from Cairo VM memory and materializes it into a `Vec<Felt>` **before** the corresponding gas cost for that array's size is computed and checked.

### Finding Description
`execute_syscall` in [1](#0-0)  first calls `SyscallRequestWrapper::<Request>::read(vm, ...)` to parse the syscall request, and only afterwards computes `syscall_gas_cost` from `request.get_linear_factor_length()` and checks it against `gas_counter`. For syscalls whose request contains a variable-length array (e.g. `SendMessageToL1Request`, which embeds a `Calldata`/`L2ToL1Payload`), parsing is done via `read_felt_array`, which allocates and fully materializes a `Vec<Felt>` of attacker/contract-controlled size: [2](#0-1) . The underlying allocation happens in `felt_range_from_ptr`, which calls `vm.get_integer_range(ptr, size)` and collects the result into a `Vec`: [3](#0-2) .

The equivalent deprecated (Cairo0) syscall path is even more directly attacker-controlled: `read_felt_array` in the deprecated syscall hint processor takes `array_size` directly as a felt value read from VM memory (fully controlled by the executing contract's own code/hints, not derived from a validated pointer difference), converts it to a `usize`, and immediately calls `felt_range_from_ptr` to allocate a `Vec` of that size — with no upper bound check against gas, resource limits, or segment size before the allocation is attempted: [4](#0-3) .

In both paths, the length value used to size the allocation is taken from data that a contract deployer fully controls (Cairo0/Cairo1 bytecode executed during a transaction), and the resource/gas cost of that length is only accounted for *after* the allocation attempt, mirroring the CWE-130 root cause of the Ant advisory: a length field derived from untrusted input is used to drive memory allocation without first validating it is proportionate to the resources the caller has paid for.

### Impact Explanation
Since blockifier execution is deterministic and re-executed identically by every honest node validating/proposing a block (and again by the Starknet OS during re-execution), a single malicious transaction invoking a declared contract that sets an oversized `array_size`/payload length in a `send_message_to_l1` (or other length-prefixed) syscall request can trigger a very large memory allocation on every node processing that transaction, before any gas-based limit takes effect. This can induce excessive memory pressure or out-of-memory failure uniformly across all sequencer/validator nodes, preventing them from completing block production/validation — i.e., a network unable to confirm new transactions, or at minimum node crashes that lead to honest-node divergence in availability.

### Likelihood Explanation
Reaching this code path requires only: (1) declaring/deploying a contract (a permissionless, unprivileged action), and (2) invoking it with a transaction that triggers the syscall with a maliciously large length value written into its own execution memory — no privileged operator or node role is required. This is directly reachable from a single submitted transaction via ordinary blockifier execution/syscall handling.

### Recommendation
Bound the array length against a hard maximum (e.g., calldata/segment size limits or gas-derived byte limits) and validate/charge gas for the claimed length **before** performing any allocation or memory read in `read_felt_array` (both `crates/blockifier/src/execution/syscalls/hint_processor.rs` and `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`), rather than deferring the gas check to after `SyscallRequestWrapper::read` completes in `execute_syscall`.

### Proof of Concept
Not independently executable from static analysis alone; the exact overflow/OOM threshold depends on `cairo-vm`'s internal `get_integer_range` allocation behavior (an external dependency), which could not be verified within this review. Conceptually: deploy a Cairo0 contract whose bytecode, prior to invoking the `send_message_to_l1` syscall, writes a very large felt (e.g., near `usize::MAX` when converted from `BigUint`) as the array-size word read by `read_felt_array` at [5](#0-4) ; invoking this entry point from any account triggers `felt_range_from_ptr` to attempt an allocation of that size before any gas accounting for the syscall's request size occurs.

**Note:** Confirming the precise memory-allocation semantics of `cairo_vm::vm::vm_core::VirtualMachine::get_integer_range` (whether it pre-allocates `size` elements before validating each memory cell exists) requires inspecting the `cairo-vm` dependency source, which is outside this repository's indexed contents and could not be verified here.

fn execute_syscall<Request, Response, ExecuteCallback, Executor>(
    syscall_executor: &mut Executor,
    vm: &mut VirtualMachine,
    selector: SyscallSelector,
    execute_callback: ExecuteCallback,
) -> Result<(), Executor::Error>
where
    Executor: SyscallExecutor,
    Request: SyscallRequest + std::fmt::Debug,
    Response: SyscallResponse + std::fmt::Debug,
    ExecuteCallback: FnOnce(
        Request,
        &mut VirtualMachine,
        &mut Executor,
        &mut u64, // Remaining gas.
    ) -> Result<Response, Executor::Error>,
{
    let syscall_gas_cost = syscall_executor
        .get_gas_cost_from_selector(&selector)
        .map_err(|error| SyscallExecutorBaseError::GasCost { error, selector })?;

    let SyscallRequestWrapper { gas_counter, request } =
        SyscallRequestWrapper::<Request>::read(vm, syscall_executor.get_mut_syscall_ptr())?;

    let syscall_gas_cost =
        syscall_gas_cost.get_syscall_cost(u64_from_usize(request.get_linear_factor_length()));
    let syscall_base_cost = syscall_executor.get_syscall_base_gas_cost();

pub fn read_felt_array<TErr>(vm: &VirtualMachine, ptr: &mut Relocatable) -> Result<Vec<Felt>, TErr>
where
    TErr: From<StarknetApiError> + From<VirtualMachineError> + From<MemoryError> + From<MathError>,
{
    // If the start and end pointers are the same, the array is empty.
    // This check is necessary to handle the case where both pointers are zero, and thus are not
    // relocatable values.
    let array_start = vm.get_maybe(&*ptr);
    if array_start.is_some() && array_start == vm.get_maybe(&(*ptr + 1_usize)?) {
        *ptr = (*ptr + 2)?;
        return Ok(vec![]);
    }

    let array_data_start_ptr = vm.get_relocatable(*ptr)?;
    *ptr = (*ptr + 1)?;
    let array_data_end_ptr = vm.get_relocatable(*ptr)?;
    *ptr = (*ptr + 1)?;
    let array_size = (array_data_end_ptr - array_data_start_ptr)?;

    Ok(felt_range_from_ptr(vm, array_data_start_ptr, array_size)?)
}

pub fn felt_range_from_ptr(
    vm: &VirtualMachine,
    ptr: Relocatable,
    size: usize,
) -> Result<Vec<Felt>, VirtualMachineError> {
    let values = vm.get_integer_range(ptr, size)?;
    // Extract values as `Felt`.
    let values = values.into_iter().map(|felt| *felt).collect();
    Ok(values)
}

pub fn read_felt_array<TErr>(vm: &VirtualMachine, ptr: &mut Relocatable) -> Result<Vec<Felt>, TErr>
where
    TErr: From<StarknetApiError>
        + From<VirtualMachineError>
        + From<MemoryError>
        + From<MathError>
        + From<TryFromBigIntError<BigUint>>,
{
    let array_size = felt_from_ptr(vm, ptr)?;
    // An empty array's data pointer may be a felt-zero null (`cast(0, felt*)`) rather than a real
    // segment.
    if array_size == Felt::ZERO {
        *ptr = (*ptr + 1)?;
        return Ok(vec![]);
    }
    let array_data_start_ptr = vm.get_relocatable(*ptr)?;
    *ptr = (*ptr + 1)?;

    Ok(felt_range_from_ptr(vm, array_data_start_ptr, usize::try_from(array_size.to_biguint())?)?)
}
