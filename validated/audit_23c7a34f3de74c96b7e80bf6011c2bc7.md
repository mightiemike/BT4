### Title
Witness rewards accrued while vote count is zero are permanently dropped from the Vi reward index and never credited to voters - (File: `chainbase/src/main/java/org/tron/core/store/DelegationStore.java`)

### Summary
`DelegationStore.accumulateWitnessVi()` skips accumulating the reward-per-vote index (`Vi`) whenever a super representative's recorded vote count for the cycle is `0`, even though block/transaction-fee rewards may have already been credited to that SR for the same cycle via `MortgageService.payReward()`. Because the `Vi` index is the only mechanism by which voters' shares of a cycle's reward are later computed and credited to their `allowance`, any reward accrued during a cycle in which the SR's vote count is `0` is silently orphaned - it is stored in `delegationStore` under the per-cycle reward key but can never be paid out to anyone, mirroring the ZivoeRewards `depositReward`/no-staker bug class.

### Finding Description
`MortgageService.payReward()` unconditionally adds block rewards and transaction-fee rewards to a witness's per-cycle reward bucket: [1](#0-0) 

These rewards are meant to be distributed to that witness's voters proportionally, via a cumulative reward index `Vi` that is updated once per maintenance cycle: [2](#0-1) 

`accumulateWitnessVi()` is the routine that turns the accumulated per-cycle reward into a `Vi` delta shared across voters: [3](#0-2) 

If `voteCount == 0` for that witness/cycle (i.e., nobody currently has votes recorded for that SR at maintenance time), the branch simply forwards the previous `Vi` value and drops the `reward` value entirely - the `delta` is never computed or added. The reward amount itself remains permanently stored under the `cycle-address-reward` key (`getReward`), but no code path ever again reads it to produce a nonzero `Vi` delta for that cycle, since `Vi` deltas are always derived from `(endVi - beginVi)` comparisons in `computeReward`: [4](#0-3) 

Consequently, the reward that was credited to the witness's cycle bucket is unreachable by any voter — no code queries `getReward(cycle, address)` directly for payout to voters; it only ever affects `Vi` through `accumulateWitnessVi`. If `voteCount` is `0` for that cycle, the reward is effectively "distributed as if voters existed" from the accounting/state perspective (it was correctly added to the reward store) but is permanently locked from ever reaching any account's `allowance`, exactly the ZivoeRewards `depositReward()` failure mode where rewards deposited while `totalSupply == 0` are lost forever.

The witness's vote count used here (`witness.getVoteCount()`) is a fully user-controlled, unprivileged value: any TRX holder can vote/unvote/re-vote witnesses via `VoteWitnessActuator`/`VoteWitnessProcessor`, and `MaintenanceManager.countVote()` applies these deltas each cycle: [5](#0-4) [6](#0-5) 

So if all voters for a given SR unvote/redirect their votes such that the SR's recorded vote count drops to `0` for a cycle while that SR is still active/producing blocks (e.g. small or private networks with few candidates where zero-vote witnesses can still be part of the active/standby set), any block reward or transaction fee reward paid to that SR for that cycle is lost.

Note that the sibling `payStandbyWitness()` path in the same file correctly guards against the zero-vote case by skipping distribution when `voteSum < 1`: [7](#0-6) 

but `payBlockReward()`/`payTransactionFeeReward()` (via `payReward()`) have no equivalent guard, and the `Vi`-accumulation logic drops the reward instead of preserving it for whenever the vote count later becomes nonzero — the exact "should be saved for when there is someone to receive them" problem the Zivoe report describes.

### Impact Explanation
Reward funds (block rewards and transaction fee rewards) that were correctly credited into a witness's per-cycle reward accounting are permanently unclaimable by any voter once the `Vi` accumulation step observes a zero vote count for that cycle. This is an accounting/settlement divergence: the protocol believes it distributed the reward (it exists in `delegationStore`), but no voter can ever be credited for it, resulting in a silent, permanent loss of reward funds. This matches the "underpriced/lost distribution" impact class - value that should eventually reach stakeholders (voters) never does.

### Likelihood Explanation
This requires that an active/reward-earning SR's recorded vote count be exactly `0` for the cycle in which it earns block or transaction-fee rewards. On a well-populated mainnet with 127+ candidates, active witnesses realistically always retain nonzero vote counts. However, the vote count is entirely derived from unprivileged, permissionless voting/unvoting actions (`VoteWitnessContract`), and the condition is trivially reachable on smaller/private java-tron based networks or edge-case testnets with few candidates, where a witness can be part of the active/standby set with zero recorded votes. No admin or privileged role is required to trigger the loss — it results purely from normal voting activity combined with normal block production/fee reward payout. This mirrors the original Sherlock finding's own acknowledged "low probability but possible" characterization.

### Recommendation
In `DelegationStore.accumulateWitnessVi()` (and the duplicated logic in `RewardViCalService`), do not silently drop the `reward` value when `voteCount == 0`. Instead, carry the reward forward (e.g., accumulate it into the next cycle's reward bucket for that witness) so that it is eventually distributed once the witness has nonzero votes, rather than discarding it: [3](#0-2) 

Alternatively, mirror the guard already used in `payStandbyWitness()` by preventing `payReward()`/`addReward()` from crediting rewards to a witness whose vote count is currently `0`, and instead routing that reward elsewhere (e.g., back to a treasury) rather than into an unreachable per-cycle bucket.

### Proof of Concept
1. Deploy/operate a small java-tron network where an SR (`W`) is part of the active/standby witness set with vote count `0` for cycle `N` (e.g., insufficient competing candidates, or all of `W`'s voters unvote at the start of cycle `N`, dropping `witness.getVoteCount()` to `0` as observed by `MaintenanceManager.doMaintenance()` for cycle `N`).
2. `W` produces one or more blocks during cycle `N`; `MortgageService.payBlockReward()`/`payTransactionFeeReward()` call `payReward()`, which calls `delegationStore.addReward(N, W, value)`, correctly recording the reward.
3. At the next maintenance, `MaintenanceManager.doMaintenance()` calls `delegationStore.accumulateWitnessVi(N, W, witness.getVoteCount())` with `voteCount == 0`.
4. Inside `accumulateWitnessVi`, since `voteCount == 0`, the `Vi` delta for `W` at cycle `N` is never computed; `Vi` is simply forwarded from `cycle N-1`.
5. Even if voters later vote for `W` in cycle `N+1`, `computeReward()`/`MortgageService.withdrawReward()` compute rewards purely from `Vi` deltas (`endVi - beginVi`), so the reward recorded in step 2 for cycle `N` can never be attributed to any voter and is permanently unclaimable, despite existing in `delegationStore` as an "already distributed" reward.

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }

  public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }
