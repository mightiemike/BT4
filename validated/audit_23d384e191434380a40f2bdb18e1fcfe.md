### Title
PoisonMicroblock accepts duplicated (non-equivocating) microblock headers as proof of a fork - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`check_microblock_header_signer` only verifies that the recovered public-key hashes of `mblock_header_1` and `mblock_header_2` match; it never checks that the two headers are actually distinct (`block_hash()` differs). An attacker can submit `TransactionPayload::PoisonMicroblock` with two identical, duplicated headers signed once and be paid a "poison" report reward as if the miner had equivocated.

### Finding Description
The equality that must hold is: *a poison-microblock reward is paid if and only if exactly one valid double-signature exists*, i.e. `mblock_header_1.block_hash() != mblock_header_2.block_hash()` **and** both are signed by the same key at the same `sequence`. `check_microblock_header_signer` at stackslib/src/chainstate/stacks/db/transactions.rs:686-713 recovers `pkh1` and `pkh2` via `check_recover_pubkey()` and only asserts `pkh1 != pkh2` fails; it never compares `mblock_header_1.block_hash()` to `mblock_header_2.block_hash()`, and never even independently confirms `mblock_header_1.sequence == mblock_header_2.sequence`.

`handle_poison_microblock` (transactions.rs:722-883) calls this signer check, then looks up `get_microblock_pubkey_hash_height`, checks the `MINER_REWARD_MATURITY` window, and unconditionally calls `env.global_context.database.insert_microblock_poison(...)` (transactions.rs:828-832 and 850-854) using `mblock_header_1.sequence` as the reported fork sequence — with no verification the two header structs differ at all. If an attacker submits `mblock_header_1` and `mblock_header_2` as byte-for-byte identical headers (same sequence, same prev-block hash, same tx-merkle root, same signature), `check_recover_pubkey()` on both yields the same `pkh`, satisfying the only actual gate in the function, and a poison report gets inserted for a miner who never double-signed anything.

This poison report subsequently feeds `find_mature_miner_rewards` / `get_poison_microblock_report` / `calculate_miner_reward`, diverting the maturing miner's coinbase commission to the "reporter" even though no equivocation occurred.

### Impact Explanation
This is block-reward theft: an honest miner who published exactly one microblock stream can have their maturing coinbase slashed and redirected to an attacker who merely resubmitted the miner's own already-published, legitimately-signed microblock header twice. This matches the Critical category "block-reward theft/double-payment/loss," since funds are misappropriated from an honest party to the attacker without any actual double-signing having occurred.

### Likelihood Explanation
The attacker needs only: (1) a chain tip at height H, (2) a miner's microblock public key hash already present via `insert_microblock_pubkey_hash` at or before H (which happens for every ordinary miner that publishes microblocks), and (3) submission within the `MINER_REWARD_MATURITY` window. The attacker does not need any privileged role, majority stake, or another party's key — they simply need to observe one already-published, signed microblock header from any miner and resubmit it twice as `mblock_header_1`/`mblock_header_2` in a `PoisonMicroblock` transaction. This is trivially and repeatably exploitable by any unprivileged transaction sender against any active/recent miner.

### Recommendation
In `check_microblock_header_signer` (or immediately before/after it in `handle_poison_microblock`), explicitly require `mblock_header_1.sequence == mblock_header_2.sequence` AND `mblock_header_1.block_hash() != mblock_header_2.block_hash()` (i.e., the headers must differ in content while committing to the same sequence and signer), returning `Error::InvalidStacksTransaction` otherwise, before recovering/comparing public keys.

### Proof of Concept
Add a test in stackslib/src/chainstate/stacks/db/transactions.rs (or its test module) that:
1. Constructs a single signed `StacksMicroblockHeader` via `make_signed_microblock` (or equivalent helper), then clones it verbatim to produce `mblock_header_1` and `mblock_header_2` (identical `sequence`, `prev_block`, `tx_merkle_root`, and `signature`).
2. Sets up chainstate so the miner's pubkey hash was inserted at height <= H via `insert_microblock_pubkey_hash`, with the maturity window open.
3. Builds a `TransactionPayload::PoisonMicroblock(mblock_header_1.clone(), mblock_header_2.clone())` transaction from an unprivileged sender account and calls `process_transaction`.
4. Asserts on both sides of the equality:
   - Before fix: `process_transaction` succeeds and `get_poison_microblock_report` / `get_microblock_poison_report(mblock_pubk_height)` returns `Some((sender, sequence))` despite `mblock_header_1.block_hash() == mblock_header_2.block_hash()`.
   - After fix: assert `process_transaction` returns `Err(Error::InvalidStacksTransaction(..))` and no poison report is inserted, since `mblock_header_1.block_hash() == mblock_header_2.block_hash()` must be rejected as a non-equivocation.
