## Finding

### Title
Transaction-backup restore commits write sets without validating them against `TransactionInfo::state_change_hash`, breaking the write-set-to-state-change-hash binding invariant - (File: `storage/aptosdb/src/backup/restore_utils.rs`, `storage/aptosdb/src/ledger_db/write_set_db.rs`)

### Summary
The transaction backup restore path deserializes `WriteSet`s from an untrusted backup chunk and forwards them straight to `WriteSetDb::put_write_set` via `restore_utils::save_transactions_impl`, without ever checking that `CryptoHash::hash(&write_set) == txn_info.state_change_hash()`. The cryptographic verification that *is* performed on the chunk (`TransactionListWithProof::verify`) does not cover write sets at all, because `TransactionListWithProof` has no write-set field.

### Finding Description
In `LoadedChunk::load` (`storage/backup/backup-cli/src/backup_types/transaction/restore.rs:99-186`), the backup record for each transaction is deserialized into `(txn, aux_info, txn_info, events, write_set)` [1](#0-0) . Only `txns`, `event_vecs`, and `txn_infos` are packed into a `TransactionListWithProofV2` and passed to `.verify()` [2](#0-1) ; `write_sets` is kept in a separate `Vec<WriteSet>` field on `LoadedChunk`, entirely outside the verified structure.

`TransactionListWithProof::verify` (`types/src/transaction/mod.rs:2693-2752`) only checks:
- transaction hash vs `txn_info.transaction_hash()`
- accumulator proof of `txn_infos` against the ledger info
- event root hash vs `txn_info.event_root_hash()` (if events present)

It has no `write_set` field and never touches `state_change_hash()` [3](#0-2) . (The write-set hash check only exists in the *separate* `TransactionOutputListWithProof::verify`, used by the state-snapshot/output-based restore path, not by `TransactionRestoreController`.) [4](#0-3) 

The unpacked `write_sets` are then routed (via `save_before_replay_version` / `replay_kv`) into `RestoreHandler::save_transactions` / `save_transactions_and_replay_kv`, which call `restore_utils::save_transactions` → `save_transactions_impl` [5](#0-4) . That function writes transactions, persisted aux info, transaction infos, the accumulator, events, and finally the write sets via `WriteSetDb::put_write_set` at lines 259-265 — with no comparison anywhere between the write set and `txn_info.state_change_hash()`.

`WriteSetDb::put_write_set` itself is a pure storage primitive that unconditionally serializes and stores whatever `WriteSet` it is given [6](#0-5) . A repo-wide search of `storage/backup/**` for `state_change_hash` / write-set-hash comparisons returned no matches, confirming the backup-cli layer performs no such check either.

Because the transaction accumulator only commits to the hash of each `TransactionInfo` (which embeds `state_change_hash`), and the ledger info only commits to the accumulator root, a backup chunk whose `WriteSet` does not hash to its paired `TransactionInfo.state_change_hash` will still pass `TransactionListWithProof::verify` and `TransactionInfoListWithProof::verify` unchanged, since those proofs never recompute or check the write-set hash against the committed `TransactionInfo`.

### Impact Explanation
A restoring node that consumes a corrupted or malicious transaction backup (e.g., from a compromised/tampered backup store, or backup transport without end-to-end integrity beyond the normal accumulator proof over transaction infos) will commit an arbitrary `WriteSet` at a version whose `TransactionInfo.state_change_hash` does not match it. This breaks the invariant that stored write sets are bound to the accumulator-proven `TransactionInfo`, allowing the restored node's key-value state and derived Merkle state root at replayed/verified versions to diverge from what honest execution/original chain produced, while the node's accumulator and ledger-info checks still pass. This is a genuine storage/proof-binding integrity break in the restore path, not merely an operator-trust issue, since the check that's supposed to bind `write_set` and `state_change_hash` (as exists for `TransactionOutputListWithProof`) is simply absent for `TransactionListWithProof`-based transaction restore.

### Likelihood Explanation
Likelihood depends on how backup chunk integrity is otherwise assured outside of this code path (e.g., transport-level integrity, or whether the backup source is considered part of the trust boundary). Within the code reviewed, there is no cryptographic gate preventing a corrupted `write_set` field in a `TransactionChunk` record from being accepted and committed, since the deserialization and the `.verify()` call operate on a structure that structurally excludes write sets.

### Recommendation
Add an explicit check in `LoadedChunk::load` (or immediately before `save_transactions`/`save_transactions_and_replay_kv` calls) that recomputes `CryptoHash::hash(&write_set)` for every entry and asserts it equals the corresponding `txn_infos[i].state_change_hash()`, mirroring the check already present in `TransactionOutputListWithProof::verify`. Reject the chunk (return an error) if any mismatch is found, before any data reaches `restore_utils::save_transactions_impl` / `WriteSetDb::put_write_set`.

### Proof of Concept
1. Take a valid transaction backup chunk file (format `V1`/`V0`) and locate one record's serialized `(txn, aux_info, txn_info, events, write_set)` tuple.
2. Replace `write_set` with a different, arbitrary `WriteSet` (e.g., one that writes to an unrelated `StateKey`) while leaving `txn_info` (and hence its `state_change_hash`) untouched, and leave `proof`/`ledger_info` files unmodified.
3. Run `TransactionRestoreController::run()` (or the batch controller) against this tampered chunk.
4. Observe that `LoadedChunk::load`'s call to `txn_list_with_proof.verify(...)` succeeds (it never inspects `write_sets`), and that `save_transactions`/`save_transactions_and_replay_kv` commit the tampered `write_set` via `WriteSetDb::put_write_set` without any `state_change_hash` comparison — the restore completes successfully despite `CryptoHash::hash(write_set) != txn_info.state_change_hash()`, and the restored node's state at that version now differs from the original chain's.

pub struct TransactionListWithProof {
    pub transactions: Vec<Transaction>,
    pub events: Option<Vec<Vec<ContractEvent>>>,
    pub first_transaction_version: Option<Version>,
    pub proof: TransactionInfoListWithProof,
}

impl TransactionListWithProof {
    /// Constructor.
    pub fn new(
        transactions: Vec<Transaction>,
        events: Option<Vec<Vec<ContractEvent>>>,
        first_transaction_version: Option<Version>,

    ) -> Self {

    /// A convenience function to create an empty proof. Mostly used for tests.
    pub fn new_empty() -> Self {
        Self::new(
            vec![],
            None,
            None,
            TransactionInfoListWithProof::new_empty(),
        )
    }

    /// Returns the first version in the transaction list
    pub fn get_first_transaction_version(&self) -> Option<Version> {
        self.first_transaction_version
    }

    /// Returns the number of transactions in the transaction list
    pub fn get_num_transactions(&self) -> usize {
        self.transactions.len()
    }

    /// Verifies the transaction list with proof using the given `ledger_info`.
    /// This method will ensure:
    /// 1. All transactions exist on the given `ledger_info`.
    /// 2. All transactions in the list have consecutive versions.
    /// 3. If `first_transaction_version` is None, the transaction list is empty.
    ///    Otherwise, the transaction list starts at `first_transaction_version`.
    /// 4. If events exist, they match the expected event root hashes in the proof.
    pub fn verify(
        &self,
        ledger_info: &LedgerInfo,
        first_transaction_version: Option<Version>,
    ) -> Result<()> {
        // Verify the first transaction versions match
        ensure!(
            self.get_first_transaction_version() == first_transaction_version,
            "First transaction version ({:?}) doesn't match given version ({:?}).",
            self.get_first_transaction_version(),
            first_transaction_version,
        );

        // Verify the lengths of the transactions and transaction infos match
        ensure!(
            self.proof.transaction_infos.len() == self.get_num_transactions(),
            "The number of TransactionInfo objects ({}) does not match the number of \
             transactions ({}).",
            self.proof.transaction_infos.len(),
            self.get_num_transactions(),
        );

        // Verify the transaction hashes match those of the transaction infos
        self.transactions
            .par_iter()
            .zip_eq(self.proof.transaction_infos.par_iter())
            .map(|(txn, txn_info)| {
                let txn_hash = txn.committed_hash();
                ensure!(
                    txn_hash == txn_info.transaction_hash(),
                    "The hash of transaction does not match the transaction info in proof. \
                     Transaction hash: {:x}. Transaction hash in txn_info: {:x}.",
                    txn_hash,
                    txn_info.transaction_hash(),
                );
                Ok(())
            })
            .collect::<Result<Vec<_>>>()?;

        // Verify the transaction infos are proven by the ledger info.
        self.proof
            .verify(ledger_info, self.get_first_transaction_version())?;

        // Verify the events if they exist.
        if let Some(event_lists) = &self.events {
            ensure!(
                event_lists.len() == self.get_num_transactions(),
                "The length of event_lists ({}) does not match the number of transactions ({}).",
                event_lists.len(),
                self.get_num_transactions(),
            );
            event_lists
                .into_par_iter()
                .zip_eq(self.proof.transaction_infos.par_iter())
                .map(|(events, txn_info)| verify_events_against_root_hash(events, txn_info))
                .collect::<Result<Vec<_>>>()?;
        }

        Ok(())
    }

pub(crate) fn save_transactions_impl(
    state_store: Arc<StateStore>,
    ledger_db: Arc<LedgerDb>,
    first_version: Version,
    txns: &[Transaction],
    persisted_aux_info: &[PersistedAuxiliaryInfo],
    txn_infos: &[TransactionInfo],
    events: &[Vec<ContractEvent>],
    write_sets: &[WriteSet],
    ledger_db_batch: &mut LedgerDbSchemaBatches,
    state_kv_batches: &mut ShardedStateKvSchemaBatch,
    kv_replay: bool,
) -> Result<()> {
    for (idx, txn) in txns.iter().enumerate() {
        ledger_db.transaction_db().put_transaction(
            first_version + idx as Version,
            txn,
            /*skip_index=*/ false,
            &mut ledger_db_batch.transaction_db_batches,
        )?;
    }

    for (idx, aux_info) in persisted_aux_info.iter().enumerate() {
        PersistedAuxiliaryInfoDb::put_persisted_auxiliary_info(
            first_version + idx as Version,
            aux_info,
            &mut ledger_db_batch.persisted_auxiliary_info_db_batches,
        )?;
    }

    for (idx, txn_info) in txn_infos.iter().enumerate() {
        TransactionInfoDb::put_transaction_info(
            first_version + idx as Version,
            txn_info,
            &mut ledger_db_batch.transaction_info_db_batches,
        )?;
    }

    ledger_db
        .transaction_accumulator_db()
        .put_transaction_accumulator(
            first_version,
            txn_infos,
            &mut ledger_db_batch.transaction_accumulator_db_batches,
        )?;

    ledger_db.event_db().put_events_multiple_versions(
        first_version,
        events,
        &mut ledger_db_batch.event_db_batches,
    )?;

    for (idx, txn_events) in events.iter().enumerate() {
        for event in txn_events {
            if let Some(event_key) = event.event_key() {
                if *event_key == new_block_event_key() {
                    LedgerMetadataDb::put_block_info(
                        first_version + idx as Version,
                        event,
                        &mut ledger_db_batch.ledger_metadata_db_batches,
                    )?;
                }
            }
        }
    }
    // insert changes in write set schema batch
    for (idx, ws) in write_sets.iter().enumerate() {
        WriteSetDb::put_write_set(
            first_version + idx as Version,
            ws,
            &mut ledger_db_batch.write_set_db_batches,
        )?;
    }
