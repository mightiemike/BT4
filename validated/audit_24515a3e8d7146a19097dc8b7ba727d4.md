Based on my analysis, the closest and best-fitting analog to the `blacklistProtocol()` bug class exists in `x/uexecutor`'s outbound finalization flow, specifically the excess-gas refund logic. This mirrors M-30's exact root cause: a state-machine step is irreversibly finalized (and removed from the "in-flight" tracking index) *before* confirming that a dependent fund-movement sub-operation fully succeeded — with no dedicated retry/rescue path for the leftover amount.

### Title
Outbound gas-refund failure is silently absorbed after outbound is finalized and removed from pending tracking, permanently stranding user's unused-gas funds - (File: x/uexecutor/keeper/outbound.go)

### Summary
`VoteOutbound` marks an `OutboundTx` as `OBSERVED` and removes it from `PendingOutbounds` *before* the compensating gas-refund logic (`applyGasRefund`) has confirmed success. `applyGasRefund` attempts a swap-refund and, on failure, a no-swap fallback; if **both** attempts fail, the function simply records `refundPcTx.Status = "FAILED"` and `RefundSwapError`, and returns without error. No retry mechanism, no dedicated rescue function, and no reversal of the already-finalized/pending-removed outbound state exists — exactly the pattern M-30 flags: finalizing (blacklisting) an operation without validating that the full withdrawal/transfer actually completed.

### Finding Description
In `x/uexecutor/keeper/msg_vote_outbound.go`, once quorum is reached: [1](#0-0) 
the outbound's status is set to `OBSERVED` and it is immediately removed from `PendingOutbounds` — the index used to track in-flight items needing further processing — before `FinalizeOutbound` (which performs the refund) is even called.

`FinalizeOutbound` then dispatches to `handleFailedOutbound`/`handleSuccessfulOutbound`, both of which call `applyGasRefund`: [2](#0-1) 

Note that while the *re-mint* leg (returning bridged principal on a failed outbound) is correctly guarded — a failed re-mint calls `AbortOutbound`, which correctly halts further optimistic state changes: [3](#0-2) 
the *gas-refund* leg has no equivalent safeguard. If both the swap-refund and the no-swap fallback fail (e.g., the gas token has no configured default fee tier, the DEX pool for it has no liquidity, or `CallUniversalCoreRefundUnusedGas` reverts for any other reason), the function just records failure metadata and returns — `handleFailedOutbound`/`handleSuccessfulOutbound` still call `k.UpdateOutbound` unconditionally, finalizing the outbound's terminal state regardless.

Because the outbound was already dropped from `PendingOutbounds` at vote time (step above), and there is no separate "PendingRefunds" index or retry sweep, the difference between `GasFee` and `GasFeeUsed` (the user's excess prepaid gas, held by the protocol/UniversalCore) becomes permanently unreachable — there is no code path in the repo that revisits `RefundSwapError`/failed `PcRefundExecution` entries.

### Impact Explanation
This causes a **permanent loss of protocol-held, user-owed funds** (the unused-gas refund amount) with no recovery path, matching the "In scope" impact category "permanent loss ... of user or protocol-controlled funds." Every ordinary crosschain transaction that results in an outbound with `gasFee > gasFeeUsed` is exposed; if the refund swap and fallback both fail for that specific gas token (a condition an unprivileged user can trigger simply by using a token whose fee-tier/liquidity configuration is momentarily unfavorable, or is not yet configured), that user's refund is dropped, and no admin or user can later reclaim it through any dedicated rescue function in this module.

### Likelihood Explanation
Likelihood is moderate: it requires the swap AND the fallback (no-swap) refund calls to fail, which typically only occurs in edge conditions (missing fee-tier config, zero liquidity, or a paused/edge-case PRC20). No malicious/privileged actor is required — an ordinary user's transaction alone can hit this via legitimate config/liquidity gaps, so it is reachable purely through the default transaction submission path.

### Recommendation
Do not treat `applyGasRefund` failure as final. Options:
- Keep a `PendingRefund`/failed-refund index (mirroring `PendingOutbounds`) for entries where `refundPcTx.Status == "FAILED"`, and provide a dedicated retry/rescue keeper function (and message) to reattempt or admin-settle the stranded refund, analogous to the fix pattern recommended for M-30 (dedicated withdraw/rescue function for stuck balances).
- Alternatively, treat a fully-failed refund the same way a failed re-mint is treated — call `AbortOutbound` (or an equivalent state that keeps it in a retry-eligible index) instead of silently finalizing via `UpdateOutbound`.

### Proof of Concept
1. A user submits a crosschain transaction whose destination-chain execution uses less gas than prepaid (`gasFeeUsed < gasFee`), using a `gasToken` for which `GetDefaultFeeTierForToken` returns an error (or the swap quote/slippage check fails).
2. UVs vote the outbound as observed/failed via `MsgVoteOutbound`; `VoteOutbound` immediately marks it `OBSERVED`/`REVERTED` and removes it from `PendingOutbounds`.
3. `FinalizeOutbound` → `applyGasRefund` attempts the swap-refund (fails per step 1), falls back to `CallUniversalCoreRefundUnusedGas` with `swap=false`; if that also fails (e.g. the underlying UniversalCore call reverts for the given token/recipient state), `refundPcTx.Status = "FAILED"` is recorded and the function returns normally.
4. `outbound.OutboundStatus` remains finalized (`OBSERVED`/`REVERTED`), it is not present in any pending index, and no code path anywhere in `x/uexecutor` revisits `PcRefundExecution.Status == "FAILED"` entries — the refund amount is permanently unrecoverable. [4](#0-3)

```go
// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
```
