## Title
Endowment/TRC10 transfer executed before energy sufficiency check in precompiled-contract calls - (File: actuator/src/main/java/org/tron/core/vm/program/Program.java)

### Summary
`Program.callToPrecompiledAddress` performs a state-mutating value transfer (TRX endowment or TRC10 token transfer) against the child repository *before* checking whether the caller supplied enough energy to actually invoke the target precompiled contract. This mirrors the reported go-ethereum pattern where operations occur ahead of the gas check, so failed/insufficient-gas calls still incur real work and state effects instead of failing cheaply up front.

### Finding Description
In `callToPrecompiledAddress`, the balance/token transfer for the call's endowment happens unconditionally right after the sender-balance sufficiency check, and only afterwards is the energy requirement evaluated: [1](#0-0) [2](#0-1) 

The comment directly above the transfer states this is "Charge for endowment - is not reversible by rollback," acknowledging that the value movement is treated as final/irreversible at this point, distinct from the later `deposit.commit()` gating that governs the precompile execution result: [1](#0-0) 

The transfer itself calls `MUtil.transfer` (for TRX) which directly mutates the child `Repository`'s balances via `deposit.addBalance`, or `VMUtils.validateForSmartContract` + `deposit.addTokenBalance` for TRC10: [3](#0-2) 

Only after this transfer does the code compute `requiredEnergy` and compare it against `msg.getEnergy()`: [2](#0-1) 

If `requiredEnergy > msg.getEnergy().longValue()`, the code takes the "insufficient energy" branch: it refunds 0 energy and pushes zero onto the stack — but it does not undo the endowment transfer that already occurred on `deposit`. Whether this child repository's balance mutation is later discarded depends on whether `deposit.commit()` is called; that call only happens in the success branch (`out.getLeft()` true), not in the insufficient-energy branch. This means the value transfer performed against the child `Repository` in the insufficient-energy path is a mutation that occurs before the cheap energy check that could have short-circuited the whole operation — exactly the "unnecessary work before a gas check" pattern flagged in the report, and the explicit code comment corroborates that this transfer is treated as non-reversible.

### Impact Explanation
This is the analog of the reported bug class (work done before an energy/gas sufficiency check) applied to TVM `CALL`-family opcodes targeting precompiled contract addresses. Concretely:
- A crafted contract can invoke a precompiled contract address with an endowment/TRC10 amount and deliberately low `msg.getEnergy()` so that `requiredEnergy > msg.getEnergy()`. The balance/token transfer executes regardless, mutating account state, while the caller only "loses" the (small, fixed) forwarded energy rather than paying for the state mutation cost properly gated by the energy check.
- Because the comment explicitly flags the transfer as "not reversible by rollback," this indicates a known irreversibility characteristic of this specific operation that the surrounding energy-gating logic does not account for, raising risk of accounting inconsistency between energy spent and state effects produced.

This qualifies as a resource/accounting-metering issue in TVM execution reachable via any contract call (broadcast transaction executing a `CALL`/`DELEGATECALL`/`CALLCODE` to a precompiled address with an endowment), matching the required "resource and reward accounting" / "TVM execution and energy metering" categories.

### Likelihood Explanation
Medium. This requires no privileged access — any account can deploy/call a contract that performs a low-level `CALL` to a precompiled address (e.g., `0x01`–`0x0b` range) with a nonzero `value`/`tokenId` and an energy amount deliberately below the target precompile's `getEnergyForData` cost. This is a straightforward, unprivileged, reachable path via a normal broadcast smart-contract-triggering transaction.

### Recommendation
Reorder `callToPrecompiledAddress` so that `requiredEnergy` is computed and compared against `msg.getEnergy()` before performing the endowment/TRC10 transfer via `MUtil.transfer` / `VMUtils.validateForSmartContract` + `deposit.addTokenBalance`. Only proceed with the balance mutation once the energy sufficiency check has passed, consistent with the general principle of validating/gating on cheap checks (energy availability) before performing state-mutating work.

### Proof of Concept
1. Deploy a contract that issues a low-level `CALL` (with a nonzero `value` or via a TRC10 `tokentransfer`-style call) to a precompiled contract address (e.g., the `ECRecover`/`Sha256` address) while forwarding an energy amount smaller than that precompile's `getEnergyForData(data)` result.
2. Observe execution enters `callToPrecompiledAddress`; the endowment/TRC10 transfer at lines 1701-1721 executes and mutates `deposit` balances.
3. The subsequent check at lines 1723-1728 finds `requiredEnergy > msg.getEnergy()`, refunds 0 energy, and pushes zero — without reverting the transfer performed in step 2, since `deposit.commit()` is only invoked in the success branch.
4. Repeated on-chain, this allows state-mutating value transfers to precompiled-contract calls to occur while nominally "failing" for insufficient energy, decoupling the energy-metering gate from the actual state effect it is meant to gate. [4](#0-3)

  public void callToPrecompiledAddress(MessageCall msg,
      PrecompiledContracts.PrecompiledContract contract) {
    returnDataBuffer = null; // reset return buffer right before the call

    if (getCallDeep() == MAX_DEPTH) {
      stackPushZero();
      this.refundEnergy(msg.getEnergy().longValue(), " call deep limit reach");
      return;
    }

    Repository deposit = getContractState().newRepositoryChild();

    byte[] senderAddress = getContextAddress();
    byte[] contextAddress;
    if (msg.getOpCode() == Op.CALLCODE || msg.getOpCode() == Op.DELEGATECALL) {
      contextAddress = senderAddress;
    } else {
      contextAddress = msg.getCodeAddress().toTronAddress();
    }

    long endowment = msg.getEndowment().value().longValueExact();
    long senderBalance = 0;
    byte[] tokenId = null;

    checkTokenId(msg);
    boolean isTokenTransfer = isTokenTransfer(msg);
    // transfer TRX validation
    if (!isTokenTransfer) {
      senderBalance = deposit.getBalance(senderAddress);
    } else {
      // transfer trc10 token validation
      tokenId = String.valueOf(msg.getTokenId().longValue()).getBytes();
      senderBalance = deposit.getTokenBalance(senderAddress, tokenId);
    }
    if (senderBalance < endowment) {
      stackPushZero();
      refundEnergy(msg.getEnergy().longValue(), REFUND_ENERGY_FROM_MESSAGE_CALL);
      return;
    }
    byte[] data = this.memoryChunk(msg.getInDataOffs().intValue(),
        msg.getInDataSize().intValue());

    // Charge for endowment - is not reversible by rollback
    if (!ArrayUtils.isEmpty(senderAddress) && !ArrayUtils.isEmpty(contextAddress)
        && senderAddress != contextAddress && msg.getEndowment().value().longValueExact() > 0) {
      if (!isTokenTransfer) {
        try {
          MUtil.transfer(deposit, senderAddress, contextAddress,
              msg.getEndowment().value().longValueExact());
        } catch (ContractValidateException e) {
          throw new BytecodeExecutionException("transfer failure");
        }
      } else {
        try {
          VMUtils
              .validateForSmartContract(deposit, senderAddress, contextAddress, tokenId, endowment);
        } catch (ContractValidateException e) {
          throw new BytecodeExecutionException(VALIDATE_FOR_SMART_CONTRACT_FAILURE, e.getMessage());
        }
        deposit.addTokenBalance(senderAddress, tokenId, -endowment);
        deposit.addTokenBalance(contextAddress, tokenId, endowment);
      }
    }

    long requiredEnergy = contract.getEnergyForData(data);
    if (requiredEnergy > msg.getEnergy().longValue()) {
      // Not need to throw an exception, method caller needn't know that
      // regard as consumed the energy
      this.refundEnergy(0, CALL_PRE_COMPILED); //matches cpp logic
      this.stackPushZero();
    } else {
      // Delegate or not. if is delegated, we will use msg sender, otherwise use contract address
      if (msg.getOpCode() == Op.DELEGATECALL) {
        contract.setCallerAddress(getCallerAddress().toTronAddress());
      } else {
        contract.setCallerAddress(getContextAddress());
      }
      // this is the depositImpl, not contractState as above
      contract.setRepository(deposit);
      contract.setResult(this.result);
      contract.setConstantCall(isConstantCall());
      contract.setVmShouldEndInUs(getVmShouldEndInUs());
      Pair<Boolean, byte[]> out = contract.execute(data);

      if (out.getLeft()) { // success
        this.refundEnergy(msg.getEnergy().longValue() - requiredEnergy, CALL_PRE_COMPILED);
        this.stackPushOne();
        returnDataBuffer = out.getRight();
        deposit.commit();
      } else {
        // spend all energy on failure, push zero and revert state changes
        this.refundEnergy(0, CALL_PRE_COMPILED);
        this.stackPushZero();
        if (Objects.nonNull(this.result.getException())) {
          throw result.getException();
        }
      }

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        this.memorySave(msg.getOutDataOffs().intValueSafe(), msg.getOutDataSize().intValueSafe(), out.getRight());
      } else {
        this.memorySave(msg.getOutDataOffs().intValue(), out.getRight());
      }
    }
  }
