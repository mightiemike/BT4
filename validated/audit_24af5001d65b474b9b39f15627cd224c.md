## Title
PoisonMicroblock accepts a re-signed (malleable) copy of a single microblock as proof of equivocation, allowing an honest miner to be slashed - ([File: stacks-codec/src/transaction.rs], [File: stackslib/src/chainstate/stacks/db/transactions.rs])

## Summary
`TransactionPayload::consensus_deserialize` only rejects two `StacksMicroblockHeader`s that are byte-identical, and `check_microblock_header_signer` only checks that both headers recover to the same signer pubkey hash. Neither of these guards requires that `tx_merkle_root` (or any other content field) actually differ, and ECDSA recoverable signatures are malleable (the same `(r,s)` value has a valid high-S/low-S complement that recovers to the *same* public key). This lets any attacker take one legitimately broadcast microblock header, derive its malleable signature twin (identical `version`/`sequence`/`prev_block`/`tx_merkle_root`, different `signature` bytes), and submit both as a `PoisonMicroblock` report, causing `handle_poison_microblock` to record a slashing report against a miner who never equivocated.

## Finding Description
The broken equality is: **"two headers that pass `h1 != h2` + same-`pubkh` checks" == "genuine equivocation (two conflicting stream branches at the same sequence, i.e., different `tx_merkle_root`/content)"**. This equality is not actually enforced by the code.

- `TransactionPayload::consensus_deserialize` for `PoisonMicroblock` only checks: `h1 == h2` is rejected, and `h1.sequence != h2.sequence && h1.prev_block != h2.prev_block` is rejected [1](#0-0) . Nothing requires `tx_merkle_root` to differ, and if the `signature` field alone differs while `version`, `sequence`, `prev_block`, `tx_merkle_root` are identical, `h1 == h2` is false and the sequence/prev_block condition is also false (since `sequence` is equal) — so the check passes.
- `StacksChainState::check_microblock_header_signer` only verifies that both headers recover to the same `Hash160` via `check_recover_pubkey`, which uses `StacksPublicKey::recover_to_pubkey_without_validating_low_s` [2](#0-1) [3](#0-2) .
- `recover_to_pubkey_without_validating_low_s` explicitly skips the low-S normalization check [4](#0-3) , and ECDSA recoverable signatures are provably malleable in this codebase: a test helper `malleablize_signature` computes `s' = n - s` and flips the recovery-id parity bit, producing a different signature byte string that still recovers to the *same* public key [5](#0-4) , and `test_with_negated_s` explicitly asserts "both signatures should recover to the same public key" [6](#0-5) .
- `handle_poison_microblock` calls `check_microblock_header_signer` and, on success, unconditionally proceeds to record a poison report keyed on `mblock_header_1.sequence` and the recovered `pubkh`, with no additional check that the headers' `tx_merkle_root` differ [7](#0-6) .

Exploit flow: attacker observes any legitimately signed `StacksMicroblockHeader` (h1) broadcast by a miner. Attacker computes `h2` = identical fields except `signature`, where `signature` is the ECDSA-malleable complement of h1's signature (flipped `s` and recovery-id parity). `h2` still recovers to the miner's pubkey. Attacker submits `PoisonMicroblock(h1, h2)`. `consensus_deserialize` accepts it (differs only in `signature`; `sequence` equal, so the fork-shape check is bypassed). `check_microblock_header_signer` succeeds (`pkh1 == pkh2`). `handle_poison_microblock` proceeds to insert a poison report and (per the design) enables commission mis-payment / punishment against the miner's coinbase, despite the miner having signed only one microblock body.

This differs from the "real" cross-check the design intends (`validate_parent_microblock_stream` at [stackslib/src/chainstate/stacks/db/blocks.rs:2992-3045]), which correctly distinguishes forks by comparing `block_hash()`/`prev_block`, but that logic is only used by the *miner's own* fork-detection when building `PoisonMicroblock` proofs from an actually-observed stream — it is not re-validated as a mandatory precondition inside `handle_poison_microblock` itself. The Clarity-level acceptance path (`check_microblock_header_signer` + sequence/pubkey checks) is the sole gate, and it accepts this malleable-signature pair.

## Impact Explanation
This allows an unprivileged, non-signer, non-majority attacker to slash/punish an honest miner's microblock public key that never actually equivocated, purely by crafting a malleable-signature twin of one legitimately observed header. Per the repo's own reward/commission logic (`handle_poison_microblock` records `(reporter_principal, reported_seq)` and computes/tracks `mblock_pubk_height` for commission against the punished miner's coinbase within the `MINER_REWARD_MATURITY` window), a successful spurious report can redirect/burn a portion of an honest miner's coinbase reward to the attacker/reporter — this is a reward-mispayment/loss impact against a specific honest party, repeatable against any observed microblock header from any miner within the maturity window. This matches the "block-reward theft/mis-payment" Critical/High impact category described in the rules.

## Likelihood Explanation
- No majority stake or privileged role is required — only the ability to observe one broadcast microblock header (trivial, as they are P2P-gossiped) and to submit a standard `PoisonMicroblock` transaction with a locally computed EC signature transform (constant-time arithmetic on `s` and flipping one bit) — no private key needed.
- Preconditions: a miner produces at least one signed microblock header (normal operation); the microblock public key hash must still be within the `MINER_REWARD_MATURITY` window (a bounded but nontrivial number of blocks) — this is the same window a legitimate poison report would need anyway.
- The attack is fully repeatable for every miner and every microblock header ever broadcast, requires no BTC spend, and executes with a single crafted transaction submission.

## Recommendation
Add an explicit "genuine equivocation" check in `handle_poison_microblock` (and/or in `TransactionPayload::consensus_deserialize`) requiring that the two headers differ in `tx_merkle_root` (i.e., represent genuinely different signed content), not merely in `signature`. Additionally, normalize/require low-S canonical signatures for microblock headers (use `recover_to_pubkey` with low-S validation, or canonicalize signatures before comparison) to eliminate the malleability vector entirely, consistent with how transaction auth signatures are already validated elsewhere (`TransactionAuthVerificationMode`).

## Proof of Concept
Rust integration test plan (e.g., in `stackslib/src/chainstate/stacks/db/transactions.rs` test module):
1. Generate a miner keypair `privk`, sign a single `StacksMicroblockHeader` `h1` (fixed `version`, `sequence`, `prev_block`, `tx_merkle_root`).
2. Compute `h2 = h1.clone()` with `signature` replaced by the malleable complement (reuse/port the `malleablize_signature` helper from `stackslib/src/chainstate/nakamoto/tests/node.rs`), leaving `tx_merkle_root`/`prev_block`/`sequence`/`version` identical.
3. Assert `h1 != h2` (only `signature` differs) — the first equality under test.
4. Assert `StacksChainState::check_microblock_header_signer(&h1, &h2)` returns `Ok(pkh)` where `pkh` equals the true miner pubkey hash — the second equality under test (both recover to the SAME key despite no real fork).
5. Build a `TransactionPayload::PoisonMicroblock(h1, h2)`, serialize/deserialize it through `TransactionPayload::consensus_deserialize` and confirm it is accepted (not rejected as "microblock headers match" or "do not identify a fork").
6. Register the miner's pubkey hash via `insert_microblock_pubkey_hash`, then call `StacksChainState::process_transaction` with a signed poison-microblock tx wrapping this payload from an arbitrary reporter account.
7. Assert the call succeeds (`Ok`) and that `get_poison_microblock_report` now records the reporter/sequence for the honest miner's key, despite `h1.tx_merkle_root == h2.tx_merkle_root` and the miner having signed only one distinct microblock body.

        let mut bytes = vec![];

            &self.signature,
        )
        .map_err(|_ve| {
            AuthError::VerifyingError(
                "Failed to verify signature: failed to recover public key".to_string(),
            )
        })?;

        pubk.set_compressed(true);
        Ok(Hash160::from_node_public_key(&pubk))
    }

            return Err(Error::InvalidStacksTransaction(msg, false));

    }

    pub fn handle_poison_microblock(
        env: &mut ExecutionState,
        invoke_ctx: &InvocationContext,
        mblock_header_1: &StacksMicroblockHeader,
        mblock_header_2: &StacksMicroblockHeader,
    ) -> Result<Value, Error> {
        let cost_before = env.global_context.cost_track.get_total();

        // encodes MARF reads for loading microblock height and current height, and loading and storing a
        // poison-microblock report
        runtime_cost(ClarityCostFunction::PoisonMicroblock, env, 0)
            .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

        let sender_principal = match &invoke_ctx.sender {
            Some(ref sender) => {
                if let PrincipalData::Standard(sender) = sender.clone() {
                    sender
                } else {
                    panic!(
                        "BUG: tried to handle poison microblock without a standard principal sender"
                    );
                }
            }
            None => {
                panic!("BUG: tried to handle poison microblock without a sender");
            }
        };

        // is this valid -- were both headers signed by the same key?
        let pubkh =
            StacksChainState::check_microblock_header_signer(mblock_header_1, mblock_header_2)?;

        let microblock_height_opt = env
            .global_context
            .database
            .get_microblock_pubkey_hash_height(&pubkh)?;
        let current_height = env.global_context.database.get_current_block_height();

        // for the microblock public key hash we had to process
        env.add_memory(20)
            .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

        // for the block height we had to load
        env.add_memory(4)
            .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

        // was the referenced public key hash used anytime in the past
        // MINER_REWARD_MATURITY blocks?
        let mblock_pubk_height = match microblock_height_opt {
            None => {
                // public key has never been seen before
                let msg = format!(
                    "Invalid Stacks transaction: microblock public key hash {} never seen in this fork",
                    &pubkh
                );
                warn!("{}", &msg;
                      "microblock_pubkey_hash" => %pubkh
                );

                return Err(Error::InvalidStacksTransaction(msg, false));
            }
            Some(height) => {
                if height
                    .checked_add(
                        u32::try_from(MINER_REWARD_MATURITY).expect("FATAL: maturity > 2^32"),
                    )
                    .expect("BUG: too many blocks")
                    < current_height
                {
                    let msg = format!(
                        "Invalid Stacks transaction: microblock public key hash from height {} has matured relative to current height {}",
                        height, current_height
                    );
                    warn!("{}", &msg;
                          "microblock_pubkey_hash" => %pubkh
                    );

                    return Err(Error::InvalidStacksTransaction(msg, false));
                }
                height
            }
        };

        // add punishment / commission record, if one does not already exist at lower sequence
        let (reporter_principal, reported_seq) = if let Some((reporter, seq)) = env
            .global_context
            .database
            .get_microblock_poison_report(mblock_pubk_height)?
        {
            // account for report loaded
            env.add_memory(u64::from(TypeSignature::PrincipalType.size().map_err(
                |_| Error::Expects("Failed to get size of PrincipalType".into()),
            )?))
            .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

            // u128 sequence
            env.add_memory(16)
                .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

            if mblock_header_1.sequence < seq {
                // this sender reports a point lower in the stream where a fork occurred, and is now
                // entitled to a commission of the punished miner's coinbase
                debug!("Sender {} reports a better poison-miroblock record (at {}) for key {} at height {} than {} (at {})", &sender_principal, mblock_header_1.sequence, &pubkh, mblock_pubk_height, &reporter, seq;
                    "sender" => %sender_principal,
                    "microblock_pubkey_hash" => %pubkh
                );
                env.global_context.database.insert_microblock_poison(
                    mblock_pubk_height,
                    &sender_principal,
                    mblock_header_1.sequence,
                )?;
                (sender_principal, mblock_header_1.sequence)
            } else {
                // someone else beat the sender to this report
                debug!("Sender {} reports an equal or worse poison-microblock record (at {}, but already have one for {}); dropping...", &sender_principal, mblock_header_1.sequence, seq;
                    "sender" => %sender_principal,
                    "microblock_pubkey_hash" => %pubkh
                );
                (reporter, seq)
            }
        } else {
            // first-ever report of a fork
            debug!(
                "Sender {} reports a poison-microblock record at seq {} for key {} at height {}",
                &sender_principal, mblock_header_1.sequence, &pubkh, &mblock_pubk_height;
                "sender" => %sender_principal,
                "microblock_pubkey_hash" => %pubkh
            );
            env.global_context.database.insert_microblock_poison(
                mblock_pubk_height,
                &sender_principal,
                mblock_header_1.sequence,
            )?;
            (sender_principal, mblock_header_1.sequence)
        };

    fn recover_to_pubkey_possibly_with_low_s_verification(
        msg: &[u8],
        sig: &MessageSignature,
        verify_low_s: bool,
    ) -> Result<Secp256k1PublicKey, &'static str> {
        _secp256k1.with(|ctx| {
            let msg = LibSecp256k1Message::from_slice(msg).map_err(|_e| {
                "Invalid message: failed to decode data hash: must be a 32-byte hash"
            })?;

            let secp256k1_sig = sig
                .to_secp256k1_recoverable()
                .ok_or("Invalid signature: failed to decode recoverable signature")?;

            if verify_low_s {
                let secp256k1_sig_standard = secp256k1_sig.to_standard();
                let mut secp256k1_sig_low_s = secp256k1_sig_standard;
                secp256k1_sig_low_s.normalize_s();
                if secp256k1_sig_low_s != secp256k1_sig_standard {
                    return Err("Invalid signature: high-S");
                }
            }

            let recovered_pubkey = ctx
                .recover_ecdsa(&msg, &secp256k1_sig)
                .map_err(|_e| "Invalid signature: failed to recover public key")?;

            Ok(Secp256k1PublicKey {
                key: recovered_pubkey,
                compressed: true,
            })
        })

/// high-S/low-S complement `s' = n - s`, with the recovery id's parity bit
/// flipped. It recovers to the same public key, so the signature remains valid,
/// but its bytes (and any hash committing to them) change. Used to construct
/// malleablized blocks: flipping the miner signature changes a block's id
/// without changing its execution.
fn malleablize_signature(sig: &MessageSignature) -> MessageSignature {
    // secp256k1 group order `n`, big-endian.
    const SECP256K1_ORDER_BE: [u8; 32] = [
        0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF, 0xFF,
        0xFE, 0xBA, 0xAE, 0xDC, 0xE6, 0xAF, 0x48, 0xA0, 0x3B, 0xBF, 0xD2, 0x5E, 0x8C, 0xD0, 0x36,
        0x41, 0x41,
    ];
    // MessageSignature layout: [recovery_id (1)][r (32)][s (32)].
    let mut bytes = sig.0;
    // s' = n - s, as a 32-byte big-endian subtraction.
    let mut borrow = 0i16;
    for i in (0..32).rev() {
        let diff = SECP256K1_ORDER_BE[i] as i16 - bytes[33 + i] as i16 - borrow;
        let (val, next_borrow) = if diff < 0 { (diff + 256, 1) } else { (diff, 0) };
        bytes[33 + i] = val as u8;
        borrow = next_borrow;
    }
    // Negating s flips the parity of R, so flip the recovery id's low bit.
    bytes[0] ^= 0x01;
    MessageSignature(bytes)
}
