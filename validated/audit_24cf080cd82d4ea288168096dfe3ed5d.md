### Title
Gas cost truncated to zero when base fee is sub-1-upc — free EVM execution for UEA payloads - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`Keeper.CalculateGasCost` truncates the dynamic EVM base fee (an `sdkmath.LegacyDec` with 18 decimals of internal sub-unit precision) down to a whole `upc` *before* multiplying by `gasUsed`. If the network's base fee ever decays below `1 upc`, the truncation floors it to `0`, and `DeductGasFeesFromReceipt` treats a non-positive `gasCost` as a legitimate no-fee case, skipping any burn. This is a direct analog of the "Division Rounding to Zero" (Pattern 1) class from the report: `a += input / x` where `input / x == 0` lets the attacker consume the resource (`b`, i.e. real EVM execution) for free.

### Finding Description [1](#0-0) 

`CalculateGasCost` does:
```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))   // truncates fractional upc
...
effectiveGasPrice := new(big.Int).Set(baseFeeBig)
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)
``` [2](#0-1) 

The comment justifying this asserts "the base fee is always a whole number of upc," but that is an assumption about the feemarket module's dynamically-adjusted base fee, not an invariant enforced in this file or provably guaranteed elsewhere in this repository's scoped code. If the on-chain base fee (adjusted per block by the standard EIP-1559-style elasticity algorithm in the external `x/feemarket` dependency) ever decays to a value whose `LegacyDec` internal representation is `< 1e18` (i.e., less than `1 upc`), `baseFeeBig.Div(..., 1e18)` truncates to `0`. `effectiveGasPrice` becomes `0`, and therefore `gasCost = 0 * gasUsed = 0` regardless of how much gas the UEA payload execution actually consumed.

`DeductGasFeesFromReceipt` explicitly treats this as a valid "nothing to charge" case: [3](#0-2) 
```go
gasCost, err := k.CalculateGasCost(...)
...
if gasCost.Sign() <= 0 {
    return nil
}
```
No fee is deducted or burned, yet `CallUEAExecutePayload` / `CallExecuteUniversalTx` already committed real EVM state changes and consumed real `gasUsed` reported in the receipt: [4](#0-3) 

This is called from both the direct `MsgExecutePayload` gasless flow and the CEA smart-contract-recipient inbound flow, both of which are reachable by an ordinary unprivileged user/attacker: [5](#0-4) [6](#0-5) 

### Impact Explanation
When the truncation-to-zero condition is met, an attacker can submit `MsgExecutePayload` (or a CEA gas-and-payload inbound) that drives arbitrary EVM computation through their UEA/CEA — consuming real chain resources and mutating EVM state — while paying **zero** `upc` gas fee. This is a free/unauthorized-cost module-originated EVM execution: protocol-controlled gas accounting is corrupted (a `gasCost` that should be positive is silently coerced to zero), and repeated exploitation lets an attacker execute unbounded EVM work without paying, which both breaks fee-based DoS protection and results in unpaid execution (a form of fund/accounting drain against the protocol's gas-fee model).

### Likelihood Explanation
Exploitability is entirely state-dependent: it requires the network's dynamically-adjusted base fee to fall below `1 upc` at the moment of execution. Genesis configurations observed in this repo set base fee at a large value (e.g., `1e9 upc`), and the actual base-fee decay/floor behavior is implemented in the external `x/feemarket` module (not vendored/inspectable in this scoped codebase), so whether `MinGasPrice`/`ElasticityMultiplier` params provide a hard floor that always keeps base fee `>= 1 upc` could not be confirmed from the code available here. If such a floor is reliably enforced, this specific precondition may be unreachable in practice; if it is not (e.g., base fee can decay arbitrarily under sustained low utilization, as EIP-1559-style formulas normally allow), this is trivially and repeatedly triggerable by any user with no privilege. This uncertainty should be resolved by checking the feemarket module's `Params` and `CalculateBaseFee` logic actually deployed on Push Chain.

### Recommendation
Do not truncate the base fee to a whole `upc` before multiplying by `gasUsed`. Instead, perform the multiplication in the higher-precision `LegacyDec` domain (`baseFee.Mul(effectiveGasPriceDec).MulInt64(gasUsed)`, or equivalently multiply first then divide once at the end so any fractional remainder rounds up rather than truncating input to zero), analogous to the report's Pattern-1 fix of ensuring `div(wad, chi()) > 0` is checked before use, or restructuring the calculation so precision loss cannot silently zero out a real cost. At minimum, add an explicit floor/guard so that `gasUsed > 0` combined with a non-zero pre-truncation base fee can never yield `gasCost == 0`.

### Proof of Concept
1. Assume (or drive via low block utilization) the on-chain `feemarket` base fee to a value `v` such that `0 < v < 1 upc` (e.g., `v = 0.5` in `LegacyDec` terms, i.e., internal big.Int `5e17`).
2. Submit `MsgExecutePayload` (gasless, so the attacker also pays no Cosmos tx fee — see `app/txpolicy/gasless.go`) targeting the attacker's own UEA, with a payload that performs non-trivial EVM computation (e.g., a loop or storage writes) and `MaxFeePerGas >= 1` so the `maxFeePerGas < baseFeeBig` guard in `CalculateGasCost` is not tripped (it compares against the truncated `baseFeeBig`, which is `0`, so any `maxFeePerGas >= 0` passes).
3. `ExecutePayloadV2` → `CallUEAExecutePayload` executes and reports `receipt.GasUsed > 0`.
4. `DeductGasFeesFromReceipt` → `CalculateGasCost` computes `effectiveGasPrice = floor(0.5) = 0`, so `gasCost = 0 * gasUsed = 0`.
5. `gasCost.Sign() <= 0` short-circuits to `nil` — no `SendCoinsFromAccountToModule`/`BurnCoins` occurs.
6. Result: real EVM computation committed via `writeCache()`, zero `upc` burned — repeatable indefinitely while the base-fee condition holds.

(Note: step 1's reachability of `base fee < 1 upc` depends on the external `x/feemarket` module's parameters, which could not be fully verified in this scoped codebase — see Likelihood Explanation.)

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}
```
