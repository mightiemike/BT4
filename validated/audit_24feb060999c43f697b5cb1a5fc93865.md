### Title
Unauthenticated `da_bumpFeeCpfp` / `da_bumpFeeRbf` RPC Methods Allow Anyone to Broadcast Wallet-Funded Bitcoin Transactions - (File: `crates/common/src/rpc/auth.rs`)

### Summary
The Citrea JSON-RPC `Auth` middleware only requires an API key for three hard-coded methods (`backup_create`, `backup_validate`, `backup_info`). Every other registered RPC method — including the fee-bumping methods exposed by the Bitcoin DA RPC module (`da_bumpFeeCpfp`, `da_bumpFeeRbf`) — is dispatched with no authentication at all, exactly the same class of bug reported for Monero's ZMQ bypass: a state-mutating admin action that the operator would reasonably expect to be gated is left reachable by any unauthenticated caller.

### Finding Description
The RPC server applies a single `Auth` layer to the whole merged `RpcModule<()>`: [1](#0-0) 

`Auth::call` only intercepts methods present in `PROTECTED_METHODS`; everything else is passed straight through to the inner service with zero credential check: [2](#0-1) 

The Bitcoin DA RPC module, which is merged into the top-level RPC module for `BatchProver` and `Sequencer` node types, exposes `da_bumpFeeCpfp` / `da_bumpFeeRbf` under the `da` namespace: [3](#0-2) [4](#0-3) 

These handlers call `BitcoinService::bump_fee`, which funds a PSBT from the service wallet at an attacker-supplied `fee_rate`, signs it, and broadcasts a brand-new Bitcoin transaction via `send_raw_transaction`: [5](#0-4) 

Neither `da_bumpFeeCpfp` nor `da_bumpFeeRbf` appears in `PROTECTED_METHODS`, so this wallet-spending, transaction-broadcasting action is reachable by any remote caller who can reach the node's JSON-RPC port with no API key, unlike the three backup methods that were deliberately protected.

### Impact Explanation
This is an unauthenticated JSON-RPC call that mutates node state, matching the High-severity impact criterion directly. An attacker can:
- Repeatedly call `da_bumpFeeCpfp`/`da_bumpFeeRbf` with an arbitrarily high `fee_rate`, forcing the sequencer/batch-prover's Bitcoin wallet to spend UTXOs on unnecessary high-fee replacement transactions, draining operational funds meant for legitimate commitment/proof submissions.
- Pass `force: true` to `da_bumpFeeCpfp`, bypassing the `CommitBumpNotAllowed` safety check meant to prevent bumping commit transactions (see `FeeServiceError::CommitBumpNotAllowed` guard in `crates/bitcoin-da/src/fee.rs:146-152`), interfering with in-flight sequencer commitment transactions and disrupting DA submission timing.
- Cause repeated RBF replacements that evict and replace the node's own pending transactions, potentially delaying or corrupting the commitment/proof publication pipeline that the rollup depends on for liveness.

### Likelihood Explanation
High. No authentication, no special role, and no on-chain preconditions are required beyond network access to the node's RPC endpoint — the same access level assumed for any other public JSON-RPC call (e.g. `eth_call`). This mirrors the original report's core defect: a documented/expected access boundary (API-key gating of privileged methods) that is not consistently enforced across the RPC surface.

### Recommendation
Add `da_bumpFeeCpfp` and `da_bumpFeeRbf` (and any other state-mutating DA/admin RPC methods) to `PROTECTED_METHODS` in `crates/common/src/rpc/auth.rs`, or better, invert the model to an allow-list of explicitly public, read-only methods, so any newly added mutating RPC method is protected by default rather than requiring an opt-in.

### Proof of Concept
1. Start a `BatchProver` or `Sequencer` node with the Bitcoin DA backend and no `api_key` configured (or with one configured, since these methods ignore it anyway).
2. From any remote host with network access to the RPC port, send:
```json
{"jsonrpc":"2.0","id":1,"method":"da_bumpFeeCpfp","params":[null, 100000.0, true]}
```
3. Observe that `BitcoinService::bump_fee` executes: it funds a PSBT from the node's wallet UTXOs, signs it, and broadcasts a new transaction via `send_raw_transaction` — with no API key or credential supplied, unlike the `backup_*` methods which return `401` under identical conditions.

    pub async fn bump_fee(
        &self,
        txid: Option<Txid>,
        fee_rate: f64,
        force: Option<bool>,
        method: BumpFeeMethod,
    ) -> Result<Txid> {
        // Look for input tx or resolve to monitored last_tx
        let (txid, tx) = match txid {
            None => self
                .monitoring
                .get_last_tx()
                .await
                .ok_or(BitcoinServiceError::NoMonitoredTransaction)?,
            Some(txid) => {
                let monitored_tx = self
                    .monitoring
                    .get_monitored_tx(&txid)
                    .await
                    .ok_or(BitcoinServiceError::ParentTransactionNotFound(txid))?;
                (txid, monitored_tx)
            }
        };

        let TxStatus::InMempool { .. } = tx.status else {
            return Err(BitcoinServiceError::WrongStatusForBumping(tx.status));
        };

        let Some(utxo) = self.utxo_manager.get_prev_utxo().await else {
            return Err(BitcoinServiceError::MissingPreviousUTXO);
        };

        let funded_psbt = match method {
            BumpFeeMethod::Cpfp => {
                self.fee
                    .bump_fee_cpfp(&tx, &txid, fee_rate, force, utxo)
                    .await
            }
            BumpFeeMethod::Rbf => self.fee.bump_fee_rbf(tx.kind, &txid).await,
        }
        .map_err(|e| BitcoinServiceError::FeeBumpFailure(e.to_string()))?;

        let wallet_psbt = self
            .client
            .wallet_process_psbt(&funded_psbt, Some(true), None, None)
            .await?;

        let processed = self.client.finalize_psbt(&wallet_psbt.psbt, None).await?;

        let Some(Ok(new_tx)) = processed.transaction() else {
            return Err(BitcoinServiceError::PsbtFinalizationFailure);
        };
        let Some(raw_hex) = processed.hex else {
            return Err(BitcoinServiceError::PsbtFinalizationFailure);
        };

        self.client.test_mempool_accept(&[&raw_hex]).await?;

        let new_txid = self.client.send_raw_transaction(&raw_hex).await?;
