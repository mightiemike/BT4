## Finding

### Title
Unbounded recursive traversal of attacker-influenced `NestedIntList` bytecode-segment structures causes stack overflow during compiled-class hashing - (File: crates/starknet_api/src/contract_class/compiled_class_hash.rs)

### Summary
The Scriban report describes a class of bug where a fix that added a *depth limit* to one recursive-descent code path (expression parsing) did not cover a second, structurally similar recursive path (array-initializer parsing), so deeply nested attacker input still triggers an uncaught `StackOverflowException`. The sequencer contains an analogous pattern: compiled-class hashing walks an attacker-influenced, tree-shaped `NestedIntList`/`HashableNestedIntList` structure with plain (non-tail) recursion and **no depth limit anywhere in the call chain**.

### Finding Description
`bytecode_hash_node` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs` recursively walks the bytecode-segmentation tree of a compiled class to compute its `CompiledClassHash`: [1](#0-0) 

This function has no recursion/depth guard: for a `Node` variant it simply calls itself once per child, and children can themselves be `Node`s, so the native call-stack depth equals the nesting depth of the `bytecode_segment_lengths` (`NestedIntList`) tree that accompanies a compiled (CASM) class: [2](#0-1) 

The exact same unguarded recursive pattern is duplicated in the Starknet OS hint implementation that reconstructs the bytecode-segment tree from the same `NestedIntList` data during OS re-execution: [3](#0-2) [4](#0-3) 

This `NestedIntList` value is produced by the Sierra→CASM compiler based on the structure of the *submitted* Sierra program (functions/branches), and it is embedded directly in the `CasmContractClass` that the sequencer compiles from a user-submitted `DECLARE` transaction: [5](#0-4) 

`executable_class.hash(&HashVersion::V2)` at line 69 immediately invokes `HashableCompiledClass::hash` → `hash_inner` → `bytecode_hash`, which is where the unguarded `bytecode_hash_node` recursion is entered: [6](#0-5) 

Only the total serialized/bytecode *size* of the submitted class is bounded (`max_bytecode_size` / `DEFAULT_MAX_BYTECODE_SIZE`, enforced as a CLI flag to the external compiler and checked post-compile): [7](#0-6) 

Nothing bounds the **depth** of the `bytecode_segment_lengths` tree itself; the compiler derives the tree shape from the control-flow/function nesting of the Sierra source, which an attacker fully controls when authoring the declared contract's Cairo/Sierra code (e.g., via deeply nested match/if branches or a deep function-call chain that the compiler segments hierarchically).

### Impact Explanation
`bytecode_hash_node` (and its OS counterpart `create_bytecode_segment_structure_inner`/`BytecodeSegmentNode::hash`) run on every node that needs to compute or re-verify a declared class's compiled-class hash: the sequencer compiling the `DECLARE` transaction, any node re-deriving/checking the compiled class hash during block building or state verification, and the Starknet OS during re-execution. A `StackOverflowException`-equivalent in Rust (stack overflow aborts the process; it cannot be caught with `Result`/`panic::catch_unwind`) would crash the process performing the hash computation. Since this computation is mandatory and deterministic for any accepted `DECLARE` transaction, a single malicious declare could be crafted to crash every honest node that processes it, which is a network-wide denial of service — nodes become unable to confirm new transactions/blocks until patched.

### Likelihood Explanation
Exploitability hinges on whether an attacker can force the Sierra→CASM compiler (an external, trusted dependency – `cairo-lang-starknet-classes`/`cairo-lang-sierra-to-casm`) to emit a `NestedIntList` tree whose recursion depth is large enough to exhaust the thread stack (typically tens of thousands of frames, similar order of magnitude to the PoC's 5000-deep nesting). Because bytecode-segment trees are shaped by the code's own function/branch structure and Sierra programs can be authored with very deep nested control flow within the size limit, this is plausible without needing to bypass any explicit protection — the sequencer's own hashing code has no depth guard at all, unlike (for instance) the `RecursionDepthGuard` explicitly used for execution-time call recursion (`crates/blockifier/src/execution/entry_point.rs`). This makes it Medium/High likelihood as an analog, though full confirmation requires validating how deep the actual compiler-produced segmentation tree can go for a given class size.

### Recommendation
Add an explicit depth counter/limit to `bytecode_hash_node` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs` and to `create_bytecode_segment_structure_inner`/`BytecodeSegmentNode::hash` in `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`, returning an error (rather than recursing further) once a configured maximum nesting depth is exceeded, consistent with how other recursive/entry-point call depths are bounded elsewhere in the codebase (`RecursionDepthGuard`, `max_recursion_depth`). Alternatively, convert these functions to an iterative (explicit-stack) traversal to eliminate the native-stack dependency entirely.

### Proof of Concept
Not independently reproduced against this repository (would require constructing a Sierra program whose compiled bytecode segmentation tree nests deeply enough to exhaust the stack and confirming the Sierra→CASM compiler actually emits such a tree); this write-up is based on static code-path analysis of the unguarded recursive functions identified above.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

fn hash_inner<H, EH, NL>(hashable_class: &impl HashableCompiledClass<EH, NL>) -> CompiledClassHash
where
    H: StarkHash,
    EH: EntryPointHashable,
    NL: HashableNestedIntList,
{
    let external_funcs_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_external_entry_points());
    let l1_handlers_hash = entry_point_hash::<H, EH>(hashable_class.get_hashable_l1_entry_points());
    let constructors_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_constructor_entry_points());

    let bytecode_hash = bytecode_hash::<H, NL>(
        &hashable_class.get_bytecode(),
        &*hashable_class.get_bytecode_segment_lengths(),
    );

    // Compute total hash by hashing each component on top of the previous one.
    CompiledClassHash(H::hash_array(&[
        *COMPILED_CLASS_V1,
        external_funcs_hash,
        l1_handlers_hash,
        constructors_hash,
        bytecode_hash,
    ]))
}

impl BytecodeSegmentNode {
    pub(crate) fn hash<H: HashFunction>(&self) -> StarkHash {
        match self {
            BytecodeSegmentNode::Leaf(leaf) => H::hash_array(&leaf.data),
            BytecodeSegmentNode::InnerNode(inner_node) => {
                let flatten_input: Vec<_> = inner_node
                    .segments
                    .iter()
                    .flat_map(|segment| [Felt::from(segment.length), segment.node.hash::<H>()])
                    .collect();
                H::hash_array(&flatten_input) + Felt::ONE
            }
        }
    }

    pub(crate) fn is_leaf(&self) -> bool {
        match self {
            BytecodeSegmentNode::Leaf(_) => true,
            BytecodeSegmentNode::InnerNode(_) => false,
        }
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

#[test]
fn test_max_bytecode_size() {
    let contract_class = get_test_contract();
    let expected_casm_bytecode_length = 1965;

    // Positive flow.
    let compiler = SierraToCasmCompiler::new(SierraCompilationConfig {
        max_bytecode_size: expected_casm_bytecode_length,
        max_memory_usage: DEFAULT_MAX_MEMORY_USAGE,
        max_cpu_time: DEFAULT_MAX_CPU_TIME,
        audited_libfuncs_only: false,
    });
    let casm_contract_class = compiler
        .compile(contract_class.clone())
        .expect("Failed to compile contract class. Probably an issue with the max_bytecode_size.");
    assert_eq!(casm_contract_class.bytecode.len(), expected_casm_bytecode_length);

    // Negative flow.
    let compiler = SierraToCasmCompiler::new(SierraCompilationConfig {
        max_bytecode_size: expected_casm_bytecode_length - 1,
        max_memory_usage: DEFAULT_MAX_MEMORY_USAGE,
        max_cpu_time: DEFAULT_MAX_CPU_TIME,
        audited_libfuncs_only: false,
    });
    let result = compiler.compile(contract_class);
    assert_matches!(result, Err(CompilationUtilError::CompilationError(string))
        if string.contains("Code size limit exceeded.")
    );
}
