## Analog Vulnerability Found

### Title
Improper Input Validation: Missing Re-Validation of Cached Cairo0 Compiled Classes After Non-Committed/Reverted Declarations - ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
The Apache CXF advisory describes an SAML token validation bypass where cached authentication state was trusted without re-validating the token against the actual (current) trust state, allowing invalid tokens to be treated as valid. The sequencer contains an analogous pattern in `StateReaderAndContractManager::get_compiled_from_class_manager`: cached compiled classes are trusted as "declared" without re-checking the authoritative state, except for one code path (Cairo1/native classes) which does perform the recheck — while the Cairo0 (`V0`) path is explicitly skipped.

### Finding Description
`get_compiled_from_class_manager` reads from a process-global `ContractClassManager` cache (shared across block-building attempts, including speculative/aborted/candidate blocks) before consulting the authoritative state reader: [1](#0-0) 

The comment explicitly acknowledges the threat model: a class can exist in the global cache purely because it was declared during a block-building attempt that was subsequently discarded/reverted ("it might contain a declared class from a reverted block, for example"), and thus the code re-validates against `self.state_reader.is_declared(class_hash)` for that case. However, this re-validation is only performed in the `_` (non-`V0`) match arm; the `RunnableCompiledClass::V0(_) => {}` arm performs no such check at all, meaning Cairo0 classes cached during a discarded/reverted block-building attempt are returned as valid ("declared") indefinitely, with no cross-check against the actual committed state's `declared_contracts` map.

This mirrors the CXF root cause exactly: a security-relevant validation result (SAML validity / class declaration validity) is cached, and the cache is trusted for a subset of cases without re-confirming it is still true against the authoritative source, letting a previously-valid-but-now-invalid credential/class be treated as valid.

### Impact Explanation
If a Cairo0 declare transaction is processed as part of a candidate block that is built speculatively and then discarded (e.g., due to concurrency-scheduler abort/re-execution, bouncer rejection, or block-building being aborted before commit), the `class_hash -> CompiledClasses::V0` entry remains in the shared `GlobalContractCache` used by `ContractClassManager`. Any subsequent transaction (deploy, invoke, or replace-class) that references that `class_hash` will have `get_compiled_class` return the stale cached class as if it were declared, even though the class was never committed to state and `declared_contracts` for that hash is `false`. This allows execution against a class hash that is not authoritatively declared, which can produce:
- A committed state root/block hash that diverges from what an honest node (with an empty/different cache) would produce for the same block, since the honest node would reject the same transaction with `UndeclaredClassHash`.
- Unauthorized execution of contract logic tied to a class hash that should be rejected, potentially affecting account behavior for deploy/invoke flows that depend on `class_hash` declaration status.

### Likelihood Explanation
Reachable purely via legitimate use of the public transaction/declare-transaction paths: a Cairo0 declare transaction included in a candidate block that later gets discarded (a normal occurrence under concurrent execution, mempool reordering, or bouncer block-fullness rejection as seen in `commit_tx`/`worker_logic.rs`), followed by any other transaction from an unprivileged sender referencing the same `class_hash`. No malicious operator/peer/proposer behavior is required — only ordinary sequencer operation combined with the fact that the `ContractClassManager` cache is not scoped/rolled-back per aborted block-building attempt.

### Recommendation
Apply the same `is_declared` re-validation currently done for non-`V0` classes to the `RunnableCompiledClass::V0(_)` branch in `get_compiled_from_class_manager`, so that Cairo0 cache hits are also confirmed against the authoritative state reader before being trusted, closing the gap between cached-but-unconfirmed class data and the certified declared-class state.

### Proof of Concept
1. Submit a Cairo0 `DeclareTransaction` for class hash `C` in a block-building attempt that gets included in a candidate block execution (populating the global `ContractClassManager` cache via `set_and_compile`) but is subsequently discarded/aborted before commit (e.g., due to concurrency validation failure/re-execution or bouncer rejecting the block as full, as modeled in `commit_tx`/`TransactionExecutorError::BlockFull` in `worker_logic.rs`).
2. Confirm via the committed state that `declared_contracts[C] == false` (class never actually declared).
3. Submit a subsequent transaction (e.g., `DeployAccount` or `Invoke`) referencing class hash `C`.
4. Because `get_compiled_from_class_manager`'s `V0` arm skips the `is_declared` check performed for non-`V0` classes [2](#0-1) , the stale cached `V0` class is returned as valid, allowing the transaction to proceed against a class the network never actually declared.

impl<S: FetchCompiledClasses> StateReaderAndContractManager<S> {
    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }
