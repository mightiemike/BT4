### Title
Anonymous request with crafted `host` query param causes unhandled exception (DoS) in `sanitizeHost` instead of graceful `null` rejection - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost` is designed to validate the `host` query parameter and return `null` (or throw a controlled `InvalidHostError` when `throwOnInvalid` is explicitly requested) for malformed input. However, it internally calls `new URL(https://${decodeHost(sanitizedHost)})` without any error handling. Because `decodeHost` simply calls `atob()` on attacker-controlled base64 data, an attacker can supply a `host` value that passes the base64 regex check but decodes into bytes that are illegal in a URL host (e.g., control characters, forbidden host code points, or a purely whitespace string). This causes the native `URL` constructor to throw a raw `TypeError`, which propagates out of `sanitizeHost` uncaught — a panic instead of the intended no-op/`null` return.

The base64 regex only checks that the *encoded* string uses base64 characters — it does not, and cannot, constrain what bytes the decoded string contains. `atob()` will happily decode any well-formed base64 string into arbitrary bytes, including control characters (0x00–0x1F), forbidden host code points (`<`, `>`, `"`, `` ` ``, `{`, `}`, `|`, `\`, `^`, space, etc.), or an empty/whitespace-only string. When such a decoded value is interpolated into `https://${decodedHost}` and passed to `new URL(...)`, the WHATWG URL parser throws `TypeError: Invalid URL` because these host code points are illegal. This throw is not wrapped in a `try/catch` anywhere in `sanitizeHost`, so it escapes the function as an unhandled exception rather than returning `null` (the function's documented no-op behavior for invalid input — see `packages/apps/shopify-api/docs/reference/utils/sanitizeHost.md`).

This function is called directly on the raw, attacker-controlled `host` query parameter (without a preceding `throwOnInvalid` guard, i.e. callers rely on the `null`-return contract) in multiple unauthenticated request-handling code paths, for example: [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

All of these call sites expect `sanitizeHost` to return `null` for bad input and then take a graceful branch (redirect to login, render App Bridge, return a 500 with a friendly message, etc.). Instead, a crafted `host` value causes an uncaught `TypeError` to bubble up through the authentication/redirect pipeline, bypassing the intended error-handling branches.

### Impact Explanation
This is directly analogous to the referenced ibc-go fix: a state-validation function that is supposed to be a safe no-op on invalid/attacker-supplied input instead panics with an unhandled exception. Here, any anonymous request to an app's OAuth entry points, admin authentication route, or embedded-app redirect endpoint that includes a crafted `host` query parameter can trigger an uncaught `TypeError` deep inside the shared `shopify-api` validation utility used by every `shopify-app-*` adapter package (Express, Remix, React Router). Depending on the hosting runtime and its top-level error handling, this can manifest as unhandled promise rejections, 500-level failures on shop-facing routes, or process-level instability under repeated requests, since the exception is thrown outside any of the callers' expected error-handling branches (some callers do not wrap the call in `try/catch` at all, e.g. `redirect-to-shopify-or-app-root.ts`).

### Likelihood Explanation
The `host` parameter is fully attacker-controlled on any GET request to the app's public authentication/redirect endpoints — no session, signature, or prior authentication is required to reach `sanitizeHost`. Constructing a base64 string that decodes to a byte sequence containing forbidden host code points (or being purely whitespace) is trivial for a remote, unauthenticated actor. This makes exploitation straightforward and repeatable at scale.

### Recommendation
Wrap the `decodeHost`/`new URL(...)` logic inside `sanitizeHost` in a `try/catch`, treating any parsing failure as an invalid host (returning `null`, or throwing the documented `InvalidHostError` only when `throwOnInvalid` is true) instead of letting the native `URL` constructor's exception propagate uncaught. Add regression tests covering base64 payloads that decode to control characters, forbidden host code points, and empty/whitespace strings.

### Proof of Concept
1. Choose a byte sequence that base64-decodes cleanly but produces an illegal URL host, e.g. a string containing a NUL byte or backslash: `payload = "\u0000.myshopify.com/admin"`.
2. Base64-encode it: `host = Buffer.from(payload, 'binary').toString('base64')` (this passes the `^[0-9a-zA-Z+/]+={0,2}$` regex).
3. Send an anonymous GET request to any embedded-app admin route or auth redirect route exposed by a `shopify-app-remix`/`shopify-app-react-router`/`shopify-app-express` app, e.g.:
   `GET /?shop=test.myshopify.com&host=<crafted_base64_host>`
4. Internally this triggers `shopify.utils.sanitizeHost(host)` → `decodeHost(host)` → `atob(...)` producing the illegal byte sequence → `new URL("https://" + illegalHost)` throws `TypeError: Invalid URL`, which is not caught in `sanitizeHost`, `validateShopAndHostParams`, or `redirectToShopifyOrAppRoot`, causing an unhandled exception instead of the expected graceful rejection of the malformed host.

export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }

    return sanitizedHost;
  };
}
