### Title
Unbounded Full-Set Iteration on Every New Ballot Creation Enables Attacker-Driven Gas/DoS Growth - (File: x/uvalidator/keeper/ballot.go)

### Summary
`CreateBallot` unconditionally walks the entire `ActiveBallotIDs` collection (via `ExpireBallotsBeforeHeight`) every single time a brand-new ballot is created, fetching each active ballot from state to check its expiry height. Because a new ballot is created for every distinct inbound/outbound observation an unprivileged user can trigger (e.g. many small, cheap cross-chain deposits observed by honest validators), the size of `ActiveBallotIDs` — and therefore the cost of every subsequent `CreateBallot` call — grows with attacker-controlled input, mirroring the TokensFarm `_removeParticipant()` pattern of iterating an ever-growing, never-pruned array on every user-triggered operation.

### Finding Description
`x/uvalidator/keeper/ballot.go`:
- `CreateBallot` (lines 13-68) calls `k.ExpireBallotsBeforeHeight(ctx, blockHeight)` (line 37) before persisting a new ballot.
- `ExpireBallotsBeforeHeight` (lines 320-364) does a two-phase walk of the **entire** `ActiveBallotIDs` collection: phase 1 iterates every active ballot ID and issues a `k.Ballots.Get(ctx, id)` for each one to check `BlockHeightExpiry`; phase 2 then calls `MarkBallotExpired` on the stale ones.

`GetOrCreateBallot` only invokes `CreateBallot` the first time a given ballot ID is observed (confirmed by `TestIntegration_GetOrCreateBallot`, which shows a second call for the same ID returns the existing ballot without re-creating it) [1](#0-0) . Each `MsgVoteInbound` / `MsgVoteOutbound` from an honest validator, in response to an ordinary unprivileged user's cross-chain deposit, derives a fresh ballot ID (`GetInboundBallotKey`/`GetOutboundBallotKey`) and calls `VoteOnBallot → GetOrCreateBallot → CreateBallot` for any genuinely new inbound/outbound event [2](#0-1) .

Because an unprivileged attacker fully controls the rate and count of distinct low-value cross-chain transfers they submit on a source chain, they control the rate at which new ballots get created on Push Chain. Every new ballot creation pays a cost proportional to the current size of `ActiveBallotIDs` (one `Ballots.Get` per active ID), and ballots are only pruned from that set as a side effect of a *subsequent* `CreateBallot` call. If the attacker creates new distinct inbounds faster than the ballot expiry window (`DefaultExpiryAfterBlocks`) can clear the backlog, `ActiveBallotIDs` accumulates unboundedly, making each new ballot creation more expensive than the last — a quadratic-cost pattern driven entirely by unprivileged input, directly analogous to the reported `TokensFarm._removeParticipant()` issue where stale array entries were never pruned and every operation re-iterated the whole array.

### Impact Explanation
This does not directly steal or freeze funds, but it degrades the honest-validator finalization path: as `ActiveBallotIDs` grows, gas/CPU cost of processing every subsequent `MsgVoteInbound`/`MsgVoteOutbound` (which triggers ballot creation for new events) increases, potentially pushing individual vote transactions toward gas-limit failures and slowing/blocking finalization of legitimate users' inbounds and outbounds — a network-reachable, non-privileged, non-network-level DoS vector against the universal-execution voting/finalization pipeline, in scope per the "denial of service only when it is not network-level and is reachable without privileged control" clause.

### Likelihood Explanation
Medium. Triggering many distinct low-value cross-chain deposits is cheap and fully within reach of an unprivileged external actor; no validator, node, or admin cooperation is required. The practical severity depends on `DefaultExpiryAfterBlocks` and typical `ActiveBallotIDs` cardinality, which were not fully characterized in this pass — I could not confirm the exact default expiry constant value or measure real-world active-ballot counts, so the precise gas-growth curve and the block height at which this becomes materially disruptive remain unverified and should be confirmed with a load test or by reading `types.DefaultExpiryAfterBlocks` and production ballot throughput.

### Recommendation
Decouple ballot-expiry pruning from ballot-creation cost: expire stale ballots via a bounded, paginated sweep (e.g. limited to N entries per block in `EndBlock`, or indexed by expiry height so only genuinely due ballots are ever touched) rather than walking the full `ActiveBallotIDs` set inside every `CreateBallot` call. Consider an expiry-height-ordered secondary index so expiration work is O(entries actually expiring) rather than O(all active ballots).

### Proof of Concept
Not executed — this is a structural/gas-growth analysis based on static code reading. To validate: seed thousands of distinct pending ballots (e.g. by driving `VoteOnBallot` with unique ballot IDs and expiry heights far in the future) and measure the wall-clock/gas cost of a subsequent `CreateBallot` call before vs. after backlog growth, similar to `TestIntegration_GetOrCreateBallot` but at scale.

func TestIntegration_GetOrCreateBallot(t *testing.T) {
	t.Run("creates a new ballot when none exists", func(t *testing.T) {
		chainApp, ctx, validators := setupBallotTest(t, 2)
		k := chainApp.UvalidatorKeeper
		voters := voterAddrs(t, validators)

		ballot, isNew, err := k.GetOrCreateBallot(ctx, "goc-new",
			uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
			voters, 1, 100)
		require.NoError(t, err)
		require.True(t, isNew, "should report newly created")
		require.Equal(t, "goc-new", ballot.Id)
		require.Equal(t, uvalidatortypes.BallotStatus_BALLOT_STATUS_PENDING, ballot.Status)
	})

	t.Run("returns existing ballot without creating a duplicate", func(t *testing.T) {
		chainApp, ctx, validators := setupBallotTest(t, 2)
		k := chainApp.UvalidatorKeeper
		voters := voterAddrs(t, validators)

		// First call creates
		b1, isNew, err := k.GetOrCreateBallot(ctx, "goc-exist",
			uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
			voters, 1, 100)
		require.NoError(t, err)
		require.True(t, isNew)

		// Second call returns existing, isNew == false
		b2, isNew, err := k.GetOrCreateBallot(ctx, "goc-exist",
			uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
			voters, 1, 100)
		require.NoError(t, err)
		require.False(t, isNew, "should not report new on second call")
		require.Equal(t, b1.Id, b2.Id)
		require.Equal(t, b1.BlockHeightCreated, b2.BlockHeightCreated)
	})

func (k Keeper) VoteOnBallot(
	ctx context.Context,
	id string,
	ballotType types.BallotObservationType,
	voter string,
	voteResult types.VoteResult,
	voters []string,
	votesNeeded int64,
	expiryAfterBlocks int64,
) (
	ballot types.Ballot,
	isFinalized bool,
	isNew bool,
	err error) {

	k.Logger().Debug("vote on ballot",
		"ballot_id", id,
		"ballot_type", ballotType.String(),
		"voter", voter,
		"vote_result", voteResult.String(),
		"votes_needed", votesNeeded,
	)

	ballot, isNew, err = k.GetOrCreateBallot(ctx, id, ballotType, voters, votesNeeded, expiryAfterBlocks)
	if err != nil {
		return ballot, false, false, errors.Wrap(err, "Error while voting on the ballot")
	}
