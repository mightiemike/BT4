### Title
Factory/UEA proxy system contracts deployed at genesis without ever calling `initialize()` — front-runnable owner takeover - (File: x/uexecutor/keeper/genesis.go, x/uregistry/keeper/genesis.go)

### Summary
Push Chain's genesis deployment logic for the UEA Factory and other proxy-based system contracts manually injects EVM account state (code, `EIP-1967` proxy-admin slot, proxy-implementation slot) instead of deploying the contract normally and invoking its Solidity `initialize()` function. This is the same bug class as the external report: an upgradeable/`Initializable` contract's `initialize()`-style setup routine is never called, leaving initializer-gated state (in this case `Ownable` owner / `Initializable._initialized`) unset and open to a hostile first caller.

### Finding Description
`deployFactoryEA` in [1](#0-0)  deploys the Factory proxy, implementation, and proxy-admin contracts purely by writing EVM account/code/storage directly: [2](#0-1) 

Only the `PROXY_ADMIN_SLOT` and `PROXY_IMPLEMENTATION_SLOT` (EIP-1967 slots) are written. There is no `evmKeeper.CallEVM(...)`/`DerivedEVMCall(...)` invocation of the Factory's `initialize(initialOwner)` method anywhere in this file or in `deployFactoryImplContract`/`deployProxyAdminContract`.

The same pattern repeats for every registry-managed system contract in `deploySystemContracts`: `deployProxyAdminContract`, `deployImplementationContract`, and `deployProxyContract` in [3](#0-2)  only set bytecode and EIP-1967 slots; the `owner` slot manually written in `deployProxyAdminContract` ( [4](#0-3) ) covers the (non-upgradeable, non-initializable) `ProxyAdmin` contract only — it does not cover the initializer flag of the upgradeable implementation/proxy contracts behind `deployImplementationContract`/`deployProxyContract`.

Crucially, the Factory's `initialize(address initialOwner)` ABI method is defined in `FactoryV1ABI` ( [5](#0-4) ) and is only ever invoked from **test setup code**, not production genesis: [6](#0-5) 

That test helper explicitly deploys the Factory, then separately calls `"initialize", owner` via `CallEVM`, and only after that step does `owner()` return the expected value — confirming that without this call the deployed Factory is left with an un-set (likely `address(0)`) owner and an un-flipped OpenZeppelin `Initializable._initialized` guard. Since production genesis (`x/uexecutor/keeper/genesis.go`) never performs this step, the live Factory proxy on-chain is deployed in the same "never-initialized" state that the test code has to work around manually.

### Impact Explanation
An `Initializable`-based contract deployed with `initialize()` never called is exploitable by any unprivileged external caller: the first account to call `initialize()` on the live Factory proxy (or, if the implementation itself was never marked as having its initializers disabled, directly on the implementation) becomes the owner. Given the Factory drives `setUEAProxyImplementation`, `registerNewChain`, and `registerUEA`/`deployUEA` (per `FactoryV1ABI`, [7](#0-6) ), an attacker who wins this race can set a malicious `UEA_PROXY_IMPLEMENTATION`, causing every subsequently deployed Universal Executor Account (`DeployUEAV2`/`CallFactoryToDeployUEA`, used throughout inbound execution — e.g. [8](#0-7)  and [9](#0-8) ) to run attacker-controlled code. This is unauthorized module-originated EVM execution and unauthorized UEA execution over user/protocol funds routed through the universal execution pipeline — squarely in the "Allowed Impact" scope (unauthorized UEA execution, unauthorized state transitions, fund draining via forged UEA implementation).

### Likelihood Explanation
High if this analysis is confirmed against the actual Solidity source: taking ownership of an uninitialized `Ownable`+`Initializable` proxy is a well-known, trivially exploitable pattern requiring only a single unprivileged transaction sent immediately after genesis/chain launch (a bot racing the chain's genesis block). No validator, relayer, or admin privilege is needed — this matches the "unprivileged external attacker" threat model required by the scope.

### Recommendation
- After deploying the Factory proxy and implementation bytecode in `deployFactoryEA` (and analogously for every `Initializable` implementation deployed by `deploySystemContracts`), invoke the contract's `initialize(...)` through `evmKeeper.CallEVM`/`DerivedEVMCall` in the same genesis transaction, mirroring what `test/utils/contracts_setup.go` already does for tests.
- Alternatively/additionally, call `_disableInitializers()` semantics on the raw implementation address (i.e., ensure the implementation's own `_initialized` sentinel is set) so the implementation cannot be initialized directly even if the proxy is properly initialized.
- Add an assertion/panic in genesis if the post-deploy `owner()` (or equivalent initializer state) does not match the expected value, to fail fast rather than silently launching with an unprotected contract.

### Proof of Concept
1. Confirm (requires the actual `Factory.sol` / `FactoryImpl` source, not available in this index) that the Factory implementation inherits `Initializable`/`OwnableUpgradeable` and gates `setUEAProxyImplementation`/`registerNewChain` behind `onlyOwner`, with `owner` set only inside `initialize()`.
2. At `InitGenesis`, observe that `deployFactoryEA` writes only code + EIP-1967 slots (no `initialize` call) — [2](#0-1) .
3. Immediately after genesis, submit an EVM transaction calling `initialize(attackerAddress)` on `FACTORY_PROXY_ADDRESS_HEX`.
4. If step 1 holds, `owner()` now returns `attackerAddress`; attacker calls `setUEAProxyImplementation(maliciousImpl)`, hijacking all future UEA deployments.

Note: I was unable to locate the Solidity source (`Factory.sol`/`FactoryImpl`) in the indexed codebase to directly confirm the storage layout and modifier usage referenced above — this is inferred from the `FactoryV1ABI` definition and the fact that production genesis code never calls `initialize` while test setup code explicitly must. A Devin session with full repository/file access should verify the actual contract source (likely stored as compiled bytecode constants rather than `.sol` files in this repo) before treating this as a confirmed, exploitable finding.

func deployFactoryProxy(ctx context.Context, evmKeeper types.EVMKeeper) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	proxyAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)
	proxyAdminOwner := common.HexToAddress(types.PROXY_ADMIN_ADDRESS_HEX)
	factoryImplAddress := common.HexToAddress(types.FACTORY_IMPL_ADDRESS_HEX)

	// Compute the code hash from the runtime bytecode
	codeHash := crypto.Keccak256(types.ProxyRuntimeBytecode)

	// Create the EVM account object
	evmAccount := statedb.Account{
		Nonce:    1,             // to prevent tx nonce=0 conflicts
		Balance:  new(uint256.Int), // zero balance by default
		CodeHash: codeHash,      // link to deployed code
	}

	// Set the EVM account with the factory proxy contract
	err := evmKeeper.SetAccount(sdkCtx, proxyAddress, evmAccount)
	if err != nil {
		panic("failed to set factory proxy contract account: " + err.Error())
	}

	// Store the runtime bytecode linked to the code hash
	evmKeeper.SetCode(sdkCtx, codeHash, types.ProxyRuntimeBytecode)

	// Update proxyAdmin Slot with the proxyAdmin owner address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_ADMIN_SLOT, common.LeftPadBytes(proxyAdminOwner.Bytes(), 32))

	// Update proxyImplementation Slot with the factory implementation address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_IMPLEMENTATION_SLOT, common.LeftPadBytes(factoryImplAddress.Bytes(), 32))
}

func deploySystemContracts(ctx context.Context, evmKeeper types.EVMKeeper, systemContracts map[string]types.ContractAddresses) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Sort contract names for deterministic iteration order across all validators
	names := make([]string, 0, len(systemContracts))
	for name := range systemContracts {
		names = append(names, name)
	}
	sort.Strings(names)

	for _, name := range names {
		contract := systemContracts[name]

		proxyAddr := common.HexToAddress(contract.Address)
		if isContractDeployed(sdkCtx, evmKeeper, proxyAddr) {
			sdkCtx.Logger().Info(
				"system contract already deployed, skipping",
				"name", name,
				"proxy", proxyAddr.Hex(),
			)
			continue
		}

		bytecodes, ok := types.BYTECODE[name]
		if !ok {
			panic(fmt.Sprintf("no bytecode found for contract %s", name))
		}

		// 1. Deploy ProxyAdmin with ADMIN_RUNTIME
		deployProxyAdminContract(ctx, evmKeeper, contract.ProxyAdmin, bytecodes.ADMIN_RUNTIME)

		// 2. Deploy Implementation with IMPL_RUNTIME
		deployImplementationContract(ctx, evmKeeper, contract.Implementation, bytecodes.IMPL_RUNTIME)

		// 3. Deploy Proxy with PROXY_RUNTIME
		deployProxyContract(ctx, evmKeeper, contract.Address, contract.ProxyAdmin, contract.Implementation, bytecodes.PROXY_RUNTIME)
	}
}
