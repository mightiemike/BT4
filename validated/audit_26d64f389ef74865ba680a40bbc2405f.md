### Title
`accrue` advances `last-update` whenever the borrow index ticks even if the liquidity index rounds to zero, permanently discarding the elapsed time-delta needed for liquidity-index growth - ([File: mainnet/contracts/vault/v0-vault-sbtc.clar])

### Summary
`next-index` and `next-liquidity-index` are both derived from the same `time-delta = stacks-block-time - last-update`, but `calc-multiplier-delta` rounds the borrow-index multiplier up (`true`) and the liquidity-index multiplier down (`false`) for that identical interval. `accrue` then advances the shared `last-update` variable if *either* index changed, using an `or` condition, so a tick in the borrow index alone resets the clock that the liquidity index depends on before it ever accumulates enough time to round to a non-zero increment.

### Finding Description
1. `accrue` binds `idx`/`lidx` from the current `index`/`lindex` vars, then computes `next` via `next-index` and `nliq` via `next-liquidity-index` in the same `let` (lines 841-842).
2. Both private functions independently recompute `time-delta` as `(- stacks-block-time (var-get last-update))` (lines 384, 398) — identical value, read from the *same* unmodified `last-update` at that point in the transaction.
3. `calc-multiplier-delta` is called with `true` (round up) for the borrow rate at line 387, and `false` (round down) for the liquidity rate at line 401. Because the liquidity rate is derived from the borrow rate scaled down by utilization and `fee-reserve` (`calc-liquidity-rate`), it is systematically smaller than the borrow rate for the same interval, making it far more likely to round down to exactly `INDEX-PRECISION` (no growth) for short intervals while the up-rounded borrow multiplier already exceeds `INDEX-PRECISION`.
4. Back in `accrue`, line 849 updates `index` only `(if (not (is-eq idx next)) ...)`, and line 852 updates `lindex` only `(if (not (is-eq lidx nliq)) ...)` — these gates are independent and correctly reflect whether each index individually moved.
5. Line 858, however, advances the *shared* `last-update` using `(or (not (is-eq idx next)) (not (is-eq lidx nliq)))`. If the borrow index ticks (a near-certainty due to round-up) while the liquidity index does not (round-down truncation for small deltas), `last-update` is still reset to `stacks-block-time`.
6. Because `last-update` is shared, the next call's `time-delta` for the liquidity index starts over at zero elapsed time from the reset point instead of continuing to accumulate from the last point at which the liquidity index actually moved. The "lost" seconds between ticks are never recovered by any later check — there is no separate `last-liquidity-update` tracking var.

### Impact Explanation
If `accrue` is invoked frequently relative to how large `time-delta` needs to be for the liquidity multiplier to round to a non-`INDEX-PRECISION` value (accrue is called on every borrow/repay/deposit/redeem per `system-borrow` at line 866, with no access control on `accrue` itself), the liquidity index can be perpetually starved of any growth while the borrow index (and thus borrower debt) keeps compounding normally. Depositors' `zft` value (driven by `lindex`) stops reflecting the interest that borrowers are actually paying, resulting in theft/freezing of unclaimed supply-side yield — matching the **High** severity category (theft/freezing of unclaimed yield).

### Likelihood Explanation
This does not require an adversarial interleaving chosen by an attacker; it is incidental to normal protocol usage under high call frequency (any user calling any lending operation triggers `accrue`). No special privilege or capital is needed — any unprivileged caller of `system-borrow`/repay/deposit/redeem repeatedly resets `last-update` in the course of ordinary interaction. The condition is deterministic given the rate spread and rounding directions in `calc-multiplier-delta`/`calc-liquidity-rate`, whose exact numeric constants I could not fully verify in this pass (they live in a shared utils contract not retrieved here), so confirmation that the liquidity multiplier actually rounds to `INDEX-PRECISION` for realistic call cadences and rates requires a Clarinet PoC.

### Recommendation
Track `last-update` (or the elapsed time-delta) per index (e.g., separate `last-update-borrow` and `last-update-liquidity` vars, or accumulate unclaimed time-delta persisted across calls when an index's multiplier rounds to no-op) so that a stalled liquidity index retains its unconsumed elapsed time instead of having it discarded whenever the borrow index alone ticks.

### Proof of Concept
Clarinet/vitest simnet plan:
1. Deploy `v0-vault-sbtc.clar` with a nonzero borrow rate and a fee-reserve/utilization combination producing a materially smaller liquidity rate.
2. Advance the simnet clock by a small increment (e.g., 1-5 seconds) between calls.
3. Call `accrue` 100 times, each time reading `get-liquidity-index` (or `var-get lindex`) and `var-get index` and `var-get last-update` before/after.
4. Assert `last-update` advances every call (matches `stacks-block-time` after each call) while `get-liquidity-index` stays constant across all 100 calls, and `index`/`total-debt` (borrower side) keeps increasing.
5. Confirm depositor share value (`convert-to-assets-preview`) does not increase proportionally to accrued borrower interest, demonstrating the yield is not being reflected/distributed to liquidity providers. [1](#0-0) [2](#0-1)

(define-private (next-index)
  (let ((states (var-get pause-states))
        (idx (var-get index)))
    (if (get accrue states)
        idx
        (let (
            (rate (interest-rate))
            (time-delta (- stacks-block-time (var-get last-update)))
            (multiplier (if (is-eq time-delta u0)
                          INDEX-PRECISION
                          (calc-multiplier-delta rate time-delta true))))
          (calc-index-next idx multiplier)))))

(define-private (next-liquidity-index)
  (let ((states (var-get pause-states))
        (lidx (var-get lindex)))

        lidx

            (rate (interest-rate))

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
