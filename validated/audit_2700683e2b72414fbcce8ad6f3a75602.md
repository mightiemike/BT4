Based on my research, I found an analogous bug in the NEAR Wallet Contract, which is the closest reachable analog to the AvailBridge `sendMessage` excess-ETH issue: a payable entry point that captures a caller's entire attached deposit but only refunds it on failure, never refunding any *excess* over what the action actually requires on success.

### Title
Wallet Contract does not refund excess attached deposit over the action's own `yocto_near` value on success - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
The `WalletContract::rlp_execute` entry point is `#[payable]`, meaning any caller (relayer or third party) can attach an arbitrary NEAR deposit when submitting an RLP-encoded Ethereum transaction to be executed as a NEAR action. [1](#0-0) 
The full attached deposit is captured into `ExecutionContext::attached_deposit` and tracked as a `CallerDeposit`, which is only used to refund the caller if the resulting cross-contract call *fails*. [2](#0-1) [3](#0-2) 
There is no logic anywhere in `inner_rlp_execute`, `action_to_promise`, or the callbacks that checks whether `attached_deposit` exceeds the deposit actually required by the decoded action (the `yocto_near` field of the emulated Ethereum transaction) and refunds the difference back to the caller on success.

### Finding Description
Unlike the AvailBridge contract, which requires `msg.value >= getFee(length)` but keeps the entire `msg.value` (including any excess) as `fees`, the Wallet Contract requires an attached NEAR deposit for a call, decodes an action from RLP-encoded transaction data whose deposit component (`yocto_near`) may be smaller than the amount attached, and on success simply forwards the decoded action's own deposit amount to the target while retaining any surplus deposit in the wallet contract's account balance rather than returning it to the external predecessor. The `CallerDeposit` mechanism exists specifically to protect external callers from losing their tokens, but it is wired only to the failure path of `rlp_execute_callback`: [4](#0-3) 
On the success path (`PromiseResult::Successful`), the deposit is never compared against what was actually consumed, and no refund receipt/promise is generated for any excess: [5](#0-4) 
This mirrors the AvailBridge pattern precisely: a payable entrypoint accepts a deposit only bounded below by what is required, and any excess is silently absorbed rather than returned.

### Impact Explanation
Any external, unprivileged caller (a relayer or arbitrary NEAR account calling `rlp_execute` with a deposit) who over-attaches NEAR relative to the actual deposit required by the decoded action permanently loses the excess to the Wallet Contract's own account balance once the action succeeds. This is unauthorized value loss for the caller — the same class of impact ("Users will lose the excess... sent in the transaction") described in the original report. This is a value-movement/fund-loss bug reachable purely from a single unprivileged RPC call/transaction, satisfying the required impact categories (unauthorized value movement / permanently frozen or misdirected funds).

### Likelihood Explanation
The bug is triggered on ordinary, expected usage: any external account calling `rlp_execute` (documented and covered by `test_caller_refunds` for the failure path only) that attaches a deposit slightly larger than the action's own `yocto_near` amount — e.g. due to relayer buffer estimation, rounding, or fee-padding practices similar to those seen for `EOABaseTokenTransfer`/`ERC20Transfer` fees. No special privileges are required; only a standard signed transaction to a deployed Wallet Contract account is needed.

### Recommendation
In `rlp_execute_callback` (and any other path that resolves the caller's promise, e.g. `address_check_callback`/`nep_141_storage_balance_callback` failure/success handling), compute the excess between `CallerDeposit.yocto_near` and the amount actually consumed by the decoded action, and issue a transfer refunding that excess back to `CallerDeposit.account_id` regardless of whether the inner promise succeeds or fails — not just on failure.

### Proof of Concept
1. Deploy/eth-implicit Wallet Contract for address `A`.
2. An external account `Caller` (not `A`) calls `rlp_execute(target, tx_bytes_b64)` with an attached deposit `D` (e.g., 3 NEAR), where the RLP-decoded action encodes a `FunctionCall`/`Transfer` with `yocto_near` value `V < D` (e.g. 0 or a small fraction of a NEAR, since `yocto_near` is only a `Uint(32)` field, capped far below `D`). [6](#0-5) 
3. If the target call succeeds, `rlp_execute_callback` returns `success: true` without ever comparing `D` and `V` or refunding `D - V` to `Caller`. [5](#0-4) 
4. `Caller`'s balance decreases by `D` even though only `V` was needed/consumed by the action, and the difference remains stuck in the Wallet Contract's balance — directly analogous to AvailBridge retaining excess `msg.value` as `fees`.

Note: the `test_caller_refunds` test in the repository only asserts the refund behavior on the failure path [7](#0-6) , and does not assert any excess-refund behavior on success, which is consistent with this gap not being covered/handled.

    #[private]
    pub fn rlp_execute_callback(
        &mut self,
        caller_deposit: Option<CallerDeposit>,
    ) -> ExecuteResponse {
        self.has_in_flight_tx = false;
        let n = env::promise_results_count();

        if n == 0 {
            // `rlp_execute_callback` is called directly in the case of an emulated self-transfer.
            return ExecuteResponse { success: true, success_value: None, error: None };
        } else if n > 1 {
            return ExecuteResponse {
                success: false,
                success_value: None,
                error: Some(format!(
                    "Invariant violation: this callback comes after a single promise. n={n}"
                )),
            };
        }

        match env::promise_result(0) {
            PromiseResult::Failed => {
                // The cross-contract call failed, refund the caller if needed
                if let Some(CallerDeposit { account_id, yocto_near }) = caller_deposit {
                    let refund_promise = env::promise_batch_create(&account_id);
                    env::promise_batch_action_transfer(
                        refund_promise,
                        NearToken::from_yoctonear(yocto_near.into()),
                    );
                }

                ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Failed Near promise".into()),
                }
            }
            PromiseResult::Successful(value) => {
                ExecuteResponse { success: true, success_value: Some(value), error: None }
            }
        }
    }

/// A data type to keep track of the deposit given by an external caller.
/// This allows us to refund the caller's deposit if the cross-contract call fails.
#[derive(Debug, PartialEq, Eq, Clone, serde::Serialize, serde::Deserialize)]
pub struct CallerDeposit {
    pub account_id: AccountId,
    pub yocto_near: NonZeroU128,
}

impl CallerDeposit {
    pub fn new(context: &ExecutionContext) -> Option<Self> {
        // Only track for external (non-self) callers
        if context.current_account_id == context.predecessor_account_id {
            return None;
        }

        NonZeroU128::new(context.attached_deposit.as_yoctonear()).map(|yocto_near| Self {
            account_id: context.predecessor_account_id.clone(),
            yocto_near,
        })
    }

// An external caller gets its deposit back if the cross-contract call fails.
#[tokio::test]
async fn test_caller_refunds() -> anyhow::Result<()> {
    let TestContext { worker, wallet_contract, wallet_sk, address_registrar, .. } =
        TestContext::new().await?;

    let caller = worker.root_account()?;
    let deposit_amount = NearToken::from_near(3);
    let create_tx = |receiver_id: &AccountId, nonce: u64| {
        let method = "register";
        let args = br#"{"account_id": "birchmd.near"}"#;
        let action = Action::FunctionCall {
            receiver_id: receiver_id.to_string(),
            method_name: method.into(),
            args: args.to_vec(),
            gas: Gas::from_tgas(10).as_gas(),
            yocto_near: 0,
        };
        utils::create_signed_transaction(
            nonce,
            receiver_id,
            Wei::new_u128(deposit_amount.as_yoctonear() / (MAX_YOCTO_NEAR as u128)),
            action,
            &wallet_sk,
        )
    };

    // External caller gets a refund when the cross-contract call fails
    let pre_tx_account_balance = caller.view_account().await?.balance;
    let receiver_id: AccountId = "fake.near".parse()?;
    let result = wallet_contract
        .rlp_execute_from(
            &caller,
            receiver_id.as_str(),
            &create_tx(&receiver_id, 0),
            deposit_amount,
        )
        .await?;
    assert!(!result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            < deposit_amount.as_yoctonear()
    );

    // External caller does not get a refund when their tokens are spent
    let pre_tx_account_balance = post_tx_account_balance;
    let receiver_id = address_registrar.id();
    let result = wallet_contract
        .rlp_execute_from(&caller, receiver_id.as_str(), &create_tx(receiver_id, 1), deposit_amount)
        .await?;
    assert!(result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            >= deposit_amount.as_yoctonear()
    );

    Ok(())
}
