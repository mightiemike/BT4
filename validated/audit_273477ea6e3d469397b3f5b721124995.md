### Title
Native CREATE2 + SUICIDE combination in the TVM enables Metamorphic Contract redeployment at a deterministic address - (File: `actuator/src/main/java/org/tron/core/vm/program/Program.java`)

### Summary
The Aquifer report describes a metamorphic-contract attack pattern: a deterministic-address deployment mechanism (`cloneDeterministic`/`CREATE2`) combined with a self-destructible implementation lets an attacker redeploy different bytecode to the same address, breaking the immutability assumption users rely on. java-tron's TVM implements the exact same underlying primitive natively via the `CREATE2` opcode and the `SUICIDE` opcode, and — unless the governance-gated `ALLOW_TVM_SELFDESTRUCT_RESTRICTION` hard fork flag has been activated on a given chain — the old, unrestricted self-destruct semantics apply, making the same class of attack reachable from any user-broadcast transaction/contract call, with no privileged actor required.

### Finding Description
`CREATE2` addresses in java-tron are computed deterministically from `(sender, salt, hash(initCode))`: [1](#0-0) 

This is invoked from the `CREATE2` opcode handler: [2](#0-1) 

When creating the contract, `createContractImpl` only treats the target address as "already occupied" if an account exists there **and** (under Constantinople rules) `isContractExist` returns true; if the prior contract at that address was previously deleted via self-destruct, this check passes and a brand-new contract (with potentially different logic) can be created at the exact same address: [3](#0-2) 

The `SUICIDE` opcode (`Op.SUICIDE = 0xff`) is wired to `OperationActions::suicideAction`, which calls `Program.suicide()`: [4](#0-3) 

The default/legacy `suicide()` implementation unconditionally deletes the account regardless of whether the contract predates the current transaction: [5](#0-4) 

A mitigation modeled on EIP-6780 exists (`suicide2`, used only when the `ALLOW_TVM_SELFDESTRUCT_RESTRICTION` feature is active), which restricts full account deletion to contracts created within the *same* transaction (`isNewContract`): [6](#0-5) 

This restricted opcode variant is only installed into the jump table when the flag is enabled: [7](#0-6) [8](#0-7) 

And that flag defaults to `0` (disabled) unless a chain governance proposal has activated it: [9](#0-8) 

Putting this together: on any java-tron-based chain where `ALLOW_TVM_SELFDESTRUCT_RESTRICTION` has not been activated (this flag must be turned on explicitly via a super-representative governance proposal — it is not on by default), a user can:
1. Deploy contract `Impl1` via `CREATE2` at address `A` (deterministic salt+init-code hash).
2. Trigger `SUICIDE` inside `Impl1`, which fully deletes the account at `A` (`Program.suicide`, line 515: `getResult().addDeleteAccount(...)`).
3. Deploy again via `CREATE2` with the same `sender/salt/init-code hash` at address `A`, but where the *constructor* logic of that identical init bytecode reads external mutable state (storage of another contract, timestamp, caller, etc.) to branch and return a different runtime bytecode this time — landing entirely different logic at the same address `A`.

This is the same "metamorphic contract" bug class as the referenced Aquifer report, except it is baked into the TVM's core opcodes rather than requiring a bespoke factory contract, and it is reachable by any account issuing ordinary `TriggerSmartContract` transactions — no privileged role needed.

### Impact Explanation
Any downstream contract or off-chain integrator (bridges, wallets, DEX routers, oracles) that trusts a `CREATE2`-derived address as immutable (a common pattern for counterfactual/precomputed wallet or vault addresses) can be silently redirected to attacker-controlled logic once the original contract self-destructs and is metamorphically redeployed. This can lead to fund theft, logic bypass, or consensus-relevant state corruption for any dApp built on this assumption — matching the "unauthorized account operation / asset or accounting corruption" impact class.

### Likelihood Explanation
Likelihood depends entirely on whether `ALLOW_TVM_SELFDESTRUCT_RESTRICTION` is active on the target network. On any deployment of this codebase where that proposal has not been passed (the flag is `0` by default per `DynamicPropertiesStore.getAllowTvmSelfdestructRestriction`), the attack is fully exploitable with ordinary transactions and requires only that the attacker controls the constructor logic of the initially deployed contract (a routine assumption for the attacker's own deployed contract). Where the restriction is active, the attack is substantially mitigated (though not necessarily eliminated for contracts already flagged "new" within one transaction chain), which lowers likelihood on hardened chains but leaves any legacy/non-upgraded java-tron network exposed.

### Recommendation
- Ensure `ALLOW_TVM_SELFDESTRUCT_RESTRICTION` is activated on all production/mainnet-derived chains using this codebase so that `suicide2` (EIP-6780 semantics) is the effective path, preventing full account deletion for contracts not created within the same transaction.
- Consider making the EIP-6780-style restriction unconditional (not proposal-gated) for new deployments/private chains, since leaving it opt-in perpetuates exposure until governance explicitly reacts.
- Document, in TVM/Solidity developer guidance, that `CREATE2`-based deterministic deployment must never be paired with implementations capable of `SUICIDE`, matching the upstream Basin/Aquifer recommendation.

### Proof of Concept
The existing test suite already demonstrates the primitives independently (deterministic `CREATE2` addressing plus `SUICIDE` at that address): [10](#0-9)

    byte[] owner = getContextAddress();
    byte[] obtainer = obtainerAddress.toTronAddress();

    if (VMConfig.allowTvmVote()) {
      withdrawRewardAndCancelVote(owner, getContractState());
    }

    long balance = getContractState().getBalance(owner);

    if (logger.isDebugEnabled()) {
      logger.debug("Transfer to: [{}] heritage: [{}]",
          Hex.toHexString(obtainer),
          balance);
    }

    increaseNonce();

    InternalTransaction internalTx = addInternalTx(null, owner, obtainer, balance, null,
        "suicide", nonce, getContractState().getAccount(owner).getAssetMapV2());

    int ADDRESS_SIZE = VMUtils.getAddressSize();
    if (FastByteComparisons.compareTo(owner, 0, ADDRESS_SIZE, obtainer, 0, ADDRESS_SIZE) == 0) {
      // if owner == obtainer just zeroing account according to Yellow Paper
      getContractState().addBalance(owner, -balance);
      byte[] blackHoleAddress = getContractState().getBlackHoleAddress();
      if (VMConfig.allowTvmTransferTrc10()) {
        getContractState().addBalance(blackHoleAddress, balance);
        MUtil.transferAllToken(getContractState(), owner, blackHoleAddress);
      }
    } else {
      createAccountIfNotExist(getContractState(), obtainer);
      try {
        MUtil.transfer(getContractState(), owner, obtainer, balance);
        if (VMConfig.allowTvmTransferTrc10()) {
          MUtil.transferAllToken(getContractState(), owner, obtainer);
        }
      } catch (ContractValidateException e) {
        if (VMConfig.allowTvmConstantinople()) {
          throw new TransferException(
              "transfer all token or transfer all trx failed in suicide: %s", e.getMessage());
        }
        throw new BytecodeExecutionException("transfer failure");
      }
    }
    if (VMConfig.allowTvmFreeze()) {
      byte[] blackHoleAddress = getContractState().getBlackHoleAddress();
      if (FastByteComparisons.isEqual(owner, obtainer)) {
        transferDelegatedResourceToInheritor(owner, blackHoleAddress, getContractState());
      } else {
        transferDelegatedResourceToInheritor(owner, obtainer, getContractState());
      }
    }
    if (VMConfig.allowTvmFreezeV2()) {
      byte[] Inheritor =
          FastByteComparisons.isEqual(owner, obtainer)
              ? getContractState().getBlackHoleAddress()
              : obtainer;
      long expireUnfrozenBalance = transferFrozenV2BalanceToInheritor(owner, Inheritor, getContractState());
      if (expireUnfrozenBalance > 0 && internalTx != null) {
        internalTx.setValue(internalTx.getValue() + expireUnfrozenBalance);
      }
    }
    getResult().addDeleteAccount(this.getContractAddress());
  }

  public long getAllowTvmSelfdestructRestriction() {
    return Optional.ofNullable(getUnchecked(ALLOW_TVM_SELFDESTRUCT_RESTRICTION))
        .map(BytesCapsule::getData)
        .map(ByteArray::toLong)
        .orElse(0L);
  }

  public void saveAllowTvmSelfdestructRestriction(long value) {
    this.put(ALLOW_TVM_SELFDESTRUCT_RESTRICTION, new BytesCapsule(ByteArray.fromLong(value)));
  }

  public boolean allowTvmSelfdestructRestriction() {
    return getAllowTvmSelfdestructRestriction() == 1L;
  }
