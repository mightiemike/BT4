## Finding

### Title
Superfluous gasless-message permission for `MsgMigrateUEA` bypasses fee/signature economics, enabling free tx-spam DoS - (File: `app/txpolicy/gasless.go`)

### Summary
`app/txpolicy/gasless.go` still whitelists `uexecutortypes.MsgMigrateUEA` as a gasless message type [1](#0-0) , even though `x/uexecutor/README.md` explicitly documents that the dedicated migration message path "has been removed" and that migration is now folded into `MsgExecutePayload` [2](#0-1) . Contrary to that documentation, `MsgMigrateUEA` is not actually dead: it remains a live, reachable gRPC message with a full `ValidateBasic`/`GetSigners` implementation [3](#0-2)  and a corresponding keeper handler (`x/uexecutor/keeper/msg_migrate_uea.go`) still wired into `MsgServer`. This is the direct analog of the external report's "declared-but-unnecessary permission expands attack surface" pattern: a message type is granted the privileged gasless capability (skip fee deduction, skip min-gas-price check, and — for brand-new signer accounts — skip full ante-chain signature/sequence checks via `AccountInitDecorator`) without the corresponding access restriction that the other UV-only gasless messages enjoy.

### Finding Description
The gasless whitelist mixes two fundamentally different trust classes into one flat list with identical fee-bypass privileges [4](#0-3) :
- `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration` are restricted to bonded, non-tombstoned Universal Validators, checked inside the message handler itself [5](#0-4) .
- `MsgExecutePayload` is intentionally open to "any" signer, but its cost/authorization model routes gas deduction to the target UEA (`DeductGasFeesFromReceipt`) and requires a cryptographic signature check inside the UEA contract before any meaningful state change can occur [6](#0-5) .
- `MsgMigrateUEA`, however, was intended to be retired per the module's own documentation, yet it is still declared in the gasless whitelist and still has a live proto RPC + keeper handler. Because `IsGaslessTx` treats it identically to the other allowed types, `AccountInitDecorator`, `MinGasPriceDecorator`, and `DeductFeeDecorator` all skip their normal economic/anti-spam gates for it [7](#0-6) [8](#0-7) .

Because `MsgMigrateUEA.GetSigners()` returns whatever bech32 address is in `Signer` with no relationship enforced to a bonded validator set or to the fee payer [9](#0-8) , and because `AccountInitDecorator` will happily create a brand-new zero-balance account mid-pipeline for any never-before-seen signer on a gasless tx [10](#0-9) , an unprivileged attacker can generate unlimited fresh keypairs and submit unlimited `MsgMigrateUEA` transactions that cost nothing (no fee, no minimum gas price) and consume no attacker-held balance, all the way through ante-chain processing and into the keeper handler before any UEA-level signature check can reject them.

This exactly mirrors the external bug class: a capability ("gasless" execution privilege) was granted to a message type that, per the codebase's own stated intent, should not need it — expanding the unprivileged attacker's reachable surface beyond the principle-of-least-privilege boundary the other gasless messages respect (bonded-validator gating or UEA-bound fee/signature gating).

### Impact Explanation
This falls under the allowed "denial of service ... not network-level and reachable without privileged control" impact category. An unprivileged attacker can flood blocks with free `MsgMigrateUEA` transactions (zero fee, zero min-gas-price, fresh throwaway signer accounts auto-created for free), consuming block space, ante-handler CPU, and keeper-handler CPU that honest gasless UV votes and `MsgExecutePayload` deliveries compete for — degrading the availability of the very gasless lanes the mechanism exists to protect, without the attacker holding a validator bond or spending any `upc`.

### Likelihood Explanation
High reachability: no privileged role, no funds, and no valid external-chain event are required — only the ability to construct and broadcast a Cosmos SDK transaction containing `MsgMigrateUEA` with a syntactically valid (but otherwise arbitrary) `UniversalAccountId`/`MigrationPayload`/`Signature`, which passes `ValidateBasic` as long as the fields are non-empty [11](#0-10) . The economic and authorization gates that would normally deter spam (fee payment, min gas price, bonded-validator check) are all bypassed specifically because this message type sits in the gasless whitelist.

### Recommendation
Remove `MsgMigrateUEA` from `GaslessMsgTypes` in `app/txpolicy/gasless.go`, consistent with the module documentation stating the dedicated migration path has been retired in favor of `MsgExecutePayload`. If the handler must remain live for backward compatibility, gate it the same way vote messages are gated (bonded-UV-only) or the same way `MsgExecutePayload` is gated (cryptographic pre-check with UEA-funded gas), rather than granting it the same zero-cost gasless privilege as consensus-critical voting messages.

### Proof of Concept
1. Generate an arbitrary new keypair/account (no funding required).
2. Construct `MsgMigrateUEA{Signer: <new addr>, UniversalAccountId: <any well-formed id>, MigrationPayload: <any well-formed payload>, Signature: <arbitrary non-empty bytes>}`.
3. Broadcast it as a standalone Cosmos transaction with zero fee and no min-gas-price.
4. `IsGaslessTx` returns true (message type is in `GaslessMsgTypes`) → `MinGasPriceDecorator` and `DeductFeeDecorator` are skipped → `AccountInitDecorator` auto-creates the new account and short-circuits normal signature/sequence verification for it → the transaction is processed at no cost to the attacker.
5. Repeat with unlimited new keypairs to flood the gasless transaction lane at zero cost.

Note: I was not able to fully verify, within the available tool budget, the internal authorization/signature-check logic of the `MigrateUEA` keeper handler itself (`x/uexecutor/keeper/msg_migrate_uea.go`) — specifically whether it performs any early, cheap rejection of unauthenticated payloads before doing meaningful work. That handler's exact contents should be reviewed to determine whether the impact is limited to bare spam/DoS or whether it can also affect UEA state, given the module's chain-config/gas-fee-driven code paths mentioned elsewhere in the same file.

```markdown
### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.

#### Where authorization actually lives

The cryptographic binding is enforced inside the UEA contract's `executeUniversalTx` (see [`UEA_EVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_EVM.sol#L145) and [`UEA_SVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_SVM.sol)):

1. The contract holds the owner's public key as **immutable bytes** set at UEA deployment via `initialize(_id, _factory)`. There is no code path that mutates this after init.
2. `executeUniversalTx(payload, signature)` verifies the `signature` (passed in as `MsgExecutePayload.VerificationData`) against this stored owner — ECDSA recovery for EVM-origin owners, the Ed25519 precompile (`0x00…00ca`) for SVM-origin owners.
3. The signed payload hash includes a contract-tracked `nonce` (monotonic per UEA) and optional `deadline`, providing replay and freshness protection.
4. If signature verification fails, the contract reverts. The revert propagates as `execErr` from `CallUEAExecutePayload`; the keeper returns the error from `ExecutePayload`; the entire Cosmos transaction (including any partial gas-fee deduction) rolls back atomically. **No state changes survive a failed signature check.**

#### Why this is safe under `Signer ≠ Owner`

An attacker submitting `MsgExecutePayload` with their own `Signer` and a victim's `UniversalAccountId` produces no exploitable outcome:

- The factory resolves the victim's UEA address from the embedded `UniversalAccountId` — correct.
- `evmFrom` (derived from `Signer`) becomes the EVM-level `msg.sender` of the call to the UEA. Since `evmFrom != UNIVERSAL_EXECUTOR_MODULE` (`0x14191Ea54B4c176fCf86f51b0FAc7CB1E71Df7d7`), the contract enforces the signature check.
- The attacker cannot forge `VerificationData` that recovers to the victim's owner key.
- The contract reverts → the keeper returns an error → the Cosmos transaction reverts in full.
- Net effect: zero state change. No EVM gas is charged to the victim UEA (the deduction is rolled back with the rest of the transaction). The submission costs the attacker nothing on chain (gasless), but also achieves nothing.
```

```go
package types

import (
	"cosmossdk.io/errors"
	sdk "github.com/cosmos/cosmos-sdk/types"
	sdkerrors "github.com/cosmos/cosmos-sdk/types/errors"
)

var (
	_ sdk.Msg = &MsgMigrateUEA{}
)

// NewMsgMigrateUEA creates new instance of MsgMigrateUEA
func NewMsgMigrateUEA(
	sender sdk.Address,
	universalAccountId *UniversalAccountId,
	migrationPayload *MigrationPayload,
	signature string,
) *MsgMigrateUEA {
	return &MsgMigrateUEA{
		Signer:             sender.String(),
		UniversalAccountId: universalAccountId,
		MigrationPayload:   migrationPayload,
		Signature:          signature,
	}
}

// Route returns the name of the module
func (msg MsgMigrateUEA) Route() string { return ModuleName }

// Type returns the action
func (msg MsgMigrateUEA) Type() string { return "migrate_uea" }

// GetSignBytes implements the LegacyMsg interface.
func (msg MsgMigrateUEA) GetSignBytes() []byte {
	return sdk.MustSortJSON(AminoCdc.MustMarshalJSON(&msg))
}

// GetSigners returns the expected signers for a MsgExecutePayload message.
func (msg *MsgMigrateUEA) GetSigners() []sdk.AccAddress {
	addr, _ := sdk.AccAddressFromBech32(msg.Signer)
	return []sdk.AccAddress{addr}
}

// ValidateBasic does a sanity check on the provided data.
func (msg *MsgMigrateUEA) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate migration payload
	if msg.MigrationPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "migration payload cannot be nil")
	}

	// Validate Signature
	if len(msg.Signature) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "signature cannot be empty")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate migration payload structure
	if err := msg.MigrationPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid migration payload")
	}

	return nil
}
```

```go
func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}
```
