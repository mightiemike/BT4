### Title
Nakamoto reward-set signer-emptiness guard checks the wrong field, allowing a zero-signature block to pass signature verification - ([File: stackslib/src/chainstate/nakamoto/coordinator/mod.rs])

### Summary
The reward set consumed by `NakamotoBlockHeader::verify_signer_signatures` is validated by `read_reward_set_at_calculated_block`, which checks that `rewarded_addresses` is non-empty and that `signers()` is not `None` [1](#0-0) . It never checks whether the *signer list itself* is an empty `Vec` (`Some(vec![])`), which is a distinct, reachable state from `StacksChainState::make_signer_set`/`make_reward_set`. Because `rewarded_addresses` is aggregated by PoX reward address while `signers` is aggregated by signing key, a staker can make these two aggregations diverge, producing a reward set that is non-empty by the address-based check but has zero total signer weight. This is the same bug class as the Superfluid report: a security-critical zero-check is performed on a derived aggregate (`getTotalUnits()==0` / `rewarded_addresses.is_empty()`) that does not track the actual invariant needed (positive tax / positive signer weight).

### Finding Description
`StacksChainState::make_reward_set` builds two independent structures from the same list of `RawRewardSetEntry` using the same per-slot `threshold`:
- `rewarded_addresses`: entries are summed **per reward address**, and slots are only granted if `stacked_amt / threshold >= 1` [2](#0-1) .
- `signers`: entries are summed **per signing key**, via `make_signer_set`, which floors `stacked_amt / threshold` and *filters out any signer whose resulting weight is 0*, silently returning `Some(vec![])` (not `None`) if every key floors to zero [3](#0-2) .

Because the two aggregation keys (reward address vs. signing key) are independent, a staker can split their contribution to a single reward address across many distinct signing keys, each individually below `threshold`, while the address total is above `threshold`. This yields `rewarded_addresses` non-empty (so it is not rejected) and `signers = Some(vec![])`.

The consumer that later re-reads this stored reward set for Nakamoto block signature verification, `read_reward_set_at_calculated_block`, only rejects when `rewarded_addresses.is_empty()` or `signers().is_none()` [4](#0-3) ; it does not check `signers().map_or(_, |s| s.is_empty())`, unlike the sibling `OnChainRewardSetProvider::get_reward_set` check which does guard on emptiness [5](#0-4) .

Downstream, `NakamotoBlockHeader::verify_signer_signatures` treats `reward_set.signers() == Some(&[])` as valid (it only early-errors on `None`), computes `total_weight = 0` via `total_signing_weight()` (sum over empty vec) [6](#0-5) , and then computes `threshold = compute_voting_weight_threshold(0) = 0` [7](#0-6) . With zero (or any) signer signatures, `total_weight_signed < threshold` is `0 < 0`, i.e. **false**, so the function returns `Ok(0)` and the block is treated as validly signed [8](#0-7) .

### Impact Explanation
This breaks the fundamental block-acceptance equality that a Nakamoto block must be signed by a supermajority of signer weight. A single unprivileged stacker who can shape their own PoX-4 signing-key registrations for one reward cycle can force the stored reward set for that cycle to have zero effective signer weight while still passing the reward-address non-emptiness guard. Miners could then produce Nakamoto blocks for that tenure with zero or arbitrary signer signatures, and every node applying `verify_signer_signatures` would accept them as validly signed — an invalid block accepted network-wide, a Critical-impact, minority/unprivileged-triggerable divergence per the scope rules.

### Likelihood Explanation
Triggering requires only ordinary PoX-4 stacking transactions (no admin/majority/other-party keys): the attacker distributes one reward address's total stake across many `stack-stx`/`stack-extend` calls, each using a distinct signing key with an amount below the computed per-slot `threshold`, while keeping the address total above `threshold`. This is fully within a single unprivileged staker's control and does not require any majority of stake or of the signer set.

### Recommendation
Make `read_reward_set_at_calculated_block` (and any other reward-set consumer) check `reward_set.signers().map_or(true, |s| s.is_empty())` — mirroring the guard already present in `OnChainRewardSetProvider::get_reward_set` — rather than only `None`. Additionally, `verify_signer_signatures` should treat an empty (but `Some`) signer list, or a `total_signing_weight() == 0`, as an unconditional rejection rather than a trivially-satisfied threshold of `0`.

### Proof of Concept
1. During a PoX-4 reward cycle, have staker `A` submit `stack-stx`/`stack-aggregation-commit` operations that all register the same PoX reward address `R`, but each with a *different* signing key `k_1..k_n`, and each individual `amount_stacked < threshold` (while `sum(amount_stacked) >= threshold`).
2. `StacksChainState::make_reward_set` computes: `rewarded_addresses` contains `R` at least once (address-level sum ≥ threshold); `make_signer_set` filters every `k_i` out because each key's stacked amount alone is `< threshold`, yielding `signers = Some(vec![])`.
3. `read_reward_set_at_calculated_block` accepts this reward set because `rewarded_addresses` is non-empty and `signers().is_none()` is false.
4. Any Nakamoto block header for this tenure is passed to `verify_signer_signatures`; `total_weight = 0`, `threshold = compute_voting_weight_threshold(0) = 0`, so any `signer_signature` vector (including an empty one) satisfies `total_weight_signed >= threshold`, and the block is accepted as validly signed by every honest node running the same check.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
