## Analog identified

The bug class in the report — a permission/security check that silently becomes **vacuously true** when the underlying collection is empty (`CheckPermission` iterating zero `cf.Servers` in nezha) — has a structural analog in this repo's Nakamoto signer-weight threshold check, where an *empty (but non-`None`) signer set* causes the 70%-weight signature requirement to degrade to "require ≥0 out of 0", i.e. no signature at all.

### Title
Empty (non-`None`) Nakamoto signer set makes `verify_signer_signatures` accept an unsigned block - (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` only rejects a reward set when `reward_set.signers()` is `None`; it never checks whether the returned signer `Vec` is *empty*. If a reward cycle's computed PoX-4 signer set ends up as `Some(vec![])` — which the `make_signer_set` builder can legitimately produce — the total signing weight is `0`, the 70% threshold computed from it is also `0`, and a block header with **zero** `signer_signature` entries passes the check trivially (`0 < 0` is `false`).

### Finding Description
`StacksChainState::make_signer_set` (`stackslib/src/chainstate/stacks/boot/mod.rs:1020-1072`) returns `None` only when the input entries list is empty [1](#0-0) . If entries are non-empty but every stacker's `stacked_amt / threshold` floors to `0`, the weight-`0` entries are filtered out and the function still returns `Some(signer_set)` with an **empty** `Vec` [2](#0-1) .

The PoX-4 Nakamoto reward-set builder, `pox_4_compute_and_update_signers`, calls `make_reward_set` (which wraps `make_signer_set`) and stores the result **without ever checking whether the resulting signer vector is empty**: [3](#0-2) . This is in stark contrast to the PoX-5 path, `pox_5_compute_and_update_signers`, which explicitly guards against this case: `if signer_set.is_empty() { return Err(ChainstateError::PoxNoRewardCycle) }` [4](#0-3) .

When this reward set is later loaded for actual block validation via `read_reward_set_at_calculated_block`, the guard only checks `reward_set.signers().is_none()` — an empty-but-`Some` vector sails through: [5](#0-4) . (Notably, the separate `OnChainRewardSetProvider::get_reward_set` epoch-2 compatibility path *does* correctly check `.is_empty()` at [6](#0-5) , showing the Nakamoto-specific reader is the outlier missing this check.)

`RewardSet::total_signing_weight()` treats `Some(empty vec)` as a valid, zero-weight reward set rather than an error (only `None` errors out): [7](#0-6) .

Finally, in `verify_signer_signatures`, the equality that is supposed to be enforced is *"signed weight ≥ 70% of total weight"*. With `total_weight == 0`, `compute_voting_weight_threshold(0) == 0`, and if the block carries **no** signatures at all, the `for signature in self.signer_signature.iter()` loop never executes, `total_weight_signed` stays `0`, and `0 < 0` is false, so the function returns `Ok(0)` — accepting the block as validly signed with zero actual signer approval: [8](#0-7) . This exact scenario is the mirror image of the report's `CheckPermission` vacuous-true bug: an empty collection makes an authorization/threshold check pass by default instead of failing closed.

This verification function is the sole gate used both when storing/accepting a Nakamoto block: [9](#0-8) , and when relaying/accepting a block received over the network: [10](#0-9) .

### Impact Explanation
This breaks the core Nakamoto consensus invariant that a block requires signatures from stackers holding ≥70% of the reward cycle's signing weight. For any reward cycle whose signer set degenerates to `Some(vec![])` (achievable by ordinary, unprivileged PoX-4 stacking behavior — e.g. many small stackers whose individual `stacked_amt` each floors below the per-slot `threshold`, none of which requires a majority or coordinated attacker), **every node in the network** will accept a completely unsigned block for that cycle as valid, since all nodes run the identical (buggy) check. This is an "invalid block accepted network-wide" condition (Critical bucket) — the miner for that tenure can produce and have blocks canonicalized without any signer participation, undermining the entire signer-security model for the affected reward cycle.

### Likelihood Explanation
Reachability requires only that a PoX-4 reward cycle's stacked-amount distribution be diluted enough that every individual stacker's floor-divided weight is `0` (e.g., an unusually large number of stackers each just under the per-slot `threshold`). No admin/majority/Sybil control is needed — it is a pure PoX-4 stacking-distribution corner case that the code fails to reject, unlike the parallel PoX-5 path which explicitly guards against it.

### Recommendation
Add the same guard used in `pox_5_compute_and_update_signers` to the PoX-4 path and to `read_reward_set_at_calculated_block`: explicitly reject (return `Error::PoXAnchorBlockRequired` / equivalent) any Nakamoto-era reward set whose `signers()` is `Some(vec) if vec.is_empty()`, not only `None`. Additionally, harden `verify_signer_signatures` to fail closed when `total_weight == 0` (e.g., treat zero total signing weight as `ChainstateError::NoRegisteredSigners`), so it can never validate a block with zero required/zero provided signatures.

### Proof of Concept
1. Construct a PoX-4 reward cycle in which many stackers each individually stack an amount `a` such that `a / threshold == 0` for every stacker (`threshold = ceil(participation/reward_slots)` can be engineered this way with enough small, distinct stackers below the per-slot cutoff), while `entries` is non-empty.
2. `StacksChainState::make_signer_set` returns `Some(vec![])` (all entries filtered for weight `0`), so `RewardSet::signers()` is `Some(&[])`, not `None`.
3. `pox_4_compute_and_update_signers` stores this reward set into `.signers` state without any empty-check.
4. When the reward cycle activates, `read_reward_set_at_calculated_block` loads this reward set successfully (only checks `is_none()`).
5. A miner produces a `NakamotoBlock` with `signer_signature = vec![]` (no signatures at all).
6. `verify_signer_signatures` computes `total_weight = 0`, `threshold = 0`, `total_weight_signed = 0`; `0 < 0` is false, so the function returns `Ok(0)`, and the block is accepted by every node as validly signed.

    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);
    }
