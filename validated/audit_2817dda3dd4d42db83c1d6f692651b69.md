### Title
Unbounded recursive JSON traversal in Cairo0 hinted-class-hash computation causes stack-overflow DoS during declare-transaction execution/re-execution - (File: `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs`)

### Summary
`compute_cairo_hinted_class_hash` calls `sort_json_value`, a self-recursive function that walks every nested `serde_json::Value` (Object/Array) with no depth bound, to canonicalize the attacker-supplied `program` fields (`attributes`, `debug_info`, `hints`, `identifiers`, `reference_manager`, etc.) of a Cairo0 (`ContractClass::V0`) contract class. These fields are `serde_json::Value` with no schema, so a declarer fully controls their shape and nesting depth [1](#0-0) . This is the same bug class as JLSEC-2026-23 (unbounded recursive descent over an attacker-controlled tree causing stack exhaustion), just implemented in Rust JSON traversal instead of YAML parsing.

### Finding Description
`sort_json_value` recurses once per nesting level of the JSON value tree with no depth limit or iterative/stack-based rewrite: [2](#0-1) 

It is invoked directly inside `compute_cairo_hinted_class_hash`, which is the function used to compute the "hinted class hash" component of the Cairo0 deprecated class hash: [3](#0-2) 

`compute_cairo_hinted_class_hash` is called by `compute_deprecated_class_hash`, which computes the full class hash for a Cairo0 class from its `ContractClass`: [4](#0-3) 

That, in turn, is invoked as a VM hint while loading a `DeprecatedCompiledClass` object during Starknet OS execution of a declare transaction (`compute_cairo_hinted_class_hash(self)` inside `load_into`): [5](#0-4) 

The `ContractClass::V0` `program` struct that feeds this recursion is fully attacker-controlled JSON (`serde_json::Value`) with no depth or size validation at deserialization time: [1](#0-0) 

A DECLARE v0/v1 transaction whose `program` field (e.g. `identifiers`, `debug_info`, `reference_manager`, or `hints` values) contains a deeply nested JSON array/object (e.g. `[[[[[...]]]]]`, tens of thousands of levels deep) will drive `sort_json_value` to recurse to that depth. Since Rust does not check stack depth, this results in a native stack overflow, which aborts the process (it is not a catchable panic).

### Impact Explanation
A stack overflow crashes the whole process running the Starknet OS/blockifier at that point — either the sequencer performing block building/re-execution of the declare transaction, or a prover/node performing the same OS execution to compute/verify the block. Since `compute_deprecated_class_hash` is exercised whenever a Cairo0 class hash must be (re)derived during declare-transaction processing, an unprivileged sender can submit a single crafted DECLARE transaction that reaches this code path on every honest node that executes it, causing repeated crashes and, in the worst case, halting the chain's ability to process new blocks/transactions until the offending transaction/class is filtered out of the flow (a "network unable to confirm new transactions" condition per the validation criteria).

### Likelihood Explanation
Likelihood is Medium: the path is reachable purely from a single, unprivileged DECLARE transaction with an unauthenticated/unschema'd `program` object, requiring no special privileges (per the "Validate" rules this maps to declared-class → Starknet OS re-execution). However, I could not fully confirm from the indexed code (1) whether the RPC/gateway-facing `stateless_transaction_validator` performs a size/structural bound on Cairo0 `program` JSON before it reaches OS re-execution (I found strict validations for Sierra `contract_class` — `validate_sierra_version`, `validate_class_length`, `validate_entry_points_sorted_and_unique` — but no analogous validation specific to the legacy/Cairo0 `program.identifiers`/`debug_info` nesting depth), and (2) whether Cairo0 DECLARE (v0/v1) transactions are still accepted in the current gateway flow of this fork or are only reachable through re-execution/bootstrap paths. This uncertainty should be resolved by a Devin session with full repository access before treating this as confirmed-exploitable via the live gateway.

### Recommendation
- Add an explicit maximum-nesting-depth (and/or maximum total node count) check on `ContractClass::V0.program`'s JSON fields (`attributes`, `debug_info`, `hints`, `identifiers`, `reference_manager`, `compiler_version`) at stateless validation time (in `apollo_gateway/src/stateless_transaction_validator.rs`), rejecting Cairo0 declares whose program JSON exceeds a safe depth (e.g., mirroring `serde_json`'s own default recursion limit of 128).
- Rewrite `sort_json_value` in `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs` to use an explicit work-stack (iterative) traversal instead of native recursion, removing the stack-overflow class entirely regardless of upstream validation.
- Add a regression test that declares (or attempts to compute the hinted class hash of) a Cairo0 class with deeply nested JSON in `identifiers`/`debug_info` and asserts a graceful error instead of a crash.

### Proof of Concept
1. Construct a `starknet_api::deprecated_contract_class::ContractClass` (Cairo0) whose `program.identifiers` (or `debug_info`/`reference_manager`) is a `serde_json::Value::Array` nested to a very large depth, e.g. programmatically:
```rust
let mut v = serde_json::Value::Array(vec![]);
for _ in 0..2_000_000 {
    v = serde_json::Value::Array(vec![v]);
}
```
2. Submit this as the `program` of a DECLARE v0/v1 transaction (or directly call `compute_deprecated_class_hash(&contract_class)` / `compute_cairo_hinted_class_hash(&contract_class)` as done during OS re-execution in [5](#0-4) ).
3. Observe that `sort_json_value`'s recursive descent over the nested array exhausts the thread stack and aborts the process (SIGSEGV/stack overflow), rather than returning an error — reproducing the JLSEC-2026-23 bug class (deep-recursion parser DoS) in this codebase's declare-transaction / OS re-execution path.

fn sort_json_value(value: serde_json::Value) -> serde_json::Value {
    match value {
        serde_json::Value::Object(map) => {
            let sorted: BTreeMap<String, serde_json::Value> =
                map.into_iter().map(|(k, v)| (k, sort_json_value(v))).collect();
            serde_json::Value::Object(sorted.into_iter().collect())
        }
        serde_json::Value::Array(arr) => {
            serde_json::Value::Array(arr.into_iter().map(sort_json_value).collect())
        }
        other => other,
    }
}
