### Title
Missing declared-class validation in Starknet OS `execute_replace_class` causes state divergence from blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The external report describes an attacker seizing `ProxyAdmin`-style control of a contract by replacing its implementation without proper authorization checks. The reachable analog in this sequencer codebase is the `replace_class` syscall, which is the native Starknet mechanism a deployed contract uses to swap its own class hash (comparable to a proxy's `upgrade_to`). The Rust `blockifier` execution path enforces that the target class hash must already be a *declared* class before allowing the swap, but the Starknet OS's Cairo re-implementation of the same syscall is missing that check, as flagged by an explicit unresolved `TODO` in the code.

### Finding Description
In `blockifier`, the `replace_class` syscall handler explicitly reads/validates the target class before mutating state: [1](#0-0) 

The Cairo-1 syscall path in `blockifier` funnels to the same `base.replace_class` check via `syscall_handler.base.replace_class(request.class_hash)?`: [2](#0-1) 

This is verified by tests that assert an "is not declared" error when a contract attempts to replace its class with an undeclared class hash: [3](#0-2) [4](#0-3) 

However, the Starknet OS's own Cairo implementation of the identical syscall (`execute_replace_class`, used during OS re-execution to produce the state diff that is committed/proven) contains an explicit, unresolved `TODO` acknowledging the missing check, and unconditionally writes the caller-supplied `class_hash` into `contract_state_changes` without verifying it corresponds to a declared class: [5](#0-4) 

The equivalent deprecated (Cairo0) OS syscall implementation has the same gap — no declared-class check before the `dict_update`: [6](#0-5) 

This is a genuine semantic divergence between the two execution engines that are meant to compute identical state transitions for the same transaction: `blockifier` (used by the sequencer to build blocks) rejects `replace_class` calls targeting undeclared class hashes, while the Starknet OS (used to re-execute the block and produce the canonical, proven state diff/commitment) does not.

### Impact Explanation
Any unprivileged contract deployer/caller can invoke `replace_class` (e.g. via the test contract's `test_replace_class`/`execute_replace_class` entry points, or any custom contract calling the syscall directly) with an arbitrary, undeclared `class_hash`. Because the OS path lacks the validation that `blockifier` enforces, this can lead to:
- The OS re-execution computing a different resulting `class_hash` for a contract (and therefore a different committed state root / Patricia tree leaf) than what the sequencer's `blockifier`-based execution would produce for the same logical transaction — an honest-node/prover divergence in the committed state.
- A contract's class hash being set to a value that has no corresponding declared/compiled class, permanently corrupting the contract (subsequent calls fail) with no path for blockifier to have blocked it, since the two engines disagree on whether the mutation is even valid.

This maps to the report's core bug class (unauthorized/unvalidated class/implementation replacement leading to loss of contract integrity) at the sequencer level, manifesting as a wrong committed root / state divergence rather than fund theft directly, but with equivalent "permanent compromise of contract state" severity.

### Likelihood Explanation
Triggering the divergent code path requires only a standard, unprivileged transaction invoking the `replace_class` syscall with a class hash that has not been declared — no elevated privileges, governance role, or compromised key are required, unlike the original Arbitrum incident. The `TODO(Yoni, 1/1/2026)` comment confirms this is a known, currently-unaddressed gap in the OS implementation.

### Recommendation
Add an explicit "class is declared" check in `execute_replace_class` in `syscall_impls.cairo` (and the deprecated Cairo0 counterpart in `deprecated_execute_syscalls.cairo`) mirroring the `blockifier` behavior (`state.get_compiled_class(request.class_hash)?` before writing the new `StateEntry`), so both execution engines reject the same invalid `replace_class` calls and always compute identical state diffs.

### Proof of Concept
1. Deploy a contract exposing an entry point that invokes the `replace_class` syscall with a caller-supplied `class_hash` (e.g. the existing `test_replace_class`/`execute_replace_class` test entry points referenced in `deprecated_syscalls_test.rs` and `syscall_tests/replace_class.rs`).
2. Submit an ordinary invoke transaction calling that entry point with an arbitrary, never-declared `class_hash` value.
3. Under `blockifier` (sequencer execution), the call fails with `"... is not declared"`, per `hint_processor.rs:795-807` and the corresponding tests.
4. Under the Starknet OS re-execution of the same call (`syscall_impls.cairo:881-920`), no declared-class check exists — the `dict_update` unconditionally records the new (undeclared) `class_hash` into `contract_state_changes`, producing a different result/state diff than step 3.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
