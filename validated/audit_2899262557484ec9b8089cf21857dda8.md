### Title
Stale cached role in `oidc_sessions` allows demoted OIDC user to retain Admin-level GraphQL privileges until session expiry - ([File: core/sessions/oidcauth/oidc.go])

### Summary
`oidcAuthenticator.AuthorizedUserWithSession` returns the `user_role` cached in the `oidc_sessions` table at login time rather than re-validating the user's current role, and this value flows directly into `GQLSession.User.Role`, which `authenticateUserIsAdmin` trusts for authorizing admin-only GraphQL mutations. Unlike the LDAP authenticator, which actively re-syncs cached session roles against the upstream directory (`ldapauth/sync.go`), the OIDC authenticator has no equivalent mechanism — `oidcauth/reaper.go` only purges sessions by age and never revalidates or updates `user_role`.

### Finding Description
- `AuthenticateGQL` calls `authenticator.AuthorizedUserWithSession(ctx, sessionID)` and stores the returned `User` (including `Role`) into the request context via `WithGQLAuthenticatedSession`. [1](#0-0) 
- For OIDC, `AuthorizedUserWithSession` executes `SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_sessions WHERE id = $1` and returns the row's `user_role` unchanged, with no query against a live source of truth for role. [2](#0-1) 
- The `user_role` is written once, at login/token-exchange time, into `oidc_sessions` (`handleTokenExchange`, `CreateSession`) from the ID token's group claims or local admin fallback role, and is never subsequently updated. [3](#0-2) [4](#0-3) 
- `oidcauth.UpdateRole` is explicitly unsupported for the OIDC authenticator, and `oidcauth.sessionReaper.Work` only deletes stale rows by `created_at`; it does not re-derive or refresh `user_role` for still-valid sessions the way LDAP's `sync.go` (`UPDATE ldap_sessions SET user_role = CASE ... END`) does. [5](#0-4) [6](#0-5) [7](#0-6) 
- `authenticateUserIsAdmin` (and the other role-gating helpers) trust `session.User.Role` from the context as-is, with no independent re-check. [8](#0-7) 

As a result, once a session row is written with `user_role = admin`, every GraphQL request replaying that session cookie will be treated as Admin for the full `SessionTimeout` window, even if the user's privileges are revoked in the interim (either via local `users` table role update for the local-admin-fallback login path, or via IdP group/claim changes for genuine OIDC-federated users — since claims are only re-evaluated at the next full OIDC login, not per-request).

### Impact Explanation
This is a privilege-persistence issue: a user whose Admin privileges have been revoked can continue to execute Admin-only GraphQL mutations (e.g., managing API tokens, jobs, users, feeds manager config) for up to the configured `SessionTimeout` (default `15m`, but administrator-configurable to arbitrarily long values). This maps to unauthorized privileged mutation execution / authorization-bypass-adjacent impact rather than classic unauthenticated escalation, since the actor must have previously held Admin and had an active session at time of revocation.

### Likelihood Explanation
Feasibility is high given typical operational patterns: revoking a compromised or departing admin's access is a routine incident-response action, and the exposure window is bounded only by `SessionTimeout`, which operators can (and in some deployments do) set to long durations for UX convenience. The precondition (existing valid session + subsequent demotion) is realistic and does not require exploiting any additional bug — it is a direct consequence of the missing revalidation logic in `AuthorizedUserWithSession`.

### Recommendation
Have `oidcAuthenticator.AuthorizedUserWithSession` re-validate the role on every call rather than trusting the cached `oidc_sessions.user_role`:
- For the local-admin-fallback path, join/lookup the current role from the `users` table by email instead of returning the cached session role.
- For federated OIDC sessions, either shorten effective privilege lifetime by enforcing much shorter admin-session TTLs, or implement an active revalidation/sync mechanism analogous to `ldapauth/sync.go` (e.g., periodic re-check against the IdP's userinfo/introspection endpoint, or forced re-authentication before privileged mutations), and explicitly invalidate/downgrade cached `oidc_sessions` rows when an admin action changes a user's local role.
- At minimum, add a `DeleteUserSession`/session-invalidation call whenever an admin explicitly changes a user's role via any admin action, so stale sessions can't outlive an explicit revocation even for the remaining TTL window.

### Proof of Concept
Integration test (extending `core/sessions/oidcauth/oidc_test.go`):
1. Insert a user into `users` with role `admin`; call `CreateSession` (local-admin-fallback path) to populate `oidc_sessions` with `user_role = admin`, obtaining `sid`.
2. Directly update `users.role = 'view'` for that email (simulating an admin demoting the user via a supported admin flow on `localauth`/other provider, or via `UpdateRole` if wired for the deployment).
3. Call `oidcAuthProvider.AuthorizedUserWithSession(ctx, sid)` again and assert that the returned `User.Role` is `admin` (demonstrating staleness) — expected/desired behavior should instead return `view`.
4. End-to-end variant: wire `AuthenticateGQL` + `authenticateUserIsAdmin` with the OIDC authenticator, replay the same session cookie against an admin-only GraphQL mutation resolver, and assert it succeeds despite the underlying role change — this should fail (be rejected) once the fix re-validates role on each request.

// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired
func (oi *oidcAuthenticator) AuthorizedUserWithSession(ctx context.Context, sessionID string) (clsessions.User, error) {
	if len(sessionID) == 0 {
		return clsessions.User{}, errors.New("session ID cannot be empty")
	}
	var foundUser clsessions.User
	err := sqlutil.TransactDataSource(ctx, oi.ds, nil, func(tx sqlutil.DataSource) error {
		// Query the oidc_sessions table for given session ID, user role and email are saved after the id claims is provided and validated
		var foundSession struct {
			UserEmail string
			UserRole  clsessions.UserRole
			Valid     bool
		}
		if err := tx.GetContext(ctx, &foundSession,
			"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM oidc_sessions WHERE id = $1",
			sessionID, oi.config.SessionTimeout().Duration(),
		); err != nil {
			if errors.Is(err, sql.ErrNoRows) {
				return clsessions.ErrUserSessionExpired
			}
			return err
		}
		if !foundSession.Valid {
			// Sessions expired, purge
			return clsessions.ErrUserSessionExpired
		}
		foundUser = clsessions.User{
			Email: foundSession.UserEmail,
			Role:  foundSession.UserRole,
		}
		return nil
	})
	if err != nil {
		if errors.Is(err, clsessions.ErrUserSessionExpired) {
			if _, execErr := oi.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE id = $1", sessionID); execErr != nil {
				oi.lggr.Errorf("error purging stale OIDC session: %v", execErr)
			}
		}
		return clsessions.User{}, err
	}
	return foundUser, nil
}

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM oidc_sessions WHERE created_at < $1", before)
	return err
}

// Authenticates the user from the session cookie and asserts has 'admin' role
func authenticateUserIsAdmin(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	if session.User.Role != sessions.UserRoleAdmin {
		return RoleNotPermittedError{session.User.Role}
	}
	return nil
}
