### Title
Unvalidated attacker-supplied `IncrementalMerkleVoucher` bytes crash `createShieldedTransaction`/`createShieldedTransactionWithoutSpendAuthSig` RPC handler thread via `ZksnarkException` from `element()`/`root()` - ([File: chainbase/src/main/java/org/tron/common/zksnark/IncrementalMerkleVoucherContainer.java])

### Summary
The `PrivateParameters`/`PrivateParametersWithoutAsk` gRPC/HTTP requests (`CreateShieldedTransaction`, `CreateShieldedTransactionWithoutSpendAuthSig`) accept a `SpendNote.voucher` field of type `IncrementalMerkleVoucher` supplied entirely by the caller. `Wallet.createShieldedTransaction`/`createShieldedTransactionWithoutSpendAuthSig` deserializes this into an `IncrementalMerkleVoucherCapsule` and constructs an `IncrementalMerkleVoucherContainer` from it, then calls `builder.addSpend(...)` which eventually calls `voucherContainer.root()`/related tree operations — without ever invoking `IncrementalMerkleTreeContainer.wfcheck()` to validate structural invariants of the tree/filled/cursor fields.

### Finding Description
`Wallet.createShieldedTransaction` (and its no-ask variant) reads `spendNote.getVoucher()` directly from the request and builds a voucher container with no validation: [3](#0-2) 

This differs fundamentally from the `GetMerkleTreeVoucherInfo` RPC path analyzed in the question, where the voucher/tree is always constructed server-side via `createWitness()`/`updateWitnesses()` using data read from the chain (trees that were built through `append()` during `ShieldedTransferActuator.executeShielded`, which does call `wfcheck()`): [4](#0-3) 

However, `createShieldedTransaction`'s voucher comes straight from client-supplied protobuf bytes (`SpendNote.voucher`), and `IncrementalMerkleVoucherContainer` never calls `wfcheck()` before `element()`/`root()`/`position()`: [5](#0-4) 

`root()`/`element()` ultimately call into `IncrementalMerkleTreeContainer.last()`, which throws `ZksnarkException("tree has no cursor")` when both `left` and `right` are absent — a state reachable if the attacker sends a `voucher.tree` with empty left/right but non-empty `filled`/`cursor` fields (or any other combination violating the canonical-tree invariants that `wfcheck()` is meant to enforce): [6](#0-5) 

Note however that `ZksnarkException` is a checked exception, and both gRPC handlers and the HTTP servlet wrap the call in try/catch that converts any thrown exception into an error response rather than crashing the process or hanging the thread: [7](#0-6) [8](#0-7) 

So while `element()`/`root()` can indeed throw `ZksnarkException` on malformed voucher input, the exception is caught at the RPC/servlet boundary and converted into an error response — it does not crash the handler thread or halt the node. This is a per-request functional/validation failure (silently accepted malformed data errors out with an "OTHER_ERROR"/exception message), not a process-level denial-of-service, and it does not affect any shared state, consensus, or other requests.

### Impact Explanation
Impact is limited to the single request: a caller who supplies a malformed `voucher` in `PrivateParameters.shielded_spends` gets back an error response (`ContractValidateException`/`ZksnarkException` wrapped, or `OTHER_ERROR`) rather than a crafted transaction. No unauthorized execution, no double-spend, no value theft, no persistent halt of the RPC endpoint, and no impact to other users' requests occurs, because the store/tree state used by `GetMerkleTreeVoucherInfo` and by consensus-critical `ShieldedTransferActuator.executeShielded` (which does call `wfcheck()`) is never touched by this attacker-supplied voucher — it's a purely local, per-call object built from the request and discarded after the call.

### Likelihood Explanation
Trivial to trigger (any client can send a malformed `SpendNote.voucher`), but the resulting effect is just a caught exception producing a normal error reply, consistent with how the code already handles `ZksnarkException` and other exceptions in this codepath (`catch (ZksnarkException e)` in `createShieldedTransaction`, generic catch in RPC/HTTP handlers). There is no evidence of thread-level crash, resource exhaustion, or lasting DoS.

### Recommendation
Although not exploitable as a DoS, for defense-in-depth it is reasonable to add an explicit `wfcheck()`-style structural validation of attacker-supplied `SpendNote.voucher`/`IncrementalMerkleVoucherCapsule` at the top of `Wallet.createShieldedTransaction`/`createShieldedTransactionWithoutSpendAuthSig` before use, so that malformed vouchers are rejected with a clear `ContractValidateException` rather than relying on incidental `ZksnarkException`s from deep inside `element()`/`root()`/`last()`.

  PrivateParameters.Builder req = PrivateParameters.newBuilder();

          .setRcm(ByteString.copyFrom(new byte[32])).build())
      .setAlpha(ByteString.copyFrom(new byte[32]))

  // ... set ask/nsk/ovk to non-empty so shieldedSpends path executes ...

  // caught by RpcApiService.createShieldedTransaction handler,

  public void wfcheck() throws ZksnarkException {
    if (treeCapsule.getParents().size() >= DEPTH) {
      throw new ZksnarkException("tree has too many parents");
    }
    if (!treeCapsule.parentsIsEmpty()) {
      PedersenHashCapsule parentCompressCapsule =
          new PedersenHashCapsule(
              treeCapsule.getParents().get(treeCapsule.getParents().size() - 1));
      if (!parentCompressCapsule.isPresent()) {
        throw new ZksnarkException("tree has non-canonical representation of parent");
      }
    }

    if ((!leftIsPresent()) && rightIsPresent()) {
      throw new ZksnarkException("tree has non-canonical representation; right should not exist");
    }

    if ((!leftIsPresent()) && treeCapsule.getParents().size() > 0) {
      throw new ZksnarkException(
          "tree has non-canonical representation; parents should be empty");
    }
  }

  public PedersenHash last() throws ZksnarkException {
    if (rightIsPresent()) {
      return treeCapsule.getRight();
    } else if (leftIsPresent()) {
      return treeCapsule.getLeft();
    } else {
      throw new ZksnarkException("tree has no cursor");
    }
  }
