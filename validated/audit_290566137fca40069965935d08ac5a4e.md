### Title
Starknet OS `execute_replace_class` performs a contract-class replacement without verifying the class is declared, diverging from the blockifier's validation — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS (SNOS) Cairo re-implementation of the `replace_class` syscall unconditionally writes the caller-supplied `class_hash` into `contract_state_changes`, with no check that the class hash was ever declared. The Rust `blockifier` implementation of the same syscall, which is what the sequencer actually uses to execute and commit transactions, does perform this check and rejects/reverts the call when the class is undeclared (or a V0/Cairo0 class). This mirrors the reported `gun` bug class (CWE-841): a state-transition is triggered by unverified input without checking that a precondition for it was actually established, letting an unprivileged party drive the "verifier" into a state the real execution engine would never reach.

### Finding Description
- Blockifier's `replace_class` syscall implementation validates the class before mutating state: [1](#0-0) 
It calls `self.state.get_compiled_class(class_hash)?` (fails for undeclared classes) and additionally rejects V0/Cairo0 replacements with `ForbiddenClassReplacement`: [2](#0-1) 
This is confirmed by the existing test, which asserts that replacing with an undeclared class hash fails with "is not declared": [3](#0-2) 
Since this failure happens inside a contract's `__execute__`, the transaction is marked REVERTED by the blockifier (fee charged, but the class-hash state change is rolled back).

- The Starknet OS's own Cairo implementation of the same syscall (used for re-execution / proving, i.e. an independent, from-scratch replay of the transaction logic used to derive/prove the state transition) does **not** perform this check. It reads the state entry, unconditionally overwrites `class_hash` with the caller-supplied value, and updates the dict — with an explicit TODO acknowledging the missing check: [4](#0-3) 
The same gap exists in the deprecated (Cairo0) syscall path: [5](#0-4) 
Both are dispatched unconditionally from the syscall selector switch with no surrounding validation: [6](#0-5) 
I searched the OS state-commitment code (`state.cairo`, squash/commitment logic) and the syscall/entry-point files for any downstream check on "declared" classes that could compensate for this gap and found none in the code available to the index; the only place performing the "declared" verification is the Rust blockifier's `get_compiled_class` check, which the Cairo OS program does not call or replicate.

### Impact Explanation
The OS re-execution is the independent Cairo-program computation of the state transition that must match the state actually committed by the sequencer/blockifier for a block. Because the OS path is missing the declared-class check that the blockifier enforces, an ordinary account contract can call `replace_class_syscall` with an arbitrary, never-declared class hash inside `__execute__`:
- In the real block-building/execution path (blockifier), this syscall fails, causing the invoking entry point to fail and the transaction to be marked REVERTED — the contract's class hash is left unchanged in the committed state.
- In the OS's independent re-execution of the same transaction, the syscall succeeds unconditionally, the contract's class hash is changed in `contract_state_changes`, and execution proceeds as if the call succeeded (no revert triggered by this syscall).

This produces a genuine honest-node divergence: two implementations of "the same" state-transition rule (blockifier vs. Starknet OS) disagree on outcome for a reachable, attacker-chosen input. Since the OS's state changes feed the Patricia-tree state commitment (`state_update`/`squash_state_changes`/`calculate_global_state_root`), this can result in the OS computing a state root/output that does not match the one actually committed by the sequencer, undermining the correctness guarantee of Starknet OS re-execution (proof generation) and constituting a wrong-committed-root / honest-node-divergence class issue as accepted by the validation rules.

### Likelihood Explanation
High likelihood of reachability: any account contract's `__execute__` can call the `replace_class` syscall with an arbitrary felt as `class_hash` — no special privileges are required, and no gating exists before dispatch to `execute_replace_class` in either the deprecated or new syscall interpreter. The only thing standing between "declared" and "undeclared" class hashes reaching this code path is the check present in the Rust blockifier but absent from the Cairo OS program, and the code contains an explicit `TODO(Yoni, 1/1/2026)` acknowledging the check is not yet implemented, confirming this is a known, not-yet-addressed gap rather than a hypothetical one.

### Recommendation
Add the equivalent "class must be declared" check to the Starknet OS Cairo implementation of `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` path) before performing the `dict_update`, mirroring the blockifier's `get_compiled_class` check (and, for parity, the V0/Cairo1 restriction enforced in `syscall_base.rs::replace_class`). This requires reading the class-hash-to-compiled-class mapping (via a hint plus an assertion against the committed class table) inside the Cairo program so that the OS's syscall failure/success semantics for `replace_class` exactly match the blockifier's.

### Proof of Concept
1. Deploy an account/contract whose `__execute__` invokes `replace_class_syscall(UNDECLARED_CLASS_HASH)` with a `class_hash` that was never declared on-chain (e.g., a random felt).
2. Submit an INVOKE transaction that triggers this `__execute__`.
3. Observe (per existing blockifier test) that in the sequencer's actual execution the call fails and the transaction is marked REVERTED, leaving the contract's class hash unchanged: [3](#0-2) 
4. When the same transaction is re-executed by the Starknet OS program (`execute_replace_class` in `syscall_impls.cairo`), no equivalent declared-class check exists, so the syscall succeeds and `contract_state_changes` records the class-hash replacement — a different outcome than the one actually committed by the sequencer, demonstrating the honest-node/re-execution divergence.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
