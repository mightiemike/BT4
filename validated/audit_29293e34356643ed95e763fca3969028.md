## Analog Found

### Title
Attached deposit to `WalletContract::rlp_execute` is permanently lost when the RLP-encoded transaction fails validation before a promise is dispatched - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
The `rlp_execute` method of the NEAR wallet contract (used for ETH-implicit accounts, NEP-518) is marked `#[payable]` and accepts an attached NEAR deposit from any caller, exactly the way the reported 1inch `ClipperRouter` accepts `msg.value` without requiring it for most code paths. The contract tracks this deposit via `CallerDeposit` so it can be refunded to the caller if the *cross-contract promise* it eventually creates fails [1](#0-0) . However, several early error paths inside `inner_rlp_execute` return before any such promise is created, and the caller's attached deposit is silently dropped and retained by the wallet contract instead of refunded.

### Finding Description
`rlp_execute` computes the caller's deposit and immediately forwards to `inner_rlp_execute` [2](#0-1) .

Inside `inner_rlp_execute`, `caller_deposit` is computed right after receiving the attached deposit via `env::attached_deposit()` [3](#0-2) . If RLP/transaction parsing subsequently fails — e.g. `Error::User(_)` (malformed signature, bad nonce, unsupported action, etc.) or `Error::Relayer(_)` — the function returns `Err(err)` directly, discarding the local `caller_deposit` variable entirely [4](#0-3) .

Back in `rlp_execute`, these error variants are handled without any reference to the deposit that was attached to the call:
- For `Error::Relayer(_)` when the signer is the wallet itself, a `create_ban_relayer_promise` is created, which only revokes the relayer's key and never refunds the deposit [5](#0-4) [6](#0-5) .
- For every other `Err(e)`, the method simply returns `PromiseOrValue::Value(e.into())` [7](#0-6) , with no promise batch created to return the caller's NEAR.

The only place a refund actually happens is deep inside `rlp_execute_callback`, and only when a *dispatched* cross-contract promise later fails: [8](#0-7) . Any deposit attached to a call that errors out *before* that promise is ever created has no refund path at all — the yoctoNEAR simply becomes part of the wallet contract's own balance.

This mirrors the 1inch pattern precisely: the contract does not require `msg.value`/attached deposit for most of the call's logic (the deposit is only meaningfully used to compensate relayers for fee-based emulated transfers, see the fee-refund logic at lines 374-385), yet it neither rejects a nonzero deposit up front nor guarantees it is returned when unused, leading to unintended, permanent loss of the caller's NEAR.

### Impact Explanation
Any unprivileged account (an external "caller"/relayer) that submits a transaction calling `rlp_execute` with an attached deposit — intended, per the contract's own `CallerDeposit` design, to be refundable on failure — can permanently lose that NEAR if the embedded Ethereum-style transaction fails validation (bad signature, bad nonce format, unsupported action, or a relayer-detected fault) before any promise is scheduled. This is a concrete, transaction-triggered, unauthorized retention of value (funds effectively "frozen"/misappropriated into the wallet contract's balance) reachable from a single RPC-submitted transaction, with no privileged role required.

### Likelihood Explanation
This is straightforward to trigger: any caller who attaches a nonzero deposit and supplies a transaction that fails NEAR-side validation (e.g., wrong nonce, unsupported action type, signature/parse errors — several of these are user-controlled inputs to `parse_rlp_tx_to_action`) hits one of the un-refunded early-return branches. No special privileges, malicious peers, or network manipulation are needed — only a normal transaction call to a deployed wallet contract instance.

### Recommendation
Ensure the attached deposit is refunded (or the call is rejected outright) on every early-error return path of `inner_rlp_execute`/`rlp_execute`, not only when a dispatched cross-contract promise later fails. Concretely:
- Reject the call up front if `env::attached_deposit()` is nonzero for code paths that do not need it (analogous to the recommended `require(msg.value == 0)` check), or
- Thread `caller_deposit` through every error return of `inner_rlp_execute` and issue a `promise_batch_action_transfer` refund to the predecessor in `rlp_execute`'s `Err(e)` branches (including the `create_ban_relayer_promise` path), mirroring the refund logic already present in `rlp_execute_callback`.

### Proof of Concept
1. An external account (not the eth-implicit wallet itself) calls `rlp_execute(target, tx_bytes_b64)` on a deployed `WalletContract`, attaching a nonzero NEAR deposit (as encouraged by the `CallerDeposit`/fee-refund design for relayers).
2. Supply an RLP-encoded Ethereum transaction that fails NEAR-side parsing/validation and results in `Error::User(_)` or `Error::Relayer(_)` from `internal::parse_rlp_tx_to_action` (e.g., an unsupported action type, or signature/nonce mismatch) — see the match arms at [4](#0-3) .
3. `inner_rlp_execute` returns `Err(err)` before creating any promise; `rlp_execute` returns `PromiseOrValue::Value(e.into())` (or dispatches `create_ban_relayer_promise` with no refund).
4. The attached deposit is never sent back to the caller; it remains part of the wallet contract account's balance, i.e., the caller has permanently lost the yoctoNEAR they attached — confirmable by comparing the caller's balance before/after the call, analogous to the balance-diff assertions used in the existing `test_caller_refunds` test [9](#0-8) , but for a synchronous (pre-promise) failure path which that test does not cover.

/// A data type to keep track of the deposit given by an external caller.
/// This allows us to refund the caller's deposit if the cross-contract call fails.
#[derive(Debug, PartialEq, Eq, Clone, serde::Serialize, serde::Deserialize)]
pub struct CallerDeposit {
    pub account_id: AccountId,
    pub yocto_near: NonZeroU128,
}

impl CallerDeposit {
    pub fn new(context: &ExecutionContext) -> Option<Self> {
        // Only track for external (non-self) callers
        if context.current_account_id == context.predecessor_account_id {
            return None;
        }

        NonZeroU128::new(context.attached_deposit.as_yoctonear()).map(|yocto_near| Self {
            account_id: context.predecessor_account_id.clone(),
            yocto_near,
        })
    }

// An external caller gets its deposit back if the cross-contract call fails.
#[tokio::test]
async fn test_caller_refunds() -> anyhow::Result<()> {
    let TestContext { worker, wallet_contract, wallet_sk, address_registrar, .. } =
        TestContext::new().await?;

    let caller = worker.root_account()?;
    let deposit_amount = NearToken::from_near(3);
    let create_tx = |receiver_id: &AccountId, nonce: u64| {
        let method = "register";
        let args = br#"{"account_id": "birchmd.near"}"#;
        let action = Action::FunctionCall {
            receiver_id: receiver_id.to_string(),
            method_name: method.into(),
            args: args.to_vec(),
            gas: Gas::from_tgas(10).as_gas(),
            yocto_near: 0,
        };
        utils::create_signed_transaction(
            nonce,
            receiver_id,
            Wei::new_u128(deposit_amount.as_yoctonear() / (MAX_YOCTO_NEAR as u128)),
            action,
            &wallet_sk,
        )
    };

    // External caller gets a refund when the cross-contract call fails
    let pre_tx_account_balance = caller.view_account().await?.balance;
    let receiver_id: AccountId = "fake.near".parse()?;
    let result = wallet_contract
        .rlp_execute_from(
            &caller,
            receiver_id.as_str(),
            &create_tx(&receiver_id, 0),
            deposit_amount,
        )
        .await?;
    assert!(!result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            < deposit_amount.as_yoctonear()
    );

    // External caller does not get a refund when their tokens are spent
    let pre_tx_account_balance = post_tx_account_balance;
    let receiver_id = address_registrar.id();
    let result = wallet_contract
        .rlp_execute_from(&caller, receiver_id.as_str(), &create_tx(receiver_id, 1), deposit_amount)
        .await?;
    assert!(result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            >= deposit_amount.as_yoctonear()
    );

    Ok(())
}
