**Analysis:** The mechanism described is the designed safety net, not an exploitable flaw. `pairing_internal!` pops `g1_element_handle`/`g2_element_handle` and immediately passes them through `safe_borrow_element!` [1](#0-0) , which looks up the handle in `AlgebraContext.objs` (a `Vec<Rc<dyn Any>>`) and performs a `downcast_ref::<$typ>()` where `$typ` is fixed by the matched `Structure` branch (e.g. `ark_bls12_381::G1Projective`) [2](#0-1) .

If a handle stored by a prior `new_internal`/deserialize call for a different structure (e.g. BN254 `G1Projective`) is replayed against a BLS12-381 branch, `downcast_ref::<ark_bls12_381::G1Projective>()` returns `None` because the underlying `Rc<dyn Any>` was created with a different concrete type. This triggers `.ok_or_else(abort_invariant_violated)?`, which aborts the entire transaction with an invariant-violation VM status rather than producing a "corrupted" handle or GT value [3](#0-2) .

This exactly matches the "Proof idea" already stated in the question — the transaction aborts. Per the review's decision standard, an abort with no state mutation does not corrupt committed state, proof material, or an authenticated response; it simply causes the transaction to fail as VM-invariant-violated. `AlgebraContext` is reset per-session via `SessionListener::start` [4](#0-3) , so no cross-transaction state leakage occurs either. There is no write-set, proof, or authenticated-response mis-binding — the finding as posed does not rise to a state-integrity violation.

macro_rules! safe_borrow_element {
    ($context:expr, $handle:expr, $typ:ty, $ptr_out:ident, $ref_out:ident) => {
        let $ptr_out = $context
            .extensions()
            .get::<AlgebraContext>()
            .objs
            .get($handle)
            .ok_or_else(abort_invariant_violated)?
            .clone();
        let $ref_out = $ptr_out
            .downcast_ref::<$typ>()
            .ok_or_else(abort_invariant_violated)?;
