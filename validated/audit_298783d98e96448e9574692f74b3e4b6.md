### Title
`TokenConfig.Enabled` flag is never checked before minting PRC20 for inbound deposits - (File: `x/uexecutor/keeper/handler.go`, `x/uregistry/keeper/keeper.go`)

### Summary
`x/uregistry.TokenConfig` carries an `enabled` field explicitly documented as "Whether this token is enabled for minting/bridging" [1](#0-0) , but no code path in `x/uexecutor` (or elsewhere) ever reads or enforces this flag before minting PRC20 tokens for an inbound deposit. This mirrors the reported "missing supported-asset check" bug class: the field exists to gate a supported/deprecated asset but is not actually enforced in the value-minting path.

### Finding Description
`GetTokenConfig`, used by every inbound-execution code path that mints PRC20 tokens, only checks for key existence in the `TokenConfigs` map and returns whatever is stored — it never inspects `config.Enabled`: [2](#0-1) 

This config is looked up and used directly to mint PRC20 to a recipient in `depositPRC20`, which is called from every inbound-funds execution flow (`ExecuteInboundFundsAndPayload`, `ExecuteInboundGas`): [3](#0-2) [4](#0-3) [5](#0-4) 

None of these call sites, nor `ValidateForExecution` on the `Inbound` type, check `tokenConfig.Enabled`: [6](#0-5) 

`MsgUpdateTokenConfig`/`UpdateTokenConfig` allow an admin to flip a token's `Enabled` field to `false` (intending to deprecate an asset) without removing the `TokenConfig` entry: [7](#0-6) 

Because nothing downstream reads `Enabled`, this update has no operational effect: any user can still submit a `MsgVoteInbound` referencing that "disabled" token, and once the honest UV ballot passes, the core validator will still mint PRC20 via `depositPRC20`/`CallPRC20Deposit`, exactly as if the token were still enabled. This is the direct analog of the reported `depositAndBridge` bug — the presence of a "supported asset" boolean that is not actually enforced, so a deprecated/soft-disabled asset keeps producing backed (or unbacked, depending on why it was disabled, e.g. compromised bridge, broken price oracle, liquidity-cap bypass) PRC20 mints on Push Chain.

### Impact Explanation
If the admin disables a token config in response to a problem with that asset on the source chain (compromised gateway/vault contract, bad liquidity, wrong decimals, etc.) but does not also call `MsgRemoveTokenConfig`, ordinary unprivileged users can keep depositing that asset and Push Chain will keep minting matching PRC20 balances, because `Enabled` is decorative. This corrupts the PRC20/native-asset accounting invariant (PRC20 supply no longer strictly reflects "currently supported/backed" assets) and can lead to unauthorized mint of PRC20 that the protocol intended to have stopped issuing. Impact is Low because it depends on an admin having only partially deprecated an asset (disable without remove), the same caveat noted in the original report.

### Likelihood Explanation
Likelihood is Low-to-Medium: it requires no attacker privilege at all — the trigger is any user submitting a normal deposit for the affected asset chain/address — but it only becomes materially exploitable once an admin has toggled `Enabled=false` for a token without removing it, which is an operational/administrative state rather than something an attacker controls directly.

### Recommendation
Enforce `TokenConfig.Enabled` (or equivalent) in the mint path: add a check in `GetTokenConfig` (or explicitly in `depositPRC20` / `ExecuteInboundFundsAndPayload` / `ExecuteInboundGas`) that returns an error when `tokenConfig.Enabled == false`, causing the inbound to fail validation/execution (and trigger the existing revert-outbound flow) rather than silently minting PRC20 for a deprecated asset. Alternatively, if `Enabled` is meant to be purely informational, remove it from `TokenConfig` to avoid the false impression that it gates mint/bridge behavior.

### Proof of Concept
1. Admin registers a token config for `eip155:1`/`0xTOKEN` with `Enabled: true` and a `NativeRepresentation.ContractAddress` PRC20.
2. Admin later calls `MsgUpdateTokenConfig` setting `Enabled: false` for the same `(chain, address)` key, intending to stop further deposits (e.g., because the source-chain gateway was compromised), but does not call `MsgRemoveTokenConfig`.
3. An unprivileged user deposits the asset on the source chain; Universal Validators observe and vote `MsgVoteInbound` honestly (ballot passes).
4. `ExecuteInboundFundsAndPayload`/`ExecuteInboundGas` call `depositPRC20`, which calls `k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)` — this succeeds and returns the config with `Enabled=false` unchecked, and `CallPRC20Deposit` mints PRC20 to the recipient exactly as before the disable.
5. Result: an asset the admin flagged as unsupported continues to back new PRC20 mints, with no observable difference from the enabled state — the `Enabled` flag is provably dead code with respect to minting.

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}

// UpdateTokenConfig updates an existing token configuration in the uregistry.
func (k Keeper) UpdateTokenConfig(ctx context.Context, tokenConfig *types.TokenConfig) error {
	storageKey := types.GetTokenConfigsStorageKey(tokenConfig.Chain, tokenConfig.Address)

	// Check if the token config exists
	if has, err := k.TokenConfigs.Has(ctx, storageKey); err != nil {
		return err
	} else if !has {
		return fmt.Errorf("token config for %s on chain %s does not exist", tokenConfig.Address, tokenConfig.Chain)
	}

	if err := k.TokenConfigs.Set(ctx, storageKey, *tokenConfig); err != nil {
		return err
	}
	k.Logger().Info("token config updated",
		"chain", tokenConfig.Chain,
		"token_address", tokenConfig.Address,
	)
	return nil
}
