### Title
Missing "class is declared" check in the Starknet OS `execute_replace_class` syscall implementation allows an untrusted-input-driven state/class-hash mismatch, diverging from Blockifier's enforced invariant - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
Any account contract can invoke the `replace_class` syscall as part of a normal `__execute__` call. In the Rust execution engine (Blockifier), `replace_class` explicitly validates that the target `class_hash` corresponds to an already-declared class before mutating `class_hash_at(contract_address)` [1](#0-0) , and the deprecated syscall handler performs the same check by reading the compiled class first [2](#0-1) . However, the Starknet OS program's Cairo re-implementation of the same syscall, `execute_replace_class`, has this validation explicitly missing, marked by an open TODO instead of an actual assertion [3](#0-2) . The identical deprecated-syscall Cairo path has the same gap [4](#0-3) .

### Finding Description
The Jenkins CVE's root cause is that a submitted identifier (agent name in the XML) is trusted to target state without validating it against constraints that a stricter reference check enforces elsewhere, letting one entity silently overwrite another entity's protected configuration. The direct analog here is a constraint divergence between the two independent "reference" execution engines for Starknet transactions: Blockifier (the engine that actually executes transactions and computes fees/state diffs for the sequencer) and the Starknet OS Cairo program (the canonical, provable re-execution logic used to attest to and prove block correctness).

Both are supposed to implement the exact same state-transition function. Blockifier's `replace_class` calls `self.state.get_compiled_class(class_hash)?` before writing `class_hash_at`, returning an `UndeclaredClassHash` error if the class was never declared [1](#0-0) . This is confirmed to be a load-bearing check by tests exercising exactly this negative case [5](#0-4) .

The Cairo OS implementation of `execute_replace_class`, by contrast, unconditionally applies the state update using only a `%{ GetContractAddressStateEntry %}` hint and directly writes `new_state_entry` with the attacker-controlled `class_hash` into `contract_state_changes`, with an explicit `TODO(Yoni, 1/1/2026)` acknowledging the missing declared-class check [6](#0-5) .

Since the OS program is the arithmetized (STARK-provable) reference implementation of the state transition function, any semantic gap between it and Blockifier is a soundness break in the "Starknet OS re-execution" path: the OS accepts as valid a state transition (a contract's `class_hash` set to an undeclared value) that Blockifier's own state-transition rules reject. This directly targets the explicitly in-scope area "Starknet OS re-execution."

### Impact Explanation
If the OS's constraint system is more permissive than Blockifier's actual state-transition semantics, the OS can be made to attest to (and a STARK proof can be produced for) a resulting state root in which a contract's `class_hash` entry points to a class hash that was never declared/compiled. Once committed to the state tree, any node computing the state root purely from OS-verified constraints (rather than replaying full Blockifier semantics) will accept this root, while any node deriving state strictly through Blockifier's `replace_class` path would have rejected the same transaction as reverted, producing state-root/honest-node divergence for the same input transaction — a consensus-critical correctness bug rather than a mere resource or DoS issue.

### Likelihood Explanation
The `replace_class` syscall is reachable by any Cairo1 contract executing under a completely ordinary invoke transaction sent by an unprivileged account — no special role, staking, or proposer privilege is required, matching the constraint that this must be reachable from a single submitted transaction. Because Blockifier is used for real (non-proving) sequencer execution, an actual invalid replace_class attempt is rejected before it ever reaches the OS through the normal single-sequencer path; the OS gap is latent and becomes concretely exploitable specifically in the "Starknet OS re-execution"/proving pipeline where the OS's Cairo logic — not Blockifier's Rust guard — is the actual source of truth for state-diff validity.

### Recommendation
Add an explicit check in `execute_replace_class` (and the deprecated syscall equivalent) in the Cairo OS program that asserts the given `class_hash` is present as a declared class in `contract_class_changes`/global class declarations before permitting the `dict_update` on `contract_state_changes`, mirroring Blockifier's `get_compiled_class(class_hash)` check, and add regression tests analogous to `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs` for the OS Cairo path.

### Proof of Concept
1. Deploy any Cairo1 contract exposing a function that calls the `replace_class` syscall with an attacker-chosen `class_hash` value that has never been declared on-chain (e.g., `test_replace_class` pattern used in `crates/blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo`, analogous to the existing test at [5](#0-4) ).
2. Submit a normal invoke transaction invoking this function from an unprivileged account; Blockifier rejects it with `UndeclaredClassHash`/`is not declared`.
3. In the Starknet OS Cairo re-execution path (`execute_replace_class`), the same syscall request, if it reaches `contract_state_changes` (e.g., via divergent trace generation for proving), is applied without any check that `class_hash` is declared, per [6](#0-5) , producing a `contract_state_changes` entry with `class_hash` set to the undeclared value and a corresponding state diff / provable state root that Blockifier's semantics would never produce.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
