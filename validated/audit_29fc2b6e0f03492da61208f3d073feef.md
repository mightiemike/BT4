### Title
Missing class-declaration and Cairo-version validation in the Starknet OS `replace_class` re-execution allows spec divergence from blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The CVE describes a privilege-elevation guard (`set_user`) whose "reset" path failed to fully restore/enforce the original protections, letting an elevated state persist beyond its intended scope. The closest reachable analog in this sequencer is the `replace_class` syscall, which lets an unprivileged contract change its own stored `class_hash` (a state-elevating action similar in spirit to changing session authorization). The actual execution engine (blockifier) enforces two guards before allowing this class swap, but the Starknet OS's Cairo re-implementation of the same syscall — used for re-execution/proving of the block — omits both guards, leaving an explicit `TODO` acknowledging the missing check.

### Finding Description
In blockifier, `replace_class` requires the target class to be (1) declared and (2) a Cairo 1 (V1) class: [1](#0-0) 

The equivalent logic inside the Starknet OS's Cairo implementation (`execute_replace_class`, used to re-execute/verify the transaction and derive the committed state root) performs neither check — it directly writes the new `class_hash` into `contract_state_changes` after only a gas-reduction step, with a `TODO` noting the declared-class check is not yet implemented, and no `is_cairo1`-equivalent check at all: [2](#0-1) 

The deprecated (Cairo0) OS syscall path has the same gap — it updates `contract_state_changes` and appends a revert-log entry without any declaration or version check: [3](#0-2) 

Because the Starknet OS Cairo program is the specification that gets proven (its execution trace determines the committed state root/block hash), any place where its enforced constraints are weaker than blockifier's constitutes a latent spec mismatch. If any code path ever causes the OS to independently accept and commit a `replace_class` transition that blockifier itself would have rejected (e.g., a class hash that is undeclared or is a Cairo0 class being set on a Cairo1-only contract), the OS would still compute a class-hash state update and revert-log entry as if it were valid, propagating an inconsistent/incorrect state root or contract behavior into the committed block — comparable to the CVE's pattern of a "reset"/administrative safety check that is present in one enforcement layer but silently absent in the other.

### Impact Explanation
`set_class_hash_at` and the corresponding storage/class dict updates directly determine which code governs a contract going forward, and therefore its account/authorization logic; an unguarded class replacement in the trusted re-execution layer can, in principle, allow an undeclared or version-incompatible class hash to become part of the committed state, causing wrong committed root/class-hash divergence between the sequencer's actual execution and the OS's canonical re-execution/proof — a state-commitment integrity issue.

### Likelihood Explanation
The bug is only reachable if the Starknet OS re-execution/proving path can be exercised on a transaction stream that was not already filtered/rejected by blockifier's own `replace_class` check (i.e., a discrepancy between the two paths' inputs). In the current single-sequencer pipeline (blockifier executes first, then the OS proves what blockifier produced), this divergence is unlikely to be triggerable by an ordinary transaction sender today, since blockifier's stricter check runs first and would reject the malicious `replace_class` call before it reaches the OS. I could not confirm from the indexed code whether any later stage (e.g., final state-commitment validation in `os.cairo`) independently re-validates class declarations, so I cannot rule out a scenario where this gap becomes exploitable (e.g., future changes decoupling OS re-execution from blockifier's pre-filtering, or a proving-only replay path).

### Recommendation
Add the same guards enforced by blockifier's `replace_class` (declared-class check via a lookup analogous to `get_compiled_class`, and a Cairo1-version check) to both `execute_replace_class` implementations in the Starknet OS Cairo sources (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`), removing the outstanding `TODO`, and add a Starknet-OS-level test asserting rejection of undeclared/Cairo0 replacement class hashes to keep the two execution layers in sync.

### Proof of Concept
Not independently exploitable from the currently indexed code alone: because blockifier's `replace_class` (crates/blockifier/src/execution/syscalls/syscall_base.rs:369) already rejects undeclared/Cairo0 class hashes before a transaction is fed to the Starknet OS, a concrete end-to-end PoC would require identifying (or introducing) a path where the OS Cairo program (`execute_replace_class`) re-executes/verifies a `replace_class` syscall independently of blockifier's guard — this could not be confirmed from the available index and would need direct repository access/execution to verify whether such a decoupled path exists.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
