## Analysis

The Superfluid Locker bug is a **spot-AMM-price-as-oracle** problem: the code trusts an instantaneous Uniswap pool price with no TWAP or manipulation guard, so an attacker who moves the pool price (e.g., via a large swap in a low-liquidity pool) can force the withdrawal logic to act on the manipulated price.

Push Chain has a structurally identical pattern in the gas-abstraction auto-swap path used for GAS and GAS_AND_PAYLOAD inbounds, and in the outbound gas-refund path. Both call `GetSwapQuote`, which queries Uniswap V3 `QuoterV2.quoteExactInputSingle` for an **instantaneous spot quote** (`SqrtPriceLimitX96: 0`, no TWAP), and then derive the slippage floor from that *same* spot read: [1](#0-0) 

That quote is used to compute `minPCOut = quote * 95 / 100` and immediately passed into the same-block swap execution: [2](#0-1) 

The identical pattern is repeated for `GAS_AND_PAYLOAD` inbounds: [3](#0-2) 

and for the excess-gas refund flow on successful outbounds: [4](#0-3) 

Because the "slippage protection" is computed from the very same manipulated spot price it is meant to protect against, it provides no real defense — exactly the root cause pattern described in the Superfluid report (`quote read` and `execution` happen against the same manipulable pool state, with no TWAP or minimum-liquidity check). The upgrade log confirms this is intentional current behavior, not a stale code path: [5](#0-4) 

### Title
Gas-abstraction PRC20→WPC autoswap and gas-refund swaps use a manipulable same-block spot AMM quote as both price reference and slippage floor, enabling sandwich extraction from bridged user funds - (File: x/uexecutor/keeper/evm.go)

### Summary
`GetSwapQuote` fetches an instantaneous (non-TWAP) quote from Uniswap V3 `QuoterV2.quoteExactInputSingle` with `sqrtPriceLimitX96 = 0` (no price-impact bound). `ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund`/`getSwapQuoteForRefund` all use this quote to derive `minPCOut = quote * 95%` and pass it to `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, which execute the real swap in the same call flow against the same pool state. Since the slippage floor is derived from the manipulated price itself rather than an external/TWAP reference, an attacker who moves a low-liquidity WPC/PRC20 pool immediately before the deposit-autoswap or refund-swap executes can force the protocol's swap to execute at an attacker-favorable, manipulated price while the "5% slippage" check trivially passes.

### Finding Description
For every GAS/GAS_AND_PAYLOAD inbound, and every outbound gas refund with a swap leg, Push Chain performs a protocol-initiated Uniswap V3 swap of a bridged PRC20 token into WPC on behalf of the user. The expected output is read via `GetSwapQuote` (spot quote, no TWAP, no price limit) and the same read is used to build the "protection" bound (`minPCOut`) that is checked against the outcome of a swap executed at the same manipulated price. This is the same anti-pattern flagged in the Superfluid report: relying on an easily-movable spot price for both the reference value and the safety check collapses the safety check to a near no-op whenever the attacker can move the pool beyond the 5% band and still land within it relative to the manipulated baseline. Because `sqrtPriceLimitX96` is hardcoded to 0, there's also no absolute price-impact ceiling independent of the (also manipulated) quote.

### Impact Explanation
An attacker who can manipulate a low-liquidity WPC/PRC20 pool for a bridged asset (a pool most newly listed or thinly traded PRC20 tokens will have) can extract value from the protocol's own automated swaps on behalf of bridging users and outbound-refund recipients, both of which are unprivileged, ordinary user flows (inbound funds bridging, outbound gas refunds). This corrupts gas-fee/refund accounting and results in users receiving less native PC/WPC than fair value while the difference is captured by the manipulator — a direct value-drain from user/protocol-controlled funds, matching the in-scope "corruption of ... gas fee accounting, refund accounting ... token mapping" and "draining ... of user or protocol-controlled funds" categories.

### Likelihood Explanation
Exploitation requires only: (1) a low-liquidity Uniswap V3 pool for the target PRC20/WPC pair (external, but well within an unprivileged actor's control to create or target), and (2) the ability to land a manipulating swap transaction in the same block/state as the module's autoswap or refund-swap call, which is triggered deterministically by ordinary vote-finalization (`VoteInbound`/`VoteOutbound`) events that any user can influence the timing of by choosing when to bridge funds, combined with standard priority-fee front-running. No malicious validator, TSS participant, or governance/admin privilege is required.

### Recommendation
Do not derive the slippage floor from the same instantaneous quote used at execution time. Use a TWAP-based quote (Uniswap V3 pool `observe()`/oracle cardinality) as the reference price, enforce a maximum allowed deviation between spot and TWAP before allowing the autoswap/refund-swap to proceed, and/or set a non-zero `sqrtPriceLimitX96` bound and a registry-configured minimum liquidity threshold per pool before routing gas-abstraction swaps through it, consistent with the mitigation suggested in the referenced report.

### Proof of Concept
1. Attacker identifies (or seeds) a low-liquidity WPC/PRC20-X pool used as the `defaultFeeTier` route for token X.
2. Attacker bridges a GAS-type inbound of token X (or waits for a legitimate user's bridge tx), then, right before the finalizing `VoteInbound`/`VoteOutbound` tx lands (via priority-fee front-running), executes a large swap that pushes the X/WPC spot price down.
3. `ExecuteInboundGas` → `GetSwapQuote` reads the manipulated spot price; `minPCOut` is computed as 95% of that already-depressed quote (`x/uexecutor/keeper/execute_inbound_gas.go:142-148`).
4. `CallPRC20DepositAutoSwap` executes the real swap against the still-manipulated pool, satisfying `minPCOut` easily while delivering far less WPC to the user's UEA than the pre-manipulation fair price would have.
5. Attacker reverses their initial swap in the same or next block, extracting the difference as sandwich profit, funded by the value that should have gone to the bridging user's UEA.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
