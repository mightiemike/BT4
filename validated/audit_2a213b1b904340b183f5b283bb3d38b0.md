### Title
Cross-shard receipt forwarding permanently stalls a shard's outgoing queue when a single receipt's congestion gas exceeds `allowed_shard_outgoing_gas` under full congestion, absent the `ClampOutgoingGasAdmission` fix - (File: `runtime/runtime/src/congestion_control.rs`)

### Summary
Just as the RocketPool `Reth` withdrawal path had exactly one route to convert `rETH` to `ETH` (burning against `RocketDepositPool` excess balance) with no fallback, so that an unmet precondition (insufficient excess balance) permanently blocked withdrawals for the whole protocol, NEAR's cross-shard receipt forwarding path has (had, pre-PV85) exactly one route to admit a buffered receipt into a fully-congested receiver's link: the sender must be the deterministically-chosen `allowed_shard`, and the *entire* receipt's congestion gas must fit under the fixed `allowed_shard_outgoing_gas` budget every chunk. A single unprivileged transaction that creates one large-gas receipt to a shard that later becomes fully congested can permanently exceed that budget, so the receipt (and everything behind it in the FIFO outgoing buffer) can never be forwarded — a transaction-triggered liveness halt for that shard link — until the protocol shipped `ClampOutgoingGasAdmission`.

### Finding Description
When a receiver shard is fully congested, `CongestionControl::outgoing_gas_limit` grants gas only to the deterministically-selected `allowed_shard`, and caps it at the fixed config value `allowed_shard_outgoing_gas`, everyone else gets `Gas::ZERO`: [1](#0-0) 

This value becomes the `OutgoingLimit.gas` budget for that link at the start of the chunk (`ReceiptSink::new`): [2](#0-1) 

The actual admission decision is made in `try_forward`. Before `ClampOutgoingGasAdmission` activates, `admission_gas` is simply the receipt's full congestion gas — never clamped to the per-chunk budget: [3](#0-2) 

If a single receipt's congestion gas (`compute_receipt_congestion_gas`, driven by attached `FunctionCall` gas plus prepaid exec/send fees) exceeds `allowed_shard_outgoing_gas`, then `forward_limit.gas >= admission_gas` is false on *every* chunk that the receiver stays fully congested, because `forward_limit.gas` is reset to at most `allowed_shard_outgoing_gas` each chunk and the receipt's gas never shrinks. The receipt is returned `NotForwarded` and stays at the head of the receiver's FIFO outgoing buffer (`buffer_receipt` / `outgoing_buffers`), blocking every other receipt queued behind it for that shard: [4](#0-3) 

The protocol itself documents this exact failure mode and its fix: the `ClampOutgoingGasAdmission` feature (PV 85) clamps `admission_gas` to `allowed_shard_outgoing_gas` precisely "so a single very-expensive receipt cannot be blocked forever by the gas limit; pre-85 the full receipt gas is used": [5](#0-4) [6](#0-5) 

This is structurally identical to the RocketPool analog: a withdrawal (here, "forward this receipt") depends on a single, unconditioned sufficiency check against a bounded resource (excess `RocketDepositPool` balance / `allowed_shard_outgoing_gas`) with no alternate path, so once the check can never be satisfied for one item, the whole downstream queue (all `SafETH` withdrawals / all receipts buffered behind this one to that shard) is bricked.

### Impact Explanation
Any single account can submit a normal `FunctionCall` transaction attaching close to the maximum allowed gas (`max_tx_gas`/the chunk gas limit) targeting a receiver on a shard. If that receiver shard subsequently becomes fully congested (a state reachable through ordinary network load, not requiring malicious validators), the resulting action receipt's congestion gas can exceed the fixed `allowed_shard_outgoing_gas` budget. Under pre-PV85 behavior, this receipt is never forwarded, and because the persistent outgoing buffer is FIFO, every subsequent receipt queued for that shard link is starved indefinitely — a transaction-triggered halt of cross-shard progress to that shard, degrading (and potentially indefinitely stalling) the protocol's liveness guarantee that "deadlocks are provably impossible" as documented in `allowed_shard_outgoing_gas`'s own doc comment.

### Likelihood Explanation
The scenario requires only an ordinary unprivileged transaction with high attached gas plus the receiver shard becoming fully congested — both are reachable without any privileged or malicious-node behavior, and the bug class is corroborated by the codebase's own documentation of the fix rationale. This is a genuine historical/version-window bug (active for protocol versions below 85, which remain within `MIN_SUPPORTED_PROTOCOL_VERSION = 83` on this tree), analogous in status to the RocketPool finding, which was also confirmed and subsequently mitigated by the project.

### Recommendation
Ensure `ClampOutgoingGasAdmission` (or equivalent per-receipt admission-gas clamping to `allowed_shard_outgoing_gas`) is unconditionally active for all supported protocol versions rather than feature-gated, and add an invariant test that a single maximal-gas receipt destined for a shard that becomes fully congested is still eventually forwarded (progress guarantee) even when `forward_limit.gas` alone would never cover its full congestion gas.

### Proof of Concept
1. Submit a `FunctionCall` transaction from an unprivileged account with `attached_gas` close to `max_tx_gas`, targeting `receiver_id` on shard `S`.
2. Drive shard `S`'s congestion level to `1.0` (fully congested) via delayed/buffered/memory congestion, as exercised in `runtime/runtime/src/tests/apply.rs` (`congestion.congestion_level() == 1.0` ⇒ `outgoing_gas_limit(local_shard) == Gas::ZERO` for non-allowed shards, `allowed_shard_outgoing_gas` for the allowed shard) — see `test_missed_chunks_finalize`: [7](#0-6) 
3. Run the network at a protocol version below `ClampOutgoingGasAdmission`'s activation (PV 85). On the sender shard, `try_forward` compares the receipt's *unclamped* full gas against `forward_limit.gas == allowed_shard_outgoing_gas`; if the receipt's gas exceeds this budget, `forward_limit.gas >= admission_gas` is permanently false, so the receipt (and the FIFO buffer behind it) never drains while the receiver stays fully congested.

```rust
            // Red traffic light: reduce to minimum speed

                self.config.allowed_shard_outgoing_gas
            } else {
                Gas::ZERO
            }
        } else {
            mix_gas(self.config.max_outgoing_gas, self.config.min_outgoing_gas, congestion)
        }
    }
```

```rust
impl ReceiptSinkV2 {
    /// Forward receipts from the outgoing buffer of buffer_shard_id to the
    /// outgoing receipts as much as the limits allow.
    ///
    /// Please note that the buffer shard id may be different than the target
    /// shard if for a short period of time after resharding. That is because
    /// some shards may have receipts for the parent shard that no longer exists
    /// and those receipts need to be forwarded to either of the child shards.
    ///
    /// TODO(resharding) - remove the parent outgoing buffer once it's empty.
    fn forward_from_buffer_to_shard(
        &mut self,
        buffer_shard_id: ShardId,
        state_update: &mut TrieUpdate,
        apply_state: &ApplyState,
        shard_layout: &ShardLayout,
    ) -> Result<(), RuntimeError> {
        let mut num_forwarded = 0;
        let mut outgoing_metadatas_updates: Vec<(ByteSize, Gas)> = Vec::new();
        for receipt_result in
            self.outgoing_buffers.to_shard(buffer_shard_id).iter(&state_update.trie, true)
        {
            let receipt = receipt_result?;
            let gas = receipt_congestion_gas(&receipt, &apply_state.config)?;
            let size = receipt_size(&receipt)?;
            let should_update_outgoing_metadatas = receipt.should_update_outgoing_metadatas();
            let receipt = receipt.into_receipt();
            let target_shard_id = receipt.receiver_shard_id(&shard_layout)?;

            match Self::try_forward(
                receipt,
                gas,
                size,
                target_shard_id,
                &mut self.outgoing_limit,
                &mut self.outgoing_receipts,
                apply_state,
                &mut self.stats,
            )? {
                ReceiptForwarding::Forwarded => {
                    self.own_congestion_info.remove_receipt_bytes(size)?;
                    self.own_congestion_info.remove_buffered_receipt_gas(gas.as_gas().into())?;
                    if should_update_outgoing_metadatas {
                        // Can't update metadatas immediately because state_update is borrowed by iterator.
                        outgoing_metadatas_updates.push((ByteSize::b(size), gas));
                    }
                    // count how many to release later to avoid modifying
                    // `state_update` while iterating based on
                    // `state_update.trie`.
                    num_forwarded += 1;
                }
                ReceiptForwarding::NotForwarded(_) => {
                    break;
                }
            }
        }

        self.outgoing_buffers.to_shard(buffer_shard_id).pop_n(state_update, num_forwarded)?;
        for (size, gas) in outgoing_metadatas_updates {
            self.outgoing_metadatas.update_on_receipt_popped(
                buffer_shard_id,
                size,
                gas,
                state_update,
            )?;
        }
        Ok(())
    }
```

```rust
    fn try_forward(
        receipt: Receipt,
        gas: Gas,
        mut size: u64,
        shard: ShardId,
        outgoing_limit: &mut HashMap<ShardId, OutgoingLimit>,
        outgoing_receipts: &mut Vec<Receipt>,
        apply_state: &ApplyState,
        stats: &mut ReceiptSinkStats,
    ) -> Result<ReceiptForwarding, RuntimeError> {
        // There is a bug which allows to create receipts that are above the size limit. Receipts
        // above the size limit might not fit under the maximum outgoing size limit. Let's pretend
        // that all receipts are at most `max_receipt_size` to avoid receipts getting stuck.
        // See https://github.com/near/nearcore/issues/12606
        let max_receipt_size = apply_state.config.wasm_config.limit_config.max_receipt_size;
        if size > max_receipt_size {
            tracing::debug!(
                target: "runtime",
                receipt_id=?receipt.receipt_id(),
                size,
                max_receipt_size,
                "try_forward observed a receipt with size exceeding the size limit",
            );
            size = max_receipt_size;
        }

        // Default case set to `Gas::MAX`: If no outgoing limit was defined for the receiving
        // shard, this usually just means the feature is not enabled. Or, it
        // could be a special case during resharding events. Or even a bug. In
        // any case, if we cannot know a limit, treating it as literally "no
        // limit" is the safest approach to ensure availability.
        let default_gas_limit = Gas::MAX;

        // Since bandwidth scheduler, a shard is not allowed to send any receipts if it doesn't have a grant.
        let default_size_limit = 0;

        let default_outgoing_limit =
            OutgoingLimit { gas: default_gas_limit, size: default_size_limit };
        let forward_limit = outgoing_limit.entry(shard).or_insert(default_outgoing_limit);

        let admission_gas = if ProtocolFeature::ClampOutgoingGasAdmission
            .enabled(apply_state.current_protocol_version)
        {
            gas.min(apply_state.config.congestion_control_config.allowed_shard_outgoing_gas)
        } else {
            gas
        };

        if forward_limit.gas >= admission_gas && forward_limit.size >= size {
            tracing::trace!(target: "runtime", ?shard, receipt_id=?receipt.receipt_id(), "forwarding buffered receipt");
            outgoing_receipts.push(receipt);
            forward_limit.gas = forward_limit.gas.saturating_sub(gas);
            forward_limit.size -= size;
            stats.forwarded_receipts.entry(shard).or_default().add_receipt(size, gas);

            Ok(ReceiptForwarding::Forwarded)
        } else {
            tracing::trace!(target: "runtime", ?shard, receipt_id=?receipt.receipt_id(), "not forwarding buffered receipt");
            Ok(ReceiptForwarding::NotForwarded(receipt))
        }
    }
```
