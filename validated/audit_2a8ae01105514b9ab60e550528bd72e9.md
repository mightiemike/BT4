### Title
`make_signer_set` floor-and-drop weight apportionment can zero out an entire PoX signer set under adversarial stake fragmentation - ([File: stackslib/src/chainstate/stacks/boot/mod.rs])

### Summary
`make_reward_set`/`make_signer_set` in `stackslib/src/chainstate/stacks/boot/mod.rs` computes each signer's weight as `stacked_amt / threshold` and drops (filters out) any entry whose weight floors to zero, with no remainder-based fallback. This is exactly the "floor-and-drop" pattern that the repo's own regression test in `stackslib/src/chainstate/nakamoto/tests/signer_set.rs` documents as buggy and which was replaced for PoX-5 by a largest-remainder ("Hare") apportionment in `pox_5_make_signer_set` (`stackslib/src/chainstate/nakamoto/signer_set.rs`).

### Finding Description
`make_signer_set` ( [1](#0-0) ) aggregates stacked amounts per signing key and computes:
```
weight = u32::try_from(stacked_amt / threshold)
if weight == 0 { drop entry }
```
with no compensating mechanism for the case where many distinct signing keys each individually fall short of `threshold` but collectively could and should command reward slots. The PoX-5 codepath (`pox_5_make_signer_set`, [2](#0-1)  ) explicitly documents and fixes this defect:
> "This avoids degenerate modes of the floor-and-drop scheme: when more than `reward_slots` distinct signers hold roughly equal stake, every base weight floors to 0, and without the leftover round the entire signer set could be dropped."

The regression test `equal_stakes_exceeding_reward_slots_are_not_all_zeroed` ( [3](#0-2) ) confirms this was a real, previously-existing bug for the old scheme, where the "entire set was dropped -- stalling the chain."

`make_signer_set` in `boot/mod.rs`, however, still uses the unfixed floor-and-drop scheme and is invoked unconditionally by `make_reward_set` ( [4](#0-3) ) for every non-PoX-5 reward-cycle calculation, i.e., it is on the live, consensus-critical path used to compute the Nakamoto signer set (`signers` field of `RewardSet::V0`, consumed by `verify_signer_signatures`/`compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs`).

### Impact Explanation
Any set of unprivileged stackers can, at reward-cycle-boundary stacking time, split their (or coordinate multiple parties') stacked STX across many distinct signing keys such that each individual signing key's `stacked_amt / threshold` floors to `0`, while the true, intended weighted total would exceed the effective reward-slot allocation. This yields an empty (or artificially truncated/asymmetric) signer set for that reward cycle relative to what the actual stake distribution implies — breaking the equality that "signer weight is proportional to the address's fraction of total stacked/locked STX for that cycle." If the resulting signer set is empty or its participant weights diverge from actual stake, block signing thresholds (`compute_voting_weight_threshold`, `verify_signer_signatures`) can no longer be met by legitimate signers, or weight is skewed toward whichever addresses happen not to be zeroed out (order-of-aggregation/ties dependent), producing a signer/weight assignment that no honest node can validate consistently with the "true" proportional-stake rule — a High-severity, minority-triggerable sortition/signer-weight divergence with a path to a temporary chain-tip/signing stall.

### Likelihood Explanation
This requires only the ability to submit multiple `stack-stx`/`stack-extend` PoX transactions with distinct signer keys during a normal stacking window — no majority stake, no privileged role, and no node-operator/admin key is needed. The condition ("more distinct signers than reward slots with individually sub-threshold stake") is realistic in cycles with many small stackers and is exactly the scenario the project's own developers flagged as a stall risk for the PoX-5 code path, but the parallel `make_signer_set` used elsewhere was not updated with the same fix.

### Recommendation
Apply the same largest-remainder ("Hare") apportionment fix used in `pox_5_make_signer_set` to `make_signer_set` in `stackslib/src/chainstate/stacks/boot/mod.rs`: after computing floor weights, distribute the leftover `reward_slots - sum(floor weights)` slots one-per-signer in descending remainder order (with deterministic tie-breaking), so that legitimate aggregate stake is never fully zeroed out purely due to fragmentation across many signing keys.

### Proof of Concept
Given `reward_slots = R` and `threshold = T` (from `get_reward_threshold_and_participation`), have `N > R` distinct stackers each stack an amount `S` such that `T/2 < S < T` (each individually floors to 0 weight under `make_signer_set`), while `N*S` in aggregate would clearly warrant `R` reward slots under any proportional scheme (mirrors the existing unit test `equal_stakes_exceeding_reward_slots_are_not_all_zeroed`, which demonstrates the identical arithmetic pattern against `pox_5_make_signer_set` before its fix). Under `make_signer_set`, every entry's `weight = stacked_amt / threshold == 0`, so all entries are filtered out via the `if weight == 0 { return None; }` branch ( [5](#0-4) ), producing an empty `signer_set` for a cycle where substantial aggregate stake was actually committed.

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );
}
