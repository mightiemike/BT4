### Title
Accrual pause acts as a silent no-op instead of blocking state-dependent operations, letting late depositors capture yield/interest that accrued while paused - ([File: mainnet/contracts/vault/v0-vault-stx.clar] and identical logic in v0-vault-sbtc.clar, v0-vault-ststx.clar, v0-vault-usdc.clar, v0-vault-usdh.clar, v0-vault-ststxbtc.clar)

### Summary
Every vault's `accrue` function is designed to advance the interest `index`/`lindex` based on elapsed time. When the vault's `accrue` pause flag is set, `accrue` does not revert — it silently passes through and returns the *old*, un-updated `index`/`lindex` as if nothing happened, while every other state-mutating entry point (`deposit`, `redeem`, `system-borrow`, `system-repay`) still executes normally against those stale values.

### Finding Description
`accrue` reads the pause flag and, if paused, returns the cached index/lindex pair without recomputing interest, without updating `last-update`, and without minting the treasury reserve fee — this is a pass-through, not a revert: [1](#0-0) 

Every value-moving public function (`deposit`, `redeem`, `system-borrow`) unconditionally calls `(try! (accrue))` first and then reads `(var-get index)` / uses conversion helpers (`convert-to-assets-preview`, `mul-div-up ... idx`) to price shares or scaled debt — these reads happen regardless of whether `accrue` actually advanced the index or merely echoed the stale one: [2](#0-1) [3](#0-2) 

The bound value is the pair `(index, lindex)` cached in the vault's data vars. The event that should invalidate/refresh it is the passage of block time (`stacks-block-time`), which normally drives `next-index` / `next-liquidity-index`. While the `accrue` pause flag is set, this invalidation is deliberately skipped, but the flag does not block `deposit`/`redeem`/`system-borrow`/`system-repay` from running — they proceed using the frozen `index`/`lindex` as if it were current. When the pause is later lifted, the very next call to `accrue` computes `next-index`/`next-liquidity-index` from `last-update`, which was never advanced during the pause, so the entire skipped interest period is applied in one retroactive jump that benefits every share holder present at that moment — including anyone who deposited seconds before the pause was lifted (or during the pause) and therefore did not bear the risk/time for that interest period.

### Impact Explanation
This lets a user deposit at the artificially low (frozen) `index`/`lindex` while the pause is active or right before it is lifted, then receive a proportional share of interest that legitimately accrued to depositors who held their position throughout the paused window. This is a direct diversion of unclaimed yield away from long-standing depositors toward an opportunistic late depositor — falling under "theft of unclaimed yield," a High severity impact.

### Likelihood Explanation
The `accrue` pause is a normal operational control (not a DAO-compromise scenario), and the exploit requires no privileged access — any address can call `deposit` while paused or immediately track the unpause transaction to be first through `accrue` afterward. The only precondition is that the DAO has activated the accrual pause for maintenance/incident response, which is an expected, intended operational state, making this readily reachable whenever that control is used.

### Recommendation
When `accrue` is paused, either (a) also pause `deposit`/`redeem`/`system-borrow`/`system-repay` (revert them with `ERR-PAUSED`) so no value-moving operation can occur against a stale index, or (b) still advance `last-update` to the current `stacks-block-time` on pause activation/deactivation so no backdated interest window can be captured by a newly entering depositor.

### Proof of Concept
1. DAO/operator sets the vault's `accrue` pause flag to `true` (e.g., `vault-stx` pause-states).
2. Time passes across one or more blocks; `accrue` is called (directly or via `deposit`/`redeem`/`system-borrow`) and returns the frozen `{index, lindex}` without updating `last-update` — confirmed by the pass-through branch: [4](#0-3) 
3. Shortly before (or right as) the pause is lifted, an attacker calls `deposit`, which invokes `accrue` (still returning stale values while paused) and then prices shares via `convert-to-assets-preview`/share-minting logic using that stale index: [5](#0-4) 
4. The pause is lifted; the next transaction that calls `accrue` computes `next-index`/`next-liquidity-index` from the old `last-update` timestamp, applying the entire deferred interest in one step and updating `index`/`lindex`/`last-update` together.
5. The attacker's freshly minted shares (from step 3) now participate in the retroactively applied interest jump, capturing yield for a period during which their capital was not actually deployed — diverting yield from depositors who were present throughout the paused window.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
