### Title
Reverted Cairo0 (deprecated) class declarations remain executable from the stale global class cache - ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` re-validates cache hits against current chain state only for Cairo1 classes, explicitly to guard against classes that were declared in a reverted block. Cairo0 (deprecated) classes are exempt from this re-validation, so once a Cairo0 class hash is cached it can keep being executed even after the declaration that put it there has been reverted from storage.

### Finding Description
`get_compiled_from_class_manager` reads from the long-lived, process-scoped `ContractClassManager`/`RawClassCache`. On a cache hit it distinguishes the two cases: [1](#0-0) 

For `RunnableCompiledClass::V0` (Cairo0/"deprecated") it does nothing (`{}`) and returns the cached class directly. For any other variant (Cairo1), it calls `self.state_reader.is_declared(class_hash)` and rejects the class with `StateError::UndeclaredClassHash` if the current state no longer considers it declared. The accompanying comment states the exact reason: *"the Cairo1 class is cached; verify it is declared, since existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)."*

Crucially, `FetchCompiledClasses::is_declared` is documented as only meaningful for Cairo1: *"Returns whether the given class hash corresponds to a declared Cairo 1 class. Cairo 0 classes always return `false`."* [2](#0-1) 

Because `is_declared` cannot express "is this Cairo0 class still declared", the code simply skips validation for V0 classes rather than using an equivalent storage check (e.g. re-checking `get_deprecated_class_definition_at`). Meanwhile, block reverts do remove Cairo0 declarations from persistent storage: [3](#0-2) 

and the batcher's revert path (`Batcher::revert_block`) drives exactly this storage revert during normal block-building operation, not only via a malicious operator: [4](#0-3) 

The `ContractClassManager`'s class cache (`RawClassCache`/`GlobalContractCache`) is not cleared per-block and is not wired into the revert flow, so a Cairo0 class hash that was cached while its declaration was live remains servable from cache after the corresponding block (and its declaration) has been reverted.

### Impact Explanation
Once a block containing a Cairo0 `DECLARE` (or a class made available through `add_deprecated_class` in the class manager path) is reverted, the class is removed from the canonical `deprecated_declared_classes` table, i.e., it should no longer be considered part of state. Nevertheless, the batcher/blockifier process that cached it can continue to serve it as a valid, executable class to any later transaction referencing that class hash (e.g., during constructor execution/deploy flows or subsequent contract-class lookups), because the V0 branch never re-checks storage. This produces block execution/state transitions based on a class the canonical state no longer recognizes as declared. Any independent re-execution (a freshly-synced full node, the Starknet OS re-execution, or a second sequencer instance without the stale cache entry) reading the same state diff would instead hit the missing deprecated-class table entry and treat the class hash as `UndeclaredClassHash`, causing an execution/consensus divergence between the two: this is precisely the "delisted item still usable" bug class from the reference report, mapped onto declared classes instead of collateral tokens.

### Likelihood Explanation
Reverts of built (not yet finalized) blocks are part of ordinary batcher operation and are not restricted to a malicious operator or attacker — they can be triggered by ordinary consensus/liveness conditions. An attacker only needs to (1) get a Cairo0 declare transaction included in a block that ends up reverted (or ride an existing organic revert), and (2) submit a follow-up transaction referencing the same class hash before the process cache entry is evicted (cache sizes are typically large, and the LRU/global cache persists across block heights within the same batcher process lifetime). Both steps are reachable through unprivileged transaction submission.

### Recommendation
Treat cached Cairo0/`V0` classes the same as Cairo1 classes on cache hit: re-validate against the current authoritative declared-classes state (e.g., check `deprecated_declared_classes`/`get_deprecated_class_definition_at` presence) before returning them, instead of unconditionally trusting the cache. Alternatively, ensure `ContractClassManager`'s cache is invalidated for any class hash affected by a block revert as part of `revert_block`/`revert_state_diff`.

### Proof of Concept
1. Submit a `DECLARE` (Cairo0/deprecated) transaction with class hash `C`; it is included in block `N` and the sequencer's `ContractClassManager` caches `C` as `RunnableCompiledClass::V0`.
2. Block `N` is reverted (via `Batcher::revert_block`, e.g. due to a consensus/liveness issue), which deletes `C` from the `deprecated_declared_classes` table (`delete_deprecated_declared_classes`).
3. In a later block, submit any transaction that triggers `state.get_compiled_class(C)` (e.g. a deploy referencing class hash `C`) without re-declaring `C`.
4. `get_compiled_from_class_manager` hits the cache, matches the `V0` branch, performs no declared-state check, and returns the stale compiled class — execution proceeds as if `C` were declared.
5. An independent re-execution/full node reading the same (reverted) state finds no entry for `C` in `deprecated_declared_classes` and returns `StateError::UndeclaredClassHash`, diverging from the sequencer's committed result.

    // This function will panic if there is a storage failure to revert the block.
    pub async fn revert_block(&mut self, input: RevertBlockInput) -> BatcherResult<()> {
        info!("Reverting block at height {}.", input.height);
        let height = self.get_height_from_storage()?.prev().ok_or(
            BatcherError::StorageHeightMarkerMismatch {
                marker_height: BlockNumber(0),
                requested_height: input.height,
            },
        )?;

        if height != input.height {
            return Err(BatcherError::StorageHeightMarkerMismatch {
                marker_height: height.unchecked_next(),
                requested_height: input.height,
            });
        }

        if let Some(height) = self.active_height {
            info!("Aborting all work on height {} due to a revert request.", height);
            self.abort_active_height().await;
        }

        // Wait for the revert commitment to be completed before reverting the storage.
        self.revert_commitment(height).await;

        self.storage_writer.revert_block(height);
        BUILDING_HEIGHT.decrement(1);
        GLOBAL_ROOT_HEIGHT.decrement(1);
        REVERTED_BLOCKS.increment(1);
        Ok(())
    }
