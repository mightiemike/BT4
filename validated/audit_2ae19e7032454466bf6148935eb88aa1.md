### Title
Unbounded gzip decompression in `decompress_program` allows memory-exhaustion DoS via `estimateFee`/`simulateTransactions` on a Declare V1 transaction - (File: crates/apollo_rpc/src/v0_8/api/mod.rs)

### Summary
`decompress_program` in `apollo_rpc` decompresses a base64-encoded, attacker-supplied gzip blob into an unbounded `Vec<u8>` with no size cap, mirroring the adm-zip bug class (CWE-400/CWE-789): a small compressed payload can expand to an enormous decompressed buffer before any validation occurs.

### Finding Description
`decompress_program` reads the entire gzip stream with `decoder.read_to_end(&mut decompressed)` into a `Vec::new()` that grows without any size limit, and the function itself carries a `TODO(dan): add time and size limits` acknowledging the gap: [1](#0-0) 

This is reachable from an unprivileged JSON-RPC caller through the `BroadcastedDeclareTransaction::V1` → `ExecutableTransactionInput` conversion, which calls `user_deprecated_contract_class_to_sn_api`, which in turn calls `decompress_program` on `value.compressed_program`: [2](#0-1) [3](#0-2) 

This conversion is invoked directly inside `estimate_fee`, an RPC method callable by anyone with no fee payment, signature verification, or mempool admission required, before any execution/resource accounting happens: [4](#0-3) 

This is in sharp contrast to every other decompression path found in the codebase, all of which are explicitly bounded:
- Gateway class validation uses `decode_and_decompress_with_size_limit`, which caps the decompressed size and errors out via `SizeLimitExceeded`: [5](#0-4) , used in `crates/apollo_http_server/src/deprecated_gateway_transaction.rs:289-301` and `crates/apollo_protobuf/src/converters/class.rs:130-138`.
- Storage-layer decompression is capped at `MAX_DECOMPRESSED_SIZE` (256 MB): [6](#0-5) 

`decompress_program` has none of these protections.

### Impact Explanation
A single `starknet_estimateFee` (or `starknet_simulateTransactions`, which uses the same `BroadcastedTransaction`→`ExecutableTransactionInput` conversion path) request containing a `BroadcastedDeclareV1Transaction` with a crafted gzip "bomb" as `compressed_program` can force the RPC-serving node to allocate an arbitrarily large `Vec<u8>` in-process, synchronously, before any resource/fee checks apply. Given typical gzip decompression ratios (often >100:1, and much higher for pathological inputs), a request within normal HTTP body-size limits can trigger multi-gigabyte allocations, crashing or OOM-killing the serving process. If this RPC/full-node process is co-located with or feeds into sequencer components (e.g., a full node acting as a fee-estimation/simulation service for the sequencer), an attacker can repeatedly crash the service, denying users the ability to get fee estimates/simulate transactions — a service-availability impact consistent with the External Report's classification (CWE-400/CWE-789, High severity).

### Likelihood Explanation
Likelihood is high for any deployment exposing the `estimateFee`/`simulateTransactions` JSON-RPC methods to untrusted clients (a very common, unauthenticated, public-facing configuration): the attacker needs no funds, no valid signature (max_fee/signature are not verified before this decompression happens), and no prior mempool admission — a single crafted request suffices, matching the "single submitted RPC call from an unprivileged sender" reachability bar.

### Recommendation
Replace the unbounded `decoder.read_to_end(&mut decompressed, ...)` in `decompress_program` with a size-limited read (e.g., `Read::take(max_size)` plus a post-read length check, following the same pattern already used in `starknet_api::compression_utils::decompress_with_size_limit`), and reject/err out (analogous to `CompressionError::SizeLimitExceeded`) rather than allocating unbounded memory. Apply the same fixed maximum program size used elsewhere (`DEFAULT_MAX_SIERRA_PROGRAM_SIZE` / `MAX_CAIRO0_PROGRAM_SIZE`) for consistency.

### Proof of Concept
1. Craft a gzip-compressed JSON `Program` payload that is small when compressed (e.g., a few hundred KB of highly repetitive/zero bytes) but decompresses to several GB.
2. Base64-encode it and place it as `compressed_program` in a `DeprecatedContractClass` field.
3. Send a JSON-RPC `starknet_estimateFee` (or `starknet_simulateTransactions`) request with a `BroadcastedDeclareTransaction` of version `0x1` (`BroadcastedDeclareV1Transaction`) whose `contract_class.program` is the crafted payload.
4. Server calls `estimate_fee` → `tx.try_into()` → `user_deprecated_contract_class_to_sn_api` → `decompress_program`, which decompresses the entire payload into memory with no limit, exhausting available memory before any fee/signature/nonce checks reject the malformed/unfunded transaction. /// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}

pub(crate) const MAX_DECOMPRESSED_SIZE: usize = 1 << 28; // 256 MB
// The compression level to use. Higher levels are slower but compress better.
const COMPRESSION_LEVEL: i32 = zstd::DEFAULT_COMPRESSION_LEVEL;

/// Returns the compressed data in a vector.
///
/// # Arguments
/// * data - bytes to compress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn compress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::compress(data, COMPRESSION_LEVEL)
}

/// Serialized and then compress object.
///
/// # Arguments
/// * object - the object to serialize and compress.
///
/// # Errors
/// Returns [`StorageSerdeError`] if any error is encountered in the serialization or compression.
pub fn serialize_and_compress(object: &impl StorageSerde) -> Result<Vec<u8>, StorageSerdeError> {
    let mut buf = Vec::new();
    object.serialize_into(&mut buf)?;
    Ok(compress(buf.as_slice())?)
}

/// Decompress data and returns it as bytes in a vector.

/// # Arguments

///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.

    zstd::bulk::decompress(data, MAX_DECOMPRESSED_SIZE)
