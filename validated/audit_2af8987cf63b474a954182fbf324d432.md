## Analysis

The reported bug class (a state-mutating function that lacks an authorization/validity check that another privileged code path enforces) has a direct analog in the Starknet OS's implementation of the `replace_class` syscall.

In the actual sequencer execution path (blockifier), replacing a contract's class hash requires the target class to already be declared: [1](#0-0) . This same enforcement exists in the syscall request/response definitions used by the native and CASM syscall handlers.

However, in the Starknet OS's own Cairo re-execution of the same syscall — used to independently verify/prove the block — this check is explicitly missing, with a TODO acknowledging it: [2](#0-1) . The deprecated (Cairo0) syscall path has the identical omission, without even a TODO comment: [3](#0-2) . A repo-wide search confirms there is no `is_declared`/`assert_class_is_declared` check anywhere else in the OS Cairo sources.

### Title
Starknet OS `replace_class` syscall omits declared-class verification present in blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The blockifier's `replace_class` syscall handler requires the target `class_hash` to correspond to an already-declared compiled class before updating a contract's class pointer (`get_compiled_class` is called and must succeed) [4](#0-3) . The Starknet OS's own Cairo implementation of the same syscall (`execute_replace_class`, both the current and deprecated variants) performs no such check — it unconditionally overwrites `state_entry.class_hash` with the caller-supplied value [5](#0-4) [6](#0-5) .

### Finding Description
`replace_class` is a syscall directly reachable by any contract invoked within a normal user transaction — it lets a contract change its own class hash. The intended invariant, enforced in the actual (blockifier) execution client, is that the new class hash must reference an already-declared class; otherwise the call fails. The Starknet OS is meant to independently re-execute/verify every transaction in a block to produce a proof that the committed state transition is correct. Because the OS Cairo implementation of `execute_replace_class` lacks the equivalent "class is declared" assertion — a gap explicitly flagged by the developers' own `TODO(Yoni, 1/1/2026)` comment — the OS accepts and commits a class-hash overwrite for any felt value the caller supplies, including class hashes that were never declared on-chain. This is the sequencer-side analog of the reported `mintRebalancer`/`burnRebalancer` bug: a state-mutating operation that omits a validation/authorization check that a parallel, "trusted" execution path enforces.

### Impact Explanation
A missing invariant check inside the component responsible for producing the OS's re-execution trace and state commitment can lead to accepting a `class_hash` value in `contract_state_changes` that was never validated against any declared class. If this divergence is not caught elsewhere before the state/commitment tree is built, it can result in a contract address being committed with a class hash that does not correspond to a real declared class, i.e. an inconsistency between what the sequencer's canonical (blockifier) execution allows and what the OS is willing to commit to — undermining the soundness guarantee that the OS proof is supposed to provide over the block's state transition.

### Likelihood Explanation
The syscall is reachable from any unprivileged transaction sender simply by having a contract invoke `replace_class` with an arbitrary felt as the class hash; no special privilege is required to trigger the code path with the missing check.

### Recommendation
Add the equivalent of the blockifier's declared-class check to both OS `execute_replace_class` implementations (current and deprecated syscall variants) — e.g., verify membership of `class_hash` in the set of declared/compiled classes (via `contract_class_changes` or the analogous class-hash commitment lookup) before writing the new `StateEntry`, mirroring `syscall_handler.state.get_compiled_class(request.class_hash)?` from the blockifier implementation.

### Proof of Concept
1. Deploy a contract that, in one of its external entry points, invokes the `replace_class` syscall with a `class_hash` value that has never been declared.
2. Submit a transaction invoking that entry point.
3. In blockifier's real execution, this call would fail validation against the declared-class registry; however, tracing through the OS's Cairo implementation shows `execute_replace_class` in `syscall_impls.cairo` (and the deprecated variant) performs the `dict_update` on `contract_state_changes` unconditionally, with no lookup or assertion verifying `class_hash` was declared — confirmed by the absence of any `is_declared`/class-registry check anywhere in the OS Cairo sources and the explicit TODO at `syscall_impls.cairo:902` acknowledging the gap.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
