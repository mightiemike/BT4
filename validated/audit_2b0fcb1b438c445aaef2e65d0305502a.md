### Title
Declare-authorization circuit breaker (`block_declare` / `authorized_declarer_accounts`) is enforced only at gateway ingestion, not in the block-building/execution path - ([File: crates/apollo_gateway/src/gateway.rs])

### Summary
`GatewayConfig::is_authorized_declarer` and `GatewayStaticConfig::block_declare` are meant to act as an admin-controlled circuit breaker that blocks declare transactions globally or restricts them to an allow-list of accounts. This gate is checked exactly once, inside `check_declare_permissions`, which only runs from the gateway's `add_tx_inner` entry point at the moment a transaction is first submitted. Nothing downstream — the mempool, the batcher's block builder, or the blockifier's declare execution (`try_declare`) — re-checks this flag before mutating state. This is the same bug class as the WLFI report: an "enabled/disabled" admin flag is enforced only where an entity is first admitted, not on the actual state-mutating operation that consumes it later.

### Finding Description
`check_declare_permissions` is called only from `add_tx_inner` in `crates/apollo_gateway/src/gateway.rs`: [1](#0-0) 

```
if let RpcTransaction::Declare(ref declare_tx) = tx {
    if let Err(e) = self.check_declare_permissions(declare_tx) {
        ...
    }
}
```

Once a Declare transaction passes this check it is handed to the mempool: [2](#0-1) 

The actual declare state mutation, `try_declare`, is invoked later from the batcher's block builder / blockifier execution path, and it checks only whether the class hash is already declared — nothing about `block_declare` or `authorized_declarer_accounts`: [3](#0-2) [4](#0-3) 

Likewise, the stateful validator used for re-validation (`crates/apollo_gateway/src/stateful_transaction_validator.rs`) and the Starknet OS declare-execution flow (`transaction_impls.cairo::execute_declare_transaction`) never read the gateway's declarer-authorization config; the OS declares a class hash unconditionally once its `__validate_declare__` succeeds: [5](#0-4) 

Because `block_declare` / `authorized_declarer_accounts` live in `GatewayStaticConfig`, an operator toggling this circuit breaker (e.g., to stop an account flooding the Sierra compiler, or to lock down declares during an incident) only affects transactions that have not yet reached the gateway's `add_tx_inner`. Any Declare transaction that has already been admitted into the mempool before the restriction takes effect is never re-checked: the batcher pulls it via `get_txs`, executes it through `try_declare`, and the class is permanently committed to state — with no code path anywhere between mempool admission and state commitment enforcing the declarer allow-list or the global block.

### Impact Explanation
The declare-authorization gate does not do what its name and configuration description ("Authorized declarer accounts. If set, only these accounts can declare new contracts"; "If true, the gateway will block declare transactions") imply. An unauthorized account whose Declare transaction is already resident in the mempool at the moment the admin restricts declares will still have that class permanently and irreversibly committed to state via ordinary block production — an unauthorized account action that the configured control was specifically meant to prevent. This is a state-commitment-affecting bypass of an explicit access-control mechanism, not merely a resource/DoS issue.

### Likelihood Explanation
This requires no privileged capability from the attacker: any account can submit a Declare transaction through the normal `add_tx` RPC path. The only external condition is that the operator changes `block_declare`/`authorized_declarer_accounts` after the transaction has already been admitted to the mempool — a plausible incident-response or governance action, exactly the same trigger condition as the original `ownerSetCategoryEnabled` report (an admin toggling a flag expecting it to immediately affect in-flight/ongoing state). Because the gate is a `static_config` value, it typically changes only via a gateway restart with a new config, but the batcher/blockifier component that ultimately executes the declare is a separate process that never consults this config at all, so the bypass window exists deterministically, not merely as a race.

### Recommendation
Enforce `block_declare` and `is_authorized_declarer` at the point of state mutation, not only at ingestion — e.g., inside `try_declare` in `crates/blockifier/src/transaction/transactions.rs`, or by threading the same authorization decision into the batcher/block-builder's tx-inclusion path, so a config change is honored for every Declare transaction, including ones already resident in the mempool. Alternatively, invalidate/evict mempool-resident Declare transactions from disallowed senders whenever `authorized_declarer_accounts`/`block_declare` changes.

### Proof of Concept
1. Operator starts the sequencer with `gateway_config.static_config.block_declare = false` and no `authorized_declarer_accounts` restriction.
2. Attacker (account `A`, otherwise unprivileged) submits a Declare(V3) transaction; it passes `check_declare_permissions` in `crates/apollo_gateway/src/gateway.rs:228-233` and is forwarded to the mempool.
3. Before the transaction is picked into a block, the operator restarts the gateway with `block_declare = true` (or `authorized_declarer_accounts` excluding `A`) as an incident-response measure.
4. The batcher's block builder still pulls the pending Declare transaction from the mempool (`crates/apollo_batcher/src/block_builder.rs`) and executes it via `DeclareTransaction::run_execute` → `try_declare` (`crates/blockifier/src/transaction/transactions.rs:155-193, 386-408`), which contains no check of `block_declare`/`authorized_declarer_accounts`.
5. The class is declared and committed to state despite the operator's restriction, demonstrating that the "circuit breaker" has no effect on transactions already admitted before the restriction was applied.

    fn check_declare_permissions(
        &self,
        declare_tx: &RpcDeclareTransaction,
    ) -> Result<(), StarknetError> {
        // TODO(noamsp): Return same error as in Python gateway.
        if self.config.static_config.block_declare {
            return Err(StarknetError {
                code: StarknetErrorCode::UnknownErrorCode(

                ),
                message: "Transaction type is temporarily blocked.".to_string(),

        let RpcDeclareTransaction::V3(declare_v3_tx) = declare_tx;

                code: StarknetErrorCode::KnownErrorCode(
                    KnownStarknetErrorCode::UnauthorizedDeclare,
                ),
                message: format!(
                    "Account address {} is not allowed to declare contracts.",
                    &declare_v3_tx.sender_address
                ),
            });
        }
        Ok(())
    }

    fn run_execute(
        &self,
        state: &mut S,
        context: &mut EntryPointExecutionContext,
        _remaining_gas: &mut u64,
    ) -> TransactionExecutionResult<Option<CallInfo>> {
        let class_hash = self.class_hash();
        match &self.tx {
            starknet_api::transaction::DeclareTransaction::V0(_)
            | starknet_api::transaction::DeclareTransaction::V1(_) => {
                if context.tx_context.block_context.versioned_constants.disable_cairo0_redeclaration
                {
                    try_declare(self, state, class_hash, None)?
                } else {
                    // We allow redeclaration of the class for backward compatibility.
                    // In the past, we allowed redeclaration of Cairo 0 contracts since there was
                    // no class commitment (so no need to check if the class is already declared).
                    state.set_contract_class(class_hash, self.contract_class().try_into()?)?;
                }
            }
            starknet_api::transaction::DeclareTransaction::V2(DeclareTransactionV2 {
                compiled_class_hash,
                ..
            })

                compiled_class_hash,
                ..
            }) => {

                    self.check_compile_class_hash_v2_declaration()?
                }
                try_declare(self, state, class_hash, Some(*compiled_class_hash))?
            }
        }
        Ok(None)
    }

/// specified class hash.
fn try_declare<S: State>(
    tx: &DeclareTransaction,
    state: &mut S,
    class_hash: ClassHash,
    compiled_class_hash: Option<CompiledClassHash>,
) -> TransactionExecutionResult<()> {
    match state.get_compiled_class(class_hash) {
        Err(StateError::UndeclaredClassHash(_)) => {
            // Class is undeclared; declare it.
            state.set_contract_class(class_hash, tx.contract_class().try_into()?)?;
            if let Some(compiled_class_hash) = compiled_class_hash {
                state.set_compiled_class_hash(class_hash, compiled_class_hash)?;
            }
            Ok(())
        }
        Err(error) => Err(error)?,
        Ok(_) => {
            // Class is already declared, cannot redeclare.
            Err(TransactionExecutionError::DeclareTransactionError { class_hash })
        }
    }
}
