### Title
`coll-final` dust-rounding fallback lets `liquidate` seize the entire remaining collateral without being capped to the debt-justified amount - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`liquidate()` computes a debt-justified collateral amount (`coll-final-raw`), but then overwrites it with the borrower's *entire* remaining collateral balance (`user-coll-balance`) whenever a "dust" remainder check evaluates to zero — with no upper bound comparing that fallback value against `coll-final-raw`/`coll-expected`. This mirrors the reported `settledPrice = totalContributions` fallback that skipped the `maximumPrice` cap.

### Finding Description
In the debt/collateral pipeline, `coll-final-raw` is the amount of collateral properly bounded by the liquidation-factor math (`scale-debt-for-liquidation`), capped at the user's balance and proportionally reduced if debt was capped: [1](#0-0) 

`liquidate()` then computes `coll-remaining = user-coll-balance - coll-final-raw` and, if that remainder is non-zero, derives `remaining-debt-to-repay` from it via a full USD→token→scaled round-trip conversion (multiple `mul-div-down`/`mul-div-up` roundings): [2](#0-1) 

The final assignment is the analog of the reported bug:
```
(coll-final (if (is-eq remaining-debt-to-repay u0) user-coll-balance coll-final-raw))
```
Just as `settledPrice_ = callValue == 0 ? totalContributions : callValue` unconditionally substitutes `totalContributions` for the checked value when `callValue` is 0 — ignoring `maximumPrice` — this line unconditionally substitutes `user-coll-balance` (the full untouched balance) for the properly bounded `coll-final-raw` whenever the *rounded* remaining-debt-to-repay estimate rounds down to `u0`. There is no comparison of `user-coll-balance` against `coll-final-raw`, `coll-expected`, or any bound derived from `max-debt-usd`/`liq-penalty` before this substitution is used downstream.

Because `remaining-debt-to-repay` is computed through several successive `mul-div-down` roundings (`rem-coll-usd`, `rem-debt-usd`, `rem-debt-tokens`, `rem-scaled`) before a final `mul-div-up`, it is possible for a genuinely non-trivial `coll-remaining` (i.e., the leftover collateral above what the liquidation-factor math justified) to round down to `u0` tokens of debt at some point in the chain, particularly for low-decimal or low-price debt assets, or when `coll-remaining` is small relative to `coll-price`/penalty scaling. When that happens, the code treats the position as "no residual collateral worth chasing" and instead of leaving `coll-final-raw` (the correctly bounded amount) in place, it grants the liquidator the *entire* `user-coll-balance` — which can exceed the debt-justified `coll-expected`/`coll-final-raw` by the full `coll-remaining` amount.

### Impact Explanation
This directly increases the collateral seized by a liquidator beyond what the graduated liquidation formula (`calc-liquidation-params`, `calc-liq-collateral-repay`) determined was justified for the specific `debt-amount` supplied, while `debt-to-repay` remains bounded by `scaled-to-remove` derived from `coll-final-raw`, not `coll-final`. This is a mismatch between collateral seized and debt repaid, i.e. the borrower is stripped of collateral beyond the debt actually paid down — a temporary/permanent freezing or loss of the borrower's remaining collateral, landing in the in-scope "temporary freezing of funds" / theft-adjacent impact class.

### Likelihood Explanation
Triggering requires only a normal `liquidate` call where the rounding chain in lines 1477-1485 happens to produce `remaining-debt-to-repay == u0` while `coll-remaining > u0` — a single-transaction condition dependent on asset decimals/price/penalty values rather than any multi-party interference, matching the reachable analog class described in the rules (a rounding/fallback value not checked against its bound before use).

### Recommendation
Before using `user-coll-balance` as `coll-final`, assert or clamp it against the debt-justified bound, e.g.:
```
(coll-final (if (is-eq remaining-debt-to-repay u0)
                (min user-coll-balance (some-justified-upper-bound coll-final-raw coll-remaining))
                coll-final-raw))
```
or simply do not substitute the full balance at all — treat a zero `remaining-debt-to-repay` as "leave the dust `coll-remaining` with the borrower" rather than "grant it all to the liquidator", i.e. keep `coll-final = coll-final-raw` regardless of the rounding outcome.

### Proof of Concept
1. Borrower has a position where `coll-aid`'s asset has few decimals / low price such that a small `coll-remaining` produces `rem-debt-tokens` (or an intermediate `mul-div-down`) that rounds to `0`.
2. Liquidator calls `liquidate(borrower, collateral-ft, debt-ft, debt-amount, min-collateral-expected, none, none)` with `debt-amount` sized so that `debt-actual`/`coll-actual` computed by `process-debt-asset`/`process-collateral-asset` yields `coll-final-raw < user-coll-balance`.
3. `coll-remaining = user-coll-balance - coll-final-raw` is non-zero but the successive roundings in the `remaining-debt-to-repay` `let` (lines 1479-1485) cause the final value to equal `u0`.
4. `coll-final` is set to `user-coll-balance` (line 1486) instead of `coll-final-raw`.
5. `collateral-remove` (line ~1506-1512) transfers `coll-final = user-coll-balance` to the liquidator, while `debt-to-repay` used in `vault-system-repay` (line 1496) is still only the amount justified by `coll-final-raw` — the liquidator receives collateral in excess of the debt-justified amount, with only the unrelated `min-collateral-expected` slippage check (line 1493) as an incidental (and attacker-controllable, since the liquidator supplies it) guard.

```text
;; Converts to scaled units, caps at current debt, calculates final collateral
;; Returns: { scaled-to-remove: uint, debt-to-repay: uint, coll-final: uint }
(define-private (scale-debt-for-liquidation
  (debt-final uint)
  (coll-actual uint)
  (curr-scaled uint)
  (asset-id uint))
  (let (;; convert debt amount to scaled units for storage
        (borrow-index (get index (unwrap-panic (get-cached-indexes asset-id))))
        (scaled-debt (mul-div-down debt-final INDEX-PRECISION borrow-index))
        ;; cap at current debt (prevent over-repayment)
        (scaled-to-remove (if (> scaled-debt curr-scaled) curr-scaled scaled-debt))
        (debt-to-repay (mul-div-up scaled-to-remove borrow-index INDEX-PRECISION))
        ;; If debt was capped, scale collateral proportionally
        (coll-final (if (< scaled-to-remove scaled-debt)
                        (mul-div-down coll-actual scaled-to-remove scaled-debt)
                        coll-actual)))
    {
      scaled-to-remove: scaled-to-remove,
      debt-to-repay: debt-to-repay,
      coll-final: coll-final
    }))
```
