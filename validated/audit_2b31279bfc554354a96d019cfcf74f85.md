Based on my research, I've found a valid native analog to the reported vault issue. The bug-class here is "an unvalidated, single-source price feed used to authorize a fund-moving action without any cross-check against manipulation," and Push Chain has a concrete instance of this in its Uniswap V3-based auto-swap paths.

### Title
Same-block Uniswap V3 spot-quote used as slippage floor for module-originated auto-swaps enables sandwich-style value extraction from gas deposit/refund flows - (File: x/uexecutor/keeper/evm.go, execute_inbound_gas.go, execute_inbound_gas_and_payload.go, outbound.go)

### Summary
The original report's root cause is that a fund-moving action (rebalancing) is authorized using a value ("nominal") that comes from a single, unchecked source with no validation that it reflects real value, letting an attacker who controls that source drain the vault. Push Chain has a structurally identical pattern: the module computes `minPCOut` (the slippage floor for its own `depositPRC20WithAutoSwap` / `refundUnusedGas(withSwap=true)` calls) from a live on-chain Uniswap V3 `QuoterV2.quoteExactInputSingle` spot price fetched in the *same* keeper call that immediately performs the swap, with only a flat 5% tolerance and no TWAP/staleness check.

### Finding Description
`GetSwapQuote` [1](#0-0)  reads the instantaneous quote from the Uniswap V3 `QuoterV2` contract. This quote is used to compute `minPCOut` with a fixed 5% haircut in three places that all execute the swap in the very same transaction/block as the quote:

- Gas inbound auto-swap: [2](#0-1) 
- Gas-and-payload auto-swap: [3](#0-2) 
- Excess-gas refund swap: [4](#0-3) 

The actual swap is then executed by module-originated `DerivedEVMCall`s (`CallPRC20DepositAutoSwap`, `CallUniversalCoreRefundUnusedGas` with `withSwap=true`) [5](#0-4) . Because the quote and the swap both read/execute against the same live pool state and there is no TWAP, oracle cross-check, or minimum-liquidity guard, an unprivileged attacker who can also trade against the underlying Uniswap V3 pool (a normal, permissionless AMM action, not a privileged one) can manipulate the pool price immediately before the module's swap is processed and reverse it immediately after — a standard sandwich. Since `minPCOut` is derived from the manipulated quote itself, the 5% band moves with the manipulated price and provides no real protection.

This is a native analog of the report's core defect: a value that gates a fund-moving action (`nominals` in the report; `minPCOut`/quote here) is sourced from something the attacker can control or influence in the same execution window, with no independent validation that it reflects real value.

### Impact Explanation
Both the deposit-auto-swap path (triggered by ordinary user `GAS`/`GAS_AND_PAYLOAD` inbounds) and the refund-swap path (triggered automatically on outbound success/failure once UVs finalize the observation) move real value between the protocol's PRC20 gas token and native PC/WPC. Manipulating the pool price around these module-triggered swaps lets an attacker extract value from the protocol-held liquidity or from the swap output intended for another user's deposit/refund, i.e., draining protocol/user-controlled funds through the swap leg of universal execution — squarely in scope ("corruption of PRC20 or native asset accounting... draining of user or protocol-controlled funds").

### Likelihood Explanation
Triggering the vulnerable code path requires only ordinary, permissionless actions: submitting a `GAS`/`GAS_AND_PAYLOAD` inbound (or waiting for any outbound's gas refund to fire) and trading against the same Uniswap V3 pool the module uses. No privileged role, validator collusion, or admin key is needed — only capital and normal DEX access, which any external user has. The main variable affecting exploitability is pool depth/liquidity relative to the swap amount and MEV/ordering conditions on Push Chain, which determine how profitably the sandwich can be executed.

### Recommendation
Do not derive the slippage floor purely from a same-block spot quote. Use a TWAP-based quote (or an external oracle) for `minPCOut`, widen protection with circuit breakers on maximum price deviation between the last observed price and the current quote, and/or route these protocol swaps through pools/mechanisms resistant to same-block manipulation (e.g., commit-reveal, batched execution, or a dedicated oracle feed as the audit for the original vault issue also recommended).

### Proof of Concept
1. Attacker identifies the WPC/gasToken Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`.
2. Attacker submits a large swap into that pool to skew the spot price just before their own (or a victim's) `GAS` inbound is processed by `ExecuteInboundGas`, or before a large outbound's `applyGasRefund` fires.
3. The module calls `GetSwapQuote` [1](#0-0)  against the now-skewed pool, computes `minPCOut = quote * 95%` [6](#0-5) , and immediately executes `depositPRC20WithAutoSwap`/`refundUnusedGas` against the same manipulated pool.
4. Attacker reverses their initial swap (arbitrage back), pocketing the difference extracted from the module's swap, which came from protocol/user funds.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// CallUniversalCoreRefundUnusedGas calls refundUnusedGas on UniversalCore to return excess gas fee
// to the recipient. withSwap=true swaps the gas token back to PC; withSwap=false deposits PRC20 directly.
func (k Keeper) CallUniversalCoreRefundUnusedGas(
	ctx sdk.Context,
	gasToken common.Address,
	amount *big.Int,
	recipient common.Address,
	withSwap bool,
	fee *big.Int,
	minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	// fee is uint24 in Solidity — pass as *big.Int (go-ethereum ABI packs non-standard widths as *big.Int)
	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress,
		handlerAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"refundUnusedGas",
		gasToken,
		amount,
		recipient,
		withSwap,
		fee,
		minPCOut,
	)
}
