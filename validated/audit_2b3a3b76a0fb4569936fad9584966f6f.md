## Analog Found

### Title
`EpochManager::minimum_stake` divides a seat price that can be zero, silently disabling the `InsufficientStake` guard on the `Stake` action - (File: `chain/epoch-manager/src/lib.rs`)

### Summary
The reported Polynomial bug is a class of "unchecked oracle/derived-price = 0 silently defeats a downstream security check." The direct nearcore analog is `EpochManager::minimum_stake`, which derives the minimum allowed stake from `epoch_info.seat_price()` without validating that the seat price is non-zero, and `action_stake` then uses that value to gate the `InsufficientStake` rejection.

### Finding Description
`EpochManager::minimum_stake` computes the floor stake required to submit a valid `Stake` action purely as `seat_price / minimum_stake_divisor`, with no check that `seat_price` is non-zero: [1](#0-0) 

`seat_price` is `EpochInfo`'s selection threshold, produced by `select_validators` as the minimum of the block-producer/chunk-producer/chunk-validator role thresholds: [2](#0-1) 

When a role's seat is not fully filled, the threshold is computed from the *total* stake of the role's proposal set via `min_stake_ratio * total_stake / (1 - min_stake_ratio)`; if `total_stake` is `Balance::ZERO` (e.g. no proposals in that role bucket, such as right after all validators unstake or on a freshly bootstrapped/private chain), the computed threshold is also zero: [3](#0-2) 

`minimum_stake` never guards against this and simply divides zero by `minimum_stake_divisor`, returning `Balance::ZERO`. This zero value is then trusted directly by `action_stake` to decide whether to reject a stake as insufficient: [4](#0-3) 

Because the comparison is `stake.stake < minimum_stake`, and `minimum_stake == 0`, the branch is unreachable for any `stake.stake > Balance::ZERO` (already guaranteed by the surrounding `if stake.stake > Balance::ZERO` guard). The `InsufficientStake` validation — the protocol's explicit economic floor meant to prevent proposal spam/dust stake — is thereby completely and silently bypassed whenever `seat_price` is zero, exactly mirroring how `KangarooVault.removeCollateral` bypassed its `minColl` check when `markPrice` was zero.

### Impact Explanation
This is an invalid-state-transition-acceptance bug: a `Stake` action that the protocol intends to reject (dust/near-zero stake, below the documented minimum-stake economic floor) is instead accepted and recorded as a validator proposal, because the derived threshold silently degrades to zero instead of causing an explicit rejection or falling back to a safe minimum. This weakens the validator-proposal admission control that `docs/RuntimeSpec/Actions.md` documents as `last_epoch_seat_price / minimum_stake_divisor`, and could let an unprivileged transaction signer flood the proposal set with dust-stake `Stake` actions during any epoch where the seat price collapses to zero (e.g., after a mass unstake event or on a low-validator/testnet-style deployment), consuming proposal-processing/state resources that the `InsufficientStake` check exists to prevent, without producing any error to the submitter.

### Likelihood Explanation
The precondition — a role bucket's total proposal stake being zero, or the whole proposal set producing a zero ratio-threshold — occurs during select_validators's degenerate branch when `total_stake == Balance::ZERO` for that role, which is reachable on genesis/bootstrap epochs, on chains/tests with very few or transiently unstaked validators, or during pathological mass-unstake events. It is a reachable state transition, not requiring any privileged/adversarial network role — any account submitting an ordinary `Stake` transaction at such a moment triggers the bypass.

### Recommendation
In `EpochManager::minimum_stake` (`chain/epoch-manager/src/lib.rs`), explicitly detect the degenerate `seat_price == 0` case and either fall back to a protocol-defined non-zero floor or propagate an error instead of silently returning `Balance::ZERO`. Additionally, harden `action_stake` (`runtime/runtime/src/actions.rs`) to treat a zero `minimum_stake` returned from `epoch_info_provider.minimum_stake` as an inconsistent/invalid condition rather than implicitly permitting any positive stake, consistent with how the analogous Solidity fix requires an explicit non-zero check before trusting a derived price/threshold value.

### Proof of Concept
1. Reach (or construct in a test-loop/mocked epoch) an epoch where the previous epoch's validator-selection round leaves `total_stake == Balance::ZERO` for at least one role bucket in `select_validators`, causing `seat_price` (the min of the three role thresholds) stored in the produced `EpochInfo` to be `Balance::ZERO` — e.g. via `chain/epoch-manager/src/validator_selection.rs:357-397` when the relevant proposal set is empty.
2. Call `EpochManager::minimum_stake(prev_block_hash)` (`chain/epoch-manager/src/lib.rs:1958-1967`); it returns `Balance::ZERO` because `seat_price.checked_div(stake_divisor)` divides zero.
3. Submit a `Stake` action with `stake.stake = Balance::from_yoctonear(1)` (any positive stake). In `runtime/runtime/src/actions.rs:76-86`, `stake.stake < minimum_stake` evaluates `1 < 0`, which is false, so the `InsufficientStake` error is never raised and the dust proposal is pushed into `result.validator_proposals` unconditionally.

```rust
    /// Get minimum stake allowed at current block. Attempts to stake with a lower stake will be
    /// rejected.
    pub fn minimum_stake(&self, prev_block_hash: &CryptoHash) -> Result<Balance, EpochError> {
        let next_epoch_id = self.get_next_epoch_id_from_prev_block(prev_block_hash)?;
        let (protocol_version, seat_price) = {
            let epoch_info = self.get_epoch_info(&next_epoch_id)?;
            (epoch_info.protocol_version(), epoch_info.seat_price())
        };
        let config = self.config.for_protocol_version(protocol_version);
        let stake_divisor = { config.minimum_stake_divisor };
        Ok(seat_price.checked_div(u128::from(stake_divisor)).unwrap())
    }
```

```rust
fn select_validators(
    mut proposals: BinaryHeap<OrderedValidatorStake>,
    max_number_selected: usize,
    min_stake_ratio: Ratio<u128>,
) -> (Vec<ValidatorStake>, BinaryHeap<OrderedValidatorStake>, Balance) {
    let mut total_stake = Balance::ZERO;
    let n = cmp::min(max_number_selected, proposals.len());
    let mut validators = Vec::with_capacity(n);
    for _ in 0..n {
        let p = proposals.pop().unwrap().0;
        let p_stake = p.stake();
        let total_stake_with_p = total_stake.checked_add(p_stake).unwrap();
        if total_stake_with_p > Balance::ZERO
            && Ratio::new(p_stake.as_yoctonear(), total_stake_with_p.as_yoctonear())
                > min_stake_ratio
        {
            validators.push(p);
            total_stake = total_stake_with_p;
        } else {
            // p was not included, return it to the list of proposals
            proposals.push(OrderedValidatorStake(p));
            break;
        }
    }
    let threshold = if validators.len() == max_number_selected {
        // all slots were filled, so the threshold stake is 1 more than the current
        // smallest stake
        validators.last().unwrap().stake().checked_add(Balance::from_yoctonear(1)).unwrap()
    } else {
        // the stake ratio condition prevented all slots from being filled,
        // or there were fewer proposals than available slots,
        // so the threshold stake is whatever amount pass the stake ratio condition
        Balance::from_yoctonear(
            (min_stake_ratio * Ratio::from_integer(total_stake.as_yoctonear())
                / (Ratio::from_integer(1u128) - min_stake_ratio))
                .ceil()
                .to_integer(),
        )
    };
    (validators, proposals, threshold)
}
```

```rust
    let increment = stake.stake.saturating_sub(account.locked());

    if let Some(new_balance) = account.amount().checked_sub(increment) {
        if account.locked().is_zero() && stake.stake.is_zero() {
            // if the account hasn't staked, it cannot unstake
```
