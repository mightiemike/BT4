### Title
Replay/execution verification silently ignores state-checkpoint root divergence - ([File: types/src/transaction/mod.rs])

### Summary
`TransactionOutput::ensure_match_transaction_info` — the function used by the chunk executor and `db-tool`'s `replay_on_archive` to verify that a locally re-executed transaction matches the authenticated `TransactionInfo` from a trusted backup/archive — checks transaction status, gas used, write-set hash, and event root hash, but does **not** check the `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` fields of `TransactionInfo`. This mirrors the structural pattern in the external report: a state-mutating/verifying operation completes its "core" checks but skips one integrity-relevant field, leading a caller to believe full verification succeeded when it did not.

### Finding Description
`ensure_match_transaction_info` in [1](#0-0)  is documented in-code as:

```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
``` [2](#0-1) 

The function verifies `status`, `gas_used`, write-set hash (`state_change_hash`), and `event_root_hash` [3](#0-2) , but has no `ensure!` on `txn_info.state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, or `position_state_checkpoint_hash()`. This function is the sole invariant check used by:
- `execution/executor/src/chunk_executor/mod.rs::verify_execution`, which re-executes archived transactions and calls `txn_out.ensure_match_transaction_info(version, txn_info, Some(write_set), Some(events))` per transaction [4](#0-3) .
- `storage/db-tool/src/replay_on_archive.rs`, used operationally to validate that replaying an archived chunk against a live/local execution produces the identical committed ledger state.

Because the state-checkpoint hash (the JMT/state-merkle root committed after a checkpoint transaction) is never compared, a divergence between the locally computed state root and the authenticated `TransactionInfo`'s `state_checkpoint_hash` (or the trading-native `position_state_checkpoint_hash`) will not be detected by this verification path — even though write-set and event hashes match. This is exactly the class of bug called out by the Proof/Storage pivots: "Wrong accumulator root, Merkle proof, transaction proof... accepted as valid" and "Hard-fork-only divergence during commit, replay, restore, or proof verification."

### Impact Explanation
If the underlying state root computation (e.g. the "trading-native" state root / hot-state root path referenced in the TODO, or any other state-merkle-tree divergence) silently diverges from the archived/authenticated ledger, replay-verification tooling (`replay_on_archive`, and the executor's own `verify_execution` chunk-replay path) will report success. This defeats the core purpose of replay verification, which is to catch state-commitment bugs (including consensus-breaking bugs) before or after they land on mainnet. It could mask a genuine state-divergence / hard-fork condition, allowing corrupted state roots to go undetected in exactly the scenarios (replay, restore, chunk-executor verify) that this Gate calls out as high/critical impact.

### Likelihood Explanation
This is not attacker-triggered in the traditional sense (it requires an underlying execution/state-root bug to exist), but the code path itself is unconditionally missing the check — it will always fail to detect a checkpoint-hash mismatch regardless of cause. The gap is explicitly acknowledged in the code as blocking the safe rollout of `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, which indicates the team is aware the feature is not yet safe to enable specifically because of this missing verification. The risk materializes primarily around the `hotness_in_epilogue` / trading-native state root feature, which is exercised in `by_transaction_execution_sharded` and `compute_trading_native_state_roots` config flags [5](#0-4) .

### Recommendation
Extend `ensure_match_transaction_info` to also assert equality of `state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, and `position_state_checkpoint_hash()` between the locally computed checkpoint hash(es) and the ones carried in the trusted `TransactionInfo`, before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (or any state-checkpointing verification path relying on this function) is enabled in production. This closes the gap flagged by the existing TODO and ensures replay/restore verification cannot silently pass over a genuine state-root divergence.

### Proof of Concept
Not independently reproducible without a concrete state-root-diverging execution bug (the divergence trigger itself is out of scope of this analysis); the finding is based on directly reading the verification function's logic and its explicit in-code acknowledgment of the gap: [1](#0-0) , plus its call sites in `chunk_executor::verify_execution` [6](#0-5)  and `db-tool/replay_on_archive.rs` (confirmed via grep match, but full file contents were not retrievable due to a tool error in the final iteration — I was unable to inspect the exact usage context there and cannot confirm additional mitigating checks might exist at that call site).

**Note on confidence:** I could not load `storage/db-tool/src/replay_on_archive.rs` in the final iteration (tool call failed), so I cannot fully confirm whether that call site has any supplementary checkpoint-hash check elsewhere that would mitigate this gap. This should be verified before treating the finding as fully conclusive.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
