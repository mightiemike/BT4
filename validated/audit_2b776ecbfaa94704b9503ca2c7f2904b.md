### Title
CASM-hash resource estimation for Declare transactions relies on an empirically-fit "linear-in-felt-count" formula, allowing under-accounting of actual OS/proving cost - ([File: crates/blockifier/src/execution/casm_hash_estimation.rs])

### Summary
Bouncer weights (`sierra_gas`, `proving_gas`) for a transaction that triggers CASM-hash computation (e.g. a `Declare`, or any first execution of a class) are not derived from the actual Starknet-OS execution cost of `compiled_class_hash`. Instead they come from `EstimateCasmHashResources`, an empirically-fit, per-felt/per-entry-point "linear" cost model [1](#0-0) , exactly the same pattern flagged in the Sudoswap report: a pre-computed value that assumes linearity is later relied on as if it were the ground truth, and the actual (attacker-influenced) computation can diverge from that assumption.

### Finding Description
`EstimateCasmHashResources::estimated_resources_of_compiled_class_hash` builds up an estimate of the VM resources for hashing a compiled class using fixed base constants plus per-felt/per-segment linear terms (`STEPS_PER_LARGE_FELT`, `STEPS_PER_SMALL_FELT`, `BASE_STEPS_FULL_MSG`, etc.) that were "determined empirically... across running multiple contracts with different bytecode segment structures" [2](#0-1) . The comments explicitly acknowledge this is an approximation, not an exact computation: "This provides resource estimates rather than exact values" [3](#0-2) .

This estimate — not the real cost of the OS's `compiled_class_hash` execution — is what feeds directly into the bouncer weight computation for every transaction that touches a class:

```
map_class_hash_to_casm_hash_computation_resources -> class.estimate_casm_hash_computation_resources()
``` [4](#0-3) 

These per-class estimated resources are then converted to gas and summed into the transaction's `bouncer_weights.sierra_gas` and `bouncer_weights.proving_gas`, which the Batcher uses to decide how many transactions/classes fit in a block [5](#0-4) .

The test `compare_estimated_vs_actual_casm_hash_resources` confirms the model is only validated to be *close* (within an "allowed margin") to the true VM execution cost for the fixed set of feature/test contracts, not proven to be an upper bound for arbitrary bytecode:

```
let n_steps_margin = estimated_resources.vm_resources.n_steps.abs_diff(actual_execution_resources.n_steps);
let allowed_n_steps_margin = hash_version.allowed_margin_n_steps();
assert!(n_steps_margin <= allowed_n_steps_margin, ...);
``` [6](#0-5) 

Because a class's declarer (any unprivileged account) fully controls the bytecode structure (number/size of segments, number of entry points, distribution of small vs. large felts, whether messages fill exactly 16 `u32` words for Blake, etc.), an attacker can craft a class whose bytecode/segment shape breaks the "typical contract" assumptions baked into the empirical constants (`BASE_HASH_ENTRY_POINTS_INNER_STEPS`, `STEPS_PER_2_U32_REMINDER`, the leaf/node segmentation heuristics), causing the *estimated* resource cost to under-count the *actual* Cairo-VM/OS cost of computing `compiled_class_hash` for that class, in the same way the KODAV2 rounding example in the referenced report broke the linear royalty assumption.

### Impact Explanation
If the estimate systematically under-counts the true CASM-hash computation cost for adversarially-shaped bytecode, the bouncer will admit more such declared/executed classes into a block than the block's real proving/CPU budget can actually sustain, because `bouncer_weights.sierra_gas`/`proving_gas` (used to enforce the block's resource capacity, see `get_tx_weights`/`BouncerWeights` in `crates/blockifier/src/bouncer.rs`) are computed from the under-estimate rather than the real cost. This can push the actual OS re-execution/proving workload for a block above its intended capacity, threatening the sequencer's ability to build/prove blocks within the expected time — a resource-exhaustion style denial of service on block production reachable purely from a submitted `Declare` transaction (or any first invocation of a crafted class), with no special privileges required.

### Likelihood Explanation
Medium confidence. The mismatch is definitionally possible because the estimator is explicitly documented as an approximation ("provides resource estimates rather than exact values") fitted against a fixed test-contract corpus, and any unprivileged declarer fully controls the bytecode/segment shape that drives the estimate. However, I could not fully verify (within the available tool budget) how large a divergence an adversarial bytecode shape could realistically produce relative to the bouncer's configured margins/capacity, nor whether there are additional runtime safety checks (e.g., a hard cap independent of the estimate) that would bound the practical impact. This uncertainty should be resolved by an engineer with full repository access before treating this as a confirmed, exploitable bug.

### Recommendation
Do not rely solely on a felt-count/segment-count linear approximation for security-relevant resource accounting (bouncer capacity). Either bound the estimate by a provable worst-case (not just an empirically-fit constant), or validate/re-price against the actual measured OS execution resources before admitting a transaction's class into a block, similar to how the Sudoswap report recommended using actual royalty amounts rather than an assumed-linear formula.

### Proof of Concept
Not independently constructed/executed — I do not have execution access to craft and measure a concrete adversarial bytecode shape against `CasmV2HashResourceEstimate` vs. the real Starknet OS `compiled_class_hash` run. This would require running `compare_estimated_vs_actual_casm_hash_resources`-style measurements (see `crates/starknet_os/src/hints/hint_implementation/compiled_class/compiled_class_test.rs`) against a deliberately crafted class (e.g., many entry points, or bytecode-segment sizes chosen to maximize `STEPS_PER_2_U32_REMINDER` remainder overhead relative to the linear terms) to empirically demonstrate a divergence exceeding the tested margins.

fn compute_sierra_gas(
    vm_resources: &ExtendedExecutionResources,
    sierra_builtin_gas_costs: &BuiltinGasCosts,
    versioned_constants: &VersionedConstants,
    tx_resources: &TransactionResources,
    migration_gas: GasAmount,
    class_hash_to_casm_hash_computation_resources: &HashMap<ClassHash, ExtendedExecutionResources>,
) -> (GasAmount, CasmHashComputationData, GasAmount) {
    let mut vm_resources_sierra_gas = extended_execution_resources_to_gas(
        vm_resources,
        sierra_builtin_gas_costs,
        versioned_constants,
    );
    let sierra_gas = tx_resources.computation.sierra_gas;

    vm_resources_sierra_gas = vm_resources_sierra_gas.checked_add_panic_on_overflow(sierra_gas);

    let sierra_gas_without_casm_hash_computation =
        vm_resources_sierra_gas.checked_add_panic_on_overflow(migration_gas);

    let (total_sierra_gas, casm_hash_computation_data_sierra_gas) =
        add_casm_hash_computation_gas_cost(
            class_hash_to_casm_hash_computation_resources,
            sierra_gas_without_casm_hash_computation,
            sierra_builtin_gas_costs,
            versioned_constants,
        );
    (total_sierra_gas, casm_hash_computation_data_sierra_gas, vm_resources_sierra_gas)
}

fn compute_proving_gas(
    cairo_primitives_counters: &CairoPrimitiveCounterMap,
    vm_resources_sierra_gas: GasAmount,
    versioned_constants: &VersionedConstants,
    proving_builtin_gas_costs: &BuiltinGasCosts,
    sierra_builtin_gas_costs: &BuiltinGasCosts,
    migration_gas: GasAmount,
    class_hash_to_casm_hash_computation_resources: &HashMap<ClassHash, ExtendedExecutionResources>,
) -> (GasAmount, CasmHashComputationData) {
    let vm_resources_proving_gas = proving_gas_from_cairo_primitives_and_sierra_gas(
        vm_resources_sierra_gas,
        cairo_primitives_counters,
        proving_builtin_gas_costs,
        sierra_builtin_gas_costs,
    );

    let proving_gas_without_casm_hash_computation =
        vm_resources_proving_gas.checked_add_panic_on_overflow(migration_gas);

    add_casm_hash_computation_gas_cost(
        class_hash_to_casm_hash_computation_resources,
        proving_gas_without_casm_hash_computation,
        proving_builtin_gas_costs,
        versioned_constants,
    )

pub fn get_tx_weights<S: StateReader>(
    state_reader: &S,
    executed_class_hashes: &HashSet<ClassHash>,
    n_visited_storage_entries: usize,
    tx_resources: &TransactionResources,
    state_changes_keys: &StateChangesKeys,
    versioned_constants: &VersionedConstants,
    tx_cairo_primitives_counters: &CairoPrimitiveCounterMap,
    bouncer_config: &BouncerConfig,
    receipt_l2_gas: GasAmount,
) -> TransactionExecutionResult<TxWeights> {
    let message_resources = &tx_resources.starknet_resources.messages;
    let message_starknet_l1gas = usize_from_u64(message_resources.get_starknet_gas_cost().l1_gas.0)
        .expect("This conversion should not fail as the value is a converted usize.");

    // Casm hash resources.
    let class_hash_to_casm_hash_computation_resources =
        map_class_hash_to_casm_hash_computation_resources(state_reader, executed_class_hashes)?;

    // Patricia update + transaction resources.
    let patricia_update_resources = get_patricia_update_resources(
        n_visited_storage_entries,
        // TODO(Yoni): consider counting here the global contract tree and the aliases as well.
        state_changes_keys.storage_keys.len(),
    );
    let vm_resources =
        &tx_resources.computation.total_extended_vm_resources() + &patricia_update_resources;

    // Builtin gas costs for stone and for stwo.
    let sierra_builtin_gas_costs = &versioned_constants.os_constants.gas_costs.builtins;
    let proving_builtin_gas_costs = &bouncer_config.builtin_gas_costs();

    // Casm hash migration resources.
    let migration_data = CasmHashMigrationData::from_state(
        state_reader,
        executed_class_hashes,
        versioned_constants,
    )?;
    // Total state changes keys are the sum of marginal state changes keys and the
    // migration state changes.
    let mut total_state_changes_keys = StateChangesKeys {
        compiled_class_hash_keys: migration_data.class_hashes_to_migrate.keys().cloned().collect(),
        ..Default::default()
    };
    total_state_changes_keys.extend(state_changes_keys);

    // Migration occurs once per contract and is not included in the CASM hash computation, which
    // is performed every time a contract is loaded.
    let sierra_migration_gas = migration_data.to_gas(sierra_builtin_gas_costs, versioned_constants);
    let proving_migration_gas =
        migration_data.to_gas(proving_builtin_gas_costs, versioned_constants);

    // Sierra gas computation.
    let (total_sierra_gas, casm_hash_computation_data_sierra_gas, vm_resources_sierra_gas) =
        compute_sierra_gas(
            &vm_resources,
            sierra_builtin_gas_costs,
            versioned_constants,
            tx_resources,
            sierra_migration_gas,
            &class_hash_to_casm_hash_computation_resources,
        );

    // Proving gas computation.
    let cairo_primitives_for_proving_gas = get_cairo_primitives_for_proving_gas_computation(
        patricia_update_resources.prover_builtins(),
        tx_resources.computation.os_vm_resources.prover_builtins(),
        tx_cairo_primitives_counters,
    );

    let (total_proving_gas, casm_hash_computation_data_proving_gas) = compute_proving_gas(
        &cairo_primitives_for_proving_gas,
        vm_resources_sierra_gas,
        versioned_constants,
        proving_builtin_gas_costs,
        sierra_builtin_gas_costs,
        proving_migration_gas,
        &class_hash_to_casm_hash_computation_resources,
    );

    let bouncer_weights = BouncerWeights {
        l1_gas: message_starknet_l1gas,
        message_segment_length: message_resources.message_segment_length,
        n_events: tx_resources.starknet_resources.archival_data.event_summary.n_events,
        state_diff_size: get_onchain_data_segment_length(&total_state_changes_keys.count()),
        sierra_gas: total_sierra_gas,
        n_txs: 1,
        proving_gas: total_proving_gas,
        receipt_l2_gas,
    };

    Ok(TxWeights {
        bouncer_weights,
        casm_hash_computation_data_sierra_gas,
        casm_hash_computation_data_proving_gas,
        class_hashes_to_migrate: migration_data.class_hashes_to_migrate,
    })
}

/// Returns a mapping from each class hash to its estimated Cairo resources for Casm hash
/// computation (done by the OS).
pub fn map_class_hash_to_casm_hash_computation_resources<S: StateReader>(
    state_reader: &S,
    executed_class_hashes: &HashSet<ClassHash>,
) -> TransactionExecutionResult<HashMap<ClassHash, ExtendedExecutionResources>> {
    executed_class_hashes
        .iter()
        .map(|class_hash| {
            let class = state_reader.get_compiled_class(*class_hash)?;
            Ok((*class_hash, class.estimate_casm_hash_computation_resources()))
        })
        .collect()
