### Title
`accrue()` pass-through under pause silently freezes interest/index state while deposit/redeem/borrow/repay remain active - (File: `mainnet/contracts/vault/v0-vault-usdc.clar`)

### Summary
The vault's `set-pause-states` exposes six independent boolean pause switches (`deposit`, `redeem`, `borrow`, `repay`, `accrue`, `flashloan`) [1](#0-0) . `accrue()` is the one function all money-moving flows depend on for correct interest bookkeeping, but when its own flag is paused it does not revert — it silently passes through and returns the stale index unchanged [2](#0-1) . Because `deposit`, `redeem`, `system-borrow`, and `system-repay` each call `(try! (accrue))` unconditionally and only assert against *their own* named flag (not `accrue`), the DAO can pause interest accrual alone while leaving deposits/redemptions/borrows/repayments fully operational on stale, unaccrued state.

### Finding Description
`accrue` checks only its own flag from `pause-states` and, when set, returns the current (unrefreshed) `index`/`lindex` with an explicit "pass-through without reverting" comment instead of failing the call: [3](#0-2) 

Every state-changing public entrypoint calls `accrue` first and then asserts against a *different* flag:
- `deposit`: asserts `(not (get deposit states))`, never checks `accrue` [4](#0-3) 
- `redeem`: asserts `(not (get redeem states))`, never checks `accrue` [5](#0-4) 
- `system-borrow`: asserts `(not (get borrow states))`, never checks `accrue` [6](#0-5) 
- `system-repay`: asserts `(not (get repay states))`, never checks `accrue` [7](#0-6) 

`set-pause-states` itself reinforces that `accrue` is meant to freeze the vault's time-accounting: when transitioning into pause it flushes pending interest once, and when transitioning out it force-jumps `last-update` to `stacks-block-time`, explicitly "skipping" the paused interval rather than accruing it: [8](#0-7) 

Because the six pause flags are independent booleans, the DAO (or anyone reaching `set-pause-states` under the intended emergency-pause use case) can set `accrue: true` while `deposit`/`redeem`/`borrow`/`repay` remain `false`. In that state:
1. `last-update`/`index`/`lindex` are frozen at pause time (value bound at the moment `accrue` flag flips).
2. The event that should invalidate the frozen index — real elapsed time / block progression while debt is outstanding — occurs, but is never applied because `accrue()` passes through instead of reverting or recomputing.
3. `deposit`/`redeem` continue to convert shares/assets using `convert-to-shares-preview`/`convert-to-assets-preview`, which read the frozen `index`/`lindex`, and `system-borrow`/`system-repay` continue to scale principal against the frozen `index` — all while real utilization-driven interest that should have compounded is discarded.
4. On unpause, `last-update` is jumped straight to "now," permanently discarding the interest that accrued (in real economic terms) for lenders during the paused window, while borrowers who borrowed/repaid during that window did so effectively interest-free for that period.

This is the exact bug class from the report: a per-action pause flag (`marketPaused`/`globalPause`) that is enforced on some flows but not others, combined with a "helper" flow (`accrue`, analogous to `refundUser`/`topupMarketBalance`) that keeps mutating/skipping state instead of reverting under its own pause — so the emergency pause does not actually freeze the state it is meant to freeze, and the skipped interval is unrecoverable once resumed.

### Impact Explanation
Lenders permanently lose the yield that should have accrued on outstanding debt during the `accrue`-paused window, since `last-update` is force-advanced to the unpause time rather than backfilling the missed interest — this is a permanent loss of unclaimed yield for LPs (in-scope: "theft of unclaimed yield ... or permanent freezing of unclaimed yield"). Simultaneously, borrowers who transact via `system-borrow`/`system-repay` during the window obtain interest-free borrowing capacity that the protocol never recovers, an insolvency-adjacent leak of protocol revenue (treasury fee-share `treasury-lp` mint in `accrue` is likewise skipped) [9](#0-8) .

### Likelihood Explanation
This requires only the DAO/pause-authority to call `set-pause-states` with `accrue: true` and other flags `false` — a plausible operational choice during an incident where the intent is "freeze the interest clock" without halting user liquidity access, exactly the kind of partial-pause scenario the analogous report describes. No attacker collusion or multi-party interference is needed; the loss occurs purely from ordinary deposit/redeem/borrow/repay traffic continuing normally while `accrue` silently no-ops. The same pattern is duplicated verbatim across all vault instances (`v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-stx.clar`, `v0-vault-usdh.clar`), increasing the surface.

### Recommendation
Make `accrue()` revert (or make callers gate on it) rather than silently pass through when paused: either (a) have `deposit`/`redeem`/`system-borrow`/`system-repay`/`flashloan` also assert `(not (get accrue states))` before proceeding so pausing accrual halts all dependent economic flows, or (b) remove the pass-through branch and have `accrue` itself return an error, forcing every caller through `try!` to fail closed. Additionally, when unpausing, accrue the interest owed for the paused interval (using a stored pre-pause snapshot) instead of jumping `last-update` forward and discarding it.

### Proof of Concept
1. DAO calls `set-pause-states` with `{ deposit: false, redeem: false, borrow: false, repay: false, accrue: true, flashloan: false }` on `v0-vault-usdc.clar`; this flushes interest once and freezes `index`/`lindex`/`last-update` [10](#0-9) .
2. Time passes (multiple blocks) with outstanding debt in the market via `system-borrow`.
3. A user calls `deposit`; `(try! (accrue))` hits the `(get accrue states)` branch and returns the old `{index, lindex}` unchanged instead of reverting [2](#0-1) ; `deposit` proceeds normally since it only checks its own `deposit` flag [11](#0-10) .
4. Borrower calls repay via the market, which triggers `system-repay`; it likewise only checks `repay` flag and proceeds on the frozen `index`, so the interest that should have compounded for that elapsed period is never charged/credited [7](#0-6) .
5. DAO unpauses `accrue`; `last-update` is force-set to `stacks-block-time`, permanently skipping the missed accrual interval [12](#0-11) . Lenders never receive the yield for that window; the treasury never receives its `treasury-lp` fee share for it either.

(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))
  (begin
    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      ;; When pausing accrue, accrue first to capture pending interest
      (if (and (not was-paused) now-paused)
          (begin (try! (accrue)) false)
          false)
      ;; When unpausing accrue, jump last-update to now to skip paused period
      (if (and was-paused (not now-paused))
          (var-set last-update stacks-block-time)
          false)
      (var-set pause-states states)
      
      (print {
        action: "vault-set-pause-states",
        caller: tx-sender,
        data: {
          vault: UNDERLYING,
          states: states
        }
      })
      
      (ok true))))

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
