### Title
Nakamoto block signature verification accepts blocks with zero signer signatures when the PoX reward set degenerates to an empty (but `Some`) signer list — ([File: stackslib/src/chainstate/nakamoto/mod.rs])

### Summary
`NakamotoBlockHeader::verify_signer_signatures` computes the approval threshold from `RewardSet::total_signing_weight()`. When the reward set's `signers` field is `Some(vec![])` (a non-`None`, but empty, signer list) rather than `None`, `total_signing_weight()` returns `Ok(0)` instead of an error, and the resulting threshold collapses to `0`. A block with an *empty* `signer_signature` vector then satisfies `total_weight_signed (0) < threshold (0) == false`, so the function returns `Ok(0)` as if the block were validly approved.

### Finding Description
`RewardSet::total_signing_weight` only errors when `self.signers()` is `None`; if it is `Some(&vec![])` it happily folds over zero entries and returns `Ok(0)`: [1](#0-0) 

`compute_voting_weight_threshold` derives the threshold purely as a fraction of `total_weight`; for `total_weight == 0` the computation `(0 * threshold_pct)/10 + ceil` yields `0`: [2](#0-1) 

`verify_signer_signatures` uses these two together. If `signer_signature` is empty, the loop never runs, `total_weight_signed` stays `0`, and the check `total_weight_signed < threshold` becomes `0 < 0`, which is `false` — the function returns `Ok(0)` (success) instead of rejecting the block: [3](#0-2) 

The degenerate `Some(vec![])` state is reachable through `make_signer_set`, which aggregates stacked amounts *per signing key* and filters out any entry whose `stacked_amt / threshold` floors to `0`. If *every* signing key in the reward set (that cycle) is below `threshold`, the function returns `Some(vec![])` rather than `None`: [4](#0-3) 

Critically, unlike the PoX‑5 path (`pox_5_compute_and_update_signers`), which explicitly checks `if signer_set.is_empty() { return Err(ChainstateError::PoxNoRewardCycle) }`: [5](#0-4) 

the classic PoX‑4 path (`pox_4_compute_and_update_signers`) has no such guard — it directly writes `reward_set.signers().unwrap_or(&empty_signers)` into the on-chain `.signers` contract and returns the `RewardSet` with `signers: Some(vec![])` unchecked: [6](#0-5) 

This is the direct analog of the reported LP-share bug: an "effective pool value"-like quantity (`total_signing_weight`) is allowed to legitimately fall to exactly zero (rather than being floored at a minimum, the way PoX‑5's `pox_5_make_signer_set` floors its threshold with `std::cmp::max(1, ...)`, see `stackslib/src/chainstate/nakamoto/signer_set.rs:873`), and the downstream consumer's inequality check silently degenerates to a vacuously-true comparison (`0 < 0` is false) instead of erroring.

### Impact Explanation
This breaks the fundamental consensus invariant "a Nakamoto block is only valid if signers holding at least the threshold weight approved it." A block with **zero signer signatures** would be accepted as validly signed by every honest node running this exact code (deterministic given the same reward-set state), i.e., an invalid block is accepted network-wide — one of the explicitly listed Critical impacts (invalid block accepted network-wide).

### Likelihood Explanation
Reachability requires a PoX‑4 reward cycle whose signer set degenerates so that *every* individual signing key's aggregated stacked amount floors to zero weight under the computed `threshold`. A single unprivileged staker who is dominant (or the sole staker) in a low-participation cycle can trigger this deterministically and without needing majority hash/stake control of the network: split their locked STX across more than `reward_slots + 1` distinct signing keys of roughly equal size, so each individual signing key's share is smaller than `threshold = participation / reward_slots` (rounded up), causing `make_signer_set` to filter out every entry and yield `Some(vec![])`. This is a minority/unprivileged, protocol-state manipulation, not a majority attack, and does not require any node operator or admin key.

### Recommendation
- In `RewardSet::total_signing_weight`, treat an empty-but-`Some` signer list the same as `None` (return an error), so `verify_signer_signatures` cannot compute a zero threshold from a degenerate reward set.
- In `pox_4_compute_and_update_signers` (and any other classic-PoX reward-set computation path), add the same guard used in `pox_5_compute_and_update_signers`: reject/handle the case where `make_signer_set` returns `Some(vec![])`, instead of silently persisting an empty signer set.
- In `compute_voting_weight_threshold`, explicitly floor `total_weight` (and/or the returned threshold) to a minimum positive value, or return an error when `total_weight == 0`, mirroring the `std::cmp::max(1, ...)` floor already used in `pox_5_make_signer_set`.

### Proof of Concept
1. Construct (or drive the chain into) a PoX‑4 reward cycle where a single participant stacks the entirety of that cycle's participation, split across `N > reward_slots` distinct signing keys, each holding `stacked_amt < threshold = ceil(participation / reward_slots)`.
2. `StacksChainState::make_signer_set(threshold, entries)` filters every entry (`stacked_amt / threshold == 0`), yielding `Some(vec![])`. This is written into `RewardSet::V0(RewardSetV0 { signers: Some(vec![]), .. })` via `pox_4_compute_and_update_signers`, with no empty-check guard (contrast with the `pox_5` path's explicit `is_empty()` check).
3. At the next block, `RewardSet::total_signing_weight()` returns `Ok(0)` (not an `Err`, since `signers()` is `Some`).
4. A miner produces a `NakamotoBlock` with `signer_signature: vec![]` (no signatures at all).
5. `verify_signer_signatures` computes `threshold = compute_voting_weight_threshold(0) == 0`; the signature loop does not execute so `total_weight_signed == 0`; the check `0 < 0` is `false`, so the function returns `Ok(0)` — the block is treated as validly signer-approved despite having zero actual signatures.

            return Err("Unable to calculate total weight - No signers in reward set".to_string());

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)

                message.bits(),

                    signature.to_hex()

            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {

                    signers.len(),

                    self.signer_signature.len(),

                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed

                .expect("FATAL: overflow while computing signer set threshold");
        }

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
