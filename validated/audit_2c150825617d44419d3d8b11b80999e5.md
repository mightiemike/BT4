### Title
Uncaught `TypeError` from `new URL()` in `sanitizeHost` causes unhandled exception / DoS in embedded-admin redirect paths - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost` only base64-validates the incoming `host` parameter before feeding the base64-decoded string directly into `new URL(`https://${decodeHost(sanitizedHost)}`)` with no `try/catch`. An attacker-controlled `host` value can pass the permissive base64 regex `/^[0-9a-zA-Z+/]+={0,2}$/` yet decode into a string that is not a syntactically valid URL authority, causing the native `URL` constructor to throw a `TypeError` that propagates uncaught out of `sanitizeHost`, `getEmbeddedAppUrl`/`buildEmbeddedAppUrl`, and the framework-level `redirectToShopifyOrAppRoot`/`validateShopAndHostParams` helpers.

### Finding Description
In `sanitizeHost` [1](#0-0) , the only gate before constructing a `URL` is the base64 regex check. Base64 can decode into arbitrary ASCII byte sequences (colons, brackets, spaces, control characters), many of which are not valid values for the `https://<authority>` template being parsed. When `new URL()` receives such a malformed authority (e.g. a decoded value like `:::::::`, which passes the base64 regex trivially since `:` is not even required — any base64 alphabet string like `Ojo6Ojo6Ojo=` decodes to `:::::::`), the WHATWG URL parser throws a `TypeError: Invalid URL`, which is not caught anywhere in `sanitizeHost`.

This exception then propagates through every caller that does not wrap the call in `try/catch`:
- `buildEmbeddedAppUrl`/`getEmbeddedAppUrl` call `sanitizeHost(config)(host, true)` unguarded [2](#0-1) .
- The Express `redirectToShopifyOrAppRoot` middleware calls `api.utils.sanitizeHost(req.query.host as string)!` directly with no try/catch around it [3](#0-2) .
- The Remix and React Router `redirectToShopifyOrAppRoot`/`validateShopAndHostParams` helpers likewise call `api.utils.sanitizeHost(...)` with no surrounding try/catch [4](#0-3) [5](#0-4) [6](#0-5) .

Critically, the exception can happen even when `throwOnInvalid` is `false` (the default), because the `new URL()` call happens unconditionally inside the `if (sanitizedHost)` block, before the `throwOnInvalid` branch is ever reached [7](#0-6) . This means the function's documented contract ("returns `null` for invalid input, only throws when `throwOnInvalid=true`") [8](#0-7)  is violated: an untyped, unhandled `TypeError` can escape regardless of the `throwOnInvalid` flag, and none of the checked call sites treat this as an expected/typed error.

### Impact Explanation
This is a request-triggerable denial-of-service in an unauthenticated code path: any anonymous request to an embedded-admin route carrying a crafted `host` query parameter (which requires no session, HMAC, or secret) can throw an unhandled `TypeError` inside the auth/redirect middleware, causing an unhandled promise rejection or a raw 500/crash depending on the host framework's async error handling, rather than the expected graceful `null`/`InvalidHostError` handling that the rest of the code relies on to redirect users safely. This matches Shopify's "DoS in an authentication handler" impact class.

### Likelihood Explanation
The precondition is minimal: an anonymous GET/POST request to any embedded-admin route (e.g., `authenticate.admin`, the Express `redirectToShopifyOrAppRoot` middleware, or Remix/React Router admin auth flows) with a `host` query parameter set to a base64 string that decodes to a malformed authority. Constructing such a base64 string requires no special access, and the flaw is reachable through the library's default configuration with no app-developer misconfiguration needed. However, actual confirmation that `new URL()` throws for a specific decoded payload (vs. silently producing an odd-but-valid `hostname`) depends on precise WHATWG URL-parsing behavior for the chosen malformed string in the Node runtime version in use — this needs to be validated experimentally with a concrete Jest run against the target Node version before treating it as fully confirmed, since I could not execute code to verify the exact throwing input at this depth of static review.

### Recommendation
Wrap the `new URL()` call in `sanitizeHost` in a `try/catch` and treat any thrown error as an invalid host (returning `null`, or throwing `InvalidHostError` only when `throwOnInvalid` is `true`), consistent with the function's documented contract:
```ts
let hostname: string;
try {
  ({hostname} = new URL(`https://${decodeHost(sanitizedHost)}`));
} catch {
  sanitizedHost = null;
}
```
Apply the same defensive handling to `decodeHost`'s `atob` call, since malformed base64 padding combinations can also throw in some `atob` implementations.

export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }

import {redirect} from '@remix-run/server-runtime';

import type {BasicParams} from '../../../types';

export async function redirectToShopifyOrAppRoot(
  request: Request,
  params: BasicParams,
  responseHeaders?: Headers,
): Promise<never> {
  const {api} = params;
  const url = new URL(request.url);

  const host = api.utils.sanitizeHost(url.searchParams.get('host')!)!;
  const shop = api.utils.sanitizeShop(url.searchParams.get('shop')!)!;

  const redirectUrl = api.config.isEmbeddedApp
    ? await api.auth.getEmbeddedAppUrl({rawRequest: request})
    : `/?shop=${shop}&host=${encodeURIComponent(host)}`;

  throw redirect(redirectUrl, {headers: responseHeaders});
}

# shopify.utils.sanitizeHost

This method makes user inputs safer by ensuring that the `host` query arguments from Shopify requests is valid.

## Example

```ts
const host = shopify.utils.sanitizeHost(req.query.host, true);

`string` | :exclamation: required

The incoming host value.

`boolean` | Defaults to `false`

If `true`, throws an error when the host is invalid.

`string | null`

The `host` value if it is properly formatted, otherwise `null`.
