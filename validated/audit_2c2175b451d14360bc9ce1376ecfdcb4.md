### Title
Unbounded recursion depth in compiled-class bytecode-segment hashing allows stack-overflow DoS of the Sierra compiler/class-manager component - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs])

### Summary
The CVE analog (uBlock Origin's unbounded parameter-nesting recursion) maps to `bytecode_hash_node` / `bytecode_hash` in [1](#0-0) , which recursively walks the `NestedIntList` bytecode-segment tree of a compiled class with **no depth limit whatsoever**. The same unbounded pattern is duplicated in the Starknet-OS re-execution path in [2](#0-1) . Because the segment-tree structure is derived from the shape of a user-submitted Sierra program during Declare-transaction compilation, an attacker can craft a class whose compiled bytecode produces a deeply/linearly nested segment tree, triggering uncontrolled native-stack recursion and crashing the process that computes the compiled-class hash.

### Finding Description
When a Declare transaction is submitted, the class manager compiles the attacker-supplied Sierra program to CASM and then immediately computes the compiled-class hash **in the same process** (not inside the resource-limited compiler subprocess): [3](#0-2) 

The compiled class hash is computed by walking the `bytecode_segment_lengths` field (`NestedIntList`) of the resulting `CasmContractClass` recursively, with unbounded depth: [4](#0-3) 

`hash_inner` (called from `HashableCompiledClass::hash`, invoked at line 69 of `apollo_compile_to_casm/src/lib.rs`) calls `bytecode_hash`, which calls `bytecode_hash_node` recursively once per tree level, with no maximum-depth check comparable to `RecursionDepthGuard` used elsewhere for Cairo call-stack recursion ( [5](#0-4) ). The bytecode-segment tree is produced by the Sierra→CASM compiler from the control-flow/branch structure of the submitted program; a program engineered with a very deep chain of nested branches/functions (within the existing size limits) can force the compiler to emit a segment tree whose depth approaches the bytecode length rather than O(log n). The size limits enforced at the gateway constrain total instruction count, not tree depth: [6](#0-5) 

Because `max_contract_bytecode_size` is 81920 instructions, an attacker has ample budget to build a segment tree with tens of thousands of nesting levels, each recursive call frame consuming native stack. This recursion:
1. Runs unconditionally on the sequencer/class-manager process for every accepted Declare transaction (`ClassManager::add_class` → `compiler.compile` → `SierraCompiler::compile` → `.hash(&HashVersion::V2)`), see [7](#0-6) .
2. Runs again, unbounded, in the Starknet OS re-execution/proving hint `create_bytecode_segment_structure_inner`, reachable whenever the class is later executed/re-executed by any node reconstructing the segment structure from the same untrusted `bytecode_segment_lengths` data: [8](#0-7) .

Unlike Cairo call recursion, which is explicitly bounded via `RecursionDepthGuard`/`max_recursion_depth` ( [9](#0-8) ), this class-hashing recursion path has no equivalent guard — precisely the CVE-2021-36773 bug class (unbounded structural nesting causing native stack exhaustion / crash instead of an explicit “malformed input” rejection).

### Impact Explanation
A crafted Sierra class that compiles to a deeply nested bytecode-segment tree causes a native stack overflow when the sequencer computes the compiled-class hash during Declare-transaction processing, and again during OS re-execution/proving. A stack overflow in Rust aborts the process (it cannot be caught), so this can crash the class-manager/gateway compiler component and/or the OS re-execution/prover process, denying declaration and block-proving service — a network-wide denial-of-service reachable from a single unprivileged Declare transaction, consistent with the "network unable to confirm new transactions" impact criterion.

### Likelihood Explanation
Likelihood is high for an attacker capable of engineering Sierra source producing pathologically deep nested control flow within the existing bytecode-size cap; this requires no special privileges — only submitting a Declare transaction, which is exactly the "contract deployer / class declarer" attacker path explicitly in scope.

### Recommendation
Add an explicit maximum-depth check (mirroring `RecursionDepthGuard`/`max_recursion_depth`) in `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs`) and `create_bytecode_segment_structure_inner` (`crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`), rejecting/erroring on classes whose bytecode-segment tree exceeds a safe depth bound, and/or convert these recursive walks to iterative (explicit-stack) algorithms so depth is bounded only by heap memory rather than native stack frames.

### Proof of Concept
1. Author a Sierra program (within `max_contract_bytecode_size` = 81920 instructions) containing deeply nested branch/function structure engineered so the Sierra→CASM compiler emits a `bytecode_segment_lengths: NestedIntList` tree with tens of thousands of nesting levels (a long chain of single-child `Node` wrappers around a `Leaf`).
2. Submit this class via a standard Declare transaction to the gateway.
3. `ClassManager::add_class` compiles the class and calls `SierraCompiler::compile`, which invokes `executable_class.hash(&HashVersion::V2)` — this recurses through `bytecode_hash_node` once per tree level, exhausting the native stack and crashing the class-manager/compiler process before any resource/step accounting can bound the operation.

/// Computes the hash of a bytecode segment. See the documentation of `bytecode_hash_node` in
/// the Starknet OS.
/// Returns the length of the processed segment and its hash.
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
