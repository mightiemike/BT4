### Title
Webhook shop-domain/topic headers are not covered by the HMAC signature, allowing cross-tenant webhook forgery - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
### Finding Description
`shopify.webhooks.validate()` (used by `authenticateWebhookFactory` in both `shopify-app-remix` and `shopify-app-react-router`) authenticates an incoming webhook purely by re-computing an HMAC over the raw request body and comparing it to the `X-Shopify-Hmac-Sha256` header, via `validateHmacFromRequestFactory` → `validateHmacString`: [1](#0-0) 

Only `rawBody` is fed into `createSHA256HMAC`/`validateHmacString`; none of the identifying headers — `X-Shopify-Shop-Domain`, `X-Shopify-Topic`, `X-Shopify-Webhook-Id`, `X-Shopify-API-Version` — are part of the signed data: [2](#0-1) 

After HMAC validation succeeds, `validateFactory` reads those same unsigned headers directly off the request and returns them as trusted (`domain`, `topic`, `webhookId`, `apiVersion`) with no cross-check against the signed body: [3](#0-2) 

This is exactly the Golom bug class: the check that is cryptographically enforced (`rawBody` HMAC) is disjoint from the attacker-controlled, business-critical field (`domain`/`topic`), which is smuggled in through an unchecked channel — here, plain unsigned HTTP headers instead of `order.root`.

Downstream, `authenticateWebhookFactory` takes `check.domain` (attacker-controllable) and uses it to look up/create an **offline session and admin API client** for that shop: [4](#0-3) [5](#0-4) 

### Impact Explanation
Because the app's API secret is shared across every shop that has the app installed (it's the app-level secret, not per-shop), any merchant/attacker who has the app installed on their own store can:
1. Trigger a legitimate webhook event on their own shop, capturing a valid `(rawBody, X-Shopify-Hmac-Sha256)` pair.
2. Replay that exact body+HMAC pair to the app's webhook endpoint, but substitute the `X-Shopify-Shop-Domain` header with a victim shop's domain (any shop that has the app installed) and/or the `X-Shopify-Topic` header with an arbitrary topic value.
3. Since the HMAC check only validates the body, the forged request passes `webhooks.validate` as `valid: true` with `domain` = victim shop.
4. `authenticate.webhook()` then loads/creates the **victim's offline session and Admin API client**, and invokes the app's webhook handler as if the event genuinely originated from the victim shop, with an attacker-chosen `topic` and attacker-controlled JSON body (limited to whatever payload they could produce from their own store's real event).

This is a cross-tenant forged-request vulnerability: it lets one merchant impersonate webhook deliveries for another shop, potentially triggering privileged app logic (e.g., `app/uninstalled` cleanup, order/customer data handlers, GDPR webhooks) against a shop the attacker doesn't own, using that shop's own stored offline access token via the `admin` client the framework attaches to the webhook context.

### Likelihood Explanation
Reachable from a single unprivileged actor: any merchant who installs the app (a normal, unprivileged onboarding action) can capture a genuine signed webhook from their own store and replay it with modified headers against the same public webhook endpoint. No secret leakage, MITM, or privileged access is required — only knowledge of the target's shop domain, which is often discoverable/guessable (`*.myshopify.com`) or obtainable via the app's own install list if the app is public.

### Recommendation
Bind the identifying headers to the signature verification instead of trusting them independently:
- Include `X-Shopify-Shop-Domain`, `X-Shopify-Topic`, and `X-Shopify-Webhook-Id` in the HMAC-signed material (this must match what Shopify actually signs; if Shopify itself only signs the body, the app-side mitigation is to verify that `domain` corresponds to a shop session that the app expects and was recently associated with a legitimate OAuth/install flow, and to rate-limit/monitor for header/body mismatches).
- At minimum, add a defense-in-depth check comparable to Golom's fix (`o.totalAmt * amount * 15/100 >= p.paymentAmt`): verify that the `domain` header's shop actually corresponds to an active, previously-established session before trusting it, and consider requiring Shopify's source IP allowlist or mTLS for webhook delivery in addition to HMAC.
- Document this limitation prominently since it is inherent to how Shopify's `X-Shopify-Hmac-Sha256` is defined (signs body only) — app developers relying solely on `shopify.webhooks.validate()`'s `domain`/`topic` output for authorization decisions should be warned this data is unauthenticated.

### Proof of Concept
1. Install the app on a shop you control (`attacker-shop.myshopify.com`).
2. Trigger any webhook topic the app subscribes to (e.g. create a product) and capture the raw POST request to your webhook endpoint, including the `X-Shopify-Hmac-Sha256` header and raw body.
3. Replay the identical body and `X-Shopify-Hmac-Sha256` value to the same endpoint, but set:
   - `X-Shopify-Shop-Domain: victim-shop.myshopify.com`
   - `X-Shopify-Topic: app/uninstalled` (or any other subscribed topic)
   - `X-Shopify-Webhook-Id`, `X-Shopify-API-Version` set to plausible values.
4. Observe that `shopify.webhooks.validate()` returns `{valid: true, domain: 'victim-shop.myshopify.com', topic: 'APP_UNINSTALLED', ...}` because only the body's HMAC was checked.
5. Observe that `authenticate.webhook()` then loads/creates the victim shop's offline session and attaches an authenticated `admin` client to the webhook context, letting the attacker-controlled handler code run business logic against the victim's shop.

*Note: I could not fully verify whether Shopify's real webhook delivery signs additional header data server-side (outside this repo) — the analysis is based solely on what this codebase itself checks. If Shopify's actual signing scheme also excludes these headers (which matches public documentation stating the HMAC covers only the raw body), the vulnerability is real and inherent to trusting these headers as authenticated.*

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };

export function validateFactory(config: ConfigInterface) {
  return async function validate({
    rawBody,
    ...adapterArgs
  }: WebhookValidateParams): Promise<WebhookValidation> {
    const request: NormalizedRequest =
      await abstractConvertRequest(adapterArgs);

    const webhookType = detectWebhookType(request.headers);

    const validHmacResult = await validateHmacFromRequestFactory(config)({
      type: HmacValidationType.Webhook,
      rawBody,
      webhookType,
      ...adapterArgs,
    });

    if (!validHmacResult.valid) {
      if (validHmacResult.reason === ValidationErrorReason.InvalidHmac) {
        const log = logger(config);
        await log.debug(
          "Webhook HMAC validation failed. Please note that events manually triggered from a store's Notifications settings will fail this validation. To test this, please use the CLI or trigger the actual event in a development store.",
        );
      }
      return validHmacResult;
    }

    return checkWebhookHeaders(request.headers, webhookType);
  };
}

function getRequiredHeader(
  headers: Headers,
  headerName: string,
  missingHeaders: string[],
): string | undefined {
  const value = getHeader(headers, headerName);
  if (!value) {
    missingHeaders.push(headerName);
  }
  return value;
}

function checkWebhookHeaders(
  headers: Headers,
  webhookType: WebhookTypeValue,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  if (webhookType === WebhookType.Webhooks) {
    return checkWebhooksHeaders(headers);
  }
  return checkEventsHeaders(headers);
}

function checkWebhooksHeaders(
  headers: Headers,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };

  const name = getHeader(headers, headerNames.name);
  if (name) fields.name = name;

  const triggeredAt = getHeader(headers, headerNames.triggeredAt);
  if (triggeredAt) fields.triggeredAt = triggeredAt;

  const eventId = getHeader(headers, headerNames.eventId);
  if (eventId) fields.eventId = eventId;

  return {valid: true, ...fields};
}

export async function ensureValidOfflineSession(
  params: BasicParams,
  shop: string,
) {
  const session = await createOrLoadOfflineSession(params, shop);

  if (!session) return undefined;

  return ensureOfflineTokenIsNotExpired(session, params, shop);
}
