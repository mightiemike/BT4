## Analog Found

### Title
Swap slippage protection in inbound gas/refund auto-swap paths is derived from a manipulable spot quote with no independent price reference, enabling sandwich extraction of user funds - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The H-2 report flags that Real Wagmi's `rebalanceAll` withdrew/deposited liquidity with no slippage bound at all, letting LPs be sandwiched; the fix added a `_checkPriceDeviation` guard comparing against a weighted-average reference price rather than trusting the spot pool state. Push Chain's inbound-gas auto-swap and outbound gas-refund auto-swap paths do compute a `minPCOut`, but it is derived entirely from a `GetSwapQuote` call made against the live pool immediately before the swap executes, with only a fixed 5% tolerance and no reference to an independent/TWAP price. This reproduces the same underlying flaw the Sherlock report targeted: slippage protection anchored to a spot price that an unprivileged actor can move just before the protected call executes.

### Finding Description
`GetSwapQuote` reads `QuoterV2.quoteExactInputSingle` against the live AMM pool state at call time: [1](#0-0) 

This quote is then turned into a `minPCOut` bound with a hardcoded ±5% tolerance and passed straight into the swap call, in both the inbound gas-deposit path: [2](#0-1) 

and the gas-and-payload inbound path: [3](#0-2) 

and the outbound gas-refund path (`applyGasRefund`), which similarly quotes then swaps with a 5% band derived from the same just-fetched price: [4](#0-3) 

None of these paths compare the quote against any independent reference (e.g., a TWAP, a weighted average across recent blocks, or an oracle) — exactly the gap the Real Wagmi report's fix (`_checkPriceDeviation`) closed. Because `GetSwapQuote` and the swap execution both read/act on the pool's current spot state, an unprivileged actor who can trade against the same Uniswap-V3-style pool referenced by `UNIVERSAL_CORE`/quoter can push the spot price to an unfavorable level immediately before the module's automated deposit-and-swap or refund-and-swap executes (e.g., by ordering a large trade transaction ahead of the block/tx in which a `MsgVoteInbound`/`MsgVoteOutbound` reaches quorum and triggers these keeper calls), causing the module to accept a materially worse output for the user while remaining "within tolerance" of the already-manipulated price, then reverse the trade afterward to capture the difference. This is a classic sandwich attack on a fixed-percent-of-spot slippage check.

### Impact Explanation
This directly corrupts gas-fee accounting and refund accounting reachable from ordinary user deposits (an inbound funds/gas transfer that triggers gasless PRC20-to-native swap, or an outbound gas refund) without requiring any malicious validator, relayer, or privileged actor — the trigger is simply an ordinary user's cross-chain transfer combined with an attacker trading on the destination pool. Users receive less PC (native gas token) than they should from `CallPRC20DepositAutoSwap` or `CallUniversalCoreRefundUnusedGas`, resulting in value extraction/loss for depositors and refund recipients, which falls within scope ("corruption of ... gas fee accounting, refund accounting ... PRC20 ... accounting").

### Likelihood Explanation
Likelihood is bounded by liquidity/depth of the relevant pool and the attacker's ability to control transaction ordering within a block (or across the quote-then-swap window), but requires no privileged role — any market participant able to trade on the referenced pool can attempt it, and the amounts (inbound deposit sizes) are attacker-observable from pending/finalized inbound votes before the swap executes.

### Recommendation
Do not derive `minPCOut` solely from a spot quote fetched immediately before execution. Compare the spot quote against an independent/TWAP-based reference price (or a recent moving average) and reject/fallback if the deviation between spot and reference exceeds a safety threshold, mirroring the `_checkPriceDeviation` fix pattern from the cited report, in addition to the existing fixed-percent `minPCOut` bound.

### Proof of Concept
1. Observe an in-flight `MsgVoteInbound` (funds/gas type) or a `MsgVoteOutbound` that will trigger `gasDepositAutoSwap`/`gasAndPayloadDepositAutoSwap`/`applyGasRefund` once quorum is reached.
2. Before the triggering vote lands (or in the same block, ordered earlier), submit a large swap against the PRC20/WPC pool referenced by `UniversalCore`'s quoter to move the spot price unfavorably for the pending auto-swap direction.
3. When quorum is reached, `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`) reads the now-manipulated spot price; `minPCOut` is computed as 95% of that already-bad quote and passed to `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas`, so the swap executes at the manipulated price without being rejected.
4. Reverse the initial trade afterward to realize the price difference as profit, at the expense of the deposit/refund recipient who receives less PC than fair value.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
```
