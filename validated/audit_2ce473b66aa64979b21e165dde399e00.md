## Title
Missing "class declared" check in the Starknet OS `execute_replace_class` allows blockifier/OS state divergence via `replace_class` syscall - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The blockifier's `replace_class` syscall handler validates that the target `class_hash` is declared (and is Cairo1) before mutating a contract's class hash. The Starknet OS re-execution path, which is supposed to faithfully re-derive the same state transition for proving/verification, has this validation explicitly missing (marked with a `TODO`), letting the OS unconditionally accept a `replace_class` to an *externally-controlled, undeclared* class hash.

### Finding Description
In the real sequencer execution path, `SyscallHandlerBase::replace_class` enforces that the class is declared before allowing the state mutation: [1](#0-0) 

This is invoked from both the Cairo1 VM and native syscall handlers: [2](#0-1) [3](#0-2) 

The deprecated (Cairo0) syscall path performs an equivalent check via `state.get_compiled_class`: [4](#0-3) 

In contrast, the Starknet OS's Cairo implementation of `execute_replace_class` — used to re-execute/prove the block for state-commitment purposes — explicitly skips this check, as marked by a TODO comment, and unconditionally writes the caller-supplied `class_hash` into `contract_state_changes`: [5](#0-4) 

Because a `class_hash` value passed to `replace_class` is entirely attacker/contract-controlled (any contract can call this syscall on itself), an attacker-crafted contract can invoke `replace_class_syscall(garbage_or_undeclared_hash)` and, instead of using `.unwrap_syscall()` (which panics on error), explicitly handle the `Result::Err` returned by blockifier's validation and continue execution successfully. In this scenario:
- Blockifier (actual sequencer execution, used to build the block and compute the "real" state) returns an error from `replace_class`, the calling contract catches it and does not change the class hash — the transaction succeeds without any class-hash mutation.
- The Starknet OS re-execution (used to generate the STARK proof and the state commitment that is ultimately what other nodes / L1 rely on) performs no such check, so it accepts the syscall unconditionally and commits the class-hash change to `contract_state_changes`, with no code path forcing a revert (there is no panic to trigger the revert-log rollback, since the "syscall" itself succeeded from the OS's perspective).

This produces two different post-state values for the same contract's class hash between the sequencer's blockifier execution and the OS's proven execution of the identical block/transaction.

### Impact Explanation
This is a root-cause-level divergence between the state actually committed by the sequencer (blockifier) and the state proven/committed by the Starknet OS. Because the state root anchored on L1 and referenced by other full nodes for sync/validation is derived from the OS execution, this can:
- Corrupt a victim contract's class hash to an arbitrary, likely non-existent/garbage value in the OS-derived state (functionally freezing/bricking the contract permanently, since future calls to it would use an undeclared/invalid class), while the sequencer's local execution shows no such change — an honest-node divergence.
- Cause the network to be unable to reconcile the sequencer-committed state with the OS-proven state, undermining the ability to confirm/attest to new blocks correctly.

This satisfies the "wrong committed root" / "honest-node divergence" impact criteria, and is reachable from a single, unprivileged, user-submitted invoke transaction (no privileged operator/proposer role required) — matching the required threat model of the analog (arbitrary/externally-controlled selection of a "class" without a mediated privilege check, akin to CVE-2019-10174's unchecked reflection into arbitrary target code).

### Likelihood Explanation
High practical likelihood: `replace_class` is a standard, documented syscall available to any Cairo1 contract; catching a syscall `Result::Err` instead of calling `.unwrap_syscall()` is common, legitimate defensive coding (e.g., in multicall/try-execute wrapper patterns), so no unusual or exotic contract behavior is required — only that the contract chooses to swallow the syscall failure rather than panic. The bug is explicitly flagged as an outstanding `TODO` in the OS source, confirming it is a known, currently-unaddressed gap rather than a hypothetical.

### Recommendation
Add the same "class must be declared" check (and the Cairo1-class-type check for parity with the blockifier's `is_cairo1` check) to `execute_replace_class` in `crates/apollo_starknet_os_program/.../syscall_impls.cairo` before writing the new `StateEntry` to `contract_state_changes`, mirroring `SyscallHandlerBase::replace_class` in `crates/blockifier/src/execution/syscalls/syscall_base.rs`. Verify the same check exists (or add it) in the deprecated/Cairo0 OS path (`deprecated_execute_syscalls.cairo::execute_replace_class`) as well, and add a regression test asserting that OS and blockifier reject/accept `replace_class` identically for both declared and undeclared class hashes.

### Proof of Concept
1. Deploy a Cairo1 contract with an external function that calls `replace_class_syscall(UNDECLARED_HASH)` and explicitly matches on the returned `Result`, ignoring the `Err` case (i.e., does not call `.unwrap_syscall()`), then returns success.
2. Submit an invoke transaction from an unprivileged account calling this function with an arbitrary/undeclared `class_hash` felt.
3. Observe: blockifier execution succeeds with no class-hash change (since `get_compiled_class` fails inside `replace_class`, the error is caught by the contract, and no `set_class_hash_at` occurs).
4. Re-execute the same block through the Starknet OS (`execute_replace_class` in `syscall_impls.cairo`): since no declared-class check exists, the OS unconditionally updates `contract_state_changes` for the contract to the undeclared `class_hash`, with no revert triggered.
5. Diff the state commitments produced by blockifier vs. the OS for the affected contract's class hash — they differ, demonstrating the divergence.

Note: I was not able to trace, within the tool budget available, the full downstream code that consumes `contract_state_changes` from the OS to build the final committed state root (e.g., the exact Patricia-tree commitment logic), so I could not directly confirm the very last step of "wrong root gets externally posted/verified" beyond the state-diff level shown above; this should be validated end-to-end by a follow-up engineer with full repository access.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
