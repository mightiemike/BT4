### Title
pprof debug endpoints mounted under authenticated-only `authv2` group without role gating, allowing view-role users to exhaust CPU/read memory profiles - ([File: core/web/router.go])

### Summary
`metricRoutes(authv2)` is called at `core/web/router.go` line 446, mounting `net/http/pprof`'s `Index`, `Cmdline`, `Profile`, `Symbol`, `Trace`, `Handler("allocs"/"block"/"goroutine"/"heap"/"mutex"/"threadcreate")` handlers directly under `/v2/debug/pprof/*` inside the `authv2` group, which is only wrapped with `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`. Unlike every other sensitive handler in that same group (e.g. `/keys/*`, `/users`, `/vault/*`), none of the pprof routes are wrapped with `auth.RequiresEditRole` or `auth.RequiresAdminRole`, so any authenticated user regardless of role — including `UserRoleView` — can hit them.

### Finding Description
In `core/web/router.go`, `v2Routes` builds `authv2` at lines 245-248 with only session/token authentication (no role check). Inside that group, virtually all state-changing or sensitive read endpoints are explicitly wrapped with `auth.RequiresEditRole` or `auth.RequiresAdminRole` (e.g. lines 251-254, 265-266, 270-273, 276-282, 311-320, etc.), and `auth.RequiresRunRole` is used for job/run triggering endpoints. However, at line 446, `metricRoutes(authv2)` is called with no role wrapper at all, and inside `metricRoutes` (lines 185-199) each pprof route (`/`, `/cmdline`, `/profile`, `/symbol` GET/POST, `/trace`, `/allocs`, `/block`, `/goroutine`, `/heap`, `/mutex`, `/threadcreate`) is registered directly against the raw `pprof.*` handlers via `ginHandlerFromHTTP`, bypassing gin's normal handler-based role checks (`RequiresAdminRole`/`RequiresEditRole`/`RequiresRunRole`) used elsewhere in `auth/auth.go` (lines 202-255).

By contrast, `debugRoutes` (lines 180-183) at least requires `auth.AuthenticateBySession` for `/debug/vars` — but is *also* not role-gated, though it only exposes public Go runtime metrics (`expvar`), not full pprof profiling/heap dump/goroutine stack capability, and not by token (only session).

Any user with a valid API token or session at `UserRoleView` (the lowest role) authenticates successfully via `auth.AuthenticateByToken`/`AuthenticateBySession` (auth.go lines 55-114), passes into the `authv2` group, and can directly call `GET /v2/debug/pprof/profile?seconds=N`, `/v2/debug/pprof/heap`, `/v2/debug/pprof/goroutine?debug=2`, or `/v2/debug/pprof/trace?seconds=N` with no further role check, since these routes have no `auth.RequiresXRole` wrapper in `metricRoutes`.

### Impact Explanation
- **DoS**: `pprof.Profile` and `pprof.Trace` accept an arbitrary `seconds` query parameter, letting an unprivileged (view-only) authenticated caller pin CPU tracing/profiling for the requested duration, repeatable in parallel across many concurrent requests to degrade node responsiveness and interfere with OCR/consensus timing-sensitive duties.
- **Secret/memory disclosure risk**: `/heap`, `/goroutine?debug=2`, and full-memory heap dumps can expose stack traces, in-flight data structures, and potentially sensitive in-memory material (e.g., decrypted keys, secrets, request payloads) depending on runtime state, to a caller who should only have read-only, view-level API access.
- This breaks the invariant that sensitive introspection/debug endpoints should be gated at least at admin (or equivalent elevated) role, matching the same pattern already applied to `/keys/*`, `/vault/*`, and `/users` in the same file.

### Likelihood Explanation
High feasibility and full repeatability: the only precondition is possession of any valid view-role API token or session — the lowest privilege tier issued to ordinary users — with no additional bypass, exploit chain, or timing dependency required. The request is a simple authenticated `GET`, directly reachable through the standard `/v2` API surface.

### Recommendation
Wrap all routes registered in `metricRoutes` with `auth.RequiresAdminRole` (consistent with other sensitive endpoints such as `/keys/*/export`, `/keys/*/import`, `/users`, `/vault/*`), e.g.:
```go
pprofGroup.GET("/profile", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Profile)))
```
applied uniformly to every path in `metricRoutes` (`core/web/router.go` lines 185-199), and consider similarly gating `debugRoutes`'s `/debug/vars` (line 182) if it can expose internal state beyond acceptable disclosure for non-admin roles.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least

func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {

		if !ok {
			c.Abort()

			c.Abort()

			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
