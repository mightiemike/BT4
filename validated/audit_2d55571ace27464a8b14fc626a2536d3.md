### Title
Privileged WebContents exposes full MojoJS surface to arbitrary renderer origins without capability-allowlist check - (File: chrome/browser/geic/geic_pwc_manager.cc)

### Summary
The GEiC `GeicPwcManager` enables MojoJS bindings for every primary-main-frame render process in a `PrivilegedWebContents`, but does not verify the committed origin against the capability allowlist. This is the same access-control mistake as `BribeVault.depositBribeERC20` being callable by any `DEPOSITOR_ROLE` holder instead of only `TokemakBribe`: a privileged capability surface is gated on a coarse identity (PWC / primary main frame) rather than on the authorized caller origin. A compromised renderer or a cross-origin navigation inside the PWC can therefore bind powerful browser Mojo interfaces that were intended only for the allowlisted GEiC guest origin.

### Finding Description
`GeicPwcManager::TabEntry::RenderFrameCreated` and `ReadyToCommitNavigation` call `render_frame_host->EnableMojoJsBindings(/*features=*/nullptr)` whenever the frame is in the primary main frame, with no origin check. The code contains an explicit TODO acknowledging the bug:

> "Prototype shortcut. This exposes the entire Mojo surface rather than only GeicApi, and the committed origin is not checked against the capability allowlist here." [1](#0-0) 

The same TODO is repeated in `ChromeContentBrowserClient::ShouldAllowMojoJsBindingsForFrame`, which is the predicate that ultimately authorizes MojoJS for these frames:

> "Enabling MojoJS for any PWC exposes the entire Mojo interface surface rather than only GeicApi, and the committed origin is not checked against the capability allowlist here." [2](#0-1) 

The capability allowlist is created in `GeicPwcManager::GetOrCreateWebContentsForTab` and contains only the configured GEiC guest origin, but it is never consulted when MojoJS is enabled:

> `auto policy_delegate = std::make_unique<pwc::FixedPwcPolicyDelegate>(/*navigation_allowlist=*/std::vector<url::Origin>{origin}, /*capability_allowlist=*/std::vector<url::Origin>{origin});` [3](#0-2) 

### Impact Explanation
MojoJS exposes the full browser-side Mojo interface surface to JavaScript in the renderer. If an attacker can navigate the PWC to an attacker-controlled origin (or compromise the renderer process and forge Mojo bind requests), the attacker can invoke browser interfaces that are normally unreachable from web content. Because `EnableMojoJsBindings` is granted to the primary main frame regardless of origin, this bypasses the intended origin-based capability boundary. The impact is a sandbox escape / SOP bypass primitive: arbitrary JavaScript in the renderer can talk directly to browser Mojo services, read or mutate browser state, and potentially escalate to code execution or universal XSS.

### Likelihood Explanation
The likelihood is medium-to-high. The PWC is designed to load a specific, allowlisted GEiC guest URL, but the navigation allowlist and capability allowlist are enforced elsewhere, not at the point MojoJS is enabled. A renderer compromise is sufficient to exploit this, and the PWC itself is a high-value target because it is intentionally given extra capabilities. Additionally, any navigation bug that allows the PWC to commit a non-allowlisted origin automatically gains MojoJS. The code explicitly flags this as a known prototype shortcut, indicating the vulnerability is present in the current implementation.

### Recommendation
Do not enable MojoJS globally for the primary main frame of a PWC. Instead:
1. Gate `EnableMojoJsBindings` on `IsOriginAllowedForGeicApi(render_frame_host->GetLastCommittedOrigin())` or compare against the `capability_allowlist` stored in the PWC policy delegate.
2. Prefer per-interface binding (e.g., `BindGeicApi`) that calls `pwc::EnforceCapabilityGate(render_frame_host)` and verifies `privileged->component() == pwc::PrivilegedComponent::kGeic`, as already done for `geic::mojom::GeicApi` and `geic::mojom::GeicBrowserHost`. [4](#0-3) [5](#0-4) 
3. Remove the prototype TODO once the origin check is enforced.

### Proof of Concept
1. An attacker compromises the renderer process hosting the GEiC PWC (e.g., via a V8 or Blink bug reachable from the guest page, or by tricking the PWC into navigating to an attacker origin).
2. The compromised renderer calls `Mojo.bindInterface` for any browser-side Mojo interface.
3. Because `GeicPwcManager::TabEntry::RenderFrameCreated` / `ReadyToCommitNavigation` already enabled MojoJS for the primary main frame without checking origin, the bind request is accepted.
4. The attacker can now invoke arbitrary browser Mojo interfaces from JavaScript, escaping the normal renderer sandbox and origin boundaries.

void BindGeicBrowserHost(
    content::RenderFrameHost* rfh,
    mojo::PendingReceiver<mojom::GeicBrowserHost> receiver) {
  pwc::PrivilegedWebContents* privileged = pwc::EnforceCapabilityGate(rfh);
  if (!privileged) {
    return;
  }

  if (privileged->component() != pwc::PrivilegedComponent::kGeic) {

  auto* manager = GeicPwcManager::GetOrCreateForProfile(profile);
  if (manager) {
    GeicBrowserHostImpl* host = manager->GetBrowserHostForPwc(privileged);
    if (host) {
      host->BindBrowserHost(std::move(receiver));
    }
  }
}

void BindGeicApi(content::RenderFrameHost* render_frame_host,
                 mojo::PendingReceiver<mojom::GeicApi> receiver) {
  // The shared gate enforces the full capability policy (and terminates the
  // renderer itself on a renderer-controllable violation); null simply means
  // do not bind.
  pwc::PrivilegedWebContents* privileged =
      pwc::EnforceCapabilityGate(render_frame_host);
  if (!privileged) {
    return;
  }

  // The gate is component-agnostic; GeicApi additionally requires the
  // component to be GEIC. A request from another component's frame is again a
  // compromised renderer.
  if (privileged->component() != pwc::PrivilegedComponent::kGeic) {
    bad_message::ReceivedBadMessage(render_frame_host->GetProcess(),
                                    bad_message::PWC_BRIDGE_UNQUALIFIED_FRAME);
    return;
  }

  if (!GeicHost::Get(privileged->unowned_user_data_host())) {
    // The frame qualifies, but the GEIC component has not attached its GeicHost
    // to this PrivilegedWebContents. That is a browser-side setup gap, not a
    // compromised renderer, so drop the request rather than terminating the
    // renderer.
    return;
  }
  GeicApiBinding::Create(render_frame_host, std::move(receiver));
}
