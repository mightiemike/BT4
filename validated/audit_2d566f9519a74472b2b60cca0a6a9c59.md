### Title
Missing declared-class validation in Starknet OS `replace_class` syscall allows honest-node state divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Cairo Starknet OS implementation of `execute_replace_class` writes an attacker-supplied `class_hash` into a contract's state entry without ever checking that the class hash was actually declared, while the equivalent Rust blockifier path enforces this check. This is analogous to CVE-2026-63300 (LXD instance migration): a security-relevant validation performed in one enforcement path (blockifier execution) is silently skipped in another path that is supposed to reproduce the identical state transition (the Starknet OS re-execution used to produce the committed state root / proof).

### Finding Description
The blockifier's `replace_class` syscall handler explicitly re-reads the compiled class before mutating the class hash of a contract, rejecting undeclared class hashes: [1](#0-0) 

The current (non-deprecated) syscall variant likewise routes through `self.base.replace_class(...)`, which performs the same "class must be declared" check (confirmed by the test error string `"is not declared"`): [2](#0-1) 

In contrast, the Cairo program that implements the Starknet OS's own version of this syscall (used to re-execute the block, compute the state diff, and produce/verify the proof) contains an explicit, unresolved `TODO` noting the check is missing, and simply overwrites the `class_hash` field of the contract's `StateEntry` unconditionally: [3](#0-2) 

The Rust-side SNOS syscall executor (`SnosHintProcessor`) for `replace_class` is also a no-op that performs no validation and simply returns success: [4](#0-3) 

Because the sequencer's blockifier (which builds/executes the actual block) enforces "class must be declared" while the OS re-execution path that recomputes/attests to the resulting state transition does not, the two components can disagree about whether a `replace_class` syscall succeeds and what state diff it produces for the same transaction, in the same way the LXD bug allowed an instance to be moved into a restricted project without the target context re-validating the configuration that the origin context had already validated.

### Impact Explanation
The Starknet OS's re-execution is the authority that recomputes/attests to the resulting state diff and is used to certify the correctness of the sequencer's block execution (via the Cairo VM hint-driven re-run and STARK proof). If the OS is willing to accept a `replace_class` to an undeclared class hash while the blockifier is not (or vice versa in edge cases where the two components diverge on which classes are considered "declared" mid-block), the OS-certified state diff can differ from the blockifier's actually-committed state diff for the same transaction. This falls under "wrong committed root or block hash / honest-node divergence" — a state root computed and proven by the OS could disagree with the state actually applied by the block-building blockifier, undermining the guarantee that the proof faithfully attests to the sequencer's execution.

### Likelihood Explanation
Any unprivileged contract deployer can trivially trigger `replace_class` from within a Cairo1 or Cairo0 contract with an attacker-chosen `class_hash` argument (as demonstrated by the existing test harness for this syscall), requiring no special permissions — analogous to the "authenticated attacker with can_create_instances" precondition in the LXD CVE which required only baseline permissions, not administrative access.

### Recommendation
Implement the same "class hash must be declared" check in the Cairo OS `execute_replace_class` function (resolving the existing `TODO(Yoni, 1/1/2026)`) and in `SnosHintProcessor::replace_class`, mirroring the blockifier's `syscall_base.rs` logic that queries `get_compiled_class`/declared-class state before allowing the class hash swap, ensuring both execution paths enforce identical validation and cannot diverge on accepted/rejected `replace_class` calls.

### Proof of Concept
1. Deploy a contract exposing `test_replace_class(class_hash)`, as in the existing test contract: [5](#0-4) 
2. Invoke it with an undeclared/arbitrary `class_hash` felt (e.g., `1234`).
3. In the blockifier execution path, the call fails with `"... is not declared"` (see test assertions): [2](#0-1) 
4. In the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo` / `SnosHintProcessor::replace_class`), no such check exists — the class-hash overwrite is unconditionally accepted, producing a divergent view of whether/what state change occurred for this transaction between the blockifier and the OS.

Note: I was not able to fully trace how the `SnosHintProcessor`'s reliance on pre-computed `call_info_tracker` execution traces (fed from the blockifier's own execution) might mask this divergence in the currently-implemented OS-runner test flows (e.g., whether the OS strictly replays blockifier-approved traces rather than independently validating). This nuance affects exactly how/when the divergence becomes exploitable versus purely dormant, and would benefit from further investigation with the actual OS/proof pipeline execution rather than static code review alone.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
