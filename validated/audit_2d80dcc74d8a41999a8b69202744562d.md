## Summary

The external report's core theme — two structurally similar operations that are supposed to enforce different semantics being conflated so that a critical check silently doesn't happen — has a concrete Aptos-native analog in the transaction replay/proof-verification path: `TransactionOutput::ensure_match_transaction_info` in `types/src/transaction/mod.rs` verifies status, gas, write-set hash, and event root hash against an authenticated `TransactionInfo`, but explicitly skips comparing the state-checkpoint hash fields, even though the function's own doc/TODO says this lets `db-tool`'s `replay_on_archive` report a "successful replay" while the state root actually diverges.

### Title
Replay-verification skips state-checkpoint-hash comparison, allowing a divergent state root to pass as verified - (File: `types/src/transaction/mod.rs`)

### Finding Description
`TransactionOutput::ensure_match_transaction_info` is the function used to prove that a locally re-executed transaction output matches the authenticated `TransactionInfo` pulled from a backup/archive. It checks `status`, `gas_used`, the write-set hash against `state_change_hash`, and the event root hash, but it explicitly does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`: [1](#0-0) 

The function's own comment acknowledges the gap: it says the comparator "ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`), so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution." [2](#0-1) 

`TransactionInfoV0`/`V1` carry `state_checkpoint_hash` (the Sparse-Merkle-Tree root of world state) as a first-class, always-populated field — it is not gated behind any experimental feature — while `position_state_checkpoint_hash` is the trading-native-specific field gated by `COMPUTE_TRADING_NATIVE_STATE_ROOTS`. [3](#0-2) 

`storage/db-tool/src/replay_on_archive.rs` is exactly the "replay-verify" tool the TODO calls out: it fetches `expected_txn_infos`/`expected_writesets`/`expected_events` from a backup and calls `execute_and_verify` to compare against locally re-executed output. [4](#0-3) 

Separately, the same `ensure_match_transaction_info` helper is used interactively by the CLI's transaction-replay/debugger command to validate a locally re-executed system transaction against the authenticated on-chain `TransactionInfo`: [5](#0-4) 

By contrast, the analogous full-node proof-verification path (`TransactionOutputListWithProof::verify`) also omits any state-checkpoint-hash comparison — it only checks events, write-set hash, gas, status, and transaction hash before delegating to the accumulator proof: [6](#0-5) 

This means the one committed value that actually represents "the world state" — the Merkle root over all account/resource/table state — is not part of the invariant these verification routines enforce, even though it is present, authenticated (accumulator-proven via the enclosing `TransactionInfo` hash), and readily available for comparison.

### Impact Explanation
If VM execution (or a storage/write-set-application bug, or a hard-fork-only divergence in state materialization) produces a `state_checkpoint_hash` that differs from the archived/authenticated one while write-set bytes, events, gas, and status coincidentally still match (or the divergence is in code paths not reflected in `write_set` — e.g., is derived independently by the storage layer when computing the SMT root), `ensure_match_transaction_info` and `TransactionOutputListWithProof::verify` will both report success. This directly undermines the purpose of replay-verify (`replay_on_archive`, `ReplayVerifyCoordinator`) and of the CLI debugger's replay-sanity check: they exist specifically to catch state divergence between independently computed execution and the authenticated ledger, and the state root is the strongest, most compact signal of "does committed state match." A silently-accepted wrong root during backup/restore verification, or during ad-hoc replay debugging, is a hard-fork-class integrity gap under the prompt's gate ("Wrong accumulator root... or state proof accepted as valid").

### Likelihood Explanation
This requires a pre-existing state-divergence bug elsewhere (e.g. in `WriteSet` application to the SMT, or a not-yet-enabled `COMPUTE_TRADING_NATIVE_STATE_ROOTS` codepath) to actually produce a diverging root; the gap itself is a missing check, not by itself an exploitable primitive. The severity is real but likelihood of triggering it depends on an independent state-computation bug being present and going undetected specifically because this verification layer does not check the field that would catch it. I could not fully confirm (tool budget exhausted) whether `execute_and_verify` in `replay_on_archive.rs` calls `ensure_match_transaction_info` directly or does its own separate comparison that might already check `state_checkpoint_hash`; this should be verified by reading `storage/db-tool/src/replay_on_archive.rs` lines ~136-211 (the `execute_and_verify` body) in a follow-up session with full file access.

### Recommendation
Extend `ensure_match_transaction_info` (and `TransactionOutputListWithProof::verify`) to compare locally computed `state_checkpoint_hash` / `hot_state_checkpoint_hash` (and, once `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled, `position_state_checkpoint_hash`) against the values carried in the authenticated `TransactionInfo`, at least whenever the local caller has the corresponding root available (e.g., after a full state-checkpoint boundary). Do this before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, as the code comment itself suggests, but also address the pre-existing gap for the plain `state_checkpoint_hash`, which is already active on mainnet and not feature-gated.

### Proof of Concept
Not applicable as a live exploit — this is a missing-invariant defect confirmed by direct code inspection: `ensure_match_transaction_info` (`types/src/transaction/mod.rs:2139-2204`) never reads `txn_info.state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, or `position_state_checkpoint_hash()`, and its own inline comment documents the exact resulting blind spot in `replay_on_archive`.

**Confidence/limitations**: I was unable to open the full body of `execute_and_verify` in `storage/db-tool/src/replay_on_archive.rs` (lines ~136-211) before the tool budget ran out, so I cannot 100% confirm it relies solely on `ensure_match_transaction_info` versus performing an additional independent state-root check. The core defect — that `ensure_match_transaction_info` and `TransactionOutputListWithProof::verify` omit state-checkpoint-hash comparison — is directly confirmed in code and by the authors' own TODO comment.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    // Execute the verify one valid range
    pub fn verify(&self, start: Version, limit: u64) -> Result<Vec<Error>> {
        let mut total_failed_txns = Vec::with_capacity(limit as usize);
        let txn_iter = self
            .backup_handler
            .get_transaction_iter(start, limit as usize)?;
        let mut cur_txns = Vec::with_capacity(limit as usize);
        let mut cur_persisted_aux_info = Vec::with_capacity(limit as usize);
        let mut expected_events = Vec::with_capacity(limit as usize);
        let mut expected_writesets = Vec::with_capacity(limit as usize);
        let mut expected_txn_infos = Vec::with_capacity(limit as usize);
        let mut chunk_start_version = start;
        let executor = AptosVMBlockExecutor::new();
        for item in txn_iter {
            // timeout check
            if let Some(duration) = self.timeout_secs {
                if self.replay_stat.get_elapsed_secs() >= duration {
                    bail!(
                        "Verify timeout: {}s elapsed. Deadline: {}s. Failed txns count: {}",
                        self.replay_stat.get_elapsed_secs(),
                        duration,
                        total_failed_txns.len(),
                    );
                }
            }

            let (
                input_txn,
                persisted_aux_info,
                expected_txn_info,
                expected_event,
                expected_writeset,
            ) = item?;
            let is_epoch_ending = expected_event.iter().any(ContractEvent::is_new_epoch_event);
            cur_txns.push(input_txn);
            cur_persisted_aux_info.push(persisted_aux_info);
            expected_txn_infos.push(expected_txn_info);
            expected_events.push(expected_event);
            expected_writesets.push(expected_writeset);
            if is_epoch_ending || cur_txns.len() >= self.chunk_size {
                let cnt = cur_txns.len();
                while !cur_txns.is_empty() {
                    // verify results
                    let failed_txn_opt = self.execute_and_verify(
                        &executor,
                        &mut chunk_start_version,
                        &mut cur_txns,
                        &mut cur_persisted_aux_info,
                        &mut expected_txn_infos,
                        &mut expected_events,
                        &mut expected_writesets,
                    )?;
                    // collect failed transactions
                    total_failed_txns.extend(failed_txn_opt);
                }
                self.replay_stat.update_cnt(cnt as u64);
                self.replay_stat.print_tps();
            }
        }
        // verify results
        let fail_txns = self.execute_and_verify(
            &executor,
            &mut chunk_start_version,
            &mut cur_txns,
            &mut cur_persisted_aux_info,
            &mut expected_txn_infos,
            &mut expected_events,
            &mut expected_writesets,
        )?;
        total_failed_txns.extend(fail_txns);
        Ok(total_failed_txns)
    }
