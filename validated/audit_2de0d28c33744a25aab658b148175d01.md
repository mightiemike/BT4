Confirmed: this is the `MsgExecutePayload` handler used directly by `MsgServer` — same pattern applies at line 87-97: `CallUEAExecutePayload` runs the EVM call directly on `sdkCtx` (not a temporary `CacheContext`), `DeductGasFeesFromReceipt` then debits/burns the computed gas cost, and only *after* that does the function check `execErr` and return it. In Cosmos SDK, a non-nil error returned from a `Msg` handler causes the entire transaction's state branch (everything written to the branched multistore during that message, including the already-executed `SendCoinsFromAccountToModule` + `BurnCoins` fee debit) to be discarded when the baseapp unwinds the tx. So whenever the UEA-side payload execution reverts (`execErr != nil`), the fee that was computed and "deducted" per `DeductGasFeesFromReceipt` never actually lands — it is rolled back along with the reverted EVM state.

### Title
Free EVM computation on reverted `MsgExecutePayload` — fee deduction is unwound together with the failed execution - (File: `x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`MsgExecutePayload` is a gasless message type [1](#0-0) , so no Cosmos-level fee is ever collected for it; the only compensation mechanism for the EVM computation it triggers is `DeductGasFeesFromReceipt`, which burns UPC from the UEA's balance based on `receipt.GasUsed` [2](#0-1) . In `Keeper.ExecutePayload`, this deduction happens on the live `sdkCtx`, but immediately afterward the function still returns `execErr` when the UEA call reverted [3](#0-2) .

### Finding Description
Cosmos SDK message handling wraps each `Msg` execution in a branched (cached) multistore; if the handler returns a non-nil error, `baseapp` discards all writes performed by that handler, including bank `SendCoinsFromAccountToModule`/`BurnCoins` calls made inside `DeductAndBurnFees` [4](#0-3) . Because `k.DeductGasFeesFromReceipt` is called on `sdkCtx` directly (not committed independently, e.g. via its own `CacheContext` + `writeCache()` before the `execErr` check), any fee that would have been "collected" for a reverted payload is unwound along with the reverted EVM state the moment `ExecutePayload` returns `execErr`.

This is functionally the same class of bug as the Ajna report: an operation that is supposed to leave the accounting invariant intact (gas consumed must be paid for) instead silently drops the compensating debit whenever a specific code path (execution failure) is hit, because the check/enforcement of the invariant happens in the wrong place relative to where state is finalized. The `ExecutePayloadV2` path (used for inbound-triggered flows) shows the team is aware this pattern is dangerous — it introduces a `CacheContext` specifically to stop a *failed fee deduction* from letting free EVM state changes through [5](#0-4)  — but it does not address the symmetric case where the fee succeeds and the EVM call itself reverts: `return receipt, execErr` is reached without calling `writeCache()`, so the successful fee burn is discarded too [6](#0-5) . The direct `MsgExecutePayload` handler (`ExecutePayload`, not V2) has the identical outcome for a different underlying reason (whole-tx rollback on returned error) [3](#0-2) .

### Impact Explanation
An unprivileged attacker who owns (or can compute a deterministic address for) a UEA can submit repeated `MsgExecutePayload` calls whose payload is engineered to perform expensive computation inside the target UEA/contract and then revert (e.g., near the end of execution). Because:
- the message is gasless at the Cosmos ante-handler layer [7](#0-6) ,
- and the UPC-denominated compensation computed in `DeductGasFeesFromReceipt` never survives the transaction rollback caused by `execErr`,

the attacker consumes real EVM computation on every Push Chain validator for zero cost, unboundedly. This is a validator resource-exhaustion / gas-griefing vector — an unauthorized, uncompensated module-originated EVM execution — reachable without any privileged role, matching the "gasless admission" and "universal execution path" allowed-impact categories (unauthorized UEA/CEA execution, DoS not at the network layer, reachable via default transaction submission).

### Likelihood Explanation
The trigger requires only a normal user-submitted `MsgExecutePayload` with a payload designed to revert after doing work; no validator collusion, no privileged access, and no cross-chain event/vote is needed since this message type takes effect directly without a ballot. The only friction is: (a) `GasLimit` in the `UniversalPayload` bounds how much a single call can do (`CalculateGasCost` checks `gasUsed <= abiPayload.GasLimit` before any deduction is attempted) [8](#0-7) , and (b) UEA auto-deploy requires the UEA to hold some balance already [9](#0-8) . Neither of these meaningfully blocks repeated free-execution spam once a UEA exists, since the attacker never needs the fee debit to actually succeed — they just need `execErr != nil`.

### Recommendation
Deduct and commit the gas fee independently of whether `execErr` is nil, so a reverted payload execution still pays for the computation it consumed:
- In `Keeper.ExecutePayload` / `ExecutePayloadV2`, perform `CallUEAExecutePayload` and `DeductGasFeesFromReceipt` in a `CacheContext`, call `writeCache()` unconditionally once the fee deduction itself succeeds (regardless of `execErr`), and only roll back the cache when the fee deduction fails (mirroring the existing rationale documented for the smart-contract inbound paths) [10](#0-9) .
- Ensure the outer `execErr` is still propagated/reported after the fee write is committed, so the tx correctly reflects failure while the fee remains charged.

### Proof of Concept
1. Deploy/derive a UEA with a small UPC balance sufficient to cover gas for one call.
2. Submit `MsgExecutePayload` with a `UniversalPayload.Data` that calls into the UEA/target contract to perform gas-heavy computation (loop, storage writes) and then explicitly reverts (e.g., calling a function that always reverts after the loop, within `GasLimit`).
3. Observe: `CallUEAExecutePayload` returns `execErr != nil` with `receipt.GasUsed` reflecting the consumed gas [11](#0-10) .
4. `DeductGasFeesFromReceipt` computes and attempts to burn the corresponding UPC amount from the UEA [12](#0-11) .
5. Because `ExecutePayload` subsequently returns `execErr`, the whole message's state branch (including the fee burn) is discarded by the SDK's tx handling; querying the UEA's UPC balance after the tx shows it is unchanged, confirming the computation was performed for free.
6. Repeat step 2 arbitrarily many times at zero net cost to the attacker (only the free-of-charge gasless Cosmos tx submission is required).

func (k Keeper) DeductAndBurnFees(ctx context.Context, from sdk.AccAddress, gasCost *big.Int) error {
	amt := sdkmath.NewIntFromBigInt(gasCost)
	coin := sdk.NewCoin(pchaintypes.BaseDenom, amt)

	k.Logger().Debug("deducting and burning fees",
		"from", from.String(),
		"gas_cost", gasCost.String(),
		"denom", pchaintypes.BaseDenom,
	)

	err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, from, types.ModuleName, sdk.NewCoins(coin))
	if err != nil {
		return err
	}

	return k.bankKeeper.BurnCoins(ctx, types.ModuleName, sdk.NewCoins(coin))
}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
