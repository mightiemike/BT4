### Title
Spot-price Uniswap V3 quote used for swap slippage protection enables sandwich-based fund loss during inbound gas-swap and gas-refund execution - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The external report's core defect is that a Chainlink price feed with a wide heartbeat/deviation window is used to compute a protective bound, and an ordinary honest-flow user can be unfairly penalized because the on-chain price can diverge materially from the true price at execution time. Push Chain's uexecutor module has the same class of defect but with a strictly worse, actively-manipulable price source: `GetSwapQuote` reads the instantaneous spot price from Uniswap V3's `QuoterV2.quoteExactInputSingle` (not a TWAP or any external validated oracle), and this quote is used, with only a fixed 5% slippage tolerance, to authorize a real on-chain swap of user/protocol funds (`depositPRC20WithAutoSwap`, `refundUnusedGas`). Because the quote is a live AMM spot price, an unprivileged attacker can move the pool price by more than 5% via ordinary transactions in the same or adjacent block, causing the executed swap to settle at a manipulated rate and extracting value from the user/protocol funds being converted.

### Finding Description
`GetSwapQuote` in [1](#0-0)  calls `QuoterV2.quoteExactInputSingle` with `commit=false`, which returns the pool's current spot-derived quote (no TWAP, no external price validation).

This quote feeds two execution paths that move real value:

1. **Inbound gas-abstraction swap** — `ExecuteInboundGas` in [2](#0-1)  fetches the fee tier, calls `GetSwapQuote`, computes `minPCOut = quote * 95 / 100` (a fixed 5% slippage bound), and immediately executes `CallPRC20DepositAutoSwap` (`depositPRC20WithAutoSwap`) — a real, committed EVM swap of the user's bridged token into PC — using that `minPCOut` as the only floor protection.

2. **Outbound gas refund** — `applyGasRefund` in [3](#0-2)  follows the identical pattern: fetch fee tier → `getSwapQuoteForRefund` (wraps `GetSwapQuote`) → `minPCOut = quote * 95 / 100` → `CallUniversalCoreRefundUnusedGas` with `withSwap=true`, swapping the excess gas token back to native PC for the recipient.

Both of these are triggered by ordinary, unprivileged user actions (a normal gas-abstracted inbound, or a normal outbound gas refund) — no special privilege is required. Since the `QuoterV2` reads the pool's live reserves/sqrtPrice, any actor who can transact against the underlying Uniswap V3 pool on Push Chain (anyone, since it's a public AMM) can push the pool price away from fair value immediately before the module's swap executes, then reverse the trade afterward (classic sandwich), capturing the difference between the manipulated execution price and the true market price. The 5% band is a fixed, static slippage tolerance sized for normal market noise — it provides no protection against deliberate, attacker-timed price manipulation of the pool used as the "oracle," which is exactly the invariant broken in the source report (a threshold-bound but easily exceeded on-chain price feed causing unfair, un-consented loss to the party whose funds are converted at that price).

This is a materially closer-to-consensus-reachable version of the original bug: the stETH/ETH Chainlink feed at least has honest, decentralized reporting nodes updating within a bounded window; here the "price feed" is a permissionless AMM pool that any attacker can push in real time with their own capital, with no TWAP smoothing and no external reference check.

### Impact Explanation
- Funds converted through `depositPRC20WithAutoSwap` (user's bridged gas token → PC) or `refundUnusedGas` (excess relayer gas fee refund → PC) can be swapped at an attacker-manipulated price within the fixed 5% band, transferring value from the user/protocol to the attacker executing the sandwich.
- This directly corrupts PRC20/native asset accounting and gas fee/refund accounting — in-scope impacts per the allowed-impact gate ("corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting").
- The loss is bounded per-transaction by the 5% slippage window but is systematically extractable by any attacker willing to trade against the pool whenever an inbound gas-swap or gas-refund is about to execute, since these events are observable on-chain (pending votes / pending outbounds) before execution.

### Likelihood Explanation
- No privileged access is required: any address can trade on the Uniswap V3 pool that the module swaps against.
- The trigger conditions (gas-abstracted inbound with a PRC20 gas token needing swap, or an outbound gas refund with excess `gasFee - gasFeeUsed`) occur in normal, expected protocol usage — not edge cases.
- The swap execution point (after UV vote finalization / outbound observation finalization) is deterministic and observable ahead of time by watching pending inbound/outbound state, giving an attacker precise timing to front-run/back-run.

### Recommendation
Do not rely on the instantaneous `QuoterV2` spot quote as the sole slippage floor. Options:
- Use a time-weighted average price (TWAP) from the pool (or an external validated price source) to compute `minPCOut`, rather than the single-block spot quote.
- Add a maximum-deviation check comparing the spot quote against a longer-window reference price, rejecting/deferring the swap if the two diverge beyond a safe bound.
- Consider widening the effective protection by combining a TWAP-based floor with the existing percentage slippage, or exposing this as a governance-tunable parameter rather than a hardcoded 5%.

### Proof of Concept
1. Attacker monitors Push Chain mempool/state for a pending inbound of type `GAS`/`GAS_AND_PAYLOAD` (visible before UV votes finalize) or a pending outbound whose `gasFee > gasFeeUsed` (visible once the destination-chain observation is about to be voted through).
2. Immediately before the triggering vote is included, attacker submits a large swap against the same Uniswap V3 pool (`prc20`/gas-token ↔ `WPC`) used by `GetSwapQuote`, moving the spot price down for the token being sold into the module's swap.
3. The module's `GetSwapQuote` (via `QuoterV2.quoteExactInputSingle`, spot-based) returns a price already skewed by the attacker's trade; `minPCOut = quote * 95/100` is computed off this skewed value.
4. `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` (`withSwap=true`) executes the real swap at the manipulated pool price, still passing the `minPCOut` check because the bound itself was computed from the same manipulated pool.
5. Attacker reverses their trade (back-run) after the module's swap lands, capturing the price difference extracted from the user's converted funds / the protocol's refund payout.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
