### Title
Unbounded recursive JSON sorting on attacker-controlled ABI/program data enables stack-overflow DoS during declared-class hash computation - ([File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs])

### Summary
`compute_cairo_hinted_class_hash` deserializes an attacker-supplied deprecated (Cairo0) contract class into a `serde_json::Value` and recursively walks it with `sort_json_value` to normalize key ordering before hashing. The recursion depth is driven directly by the nesting depth of the `abi` (typed as unconstrained `serde_json::Value`) and other free-form JSON fields (`program.identifiers`, `hints`, `reference_manager`) inside the declared class, with no depth limit enforced anywhere in the validation pipeline.

### Finding Description
`sort_json_value` recurses once per nested JSON object/array level with no bound: [1](#0-0) 

It is invoked from `compute_cairo_hinted_class_hash`, which is called whenever a deprecated (Cairo0) contract class's hinted class hash must be computed: [2](#0-1) 

This is reached from `compute_deprecated_class_hash`, used by the Starknet OS re-execution path when processing declared Cairo0 classes: [3](#0-2) 

The `abi` field of `CairoContractDefinition` is explicitly documented as having "no schema definition" and is deserialized as an arbitrary `serde_json::Value`: [4](#0-3) 

The only gateway-side protections on a declared class are total byte-size and bytecode-size limits, not structural nesting depth: [5](#0-4) [6](#0-5) 

A JSON payload can be constructed with extremely deep nesting (e.g. `[[[[[...]]]]]`) using only a few bytes per nesting level, so the configured `max_contract_class_object_size` (~4 MB) permits well over a million nesting levels while staying under the byte limit — far more than needed to exhaust a thread's call stack via recursive `sort_json_value` calls. No stack-size hardening (e.g., `stacker`, custom thread stack size) was found guarding this code path.

### Impact Explanation
Unbounded recursion on attacker-controlled, deeply nested JSON causes a stack overflow, which aborts the process (Rust has no way to catch a stack overflow) rather than returning an error. Because this computation happens on the Starknet OS re-execution / declared-class hashing path, a single malicious Cairo0 `DECLARE` transaction (or a corresponding L1/replay path re-executing it) can crash the sequencer process handling it, mirroring the "resource exhaustion / hang" character of the analog report (CWE-404), but manifesting as an abrupt crash (CWE-674 uncontrolled recursion) rather than an infinite hang. Repeated submission could be used to repeatedly crash sequencer processes performing class-hash computation, disrupting block/transaction processing availability.

### Likelihood Explanation
The `abi` field is deliberately unconstrained (arbitrary JSON per the code's own doc comment), and existing validators check only byte-count limits, not nesting depth. An attacker only needs to craft a Cairo0 declare transaction with a deeply nested but small ABI/JSON substructure — no special privileges, signatures forging, or state manipulation required — making this readily reachable by any transaction sender able to submit a `DECLARE` (V0/V1 style) transaction that ends up processed through the deprecated class hash computation path.

### Recommendation
- Enforce a maximum JSON nesting depth (and/or use an iterative, explicit-stack traversal instead of recursion) in `sort_json_value` and anywhere else that recursively walks attacker-controlled `serde_json::Value` structures (`abi`, `identifiers`, `hints`, `reference_manager`).
- Reject declared classes whose ABI/program JSON exceeds a configurable depth during stateless validation, before any recursive processing occurs.
- Consider running class-hash computation on a thread with a bounded, monitored stack and converting stack-overflow-prone recursive helpers to iterative equivalents using an explicit `Vec`-based worklist.

### Proof of Concept
1. Construct a `DeprecatedContractClass` (Cairo0) declare transaction whose `abi` field is a deeply nested JSON array, e.g. programmatically build `"[".repeat(N) + "]".repeat(N)` for `N` in the hundreds of thousands to a few million (staying under `max_contract_class_object_size` ≈ 4 MB, easily achievable since each nesting level costs only 2 bytes).
2. Submit the class for hashing via the deprecated declare path (`compute_deprecated_class_hash` → `compute_cairo_hinted_class_hash`), e.g. through Starknet OS re-execution of the transaction.
3. `sort_json_value` recurses once per array nesting level while serializing `contract_class` to a sorted `Value`; at sufficient depth the recursive call stack exceeds the thread's stack limit, causing an unrecoverable stack overflow and process abort — verified by the unbounded recursive structure shown in the cited code with no depth guard present anywhere in the call chain.

/// Recursively sorts all JSON objects by their keys.
/// This ensures deterministic serialization regardless of the `preserve_order` feature in
/// serde_json.
fn sort_json_value(value: serde_json::Value) -> serde_json::Value {
    match value {
        serde_json::Value::Object(map) => {
            let sorted: BTreeMap<String, serde_json::Value> =
                map.into_iter().map(|(k, v)| (k, sort_json_value(v))).collect();
            serde_json::Value::Object(sorted.into_iter().collect())
        }
        serde_json::Value::Array(arr) => {
            serde_json::Value::Array(arr.into_iter().map(sort_json_value).collect())
        }
        other => other,
    }
}

pub fn compute_cairo_hinted_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    // Serialize to Value, sort all objects by keys for deterministic output, then to bytes.
    // The sorting is necessary because serde_json with `preserve_order` feature enabled
    // maintains insertion order instead of sorting keys.
    // TODO(Meshi): Compute hinted hashes when loading serialized contracts from storage, before
    // deserializing, to avoid back-and-forth serde.
    let contract_value = serde_json::to_value(contract_class)?;
    let sorted_contract_value = sort_json_value(contract_value);
    let contract_definition_vec = serde_json::to_vec(&sorted_contract_value)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let mut string_buffer = vec![];

    let mut ser = serde_json::Serializer::with_formatter(&mut string_buffer, PythonJsonFormatter);
    contract_definition.serialize(&mut ser)?;

    let mut raw_json_output = String::from_utf8(string_buffer)?;
    if contract_definition.program.compiler_version.is_none() {
        add_backward_compatibility_space(&mut raw_json_output);
    }
