### Title
Zero-weight (degenerate) signer set makes `verify_signer_signatures` accept completely unsigned Nakamoto blocks — (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` never rejects a reward set whose `signers` field is `Some(vec![])` (present but empty). In that state `total_signing_weight()` returns `Ok(0)`, `compute_voting_weight_threshold(0)` evaluates to `0`, and the accumulated `total_weight_signed` for a block with zero (or any non-matching) signatures is also `0`. The check `total_weight_signed < threshold` (`0 < 0`) is false, so the block is accepted as validly signed even though nobody signed it. This mirrors CL-2021-32 (Prysm `AggregatePublicKeys`): an empty/degenerate input silently satisfies a check that was meant to enforce a minimum quorum.

### Finding Description
`RewardSet::total_signing_weight` treats an empty-but-present signer vector as a valid, fully-computed weight of `0` rather than an error: [1](#0-0) 

This differs from the `None` case, which `verify_signer_signatures` does reject explicitly: [2](#0-1) 

but `Some(vec![])` passes that check and proceeds. The verification loop then computes: [3](#0-2) 

with `total_weight = 0`, and the final acceptance test: [4](#0-3) 

`compute_voting_weight_threshold(0)` returns `0`: [5](#0-4) 

so for an empty `self.signer_signature`, `total_weight_signed (0) < threshold (0)` is `false`, and the function returns `Ok(0)` — i.e., "signatures verified" for a block nobody signed.

The degenerate `Some(vec![])` state is directly reachable from `RewardSet` construction: `StacksChainState::make_signer_set` only returns `None` when the input `entries` list itself is empty; if entries exist but every entry's computed `weight` (`stacked_amt / threshold`) floors to `0`, they are all filtered out and the function still returns `Some(vec![])`, not `None`: [6](#0-5) 

That vector is stored, unguarded, into the PoX-4/V0 reward set: [7](#0-6) 

Notably, the PoX-5 path *does* explicitly guard against this exact condition ("Fatal network condition: reward set computed with an empty signer set"): [8](#0-7) 

confirming that an empty-but-present signer set is a recognized dangerous state — but the guard is missing from the general verification path in `NakamotoBlockHeader::verify_signer_signatures` and from the PoX-4/V0 construction path (`pox_4_compute_and_update_signers`).

### Impact Explanation
`verify_signer_signatures` is the sole gate ensuring a Nakamoto block reflects sufficient stacked-weight approval from the active signer set. If a reward cycle's computed signer set degenerates to `Some(vec![])` (weight-0 for every stacker after flooring), every conforming node deterministically computes `threshold = 0` and will accept a block with **zero signer signatures** as fully valid — a block anyone (no private key required) can construct and propagate. This is an "invalid block accepted... network-wide" condition, which the prompt classifies as Critical impact, since it breaks the fundamental equality that block acceptance requires signer approval ≥ threshold.

### Likelihood Explanation
Triggering requires the reward-cycle signer-weight computation to yield an empty, non-`None` signer vector — i.e. every stacker's floor-divided weight is `0` for that cycle. This is an edge case in stake distribution/threshold math (not a majority-collusion attack and not requiring any privileged key), and the code base itself acknowledges this exact edge case exists and is dangerous (it is explicitly guarded against in the PoX-5 path but not in PoX-4/V0 or in `verify_signer_signatures` itself), which supports plausibility of reachability.

### Recommendation
- In `RewardSet::total_signing_weight` (and/or in `verify_signer_signatures`), treat `signers().is_some() && signers().unwrap().is_empty()` the same as `None` — return an error (`NoRegisteredSigners`) instead of `Ok(0)`.
- Add the same `signer_set.is_empty()` guard used in `pox_5_compute_and_update_signers` to the PoX-4/V0 path (`pox_4_compute_and_update_signers`) so a degenerate empty signer set can never be persisted as an active `RewardSet`.
- Add a defense-in-depth check in `verify_signer_signatures`: reject if `total_weight == 0`.

### Proof of Concept
1. Construct (or force via property tests) a set of PoX-4 stacker entries whose individual `amount_stacked / threshold` all floor to `0`, causing `StacksChainState::make_signer_set` to return `Some(vec![])`.
2. Let this reward set become the active signer set for a cycle (`pox_4_compute_and_update_signers` stores it without an emptiness check).
3. Produce a `NakamotoBlockHeader` with `signer_signature = vec![]` (no signatures at all).
4. Call `header.verify_signer_signatures(&reward_set, epoch_id)` — observe it returns `Ok(0)` instead of an error, as demonstrated by the existing threshold-math in `compute_voting_weight_threshold(0) == 0` and the loop/threshold logic at `stackslib/src/chainstate/nakamoto/mod.rs:1115-1189`.

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
    }

    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
