## Title
Unauthenticated `batchProver_setCommitments` and `batchProver_submitFakeProof` JSON-RPC methods allow overriding sequencer-commitment state and injecting a fabricated proof - (File: crates/batch-prover/src/rpc.rs)

### Summary
The batch prover exposes `setCommitments` and `submitFakeProof` over JSON-RPC. Neither method is access-controlled: the node's only RPC gate is the `Auth` middleware, which restricts exactly three method names (`backup_create`, `backup_validate`, `backup_info`) and lets every other method through unauthenticated, regardless of the configured API key. [1](#0-0) [2](#0-1) 

### Finding Description
`set_commitments` blindly writes attacker-supplied `SequencerCommitmentRpcParam` values (arbitrary `merkle_root`, `index`, `l2_end_block_number`, `l1_height`) into the ledger DB, overriding any existing commitment at that index and marking it pending for proving — with the doc-comment itself warning "It overrides the commitment already if exists, so use with caution." [3](#0-2) [4](#0-3) 

`submit_fake_proof` goes further: it builds a `BatchProofCircuitOutput` (state roots, final block hash, cumulative state diff, commitment index range) directly from whatever commitments/state are currently in the ledger DB, wraps it in a RISC0 `FakeReceipt`, and sends it to the DA layer as a `DaTxRequest::ZKProof` — i.e., it submits a "proof" to L1 without ever running the ZK guest. [5](#0-4) 

Chaining the two: an unauthenticated caller with network access to a batch-prover node's RPC port can (1) call `setCommitments` to inject a fabricated commitment (arbitrary merkle root / L2 range / index) into the prover's ledger, and (2) call `submitFakeProof` to have the node package a `FakeReceipt` output built from that fabricated state and broadcast it to L1 as a genuine-looking batch proof transaction. This is the exact analog of `sfnProcessTradeDispute`: a function with the power to "override prices" (here: override the sequencer-commitment/state binding that proofs are built from) but lacking any `onlyCegaAdmin`-style access control, exposed to any caller.

### Impact Explanation
This breaks the binding between "the proof journal" and "what actually happened," which is explicitly the Critical bucket: a false state transition can be proved (or, by overriding a legitimately-indexed commitment, a true one can be made unprovable/discarded). Whether the fake proof is ultimately accepted end-to-end depends on downstream verification (e.g., RISC0 receipt verification against the real method ID in the light-client/full-node verifier, which normal FakeReceipts would fail unless the network runs in ZK dev-mode), and I could not fully verify within available context whether production nodes reject `FakeReceipt`s outright. Regardless of that downstream gate, `setCommitments` alone already lets any unauthenticated caller corrupt the batch prover's local commitment table (index collisions, wrong merkle roots, wrong L2 ranges), directly undermining the prover's proving pipeline and node state — squarely fitting "an unauthenticated JSON-RPC call that mutates node state or bypasses `Auth`" (High).

### Likelihood Explanation
No credentials, roles, or special access are required beyond reaching the batch prover's JSON-RPC endpoint — the `Auth` middleware's allow-list design means these methods are open by default with no opt-in protection available at all (they aren't even eligible for the API-key gate, unlike `backup_*`). Any deployment that exposes the batch-prover RPC port (even behind normal firewalling for legitimate node-operator API use) is exposed to any client that can reach that port.

### Recommendation
Extend the RPC `Auth` middleware (or add per-method guards) to require the API key — or a dedicated privileged-role check — for all state-mutating `batchProver_*` methods, at minimum `setCommitments`, `submitFakeProof`, `prove`, `pauseProving`, and `retryProvingJob`. Do not rely on network-level obscurity; add these method names to `PROTECTED_METHODS` in `crates/common/src/rpc/auth.rs` (or replace the allow-list with a default-protect / explicit-allow model), consistent with the CEGA remediation of adding an explicit admin-only modifier to `sfnProcessTradeDispute`.

### Proof of Concept
1. Start a batch-prover node with RPC enabled (no special auth needed, since `batchProver_*` methods aren't in `PROTECTED_METHODS`).
2. As an unauthenticated client, call:
```json
{"jsonrpc":"2.0","method":"batchProver_setCommitments","params":[[{"merkleRoot":"0x...attacker chosen...","index":"0x5","l2EndBlockNumber":"0x64","l1Height":"0x1"}]],"id":1}
```
This overwrites `put_commitment_by_index`/`put_commitment_index_by_l1`/`put_prover_pending_commitment` for index 5 with attacker data. [4](#0-3) 
3. Call:
```json
{"jsonrpc":"2.0","method":"batchProver_submitFakeProof","params":[2,5],"id":2}
```
which builds a `BatchProofCircuitOutput` from the (now attacker-controlled) commitment/state data and submits a `FakeReceipt`-based `DaTxRequest::ZKProof` transaction to the DA layer. [6](#0-5)

    async fn set_commitments(
        &self,
        commitments: Vec<SequencerCommitmentRpcParam>,
    ) -> RpcResult<()> {
        for commitment in commitments {
            let l1_height = commitment.l1_height.to::<u64>();
            let commitment = SequencerCommitment {
                merkle_root: commitment.merkle_root,
                index: commitment.index.to::<u32>(),
                l2_end_block_number: commitment.l2_end_block_number.to::<u64>(),
            };

            info!(
                "Overriding sequencer commitment, index={} merkle_root={} l2_end_height={} l1_height={}",
                commitment.index,
                hex::encode(commitment.merkle_root),
                commitment.l2_end_block_number,
                l1_height,
            );

            self.context
                .ledger_db
                .put_commitment_by_index(&commitment)
                .map_err(internal_rpc_error)?;
            // This might cause some duplicate commitment indices appear in l1 -> index table which is ok
            self.context
                .ledger_db
                .put_commitment_index_by_l1(SlotNumber(l1_height), commitment.index)
                .map_err(internal_rpc_error)?;
            self.context
                .ledger_db
                .put_prover_pending_commitment(commitment.index)
                .map_err(internal_rpc_error)?;
        }

        Ok(())
    }

    async fn submit_fake_proof(
        &self,
        index_start: u32,
        index_end: u32,
    ) -> RpcResult<BatchProofResponse> {
        info!(
            "Submitting fake proof for commitment index range [{},{}]",
            index_start, index_end
        );

        let ledger_db = &self.context.ledger_db;

        if index_start > index_end {
            return Err(internal_rpc_error("Invalid index range"));
        }
        // don't allow first commitment index to be called through this rpc as it requires extra handling
        if index_start <= 1 {
            return Err(internal_rpc_error(
                "submitFakeProof rpc supports only index_start > 1",
            ));
        }

        let previous_commitment = ledger_db
            .get_commitment_by_index(index_start - 1)
            .map_err(internal_rpc_error)?
            .ok_or_else(|| internal_rpc_error("Missing previous commitment index"))?;

        let commitments = ledger_db
            .get_commitment_by_range(index_start..=index_end)
            .map_err(internal_rpc_error)?;
        if commitments.len() as u32 != index_end - index_start + 1 {
            return Err(internal_rpc_error(
                "Missing some commitment indices from the range",
            ));
        }

        let last_commitment = commitments.last().expect("Already ensured");
        let last_l2_block = ledger_db
            .get_l2_block_by_number(&L2BlockNumber(last_commitment.l2_end_block_number))
            .map_err(internal_rpc_error)?
            .ok_or_else(|| internal_rpc_error("Not synced up to latest L2 block yet"))?;

        let initial_state_root = ledger_db
            .get_l2_state_root(previous_commitment.l2_end_block_number)
            .map_err(internal_rpc_error)?
            .expect("Initial L2 state root must exist");

        let mut start_l2_height = previous_commitment.l2_end_block_number + 1;
        let mut sequencer_commitment_hashes = Vec::with_capacity(commitments.len());
        let mut state_roots = Vec::with_capacity(commitments.len() + 1);
        state_roots.push(initial_state_root);

        let mut cumulative_state_diff = CumulativeStateDiff::new();
        for commitment in commitments.iter() {
            let end_l2_height = commitment.l2_end_block_number;

            for l2_height in start_l2_height..=end_l2_height {
                let state_diff = ledger_db
                    .get_l2_state_diff(L2BlockNumber(l2_height))
                    .map_err(internal_rpc_error)?
                    .expect("L2 state diff must exist");
                cumulative_state_diff.extend(state_diff);
            }

            sequencer_commitment_hashes.push(commitment.serialize_and_calculate_sha_256());

            let end_state_root = ledger_db
                .get_l2_state_root(end_l2_height)
                .map_err(internal_rpc_error)?
                .expect("L2 state root must exist");
            state_roots.push(end_state_root);

            start_l2_height = end_l2_height + 1;
        }

        let storage = self
            .context
            .storage_manager
            .create_storage_for_l2_height(last_l2_block.height + 1);
        let last_l1_hash_on_contract = get_last_l1_hash_on_contract::<DefaultContext>(
            Default::default(),
            storage,
            &mut Default::default(),
            [0; 32],
        );

        let output = BatchProofCircuitOutput::V3(BatchProofCircuitOutputV3 {
            state_roots,
            final_l2_block_hash: last_l2_block.hash,
            state_diff: cumulative_state_diff,
            last_l2_height: last_l2_block.height,
            sequencer_commitment_hashes,
            sequencer_commitment_index_range: (index_start, index_end),
            last_l1_hash_on_bitcoin_light_client_contract: last_l1_hash_on_contract,
            previous_commitment_index: Some(previous_commitment.index),
            previous_commitment_hash: Some(previous_commitment.serialize_and_calculate_sha_256()),
        });

        let output_serialized = borsh::to_vec(&output).expect("Output serialization cannot fail");

        let spec_id = fork_from_block_number(last_l2_block.height).spec_id;
        let method_id: [u32; 8] = self
            .context
            .code_commitments
            .get(&spec_id)
            .expect("Spec for L2 block must exist")
            .clone()
            .into();

        let claim = MaybePruned::Value(ReceiptClaim::ok(method_id, output_serialized));
        let fake_receipt = FakeReceipt::new(claim);
        // Receipt with verifiable claim
        let receipt = InnerReceipt::Fake(fake_receipt);
        let proof = bincode::serialize(&receipt).expect("Receipt serialization cannot fail");

        let tx_id = self
            .context
            .da_service
            .send_transaction(DaTxRequest::ZKProof(proof.clone()))
            .await
            .map_err(internal_rpc_error)?;

        Ok(BatchProofResponse {
            l1_tx_id: Some(tx_id.into()),
            proof,
            proof_output: StoredBatchProofOutput::from(output).into(),
            info: None,
        })
    }
