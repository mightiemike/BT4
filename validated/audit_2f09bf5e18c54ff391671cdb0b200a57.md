### Title
`handle_poison_microblock` slashes a miner for a legitimate microblock chain because it never checks that the two headers actually equivocate (same sequence/parent) - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`check_microblock_header_signer` (used inside `handle_poison_microblock`) only verifies that both microblock headers were signed by the same key; it never verifies that the two headers represent divergent continuations of the same predecessor at the same sequence number. A valid, non-forked two-microblock chain from a single miner (`h2.prev_block == h1.block_hash()`) will pass this check and be recorded as a valid poison report, mis-attributing the reporter a "poison" credit against an honest miner.

### Finding Description
The claimed equality is:
`reported_pair == a_genuine_equivocation_(same_seq,_different_content)`

The code that is supposed to enforce this equality inside the consensus-processing path is `check_microblock_header_signer`: [1](#0-0) 

This function only recovers each header's public key and compares `pkh1 != pkh2` — it never checks `mblock_hdr_1.sequence == mblock_hdr_2.sequence` or `mblock_hdr_1.prev_block == mblock_hdr_2.prev_block`. It is the *only* structural check performed by `handle_poison_microblock` before it records the report and computes the punished pubkey-hash height and reporter/sequence: [2](#0-1) 

Notice that `handle_poison_microblock` uses `mblock_header_1.sequence` directly as the "reported_seq" that determines whether this reporter "beats" a prior report and gets recorded as the entitled reporter — with no verification that `h1` and `h2` are actually a fork at that sequence.

By contrast, the equivalent structural check *is* present, but only at the mempool-admission layer (`will_admit_mempool_tx`), not in the consensus/block-processing path: [3](#0-2) 

That mempool check enforces `sequence` equality, `prev_block` equality, `version` equality, and same signer — exactly the conditions needed to prove an actual equivocation (two different continuations from the same predecessor at the same sequence). But this check is bypassed entirely once a transaction is included directly into a block by a block-producer (a role explicitly available to the unprivileged attacker per the threat model, who "can... submit Nakamoto blocks and microblocks"). `process_transaction`/`process_transaction_payload` route straight to `handle_poison_microblock`, which — as shown above — does not re-derive or re-check this equivocation condition.

Exploit flow:
1. Attacker (a miner or a block producer) observes any honest miner's normal, non-forked microblock stream, e.g. `h1` then `h2` with `h2.prev_block == h1.block_hash()` and `h2.sequence == h1.sequence + 1`.
2. Attacker crafts a `PoisonMicroblock(h1, h2)` transaction and includes it directly in a block they produce (bypassing `will_admit_mempool_tx`'s stricter mempool-only check), or otherwise gets it processed via `process_transaction`.
3. `check_microblock_header_signer` succeeds because `pkh1 == pkh2` (same honest miner's key signed both, since it's one legitimate stream).
4. `handle_poison_microblock` proceeds, finds the pubkey hash's block height still within `MINER_REWARD_MATURITY`, and records the attacker as the "reporter" with `sequence = h1.sequence`, entitling them to the punished miner's coinbase commission.

### Impact Explanation
This lets an unprivileged attacker falsely trigger the poison-microblock slashing/commission mechanism against a miner who never equivocated, redirecting reward/commission to the reporter and improperly punishing an honest miner. This matches the Critical category "block-reward theft/double-payment/loss," since real STX reward value is misappropriated from an honest miner to an attacker without an actual double-sign/fork having occurred.

### Likelihood Explanation
The attacker needs no majority stake and no privileged role — only the ability to hold a miner/block-producer slot at some point (already assumed in the threat model) or otherwise get an arbitrary transaction included in a block (e.g., colluding with any miner, or being a miner themselves for one tenure), plus knowledge of any honest miner's public, broadcast microblock stream (which is inherently public). This is entirely repeatable against any observed non-forked two-microblock sequence and requires no minority-stake threshold beyond holding a single miner slot.

### Recommendation
In `handle_poison_microblock` (and/or `check_microblock_header_signer`), require the two headers to genuinely represent a fork at the same predecessor and sequence before treating the report as valid: assert `mblock_header_1.sequence == mblock_header_2.sequence`, `mblock_header_1.prev_block == mblock_header_2.prev_block`, and `mblock_header_1.block_hash() != mblock_header_2.block_hash()`, mirroring the check already present in `will_admit_mempool_tx` (`stackslib/src/chainstate/stacks/db/blocks.rs:6844-6868`), and enforce it uniformly at the consensus level, not only at mempool admission.

### Proof of Concept
Rust integration test plan (chainstate-level, bypassing mempool):
1. Generate a miner keypair `privk` and build two legitimately-chained microblocks: `h1` with `sequence = 0`, and `h2` with `sequence = 1`, `h2.prev_block == h1.block_hash()`, both signed with `privk`. Assert `h1.block_hash() != h2.block_hash()` (different content, same continuous chain, no fork).
2. Register `privk`'s pubkey hash at some block height using `StacksChainState::insert_microblock_pubkey_hash` (as in the existing test at `stackslib/src/chainstate/stacks/db/transactions.rs:5509-5597`), simulating an honest miner's registered microblock key.
3. Build a `TransactionPayload::PoisonMicroblock(h1.header, h2.header)` transaction signed by an unrelated "attacker/reporter" key, and call `StacksChainState::process_transaction` directly (as done in the existing `poison_microblock` test), i.e. bypassing `will_admit_mempool_tx`.
4. Assert on both sides of the equality:
   - Equality claimed: `check_microblock_header_signer(h1, h2)` succeeds and returns `Ok(pubkh)` (demonstrating the flaw — same-key check alone).
   - Equality that should hold for a genuine equivocation: `h1.sequence == h2.sequence && h1.prev_block == h2.prev_block` — assert this is **false** for this legitimately-chained pair.
   - Expected (fixed) behavior: `process_transaction` should return `Err(...)` for this pair since it is not a genuine equivocation; current code returns `Ok(...)` and records a poison report crediting the attacker/reporter — assert this occurs today, proving the bug.

    /// Given two microblock headers, were they signed by the same key?
    /// Return the pubkey hash if so; return Err otherwise
    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }

    pub fn handle_poison_microblock(
        env: &mut ExecutionState,
        invoke_ctx: &InvocationContext,
        mblock_header_1: &StacksMicroblockHeader,
        mblock_header_2: &StacksMicroblockHeader,
    ) -> Result<Value, Error> {
        let cost_before = env.global_context.cost_track.get_total();

        // encodes MARF reads for loading microblock height and current height, and loading and storing a
        // poison-microblock report
        runtime_cost(ClarityCostFunction::PoisonMicroblock, env, 0)
            .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

        let sender_principal = match &invoke_ctx.sender {
            Some(ref sender) => {
                if let PrincipalData::Standard(sender) = sender.clone() {
                    sender
                } else {
                    panic!(
                        "BUG: tried to handle poison microblock without a standard principal sender"
                    );
                }
            }
            None => {
                panic!("BUG: tried to handle poison microblock without a sender");
            }
        };

        // is this valid -- were both headers signed by the same key?
        let pubkh =
            StacksChainState::check_microblock_header_signer(mblock_header_1, mblock_header_2)?;

        let microblock_height_opt = env
            .global_context
            .database
            .get_microblock_pubkey_hash_height(&pubkh)?;
        let current_height = env.global_context.database.get_current_block_height();

        // for the microblock public key hash we had to process
        env.add_memory(20)
            .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

        // for the block height we had to load
        env.add_memory(4)
            .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

        // was the referenced public key hash used anytime in the past
        // MINER_REWARD_MATURITY blocks?
        let mblock_pubk_height = match microblock_height_opt {
            None => {
                // public key has never been seen before
                let msg = format!(
                    "Invalid Stacks transaction: microblock public key hash {} never seen in this fork",
                    &pubkh
                );
                warn!("{}", &msg;
                      "microblock_pubkey_hash" => %pubkh
                );

                return Err(Error::InvalidStacksTransaction(msg, false));
            }
            Some(height) => {
                if height
                    .checked_add(
                        u32::try_from(MINER_REWARD_MATURITY).expect("FATAL: maturity > 2^32"),
                    )
                    .expect("BUG: too many blocks")
                    < current_height
                {
                    let msg = format!(
                        "Invalid Stacks transaction: microblock public key hash from height {} has matured relative to current height {}",
                        height, current_height
                    );
                    warn!("{}", &msg;
                          "microblock_pubkey_hash" => %pubkh
                    );

                    return Err(Error::InvalidStacksTransaction(msg, false));
                }
                height
            }
        };

        // add punishment / commission record, if one does not already exist at lower sequence
        let (reporter_principal, reported_seq) = if let Some((reporter, seq)) = env
            .global_context
            .database
            .get_microblock_poison_report(mblock_pubk_height)?
        {
            // account for report loaded
            env.add_memory(u64::from(TypeSignature::PrincipalType.size().map_err(
                |_| Error::Expects("Failed to get size of PrincipalType".into()),
            )?))
            .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

            // u128 sequence
            env.add_memory(16)
                .map_err(|e| Error::from_cost_error(e, cost_before.clone(), env.global_context))?;

            if mblock_header_1.sequence < seq {
                // this sender reports a point lower in the stream where a fork occurred, and is now
                // entitled to a commission of the punished miner's coinbase
                debug!("Sender {} reports a better poison-miroblock record (at {}) for key {} at height {} than {} (at {})", &sender_principal, mblock_header_1.sequence, &pubkh, mblock_pubk_height, &reporter, seq;
                    "sender" => %sender_principal,
                    "microblock_pubkey_hash" => %pubkh
                );
                env.global_context.database.insert_microblock_poison(
                    mblock_pubk_height,
                    &sender_principal,
                    mblock_header_1.sequence,
                )?;
                (sender_principal, mblock_header_1.sequence)
            } else {
                // someone else beat the sender to this report
                debug!("Sender {} reports an equal or worse poison-microblock record (at {}, but already have one for {}); dropping...", &sender_principal, mblock_header_1.sequence, seq;
                    "sender" => %sender_principal,
                    "microblock_pubkey_hash" => %pubkh
                );
                (reporter, seq)
            }
        } else {
            // first-ever report of a fork
            debug!(
                "Sender {} reports a poison-microblock record at seq {} for key {} at height {}",
                &sender_principal, mblock_header_1.sequence, &pubkh, &mblock_pubk_height;
                "sender" => %sender_principal,
                "microblock_pubkey_hash" => %pubkh
            );
            env.global_context.database.insert_microblock_poison(
                mblock_pubk_height,
                &sender_principal,
                mblock_header_1.sequence,
            )?;
            (sender_principal, mblock_header_1.sequence)
        };
