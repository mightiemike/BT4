## Title
Unauthenticated `RescueFundsOnSourceChain` events let anyone trigger a rescue outbound for another user's stuck funds with attacker-chosen `GasFee`/`GasPrice`/`GasLimit` - (File: `x/uexecutor/keeper/create_outbound.go`)

### Summary
`AttachRescueOutboundFromReceipt` (invoked from every EVM transaction via `EVMHooks.PostTxProcessing`) processes `RescueFundsOnSourceChain` log events and attaches a `RESCUE_FUNDS` outbound to the original, stuck `UniversalTx`, without ever validating that the event's `Sender` is the original inbound's owner/sender. The gas parameters (`GasFee`, `GasPrice`, `GasLimit`) that end up on the resulting outbound are taken verbatim from the emitting transaction's log, i.e. fully attacker-controlled.

### Finding Description
`AttachRescueOutboundFromReceipt` [1](#0-0)  is wired into `EVMHooks.PostTxProcessing`, which runs after *every* EVM transaction on Push Chain [2](#0-1) . It scans logs for the `RescueFundsOnSourceChain` event emitted by the `UniversalGatewayPC` system contract, decodes it, and looks up the original stuck `UniversalTx` purely by `universalTxId`.

Eligibility is checked only against the *state of the UTX* (CEA deposit `FAILED`, or non-CEA `INBOUND_REVERT` outbound `REVERTED`), and against duplicate-active-rescue protection [3](#0-2) . There is no check anywhere in this function that `event.Sender` (the caller who invoked the rescue function on the gateway contract) matches `originalUtx.InboundTx.Sender` or any authorized party for that UTX.

The resulting `RESCUE_FUNDS` outbound is built using `GasFee`, `GasPrice`, and `GasLimit` taken directly from the decoded event data [4](#0-3) , and the decoder places no bounds on these values [5](#0-4) . Since these fields come from an EVM log emitted by an ordinary (unprivileged) contract call, any account can call the rescue entrypoint on `UniversalGatewayPC` for any `universalTxId` (as long as it happens to be in a rescue-eligible state) and choose whatever `gasFee`/`gasPrice`/`gasLimit` values it likes.

The recipient of the rescue outbound is bound to the *original* inbound's sender/`RevertInstructions.FundRecipient`, so the attacker cannot redirect the principal to themselves [6](#0-5) . However, since the gas fee is attacker-supplied and is deducted from the rescued funds during outbound processing (per the `GasFee`/`gas_fee.go` handling in the outbound pipeline), an unauthorized third party can force an inflated gas-fee deduction against a victim's stuck funds, reducing the amount the legitimate owner ultimately recovers — an unauthorized, attacker-triggered value corruption of someone else's locked-fund record, analogous to the `destroyEscrow()` pattern of mutating/consuming an escrow-like record without checking who is entitled to act on it or what funds are already committed.

### Impact Explanation
This falls under "corruption of ... gas fee accounting, refund accounting ... of canonical UniversalTx state" and "unauthorized ... refund of user or protocol-controlled funds" in the allowed-impact gate: an unprivileged actor with no relationship to a stuck inbound can force a rescue at a gas cost of their choosing, degrading the amount ultimately delivered to the rightful owner, and can also grief timing (triggering rescue attempts on someone else's behalf, consuming the one-active-rescue-at-a-time slot with attacker-chosen parameters, blocking the legitimate owner from initiating their own rescue with reasonable gas terms until the forced rescue resolves).

### Likelihood Explanation
Likelihood depends on the actual authorization behavior of the (out-of-Go-scope) `UniversalGatewayPC` Solidity `rescueFunds`-triggering function — its bytecode is embedded as a hex blob in `x/uregistry` and not visible in this repository, so it cannot be conclusively confirmed here whether the contract itself restricts the caller to the original sender. If the contract does not restrict callers (which the Go-side event/keeper handling in `AttachRescueOutboundFromReceipt` clearly does not compensate for), the trigger is trivially reachable by any unprivileged user, since the eligibility state (deposit FAILED / revert REVERTED) is public on-chain data queryable via `GetUniversalTx`.

### Recommendation
In `AttachRescueOutboundFromReceipt`, cross-check `event.Sender` against `originalUtx.InboundTx.Sender` (or an explicitly authorized rescue-initiator field) before honoring the event, and/or clamp `GasFee`/`GasPrice`/`GasLimit` to protocol-defined bounds (e.g., the same oracle-derived gas price used elsewhere in `x/uexecutor/keeper/gas_fee.go`) rather than trusting the values embedded in an arbitrary caller's transaction log.

### Proof of Concept
Not independently verified end-to-end because the Solidity source for `UniversalGatewayPC`'s rescue-triggering function is not present in this repository (only compiled bytecode is stored in `x/uregistry`), so it cannot be confirmed from the Go codebase alone whether the contract itself gates the caller. The Go-side gap is directly demonstrable, however: `AttachRescueOutboundFromReceipt` performs no sender/authorization check against `originalUtx.InboundTx.Sender`, and `test/integration/uexecutor/rescue_funds_test.go` confirms the rescue outbound is created purely from decoded log data (`buildRescueFundsLog`) with an arbitrary `senderAddr`, `gasFee`, `gasPrice`, and `gasLimit`, with no assertion anywhere in that test suite that the caller must equal the original inbound's sender [7](#0-6) .

func (k Keeper) AttachRescueOutboundFromReceipt(
	ctx sdk.Context,
	receipt *evmtypes.MsgEthereumTxResponse,
	pcTx types.PCTx,
) error {
	universalGatewayPC := strings.ToLower(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_GATEWAY_PC"].Address)

	evmChainID, err := utils.ExtractEvmChainID(ctx.ChainID())
	if err != nil {
		return fmt.Errorf("rescue: failed to extract EVM chain ID: %w", err)
	}
	pushChainCaip := fmt.Sprintf("eip155:%s", evmChainID)

	for _, lg := range receipt.Logs {
		if lg.Removed {
			continue
		}
		if strings.ToLower(lg.Address) != universalGatewayPC {
			continue
		}
		if len(lg.Topics) == 0 {
			continue
		}
		if strings.ToLower(lg.Topics[0]) != strings.ToLower(types.RescueFundsOnSourceChainEventSig) {
			continue
		}

		event, err := types.DecodeRescueFundsOnSourceChainFromLog(lg)
		if err != nil {
			return fmt.Errorf("failed to decode RescueFundsOnSourceChain: %w", err)
		}

		// The universalTxId in the event is a 0x-prefixed bytes32 matching our UTX key.
		originalUtxId := strings.TrimPrefix(event.UniversalTxId, "0x")

		originalUtx, found, err := k.GetUniversalTx(ctx, originalUtxId)
		if err != nil {
			return fmt.Errorf("rescue: failed to fetch UTX %s: %w", originalUtxId, err)
		}
		if !found {
			return fmt.Errorf("rescue: original UTX %s not found", originalUtxId)
		}
		if originalUtx.InboundTx == nil {
			return fmt.Errorf("rescue: UTX %s has no inbound tx", originalUtxId)
		}

		// Rescue eligibility differs by inbound type:
		//
		//  CEA inbounds: the deposit (first PCTx) must have failed, meaning the funds
		//  never arrived on Push Chain and are still locked on the source chain.
		//
		//  Non-CEA inbounds: the auto-generated INBOUND_REVERT outbound must exist and
		//  have reached REVERTED status, meaning TSS could not return the funds to the
		//  source chain and they are stuck (held by the gateway contract or in escrow).
		if originalUtx.InboundTx.IsCEA {
			if len(originalUtx.PcTx) == 0 || originalUtx.PcTx[0] == nil || originalUtx.PcTx[0].Status != "FAILED" {
				return fmt.Errorf("rescue: UTX %s CEA deposit did not fail", originalUtxId)
			}
		} else {
			hasRevertedAutoRevert := false
			for _, ob := range originalUtx.OutboundTx {
				if ob != nil && ob.TxType == types.TxType_INBOUND_REVERT && ob.OutboundStatus == types.Status_REVERTED {
					hasRevertedAutoRevert = true
					break
				}
			}
			if !hasRevertedAutoRevert {
				return fmt.Errorf("rescue: UTX %s has no reverted inbound-revert outbound", originalUtxId)
			}
		}

		k.Logger().Info("rescue outbound detected",
			"original_utx_id", originalUtxId,
			"pc_tx_hash", receipt.Hash,
		)

		// Guard against duplicate rescue outbounds: reject if an active rescue
		// (PENDING or OBSERVED) already exists. A REVERTED rescue may be retried.
		for _, ob := range originalUtx.OutboundTx {
			if ob == nil || ob.TxType != types.TxType_RESCUE_FUNDS {
				continue
			}
			if ob.OutboundStatus == types.Status_PENDING || ob.OutboundStatus == types.Status_OBSERVED {
				k.Logger().Warn("rescue outbound rejected: active rescue already exists",
					"original_utx_id", originalUtxId,
					"existing_outbound_id", ob.Id,
				)
				return fmt.Errorf("rescue: UTX %s already has an active rescue outbound (%s)", originalUtxId, ob.Id)
			}
		}

// buildRescueFundsLog constructs a synthetic evmtypes.Log that looks exactly like a
// RescueFundsOnSourceChain event emitted by UniversalGatewayPC. This lets integration
// tests drive AttachRescueOutboundFromReceipt without a real on-chain call.
//
// Event: RescueFundsOnSourceChain(bytes32 indexed universalTxId, address indexed prc20,
//
//	string chainNamespace, address indexed sender, uint8 txType,
//	uint256 gasFee, uint256 gasPrice, uint256 gasLimit)
func buildRescueFundsLog(
	t *testing.T,
	utxId string, // UTX key (64-char hex, no 0x prefix)
	prc20Addr common.Address,
	senderAddr common.Address,
	chainNamespace string,
	gasFee, gasPrice, gasLimit *big.Int,
) *evmtypes.Log {
	t.Helper()

	stringType, _ := abi.NewType("string", "", nil)
	uint8Type, _ := abi.NewType("uint8", "", nil)
	uint256Type, _ := abi.NewType("uint256", "", nil)

	args := abi.Arguments{
		{Type: stringType},  // chainNamespace
		{Type: uint8Type},   // txType (RESCUE_FUNDS = 4)
		{Type: uint256Type}, // gasFee
		{Type: uint256Type}, // gasPrice
		{Type: uint256Type}, // gasLimit
	}
	data, err := args.Pack(chainNamespace, uint8(4), gasFee, gasPrice, gasLimit)
	require.NoError(t, err)

	// UTX ID is stored as a bytes32 topic: "0x" + the 64-char hex UTX key.
	utxIdTopic := "0x" + utxId

	gwPCAddr := utils.GetDefaultAddresses().UniversalGatewayPCAddr

	return &evmtypes.Log{
		Address: gwPCAddr.Hex(),
		Topics: []string{
			uexecutortypes.RescueFundsOnSourceChainEventSig,
			utxIdTopic,
			common.BytesToHash(prc20Addr.Bytes()).Hex(),  // indexed prc20
			common.BytesToHash(senderAddr.Bytes()).Hex(), // indexed sender
		},
		Data:    data,
		Removed: false,
	}
}
