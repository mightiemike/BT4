## Analog Identified: Unvalidated PRC20/asset binding in rescue-outbound attachment

### Title
Rescue outbound accepts attacker-influenced `PRC20` / gas parameters without binding them to the original inbound's deposited asset — ([File: x/uexecutor/keeper/create_outbound.go])

### Summary
The external report's root cause is that `callbackParams.gauge` is accepted and later trusted for a privileged fund-routing decision without verifying it is the *correct* gauge tied to the position being acted on. The Push Chain analog is `AttachRescueOutboundFromReceipt`, which builds a real cross-chain `RESCUE_FUNDS` `OutboundTx` (later signed by TSS and broadcast to release real funds on the source chain) from event fields (`PRC20`, gas fields) embedded in an EVM log, without validating that the `PRC20` address in that log is the *same* token that was actually attempted for deposit on the original, failed inbound.

### Finding Description
`AttachRescueOutboundFromReceipt` [1](#0-0)  scans any EVM receipt for a `RescueFundsOnSourceChain` log emitted by the `UniversalGatewayPC` system contract, decodes it, and resolves the outbound's `ExternalAssetAddr`/`Prc20AssetAddr` purely from the log's `event.PRC20` field: [2](#0-1) 

The only checks performed are:
- the original UTX exists and its deposit previously failed (for CEA) or its auto-revert reverted (non-CEA),
- no other active rescue outbound exists for that UTX,
- the resolved `event.PRC20` maps to *some* registered `TokenConfig` on the UTX's `SourceChain` via `GetTokenConfigByPRC20`.

There is **no check that `event.PRC20` equals the PRC20 mapped to `originalUtx.InboundTx.AssetAddr`** (the asset the user actually attempted to deposit). The keeper effectively lets whatever `PRC20` value is present in the log — a value produced by the EVM call that emitted the event, not cross-checked against the UTX's own recorded asset — determine which registered token the outbound instructs TSS/vault infrastructure to release on the source chain, while `Amount` is still copied verbatim from the original inbound (`originalUtx.InboundTx.Amount`).

This mirrors the gauge bug precisely: a parameter (`gauge` / here `PRC20`) that determines a privileged downstream action (position rebalance / here: which registered asset gets released) is taken from attacker-influenced input and never bound back to the specific record it is being applied to.

### Impact Explanation
If an attacker can trigger a `RescueFundsOnSourceChain` log with `universalTxId` pointing at their own UTX (one they control end-to-end: they set the original `AssetAddr` to a worthless/unregistered token so the CEA deposit fails, making the UTX rescue-eligible) but with `PRC20` set to a *different*, high-value registered token on that same chain, `AttachRescueOutboundFromReceipt` will create a `RESCUE_FUNDS` outbound that carries the original `Amount` but is tagged with the unrelated high-value `ExternalAssetAddr`/`Prc20AssetAddr`. Once UVs observe/sign this outbound via TSS, the vault on the source chain would be instructed to release `Amount` of the *substituted* high-value asset to the recipient — funds the protocol never actually received for that UTX. This is an unauthorized release/drain of protocol-controlled funds via a token-mapping mismatch, directly matching the "corruption of ... token mapping ... must not misroute value or attach the wrong asset semantics" allowed-impact category.

### Likelihood Explanation
Exploitability hinges on whether an unprivileged user can cause the `UniversalGatewayPC` Solidity contract to emit a `RescueFundsOnSourceChain` log with attacker-chosen `PRC20`/gas parameters (e.g., by directly invoking the contract via their own UEA's `executeUniversalTx`, which is a normal user-reachable, gasless-friendly flow per `DERIVED_TRANSACTIONS.md`/`MsgExecutePayload`). That access-control boundary lives in the EVM contract, which is outside this Go repository, so likelihood cannot be fully confirmed from the scoped code alone — but the Go-side keeper provides zero defense-in-depth: even if the contract-side restriction is later found to be insufficient (or is bypassed via any other path that can emit this exact log/topic0 from the gateway address), the keeper will happily convert it into a real, TSS-signed fund release without the missing binding check.

### Recommendation
In `AttachRescueOutboundFromReceipt`, resolve the expected PRC20 from `originalUtx.InboundTx.AssetAddr` via `GetTokenConfig` (chain + asset), and require `event.PRC20` to equal that token's registered `NativeRepresentation.ContractAddress` before building the outbound. Reject (or log-and-skip) any rescue log whose `PRC20` does not match the asset originally recorded for that UTX, closing the "gauge-style" unvalidated-field gap.

### Proof of Concept
1. Attacker submits a CEA inbound whose `AssetAddr` is an unregistered/worthless token so the deposit fails (as in `setupRescueFundsTest` [3](#0-2) ), reaching quorum so a UTX with `FAILED` first `PcTx` exists, with `RevertInstructions.FundRecipient` set to the attacker's own address.
2. Attacker triggers (directly or via their UEA payload) a call that causes `UniversalGatewayPC` to emit `RescueFundsOnSourceChain` with `universalTxId` = the attacker's UTX id, but `PRC20` = the PRC20 address of a real, high-value registered token on the same source chain (e.g., USDC), as constructed in `buildRescueFundsLog` [4](#0-3) .
3. `AttachRescueOutboundFromReceipt` accepts the log, resolves `tokenCfg` via `GetTokenConfigByPRC20(chain, event.PRC20)` [5](#0-4) , and creates a `RESCUE_FUNDS` outbound for the original `Amount` tagged with the substituted high-value `ExternalAssetAddr`/`Prc20AssetAddr` [6](#0-5) , which then proceeds through normal outbound voting/TSS signing to release funds on the source chain.

// AttachRescueOutboundFromReceipt scans the receipt for RescueFundsOnSourceChain events
// emitted by UniversalGatewayPC and, for each one found, attaches a RESCUE_FUNDS outbound
// to the original UTX referenced by the event's universalTxId.
//
// Unlike normal outbounds (which create a new UTX), rescue outbounds are appended to the
// already-existing UTX whose funds are stuck on the source chain.
func (k Keeper) AttachRescueOutboundFromReceipt(
	ctx sdk.Context,
	receipt *evmtypes.MsgEthereumTxResponse,
	pcTx types.PCTx,
) error {
	universalGatewayPC := strings.ToLower(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_GATEWAY_PC"].Address)

	evmChainID, err := utils.ExtractEvmChainID(ctx.ChainID())
	if err != nil {
		return fmt.Errorf("rescue: failed to extract EVM chain ID: %w", err)
	}
	pushChainCaip := fmt.Sprintf("eip155:%s", evmChainID)

	for _, lg := range receipt.Logs {
		if lg.Removed {
			continue
		}
		if strings.ToLower(lg.Address) != universalGatewayPC {
			continue
		}
		if len(lg.Topics) == 0 {
			continue
		}
		if strings.ToLower(lg.Topics[0]) != strings.ToLower(types.RescueFundsOnSourceChainEventSig) {
			continue
		}

		event, err := types.DecodeRescueFundsOnSourceChainFromLog(lg)
		if err != nil {
			return fmt.Errorf("failed to decode RescueFundsOnSourceChain: %w", err)
		}

		// The universalTxId in the event is a 0x-prefixed bytes32 matching our UTX key.
		originalUtxId := strings.TrimPrefix(event.UniversalTxId, "0x")

		originalUtx, found, err := k.GetUniversalTx(ctx, originalUtxId)
		if err != nil {
			return fmt.Errorf("rescue: failed to fetch UTX %s: %w", originalUtxId, err)
		}
		if !found {
			return fmt.Errorf("rescue: original UTX %s not found", originalUtxId)
		}

//	string chainNamespace, address indexed sender, uint8 txType,
//	uint256 gasFee, uint256 gasPrice, uint256 gasLimit)
func buildRescueFundsLog(
	t *testing.T,
	utxId string, // UTX key (64-char hex, no 0x prefix)
	prc20Addr common.Address,
	senderAddr common.Address,
	chainNamespace string,
	gasFee, gasPrice, gasLimit *big.Int,
) *evmtypes.Log {
	t.Helper()

	stringType, _ := abi.NewType("string", "", nil)
	uint8Type, _ := abi.NewType("uint8", "", nil)
	uint256Type, _ := abi.NewType("uint256", "", nil)

	args := abi.Arguments{
		{Type: stringType},  // chainNamespace
		{Type: uint8Type},   // txType (RESCUE_FUNDS = 4)
		{Type: uint256Type}, // gasFee
		{Type: uint256Type}, // gasPrice
		{Type: uint256Type}, // gasLimit
	}
	data, err := args.Pack(chainNamespace, uint8(4), gasFee, gasPrice, gasLimit)
	require.NoError(t, err)

	// UTX ID is stored as a bytes32 topic: "0x" + the 64-char hex UTX key.
	utxIdTopic := "0x" + utxId

	gwPCAddr := utils.GetDefaultAddresses().UniversalGatewayPCAddr

	return &evmtypes.Log{
		Address: gwPCAddr.Hex(),
		Topics: []string{
			uexecutortypes.RescueFundsOnSourceChainEventSig,
			utxIdTopic,
			common.BytesToHash(prc20Addr.Bytes()).Hex(),  // indexed prc20
			common.BytesToHash(senderAddr.Bytes()).Hex(), // indexed sender
		},
		Data:    data,
		Removed: false,
	}
}
