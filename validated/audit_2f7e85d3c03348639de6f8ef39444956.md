### Title
Quadratic-time field lookup in lazily-decoded messages via unbounded linear index scan - (File: internal/protolazy/lazy.go)

### Summary
`lookupField` in `internal/protolazy/lazy.go` performs an O(N) linear scan of the per-message field index on every single field lookup, with no early exit optimized for repeated lookups on the same index. When a message contains many distinct field entries and the runtime performs one lookup per field (as happens during merge, clone, or re-serialization of lazily-decoded messages), the cumulative cost becomes O(N²), mirroring the "O(N²) via repeated per-item full-collection rescans" pattern described in the mistune advisory.

### Finding Description
`buildIndex` in `internal/protolazy/lazy.go:88-266` builds a single flat `[]IndexEntry` covering every field encoded in a lazy submessage's raw bytes in one linear pass (plus an `O(N log N)` sort if the wire bytes are out of field-number order) [1](#0-0) .

Every subsequent lookup for a specific field number goes through `lookupField`, which scans the entire index array from the beginning:
```
func lookupField(indexp *[]IndexEntry, fieldNum uint32) (...) {
	index := *indexp
	for i, entry := range index {
		if fieldNum == entry.FieldNum { ... }
		if fieldNum < entry.FieldNum { return 0, 0, false, false, nil }
	}
	...
}
``` [2](#0-1) 

This is invoked from `FindFieldInProto`, which is the single entry point used to locate a field's raw bytes for lazy unmarshaling [3](#0-2) .

The critical amplifier is that `FindFieldInProto`/`lookupField` is called **once per lazy field**, not once per message. This is visible both during normal unmarshal (`unmarshalPointerLazy`) and during `proto.Merge`:
```
if f.isLazy {
	if sfptr.AtomicGetPointer().IsNil() {
		mi.lazyUnmarshal(src, f.num)
	}
	...
}
``` [4](#0-3) [5](#0-4) 

If a message with `N` fields marked `[lazy = true]` in the `.proto` schema (a legitimate, trusted-schema design choice for large log/config-style messages using the opaque API) is populated by attacker-controlled wire bytes with `N` distinct, non-contiguous field entries, then any subsequent operation that must touch every field — `proto.Merge`, `proto.Clone`, or a full re-marshal to binary/JSON — triggers `N` separate calls to `mi.lazyUnmarshal`, each internally performing an `O(N)` `lookupField` scan over the same index. Total cost: `O(N²)`.

Lazy decoding is on by default for `[lazy=true]`-annotated fields (per `runtime/protolazy/protolazy.go`'s documented default), so no special unmarshal options are required by the caller receiving the request [6](#0-5) .

### Impact Explanation
An attacker who can only control the wire bytes of a request (default `proto.Unmarshal`, trusted schema with `[lazy=true]` fields) can force the server to spend quadratic CPU time during any downstream code path that must visit all fields of the lazily-decoded submessage (merge, clone, re-serialize, log). This is a CPU-exhaustion / algorithmic-complexity DoS analogous to CVE-2026-59928, matching CWE-407/CWE-1333.

### Likelihood Explanation
Exploitability depends on the target schema actually annotating a sizeable number of fields with `[lazy = true]` on a message reachable from unprivileged input, and on the service performing an operation (merge/clone/re-marshal) that forces per-field lazy unmarshaling of all of them. This is a real but narrower precondition than a fully generic "any protobuf service" bug — it only manifests for services deliberately using the lazy-decoding feature with many lazy fields per message.

### Recommendation
Replace the linear index scan in `lookupField` with a binary search (the index is already sorted by field number after `buildIndex`) or a map lookup built once per `FindFieldInProto`/`lazyUnmarshal` cycle, reducing per-lookup cost to `O(log N)` and total cost across `N` fields to `O(N log N)`.

### Proof of Concept
Conceptually (schema-dependent, illustrating the amplification, not a plugin-free generic exploit):
```go
// Given a message type M with N fields f1..fN all annotated [lazy = true]
// in a message type Big (opaque API, default lazy decoding).
//
// Craft raw bytes for the Big submessage with N distinct field numbers,
// each occurring exactly once, e.g. field 1, field 3, field 5, ... field 2N-1,
// so buildIndex produces N distinct IndexEntry records.
buf := craftLazySubmessageBytes(N) // N distinct field tags, minimal payloads

wrapper := &Outer{BigField: buf} // BigField is [lazy=true]
data, _ := proto.Marshal(wrapper)

var m1 Outer
proto.Unmarshal(data, &m1) // default binary unmarshal, lazy decode deferred

// Any operation that must visit every field of BigField triggers
// N calls to lazyUnmarshal -> FindFieldInProto -> lookupField,
// each an O(N) scan over the same index -> O(N^2) total.
var m2 Outer
proto.Merge(&m2, &m1)
```
Doubling `N` should roughly quadruple the time spent inside `lookupField`, consistent with the O(N²) pattern in the mistune advisory.

func (lazy *XXX_lazyUnmarshalInfo) FindFieldInProto(fieldNum uint32) (start, end uint32, found, multipleContiguous bool, multipleEntries []IndexEntry) {
	if lazy.Protobuf == nil {
		// There is no backing protobuf for this message -- it was made from a builder
		return 0, 0, false, false, nil
	}
	index := atomicLoadIndex(&lazy.index)
	if index == nil {
		r, err := buildIndex(lazy.Protobuf)
		if err != nil {
			panic(fmt.Sprintf("findFieldInfo: error building index when looking for field %d: %v", fieldNum, err))
		}
		// lazy.index is a pointer to the slice returned by BuildIndex
		index = &r
		atomicStoreIndex(&lazy.index, index)
	}
	return lookupField(index, fieldNum)
}

func lookupField(indexp *[]IndexEntry, fieldNum uint32) (start, end uint32, found bool, multipleContiguous bool, multipleEntries []IndexEntry) {
	// The pointer indexp to the index was already loaded atomically.
	// The slice is uniquely associated with the pointer, so it doesn't
	// need to be loaded atomically.
	index := *indexp
	for i, entry := range index {
		if fieldNum == entry.FieldNum {
			if i < len(index)-1 && entry.FieldNum == index[i+1].FieldNum {
				// Handle the uncommon case where there are
				// repeated entries for the same field which
				// are not contiguous in the protobuf.
				multiple := make([]IndexEntry, 1, 2)
				multiple[0] = IndexEntry{fieldNum, entry.Start, entry.End, entry.MultipleContiguous}
				i++
				for i < len(index) && index[i].FieldNum == fieldNum {
					multiple = append(multiple, IndexEntry{fieldNum, index[i].Start, index[i].End, index[i].MultipleContiguous})
					i++
				}
				return 0, 0, false, false, multiple

			}
			return entry.Start, entry.End, true, entry.MultipleContiguous, nil
		}
		if fieldNum < entry.FieldNum {
			return 0, 0, false, false, nil
		}
	}
	return 0, 0, false, false, nil
}
