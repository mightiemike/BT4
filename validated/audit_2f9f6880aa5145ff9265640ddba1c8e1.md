**Analysis:**

`get_scalars` on `Witness` is a `public(friend)` function restricted to a small allow-list of friend modules (`sigma_protocol_proof`, `sigma_protocol_homomorphism`, `sigma_protocol`, `sigma_protocol_registration`, `sigma_protocol_withdraw`, `sigma_protocol_transfer`, `sigma_protocol_key_rotation`, plus test-only friends), not a `public` function callable by arbitrary unprivileged Move code outside this module family. [1](#0-0) 

It also returns an immutable reference (`&vector<Scalar>`), so no caller can mutate the underlying `w` vector through it — only read/clone it. [2](#0-1) 

Every `psi` implementation for each protocol (`sigma_protocol_registration`, `sigma_protocol_withdraw`, `sigma_protocol_transfer`) begins with a "WARNING: Crucial for security" length assertion on both the `Statement`'s `n1`/`n2` counts and the `Witness`'s length before any scalar is bound to a generator index, e.g.: [3](#0-2) [4](#0-3) [5](#0-4) 

These asserts use `e_wrong_witness_len`, `e_wrong_num_scalars`, and `e_wrong_num_points` and abort the transaction on any arity mismatch, exactly as the proof idea in the question anticipates. This is the intended defensive design, not a vulnerability — a mismatched-arity `Statement`/`Witness` pairing simply aborts rather than producing a corrupted but accepted `Proof`. The `sigma_protocol::verify` path additionally re-checks lengths against the homomorphism output before accepting any proof. [6](#0-5) 

Since (1) `get_scalars` is friend-scoped and inaccessible to unprivileged external callers, (2) it exposes only an immutable reference, and (3) every consumer of witness/statement scalars validates lengths before binding scalars to generator indices — with failure causing an abort rather than acceptance of a corrupted proof — there is no path by which unprivileged input can misbind a witness scalar to the wrong public generator in an *accepted* `Proof`.
