### Title
Missing overflow guard for FrozenSupply.expireTime pre-VERSION_4_8_1 allows negative/wrapped Frozen.expireTime - ([File: actuator/src/main/java/org/tron/core/actuator/AssetIssueActuator.java])

### Summary
`AssetIssueActuator.validate()` only calls `StrictMathWrapper.addExact(startTime, frozenPeriod)` to guard against `long` overflow of `Frozen.expireTime` when `chainBaseManager.getForkController().pass(ForkBlockVersionEnum.VERSION_4_8_1)` is `true`. Before this fork is activated network-wide, an attacker can submit an `AssetIssueContract` with `startTime` close to `Long.MAX_VALUE` and a valid `frozenDays`, causing `execute()` to silently compute `startTime + next.getFrozenDays() * FROZEN_PERIOD` with wraparound, producing a negative/garbage `Frozen.expireTime` written into `AccountCapsule.frozenSupply`.

### Finding Description
In `validate()` [1](#0-0) , the overflow check is gated behind `chainBaseManager.getForkController().pass(ForkBlockVersionEnum.VERSION_4_8_1)`. There is no upper bound check on `assetIssueContract.getStartTime()` anywhere in `validate()` — the only constraint is `startTime > dynamicStore.getLatestBlockHeaderTimestamp()` [2](#0-1) . `frozenDays` is bounded only by `minFrozenSupplyTime`/`maxFrozenSupplyTime` [3](#0-2) , which does not prevent overflow of `startTime + frozenDays * FROZEN_PERIOD` when `startTime` itself is attacker-chosen near `Long.MAX_VALUE`. In `execute()`, the same expression is computed without any guard: `long expireTime = startTime + next.getFrozenDays() * FROZEN_PERIOD;` [4](#0-3) , and the resulting `Frozen` object (with a wrapped/negative `expireTime`) is written into `accountCapsule`'s `frozenSupply` list and persisted to `accountStore` [5](#0-4) .

However, examining `ForkController.pass()` [6](#0-5) , fork activation for `passNew()` (used for any `ForkBlockVersionEnum` with value greater than `VERSION_4_0`, which `VERSION_4_8_1` is) is derived deterministically from `manager.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp()` and on-chain witness version-signaling statistics (`statsByVersion`), both of which are part of consensus state replicated identically across all nodes that process the same chain of blocks. This is not a node-local "has this node been upgraded" flag — it is chain state derived from block headers and witness signaling recorded in previously-committed blocks, so `pass()` returns the same boolean for every honest node evaluating the same block height/timestamp, precluding a state divergence between "forked" and "non-forked" honest nodes for the *same block*. The genuine risk window is temporal (before the fork activates for the whole network), not a per-node divergence — meaning while overflow *can* occur before `VERSION_4_8_1` activates, it occurs consistently for all honest nodes, not divergently.

### Impact Explanation
Before `VERSION_4_8_1` activates network-wide, an attacker-crafted `AssetIssueContract` with an overflowing `startTime`/`frozenDays` combination results in a negative or wrapped `Frozen.expireTime` being persisted on-chain in the issuer's `AccountCapsule.frozenSupply`. This is a real state-correctness bug (a frozen supply entry with an invalid/negative expire time could interact unpredictably with unfreeze logic), but it does not by itself cause divergence between honest nodes at the same block height/timestamp, since fork activation is consensus-derived and uniform.

### Likelihood Explanation
Reachable by any unprivileged account submitting an `AssetIssueContract` transaction (broadcastable via the public transfer/broadcast API) before the network's `VERSION_4_8_1` hard fork time is reached. Fully repeatable pre-fork; not exploitable post-fork due to the added `addExact` guard.

### Recommendation
Remove the `ForkBlockVersionEnum.VERSION_4_8_1` gating and apply the `StrictMathWrapper.addExact` overflow check unconditionally in `validate()`, and add a defensive bound on `startTime` (or use the same guarded computation) in `execute()` as well, so overflow is rejected regardless of fork status.

### Proof of Concept
```java
// AssetIssueActuatorTest.java (framework/src/test/java/org/tron/core/actuator/)
@Test
public void testOverflowExpireTimePreFork() throws Exception {
  // Simulate ForkController.pass(VERSION_4_8_1) == false (pre-fork chain state)
  // e.g. by setting latestBlockHeaderTimestamp before the hard fork time.

  long startTime = Long.MAX_VALUE - 1000; // near overflow boundary
  long frozenDays = dbManager.getDynamicPropertiesStore().getMinFrozenSupplyTime();

  AssetIssueContract contract = AssetIssueContract.newBuilder()
      .setOwnerAddress(ByteString.copyFrom(OWNER_ADDRESS))
      .setName(ByteString.copyFromUtf8("testAsset"))
      .setTotalSupply(1000L)
      .setTrxNum(1)
      .setNum(1)
      .setStartTime(startTime)
      .setEndTime(startTime + 1) // must be > startTime
      .addFrozenSupply(FrozenSupply.newBuilder()
          .setFrozenAmount(100L)
          .setFrozenDays(frozenDays)
          .build())
      .build();

  AssetIssueActuator actuator = new AssetIssueActuator();
  actuator.setChainBaseManager(chainBaseManager);
  actuator.setAny(Any.pack(contract));

  // validate() should throw ContractValidateException regardless of fork status,
  // but currently passes pre-fork.
  actuator.validate(); // expected: throws; actual (pre-fork): does not throw

  TransactionResultCapsule ret = new TransactionResultCapsule();
  actuator.execute(ret);

  AccountCapsule account = accountStore.get(OWNER_ADDRESS);
  long computedExpire = account.getInstance().getFrozenSupply(0).getExpireTime();
  // Assert the bug: expireTime wraps to negative due to overflow
  assertTrue("expected overflow wraparound", computedExpire < 0);
}
```
Expected: post-fix, `validate()` throws `ContractValidateException("Start time and frozen days would cause expire time overflow")` unconditionally, regardless of `ForkController.pass(VERSION_4_8_1)` result.

  private boolean passNew(int version) {
    ForkBlockVersionEnum versionEnum = ForkBlockVersionEnum.getForkBlockVersionEnum(version);
    if (versionEnum == null) {
      logger.warn("Not exist block version: {}.", version);
      return false;
    }
    long latestBlockTime = manager.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    long maintenanceTimeInterval = manager.getDynamicPropertiesStore().getMaintenanceTimeInterval();
    long hardForkTime = ((versionEnum.getHardForkTime() - 1) / maintenanceTimeInterval + 1)
        * maintenanceTimeInterval;
    if (latestBlockTime < hardForkTime) {
      return false;
    }
    byte[] stats = manager.getDynamicPropertiesStore().statsByVersion(version);
    if (stats == null || stats.length == 0) {
      return false;
    }
    int count = 0;
    for (int i = 0; i < stats.length; i++) {
      if (check[i] == stats[i]) {
        ++count;
      }
    }
    return count >= ceil((double) versionEnum.getHardForkRate() * stats.length / 100,
        manager.getDynamicPropertiesStore().disableJavaLangMath());
  }
