### Title
Vault `accrue` pause pass-through returns stale index/lindex instead of reverting, allowing dependent calculations to silently use outdated values - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
The lnd bug fixes a TOCTOU where a value (open-channel count) is checked, then invalidated by a concurrent event, then acted upon without re-checking. The Zest vault contracts have a single-transaction analog: `accrue` reads `pause-states` and, when `accrue` is paused, returns the **currently stored** `index`/`lindex` unchanged - a pass-through instead of a revert - while every caller (`deposit`, `redeem`, `system-borrow`, `system-repay`, `socialize-debt`, `flashloan`) still treats that returned pair as fresh/authoritative for computing shares, debt, and caps in the same call.

### Finding Description
`accrue` in `mainnet/contracts/vault/v0-vault-stx.clar` (lines 835-863) is structured as:
```clarity
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ...
``` [1](#0-0) 

When `accrue` is paused, this returns `(ok {...})` with success, not an error - callers cannot distinguish "fresh index" from "stale index because accrual is paused." Every state-mutating entry point (`deposit`, `redeem`, `system-borrow`, `system-repay`) calls `(u (try! (accrue)))` at the top and then proceeds to compute `total-debt`, `convert-to-shares-preview`/`convert-to-assets-preview`, and cap checks using `(var-get index)`/`(var-get principal-scaled)` as if they reflect current time. [2](#0-1) [3](#0-2) 

Separately, `set-pause-states` (lines 723-748) shows the intended invariant: when unpausing accrual, it explicitly jumps `last-update` to `stacks-block-time` "to skip paused period," i.e., the protocol designer's assumption is that no interest/index drift occurs while paused. [4](#0-3) 

This maps to the "a pause that passes through instead of reverting" analog class named in scope: the source of truth (the interest index) is meant to move with time (`next-index`/`next-liquidity-index` use `stacks-block-time - last-update`), but while `accrue` is paused, the index is frozen at whatever value it had when the pause was toggled by DAO action - and downstream math (deposit share pricing, debt totals, socialize-debt lindex write-down) keeps consuming that frozen value as if it were live, with no error path signaling staleness to composed callers in `mainnet/contracts/market/v0-4-market.clar`'s `accrue-and-cache`, which caches whatever `vault-accrue` returns per block-timestamp key without any staleness flag. [5](#0-4) 

### Impact Explanation
Because the market's `accrue-and-cache` treats the vault's returned index as ground truth for pricing zToken collateral and scaled-debt conversion during `borrow`, `repay`, `collateral-add`, and `liquidate` in the same block, a paused-accrue vault silently freezes valuation at a stale rate for the duration of the pause, while collateral/debt positions denominated in other (unpaused) assets keep moving. This can misprice collateral vs. debt across assets within the same egroup and distort health-factor checks (`is-healthy`, liquidation thresholds), potentially permitting under-collateralized borrows or mispriced liquidations while the pause is active - a temporary freezing/mispricing of funds condition rather than a benign no-op.

### Likelihood Explanation
This requires DAO-controlled `set-pause-states` (accrue: true) to be active, which is an admin action, but once active it is not a deliberate "safety" outcome documented anywhere as intentionally freezing valuation math for dependent contracts - the pass-through is silent (`ok`, not `err`), so composing contracts have no way to detect and defensively handle the stale state. The likelihood of the pause being toggled is admin-gated, but the vulnerability itself - lack of any propagated staleness signal - is a code-level gap independent of DAO trust.

### Recommendation
When `accrue` is paused, either (a) return an explicit error/staleness flag distinguishable from a fresh accrual result so callers like `market.clar`'s `accrue-and-cache` and health-check logic can decide whether to proceed, or (b) ensure all downstream consumers of `index`/`lindex` are also paused/blocked consistently while accrual is paused, preventing mixed fresh/stale valuations within the same transaction.

### Proof of Concept
1. DAO calls `set-pause-states` on `v0-vault-stx` with `accrue: true`, freezing `index`/`lindex` at time T0. [4](#0-3) 
2. Time passes; other vaults (e.g., `v0-vault-usdc`) continue accruing normally.
3. A user calls `market.clar`'s `borrow`/`collateral-add`/`liquidate` involving both the paused-accrue STX vault (as zSTX collateral) and an actively-accruing debt asset.
4. `accrue-and-cache` calls `vault-accrue` on the STX vault, which hits the pause branch and returns the T0 index/lindex as `(ok ...)` with no distinguishing signal. [5](#0-4) 
5. `get-notional-evaluation`/`calculate-asset-notional-value` price the zSTX collateral using this stale index while the debt side uses live-accrued values, producing a skewed collateral/debt ratio used in the health check that gates the borrow/liquidation. [6](#0-5)

(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))
  (begin
    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      ;; When pausing accrue, accrue first to capture pending interest
      (if (and (not was-paused) now-paused)
          (begin (try! (accrue)) false)
          false)
      ;; When unpausing accrue, jump last-update to now to skip paused period
      (if (and was-paused (not now-paused))
          (var-set last-update stacks-block-time)
          false)
      (var-set pause-states states)

        action: "vault-set-pause-states",
        caller: tx-sender,
        data: {
          vault: UNDERLYING,
          states: states
        }
      })
      
      (ok true))))

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
