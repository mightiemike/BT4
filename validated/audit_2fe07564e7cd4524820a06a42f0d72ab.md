## Title
Integer-division truncation of `minPCOut` (quote × 95 / 100) nullifies slippage protection on module-driven PRC20→WPC auto-swaps — ([File: x/uexecutor/keeper/execute_inbound_gas.go])

### Summary
The `_getExchangeRate`-style precision-loss bug class in the Sherlock report (integer division rounding a minimum-received value to zero) has a direct analog in `x/uexecutor/keeper`'s slippage calculation for the on-chain Uniswap auto-swap performed on every `GAS` / `GAS_AND_PAYLOAD` inbound and on the excess-gas refund path. `minPCOut` is computed with the same rounding-down integer arithmetic and is used as the sole slippage guard for a real AMM swap the module executes on behalf of the depositing user.

### Finding Description
In three places the keeper computes a "5% slippage" minimum output by multiplying a quoted amount by 95 and dividing by 100 using Go `big.Int` integer division (truncating, not rounding): [1](#0-0) [2](#0-1) [3](#0-2) 

`quote` itself is fetched live from the Uniswap V3 `QuoterV2.quoteExactInputSingle` call, i.e., it reflects the current on-chain pool price for the exact `amount` being swapped: [4](#0-3) . `minPCOut` is then passed straight through to `depositPRC20WithAutoSwap` (or `refundUnusedGas`) on the `UniversalCore` handler contract, which uses it as the Uniswap `amountOutMinimum` for a real swap: [5](#0-4) [6](#0-5) .

Because `quote * 95 / 100` is computed with Go's truncating integer division, whenever `quote < 20` (in raw base units of the output token — e.g. a small deposit amount, a low-decimals/low-priced PRC20 token, or a small residual gas refund), the result truncates to `0`. This exactly reproduces the root cause described in the external report: `(priceIn * K) / priceOut` rounding to zero for cheap/low-magnitude inputs, here manifesting as the swap's slippage floor collapsing to zero.

With `minPCOut == 0`, the module's swap transaction (`depositPRC20WithAutoSwap` / `refundUnusedGas` with `withSwap=true`) has **no effective slippage protection at all**. Any unprivileged actor able to see this pending module transaction (mempool/block-builder visibility on the Push Chain EVM) can sandwich it: push the PRC20/WPC pool price against the module's swap immediately beforehand, let the module's zero-minimum swap execute at the manipulated price, and reverse the price afterward — extracting essentially the entire swapped value out of the user's deposited/refunded funds. This is a purely permissionless, honest-validator-compatible attack: the validators correctly vote on the inbound and correctly compute the same (buggy) `minPCOut`; the loss occurs purely from the on-chain AMM interaction lacking real slippage protection.

### Impact Explanation
This directly corrupts PRC20/native asset accounting for the depositing user: the amount of WPC (native Push token) credited to the user's UEA after a `GAS`/`GAS_AND_PAYLOAD` inbound, or the amount refunded via `applyGasRefund`, can be driven down to near zero by any unprivileged party sandwiching the module's swap, even though the deposit/inbound itself was legitimate and correctly voted on by honest validators. This matches the in-scope impact category "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" and can cause unbounded value extraction/loss for the affected user with no privileged actor required.

### Likelihood Explanation
Deposits of small amounts, dust gas refunds, or PRC20 tokens with few decimals/low unit price are common and would trivially produce `quote < 20`, so `minPCOut = 0` is a realistic, frequently-triggerable condition rather than an edge case. Once `minPCOut` is zero, exploitation only requires ordinary transaction submission ability against the Push Chain EVM around the module's known swap call pattern (deterministic contract/method), which is achievable by any external, unprivileged party.

### Recommendation
- Do not let `minPCOut` truncate to zero when `quote` is non-zero: use a rounding scheme that preserves a meaningful floor (e.g., compute in higher precision, or explicitly enforce `minPCOut = max(1, quote*95/100)` combined with a `require(minPCOut > 0)`-style check before invoking the swap), or reject/skip the auto-swap path entirely when the computed minimum would be zero, falling back to a non-swap deposit.
- More generally, apply the fix consistently across all three call sites (`execute_inbound_gas.go`, `execute_inbound_gas_and_payload.go`, `outbound.go`) since they share the identical vulnerable pattern.

### Proof of Concept
1. A user bridges a small amount of a PRC20-eligible gas token (or a low-decimals/low-priced token) as a `GAS` inbound such that `GetSwapQuote` returns `quote < 20` raw units of WPC.
2. Honest validators vote the inbound to quorum; `ExecuteInboundGas` computes `minPCOut := quote*95/100` which truncates to `0` (see `x/uexecutor/keeper/execute_inbound_gas.go` lines 142-146).
3. `CallPRC20DepositAutoSwap` invokes `depositPRC20WithAutoSwap(prc20, amount, ueaAddr, fee, minPCOut=0, deadline)` on `UniversalCore`, which performs a Uniswap V3 exact-input swap with `amountOutMinimum = 0`.
4. An unprivileged attacker observing this transaction sandwiches it (buy WPC before / sell after in the same pool), causing the module's swap to execute at a manipulated price and deliver near-zero WPC to the user's UEA, while the attacker captures the difference.
5. The same pattern applies to `gasAndPayloadDepositAutoSwap` (`execute_inbound_gas_and_payload.go`) and to the gas-refund swap in `applyGasRefund` (`outbound.go`).

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
