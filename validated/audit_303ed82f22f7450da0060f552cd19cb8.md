### Title
Rounding mismatch between signer-side global-agreement threshold and on-chain block-approval threshold allows a sub-70% signer minority to force a divergent "global state" - ([File: libsigner/src/v0/signer_state.rs])

### Summary
`GlobalStateEvaluator::reached_agreement` in `libsigner/src/v0/signer_state.rs` computes the 70%-of-weight agreement threshold using **floor** integer division, while the canonical, on-chain block-approval threshold `NakamotoBlockHeader::compute_voting_weight_threshold` in `stackslib/src/chainstate/nakamoto/mod.rs` computes the same 70% cutoff using **ceiling** division. The two are supposed to represent the same "supermajority" quantity but disagree by 1 unit of weight whenever `total_weight * 7` is not a multiple of 10 — which is the common case. A minority of signers holding exactly the floor-rounded weight (one weight-unit below the real, ceiling-rounded 70% threshold) can therefore make `GlobalStateEvaluator` report that "global agreement" has been reached, even though that same weight would be rejected as insufficient by the actual block-signing threshold check. [1](#0-0) [2](#0-1) 

### Finding Description
`compute_voting_weight_threshold` — the function that gates real block signature/acceptance consensus (`verify_signer_signatures`, and the identical calculation duplicated in `store_and_process_block_signature`/`handle_block_pre_commit` in `stacks-signer/src/v0/signer.rs`) — always rounds *up*:

```rust
pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
    let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD; // = 7
    let total_weight = u64::from(total_weight);
    let ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
    u32::try_from((total_weight * threshold) / 10 + ceil)...
}
``` [3](#0-2) 
confirmed by the unit test: for `total_weight = 511`, threshold = 358 (`511*7=3577 → 357.7 → ceil → 358`). [4](#0-3) 

By contrast, `GlobalStateEvaluator::reached_agreement`, used by the signer state machine to decide whether the *global* protocol version, burn view, current-miner/tenure state, and transaction-replay set have reached consensus, rounds *down* (plain integer truncation):

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    u64::from(vote_weight)
        >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
}
``` [5](#0-4) 

For `total_weight = 511`, `reached_agreement` treats `357` as sufficient (`511*7/10 = 357` after floor), one unit below the `358` that the on-chain/block-level path actually requires. This function is the sole primitive used by `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, `determine_global_state`, and `find_majority_prefix_replay_set` [6](#0-5) [7](#0-6)  — all of which are consumed by `stacks-signer` (`stacks-signer/src/v0/signer_state.rs`, `stacks-signer/src/v0/signer.rs`) to decide which miner/tenure the signer set as a whole recognizes as canonical.

This is the same bug class as the referenced report: two logically-equivalent "≥ threshold-of-total" checks are implemented with different rounding directions, so a value that should uniformly pass/fail on both sides instead passes on the looser side and fails on the stricter side. Here the equality broken is: *the weight required for "signer-set consensus" on global state* should equal *the weight required for a block's signatures to be valid*, but it does not.

### Impact Explanation
An adversarial or just unlucky signer subset controlling weight equal to `floor(total_weight*7/10)` (a strict, computable minority under the intended 70% supermajority, requiring no majority collusion) can:
- Cause `GlobalStateEvaluator` to report "global agreement" on a miner/tenure/burn-view/protocol-version state that a stricter reading of the same 70% rule (as enforced for actual block signature acceptance) would reject as under-threshold.
- Produce **divergent views among signer nodes** about the canonical global state (miner validity, tenure, replay set) whenever different signer processes compute this weight-boundary case differently in time (e.g., depending on update arrival order in the `HashMap` iteration in `determine_global_state`), or when the true block-signing path (needing 358) later fails to reach consensus while the state-machine layer (needing only 357) already "decided."

This is a minority-triggerable validation/consensus divergence bounded to signer state-machine agreement (miner/tenure recognition, replay-set agreement), which can manifest as temporary tip/miner disagreement across signers — matching the **High** severity bucket ("a minority-triggerable sortition/VRF/static-validation divergence... temporary tip disagreement"). It does not directly forge STX rewards or corrupt the MARF/state root, so it does not rise to Critical.

### Likelihood Explanation
The discrepancy is deterministic and occurs whenever `total_weight * 7` is not evenly divisible by 10 — the overwhelming majority of realistic `total_weight` values (any reward-set size not a multiple of 10). No node operator or admin key is required; a signer weight distribution that happens to land exactly on the off-by-one boundary (an unprivileged, naturally occurring condition, or one an attacker holding slightly less than 70% weight can arrange) is sufficient to trigger the divergence at every reward cycle where this boundary condition arises.

### Recommendation
Change `GlobalStateEvaluator::reached_agreement` (and, symmetrically, `reached_disagreement`) to use the same ceiling-division formula as `NakamotoBlockHeader::compute_voting_weight_threshold`, i.e.:

```rust
pub fn reached_agreement(&self, vote_weight: u32) -> bool {
    let total = u64::from(self.total_weight);
    let threshold = total.strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD);
    let ceil = if threshold % 10 == 0 { 0 } else { 1 };
    u64::from(vote_weight) >= threshold / 10 + ceil
}
```
so that "global state agreement" and "block signature acceptance" always require exactly the same weight threshold, eliminating the possibility that a sub-threshold minority is treated as having reached consensus by one code path but not the other. Ideally, both call sites should share a single canonical threshold function (e.g. exposing `NakamotoBlockHeader::compute_voting_weight_threshold` for reuse in `libsigner`) rather than maintaining two independent implementations that can drift.

### Proof of Concept
1. Configure a reward-cycle signer set whose weights sum to `total_weight = 511` (any value where `total_weight * 7 % 10 != 0` works; `511` is directly validated by the existing `test_compute_voting_weight_threshold` unit test, which asserts the on-chain threshold is `358`). [4](#0-3) 
2. Have a subset of signers whose combined weight is exactly `357` submit matching `StateMachineUpdate`s (e.g., agreeing on the same `current_miner`/tenure or burn view).
3. Call `GlobalStateEvaluator::reached_agreement(357)` with `total_weight = 511`:
   `357 >= 511*7/10 (=357, floored)` → returns `true` — the signer layer now believes global consensus/agreement has been reached on that miner/tenure/burn-view state.
4. Simultaneously, the same 357 weight, if it were being used to authorize an actual Nakamoto block (`verify_signer_signatures` → `compute_voting_weight_threshold(511) == 358`), would be rejected: `357 < 358` → `"Not enough signatures"` error. [8](#0-7) 
5. This demonstrates the two consensus-critical thresholds diverge by exactly one weight unit for identical inputs, letting a minority (357/511 ≈ 69.86%, strictly less than the intended 70% supermajority) force the signer state machine into "agreement" that the block-level protocol would not itself recognize as sufficient.

    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Check if there is an agreed upon global state
    pub fn determine_global_state(&self) -> Option<SignerStateMachine> {
        let active_signer_protocol_version =
            self.determine_latest_supported_signer_protocol_version()?;
        let mut state_views = HashMap::new();
        let mut tx_replay_sets = HashMap::new();
        let mut found_state_view = None;
        let mut found_replay_set = None;
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

            if self.reached_agreement(*entry) {
                found_state_view = Some(state_machine);
            }

            let replay_entry = tx_replay_sets
                .entry(tx_replay_set.clone())
                .or_insert_with(|| 0);
            *replay_entry += weight;

            if self.reached_agreement(*replay_entry) {
                found_replay_set = Some(tx_replay_set);
            }
            if found_replay_set.is_some() && found_state_view.is_some() {
                break;
            }
        }
        // Try to find agreed replay set, or find longest common prefix if no exact agreement
        let final_replay_set = if let Some(tx_replay_set) = found_replay_set {
            tx_replay_set
        } else {
            // No exact agreement found, try finding longest common prefix with majority support
            self.find_majority_prefix_replay_set(&tx_replay_sets)
                .unwrap_or_else(ReplayTransactionSet::none)
        };

        if let Some(state_view) = found_state_view.as_mut() {
            state_view.tx_replay_set = final_replay_set;
        }
        found_state_view
    }
