### Title
Starknet OS `execute_replace_class` omits the declared-class check enforced by the Blockifier, causing execution divergence on `replace_class` syscall - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Blockifier's Rust implementation of the `replace_class` syscall validates that the target `class_hash` is actually declared (and Cairo-version-compatible) before mutating contract state, but the Starknet OS's Cairo re-implementation of the same syscall performs the state mutation unconditionally, with an explicit `TODO` noting the missing check. Any contract can invoke `replace_class` with an arbitrary, undeclared class hash from a single unprivileged transaction, exercising this divergent code path.

### Finding Description
In the Blockifier, `replace_class` is guarded by an explicit declared-class check before the state is mutated: [1](#0-0) 

The non-deprecated syscall path and native syscall handler simply forward to a shared `base.replace_class`, which performs the same validation (confirmed by the test asserting `"is not declared"` and `"Cannot replace V1 class hash with V0 class hash"` errors): [2](#0-1) [3](#0-2) 

In contrast, the Starknet OS's Cairo implementation of the same syscall in `syscall_impls.cairo` (the "new" syscalls path used for re-execution/proving) writes the new class hash into `contract_state_changes` with no declared-class validation at all, and explicitly flags the gap with a TODO: [4](#0-3) 

The same omission exists in the deprecated syscalls path used by the OS: [5](#0-4) 

This mirrors the audit pattern cited in the report: one code path (`register`/Blockifier) enforces a whitelist/validity check, while a semantically-equivalent sibling path (`replace`/Starknet OS) omits it, allowing an operation that should be rejected to succeed.

### Impact Explanation
Since the Starknet OS independently re-executes the Cairo VM syscall trace as part of Starknet OS re-execution to compute/verify the state transition, a transaction that calls `replace_class` with an undeclared (or Cairo-version-incompatible) class hash will be rejected/reverted by the Blockifier when the block is actually built, but the OS's Cairo implementation would accept and apply the same state mutation without error if it independently executed the transaction. This is a concrete honest-node divergence: the two execution engines that are supposed to agree on the semantics of the same transaction can compute different results (reverted vs. succeeded, and different resulting class hash / state root), undermining the soundness guarantee that OS proofs faithfully represent valid Starknet state transitions.

### Likelihood Explanation
The `replace_class` syscall is reachable directly from any contract via a single unprivileged transaction with no special privileges required — any account or contract can invoke it with an arbitrary calldata-supplied class hash, making the divergent code path trivially exercisable.

### Recommendation
Add a "declared class" check in the OS's `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) mirroring the Blockifier's `get_compiled_class` validation, and mirror the Cairo0/Cairo1 replacement compatibility check enforced in the Blockifier, so both execution engines reject the same set of transactions.

### Proof of Concept
1. Deploy a contract exposing an entry point that calls the `replace_class` syscall with a `class_hash` for which no class has been declared (as done in the Blockifier regression test `undeclared_class_hash`). [3](#0-2) 
2. Submit this transaction; the Blockifier rejects it with `"is not declared"`.
3. Independently trace the same syscall through the OS's Cairo `execute_replace_class`, which lacks the equivalent check and would apply the state mutation unconditionally. [6](#0-5)

func execute_replace_class{contract_state_changes: DictAccess*, revert_log: RevertLogEntry*}(
    contract_address, syscall_ptr: ReplaceClass*

    alloc_locals;
    let class_hash = syscall_ptr.class_hash;

    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
