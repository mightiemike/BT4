### Title
Non-EVM/non-Solana chain addresses and tx hashes are canonicalized as a pass-through, letting equal-value encoding variants fragment inbound ballots and UniversalTx keys - (File: `utils/canonical.go`)

### Summary
`uregistry`'s `ChainConfig.VmType` explicitly enumerates non-EVM/non-SVM virtual machines (`MOVE_VM`, `WASM_VM`, `CAIRO_VM`, `TRON_VM`, `STELLAR_VM`, `BITCOIN_SCRIPT`, `OTHER_VM`) as supported chain types, and `ChainConfig.ValidateBasic` accepts any value in that enum [1](#0-0) [2](#0-1) . However, the canonicalization layer that keeps ballot/UTX keys collision-free across encoding variants only implements real per-namespace normalization for `eip155` and `solana`; every other CAIP-2 namespace falls through to a bare `strings.TrimSpace` pass-through [3](#0-2) . This is exactly the seed bug's pattern: a function whose logic is written for one/two specific supported "domains" and silently mishandles any other value the schema claims to support.

### Finding Description
`CanonicalizeAddressByNamespace` and `CanonicalizeTxHashByNamespace` switch only on `namespaceEVM` ("eip155") and `namespaceSolana` ("solana"); the `default` branch returns the trimmed input unchanged, with no case, padding, or format normalization [3](#0-2) . Their lenient wrappers, `LenientCanonicalizeAddress` and `LenientCanonicalizeTxHash`, are used directly in `Inbound.Canonicalize()` to normalize `SourceChain`, `TxHash`, `Sender`, `AssetAddr`, and `RevertInstructions.FundRecipient` before ballot/UTX keys are derived [4](#0-3) . The file's own doc comment states the intended invariant: "One form per value so encoding variance can't fragment votes or duplicate rows" [5](#0-4)  — an invariant that is only enforced for two of the nine declared VM types.

`VoteInbound` derives both the UTX key and the ballot key straight from the (canonicalized) `Inbound` fields [6](#0-5) , and ballot finalization requires 2/3+ of Universal Validators to vote on the *same* ballot key [7](#0-6) . Many of the non-EVM/non-SVM chain families listed in `VmType` have multiple textually-distinct valid representations of the same on-chain identity (e.g. Move/Aptos-style addresses with variable leading-zero padding, mixed-case Cosmos-style bech32 vs hex forms, or checksum-vs-lowercase variants for various VM address encodings). Because the registry advertises support for these VM types but the shared canonicalization utility does not normalize them, honest Universal Validators independently reading the exact same real-world gateway event from an external chain of one of these types can legitimately report a different literal string for `Sender`/`AssetAddr`/`TxHash`/`FundRecipient` — with no malicious actor involved.

### Impact Explanation
If honest UVs diverge on the canonical string for the same logical inbound (purely due to formatting differences in the source-chain address/hash they each independently observed), each distinct literal string produces its own `InboundVariant`/ballot key via `GetInboundBallotKey`/`GetInboundUniversalTxKey`. Votes for the same real event get split across multiple ballots, none of which independently reaches the 2/3+ threshold. This is a broken honest-validator finalization invariant ("user-created source events... must not let honest UVs converge on the wrong ballot") that can result in a genuine user deposit never reaching quorum — i.e., the inbound sits unresolved (or times out and is only recoverable via the admin-only `RevertStuckInbound` path [8](#0-7) ), which is a permanent-freezing-of-user-funds risk for chains of these VM types, reachable purely from an ordinary user's deposit on an already-configured non-EVM/non-SVM chain, with no privileged or malicious actor required.

### Likelihood Explanation
Likelihood is currently constrained by the fact that no production `ChainConfig` in this repo's config directories uses a VM type other than `EVM` or `SVM` today (only `eip155:*` and `solana:*` configs were found in `config/` and test fixtures) — this is analogous to the seed report's own admission that Linea "currently only supports registration of base domain `linea.eth`... this issue does not presently occur." The moment `uregistry`'s admin (a legitimate, non-malicious, in-scope configuration action, not "admin abuse") activates any of the other seven declared `VmType` values, this gap becomes live and reachable purely by ordinary users depositing on that chain — no validator, relayer, or admin misbehavior is needed to trigger the divergence, only encoding variance inherent to the target chain's address/hash format.

### Recommendation
Add explicit per-namespace canonicalization branches in `CanonicalizeAddressByNamespace` and `CanonicalizeTxHashByNamespace` (`utils/canonical.go`) for every `VmType` the registry allows to be configured (`MOVE_VM`, `WASM_VM`, `CAIRO_VM`, `TRON_VM`, `STELLAR_VM`, `BITCOIN_SCRIPT`, `OTHER_VM`), matching the canonical/checksum format used by that chain family, instead of relying on the generic trim-only `default` branch. Alternatively, gate `uregistry.AddChainConfig`/`ChainConfig.ValidateBasic` so it rejects `VmType` values that the canonicalization layer (and `universalClient/chains.addChain`, which already errors on unsupported VM types [9](#0-8) ) does not yet fully support end-to-end, keeping the declared enum and the actually-safe implementation in sync.

### Proof of Concept
1. `uregistry` admin adds a `ChainConfig` with `vm_type = MOVE_VM` (or any non-`EVM`/`SVM` value) — this passes `ValidateBasic` since it only range-checks the enum [1](#0-0) .
2. A user deposits funds via that chain's gateway; the address format for the sender legitimately has two equal-value textual encodings (e.g., zero-padded vs. non-padded forms common in Move-VM addressing).
3. Two honest Universal Validators independently observe the same event but each surfaces the sender address in its own (both valid) textual form.
4. Both call `MsgVoteInbound`; `Inbound.Canonicalize()` → `LenientCanonicalizeAddress` hits the `default` branch of `CanonicalizeAddressByNamespace` and passes each string through unchanged (only trimmed) [10](#0-9) .
5. `GetInboundBallotKey`/`GetInboundUniversalTxKey` therefore produce two different keys for what is the same logical inbound, splitting the vote across two ballots that individually never reach the 2/3+ `votesNeeded` threshold in `VoteOnInboundBallot` [7](#0-6) , leaving the user's inbound permanently unfinalized absent manual admin intervention.

I could not directly execute this end-to-end in the codebase (no live non-EVM/non-SVM chain config exists in this repo to exercise), so the concrete trigger condition (a chain family with genuinely ambiguous address/hash textual encodings) is inferred from the `VmType` enum's declared scope rather than observed in a live configuration — this should be validated against the specific address/hash formats of whichever `VmType` chain is first activated.

// CanonicalizeAddressByNamespace canonicalizes an address for the given
// CAIP-2 chain. Empty input passes through (optional fields).
func CanonicalizeAddressByNamespace(chain, addr string) (string, error) {
	addr = strings.TrimSpace(addr)
	if addr == "" {
		return "", nil
	}
	switch CAIP2Namespace(chain) {
	case namespaceEVM:
		return CanonicalizeEVMAddress(addr)
	case namespaceSolana:
		return canonicalizeSolanaValue(addr)
	default:
		return addr, nil
	}
}

// CanonicalizeTxHashByNamespace canonicalizes a transaction hash/signature
// for the given CAIP-2 chain. Empty input passes through (e.g. failed
// outbound observations carry no hash).
func CanonicalizeTxHashByNamespace(chain, txHash string) (string, error) {
	txHash = strings.TrimSpace(txHash)
	if txHash == "" {
		return "", nil
	}
	switch CAIP2Namespace(chain) {
	case namespaceEVM:
		return CanonicalizeEVMHash(txHash)
	case namespaceSolana:
		return canonicalizeSolanaTxHash(txHash)
	default:
		return txHash, nil
	}
}

func (p *Inbound) Canonicalize() {
	p.SourceChain = strings.TrimSpace(p.SourceChain)
	p.TxHash = utils.LenientCanonicalizeTxHash(p.SourceChain, p.TxHash)
	p.Sender = utils.LenientCanonicalizeAddress(p.SourceChain, p.Sender)
	p.AssetAddr = utils.LenientCanonicalizeAddress(p.SourceChain, p.AssetAddr)
	// Recipient lives on Push Chain (EVM) regardless of source chain.
	p.Recipient = utils.LenientCanonicalizeEVMAddress(p.Recipient)
	p.LogIndex = strings.TrimSpace(p.LogIndex)
	p.Amount = strings.TrimSpace(p.Amount)
	p.RawPayload = utils.CanonicalizeHexBlob(p.RawPayload)
	p.VerificationData = utils.CanonicalizeHexBlob(p.VerificationData)
	if p.RevertInstructions != nil {
		// Refunds return to the source chain.
		p.RevertInstructions.FundRecipient = utils.LenientCanonicalizeAddress(p.SourceChain, p.RevertInstructions.FundRecipient)
	}
}

func (k Keeper) VoteOnInboundBallot(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	inbound types.Inbound,
) (isFinalized bool,
	isNew bool,
	err error) {
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return false, false, err
	}

	universalValidatorSet, err := k.uvalidatorKeeper.GetEligibleVoters(ctx)
	if err != nil {
		return false, false, err
	}

	// number of validators
	totalValidators := len(universalValidatorSet)

	// votesNeeded = ceil(2/3 * totalValidators)
	// >2/3 quorum similar to tendermint
	votesNeeded := (types.VotesThresholdNumerator*totalValidators)/types.VotesThresholdDenominator + 1

	k.Logger().Debug("voting on inbound ballot",
		"ballot_key", ballotKey,
		"validator", universalValidator.String(),
		"total_validators", totalValidators,
		"votes_needed", votesNeeded,
	)

	// Convert []sdk.ValAddress → []string
	universalValidatorSetStrs := make([]string, len(universalValidatorSet))
	for i, v := range universalValidatorSet {
		universalValidatorSetStrs[i] = v.IdentifyInfo.CoreValidatorAddress
	}

	// Step 2: Call VoteOnBallot for this inbound synthetic
	_, isFinalized, isNew, err = k.uvalidatorKeeper.VoteOnBallot(
		ctx,
		ballotKey,
		uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
		universalValidator.String(),
		uvalidatortypes.VoteResult_VOTE_RESULT_SUCCESS,
		universalValidatorSetStrs,
		int64(votesNeeded),
		int64(types.DefaultExpiryAfterBlocks),
	)

func TestRevertStuckInbound_HappyPath_ExpiredBallot_CreatesRevertOutbound(t *testing.T) {

	seedBallot(t, chainApp, ctx, inbound, uvalidatortypes.BallotStatus_BALLOT_STATUS_EXPIRED)

	resp, err := ms.RevertStuckInbound(sdk.WrapSDKContext(ctx), &uexecutortypes.MsgRevertStuckInbound{
		Signer:  admin,
		Inbound: inbound,
	})
	require.NoError(t, err)
	require.NotEmpty(t, resp.UtxId)
	require.NotEmpty(t, resp.OutboundId)

	// --- UTX assertions ---
	utx, _, err := chainApp.UexecutorKeeper.GetUniversalTx(ctx, resp.UtxId)
	require.NoError(t, err)
	require.Equal(t, resp.UtxId, utx.Id, "UTX id should match response")
	require.Equal(t, uexecutortypes.GetInboundUniversalTxKey(*inbound), utx.Id,

	require.Equal(t, "FAILED", utx.PcTx[0].Status, "PCTx must indicate the original execution failed")
