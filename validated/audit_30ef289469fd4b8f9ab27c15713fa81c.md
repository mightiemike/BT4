### Title
Missing declared-class validation in Starknet OS `replace_class` syscall causes state divergence between sequencer execution and OS re-execution - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `ReplaceClass` syscall lets a deployed contract change its own class hash at any time. In the blockifier's native/Rust syscall handler, this is guarded by a check that the target class is actually declared before the class hash is swapped. The Cairo implementation of the same syscall inside the Starknet OS (SNOS) re-execution/proving path does not perform this check — it is explicitly marked with a `TODO` acknowledging the missing validation.

### Finding Description
The blockifier's deprecated syscall handler enforces declared-class validation before performing a class replacement: [1](#0-0) 

The current (non-deprecated) native syscall handler forwards to `self.base.replace_class`, which is expected to perform the same underlying state-layer validation. [2](#0-1) 

However, the Starknet OS Cairo implementation used for re-execution/proving (`execute_replace_class` in `syscall_impls.cairo`) directly updates `contract_state_changes` with the requested `class_hash` without first checking that the class was declared. The code contains an explicit acknowledgment of this gap: [3](#0-2) 

The equivalent deprecated-syscalls Cairo path (`deprecated_execute_syscalls.cairo`) has the same unguarded behavior: [4](#0-3) 

Meanwhile, the SNOS Rust-side syscall executor for `replace_class` is a no-op passthrough that defers entirely to the Cairo hint logic above, so no Rust-level check exists to compensate: [5](#0-4) 

By contrast, the blockifier explicitly tests and enforces that replacing with an undeclared class hash fails during normal (sequencer) execution: [6](#0-5) 

### Impact Explanation
This creates a divergence between the two paths that must agree on state transitions in a Starknet-based sequencer: the blockifier (used during block building/execution) rejects a `replace_class` call targeting an undeclared class hash, while the OS (used for re-execution/proof generation of the same block) accepts it and commits the state change into `contract_state_changes` unconditionally. Any transaction sender can trigger this divergence via a plain `replace_class` syscall call from any deployed contract, without special privileges — analogous to the ceph CVE where an unprivileged caller could perform state-mutating operations that should have required stronger validation. If the sequencer accepts a transaction, the resulting state commitment (Patricia root / block hash from the OS side) can differ from what the blockifier computed, or a maliciously/accidentally reachable code path that panics differently between the two executions could halt proof generation or produce a wrong committed root, undermining the chain's ability to confirm the block. This matches the "wrong committed root" / "honest-node divergence" impact class explicitly permitted by the validation rules.

### Likelihood Explanation
Likelihood is high in terms of reachability: any account/contract deployer can trigger the `replace_class` syscall from a contract they control with an arbitrary (potentially undeclared) `class_hash` argument, since the syscall does not restrict the caller or require prior authorization beyond gas payment. The gap is explicitly flagged as a known TODO in the code, indicating it is a currently-unaddressed and reachable code path rather than a purely theoretical one.

### Recommendation
Add the same declared-class validation to the Cairo `execute_replace_class` implementations in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` that the blockifier already performs (i.e., verify a compiled/declared class exists for `class_hash` before writing the new `StateEntry`), ensuring OS re-execution rejects the same inputs that the sequencer's blockifier rejects.

### Proof of Concept
1. Deploy any contract exposing a `replace_class` syscall call (e.g. the `TestContract` used in `deprecated_syscalls_test.rs`).
2. Submit an invoke transaction that triggers `replace_class` with an arbitrary, undeclared `class_hash`.
3. Blockifier execution (sequencer) rejects the transaction with `UndeclaredClassHash`/"is not declared", as shown in `deprecated_syscalls_test.rs` lines 383–391.
4. If any code path allows this same transaction/state diff to reach OS re-execution (e.g., via a future or misconfigured skip of the same guard, or via testing/validation tooling that directly drives OS execution against a claimed state diff), the OS's `execute_replace_class` in `syscall_impls.cairo` (lines 881–920) performs the class-hash swap unconditionally, since it lacks the corresponding check — confirmed by the `TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment at line 902.

Note: I was not able to fully trace whether the blockifier-side rejection at transaction-execution time is the *only* barrier preventing an undeclared-class `replace_class` state diff from ever reaching the OS re-execution stage (e.g., whether the OS strictly re-derives calls from the same execution rather than trusting a submitted state diff). This should be verified against `crates/starknet_os` execution-context wiring to determine if the blockifier-level check is a hard prerequisite gating all OS re-executions, which would affect the actual exploitability of this divergence in production.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
