### Title
Missing declared-class check in the Starknet OS `execute_replace_class` syscall implementation causes OS/blockifier execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall does not verify that the target `class_hash` corresponds to a declared class before overwriting the contract's `StateEntry.class_hash`. The Rust blockifier — the code path actually used by the sequencer to execute transactions, build blocks, and commit the resulting state — enforces this check and fails the syscall with an `"is not declared"` error. This asymmetry is directly analogous to the RDMA `rereg_mr` bug: one code path (mlx4/most drivers) validates a state-mutating operation, while another path (the missing `ib_umem_check_rereg`) skips it, producing an unsafe/incompatible re-registration. Here, blockifier validates `replace_class`, but the Starknet OS re-execution path does not.

### Finding Description
The Cairo implementation of the syscall explicitly documents the gap: [1](#0-0) 

Note the `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment immediately followed by an unconditional `dict_update` that writes the attacker-supplied `class_hash` into `contract_state_changes` with no existence check. The same omission exists in the deprecated (Cairo 0) syscall path: [2](#0-1) 

In contrast, the blockifier's Rust `replace_class` handler — used for actual sequencer execution/block-building — explicitly reads the compiled class to force a declared-class existence check before mutating state: [3](#0-2) 

This behavior is confirmed by dedicated tests asserting an `"is not declared"` error for undeclared class hashes on both the Cairo0 legacy path and the modern (VM/Native) syscall path: [4](#0-3) [5](#0-4) 

So blockifier will fail/revert an `__execute__` (or other entry point) that calls `replace_class_syscall` with an undeclared class hash, whereas the Starknet OS's Cairo re-implementation of the same syscall will unconditionally succeed and commit the bogus `class_hash` into the contract's state entry.

### Impact Explanation
The Starknet OS is the program whose execution is proven and whose output (state diff / state root / block hash) is meant to match what the sequencer actually committed. The reexecution/verification tooling in this repo explicitly compares state diffs and block hashes computed from execution against the expected on-chain values: [6](#0-5) [7](#0-6) 

Because the OS's `execute_replace_class` omits the declared-class check that blockifier enforces, any transaction whose execution calls `replace_class_syscall` with an undeclared (or otherwise not-yet-declared/garbage) class hash will:
- Fail/revert under blockifier (the sequencer's actual execution engine that builds the block and commits state), producing one state diff / transaction outcome, versus
- Succeed under the Starknet OS re-execution, producing a different state diff, different transaction success/failure outcome, and consequently a different computed state root / block hash.

This is a wrong-committed-root / honest-node-divergence class issue: the proof-generation (OS) side and the execution (blockifier) side disagree on the correctness of a state-mutating operation reachable by any contract deployer/invoker via a single transaction that calls `replace_class_syscall`.

### Likelihood Explanation
Trivially reachable: any account or contract can call `replace_class_syscall(class_hash)` with an arbitrary, undeclared `class_hash` from within its own execution (e.g., `__execute__`). No special privileges are required — this is a standard Cairo syscall available to any Starknet contract, as demonstrated in test/fuzz contracts already present in the repo: [8](#0-7) 

### Recommendation
Add the equivalent declared-class existence check (and Cairo0/Cairo1 version compatibility check, mirroring blockifier's checks) inside `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` in the Starknet OS Cairo program, so that the OS rejects (or panics/reverts consistently with blockifier) any `replace_class` call targeting an undeclared class hash — resolving the TODO comment already present in the code.

### Proof of Concept
1. Deploy a contract (e.g., based on `fuzz_revert.cairo`'s `Scenario::ReplaceClass` handler) whose `__execute__` calls `replace_class_syscall(class_hash)` with a `class_hash` that has never been declared on-chain.
2. Submit an invoke transaction targeting this entry point.
3. Under blockifier (the sequencer's real execution/block-building path), the syscall handler's `get_compiled_class(request.class_hash)` call fails with `"is not declared"`, causing the entry point / transaction to fail or revert (see `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:15-29` and `crates/blockifier/src/execution/deprecated_syscalls/deprecated_syscalls_test.rs:375-391`).
4. When the Starknet OS re-executes the same block/transaction for proof generation (`syscall_impls.cairo:881-920` / `deprecated_execute_syscalls.cairo:307-329`), no such check exists — the syscall succeeds unconditionally, writing the undeclared `class_hash` into `contract_state_changes`.
5. This produces divergent transaction outcomes and state diffs between blockifier and the OS, which the repo's own reexecution-comparison tooling (`compare_state_diffs`/`compare_block_hash` in `crates/blockifier_reexecution/src/utils.rs:179-255`) is designed to catch as a mismatch, confirming the state root / block hash computed by re-execution would not match the one actually committed by the sequencer.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}

/// Compares two state diffs, Returns `true` if they match.
/// On mismatch, logs a detailed diff.
pub fn compare_state_diffs(
    expected_state_diff: CommitmentStateDiff,
    actual_state_diff: CommitmentStateDiff,
    block_number: BlockNumber,
) -> bool {
    let expected = ComparableStateDiff::from(expected_state_diff);
    let actual = ComparableStateDiff::from(actual_state_diff);
    let is_match = expected == actual;
    if !is_match {
        let expected_str = format!("{expected:#?}");
        let actual_str = format!("{actual:#?}");
        let diff = pretty_assertions::StrComparison::new(&expected_str, &actual_str);
        tracing::warn!("State diff mismatch for block {block_number}.\n{diff}");
    }
    is_match
}

    /// Reexecutes a block and verifies both the state diff and block hash.
    /// Returns `true` if all checks passed, `false` if any mismatch was detected.
    /// Panics on execution errors.
    ///
    /// Must be called from a blocking context (e.g. `spawn_blocking`), since block hash
    /// computation spawns async tasks internally.
    fn reexecute_and_verify_correctness(self, block_number: BlockNumber) -> bool {
        let block_header = self.get_block_header().expect("Failed to get block header");
        let ReexecuteBlockOutcome {
            expected_state_diff, actual_state_diff, txs_hashing_data, ..
        } = self.reexecute_block().expect("Block reexecution failed");
        let state_diff_matched =
            compare_state_diffs(expected_state_diff, actual_state_diff.clone(), block_number);
        if !state_diff_matched {
            return false;
        }
        Handle::current()
            .block_on(compare_block_hash(
                txs_hashing_data,
                actual_state_diff,
                &block_header,
                block_number,
            ))
            .expect("Block hash comparison failed")
    }
