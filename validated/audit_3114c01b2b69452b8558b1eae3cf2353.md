### Title
Fixed 5% slippage band computed from a manipulable spot-price quote allows sandwich-style value extraction on inbound gas autoswap and outbound gas refund swaps - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go, x/uexecutor/keeper/evm.go)

### Summary
The external report flags that AMM `addLiquidity`/`removeLiquidity` are unpredictable because they use the live pool price with no caller-specified bound. Push Chain's own module code has the same structural weakness in its internal Uniswap-V3-based autoswap flows: `GetSwapQuote` pulls a single spot-price quote from `QuoterV2.quoteExactInputSingle` and the module immediately derives `minPCOut` as a hardcoded 95% of that quote, then executes the swap against that bound. Because the quote itself (not just the post-quote drift) can be moved by an ordinary user transacting against the same on-chain pool earlier in the block, the "protection" only bounds slippage relative to an already-attacker-controlled reference price.

### Finding Description
`GetSwapQuote` [1](#0-0)  issues a `CallEVM` (non-commit) view call to the on-chain `QuoterV2` at the exact moment the inbound is executed, returning the current spot-derived `amountOut` for the `prc20 → wpc` pair.

Every autoswap call site then computes the minimum acceptable output purely as a fixed percentage of that just-fetched quote:
- `ExecuteInboundGas` (TxType_GAS): `minPCOut := quote * 95 / 100` [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (TxType_GAS_AND_PAYLOAD): identical pattern [3](#0-2) 
- `applyGasRefund` (outbound gas refund swap): identical pattern [4](#0-3) 

The actual swap is then executed on-chain via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, both of which call into `UniversalCore`'s `depositPRC20WithAutoSwap` / `refundUnusedGas` with the `minPCOut` computed above as the sole floor [5](#0-4) .

Because `quote`, `minPCOut`, and the swap execution all reference the pool's *current* state rather than any TWAP or externally supplied caller/user bound, an unprivileged actor can manipulate the underlying `PRC20/WPC` Uniswap V3 pool (a normal contract reachable by any EVM account on Push Chain) with an ordinary transaction placed earlier in the same block than the `MsgVoteInbound` finalizing transaction (the last vote needed for quorum is a public, unauthenticated broadcast visible in mempool ahead of execution). This shifts the spot price before the module ever calls `GetSwapQuote`, so the "5% band" is computed against an already-corrupted reference price rather than the fair market price. The bridging user's PRC20→WPC (or gas-refund) conversion then executes inside that manipulated band, and the attacker reverses the price afterward, capturing the difference as arbitrage profit extracted from the bridging user's principal.

This is the direct on-chain analog of the reported AMM issue: no caller-specified maximum-input / minimum-output guard exists that is resistant to price movement introduced by the same block's transactions; the module-computed bound merely re-derives from the manipulated state.

### Impact Explanation
Any inbound of `TxType_GAS` or `TxType_GAS_AND_PAYLOAD`, and any outbound gas refund with excess (`gasFee > gasFeeUsed`), routes user/protocol funds through this unprotected-reference-price swap. An attacker can systematically extract value from bridging users' gas-token deposits and refunds, causing partial but material and repeatable loss of user-controlled funds routed through the universal execution and gas-refund flows — falling under "stealing ... of user or protocol-controlled funds" in the allowed impact set, reachable purely from ordinary unprivileged EVM transactions against the pool with no validator, relayer, or admin involvement required.

### Likelihood Explanation
The attack requires only: (1) an EOA capable of submitting a normal swap transaction against the PRC20/WPC pool on Push Chain's EVM, and (2) visibility into the mempool for the finalizing `MsgVoteInbound`/`MsgVoteOutbound` transaction (a routine, publicly gossiped, unauthenticated bonded-UV vote). Both conditions are ordinary and require no privileged role, making this readily and repeatably exploitable by any unprivileged actor that monitors the mempool, which is standard practice for MEV/sandwich extraction.

### Recommendation
Do not derive `minPCOut` solely from a quote fetched in the same execution as the swap. Use a manipulation-resistant reference (e.g., a TWAP oracle, or an admin/governance-configured max-slippage-from-registry price with sanity bounds), and/or widen protection by capping the deviation allowed between consecutive blocks' observed pool price and the quote used, rejecting/deferring execution if the spot price has moved abnormally versus a recent moving average. Consider making the quote+swap resistant to same-block manipulation (e.g., only trusting pool state that has existed for N blocks) rather than trusting the instantaneous `quoteExactInputSingle` result computed immediately before the swap.

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` transaction that will finalize an inbound with non-trivial gas amount (`TxType_GAS`/`GAS_AND_PAYLOAD`) or observes a pending `MsgVoteOutbound` that will produce an excess-gas refund.
2. Attacker submits a swap transaction against the PRC20/WPC Uniswap V3 pool with a higher gas price/fee to land earlier in the same block, moving the pool's spot price unfavorably for the upcoming autoswap direction.
3. The finalizing vote transaction executes; `GetSwapQuote` in `x/uexecutor/keeper/evm.go` returns a quote based on the now-manipulated pool state; `minPCOut` is computed as 95% of that already-bad quote.
4. `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes the swap, converting the user's/protocol's gas tokens at the manipulated rate (bounded only by the corrupted 5% band).
5. Attacker submits a reverse swap to restore the pool price and realize arbitrage profit extracted from the difference, at the expense of the bridging user's deposited or refunded value.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```

```go
// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
```
