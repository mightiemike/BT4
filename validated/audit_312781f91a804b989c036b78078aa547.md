### Title
Unprivileged actor can pre-consume a Vault request's replay-guard slot to block the legitimate authorized request (DoS analog of cooldown griefing) - (File: `core/capabilities/vault/request_replay_guard.go`)

### Summary
Vault's `RequestReplayGuard.CheckAndRecord` deduplicates JSON-RPC requests purely by the deterministic `req.Digest()` value (hash of `method` + `params`), independent of who actually submits the HTTP request to the gateway/DON. For requests authorized via `AllowListBasedAuth`, the allowlisting of a digest is public on-chain data, and for several Vault methods the full plaintext request body needed to reproduce that digest is fully public (owner address + fixed namespace, no secret material). Any unprivileged actor can therefore reconstruct byte-for-byte the exact request a legitimate workflow owner intends to submit, race it to the gateway first, and cause the guard to mark that digest as "seen" for the full on-chain `ExpiryTimestamp` window — permanently blocking the legitimate owner's actual request for that period, analogous to the `checkTransaction` cooldown-reset DoS described in the reference report.

### Finding Description
`RequestReplayGuard.CheckAndRecord` is keyed only by `digest` and stores the caller-supplied `expiresAtUnix`; it has no notion of which principal is allowed to record a given digest first: [1](#0-0) 

It is invoked from `authorizer.AuthorizeRequest` immediately after auth succeeds, and any digest collision causes the request to be rejected with `ErrRequestAlreadySeen`: [2](#0-1) 

For the allowlist-based path, authorization succeeds for *anyone* who submits a JSON-RPC request whose digest matches an entry in the on-chain `WorkflowRegistry` allowlist — there is no check that the HTTP caller is the workflow owner or holds any credential tied to that digest: [3](#0-2) 

The allowlist entries (`Owner`, `RequestDigest`, `ExpiryTimestamp`) are read from on-chain/synced state via `GetAllowlistedRequests`, which is public information: [4](#0-3) 

Because the digest is `hash(method, params)` and, for methods such as `vault.secrets.list` / `vault.publicKey.get`, the params contain no secret material — only the owner's public address and a namespace string (as seen in test fixtures constructing `ListSecretIdentifiersRequest{Namespace, Owner}` before submission) — any external observer who knows (or can derive/enumerate) the owner address and namespace can construct the identical request and its digest without needing the owner's private key or JWT: [5](#0-4) 

An attacker who submits this reconstructed request to the vault gateway before the legitimate owner does will pass `AllowListBasedAuth` (since the digest is genuinely allowlisted on-chain for that owner) and cause `CheckAndRecord` to store the digest with the full on-chain `ExpiryTimestamp`. When the legitimate owner subsequently submits their (identical) request, it is rejected with `ErrRequestAlreadySeen`, exactly mirroring the reference bug class: an unprivileged actor front-runs and consumes a stateful guard meant to protect a privileged action, causing the intended actor's transaction to fail. Existing test comments in the system tests explicitly acknowledge this dedup edge case can surface as an operational error path ("request was already authorized previously"), confirming the mechanism's reachability in production flows: [6](#0-5) 

### Impact Explanation
This allows any unauthenticated/unprivileged network actor to deny a specific legitimate Vault operation (e.g., a workflow's secrets listing or public-key retrieval) for the entire duration of the on-chain allowlist window (`ExpiryTimestamp`), since the digest slot in `RequestReplayGuard.seen` is locked until that expiry. This is a denial-of-service against the Vault capability's authorized-request pipeline, blocking legitimate workflow/vault interactions — analogous in class to blocking the BORG SAFE's guarded execution via a public state-mutating function.

### Likelihood Explanation
Exploitability depends on the attacker being able to reconstruct the exact `method`+`params` bytes of the victim's pending request. For secret-bearing methods (e.g., `vault.secrets.create`) this is hard since the params include encrypted payloads not otherwise public before submission. However, for read/list-style methods whose params consist only of public identifiers (owner address, fixed namespace strings), reconstruction is straightforward, making the race practical for those methods. The attacker also needs to win a network race to submit before the legitimate owner, which is generally feasible for an active network participant monitoring on-chain allowlist events for a target owner.

### Recommendation
Bind replay-guard entries (and/or the `CheckAndRecord` call) to the authorized principal, not just the raw request digest — e.g., incorporate the resolved `AuthorizedOwner`/`workflowOwner` into the dedup key, or require that the first successful record of a digest also cryptographically prove possession of the owner's credential (JWT/allowlist-bound sender) rather than any caller who can reproduce public params. Alternatively, only allow the party that performed the on-chain `AllowlistRequest` (or a signature tied to that owner) to consume the guard slot for that digest.

### Proof of Concept
1. Workflow owner `O` calls `WorkflowRegistry.AllowlistRequest(digest, expiry)` on-chain for a `vault.secrets.list` request with `Namespace: "main", Owner: O`. This is public on-chain state, readable via `GetAllowlistedRequests` [7](#0-6) .
2. Attacker `A` (no credentials, no relationship to `O`) constructs the identical JSON-RPC request `{method: "vault.secrets.list", params: {namespace: "main", owner: O}}`, computes the same digest, and submits it to the vault gateway before `O` does.
3. `allowListBasedAuth.AuthorizeRequest` succeeds for `A`'s copy because it only checks digest membership in the on-chain allowlist, not the HTTP submitter's identity [8](#0-7) .
4. `authorizer.AuthorizeRequest` calls `replayGuard.CheckAndRecord(digest, expiresAt)`, which succeeds and stores the digest until `expiresAt` [9](#0-8) , [1](#0-0) .
5. `O` then submits their genuine request with the same digest; `CheckAndRecord` returns `ErrRequestAlreadySeen`, and `O`'s legitimate request is rejected until the on-chain expiry passes.

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func (r *allowListBasedAuth) AuthorizeRequest(ctx context.Context, req jsonrpc.Request[json.RawMessage]) (*AuthResult, error) {
	r.lggr.Debugw("AllowListBasedAuth authorizing request", "method", req.Method, "requestID", req.ID)
	requestDigest, err := req.Digest()
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to create digest", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, err
	}
	requestDigestBytes, err := hex.DecodeString(requestDigest)
	if err != nil {
		r.lggr.Debugw("AllowListBasedAuth failed to decode digest", "method", req.Method, "requestID", req.ID, "requestDigest", requestDigest, "error", err)
		return nil, err
	}
	requestDigestBytes32 := [32]byte(requestDigestBytes)
	if r.workflowRegistrySyncer == nil {
		r.lggr.Errorw("AllowListBasedAuth workflowRegistrySyncer is nil", "method", req.Method, "requestID", req.ID)
		return nil, errors.New("internal error: workflowRegistrySyncer is nil")
	}
	allowlistedRequest, allowedRequestsStrs, err := r.findAllowlistedItemWithRetry(ctx, req, requestDigest, requestDigestBytes32)
	if err != nil {
		return nil, err
	}
	if allowlistedRequest == nil {
		r.lggr.Debugw("AllowListBasedAuth request digest not allowlisted",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"allowedRequestsStrs", allowedRequestsStrs)
		return nil, errors.New("request not allowlisted")
	}

	if time.Now().UTC().Unix() > int64(allowlistedRequest.ExpiryTimestamp) {
		authorizedRequestStr := string(allowlistedRequest.RequestDigest[:])
		r.lggr.Debugw("AllowListBasedAuth authorization expired", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", authorizedRequestStr, "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
		return nil, errors.New("request authorization expired")
	}

	digestKey := string(allowlistedRequest.RequestDigest[:])
	r.lggr.Debugw("AllowListBasedAuth authorization succeeded", "method", req.Method, "requestID", req.ID, "authorizedRequestStr", digestKey, "owner", allowlistedRequest.Owner.Hex(), "expiryTimestamp", allowlistedRequest.ExpiryTimestamp)
	return &AuthResult{
		workflowOwner: allowlistedRequest.Owner.Hex(),
		digest:        digestKey,
		expiresAt:     int64(allowlistedRequest.ExpiryTimestamp),
	}, nil
}

func (r *allowListBasedAuth) findAllowlistedItemWithRetry(ctx context.Context, req jsonrpc.Request[json.RawMessage], requestDigest string, requestDigestBytes32 [32]byte) (*workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, []string, error) {
	for attempt := 0; attempt <= r.retryCount; attempt++ {
		allowedRequests := r.workflowRegistrySyncer.GetAllowlistedRequests(ctx)
		allowedRequestsStrs := make([]string, 0, len(allowedRequests))
		for _, rr := range allowedRequests {
			allowedReqStr := fmt.Sprintf("AuthorizedOwner: %s, RequestDigest: %s, ExpiryTimestamp: %d", rr.Owner.Hex(), hex.EncodeToString(rr.RequestDigest[:]), rr.ExpiryTimestamp)
			allowedRequestsStrs = append(allowedRequestsStrs, allowedReqStr)
		}
		r.lggr.Debugw("AllowListBasedAuth loaded allowlisted requests", "method", req.Method, "requestID", req.ID, "attempt", attempt+1, "allowedRequests", allowedRequestsStrs)

		allowlistedRequest := r.fetchAllowlistedItem(allowedRequests, requestDigestBytes32)
		if allowlistedRequest != nil {
			return allowlistedRequest, allowedRequestsStrs, nil
		}
		if attempt == r.retryCount {
			return nil, allowedRequestsStrs, nil
		}

		r.lggr.Debugw("AllowListBasedAuth request digest not yet allowlisted, retrying",
			"method", req.Method,
			"requestID", req.ID,
			"digestHexStr", requestDigest,
			"attempt", attempt+1,
			"maxAttempts", r.retryCount+1,
			"retryInterval", r.retryInterval)
		if err := sleepWithContext(ctx, r.retryInterval); err != nil {
			r.lggr.Debugw("AllowListBasedAuth retry canceled", "method", req.Method, "requestID", req.ID, "error", err)
			return nil, nil, err
		}
	}

	return nil, nil, nil // unreachable: loop always returns
}

func (r *allowListBasedAuth) fetchAllowlistedItem(allowListedRequests []workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest, digest [32]byte) *workflow_registry_wrapper_v2.WorkflowRegistryOwnerAllowlistedRequest {
	for _, item := range allowListedRequests {
		if item.RequestDigest == digest {
			return &item
		}
	}
	return nil
}

// sendConcurrentVaultCreate sends an already-allowlisted create request to the gateway and tolerates
// the replay-guard outcome. Under burst load, the gateway can time out (503 "Request timed out") while
// DON still processes the create; the test's HTTP retry then re-sends the same request digest, which
// vault's replay guard rejects with "request was already authorized previously". That error proves the
// original request was accepted and processed, so we treat it as success — there is no later response
// payload to validate when this path fires.
func sendConcurrentVaultCreate(t *testing.T, gwURL, requestID string, jsonRequest jsonrpc.Request[json.RawMessage], authorizedOwner, expectedResponseOwner string, namespaces []string) {
	t.Helper()

	authToken := jsonRequest.Auth
	stripped := outboundRequestWithoutAuth(jsonRequest)
	requestBody, err := json.Marshal(stripped)
	require.NoError(t, err, "failed to marshal vault request")
	headers := map[string]string{}
	if authToken != "" {
		headers["Authorization"] = "Bearer " + authToken
	}

	statusCode, body := sendVaultRequestToGatewayWithHeaders(t, gwURL, requestBody, headers)

	// Under burst load the gateway can return 503 "Request timed out" when it gives up relaying the
	// response, even though the DON has already processed the request. Tolerate that here — the goal
	// of this subtest is to drive concurrent load for the docker-log batching assertions below, not
	// to verify per-request response payloads.
	if statusCode == http.StatusServiceUnavailable && bytes.Contains(body, []byte("Request timed out")) {
		framework.L.Info().Str("requestID", requestID).Msg("vault create gateway-to-DON timeout; treating as success for batching load test")
		return
	}
	// Replay guard can arrive on a non-200 HTTP status after a retried gateway call; check before StatusOK.
	if bytes.Contains(body, []byte("request was already authorized previously")) {
		framework.L.Info().Str("requestID", requestID).Msg("vault create returned replay-guard error after retry; DON processed the original request — treating as success")
		return
	}
