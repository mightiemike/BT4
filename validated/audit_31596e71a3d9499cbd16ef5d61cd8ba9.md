### Title
Dynamic config parameters (gas price bounds / overrides) can change mid-consensus-round, causing proposer/validator gas-price computation divergence - (File: `crates/apollo_consensus_orchestrator/src/sequencer_consensus_context.rs`)

### Summary
The original report describes an owner who can mutate auction parameters (`timeBuffer`, `minBidIncrement`, `duration`, `reservePrice`) while the auction is in a paused-but-ongoing state, creating an unfair mismatch between the parameters a bidder expected and the parameters actually applied to their bid. The sequencer analog is `ContextDynamicConfig` (min/max L2 gas price, `override_l2_gas_price_fri`, `min_l2_gas_price_per_height`, etc.), which is hot-reloaded into `SequencerConsensusContext` while a height/round's proposal is actively being built and later validated, potentially causing the values used at "fin" time to differ from the values used at "decision" time or by a validating peer.

### Finding Description
`ContextDynamicConfig` is periodically reloaded from disk/CLI and pushed to the running node via the `ConfigManager` component (`crates/apollo_config_manager/src/config_manager_runner.rs:123-156`, `crates/apollo_config_manager/src/config_manager.rs:59-73`), by default every 20 seconds (`config_manager_config.config_update_interval_secs: 20.0`, `crates/apollo_deployments/resources/app_configs/config_manager_config.json:1-4`).

`SequencerConsensusContext` reads `self.config.dynamic_config.*` live (not a config snapshot fixed at round start) at multiple points in the lifecycle of a single height/round:
- when building the proposal args (`override_l2_gas_price_fri`, `min_l2_gas_price_per_height`, `compare_retrospective_block_hash`) at `crates/apollo_consensus_orchestrator/src/sequencer_consensus_context.rs:786-797`;
- when computing `calculate_next_l2_gas_price` for the fin, again reading `self.config.dynamic_config.override_l2_gas_price_fri` / `min_l2_gas_price_per_height` (`crates/apollo_consensus_orchestrator/src/sequencer_consensus_context.rs:437-444`);
- again independently at `update_l2_gas_price` when the block is decided (`crates/apollo_consensus_orchestrator/src/sequencer_consensus_context.rs:500-512`), which is documented in the code/tests as running "once per decided block" for metrics purposes but nonetheless re-reads live config.

Because building a proposal, streaming/validating it, and reaching a decision on it are not atomic with respect to a single config snapshot, a config reload landing inside that window changes the effective `min_gas_price` / cap / override used for the *same* height between the moment the fin was computed and the moment the block is decided, or between the proposer's node and a validator node whose config-manager reload timing differs. `calculate_next_l2_gas_price_for_fin` (`crates/apollo_consensus_orchestrator/src/fee_market/mod.rs:73-109`) and `l2_gas_price_cap`/`get_min_gas_price_for_height` (`crates/apollo_consensus_orchestrator/src/fee_market/mod.rs:41-69`) both branch directly on these dynamic values, so a change to `min_l2_gas_price_per_height` or `override_l2_gas_price_fri` mid-round changes the computed `next_l2_gas_price`, which is embedded in the proposal commitment / fin.

This is structurally the same bug class as the report: a "pause-safe" configuration knob (there, `whenPaused` setters; here, hot-reloadable dynamic config) is mutated concurrently with an in-flight state-changing process (there, bidding; here, building/finalizing a height's proposal), and the code does not pin the parameters used throughout that single logical operation to one consistent snapshot.

### Impact Explanation
If two honest nodes (the proposer and a validator, or the same proposer at fin-time vs. decision-time) observe different values of `min_l2_gas_price_per_height` / `override_l2_gas_price_fri` because a config reload landed between the two reads, they will compute different `next_l2_gas_price` / `NextL2GasPrice.published_price` for the same height. Since this value is embedded in the proposal's committed fin data (used for `ProposalCommitment`), this can manifest as validators rejecting an otherwise-honest proposal (liveness impact) or, in the worst case, as honest-node divergence on the committed gas price for a block, which the rules explicitly list as an acceptable severe outcome. It also unfairly disadvantages transactions relying on a specific gas-price bound in flight during the height, echoing the "unfair advantage" framing of the original report.

### Likelihood Explanation
The dynamic config reload is a normal, built-in operational feature (`enable_config_updates: true`, 20s interval) rather than a rare admin mistake, so the race window recurs continuously in production. Any transaction/proposal whose build+decide window straddles a config-reload tick is affected; with a 20-second interval and per-height/round proposal cycles that can be sub-20-seconds apart, the window is realistically reachable without any attacker action — it only requires normal transaction submission concurrent with a scheduled dynamic-config refresh (e.g., an operator adjusting `min_l2_gas_price_per_height` for a future height, which is a supported, non-malicious operation per the config format's own height-keyed design).

### Recommendation
Snapshot `ContextDynamicConfig` (or at least the gas-price-relevant fields: `override_l2_gas_price_fri`, `min_l2_gas_price_per_height`) once at the start of a height/round's proposal-build lifecycle, and reuse that same snapshot for every downstream computation of `next_l2_gas_price` for that height, including at fin time and at decision time (`update_l2_gas_price`). Do not re-read the live `self.config.dynamic_config` mid-round.

### Proof of Concept
Not independently reproduced with a live cluster; based on static-code tracing this write-up identifies:
1. `crates/apollo_consensus_orchestrator/src/sequencer_consensus_context.rs:437-444` (`calculate_next_l2_gas_price`, called when building the fin) and `crates/apollo_consensus_orchestrator/src/sequencer_consensus_context.rs:500-512` (`update_l2_gas_price`, called at decision time) both independently read `self.config.dynamic_config.override_l2_gas_price_fri` / `min_l2_gas_price_per_height` for the *same* height.
2. `crates/apollo_config_manager/src/config_manager_runner.rs:123-154` shows the config is reloaded and pushed on a periodic timer independent of consensus height/round boundaries.
3. If `min_l2_gas_price_per_height` or `override_l2_gas_price_fri` changes between step 1's two reads (or between the proposer and a validator due to independent reload timing), the computed `NextL2GasPrice` differs for the same height, per the branching logic in `crates/apollo_consensus_orchestrator/src/fee_market/mod.rs:73-109`.

I was not able to fully trace whether `apollo_consensus_orchestrator` enforces a per-height config lock/snapshot elsewhere in the codebase (e.g., an intermediate config-copy step not surfaced by my searches); confirming the exact absence of such a snapshot and constructing a concrete two-node divergence test would require running the actual consensus/config-manager integration tests, which is beyond what static search could verify here. /// Get the minimum gas price for a given block height from the min_l2_gas_price_per_height
/// configuration. If not exist for the given height, use versioned constants min_gas_price as
/// fallback.
///
/// # Parameters
/// - `height`: The block height to look up.
/// - `min_l2_gas_price_per_height`: List of height-price pairs from configuration, assumed to be
///   sorted by height in ascending order.
pub fn get_min_gas_price_for_height(
    height: BlockNumber,
    min_l2_gas_price_per_height: &[PricePerHeight],
) -> GasPrice {
    let fallback_min_gas_price = VersionedConstants::latest_constants().min_gas_price;
    min_l2_gas_price_per_height
        .iter()
        .rev()
        .find(|e| e.height <= height.0)
        .map(|e| GasPrice(e.price))
        .unwrap_or(fallback_min_gas_price)
}

/// The ceiling on the L2 gas price: `MAX_GAS_PRICE_MULTIPLIER` times `min_gas_price`. Applies to
/// every block regardless of its `starknet_version`. Proposer and validator reach the ceiling
/// through this function, so they cannot disagree on it.
// [Temporary comment] Single caller on this lineage. The fee-proposal band clamp, which is its
// second caller, is deferred to `main`.
pub fn l2_gas_price_cap(min_gas_price: GasPrice) -> GasPrice {
    GasPrice(min_gas_price.0.saturating_mul(MAX_GAS_PRICE_MULTIPLIER))
}

/// Compute the next L2 gas price (for the fin or for updating state). Respects override when set.
/// Reporting the bounds is the caller's job, through `NextL2GasPrice::record_clamping`.
pub fn calculate_next_l2_gas_price_for_fin(
    current_l2_gas_price: GasPrice,
    height: BlockNumber,
    l2_gas_used: GasAmount,
    override_l2_gas_price_fri: Option<u128>,
    min_l2_gas_price_per_height: &[PricePerHeight],
    fee_actual: Option<GasPrice>,
) -> NextL2GasPrice {
    if let Some(override_value) = override_l2_gas_price_fri {
        // Operator pin: escapes both bounds by design; each side substitutes its own override.
        info!(
            "L2 gas price ({}) is not updated, remains on override value of {override_value} fri",
            current_l2_gas_price.0
        );
        return NextL2GasPrice { published_price: GasPrice(override_value), bounds: None };
    }
    let gas_target = VersionedConstants::latest_constants().gas_target;
    let config_min = get_min_gas_price_for_height(height, min_l2_gas_price_per_height);
    let cap = l2_gas_price_cap(config_min);

    let snip35_min = fee_actual.map_or(config_min, |fee_actual| max(config_min, fee_actual));
    let effective_min = min(snip35_min, cap);

    let raw_price =
        calculate_next_base_gas_price(current_l2_gas_price, l2_gas_used, gas_target, effective_min);

    NextL2GasPrice {
        published_price: min(raw_price, cap),
        bounds: Some(L2GasPriceBounds {
            current_price: current_l2_gas_price,
            raw_price,
            snip35_min,
            effective_min,
            cap,
        }),
    }
}

    pub(crate) async fn set_node_dynamic_config(
        &self,
        node_dynamic_config: NodeDynamicConfig,
    ) -> ConfigManagerResult<()> {
        info!("ConfigManager: updating node dynamic config");
        if let Err(errors) = node_dynamic_config.validate() {
            error!(
                "ConfigManager: dynamic config update rejected: {errors}. Keeping previous config."
            );
            return Err(ConfigManagerError::InvalidConfig(errors.to_string()));
        }
        let mut config = self.latest_node_dynamic_config.write().await;
        *config = node_dynamic_config;
        Ok(())
    }

/// Dynamic configuration for the Context struct.
#[derive(Debug, Deserialize, Serialize, Clone, PartialEq, Validate)]
#[validate(schema(function = "validate_dynamic_config"))]
pub struct ContextDynamicConfig {
    /// Safety margin in milliseconds to make sure that the batcher completes building the proposal
    /// with enough time for the Fin to be checked by validators.
    #[serde(
        deserialize_with = "deserialize_milliseconds_to_duration",
        serialize_with = "serialize_duration_as_milliseconds"
    )]
    pub build_proposal_margin_millis: Duration,
    /// The minimum L1 gas price in wei.
    pub min_l1_gas_price_wei: u128,
    /// The maximum L1 gas price in wei.
    pub max_l1_gas_price_wei: u128,
    /// The minimum L1 data gas price in wei.
    pub min_l1_data_gas_price_wei: u128,
    /// The maximum L1 data gas price in wei.
    pub max_l1_data_gas_price_wei: u128,
    /// Part per thousand of multiplicative factor to apply to the data gas price, to enable
    /// fine-tuning of the price charged to end users. Commonly used to apply a discount due to
    /// the blob's data being compressed. Can be used to raise the prices in case of blob
    /// under-utilization.
    pub l1_data_gas_price_multiplier_ppt: u128,
    /// This additional gas is added to the L1 gas price.
    pub l1_gas_tip_wei: u128,
    /// SNIP-35 target USD cost per L2 gas unit, in atto-USD ($0.88 per 1e9 L2 gas = 880_000_000
    /// atto-USD).
    pub snip35_target_atto_usd_per_l2_gas: u128,
    /// If given, will override the L2 gas price.
    pub override_l2_gas_price_fri: Option<u128>,
    /// If given, will override the L1 gas price in FRI.
    pub override_l1_gas_price_fri: Option<u128>,
    /// If given, will override the L1 data gas price in FRI.

        serialize_with = "serialize_price_per_height_as_string"
    )]
    pub min_l2_gas_price_per_height: Vec<PricePerHeight>,
    pub compare_retrospective_block_hash: bool,
}
