### Title
Exchange transaction fee is deducted from user balance but never burned or transferred to the blackhole/fee pool - (File: `actuator/src/main/java/org/tron/core/actuator/ExchangeTransactionActuator.java`)

### Summary
`ExchangeTransactionActuator.execute()` computes a fee via `calcFee()` and subtracts it from the trader's TRX balance, but — unlike every sibling exchange actuator in the same package — it never routes that deducted amount to the black-hole address, the transaction fee pool, or a `burnTrx()` call. The fee simply vanishes from the deducted account's balance with no corresponding sink, which breaks TRX supply accounting on every `ExchangeTransactionContract` that carries a non-zero fee.

### Finding Description
In `ExchangeTransactionActuator.execute()`: [1](#0-0) [2](#0-1) 

The fee is subtracted from `accountCapsule`'s balance at line 77 (`newBalance = subtractExact(accountCapsule.getBalance(), calcFee())`) and the modified account is persisted at line 93, but nowhere in the method is the fee amount added to the blackhole account, added to `dynamicStore.addTransactionFeePool(fee)`, or burned via `dynamicStore.burnTrx(fee)`.

This is inconsistent with every other actuator in the same `AbstractExchangeActuator` family and with the broader fee-handling convention used throughout the actuator package, all of which explicitly settle the fee:
- `ExchangeCreateActuator` explicitly burns/transfers the fee after execution: [3](#0-2) 
- The generic resource-fee helpers (`consumeFeeForBandwidth`, `consumeFeeForNewAccount`) in `ResourceProcessor` also always route the fee to the fee pool/blackhole/burn: [4](#0-3) 
- `TransferAssetActuator` follows the same pattern for its fee: [5](#0-4) 

`ExchangeTransactionActuator` is the outlier: it computes and deducts `fee` from the caller's account but performs no equivalent burn/transfer step for that value anywhere in `execute()`. [6](#0-5) 

This is directly analogous to the reported `ClaggBaseAdapter._handleFee()` bug: a fee is subtracted from the user's asset/balance calculation, but the actual funds movement/accounting logic that should settle where the fee goes was never implemented.

### Impact Explanation
Every successful `ExchangeTransactionContract` (a normal, unprivileged, anonymous-broadcastable transaction that any account can submit against an existing bancor-style exchange pair) that has a non-zero `calcFee()` value causes TRX to be removed from the sender's balance without being credited to the blackhole, the transaction fee pool, or burned via `dynamicPropertiesStore`. This breaks the network's TRX supply invariant that "total burned + total blackhole + total account balances == total issued supply," since consensus/accounting code elsewhere (e.g., `supportBlackHoleOptimization`/`burnTrx` accounting, node total-supply verification, and downstream tooling relying on burn totals) will not see this fee reflected anywhere. Effectively, TRX is destroyed from the sender without any traceable ledger effect, corrupting on-chain economic accounting and diverging from the accounting semantics guaranteed by every other fee path in the codebase.

### Likelihood Explanation
High reachability: `ExchangeTransactionContract` is a standard user-facing contract type processed by `ExchangeTransactionActuator`, reachable from any anonymous broadcast transaction as long as an exchange pair exists (a normal, unprivileged operation available to any account). The bug fires deterministically whenever `calcFee()` (the network's configured exchange-transaction fee, via `DynamicPropertiesStore`) is non-zero — this depends on chain configuration but requires no special privileges or attacker preconditions beyond initiating a normal exchange trade.

### Recommendation
In `ExchangeTransactionActuator.execute()`, after deducting `fee` from the account balance, add the same settlement logic used in `ExchangeCreateActuator`/`ExchangeInjectActuator`/`ExchangeWithdrawActuator`:
```java
if (dynamicStore.supportBlackHoleOptimization()) {
  dynamicStore.burnTrx(fee);
} else {
  adjustBalance(accountStore, accountStore.getBlackhole(), fee);
}
```
(or route through `dynamicStore.addTransactionFeePool(fee)` if `supportTransactionFeePool()` is enabled, consistent with `ResourceProcessor`). This ensures the fee is properly accounted for rather than silently disappearing from total supply.

### Proof of Concept
1. Configure/observe a network where the exchange transaction fee (`calcFee()` in `ExchangeTransactionActuator`, backed by the relevant `DynamicPropertiesStore` getter) is non-zero.
2. Create an exchange pair via `ExchangeCreateContract`.
3. Broadcast an `ExchangeTransactionContract` from any account with sufficient balance.
4. Observe: the trader's account balance decreases by `fee` (per line 77 of `ExchangeTransactionActuator.java`), but neither the blackhole account balance, `burnTrx` total, nor the transaction fee pool increases by that amount — unlike the equivalent flow for `ExchangeCreateContract`, `ExchangeInjectContract`, or `ExchangeWithdrawContract`, where the corresponding sink update is visible.
5. Summing all account balances + blackhole balance + burn totals before and after the transaction shows a discrepancy equal to `fee`, demonstrating the TRX supply accounting break.

  @Override
  public boolean execute(Object object) throws ContractExeException {
    TransactionResultCapsule ret = (TransactionResultCapsule) object;
    if (Objects.isNull(ret)) {
      throw new RuntimeException(ActuatorConstant.TX_RESULT_NULL);
    }

    long fee = calcFee();
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    ExchangeStore exchangeStore = chainBaseManager.getExchangeStore();
    ExchangeV2Store exchangeV2Store = chainBaseManager.getExchangeV2Store();
    AssetIssueStore assetIssueStore = chainBaseManager.getAssetIssueStore();
    try {
      final ExchangeTransactionContract exchangeTransactionContract = this.any
          .unpack(ExchangeTransactionContract.class);
      AccountCapsule accountCapsule = accountStore
          .get(exchangeTransactionContract.getOwnerAddress().toByteArray());

      ExchangeCapsule exchangeCapsule = Commons
          .getExchangeStoreFinal(dynamicStore, exchangeStore, exchangeV2Store)
          .get(ByteArray.fromLong(exchangeTransactionContract.getExchangeId()));

      byte[] firstTokenID = exchangeCapsule.getFirstTokenId();
      byte[] secondTokenID = exchangeCapsule.getSecondTokenId();

      byte[] tokenID = exchangeTransactionContract.getTokenId().toByteArray();
      long tokenQuant = exchangeTransactionContract.getQuant();

      byte[] anotherTokenID;
      long anotherTokenQuant = exchangeCapsule.transaction(tokenID, tokenQuant,
          dynamicStore.allowStrictMath(), allowHarden());

      if (Arrays.equals(tokenID, firstTokenID)) {
        anotherTokenID = secondTokenID;
      } else {
        anotherTokenID = firstTokenID;
      }

      long newBalance = subtractExact(accountCapsule.getBalance(), calcFee());
      accountCapsule.setBalance(newBalance);

      if (Arrays.equals(tokenID, TRX_SYMBOL_BYTES)) {
        accountCapsule.setBalance(subtractExact(newBalance, tokenQuant));
      } else {
        accountCapsule.reduceAssetAmountV2(tokenID, tokenQuant, dynamicStore, assetIssueStore);
      }

      if (Arrays.equals(anotherTokenID, TRX_SYMBOL_BYTES)) {
        accountCapsule.setBalance(addExact(newBalance, anotherTokenQuant));
      } else {
        accountCapsule
            .addAssetAmountV2(anotherTokenID, anotherTokenQuant, dynamicStore, assetIssueStore);
      }

      accountStore.put(accountCapsule.createDbKey(), accountCapsule);

      Commons.putExchangeCapsule(exchangeCapsule, dynamicStore, exchangeStore, exchangeV2Store,
          assetIssueStore);

      ret.setExchangeReceivedAmount(anotherTokenQuant);
      ret.setStatus(fee, code.SUCESS);
    } catch (ItemNotFoundException | InvalidProtocolBufferException
        | ContractValidateException | ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    }
    return true;
  }

  protected boolean consumeFeeForBandwidth(AccountCapsule accountCapsule, long fee) {
    try {
      long latestOperationTime = dynamicPropertiesStore.getLatestBlockHeaderTimestamp();
      accountCapsule.setLatestOperationTime(latestOperationTime);
      Commons.adjustBalance(accountStore, accountCapsule, -fee,
          this.disableJavaLangMath());
      if (dynamicPropertiesStore.supportTransactionFeePool()) {
        dynamicPropertiesStore.addTransactionFeePool(fee);
      } else if (dynamicPropertiesStore.supportBlackHoleOptimization()) {
        dynamicPropertiesStore.burnTrx(fee);
      } else {
        Commons.adjustBalance(accountStore, accountStore.getBlackhole().createDbKey(), +fee,
            this.disableJavaLangMath());
      }

      return true;
    } catch (BalanceInsufficientException e) {
      return false;
    }
  }
