### Title
Unauthenticated post-genesis abuse of the `BOOTSTRAP` declare fast-path bypasses validation, fees, and nonce enforcement - ([File: crates/blockifier/src/transaction/account_transaction.rs])

### Summary
The blockifier and Starknet OS both implement a special-cased "bootstrap declare" transaction path intended only for chain genesis, gated solely by transaction-supplied fields (`sender_address == bootstrap_address()`, `nonce == 0`, tx version 3, and a derived `charge_fee == false` flag) rather than by any check that the chain is actually uninitialized/at genesis. Any external declare transaction that reproduces these attacker-controlled conditions is routed through this path at any block height, skipping `__validate_declare__`, fee charging, and nonce incrementing.

### Finding Description
The bootstrap fast-path is defined by `DeclareTransaction::is_bootstrap_declare` and consumed in `AccountTransaction::execute_raw`: [1](#0-0) 

The guard checks only `sender_address == bootstrap_address()` (a fixed, publicly known felt encoding of the literal string `'BOOTSTRAP'`), `nonce == 0`, and `!charge_fee`. `charge_fee` itself is derived purely from the transaction's own resource bounds via `enforce_fee`: [2](#0-1) 

and is set in `AccountTransaction::new_for_sequencing`, again purely from transaction-controlled data with no reference to chain height or state: [3](#0-2) 

When these attacker-controlled conditions hold, `execute_raw` skips `perform_pre_validation_stage` (nonce/fee checks), skips `__validate_declare__`, and skips fee handling entirely, directly writing the class declaration to state: [4](#0-3) 

The identical special case is mirrored in the Starknet OS Cairo code, confirming this is not merely a native-execution shortcut but part of the OS-verified state transition: [5](#0-4) 

Crucially, nowhere in this path (Rust or Cairo) is there a check that the chain has zero blocks, that the state is empty, or any other "genesis-only" gate analogous to emlog's missing "already installed" check. The only "state" check is that the *same class hash* cannot be declared twice (`dict_update` with `prev_value=0`), which does not prevent repeated abuse with distinct class hashes. Because this branch returns before `check_and_increment_nonce` runs, the nonce for the `BOOTSTRAP` address is never incremented, so the same zero-nonce condition is satisfiable indefinitely, by design (this is explicitly acknowledged as intentional-but-unintuitive behavior for the mempool): [6](#0-5) 

The `bootstrap_address()` value is a hardcoded, publicly known constant (not a secret), computable by anyone: [7](#0-6) 

This structurally parallels the emlog CVE: a privileged, one-time initialization action (`install.php?action=reinstall` / "bootstrap declare") is reachable outside its intended one-time initialization window because the guard checks only request/transaction-supplied markers instead of verifying actual system state (`already installed` / `chain already has blocks`).

### Impact Explanation
An unprivileged transaction sender can submit an arbitrary number of `Declare` V3 transactions with `sender_address = bootstrap_address()`, `nonce = 0`, and resource bounds crafted so `enforce_fee()` returns false, at any point after genesis (not just at chain bootstrap). Each such transaction:
- Bypasses `__validate_declare__` entirely (no signature or account-contract check, no real "account" needs to exist at that address),
- Bypasses fee charging and resource-bound enforcement entirely,
- Declares an arbitrary class into the committed state for free.

This is an unauthorized-account-action bypass of the fee-and-resource-accounting subsystem: the network is defrauded of the class-declaration fee that every other declarer must pay, and a construct that should only exist transiently at genesis becomes a permanent, unauthenticated free-declaration channel. Because it can be repeated with new class hashes indefinitely, it also creates an unbounded resource-consumption vector for the sequencer (Sierra→CASM compilation/verification, class-hash computation) with zero cost to the attacker, undermining the fee mechanism that is meant to price and rate-limit exactly this kind of state-changing work.

### Likelihood Explanation
The condition is trivial to satisfy: `bootstrap_address()` is a fixed, derivable constant, `nonce = 0` is always valid for that "account" (since it can never be incremented via this path), and `charge_fee = false` only requires crafting resource bounds that the tx's own `enforce_fee()` evaluates as fee-not-enforced. No signature, no account deployment, and no special network position are required — any transaction sender can construct and submit such a transaction through the ordinary gateway/mempool ingestion path.

### Recommendation
Gate the bootstrap declare fast-path on actual system state rather than transaction-supplied fields alone — e.g., require that this branch (in both the blockifier `execute_raw` and the Starknet OS `transaction_impls.cairo`) only executes when the current block number is the genesis block / the chain has not yet produced any block, and reject (or route to the normal validate/fee path) any `BOOTSTRAP`-sender declare transaction observed thereafter. Additionally consider rejecting `sender_address == bootstrap_address()` at gateway/mempool ingestion once the chain is past genesis, so the fast-path can never be reached by post-genesis transactions.

### Proof of Concept
1. After genesis (chain already has ≥1 block), craft an RPC `DeclareTransactionV3` with:
   - `sender_address = DeclareTransaction::bootstrap_address()` (`0x424f4f545354524150`),
   - `nonce = 0`,
   - `resource_bounds` chosen so that `enforce_fee()` (see `crates/blockifier/src/transaction/transactions.rs:379-383`) evaluates to `false` (e.g., the same all-zero/no-fee-enforcement bounds used by `generate_bootstrap_declare` in `crates/mempool_test_utils/src/starknet_api_test_utils.rs:585-595`),
   - `class_hash`/`compiled_class_hash` for any not-yet-declared class, signature empty.
2. Submit via the gateway like any ordinary declare transaction.
3. Observe in `AccountTransaction::execute_raw` (`crates/blockifier/src/transaction/account_transaction.rs:899-911`) that `is_bootstrap_declare` returns `true`, `__validate_declare__` and fee charging are skipped, and the class is declared directly into state at no cost.
4. Repeat with a different `class_hash` (nonce remains 0, since it's never incremented on this path) to declare further classes for free indefinitely.

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }

        // Do not run validate or perform any account-related actions for declare transactions that
        // meet the following conditions.
        // This flow is used for the sequencer to bootstrap a new system.
        // Note: The absence of any account-related action leads to some unintuitive but expected
        // behavior:
        // - After the transaction is executed successfully, the batcher does not notify the mempool
        //   about its inclusion in a block. As a result, the transaction remains in the mempool.
        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.
        // - The transaction will then be marked as rejected, the mempool will be notified, and the
        //   transaction will be removed from the mempool.
        if let Transaction::Declare(tx) = &self.tx {
            if tx.is_bootstrap_declare(self.execution_flags.charge_fee) {
                let mut context = EntryPointExecutionContext::new_invoke(
                    tx_context.clone(),
                    self.execution_flags.charge_fee,
                    SierraGasRevertTracker::new(GasAmount::default()),
                );
                let mut remaining_gas = 0;
                let res = tx.run_execute(state, &mut context, &mut remaining_gas)?;
                assert!(res.is_none(), "Declare execute should not result in a CallInfo.");

                return Ok(TransactionExecutionInfo::default());
            }
        }
