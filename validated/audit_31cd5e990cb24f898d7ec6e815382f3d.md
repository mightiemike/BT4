### Title
Poison-microblock check accepts ECDSA-malleated signature pair, allowing a false "double-sign" report against a miner who signed only one microblock - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`)

### Summary
`check_microblock_header_signer` only checks that two `StacksMicroblockHeader`s recover to the same pubkey hash via `check_recover_pubkey`, and never checks that the headers represent genuinely distinct signed content beyond struct inequality. Because ECDSA (secp256k1) signatures are malleable and recovery is done with `recover_to_pubkey_without_validating_low_s` (no low-S enforcement), an attacker can take a single real signature `(r, s, v)` from one legitimately broadcast microblock and derive a second, byte-different signature `(r, n-s, 1-v)` that recovers to the identical public key for the identical message digest. This produces two structurally distinct headers (`h1 != h2`, `block_hash(h1) != block_hash(h2)`) that both pass `check_microblock_header_signer`, letting an unprivileged attacker fabricate a `PoisonMicroblock` transaction and slash a miner who never double-signed.

### Finding Description
The broken equality is: **"two headers pass `check_microblock_header_signer`" should imply "the miner produced two genuinely distinct signed microblocks at the same position."** This equality is violated.

- `StacksMicroblockHeader::check_recover_pubkey` (`stacks-codec/src/transaction.rs:2598-2616`) computes `digest = Sha512Trunc256Sum(serialize(header_with_signature_zeroed))` and recovers the pubkey via `StacksPublicKey::recover_to_pubkey_without_validating_low_s(digest, self.signature)` [1](#0-0)  — note the digest depends only on `version, sequence, prev_block, tx_merkle_root`, and the recovery explicitly skips low-S validation (`recover_to_pubkey_without_validating_low_s`, `stacks-common/src/util/secp256k1/native.rs:200-205`).
- `check_microblock_header_signer` (`stackslib/src/chainstate/stacks/db/transactions.rs:686-713`) only compares `pkh1 == pkh2`, never comparing `sequence`, `prev_block`, `tx_merkle_root`, or requiring the signatures to actually differ in a way that proves distinct broadcast content.
- ECDSA recoverable signatures are malleable: for any valid `(r, s, v)`, `(r, n-s, 1-v)` recovers to the same public key for the same message. The repo's own test `test_with_negated_s` in `stacks-common/src/util/secp256k1/native.rs:792-837` proves this exact property using `ctx.recover_ecdsa`, and even ships a `MessageSignature::with_negated_s()` helper performing the transform (gated behind `#[cfg(any(test, feature = "testing"))]`, but the transformation itself is a public elliptic-curve operation requiring no private key — any attacker can reimplement it with `secp256k1` library calls).
- `StacksMicroblockHeader::block_hash()` hashes the **full** serialized header including the real signature bytes (`stacks-codec/src/transaction.rs:2631-2636`), so a malleated signature yields a different `block_hash()` and a different struct (`h1 != h2`) even though semantically it is the exact same microblock content signed by the same key.

Exploit flow:
1. Attacker observes one broadcast microblock header `h1 = (version, sequence, prev_block, tx_merkle_root, sig1=(r,s,v))` signed once by the target miner.
2. Attacker computes `sig2 = (r, n-s mod n, 1-v)` — a pure public-key-curve arithmetic operation, no private key needed.
3. Attacker forms `h2 = (version, sequence, prev_block, tx_merkle_root, sig2)`. `h1 != h2` and `block_hash(h1) != block_hash(h2)`.
4. Attacker submits `TransactionPayload::PoisonMicroblock(h1, h2)`.
5. `handle_poison_microblock` calls `check_microblock_header_signer(h1, h2)` (`stackslib/src/chainstate/stacks/db/transactions.rs:751-752`), which recovers `pkh1 == pkh2` (same key, same digest) and succeeds.
6. The poison report is recorded via `insert_microblock_poison` at `mblock_header_1.sequence`, and downstream reward-maturation logic (governed by `MINER_REWARD_MATURITY`, `stackslib/src/chainstate/stacks/db/transactions.rs:768-803`) will use this report to slash/redirect the miner's matured coinbase to the reporter — despite the miner having produced exactly one microblock at that sequence.

Existing guards do not catch this: the codec's `consensus_deserialize` for `StacksMicroblockHeader` (`stacks-codec/src/transaction.rs:2543-2567`) only rejects malformed signature encodings, not malleated-but-valid ones; `validate_parent_microblock_stream`'s equivocation-detection logic (`stackslib/src/chainstate/stacks/db/blocks.rs:2992-3045`) is a separate, honest-node code path used when the node itself observed a real fork — it is not invoked when an attacker fabricates and submits a standalone `PoisonMicroblock` transaction directly.

### Impact Explanation
This results in block-reward theft: an honest miner who produced only one microblock at a given sequence position has their coinbase slashed/redirected to an attacker-controlled reporter, based on a synthetic, non-double-signed pair of headers. This matches the "Critical: block-reward theft/double-payment" and "High: reward mis-payment bounded to fees/commission" categories depending on the exact commission mechanics, since it is a wrongful reward reassignment triggered by a minority/unprivileged attacker with no double-signing having actually occurred.

### Likelihood Explanation
The attacker needs no elevated privileges: only the ability to observe one publicly broadcast, real microblock header+signature (trivially obtainable from the P2P network or any node's `/v2/microblocks` endpoint) and the ability to submit an ordinary Stacks transaction (`PoisonMicroblock`) with a nominal fee. No BTC spend, no majority stake, no signer key, and no compromise of the actual miner's private key are required — only elementary secp256k1 arithmetic (`s' = n - s`, flip recovery id), which is a standard, publicly documented operation. This is repeatable against any miner for whom at least one microblock (with a recoverable signature) is observed, subject only to the existing "hasn't matured / hasn't already been reported at a lower sequence" checks in `handle_poison_microblock`.

### Recommendation
`check_microblock_header_signer` (and/or `check_recover_pubkey`) should reject malleated/non-canonical signatures by enforcing low-S normalization during poison-microblock signature recovery (i.e., use `recover_to_pubkey` instead of `recover_to_pubkey_without_validating_low_s`, or explicitly verify `sig.to_secp256k1_recoverable().to_standard()` is already normalized). Additionally, `check_microblock_header_signer` should require that the two headers actually differ in `prev_block`/`tx_merkle_root` content at the same `sequence` (i.e., mirror the equivocation logic already present in `validate_parent_microblock_stream`), not merely that they recover to the same key — this closes the case where only the signature encoding differs but the signed content is identical.

### Proof of Concept
Rust integration test plan (in `stackslib/src/chainstate/stacks/db/transactions.rs` test module, alongside `process_poison_microblock_invalid_transaction`):

```rust
#[test]
fn poison_microblock_malleated_signature_false_positive() {
    // 1. Generate a real microblock header h1 signed once by `block_privk`.
    let block_privk = StacksPrivateKey::random();
    let block_pubkh = Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_privk));
    let mut h1 = StacksMicroblockHeader::first_unsigned(&BlockHeaderHash([0x11; 32]), &Sha512Trunc256Sum([0x22; 32]));
    h1.sequence = 5;
    h1.sign(&block_privk).unwrap();

    // 2. Derive h2 by malleating ONLY the signature (r, n-s, 1-v); content fields identical.
    let mut h2 = h1.clone();
    h2.signature = h1.signature.with_negated_s(); // public EC operation, no privkey needed

    // 3. Sanity: headers are structurally distinct and hash differently,
    //    yet represent the SAME single broadcast microblock.
    assert_ne!(h1, h2);
    assert_ne!(h1.block_hash(), h2.block_hash());
    assert_eq!(h1.sequence, h2.sequence);
    assert_eq!(h1.prev_block, h2.prev_block);
    assert_eq!(h1.tx_merkle_root, h2.tx_merkle_root);

    // 4. THE BROKEN EQUALITY: check_microblock_header_signer must NOT succeed here,
    //    because there is no genuine double-sign -- only one real signature exists.
    let result = StacksChainState::check_microblock_header_signer(&h1, &h2);

    // Current (vulnerable) behavior: this succeeds and returns block_pubkh.
    // Expected (fixed) behavior: this must return Err(...) because the signature
    // is non-canonical/malleated and/or the content is identical.
    assert!(result.is_err(), "check_microblock_header_signer incorrectly accepted a malleated-signature pair as proof of double-signing");
}
```

    /// Given two microblock headers, were they signed by the same key?
    /// Return the pubkey hash if so; return Err otherwise
    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
