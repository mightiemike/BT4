## Analysis: Price-manipulation analog to the `StakedToken` donation attack

The underlying bug class in the `StakedToken` report is: **a protocol-controlled accounting value (exchange rate) is derived from a spot, attacker-influenceable on-chain quantity (`balanceOf`), and that same manipulated value is then used, within the same transaction window, to price a value transfer to/from another party — with no protection against a single-block distortion.**

The closest reachable analog in Push Chain's scoped code is not `StakedToken` itself (no such share-vault contract exists here), but the **Uniswap V3 spot-quote based auto-swap accounting** in `x/uexecutor`, which reads a manipulable AMM spot price and uses it (with only fixed 5% slippage protection, no TWAP) to price protocol-driven PRC20→PC swaps on behalf of users.

### Root cause path
- `GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` — a spot-price read against the live Uniswap V3 pool reserves. [1](#0-0) 
- `ExecuteInboundGas` (GAS / GAS_AND_PAYLOAD inbound routes) uses that quote to compute `minPCOut = quote * 95 / 100` — a fixed 5% slippage bound derived entirely from the just-read spot price — then immediately executes `CallPRC20DepositAutoSwap` against the same pool. [2](#0-1) 
- The same pattern is repeated for `GAS_AND_PAYLOAD` deposits in `gasAndPayloadDepositAutoSwap`, and for excess-gas refunds in `applyGasRefund`/`getSwapQuoteForRefund`, all of which price a real value transfer using the identical single-block spot quote with a 5% band. [3](#0-2) [4](#0-3) 
- This 5%-slippage design was intentionally introduced to replace a previous 0-slippage call, per the upgrade log, but it does not address price manipulation, only stale-quote reverts. [5](#0-4) 

### Why this is the matching analog
Just as the `StakedToken` attacker donates underlying tokens directly to inflate `balanceOf`-derived `exchangeRate` right before a victim's stake/redeem executes, an unprivileged attacker here can execute an ordinary swap against the same Uniswap V3 pool (front-running or sandwiching the module's inbound-triggered auto-swap or gas-refund call, which is deterministic and publicly observable as it's driven by validator-quorum-finalized inbound votes) to skew `quoteExactInputSingle`'s spot output immediately before the module reads it. Because `minPCOut` is derived from that same distorted read with only a flat 5% band, the attacker can force the protocol's `depositPRC20WithAutoSwap` / `refundUnusedGas` swap to execute at a manipulated price, extracting value from either the user (under-crediting PC on deposit) or the protocol (over-paying on refund) — the same "quantity used to price a transfer is manipulable by an unprivileged party within the transaction window" failure mode as the `StakedToken` donation bug.

This is a **PRC20/native asset accounting corruption** reachable from ordinary user deposit paths (GAS / GAS_AND_PAYLOAD inbounds), triggered purely by an unprivileged actor executing normal swaps against a public AMM pool — no privileged validator, relayer, or governance action required.

### Title

### Summary
`GetSwapQuote` reads a Uniswap V3 QuoterV2 spot price and this value directly drives `minPCOut` (a fixed 5% slippage band) for protocol-executed PRC20→PC swaps on inbound GAS/GAS_AND_PAYLOAD deposits and on excess-gas refunds. An unprivileged attacker can manipulate the pool's spot price with an ordinary swap immediately before the module's derived EVM call executes, forcing the deposit/refund swap to clear at an attacker-favorable price and extracting value from either the depositing user or the protocol's refund pool — the same accounting-manipulation-via-attacker-influenceable-live-value pattern as the `StakedToken` donation exploit.

### Finding Description
`GetSwapQuote` performs a live, spot AMM read via `quoteExactInputSingle` with no TWAP or oracle cross-check. [1](#0-0) 
This quote is used, unmodified aside from a flat ×0.95 multiplier, to bound the acceptable output of a real swap the protocol executes on behalf of the user in `ExecuteInboundGas`: [6](#0-5) 
The identical quote→minPCOut→swap sequence occurs for GAS_AND_PAYLOAD deposits and for excess-gas refunds after a successful outbound: [3](#0-2) [4](#0-3) 
Because the quote and the swap execution happen close together in wall-clock/block terms with no commitment to a pre-attack price, and the pool itself is a permissionless, publicly tradable Uniswap V3 pool, any unprivileged trader can shift the spot price via ordinary swap transactions surrounding the protocol's derived call, causing the protocol-executed swap to settle within the 5% band but at a price far from fair value — mirroring the `StakedToken` bug's core flaw of pricing a value transfer off a live, attacker-touchable on-chain quantity read moments before use.

### Impact Explanation
An attacker can extract value in two directions: (1) on inbound GAS/GAS_AND_PAYLOAD deposits, depressing the quoted PC output so the depositing user's UEA receives materially less PC than fair value, with the difference captured by the attacker's counter-trade in the pool; (2) on gas refunds, inflating the quote so the protocol's `refundUnusedGas` swap pays out more PC than the refund is actually worth, draining protocol-held PRC20/PC reserves. Both are unauthorized value transfers reachable purely through unprivileged AMM trading — matching the in-scope "corruption of PRC20 or native asset accounting" and "stealing/draining ... of user or protocol-controlled funds" impacts.

### Likelihood Explanation
Medium-to-High. The trigger requires no validator collusion, no privileged access, and no cryptographic bypass — only ordinary swap transactions against a Uniswap V3 pool that is otherwise a normal, permissionless AMM. The protocol's auto-swap/refund calls are deterministically triggered by validator-quorum-finalized inbound/outbound events that are publicly observable in advance (mempool/pending ballots), giving an attacker a predictable window to position trades. The fixed 5% band is wide enough on lower-liquidity PRC20 pools to make manipulation profitable.

### Recommendation
Replace or supplement the spot `quoteExactInputSingle` read with a manipulation-resistant reference (e.g., TWAP over multiple blocks, or cross-check against `x/uexecutor`'s own `ChainMeta`/gas-price oracle where applicable) before computing `minPCOut`. Consider tightening slippage bounds dynamically based on pool liquidity/observed volatility rather than a flat 5%, and/or requiring the swap to execute atomically with the quote read (already true) plus a maximum staleness/deviation check against a longer-window average price.

### Proof of Concept
1. Attacker monitors pending `MsgVoteInbound` transactions for a GAS/GAS_AND_PAYLOAD inbound that will trigger `ExecuteInboundGas`.
2. Immediately before the finalizing vote lands (or in the same block if same-block execution is possible), attacker swaps a large amount into/out of the relevant PRC20/WPC Uniswap V3 pool to skew the spot price reported by `quoteExactInputSingle`.
3. The module reads the skewed quote via `GetSwapQuote`, computes `minPCOut = quote * 95 / 100`, and calls `CallPRC20DepositAutoSwap`, executing the deposit swap at the manipulated price. [2](#0-1) 
4. Attacker reverses their positioning trade after the module's swap executes, capturing the price difference at the expense of the depositing user (or the protocol's refund reserve, using the equivalent path in `applyGasRefund`). [4](#0-3)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
