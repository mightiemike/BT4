### Title
Same-transaction quote-and-swap in inbound gas autoswap and outbound gas-refund autoswap provides no real slippage protection against pool-price manipulation (sandwich attack) - ([File: x/uexecutor/keeper/execute_inbound_gas.go], [File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go], [File: x/uexecutor/keeper/outbound.go])

### Summary
`x/uexecutor`'s `GAS`/`GAS_AND_PAYLOAD` inbound autoswap path and the outbound excess-gas-refund autoswap path both compute a Uniswap V3 quote and immediately use that same quote (minus a hardcoded 5%) as the `minPCOut` slippage floor for the actual swap, in the same keeper call, against the same pool state. Because the "protection" value is derived from the exact price the swap will execute at, it does not protect against pool price manipulation — an unprivileged attacker who trades against the public WPC/PRC20 pool immediately before the validator-submitted `MsgVoteInbound`/`MsgVoteOutbound` tx lands can move the pool price arbitrarily, and the module-originated swap will still "pass" its own slippage check while executing at the attacker-manipulated price, exactly analogous to the ERC4626 report's "no protection against changes in fee/pool size."

### Finding Description
Three call sites in `x/uexecutor` follow the identical pattern:

1. `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:104-153`): fetches `GetSwapQuote(...)` then computes `minPCOut := quote * 95 / 100` and immediately calls `CallPRC20DepositAutoSwap(..., amount, fee, minPCOut)`. [1](#0-0) 
2. `gasAndPayloadDepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:348-379`): identical pattern for `GAS_AND_PAYLOAD` inbounds. [2](#0-1) 
3. `applyGasRefund` (`x/uexecutor/keeper/outbound.go:213-236`): identical pattern for the outbound excess-gas refund swap (gasToken → PC). [3](#0-2) 

In each case, `GetSwapQuote` performs a static `CallEVM` (`commit=false`) against `QuoterV2.quoteExactInputSingle` reading current pool state (`x/uexecutor/keeper/evm.go:500-538`), and the resulting `minPCOut` is passed straight into a `DerivedEVMCall` (`commit=true`) that executes the real swap on the same pool a few lines later, with `deadline = 0` ("contract uses its default") for the inbound path. [4](#0-3) 

Because both the quote and the actual swap read the same live pool state back-to-back within one keeper invocation, `minPCOut` is not an independent, attacker-resistant reference price — it is derived from whatever price the pool happens to be at right before execution. The pools themselves (`WPC`/PRC20 Uniswap V3 pools) are ordinary, publicly-tradable pools created during setup and used by `UniversalCore` for these autoswaps. [5](#0-4) 

An unprivileged attacker can submit an ordinary EVM swap transaction against the same WPC/PRC20 pool to push the price in their favor immediately before the validator-submitted `MsgVoteInbound` (which triggers `ExecuteInboundGas`) or `MsgVoteOutbound` (which triggers `applyGasRefund`) is included in a block. Because the quote is fetched and consumed atomically with the swap, the attacker's manipulated price simply becomes the new "reference," the 5% band it is checked against is computed from that same manipulated price, and the module-originated swap executes at the manipulated rate. The attacker then reverses their initial trade for a profit — a classic sandwich attack — while the bridging user (for `GAS`/`GAS_AND_PAYLOAD` inbound top-ups) or the refund recipient (for outbound gas refunds) receives a materially smaller amount of native PC than the pool's undisturbed price would imply, and value is extracted from protocol-controlled liquidity/PRC20 balances.

### Impact Explanation
This directly corrupts the amount of native PC token credited during PRC20↔WPC autoswaps that are part of universal execution (`GAS`/`GAS_AND_PAYLOAD` inbound processing) and the outbound gas-fee refund accounting path. This is unauthorized value extraction reachable by an ordinary unprivileged user submitting normal swap transactions against a public AMM pool wired into the protocol's registry/accounting flow — matching the in-scope "corruption of ... gas fee accounting, refund accounting ... token mapping ... UniversalTx state" and "stealing ... funds" categories. Impact is medium: it does not break consensus or allow unauthorized minting/burning outright, but it does let an attacker skim value from every gas-top-up or gas-refund autoswap, at the expense of users and/or protocol liquidity.

### Likelihood Explanation
Likelihood is medium-to-high in an environment with public liquidity pools of realistic size: this requires no privileged access, no validator/relayer collusion, and no bug beyond normal AMM sandwich mechanics against a pool whose trigger transaction (`MsgVoteInbound`/`MsgVoteOutbound`) is visible in the mempool like any other transaction. The hardcoded flat 5% band offers a nominal per-call bound but not protection against manipulation because the reference price itself is attacker-influenced at execution time.

### Recommendation
Do not derive `minPCOut` from a quote fetched in the same call as the swap execution. Instead:
- Use a manipulation-resistant reference price (e.g., a time-weighted average price/oracle, or a governance/registry-configured expected rate) independent of the pool's instantaneous spot price, or
- Require a real user- or protocol-supplied slippage bound validated against an external reference, and add a genuine deadline (currently passed as `0`, i.e., "use default," in `CallPRC20DepositAutoSwap`) tied to the inbound/outbound observation window rather than to the swap call itself.
- Consider limiting single-swap size relative to pool depth/liquidity caps so the price impact of a single sandwich is bounded independent of the 5% figure.

### Proof of Concept
1. Attacker observes an `eip155:X` GAS or GAS_AND_PAYLOAD inbound event that will be voted on by Universal Validators (visible pre-confirmation via public inbound observation / mempool of `MsgVoteInbound`).
2. Before the finalizing `MsgVoteInbound` tx lands, attacker submits a large swap on the public WPC/PRC20 Uniswap V3 pool (deployed per `e2e-tests/setup.sh` `create-pool`) to push the PRC20→WPC price down.
3. `MsgVoteInbound` finalizes; `ExecuteInboundGas` calls `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`), which reads the now-manipulated pool price, computes `minPCOut = quote*95/100`, and calls `CallPRC20DepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas.go:142-153`) which executes at the manipulated price — the check trivially passes since it's derived from the same price.
4. Attacker immediately reverses their initial trade on the same pool, restoring price and capturing the spread — the bridging user's UEA receives less native PC than an unmanipulated quote would have produced.
