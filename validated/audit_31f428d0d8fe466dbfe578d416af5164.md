Based on my investigation, this exact attack scenario is already explicitly guarded against in the codebase and has a dedicated regression test.

The proposed exploit—ancestors={A,B} where B is a rooted-but-non-ancestor slot causing `do_load` to return B's stale value instead of A's newer write—is precisely what `AccountsIndex::latest_slot` and `AccountsCache::load_latest` are designed to prevent via `min_slot`/`max_root` bounding.

In `AccountsIndex::latest_slot`, when an ancestor is found, the function returns immediately without considering roots at all, and the doc comment explicitly states: "If there is a root that is newer than the newest ancestor but not an ancestor then the root is from a different fork and should not be returned."
<cite repo="Thankgoddavid56/agave--034" path="accounts-db/src/accounts_index.rs" start="429="454" end="450" /> [1](#0-0) 

The `max_root` bound passed into `get_with_and_then` is derived from `ancestors.min_slot()`, not `max_slot()`, which is the key correctness property preventing a rooted-but-non-ancestor slot (B) from shadowing a newer ancestor write (A) when B falls between the ancestor set's min and max: [2](#0-1) 

Similarly, `AccountsCache::load_latest` bounds the root search to `ancestors.min_slot()` with an explicit comment: "Using min_slot is more correct than max_slot because a root between min and max that is not an ancestor belongs to a different fork and should not be returned." [3](#0-2) 

There is already a targeted regression test, `test_load_does_not_return_data_from_non_ancestor_root`, that reproduces exactly the scenario described in the question (ancestors={17,19}, rooted-but-non-ancestor slot 18, rooted ancestor slot 16) and asserts the correct slot (16) is returned rather than the stale/wrong-fork slot 18. The test's docstring even references the historical race this was designed to close ("the original race where `set_root(N+1)` adds a root...causing RPC to return data from slot N+1 while reporting `context.slot = N`"). [4](#0-3) 

Additionally, `AccountsCache::load_latest` checks ancestors exhaustively (highest to lowest) before ever falling back to roots, so any ancestor write for pubkey A at a higher slot always wins over any root: [5](#0-4) 

Given the unprivileged attacker described (controls only write frequency/fork depth via system transfers, no ability to bypass `Ancestors` construction which is derived from validated bank ancestry, not attacker input), there's no way to make `do_load` skip the `min_slot` bound or make a non-ancestor root be treated as an ancestor — the ancestor set itself is not attacker-controlled data, it's derived from the bank's own fork lineage.

### No vulnerability found for this question.

The described stale/wrong-fork load path is already prevented by the `min_slot`-bounded root lookup in both `AccountsIndex::latest_slot`/`get_with_and_then` and `AccountsCache::load_latest`, and is covered by an existing dedicated regression test (`test_load_does_not_return_data_from_non_ancestor_root`) that asserts the exact `LOAD_FRESHNESS` property the question asks to fuzz. The attacker's write-frequency/fork-depth control has no way to bypass this bound since `Ancestors` is derived from validated bank lineage, not attacker-supplied data.

/// data from a rooted slot that is not an ancestor of the querying bank.
///
/// Scenario
///   - Bank at slot 19 has ancestors {17, 19}
///   - Account exists at slot 18 (rooted but NOT an ancestor — different fork)
///   - Account exists at slot 16 (rooted)
///   - min_slot of ancestors = 17
///   - Slot 18 > 17 so it must be excluded; slot 16 <= 17 so it is returned.
///
/// This also covers the original race where `set_root(N+1)` adds a root to

/// return data from slot N+1 while reporting `context.slot = N`.
#[test]
fn test_load_does_not_return_data_from_non_ancestor_root() {
    let db = AccountsDb::new_for_tests_with_config(Vec::new(), DEFAULT_ACCOUNTS_DB_CONFIG);
    let pubkey = Pubkey::new_unique();

    // Store account at slot 16 (rooted, below ancestors.min_slot)
    let account_v1 = AccountSharedData::new(100, 0, &Pubkey::default());
    db.store_for_tests((16, &[(&pubkey, &account_v1)][..]));
    db.add_root(16);

    // Store account at slot 18 (rooted, but not an ancestor of bank 19)
    let account_v2 = AccountSharedData::new(200, 0, &Pubkey::default());
    db.store_for_tests((18, &[(&pubkey, &account_v2)][..]));
    db.add_root(18);

    // Ancestors = {17, 19}: min_slot = 17. Slot 18 is rooted but not an
    // ancestor, so it must be excluded. Slot 16 <= 17, so it is returned.
    let ancestors = Ancestors::from(vec![17, 19]);
    let (account, slot) = db.do_load_for_tests(&ancestors, &pubkey).unwrap();

    assert_eq!(
        slot, 16,
        "must return slot 16, not non-ancestor root at slot 18"
    );
    assert_eq!(account.lamports(), 100);
}
