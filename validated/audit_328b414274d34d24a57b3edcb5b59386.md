### Title
DoS: Unbounded growth of per-shop session-ID index in `RedisSessionStorage` causes linear-time, network-bound iteration in `findSessionsByShop()` - (File: `packages/apps/session-storage/shopify-app-session-storage-redis/src/redis.ts`)

### Summary
`RedisSessionStorage` maintains, per shop, a JSON array of session-id keys (`addKeyToShopList`) that is never capped or deduplicated by user/session semantics. Any flow that stores a new session with a fresh id (e.g. non-embedded OAuth online sessions, which get a `crypto.randomUUID()` id on every completed login) appends a new entry to that array indefinitely. `findSessionsByShop()` then has to issue one sequential Redis `GET` per entry in that array, so its cost grows linearly (and un-boundedly) with the number of stored sessions for a shop — directly mirroring the "cheap, attacker-created receipts must all be processed later" pattern from the referenced report.

### Finding Description
- `addKeyToShopList()` only guards against exact-duplicate `idKey`s; it never limits array size or removes stale/expired entries: [1](#0-0) 
- `findSessionsByShop()` loops over every id in that array and performs a separate network round-trip (`this.client.get(idKey, false)`) for each one, with no size limit or pagination: [2](#0-1) 
- For non-embedded apps, every completed OAuth login mints a brand-new random session id (not tied to a stable user id), so repeated legitimate OAuth completions for the same shop keep appending distinct entries to the shop's array without ever reusing/overwriting an old one: [3](#0-2) 
- `findSessionsByShop()` is invoked from operational/auth-adjacent paths such as `AppInstallations.includes()`/`AppInstallations.delete()` (used by the `app/uninstalled` webhook handler and other lifecycle checks), meaning the unbounded loop is reachable from normal webhook/auth processing, not just admin tooling: [4](#0-3) [5](#0-4) 

This is the same bug class as the report: a low/no-cost attacker action (creating a new "receipt"/session) accumulates indefinitely in a collection, and a later, otherwise-bounded operation (`withdrawExcessRewards()` / `findSessionsByShop()`) is forced to iterate over the entire, attacker-inflated collection, with cost proportional to the number of entries created.

### Impact Explanation
As the number of stored sessions for a shop grows, `findSessionsByShop()` degrades from O(1) to O(n) sequential network round-trips. Because this function backs webhook lifecycle processing (`app/uninstalled` handling) and other operational checks, a shop with a large number of accumulated session records can cause that handler to take significantly longer or exhaust connection/time budgets, resulting in denial-of-service style degradation of that auth-adjacent processing path. This does not lead to token theft or cross-tenant access — it is a resource-exhaustion/availability issue confined to the Redis session-storage adapter.

### Likelihood Explanation
Reaching a materially large `n` requires many stored sessions for a single shop. For non-embedded apps, each completed OAuth login for an online session is assigned a fresh `crypto.randomUUID()` id and is never deduplicated against previous logins by the same user, so repeated (automatable) OAuth completions by a shop's own staff/admin (a "malicious normal user abusing valid product flows," not a privileged operator of the codebase) can inflate this array over time. This still requires successfully completing the OAuth handshake with Shopify for each entry, which bounds the rate somewhat, but there is no cap, expiry-based pruning, or size limit enforced by the library itself.

### Recommendation
- Cap or paginate the per-shop id list, or replace it with a Redis Set/Sorted Set and use pipelining/`MGET` to batch-fetch session values instead of sequential `GET` calls.
- Prune expired/stale session ids from the per-shop index on read or via TTL, and deduplicate by user id for online sessions where possible.
- Consider bounding `findSessionsByShop()` results or provide a configurable limit to protect callers like `AppInstallations`.

### Proof of Concept
1. For a non-embedded, shop-owned app, repeatedly complete the OAuth flow to obtain online access tokens (each completion is a normal, unprivileged action available to any authorized user of the shop).
2. Each completion produces a new `Session` with `id = crypto.randomUUID()`: [3](#0-2) 
3. `storeSession()` calls `addKeyToShopList()`, which appends the new unique id to the shop's array in Redis with no upper bound: [6](#0-5) 
4. Any later call to `findSessionsByShop(shop)` (e.g. triggered by the `app/uninstalled` webhook via `AppInstallations.delete`) must issue one Redis GET per accumulated id, so its latency/cost scales linearly with the number of OAuth completions performed in step 1: [2](#0-1)

  public async findSessionsByShop(shop: string): Promise<Session[]> {
    await this.ready;

    const idKeysArrayString = await this.client.get(shop);
    if (!idKeysArrayString) return [];

    const idKeysArray = JSON.parse(idKeysArrayString);
    const results: Session[] = [];
    for (const idKey of idKeysArray) {
      const rawResult = await this.client.get(idKey, false);
      if (!rawResult) continue;

      const session = Session.fromPropertyArray(JSON.parse(rawResult), true);
      results.push(session);
    }

    return results;
  }

  private async addKeyToShopList(session: Session) {
    const shopKey = session.shop;
    const idKey = this.client.generateFullKey(session.id);
    const idKeysArrayString = await this.client.get(shopKey);

    if (idKeysArrayString) {
      const idKeysArray = JSON.parse(idKeysArrayString);

      if (!idKeysArray.includes(idKey)) {
        idKeysArray.push(idKey);
        await this.client.set(shopKey, JSON.stringify(idKeysArray));
      }
    } else {
      await this.client.set(shopKey, JSON.stringify([idKey]));
    }
  }

  async includes(shopDomain: string): Promise<boolean> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      for (const session of shopSessions) {
        if (session.accessToken) return true;
      }
    }
    return false;
  }

  async delete(shopDomain: string): Promise<void> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      await this.sessionStorage.deleteSessions!(
        shopSessions.map((session: Session) => session.id),
