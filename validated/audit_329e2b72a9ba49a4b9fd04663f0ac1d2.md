### Title
User-favoured truncation in `CalculateGasCost` rounds gas fee down instead of up, under-charging every derived-payload execution - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`x/uexecutor/keeper/fees.go`'s `CalculateGasCost` unwraps the fee-market's `LegacyDec` base fee by truncating (`big.Int.Div`) instead of rounding up, discarding any fractional-upc precision in the base fee before multiplying by `gasUsed`. This mirrors the OmniX report's core flaw — rounding a fee calculation in the user's favor instead of the contract's/protocol's — except here the asset being under-collected is the gas fee burned for every module-originated (`DerivedEVMCall`) UEA payload execution.

### Finding Description
`CalculateGasCost` recovers the human-readable base fee from the `LegacyDec` 18-decimal internal representation with a plain, truncating division: [1](#0-0) 

The inline comment asserts "no fractional upc exists," but that assumption depends entirely on the fee-market module's dynamic EIP-1559-style base-fee adjustment never producing a non-integer `LegacyDec` value — logic that lives outside this repo's custom code and is not enforced anywhere in the scoped `x/uexecutor` code. Any fractional remainder present in `baseFee` is silently dropped (rounded toward zero, i.e., down) rather than rounded up, before it's multiplied by `gasUsed` to produce `gasCost`: [2](#0-1) 

This is then used to burn fees directly from the recipient's UEA balance in the universal execution path: [3](#0-2) 

Contrast this with the two other fee-computation sites in the same scoped codebase, both of which correctly round *up* (in favor of the protocol) when converting a `Dec` gas price into an integer fee: [4](#0-3) [5](#0-4) 

`CalculateGasCost` is the only fee-derivation function in the codebase that truncates instead of ceiling, and it is reachable from the ordinary, unprivileged user-facing execution paths `ExecuteInboundFundsAndPayload` and `ExecuteInboundGasAndPayload` on every smart-contract-recipient (isCEA) inbound: [6](#0-5) [7](#0-6) 

### Impact Explanation
Each derived EVM call that consumes gas has its owed fee computed from `floor(baseFee) × gasUsed` rather than `baseFee × gasUsed` rounded up. Any fractional-upc component of the base fee (which arises naturally whenever the fee-market's EIP-1559 style adjustment increases/decreases the base fee by a percentage each block — a `LegacyDec` operation with no guarantee of landing on an integer upc boundary) is discarded in the user's favor on every single execution. This is a systemic under-collection of gas-fee accounting (an explicitly in-scope impact: "corruption of ... gas fee accounting ... under ordinary user deposits, payloads, contracts, or default transaction submission paths alone"), reachable by any unprivileged user simply by triggering UEA/CEA payload execution — no privileged actor or malicious validator/relayer assumption is required.

### Likelihood Explanation
High reachability: `DeductGasFeesFromReceipt` → `CalculateGasCost` executes on every successful smart-contract-recipient inbound execution (`isCEA` branch) in both `ExecuteInboundFundsAndPayload` and `ExecuteInboundGasAndPayload`, which are core, non-privileged, everyday execution paths. The only precondition is that the fee-market's `BaseFee` is not an exact integer multiple of 1e18 in its internal `LegacyDec` representation at the moment of the call, which is the normal/expected state for any dynamically adjusting EIP-1559-style base fee.

### Recommendation
Round the unwrapped base fee up rather than truncating it — e.g., use `Ceil()`/`RoundUp` semantics consistent with `app/ante/validator_tx_fee.go` and `app/cosmos/min_gas_price.go` — so that `CalculateGasCost` never under-charges the recipient for the true EVM gas cost incurred.

### Proof of Concept
1. Let the fee-market's `BaseFee` (a `LegacyDec`) settle, after ordinary EIP-1559-style block-by-block adjustment, at a non-integer upc value, e.g. `1_000_000_000.7` upc (internal `BigInt()` = `1000000000700000000000000000000000000`... i.e., not an exact multiple of `1e18`).
2. A user submits a `MsgExecutePayload`/inbound that routes to a smart-contract recipient (`isSmartContract` branch), consuming `gasUsed = 100_000` gas.
3. `CalculateGasCost` computes `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`, silently truncating `1_000_000_000.7` down to `1_000_000_000`, then computes `gasCost = 1_000_000_000 × 100_000`, instead of the fee owed under the true (rounded-up) base fee of `1_000_000_001`.
4. `DeductAndBurnFees` burns the truncated (lower) amount from the recipient's UEA account; the difference — `0.7 upc × gasUsed` per call — is never collected, repeating on every subsequent execution while the base fee is non-integer.

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```
