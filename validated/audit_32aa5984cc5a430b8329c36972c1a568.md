### Title
Starknet OS `execute_replace_class` accepts undeclared/wrong-version class hashes, causing divergence from the blockifier's `replace_class` validation - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Biswap `V3Migrator` exploit worked because the migrator contract trusted a caller-supplied address (`pair`) and its returned data without verifying that the address corresponded to a legitimate, expected object — allowing an attacker to substitute a fake contract whose data was blindly accepted and used to move funds. The sequencer's analog is a place where an unprivileged transaction's syscall input (a `class_hash` argument to `replace_class`) is written into committed contract state by the Starknet OS without verifying that the class hash corresponds to a real, declared, compatible class — while the Rust `blockifier` (the actual state-transition authority used to build/validate blocks) does perform this check.

### Finding Description
`blockifier`'s syscall implementation of `replace_class` explicitly validates the target class before mutating state: [1](#0-0) 
It reads the compiled class (failing if undeclared) and rejects Cairo v0 (deprecated) classes.

The equivalent Cairo implementation used by the Starknet OS (which re-executes transactions for proving / re-execution verification) does **not** perform this check. The code contains an explicit, unresolved TODO acknowledging the missing validation, and unconditionally writes the caller-supplied `class_hash` into the contract's new `StateEntry`: [2](#0-1) 

Specifically, line 902 (`// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`) shows the class-declared check and Cairo-version check present in the Rust blockifier (`get_compiled_class` + `is_cairo1`) is absent in the OS Cairo implementation — the state entry is updated with `class_hash=request.class_hash` regardless of whether that class was ever declared or whether it is a Cairo0/Cairo1 class.

This is directly analogous to the Biswap bug class: an unprivileged, attacker-controlled input (the `class_hash` argument to the `replace_class` syscall, reachable from any contract executing user calldata) is trusted and committed to state without verifying its legitimacy against the actual declared-class registry, in one of the two independent implementations of the same state-transition function (blockifier vs. Starknet OS).

### Impact Explanation
The sequencer's block-production/consensus path (blockifier) and the proving/re-execution path (Starknet OS) must compute identical state transitions for a block to be provable and verifiable. If a contract invokes `replace_class` with:
- an undeclared class hash, or
- a Cairo V0 (deprecated) class hash (explicitly forbidden by blockifier: `ForbiddenClassReplacement`),

the blockifier will fail that syscall (propagating a revert of the inner call, or aborting the transaction), whereas the OS's Cairo implementation will accept it silently and commit the invalid `class_hash` into `contract_state_changes`. Since Starknet contracts commonly call `replace_class_syscall(...)` through "safe" call patterns that catch `SyscallResult` errors, this divergence is directly observable and does not necessarily abort transaction execution in either environment.

This produces a genuine state-transition divergence between the two implementations: the state root/committed class hash for the affected contract would differ between what the sequencer nodes agree on (via blockifier) and what the Starknet OS proves (via the Cairo re-execution program). This maps to "wrong committed root" / "honest-node divergence" among the accepted impact categories — a contract's class hash entry in the Patricia state tree can end up permanently set to a garbage/undeclared value from the OS's perspective, breaking provability of otherwise-valid blocks, or conversely allowing a state transition to be "proven" that the actual network state disagrees with.

### Likelihood Explanation
The `replace_class` syscall is reachable from any account or contract executing ordinary calldata — no special privileges, staking, or proposer/operator role is required. Any unprivileged transaction sender can trigger `replace_class_syscall` with an arbitrary felt as `class_hash`. The bug is gated only by whether the OS's execution path is exercised (re-execution / proving), which is a normal part of the sequencer's operation for every block. The explicit TODO comment confirms this is a known, currently-unaddressed gap in the codebase (dated 1/1/2026), which increases confidence that this divergence is real and unresolved as of the current snapshot.

### Recommendation
Add the missing declared-class (and Cairo-version) check to `execute_replace_class` in `syscall_impls.cairo`, mirroring the Rust blockifier's logic in `syscall_base.rs::replace_class` (`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`): before performing the `dict_update`, verify that `class_hash` exists in the declared-classes state (analogous to the class-hash lookup hinted via `GetContractAddressStateEntry`/class-manager reads elsewhere) and that it is not a deprecated (Cairo V0) class hash, raising a syscall failure otherwise — exactly as `deploy_contract.cairo` enforces `state_entry.class_hash = UNINITIALIZED_CLASS_HASH` before deploy. This restores parity between the OS and blockifier state-transition semantics.

### Proof of Concept
1. Deploy or use any existing contract exposing a wrapper for `replace_class_syscall` (e.g., analogous to `test_replace_class` in `blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo`), using a "safe"/non-panicking dispatcher pattern that swallows syscall errors (a common account/library pattern).
2. Submit an ordinary `INVOKE` transaction calling this entry point with an arbitrary, never-declared felt as `class_hash` (e.g., `0xdeadbeef`), or with a valid but Cairo V0 class hash.
3. In blockifier-based execution (sequencer state transition), the syscall fails: `syscall_handler.state.get_compiled_class(request.class_hash)?` returns "is not declared" (see `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`), so the contract's class hash is left unchanged in the committed state.
4. In the Starknet OS re-execution of the same transaction (`execute_replace_class` in `syscall_impls.cairo`), no such check exists: the `dict_update` unconditionally sets `new_state_entry.class_hash = class_hash` for the undeclared/invalid value, and a `RevertLogEntry` marking `CHANGE_CLASS_ENTRY` is recorded as if the change succeeded.
5. The two independently-computed state diffs for the same block/transaction now disagree on the contract's class hash, demonstrating the divergence between the blockifier's committed state and the Starknet OS's re-executed/proven state.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
