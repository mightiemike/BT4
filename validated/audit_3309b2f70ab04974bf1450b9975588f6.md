### Title
Starknet OS `replace_class` syscall implementation omits the "declared class" check enforced by the Blockifier, enabling a sequencer/OS state divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Woodpecker advisory describes a privileged field (`serviceAccountName`) being forwarded unchecked into a privileged execution context, bypassing an authorization gate that the design assumes exists. The sequencer analog is the `ReplaceClass` syscall's `class_hash` field: the Rust Blockifier (which produces the canonical execution trace used to build/commit blocks) explicitly gates the class-hash write behind a "declared class" check, but the Cairo Starknet OS (SNOS) program — which re-executes the same transactions to generate the STARK proof of the block — does **not** perform this check before writing the new class hash into `contract_state_changes`.

### Finding Description
In the Blockifier (native execution used to build and commit the block), `replace_class` first verifies the target class is declared before mutating state: [1](#0-0) 

The forbidden V0/V1 downgrade and declared-class checks are enforced through `syscall_handler.base.replace_class` / `state.get_compiled_class`, and this is directly asserted by unit tests expecting rejection of undeclared or V0 class hashes: [2](#0-1) 

However, the Cairo implementation of the same syscall inside the Starknet OS program, which is what actually gets proven and is meant to be a faithful re-execution of the block, contains an explicit `TODO` marking the missing check and unconditionally overwrites the contract's class hash: [3](#0-2) 

The deprecated (Cairo0) syscall path in the OS program exhibits the identical gap — no declared-class check before the state dict update: [4](#0-3) 

Because non-reverted transactions are the only ones actually re-executed step-by-step by the OS (reverted transactions are skipped entirely, per the `is_reverted` short-circuit in `execute_invoke_function_transaction`): [5](#0-4) 

a contract that *catches* the `ReplaceClass` syscall failure (Cairo 1 syscalls return a `Result` and can be handled without unwrapping) will, under the Blockifier, never mutate `class_hash` because the check fails before the state write — the transaction is recorded as **succeeded**, with no class-hash change. Under the SNOS Cairo re-execution of that same non-reverted transaction, `execute_replace_class` performs the state dictionary update unconditionally, regardless of whether the class is declared or is a forbidden V0 downgrade. This is exactly the "field passed to a privileged operation without the corresponding authorization gate" pattern from the advisory, just relocated to the OS's syscall handler instead of a Kubernetes pod spec.

### Impact Explanation
This produces a genuine committed-state vs. proven-state divergence for the `class_hash` of any contract address reachable via a single unprivileged transaction calling `replace_class` with an undeclared or forbidden class hash inside a caught-error branch. Since the OS's output includes the resulting Patricia tree commitments that back the proof, an undetected divergence here means the proof would attest to a different `class_hash` for that contract than what the sequencer's Blockifier actually committed to the DA/state — i.e., a wrong committed root, or a rejected/mismatched proof relative to the sequencer's block, which is one of the explicitly accepted high-impact outcomes (wrong committed root / honest-node divergence).

### Likelihood Explanation
Reachable directly from a single Cairo1 contract invocation: any account with Push-equivalent capability here (i.e., any address that can invoke a contract) can deploy or call a contract that performs `replace_class_syscall(...)` and handles the `Result` without propagating the error, causing the call (and therefore the transaction) to succeed while the class hash write is skipped by the Blockifier. No special privilege, staking, or operator access is required — matching the "single submitted transaction" reachability bar. Confidence is bounded by the fact that I could confirm the two divergent code paths (Blockifier's checked path with tests, and OS's explicit unchecked TODO) but could not fully trace the SNOS hint/witness plumbing that supplies `class_hash` into the OS's `syscall_ptr.response`/`GetContractAddressStateEntry` hint at proof-generation time within the remaining investigation budget.

### Recommendation
Add the same "class must be declared" (and, if applicable, "cannot downgrade V1→V0") check to the OS Cairo implementations of `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring the Blockifier's `get_compiled_class` check in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`, before the `dict_update` that mutates `contract_state_changes`. This closes the TODO and removes the semantic gap between the executing engine and the proving engine.

### Proof of Concept
1. Declare a class `V0_CLASS` (Cairo 0) or leave a class hash `X` entirely undeclared.
2. Deploy a Cairo 1 contract `Attacker` whose entry point calls `replace_class_syscall(X)` and explicitly matches on the `Result`, discarding any `Err` (i.e., does not `unwrap_syscall()`), so the entry point completes successfully regardless of syscall outcome — analogous to the `fuzz_revert.cairo` "catch and continue" pattern already present in the test contracts.
3. Submit an `INVOKE` transaction calling `Attacker`'s entry point.
4. Blockifier execution: `replace_class` syscall handler in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs` fails the declared-class check, returns `Err` to the caller, caller ignores it, transaction is recorded as **ACCEPTED** with `class_hash` unchanged at `Attacker`'s address.
5. SNOS re-execution of the same (non-reverted) transaction: `execute_replace_class` in `syscall_impls.cairo` performs the `dict_update` unconditionally, setting `Attacker`'s `class_hash` to `X` in the OS's view of `contract_state_changes` — diverging from what the Blockifier actually committed.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
