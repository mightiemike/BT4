## Finding: Hardcoded `MAX_GAS_PRICE_MULTIPLIER` Caps L2 Gas Price, Preventing Fee Market From Tracking Real Costs During Extreme Market Events

### Summary

The consensus orchestrator's fee market enforces a hard ceiling on the L2 gas price equal to a hardcoded constant, `MAX_GAS_PRICE_MULTIPLIER = 10`, times the configured minimum gas price. Unlike every other bound in the same pricing pipeline (the minimum-price-per-height table, the L1 gas price bounds, the exchange-rate bounds), this ceiling is not exposed through any config and can only be changed by shipping new node code. In a "LUNA-style" market event — a rapid STRK devaluation or L1 fee spike — this immutable, hardcoded multiplier prevents SNIP-35 dynamic pricing from raising the L2 gas price enough to track real, USD-denominated costs, structurally under-pricing L2 gas relative to the network's true cost of settling on L1.

### Finding Description

`l2_gas_price_cap` computes the ceiling for the next L2 gas price as `min_gas_price * MAX_GAS_PRICE_MULTIPLIER`, where `MAX_GAS_PRICE_MULTIPLIER` is a `const u128 = 10` defined in the module, explicitly noted by the code's own author as a stopgap: `// TODO(asaf-sw): Move to versioned constants in 0.14.4.` [1](#0-0) 

This cap is enforced on every published price, both for the EIP-1559-style congestion adjustment and for the SNIP-35 oracle-driven floor: `calculate_next_l2_gas_price_for_fin` clamps `raw_price` and the oracle-derived `snip35_min` to `cap` before publishing, and both proposer and validator are forced to agree on this ceiling since they both call the same hardcoded function. [2](#0-1) 

The SNIP-35 mechanism (`compute_fee_target`) is designed specifically to react to a collapsing STRK/USD rate by increasing the FRI-denominated gas price so that a fixed USD-denominated cost target is preserved: `floor_fri = target_atto_usd_per_l2_gas * 10^18 / strk_usd_rate` — as `strk_usd_rate` falls, the required FRI price rises proportionally, without bound. [3](#0-2) 

But regardless of how far the oracle-driven target rises, the actual price the sequencer publishes is silently clipped to the hardcoded `10x` ceiling: `snip35_min_above_cap` is explicitly logged and metered as an expected, recurring event (`snip35_fee_target_above_maximum` alert), confirming this is a known, accepted failure mode rather than an edge case. [4](#0-3) [5](#0-4) 

Contrast this with every neighboring bound in the pricing pipeline, which *is* operator-adjustable without a code change:
- `min_l2_gas_price_per_height` — dynamic config, height-indexed. [6](#0-5) 
- `min_l1_gas_price_wei` / `max_l1_gas_price_wei` — dynamic config. [7](#0-6) 
- `rate_bounds_config` for ETH/USD, STRK/USD, ETH/STRK — dynamic config, validated on load. [8](#0-7) 

Only the L2 gas price ceiling itself — the one bound that directly determines whether the sequencer can charge enough to cover the true cost of an L1 posting spike or STRK collapse — is hardcoded into the binary with no config knob, exactly the "hardcoded `maxSlippage`" pattern from the source report: every other lever is adjustable, but the one that matters most in an emergency is not.

### Impact Explanation

During a rapid STRK devaluation or an extreme L1 fee spike, the fee market's ceiling silently caps the L2 gas price at 10x the minimum regardless of real cost. Because ordinary user transactions (fully within reach of any unprivileged sender, simply by using the network under normal congestion) drive the EIP-1559 congestion term and interact with the same capped ceiling, the sequencer is forced to accept blocks priced below the true L1/settlement cost for as long as the emergency persists. This is a direct, sustained loss-of-funds condition for the network/operator: L2 gas fees collected from users structurally fail to cover the L1 costs the sequencer must pay, with no config-only remedy — a node operator cannot raise the ceiling without a coordinated software upgrade, unlike the L1 gas price bounds or rate bounds, which can be corrected immediately via dynamic config.

### Likelihood Explanation

The `snip35_fee_target_above_maximum` alert and its dedicated metric exist specifically because this ceiling is already known to be hit in practice — the codebase's own dashboard treats "target exceeds the maximum" as a real, expected condition to monitor, not a theoretical corner case. [5](#0-4)  A sharp STRK/USD devaluation or L1 gas spike is exactly the kind of market event the original report envisions ("if something unexpected happens (like LUNA)"), and the sequencer has no config-level lever to raise this ceiling in response — only a binary upgrade, which cannot happen fast enough to prevent losses during an acute event.

### Recommendation

Move `MAX_GAS_PRICE_MULTIPLIER` out of a hardcoded Rust constant into `VersionedConstants` or a dynamic config value (as the existing `TODO(asaf-sw)` comment already recommends), consistent with how `min_l2_gas_price_per_height`, the L1 gas price bounds, and the exchange rate bounds are already handled. This allows operators to raise the ceiling quickly during an emergency without requiring a full node software release and rollout.

### Proof of Concept

1. `MAX_GAS_PRICE_MULTIPLIER` is fixed at `10` in code with no config path: [1](#0-0) 
2. `l2_gas_price_cap` derives the ceiling solely from this constant and the current minimum price: [9](#0-8) 
3. `calculate_next_l2_gas_price_for_fin` clamps both the EIP-1559 congestion-driven price and the SNIP-35 oracle-driven floor (`snip35_min`) to this cap before publishing: [10](#0-9) 
4. Existing tests already demonstrate the SNIP-35 floor being driven far above the ceiling and getting silently clipped, showing the mechanism is exercised, not merely theoretical: `test_fee_actual_above_the_ceiling_publishes_the_ceiling` and the `snip35_floor_above_the_ceiling` test case. [11](#0-10) [12](#0-11) 
5. There is no config field anywhere (`config_schema.json`) that exposes this multiplier, unlike every neighboring bound (`min_l1_gas_price_wei`, `max_l1_gas_price_wei`, `rate_bounds_config.*`), confirming operators cannot remediate without a code deployment.

```rust
/// configuration. If not exist for the given height, use versioned constants min_gas_price as
/// fallback.
///
/// # Parameters
/// - `height`: The block height to look up.
/// - `min_l2_gas_price_per_height`: List of height-price pairs from configuration, assumed to be
///   sorted by height in ascending order.
pub fn get_min_gas_price_for_height(
    height: BlockNumber,
    min_l2_gas_price_per_height: &[PricePerHeight],
) -> GasPrice {
    let fallback_min_gas_price = VersionedConstants::latest_constants().min_gas_price;
    min_l2_gas_price_per_height
        .iter()
        .rev()
        .find(|e| e.height <= height.0)
        .map(|e| GasPrice(e.price))

}
```

```rust
/// The ceiling on the L2 gas price: `MAX_GAS_PRICE_MULTIPLIER` times `min_gas_price`. Applies to
/// every block regardless of its `starknet_version`. Proposer and validator reach the ceiling
/// through this function, so they cannot disagree on it.

// second caller, is deferred to `main`.
pub fn l2_gas_price_cap(min_gas_price: GasPrice) -> GasPrice {
    GasPrice(min_gas_price.0.saturating_mul(MAX_GAS_PRICE_MULTIPLIER))

/// Compute the next L2 gas price (for the fin or for updating state). Respects override when set.
/// Reporting the bounds is the caller's job, through `NextL2GasPrice::record_clamping`.
pub fn calculate_next_l2_gas_price_for_fin(
    current_l2_gas_price: GasPrice,
    height: BlockNumber,
    l2_gas_used: GasAmount,
    override_l2_gas_price_fri: Option<u128>,
    min_l2_gas_price_per_height: &[PricePerHeight],
    fee_actual: Option<GasPrice>,
) -> NextL2GasPrice {
    if let Some(override_value) = override_l2_gas_price_fri {
        // Operator pin: escapes both bounds by design; each side substitutes its own override.
        info!(
            "L2 gas price ({}) is not updated, remains on override value of {override_value} fri",
            current_l2_gas_price.0
        );
        return NextL2GasPrice { published_price: GasPrice(override_value), bounds: None };
    }
    let gas_target = VersionedConstants::latest_constants().gas_target;
    let config_min = get_min_gas_price_for_height(height, min_l2_gas_price_per_height);
    let cap = l2_gas_price_cap(config_min);

    let snip35_min = fee_actual.map_or(config_min, |fee_actual| max(config_min, fee_actual));
    let effective_min = min(snip35_min, cap);

    let raw_price =
        calculate_next_base_gas_price(current_l2_gas_price, l2_gas_used, gas_target, effective_min);

    NextL2GasPrice {
        published_price: min(raw_price, cap),
        bounds: Some(L2GasPriceBounds {
            current_price: current_l2_gas_price,
            raw_price,
            snip35_min,
            effective_min,
            cap,
        }),
    }
}
```

```rust
/// Compute the fee target from STRK/USD price and a USD cost target.
///
/// `target_atto_usd_per_l2_gas` is in atto-USD (atto = 10⁻¹⁸; so a value of
/// `3_000_000_000` means 3·10⁻⁹ USD = 3 nanodollars per L2 gas unit).
/// `strk_usd_rate` is the STRK/USD price as USD per STRK with 18 decimals (from the oracle);
/// a rate of `0` returns `None` (treat as oracle failure: callers freeze at `fee_actual`).
/// Returns the target in FRI; the multiplicative margin clamp in `compute_fee_proposal`
/// keeps the published proposal bounded relative to `fee_actual`.
pub fn compute_fee_target(
    target_atto_usd_per_l2_gas: u128,
    strk_usd_rate: u128,
) -> Option<GasPrice> {
    if strk_usd_rate == 0 {
        return None;
    }
    // floor_fri = target_atto_usd_per_l2_gas * 10^18 / strk_usd_rate
    let numerator = U256::from(target_atto_usd_per_l2_gas) * U256::from(FRI_DECIMALS_SCALE);
    let floor = numerator / U256::from(strk_usd_rate);
    Some(GasPrice(u128::try_from(floor).unwrap_or(u128::MAX)))
}
```
