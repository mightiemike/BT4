### Title
Unbounded `VotesStore` full-table scan in `countVote()` allows anonymous vote-spam DoS of consensus maintenance and public witness-list RPC - (File: consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java)

### Summary
`VotesStore` is a single shared key-value store where every account that casts a `VoteWitnessContract` gets one entry keyed by its address. Two code paths perform an **unbounded full iteration** of this store: `MaintenanceManager.doMaintenance()` → `countVote()`, which every full node must execute at every DPoS maintenance boundary, and `Wallet.getPaginatedNowWitnessList()` → `countVote()`, which is invoked synchronously on **every anonymous HTTP/gRPC request** to `getPaginatedNowWitnessList`. Because voting only requires freezing a minimal amount of TRX (as little as the resource needed to satisfy `voteCount * TRX_PRECISION <= tronPower`, i.e. 1 TRX per vote), an attacker can create a very large number of low-cost accounts/votes to blow up `VotesStore` size, then either wait for the next maintenance cycle (forcing every node, including consensus block-production, to iterate the huge store) or directly hammer the public `getPaginatedNowWitnessList` API to force repeated full-store scans on demand — a stronger and directly RPC-triggerable version of the same "unbounded shared queue processed every round" bug class described in the report.

### Finding Description
`VoteWitnessActuator.countVoteAccount` (and the TVM-equivalent `VoteWitnessProcessor.execute`) puts one `VotesCapsule` per unique voter address into `VotesStore`, keyed by the voter's address: [1](#0-0) 

There is no cap on the *number of distinct addresses* that can populate `VotesStore` — only `MAX_VOTE_NUMBER` bounds votes *within a single* transaction: [2](#0-1) 

Every DPoS maintenance cycle, `MaintenanceManager.doMaintenance()` calls `countVote(votesStore)`, which does a full iterator scan over the entire `VotesStore`, deleting every entry as it goes: [3](#0-2) [4](#0-3) 

`doMaintenance()` is invoked synchronously from `applyBlock()`, which runs on the block-application critical path of every full node/witness whenever a block crosses the next maintenance timestamp: [5](#0-4) 

Separately, and more directly attacker-triggerable, `Wallet.getPaginatedNowWitnessList` performs the **same unbounded full scan of `VotesStore`** on every call, without deleting entries, meaning an attacker can repeatedly invoke this call to force repeated O(N) scans where N is attacker-controlled: [6](#0-5) [7](#0-6) 

This endpoint is exposed over HTTP with no per-request cost or bound other than a generic rate limiter: [8](#0-7) 

The cost to the attacker to grow `VotesStore` is only account-creation fees plus freezing minimal TRX per account/vote — `VoteWitnessProcessor` only checks `sum * TRX_PRECISION <= tronPower`, with no floor other than `voteCount > 0`: [9](#0-8) 

This mirrors the reported bug class precisely: a single store/queue shared across all participants, populated cheaply by an attacker, and fully iterated on a routine, unavoidable, protocol-driven cadence (maintenance) — plus, in java-tron's case, also reachable synchronously from an anonymous RPC call, which is an even stronger primitive than the original Sherlock relayer-DoS.

### Impact Explanation
- **Consensus-path DoS**: `doMaintenance()` runs inline in `applyBlock()` on every full node and every witness at each maintenance boundary (roughly every few hours by default). A sufficiently large `VotesStore` (tens/hundreds of thousands of entries, each with nested `Vote` protobuf lists) will materially slow down or stall block production/maintenance processing across the network at the same wall-clock instant for every node, which is a synchronized, network-wide DoS window rather than a single relayer's problem.
- **RPC DoS**: `getPaginatedNowWitnessList` lets any anonymous client force repeated full scans of the same bloated store on demand, without waiting for the maintenance cycle, amplifying the attack and allowing a sustained node-level resource-exhaustion DoS against public API nodes.
- No funds are directly stolen, but block-production delays / node unavailability at a genuinely low attacker cost qualify as a DoS via the RPC-API/protocol implementation per the acceptance criteria.

### Likelihood Explanation
Feasibility depends on the actual minimum cost to cast one vote (freezing 1 TRX-equivalent bandwidth/energy per account plus TRX for account activation) times the number of distinct addresses needed to make the scan expensive. This is directly analogous to the original report where the auditor (3xHarry) disputed practical feasibility due to non-trivial per-entry cost (`minRequiredDeposit` there vs. minimal freeze + account-activation fee here). I was not able to fully confirm within the available context whether java-tron enforces any minimum frozen-balance floor beyond `voteCount > 0` (I found references to "must be positive" checks in `FreezeBalanceProcessor`/`FreezeBalanceV2Processor` but did not get to inspect their exact numeric thresholds before this session ended), so the exact economic cost-per-entry — and therefore whether this is cheap enough to be practically exploitable at scale — remains unverified and should be checked directly in a follow-up session.

### Recommendation
- Bound `VotesStore` iteration cost: track vote-count deltas incrementally as votes are cast (rather than re-scanning the entire store every maintenance cycle and on every `getPaginatedNowWitnessList` call), or shard/paginate the scan across multiple blocks.
- Enforce a meaningful minimum frozen balance / vote weight before an address is allowed to create a `VotesStore` entry, and/or cap the total number of distinct voter entries retained between maintenance cycles.
- For `Wallet.getPaginatedNowWitnessList`, avoid a full unbounded scan per request — cache the computed vote-count deltas for the current epoch and invalidate/refresh the cache only when new votes are cast, rather than recomputing from scratch on every anonymous API call.

### Proof of Concept
Conceptual (not executed, given ask-only/reachability constraints):
1. Attacker creates N new accounts (activation fee + minimal TRX per account).
2. For each account, freeze the minimum resource needed to satisfy `voteCount(=1) * TRX_PRECISION <= tronPower`, then broadcast a `VoteWitnessContract` transaction voting for any valid witness — this inserts one entry into `VotesStore` per account via `VoteWitnessActuator.countVoteAccount` / `VoteWitnessProcessor.execute`.
3a. **Consensus path**: Wait for the next maintenance timestamp; every full node/witness executes `MaintenanceManager.doMaintenance()` → `countVote()`, iterating all N entries in `VotesStore` inline with block application, at the same time on every node.
3b. **RPC path**: Repeatedly call the public `/wallet/getpaginatednowwitnesslist` HTTP endpoint (or gRPC equivalent); each call triggers `Wallet.getPaginatedNowWitnessList` → `countVote()`, a full O(N) scan of `VotesStore`, letting the attacker force unbounded CPU work on any full node serving this API without further cost per call.

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }

  public WitnessList getPaginatedNowWitnessList(long offset, long limit) throws
      MaintenanceUnavailableException {
    if (limit <= 0 || offset < 0) {
      return null;
    }
    if (limit > WITNESS_COUNT_LIMIT_MAX) {
      limit = WITNESS_COUNT_LIMIT_MAX;
    }

    /*
      In the maintenance period, the VoteStores will be cleared.
      To avoid the race condition of VoteStores deleted but Witness vote counts not updated,
      return retry error.
      Only apply to requests that rely on the latest block,
      which means the normal fullnode requests with HEAD cursor.
    */
    boolean isMaintenance = chainBaseManager.getDynamicPropertiesStore().getStateFlag() == 1;
    if (isMaintenance && !Args.getInstance().isSolidityNode() && getCursor() == Cursor.HEAD) {
      String message =
          "Service temporarily unavailable during maintenance period. Please try again later.";
      throw new MaintenanceUnavailableException(message);
    }
    // It contains the final vote count at the end of the last epoch.
    List<WitnessCapsule> witnessCapsuleList = chainBaseManager.getWitnessStore().getAllWitnesses();
    if (offset >= witnessCapsuleList.size()) {
      return null;
    }

    VotesStore votesStore = chainBaseManager.getVotesStore();
    // Count the vote changes for each witness in the current epoch, it is maybe negative.
    Map<ByteString, Long> countWitness = countVote(votesStore);

    // Iterate through the witness list to apply vote changes and calculate the real-time vote count
    witnessCapsuleList.forEach(witnessCapsule -> {
      long voteCount = countWitness.getOrDefault(witnessCapsule.getAddress(), 0L);
      witnessCapsule.setVoteCount(witnessCapsule.getVoteCount() + voteCount);
    });

    // Use the same sorting logic as in the Maintenance period
    WitnessStore.sortWitnesses(witnessCapsuleList,
        chainBaseManager.getDynamicPropertiesStore().allowWitnessSortOptimization());

    List<WitnessCapsule> sortedWitnessList = witnessCapsuleList.stream()
        .skip(offset)
        .limit(limit)
        .collect(Collectors.toList());

    WitnessList.Builder builder = WitnessList.newBuilder();
    sortedWitnessList.forEach(witnessCapsule ->
        builder.addWitnesses(witnessCapsule.getInstance()));

    return builder.build();
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }

@Component
@Slf4j(topic = "API")
public class GetPaginatedNowWitnessListServlet extends RateLimiterServlet {

  @Autowired
  private Wallet wallet;

  protected void doGet(HttpServletRequest request, HttpServletResponse response) {
    try {
      boolean visible = Util.getVisible(request);
      long offset = Long.parseLong(request.getParameter("offset"));
      long limit = Long.parseLong(request.getParameter("limit"));
      fillResponse(offset, limit, visible, response);
    } catch (Exception e) {
      Util.processError(e, response);
    }
  }

  protected void doPost(HttpServletRequest request, HttpServletResponse response) {
    try {
      PostParams params = PostParams.getPostParams(request);
      GrpcAPI.PaginatedMessage.Builder build = GrpcAPI.PaginatedMessage.newBuilder();
      JsonFormat.merge(params.getParams(), build, params.isVisible());
      fillResponse(build.getOffset(), build.getLimit(), params.isVisible(), response);
    } catch (Exception e) {
      Util.processError(e, response);
    }
  }

  private void fillResponse(long offset, long limit, boolean visible, HttpServletResponse response)
      throws IOException, MaintenanceUnavailableException {
    GrpcAPI.WitnessList reply = wallet.getPaginatedNowWitnessList(offset, limit);
    if (reply != null) {
      response.getWriter().println(JsonFormat.printToString(reply, visible));
    } else {
      response.getWriter().println("{}");
    }
  }
