### Title
Unvalidated `RevertInstructions.FundRecipient` / `Sender` addresses can route reverted/re-minted PRC20 funds to `address(0)`, causing permanent loss - (File: `x/uexecutor/keeper/build_revert_outbound.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The external report describes a Staking contract that sends fees to an uninitialized `protocolFeeAddress`, defaulting to `address(0)` and permanently burning value with no setter to fix it. The scoped Push Chain analog is structurally similar: recipient addresses used for revert/re-mint flows (`recipient := inbound.Sender` / `outbound.Sender`, optionally overridden by `RevertInstructions.FundRecipient`) are converted with `common.HexToAddress(recipient)` without first validating that the string is a well-formed hex address, unlike `OutboundTx.ValidateBasic`, which does call `utils.IsValidAddress(p.Sender, utils.HEX)` [1](#0-0) . `Inbound.ValidateBasic`, by contrast, only checks that `Sender` is non-empty, never that it is a valid address [2](#0-1) , and `ValidateForExecution` never validates `RevertInstructions.FundRecipient` format at all [3](#0-2) .

### Finding Description
When an inbound fails validation or execution, `buildRevertOutbound` computes the refund recipient as `inbound.Sender`, optionally overridden by `inbound.RevertInstructions.FundRecipient` if non-empty — with no format check on either value: [4](#0-3) 

Similarly, when an outbound observation reports failure, `handleFailedOutbound` re-mints the bridged PRC20 tokens back to `outbound.Sender` or `outbound.RevertInstructions.FundRecipient` and passes it straight into `common.HexToAddress(recipient)` for `CallPRC20Deposit`: [5](#0-4) 

`applyGasRefund` follows the identical pattern for excess-gas refunds: [6](#0-5) 

If `Sender` or `FundRecipient` is not a syntactically valid hex address (e.g., malformed, truncated, or containing invalid characters), `common.HexToAddress` in go-ethereum decodes it permissively rather than erroring, which can resolve to the zero address for malformed input. Any resulting `CallPRC20Deposit` / `CallUniversalCoreRefundUnusedGas` call would then mint PRC20 tokens or refund gas to `address(0)`, permanently and unrecoverably losing user or protocol-controlled funds — the same root-cause class as the reported Staking bug (value sent to an unchecked/uninitialized-equivalent zero address with no recovery path).

### Impact Explanation
If reachable, this is a permanent loss of user funds: bridged assets that should have been refunded to the depositor are instead minted to `address(0)`, an address no one controls. This fits the in-scope "permanent loss ... of user or protocol-controlled funds" category and the "Registry and accounting path ... revert instructions must not misroute value" pivot.

### Likelihood Explanation
Likelihood is uncertain and could not be conclusively established in this pass. It hinges on two unverified facts:
1. Whether `RevertInstructions.FundRecipient` (and any of the `Sender` fields populated from source-chain events) is decoded from attacker-influenceable calldata without upstream hex validation in `universalClient/chains/evm/event_parser.go`, `universalClient/chains/push/event_parser.go`, or `universalClient/chains/svm/event_parser.go` (not inspected due to iteration limit).
2. Whether Go's `common.HexToAddress` on malformed strings actually degrades to `address(0)` versus some other deterministic (but still wrong) address, and whether there's an intermediate validation step in the `MsgVoteInbound`/`MsgVoteOutbound` handlers that I did not locate that would reject malformed addresses before they reach `buildRevertOutbound` / `handleFailedOutbound`.

### Recommendation
- Add explicit hex-address validation (mirroring `OutboundTx.ValidateBasic`'s `utils.IsValidAddress(..., utils.HEX)` check) to `Inbound.ValidateBasic`/`ValidateForExecution` for `Sender` and to any decode path that populates `RevertInstructions.FundRecipient`.
- In `buildRevertOutbound` and `handleFailedOutbound`/`applyGasRefund`, reject (or fall back safely, e.g., to a known-good recorded sender) any recipient string that fails `utils.IsValidAddress` before calling `common.HexToAddress`, rather than silently converting to a potentially zero/garbage address.
- Add an explicit guard rejecting `common.Address{}` (zero address) as a mint/refund/deposit target in `CallPRC20Deposit` and `CallUniversalCoreRefundUnusedGas` call sites, analogous to the recommended `if protocolFeeAddress_ == address(0)) revert` pattern in the original report.

### Proof of Concept
Not fully constructible without confirming the upstream decode path. Conceptually: an attacker deposits on a source chain via the gateway, supplying a `RevertInstructions.FundRecipient` value that is not a well-formed 20-byte hex address (e.g., malformed/short bytes) in the gateway event payload that `universalClient` decodes into `Inbound.RevertInstructions`. If validators observe and vote this inbound, and execution subsequently fails validation (e.g., unsupported token, zero-amount rejection for `FUNDS` type as shown in `test/integration/uexecutor/inbound_zero_amount_test.go:464-500`), `buildRevertOutbound` uses the malformed `FundRecipient` unchecked, and the resulting `INBOUND_REVERT` outbound would deposit reverted PRC20 tokens to `common.HexToAddress(FundRecipient)` — potentially `address(0)` — with no subsequent recovery mechanism found in the reviewed code paths.

func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}
