## Title
Division-before-multiplication truncation in `CalculateGasCost` can zero out gas fees once the base fee drops below 1 upc - (File: `x/uexecutor/keeper/fees.go`)

### Summary
The `calculateArchNeededForLeverage()` bug is a classic "divide-then-multiply" rounding defect: performing integer division before multiplication truncates the fractional remainder, silently under-charging the caller (and, in edge cases, charging nothing at all). The exact same operation order exists in `Keeper.CalculateGasCost` in `x/uexecutor/keeper/fees.go`, which is the function used to compute how much `upc` gas fee must be deducted (and burned) from a smart-account recipient after a `DerivedEVMCall`/`executeUniversalTx` execution.

### Finding Description
`CalculateGasCost` takes `baseFee sdkmath.LegacyDec` (18-decimal fixed point) and unwraps it to a whole-`upc` integer **before** multiplying by `gasUsed`: [1](#0-0) 

```go
baseFeeBig := baseFee.BigInt()
// ... comment asserts baseFee is always a whole number of upc ...
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
```

Only after this integer division does the code multiply by `gasUsed`: [2](#0-1) 

This is the same "divide first, then multiply" pattern flagged in the external report. The comment on line 54-56 asserts the invariant that `baseFee` is always a whole number of `upc` (no fractional part), which is why the developers believed unwrapping via division was safe. That invariant is **not enforced in code** — it depends entirely on `FeeMarketKeeper.GetBaseFee` (the standard cosmos-evm feemarket base-fee adjustment algorithm) never producing a value below `1e18` (i.e., below 1 whole `upc`). The `FeeMarketKeeper` interface used here only guarantees a `LegacyDec` return value, with no lower-bound check: [3](#0-2) 

If network gas usage stays below target for a sustained period, the standard EIP-1559-style feemarket reduces `BaseFee` by a percentage each block. Because this decay is exponential/multiplicative, the base fee can pass below `1.0` `upc` (while still being a valid positive `LegacyDec`) purely from ordinary, unprivileged usage of the chain (i.e., simply not spamming the EVM). Once `baseFee < 1e18` in the internal `LegacyDec` representation, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates to `0`, making `effectiveGasPrice = 0` and therefore `gasCost = effectiveGasPrice * gasUsed = 0` — regardless of how much gas was actually consumed.

This feeds directly into `DeductGasFeesFromReceipt`, which is invoked after `DerivedEVMCall`/payload execution to charge the recipient for gas consumed: [4](#0-3) 

When `gasCost.Sign() <= 0`, the function returns `nil` without deducting or burning anything, silently skipping fee collection: [5](#0-4) 

### Impact Explanation
An unprivileged user who triggers universal-execution EVM calls (e.g. via `MsgExecutePayload`/CEA `executeUniversalTx`) during a period when the network base fee has decayed under 1 `upc` gets **all** EVM gas execution for free, no matter how much gas is actually used. This corrupts the gas-fee accounting invariant ("gas cost must scale with gas used") and can be leveraged to force unbounded, unpaid EVM execution work onto validators — a resource/DoS vector reachable purely by ordinary use (staying below target gas usage lets base fee decay), not by any privileged or malicious-validator behavior.

### Likelihood Explanation
This requires the base fee to organically decay below `1 upc`, which depends on network parameters (decay rate, floor/min base fee configuration) and sustained low utilization. It is not instantly or arbitrarily triggerable by an attacker, but it is a reachable state under the feemarket's normal, unprivileged operation, similar in class/likelihood to the original report's rated 3/10 likelihood.

### Recommendation
Reorder the arithmetic to multiply before dividing, matching the correct EIP-1559 fee formula: compute `gasCost = baseFee.BigInt() (full 18-decimal precision) * gasUsed`, then divide by `1e18` once, at the end — mirroring the `Mul` → `Div` pattern already correctly used elsewhere in the codebase for slippage calculations (e.g. `minPCOut := quote.Mul(95); minPCOut.Div(100)` in `x/uexecutor/keeper/evm.go` and `execute_inbound_gas.go`). Additionally, consider enforcing/asserting a minimum base fee floor (e.g., 1 `upc`) at the feemarket parameter level so `effectiveGasPrice` can never round down to zero.

### Proof of Concept
1. Let network `BaseFee` decay (via ordinary low utilization) to `0.9` `upc`, i.e. `baseFee.BigInt() = 9 * 10^17`.
2. Call `CalculateGasCost(baseFee, maxFeePerGas, maxPriorityFeePerGas, gasUsed)` with any `gasUsed > 0`.
3. `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` → `9*10^17 / 10^18 = 0` (integer truncation).
4. `gasCost = 0 * gasUsed = 0`.
5. `DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns `nil` without deducting or burning any `upc`, even though the EVM call consumed real gas resources.

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```
