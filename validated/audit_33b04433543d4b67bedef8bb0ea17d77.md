### Title
Blocking `acquire()` in `GlobalPreemptibleStrategy` allows a bounded gRPC thread-pool exhaustion by an unprivileged caller when `apiNonBlocking=false` - ([File: framework/src/main/java/org/tron/core/services/ratelimiter/strategy/GlobalPreemptibleStrategy.java])

### Summary
When `rate.limiter.apiNonBlocking` is `false` (the documented default), `RateLimiterInterceptor.interceptCall` calls `acquirePermit()`, which for a `GlobalPreemptibleAdapter`-protected RPC method resolves to `GlobalPreemptibleStrategy.acquire()`, blocking the calling thread on `sp.tryAcquire(2, TimeUnit.SECONDS)` [1](#0-0) . Because gRPC handler dispatch happens on the shared server `executorService` (or gRPC's shared default executor if `rpcThreadNum` is not configured), an attacker opening `permit+K` concurrent connections to that single endpoint can tie up `K` worker threads for up to 2 seconds each, and repeating this continuously can starve the shared thread pool used by all other RPC methods on the same server instance.

### Finding Description
`RateLimiterInterceptor.interceptCall` looks up the per-method `IRateLimiter` for the invoked gRPC method and calls `rateLimiter.acquirePermit(runtimeData)` before allowing `next.startCall()` to proceed [2](#0-1) . `acquirePermit()` (default method on `IRateLimiter`) dispatches to `tryAcquire()` if `Args.getInstance().isRateLimiterApiNonBlocking()` is true, or to `acquire()` otherwise [3](#0-2) . The default/documented value of `apiNonBlocking` is `false` [4](#0-3) [5](#0-4) .

For a `GlobalPreemptibleAdapter`-configured endpoint, `acquire()` delegates to `GlobalPreemptibleStrategy.acquire()`, which blocks the calling thread on `sp.tryAcquire(DEFAULT_ACQUIRE_TIMEOUT, TimeUnit.SECONDS)` for up to 2 seconds [6](#0-5) [7](#0-6) . This call happens synchronously inside `interceptCall`, which itself runs on the gRPC call-handling thread, i.e., on the server's request executor (either the configured `ExecutorServiceManager.newFixedThreadPool` if `rpcThreadNum > 0`, or gRPC/Netty's own shared default executor) [8](#0-7) . Requests beyond the configured `permit` count for that endpoint each occupy one worker thread for up to 2 seconds while waiting for the semaphore, instead of being rejected immediately (the rejection-on-overload path only exists in `tryAcquire()`, gated by the non-blocking mode) [9](#0-8) .

This is not stopped by any auth/accounting mechanism — `GlobalPreemptibleAdapter` endpoints are typically public read RPCs (e.g., `GetBlockByLatestNum2` in the example config) reachable by any unauthenticated client [10](#0-9) . There is no per-IP cap on how many concurrent connections/streams a single attacker can open against a preemptible endpoint from the rate limiter itself (the per-IP QPS limiter is a separate, unrelated strategy).

### Impact Explanation
If the server is configured with a bounded thread pool (`rpcThreadNum > 0`) or relies on gRPC's default bounded executor, an attacker who opens `permit + K` concurrent calls to a single `GlobalPreemptibleAdapter`-protected method can occupy `K` worker threads for ~2 seconds per wave, repeatable indefinitely. If `K` approaches or exceeds the pool size, this degrades or blocks processing of unrelated RPC methods sharing the same executor/server, producing node-wide RPC latency/availability degradation. This is a resource-exhaustion / DoS class impact scoped to the shared gRPC/Netty worker pool, not memory corruption or fund loss.

### Likelihood Explanation
Preconditions: `rate.limiter.apiNonBlocking = false` (default/shipped config) and at least one method configured with `GlobalPreemptibleAdapter` and a small permit count (default configs commented out, but reference config's example is `permit=1`) [11](#0-10) . By default the `rpc` list in `config.conf` is empty, meaning no method actually uses `GlobalPreemptibleAdapter` out of the box [12](#0-11) . This significantly reduces likelihood on a stock deployment — the vulnerability is only reachable if an operator explicitly enables `GlobalPreemptibleAdapter` for a public RPC method while leaving `apiNonBlocking` at its default `false`. Given that, the attack is trivial and fully repeatable by an unprivileged network client with no special access, and the design comment in the same file explicitly documents the intended mitigation (non-blocking mode) is a config toggle rather than the default behavior.

### Recommendation
- Make the blocking `acquire()` path bound the total number of threads that can be parked waiting on the semaphore (e.g., cap concurrent waiters, or use a bounded queue ahead of the semaphore) so a burst cannot consume more than a fixed number of executor threads.
- Consider making non-blocking (`tryAcquire`) the default (`apiNonBlocking = true`) for public RPC-facing rate limiters, or enforce it specifically for `GlobalPreemptibleAdapter`, since blocking on a shared request-handling thread is inherently unsafe when threads are a shared, finite resource.
- Alternatively, perform the `acquire()` wait asynchronously (e.g., via a separate bounded scheduler) rather than blocking the calling gRPC dispatch thread, freeing the worker thread while waiting for a permit.
- Add a per-IP or global concurrent-connection cap independent of the per-endpoint semaphore to prevent a single attacker from opening arbitrarily many concurrent streams.

### Proof of Concept
```java
// Integration test sketch (extends existing RateLimiterInterceptorTest style)
@Test
public void testBlockingModeExhaustsExecutorUnderBurst() throws Exception {
  // Configure apiNonBlocking = false (default) and register a
  // GlobalPreemptibleAdapter with permit=1 for METHOD_NAME.
  GlobalPreemptibleAdapter limiter = new GlobalPreemptibleAdapter("permit=1");
  container.add(KEY_RPC, METHOD_NAME, limiter);

  ExecutorService bounded = Executors.newFixedThreadPool(4); // simulate small rpc thread pool
  int burst = 10; // permit(1) + K(9) concurrent callers
  CountDownLatch started = new CountDownLatch(burst);
  CountDownLatch release = new CountDownLatch(1);

  // First caller holds the only permit for the whole test.
  limiter.acquirePermit(runtimeData);

  long start = System.nanoTime();
  List<Future<?>> futures = new ArrayList<>();
  for (int i = 0; i < burst; i++) {
    futures.add(bounded.submit(() -> {
      started.countDown();
      // Each of these blocks up to DEFAULT_ACQUIRE_TIMEOUT (2s) inside acquire().
      limiter.acquirePermit(runtimeData);
    }));
  }

  // Assert: with only 4 threads and 9 blocking waiters each occupying a thread
  // for ~2s, the bounded pool cannot make progress on unrelated tasks submitted
  // concurrently -> measure a control task's latency spikes during this window.
  Future<Long> controlTaskLatency = bounded.submit(() -> {
    long t0 = System.nanoTime();
    // no-op work representing an unrelated RPC method sharing the pool
    return System.nanoTime() - t0;
  });

  // Expected: controlTaskLatency observed queue delay approaches/exceeds
  // DEFAULT_ACQUIRE_TIMEOUT seconds because all pool threads are parked in acquire().
  assertTrue(controlTaskLatency.get(5, TimeUnit.SECONDS) > TimeUnit.SECONDS.toNanos(1));
}
```
Expected assertion: the unrelated control task's execution is delayed on the order of `DEFAULT_ACQUIRE_TIMEOUT` seconds because all bounded-pool threads are parked inside `GlobalPreemptibleStrategy.acquire()`, demonstrating executor starvation caused by the blocking wait.

  public static final int DEFAULT_ACQUIRE_TIMEOUT = 2;
  private Semaphore sp;

  public GlobalPreemptibleStrategy(String paramString) {
    super(paramString);
    sp = new Semaphore((Integer) mapParams.get(STRATEGY_PARAM_PERMIT).value);
  }

  // define the default strategy params.
  @Override
  protected Map<String, ParamItem> defaultParam() {
    Map<String, ParamItem> map = new HashMap<>();
    map.put(STRATEGY_PARAM_PERMIT, new ParamItem(Integer.class, DEFAULT_PERMIT_NUM));
    return map;
  }

  // Non-blocking: immediately rejects if no permit is available. Used when the
  // apiNonBlocking switch is on, to shed overload instead of tying up Netty IO /
  // gRPC executor threads while waiting for a permit.
  public boolean tryAcquire() {
    return sp.tryAcquire();
  }

  public boolean acquire() {
    try {
      return sp.tryAcquire(DEFAULT_ACQUIRE_TIMEOUT, TimeUnit.SECONDS);
    } catch (InterruptedException e) {
      // Restore the interrupt flag and reject — caller must not release a permit
      // it never acquired.
      logger.error("acquire permit with error: {}", e.getMessage());
      Thread.currentThread().interrupt();
      return false;
    }
  }
