### Title
Same-block Uniswap V3 spot-quote manipulation lets an attacker drain value from `x/uexecutor`'s auto-swap and gas-refund flows - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The external report's core lesson is that letting two components price the *same* value from *independently-updatable* sources (two oracles with different heartbeat/threshold behavior) creates a redemption/arbitrage window that leaks value. Push Chain's analog is not two Chainlink-style oracles, but a single **manipulable, same-block AMM spot price** used both to produce a swap quote and to derive that swap's own slippage floor. Because the floor is computed from the same manipulated number instead of an independent, tamper-resistant reference, the safety check is self-referential and provides no real protection.

### Finding Description
`x/uexecutor` performs on-chain PRC20↔native swaps in two places, both driven by `UniversalCore`'s Uniswap V3 `QuoterV2`:

- **Inbound auto-swap** (`GAS`/`GAS_AND_PAYLOAD` routes) — per the upgrade log, the module now "call[s] the Uniswap V3 QuoterV2 contract to obtain an on-chain swap quote and pass `minPCOut` (quote × 95%) to `CallPRC20DepositAutoSwap`" [1](#0-0) .
- **Outbound gas refund** — `applyGasRefund` fetches a quote via `getSwapQuoteForRefund` and computes `minPCOut = quote * 95 / 100`, then calls `CallUniversalCoreRefundUnusedGas` with that floor [2](#0-1) .

`getSwapQuoteForRefund` resolves the quoter and WPC addresses and calls `GetSwapQuote`, which is a direct, un-TWAP'd `QuoterV2` spot-price read [3](#0-2) .

Both of these operations execute synchronously inside `DerivedEVMCall`s triggered deterministically by an honest UV's `MsgVoteInbound` / `MsgVoteOutbound` message (i.e., inside a normal block, in the same EVM state as any earlier transaction in that block) [4](#0-3) . Because the quote is read and consumed in the same block, an unprivileged attacker who can predict or trigger the timing of an inbound/outbound vote finalization (e.g., by submitting their own bridging transaction, or simply front-running a UV's vote transaction in the mempool with a large swap against the same Uniswap V3 pool) can:

1. Push the pool's spot price in the desired direction with a large trade.
2. Let the module's quote call read this manipulated price and compute `minPCOut` from it (95% of the *already-skewed* quote — not an independent, honest reference price).
3. The protocol's swap then executes at the skewed price and clears the self-referential floor trivially, since the floor was derived from the same skew.
4. Reverse the initial trade after the module's swap lands, capturing the price-impact spread as profit extracted from the protocol's WPC/PRC20 liquidity/treasury.

This is the direct functional analog of the reported bug class: instead of "old oracle vs. new oracle" price divergence enabling redemption arbitrage, Push Chain's own swap-quote/slippage-check pairing has zero independence between the "price used to size the trade" and the "price used to bound the trade," so an attacker-controlled AMM price at execution time silently becomes the accepted ground truth.

### Impact Explanation
Successful manipulation lets an unprivileged attacker extract value from the protocol's on-chain liquidity during either:
- inbound `GAS`/`GAS_AND_PAYLOAD` auto-swap deposits (`CallPRC20DepositAutoSwap`), or
- outbound gas-refund swaps (`CallUniversalCoreRefundUnusedGas` with `withSwap=true`),

corrupting PRC20/native gas-token accounting and draining protocol-held WPC/native value beyond what honest pricing would allow. This falls squarely within the "corruption of PRC20 or native asset accounting" and "stealing/draining... of protocol-controlled funds" impact categories, reachable by an ordinary user submitting deposits/withdrawals without any privileged role.

### Likelihood Explanation
Likelihood depends on the depth/liquidity of the specific Uniswap V3 pool used for a given `gasToken`/WPC pair and on the attacker's ability to control transaction ordering within the block where the UV's vote lands (achievable via mempool front-running or, on chains/relayers without strict ordering guarantees, by timing their own bridge transaction). Both swap paths use only a fixed 5% slippage tolerance with no TWAP or external price cross-check, so any pool with moderate depth relative to the swap size is exploitable. This is more concrete/practically exploitable than the disputed original C4 finding, since it does not require an admin-triggered "protocol upgrade" precondition — it exists in the steady-state code path today.

### Recommendation
- Replace the single QuoterV2 spot read with a manipulation-resistant reference (TWAP over N blocks, or a Chainlink/median oracle) for computing `minPCOut`, independent from the value being swapped.
- If a spot quote must be used, bound the acceptable spot price against a separate reference price (not solely a percentage of itself) before allowing the swap to execute.
- Consider adding a maximum swap size relative to on-chain pool liquidity, or executing swaps via a private/no-front-running path, to reduce the sandwich-attack surface for module-originated `DerivedEVMCall`s.

### Proof of Concept
1. Identify a Uniswap V3 pool used as the `gasToken`/WPC pair with moderate liquidity for a route reachable via inbound `GAS_AND_PAYLOAD` deposit or an outbound needing a gas refund.
2. Submit a large swap against that pool immediately before triggering (or front-running) the UV vote transaction that will cause `x/uexecutor` to call `getSwapQuoteForRefund`/`GetSwapQuote` and then `CallUniversalCoreRefundUnusedGas` / `CallPRC20DepositAutoSwap` [2](#0-1) .
3. Because `minPCOut` is derived from the same skewed quote (`quote * 95 / 100`), the module's swap clears against the manipulated price.
4. Reverse the initial trade in a subsequent transaction in the same or next block, realizing the price-impact spread as profit at the protocol's expense.

Note: I was not able to fully trace `x/uexecutor/keeper/execute_inbound_gas.go` and `evm.go`'s exact `minPCOut`/quote wiring line-by-line due to index/tool-call limits reached before completing that read; the citations above for the inbound auto-swap path are based on the upgrade changelog description rather than the raw function body, so the exact line numbers for that specific call site should be verified directly in the repository (or via a Devin session with full file access) before treating this as fully confirmed for that code path. The outbound refund path (`outbound.go`) is fully verified from source.

func (k Keeper) getSwapQuoteForRefund(ctx sdk.Context, gasToken common.Address, fee *big.Int, amount *big.Int) (*big.Int, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(ctx)
	if err != nil {
		return nil, err
	}
	wpcAddr, err := k.GetUniversalCoreWPCAddress(ctx)
	if err != nil {
		return nil, err
	}
	return k.GetSwapQuote(ctx, quoterAddr, gasToken, wpcAddr, fee, amount)

## EVM Integration

`x/uexecutor` is unusual in that it issues EVM calls as a Cosmos module. On fresh genesis (`Exported=false`) it deploys the **UEA factory** contract.
