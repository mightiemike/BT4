### Title
Missing declared-class validation in Starknet OS `replace_class` syscall enables blockifier/SNOS execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS (SNOS) implementation of the `replace_class` syscall updates `contract_state_changes` with an attacker-supplied `class_hash` without verifying that a compiled class is actually declared for that hash, unlike the Blockifier's Rust implementation of the same syscall, which explicitly performs this check before mutating state.

### Finding Description
The `replace_class` syscall lets a contract change its own class hash. Any unprivileged account/contract can trigger it directly via an `INVOKE` transaction that calls a contract exposing `replace_class_syscall`.

In the Blockifier (the component the sequencer actually uses to execute transactions and decide success/revert/fee), the syscall handler explicitly validates that the target class hash corresponds to a declared, compiled class before mutating state: [1](#0-0) 

The same validation is exercised by the blockifier's tests, which confirm that supplying an undeclared class hash causes the entry point call — and hence the encompassing transaction — to fail with an "is not declared" error: [2](#0-1) [3](#0-2) 

However, the Cairo implementation of the identical syscall inside the Starknet OS (used for re-execution/proof generation of the very same block) omits this check entirely. It is explicitly marked with an unresolved TODO: [4](#0-3) 

The same gap exists in the deprecated syscall path used for Cairo0 contracts: [5](#0-4) 

I was not able to find any additional validation elsewhere in the OS pipeline (e.g., during class-tree squashing/commitment in `state.cairo`, or during output emission) that rejects a `contract_state_changes` entry pointing to a `class_hash` with no corresponding entry in `contract_class_changes`/declared classes. The `state_update` function in `state.cairo` only squashes and commits whatever class hash values are present in the dict — it does not cross-check that the class hash was actually declared: [6](#0-5) 
Given the size limits on the indexed codebase, I could not exhaustively verify every file in `crates/apollo_starknet_os_program` (e.g., hint implementations backing `%{ GetContractAddressStateEntry %}`), so it is possible additional validation exists outside the indexed/retrieved excerpts. A full audit with direct repository access is recommended to close this gap with certainty.

### Impact Explanation
This is a soundness/consistency bug between the two independent implementations of the same state-transition rule: the Blockifier (which the sequencer uses to build blocks and decide transaction success/failure/state diffs) and the Starknet OS (whose Cairo program is executed and proven to attest that the block's state transition is correct, per Starknet's Validity Rollup design). 

Because the Blockifier already rejects `replace_class` calls to undeclared class hashes (causing the enclosing transaction/call to fail/revert before the block is even built), the state diff committed by the sequencer never contains such invalid class replacements — so in the currently-implemented flow, the buggy SNOS code path may never legitimately be exercised with a genuinely-undeclared hash for an already-accepted block. The exposure is therefore latent divergence risk: if any code path exists (now or introduced later) where the OS re-executes a transaction independently of the blockifier's pre-check (e.g., alternate execution engine, replay, or future feature relying on this Cairo function without the equivalent Rust-side gate), the OS would silently accept and commit a `class_hash` for which no compiled class exists. This yields either (a) a wrong committed class-tree/global root relative to what a compliant Blockifier would produce, or (b) an unprovable/incorrect state that could be used to justify an unauthorized account action (a contract claiming to run bytecode that was never declared/verified), undermining the correctness guarantee the SNOS proof is supposed to provide.

### Likelihood Explanation
Likelihood of triggering observable damage today is low-to-medium, since the primary defense (Blockifier's `get_compiled_class` check) is intact and gates the current production execution path. The vulnerability is a genuine code-level divergence/soundness gap (confirmed by an explicit unresolved `TODO` in the source) rather than a theoretical concern, and it directly parallels the reported bug class: a privileged-looking operation (mutating a contract's class assignment, which is enforced with strict checks in one trusted component) is reachable and unguarded in a second component that is implicitly trusted to enforce the same invariant.

### Recommendation
Add the same "class must be declared" validation to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring the Blockifier's `get_compiled_class`/`is not declared` check, before writing the new `class_hash` into `contract_state_changes`. Resolve the outstanding `TODO(Yoni, 1/1/2026)` comment and add an SNOS-side regression test analogous to `replace_class.rs`'s `undeclared_class_hash` test to lock in behavioral parity between the Blockifier and the Starknet OS.

### Proof of Concept
1. Deploy a contract exposing a Cairo `replace_class_syscall(class_hash)` entry point (as in `fuzz_revert_2.cairo`'s `Scenario::ReplaceClass` handler). [7](#0-6) 
2. Submit an `INVOKE` transaction calling this entry point with an arbitrary, never-declared `class_hash`.
3. Under the Blockifier, this call fails with "... is not declared", as shown by the existing test `undeclared_class_hash`. [8](#0-7) 
4. Inspect the corresponding Cairo implementation `execute_replace_class` in `syscall_impls.cairo`: it performs no equivalent lookup/assertion before writing `new_state_entry` with the unchecked `class_hash` into `contract_state_changes`, confirming the divergent, unguarded code path exists in the OS/proving pipeline. [9](#0-8)

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
