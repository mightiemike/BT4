### Title
Algorithmic-complexity DoS in app-proxy HMAC pre-check via duplicate query-parameter string concatenation - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
`normalizeQuery` merges repeated query-parameter values by repeated string concatenation (`normalizedQuery[key] = \`${existingValue},${value}\``) inside a loop over every entry of an attacker-supplied `URLSearchParams` object, before the HMAC signature is checked, so an anonymous requester can force large, expensive string-building work at negligible cost to themselves.

### Finding Description
`validateHmac` (`packages/apps/shopify-api/lib/utils/hmac-validator.ts:84-116`) calls `normalizeQuery(query, signator)` unconditionally, prior to any HMAC/signature comparison. When `query` is a `URLSearchParams` instance, `normalizeQuery` (lines 118-151) iterates over `query.entries()` and, for any key not in `APP_PROXY_SINGLE_VALUE_PARAMS` (`hmac`, `shop`, `signature`, `timestamp`), repeatedly appends new values onto a growing string: [1](#0-0) 
Because JS strings are immutable, each `normalizedQuery[key] = \`${existingValue},${value}\`` allocates and copies a new string of increasing length. For `N` repeated query-parameter occurrences under one key, this becomes an O(N²) time/memory operation, executed entirely before the constant-time `safeCompare` and before the invalid signature is rejected.

This is directly reachable from an anonymous HTTP request to the app-proxy endpoint. `authenticateAppProxyFactory` builds `searchParams` from the raw, un-sanitized request URL and passes it straight into `api.utils.validateHmac`: [2](#0-1) 
An attacker does not need a valid HMAC, a merchant session, or any prior authentication — they only need to hit the app's app-proxy route (`/apps/<subpath>`) with a crafted query string containing a very large number of repeated, non-reserved parameter names (e.g., `?a=1&a=2&a=3...` repeated hundreds of thousands of times), which browsers/servers/CDNs and this library's own parsing do not bound.

The `normalizeQuery` path is only exercised through the `URLSearchParams` branch; the OAuth callback path (`packages/apps/shopify-api/lib/auth/oauth/oauth.ts:178`) builds `authQuery` via `Object.fromEntries(query.entries())`, which collapses duplicates before `validateHmac` is called, so that path is not affected the same way. The app-proxy authenticate flow is the reachable, unprivileged trigger.

### Impact Explanation
This is a targeted denial-of-service against the request-authentication handler for app-proxy routes, directly analogous to the Besu report's "expensive operation performed as part of verifying an untrusted request before rejecting it" bug class: cheap attacker input forces disproportionately expensive server-side work in a code path that must run for every incoming request, prior to the actual cryptographic check that would reject it. A single crafted request with a very large duplicate-parameter query string can consume significant CPU/memory on the Node.js event loop, potentially blocking or slowing down processing of legitimate requests handled by the same process (Node.js is single-threaded for JS execution), and can be repeated cheaply by an attacker to sustain the effect.

### Likelihood Explanation
The app-proxy endpoint is intentionally public/unauthenticated by design (Shopify calls it on behalf of storefront visitors, and it's also reachable directly by any anonymous internet client since app proxy URLs are just regular HTTP endpoints on the app's server). No merchant, session, or valid signature is required to reach `validateAppProxyHmac`/`normalizeQuery`; the query string is fully attacker-controlled. The only constraint is however the hosting platform/reverse proxy limits URL/query length, which determines the practically achievable `N` and thus the severity, but no protection exists at the shopify-app-js layer itself (no cap on parameter count before the O(N²) merge occurs).

### Recommendation
- In `normalizeQuery` (`packages/apps/shopify-api/lib/utils/hmac-validator.ts`), avoid O(N²) string concatenation: collect repeated values into an array first and `Array.prototype.join(',')` once per key, or track counts and only build final strings once.
- Add an early bound on the number of query parameters (and/or a maximum length) processed by `normalizeQuery`/`validateAppProxyHmac`, rejecting oversized requests before any parsing/merging work is performed.
- Consider performing a cheap sanity check on `URLSearchParams` size (e.g., `Array.from(query.keys()).length`) at the very start of `validateHmac`, throwing `InvalidHmacError` immediately if it exceeds a sane threshold, mirroring how `timestamp`/`hmac` presence is checked early.

### Proof of Concept
1. Deploy a shopify-app-remix (or shopify-app-express) app configured with an app-proxy route.
2. Send an unauthenticated HTTP GET to the app-proxy path with a query string containing a very large number of repeated occurrences of a single non-reserved parameter, e.g.:
   `GET /apps/proxy?shop=x.myshopify.com&timestamp=123&signature=bogus&a=1&a=2&a=3...&a=200000`
3. Observe `authenticateAppProxyFactory` → `validateAppProxyHmac` → `api.utils.validateHmac(searchParams, {signator:'appProxy'})` → `normalizeQuery` spend disproportionate CPU time building the concatenated `a` value via repeated string copies, before ultimately failing the (bogus) signature check — demonstrating that cost is incurred pre-authentication, scaling quadratically with attacker-controlled repetition count. function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}
