### Title
Meta-transaction `meta_tx_v0` syscall bypasses `__validate__` signature check, letting any contract invoke another account's `__execute__` directly - (File: crates/blockifier/src/execution/syscalls/syscall_base.rs)

### Summary
The `meta_tx_v0` syscall lets any executing contract invoke the `__execute__` entry point of an arbitrary target contract address while spoofing the caller as the zero/"OS" address, without ever calling the target's `__validate__`. Because the canonical Starknet account pattern authorizes `__execute__` purely by checking `caller_address == 0` (trusting that this can only happen after the OS ran `__validate__`), any contract can reach and execute another account's `__execute__` logic while completely skipping signature verification.

### Finding Description
`SyscallHandlerBase::meta_tx_v0` in [1](#0-0)  builds a `CallEntryPoint` targeting an attacker-supplied `contract_address`, forcing `entry_point_selector` to be `__execute__`, and sets `caller_address: ContractAddress::default()` (the zero address) — the same value the OS uses when it calls a real account's `__execute__` after `__validate__` has succeeded. The corresponding Starknet OS implementation mirrors this: `execute_meta_tx_v0` in [2](#0-1)  only requires `selector == EXECUTE_ENTRY_POINT_SELECTOR` and sets `caller_address=ORIGIN_ADDRESS` unconditionally for any `contract_address` supplied by the caller — there is no check that the target contract opted in to meta-transactions, nor is `__validate__` invoked on the target.

The standard/canonical account templates authorize `__execute__` solely via this caller check, e.g. `account_with_real_validate.cairo`: [3](#0-2) 
Signature verification only happens inside `__validate__` (`validate_transaction`), never inside `__execute__`: [4](#0-3) 

Since `meta_tx_v0` never calls `__validate__` on the target and satisfies the target's only authorization gate (`caller_address == 0`), any contract that is itself invoked via a transaction can call `meta_tx_v0_syscall` naming an arbitrary already-deployed account as `contract_address`, and its `__execute__` will run with attacker-chosen calldata as if it were a fully-validated transaction from that account — without possessing the account's private key or producing a valid signature.

### Impact Explanation
This directly enables unauthorized account action: an attacker-controlled contract can trigger execution of the victim account's `__execute__` (e.g., asset transfers, approvals) on the victim's behalf, bypassing the cryptographic authorization (`__validate__`) that the entire account-abstraction security model relies on. This matches "unauthorized account action" impact and can lead to concrete loss of funds for any deployed account whose `__execute__` implementation follows the canonical `caller_address == 0` authorization pattern (the standard/most widely deployed account pattern), since it was never designed with awareness that `meta_tx_v0` could reach it with a spoofed zero caller.

### Likelihood Explanation
Reachable from a single ordinary INVOKE transaction: an attacker deploys/uses any contract that calls the `meta_tx_v0` syscall (available in `Execute` mode, rejected only in `Validate` mode per `self.reject_syscall_in_validate_mode` in [5](#0-4) ), naming any target account address and empty/dummy calldata/signature. No special privileges, keys, or victim cooperation are required.

### Recommendation
Restrict `meta_tx_v0` targets to contracts that explicitly opt in to meta-transaction handling (e.g., via an interface/entry-point capability check, or a dedicated `__execute_meta_tx__`-style entry point rather than reusing `__execute__`), or require the target to still run its own `__validate__` (with the substituted meta-tx signature/hash) before `__execute__` is invoked, so that plain accounts relying on `caller_address == 0` for authorization are not silently exposed.

### Proof of Concept
1. Attacker deploys/controls contract `A` exposing a function that calls `meta_tx_v0_syscall(address=victim_account, entry_point_selector=EXECUTE_ENTRY_POINT_SELECTOR, calldata=<attacker calls>, signature=<anything>)`, as demonstrated by the test helper `execute_meta_tx_v0` in [6](#0-5) .
2. Attacker submits an ordinary INVOKE transaction (signed with attacker's own key) that calls `A`, which internally invokes the syscall against `victim_account` (a standard account using the `caller_address==0` `__execute__` gate).
3. `meta_tx_v0` sets `caller_address = ContractAddress::default()` per [7](#0-6) , satisfying `victim_account.__execute__`'s sole check, and the attacker-supplied calldata executes as `victim_account` without `victim_account.__validate__` ever running or checking a real signature.

// * The signature is replaced with the given signature.
// * The caller is the OS (address 0).
// * The transaction version is replaced by 0.
// * The transaction hash is replaced by the corresponding version-0 transaction hash.
// The changes apply to the called contract and the inner contracts it calls.
func execute_meta_tx_v0{
    range_check_ptr,
    syscall_ptr: felt*,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    revert_log: RevertLogEntry*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, caller_execution_context: ExecutionContext*) {
    alloc_locals;

    let request = cast(syscall_ptr + RequestHeader.SIZE, MetaTxV0Request*);
    local calldata_start: felt* = request.calldata_start;
    local calldata_size = request.calldata_end - calldata_start;

    let specific_base_gas_cost = (
        META_TX_V0_GAS_COST + META_TX_V0_CALLDATA_FACTOR_GAS_COST * calldata_size
    );
    let (success, remaining_gas) = reduce_syscall_base_gas(
        specific_base_gas_cost=specific_base_gas_cost, request_struct_size=MetaTxV0Request.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    local contract_address = request.contract_address;
    local selector = request.selector;
    local caller_execution_info: ExecutionInfo* = caller_execution_context.execution_info;
    local old_tx_info: TxInfo* = caller_execution_info.tx_info;

    if (selector != EXECUTE_ENTRY_POINT_SELECTOR) {
        write_failure_response(remaining_gas=remaining_gas, failure_felt=ERROR_INVALID_ARGUMENT);
        return ();
    }

    // Sanity check: Verify that `signature` is a valid Sierra array.
    assert_nn_le(request.signature_end - request.signature_start, SIERRA_ARRAY_LEN_BOUND - 1);

        key=contract_address
    );

    // Compute the meta-transaction hash.
    let pedersen_ptr = builtin_ptrs.selectable.pedersen;
    with pedersen_ptr {
        let meta_tx_hash = compute_meta_tx_v0_hash(
            contract_address=contract_address,
            entry_point_selector=selector,
            calldata=calldata_start,
            calldata_size=calldata_size,
            chain_id=old_tx_info.chain_id,
        );

    update_pedersen_in_builtin_ptrs(pedersen_ptr=pedersen_ptr);

        account_contract_address=contract_address,
        max_fee=0,

        signature_end=request.signature_end,

        chain_id=old_tx_info.chain_id,
        nonce=0,
        resource_bounds_start=cast(0, ResourceBounds*),
        resource_bounds_end=cast(0, ResourceBounds*),

        account_deployment_data_end=cast(0, felt*),
        proof_facts_start=cast(0, felt*),
        proof_facts_end=cast(0, felt*),
    );
