### Title
Unbounded full `VotesStore` iteration in `Wallet.getPaginatedNowWitnessList()` allows CPU-exhaustion DoS via anonymous RPC/HTTP - (File: `framework/src/main/java/org/tron/core/Wallet.java`)

### Summary
The public, unauthenticated `getPaginatedNowWitnessList` HTTP/gRPC endpoint claims to be "paginated" via `offset`/`limit`, but before applying pagination it unconditionally iterates the **entire** `VotesStore` to recompute real-time vote deltas. This full-store scan cost is completely decoupled from the requested page size, so an attacker can force the node to repeatedly perform an O(n) computation (n = number of distinct voters in the current epoch) on every single request, at negligible cost to themselves, mirroring the `ResetClearLoopSubsystem.clearLoop()` pattern of looping over an entire unbounded collection in one execution unit.

### Finding Description
`Wallet.getPaginatedNowWitnessList(offset, limit)` clamps `limit` to `WITNESS_COUNT_LIMIT_MAX`, but that only bounds the *output* size, not the work performed to produce it. Internally it always calls `countVote(votesStore)`, which iterates every entry of `chainBaseManager.getVotesStore()` via `votesStore.iterator()` and, for each entry, iterates that voter's full `oldVotes`/`newVotes` lists, before any pagination/limit/offset is applied: [1](#0-0) [2](#0-1) 

This is analogous to the reported `clearLoop()` issue: the store being iterated (`VotesStore`) grows with the number of distinct accounts that cast votes during the current maintenance epoch — a value fully controlled by public, unprivileged users through ordinary `VoteWitnessContract` transactions (each account that votes creates/updates an entry). There is no cap on the number of `VotesStore` entries processed per call, unlike the vote count itself which is capped by `MAX_VOTE_NUMBER` at the per-transaction level: [3](#0-2) 

The endpoint is exposed with no authentication, only wrapped in a generic rate limiter, via `GetPaginatedNowWitnessListServlet`: [4](#0-3) 
and the equivalent gRPC method in `RpcApiService`/`RpcApiServiceOnSolidity`, as well as the Solidity-node HTTP mirrors.

### Impact Explanation
Each incoming request forces the node to fully walk the current epoch's `VotesStore`, an amount of work that scales with real, attacker-influenceable chain state (total distinct voters this cycle) rather than with the requester-specified `limit`. Sending a burst of such requests (within/around the rate limiter's allowance, or from multiple source IPs) causes disproportionate CPU/DB-iteration load on the node relative to the cost paid by the caller, degrading availability of the HTTP/gRPC API service — a DoS vector reachable purely via anonymous RPC.

### Likelihood Explanation
Likelihood is Low/Moderate: it requires the `VotesStore` to contain a non-trivial number of entries (achievable by seeding many low-cost votes from many accounts, or simply during periods of active voting on the live network), and repeated calls to a rate-limited but still-anonymous endpoint. No privileged access or special conditions are needed.

### Recommendation
Restructure `getPaginatedNowWitnessList`/`countVote` so the vote-delta computation is bounded by, or incremental with, the requested page, or cache/pre-aggregate the epoch's vote deltas once (e.g., recomputed lazily and reused) instead of re-scanning the entire `VotesStore` on every API call. Alternatively, cap or reject requests when the store size exceeds a safe processing bound, and/or move this computation off the request hot-path.

### Proof of Concept
1. Have N distinct accounts (N large) each submit a `VoteWitnessContract` transaction during the current maintenance epoch, populating `VotesStore` with N entries.
2. Call `GET /walletsolidity/getpaginatednowwitnesslist?offset=0&limit=1` (or the gRPC equivalent) repeatedly.
3. Observe that despite `limit=1`, each call performs a full O(N) iteration over `VotesStore` inside `countVote()` [2](#0-1) , so response latency and node CPU usage scale with N and are unaffected by the small requested page size, allowing repeated cheap requests to degrade node responsiveness.

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }

@Component
@Slf4j(topic = "API")
public class GetPaginatedNowWitnessListServlet extends RateLimiterServlet {

  @Autowired
  private Wallet wallet;

  protected void doGet(HttpServletRequest request, HttpServletResponse response) {
    try {
      boolean visible = Util.getVisible(request);
      long offset = Long.parseLong(request.getParameter("offset"));
      long limit = Long.parseLong(request.getParameter("limit"));
      fillResponse(offset, limit, visible, response);
    } catch (Exception e) {
      Util.processError(e, response);
    }
  }

  protected void doPost(HttpServletRequest request, HttpServletResponse response) {
    try {
      PostParams params = PostParams.getPostParams(request);
      GrpcAPI.PaginatedMessage.Builder build = GrpcAPI.PaginatedMessage.newBuilder();
      JsonFormat.merge(params.getParams(), build, params.isVisible());
      fillResponse(build.getOffset(), build.getLimit(), params.isVisible(), response);
    } catch (Exception e) {
      Util.processError(e, response);
    }
  }

  private void fillResponse(long offset, long limit, boolean visible, HttpServletResponse response)
      throws IOException, MaintenanceUnavailableException {
    GrpcAPI.WitnessList reply = wallet.getPaginatedNowWitnessList(offset, limit);
    if (reply != null) {
      response.getWriter().println(JsonFormat.printToString(reply, visible));
    } else {
      response.getWriter().println("{}");
    }
  }
