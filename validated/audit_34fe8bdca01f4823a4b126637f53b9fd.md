Based on my investigation, I found a genuine gap, but I could not fully confirm the exploit chain end-to-end due to iteration limits, so I'll report what is verified and flag what remains unconfirmed.

### Title
`set_state_to_end_of_evm_block_by_block_id` skips the pruned-height check on the `BlockId::Hash` branch, letting hash-tagged queries read state below the prune horizon - (File: `crates/evm/src/query.rs`)

### Summary
`set_state_to_end_of_evm_block_by_block_id` calls `self.check_if_l2_block_pruned(num, working_set)?` only in the `BlockId::Number` branch before calling `set_state_to_end_of_evm_block`, but the `BlockId::Hash` branch resolves the block number via `get_block_number_by_block_hash` and calls `set_state_to_end_of_evm_block::<C>(block_num, working_set)` directly, with no pruned-height guard. [1](#0-0)  Additionally, `get_call_inner` and the `debug_traceCall` handler resolve `block_id` (Number or Hash) and invoke `set_state_to_end_of_evm_block::<C>(block_num, working_set)` for any non-Pending/Latest tag without ever calling `check_if_l2_block_pruned`. [2](#0-1) [3](#0-2) 

### Finding Description
The intended binding is: `query_root(block_tag) == provable_root(block_tag)` for every accepted `block_tag`, enforced by rejecting any `block_number <= last_pruned_l2_height` via `check_if_l2_block_pruned`: [4](#0-3) 

`set_state_to_end_of_evm_block` itself performs no bounds checking — it unconditionally repoints the working set's archival version: [5](#0-4) 

For `eth_getTransactionCount` / `eth_getCode`, the number path is guarded (`num` is checked before use), but the hash path is not:
```
Some(BlockId::Hash(block_hash)) => self
    .get_block_number_by_block_hash(block_hash.block_hash, working_set)
    .ok_or_else(|| EthApiError::UnknownBlockOrTxIndex)?,
};
set_state_to_end_of_evm_block::<C>(block_num, working_set);
``` [6](#0-5) 

Similarly, `get_call_inner` (backing `eth_call`/`eth_estimateGas` style flows, and taking attacker-supplied `state_overrides`/`block_overrides`) resolves a `BlockId::Hash` to a number and calls `set_state_to_end_of_evm_block` for any non-Pending/Latest tag, with no call to `check_if_l2_block_pruned` anywhere in this function: [7](#0-6)  The same pattern recurs in the `debug_traceCall` handler. [8](#0-7) 

`estimate_tx_expenses` (backing `eth_estimateGas`/`eth_estimateDiffSize`, referenced via `EstimatedTxExpenses`) resolves a concrete block via `get_sealed_block_by_number` and calls `set_state_to_end_of_evm_block` for any block number that isn't `None`/`Pending`/`Latest`, again without any pruned-height check: [9](#0-8) 

Root cause: `check_if_l2_block_pruned` is a helper defined once but only wired into one of several code paths that ultimately call `set_state_to_end_of_evm_block`. The other call sites (`get_call_inner`, `debug_traceCall`, `estimate_tx_expenses`, and the `BlockId::Hash` arm of `set_state_to_end_of_evm_block_by_block_id`) do not perform this check before repointing the archival version.

An unprivileged attacker (per the given entrypoint) writes a slot in some block N, waits for the node's pruner to run (pruner runs automatically based on `PruningConfig.distance`) — verified pruner code prunes ledger, state, and native DBs concurrently to the same `up_to_block` [10](#0-9)  — and then issues `eth_call`/`debug_traceCall` with `block_id = BlockId::Hash(hash_of_block_N)` (or `BlockId::Number(N)` for `eth_call`/`eth_estimateGas`/`eth_estimateDiffSize`), optionally with `state_overrides`/`block_overrides` layered on top.

**What I could not fully verify** given the remaining iteration budget: whether `get_sealed_block_by_number` (used to fetch the header before `set_state_to_end_of_evm_block` in `get_call_inner`/`debug_traceCall`/`estimate_tx_expenses`) itself already fails for a pruned block, because native DB block/header data is pruned at the same `up_to_block` as state DB data — which would turn this into an early `HeaderNotFound` error rather than a silent read of unprovable state. I found the native pruning logic in `crates/storage-ops/src/pruning/native.rs` (deleting `E/blocks/e*`, `E/receipts/e*`, `E/transactions/e*` keys by version), but did not get to fully trace whether `get_sealed_block_by_number` reads from a table that survives pruning (e.g., a separate accessory-state vector indexed differently), nor whether `self.block_hashes` (used by `get_block_number_by_block_hash`) is subject to the same generic single-version-key pruning logic that appeared to preserve unique, never-rewritten keys indefinitely. If `get_sealed_block_by_number`/`get_block_number_by_block_hash` return stale-but-resolvable data after the corresponding state has been pruned, the missing `check_if_l2_block_pruned` call in these paths would let `set_state_to_end_of_evm_block` point the working set at a pruned archival version, and the subsequent JMT/state read behavior at that version (explicit error vs. silently wrong/default value) is what determines whether this is exploitable as "serving state contradicting the proved chain" versus merely a benign internal error.

### Impact Explanation
If the untraced piece confirms that header/hash lookups survive pruning while state does not, and JMT reads at a pruned archival version silently return incorrect data instead of erroring, this would let any RPC-facing node serve `eth_call`/`eth_estimateGas`/`eth_getCode`/`eth_getTransactionCount` results at a root the node can no longer prove — directly the "High: an honest node persisting or serving state contradicting the proved chain" category, since consumers (bridges, exchanges, Clementine operators) making read-only calls against a supposedly-valid historical block hash would receive results that don't correspond to any provable state. Without confirming the JMT-read behavior at pruned versions, I cannot state with certainty that this manifests as silently wrong data rather than a clean error/panic, which would make it a non-issue (or at most a DB-hygiene issue, out of scope per the rules).

### Likelihood Explanation
Preconditions: pruning must be enabled (`PruningConfig` present) and enough blocks must pass for the pruner to fire (`current_block >= last_pruned_block + 2*distance`). The attacker needs only to have written a slot at some historical block and later query it by hash or number after that block falls below the prune horizon — no privileged role required, no BTC fee beyond ordinary L2 transaction cost. This is repeatable indefinitely across blocks as pruning continues to advance, provided the missing-check code paths are reachable and the underlying read does not already fail earlier for reasons I couldn't verify in this pass.

### Recommendation
Insert the same `self.check_if_l2_block_pruned(block_num, working_set)?` guard immediately before every remaining call to `set_state_to_end_of_evm_block` that currently lacks it: the `BlockId::Hash` arm in `set_state_to_end_of_evm_block_by_block_id`, `get_call_inner`, the `debug_traceCall` handler, and `estimate_tx_expenses`. Ideally, refactor so `set_state_to_end_of_evm_block` itself takes the check as a mandatory precondition (or wraps it internally and returns `Result`), so no future call site can bypass it.

4. Assert the two sides of the equality:
   - Side A (provable root): `working_set.get_last_pruned_l2_height()` shows `K` is pruned, and `eth_getBalance`/`eth_getTransactionCount` by `BlockId::Number(K)` return `EthApiError`/`ProviderError::StateAtBlockPruned`.

5. If (b) is observed, additionally dump `working_set`'s archival version reads during the call to show it resolved to version `K+1`, a version the node's pruner has already discarded from state DB, confirming the query executed against unprovable state.

    /// Returns `ProviderError::StateAtBlockPruned` if the state at the given block number is pruned
    fn check_if_l2_block_pruned(
        &self,
        block_number: u64,
        working_set: &mut WorkingSet<C::Storage>,
    ) -> Result<(), ProviderError> {
        if let Some(last_pruned_l2_height) = working_set
            .get_last_pruned_l2_height()
            .expect("Failed to get last pruned l2 height")
        {
            if block_number == 0 {
                // Genesis block is never pruned
                return Ok(());
            } else if block_number <= last_pruned_l2_height {
                return Err(ProviderError::StateAtBlockPruned(block_number));
            }
        }
        Ok(())
    }

    /// Prune everything
    pub async fn prune(
        &self,
        node_type: NodeType,
        up_to_block: u64,
        shutdown_signal: Option<GracefulShutdown>,
    ) -> anyhow::Result<()> {
        let ledger_db = self.ledger_db.clone();
        let native_db = self.native_db.clone();
        let state_db = self.state_db.clone();

        let ledger_shutdown_signal = shutdown_signal.clone();
        let ledger_pruning_handle = tokio::task::spawn_blocking(move || {
            prune_ledger_db(
                node_type,
                ledger_db,
                up_to_block,
                ledger_shutdown_signal.as_ref(),
            )
        });

        let state_shutdown_signal = shutdown_signal.clone();
        let state_db_pruning_handle = tokio::task::spawn_blocking(move || {
            prune_state_db(state_db, up_to_block, state_shutdown_signal.as_ref())
        });

        let native_shutdown_signal = shutdown_signal.clone();
        let native_db_pruning_handle = tokio::task::spawn_blocking(move || {
            prune_native_db(native_db, up_to_block, native_shutdown_signal.as_ref())
        });

        let [ledger_result, state_result, native_result] = future::join_all([
            ledger_pruning_handle,
            state_db_pruning_handle,
            native_db_pruning_handle,
        ])
        .await
        .try_into()
        .expect("join_all returned unexpected number of results");

        check_pruning_result(ledger_result, "ledger")?;
        check_pruning_result(state_result, "state")?;
        check_pruning_result(native_result, "native")?;

        self.store_last_pruned_l2_height(up_to_block)?;

        Ok(())
    }
