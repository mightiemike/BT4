### Title
Permissionless unbounded `WitnessCreateContract` growth causes O(N) unbounded loops in `MaintenanceManager.doMaintenance()`, `Wallet.getWitnessList()`/`getPaginatedNowWitnessList()` - (File: consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java)

### Summary
The analog bug class from the ECG `SurplusGuildMinter.getReward()` report (unbounded loop over a permissionlessly-growable collection) maps onto java-tron's witness registry. `WitnessCreateActuator.validate()` places no cap on the total number of witnesses that can ever be created — the only checks are address validity, URL validity, non-existing witness, and sufficient balance for `AccountUpgradeCost`.

### Finding Description
`WitnessCreateActuator.validate()` never checks a total witness-count ceiling before allowing `createWitness()` to insert a brand-new `WitnessCapsule` into `witnessStore`: [1](#0-0) 

Any unprivileged account holding enough balance to pay `AccountUpgradeCost` can create a new, distinct witness address, and nothing prevents repeating this indefinitely from different addresses (a script can generate unlimited fresh addresses, fund each with the upgrade cost, and issue one `WitnessCreateContract` per address). This grows `WitnessStore` without bound, analogous to `GuildToken.setMaxGauges()`/`addGauge()` growing the gauge set without bound in the original report.

Several consensus- and query-critical code paths then iterate the *entire* witness set on every maintenance cycle (every block-producing node, every cycle) or every API/RPC call:

- `MaintenanceManager.doMaintenance()` calls `consensusDelegate.getAllWitnesses()` three separate times per maintenance cycle, each producing a full `O(N)` iteration over every witness ever created (accumulating VI, rebuilding the candidate address list, and updating brokerage/vote snapshots): [2](#0-1) 
- `WitnessStore.getAllWitnesses()` performs a full DB scan with no pagination: [3](#0-2) 
- `Wallet.getWitnessList()` and `Wallet.getPaginatedNowWitnessList()` both call `getAllWitnesses()` and then `sortWitnesses()` on the full list even though only a page is returned: [4](#0-3) 

Maintenance-cycle processing is performed synchronously by **every node** as part of block processing at the maintenance boundary (it is not an isolated, opt-in user transaction like `SurplusGuildMinter.getReward()`), so an unbounded witness count degrades or stalls this critical path network-wide rather than merely reverting a single user's transaction.

### Impact Explanation
If witness count grows very large, `doMaintenance()` becomes increasingly expensive and is executed by all full nodes/SRs at every maintenance interval, directly on the block-processing critical path. This can cause maintenance-cycle block production time to increase, potentially causing missed slots or de-synchronization across nodes if execution time exceeds block-time budgets — an availability/liveness risk (analogous to, but network-wide in scope compared to, the original single-account DoS). Public read APIs (`getWitnessList`, `getPaginatedNowWitnessList`) also become progressively slower/heavier for every caller, which is a resource-exhaustion vector for full-node operators serving external API queries.

### Likelihood Explanation
Likelihood is constrained by the economic cost of `AccountUpgradeCost` (paid per witness registration), which raises the bar compared to the original C4 finding (which required no comparable per-item cost, only voting quorum via `LendingTermOnboarding`). This makes mass creation of tens of thousands of witnesses expensive but not impossible for a well-funded attacker or over a long accumulation period, and there is currently no explicit upper bound enforced in code — unlike `MAX_VOTE_NUMBER` which caps per-account vote list size to 30 in `VoteWitnessActuator`/`VoteWitnessProcessor`. Given TRX's typical `AccountUpgradeCost` value, this is a lower-likelihood but not theoretical scenario; no mitigating cap exists in the validated code path to fall back on if the cost parameter is ever lowered via governance (`ProposalCreate` type-controllable dynamic parameters commonly adjust such costs).

### Recommendation
Add an explicit, governance-controlled maximum total witness count check in `WitnessCreateActuator.validate()` (e.g., reject if `witnessStore.getAllWitnesses().size() >= MAX_WITNESS_COUNT` or maintain a counter in `DynamicPropertiesStore`), mirroring the existing `MAX_VOTE_NUMBER`/`MAX_ACTIVE_WITNESS_NUM` bounding pattern already used for votes and active witness selection. Additionally, consider decoupling `doMaintenance()`'s per-cycle bookkeeping from linear scans over the *entire* witness store (e.g., only iterate witnesses that changed, or maintain incremental VI/brokerage bookkeeping) to remove the latent O(N) cost even if the count grows.

### Proof of Concept
Conceptual reproduction (not executed, requires the ability to fund N distinct addresses with `AccountUpgradeCost` each):
1. Generate N fresh addresses; fund each with `AccountUpgradeCost` TRX via transfer.
2. For each address, broadcast a `WitnessCreateContract` (unique URL per address) — `WitnessCreateActuator.validate()` places no ceiling on total registered witnesses beyond per-address uniqueness and balance.
3. Repeat until N is in the tens of thousands.
4. At the next maintenance cycle, `MaintenanceManager.doMaintenance()` performs 3 full `O(N)` scans over `witnessStore` (`consensusDelegate.getAllWitnesses()` calls), and any client calling `Wallet.getWitnessList()`/`getPaginatedNowWitnessList()` also triggers a full-table scan and sort — degrading maintenance-cycle and query-API performance proportionally to N, with no code-enforced upper bound to prevent this from growing indefinitely.

Note: I was unable to confirm the exact numeric value of `AccountUpgradeCost` in this deployment/config from the indexed context, so the precise economic cost threshold for this attack (i.e., how large N can practically get) is uncertain; this would need to be verified against `DynamicPropertiesStore.getAccountUpgradeCost()`'s default/config value in a full checkout.

  public void doMaintenance() {
    VotesStore votesStore = consensusDelegate.getVotesStore();

    tryRemoveThePowerOfTheGr();

    DynamicPropertiesStore dynamicPropertiesStore = consensusDelegate.getDynamicPropertiesStore();
    DelegationStore delegationStore = consensusDelegate.getDelegationStore();
    if (dynamicPropertiesStore.useNewRewardAlgorithm()) {
      long curCycle = dynamicPropertiesStore.getCurrentCycleNumber();
      consensusDelegate.getAllWitnesses().forEach(witness -> {
        delegationStore.accumulateWitnessVi(curCycle, witness.createDbKey(), witness.getVoteCount());
      });
    }

    Map<ByteString, Long> countWitness = countVote(votesStore);
    if (!countWitness.isEmpty()) {
      List<ByteString> currentWits = consensusDelegate.getActiveWitnesses();

      List<ByteString> newWitnessAddressList = new ArrayList<>();
      consensusDelegate.getAllWitnesses()
          .forEach(witnessCapsule -> newWitnessAddressList.add(witnessCapsule.getAddress()));

      countWitness.forEach((address, voteCount) -> {
        byte[] witnessAddress = address.toByteArray();
        WitnessCapsule witnessCapsule = consensusDelegate.getWitness(witnessAddress);
        if (witnessCapsule == null) {
          logger.warn("Witness capsule is null. address is {}", Hex.toHexString(witnessAddress));
          return;
        }
        AccountCapsule account = consensusDelegate.getAccount(witnessAddress);
        if (account == null) {
          logger.warn("Witness account is null. address is {}", Hex.toHexString(witnessAddress));
          return;
        }
        witnessCapsule.setVoteCount(witnessCapsule.getVoteCount() + voteCount);
        consensusDelegate.saveWitness(witnessCapsule);
        logger.info("address is {} , countVote is {}", witnessCapsule.createReadableString(),
            witnessCapsule.getVoteCount());
      });

      dposService.updateWitness(newWitnessAddressList);

      incentiveManager.reward(newWitnessAddressList);

      List<ByteString> newWits = consensusDelegate.getActiveWitnesses();
      if (!CollectionUtils.isEqualCollection(currentWits, newWits)) {
        currentWits.forEach(address -> {
          WitnessCapsule witnessCapsule = consensusDelegate.getWitness(address.toByteArray());
          witnessCapsule.setIsJobs(false);
          consensusDelegate.saveWitness(witnessCapsule);
        });
        newWits.forEach(address -> {
          WitnessCapsule witnessCapsule = consensusDelegate.getWitness(address.toByteArray());
          witnessCapsule.setIsJobs(true);
          consensusDelegate.saveWitness(witnessCapsule);
        });

        SRMetrics.recordSrSetChange(currentWits, newWits);
      }

      logger.info("Update witness success. \nbefore: {} \nafter: {}",
          getAddressStringList(currentWits),
          getAddressStringList(newWits));
    }

    if (dynamicPropertiesStore.allowChangeDelegation()) {
      long nextCycle = dynamicPropertiesStore.getCurrentCycleNumber() + 1;
      dynamicPropertiesStore.saveCurrentCycleNumber(nextCycle);
      consensusDelegate.getAllWitnesses().forEach(witness -> {
        delegationStore.setBrokerage(nextCycle, witness.createDbKey(),
            delegationStore.getBrokerage(witness.createDbKey()));
        delegationStore.setWitnessVote(nextCycle, witness.createDbKey(), witness.getVoteCount());
      });
    }
  }

  public WitnessList getPaginatedNowWitnessList(long offset, long limit) throws
      MaintenanceUnavailableException {
    if (limit <= 0 || offset < 0) {
      return null;
    }
    if (limit > WITNESS_COUNT_LIMIT_MAX) {
      limit = WITNESS_COUNT_LIMIT_MAX;
    }

    /*
      In the maintenance period, the VoteStores will be cleared.
      To avoid the race condition of VoteStores deleted but Witness vote counts not updated,
      return retry error.
      Only apply to requests that rely on the latest block,
      which means the normal fullnode requests with HEAD cursor.
    */
    boolean isMaintenance = chainBaseManager.getDynamicPropertiesStore().getStateFlag() == 1;
    if (isMaintenance && !Args.getInstance().isSolidityNode() && getCursor() == Cursor.HEAD) {
      String message =
          "Service temporarily unavailable during maintenance period. Please try again later.";
      throw new MaintenanceUnavailableException(message);
    }
    // It contains the final vote count at the end of the last epoch.
    List<WitnessCapsule> witnessCapsuleList = chainBaseManager.getWitnessStore().getAllWitnesses();
    if (offset >= witnessCapsuleList.size()) {
      return null;
    }

    VotesStore votesStore = chainBaseManager.getVotesStore();
    // Count the vote changes for each witness in the current epoch, it is maybe negative.
    Map<ByteString, Long> countWitness = countVote(votesStore);

    // Iterate through the witness list to apply vote changes and calculate the real-time vote count
    witnessCapsuleList.forEach(witnessCapsule -> {
      long voteCount = countWitness.getOrDefault(witnessCapsule.getAddress(), 0L);
      witnessCapsule.setVoteCount(witnessCapsule.getVoteCount() + voteCount);
    });

    // Use the same sorting logic as in the Maintenance period
    WitnessStore.sortWitnesses(witnessCapsuleList,
        chainBaseManager.getDynamicPropertiesStore().allowWitnessSortOptimization());

    List<WitnessCapsule> sortedWitnessList = witnessCapsuleList.stream()
        .skip(offset)
        .limit(limit)
        .collect(Collectors.toList());

    WitnessList.Builder builder = WitnessList.newBuilder();
    sortedWitnessList.forEach(witnessCapsule ->
        builder.addWitnesses(witnessCapsule.getInstance()));

    return builder.build();
  }
