### Title
Open redirect via unvalidated `exitIframe` query parameter in `respondToExitIframeRequest` - (File: packages/apps/shopify-app-remix/src/server/authenticate/admin/authenticate.ts)

### Summary
`respondToExitIframeRequest` reads the `exitIframe` query parameter directly from the request URL and passes it to `renderAppBridge`, which only validates the URL's protocol (http/https) and structural shape via `sanitizeRedirectUrl`, without any allow-list check against the shop's or app's own domain. This lets an unauthenticated attacker craft a link that causes the app to serve a page whose script performs `window.open(<attacker-url>, "_top")`, breaking the merchant out of the embedded iframe into an attacker-controlled site.

### Finding Description
In `authenticateAdmin`, `respondToExitIframeRequest` runs before any session-token or shop validation: [1](#0-0) 
It reads `url.searchParams.get('exitIframe')!` unsanitized and forwards it as `{url: destination}` to `renderAppBridge`, and this call happens at line 148 of `authenticateAdmin`, prior to `getSessionTokenContext` at line 160 - i.e., no session token, shop, or host validation gates this path.

`renderAppBridge` calls `sanitizeRedirectUrl(config.appUrl, redirectTo.url)` to build the redirect script: [2](#0-1) 

`sanitizeRedirectUrl`/`isSafe` only rejects file URIs, whitespace, malformed relative paths (`//`), non-http(s) protocols, and (optionally) non-SSL protocols. It does **not** check that the resulting hostname is the app's own domain, `myshopify.com`, or any allow-listed domain — `new URL(redirectUrl, domain)` will simply resolve to the attacker's absolute URL if one is supplied: [3](#0-2) 

The existing test suite confirms only protocol-based validation is exercised (`file://` is rejected, but arbitrary `https://` targets are not tested against an allow-list) and even demonstrates arbitrary external URLs (`config.appUrl`) being accepted as `exitIframe` destinations and rendered into the `window.open` script: [4](#0-3) [5](#0-4) 

Since `https://evil.example` passes `VALID_PROTOCOLS` and none of the other rejection checks, it will be rendered verbatim into `window.open("https://evil.example/", "_top")`.

### Impact Explanation
An unprivileged attacker who gets a merchant to click `{app}/exitIframe?exitIframe=https://evil.example` (or the configured `exitIframePath`) causes the merchant's browser to execute a script that performs `window.open(attacker_url, "_top")`, navigating the top-level (out-of-iframe) browsing context to an attacker-controlled site. This is a classic open redirect out of the trusted embedded-app context, which can be leveraged for phishing (e.g., a fake Shopify login page) since the URL is served from the legitimate app domain, increasing victim trust. This matches Shopify's open redirect / phishing launchpad impact class.

### Likelihood Explanation
The precondition is simply that the app is embedded (default for most apps) and the attacker can get a merchant to click a link — no secrets, no session token, no shop-validation bypass needed since this check runs before `getSessionTokenContext`. This is fully reachable by an anonymous HTTP client, is deterministic, and repeatable on every request to the exit-iframe path.

### Recommendation
Restrict `exitIframe` destinations to relative paths or to hosts within an explicit allow-list (the app's own domain and Shopify admin/myshopify domains) rather than accepting any absolute http(s) URL. `sanitizeRedirectUrl`/`isSafe` should compare the resolved URL's origin against `config.appUrl`'s origin (or a configured allow-list) and reject cross-origin absolute URLs unless explicitly permitted.

export function renderAppBridge(
  {config}: BasicParams,
  request: Request,
  redirectTo?: RedirectToOptions,
): never {
  let redirectToScript = '';
  if (redirectTo) {
    const destination = sanitizeRedirectUrl(config.appUrl, redirectTo.url);

    const target = redirectTo.target ?? '_top';

    redirectToScript = `<script>window.open(${JSON.stringify(
      destination.toString(),
    )}, ${JSON.stringify(target)})</script>`;
  }

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
