The comm advisory describes a bug where a CLI utility performs an exploratory/comparison pre-read on FIFO/pipe inputs before validating they're safe to fully consume, causing silent data loss or hangs on non-regular files. I searched protobuf-go's decode paths for an analogous "read-before-validate" invariant violation — particularly `encoding/protodelim`, which is the only API in this codebase that reads directly from an `io.Reader`/stream.

`protodelim.UnmarshalOptions.UnmarshalFrom` reads a varint size prefix via `ReadByte`, validates it against `MaxSize`, and only then reads exactly that many bytes (via `bufio.Reader.Peek`/`Discard` or `io.ReadFull`) before calling `Unmarshal` [1](#0-0) . This is the intended, self-describing size-delimited wire format contract — the function only consumes exactly what its own size prefix declares, it doesn't perform a separate "comparison pre-read" that discards or duplicates data before the real parse, and it does not read speculatively from `/dev/zero`-like infinite streams beyond the declared size. There's no equivalent to `are_files_identical` doing an unconditional full-content pre-read of two independent file paths without checking file type first.

Other stream-consuming code in this repo (`internal/cmd/pbdump/pbdump.go` reading from stdin, `internal/conformance/conformance_test.go`'s size-prefixed request loop) are internal dev/test tools, not part of a reachable unprivileged production request path, and they also follow the same "read declared size, then parse" pattern rather than draining unbounded/untyped input. No code path was found where protobuf-go silently drains a non-regular-file input stream (FIFO/pipe) before a validation or comparison step, matching the CWE-20/data-loss pattern from the report.

func (o UnmarshalOptions) UnmarshalFrom(r Reader, m proto.Message) error {
	var sizeArr [binary.MaxVarintLen64]byte
	sizeBuf := sizeArr[:0]
	for i := range sizeArr {
		b, err := r.ReadByte()
		if err != nil {
			// Immediate EOF is unexpected.
			if err == io.EOF && i != 0 {
				break
			}
			return err
		}
		sizeBuf = append(sizeBuf, b)
		if b < 0x80 {
			break
		}
	}
	size, n := protowire.ConsumeVarint(sizeBuf)
	if n < 0 {
		return protowire.ParseError(n)
	}

	maxSize := o.MaxSize
	if maxSize == 0 {
		maxSize = defaultMaxSize
	}
	if maxSize == -1 {
		// No limit specified: Just check that size fits into an integer,
		// otherwise the make([]byte, size) call below will panic.
		if size > math.MaxInt {
			return errors.Wrap(&SizeTooLargeError{Size: size, MaxSize: math.MaxInt}, "")
		}
	} else if size > uint64(maxSize) {
		return errors.Wrap(&SizeTooLargeError{Size: size, MaxSize: uint64(maxSize)}, "")
	}

	var b []byte
	var err error
	if br, ok := r.(*bufio.Reader); ok {
		// Use the []byte from the bufio.Reader instead of having to allocate one.
		// This reduces CPU usage and allocated bytes.
		b, err = br.Peek(int(size))
		if err == nil {
			defer br.Discard(int(size))
		} else {
			b = nil
		}
	}
	if b == nil {
		b = make([]byte, size)
		_, err = io.ReadFull(r, b)
	}

	if err == io.EOF {
		return io.ErrUnexpectedEOF
	}
	if err != nil {
		return err
	}
	if err := o.Unmarshal(b, m); err != nil {
		return err
	}
	return nil
