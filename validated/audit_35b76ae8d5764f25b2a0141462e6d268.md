### Title
Unprotected fixed 5% slippage tolerance on module-driven `depositPRC20WithAutoSwap` lets an unprivileged attacker sandwich cross-chain gas-abstraction and funds+payload deposits, extracting value from depositors — ([File: x/uexecutor/keeper/execute_inbound_gas.go], [File: x/uexecutor/keeper/evm.go])

### Summary
The reported TridentRouter bug is a slippage-protection failure class: routers that don't let the caller supply a real minimum-output bound either revert (M-03) or, in weaker variants, silently accept a manipulated price. Push Chain's `uexecutor` module performs the router's job on the depositor's behalf for `GAS` and `GAS_AND_PAYLOAD` inbounds: it fetches a spot quote and swaps the user's bridged `PRC20` for `WPC` using a fixed, protocol-hardcoded 5% slippage tolerance that no user can tighten, with no deadline and no TWAP protection.

### Finding Description
In `ExecuteInboundGas`, the module computes the accepted minimum output purely from an instantaneous `QuoterV2.quoteExactInputSingle` call, then immediately swaps: [1](#0-0) 

The quote (`GetSwapQuote`) is a live, spot AMM price read, not a TWAP: [2](#0-1) 

`minPCOut` is always `quote * 95 / 100`, a fixed tolerance chosen by the protocol rather than the depositor, and the swap call is made with `deadline = 0` (contract default, effectively unbounded): [3](#0-2) 

The identical pattern (fixed 5% tolerance, quote fetched immediately before swap) is reused in `gasAndPayloadDepositAutoSwap` for `GAS_AND_PAYLOAD` inbounds: [4](#0-3) 

This is invoked deterministically from `ExecuteInbound` as part of ballot finalization for every `GAS`/`GAS_AND_PAYLOAD` inbound, with no depositor-supplied slippage or minimum-output parameter anywhere in the `Inbound`/`UniversalPayload` schema: [5](#0-4) 

Because the PRC20/WPC Uniswap V3 pool is a public, permissionless pool that any unprivileged actor can trade against, an attacker can:
1. Observe (or predict, since deposits/finalizations are deterministic on 2/3+ UV votes) that a large inbound deposit is about to trigger an auto-swap.
2. Submit their own swap transaction ordered immediately before the module's `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` execution in the same block, moving the PRC20/WPC pool price down by up to just under 5%.
3. Let the module's swap execute against the manipulated price — it still passes the `minPCOut` check because the check itself is derived from the same (now-manipulated) pool state, not from any price observed before the attacker's trade.
4. Reverse the trade afterward, capturing the spread extracted from the depositor's real bridged principal.

Unlike Uniswap V2 router (`UniswapV2Router02.sol`), which lets the *caller* pass a minimum-output bound reflecting their own risk tolerance, here the tolerance is fixed protocol-wide at 5% regardless of trade size vs. pool depth, and it is computed from the *same* possibly-manipulated on-chain state used to satisfy the check — there is no external reference price (TWAP/oracle) and no user-settable protection.

### Impact Explanation
This directly reduces the value credited to depositors' `UEA` on `PC_EXECUTED` for gas-abstraction and funds+payload inbounds — a partial, unauthorized value extraction from user-controlled funds during universal execution, reachable by an ordinary unprivileged attacker with no validator, relayer, or admin privileges, and with fully honest validators/nodes. It falls within "corruption of PRC20 or native asset accounting ... unauthorized module-originated EVM execution" impact category, since the module executes a swap on the user's behalf at a price the module itself cannot verify is fair, up to a 5% haircut per deposit.

### Likelihood Explanation
Medium. The attack requires the attacker to control transaction ordering ahead of the module's `DerivedEVMCall` within the same block (or accept opportunistic execution when their own swap lands in an adjacent block before finalization), and requires sufficient capital relative to pool depth to move price meaningfully within the 5% band. It does not require any privileged role, malicious validator, or malicious relayer — any wallet holding the traded assets can attempt it, and larger/rarer inbound deposits (which move price more on quote) are the most attractive targets.

### Recommendation
- Do not derive `minPCOut` solely from a spot quote fetched in the same execution; use a TWAP-based reference price (or a bounded max staleness/deviation check against a recent observed price) so the accepted bound cannot be set by the same block's manipulated pool state.
- Consider making the slippage tolerance scale with trade size relative to pool liquidity, or expose it as a governance-tunable parameter with a conservative default, rather than a hardcoded 5% for all deposits.
- Set an explicit, bounded `deadline` on `depositPRC20WithAutoSwap`/`refundUnusedGas` calls instead of `0`.

### Proof of Concept
1. Attacker monitors the source chain / mempool for a large inbound `GAS` or `GAS_AND_PAYLOAD` transfer destined for Push Chain gas-abstraction.
2. Once the inbound is observed by UVs and about to be finalized, attacker submits a swap on the PRC20/WPC Uniswap V3 pool that moves price down by just under 5% (bounded by pool depth vs. attacker capital), ordered before the module's `ExecuteInboundGas` execution in the block.
3. `GetSwapQuote` in `x/uexecutor/keeper/evm.go` reads the now-depressed price; `minPCOut = quote*95/100` is computed from this depressed quote.
4. `CallPRC20DepositAutoSwap` executes the deposit-and-swap using the depressed `minPCOut`, crediting the user's UEA with WPC valued below the pre-attack fair price.
5. Attacker reverses their swap, netting the price-impact spread extracted from the depositor's principal, while the depositor's transaction never reverts and the loss is invisible in the `UniversalTx` record (recorded as `SUCCESS`).

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}

func (k Keeper) ExecuteInbound(ctx context.Context, utx types.UniversalTx) error {
	k.Logger().Info("execute inbound dispatched",
		"utx_key", utx.Id,
		"tx_type", utx.InboundTx.TxType.String(),
		"source_chain", utx.InboundTx.SourceChain,
		"amount", utx.InboundTx.Amount,
	)

	switch utx.InboundTx.TxType {
	case types.TxType_GAS: // fee abstraction
		return k.ExecuteInboundGas(ctx, *utx.InboundTx)

	case types.TxType_FUNDS: // synthetic
		return k.ExecuteInboundFunds(ctx, utx)

	case types.TxType_FUNDS_AND_PAYLOAD: // synthetic + payload
		return k.ExecuteInboundFundsAndPayload(ctx, utx)

	case types.TxType_GAS_AND_PAYLOAD: // fee abstraction + payload
		return k.ExecuteInboundGasAndPayload(ctx, utx)

	default:
		k.Logger().Error("unsupported inbound tx type", "utx_key", utx.Id, "tx_type", utx.InboundTx.TxType)
		return fmt.Errorf("unsupported inbound tx type: %d", utx.InboundTx.TxType)
	}
