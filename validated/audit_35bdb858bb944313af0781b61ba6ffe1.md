### Title
Bootstrap-declare bypass allows unprivileged transactions to skip validation, fees, and nonce checks - ([File: crates/blockifier/src/transaction/account_transaction.rs])

### Summary
The `AccountTransaction::execute_raw` path contains a special "bootstrap declare" branch intended only for genesis/system-bootstrapping, which is gated solely by transaction-field values (`sender_address == BOOTSTRAP`, `nonce == 0`) rather than by any execution-context privilege check, mirroring the Cooler `Roll()` pattern of an action meant for a privileged actor but guarded by conditions an ordinary caller can satisfy.

### Finding Description
`execute_raw` special-cases `Declare` transactions that satisfy `tx.is_bootstrap_declare(self.execution_flags.charge_fee)`: [1](#0-0) 

`is_bootstrap_declare` only checks transaction-supplied fields — a fixed sentinel `sender_address` and `nonce == 0` — combined with the `charge_fee` execution flag: [2](#0-1) 

When this condition holds, the transaction entirely skips `perform_pre_validation_stage` (nonce/fee checks), skips `__validate_declare__`, and skips fee transfer, directly declaring the class: [3](#0-2) 

The comment explicitly states this flow exists "for the sequencer to bootstrap a new system" — i.e., it should be restricted to a privileged genesis-provisioning context, not to a normal transaction submitted by any account. However, nothing in `is_bootstrap_declare` verifies that the execution is actually occurring during genesis/system-bootstrap; it relies purely on the attacker-controllable `sender_address` field of the declare transaction plus `nonce == 0` and the ambient `charge_fee` flag of the execution flow that processes the transaction.

### Impact Explanation
If a declare transaction carrying `sender_address = BOOTSTRAP` and `nonce = 0` can reach `execute_raw` through a normal (non-genesis) execution path where `charge_fee` is false, an unprivileged sender could declare an arbitrary class hash for free, without any account validation/signature check and without paying fees or consuming a real account's nonce — directly analogous to Cooler's missing borrower check letting anyone invoke a privileged action. This would let an attacker bypass the declare-fee/resource-accounting economics and the `authorized_declarer_accounts` allow-list entirely (since the sentinel bootstrap sender is presumably exempt from that check as well), for as long as the specific class hash has not already been declared via this route (enforced only by `prev_value == 0` on the class dict entry).

### Likelihood Explanation
This depends on whether `execution_flags.charge_fee == false` is reachable for a transaction submitted through the ordinary gateway → mempool → batcher pipeline (i.e., whether normal block-sequencing constructors such as `AccountTransaction::new_for_sequencing` can ever produce `charge_fee = false` for an externally submitted declare tx), versus being confined to dedicated, non-externally-reachable genesis/bootstrap tooling. I was not able to fully trace, within the available iterations, every call site that sets `execution_flags.charge_fee` for the production block-building path (the pattern appears mostly in test files: `crates/blockifier/src/transaction/account_transactions_test.rs`, `crates/blockifier/src/transaction/execution_flavors_test.rs`), so I cannot conclusively confirm or rule out that an ordinary externally-submitted transaction can trigger `charge_fee = false` outside of a genesis-only, operator-controlled code path. This is the key open question that determines whether the bug is reachable by an unprivileged sender.

### Recommendation
Gate the bootstrap-declare bypass on an explicit execution-context flag (e.g., "is genesis block" / "is bootstrap provisioning run") set only by trusted node-internal code, rather than relying solely on the transaction's own `sender_address`/`nonce` fields and the ambient `charge_fee` flag, which can potentially be influenced by transaction submission parameters. Additionally, ensure the gateway explicitly rejects any externally submitted transaction using the reserved `BOOTSTRAP` sender address.

### Proof of Concept
Not fully constructible from static analysis alone: exploitation requires confirming a code path where a declare transaction with `sender_address = bootstrap_address()`, `nonce = 0` is executed via the normal external-transaction pipeline with `execution_flags.charge_fee = false`. The unit test `test_bootstrap_declare` demonstrates the mechanics of the bypass (skips fee/nonce/validation) using `AccountTransaction::new_for_sequencing`: [4](#0-3) 
but confirming attacker-reachability requires verifying that `new_for_sequencing` (or another constructor reachable from gateway-submitted transactions) can yield `charge_fee = false` outside of genesis-only, trusted invocation — which I could not fully verify with the tools available.

        // meet the following conditions.
        // This flow is used for the sequencer to bootstrap a new system.
        // Note: The absence of any account-related action leads to some unintuitive but expected
        // behavior:
        // - After the transaction is executed successfully, the batcher does not notify the mempool
        //   about its inclusion in a block. As a result, the transaction remains in the mempool.
        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.
        // - The transaction will then be marked as rejected, the mempool will be notified, and the
        //   transaction will be removed from the mempool.
        if let Transaction::Declare(tx) = &self.tx {
            if tx.is_bootstrap_declare(self.execution_flags.charge_fee) {
                let mut context = EntryPointExecutionContext::new_invoke(
                    tx_context.clone(),
                    self.execution_flags.charge_fee,
                    SierraGasRevertTracker::new(GasAmount::default()),

                assert!(res.is_none(), "Declare execute should not result in a CallInfo.");

                return Ok(TransactionExecutionInfo::default());

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }

fn test_bootstrap_declare(
    block_context: BlockContext,
    #[case] declare_tx: DeclareTransaction,
    #[case] hash_version: HashVersion,
) {
    let class_info = calculate_class_info_for_testing(
        FeatureContract::Empty(CairoVersion::Cairo1(RunnableCairo1::Casm)).get_class(),
    );
    let contract_class = class_info.contract_class();
    let mut executable_declare = ApiExecutableDeclareTransaction {
        tx: declare_tx.clone(),
        tx_hash: TransactionHash::default(),
        class_info,
    };

    // Update compiled_class_hash in V3 declare txs to match the contract class with the given hash
    // version.
    if let DeclareTransaction::V3(tx) = &mut executable_declare.tx {
        if let ContractClass::V1((casm, _)) = &contract_class {
            tx.compiled_class_hash = casm.hash(&hash_version);
        }
    }
    let compiled_class_hash = executable_declare.tx.compiled_class_hash();
    let declare_account_tx = AccountTransaction::new_for_sequencing(
        ApiExecutableTransaction::Declare(executable_declare),
    );

    let mut state = CachedState::from(DictStateReader::default());
    let res = declare_account_tx.execute(&mut state, &block_context).unwrap();

    // Check declaration.
    assert_eq!(
        state.get_compiled_class_hash(declare_tx.class_hash()).unwrap(),
        compiled_class_hash
    );

    // Ensure the only change is the class declaration: no fees, nonce bump, etc.
    assert_eq!(res, TransactionExecutionInfo::default());
    assert_eq!(
        state.to_state_diff().unwrap().state_maps,
        StateMaps {
            compiled_class_hashes: HashMap::from([(declare_tx.class_hash(), compiled_class_hash)]),
            declared_contracts: HashMap::from([(declare_tx.class_hash(), true)]),
            ..Default::default()
        }
    );
}
