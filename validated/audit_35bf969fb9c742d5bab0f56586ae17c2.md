## Analysis

The DODO H‑1 report is a classic "predictable state‑change + generous tolerance ⇒ sandwichable" bug: an on‑chain value (exchange rate) is recomputed right before/after a state transition that any unprivileged actor can observe in the mempool, and the protocol's tolerance for that change is wide enough to let an attacker extract value risk‑free by bracketing the transaction.

Push Chain has a direct structural analog in the **gas‑abstraction auto‑swap path**: `ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap` fetch a Uniswap‑V3 quote and then execute the swap with only a flat, hardcoded 5% slippage bound, and both steps are driven deterministically by a publicly observable vote‑finalization event.

### Title
Fixed 5% slippage tolerance on module-driven `depositPRC20WithAutoSwap` enables sandwich-attack value extraction from user inbound funds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`)

### Summary
`ExecuteInboundGas` (and the equivalent path in `execute_inbound_gas_and_payload.go`) fetches a `QuoterV2.quoteExactInputSingle` price quote for converting a user's inbound PRC20 gas token into PC, then immediately submits the real swap (`depositPRC20WithAutoSwap`) using a `minPCOut` computed as a flat `quote * 95 / 100`. [1](#0-0)  The trigger for this swap — quorum on an `Inbound` — is reached via ordinary, publicly visible `MsgVoteInbound` transactions [2](#0-1) , so an unprivileged actor can predict exactly when, for which token, and for roughly what amount the on-chain swap will fire.

### Finding Description
The quote used to bound the swap is read live from the pool via `GetSwapQuote`, which calls the QuoterV2 contract with `commit=false` [3](#0-2) , immediately followed by the actual swap execution through `CallPRC20DepositAutoSwap`/`DerivedEVMCall` with `commit=true` [4](#0-3) . Because the tolerance between the observed quote and the executed swap is a static 5%, and the swap is not user‑initiated but automatically triggered by validator vote finalization (an event visible ahead of time in the mempool as `MsgVoteInbound`s accumulate toward quorum), an attacker can:
1. Front‑run by swapping into the PRC20/WPC pool to skew the price against the pending auto‑swap.
2. Let the module's `depositPRC20WithAutoSwap` execute at the worse price (still within the permissive 5% band).
3. Back‑run by reversing their own swap, capturing the price impact as profit — extracted directly from the value that should have gone to the user's UEA as converted PC.

This mirrors the DODO H‑1 pattern precisely: a protocol-driven, fully deterministic state transition (there, `withdrawReserves`; here, the auto-swap) that changes an exchange-rate-like value, bracketable by an unprivileged party because the tolerance band is fixed and generous rather than tied to real-time market conditions or a user-supplied slippage parameter.

### Impact Explanation
Successful sandwiching directly reduces the PC amount credited to the victim's UEA from `CallPRC20DepositAutoSwap`, i.e., it corrupts PRC20/PC accounting and effectively steals value from ordinary users going through the gasless gas‑abstraction inbound flow — falling under the in-scope "corruption of PRC20 or native asset accounting" and "stealing... funds of user" categories.

### Likelihood Explanation
Any unprivileged actor with mempool visibility and access to the same DEX pool used by the `UniswapV3Quoter`/`WPC` pair can execute this without any privileged role, validator collusion, or key compromise — it only requires ordinary swap transactions timed around the visible inbound quorum event.

### Recommendation
Replace the fixed 5% band with a tighter, time-weighted or oracle-anchored slippage bound, and/or split quote-fetch and swap-execution so the quote is fetched from a manipulation-resistant TWAP source rather than the instantaneous spot-quote right before execution. Consider capping swap size relative to pool depth or routing gas-abstraction swaps through a mechanism with built-in MEV protection.

### Proof of Concept
1. Observe pending `MsgVoteInbound`s for a `GAS`/`GAS_AND_PAYLOAD` inbound approaching 2/3 quorum for a known source-chain token and amount.
2. Submit a swap on the underlying PRC20↔WPC Uniswap V3 pool to move the price unfavorably for a `prc20→wpc` sell (the direction the module's auto-swap will execute).
3. Wait for the quorum-triggering `MsgVoteInbound` to land, causing `ExecuteInboundGas` to call `GetSwapQuote` then `CallPRC20DepositAutoSwap` with `minPCOut = quote*0.95` [5](#0-4) , executing at the skewed price (still within the 5% band, so it doesn't revert).
4. Submit a reverse swap to restore the pool price, realizing profit equal to the price impact minus fees, extracted from the amount that should have been credited to the victim's UEA.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
