### Title
Deleting a funded Gas Key permanently burns its remaining balance instead of refunding it to the owner - ([File: runtime/runtime/src/access_keys.rs])

### Summary
This is a direct analog to the reported bug class: a user-controlled configuration change (deleting an access key) is performed without first requiring/returning outstanding value tied to that configuration, causing user funds to be permanently and irrecoverably destroyed. In `bondappetit-protocol`, changing the `incoming` token config abandons remaining LP tokens. In nearcore, deleting a "gas key" (an access key that holds a prepaid `balance` for gas sponsorship, NEP-591) does not require the balance to be withdrawn first — it simply burns whatever balance (up to 1 NEAR) is left on the key.

### Finding Description
A gas key (`AccessKeyPermission::GasKeyFullAccess`/`GasKeyFunctionCall`) carries a `GasKeyInfo.balance` field that a full-access-key owner funds via `action_transfer_to_gas_key` (`runtime/runtime/src/access_keys.rs:257-288`) and can normally recover via `action_withdraw_from_gas_key` (`:290-335`), which credits the balance back to `account.amount()`.

However, `DeleteKey` on a gas key routes to `delete_gas_key` (`runtime/runtime/src/access_keys.rs:93-134`):

```rust
fn delete_gas_key(...) -> Result<(), RuntimeError> {
    if gas_key_info.balance > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh { .. }.into());
        return Ok(());
    }
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_info.balance).ok_or(IntegerOverflowError)?;
    ...
    remove_access_key(state_update, account_id.clone(), public_key.clone());
    ...
}
``` [1](#0-0) 

This is confirmed by the unit test `test_delete_gas_key_burns_balance`, which explicitly asserts the deposited balance is added to `tokens_burnt` (i.e., permanently removed from supply, not refunded to the account or beneficiary): [2](#0-1) 

The `GasKeyInfo::MAX_BALANCE_TO_BURN` guard only prevents burning balances *above* 1 NEAR (rejecting the whole delete as `GasKeyBalanceTooHigh`); for any balance at or below that threshold, `DeleteKey` unconditionally destroys it. There is no code path that automatically withdraws the balance to the owner before removing the key — the recommended safe flow (`WithdrawFromGasKey` before `DeleteKey`) is not enforced by the protocol.

The same unconditional-burn logic is also reachable transitively via `DeleteAccount`, which sums *all* gas-key balances on the account (`compute_gas_key_balance_sum`) and burns them if the total is under the 1-NEAR ceiling (`runtime/runtime/src/actions.rs:330-406`, confirmed by `test_delete_account_burns_gas_key_balances`): [3](#0-2) 

### Impact Explanation
Any funded gas key up to 1 NEAR that is deleted (intentionally by the owner, by a full-access key holder cleaning up keys, by a relayer/dApp automating key rotation, or as a side effect of `DeleteAccount`) results in permanent, protocol-level destruction of the user's yoctoNEAR balance held on that key. This is real value loss enforced by consensus rules (every honest node burns the tokens identically), matching "permanently frozen funds" under the accepted impact categories. Because the threshold is 1 NEAR, an attacker-controlled or careless client integration (e.g., an app that funds gas keys generously and later rotates/deletes keys without withdrawing first) can repeatedly destroy meaningful value with no recovery path, and there is no on-chain warning/refund step — exactly the "recommend removing liquidity before changing the config" gap described in the source report.

### Likelihood Explanation
High likelihood of accidental loss: `DeleteKey`/`DeleteAccount` are ordinary, permissionless, single-transaction actions any full-access-key holder can issue on their own account. Nothing in the transaction validation or action execution path requires or even warns that the gas key's balance must be withdrawn first; the burn is silent (recorded only in `tokens_burnt`, not surfaced as an error). Given gas keys are a newer NEP-591 feature intended for exactly this kind of pre-funded relayer/session-key balance, key rotation/cleanup workflows are a normal, expected usage pattern, making accidental triggering likely.

### Recommendation
Before removing a gas key (in `delete_gas_key`) or deleting an account with funded gas keys (in `action_delete_account`), automatically refund the outstanding `GasKeyInfo.balance` to the owning account's `amount` (or to the deletion beneficiary for `DeleteAccount`) instead of adding it to `tokens_burnt`. If a design reason exists for capping refundable amounts (e.g., avoiding unbounded refund receipts), that reasoning should apply symmetrically to `WithdrawFromGasKey`, not silently convert to a burn. At minimum, surface a hard error requiring the caller to withdraw all gas-key balance before deletion, mirroring how `DeleteAccountStaking` blocks account deletion while stake is locked.

### Proof of Concept
1. Full-access key holder adds a gas key via `AddKey` with `AccessKeyPermission::GasKeyFullAccess` (`action_add_key` → `add_gas_key`, `access_keys.rs:194-228`).
2. Fund the gas key with e.g. 0.5 NEAR via `TransferToGasKey` (`action_transfer_to_gas_key`, `access_keys.rs:257-288`).
3. Instead of calling `WithdrawFromGasKey`, submit `DeleteKey` for that public key.
4. `action_delete_key` → `delete_gas_key` executes: `gas_key_info.balance` (0.5 NEAR) is added to `result.tokens_burnt` and the key is removed (`access_keys.rs:93-134`).
5. Observe: the account's total NEAR balance decreases by 0.5 NEAR with no receipt, refund, or recoverable record — verified directly by the existing repository test `test_delete_gas_key_burns_balance` (`access_keys.rs:607-644`), which asserts `result.tokens_burnt == deposit_amount`.

```rust
fn delete_gas_key(
    config: &RuntimeConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    public_key: &PublicKey,
    access_key: &AccessKey,
    gas_key_info: &GasKeyInfo,
) -> Result<(), RuntimeError> {
    if gas_key_info.balance > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: Some(Box::new(public_key.clone())),
            balance: gas_key_info.balance,
        }
        .into());
        return Ok(());
    }
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_info.balance).ok_or(IntegerOverflowError)?;
    let num_nonces = gas_key_info.num_nonces as usize;
    for i in 0..gas_key_info.num_nonces {
        remove_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i);
    }
    let nonce_key_len = gas_key_nonce_key_len(account_id, &public_key.into());
    let nonce_remove_compute = storage_removes_compute(
        &config.wasm_config.ext_costs,
        num_nonces,
        nonce_key_len * num_nonces,
        AccessKey::NONCE_VALUE_LEN * num_nonces,
    );
    result.compute_usage = safe_add_compute(result.compute_usage, nonce_remove_compute)?;
    remove_access_key(state_update, account_id.clone(), public_key.clone());
    account.set_storage_usage(account.storage_usage().saturating_sub(gas_key_storage_cost(
        &config.fees,
        public_key,
        access_key,
        gas_key_info.num_nonces,
    )));
    Ok(())
}

    #[test]
    fn test_delete_account_burns_gas_key_balances() {
        let (account_id, public_key, access_key) = test_account_keys();
        let public_keys: Vec<PublicKey> = (0..3)
            .map(|i| PublicKey::from_seed(KeyType::ED25519, &format!("gas_key_{i}")))
            .collect();
        let mut state_update = setup_account(&account_id, &public_key, &access_key);
        let mut account = get_account(&state_update, &account_id).unwrap().unwrap();
        for public_key in &public_keys {
            add_gas_key_to_account(&mut state_update, &mut account, &account_id, public_key);
        }

        // Fund each gas key with different amounts
        let deposit_amounts = [
            Balance::from_yoctonear(100_000),
            Balance::from_yoctonear(200_000),
            Balance::from_yoctonear(300_000),
        ];
        for (public_key, amount) in public_keys.iter().zip(deposit_amounts.iter()) {
            transfer_to_gas_key(&mut state_update, &account_id, public_key, *amount);
        }
        state_update.commit(StateChangeCause::InitialState);

        let action_result = test_delete_account(
            &account_id,
            AccountContract::from_local_code_hash(CryptoHash::default()),
            100,
            PROTOCOL_VERSION,
            &mut state_update,
        );
        assert!(action_result.result.is_ok());

        // Verify total burned balance equals sum of all gas key balances
        let expected_burnt =
            deposit_amounts.iter().fold(Balance::ZERO, |acc, x| acc.checked_add(*x).unwrap());
        assert_eq!(action_result.tokens_burnt, expected_burnt);
        let expected_compute: u64 = public_keys
            .iter()
            .map(|pk| expected_nonce_remove_compute(&account_id, pk, TEST_NUM_NONCES as usize))
            .sum();
        assert_eq!(action_result.compute_usage, expected_compute);
    }
