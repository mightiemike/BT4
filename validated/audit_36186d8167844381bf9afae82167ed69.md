### Title
Stack overflow via missing recursion-depth limit in compiled-class-hash bytecode segment hashing - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
The compiled-class-hash computation recursively walks a `NestedIntList` bytecode-segment tree with no recursion-depth bound. The segment tree structure is derived from a declarer-submitted Sierra program compiled to CASM, and the hashing runs synchronously, in-process, on the sequencer's class-manager / block-building path for every `DECLARE` transaction. A contract crafted to make the compiler emit a deeply nested segment tree can drive `bytecode_hash_node` into unbounded native recursion and overflow the process stack — the same bug class as CVE-2026-46557 (ImageMagick `fx`), where a missing depth check in a recursive operation over attacker-influenced input leads to stack overflow.

### Finding Description
`bytecode_hash_node` recurses once per level of the bytecode-segment tree with no depth counter or limit: [1](#0-0) 

It is invoked from `bytecode_hash`, which is invoked from `hash_inner`, which is the implementation backing `HashableCompiledClass::hash`: [2](#0-1) [3](#0-2) 

`hash()` is called immediately (synchronously, in the same process/thread) right after Sierra→CASM compilation on every class declaration: [4](#0-3) 

That compilation/hashing path is reached from `ClassManager::add_class`, which any unprivileged class declarer triggers for every submitted class: [5](#0-4) 

Unlike the actual Sierra→CASM compiler invocation — which is deliberately run in an external subprocess bounded by CPU time and memory limits (`compile_with_args` / `ResourceLimits`) precisely because compiling untrusted classes is dangerous — the subsequent `.hash(&HashVersion::V2)` call happens back in the main process with none of those isolation guarantees: [6](#0-5) 

The `NestedIntList` (`bytecode_segment_lengths`) that drives the recursion depth is derived from the nesting structure of the compiled CASM (functions/branches), which in turn is controlled by the shape of the declarer's Cairo/Sierra source, up to the enforced `max_bytecode_size` (81920 felts) bound: [7](#0-6) 

By writing a program consisting of a long, deeply right-nested chain of trivial branches/functions (each contributing one level to the segment tree, up to the bytecode-size cap), a declarer can make the compiler emit a segment tree whose depth is on the order of tens of thousands — comparable to the elsewhere-acknowledged risk of deep Cairo recursion, which the codebase explicitly defends against for *contract execution* (native call recursion) via dedicated large pre-allocated thread stacks: [8](#0-7) [9](#0-8) 

No equivalent protection (recursion-depth guard, iterative rewrite, or dedicated large stack) exists for `bytecode_hash_node`, even though this code path is also reachable from `blockifier`'s compiled-class-hash validation logic (`crates/blockifier/src/execution/contract_class.rs`, which imports the same `NestedIntList`/hashing machinery) during block building and OS re-execution, i.e. directly on the transaction-processing hot path of the sequencer, not just the class-manager service.

### Impact Explanation
A native stack overflow in Rust aborts the process (it cannot be caught like a panic). If triggered inside the class-manager service, that service crashes and cannot service further class declarations/compilations. If triggered inside the block-builder/blockifier process during compiled-class-hash validation for a declare transaction being built into a block, it can crash the sequencer process itself mid-block-building. Because every honest sequencer that attempts to include or re-execute the same malicious declare transaction would hit the identical deterministic recursion depth, this can cause synchronized crashes across honest nodes processing the same transaction, degrading the network's ability to confirm new blocks/transactions — this is a Medium/High severity, unprivileged-single-transaction-triggered denial-of-service, matching the class of impact accepted by the validation rules.

### Likelihood Explanation
Likelihood is Medium: it requires only a single `DECLARE` transaction with a crafted Sierra contract (no special privileges), but requires reverse-engineering how the specific `cairo-lang-starknet-classes` CASM compiler's segment-length computation maps source-code structure to `NestedIntList` nesting depth, and confirming the resulting depth is sufficient to overflow the default OS thread stack size used by whichever process performs the hashing (class manager vs. blockifier validation). I was not able to fully verify the exact stack size configured for the class-manager async runtime thread or the precise segment-nesting depth achievable within the 81920-felt bytecode cap; this would need to be empirically validated (e.g., via a Devin session with the ability to compile and run the code) before being certain of the crash threshold.

### Recommendation
Convert `bytecode_hash_node` (and the analogous `hash_entry_points_inner`/segment-walking helpers) to an iterative, explicit-stack (heap-allocated) traversal, or add an enforced maximum nesting-depth check consistent with the compiler's own `max_bytecode_size`/segment limits, returning a compilation/hashing error instead of recursing unbounded. Additionally, ensure any hashing of compiler-derived/untrusted-shaped structures that runs outside the sandboxed compiler subprocess is bounded the same way the subprocess itself is bounded (CPU/memory/depth), or moved into a similarly isolated execution context with a bounded, pre-sized stack (as already done for Cairo Native recursive execution).

### Proof of Concept
Conceptual PoC (requires a live environment to confirm exact depth threshold — not verified in this analysis):
1. Author a Cairo1 contract whose Sierra program compiles to CASM with a long, linear chain of deeply nested trivial branches/function bodies (e.g., thousands of sequential `if`/`match` arms or nested helper functions), sized up to `max_bytecode_size` (81920 felts), such that the `cairo-lang-starknet-classes` compiler's bytecode-segmentation logic produces a `NestedIntList` with recursion depth in the tens of thousands.
2. Submit this as a `DECLARE` transaction (or directly to `ClassManager::add_class` / `SierraCompiler::compile`).
3. After the sandboxed compiler subprocess successfully returns the `CasmContractClass`, the in-process call to `executable_class.hash(&HashVersion::V2)` (`crates/apollo_compile_to_casm/src/lib.rs:69`) invokes `bytecode_hash_node` recursively for each segment-tree level, exhausting the calling thread's native stack and aborting the process.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

/// Computes the compiled class hash for a given hashable class using the specified hash algorithm.
fn hash_inner<H, EH, NL>(hashable_class: &impl HashableCompiledClass<EH, NL>) -> CompiledClassHash
where
    H: StarkHash,
    EH: EntryPointHashable,
    NL: HashableNestedIntList,
{
    let external_funcs_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_external_entry_points());
    let l1_handlers_hash = entry_point_hash::<H, EH>(hashable_class.get_hashable_l1_entry_points());
    let constructors_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_constructor_entry_points());

    let bytecode_hash = bytecode_hash::<H, NL>(
        &hashable_class.get_bytecode(),
        &*hashable_class.get_bytecode_segment_lengths(),
    );

    // Compute total hash by hashing each component on top of the previous one.
    CompiledClassHash(H::hash_array(&[
        *COMPILED_CLASS_V1,
        external_funcs_hash,
        l1_handlers_hash,
        constructors_hash,
        bytecode_hash,
    ]))
}

    pub async fn add_class(&mut self, class: RawClass) -> ClassManagerResult<ClassHashes> {
        let sierra_class = SierraContractClass::try_from(&class)?;
        let class_hash = sierra_class.calculate_class_hash();
        if let Ok(Some(executable_class_hash_v2)) =
            self.classes.get_executable_class_hash_v2(class_hash)
        {
            // Class already exists.
            return Ok(ClassHashes { class_hash, executable_class_hash_v2 });
        }

        let compilation_start_time = Instant::now();
        let (raw_executable_class, executable_class_hash_v2) =
            self.compiler.compile(class.clone()).await.map_err(|err| match err {
                SierraCompilerClientError::SierraCompilerError(error) => {
                    ClassManagerError::SierraCompiler { class_hash, error }
                }
                SierraCompilerClientError::ClientError(error) => {
                    ClassManagerError::Client(error.to_string())
                }
            })?;
        debug!(
            %class_hash,
            compiled_class_hash = %executable_class_hash_v2,
            compilation_elapsed_ms = compilation_start_time.elapsed().as_millis(),
            class_size_bytes =
                class.size().map_or("Failed to get class size".to_owned(), |size| size.to_string()),
            casm_size_bytes =
                raw_executable_class.size().map_or("Failed to get casm size".to_owned(), |size| size.to_string()),
            "Finished compiling class."
        );

        self.validate_class_length(&raw_executable_class)?;
        Self::validate_class_version(&sierra_class)?;
        self.classes.set_class(
            class_hash,
            class,
            executable_class_hash_v2,
            raw_executable_class,
        )?;

        let class_hashes = ClassHashes { class_hash, executable_class_hash_v2 };
        Ok(class_hashes)

impl<S: StateReader + Send> TransactionExecutor<S> {
    pub fn execute_txs_sequentially(
        &mut self,
        txs: &[Transaction],
        execution_deadline: Option<Instant>,
    ) -> Vec<TransactionExecutorResult<TransactionExecutionOutput>> {
        #[cfg(not(feature = "cairo_native"))]
        return self.execute_txs_sequentially_inner(txs, execution_deadline);
        #[cfg(feature = "cairo_native")]
        {
            // TODO(meshi): find a way to access the contract class manager config from transaction
            // executor.
            let txs = txs.to_vec();
            std::thread::scope(|s| {
                std::thread::Builder::new()
                    // when running Cairo natively, the real stack is used and could get overflowed
                    // (unlike the VM where the stack is simulated in the heap as a memory segment).
                    //
                    // We pre-allocate the stack here, and not during Native execution (not trivial), so it
                    // needs to be big enough ahead.
                    // However, making it very big is wasteful (especially with multi-threading).
                    // So, the stack size should support calls with a reasonable gas limit, for extremely deep
                    // recursions to reach out-of-gas before hitting the bottom of the recursion.
                    //
                    // The gas upper bound is MAX_POSSIBLE_SIERRA_GAS, and sequencers must not raise it without
                    // adjusting the stack size.
                    .stack_size(self.config.stack_size)
                    .spawn_scoped(s, || self.execute_txs_sequentially_inner(&txs, execution_deadline))
                    .expect("Failed to spawn thread")
                    .join()
                    .expect("Failed to join thread.")
            })
        }
    }
