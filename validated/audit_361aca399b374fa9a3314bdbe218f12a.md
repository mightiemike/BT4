### Title
Token exchange does not verify that the `shop` parameter matches the session token's `dest`/`iss` claim, allowing cross-tenant OAuth token exchange - ([File: packages/apps/shopify-api/lib/auth/oauth/token-exchange.ts])

### Summary
`tokenExchange()` calls `decodeSessionToken(config)(sessionToken)` purely to verify the JWT signature/audience/expiry, but discards the returned payload entirely. The `shop` used to build the outbound `POST https://${shop}/admin/oauth/access_token` request and the resulting local `Session` object is taken directly from the caller-supplied `shop` parameter, sanitized only for format (via `sanitizeShop`), with no comparison to the `dest`/`iss` claim of the verified session token.

### Finding Description
In `tokenExchange` (`packages/apps/shopify-api/lib/auth/oauth/token-exchange.ts`), the flow is: [1](#0-0) 

`decodeSessionToken(config)(sessionToken)` is awaited but its return value is never assigned or used, so any claims inside the token (`dest`, `iss`, `sub`) are dropped immediately. `decodeSessionToken` itself only checks the HS256 signature (using `config.apiSecretKey`), `exp`/`nbf` (via the JWT library), and optionally `aud === config.apiKey`: [2](#0-1) 

It performs no comparison between `payload.dest`/`payload.iss` and any expected shop. Separately, `sanitizeShop` only validates that the `shop` string is a syntactically valid myshopify-style domain — it has no knowledge of, or relationship to, the session token: [3](#0-2) 

As a result, an app built on this library that exposes a token-exchange endpoint accepting both `sessionToken` and `shop` from the client (a common integration pattern, e.g. `shopify-app-express`'s `performTokenExchange` middleware) can be driven to perform the OAuth token-exchange POST against `shop=B` while the `subject_token` is a validly-signed session token for `shop=A`. The library builds the resulting `Session` using `shop: cleanShop` (attacker-controlled `B`), not the shop bound to the verified token: [4](#0-3) 

The library provides no tenant-isolation invariant tying the verified JWT subject/dest to the shop used for the exchange — that check is entirely absent from this code path.

### Impact Explanation
This breaks tenant isolation at the library level: the library will happily issue a cross-shop OAuth token-exchange request using shop A's identity token against shop B's domain, and will construct a local session record labeled with the attacker-chosen shop. Whether the exploit fully succeeds end-to-end depends on Shopify's OAuth server also validating the `dest` claim against the target shop domain (which is outside this repository), but the library itself omits a defense-in-depth check it has all the information to perform, and any resulting error state (or partial success in host apps that don't independently re-verify) constitutes a broken tenant-isolation invariant and corresponds to the "cross-tenant data/state access" bounty impact class.

### Likelihood Explanation
Exploitability requires only that: (1) the attacker is a legitimate authenticated user of some shop A with a valid session token (unprivileged, expected precondition for embedded apps), and (2) the host app exposes `shop` as a client-controllable field on its token-exchange endpoint (a common pattern since Shopify's official token-exchange guidance often takes `shop` from the request). Given those conditions, the request is trivially repeatable and requires no secrets or privileged access.

### Recommendation
After decoding the session token, compare the sanitized `shop` against the shop derived from the token's `dest` (or `iss`) claim and throw (e.g. `InvalidJwtError`/`InvalidShopError`) on mismatch before performing the outbound request:
```ts
const decoded = await decodeSessionToken(config)(sessionToken);
const cleanShop = sanitizeShop(config)(shop, true)!;
const tokenShop = sanitizeShop(config)(new URL(decoded.dest).hostname, true);
if (tokenShop !== cleanShop) {
  throw new ShopifyErrors.InvalidJwtError('Session token does not match shop');
}
```

```ts
// packages/apps/shopify-api/lib/auth/oauth/__tests__/token-exchange.test.ts
test('throws when shop param does not match dest claim in session token', async () => {
  const shopify = shopifyApi(testConfig());

  const sessionTokenPayload = {
    iss: 'shopA.myshopify.io/admin',
    dest: 'shopA.myshopify.io',
    aud: shopify.config.apiKey,
    sub: '1',
    exp: Date.now() / 1000 + 3600,
    nbf: 1234,
    iat: 1234,
    jti: '4321',
    sid: 'abc123',
  };

  const sessionToken = await signJWT(shopify.config.apiSecretKey, sessionTokenPayload);

  await expect(
    shopify.auth.tokenExchange({
      shop: 'shopB.myshopify.io', // attacker-chosen, different tenant
      sessionToken,
      requestedTokenType: RequestedTokenType.OnlineAccessToken,
    }),
  ).rejects.toThrow(ShopifyErrors.InvalidJwtError);
});
```
This test currently fails (no error is thrown, and the POST is sent to `shopB.myshopify.io` with `subject_token` bound to `shopA`), demonstrating the missing tenant-isolation check.

export function decodeSessionToken(config: ConfigInterface) {
  return async (
    token: string,
    {checkAudience = true}: DecodeSessionTokenOptions = {},
  ): Promise<JwtPayload> => {
    let payload: JwtPayload;
    try {
      payload = (
        await jose.jwtVerify(token, getHMACKey(config.apiSecretKey), {
          algorithms: ['HS256'],
          clockTolerance: JWT_PERMITTED_CLOCK_TOLERANCE,
        })
      ).payload as unknown as JwtPayload;
    } catch (error) {
      throw new ShopifyErrors.InvalidJwtError(
        `Failed to parse session token '${token}': ${error.message}`,
      );
    }

    // The exp and nbf fields are validated by the JWT library

    if (checkAudience && payload.aud !== config.apiKey) {
      throw new ShopifyErrors.InvalidJwtError(
        'Session token had invalid API key',
      );
    }

    return payload;
  };

export function sanitizeShop(config: ConfigInterface) {
  return (shop: string, throwOnInvalid = false): string | null => {
    let shopUrl = shop;
    const domainsRegex = [
      'myshopify\\.com',
      'shopify\\.com',
      'myshopify\\.io',
      'shop\\.dev',
    ];

    // Add domains from transformations (both source and target)
    if (config.domainTransformations) {
      domainsRegex.push(...getTransformationDomains(config));
    }

    const shopUrlRegex = new RegExp(
      `^[a-zA-Z0-9][a-zA-Z0-9-_]*\\.(${domainsRegex.join('|')})[/]*$`,
    );

    const shopAdminRegex = new RegExp(
      `^admin\\.(${domainsRegex.join('|')})/store/([a-zA-Z0-9][a-zA-Z0-9-_]*)$`,
    );

    const isShopAdminUrl = shopAdminRegex.test(shopUrl);
    if (isShopAdminUrl) {
      shopUrl = shopAdminUrlToLegacyUrl(shopUrl) || '';
    }

    const sanitizedShop = shopUrlRegex.test(shopUrl) ? shopUrl : null;
    if (!sanitizedShop && throwOnInvalid) {
      throw new InvalidShopError('Received invalid shop argument');
    }

    if (sanitizedShop && config.domainTransformations) {
      return applyDomainTransformations(sanitizedShop, config);
    }

    return sanitizedShop;
  };
