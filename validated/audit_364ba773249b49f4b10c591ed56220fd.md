### Title
Any unprivileged account can grief a victim's UEA gas balance via unauthenticated `MsgExecutePayload` calls that revert on signature check but still deduct gas fees - (File: `x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`MsgExecutePayload` deliberately allows `Signer` (the Cosmos tx submitter) to differ from `UniversalAccountId.Owner` (the UEA whose payload executes) — this is documented as safe because the UEA contract's `executeUniversalTx` verifies `verificationData` against the owner's key and reverts on mismatch, rolling back "all state changes." However, gas-fee deduction from the victim UEA is not part of that atomic rollback: `ExecutePayload` calls `k.DeductGasFeesFromReceipt(...)` against the *victim's* UEA address using whatever `receipt.GasUsed` the reverted EVM call produced, independent of whether `CallUEAExecutePayload` succeeded. Since the message is in the gasless allowlist, the attacker pays nothing to repeatedly invoke this against any victim `UniversalAccountId`, draining `upc` from the victim UEA on every failed, unauthenticated attempt — an unprivileged, no-cost fund-drain analogous to H-12's "any lender can act on a loan without borrower consent."

### Finding Description
`x/uexecutor/keeper/msg_execute_payload.go` `ExecutePayload`: [1](#0-0) 

The order of operations is: (1) call `CallUEAExecutePayload` via `DerivedEVMCall` with `commit=true` (a real, receipted EVM tx) using the attacker-controlled `evmFrom` and attacker-supplied `verificationData`; (2) unconditionally call `DeductGasFeesFromReceipt(ctx, sdkCtx, ueaAddr, receipt, universalPayload)` against the victim UEA using whatever gas the reverted call consumed; (3) only after fee deduction, check `execErr` and return it.

`DeductGasFeesFromReceipt` only skips deduction if `receipt == nil || receipt.GasUsed == 0`: [2](#0-1) 

Because `commit=true` in `CallUEAExecutePayload`, an EVM revert (e.g., invalid Ed25519/ECDSA signature check inside `executeUniversalTx`) still produces a receipt with non-zero `GasUsed` (the EVM charges gas up to the point of revert). The keeper then burns real `upc` from the victim's UEA balance for gas the victim never authorized and derived no benefit from.

The `MsgExecutePayload` authorization model explicitly does not bind `Signer` to `UniversalAccountId.Owner` — "Any account may submit the message" — relying entirely on the UEA contract's cryptographic check to make third-party submission safe: [3](#0-2) [4](#0-3) 

That safety argument only covers *state changes from the payload execution itself* ("No state changes survive a failed signature check"). It does not address the separate gas-fee-deduction step performed outside the reverted call's cache, which is exactly the code path exercised here: the attacker (an unprivileged "lender"-analog) can act on the victim's UEA (the "borrower"-analog) resource without any owner authorization, paying zero cost themselves (gasless whitelist) while inflicting real, unauthorized fund loss on the victim.

Note: `ExecutePayloadV2` (used elsewhere) wraps the call and fee deduction in a `CacheContext` that only commits on success — but the primary `ExecutePayload` message handler path used by `MsgExecutePayload` does not use that cache-wrapped variant; it deducts fees directly against `sdkCtx`, independent of `execErr`. ### Impact Explanation
An attacker who knows any victim's `UniversalAccountId` (chain namespace, chain id, owner address — all public) can repeatedly submit `MsgExecutePayload` for that victim with garbage `VerificationData` and a large `GasLimit`/`MaxFeePerGas`. Each call is gasless for the attacker (no Cosmos fee, since `MsgExecutePayload` is in the gasless allowlist), but each reverted attempt burns real `upc` from the victim's UEA balance via `DeductGasFeesFromReceipt`, since the deduction is unconditional on `execErr`. Repeated over many blocks/messages, this permanently and unauthorized-ly drains victim UEA gas balances — a fund-drain / DoS on victim funds reachable by any unprivileged external attacker, matching the "unauthorized burn ... of user-controlled funds" and "gasless admission" impact categories in scope.

### Likelihood Explanation
High reachability: `MsgExecutePayload` requires no special permission, is explicitly gasless, and its `UniversalAccountId` (victim identifier) is a public value observable on-chain from any prior UEA deployment or inbound. `VerificationData` can be trivially malformed to guarantee an EVM-level revert with non-trivial gas consumption before the signature check fails (revert typically happens partway through EVM execution, e.g., after ABI decode, storage read of owner key, and ecrecover/precompile call, all of which consume gas). No validator collusion or privileged access is required — this is triggerable by a single unprivileged externally owned account.

### Recommendation
Ensure gas-fee deduction from the victim UEA is only ever billed to whichever party actually authorized/benefited from the execution attempt, or wrap the EVM call + gas deduction from the direct `ExecutePayload` path in the same fail-safe pattern already used by `ExecutePayloadV2` (`CacheContext` with `writeCache()` gated on success), and additionally consider not billing the UEA at all for revert-due-to-invalid-signature outcomes (only bill for `GasUsed` incurred by an authenticated/successful `executeUniversalTx` call, or cap/rate-limit failed-signature attempts per UEA per block). At minimum, distinguish "signature verification failed" reverts (which should not consume UEA funds) from legitimate payload-execution-reverts (where charging gas may be intended), and require the fee-deduction step to be atomic with the underlying call outcome rather than always applied post hoc against `sdkCtx`.

### Proof of Concept
1. Identify a victim `UniversalAccountId{ChainNamespace, ChainId, Owner}` with a deployed, funded UEA (public knowledge from prior inbound activity).
2. Attacker (any account, no funds required — `MsgExecutePayload` is gasless) submits `MsgExecutePayload{Signer: attacker, UniversalAccountId: victim, UniversalPayload: {arbitrary valid-shaped payload with high GasLimit/MaxFeePerGas}, VerificationData: <garbage bytes>}`.
3. `ExecutePayload` keeper method resolves victim's UEA (already deployed, so no auto-deploy gate blocks it) and calls `CallUEAExecutePayload` → `DerivedEVMCall(commit=true, ...)`.
4. The UEA contract's `executeUniversalTx` reverts on invalid signature after consuming gas (nonzero `receipt.GasUsed`).
5. `DeductGasFeesFromReceipt` is called with that receipt regardless of `execErr`, and burns `gasCost` upc from the victim's UEA balance via `DeductAndBurnFees`.
6. `ExecutePayload` returns `execErr` (the reverted tx error) to the attacker, but the victim's UEA balance is already reduced.
7. Repeat arbitrarily many times at zero cost to the attacker to drain the victim's UEA `upc` balance.

Confidence caveat: I could not directly inspect the `pushchain/evm` fork's `DerivedEVMCall`/underlying EVM execution to confirm the exact gas-accounting behavior on revert (i.e., that `receipt.GasUsed > 0` is guaranteed on a signature-check revert inside `executeUniversalTx`, as opposed to `commit` failing before any gas is charged). This is based on standard EVM semantics (gas is consumed up to the revert point) and the explicit "No state changes survive a failed signature check" language in the README, which conspicuously does not mention gas billing — but the precise behavior of this repo's forked EVM commit path was not independently verified from source in this repo (the fork itself lives in a separate `pushchain/evm` repository not in scope/indexed here). I recommend a Devin session with terminal/test access to confirm `receipt.GasUsed` on a reverted `executeUniversalTx` call before treating this as fully confirmed.

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```

#### Why this is safe under `Signer ≠ Owner`

An attacker submitting `MsgExecutePayload` with their own `Signer` and a victim's `UniversalAccountId` produces no exploitable outcome:

- The factory resolves the victim's UEA address from the embedded `UniversalAccountId` — correct.
- `evmFrom` (derived from `Signer`) becomes the EVM-level `msg.sender` of the call to the UEA. Since `evmFrom != UNIVERSAL_EXECUTOR_MODULE` (`0x14191Ea54B4c176fCf86f51b0FAc7CB1E71Df7d7`), the contract enforces the signature check.
- The attacker cannot forge `VerificationData` that recovers to the victim's owner key.
- The contract reverts → the keeper returns an error → the Cosmos transaction reverts in full.
- Net effect: zero state change. No EVM gas is charged to the victim UEA (the deduction is rolled back with the rest of the transaction). The submission costs the attacker nothing on chain (gasless), but also achieves nothing.
```

	// Step 2: Wrap EVM execution + fee deduction in a CacheContext so they
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr
	}
