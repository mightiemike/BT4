## Analysis

The Chainlink bug class here is "trusting a price value from an on-chain source without any deviation/staleness/sanity bound, so a moved-but-technically-valid price gets used as ground truth for a fund-affecting calculation." Searching Push Chain's own price-dependent code (`x/uexecutor/keeper/evm.go`, `execute_inbound_gas.go`, `execute_inbound_gas_and_payload.go`, `outbound.go`), the closest structural analog is not the validator-voted `ChainMeta`/gas-price oracle (that path is gated to universal validators and explicitly out of scope per the allowed-impact gate), but the **Uniswap V3 `QuoterV2` spot-price call used to derive `minPCOut` slippage protection for every PRC20→PC auto-swap deposit and every excess-gas refund**.

`GetSwapQuote` reads a live, single-block spot quote directly from the pool with no TWAP, no staleness window, and no deviation bound: [1](#0-0) . That quote is then immediately used to compute the *only* protection against value extraction — a fixed 5% band derived from the same manipulable number — both on the inbound gas-swap path [2](#0-1) , the gas-and-payload inbound path [3](#0-2) , and the outbound excess-gas refund path [4](#0-3) .

### Title
Unbounded single-block Uniswap spot quote used as sole slippage protection for PRC20 auto-swap deposits and gas refunds - (File: `x/uexecutor/keeper/evm.go`)

### Summary
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` for an instantaneous, single-block AMM spot price and passes it straight through to `minPCOut = quote * 95/100`, with no staleness check, no TWAP, and no deviation guard against the pool's recent trading history. This mirrors the Chainlink `minAnswer`/`maxAnswer` bug class: the code accepts whatever the underlying "price feed" reports as ground truth and does not validate that the value is within a sane range before using it to gate fund-moving operations.

### Finding Description
`GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`) performs a `commit=false` `CallEVM` to the pool's `QuoterV2` and returns whatever `amountOut` the pool computes at that instant [5](#0-4) . This value is used to compute `minPCOut` for `depositPRC20WithAutoSwap` in three separate flows:
- `ExecuteInboundGas` (GAS inbound route) [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound route) [6](#0-5) 
- `applyGasRefund` → `getSwapQuoteForRefund` (outbound excess-gas refund) [7](#0-6) 

In every case the 5% tolerance is computed *from the same manipulated number*, so it protects against nothing but ordinary rounding — it does not protect against the quote itself being pushed away from the pool's "true" equilibrium price immediately before the swap executes. An unprivileged actor who can trade against the Push Chain-side WPC/PRC20 pool (a pool the protocol itself deploys and that end users can freely trade on) can move the spot price down, then trigger (or wait for) their own inbound deposit / outbound gas refund to auto-swap at the depressed price, extracting the difference, or push it up to force `minPCOut` artificially high, causing legitimate user autoswaps to revert (denial of the auto-swap leg) and fall back to the raw PRC20 deposit path, silently changing the asset a user actually receives.

### Impact Explanation
This directly touches PRC20/native asset accounting and refund accounting: the amount of PC a user's deposit or gas refund is credited with is derived from a value an ordinary trader can move within the same window the swap executes. Successful exploitation lets an attacker extract value from the protocol-owned liquidity used for these system auto-swaps at the expense of users receiving less PC than the honest market rate, or forces unexpected fallback behavior (no-swap raw PRC20 deposit) that changes the effective payout asset for a user's bridged funds. This fits the allowed-impact categories of "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" and "unauthorized... refund" resulting from ordinary user trading actions.

### Likelihood Explanation
Reachable purely by unprivileged users: no validator, admin, or TSS compromise needed. The attacker only needs (a) the ability to trade on the Push Chain-side gas-token/WPC pool (public), and (b) the ability to trigger their own inbound gas top-up / gas-and-payload inbound, or to have a pending outbound with excess gas refunded, both of which are ordinary user-initiated crosschain actions. Actual profitability depends on the pool's depth and the attacker's ability to sequence their manipulating trade close enough to the auto-swap execution (same or adjacent block), which is achievable given they control when they submit both the manipulating trade and the deposit that triggers the inbound processing.

### Recommendation
Do not use a raw single-call spot quote as the reference price for `minPCOut`. Use a time-weighted average price (TWAP) from the pool (or an external validated price source), enforce a maximum allowed deviation between the current spot price and the TWAP before proceeding, and/or bound the acceptable `minPCOut` against a governance/registry-configured reference price rather than deriving both the estimate and its own tolerance from the same instantaneous read.

### Proof of Concept
1. Attacker holds gas-token PRC20 (or the pool's counter-asset) and trades a sufficiently large amount against the UniversalCore-associated WPC/gasToken pool to push the spot price used by `QuoterV2.quoteExactInputSingle` down.
2. In the same or an adjacent block, the attacker's own bridged inbound (GAS or GAS_AND_PAYLOAD type) reaches quorum and is executed, calling `GetSwapQuote` → `depositPRC20WithAutoSwap` with `minPCOut` computed from the manipulated low quote [2](#0-1) .
3. The attacker (or a subsequent trade) restores the pool price, having captured the difference between the manipulated quote and the pool's normal equilibrium price, at the expense of the protocol-owned swap liquidity / other users relying on the same "5% off spot" tolerance.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
