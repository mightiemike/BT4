### Title
Bridge OutgoingToken secret disclosed to view-role users via unauthorized-role Show endpoint - ([File: core/web/router.go])

### Summary
The `GET /v2/bridge_types/:BridgeName` route is registered as `authv2.GET("/bridge_types/:BridgeName", bt.Show)` with only session/token authentication and no `RequiresEditRole`/`RequiresAdminRole` wrapper, unlike the sibling `Create`, `Update`, and `Destroy` routes on the same controller. `BridgeTypesController.Show` returns a `presenters.BridgeResource` that unconditionally includes the bridge's `OutgoingToken` field (no `omitempty`), so any authenticated user, including one with the lowest `UserRoleView` role, can retrieve a bridge's outgoing auth token.

### Finding Description
`v2Routes` in `core/web/router.go` registers bridge routes as:
```go
bt := BridgeTypesController{app}
authv2.GET("/bridge_types", paginatedRequest(bt.Index))
authv2.POST("/bridge_types", auth.RequiresEditRole(bt.Create))
authv2.GET("/bridge_types/:BridgeName", bt.Show)
authv2.PATCH("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Update))
authv2.DELETE("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Destroy))
```
Only `Show` lacks a role guard. All handlers under `authv2` pass through `auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession)`, which merely sets the authenticated `*clsessions.User` in the gin context (`core/web/auth/auth.go` lines 155-175) without checking role — role checks only happen in the `RequiresRunRole`/`RequiresEditRole`/`RequiresAdminRole` wrappers. Because `Show` isn't wrapped by any of these, a `UserRoleView` user (the lowest privilege role, which fails all three role checks) can call it successfully.

`BridgeTypesController.Show` (`core/web/bridge_types_controller.go` lines 124-146) looks up the bridge by name and calls `presenters.NewBridgeResource(bt)`, which sets `OutgoingToken: b.OutgoingToken` unconditionally in the JSON response (`core/web/presenters/bridges.go` lines 17-39). Unlike `IncomingToken`, which is tagged `json:"incomingToken,omitempty"` and only populated on `Create`, `OutgoingToken` has no `omitempty` and is always serialized whenever a `BridgeResource` is built from a stored `bridges.BridgeType`, including via `Show`, `Index`, `Update`, and `Destroy` responses.

### Impact Explanation
The bridge's outgoing token (`OutgoingToken`) is the credential the Chainlink node uses to authenticate outbound calls to external adapters/bridges — its exposure to a view-role principal is disclosure of a secret credential to an unauthorized lower-privilege user, violating the intended invariant that only edit/admin-role users can access bridge secrets. This matches a secret-disclosure impact class: a low-privilege API/session user can pull external-adapter authentication tokens for any bridge configured on the node, which could then be reused to interact with the external adapter as the node.

### Likelihood Explanation
Fully feasible and repeatable: it requires only a valid `view`-role session/API token (the lowest privilege tier), and a single unauthenticated-role-checked `GET /v2/bridge_types/:BridgeName` request. No additional bypass, timing, or race condition is needed — the missing role guard is a straightforward routing omission, and the existing test `TestBridgeController_Show` in `core/web/bridge_types_controller_test.go` (lines 271-300) exercises `Show` without any role restriction, confirming the endpoint is reachable by any authenticated client.

### Recommendation
Wrap the `Show` route with `auth.RequiresEditRole` (or, at minimum, `auth.RequiresRunRole`) to match the access level required for `Update`/`Destroy`, e.g.:
```go
authv2.GET("/bridge_types/:BridgeName", auth.RequiresEditRole(bt.Show))
```
Alternatively/additionally, avoid returning `OutgoingToken` from `presenters.NewBridgeResource` for read paths not intended to expose secrets (mirroring the `omitempty`/create-only pattern already used for `IncomingToken`).

### Proof of Concept
Add a test analogous to `TestBridgeController_Show` in `core/web/bridge_types_controller_test.go` that:
1. Creates an application and a bridge with a known `OutgoingToken` (e.g., `"super-secret-outgoing-token"`) via `app.BridgeORM().CreateBridgeType`.
2. Creates a user session/API-token client scoped to `clsessions.UserRoleView` (as used elsewhere in tests, e.g. `cltest.NewApplication` with a view-role user, or `app.NewHTTPClient(&cltest.User{Role: clsessions.UserRoleView})` pattern used in other role-restriction tests in the same test file).
3. Calls `client.Get("/v2/bridge_types/" + bt.Name.String())`.
4. Asserts the response status is `200 OK` (not `401`/`403`) and that the parsed `presenters.BridgeResource.OutgoingToken` equals the secret value set in step 1, demonstrating that a view-role user retrieved the bridge secret — expected/fixed behavior should instead return `401 Unauthorized`.

// Show returns the details of a specific Bridge.
func (btc *BridgeTypesController) Show(c *gin.Context) {
	ctx := c.Request.Context()
	name := c.Param("BridgeName")

	taskType, err := bridges.ParseBridgeName(name)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	bt, err := btc.App.BridgeORM().FindBridge(ctx, taskType)
	if errors.Is(err, sql.ErrNoRows) {
		jsonAPIError(c, http.StatusNotFound, errors.New("bridge not found"))
		return
	}
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	jsonAPIResponse(c, presenters.NewBridgeResource(bt), "bridge")
}

func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))

		}

			return
		}
		handler(c)
	}
