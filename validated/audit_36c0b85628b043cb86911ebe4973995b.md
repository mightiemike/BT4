## Open Redirect via Unvalidated `exitIframe` Destination Parameter - (`packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts`)

### Summary
The `exitIframe` app-bridge exit path lets an **anonymous** requester fully control the redirect destination via the `exitIframe` query parameter. The destination is only checked by `sanitizeRedirectUrl()`, which validates the URL's *protocol* (must be `http:`/`https:`) but never validates that the URL's *origin* matches the app's own `appUrl`. This mirrors the MapleLoan bug class: a caller is allowed to supply the "arguments" (here, the redirect target) for a privileged flow that should instead use a hardcoded/restricted value, letting them steer the outcome in their favor.

### Finding Description
`respondToExitIframeRequest` is invoked unconditionally, before any session/auth check, whenever the request path matches `config.auth.exitIframePath`: [1](#0-0) 

It takes the raw `exitIframe` query-string value and passes it straight to `renderAppBridge`: [2](#0-1) 

`renderAppBridge` calls `sanitizeRedirectUrl(config.appUrl, redirectTo.url)` to "validate" it. But `sanitizeRedirectUrl`/`isSafe` only rejects `file:///` URIs, whitespace, backslash/slash-doubled relative paths, and non-`http(s)` protocols — it never compares `url.origin` (or hostname) against the `domain` (i.e. `config.appUrl`) argument that was passed in: [3](#0-2) 

Because `new URL(redirectUrl, domain)` returns the *absolute* URL when `redirectUrl` is already absolute (ignoring the `domain` base), any fully-qualified `https://attacker.example` value passes `isSafe` and is accepted as a valid redirect target. The existing test suite only asserts same-origin, relative-path, and `file://` cases — there is no test enforcing origin restriction to `appUrl`, confirming the check is missing: [4](#0-3) 

The resulting response embeds the attacker-controlled URL directly into a `window.open(destination, "_top")` script: [5](#0-4) 

### Impact Explanation
Since `target` defaults to `_top`, visiting a crafted link causes the top-level browser window (which the merchant/user believes is the Shopify Admin, since the app is embedded) to navigate to an attacker-controlled domain. This enables phishing (e.g., a fake Shopify login/OAuth page to steal merchant credentials or re-authorize a malicious app) and can be weaponized in social-engineering attacks against merchants who trust links pointing at the legitimate app domain (`{appUrl}/auth/exit-iframe?...`). No privileged access or existing session is required to construct or send this URL — it is reachable pre-authentication.

### Likelihood Explanation
High. The `exitIframePath` route is reached by any unauthenticated HTTP GET before session-token/shop validation occurs, and the query parameter is attacker-controlled with no origin allow-listing enforced by `sanitizeRedirectUrl`. An attacker only needs to know the app's `appUrl` (public) and the exit-iframe path (a fixed, documented convention), then distribute a link such as `https://<appUrl>/auth/exit-iframe?exitIframe=https://evil.example&shop=<shop>.myshopify.com`.

### Recommendation
In `isSafe` (`validate-redirect-url.ts`), enforce that the resolved `url.origin` equals `new URL(domain).origin` for absolute URLs, only permitting relative paths or same-origin absolute URLs — rather than merely checking the protocol scheme. This closes the gap where a caller can supply an arbitrary "destination argument" instead of the intended hardcoded/allow-listed target.

### Proof of Concept
```
GET https://<merchant-app-domain>/auth/exit-iframe?exitIframe=https%3A%2F%2Fevil.example%2Fphish&shop=example.myshopify.com HTTP/1.1
```
Response body includes:
```html
<script>window.open("https://evil.example/phish", "_top")</script>
```
which is executed automatically by any browser loading this URL (e.g., inside the Shopify Admin iframe or via a direct link), navigating the top window to the attacker's page.

export function renderAppBridge(
  {config}: BasicParams,
  request: Request,
  redirectTo?: RedirectToOptions,
): never {
  let redirectToScript = '';
  if (redirectTo) {
    const destination = sanitizeRedirectUrl(config.appUrl, redirectTo.url);

    const target = redirectTo.target ?? '_top';

    redirectToScript = `<script>window.open(${JSON.stringify(
      destination.toString(),
    )}, ${JSON.stringify(target)})</script>`;
  }
```

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
```
