### Title
Unbounded gzip decompression of attacker-controlled `compressed_program` in JSON-RPC `decompress_program` causes memory-exhaustion DoS - (File: crates/apollo_rpc/src/v0_8/api/mod.rs)

### Summary
The JSON-RPC v0.8 API's Cairo-v0 (deprecated) declare-transaction path decompresses the user-supplied, base64+gzip-encoded `compressed_program` field with an **unbounded** `GzDecoder::read_to_end`, before any validation of the transaction (no signature check, no size limit, no zip-bomb guard). This mirrors the Minder `HandleGithubWebhook` bug class: reading an untrusted, attacker-controlled payload fully into memory prior to any validation step, enabling a classic decompression-bomb / memory-exhaustion DoS.

### Finding Description
`decompress_program` in [1](#0-0)  base64-decodes and then gzip-decompresses the `compressed_program` field of a `DeprecatedContractClass` with no cap on the decompressed size or CPU/time budget:
```
// TODO(dan): add time and size limits.
let mut decoder = GzDecoder::new(compressed_data.as_slice());
let mut decompressed = Vec::new();
decoder.read_to_end(&mut decompressed).map_err(internal_server_error)?;
```
This function is called from `user_deprecated_contract_class_to_sn_api`, itself invoked from `TryFrom<BroadcastedDeclareTransaction> for ExecutableTransactionInput` (`BroadcastedDeclareTransaction::V1` arm), at [2](#0-1) . This conversion runs before any stateful/stateless transaction validation, fee/signature checks, or the class-manager/gateway size gates (`max_contract_bytecode_size`, `max_contract_class_object_size`) that protect the separate `/gateway/add_transaction` HTTP path.

By contrast, every other decompression path deliberately bounds memory: `decode_and_decompress_with_size_limit` caps the reader with `.take(max_size+1)` at [3](#0-2) , and storage-side decompression bounds with `MAX_DECOMPRESSED_SIZE` at [4](#0-3) . `decompress_program` is the sole unguarded outlier, and its own inline `TODO` acknowledges the missing limits.

Any node exposing the JSON-RPC write API (`starknet_estimateFee`, `starknet_addDeclareTransaction`) to an unprivileged caller is reachable: an attacker submits a `BROADCASTED_DECLARE_TXN_V1` whose `contract_class.program` is a small, highly-compressed gzip payload (a classic zip bomb can expand many orders of magnitude), causing the RPC node process to allocate gigabytes of memory and potentially be OOM-killed, denying service to all other RPC clients on that node.

### Impact Explanation
This is a network-reachable, unauthenticated-cost memory-exhaustion DoS against a sequencer/full-node RPC endpoint: a single small JSON-RPC request can force the process to allocate unbounded memory and crash (or severely degrade) it, matching CWE-400 / "network unable to confirm new transactions" (any RPC-serving node using this path becomes unavailable). This is High severity by analogy to the referenced advisory, since it is triggerable by any unprivileged JSON-RPC caller with no state, funds, or prior conditions required.

### Likelihood Explanation
Likelihood is high: the endpoints (`estimateFee`, `addDeclareTransaction`, and by extension any code path deserializing `BroadcastedDeclareTransaction::V1`) are part of the standard public JSON-RPC surface, take attacker-supplied strings directly, and the missing bound is explicit and trivial to exploit (no cryptographic or economic barrier — no fee is paid for `estimateFee`, and even `addDeclareTransaction` fails cheaply after allocation, i.e., the OOM already happened before rejection).

### Recommendation
Apply the same bounded-decompression pattern used elsewhere in the codebase: replace the raw `GzDecoder::read_to_end` in `decompress_program` with a size-limited read (e.g., wrap in `.take(max_size)` and reject if the decoder still has bytes left) analogous to `decompress_with_size_limit` in [5](#0-4) , ideally reusing `decode_and_decompress_with_size_limit` directly instead of ad hoc base64/gzip handling. Additionally, enforce this limit before any other work is performed on the request in the JSON-RPC layer, and consider bounding decompression time as well.

### Proof of Concept
1. Craft a `BROADCASTED_DECLARE_TXN_V1` JSON-RPC payload where `contract_class.program` is a base64-encoded gzip stream that decompresses to several GB from a KB-sized input (a standard "gzip bomb", e.g., repeating zero bytes compress extremely well).
2. Send it via `starknet_estimateFee` or `starknet_addDeclareTransaction` to a node's JSON-RPC endpoint.
3. Observe `decompress_program` (`crates/apollo_rpc/src/v0_8/api/mod.rs:671-682`) call `decoder.read_to_end(&mut decompressed)` with no size cap, causing the process's memory usage to spike unbounded until OOM-killed or the host becomes unresponsive — analogous to the reproduction steps in the referenced Minder advisory (`maliciousBody`/`io.MultiReader` unbounded read before validation).

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}

pub(crate) const MAX_DECOMPRESSED_SIZE: usize = 1 << 28; // 256 MB
// The compression level to use. Higher levels are slower but compress better.
const COMPRESSION_LEVEL: i32 = zstd::DEFAULT_COMPRESSION_LEVEL;

/// Returns the compressed data in a vector.
///
/// # Arguments
/// * data - bytes to compress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn compress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::compress(data, COMPRESSION_LEVEL)
}

/// Serialized and then compress object.
///
/// # Arguments
/// * object - the object to serialize and compress.
///
/// # Errors
/// Returns [`StorageSerdeError`] if any error is encountered in the serialization or compression.
pub fn serialize_and_compress(object: &impl StorageSerde) -> Result<Vec<u8>, StorageSerdeError> {
    let mut buf = Vec::new();
    object.serialize_into(&mut buf)?;
    Ok(compress(buf.as_slice())?)
}

/// Decompress data and returns it as bytes in a vector.
///
/// # Arguments
/// * data - bytes to decompress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn decompress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::decompress(data, MAX_DECOMPRESSED_SIZE)
}
