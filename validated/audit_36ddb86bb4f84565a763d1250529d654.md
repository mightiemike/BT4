### Title
`accept_new_txs` pause flag is enforced only at the HTTP server layer and can be bypassed by submitting transactions directly to the Gateway component's remote/local endpoint or via the mempool P2P path - ([File: crates/apollo_http_server/src/http_server.rs])

### Summary
The sequencer implements a "reject new transactions" pause mechanism (`accept_new_txs`) that is intended to let an operator stop transaction intake node-wide. This check is enforced exclusively in the HTTP server's request handlers, not in the `Gateway` component itself. Since the `Gateway` is reachable directly through its own `RemoteComponentServer`/`GatewayClient` interface (used, e.g., by `MempoolP2pRunner` to forward transactions relayed from peers), an unprivileged transaction sender/peer can have transactions admitted to the mempool while the node is supposedly "paused," exactly mirroring the reported bug class where a pause implemented at an outer "router" layer is bypassed by calling the underlying component directly.

### Finding Description
`accept_new_txs` is a dynamic config flag checked only inside the two HTTP handlers `add_rpc_tx` and `add_tx`: [1](#0-0) [2](#0-1) 

Both handlers call `check_new_transactions_are_allowed(accept_new_txs)` before forwarding the transaction to `app_state.gateway_client.add_tx(...)`. This flag is defined and documented as "Enables accepting new txs," which is the sequencer's closest analog to `ArrakisV2RouterStorage.pause()`/`unpause()` acting as an admission gate in front of the underlying state-changing entry point.

However, the actual admission logic (stateless validation, stateful validation, and forwarding to the mempool) lives entirely in `Gateway::add_tx` / `GenericGateway::add_tx_inner`, which has no knowledge of, and performs no check against, `accept_new_txs`: [3](#0-2) [4](#0-3) 

The `Gateway` component exposes this same `add_tx` entry point directly to other callers via its own component request handler and remote server, completely independent of the HTTP server: [5](#0-4) [6](#0-5) 

Concretely, `MempoolP2pRunner` — which forwards transactions received from other peers over gossipsub — calls `gateway_client.add_tx(GatewayInput { rpc_tx, message_metadata })` directly, entirely bypassing the HTTP server and therefore the `accept_new_txs` gate: [7](#0-6) 

In multi-service/distributed deployments the `Gateway`'s remote server is also bound to a network port (`components.gateway.remote_server_config`) that is reachable by any client that can route to it, again with no `accept_new_txs`/pause check anywhere on that path: [8](#0-7) 

This is architecturally identical to the reported issue: the "pause" is implemented as an admission check bolted onto one entry point (`ArrakisV2Router`/HTTP server) while the underlying component that actually performs the state-changing action (`vault.mint`/`burn` ≈ `Gateway.add_tx` ≈ `Mempool.add_tx`) has no independent enforcement of the same restriction and remains reachable through other paths (direct vault call ≈ direct Gateway RPC/P2P forwarding).

### Impact Explanation
If an operator sets `accept_new_txs = false` intending to stop the node from accepting further transactions (e.g., during an incident, migration, or graceful shutdown), transactions can still enter the mempool and subsequently the block-building pipeline via:
1. Any other node relaying transactions over the mempool P2P gossip protocol, which the local `MempoolP2pRunner` will forward straight into the local `Gateway`/`Mempool`, or
2. Any client with network access to the `Gateway`'s remote component server port in distributed deployments.

This undermines the operational safety guarantee the flag is meant to provide and can result in transactions being admitted and later included in blocks against operator intent, which is a functional/availability control bypass at the sequencer boundary.

### Likelihood Explanation
Likelihood is moderate to high in any deployment where mempool P2P is enabled (the default topology per `docs/diagrams/02-tx-submission-flow.md`) or where the Gateway's remote server is network-reachable independent of the HTTP server, since no additional privilege is required beyond normal transaction submission or normal peer-to-peer participation — both are unprivileged capabilities of any user/peer.

### Recommendation
Enforce the `accept_new_txs` (or an equivalent pause) check inside `Gateway::add_tx` / `GenericGateway::add_tx_inner` itself (via `ConfigManagerClient`/dynamic config already used elsewhere in the gateway), rather than only in the HTTP server's handlers, so that all entry points into transaction admission — HTTP, direct Gateway RPC, and P2P forwarding — are uniformly subject to the same pause control.

### Proof of Concept
1. Operator sets `http_server_config.dynamic_config.accept_new_txs = false`.
2. A client attempts `POST /gateway/add_transaction` → correctly rejected with `HttpServerError::DisabledError` via `check_new_transactions_are_allowed`. [2](#0-1) 
3. A peer broadcasts the same transaction over the mempool-P2P gossip topic. `MempoolP2pRunner` receives it and calls `gateway_client.add_tx(...)` directly. [7](#0-6) 
4. `Gateway::add_tx`/`add_tx_inner` runs stateless/stateful validation and forwards the transaction to the mempool with no check of `accept_new_txs` at all. [9](#0-8) 
5. The transaction is admitted to the mempool despite the node being configured to reject new transactions, confirming the pause bypass.

    async fn add_tx_inner(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        let mut metric_counters = GatewayMetricHandle::new(&tx, &p2p_message_metadata);
        metric_counters.count_transaction_received();
        if let RpcTransaction::Invoke(RpcInvokeTransaction::V3(ref inv)) = tx {
            if !inv.proof_facts.is_empty() {
                metric_counters.count_private_transaction_received();
            }
        }
        let is_p2p = p2p_message_metadata.is_some();

        if let RpcTransaction::Declare(ref declare_tx) = tx {
            if let Err(e) = self.check_declare_permissions(declare_tx) {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        }

        // Perform stateless validations.
        self.stateless_tx_validator.validate(&tx)?;

        let tx_signature = tx.signature().clone();

        // Declare conversions overload the compiler component's CPU and memory. Reject declares if
        // there are too many declares compiling in parallel. The permit is held only across
        // compilation and released before stateful validation.
        let compilation_permit = if matches!(tx, RpcTransaction::Declare(_)) {
            Some(self.declare_compilation_semaphore.try_acquire().map_err(|_| {
                let error = StarknetError::too_many_concurrent_declare_compilations();
                metric_counters.record_add_tx_failure(&error);
                error
            })?)
        } else {
            None
        };

        let (internal_tx, executable_tx, proof_data) =
            self.convert_rpc_tx_to_internal_and_executable_txs(tx, &tx_signature).await?;
        drop(compilation_permit);

        let mut stateful_transaction_validator = self
            .stateful_tx_validator_factory
            .instantiate_validator(self.config.dynamic_config.native_classes_whitelist.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let nonce = stateful_transaction_validator
            .extract_state_nonce_and_run_validations(&executable_tx, self.mempool_client.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let proof_archive_handle = self
            .store_proof_and_spawn_archiving(proof_data, internal_tx.tx_hash, is_p2p)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let gateway_output = create_gateway_output(&internal_tx);

        let add_tx_args = AddTransactionArgsWrapper {
            args: AddTransactionArgs::new(internal_tx, nonce),
            p2p_message_metadata,
        };

        // Await as late as possible for proof archiving before sending the transaction to the
        // mempool.
        Self::await_proof_archiving(proof_archive_handle)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let mempool_client_result = self.mempool_client.add_tx(add_tx_args).await;
        match mempool_client_result_to_deprecated_gw_result(&tx_signature, mempool_client_result) {
            Ok(()) => {}
            Err(e) => {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        };

        metric_counters.transaction_sent_to_mempool();

        Ok(gateway_output)
    }
