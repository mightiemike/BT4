## Analog Found: Division-Before-Multiplication in Gas Fee Calculation

### Title
Truncated base-fee division performed before multiplication by gasUsed causes systematic gas-fee undercharging - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`Keeper.CalculateGasCost` in `x/uexecutor/keeper/fees.go` reproduces the exact division-before-multiplication precision-loss pattern flagged in the external report's `Utils.sol` finding. The function converts the `LegacyDec` base fee to a raw upc value by dividing its internal representation by `1e18` *before* multiplying by `gasUsed`, instead of multiplying first and dividing once at the end.

### Finding Description
`CalculateGasCost` unwraps the fee-market base fee with integer division and only afterward multiplies by gas used: [1](#0-0) 

```
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
...
effectiveGasPrice := new(big.Int).Set(baseFeeBig)
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)
``` [2](#0-1) 

The code's own comment asserts "the base fee is always a whole number of upc -- no fractional upc exists," [3](#0-2)  but `baseFee` is supplied by `feemarketKeeper.GetBaseFee`, an interface typed as `sdkmath.LegacyDec` [4](#0-3) . EIP-1559-style fee markets (the `cosmos/evm` `x/feemarket` module used here) recompute the base fee every block by multiplying it by an elasticity-derived ratio (`gasUsed/targetGas`, `baseFeeChangeDenominator`, etc.), which generically produces a `LegacyDec` value that is *not* an exact multiple of `1e18`. When that happens, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates the fractional-upc remainder to zero **before** it is multiplied by `gasUsed`, rather than truncating once after the full `baseFee * gasUsed` product is computed. This is the identical bug class as `Utils._convertETHWeiToUSDWei()` in the external report: an intermediate division is performed first, discarding precision that should have survived until after the multiplication.

`CalculateGasCost` feeds directly into `DeductGasFeesFromReceipt`, which burns the computed `gasCost` from the recipient's account for every EVM-originated universal-execution transaction (inbound `FUNDS_AND_PAYLOAD`/gasless flows) that consumes gas: [5](#0-4) 

### Impact Explanation
Because truncation happens per-unit-of-base-fee rather than on the final product, the relative loss scales with the fractional part of the base fee and is **multiplied by the entire gas-used amount** rather than by 1. E.g., if the true base fee is `1.9` upc and `gasUsed = 100,000`, the correct burn is `190,000` upc, but the buggy calculation yields `floor(1.9) * 100,000 = 100,000` upc — a 47% under-collection on that single transaction. This directly corrupts the protocol's gas-fee accounting/burn invariant: unprivileged users systematically pay (and the protocol burns) less than the EIP-1559 formula dictates, for every ordinary gasless/UniversalPayload execution where the current base fee happens to carry a fractional-upc component (which is the expected steady-state under elasticity-based fee adjustment, not a rare edge case).

### Likelihood Explanation
This code path executes unconditionally on every EVM-originated universal execution with non-zero `GasUsed` and a `UniversalPayload`, triggered by ordinary user inbound transactions with no privileged actor required. It only fails to manifest if the fee-market's base fee is coincidentally always an exact multiple of `1e18` upc, which is not guaranteed by the elasticity/adjustment math of a standard `x/feemarket` implementation.

### Recommendation
Perform the multiplication before the division: compute `gasCost = (baseFeeBig_raw * gasUsedBig) / 1e18` in one step (using the full unrounded `LegacyDec`-encoded value, i.e. `baseFee.MulInt64(int64(gasUsed)).BigInt() / 1e18`, or equivalent `sdkmath.LegacyDec` multiplication followed by a single truncation at the end) instead of truncating the base fee to a whole upc value first.

### Proof of Concept
1. Fee market sets `BaseFee = 1_900_000_000_000_000_000` (i.e., 1.9 upc) as a `LegacyDec` (this is a normal, expected value after an elasticity adjustment, not an edge case).
2. A user submits an inbound `FUNDS_AND_PAYLOAD` transaction whose EVM execution consumes `gasUsed = 100_000`.
3. `CalculateGasCost` computes `baseFeeBig.Div(_, 1e18) = 1`, then `gasCost = 1 * 100_000 = 100_000` upc.
4. The mathematically correct EIP-1559 fee is `1.9 * 100_000 = 190_000` upc.
5. `DeductGasFeesFromReceipt` burns only `100_000` upc instead of `190_000` upc from the recipient, an under-collection of 90,000 upc (~47%) that recurs on every transaction while the base fee carries a fractional component.

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```
