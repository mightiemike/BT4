### Title
Unauthenticated `BOOTSTRAP` Declare Transaction Can Be Front-Run by Any Sender - ([File: crates/blockifier/src/transaction/account_transaction.rs])

### Summary
The sequencer implements a special "bootstrap declare" fast-path used to seed a brand-new chain with its first system classes for free, before any account exists. This path is gated only by a hardcoded literal sender address (`'BOOTSTRAP'`), `nonce == 0`, and zero resource bounds — there is no signature check, no `__validate_declare__` call, and (in the default/observed deployment configuration) no gateway-level authorization restricting who may submit it. Any unprivileged transaction sender can therefore craft and submit a `Declare` V3 transaction with `sender_address = 'BOOTSTRAP'`, `nonce = 0`, and zero resource bounds and have it accepted, front-running the legitimate sequencer-operator's own genesis bootstrap declarations.

### Finding Description
The bootstrap-declare check is implemented purely on transaction-field values, not on any proof of privilege: [1](#0-0) 

`is_bootstrap_declare` only checks `sender_address == bootstrap_address()` (a fixed felt derived from the ASCII string `"BOOTSTRAP"`), `nonce == 0`, and that fee is not being charged — all of which are attacker-controllable fields of a self-crafted transaction, since `'BOOTSTRAP'` is not a real deployed account and no signature/ownership is verified for it.

When this condition holds, `AccountTransaction::execute_raw` skips `perform_pre_validation_stage` (nonce/fee checks) entirely and skips the account's `__validate_declare__` entry point, directly declaring the class: [2](#0-1) 

The identical bypass exists in the Starknet OS Cairo re-implementation used for proving, so both blockifier execution and OS re-execution honor the same unauthenticated fast-path: [3](#0-2) 

The only gateway-level gate that could restrict who may submit such a declare is `authorized_declarer_accounts`, which is checked in `check_declare_permissions`: [4](#0-3) 

But this allow-list defaults to `None` (i.e., unrestricted — any address permitted), which is exactly the configuration required for real bootstrap operators to submit their own bootstrap declares at genesis (before any account is registered): [5](#0-4) [6](#0-5) 

This is confirmed by the shipped deployment overlays, which explicitly leave `authorized_declarer_accounts` unset: [7](#0-6) 

The documented behavior itself acknowledges the mempool re-proposes this transaction indefinitely until it fails: [8](#0-7) 

This is the direct structural analog of the reported vulnerability class: an "initializer" (here, the one-time, no-fee, no-signature class-registration path meant to bootstrap a fresh system) lacks any access-control check tied to the actual privileged party (the sequencer operator), relying solely on a public, guessable constant (`'BOOTSTRAP'`) that any unprivileged transaction sender can also use as `sender_address`.

### Impact Explanation
Because the `BOOTSTRAP` sender's nonce is never incremented on this path and no signature is required, any party can repeatedly submit zero-fee `Declare` transactions with `sender_address = 'BOOTSTRAP'`, `nonce = 0`, targeting arbitrary (attacker-chosen, but content-addressed) class hashes. Since the mempool/consensus can generally only carry one in-flight transaction per `(sender_address, nonce)` key, an attacker can continuously occupy the `(BOOTSTRAP, 0)` slot with junk declarations, front-running and starving out the legitimate operator's own genesis bootstrap declares of the chain's real system contracts (e.g., account/fee-token classes). During chain genesis this can prevent the network from ever completing bootstrap and confirming further transactions, and even after genesis it provides a permanent, unauthenticated, free (`max_possible_fee == 0`) class-declaration/compilation path bypassing normal fee and validation machinery.

### Likelihood Explanation
The precondition — `authorized_declarer_accounts` left unset — is the shipped default and is what appears in the repository's own hybrid deployment configuration overlays, so it is the realistic operating configuration, not a misconfiguration. Constructing the transaction requires only knowledge of the public constant `'BOOTSTRAP'` felt value and setting zero resource bounds; no private key or prior state is needed.

### Recommendation
Restrict the bootstrap-declare fast path so it cannot be exercised by externally-submitted transactions once the chain is live: e.g., disable/expire `is_bootstrap_declare` handling entirely after the genesis block(s) are produced, or require gateway/consensus-level authorization (independent of the general `authorized_declarer_accounts` allow-all default) specifically for `sender_address == bootstrap_address()`, so only the trusted deployment/bootstrap process can submit it.

### Proof of Concept
1. Deploy/observe a sequencer running with the default (or shipped hybrid overlay) gateway configuration, where `gateway_config.static_config.authorized_declarer_accounts` is unset (`#is_none: true`).
2. Craft a `Declare` V3 RPC transaction with `sender_address = ContractAddress::from(0x424f4f545354524150_u128)` (the `'BOOTSTRAP'` felt, see `bootstrap_address()`), `nonce = Nonce(0)`, all resource bounds set to zero, and an arbitrary valid Sierra class + matching `compiled_class_hash`.
3. Submit it via the gateway's `add_tx`; `check_declare_permissions` passes because `authorized_declarer_accounts` is `None`.
4. In execution, `is_bootstrap_declare` evaluates true, `perform_pre_validation_stage`/`__validate_declare__` are skipped, and the class is declared for free without any signature check.
5. Repeat with distinct throwaway classes (or race the legitimate operator's own `(BOOTSTRAP, 0)` bootstrap declare) to occupy the shared `(sender, nonce)` slot and block the intended genesis declarations.

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }

        // meet the following conditions.
        // This flow is used for the sequencer to bootstrap a new system.
        // Note: The absence of any account-related action leads to some unintuitive but expected
        // behavior:
        // - After the transaction is executed successfully, the batcher does not notify the mempool
        //   about its inclusion in a block. As a result, the transaction remains in the mempool.
        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.
        // - The transaction will then be marked as rejected, the mempool will be notified, and the
        //   transaction will be removed from the mempool.
        if let Transaction::Declare(tx) = &self.tx {
            if tx.is_bootstrap_declare(self.execution_flags.charge_fee) {
                let mut context = EntryPointExecutionContext::new_invoke(
                    tx_context.clone(),
                    self.execution_flags.charge_fee,
                    SierraGasRevertTracker::new(GasAmount::default()),

                let mut remaining_gas = 0;
                let res = tx.run_execute(state, &mut context, &mut remaining_gas)?;
                assert!(res.is_none(), "Declare execute should not result in a CallInfo.");

                return Ok(TransactionExecutionInfo::default());

    fn check_declare_permissions(
        &self,
        declare_tx: &RpcDeclareTransaction,
    ) -> Result<(), StarknetError> {
        // TODO(noamsp): Return same error as in Python gateway.
        if self.config.static_config.block_declare {
            return Err(StarknetError {

                ),
                message: "Transaction type is temporarily blocked.".to_string(),

        let RpcDeclareTransaction::V3(declare_v3_tx) = declare_tx;

                code: StarknetErrorCode::KnownErrorCode(
                    KnownStarknetErrorCode::UnauthorizedDeclare,
                ),
                message: format!(
                    "Account address {} is not allowed to declare contracts.",
                    &declare_v3_tx.sender_address
                ),
