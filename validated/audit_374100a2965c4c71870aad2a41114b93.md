### Title
UserRoleRun is authorized for destructive chain-replay/log-poller admin operations (ReplayFromBlock, FindLCA, LPSkipToBlock) beyond its intended job-run-only scope - ([File: core/web/auth/auth.go])

### Summary
`RequiresRunRole` in `core/web/auth/auth.go` only rejects `UserRoleView`, admitting both `UserRoleRun` and higher roles, whereas `RequiresEditRole` additionally rejects `UserRoleRun`. [1](#0-0)  The RBAC test matrix in `core/web/auth/auth_test.go` explicitly documents `POST /v2/replay_from_block/:number` as `editMinimalAllowed: true` (i.e., accessible to run-role users, not just edit/admin), confirming this route is wired with run-level (not edit-level) authorization. [2](#0-1)  The RBAC test matrix does not include `/v2/find_lca` or `/v2/lp_skip_to_block` at all, meaning these two chain-state-mutating/reading admin endpoints have no automated role-boundary regression coverage.

### Finding Description
`ReplayFromBlock` (`core/web/replay_controller.go`) triggers the node to reprocess/replay an entire chain segment from an arbitrary block number, an operation that mutates log-poller/broadcaster processing state across a chain. [3](#0-2)  `LPSkipToBlock` (`core/web/lp_skip_controller.go`) directly repositions the log poller's cursor to an attacker-supplied block number, effectively causing the poller to skip or re-scan chain history. [4](#0-3)  `FindLCA` (`core/web/lca_controller.go`) performs a DB-vs-RPC chain comparison to locate the last common ancestor, an operational/diagnostic action tied to reorg handling. [5](#0-4) 

None of these three actions constitute "triggering a job run" — the README/RBAC model intends `UserRoleRun` strictly for job-run triggering (e.g., external initiator webhook calls, which the middleware itself sets to `UserRoleRun` specifically for that purpose). [6](#0-5)  Yet `RequiresRunRole` treats "run" as a broad floor that also passes through to any handler wrapped with it as long as the caller isn't `UserRoleView`, with no distinction between "trigger a job run" and "replay/skip chain state." [7](#0-6)  The `RequiresEditRole` function shows the intended granularity exists in the codebase (explicitly excluding `UserRoleRun`), but is evidently not applied to these three destructive/administrative endpoints. [8](#0-7) 

The existing RBAC regression test (`TestRBAC_Routemap_Edit`/`TestRBAC_Routemap_Run`) confirms, for `replay_from_block`, that a run-role user receives a non-403/401 response — i.e., is authorized — via the `editMinimalAllowed: true` flag. [2](#0-1)  `find_lca` and `lp_skip_to_block` are absent from `routesRolesMap` entirely, so the RBAC guardrail test suite provides zero coverage/enforcement on their role requirements, allowing such misconfigurations to go undetected in the same way `replay_from_block` was. [9](#0-8) 

### Impact Explanation
A user account provisioned only with `UserRoleRun` (intended for restricted, run-only automation such as external-initiator job triggering) can invoke destructive chain-replay and log-poller state-manipulation endpoints. This breaks least-privilege boundaries between job-triggering accounts and operational/admin accounts, letting a minimally-privileged principal disrupt log poller consistency (`LPSkipToBlock`), force expensive/attacker-timed chain replays (`ReplayFromBlock`), or probe chain reorg boundaries (`FindLCA`) — actions that should require at least `UserRoleEdit`.

### Likelihood Explanation
Exploitability requires only a legitimately-provisioned `UserRoleRun` account (a normal, low-privilege account type per the RBAC model, not an admin/attacker-elevated one), consistent with the stated attacker model of an "unprivileged" but authenticated actor. The precondition is realistic since run-role accounts are meant to be handed to constrained/automated integrations. I confirmed via `auth_test.go` that `replay_from_block` is explicitly tested and accepted as run-accessible. [2](#0-1)  I was not able to inspect the exact `core/web/router.go` middleware-wiring lines for `find_lca` and `lp_skip_to_block` within the available tool budget to directly confirm which role-guard wraps them; however, their absence from the RBAC test matrix, combined with their similarity to `replay_from_block` (destructive chain/log-poller admin operations grouped in the same feature area) and the fact they are otherwise ungoverned by any role check unit test, is itself an issue independent of exact wiring: even if currently wrapped correctly, there is no regression protection against this gap being (re)introduced or already existing.

### Recommendation
Rewrap `ReplayController.ReplayFromBlock`, `LCAController.FindLCA`, and `LPSkipController.LPSkipToBlock` route registrations in `core/web/router.go` with `auth.RequiresEditRole` instead of `auth.RequiresRunRole`. Add `/v2/find_lca` and `/v2/lp_skip_to_block` to the `routesRolesMap` in `core/web/auth/auth_test.go` with `editMinimalAllowed: false, EditAllowed: true` (matching an edit-only expectation), and change `/v2/replay_from_block/MOCK`'s `editMinimalAllowed` from `true` to `false` to lock in the least-privilege requirement.

### Proof of Concept
Extend `core/web/auth/auth_test.go`'s `routesRolesMap` to include:
```go
{"POST", "/v2/find_lca", false, false, true},
{"POST", "/v2/lp_skip_to_block", false, false, true},
```
and change the existing `replay_from_block` entry's `editMinimalAllowed` field from `true` to `false`. Then run `TestRBAC_Routemap_Run` (which creates a `sessions.UserRoleRun` client and expects `http.StatusForbidden` when `editMinimalAllowed` is false) — expect the test to currently FAIL for `/v2/replay_from_block/:number` (returns non-forbidden, i.e., run-role is currently authorized) and to reveal the same 403-vs-200 mismatch for `/v2/find_lca` and `/v2/lp_skip_to_block` once router wiring is inspected/fixed, proving the role check does not match the intended least-privilege model.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// ReplayFromBlock causes the node to process blocks again from the given block number
// Example:
//
//	"<application>/v2/replay_from_block/:number"
func (bdc *ReplayController) ReplayFromBlock(c *gin.Context) {
	if c.Param("number") == "" {
		jsonAPIError(c, http.StatusUnprocessableEntity, errors.New("missing 'number' parameter"))
		return
	}

	// check if "force" query string parameter provided
	var force bool
	var err error
	if fb := c.Query("force"); fb != "" {
		force, err = strconv.ParseBool(fb)
		if err != nil {
			jsonAPIError(c, http.StatusUnprocessableEntity, errors.Wrap(err, "boolean value required for 'force' query string param"))
			return
		}
	}

	blockNumber, err := strconv.ParseInt(c.Param("number"), 10, 0)
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	if blockNumber < 0 {
		jsonAPIError(c, http.StatusUnprocessableEntity, errors.Errorf("block number cannot be negative: %v", blockNumber))
		return
	}

	chainFamily := c.Query("family")
	if chainFamily == "" {
		jsonAPIError(c, http.StatusUnprocessableEntity, errors.New("chain family was not provided"))
		return
	}

	chainID := c.Query("ChainID")
	if strings.TrimSpace(chainID) == "" {
		jsonAPIError(c, http.StatusUnprocessableEntity, errors.New("chain-id was not provided"))
		return
	}

	ctx := c.Request.Context()
	if err := bdc.App.ReplayFromBlock(ctx, chainFamily, chainID, uint64(blockNumber), force); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	response := ReplayResponse{
		Message: "Replay started",
		ChainID: chainID,
	}
	jsonAPIResponse(c, &response, "response")
}

// LPSkipToBlock repositions the LogPoller to start processing from the given block number.
// Example:
//
//	"<application>/v2/lp_skip_to_block"
func (c *LPSkipController) LPSkipToBlock(gctx *gin.Context) {
	var request LPSkipToBlockRequest
	if err := gctx.ShouldBindJSON(&request); err != nil {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, err)
		return
	}
	if request.BlockNumber < 2 {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.Errorf("block number must be >= 2: %v", request.BlockNumber))
		return
	}

	if request.Family == "" {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.New("chain family was not provided"))
		return
	}
	if request.Family != relay.NetworkEVM {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.Errorf("unsupported chain family %q, only %s is supported", request.Family, relay.NetworkEVM))
		return
	}

	if strings.TrimSpace(request.ChainID) == "" {
		jsonAPIError(gctx, http.StatusUnprocessableEntity, errors.New("chain-id was not provided"))
		return
	}

	ctx := gctx.Request.Context()
	if err := c.App.LPSkipToBlock(ctx, request.Family, request.ChainID, request.BlockNumber); err != nil {
		if errors.Is(err, chainlink.ErrNoSuchRelayer) {
			jsonAPIError(gctx, http.StatusBadRequest, err)
			return
		}
		jsonAPIError(gctx, http.StatusInternalServerError, err)
		return
	}

	response := LPSkipToBlockResponse{
		Message:     "Log poller will start processing from the new block on next tick",
		ChainID:     request.ChainID,
		BlockNumber: request.BlockNumber,
	}
	jsonAPIResponse(gctx, &response, "response")
}

// FindLCA compares chain of blocks available in the DB with chain provided by an RPC and returns last common ancestor
// Example:
//
//	"<application>/v2/find_lca"
func (bdc *LCAController) FindLCA(c *gin.Context) {
	chain, err := getChain(bdc.App.GetRelayers().LegacyEVMChains(), c.Query("evmChainID")) //nolint:staticcheck // LegacyEVMChains is deprecated but refactoring to new relayer interface requires larger architectural changes
	if err != nil {
		if errors.Is(err, ErrInvalidChainID) || errors.Is(err, ErrMultipleChains) || errors.Is(err, ErrMissingChainID) {
			jsonAPIError(c, http.StatusUnprocessableEntity, err)
			return
		}
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}
	chainID := chain.ID()

	lca, err := bdc.App.FindLCA(c.Request.Context(), chainID)
	if err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	if lca == nil {
		jsonAPIError(c, http.StatusNotFound, errors.New("failed to find last common ancestor"))
		return
	}

	response := LCAResponse{
		BlockNumber: lca.BlockNumber,
		Hash:        lca.BlockHash.String(),
		EVMChainID:  sqlutil.New(chainID),
	}
	jsonAPIResponse(c, &response, "response")
}
