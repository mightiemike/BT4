### Title
Missing `withdrawReward`/`VoteRewardUtil.withdrawReward` cleanup call in `CancelAllUnfreezeV2Actuator`/`CancelAllUnfreezeV2Processor` before mutating resource weight and frozen state - (File: `actuator/src/main/java/org/tron/core/actuator/CancelAllUnfreezeV2Actuator.java`, `actuator/src/main/java/org/tron/core/vm/nativecontract/CancelAllUnfreezeV2Processor.java`)

### Summary
Every other actuator/native-contract processor in java-tron that mutates an account's frozen balance, resource weight, or votes (i.e. state that feeds into reward computation) begins by calling the reward "clean up" routine — `MortgageService.withdrawReward()` at the actuator level, or `VoteRewardUtil.withdrawReward()` at the TVM native-contract level — before applying the state change. `CancelAllUnfreezeV2Actuator.execute()` and its TVM counterpart `CancelAllUnfreezeV2Processor.execute()` do not call this routine at all, even though they mutate `FrozenV2`, `UnfrozenV2`, and the global `TotalNetWeight`/`TotalEnergyWeight`/`TotalTronPowerWeight` counters, and restore `oldTronPower`-relevant state without going through the same initialize/invalidate bookkeeping used elsewhere.

### Finding Description
The pattern across the codebase is consistent:
- `UnfreezeBalanceActuator.execute()` calls `mortgageService.withdrawReward(ownerAddress)` first [1](#0-0) .
- `UnfreezeBalanceV2Actuator.execute()` calls `mortgageService.withdrawReward(ownerAddress)` before touching frozen/unfrozen lists, total weights, or votes [2](#0-1) .
- `WithdrawBalanceActuator.execute()` and `VoteWitnessActuator.countVoteAccount()` do the same, both marked with an explicit `//` comment line calling out the step [3](#0-2) [4](#0-3) .
- On the TVM native-contract side, `UnfreezeBalanceV2Processor.execute()`, `VoteWitnessProcessor.execute()`, and `WithdrawRewardProcessor.execute()` all invoke `VoteRewardUtil.withdrawReward(ownerAddress, repo)` as the first step [5](#0-4) [6](#0-5) [7](#0-6) .

In contrast, `CancelAllUnfreezeV2Actuator.execute()` — which re-freezes previously-pending unfreeze balances, adds them back into `FrozenV2`, and bumps `TotalNetWeight`/`TotalEnergyWeight`/`TotalTronPowerWeight` — performs none of this cleanup, nor does it touch the `oldTronPower` initialize/invalidate bookkeeping (`oldTronPowerIsNotInitialized`/`initializeOldTronPower`/`invalidateOldTronPower`) that every other weight-mutating actuator applies [8](#0-7) . The TVM equivalent `CancelAllUnfreezeV2Processor.execute()` mirrors this same omission [9](#0-8) .

This is structurally the same bug class as the Reality Cards report: a "clean up stale accounting before mutating balance/weight state" routine that is consistently invoked by sibling code paths is missing from one specific path that also mutates the same accounting state.

### Impact Explanation
Because `withdrawReward`/`VoteRewardUtil.withdrawReward` is responsible for snapshotting reward-cycle bookkeeping (`beginCycle`/`endCycle`, per-cycle vote snapshot) before the account's underlying resource/weight state changes, skipping it in `CancelAllUnfreezeV2` means the reward-cycle snapshot used for later reward computation is taken (whenever it eventually runs) against a state that has already silently changed via the cancel operation, without the intermediate step being recorded through the normal path. This can produce reward/vote/resource-weight bookkeeping drift for the account performing the cancel, i.e., accounting corruption analogous to the "closed-market bids still counted" issue in the original report — stale/mis-attributed state persists because the expected cleanup call is absent from this one path.

### Likelihood Explanation
`CancelAllUnfreezeV2` is a reachable, permissionless user-triggered transaction (`CancelAllUnfreezeV2Contract`) and TVM opcode (`cancelAllUnfreezeV2Action` in `Program.java`), gated only by the `supportAllowCancelAllUnfreezeV2` chain parameter, so any account with a pending unfreeze can trigger this path without special privileges [10](#0-9) . The likelihood of the omission mattering in practice depends on whether reward computation elsewhere in `MortgageService`/`VoteRewardUtil` is sensitive to the exact ordering of weight changes versus cycle-snapshotting — this could not be fully confirmed from the available code paths, so this should be treated as a structural inconsistency finding rather than a proven exploit.

### Recommendation
Add the same `mortgageService.withdrawReward(ownerAddress)` call (actuator) / `VoteRewardUtil.withdrawReward(ownerAddress, repo)` call (TVM processor) at the start of `CancelAllUnfreezeV2Actuator.execute()` and `CancelAllUnfreezeV2Processor.execute()`, consistent with every other actuator/processor that mutates frozen balance, resource weight, or vote-related state, and audit whether the `oldTronPower` initialize/invalidate bookkeeping also needs to be applied in this path for consistency with `UnfreezeBalanceV2Actuator`/`UnfreezeBalanceV2Processor`.

### Proof of Concept
Not independently reproduced; based on static comparison of `CancelAllUnfreezeV2Actuator.execute()` [8](#0-7)  and `CancelAllUnfreezeV2Processor.execute()` [9](#0-8)  against the consistent `withdrawReward` pattern used in `UnfreezeBalanceV2Actuator.execute()` [11](#0-10)  and `UnfreezeBalanceV2Processor.execute()` [5](#0-4) .

  public boolean execute(Object result) throws ContractExeException {
    TransactionResultCapsule ret = (TransactionResultCapsule) result;

    }
    long fee = calcFee();
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    byte[] ownerAddress;
    try {
      ownerAddress = getOwnerAddress().toByteArray();
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    }
    AccountCapsule ownerCapsule = accountStore.get(ownerAddress);
    List<UnFreezeV2> unfrozenV2List = ownerCapsule.getUnfrozenV2List();
    long now = dynamicStore.getLatestBlockHeaderTimestamp();
    AtomicLong atomicWithdrawExpireBalance = new AtomicLong(0L);
    /* The triple object is defined by resource type, with left representing the pair object
    corresponding to bandwidth, middle representing the pair object corresponding to energy, and
    right representing the pair object corresponding to tron power. The pair object for each
    resource type, left represents resource weight, and right represents the number of unfreeze
    resources for that resource type. */
    Triple<Pair<AtomicLong, AtomicLong>, Pair<AtomicLong, AtomicLong>, Pair<AtomicLong, AtomicLong>>
        triple = Triple.of(
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)),
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)),
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)));
    for (UnFreezeV2 unFreezeV2 : unfrozenV2List) {
      updateAndCalculate(triple, ownerCapsule, now, atomicWithdrawExpireBalance, unFreezeV2);
    }
    ownerCapsule.clearUnfrozenV2();
    addTotalResourceWeight(dynamicStore, triple);

    long withdrawExpireBalance = atomicWithdrawExpireBalance.get();
    if (withdrawExpireBalance > 0) {
      ownerCapsule.setBalance(ownerCapsule.getBalance() + withdrawExpireBalance);
    }

    accountStore.put(ownerCapsule.createDbKey(), ownerCapsule);
    ret.setWithdrawExpireAmount(withdrawExpireBalance);
    Map<String, Long> cancelUnfreezeV2AmountMap = new HashMap<>();
    cancelUnfreezeV2AmountMap.put(BANDWIDTH.name(), triple.getLeft().getRight().get());
    cancelUnfreezeV2AmountMap.put(ENERGY.name(), triple.getMiddle().getRight().get());
    cancelUnfreezeV2AmountMap.put(TRON_POWER.name(), triple.getRight().getRight().get());
    ret.putAllCancelUnfreezeV2AmountMap(cancelUnfreezeV2AmountMap);
    ret.setStatus(fee, code.SUCESS);
    return true;
  }

  public Map<String, Long> execute(CancelAllUnfreezeV2Param param, Repository repo) throws ContractExeException {
    Map<String, Long> result = new HashMap<>();
    byte[] ownerAddress = param.getOwnerAddress();
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    long now = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    long withdrawExpireBalance = 0L;
    for (Protocol.Account.UnFreezeV2 unFreezeV2: ownerCapsule.getUnfrozenV2List()) {
      if (unFreezeV2.getUnfreezeExpireTime() > now) {
        String resourceName = unFreezeV2.getType().name();
        result.put(resourceName, result.getOrDefault(resourceName, 0L) + unFreezeV2.getUnfreezeAmount());

        updateFrozenInfoAndTotalResourceWeight(ownerCapsule, unFreezeV2, repo);
      } else {
        // withdraw
        withdrawExpireBalance += unFreezeV2.getUnfreezeAmount();
      }
    }
    if (withdrawExpireBalance > 0) {
      ownerCapsule.setBalance(ownerCapsule.getBalance() + withdrawExpireBalance);
    }
    ownerCapsule.clearUnfrozenV2();

    repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);

    result.put(VMConstant.WITHDRAW_EXPIRE_BALANCE, withdrawExpireBalance);
    return result;
  }
