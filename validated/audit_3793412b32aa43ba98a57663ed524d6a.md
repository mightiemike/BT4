## Analysis

The Capgo bug class — a resource that should be excluded after deletion but remains selectable because a specific code path skips the deletion filter — has a direct analog in the sequencer's contract-class caching layer.

### Title
Stale Cairo 0 (deprecated) Class Remains Executable From Global Cache After Its Declaring Block Is Reverted — Missing `is_declared` Verification Filter (File: `crates/blockifier/src/state/state_reader_and_contract_manager.rs`)

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` serves compiled classes from a process-wide `GlobalContractCache` (`ContractClassManager`). For Cairo 1 classes it explicitly re-verifies declaration status against the state reader before trusting a cache hit, specifically to guard against serving "a declared class from a reverted block." That same verification is unconditionally skipped for Cairo 0 (deprecated/V0) classes, and the reason is structural: `FetchCompiledClasses::is_declared` is documented and implemented to always return `false` for Cairo 0 classes, so it cannot be used to validate them. This leaves V0 class cache entries with no invalidation mechanism whatsoever when the declaring block is reverted.

### Finding Description
In `get_compiled_from_class_manager`: [1](#0-0) 

the match arm explicitly no-ops for `RunnableCompiledClass::V0(_)`, while non-V0 (Cairo 1) classes are re-checked via `self.state_reader.is_declared(class_hash)`. The accompanying comment states this check exists precisely because "existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)" — i.e., the developers were aware of and explicitly patched this exact bug class for Cairo 1, but the fix could not be extended to Cairo 0 because: [2](#0-1) 

`is_declared` is documented to always return `false` for Cairo 0 classes and is implemented that way in production readers, e.g. `apollo_state_reader::ApolloReader::is_declared` only inspects the Cairo-1 declared-classes table: [3](#0-2) 

and `DictStateReader::is_declared` documents "Cairo0 classes are not declared": [4](#0-3) 

Meanwhile, storage-level reverts do delete deprecated declared classes when the declaring block is rolled back: [5](#0-4) 
via `revert_block`, which walks header/body/state-diff/class-manager markers: [6](#0-5) 

So after such a revert, the storage-level state correctly reflects that the class is no longer declared (analogous to Capgo's `app_versions.deleted` flag), but the sequencer's in-memory `GlobalContractCache`/`ContractClassManager` (`crates/starknet_api/src/class_cache.rs`, `crates/blockifier/src/state/global_cache.rs`) still holds the compiled V0 class with no filter to reject it on lookup.

### Impact Explanation
Any node/process that has previously cached a Cairo 0 class (e.g., by executing a `DEPLOY`/`DEPLOY_ACCOUNT`/invoke that used it before a revert) will continue to treat it as declared and executable indefinitely after the revert, while a node whose cache was cold (or was cleared) at that moment will correctly reject the class hash as undeclared via `get_compiled_classes` → `StateError::UndeclaredClassHash`. This creates execution-result divergence for a transaction/class hash between honest nodes purely based on transient cache state, which can produce different state roots/committed state between sequencer instances (or across a sequencer restart vs. no-restart), i.e. exactly the class of "unauthorized action on a deleted resource" harm described in the Capgo report, mapped to consensus-relevant state (wrong committed root / honest-node divergence).

### Likelihood Explanation
Reverts of committed blocks are an operational reality that this codebase explicitly supports and tests for (`apollo_reverts`, `revert_state_diff`, the "0.11" historical-revert comments in `apollo_storage/src/state/mod.rs`). Any Cairo 0 class declared and exercised in a block that is later reverted, on a sequencer process that had already warmed its `ContractClassManager` cache for that class hash, hits this gap with no additional attacker sophistication required — a single legitimate declare+use of a Cairo 0 class followed by a revert (which the developers already anticipated for the V1 path) is sufficient to reproduce it.

### Recommendation
Extend the reverted-class verification to Cairo 0 classes. Since `is_declared` structurally cannot answer this for V0 classes, add a storage-backed check equivalent (e.g., `get_deprecated_class_definition_block_number`) that the class manager can call for `RunnableCompiledClass::V0` cache hits, mirroring the existing Cairo 1 guard, or invalidate/evict the relevant class cache entries as part of `revert_block`/`try_revert_class_manager_marker`.

### Proof of Concept
1. Declare and deploy a Cairo 0 (deprecated) class `C` in block `N`; a sequencer process executes a transaction referencing `C`, warming `ContractClassManager`'s `class_cache` with `CompiledClasses::V0(...)` for `C`.
2. Trigger `revert_block` down to before block `N` (via `apollo_reverts::revert_block`), which calls `delete_deprecated_declared_classes`/`delete_deprecated_declared_classes_block`, removing `C` from the `deprecated_declared_classes` table.
3. On the same warm process, submit another transaction referencing class hash `C` (e.g., deploying a new contract with class hash `C`, or invoking one already deployed with it). `get_compiled_from_class_manager` hits the cache, matches `RunnableCompiledClass::V0(_)`, performs no `is_declared` check, and returns the stale compiled class — the transaction executes successfully.
4. On a second node/process without a warm cache for `C` (or after cache eviction), the same transaction fails with `StateError::UndeclaredClassHash(C)` via `get_compiled_classes`, producing divergent execution outcomes for identical inputs.

fn delete_deprecated_declared_classes<'env>(
    txn: &'env DbTransaction<'env, RW>,
    block_number: BlockNumber,
    thin_state_diff: &ThinStateDiff,
    deprecated_declared_classes_table: &'env DeprecatedDeclaredClassesTable<'env>,
    file_handlers: &FileHandlers<RW>,
) -> StorageResult<IndexMap<ClassHash, DeprecatedContractClass>> {
    // Class hashes of the contracts that were deployed in this block.
    let deployed_contracts_class_hashes = thin_state_diff.deployed_contracts.values();

    // Merge the class hashes from the state diff and from the deployed contracts into a single
    // unique set.
    let class_hashes: HashSet<&ClassHash> = thin_state_diff
        .deprecated_declared_classes
        .iter()
        .chain(deployed_contracts_class_hashes)
        .collect();

    let mut deleted_data = IndexMap::new();
    for class_hash in class_hashes {
        // If the class is not in the deprecated classes table, it means that either we didn't
        // download it yet or the hash is of a deployed contract of a new class type. We've decided
        // to avoid deleting these classes because they're from at most 0.11.
        if let Some(IndexedDeprecatedContractClass {
            block_number: declared_block_number,
            location_in_file,
        }) = deprecated_declared_classes_table.get(txn, class_hash)?
        {
            // If the class was declared in a different block then we should'nt delete it.
            if block_number == declared_block_number {
                deleted_data.insert(
                    *class_hash,
                    file_handlers.get_deprecated_contract_class_unchecked(location_in_file)?,
                );
                deprecated_declared_classes_table.delete(txn, class_hash)?;
            }
        }
    }

    Ok(deleted_data)
}

/// Reverts everything related to the block, will succeed even if there is partial information for
/// the block.
// This function will panic if the storage reader fails to revert.
pub fn revert_block(storage_writer: &mut StorageWriter, target_block_marker: BlockNumber) {
    let txn = storage_writer
        .begin_rw_txn()
        .unwrap()
        .revert_header(target_block_marker)
        .unwrap()
        .0
        .revert_body(target_block_marker)
        .unwrap()
        .0
        .revert_state_diff(target_block_marker)
        .unwrap()
        .0
        .try_revert_class_manager_marker(target_block_marker)
        .unwrap()
        .try_revert_base_layer_marker(target_block_marker)
        .unwrap()
        .revert_partial_block_hash_components(&target_block_marker)
        .unwrap()
        .revert_block_hash(&target_block_marker)
        .unwrap()
        .revert_global_root(&target_block_marker)
        .unwrap();

    #[cfg(feature = "os_input")]
    let txn = txn.revert_accessed_keys(target_block_marker).unwrap();

    txn.commit().unwrap();
}
