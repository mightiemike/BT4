### Title
Unbounded recursion in compiled-class-hash computation over attacker-controlled bytecode segment structure enables stack-overflow DoS - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs])

### Summary
The `bytecode_hash_node` function recursively walks a `NestedIntList` tree describing how a declared contract's CASM bytecode is segmented, in order to compute the compiled class hash. This tree's shape and depth are derived from the CASM produced by compiling an attacker-submitted Sierra program, and the recursive walk has no depth bound, matching the jq `jv_dump_term` bug class (unbounded recursion over an attacker-influenced nested structure causing stack exhaustion).

### Finding Description
`bytecode_hash_node` recurses once per level of the `NestedIntList` segment tree, with no maximum-depth check: [1](#0-0) 

This function is invoked from `hash_inner`, which is the sole implementation of `HashableCompiledClass::hash`, called for every declared class in multiple contexts (compiler pipeline, gateway/class-manager, storage, batcher/os re-execution): [2](#0-1) 

Critically, in the Sierra compiler service, hash computation happens in the *parent* process after the CASM is returned from the resource-limited compilation subprocess — it is not itself resource-limited or depth-guarded: [3](#0-2) 

`get_bytecode_segment_lengths` takes the `bytecode_segment_lengths` field straight from the compiler's `CasmContractClass` output: [4](#0-3) 

The segment tree's nesting depth is a function of the structure of the (attacker-submitted) Sierra program — the compiler's bytecode-segmentation strategy nests segments according to a program's function/branch structure. The gateway bounds the total bytecode *size* (`max_bytecode_size`) and the number of *concurrent* compilations, but nothing in this path bounds the *depth* of the resulting segment tree: [5](#0-4) 

This is structurally analogous to the reported jq CVE-2016-4074: a recursive dump/serialize routine over a nested structure whose depth is attacker-controlled, with no recursion-depth guard, leading to stack exhaustion. The codebase elsewhere explicitly guards against this class of issue for *execution* recursion (`RecursionDepthGuard`, `max_recursion_depth`, and dedicated large stacks for Cairo Native execution): [6](#0-5) [7](#0-6) 

but no equivalent protection exists for `bytecode_hash_node`.

### Impact Explanation
If a crafted declare transaction produces a CASM class whose `bytecode_segment_lengths` tree is deep enough, every node (gateway, sierra-compiler service, class manager, batcher, and any node re-executing/verifying the block, including the Starknet OS/committer paths that also perform analogous nested-segment hashing) that computes the compiled class hash via `hash_inner`/`bytecode_hash_node` will attempt the same unbounded recursion and can crash with a stack overflow. Because this hash is computed as part of normal declare-transaction ingestion/validation (not inside a sandboxed, depth-limited subprocess), a single malicious declare transaction could crash gateway/class-manager processes network-wide, i.e., a network-halting DoS reachable by a single contract declarer — matching the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Reachable directly from an unprivileged declare transaction (attacker only needs to craft a Sierra program that compiles to a CASM with a deeply nested segment structure); no special privileges required. Likelihood depends on whether the underlying Cairo compiler (`cairo_lang_starknet_classes`) can actually be coerced into producing arbitrarily deep `NestedIntList` trees within the existing `max_bytecode_size` bound — this repo does not control that compiler's segmentation algorithm, so confirming exploitability requires testing against the actual compiler binary used (`apollo_compile_to_casm`), which is out of scope for static analysis alone.

### Recommendation
Add an explicit recursion-depth bound/iterative rewrite for `bytecode_hash_node` (and the equivalent `bytecode_hash_node` in the Cairo OS hint implementation and `.cairo` counterparts), mirroring the `RecursionDepthGuard` pattern already used for entry-point call recursion, and reject/skip classes whose segment tree exceeds a safe depth before attempting to hash them.

### Proof of Concept
Not executed — would require driving the actual `cairo_lang_starknet_classes` Sierra→CASM compiler with a crafted Sierra program to confirm it emits a `bytecode_segment_lengths` `NestedIntList` deep enough to overflow the default thread stack when `bytecode_hash_node` recurses over it. This requires running the real compiler binary/toolchain, which is not available via static code review alone.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

fn hash_inner<H, EH, NL>(hashable_class: &impl HashableCompiledClass<EH, NL>) -> CompiledClassHash
where
    H: StarkHash,
    EH: EntryPointHashable,
    NL: HashableNestedIntList,
{
    let external_funcs_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_external_entry_points());
    let l1_handlers_hash = entry_point_hash::<H, EH>(hashable_class.get_hashable_l1_entry_points());
    let constructors_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_constructor_entry_points());

    let bytecode_hash = bytecode_hash::<H, NL>(
        &hashable_class.get_bytecode(),
        &*hashable_class.get_bytecode_segment_lengths(),
    );

    // Compute total hash by hashing each component on top of the previous one.
    CompiledClassHash(H::hash_array(&[
        *COMPILED_CLASS_V1,
        external_funcs_hash,
        l1_handlers_hash,
        constructors_hash,
        bytecode_hash,
    ]))
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
