### Title
Duplicate `event.TxID` from a single receipt lets `attachOutboundsToUtx` append colliding outbound records that `UpdateOutbound`/`VoteOutbound` resolve to the wrong entry — (File: `x/uexecutor/keeper/create_outbound.go`, `x/uexecutor/keeper/msg_vote_outbound.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`Keeper.BuildOutboundsFromReceipt` builds one `OutboundTx` per matching `UniversalTxOutbound` log in a receipt and sets `Id` directly from the decoded `event.TxID` with no uniqueness check within the same receipt/UTX. [1](#0-0) [2](#0-1) 

`attachOutboundsToUtx` then simply appends every built outbound to `utx.OutboundTx` and (re)writes the `PendingOutbounds` index keyed by `outbound.Id`, with no rejection of duplicate IDs already present on the same `utx.OutboundTx` slice: [3](#0-2) 

Downstream, both the voting path and the finalize/update path locate an outbound purely by linear `ob.Id == outboundId` match and `break` on the first hit: [4](#0-3) [5](#0-4) 

### Finding Description
If a single PC transaction/payload receipt causes `UniversalGatewayPC` to emit two (or more) `UniversalTxOutbound` logs whose `event.TxID` values collide (identical), `BuildOutboundsFromReceipt` returns two `*types.OutboundTx` entries carrying the same `Id` but potentially different `DestinationChain`, `Recipient`, `Amount`, `TxType`, `RevertInstructions`, etc. (whatever the two log payloads encode).

`attachOutboundsToUtx` appends both to `utx.OutboundTx` unconditionally and writes/overwrites a single `PendingOutbounds[Id]` entry pointing at this UTX (the second `Set` call simply overwrites the first, which is only a bookkeeping index and not itself exploited further).

The real corruption happens in the id-based lookups that follow:
- `VoteOutbound` fetches the UTX by the UV-supplied `utxId`, then scans `utx.OutboundTx` for `ob.Id == outboundId` and takes the **first array match**, ignoring that a second entry with the identical `Id` (and different destination/amount/recipient) also exists in the same slice.
- `UpdateOutbound` (used by `FinalizeOutbound`, `AbortOutbound`) likewise updates only the first slice element matching `Id`.

Because there is no correlation to `PcTx.LogIndex` or the specific log data actually observed by validators, an honest Universal Validator voting on the outbound that was really emitted at log index N (e.g., a small legitimate transfer) will have its vote applied by the keeper to slot 0 of the array — which may be a different outbound record (e.g., one that specifies a much larger amount, a different recipient, or a different `RevertInstructions.FundRecipient`) crafted by the attacker via the second colliding log in the same receipt. Since `handleFailedOutbound`/`handleSuccessfulOutbound` mint/refund based on the fields of the record actually mutated (amount, `Prc20AssetAddr`, revert recipient), status transitions, refund math, and remint destination can all be applied to the attacker-chosen (wrong) outbound record rather than the one genuinely observed on the destination chain.

### Impact Explanation
This breaks the required invariant that "receipt-derived outbounds must stay bound to the exact originating UTX/PC tx and observation" at the granularity of individual outbound records within one receipt. Depending on which of the two colliding-ID records gets mutated:
- An attacker can cause a legitimate small outbound observation to finalize state (mint-back/refund) using a different outbound's amount/recipient/asset fields, resulting in incorrect remint amounts or refunds routed to an attacker-controlled address (`RevertInstructions.FundRecipient`) — theft/loss of protocol/user funds.
- Alternatively, it can permanently strand a genuine outbound in `PENDING` (since only the colliding twin ever transitions, and `VoteOutbound` rejects re-voting once `OutboundStatus != PENDING` is violated for the "wrong" slot) — leading to permanent freezing of the real outbound's funds pending manual intervention.

### Likelihood Explanation
This requires the attacker's own user-controlled payload execution (via `ExecutePayload`/`ExecutePayloadV2`, reachable through the ordinary `MsgExecutePayload` / inbound-payload flow) to make the `UniversalGatewayPC` contract emit two `UniversalTxOutbound` events with colliding `TxID` in one transaction. Whether this is actually achievable depends entirely on how `TxID` is generated inside the `UniversalGatewayPC` Solidity contract (deterministic per-call nonce vs. attacker-influenced value) — that contract's production source is **not present in this repository** (only a test-only mock is included, which does not implement real TxID generation), so I could not verify from static code whether the production contract already guarantees `TxID` uniqueness across logs within a single transaction. If the contract does guarantee strict uniqueness (e.g., via an incrementing on-chain nonce independent of caller input), this specific collision path is not reachable and the keeper-side lack of a defensive uniqueness check is a hardening gap rather than an exploitable bug. If the contract's TxID derivation can be influenced or repeated by the caller (e.g., via payload replay-style calls within one tx, or a TxID scheme not tied to a strictly monotonic nonce), the vulnerability is directly reachable by any unprivileged user.

### Recommendation
Regardless of contract-side guarantees, add a defense-in-depth check in `attachOutboundsToUtx` (and/or `BuildOutboundsFromReceipt`) that rejects (or dedupes with an explicit fatal error) any outbound whose `Id` already exists either in the target `utx.OutboundTx` slice or in the `PendingOutbounds` index bound to a different UTX before appending. Additionally, `VoteOutbound`/`UpdateOutbound` should validate that at most one `OutboundTx` entry in a `UniversalTx` carries a given `Id`, and should bind the vote to the specific record via `PcTx.LogIndex`/`TxHash` rather than relying solely on `Id` equality with first-match semantics.

### Proof of Concept
A keeper-level integration test can demonstrate the mechanical flaw without needing the real contract:
1. Construct an `evmtypes.MsgEthereumTxResponse` receipt with two logs at `UNIVERSAL_GATEWAY_PC`, both with topic `UniversalTxOutboundEventSig`, and both encoding the same `event.TxID` (e.g., `0x...01`) but different `Amount`/`Recipient`/`RevertRecipient` values (mirroring the pattern used in `TestPostTxProcessing_WithSyntheticOutboundEvent`, referencing `test/integration/uexecutor/evm_hooks_and_outbound_test.go`).
2. Call `hooks.PostTxProcessing` (or directly `k.BuildOutboundsFromReceipt` + `attachOutboundsToUtx`) and observe that `utx.OutboundTx` now contains two entries sharing the same `Id`.
3. Simulate `MsgVoteOutbound` quorum (`utils.ExecVoteOutbound`) for the outbound ID, using an `ObservedTx` that matches log #2's semantics (e.g., destination chain/amount from the second log).
4. Assert that `UpdateOutbound`/`FinalizeOutbound` mutate `utx.OutboundTx[0]` (the first log's record) instead of `utx.OutboundTx[1]`, confirming the mismatch between what validators actually observed and what got finalized — with mint/refund math drawn from the wrong record's `Amount`/`Prc20AssetAddr`/`RevertInstructions`. func (k Keeper) BuildOutboundsFromReceipt(
	ctx context.Context,
	utxId string,
	receipt *evmtypes.MsgEthereumTxResponse,
) ([]*types.OutboundTx, error) {

	outbounds := []*types.OutboundTx{}
	universalGatewayPC := strings.ToLower(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_GATEWAY_PC"].Address)

	k.Logger().Debug("building outbounds from receipt", "utx_id", utxId, "tx_hash", receipt.Hash, "log_count", len(receipt.Logs))

	for _, lg := range receipt.Logs {
		if lg.Removed {
			continue
		}

		if strings.ToLower(lg.Address) != universalGatewayPC {
			continue
		}

		if len(lg.Topics) == 0 {
			continue
		}

		if strings.ToLower(lg.Topics[0]) != strings.ToLower(types.UniversalTxOutboundEventSig) {
			continue
		}

		event, err := types.DecodeUniversalTxOutboundFromLog(lg)
		if err != nil {
			return nil, fmt.Errorf("failed to decode UniversalTxWithdraw: %w", err)
		}

		// Check if outbound is enabled for the destination chain
		outboundEnabled, err := k.uregistryKeeper.IsChainOutboundEnabled(ctx, event.ChainId)
		if err != nil {
			return nil, fmt.Errorf("failed to check outbound enabled for chain %s: %w", event.ChainId, err)
		}
		if !outboundEnabled {
			k.Logger().Warn("outbound disabled for chain", "chain_id", event.ChainId, "utx_id", utxId)
			return nil, fmt.Errorf("outbound is disabled for chain %s", event.ChainId)
		}

		// Get the external asset addr
		tokenCfg, err := k.uregistryKeeper.GetTokenConfigByPRC20(
			ctx,
			event.ChainId,
			event.Token, // PRC20 address
		)
		if err != nil {
			return nil, err
		}

		outbound := &types.OutboundTx{
			DestinationChain:  event.ChainId,
			Recipient:         event.Target,
			Amount:            event.Amount.String(),
			ExternalAssetAddr: tokenCfg.Address,
			Prc20AssetAddr:    event.Token,
			Sender:            event.Sender,
			Payload:           event.Payload,
			GasFee:            event.GasFee.String(),
			GasLimit:          event.GasLimit.String(),
			GasPrice:          event.GasPrice.String(),
			GasToken:          event.GasToken,
			TxType:            event.TxType,
			PcTx: &types.OriginatingPcTx{
				TxHash:   receipt.Hash,
				LogIndex: fmt.Sprintf("%d", lg.Index),
			},
			RevertInstructions: &types.RevertInstructions{
				FundRecipient: event.RevertRecipient,
			},
			OutboundStatus: types.Status_PENDING,
			Id:             strings.TrimPrefix(event.TxID, "0x"),
		}

		k.Logger().Debug("outbound built from receipt",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"dest_chain", outbound.DestinationChain,
			"amount", outbound.Amount,
			"tx_type", outbound.TxType.String(),
		)
		outbounds = append(outbounds, outbound)
	}

	k.Logger().Debug("outbounds built from receipt", "utx_id", utxId, "count", len(outbounds))
	return outbounds, nil
}

func (k Keeper) UpdateOutbound(ctx context.Context, utxId string, outbound types.OutboundTx) error {
	k.Logger().Debug("updating outbound state",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"status", outbound.OutboundStatus.String(),
	)
	return k.UpdateUniversalTx(ctx, utxId, func(utx *types.UniversalTx) error {
		if utx.OutboundTx == nil {
			return fmt.Errorf("outbound tx list is not initialized for utx %s", utxId)
		}

		updated := false
		for i, ob := range utx.OutboundTx {
			if ob.Id == outbound.Id {
				utx.OutboundTx[i] = &outbound
				updated = true
				break
			}
		}

		if !updated {
			return fmt.Errorf(
				"outbound with id %s not found in utx %s",
				outbound.Id,
				utxId,
			)
		}

		return nil
	})
}
