### Title
Missing declared-class validation in Starknet OS `execute_replace_class` allows honest-node state-commitment divergence from Blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall writes an attacker-supplied `class_hash` into a contract's state entry without ever validating that the class hash corresponds to a declared class. This check is present in the Rust `blockifier` (the component that actually builds/validates blocks) but is explicitly missing in the Cairo OS program (the component used for Starknet OS re-execution / proof generation), as acknowledged by an in-code `TODO`. This is the same bug class as the Wekan report: a caller-supplied identifier is used to perform a privileged state mutation without the authorization/validity check that the "trusted" code path enforces elsewhere.

### Finding Description
The Rust `blockifier` syscall implementation for `replace_class` explicitly reads the class before allowing the state mutation, rejecting undeclared or Cairo0 classes: [1](#0-0) 

The corresponding Starknet OS Cairo implementation (`execute_replace_class` in `syscall_impls.cairo`), however, unconditionally accepts the caller-supplied `class_hash` from `request.class_hash` and writes it straight into the contract's `StateEntry` via `dict_update`, with no check that the class hash is declared. This is explicitly flagged by the developers themselves: [2](#0-1) 

The equivalent Cairo0 syscall handler (`deprecated_execute_syscalls.cairo::execute_replace_class`) has the identical gap — it reads the current `StateEntry` via the `GetContractAddressStateEntry` hint and overwrites `class_hash` with the caller-supplied value, again without any declared-class check: [3](#0-2) 

I inspected `state.cairo`, which performs the Patricia-tree commitment computation over the squashed `contract_state_changes` and `contract_class_changes` dicts. It has no independent verification that every `class_hash` written into a contract's state entry corresponds to an entry that was actually declared in `contract_class_changes` or previously committed classes — it purely commits whatever class hash values appear in the (already accepted) state-change dict: [4](#0-3) 

This mirrors the Wekan `cloneBoard` pattern precisely: a caller-supplied ID (`class_hash` here, `sourceBoardId` there) is used to drive a sensitive, state-affecting operation (writing a contract's class pointer / cloning a board's contents) without invoking the validity/ownership check (`is_declared`/`get_compiled_class` here, `canExport()`/membership check there) that the equivalent "trusted" path enforces.

### Impact Explanation
The Starknet OS is the program whose correct execution the STARK proof attests to, and it is also used for independent re-execution/verification of blocks (see `apollo_starknet_os_program`/`starknet_os` crates and the re-execution flow). If the OS's `execute_replace_class` accepts an undeclared class hash where the blockifier would have rejected the transaction (causing a revert and no state mutation), the OS-computed state diff/commitment for that contract can differ from what the blockifier-driven sequencer actually committed. This is exactly the "honest-node divergence" / "wrong committed root" class of impact called out in the validation criteria: two conforming implementations of "the sequencer" (blockifier vs. OS re-execution) disagree on whether the class-replacement mutation is legal, which can produce differing final state roots for the same block, breaking state-root consensus/verification, or — if the OS path is authoritative for proving — could let a class hash pointing to a non-existent/undeclared class become committed into the global state tree, permanently corrupting calls to that contract address (denial of service / loss of contract functionality, i.e., a form of "permanent freezing" of the affected contract's usable state).

### Likelihood Explanation
Any contract can invoke `replace_class_syscall` with an arbitrary attacker-chosen `class_hash` (as demonstrated by the `test_replace_class` feature-contract entry points), i.e., it is reachable by a single unprivileged contract call within any transaction. No additional privilege, staking, or network position is required — only the ability to deploy/call a contract with this instruction, which is available to any transaction sender. The gap is also explicitly acknowledged as unresolved in the code via the `TODO(Yoni, 1/1/2026)` comment, indicating the developers are aware the check is missing but it has not yet been implemented.

### Recommendation
Add an explicit "class is declared" check in both `execute_replace_class` (Cairo1, `syscall_impls.cairo`) and the deprecated Cairo0 `execute_replace_class` before writing the new `class_hash` into the contract's `StateEntry`, mirroring the Rust blockifier's `get_compiled_class(class_hash)` validation (and its Cairo1-only restriction) in `syscall_base.rs::replace_class`. This keeps the OS's semantics consistent with the actual execution engine and prevents any class-hash write into committed state that was not itself declared/committed in the same or a prior block.

### Proof of Concept
1. Deploy a contract exposing `test_replace_class` (as in `blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo:201-203`, which calls `syscalls::replace_class_syscall(class_hash)` directly).
2. Submit an `INVOKE` transaction calling `test_replace_class` with an arbitrary, undeclared `class_hash` (e.g., `felt!(1234)`), analogous to the existing Rust test `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`, which shows the Rust blockifier rejecting this with `"is not declared"`.
3. Because the blockifier rejects the call, this specific transaction reverts in normal sequencer operation; however, the Starknet OS Cairo code path that re-executes/proves the same syscall sequence (`execute_replace_class` in `syscall_impls.cairo` / `deprecated_execute_syscalls.cairo`) contains no equivalent rejection logic, so any code path or future change that allows this syscall to reach OS execution with an undeclared class hash (e.g., differences in revert-log handling, or future features that bypass Blockifier's pre-check) will silently commit the invalid class hash into the state commitment, producing a state root the blockifier's own execution model would never have produced.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}

func state_update{poseidon_ptr: PoseidonBuiltin*, hash_ptr: HashBuiltin*, range_check_ptr}(
