The premise linking `rpc_methods` to the nonce invariant does not hold up under inspection.

**Binding check:** `rpc_methods` in `crates/citrea-stf/src/runtime.rs` is purely native-only RPC wiring: it calls `get_rpc_methods::<C, Da>(storage, ledger)` to register `EvmRpcImpl`, `AccountsRpcImpl`, `L2BlockRuleEnforcerRpcImpl` as JSON-RPC servers. [1](#0-0) 

It has no involvement whatsoever in transaction signature verification, dispatch, or nonce checking/incrementing. `CitreaRuntime` (the struct) and `genesis_config` (the sibling function) are likewise unrelated to nonce handling — `genesis_config` only loads genesis state from `GenesisPaths`. [2](#0-1) [3](#0-2) 

**Where the actual nonce invariant lives:** the equality `sender.nonce == tx.nonce()` is checked and enforced entirely in `sov_accounts::hooks::Accounts::pre_dispatch_tx_hook` (reads `tx.nonce()` against the stored `Account.nonce`, keyed by `tx.pub_key()`) and incremented exactly once in `post_dispatch_tx_hook` (`account.nonce += 1`, keyed by the same `tx.pub_key()`). [4](#0-3) 

Both the pre-check and the post-increment key off `tx.pub_key()`, which is derived from the transaction's verified signature — not from any RPC dispatch path, and definitely not from `rpc_methods`, which never touches a `Transaction`, a `WorkingSet`, or the accounts state map at all. A malleated/re-encoded signature envelope would need to change `tx.pub_key()` or `tx.nonce()` as seen by these hooks in order to break the invariant, and that verification/deserialization happens upstream of dispatch (in the STF blueprint's transaction/tx-envelope decoding), a path that is disjoint from `rpc_methods`.

Since `rpc_methods` has no read or write of any nonce, account, or `WorkingSet` entry, there is no reachable path from an attacker-controlled transaction envelope through `rpc_methods` that could cause `sender.nonce` and `tx.nonce()` to diverge. The question's exploit idea rests on a fabricated adjacency between `rpc_methods`/`CitreaRuntime`/`genesis_config` and the nonce hook logic that does not exist in the code.

    fn pre_dispatch_tx_hook(
        &self,
        tx: &Transaction,
        working_set: &mut WorkingSet<C::Storage>,
        _sequencer: &Self::PreArg,
        _spec_id: SpecId,
    ) -> Result<AccountsTxHook, L2BlockHookError> {
        let sender = self.get_or_create_default(tx.pub_key(), working_set)?;
        let tx_nonce = tx.nonce();

        if sender.nonce != tx_nonce {
            return Err(L2BlockHookError::SovTxBadNonce);
        }

        Ok(AccountsTxHook {
            sender: sender.addr,
        })
    }

    fn post_dispatch_tx_hook(
        &self,
        tx: &Transaction,
        _ctx: &C,
        working_set: &mut WorkingSet<C::Storage>,
        _spec_id: SpecId,
    ) -> Result<(), L2BlockHookError> {
        let mut account = self
            .accounts
            .get_or_err(tx.pub_key(), working_set)
            .map_err(|_| L2BlockHookError::SovTxAccountNotFound)?;
        account.nonce += 1;
        self.accounts.set(tx.pub_key(), &account, working_set);

        Ok(())
    }
