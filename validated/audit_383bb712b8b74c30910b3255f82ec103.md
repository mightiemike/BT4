## Analysis

The auction report's core defect is a **best-effort value-discovery mechanism with no enforced floor tied to a manipulation-resistant reference price** — an attacker can starve/skew the mechanism so it settles below the true/fair value, permanently costing the protocol funds.

Push Chain's closest structural analog is the **Uniswap V3 spot-quote-based slippage guard used for module-originated PRC20↔native-PC swaps** in the gas-refund and gas-deposit-with-autoswap flows.

### Where it lives

- `x/uexecutor/keeper/evm.go` `GetSwapQuote` — calls `QuoterV2.quoteExactInputSingle` for a spot AMM quote. [1](#0-0) 
- `x/uexecutor/keeper/outbound.go` `applyGasRefund` — fetches a spot quote via `getSwapQuoteForRefund`, then derives `minPCOut = quote * 95 / 100` and immediately submits the swap in the same call. [2](#0-1) 
- `x/uexecutor/keeper/execute_inbound_gas.go` `ExecuteInboundGas` — same pattern for `GAS` inbound deposits: quote-then-swap in the same keeper execution with a fixed 5% slippage bound. [3](#0-2) 
- `x/uexecutor/keeper/execute_inbound_gas_and_payload.go` `gasAndPayloadDepositAutoSwap` — identical pattern for `GAS_AND_PAYLOAD` inbounds. [4](#0-3) 
- `CallPRC20DepositAutoSwap` explicitly documents that `fee` and `minPCOut` are "pre-computed by the caller" — the EVM contract performs no independent floor/oracle check. [5](#0-4) 

The upgrade log confirms this design was deliberately chosen: "GAS and GAS_AND_PAYLOAD inbound routes now call the Uniswap V3 QuoterV2 contract to obtain an on-chain swap quote and pass minPCOut (quote × 95%) ... replacing the previous 0-slippage call." [6](#0-5) 

### Title
Spot-price-derived slippage bound in module-originated PRC20↔PC swaps is sandwichable, letting an unprivileged attacker drain refund/deposit value without any floor tied to a manipulation-resistant price - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
Like the audited auction that had no reserve price enforced against any external ground truth (only a self-referential "current highest bid" concept), Push Chain's module-originated swaps compute their `minPCOut` slippage floor from the *very same* AMM pool they are about to trade against, fetched moments before execution, with no TWAP or external price oracle. An unprivileged attacker who can manipulate the pool's spot price immediately before the module's swap call (and reverse it immediately after) can force the module to accept a `minPCOut` that is itself derived from the manipulated price, defeating the slippage protection entirely and extracting value that should accrue to the user (gas refund recipient) or to the deposited UEA balance.

### Finding Description
`applyGasRefund`, `ExecuteInboundGas`, and `gasAndPayloadDepositAutoSwap` all follow the same pattern:
1. Call `GetSwapQuote` → reads the pool's current spot price via `QuoterV2.quoteExactInputSingle`.
2. Compute `minPCOut = quote * 95 / 100` — a fixed 5% band around whatever the spot price happens to be at that instant.
3. Immediately execute the real swap (`CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` with `withSwap=true`) using that `minPCOut`.

Because steps 1–3 occur back-to-back on-chain with no time delay or independent price reference, an attacker can:
- Front-run: swap a large amount into/out of the same pool to push the spot price down just before the module's `GetSwapQuote` call executes (both land in the same block since Cosmos EVM mempool visibility lets a searcher see the pending `MsgVoteInbound`/`MsgVoteOutbound` that triggers this code path, and construct surrounding transactions).
- The module then reads the *already-manipulated* price as `quote`, computes `minPCOut` from it (so the floor is corrupted along with the price — it is not a defense at all in this scenario), and executes the swap at the bad price.
- Back-run: attacker reverses their initial trade, pocketing the difference, which is extracted directly from the refund/deposit amount that should have gone to the legitimate recipient (the outbound sender, `RevertInstructions.FundRecipient`, or the depositing UEA).

This is functionally identical to the audited bug class: a "best effort" value-realization mechanism (auction bids / AMM slippage bound) whose floor is not anchored to any authoritative, attacker-resistant reference, so the mechanism can be driven to an economically bad outcome that permanently costs the protocol/user funds — while every individual step (quote, then swap with that quote's derived floor) behaves "correctly" per its own logic.

### Impact Explanation
This falls squarely under the allowed impact "corruption of ... gas fee accounting, refund accounting ... " and "stealing, draining, permanent loss ... of user or protocol-controlled funds," triggered purely by an unprivileged external actor observing and surrounding ordinary, honestly-voted inbound/outbound finalization transactions — no validator, relayer, or admin compromise required. Every `GAS`, `GAS_AND_PAYLOAD` inbound deposit and every outbound gas refund that takes the swap path is exposed; funds lost this way are not recoverable (the swap settles on-chain against the real pool).

### Likelihood Explanation
Requires the attacker to have capital to move the specific PRC20↔WPC pool's price meaningfully within the slippage band and to time their trades around the finalizing vote transaction within the same block (or adjacent blocks, since spot price persists across blocks until arbitraged back by others). This is a well-understood, commonly exploited pattern (JIT sandwich attacks against fixed-percentage slippage swaps) and does not require any privileged access, making it realistically executable, especially for higher-value refunds/deposits or thinly-liquid PRC20 pools.

### Recommendation
Do not derive the slippage floor from a spot quote taken immediately before the swap. Use a manipulation-resistant reference (e.g., a TWAP over a sufficient window, or an external price oracle already used elsewhere such as the chain-meta gas price oracle) to bound `minPCOut`, and/or cap the maximum single-block price impact the module's swap is allowed to accept independent of the pool's current instantaneous state. Consider also enforcing a maximum swap size relative to pool liquidity, and emitting an alert/fallback to the no-swap path when the quote deviates significantly from a longer-window average.

### Proof of Concept
1. Attacker monitors the mempool for a `MsgVoteOutbound`/`MsgVoteInbound` transaction that will be the finalizing (quorum-reaching) vote for a GAS-type inbound or a successful outbound with excess gas to refund.
2. Attacker submits a transaction just before it that swaps a large amount of native PC (or WPC) into the relevant PRC20↔WPC pool on the built-in Uniswap V3 pool, depressing the PRC20 price against PC.
3. The finalizing vote executes `ExecuteInboundGas`/`applyGasRefund`, which calls `GetSwapQuote` and reads the now-depressed price, computes `minPCOut` from it, and executes `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` at that bad rate — the recipient/UEA receives materially less native PC than fair value.
4. Attacker submits a follow-up transaction reversing their initial swap, realizing a profit equal to the value extracted from the refund/deposit, at the expense of protocol/user funds.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
