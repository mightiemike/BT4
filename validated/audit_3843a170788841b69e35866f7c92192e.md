### Title
Panic on empty L1-handler calldata in message-hash computation - (File: `crates/starknet_api/src/hash.rs`)

### Summary
`l1_handler_message_hash` (used by `L1HandlerTransaction::calc_msg_hash`) unconditionally calls `.expect()` on `calldata.0.split_first()`, assuming the calldata always contains at least the `from_address` element. `Calldata` carries no non-empty invariant, and the codebase itself documents elsewhere that an empty `L1HandlerTransaction` calldata is constructible via `Deserialize` (see the `payload_size` fix that uses `saturating_sub` specifically to avoid this class of bug). [1](#0-0) 

### Finding Description
`l1_handler_message_hash` computes the L1↔L2 message hash used for RPC message-hash queries (`starknet_getMessagesStatus`/`calc_msg_hash` paths in `apollo_rpc`) and other flows that construct an `L1HandlerTransaction` from external/untrusted data:

```rust
let (from_address, payload) =
    calldata.0.split_first().expect("Invalid calldata, expected at least from_address");
```

`Calldata` is a plain `Arc<Vec<Felt>>` wrapper with no non-empty invariant enforced at deserialization or construction time [2](#0-1) . The codebase's own regression test explicitly documents that `L1HandlerTransaction` deserializes with an empty calldata without any validation, and that a sibling function (`payload_size`) was hardened with `saturating_sub` for exactly this reason:

```rust
/// `Calldata` has no non-empty invariant and `L1HandlerTransaction` derives `Deserialize`, so an
/// empty calldata is constructible. `payload_size` must not underflow ...
``` [3](#0-2) 

This is analogous to the `MatrixDiag*` bug class: an operation is implemented assuming a non-empty input tensor/array without validating the assumption at the API boundary, and the unvalidated path is reachable with attacker-influenced data (an L1-handler transaction/calldata originating from an L1 message or from RPC endpoints that accept/construct `L1HandlerTransaction` objects, e.g. `calc_msg_hash` call sites in `apollo_rpc`). Unlike `payload_size`, which was explicitly patched to tolerate empty calldata, `l1_handler_message_hash` was not, leaving a `.expect()`-triggered panic reachable through the same object.

### Impact Explanation
A panic in `l1_handler_message_hash`, if reached from an RPC-facing or transaction-processing code path that accepts an `L1HandlerTransaction`/`Calldata` value from external input without first validating non-emptiness, would crash the processing task/thread. If reached on a hot code path used consistently by all nodes (e.g., during transaction hash/message-hash computation as part of ingesting or serving L1 handler transactions), this could produce a crash/DoS on any node that processes the crafted transaction, and in the worst case a divergence if only some nodes panic while others don't (though panics are typically deterministic across nodes running the same code, so the primary impact is denial-of-service/crash rather than state divergence).

### Likelihood Explanation
Likelihood depends on whether `calc_msg_hash`/`l1_handler_message_hash` is reachable with attacker-supplied, unvalidated `Calldata` prior to it entering the trusted L1-scraper path (where the `from_address` is always deterministically prepended by trusted scraper code). I was not able to fully confirm, within the available indexed context, whether the `apollo_rpc` call sites of `calc_msg_hash` accept a raw/unvalidated `L1HandlerTransaction` from client-supplied RPC parameters (e.g., a `getMessagesStatus`/`estimateMessageFee`-style endpoint) versus only operating on already-stored, scraper-produced transactions. This is a genuine gap in verification — the `apollo_rpc/src/v0_8/api/api_impl.rs` call sites of `calc_msg_hash` were located but their argument provenance was not read within the remaining tool budget.

### Recommendation
Replace the `.expect()` in `l1_handler_message_hash` with a `Result`-returning check that rejects empty `Calldata` (mirroring the precedent set by `payload_size`'s `saturating_sub` fix), and audit all call sites of `calc_msg_hash` (and any other place constructing/hashing `L1HandlerTransaction` calldata) to ensure any externally-supplied `L1HandlerTransaction`/`Calldata` is validated as non-empty at the boundary before reaching this function.

### Proof of Concept
Construct an `L1HandlerTransaction` (via any deserialization path that doesn't independently enforce non-empty calldata) with `calldata: Calldata(Arc::new(vec![]))`, then call `.calc_msg_hash()`:
```rust
let tx = L1HandlerTransaction {
    version: TransactionVersion::ZERO,
    nonce: Nonce::default(),
    contract_address: Default::default(),
    entry_point_selector: Default::default(),
    calldata: Calldata(Arc::new(vec![])),
};
tx.calc_msg_hash(); // panics: "Invalid calldata, expected at least from_address"
``` [4](#0-3) 

**Confidence note:** I could not verify within the tool budget whether `calc_msg_hash`'s RPC call sites in `crates/apollo_rpc/src/v0_8/api/api_impl.rs` expose this panic to unprivileged, externally-supplied calldata (as opposed to only trusted, scraper-validated data). This should be confirmed before treating this as a confirmed exploitable finding rather than a defensive-coding gap.

/// Calculating the message hash of L1 -> L2 message.
/// For more info: <https://docs.starknet.io/documentation/architecture_and_concepts/Network_Architecture/messaging-mechanism/#structure_and_hashing_l1-l2>
pub fn l1_handler_message_hash(
    contract_address: &ContractAddress,
    nonce: Nonce,
    entry_point_selector: &EntryPointSelector,
    calldata: &Calldata,
) -> L1L2MsgHash {
    let (from_address, payload) =
        calldata.0.split_first().expect("Invalid calldata, expected at least from_address");

    let mut encoded = Vec::new();
    encoded.extend(from_address.to_bytes_be());
    encoded.extend(contract_address.0.key().to_bytes_be());
    encoded.extend(nonce.to_bytes_be());
    encoded.extend(entry_point_selector.0.to_bytes_be());

    let payload_length_as_felt =
        Felt::from(u64::try_from(payload.len()).expect("usize should fit in u64"));
    encoded.extend(payload_length_as_felt.to_bytes_be());

    for felt in payload {
        encoded.extend(felt.to_bytes_be());
    }

    let mut keccak = Keccak256::default();
    keccak.update(&encoded);
    L1L2MsgHash(keccak.finalize().into())
}

pub struct L1HandlerTransaction {

    pub paid_fee_on_l1: Fee,

impl L1HandlerTransaction {
    pub const L1_HANDLER_TYPE_NAME: &str = "L1_HANDLER";

    pub fn create(
        raw_tx: crate::transaction::L1HandlerTransaction,
        chain_id: &ChainId,
        paid_fee_on_l1: Fee,
    ) -> Result<L1HandlerTransaction, StarknetApiError> {
        let tx_hash = raw_tx.calculate_transaction_hash(chain_id, &raw_tx.version)?;
        Ok(Self { tx: raw_tx, tx_hash, paid_fee_on_l1 })
    }

    pub fn payload_size(&self) -> usize {
        // The calldata includes the "from" field, which is not a part of the payload.
        // `saturating_sub` guards the empty-calldata case (which would otherwise underflow to
        // `usize::MAX` in release): `L1HandlerTransaction` derives `Deserialize` and `Calldata`
        // has no non-empty invariant.
        self.tx.calldata.0.len().saturating_sub(1)
    }
}
