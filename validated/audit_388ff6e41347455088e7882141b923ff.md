### Title
Unbounded per-key `find_element` linear scans in the Starknet OS alias-replacement path allow quadratic-cost DoS during Starknet OS re-execution - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/state/aliases.cairo`)

### Summary
The Starknet OS's stateful-compression ("alias") mechanism resolves each modified storage key/contract address to a numeric alias by scanning the full list of aliases touched in the block with `find_element`, once per key. This is a linear-scan-per-lookup pattern reachable purely through normal transaction activity (many distinct large storage writes across many contracts in one block), giving quadratic cost in the number of aliased keys, unlike the Rust-side `blockifier` compression path which uses O(1) hashmap-backed state reads.

### Finding Description
`replace_aliases_and_serialize_full_contract_state_diff` builds an `Aliases { len: n_aliases, ptr: aliases_ptr }` struct covering every alias entry touched in the block [1](#0-0) , and then for every modified contract address and every "big" (aliasable) storage key it calls `get_alias`/`get_alias_of_big_key`, each of which performs a `find_element` linear scan over the entire `aliases` array of size `n_aliases`: [2](#0-1) 

This function is invoked once per storage key in `replace_storage_diff_big_keys` (iterated over every big key in every contract's diff) [3](#0-2) , and once per contract address in `replace_contract_state_diff` [4](#0-3) . Consequently, resolving `k` keys against `n` total aliases costs `O(k·n)`, which is quadratic when `k` and `n` scale together (a block touching many distinct large-valued storage keys across many contracts).

The actual Rust implementation of `find_element`'s underlying "optimistic" hint (`search_sorted_optimistic`) performs an explicit `for i in 0..n_elms` loop with no cap: [5](#0-4) 
The corresponding Cairo/Python hint documentation shows an optional `__find_element_max_size` guard, but the Rust port explicitly notes it ignores that variable: [6](#0-5) [7](#0-6) 
so no size limit bounds these lookups in the current implementation.

This differs materially from the blockifier's own Rust-side alias handling (`allocate_aliases_in_storage`/`compress`) used during block building/fee accounting, which resolves aliases via `O(1)` `state.get_storage_at` reads through a `HashMap`/state-cache rather than a linear array scan: [8](#0-7) [9](#0-8) . The blockifier's bouncer/gas accounting is calibrated against this O(1) Rust path (and against per-tx Cairo-VM step costs for user code), not against the O(n) `find_element` cost incurred later, when the Starknet OS re-executes the block (during proving, and during the sequencer's own "Starknet OS re-execution" verification pass) to compute the state-diff and block commitment.

### Impact Explanation
Because block admission/step-budget accounting (the bouncer, `crates/blockifier/src/bouncer.rs`) is based on transaction execution resources and is not aware of the quadratic alias-resolution cost paid later during Starknet OS re-execution, an attacker who crafts a block's worth of transactions that legitimately fit within normal execution/gas budgets — but that touch many distinct large-valued storage keys spread across many distinct contracts — can cause the Starknet OS phase (used for state-diff/commitment computation and re-execution verification) to incur quadratic (rather than linear) `find_element` scans. This can materially slow down or stall the block-finalization/proving pipeline for that block, delaying or preventing the network from confirming the next block (a network-unable-to-confirm-new-transactions class of impact), without the disproportionate cost having been reflected in the resources charged to, or bounded from, the responsible transactions.

### Likelihood Explanation
Reachable from ordinary, unprivileged transactions: any account contract can write to many distinct storage slots (values ≥ `MIN_VALUE_FOR_ALIAS_ALLOC`) across many different contract addresses within a single block, which is the only precondition for triggering large `n_aliases`/`k` values feeding the quadratic `find_element` cost. No special privileges, malicious operator/peer behavior, or leaked keys are required — only a moderately large number of storage writes concentrated in one block, which is within an ordinary user's capability given typical bouncer limits (max storage updates per block can be in the thousands).

### Recommendation
Replace the per-key linear `find_element` scan in `get_alias_of_big_key`/`get_alias` with an O(1) or O(log n) lookup structure consistent with the guarantees used elsewhere (e.g., binary search over a sorted `aliases` array, or maintain the same hashmap-backed resolution used by the Rust `blockifier` alias compressor), and/or enforce the existing (currently ignored) `__find_element_max_size` bound in the Rust `search_sorted_optimistic` hint implementation so a maliciously large `n_elms` cannot silently blow up per-call cost. Ensure the bouncer/step-cost model for Starknet OS re-execution accounts for the true (worst-case) cost of alias resolution proportional to `k·n`, not just `n`.

### Proof of Concept
1. An attacker deploys/uses several distinct contracts (or one contract with per-slot writes) and, in a single block, submits enough `INVOKE` transactions writing to many distinct storage keys with values ≥ `MIN_VALUE_FOR_ALIAS_ALLOC` (`0x80`) across many contract addresses, keeping each individual transaction's Cairo-VM execution within normal fee/step limits so the bouncer accepts the block.
2. When the Starknet OS processes this block's state diff, `replace_aliases_and_serialize_full_contract_state_diff` builds an `Aliases` array of size `n_aliases` equal to the number of alias entries touched in the block [10](#0-9) .
3. For each of the `k` big storage keys/contract addresses in the diff, `get_alias`/`get_alias_of_big_key` calls `find_element` over the full `n_aliases`-sized array [2](#0-1) , and the underlying hint executes an unbounded `for i in 0..n_elms` loop per call [11](#0-10) , yielding `O(k·n)` total work for the block's alias-replacement phase, disproportionate to the per-transaction resources charged during normal execution/bouncer accounting.

// Writes the contract state diff with replaced aliases into `res`.
func replace_contract_state_diff{range_check_ptr, res: felt*}(
    aliases: Aliases, n_contracts: felt, contract_state_diff: felt*
) {
    if (n_contracts == 0) {
        return ();
    }
    alloc_locals;

    let contract_header = cast(contract_state_diff, FullContractHeader*);
    local contract_address = contract_header.address;
    local storage_diff_start: FullStateUpdateEntry* = cast(
        &contract_state_diff[FullContractHeader.SIZE], FullStateUpdateEntry*
    );
    local n_storage_diffs = contract_header.n_storage_diffs;
    local storage_diff_end: FullStateUpdateEntry* = &storage_diff_start[n_storage_diffs];
    let skip_contract = should_skip_contract(contract_address=contract_address);
    if (skip_contract != FALSE) {
        // No aliases for this contract - copy the diff and continue.
        tempvar diff_len = cast(storage_diff_end, felt*) - contract_state_diff;
        memcpy(dst=res, src=contract_state_diff, len=diff_len);
        let res = &res[diff_len];
        return replace_contract_state_diff(
            aliases=aliases, n_contracts=n_contracts - 1, contract_state_diff=storage_diff_end
        );
    }

    // Replace the contract address.
    let address_alias = get_alias(aliases=aliases, key=contract_address);
    // Write the header.
    let replaced_contract_header = cast(res, FullContractHeader*);
    assert [replaced_contract_header] = FullContractHeader(
        address=address_alias,
        prev_nonce=contract_header.prev_nonce,
        new_nonce=contract_header.new_nonce,
        prev_class_hash=contract_header.prev_class_hash,
        new_class_hash=contract_header.new_class_hash,
        n_storage_diffs=n_storage_diffs,
    );
    let res = &res[FullContractHeader.SIZE];

    // Replace the storage diff.
    replace_storage_diff(
        aliases=aliases, storage_diff_start=storage_diff_start, storage_diff_end=storage_diff_end
    );
    return replace_contract_state_diff(
        aliases=aliases, n_contracts=n_contracts - 1, contract_state_diff=storage_diff_end
    );
}

// Same as `replace_storage_diff`, but assumes all keys are at least MIN_VALUE_FOR_ALIAS_ALLOC.
func replace_storage_diff_big_keys{range_check_ptr, res: felt*}(
    aliases: Aliases,
    storage_diff_start: FullStateUpdateEntry*,
    storage_diff_end: FullStateUpdateEntry*,
) {
    if (storage_diff_start == storage_diff_end) {
        return ();
    }

    let current_entry = storage_diff_start[0];
    let key_alias = get_alias_of_big_key(aliases=aliases, key=current_entry.key);
    let replaced_entry = cast(res, FullStateUpdateEntry*);
    assert [replaced_entry] = FullStateUpdateEntry(
        key=key_alias, prev_value=current_entry.prev_value, new_value=current_entry.new_value
    );
    let res = &res[FullStateUpdateEntry.SIZE];
    return replace_storage_diff_big_keys(
        aliases=aliases,
        storage_diff_start=&storage_diff_start[1],
        storage_diff_end=storage_diff_end,
    );
}

// Returns the alias of the given key.
// Assumes the given key is at least MIN_VALUE_FOR_ALIAS_ALLOC.
func get_alias_of_big_key{range_check_ptr}(aliases: Aliases, key: felt) -> felt {
    // Sanity check.
    %{ AssertKeyBigEnoughForAlias %}
    static_assert DictAccess.key == 0;
    let (entry: DictAccess*) = find_element(
        array_ptr=aliases.ptr, elm_size=DictAccess.SIZE, n_elms=aliases.len, key=key
    );
    return entry.new_value;
}

    /// Inserts the alias key to the updates if it's not already aliased.
    fn insert_alias(&mut self, alias_key: &AliasKey) -> StateResult<()> {
        if alias_key.0 >= MIN_VALUE_FOR_ALIAS_ALLOC
            && self.state.get_storage_at(self.alias_contract_address, *alias_key)? == Felt::ZERO
        {
            let alias_to_allocate = self.next_free_alias.unwrap_or(INITIAL_AVAILABLE_ALIAS);
            self.set_alias_in_storage(*alias_key, alias_to_allocate)?;
            self.is_alias_inserted = true;
            self.next_free_alias = Some(alias_to_allocate + Felt::ONE);
        }
        Ok(())
    }
