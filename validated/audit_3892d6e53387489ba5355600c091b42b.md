## Analog Found

### Title
CREATE2 address collision against a future UEA enables draining of bridged funds via pre-set token allowance — (File: `x/uexecutor/keeper/deploy_uea.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_funds_and_payload.go`)

### Summary
Push Chain's Universal Executor Account (UEA) is deployed by the on-chain `FactoryV1` contract via `CREATE2`, where the deterministic salt is derived purely from the `UniversalAccountId{ChainNamespace, ChainId, Owner}` tuple [1](#0-0) . The `Owner` field is arbitrary attacker-influenceable bytes at deploy time — it is only format-validated (non-empty, valid hex), never cryptographically checked against a real key at deployment [2](#0-1) . The chain's own node code (`x/uexecutor`) auto-deploys the UEA deterministically at this address whenever an honest-validator-finalized inbound arrives for that owner, then immediately credits bridged funds to it, without checking whether the target address already had prior code/state — the classic CREATE2 meet-in-the-middle precondition from the Arcadia report.

### Finding Description
The UEA deployment flow works as follows:
- `CallFactoryToDeployUEA` / `DeployUEAV2` invoke the Factory's `deployUEA(_id)` function through `DerivedEVMCall`, passing the `UniversalAccountId` unchanged [3](#0-2) [4](#0-3) .
- The resulting UEA address is fully deterministic and can be precomputed off-chain via `computeUEA`/`getUEAForOrigin` before deployment [5](#0-4) , exactly like the Arcadia factory's precomputable `CREATE2` address.
- Inbound processing (`ExecuteInboundGas`, `ExecuteInboundFundsAndPayload`) automatically calls `CallFactoryToGetUEAAddressForOrigin` then `DeployUEAV2` for whatever `owner` value the honest-validator-finalized inbound event carries, and then deposits bridged PRC20/native funds into that address [6](#0-5) [7](#0-6) .
- Nothing in this flow verifies that the deploy-target address is "clean" (i.e., that no prior contract/allowance was ever set there) before deploying and crediting funds.

This reproduces the Arcadia root cause: an attacker can (1) brute-force real origin-chain addresses (owners) whose future `UniversalAccountId`-derived UEA salt/address they can precompute via `computeUEA`, (2) separately brute-force their own `CREATE2` deployment on Push Chain (ordinary EVM `CREATE2`, unrestricted) to find a colliding address, (3) deploy a contract there, set an infinite PRC20 allowance to themselves, and self-destruct within the same transaction so the account is fully wiped from state (per EIP‑6780 same-transaction self-destruct semantics, assuming Push Chain's `cosmos-evm` module retains upstream go-ethereum post-Dencun/Cancun behavior — this specific EVM-level detail is inherited from the underlying `cosmos/evm` dependency and was not independently re-verified in this repository's own Go code). Once a real bridge deposit later arrives for the colliding owner, `x/uexecutor` deterministically redeploys the UEA at the same address and credits bridged assets to it, at which point the attacker's pre-set allowance lets them drain the deposit via a normal `transferFrom` on the PRC20 token — no compromise of validators, TSS, or keys required.

### Impact Explanation
If realized, this allows an unprivileged attacker to drain PRC20/native funds credited to any victim's UEA the instant it is first funded/deployed, without needing the victim's private key, matching the "Impact: complete draining" characterization in the source report and falling squarely within the in-scope impact of "unauthorized UEA execution" / "stealing, draining ... of user or protocol-controlled funds" for universal execution flows.

### Likelihood Explanation
Likelihood mirrors the original Sherlock discussion: it requires a very large, non-trivial amount of brute-force compute (searching the origin-chain address space crossed with a Push Chain `CREATE2` salt search) and is not adjudicated as practically imminent, but the underlying design defect — using an unauthenticated, attacker-visible `owner` byte string as the sole `CREATE2` salt input with no binding proof at deploy time — is a structural weakness independent of current hardware cost. As in the original judged issue, this was treated as valid-but-lower-severity due to attack cost, not because the root cause is absent.

### Recommendation
- Require the `UniversalAccountId.Owner` to be cryptographically bound (e.g., verified signature or authenticated origin-chain proof) before the Factory ever deploys a UEA at the corresponding address, rather than deferring all authentication to `executeUniversalTx`.
- Alternatively, do not let raw attacker/validator-observed bytes alone determine the `CREATE2` salt; incorporate a value that cannot be freely searched independent of real key ownership (e.g., a KYC-like origin signature check at first-deploy time), consistent with the fix pattern the Arcadia team eventually adopted (constraining salt entropy an attacker fully controls).
- Confirm whether Push Chain's `cosmos-evm` fork implements EIP‑6780 same-tx-selfdestruct account wipe; if so, consider disabling/mitigating that path for module-privileged deploy targets, or add an explicit "was this address previously used" guard before crediting funds to a freshly (re)deployed UEA.

### Proof of Concept
Conceptual PoC (cannot be executed without off-chain brute-force compute and access to the actual `FactoryV1` Solidity source, which lives outside this repo and is only present here as compiled bytecode [8](#0-7) ):
1. Off-chain, call `computeUEA({chainNamespace, chainId, owner})` for a large set of candidate `owner` byte strings (real or attacker-chosen) to build a table of future UEA addresses.
2. On Push Chain, deploy attacker-controlled contracts via ordinary `CREATE2` searching for a salt whose resulting address matches an entry in step 1.
3. On match, deploy the attacker contract to the colliding address, call `approve(attacker, type(uint256).max)` on the relevant PRC20 token, then `selfdestruct` within the same transaction.
4. Wait for (or trigger, if the owner is attacker-controlled) an inbound deposit for that `owner`; `ExecuteInboundGas`/`ExecuteInboundFundsAndPayload` will auto-deploy the UEA at the identical address via `DeployUEAV2` and credit bridged funds [9](#0-8) .
5. Call `transferFrom(colludedUEA, attacker, amount)` on the PRC20 token using the allowance set in step 3 to drain the freshly credited funds.

Note: I could not directly inspect the `FactoryV1.sol` / `UEA_EVM.sol` Solidity source (only referenced externally at `pushchain/push-chain-core-contracts` and embedded as compiled bytecode in this repo), nor independently confirm this repo's `cosmos/evm` dependency version implements EIP‑6780 same-transaction self-destruct semantics — these are prerequisites for the full attack chain and should be verified in a live session with full repository/dependency access.

func (p UniversalAccountId) ValidateBasic() error {
	p.ChainNamespace = strings.TrimSpace(p.ChainNamespace)
	p.ChainId = strings.TrimSpace(p.ChainId)
	p.Owner = strings.TrimSpace(p.Owner)

	// Validate ChainNamespace and ChainId are non-empty
	if len(p.ChainNamespace) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "chain namespace cannot be empty")
	}
	if len(p.ChainId) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "chain ID cannot be empty")
	}

	// Validate Owner is non-empty
	if len(p.Owner) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "owner cannot be empty")
	}

	// Validate owner hex format
	ownerStr := strings.TrimPrefix(p.Owner, "0x")
	_, err := hex.DecodeString(ownerStr)
	if err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "owner must be valid hex string")
	}

	return nil
}

// CallFactoryToDeployUEA deploys a new UEA using factory contract
// Returns deployment response or error if deployment fails
func (k Keeper) CallFactoryToDeployUEA(
	ctx sdk.Context,
	from, factoryAddr common.Address,
	universalAccount *types.UniversalAccountId,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: deployUEA",
		"factory", factoryAddr.Hex(),
		"chain_namespace", universalAccount.ChainNamespace,
		"chain_id", universalAccount.ChainId,
		"owner", universalAccount.Owner,
	)

	abi, err := types.ParseFactoryABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse factory ABI")
	}

	abiUniversalAccount, err := types.NewAbiUniversalAccountId(universalAccount)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal account")
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,        // who is sending the transaction
		factoryAddr, // destination: FactoryV1 contract
		big.NewInt(0),
		nil,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"deployUEA",
		abiUniversalAccount,
	)
}

func (k Keeper) DeployUEAV2(ctx context.Context, evmFrom common.Address, universalAccountId *types.UniversalAccountId) (*evmtypes.MsgEthereumTxResponse, error) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Debug("deploying UEA",
		"chain_namespace", universalAccountId.ChainNamespace,
		"chain_id", universalAccountId.ChainId,
		"owner", universalAccountId.Owner,
		"from", evmFrom.Hex(),
	)

	// EVM Call arguments
	factoryAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)

	// Use your keeper CallEVM directly
	receipt, err := k.CallFactoryToDeployUEA(
		sdkCtx,
		evmFrom,
		factoryAddress,
		universalAccountId,
	)
	if err != nil {
		return nil, err
	}

	k.Logger().Info("UEA deployed",
		"chain_namespace", universalAccountId.ChainNamespace,
		"chain_id", universalAccountId.ChainId,
		"owner", universalAccountId.Owner,
		"tx_hash", receipt.Hash,
		"gas_used", receipt.GasUsed,
	)

	return receipt, nil
}
