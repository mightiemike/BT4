### Title
Starknet OS `execute_replace_class` omits the declared-class check enforced by the Blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Blockifier's `replace_class` syscall handler requires the target class hash to be a declared class before allowing a contract to switch its class hash, but the Starknet OS Cairo implementation of the same syscall (`execute_replace_class`) has this check explicitly marked as a TODO and never enforces it. This is the same bug class as M-8 ("Missing revert keyword"): a check that is intended/expected to gate an operation is present as a comment/placeholder but not actually implemented, so the operation silently proceeds without verifying its target is valid.

### Finding Description
In the Blockifier (native/deprecated Cairo1-VM path), `replace_class` explicitly reads the compiled class before mutating storage, to "Ensure the class is declared": [1](#0-0) 
This causes the syscall to fail with a `StateError` (e.g. "is not declared") whenever `request.class_hash` was never declared, as confirmed by the negative-flow test: [2](#0-1) 

In contrast, the Starknet OS's own Cairo implementation of the identical syscall, `execute_replace_class`, updates `contract_state_changes` (i.e., commits the new class hash into the state that will be Merkle-committed) without ever verifying the class hash is declared. The check is explicitly deferred via a TODO comment and never implemented: [3](#0-2) 

The critical missing line is:
```
// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
```
right where the Blockifier performs `syscall_handler.state.get_compiled_class(request.class_hash)?;` before proceeding. The OS instead reads the current `StateEntry` via a hint (`GetContractAddressStateEntry`) and directly writes a new `StateEntry` with the caller-supplied `class_hash`, with no constraint tying that class hash to any declared-class fact.

### Impact Explanation
The Starknet OS is the ground-truth state-transition program used for re-execution/proving of a block (an explicitly in-scope reachable path). Since the Blockifier (sequencer execution) rejects `replace_class` calls targeting an undeclared class hash, but the OS does not, any contract invocation reachable from a single transaction sender that calls `replace_class_syscall` with an undeclared class hash will:
- Be rejected/reverted by the Blockifier during normal sequencing, but
- Be silently accepted by the OS re-execution path, committing an arbitrary/undeclared class hash into `contract_state_changes` and hence into the state root.

This produces a divergence between the sequencer's committed state and the state the OS/prover would derive, i.e., an incorrect committed root, honest-node divergence, or an unprovable/invalid block (the network becomes unable to confirm blocks whose proof does not match the sequencer's execution). This satisfies the "wrong committed root" / "honest-node divergence" impact bar.

### Likelihood Explanation
Likelihood is high for any transaction that reaches this code path: it requires nothing more than a single contract invoking `replace_class_syscall(class_hash)` with a `class_hash` that has not been declared — a trivial, unprivileged operation any contract deployer/caller can trigger. No special permissions, malicious operator, or prover collusion is needed to reach the divergent code path; the divergence exists purely due to the missing validation in the OS Cairo code relative to the Blockifier's Rust implementation.

### Recommendation
Add the missing declared-class check in `execute_replace_class` (crates/apollo_starknet_os_program/.../syscall_impls.cairo), mirroring the Blockifier's behavior: before writing the new `StateEntry`, verify (via a Merkle/dict lookup against the declared-classes commitment, analogous to how `deploy_contract` and other syscalls validate class facts) that `class_hash` corresponds to a declared class, and fail/return an appropriate error response otherwise, so that the OS's acceptance criteria matches the Blockifier's.

### Proof of Concept
1. Sender deploys/uses any account or contract with an entry point that calls `replace_class_syscall(class_hash)`.
2. Use a `class_hash` value that was never declared on-chain.
3. In the Blockifier (sequencer execution), the call fails because `get_compiled_class` returns `StateError::UndeclaredClassHash`, as shown by the existing test: [4](#0-3) 
4. If the same transaction/trace were re-executed by the Starknet OS (`execute_replace_class` in syscall_impls.cairo), no equivalent check exists, so the OS would accept the state update, writing the undeclared class hash into `contract_state_changes` and ultimately into the committed state root — diverging from the Blockifier's rejection.

**Note on verification confidence:** I was not able to fully trace whether some higher-level OS commitment/finalization step (outside `syscall_impls.cairo`) independently re-validates that all class hashes appearing in `contract_state_changes` are declared before computing the final state root; the TODO comment strongly suggests no such check exists yet, but I could not exhaustively rule out a downstream validation pass within the index size limits of this analysis. A Devin session with full repository access could confirm this by tracing `contract_state_changes` through to state-root commitment logic in the OS.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
