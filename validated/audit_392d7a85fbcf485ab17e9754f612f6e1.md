## Title
Public getdelegatedresourceaccountindexv2 GET endpoint performs unbounded O(N) prefixQuery+sort while the on-chain DelegateResourceContract cost of growing N is only bandwidth/energy consumption, not a scaling fee - (File: framework/src/main/java/org/tron/core/services/http/GetDelegatedResourceAccountIndexV2Servlet.java)

## Summary
`GetDelegatedResourceAccountIndexV2Servlet.doGet`/`doPost` calls `Wallet.getDelegatedResourceAccountIndexV2` which calls `DelegatedResourceAccountIndexStore.getV2Index` → `getWithPrefix`, which performs two `prefixQuery` scans plus `List.sort` over all `V2_FROM_PREFIX`/`V2_TO_PREFIX` entries for a given address. Each `DelegateResourceContract` execution adds one entry to each prefix set for both the owner and the receiver via `DelegateResourceProcessor.delegateResource`/`DelegateResourceActuator.delegateResource`, and `DelegateResourceActuator.calcFee()` returns `0`, meaning the per-delegation on-chain cost is only bandwidth/energy usage (not a fee that scales with index size), so an attacker can cheaply inflate a target address's index size to make the public GET handler do disproportionate work.

## Finding Description
The reachable path is: `GetDelegatedResourceAccountIndexV2Servlet.doGet` (`framework/src/main/java/org/tron/core/services/http/GetDelegatedResourceAccountIndexV2Servlet.java:26-37`) → `Wallet.getDelegatedResourceAccountIndexV2` (`framework/src/main/java/org/tron/core/Wallet.java:1053-1064`) → `DelegatedResourceAccountIndexStore.getV2Index` (`chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java:114-116`) → `getWithPrefix` (`chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java:118-138`), which does two `this.prefixQuery(key)` calls and sorts each resulting list with `Comparator.comparing(...)`.

Each call to `DelegateResourceActuator`/`DelegateResourceProcessor` for a distinct owner→receiver pair inserts one new key under `V2_FROM_PREFIX+owner+receiver` and one under `V2_TO_PREFIX+receiver+owner` (`actuator/src/main/java/org/tron/core/actuator/DelegateResourceActuator.java:313-315`, and the native-contract counterpart `DelegateResourceProcessor.java:166-180`). The only floor for creating such entries is `delegateBalance >= 1 TRX` (`DelegateResourceActuator.validate()`, `framework/.../DelegateResourceActuator.java:148-150`) and having available frozen V2 balance, and `calcFee()` is `0` (`DelegateResourceActuator.java:278-280`), i.e., the transaction fee model does not charge extra for growing an account's index set — cost is bounded by bandwidth/energy for the transaction itself, which is a fixed, small, roughly-constant per-tx cost regardless of how large the target's existing index already is.

Because `getWithPrefix` is unbounded (no pagination, no cap on `prefixQuery` results) and runs on every GET to `/wallet/getdelegatedresourceaccountindexv2` (also exposed on `/walletsolidity/...` and PBFT/Solidity variants), an attacker who creates many distinct receiver addresses and delegates >=1 TRX from a single owner (or many owners delegating to one victim receiver) grows the `V2_FROM_PREFIX`/`V2_TO_PREFIX` key-space for that address linearly with the number of delegations performed, each delegation costing only the fixed per-tx bandwidth/energy price — not a price that grows with the resulting query cost. Every subsequent GET against that address then does O(N) prefix-scan + sort work.

## Impact Explanation
This allows an unprivileged attacker to make the free, public HTTP query endpoint arbitrarily expensive (CPU for sorting/scanning, memory for materializing the full list) for a specific address, degrading node availability for that RPC path, while the endpoint is also rate-limited only at a per-request/per-IP QPS level (`RateLimiterServlet`), not by the size of work a given request can trigger. This is a resource-exhaustion / DoS-flavored concern on a read path, not fund loss or consensus divergence.

## Likelihood Explanation
Feasibility requires the attacker to fund many accounts each with >=1 TRX freeze + delegate; this is real but has a linear TRX/bandwidth cost to the attacker (self-financed, not free), and each entry addition is bounded to one bandwidth-priced transaction. This is a genuine amplification of read-side cost relative to write-side cost (O(1) fee vs. O(N) query cost growth), but it is not "free" for the attacker — they must pay for N transactions to grow N. The severity is moderate: it costs the attacker real (if modest) transaction resources per unit of growth, and node operators can mitigate via query-side limits/caching without protocol changes.

## Recommendation
Cap or paginate `DelegatedResourceAccountIndexStore.getWithPrefix`/`getV2Index` (e.g., limit number of returned entries per prefixQuery, or require pagination parameters in the servlet), and/or cache computed indices to amortize repeated GETs. Alternatively, bound the number of active delegation relationships a single account can have, or make the per-tx fee for `DelegateResourceContract` account for the resulting growth of the index (e.g., scale with current index size) to remove the underpricing asymmetry.

```java
// framework/src/test/java/org/tron/core/store/DelegatedResourceAccountIndexStoreGrowthTest.java
@Test
public void testGetV2IndexCostGrowsWithDelegationCount() {
  byte[] owner = ByteArray.fromHexString(OWNER_ADDRESS);
  int[] sizes = {100, 1000, 10000};
  long[] elapsedNanos = new long[sizes.length];

  int created = 0;
  for (int s = 0; s < sizes.length; s++) {
    while (created < sizes[s]) {
      byte[] receiver = randomAddress(); // fresh account each time
      freezeBalanceV2ForOwnerAndReceiver(owner, receiver, 1_000_000L); // 1 TRX
      DelegateResourceActuator actuator = new DelegateResourceActuator();
      actuator.setChainBaseManager(dbManager.getChainBaseManager())
          .setAny(getDelegateContractForBandwidth(
              ByteArray.toHexString(owner), ByteArray.toHexString(receiver), 1_000_000L));
      TransactionResultCapsule ret = new TransactionResultCapsule();
      actuator.validate();
      actuator.execute(ret); // fee == 0, only bandwidth consumed
      created++;
    }
    long t0 = System.nanoTime();
    dbManager.getChainBaseManager().getDelegatedResourceAccountIndexStore().getV2Index(owner);
    elapsedNanos[s] = System.nanoTime() - t0;
  }

  // Assert latency does NOT stay O(1): expect it to grow roughly proportionally with size.
  Assert.assertTrue("latency for 10000 delegations should be materially larger than for 100",
      elapsedNanos[2] > elapsedNanos[0] * 5);
}
```
Expected result: latency (and heap allocation, verifiable via a profiler/JFR run) for `getV2Index` scales with the number of delegations created, while `DelegateResourceActuator.calcFee()` returns `0` for every one of those creating transactions — confirming the described O(N) query cost against O(1) on-chain fee.   private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
```java
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }
```

```java
  private void delegateResource(byte[] ownerAddress, byte[] receiverAddress, boolean isBandwidth,
                                long balance, boolean lock, long lockPeriod) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicPropertiesStore = chainBaseManager.getDynamicPropertiesStore();
    DelegatedResourceStore delegatedResourceStore = chainBaseManager.getDelegatedResourceStore();
    DelegatedResourceAccountIndexStore delegatedResourceAccountIndexStore = chainBaseManager
        .getDelegatedResourceAccountIndexStore();

    // 1. unlock the expired delegate resource
    long now = chainBaseManager.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    delegatedResourceStore.unLockExpireResource(ownerAddress, receiverAddress, now);

    //modify DelegatedResourceStore
    long expireTime = 0;
    if (lock) {
      expireTime = now + lockPeriod * BLOCK_PRODUCED_INTERVAL;
    }
    byte[] key = DelegatedResourceCapsule.createDbKeyV2(ownerAddress, receiverAddress, lock);
    DelegatedResourceCapsule delegatedResourceCapsule = delegatedResourceStore.get(key);
    if (delegatedResourceCapsule == null) {
      delegatedResourceCapsule = new DelegatedResourceCapsule(ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
    }

    if (isBandwidth) {
      delegatedResourceCapsule.addFrozenBalanceForBandwidth(balance, expireTime);
    } else {
      delegatedResourceCapsule.addFrozenBalanceForEnergy(balance, expireTime);
    }
    delegatedResourceStore.put(key, delegatedResourceCapsule);

    //modify DelegatedResourceAccountIndexStore
    delegatedResourceAccountIndexStore.delegateV2(ownerAddress, receiverAddress,
        dynamicPropertiesStore.getLatestBlockHeaderTimestamp());

    //modify AccountStore for receiver
    AccountCapsule receiverCapsule = accountStore.get(receiverAddress);
    if (isBandwidth) {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(balance);
    } else {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForEnergy(balance);
    }
    accountStore.put(receiverCapsule.createDbKey(), receiverCapsule);
  }
```

```java
  @Override
  protected void service(HttpServletRequest req, HttpServletResponse resp)
      throws ServletException, IOException {

    RuntimeData runtimeData = new RuntimeData(req);
    IRateLimiter rateLimiter = container.get(KEY_PREFIX_HTTP, getClass().getSimpleName());

    // Check per-endpoint first to avoid consuming global IP/QPS quota for requests
    // that would be rejected by the per-endpoint limiter anyway. acquirePermit()
    // chooses blocking or non-blocking semantics based on rate.limiter.apiNonBlocking.
    boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
    boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);

    String contextPath = req.getContextPath();
    String url = Strings.isNullOrEmpty(req.getServletPath())
        ? MetricLabels.UNDEFINED : contextPath + req.getServletPath();
    // int64_as_string is honored only on GET requests (URL query). POST is intentionally
    // unsupported because reading the body here would consume request.getReader() and
    // break downstream servlets that read it themselves.
    if ("GET".equalsIgnoreCase(req.getMethod())) {
      JsonFormat.setInt64AsString(Util.getInt64AsString(req));
    }
    try {
      resp.setContentType("application/json; charset=utf-8");

      if (acquireResource) {
        Histogram.Timer requestTimer = Metrics.histogramStartTimer(
            MetricKeys.Histogram.HTTP_SERVICE_LATENCY, url);
        super.service(req, resp);
        Metrics.histogramObserve(requestTimer);
      } else {
        resp.getWriter()
            .println(Util.printErrorMsg(new IllegalAccessException("lack of computing resources")));
      }
    } catch (ServletException | IOException | BadMessageException e) {
      throw e;
    } catch (Exception unexpected) {
      logger.error("Http Api {}, Method:{}. Error：", url, req.getMethod(), unexpected);
    } finally {
      // CRITICAL: this clear pairs with the setInt64AsString call above. Removing it
      // will leak int64_as_string state across requests on reused Tomcat threads,
      // producing intermittent quoted/unquoted output that is very hard to debug.
      JsonFormat.clearInt64AsString();
      // Release whenever the per-endpoint permit was acquired (covers both the normal
      // completion path and the case where GlobalRateLimiter rejected the request).
      if (rateLimiter instanceof IPreemptibleRateLimiter && perEndpointAcquired) {
        ((IPreemptibleRateLimiter) rateLimiter).release();
      }
    }
  }
```
