## Analysis

The claim is accurate and traces to a real gap in the ante pipeline.

**Path traced:**

1. `IsGaslessTx` in [1](#0-0)  whitelists `MsgVoteTssKeyProcess` and `MsgVoteFundMigration` purely by message type URL — it performs no signer/bonded-status check, so *any* transaction containing only these message types is treated as gasless regardless of who signs it.

2. In the ante chain ( [2](#0-1) ), `MinGasPriceDecorator` and `DeductFeeDecorator` both short-circuit to `next()` for any gasless tx without requiring fee tokens: [3](#0-2)  and [4](#0-3) . No account balance or stake is required.

3. `AccountInitDecorator` then runs, *before any SigVerification/ValidateSigCount/bonded-status logic*, and unconditionally creates an on-chain account for any never-seen signer of a gasless tx after only verifying a self-consistent signature (account_number=0/sequence=0): [5](#0-4) .

4. The bonded-validator gate (`IsBondedUniversalValidator`) is enforced only inside the message server, e.g. [6](#0-5)  — this runs *after* the ante chain has already completed and committed its own state changes.

5. This ordering matters because in Cosmos SDK's `runTx`, state mutations performed by the AnteHandler (including `SetAccount`) are committed independently of whether the subsequent message execution succeeds or fails. So even though `VoteFundMigration`/`VoteTssKeyProcess` will reject an unbonded signer, the account created in step 3 persists regardless.

**Conclusion:** An unprivileged, unbonded attacker can generate arbitrary fresh keypairs, wrap each in a gasless `MsgVoteTssKeyProcess`/`MsgVoteFundMigration` envelope, and force `NewAccountWithAddress`/`SetAccount` to run for every one of them at zero token cost — the account persists in state even though the vote itself is rejected downstream for lacking bonded status. This is a legitimate non-network-layer DoS vector (permanent account/state growth) reachable through ordinary transaction submission by an unprivileged actor, consistent with the "Admission and cryptographic path" pivot in the review criteria (gasless allowlisting + first-use account initialization not gated on authorization).

### Title
Unbonded attacker can create unbounded free on-chain accounts via gasless TSS vote envelopes before the bonded-validator check runs - (File: `app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator` creates and persists a new account for any first-time signer of a message type on the gasless whitelist (`MsgVoteTssKeyProcess`, `MsgVoteFundMigration`), without checking whether that signer is actually a bonded Universal Validator. The bonded check only happens later, inside the message handler, and by then the account-creation side effect from the ante phase has already been committed independently of message success.

### Finding Description
- `txpolicy.IsGaslessTx` only inspects the message type URL, not the signer's privilege/bonded status [7](#0-6) .
- `MinGasPriceDecorator`/`DeductFeeDecorator` skip all fee/balance requirements for gasless txs [3](#0-2) [4](#0-3) .
- `AccountInitDecorator.AnteHandle` unconditionally calls `NewAccountWithAddress`/`SetAccount` for any never-seen signer of such a tx, gated only by a self-referential signature check (account_number=0, sequence=0), and then returns without invoking `next` — bypassing normal sig-count/sig-verification decorators [5](#0-4) .
- The actual authorization check (`IsBondedUniversalValidator`) is performed only inside `VoteFundMigration`/`VoteTssKeyProcess` message handlers [8](#0-7) , i.e., after the ante chain (and its account-creation state write) has already run and committed.

### Impact Explanation
Because Cosmos SDK commits AnteHandler-side state mutations independently of message-execution outcome, the account created in the ante phase survives even when the message is later rejected for lacking bonded status. This lets any unprivileged party permanently grow account state at zero economic cost (no fee, no balance, no stake), degrading long-term store size/iteration cost — a non-network-layer, state-persistence form of DoS.

### Likelihood Explanation
Moderate-to-high: the attacker needs only to generate a fresh keypair and craft a validly self-signed envelope of an allowed gasless message type — no special privileges, no funds, no cooperation from validators, TSS participants, or admins required. The only natural throttle is per-block gas/tx-count limits, not any economic cost.

### Recommendation
Move (or duplicate) the bonded/tombstoned Universal Validator check into `AccountInitDecorator` (or a preceding ante decorator) for the TSS/gasless vote message types before creating a new account, so account creation is gated on signer eligibility rather than occurring unconditionally for any first-time signer of a gasless-whitelisted message type.

### Proof of Concept
1. Generate N fresh keypairs, none registered as Universal Validators.
2. For each key, build a tx containing only `MsgVoteTssKeyProcess{Signer: addr}`, sign with account_number=0/sequence=0, gas>0, fee=empty.
3. Submit via CheckTx/DeliverTx.
4. Observe: `AccountInitDecorator` creates and persists the account (`ak.HasAccount` becomes true) even though `VoteTssKeyProcess`'s subsequent `IsBondedUniversalValidator` check fails and the tx result is an error.
5. Repeat with N fresh keys to demonstrate unbounded account growth versus rejected-vote count.

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
