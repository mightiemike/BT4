### Title
Missing allowlist/rate-limiting enforcement on legacy Web API trigger messages - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` in the gateway's capabilities handler contains a TODO explicitly noting that allowlist and rate-limiting checks are not applied before forwarding user-originated trigger requests to every DON member node.

### Finding Description
In `handler.HandleLegacyUserMessage`, after basic payload parsing, timestamp/staleness checks, and method validation, the code has:
```go
// TODO: apply allowlist and rate-limiting here
if msg.Body.Method != MethodWebAPITrigger {
``` [1](#0-0) 
No allowlist check is performed to verify the caller/sender is permitted to invoke this DON's web API trigger, and no rate limiting is applied to this legacy user-facing path (unlike `handleWebAPIOutgoingMessage`, which does call `h.nodeRateLimiter.Allow(nodeAddr)` for node-originated messages) [2](#0-1) . After the checks, the request is forwarded to every node in the DON: `don.SendToNode(ctx, member.Address, req)` for all `h.donConfig.Members` [3](#0-2) .

By contrast, the newer v2 HTTP trigger handler (`httpTriggerHandler.HandleUserTriggerRequest`) does implement authorization (`h.authorizeRequest` → `workflowMetadataHandler.Authorize`) and rate limiting (`h.checkRateLimit` → `userRateLimiter.AllowErr`) before dispatching to nodes [4](#0-3) , confirming that the legacy path in `handler.go` is missing equivalent protections that the codebase itself considers necessary.

### Impact Explanation
Without an allowlist check, any unprivileged external caller able to reach the gateway's legacy user message endpoint can trigger workflow execution requests fanned out to every DON member node, without the gateway verifying that the caller is an authorized user of that DON/workflow. Combined with the absence of rate limiting on this path, this also opens a resource-exhaustion vector (unbounded triggering of node work and outbound requests) distinct from the already-limited `handleWebAPIOutgoingMessage` path.

### Likelihood Explanation
The legacy `HandleLegacyUserMessage` path is reachable by any external user message routed by method `MethodWebAPITrigger`; the code path is straightforward (parse payload → check timestamp → check method → forward to nodes) and doesn't depend on any privileged or malicious-peer setup, only on this handler still being active for a given gateway deployment. I could not verify from indexed code whether this legacy handler is still wired up in production gateway configurations or has since been fully superseded by the v2 `httpTriggerHandler`, which limits my confidence about current production exposure.

### Recommendation
Implement the allowlist check (verifying the message sender/workflow is permitted for this DON) and apply rate limiting (per-sender and/or per-workflow) in `HandleLegacyUserMessage` before forwarding to DON members, mirroring the authorization/rate-limit pattern already implemented in `httpTriggerHandler.HandleUserTriggerRequest`. Alternatively, if the legacy path is deprecated, confirm it is disabled/unreachable in production and remove or gate it explicitly.

### Proof of Concept
Not independently reproducible from static analysis alone — the TODO itself is the root-cause evidence: no allowlist or rate-limit call exists between payload validation and `don.SendToNode` fan-out in `HandleLegacyUserMessage` [5](#0-4) , whereas the parallel outgoing-message path and the v2 trigger handler both enforce such controls.

**Note:** All other TODOs found in this scan (e.g., `ocr2/validate/validate.go` DR-OCR validator stub, CCIP changeset "add rest of config validation", CRE reconciler `TODO.md` items on discovery/multi-chain support, `orgID` metering TODO) are either deployment/test tooling, non-reachable by unprivileged users, or informational/config-validation gaps without a concrete auth-bypass or compromise path, and were excluded per scope rules.

	body := msg.Body

		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if payload.Timestamp == 0 {
		h.lggr.Errorw(ErrDecodingPayload)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload,
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

	if uint(time.Now().Unix())-h.config.MaxAllowedMessageAgeSec > uint(payload.Timestamp) {

			RawResponse: codec.EncodeNewErrorResponse(

				nil,
			),
			ErrorCode: api.HandlerError,
