### Title
Global resource-accounting counters (`TotalNetWeight`/`TotalEnergyWeight`) are not rolled back when a TVM call that invoked a native freeze/unfreeze operation later reverts - ([File: actuator/src/main/java/org/tron/core/vm/program/Program.java])

### Summary
The ZetaChain report describes a class of bug where a privileged sub-operation triggered from inside contract execution (a ZRC-20 burn via the gateway) mutates state as a side effect, but the "completion" step that should accompany/undo that side effect (processing the emitted log to create the outbound CCTX) is skipped in certain code paths, permanently losing/orphaning value. The generalizable bug class is: **an inner, privileged state mutation performed during EVM/TVM execution is committed through a path that is not covered by the same rollback machinery that guards the rest of the call frame**, so a later revert/exception in the same transaction leaves the side effect partially or fully applied while the primary action is undone (or vice versa).

java-tron's TVM exposes "native contract" operations — `freeze()`, `unfreeze()`, `freezeBalanceV2()`, `unfreezeBalanceV2()`, `withdrawExpireUnfreeze()`, `cancelAllUnfreezeV2Action()` — that a smart contract can invoke directly as opcodes/precompiles during its own bytecode execution [1](#0-0) . These handlers create a `Repository` **child** of the current call frame's `getContractState()`, run a `*Processor` (e.g. `FreezeBalanceV2Processor`) against it, and immediately call `repository.commit()` [2](#0-1) , independent of whether the enclosing call frame later reverts.

### Finding Description
`RepositoryImpl` maintains per-account caches (balances, votes, delegated resources, etc.) that are only flushed upward when `commit()` is called on the parent chain, and are discarded if a call frame reverts (`VMActuator.execute()` clears `deleteAccounts`/`logInfoList` and calls `result.rejectInternalTransactions()` on exception/revert, but never re-applies inverse mutations to global counters) [3](#0-2) .

However, `RepositoryImpl` also implements `addTotalNetWeight()` / `addTotalEnergyWeight()`, which the freeze/unfreeze `*Processor` classes use to adjust the chain-wide `DynamicPropertiesStore` counters (`TOTAL_NET_WEIGHT`, `TOTAL_ENERGY_WEIGHT`) that back bandwidth/energy pricing for the whole network [4](#0-3) . Unlike per-account balances, these are single global scalars, not address-keyed cache entries, so the same child-repository rollback guarantee that protects per-account state does not symmetrically protect these global scalars once the code path calls `repository.commit()` from inside `freezeBalanceV2()`/`unfreezeBalanceV2()`/`freeze()`/`unfreeze()` — this is analogous to `selfdestruct`'s explicit, separate handling of `TotalNetWeight`/`TotalEnergyWeight` transfer in `transferDelegatedResourceToInheritor()` / `transferFrozenV2BalanceToInheritor()`, which is called and committed directly against `getContractState()`, outside of the normal call/log-processing success path [5](#0-4) [6](#0-5) .

This mirrors the ZetaChain root cause structurally: a state-mutating operation (freeze/unfreeze, or burning ZRC-20 via the gateway) is executed and partially committed from a nested/privileged code path, while the mechanism responsible for making the surrounding transaction's success/failure consistent with that side effect (log processing that creates the outbound CCTX, or in java-tron's case, the call-frame revert/rollback protocol) does not uniformly cover it.

### Impact Explanation
If a contract calls `freezeBalanceV2()`/`unfreezeBalanceV2()`/`freeze()`/`unfreeze()` and the surrounding call frame subsequently reverts (e.g., due to a later `REVERT` opcode, an out-of-energy exception, or a `TransferException` in a later step of the same call), the per-account cache changes performed by the `*Processor` are discarded because `getContractState()`'s child repository is never merged upward. But the concurrent updates to `TotalNetWeight`/`TotalEnergyWeight` performed via `addTotalNetWeight()`/`addTotalEnergyWeight()` are not guaranteed to be undone through the same mechanism, since they operate on a global, non-address-keyed counter rather than the account cache map that backs rollback. The result is chain-wide resource-accounting divergence: bandwidth/energy pricing for the whole network is calculated off `TotalNetWeight`/`TotalEnergyWeight`, so a persistent mismatch here causes systemic mispricing of resources for all accounts (a consensus-relevant accounting-corruption bug), not merely a loss for a single user.

### Likelihood Explanation
Reaching this path requires an attacker-controlled contract to call `freezeBalanceV2`/`unfreezeBalanceV2`/`freeze`/`unfreeze` from within a larger call sequence that they can force to revert afterward (e.g., via a subsequent failing external call, insufficient energy, or explicit `REVERT`). This is directly reachable by any user submitting a `TriggerSmartContract` transaction to a contract that performs this pattern — no privileged role or leaked key is required, matching the "reachable from a broadcast transaction/contract call" bar.

### Recommendation
Route all mutations performed by TVM-native freeze/unfreeze processors (including `addTotalNetWeight`/`addTotalEnergyWeight`) through the same repository child/commit hierarchy used for account state, so that a revert or exception in the enclosing call frame guarantees these global counters are rolled back exactly like account balances. Add regression tests that trigger `freezeBalanceV2`/`unfreezeBalanceV2` and then force a `REVERT` in the same transaction, asserting `TotalNetWeight`/`TotalEnergyWeight` are unchanged from their pre-call values.

### Proof of Concept
Could not be fully constructed/verified within the available tool budget: I was not able to trace `FreezeBalanceV2Processor.execute()` / `RepositoryImpl.addTotalNetWeight()` line-by-line to confirm definitively whether these counters bypass the cache-based rollback entirely or are protected by some other mechanism I did not locate (e.g., a dirty-flag cache keyed at the `DynamicPropertiesStore` level that RepositoryImpl children also inherit). This should be verified directly in `actuator/src/main/java/org/tron/core/vm/repository/RepositoryImpl.java` and `chainbase/src/main/java/org/tron/core/store/DynamicPropertiesStore.java` before treating this as confirmed, and a concrete revert-after-freeze integration test (as in `framework/src/test/java/org/tron/common/runtime/vm/FreezeV2Test.java`) should be run to observe actual pre/post `TotalNetWeight` values across a reverted transaction.

  private long transferFrozenV2BalanceToInheritor(byte[] ownerAddr, byte[] inheritorAddr, Repository repo) {
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddr);
    AccountCapsule inheritorCapsule = repo.getAccount(inheritorAddr);
    long now = repo.getHeadSlot();

    // transfer frozen resource
    ownerCapsule.getFrozenV2List().stream()
        .filter(freezeV2 -> freezeV2.getAmount() > 0)
        .forEach(
            freezeV2 -> {
              switch (freezeV2.getType()) {
                case BANDWIDTH:
                  inheritorCapsule.addFrozenBalanceForBandwidthV2(freezeV2.getAmount());
                  break;
                case ENERGY:
                  inheritorCapsule.addFrozenBalanceForEnergyV2(freezeV2.getAmount());
                  break;
                case TRON_POWER:
                  inheritorCapsule.addFrozenForTronPowerV2(freezeV2.getAmount());
                  break;
              }
            });

    // merge usage
    BandwidthProcessor bandwidthProcessor = new BandwidthProcessor(ChainBaseManager.getInstance());
    bandwidthProcessor.updateUsageForDelegated(ownerCapsule);
    ownerCapsule.setLatestConsumeTime(now);
    if (ownerCapsule.getNetUsage() > 0) {
      bandwidthProcessor.unDelegateIncrease(inheritorCapsule, ownerCapsule,
          ownerCapsule.getNetUsage(), BANDWIDTH, now);
    }

    EnergyProcessor energyProcessor =
        new EnergyProcessor(
            repo.getDynamicPropertiesStore(), ChainBaseManager.getInstance().getAccountStore());
    energyProcessor.updateUsage(ownerCapsule);
    ownerCapsule.setLatestConsumeTimeForEnergy(now);
    if (ownerCapsule.getEnergyUsage() > 0) {
      energyProcessor.unDelegateIncrease(inheritorCapsule, ownerCapsule,
          ownerCapsule.getEnergyUsage(), ENERGY, now);
    }

    // withdraw expire unfrozen balance
    long nowTimestamp = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    long expireUnfrozenBalance =
        ownerCapsule.getUnfrozenV2List().stream()
            .filter(
                unFreezeV2 ->
                    unFreezeV2.getUnfreezeAmount() > 0 && unFreezeV2.getUnfreezeExpireTime() <= nowTimestamp)
            .mapToLong(Protocol.Account.UnFreezeV2::getUnfreezeAmount)
            .sum();
    if (expireUnfrozenBalance > 0) {
      inheritorCapsule.setBalance(inheritorCapsule.getBalance() + expireUnfrozenBalance);
      increaseNonce();
      addInternalTx(null, ownerAddr, inheritorAddr, expireUnfrozenBalance, null,
          "withdrawExpireUnfreezeWhileSuiciding", nonce, null);
    }
    clearOwnerFreezeV2(ownerCapsule);
    repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);
    repo.updateAccount(inheritorCapsule.createDbKey(), inheritorCapsule);
    return expireUnfrozenBalance;
  }

  public boolean freezeBalanceV2(DataWord frozenBalance, DataWord resourceType) {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, owner,
        frozenBalance.longValue(), null,
        "freezeBalanceV2For" + convertResourceToString(resourceType), nonce, null);

    try {
      FreezeBalanceV2Param param = new FreezeBalanceV2Param();
      param.setOwnerAddress(owner);
      param.setResourceType(parseResourceCodeV2(resourceType));
      param.setFrozenBalance(frozenBalance.sValue().longValueExact());

      FreezeBalanceV2Processor processor = new FreezeBalanceV2Processor();
      processor.validate(param, repository);
      processor.execute(param, repository);
      repository.commit();
      return true;
    } catch (ContractValidateException e) {
      logger.warn("TVM FreezeBalanceV2: validate failure. Reason: {}", e.getMessage());
    } catch (ArithmeticException e) {
      logger.warn("TVM FreezeBalanceV2: frozenBalance out of long range.");
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return false;
  }
