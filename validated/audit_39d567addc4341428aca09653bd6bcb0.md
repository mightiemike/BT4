## Analysis

The reported bug class is **reward/value inflation via a flash loan that manipulates a state snapshot used mid-transaction**, exploiting the fact that a protocol takes a price/state reading and then acts on it atomically without protecting against attacker-controlled manipulation of that reading within the same block.

Push Chain's closest native analog is in the **gas-token auto-swap path of `x/uexecutor`**, where the module reads a live Uniswap V3 quote from its own on-chain AMM and immediately uses it (with only a fixed 5% slippage buffer) to execute a real swap that moves user funds — a pattern structurally identical to "read state → act on state → same-transaction" that a flash loan/sandwich can exploit.

### Title
On-chain Uniswap V3 quote used for auto-swap deposits is sandwichable via flash-loan pool manipulation, causing under-valued PRC20→PC conversions - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`GetSwapQuote` reads a live price from the protocol-deployed Uniswap V3 `QuoterV2` contract on Push Chain's own EVM [1](#0-0) , and the result is used, with a fixed 5% slippage tolerance, to compute `minPCOut` for `depositPRC20WithAutoSwap` [2](#0-1) . The same quote→swap pattern is repeated for `GAS_AND_PAYLOAD` inbounds [3](#0-2)  and for excess-gas refunds on outbound completion [4](#0-3) . Because the pool being quoted is a normal, permissionlessly-tradeable on-chain AMM, and the 5% band is the *only* protection against price movement, an unprivileged attacker can submit an ordinary EVM transaction that swaps against the same pool immediately before the inbound-finalizing transaction lands in the same block, depress/inflate the quoted price within the 5% window, capture the auto-swap's real conversion at the manipulated rate, and then reverse the manipulating trade — extracting value from the crosschain depositor's PRC20→PC conversion. This mirrors the reported bug class: a state value (here, an AMM spot price) that is read and consumed atomically within one execution, with no time-weighting, TWAP, or wider deviation guard, letting a same-block manipulation (flash swap) distort the value used for real fund movement.

### Finding Description
- `GetSwapQuote` performs a single spot-price read (`quoteExactInputSingle`, `commit=false`) against the `UniversalCore`-configured Uniswap V3 pool [1](#0-0) .
- That spot quote is immediately turned into `minPCOut = quote * 95 / 100` and passed straight into a real, value-moving swap (`depositPRC20WithAutoSwap`) [5](#0-4) , [6](#0-5) .
- The same construction is used for the gas-refund swap path when an outbound completes with unused gas [4](#0-3) .
- There is no TWAP, no multi-block averaging, and no wider circuit-breaker beyond the fixed 5% band — a spot price at the exact moment of execution is trusted.
- The inbound-finalizing transaction (last `MsgVoteInbound` reaching quorum) executes the deposit+swap synchronously as part of one Cosmos transaction [7](#0-6) , but nothing prevents an ordinary unprivileged account from placing an adjacent transaction in the same block (via normal mempool gas-price competition) that first swaps against the same pool to shift its spot price, then swaps back after the module's auto-swap executes — a classic flash-loan/sandwich pattern, explicitly called out as in-scope by the project's own policy ("This does not exclude oracle manipulation/flash-loan attacks" in `SECURITY.md`) [8](#0-7) .

### Impact Explanation
A successful sandwich forces the module's `depositPRC20WithAutoSwap` (or `refundUnusedGas` swap leg) to execute at an artificially unfavorable rate within the 5%-tolerance band, causing the crosschain user's UEA to receive less PC-native value than the fair market rate for their bridged gas/funds, while the attacker captures the difference by reversing their manipulating trade in the same block. This is a corruption of native-asset accounting/token-mapping value transferred through the universal execution flow (in-scope: "corruption of PRC20 or native asset accounting ... token mapping") and results in a real, unauthorized value transfer from user deposits to the attacker.

### Likelihood Explanation
Feasibility depends on the pool's on-chain liquidity depth at the affected fee tier: this is explicitly noted as "more feasible for smaller [pools]" in the original report, and thinly-liquid PRC20/WPC pools (especially for newer or lower-cap tokens) are realistic on a young chain. The attacker needs no privileged role — only an ordinary EVM account able to submit transactions and, ideally, pay competitive gas to land adjacent to the inbound-finalizing transaction, which is a standard, permissionless MEV/sandwich capability rather than a validator-privileged one.

### Recommendation
Replace the single-block spot quote with a TWAP (time-weighted average price) read from the pool, add a maximum-deviation check against a longer window before trusting `GetSwapQuote`'s output, and/or require the deposit-triggering flow to defer or randomize execution relative to raw mempool ordering so an attacker cannot deterministically bracket the module's swap. At minimum, tighten and make configurable the slippage band per token/pool liquidity rather than a fixed 5% for all tokens.

### Proof of Concept
1. Attacker identifies a PRC20/WPC pool with shallow liquidity that is used by `GetSwapQuote`/`CallPRC20DepositAutoSwap` for a GAS or GAS_AND_PAYLOAD inbound route.
2. Attacker observes (via mempool) a pending `MsgVoteInbound` that will bring an inbound to quorum and trigger `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`.
3. Attacker submits, in the same block, a large swap against the same pool to move the spot price down (or up) within a plausible range still inside the 5% slippage band that `CallPRC20DepositAutoSwap` will tolerate.
4. The module's `GetSwapQuote` reads the manipulated spot price; `CallPRC20DepositAutoSwap` executes the deposit-swap at the distorted rate, giving the victim UEA less PC than fair value.
5. Attacker reverses their manipulating swap in the same or following block, extracting the price difference as profit funded by the shortfall in the victim's auto-swapped deposit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
