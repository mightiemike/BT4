### Title
Vault `accrue` silently passes through a stale index during a pause instead of reverting, letting `market` bake mispriced debt/collateral into permanent on-chain state - (File: `local-testing/contracts/vault/vault-sbtc.clar`, `mainnet/contracts/vault/v0-vault-ststx.clar`, `mainnet/contracts/market/v0-4-market.clar`)

### Summary
Every vault's `accrue` function is supposed to update the borrow/liquidity `index`/`lindex` to reflect elapsed interest. When the vault's `accrue` flag is administratively paused, `accrue` does not revert and does not skip the caller — it returns the **old, un-updated** `index`/`lindex` as if they were the current, correct values. `market`'s `accrue-and-cache` caches this stale pass-through result for the block and feeds it straight into zToken price resolution and into debt-scaling math used by `borrow`, `repay`, and `liquidate`. The stale values then get baked into permanently stored `scaled` debt/collateral entries.

### Finding Description
`accrue` in the vault contracts checks the pause state and, if paused, short-circuits with the stored (stale) index instead of reverting: [1](#0-0) 

This same pattern is duplicated across every vault (`vault-ststx.clar`, `vault-ststxbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdh.clar`), confirming it is a systemic implementation choice, not a one-off: [2](#0-1) 

The market's caching layer treats whatever `vault-accrue` returns as ground truth for the whole block and caches it, with no distinction between "freshly accrued" and "passed-through/stale": [3](#0-2) 

That cached value is then used to resolve zToken prices via `resolve-ztoken`: [4](#0-3) 

and to compute both collateral and debt notional values used in health checks: [5](#0-4) 

`borrow` explicitly accrues first ("populates cache for ztokens") and then resolves prices/health using that cache, and finally converts to `scaled-debt-added` using the very same (potentially stale) `borrow-index` that gets permanently written via `debt-add-scaled`: [6](#0-5) 

`liquidate` follows the identical "accrue FIRST, then resolve prices" ordering: [7](#0-6) 

### Impact Explanation
Because the pause pass-through returns the old index instead of reverting, any `borrow`/`repay`/`liquidate` executed while a vault's accrual is paused uses financial state that does not reflect actual elapsed interest. Debt taken out (or repaid) during the pause is scaled using the frozen `index`, and that `scaled` amount is written permanently to storage (`debt-add-scaled` / collateral scaling). When the pause lifts and accrual resumes normally, the true interest that should have accrued during the pause window is never retroactively applied to positions that borrowed/repaid mid-pause — collateral and debt accounting permanently diverges from the economically correct value. This can let a borrower's health check pass using undervalued debt (or overvalued zToken collateral), enabling them to extract more borrowing power than truly collateralized — a protocol-insolvency-class impact — or can incorrectly block/mis-price a liquidation that should have occurred, causing temporary freezing of the ability to correctly seize collateral.

### Likelihood Explanation
Triggering the condition only requires the vault's `accrue` pause flag to be active, which is an operational admin control (e.g., during maintenance or an oracle/liquidity issue) rather than a compromise of the DAO or leaked keys. Any user transaction (`borrow`, `repay`, `liquidate`, collateral add/remove with debt) executed while that pause is active will silently use the stale index end-to-end within that single transaction, satisfying the "single-transaction pass-through instead of revert" pattern.

### Recommendation
Change the paused branch of `accrue` in every vault to `(err ERR-PAUSED)` (or an equivalent revert) instead of `(ok { index: idx, lindex: lidx })`, so that any operation depending on fresh accrual state fails closed during a pause rather than silently proceeding on stale data. Alternatively, tag the returned indexes with a "stale" flag that `market` explicitly checks before permitting scaled-debt/collateral mutations, health checks, or liquidations.

### Proof of Concept
1. Admin sets `accrue` pause = true on `vault-usdc` (or any vault) for maintenance, freezing `index`/`lindex` at their pre-pause values as shown in `accrue`'s paused branch.
2. A user calls `market.borrow` for `zUSDC`-backed debt or `USDC` debt. `borrow` calls `accrue-user-debts`/`accrue-user-collateral` → `accrue-and-cache` → `vault-accrue` → the paused `vault-usdc.accrue`, which returns the stale `index`/`lindex` (`local-testing/contracts/vault/vault-sbtc.clar:841-843` pattern) and this gets cached in `index-cache` for the block.
3. `get-assets`/`get-notional-evaluation` resolve collateral/debt USD values using this stale cached index via `resolve-ztoken` and `calculate-asset-notional-value`.
4. `is-healthy-with-mask` passes based on the stale (lower) debt/(higher) collateral notional value that doesn't reflect the interest that should have accrued.
5. `borrow` proceeds, converting the requested amount to `scaled-debt-added` using the stale `borrow-index`, and writes it permanently via `contract-call? .v0-market-vault debt-add-scaled` (`mainnet/contracts/market/v0-4-market.clar:1289-1296`).
6. When the pause is lifted and true accrual resumes, the position's `scaled` debt understates real economic debt owed for the pause window — funds/interest that should have accrued are permanently lost from vault accounting.

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
