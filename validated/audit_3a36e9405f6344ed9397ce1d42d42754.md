### Title
Nakamoto reward-set signer weight can floor to an empty set, letting a block with zero signer signatures pass consensus verification - ([File: stackslib/src/chainstate/nakamoto/signer_set.rs] / [File: stackslib/src/chainstate/nakamoto/coordinator/mod.rs] / [File: stackslib/src/chainstate/nakamoto/mod.rs])

### Summary
The external report's bug class ("a divisor/threshold parameter reaching 0 makes an otherwise-guarded check silently pass") has a real analog in the Nakamoto signer-weight/threshold machinery. When per-signer stacked amounts floor to zero weight under `StacksChainState::make_signer_set`, the resulting reward set can end up with `signers = Some(vec![])` rather than `None`. One reward-set loading path, `read_reward_set_at_calculated_block`, only rejects a `None` signer list, not an *empty* one, so this degenerate reward set is accepted and stored. Later, `NakamotoBlockHeader::verify_signer_signatures` computes `total_weight = 0` and `threshold = compute_voting_weight_threshold(0) = 0`, so a block carrying **zero signer signatures** satisfies `total_weight_signed (0) < threshold (0)` as false, and is treated as validly signed.

### Finding Description
`StacksChainState::make_signer_set` (`stackslib/src/chainstate/stacks/boot/mod.rs:1020-1072`) filters out any aggregated signer whose `weight = stacked_amt / threshold == 0`, but it unconditionally returns `Some(signer_set)` even when the filtered vector is empty: [1](#0-0) 

The `threshold` used here is derived from `get_reward_threshold_and_participation`, which scales with `max(participation, liquid_ustx / POX_MAXIMAL_SCALING)` and is independent of how many individual stackers there are: [2](#0-1) 

If total participation is low relative to `liquid_ustx`, the computed per-slot threshold can exceed the aggregated amount each individual signer key committed, causing every entry to floor to weight 0 and be filtered — producing `RewardSet` with `signers: Some(vec![])`.

The Nakamoto PoX-4 path that computes and persists this reward set, `pox_4_compute_and_update_signers`, does **not** check for this empty-signer-set condition (unlike the PoX-5 path, which explicitly rejects it): [3](#0-2) [4](#0-3) 

When this reward set is later read back for verifying blocks in the corresponding reward cycle, `read_reward_set_at_calculated_block` only guards against `signers().is_none()`, not an empty (but `Some`) vector: [5](#0-4) 

Compare this to the sibling epoch-2/nakamoto-boundary reader, `OnChainRewardSetProvider::get_reward_set`, which *does* explicitly check `reward_set.signers().map_or(true, |s| s.is_empty())` and errors out — showing the intended invariant is "no empty signer set may reach Nakamoto", but the invariant is not enforced on this path: [6](#0-5) 

Finally, `NakamotoBlockHeader::verify_signer_signatures` treats the empty-signer reward set as trivially satisfied: [7](#0-6) 
- `reward_set.signers()` returns `Some(&vec![])`, so the initial `else` guard does not fire.
- `total_weight = reward_set.total_signing_weight()` folds over an empty vector and returns `Ok(0)`.
- The `for signature in self.signer_signature.iter()` loop only executes if signatures are present; if the block's `signer_signature` field is also empty, `total_weight_signed` remains `0`.
- `threshold = compute_voting_weight_threshold(0)` evaluates to `0` (`stackslib/src/chainstate/nakamoto/mod.rs:1192-1207`).
- `if total_weight_signed < threshold` → `0 < 0` is `false`, so the function returns `Ok(0)` — **the block is accepted as validly signed with no signatures at all.**

This breaks the core equality the signer subsystem is supposed to enforce: *"a block is valid only if signer weight ≥ threshold weight of the active signer set."* Here, both sides degenerate to zero simultaneously, and the check silently passes instead of failing closed.

### Impact Explanation
This is deterministic, on-chain-state-driven behavior: every node computes the same `threshold`/`participation`/`signer_set` from the same PoX-4 stacking data, so every node in the network would independently reach the same degenerate empty-signer reward set and would independently accept the same zero-signature block as valid. This is not merely a validation *divergence* between nodes — it is a network-wide bypass of the Nakamoto signer-approval mechanism, i.e., an "invalid block accepted network-wide" per the impact taxonomy, since a block with zero signer weight backing it would pass `verify_signer_signatures` and could be appended to the canonical chain.

### Likelihood Explanation
Reaching this condition requires no majority stake and no governance/admin action — it only requires that aggregate PoX-4 stacking participation for a reward cycle be low enough, relative to `liquid_ustx`, that every individual signer's floor-divided weight rounds down to zero. This is most plausible in low-participation periods (e.g. testnets, early network states, or reward cycles where the majority of previously-locked STX unlocks and inflates `liquid_ustx` relative to newly-locked STX) — conditions that do not require an attacker to control significant stake, only to observe or wait for low aggregate participation. This makes it a "minority-triggerable" (in fact "no-stake-required") edge case rather than one gated by a 51%/majority assumption.

### Recommendation
Add the same guard used in `OnChainRewardSetProvider::get_reward_set` and in the PoX-5 path to `pox_4_compute_and_update_signers` and to `read_reward_set_at_calculated_block`: explicitly reject/fail-closed (return `Error::PoXAnchorBlockRequired` or an equivalent `ChainstateError`) whenever `reward_set.signers()` is `Some(&[])` in a Nakamoto reward cycle, not just when it is `None`. Additionally, `NakamotoBlockHeader::verify_signer_signatures` should treat a zero total signing weight as an explicit error condition rather than relying on `0 < 0` to fail safely.

### Proof of Concept
Conceptual reproduction (cannot be executed without live node/test harness access):
1. Configure a PoX-4/Nakamoto reward cycle where aggregate stacking participation is low enough that `get_reward_threshold_and_participation` computes a `threshold` exceeding every individual stacker's `amount_stacked` (e.g., one or a few small stackers, each below `liquid_ustx / (4 * reward_slots)`).
2. Let `pox_4_compute_and_update_signers` run for that cycle; `StacksChainState::make_signer_set` filters every entry to weight 0, yielding `RewardSet.signers = Some(vec![])`, which is stored via `update_signers`/`get_reward_set`.
3. In the following reward cycle, a miner produces a Nakamoto block with `signer_signature = vec![]` (no signer approvals).
4. `read_reward_set_at_calculated_block` loads the persisted reward set, passes the `signers().is_none()` check (since it's `Some(vec![])`), and returns it.
5. `NakamotoBlockHeader::verify_signer_signatures` computes `total_weight = 0`, `threshold = 0`, `total_weight_signed = 0`, and returns `Ok(0)` — the unsigned block is accepted.

Whether the specific numeric thresholds in `get_reward_threshold_and_participation` can be driven to zero-weight-for-all-entries in realistic mainnet conditions (vs. only in low-liquidity testnets) was not fully verified within the available tool budget; a background engineering session with access to run the existing property tests (`stackslib/src/chainstate/stacks/tests/reward_set.rs`, which currently assumes `threshold > 0` via `prop_assume!` and does not explicitly probe the "all entries filtered to empty" case for PoX-4) would be needed to construct a concrete numeric example and confirm end-to-end reachability through `pox_4_compute_and_update_signers`.

    pub fn get_reward_threshold_and_participation(
        pox_settings: &PoxConstants,
        addresses: &[RawRewardSetEntry],
        liquid_ustx: u128,
    ) -> (u128, u128) {
        let participation = addresses
            .iter()
            .fold(0, |agg, entry| agg + entry.amount_stacked);

        assert!(
            participation <= liquid_ustx,
            "CORRUPTION: More stacking participation than liquid STX"
        );

        // set the lower limit on reward scaling at 25% of liquid_ustx
        //   (i.e., liquid_ustx / POX_MAXIMAL_SCALING)
        let scale_by = cmp::max(participation, liquid_ustx / POX_MAXIMAL_SCALING);

        let reward_slots = u128::try_from(pox_settings.reward_slots())
            .expect("FATAL: unreachable: more than 2^128 reward slots");
        let threshold_precise = scale_by / reward_slots;
        // compute the threshold as nearest 10k > threshold_precise
        let ceil_amount = match threshold_precise % POX_THRESHOLD_STEPS_USTX {
            0 => 0,
            remainder => POX_THRESHOLD_STEPS_USTX - remainder,
        };
        let threshold = threshold_precise + ceil_amount;
        info!(
            "PoX participation threshold is {}, from {} + {} ({}), participation is {}",
            threshold, threshold_precise, ceil_amount, scale_by, participation
        );
        (threshold, participation)
    }

    #[cfg_attr(test, mutants::skip)]
    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);
    }
