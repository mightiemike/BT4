### Title
Nakamoto block signing threshold silently collapses to zero when the reward-set signer list is present-but-empty, allowing a block with zero signer signatures to be accepted - (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` and its two dependencies, `RewardSet::total_signing_weight` and `NakamotoBlockHeader::compute_voting_weight_threshold`, only guard against the case where a reward set has *no* signer field at all (`signers() == None`). They never guard against the reward set having signers `Some(vec![])` — a non-`None`, zero-length list. In that degenerate state both sides of the acceptance check independently default to `0` (required threshold `0`, and accumulated signature weight `0` for a block with an empty `signer_signature` vector), so the equality/inequality check `total_weight_signed < threshold` is trivially false and the block is accepted with **no signer signatures whatsoever**. This is structurally the same class of bug as the Sherlock H-6 finding: an authorization check that is bypassed because two independently-computed values both collapse to the same "unset" default.

### Finding Description
`RewardSet::total_signing_weight` treats an empty-but-present signer vector as valid input and returns `Ok(0)` instead of an error — it only returns `Err` when `signers()` returns `None`: [1](#0-0) 

`NakamotoBlockHeader::compute_voting_weight_threshold` computes `ceil(total_weight * 7 / 10)`, so for `total_weight == 0` the threshold is `0`: [2](#0-1) 

`verify_signer_signatures` only rejects reward sets with `signers() == None`, not `Some(vec![])`. When `signers` is an empty (but present) vector: `signers_by_pk` is empty, the loop over `self.signer_signature` executes zero times if the header carries no signatures, `total_weight_signed` stays `0`, `total_weight` is `0`, `threshold` is `0`, and `0 < 0` is false, so the function returns `Ok(0)` — the block's signatures are considered sufficiently validated: [3](#0-2) 

This state is reachable through the reward-set computation pipeline: `StacksChainState::make_signer_set` filters out any entry whose computed weight rounds down to `0` via integer division `stacked_amt / threshold`, and returns `Some(vec![])` (not `None`) whenever the input entries list is non-empty but every entry's weight rounds to zero: [4](#0-3) 

Contrast this with the newer PoX-5 path, `pox_5_compute_and_update_signers`, which explicitly detects and rejects an empty signer set with a hard error before it can propagate into a `RewardSet`: [5](#0-4) 

The PoX-4 path (`pox_4_compute_and_update_signers`) has no equivalent guard — it passes whatever `make_reward_set`/`make_signer_set` produces straight into the stored `RewardSet`, using `unwrap_or(&empty_signers)` only for the StackerDB-list construction, not as a correctness check on the reward set itself: [6](#0-5) 

### Impact Explanation
If a reward cycle's stacking participation is such that every stacker's `amount_stacked / threshold` rounds down to `0` (e.g., broad but very shallow participation, or a threshold computed from `liquid_ustx` that is momentarily large relative to actual stacked amounts), the resulting `RewardSetV0.signers` field becomes `Some(vec![])`. From that point on, for the entire reward cycle, `verify_signer_signatures` will accept **any** Nakamoto block whose `signer_signature` vector is empty — i.e., a miner can produce and have accepted blocks with zero real signer approval. This breaks the core Nakamoto consensus invariant that a block needs signer-weight approval above a 70% threshold, and different nodes that receive/didn't receive out-of-band signatures could diverge on which blocks they consider validly signed, leading to a chain split / invalid-block-accepted-network-wide scenario, matching the Critical impact bucket ("an invalid block accepted... network-wide").

### Likelihood Explanation
This does not require an attacker to forge signatures or compromise any key — the vulnerable state is a data condition of the PoX-4 reward-set computation (`make_signer_set`'s weight-flooring behavior), not an attacker action against a live check. It requires a low-participation reward cycle to produce an all-zero-weight (but non-empty) `RawRewardSetEntry` list, which is a natural (if rare) participation edge case rather than a guaranteed-to-happen condition, so likelihood is data-dependent and not universally reproducible. However, once the degenerate reward set exists, exploitation requires no privilege at all — any miner can simply omit signatures on a block, so the trigger for actually using the bypass is minority/unprivileged.

### Recommendation
- In `RewardSet::total_signing_weight`, additionally return an error when `signers()` is `Some(vec![])` (i.e., treat "no signers with nonzero weight" the same as "no signers field") rather than silently returning `Ok(0)`.
- In `NakamotoBlockHeader::verify_signer_signatures`, explicitly reject when `signers.is_empty()`, mirroring the `None` check already present, so an empty reward set can never yield `threshold == 0`.
- Add the same "empty signer set is fatal" guard that `pox_5_compute_and_update_signers` already has to the PoX-4 path (`pox_4_compute_and_update_signers`), so a degenerate reward set is caught at computation time instead of at block-verification time.

### Proof of Concept
1. Construct a PoX-4 reward cycle where several distinct stackers each stack an amount `A` such that `A / threshold == 0` for the reward-set's per-slot `threshold` (e.g., threshold set high by low total participation, while each individual `amount_stacked` is just under it). `StacksChainState::make_signer_set` (lines 1020-1072) will produce `signer_set = Some(vec![])` since every entry's `weight == 0` is filtered out but the entries list itself is non-empty.
2. This `RewardSetV0` (with `signers: Some(vec![])`) becomes the active reward set for the next cycle via `pox_4_compute_and_update_signers` (no guard against empty `Some(vec![])`, lines 703-737 of `signer_set.rs`).
3. During the reward cycle, a miner produces a `NakamotoBlockHeader` with `signer_signature: vec![]` (no signatures collected/attached).
4. `verify_signer_signatures` is invoked: `reward_set.signers()` returns `Some(&vec![])` so the `None`-check at lines 1103-1107 does not fire; `total_weight = reward_set.total_signing_weight()` returns `Ok(0)` (lines 493-503 of `boot/mod.rs`); `threshold = compute_voting_weight_threshold(0) = 0` (lines 1192-1207); the `for signature in self.signer_signature.iter()` loop (empty) leaves `total_weight_signed = 0`; the final check `total_weight_signed < threshold` → `0 < 0` → `false`, so the function returns `Ok(0)` and the block is treated as validly signed with zero actual signer approval.

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
    }

    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);
    }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
