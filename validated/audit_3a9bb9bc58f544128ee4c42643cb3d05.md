### Title
Missing declared-class existence check in Starknet OS `execute_replace_class` allows a state transition the sequencer itself would reject - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The audited bug removes an "active" resource without first verifying the resource actually exists/is active, corrupting downstream accounting. The Starknet OS analog is the `replace_class` syscall handler: the Rust/blockifier execution path validates that the target class hash is actually declared before mutating a contract's class hash, but the Cairo Starknet-OS re-execution path performs the identical state mutation with **no existence check at all** — the check is literally marked as an outstanding `TODO`.

### Finding Description
In blockifier, `replace_class` explicitly reads the compiled class before writing the new class hash, which causes the transaction to revert with `"... is not declared"` if the class hash is undeclared: [1](#0-0) 

The same enforcement, and reversion behavior, is verified by tests: [2](#0-1) 

In the Starknet OS Cairo implementation of the same syscall, the state entry is unconditionally updated with the caller-supplied `class_hash`, with an explicit acknowledgment that the "is declared" check is missing: [3](#0-2) 

The deprecated-syscalls Cairo path (`execute_replace_class` in `deprecated_execute_syscalls.cairo`) has the exact same gap — it writes the new `StateEntry` with the requested `class_hash` without any check that the class was declared: [4](#0-3) 

This is structurally the same bug class as the audited report: a state-mutating operation (`removeBSPOperator` removing an operator regardless of whether it is actually active; `execute_replace_class` in the OS setting a contract's class hash regardless of whether the target class is actually declared) proceeds without validating a precondition that the "reference" implementation (blockifier) does enforce.

### Impact Explanation
The Starknet OS is the authoritative Cairo program used to independently re-derive/verify the state transition (and, ultimately, the committed state root/block hash) for proving and OS-based validation flows (e.g., Echonet OS validation service, SNOS flow tests). Because the OS's `execute_replace_class` omits the "is declared" check that blockifier enforces, a transaction/program path that reaches this syscall with an undeclared class hash is handled inconsistently between the two execution engines: blockifier reverts the transaction, while the OS accepts it and commits a `new_class_hash` for the contract with no corresponding declared class. This is a concrete case of "honest-node divergence" / "wrong committed root" risk — the two components that are supposed to agree on the resulting state (and therefore on the committed root/block hash) can disagree on whether this particular state mutation is valid, since one enforces a precondition the other omits entirely.

### Likelihood Explanation
`replace_class` is a syscall directly reachable from a single unprivileged transaction sender's contract execution (any deployed contract can invoke it). No special privileges, timing, or multi-party collusion is required to reach the vulnerable code path — an attacker only needs to deploy/call a contract that invokes `replace_class` with an undeclared class hash while the flow is processed via the Starknet OS execution path rather than (or in addition to) blockifier's Rust path.

### Recommendation
Add an explicit "class is declared" check in the Cairo `execute_replace_class` implementations (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`), mirroring the blockifier Rust behavior (read/verify the compiled class for `class_hash` and fail/revert if it is not declared) before writing the new `StateEntry`. Resolve the outstanding `TODO(Yoni, 1/1/2026)` marker accordingly so both execution engines enforce identical preconditions for this syscall.

### Proof of Concept
1. Deploy a Cairo1 contract exposing an entry point that invokes the `replace_class` syscall (as in the `test_replace_class` feature contract used by blockifier's own tests). [2](#0-1) 
2. Invoke that entry point supplying an arbitrary, never-declared class hash.
3. Under blockifier, execution reverts with an `"is not declared"` error, as asserted in the existing test.
4. Under the Starknet OS Cairo execution path (`execute_replace_class`), the same call proceeds and unconditionally commits a `StateEntry` with the undeclared `class_hash` for the contract, because the declared-class check is absent (only a TODO comment notes its absence). [5](#0-4) 
5. This demonstrates a state-transition divergence between the two execution engines for the identical transaction/syscall input.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
