## Finding

### Title
Version/metadata desync between publish-time validation and runtime randomness-annotation lookup allows unvalidated `#[randomness]` (and other) function attributes on version-5 modules - ([File: types/src/vm/module_metadata.rs])

### Summary
`get_metadata_from_compiled_code` (used during module publish validation) special-cases bytecode `version() == 5` by clearing `fun_attributes`/`struct_attributes` before any attribute is validated, with an explicit comment admitting "this should have been gated in the verify module metadata." [1](#0-0)  However `get_metadata` — the function backing `get_randomness_annotation_for_entry_function`, which is used both by consensus (`rand_txns_check`) and by the VM at execution time — reads the *same raw metadata bytes* without any such version-based clearing. [2](#0-1) 

### Finding Description
The Aptos binary format only allows a `METADATA` table starting at `VERSION_5`, so a version-5 module can legally embed a V1 metadata blob (`aptos::metadata_v1`) at the deserializer level. [3](#0-2)  But the V1 metadata *schema* is documented as only intended for file-format version ≥ 6: `METADATA_V1_MIN_FILE_FORMAT_VERSION: u32 = 6`. [4](#0-3) 

`verify_module_metadata_for_module_publishing`, which is the only gate that checks whether `fun_attributes`/`struct_attributes` entries are legitimate (e.g. `is_valid_unbiasable_function`, `is_valid_view_function`, rejecting unknown attribute kinds), obtains its metadata via `get_metadata_from_compiled_code`. [5](#0-4)  For `version() == 5`, that helper wipes `fun_attributes`/`struct_attributes` to empty *before* the validation loops run, so the loops iterate over nothing and skip all checks — an attacker can attach an arbitrary `KnownAttribute` (including a fabricated `#[randomness(...)]` claim, or any other/unknown kind) to any function, public or private, entry or non-entry, and publication still succeeds. [6](#0-5) 

At runtime, `get_randomness_annotation_for_entry_function` does not go through `get_metadata_from_compiled_code`; it calls `get_metadata`, which has no version check at all and simply deserializes and returns whatever `fun_attributes` are present in the raw module metadata. [7](#0-6)  This function is consumed by consensus's `rand_txns_check` to decide whether a block "needs randomness" and must wait for randomness aggregation. [8](#0-7)  It is also imported into `aptos_vm.rs` for use during entry-function dispatch. [9](#0-8) 

So the two places that are supposed to agree on "did the compiler/validator actually authorize this attribute for this function" diverge specifically for version-5 modules: the validator treats the attributes as absent (and therefore performs no legitimacy check on them), while the runtime randomness-lookup path treats them as present and semantically meaningful.

### Impact Explanation
This breaks the invariant that randomness annotations (and other `KnownAttribute`s such as view-function/resource-group markers) only apply to functions that were actually compiled and validated with them. A version-5 module can carry a crafted, unvalidated `#[randomness]` marker on a function that would have been rejected by `is_valid_unbiasable_function` (e.g. a public function) had validation actually run. Downstream consumers of `get_randomness_annotation_for_entry_function` (block-level "does this block need randomness" signal in consensus, and any VM-side dispatch logic keyed off the same function) then act on attacker-controlled, unvalidated data rather than the ground-truth compiled semantics.

### Likelihood Explanation
Reaching this requires an unprivileged actor to hand-craft raw module bytecode (bypassing the normal Move compiler) that sets the file-format `version` field to exactly 5 while still embedding a V1 metadata table with attacker-chosen `fun_attributes`, then publish it via the standard `code::publish_package_txn` entry point. Constructing such bytecode is feasible (the binary format explicitly permits `METADATA` at version 5), and no other part of `verify_module_metadata_for_module_publishing` blocks it for this specific version value; `check_metadata_format`, when run, only validates that the bytes deserialize, not their content or version-appropriateness. [10](#0-9) 

### Recommendation
Make the version-5 handling consistent everywhere metadata is read: either (a) have `get_metadata` (and hence `get_randomness_annotation_for_entry_function`) apply the same `version() == 5` clearing logic that `get_metadata_from_compiled_code` applies, or (b) reject V1 metadata outright at deserialization/publish time for any module with `version() < METADATA_V1_MIN_FILE_FORMAT_VERSION (6)` instead of silently clearing it post hoc, so there is a single authoritative source of truth for which attributes are legitimate.

### Proof of Concept
1. Compile a normal Move module, then use `CompiledModule::deserialize`/manual field patching (as done in existing test helpers `build_package_and_insert_attribute`/`test_bad_fun_attribute_in_compiled_module`) to force `compiled_module.version = 5` and insert an `aptos::metadata_v1` entry whose `fun_attributes` maps a public, non-entry function to `KnownAttribute::randomness(None)`. [11](#0-10) 
2. Publish via `code_publish_package_txn`; because `get_metadata_from_compiled_code` clears attributes for version 5 before validation, `verify_module_metadata_for_module_publishing`'s attribute loop is empty and the publish succeeds despite the attribute being invalid for that function. [6](#0-5) 
3. Call `get_randomness_annotation_for_entry_function` (as consensus does in `rand_txns_check`) against the published module's raw metadata for that function and observe it returns `Some(RandomnessAnnotation)` even though the function was never legitimately validated as unbiasable-eligible, diverging from ground truth. [7](#0-6) 

**Caveat**: I was unable to fully trace, within the available tool budget, the exact single call site in `aptos-move/aptos-vm/src/aptos_vm.rs` that consumes `get_randomness_annotation_for_entry_function`'s result during entry-function execution (only the import and one match were located), so I cannot conclusively confirm whether this specific desync directly perturbs `TransactionOutput`/write-set bytes versus only affecting the consensus-level randomness-wait signal. I recommend a Devin session trace that call site to determine whether gas charging or execution-path selection (and thus committed state) is affected, or whether the impact is confined to the non-consensus-critical scheduling hint in `pipeline_builder.rs`.

/// Extract metadata from the VM, upgrading V0 to V1 representation as needed
pub fn get_metadata(md: &[Metadata]) -> Option<Arc<RuntimeModuleMetadataV1>> {
    if let Some(data) = find_metadata(md, APTOS_METADATA_KEY_V1) {
        V1_METADATA_CACHE.with(|ref_cell| {
            let mut cache = ref_cell.borrow_mut();
            if let Some(meta) = cache.get(&data.value) {
                meta.clone()
            } else {
                let meta = bcs::from_bytes::<RuntimeModuleMetadataV1>(&data.value)
                    .ok()
                    .map(Arc::new);
                cache.put(data.value.clone(), meta.clone());
                meta
            }
        })
    } else if let Some(data) = find_metadata(md, APTOS_METADATA_KEY) {
        V0_METADATA_CACHE.with(|ref_cell| {
            let mut cache = ref_cell.borrow_mut();
            if let Some(meta) = cache.get(&data.value) {
                meta.clone()
            } else {
                let meta = bcs::from_bytes::<RuntimeModuleMetadata>(&data.value)
                    .ok()
                    .map(RuntimeModuleMetadata::upgrade)
                    .map(Arc::new);
                cache.put(data.value.clone(), meta.clone());
                meta
            }
        })
    } else {
        None
    }
}

/// For the specified entry function, tries to find randomness attribute in its metadata. If it
/// does not exist, [None] is returned.
pub fn get_randomness_annotation_for_entry_function(
    entry_func: &EntryFunction,
    metadata: &[Metadata],
) -> Option<RandomnessAnnotation> {
    get_metadata(metadata).and_then(|metadata| {
        metadata
            .fun_attributes
            .get(entry_func.function().as_str())
            .map(|attrs| {
                attrs
                    .iter()
                    .filter_map(KnownAttribute::try_as_randomness_annotation)
                    .next()
            })
            .unwrap_or(None)
    })
}

fn check_metadata_format(module: &CompiledModule) -> Result<(), MalformedError> {
    let mut exist = false;
    let mut compilation_key_exist = false;
    for data in module.metadata.iter() {
        if data.key == *APTOS_METADATA_KEY || data.key == *APTOS_METADATA_KEY_V1 {
            if exist {
                return Err(MalformedError::DuplicateKey);
            }
            exist = true;

            if data.key == *APTOS_METADATA_KEY {
                bcs::from_bytes::<RuntimeModuleMetadata>(&data.value)
                    .map_err(|e| MalformedError::DeserializedError(data.key.clone(), e))?;
            } else if data.key == *APTOS_METADATA_KEY_V1 {
                bcs::from_bytes::<RuntimeModuleMetadataV1>(&data.value)
                    .map_err(|e| MalformedError::DeserializedError(data.key.clone(), e))?;
            }
        } else if data.key == *COMPILATION_METADATA_KEY {
            if compilation_key_exist {
                return Err(MalformedError::DuplicateKey);
            }
            compilation_key_exist = true;
            bcs::from_bytes::<CompilationMetadata>(&data.value)
                .map_err(|e| MalformedError::DeserializedError(data.key.clone(), e))?;
        } else {
            return Err(MalformedError::UnknownKey(data.key.clone()));
        }
    }

    Ok(())
}

pub fn verify_module_metadata_for_module_publishing(
    module: &CompiledModule,
    features: &Features,
) -> Result<(), MetaDataValidationError> {
    if features.is_enabled(FeatureFlag::SAFER_METADATA) {
        check_module_complexity(module)?;
    }

    if features.are_resource_groups_enabled() {
        check_metadata_format(module)?;
    }
    let metadata = if let Some(metadata) = get_metadata_from_compiled_code(module) {
        metadata
    } else {
        return Ok(());
    };

    let functions = module
        .function_defs
        .iter()
        .map(|func_def| {
            let func_handle = module.function_handle_at(func_def.function);
            let name = module.identifier_at(func_handle.name);
            (name, (func_handle, func_def))
        })
        .collect::<BTreeMap<_, _>>();

    for (fun, attrs) in &metadata.fun_attributes {
        for attr in attrs {
            if attr.is_view_function() {
                is_valid_view_function(module, &functions, fun)?;
            } else if attr.is_randomness() {
                is_valid_unbiasable_function(&functions, fun)?;
            } else {
                return Err(AttributeValidationError {
                    key: fun.clone(),
                    attribute: attr.kind,
                }
                .into());
            }
        }
    }

fn build_package_and_insert_attribute(
    source: &str,
    struct_attr: Option<(&str, FakeKnownAttribute)>,
    func_attr: Option<(&str, FakeKnownAttribute)>,
) -> (Vec<Vec<u8>>, Vec<u8>) {
    let mut builder = PackageBuilder::new("Package");
    builder.add_source("m.move", source);
    let path = builder.write_to_temp().unwrap();

    let package = BuiltPackage::build(path.path().to_path_buf(), BuildOptions::default())
        .expect("building package must succeed");
    let code = package.extract_code();
    // There should only be one module
    assert!(code.len() == 1);
    let mut compiled_module = CompiledModule::deserialize(&code[0]).unwrap();
    let mut value = RuntimeModuleMetadataV1 {
        error_map: BTreeMap::new(),
        struct_attributes: BTreeMap::new(),
        fun_attributes: BTreeMap::new(),
    };

    if let Some((name, attr)) = struct_attr {
        let fake_attribute = bcs::to_bytes(&attr).unwrap();
        let known_attribute = bcs::from_bytes(&fake_attribute).unwrap();
        value
            .struct_attributes
            .insert(name.to_string(), vec![known_attribute]);
    };
    if let Some((name, attr)) = func_attr {
        let fake_attribute = bcs::to_bytes(&attr).unwrap();
        let known_attribute = bcs::from_bytes(&fake_attribute).unwrap();
        value
            .fun_attributes
            .insert(name.to_string(), vec![known_attribute]);
    }

    let metadata = Metadata {
        key: APTOS_METADATA_KEY_V1.to_vec(),
        value: bcs::to_bytes(&value).unwrap(),
    };

    compiled_module.metadata = vec![metadata];
    let mut code = vec![];
    compiled_module.serialize(&mut code).unwrap();
    let metadata = package
        .extract_metadata()
        .expect("extracting package metadata must succeed");
    (vec![code], bcs::to_bytes(&metadata).unwrap())
}
