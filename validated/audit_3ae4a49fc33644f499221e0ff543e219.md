### Title
Spot-Price Uniswap V3 Quote Used for Auto-Swap Slippage Protection Enables Sandwich Extraction of Depositor Funds - (File: x/uexecutor/keeper/evm.go)

### Summary
The `BaseDynamicFee.poke()` bug class is about a value (LP fee) that is (re)computed from live, attacker-influenceable external state at an arbitrary, attacker-chosen moment, then immediately used to price a trade in the same transaction — enabling manipulate-then-trade extraction. Push Chain's `GAS`/`GAS_AND_PAYLOAD` inbound execution path reproduces this exact pattern: `GetSwapQuote` reads the **current spot price** from a Uniswap V3 `QuoterV2.quoteExactInputSingle` call [1](#0-0) , and the resulting quote is used, with only a flat 5% slippage buffer, as the `minPCOut` floor for the actual on-chain swap executed moments later in the very same keeper call [2](#0-1) . No TWAP or other manipulation-resistant price source is used anywhere in the codebase.

### Finding Description
When an inbound of type `GAS` or `GAS_AND_PAYLOAD` finalizes (a bonded UV's `MsgVoteInbound` crosses the ballot threshold), the keeper executes `ExecuteInboundGas` synchronously inside that same transaction's `deliverTx` [3](#0-2) . This function:
1. Fetches the quoter address, WPC address, and default fee tier — all static config reads.
2. Calls `GetSwapQuote`, which performs a live, non-committed `quoteExactInputSingle` call against the Uniswap V3 `QuoterV2` contract deployed on Push Chain's own EVM, returning the amount of PC the pool would currently give for the deposited PRC20 amount [1](#0-0) .
3. Computes `minPCOut = quote * 95 / 100` and immediately calls `CallPRC20DepositAutoSwap`, which performs the actual swap against the same pool with that `minPCOut` floor [4](#0-3) .

Because the quote and the swap read the pool's instantaneous reserves rather than a time-weighted average, an unprivileged attacker who can trade against the same underlying Uniswap V3 pool on Push Chain's EVM can push the spot price down immediately before the `MsgVoteInbound`-triggered swap lands in a block, causing the deposited PRC20 to be swapped for far less PC than fair value while still satisfying the artificially-lowered `minPCOut`. The attacker then reverses the price move afterward, capturing the difference — a classic sandwich attack. This is functionally identical to the `poke()` risk described in the external report: a permissionless mechanism ("trade against the pool") lets an attacker manipulate the state that a subsequent, immediately-following fee/price computation depends on, and that computation is then trusted to gate a real value transfer.

The identical pattern also appears in the `GAS_AND_PAYLOAD` deposit-swap helper [5](#0-4)  and in the excess-gas refund swap path [6](#0-5) , both of which call `GetSwapQuote` and immediately execute a swap with the same 95%-of-spot-quote floor.

### Impact Explanation
This directly causes unauthorized loss of user/protocol-controlled funds: depositors bridging gas tokens (or receiving gas refunds) into Push Chain can have their PRC20→PC auto-swap executed at a manipulated price, permanently losing up to the full 5% slippage tolerance (or more, since the "floor" itself is derived from the manipulated price, not a fair one) to an unprivileged attacker who only needs to trade on a public AMM pool — no validator, TSS, or admin collusion required. This falls squarely in the "corruption of PRC20 or native asset accounting" and "unauthorized... refund" impact categories.

### Likelihood Explanation
Likelihood is high for any Uniswap V3 pool with realistically thin liquidity relative to deposit sizes, since: (1) the attacker needs no special privileges — only the ability to submit ordinary EVM swap transactions against the pool on Push Chain; (2) the vulnerable swap fires deterministically and synchronously whenever a `MsgVoteInbound` (or outbound-refund vote) finalizes, which is publicly observable in the mempool/ballot state before it lands; (3) the 5% slippage tolerance is a fixed, generous buffer that provides essentially no protection against a spot-price-based sandwich, since the "reference" quote itself is taken from the same manipulable pool at the same near-instant.

### Recommendation
Do not use the instantaneous `quoteExactInputSingle` spot quote as the reference price for slippage protection. Instead, derive `minPCOut` from a manipulation-resistant reference such as a time-weighted average price (Uniswap V3 TWAP via `observe()`), an external validator-attested price (e.g., extend `ChainMeta`/gas-price-style multi-signer median voting to a PC/PRC20 exchange rate), or a governance/admin-configured hard floor with periodic updates. If a live quote must be used, widen slippage protection cannot be the sole defense — enforce a maximum allowed deviation from a longer-window TWAP, and/or cap single-block price impact for these module-driven swaps.

### Proof of Concept
1. Attacker identifies a Push Chain Uniswap V3 pool (PRC20 token X / WPC) used by `UniversalCore.uniswapV3Quoter` for a token with modest liquidity.
2. Attacker observes (via mempool or UV ballot state) that an inbound `GAS` deposit of token X, of size `A`, is about to finalize via `MsgVoteInbound`.
3. Immediately before that transaction is included, attacker submits a large swap on the same pool that sells WPC for token X, depressing the X→WPC spot price.
4. The finalizing `MsgVoteInbound` transaction executes `ExecuteInboundGas`, which calls `GetSwapQuote` at the now-depressed price and computes `minPCOut = quote * 95/100` — a floor far below the pool's normal fair price.
5. `CallPRC20DepositAutoSwap` executes the deposit-triggered swap at the depressed price, satisfying the depressed `minPCOut`; the depositor's UEA receives far less PC than fair value.
6. Attacker reverses their initial swap (sell token X back for WPC), restoring the price and capturing the spread as profit, extracted directly from the depositor's swapped value.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
