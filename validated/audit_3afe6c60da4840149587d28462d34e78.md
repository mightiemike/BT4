### Title
Webhook HMAC validation does not bind the `X-Shopify-Shop-Domain` header, enabling cross-tenant offline session/access-token disclosure - ([File: packages/apps/shopify-app-remix/src/server/authenticate/webhooks/authenticate.ts])

### Summary
The webhook `authenticate()` function trusts `check.domain` — a value parsed purely from the unauthenticated `X-Shopify-Shop-Domain` header — to load and return another shop's offline session via `ensureValidOfflineSession(params, check.domain)`. The HMAC that gates `check.valid` is computed only over `rawBody` and the app's `apiSecretKey`; the domain header is never part of the signed data, so a genuine HMAC-signed webhook payload can be replayed with a forged domain header to obtain a different (victim) tenant's session/admin client.

### Finding Description
In `authenticate()`, `check.valid` comes from `api.webhooks.validate({rawBody, rawRequest: request})` [1](#0-0) , which internally calls `validateHmacFromRequestFactory` and, if the HMAC succeeds, separately parses headers (including `domain`) via `checkWebhooksHeaders`/`checkEventsHeaders` with no cross-check against the HMAC-signed content [2](#0-1) [3](#0-2) .

The HMAC computation itself confirms the domain is not covered: `validateHmacFromRequest` reads only the `X-Shopify-Hmac-*` header and calls `validateHmacString(config, rawBody, hmac, HashFormat.Base64)`, which hashes `rawBody` with `config.apiSecretKey` — no header data, including domain, is included in the signed material [4](#0-3) [5](#0-4) .

Once `check.valid` is true, `authenticate()` unconditionally passes `check.domain` into `ensureValidOfflineSession`, which loads whatever session is stored for that shop name and returns a live (refreshed) admin session/access token bound to it [6](#0-5) [7](#0-6) . That session is then attached to the returned `webhookContext.admin`/`session`, giving the caller of the webhook handler an authenticated admin client for whatever shop name was in the header [8](#0-7) .

Because `apiSecretKey` is a single app-wide secret shared across all shops that install the app (not a per-shop secret), any party who legitimately receives one authentic webhook delivery for their own shop (e.g., an ordinary merchant who installs the app) possesses a rawBody+HMAC pair that is valid regardless of which `Domain` header accompanies it. They can POST that exact `rawBody` with the original HMAC header directly to the app's webhook endpoint while substituting `X-Shopify-Shop-Domain` for a victim shop that also has the app installed. `check.valid` remains true (HMAC only checks rawBody), `check.domain` becomes the victim's shop, and `ensureValidOfflineSession` hands back the victim's offline session/access token to the attacker-controlled request path.

### Impact Explanation
This is a cross-tenant session/access-token disclosure: an unprivileged actor (a merchant who has installed the app on their own store — not the app developer, no leaked secret) can obtain another merchant's offline access token/session object inside the webhook handler context, and the resulting `admin` client can be used to act against the victim shop's Admin API. This matches Shopify's bounty impact class for cross-tenant/cross-merchant data or session access via authentication bypass.

### Likelihood Explanation
Preconditions are low: the attacker only needs (1) their own legitimate installation of the target app (any merchant can do this, no special privilege), which yields at least one authentic `rawBody`+HMAC pair delivered by Shopify, and (2) knowledge of the victim shop's domain (publicly guessable/known `*.myshopify.com` names). No secret material, MITM, or host-app misconfiguration is required — the gap is structural: HMAC coverage excludes headers entirely. This is reproducible for any deployment using `authenticateWebhookFactory` as shipped.

### Recommendation
Bind the authenticated shop domain to the HMAC-verified data, e.g. by requiring correlation between `check.domain` and a shop-scoped secret (webhook secrets are shop/topic scoped in modern Shopify webhook delivery via `eventId`/registered webhook records), or by validating that `check.webhookId`/`eventId` was actually registered for `check.domain` in the app's webhook registry before calling `ensureValidOfflineSession`. At minimum, cross-check that the resolved session's shop matches an app-managed record confirming that domain is the one that genuinely triggered the event.

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/utils/__tests__/hmac-domain-not-signed.test.ts
import {validateHmacFromRequestFactory} from '../hmac-validator';
import {HmacValidationType} from '../types';
import {createSHA256HMAC} from '../../../runtime/crypto';
import {HashFormat} from '../../../runtime/crypto/types';

test('HMAC validity is independent of the Domain header', async () => {
  const config = { apiSecretKey: 'shared-app-secret' } as any;
  const rawBody = JSON.stringify({id: 1, note: 'attacker shop order'});
  const hmac = await createSHA256HMAC(config.apiSecretKey, rawBody, HashFormat.Base64);

  const validate = validateHmacFromRequestFactory(config);

  const attackerRequest = {
    type: HmacValidationType.Webhook,
    rawBody,
    headers: {
      'X-Shopify-Hmac-Sha256': hmac,
      'X-Shopify-Shop-Domain': 'victim-shop.myshopify.com', // forged
      'X-Shopify-Topic': 'orders/create',
      'X-Shopify-Webhook-Id': 'attacker-controlled-id',
    },
  } as any;

  const result = await validate(attackerRequest);
  expect(result.valid).toBe(true); // HMAC passes even though domain was swapped
});
```

Followed by, in `authenticate()`, `check.domain === 'victim-shop.myshopify.com'` reaches `ensureValidOfflineSession(params, 'victim-shop.myshopify.com')`, returning the victim's stored session if `victim-shop.myshopify.com` has installed the app, as shown by `ensure-valid-offline-session.ts` looking up strictly by the `shop` string parameter with no additional authentication tie-back to the HMAC. function checkWebhooksHeaders(
  headers: Headers,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };

  const name = getHeader(headers, headerNames.name);
  if (name) fields.name = name;

  const triggeredAt = getHeader(headers, headerNames.triggeredAt);
  if (triggeredAt) fields.triggeredAt = triggeredAt;

  const eventId = getHeader(headers, headerNames.eventId);
  if (eventId) fields.eventId = eventId;

  return {valid: true, ...fields};
}

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };
}

import {AppDistribution, BasicParams} from '../types';

export async function createOrLoadOfflineSession(
  {api, config, logger}: BasicParams,
  shop: string,
) {
  if (config.distribution === AppDistribution.ShopifyAdmin) {
    logger.debug('Creating custom app session from configured access token', {
      shop,
    });
    return api.session.customAppSession(shop);
  } else {
    logger.debug('Loading offline session from session storage', {shop});
    const offlineSessionId = api.session.getOfflineId(shop);
    const session = await config.sessionStorage!.loadSession(offlineSessionId);

    return session;
  }
}
