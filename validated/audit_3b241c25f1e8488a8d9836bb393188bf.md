### Title
Stale global class cache skips re-declaration/reorg check for Cairo 0 classes, allowing execution against an undeclared class - (File: crates/blockifier/src/state/state_reader_and_contract_manager.rs)

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` re-validates a cache hit against the live state reader only for Cairo 1 classes (`is_declared`). For Cairo 0 (`RunnableCompiledClass::V0`) it returns the globally cached compiled class unconditionally, with no check that the class is still declared in the state being validated/executed against.

### Finding Description
The `contract_class_manager` cache (`ContractClassManager` / `GlobalContractCache`) is a process-global cache shared across the gateway's stateful validator instances, the batcher's block execution, and view calls — it lives far longer than a single block and is not scoped to the "latest" state used per transaction. [1](#0-0) 

When a class hash is looked up, the code explicitly acknowledges that a cache hit "does not guarantee" the class is currently declared — "it might contain a declared class from a reverted block, for example" — and re-verifies via `self.state_reader.is_declared(class_hash)` for any non-`V0` (Cairo 1) result: [2](#0-1) 

However, for `RunnableCompiledClass::V0(_)` (Cairo 0 classes) the `match` arm is empty — no re-verification against the current state is performed at all: [3](#0-2) 

The `FetchCompiledClasses::is_declared` trait method itself is documented to "always return `false`" for Cairo 0 classes, confirming there is no declared-status oracle available/consulted for V0 at all: [4](#0-3) 

This is precisely the pattern in the reported Carapace bug class: an authorization/eligibility check (`is_declared`/pool-active-status) is derived from a value that is cached/batched rather than freshly read from the current state, and the code path that omits the refresh (the Cairo 0 branch here, analogous to `assessStateBatch` not being invoked) allows an action (executing/validating a transaction that deploys, replaces class, or invokes against a class hash) to proceed as if the class were still declared, even though the authoritative state may have diverged (e.g., after a reorg that reverted the declaring block, or in the `StateReaderAndContractManager` used by the gateway's stateful validator, which is instantiated fresh per-`add_tx` but shares this long-lived global cache across all such instantiations and across the batcher/view-call paths).

The existing unit tests explicitly enumerate the reorg-staleness scenario for Cairo 1 (`cached_but_verification_failed_after_reorg_scenario`, expecting `Err(StateError::UndeclaredClassHash(..))`), but there is no analogous test or code path guarding Cairo 0 classes: [5](#0-4) [6](#0-5) 

### Impact Explanation
If a Cairo 0 class is declared, cached in the process-global `contract_class_manager`, and then the declaring block is reverted/reorged (or the class is otherwise no longer valid in the state the validator/executor is now reading), any subsequent transaction referencing that `class_hash` (e.g., `DeployAccount`, `Deploy`, or `ReplaceClass` to that hash) will retrieve the stale cached compiled class and be allowed to execute/validate against it, even though the current authoritative state no longer contains that declaration. This can let the gateway admit a transaction to the mempool that should have been rejected as referencing an undeclared class, or let the batcher execute it during block building — producing state transitions / commitments based on a class that is not actually declared in the canonical state, i.e., wrong execution results and potentially a wrong committed state root relative to what an honest re-execution (Starknet OS) using accurate declared-class state would produce.

### Likelihood Explanation
Reachable purely from normal transaction submission: an attacker (or even benign user) sends a Cairo 0 `Declare`, then triggers/observes a reorg (or any scenario where the class becomes undeclared in the state used for a later request while the process cache is not evicted), then submits a transaction referencing that class hash. Because the cache is process-global and long-lived (shared with the batcher and view-call paths per `crates/apollo_batcher/src/batcher.rs:2068-2076`), the window during which the stale entry remains valid is not bounded to a single block, increasing the likelihood the check is bypassed.

### Recommendation
Apply the same `is_declared`-style re-verification for `RunnableCompiledClass::V0` cache hits in `get_compiled_from_class_manager` as is already done for Cairo 1 classes, rather than leaving the Cairo 0 branch as a no-op. If `is_declared` cannot distinguish Cairo 0 status by design, extend `FetchCompiledClasses` with a declared-status check that covers Cairo 0 classes too, and invoke it unconditionally on every cache hit before trusting the cached compiled class.

### Proof of Concept
1. Declare a Cairo 0 class via `Declare` transaction; it gets compiled and inserted into the process-global `contract_class_manager` cache with variant `CompiledClasses::V0`.
2. Cause the declaring block to be reverted (reorg) or otherwise arrange for `state_reader` (the fresh per-request state, e.g., from `SyncStateReaderFactory::get_blockifier_state_reader_and_gateway_fixed_block_from_latest_block`) to no longer consider the class hash declared.
3. Submit a new transaction referencing the same `class_hash` (e.g., a `DeployAccount` or `Invoke` requiring `get_compiled_class`).
4. `get_compiled_from_class_manager` hits the cache, matches `RunnableCompiledClass::V0(_)`, takes the empty branch, and returns the cached class without calling `is_declared` — unlike the Cairo 1 path in `cached_but_verification_failed_after_reorg_scenario`, which would correctly return `Err(StateError::UndeclaredClassHash(..))`.

impl<S: FetchCompiledClasses> StateReaderAndContractManager<S> {
    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }
