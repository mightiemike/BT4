### Title
Uncapped `memorySave` in `callToPrecompiledAddress` causes memory writes beyond the CALL-declared return size, diverging from priced/declared memory bounds - (File: `actuator/src/main/java/org/tron/core/vm/program/Program.java`)

### Summary
The external report describes a Solidity pattern where `.call{gas, value}(...)` unconditionally copies the *entire* return data into memory regardless of how much the caller actually needs, causing memory-expansion gas to be spent (or griefed) beyond what the caller expects/prices for. The java-tron TVM analog exists in the handling of calls to precompiled contracts, specifically in `Program.callToPrecompiledAddress`, where the amount of memory actually written after the call can diverge from the size that was priced for and declared by the `CALL`/`STATICCALL`/`DELEGATECALL` opcode's `outDataSize` operand.

### Finding Description
When a contract executes `CALL`/`STATICCALL`/`DELEGATECALL` against a precompiled-contract address, the energy (gas) cost for the operation — including the memory-expansion component for the caller-declared output region — is computed up front from the stack operands `outOffset`/`outSize` via `EnergyCost.getCalculateCallCost` → `calcMemEnergy`, which uses `memNeeded` on the declared out-offset/out-size operands: [1](#0-0) 

Execution then proceeds through `exeCall`, which expands memory to the declared `outDataOffs`/`outDataSize` before dispatching the call, and routes precompiled-contract calls to `Program.callToPrecompiledAddress`: [2](#0-1) 

Inside `callToPrecompiledAddress`, after the precompiled contract executes and returns `out.getRight()` (the actual return payload, whose length is controlled by the precompiled contract's implementation, not by the caller's declared `outDataSize`), the result is written to memory. The write is only bounded by the caller-declared `outDataSize` when the `allowTvmSelfdestructRestriction` hard-fork flag is active; otherwise it falls back to an unbounded write of the entire returned buffer: [3](#0-2) 

Compare this to the equivalent path for calls to ordinary (non-precompiled) contracts, `callToAddress`, which always caps the write to the declared `outDataSize` via `memorySaveLimited`, regardless of any hard-fork flag: [4](#0-3) 

This asymmetry means that, under the legacy code path (`!allowTvmSelfdestructRestriction()`), the memory actually mutated by a call to a precompiled contract can exceed the region the caller declared (and that energy was charged for), exactly mirroring the report's root cause: the actual bytes copied from an external call's return data are not bounded to what the caller intended/priced, but instead determined by the callee's returned payload size.

### Impact Explanation
If the legacy branch is exercised (i.e., on any node/snapshot where `allowTvmSelfdestructRestriction` is not active — e.g., historical replay, non-mainnet networks, or prior to that feature's activation), a precompiled contract returning more data than the caller declared in `outDataSize` will overwrite memory outside the caller-declared/energy-priced output window. This can silently corrupt adjacent EVM memory contents that the calling contract's compiled logic assumes are untouched, leading to state/logic divergence in the calling contract without any corresponding additional energy charge for the extra memory written — an unpriced side effect analogous to the "external calls may use more gas than gasLimit" class from the report, except here it manifests as unpriced/unbounded memory mutation rather than just gas overuse. In a deterministic replicated VM like TVM, any code path whose behavior (memory contents) can diverge from what the energy-accounting model assumes is a correctness/consensus-relevant concern.

### Likelihood Explanation
This code path is only reachable through calls (`CALL`/`STATICCALL`/`DELEGATECALL`/`CALLCODE`) targeting a precompiled contract address, which is fully controllable by any unprivileged contract deployer/caller — no privileged role is required. The actual severity depends on (a) whether `allowTvmSelfdestructRestriction` is currently activated on the target network (I could not confirm current mainnet activation status from the indexed code; this is a chain-governance-controlled flag in `DynamicPropertiesStore`/`ProposalUtil`), and (b) whether any specific precompiled contract can be made to return a payload larger than a caller-declared `outDataSize`. I was not able to fully enumerate the precompiled-contract implementations to confirm which of them can return variable/larger-than-declared payload sizes, so likelihood is uncertain and should be verified with a full audit of `PrecompiledContracts.java` and the `allowTvmSelfdestructRestriction` activation status.

### Recommendation
Make the write of a precompiled contract's return data unconditionally bounded to the caller-declared `outDataSize`/`outDataOffs`, matching the behavior of `callToAddress`'s `memorySaveLimited` call, regardless of the `allowTvmSelfdestructRestriction` flag state: [3](#0-2) 
This removes the legacy unbounded-copy branch so the memory actually mutated by any call always matches the region that was expanded and energy-priced for it.

### Proof of Concept
1. Deploy a contract that issues `CALL`/`STATICCALL` to a precompiled-contract address (e.g., one of the TRON-specific precompiles in `PrecompiledContracts.java`) with a small declared `outDataSize` (e.g., 1 word) while the precompile's actual implementation returns a larger payload.
2. Run this on a node/snapshot where `allowTvmSelfdestructRestriction()` evaluates to `false` (verify via `VMConfig`/`DynamicPropertiesStore` activation state).
3. Observe, via `Program.callToPrecompiledAddress` line 1760 (`this.memorySave(msg.getOutDataOffs().intValue(), out.getRight());`), that memory beyond the declared `outDataOffs + outDataSize` window is overwritten with the excess return bytes, while the energy charged for the call (computed in `EnergyCost.getCalculateCallCost`) was based only on the declared, smaller `outDataSize`.
4. Confirm the mismatch between the memory actually expanded/charged for (per `calcMemEnergy`) and the memory actually written (unbounded `out.getRight()` length) demonstrates the priced-vs-actual divergence.

Note: I was unable to conclusively determine, from the indexed code alone, (a) the current activation state of `allowTvmSelfdestructRestriction` on production networks, and (b) which specific precompiled contracts can return a payload exceeding a caller's declared `outDataSize`. These should be verified directly against the deployed `DynamicPropertiesStore` state and the full `PrecompiledContracts.java` implementation before treating this as exploitable in the current mainnet configuration.

```java
  public static long getCalculateCallCost(Stack stack, Program program,
                                          long energyCost, int opOff) {
    int op = program.getCurrentOpIntValue();
    long oldMemSize = program.getMemSize();
    DataWord callEnergyWord = stack.get(stack.size() - 1);
    // in offset+size
    BigInteger in = memNeeded(stack.get(stack.size() - opOff),
        stack.get(stack.size() - opOff - 1));
    // out offset+size
    BigInteger out = memNeeded(stack.get(stack.size() - opOff - 2),
        stack.get(stack.size() - opOff - 3));
    energyCost += calcMemEnergy(oldMemSize, in.max(out),
        0, op);
```

```java
  public static void exeCall(Program program, DataWord adjustedCallEnergy,
      DataWord codeAddress, DataWord value, DataWord tokenId, boolean isTokenTransferMsg) {

    DataWord inDataOffs = program.stackPop();
    DataWord inDataSize = program.stackPop();

    DataWord outDataOffs = program.stackPop();
    DataWord outDataSize = program.stackPop();

    program.memoryExpand(outDataOffs, outDataSize);
    int op = program.getCurrentOpIntValue();
    MessageCall msg = new MessageCall(
        op, adjustedCallEnergy, codeAddress, value, inDataOffs, inDataSize,
        outDataOffs, outDataSize, tokenId, isTokenTransferMsg);

    PrecompiledContracts.PrecompiledContract contract =
        PrecompiledContracts.getContractForAddress(codeAddress);
    if (contract != null) {
      if (program.isConstantCall()) {
        contract =  PrecompiledContracts.getOptimizedContractForConstant(contract);
      }
      program.callToPrecompiledAddress(msg, contract);
    } else {
      program.callToAddress(msg);
    }
    program.step();
  }
```
