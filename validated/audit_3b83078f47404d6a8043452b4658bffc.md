## Title
Missing "class must be declared" check in Starknet OS `execute_replace_class` allows unauthorized state/root divergence from Blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The `ReplaceClass` syscall handler enforces access/validity checks inconsistently between the two execution engines that must agree bit-for-bit: the Rust `blockifier` (used for actual block building/execution) and the Cairo Starknet OS (used for re-execution and proof generation / state-root commitment). The OS implementation is missing the check that the target `class_hash` was actually declared before allowing a contract to replace its own class, which is precisely the "propose an action without verifying the caller/target is authorized/valid" bug class described in the external report (functions performing sensitive state changes without the guard that should gate them).

### Finding Description
In the Rust execution engine, `replace_class` explicitly verifies the class is declared before mutating state: [1](#0-0) 
```
fn replace_class(...) {
    // Ensure the class is declared (by reading it).
    syscall_handler.state.get_compiled_class(request.class_hash)?;
    syscall_handler.state.set_class_hash_at(...)?;
    ...
}
```
This is confirmed by the negative-flow unit test asserting `"is not declared"` is raised for undeclared class hashes: [2](#0-1) 

However, the equivalent Cairo implementation used by the Starknet OS to re-execute the block (for proof generation and to independently derive the committed state diff / block hash) does **not** perform this check — it is explicitly marked as a `TODO`: [3](#0-2) 
```
func execute_replace_class{...}(contract_address: felt) {
    ...
    let class_hash = request.class_hash;
    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}
    tempvar new_state_entry = new StateEntry(class_hash=class_hash, ...);
    dict_update{dict_ptr=contract_state_changes}(...);
    ...
}
```
The deprecated (Cairo 0) syscall path in the OS has the same omission: [4](#0-3) 

### Impact Explanation
The Starknet OS is the component whose Cairo execution trace is proved and whose outputs (state diff, state root, block hash) become the network's canonical committed state — this is exactly the "Starknet OS re-execution" attack surface explicitly listed as in-scope. If the OS accepts a `replace_class` state transition without validating that the class hash was declared (unlike the blockifier, which is the reference/consensus execution used to build the block), the OS's independently-computed state diff can diverge from what the blockifier actually produced/validated, or the OS can be made to accept and commit a class-hash assignment for a class that was never declared in state. Because class declaration is the access-control gate protecting `replace_class` (only a declared, vetted class may become a contract's class), skipping it in the OS is directly analogous to the reported bug class: a sensitive state-mutating operation lacking the authorization/validity check that should restrict it. The consequence is a wrong committed state root / block hash or honest-node divergence between the blockifier's execution result and the OS's re-derivation of that same block, undermining state-transition integrity guaranteed by the proof.

### Likelihood Explanation
Reachability requires only a normal contract invoking the `replace_class` syscall (`replace_class_syscall`) with an arbitrary `class_hash`, exactly as demonstrated by the existing test contracts (`test_replace_class`) that any external, unprivileged transaction can trigger by calling into a contract that performs this syscall: [5](#0-4) 
No privileged role, operator key, or malicious-proposer collusion is needed to invoke the syscall itself — the vulnerability is that the OS re-execution path (which independently processes the syscall using hint-supplied `class_hash` values) omits the same guard the blockifier enforces. This is a genuine code-level omission (marked with an explicit TODO by the maintainers) rather than a speculative concern, though I was not able to fully trace whether an upstream global "all classes referenced in the block's state diff must be declared" check elsewhere in `os.cairo` / `state.cairo` might independently catch this before final output commitment — the grep for `contract_class_changes`/`get_compiled_class` in `os.cairo`, `state.cairo`, and `combine_blocks.cairo` shows related class-management logic there, but I did not confirm within available context whether any of it constitutes an equivalent global "declared-class" enforcement that would make this specific TODO practically unreachable. This uncertainty should be verified by a deeper review of `os.cairo`'s state-diff finalization and `state.cairo`'s class-hash update mechanics.

### Recommendation
Add the missing declared-class verification in the Starknet OS's `execute_replace_class` (in `syscall_impls.cairo`) and in the deprecated syscall path (`deprecated_execute_syscalls.cairo`), mirroring the blockifier's `get_compiled_class` check, before performing the `dict_update` that mutates `contract_state_changes`. This should be validated by a dedicated Cairo test analogous to the existing Rust `test_replace_class` negative-flow test, and by cross-checking that OS output diverges/fails identically to blockifier rejection for an undeclared class hash.

### Proof of Concept
Conceptual PoC (cannot be executed without the full OS test harness):
1. Deploy a contract implementing `test_replace_class(class_hash)` calling `replace_class_syscall(class_hash)`, as already present in `cairo_steps_test_contract.cairo`.
2. Submit an ordinary `INVOKE` transaction (no special privilege) calling `test_replace_class` with a `class_hash` that was never declared.
3. In the blockifier (actual block execution), this reverts with `"... is not declared"` per `deprecated_syscalls_test.rs::test_replace_class` negative flow.
4. Independently, feed the same transaction/hints into the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo`); because the `TODO` check is absent, the OS accepts the state mutation without verifying declaration, producing a `contract_state_changes` entry and resulting state diff/root that the blockifier would never have produced for this transaction — a concrete instance of unauthorized/invalid state mutation slipping through the re-execution/proving layer that is supposed to attest to the sequencer's Blockifier execution.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
