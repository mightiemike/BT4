### Title
Starknet OS `execute_replace_class` accepts an undeclared class hash, diverging from Blockifier's declared-class check on `replace_class` — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
Analogous to the reported bug — a component trusted an externally supplied value (`asset()`) without verifying it against the canonical source of truth — the Starknet OS Cairo implementation of the `replace_class` syscall accepts an attacker-supplied `class_hash` from a contract's syscall request and writes it directly into `contract_state_changes` **without ever checking that a contract class is actually declared under that hash**, while the Rust Blockifier execution path performs exactly this check.

### Finding Description
The OS's `execute_replace_class` in `execution/syscall_impls.cairo` reads `class_hash` straight from the syscall request and stores it into the contract's `StateEntry`, with an explicit acknowledgment that the required validation is missing: [1](#0-0) 

The same missing check exists in the deprecated syscall path's OS implementation: [2](#0-1) 

By contrast, the Rust Blockifier — the engine that actually executes transactions to build blocks — explicitly validates that the class is declared before allowing the replacement, by attempting to read the compiled class (which fails with an `UndeclaredClassHash`/"is not declared" error if it doesn't exist): [3](#0-2) 

This is confirmed by Blockifier's own tests, which assert that calling `replace_class` with an undeclared class hash fails with "is not declared": [4](#0-3) [5](#0-4) 

The Starknet OS re-executes the same block's transactions in Cairo (via the `starknet_os` hint processor / `apollo_starknet_os_program`) to independently derive the resulting state and produce a STARK proof attesting to the correctness of the state transition. If the OS's syscall semantics do not match the Blockifier's semantics for the same syscall, the OS can compute a different execution outcome (success vs. revert, and a different final class hash for the contract) than what the Blockifier actually committed to the block.

### Impact Explanation
This is a root-cause honest-node/OS divergence for a state-modifying syscall reachable by any unprivileged contract that calls `replace_class`. Under Blockifier's rules, calling `replace_class` with an undeclared class hash causes the syscall (and hence the enclosing execution) to fail, which is reflected in the block's REVERTED transaction and the resulting state diff/commitment. The Starknet OS Cairo program, lacking the same "must be declared" check (explicitly marked with a `TODO` in the code), would not raise the same failure at the same point, meaning it can compute a different state transition (and hence a different state root / block hash) for that same execution than the one Blockifier actually produced and committed on-chain. Because the OS's output is meant to be verified (proved) as the canonical state transition, any divergence here threatens the correctness of the committed root/block hash and the network's ability to validate/finalize blocks consistently — i.e., a wrong committed root or honest-node divergence between the execution engine and the proving/re-execution engine.

### Likelihood Explanation
The `replace_class` syscall is callable directly by any contract in an ordinary transaction — no special privileges, staking, or operator access is required; a normal account/contract simply issues the syscall with an arbitrary `class_hash` argument. The reachability is therefore very high (a single submitted transaction). What is uncertain, given the available tooling, is the exact operational path by which the OS ends up processing a transaction that the Blockifier itself would revert/reject for this reason (e.g., whether upstream validation elsewhere in the OS/Blockifier pipeline always forces consistency before the OS re-executes it). This should be verified with a full repository checkout/session, since the wiki/code index used here does not expose the complete surrounding block-building/re-execution pipeline to confirm whether any other layer effectively already guards against this divergence before the OS runs `execute_replace_class`.

### Recommendation
Implement the check flagged by the existing `TODO(Yoni, 1/1/2026)` comment: before writing the new `class_hash` into `contract_state_changes` in `execute_replace_class` (both in `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`), verify that the given `class_hash` corresponds to an actually declared contract class (mirroring the Blockifier's `get_compiled_class`/`is_declared` check), and fail/produce the equivalent OS-level failure behavior (matching Blockifier's revert semantics) if it does not. This restores consistency between the Blockifier execution engine and the Starknet OS re-execution/proving engine for this syscall.

### Proof of Concept
1. An account contract deployed on Starknet calls the `replace_class` syscall with an arbitrary/never-declared `class_hash` value (e.g., `felt!(1234)`), as demonstrated by Blockifier's own regression test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`.
2. Under the Rust Blockifier (actual sequencer execution), this syscall fails with `"is not declared"`, causing the invoking transaction to revert (per `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:801`).
3. When the same block/transaction is re-executed by the Starknet OS Cairo program (`execute_replace_class` in `syscall_impls.cairo:881-920`), no equivalent check exists — the OS unconditionally writes the new (undeclared) `class_hash` into `contract_state_changes` and proceeds, producing a different state outcome for the same transaction than the Blockifier committed.
4. This divergence between the two independently-computed results for the identical transaction constitutes a wrong committed root / honest-node divergence, as required by the acceptance criteria.

func execute_replace_class{contract_state_changes: DictAccess*, revert_log: RevertLogEntry*}(
    contract_address, syscall_ptr: ReplaceClass*

    alloc_locals;
    let class_hash = syscall_ptr.class_hash;

    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce

    );
