### Title
Unbounded payload size/shape in `HandleLegacyUserMessage` amplifies DoS across all DON members - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` unmarshals the attacker-controlled `body.Payload` into `webapicap.TriggerRequestPayload` with no size, depth, or field-count validation, and then fans the entire raw message out to *every* DON member via a loop calling `don.SendToNode`. The handler explicitly documents that rate-limiting/allowlisting on this path is not implemented (`// TODO: apply allowlist and rate-limiting here`), so a single unprivileged request's cost is multiplied by the number of DON members with no mitigating control in this code path.

### Finding Description
In `core/services/gateway/handlers/capabilities/handler.go`, `HandleLegacyUserMessage` (lines 341-421) does: [1](#0-0) 
`json.Unmarshal(body.Payload, &payload)` uses the standard `encoding/json` decoder, which by default silently accepts unknown/extra fields (no `DisallowUnknownFields`) and imposes no limits on nesting depth, map key count, or array length. The only content checks performed afterward are a non-zero `Timestamp` and a staleness window check, plus a method-name equality check. [2](#0-1) 

Critically, the code contains an explicit acknowledgment that no rate-limiting or allowlisting is applied on this ingress path: [3](#0-2) 

The original message is then converted via `common.ValidatedRequestFromMessage(msg)`, which does nothing but `json.Marshal(msg)` (no size cap) into JSON-RPC params, and this same request object is forwarded to **every** DON member in a loop: [4](#0-3) [5](#0-4) 

Thus a single unprivileged HTTP/JSON-RPC submission with a large `Topics` array or a deeply nested `Params` map is: (1) accepted without shape/size validation, (2) re-serialized once, and (3) transmitted N times (once per DON member) — multiplying the attacker's cost by the DON's member count. There is no `nodeRateLimiter` gate on this path (that rate limiter is only applied in `handleWebAPIOutgoingMessage`, the node→gateway direction, not the user→gateway direction), and no evidence in this handler of a payload size cap prior to marshal/fan-out.

### Impact Explanation
This is a fan-out amplification DoS: a single unprivileged caller can cause the Gateway to perform N outbound sends (N = DON member count) of an oversized/complex payload, multiplying bandwidth and downstream per-node JSON decode/processing cost across the entire DON from one request. This matches a bounty-relevant "Denial of Service" / resource-exhaustion impact class scoped to gateway-to-DON fan-out, though it does not itself provide auth bypass, fund loss, or code execution.

### Likelihood Explanation
Feasibility depends on what size/shape limits, if any, exist upstream of this handler (e.g., at the HTTP server layer or JSON-RPC transport) — I was not able to fully confirm within the available tool calls whether `core/services/gateway/network/httpserver.go` enforces a request body size cap before requests reach `HandleLegacyUserMessage`. If such an upstream cap exists and is reasonably small, the practical amplification is bounded by that cap × member count, which reduces but does not eliminate the risk (amplification by member count still stands). If no such cap exists, the risk is more severe and directly reachable by any unprivileged client that can reach the gateway's user-facing endpoint. The explicit `// TODO: apply allowlist and rate-limiting here` comment in the shipped code confirms the intended mitigation for this exact path is not yet implemented, which raises confidence that the underlying issue is real, but I could not fully verify the outer HTTP-layer body-size behavior in this session.

### Recommendation
- Enforce `json.Decoder.DisallowUnknownFields()` and a `io.LimitReader`/`http.MaxBytesReader`-style cap on `body.Payload` before unmarshalling into `webapicap.TriggerRequestPayload`.
- Add explicit bounds on `Topics` array length and `Params` map depth/size in the `TriggerRequestPayload` validation step (immediately after unmarshal, alongside the existing `Timestamp` check).
- Implement the rate-limiting/allowlisting called out by the `// TODO` comment in `HandleLegacyUserMessage`, reusing `h.nodeRateLimiter`-style limiting keyed by caller identity/IP before the fan-out loop.
- Consider capping total payload bytes sent per user request regardless of DON member count (e.g., reject before the `for _, member := range h.donConfig.Members` loop rather than after per-member send failures).

### Proof of Concept
Unit/fuzz test plan for `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `webapicap.TriggerRequestPayload` with `Topics` containing 100k+ entries or `Params` containing deeply nested maps (e.g., 10k levels or MB-scale JSON).
2. Call `HandleLegacyUserMessage` with a mock `don.DON` whose `SendToNode` is instrumented to record total bytes and call count across all `donConfig.Members`.
3. Assert that: (a) no error is returned for the oversized payload (showing no size limit is enforced), and (b) total bytes transmitted via `SendToNode` equals `payload_size × len(donConfig.Members)`, demonstrating unbounded, multiplied resource cost from a single unprivileged call.
4. Fuzz progressively larger `Topics`/`Params` sizes, measuring wall-clock time and memory in `json.Unmarshal` + `json.Marshal` (via `ValidatedRequestFromMessage`) to show near-linear or worse cost growth with no rejection threshold.

func (h *handler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	body := msg.Body
	var payload webapicap.TriggerRequestPayload
	codec := api.JsonRPCCodec{}
	err := json.Unmarshal(body.Payload, &payload)
	if err != nil {
		h.lggr.Errorw(ErrDecodingPayload, "err", err)
		return callback.SendResponse(handlers.UserCallbackPayload{
			RawResponse: codec.EncodeNewErrorResponse(
				msg.Body.MessageId,
				api.ToJSONRPCErrorCode(api.UserMessageParseError),
				ErrDecodingPayload+" "+err.Error(),
				nil,
			),
			ErrorCode: api.UserMessageParseError,
		})
	}

// ValidatedRequestFromMessage converts a legacy Gateway Message to a JSON-RPC request
func ValidatedRequestFromMessage(msg *api.Message) (*jsonrpc.Request[json.RawMessage], error) {
	if msg == nil {
		return nil, errors.New("nil message")
	}
	if msg.Body.MessageId == "" {
		return nil, errors.New("message ID is empty")
	}
	if msg.Body.Method == "" {
		return nil, errors.New("method is empty")
	}
	params, err := json.Marshal(msg)
	if err != nil {
		return nil, fmt.Errorf("failed to marshal message: %w", err)
	}
	rawParams := json.RawMessage(params)
	req := &jsonrpc.Request[json.RawMessage]{
		Version: "2.0",
		ID:      msg.Body.MessageId,
		Method:  msg.Body.Method,
		Params:  &rawParams,
	}
	return req, nil
}
