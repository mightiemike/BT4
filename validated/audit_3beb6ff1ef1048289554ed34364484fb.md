## Analysis

The Airbyte bug class is a **confused-deputy / mismatched-validation** pattern: the authorization decision is made using an attacker-controlled identifier, and a completely different code path performs the sensitive action without ever re-validating that identifier against the actual target. The closest analog in the sequencer is a validation-parity mismatch between the Rust `blockifier` execution engine (which builds and commits the block/state) and the Cairo `Starknet OS` program (which re-executes the same transactions to generate the STARK proof): one side enforces a required precondition on `replace_class`, the other doesn't.

`blockifier`'s syscall implementation for `replace_class` requires the target class hash to be **declared** and to be a **Cairo1** class before mutating storage: [1](#0-0) 

This is enforced identically for the deprecated syscall handler: [2](#0-1) 

and is covered by tests asserting the exact rejection behavior for undeclared/Cairo0 class hashes: [3](#0-2) [4](#0-3) 

However, the Starknet OS's Cairo re-implementation of the same syscall, `execute_replace_class` in `syscall_impls.cairo`, performs **no such check** — it explicitly flags this as an open TODO and unconditionally writes the caller-supplied `class_hash` into `contract_state_changes`: [5](#0-4) 

The deprecated (Cairo0) OS syscall path has the identical gap: [6](#0-5) 

### Title
Missing declared-class/Cairo1 validation in Starknet OS `execute_replace_class` causes state-root divergence from blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Rust `blockifier` (which builds blocks and computes the committed state diff) rejects `replace_class` syscalls that target an undeclared class hash or a Cairo0 (deprecated) class hash. The Cairo `Starknet OS` program (which re-executes the same transactions during proving) has no equivalent check — it is explicitly marked with an unresolved `TODO` — and unconditionally commits the caller-supplied class hash to `contract_state_changes`.

### Finding Description
A contract's `__execute__`/inner call flow can invoke `replace_class_syscall(class_hash)` with an arbitrary, attacker-chosen `class_hash` value taken directly from calldata, exactly as in the `test_contract.cairo` feature contract's `test_replace_class` entry point [7](#0-6) .

In `blockifier`, `SyscallHandlerBase::replace_class` reads the compiled class for the given hash and rejects the call unless the class exists and `is_cairo1(&compiled_class)` holds [1](#0-0) . If a caller contract catches this syscall error (rather than unwrapping/panicking on it), the enclosing transaction does not revert as a whole — the class replacement simply does not happen, and the block-builder's committed state diff never reflects it.

In the Starknet OS, `execute_replace_class` performs the corresponding state mutation purely from the hint-provided `state_entry` and the caller-supplied `class_hash`, with a comment acknowledging the missing check ("`// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`") [8](#0-7) . There is no assertion tying the class hash to a declared/Cairo1 class before the `dict_update` into `contract_state_changes`, which directly feeds the Patricia-tree contract-state commitment computed in `commitment.cairo` [9](#0-8) .

This is the same bug shape as the Airbyte report: the code path that makes the "is this allowed" decision (blockifier's `is_cairo1`/declared-class check) is disjoint from the code path that performs the actual state mutation for proving (the OS's `execute_replace_class`), and nothing after the fact reconciles the two. Because the sequencer commits the block/state root using blockifier's result while the prover (OS) re-derives a state root using its own, weaker-checked execution, the two can diverge for the exact same transaction stream.

### Impact Explanation
If a caller contract wraps `replace_class_syscall` in a way that swallows the syscall failure (any Cairo1 contract using `SyscallResult` matching instead of `unwrap_syscall`), blockifier will not apply the class replacement, but the OS will silently apply it during re-execution/proving. This produces a different `contract_state_changes` entry, therefore a different contract-state Merkle root, therefore a different global state commitment and block hash than the one the sequencer actually committed on L2 — an honest-node/proof divergence and a wrong committed state root, which can halt proof generation/verification or produce an invalid proof for an already-committed block.

### Likelihood Explanation
Reachable by any unprivileged transaction sender via a single ordinary `INVOKE` transaction to any Cairo1 contract that calls `replace_class_syscall` and does not unconditionally unwrap/panic on failure — no special privileges, staking, or operator access needed. The only requirement is supplying a `class_hash` argument that is undeclared or belongs to a Cairo0 class, which is trivially satisfiable calldata.

### Recommendation
Add the same declared-class and Cairo1-version check to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` that `blockifier`'s `SyscallHandlerBase::replace_class` performs, resolving the existing `TODO(Yoni, 1/1/2026)` comment, so that OS re-execution and blockifier execution reject the same invalid `replace_class` calls identically.

### Proof of Concept
1. Declare a Cairo1 contract `A` whose entry point calls `replace_class_syscall(class_hash)` where `class_hash` comes from calldata, and catches the `SyscallResult` error instead of unwrapping it (pattern already present in `meta_tx_test_contract.cairo`'s error-catching style).
2. Send an `INVOKE` transaction calling that entry point with an undeclared (or Cairo0) `class_hash`.
3. In blockifier, `replace_class` returns `Err(StateError::UndeclaredClassHash)` / `ForbiddenClassReplacement`, which the contract catches; the transaction succeeds without any class-hash change, and the block's committed state diff has no entry for contract `A`'s class hash.
4. When the Starknet OS re-executes this same block/transaction for proving, `execute_replace_class` (`syscall_impls.cairo:881-920`) unconditionally performs `dict_update` on `contract_state_changes` with the same undeclared/Cairo0 `class_hash`, producing a differing contract-state leaf and therefore a differing computed state root/block hash from the one the sequencer already committed.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
