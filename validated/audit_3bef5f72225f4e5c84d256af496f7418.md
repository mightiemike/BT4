### Title
Starknet OS `execute_replace_class` skips class-declaration validation enforced by the Blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Rust `blockifier` requires that any class hash passed to the `replace_class` syscall corresponds to an already-declared (and Cairo1) class before it rewrites a contract's class pointer. The Starknet OS Cairo re-implementation of the same syscall, which is used to re-execute and commit the block during proving, has no such check and contains an explicit `TODO` acknowledging the missing validation.

### Finding Description
In the Blockifier, `replace_class` explicitly reads the compiled class to force declaration validation and rejects non-Cairo1 classes: [1](#0-0) 

The Starknet OS Cairo implementation of the identical syscall (`execute_replace_class`), which any deployed/declared contract can invoke via a plain `replace_class` syscall from a normal invoke transaction, updates `contract_state_changes` with an attacker-supplied `class_hash` without ever checking that the class was declared: [2](#0-1) 

The comment on line 902 makes the gap explicit: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The deprecated syscall path (`execute_replace_class` in `deprecated_execute_syscalls.cairo`) has the same unchecked pattern: [3](#0-2) 

By contrast, elsewhere in the OS, when a class is meant to be newly registered, the code explicitly enforces `prev_value=0` on the `contract_class_changes` dict to ensure a class can only be declared once (see the bootstrap-declare flow in `transaction_impls.cairo`), showing the codebase's expected pattern of validating class-hash state via the dictionaries it maintains — a pattern `execute_replace_class` does not follow for the target class hash.

This mirrors the "Lack of Validation Pool" bug class from the referenced TransitFinance report: a caller-supplied identifier (there, a "pool" address; here, a `class_hash`) is trusted and used to redirect execution/state without validating it against the set of legitimate/registered values.

### Impact Explanation
Because the Blockifier (which actually executes transactions and produces the state diff that gets committed to Starknet) enforces the declared-class check while the OS (which re-executes the same transactions inside the STARK proof to attest to the same state transition) does not, a transaction that attempts `replace_class` with an undeclared class hash is rejected/reverted by the Blockifier but would be silently accepted by the OS's Cairo re-execution if it were ever reached with such an argument (e.g., via a code path, virtual/other execution flavor, or future refactor that skips the Rust-side gate before OS replay). This creates a divergence between the two execution engines that are supposed to produce and prove the identical state transition: the committed root proven by the OS could end up including a contract pointing at a never-declared, non-existent class hash — an invalid/wrong committed state root relative to what any honest node executing via the Blockifier would produce, and a contract permanently bricked to an unusable class hash if such a state entry is ever committed and proven.

### Likelihood Explanation
The syscall is reachable by any contract that calls `replace_class` — this is a core Starknet syscall available to any account or contract from within a normal invoke transaction. Today, the Rust-side gate in `blockifier/src/execution/syscalls/syscall_base.rs` prevents the missing check from being exploited in the currently deployed execution path, since it is Blockifier execution that determines what is admitted into a block. However, the OS is the layer used for proof generation and is expected to be a faithful, independent re-execution of the same semantics as the Blockifier; the explicit `TODO` marks this as a known, unresolved gap in that re-implementation rather than an intentional relaxation, making it a genuine correctness/consistency risk in the OS re-execution and proving pipeline rather than a purely theoretical one.

### Recommendation
Add an explicit declared-class check in `execute_replace_class` (both the Sierra/new-syscalls path in `syscall_impls.cairo` and the deprecated path in `deprecated_execute_syscalls.cairo`) that mirrors the Blockifier's `get_compiled_class`/Cairo1-only check — e.g., read the `contract_class_changes` dict (or equivalent compiled-class-hash mapping) for `class_hash` and assert it is non-zero (declared) before writing the new `StateEntry`, exactly as the Blockifier does before allowing state mutation. Track and resolve the `TODO(Yoni, 1/1/2026)` before relying on the OS as an independent verifier of Blockifier-produced state diffs.

### Proof of Concept
I could not construct or verify an end-to-end exploit trace because the current gate in `blockifier/src/execution/syscalls/syscall_base.rs` (Rust) blocks invalid `replace_class` calls before OS re-execution is reached in the current pipeline as I explored it; I was not able to trace a live production code path (versus test-only/virtual OS harnesses) where the OS's `execute_replace_class` is invoked directly on attacker-controlled input without first passing through this Blockifier check. This should be verified by a maintainer with fuller visibility into how/when the OS Cairo replay is invoked relative to Blockifier validation (e.g., in the `starknet_os_flow_tests` or proving harness), and whether any path allows the OS to process a `replace_class` syscall for a class hash that was never validated as declared by the Blockifier beforehand.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

}
