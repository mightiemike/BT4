### Title
Gas for WASM contract loading/compilation not charged on failure during `FunctionCall` execution - ([File: runtime/near-vm-runner/src/wasmtime_runner/mod.rs])

### Summary
On stable protocol (2.13.0, `fix_contract_loading_cost = false`), the gas fee that prices WASM contract loading/compilation is charged **after** the expensive compile/link/instantiate work completes, and only on the success path. When compilation or loading fails, the loading fee is skipped entirely, letting an attacker force the validator to perform expensive WASM compilation for free via ordinary `FunctionCall` transactions — the same bug class as the Arbitrum report ("gas for WASM program activation not charged early enough").

### Finding Description
`WasmtimeVM::with_compiled_and_loaded` resolves a contract through a two-level cache; on a cache miss it calls `compile_and_cache`, deserializes the module, resolves the memory export, builds a `Linker`, and calls `instantiate_pre` — all of this is the computationally expensive part, analogous to Brotli decompression in the Arbitrum report [1](#0-0) . Only *after* this expensive work is done does the code call `gas_counter.before_loading_executable`, which pre-charges the loading fee **only if** `config.fix_contract_loading_cost` is set [2](#0-1) .

For the compile/load failure branches — `CompileModuleError`, `Module::deserialize` failure, missing memory export, or `linker.instantiate_pre` failure — the code returns a cached `Err`/error variant that is turned into `PreparationResult::OutcomeAbort` without ever calling `after_loading_executable` (the post-charge path) [3](#0-2) . `after_loading_executable` — the only place that charges `add_contract_loading_fee` on stable protocol — is invoked exclusively in the `Ok(res)` (successful load) branch:

```
match pre_result {
    Ok(res) => {
        let result = gas_counter.after_loading_executable(&config, wasm_bytes);
        ...
        closure(gas_counter, res)
    }
    Err(e) => {
        let result = PreparationResult::OutcomeAbort(FunctionCallError::CompilationError(e));
        return Ok(PreparedContract { config, gas_counter, result });
    }
}
``` [3](#0-2) 

`before_loading_executable`/`after_loading_executable`/`add_contract_loading_fee` in `gas_counter.rs` confirm the fee is gated behind `fix_contract_loading_cost`, which per the component spec is **nightly-only (PV 129) and not active on mainnet (PV 86, 2.13.0)** [4](#0-3) . The spec explicitly documents this: "on stable it stays `false`, so the fee is charged post-load and loading-phase resolve errors return NOP outcomes" [5](#0-4) .

Compiled failures are cached (`CompiledContract::CompileModuleError`) so the *same* contract can't be recompiled for free repeatedly [6](#0-5) , but an attacker only needs to control the WASM content to produce a fresh `code_hash` per attempt (e.g. via distinct padding/dead code, or deep/pathological module structures that pass `prepare_v3`'s cheap static validation but are slow or fail during wasmtime's actual native compilation/instantiation). Each such contract is deployed via a normal `DeployContract` action, whose fee is a fixed linear-in-size estimate covering the *typical* (successful) compile cost — not tied to whether the subsequent on-demand compile at `FunctionCall` time succeeds. When a `FunctionCall` targets that contract and the cache misses (cold node, evicted entry, cross-shard target, or a deploy where the fire-and-forget warm compile in `action_deploy_contract`/`precompile_contract_with_warming` didn't populate the same cache before the call), the compile happens synchronously inside the metered `FunctionCall` execution, but on failure the corresponding `contract_loading_base`/`contract_loading_bytes` fee is never burnt.

### Impact Explanation
This is a gas-metering bypass reachable by any unprivileged transaction signer via ordinary `DeployContract` + `FunctionCall` actions — no privileged role needed. Because the loading/compilation fee (the only fee sized to the actual expensive VM work of loading/compiling a WASM module) is skipped whenever that work fails, an attacker can craft WASM modules that pass cheap static preparation checks but are expensive/fail during wasmtime compilation or module resolution, and drive full compilation cost onto every validator for a fraction of the true gas price. Since this can be repeated with many distinct contracts (deploy cost only covers an assumed successful-compile estimate, not per-attempt actual VM cost), it enables a denial-of-service amplification against chunk producers/validators — an economically underpriced, transaction-triggered CPU sink, matching the "fee bypass" / "transaction-triggered" impact criteria.

### Likelihood Explanation
Likelihood is high given that: the vulnerable code path (`fix_contract_loading_cost = false`) is the **active mainnet behavior** (per `protocol-model/spec/contract-vm.md`, PV 86/2.13.0), the failure branches are reachable through completely normal actions (`DeployContract`, `FunctionCall`) available to any signer, and producing a WASM module that compiles slowly/fails in wasmtime while passing the cheaper `prepare_v3` static checks is a realistic engineering task (similar to known WASM-bomb/adversarial-compile patterns already tracked by the project's own estimator, e.g. `AdversarialCompileMaxBlocks`) [7](#0-6) .

### Recommendation
- Short term: charge the contract-loading fee (`add_contract_loading_fee`) unconditionally *before* attempting compilation/deserialization/instantiation, and treat the fee-charging as mandatory (not gated behind `fix_contract_loading_cost`) so failures still burn gas — i.e., backport the `FixContractLoadingCost` behavior (pre-charge in `before_loading_executable`, commit as `abort` rather than NOP) to stable protocol rather than leaving it nightly-only.
- Long term: audit all other on-demand, cache-miss-triggered expensive operations (module deserialization, linking, instantiation, and any future compilation backends) to ensure gas/compute is charged proportionally to work performed regardless of outcome, consistent with the "charge before execution" principle documented in `docs/architecture/gas/README.md`.

### Proof of Concept
1. Craft a WASM module `M` that satisfies all `prepare_v3` static validation limits (function/local/table counts, memory pages, sizes) — so it deploys successfully and passes cheap preparation — but is engineered to fail wasmtime's actual compilation or `instantiate_pre` (e.g., a pathological control-flow/type structure that wasmtime rejects post-validation, or a memory/table export mismatch causing `LinkError`).
2. Submit `DeployContract(M)` from an unprivileged account; deployment succeeds (fee is the fixed per-byte deploy fee, independent of eventual compile outcome) — see `runtime/runtime/src/actions.rs:290-327` and `runtime/runtime/src/cache_warming.rs:65-78` (errors from the warming precompile are silently dropped).
3. Ensure a cold on-demand compile path is hit at `FunctionCall` time (e.g., call from a node/shard where the in-memory/on-disk cache wasn't warmed, or after cache eviction).
4. Submit `FunctionCall` targeting `M`; the runtime performs the full compile/deserialize/link/instantiate_pre attempt (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:704-780`), it fails, and the outcome is built via `OutcomeAbort(FunctionCallError::CompilationError(e))` without `after_loading_executable` ever being invoked (`mod.rs:819-833`) — so `contract_loading_base`/`contract_loading_bytes` gas is never burnt for that expensive attempt, while only the cheap base action/receipt fees are charged.
5. Repeat with many distinct `M` variants (different code_hash each time) to keep forcing fresh, unpriced expensive compile attempts across the network.

    /// VM independent setup before loading the executable.
    ///
    /// Does VM independent checks that happen after the host state has been set
    /// up but before loading the executable. This includes pre-charging gas
    /// costs for loading the executable, which depends on the size of the WASM code.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn before_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        method_name: &str,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if method_name.is_empty() {
            let error = super::errors::FunctionCallError::MethodResolveError(
                super::errors::MethodResolveError::MethodEmptyName,
            );
            return Err(error);
        }
        if config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                let error =
                    super::errors::FunctionCallError::HostError(super::HostError::GasExceeded);
                return Err(error);
            }
        }
        Ok(())
    }

    /// Legacy code to preserve old gas charging behaviour in old protocol versions.
    #[cfg(feature = "wasmtime_vm")]
    pub(crate) fn after_loading_executable(
        &mut self,
        config: &near_parameters::vm::Config,
        wasm_code_bytes: u64,
    ) -> std::result::Result<(), super::errors::FunctionCallError> {
        if !config.fix_contract_loading_cost {
            if self.add_contract_loading_fee(wasm_code_bytes).is_err() {
                return Err(super::errors::FunctionCallError::HostError(
                    super::HostError::GasExceeded,
                ));
            }
        }
        Ok(())
    }
