### Title
Starknet OS `execute_replace_class` omits declared-class check enforced by Blockifier, causing committed state root/block hash divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Blockifier's `replace_class` syscall handler enforces that the target class hash is declared (and Cairo1) before allowing a contract to change its own class hash: `syscall_base.rs` calls `self.state.get_compiled_class(class_hash)?` and rejects non-Cairo1 classes before calling `set_class_hash_at` [1](#0-0) , and the deprecated syscall path does the same via `syscall_handler.state.get_compiled_class(request.class_hash)?` [2](#0-1) . This behavior is directly tested and enforced (`"is not declared"` errors) [3](#0-2) . However, the Starknet OS's Cairo re-implementation of the same syscall, `execute_replace_class` in `syscall_impls.cairo`, has an explicit unresolved TODO and performs no such check before updating the contract's `StateEntry.class_hash` in `contract_state_changes` [4](#0-3) .

### Finding Description
`execute_replace_class` reads the requested `class_hash` from the syscall request, and unconditionally writes it into the contract's `StateEntry` and into `contract_state_changes`, with only a comment noting the missing check:
```
let class_hash = request.class_hash;

// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
local state_entry: StateEntry*;
%{ GetContractAddressStateEntry %}
...
dict_update{dict_ptr=contract_state_changes}(...)
``` [5](#0-4) 

This is the OS-side re-execution path used to reprove/re-validate a block's transactions (Starknet OS re-execution). The corresponding Blockifier code path — the actual sequencer execution engine that decides whether a transaction succeeds/reverts and what state diff is produced — requires the class to be declared (`get_compiled_class`) before permitting the class-hash swap, otherwise the syscall fails with `StateError::UndeclaredClassHash` and the transaction execution reverts at that point [6](#0-5) . Any account contract can trigger a `replace_class` call inside `__execute__` (e.g. via a `test_replace_class`-style entry point) with an attacker-chosen, undeclared class hash [7](#0-6) .

Because the OS omits the equivalent check, if the OS's syscall trace/hints for a transaction ever diverge from Blockifier's rejection behavior (e.g. through crafted hint values, a bug in hint generation, or a discrepancy in what is considered "declared" between the two implementations), the OS will happily commit a state entry with an undeclared/arbitrary class hash where Blockifier would have reverted the syscall and produced a different (or no) state change. The OS's `contract_state_changes` dict feeds directly into the state commitment (Patricia tree updates) and the block's computed `output`/state diff that is checked against the real state transition. A discrepancy here is a root-cause candidate for wrong committed state root / block hash or honest-node divergence between the sequencer's actual (Blockifier) execution and the OS's re-execution/proving path.

### Impact Explanation
This falls in the class of "wrong committed root or block hash / honest-node divergence" that the prompt explicitly lists as an in-scope, high-severity outcome. The OS is responsible for validating and committing the final state diff that is checked against/consumed by the rest of the pipeline (Patricia tree state commitment, block hash and commitments). A missing declared-class check on `replace_class` in the OS means the OS's model of valid execution is strictly weaker than Blockifier's, so any scenario where the OS accepts a class-hash write that Blockifier would reject (or vice versa, in edge conditions around what states/hints are provided) directly produces a state root/commitment inconsistent with the actual execution, which is the exact bug class described in the report (a missing authorization/validation check on a specific code path that exists on the parallel/equivalent path elsewhere, permitting an unauthorized state write).

### Likelihood Explanation
`replace_class` is a syscall reachable by any deployed account/contract during normal `__execute__` execution — no special privilege is required, matching the "unprivileged transaction sender" reachability requirement. The trigger condition (an undeclared or otherwise invalid class hash reaching the OS's `execute_replace_class` without the check that exists in Blockifier) depends on the hint-generation/replay machinery staying perfectly in sync with Blockifier's declared-class enforcement; the TODO comment indicates the developers are aware this specific validation is currently missing in the OS Cairo code, which raises the likelihood that edge cases (reverted syscalls, hint mismatches, or malformed but "declared-looking" state entries) are not caught here today.

### Recommendation
Add an explicit "class is declared" check in `execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo` (and its deprecated counterpart in `deprecated_execute_syscalls.cairo`) that mirrors the Blockifier's `replace_class` logic (`get_compiled_class`/`is_declared` check, and Cairo1-only restriction) before performing the `dict_update` that mutates `contract_state_changes`, so that the OS's acceptance criteria for a class-hash replacement can never be looser than Blockifier's.

### Proof of Concept
Not independently reproducible from static analysis alone: the divergence requires driving the OS's hint/State-reading path (`%{ GetContractAddressStateEntry %}`) with a class hash that is undeclared relative to Blockifier's view of state while making the OS still process the syscall as successful, which depends on the hint-generation code (not fully covered in the indexed portions of the repo). The static evidence is the parity comparison between:
- Blockifier enforcement: `crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378` and `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:795-807`.
- Missing OS enforcement: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo:881-920` (explicit TODO at line 902).

Due to index size limits, the hint-generation Python/Rust code that supplies `GetContractAddressStateEntry` values to the OS was not fully available for review; confirming the exact end-to-end exploitability (whether hints can actually be crafted to produce a divergent, provable state transition) would require a full-repository review, best done in a Devin session with complete file access.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
