### Title
Missing "class must be declared" check in Starknet OS `execute_replace_class` diverges from Blockifier's enforcement, permitting an OS-accepted state transition to an undeclared class hash - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handler in the Starknet OS Cairo program (`execute_replace_class`) writes an attacker/contract-supplied `class_hash` directly into `contract_state_changes` without ever checking that a contract class is declared for that hash — the check is explicitly marked as a `TODO`. In contrast, every Rust-side (Blockifier) execution path for the same syscall — both the deprecated (Cairo0) and current syscall handlers, for VM and Native execution — explicitly requires `get_compiled_class`/`is_declared` to succeed before mutating state, and reverts the transaction with an `"is not declared"` error otherwise. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
The `replace_class` syscall is reachable by any contract (and therefore by any user transaction that triggers execution of a contract that calls it) to change the class hash bound to its own storage address. Blockifier's implementation of this syscall on every code path — the Cairo0/deprecated syscall executor, the current VM syscall executor, and the Native (Cairo-Native) executor — reads the target class via `state.get_compiled_class(request.class_hash)` (or the equivalent Native path through `self.base.replace_class`) before applying the state change, and fails the call with an `UndeclaredClassHash`/`"is not declared"` error if the class hasn't been declared: [2](#0-1) [4](#0-3) [5](#0-4) 

This is verified by dedicated regression tests asserting the negative flow explicitly fails with `"is not declared"`: [3](#0-2) [6](#0-5) 

However, the Starknet OS's own Cairo implementation of the same syscall (`execute_replace_class`, used for OS re-execution / proving of a block) has no equivalent check — the comment explicitly flags this as an outstanding TODO — and unconditionally writes the requested `class_hash` into `contract_state_changes`: [7](#0-6) 

Separately, the standalone `starknet_os` re-execution crate's `SnosSyscallExecutor::replace_class` is a complete no-op that unconditionally returns success without touching state or validating the class at all: [8](#0-7) 

The result is that the component responsible for independently re-executing/proving Starknet blocks (the OS) enforces a strictly weaker precondition for `replace_class` than the Blockifier component that actually builds blocks. Since these two paths are supposed to compute identical state transitions and the identical resulting state root/commitment for the same block, any place where their acceptance criteria diverge is a root-cause candidate for the OS accepting (or silently no-op'ing) a state transition that the sequencer's block-building Blockifier would reject/revert, or vice versa.

### Impact Explanation
If the OS's laxer (or entirely absent, in the `starknet_os` crate path) validation ever accepts a `replace_class` state transition that Blockifier would revert, the OS-computed state commitment/root diverges from the one actually committed by block production. This falls squarely into "wrong committed root or block hash" / "honest-node divergence" — a proof generated by re-execution would not match the state actually persisted by the network, and the discrepancy would only surface when the proof is checked against the committed block, threatening the network's ability to produce or accept valid proofs for the affected block. This is a Medium-severity centralization/soundness analog to the original report: the original bug lets an authorization check on a state-changing operation ("depository"/whitelist" removal) silently succeed/fail inconsistently across code paths, permanently corrupting the ability to interact correctly with previously-valid state; here, the analog is an authorization check (declared-class enforcement) on `replace_class` that is inconsistently enforced between the two components that are required to agree on the exact same state transition.

### Likelihood Explanation
In the currently intended block-production flow, Blockifier's check runs first and would revert any transaction attempting to replace a class with an undeclared hash, so the class would already be declared by the time the OS re-executes the same accepted block, making the missing OS check benign under the *current* single-path flow. However, this is fragile: it depends entirely on the two independently-maintained implementations (Blockifier syscalls vs. OS Cairo hints vs. the separate `starknet_os` crate) staying in lockstep as they evolve, and the code itself flags this gap as a known, currently-open TODO rather than an intentional invariant. Any future change to either path (e.g., a fee-computation reordering, alternate re-execution entry point, or a change to which validations happen before vs. after `replace_class`) could expose the divergence directly, and the `starknet_os` crate's no-op implementation is already fully divergent today for its own re-execution flow.

### Recommendation
Add the missing declared-class check in `execute_replace_class` in `syscall_impls.cairo` to mirror Blockifier's `get_compiled_class`/`is_declared` check exactly (including the "cannot replace V1 class hash with V0 class hash" restriction enforced in the Rust syscall handler), and replace the no-op `replace_class` implementation in `starknet_os/src/hint_processor/snos_syscall_executor.rs` with logic that performs the equivalent validation and state update, ensuring the OS and Blockifier can never diverge on this syscall's acceptance criteria.

### Proof of Concept
1. A contract's `__execute__` (or any externally-callable entry point) calls the `replace_class` syscall with an arbitrary, attacker-controlled `class_hash` value (e.g., taken from calldata), as demonstrated in the test contract's `test_replace_class` entry point exercised by the existing tests.
2. Under Blockifier (block building), if `class_hash` is undeclared, the call fails with `StateError::UndeclaredClassHash`/`"is not declared"` and the transaction reverts — confirmed by `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29` and `crates/blockifier/src/execution/deprecated_syscalls/deprecated_syscalls_test.rs:375-391`.
3. Under the Starknet OS's Cairo `execute_replace_class` (`syscall_impls.cairo:881-920`), the identical call would instead unconditionally write the undeclared `class_hash` into `contract_state_changes` since no declared-class check exists there (per the explicit TODO at line 902) — and under the standalone `starknet_os` crate's `SnosSyscallExecutor::replace_class` (`snos_syscall_executor.rs:319-326`), the call is a complete no-op that reports success regardless of any check.
4. This demonstrates that, absent the missing check being added, the OS and Blockifier are not provably equivalent for this syscall, meaning any future divergence in ordering/validation between the two components (or use of the `starknet_os` crate's re-execution path) can produce a state root that the block-building sequencer never actually committed.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}

    fn replace_class(&mut self, class_hash: Felt, remaining_gas: &mut u64) -> SyscallResult<()> {
        self.pre_execute_syscall(
            remaining_gas,
            self.gas_costs().syscalls.replace_class.base_syscall_cost(),
            SyscallSelector::ReplaceClass,
        )?;

        self.base
            .replace_class(ClassHash(class_hash))
            .map_err(|err| self.handle_error(remaining_gas, err))?;
