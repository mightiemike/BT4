## Analysis

Confirmed chain of code:

- Every new inbound/outbound observation ballot is created via `GetOrCreateBallot`, which calls `CreateBallot` when the ballot key doesn't yet exist [1](#0-0) .
- `CreateBallot` unconditionally runs `k.ExpireBallotsBeforeHeight(ctx, blockHeight)` before creating and storing the new ballot, on every single invocation [2](#0-1) .
- `ExpireBallotsBeforeHeight` iterates the *entire* `ActiveBallotIDs` set and does a `k.Ballots.Get` per entry [3](#0-2) .
- `DefaultExpiryAfterBlocks` is set to 100,000,000 blocks (~19 years), explicitly to "effectively disable expiry" until a pruning mechanism exists [4](#0-3) .
- Ballot keys for inbound/outbound votes are derived from the observed event content (`GetInboundBallotKey`/`GetOutboundBallotKey`), so each distinct cross-chain transaction (or each distinct validator-observed variant) that a UV votes on produces a brand-new ballot ID via `VoteOnInboundBallot`/`VoteOnOutboundBallot` [5](#0-4) .

### Title
Unbounded `ActiveBallotIDs` growth causes O(n) work per ballot creation, quadratic-cost DoS in `x/uvalidator` ballot finalization path - (File: `x/uvalidator/keeper/ballot.go`)

### Summary
`CreateBallot` calls `ExpireBallotsBeforeHeight`, which scans every entry in `ActiveBallotIDs`, on every new ballot creation. Because `DefaultExpiryAfterBlocks` is set to ~100M blocks (effectively "never"), and a new ballot is created for every distinct inbound/outbound observation an ordinary user can trigger, this active-ballot set only grows and never shrinks via expiry. The per-ballot-creation scan therefore grows linearly with total historical non-finalized ballots, producing quadratic total cost as more cross-chain activity accumulates — the same nested/growing-loop-over-history bug class as the referenced `MergingPool::claimRewards`/`RankedBattle::claimNRN` report.

### Finding Description
An ordinary, unprivileged user can cause arbitrarily many *distinct* inbound events by submitting many low-value cross-chain transactions on a supported source chain (each with a unique `tx_hash`/`log_index`, hence a unique `GetInboundBallotKey`). Each such event, once voted on by universal validators via `VoteInbound` → `VoteOnInboundBallot` → `uvalidatorKeeper.VoteOnBallot` → `GetOrCreateBallot`, results in a new ballot being created if it doesn't already exist [6](#0-5) .

Every such `CreateBallot` call first executes `ExpireBallotsBeforeHeight(ctx, blockHeight)`, which iterates the whole `ActiveBallotIDs` keyset and does a `Ballots.Get` for each ID to check its expiry height [7](#0-6) . Since `DefaultExpiryAfterBlocks = 100_000_000` [4](#0-3) , ballots that don't reach quorum (or take a long time to reach it) remain "active" indefinitely — nothing removes them from `ActiveBallotIDs` except finalization or the effectively-disabled expiry.

This means:
1. `ActiveBallotIDs` is a monotonically-growing set bounded only by the number of distinct inbound/outbound observation events ever submitted through the system's normal user-facing flow.
2. Every subsequent ballot creation (triggered by ordinary cross-chain deposits) re-scans this entire growing set.
3. Total on-chain work across N ballot creations is O(N²), matching the exact bug class in the referenced report (loop cost growing with accumulated historical state, reachable via routine user action).

### Impact Explanation
This is a state-machine-level, non-network DoS reachable purely from ordinary user cross-chain deposit activity (an unprivileged actor can generate many distinct low-value inbound transactions on any supported external chain). As `ActiveBallotIDs` grows, the gas/time cost of `VoteInbound`/`VoteOutbound` transactions submitted by honest universal validators increases without bound, eventually threatening to exceed block gas limits or materially degrade UV vote-processing throughput, which can stall inbound/outbound finalization for all users — a state-machine divergence/DoS risk reachable "without privileged control" as required by the allowed-impact gate. It does not lead to fund loss directly, but threatens liveness of the finalization pipeline that all universal-execution flows depend on.

### Likelihood Explanation
High over time: any external user can cheaply generate many distinct inbound events (e.g., many small transfers with unique tx hashes) without needing quorum to ever be reached (or even if quorum is eventually reached, ballots that reach terminal state are removed, but any variant/ballot that stalls, is contested among validators, or is simply created faster than it finalizes keeps accumulating). The `DefaultExpiryAfterBlocks` comment explicitly acknowledges this is a known gap ("Ballots should not expire without an escape hatch... most likely enable once ballot pruning is implemented"), confirming the maintainers are aware pruning is missing but have not implemented a bounded mechanism.

### Recommendation
- Avoid a full active-set scan on every `CreateBallot` call; instead use a time/height-indexed structure (e.g., bucket ballots by expiry height) so expiration is O(1) amortized rather than O(active-count) per call.
- Alternatively, decouple ballot expiry sweeping from the hot path (`CreateBallot`) and move it to `BeginBlock`/`EndBlock` with a bounded per-block sweep budget.
- Re-enable a bounded, sane `DefaultExpiryAfterBlocks` and add a pruning/garbage-collection mechanism for stale non-finalized ballots so `ActiveBallotIDs` cannot grow unboundedly from ordinary user-triggered inbound/outbound observation traffic.

### Proof of Concept
Conceptual (not runnable without full test harness, but structurally verifiable from code):
1. Submit N distinct inbound events (`Inbound{SourceChain, TxHash: unique, LogIndex, ...}`) each below quorum threshold votes (or with validators observing different data so ballots never finalize), causing N `CreateBallot` calls to add N entries to `ActiveBallotIDs` that never expire (`DefaultExpiryAfterBlocks` ~19 years).
2. Submit one more distinct inbound event and measure gas/time of the resulting `VoteInbound` call — it will call `ExpireBallotsBeforeHeight`, which now iterates all N previously stored active ballots via `k.Ballots.Get` in a loop [8](#0-7) .
3. As N grows (driven purely by ordinary inbound submissions from unprivileged users), the cost of each subsequent `VoteInbound`/`VoteOutbound` transaction grows linearly, and cumulative cost grows quadratically — eventually risking block gas-limit issues for UV vote transactions.

Note: I could not fully verify from indexed content whether there is any other pruning path (e.g., a governance-triggered cleanup) elsewhere in the codebase that mitigates this; the `README.md` and test files reference `GetOrCreateBallot`/`ExpireBallotsBeforeHeight` extensively but I did not locate a bounded/paginated expiry sweep in the reachable code shown. If such a mechanism exists elsewhere, it would need to be reviewed to determine whether it fully closes this gap.

// GetOrCreateBallot returns the ballot if it exists, otherwise creates it.
func (k Keeper) GetOrCreateBallot(
	ctx context.Context,
	id string,
	ballotType types.BallotObservationType,
	voters []string,
	votesNeeded int64,
	expiryAfterBlocks int64,
) (types.Ballot, bool, error) {

	if ballot, err := k.Ballots.Get(ctx, id); err == nil {
		k.Logger().Debug("ballot found (existing)", "ballot_id", id)
		return ballot, false, nil
	}

	k.Logger().Debug("ballot not found, creating new", "ballot_id", id, "ballot_type", ballotType.String())
	newBallot, err := k.CreateBallot(ctx, id, ballotType, voters, votesNeeded, expiryAfterBlocks)

	return newBallot, true, err
}

// ExpireBallotsBeforeHeight checks active ballots and marks expired ones.
// It uses a two-phase approach: first collect IDs to expire, then mutate,
// to avoid modifying the ActiveBallotIDs collection during iteration.
func (k Keeper) ExpireBallotsBeforeHeight(ctx context.Context, currentHeight int64) error {
	iter, err := k.ActiveBallotIDs.Iterate(ctx, nil)
	if err != nil {
		return err
	}

	// Phase 1: collect IDs to expire
	var toExpire []string
	for ; iter.Valid(); iter.Next() {
		id, err := iter.Key()
		if err != nil {
			iter.Close()
			return err
		}

		ballot, err := k.Ballots.Get(ctx, id)
		if err != nil {
			iter.Close()
			return err
		}

		if ballot.BlockHeightExpiry <= currentHeight {
			toExpire = append(toExpire, id)
		}
	}

func (k Keeper) VoteOnInboundBallot(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	inbound types.Inbound,
) (isFinalized bool,
	isNew bool,
	err error) {
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return false, false, err
	}

	universalValidatorSet, err := k.uvalidatorKeeper.GetEligibleVoters(ctx)
	if err != nil {
		return false, false, err
	}

	// number of validators
	totalValidators := len(universalValidatorSet)

	// votesNeeded = ceil(2/3 * totalValidators)
	// >2/3 quorum similar to tendermint
	votesNeeded := (types.VotesThresholdNumerator*totalValidators)/types.VotesThresholdDenominator + 1

	k.Logger().Debug("voting on inbound ballot",
		"ballot_key", ballotKey,
		"validator", universalValidator.String(),
		"total_validators", totalValidators,
		"votes_needed", votesNeeded,
	)

	// Convert []sdk.ValAddress → []string
	universalValidatorSetStrs := make([]string, len(universalValidatorSet))
	for i, v := range universalValidatorSet {
		universalValidatorSetStrs[i] = v.IdentifyInfo.CoreValidatorAddress
	}

	// Step 2: Call VoteOnBallot for this inbound synthetic
	_, isFinalized, isNew, err = k.uvalidatorKeeper.VoteOnBallot(
		ctx,
		ballotKey,
		uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
		universalValidator.String(),
		uvalidatortypes.VoteResult_VOTE_RESULT_SUCCESS,
		universalValidatorSetStrs,
		int64(votesNeeded),
		int64(types.DefaultExpiryAfterBlocks),
	)
	if err != nil {
		return false, false, err
	}

	if isNew {
		k.Logger().Debug("inbound ballot created", "ballot_key", ballotKey)
	}
	if isFinalized {
		k.Logger().Info("inbound ballot finalized", "ballot_key", ballotKey, "source_chain", inbound.SourceChain)
	}

	return isFinalized, isNew, nil
}
