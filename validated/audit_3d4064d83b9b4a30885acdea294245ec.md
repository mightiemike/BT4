Found a concrete instance of the bug class: `depositPRC20` in `x/uexecutor/keeper/handler.go` looks up the token's `NativeRepresentation.ContractAddress` from `uregistryKeeper.GetTokenConfig` and mints PRC20 to the recipient **without checking `TokenConfig.Enabled`**. The analog to "checks one specific module/flag but not the complete gating state" holds here: only chain-level `IsInboundEnabled`/`IsChainOutboundEnabled` is checked (in `VoteInbound` / `msg_execute_payload.go`), but the token-level `Enabled` flag returned by `GetTokenConfig` is read into `tokenConfig` and then silently ignored before minting PRC20.

### Title
Token-level `Enabled` flag is never enforced before minting PRC20 on inbound deposit - ([File: x/uexecutor/keeper/handler.go])

### Summary
`depositPRC20` (and its callers in `execute_inbound_funds_and_payload.go`, `execute_inbound_gas.go`, `execute_inbound_gas_and_payload.go`) fetches `TokenConfig` via `uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)` and immediately uses `tokenConfig.NativeRepresentation.ContractAddress` to mint PRC20 to the recipient. The struct has an `Enabled bool` field (used elsewhere in tests to gate whitelisting), but `depositPRC20` never reads or checks it — it only checks `NativeRepresentation != nil`. This mirrors the Gnosis Safe `TransactionValidator` finding: one specific authorization/config gate is checked (the token exists / has a native representation) but a co-located, equally important gate (whether the token is currently `Enabled`) is not, allowing state that should be blocked from producing effects.

### Finding Description
`x/uregistry` models tokens with an explicit `Enabled` flag on `TokenConfig`, intended to whitelist/de-whitelist tokens (`MsgUpdateTokenConfig`, `MsgRemoveTokenConfig`). However, the inbound execution path that actually moves value — `depositPRC20` in `x/uexecutor/keeper/handler.go:12-46` — retrieves the full `TokenConfig` and only validates `NativeRepresentation != nil` before calling `k.CallPRC20Deposit`, which performs a real `DerivedEVMCall` minting PRC20 tokens to the recipient [1](#0-0) . If an admin has disabled a token (`Enabled=false`, e.g. after discovering a bridging bug, an oracle mismatch, or a security issue with a specific asset) but the `TokenConfig` entry still exists with `NativeRepresentation` set, `depositPRC20` will keep minting for that asset because the enabled flag itself is never consulted at the value-moving choke point. Vote-time chain gating (`IsChainInboundEnabled`) is enforced in `VoteInbound` [2](#0-1) , but that is a *chain*-level flag, not the *token*-level `Enabled` flag — so disabling a specific token does not actually stop inbound minting for that token through this path, exactly analogous to the report's "checks executor module but not other modules."

### Impact Explanation
If token disablement is the operational mechanism for pausing a compromised or mispriced asset (bridging pause without pausing the whole chain), an unprivileged user submitting inbound events for that disabled token can still have their PRC20 minted via `depositPRC20`, because the enforcement gap is in the honest-validator-approved production code path, not a privileged bypass. This corrupts PRC20 accounting invariants ("unauthorized mint" / "corruption of PRC20 accounting") for an asset the registry admin explicitly tried to shut off.

### Likelihood Explanation
Medium: exploitation requires (a) a token later transitioning to `Enabled=false` while its `TokenConfig`/`NativeRepresentation` record remains, and (b) an ordinary user submitting a genuine (or previously-queued) inbound for that asset. This is a normal operational sequence (temporarily disabling an asset without deleting its config), not a privileged-attacker scenario, so it is plausible in production if the `Enabled` flag is actually relied upon as a live circuit breaker.

### Recommendation
Enforce `TokenConfig.Enabled` at the same choke point where `NativeRepresentation` is validated — i.e., in `depositPRC20` (and any other keeper function that reads `TokenConfig` right before a value-moving `DerivedEVMCall`), return an error/failed-PCTx path when `!tokenConfig.Enabled`, mirroring the existing chain-level `IsInboundEnabled` check pattern in `VoteInbound`/`ExecutePayload`.

### Proof of Concept
Not directly exploitable by tool inspection alone (requires runtime state: a `TokenConfig` set with `Enabled=false` post-facto). Conceptually:
1. Admin whitelists token X (`Enabled=true`) and users start bridging it.
2. Admin sets `Enabled=false` via `MsgUpdateTokenConfig` after discovering an issue, expecting no further minting for X.
3. An inbound event for token X (submitted/observed by honest validators as usual) reaches quorum in `VoteInbound`; `ValidateForExecution` does not check token-enabled either [3](#0-2) .
4. Execution reaches `ExecuteInboundFundsAndPayload`/`ExecuteInboundGas`, which calls `depositPRC20`, which only checks `NativeRepresentation != nil` and mints PRC20 to the recipient regardless of `Enabled` [4](#0-3) .

**Uncertainty note:** I could not fully confirm from the indexed code whether `Enabled` is checked anywhere upstream (e.g., in a keeper-level `GetTokenConfig` wrapper) before reaching `depositPRC20`, since the full body of `x/uregistry/keeper/keeper.go`'s `GetTokenConfig` was not returned by the search tools. If `GetTokenConfig` itself already errors out for disabled tokens, this finding would be invalidated — this should be verified directly in a Devin session before treating this as confirmed.

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

// ValidateForExecution checks fields that are required for actual execution of the inbound.
// Called after ballot finalization, before ExecuteInbound. Failures here produce a failed
// PCTx and (for non-isCEA) a revert outbound, rather than dropping the vote.
func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}
