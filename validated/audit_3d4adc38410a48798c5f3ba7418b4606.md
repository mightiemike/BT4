### Title
Missing "class must be declared" validation in Starknet OS `replace_class` syscall handling can cause OS re-execution to diverge from Blockifier's committed state - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `RFPSimpleStrategy.setPoolActive()` report describes a privileged state-mutating function missing a required guard/validation before executing. The closest reachable analog in this sequencer codebase is the `replace_class` syscall handling: `blockifier` (the component that actually builds/validates blocks) enforces that the target `class_hash` must already be declared before allowing a contract to replace its own class hash, but the Starknet OS Cairo implementation of the same syscall — used for re-execution/proving — omits this check entirely, as flagged by its own `TODO` comment.

### Finding Description
In `blockifier`, the `replace_class` syscall handler explicitly guards the state mutation by first confirming the class is declared: [1](#0-0) 

This is confirmed by a dedicated negative test asserting that replacing to an undeclared class hash fails with `"is not declared"`: [2](#0-1) 

However, the Starknet OS's own Cairo implementation of the same syscall (`execute_replace_class`) performs the state-entry update unconditionally, and explicitly documents the missing check via a `TODO`: [3](#0-2) 

The same gap exists in the deprecated syscall path used for Cairo0 contracts: [4](#0-3) 

Because `blockifier` treats an inner-call failure (undeclared class) as a validation error that reverts the triggering transaction (no class-hash state change is committed for that call), while the OS's Cairo re-implementation performs the class hash swap unconditionally regardless of whether the class was ever declared, the two "sources of truth" for the state transition function (the sequencer's `blockifier` execution and the Starknet OS's independent re-execution used to produce/verify proofs) can disagree on the outcome of the exact same transaction.

### Impact Explanation
The Starknet OS is one of the explicitly in-scope reachable surfaces ("Starknet OS re-execution") because it independently recomputes the state transition instead of trusting the sequencer's precomputed diff. If the OS accepts a `replace_class` syscall targeting an undeclared class hash that `blockifier` would reject/revert, the OS-computed state diff for that contract's class hash can differ from the one actually committed by the sequencer via `blockifier`. This is a "wrong committed root / honest-node divergence" class issue: the block/proof pipeline could compute or validate a different final class-hash-to-contract mapping than what the sequencer's own execution engine produced, undermining state-root/proof integrity for the affected contract.

### Likelihood Explanation
Triggering the divergent code path requires only an ordinary, unprivileged transaction: any deployed contract can invoke the `replace_class` syscall on itself with an arbitrary, never-declared `class_hash` felt value — no special privilege, declaration, or L1 message is needed, matching the "unprivileged transaction sender" reachability bar. The severity is tempered by the fact that under a correctly-behaving `blockifier` this specific transaction would already be marked reverted before ever reaching a state where a divergent commit is possible; I could not fully verify (within the exploration performed) whether the OS's hint-driven re-execution independently re-derives revert status for such inner-call failures or simply follows a supplied execution trace, which affects whether the OS gap is actually exploitable end-to-end or is presently a hardening/defense-in-depth gap explicitly tracked by the author's own `TODO(Yoni, 1/1/2026)`.

### Recommendation
Add the same "class must be declared" check in the Starknet OS's `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` path) that already exists in `blockifier`'s Rust `replace_class` implementation, i.e., verify a compiled/declared class entry exists for `request.class_hash` before performing the `dict_update` on `contract_state_changes`, and fail/revert the syscall consistently with `blockifier`'s behavior when it does not.

### Proof of Concept
1. Deploy a contract `A` on the network without ever declaring any class `X`.
2. Submit a standard INVOKE transaction where `A` calls the `replace_class` syscall on itself with `class_hash = X` (an arbitrary, undeclared felt).
3. In `blockifier` (real sequencer execution), this call fails at `hint_processor.rs:801` (`get_compiled_class` returns `UndeclaredClassHash`), reverting the effect on `A`'s class hash for this call — matching the test in `deprecated_syscalls_test.rs:375-392`.
4. When the same transaction is re-executed by the Starknet OS (`execute_replace_class` in `syscall_impls.cairo:881-920` or `deprecated_execute_syscalls.cairo:307-329`), no equivalent declared-class check exists, so the state-entry update proceeds unconditionally, potentially producing a different final class hash for `A` in the OS's independently recomputed state diff than the one the sequencer actually committed.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
