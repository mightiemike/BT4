### Title
Live Uniswap V3 spot-price quote used for deposit auto-swap `minPCOut` enables sandwich-manipulation of protocol-executed swaps - (File: `x/uexecutor/keeper/evm.go`)

### Summary
The bug report describes how using a *market rate feed* (rather than a manipulation-resistant exchange/oracle rate) to price a protocol-executed conversion opens up sandwich-style arbitrage against the protocol. Push Chain has a direct structural analog: `GetSwapQuote` fetches a **live, single-block spot price** from `QuoterV2.quoteExactInputSingle` [1](#0-0)  and this same-block quote is used, with only a flat 5% slippage buffer, to authorize the module-executed `depositPRC20WithAutoSwap` call that mints/converts protocol-controlled value on the user's behalf [2](#0-1) .

### Finding Description
`ExecuteInboundGas` (GAS inbound route) and `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound route) both compute `minPCOut` the same way: fetch the current Uniswap V3 `QuoterV2` quote for the exact input amount, then apply a hard-coded 5% slippage tolerance: [3](#0-2) 

`GetSwapQuote` reads `quoteExactInputSingle` with `sqrtPriceLimitX96 = 0` (no price-limit protection) directly against the live pool state — this is a spot/market price, not a time-weighted or otherwise manipulation-resistant rate: [1](#0-0) 

The resulting `minPCOut` is passed straight into `CallPRC20DepositAutoSwap`, which the `uexecutor` module account executes as a real, committed EVM transaction (`depositPRC20WithAutoSwap`) that swaps the user's freshly-minted PRC20 into WPC using the on-chain `UniversalCore`/router: [4](#0-3) 

The same live-quote pattern with the same 5% band is reused for the gas-refund swap path (`applyGasRefund` → `getSwapQuoteForRefund` → `CallUniversalCoreRefundUnusedGas`): [5](#0-4) 

A search of the codebase confirms there is no TWAP, price-limit, or oracle-deviation check anywhere protecting these quote calls — `sqrtPriceLimitX96` is always hard-coded to `0` and no `observe()`/TWAP call exists in the repository.

Because the quote is read and consumed within the same keeper call (no reentrancy window inside a single Cosmos tx), the attack surface is not "flash-loan within one tx" — it is: an attacker temporarily skews the WPC/PRC20 pool price with an ordinary, permissionless EVM swap transaction timed to land in the same block, immediately before the validator vote message that triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` for their own pending inbound. Because Push Chain's mempool orders by priority fee like any Cosmos-EVM chain, an unprivileged attacker can pay to get their manipulation transaction included ahead of the finalizing vote transaction in the same block, without needing a malicious validator or proposer. With a 5% slippage tolerance (far wider than pools with normal, non-manipulated liquidity require), skewing the pool price by even a few percent lets the attacker force the module's swap to fill fewer/more tokens than fair value, and then reverse the skew afterward in the same or next block to extract the difference — a two-way, protocol-funded arbitrage structurally identical to the report's "deposit before, withdraw/settle after the price moves" pattern.

### Impact Explanation
This falls under "corruption of PRC20 or native asset accounting" and potential "unauthorized mint/unauthorized release of protocol-controlled funds" in the allowed impact gate: the module-executed swap moves real WPC/PC-native value between the attacker and the protocol's Uniswap pool based on an attacker-manipulable spot price, with only a fixed and generous 5% band as protection. Depending on pool depth, this can drain value from the pool (funded implicitly by the protocol's own deposit-swap flow and by other users' liquidity) on every GAS / GAS_AND_PAYLOAD inbound and on every gas-refund swap.

### Likelihood Explanation
Likelihood is moderate-to-high wherever the WPC/PRC20 pool has shallow liquidity relative to deposit size (typical for a new chain's bridged-asset pools). The attacker needs only: (1) an ordinary, unprivileged EVM transaction to skew the pool, (2) an inbound of their own (or targeting any user's pending inbound, since the swap benefits/harms the recipient's `minPCOut` execution, though the attacker profits via pool arbitrage regardless of the swap counterpart), and (3) normal priority-fee-based transaction ordering — no validator collusion, no protocol-key compromise, and no out-of-scope assumptions are required.

### Recommendation
Replace the live spot quote with a TWAP-based reference price (e.g., Uniswap V3 `observe()` over a meaningful window) or an off-chain/UV-voted aggregated rate for computing `minPCOut`, similar to how `ChainMeta`/`GasPrice` already use a median-of-votes design elsewhere in the same module. At minimum, tighten the slippage band adaptively based on pool depth/liquidity rather than a flat 5%, and consider bounding the maximum allowed single-block price deviation before allowing an auto-swap to proceed (falling back to a non-swap deposit path, which already exists via `CallPRC20Deposit`).

### Proof of Concept
1. Attacker identifies a pending inbound (their own or another user's) that will route through `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` once the 2/3 UV vote threshold is met.
2. Attacker submits a high-priority-fee EVM transaction that swaps a large amount through the same PRC20/WPC Uniswap V3 pool referenced by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`, shifting the pool's spot price by up to the discoverable slippage-tolerable band (~5%).
3. If this transaction lands in the same block, before the qualifying `MsgVoteInbound` transaction is processed, `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) returns the skewed price, and `minPCOut = quote * 95 / 100` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:374-376`) is computed off that skewed value.
4. `CallPRC20DepositAutoSwap` executes `depositPRC20WithAutoSwap` at the skewed price, transferring more/less WPC value than fair market price to/from the protocol's pool.
5. Attacker reverses their initial skewing swap in the same or the following block, realizing arbitrage profit funded by the protocol-executed swap, repeatable for every subsequent GAS/GAS_AND_PAYLOAD inbound or gas-refund event.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
