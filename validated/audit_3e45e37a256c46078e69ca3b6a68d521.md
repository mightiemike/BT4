### Title
Deprecated (Cairo 0) Class Hash Computation Uses Escape-Unaware Regex on Attacker-Controlled Strings, Risking Hash Divergence - (File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs)

### Summary
`compute_cairo_hinted_class_hash` (used by `compute_deprecated_class_hash`) builds the canonical byte representation of a legacy Cairo 0 contract class by serializing it to JSON with a Python-compatible formatter and then applying regex-based text rewrites (`add_backward_compatibility_space`) before hashing the result with Keccak256. The regexes used to "fix" formatting for backward compatibility operate on raw JSON text and are not aware of JSON string-escaping rules (`\"`, `\\`), which is directly analogous to the reported AWS CloudFront issue where policy documents built from unescaped/unvalidated special characters could be mis-interpreted. [1](#0-0) 

### Finding Description
`compute_cairo_hinted_class_hash` serializes the `ContractClass` to a sorted `serde_json::Value`, re-parses it into a typed `CairoContractDefinition`, and serializes it again using `PythonJsonFormatter` to byte-exactly reproduce the legacy Python implementation's JSON text, which is then hashed with Keccak256 to produce the `hinted_class_hash`: [2](#0-1) 

For classes without a `compiler_version` (pre‑0.10.0 format), an additional post-processing step, `add_backward_compatibility_space`, is applied directly to the produced JSON *text* using regexes:

```rust
let cairo_regex = Regex::new(r#""cairo_type"\s*:\s*"\(([^"]*)\)""#).unwrap();
let value_regex = Regex::new(r#""value"\s*:\s*"(.*?)""#).unwrap();
``` [3](#0-2) 

Both `value` and `cairo_type` fields inside the class's `program.attributes` (`AttributeScope.value: String`) are fully attacker-controlled by whoever authors/declares the deprecated class — they can contain arbitrary bytes, including embedded double quotes, JSON escape sequences (`\"`), backslashes, or parentheses. The regexes match on literal `"` characters without accounting for JSON escaping (`\"` inside a string still contains a literal `"` character in the raw text that the regex cannot distinguish from a real string terminator). This means:
- A crafted `value` string containing an escaped quote or backslash sequence can cause `value_regex`'s non-greedy `(.*?)` to terminate at the wrong position, corrupting the reconstructed JSON text in a way that differs from what a canonical/other implementation of the same specification would produce.
- Because the final hash is computed over the resulting raw bytes (`KeccakWriter`), any divergence between how this regex-based rewrite handles adversarial input versus other implementations (or versus the originally intended semantics) directly changes the computed `hinted_class_hash`, and subsequently `compute_deprecated_class_hash`. [4](#0-3) 

This is architecturally the same bug class as the CloudFront advisory: a structured document (JSON text used as a hash preimage/policy) is built from untrusted input using naive string/regex manipulation that does not correctly handle escaping of special characters, so the effective "meaning" of the document (here, the byte sequence that is hashed) can diverge from what is intended or from what other implementations compute for the same logical input.

### Impact Explanation
The `hinted_class_hash`/deprecated `class_hash` is a consensus-critical value: it is asserted by the Starknet OS during `DECLARE` transaction processing and used to identify contract classes in the class commitment tree. If this Rust reimplementation of the legacy Python hash algorithm diverges from the canonical/reference computation for adversarially crafted (but syntactically valid) legacy class definitions containing special characters in `attributes[].value` or `cairo_type`, an attacker (any class declarer) could:
- Cause this node to compute a different class hash than other honest nodes/implementations for the same declared class, leading to state/class-commitment divergence and honest-node consensus failure (chain split) if the sequencer's implementation is what other nodes rely on for validation, or
- Cause an OS assertion (class hash mismatch) leading to block re-execution failure, which can halt block production/finality for transactions involving that class.

This satisfies "wrong committed root or block hash" / "honest-node divergence" criteria for a Medium/High severity analog, since it's reachable purely by declaring a Cairo 0 class as an unprivileged sender.

### Likelihood Explanation
Likelihood is moderate: exploitation requires crafting a legacy (pre-0.10.0, no `compiler_version`) Cairo 0 class whose `program.attributes` contain a `value`/`cairo_type` string with special characters (quotes/backslashes) positioned to make the non-escape-aware regex mis-match. This is a narrow, specific code path (only triggered for old-format classes and only for the `attributes` field), and legacy class declaration is a rare-but-still-reachable operation on Starknet (declaring old Cairo 0 classes is permitted). The exact divergence would need to be validated against the canonical Python/pathfinder reference implementation to confirm an actual behavioral difference — this could not be fully verified with the available tooling (no execution environment to run both implementations side by side), so likelihood should be treated as unconfirmed but plausible given the code's own comments acknowledging its fragility ("When debugging mismatching hashes, it might be useful to check the length...").

### Recommendation
- Replace the regex-based text post-processing (`add_backward_compatibility_space`) with an escape-aware JSON-level transformation (operate on parsed `serde_json::Value` string content rather than raw serialized bytes), or explicitly unescape/reescape JSON strings before regex matching so that embedded `\"`/`\\` sequences cannot be mis-interpreted as structural quotes.
- Add fuzz/differential tests comparing this implementation's `compute_deprecated_class_hash` against the canonical reference (e.g., pathfinder/cairo-lang) using adversarial `attributes[].value` and `cairo_type` strings containing quotes, backslashes, and parentheses.
- Add defensive validation on class declaration to reject or fully escape `value`/`cairo_type` content in `attributes` that appears likely to break the compatibility regex before allowing the class into the mempool/committer path.

### Proof of Concept
Not independently executed against a live sequencer instance (no code execution tooling available in this session). Conceptually:
1. Craft a legacy Cairo 0 `ContractClass` JSON (no `compiler_version` field) whose `program.attributes` array includes an `AttributeScope` with `"value": "(a: felt) \" extra \")"` — i.e., a value string containing an escaped quote followed by additional parenthesis content.
2. Submit this class via a `DECLARE` transaction (gateway class declaration path is reachable by any sender).
3. Compare the `hinted_class_hash` produced by `compute_cairo_hinted_class_hash` (this repo, `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs`) against the hash produced by the canonical reference Python/pathfinder implementation for the identical class JSON.
4. A divergence in the resulting hash would confirm the vulnerability and its consensus impact.

This PoC step (4) requires running both implementations, which was not possible in this analysis session — this is flagged as unverified pending dynamic testing.

pub fn compute_cairo_hinted_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    // Serialize to Value, sort all objects by keys for deterministic output, then to bytes.
    // The sorting is necessary because serde_json with `preserve_order` feature enabled
    // maintains insertion order instead of sorting keys.
    // TODO(Meshi): Compute hinted hashes when loading serialized contracts from storage, before
    // deserializing, to avoid back-and-forth serde.
    let contract_value = serde_json::to_value(contract_class)?;
    let sorted_contract_value = sort_json_value(contract_value);
    let contract_definition_vec = serde_json::to_vec(&sorted_contract_value)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let mut string_buffer = vec![];

    let mut ser = serde_json::Serializer::with_formatter(&mut string_buffer, PythonJsonFormatter);
    contract_definition.serialize(&mut ser)?;

    let mut raw_json_output = String::from_utf8(string_buffer)?;
    if contract_definition.program.compiler_version.is_none() {
        add_backward_compatibility_space(&mut raw_json_output);
    }

    let mut keccak_writer = KeccakWriter::default();
    keccak_writer
        .write_all(raw_json_output.as_bytes())
        .expect("writing to KeccakWriter never fails");

    let KeccakWriter(hash) = keccak_writer;
    Ok(truncated_keccak(<[u8; 32]>::from(hash.finalize())))
}

/// Adds space before the colon when formatting named tuple types.
/// This should be used for backward compatibility in the contract hash computation in versions
/// before 0.10.0.
/// For example, use "(a : felt)" instead of "(a: felt)".
pub fn add_backward_compatibility_space(input: &mut String) {
    let cairo_regex = Regex::new(r#""cairo_type"\s*:\s*"\(([^"]*)\)""#).unwrap();
    let value_regex = Regex::new(r#""value"\s*:\s*"(.*?)""#).unwrap();
    let paren_regex = Regex::new(r"\(([^()]+)\)").unwrap();
    let pair_regex = Regex::new(r"([^:\s,]+):\s*([^,\s)]+)").unwrap();

    // Fix cairo_type, which must be a single type (either a simple type or a tuple).
    *input = cairo_regex
        .replace_all(input, |caps: &regex::Captures<'_>| {
            let inner = &caps[1];
            let fixed = pair_regex.replace_all(inner, "$1 : $2");
            format!("\"cairo_type\": \"({fixed})\"")
        })
        .into_owned();

    // Fix only (key: value) pairs inside (...) in "value".
    *input = value_regex
        .replace_all(input, |caps: &regex::Captures<'_>| {
            let raw_value = &caps[1];
            let fixed = paren_regex
                .replace_all(raw_value, |paren_caps: &regex::Captures<'_>| {
                    let inner = &paren_caps[1];
                    let fixed_inner = pair_regex.replace_all(inner, "$1 : $2");
                    format!("({fixed_inner})")
                })
                .into_owned();
            format!("\"value\": \"{fixed}\"")
        })
        .into_owned();

pub fn compute_deprecated_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    let hinted_class_hash = compute_cairo_hinted_class_hash(contract_class)?;
    let contract_definition_vec = serde_json::to_vec(contract_class)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let FlatEntryPointFelts { external, l1_handler, constructor } =
        get_flat_entry_point_felts(&contract_definition.entry_points_by_type);
    let builtins = ascii_strs_as_felts(&contract_definition.program.builtins);
    let bytecode = hex_strs_as_felts(&contract_definition.program.data);

    let mut hash_state = HashState::<Pedersen>::new();
    hash_state.update_single(&DEPRECATED_COMPILED_CLASS_VERSION);
    hash_state.update_with_hashchain(&external);
    hash_state.update_with_hashchain(&l1_handler);
    hash_state.update_with_hashchain(&constructor);
    hash_state.update_with_hashchain(&builtins);
    hash_state.update_single(&hinted_class_hash);
    hash_state.update_with_hashchain(&bytecode);
    Ok(hash_state.finalize())
}
