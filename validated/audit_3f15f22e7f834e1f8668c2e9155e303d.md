### Title
Webhook shop-domain header is not bound to the HMAC signature, enabling cross-tenant webhook replay - (File: `packages/apps/shopify-api/lib/webhooks/validate.ts`)

### Summary
`validateFactory` verifies only that the raw request body is signed with the app's `apiSecretKey`; it never binds that signature to the `X-Shopify-Shop-Domain` (or topic) header. `checkWebhooksHeaders` then reads the shop domain, topic, and webhook id directly from unauthenticated request headers and returns them as trusted fields. Any actor who can obtain one valid `(rawBody, hmac)` pair for the app (e.g. a merchant with the app installed, using a webhook subscription pointed at infrastructure they control) can replay that exact body/HMAC pair to the app's webhook endpoint with a forged `X-Shopify-Shop-Domain` header claiming a different shop.

### Finding Description
`validateFactory` in `packages/apps/shopify-api/lib/webhooks/validate.ts` (lines 46-75) calls `validateHmacFromRequestFactory` and, on success, calls `checkWebhookHeaders` → `checkWebhooksHeaders` (lines 89-146). The HMAC check performed in `validateHmacFromRequestFactory`/`validateHmacString` (`packages/apps/shopify-api/lib/utils/hmac-validator.ts` lines 168-201, 153-162) computes `base64(HMAC-SHA256(config.apiSecretKey, rawBody))` and compares it with the `hmac` header via `safeCompare`. Crucially, this signed material is **only the raw body** — it does not include the `X-Shopify-Shop-Domain`, `X-Shopify-Topic`, or `X-Shopify-Webhook-Id` headers.

`checkWebhooksHeaders` (lines 99-146) then simply reads those headers with `getRequiredHeader`/`getHeader` and returns them as trusted fields (`domain`, `topic`, `webhookId`, etc.) once the HMAC on the body checks out, with no cross-check that the body content actually corresponds to the claimed `domain`/`topic`.

Because the same `apiSecretKey` is used to sign webhooks for **every shop** that installs the app, a valid `(rawBody, hmac)` pair generated for one shop's webhook delivery remains cryptographically valid regardless of which shop's domain is asserted in the header. An attacker who can obtain one legitimately-signed webhook body (for example, by installing the app on their own shop and configuring/observing a webhook delivery to a server they control) can resend that exact body and HMAC to the target app's webhook endpoint while substituting `X-Shopify-Shop-Domain` for a different (victim) shop. `validateHmacFromRequest` still returns `valid: true` because it never looked at the domain header, and `checkWebhooksHeaders` will happily report the forged domain as the authenticated shop for that webhook.

### Impact Explanation
If the host application's webhook processor (`packages/apps/shopify-api/lib/webhooks/process.ts` and its handler dispatch) uses the `domain` field returned by `checkWebhooksHeaders` to select which shop's session/data to mutate (a common and encouraged pattern, since this is exactly the field the library exposes as "the shop"), an attacker can trigger cross-tenant state changes — e.g., replaying an `app/uninstalled`, `customers/redact`, or order webhook that was validly signed for their own shop but attributed to a victim shop, causing the app to delete/modify data belonging to a shop the attacker does not control. This matches the "Cross-tenant webhook action" impact class in scope for this audit.

### Likelihood Explanation
Exploitation requires the attacker to first obtain a genuinely HMAC-signed `(rawBody, hmac)` pair from Shopify. The most direct route allowed under the "single merchant" threat model is: install the app (or otherwise have webhooks delivered) to infrastructure the attacker controls, capture one valid signed webhook, then replay it against the shared app endpoint with a different `X-Shopify-Shop-Domain` header. This does not require the `apiSecretKey`, MITM, or any privileged role beyond being a normal merchant/customer of the app — it is within the allowed "single merchant... sending crafted requests" scenario. The library performs no additional binding between the signed body and the claimed shop domain, so the replay is deterministic and repeatable, not probabilistic.

### Recommendation
Bind the shop identity to the signed payload rather than trusting the header in isolation:
- Cross-check the `X-Shopify-Shop-Domain` header against the shop domain embedded/derivable from the webhook body or webhook subscription lookup (e.g., verify the `webhookId`/topic against records already known to belong to that shop) before trusting `domain` downstream.
- Alternatively/additionally, look up the webhook's registered target shop (via `webhookId`) in the app's own webhook registry and reject if it doesn't match the claimed `domain` header, rather than returning the header value unconditionally as trusted output.
- Document explicitly (and enforce in `checkWebhooksHeaders`) that the `domain` header must never be used as an authorization key without correlating it to shop-specific state already known to the app (e.g., verifying an active session exists for that shop before processing).

```ts
// packages/apps/shopify-api/lib/webhooks/__tests__/validate-domain-spoof.test.ts
import {validateFactory} from '../validate';
import {createSHA256HMAC} from '../../../runtime/crypto';
import {HashFormat} from '../../../runtime/crypto/types';
import {WEBHOOK_HEADER_NAMES, WebhookType} from '../types';

test('valid HMAC but forged shop domain is accepted as trusted', async () => {
  const config = /* test config with a fixed apiSecretKey */;
  const rawBody = JSON.stringify({id: 1, order: 'legit-for-shopA'});
  const hmac = await createSHA256HMAC(config.apiSecretKey, rawBody, HashFormat.Base64);

  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const headers = {
    [headerNames.hmac]: hmac,
    [headerNames.topic]: 'orders/create',
    [headerNames.domain]: 'victim-shop.myshopify.com', // forged, not shop-A
    [headerNames.apiVersion]: '2024-01',
    [headerNames.webhookId]: 'wh_123',
  };

  const validate = validateFactory(config);
  const result = await validate({rawBody, headers /* ...adapterArgs */});

  // HMAC check passes because it only covers rawBody, not the domain header
  expect(result.valid).toBe(true);
  // domain is returned as trusted even though it wasn't part of the signed payload
  expect((result as any).domain).toBe('victim-shop.myshopify.com');
});
```

```typescript
export function validateFactory(config: ConfigInterface) {
  return async function validate({
    rawBody,
    ...adapterArgs
  }: WebhookValidateParams): Promise<WebhookValidation> {

      await abstractConvertRequest(adapterArgs);

      rawBody,

    }

  };
```

```typescript
function checkWebhooksHeaders(
  headers: Headers,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };

  const name = getHeader(headers, headerNames.name);
  if (name) fields.name = name;

  const triggeredAt = getHeader(headers, headerNames.triggeredAt);
  if (triggeredAt) fields.triggeredAt = triggeredAt;

  const eventId = getHeader(headers, headerNames.eventId);
  if (eventId) fields.eventId = eventId;

  return {valid: true, ...fields};
}
```

```typescript
export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };
}
```
