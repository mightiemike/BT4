### Title
Unbounded per-request iteration over `VotesStore` in `getPaginatedNowWitnessList` enables public-API resource-exhaustion DoS - (File: `framework/src/main/java/org/tron/core/Wallet.java`)

### Summary
`Wallet.getPaginatedNowWitnessList` is exposed via the public, rate-limited-only HTTP/gRPC API (`GetPaginatedNowWitnessListServlet`) and, on every call, invokes `countVote(votesStore)`, which iterates over **every entry** in `VotesStore` regardless of the requested `offset`/`limit`. [1](#0-0) [2](#0-1)  `VotesStore` size grows with the number of distinct voting accounts on-chain, a value fully controlled by unprivileged users, matching the reported bug class of "external/unbounded work in a loop causing DoS as the underlying collection grows."

### Finding Description
`getPaginatedNowWitnessList(offset, limit)` caps only the *returned* witness count (`WITNESS_COUNT_LIMIT_MAX`), but before pagination it calls `countVote(votesStore)`, which walks the full `VotesStore` iterator to sum vote deltas for the current epoch: [3](#0-2) 

Any account can add an entry to `VotesStore` by calling `VoteWitnessContract` after freezing only a small amount of TRX for `tronPower` (the actuator only requires `sum (votes*TRX_PRECISION) <= tronPower`, with `voteCount > 0` and up to `MAX_VOTE_NUMBER` (30) candidate witnesses per vote), which is validated in `VoteWitnessActuator.validate()`: [4](#0-3) 

Each voting account produces exactly one `VotesCapsule` entry in `VotesStore`, keyed by the voter's address, as seen in `VoteWitnessProcessor.execute` (and the classic actuator path), which is deleted only during the once-per-epoch `MaintenanceManager.doMaintenance()`/`countVote()`: [5](#0-4) [6](#0-5) 

Because votes are only cleared at maintenance time (roughly every epoch), an attacker can, within a single epoch, generate a very large number of accounts (account creation is cheap), freeze the minimal TRX needed for `tronPower > 0`, and issue one `VoteWitnessContract` transaction per account. This inflates `VotesStore` to an attacker-chosen size N. Every subsequent call to the public `getPaginatedNowWitnessList` API (`GetPaginatedNowWitnessListServlet`, also reachable via gRPC `RpcApiService` and Solidity-node HTTP/gRPC mirrors) then performs O(N) work in `countVote()` before any pagination is applied, regardless of the small `limit` parameter requested. [7](#0-6) 

The only defense present is a generic servlet rate limiter (`RateLimiterServlet`) that limits request *rate*, not the *cost* of each request — it does not bound N, the size of `VotesStore`, so each allowed request can still be made arbitrarily expensive by the attacker growing `VotesStore` beforehand.

### Impact Explanation
This is a public, unauthenticated, unprivileged-user-reachable resource-exhaustion vector against full/solidity nodes serving the witness-list API. Because the loop cost scales with attacker-controlled state (number of distinct voters, unbounded until the next maintenance cycle), a moderately funded attacker can drive `countVote()`'s per-request cost arbitrarily high, degrading or denying the API for legitimate users and consuming node CPU on every poll of this endpoint — a realistic node-availability/DoS impact consistent with the "invalid-state/divergence/halt" and "underpriced-public-work" impact categories called out in the validation rules (the API performs unbounded compute per call while the requester pays nothing beyond rate-limiter cadence).

### Likelihood Explanation
Likelihood is moderate-to-high: creating accounts and submitting `VoteWitnessContract` transactions requires only ordinary account-creation and freeze/vote fees — no privileged role, leaked key, or protocol bypass is needed. The attack must be sustained/refreshed since `VotesStore` is cleared at each maintenance cycle, but epochs are long enough (multiple hours) that an attacker has ample time to inflate the store and hammer the public endpoint before the next cleanup. The endpoint is directly reachable by any external client via HTTP/gRPC, and equivalent unbounded per-call iteration also occurs in the closely related `MaintenanceManager.countVote()`/`doMaintenance()` path, which runs automatically in block processing and would similarly slow down as `VotesStore` grows, compounding the risk.

### Recommendation
- Bound the per-request cost of `getPaginatedNowWitnessList` independent of `VotesStore` size, e.g., by maintaining an incrementally updated vote-delta index/cache instead of recomputing `countVote()` over the full store on every API call.
- Consider capping or aging out `VotesStore` entries (or requiring higher minimum stake/vote to add an entry) to prevent unbounded growth within a single epoch.
- Apply cost-based rate limiting (e.g., limit by estimated `VotesStore` size or CPU time) in addition to the existing request-rate limiter in `RateLimiterServlet`.
- Apply the same review to `MaintenanceManager.countVote()`/`doMaintenance()`, since it has the identical unbounded-iteration pattern executed on the consensus/block-processing critical path.

### Proof of Concept
1. Programmatically create a large number (e.g., tens of thousands) of new TRON accounts.
2. For each account, freeze the minimum TRX required to obtain `tronPower > 0` (e.g., 1 TRX) via `FreezeBalanceContract`.
3. Submit one `VoteWitnessContract` transaction per account, voting for any valid witness with `voteCount = 1`. Each transaction succeeds `VoteWitnessActuator.validate()`'s checks and adds one entry to `VotesStore`.
4. Before the next maintenance cycle clears `VotesStore` (`MaintenanceManager.doMaintenance()` → `countVote()`), repeatedly call the public `GET /wallet/getpaginatednowwitnesslist?offset=0&limit=1` HTTP endpoint (or the equivalent gRPC/Solidity-node call).
5. Observe that each call's latency and CPU cost scale with the number of `VotesStore` entries created in step 3, not with the requested `limit`, because `Wallet.getPaginatedNowWitnessList` unconditionally calls `countVote(votesStore)` over the entire store before applying pagination.

  public WitnessList getPaginatedNowWitnessList(long offset, long limit) throws
      MaintenanceUnavailableException {
    if (limit <= 0 || offset < 0) {
      return null;
    }
    if (limit > WITNESS_COUNT_LIMIT_MAX) {
      limit = WITNESS_COUNT_LIMIT_MAX;
    }

    /*
      In the maintenance period, the VoteStores will be cleared.
      To avoid the race condition of VoteStores deleted but Witness vote counts not updated,
      return retry error.
      Only apply to requests that rely on the latest block,
      which means the normal fullnode requests with HEAD cursor.
    */
    boolean isMaintenance = chainBaseManager.getDynamicPropertiesStore().getStateFlag() == 1;
    if (isMaintenance && !Args.getInstance().isSolidityNode() && getCursor() == Cursor.HEAD) {
      String message =
          "Service temporarily unavailable during maintenance period. Please try again later.";
      throw new MaintenanceUnavailableException(message);
    }
    // It contains the final vote count at the end of the last epoch.
    List<WitnessCapsule> witnessCapsuleList = chainBaseManager.getWitnessStore().getAllWitnesses();
    if (offset >= witnessCapsuleList.size()) {
      return null;
    }

    VotesStore votesStore = chainBaseManager.getVotesStore();
    // Count the vote changes for each witness in the current epoch, it is maybe negative.
    Map<ByteString, Long> countWitness = countVote(votesStore);

    // Iterate through the witness list to apply vote changes and calculate the real-time vote count
    witnessCapsuleList.forEach(witnessCapsule -> {
      long voteCount = countWitness.getOrDefault(witnessCapsule.getAddress(), 0L);
      witnessCapsule.setVoteCount(witnessCapsule.getVoteCount() + voteCount);
    });

    // Use the same sorting logic as in the Maintenance period
    WitnessStore.sortWitnesses(witnessCapsuleList,
        chainBaseManager.getDynamicPropertiesStore().allowWitnessSortOptimization());

    List<WitnessCapsule> sortedWitnessList = witnessCapsuleList.stream()
        .skip(offset)
        .limit(limit)
        .collect(Collectors.toList());

    WitnessList.Builder builder = WitnessList.newBuilder();
    sortedWitnessList.forEach(witnessCapsule ->
        builder.addWitnesses(witnessCapsule.getInstance()));

    return builder.build();
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }
