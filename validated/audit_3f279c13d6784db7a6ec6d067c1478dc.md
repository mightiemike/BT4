### Title
Missing role check on WebAuthn enrollment endpoint allows View-role users to register persistent MFA credentials - ([File: core/web/router.go])

### Summary
The `/v2/enroll_webauthn` (`GET`/`POST`) routes are registered in `v2Routes` with only session/token authentication and no `RequiresEditRole`/`RequiresAdminRole` guard, unlike comparable security-sensitive routes. This lets any authenticated user, including one holding the lowest-privilege `View` role, complete `WebAuthnController.FinishRegistration` and persist an attacker-controlled WebAuthn credential tied to their account via `sessions.AddCredentialToUser`.

### Finding Description
In `core/web/router.go`, the route registration `authv2.GET("/enroll_webauthn", wa.BeginRegistration)` / `authv2.POST("/enroll_webauthn", wa.FinishRegistration)` [1](#0-0)  applies no role middleware, while sibling routes for admin operations use `auth.RequiresAdminRole` or `auth.RequiresEditRole`. `WebAuthnController.FinishRegistration` [2](#0-1)  only validates that a session exists via `auth.GetAuthenticatedUser`, then unconditionally saves the submitted WebAuthn credential to the user's account. Because Chainlink's user roles (`View`, `Run`, `Edit`, `Admin`) are hierarchical, and role changes are performed later by an admin via `UpdateRole` (`PATCH /v2/users`, itself correctly gated by `auth.RequiresAdminRole`), a credential registered while the account is `View`-role persists unchanged after the account is promoted to `Edit`/`Admin`. If a low-priv account/session is compromised (e.g., leaked View-only API token) and the attacker registers their own hardware/software authenticator, that authenticator becomes a valid second factor forever, even after credentials/passwords are rotated, as long as the account itself isn't deleted or the WebAuthn credential explicitly removed.

### Impact Explanation
This allows an attacker who compromises a low-privilege account to persistently back-door authentication for that account. If an admin subsequently elevates that account's role (a legitimate future administrative action, not itself a vulnerability), the attacker's pre-planted WebAuthn credential grants full MFA-satisfying access at the new elevated privilege, enabling unauthorized transaction submission, job/key management, or other admin actions — a persistent authentication-factor backdoor and privilege-escalation vector.

### Likelihood Explanation
Requires only a valid low-privilege session or API token (explicitly the granted precondition) and a single unauthenticated-role-check API call to `/v2/enroll_webauthn` GET then POST; feasibility is high and fully repeatable since no role gate exists at all (confirmed by the RBAC test table marking `viewOnlyAllowed: true` for this route) [3](#0-2) .

### Recommendation
Gate `/v2/enroll_webauthn` GET/POST with at minimum `auth.RequiresEditRole` (or `RequiresAdminRole`, matching the sensitivity of adding a persistent authentication factor) in `core/web/router.go`, consistent with other security-state-changing endpoints like `/user/token` and `/keys/*`. Update the RBAC test table in `core/web/auth/auth_test.go` to reflect the new restriction.

### Proof of Concept
Integration test extending `TestRBAC_Routemap_*` in `core/web/auth/auth_test.go`:
1. Create an application and a `View`-role user/session via `cltest.User{Role: sessions.UserRoleView}`.
2. `GET /v2/enroll_webauthn` — expect current behavior returns 200 (registration options), assert this should instead be `403 Forbidden` after fix.
3. Simulate `POST /v2/enroll_webauthn` with a crafted WebAuthn attestation response — expect current behavior calls `FinishRegistration` and persists credential via `sessions.AddCredentialToUser`; assert `GetUserWebAuthn` now returns the new credential for the View-role user, proving unauthorized MFA enrollment succeeded without an Edit/Admin role check.

```go
func (w *WebAuthnController) FinishRegistration(c *gin.Context) {
	ctx := c.Request.Context()
	user, ok := auth.GetAuthenticatedUser(c)
	if !ok {
		logger.Sugared(w.App.GetLogger()).AssumptionViolationf("failed to obtain current user from context")
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	orm := w.App.AuthenticationProvider()
	uwas, err := orm.GetUserWebAuthn(ctx, user.Email)
	if err != nil {
		w.App.GetLogger().Errorf("failed to obtain current user MFA tokens: error in GetUserWebAuthn: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	webAuthnConfig := w.App.GetWebAuthnConfiguration()

	credential, err := w.inProgressRegistrationsStore.FinishWebAuthnRegistration(*user, uwas, c.Request, webAuthnConfig)
	if err != nil {
		w.App.GetLogger().Errorf("error in FinishWebAuthnRegistration: %s", err)
		jsonAPIError(c, http.StatusBadRequest, errors.New("registration was unsuccessful"))
		return
	}

	if sessions.AddCredentialToUser(ctx, w.App.AuthenticationProvider(), user.Email, credential) != nil {
		w.App.GetLogger().Errorf("Could not save WebAuthn credential to DB for user: %s", user.Email)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}
```
