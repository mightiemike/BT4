### Title
Unrestricted `TransferToGasKey` Allows Any Account to Permanently Block Victim's Gas Key and Account Deletion — (`runtime/runtime/src/actions.rs`)

---

### Summary

`check_actor_permissions` explicitly places `Action::TransferToGasKey` in the **unrestricted** branch alongside `Transfer` and `FunctionCall`, meaning any account or contract can send a `TransferToGasKey` receipt targeting any other account's gas key. Combined with the hard `MAX_BALANCE_TO_BURN = 1 NEAR` guard in `delete_gas_key` and `action_delete_account`, an unprivileged attacker can push a victim's gas key balance above 1 NEAR, causing every subsequent `DeleteKey` and `DeleteAccount` attempt on that account to fail with `GasKeyBalanceTooHigh`. This is the nearcore analog of the `reclaim_session` class: an external party can forcibly disrupt a user's ability to manage (close/delete) their own key-session.

---

### Finding Description

**Root cause — `check_actor_permissions` (`runtime/runtime/src/actions.rs:711-756`)**

```rust
Action::CreateAccount(_)
| Action::FunctionCall(_)
| Action::Transfer(_)
| Action::TransferToGasKey(_) => (),   // ← no actor check
```

`WithdrawFromGasKey` is in the restricted branch (requires `actor_id == account_id`), but `TransferToGasKey` is not. [1](#0-0) 

**Execution path — `action_transfer_to_gas_key` (`runtime/runtime/src/access_keys.rs:257-288`)**

The function receives `account_id` (the receipt's `receiver_id`) and unconditionally adds `action.deposit` to the gas key's balance, then writes it back to the trie. There is no check on who the predecessor is. [2](#0-1) 

**Deletion guard — `delete_gas_key` (`runtime/runtime/src/access_keys.rs:93-133`)**

```rust
if gas_key_info.balance > GasKeyInfo::MAX_BALANCE_TO_BURN {
    result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh { … });
    return Ok(());
}
```

`MAX_BALANCE_TO_BURN = Balance::from_near(1)`. If the balance exceeds 1 NEAR, the key cannot be deleted. [3](#0-2) 

**Account deletion guard — `action_delete_account` (`runtime/runtime/src/actions.rs:339-347`)**

The same threshold is applied to the **sum** of all gas key balances on the account. [4](#0-3) 

**`GasKeyInfo::MAX_BALANCE_TO_BURN` definition:** [5](#0-4) 

**Cross-contract trigger — `promise_batch_action_transfer_to_gas_key` (VM host function)**

A contract can call this host function targeting any `receiver_id` and any `public_key`. The host function deducts the deposit from the calling contract's balance and appends a `TransferToGasKey` action to a receipt whose `receiver_id` is the victim. [6](#0-5) 

---

### Impact Explanation

**Broken invariant:** A gas key owner should be the only party able to alter the key's balance in a way that affects their own account's administrative operations (deletion). The current design allows any third party to inflate the balance past the deletion threshold.

**Concrete corrupted value:** `gas_key_info.balance` on the victim's account is pushed above `1_000_000_000_000_000_000_000_000` yoctoNEAR (1 NEAR), causing `delete_gas_key` and `action_delete_account` to return `GasKeyBalanceTooHigh` and leave the key/account intact.

**Affected operations:**
- `Action::DeleteKey` on the inflated gas key → permanently blocked until victim withdraws
- `Action::DeleteAccount` → blocked if the sum of all gas key balances exceeds 1 NEAR

**Partial mitigation available to victim:** The victim can call `WithdrawFromGasKey` (which *is* restricted to `actor_id == account_id`) to drain the balance back below 1 NEAR. However:
1. If the victim only holds a `GasKeyFunctionCall` key (not `GasKeyFullAccess` or a regular `FullAccess` key), they may be unable to issue a `WithdrawFromGasKey` transaction.
2. An attacker can continuously re-fund the key (each re-fund costs the attacker NEAR, which accumulates in the victim's gas key), creating a sustained griefing loop.

---

### Likelihood Explanation

- The attacker must know the victim's account ID and gas key public key (both are public on-chain).
- The attacker must spend their own NEAR (it is not burned; it accumulates in the victim's gas key balance).
- The attack is cheap: sending just `1 yoctoNEAR` above the threshold suffices if the victim's key is already near 1 NEAR.
- No privileged role is required; any ordinary account or deployed contract can execute this via `promise_batch_action_transfer_to_gas_key`.

---

### Recommendation

Add `Action::TransferToGasKey` to the restricted branch in `check_actor_permissions`, requiring `actor_id == account_id`:

```rust
Action::WithdrawFromGasKey(_)
| Action::TransferToGasKey(_) => {   // add here
    if actor_id != account_id {
        return Err(ActionErrorKind::ActorNoPermission { … }.into());
    }
}
```

Alternatively, change the deletion semantics so that when `balance > MAX_BALANCE_TO_BURN`, the excess is moved to the account's `amount` rather than causing a hard failure — eliminating the DoS vector entirely regardless of who funded the key.

---

### Proof of Concept

1. **Setup:** Victim `victim.near` creates a `GasKeyFullAccess` gas key with public key `GK_PK` and funds it with `0.9 NEAR` via `TransferToGasKey`.

2. **Attack:** Attacker deploys a contract on `attacker.near` that calls:
   ```
   promise_batch_action_transfer_to_gas_key(
       promise_idx,          // receipt targeting victim.near
       GK_PK,
       0.2 NEAR              // pushes balance to 1.1 NEAR > MAX_BALANCE_TO_BURN
   )
   ```
   The attacker submits a transaction calling this contract method. The resulting receipt targets `victim.near` with `Action::TransferToGasKey { public_key: GK_PK, deposit: 0.2 NEAR }`. `check_actor_permissions` returns `Ok(())` with no restriction. `action_transfer_to_gas_key` writes `balance = 1.1 NEAR` to the trie.

3. **Effect:** Victim submits `Action::DeleteKey { public_key: GK_PK }`. Runtime calls `action_delete_key` → `delete_gas_key` → `1.1 NEAR > 1 NEAR` → returns `GasKeyBalanceTooHigh`. Key is not deleted. Victim submits `Action::DeleteAccount` → `compute_gas_key_balance_sum` returns `1.1 NEAR > 1 NEAR` → returns `GasKeyBalanceTooHigh`. Account is not deleted.

4. **Sustained attack:** Each time victim calls `WithdrawFromGasKey` to drain the balance, attacker re-funds via another cross-contract call, maintaining the balance above the threshold indefinitely at a cost of `>0 NEAR` per round to the attacker.

pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
