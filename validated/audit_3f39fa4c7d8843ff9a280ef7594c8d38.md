Found a concrete analog: `SnapshotMinimizer::filter_storage` in `runtime/src/snapshot_minimizer.rs` calls `AccountsDb::get_unique_accounts_from_storage`, which itself scans storage via the raw `AccountsFile::scan_accounts_without_data` path rather than the `AccountStorageEntry::scan_accounts_without_data` wrapper that applies `excluded_offsets()` (obsolete accounts + tombstones). This is exactly the same bug class as the WLFI report: a state that is supposed to be "excluded" (obsolete/tombstone accounts, analogous to `excludedVotingPower`) is enforced in one code path (`AccountsDb::shrink_collect`, which manually re-filters `obsolete_offsets`/`tombstone_offsets` after calling the same unfiltered helper) but not in another path that reuses the same underlying function without applying the exclusion.

### Title
Snapshot minimizer resurrects obsolete/tombstone (logically dead) accounts by bypassing storage exclusion filtering - ([File: runtime/src/snapshot_minimizer.rs])

### Summary
`AccountsDb::get_unique_accounts_from_storage` [1](#0-0)  scans a storage's raw bytes with `store.accounts.scan_accounts_without_data`, the unfiltered `AccountsFile` method, instead of `AccountStorageEntry::scan_accounts_without_data`, which applies `excluded_offsets()` to skip obsolete accounts and tombstones [2](#0-1) . The only caller that is safe, `shrink_collect`, compensates by manually re-filtering `obsolete_accounts_read_lock()` and `tombstone_offsets_read_lock()` on the returned `stored_accounts` before using them [3](#0-2) . `SnapshotMinimizer::filter_storage`, however, consumes the same unfiltered result directly, without ever re-applying that obsolete/tombstone filter [4](#0-3) .

### Finding Description
`AccountStorageEntry` tracks two categories of "excluded" bytes that must never be treated as live accounts again:
- `obsolete_accounts`: accounts rewritten to a newer slot or zeroed-out and older than the last full snapshot; "removed from the accounts index entirely," "will not be picked up by scan" [5](#0-4) .
- `tombstone_offsets`: zero-lamport accounts "removed from the accounts index entirely (a tombstone)" whose bytes are retained purely so an incremental snapshot can still observe the deletion [6](#0-5) .

`AccountStorageEntry::excluded_offsets()` combines both sets and is meant to be applied by every consumer that iterates the raw storage bytes, e.g. `scan_accounts` / `scan_accounts_without_data` [7](#0-6) . This is analogous to the WLFI token's `getVotes()` check on `_excludedVotingPower`.

However, `AccountsDb::get_unique_accounts_from_storage` calls the *inner* `AccountsFile`'s `scan_accounts_without_data` directly — bypassing the `AccountStorageEntry` wrapper and its exclusion filter entirely [8](#0-7) . This is analogous to `_delegate()`/`_update()` not enforcing the `excludedVotingPower` flag: the "dead" marking exists, but this particular mutation/read path doesn't check it.

Only one of its two callers is safe: `shrink_collect` explicitly re-derives `obsolete_offsets` and `tombstone_offsets` and retains/filters `stored_accounts` against them before use [3](#0-2) . `SnapshotMinimizer::filter_storage` (used by ledger-tool / RPC snapshot minimization) does not perform any equivalent filtering — it takes `stored_accounts` from `get_unique_accounts_from_storage` and directly partitions them into "keep" (rewritten into a new storage) vs. "purge" based solely on membership in `minimized_account_set` [9](#0-8) .

### Impact Explanation
If a storage being minimized contains an obsolete-marked account (rewritten to a newer slot) or a tombstone (a zero-lamport account already removed from the index) whose pubkey happens to be in `minimized_account_set` (e.g., because a *different*, newer version of the same pubkey is a required account), `filter_storage` will pick up the obsolete/tombstone copy from this older storage as a "keep_accounts" entry and re-store it via `store_accounts_for_shrink` [10](#0-9) . This re-inserts a stale/dead account version back into the accounts index, silently reintroducing a wrong balance/state for that pubkey — the same "resurrection" class of bug the codebase's zero-lamport/tombstone tests are specifically designed to prevent (see `test_incremental_snapshots_handle_zero_lamport_accounts`, which asserts "Account1 has not been brought back from the dead" [11](#0-10) ). This would cause a wrong/stale account load and a divergent accounts lt hash / bank hash relative to what a full replay would produce, exactly the failure mode `test_scan_accounts_excludes_obsolete_and_tombstones` guards against for the normal scan path [12](#0-11) .

### Likelihood Explanation
`SnapshotMinimizer` is gated behind `dev-context-only-utils` [13](#0-12)  and is intended for offline/ledger-tool snapshot minimization rather than normal validator consensus paths. Triggering the bug requires a storage slot that (a) is retained by minimization (`minimized_slot_set`) and (b) contains an obsolete or tombstone offset for a pubkey that is also in `minimized_account_set` from a later slot. This is a plausible but not everyday scenario (any account rewritten across slots, or zeroed after the last full snapshot, within the minimized region). Since this tool is not part of normal validator/replay operation, likelihood in a production validator context is low, but the underlying root cause — `get_unique_accounts_from_storage` omitting the exclusion filter that its sibling `AccountStorageEntry::scan_accounts_without_data` enforces — is a genuine inconsistency that any future caller of `get_unique_accounts_from_storage` could also fall into.

### Recommendation
Make `AccountsDb::get_unique_accounts_from_storage` use `store.scan_accounts_without_data` (the `AccountStorageEntry` wrapper that applies `excluded_offsets()`) instead of `store.accounts.scan_accounts_without_data` (the raw, unfiltered `AccountsFile` method), so obsolete and tombstone offsets are excluded at the source for every caller. This removes the need for `shrink_collect`'s ad-hoc re-filtering and closes the gap that `SnapshotMinimizer::filter_storage` currently falls into.

### Proof of Concept
1. Store account `pubkey` in slot `S`; root and flush.
2. Store a newer version of `pubkey` in slot `S+1`; root and flush without clean, so slot `S`'s entry for `pubkey` becomes obsolete-markable, or drive `pubkey` to zero lamports and let it become a shrink-carried tombstone in slot `S` (as in `test_clean_purges_zero_lamport_single_ref_at_reclaim` / shrink tombstone flow) [14](#0-13) .
3. Ensure slot `S`'s storage retains the obsolete/tombstone bytes for `pubkey` (obsolete accounts are marked, not physically removed) [5](#0-4) .
4. Run `SnapshotMinimizer::minimize` with `starting_slot` beyond `S+1` and `minimized_account_set` containing `pubkey` (kept because of its slot `S+1` version) and with slot `S` included in `minimized_slot_set` (e.g., because another required pubkey also lives in slot `S`).
5. In `filter_storage`, when processing slot `S`'s storage, `get_unique_accounts_from_storage` returns the obsolete/tombstone copy of `pubkey` unfiltered; since `pubkey` is in `minimized_account_set`, it is placed into `keep_accounts` and re-stored via `store_accounts_for_shrink`, reinserting the stale slot-`S` version of `pubkey` into the accounts index alongside (or instead of, if `S+1` isn't retained by other logic) the correct newer version.
6. Assert on the resulting minimized bank that `bank.get_account(&pubkey)` matches the stale slot-`S` data rather than the true slot-`S+1` state, and/or that `calculate_accounts_lt_hash_at_startup_from_index` diverges from the un-minimized bank's expected hash.

    /// Collect the offsets that should be excluded from scans
    fn excluded_offsets(&self) -> IntSet<Offset> {
        let mut offsets: IntSet<_> = self
            .obsolete_accounts_read_lock()
            .filter_obsolete_accounts(None)
            .map(|(offset, _)| offset)
            .collect();
        offsets.extend(self.tombstone_offsets_read_lock().iter().copied());
        offsets
    }

    /// Iterate over the alive accounts in this storage, excluding obsolete accounts and tombstones.
    /// The return value is the number of values excluded from the scan.
    pub(crate) fn scan_accounts<'a>(
        &'a self,
        reader: &mut impl RequiredLenBufFileRead<'a>,
        mut callback: impl for<'local> FnMut(Offset, StoredAccountInfo<'local>),
    ) -> Result<u64, AccountsFileError> {
        let excluded_offsets = self.excluded_offsets();
        let mut num_excluded = 0;
        self.accounts.scan_accounts(reader, |offset, account| {
            if excluded_offsets.contains(&offset) {
                num_excluded += 1;
                return;
            }
            callback(offset, account);
        })?;
        Ok(num_excluded)
    }

    /// Iterate over the alive accounts in this storage without reading data, excluding obsolete
    /// accounts and tombstones. The return value is the number of values excluded from the scan.
    pub(crate) fn scan_accounts_without_data(
        &self,
        mut callback: impl for<'local> FnMut(Offset, StoredAccountInfoWithoutData<'local>),
    ) -> Result<u64, AccountsFileError> {
        let excluded_offsets = self.excluded_offsets();
        let mut num_excluded = 0;
        self.accounts
            .scan_accounts_without_data(|offset, account| {
                if excluded_offsets.contains(&offset) {
                    num_excluded += 1;
                    return;
                }
                callback(offset, account);
            })?;
        Ok(num_excluded)
    }

    fn test_scan_accounts_excludes_obsolete_and_tombstones() {
        let slot = 0;
        let temp_dir = TempDir::new().unwrap();
        let storage = AccountStorageEntry::new(
            temp_dir.path(),
            slot,
            0,
            1024 * 1024,
            AccountsFileProvider::AppendVec,

        // Write five accounts and capture their offsets.
        let accounts: Vec<_> = iter::repeat_with(|| {
            (
                Pubkey::new_unique(),
                AccountSharedData::new(1, 10, &Pubkey::default()),
            )
        })
        .take(5)
        .collect();
        let offsets = storage
            .accounts
            .write_accounts(&(slot, &accounts[..]))
            .unwrap()
            .offsets;

        // Mark account 1 obsolete and record account 3 as a tombstone.
        let obsolete_offset = offsets[1];
        let tombstone_offset = offsets[3];
        let data_lens = storage.accounts.get_account_data_lens(&[obsolete_offset]);
        storage
            .obsolete_accounts()
            .write()
            .unwrap()
            .mark_accounts_obsolete(iter::once((obsolete_offset, data_lens[0])), slot);
        storage.batch_insert_tombstone_offsets([tombstone_offset]);

        // Scan and collect the accounts that were visited, in offset order.
        let mut reader = new_scan_accounts_reader();
        let mut visited = Vec::new();
        let num_excluded = storage
            .scan_accounts(&mut reader, |offset, account| {
                visited.push((offset, *account.pubkey()));
            })
            .unwrap();

        // Accounts 0, 2, and 4 are alive; 1 (obsolete) and 3 (tombstone) are excluded.
        assert_eq!(num_excluded, 2);
        let expected: Vec<_> = [0, 2, 4]
            .iter()
            .map(|&i| (offsets[i], accounts[i].0))
            .collect();
        assert_eq!(visited, expected);

        // scan_accounts_without_data excludes the same offsets from the same storage.
        let mut visited = Vec::new();
        let num_excluded = storage
            .scan_accounts_without_data(|offset, account| {
                visited.push((offset, *account.pubkey()));
            })
            .unwrap();
        assert_eq!(num_excluded, 2);
        assert_eq!(visited, expected);
    }

        &self,
        storage: &Arc<AccountStorageEntry>,
        dead_storages: &Mutex<Vec<Arc<AccountStorageEntry>>>,

        let slot = storage.slot();
        let GetUniqueAccountsResult {
            stored_accounts, ..
        } = self.accounts_db().get_unique_accounts_from_storage(storage);

        let keep_accounts_collect = Mutex::new(Vec::with_capacity(stored_accounts.len()));
        let purge_pubkeys_collect = Mutex::new(Vec::with_capacity(stored_accounts.len()));
        let total_bytes_collect = AtomicUsize::new(0);
        const CHUNK_SIZE: usize = 50;
        stored_accounts.par_chunks(CHUNK_SIZE).for_each(|chunk| {
            let mut chunk_bytes = 0;
            let mut keep_accounts = Vec::with_capacity(CHUNK_SIZE);
            let mut purge_pubkeys = Vec::with_capacity(CHUNK_SIZE);
            chunk.iter().for_each(|account| {
                if self.minimized_account_set.contains(account.pubkey()) {
                    chunk_bytes += account.stored_size();
                    keep_accounts.push(account);
                } else if self.accounts_db().contains(account.pubkey()) {
                    purge_pubkeys.push(account.pubkey());
                }
            });

            keep_accounts_collect
                .lock()
                .unwrap()
                .append(&mut keep_accounts);
            purge_pubkeys_collect
                .lock()
                .unwrap()
                .append(&mut purge_pubkeys);
            total_bytes_collect.fetch_add(chunk_bytes, Ordering::Relaxed);
        });

        let keep_accounts = keep_accounts_collect.into_inner().unwrap();
        let remove_pubkeys = purge_pubkeys_collect.into_inner().unwrap();
        let total_bytes = total_bytes_collect.load(Ordering::Relaxed);

fn test_clean_purges_zero_lamport_single_ref_at_reclaim() {
