### Title
`deposit` mints zero shares for a real asset contribution when vault equity is zero after bad-debt socialization - ([File: mainnet/contracts/vault/v0-vault-usdc.clar])

### Summary
`convert-to-shares-preview`, used by `deposit` in every `v0-vault-*.clar` contract, returns `u0` whenever `total-supply-preview` is non-zero but `total-assets-preview` is zero. Unlike `redeem`, which explicitly guards against a zero output with `ERR-OUTPUT-ZERO`, `deposit` has no equivalent guard on the shares it mints. A depositor who transfers real underlying funds into the vault while its equity/assets accounting is zero (following `socialize-debt` bad-debt write-off) receives `u0` shares and permanently loses their entire deposit to existing `zft` holders in a single transaction.

### Finding Description
`convert-to-shares-preview` computes shares as: [1](#0-0) 
```
(define-private (convert-to-shares-preview (amount uint))
  (let ((ta (total-assets-preview))
        (ts (total-supply-preview)))
    (if (is-eq ts u0)
        amount
        (if (is-eq ta u0)
            u0
            (mul-div-down amount ts ta)))))
```
When `ts != u0` (shares already exist) but `ta == u0` (vault's accounted assets/equity are zero), the function returns `u0` instead of `amount` or an error.

`ta` (`total-assets-preview`) reads directly from the `assets` data-var plus accrued interest: [2](#0-1) 

The `assets` var can be driven to zero by `socialize-debt`, the bad-debt write-off entrypoint invoked by the market contract during liquidation when a borrower has no collateral left: [3](#0-2) 
```
(var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
```
Critically, `socialize-debt` reduces `assets` and `total-borrowed` but never burns any `zft` shares, so `total-supply-preview` (`ts`) remains unchanged and non-zero after a full write-off.

`deposit` then uses the resulting `inkind` (shares to mint) without any positivity check: [4](#0-3) 
```
(define-public (deposit (amount uint) (min-out uint) (recipient principal))
    (let (
      ...
      (inkind (convert-to-shares-preview amount)))
    (asserts! (not (get deposit states)) ERR-PAUSED)
    ...
    (asserts! (>= inkind min-out) ERR-SLIPPAGE)
    ...
    (try! (receive-underlying amount account))
    (try! (ft-mint? zft inkind recipient))
    (var-set assets (+ current-assets amount))
    ...
    (ok inkind)))
```
If `min-out` is `0` (the natural choice when a user has no reason to expect zero-value shares), the slippage check `(>= inkind min-out)` trivially passes even when `inkind = u0`. The real underlying tokens are pulled from the depositor via `receive-underlying`, `ft-mint?` mints zero `zft` to the depositor, and `assets` is increased by the full deposit amount — meaning the depositor's contribution becomes value now backing the *existing* `zft` supply, with the depositor left holding nothing.

This is a single-transaction analog of the reported `valueToShares`/equity=0 class of bug: a degenerate accounting state (`equity`/`assets == 0` while shares outstanding) collapses the share-minting formula into a value-destroying branch, and the calling function mutates state (mints shares, pulls funds) without validating that the computed value is meaningful. `redeem` in the same contract explicitly protects against the mirrored zero-output case (`ERR-OUTPUT-ZERO`), confirming the missing check in `deposit` is an oversight rather than an intended design choice.

### Impact Explanation
A depositor's principal is redistributed in full to pre-existing shareholders within a single transaction, with no way to recover it (their `zft` balance is `0`, so `redeem` cannot return anything to them). This is a direct, permanent loss of user funds at rest, matching the Critical impact bar (direct theft of user funds).

### Likelihood Explanation
The precondition — `assets` reduced to `0` (or near it) by `socialize-debt` while `zft` supply remains positive — is reachable through the market contract's normal, permissioned bad-debt socialization flow after a liquidation leaves a borrower with no collateral (not a DAO compromise or oracle manipulation). Any user who deposits after such a socialization event (with `min-out` left at `0`, the default UX expectation) triggers the loss automatically; no attacker action against another user is required — the loss is intrinsic to the depositor's own transaction.

### Recommendation
In `deposit`, explicitly reject a computed `inkind` of `u0` (mirroring the `ERR-OUTPUT-ZERO` check already present in `redeem`), e.g. `(asserts! (> inkind u0) ERR-OUTPUT-ZERO)`. Additionally, reconsider the `is-eq ta u0` branch in `convert-to-shares-preview`: when supply is non-zero but assets are zero due to a total loss event, the vault should either revert deposits entirely or re-base share price rather than silently zeroing out the depositor's shares.

### Proof of Concept
1. Market/vault has existing depositors holding `zft` shares, `total-supply-preview > 0`.
2. A borrower's position becomes fully undercollateralized; `liquidate` in the market contract triggers `socialize-debt` on the vault, which sets `assets` to `u0` (or drives `total-assets-preview` to `u0`) while leaving `zft` supply unchanged: [5](#0-4) .
3. A new (or existing) user calls `deposit(amount, min-out=0, recipient)` with real funds.
4. `convert-to-shares-preview` computes `ts != 0`, `ta == 0` → returns `u0`.
5. `(asserts! (>= inkind min-out) ERR-SLIPPAGE)` passes trivially since `0 >= 0`.
6. `receive-underlying` pulls `amount` real tokens from the depositor; `ft-mint?` mints `0` `zft` to `recipient`; `assets` is increased by `amount`.
7. The depositor now holds `0` shares while having contributed `amount` real underlying tokens now backing other holders' shares — total, unrecoverable loss of their deposit in one transaction. [6](#0-5)

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
