### Title
`debug_redact` field option is not enforced by `prototext`/`fmt.Stringer` formatting, leaking sensitive field values in debug output - (File: internal/impl/api_export.go, encoding/prototext/encode.go)

### Summary
`google.protobuf.FieldOptions.debug_redact` (and the equivalent `EnumValueOptions.debug_redact`) exists specifically to mark a field as containing sensitive credentials that "should not be printed out when using debug formats." [1](#0-0)  However, the generated `String()` method that every protobuf message implements simply calls `protoimpl.X.MessageStringOf(x)`, which unconditionally formats the full message via `prototext.MarshalOptions{Multiline: false}.Format(m)` with no check of `debug_redact` anywhere in the marshaling path. [2](#0-1) 

### Finding Description
The invariant broken here mirrors the auth0 report: a value explicitly marked as sensitive (there: the `Authorization` header; here: any field annotated `[(google.protobuf.field_options).debug_redact = true]`) is expected to be scrubbed before it reaches a generic "print/log this object" code path, but the actual sanitization step is missing.

- `descriptor.proto`/`descriptorpb` defines `debug_redact` precisely so message authors can flag credential-carrying fields (e.g. OAuth tokens, passwords) for exclusion from debug/log output. [1](#0-0) 
- Every generated message's `fmt.Stringer` implementation (`String()`) — which is what gets invoked implicitly whenever a message is passed to `fmt.Println`, `log.Printf("%v", msg)`, wrapped in an `error`, etc. — routes through `protoimpl.X.MessageStringOf`. [2](#0-1) 
- Searching the entire `encoding/prototext` package (`encode.go`, `decode.go`) and `internal/impl` for any reference to `DebugRedact`/`GetDebugRedact` returns zero matches — the marshaler walks every field and serializes its value with no redaction logic at all. [3](#0-2) 
- The only place in the whole codebase that performs manual sensitive-value redaction is a hand-written example using `protorange.Range` that does ad-hoc string substitution — it is not a built-in enforcement of `debug_redact` and requires the caller to write custom logic for each sensitive string. [4](#0-3) 

So a schema author can mark a field `debug_redact = true` believing the library will honor that annotation and omit it from any debug print, log statement, or error message built from `%v`/`%s` on the message — but protobuf-go's `String()`/`prototext.Format()` prints the raw value regardless.

### Impact Explanation
Any unprivileged request path that ends up logging, error-wrapping, or otherwise stringifying a request/response protobuf message (a very common Go idiom: `log.Printf("received: %v", req)` or wrapping a message in an error) will emit the full plaintext value of fields the schema owner explicitly tagged as sensitive credentials. This is a confidentiality leak of exactly the class the `debug_redact` option was created to prevent — session tokens, API keys, passwords embedded in a proto message — into logs, crash reports, or error responses, directly analogous to the auth0 `Authorization` header leaking into error logs.

### Likelihood Explanation
High for any codebase that already relies on `debug_redact` as documented (the field's own doc comment says "e.g. when the field contains sensitive credentials") and then logs/prints messages using the standard Go `%v`/`String()` convention or `prototext.Format`/`prototext.MarshalOptions.Format`. No attacker input, custom resolver, or malicious peer is needed — the trigger is simply normal application logging of a trusted, schema-defined message that contains a `debug_redact` field.

### Recommendation
Enforce `debug_redact` in `prototext` marshaling (and therefore in `MessageStringOf`/`String()`), and consider similarly plumbing it into `protojson` debug-style output, by checking `fd.Options().(*descriptorpb.FieldOptions).GetDebugRedact()` (or the equivalent enum-value check) for each field before writing its value, substituting a fixed redaction marker in place of the raw value.

### Proof of Concept
```protobuf
syntax = "proto3";
import "google/protobuf/descriptor.proto";

message LoginRequest {
  string username = 1;
  string password = 2 [
    (google.protobuf.field_options) = { debug_redact: true } // hypothetical inline option usage
  ];
}
```
```go
req := &LoginRequest{Username: "alice", Password: "S3cr3tToken!"}
log.Printf("handling request: %v", req)
// Output: handling request: username:"alice"  password:"S3cr3tToken!"
```
Despite `password` being annotated `debug_redact = true`, `req.String()` (via `protoimpl.X.MessageStringOf` → `prototext.MarshalOptions{Multiline:false}.Format`) prints the raw credential because no code path checks `GetDebugRedact()`. [2](#0-1)

// Scan all protobuf string values for a sensitive word and replace it with
// a suitable alternative.
func Example_sanitizeStrings() {
	m := &newspb.Article{
		Author:  "Hermione Granger",
		Date:    timestamppb.New(time.Date(1998, time.May, 2, 0, 0, 0, 0, time.UTC)),
		Title:   "Harry Potter vanquishes Voldemort once and for all!",
		Content: "In a final duel between Harry Potter and Lord Voldemort earlier this evening...",
		Tags:    []string{"HarryPotter", "LordVoldemort"},
		Attachments: []*anypb.Any{{
			TypeUrl: "google.golang.org.KeyValueAttachment",
			Value: mustMarshal(&newspb.KeyValueAttachment{
				Name: "aliases.txt",
				Data: map[string]string{
					"Harry Potter": "The Boy Who Lived",
					"Tom Riddle":   "Lord Voldemort",
				},
			}),
		}},
	}

	protorange.Range(m.ProtoReflect(), func(p protopath.Values) error {
		const (
			sensitive   = "Voldemort"
			alternative = "[He-Who-Must-Not-Be-Named]"
		)

		// Check if there is a sensitive word to redact.
		last := p.Index(-1)
		s, ok := last.Value.Interface().(string)
		if !ok || !strings.Contains(s, sensitive) {
			return nil
		}
		s = strings.Replace(s, sensitive, alternative, -1)

		// Store the redacted string back into the message.
		beforeLast := p.Index(-2)
		switch last.Step.Kind() {
		case protopath.FieldAccessStep:
			m := beforeLast.Value.Message()
			fd := last.Step.FieldDescriptor()
			m.Set(fd, protoreflect.ValueOfString(s))
		case protopath.ListIndexStep:
			ls := beforeLast.Value.List()
			i := last.Step.ListIndex()
			ls.Set(i, protoreflect.ValueOfString(s))
		case protopath.MapIndexStep:
			ms := beforeLast.Value.Map()
			k := last.Step.MapIndex()
			ms.Set(k, protoreflect.ValueOfString(s))
		}
		return nil
	})
