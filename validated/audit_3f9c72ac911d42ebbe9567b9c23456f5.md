### Title
`PoisonMicroblock(h, h)` with an identical header accepted as valid equivocation proof, causing reward slashing without an actual fork - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`)

### Summary
`check_microblock_header_signer` only verifies that the two microblock headers recover to the same public-key hash; it never checks that the two headers are actually distinct. `handle_poison_microblock` accepts whatever `check_microblock_header_signer` returns and unconditionally records a poison report via `insert_microblock_poison`, so a `PoisonMicroblock(h, h)` transaction with `h1 == h2` passes validation trivially even though no equivocation ever occurred.

### Finding Description
The equality that should be enforced is: "poison-microblock is valid IFF there exist **two distinct** microblock headers at the same sequence, signed by the same key" (i.e. `h1 != h2 AND pkh(h1) == pkh(h2)`). The code only checks the second half of that conjunction.

`check_microblock_header_signer` recovers the pubkey hash from each header independently and compares only the hashes: [1](#0-0) 

If `mblock_hdr_1` and `mblock_hdr_2` are the exact same header (byte-for-byte), `pkh1` and `pkh2` are trivially equal since they are computed from identical bytes — no fork or equivocation is required. `handle_poison_microblock` calls this function and, on success, proceeds directly to look up the height for the pubkey hash and insert a poison report, with no additional check that the two input headers differ: [2](#0-1) [3](#0-2) 

The mempool admission path (`will_admit_mempool_tx`) has the same gap: it checks `sequence`, `prev_block`, `version` equality and pubkey-hash equality, but never asserts the two headers are distinct (e.g. via `block_hash()` or full struct inequality): [4](#0-3) 

All existing unit tests that exercise poison-microblock processing explicitly construct two *different* signed microblocks and assert `mblock_1 != mblock_2` before submitting them, e.g.: [5](#0-4) 
No test exists for the same-header (`h==h`) case, and no code path (mempool admission nor `handle_poison_microblock`) rejects it.

### Impact Explanation
If a `PoisonMicroblock` transaction with `mblock_header_1 == mblock_header_2` is accepted, `insert_microblock_poison` records a slashing entry for a miner's `microblock_pubkey_hash` at a real height even though that miner never produced two conflicting microblocks at that sequence. Downstream reward-maturation logic that consults this poison report to forfeit/redirect coinbase (to the reporting principal) would then misattribute reward away from an honest miner who never equivocated — this is a reward-theft / reward-mispayment condition against a specific miner, satisfying the Critical "block-reward theft" category since it results in reward paid to the wrong party based on a false equivocation claim.

### Likelihood Explanation
The precondition is simply that the target miner has a registered `microblock_pubkey_hash` recorded via `insert_microblock_pubkey_hash` within the maturity window (`MINER_REWARD_MATURITY`), which is normal for any active miner who produced at least one microblock. The attacker needs no special stake, no majority position, and no signer key — they only need to duplicate a header they can observe on the wire (or even one they construct with the miner's already-known public microblock pubkey hash, as long as `check_recover_pubkey` succeeds), and submit `PoisonMicroblock(h, h)`. This is fully unprivileged and trivially repeatable against any miner with a valid, seen microblock header.

### Recommendation
Add an explicit distinctness check before (or inside) `check_microblock_header_signer` / `handle_poison_microblock`, e.g. reject when `mblock_header_1.block_hash() == mblock_header_2.block_hash()` (or, more strongly, when the full serialized headers are identical), mirroring the same check that should also be added to the mempool admission path in `will_admit_mempool_tx`.

### Proof of Concept
Rust integration test plan (extending the existing `stackslib/src/chainstate/stacks/db/transactions.rs` poison-microblock test module):
1. Register a real miner's `microblock_pubkey_hash` via `StacksChainState::insert_microblock_pubkey_hash` at some height `H` (as done in `process_poison_microblock_invalid_transaction`).
2. Construct a single signed `StacksMicroblockHeader h` for that miner (one real microblock, no fork).
3. Build `TransactionPayload::PoisonMicroblock(h.clone(), h.clone())` — the identical header on both sides — sign it as a reporter, and call `StacksChainState::process_transaction`.
4. Assert (equality check before/after):
   - Before: no poison report exists for `H` (`get_poison_microblock_report(H)` returns `None`).
   - Expected/desired: the transaction should be rejected (e.g. `Error::InvalidStacksTransaction` with a "headers are identical" message), leaving `get_poison_microblock_report(H)` as `None`.
   - Actual (current code): `process_transaction` succeeds, and `get_poison_microblock_report(H)` returns `Some((reporter_addr, h.sequence))`, proving the miner was slashed with no second, distinct microblock ever existing.
5. Additionally add the same identical-header case to `will_admit_mempool_tx` tests and assert it is rejected with `MemPoolRejection::PoisonMicroblocksDoNotConflict` (currently it is admitted).

    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
