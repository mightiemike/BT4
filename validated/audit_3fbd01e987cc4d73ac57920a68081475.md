### Title
Empty/all-zero-weight signer set makes the 70% signing-weight threshold trivially satisfiable by zero signatures - (File: `stackslib/src/chainstate/stacks/boot/mod.rs`, `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`RewardSet::total_signing_weight()` and `NakamotoBlockHeader::compute_voting_weight_threshold()` do not guard against a total signer weight of zero. If the reward-set-building logic (`make_signer_set`) produces a `Some(vec![])` signer list (distinct from `None`), the "quorum" for block signing collapses to zero, and a block with an empty `signer_signature` vector passes `verify_signer_signatures` unconditionally — the exact equality-breaking pattern described in the Nouns Builder report (quorum() == 0 ⇒ `for < quorum` never true).

### Finding Description
`RewardSet::total_signing_weight` treats `signers() == Some(empty vec)` as a valid, zero-weight set rather than an error: [1](#0-0) 

`NakamotoBlockHeader::compute_voting_weight_threshold` computes `ceil(total_weight * 7 / 10)`, which is `0` when `total_weight == 0`: [2](#0-1) 

`verify_signer_signatures` only rejects if `total_weight_signed < threshold`; with `threshold == 0` and zero signatures (`total_weight_signed == 0`), `0 < 0` is `false`, so the block is accepted as validly signed: [3](#0-2) 

The root cause producing a `Some(vec![])` reward set is the legacy floor-and-drop `make_signer_set` (used for pre-PoX-5 reward cycles), which filters out any entry whose `stacked_amt / threshold` floors to `0`, but only returns `None` when the *input* `entries` list is empty — not when every entry floors to weight `0`: [4](#0-3) 

Notably, this exact failure mode was independently identified and *fixed* for PoX-5 via a "Hare / largest-remainder" apportionment (`pox_5_make_signer_set`) that guarantees every retained signer has `weight >= 1`, explicitly citing the old bug: "the old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every signer's weight floored to 0 and the entire set was dropped": [5](#0-4) 

This confirms the bug class is real and reachable in this codebase; the open question (which I could not fully verify given tool-call limits) is whether the legacy `make_signer_set` path in `boot/mod.rs` is still reachable for any currently-active reward cycle/epoch, or whether it has been fully superseded by `pox_5_make_signer_set` everywhere a `RewardSet` is committed on-chain. I was unable to complete tracing every call site of `make_signer_set` before the session ended.

### Impact Explanation
If a reward set with `signers = Some(vec![])` (or, more subtly, a set whose surviving weight sums to `0`) is ever committed as the canonical reward set for a cycle, `verify_signer_signatures` — the sole gate that a Nakamoto block has legitimate stacker/signer approval — becomes a no-op: any miner could produce a block with zero signer signatures and have it accepted as validly signed network-wide. This is a wrongful-accept of an unsigned block, i.e., a Critical-class equality break (an invalid block accepted network-wide), since the signer-approval invariant (`total_weight_signed >= threshold`) is defeated by the divide/floor producing `threshold == 0`.

### Likelihood Explanation
Triggering this requires the aggregate stacked amount across signers to be small/skewed enough relative to the derived reward-slot quota (`threshold = stacked_amt / reward_slots` style division) that every individual entry's weight floors to zero under the legacy scheme — a low-total-stake condition analogous to the Nouns Builder "low token supply" trigger, and plausible during PoX-4-and-earlier reward cycles or in low-participation Testnets/regtest/early mainnet cycles. It does not require majority collusion — it can occur from ordinary low aggregate participation. Likelihood is Medium-to-High if the legacy path remains reachable; it is a non-issue if PoX-5's Hare apportionment has fully replaced it for all commit paths — which I could not confirm.

### Recommendation
- In `RewardSet::total_signing_weight`, treat `signers() == Some(vec![])` the same as `None` (return an error) so `total_weight == 0` cannot silently occur.
- In `compute_voting_weight_threshold`, reject/round `total_weight == 0` to a threshold that can never be satisfied by zero signatures (e.g., return an error rather than `0`), or require `total_weight > 0` upstream when constructing/loading a `RewardSet` for block-signing purposes.
- Audit and remove (or hard-error) any remaining callers of the legacy `make_signer_set` (`boot/mod.rs:1020`) that could still produce a `Some(vec![])` signer list for any epoch/PoX version still supported by mainnet nodes, applying the same "largest remainder, weight ≥ 1" fix that PoX-5's `pox_5_make_signer_set` already uses.

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
    }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
