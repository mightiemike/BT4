### Title
Write-method feature-gate check occurs after replay-guard digest consumption, allowing DoS via digest exhaustion - ([File: core/services/gateway/handlers/vault/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` calls `h.requestProcessor.ProcessRequest` before dispatching to method-specific handlers, and `ProcessRequest` (via `authorizeAndStamp`) authorizes the request and records its replay-guard digest as a side effect of `Authorizer.AuthorizeRequest`. The `h.writeMethodsEnabled.AllowErr(ctx)` gate check that determines whether secret-write methods are even enabled is only performed later, inside `handleSecretsCreate`/`handleSecretsUpdate`/`handleSecretsDelete`. This lets an unprivileged caller consume a legitimate one-time allowlisted digest even though the request is ultimately rejected for an unrelated reason (write methods disabled), permanently blocking the legitimate owner's future valid retry with that digest.

### Finding Description
In `core/services/gateway/handlers/vault/handler.go`, `HandleJSONRPCUserMessage` performs the following sequence for `MethodSecretsCreate`/`Update`/`Delete`:
1. `authorized, err := h.requestProcessor.ProcessRequest(ctx, &req, cachedPublicKey)` [1](#0-0) 
2. Then dispatches to `h.handleSecretsCreate(ctx, ar)` etc. [2](#0-1) 

`ProcessRequest` routes to `processCreateSecretsRequest`, which calls `authorizeAndStamp`, which in turn calls `p.authorizer.AuthorizeRequest(ctx, *req)` — per the processor's own documented pipeline invariant, this authorization step "also applies the replay guard (digest deduplication)" [3](#0-2) , and only after that mutates `req.ID`/`req.Params` (owner-prefixing/stamping) [4](#0-3) . The replay guard itself is a one-shot digest consumer: `CheckAndRecord` returns `ErrRequestAlreadySeen` on any subsequent call with the same digest and otherwise permanently records it until expiry [5](#0-4) .

Only after this authorization/replay-recording step succeeds does `handleSecretsCreate` check `h.writeMethodsEnabled.AllowErr(ctx)`, and if write methods are disabled, it responds with `api.UnsupportedMethodError` without ever forwarding the request to vault nodes [6](#0-5) . The gate is backed by `cresettings.Default.GatewayVaultManagementEnabled`, an operator-controlled feature flag independent of any specific request's validity [7](#0-6) .

Because the digest is consumed before the feature-gate check runs, a request submitted while writes are disabled still burns the one-time digest even though it is rejected for an unrelated reason (the gate, not authorization). This violates the invariant that authorization/replay state should not be mutated by requests that are ultimately rejected for reasons unrelated to authorization.

### Impact Explanation
An unprivileged actor who can observe or reconstruct a valid allowlisted digest (e.g., from a publicly-readable workflow spec, as stated in the precondition) can submit a `MethodSecretsCreate`/`Update`/`Delete` request while the administrator has `GatewayVaultManagementEnabled` disabled. This silently consumes the legitimate owner's one-time digest. When the administrator later re-enables write methods, the legitimate owner's retry with the same (correct, non-replayed) request is incorrectly rejected with `ErrRequestAlreadySeen`, denying them the ability to create/update/delete their own secret. This is a denial-of-service against legitimate secret-write operations, matching a "DoS of protocol functionality" class of impact.

### Likelihood Explanation
Feasibility depends on the DON/gateway operator having write methods disabled at some point (an administrative/maintenance state, not attacker-controlled) and on the attacker knowing a valid digest tied to a workflow they don't own. The prompt states this precondition is met (a public workflow spec observable by the attacker). Given that, the exploit path requires only a single unauthenticated-content JSON-RPC submission through the normal gateway ingress — no privilege escalation, no signature forgery, and it is fully reproducible/deterministic given the stated preconditions.

### Recommendation
Move the `h.writeMethodsEnabled.AllowErr(ctx)` gate check in `handler.go` to occur before `h.requestProcessor.ProcessRequest` is invoked for write methods (`MethodSecretsCreate`/`Update`/`Delete`), i.e., check the feature gate immediately after determining `req.Method` and before any authorization/replay-guard side effects occur. Alternatively, restructure `ProcessRequest`/`authorizeAndStamp` so the replay-guard digest is only committed (not just checked) after all gating decisions — including the write-methods-enabled check — have succeeded, so that requests rejected for gate reasons never mutate replay state.

### Proof of Concept
Integration test in `core/services/gateway/handlers/vault` (extending `handler_test.go`):
1. Construct a `handler` with `cresettings.Default.GatewayVaultManagementEnabled` gate forced to `false` via the `limitsFactory`/`writeMethodsEnabled` test hook.
2. Build a valid `MethodSecretsCreate` JSON-RPC request with a legitimate allowlisted digest/auth for a known owner.
3. Call `h.HandleJSONRPCUserMessage(ctx, req, callback)`; assert the callback response has `ErrorCode == api.UnsupportedMethodError` (confirms the gate rejected it).
4. Re-enable the write-methods gate (flip the gate limiter to allow).
5. Resubmit the identical request (same digest/ID/params) via `HandleJSONRPCUserMessage`.
6. Assert expected behavior: the retry should succeed and be forwarded to vault nodes (`fanOutToVaultNodes` called) — but currently it fails, returning an authorization error because `p.authorizer.AuthorizeRequest`'s embedded replay guard raises `ErrRequestAlreadySeen` from step 2's earlier `CheckAndRecord` call, demonstrating the digest was consumed despite the request being rejected purely due to the disabled write-methods gate.

func (h *handler) handleSecretsCreate(ctx context.Context, ar *activeRequest) error {
	l := logger.With(h.lggr, "method", ar.req.Method, "requestID", ar.req.ID)

	err := h.writeMethodsEnabled.AllowErr(ctx)
	if errors.Is(err, limits.ErrorNotAllowed{}) {
		l.Warnw("secrets write method called but write methods are disabled", "error", err)
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.UnsupportedMethodError, errors.New("vault write methods(create/update/delete) are disabled: "+err.Error()), nil))
	} else if err != nil {
		l.Errorw("error checking if write methods are enabled", "error", err)
		return h.sendResponse(ctx, ar, h.errorResponse(ar.req, api.FatalError, errors.New("error checking if write methods are enabled: "+err.Error()), nil))
	}

	return h.fanOutToVaultNodes(ctx, l, ar)
}

func (p *GatewayVaultRequestProcessor) authorizeAndStamp(
	ctx context.Context,
	req *jsonrpc.Request[json.RawMessage],
	stamp func(prefixedRequestID string) error,
) (*AuthorizedGatewayVaultRequest, error) {
	incomingOwner := ""
	if idx := strings.Index(req.ID, vaulttypes.RequestIDSeparator); idx != -1 {
		incomingOwner = req.ID[:idx]
	}

	p.lggr.Debugw("authorizing gateway vault request", "method", req.Method, "requestID", req.ID)
	authResult, err := p.authorizer.AuthorizeRequest(ctx, *req)
	if err != nil {
		authErr := fmt.Errorf("request not authorized: %w", err)
		p.lggr.Errorw("gateway vault request authorization failed", "method", req.Method, "requestID", req.ID, "hasAuth", req.Auth != "", "incomingOwner", incomingOwner, "error", authErr)
		return nil, authErr
	}

	originalRequestID := req.ID
	authorizedOwner := authResult.AuthorizedOwner()
	prefixedRequestID := authorizedOwner + vaulttypes.RequestIDSeparator + originalRequestID
	req.ID = prefixedRequestID

	if err := stamp(prefixedRequestID); err != nil {
		p.lggr.Errorw("failed to stamp authorized request params", "method", req.Method, "requestID", req.ID, "error", err)
		return nil, fmt.Errorf("failed to stamp authorized request params: %w", err)
	}

	p.lggr.Debugw("authorized gateway vault request", "method", req.Method, "requestID", req.ID, "owner", authorizedOwner, "orgID", authResult.OrgID(), "workflowOwner", authResult.WorkflowOwner())
	return &AuthorizedGatewayVaultRequest{
		Req:        *req,
		AuthResult: authResult,
	}, nil
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}
