### Title
Gateway logs full raw transaction (calldata, proof_facts, signature) at `debug` level, defeating the privacy-pool confidentiality guarantee - (File: crates/apollo_gateway/src/gateway.rs)

### Summary
The Spinnaker/Rosco advisory is about secrets/sensitive data being written to logs without proper masking. In this sequencer, `GenericGateway::add_tx` logs the entire incoming `RpcTransaction` (including `calldata`, `proof_facts`, and `signature`) via `Debug` formatting, unmasked, for every transaction an unprivileged sender submits. Elsewhere in the same codebase this exact data is explicitly treated as confidential ("transaction calldata is private user data per the privacy-pool threat model") and is deliberately excluded from HTTP-level request logs, but the gateway's own logging path bypasses that protection entirely.

### Finding Description
`GenericGateway::add_tx` unconditionally logs the full transaction object before any privacy-sensitive handling occurs: [1](#0-0) 

This is directly attacker/sender-reachable: any account can submit an `RpcTransaction::Invoke(V3)` with non-empty `proof_facts`/`proof` — the "private transaction" / client-side-proving / privacy-pool path recognized elsewhere in the gateway: [2](#0-1) 

The codebase explicitly treats this exact data (`calldata`, and by extension `proof_facts`/`signature` of privacy-pool transactions) as sensitive and designs other logging layers to avoid leaking it, e.g. the transaction prover's request logger: [3](#0-2) 

and the "privacy-pool `apply_actions`" transaction type / `SNOS` proof-facts machinery whose whole purpose is confidentiality of the underlying transaction contents: [4](#0-3) [5](#0-4) 

The repository even has a dedicated `Sensitive<T>` wrapper (used for config secrets/URLs) whose entire purpose is to prevent exactly this class of bug — accidental leakage through `Debug`/`Display`/serialization: [6](#0-5) 

but this redaction primitive is not applied to the transaction payload path in `apollo_gateway`. In addition, a second gateway log line also prints the raw tx `signature` on error/return paths: [7](#0-6) 
which is likewise unmasked when constructing internal errors (`internal_with_signature_logging`).

### Impact Explanation
This causes exposure of transaction content that the system's own threat model classifies as private (privacy-pool/client-side-proving calldata, proof facts, and signatures) to node operators' logs/observability pipelines, at debug level, for every single transaction processed by the gateway — not just failures. Because Grafana dashboards and log queries in this repo are built directly around the string "Processing tx" (e.g. `"log_query": "\"Processing tx\" AND \"is_p2p=\""`), this data is expected to flow into centralized logging/monitoring infrastructure, widening exposure beyond a single node's disk. This is a confidentiality violation of the privacy-pool guarantee, matching the "C:L" component of the referenced CVE (improper masking of sensitive data in logs), reachable purely by submitting a normal transaction — no privileged operator/proposer access required.

### Likelihood Explanation
High likelihood of occurrence: the log statement fires unconditionally on every call to `add_tx` for every transaction type, with no filtering of private/proof-bearing transactions. The only mitigating factor is that `debug!` may be filtered out depending on the deployed log level configuration, but debug-level tracing is commonly enabled in staging/debugging and is explicitly wired into dashboards/log queries in this repo, so it is a realistic, low-friction path to exposure rather than a purely theoretical one. It requires no bypass of validation and works with a plain, self-crafted `Invoke V3` transaction carrying `proof_facts`.

### Recommendation
- Do not `Debug`-format the whole `RpcTransaction` in `add_tx`; log only non-sensitive identifiers (tx type, tx hash once computed, `is_p2p`).
- Wrap or redact `calldata`, `proof_facts`, `proof`, and `signature` fields (similar to the existing `Sensitive<T>` pattern in `apollo_config::secrets`) before they can reach any `Debug`/`tracing` sink, or gate detailed payload logging behind a compile-time/feature-flag that is explicitly documented as privacy-breaking and disabled in production.
- Apply the same treatment to `StarknetError::internal_with_signature_logging`, which also logs raw transaction signatures.
- Add a regression test (mirroring the existing `record_region_gateway_failing_tx` test in `apollo_http_server`) asserting that `logs_contain(...)` does not match calldata/proof_facts/signature content for private (proof-bearing) transactions processed through the gateway.

### Proof of Concept
1. Submit a normal `RpcTransaction::Invoke(V3)` transaction to the gateway's `add_tx` with non-empty `proof_facts`/`proof` (a legitimate privacy-pool / client-side-proving transaction, as constructed by `invoke_args_with_client_side_proving()` in the gateway tests).
2. Observe that `GenericGateway::add_tx` executes `debug!("Processing tx: {:?}", &tx)` before any validation, printing the full transaction — including `calldata`, `proof_facts`, and `signature` — to the node's log stream.
3. If the deployment runs with `debug` tracing enabled (as supported by the repo's tracing/log configuration and referenced directly in Grafana `log_query` fields), this data is now present in centralized logs/log-based dashboards, defeating the confidentiality property the privacy-pool feature is designed to provide.

    pub async fn add_tx(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        debug!("Processing tx: {:?}", &tx);
        let tx_signature = tx.signature().clone();
        let is_p2p = p2p_message_metadata.is_some();

        let start_time = std::time::Instant::now();
        let ret = self.add_tx_inner(tx, p2p_message_metadata).await;
        let elapsed = start_time.elapsed().as_secs_f64();

        debug!(
            "Processed tx with signature: {:?}. duration: {elapsed} sec, ret: {ret:?}, is_p2p: \
             {is_p2p}",
            &tx_signature,
        );
