### Title
Webhook `X-Shopify-Shop-Domain` header is never validated against the myshopify.com allowlist, allowing an attacker who possesses one valid webhook HMAC to spoof `check.domain` and load another shop's offline session - ([File: packages/apps/shopify-api/lib/webhooks/validate.ts])

### Summary
`checkWebhooksHeaders`/`checkEventsHeaders` copy the raw `X-Shopify-Shop-Domain` header straight into `check.domain` without ever calling `sanitizeShop`/`sanitizeHost`, and the HMAC validated in `validateHmacFromRequestFactory` covers only `rawBody`, not this header. Downstream consumers (e.g. `authenticateWebhookFactory` in `shopify-app-remix`/`shopify-app-react-router`) pass `check.domain` directly into `ensureValidOfflineSession(params, check.domain)` to look up and return an offline session/admin client, so a forged domain can cause the library to load and hand back a different shop's session.

### Finding Description
`checkWebhooksHeaders` and `checkEventsHeaders` build the returned `fields.domain` directly from the `X-Shopify-Shop-Domain` header with no format check: `const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders); ... domain: domain!` [1](#0-0)  Unlike `shopify.utils.sanitizeShop`/`sanitizeHost`, which enforce the `myshopify.com|shopify.com|myshopify.io|shop.dev`/`spin.dev` suffix allowlist [2](#0-1) , no such check exists on the webhook domain path.

Critically, the HMAC that is verified before this header is even read only signs `rawBody`: `const validHmac = await validateHmacString(config, rawBody, hmac, HashFormat.Base64);` [3](#0-2)  The `X-Shopify-Shop-Domain` header is not part of the signed material at all, so once `validate()` succeeds it returns `{valid: true, ...fields}` with `domain` taken verbatim from an unauthenticated header [4](#0-3) .

Downstream, `authenticateWebhookFactory` trusts this value directly to load a session: `const session = await ensureValidOfflineSession(params, check.domain);` and exposes `shop: check.domain` plus an `admin` client built from whatever session is returned [5](#0-4) . `ensureValidOfflineSession` → `createOrLoadOfflineSession` uses this shop string as the session-storage key (`api.session.getOfflineId(shop)` then `sessionStorage.loadSession(...)`) with no re-validation against the allowlist [6](#0-5) .

Exploit flow: An attacker who is a legitimate merchant with the target app installed on their own store receives real Shopify-signed webhooks for their own shop (a normal, unprivileged interaction — no `apiSecretKey` needed). Because the domain header is outside the HMAC's signed content, the attacker can replay that same body+HMAC to the app's webhook endpoint while substituting `X-Shopify-Shop-Domain` with a different, arbitrary shop domain (e.g. a known target `victim-store.myshopify.com`). `validateHmacFromRequestFactory` still succeeds (body/HMAC pair unchanged), and `checkWebhooksHeaders` never checks that the domain header is a syntactically valid, allowlisted `myshopify.com` domain, so `check.domain` becomes `victim-store.myshopify.com`. The webhook handler then receives `admin`/`session` scoped to the victim shop's stored offline session instead of the attacker's own shop.

### Impact Explanation
This lets an attacker who legitimately installed the app on shop A obtain a live `admin` GraphQL/REST client and offline `session` object for an arbitrary other shop that also has the app installed and a stored session — i.e., cross-tenant session/access-token misuse triggered entirely by an unprivileged app user, matching Shopify's "cross-tenant data access" / "authentication bypass leading to another merchant's session" bounty class. The concrete data exposure depends on what the app's registered webhook handler does with the resulting `session`/`admin` (a host-app concern), but the library itself fails to authenticate the shop-identifying header it hands to consumers as trusted.

### Likelihood Explanation
Preconditions: the attacker must (1) have the target app installed on a shop they control so they can capture a body+HMAC pair for a topic the app subscribes to, and (2) know or guess a target shop's `myshopify.com` domain (often discoverable/public). No secret key, MITM, or privileged role is required — this is squarely within the "unprivileged merchant sending crafted requests" threat model. The attack is fully repeatable (same captured body/HMAC pair can be replayed against many guessed domains) and doesn't require timing or race conditions.

### Recommendation
In `checkWebhooksHeaders`/`checkEventsHeaders` (`packages/apps/shopify-api/lib/webhooks/validate.ts`), validate the `domain` header with `sanitizeShop` (or an equivalent allowlist regex) before returning it, rejecting the webhook as invalid if it doesn't match. Additionally, consider incorporating the domain header into the HMAC-signed payload comparison where the Shopify webhook contract allows it, so the shop identity can't be swapped independently of the signed body.

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/webhooks/__tests__/validate-domain-spoof.test.ts
import {shopifyApi, LogSeverity} from '../../..';
import {testConfig} from '../../__tests__/test-config';
import * as ShopifyHeader from '../../types';

test('validate() returns unvalidated arbitrary domain header', async () => {
  const shopify = shopifyApi(testConfig());
  const rawBody = JSON.stringify({id: 1});

  // Compute a real HMAC the way Shopify would, using the *test* secret we control
  // (simulating a webhook the attacker legitimately received for their own shop)
  const crypto = require('crypto');
  const hmac = crypto
    .createHmac('sha256', shopify.config.apiSecretKey)
    .update(rawBody, 'utf8')
    .digest('base64');

  const headers = {
    'X-Shopify-Topic': 'orders/create',
    'X-Shopify-Hmac-Sha256': hmac,
    'X-Shopify-Shop-Domain': 'evil.com', // not a *.myshopify.com domain
    'X-Shopify-Api-Version': '2024-01',
    'X-Shopify-Webhook-Id': 'abc123',
  };

  const result = await shopify.webhooks.validate({
    rawBody,
    rawRequest: {headers, method: 'POST', url: '/webhooks'} as any,
  });

  expect(result.valid).toBe(true);
  expect((result as any).domain).toBe('evil.com'); // never sanitized/allowlist-checked
});
```
Expected (current, buggy) result: `valid: true` and `domain === 'evil.com'`, proving `check.domain` is passed through without ever calling `sanitizeShop`/`sanitizeHost`, confirming the finding.

export function sanitizeShop(config: ConfigInterface) {
  return (shop: string, throwOnInvalid = false): string | null => {
    let shopUrl = shop;
    const domainsRegex = [
      'myshopify\\.com',
      'shopify\\.com',
      'myshopify\\.io',
      'shop\\.dev',
    ];

    // Add domains from transformations (both source and target)
    if (config.domainTransformations) {
      domainsRegex.push(...getTransformationDomains(config));
    }

    const shopUrlRegex = new RegExp(
      `^[a-zA-Z0-9][a-zA-Z0-9-_]*\\.(${domainsRegex.join('|')})[/]*$`,
    );

    const shopAdminRegex = new RegExp(
      `^admin\\.(${domainsRegex.join('|')})/store/([a-zA-Z0-9][a-zA-Z0-9-_]*)$`,
    );

    const isShopAdminUrl = shopAdminRegex.test(shopUrl);
    if (isShopAdminUrl) {
      shopUrl = shopAdminUrlToLegacyUrl(shopUrl) || '';
    }

    const sanitizedShop = shopUrlRegex.test(shopUrl) ? shopUrl : null;
    if (!sanitizedShop && throwOnInvalid) {
      throw new InvalidShopError('Received invalid shop argument');
    }

    if (sanitizedShop && config.domainTransformations) {
      return applyDomainTransformations(sanitizedShop, config);
    }

    return sanitizedShop;
  };
}

import {AppDistribution, BasicParams} from '../types';

export async function createOrLoadOfflineSession(
  {api, config, logger}: BasicParams,
  shop: string,
) {
  if (config.distribution === AppDistribution.ShopifyAdmin) {
    logger.debug('Creating custom app session from configured access token', {
      shop,
    });
    return api.session.customAppSession(shop);
  } else {
    logger.debug('Loading offline session from session storage', {shop});
    const offlineSessionId = api.session.getOfflineId(shop);
    const session = await config.sessionStorage!.loadSession(offlineSessionId);

    return session;
  }
