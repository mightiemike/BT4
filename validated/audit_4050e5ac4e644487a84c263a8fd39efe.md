### Title
App-proxy HMAC binds to an ambiguous, delimiter-less parameter serialization, allowing signature reuse across distinct parameter sets - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
`stringifyQueryForAppProxy` concatenates sorted `key=value` pairs with no separator between them, so two structurally different query dictionaries can serialize to the identical string and therefore produce an identical HMAC. Because `validateHmac` only re-derives this ambiguous string and compares it via `safeCompare`, a signature that Shopify (or `generateLocalHmac`) computed for one parameter set will also validate a different, attacker-chosen parameter set that collides under this serialization.

### Finding Description
`stringifyQueryForAppProxy` builds the signing input as: [1](#0-0) 
with no `&` or other delimiter between `key=value` pairs, unlike `stringifyQueryForAdmin`, which uses `ProcessedQuery.stringify(true)` (delimited).

Because pair boundaries are only inferable from the key names, a value that contains characters resembling `key=value` text can absorb an entire adjacent pair. For example:
- `{ p: '1', q: '23', timestamp: T }` → sorted keys `p, q, timestamp` → `"p=1" + "q=23" + "timestamp=T"` = `"p=1q=23timestamp=T"`
- `{ p: '1q=23', timestamp: T }` → sorted keys `p, timestamp` → `"p=1q=23" + "timestamp=T"` = `"p=1q=23timestamp=T"`

Both strings are byte-identical, so `generateLocalHmac` produces the same HMAC for both dictionaries: [2](#0-1) 

`validateHmac` then accepts either representation as long as `safeCompare` matches: [3](#0-2) 

`normalizeQuery` only prevents duplicate occurrences of `hmac`/`shop`/`signature`/`timestamp`; it does not prevent arbitrary custom keys/values from colliding under concatenation: [4](#0-3) 

Since this is exactly the algorithm Shopify itself uses to sign real app-proxy requests, an unprivileged storefront visitor can request the proxy URL with a param set that produces a colliding canonical string (e.g. `?p=1&q=23&timestamp=T`), causing Shopify to genuinely sign that string with the real `apiSecretKey`. That same `signature` value can then be replayed directly against the app's backend endpoint with a *different* parameter set that serializes identically (e.g. `?p=1q%3D23&timestamp=T`, omitting `q` entirely and embedding merged/attacker-controlled content in `p`). `validateHmac` will accept it because the serialized signing input is identical, even though the actual request the app receives is not the one Shopify signed.

### Impact Explanation
This breaks the core invariant that a valid app-proxy signature binds unambiguously to the exact parameter set the app receives (CWE-347: Improper Verification of Cryptographic Signature due to canonicalization ambiguity). It enables app-proxy parameter/request forgery: an app trusting "signature valid ⇒ this exact query came from Shopify" can be fed a colliding, attacker-crafted parameter set (e.g. missing expected params, or values merged with attacker-chosen substrings) that still passes verification, potentially bypassing app-side authorization/business logic that depends on the presence or exact value of specific parameters.

### Likelihood Explanation
The attacker needs only: (1) to be able to trigger a legitimately-signed proxy request with a colliding-serialization parameter set (fully unprivileged, e.g. crafting the query string on the storefront proxy URL themselves), and (2) the ability to send an HTTP request directly to the app's backend URL, reusing the captured `signature` and `timestamp` (valid for 90 seconds per `validateHmacTimestamp`). No secret, no privileged role, and no non-default configuration are required. The main constraint is timing (the reused signature is only valid within the timestamp tolerance window) and knowledge of the app's real backend URL, which is standard for app-proxy-based apps.

### Recommendation
Change `stringifyQueryForAppProxy` to use an unambiguous, length-prefixed or delimiter-based canonical encoding (e.g., include `&` between pairs and percent/escape any literal `&`/`=` inside values, or use a canonical form like `JSON.stringify` of a sorted array of `[key, value]` tuples) so that no two distinct parameter dictionaries can serialize to the same signing input.

### Proof of Concept
```ts
import {generateLocalHmac, validateHmac} from '../hmac-validator';
// config with any apiSecretKey

test('colliding app-proxy query dictionaries produce the same HMAC', async () => {
  const config = { apiSecretKey: 'secret' } as any;
  const timestamp = String(Math.trunc(Date.now() / 1000));

  const legit = {p: '1', q: '23', timestamp};
  const forged = {p: '1q=23', timestamp};

  const sig = await generateLocalHmac(config)(legit, 'appProxy');

  // Same signature validates a structurally different parameter set
  const isValid = await validateHmac(config)(
    {...forged, signature: sig},
    {signator: 'appProxy'},
  );

  expect(isValid).toBe(true); // demonstrates signature reuse across colliding dictionaries
});
```

function stringifyQueryForAppProxy(query: AuthQuery): string {
  return Object.entries(query)
    .sort(([val1], [val2]) => val1.localeCompare(val2))
    .reduce((acc, [key, value]) => {
      return `${acc}${key}=${Array.isArray(value) ? value.join(',') : value}`;
    }, '');
}

  return async (

    signator: HMACSignator = 'admin',

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}
