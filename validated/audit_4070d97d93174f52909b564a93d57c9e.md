Based on the report's core bug pattern — a state-write path that trusts an unvalidated input value (an address/class-hash) without independently re-verifying it before committing it into protocol state — there is a concrete analog in this repository's Starknet OS syscall implementation for `replace_class`.

### Title
Starknet OS `execute_replace_class` commits an unverified, possibly-undeclared class hash into the state diff, unlike the Blockifier's enforcement path - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Blockifier (the actual Rust execution engine used to build blocks) enforces that a class hash passed to the `replace_class` syscall must correspond to an already-declared (and Cairo1) class before it is written to a contract's state entry. [1](#0-0)  The equivalent Starknet OS (Cairo) implementation of the same syscall, however, does not perform this check at all — it is explicitly flagged with an unresolved `TODO` and directly writes the caller-supplied `class_hash` into `contract_state_changes` for the calling contract's own address. [2](#0-1) 

### Finding Description
`replace_class` is invoked via a normal `replace_class_syscall` from any contract during ordinary transaction execution — this is fully reachable by any unprivileged transaction sender, matching the reachability criteria (comparable to how the external report's `onInstall` was reachable through any permissive executor call). [3](#0-2) 

In the Blockifier's real execution path, `replace_class` calls `self.state.get_compiled_class(class_hash)?` to ensure the class is declared and rejects Cairo0 class hashes, before mutating the contract's class hash: [1](#0-0) 

This is confirmed by the negative-flow test, which shows the Blockifier reverting with "is not declared" for an arbitrary class hash. [4](#0-3) 

In the Starknet OS's Cairo implementation of the same syscall (used for independent re-execution / proof generation of the block, i.e., "Starknet OS re-execution"), the analogous check is missing — the code takes `request.class_hash` verbatim from the syscall request and writes it into the contract's new `StateEntry`, with only a comment acknowledging the gap: [5](#0-4) 

The deprecated Cairo0 syscall handler (`deprecated_execute_syscalls.cairo`) has the identical gap — no declared-class verification before the `dict_update` that commits the new class hash. [6](#0-5) 

Since the entire purpose of the Starknet OS is to independently and redundantly re-derive/verify every state transition rule that the Blockifier is supposed to enforce (this redundancy is the basis of the STARK proof's soundness — the OS must not blindly trust that the Blockifier-produced trace obeyed all consensus rules), omitting this check means the OS accepts and commits a `class_hash` value into the state diff (and ultimately into the Patricia class-hash tree / state commitment) without verifying that class was ever declared.

### Impact Explanation
If a class-hash replacement to an undeclared/non-existent class hash is ever committed by the OS without validation, the resulting contract's class hash entry — and therefore the state root / committed class commitment produced by OS re-execution — would not match what a fully rule-enforcing node (the Blockifier) would have produced or accepted. This is a "wrong committed root" / "honest-node divergence" class impact: it undermines the guarantee that the STARK proof of block execution independently enforces every state-transition rule rather than trusting the prover-supplied trace. Because `replace_class` operates on the calling contract's own storage address (self-scoped, analogous to the "self-binding" fix recommended in the report), the blast radius is at least one contract's class binding, but since class hash feeds directly into the committed state root, any acceptance of an unvalidated value threatens block-level state-commitment correctness.

### Likelihood Explanation
Reachability is trivial and permissionless: any contract, called by any transaction sender, can invoke `replace_class_syscall(class_hash)` with an arbitrary felt value. [3](#0-2)  The check is missing specifically and only in the OS Cairo path, which is exactly the redundant, from-scratch verification layer meant to catch exactly such omissions; the code contains an explicit self-acknowledged `TODO(Yoni, 1/1/2026)` confirming the gap is currently unaddressed. [7](#0-6) 

### Recommendation
Add an explicit declared-class check in the OS's `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` handler), mirroring the Blockifier's `get_compiled_class` verification, before writing the new `StateEntry` into `contract_state_changes`. This restores parity between the Blockifier's enforcement and the OS's independent re-verification, matching the report's underlying principle that a state-mutating action must be validated at the layer that ultimately commits it, rather than trusted from an external caller/trace.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
