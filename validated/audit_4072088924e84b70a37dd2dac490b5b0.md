Starknet OS `replace_class` syscall omits the "class must be declared" invariant enforced by the Rust blockifier, allowing state-transition divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Rust `blockifier`, which is the actual execution engine the sequencer uses to build blocks, enforces an invariant on the `replace_class` syscall: the target `class_hash` must reference a **declared** class (and be Cairo1) before a contract's class hash can be swapped. This is enforced in `syscall_base.rs::replace_class` [1](#0-0) , in the deprecated syscall handler [2](#0-1) , and is regression-tested (`is not declared`) [3](#0-2) .

However, the Cairo implementation of the same syscall inside the Starknet OS program (used for re-execution/proving of the block, i.e. SNOS) does **not** enforce this invariant — it contains an explicit TODO acknowledging the missing check: [4](#0-3) 

```
    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
```

The deprecated (Cairo0) syscall path in the OS has the identical gap [5](#0-4) .

### Finding Description
This is the same bug class as the external report: an off-chain/other-layer value (there: oracle-reported `stoppedValidatorCounts`; here: the state entry produced during OS re-execution) is used and committed to the canonical state (there: to compute `preExitingBalance`/`activeCount`; here: to compute the new `class_hash` written into `contract_state_changes`, which flows into the state commitment/Patricia tree and ultimately the block's state root) **without enforcing an invariant that the other execution path (the actual blockifier) does enforce**.

Concretely: any unprivileged contract can invoke the `replace_class` syscall with an arbitrary, undeclared `class_hash` felt value as part of a normal transaction. In blockifier execution (the sequencer's actual state-transition function), this transaction reverts with `UndeclaredClassHash`/`is not declared`, so no state change occurs and no such class hash is ever placed in the state diff that the sequencer commits. But the OS's Cairo re-implementation of the same syscall — which recomputes/validates the state transition (`contract_state_changes`) that is committed into the Patricia tree and used to derive the state/global root during proving/re-execution — accepts the request unconditionally and installs the new (potentially non-existent) `class_hash` into `StateEntry`.

Because the invariant "class hash written to state must correspond to a declared class" is enforced only in one of the two independent implementations of the same state-transition logic, the two paths can diverge on transactions that exercise `replace_class` with an undeclared hash: blockifier rejects/reverts, OS silently accepts and commits a state entry with an undeclared class hash to the trie. This mirrors the report's root cause precisely — "the function does not enforce [an] invariant... signal/state can be manipulated" because the value is used/stored before the invariant is checked on-chain (or, here, in the canonical re-execution logic).

### Impact Explanation
If the OS accepts and commits a class-hash update that the sequencer's blockifier would have rejected, this yields either (a) a state root/committed root computed by the OS that does not match the state root the sequencer actually committed for the block (honest-node/re-execution divergence), or (b) a class hash entry in the committed contract-state trie that is not backed by any declared class, meaning future calls to that contract would themselves be undefined/inconsistent (a contract silently becomes "bricked" or points at code that was never declared, which is an unauthorized/incorrect account-state action). Either outcome falls squarely into "wrong committed root or block hash" / "honest-node divergence" categories called for in the validation rules.

### Likelihood Explanation
Reachability is trivial and requires no privileged role: any contract that exposes (or can be tricked into calling) the `replace_class` syscall with attacker-supplied calldata can trigger it — the deprecated_class.json feature-contract test artifacts already expose a generic `test_replace_class(class_hash)` entry point that takes the class hash directly from calldata [6](#0-5) . No governance, operator, or prover privilege is needed — it is exactly the class of "single submitted transaction from an unprivileged sender" that this scan is scoped to accept.

### Recommendation
Add the same "class must be declared" check to the OS's Cairo `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` that the Rust `syscall_base.rs::replace_class` performs, before writing the new `StateEntry`/updating `contract_state_changes`. This should mirror the blockifier's check (verify the class hash is declared and is Cairo1 before allowing the replacement) so both execution paths enforce identical invariants and cannot diverge on this syscall.

### Proof of Concept
1. Deploy/exercise a contract exposing a `replace_class`-invoking entry point (e.g. the pattern in `test_replace_class`, taking `class_hash` as calldata) as an ordinary unprivileged sender.
2. Call it with a `class_hash` felt that has never been declared on-chain.
3. In blockifier (the sequencer's real execution), the transaction reverts with `UndeclaredClassHash` — confirmed by the existing test [3](#0-2) .
4. Feed the same transaction sequence to the Starknet OS's Cairo `execute_replace_class` (`syscall_impls.cairo`); because of the missing declared-class check (explicitly flagged by the `TODO(Yoni, 1/1/2026)` comment), the OS accepts the update and writes the undeclared `class_hash` into `contract_state_changes`, which is then committed to the state trie — producing a state/root computation inconsistent with what blockifier actually committed for that transaction outcome.

*Note: I was unable to fully trace how/whether the Starknet OS's committed state diff from `execute_replace_class` is cross-checked against blockifier's committed diff elsewhere in the pipeline (e.g. in `starknet_committer` reconciliation code); if such a downstream consistency check exists and rejects any OS-only state entries, the severity would be reduced. This should be verified directly in the repository before finalizing severity.*

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}
