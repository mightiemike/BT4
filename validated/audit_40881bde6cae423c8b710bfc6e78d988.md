## Finding Analysis

The external report's root cause is: an oracle/price value is consumed without validating how stale it is at the point of use — only correctness (sign, format) is checked, never freshness. Searching Push Chain's scope, the closest analog is the `ChainMeta` gas-price oracle in `x/uexecutor`, which is written by Universal Validator votes and consumed by on-chain gas-fee/refund logic with the same asymmetry: freshness is enforced only at the **write** path, never at the **read/consumption** path.

### Title
Missing freshness check when consuming `ChainMeta` gas price allows stale gas-price data to drive outbound fee accounting - (File: `x/uexecutor/keeper/chain_meta.go`, `x/uexecutor/keeper/evm.go`)

### Summary
`VoteChainMeta` filters *votes* older than `chainMetaVoteStalenessSeconds` (300s) out of the median computation [1](#0-0) , but the **applied, on-chain gas price itself carries no expiry/`updatedAt`-style bound**. Once `LastAppliedChainHeight` is set, it is only updated when enough *fresh* votes arrive again [2](#0-1) ; if fresh votes stop arriving (validator downtime, RPC failure on the observed chain, network partition, or simply no new votes because price hasn't "changed enough" to be resubmitted), the previously-applied price stays live on the `UniversalCore` EVM contract indefinitely.

Every consumer of this price — `GetGasPriceByChain` [3](#0-2)  and the Solidity-side `getOutboundTxGasAndFees` / `gasPriceByChainNamespace` used to compute the `GasFee`/`GasPrice` charged to users for outbound transactions [4](#0-3)  — reads this value with **no freshness check whatsoever**, exactly the pattern flagged in the Chainlink report (`getPrice()` never checking `updatedAt`).

### Finding Description
1. `VoteChainMeta` staleness logic only governs which *votes* are eligible for the median at the moment a new vote is cast [5](#0-4) .
2. If `len(fresh) == 0` at vote time, the code explicitly skips the EVM write and keeps the old value active [6](#0-5) .
3. There is no on-chain record of "when was the last applied price actually pushed" being checked anywhere it's consumed — `ChainMeta.LastAppliedChainHeight` tracks *chain height*, not wall-clock recency, and nothing compares `ctx.BlockTime()` against a max-staleness bound before using the resulting `gasPriceByChainNamespace()` value in fee computation.
4. Every consumer (`applyGasRefund` → `CallUniversalCoreRefundUnusedGas` [7](#0-6) , and outbound creation's `getOutboundTxGasAndFees`) trusts whatever price is currently stored, with no `updatedAt`/heartbeat-style validation before use — the same missing check the Chainlink report calls out.

### Impact Explanation
If the real gas price on the destination chain moves quickly (a legitimate "flash" market event on that chain, not attacker-controlled) while Push Chain's `ChainMeta` price is frozen due to lack of fresh votes, any user submitting a normal outbound-generating transaction during that window has their `GasFee`/`GasPrice` computed from the stale value:
- If the real price spiked and the stored price is stale-low, users are systematically undercharged for gas, and the protocol/TSS signer absorbs the deficit when actually broadcasting on the destination chain — a bad-debt/fee-accounting corruption analogous to the original report's "bad debts to the protocol."
- If the real price crashed and the stored price is stale-high, users are overcharged, corrupting gas fee/refund accounting in the opposite direction.

This directly falls in the in-scope "corruption of ... gas fee accounting, refund accounting ... or canonical UniversalTx state" bucket, reachable by an ordinary unprivileged user simply submitting a payload/outbound transaction — no validator or admin privilege required to trigger the mis-accounting.

### Likelihood Explanation
Moderate. It requires a genuine, temporary gap between real-world gas-price movement and validator re-votes (e.g., during high volatility, RPC hiccups on the observed chain, or simply below-threshold price changes not triggering a re-vote), which is a realistic and recurring operational condition rather than a contrived edge case — the same class of condition Chainlink explicitly warns about with `heartbeat`/`updatedAt`.

### Recommendation
Add a maximum-staleness check at the consumption site, not just the vote-aggregation site: store the wall-clock timestamp of the last *applied* (not just last-voted) price update in `ChainMeta`/`UniversalCore`, and have `GetGasPriceByChain`/`getOutboundTxGasAndFees` reject or fall back safely when `block.timestamp - lastAppliedAt > maxStaleness`, mirroring Chainlink's `updatedAt` heartbeat guidance.

### Proof of Concept
1. Validators vote `ChainMeta` for chain X, price bootstraps and `LastAppliedChainHeight` is set.
2. Validators stop submitting new votes for chain X (e.g., due to an RPC outage on their `ChainMetaOracle` fetch loop) for an extended period, while chain X's real gas price moves sharply.
3. `VoteChainMeta` never runs again for chain X (no new votes, so no staleness filtering or re-median is even attempted), leaving the old price live on `UniversalCore`.
4. A user submits a normal payload that produces an outbound to chain X; `getOutboundTxGasAndFees` computes `GasFee`/`GasPrice` from the frozen, stale price via `gasPriceByChainNamespace` — undercharging or overcharging the user relative to the real cost, with no on-chain check ever comparing the price's age against an acceptable bound.

		}

// GetGasPriceByChain reads the gas price for a chain from the UniversalCore contract.
func (k Keeper) GetGasPriceByChain(ctx sdk.Context, chainNamespace string) (*big.Int, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, abi, ueModuleAccAddress, handlerAddr, false, nil, "gasPriceByChainNamespace", chainNamespace)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call gasPriceByChainNamespace")
	}

	results, err := abi.Methods["gasPriceByChainNamespace"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack gasPriceByChainNamespace result")
	}

	return results[0].(*big.Int), nil
}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}
