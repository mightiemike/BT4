### Title
Empty-but-`Some` signer set causes `verify_signer_signatures` to accept Nakamoto blocks with zero signer signatures - ([File: stackslib/src/chainstate/nakamoto/mod.rs])

### Summary
`NakamotoBlockHeader::verify_signer_signatures` only rejects a `reward_set` when `signers()` returns `None`; it does not special-case a reward set whose signer list is present but empty. When every reward-cycle entry's `stacked_amt` divides to a weight of `0` under the current `pox_ustx_threshold`, `StacksChainState::make_signer_set` filters out all entries yet still returns `Some(vec![])` rather than `None`. This degenerates `total_signing_weight()` to `0`, `compute_voting_weight_threshold(0)` to `0`, and the check `total_weight_signed < threshold` becomes `0 < 0`, which is false — so a block with **no signer signatures at all** is deterministically accepted as validly signed by every conforming node.

### Finding Description
`make_signer_set` builds the reward-cycle's signer set by dividing each stacker's `amount_stacked` by a `threshold` (derived from `get_reward_threshold_and_participation`, which is a function of total liquid STX and participation — independent of any individual staker's amount) and filtering out any entry whose resulting `weight` is `0`: [1](#0-0) 

If every entry's `stacked_amt` is smaller than `threshold` (a realistic outcome at low participation, since `threshold` is not bounded by any individual stacker's amount), the filter drops every entry, and the function still returns `Some(signer_set)` with an **empty but non-`None`** vector: [2](#0-1) 

`RewardSet::total_signing_weight` only errors when `signers()` is `None`; an empty `Some(vec![])` yields `Ok(0)` via `fold`: [3](#0-2) 

`NakamotoBlockHeader::verify_signer_signatures` likewise only bails out when `signers()` is `None`, not when it is empty: [4](#0-3) 

With `total_weight = 0`, `compute_voting_weight_threshold` computes `threshold = (0 * 70) / 10 + 0 = 0`: [5](#0-4) 

Because `signers_by_pk` is empty, the `for signature in self.signer_signature.iter()` loop never executes when the block carries zero signer signatures, leaving `total_weight_signed = 0`. The final acceptance check then evaluates `0 < 0`, which is `false`, so the function returns `Ok(0)` instead of rejecting the block: [6](#0-5) 

This is the direct analog of the reported bug class: just as a swap through an empty pool bypasses the intended value-conservation check because the pool's total liquidity is zero, here a block's signature check bypasses the intended 70%-weight-threshold check because the reward-cycle's total signer weight degenerates to zero. The equality that should hold — "a Nakamoto block requires signatures worth ≥70% of real registered signer weight" — instead collapses to a vacuous `0 ≥ 0`.

### Impact Explanation
This breaks a core Nakamoto safety invariant: block finality is supposed to require a supermajority of signer weight, but here **any block with zero signatures** is treated as validly signed once the reward set's signer list is empty. This is deterministic across all conforming nodes (not a fork), so its impact is an invalid block being accepted network-wide without any signer participation, effectively removing the signer-approval security property for that reward cycle. This matches the Critical category: "an invalid block accepted ... network-wide."

### Likelihood Explanation
Triggering requires a reward cycle where total stacking participation is low enough (relative to `pox_ustx_threshold`, which is derived from total liquid STX/participation and not any individual staker amount) that every registered stacker's `amount_stacked` falls below the per-slot threshold. No majority stake, admin privilege, or additional party's key is required — the condition arises purely from an unprivileged low-participation reward cycle, which is plausible on low-activity or newly-launched networks/subnets using this code.

### Recommendation
In `make_signer_set`, return `None` (not `Some(vec![])`) when the filtered signer set is empty, so downstream code (`verify_signer_signatures`, `total_signing_weight`) treats it identically to "no signers configured" and errors out via `ChainstateError::NoRegisteredSigners`. Additionally, harden `verify_signer_signatures` to explicitly reject when `total_weight == 0` or `signers.is_empty()`, and require `threshold > 0` regardless of `total_weight`, so a zero-weight reward set can never vacuously satisfy the signature-weight check.

### Proof of Concept
1. Construct a reward cycle where all `RawRewardSetEntry` items have `amount_stacked < threshold` (achievable at low stacking participation since `threshold` from `get_reward_threshold_and_participation` does not depend on individual stacker amounts).
2. `StacksChainState::make_signer_set(threshold, entries)` filters every entry's `weight` to `0` and returns `Some(vec![])`. [7](#0-6) 
3. The resulting `RewardSet` has `signers() == Some(&vec![])`, so `total_signing_weight() == Ok(0)`.
4. Any Nakamoto miner creates a `NakamotoBlockHeader` with `signer_signature = vec![]` (zero signatures) for this reward cycle and calls `verify_signer_signatures`.
5. `signers()` is `Some`, so the early-return error path is skipped; `total_weight = 0`; `compute_voting_weight_threshold(0) = 0`; the loop over `signer_signature` (empty) leaves `total_weight_signed = 0`; the check `0 < 0` is false. [6](#0-5) 
6. `verify_signer_signatures` returns `Ok(0)`, and the block is treated as validly signed by all conforming nodes despite carrying no signatures.

    /// If there are no reward set signers, a ChainstateError is returned.

        let Some(signers) = self.signers() else {
            return Err("Unable to calculate total weight - No signers in reward set".to_string());

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
