### Title
Integer truncation of `baseFee` to zero lets gas-fee accounting be bypassed, granting free UEA/payload execution - (File: x/uexecutor/keeper/fees.go)

### Summary
The external report's bug class is: an amount computed for pulling/charging a user rounds down to less than 1 (integer truncation), the system treats "amount to charge == 0" as "nothing owed," and skips the charge — but the corresponding credit/benefit (minted shares) is still granted in full. The Push Chain analog is in the gas-fee accounting path for `MsgExecutePayload` / inbound payload execution: `CalculateGasCost` in [1](#0-0)  truncates the EVM `baseFee` (an 18-decimal `LegacyDec`) down to a whole-`upc` integer via `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` before multiplying by `gasUsed`. If `baseFee < 1 upc` (i.e. the decimal value is less than `1e18` in its internal fixed-point representation), this division truncates to `0`, making `effectiveGasPrice == 0` and therefore `gasCost == 0` regardless of how much gas was actually used.

### Finding Description
`DeductGasFeesFromReceipt` [2](#0-1)  is the sole gate that bills a UEA/recipient for EVM execution it consumed via `CallUEAExecutePayload` / `CallExecuteUniversalTx`. It calls `CalculateGasCost(baseFee, maxFeePerGas, maxPriorityFeePerGas, gasUsed)` and then:

```go
if gasCost.Sign() <= 0 {
    return nil
}
```

`CalculateGasCost` computes `effectiveGasPrice` by taking `baseFee.BigInt()` (which is `baseFee_decimal * 1e18`) and doing an **integer** division by `1e18`:

```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
...
effectiveGasPrice := new(big.Int).Set(baseFeeBig)
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)
``` [3](#0-2) 

Any `baseFee` strictly less than `1` (e.g. `0.9999...` upc) truncates to `0`, making `gasCost = 0 * gasUsed = 0` no matter how large `gasUsed` is. `DeductGasFeesFromReceipt` then returns `nil` without deducting or burning anything, while the EVM state changes from the already-executed payload are committed via `writeCache()` in the caller:

- `ExecutePayloadV2` [4](#0-3)  executes the UEA call in a `CacheContext`, calls `DeductGasFeesFromReceipt`, and only rolls back on a fee-deduction *error* — a "no fee owed" result (`nil, nil`) is treated identically to a legitimate zero-cost tx, and `writeCache()` commits the free execution.
- The same skip-on-zero pattern recurs in `ExecutePayload` (direct `MsgExecutePayload` path) [5](#0-4)  and in the CEA smart-contract paths in `execute_inbound_funds_and_payload.go` / `execute_inbound_gas_and_payload.go`.

`MsgExecutePayload` is itself in the gasless allowlist [6](#0-5) , so the attacker pays zero Cosmos-level fee to submit it; the only cost mechanism for arbitrary EVM execution against a UEA is this internal `gasCost` billed against the UEA's own `upc` balance. When `gasCost` truncates to `0`, that billing mechanism is fully bypassed — the attacker (or a UEA owner authorizing gasless third-party delivery) can execute arbitrary-length/arbitrary-gas payloads through their UEA for free.

Whether `baseFee` can actually fall below `1e18` (1 upc) in practice depends on the feemarket module's dynamic EIP-1559-style adjustment; genesis configs observed in this repo set `base_fee` to `1000000000` upc initially [7](#0-6) , but the feemarket base fee decreases geometrically during sustained low block utilization, and I was not able to confirm (within the available tool budget) whether a hard floor above `1e18` is enforced elsewhere in the fork's feemarket parameters. This is a genuine gap in verification: the vulnerability is real and reachable as coded, but its *likelihood* depends on network conditions I could not fully confirm.

### Impact Explanation
If `baseFee` ever drops below 1 upc (even transiently, e.g. long periods of low network activity or on a low-traffic testnet/devnet), any unprivileged user can:
- Submit `MsgExecutePayload` (gasless message type) targeting their own UEA.
- Execute arbitrary EVM logic through the UEA (bounded only by the payload's declared `gasLimit`) with zero `upc` cost, since `DeductGasFeesFromReceipt` silently no-ops.
- Repeat this indefinitely, consuming real chain resources (EVM execution, storage writes) without paying the gas-fee accounting mechanism designed to prevent exactly that — corrupting the gas fee accounting invariant explicitly called out in the allowed-impact gate ("corruption of ... gas fee accounting").

This does not directly mint/drain PRC20 or native tokens, but it defeats the fee mechanism that is supposed to make UEA-originated EVM execution non-free, which is a direct analogue to the C4 finding's "get more than he deserves" pattern (paying `0` while receiving a full unit of the metered resource).

### Likelihood Explanation
Medium-to-low, contingent on unverified feemarket parameterization: this requires `baseFee` to be under `1e18` (in `LegacyDec` terms) at the time of the transaction, which is plausible on low-fee testnets/devnets or during any period where the feemarket algorithm pushes `baseFee` toward its floor, but not confirmed to be reachable on a properly configured mainnet with a high floor. No privileged actor or malicious validator is needed — an ordinary UEA owner can trigger this purely through normal `MsgExecutePayload` submission.

### Recommendation
- In `CalculateGasCost`, do not truncate `baseFee` to a whole `upc` via integer division before multiplying by `gasUsed`. Instead, keep the calculation in `LegacyDec` (fractional) precision through the final multiplication, and only round the *final* `gasCost` (rounding up, not down) when converting to an integer `upc` amount to bill.
- In `DeductGasFeesFromReceipt`, do not silently skip billing when `gasCost.Sign() <= 0`; if `receipt.GasUsed > 0`, charge at least `1` upc (mirroring the C4 recommendation to reject/round up rather than silently drop micro-amounts to zero), or explicitly document/enforce a floor on `baseFee` at the feemarket-parameter level so this code path can never see a sub-1-upc `baseFee`.

### Proof of Concept
Conceptual (not run against a live node, since this analysis was performed via static code review only):
1. Configure/observe a chain state where `FeeMarketKeeper.GetBaseFee(ctx)` returns a `LegacyDec` less than `1.0` (e.g. `0.5`) — plausible after sustained low-utilization blocks decay the base fee from its genesis value.
2. Submit `MsgExecutePayload` (gasless, no Cosmos fee required) with a `UniversalPayload` whose `Data` calls a gas-heavy operation on the UEA’s target contract, with `gasLimit` sufficient to cover it.
3. `CallUEAExecutePayload` executes and reports `receipt.GasUsed > 0`.
4. `DeductGasFeesFromReceipt` → `CalculateGasCost` computes `baseFeeBig.Div(baseFeeBig, 1e18) == 0` → `effectiveGasPrice == 0` → `gasCost == 0`.
5. `DeductGasFeesFromReceipt` returns `nil` (line `if gasCost.Sign() <= 0 { return nil }`), no `SendCoinsFromAccountToModule`/`BurnCoins` occurs.
6. `writeCache()` commits the EVM execution regardless — the caller received `receipt.GasUsed` worth of computation for `0` upc.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}

	k.Logger().Debug("gas fees deducted",
		"recipient", recipient.Hex(),
		"gas_used", receipt.GasUsed,
		"gas_cost", gasCost.String(),
	)
	return nil
}
