### Title
Unbounded gzip decompression in RPC `estimateFee`/`simulateTransactions` `BroadcastedDeclareTransaction::V1` handling enables zip-bomb memory exhaustion - ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
The Starknet RPC node exposes `estimateFee` and `simulateTransactions` JSON-RPC methods, which accept `BroadcastedTransaction` inputs directly from any unprivileged caller. For `BroadcastedDeclareTransaction::V1`, the contract class's compressed program is decompressed via `user_deprecated_contract_class_to_sn_api` → `decompress_program`, which performs a raw, unbounded gzip decompression into memory with no post-decompression size limit, unlike every other decompression path in the codebase (gateway, storage, protobuf class conversion), all of which use `decode_and_decompress_with_size_limit`/`MAX_DECOMPRESSED_SIZE` bounds.

### Finding Description
`decompress_program` in [1](#0-0)  base64-decodes and gzip-decompresses attacker-supplied `compressed_program` data by calling `decoder.read_to_end(&mut decompressed)` with no size cap — the code contains an explicit `// TODO(dan): add time and size limits.` acknowledging the gap. This function is called from `user_deprecated_contract_class_to_sn_api` [2](#0-1) , which is invoked when converting a `BroadcastedDeclareTransaction::V1` into an `ExecutableTransactionInput::DeclareV1` in the `TryFrom<BroadcastedDeclareTransaction>` impl [3](#0-2) . This `TryFrom` is used by `estimate_fee` and `simulate_transactions` RPC handlers [4](#0-3)  to build `executable_txns` directly from caller-controlled `Vec<BroadcastedTransaction>` before any resource/fee validation, gateway admission, or class size checks are applied.

By contrast, every other decompression entry point in the codebase enforces a bound: the HTTP gateway path uses `decode_and_decompress_with_size_limit` bounded by `max_sierra_program_size` [5](#0-4) , the p2p protobuf class converter caps Cairo0 programs at `MAX_CAIRO0_PROGRAM_SIZE` (4MB) [6](#0-5) , and storage decompression is capped at `MAX_DECOMPRESSED_SIZE` (256MB) via `zstd::bulk::decompress` [7](#0-6) . The generic helper `decompress_with_size_limit` in `starknet_api` even implements the correct pattern using `.take(max_size + 1)` [8](#0-7) , but `decompress_program` in the RPC crate does not use it.

### Impact Explanation
A caller submitting a crafted `BroadcastedDeclareTransaction::V1` with a small but highly compressible `compressed_program` (a classic gzip bomb, e.g. a few KB compressing to gigabytes) to `estimateFee` or `simulateTransactions` forces the RPC node to allocate unbounded memory during decompression before any fee/size checks run. This can exhaust node memory/CPU, causing denial of service to the RPC endpoint, potentially disrupting a node's ability to serve/relay transactions from users — a network-availability impact, not merely a resource-only cosmetic bug, since RPC nodes are part of the transaction submission and estimation path.

### Likelihood Explanation
The vulnerable path is reachable via a single unauthenticated JSON-RPC call (`estimateFee`/`simulateTransactions`) containing a self-crafted `DECLARE` transaction body; no prior state, fees, or signatures need be valid since the decompression happens before validation. This makes the likelihood high for any RPC node exposing these standard read-only simulation endpoints to the public.

### Recommendation
Replace the raw `GzDecoder::read_to_end` call in `decompress_program` (crates/apollo_rpc/src/v0_8/api/mod.rs) with the same bounded pattern used elsewhere in the codebase (e.g. `starknet_api::compression_utils::decode_and_decompress_with_size_limit`, or wrap the `GzDecoder` with `.take(MAX_SIZE)` as done in `decompress_with_size_limit`), enforcing a maximum decompressed program size consistent with `max_sierra_program_size`/`MAX_CAIRO0_PROGRAM_SIZE` before returning the parsed `Program`.

### Proof of Concept
1. Construct a Cairo0 program JSON compressible to a tiny gzip payload (e.g. repeated bytes/whitespace) using `flate2`/`starknet_api::compression_utils::compress_and_encode`, sized to decompress into several GB.
2. Base64-encode the compressed bytes as `compressed_program` in a `BroadcastedDeclareTransaction::V1` payload.
3. Send it to the target RPC node's `starknet_estimateFee` or `starknet_simulateTransactions` method.
4. Observe `decompress_program` (crates/apollo_rpc/src/v0_8/api/mod.rs:671-682) decompress the payload unbounded, driving memory usage far beyond the compressed payload size and potentially causing the RPC process to OOM or stall, denying service to other RPC clients.

pub(crate) const MAX_DECOMPRESSED_SIZE: usize = 1 << 28; // 256 MB
// The compression level to use. Higher levels are slower but compress better.
const COMPRESSION_LEVEL: i32 = zstd::DEFAULT_COMPRESSION_LEVEL;

/// Returns the compressed data in a vector.
///
/// # Arguments
/// * data - bytes to compress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn compress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::compress(data, COMPRESSION_LEVEL)
}

/// Serialized and then compress object.
///
/// # Arguments
/// * object - the object to serialize and compress.
///
/// # Errors
/// Returns [`StorageSerdeError`] if any error is encountered in the serialization or compression.
pub fn serialize_and_compress(object: &impl StorageSerde) -> Result<Vec<u8>, StorageSerdeError> {
    let mut buf = Vec::new();
    object.serialize_into(&mut buf)?;
    Ok(compress(buf.as_slice())?)
}

/// Decompress data and returns it as bytes in a vector.
///
/// # Arguments
/// * data - bytes to decompress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn decompress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::decompress(data, MAX_DECOMPRESSED_SIZE)
}

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
