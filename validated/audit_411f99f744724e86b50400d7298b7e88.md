## Finding

Yes — this is a real, in-scope denial-of-service issue rooted in a mismatch between the flat gas price and the actual (linear-in-input) computational cost of `VerifyEd25519RawMessage`.

### Title
Fixed 4000-gas cost for `verifyEd25519RawMessage` does not scale with message size, allowing gas-cheap CPU amplification via memory reuse - (`precompiles/usigverifier/usigverifier.go`)

### Summary
`RequiredGas` charges a flat `VerifyEd25519RawMessageGas = 4000` for `verifyEd25519RawMessage` regardless of the size of the `message` argument, while the actual work performed — `ed25519.Verify(pubKeyBytes, message, signature)` — hashes the entire message with SHA-512 internally, an operation whose cost is linear in `len(message)`. There is no length check on `message` anywhere in the precompile or its ABI. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
An attacker-controlled contract can:
1. Expand EVM memory once to a size bounded only by the block gas limit's quadratic memory-expansion cost (e.g., a few MB).
2. Repeatedly `CALL`/`STATICCALL` `0xEC...01` with `verifyEd25519RawMessage`, pointing the calldata `inOffset`/`inSize` at that already-expanded memory region.

Because EVM memory-expansion gas is only charged once per new high-water mark, subsequent calls reusing the same memory range pay only the warm-call overhead (~100 gas) plus the flat `RequiredGas` of 4000 gas — not the cost of re-hashing the large buffer. This lets a single transaction trigger thousands of large-message Ed25519 verifications (each doing multi-MB SHA-512 hashing) for a gas cost that looks like ordinary lightweight precompile calls. The declared/charged gas therefore massively understates the real CPU work the executing node must perform for that transaction, since `RequiredGas` (`precompiles/usigverifier/usigverifier.go:66-86`) has no dependency on `len(input)` for this method.

### Impact Explanation
This is a non-network-level, unprivileged-user-reachable denial-of-service vector: a single ordinary transaction (well within a normal declared gas limit) can force the executing node to perform an amount of hashing work far exceeding what its gas accounting implies, stalling per-transaction/per-block EVM execution time on every honest node that processes that block, and delaying block finalization. It does not require malicious validators, peers, or any privileged role — only a normal contract deployment and call.

### Likelihood Explanation
Likelihood is moderate-to-high: exploitation only requires writing a simple Solidity/EVM contract that expands memory once and loops calls to the precompile, well within normal user capabilities and gas budgets. No special access or timing is needed.

### Recommendation
Make `RequiredGas` for `VerifyEd25519RawMessageMethod` (and `VerifyEd25519Method`) a function of input length, e.g., `VerifyEd25519RawMessageGas + perByteGas*len(message)`, mirroring how other hash/signature precompiles (e.g., `ecrecover`, `sha256`, `ripemd160`) price gas by input size in upstream go-ethereum. Additionally consider enforcing a maximum `message` length to bound worst-case per-call CPU cost.

### Proof of Concept
1. Deploy a contract that:
   - Executes an `MSTORE`/`CALLDATACOPY` at a high memory offset to expand memory to several MB once.
   - Loops, calling `0xEC00000000000000000000000000000000000001` with `verifyEd25519RawMessage(pubKey, message, signature)` where `message`'s calldata pointer/length reference the pre-expanded memory region, for as many iterations as the transaction's gas limit allows at ~4100 gas/call.
2. Run this transaction in a local EVM test harness / node and measure wall-clock execution time versus the transaction's gas consumption — the wall-clock time will scale with total bytes hashed (megabytes × iteration count) while gas consumption stays proportional only to the small fixed per-call charge, demonstrating gas/CPU-time decoupling.

func (p Precompile) VerifyEd25519RawMessage(
	method *abi.Method,
	args []interface{},
) ([]byte, error) {

	pubKey, ok := args[0].([]byte)
	if !ok {
		return nil, fmt.Errorf("invalid pubKey type")
	}

	message, ok := args[1].([]byte)
	if !ok {
		return nil, fmt.Errorf("invalid message type")
	}

	signature, ok := args[2].([]byte)
	if !ok {
		return nil, fmt.Errorf("invalid signature type")
	}

	pubKeyBytes, err := getSolanaPubKeyFromAddress(pubKey)
	if err != nil {
		return nil, fmt.Errorf("failed to parse pubKey: %w", err)
	}

	if len(pubKeyBytes) != ed25519.PublicKeySize || len(signature) != ed25519.SignatureSize {
		return nil, fmt.Errorf("invalid params")
	}

	ok = ed25519.Verify(pubKeyBytes, message, signature)

	return method.Outputs.Pack(ok)
}
