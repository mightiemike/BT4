## Title
Missing pubkey-to-address binding check in `AccountInitDecorator` allows forging the first transaction of any uninitialized account, enabling unauthorized gasless message execution (forged inbound/outbound/TSS/chain-meta votes) - (File: `app/ante/account_init_decorator.go`)

### Summary
This is the same bug class as the reported `addPool` issue: a gate function checks *some* preconditions but omits a dependent invariant that the rest of the system silently relies on. `AccountInitDecorator` checks that a tx is gasless, that the account doesn't exist yet, that signature/signer counts match, and that a pubkey is present and cryptographically valid — but it never checks that the supplied pubkey's derived address (`pubKey.Address()`) actually equals the claimed signer address (`newAccAddr`). That binding check normally happens in the SDK's `SetPubKeyDecorator`, which this decorator is explicitly ordered *before* and bypasses entirely on the "new account" branch.

### Finding Description
`AccountInitDecorator.AnteHandle` (`app/ante/account_init_decorator.go:31-81`) only fires for gasless transactions (`txpolicy.IsGaslessTx`), whose whitelist includes `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration` (see `app/README.md:161-170`). [1](#0-0) 

When the single tx signer (`newAccAddr`) has no on-chain account yet, the decorator calls `verifySignatureForNewAccount` and, on success, directly creates the account and **returns `ctx, nil`**, short-circuiting the remainder of the ante chain — critically, skipping `ante.NewSetPubKeyDecorator` which is registered right after it in `app/ante/ante_cosmos.go:48-50` and is the decorator that normally enforces `pubKey.Address() == signer address`. [2](#0-1) 

`verifySignatureForNewAccount` (`app/ante/account_init_decorator.go:83-170`) checks: signer/signature count equality, `pubKey != nil`, and calls `authsigning.VerifySignature` with a hard-coded `AccountNumber=0, Sequence=0` and `Address: newAccAddr.String()`. `authsigning.VerifySignature` only proves that *some* signature over the canonical sign bytes is valid for the given `pubKey` — it does **not** verify that `pubKey` cryptographically belongs to `newAccAddr`. Nothing in this function performs that binding check. [3](#0-2) 

Consequence: any attacker who knows an address that (a) is claimed as `Signer` on a gasless message and (b) has never yet transacted on Push Chain (`HasAccount == false`) can submit that message with **any keypair of their choosing**. The decorator accepts the forged signature, creates a real `BaseAccount` for `newAccAddr` with `sequence=1`, and dispatches the message to the handler as if legitimately signed by that address's owner.

This is directly reachable in the honest-validator flow: Universal Validators are granted `authz` permission from their core validator address to a separate operational "UV" address to submit gasless votes (as seen in `test/integration/uexecutor/vote_inbound_validation_test.go:88-102`, `SaveGrant(ctx, uniValAddr, coreValAddr, auth, ...)`). The `authz.Grant` is real on-chain state created independently of whether the grantee (`uniValAddr`) has ever transacted. Until the real UV daemon submits its first tx, `uniValAddr` has no account — exactly the bypass condition. An attacker can therefore forge the outer `authz.MsgExec` (signed with an arbitrary keypair claiming to be `uniValAddr`) wrapping an inner `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteTssKeyProcess`/`MsgVoteFundMigration`/`MsgVoteChainMeta` whose `Signer` is the legitimate core validator address. The `x/authz` module will honor the pre-existing grant, and downstream handlers such as `VoteInbound` (`x/uexecutor/keeper/msg_vote_inbound.go`) only check `IsBondedUniversalValidator(ctx, msg.Signer)` — a string comparison that is satisfied because `msg.Signer` is the real validator's address, regardless of who actually signed the enclosing tx. [4](#0-3) 

### Impact Explanation
An unprivileged attacker (no validator key, no TSS key, no admin rights) can inject forged votes into the honest-validator ballot machinery before a legitimate but not-yet-initialized Universal Validator account submits its first transaction:
- Forged `MsgVoteInbound` / `MsgVoteOutbound` votes corrupt inbound/outbound ballot tallies and can push ballots toward premature or wrong finalization, corrupting `UniversalTx` state, gateway execution, and refund/revert routing.
- Forged `MsgVoteTssKeyProcess` / `MsgVoteFundMigration` votes corrupt TSS key finalization and fund-migration records — a direct hit on the TSS coordination invariant called out in the required impact list.
- Forged `MsgVoteChainMeta` corrupts gas-price/chain-meta state used for fee accounting.

This matches "forged, replayed, mismatched, or cross-linked inbound, outbound, ballot, chain-meta, TSS, or migration state accepted through user-reachable flows with honest validators and honest nodes" from the allowed impact gate.

### Likelihood Explanation
High reachability: every freshly-registered Universal Validator (`MsgAddUniversalValidator`) has an authz grant address that has not yet transacted at registration time — this is precisely the intended bootstrap window this decorator was built for ("If signer has no on-chain account yet, creates it mid-pipeline... verifies the signature against those values, and short-circuits the rest of the ante chain" — `app/README.md:180`). No privileged access, no race condition beyond "attacker acts before the legitimate first tx lands," which an attacker can trivially win by monitoring mempool/chain state for new UV registrations.

### Recommendation
In `verifySignatureForNewAccount` (or immediately before calling it), add an explicit check that `pubKey.Address()` (converted to `sdk.AccAddress`) equals `newAccAddr` for every signature, mirroring the check performed by the standard SDK `SetPubKeyDecorator`. Reject the tx with `sdkerrors.ErrInvalidPubKey` if it does not match, before performing account creation or any signature-bytes verification.

### Proof of Concept
1. Core validator `V` (address `push1V...`) grants `authz.MsgGrant` to a fresh UV operational address `push1UV...` for `MsgVoteInbound` (standard onboarding flow, already exercised in `test/integration/uexecutor/vote_inbound_validation_test.go`).
2. Before the real UV daemon broadcasts anything, `push1UV...` has no on-chain account.
3. Attacker (holding an unrelated keypair `K_attacker`) builds an `authz.MsgExec{Grantee: push1UV..., Msgs: [MsgVoteInbound{Signer: push1V..., Inbound: <attacker-chosen fake inbound>}]}`, sets `GetSigners() == [push1UV...]`, and signs the tx bytes with `K_attacker` (an SDK signing library allows constructing arbitrary `SignerData.Address` independent of the actual signing key when calling low-level signing helpers, or by crafting the raw tx bytes directly against the RPC).
4. `AccountInitDecorator.AnteHandle` sees the tx is gasless, `push1UV...` has no account, calls `verifySignatureForNewAccount`, which succeeds because it only validates the signature against `K_attacker`'s pubkey and never checks `K_attacker.Address() == push1UV...`.
5. The decorator creates account `push1UV...` and short-circuits to `next` disabled — the tx is applied. `x/authz` finds the real grant from `push1V...` to `push1UV...` and executes the inner `MsgVoteInbound` as `Signer = push1V...`, which passes `IsBondedUniversalValidator` and records a forged vote toward ballot finalization, without the attacker ever possessing `push1V...`'s or `push1UV...`'s private key.

func (ms msgServer) VoteInbound(ctx context.Context, msg *types.MsgVoteInbound) (*types.MsgVoteInboundResponse, error) {
	signerAccAddr, err := sdk.AccAddressFromBech32(msg.Signer)
	if err != nil {
		return nil, fmt.Errorf("invalid signer address: %w", err)
	}

	// Convert account to validator operator address
	signerValAddr := sdk.ValAddress(signerAccAddr)

	// Lookup the linked universal validator for this signer
	isBonded, err := ms.k.uvalidatorKeeper.IsBondedUniversalValidator(ctx, msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to check bonded status for signer %s", msg.Signer)
	}
	if !isBonded {
		return nil, fmt.Errorf("universal validator for signer %s is not bonded", msg.Signer)
	}

	isTombstoned, err := ms.k.uvalidatorKeeper.IsTombstonedUniversalValidator(ctx, msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to check tombstoned status for signer %s", msg.Signer)
	}
	if isTombstoned {
		return nil, fmt.Errorf("universal validator for signer %s is tombstoned", msg.Signer)
	}

	// continue with inbound synthetic creation / voting logic here
	err = ms.k.VoteInbound(ctx, signerValAddr, *msg.Inbound)
	if err != nil {
		return nil, err
	}

	return &types.MsgVoteInboundResponse{}, nil
}
