The premise in the question holds against the actual code. In `universalClient/chains/svm/event_listener.go`, `processSignatureBatch` iterates every log line in `tx.Meta.LogMessages` for any transaction returned by `GetSignaturesForAddress` (which matches by *account involvement*, not by which program emitted a given log line), and calls `determineEventType`/`ParseEvent` purely on the raw log string content, with no check binding the log to the gateway program's execution context. [1](#0-0) 

`determineEventType` only strips the `"Program data: "` prefix, base64-decodes, and matches the first 8 bytes against a discriminator map — it never checks which program's invocation produced that log line: [2](#0-1) 

`GetSignaturesForAddress` on Solana returns any transaction where the address appears in the account list (signer, writable, or read-only), not only transactions where it's the executing program: [3](#0-2) 

I traced the downstream impact: a parsed event becomes a `store.Event`/`Inbound` that off-chain code turns into `MsgVoteInbound`, votes are tallied by ballot key = `hex(marshal(Inbound))` requiring >2/3 quorum of honest UVs, and on finalization `ExecuteInboundFunds`/`ExecuteInboundFundsAndPayload` call `depositPRC20` → `CallPRC20Deposit`, which mints PRC20 balance to `inbound.Recipient` for `inbound.Amount` with no additional cryptographic proof that a real gateway-controlled transfer occurred. Because parsing is deterministic and every honest UV runs the same vulnerable `universalClient` code against the same public Solana transaction, all honest validators would independently derive the identical forged `Inbound` and vote for the same ballot — reaching quorum through the legitimate honest-majority path, not through validator collusion. This satisfies the "honest-validator finalization path" pivot: an unprivileged attacker forging a plausible log via a decoy program that merely references the gateway address as an account can make the network mint PRC20 tokens with no real underlying deposit.

### Title
Forged Solana gateway event acceptance due to missing program-origin binding in log parsing - (File: universalClient/chains/svm/event_listener.go)

### Summary
`processSignatureBatch` treats any log line inside a transaction that merely references the gateway address as an account as if it were emitted by the gateway program itself. An attacker can deploy an arbitrary program, include the real gateway address as a (non-executing) account reference, and emit a `sol_log_data`/`"Program data: "` log whose first 8 bytes match a known gateway event discriminator and whose payload matches the expected `sendFunds` layout. This is picked up identically by every honest universal validator's off-chain listener, is voted on to quorum, and results in PRC20 tokens being minted to an attacker-chosen recipient for an attacker-chosen amount with no real fund transfer into the gateway vault.

### Finding Description
`processSlotRange` fetches signatures via `GetSignaturesForAddress(gatewayAddr, ...)`, which per Solana RPC semantics returns any transaction where the gateway address appears in the account list — including as a read-only, non-executing account. For each returned transaction, `processSignatureBatch` fetches `tx.Meta.LogMessages` and, for *every* log line in the flat list (regardless of which program in the instruction/invoke stack emitted it), calls `determineEventType`, which only checks a `"Program data: "` prefix and an 8-byte discriminator match: [7](#0-6) 

There is no correlation to the `"Program <id> invoke [n]"` / `"Program <id> success"` markers that Solana emits around each instruction's logs, so the code cannot and does not verify that the discriminator-matching log actually originated from the gateway program's own instruction execution. `ParseEvent` in `universalClient/chains/svm/event_parser.go` then decodes the attacker-controlled payload bytes directly into `sender`, `recipient`, `amount`, `rawPayload`, `revertAddress`, `txType`, and `verificationData` fields, which flow unmodified into `store.Event`/`Inbound`.

Downstream, `x/uexecutor/keeper/msg_vote_inbound.go`'s `VoteInbound` requires a >2/3 quorum of honest UVs to vote the same ballot (`GetInboundBallotKey` = hash of the marshaled `Inbound`), which is trivially reached because all honest UVs run the identical vulnerable parser against the same public forged transaction and thus produce byte-identical `Inbound` structs. Once finalized, `ExecuteInboundFunds`/`ExecuteInboundFundsAndPayload` call `depositPRC20` → `CallPRC20Deposit`, minting PRC20 tokens to the attacker-controlled recipient for the attacker-controlled amount, with no verification that any lamports/tokens actually moved into the gateway's vault PDA on Solana.

### Impact Explanation
This allows an unprivileged attacker to mint arbitrary amounts of PRC20 tokens on Push Chain without depositing any real assets into the Solana gateway/vault, i.e., unauthorized mint of protocol-controlled funds — a direct violation of the UTX/accounting invariant that only genuine gateway deposit events should be able to create inbound value. This is reachable purely through a standard, permissionless Solana transaction (deploying a program and calling it), with all validators behaving honestly.

### Likelihood Explanation
Likelihood is high: constructing a Solana transaction that references an arbitrary pubkey as an account and logs attacker-chosen bytes via `sol_log_data` is trivial and requires no special privileges, only knowledge of the target discriminator (derivable from the on-chain gateway program's IDL/method identifiers, which are part of `x/uregistry` chain config and are public).

### Recommendation
When scanning `tx.Meta.LogMessages`, bind each `"Program data: "` line to the enclosing `"Program <id> invoke"`/`"Program <id> success"` frame and only call `determineEventType`/`ParseEvent` for log lines emitted while `gatewayAddress` is the currently-executing program (tracking the invoke depth stack), rather than scanning the flat log list unconditionally.

### Proof of Concept
1. Attacker deploys a minimal Solana program `Evil` that, when invoked, calls `sol_log_data` with bytes `discriminator(sendFunds) || sender(32) || recipient(20) || amount || rawPayload || revertAddr(32) || txType || sigData`, using an attacker-controlled `recipient`/`amount`.
2. Attacker submits a transaction invoking `Evil`, listing the real Push Chain gateway program address as one of the transaction's accounts (e.g., as an unused read-only account) so the tx shows up in `GetSignaturesForAddress(gatewayAddr)`.
3. Every honest UV's `event_listener.go` fetches this transaction via `GetTransaction`, scans `tx.Meta.LogMessages`, finds the `Evil`-emitted `"Program data: ..."` line, matches the `sendFunds` discriminator via `determineEventType`, and calls `ParseEvent`, producing an `Inbound`/event identical across all honest UVs.
4. UVs broadcast `MsgVoteInbound` with the identical forged `Inbound`; quorum (>2/3) is reached purely from honest, independent observation of the same public forged transaction.
5. `VoteInbound` finalizes the ballot, `ExecuteInboundFunds` deposits PRC20 tokens to the attacker's `recipient` for `amount`, completing an unauthorized mint with no real Solana-side asset movement.

// Processes in-range sigs from `batch`, returns how many. `continue` on both
// bounds so it tolerates any in-page order.
func (el *EventListener) processSignatureBatch(
	ctx context.Context,
	batch []*solanarpc.TransactionSignature,
	fromSlot, toSlot uint64,
) (uint64, error) {
	var processed uint64
	for _, sig := range batch {
		if sig.Slot < fromSlot {
			continue
		}
		if sig.Slot > toSlot {
			continue
		}
		processed++

		// Get transaction details
		tx, err := el.rpcClient.GetTransaction(ctx, sig.Signature)
		if err != nil {
			el.logger.Error().
				Err(err).
				Str("signature", sig.Signature.String()).
				Msg("failed to get transaction")
			continue
		}

		// Process each log in the transaction
		if tx != nil && tx.Meta != nil && len(tx.Meta.LogMessages) > 0 {
			for logIndex, log := range tx.Meta.LogMessages {
				// Determine event type based on discriminator
				eventType := el.determineEventType(log)
				if eventType == "" {
					continue
				}

				// Parse gateway event from individual log
				event := ParseEvent(log, sig.Signature.String(), sig.Slot, uint(logIndex), eventType, el.chainID, el.logger)
				if event != nil {
					// Insert event if it doesn't already exist
					if stored, err := el.chainStore.InsertEventIfNotExists(event); err != nil {
						el.logger.Error().
							Err(err).
							Str("event_id", event.EventID).
							Str("type", event.Type).
							Uint64("slot", event.BlockHeight).
							Msg("failed to store event")
					} else if stored {
						el.logger.Debug().
							Str("event_id", event.EventID).
							Str("type", event.Type).
							Uint64("slot", event.BlockHeight).
							Str("confirmation_type", event.ConfirmationType).
							Msg("stored new event")
					}
				}
			}
		}
	}

	return processed, nil
}

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

// GetSignaturesForAddress gets transaction signatures for an address. If
// `before` is the zero signature, fetching starts from the most recent block;
// otherwise it returns signatures strictly older than `before`, enabling
// backward pagination.
func (rc *RPCClient) GetSignaturesForAddress(ctx context.Context, address solana.PublicKey, before solana.Signature) ([]*rpc.TransactionSignature, error) {
	var opts *rpc.GetSignaturesForAddressOpts
	if !before.IsZero() {
		opts = &rpc.GetSignaturesForAddressOpts{Before: before}
	}
	var signatures []*rpc.TransactionSignature
	err := rc.executeWithFailover(ctx, "get_signatures_for_address", func(client *rpc.Client) error {
		var innerErr error
		signatures, innerErr = client.GetSignaturesForAddressWithOpts(ctx, address, opts)
		return innerErr
	})
	return signatures, err
}

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}
