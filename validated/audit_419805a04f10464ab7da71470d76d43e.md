## Finding

The original report's bug class — liquidity/swap operations that hard-code `amountMin = 0` and thus have no real slippage protection against sandwich attacks — has a native analog in Push Chain's own on-chain gas-abstraction auto-swap logic in `x/uexecutor`.

### Where the analog lives

`ExecuteInboundGas` and `gasAndPayloadDepositAutoSwap` (used for `TxType_GAS` and `TxType_GAS_AND_PAYLOAD` inbounds) compute a slippage-protected minimum output before calling the real swap: [1](#0-0) 

The "protection" is `minPCOut = quote * 95 / 100`, where `quote` comes from a **live, unbounded Uniswap V3 QuoterV2 spot-price read** taken in the very same execution: [2](#0-1) 

and then immediately consumed by the actual swap: [3](#0-2) 

The same pattern is duplicated in the payload path and in the gas-refund path: [4](#0-3) [5](#0-4) 

### Why this is exactly the same root cause as the external report

The Marginal team's own response to the original report explicitly names this trade-off:

> "The latter (Uniswap v3 pool spot price from `slot0()`) is manipulable and doesn't really provide any more protection than setting mins to 0."

Push Chain's implementation chose exactly that manipulable reference (`quoteExactInputSingle`, which reads the pool's current tick/sqrtPrice, i.e., spot price) as the slippage anchor. Because the minimum is derived from the same spot price an attacker can move, an attacker can:
1. Front-run the block/ballot finalization that will trigger `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap` (the timing is predictable — the attacker created the inbound deposit themselves, and inbound finalization only occurs once enough validators vote, which is publicly observable) by swapping in the Uniswap V3 pool referenced by `defaultFeeTier`/`WPC` to push the PRC20/PC price to an unfavorable rate.
2. Let the module's `GetSwapQuote` read this manipulated price and compute `minPCOut` as 95% of that already-bad price — a bound that offers no real floor relative to the true market price.
3. Let `CallPRC20DepositAutoSwap`/`gasAndPayloadDepositAutoSwap` execute at the manipulated rate (it will always satisfy `minPCOut` since `minPCOut` was derived from the same manipulated state).
4. Back-run to restore the pool price, pocketing the spread. The victim (the user whose inbound deposit is being auto-swapped for gas) receives less native PC than a fair-market swap would have produced, i.e., value is siphoned out of the deposit/refund flow that is supposed to grant the user usable gas.

This reproduces the acknowledged worst case from the original report — "less liquidity ... deployed" / bad execution price — but here the impact is on end-user gas-abstraction and gas-refund accounting rather than treasury liquidity provisioning, and it is fully reachable by an unprivileged actor who simply times an ordinary deposit and an ordinary DEX swap.

### Assessment against the allowed-impact gate

This affects "corruption of ... gas fee accounting, refund accounting ... canonical UniversalTx state" via a manipulable price reference used in a user-reachable flow (inbound GAS/GAS_AND_PAYLOAD execution and outbound gas refunds), triggered purely by ordinary deposit + ordinary swap actions, with no privileged actor assumption. It mirrors the exact acknowledged low-severity manipulability trade-off from the external report, which Push Chain's own code adopted (Option 2, spot-price quoter) rather than avoided.

### Title
On-chain auto-swap "slippage protection" for gas abstraction derives its minimum-output bound from a manipulable spot-price quote, enabling sandwich extraction from user gas deposits/refunds - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund` all compute `minPCOut` as 95% of a live `QuoterV2.quoteExactInputSingle` spot-price read (`GetSwapQuote`) and pass it straight into the real swap (`CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`) within the same execution. Because the bound is derived from the same manipulable AMM state it is meant to protect against, an attacker who sandwiches the Uniswap V3 pool around the block in which the module's swap executes can force the deposit/refund swap through at an attacker-favorable rate while the 5% check still passes.

### Finding Description
See analysis above: `GetSwapQuote` [2](#0-1)  reads current pool spot price via `quoteExactInputSingle` with `SqrtPriceLimitX96: 0` (no price-limit safeguard either), and the resulting `quote` is immediately turned into `minPCOut = quote*95/100` and consumed by `CallPRC20DepositAutoSwap` [6](#0-5) . There is no TWAP, external price oracle, or user-supplied bound — the "protection" always self-validates against whatever price the pool is at when the module executes.

### Impact Explanation
Each GAS/GAS_AND_PAYLOAD inbound execution and each outbound gas refund with excess gas is an opportunity for a sandwich attack against the pool referenced by `defaultFeeTier`/`WPC`, extracting value from the user's deposited PRC20/gas token at the expense of the amount of native PC credited to the user's UEA (or refunded to the sender). This is a repeatable value-extraction primitive reachable by any unprivileged actor who can trade in the underlying pool and time/observe inbound finalization.

### Likelihood Explanation
Moderate: it requires the attacker to control (or be) the depositor whose inbound triggers the swap, and to also act in the Uniswap V3 pool at the right moment. Inbound finalization timing is observable (pending votes/ballots), and pool liquidity for PRC20/WPC pairs may be shallow enough to move price cheaply, making this practically exploitable, especially for lower-liquidity PRC20 tokens.

### Recommendation
Replace the spot-price quote with a manipulation-resistant reference (e.g., a time-weighted average price, an external price oracle, or a governance/registry-configured max-deviation bound), or bound `SqrtPriceLimitX96` to a sane value tied to a trusted reference price rather than `0`. Alternatively, cap the maximum PRC20 amount auto-swapped per block/pool to limit the economic incentive for sandwiching, consistent with Marginal's own acknowledgment that spot-price-based slippage bounds provide no real protection.

### Proof of Concept
1. Attacker deposits PRC20 `T` on a source chain to trigger a `TxType_GAS` inbound for their own UEA.
2. As soon as enough validator votes are pending/likely to finalize the inbound (publicly observable via `MsgVoteInbound` traffic or ballot state), attacker submits a large sell of `T` into the `T/WPC` Uniswap V3 pool used by `defaultFeeTier`, depressing `T`'s price.
3. When the finalizing vote lands, `ExecuteInboundGas` calls `GetSwapQuote` and reads the depressed price, computing a `minPCOut` that is 95% of an already-bad rate.
4. `CallPRC20DepositAutoSwap` executes the deposit-and-swap at the depressed rate — well below fair value — but does not revert because `minPCOut` was derived from the same depressed state.
5. Attacker immediately buys back `T` in the pool, restoring price and capturing the spread, while the victim's UEA receives less native PC than it would have under undistorted market pricing.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
