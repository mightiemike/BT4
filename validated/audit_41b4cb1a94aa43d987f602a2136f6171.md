## Title
Auto-swap "slippage protection" derives its bound from a manipulable, same-transaction spot quote — analog of the Illuminate `yield()` leak - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The Illuminate finding is about a "slippage guard" that is not actually a guard: it takes the DEX's own preview/quote value and uses it as the accepted minimum, so the check can never fail regardless of price movement. Push Chain's PRC20→WPC auto-swap path exhibits the same structural weakness: `minPCOut` is derived exclusively from `GetSwapQuote` (a live `quoteExactInputSingle` call to the same Uniswap-V3-style pool the swap will execute against), taken 95% of that number, with no independent/oracle/TWAP reference price and no user- or governance-supplied bound. An unprivileged actor who can move the pool price (a normal, permissionless swap on the PRC20/WPC pool) immediately before the protocol's own deposit-and-swap executes can push the "reference" price down first, after which the protocol-computed `minPCOut` simply certifies whatever degraded price the attacker already created.

### Finding Description
`GetSwapQuote` in [1](#0-0)  performs a static `CallEVM` (`commit=false`) call to `QuoterV2.quoteExactInputSingle` against the live pool state at the moment of the call. Every caller that needs a slippage bound builds it purely from this same live number:

- `ExecuteInboundGas`: [2](#0-1) 
- `gasAndPayloadDepositAutoSwap`: [3](#0-2) 
- `applyGasRefund` (outbound gas refund swap leg): [4](#0-3) 

In each case the pattern is identical:
```go
quote, execErr = k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
...
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
receipt, execErr = k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
```
`quote` and the swap execution happen back-to-back inside the same keeper call — there is no external price feed, no time-weighted average, and no caller-supplied minimum. The "5% slippage" only bounds movement *between the quote call and the swap call within the same message*; it does nothing to bound the price the pool was already sitting at when the quote was taken. Exactly like `sellBasePreview` in the Illuminate report, the "check" is self-referential: it validates the swap against a number that itself is fully attacker-influenceable, so an attacker who manipulates the pool (a normal, permissionless AMM trade — not a privileged action) *before* their inbound is finalized by validators can guarantee the depressed price still "passes" the bound.

Concretely: the AMM pool (`v3-core`/`v3-periphery`, deployed per `e2e-tests/setup.sh` `step_setup_swap_amm`) for a given PRC20/WPC pair is a standard permissionless pool. Any user can submit an ordinary swap transaction against it. Inbound processing that triggers `CallPRC20DepositAutoSwap` happens only after cross-chain confirmation delay (`FastInbound`/`StandardInbound` block confirmations) plus validator voting — a window fully known and exploitable by the depositing user, who can time a large pool-distorting trade to land immediately before their own inbound's auto-swap executes, then reverse the trade afterward, extracting value from their own deposit (and from any other queued PRC20→WPC deposits sharing the same pool/fee tier) while the "slippage" check always passes because it is derived from the manipulated price itself.

### Impact Explanation
This corrupts PRC20/native asset accounting and gas-fee accounting: depositors (or the protocol paying gas refunds) receive materially less WPC than fair value while the on-chain "slippage guard" reports success, because the guard's reference price is attacker-controlled at the moment it is computed. This falls under "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" and unauthorized value extraction/loss of user/protocol-controlled funds in the allowed-impact gate, triggered purely by an unprivileged user's own ordinary deposit and permissionless AMM trades — no validator, relayer, or admin collusion required.

### Likelihood Explanation
Requires an unprivileged actor to (a) submit an ordinary cross-chain deposit that queues a GAS/GAS_AND_PAYLOAD auto-swap, and (b) execute an ordinary AMM trade on the PRC20/WPC pool timed just before validator quorum finalizes the inbound. Both are default, permissionless transaction paths reachable by any user; the multi-block confirmation + voting delay before execution gives a predictable window to time the manipulation. Effectiveness scales inversely with pool liquidity/depth for a given PRC20, which is realistic for newly-listed or lower-liquidity token pairs.

### Recommendation
Do not derive `minPCOut` solely from a spot quote taken in the same call. Options: (1) use a TWAP/oracle-based reference price with a bounded deviation check against the spot quote, rejecting execution (and instead routing to the no-swap PRC20 deposit fallback) if spot deviates too far from TWAP; (2) cap per-block/per-pool auto-swap notional to limit manipulation profitability; (3) allow governance-configured maximum slippage/reference price per token rather than a self-referential percentage of the just-fetched quote; (4) consider deferring/batching auto-swaps or requiring price impact checks against pool liquidity depth before proceeding.

### Proof of Concept
1. Attacker holds PRC20 token `X` (registered token with a live PRC20X/WPC pool).
2. Attacker initiates a normal cross-chain deposit of `X` with `TxType_GAS` (or `GAS_AND_PAYLOAD`) — an ordinary, permissionless action.
3. While the inbound is waiting on confirmations/validator quorum (`ExecuteInboundGas` / `execute_inbound_gas_and_payload.go` path not yet triggered), attacker submits a large ordinary swap on the PRC20X/WPC pool that depresses X's price.
4. Validators reach quorum and `ExecuteInboundGas` runs: `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-537`) returns the now-depressed price; `minPCOut = quote * 95%` is computed from that depressed price (`execute_inbound_gas.go:142-153`).
5. `CallPRC20DepositAutoSwap` executes at the depressed price, successfully satisfying `minPCOut` even though the depositor/UEA receives far less WPC than the token's fair value.
6. Attacker reverses their manipulating swap afterward, pocketing the difference extracted from the deposit that was force-converted at the manipulated price. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```
