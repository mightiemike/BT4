### Title
Unbounded prefix-scan amplification in `getdelegatedresourceaccountindexv2` enables cheap CPU/DB-IO DoS via attacker-inflated delegation index - ([File: framework/src/main/java/org/tron/core/services/http/GetDelegatedResourceAccountIndexV2Servlet.java])

### Summary
`GetDelegatedResourceAccountIndexV2Servlet.fillResponse` calls `Wallet.getDelegatedResourceAccountIndexV2`, which reaches `DelegatedResourceAccountIndexStore.getV2Index` → `getWithPrefix`, performing two unbounded `prefixQuery()` scans plus `O(n log n)` sorts on every request. An attacker can cheaply inflate the number of `V2_FROM_PREFIX`/`V2_TO_PREFIX` entries for a target address by broadcasting many low-value `DelegateResourceContract` transactions from disposable funded accounts, then repeatedly hit the free/unauthenticated HTTP endpoint to force disproportionate per-request CPU/DB cost.

### Finding Description
`getWithPrefix` builds the full response by calling `this.prefixQuery(key)` twice (once for `V2_FROM_PREFIX`, once for `V2_TO_PREFIX`) and sorting the resulting collections by timestamp with no page size, no result cap, and no cost accounting relative to the number of stored entries: [1](#0-0) 

Each `DelegateResourceContract` execution unconditionally adds one `V2_FROM_PREFIX` and one `V2_TO_PREFIX` entry keyed by `(prefix, ownerAddress, receiverAddress)`/`(prefix, receiverAddress, ownerAddress)`, with no cap on the number of distinct owner accounts that may delegate to the same receiver: [2](#0-1) 

The only economic gates on issuing a `DelegateResourceContract` are: the owner account must exist, must have frozen ≥1 TRX via FreezeBalanceV2 for the chosen resource, and the receiver must be a non-contract existing account: [3](#0-2) [4](#0-3) 
None of these checks bound how many distinct *owner* accounts may target the same receiver address, so an attacker can create many funded low-balance accounts, freeze the 1-TRX minimum in each, and delegate to a single victim address, linearly growing that address's `V2_TO_PREFIX` index (and correspondingly the delegator's `V2_FROM_PREFIX` index).

On the read path, the HTTP servlet forwards the raw address straight into `Wallet.getDelegatedResourceAccountIndexV2` with no pagination or size limits: [5](#0-4) 
The only protective mechanism present is `RateLimiterServlet`'s generic per-endpoint/global QPS limiter, which throttles *request rate* but does not account for the *cost per request*, i.e., it does not scale down allowed throughput based on how large the target's delegation index has become: [6](#0-5) 
Thus a fixed QPS budget times an attacker-inflated O(n) query cost per request produces aggregate CPU/IO cost that grows with attacker-chosen n, i.e., a violation of "query cost bounded relative to a free HTTP request."

### Impact Explanation
This is a resource-amplification / disproportionate-cost DoS against the FullNode/SolidityNode HTTP API: each request against an inflated address triggers two full LevelDB/RocksDB prefix scans and in-memory sorts proportional to the number of delegation records for that address, unbounded by any query-size cap. At scale (tens of thousands of index entries), sustained legitimate QPS-limited traffic against this endpoint can consume disproportionate CPU and DB IO on the node, degrading service for other API consumers — this matches TRON's "DoS via RPC-API" impact class. It does not affect consensus, asset accounting, or key material; the impact is scoped to node-level API availability/performance degradation.

### Likelihood Explanation
Feasibility is moderate: the attacker needs many funded accounts (TRX for account activation/bandwidth) each freezing the minimum 1 TRX via `FreezeBalanceV2` and issuing a `DelegateResourceContract` targeting the victim address. This capital is temporarily locked (subject to unfreeze delay) but not destroyed, and transaction fees for freeze/delegate are minimal (bandwidth-based, no explicit `calcFee` cost — `calcFee()` returns 0 for `DelegateResourceActuator`). Building 10k+ entries is a bulk-but-cheap on-chain operation reachable by any unprivileged funded account; no special role, signature bypass, or non-default config is required. The read side requires no authentication and is repeatable indefinitely subject only to the generic QPS limiter, so the attack is fully repeatable once the index is inflated.

### Recommendation
- Cap the number of records `getWithPrefix`/`prefixQuery` will scan and return per request (pagination with `offset`/`limit`), or store/maintain a bounded, capped index (reject or evict beyond a max delegator/delegatee count per address) enforced in `DelegateResourceActuator`/`DelegateResourceProcessor` at write time.
- Alternatively/additionally, make the per-endpoint rate limiter cost-aware (e.g., weight QPS cost by index size) so inflated targets don't get a flat request budget.
- Consider moving the sort into the query (e.g., storing entries in an already-sorted key layout) to avoid `O(n log n)` in-memory sorting on every read.

public void benchmarkGetV2IndexScalesWithEntryCount() {
  byte[] victim = randomAddress();

    delegatedResourceAccountIndexStore.delegateV2(delegator, victim, i);

  DelegatedResourceAccountIndexCapsule result =
      delegatedResourceAccountIndexStore.getV2Index(victim);
  long elapsed = System.nanoTime() - start;
  // Expected (failing) assertion: latency stays sub-linear/bounded regardless of N
  assertTrue("per-request cost should not scale linearly with attacker-controlled N",
      elapsed < BOUNDED_THRESHOLD_NS);
}

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }

  @Override
  protected void service(HttpServletRequest req, HttpServletResponse resp)
      throws ServletException, IOException {

    RuntimeData runtimeData = new RuntimeData(req);
    IRateLimiter rateLimiter = container.get(KEY_PREFIX_HTTP, getClass().getSimpleName());

    // Check per-endpoint first to avoid consuming global IP/QPS quota for requests
    // that would be rejected by the per-endpoint limiter anyway. acquirePermit()
    // chooses blocking or non-blocking semantics based on rate.limiter.apiNonBlocking.
    boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
    boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);

    String contextPath = req.getContextPath();
    String url = Strings.isNullOrEmpty(req.getServletPath())
        ? MetricLabels.UNDEFINED : contextPath + req.getServletPath();
    // int64_as_string is honored only on GET requests (URL query). POST is intentionally
    // unsupported because reading the body here would consume request.getReader() and
    // break downstream servlets that read it themselves.
    if ("GET".equalsIgnoreCase(req.getMethod())) {
      JsonFormat.setInt64AsString(Util.getInt64AsString(req));
    }
    try {
      resp.setContentType("application/json; charset=utf-8");

      if (acquireResource) {
        Histogram.Timer requestTimer = Metrics.histogramStartTimer(
            MetricKeys.Histogram.HTTP_SERVICE_LATENCY, url);
        super.service(req, resp);
        Metrics.histogramObserve(requestTimer);
      } else {
        resp.getWriter()
            .println(Util.printErrorMsg(new IllegalAccessException("lack of computing resources")));
      }
    } catch (ServletException | IOException | BadMessageException e) {
      throw e;
    } catch (Exception unexpected) {
      logger.error("Http Api {}, Method:{}. Error：", url, req.getMethod(), unexpected);
    } finally {
      // CRITICAL: this clear pairs with the setInt64AsString call above. Removing it
      // will leak int64_as_string state across requests on reused Tomcat threads,
      // producing intermittent quoted/unquoted output that is very hard to debug.
      JsonFormat.clearInt64AsString();
      // Release whenever the per-endpoint permit was acquired (covers both the normal
      // completion path and the case where GlobalRateLimiter rejected the request).
      if (rateLimiter instanceof IPreemptibleRateLimiter && perEndpointAcquired) {
        ((IPreemptibleRateLimiter) rateLimiter).release();
      }
    }
  }
