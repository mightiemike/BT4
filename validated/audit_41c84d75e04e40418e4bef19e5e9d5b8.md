### Title
Vault `accrue()` pause pass-through combined with `last-update` clock jump on unpause causes silent interest loss and can transiently misstate debt/collateral used in the same-block health check - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Each vault's `accrue` function contains a "pass-through without reverting" branch when the `accrue` pause flag is set: instead of erroring out (which would force callers of `borrow`/`repay`/`deposit`/`redeem`/`system-borrow` to halt), it silently returns the *stale* cached `index`/`lindex` values without updating `last-update`. [1](#0-0) 

### Finding Description
`accrue` is called at the top of nearly every state-mutating vault entrypoint (`deposit`, `redeem`, `system-borrow`, `transfer`) via `(u (try! (accrue)))`, and by `market.clar`'s `borrow`/`repay`/`liquidate` flows indirectly through vault interest accrual before health is evaluated. When the `accrue` pause bit is set, `accrue` takes the pass-through branch and returns `{index: idx, lindex: lidx}` unchanged, bypassing the block that would otherwise recompute `next-index`/`next-liquidity-index`, mint the treasury reserve share (`treasury-lp`), and bump `last-update` to `stacks-block-time`. [2](#0-1) 

The DAO-only `set-pause-states` function is the only place that reconciles the clock: on *pausing* accrue it calls `accrue` once to flush pending interest, and on *unpausing* it jumps `last-update` directly to `stacks-block-time`, silently discarding whatever real-world time elapsed while paused rather than accounting for it. [3](#0-2) 

This is the "clock advanced only on change" / "pause that passes through instead of reverting" analog: the interest index is a cached value derived from `last-update` and `stacks-block-time`, and it is never invalidated/reconciled for real elapsed time while `accrue`-pause is active — it is simply frozen and then the clock is teleported forward on unpause. Every caller (`deposit`, `redeem`, `system-borrow`, and — through vault calls — `market.clar`'s `borrow`/`repay`/`liquidate`) that runs during the paused window operates on the stale index as if no time had passed, and the DAO-controlled unpause step erases the entire paused interval from the interest calculation rather than reverting or catching up.

### Impact Explanation
While the DAO is a privileged actor and toggling the pause flag itself is intended functionality, the *mechanism* by which `accrue()` passes through silently (instead of reverting the operations that depend on it) means depositors' and borrowers' interest accounting silently stalls for the duration of the pause and is never made whole — lenders permanently lose the yield/interest that should have accrued over that period, and the treasury reserve fee (`treasury-lp`) that would have been minted on that accrued interest is likewise never captured. This is a temporary/permanent freezing of unclaimed yield for lenders (impact class: theft/freezing of unclaimed yield), since the interest that should have compounded over the paused window is unrecoverable once `last-update` is jumped forward on unpause.

### Likelihood Explanation
This does not require any external attacker interference — it triggers automatically any time the DAO pauses and later unpauses `accrue` on a vault (e.g., for a genuine incident response or maintenance window), which is a documented, expected operational lever. The longer the pause window, the larger the amount of unclaimed yield permanently lost across all depositors and the debt-interest gap for borrowers, with no compensating mechanism in the contract.

### Recommendation
When unpausing `accrue`, instead of jumping `last-update` to `stacks-block-time` (discarding the paused interval), either (a) accrue interest for the pre-pause period only and preserve `last-update` at the pause timestamp so time resumes correctly, or (b) explicitly document/checkpoint the frozen interval and apply an off-chain-computed catch-up accrual before resuming normal accrual, ensuring lenders are not silently deprived of interest for the paused duration.

### Proof of Concept
1. At `T0`, vault `index`/`lindex` reflect all interest accrued up to `T0`; `last-update = T0`.
2. DAO calls `set-pause-states` with `accrue: true`. This triggers `(try! (accrue))` once to flush interest up to `T0`, then sets `pause-states` with `accrue = true`. [3](#0-2) 
3. Time passes to `T1` (e.g., days). Any user calls `deposit`/`redeem`, or `market.clar` drives `borrow`/`repay` on this vault. Each of these calls `(try! (accrue))`, which takes the paused branch and returns the stale `{index, lindex}` from `T0` without reverting and without updating `last-update`. [4](#0-3) 
4. DAO calls `set-pause-states` with `accrue: false` at `T1`. Because `was-paused` is true and `now-paused` is false, `last-update` is set directly to `stacks-block-time` (i.e., `T1`), with no accrual computed for the `[T0, T1]` interval. [5](#0-4) 
5. Net effect: the interest that should have accrued between `T0` and `T1` is permanently lost — `index`/`lindex` never reflect it, and `treasury-lp` for that period is never minted — even though all deposit/redeem/borrow/repay operations that occurred during `[T0, T1]` proceeded (pass-through, not reverted) as if no time had elapsed.
