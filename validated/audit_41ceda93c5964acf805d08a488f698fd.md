### Title
Unsafe division on `totalEnergyWeight` in `RepositoryImpl.calculateGlobalEnergyLimit` guarded only by a disabled-by-default `assert` - (File: `actuator/src/main/java/org/tron/core/vm/repository/RepositoryImpl.java`)

### Summary
The reported bug class is division operations (`rdivide`/`wdivide`) that accept a divisor from state/input without validating it is non-zero, causing reverts/DoS. The java-tron analog is `RepositoryImpl.calculateGlobalEnergyLimit`, which divides by `totalEnergyWeight` (a value read from `DynamicPropertiesStore`) while relying solely on a Java `assert` statement to guarantee the divisor is non-zero. Java assertions are disabled by default at runtime unless the JVM is started with `-ea`, and no production launch configuration in this repo enables assertions (only the test config does).

### Finding Description
`calculateGlobalEnergyLimit` reads `totalEnergyWeight` from the dynamic properties store and then unconditionally divides by it, with only an `assert` as a safety net: [1](#0-0) 

Compare this to the sibling implementation in `EnergyProcessor.calculateGlobalEnergyLimit`, which explicitly checks `totalEnergyWeight <= 0` and returns `0` when the network has enabled the `allowNewReward` proposal — but still falls through to the same bare `assert` in the `else` branch (i.e., when `allowNewReward()` is not enabled): [2](#0-1) 

`RepositoryImpl.calculateGlobalEnergyLimit`, unlike `EnergyProcessor`, has **no** `allowNewReward`/zero-check guard at all before dividing — it only has the `assert`: [3](#0-2) 

Because Java `assert` statements are stripped/no-ops unless the JVM is run with `-ea`, and the repository's production/reference configuration does not set this flag (only `framework/src/test/resources/config-test.conf` does), the `assert totalEnergyWeight > 0;` provides no actual runtime protection in a production deployment. If `totalEnergyWeight` is `0` (e.g., no TRX has been frozen for energy on the network/private chain, or the value is legitimately zero prior to the `allowNewReward` hardfork), execution reaches:
```java
return (long) (energyWeight * ((double) totalEnergyLimit / totalEnergyWeight));
```
Dividing a `double` by `0` does not throw in Java (produces `Infinity`/`NaN`), but the hardened path uses `BigInteger.divide`, which throws `ArithmeticException` on division by zero: [4](#0-3) 

### Impact Explanation
`calculateGlobalEnergyLimit` is invoked from the VM/actuator execution path (`RepositoryImpl`, used by `VMActuator`, `ContractState`, and `Repository`) to compute an account's energy limit during smart contract execution/energy accounting. If `totalEnergyWeight` is zero and `hardenResourceCalculation()` is enabled, the `BigInteger.divide` call throws `ArithmeticException`, which is an unhandled exception in the transaction execution path rather than a validated/expected error. This can cause transaction processing to fail unpredictably or, depending on where the exception propagates, cause divergence between nodes with different JVM assertion settings (nodes run with `-ea` would fail earlier/differently than nodes without it) — an invalid-state/divergence risk in TVM energy accounting.

### Likelihood Explanation
`totalEnergyWeight` being exactly zero is a real possible state for private/test chains, freshly bootstrapped networks, or specific proposal-gating windows before any account freezes TRX for energy, since it is a plain sum of frozen-for-energy balances tracked in `DynamicPropertiesStore`. On such networks the guard that exists in `EnergyProcessor` (checking `allowNewReward()` and `totalEnergyWeight <= 0`) is absent in `RepositoryImpl`, making this reachable without any privileged action — any user's transaction that triggers energy limit calculation on such a network state would hit the same code path.

### Recommendation
Replace the `assert totalEnergyWeight > 0;` in `RepositoryImpl.calculateGlobalEnergyLimit` with an explicit runtime check (mirroring `EnergyProcessor`'s guard), e.g.:
```java
if (totalEnergyWeight <= 0) {
  return 0;
}
```
before performing either the `BigInteger` division or the `double` division, so the function is safe regardless of whether JVM assertions are enabled.

### Proof of Concept
1. Deploy/operate a java-tron node where no account has frozen TRX for energy (`totalEnergyWeight == 0`), which is achievable on a freshly initialized private network or in specific pre-hardfork configurations.
2. Enable `allowHardenResourceCalculation` (`hardenResourceCalculation()` returns `true`).
3. Trigger any smart contract call that causes `RepositoryImpl.calculateGlobalEnergyLimit` to be invoked for an account with `frozeBalance >= TRX_PRECISION`.
4. Since the JVM runs without `-ea` in production, the `assert totalEnergyWeight > 0;` at [5](#0-4)  is a no-op, and execution reaches `BigInteger.valueOf(totalEnergyLimit).divide(BigInteger.valueOf(totalEnergyWeight))`, throwing `ArithmeticException: / by zero` and disrupting the energy-limit calculation for that transaction/account.

  public long calculateGlobalEnergyLimit(AccountCapsule accountCapsule) {
    long frozeBalance = accountCapsule.getAllFrozenBalanceForEnergy();
    if (frozeBalance < TRX_PRECISION) {
      return 0;
    }
    long energyWeight = frozeBalance / TRX_PRECISION;
    long totalEnergyLimit = getDynamicPropertiesStore().getTotalEnergyCurrentLimit();
    long totalEnergyWeight = getDynamicPropertiesStore().getTotalEnergyWeight();

    assert totalEnergyWeight > 0;

    if (hardenResourceCalculation()) {
      return BigInteger.valueOf(energyWeight)
          .multiply(BigInteger.valueOf(totalEnergyLimit))
          .divide(BigInteger.valueOf(totalEnergyWeight))
          .longValueExact();
    }
    return (long) (energyWeight * ((double) totalEnergyLimit / totalEnergyWeight));
  }

  public long calculateGlobalEnergyLimit(AccountCapsule accountCapsule) {
    long frozeBalance = accountCapsule.getAllFrozenBalanceForEnergy();
    if (dynamicPropertiesStore.supportUnfreezeDelay()) {
      return calculateGlobalEnergyLimitV2(frozeBalance);
    }
    if (frozeBalance < TRX_PRECISION) {
      return 0;
    }

    long totalEnergyLimit = dynamicPropertiesStore.getTotalEnergyCurrentLimit();
    long totalEnergyWeight = dynamicPropertiesStore.getTotalEnergyWeight();
    if (dynamicPropertiesStore.allowNewReward() && totalEnergyWeight <= 0) {
      return 0;
    } else {
      assert totalEnergyWeight > 0;
    }
    if (hardenCalculation()) {
      return calculateGlobalLimitV1(frozeBalance, totalEnergyLimit, totalEnergyWeight);
    }
    long energyWeight = frozeBalance / TRX_PRECISION;
    return (long) (energyWeight * ((double) totalEnergyLimit / totalEnergyWeight));
  }
