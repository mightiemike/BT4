Starknet OS `execute_replace_class` lacks the "class must be declared and Cairo1" check enforced by the Blockifier, causing execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
Any contract can invoke the `replace_class` syscall to change its own class hash. In the Blockifier (the execution engine used by the sequencer to build blocks), this syscall is guarded: the target class hash must already be declared (`state.get_compiled_class(class_hash)?`) and must be a Cairo 1 (Sierra/CASM) class (`is_cairo1` check), otherwise the call reverts with `ForbiddenClassReplacement`. The Starknet OS (the Cairo program used to re-execute the block and produce the proven state diff / block hash) implements the same syscall in `execute_replace_class` but only carries a `TODO` comment noting the missing check, and unconditionally accepts any `class_hash` value, declared or not, Cairo0 or Cairo1, and writes it into `contract_state_changes`.

### Finding Description
`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378` implements `replace_class`: [1](#0-0) 
This enforces two invariants before allowing a contract to change its own class: the class hash must be declared, and it must be a Cairo 1 class (Cairo 0 replacement is explicitly forbidden).

The corresponding Cairo implementation used by the Starknet OS, `execute_replace_class`, does not perform either check: [2](#0-1) 
The comment at line 902, `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`, confirms the check is known to be missing. The function reads the class hash straight from syscall input and writes it into `contract_state_changes` unconditionally, with no declaration check and no Cairo-version check.

Because block building (Blockifier) and block re-execution/proving (Starknet OS) are supposed to be functionally equivalent so that the sequencer-committed state root matches the OS-computed state root, this asymmetry means:
- A transaction that calls `replace_class` with an undeclared class hash, or with a Cairo 0 class hash, will be **reverted** by the Blockifier during block building (since `get_compiled_class` fails or `is_cairo1` fails), producing one state diff.
- If any code path or future integration re-executes/verifies such a call through the OS's `execute_replace_class` without the same guard, it will **succeed**, silently changing the contract's `class_hash` to an arbitrary (possibly non-existent/invalid) value, producing a different state diff/state root and block hash for logically the same transaction.

This is a "missing authorization/validation check" bug class exactly analogous to the DolphinScheduler CVE (an operation - deleting/mutating a resource - permitted without the ownership/validity check that the rest of the system assumes is enforced), reachable by any unprivileged contract deployer/caller via a plain `replace_class` syscall — no special privilege needed, matching the constraint that only unprivileged-transaction-sender-reachable bugs are in scope.

### Impact Explanation
If exploited (i.e., if this OS code path is reached with an unchecked class hash — which is the documented current behavior), it results in wrong committed state root / block hash computation via the OS relative to what the Blockifier's block-building logic considers valid, i.e., an honest-node/execution-engine divergence for the same transaction. This can manifest as:
- The OS accepting a state transition (contract class replaced with an undeclared/invalid hash) that the Blockifier would have reverted, corrupting the resulting Merkle/Patricia state root and block hash committed by the OS, or causing proof generation to fail/diverge from the sequencer's block.
- Downstream: a contract's class hash could be set to an undeclared class hash, permanently making the account/contract at that address non-functional (loss of contract functionality, potentially freezing funds locked behind that contract if the address becomes uncallable), or set to a Cairo 0 class hash in violation of the invariant the rest of the OS/Blockifier code assumes (Cairo1-only replacement), leading to unexpected `is_deprecated`/dispatch logic downstream.

This satisfies the "wrong committed root or block hash" / "honest-node divergence" / "permanent freezing of funds" acceptance criteria, and is rated Medium/High since it affects state commitment integrity for any transaction sender invoking a standard, unprivileged syscall.

### Likelihood Explanation
Likelihood is high in terms of reachability: `replace_class` is a public Cairo1 syscall available to any deployed contract, requiring no special permission, and is exercised in existing feature-contract test helpers (e.g., `test_replace_class`). The only uncertainty is exactly which callers/paths route through the OS `execute_replace_class` function versus the Blockifier's Rust `replace_class` in the current proving/re-execution pipeline; the explicit `TODO(Yoni, 1/1/2026)` comment strongly indicates the developers are aware the OS implementation is behind the Blockifier's and have not yet closed the gap, confirming the bug currently exists in the codebase rather than being purely theoretical.

### Recommendation
Add the same two checks in `execute_replace_class` (`crates/apollo_starknet_os_program/.../syscall_impls.cairo`) that exist in the Blockifier's `replace_class` (`crates/blockifier/src/execution/syscalls/syscall_base.rs`):
1. Verify the given `class_hash` corresponds to a declared contract class (read/lookup it and assert existence/success), mirroring `state.get_compiled_class(class_hash)?`.
2. Verify the declared class is Cairo 1 (reject Cairo 0/deprecated classes), mirroring the `is_cairo1` check and `ForbiddenClassReplacement` error.

These checks should be enforced before performing the `dict_update` on `contract_state_changes`, so that OS re-execution semantics remain identical to Blockifier semantics for `replace_class`.

### Proof of Concept
1. Deploy a Cairo1 contract `C` that calls the `replace_class_syscall` with an attacker-supplied `class_hash` argument that is either (a) never declared on-chain, or (b) the hash of a valid Cairo 0 class.
2. Submit an invoke transaction calling `C`'s external entrypoint with that malicious `class_hash`.
3. Under the Blockifier (sequencer block building), `syscall_base::replace_class` calls `state.get_compiled_class(class_hash)` which fails for an undeclared hash (or `is_cairo1` fails for a Cairo0 hash), causing the transaction/call to revert — no state change to `C`'s class hash.
4. Under the Starknet OS's `execute_replace_class` (`syscall_impls.cairo:881-920`), no such check exists: the OS unconditionally executes `dict_update` setting `C`'s class hash to the attacker-supplied value, regardless of whether it is declared or of the correct class version.
5. Comparing the two state diffs for the identical transaction shows a divergence in the contract's `class_hash` field, demonstrating that OS re-execution and Blockifier execution produce different results for the same transaction — violating the correctness invariant that both must agree in order to produce a valid, provable state root/block hash.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
