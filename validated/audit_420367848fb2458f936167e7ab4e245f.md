### Title
Open Redirect via unvalidated `redirectTo.url` origin in `renderAppBridge`/`sanitizeRedirectUrl` reachable through `/auth/exit-iframe?exitIframe=` - ([File: packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts])

### Summary
`isSafe()`/`sanitizeRedirectUrl()` validate only that a redirect URL is not a `file://` URI, contains no whitespace, has no doubled slashes in its pathname, and uses `http`/`https`, but never verify that the resulting URL's origin matches the trusted `domain` argument (`config.appUrl`). This is reachable pre-authentication via the exit-iframe route, which forwards the `exitIframe` query parameter directly into `renderAppBridge`'s `redirectTo.url`, producing an emitted `window.open(...)` script that navigates the top-level browsing context to an attacker-supplied absolute URL.

### Finding Description
In `authenticate.ts`, `respondToExitIframeRequest` reads the `exitIframe` query parameter unsanitized and passes it straight through to `renderAppBridge` as `redirectTo.url`: [1](#0-0)  This function is invoked very early in the `authenticateAdmin` flow, before shop/host validation, session-token verification, or session loading: [2](#0-1)  meaning an unauthenticated request can reach it directly.

`renderAppBridge` then calls `sanitizeRedirectUrl(config.appUrl, redirectTo.url)` and embeds the result verbatim into an inline `<script>window.open(...)</script>`: [3](#0-2) 

The validation logic in `isSafe()` checks only for `file://`-style triple slashes, whitespace, doubled slashes in the *pathname*, and http/https protocol — it never compares `url.origin`/`url.hostname` to `domain`: [4](#0-3)  An absolute URL like `https://attacker.example.com/steal` passes every check (no `///`, no whitespace, pathname `/steal` has no doubled slash, protocol is `https:`), so `new URL(redirectUrl, domain)` resolves to the attacker's own origin and is returned as "safe." The existing unit tests only assert same-origin/relative-path success cases and never assert rejection of a foreign absolute origin, confirming the gap is untested behavior rather than a deliberate check: [5](#0-4)  and the exit-iframe test suite likewise only exercises same-origin and relative-path cases, never a cross-origin absolute URL: [6](#0-5) 

### Impact Explanation
This is a reflected open redirect from an unauthenticated route into a top-level `window.open` navigation of the merchant's/user's browser. Because the exit-iframe page is reached while the app is embedded in the Shopify Admin iframe, the crafted link can be used for phishing (e.g., presenting a fake Shopify/App login page to steal merchant credentials or OAuth-consent trickery), which maps to Shopify's "open redirect / unvalidated redirect leading to phishing" bounty class. It does not by itself forge a session, leak a secret, or grant cross-tenant data access — the impact is limited to redirect/phishing exposure, not a full session/token compromise.

### Likelihood Explanation
Fully unauthenticated and requires no special privileges: an attacker only needs to send a merchant/victim a crafted `https://<app-domain>/auth/exit-iframe?exitIframe=https://attacker.example.com/steal&shop=<shop>.myshopify.com` link. `respondToExitIframeRequest` is checked before any shop/host/session-token validation in `authenticateAdmin`, so the path is trivially reachable. This is a default-configuration issue (no non-default settings required) and is fully repeatable.

### Recommendation
In `isSafe()`, after resolving `url = new URL(redirectUrl, domain)`, explicitly reject the URL unless `url.origin === new URL(domain).origin` (i.e., only allow same-origin absolute URLs or relative paths resolved against `domain`), rather than relying solely on protocol/whitespace/slash checks.

export function renderAppBridge(
  {config}: BasicParams,
  request: Request,
  redirectTo?: RedirectToOptions,
): never {
  let redirectToScript = '';
  if (redirectTo) {
    const destination = sanitizeRedirectUrl(config.appUrl, redirectTo.url);

    const target = redirectTo.target ?? '_top';

    redirectToScript = `<script>window.open(${JSON.stringify(
      destination.toString(),
    )}, ${JSON.stringify(target)})</script>`;
  }

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
