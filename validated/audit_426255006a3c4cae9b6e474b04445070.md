### Title
`accrue()` pause pass-through lets deposit/redeem/borrow/repay execute against a stale interest index, freezing accrued yield - (File: `mainnet/contracts/vault/v0-vault-usdc.clar` and equivalent `v0-vault-*.clar` vaults)

### Summary
Each vault (`v0-vault-usdc.clar`, `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`) gates its `accrue` logic behind a dedicated `accrue` flag inside `pause-states`, separate from the `deposit`, `redeem`, `borrow`, and `repay` flags. When `accrue` is paused, `accrue` short-circuits and returns the currently stored `index`/`lindex` unchanged instead of reverting or halting dependent operations. Every other public entrypoint (`deposit`, `redeem`, `system-borrow`, `system-repay`) unconditionally calls `(try! (accrue))` and then proceeds to mutate state (mint/burn zTokens, update `principal-scaled`, `total-borrowed`, `assets`) using whatever index value `accrue` returned - stale or not. Because those operations are pausable independently, an operator pausing only `accrue` (e.g. to freeze interest computation while investigating an issue) leaves the economic pricing (`index`, `lindex`) frozen while value-moving operations continue to execute at that frozen rate.

### Finding Description
`accrue` in `mainnet/contracts/vault/v0-vault-usdc.clar` (and identically in the sibling vaults): [1](#0-0) 
```
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ...
```
This mirrors the exact pattern in `v0-vault-stx.clar`, `v0-vault-ststx.clar`, `v0-vault-sbtc.clar`, `v0-vault-usdh.clar`, and `v0-vault-ststxbtc.clar`. [2](#0-1) [3](#0-2) 

`system-borrow`, `system-repay`, `deposit`, and `redeem` each call `(try! (accrue))` and, regardless of whether real accrual happened, continue to compute scaled amounts (`mul-div-up amount INDEX-PRECISION idx`, share conversions, etc.) and mutate `principal-scaled`/`total-borrowed`/`assets`: [4](#0-3) 

`pause-states` stores independent boolean flags (`accrue`, `deposit`, `redeem`, `borrow`, `repay`), so pausing `accrue` alone does not block the other operations - they simply consume the pass-through, unmutated `index`/`lindex`: [5](#0-4) 

This is the exact "pause that passes through instead of reverting" bug class: a cached value (`index`/`lindex`, and derived `last-update`) that is bound at the top of `accrue`, an invalidating event (real accrual being skipped because `accrue` is paused), and a later use (share/debt conversions in `deposit`/`redeem`/`system-borrow`/`system-repay` within the same or a subsequent transaction) that treats the frozen value as current.

### Impact Explanation
While `accrue` is paused but the other operations remain active:
- Interest that should accrue on outstanding debt does not accrue, and the yield that should flow to liquidity providers (via `treasury-lp` mint and index growth) is skipped for the duration of the pause.
- Depositors/redeemers transact at a stale exchange rate (`index`/`lindex`) instead of the economically correct one, meaning any interest that should have compounded into share pricing during the pause window is not reflected — this is a temporary freezing of unclaimed yield for existing suppliers, since the yield that should have accrued during the pause is not captured in the share price at the time users interact with the vault.
- Because `last-update` is only advanced when the computed index actually changes, once `accrue` is unpaused the next real accrual call computes interest for the entire elapsed period (pre-pause + paused window + post-pause) in one jump, meaning value distribution/pricing during the pause window itself was determined by the stale, frozen index rather than the correct one — a genuine but temporary distortion of yield distribution among depositors who transact during the pause.

This lands in the "temporary freezing of unclaimed yield" bucket of the in-scope High impact class.

### Likelihood Explanation
The trigger requires the DAO/operator to pause `accrue` specifically (via `set-pause-states` on any vault) without also pausing `deposit`/`redeem`/`borrow`/`repay` on that same vault. This is an operationally plausible but narrow scenario (a partial pause), and its likelihood is inherently governance/operator-dependent rather than attacker-triggered, which lowers the overall likelihood relative to a purely on-chain adversarial path. The mechanism itself, however, is fully reachable under normal Clarity evaluation order without any additional preconditions once that partial-pause state exists.

### Recommendation
Either (a) make `accrue` revert (return an error) instead of pass-through when paused, so that dependent operations (`deposit`, `redeem`, `borrow`, `repay`) also fail fast and cannot execute against a stale index, or (b) make the `deposit`/`redeem`/`borrow`/`repay` pause flags imply/require the `accrue` flag to be unset (i.e., validate that `accrue` is not paused before allowing these operations to proceed), ensuring interest/index freezing can never be decoupled from value-moving operations.

### Proof of Concept
1. DAO calls `set-pause-states` on `v0-vault-usdc.clar` with `{ accrue: true, deposit: false, redeem: false, borrow: false, repay: false }`.
2. Time passes (blocks advance), so the "true" index/lindex (if accrual ran) would be higher than the stored `index`/`lindex`.
3. A user calls `redeem` (or `deposit`). Inside, `(try! (accrue))` hits the `accrue` paused branch and returns the old, stale `{ index: idx, lindex: lidx }` unchanged: [1](#0-0) 
4. `redeem`/`deposit` continue using `convert-to-assets-preview`/share math derived from the stale `lindex`, minting/burning shares and moving underlying assets at a rate that does not reflect the yield that should have accrued during the pause window.
5. When the DAO later unpauses `accrue`, the very next `accrue()` call jumps the index to reflect the full elapsed time, but the value transferred to users who interacted during the pause was priced off the stale rate, temporarily freezing/misallocating the yield that should have been reflected during that window.
