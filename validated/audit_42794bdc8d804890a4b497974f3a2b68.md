### Title
Pending-transaction disclosure endpoints enable AssetIssueContract name front-running / token-name squatting - ([File: framework/src/main/java/org/tron/core/services/http/GetTransactionFromPendingServlet.java])

### Summary
`GetTransactionFromPendingServlet.doGet`/`doPost` calls `Manager.getTxFromPending(String txId)` and `GetTransactionListFromPendingServlet` calls `Manager.getTxListFromPending()`, both of which expose the full contents of unconfirmed transactions sitting in `pendingTransactions`/`rePushTransactions` to any unauthenticated HTTP caller. Because `AssetIssueActuator.validate()` rejects a new token issuance only if `assetIssueStore.get(name) != null` (i.e., only after the first issuance is actually committed), an attacker who reads a victim's pending `AssetIssueContract` name via these endpoints can race a competing issuance for the identical name before the victim's transaction is packed into a block.

### Finding Description
`GetTransactionFromPendingServlet.doGet` reads the `value` (txId) parameter and calls `manager.getTxFromPending(input)` [1](#0-0) , which serializes and returns the full unmined transaction (via `Util.printTransaction`), including its `AssetIssueContract` payload and the reserved token `name`. `Manager.getTxFromPending` walks the live `pendingTransactions` and `rePushTransactions` queues by transaction id and returns the matching `TransactionCapsule` with no authorization check tied to the transaction's owner [2](#0-1) . `Manager.getTxListFromPending` similarly enumerates all pending transaction ids, which an attacker can pair with `GetTransactionFromPendingServlet`/`GetTransactionByIdServlet` to enumerate and inspect every pending contract, including asset-issuance name reservations, before they are mined [3](#0-2) .

The uniqueness check for token names lives only in `AssetIssueActuator.validate()`, which throws `"Token exists"` if `dynamicStore.getAllowSameTokenName() == 0 && assetIssueStore.get(name) != null` [4](#0-3) . This check only consults the committed `assetIssueStore`, not the mempool — there is no reservation/lock on names for pending, unconfirmed transactions. The existing regression test `IssueSameTokenNameAssert` confirms the check strictly depends on whether the name is already persisted in `assetIssueStore`, with no notion of "who submitted first" beyond block inclusion order [5](#0-4) .

Exploit flow: (1) victim broadcasts a signed `AssetIssueContract` with a unique name and it lands in `pendingTransactions`; (2) attacker calls `GET /wallet/gettransactionlistfrompending` to enumerate pending tx ids, then `GET /wallet/gettransactionfrompending?value=<txId>` to read the full contract, including the reserved `name`; (3) attacker crafts and broadcasts their own `AssetIssueContract` with the identical name, paying normal issuance fees, and races to get it included in an earlier or same block ahead of/instead of the victim's; (4) if the attacker's transaction is committed first, `assetIssueStore.put` reserves the name for the attacker's account, and the victim's later-processed transaction with the same name fails `AssetIssueActuator.validate()` with `"Token exists"`, permanently squatting the name.

None of the standard defenses stop this: `TransactionCapsule.validateSignature` only verifies the attacker's own signature on their own competing transaction (which is valid, since they own their own account and pay the fee) — it does not protect the victim's name reservation. There is no rate limiter or size limit that meaningfully prevents enumeration of a small mempool. `ForkController` gates are unrelated to this logic path. The endpoints are also not behind any authorization/permission check tied to transaction ownership.

### Impact Explanation
This falls under the "unauthorized account operations" / "asset accounting corruption" bounty class: an unprivileged attacker can deny the legitimate first-mover exclusive right to a unique token name, and instead claim that name for themselves, by leveraging leaked mempool visibility to win a race that should be decided purely by transaction validity, fee, and honest block-inclusion order — not by information asymmetry created by the node's own pending-transaction disclosure APIs. The victim's transaction fails, and legitimate business/branding value tied to the asset name is misappropriated by the attacker. This does not involve theft of TRX or existing asset balances, but it does corrupt the integrity of the unique-name namespace and can be used for extortion/griefing against real projects issuing tokens.

### Likelihood Explanation
Preconditions are all attacker-reachable with no special privileges: `allowSameTokenName == 0` is the default/legacy mode referenced directly by the check in `AssetIssueActuator.validate()`; the victim only needs sufficient balance to pay the (currently non-zero, but fixed) issuance fee and to broadcast a normal signed transaction. The attacker needs only an ordinary funded TRON account to pay the competing issuance fee, and network access to the node's HTTP API (`gettransactionfrompending`, `gettransactionlistfrompending`) which are enabled by default with no authentication — only generic `RateLimiterServlet` throttling applies. The race itself (getting a competing tx included before/instead of the victim's) depends on network conditions and the attacker's ability to get faster/preferential inclusion, but this is a realistic and repeatable griefing/squatting attack pattern, not a one-off edge case, and it is fully reproducible with a JUnit test that exercises two `AssetIssueActuator` instances with identical names.

### Recommendation
- Restrict `GetTransactionFromPendingServlet`/`GetTransactionListFromPendingServlet` (and any pending-transaction/mempool inspection API) from exposing full contract payloads of transactions not owned by the requester, or disable/gate these endpoints by default (they primarily exist for node operators/debugging, not public API consumers).
- Alternatively/additionally, close the underlying race by reserving asset names atomically at admission into the mempool (not just at block-commit time) so that once a valid, signed `AssetIssueContract` for a given name is accepted into `pendingTransactions`, competing transactions for the same name are rejected at validation time regardless of pending queue visibility, removing the incentive to snoop the mempool.
- Consider redacting or truncating sensitive/unique-reservation fields (e.g., asset name) from pending-transaction disclosure responses until the transaction is confirmed.

@Test
public void pendingDisclosureEnablesNameSquat() throws Exception {
  dbManager.getDynamicPropertiesStore().saveAllowSameTokenName(0);

  // 1. Victim's AssetIssueContract enters pending (simulated by adding directly
  //    to dbManager.getPendingTransactions(), mirroring what pushTransaction does
  //    before block inclusion).
  AssetIssueContract victimContract = AssetIssueContract.newBuilder()
      .setOwnerAddress(ByteString.copyFrom(ByteArray.fromHexString(VICTIM_ADDRESS)))
      .setName(ByteString.copyFrom(ByteArray.fromString(NAME)))
      .setTotalSupply(TOTAL_SUPPLY).setTrxNum(TRX_NUM).setNum(NUM)
      .setStartTime(1).setEndTime(100)
      .build();
  TransactionCapsule victimTx = buildAssetIssueTx(victimContract);
  dbManager.getPendingTransactions().add(victimTx);

  // 2. Attacker reads pending contents via the same code path the servlet uses.
  TransactionCapsule leaked = dbManager.getTxFromPending(
      victimTx.getTransactionId().toString());
  AssetIssueContract leakedContract =
      leaked.getInstance().getRawData().getContract(0).getParameter()
          .unpack(AssetIssueContract.class);
  Assert.assertEquals(NAME, leakedContract.getName().toStringUtf8()); // leak confirmed

  // 3. Attacker submits and commits their own AssetIssueContract with the same name first.
  AssetIssueActuator attackerActuator = new AssetIssueActuator();
  attackerActuator.setChainBaseManager(dbManager.getChainBaseManager())
      .setAny(buildAssetIssueAny(ATTACKER_ADDRESS, NAME));
  TransactionResultCapsule attackerRet = new TransactionResultCapsule();
  attackerActuator.validate();          // succeeds: assetIssueStore has no entry yet
  attackerActuator.execute(attackerRet);
  Assert.assertEquals(code.SUCESS, attackerRet.getInstance().getRet());

  // 4. Victim's original transaction is now processed and fails.
  AssetIssueActuator victimActuator = new AssetIssueActuator();
  victimActuator.setChainBaseManager(dbManager.getChainBaseManager())
      .setAny(victimContract... /* same Any used for victimTx */);
  try {
    victimActuator.validate();
    Assert.fail("victim should be rejected due to name squat");
  } catch (ContractValidateException e) {
    Assert.assertEquals("Token exists", e.getMessage()); // confirms squat succeeded
  }
}

  public TransactionCapsule getTxFromPending(String txId) {
    AtomicReference<TransactionCapsule> transactionCapsule = new AtomicReference<>();
    Sha256Hash txHash = Sha256Hash.wrap(ByteArray.fromHexString(txId));
    pendingTransactions.forEach(tx -> {
      if (tx.getTransactionId().equals(txHash)) {
        transactionCapsule.set(tx);
        return;
      }
    });
    if (transactionCapsule.get() != null) {
      return transactionCapsule.get();
    }
    rePushTransactions.forEach(tx -> {
      if (tx.getTransactionId().equals(txHash)) {
        transactionCapsule.set(tx);
        return;
      }
    });
    return transactionCapsule.get();
  }

  public Collection<String> getTxListFromPending() {
    Set<String> result = new HashSet<>();
    pendingTransactions.forEach(tx -> {
      result.add(tx.getTransactionId().toString());
    });
    rePushTransactions.forEach(tx -> {
      result.add(tx.getTransactionId().toString());
    });
    return result;
  }

  public boolean validate() throws ContractValidateException {
    if (this.any == null) {
      throw new ContractValidateException(ActuatorConstant.CONTRACT_NOT_EXIST);
    }
    if (chainBaseManager == null) {
      throw new ContractValidateException(ActuatorConstant.STORE_NOT_EXIST);
    }
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    AssetIssueStore assetIssueStore = chainBaseManager.getAssetIssueStore();
    AccountStore accountStore = chainBaseManager.getAccountStore();
    if (!this.any.is(AssetIssueContract.class)) {
      throw new ContractValidateException(
          "contract type error,expected type [AssetIssueContract],real type[" + any
              .getClass() + "]");
    }

    final AssetIssueContract assetIssueContract;
    try {
      assetIssueContract = this.any.unpack(AssetIssueContract.class);
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }

    byte[] ownerAddress = assetIssueContract.getOwnerAddress().toByteArray();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid ownerAddress");
    }

    if (!TransactionUtil.validAssetName(assetIssueContract.getName().toByteArray())) {
      throw new ContractValidateException("Invalid assetName");
    }

    if (dynamicStore.getAllowSameTokenName() != 0) {
      String name = assetIssueContract.getName().toStringUtf8().toLowerCase(Locale.ROOT);
      if (("trx").equals(name)) {
        throw new ContractValidateException("assetName can't be trx");
      }
    }

    int precision = assetIssueContract.getPrecision();
    if (precision != 0
        && dynamicStore.getAllowSameTokenName() != 0
        && (precision < 0 || precision > ActuatorConstant.PRECISION_DECIMAL)) {
      throw new ContractValidateException("precision cannot exceed 6");
    }

    if ((!assetIssueContract.getAbbr().isEmpty()) && !TransactionUtil
        .validAssetName(assetIssueContract.getAbbr().toByteArray())) {
      throw new ContractValidateException("Invalid abbreviation for token");
    }

    if (!TransactionUtil.validUrl(assetIssueContract.getUrl().toByteArray())) {
      throw new ContractValidateException("Invalid url");
    }

    if (!TransactionUtil
        .validAssetDescription(assetIssueContract.getDescription().toByteArray())) {
      throw new ContractValidateException("Invalid description");
    }

    if (assetIssueContract.getStartTime() == 0) {
      throw new ContractValidateException("Start time should be not empty");
    }
    if (assetIssueContract.getEndTime() == 0) {
      throw new ContractValidateException("End time should be not empty");
    }

      throw new ContractValidateException("End time should be greater than start time");
    }
    if (assetIssueContract.getStartTime() <= dynamicStore.getLatestBlockHeaderTimestamp()) {
      throw new ContractValidateException("Start time should be greater than HeadBlockTime");
    }

        && assetIssueStore.get(assetIssueContract.getName().toByteArray())
        != null) {
