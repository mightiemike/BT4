Based on my investigation, I found a genuine rounding-direction mismatch analogous to the ERC5095 report, in the signer global-state quorum logic.

### Title
`GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use floor division instead of the ceiling rounding used for on-chain block-signature quorum, causing signer-side consensus to require a weaker threshold than the actual chain-enforced threshold - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
The chain-level rule for accepting a Nakamoto block requires signature weight to meet a *ceiling*-rounded 70% threshold, computed by `NakamotoBlockHeader::compute_voting_weight_threshold` [1](#0-0) , which is enforced by `verify_signer_signatures` when a block is accepted into the canonical chain [2](#0-1) . However, the signer-side `GlobalStateEvaluator::reached_agreement`/`reached_disagreement`, which determines the signers' shared off-chain view of the current miner, burn view, protocol version, and tx-replay set, use plain *floor* integer division of the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` constant instead of the ceiling used on-chain [3](#0-2) .

### Finding Description
`compute_voting_weight_threshold` computes `ceil(total_weight * 7 / 10)` (adds `1` when there is a remainder) [4](#0-3) . This is the threshold that governs whether a block is actually valid and accepted by nodes (`verify_signer_signatures`) [5](#0-4) .

`GlobalStateEvaluator::reached_agreement` instead computes `floor(total_weight * 7 / 10)` with no ceiling correction [6](#0-5) , and `reached_disagreement` similarly floors `total_weight * (10 - 7) / 10` [7](#0-6) . For any `total_weight` where `total_weight * 7` is not evenly divisible by 10 (e.g. `total_weight = 13` → floor gives `9`, ceiling gives `10`), the two computations diverge by exactly one unit of weight.

This threshold governs `determine_global_state`, `determine_global_burn_view`, and `capitulate_miner_view`, all of which decide which miner/tenure/burn-view the signer set treats as canonical and whether a signer capitulates its local view or rejects a block via `check_block_against_global_state` [8](#0-7)  and `capitulate_viewpoint`/`capitulate_miner_view` [9](#0-8) . Because the off-chain quorum accepted by `reached_agreement` is systematically weaker (by one weight unit whenever there's a remainder) than the on-chain quorum enforced by `compute_voting_weight_threshold`, a set of signers whose combined weight satisfies the *looser* floor threshold but not the *stricter* ceiling threshold can be judged by their peers to have reached "global agreement" on a miner/tenure/burn view that the actual block-acceptance rule would not yet recognize as having sufficient signatures.

### Impact Explanation
This narrows the intended safety margin between the signer approval quorum (70%) and Byzantine fault tolerance (30%). It does not require majority collusion — the divergence is deterministic and triggered simply by `total_weight` values whose product with 7 isn't a multiple of 10 (the common case). Two disjoint groups of signers can each independently satisfy the loosened `reached_agreement`/`reached_disagreement` floor thresholds where under the correct ceiling rule they would not, allowing the signer set's internal state machine (current miner/tenure view) to flip or disagree with the actual on-chain-enforced quorum. This can manifest as a temporary tip disagreement among signers/miners (they capitulate to different miner views) even though the ceiling-rounded chain rule for a block's actual acceptance is unaffected — bounding the impact to the signer coordination layer rather than causing a chain split at the consensus/block-storage level.

### Likelihood Explanation
High likelihood of divergence occurring in practice: any `total_weight` not evenly divisible into tenths of `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` (the vast majority of possible signer-weight totals) triggers the off-by-one gap between the two threshold formulas. No privileged access or majority collusion is needed to trigger the divergence itself — it is a deterministic consequence of the signer-weight distribution for a reward cycle, and is exercised on every call to `reached_agreement`/`reached_disagreement`.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` use the same ceiling-rounding logic as `NakamotoBlockHeader::compute_voting_weight_threshold` (ideally by calling that shared function directly) so the signer-side global-state quorum and the on-chain block-acceptance quorum are guaranteed to agree bit-for-bit.

### Proof of Concept
1. Configure a reward cycle where `total_weight = 13` (e.g., 13 signers each with weight 1, or any combination summing to 13).
2. `compute_voting_weight_threshold(13)` returns `ceil(13*7/10) = ceil(9.1) = 10`.
3. `GlobalStateEvaluator::reached_agreement` with `total_weight = 13` returns true once `vote_weight >= floor(13*7/10) = 9`.
4. A group of exactly 9 out of 13 signers (69.2%) can cause `determine_global_state`/`determine_global_burn_view` to report "global agreement" reached, and drive `capitulate_miner_view` to switch signers to a new miner/tenure view, even though this 9/13 weight would be insufficient to actually get a block accepted on-chain via `verify_signer_signatures`, which requires 10/13. This produces a state where the signer set's coordinated view of the canonical miner diverges from what the chain-enforced signature-threshold rule would accept, a temporary tip/view disagreement bounded to the signer-coordination layer.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.

        u64::from(vote_weight)
