### Title
Unbounded gzip Decompression of Declare V1 Cairo0 Program in RPC Node - (File: crates/apollo_rpc/src/v0_8/api/mod.rs)

### Summary
`decompress_program()` in `crates/apollo_rpc/src/v0_8/api/mod.rs` decompresses the base64+gzip-encoded Cairo0 `program` field of a `BroadcastedDeclareV1Transaction` into an unbounded in-memory `Vec<u8>`, with no cap on the decompressed size or decompression time. This is the same bug class as the Rekor `GHSA-47q9-m4ww-924m` advisory: a `GzDecoder` reading fully to `read_to_end` with no `.take()` limit, driven by unauthenticated, attacker-controlled input. [1](#0-0) 

### Finding Description
`decompress_program` base64-decodes the client-supplied `compressed_program` string and feeds it straight into `flate2::bufread::GzDecoder`, then calls `decoder.read_to_end(&mut decompressed)` with an explicit `// TODO(dan): add time and size limits.` comment acknowledging the missing guard: [1](#0-0) 

This is invoked when converting a `BroadcastedDeclareV1Transaction` (submitted by any client via the RPC server's `addDeclareTransaction`, `estimateFee`, or `simulateTransactions` methods) into `ExecutableTransactionInput::DeclareV1`, as exercised in `execution_test.rs`'s `broadcasted_to_executable_declare_v1` test, which sets `tx.contract_class.compressed_program` and converts the broadcasted transaction via `TryInto`. [2](#0-1) 

The codebase elsewhere already fixed this exact bug class for Sierra/CASM classes and Cairo0 legacy declares in the protobuf/gateway path via `decode_and_decompress_with_size_limit`, which bounds the decompressor with `.take((max_size + 1) as u64)` before reading: [3](#0-2) 
and is used for gateway-submitted Sierra contract classes and protobuf-converted Cairo0 classes: [4](#0-3) [5](#0-4) 

However, `decompress_program` in the RPC v0_8 API layer was never migrated to this bounded helper and remains fully unbounded.

### Impact Explanation
An unauthenticated caller of the JSON-RPC server can submit a `BroadcastedDeclareV1Transaction` (or use it in `estimateFee`/`simulateTransactions`) with a `compressed_program` value that is a small gzip bomb (e.g., a few MB compressed expanding to hundreds of MB or GB). Because the decompression is fully in-memory with no size cap, this can exhaust node heap memory and crash or OOM-kill the RPC/sequencer process, causing denial of service for a node serving RPC traffic — impacting the node's ability to process/confirm transactions submitted through it.

### Likelihood Explanation
High: the endpoint accepting `BroadcastedDeclareV1Transaction` is reachable without authentication or fee payment (declare v1 broadcasted transactions used for gas estimation/simulation, and add-transaction flows), and crafting a high-ratio gzip payload is trivial and cheap for an attacker.

### Recommendation
Replace the manual `GzDecoder::new(...).read_to_end(...)` call in `decompress_program` with the existing bounded helper `decode_and_decompress_with_size_limit` (or equivalently wrap the decoder with `.take(max_size + 1)` and reject if the result exceeds the configured max program size), mirroring the fix already applied to the Sierra and protobuf Cairo0 class conversion paths. [1](#0-0) [3](#0-2) 

### Proof of Concept
1. Craft a gzip stream of highly compressible data (e.g., `gzip -9` over a large run of zero bytes) achieving a very high compression ratio (~1000:1), producing e.g. a ~2MB compressed payload expanding to ~2GB decompressed.
2. Base64-encode the compressed bytes and place them into the `program` field of a `BroadcastedDeclareV1Transaction`'s `contract_class`.
3. Submit this broadcasted transaction to the JSON-RPC node via any method that accepts `BroadcastedTransaction` (e.g. `starknet_estimateFee`, `starknet_simulateTransactions`, or the declare-submission flow) so that it is converted through `TryFrom<BroadcastedTransaction>` into `ExecutableTransactionInput::DeclareV1`, invoking `decompress_program`.
4. Observe the RPC node's memory usage spike unbounded as `decoder.read_to_end(&mut decompressed)` runs to completion regardless of size, causing OOM/crash. [1](#0-0) [2](#0-1)

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
