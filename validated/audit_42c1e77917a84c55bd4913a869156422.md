Based on the investigation, I found a legitimate analog of this issue in java-tron's witness reward distribution logic.

### Title
Witness block/standby rewards earned while a witness's vote count is zero are permanently lost and never distributed to any voter - (File: `chainbase/src/main/java/org/tron/core/store/DelegationStore.java`, `chainbase/src/main/java/org/tron/core/service/MortgageService.java`)

### Summary
### Finding Description
java-tron distributes witness (SR) block/standby rewards to voters proportionally to their vote share, using an accumulator design directly analogous to the reported `rewardPerTokenStored`/`totalSupply()==0` pattern. Every block, `Manager.payReward()` unconditionally credits a witness with block-production and transaction-fee rewards via `MortgageService.payBlockReward`/`payTransactionFeeReward`, which call `delegationStore.addReward(cycle, witnessAddress, value)` [1](#0-0) . This reward accumulation happens regardless of the witness's current vote total.

At each maintenance cycle boundary, `MaintenanceManager.doMaintenance()` converts the accumulated per-cycle reward into a per-vote index ("Vi") using the witness's vote count for that just-completed cycle: `delegationStore.accumulateWitnessVi(curCycle, witness.createDbKey(), witness.getVoteCount())` [2](#0-1) . Inside `accumulateWitnessVi`, if `voteCount == 0` (the direct analog of `totalSupply() == 0`), the accumulated reward for that cycle is dropped — the code simply forwards the previous Vi value instead of folding the reward into it:
```java
public void accumulateWitnessVi(long cycle, byte[] address, long voteCount) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      ...
    }
}
``` [3](#0-2) 

The same "skip if totalVote==0" pattern also exists in the legacy reward algorithm, `MortgageService.computeReward(cycle, votes)`:
```java
long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
if (totalVote == DelegationStore.REMARK || totalVote == 0) {
  continue;
}
``` [4](#0-3) 

In both algorithms, once a cycle's reward is skipped because `voteCount`/`totalVote` was `0`, there is no other code path that later reclaims or redistributes that reward — the `reward` value stored by `addReward` for that cycle remains in the store, but it is never folded into the Vi accumulator that voters use to claim their share via `withdrawReward`/`queryReward` (`MortgageService.withdrawReward`/`queryReward`, `VoteRewardUtil.withdrawReward`/`queryReward`) [5](#0-4) [6](#0-5) .

### Impact Explanation
An active, block-producing witness earns rewards continuously via `payReward` regardless of its live vote count. The vote count used to convert that cycle's reward into distributable Vi is the value recorded from *before* the maintenance recalculation — i.e., the vote count as it stood through the just-finished cycle. If all of a witness's voters withdraw their votes/stake (e.g., via `UnfreezeBalanceV2Actuator`/`UnfreezeBalanceV2Processor`, which reduce or clear `AccountCapsule` votes [7](#0-6) ) such that the witness's effective vote count reaches `0` while it remains in the currently active/standby witness set (the active set is only re-derived at the next maintenance boundary), then every block/standby reward earned by that witness during the remainder of that cycle is permanently dropped when `accumulateWitnessVi`/`computeReward` runs at the next maintenance. No voter ever receives credit for that period's reward, and there is no recovery mechanism — the value is effectively burned/stuck in accounting with no path to being claimed.

### Likelihood Explanation
This requires an unprivileged, realistic sequence of events: normal TRX holders calling unfreeze/vote-withdrawal operations can drive a witness's tallied vote count to zero for a cycle while the witness is still active and producing blocks (since the active SR set updates only at maintenance boundaries). No privileged role is needed — it is triggerable purely through standard voting/unfreezing actions by unprivileged accounts, making it more than theoretical, though it does require a specific but plausible sequence (mass unvoting of a marginal/standby SR) rather than being trivially exploitable at will.

### Recommendation
Instead of silently dropping the reward when `voteCount == 0`, forward the undistributed reward amount to the next cycle's reward pool for that witness (or to a globally recoverable pool) so it can still be distributed once the witness regains nonzero votes, mirroring the fix recommended in the original report (track/roll-over undistributed rewards rather than discarding them).

### Proof of Concept
1. Witness `W` is an active SR and accrues block rewards each block via `Manager.payReward()` → `MortgageService.payBlockReward()` → `delegationStore.addReward(cycle, W, value)`.
2. Within the current cycle, all voters call unfreeze/vote-withdrawal (`UnfreezeBalanceV2Actuator`), reducing `W`'s tallied `voteCount` to `0`. `W` remains in the active witness set until the next `MaintenanceManager.doMaintenance()` call.
3. `W` continues to produce blocks and accrue reward (`addReward`) for the rest of the cycle while `voteCount` is `0`.
4. At the next maintenance, `accumulateWitnessVi(curCycle, W, 0)` is invoked; since `voteCount == 0`, the accumulated reward for that cycle is discarded (`preVi` is simply forwarded), per `DelegationStore.accumulateWitnessVi` lines 133-146.
5. No former voter of `W` can ever claim that cycle's reward via `withdrawReward`/`queryReward`, since the Vi delta was never recorded — the reward is permanently lost.

  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }

    BigInteger preVi = getWitnessVi(cycle - 1, address);
