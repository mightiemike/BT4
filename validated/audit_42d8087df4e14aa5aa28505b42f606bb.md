The reported issue concerns Solidity smart-contract code (`InfiltrationPeriphery.sol`'s `_healRequestFulfilled` function using `healingAgentIds[i.unsafeAdd(1)]`), which has no structural analog in protobuf-go. Searching protobuf-go's decode paths for the same broken invariant (array indexing without bounds checks) shows that all relevant array/buffer access sites are guarded:

- `BufferReader.DecodeVarint`/`DecodeVarint32` explicitly check `i >= len(buf)` before indexing into the buffer. [1](#0-0) 
- `buildIndex` in `internal/protolazy/lazy.go` bounds-checks (`i >= len(buf)`) before reading tag bytes and returns `errOutOfBounds` otherwise. [2](#0-1) 
- `lookupField` iterates the index slice using safe range-based access (`i < len(index)-1`) rather than unchecked pointer arithmetic. [3](#0-2) 
- The generic message decode loop in `internal/impl/decode.go` checks `n < 0` after every `ConsumeVarint`/`ConsumeBytes` call before advancing/slicing `b`. [4](#0-3) 
- Repeated-field codec functions (e.g. `consumeInt32Slice`, `consumeInt64Slice`) check `n < 0` before using it to slice the buffer. [5](#0-4) 

No reachable unprivileged decode path (default binary or ProtoJSON parser, trusted schema) exposes an unchecked array index analogous to the reported `healingAgentIds[i.unsafeAdd(1)]` pattern. Per the rules, this is a different project's Solidity-specific bug class with no matching broken invariant in protobuf-go's production code.
