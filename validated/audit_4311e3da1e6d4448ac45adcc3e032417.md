## Analysis

This is a legitimate native analog of the Lockbox V2 "ineffective slippage control" bug class, found in Push Chain's inbound gas-swap flow.

### Title
Self-referential spot-price slippage bound in `CallPRC20DepositAutoSwap` allows sandwich-attack value extraction on GAS/GAS_AND_PAYLOAD inbounds and gas refunds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Whenever Push Chain executes a `GAS` or `GAS_AND_PAYLOAD` inbound, or refunds unused destination-chain gas, the `uexecutor` keeper auto-swaps the deposited PRC20 for native PC via Uniswap V3. The "slippage protection" (`minPCOut`) is derived entirely from a live spot-price quote (`GetSwapQuote` → `QuoterV2.quoteExactInputSingle`) fetched immediately before the swap executes, rather than from a value the depositing user pre-agreed to at a fair, unmanipulated price [1](#0-0) . Just like the Lockbox V2 report, this is a self-referential bound: an unprivileged attacker who moves the pool price beforehand causes both the "quote" and the "protection" to be computed off the manipulated price, so the check enforces nothing meaningful against the manipulation itself — it only guards against a *second* movement beyond 5%.

### Finding Description
The relevant computation appears identically in three call sites:

1. `ExecuteInboundGas` (GAS inbound top-up): [2](#0-1) 

2. `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound): [3](#0-2) 

3. `applyGasRefund` (unused-gas refund after outbound observation): [4](#0-3) 

In all three, `GetSwapQuote` performs a static call to Uniswap V3's `QuoterV2.quoteExactInputSingle`, which reflects the pool's *current* `sqrtPriceX96` [5](#0-4) . The result is immediately discounted by a fixed 5% and passed straight into `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, which perform the real swap on the same pool at essentially the same moment [6](#0-5) . There is no external, pre-committed, user- or governance-supplied reference price and no TWAP — the entire bound is a percentage of the instantaneous, attacker-influenceable pool state.

Since the pool (`UNIVERSAL_CORE`/`WPC` Uniswap V3 pair) is a normal on-chain AMM reachable by any account, an unprivileged attacker can, in the same block as the inbound-finalization/refund transaction:
1. Swap a large amount into/out of the WPC/PRC20 pool to skew the spot price against the pending deposit's swap direction.
2. Let the module's `ExecuteInboundGas`/`applyGasRefund` fetch its quote and compute `minPCOut` off this already-skewed price — the 5% margin is applied on top of the manipulated number, so it still passes.
3. Have the module's swap execute at the attacker-skewed price, extracting value from the pool at the depositor's expense.
4. Reverse the initial swap to restore price and realize profit, while the depositor's PRC20 was converted to PC at an unfair rate.

This mirrors the report's core flaw precisely: "the function using the current onchain price to determine the requested [output], which can be manipulated by an attacker."

### Impact Explanation
Successful exploitation causes ordinary cross-chain depositors (anyone bridging funds for `GAS`/`GAS_AND_PAYLOAD` inbounds) to receive less native PC than the fair market rate would produce, with the difference captured by the attacker — a direct, unprivileged-triggerable value-extraction/fund-loss path from protocol-mediated swaps, matching the in-scope impact of "corruption of ... gas fee accounting, refund accounting ... PRC20 or native asset accounting" and unauthorized value drain from user-controlled funds during universal execution.

### Likelihood Explanation
Moderate-to-high: it requires only ordinary, permissionless interaction with the on-chain Uniswap V3 pool (swap transactions), no validator, relayer, or admin privilege, and no cryptographic bypass — only the ability to place transactions around the block in which the module-triggered swap executes. The 5% fixed slippage margin actually widens the attacker's profitable manipulation window rather than closing it, since 5% is a large tolerance for a single-block price move on a thinly-traded PRC20/WPC pair.

### Recommendation
Do not derive `minPCOut` purely from a spot quote taken in the same execution as the swap. Options:
- Use a manipulation-resistant reference price (e.g., a time-weighted average price/TWAP oracle over multiple blocks) to bound acceptable output, rather than `QuoterV2`'s instantaneous quote.
- Cap the deposit/swap size relative to available pool liquidity, or route through pools with sufficient depth/oracle protections.
- Consider using a protocol-governed, periodically-updated reference exchange rate (similar to the existing `ChainMeta`/`GasPrice` oracle pattern already used elsewhere in `uexecutor`) instead of trusting the AMM's live price at the moment of execution.
- At minimum, tighten the slippage tolerance and add sanity bounds comparing the quote against a longer-window reference price, rejecting execution (and instead reverting/queuing) if deviation exceeds a safe threshold.

### Proof of Concept
1. Attacker observes a pending `GAS` inbound in `uexecutor` state (public UTX data) about to reach quorum/finalization.
2. Immediately before the block in which `ExecuteInboundGas` will run its auto-swap, attacker sends a large swap on the PRC20/WPC Uniswap V3 pool in the direction that depresses the PRC20 price.
3. `GetSwapQuote` (`x/uexecutor/keeper/evm.go` `GetSwapQuote`) returns a depressed `amountOut`; `minPCOut = quote * 95 / 100` is computed off this depressed value.
4. `CallPRC20DepositAutoSwap` executes the deposit-triggered swap against the still-depressed pool, satisfying `minPCOut` easily while yielding far less PC than the depositor should have received at the undisturbed market price.
5. Attacker reverses their initial swap, restoring the price and capturing the spread as profit — funded by the value lost by the honest cross-chain depositor.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
```
