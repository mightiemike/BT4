This confirms the analog is real and reachable. There is no upper bound on `UniversalPayload.GasLimit` in `ValidateBasic` (only checks it's a non-negative uint256) [1](#0-0) , and zero-amount `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` inbounds with `isCEA=true` are explicitly permitted, skipping any deposit while still executing the attacker-supplied payload against an attacker-controlled recipient contract [2](#0-1) . The CEA smart-contract execution path calls the attacker's contract via `CallExecuteUniversalTx` inside a `CacheContext` and only afterward attempts to bill the recipient's native balance via `DeductGasFeesFromReceipt`, discarding just the state changes (not the computation already spent) when billing fails [3](#0-2) .

### Title
Free, attacker-triggered EVM computation via zero-cost CEA payload execution with unbounded, unbilled `GasLimit` - (File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go)

### Summary
This is the closest Push Chain analog to the UNCX gas-siphoning report. The auto-collector's "protocol pays gas, caller picks the target contract" pattern maps to Push Chain's module-originated `CallExecuteUniversalTx`/`CallUEAExecutePayload` flow, where the `uexecutor` module account (not the attacker) issues a real, gas-metered `DerivedEVMCall` against an attacker-chosen contract and attacker-chosen `GasLimit`, and cost recovery is attempted only after the call executes.

### Finding Description
An unprivileged attacker can:
1. Deploy an arbitrary "recipient" contract on any registered source chain with an `executeUniversalTx`-compatible fallback that burns large amounts of gas (loops, storage writes, etc.).
2. Emit a normal, honestly-observed source-chain event referencing that contract as `Recipient`, with `IsCEA=true`, `TxType=GAS_AND_PAYLOAD` (or `FUNDS_AND_PAYLOAD`), `Amount="0"`, and `UniversalPayload.GasLimit` set to an arbitrarily large value (tests in this repo use `21000000`) [4](#0-3) .
3. `ValidateForExecution` explicitly allows zero-amount `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` inbounds to skip the deposit step while still executing the payload [5](#0-4) , and `UniversalPayload.ValidateBasic` never bounds `GasLimit` against any protocol maximum — it is only checked to be a non-negative integer [1](#0-0) .
4. Once honest Universal Validators reach quorum on the inbound (an ordinary, unprivileged voting flow), `ExecuteInboundGasAndPayload` detects the recipient is a smart contract (not a UEA) and unconditionally calls `CallExecuteUniversalTx` as the module account inside a `CacheContext`, spending real EVM gas/computation up to the attacker-chosen `GasLimit` [6](#0-5) .
5. Fee recovery is attempted only afterward via `DeductGasFeesFromReceipt`, which bills the recipient contract's native `upc` balance. Since the attacker never funded the contract (amount is 0, and native balance is separate from any PRC20 deposit), this billing step deterministically fails every time, and only the *EVM state changes* are rolled back via `writeCache()` not being called — the CPU/computation cost incurred by validators processing the `DerivedEVMCall` is not refunded or avoided [7](#0-6) .
6. This exact "free execution gap" is documented in the code as a known concern (`F-2026-16738`) but the fix only ensures the recipient's *state mutation* doesn't survive unpaid execution — it does not prevent or bound the computational cost from being spent by validators in the first place [8](#0-7) .

### Impact Explanation
This is a compute/gas-griefing analog to the reported bug class: the protocol (via the `uexecutor` module account) is induced to spend real, metered EVM execution against attacker-chosen bytecode and an attacker-chosen gas ceiling, at zero cost to the attacker (no deposit required, no native balance required, and the Cosmos-level vote messages themselves are gasless for Universal Validators). Repeated submission of such zero-value inbounds from many source chains can impose sustained, unbounded computational load on every validator processing blocks, which is an unprivileged-triggered, non-network-level DoS vector reachable through ordinary deposit/payload submission — squarely within the "denial of service...reachable without privileged control" allowed impact.

### Likelihood Explanation
High: no privileged access or malicious validator/relayer collusion is required. The attacker only needs to control a contract on any registered source chain and emit one low-cost transaction; honest Universal Validators observing and voting on that event (their designed, intended behavior) is sufficient to trigger the module-originated call. The `GasLimit` and zero-amount paths are both explicitly supported and tested in the current codebase, showing this is a live, reachable pattern rather than a hypothetical one.

### Recommendation
- Enforce an upper bound on `UniversalPayload.GasLimit` for module-originated CEA/UEA calls (e.g., cap to a small multiple of standard call overhead) in `UniversalPayload.ValidateBasic` or `ValidateForExecution`.
- For CEA smart-contract recipients, verify the recipient has sufficient native `upc` balance (or require a bonded/pre-paid gas escrow) to cover the *worst-case* cost of `GasLimit` before invoking `CallExecuteUniversalTx`, rather than attempting cost recovery only after the call executes.
- Consider metering/throttling module-account-initiated derived calls per block/epoch so a single attacker cannot force unbounded validator computation through repeated zero-value CEA inbounds.

### Proof of Concept
1. Deploy a contract on a registered source chain (e.g., Sepolia) whose `executeUniversalTx`-style entrypoint contains a gas-intensive loop (e.g., repeated `SSTORE`s) bounded only by the gas forwarded.
2. Emit a deposit-style event with `Recipient = <malicious contract>`, `IsCEA = true`, `TxType = GAS_AND_PAYLOAD`, `Amount = "0"`, and `UniversalPayload.GasLimit = "21000000"` (as used in `test/integration/uexecutor/inbound_zero_amount_test.go:350-382`).
3. Have 3+ honest validators vote via `MsgVoteInbound` (gasless, as in the existing integration test harness).
4. Observe: `ExecuteInboundGasAndPayload` invokes `CallExecuteUniversalTx` against the malicious contract with the full attacker-chosen gas limit; `DeductGasFeesFromReceipt` fails (contract has zero `upc`), the PCTx is marked `FAILED`, but the module account/validators have already paid the real computational cost of executing the call.
5. Repeat with many source-chain transactions to amplify aggregate validator compute cost at negligible attacker cost.

func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
