## Finding: Unbounded native-Rust recursion when hashing a declared contract's bytecode-segment tree (analogous to CVE-2017-15595's crafted-structure stack-consumption bug)

### Title
Unbounded recursion in bytecode-segment hashing of an attacker-declared class can stack-overflow the sequencer's non-sandboxed process - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
CVE-2017-15595 is a bug class where an unprivileged actor supplies a crafted, deeply-nested structure (page tables) that a privileged component processes with unbounded, non-tail recursion, exhausting the native call stack and crashing the process. The sequencer contains a structurally identical pattern: a `Declare` transaction's Sierra program is compiled to CASM, and the resulting `bytecode_segment_lengths` tree (a `NestedIntList`) is then hashed with a plain recursive function that has no depth bound, running directly in the gateway/sequencer process rather than inside the resource-limited compiler subprocess.

### Finding Description
When a class is declared, compilation (the CPU-heavy step) is executed in a sandboxed subprocess with CPU/memory limits via `SierraToCasmCompiler::compile` [1](#0-0) , applied through `ResourceLimits`/`compile_with_args` [2](#0-1) .

However, immediately after the subprocess returns the compiled `CasmContractClass`, the sequencer computes the compiled-class hash **in-process, unsandboxed**: [3](#0-2) 

That hash computation walks the CASM's `bytecode_segment_lengths` (a `NestedIntList`) with a plain, non-tail recursive function that has no explicit depth limit: [4](#0-3) 

The `bytecode_segment_lengths` tree is produced by the Sierra→CASM compiler based on the *declarer-supplied* Sierra program's function/branch structure — it is untrusted, attacker-influenced data. The only limit enforced on it is a flat felt-count cap (`max_bytecode_size`, default 81920) [5](#0-4) , not a bound on the *nesting depth* of the segment tree. A contract crafted to maximize segment nesting (e.g., many small nested function/branch bodies) can therefore produce a `NestedIntList` whose depth is large relative to the recursion's stack-frame cost, while still satisfying the flat bytecode-size limit.

The same unguarded recursive-descent pattern also exists in the Starknet OS hint implementation that reconstructs this tree during block building / OS re-execution: [6](#0-5) 

This is functionally distinct from the blockifier's `RecursionDepthGuard`, which only bounds *Cairo entry-point call* recursion inside VM/Sierra-gas-metered execution [7](#0-6) . That guard does not protect this native Rust recursion, which runs entirely outside Cairo step/gas metering and outside the compiler subprocess's resource limits.

### Impact Explanation
If the recursion depth is large enough relative to the process's stack size, the gateway (or later, the block builder / OS re-execution / full node performing re-execution) crashes with a native stack overflow while processing a single `Declare` transaction — a class-declarer-triggerable denial of service. Because the hash is (re-)computed at multiple points (declare-time in the gateway, block building, and OS re-execution/verification), a single malicious declared class can repeatedly crash any component that re-derives the compiled-class hash, potentially preventing the network from confirming or re-validating blocks containing (or referencing) that class — consistent with "a network unable to confirm new transactions."

### Likelihood Explanation
Reachable by any account capable of submitting a `Declare` transaction (no special privileges needed) — the gateway compiles and hashes every submitted class before/while admitting it to the mempool. The compilation subprocess is isolated, but the hashing step that walks the untrusted segment tree is not, so the mitigation that exists for CPU/memory exhaustion during compilation does not cover this stack-depth vector. Practical exploitability depends on how deeply the external Sierra→CASM compiler (`cairo_lang_starknet_classes`) will nest segments for a crafted program within the 81920-felt limit; this repo does not implement or bound that nesting depth, so no protection currently exists regardless of the achievable depth.

### Recommendation
- Add an explicit recursion/tree-depth limit when validating a compiled class's `bytecode_segment_lengths` before hashing it (reject classes whose segment tree exceeds a safe depth), enforced both at declare-time and wherever the OS/blockifier reconstructs or hashes this structure.
- Convert `bytecode_hash_node` (and `create_bytecode_segment_structure_inner`, `get_visited_segments`) to explicit iterative/worklist algorithms instead of unbounded native recursion, so depth is no longer bounded by stack size.
- If recursion must be kept, run the hashing step (not just compilation) inside the same resource-limited subprocess/sandbox used for compilation, or run it on a thread with a bounded, monitored stack that fails gracefully instead of crashing the process.

### Proof of Concept
Not runnable without access to the external `cairo_lang_starknet_classes` compiler's exact segmentation heuristics (which determine how deeply `bytecode_segment_lengths` nests for a given Sierra program). Conceptually: craft a Sierra program (within `max_bytecode_size` felts) composed of many deeply/sequentially nested small functions or branches so that the compiler's bytecode segmentation produces a maximally-nested `NestedIntList`; submit it as a `Declare` transaction; observe that `SierraCompiler::compile`'s in-process call to `executable_class.hash(&HashVersion::V2)` (via `bytecode_hash_node`) recurses to the tree's depth and crashes the gateway process with a native stack overflow instead of returning a compilation/validation error.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}

// Implementing the Drop trait to decrement the recursion depth when the guard goes out of scope.
impl Drop for RecursionDepthGuard {
    fn drop(&mut self) {
        *self.current_depth.borrow_mut() -= 1;
    }
}
