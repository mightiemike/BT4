I now have sufficient evidence to write the final analysis. The confirmed analog is: `GlobalContractDeployMode::AccountId` lets a single account (reachable by any unprivileged transaction signer) redeploy code referenced by `GlobalContractIdentifier::AccountId`, and every account that previously executed `UseGlobalContractAction`/`UseGlobalContractByAccountId` against that identifier will silently run whatever new code is redeployed under that account id — exactly the "mutable pointer to shared logic that a single non-fully-trusted party can rewrite after other parties have already committed to it" pattern in the Fei report.

### Title
Global contract redeploy under `GlobalContractDeployMode::AccountId` lets the publisher silently swap code already relied on by other accounts, enabling rug-pull of funds/logic controlled by `GlobalByAccount` references - (File: `runtime/runtime/src/global_contracts.rs`)

### Summary
A `GlobalContractDeployMode::AccountId` global contract is referenced by accounts via `AccountContract::GlobalByAccount(AccountId)` [1](#0-0)  rather than by an immutable code hash. Any account can later re-issue `DeployGlobalContractAction` with `AccountId` mode to overwrite the code that all other accounts referencing it via `UseGlobalContractAction`/`UseGlobalContractByAccountId` continue to run, without those referencing accounts taking any new action or consenting again.

### Finding Description
The docs explicitly describe this as a mutable-reference design: "Contract is deployed under the owner account id. Users will be able reference it by that account id. This allows the owner to update the contract for all its users." [2](#0-1) 

`action_use_global_contract`/`use_global_contract` sets the account's contract to `AccountContract::GlobalByAccount(id)` when the identifier is `GlobalContractIdentifier::AccountId` [3](#0-2) . At execution time, code for a `GlobalByAccount` account is resolved dynamically through `GlobalContractIdentifier::hash`/`code`, which look up the *current* trie entry for that identifier (i.e., whatever was most recently deployed under that account id), not a value pinned at the time the referencing account called `UseGlobalContract` [4](#0-3) . The `test_global_contract_update` test confirms this end-to-end: accounts that already called `UseGlobalContract` against an `AccountId` identifier see their calls immediately reflect a contract redeployed later by the owner, going from `MethodNotFound` to full success purely because the owner republished code under the same identifier [5](#0-4) .

This is directly analogous to `FlywheelCore.setBooster()`: a role that is not the protocol/validator set, but is "authorized" only in the narrow sense of being the original contract's deployer, can unilaterally rewrite the shared logic (`boostedBalanceOf`/global contract code) that other independent accounts have already opted into and built value-bearing logic or trust relationships on top of, without any timelock, versioning pin, or re-consent step from those other accounts.

### Impact Explanation
If a `GlobalContractDeployMode::AccountId` contract is used as shared logic for value-bearing operations (e.g., a shared vault/pool/staking-helper contract referenced by many `GlobalByAccount` accounts holding balances or making transfers based on that code's logic), the publishing account can redeploy arbitrary new code at any time and have it apply retroactively/immediately to every referencing account's next call — including code that redirects transfers, drains balances via `Promise`-issued actions, or otherwise diverts value away from the honest logic the referencing accounts originally audited and accepted. Because the swap requires no cooperation from, or even notification to, the referencing accounts, this is a rug vector reachable by a single `DeployGlobalContractAction` transaction from the publisher account.

### Likelihood Explanation
This requires the publisher of an `AccountId`-mode global contract to act maliciously (or have their key compromised) after other unprivileged accounts have already referenced their contract via `UseGlobalContract`. This is an inherent, documented behavior of the `AccountId` deploy mode rather than a bug in validation logic, so it is a known, always-available rug vector for any application built on top of `GlobalByAccount` contracts, exploitable with a single ordinary transaction and no special privileges beyond owning the originally-deployed account.

### Recommendation
For value-bearing use cases, applications should be steered toward (or the protocol should provide a stronger primitive resembling) `GlobalContractDeployMode::CodeHash`, which pins code immutably by hash [6](#0-5) . For `AccountId` mode, consider adding an explicit "pin to current code hash" action so referencing accounts can opt out of future updates, and/or a timelock/notification mechanism before a redeploy takes effect for existing referrers, mirroring the Fei-report mitigation of making the mutable pointer immutable or gated when there are already active users.

### Proof of Concept
1. Account `owner` deploys a global contract in `AccountId` mode containing benign logic (`DeployGlobalContractAction{ deploy_mode: AccountId }`).
2. Account `victim` (and others) call `UseGlobalContractAction{ contract_identifier: AccountId(owner) }`, setting their `AccountContract` to `GlobalByAccount(owner)`, and begin relying on it (e.g., accepting deposits that the contract logic is expected to safeguard/route correctly) — mirrored by `test_global_contract_update` [5](#0-4) .
3. `owner` issues a new `DeployGlobalContractAction{ deploy_mode: AccountId }` with malicious code that, e.g., forwards any deposit/`Promise` calls to `owner`'s own account instead of the intended recipient.
4. On `victim`'s very next `FunctionCall` receipt, `RuntimeContractIdentifier::resolve`/`GlobalContractAccessExt::code` fetch the just-redeployed code for `GlobalByAccount(owner)` [7](#0-6)  and execute it under `victim`'s account context, diverting value with no further action required from `victim`.

    pub(crate) fn resolve(
        account_id: &AccountId,
        account_contract: AccountContract,
        state_update: &TrieUpdate,
        chain_id: &str,
        access: AccessOptions,
    ) -> Result<Self, StorageError> {
        let local_hash = match GlobalContractIdentifier::try_from(account_contract) {
            Ok(gci) => {
                let code_hash = gci.clone().hash(state_update, access)?;
                return Ok(RuntimeContractIdentifier::Global { code_hash, identifier: gci });
            }
            Err(ContractIsLocalError::NotDeployed) => return Ok(RuntimeContractIdentifier::None),
            Err(ContractIsLocalError::Deployed(local_hash)) => local_hash,
        };

        if account_id.get_account_type() == AccountType::EthImplicitAccount {
            // Accounts that look like eth implicit accounts and have existed prior to the
            // eth-implicit accounts protocol change (these accounts are discussed in the
            // description of #11606) may have something else deployed to them. Only return
            // something here if the accounts have a wallet contract hash. Otherwise use the
            // regular path to grab the deployed contract.
            if LegacyEthWallet::resolve(local_hash).is_some() {
                // ETH implicit wallet accounts use global contracts, including
                // those created in old protocol versions.
                let global_hash = eth_wallet_global_contract_hash(chain_id);
                return Ok(RuntimeContractIdentifier::Global {
                    code_hash: global_hash,
                    identifier: GlobalContractIdentifier::CodeHash(global_hash),
                });
            }
        }

        Ok(RuntimeContractIdentifier::AccountLocal {
            code_hash: local_hash,
            account_id: account_id.clone(),
        })
    }

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =
            store.get_ref(&key, KeyLookupMode::MemOrFlatOrTrie, access)?.ok_or_else(|| {
                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }

    fn code(self, store: &TrieUpdate) -> Result<Option<ContractCode>, StorageError> {
        let key = TrieKey::GlobalContractCode { identifier: self.clone().into() };
        let code_hash = match self {
            GlobalContractIdentifier::AccountId(_) => None,
            GlobalContractIdentifier::CodeHash(hash) => Some(hash),
        };
        let code = store.get(&key, AccessOptions::DEFAULT)?;
        Ok(code.map(|code| ContractCode::new(code, code_hash)))
    }
