### Title
Default QPS rate limiter for `/wallet/deploycontract` is a single global bucket, not per-IP, allowing one attacker to starve all other clients - (`framework/src/main/java/org/tron/core/services/http/RateLimiterServlet.java`)

### Summary
`DeployContractServlet` inherits from `RateLimiterServlet`, which resolves its rate limiter from `config.conf`'s `http` map keyed by servlet class name; when no entry exists (the default), it falls back to `DefaultBaseQqsAdapter` built from `QpsStrategy.DEFAULT_QPS_PARAM` [1](#0-0) . `QpsStrategy` wraps a single shared `com.google.common.util.concurrent.RateLimiter` instance that is not keyed by client IP, unlike `IPQpsStrategy`, which maintains a per-IP `Cache<String, RateLimiter>` [2](#0-1) [3](#0-2) . Because `DeployContractServlet` is not shown to have an explicit `IPQPSRateLimiterAdapter` entry configured in `config.conf`, its default adapter is the global (non-IP-keyed) strategy, so a single attacker can consume the whole per-endpoint QPS budget and deny service to legitimate callers from other source IPs.

### Finding Description
`RateLimiterServlet.addRateContainer()` looks up the servlet's rate-limiter configuration by class name in `Args.getInstance().getRateLimiterInitialization().getHttpMap()`; if no entry is present it silently falls back to `DEFAULT_ADAPTER_NAME` (`DefaultBaseQqsAdapter`) with `QpsStrategy.DEFAULT_QPS_PARAM` [1](#0-0) . `QpsStrategy` is a global, non-IP-partitioned limiter: it constructs exactly one `RateLimiter` for the whole servlet and every caller consumes tokens from that same bucket regardless of source IP [4](#0-3) . By contrast, `IPQpsStrategy` is explicitly per-IP, allocating an independent `RateLimiter` per client IP via a Guava cache keyed on the caller's address [5](#0-4) . In `RateLimiterServlet.service()`, every request goes through the per-endpoint limiter first (`rateLimiter.acquirePermit(runtimeData)`) and then the process-wide `GlobalRateLimiter.acquirePermit(runtimeData)` before the handler is invoked [6](#0-5) . If `/wallet/deploycontract` is not explicitly mapped to `IPQPSRateLimiterAdapter` in `config.conf`, an unprivileged attacker can send requests fast enough (single or few concurrent connections) to keep the shared token bucket permanently drained, so `tryAcquire()`/`acquire()` in `QpsStrategy` fails for all other callers hitting the same servlet class, independent of their IP.

### Impact Explanation
This matches a DoS-via-RPC-API class impact: a single unprivileged client can deny service on `/wallet/deploycontract` to every other legitimate caller by exhausting a shared, non-partitioned QPS bucket, since the bucket is keyed by servlet, not by IP [2](#0-1) .

### Likelihood Explanation
No privileged role, key, or non-default network position is required — only default rate-limiter configuration must be in effect (i.e., no explicit `IPQPSRateLimiterAdapter` entry configured for `DeployContractServlet` in `config.conf`). I was unable to confirm from the retrieved config files whether the shipped default `config.conf` actually assigns `DeployContractServlet` to `IPQPSRateLimiterAdapter` or leaves it on the fallback `QpsStrategy` path — the `http` rate-limiter map entries in `framework/src/main/resources/config.conf` were not directly inspectable in this session, so this is a conditional finding contingent on that specific mapping. Given the default fallback logic in `addRateContainer()` uses the global `QpsStrategy`, any endpoint lacking an explicit override is exposed.

### Recommendation
Verify (and if necessary change) the default fallback adapter in `RateLimiterServlet.addRateContainer()` for sensitive/expensive endpoints like `DeployContractServlet` to `IPQPSRateLimiterAdapter` rather than the global `DefaultBaseQqsAdapter`/`QpsStrategy`, or explicitly configure `/wallet/deploycontract` with per-IP QPS limits in `config.conf`.

### Proof of Concept
Not fully constructible without confirming the shipped `config.conf` mapping for `DeployContractServlet`; a definitive PoC requires inspecting `framework/src/main/resources/config.conf`'s `rate.limiter.http` section to confirm whether `DeployContractServlet` is left on the default (global) adapter. This could not be completed within this session due to tool/search limitations on retrieving that config block; a Devin session with full file access should confirm the exact `http` map entry for `DeployContractServlet` before treating this as conclusively exploitable.

      params = QpsStrategy.DEFAULT_QPS_PARAM;

      params = item.getParams();

      container.add(KEY_PREFIX_HTTP, name, buildAdapter(cName, params, name));

      throw rateLimiterInitError(cName, params, name, e);

public class IPQpsStrategy extends Strategy {

  public static final String STRATEGY_PARAM_IPQPS = "qps";
  public static final Double DEFAULT_IPQPS = 2D;

  private Cache<String, RateLimiter> ipLimiter = CacheBuilder.newBuilder().maximumSize(10000)
      .expireAfterWrite(600, TimeUnit.SECONDS).recordStats().build();

  public IPQpsStrategy(String paramString) {
    super(paramString);
  }

  public boolean tryAcquire(String ip) {
    RateLimiter limiter = loadLimiter(ip);
    return limiter != null && limiter.tryAcquire();
  }

  public boolean acquire(String ip) {
    RateLimiter limiter = loadLimiter(ip);
    if (limiter == null) {
      return false;
    }
    limiter.acquire();
    return true;
  }

  private RateLimiter loadLimiter(String ip) {
    try {
      // cache.get is atomic: only one loader executes per key under concurrent requests,
      // preventing multiple RateLimiter instances from being created for the same IP.
      return ipLimiter.get(ip, this::newRateLimiter);
    } catch (Exception e) {
      logger.warn("Failed to load IP rate limiter for {}, denying request: {}",
          ip, e.getMessage());
      return null;
    }
  }
