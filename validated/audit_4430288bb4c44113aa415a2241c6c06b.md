### Title
Type-Mismatch in `safeCompare()` Causes Unhandled Exception (DoS) in OAuth `hmac` Validation for Unvalidated Duplicate Query Parameters - ([File: packages/apps/shopify-api/lib/auth/oauth/safe-compare.ts])

### Summary
`safeCompare()`, the constant-time comparison utility used to validate the Shopify `hmac`/`signature` parameter, does not gracefully return `false` when the two values it compares are of different JS types — it `throw`s instead. `hmac-validator.ts` uses this function directly on the raw, network-supplied `hmac`/`signature` value without first coercing it to a single string for every code path. The dedicated duplicate-parameter defense (`APP_PROXY_SINGLE_VALUE_PARAMS` check) that would normally prevent an attacker from supplying an array-typed `hmac`/`signature` is only exercised for the `appProxy` signator, not the default `admin`/OAuth signator, mirroring the reported bug class: an unconditional exception is thrown whenever the code encounters an input shape it did not anticipate, permanently denying the operation for that (valid, reachable) input class instead of failing safely.

### Finding Description
`safeCompare()`'s control flow is: [1](#0-0) 

If `typeof strA !== typeof strB`, it throws `ShopifyErrors.SafeCompareError` instead of returning `false`.

This function is invoked from the HMAC validator with the raw HTTP-derived value: [2](#0-1) 

`hmac`/`signature` originate from the request's query string, i.e., attacker-controlled input processed by whichever HTTP framework parses the query (many frameworks, e.g. Express's default `qs` parser, turn a repeated key like `?hmac=a&hmac=b` into an **array**, not a string). `generateLocalHmac()` always produces a `string`: [3](#0-2) 

so a duplicated `hmac`/`signature` parameter causes `typeof normalizedQuery.hmac` (`object`, an array) to differ from `typeof localHmac` (`string`), which drives `safeCompare()` into the `throw` branch rather than the intended `false` (invalid-signature) branch.

Critically, the test suite shows that the "reject repeated security param" defense is only asserted for the `appProxy` signator: [4](#0-3) 

No equivalent duplicate-parameter rejection test/guard exists in the `admin`/default `signator` describe block that governs standard OAuth callback and flow-webhook validation (lines 10–143 of the same test file), indicating the admin/OAuth code path lacks the same normalization hardening applied to app-proxy requests.

`validateHmac()` and `validateHmacFromRequestFactory()` do not wrap the `safeCompare()` call in a `try/catch`: [5](#0-4) [6](#0-5) 

so any `SafeCompareError` thrown here propagates as an unhandled rejection up through the OAuth callback / webhook authentication call stack, rather than resulting in the expected "invalid signature" (`false`/401) response.

### Impact Explanation
This is directly analogous to the reported bug class: a helper function makes an unstated assumption about the shape/format of its input (a `bool` return value in the original report; a matching JS `typeof` here) that does not hold for a class of otherwise-reachable inputs, and instead of degrading gracefully it throws unconditionally, denying the intended operation. Here, an anonymous, unauthenticated caller of the OAuth callback endpoint (or flow-webhook endpoint) can trigger an unhandled exception in the HMAC-validation code path — a core request-authentication handler — by supplying a duplicated `hmac` query parameter, rather than receiving the expected "invalid HMAC" rejection. Depending on the runtime adapter's unhandled-rejection/error handling, this can crash the request (and, in Node.js runtimes without a global unhandled-rejection guard, the process), constituting a denial-of-service of an auth handler triggered entirely by an anonymous request.

### Likelihood Explanation
Likelihood is moderate: it requires only a crafted query string with a duplicated `hmac`/`signature` value sent to a public OAuth callback or webhook endpoint — no privileged access, secrets, or MITM position needed. The main uncertainty (not fully verifiable from the indexed portion of the file, since lines ~118–152 of `hmac-validator.ts` containing `normalizeQuery`/`validateHmacTimestamp` were not retrieved) is whether `normalizeQuery` already coerces/rejects array-typed `hmac` values for the `admin` signator before `safeCompare()` is reached. The asymmetric test coverage (duplicate-parameter rejection tests exist only for `appProxy`) is the strongest available signal that this normalization is not uniformly applied.

### Recommendation
- Harden `safeCompare()` to return `false` (not throw) whenever inputs cannot be safely compared, mirroring the recommended hardening of `safeTokenApprove()` in the original report (fail closed without reverting/throwing the entire call chain).
- Explicitly normalize/reject non-string (e.g., array) values for `hmac`/`signature` in the `admin`/default signator path the same way it's already done for `appProxy` via `APP_PROXY_SINGLE_VALUE_PARAMS`, before invoking `safeCompare()`.
- Wrap `safeCompare()` invocations in `validateHmac()`/`validateHmacFromRequestFactory()` with error handling that converts any thrown `SafeCompareError` into a standard "invalid signature" result instead of letting it propagate as an unhandled exception.

### Proof of Concept
1. Send a GET request to the app's OAuth callback route (e.g., `/api/auth/callback`) with a duplicated `hmac` parameter: `?code=...&shop=...&state=...&timestamp=...&hmac=a&hmac=b`.
2. If the HTTP framework's query parser turns the repeated key into an array (e.g., Express + `qs`, or manual `URLSearchParams`-to-object logic that doesn't dedupe for the admin path), `normalizedQuery.hmac` becomes an array.
3. `generateLocalHmac()` returns a `string`.
4. `safeCompare(hmac as string, localHmac)` is called with `typeof hmac === 'object'` vs `typeof localHmac === 'string'`, triggering the `throw new ShopifyErrors.SafeCompareError(...)` branch.
5. Because `validateHmac`/`validateHmacFromRequestFactory` do not catch this, the exception propagates unhandled through the OAuth callback handler instead of returning a normal 400/401 "invalid HMAC" response. [1](#0-0)

export const safeCompare: SafeCompare = (strA, strB) => {
  if (typeof strA === typeof strB) {
    const enc = new TextEncoder();
    const buffA = enc.encode(JSON.stringify(strA));
    const buffB = enc.encode(JSON.stringify(strB));

    if (buffA.length === buffB.length) {
      return timingSafeEqual(buffA, buffB);
    }
  } else {
    throw new ShopifyErrors.SafeCompareError(
      `Mismatched data types provided: ${typeof strA} and ${typeof strB}`,
    );
  }
  return false;
};

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };
}
