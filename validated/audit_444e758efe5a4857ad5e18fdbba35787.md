### Title
`vote-for-aggregate-public-key` never enforces its own voting-window check, letting a stale signer set retroactively set a reward cycle's aggregate public key - (File: stackslib/src/chainstate/stacks/boot/signers-voting.clar)

### Summary
The `.signers-voting` contract defines a private helper `is-in-voting-window` whose stated purpose is to scope voting to the reward cycle whose signer set the node has just computed (`last-set-cycle`) and only during the prepare phase. However, `vote-for-aggregate-public-key`, the only public entry point that mutates vote/tally state, never calls it. The only cycle-scoping check actually performed is that `aggregate-public-keys` has not yet been set for the target `reward-cycle` — nothing checks that the target `reward-cycle` is the currently active one or that voting is even in the prepare phase.

### Finding Description
`get-signer-weight` validates that the caller was a member of the signer set for the requested `reward-cycle` at the requested index: [1](#0-0) 

`is-in-voting-window` is defined to additionally require that `reward-cycle` equals `last-set-cycle` (the most recently computed signer set) and that the burn height is currently in the prepare phase: [2](#0-1) 

But `vote-for-aggregate-public-key` only checks:
1. that `aggregate-public-keys` has no entry yet for `reward-cycle` (line 155),
2. key well-formedness, novelty, no double vote, and monotonic round.

It never calls `is-in-voting-window`: [3](#0-2) 

The `.signers` contract permanently retains each cycle's `{signer, weight}` list in `cycle-signer-set` — it is never pruned when a new cycle is set: [4](#0-3) 

Because of this permanence, a principal who was a signer at index `i` for an *old* reward cycle `N` remains able to pass `get-signer-weight` for `N` indefinitely, even after `last-set-cycle` has advanced far past `N` (i.e., long after cycle `N`'s intended voting window closed). As long as no aggregate key has yet been recorded for `N` (e.g., the vote never reached the 70% threshold during its real window), that stale signer can resume voting for `N` at any future block height and, together with other former members of that stale signer set, push the tally over threshold and retroactively insert an `aggregate-public-keys` entry for a reward cycle that has already elapsed.

This is directly analogous to the reported `setRole` bug: a scope-qualifying parameter (`safeId` there, `reward-cycle`/prepare-phase window here) is documented and even partially implemented (`is-in-voting-window`), but the enforcement path that should gate the privileged write is not actually wired into the function that performs the mutation, letting an actor act outside their intended scope (an expired cycle) instead of being confined to it.

### Impact Explanation
The aggregate public key recorded via `get-approved-aggregate-key` is consumed by the node's chainstate logic (`stackslib/src/chainstate/stacks/boot/mod.rs`) as the consensus-relevant signer aggregate key for a reward cycle, used in validating the signer set's threshold signatures for Nakamoto blocks in that cycle. If this value is set (or changes from "unset" to "set") *after* the cycle's real voting window has closed — i.e., after signers, miners, or other nodes have already begun operating under the assumption that cycle `N` has no approved key, or under a different reconstructed voting history — this creates a divergence in which signature/threshold verification an honest node believes is authoritative for blocks produced during cycle `N`. Since this can be triggered by a coordinated minority of former (not necessarily current-majority) signers from an already-superseded cycle, it fits the "minority-triggerable... validation divergence" / "temporary tip disagreement" class rather than requiring majority collusion of the *current* signer set.

### Likelihood Explanation
Exploitability requires only:
- Being a member (at a known index) of some past reward cycle's signer set that never reached the 70% approval threshold during its live window (plausible in practice — DKG rounds can fail to converge before the cycle rolls over), and
- Colluding with enough of that same stale signer set (which can be a small subset relative to the *current* active signer set, since threshold is computed against the *cached* total weight for that old cycle, not the current cycle) to cross the cached threshold for cycle `N`.

No admin, operator, or private key beyond the stale signers' own keys is needed, and the check that should have prevented this (`is-in-voting-window`) already exists in the codebase but is simply not invoked, indicating this is a concrete, reachable oversight rather than a theoretical gap.

### Recommendation
Call `(try! (is-in-voting-window burn-block-height reward-cycle))` (converted to return a proper error, e.g. `ERR_OUT_OF_VOTING_WINDOW`) at the top of `vote-for-aggregate-public-key`, before any state mutation, so that votes are only accepted for the reward cycle whose signer set was most recently set (`last-set-cycle`) and only during that cycle's prepare phase — matching the check's original documented intent.

### Proof of Concept
1. Reward cycle `N`'s signer set is computed and stored in `.signers`' `cycle-signer-set` (via `set-signers`), with `last-set-cycle = N`. During cycle `N`'s prepare phase, voting fails to reach the 70% threshold, so `aggregate-public-keys` has no entry for `N`.
2. Reward cycle `N+1`, `N+2`, ... proceed normally; `last-set-cycle` advances well beyond `N`. `.signers`' `cycle-signer-set` for `N` is still present (never deleted).
3. At any later block height, a signer who held index `i` in cycle `N`'s signer set calls `.signers-voting.vote-for-aggregate-public-key(i, key, round, N)`. `get-signer-weight(i, N)` still succeeds because `.signers.get-signer-by-index(N, i)` still returns that signer's entry, and `tx-sender` still matches.
4. Since no check equivalent to `is-in-voting-window` gates the call, the vote is accepted, the tally for cycle `N` is updated, and if enough of that stale signer set repeats this, `map-insert aggregate-public-keys N key` succeeds — setting an aggregate key for cycle `N` long after its real voting window closed and after other components of the system have already treated cycle `N` as having no approved key.

(define-public (vote-for-aggregate-public-key (signer-index uint) (key (buff 33)) (round uint) (reward-cycle uint))
    (let ((tally-key {reward-cycle: reward-cycle, round: round, aggregate-public-key: key})
            ;; vote by signer weight
            (signer-weight (try! (get-signer-weight signer-index reward-cycle)))
            (new-total (+ signer-weight (default-to u0 (map-get? tally tally-key))))
            (cached-weight (try! (get-and-cache-total-weight reward-cycle)))
            (threshold-weight (get-threshold-weight reward-cycle))
            (current-round (default-to {
                votes-count: u0, 
                votes-weight: u0} (map-get? round-data {reward-cycle: reward-cycle, round: round})))
                )
        ;; Check that the key has not yet been set for this reward cycle
        (asserts! (is-none (map-get? aggregate-public-keys reward-cycle)) (err ERR_OUT_OF_VOTING_WINDOW))
        ;; Check that the aggregate public key is the correct length
        (asserts! (is-eq (len key) u33) (err ERR_ILL_FORMED_AGGREGATE_PUBLIC_KEY))

        ;; Check that the round is incremented by at most 1

(define-map cycle-signer-set uint (list 4000 { signer: principal, weight: uint }))

;; Called internally by the Stacks node.
;; Stores the stackerdb signer slots for a given reward cycle.
;; Since there is one stackerdb per signer message, the `num-slots` field will always be u1.
(define-private (stackerdb-set-signer-slots 
                   (signer-slots (list 4000 { signer: principal, num-slots: uint }))
                   (reward-cycle uint)
                   (set-at-height uint))
	(let ((cycle-mod (mod reward-cycle u2)))
        (map-set cycle-set-height reward-cycle set-at-height)
        (var-set last-set-cycle reward-cycle)
        (if (is-eq cycle-mod u0)
            (ok (var-set stackerdb-signer-slots-0 signer-slots))
            (ok (var-set stackerdb-signer-slots-1 signer-slots)))))

;; Called internally by the Stacks node.
;; Sets the list of signers and weights for a given reward cycle.
(define-private (set-signers
                 (reward-cycle uint)
                 (signers (list 4000 { signer: principal, weight: uint })))
     (begin
      (asserts! (is-eq (var-get last-set-cycle) reward-cycle) (err ERR_CYCLE_NOT_SET))
      (ok (map-set cycle-signer-set reward-cycle signers))))

;; Get the list of signers and weights for a given reward cycle.
(define-read-only (get-signers (cycle uint))
     (map-get? cycle-signer-set cycle))
