### Title
Module-derived `CallExecuteUniversalTx` EVM sub-call is not bounded by the attacker-declared `UniversalPayload.GasLimit` before execution - (File: x/uexecutor/keeper/evm.go)

### Summary
For `isCEA` inbounds routed to a smart-contract recipient, `x/uexecutor` calls the attacker-controlled recipient's `executeUniversalTx` via `CallExecuteUniversalTx`, passing `gasLimit=nil` to `DerivedEVMCall`. This means the actual EVM execution is capped only by the fork's internal default, not by the `UniversalPayload.GasLimit` value the inbound declares. The declared `GasLimit` is enforced only *after* the call completes, inside `DeductGasFeesFromReceipt`, by comparing `receipt.GasUsed` against `abiPayload.GasLimit` and erroring if exceeded.

### Finding Description
This mirrors the "unbounded nuisance gas" pattern: a sub-execution's budget is not constrained by the parent-declared/enforced budget before the call runs, only checked (and reacted to) afterward. Here, the attacker (who controls the destination `recipientAddr` contract and the `Data`/payload content via the inbound they cause to be voted on) can make the `executeUniversalTx` call on their own malicious contract consume gas far beyond the small `GasLimit` they declared in `UniversalPayload`, up to whatever the fork's internal default cap allows. `CallExecuteUniversalTx` never passes `universalPayload.GasLimit` into `DerivedEVMCall`'s `gasLimit` parameter — unlike the sibling function `CallUEAExecutePayload`, which does parse and forward `universal_payload.GasLimit` as the explicit cap (`x/uexecutor/keeper/evm.go:172-192`). Only after the (uncapped, real) EVM execution finishes does `DeductGasFeesFromReceipt` detect the mismatch (`gasUsedBig.Cmp(abiPayload.GasLimit) > 0`) and return an error, which causes the surrounding `CacheContext` in `ExecuteInboundGasAndPayload`/`ExecuteInboundFundsAndPayload` to be discarded without committing (`writeCache()` skipped). The recipient's state changes are rolled back, but the real, unbounded EVM computation already ran and was metered against the block/tx gas meter of the underlying Cosmos context (the `CacheContext` shares the parent gas meter), while the declared, attacker-supplied `GasLimit` provided no actual pre-execution cap.

### Impact Explanation
This lets an unprivileged attacker who registers a malicious "recipient" contract (or points an inbound's recipient to one) declare an artificially small `GasLimit` in the payload while their contract's `executeUniversalTx` implementation performs arbitrarily expensive computation, unconstrained until after the fact. Because enforcement is reactive rather than a hard execution cap, the attacker can force the protocol/module-account-originated EVM call to consume real, uncapped gas resources per voted inbound, without ever being billed for it (the compensating `DeductGasFeesFromReceipt` fee-deduction attempt fails and is rolled back). This is a resource/gas accounting invariant violation reachable purely from a standard, honestly-voted inbound with attacker-chosen recipient/payload content — matching the "denial of service... reachable without privileged control" and "corruption of ... gas fee accounting" categories in scope.

### Likelihood Explanation
Requires only that an attacker control (or deploy) the destination recipient contract for a `TxType_GAS_AND_PAYLOAD` or `TxType_FUNDS_AND_PAYLOAD` isCEA inbound with a small `UniversalPayload.GasLimit` and expensive contract logic, then get the inbound voted normally by honest validators — no privileged access needed.

### Recommendation
Pass `universalPayload.GasLimit` (parsed as in `CallUEAExecutePayload`) as the explicit `gasLimit` argument to `DerivedEVMCall` inside `CallExecuteUniversalTx`, so the sub-call is hard-capped at the declared budget before execution, rather than only checked against it after the fact.

### Proof of Concept
1. Deploy a malicious `recipient` contract implementing `executeUniversalTx` with a gas-heavy loop/storage-write pattern.
2. Submit/cause an `isCEA` inbound (`TxType_GAS_AND_PAYLOAD` or `TxType_FUNDS_AND_PAYLOAD`) with `Recipient` = malicious contract, `UniversalPayload.GasLimit` set very low (e.g. `"21000"`), and `Data` crafted to trigger the expensive path.
3. Have the inbound voted in normally by honest validators (`MsgVoteInbound` x N).
4. Observe `CallExecuteUniversalTx` (`x/uexecutor/keeper/evm.go:648`) executes with `gasLimit=nil`, letting the recipient consume gas well above the declared `21000`.
5. `DeductGasFeesFromReceipt` (`x/uexecutor/keeper/fees.go:130`) detects `gasUsed > GasLimit`, errors, and the `CacheContext` write is skipped — no fee ever collected for the real (large) computation performed.

// CallExecuteUniversalTx calls executeUniversalTx on a smart-contract recipient.
// This is used for isCEA inbounds whose recipient is a deployed contract (not a UEA).
func (k Keeper) CallExecuteUniversalTx(
	ctx sdk.Context,
	recipientAddr common.Address,
	sourceChain string,
	ceaAddress []byte,
	payload []byte,
	amount *big.Int,
	prc20AssetAddr common.Address,
	txId [32]byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	recipientABI, err := types.ParseRecipientContractABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse recipient contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		recipientABI,
		ueModuleAccAddress,
		recipientAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"executeUniversalTx",
		sourceChain,
		ceaAddress,
		payload,
		amount,
		prc20AssetAddr,
		txId,
	)
}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}
