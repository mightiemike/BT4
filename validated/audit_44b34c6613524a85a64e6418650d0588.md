### Title
Stale global class cache serves undeclared Cairo0 classes after a state revert, bypassing declaration checks - ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` reads from the shared, process-wide `GlobalContractCache` before consulting the state's declaration status. For Cairo1 classes it re-validates a cache hit against `is_declared`, but for Cairo0 (`RunnableCompiledClass::V0`) classes this validation is explicitly skipped, so a cache entry populated before a revert is trusted forever afterward, exactly mirroring the Olympus Treasury "cache not re-initialized after state-affecting change" bug class.

### Finding Description
`get_compiled_from_class_manager` is the entry point used by every `get_compiled_class` call during transaction execution: [1](#0-0) 

For a cache hit, the code branches on the compiled class type: [2](#0-1) 

For `RunnableCompiledClass::V0(_)` the match arm is empty — no re-validation is performed — whereas for `V1`/`V1Native` the code calls `self.state_reader.is_declared(class_hash)` and errors with `UndeclaredClassHash` if the state no longer considers the class declared. The comment explicitly acknowledges the bug class this is defending against: *"the Cairo1 class is cached; verify it is declared, since existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)."*

The `is_declared` trait contract itself documents that it only covers Cairo1 classes: [3](#0-2) 

The cache in question, `GlobalContractCache`, is a long-lived LRU shared across blocks (and even shared with view-call execution per `StorageViewStateReaderFactory`), not invalidated automatically when storage is reverted: [4](#0-3) 

The legacy `native_blockifier` Python-bound executor is aware of exactly this hazard and defends against it by clearing the *entire* class cache on every revert: [5](#0-4) 

However, the modern Rust-native revert path used by the sequencer's batcher/consensus components, `apollo_reverts::revert_block`, only touches storage tables (header, body, state diff, class-manager marker, base-layer marker, partial block hash, block hash, global root, accessed keys) and never references `ContractClassManager` / `GlobalContractCache`: [6](#0-5) 

I was not able to fully trace, within the remaining tool budget, whether `apollo_batcher::batcher.rs`'s revert handling (which calls into `apollo_reverts::revert_block`) separately clears the batcher's own `ContractClassManager` instance (the same one shared with `StorageViewStateReaderFactory` for view calls) elsewhere in that call path. This is the key open question: if that clear does not happen, the asymmetry described above becomes concretely reachable in production block-building/consensus reverts, not just in the legacy Python bindings.

### Impact Explanation
If a Cairo0 class is declared in block N, cached in the shared `GlobalContractCache`, and block N is later reverted (e.g., due to an L1/L2 consensus reorg) without the cache being cleared, any later transaction referencing that class hash (e.g. `deploy_account` with that class hash, or an `invoke` targeting a contract deployed with it) will succeed using the stale cached compiled class instead of failing with `UndeclaredClassHash`, because the V0 branch never re-checks declaration status. This causes a sequencer node with a warm cache to accept and execute a transaction that a node with a cold cache (or one that correctly re-validates state) would reject, producing divergent state transitions / state roots between otherwise-honest nodes and potentially permitting execution against a class that is not part of the canonical declared-class set.

### Likelihood Explanation
Requires: (1) a Cairo0 class hash to have been declared and then reverted (a legitimate, non-malicious L1/L2 reorg scenario, not an attacker-controlled action), and (2) the shared class-cache not being cleared by the Rust-native revert path. Given the codebase already treats this exact scenario as a bug worth fixing for Cairo1 (`is_declared` check) and even fixes it defensively for the whole cache in the legacy Python executor's `revert_block`, the gap for Cairo0 in the modern path is a real, reachable inconsistency rather than a purely theoretical one — but I could not confirm from the available context whether a compensating `clear()` call exists elsewhere in `apollo_batcher`'s revert flow, which is needed to fully confirm exploitability in the current Rust-native sequencer.

### Recommendation
Apply the same re-validation performed for Cairo1 classes to Cairo0 classes in `get_compiled_from_class_manager` — i.e., check the current declaration status (e.g., via `is_declared`/an equivalent Cairo0-aware check, or by confirming presence in `get_compiled_classes`/storage) before trusting a `V0` cache hit — or ensure every revert path (including `apollo_reverts::revert_block` and any batcher-level revert handling) explicitly clears the shared `ContractClassManager`/`GlobalContractCache`, mirroring the `py_block_executor::revert_block` mitigation: [7](#0-6) 

### Proof of Concept
1. Declare a Cairo0 class with hash `X` in block `N`; `get_compiled_from_class_manager` misses the cache, fetches `X` from storage, and caches it as `RunnableCompiledClass::V0` via `set_and_compile`. [8](#0-7) 
2. Block `N` is reverted through the Rust-native revert path (`apollo_reverts::revert_block`), which deletes `X`'s declaration from storage tables but performs no cache invalidation. [6](#0-5) 
3. In a later block, a transaction (e.g. `deploy_account` using class hash `X`) calls `get_compiled_class(X)`; the cache lookup succeeds, hits the `V0` branch, skips the `is_declared` check, and returns the stale compiled class as valid. [9](#0-8) 
4. Execution proceeds as if `X` is declared, contrary to actual state, while a node without a warm cache (or with correct invalidation) would raise `StateError::UndeclaredClassHash` per the existing test coverage for the undeclared-class-hash path. [10](#0-9)

    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }
        self.increment_cache_miss_metric();

        let compiled_class = self.state_reader.get_compiled_classes(class_hash)?;
        self.contract_class_manager.set_and_compile(class_hash, compiled_class.clone());
        // Access the cache again in case the class was compiled.
        let runnable_class = self
            .contract_class_manager
            .get_runnable(&class_hash, &self.native_classes_whitelist)
            .unwrap_or_else(|| {
                // Edge case that should not be happen if the cache size is big enough.
                // TODO(Yoni): consider having an atomic set-and-get.
                log::error!("Class is missing immediately after being cached.");
                compiled_class.to_runnable()
            });

pub struct GlobalContractCache<T: Clone>(pub Arc<Mutex<ContractLRUCache<T>>>);

impl<T: Clone> GlobalContractCache<T> {
    /// Locks the cache for atomic access. Although conceptually shared, writing to this cache is
    /// only possible for one writer at a time.
    pub fn lock(&self) -> LockedClassCache<'_, T> {
        self.0.lock().expect("Global contract cache is poisoned.")
    }

    pub fn get(&self, class_hash: &ClassHash) -> Option<T> {
        self.lock().cache_get(class_hash).cloned()
    }

    pub fn set(&self, class_hash: ClassHash, contract_class: T) {
        self.lock().cache_set(class_hash, contract_class);
    }

    pub fn clear(&mut self) {
        self.lock().cache_clear();
    }

    pub fn new(cache_size: usize) -> Self {
        Self(Arc::new(Mutex::new(ContractLRUCache::<T>::with_size(cache_size))))
    }

/// Reverts everything related to the block, will succeed even if there is partial information for
/// the block.
// This function will panic if the storage reader fails to revert.
pub fn revert_block(storage_writer: &mut StorageWriter, target_block_marker: BlockNumber) {
    let txn = storage_writer
        .begin_rw_txn()
        .unwrap()
        .revert_header(target_block_marker)
        .unwrap()
        .0
        .revert_body(target_block_marker)
        .unwrap()
        .0
        .revert_state_diff(target_block_marker)
        .unwrap()
        .0
        .try_revert_class_manager_marker(target_block_marker)
        .unwrap()
        .try_revert_base_layer_marker(target_block_marker)
        .unwrap()
        .revert_partial_block_hash_components(&target_block_marker)
        .unwrap()
        .revert_block_hash(&target_block_marker)
        .unwrap()
        .revert_global_root(&target_block_marker)
        .unwrap();

    #[cfg(feature = "os_input")]
    let txn = txn.revert_accessed_keys(target_block_marker).unwrap();

    txn.commit().unwrap();
}

fn test_fail_deploy_account_undeclared_class_hash(
    block_context: BlockContext,
    default_all_resource_bounds: ValidResourceBounds,

    let block_context = &block_context;
    let chain_info = &block_context.chain_info;
    let state = &mut test_state(chain_info, BALANCE, &[]);
    let undeclared_hash = class_hash!("0xdeadbeef");
    let deploy_account = AccountTransaction::new_with_default_flags(executable_deploy_account_tx(
        deploy_account_tx_args! {
            resource_bounds: default_all_resource_bounds,  class_hash: undeclared_hash
        },
    ));
    let tx_context = block_context.to_tx_context(&deploy_account);
    let fee_type = tx_context.tx_info.fee_type();

    // Fund account, so as not to fail pre-validation.
    state
        .set_storage_at(
            chain_info.fee_token_address(&fee_type),
            get_fee_token_var_address(deploy_account.sender_address()),
            felt!(BALANCE.0),
        )
        .unwrap();

    let error = deploy_account.execute(state, block_context).unwrap_err();
    assert_matches!(
        error,
        TransactionExecutionError::ContractConstructorExecutionFailed(
            ConstructorEntryPointExecutionError::ExecutionError { error, .. }

        if matches!(
            error.unannotated(),
            EntryPointExecutionError::StateError(StateError::UndeclaredClassHash(class_hash))

        )
    );
}
