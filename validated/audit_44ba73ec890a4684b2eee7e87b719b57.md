### Title
Caller deposit is permanently lost when an intermediate cross-contract callback fails in the Wallet Contract - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
The external report describes a DAO pool contract that assumes a cross-contract call succeeded without verifying the resulting state, leading to permanently frozen user funds. The reachable analog in nearcore is in the NEAR Wallet Contract (`WalletContract`), which relays Ethereum-emulated transactions as chained NEAR promises. Two of its three promise-chain failure branches drop the tracked `CallerDeposit` instead of refunding it, unlike the final callback which does refund correctly, so an attached deposit can become permanently stuck whenever an intermediate step in the chain fails.

### Finding Description
`inner_rlp_execute` tracks any NEAR deposit attached by an external (non-owner) caller in a `CallerDeposit` struct so it can be refunded if the underlying action ultimately fails [1](#0-0) . For multi-step promise chains (address registrar lookup, then NEP-141 `storage_balance_of` lookup, then the action), the `caller_deposit` is threaded as an argument through each callback with the intent that the terminal callback, `rlp_execute_callback`, performs the refund when `PromiseResult::Failed` is observed:

```rust
PromiseResult::Failed => {
    // The cross-contract call failed, refund the caller if needed
    if let Some(CallerDeposit { account_id, yocto_near }) = caller_deposit {
        let refund_promise = env::promise_batch_create(&account_id);
        env::promise_batch_action_transfer(refund_promise, NearToken::from_yoctonear(yocto_near.into()));
    }
    ...
}
``` [2](#0-1) 

However, the two earlier callbacks in the same chain, `address_check_callback` and `nep_141_storage_balance_callback`, handle their own `PromiseResult::Failed` case by returning an error `ExecuteResponse` directly — they never forward to `rlp_execute_callback`, and they simply drop `caller_deposit` without issuing any refund:

In both branches `caller_deposit` is a function parameter that is simply discarded — no `promise_batch_action_transfer` refund is scheduled, and the deposit was never persisted anywhere else. The only test that exercises the caller-refund path (`test_caller_refunds`) only covers the case where the target action fails directly and reaches `rlp_execute_callback` [5](#0-4) ; it does not cover failures in `address_check_callback` or `nep_141_storage_balance_callback`.

This mirrors the root cause of the reported bug: a low-level/cross-contract call outcome is not properly validated end-to-end, and the code silently proceeds/fails without reconciling the actual balance/ownership state, leaving user-provided value stranded.

### Impact Explanation
Any external, unprivileged caller (e.g. a relayer) who submits an `rlp_execute` transaction to someone's Wallet Contract with a non-zero attached NEAR deposit, targeting an ERC-20 emulation transfer or an EOA transfer requiring an address-registrar check, risks permanent loss of that deposit if:
- the address registrar's `lookup` call fails (e.g., registrar contract paused, out of gas, or account issues), or
- the target NEP-141 token's `storage_balance_of` call fails (e.g., the token contract panics, is paused, or runs out of gas).

In either case, the attached deposit remains in the Wallet Contract's balance with no on-chain record allowing it to be reclaimed by the depositor — it is effectively burned/frozen from the depositor's perspective, since the contract only refunds deposits when failure occurs in the final action step, not in the earlier registrar/storage-balance steps of the promise chain.

### Likelihood Explanation
This is trivially reachable by any account that calls `rlp_execute` on any deployed Wallet Contract while attaching a NEAR deposit for the "faulty relayer refund" or generic deposit-tracking use case, targeting an ERC20 transfer or an eth-implicit target requiring an address check. Failure of the intermediate cross-contract call (registrar lookup or `storage_balance_of`) can be triggered by ordinary conditions (insufficient gas, a paused/reverting token contract, or simply an incorrect/removed registrar entry) — it does not require a malicious validator or network-level fault, only a single transaction from an unprivileged signer.

### Recommendation
Ensure every `PromiseResult::Failed` branch in the promise chain (`address_check_callback`, `nep_141_storage_balance_callback`, and any future intermediate callbacks) performs the same caller-deposit refund logic that `rlp_execute_callback` performs, rather than dropping `caller_deposit` and returning an error directly. Ideally, factor the refund-on-failure logic into a shared helper invoked from all failure branches to avoid this inconsistency recurring.

### Proof of Concept
1. Deploy a `WalletContract` for address `A`.
2. Have an external account `R` (not `A`) call `rlp_execute` targeting a NEP-141 token `T` with an RLP-encoded ERC-20 `transfer` call, attaching `1 NEAR` as deposit (creating a `CallerDeposit { account_id: R, yocto_near: 1 NEAR }`).
3. Configure/force `T::storage_balance_of` to fail (e.g., deploy a token that panics in `storage_balance_of`, or attach insufficient gas so the cross-contract call runs out of gas).
4. Observe that `nep_141_storage_balance_callback` is invoked with `PromiseResult::Failed`, returns `ExecuteResponse { success: false, ... }`, and never refunds the `1 NEAR` to `R` — confirm via `view_account` that `A`'s (the wallet's) balance retains the deposit while `R`'s balance is reduced by that amount with no corresponding refund receipt, unlike the behavior demonstrated for the final-callback failure path in `test_caller_refunds` [6](#0-5) .

/// A data type to keep track of the deposit given by an external caller.
/// This allows us to refund the caller's deposit if the cross-contract call fails.
#[derive(Debug, PartialEq, Eq, Clone, serde::Serialize, serde::Deserialize)]
pub struct CallerDeposit {
    pub account_id: AccountId,
    pub yocto_near: NonZeroU128,
}

impl CallerDeposit {
    pub fn new(context: &ExecutionContext) -> Option<Self> {
        // Only track for external (non-self) callers
        if context.current_account_id == context.predecessor_account_id {
            return None;
        }

        NonZeroU128::new(context.attached_deposit.as_yoctonear()).map(|yocto_near| Self {
            account_id: context.predecessor_account_id.clone(),
            yocto_near,
        })
    }

// An external caller gets its deposit back if the cross-contract call fails.
#[tokio::test]
async fn test_caller_refunds() -> anyhow::Result<()> {
    let TestContext { worker, wallet_contract, wallet_sk, address_registrar, .. } =
        TestContext::new().await?;

    let caller = worker.root_account()?;
    let deposit_amount = NearToken::from_near(3);
    let create_tx = |receiver_id: &AccountId, nonce: u64| {
        let method = "register";
        let args = br#"{"account_id": "birchmd.near"}"#;
        let action = Action::FunctionCall {
            receiver_id: receiver_id.to_string(),
            method_name: method.into(),
            args: args.to_vec(),
            gas: Gas::from_tgas(10).as_gas(),
            yocto_near: 0,
        };
        utils::create_signed_transaction(
            nonce,
            receiver_id,
            Wei::new_u128(deposit_amount.as_yoctonear() / (MAX_YOCTO_NEAR as u128)),
            action,
            &wallet_sk,
        )
    };

    // External caller gets a refund when the cross-contract call fails
    let pre_tx_account_balance = caller.view_account().await?.balance;
    let receiver_id: AccountId = "fake.near".parse()?;
    let result = wallet_contract
        .rlp_execute_from(
            &caller,
            receiver_id.as_str(),
            &create_tx(&receiver_id, 0),
            deposit_amount,
        )
        .await?;
    assert!(!result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            < deposit_amount.as_yoctonear()
    );

    // External caller does not get a refund when their tokens are spent
    let pre_tx_account_balance = post_tx_account_balance;
    let receiver_id = address_registrar.id();
    let result = wallet_contract
        .rlp_execute_from(&caller, receiver_id.as_str(), &create_tx(receiver_id, 1), deposit_amount)
        .await?;
    assert!(result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            >= deposit_amount.as_yoctonear()
    );

    Ok(())
}
