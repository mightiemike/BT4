### Title
Stale `get_last_globally_accepted_block` check in v1 tenure-change validation allows duplicate tenure-start block acceptance - (File: stacks-signer/src/chainstate/v1.rs)

### Summary
`stacks-signer/src/chainstate/v1.rs`'s `validate_tenure_change_payload` still uses `signer_db.get_last_globally_accepted_block(...)` to decide whether a tenure-start (`BlockFound`/tenure-change) proposal is a duplicate for the current tenure. The v2 implementation of the identical check (`stacks-signer/src/chainstate/v2.rs`) was fixed to use `get_last_signed_block` after a confirmed regression: `get_last_globally_accepted_block` misses blocks in `LocallyAccepted` or `PreCommitted` state, so a signer can be tricked into accepting (and signing) a second, competing tenure-start block for a tenure it has already locally-accepted a different tenure-start block for.

### Finding Description
The v1 duplicate-check is: [1](#0-0) 

which only rejects a tenure-change proposal (`RejectReason::DuplicateBlockFound`) when a **globally accepted** block already exists for the consensus hash. It does not consult blocks that this same signer has already locally accepted (signed) but that have not yet reached network-wide consensus.

The v2 code path performs the same check but was patched to use `get_last_signed_block` (which covers `LocallyAccepted`, `PreCommitted`→confirmed states as well as globally accepted ones): [2](#0-1) 

The regression test that documents the original bug and its fix explicitly states the equality that must hold — "a signer must not sign two competing tenure-start blocks for the same tenure" — and shows that the narrower `get_last_globally_accepted_block` check breaks it: [3](#0-2) 

Because `stacks-signer/src/chainstate/v1.rs` was never updated to use the same fix, a signer still running the v1 chainstate validation path retains the original defect: it will only reject a duplicate tenure-change block if a prior tenure-start block for that same tenure has already become **globally** accepted. If a byzantine/faulty miner proposes a first tenure-start block that a v1 signer locally accepts (signs) but that never crosses the global-acceptance threshold, the miner can then propose a second, different tenure-start block for the *same tenure*, and that same v1 signer will validate and sign it too — because `get_last_globally_accepted_block` finds nothing.

This directly parallels the `FollowNFT.tryMigrate()` bug: both bugs rely on a state read (`_followTokenIdByFollowerProfileId` / `get_last_globally_accepted_block`) that is blind to an intermediate state introduced by a partially-completed action (a pre-V2-migration follow / a locally-but-not-globally accepted block), letting an already-registered/already-signed entity be registered/signed a second time.

### Impact Explanation
If enough (but not necessarily a majority of) still-v1 signers sign both competing tenure-start blocks for one tenure, this produces:
- A validation-verdict divergence between v1 signers (who sign the duplicate) and v2 signers or any v1 signer who already saw global acceptance (who correctly reject it via `DuplicateBlockFound`).
- Signatures split across two candidate tenure-start blocks for the same tenure, which can produce a temporary tip disagreement/fork at the tenure-start boundary, since Nakamoto tenure descent assumes at most one signed tenure-start block per tenure.

This matches the in-scope "High" impact category: a minority-triggerable signer validation divergence causing temporary tip disagreement, not requiring a majority of signers or any privileged key beyond a normal miner producing a second commit/proposal.

### Likelihood Explanation
Requires: (1) at least one signer still executing the v1 chainstate validation path, and (2) a miner (unprivileged, no special key needed beyond normal mining) racing two tenure-start block proposals for the same tenure before the first reaches global acceptance. Both are plausible operational conditions (v1 support is retained in the codebase for backward compatibility — imported across `stacks-signer/src/v0/signer.rs`, `signer_state.rs`, `runloop.rs`, `lib.rs`), but I was unable to fully confirm from the index whether any currently-deployed signer version still exercises the v1 chainstate path versus always defaulting to v2, since a tool-call budget limit prevented me from tracing the exact protocol-version dispatch logic (`SortitionsView` enum construction in `stacks-signer/src/chainstate/mod.rs`).

### Recommendation
Update `stacks-signer/src/chainstate/v1.rs::validate_tenure_change_payload` to use `signer_db.get_last_signed_block` (or equivalent inclusive check covering `LocallyAccepted`/`PreCommitted`/`GloballyAccepted` states) instead of `get_last_globally_accepted_block`, mirroring the fix already applied in `v2.rs`. Add a regression test for v1 analogous to `check_tenure_change_rejects_when_locally_accepted_block_exists` in `v2.rs`.

### Proof of Concept
Not independently reproduced in this session (read-only analysis). The existing test `check_tenure_change_rejects_when_locally_accepted_block_exists` in `stacks-signer/src/chainstate/tests/v2.rs` (lines 748-850) demonstrates the exact scenario against the v2 code before its fix; the same test structure, run against `stacks-signer/src/chainstate/v1.rs::validate_tenure_change_payload`, would show the still-present `DuplicateBlockFound` rejection failing to trigger for a `LocallyAccepted` (non-globally-accepted) existing block, since v1.rs still calls `get_last_globally_accepted_block` at lines 505-518.

/// Test that a tenure change proposal is rejected when a locally-accepted
/// (but not globally-accepted) block already exists in the same tenure.
///
/// This is a regression test: previously, the check used
/// `get_last_globally_accepted_block`, which would miss blocks in
/// `LocallyAccepted` or `PreCommitted` state and incorrectly allow
/// a duplicate tenure change.
#[test]
fn check_tenure_change_rejects_when_locally_accepted_block_exists() {
    let MockServerClient {
        server,
        client: stacks_client,
        config: _,
    } = MockServerClient::new();
    let rand_int = server.local_addr().unwrap().port();

    let (_stacks_client, mut signer_db, block_sk, mut block, cur_sortition, _, sortitions_view) =
        setup_test_environment(&format!("{}_{rand_int}", function_name!()));

    // Set up the block in the current tenure
    block.header.consensus_hash = cur_sortition.data.consensus_hash.clone();
    let parent_block_header = make_parent_header_meta(&block_sk, &mut block);
    let response = crate::client::tests::build_get_tenure_tip_response(&parent_block_header);

    // Insert a locally-accepted block in the same tenure (same consensus_hash).
    // This simulates a miner's first tenure-start block that the signer has
    // locally accepted but that hasn't yet gathered enough signatures to be
    // globally accepted. In practice this block would contain a tenure-change
    // and coinbase tx, but we omit them here because `get_last_accepted_block`
    // only queries by consensus_hash and block state — the block's transactions
    // are irrelevant to the duplicate check.
    let existing_block_proposal = BlockProposal {
        block: NakamotoBlock::new(
            NakamotoBlockHeader {
                version: 1,
                chain_length: 10,
                burn_spent: 10,
                consensus_hash: cur_sortition.data.consensus_hash.clone(),
                parent_block_id: StacksBlockId([0; 32]),
                tx_merkle_root: Sha512Trunc256Sum([0; 32]),
                state_index_root: TrieHash([0; 32]),
                timestamp: 11,
                miner_signature: MessageSignature::empty(),
                signer_signature: vec![],
                pox_treatment: BitVec::ones(1).unwrap(),
                problematic_txs: vec![],
            },
            vec![],
        ),
        burn_height: 2,
        reward_cycle: 1,
        block_proposal_data: BlockProposalData::empty(),
    };
    let mut existing_block_info = BlockInfo::from(existing_block_proposal);
    existing_block_info.mark_locally_accepted(false).unwrap();
    signer_db.insert_block(&existing_block_info).unwrap();

    // Now build a *second* tenure-start block proposal for the same tenure.
    // This simulates the miner attempting to replace their first block (e.g.,
    // with different transactions). The tenure change tx must have
    // cause=BlockFound with a coinbase to be recognized as a tenure-start block.
    let tenure_change_payload = TenureChangePayload {
        tenure_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        prev_tenure_consensus_hash: cur_sortition.data.parent_tenure_id.clone(),
        burn_view_consensus_hash: cur_sortition.data.consensus_hash.clone(),
        previous_tenure_end: block.header.parent_block_id.clone(),
        previous_tenure_blocks: 1,
        cause: TenureChangeCause::BlockFound,
        pubkey_hash: Hash160::from_node_public_key(&StacksPublicKey::from_private(&block_sk)),
    };
    let tenure_change_tx = make_tenure_change_tx(tenure_change_payload);
    let coinbase_tx = StacksTransaction::new(
        TransactionVersion::Testnet,
        TransactionAuth::Standard(TransactionSpendingCondition::new_initial_sighash()),
        TransactionPayload::Coinbase(CoinbasePayload([0; 32]), None, Some(VRFProof::empty())),
    );
    *block.executed_and_skipped_txs_mut() = vec![tenure_change_tx, coinbase_tx];
    block.header.sign_miner(&block_sk).unwrap();

    let exit_flag = Arc::new(AtomicBool::new(false));
    let moved_exit_flag = exit_flag.clone();

    let serve = std::thread::spawn(move || {
        crate::client::tests::write_response_nonblockinig(
            &server,
            response.as_bytes(),
            moved_exit_flag,
        );
    });

    let result = sortitions_view.check_proposal(&stacks_client, &mut signer_db, &block);

    exit_flag.store(true, Ordering::SeqCst);
    serve.join().unwrap();

    // The proposal should be rejected because there's already a locally-accepted
    // block in this tenure. Before the fix, this would have incorrectly passed
    // because get_last_globally_accepted_block would not find the locally-accepted block.
    assert!(
        matches!(result, Err(RejectReason::DuplicateBlockFound)),
        "Expected DuplicateBlockFound rejection when a locally-accepted block exists in the tenure, got: {result:?}"
    );
}
