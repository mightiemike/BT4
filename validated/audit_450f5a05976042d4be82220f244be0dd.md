### Title
Gas-fee rounding to zero lets `MsgExecutePayload` execute UEA payloads for free — ([File: x/uexecutor/keeper/fees.go])

### Summary
`x/uexecutor`'s `CalculateGasCost` / `DeductGasFeesFromReceipt` is the *only* fee-collection mechanism for `MsgExecutePayload`, since that message type is explicitly gasless at the Cosmos ante layer [1](#0-0) . The function unwraps a `LegacyDec` base fee into an integer "upc" amount via integer division by `1e18`, based on the assumption that the fee-market's base fee "is always a whole number of upc" [2](#0-1) . If that base fee is ever fractional and below 1 upc (or is legitimately zero, e.g. `minGasPrice.IsZero()` is an explicitly supported/short-circuited state in the ante pipeline [3](#0-2) ), the division truncates to `0`, `effectiveGasPrice` becomes `0`, and `gasCost` becomes `0` regardless of how much real gas the UEA execution actually consumed [4](#0-3) . `DeductGasFeesFromReceipt` then explicitly treats `gasCost.Sign() <= 0` as "nothing to charge" and returns `nil` without any floor/sanity check [5](#0-4) .

### Finding Description
This is structurally the same bug class as the reported ERC4626 issue: a division that is assumed to never round down to zero is used to gate a payment, and the zero result is not sanity-checked before being treated as "nothing owed." Here:

1. `MsgExecutePayload` is a gasless Cosmos message — the signer pays no ante-level transaction fee [1](#0-0) .
2. The actual EVM computation performed via `CallUEAExecutePayload` → `DerivedEVMCall` is real, metered, committed EVM work with a real gas receipt [6](#0-5) .
3. The **only** cost-recovery step for that real EVM work is `DeductGasFeesFromReceipt`, called right after the EVM call inside a `CacheContext` that is only committed if fee deduction succeeds [7](#0-6) .
4. `CalculateGasCost` derives the fee purely from `baseFee` (ignoring `maxPriorityFeePerGas` per its own comments) [8](#0-7) , and truncates `baseFee`'s `LegacyDec` representation to a whole "upc" integer via a plain `Div`, with no `Ceil()`/rounding-up and no minimum-of-1 floor, unlike the analogous ante-layer computation which uses `Ceil().RoundInt()` for the same kind of price×limit math [9](#0-8) .
5. When `gasCost` rounds to `0`, the code path silently accepts `0` as valid and skips billing entirely — there is no assertion that a non-zero amount of real gas used must translate into a non-zero charge.

### Impact Explanation
Any unprivileged user who can submit `MsgExecutePayload` can get arbitrary-complexity UEA-routed EVM execution funded entirely by the protocol whenever the network base fee is at or near zero (a state the codebase itself treats as valid/expected, e.g. `minGasPrice.IsZero()`). This corrupts gas-fee accounting invariants explicitly in scope ("corruption of ... gas fee accounting ... must not misroute value") and creates an unprivileged, non-network-level denial-of-service vector: since there is no Cosmos-level fee and no minimum EVM-level fee enforced, an attacker can flood the chain with expensive UEA payload executions at zero cost, consuming validator CPU/storage resources without any economic disincentive.

### Likelihood Explanation
Exploitability depends entirely on the live value of the fee-market base fee at the moment of the call — an attacker does not need to manipulate consensus or collude with validators, only to observe the public `ChainMetas`/fee-market state and time submissions accordingly (or the network's default/floor base fee configuration already sits in this range). I was not able to fully confirm from the indexed code what floor is enforced on the feemarket's `base_fee` param over time (e.g. via `MinGasPrice`/AIMD dynamics) — that would require inspecting the fee-market module's parameter-update logic and genesis defaults, which were not fully available in the index. This uncertainty affects the practical likelihood but not the underlying logical defect: the code has no independent floor/sanity check protecting `gasCost` from truncating to zero.

### Recommendation
- In `CalculateGasCost`, round the base-fee unwrapping up (`Ceil()`/`RoundInt` style, matching `app/cosmos/min_gas_price.go`) rather than truncating down, and/or enforce a minimum non-zero `effectiveGasPrice` when `gasUsed > 0`.
- In `DeductGasFeesFromReceipt`, treat `gasCost.Sign() <= 0` while `receipt.GasUsed > 0` as an anomaly to reject or charge a protocol-defined minimum fee, rather than silently skipping fee collection.
- Add an explicit invariant test asserting fee collection is always positive whenever real EVM gas was consumed, independent of the feemarket's current base-fee value.

### Proof of Concept
Conceptual PoC (based on code inspection; not executed):
1. Drive/observe the feemarket base fee to a state where its `LegacyDec` value truncates to `0` upc when divided by `1e18` in `CalculateGasCost` (e.g., a state where `minGasPrice`/base fee is at its floor, as already handled as a first-class case in `app/cosmos/min_gas_price.go`).
2. Submit `MsgExecutePayload` with a `UniversalPayload` whose `To`/`Data` triggers non-trivial EVM computation in the target UEA (arbitrarily large `GasLimit`, high `MaxFeePerGas`/`MaxPriorityFeePerGas` so the `maxFeePerGas >= baseFee` check in `CalculateGasCost` trivially passes).
3. `DerivedEVMCall` executes the payload as a real, committed EVM transaction with non-zero `GasUsed` in the receipt.
4. `CalculateGasCost` returns `gasCost == 0` due to the truncation; `DeductGasFeesFromReceipt` returns `nil` without deducting or burning any coins.
5. Repeat arbitrarily — the attacker obtains unlimited free EVM execution through the UEA path with no economic cost, while the module has already committed the `CacheContext` (`writeCache()`) since `feeErr == nil`.

### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.

func (k Keeper) CallUEAExecutePayload(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	universal_payload *types.UniversalPayload,
	verificationData []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiUniversalPayload, err := types.NewAbiUniversalPayload(universal_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	gasLimit := new(big.Int)
	gasLimit, ok := gasLimit.SetString(universal_payload.GasLimit, 10)
	if !ok {
		return nil, fmt.Errorf("invalid gas limit: %s", universal_payload.GasLimit)
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		gasLimit,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"executeUniversalTx",
		abiUniversalPayload,
		verificationData,
	)
}
