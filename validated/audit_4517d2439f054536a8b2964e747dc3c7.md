### Title
Unauthenticated, fee-free, unlimited account creation via `AccountInitDecorator` + gasless `MsgExecutePayload` — persistent state-bloat DoS - (File: app/ante/account_init_decorator.go)

### Summary
`AccountInitDecorator` auto-creates and persists a brand-new on-chain account for *any* signer of a gasless transaction, verifying only a self-consistent signature over hardcoded `account_number=0, sequence=0`. Because `MsgExecutePayload` is gasless and explicitly allows "any account" as signer [1](#0-0) , and because Cosmos SDK's standard `runTx` commits AnteHandler state changes independently of message execution success, an attacker can mint unlimited fresh accounts on-chain for zero cost and zero rate limiting, regardless of whether the underlying payload subsequently fails.

### Finding Description
`AccountInitDecorator.AnteHandle` in [2](#0-1)  only checks `txpolicy.IsGaslessTx(tx)` to decide whether to run the account-bootstrap path. `IsGaslessTx` in [3](#0-2)  whitelists `MsgExecutePayload` unconditionally — unlike the vote messages, it carries no bonded-validator gate.

When the signer has no account yet, the decorator verifies the signature against hardcoded `accSequence=0, accNum=0` [4](#0-3) , then unconditionally creates the account, sets sequence to 1, persists it, and **returns without calling `next`** — short-circuiting the remaining sig/gas decorators [5](#0-4) .

Crucially, this is standard ante-handler behavior in the Cosmos SDK: `baseapp.runTx` commits ante-produced state changes to the parent context as soon as the ante handler returns without error, *before* message execution runs, and independently of whether message execution later fails. `NewAnteHandler`/`NewCosmosAnteHandler` here are unmodified in that respect [6](#0-5) [7](#0-6) . This means: even if the subsequent `MsgExecutePayload` execution fails (e.g. `k.ExecutePayload` returns "UEA is not deployed" per [8](#0-7) ), the newly-created account persists in state.

No fee is charged (gasless), no minimum balance is required, no per-address rate limit exists, and the attacker can generate an arbitrary number of fresh keypairs, each producing exactly one valid "new account" signature. This lets an unprivileged attacker permanently grow chain state (auth store + IAVL tree) at effectively zero cost, block after block, with no privileged actor, malicious validator, or external-chain assumption involved.

### Impact Explanation
This is a state-growth / resource-exhaustion denial-of-service vector that is not network-level (it is an application/state-layer effect) and is triggerable purely through the default, publicly-documented `MsgExecutePayload` gasless submission path — matching the in-scope "denial of service ... reachable without privileged control" criterion. Sustained abuse increases disk/IAVL storage and sync cost for every honest full node and validator indefinitely, with no compensating fee revenue, and no cleanup path (accounts are never pruned).

### Likelihood Explanation
High reachability: any external party can generate keys locally, sign a trivial "new account" payload each time, and broadcast it — no bonded-validator status, balance, or governance approval is required, consistent with `MsgExecutePayload`'s documented "any account may submit" design intent for legitimate UX purposes [9](#0-8) .

### Recommendation
- Rate-limit or fee-gate first-use account creation (e.g., require a minimal bond/fee burned from a pre-funded relayer even for gasless messages, or cap new-account creations per block/per source).
- Ensure a subsequently-failing `MsgExecutePayload` (or other gasless message) cannot leave a permanent, cost-free account behind — e.g., only persist the new account if the message itself later succeeds, or require the UEA/payload validity to be confirmed before account materialization.
- Consider restricting the `AccountInitDecorator` fast path to message types where the recipient/target already has a provable claim (e.g., a pre-funded balance, as already handled by `ExecutePayload`'s pre-funded auto-deploy branch at [8](#0-7) ), rather than any never-seen signer.

### Proof of Concept
1. Generate a fresh ECDSA/Ed25519 keypair `K_i` off-chain (free, unlimited).
2. Construct a `MsgExecutePayload` tx signed by `K_i` with `account_number=0, sequence=0`, using an arbitrary/garbage `UniversalAccountId`/payload (execution failure is irrelevant to the exploit).
3. Broadcast the tx. `AccountInitDecorator` verifies the self-consistent signature, creates and persists a new account for `K_i` with sequence=1, and short-circuits the ante chain — no fee is deducted (gasless).
4. `k.ExecutePayload` may fail (e.g., UEA not deployed, zero balance) — the message fails, but the account created in step 3 already committed to state per Cosmos SDK's `runTx` ante/msg separation.
5. Repeat with `K_1 … K_n` for unbounded `n`, at zero marginal cost, to grow on-chain account state without bound.

### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}

func NewAnteHandler(options HandlerOptions) sdk.AnteHandler {
	return func(
		ctx sdk.Context, tx sdk.Tx, sim bool,
	) (newCtx sdk.Context, err error) {
		var anteHandler sdk.AnteHandler

		txWithExtensions, ok := tx.(authante.HasExtensionOptionsTx)
		if ok {
			opts := txWithExtensions.GetExtensionOptions()
			if len(opts) > 0 {
				switch typeURL := opts[0].GetTypeUrl(); typeURL {
				case "/cosmos.evm.vm.v1.ExtensionOptionsEthereumTx":
					// handle as *evmtypes.MsgEthereumTx
					anteHandler = newMonoEVMAnteHandler(ctx, options)
				case "/cosmos.evm.types.v1.ExtensionOptionDynamicFeeTx":
					// cosmos-sdk tx with dynamic fee extension
					anteHandler = NewCosmosAnteHandler(ctx, options)
				default:
					return ctx, errorsmod.Wrapf(
						errortypes.ErrUnknownExtensionOptions,
						"rejecting tx with unsupported extension option: %s", typeURL,
					)
				}

				return anteHandler(ctx, tx, sim)
			}
		}

		// handle as totally normal Cosmos SDK tx
		switch tx.(type) {
		case sdk.Tx:
			anteHandler = NewCosmosAnteHandler(ctx, options)
		default:
			return ctx, errorsmod.Wrapf(errortypes.ErrUnknownRequest, "invalid transaction type: %T", tx)
		}

		return anteHandler(ctx, tx, sim)
	}
}
