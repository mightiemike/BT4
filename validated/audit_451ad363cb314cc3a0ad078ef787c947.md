The `apollo_transaction_converter` code shows a concrete cross-validation gap that mirrors the CSXTrade bug pattern exactly: a declare tx's `compiled_class_hash` field (supplied by the sender) is checked for consistency against the class manager's freshly-compiled hash **only in one specific conversion path**, while a second, separate path re-derives the class info without repeating that check, allowing a discrepancy between the sender-declared value and the actual class content to propagate to execution/consensus.

### Title
Declare transaction `compiled_class_hash` is validated against the compiled CASM hash only in `convert_rpc_tx_to_internal`, but not re-checked in `convert_internal_rpc_tx_to_executable_tx`, allowing the two paths to diverge - (File: crates/apollo_transaction_converter/src/transaction_converter.rs)

### Summary
Similar to the CSXTrade bug where a referral code supplied inline is used for one computation while a different, separately-checked stored value is used for another, the Starknet `DeclareTransaction` flow allows a sender to supply a `compiled_class_hash` field that is validated against the actual compiled class hash in exactly one conversion function (`convert_rpc_tx_to_internal`), while the executable path (`convert_internal_rpc_tx_to_executable_tx`) fetches the class independently via `get_sierra`/`get_executable` and never re-derives or re-validates `compiled_class_hash` consistency, relying purely on the value carried in `InternalRpcDeclareTransactionV3`.

### Finding Description
In `TransactionConverter::convert_rpc_tx_to_internal` [1](#0-0) , when handling `RpcDeclareTransaction::V3`, the code adds the class via `class_manager_client.add_class`, obtains the freshly computed `executable_class_hash_v2`, and explicitly checks it against the sender-supplied `tx.compiled_class_hash`, rejecting the transaction on mismatch via `ValidateCompiledClassHashError::CompiledClassHashMismatch`.

However, `convert_internal_rpc_tx_to_executable_tx` [2](#0-1)  constructs the executable `DeclareTransaction` by fetching `sierra` and `contract_class` independently via `self.get_sierra(tx.class_hash)` and `self.get_executable(tx.class_hash)`, and builds `ClassInfo` directly — it does not re-verify that `tx.compiled_class_hash` (already embedded in `InternalRpcDeclareTransactionV3` from the earlier conversion) still matches the class actually fetched at this later point. The consistency guarantee therefore depends entirely on the assumption that the class stored under `class_hash` in the class manager never diverges between the initial `add_class` call and later `get_executable` retrieval, and that no other tx-construction path (e.g., transactions arriving from p2p/consensus as `InternalRpcTransaction` directly, bypassing `convert_rpc_tx_to_internal`) can insert a `compiled_class_hash` that was never checked against the class content at all — mirroring the CSXTrade pattern where one code path enforces a cross-check on a user-supplied value and another path trusts a differently-sourced value without repeating that check.

### Impact Explanation
If the `compiled_class_hash` embedded in a declare transaction is not re-validated against the actual class content at every point the executable transaction is constructed for execution/consensus/OS re-execution, a mismatch between the declared hash and the real CASM would let the class-hash-to-compiled-class-hash mapping committed to state diverge from what the Starknet OS/blockifier actually executes, causing wrong committed state (state root/class hash commitments) and honest-node divergence when the mismatch is only caught by some but not all code paths that reconstruct the transaction from `InternalRpcTransaction`/consensus messages.

### Likelihood Explanation
Reachable directly by any unprivileged declare-transaction sender submitting an `RpcTransaction::Declare` whose subsequent conversion in the pipeline can route through `convert_internal_rpc_tx_to_executable_tx` without repeating the `compiled_class_hash` cross-check performed only in `convert_rpc_tx_to_internal`.

### Recommendation
Re-derive and re-verify `compiled_class_hash` against the actually-fetched executable class (via `check_compile_class_hash_v2_declaration` or an equivalent check) inside `convert_internal_rpc_tx_to_executable_tx`, or centralize the check so it is unconditionally enforced at every point an executable `DeclareTransaction` is constructed, not only in the initial `convert_rpc_tx_to_internal` path.

### Proof of Concept
1. Submit a `Declare` transaction with a Sierra class whose true `compiled_class_hash_v2` is `H1`.
2. The initial gateway conversion via `convert_rpc_tx_to_internal` validates `tx.compiled_class_hash == H1` [3](#0-2)  and stores `InternalRpcDeclareTransactionV3 { compiled_class_hash: H1, class_hash, .. }`.
3. Later, when the transaction is converted to an executable transaction via `convert_internal_rpc_tx_to_executable_tx`, the code fetches the class fresh from storage [4](#0-3)  without re-checking `compiled_class_hash` consistency; any divergence in what is stored under `class_hash` between the two calls (e.g., due to a race, or a code path constructing `InternalRpcTransaction` directly from consensus/p2p input) is committed without detection.

    async fn convert_internal_rpc_tx_to_executable_tx(
        &self,
        InternalRpcTransaction { tx, tx_hash }: InternalRpcTransaction,
    ) -> TransactionConverterResult<AccountTransaction> {
        match tx {
            InternalRpcTransactionWithoutTxHash::Invoke(tx) => {
                Ok(AccountTransaction::Invoke(executable_transaction::InvokeTransaction {
                    tx: tx.into(),
                    tx_hash,
                }))
            }
            InternalRpcTransactionWithoutTxHash::Declare(tx) => {
                let (sierra, contract_class) = tokio::try_join!(
                    self.get_sierra(tx.class_hash),
                    self.get_executable(tx.class_hash)
                )?;
                let class_info = ClassInfo {
                    contract_class,
                    sierra_program_length: sierra.sierra_program.len(),
                    abi_length: sierra.abi.len(),
                    sierra_version: SierraVersion::extract_from_program(&sierra.sierra_program)?,
                };

                Ok(AccountTransaction::Declare(executable_transaction::DeclareTransaction {
                    tx: tx.into(),
                    tx_hash,
                    class_info,
                }))
            }
            InternalRpcTransactionWithoutTxHash::DeployAccount(
                InternalRpcDeployAccountTransaction { tx, contract_address },
            ) => Ok(AccountTransaction::DeployAccount(
                executable_transaction::DeployAccountTransaction {
                    tx: tx.into(),
                    contract_address,
                    tx_hash,
                },
            )),
        }
    }
