## Finding: Gasless whitelist lets any unprivileged UEA sender submit fee-free, computation-heavy `MsgExecutePayload`/`MsgMigrateUEA` transactions that revert after consuming full EVM gas — free-of-charge DoS

### Summary
Push Chain's gasless-transaction subsystem (`app/txpolicy/gasless.go`, `app/ante/fee.go`, `app/cosmos/min_gas_price.go`, `app/ante/account_init_decorator.go`) exempts a fixed whitelist of message types from *both* fee deduction and minimum-gas-price checks. That whitelist is not restricted to bonded Universal Validators — it also includes `uexecutor.v1.MsgExecutePayload` and `uexecutor.v1.MsgMigrateUEA`, which any external, unprivileged UEA owner can sign and submit, and which can trigger arbitrarily expensive full EVM execution (`CallUEAExecutePayload`) before the node discovers (post-execution) that the sender cannot pay and rolls the state back. This is the same bug class as the SORA report: a set of user-reachable extrinsics carry zero mandatory cost, so an attacker can flood the chain with expensive-to-process transactions at no cost, consuming validator computation/block-gas budget as a denial-of-service vector.

### Finding Description
`IsGaslessTx` in `app/txpolicy/gasless.go` marks a tx gasless if *every* message (including inside `authz.MsgExec`) is one of:
```
/uexecutor.v1.MsgMigrateUEA
/uexecutor.v1.MsgExecutePayload
/uexecutor.v1.MsgVoteInbound
/uexecutor.v1.MsgVoteOutbound
/utss.v1.MsgVoteTssKeyProcess
/utss.v1.MsgVoteFundMigration
/uexecutor.v1.MsgVoteChainMeta
``` [1](#0-0) 

Unlike the `Vote*`/TSS messages — whose msg-server handlers explicitly gate on `IsBondedUniversalValidator` before doing any real work (`x/uexecutor/keeper/msg_server.go` lines 82-89, 122-129, 156-162) — `MsgExecutePayload` and `MsgMigrateUEA` are open to any signer and immediately dispatch to expensive EVM execution logic: [2](#0-1) 

`DeductFeeDecorator.AnteHandle` skips all fee collection for gasless txs: [3](#0-2) 

and `MinGasPriceDecorator` similarly skips the FeeMarket minimum-fee check for the same class of tx (per `app/README.md`): [4](#0-3) 

`AccountInitDecorator` further allows a brand-new, unfunded account to be created mid-pipeline and used immediately (bypassing the rest of the ante chain including balance requirements): [5](#0-4) 

The actual message handler for direct `MsgExecutePayload` calls performs full EVM execution via `CallUEAExecutePayload` *before* attempting to charge the sender: [6](#0-5) 

The fee is computed and deducted only afterward in `DeductGasFeesFromReceipt`, and only fails (causing rollback) if the recipient lacks upc balance: [7](#0-6) 

Because `feeErr` causes the whole Cosmos message to return an error, the outer `baseapp.runMsgs` cache context is discarded and no state persists — but the EVM computation (bounded by the attacker-declared `GasLimit`/tx `GasWanted`, up to the per-block gas limit) has already been fully executed by every validator during `DeliverTx`. The attacker paid nothing: no SDK fee (gasless whitelist), no minimum gas price, and no requirement to ever fund the UEA/account.

### Impact Explanation
This falls squarely within the allowed "denial of service ... reachable without privileged control" impact: an unprivileged external attacker (any address, freshly generated, never funded) can:
1. Generate an unlimited number of ed25519/secp256k1 keypairs and derive fresh Cosmos accounts.
2. Sign `MsgExecutePayload` messages targeting a UEA with a maximal `GasLimit`/expensive payload, using the `AccountInitDecorator` bootstrap path so no funding is required.
3. Submit these transactions with zero fee and no minimum gas price requirement (gasless whitelist).
4. Have every validator run full EVM execution for each transaction during block execution, consuming block gas/computation, and only then discover the sender cannot pay — reverting the tx but not refunding the wasted computation to the network.

Repeated at volume, this crowds out legitimate transactions' block-gas budget and burns validator CPU for free, degrading chain throughput/availability — the same "zero-weight extrinsic spam" pattern as the SORA finding, now realized via the gasless whitelist rather than a literal zero-weight annotation.

### Likelihood Explanation
High. No special privilege, staked bond, or existing balance is required — the exact opposite of the `Vote*`/TSS gasless messages, which are gated behind `IsBondedUniversalValidator`. `MsgExecutePayload`/`MsgMigrateUEA` are ordinary user-facing entry points intentionally left ungated for gasless support so that new UEA users don't need PC gas up front; this same design choice is what removes the economic cost that would otherwise deter spam.

### Recommendation
- Require the sender (or associated UEA) to hold a minimum bonded/pre-funded balance, or apply a cheap up-front deposit/pre-check before allowing `CallUEAExecutePayload`'s full EVM execution to run, so failed fee deduction is detected before expensive computation rather than after.
- Alternatively, remove `MsgExecutePayload`/`MsgMigrateUEA` from the unconditional gasless whitelist and instead charge a minimal, non-refundable base SDK fee for these message types (independent of the post-execution PRC20/upc gas accounting), mirroring `checkTxFeeWithValidatorMinGasPrices` used for normal txs.
- Rate-limit/throttle per-signer gasless submissions in the mempool (e.g., via a dedicated ante decorator counting gasless-message submissions per account/per block) to bound worst-case spam even if a floor fee cannot be added.

### Proof of Concept
1. Generate a new keypair/address `A` with zero on-chain balance and no pre-existing account.
2. Deploy or target an existing UEA the attacker doesn't need to own funds in.
3. Build `MsgExecutePayload{Signer: A, UniversalAccountId: ..., UniversalPayload: {GasLimit: <large>, Data: <expensive contract call>}}`.
4. Submit as a tx with `Fee=0`, `GasWanted=<large>` — passes `MinGasPriceDecorator` (skipped), `DeductFeeDecorator` (skipped via `IsGaslessTx`), and `AccountInitDecorator` (creates account with `sequence=1`, bypasses remaining ante checks) per `app/ante/account_init_decorator.go` lines 52-75.
5. Message handler executes `CallUEAExecutePayload` (full EVM gas consumption) then `DeductGasFeesFromReceipt` fails due to zero upc balance on the UEA; the whole tx errors out with `"gas fee deduction failed"`, per `x/uexecutor/keeper/msg_execute_payload.go` lines 89-93 and `x/uexecutor/keeper/fees.go` lines 134-140 — no state change persists, no fee is ever paid.
6. Repeat with a fresh keypair each time (accounts are free to create via step 4) to sustain a continuous, cost-free flood of block-gas-consuming transactions.

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
