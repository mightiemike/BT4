### Title
Deposit-auto-swap and gas-refund paths derive `minPCOut` from a manipulable single-block AMM spot quote, enabling sandwich attacks that steal value from GAS/GAS_AND_PAYLOAD depositors and outbound gas-refund recipients - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
Push Chain's own commit history shows the team already recognized and partially fixed the exact class of bug described in the external report: the GAS/GAS_AND_PAYLOAD inbound routes used to call `CallPRC20DepositAutoSwap` with zero slippage protection, and were "fixed" by computing `minPCOut` as 95% of a freshly-fetched Uniswap V3 QuoterV2 spot quote [1](#0-0) . The same pattern was copied into the gas-refund swap path [2](#0-1) . However, the fix only guards against slippage occurring *between* the quote fetch and the swap execution — it does nothing to protect against the quote itself being computed from a spot AMM price that an unprivileged attacker manipulated in a prior transaction. Because the quote and the swap execute inside the same atomic Cosmos SDK message handling (no time/tx gap between `GetSwapQuote` and `CallPRC20DepositAutoSwap`), an attacker can sandwich the finalizing vote transaction, distort the Uniswap V3 pool price, and cause the deposit/refund swap to lock in a manipulated (low) exchange rate that still satisfies the 5% band — draining value from the depositing user (or the outbound sender receiving a gas refund) into the attacker's pocket. This is the direct on-chain analog of `mintForToken()`'s missing/ineffective slippage protection.

### Finding Description
Three call sites mint PC-denominated value for a user based on a Uniswap V3 spot quote with only a fixed 5% band as protection:

1. `ExecuteInboundGas` — fetches `quote := GetSwapQuote(...)` then computes `minPCOut = quote*95/100` and immediately calls `CallPRC20DepositAutoSwap` in the same function invocation [3](#0-2) .
2. `gasAndPayloadDepositAutoSwap` — identical pattern for GAS_AND_PAYLOAD inbound execution [4](#0-3) .
3. `applyGasRefund` — identical pattern for refunding unused outbound gas via `CallUniversalCoreRefundUnusedGas` [2](#0-1) .

`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` — a pure spot-price read against the live Uniswap V3 pool reserves, not a TWAP or external oracle [5](#0-4) . Because the quote fetch and the swap execution happen back-to-back inside the same handler with no intervening block, the 5% band (`minPCOut = quote * 95 / 100`) only bounds slippage *within* that single call — it provides zero protection if the pool's spot price was already pushed away from fair value by an attacker's transaction that landed just before the vote-finalizing transaction in the same or a preceding block.

This is materially the same defect flagged in the external report: `mintForToken()` computed the mint amount from a manipulable price reference with no independent floor tied to fair value, so a frontrunner could distort the reference right before the victim's transaction executes, capture the spread, then reverse the distortion. Here, an unprivileged actor can:
1. Observe (or predict, since UV voting is public and deterministic once quorum is reachable) that a `MsgVoteInbound`/`MsgVoteOutbound` transaction is about to finalize and trigger `ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap` / `applyGasRefund` for a known PRC20/gas-token amount.
2. Submit an ordinary swap against the public WPC/PRC20 Uniswap V3 pool that depresses the token's price just before that transaction executes.
3. The `GetSwapQuote` call inside the vote-finalization returns the depressed price; `minPCOut` is set to 95% of that depressed number, so `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes successfully against the manipulated pool, converting the user's/protocol's token amount into far less PC than fair value.
4. The attacker reverses their initial swap afterward, extracting the value that should have gone to the depositing user or the gas-refund recipient.

### Impact Explanation
This directly corrupts native/PRC20 asset accounting and gas-refund accounting reachable purely from ordinary, unprivileged transaction submission (an inbound deposit or an outbound gas refund), which is explicitly in scope ("corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting"). Victims (end users bridging GAS/GAS_AND_PAYLOAD, or outbound senders due excess-gas refunds) receive a PC amount that can be pushed down to (quote_manipulated × 0.95) instead of a fair-value amount, while the attacker profits the difference by trading against the same pool. Severity scales with pool liquidity/depth and the size of the bridged/refunded amount — for shallow pools this can result in substantial value loss to the user with no honest-validator or privileged-actor involvement.

### Likelihood Explanation
Likelihood is moderate-to-high on any chain where the WPC/PRC20 Uniswap V3 pool has moderate-to-shallow liquidity, since the attack requires only: (a) capital to move the pool price temporarily, and (b) observability of an impending inbound/outbound finalization (which is realistic — UV votes and pending inbound/outbound records are queryable on-chain, and the amounts/tokens involved are visible before the 2/3 threshold is reached). No validator collusion, relayer compromise, or privileged access is required — this is an ordinary DEX price-manipulation/sandwich attack layered on top of a protocol code path that treats a fresh spot quote as a trustworthy price floor.

### Recommendation
- Do not derive `minPCOut` solely from an instantaneous `quoteExactInputSingle` spot call taken inside the same execution as the swap. Use a manipulation-resistant reference (e.g., a TWAP over a meaningful window, or an external price oracle already used elsewhere for `ChainMeta`/gas pricing) to compute the fair-value floor, and apply the slippage band on top of that reference rather than on top of the same-block spot price.
- Alternatively/additionally, add sanity bounds comparing the spot quote against a recent moving-average or previously observed price for the pair, and abort/queue for manual resolution (rather than silently executing) if deviation exceeds a safe threshold.
- Consider widening the atomicity gap analysis: since quote-then-swap already happens atomically (no exploitable internal gap), the actual exposure is entirely about the *input* price being attacker-influenced before the transaction lands — thus the fix must target price-source integrity, not just internal slippage bounding.

### Proof of Concept
1. Identify a pending `MsgVoteInbound` (or an outbound about to be observed as successful) for a GAS/GAS_AND_PAYLOAD inbound bridging PRC20 token `T` of amount `A`, destined to be swapped to PC via `ExecuteInboundGas` → `CallPRC20DepositAutoSwap` [6](#0-5) .
2. Before that vote reaches 2/3 quorum and executes, submit a large swap on the public T/WPC Uniswap V3 pool that pushes T's price down relative to WPC.
3. Once the vote finalizes, `GetSwapQuote(T, WPC, fee, A)` returns a depressed `quote` [7](#0-6) ; `minPCOut = quote*95/100` is computed and passed to `CallPRC20DepositAutoSwap`, which executes against the still-depressed pool and mints the recipient a PC amount well below fair value [8](#0-7) .
4. Reverse the initial swap on the T/WPC pool, realizing the price-impact spread as profit while the bridging user (or gas-refund recipient) ends up with less PC than the true market rate for amount `A`.

```go
// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
```

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```

```go
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
```
