### Title
Paused vault `accrue()` silently returns stale indexes instead of reverting, letting borrow/repay/deposit/redeem proceed on frozen interest state - (File: mainnet/contracts/vault/v0-vault-stx.clar)

### Summary
Each vault's `accrue` function checks a per-operation pause flag (`(get accrue states)`), but when that flag is set it does not revert — it returns `(ok { index: idx, lindex: lidx })` with the pre-pause values, silently skipping the interest-index update instead of blocking the caller. Every state-mutating vault entrypoint (`system-borrow`, `deposit`, `redeem`, etc.) unconditionally calls `(try! (accrue))` and continues to execute using whatever `accrue` returns, so a "pause" on interest accrual is invisible to callers rather than halting the operation. The market's own `accrue-and-cache` wrapper then caches this frozen (or fresh) value keyed only by `{timestamp, aid}` and reuses it for all downstream LTV/health/debt-conversion math without any indication that the value came from a paused source.

### Finding Description
In `mainnet/contracts/vault/v0-vault-stx.clar` (and identically in `v0-vault-sbtc.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, and the stSTX/stSTXbtc variants):

```
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          ...
``` [1](#0-0) 

This is the "pause that passes through instead of reverting" pattern: the guard (`pause-states.accrue`) is checked, but its effect is only to skip the state update — the function still returns `ok`, so every caller of `accrue` treats the paused state exactly like a successful accrual.

Every state-changing vault function binds this pass-through result unconditionally at the top of its `let`, e.g. `system-borrow`:
```
(define-public (system-borrow (amount uint) (receiver principal))
  (let (
      (states (var-get pause-states))
      (u (try! (accrue)))
      ...
``` [2](#0-1) 

Because `accrue` never errors while `accrue` is paused, `system-borrow`, `deposit`, and `redeem` proceed to mutate `principal-scaled`, `total-borrowed`, and `assets` against the **frozen** `index`/`lindex`, i.e. debt and share value stop compounding for the duration of the pause while normal borrowing/repaying/depositing/redeeming continues unaffected.

On top of this, the hub contract caches whatever `accrue` (via `vault-accrue`) returns, with no distinction for a paused vs. non-paused source:
```
(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))
    (match cached?
      cached-indexes (ok cached-indexes)
      (let ((indexes (try! (vault-accrue aid))))
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
``` [3](#0-2) 

The market uses these cached indexes to convert scaled debt (`convert-to-scaled-debt`), compute collateral/debt USD values, and evaluate health checks in `borrow`, `repay`, and `liquidate`. None of that logic differentiates a legitimately-updated index from one that is stale because the source vault's accrual was paused.

### Impact Explanation
While a vault's `accrue` is paused, the index that determines how much interest has accrued on borrowed principal stops advancing, yet borrowers can keep borrowing and repaying at the frozen rate, and suppliers keep depositing/redeeming against a share price that no longer reflects true elapsed-time interest. Any interest that should have accrued to depositors during the pause window is permanently lost — it is never retroactively applied once accrual resumes, since the index only moves forward from the point accrual is un-paused. This is a **temporary/permanent freezing of unclaimed yield** for liquidity providers in the affected vault, without the pause actually stopping user activity as its name implies.

### Likelihood Explanation
Triggering the condition requires only that the vault's `accrue` pause flag be set (an operational/admin action already supported by the contract's own pause-state design) combined with any user calling `borrow`, `repay`, `deposit`, or `redeem` during that window — no privileged action beyond normal DAO/pauser operation is needed to observe the pass-through behavior, and it happens automatically on every such call while the flag is active.

### Recommendation
Make the `accrue` pause a true guard: when `(get accrue states)` is true, `system-borrow`, `deposit`, and `redeem` should either revert (consistent with all their other `ERR-PAUSED` checks) or explicitly track/apply the skipped interest once un-paused, instead of silently proceeding with a frozen index. Likewise, `accrue-and-cache` in `v0-4-market.clar` should not cache/reuse indexes obtained while the underlying vault reports its accrual paused.

### Proof of Concept
1. DAO/pauser sets `pause-states.accrue = true` on `v0-vault-stx` (a supported, self-contained pause toggle) while `pause-states.borrow`/`deposit`/`redeem` remain `false`.
2. `index`/`lindex` are frozen at their pre-pause values [4](#0-3) .
3. A user calls `market.borrow` for the STX asset; `borrow` in `v0-4-market.clar` calls `accrue-and-cache` -> `vault-accrue` -> `accrue`, which returns the frozen index without error [5](#0-4) .
4. Borrow proceeds normally, scaled debt is computed off the frozen index, and time continues to pass on-chain with no additional interest being charged to the borrower or credited to suppliers.
5. When the pause is lifted, the index resumes progression only from the frozen value forward — the interest that should have accrued during the pause window is permanently unrecoverable, representing a freeze/loss of yield owed to depositors.
