### Title
Fold that absorbs per-asset socialization failure still reverts the entire `liquidate()` call, permanently blocking liquidation of underwater positions - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`liquidate()` seizes collateral and reduces debt via `try!` calls that succeed and commit within the transaction, then — if the borrower has no collateral left — tries to socialize the borrower's remaining bad debt through a `fold` over `socialize-debt-asset`. That fold is written to *absorb* a per-item failure (short-circuiting subsequent list items) rather than aborting immediately, but the caller then turns that absorbed failure into a hard `asserts!` revert that unwinds the entire liquidation, including the already-successful debt repay and collateral seizure that occurred earlier in the same atomic transaction.

### Finding Description
`socialize-debt-asset` is a fold reducer used to write off a borrower's remaining debt entries after their collateral is exhausted: [1](#0-0) 

It uses `unwrap!` on `vault-socialize-debt` and on `contract-call? .v0-market-vault debt-remove-scaled` to set `{ borrower: ..., success: false }` if either call errors, and every subsequent list item is skipped via the `(if (not (get success acc)) acc)` early-return — i.e. the fold "absorbs" the failure for the rest of the list instead of reverting at the point of failure.

The caller in `liquidate()` then converts that absorbed per-item failure into a full transaction revert: [2](#0-1) 

Crucially, by the time this fold runs, `liquidate()` has already executed `vault-system-repay` (debt repaid to the vault) and `debt-remove-scaled` / `collateral-remove` (collateral seized to the liquidator) via `try!` earlier in the same function: [3](#0-2) 

Because Clarity transactions are atomic, the `(asserts! (get success socialization-result) ERR-BAD-DEBT-SOCIALIZATION-FAILED)` at line 1548 unwinds *all* state changes made earlier in the same call — the repay, the debt reduction, and the collateral transfer — the moment any single remaining debt asset fails to socialize. This is the "fold that absorbs failure" pattern followed by a later guard that discards the entire multi-step operation on abort.

### Impact Explanation
If any one of the borrower's remaining debt assets is in a state where `vault-socialize-debt` or `.v0-market-vault debt-remove-scaled` returns an error for that asset (e.g., a scaled-debt/state mismatch causing an internal `asserts!`/`unwrap!` to fail in the vault or market-vault logic), the borrower's fully-collateral-drained, insolvent position can never be liquidated: every future `liquidate()` call re-derives `no-collateral-left = true`, re-attempts socialization of the same fixed debt-asset list, hits the same failure, and reverts the whole transaction — including the collateral seizure and repay that would otherwise have succeeded. This permanently freezes the bad-debt position: it can never be closed, its uncollateralized debt is never written off, and its residual collateral (if any is later added) is never seized. This lands on temporary/permanent freezing of funds (the position's collateral/debt), and left unresolved indefinitely, contributes to protocol insolvency since bad debt cannot be socialized off the books.

### Likelihood Explanation
This is a single-transaction analog, not two-user interference — it operates purely on one borrower's own debt list within one atomic `liquidate()` call, matching the allowed "fold absorbs failure" mechanism class. I confirmed the fold-then-assert-then-revert control flow directly from the code. I was **not able to fully verify**, within the scope of this pass, the exact internal implementation of `vault-socialize-debt` and `.v0-market-vault debt-remove-scaled` (i.e., the precise condition under which one of these calls legitimately errors outside of a DAO-controlled pause, which would be out of scope). This limits certainty on how easily/likely a real-world trigger for the initial per-item failure is, though the revert-cascades-through-atomic-tx mechanism itself is confirmed and is the root cause of turning a single-asset socialization hiccup into a total liquidation block.

### Recommendation
Do not let a socialization failure on one debt asset revert the collateral seizure and debt repay that already succeeded. Either (a) make `socialize-debt-asset` best-effort per asset (skip and log failed assets instead of aborting the whole liquidation), or (b) decouple bad-debt socialization into a separate, retriable step/transaction from the collateral-seizing liquidation, so a failure to write off one debt asset cannot strand the entire liquidation and re-freeze already-drained collateral.

### Proof of Concept
1. Borrower has multiple debt assets outstanding and their collateral gets seized to zero in a `liquidate()` call (`no-collateral-left` becomes `true`), per lines 1526-1532.
2. `fresh-debt-list` (remaining debt assets excluding the one just liquidated) is folded through `socialize-debt-asset` (lines 1544-1547, 879-903).
3. Assume one asset in that list is in a state where `vault-socialize-debt` or `debt-remove-scaled` returns an error for it (e.g., a scaled/stored-debt mismatch). The fold's `unwrap!` sets `success: false`; remaining items are skipped by the early-return guard (line 883-884), but the fold call itself returns normally with `success: false`.
4. Back in `liquidate()`, `(asserts! (get success socialization-result) ERR-BAD-DEBT-SOCIALIZATION-FAILED)` at line 1548 fires, reverting the **entire** `liquidate()` transaction, including the `vault-system-repay` (line 1496) and `debt-remove-scaled`/`collateral-remove` (lines 1499-1512) that had already executed.
5. Since the failing debt asset and the borrower's state are unchanged by this reverted attempt, every subsequent liquidator who calls `liquidate()` on this borrower hits the identical code path and the identical revert — the position is permanently unliquidatable, freezing its collateral/debt indefinitely.

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

            ;; Socialize in vault - pass scaled directly to avoid rounding
            (unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)
            ;; Refresh cache with new indexes post-write-down (lindex decreased)
            (map-set index-cache
                     { timestamp: stacks-block-time, aid: asset-id }
                     (unwrap! (vault-accrue asset-id) failed-status))
            ;; Remove from obligation
            (unwrap! (contract-call? .v0-market-vault
                                      debt-remove-scaled
                                      borrower
                                      scaled-debt
                                      asset-id) failed-status)
          acc)
        ))
