### Title
Starknet OS `replace_class` syscall omits the "class must be declared" check enforced by the Blockifier - honest-node state divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The external report describes Avo trusting a user-supplied class identifier without validating it against an allow-list, leading to crashes/undefined behavior when the class doesn't correspond to what the application expects. The reachable analog in this sequencer is the `replace_class` syscall: an unprivileged contract can invoke it with an **arbitrary, attacker-chosen `class_hash`** felt in its calldata. The Blockifier (the execution engine that actually builds/validates blocks) explicitly rejects this call when the class hash is not declared, but the Starknet OS Cairo implementation used for re-execution/proving skips this check entirely, as marked by an explicit `TODO`.

### Finding Description
In the Blockifier, `replace_class` reads the compiled class before mutating state, causing an error if the class is undeclared: [1](#0-0) 

This is confirmed by the test asserting the transaction fails with `"is not declared"` for both Cairo0 and Cairo1 test contracts: [2](#0-1) 

In contrast, the Starknet OS's Cairo implementation of the same syscall (`execute_replace_class` in `syscall_impls.cairo`, used for Cairo1/current syscalls) directly overwrites the contract's class hash in `contract_state_changes` without checking that a class with that hash was ever declared. The missing check is explicitly flagged by a TODO comment: [3](#0-2) 

The same omission exists in the deprecated (Cairo0) syscall path of the OS: [4](#0-3) 

This is a direct structural analog to the Avo bug class (CWE-20/CWE-470): a user-controlled identifier (here, `class_hash` instead of a Ruby class name) is trusted and acted upon by one code path (the OS) without the same input validation performed by the other authoritative path (the Blockifier).

### Impact Explanation
The Starknet OS is the program executed (and proven) to re-derive/verify the state transition that the sequencer already committed via the Blockifier. If a transaction calls `replace_class_syscall(class_hash)` with an undeclared `class_hash`:
- The Blockifier (used when the sequencer builds/executes the block) reverts the transaction (or the call fails) because the class is not declared.
- The Starknet OS, when re-executing the same transaction to build the STARK proof / re-derive the state diff, does **not** perform this check and will happily apply the class-hash replacement, producing a different `contract_state_changes` entry (and thus a different resulting state) than what the Blockifier computed.

This causes a mismatch between the sequencer-committed state (post-Blockifier) and the OS-derived state (post re-execution), i.e., an honest-node/proof divergence and potentially a wrong committed state root, satisfying "wrong committed root or block hash, honest-node divergence" from the validation criteria. In a worst case, code that should have reverted (invalid class replacement) is accepted by the OS, letting a contract's class hash be swapped to an unvalidated class hash purely from the OS's perspective, undermining the proof's correctness relative to what the sequencer actually executed.

### Likelihood Explanation
This is trivially reachable by any account: any contract execution that reaches `replace_class_syscall` with a felt the caller controls (e.g., invoking `test_replace_class` style entry points, or any account/contract logic that forwards a user-supplied value into `replace_class_syscall`) triggers the divergent code path in the OS with no special privileges, and no dependency on validator/proposer misbehavior — a single submitted transaction from an ordinary sender is sufficient.

### Recommendation
Add the missing "class hash is declared" validation to the Starknet OS's `execute_replace_class` implementations (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) so that they mirror the Blockifier's behavior exactly (reject the syscall / propagate a failure) when the requested class hash has not been declared, closing the TODO at `syscall_impls.cairo:902` and adding the equivalent check to the deprecated path.

### Proof of Concept
1. Deploy a contract with an entry point invoking `replace_class_syscall(class_hash)` where `class_hash` is taken directly from calldata (e.g., the existing `test_replace_class` feature-contract function, reachable from any external caller).
2. Submit an invoke transaction calling this entry point with an arbitrary, never-declared `class_hash` value.
3. Sequencer-side execution (Blockifier) reverts/rejects the call per `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:795-807` (verified behavior in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:15-29`).
4. Re-execute/prove the same block/transaction through the Starknet OS path (`execute_replace_class` in `syscall_impls.cairo:881-920`), which lacks the declared-class check (see TODO at line 902) and instead unconditionally updates `contract_state_changes` with the attacker-supplied class hash — producing a different state transition than what was actually committed by the sequencer.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
