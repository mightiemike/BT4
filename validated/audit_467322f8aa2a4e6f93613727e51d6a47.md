### Title
`mark_cancellation_request()` can overwrite an already-`Consumed` L1 handler transaction's terminal state - (File: `crates/apollo_l1_events/src/transaction_record.rs`)

### Summary
`TransactionRecord::mark_cancellation_request` guards the cancellation-request state transition only against the transaction being already `Committed`, but not against the transaction being already `Consumed`. This mirrors the reported `cancelAuction()` bug class: a state-mutating action performs a check on only one condition (bid price) while ignoring the other terminal condition (auction already ended). Here the code checks `is_committed()` but omits `is_consumed()`, allowing a "cancellation requested" event to clobber the `Consumed` terminal state of an L1 handler transaction record.

### Finding Description
`mark_cancellation_request` is the sole guard used when an L1 `TransactionCancellationStarted` event is applied to a `TransactionRecord`: [1](#0-0) 

It only special-cases `is_committed()`:
```rust
if self.is_committed() {
    warn!(...)
} else {
    info!(...)
    self.state = TransactionState::CancellationStartedOnL2;
}
```
But the module's own `is_validatable()` treats three states as terminal/blocking: `Committed`, `CancelledOnL2`, and `Consumed`: [2](#0-1) 

`mark_consumed()` similarly marks the record `Consumed` (a terminal state for the message once it has been executed/consumed on L1), and unlike `mark_cancellation_request`, it explicitly documents "Double consumption is a bug" and is protected by a dedicated `consumed_at` check in `TransactionManager::consume_tx`: [3](#0-2) 

However, no such protection exists in the other direction: `TransactionManager::request_cancellation` -> `mark_cancellation_request` will happily flip a `Consumed` record's `state` back to `CancellationStartedOnL2` if a `TransactionCancellationStarted` event for that `tx_hash` is applied after the `Consumed` state was set: [4](#0-3) 

This is analogous to the audited bug: `cancelAuction()` should have added a completion/end-time check in addition to the price check; here `mark_cancellation_request()` should have added an `is_consumed()` check in addition to the `is_committed()` check before transitioning state.

### Impact Explanation
If a `Consumed` record's state is overwritten to `CancellationStartedOnL2`, `update_time_based_state` will (after the configured timelock) further transition it to `CancelledOnL2`: [5](#0-4) 

Both intermediate states are excluded from `is_validatable()`, so this by itself doesn't re-admit the tx for proposal. But it corrupts the terminal `Consumed` marker that `TransactionManager::consume_tx` and `maintain_indices`/`consumed_queue` rely on (`get_consumed_at_timestamp()` is used to enqueue records for later removal from the manager, and `is_committed(tx_hash)` / snapshot logic assume state consistency). Once overwritten, the record's `consumed_at` bookkeeping and its expected lifecycle (`Consumed` -> removed via `consumed_queue`) is broken, and the record may instead be pulled toward removal via the cancellation-finalization path (`finalize_cancellation`), which warns "not in the cancellation started on L2 state" is expected but is silently violated here, or leaves the record stuck in a state inconsistent with its true finality on L1. This is a divergence between the transaction's actual finalized L1 status and the sequencer's internal bookkeeping of L1 handler transaction lifecycle — a state-machine/bookkeeping corruption bug in the L1 events subsystem that participates in transaction admission decisions.

### Likelihood Explanation
Reachable purely through the L1 message sender's control: they control both the `L1HandlerTransaction` (via `sendMessageToL2`) and calls to `startL1ToL2MessageCancellation`, whose resulting events (`TransactionCancellationStarted` and `ConsumedMessageToL2`) are scraped and replayed via `add_events`/`initialize`. If these two events are ever observed by the provider in an order where the `Consumed` marking is later followed by a `CancellationStarted` event for the same hash (e.g., due to scraper batching, reorg-driven re-scraping/backfill of an earlier missed cancellation-request event, or out-of-order combination across separate polling windows since `add_events` is called repeatedly with different event batches over time), the check gap is triggered — there is no code path re-validating consumption before applying the state transition.

### Recommendation
Add an `is_consumed()` guard (mirroring the `is_committed()` guard) in `mark_cancellation_request`, e.g.:
```rust
pub fn mark_cancellation_request(&mut self, timestamp: BlockTimestamp) -> Option<BlockTimestamp> {
    let tx_hash = self.tx.tx_hash();
    if self.is_committed() || self.is_consumed() {
        warn!("... cancellation request ignored, tx already {:?}", self.state);
    } else {
        self.state = TransactionState::CancellationStartedOnL2;
    }
    ...
}
```
This ensures a terminal `Consumed` state can never be overwritten by a later-arriving cancellation-request event, consistent with the treatment already given to `Committed` transactions.

### Proof of Concept
1. Provider receives `L1HandlerTransaction` event for `tx_hash` -> `add_tx` creates record in `Pending` state.
2. Provider receives `ConsumedMessageToL2` for `tx_hash` -> `TransactionManager::consume_tx` -> `TransactionRecord::mark_consumed` sets `state = Consumed`, `consumed_at = Some(t)`. [6](#0-5) 
3. Provider later receives a `TransactionCancellationStarted` event for the same `tx_hash` (e.g., a delayed/backfilled log from an earlier L1 block, or reorg-triggered re-scrape) -> `add_events` unconditionally calls `request_cancellation` when `tx_manager.exists(tx_hash)` is true (no consumed check): [7](#0-6) 
4. `mark_cancellation_request` sees `is_committed() == false` (state is `Consumed`, not `Committed`) and overwrites `state = CancellationStartedOnL2`, discarding the `Consumed` marker set in step 2 while `consumed_at` remains populated — producing an inconsistent record (`state = CancellationStartedOnL2` but `consumed_at = Some(t)`), corrupting the transaction's lifecycle bookkeeping used by `consume_tx`'s double-consumption protection and `maintain_indices`/`consumed_queue` cleanup.

    pub fn mark_cancellation_request(
        &mut self,
        timestamp: BlockTimestamp,
    ) -> Option<BlockTimestamp> {
        let tx_hash = self.tx.tx_hash();
        // Once committed on L2, cancellation requests are only recorded for debugging purposes, but
        // not processed.
        if self.is_committed() {
            warn!(
                "L1 handler transaction {tx_hash} was not marked for cancellation started on L2 \
                 as it is already committed."
            )
        } else {
            info!("Marking L1 handler transaction {tx_hash} as cancellation started on L2.");
            self.state = TransactionState::CancellationStartedOnL2;
        }

        match self.cancellation_requested_at {
            Some(existing) => Some(existing),
            None => {
                self.cancellation_requested_at = Some(timestamp);
                None
            }
        }
    }

    /// The timestamp is the L1 block timestamp where this tx was marked consumed.
    /// If tx was not already consumed (expected result), return None.
    /// If tx was already consumed (double consumption), return the time when it was previously
    /// consumed. Note that double consumption is a bug.
    pub fn mark_consumed(&mut self, timestamp: BlockTimestamp) -> Option<BlockTimestamp> {
        if self.is_committed() {
            debug!("Marking a committed transaction {} as consumed.", self.tx.tx_hash());
        } else {
            // TODO(guyn): check if this situation should be an error.
            // TODO(guyn): check other state combinations that may be worth an error/warning/debug
            // log.
            debug!(
                "Marking a non-committed transaction {} as consumed. Previous state: {:?}",
                self.tx.tx_hash(),
                self.state
            );
        }
        self.state = TransactionState::Consumed;
        // First check if the tx was already consumed. Double consumption is a bug!
        // If None, it wasn't previously consumed: mark the time and return None to signal
        // everything is ok. If Some, it was already consumed: report the time when it was
        // previously consumed, the caller decides what to do.
        match self.consumed_at {
            Some(existing) => Some(existing),
            None => {
                self.consumed_at = Some(timestamp);
                None
            }
        }
    }

    /// Update the state of the record based on the current time and policy.
    /// This updates the state based on time-based state transitions, such as moving from
    /// CancellationStartedOnL2 to CancelledOnL2 after the timelock expires.
    pub fn update_time_based_state(&mut self, unix_now: u64, policy: TransactionRecordPolicy) {
        if let Some(requested_at) = self.cancellation_requested_at {
            if self.committed {
                return; // Committing overrides cancellations.
            }

            let cancellation_timelock = &policy.cancellation_timelock.as_secs();
            let is_cancellation_timelock_passed =
                unix_now >= *requested_at.saturating_add(cancellation_timelock);

            if is_cancellation_timelock_passed {
                self.state = TransactionState::CancelledOnL2;
            }
        }
    }

    pub fn consume_tx(
        &mut self,
        tx_hash: TransactionHash,
        consumed_at: BlockTimestamp,
        unix_now: u64,
    ) -> Result<(), BlockTimestamp> {
        self.clear_old_tx_from_consumed_queue(unix_now);

        let Some(record) = self.records.get(&tx_hash) else {
            debug!(
                "Attempted to consume an unknown transaction: {tx_hash}. This can happen if the \
                 transaction was too old to be scraped (e.g. it was created before we started \
                 scraping)."
            );
            return Ok(());
        };

        // Double consumption is a bug.
        if let Some(previously_consumed_at) = record.get_consumed_at_timestamp() {
            return Err(previously_consumed_at);
        }

        // Mark the transaction as consumed.
        self.with_record(tx_hash, |record| record.mark_consumed(consumed_at));
        Ok(())
    }
