### Title
Cross-origin credential disclosure via unrestricted `domain` parameter in `RemoteActorCredentialSharingImpl::RequestAgentAuthentication` - (File: chrome/browser/password_manager/remote_actor/remote_actor_credential_sharing_impl.cc)

### Summary
The Mojo endpoint `chrome::mojom::RemoteActorCredentialSharing` is bound to a document based only on the *frame's own origin* being on an allowlist, but the privileged operation it exposes (`RequestAgentAuthentication`) accepts a caller-supplied `domain` string that is never checked against the calling frame's own origin. That attacker-influenced `domain` is used to query the password store and, if the user confirms, to package and transmit stored credentials for that arbitrary domain to a remote sharing service — an access-control gap on the parameter that decides *whose* secrets get exfiltrated, structurally analogous to the `DcntEth::setRouter()` bug where the absence of a binding/ownership check let an unauthorized caller redirect a privileged capability (there: minting/burning; here: cross-origin credential release) to an attacker-chosen target.

### Finding Description
`RemoteActorCredentialSharingImpl::BindReceiver` only verifies the frame is the primary main frame and that its committed origin is on the small allowlist (`IsRemoteActorCredentialSharingAllowedForOrigin`), terminating the renderer otherwise. [1](#0-0) 

Once bound, `RequestAgentAuthentication(gaia_id, domain, task_id, callback)` is invoked by the renderer's JS bridge with an arbitrary `domain` string. `ValidateRequestPreconditions` only checks that the request comes from the primary main frame, has user activation, that the process can access the frame's *own* origin, and that argument lengths are bounded — it never checks that `domain` corresponds to the frame's own origin or to any origin the frame is authorized to represent: [2](#0-1) 

`VerifyUserIdentityAndSyncState` similarly only validates that `gaia_id` matches the signed-in account, not that `domain` is related to the caller: [3](#0-2) 

The caller-controlled `domain` is then used directly to build a `PasswordFormDigest` and query the password stores for logins matching *that* domain: [4](#0-3) 

If a matching credential exists and the user proceeds through the selection dialog, the credential for the attacker-chosen `domain` is packaged as `ShareParameters.web_origin = domain` and sent to `RemoteActorCredentialSharingService::SharePassword`, i.e., released off the browser's local storage boundary: [5](#0-4) 

No code path binds `domain` to `render_frame_host().GetLastCommittedOrigin()`, so the "which site's credentials get exfiltrated" decision is entirely attacker (caller)-supplied, just as `setRouter()` let the caller choose which address gets privileged mint/burn rights.

### Impact Explanation
An origin permitted to reach this Mojo interface (or any script capable of driving it, e.g. via a compromised/XSS'd instance of the allowlisted host) can request and, with a single user click through the confirmation dialog, exfiltrate saved passwords for *any* domain stored in the profile/account password store — not just credentials belonging to the calling origin. This breaks the same-origin boundary that password manager storage is expected to enforce and results in cross-origin disclosure of sensitive secrets (arbitrary site passwords) to a remote server, which is a high-impact SOP violation comparable in class to the `DcntEth` unrestricted-router bug (unauthorized redirection of a privileged action to attacker-chosen scope).

### Likelihood Explanation
Reaching `RequestAgentAuthentication` requires: (1) being on the origin allowlist for the feature (currently a specific Google host) and having the feature flag enabled, and (2) user activation plus explicit confirmation via the credential-selection dialog, since the callback only proceeds after `OnDialogResult`/device reauth. This meaningfully limits exploitability to a compromise of the allowlisted origin (e.g., XSS on that host) rather than being exploitable from an arbitrary page. It is not exploitable purely by DOM/script from any web page, but any renderer content that reaches the bound interface (via the allowed origin) can pick an arbitrary `domain` with no cross-checks.

### Recommendation
Add an explicit check in `ValidateRequestPreconditions` (or before `QueryPasswordStores`) that the requested `domain` corresponds to a domain the calling frame/document is authorized to request credentials for (e.g., matches `render_frame_host().GetLastCommittedOrigin()`, or is validated against an explicit per-task allowlist established out-of-band by a trusted broker), analogous to adding access control to `setRouter()` so the privileged action can only target the entity that is supposed to own it.

### Proof of Concept
1. Load the allowlisted origin (e.g., `gemini.google.com`) with the `RemoteActorCredentialSharing` feature enabled.
2. From that document's JS, call `chrome.requestAgentAuthentication(myGaiaId, "victim-bank.com", "task_id", cb)` — a domain unrelated to the calling origin.
3. `RequestAgentAuthentication` passes all preconditions (own-origin process check, user activation, gaia match) since none of them validate `domain` against the frame's origin, per [2](#0-1) .
4. The store is queried for `victim-bank.com` credentials [4](#0-3) , and upon user confirmation, that credential is shared with `web_origin` set to `victim-bank.com` [5](#0-4) , disclosing a credential for a site the calling document does not own.

void RemoteActorCredentialSharingImpl::BindReceiver(
    mojo::PendingAssociatedReceiver<chrome::mojom::RemoteActorCredentialSharing>
        receiver,
    content::RenderFrameHost* rfh) {
  if (!rfh->IsInPrimaryMainFrame()) {
    return;
  }
  if (!IsRemoteActorCredentialSharingAllowedForOrigin(
          rfh->GetLastCommittedOrigin())) {
    rfh->GetProcess()->ShutdownForBadMessage(
        content::RenderProcessHost::CrashReportMode::GENERATE_CRASH_DUMP);
    return;
  }

  auto* impl =
      RemoteActorCredentialSharingImpl::GetOrCreateForCurrentDocument(rfh);
  impl->Bind(std::move(receiver));
}

bool RemoteActorCredentialSharingImpl::ValidateRequestPreconditions(
    const std::string& gaia_id,
    const std::string& domain,
    const std::string& task_id) {
  content::RenderFrameHost& target_frame = render_frame_host();

  if (!target_frame.IsInPrimaryMainFrame()) {
    receiver_.ReportBadMessage(
        "RemoteActorCredentialSharing: Request from subframe");
    return false;
  }

  if (!target_frame.HasTransientUserActivation()) {
    receiver_.ReportBadMessage(
        "RemoteActorCredentialSharing: Request without user gesture");
    return false;
  }

  auto* policy = content::ChildProcessSecurityPolicy::GetInstance();
  if (!policy->CanAccessDataForOrigin(
          target_frame.GetProcess()->GetID().GetUnsafeValue(),
          target_frame.GetLastCommittedOrigin())) {
    receiver_.ReportBadMessage(
        "RemoteActorCredentialSharing: Process cannot access origin");
    return false;
  }

  if (gaia_id.length() >= kMaxArgumentLength ||
      domain.length() >= kMaxArgumentLength ||
      task_id.length() >= kMaxArgumentLength) {
    receiver_.ReportBadMessage(
        "RemoteActorCredentialSharing: Argument length limit exceeded");
    return false;
  }

  return true;
}

bool RemoteActorCredentialSharingImpl::VerifyUserIdentityAndSyncState(
    Profile* profile,
    const std::string& gaia_id) {
  auto* identity_manager = IdentityManagerFactory::GetForProfile(profile);
  if (!identity_manager) {
    return false;
  }
  CoreAccountInfo primary_account =
      identity_manager->GetPrimaryAccountInfo(signin::ConsentLevel::kSignin);
  if (primary_account.gaia.empty() || primary_account.gaia != GaiaId(gaia_id)) {
    return false;
  }

  auto* sync_service = SyncServiceFactory::GetForProfile(profile);
  if (sync_service) {
    if (sync_service->GetAuthError().IsPersistentError()) {
      return false;
    }
    if (sync_service->GetUserSettings()
            ->IsTrustedVaultKeyRequiredForPreferredDataTypes()) {
      return false;
    }
  }

  return true;
}
