### Title
Proof-forgery via ProofFacts-keyed cache lets a forged/mismatched proof bypass cryptographic verification for client-side-proven Invoke transactions - (File: crates/apollo_transaction_converter/src/transaction_converter.rs)

### Summary
The Aztec V1 report shows the class of bug: a permissionless entry point that accepts an attacker-supplied proof and grants privileges based on it, where a proof accepted by the verifier does not actually correspond to the claimed authorization. In this sequencer, the equivalent primitive is the "client-side proving" feature for `Invoke V3` transactions, where a sender submits `proof_facts` (signed, part of the transaction hash) together with a separate `proof` blob (a STARK proof over the Virtual OS execution) that is verified out-of-band by `starknet_proof_verifier::verify_proof`. Verification is skipped whenever the proof-manager cache already contains an entry keyed solely by the hash of `proof_facts` — not by the submitted `proof` bytes — which lets a second transaction reuse someone else's already-verified `proof_facts` while attaching an unrelated, unverified `proof`.

### Finding Description
`Invoke V3` transactions may carry `proof_facts`/`proof` for the client-side-proving feature [1](#0-0) . The transaction hash (which the sender signs) only commits to `proof_facts`, not to the raw `proof` bytes — the `proof` field is explicitly dropped when the transaction is converted internally, and `get_invoke_transaction_v3_hash` only folds in `proof_facts` [2](#0-1) [3](#0-2) .

Cryptographic verification of `(proof_facts, proof)` happens in `run_proof_verification`, which first asks the `ProofManager` whether it already `contains_proof` for the given `proof_facts`, and — if so — **skips calling `verify_proof` entirely**, treating the transaction as already validated [4](#0-3) . The `ProofManager`'s cache and persistent store are both keyed exclusively by `proof_facts.hash()`, with no binding to the specific `proof` bytes that were verified for that hash [5](#0-4) [6](#0-5) . `ProofFacts` are public transaction fields visible in any submitted transaction on the network, so any subsequent sender can read a previously-verified `proof_facts` value and reuse it.

Consequently, an unprivileged attacker can craft a new `Invoke V3` transaction that:
1. Copies `proof_facts` from any previously verified/accepted transaction (public data), and
2. Attaches an arbitrary/garbage `proof` byte blob (or a proof generated for entirely different content).

Because `contains_proof(proof_facts)` returns true, `run_proof_verification` returns `Ok(false)` without ever invoking `starknet_proof_verifier::verify_proof` on the attacker's `proof` — the STARK circuit check that would normally reject a proof that doesn't match the output preimage derived from `proof_facts` [7](#0-6) . The transaction is accepted into the gateway/mempool/consensus flow as if a real cryptographic proof had been checked for it (`spawn_proof_verification` / `spawn_verify_and_store_proof`) [8](#0-7) .

Note that the downstream `validate_proof_facts` in the blockifier and `check_proof_facts` in the Cairo OS only re-check metadata fields inside `proof_facts` (program hash, block hash/number, config hash) [9](#0-8) [10](#0-9) ; they do not re-verify the STARK proof bytes themselves — that check is performed exactly once, off-chain, in `starknet_proof_verifier::verify_proof`, and is what the cache bypass skips.

### Impact Explanation
This breaks the "unauthorized account action" and cryptographic-soundness invariant analogous to Aztec's escapeHatch bug: a transaction can be treated as backed by a valid client-side proof (and thus be granted the "client-side proving" gas-accounting/trust semantics, since the OS `check_proof_facts` accepts it based purely on metadata that the attacker also copies verbatim) without the accompanying proof bytes ever being checked against the circuit. Depending on what downstream trust the Virtual OS output ultimately grants for `proof_facts` (block-hash/message-hash attestation used to justify skipped Sierra gas accounting and privacy-circuit trust), this allows a sender to piggyback on someone else's verified computation while supplying fabricated proof bytes, undermining the guarantee that "a proof accompanying `proof_facts` was checked by the circuit verifier." This is a proof-verification bypass reachable by any unprivileged transaction sender via the gateway or consensus flow.

### Likelihood Explanation
High likelihood of reachability: `proof_facts` are public (visible in any broadcast transaction or accepted block), the check-skip condition (`contains_proof` true) is the normal steady-state path once any proof is verified once, and no additional privilege is required — an attacker only needs to submit a standard `Invoke V3` RPC transaction with client-side proving enabled (`allow_client_side_proving` config) [11](#0-10) .

### Recommendation
Key the proof cache (and the `contains_proof`/`get_proof`/`set_proof` operations) by a hash that binds both `proof_facts` and the actual `proof` bytes (e.g., `hash(proof_facts || proof)`), or otherwise verify that the specific submitted `proof` matches a previously verified `proof` for the same `proof_facts` before skipping `verify_proof`. Alternatively, always run `verify_proof` on the submitted `(proof_facts, proof)` pair once per transaction rather than caching by `proof_facts` alone.

### Proof of Concept
Not independently reproducible from the index alone (concrete behavior depends on how `proof_facts`/Virtual OS output are subsequently consumed for trust decisions, which the index does not fully expose). Conceptual PoC:
1. Observe any accepted `Invoke V3` transaction with non-empty `proof_facts`/`proof` on the network.
2. Submit a new `Invoke V3` transaction using the identical `proof_facts` but a different (invalid) `proof` blob.
3. `run_proof_verification` calls `contains_proof(proof_facts)` → `true` (already cached from step 1) → returns `Ok(false)` without calling `starknet_proof_verifier::verify_proof` [4](#0-3) .
4. The transaction proceeds through pre-validation/OS execution treating `proof_facts` as backed by a verified proof, even though the attacker's actual `proof` bytes were never checked.

Due to index size limits, some file contents (e.g., full `apollo_gateway` proof-handling pipeline and downstream consumers of `proof_facts`/Virtual OS output for trust decisions) may not be fully available; a Devin session with full repository access is recommended to confirm the exact downstream privilege granted by verified `proof_facts` and to validate the exploit end-to-end.

    /// Runs proof verification: checks if the proof already exists, and if not, verifies it.
    /// Returns `true` if verification was performed, `false` if skipped (proof already stored).
    /// This is the shared verification logic used by both gateway and consensus flows.
    async fn run_proof_verification(
        proof_facts: ProofFacts,
        proof: Proof,
        proof_manager_client: SharedProofManagerClient,
    ) -> Result<bool, TransactionConverterError> {
        let contains_proof = proof_manager_client.contains_proof(proof_facts.clone()).await?;

        if contains_proof {
            return Ok(false);
        }

        let proof_facts_hash = proof_facts.hash();
        let verify_start = Instant::now();
        tokio::task::spawn_blocking(move || {
            starknet_proof_verifier::verify_proof(proof_facts, proof)
        })
        .await
        .expect("proof verification task panicked")?;
        let verify_duration = verify_start.elapsed();
        PROOF_VERIFICATION_LATENCY.record(verify_duration.as_secs_f64());
        info!(
            "Proof verification took: {verify_duration:?} for proof facts hash: \
             {proof_facts_hash:?}"
        );

        Ok(true)
    }

            Self::run_proof_verification(task_proof_facts, task_proof, pmc).await?;
            Ok(())

    /// Used by the consensus flow, where tasks run concurrently with batcher execution and
    /// are awaited at fin.
    fn spawn_verify_and_store_proof(
        &self,
        proof_facts: ProofFacts,
        proof: Proof,
    ) -> VerifyAndStoreProofTask {
        let pmc = self.proof_manager_client.clone();
        let proof_facts_hash = proof_facts.hash();
        tokio::spawn(async move {

                return Ok(());

            info!(
                "Proof manager store took: {duration:?} for proof facts hash: {proof_facts_hash:?}"
            );
            Ok(())
        })
    }

    pub async fn set_proof(
        &self,
        proof_facts: ProofFacts,
        proof: Proof,
    ) -> Result<(), FsProofStorageError> {
        if self.contains_proof(proof_facts.clone()).await? {
            return Ok(());
        }
        let facts_hash = proof_facts.hash();
        self.proof_storage.set_proof(facts_hash, proof.clone()).await?;
        self.cache.insert(facts_hash, proof);
        Ok(())
    }

    pub async fn get_proof(
        &self,
        proof_facts: ProofFacts,
    ) -> Result<Option<Proof>, FsProofStorageError> {
        let facts_hash = proof_facts.hash();
        // Check cache first.
        if let Some(proof) = self.cache.get(&facts_hash) {
            return Ok(Some(proof));
        }
        // Fallback to filesystem.
        let proof = self.proof_storage.get_proof(facts_hash).await?;
        if let Some(proof) = &proof {
            self.cache.insert(facts_hash, proof.clone());
        }
        Ok(proof)
    }

    pub async fn contains_proof(
        &self,
        proof_facts: ProofFacts,
    ) -> Result<bool, FsProofStorageError> {
        let facts_hash = proof_facts.hash();
        // Check cache first.
        if self.cache.contains(&facts_hash) {
            return Ok(true);
        }
        // Fallback to filesystem.
        self.proof_storage.contains_proof(facts_hash).await
    }

/// Verifies a submitted proof against the proof facts using the circuit verifier.
///
/// The first element of `proof_facts` must be V1, verified via `privacy-circuit-verify-v1`.
pub fn verify_proof(proof_facts: ProofFacts, proof: Proof) -> Result<(), VerifyProofError> {
    // Reject empty proof payloads before running the verifier.
    if proof.is_empty() {
        return Err(VerifyProofError::EmptyProof);
    }

    let proof_version_felt = proof_facts.0.first().copied().unwrap_or_default();
    let proof_version = ProofVersion::try_from(proof_version_felt)
        .map_err(|()| VerifyProofError::InvalidProofVersion { actual: proof_version_felt })?;

    let output_preimage = reconstruct_output_preimage(&proof_facts)?;
    // TODO(Avi): Avoid cloning the proof.
    let proof_bytes = proof.0.to_vec();

    match proof_version {
        // V0 proofs are no longer verifiable: the v0 circuit was removed. V0 proof facts are only
        // tolerated by the blockifier (gated per protocol version) for replaying historical blocks.
        ProofVersion::V0 => {
            return Err(VerifyProofError::InvalidProofVersion { actual: proof_version_felt });
        }
        ProofVersion::V1 => {
            let proof_output = privacy_circuit_verify_v1::PrivacyProofOutput {
                proof: proof_bytes,
                output_preimage,
            };
            privacy_circuit_verify_v1::verify_recursive_circuit(&proof_output)
                .map_err(|e| VerifyProofError::Verification(e.to_string()))?;
        }
    }

    Ok(())
}

    fn validate_proof_facts(
        &self,
        block_context: &BlockContext,
        state: &mut dyn State,
    ) -> TransactionPreValidationResult<()> {
        // Only Invoke V3 transactions can carry proof facts.
        let Transaction::Invoke(invoke_tx) = &self.tx else {
            return Ok(());
        };
        if invoke_tx.version() < TransactionVersion::THREE {
            return Ok(());
        }

        // Parse proof facts.
        let proof_facts = invoke_tx.proof_facts();
        let snos_proof_facts = match ProofFactsVariant::try_from(&proof_facts)
            .map_err(|e| TransactionPreValidationError::InvalidProofFacts(e.to_string()))?
        {
            ProofFactsVariant::Empty => return Ok(()),
            ProofFactsVariant::Snos(snos_proof_facts) => snos_proof_facts,
        };
        let os_constants = &block_context.versioned_constants.os_constants;

        if !os_constants.allowed_proof_versions.contains(&snos_proof_facts.proof_version.as_felt())
        {
            return Err(TransactionPreValidationError::InvalidProofFacts(format!(
                "Proof version {} is not allowed under this protocol version.",
                snos_proof_facts.proof_version
            )));
        }

        // Validate the program hash.
        let allowed = &os_constants.allowed_virtual_os_program_hashes;
        if !allowed.contains(&snos_proof_facts.program_hash) {
            return Err(TransactionPreValidationError::InvalidProofFacts(format!(
                "Virtual OS program hash {} is not allowed",
                snos_proof_facts.program_hash
            )));
        }

        // Validate the block hash and block number.
        let proof_block_hash = snos_proof_facts.block_hash.0;
        let proof_block_number = snos_proof_facts.block_number.0;
        Self::validate_proof_block_number(
            proof_block_number,
            block_context.block_info.block_number,
        )?;
        Self::validate_proof_block_hash(proof_block_hash, proof_block_number, os_constants, state)?;

        // Validate the config hash.
        let virtual_os_config_hash = block_context.virtual_os_config_hash();
        let proof_config_hash = snos_proof_facts.config_hash;
        if virtual_os_config_hash != proof_config_hash {
            return Err(TransactionPreValidationError::InvalidProofFacts(format!(
                "Virtual OS config hash mismatch. Computed virtual OS config hash: \
                 {virtual_os_config_hash}, expected virtual OS config hash: {proof_config_hash}."
            )));
        }

        Ok(())
    }

// Validates that the proof facts of an invoke transaction are of a valid virtual OS run.
func check_proof_facts{range_check_ptr, contract_state_changes: DictAccess*}(
    proof_facts_size: felt,
    proof_facts: felt*,
    current_block_number: felt,
    virtual_os_config_hash: felt,
) {
    if (proof_facts_size == 0) {
        return ();
    }

    assert_le(ProofHeader.SIZE + VirtualOsOutputHeader.SIZE, proof_facts_size);

    // Validate the proof header.
    static_assert ProofHeader.SIZE == 3;
    let proof_header = cast(proof_facts, ProofHeader*);
    assert proof_header.proof_variant = VIRTUAL_SNOS;
    assert is_program_hash_allowed(proof_header.program_hash) = TRUE;
    // Only proof version V1 is accepted.
    with_attr error_message("Unsupported proof version") {
        assert proof_header.proof_version = PROOF_VERSION_V1;
    }

    // Validate the virtual OS output header.
    let os_output_header = cast(&proof_facts[ProofHeader.SIZE], VirtualOsOutputHeader*);

    with_attr error_message("Virtual OS output version is not supported") {
        assert os_output_header.output_version = VIRTUAL_OS_OUTPUT_VERSION;
    }

    // Validate that the proof facts block number is not too recent.
    // (This is a sanity check - the following non-zero check ensures that the block hash is
    // not trivial).
    assert_nn_le(
        os_output_header.base_block_number, current_block_number - STORED_BLOCK_HASH_BUFFER
    );
    // Not all block hashes are stored in the contract; Make sure the requested one is not trivial.
    assert_not_zero(os_output_header.base_block_hash);

    // validate that the proof facts block hash is the true hash of the proof facts block number.
    read_block_hash_from_storage(
        block_number=os_output_header.base_block_number,
        expected_block_hash=os_output_header.base_block_hash,
    );

    // validate that the proof facts config hash is the true hash of the OS config.
    assert os_output_header.starknet_os_config_hash = virtual_os_config_hash;

    return ();
}
