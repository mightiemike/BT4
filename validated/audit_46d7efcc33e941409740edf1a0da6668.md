### Title
Session tokens have no absolute expiration and can be kept alive indefinitely via sliding idle-timeout refresh - (File: core/sessions/localauth/orm.go)

### Summary
`AuthorizedUserWithSession` validates a session solely against `last_used + sessionDuration >= now()` and then unconditionally refreshes `last_used` to `now()` on every successful use, with no check against the session's `created_at` (absolute age). Since the paired `sessionReaper` also only reaps by `last_used < threshold`, a session with a continuously refreshed `last_used` is never invalidated for as long as it keeps being used, regardless of how old it actually is.

### Finding Description
`findValidSession` determines validity purely from a sliding window: [1](#0-0) 
and `updateSessionLastUsed` is called at the end of every successful `AuthorizedUserWithSession` call, resetting the clock: [2](#0-1) 

The background reaper that would otherwise purge stale rows uses the same sliding metric (`last_used`), not `created_at`, so it cannot bound a session that is continuously kept "fresh": [3](#0-2) 

Given the stated precondition — the attacker has already captured a valid `sessionID` once (e.g., via a logging misconfiguration or XSS) — the attacker (or a script replaying the value) can call any authenticated endpoint (which routes through `AuthorizedUserWithSession` via `AuthenticateGQL`/session middleware) at an interval shorter than `WebServer().SessionTimeout()`. Each call both authenticates and refreshes `last_used`, so `findValidSession`'s `last_used + sessionDuration >= now()` check remains true forever, and the reaper's `last_used < threshold` never fires. There is no separate absolute-lifetime check anywhere in this authentication path — `created_at` is stored on the `sessions` row but is never compared to `now()` for expiration purposes in the local-auth authenticator.

The same pattern (sliding-window-only expiry with no absolute cap enforced against `created_at`) exists in the OIDC and LDAP authenticators as well, which rely on `created_at + timeout >= now()` at query time but simply overwrite/replace `created_at` implicitly through re-login flows rather than a true sliding refresh in those cases — for local auth specifically, the `last_used` refresh on every call is the mechanism that removes the natural upper bound.

This confirms the sliding-expiration design has no absolute maximum lifetime safeguard as an additional layer of defense.

### Impact Explanation
If a session ID leaks once (via a logging misconfiguration, a proxy/cache, or an XSS bug elsewhere), and the legitimate user's browser tab continues to generate periodic requests using that same session (or the attacker independently pings any authenticated endpoint faster than `SessionTimeout`), the leaked credential remains valid indefinitely. This grants unbounded, indefinite unauthorized access to any endpoint reachable with that user's role (job management, workflow, keys, bridges, vault-management UI, etc.) — the blast radius of a single leaked token is not bounded by any absolute session lifetime policy, only by the operator's ability to detect and manually revoke the session via `DeleteUserSession`.

### Likelihood Explanation
Feasibility is directly dependent on the stated precondition holding (a session ID leak occurring at all, which is outside this component's control), but once that precondition is met, exploitation is trivial and fully repeatable: the attacker only needs to issue GET/POST calls (or rely on the victim's own normal usage) more frequently than the configured `SessionTimeout` to keep `last_used` refreshed forever. No additional secrets, races, or privilege are required.

### Recommendation
Enforce an absolute maximum session lifetime independent of the sliding idle timeout: track `created_at` at session-issue time and reject/purge sessions where `now() - created_at` exceeds a configured absolute max age (e.g., `SessionAbsoluteMaxAge`), in addition to the existing idle-timeout check in `findValidSession`. Apply the same fix to the reaper (`localauth/reaper.go`, and equivalently `oidcauth/reaper.go`) so it purges by absolute age as well as idle staleness, and force re-authentication (e.g., MFA/password) once the absolute cap is hit.

### Proof of Concept
Unit test plan (extending `core/sessions/localauth/orm_test.go`):
1. Create a user and insert a session row with `created_at` set far in the past (e.g., `now() - 30 days`) and `last_used = now() - 1 minute`.
2. In a loop simulating elapsed time, repeatedly call `orm.AuthorizedUserWithSession(ctx, sessionID)` at intervals shorter than `sessionDuration`, and after each call assert success and that `last_used` has been bumped to `now()` (as already verified by `TestORM_AuthorizedUserWithSession`).
3. Assert that after simulating a duration far exceeding any reasonable absolute session lifetime (e.g., months of simulated "refresh" calls), `AuthorizedUserWithSession` still returns `nil` error and a valid user — demonstrating there is no absolute-lifetime cutoff.
4. Additionally, run `sessionReaper.Work`/`WakeUp` during the loop and assert the session row is never deleted despite its old `created_at`, confirming the reaper only checks `last_used`, not absolute age.

// findValidSession finds an unexpired session by its ID and returns the associated email.
func (o *orm) findValidSession(ctx context.Context, sessionID string) (email string, err error) {
	if err := o.ds.GetContext(ctx, &email, "SELECT email FROM sessions WHERE id = $1 AND last_used + $2 >= now() FOR UPDATE", sessionID, o.sessionDuration); err != nil {
		o.lggr.Infof("query result: %v", email)
		return email, pkgerrors.Wrap(err, "no matching user for provided session token")
	}
	return email, nil
}

// updateSessionLastUsed updates a session by its ID and sets the LastUsed field to now().
func (o *orm) updateSessionLastUsed(ctx context.Context, sessionID string) error {
	_, err := o.ds.ExecContext(ctx, "UPDATE sessions SET last_used = now() WHERE id = $1", sessionID)
	return err
}

// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired, and update session's LastUsed field.
// AuthorizedUserWithSession will return the API user associated with the Session ID if it
// exists and hasn't expired, and update session's LastUsed field.
func (o *orm) AuthorizedUserWithSession(ctx context.Context, sessionID string) (user sessions.User, err error) {
	if len(sessionID) == 0 {
		return sessions.User{}, sessions.ErrEmptySessionID
	}

	email, err := o.findValidSession(ctx, sessionID)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	user, err = o.findUser(ctx, email)
	if err != nil {
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	if err := o.updateSessionLastUsed(ctx, sessionID); err != nil {
		return sessions.User{}, err
	}

	return user, nil
}

func (sr *sessionReaper) Work(ctx context.Context) {
	recordCreationStaleThreshold := sr.config.SessionReaperExpiration().Before(
		sr.config.SessionTimeout().Before(time.Now()))
	err := sr.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		sr.lggr.Error("unable to reap stale sessions: ", err)
	}
}

// DeleteStaleSessions deletes all sessions before the passed time.
func (sr *sessionReaper) deleteStaleSessions(ctx context.Context, before time.Time) error {
	_, err := sr.ds.ExecContext(ctx, "DELETE FROM sessions WHERE last_used < $1", before)
	return err
}
