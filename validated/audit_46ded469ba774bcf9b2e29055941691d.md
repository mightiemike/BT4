Analysis of the analog bug class (open redirect via unvalidated fallback URL fragment) in `shopify-app-js`:

The `/auth/exit-iframe` endpoint (`respondToExitIframeRequest` in both `shopify-app-remix` and `shopify-app-react-router`) reads a fully attacker-controlled `exitIframe` query parameter directly from an unauthenticated GET request and passes it to `renderAppBridge` as the redirect destination: [1](#0-0) 

This destination is only checked by `sanitizeRedirectUrl`/`isSafe`, which rejects file URIs, whitespace, invalid relative paths, and non-http(s) protocols — but it does **not** verify that the resulting URL's host matches `config.appUrl` or any Shopify domain: [2](#0-1) 

Because `new URL(redirectUrl, domain)` returns the absolute URL as-is whenever `redirectUrl` is already absolute (the `domain`/`base` argument is only used to resolve relative paths), any `https://` or `http://` absolute URL passes validation. The rendered response then does `window.open(<attacker-controlled URL>, "_top")`: [3](#0-2) 

The existing test suite confirms this behavior: absolute URLs matching `config.appUrl` are accepted and rendered verbatim, only `file://`-style and whitespace/relative-traversal URLs are rejected — no host allowlist check exists: [4](#0-3) [5](#0-4) 

### Title
Open Redirect via `exitIframe` Query Parameter in Exit-Iframe Handler - (File: `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts`)

### Summary
The `/auth/exit-iframe` route (and identically in `shopify-app-react-router`) accepts an `exitIframe` query parameter from any unauthenticated GET request and uses it as the top-level redirect target via `window.open(url, "_top")`, after passing it through `sanitizeRedirectUrl`. That sanitizer only validates protocol (`http:`/`https:`), rejects file URIs, whitespace, and malformed relative paths — it never checks that the resulting URL's origin matches the app's own domain (`config.appUrl`) or a Shopify domain.

### Finding Description
`respondToExitIframeRequest` reads `url.searchParams.get('exitIframe')` straight from the request URL of an unauthenticated request and forwards it to `renderAppBridge` as the redirect destination [1](#0-0) . `renderAppBridge` calls `sanitizeRedirectUrl(config.appUrl, redirectTo.url)` and, if it doesn't throw, embeds the returned URL directly into a `window.open(...)` script tag [3](#0-2) . `isSafe()` in `validate-redirect-url.ts` uses `new URL(redirectUrl, domain)` merely to make relative URLs resolvable; when `redirectUrl` is already absolute (e.g. `https://evil.example.com`), the `domain` argument is ignored entirely by the `URL` constructor, so the function only confirms the scheme is `http`/`https` and there's no embedded whitespace/file traversal — it never compares `url.origin` to `domain` [6](#0-5) . This is the same root cause as the reported Qoinpay bug: a fallback/redirect parameter taken from an untrusted, unauthenticated input source is validated only for URL well-formedness, not for its destination host.

### Impact Explanation
Any anonymous party can craft a link like `https://victim-app.example.com/auth/exit-iframe?exitIframe=https://phishing-site.example&shop=whatever` and send it to a merchant. When the merchant opens it (often from within the Shopify Admin iframe context this endpoint is specifically designed to "exit"), the browser's top-level frame is redirected to the attacker's site via `window.open(url, "_top")`. This enables phishing pages that closely impersonate the Shopify OAuth/login flow, potential session/token theft, and general reputational damage to the app, matching the "open redirect leading to phishing" impact class described in the source report.

### Likelihood Explanation
High. The endpoint requires no authentication, no valid session, and no prior state — a single crafted URL sent to any target is sufficient. It matches an intentionally public, unauthenticated route (`config.auth.exitIframePath`) that exists specifically to be linked to from Shopify Admin, making it a natural phishing vector at scale.

### Recommendation
In `isSafe()` (`validate-redirect-url.ts`), after resolving the URL, enforce that `url.origin` equals `new URL(domain).origin` (or an explicit allowlist of trusted hosts, e.g. `myshopify.com`/`shopify.com`/`config.appUrl`) before accepting it, mirroring how `sanitizeHost`/`sanitizeShop` already validate the `host`/`shop` params against a domain allowlist [7](#0-6) . Reject absolute URLs whose origin doesn't match before returning them for use in `window.open`/redirects.

### Proof of Concept
```
GET https://<victim-app-domain>/auth/exit-iframe?exitIframe=https%3A%2F%2Fattacker.example%2Fphish&shop=test-shop.myshopify.com
```
Response body (per existing test pattern) contains:
```html
<script data-api-key="..." src="https://cdn.shopify.com/shopifycloud/app-bridge.js"></script>
<script>window.open("https://attacker.example/phish", "_top")</script>
```
This matches the exact rendering logic exercised by the existing (non-adversarial) test case that passes `config.appUrl` as `exitIframe` and asserts it is echoed verbatim into the `window.open` call [4](#0-3) ; substituting an attacker-controlled absolute URL for `config.appUrl` produces the same accepted output since no origin check exists.

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}

export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }

    return sanitizedHost;
  };
