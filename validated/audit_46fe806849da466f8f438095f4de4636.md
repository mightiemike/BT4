## Finding

### Title
Inconsistent rounding of the 70% signer supermajority threshold between `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` and `NakamotoBlockHeader::compute_voting_weight_threshold` - (File: libsigner/src/v0/signer_state.rs, stackslib/src/chainstate/nakamoto/mod.rs)

### Summary
The Bond-protocol report (M-5) showed that computing the *same* conceptual quantity in two places with different rounding directions breaks an invariant the protocol depends on. The Stacks signer protocol has an analogous pattern: the "70% supermajority" (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`) is computed twice for the same purpose but with different rounding, so the weight needed to "reach agreement" in the signer set's global-state machine can be strictly lower than the weight actually required to get a block signed/accepted.

### Finding Description
- `NakamotoBlockHeader::compute_voting_weight_threshold` explicitly rounds **up** (ceiling): it adds 1 whenever `total_weight * 7` is not a multiple of 10. [1](#0-0) 
This function is used consensus-critically both to verify a block's on-chain signature weight and by signers to decide whether pre-commits/rejections cross the threshold. [2](#0-1) [3](#0-2) 

- `GlobalStateEvaluator::reached_agreement`/`reached_disagreement`, used to determine the signer set's agreed-upon global state (current miner, burn view, protocol version, tx replay set), instead performs a plain integer division, which **floors** (rounds down) the same 70%/30% thresholds: [4](#0-3) 

- The codebase itself treats these two thresholds as conceptually the same "70% supermajority," e.g. a test comment states the GlobalStateEvaluator's threshold "is exactly the threshold" used elsewhere for block approval: [5](#0-4) 

- Concretely, for `total_weight = 511`: `compute_voting_weight_threshold` returns `358` (ceiling), confirmed by an explicit regression test: [6](#0-5) 
but `reached_agreement` would return `true` for a vote weight of `357` (`floor(511*7/10) = 357`, and the check is `>=`). This one-weight-unit gap is not incidental — it is exactly the ceiling-vs-floor difference the Bond report's rounding bug describes, just applied to a threshold rather than a price.

- `GlobalStateEvaluator::determine_global_state` (gated by the floored `reached_agreement`) feeds directly into `GlobalStateView::check_proposal`, which decides whether a proposed block's consensus hash/miner pubkey matches what the signer set as a whole believes is the "current miner": [7](#0-6) [8](#0-7) 

### Impact Explanation
Because the "global state" (miner/tenure view) can flip at a weight one unit below the true `compute_voting_weight_threshold` ceiling, a signer subset holding exactly `floor(total_weight*7/10)` weight can force the signer network's *shared* view of "who the current miner is" to change, while that same subset is *insufficient* to ever actually collect the signatures required (`compute_voting_weight_threshold`, ceiling) to sign a block under the new view. This produces the class of bug allowed by the rules — a minority-triggerable signer-weight-vs-threshold divergence causing temporary tip disagreement: some signers reject the old miner's (still overtly valid) blocks based on the floor-rounded "global state" flip, while the new miner cannot gather enough signatures under the stricter ceiling threshold, stalling block production/approval until enough real signer participation appears. This is bounded to a temporary tip disagreement / stall, not a chain split, matching the High-severity bucket ("a minority-triggerable ... divergence ... temporary tip disagreement").

### Likelihood Explanation
This is deterministic and reproducible any time `total_weight * 7` is not evenly divisible by 10 (i.e., most possible signer-weight totals) and vote weight lands exactly at `floor(total_weight*7/10)`. No adversarial majority is required — it only needs signers whose combined weight equals that floor value, which is a normal, expected distribution outcome rather than a contrived edge case.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` use the same ceiling-rounding logic as `NakamotoBlockHeader::compute_voting_weight_threshold` (or have both call into a single shared threshold function), so the "70%/30%" semantics are identical everywhere they are used to gate consensus-relevant decisions.

### Proof of Concept
1. Configure a signer set with `total_weight = 511` (achievable via normal PoX stacking distribution).
2. `NakamotoBlockHeader::compute_voting_weight_threshold(511)` returns `358` — this is the number of signature-weight units required to actually approve/sign a block (per the existing unit test at `stackslib/src/chainstate/nakamoto/tests/mod.rs:4118-4122`).
3. Have signers representing exactly `357` weight units switch to reporting a new `current_miner` in their `StateMachineUpdate`.
4. Call `GlobalStateEvaluator::reached_agreement(357)` with `total_weight = 511`: `357 >= 511*7/10 (=357, floored)` evaluates `true`, so `determine_global_state()` flips the agreed global state to the new miner.
5. Any block proposal from the old miner is now rejected via `GlobalStateView::check_proposal` (`ConsensusHashMismatch`/`PubkeyHashMismatch`) system-wide, even though the `357`-weight minority backing the new miner is one unit short of the `358` threshold actually required by `compute_voting_weight_threshold` to ever get a block from the new miner signed — stalling block approval.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
