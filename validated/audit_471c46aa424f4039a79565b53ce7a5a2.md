## Title
Signer can permanently squat any aggregate public key and block it from ever being approved for its intended reward cycle - (File: stackslib/src/chainstate/stacks/boot/signers-voting.clar)

### Summary
The `vote-for-aggregate-public-key` function in the `.signers-voting` boot contract records every voted-on key into a global, cycle-scoped `used-aggregate-public-keys` map *unconditionally*, before any weight-threshold check is applied. Any single registered signer — regardless of their signing weight, and without needing majority support — can therefore cast one low-weight vote for a specific (buff 33) key tagged with an arbitrary `reward-cycle` of their choosing. Once recorded, `is-novel-aggregate-public-key` permanently rejects any future vote for that exact key unless it targets that same (attacker-chosen) reward cycle. This lets a minority, unprivileged signer irreversibly block the honest DKG-derived aggregate key from ever being approved for its true target reward cycle — directly analogous to `cancelOrdersUpTo(MAX_UINT256-1)`: a single, cheap, irreversible call with insufficient preconditions that permanently forecloses a legitimate future state.

### Finding Description
`vote-for-aggregate-public-key` performs these key checks/writes in order: [1](#0-0) 

Critically:
- `is-novel-aggregate-public-key` only guarantees a key can be reused *within the same reward cycle* it was previously recorded under: `(is-eq (default-to reward-cycle (map-get? used-aggregate-public-keys key)) reward-cycle)`. [2](#0-1) 
- The write `(map-set used-aggregate-public-keys key reward-cycle)` happens unconditionally for *every* successful vote, regardless of whether the vote reached the `threshold-consensus` (70%) required to actually finalize a key for that cycle: [3](#0-2) 
- The only requirement to cast a vote is holding *any* nonzero signer-index/weight for the *reward-cycle argument the caller supplies* (verified via `get-signer-weight`), and the round for that same reward-cycle can only advance by 1 per call — but there is no restriction tying the supplied reward-cycle to "the next cycle" or the "current voting window": `is-in-voting-window` is defined but is never called anywhere in `vote-for-aggregate-public-key`. [4](#0-3) [5](#0-4) 

Because Stacks aggregate-key votes are ordinary contract-call transactions broadcast to the public mempool, the actual DKG-computed key value proposed by the honest signer majority for cycle `N` becomes publicly visible the moment the first honest vote transaction is submitted. An attacker who is a registered signer for *some other cycle `M` (M != N)* they control (even with the smallest possible weight) can front-run by submitting their own `vote-for-aggregate-public-key` call with `key = <the honest key>` and `reward-cycle = M`. Because `used-aggregate-public-keys` is written unconditionally, the map now stores `key -> M`. Every subsequent honest vote for `key` under `reward-cycle = N` then fails `is-novel-aggregate-public-key` (`ERR_DUPLICATE_AGGREGATE_PUBLIC_KEY`), even though the honest signers hold the required threshold weight for cycle `N`. This permanently forecloses on-chain approval of that specific key for cycle `N`; it cannot be reversed, since the map has no clearing mechanism, and off-chain the signer set has already performed FROST/DKG under that specific key.

### Impact Explanation
This breaks the intended equality that "the aggregate public key approved on-chain for reward cycle `N`" equals "the key the honest, threshold-weighted signer set for cycle `N` actually agreed on via DKG." A single minority, unprivileged signer can force this equality to permanently fail for a target cycle, denying finalization of `aggregate-public-keys` for that cycle. This is a minority-triggerable divergence in the signer/DKG finalization process (a form of the "signer weight below threshold / wrong set" equality break called out in scope), which can cause block/tenure signing disruption and node/signer disagreement about which key is authoritative for the cycle — matching the "High: minority-triggerable... divergence... temporary tip disagreement" impact bucket.

### Likelihood Explanation
The precondition is modest: the attacker only needs to be a registered signer for *any* reward cycle (even one far in the future or one where they hold the minimum weight), and needs to observe the honest vote transaction for the target key in the mempool before it confirms — a standard front-running scenario on a public blockchain. No majority collusion, no privileged role, and no protocol-level authorization beyond being any signer is required.

### Recommendation
- Only write to `used-aggregate-public-keys` once a key is actually approved (i.e., inside the `(>= new-total threshold-weight)` branch when `map-insert aggregate-public-keys reward-cycle key` succeeds), not on every individual vote.
- Additionally consider binding votes to `is-in-voting-window` so that a signer cannot pre-register votes for reward cycles outside the legitimate voting window/DKG schedule for that signer.

### Proof of Concept
1. Signer S1 belongs to reward-cycle `N+1`'s signer set (assigned by the node); honest signers begin threshold voting for the DKG-derived `aggregate_key = K` under `reward-cycle = N+1`.
2. Attacker A is a registered signer in some other reward cycle `M` (any cycle where A has a valid `signer-index`, even weight 1). A observes the first honest vote tx containing `K` in the mempool.
3. A front-runs with `(contract-call? .signers-voting vote-for-aggregate-public-key A-index K round=0 M)`. This passes all checks (`K` not yet used for `M`, well-formed, no prior vote by A at round 0/cycle M) and unconditionally executes `(map-set used-aggregate-public-keys K M)` per [6](#0-5) .
4. When honest signers' votes for `K` under `reward-cycle = N+1` are processed, `is-novel-aggregate-public-key K N+1` evaluates `(map-get? used-aggregate-public-keys K)` = `M`, which is `!= N+1`, so the assertion at [7](#0-6)  fails with `ERR_DUPLICATE_AGGREGATE_PUBLIC_KEY` for every honest signer, permanently blocking approval of `K` for cycle `N+1`.

(define-public (vote-for-aggregate-public-key (signer-index uint) (key (buff 33)) (round uint) (reward-cycle uint))
    (let ((tally-key {reward-cycle: reward-cycle, round: round, aggregate-public-key: key})
            ;; vote by signer weight
            (signer-weight (try! (get-signer-weight signer-index reward-cycle)))
            (new-total (+ signer-weight (default-to u0 (map-get? tally tally-key))))
            (cached-weight (try! (get-and-cache-total-weight reward-cycle)))
            (threshold-weight (get-threshold-weight reward-cycle))
            (current-round (default-to {
                votes-count: u0, 
                votes-weight: u0} (map-get? round-data {reward-cycle: reward-cycle, round: round})))
                )
        ;; Check that the key has not yet been set for this reward cycle
        (asserts! (is-none (map-get? aggregate-public-keys reward-cycle)) (err ERR_OUT_OF_VOTING_WINDOW))
        ;; Check that the aggregate public key is the correct length
        (asserts! (is-eq (len key) u33) (err ERR_ILL_FORMED_AGGREGATE_PUBLIC_KEY))
        ;; Check that aggregate public key has not been used in a previous reward cycle
        (asserts! (is-novel-aggregate-public-key key reward-cycle) (err ERR_DUPLICATE_AGGREGATE_PUBLIC_KEY))
        ;; Check that signer hasn't voted in this reward-cycle & round
        (asserts! (map-insert votes {reward-cycle: reward-cycle, round: round, signer: tx-sender} {aggregate-public-key: key, signer-weight: signer-weight}) (err ERR_DUPLICATE_VOTE))
        ;; Check that the round is incremented by at most 1
        (try! (update-last-round reward-cycle round))
        ;; Update the tally for this aggregate public key candidate
        (map-set tally tally-key new-total)
        ;; Update the current round data
        (map-set round-data {reward-cycle: reward-cycle, round: round} {
            votes-count: (+ (get votes-count current-round) u1),
            votes-weight: (+ (get votes-weight current-round) signer-weight)})
        ;; Update used aggregate public keys
        (map-set used-aggregate-public-keys key reward-cycle)
        (print {
            event: "voted",
            signer: tx-sender,
            reward-cycle: reward-cycle,
            round: round,
            key: key,
            new-total: new-total,
        })
        ;; If the new total weight is greater than or equal to the threshold consensus
        (if (>= new-total threshold-weight)
            ;; Save this approved aggregate public key for this reward cycle.
            ;; If there is not already a key for this cycle, the insert will
            ;; return true and an event will be created.
            (if (map-insert aggregate-public-keys reward-cycle key)
                (begin
                    ;; Create an event for the approved aggregate public key
                    (print {
                        event: "approved-aggregate-public-key",
                        reward-cycle: reward-cycle,
                        round: round,
                        key: key,
                    })
                    true)
                false
            )
            false
        )
