### Title
Starknet OS `execute_replace_class` allows replacing a contract's class hash with an undeclared class hash, while the Blockifier enforces declaration — causing OS/Blockifier execution divergence — (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Blockifier's `replace_class` syscall implementations explicitly verify that the target class hash is a declared class before mutating a contract's class hash. The Starknet OS Cairo re-implementation of the same syscall (`execute_replace_class`) performs the state mutation unconditionally, with an explicit `TODO` acknowledging the missing declared-class check. This mirrors the reported bug class: an authorization/state check enforced on one code path (`BranchPort.requiresBridgeAgent` / Blockifier's declared-class check) is missing on a parallel path (`BranchBridgeAgent.callOut` / Starknet OS `execute_replace_class`) that an ordinary, unprivileged transaction sender can reach.

### Finding Description
Any contract can invoke the `replace_class_syscall` from an `__execute__` (or other) entry point during normal transaction execution — this is a standard, unprivileged Cairo 1 syscall, reachable by any invoke transaction.

In the Blockifier (used by the sequencer to build and execute blocks), `replace_class` is checked against declared classes before the state is updated: [1](#0-0) 

The equivalent Cairo1/VM `replace_class` execution flow funnels through common state operations (`base.replace_class`) shared by both the VM and Native syscall handlers: [2](#0-1) 

By contrast, the Starknet OS's Cairo implementation of the same syscall — used for re-execution/proving of the block (Starknet OS flow) — updates the contract's class hash in `contract_state_changes` without verifying the class was ever declared, and explicitly notes the gap with a TODO comment: [3](#0-2) 

The older/deprecated Cairo0 OS syscall path has the identical gap: [4](#0-3) 

Meanwhile, the Blockifier's own unit tests confirm that an undeclared class hash is explicitly rejected during normal (sequencer) execution, both for deprecated Cairo0 contracts and for Cairo1/Native runnable contracts: [5](#0-4) [6](#0-5) 

Thus the two execution engines — the Blockifier (block-building/state-transition authority) and the Starknet OS (used to re-derive/prove the same state transition) — implement materially different semantics for the same syscall: one path enforces "this class must be a recognized/declared class" (analogous to `requiresBridgeAgent`), the other omits that check entirely (analogous to the missing check in `BranchBridgeAgent.callOut`).

### Impact Explanation
Because block validity/state-transition correctness in this architecture depends on the Starknet OS faithfully re-deriving the same state diff/commitments that the Blockifier produced when building the block, any semantic gap between the two engines is a critical correctness bug class, not merely a resource-accounting quirk:

- If a transaction issues `replace_class_syscall` with an undeclared class hash, the Blockifier will reject/fail that call (raising an `UndeclaredClassHash`/"is not declared" error), causing the invoking transaction (or the specific call, depending on error propagation/try-catch) to behave one way when the sequencer executes/commits the block.
- The Starknet OS, tasked with recomputing/proving that same execution, will instead accept the undeclared class hash and commit the corresponding `StateEntry.class_hash` update to `contract_state_changes`, producing a different resulting contract class assignment (and hence a different state diff / committed root) for that contract address than what the sequencer actually committed.

This is a direct violation of the required invariant that Starknet OS re-execution must match the sequencer's actual state transition, and falls squarely into the "wrong committed root or block hash / honest-node divergence" impact category. This can, in principle, desynchronize proven and committed state, undermining the validity guarantee that the prover attaches to blocks, or make certain crafted transactions produce inconsistent results between block building and proof generation.

### Likelihood Explanation
The action is trivially reachable: any contract with `replace_class_syscall` support (any Cairo1 or Cairo0 contract) can invoke it with an arbitrary/undeclared class hash as part of a normal invoke transaction — no privileged role, staking, sequencer/proposer misbehavior, or race condition is required. The bug is also explicitly self-documented by the code's own `TODO(Yoni, 1/1/2026)` comment acknowledging the missing check, indicating this is a known, unaddressed gap rather than a speculative one.

### Recommendation
Add the same "class must be declared" check to the Starknet OS's `execute_replace_class` (both the current Cairo1 syscall implementation in `syscall_impls.cairo` and the deprecated Cairo0 path in `deprecated_execute_syscalls.cairo`) that the Blockifier already performs (i.e., verify `class_hash` exists in `contract_class_changes`/declared classes, aborting/reverting analogous to `get_compiled_class` failing in the Blockifier) before writing the new `StateEntry`. This restores parity between the two execution engines for this syscall and removes the risk of state-root/commitment divergence.

### Proof of Concept
1. Deploy a Cairo1 contract exposing `test_replace_class(class_hash)` which calls `replace_class_syscall(class_hash)` (an existing feature contract already provides this, e.g. `cairo_steps_test_contract.cairo`): [7](#0-6) 
2. Submit an invoke transaction calling `test_replace_class` with a class hash that has never been declared on-chain.
3. Under normal sequencer execution (Blockifier), this call fails with an "is not declared" / `UndeclaredClassHash` error, as demonstrated by the existing negative-flow test: [8](#0-7) 
4. Under Starknet OS re-execution (used for proof generation/re-derivation of the block), the corresponding Cairo code path (`execute_replace_class`) performs no such check and would instead succeed in writing the new (undeclared) class hash into `contract_state_changes`: [9](#0-8) 
5. The divergent outcomes (transaction fails/reverts in the Blockifier vs. succeeds with a state update in the OS) demonstrate that the two engines can compute different final states for the same block/transaction, i.e., an honest-node/prover divergence and potential wrong committed state root.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
