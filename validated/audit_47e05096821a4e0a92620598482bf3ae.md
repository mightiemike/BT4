## Finding

### Title
Front-runnable `initialize()` on the UEA Factory proxy allows attacker to claim ownership and redirect `setUEAProxyImplementation` — (File: x/uexecutor/keeper/genesis.go, x/uexecutor/types/abi.go, x/uexecutor/types/constants.go)

### Summary
The external report's bug class is "implementation/proxy contracts left uninitialized, letting an unprivileged caller claim them." The scoped analog is not a cosmetic implementation-only issue but reaches the live `FACTORY_PROXY` contract at `0x00000000000000000000000000000000000000eA` — the contract every inbound execution, `MsgExecutePayload`, and `DeployUEAV2` call relies on to deploy and resolve Universal Executor Accounts (UEAs).

### Finding Description
At genesis, `x/uexecutor/keeper/genesis.go` deploys the three factory-related EVM accounts: [1](#0-0) 

- `deployFactoryImplContract` sets the implementation's code but never calls `initialize` on it. [2](#0-1) 
- `deployProxyAdminContract` explicitly writes the `Ownable` owner storage slot directly via `SetState`, bypassing any `initialize`/`transferOwnership` call. [3](#0-2) 
- `deployFactoryProxy`, by contrast, only sets the EIP-1967 admin slot and implementation slot — it never sets an owner value for the Factory logic (which lives behind the proxy and is reached via delegatecall). [4](#0-3) 

The Factory ABI used by the keeper explicitly defines an `initialize(address initialOwner)` entrypoint plus the privileged `setUEAProxyImplementation(address)` function that the owner alone should be able to call: [5](#0-4) 

A grep of the entire production codebase (excluding tests) turns up **zero** production callers of `initialize` on the factory proxy/implementation — the only place `initialize` is invoked is in test scaffolding (`test/utils/contracts_setup.go`), where the test explicitly checks that the owner is unset after genesis before calling `initialize`: [6](#0-5) 

This means on a real chain, immediately after genesis, the live `FACTORY_PROXY` at `0x…eA` has no owner set (typical OpenZeppelin `Initializable`/`OwnableUpgradeable` pattern guards `initialize()` only against being called twice — not against being called by an unprivileged caller). The first party to submit `initialize(attackerAddr)` against the proxy becomes the Factory owner and can subsequently call `setUEAProxyImplementation(maliciousImpl)`, redirecting the implementation used by every future `deployUEA` call driven from `x/uexecutor/keeper/deploy_uea.go` (`DeployUEAV2`) and `x/uexecutor/keeper/evm.go` (`CallFactoryToDeployUEA`). [7](#0-6) [8](#0-7) 

Every subsequently deployed UEA — triggered automatically from ordinary inbound execution (`ExecuteInboundGas`) whenever a new source-chain user's inbound is first processed — would then be instantiated as the attacker's malicious logic contract instead of the legitimate UEA implementation. [9](#0-8) 

### Impact Explanation
If exploitable, this is not a mere phishing/reputation issue as in the original report — because the target is the live, canonical proxy address (`0x…eA`) that the entire universal-execution pipeline hardcodes and calls (`FACTORY_PROXY_ADDRESS_HEX`), not a discardable, unreferenced implementation. An attacker front-running the legitimate `initialize` call gains ownership of the one Factory contract the whole system depends on and can point `UEA_PROXY_IMPLEMENTATION` at arbitrary attacker-controlled logic. Every user whose UEA is deployed after that point would have attacker-controlled code running as their smart account, enabling theft of any funds routed to or held by those UEAs — squarely within the "unauthorized UEA execution" / "stealing user funds" allowed-impact categories.

### Likelihood Explanation
Exploitability hinges entirely on whether some out-of-repo genesis/bootstrap step (e.g., a `genesis.json` app-state field, an included Solidity constructor argument, or an off-chain deploy script not present in this Go repository) sets the Factory owner atomically with the genesis block, closing the window. I could not find any such call in the indexed Go source, upgrade handlers (`app/upgrades/**`), or module wiring — the only place `initialize` is invoked is test-only code, and unlike the ProxyAdmin (which gets its owner slot force-written directly in `deployProxyAdminContract`), the Factory logic contract has no equivalent direct-write path. This strongly suggests the production chain is missing an atomic "deploy + initialize" step for the Factory proxy, leaving a real, reachable window for a race between chain start and the first `initialize` transaction.

### Recommendation
- In `deployFactoryProxy` (and `deployFactoryImplContract`), atomically set the Factory owner in the same genesis routine that writes the proxy/implementation slots — either by directly writing the `Ownable` owner storage slot via `evmKeeper.SetState` (as already done for `ProxyAdminContract`), or by having genesis synchronously invoke `initialize(moduleOrGovAddress)` via `DerivedEVMCall` before the chain accepts any transactions.
- Additionally, petrify the Factory implementation contract itself (call `_disableInitializers()` equivalent / mark it initialized at deploy time) so it can never be claimed directly, consistent with the original report's recommendation.
- Add an invariant/init-genesis test (mirroring `TestDeploySystemContracts_DeploysFullTripleForEveryReservedAddress` in `x/uregistry`) asserting the Factory owner slot is non-zero immediately after `InitGenesis`, before any external transaction can be included.

### Proof of Concept
1. Bootstrap a Push Chain node from genesis using the current `x/uexecutor` `InitGenesis` path (`deployFactoryEA` → `deployFactoryProxy`/`deployFactoryImplContract`/`deployProxyAdminContract`).
2. Immediately after the genesis block (before any legitimate `initialize` transaction, if one exists off-repo, has a chance to land), submit an EVM transaction calling `initialize(attackerAddress)` on `0x00000000000000000000000000000000000000eA` from an unprivileged account.
3. Query `owner()` on the proxy — it now returns `attackerAddress`.
4. Call `setUEAProxyImplementation(maliciousImplAddress)` as the attacker.
5. Trigger any ordinary user inbound that causes `DeployUEAV2`/`CallFactoryToDeployUEA` to deploy a new UEA — it is deployed against the attacker's malicious implementation, giving the attacker control over that user's Universal Executor Account.

func deployFactoryProxy(ctx context.Context, evmKeeper types.EVMKeeper) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	proxyAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)
	proxyAdminOwner := common.HexToAddress(types.PROXY_ADMIN_ADDRESS_HEX)
	factoryImplAddress := common.HexToAddress(types.FACTORY_IMPL_ADDRESS_HEX)

	// Compute the code hash from the runtime bytecode
	codeHash := crypto.Keccak256(types.ProxyRuntimeBytecode)

	// Create the EVM account object
	evmAccount := statedb.Account{
		Nonce:    1,             // to prevent tx nonce=0 conflicts
		Balance:  new(uint256.Int), // zero balance by default
		CodeHash: codeHash,      // link to deployed code
	}

	// Set the EVM account with the factory proxy contract
	err := evmKeeper.SetAccount(sdkCtx, proxyAddress, evmAccount)
	if err != nil {
		panic("failed to set factory proxy contract account: " + err.Error())
	}

	// Store the runtime bytecode linked to the code hash
	evmKeeper.SetCode(sdkCtx, codeHash, types.ProxyRuntimeBytecode)

	// Update proxyAdmin Slot with the proxyAdmin owner address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_ADMIN_SLOT, common.LeftPadBytes(proxyAdminOwner.Bytes(), 32))

	// Update proxyImplementation Slot with the factory implementation address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_IMPLEMENTATION_SLOT, common.LeftPadBytes(factoryImplAddress.Bytes(), 32))
}

// CallFactoryToDeployUEA deploys a new UEA using factory contract
// Returns deployment response or error if deployment fails
func (k Keeper) CallFactoryToDeployUEA(
	ctx sdk.Context,
	from, factoryAddr common.Address,
	universalAccount *types.UniversalAccountId,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: deployUEA",
		"factory", factoryAddr.Hex(),
		"chain_namespace", universalAccount.ChainNamespace,
		"chain_id", universalAccount.ChainId,
		"owner", universalAccount.Owner,
	)

	abi, err := types.ParseFactoryABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse factory ABI")
	}

	abiUniversalAccount, err := types.NewAbiUniversalAccountId(universalAccount)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal account")
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,        // who is sending the transaction
		factoryAddr, // destination: FactoryV1 contract
		big.NewInt(0),
		nil,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"deployUEA",
		abiUniversalAccount,
	)
}
