### Title
`TransactionOutput::ensure_match_transaction_info` never checks the state/hot-state checkpoint or position-state-checkpoint hashes, letting replay/restore accept a divergent ledger state as valid - (File: `types/src/transaction/mod.rs`)

### Summary
`ensure_match_transaction_info` is the integrity gate used to confirm that a locally re-executed `TransactionOutput` matches an authenticated, previously-committed `TransactionInfo` (the entry stored in the transaction accumulator). It validates status, gas used, write-set hash, and event-root hash, but explicitly skips the state-checkpoint hash, hot-state-checkpoint hash, and the new `position_state_checkpoint_hash` field. This is a self-acknowledged gap (see the inline TODO) that allows a re-executed/replayed state root to silently diverge from the authenticated root while the comparator still reports a match.

### Finding Description
`TransactionInfoV0`/`V1` carry `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` fields, each of which commits to the Sparse-Merkle/JMT-derived root of the world state (or the native "position" state) at a checkpoint boundary [1](#0-0) .

`ensure_match_transaction_info` is the function responsible for verifying that a computed `TransactionOutput` (produced either during normal execution, or during replay/restore of an already-authenticated `TransactionInfo`) is consistent with that authenticated info. It checks `status`, `gas_used`, `write_set` hash (`state_change_hash`), and `event_root_hash`, but the function returns `Ok(())` without ever comparing `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` [2](#0-1) . The code contains an explicit acknowledgement of this:

```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
``` [3](#0-2) 

This mirrors the bug-class in the seed report: a fee/validity computation is supposed to cover all relevant inputs, but a subset of inputs (`shortAmount`/`longAmount` == 0) is silently treated as "nothing to check," letting the caller bypass the intended enforcement. Here, the analogous invariant is "the recomputed output must match every commitment field in the authenticated `TransactionInfo`," but the comparator only enforces write-set/event commitments and omits the state-root commitments entirely — regardless of whether those fields are populated in the authenticated `TransactionInfo`.

The `position_state_checkpoint_hash` is populated by the executor's `assemble_transaction_infos` from computed `position_state_checkpoint_hashes` [4](#0-3) , and is produced during state-checkpoint output construction [5](#0-4) , gated behind the `compute_trading_native_state_roots` on-chain config flag [6](#0-5) . This flag is defined but I could not confirm from the index whether it is currently active on mainnet; it appears to be an in-progress ("trading-native") feature.

### Impact Explanation
If replay/restore/archive-verification tooling (e.g., `storage/db-tool/src/replay_on_archive.rs`, which iterates authenticated `expected_txn_infos` from backup and compares against locally re-executed output [7](#0-6) ) relies on `ensure_match_transaction_info` (or an equivalent comparator with the same blind spot) as its correctness oracle, a bug in state-root computation for the checkpoint/hot-state/position-state trees would go completely undetected: the tool would report "replay succeeded" even though the recomputed Merkle/JMT root differs from the one committed and signed by validators. This breaks the "committed state that differs from correct VM result... goes undetected" and "restore/replay must not reinterpret committed data into a different ledger state" integrity gates, because a corrupted or forked state root at these checkpoints would pass validation silently, undermining confidence in fast-sync/restore verification and hard-fork detection tooling built on this comparator.

### Likelihood Explanation
The gap is not hidden — it's explicitly documented in code as a known, unresolved TODO, meaning it is a live, admitted omission in the codebase today (not a hypothetical). Its real-world severity depends on whether `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (and the general state-checkpoint-hash validation) is relied upon in production replay-verification workflows before the TODO is addressed; the comment itself says validation must be added "before enabling" that feature, implying the authors are aware this must be fixed pre-launch. This lowers immediate mainnet exploitability but represents a real integrity hole for any code path that trusts `ensure_match_transaction_info` as a complete correctness check.

### Recommendation
Extend `ensure_match_transaction_info` to compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` against locally computed equivalents whenever they are `Some` in the authenticated `TransactionInfo`, returning an error on mismatch just as is done for `write_set_hash` and `event_root_hash`. This must land before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (or any hot-state/position-state root feature) is enabled, and ideally before any replay/restore tooling is treated as an authoritative correctness oracle for these fields.

### Proof of Concept
Conceptual (no runnable PoC available from static review alone):
1. Enable/emulate a code path that produces a `position_state_checkpoint_hash` (or `state_checkpoint_hash`) differing from the one in the authenticated backup's `TransactionInfo`, e.g. via a bug in JMT batch update or a wrong version bound in `PositionStateWithSummary` construction.
2. Run `storage/db-tool/src/replay_on_archive.rs`'s `Verifier::verify` / `execute_and_verify` flow, which is expected to call the output-vs-authenticated-info comparator per replayed transaction.
3. Because `ensure_match_transaction_info` never inspects the checkpoint-hash fields, the comparator returns `Ok(())` and the tool reports the chunk as successfully replayed/verified, even though the recomputed state root diverges from the one bound to the signed `LedgerInfo`/accumulator.

This confirms the local root cause (omitted field checks in `ensure_match_transaction_info`) and the resulting impact (undetected state-root divergence in replay/restore verification), though full exploitation requires the `compute_trading_native_state_roots`/hot-state-root feature to be active, which I could not confirm is enabled on mainnet from the available index.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn assemble_transaction_infos(
        to_commit: &TransactionsWithOutput,
        transaction_info_v1: bool,
        state_checkpoint_hashes: &[Option<HashValue>],
        hot_state_checkpoint_hashes: Option<&[Option<HashValue>]>,
        position_state_checkpoint_hashes: Option<&[Option<HashValue>]>,
    ) -> (Vec<TransactionInfo>, Vec<HashValue>) {
        let _timer = OTHER_TIMERS.timer_with(&["assemble_transaction_infos"]);

        (0..to_commit.len())
            .into_par_iter()
            .with_min_len(optimal_min_len(to_commit.len(), 64))
            .map(|i| {
                let txn = &to_commit.transactions[i];
                let txn_output = &to_commit.transaction_outputs[i];
                let persisted_auxiliary_info = &to_commit.persisted_auxiliary_infos[i];
                // Use the auxiliary info hash directly from the persisted info
                let auxiliary_info_hash = match persisted_auxiliary_info {
                    PersistedAuxiliaryInfo::None => None,
                    PersistedAuxiliaryInfo::V1 { .. } => {
                        Some(CryptoHash::hash(persisted_auxiliary_info))
                    },
                    PersistedAuxiliaryInfo::TimestampNotYetAssignedV1 { .. } => None,
                };
                let state_checkpoint_hash = state_checkpoint_hashes[i];
                let event_hashes = txn_output
                    .events()
                    .iter()
                    .map(CryptoHash::hash)
                    .collect::<Vec<_>>();
                let event_root_hash =
                    InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash();
                let write_set_hash = CryptoHash::hash(txn_output.write_set());
                let status = txn_output
                    .status()
                    .as_kept_status()
                    .expect("Already sorted.");
                let txn_info = if transaction_info_v1 {
                    TransactionInfo::builder_v1()
                        .transaction_hash(txn.committed_hash())
                        .state_change_hash(write_set_hash)
                        .event_root_hash(event_root_hash)
                        .maybe_state_checkpoint_hash(state_checkpoint_hash)
                        .maybe_hot_state_checkpoint_hash(
                            hot_state_checkpoint_hashes.and_then(|hot| hot[i]),
                        )
                        .gas_used(txn_output.gas_used())
                        .status(status)
                        .maybe_auxiliary_info_hash(auxiliary_info_hash)
                        .maybe_position_state_checkpoint_hash(
                            position_state_checkpoint_hashes.and_then(|p| p[i]),
                        )
                        .build()
                } else {
                    TransactionInfo::builder_v0()
                        .transaction_hash(txn.committed_hash())
                        .state_change_hash(write_set_hash)
                        .event_root_hash(event_root_hash)
                        .maybe_state_checkpoint_hash(state_checkpoint_hash)
                        .gas_used(txn_output.gas_used())
                        .status(status)
                        .maybe_auxiliary_info_hash(auxiliary_info_hash)
                        .build()
                };
