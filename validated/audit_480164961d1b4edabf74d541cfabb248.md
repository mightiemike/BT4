### Title
Orphaned Postponed Receipts and PromiseYield Entries After Account Deletion Allow Unauthorized Actions on Recreated Accounts - (File: core/store/src/utils/mod.rs)

### Summary

`remove_account` deletes an account's core record, contract code, access keys, and contract data, but leaves all receipt-related trie entries intact. If an account is deleted and later recreated with the same ID, orphaned `PostponedReceipt`, `PendingDataCount`, `PostponedReceiptId`, `ReceivedData`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, and `DataIdToYieldId` entries remain in the trie and are processed by the runtime against the new account. An attacker who previously owned the account can exploit this to inject arbitrary actions — including `AddKey` — onto the new account, enabling full account takeover and fund theft.

### Finding Description

`remove_account` in `core/store/src/utils/mod.rs` explicitly removes five categories of trie state: [1](#0-0) 

The removed categories are `TrieKey::Account`, `TrieKey::ContractCode`, all `TrieKey::AccessKey` entries (via prefix iteration), all `TrieKey::GasKeyNonce` entries, and all `TrieKey::ContractData` entries.

The following account-scoped `TrieKey` variants listed in `COLUMNS_WITH_ACCOUNT_ID_IN_KEY` are **never touched** by `remove_account`: [2](#0-1) 

Specifically: `ReceivedData`, `PostponedReceiptId`, `PendingDataCount`, `PostponedReceipt`, `PromiseYieldReceipt`, `PromiseYieldStatus`, `YieldIdToDataId`, and `DataIdToYieldId`.

`action_delete_account` calls `remove_account` and performs no additional cleanup of these entries: [3](#0-2) 

The storage-usage guard that could block deletion is computed from `account.storage_usage()`, which does **not** track postponed receipt storage, so deletion succeeds even when postponed receipts exist: [4](#0-3) 

When a data receipt later arrives for an orphaned `PostponedReceipt`, `process_receipt` looks up the entry by `(receiver_id, receipt_id)` and executes it unconditionally against whatever account currently holds that ID: [5](#0-4) 

The same applies to `PromiseYield`: when a `PromiseResume` receipt arrives, the runtime fetches the orphaned `PromiseYieldReceipt` and executes it on the current account: [6](#0-5) 

`promise_yield_resume` can be called from **any** contract — there is no restriction to the account that created the yield: [7](#0-6) 

### Impact Explanation

An attacker who previously owned `victim.near` can pre-plant a `PostponedReceipt` whose `predecessor_id == receiver_id == victim.near` and whose action list contains `AddKey(attacker_full_access_pubkey)`. After deleting `victim.near`, the orphaned receipt persists. When a legitimate user recreates `victim.near`, the attacker triggers the data receipt from a contract they control (`attacker.near`). The runtime executes the old receipt on the new account: because `predecessor_id == receiver_id`, the `AddKey` action passes `check_account_existence` and is applied to the new account. The attacker now holds a full-access key and can drain all funds.

The `PromiseYield` path is also exploitable: with `promise_yield_create_with_id`, the attacker chooses a known `yield_id`, reads the corresponding `data_id` from the surviving `YieldIdToDataId` trie entry after deletion, and calls `promise_yield_resume(data_id, payload)` from any contract to execute the orphaned yield callback on the new account.

Affected invariant: **account deletion must atomically remove all account-scoped state**; failure to do so allows cross-lifecycle state injection that breaks authorization and balance invariants.

### Likelihood Explanation

The attacker must have previously owned the target account ID and must control a second contract to supply the data receipt. Both conditions are achievable by any unprivileged user. The window of exploitation opens the moment the new account is created and remains open until the orphaned receipt times out (for `PromiseYield`) or indefinitely (for `PostponedReceipt`, which has no timeout). Account name reuse is common in practice (e.g., after a project abandons a name), making this a realistic attack surface.

### Recommendation

Extend `remove_account` to iterate and delete all account-scoped receipt entries before returning. Specifically, add prefix-iteration removal for:

- `col::RECEIVED_DATA` prefix `receiver_id`
- `col::POSTPONED_RECEIPT_ID` prefix `receiver_id`
- `col::PENDING_DATA_COUNT` prefix `receiver_id`
- `col::POSTPONED_RECEIPT` prefix `receiver_id`
- `col::PROMISE_YIELD_RECEIPT` prefix `receiver_id`
- `col::PROMISE_YIELD_STATUS` prefix `receiver_id`
- `col::YIELD_ID_TO_DATA_ID` prefix `receiver_id`
- `col::DATA_ID_TO_YIELD_ID` prefix `receiver_id`

This mirrors the existing pattern used for `ContractData` removal: [8](#0-7) 

Additionally, add a guard in `action_delete_account` that rejects deletion if any postponed receipts or active yield receipts exist for the account, similar to the existing locked-balance check.

### Proof of Concept

**Setup (attacker controls `victim.near` and `attacker.near`):**

1. Deploy contract A to `victim.near`. Contract A has a function `setup_trap` that:
   - Calls `promise_batch_create("attacker.near")` → `promise_idx_0`
   - Calls `promise_then(promise_idx_0, "victim.near", "noop", [], gas)` → `promise_idx_1`
   - Calls `promise_batch_action_add_key(promise_idx_1, attacker_pubkey, FullAccess)` on the callback receipt
   - Returns `promise_idx_1`

2. Attacker calls `victim.near::setup_trap()`. The runtime creates:
   - An outgoing action receipt to `attacker.near` (to call `noop`)
   - A `PostponedReceipt` for `victim.near` with `predecessor_id=victim.near`, `receiver_id=victim.near`, `actions=[AddKey(attacker_pubkey, FullAccess)]`, waiting for data from `attacker.near`

3. Attacker calls `DeleteAccount` on `victim.near`. `remove_account` deletes the account record, contract, and access keys, but the `PostponedReceipt` and `PostponedReceiptId` entries remain in the trie.

**Exploitation (after legitimate user creates `victim.near`):**

4. Legitimate user creates `victim.near` with their own key and funds it.

5. Attacker calls `attacker.near::noop()`. The runtime generates a data receipt to `victim.near` for the pending `data_id`.

6. The runtime processes the data receipt:
   - Finds `PostponedReceiptId[victim.near, data_id]` → `receipt_id`
   - Decrements `PendingDataCount` to 0
   - Fetches `PostponedReceipt[victim.near, receipt_id]`
   - Calls `apply_action_receipt` on the new `victim.near`
   - `check_account_existence` passes (account exists)
   - `predecessor_id == receiver_id == victim.near` → `AddKey` is permitted
   - `attacker_pubkey` is added as a full-access key to the new `victim.near`

7. Attacker signs a `Transfer` transaction from `victim.near` using `attacker_pubkey`, draining all funds. [1](#0-0) [9](#0-8) [10](#0-9) [11](#0-10) [2](#0-1)

/// Removes account, code and all access keys and gas keys associated to it.
pub fn remove_account(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
) -> Result<RemoveAccountResult, StorageError> {
    state_update.remove(TrieKey::Account { account_id: account_id.clone() });
    state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });

    let mut gas_key_nonce_count: usize = 0;
    let mut gas_key_nonce_total_key_bytes: usize = 0;

    // Removing access keys and gas key nonces
    let lock = state_update.trie().lock_for_iter();
    let mut keys_to_remove: Vec<TrieKey> = Vec::new();
    for raw_key in state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_access_keys(account_id), &lock)?
    {
        let raw_key = raw_key?;
        let key_handle = trie_key_parsers::parse_key_handle_from_access_key_key(
            &raw_key, account_id,
        )
        .map_err(|_e| {
            StorageError::StorageInconsistentState(
                "Can't parse key handle from raw key for AccessKey".to_string(),
            )
        })?;
        let nonce_index =
            trie_key_parsers::parse_nonce_index_from_gas_key_key(&raw_key, account_id, &key_handle)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse nonce index from raw key for AccessKey".to_string(),
                    )
                })?;
        if let Some(index) = nonce_index {
            gas_key_nonce_count += 1;
            gas_key_nonce_total_key_bytes += raw_key.len();
            keys_to_remove.push(TrieKey::gas_key_nonce(
                account_id.clone(),
                key_handle.clone(),
                index,
            ));
        } else {
            keys_to_remove.push(TrieKey::access_key(account_id.clone(), key_handle.clone()));
        }
    }
    drop(lock);

    for trie_key in keys_to_remove {
        state_update.remove(trie_key);
    }

    // Removing contract data
    let lock = state_update.trie().lock_for_iter();
    let data_keys = state_update
        .locked_iter(&trie_key_parsers::get_raw_prefix_for_contract_data(account_id, &[]), &lock)?
        .map(|raw_key| {
            trie_key_parsers::parse_data_key_from_contract_data_key(&raw_key?, account_id)
                .map_err(|_e| {
                    StorageError::StorageInconsistentState(
                        "Can't parse data key from raw key for ContractData".to_string(),
                    )
                })
                .map(Vec::from)
        })
        .collect::<Result<Vec<_>, _>>()?;
    drop(lock);

    for key in data_keys {
        state_update.remove(TrieKey::ContractData { account_id: account_id.clone(), key });
    }
    Ok(RemoveAccountResult { gas_key_nonce_count, gas_key_nonce_total_key_bytes })
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}

        &mut self,

        self.result_state.gas_counter.pay_base(base)?;
        if self.context.is_view() {
            return Err(HostError::ProhibitedInView {
                method_name: "promise_yield_resume".to_string(),
            }
            .into());
        }
        self.result_state.gas_counter.pay_base(yield_resume_base)?;
        self.result_state.gas_counter.pay_per(yield_resume_byte, payload_len)?;
        let data_id = get_memory_or_register!(self, data_id_ptr, data_id_len)?;
        let payload = get_memory_or_register!(self, payload_ptr, payload_len)?;
        let payload_len = payload.len() as u64;
        if payload_len > self.config.limit_config.max_yield_payload_size {
            return Err(HostError::YieldPayloadLength {
                length: payload_len,
                limit: self.config.limit_config.max_yield_payload_size,
            }
            .into());
        }

        let data_id: [_; CryptoHash::LENGTH] =
            (&*data_id).try_into().map_err(|_| HostError::DataIdMalformed)?;
        let data_id = CryptoHash(data_id);
        let payload = payload.into_owned();
        self.ext.submit_promise_resume_data(data_id, payload).map(u32::from)
