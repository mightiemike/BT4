### Title
Spot-price Uniswap V3 quote manipulation in `ExecuteInboundGas` gas-abstraction auto-swap enables theft of PC/PRC20 value - ([File: x/uexecutor/keeper/execute_inbound_gas.go])

### Summary
`ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go`) computes the minimum acceptable swap output (`minPCOut`) for the auto-swap that converts bridged-in PRC20 gas tokens to native PC by calling `k.GetSwapQuote`, which in turn calls Uniswap V3's `QuoterV2.quoteExactInputSingle` — a **spot-price** read of the live on-chain pool, not a time-weighted average. Because the slippage guard is derived from the very same manipulable spot price it is supposed to protect against, an unprivileged attacker can move the pool price immediately before triggering a `GAS`/`GAS_AND_PAYLOAD` inbound, causing the protocol-executed swap to settle at an attacker-favorable (or protocol-unfavorable) rate. This is the same class of bug as the Tracer Protocol `Pricing.updatePrice()` finding: using an easily wash-tradable price feed (rather than a manipulation-resistant TWAP) both to derive the reference value and to gate the trade's own slippage protection.

### Finding Description
The vulnerable flow:
1. `GetSwapQuote` in `x/uexecutor/keeper/evm.go` (lines 500-538) calls `quoteExactInputSingle` on the Uniswap V3 `QuoterV2` contract for the `prc20 → wpc` pair using the current pool state — a spot price. [1](#0-0) 
2. `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go` lines 134-148) takes that quote and derives `minPCOut` as `quote * 95 / 100` (a flat 5% slippage tolerance), then immediately performs `CallPRC20DepositAutoSwap` using this quote-derived bound. [2](#0-1) 

Because the "reference" price and the "protection" bound come from the same single spot observation, an attacker can:
- Execute large wash trades (self-trades across the pool, or trades between two attacker-controlled accounts) on the Uniswap V3 `prc20/WPC` pool on Push Chain immediately before the inbound executes, pushing the pool price to an extreme.
- Trigger (or wait for) their own bridge deposit of `TxType_GAS` / `GAS_AND_PAYLOAD` to be voted in by honest validators, which is processed atomically within the same block/transaction context as the manipulated pool state (there is no cooldown, TWAP, or external reference-price check).
- Extract WPC/PC out of the pool at a distorted rate, or conversely force the protocol's auto-swap to receive far less PC than fair value, since `minPCOut` merely tracks the same skewed quote rather than a stable, external anchor.

This mirrors the audit report exactly: "on-chain TWAP systems...require orders to exist in a priority queue" — here, no such mechanism exists at all; a single spot `quoteExactInputSingle` call is trusted directly for both valuation and slippage protection.

### Impact Explanation
This falls within the "corruption of PRC20 or native asset accounting" and "unauthorized module-originated EVM execution" impact categories: the module-originated `CallPRC20DepositAutoSwap` executes with a manipulated reference price, which can result in loss of protocol-held PC/PRC20 value in the Uniswap pool the module swaps against, or a user receiving corrupted/incorrect PC amounts on gas-abstraction inbound. Repeated exploitation, especially with a thinly-liquid pool (a realistic scenario on a newly-launched chain), can drain the liquidity/PC available to the auto-swap route.

### Likelihood Explanation
Reachable by any unprivileged external user with an account: creating/controlling the Uniswap V3 pool trades (self-trading is unrestricted for any pool participant) and then submitting a normal cross-chain deposit of `TxType_GAS` or `GAS_AND_PAYLOAD`, which honest validators simply vote on as observed on the source chain. No privileged, validator, or admin action is required to trigger the swap — only the ordinary user-facing inbound deposit path.

### Recommendation
Do not use a single spot `quoteExactInputSingle` call as both valuation and slippage-protection source. Use a manipulation-resistant reference price (e.g., a Uniswap V3 TWAP oracle over a sufficiently long window, or the already-existing `ChainMeta`/gas-price median oracle path) to compute `minPCOut` independently of the instantaneous quote, and/or cap the maximum deviation allowed between the spot quote and the TWAP reference before allowing the swap to proceed.

### Proof of Concept
1. Attacker deploys/uses two accounts (or a single account with paired trades) against the on-chain `prc20/WPC` Uniswap V3 pool referenced by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`.
2. Attacker executes large wash trades on the pool to skew the spot price of `prc20` in terms of `WPC` far from its fair market value.
3. Attacker (or an accomplice) bridges in a `GAS`/`GAS_AND_PAYLOAD` inbound event for that `prc20`; honest universal validators vote it in normally via `VoteInbound` → ballot finalization → `ExecuteInboundGas`.
4. `GetSwapQuote` returns the skewed spot price; `minPCOut = quote*95/100` is computed from that same skewed value; `CallPRC20DepositAutoSwap` executes at the manipulated rate, extracting value from the pool/module in the attacker's favor.
5. Attacker reverses the wash trade afterward (or simply lets it settle), realizing the discrepancy in PC value versus true market rate. [3](#0-2) [4](#0-3)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
