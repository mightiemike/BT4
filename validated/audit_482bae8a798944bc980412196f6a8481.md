### Title
Unbounded `ListWitnesses` response allows attacker-inflatable RPC/HTTP bandwidth and CPU DoS - (File: `framework/src/main/java/org/tron/core/Wallet.java`)

### Summary
`Wallet.getWitnessList()` calls `WitnessStore.getAllWitnesses()` and serializes every witness in the store into a `WitnessList` protobuf with no offset/limit, unlike the size-capped `getPaginatedNowWitnessList` (`WITNESS_COUNT_LIMIT_MAX`). Because witness accounts can be created by any funded account via `WitnessCreateActuator`, an attacker can grow the `WitnessStore` and force every subsequent unauthenticated `ListWitnesses` gRPC/HTTP call to build and serialize a response proportional to the number of witnesses created.

### Finding Description
`Wallet.getWitnessList()` iterates `chainBaseManager.getWitnessStore().getAllWitnesses()` and adds every `WitnessCapsule` to the `WitnessList.Builder` with no cap: [1](#0-0) 

`WitnessStore.getAllWitnesses()` streams the entire underlying DB with no size limit: [2](#0-1) 

This is reachable unauthenticated via gRPC `listWitnesses` on both the full-node and solidity wallet services: [3](#0-2) [4](#0-3) 
and via the HTTP endpoint `ListWitnessesServlet`, which also has no offset/limit parameters: [5](#0-4) 

By contrast, `getPaginatedNowWitnessList` explicitly clamps `limit` to `WITNESS_COUNT_LIMIT_MAX` and returns `null` for invalid offset/limit before doing any heavy work: [6](#0-5) 

The witness set is attacker-inflatable: any funded account can broadcast a `WitnessCreateContract`, validated by `WitnessCreateActuator.validate()`, which only checks address validity, URL validity, account existence, that the address is not already a witness, and that balance ≥ `getAccountUpgradeCost()`: [7](#0-6) 
The fee charged is exactly `dynamicStore.getAccountUpgradeCost()`, deducted from the creator's balance and burned/sent to the black hole: [8](#0-7) 
Each witness account is a distinct address (no reuse), so the attacker must fund `K` separate addresses to create `K` witnesses, but there is no upper bound on `K` in the protocol itself — only economic cost limits it, and this cost is fixed per witness regardless of how large the store already is. `RateLimiterServlet` (extended by `ListWitnessesServlet`) provides per-IP/QPS throttling, not a cap on payload size per request, so repeated calls from distributed/rotated IPs (or from many gRPC clients, which does not go through `RateLimiterServlet` at all) still each pay the full O(K) cost of `getAllWitnesses()` + serialization.

### Impact Explanation
This matches the "DoS via RPC-API" bounty class: unauthenticated callers can force the node to build and transmit responses whose size scales linearly with an attacker-controlled parameter (K = number of witnesses created), with no per-call cap available to the server or the caller, unlike the paginated equivalent. Repeated concurrent calls to `listWitnesses`/`GetPaginatedNowWitnessList`'s unpaginated sibling can consume server CPU (protobuf/JSON serialization, list iteration) and network bandwidth, degrading availability for legitimate RPC/HTTP clients.

### Likelihood Explanation
Preconditions: attacker needs no privileged role, only enough TRX to pay `getAccountUpgradeCost()` per witness account created (a real chain economic cost, not free). Feasibility is bounded by how cheap this cost is relative to the attacker's resources — the more witnesses created, the greater and more persistent the amplification, since the inflated `WitnessStore` affects all future callers, not just the attacker. This is a lower-severity, cost-gated DoS vector (bounded by real fee cost per witness) rather than a free/instant crash, but the underlying code path has no defensive cap contrary to the sibling paginated API, which is a genuine inconsistency and exploitable design gap.

### Recommendation
Add pagination (offset/limit, capped by a constant analogous to `WITNESS_COUNT_LIMIT_MAX`) to `Wallet.getWitnessList()` / `ListWitnessesServlet` / gRPC `listWitnesses`, or otherwise cap the number of witnesses returned by a single unauthenticated call, and consider capping response size at the servlet/interceptor layer for all list-returning unauthenticated endpoints.

### Proof of Concept
```java
// JUnit-style PoC in framework/src/test/java/org/tron/core/WalletTest.java
@Test
public void testUnboundedListWitnessesGrowth() {
  int N = 5000; // simulate attacker-inflated witness set
  for (int i = 0; i < N; i++) {
    saveWitnessWith("dos_witness_" + i, 1L); // helper used elsewhere in WalletTest
  }
  long start = System.nanoTime();
  GrpcAPI.WitnessList list = wallet.getWitnessList();
  long elapsed = System.nanoTime() - start;
  Assert.assertTrue(list.getWitnessesCount() >= N); // no cap enforced
  logger.info("Serialized size={} bytes, elapsed={} ns",
      list.getSerializedSize(), elapsed);
  // Contrast: getPaginatedNowWitnessList caps at WITNESS_COUNT_LIMIT_MAX regardless of N
  for (int i = 0; i < N; i++) {
    chainBaseManager.getWitnessStore().delete(("dos_witness_" + i).getBytes());
  }
}
```
Expected result: `list.getWitnessesCount()` and `getSerializedSize()` grow linearly and unboundedly with `N`, confirming no cap is enforced in `getWitnessList()`, in contrast to `getPaginatedNowWitnessList` which is capped via `WITNESS_COUNT_LIMIT_MAX`. [9](#0-8)

    }

  private void createWitness(final WitnessCreateContract witnessCreateContract)
      throws BalanceInsufficientException {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    WitnessStore witnessStore = chainBaseManager.getWitnessStore();
    //Create Witness by witnessCreateContract
    final WitnessCapsule witnessCapsule = new WitnessCapsule(
        witnessCreateContract.getOwnerAddress(),
        0,
        witnessCreateContract.getUrl().toStringUtf8());

    logger.debug("createWitness,address[{}]", witnessCapsule.createReadableString());
    witnessStore.put(witnessCapsule.createDbKey(), witnessCapsule);
    AccountCapsule accountCapsule = accountStore
        .get(witnessCapsule.createDbKey());
    accountCapsule.setIsWitness(true);
    if (dynamicStore.getAllowMultiSign() == 1) {
      accountCapsule.setDefaultWitnessPermission(dynamicStore);
    }
    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    long cost = dynamicStore.getAccountUpgradeCost();
    adjustBalance(accountStore, witnessCreateContract.getOwnerAddress().toByteArray(), -cost);
    if (dynamicStore.supportBlackHoleOptimization()) {
      dynamicStore.burnTrx(cost);
    } else {
      adjustBalance(accountStore, accountStore.getBlackhole(), +cost);
    }
    dynamicStore.addTotalCreateWitnessCost(cost);
  }

  public void testGetPaginatedNowWitnessList_CornerCase() {

          witnessList == null);

      witnessList = wallet.getPaginatedNowWitnessList(100, 0);
      Assert.assertTrue("Should return an empty witness list when limit is 0", witnessList == null);

      String fakeWitnessAddressPrefix = "fake_witness";
      int fakeNumberOfWitnesses = 1000 + 10;
      // Mock additional witnesses with vote counts greater than 1000
      for (int i = 0; i < fakeNumberOfWitnesses; i++) {
        saveWitnessWith(fakeWitnessAddressPrefix + i, 200);

      witnessList = wallet.getPaginatedNowWitnessList(0, 1000000);
      // Check the returned witness list should contain 1000 witnesses with descending vote count
      Assert.assertTrue("Witness list should contain 1000 witnesses",
          witnessList.getWitnessesCount() == 1000);

      // clean up, delete the fake witnesses
      for (int i = 0; i < fakeNumberOfWitnesses; i++) {
        chainBaseManager.getWitnessStore()
            .delete(ByteString.copyFromUtf8(fakeWitnessAddressPrefix + i).toByteArray());
      }
    } catch (MaintenanceUnavailableException e) {
      Assert.fail(e.getMessage());
    }
