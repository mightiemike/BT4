## Analysis

The `scalarPrice` bug class (multiplication should precede division to avoid truncation loss) has a direct, more severe analog in `x/uexecutor/keeper/fees.go`'s `CalculateGasCost`.

### Title
Division-before-multiplication in `CalculateGasCost` truncates sub-1-upc base fees to zero, allowing free module-originated EVM execution - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` divides the base fee by `1e18` (to "unscale" the `LegacyDec` representation) **before** multiplying by `gasUsed`, instead of multiplying first and dividing once at the end. Because the smallest usable gas-price granularity on Push Chain is expected to be a small fraction of one whole `upc` (analogous to gwei being a small fraction of one ETH), this early division floors the effective gas price to `0` whenever the real base fee is < 1 `upc` per gas unit, making the entire fee computation `0 * gasUsed = 0`.

### Finding Description [1](#0-0) 

```go
baseFeeBig := baseFee.BigInt()
// ... comment asserts base fee is always a whole number of upc
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
...
effectiveGasPrice := new(big.Int).Set(baseFeeBig)
gasUsedBig := new(big.Int).SetUint64(gasUsed)
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)
```

`baseFee.BigInt()` returns the raw internal `big.Int` of the `LegacyDec` (i.e., the real base-fee value scaled by `1e18`). The code un-scales it back to a whole-number `upc` amount by dividing by `1e18` **before** multiplying by `gasUsed`. This is precisely the anti-pattern flagged in the external report: division performed ahead of a later multiplication causes needless truncation.

The code's inline comment assumes "the base fee is always a whole number of upc -- no fractional upc exists." That assumption is not something this function enforces or verifies; `baseFee` comes from `k.feemarketKeeper.GetBaseFee(sdkCtx)` [2](#0-1) , an EIP-1559-style fee market that is designed to move the base fee smoothly in fractional Dec increments block-to-block based on gas-usage elasticity. If the realistic operating base fee per gas unit is meant to be a small fraction of a whole `upc` (as is typical for EVM chains, where gas price is denominated far below the native coin's base unit), this truncation floors `baseFeeBig` to `0`, making `effectiveGasPrice = 0` and therefore `gasCost = 0`.

This function feeds directly into `DeductGasFeesFromReceipt`, which is the mechanism used to charge gas fees to a UEA/CEA recipient after a module-originated `DerivedEVMCall` executes a `UniversalPayload` on Push Chain: [3](#0-2) . This is on the ordinary universal-execution path triggered by any unprivileged user's inbound payload — there is no privileged actor involved.

### Impact Explanation
If `gasCost` truncates to `0`, `DeductGasFeesFromReceipt` short-circuits (`if gasCost.Sign() <= 0 { return nil }`) and skips `DeductAndBurnFees` entirely [4](#0-3) . That means users get their `UniversalPayload` EVM execution for free — no gas fee is deducted or burned from their account regardless of how much gas was actually consumed on Push Chain. This corrupts gas-fee accounting and removes the anti-spam economic backstop for gasless/universal-execution transactions, allowing unlimited free EVM execution through the module's `DerivedEVMCall` path and permanent loss of protocol fee revenue.

### Likelihood Explanation
This is not an edge case — it is the expected steady-state whenever the real base fee (in `upc`, the smallest denomination) is less than 1 whole `upc` per unit of gas, which is the typical regime for any EVM-style fee market denominated in the chain's smallest unit. Every ordinary user transaction that goes through `DeductGasFeesFromReceipt` is affected identically and deterministically.

### Recommendation
Restructure `CalculateGasCost` to multiply before dividing, and perform the `1e18` unscaling only once, at the end, on the product:
```go
baseFeeRaw := baseFee.BigInt() // still 1e18-scaled
gasUsedBig := new(big.Int).SetUint64(gasUsed)
scaledCost := new(big.Int).Mul(baseFeeRaw, gasUsedBig)
gasCost := new(big.Int).Div(scaledCost, big.NewInt(1e18))
```
This preserves fractional-`upc`-per-gas precision across the full `gasUsed` multiplier instead of truncating it away per-unit before scaling by gas usage. Additionally, the `maxFeePerGas.Cmp(baseFeeBig)` validation check should use the un-truncated (or correctly rounded-up) base fee, not a value that can silently become `0`.

### Proof of Concept
1. Feemarket sets `baseFee` (a `LegacyDec`) to a realistic sub-1-`upc` gas price, e.g. real value `0.0000001` upc/gas (internal `big.Int` representation `100000000000` after `1e18` scaling).
2. A user submits a `UniversalPayload` message with `maxFeePerGas` set to any nonzero value and it gets executed through `DerivedEVMCall`, consuming, e.g., `500000` gas.
3. `CalculateGasCost` computes `baseFeeBig.Div(baseFeeBig, 1e18)` → `0` (since `100000000000 / 1e18 = 0`).
4. `effectiveGasPrice = 0`, `gasCost = 0 * 500000 = 0`.
5. `DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns without deducting/burning any fee from the recipient, even though real gas usage and a nonzero base fee existed.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
