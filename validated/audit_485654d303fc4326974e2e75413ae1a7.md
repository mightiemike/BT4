### Title
Malformed PoX-4 `signer` buffer collapses distinct stackers into a single unsignable "zero-key" signer, corrupting the Nakamoto reward-set signing weight - (File: stackslib/src/chainstate/nakamoto/signer_set.rs)

### Summary
`RawRewardSetEntry::from_pox_4_tuple` parses the `signer` field returned from `.pox-4`'s `get-reward-set-pox-address`. Because Clarity's `(buff 33)` type only enforces a *maximum* length, a stacker can register with a `signer-key` shorter than 33 bytes. The code explicitly acknowledges this ("`(buff 33) only enforces max size, not min size`") but instead of rejecting the entry, it silently substitutes an all-zero 33-byte key for *any* non-33-byte buffer, exactly mirroring the reported anti-pattern of substituting a benign-looking default (`address(0x0)`) instead of failing loudly.

Any unprivileged stacker calling `stack-stx`/`stack-extend`/`stack-aggregation-commit` on `.pox-4` can supply a `signer-key` argument that is shorter than 33 bytes (e.g. a 1-byte or empty buffer). Clarity's type checker accepts this because `(buff 33)` bounds the *maximum*, not exact, length. When the node later builds the reward set for the next cycle via `NakamotoSigners::make_signer_set` / `pox_5_make_signer_set` (which key a `BTreeMap` by `signing_key`), every stacker who submits such a malformed key is coalesced under the identical `[0u8; 33]` "signing key" — an invalid point that is not a genuine compressed secp256k1 public key and for which no private key exists.

This breaks the equality that the report's bug class targets: "signer weight below threshold or from the wrong set." The weight assigned to the reward-set entry with `signing_key = [0;33]` is real (backed by locked STX) but is not attributable to any actual signer who can produce a valid signature over it. Multiple, unrelated, and mutually distrusting stackers get merged into one bogus "signer," and their combined weight becomes part of `RewardSet::total_signing_weight()` used by `NakamotoBlockHeader::compute_voting_weight_threshold()` and `verify_signer_signatures()` ( [2](#0-1) ) to compute the 70% approval threshold. Because nobody can ever sign as `[0;33]`, this portion of `total_weight` is permanently unreachable, silently raising the effective bar the legitimate signer set must clear (or, in reward-set/weight-based bookkeeping elsewhere, is dropped/merged in a way the code never anticipated for two unrelated stackers).

### Impact Explanation
This is a minority-triggerable divergence in the reward-set/weight computation: a single unprivileged stacker (no special key, no majority needed) can register a syntactically-valid but semantically-bogus signer identity that the protocol treats as a legitimate member of the reward set with real voting weight, backed by real locked STX, that can never be exercised. This falls squarely in the allowed "signer weight below threshold or from the wrong set" class — it corrupts the reward set that all nodes/signers compute independently from the same chain state, and depending on how much weight accumulates under the phantom zero-key, it can push the required signing threshold out of reach for the legitimately-keyed signers, causing tenures to stall (temporary tip disagreement / signing deadlock) until the affected reward cycle rolls over. It does not, by itself, achieve outright double-payment or an irreversible fork, so it is best characterized as **High**: a minority-triggerable weight-computation divergence bounded to a reward cycle.

### Likelihood Explanation
Likelihood is high in terms of triggerability (any stacker can pass a short buffer to a public, unprivileged Clarity call — no special access needed), but the corrupting effect only matters if the accumulated "zero-key" weight is large enough to matter relative to the 70% threshold, so real-world severity depends on economic scale of the malformed registration(s).

### Recommendation
In `RawRewardSetEntry::from_pox_4_tuple` (and the analogous PoX-5 raw-entry parsing path), treat a `signer` buffer whose length is not exactly `SIGNERS_PK_LEN` (33) as a hard parse error (`ChainstateError::Expects(...)`) rather than silently defaulting to `[0u8; SIGNERS_PK_LEN]`. This is consistent with how `RocketBase.getContractAddress()` in the referenced report requires the value to be genuinely present rather than allowing an implicit, indistinguishable default to enter downstream logic.

### Proof of Concept
1. An unprivileged account calls `.pox-4`'s `stack-stx` (or `stack-extend`) supplying a `signer-key` argument of length < 33 bytes (e.g. `0x00` or an empty buffer) — the Clarity type-checker accepts this since `(buff 33)` only bounds the maximum length.
2. At the next reward-cycle boundary, `StacksChainState::get_reward_addresses_pox_4` → `RawRewardSetEntry::from_pox_4_tuple` reads this entry; because `signer.len() != 33`, `pk_bytes` becomes `[0u8; 33]` ( [3](#0-2) ).
3. `StacksChainState::make_signer_set` ( [4](#0-3) ) inserts/accumulates this entry's `amount_stacked` under key `[0;33]` in a `BTreeMap`, merging it with any other stacker who (deliberately or accidentally) also submitted a malformed key.
4. The resulting `NakamotoSignerEntry{ signing_key: [0;33], weight, .. }` is included in the `RewardSet` used by `verify_signer_signatures`/`compute_voting_weight_threshold`, contributing to `total_weight` without ever being able to contribute `total_weight_signed`, since no signature can ever recover to public key `[0;33]`.

    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
    }
