### Title
Unbounded gzip decompression of user-supplied deprecated contract program allows memory-exhaustion DoS via decompression bomb - ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
The Starknet JSON-RPC gateway function `decompress_program` decompresses a user-supplied, base64-encoded gzip blob (the Cairo0 `program` field of a broadcasted Declare V0/V1 transaction) into an unbounded, dynamically-growing `Vec<u8>` with no size limit or time limit, unlike the equivalent decompression helpers used elsewhere in the codebase.

### Finding Description
`decompress_program` in `crates/apollo_rpc/src/v0_8/api/mod.rs` decodes the base64 string and pipes it through `flate2::bufread::GzDecoder`, reading to completion via `read_to_end` into an unconstrained `Vec<u8>`: [1](#0-0) 

The code explicitly acknowledges the missing protection with `// TODO(dan): add time and size limits.` at line 677. This is invoked from `user_deprecated_contract_class_to_sn_api`, which converts a user-supplied, RPC-broadcasted `DeprecatedContractClass.compressed_program` field into a `Program` for transaction simulation/fee estimation: [2](#0-1) 

This contrasts with every other decompression path in the codebase, which enforces explicit size bounds:
- `starknet_api::compression_utils::decode_and_decompress_with_size_limit`, which caps decompressed output via `.take(max_size + 1)` before reading: [3](#0-2) 
- `apollo_protobuf` class conversion, which bounds Cairo0 program decompression to 4MB: [4](#0-3) 
- `apollo_storage::compression_utils::decompress`, bounded by `MAX_DECOMPRESSED_SIZE` (256MB): [5](#0-4) 

`decompress_program` has no equivalent bound, meaning a small (KB-scale) gzip payload crafted as a decompression bomb can expand to gigabytes in memory before any size check is applied.

### Impact Explanation
An unauthenticated/unprivileged RPC caller can submit a `BroadcastedDeclareTransaction` (V0/V1, with a deprecated Cairo0 class) to `starknet_estimateFee` or `starknet_simulateTransactions`, embedding a crafted gzip-bomb as the `program` field. Processing this request causes the node to attempt to allocate an arbitrarily large buffer in memory, which can exhaust available memory and crash or stall the RPC/execution process, denying service to the sequencer node's RPC layer (and potentially to shared execution resources) — a concrete availability impact consistent with CWE-409/decompression-bomb DoS class described in the reference advisory.

### Likelihood Explanation
Likelihood is high: the code path is reachable directly by any external, unauthenticated caller of the public JSON-RPC `estimateFee`/`simulateTransactions` endpoints with a single crafted request containing a Declare V0/V1 transaction; no special privileges, prior state, or on-chain funds are required, and the vulnerable function is explicitly unguarded (per its own TODO comment).

### Recommendation
Apply the same pattern already used elsewhere in the codebase: bound decompression using a `.take(max_size)` reader wrapper (as in `starknet_api::compression_utils::decompress_with_size_limit`) with a conservative, configurable maximum (e.g., matching `MAX_CAIRO0_PROGRAM_SIZE` = 4MB used in `apollo_protobuf`), and reject/fail the RPC request if the limit is exceeded, before allowing the request into transaction simulation/fee estimation.

### Proof of Concept
1. Craft a gzip stream containing megabytes of a repeated byte (e.g., all zeros), so that a small (few-KB) compressed payload decompresses to several GB.
2. Base64-encode this compressed blob and place it as the `program` field of a `DeprecatedContractClass` inside a `BroadcastedDeclareTransaction` (V0 or V1).
3. Submit this transaction via `starknet_estimateFee` or `starknet_simulateTransactions` to the node's RPC endpoint.
4. Observe `decompress_program` (crates/apollo_rpc/src/v0_8/api/mod.rs:671-682) attempt to fully materialize the decompressed data with `read_to_end`, consuming excessive memory and potentially crashing or stalling the node process, denying RPC service.

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}

pub(crate) const MAX_DECOMPRESSED_SIZE: usize = 1 << 28; // 256 MB
// The compression level to use. Higher levels are slower but compress better.
const COMPRESSION_LEVEL: i32 = zstd::DEFAULT_COMPRESSION_LEVEL;

/// Returns the compressed data in a vector.
///
/// # Arguments
/// * data - bytes to compress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn compress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::compress(data, COMPRESSION_LEVEL)
}

/// Serialized and then compress object.
///
/// # Arguments
/// * object - the object to serialize and compress.
///
/// # Errors
/// Returns [`StorageSerdeError`] if any error is encountered in the serialization or compression.
pub fn serialize_and_compress(object: &impl StorageSerde) -> Result<Vec<u8>, StorageSerdeError> {
    let mut buf = Vec::new();
    object.serialize_into(&mut buf)?;
    Ok(compress(buf.as_slice())?)
}

/// Decompress data and returns it as bytes in a vector.
///
/// # Arguments
/// * data - bytes to decompress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn decompress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::decompress(data, MAX_DECOMPRESSED_SIZE)
}
