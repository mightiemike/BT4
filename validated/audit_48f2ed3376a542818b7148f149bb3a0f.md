### Title
Unsanitized `shop` query parameter reflected into CSP/Link response headers - ([File: packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/render-app-bridge.ts])

### Summary
In `shopify-app-remix`, the anonymous, unauthenticated `App Bridge` bootstrap response (`renderAppBridge`) passes the raw `shop` query-string value straight into `addDocumentResponseHeaders`, which builds security-sensitive headers (Content-Security-Policy `frame-ancestors` and the `Link` preconnect header) from it, without first validating/sanitizing it with `sanitizeShop`. [1](#0-0) 

### Finding Description
`renderAppBridge` is reached for anonymous/unauthenticated requests to the admin authentication entry point whenever the shop/host params are missing or invalid (via `validateShopAndHostParams` → `renderAppBridgeOrError`/`renderAppBridge`), and it is invoked with the raw `request.url` query string. [2](#0-1) 

In the `shopify-app-remix` implementation, the `shop` value is taken directly from `new URL(request.url).searchParams.get('shop')` and fed unsanitized into `addDocumentResponseHeaders`: [3](#0-2) 

This is the exact bug class described in the external report: user-controlled input (here the `shop` param, analogous to the unvalidated `tokenSymbol`) is stored/used and later reflected into a client-facing surface (here, HTTP response headers that control iframe embedding policy) without validation.

Critically, the sibling package `shopify-app-react-router` implements the identical function but explicitly sanitizes the shop value with `api.utils.sanitizeShop(...)` before building headers, with a code comment and dedicated regression test stating this exact vulnerability was previously present and fixed: [4](#0-3) [5](#0-4) 

The `shopify-app-remix` package's `render-app-bridge.ts` was not updated with the same sanitization, leaving the vulnerability unpatched in that package.

### Impact Explanation
`shop` is attacker-controlled (anonymous GET request, no authentication required to reach this code path). If `addDocumentResponseHeaders` inserts the raw shop value into the `Content-Security-Policy: frame-ancestors` directive and/or `Link` preconnect header (as it demonstrably does in the parallel, already-patched `shopify-app-react-router` package, per its regression test asserting the CSP must not contain an attacker-controlled value like `evil.com`), an attacker can supply `?shop=evil.com` and cause the app's own bootstrap page to whitelist an attacker-controlled origin in `frame-ancestors`. This can enable clickjacking/UI-redress attacks against the App Bridge bootstrap page, and generically demonstrates unsanitized user input flowing into security-relevant HTTP headers — the same "unvalidated input reflected to a client surface" root cause as the reported bug class.

### Likelihood Explanation
High for triggering: the endpoint is reachable by any anonymous, unauthenticated HTTP request (no session/HMAC needed) whenever `shop`/`host` params are missing or fail `sanitizeShop`/`sanitizeHost` validation in `validateShopAndHostParams`, which is a normal, easily reachable code path for any embedded remix-based Shopify app using `authenticate.admin`. The only gating factor is confirming that `addDocumentResponseHeaders` in the remix package echoes the shop value into headers the same way the react-router counterpart does — this could not be independently verified because the contents of `packages/apps/shopify-app-remix/src/server/authenticate/helpers/add-response-headers.ts` were not retrievable via the available search/read tools (index size limits). Given the identical function name, identical call signature, and shared architecture between the react-router and remix packages, it is highly likely the implementations are equivalent, but this should be confirmed by reading that file directly in a full checkout.

### Recommendation
In `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/render-app-bridge.ts`, sanitize the `shop` query parameter with `api.utils.sanitizeShop(...)` (as already done in `shopify-app-react-router`) before passing it to `addDocumentResponseHeaders`, and add a regression test mirroring the one in `shopify-app-react-router`'s `doc-request-path.test.ts` to ensure an attacker-controlled `shop` value never appears in the CSP `frame-ancestors` directive or `Link` header.

### Proof of Concept
1. As an anonymous user, send `GET {APP_URL}?shop=evil.com&host=<validBase64Host>` to an app built with `shopify-app-remix` using `shopify.authenticate.admin`.
2. Because `shop=evil.com` fails `sanitizeShop` inside `validateShopAndHostParams`, the request is routed to `renderAppBridge`. [2](#0-1) 
3. `renderAppBridge` reads the raw, unsanitized `shop` value directly from the URL and forwards it to `addDocumentResponseHeaders`. [3](#0-2) 
4. Inspect the response's `Content-Security-Policy` and `Link` headers for the literal string `evil.com` — presence of it (as demonstrated to be a real, previously-existing issue by the react-router regression test) confirms the analog vulnerability.

import {redirect} from '@remix-run/server-runtime';

import {BasicParams} from '../../../types';

export function validateShopAndHostParams(
  params: BasicParams,
  request: Request,
) {
  const {api, config, logger} = params;

  if (config.isEmbeddedApp) {
    const url = new URL(request.url);
    const shop = api.utils.sanitizeShop(url.searchParams.get('shop')!);
    if (!shop) {
      logger.debug('Missing or invalid shop, redirecting to login path', {
        shop,
      });
      throw redirectToLoginPath(request, params);
    }

    const host = api.utils.sanitizeHost(url.searchParams.get('host')!);
    if (!host) {
      logger.debug('Invalid host, redirecting to login path', {
        shop,
        host: url.searchParams.get('host'),
      });
      throw redirectToLoginPath(request, params);
    }
  }
}
