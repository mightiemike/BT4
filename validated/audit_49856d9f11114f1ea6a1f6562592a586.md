### Title
Unchecked `undefined` from stale shop→session index causes crash in `AppInstallations` uninstall/reinstall flow (KV session storage) - (File: `packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`)

### Summary
This is structurally the same bug class as the kaia commit: a secondary index (kaia's gov/vote block-number index; here, `KVSessionStorage`'s per-shop list of session ids) can drift out of sync with the primary data store, and the code that resolves entries from the index dereferences the result without a nil/undefined check.

### Finding Description
`KVSessionStorage.findSessionsByShop` at [2](#0-1)  maintains a `shop:<shop>` index of session ids (`addShopIds`/`removeShopIds`, lines 75-88) that is a separate KV entry from the actual session records. `findSessionsByShop` reads that index and, for every id in it, calls `this.loadSession(id)` and forces the result to non-`undefined` with `!`:
```
return Promise.all(
  sessionIds.map(async (id) => (await this.loadSession(id))!),
);
```
If the individual session key has expired, was deleted independently of the shop index (e.g. partial failure between `storeSession`/`deleteSession` and the corresponding `addShopIds`/`removeShopIds` call, TTL eviction, or manual KV maintenance), `loadSession` returns `undefined`, and that `undefined` is placed directly into the returned array as if it were a `Session`. Because `!` is a TypeScript-only assertion, there is no runtime error at this point — the array silently contains `undefined` entries, exactly mirroring the "index and header DB diverged" scenario in the kaia report.

Downstream, `AppInstallations.includes` and `AppInstallations.delete` in `packages/apps/shopify-app-express/src/app-installations.ts` (lines 22-41) consume this array and immediately access `session.accessToken` and `session.id` on every element without a null check [1](#0-0) . Dereferencing `.accessToken`/`.id` on an `undefined` array element throws a `TypeError`, crashing the request handler synchronously — the direct analog of kaia's nil-pointer panic on a divergent index.

### Impact Explanation
`AppInstallations.delete`/`includes` are invoked from the app-installed/app-uninstalled webhook processing path and OAuth begin/callback flow in `shopify-app-express` — both are reachable from unauthenticated inbound requests (webhooks are HMAC-verified but externally triggered, and shop lookups happen pre-auth during OAuth). A crash here is a denial-of-service of an auth-adjacent handler: repeated webhook delivery against a shop whose KV index has drifted (e.g., due to TTL differences between session and index entries, which KV storage is prone to) would reliably crash the handler on every retry, similar to the "restart loop" characterization in the original kaia report.

### Likelihood Explanation
Likelihood is contingent on the KV session index actually drifting from live session records — this can happen through independent expiry/eviction of the session key vs. the shop-index key, or through non-atomic multi-key writes to KV (there is no transaction between `storeSession`/`namespace.put` and `addShopIds`). This is a plausible but not certain condition; I could not find code enforcing atomicity between these two KV writes, which supports the likelihood but I did not find a concrete external trigger guaranteeing this divergence (e.g., no explicit TTL settings visible in the shown code), so this should be treated as a real but conditional weakness rather than a trivially exploitable one.

### Recommendation
In `KVSessionStorage.findSessionsByShop` (`packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`), filter out `undefined` results from `loadSession` instead of force-unwrapping them, e.g. resolve all promises and then `.filter((s): s is Session => s !== undefined)`. Defensively, `AppInstallations.includes`/`delete` in `shopify-app-express/src/app-installations.ts` should also guard against non-`Session` falsy entries before accessing `.accessToken`/`.id`, consistent with how other storage adapters (e.g., `MemorySessionStorage.findSessionsByShop`) never produce sparse/undefined entries in the first place.

### Proof of Concept
1. Configure `shopify-app-express` with `KVSessionStorage`.
2. Store a session for `shop.myshopify.com`, so `shop:shop.myshopify.com` index in KV contains its id and the session key exists.
3. Independently expire/delete the session's own KV key (e.g., TTL expiry) while leaving the shop-index key intact — simulating index/data divergence, analogous to a header no longer being canonical in kaia.
4. Trigger the `app/uninstalled` webhook (or any OAuth path invoking `AppInstallations.delete`/`includes`) for that shop.
5. `findSessionsByShop` returns an array containing `undefined`; `AppInstallations.delete`/`includes` then throws a `TypeError` when accessing `.accessToken`/`.id`, crashing the handler.

  public async findSessionsByShop(shop: string): Promise<Session[]> {
    const sessionIds = await this.namespace.get<string[]>(
      this.getShopSessionIdsKey(shop),
      {type: 'json'},
    );

    if (!sessionIds) {
      return [];
