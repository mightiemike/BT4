### Title
Phantom Account Registration Enables Griefing of Legitimate Relayers via Missing On-Chain Existence Check — (`runtime/near-wallet-contract/implementation/address-registrar/src/lib.rs`)

---

### Summary

The `register` function in the address registrar contract accepts any syntactically valid named `account_id` and stores the `address → account_id` mapping without verifying that the account actually exists on-chain. An unprivileged attacker can pay the small storage deposit and register a non-existent ("phantom") account. When a legitimate relayer subsequently routes a user's ETH-style transaction to the corresponding eth-implicit address (correctly, because the named account does not exist), the wallet contract's `address_check_callback` sees a non-`None` result from `lookup`, concludes the relayer is faulty, and deletes the relayer's access key from the wallet contract.

---

### Finding Description

**Missing guard in `register`:** [1](#0-0) 

The only guards present are:
1. Reject eth-implicit accounts (line 42).
2. Require sufficient deposit (line 54).

There is no cross-contract call or any other mechanism to verify that `account_id` is a live account on-chain. Any syntactically valid NEAR account ID (e.g., `phantom.near`) is accepted and inserted into the `LookupMap` at line 69. [2](#0-1) 

**Downstream effect in `address_check_callback`:**

The wallet contract calls `registrar.lookup(address)` and branches solely on whether the result is `Some` or `None`: [3](#0-2) 

If `maybe_account_id.is_some()` and the signer is the wallet contract account (the normal relayer case, where the relayer holds a function-call access key on the wallet contract), `create_ban_relayer_promise` is called, which deletes the relayer's public key: [4](#0-3) 

The wallet contract never verifies that the returned `AccountId` actually corresponds to a live account before acting on it.

---

### Impact Explanation

An attacker who registers `phantom.near` (non-existent) causes address `X = keccak256("phantom.near")[12:32]` to be permanently mapped in the registrar. Any relayer that correctly routes a user transaction to the eth-implicit account `0x...X` (the right behavior, since `phantom.near` does not exist) will have its access key deleted from the user's wallet contract. The user's transaction also fails. Because the nonce is not incremented in this branch (line 178), the user can retry, but every subsequent honest relayer that attempts to route to `0x...X` will also be banned until the phantom registration is somehow superseded (which is impossible once the slot is occupied, due to the collision guard at lines 73–84). [5](#0-4) 

This constitutes:
- **Unauthorized key deletion** from the wallet contract (the relayer's access key is removed without the wallet owner's intent).
- **Permanent contract execution flow breakage** for any user whose intended recipient address was pre-poisoned by the attacker.

**Correction of the question's framing**: There is no trie corruption and no misdirected transfer receipt. The trie is correctly updated with the phantom mapping. The wallet contract does not forward the transfer to the phantom account; it bans the relayer or returns an error. The real impact is unauthorized relayer key deletion and permanent transaction routing failure for poisoned addresses.

---

### Likelihood Explanation

- The attacker is fully unprivileged; only a standard `register` call with a small storage deposit is required.
- The deposit is on the order of hundreds of yoctoNEAR (storage cost for ~30 bytes), making mass poisoning cheap.
- Once a slot is occupied, the collision guard prevents any correction: the phantom mapping is permanent.
- The attack is silent and requires no interaction with the victim wallet contract or relayer beforehand.

---

### Recommendation

Add an on-chain existence check before inserting the mapping. Since NEAR smart contracts cannot synchronously query account existence, `register` must be restructured as a two-step async call:

1. Issue a cross-contract call (e.g., `Promise::new(account_id.clone()).function_call("...", ...)` or a balance query) to confirm the account exists.
2. In the callback, only insert the mapping if the account was confirmed live; refund the deposit otherwise.

Alternatively, restrict `register` so that only the account being registered can call it (i.e., require `env::predecessor_account_id() == account_id`), which implicitly proves the account exists and controls the registration.

---

#[tokio::test]
async fn test_phantom_account_registration_griefs_relayer() -> anyhow::Result<()> {
    let TestContext {
        worker,
        mut wallet_contract,
        wallet_sk,
        address_registrar,
        ..
    } = TestContext::new().await?;

    // 1. Attacker registers a non-existent account.
    //    "phantom-does-not-exist.near" has never been created on-chain.
    let phantom_id = "phantom-does-not-exist.near";
    let register_output: Option<String> = address_registrar
        .call("register")
        .args_json(serde_json::json!({ "account_id": phantom_id }))
        .max_gas()
        .deposit(NearToken::from_millinear(1))
        .transact()
        .await?
        .json()?;
    // Registration succeeds — no existence check.
    assert!(register_output.is_some(), "phantom account was accepted");

    // 2. Derive the eth-implicit address for the phantom account.
    let phantom_address = {
        let hash = near_sdk::env::keccak256_array(phantom_id.as_bytes());
        let mut addr = [0u8; 20];
        addr.copy_from_slice(&hash[12..32]);
        addr
    };

    // 3. Register a relayer and send a base-token transfer to the phantom address.
    let relayer_pk = wallet_contract.register_relayer(&worker).await?;
    let tx = /* build signed ETH tx targeting phantom_address */;
    let result = wallet_contract
        .rlp_execute(&format!("0x{}", hex::encode(phantom_address)), &tx)
        .await?;

    // 4. The relayer is banned even though it acted correctly.
    assert!(!result.success);
    assert_revoked_key(&wallet_contract.inner, &relayer_pk).await;

    // 5. Confirm the lookup still returns Some (phantom persists).
    let lookup: Option<String> = address_registrar
        .call("lookup")
        .args_json(serde_json::json!({ "address": format!("0x{}", hex::encode(phantom_address)) }))
        .view()
        .await?
        .json()?;
    assert!(lookup.is_some()); // Should be None for a valid registrar — test demonstrates the bug.

    Ok(())
}

    pub fn register(&mut self, account_id: AccountId) -> Option<String> {
        // It is not allowed to register eth-implicit accounts because the purpose
        // of the registry is to allow looking up the named account associated with
        // an address obtained via hashing, but eth-implicit accounts are already
        // parsable as addresses.
        if is_eth_implicit(&account_id) {
            let log_message = format!("Refuse to register eth-implicit account {account_id}");
            env::log_str(&log_message);
            return None;
        }

        // Must store the address and the account id
        let bytes_to_store = 20 + (account_id.len() as u128);
        let required_deposit =
            NearToken::from_yoctonear(env::storage_byte_cost().as_yoctonear() * bytes_to_store);
        let given_deposit = env::attached_deposit();
        // The caller must pay for the storage cost of registering.
        if given_deposit < required_deposit {
            let message = format!(
                "Insufficient deposit to cover storage cost. Given={} Expected={}",
                given_deposit.as_yoctonear(),
                required_deposit.as_yoctonear(),
            );
            env::panic_str(&message);
        }

        let address = account_id_to_address(&account_id);

        match self.addresses.entry(address) {
            Entry::Vacant(entry) => {
                let address = format!("0x{}", hex::encode(address));
                let log_message = format!("Added entry {} -> {}", address, account_id);
                entry.insert(account_id);
                env::log_str(&log_message);
                Some(address)
            }
            Entry::Occupied(entry) => {
                let log_message = format!(
                    "Address collision between {} and {}. Keeping the former.",
                    entry.get(),
                    account_id
                );
                env::log_str(&log_message);
                // Transfer the deposit back to the caller since no storage was updated.
                let refund_promise = env::promise_batch_create(&env::predecessor_account_id());
                env::promise_batch_action_transfer(refund_promise, given_deposit);
                None
            }
        }
    }

fn create_ban_relayer_promise(current_account_id: AccountId) -> Promise {
    let pk = env::signer_account_pk();
    Promise::new(current_account_id).delete_key(pk).function_call_weight(
        "ban_relayer".into(),
        Vec::new(),
        NearToken::from_yoctonear(0),
        Gas::from_tgas(1),
        GasWeight(1),
