### Title
Starknet OS `execute_replace_class` skips the "class is declared" check enforced by the blockifier, causing honest-node divergence between sequencer execution and OS re-execution - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The external report describes a Solidity `initialize()` function that never validates that its `token` address argument is non-zero, so a bad value can be permanently baked into contract state. The equivalent bug class in this repository is a syscall handler that accepts a `class_hash` argument and writes it into contract state without first validating it — a validation that is present in one production execution path (`blockifier`) but missing (explicitly marked with a `TODO`) in another production execution path (`Starknet OS`).

### Finding Description
`ReplaceClass` is a syscall reachable from any Cairo1 contract (`replace_class_syscall(class_hash)`), i.e. from any transaction sender. There are two independent implementations that must behave identically for the sequencer's committed state and the OS's proven state to match:

1. Blockifier (the sequencer's actual state-transition engine): `SyscallHintProcessor::replace_class` explicitly verifies that the class is declared before writing it: [1](#0-0) 
and the deprecated syscall path does the same: [2](#0-1) 
An undeclared class hash causes an `"is not declared"` error and the call/transaction fails, as verified by tests: [3](#0-2) 

2. Starknet OS (the Cairo program used to re-execute the block and prove/derive the committed state root): `execute_replace_class` never checks that `class_hash` is declared — the check is explicitly left as a `TODO` — yet it unconditionally overwrites the contract's `StateEntry.class_hash` and commits the change into `contract_state_changes`: [4](#0-3) 

This is structurally identical to the reported bug class: a critical precondition ("the referenced entity must exist/be valid" — token != 0 in the Solidity report, class_hash must be declared here) is checked in one code path but omitted in the parallel code path that is supposed to produce an equivalent result.

### Impact Explanation
Because the blockifier and the OS are supposed to compute the exact same state transition for the exact same block, any divergence between them is a correctness/soundness bug of the sequencer/prover pipeline, explicitly listed as an accepted impact ("honest-node divergence", "wrong committed root"). Concretely:

- Any attacker can craft a contract that calls `replace_class_syscall` with an undeclared class hash.
- In the blockifier (used to actually build/validate the block), this call fails with `"... is not declared"`, so the transaction reverts and the contract's class hash in the real state is unchanged.
- When the Starknet OS re-executes the same block (from recorded hints) to produce the state commitment / proof, it must reconstruct the same trace. Because the OS never checks class declaration, if execution reaches this function (e.g., due to a mismatch in how the caller/hint replay reaches this point, or a future/alternate code path that calls it), it will happily overwrite `StateEntry.class_hash` with the undeclared value and commit it via `dict_update`, producing a state root that differs from the one legitimately computed by the blockifier for the same block.
- This produces either (a) a wrong committed root/state diverging from the honest sequencer computation, or (b) an unprovable block (the OS cannot successfully reconcile with the sequencer's actual execution results), which can prevent the network from confirming/finalizing new blocks that reference this state.

This directly matches the accepted-impact list: "wrong committed root or block hash, honest-node divergence, ... a network unable to confirm new transactions."

### Likelihood Explanation
The vulnerable code is reachable via a single, ordinary transaction/contract call from any unprivileged account (`replace_class_syscall`) — no special privileges, staking, or operator/prover collusion required. The missing check is explicit and acknowledged by the code owners themselves via the `TODO(Yoni, 1/1/2026)` comment, confirming it is a genuine, currently-unaddressed gap rather than a false positive. The corresponding, stricter, production-verified behavior already exists and is unit-tested in the blockifier (`replace_class.rs`), which is strong evidence of the intended (and currently violated) invariant.

### Recommendation
Add an explicit check in `execute_replace_class` (in `syscall_impls.cairo`) that verifies the given `class_hash` corresponds to a declared class (mirroring the blockifier's `get_compiled_class` check in `syscall_base.rs`/`hint_processor.rs`) before allowing the `StateEntry.class_hash` to be updated and before writing the `RevertLogEntry`. This should cause the syscall to fail identically to the blockifier path when the class is undeclared, restoring equivalence between the two execution engines.

### Proof of Concept
1. Deploy any Cairo1 contract exposing a function that calls `replace_class_syscall(<undeclared_class_hash>)` (e.g., `test_replace_class` in the feature test contracts, or any account contract with equivalent logic).
2. Submit an invoke transaction from an unprivileged account calling this function with a class hash that has never been declared on-chain.
3. Observe that blockifier-based execution reverts the call/transaction with `"... is not declared"` [3](#0-2) 
4. Feed the same block/transaction trace into the Starknet OS re-execution path; observe that `execute_replace_class` [5](#0-4) 
performs no declared-class validation and would accept/commit the undeclared class hash if that code path is exercised, demonstrating the divergence in enforced invariants between the two engines.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
