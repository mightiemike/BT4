### Title
Gas-fee calculation for outbound transactions uses a potentially stale on-chain gas price with no freshness check - (File: x/uexecutor/keeper/gas_fee.go)

### Summary
The `UniversalCore` Solidity contract exposes `timestampObservedAtByChainNamespace(chainNamespace)` [1](#0-0)  — the on-chain equivalent of the Chainlink "timestamp of the latest answer" the external report flags. However, the Go keeper code that consumes the gas price for fee accounting, `GetOutboundTxGasAndFees`, never calls or checks this timestamp view function before using the returned `gasPrice`/`gasFee` values [2](#0-1) .

### Finding Description
The gas price used for outbound-tx fee accounting is written to `UniversalCore` only when `VoteChainMeta` computes a fresh median from validator votes stored within `chainMetaVoteStalenessSeconds` [3](#0-2) . That freshness gate exists purely at *write time* — it filters which votes may update the on-chain value, and if no fresh votes exist for a chain (e.g., all UV RPC connections to that chain go stale, or gas-price polling for that `chain_id` in `universalClient/chains/*/chain_meta_oracle.go` stalls), `VoteChainMeta` simply skips the EVM write and leaves the previously-applied (now arbitrarily old) price sitting in the contract state indefinitely [4](#0-3) .

Critically, at *read time* — when a user's outbound transaction is being processed — `GetOutboundTxGasAndFees` reads `gasToken`, `gasFee`, `gasPrice`, and `gasLimit` straight from the contract call result with zero staleness validation [5](#0-4) , even though the contract itself tracks `timestampObservedAtByChainNamespace` for exactly this purpose. This value is then used to charge the user's gas fee for the outbound and, on completion, to compute the excess-gas refund in `applyGasRefund` (`gasFee - gasFeeUsed`) [6](#0-5) .

### Impact Explanation
If the on-chain gas price for a destination chain becomes stale (external chain RPC outage, congestion, or a spike/drop in real gas prices after the last applied vote) and no sanity check exists at the consumption point, an ordinary user submitting a normal outbound withdrawal is charged a gas fee based on outdated market conditions:
- If the stale price is far **below** current market gas cost, the relayer/validator infrastructure spends more real gas on the destination chain than what was deducted from the user, causing an under-collateralized outbound that can fail to execute or under-fund the relayer, risking the outbound tx getting stuck (funds effectively frozen pending manual intervention) or the protocol absorbing losses without recourse.
- If the stale price is far **above** current market gas cost, ordinary users are overcharged for standard withdrawal operations, which is a direct value loss to unprivileged users through no fault of their own, entirely from ordinary tx submission.

This is reachable by any unprivileged user simply initiating a normal outbound/bridge-out transaction — no privileged or malicious actor is required, satisfying the "ordinary user deposits/default transaction submission paths alone" scope criterion.

### Likelihood Explanation
Likelihood depends on external-chain conditions (RPC outages, oracle polling stalls) rather than an active attacker forcing the state, so this is a passive/latent risk rather than an actively-exploitable attack with a deterministic PoC. The team's own reasoning in the external report (Section 4: "Opening new margin positions... we validate the adequacy of the actual price after a swap... If the oracle price is outdated, inadequate positions can be opened... We will manage this scenario with our emergency shutdown system") mirrors this exactly, and the same class of mitigation (off-chain monitoring / emergency pause) is not visible anywhere in the reachable Go code paths inspected (`gas_fee.go`, `outbound.go`, `chain_meta.go`). I was not able to find any external pause/circuit-breaker mechanism wired into `GetOutboundTxGasAndFees` or `applyGasRefund` within the indexed portion of the codebase, so likelihood cannot be fully bounded — it is plausible this is handled by an off-chain monitoring component (analogous to the emergency pause service mentioned in the report) that sits outside `x/uexecutor` and `universalClient` and was not indexed.

### Recommendation
In `GetOutboundTxGasAndFees` (`x/uexecutor/keeper/gas_fee.go`), additionally call `timestampObservedAtByChainNamespace(chainNamespace)` and compare it against the current block time / a configurable max-staleness threshold (mirroring the `chainMetaVoteStalenessSeconds` constant already used on the write side in `chain_meta.go`). If the observed timestamp exceeds the staleness threshold, either revert the outbound-fee computation (forcing a retry once a fresh vote lands) or fall back to a conservative default gas price, rather than silently using an arbitrarily old value for fee/refund accounting.

### Proof of Concept
Not independently reproducible from the indexed code alone — this is a structural gap (missing check) rather than a state-manipulable exploit. To validate concretely, a background agent with full repo/test access should:
1. In an integration test analogous to `test/integration/uexecutor/vote_chain_meta_test.go`, seed `ChainMetas` with an old `StoredAts` far beyond `chainMetaVoteStalenessSeconds` and no subsequent fresh votes so the EVM-applied price is never refreshed.
2. Call `GetOutboundTxGasAndFees` for that chain and confirm it returns the stale price without error, and that `applyGasRefund`/outbound fee deduction proceeds unconditionally using that value.

func (k Keeper) GetOutboundTxGasAndFees(ctx sdk.Context, prc20 common.Address, gasLimitWithBaseLimit *big.Int) (*GasFeeInfo, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
}

func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return

		return
	}
