**Analysis:**

The premise of the exploit is mathematically incorrect and the described code path does not exist in the confidential-asset production flow.

1. **Group addition is total and identity is a valid operand.** `ristretto255_elgamal::ciphertext_add`/`ciphertext_add_assign` perform plain elliptic-curve point addition on the `left` and `right` components independently [1](#0-0) . Ristretto255 point addition is a complete group law — adding the identity element to any point `P` yields exactly `P` (`P + O = P`), which is the correct algebraic result, not a "divergence." There is no separate/undefined behavior for identity points at the point-addition level; `is_identity` checks elsewhere in the codebase exist for *policy* reasons (e.g. rejecting a zero encryption key so that funds aren't unrecoverable), not because point addition misbehaves when one operand is the identity.

2. **`new_ciphertext_from_bytes` only validates that both 32-byte halves decode to valid Ristretto255 points** [2](#0-1) . The identity element is itself a valid, canonically-encoded Ristretto255 point, so accepting it here is correct behavior, not a bypassed check — there was never an invariant that `right != identity` for a ciphertext to be well-formed (in fact `new_ciphertext_no_randomness` deliberately constructs ciphertexts with `right = identity`, i.e. `r = 0`) [3](#0-2) .

3. **`ciphertext_add_assign` is not used anywhere in the confidential-asset production code.** A repo-wide search shows it only appears inside `ristretto255_elgamal.move` itself and in Move-prover artifacts — it has no call sites in `confidential_asset.move` or `confidential_balance.move`. The actual balance-folding logic in `confidential_balance.move` operates directly on `RistrettoPoint` vectors via `add_mut_base`, `add_assign_pending`, and `add_assign_available_excluding_auditor` [4](#0-3) [5](#0-4) [6](#0-5) , never wrapping values in `ristretto255_elgamal::Ciphertext` or calling `ciphertext_add_assign`/`new_ciphertext_from_bytes`. So the required state ("any protocol calling `ciphertext_add_assign` to fold user-submitted ciphertexts into a stored balance") does not exist on mainnet.

Since the addition operation is correct even when a component equals the identity, and the confidential-asset balance accumulation path never routes through `ciphertext_add_assign`/`new_ciphertext_from_bytes`, there is no state divergence to exploit.

        let right_point = ristretto255::new_point_from_bytes(bytes_right);

                left: left_point.extract<RistrettoPoint>(),
                right: right_point.extract<RistrettoPoint>()
            })
        } else {
            std::option::none<Ciphertext>()
        }
    }
