### Title
Missing "class must be declared" check in Starknet OS `execute_replace_class` allows OS-accepted state transitions that diverge from Blockifier semantics - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Blockifier's `replace_class` syscall handler explicitly requires that the target class hash be declared (and, for the current syscall interface, be a Cairo1 class) before allowing a contract to change its own class hash. The Starknet OS's Cairo re-implementation of the same syscall (`execute_replace_class`, used to re-execute/prove blocks) omits this check entirely — it is marked with an explicit `TODO` and unconditionally writes the caller-supplied `class_hash` into `contract_state_changes`.

### Finding Description
`replace_class` is reachable by any account/contract via a plain `replace_class_syscall` call inside an ordinary invoke transaction — no special privilege required.

In the Blockifier (execution engine used by the sequencer's batcher/gateway to build and validate blocks), the syscall implementation enforces validation before mutating state: [1](#0-0) [2](#0-1) 

Both paths call `get_compiled_class(class_hash)` and propagate an error ("is not declared") if the class hash was never declared — this is exercised by the existing negative-flow test: [3](#0-2) 

By contrast, the Starknet OS's Cairo implementation of the *same* syscall, which independently re-derives/proves the state transition for a produced block, performs no such check: [4](#0-3) 

The comment at line 902 — `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` — confirms the check is known to be missing. The legacy/deprecated syscall path in the OS has the identical omission: [5](#0-4) 

The OS pulls the pre/post state entry via a hint (`%{ GetContractAddressStateEntry %}`), and the class hash written into `contract_state_changes` comes directly from the syscall request (`request.class_hash`) with no Cairo-level assertion binding it to a declared class. This means the arithmetic/dict-update constraints proven by the OS accept *any* felt as a valid new class hash for `contract_state_changes`, whereas the Blockifier's Rust logic would reject (or revert) the same call.

### Impact Explanation
The Starknet OS is the component whose Cairo execution trace is STARK-proven and is meant to be the source of truth verifying that a sequencer's claimed block execution/state transition followed the protocol rules — the same rules the Blockifier enforces when actually building blocks. A missing validation in the OS that exists in the Blockifier is a semantic divergence between the two independently-implemented enforcement points for the identical protocol rule (CWE-20: improper input validation of `class_hash`). Concretely:

- A transaction that legitimately fails/reverts in the Blockifier (undeclared class hash) is not rejected by the OS's `execute_replace_class` constraints, so the OS would happily prove a `contract_state_changes` entry setting a contract's class hash to an undeclared/garbage value.
- Since the OS's replayed state comes from execution-helper-provided hints rather than an independently-verified declared-class table lookup at this specific site, this weakens the End-to-end guarantee that "the proven state transition equals what the Blockifier would have produced," which is the analog of the CVE's "unvalidated privileged input crossing a trust boundary."
- If such a state ever reaches committed state (via a malicious/compromised block-producing/execution-helper path feeding the OS, or a future code path that bypasses the Blockifier's own check), the affected contract permanently points to a non-existent/undeclared class — the contract becomes unusable and any funds held by it are permanently frozen, and it also breaks honest-node re-execution consistency (nodes and the OS would disagree with what "should" be a valid class hash reference).

This matches the accepted analog categories: "Starknet OS re-execution" and "honest-node divergence" causing "wrong committed root" / "permanent freezing of funds."

### Likelihood Explanation
Likelihood is Medium: under the current architecture the Blockifier's own check normally prevents an undeclared class hash from ever being committed by an honest sequencer, so the divergence is not trivially triggerable end-to-end today. However, the bug is a genuine, acknowledged (via TODO) gap in the OS's independent enforcement of a protocol-critical invariant, and it is directly reachable by any unprivileged account issuing a `replace_class` syscall. Any future refactor, alternate execution-helper implementation, or code path that feeds the OS a trace not filtered through the Blockifier's check (e.g., a different execution backend or a bug in hint generation) would allow the divergence to surface with concrete impact (state corruption / frozen contract).

### Recommendation
Add an explicit declared-class check in the OS's `execute_replace_class` (and the deprecated variant) mirroring the Blockifier's `get_compiled_class` check, asserting that `contract_class_changes` (or an equivalent declared-classes structure) contains an entry for `request.class_hash` before permitting the `StateEntry` update, and resolve the `TODO(Yoni, 1/1/2026)` accordingly to keep OS and Blockifier semantics provably identical.

### Proof of Concept
1. Deploy an account/contract `A`.
2. Issue an invoke transaction with `A` calling `replace_class_syscall(undeclared_class_hash)` where `undeclared_class_hash` has never been declared.
3. In the Blockifier (sequencer execution), this call fails with `"... is not declared"` (per `deprecated_syscalls_test.rs:375-392`), so the transaction reverts/rejects.
4. Trace the equivalent syscall segment through the Starknet OS's `execute_replace_class` (`syscall_impls.cairo:881-920`): the Cairo constraints do not require `class_hash` to correspond to any declared class in `contract_class_changes`; the dict-update succeeds unconditionally for any `request.class_hash` value, demonstrating the OS would accept a state transition the Blockifier disallows if such a trace/hint were ever supplied to it.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
