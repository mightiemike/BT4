### Title
Missing check of fee-transfer call success (`execution.failed`) lets a reverted ERC20 fee transfer be treated as a successful fee charge - (File: crates/blockifier/src/transaction/account_transaction.rs)

### Summary
The Ion-Protocol report flags Solidity code that calls `transferFrom` and never checks the boolean "success" return value, allowing a failed transfer to be silently accepted. The sequencer has a structurally identical pattern in its own mandatory fee-transfer flow: `AccountTransaction::execute_fee_transfer` invokes the fee token's `transfer` entry point but calls the plain `execute` API instead of `non_reverting_execute`, so a reverted/failed Cairo execution of the transfer is never turned into an error.

### Finding Description
`AccountTransaction::execute_fee_transfer` builds a `CallEntryPoint` for `TRANSFER_ENTRY_POINT_NAME` on the fee token contract and executes it with: [1](#0-0) 
This uses `CallEntryPoint::execute`, which returns `Ok(CallInfo)` even when the callee panicked/reverted (`call_info.execution.failed == true`); it only turns into an `Err` for outer-level VM/pre-execution errors, not Cairo1 logical failures: [2](#0-1) 

By contrast, every other top-level entry-point call in the transaction flow (the account's own `__execute__`, and L1 handler execution) explicitly uses `non_reverting_execute`, which checks `call_info.execution.failed` and converts a failed call into an `Err`: [3](#0-2) [4](#0-3) [5](#0-4) 

`execute_fee_transfer`'s result is only checked with `.map_err` for VM/pre-execution errors from `.execute()` itself — the `success`/`failed` semantics of the token contract's own execution (the Cairo analogue of checking `transferFrom`'s boolean return) is never inspected: [6](#0-5) 

`handle_fee`, which calls `execute_fee_transfer`, simply wraps whatever `CallInfo` comes back into `Some(fee_transfer_call_info)` regardless of its `failed` flag, and `execute_raw` unconditionally records `final_fee` (the fee computed before the transfer attempt) into the transaction receipt: [7](#0-6) [8](#0-7) 

### Impact Explanation
If the fee-token `transfer` entry point can fail internally without the outer `execute` call becoming a VM/pre-execution `Err` (e.g., a Cairo1 panic/assertion failure inside the fee token contract, or an entry-point-not-found/failure path that `execute_entry_point_call_wrapper` converts into a normal `Ok(CallInfo{failed:true,...})`), the blockifier will still record the transaction as having successfully paid `final_fee`, produce a `fee_transfer_call_info` with `failed = true` that is embedded into the committed transaction receipt, and proceed to commit the block as if the sequencer was actually paid. This can result in the sequencer/network under-collecting fees for transactions whose fee-transfer execution logically failed, and — because `execute()` (unlike `non_reverting_execute`) does not force the caller to discard the callee's side effects — any partial state changes made before the panic in the fee-token contract are not guaranteed to be rolled back at this call site the way they are for every other top-level call. This is reachable purely by an ordinary account submitting a transaction; no privileged access is required.

### Likelihood Explanation
The path is reached on essentially every fee-charging transaction, since `handle_fee`/`execute_fee_transfer` runs whenever `charge_fee` is enabled and the fee is non-zero. Note, however, that in the current codebase the fee-token contract (STRK/ETH ERC20) is a fixed, network-controlled contract expected to revert cleanly on insufficient balance rather than return `false`, which is the reason this divergence from the `non_reverting_execute` pattern used everywhere else has apparently gone unnoticed; I was not able to fully verify within the available context whether there exists a code path (e.g. gas-exhaustion mid-transfer, `ENTRYPOINT_NOT_FOUND` handling in `execute_entry_point_call_wrapper`, or a reverts-enabled edge case) that produces `Ok(CallInfo{failed:true})` from `execute()` for the fee-transfer call in practice. This uncertainty should be resolved by exercising `execute_fee_transfer` with a mock fee token that intentionally reverts to observe whether the resulting `TransactionExecutionInfo`/committed receipt incorrectly reports the fee as paid.

### Recommendation
Change `execute_fee_transfer` in `crates/blockifier/src/transaction/account_transaction.rs` to call `fee_transfer_call.non_reverting_execute(...)` (matching the pattern used by `InvokeTransaction::run_execute` and `L1HandlerTransaction::run_execute`) instead of the plain `.execute(...)`, so that a failed/reverted fee-transfer call is surfaced as a `TransactionFeeError`/`TransactionExecutionError` rather than being silently treated as a successful, fee-collected `CallInfo`.

### Proof of Concept
Not independently reproduced; this analysis is based on static code inspection only. A concrete PoC would require constructing/mocking a fee-token class whose `transfer` implementation causes `execute_entry_point_call_wrapper` to return `Ok(CallInfo{ execution: CallExecution { failed: true, .. }, .. })` for the top-level call (e.g., via the `EntryPointNotFound`/`InsufficientEntryPointGas` "soft-fail" path in `execute_entry_point_call_wrapper`, lines 77-118 of `crates/blockifier/src/execution/execution_utils.rs`), invoking `AccountTransaction::execute_raw` with that fee token, and confirming that `TransactionExecutionInfo.fee_transfer_call_info.execution.failed == true` while `TransactionExecutionInfo.receipt.fee` is still non-zero and no `Err` is propagated.

    fn execute_fee_transfer(
        state: &mut dyn State,
        tx_context: Arc<TransactionContext>,
        actual_fee: Fee,
    ) -> TransactionExecutionResult<CallInfo> {
        // The least significant 128 bits of the amount transferred.
        let lsb_amount = Felt::from(actual_fee.0);
        // The most significant 128 bits of the amount transferred.
        let msb_amount = Felt::ZERO;

        let TransactionContext { block_context, tx_info } = tx_context.as_ref();
        let storage_address = tx_context.fee_token_address();
        // The fee contains the cost of running this transfer, and the token contract is
        // well known to the sequencer, so there is no need to limit its run.
        let mut remaining_gas_for_fee_transfer =
            block_context.versioned_constants.os_constants.gas_costs.base.default_initial_gas_cost;
        let fee_transfer_call = CallEntryPoint {
            class_hash: None,
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector_from_name(constants::TRANSFER_ENTRY_POINT_NAME),
            calldata: calldata![
                *block_context.block_info.sequencer_address.0.key(), // Recipient.
                lsb_amount,
                msb_amount
            ],
            storage_address,
            caller_address: tx_info.sender_address(),
            call_type: CallType::Call,

            initial_gas: remaining_gas_for_fee_transfer,
        };
        let mut context = EntryPointExecutionContext::new_invoke(
            tx_context,
            true,
            SierraGasRevertTracker::new(GasAmount(remaining_gas_for_fee_transfer)),
        );

        Ok(fee_transfer_call
            .execute(state, &mut context, &mut remaining_gas_for_fee_transfer)
            .map_err(|error| Box::new(TransactionFeeError::ExecuteFeeTransferError(error)))?)
    }

impl CallEntryPoint {
    pub fn execute(
        mut self,
        state: &mut dyn State,
        context: &mut EntryPointExecutionContext,
        remaining_gas: &mut u64,
    ) -> EntryPointExecutionResult<CallInfo> {
        let tx_context = &context.tx_context;
        let strip_vm_frames = context.versioned_constants().strip_vm_frames_in_sierra_gas;
        let mut decrement_when_dropped = RecursionDepthGuard::new(
            context.current_recursion_depth.clone(),
            context.versioned_constants().max_recursion_depth,
        );
        decrement_when_dropped
            .try_increment_and_check_depth()
            .map_err(|e| e.annotated(TrackedResource::CairoSteps, strip_vm_frames))?;

        // Validate contract is deployed.
        let storage_class_hash = state.get_class_hash_at(self.storage_address).map_err(|e| {
            EntryPointExecutionError::from(e)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames)
        })?;
        if storage_class_hash == ClassHash::default() {
            return Err(EntryPointExecutionError::from(
                PreExecutionError::UninitializedStorageAddress(self.storage_address),
            )
            .annotated(TrackedResource::CairoSteps, strip_vm_frames));
        }

        let class_hash = match self.class_hash {
            Some(class_hash) => class_hash,
            None => storage_class_hash, // If not given, take the storage contract class hash.
        };
        // Hack to prevent version 0 attack on argent accounts.
        if tx_context.tx_info.version() == TransactionVersion::ZERO
            && class_hash
                == ClassHash(
                    Felt::from_hex(FAULTY_CLASS_HASH).expect("A class hash must be a felt."),
                )
        {
            return Err(EntryPointExecutionError::from(PreExecutionError::FraudAttempt)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames));
        }
        // Add class hash to the call, that will appear in the output (call info).
        self.class_hash = Some(class_hash);
        let compiled_class = state.get_compiled_class(class_hash).map_err(|e| {
            EntryPointExecutionError::from(e)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames)
        })?;

        context.revert_infos.0.push(EntryPointRevertInfo::new(
            self.storage_address,
            storage_class_hash,
            context.n_emitted_events,
            context.n_sent_messages_to_l1,
        ));

        // This is the last operation of this function.
        execute_entry_point_call_wrapper(
            self.into_executable(class_hash),
            compiled_class,
            state,
            context,
            remaining_gas,
        )
    }

    /// Similar to `execute`, but returns an error if the outer call is reverted.
    pub fn non_reverting_execute(
        self,
        state: &mut dyn State,
        context: &mut EntryPointExecutionContext,
        remaining_gas: &mut u64,
    ) -> EntryPointExecutionResult<CallInfo> {
        let execution_result = self.execute(state, context, remaining_gas);
        if let Ok(call_info) = &execution_result {
            // Update revert gas tracking (for completeness - value will not be used unless the tx
            // is reverted).
            context.sierra_gas_revert_tracker.update_with_next_remaining_gas(
                call_info.tracked_resource,
                GasAmount(*remaining_gas),
            );
            // If the execution of the outer call failed, revert the transction.
            if call_info.execution.failed {
                return Err(EntryPointExecutionError::ExecutionFailed {
                    error_trace: extract_trailing_cairo1_revert_trace(
                        call_info,
                        Cairo1RevertHeader::Execution,
                    ),
                }
                .annotated(
                    call_info.tracked_resource,
                    context.versioned_constants().strip_vm_frames_in_sierra_gas,
                ));
            }
        }

        execution_result
    }
