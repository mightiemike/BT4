### Title
Reflected XSS via unescaped `dangerouslySetInnerHTML` in `boundary.error` helper - ([File: packages/apps/shopify-app-remix/src/server/boundary/error.tsx](https://github.com/patrichyt/shopify-app-js--020/blob/main/packages/apps/shopify-app-remix/src/server/boundary/error.tsx) and [File: packages/apps/shopify-app-react-router/src/server/boundary/error.tsx](https://github.com/patrichyt/shopify-app-js--020/blob/main/packages/apps/shopify-app-react-router/src/server/boundary/error.tsx))

### Summary
Both `shopify-app-remix` and `shopify-app-react-router` ship an identical `errorBoundary` helper that is documented and intended for merchants' app developers to wire into their route `ErrorBoundary` components. It unconditionally injects the thrown `ErrorResponse`'s `data` field into the DOM using `dangerouslySetInnerHTML` without any escaping, exactly the anti-pattern described in the external report.

### Finding Description
`errorBoundary` checks whether the caught error is a React Router `ErrorResponse`/`ErrorResponseImpl` and, if so, renders its `data` payload raw: [1](#0-0) [2](#0-1) 

This helper is exported and documented as the recommended way for app authors to render errors in `ErrorBoundary`, via `boundary.error(useRouteError())`: [3](#0-2) 

`ErrorResponse.data` is whatever body was passed to a thrown `Response`/`data()`/`json()` anywhere upstream in the route tree (loaders/actions), including ones this same library throws with attacker/upstream-influenced content — for example `handleClientErrorFactory` forwards the raw upstream API response body verbatim into a thrown `Response`: [4](#0-3) 

Because `errorBoundary` treats `error.data` as trusted HTML instead of auto-escaped text (mirroring the exact `AlertView`/`text` prop bug class from the report), any code path — app-authored or library-authored — that places unescaped, request-influenced text into a thrown response's body will have that content executed as HTML/JS in the merchant's embedded admin session when the error boundary renders.

### Impact Explanation
If a request handler in an app using this library throws a `Response`/`data()` whose body reflects any request-controlled value (query params, form fields, or forwarded upstream JSON/text bodies) without HTML-escaping, that value is rendered unescaped into the authenticated admin page via `boundary.error`, resulting in script execution in the context of the merchant's authenticated embedded app session (session/token theft, cross-tenant impact if combined with other app behavior).

### Likelihood Explanation
The library actively documents and encourages the vulnerable pattern (`boundary.error(useRouteError())`) as the standard way to implement `ErrorBoundary` in Shopify embedded apps, and the library itself constructs some of the thrown responses whose bodies get plugged into `dangerouslySetInnerHTML` unmodified. Any app author following the documented pattern while echoing user input in error responses inherits an XSS sink that the library provides, without any indication in the API surface that `data` will be treated as raw HTML.

### Recommendation
Remove `dangerouslySetInnerHTML` from `errorBoundary` in both `packages/apps/shopify-app-remix/src/server/boundary/error.tsx` and `packages/apps/shopify-app-react-router/src/server/boundary/error.tsx`; render `error.data` as plain text (e.g. `<div>{error.data || 'Handling response'}</div>`) so React auto-escapes it, consistent with the referenced fix for `AlertView`.

### Proof of Concept
1. An app author (following the library's documented pattern) has a loader that echoes a query parameter into a thrown error, e.g. `throw new Response(new URL(request.url).searchParams.get('q'), {status: 400})`, and an `ErrorBoundary` calling `boundary.error(useRouteError())`.
2. A merchant/user requests `/app/some-route?q=<img src=x onerror=alert(document.cookie)>`.
3. React Router surfaces this as an `ErrorResponseImpl` whose `data` is the raw query value.
4. `errorBoundary` renders `<div dangerouslySetInnerHTML={{__html: "<img src=x onerror=alert(document.cookie)>"}} />`, executing attacker script inside the merchant's authenticated embedded admin frame.

export function errorBoundary(error: any) {
  if (
    error.constructor.name === 'ErrorResponse' ||
    error.constructor.name === 'ErrorResponseImpl'
  ) {
    return (
      <div
        dangerouslySetInnerHTML={{__html: error.data || 'Handling response'}}
      />
    );
  }

  throw error;
}
