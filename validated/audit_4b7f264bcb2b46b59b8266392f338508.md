### Title
Unchecked ERC20 `transfer` success flag in Starknet OS `charge_fee` allows fee-transfer bypass - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/transaction_impls.cairo`)

### Summary
The Starknet OS `charge_fee` function invokes the fee-token contract's `transfer` entry point via `non_reverting_select_execute_entry_point_func`, but never inspects the returned `(success: felt)` value of that call. Unlike the analogous `run_validate` flow, which explicitly checks `retdata[0] = VALIDATED` after invoking `__validate__`, `charge_fee` discards `retdata_size`/`retdata` entirely.

### Finding Description
`charge_fee` builds a `TransferCallData` and executes the ERC20 `transfer` entry point on the configured fee token contract using `non_reverting_select_execute_entry_point_func`: [1](#0-0) 

That helper only asserts that the call did not revert; it returns `retdata_size`, `retdata`, and `is_deprecated` to the caller for optional inspection: [2](#0-1) 

In `charge_fee`, the return values are dropped completely (the call result is not even bound to a variable), whereas the structurally identical `run_validate` function does check the return value against the expected `VALIDATED` selector: [3](#0-2) [4](#0-3) 

The standard ERC20 fee-token contract (Cairo0 reference implementation) enforces success via `assert_not_zero`/`assert` on allowance and balance checks so that a failed transfer reverts rather than returning `FALSE`: [5](#0-4) 

This means the OS's correctness for fee charging today implicitly relies on the assumption that *every* class hash ever installed at `fee_token_address` follows this "revert-on-failure" convention. Nothing in `charge_fee` itself enforces that a `transfer` call returning `success = FALSE` (a legal ERC20 return per the Cairo ABI, mirrored exactly in the Solidity analog described in the source report) is treated as a failure. This is architecturally the same unchecked-return-value class as the reported `Allo._fundPool` issue: a token "transfer" call's boolean success indicator is ignored, and the surrounding logic (`PoolFunded`/committed fee accounting) proceeds as if funds moved.

### Impact Explanation
If the fee token class (which is a governed system parameter, not attacker-controlled in the base protocol, but is a single point of trust for every transaction in the network) is ever upgraded/replaced with an implementation that returns `success = FALSE` instead of reverting on insufficient balance or blocked transfer (a spec-compliant ERC20 behavior), `charge_fee` would treat the transaction as having successfully paid the fee. Every node that re-executes the block (Starknet OS re-execution / block hash / state commitment) would compute the same (incorrect) state, so this would not cause consensus divergence between honest nodes, but it would let transactions execute without moving actual fee funds, permanently under-crediting the sequencer/treasury balance while validation output still reports collected fees — a concrete loss/permanent misallocation of funds condition once triggered.

### Likelihood Explanation
Likelihood is Medium: it does not require an unprivileged attacker to break funds under the *current* reference ERC20 implementation (which reverts on failure), so it is not exploitable purely from a single unprivileged transaction today. It is a latent unchecked-return-value defect analogous to the source finding: the code path is reachable by every transaction (`charge_fee` runs whenever `max_fee != 0`), and the absence of a defense-in-depth check means any future/alternate fee-token class implementation that follows the letter of the ERC20 `transfer` ABI (returning `FALSE` rather than reverting) silently breaks fee accounting. Given `run_validate` in the same file already implements the correct pattern (checking `retdata[0]`), this omission in `charge_fee` looks like an inconsistency/bug rather than an intentional design choice.

### Recommendation
Mirror the `run_validate` pattern in `charge_fee`: capture `retdata_size`/`retdata` from `non_reverting_select_execute_entry_point_func` and assert `retdata_size == 1 && retdata[0] == TRUE` (or the appropriate success constant) before treating the fee as paid, so that a fee-token implementation returning a falsy success value causes OS-level rejection rather than silent fee-transfer bypass.

### Proof of Concept
1. Deploy/declare a fee-token class whose `transfer` implementation follows the ERC20 ABI but returns `felt` `0` (FALSE) on failure instead of asserting/reverting (this is valid per the ABI signature shown in `crates/apollo_rpc/resources/erc20_fee_contract_class.json:211-226`, which only requires a `success: felt` output).
2. Set this class as `fee_token_address`'s class hash (governance/system configuration action, out of scope for a single transaction but a legitimate protocol-level input to `charge_fee`).
3. Submit a transaction from an account with insufficient fee-token balance.
4. `charge_fee` calls `non_reverting_select_execute_entry_point_func`, which only asserts `is_reverted == 0`; the fee-token contract does not revert, it returns `retdata = [0]`.
5. `charge_fee` returns `()` without inspecting `retdata`, treating the fee as charged; the OS proceeds with the transaction as if the fee was paid, while no fee tokens actually moved. [6](#0-5)

// Charges a fee from the user.
// If max_fee is not 0, validates that the selector matches the entry point of an account contract
// and executes an ERC20 transfer on the behalf of that account contract.
//
// Arguments:
// block_context - a global context that is fixed throughout the block.
// tx_execution_context - The execution context of the transaction that pays the fee.
func charge_fee{
    range_check_ptr,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, tx_execution_context: ExecutionContext*) {
    alloc_locals;

    local tx_info: TxInfo* = tx_execution_context.execution_info.tx_info;
    let max_fee = compute_max_possible_fee(tx_info=tx_info);

    if (max_fee == 0) {
        return ();
    }

    local low_actual_fee;
    %{ LoadActualFee %}
    local calldata: TransferCallData = TransferCallData(
        recipient=block_context.block_info_for_execute.sequencer_address,
        amount=Uint256(low=low_actual_fee, high=0),
    );

    // Verify that the charged amount is not larger than the transaction's max_fee field.
    assert_nn_le(calldata.amount.low, max_fee);

    // TODO(ilya, 01/01/2026): Consider caching the fee_token_class_hash.
    local fee_token_address = block_context.os_global_context.starknet_os_config.fee_token_address;
    let (fee_state_entry: StateEntry*) = dict_read{dict_ptr=contract_state_changes}(
        key=fee_token_address
    );
    let (__fp__, _) = get_fp_and_pc();
    // Use block_info directly from block_context, so that charge_fee will always run in
    // execute-mode rather than validate-mode.
    local execution_context: ExecutionContext = ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=fee_state_entry.class_hash,
        calldata_size=TransferCallData.SIZE,
        calldata=&calldata,
        execution_info=new ExecutionInfo(
            block_info=block_context.block_info_for_execute,
            tx_info=tx_info,
            caller_address=tx_info.account_contract_address,
            contract_address=fee_token_address,
            selector=TRANSFER_ENTRY_POINT_SELECTOR,
        ),
        deprecated_tx_info=tx_execution_context.deprecated_tx_info,
    );

    let remaining_gas = DEFAULT_INITIAL_GAS_COST;
    non_reverting_select_execute_entry_point_func{remaining_gas=remaining_gas}(
        block_context=block_context, execution_context=&execution_context
    );
    return ();
}

func non_reverting_select_execute_entry_point_func{
    range_check_ptr,
    remaining_gas: felt,
    builtin_ptrs: BuiltinPointers*,

    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,

    retdata_size: felt, retdata: felt*, is_deprecated: felt

    let revert_log = init_revert_log();

        revert_log=revert_log
