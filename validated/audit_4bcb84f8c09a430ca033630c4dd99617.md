## Analysis

I found a valid analog to CVE-2019-20016's bug class (unbounded recursion over nested tree structures parsed from an external input, leading to stack exhaustion) in the sequencer's compiled-class hashing code path, which is reachable from a single `declare` transaction.

### Title
Unbounded recursion in bytecode segment-tree hashing (`bytecode_hash_node`/`create_bytecode_segment_structure_inner`) allows a declarer to crash the sequencer via stack exhaustion - (File: crates/starknet_api/src/contract_class/compiled_class_hash.rs)

### Summary
`bytecode_hash_node` recursively walks a `NestedIntList` tree (`bytecode_segment_lengths`) with no depth limit while computing a declared class's compiled-class hash, mirroring the CVE-2019-20016 pattern of unbounded recursion over an attacker-influenced nested structure causing stack consumption.

### Finding Description
Computing a `CasmContractClass`'s compiled-class hash recurses over its `bytecode_segment_lengths` tree with no depth bound: [1](#0-0) 

The `HashableNestedIntList` trait and its `NestedIntList` implementation give no depth cap either: [2](#0-1) 

`hash()`/`hash_inner()` (called for every declare) invoke this recursive walk directly: [3](#0-2) 

This is reachable in-process on the declare path: the `SierraCompiler` component compiles the attacker-submitted Sierra to CASM via an external binary, deserializes the result (including `bytecode_segment_lengths`), and immediately calls `.hash(&HashVersion::V2)` in the sequencer's own process (not the sandboxed subprocess): [4](#0-3) 

The gateway's declare flow triggers this compilation/hash computation for every incoming declare transaction: [5](#0-4) 

The hash is recomputed a second time (again recursively) when validating the declare transaction's CASM hash: [6](#0-5) 

An analogous unguarded recursive walk over the same untrusted structure also exists in the OS/prover hint path used during re-execution/proving of declared classes: [7](#0-6) 

Notably, the codebase is otherwise aware of stack-overflow risk from unbounded/deep recursion and defends against it elsewhere — e.g. entry-point call recursion has an explicit `RecursionDepthGuard`/`max_recursion_depth`, and the native blockifier binary bumps `RUST_MIN_STACK` specifically to accommodate `MAX_ENTRY_POINT_RECURSION_DEPTH`: [8](#0-7) [9](#0-8) 

No equivalent depth guard exists for the `bytecode_segment_lengths` recursion.

### Impact Explanation
A crafted Sierra program that causes the compiler to emit a deeply-nested `bytecode_segment_lengths` tree (e.g. via many chained/nested function segments) will, when hashed in-process by the gateway/sierra-compiler component (and again by any node/prover re-executing or validating the class), consume stack frames proportional to tree depth with no bound. If the recursion depth is sufficient to exceed the process stack, this crashes the sequencer/gateway component processing declare transactions — a network-wide DoS ("a network unable to confirm new transactions") since every full node validating or re-executing the same declared class hits the identical unbounded recursion.

### Likelihood Explanation
The path is reachable by any unprivileged account submitting a single `declare` transaction; no special privileges are required. The compiler's segmentation algorithm itself lives outside this repo (`cairo_lang_starknet_classes`), so the exact depth achievable per unit of bytecode/gas cost cannot be confirmed from this codebase alone, but the sequencer-side hashing code that consumes the resulting structure has no independent depth check, meaning any sufficiently deep structure the compiler is willing to produce will trigger the crash.

### Recommendation
Add an explicit maximum recursion/tree-depth check (and/or convert `bytecode_hash_node`/`create_bytecode_segment_structure_inner` to iterative, explicit-stack traversal) before or during traversal of `NestedIntList`/`bytecode_segment_lengths`, rejecting classes whose segment tree exceeds a safe depth, analogous to the existing `RecursionDepthGuard` used for entry-point call recursion.

### Proof of Concept
1. Craft a Sierra program designed to make the Sierra→CASM compiler emit a `CasmContractClass` with a deeply nested `bytecode_segment_lengths: NestedIntList::Node(vec![NestedIntList::Node(vec![...])])` structure (e.g., via a long chain of nested function/branch segments).
2. Submit it as a `declare` transaction to the gateway.
3. `SierraCompiler::compile` deserializes the compiler's CASM output and calls `executable_class.hash(&HashVersion::V2)` in-process (`crates/apollo_compile_to_casm/src/lib.rs:69`), triggering `bytecode_hash_node`'s unbounded recursion (`crates/starknet_api/src/contract_class/compiled_class_hash.rs:111-131`).
4. If nesting depth is sufficient, the sequencer/gateway process stack overflows and crashes; every other node performing the same hash validation or OS re-execution on the same class hits the identical crash.

pub trait HashableNestedIntList: Clone {
    /// Returns true if this is a leaf node, false if it's a node with children.
    fn is_leaf(&self) -> bool;

    /// Returns the segment length stored in a leaf node. Panics if called on a non-leaf.
    fn get_segment_length(&self) -> usize;

    /// Returns an iterator over child nodes if this is a node, panics if called on a leaf.
    fn iter_children(&self) -> impl Iterator<Item = &Self>;
}

impl HashableNestedIntList for NestedIntList {
    fn is_leaf(&self) -> bool {
        matches!(self, NestedIntList::Leaf(_))
    }

    fn get_segment_length(&self) -> usize {
        match self {
            NestedIntList::Leaf(segment_len) => *segment_len,
            NestedIntList::Node(_) => panic!("Called get_segment_length on a Node"),
        }
    }

    fn iter_children(&self) -> impl Iterator<Item = &Self> {
        match self {
            NestedIntList::Leaf(_) => panic!("Called iter_children on a Leaf"),
            NestedIntList::Node(children) => children.iter(),
        }
    }
}

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
