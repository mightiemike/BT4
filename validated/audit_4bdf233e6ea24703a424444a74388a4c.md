### Title
Unbounded, Fee-Free On-Chain Account Creation via Gasless `MsgExecutePayload`/Ante `AccountInitDecorator` - (File: `app/ante/account_init_decorator.go`)

### Summary
The Mintbase report describes `nft_on_approve` growing marketplace storage state on every call without collecting any storage fee from the caller, letting an attacker lock funds by spamming approvals for free. Push Chain has a structurally identical pattern in `AccountInitDecorator.AnteHandle` (`app/ante/account_init_decorator.go:31-81`): for any gasless transaction whose signer has no on-chain account yet, the decorator unconditionally creates and persists a brand-new `auth` module account (`acc := aid.ak.NewAccountWithAddress(...); aid.ak.SetAccount(ctx, acc)`) before the rest of the ante pipeline (fee deduction, `SetPubKeyDecorator`, etc.) ever runs, and it does so for **zero fee**, since `DeductFeeDecorator` (`app/ante/fee.go:59-64`) and `MinGasPriceDecorator` (`app/cosmos/min_gas_price.go:81-84`) both explicitly skip all fee/min-gas checks for gasless transactions.

### Finding Description
`MsgExecutePayload` is in the gasless whitelist (`app/txpolicy/gasless.go:19`) and, per `x/uexecutor/README.md:204,215`, is explicitly designed so that "**any** account may submit the message" — the `Signer` need not match, own, or fund the target `UniversalAccountId`. Its `ValidateBasic` (`x/uexecutor/types/msg_execute_payload.go:49-84`) only validates field formatting (bech32, non-nil, hex), never touching account balances or bonding status.

An unprivileged external attacker can:
1. Generate an arbitrary number of throwaway keypairs offline (free).
2. For each keypair, craft a syntactically valid `MsgExecutePayload` (any `UniversalAccountId`/payload passes `ValidateBasic`), sign it under `account_number=0, sequence=0` as required by `verifySignatureForNewAccount` (`app/ante/account_init_decorator.go:83-170`).
3. Broadcast the tx. Because it is classified gasless, `MinGasPriceDecorator` and `DeductFeeDecorator` are bypassed entirely, and `AccountInitDecorator` runs next: it verifies the (self-produced, trivially valid) signature, then calls `NewAccountWithAddress` + `SetAccount` and returns `ctx, nil` immediately — short-circuiting before `SetPubKeyDecorator`/signature/fee logic ever executes further.

In Cosmos SDK's `baseapp.runTx`, ante-handler state mutations are committed to the real store independent of whether the subsequent message execution (the actual `ExecutePayload` call, which will fail because the attacker doesn't own the target UEA) succeeds or reverts. So the new account persists in `auth` module state permanently, at zero cost to the attacker, on every single such transaction — this is the same "state/storage growth accepted from the caller without collecting compensation" bug class as the Mintbase report, just manifesting as unauthenticated account-trie bloat instead of NFT-listing storage lock.

### Impact Explanation
This is an unprivileged, fee-free primitive for permanently growing core `auth` module state (account number allocation, account records) with no economic cost to the attacker, since it bypasses the very fee mechanism (`DeductFeeDecorator`/`MinGasPriceDecorator`) that normally deters such spam for every other message type. Because Cosmos SDK account records are not prunable/removable once created, this state growth is permanent, unlike a typical rate-limited spam scenario. Over time this degrades node disk/IO/state-sync costs for all node operators — a reachable, non-network-level DoS vector requiring no privileged position, consistent with the "denial of service...reachable without privileged control" allowed-impact category.

### Likelihood Explanation
High feasibility: no bonded/validator status, no balance, and no relationship to any real UEA owner is required — only the ability to generate a keypair and produce one signature over fixed `(account_number=0, sequence=0)` data, which is trivial and can be scripted for mass, cheap (network-bandwidth-only) submission of many such transactions across blocks, bounded only by per-block gas capacity (which nobody pays for, since the tx is gasless).

### Recommendation
Require the `AccountInitDecorator`-created account path to still be gated by some minimal cost or rate limit — e.g., require gasless first-use account creation only for signers that are also the observed voter set (`x/uvalidator` bonded UVs) rather than for arbitrary `MsgExecutePayload` signers, or require a minimal balance/fee deposit before creating a new on-chain account even on the gasless path, or cap the number of new-account creations processed per block from this path.

### Proof of Concept
1. Generate N distinct new secp256k1/ed25519 keypairs, none of which have ever had an on-chain account.
2. For each keypair, construct a `MsgExecutePayload` with any syntactically valid (but non-owned) `UniversalAccountId`/`UniversalPayload`/`VerificationData`, sign it as a `SIGN_MODE` transaction assuming `account_number=0, sequence=0`.
3. Broadcast all N transactions. Each is classified gasless by `IsGaslessTx` (`app/txpolicy/gasless.go:14-49`), bypasses `MinGasPriceDecorator`/`DeductFeeDecorator`, and is processed by `AccountInitDecorator`, which persists a new account for each signer regardless of the subsequent `ExecutePayload` message failing.

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}

	ctx.Logger().Debug("account init decorator: existing account on gasless tx, passing to next handler",
		"address", sdk.AccAddress(newAccAddr).String(),
	)
	return next(ctx, tx, simulate)
}

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}

// ValidateBasic does a sanity check on the provided data.
func (msg *MsgExecutePayload) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate universal payload
	if msg.UniversalPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal payload cannot be nil")
	}

	// Validate verificationData
	if len(msg.VerificationData) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "verificationData cannot be empty")
	}
	if _, err := hex.DecodeString(strings.TrimPrefix(msg.VerificationData, "0x")); err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid verificationData hex")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate universal payload structure
	if err := msg.UniversalPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universal payload")
	}

	return nil
}

### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
