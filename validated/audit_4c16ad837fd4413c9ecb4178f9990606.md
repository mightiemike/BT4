## Title
Webhook `shop` identity is taken from an unauthenticated header while HMAC only signs the body, allowing cross-tenant session-storage wipe via forged `APP_UNINSTALLED` webhook - (File: packages/apps/shopify-api/lib/webhooks/process.ts, packages/apps/shopify-api/lib/utils/hmac-validator.ts, packages/apps/shopify-api/lib/webhooks/validate.ts)

### Summary
The reported SmartSession bug is a case where a multi-role component performs a destructive, irreversible action (wiping session storage) against the wrong target because the component cannot correctly bind "which part is being acted on" to "who authorized it." The same class of flaw exists in `shopify-app-js`'s webhook pipeline: the value used to identify **which shop's sessions to wipe** (`X-Shopify-Shop-Domain`) is never covered by the HMAC signature, only the raw body is. An attacker who legitimately controls one shop can capture a valid `(rawBody, hmac)` pair from their own real webhook delivery and replay it against the app's webhook endpoint with a forged `X-Shopify-Shop-Domain` header pointing at a victim shop, causing the framework's `APP_UNINSTALLED` handler to wipe out the victim's session storage.

### Finding Description
`validateHmacFromRequestFactory` computes and checks the HMAC using only the request's raw body: [1](#0-0) 

`validateFactory` separately reads the shop-identifying header (`X-Shopify-Shop-Domain`, exposed as `domain`) and other metadata straight from unauthenticated request headers — none of these headers are part of the HMAC computation: [2](#0-1) 

`process()` then hands `webhookCheck.domain` (the unauthenticated header value) directly to the registered handler callback as the `shop` argument, as soon as the body-only HMAC check succeeds: [3](#0-2) 

For `shopify-app-express`, the framework auto-registers a handler for `APP_UNINSTALLED` that takes this `shop` value at face value and wipes **all** stored sessions for that shop: [4](#0-3) [5](#0-4) [6](#0-5) 

Because the HMAC only binds the body, and the handler is invoked with the header-derived `domain` rather than anything cryptographically tied to that domain, there is no check that the signed body actually corresponds to the shop named in the header. An attacker who legitimately installs the app on their own store will receive a genuine `(rawBody, X-Shopify-Hmac-Sha256)` pair for a real `APP_UNINSTALLED` (or any other) webhook. Because the app's client secret — and therefore the HMAC — is the same across every shop that has the app installed, that captured `(rawBody, hmac)` pair remains valid regardless of which shop's domain header accompanies it. The attacker can replay the exact same body/HMAC to the app's public webhook endpoint while substituting `X-Shopify-Shop-Domain: victim-shop.myshopify.com`. The signature check passes (it never looked at the domain header), and `deleteAppInstallationHandler` will call `AppInstallations.delete('victim-shop.myshopify.com')`, deleting every session stored for the victim shop.

### Impact Explanation
This is a direct analog of the SmartSession issue: a shared/global secret is reused across "tenants" (shops), and the mechanism does not bind the destructive action to the correct target, so a valid credential for one tenant lets an attacker corrupt state for another. Concretely, deleting all offline/online sessions for a victim shop:
- Forces that shop's app instance into a broken/uninstalled state from the app's perspective, breaking the embedded app for that merchant and any background jobs relying on the offline token.
- Constitutes a cross-tenant Denial of Service against an arbitrary shop the attacker merely needs to know the domain of (shop domains are guessable/public, e.g. `<name>.myshopify.com`).
- If other webhook handlers in a given app treat `shop` from this same pipeline as trusted for more sensitive operations (e.g., writes keyed by shop, GDPR data deletion, billing changes), the same header-spoofing primitive extends the blast radius further, since every HTTP webhook handler receives this unauthenticated `domain` value as its `shop` parameter.

### Likelihood Explanation
Any actor who can install the app on a single shop they control (a normal, unprivileged action for any merchant, including via a free public listing or dev store) can capture a valid webhook body/HMAC pair for their own store using standard tooling. The `X-Shopify-Shop-Domain` header is fully attacker-controlled at the HTTP layer, and this code path is reachable from a purely anonymous/public HTTP endpoint (`config.webhooks.path`) with no session or authentication requirement beyond the trivially satisfiable HMAC-of-body check.

### Recommendation
Bind the shop identity used by handlers to something cryptographically verified, not a bare header:
- Prefer verifying that the body payload's own `shop_domain`/`shop_id` (present in Shopify's actual webhook JSON payloads) matches the `X-Shopify-Shop-Domain` header before trusting either.
- Where feasible, include header values (domain, topic, webhook id) as part of the HMAC-covered material, or otherwise cryptographically tie the claimed domain to the verified body content.
- At minimum, cross-check the header-derived shop against the session/offline-token record already associated with that webhook subscription before performing destructive actions like `deleteSessions`.

### Proof of Concept
1. Install the target app on an attacker-controlled shop `attacker-shop.myshopify.com`; trigger a legitimate `APP_UNINSTALLED` webhook delivery and capture the exact `rawBody` and `X-Shopify-Hmac-Sha256` header Shopify sends.
2. Replay an HTTP POST to the app's public webhook endpoint (`config.webhooks.path`) with:
   - Same `rawBody` and same `X-Shopify-Hmac-Sha256` value captured in step 1.
   - `X-Shopify-Topic: app/uninstalled`
   - `X-Shopify-Shop-Domain: victim-shop.myshopify.com` (any known/target shop domain)
   - Other required headers (`X-Shopify-API-Version`, `X-Shopify-Webhook-Id`) filled with arbitrary/duplicated values, since only HMAC-over-body is checked at `validateHmacFromRequestFactory`.
3. `validateFactory` succeeds because the HMAC only validates `rawBody` against the app's shared secret; `checkWebhooksHeaders` extracts `domain: 'victim-shop.myshopify.com'` from the forged header.
4. `process()` invokes `deleteAppInstallationHandler` with `shop = 'victim-shop.myshopify.com'`, which calls `AppInstallations.delete('victim-shop.myshopify.com')`, deleting all of that shop's stored sessions even though the victim never uninstalled the app.
