# No vulnerability found for this question.

Analysis:

The claimed exploit requires the attacker to submit `PoisonMicroblock` headers with `sequence=1` (or any sequence lower than the true fork point) that are "self-signed/forged" yet still recover to the **same** `pubkh` as the target miner's genuine, previously-registered microblock public key.

Tracing `handle_poison_microblock` in `stackslib/src/chainstate/stacks/db/transactions.rs`, the gating check is `check_microblock_header_signer`, which calls `mblock_hdr.check_recover_pubkey()` on each header [1](#0-0) . `check_recover_pubkey` performs ECDSA public-key recovery from the header's actual `signature` field over the header's serialized bytes [2](#0-1) . The resulting `pubkh` is then looked up via `get_microblock_pubkey_hash_height(&pubkh)`, which only succeeds if that exact hash was registered from a real anchored block committed by the actual miner [3](#0-2) .

For an attacker to fabricate a header pair that recovers to the *target miner's* real `pubkh` without possessing the miner's private key, they would need to either forge an ECDSA signature verifying under someone else's public key, or find a second-preimage collision producing the same Hash160 — both of which are standard cryptographic hardness assumptions, explicitly out of scope ("Bitcoin-consensus defects", "compromised dependencies" adjacent, and generally not a repo-level logic bug). An attacker using their *own* key would recover to their *own* `pubkh`, which either has no registered height (rejected with "never seen in this fork") or corresponds to blocks the attacker themselves mined (not the targeted honest miner) — so `insert_microblock_poison` would never be reachable against the target's report record for that other miner.

The `mblock_header_1.sequence < seq` comparison in `handle_poison_microblock` already enforces the correct equality: only a genuinely lower, validly-signed conflicting pair (i.e., an actual second microblock the real miner double-signed at that lower sequence) can overwrite an existing report; equal sequences do not overwrite [4](#0-3) . If the real equivocation only occurred at sequence 50, no genuine signed conflicting header pair exists at sequence 1, so no valid `PoisonMicroblock` transaction can be constructed for that sequence by anyone lacking the miner's key. The race for "who submits first" is only meaningful among parties who each independently possess a **genuine** conflicting signed pair at the true (or a truly lower) fork point — which is the intended design, not a forgeable front-run.

Since the "equality broken" premise depends on signature/hash forgery that is cryptographically infeasible for an unprivileged attacker, and the existing `check_microblock_header_signer` + `get_microblock_pubkey_hash_height` checks already prevent it, there is no reachable code path granting an unprivileged attacker the described reward-theft primitive.

    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }

    pub fn check_recover_pubkey(&self) -> Result<Hash160, AuthError> {
        let mut bytes = vec![];
        self.serialize(&mut bytes, true)
            .expect("BUG: failed to serialize to a vec");
        let digest = Sha512Trunc256Sum::from_data(&bytes[..]);

        let mut pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            digest.as_bytes(),
            &self.signature,
        )
        .map_err(|_ve| {
            AuthError::VerifyingError(
                "Failed to verify signature: failed to recover public key".to_string(),
            )
        })?;

        pubk.set_compressed(true);
        Ok(Hash160::from_node_public_key(&pubk))
    }
