Based on the vulnerability pattern in the report — a slippage check performed on a pre-fee value (`truePayoutSize`) instead of the actual value that gets used downstream (`payoutAfterFee`) — I found a structurally identical pattern in `shop-validator.ts`'s `sanitizeShop` function.

### Title
Shop domain validation is performed on the pre-transformation value, not the final value returned and trusted downstream - (File: packages/apps/shopify-api/lib/utils/shop-validator.ts)

### Summary
`sanitizeShop` validates the untransformed shop string against an allow-list regex, but then applies `applyDomainTransformations` and returns that transformed result *without re-validating it*. This mirrors the reported bug class: a security check is applied to an intermediate value (`truePayoutSize`) while the value that is actually used/returned (`payoutAfterFee`) bypasses the check entirely.

### Finding Description
`sanitizeShop` builds `domainsRegex`/`shopUrlRegex` from known Shopify domains plus any configured `domainTransformations` source/target domains, and only returns a shop string if the *original* `shopUrl` matches this regex: [1](#0-0) 

Critically, after `sanitizedShop` passes the regex check, the function calls `applyDomainTransformations(sanitizedShop, config)` and returns *that* value instead of `sanitizedShop` itself: [2](#0-1) 

`applyDomainTransformations` can return an arbitrary string derived from a regex-capture substitution or an app-supplied transform function, with no re-validation against the myshopify allow-list regex: [3](#0-2) 

The value returned by `sanitizeShop` is treated as a trusted, validated shop domain everywhere it's consumed — including constructing the OAuth authorize redirect URL (`https://${cleanShop}/admin/oauth/authorize`) in `oauth.ts`, and deriving session/storage identifiers via `getJwtSessionId`/`getOfflineId`/`customAppSession` in `session-utils.ts`: [4](#0-3) [5](#0-4) 

If a `domainTransformations` entry's `transform` is a function (developer-supplied) or a template string with `$n` placeholders substituted from attacker-influenced regex capture groups, the final domain returned by `sanitizeShop` is never checked against the myshopify/shopify allow-list a second time — exactly analogous to checking `truePayoutSize` while paying out `payoutAfterFee`.

### Impact Explanation
Because the check is bound to the pre-transform value, the guarantee "the returned shop always matches an approved Shopify domain pattern" is not actually enforced on the value callers rely on. Depending on how the host app configures `domainTransformations` (a first-party configuration point, not attacker data), this can result in `sanitizeShop` returning a non-Shopify hostname used later to build the OAuth `redirect_uri`/authorize target, or in constructing session/storage keys — creating open-redirect/SSRF or cross-tenant session-key confusion risk.

### Likelihood Explanation
Exploitation is entirely dependent on how a given app configures `domainTransformations` (e.g., using a permissive regex or a transform function that reflects capture groups without constraint). It cannot be triggered against apps that do not use `domainTransformations`, or apps using tight, non-reflective transform templates — this significantly limits real-world likelihood.

### Recommendation
Re-validate the output of `applyDomainTransformations` against the same `shopUrlRegex` (or an equivalent allow-list check) before returning it from `sanitizeShop`, so the final, actually-used value is what gets validated — not just the pre-transform input.

### Proof of Concept
Not applicable as a concrete exploit against the default configuration; the weakness is only reachable when a host app supplies a `domainTransformations` entry whose `transform` echoes attacker-controlled regex captures without further domain constraints, allowing `sanitizeShop(attackerShop)` to return a value that was never checked against the myshopify allow-list.

export function applyDomainTransformations(
  shopUrl: string,
  config: ConfigInterface,
): string | null {
  if (
    !config.domainTransformations ||
    config.domainTransformations.length === 0
  ) {
    return shopUrl;
  }

  for (const transformation of config.domainTransformations) {
    const regex =
      typeof transformation.match === 'string'
        ? new RegExp(transformation.match)
        : transformation.match;

    const matches = shopUrl.match(regex);

    if (!matches) {
      continue;
    }

    if (typeof transformation.transform === 'function') {
      return transformation.transform(matches);
    }

    let result = transformation.transform;
    matches.forEach((match, index) => {
      result = result.replace(new RegExp(`\\$${index}`, 'g'), match || '');
    });

    return result;
  }

  return shopUrl;
}
