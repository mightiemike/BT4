### Title
CRLF/header injection in `sanitizeHost`/`buildEmbeddedAppUrl` via unsanitized decoded `host` param used to build embedded app redirect URL - (File: `packages/apps/shopify-api/lib/utils/shop-validator.ts`, `packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts`)

### Summary
`sanitizeHost` only validates the `hostname` portion parsed by the WHATWG `URL` constructor (which silently strips CR/LF and other control characters before parsing), but `buildEmbeddedAppUrl` then re-decodes the raw base64 `host` value and concatenates the **unstripped** decoded string directly into the redirect URL. An attacker who controls the `host` query parameter can therefore smuggle raw CR/LF (and other characters) past validation into the final `https://${decodedHost}/apps/${apiKey}` string returned by `getEmbeddedAppUrl`/`buildEmbeddedAppUrl`, which many app integrations pass straight to `res.redirect(...)`.

### Finding Description
`sanitizeHost` (`packages/apps/shopify-api/lib/utils/shop-validator.ts`) validates the host as follows: [1](#0-0) 

It base64-checks the raw `host` param, then decodes it with `decodeHost` (a plain `atob`) and constructs `new URL('https://' + decodeHost(sanitizedHost))`, checking only `hostname` against the allow-listed domain suffixes. Because `atob` can decode to arbitrary bytes (including `\r`/`\n`), and the WHATWG URL parser strips ASCII tab/newline characters from its input during parsing, a crafted decoded string such as `test.myshopify.com/admin\r\nInjected: 1` still yields a valid `hostname` of `test.myshopify.com`, so `sanitizeHost` reports it as valid.

The problem is that `buildEmbeddedAppUrl` does not reuse the sanitized/stripped URL object — it re-decodes the raw host and interpolates it verbatim: [2](#0-1) 

So the returned string retains the original `\r\n` (or other injected bytes) beyond the hostname, e.g. `https://test.myshopify.com/admin\r\nInjected: 1/apps/<apiKey>`. This value is consumed directly by callers as a redirect target, e.g.: [3](#0-2) [4](#0-3) 

`getEmbeddedAppUrl` itself pulls `host` straight from the request's query string with no additional sanitization pass on the decoded value: [5](#0-4) 

The core root cause: validation is performed on a *normalized/stripped* representation (the parsed `URL.hostname`), while the *raw, unstripped* decoded string is what's actually embedded into the output URL — a classic "validate one thing, use another" (TOCTOU-style) sanitization bypass.

### Impact Explanation
This breaks the stated invariant that "embedded app URL host is verified" — verification only covers the hostname suffix, not the full decoded content that ends up in the constructed URL. Where the underlying HTTP stack does not itself reject control characters in header values (e.g., non-Node runtimes/adapters, or any code path that manually writes the `Location` header/response instead of using a hardened `res.redirect`), this allows response header/HTTP response splitting from a single unauthenticated request bearing a crafted `host` parameter, which can lead to reflected header injection, cache poisoning, or open-redirect-style content injection within the embedded frame. In modern Node/Express deployments, Node's `http` module independently rejects raw CR/LF in header values, which mitigates (but does not fix) the underlying library defect — the sanitization gap in `shopify-api` itself remains regardless of that incidental downstream protection.

### Likelihood Explanation
Fully unprivileged: the attacker only needs to send a GET request with a crafted, base64-encoded `host` query parameter to any endpoint that calls `shopify.auth.getEmbeddedAppUrl`/`buildEmbeddedAppUrl` (e.g., `ensureInstalledOnShop`, `redirectToShopifyOrAppRoot` across the Express/Remix/React Router adapters), which are reachable pre-authentication in the app-install/embed flow. No secret, HMAC, or session is required to trigger the code path — the attacker only needs to control the `host` param.

### Recommendation
In `buildEmbeddedAppUrl`, do not re-decode and re-interpolate the raw `host` string. Instead, reuse the parsed/sanitized `URL` object (e.g. `url.toString()` or reconstruct explicitly from `url.hostname`/`url.pathname` after stripping control characters), and/or explicitly reject any decoded host value containing control characters (`\r`, `\n`, or other non-printable bytes) before it's used to build the final redirect string in `packages/apps/shopify-api/lib/utils/shop-validator.ts` and `packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts`.

### Proof of Concept
```ts
import {shopifyApi} from '../..';
import {testConfig} from '../../__tests__/test-config';

test('buildEmbeddedAppUrl leaks raw CRLF beyond validated hostname', () => {
  const shopify = shopifyApi(testConfig());

  const maliciousHost = 'test.myshopify.com/admin\r\nX-Injected: evil';
  const base64Host = Buffer.from(maliciousHost, 'utf-8').toString('base64');

  // sanitizeHost only checks the parsed hostname, so this returns the (unstripped) input
  expect(shopify.utils.sanitizeHost(base64Host)).toEqual(base64Host);

  // buildEmbeddedAppUrl re-decodes and concatenates the raw string, CRLF intact
  const url = shopify.auth.buildEmbeddedAppUrl(base64Host);
  expect(url).toContain('\r\n');
  expect(url).toBe(
    `https://${maliciousHost}/apps/${shopify.config.apiKey}`,
  );
});
```
Expected result today: the test passes, confirming CR/LF from the decoded `host` param survives unsanitized into the value returned for use as a redirect target — demonstrating the injection primitive at the library level, independent of any downstream HTTP-layer mitigation.

export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;

export function getEmbeddedAppUrl(config: ConfigInterface): GetEmbeddedAppUrl {
  return async ({...adapterArgs}: GetEmbeddedAppUrlParams): Promise<string> => {
    const request = await abstractConvertRequest(adapterArgs);

    if (!request) {
      throw new ShopifyErrors.MissingRequiredArgument(
        'getEmbeddedAppUrl requires a request object argument',
      );
    }

    if (!request.url) {
      throw new ShopifyErrors.InvalidRequestError(
        'Request does not contain a URL',
      );
    }

    const url = new URL(request.url, `https://${request.headers.host}`);
    const host = url.searchParams.get('host');

    if (typeof host !== 'string') {
      throw new ShopifyErrors.InvalidRequestError(
        'Request does not contain a host query parameter',
      );
    }

    return buildEmbeddedAppUrl(config)(host);
  };
}

export function buildEmbeddedAppUrl(
  config: ConfigInterface,
): BuildEmbeddedAppUrl {
  return (host: string): string => {
    sanitizeHost(config)(host, true);
    const decodedHost = decodeHost(host);

    return `https://${decodedHost}/apps/${config.apiKey}`;
  };
}
