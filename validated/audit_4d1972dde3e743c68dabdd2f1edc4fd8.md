## Analysis Result

### Title
Missing server-side expiry enforcement for signed OAuth `state` cookie allows stale/replayed nonce to complete OAuth callback - (File: `packages/apps/shopify-api/runtime/http/cookies.ts`)

### Summary
The Deriverse report describes a check that exists (`voting_end_time`) but is only enforced too late/at the wrong point (in `finalize_voting()`), so the vote itself is recorded before expiry is validated. The shopify-app-js analog is the OAuth `state` nonce cookie: `begin()` sets an explicit 60-second expiry on the signed `state` cookie, but the verification routine that later reads it, `Cookies.getAndVerify()` → `isSignedCookieValid()`, never checks that expiry — it only checks that the cookie/signature pair exists and that the signature is cryptographically valid.

### Finding Description
In `packages/apps/shopify-api/lib/auth/oauth/oauth.ts`, `begin()` creates a random `state` nonce and stores it in a signed cookie with a hard 60-second expiry: [1](#0-0) 

In `callback()`, the state is retrieved with `cookies.getAndVerify(STATE_COOKIE_NAME)` and compared against the `state` query param using `safeCompare`, but the expiry of the cookie is never independently re-checked server-side: [2](#0-1) 

The actual verification logic in `Cookies.getAndVerify()`/`isSignedCookieValid()` only validates cookie existence and HMAC signature correctness — the `expires`/`maxAge` field set at issuance time is never consulted during verification: [3](#0-2) 

The only other time-bound check in the callback path is `validateHmacTimestamp()`, but that validates the `timestamp` query parameter generated by Shopify at redirect time (with a 90-second tolerance window) — it has no relationship to when the `state` cookie itself was minted, so it does not compensate for the missing cookie-expiry check: [4](#0-3) 

This mirrors the report's root cause pattern exactly: an expiry field is set/intended (`voting_end_time` / cookie `expires: Date.now() + 60000`), but the function that consumes/validates the protected action (`voting()` / `getAndVerify()`) never actually checks it against current time, only checking a value's structural/cryptographic validity.

### Impact Explanation
If a `state` cookie value and its signature are retained or replayed by an attacker beyond the intended 60-second OAuth window (e.g., via a shared/compromised browser profile, cached HTTP client, proxy log, or any mechanism that lets the cookie survive past its intended lifetime instead of being deleted by the client), `getAndVerify()` will still validate it as long as the raw signature matches — with no server-side enforcement that the nonce has expired. This weakens the intended narrow anti-CSRF/replay window for the OAuth `state` nonce, an unprivileged-actor-reachable path via the app's own `/auth/callback` endpoint.

### Likelihood Explanation
Exploitation still requires the attacker to possess both the (stale) signed `state` cookie and a subsequent valid Shopify-issued `code`/`hmac` for the same `state`/`shop` pair — this is a real but narrower precondition than a full open replay, since Shopify's HMAC on the callback query still has its own tolerance window. The core defect — no server-side expiry check on the nonce cookie — is nonetheless a clear violation of the design intent (a 60-second nonce should not verify indefinitely).

### Recommendation
Have `Cookies.isSignedCookieValid()` (or a dedicated check in `oauth.ts`'s `callback()`) compare the cookie's `expires` timestamp (recorded at signing time, e.g., by embedding an issuance time in the signed payload) against the current time, and reject the `state` cookie if it is past its intended TTL, mirroring the recommended Deriverse fix of validating the time bound before accepting/consuming the tokened action.

### Proof of Concept
1. Call `shopify.auth.begin()`, capturing the `Set-Cookie` response containing the signed `shopify_app_state`/`shopify_app_state.sig` cookie pair (intended `expires` = now + 60s).
2. Wait beyond 60 seconds (or otherwise retain the cookie past its intended lifetime, e.g., a client/proxy that does not honor `Expires`).
3. Present the same (stale) signed cookie together with a subsequently obtained valid `state`/`hmac`/`code` combination to `shopify.auth.callback()`.
4. Observe that `cookies.getAndVerify(STATE_COOKIE_NAME)` in [5](#0-4)  returns the value successfully because `isSignedCookieValid()` never checks `expires`, allowing the callback to proceed despite the nonce's intended expiry having passed.

  async getAndVerify(name: string): Promise<string | undefined> {
    const value = this.get(name);
    if (!value) return undefined;
    if (!(await this.isSignedCookieValid(name))) {
      return undefined;
    }
    return value;
  }

  private get canSign() {
    return this.keys?.length > 0;
  }

  set(name: string, value: string, opts: Partial<CookieData> = {}): void {
    this.outgoingCookieJar[name] = {
      ...opts,
      name,
      value,
    };
    this.updateHeader();
  }

  async setAndSign(
    name: string,
    value: string,
    opts: Partial<CookieData> = {},
  ): Promise<void> {
    if (!this.canSign) {
      throw Error('No keys provided for signing.');
    }
    this.set(name, value, opts);
    const sigName = `${name}.sig`;
    const signature = await createCookieSignature(this.keys[0], value);
    this.set(sigName, signature, opts);
    this.updateHeader();
  }

  async isSignedCookieValid(cookieName: string): Promise<boolean> {
    const signedCookieName = `${cookieName}.sig`;
    if (
      !this.cookieExists(cookieName) ||
      !this.cookieExists(signedCookieName)
    ) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }
    const cookieValue = this.get(cookieName);
    const signature = this.get(signedCookieName);

    if (!cookieValue || !signature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    const allCheckSignatures = await Promise.all(
      this.keys.map((key) => createCookieSignature(key, cookieValue)),
    );

    const validSignature = allCheckSignatures.some((checkSignature) =>
      safelyCompareSignatures(checkSignature, signature),
    );

    if (!validSignature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    return true;
  }

function validateHmacTimestamp(query: AuthQuery) {
  const {timestamp} = query;

  if (
    timestamp === undefined ||
    timestamp === null ||
    Array.isArray(timestamp)
  ) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is missing or invalid',
    );
  }

  const parsedTimestamp = Number(timestamp);

  if (!Number.isInteger(parsedTimestamp)) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is missing or invalid',
    );
  }

  if (
    Math.abs(getCurrentTimeInSec() - parsedTimestamp) >
    HMAC_TIMESTAMP_PERMITTED_CLOCK_TOLERANCE_SEC
  ) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is outside of the tolerance range',
    );
  }
}
