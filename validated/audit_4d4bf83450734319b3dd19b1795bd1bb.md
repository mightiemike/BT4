### Title
Empty (but non-`None`) signer set collapses the Nakamoto signature-weight threshold to zero, allowing a block to be accepted with no signer signatures - ([File: stackslib/src/chainstate/stacks/boot/mod.rs], [File: stackslib/src/chainstate/nakamoto/mod.rs])

### Summary
`StacksChainState::make_signer_set()` can return `Some(vec![])` — a *populated* `Option` wrapping an *empty* vector — when every stacker entry's `amount_stacked / threshold` rounds down to zero. This degenerate `RewardSet` is not caught by `read_reward_set_at_calculated_block`'s `signers().is_none()` guard (empty `Some` passes it), and it propagates into `NakamotoBlockHeader::verify_signer_signatures()`, where `total_signing_weight()` returns `0`, `compute_voting_weight_threshold(0)` returns `0`, and the comparison `total_weight_signed < threshold` (`0 < 0`) is `false`. A Nakamoto block requiring **zero signer signatures** is therefore accepted as valid.

### Finding Description
`make_signer_set` aggregates stacked amounts per signing key and computes each signer's weight as `stacked_amt / threshold`, filtering out entries whose weight is `0`: [1](#0-0) 

Critically, the function only returns `None` when the *input* entry list is empty: [2](#0-1) 

If entries exist (so `entries.first()` is `Some`, and every entry carries a `signer` key) but every individual signer's aggregated `stacked_amt` is below `threshold` (e.g., many small stackers with distinct signing keys, none crossing the per-slot cutoff), every computed `weight` is `0` and is filtered out by `filter_map`. The function still returns `Some(signer_set)`, where `signer_set` is an **empty** `Vec` — not `None`.

This `Some(vec![])` is stored directly in `RewardSetV0.signers`: [3](#0-2) 

The consumer-side sanity check in the coordinator only rejects a reward set when `rewarded_addresses` is empty or when `signers()` is `None` — it never checks that the signer *vector itself* is non-empty: [4](#0-3) 

So a reward set with non-empty `rewarded_addresses` (real stackers exist) but an empty `signers` vector sails through as valid.

`RewardSet::total_signing_weight()` sums the (empty) signer weights via `fold`, which yields `0` (not an error, since `signers()` returned `Some`, just with zero elements): [5](#0-4) 

This zero total weight then flows into `NakamotoBlockHeader::verify_signer_signatures`: [6](#0-5) 

With `total_weight = 0`, `compute_voting_weight_threshold` computes:
```
ceil = if (0 * 7) % 10 == 0 { 0 } else { 1 }  // = 0
threshold = (0 * 7) / 10 + 0 = 0
``` [7](#0-6) 

Because the block's `signer_signature` vector can legitimately be empty (no signers exist to sign — the loop over `self.signer_signature.iter()` simply doesn't execute), `total_weight_signed` remains `0`. The final guard is:
```rust
if total_weight_signed < threshold {   // 0 < 0 -> false
    return Err(...)
}
return Ok(total_weight_signed);        // Ok(0)  -- ACCEPTED
``` [8](#0-7) 

This exactly mirrors the referenced report's bug class: a divide/threshold function that is supposed to enforce a strictly-positive gate silently returns `0` in the degenerate all-zero-shares/zero-weight case, and the caller treats "0 required, 0 provided" as satisfying the condition instead of treating it as an invalid/undefined state. Here, the broken equality is: *a block is accepted iff signer weight signed ≥ required threshold weight*, but when the reward set is degenerate, the threshold silently drops to 0, so the equality is trivially satisfied by any block — including one carrying no signatures at all.

### Impact Explanation
This breaks the core Nakamoto safety invariant that a block header must be approved by signers holding at least the NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD fraction of signing weight. Under the degenerate reward set condition, `verify_signer_signatures` accepts a block that carries *zero* valid signer signatures. Since this validation logic is deterministic and identical across all conformant nodes, all nodes reach the same (wrong) verdict — an unauthorized, unsigned block is accepted as consensus-valid network-wide. This is a "an invalid block accepted... network-wide" class Critical impact: it removes signer-set enforcement entirely for the affected reward cycle, letting a miner alone (with no signer cooperation) finalize any block content they choose during that cycle.

### Likelihood Explanation
The degenerate condition requires that, for the relevant reward cycle, PoX participation is non-empty (there are real stackers/reward addresses) yet every aggregated per-signing-key stacked amount is individually less than `threshold` (the per-slot uSTX amount). This is plausible in periods of very broad, shallow stacking distribution (many small stackers each registering distinct signing keys, none individually crossing the per-slot cutoff) — a condition influenced by economic parameters rather than requiring privileged access, and reachable without needing a majority of stake or keys; it only requires that the natural stacking distribution (or an attacker fragmenting stake across many signing keys they control) produces this specific degenerate shape for one reward cycle.

### Recommendation
`StacksChainState::make_signer_set` should return `None` (triggering the existing `PoXAnchorBlockRequired`/no-participation handling) whenever the *post-filter* signer set is empty, not only when the raw input entry list is empty. Additionally, `read_reward_set_at_calculated_block` and `RewardSet::total_signing_weight()` should explicitly treat an empty (but `Some`) signer vector as an error condition equivalent to "no signers," and `NakamotoBlockHeader::verify_signer_signatures` should reject (rather than trivially accept) any block whose reward set has `total_weight == 0`.

### Proof of Concept
1. During the PoX-4 registration window for reward cycle `N`, arrange for many distinct stackers to each register a distinct signer key, with each stacker's aggregated `amount_stacked` individually less than the computed `threshold` (`liquid_ustx / reward_slots`), while total participation (`rewarded_addresses`) remains non-empty.
2. `pox_4_compute_and_update_signers` → `StacksChainState::make_signer_set(threshold, entries)` computes `weight = stacked_amt / threshold == 0` for every entry, filters all of them out via `filter_map`, and returns `Some(vec![])` (see `stackslib/src/chainstate/stacks/boot/mod.rs:1051-1071`).
3. The reward set is stored with `signers: Some(vec![])`; `read_reward_set_at_calculated_block`'s only guards (`rewarded_addresses` empty, `signers().is_none()`) both pass.
4. A miner produces a Nakamoto block for cycle `N+1` with `signer_signature: vec![]` (no signer approvals obtained).
5. `verify_signer_signatures` computes `total_weight = 0`, `threshold = compute_voting_weight_threshold(0) = 0`, and `total_weight_signed = 0`; the check `0 < 0` is false, so the function returns `Ok(0)` and the block is accepted as validly signed by every node in the network, despite having zero actual signer approvals.

    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
