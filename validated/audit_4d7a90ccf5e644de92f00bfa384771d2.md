### Title
Unbounded free account creation via `AccountInitDecorator` on gasless message types allows unprivileged state-bloat DoS - (File: `app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator` creates and permanently persists a new on-chain `auth` account for *any* first-time signer of a gasless-whitelisted message, independent of whether that message will later succeed in its message handler. Because gasless transactions bypass both the FeeMarket minimum-gas-price check and fee deduction, an attacker with zero PC tokens can generate unlimited fresh keypairs and submit garbage `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta`/etc. transactions that are guaranteed to fail at the msg-server's `IsBondedUniversalValidator` check, yet the account-creation side effect from the AnteHandler is already committed to state before that failure occurs. This is a native analog of the reported "no rate-limiting" issue: without any per-account/per-IP/per-token cost or throttle, unprivileged users can flood every honest node's state store indefinitely at no cost.

### Finding Description
The gasless-tx pipeline in Push Chain is composed of three custom AnteHandler decorators layered on top of the standard Cosmos SDK ante chain [3](#0-2) :
- `MinGasPriceDecorator` skips the FeeMarket minimum-fee check for gasless txs.
- `DeductFeeDecorator` skips fee deduction entirely for gasless txs, only requiring `feeTx.GetGas() != 0` [4](#0-3) .
- `AccountInitDecorator` runs before all signature-verification decorators and, when the signer has no existing account, verifies the signature against `account_number=0, sequence=0` and then unconditionally creates + persists the account, short-circuiting the rest of the ante chain [5](#0-4) .

The gasless allowlist (`IsGaslessTx`) includes `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`, `MsgExecutePayload`, and `MsgMigrateUEA` [6](#0-5) . These message types were designed to be gasless specifically so unfunded Universal Validators could vote on their very first transaction, per the documented purpose of `AccountInitDecorator` [7](#0-6) .

However, `ValidateBasic()` for these messages performs only syntactic checks (address format, non-empty fields) and never verifies UV membership [2](#0-1) . The actual authorization check (`IsBondedUniversalValidator`) only happens in the msg-server handler, which runs after the AnteHandler chain has already completed and its state changes committed [1](#0-0) .

Because AnteHandler-branch state changes in the Cosmos SDK `runTx` pipeline are committed independently of, and prior to, message execution, the newly created account persists even though the wrapped `MsgVoteInbound` will unconditionally fail with `"universal validator for signer ... is not bonded"`. Any external, unprivileged, unfunded attacker can therefore:
1. Generate an arbitrary number of fresh Cosmos keypairs (free, off-chain).
2. Sign a syntactically valid but semantically bogus `MsgVoteInbound` (or other gasless message) with each key, using `sequence=0`.
3. Submit each as a separate transaction — no PC balance, no minimum gas price, and no per-account/per-IP throttle is required or enforced anywhere in the pipeline.
4. Have each transaction, even though its `MsgVoteInbound` payload ultimately fails, permanently add one new entry to the `auth` module's global account store on every honest full node.

There is no protocol-level rate limiter, access-token, or per-signer cost gating this account-creation side effect — exactly the missing control called out in the source report.

### Impact Explanation
This is an unprivileged, cost-free, unbounded state-growth attack against every honest validator/full node in the network. Because gasless transactions require neither an existing balance nor a meaningful gas cost, the attacker's only expense is transaction propagation/bandwidth — no PC tokens are burned since the message fails after account creation and never reaches fee deduction (which is skipped anyway for gasless txs). Repeated at scale, this permanently bloats the `auth` account KV-store, increasing disk usage, IAVL tree size, state-sync payload size, snapshot size, and node startup/replay time for all participants — a denial-of-service against the network's operational health that is reachable purely through the ordinary, permissionless transaction-submission path, matching the "denial of service...reachable without privileged control" allowed impact.

### Likelihood Explanation
High. No special access, tokens, or validator status is required. The only "cost" is generating a keypair (free) and broadcasting a transaction; CometBFT mempools generally admit gasless-valid txs without requiring balance. An attacker can trivially script this to submit large volumes of unique-signer transactions.

### Recommendation
- Do not persist the new account inside `AccountInitDecorator` unconditionally; defer account materialization until after the wrapped message has been authorized/validated (e.g., only create the account once `IsBondedUniversalValidator` or equivalent per-message authorization succeeds), or perform a lightweight pre-check (UV-set membership, TSS-participant membership, etc.) inside the decorator before creating state.
- Alternatively, gate account auto-creation behind a per-address/per-block rate limit or require the signer to already be a known/whitelisted validator/operator key before allowing gasless first-use account creation.
- More generally, apply the source report's recommendation: enforce a cost or quota (e.g., an admission/allowlist check, or a bounded per-block/per-IP counter) on any state-mutating, fee-exempt code path reachable by unauthenticated actors.

### Proof of Concept
1. Generate a fresh Cosmos keypair `K` with derived address `A` (no on-chain account, no funds).
2. Construct `MsgVoteInbound{Signer: A, Inbound: <arbitrary syntactically-valid dummy fields>}`.
3. Wrap it in a transaction with `sequence=0`, `account_number=0`, any positive `Gas`, and zero fee; sign with `K`.
4. Broadcast the transaction. `IsGaslessTx` returns true (message type is in the allowlist), so `MinGasPriceDecorator`/`DeductFeeDecorator` impose no cost. `AccountInitDecorator` verifies the signature against `(account_number=0, sequence=0)`, succeeds, and calls `aid.ak.SetAccount(ctx, acc)`, persisting a new account for `A`.
5. Message execution subsequently fails in `msgServer.VoteInbound` with `"universal validator for signer ... is not bonded"`, but this does not roll back the account creation performed in the AnteHandler branch of `runTx`.
6. Repeat steps 1–5 with a new keypair each time — each iteration adds one permanent account entry to every node's state store at zero token cost.

// IsGaslessTx checks if a transaction contains only allowed gasless message types
// Returns true if all messages in the transaction are in the allowed gasless message types
func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
