### Title
Deposit-auto-swap and gas-refund-swap use manipulable spot-pool quote as their own slippage oracle, enabling sandwich extraction of bridged value - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
Like the referenced `AutoCompoundingPodLP` bug, Push Chain computes a swap's minimum-output slippage bound from a price value that does not represent an independent, manipulation-resistant reference. Instead of a TWAP oracle, `GetSwapQuote` ( [1](#0-0) ) fetches a live spot quote from the on-chain `QuoterV2.quoteExactInputSingle`, which reflects the current instantaneous Uniswap V3 pool reserves. This exact value (minus a flat 5%) is then used as `minPCOut` for the module's own subsequent swap of bridged PRC20 into PC via `depositPRC20WithAutoSwap` and `refundUnusedGas`.

### Finding Description
Three call sites compute `minPCOut = quote * 95 / 100` where `quote` comes straight from `GetSwapQuote`:
- `ExecuteInboundGas` for `GAS` inbounds [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` for `GAS_AND_PAYLOAD` inbounds [3](#0-2) 
- `applyGasRefund` for outbound gas-fee excess refunds [4](#0-3) 

`GetSwapQuote` is a pure spot-price read of the current Uniswap V3 pool state (`sqrtPriceLimitX96 = 0`, no averaging/observation window) [5](#0-4) . Because the "5% slippage" bound is derived from the same manipulable pool that the module's swap will execute against — rather than a TWAP or external price feed — an unprivileged actor can move the WPC/PRC20 pool price down immediately before the finalizing block that triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`/outbound-vote finalization (both are triggered deterministically once quorum among honest validators is reached, and the triggering `MsgVoteInbound`/`MsgVoteOutbound` transactions are visible in the mempool ahead of inclusion). The quote used for the module's own swap will reflect the depressed price, so `minPCOut` provides no real floor above the manipulated price — the module will happily execute the swap at the manipulated rate. The attacker then reverses their price-moving trade after the module's swap lands, extracting the spread as arbitrage profit funded by the bridged deposit/refund value that should have gone to the recipient UEA or refund recipient.

This is structurally the same root cause flagged in the external report — a slippage bound sourced from a price that is not resistant to attacker manipulation — but here it applies to Push Chain's own internal auto-swap of user-bridged funds and gas refunds into native PC, rather than a lending/pod price feed.

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound (used to top up a user's UEA with PC) and every outbound excess-gas refund swap is exposed. An attacker who sandwiches the pool right before finalization can cause the protocol to swap bridged PRC20 for PC at a manipulated (depressed) rate, meaning the recipient UEA / refund recipient receives less PC than fair value while the attacker captures the difference. This is a direct, repeatable value-extraction path from ordinary user deposit/refund flows — falls under "corruption of ... gas fee accounting, refund accounting ... token mapping" and unauthorized loss of user-controlled funds during universal execution.

### Likelihood Explanation
The trigger requires only an unprivileged actor able to submit ordinary swaps against the Push Chain Uniswap V3 pool and observe the public mempool for pending `MsgVoteInbound`/`MsgVoteOutbound` transactions that will finalize a `GAS`/`GAS_AND_PAYLOAD` inbound or a gas refund — no validator, TSS, or admin privilege is needed. The size of extractable value scales with pool liquidity depth and the deposit/refund amount, so profitability is bounded by available liquidity, but the mechanism itself requires no special conditions.

### Recommendation
Do not derive `minPCOut` from a live spot quote of the same pool the swap executes against. Use a manipulation-resistant reference such as a Uniswap V3 TWAP (via `observe()`/`slot0` averaged over a window) or an external attested price, and/or bound the acceptable deviation between the spot quote and the TWAP reference before allowing the auto-swap to proceed, similar to the suggested mitigation in the source report of using a correctly-denominated, non-manipulable price for slippage checks.

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` (or `MsgVoteOutbound`) transaction in the mempool that will push a `GAS_AND_PAYLOAD` inbound (or outbound gas refund) over quorum.
2. Immediately before this transaction is included, attacker submits a large swap against the WPC/PRC20 Uniswap V3 pool on Push Chain, depressing the PRC20→WPC spot price.
3. The finalizing vote transaction triggers `ExecuteInboundGasAndPayload` → `gasAndPayloadDepositAutoSwap`, which calls `GetSwapQuote` against the now-manipulated pool and computes `minPCOut` as 95% of that depressed quote [3](#0-2) .
4. `CallPRC20DepositAutoSwap` executes the module's swap at the manipulated rate, since `minPCOut` is trivially satisfied.
5. Attacker reverses their initial swap, restoring the pool price and pocketing the arbitrage profit extracted from the value that should have accrued to the recipient UEA.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
