### Title
CCIP `FeeQuoter` prices wrapped tokens (WBTC, WBNB, WAVAX, WPOL, etc.) using the base-asset Chainlink feed instead of a wrapped-asset-specific feed - ([File: deployment/ccip/shared/token_info.go])

### Summary
Chainlink CCIP's token-pricing configuration maps the generic base-asset Chainlink feed (e.g. `BTC / USD`) to wrapped/bridged token symbols (e.g. `WBTC`, `WBTCN`) and uses that feed's price as the on-chain USD price for the wrapped token in `FeeQuoter`. This is the same root-cause pattern as the referenced report: using the collateral asset's price feed as a stand-in for the wrapped token's price, ignoring depeg risk between the wrapped token and its underlying asset.

### Finding Description
`DescriptionToTokenSymbols` in `deployment/ccip/shared/token_info.go` maps the Chainlink feed description `"BTC / USD"` to both `WBTCNSymbol` and `WBTCSymbol`: [1](#0-0) 

This mapping is not just a documentation artifact — it's used live in two production paths:

1. **Automatic feed discovery**: `LoadChainState` reads each on-chain `AggregatorV3Interface`'s `Description()` and resolves it to a token symbol via `GetSymbolsFromDescription`, storing the result in `state.USDFeeds[key]`: [2](#0-1) 

2. **FeeQuoter configuration**: `UpdateTokenPriceFeedsFeeQuoterChangeset` takes the resolved `feed := state.Chains[cfg.FeedChainSelector].USDFeeds[update.SourceToken]` (i.e. the BTC/USD feed for WBTC) and wires it directly into the on-chain `FeeQuoter.UpdateTokenPriceFeeds` as `DataFeedAddress`: [3](#0-2) 

The `FeeQuoter` then reports this BTC/USD-derived price via `getTokenPrice`/`getValidatedTokenPrice`, which callers rely on as the WBTC/USD price: [4](#0-3) 

Similarly, non-FeeQuoter token-pool views (v1.5/v1.5.1 `TokenPool`) resolve `usdFeedOrDefault(tokenSymbol)` to the same base-asset feed for reporting/config purposes: [5](#0-4) 

This is not limited to WBTC — the same design is applied systemically to other wrapped/bridged assets: `WBNB`→`BNB/USD`, `WAVAX`→`AVAX/USD`, `WPOL`→`MATIC/USD`, `WCORE`→`ARB/USD`, `WAPE`/`WHSK`/`WCRO`→`USDC/USD`, `WHYPE`→`LTC/USD`: [1](#0-0) 

None of these are the wrapped token's own price feed; there is no WBTC/BTC combination or depeg-check logic anywhere in this configuration path.

### Impact Explanation
The `FeeQuoter`'s reported USD price for a wrapped token is used to:
- Compute cross-chain transfer fees (`MinFeeUSDCents`/`MaxFeeUSDCents`/`DeciBps` in `TokenTransferFeeConfig`), and
- Enforce the USD-denominated `AggregateRateLimitEnabled` value cap for token transfers [6](#0-5) 

If a wrapped token (e.g. WBTC) depegs from its underlying asset (BTC), as has happened historically, the on-chain USD price used by CCIP's `FeeQuoter` will misreport the token's actual USD value. This causes:
- Incorrect fee charging (under/over-charging cross-chain transfer fees), and
- Miscalculated aggregate USD rate-limit consumption, allowing more or less real USD value to be transferred through a lane than the configured cap intends — a data-tampering/misreporting condition in a core CCIP pricing/validation path.

### Likelihood Explanation
This requires an actual depeg event of the wrapped asset from its underlying collateral (an external market condition, not directly attacker-triggered), matching the low/moderate likelihood profile of the original report. However, because this is a hard-coded, systemic design decision applied to numerous wrapped-token symbols across the CCIP token registry (not a one-off bug), any of these tokens depegging activates the flaw without requiring any additional code change or attacker action.

### Recommendation
For each wrapped/bridged token registered in `DescriptionToTokenSymbols`, either:
- Source a token-specific price feed (e.g., a genuine `WBTC/USD` feed where available), or
- Combine two feeds (e.g., `WBTC/BTC` × `BTC/USD`) as recommended in the referenced report, or
- Add a depeg/deviation sanity check (bound the wrapped-asset price against the base-asset price, and pause/flag pricing if the deviation exceeds a threshold) before trusting the base-asset feed for fee and rate-limit computations.

### Proof of Concept
1. Deploy/operate a CCIP lane with WBTC as a transferred/fee token; run `UpdateTokenPriceFeedsFeeQuoterChangeset` with `SourceToken = WBTCSymbol` — the changeset resolves `state.Chains[cfg.FeedChainSelector].USDFeeds[WBTCSymbol]`, which (per `DescriptionToTokenSymbols`) is the on-chain `BTC / USD` Chainlink aggregator, not a WBTC-specific feed [7](#0-6) .
2. `FeeQuoter.UpdateTokenPriceFeeds` is called with this `DataFeedAddress`, so `FeeQuoter.getTokenPrice(WBTC)` now always reports the BTC/USD price regardless of WBTC's actual market price [8](#0-7) .
3. Simulate a WBTC depeg (e.g., WBTC trading at 0.95x BTC). `FeeQuoter` still reports WBTC at full BTC/USD price. Any CCIP lane transferring WBTC with `AggregateRateLimitEnabled` or USD-based fee tiers will compute an inflated USD value for the same amount of (depegged) WBTC, letting more real economic value than intended pass the rate limiter and/or miscalculating transfer fees.
