### Title
PoX-5 signer weight can be inflated beyond the staker's true STX proportion by fragmenting a stake across many `signer_key`s in the Hare-quota leftover round - (File: stackslib/src/chainstate/nakamoto/signer_set.rs)

### Summary
`NakamotoSigners::pox_5_make_signer_set` apportions Nakamoto block-signing weight to `signer_key`s using a largest-remainder ("Hare quota") method: each signer gets `floor(stacked/threshold)` base weight, and the `reward_slots - base` leftover slots go one-per-signer, ranked by fractional remainder (`stacked % threshold`), descending. Because aggregation is keyed strictly by `signer_key` [1](#0-0) , a single economic staker who registers multiple `signer_key`s can split one stake into several sub-threshold pieces, each carrying a large remainder, and thereby capture more of the shared leftover-slot pool than a single lumped entry (and hence more voting weight) than their real proportional stake warrants — the same "fragment into many small units to raid a fixed/rounding-based pool" pattern as the Kairos `sendInterests` bug.

### Finding Description
The threshold ("quota") is computed once from the total locked STX across *all* entries and is unaffected by how many keys any one staker uses: [2](#0-1) 

Weight is then assigned per-`signer_key` via floor-division plus an at-most-one-slot leftover bonus decided by descending remainder: [3](#0-2) 

The per-entry "quota property" (weight ∈ {base, base+1}) holds for each *entry*, but nothing aggregates entries by the real staker identity before the leftover round runs — only by `signer_key`. An attacker who splits stake `S` into `N` pieces, each sized just under `threshold` (so each floors to base weight 0, but has a large remainder), turns what would be a single entry's "at most +1" bonus into up to `N` separate leftover-slot wins, so long as legitimate stakers' remainders are smaller. This directly steals leftover slots that would otherwise have gone to honest stakers with larger absolute stake but a smaller fractional remainder.

### Impact Explanation
`weight` from `pox_5_make_signer_set` becomes each signer's entry in the PoX-5 `RewardSet::Waterfall` signer set, which is used to compute `total_signing_weight`, and consequently the Nakamoto block-approval threshold and the 30%+ "blocking minority" rejection threshold in `NakamotoBlockHeader::verify_signer_signatures` / `compute_voting_weight_threshold` [4](#0-3) , and in the signer-side quorum bookkeeping (`reached_agreement`/`reached_disagreement`, `weight_threshold`) [5](#0-4) [6](#0-5) . By fragmenting stake across multiple `signer_key`s, a staker with materially less locked STX than another can obtain equal or greater signing weight, letting them approve or, more importantly, block blocks (reach the >30% blocking-minority threshold) with less real economic stake than the protocol intends signers to need. This breaks the invariant that voting/blocking power in Nakamoto consensus is proportional to locked STX, degrading the security assumption underlying block finality without requiring a majority of stake — an unprivileged, minority-triggerable distortion of the signer-weight equality.

### Likelihood Explanation
Any staker can register an arbitrary number of distinct `signer_key`s under PoX-5 stacking calls with no minimum per-key requirement beyond staying under `threshold` per fragment (fragment amounts under `threshold` are exactly the ones with base weight 0 and maximal remainder, i.e., cheapest to arrange). No special privilege, node-operator access, or majority stake is required — only enough real stake to be economically active as a signer, plus the ability to split it across many self-controlled keys. This is entirely unprivileged and deterministic once conditions (many sub-threshold pieces with large remainders vs. legitimate low-remainder stakers) are met.

### Recommendation
Aggregate by the underlying staker/stacker identity (or STX-owning principal) before running the Hare/largest-remainder leftover round, not solely by `signer_key`, so that splitting one staker's STX across multiple signer keys cannot manufacture additional leftover-slot wins beyond what the staker's total locked amount would earn as a single entry. Alternatively, cap total leftover slots awarded to entries sharing the same controlling stacker principal.

### Proof of Concept
Let `reward_slots = 10`, giving `threshold = ceil(total_locked / 10)`. Set `threshold = 100`.

- Legit staker `L` locks `500` (exact multiple of threshold): `base_L = 5`, `remainder_L = 0`.
- Attacker `A` locks `399` total.

Lumped (single `signer_key`):
- `base_A = 3`, `remainder_A = 99`.
- `sum_base = 8`, `leftover = 2`.
- Ranked by remainder: `A(99) > L(0)` → both entities receive the leftover bonus (only 2 entities, 2 leftover slots).
- Final: `weight_A = 4`, `weight_L = 6`.

Fragmented (attacker splits `399` into 5 `signer_key`s: `80, 80, 80, 80, 79`):
- Each piece `< threshold` ⇒ `base = 0` for all 5, remainders `= {80,80,80,80,79}`.
- `sum_base = 5` (from `L` only), `leftover = 5`.
- Ranked by remainder, top 5 are all attacker pieces (`80,80,80,80,79`), all strictly greater than `L`'s remainder of `0` → attacker's 5 pieces sweep all 5 leftover slots; `L` gets none.
- Final: `weight_A(total across 5 keys) = 5`, `weight_L = 5`.

Result: by fragmenting identical real stake (`399`) across 5 keys instead of 1, the attacker raises its total signing weight from `4` to `5` (a 25% increase) while the honest staker `L` — who locked *more* real STX (`500` vs `399`) — loses weight from `6` down to `5`, ending up with **equal** signing power to the attacker despite locking substantially more STX. This is computed identically in `pox_5_make_signer_set` [7](#0-6)  and is directly testable by feeding these `RawPox5Entry` inputs into the function as done in the existing property tests [8](#0-7) .

    pub(crate) fn pox_5_make_signer_set<I>(
        entries: &mut I,
        pox_constants: &PoxConstants,
    ) -> Result<Pox5SignerSetOutput, ChainstateError>
    where
        I: Iterator<Item = Result<RawPox5Entry, PoxEntryParsingError>>,
    {
        let mut signer_set = HashMap::new();
        let mut total_ustx_locked = 0u128;
        for entry_res in entries {
            let entry = match entry_res {
                Ok(x) => x,
                Err(PoxEntryParsingError::Skip(err_str)) => {
                    warn!(
                        "Error while iterating PoX-5 entries, impacting a single entry. Dropping entry from signer set";
                        "error" => err_str
                    );
                    continue;
                }
                Err(PoxEntryParsingError::Abort(err_str)) => {
                    error!(
                        "Abort-triggering error while iterating PoX-5 entries";
                        "error" => err_str
                    );
                    return Err(ChainstateError::PoxNoRewardCycle);
                }
            };

            total_ustx_locked += entry.amount_ustx;

            signer_set
                .entry(entry.signer_key)
                .and_modify(|existing_entry| *existing_entry += entry.amount_ustx)
                .or_insert_with(|| entry.amount_ustx);
        }

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

#[test]
fn duplicate_signer_keys_are_aggregated() {
    let pox_constants = test_pox_constants(1_000);
    let key = signer_key(0xAA);
    let entries = vec![
        RawPox5Entry {
            signer_key: key,
            amount_ustx: 600_000,
        },
        RawPox5Entry {
            signer_key: key,
            amount_ustx: 400_000,
        },
    ];
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");
    assert_eq!(signer_set.len(), 1);
    assert_eq!(signer_set[0].signing_key, key);
    assert_eq!(signer_set[0].stacked_amt, 1_000_000);
}

#[test]
fn weight_zero_entries_are_filtered() {
    // reward_slots == 4. Four big signers with equal stake consume all four
    // leftover slots (their remainders are larger than the dust signer's), so
    // the dust signer wins no slot and is filtered out.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    assert_eq!(pox_constants.reward_slots(), 4);
    let dust = signer_key(0xFF);
    let mut entries: Vec<_> = (0..4u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: 10_000_000,
        })
        .collect();
    entries.push(RawPox5Entry {
        signer_key: dust,
        amount_ustx: 1,
    });
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");
    assert_eq!(signer_set.len(), 4);
    assert!(
        !signer_set.iter().any(|e| e.signing_key == dust),
        "dust signer should have been filtered out"
    );
    // The four big signers split the four slots evenly.
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, 4);
}
