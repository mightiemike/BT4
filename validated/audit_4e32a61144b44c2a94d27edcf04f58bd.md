### Title
Declared PRC20 `liquidity_cap` is never enforced during inbound minting, allowing unbounded synthetic-token issuance beyond the configured cap - (File: `x/uexecutor/keeper/handler.go`)

### Summary
`TokenConfig.LiquidityCap` is a chain-registry field intended to bound the total synthetic supply of a bridged PRC20 asset, analogous to `term.maxDebt` in the bond-market circuit breaker report. Just as the SDA circuit breaker only closed the market *after* a purchase had already breached `maxDebt` — letting a single transaction blow past the intended limit — Push Chain's `LiquidityCap` invariant is checked nowhere at all in the honest-validator-driven minting path, so it never gates minting even after the fact.

### Finding Description
`TokenConfig.LiquidityCap` is required to be a non-empty string at registration time (`ValidateBasic`) [1](#0-0) , and it's advertised as the "max supply cap for this token" both in the proto comment and the module README [5](#0-4) [2](#0-1) .

The inbound execution flow that actually mints PRC20 tokens to a recipient — `ExecuteInboundFunds` → `depositPRC20` → `CallPRC20Deposit` — never fetches, tracks, or compares against `LiquidityCap`:
- `depositPRC20` looks up the `TokenConfig` only to resolve the PRC20 contract address, ignoring `LiquidityCap` entirely [3](#0-2) .
- `CallPRC20Deposit` issues the mint via `DerivedEVMCall("depositPRC20Token", ...)` with no pre-check of cumulative minted supply against any cap [4](#0-3) .
- `handleFailedOutbound`'s re-mint-on-revert path (`CallPRC20Deposit`) similarly has no cap check [6](#0-5) .

I found no cap-tracking state (no running "total minted" counter, no comparison against `LiquidityCap`) anywhere in `x/uexecutor` or `x/uregistry` keeper code — `LiquidityCap` only appears in proto marshal/unmarshal code and `ValidateBasic`'s non-empty check.

### Impact Explanation
Because the cap is purely declarative and never enforced against actual on-chain PRC20 supply, an unprivileged external user can deposit (via real, honestly-observed source-chain events, going through the normal `MsgVoteInbound` quorum path) arbitrarily large or arbitrarily many amounts of a whitelisted asset, and Push Chain will mint a matching PRC20 amount every time with no ceiling. This corrupts PRC20 accounting invariants the protocol explicitly documents (liquidity cap as a supply/backing bound), and can be used to over-mint a synthetic asset far past its intended backing/liquidity assumptions — a direct violation of the "corruption of PRC20 or native asset accounting" allowed-impact category. Unlike the original bond report where the *breach amount* is bounded by one transaction's `maxPayout`, here there is no bound whatsoever: repeated legitimate deposits can drive total PRC20 supply arbitrarily above the configured cap indefinitely, with no circuit breaker ever tripping.

### Likelihood Explanation
High reachability: this requires nothing but ordinary, honest inbound deposits from any external user through the standard `MsgVoteInbound` → quorum → `ExecuteInboundFunds` path — no privileged action, no malicious validator, and no protocol misconfiguration beyond having set a `liquidity_cap` value that the code silently never checks. Every deployed token config in the repo's own config fixtures sets a `liquidity_cap`, confirming this is an active, relied-upon field in production configs, not a legacy/unused one [7](#0-6) .

### Recommendation
Track cumulative minted PRC20 supply per token (or query it from the PRC20 contract) and enforce it against `TokenConfig.LiquidityCap` inside `depositPRC20` (and the failed-outbound re-mint path) before calling `CallPRC20Deposit`. If a deposit would exceed the cap, either partially mint up to the cap and refund/revert the remainder (mirroring the bond report's own recommendation), or reject/queue the inbound for manual/admin handling rather than silently minting past the declared limit.

### Proof of Concept
1. Admin registers a token config with `liquidity_cap = "1000000000000000000000000"` (as done in every fixture, e.g. `config/testnet-donut/eth_sepolia/tokens/usdc.json`).
2. An external user deposits a source-chain amount into the gateway that, once bridged, would mint PRC20 tokens exceeding the configured `liquidity_cap` — either via one very large deposit or many smaller ones.
3. Honest UVs observe and vote `MsgVoteInbound` for each deposit; quorum is reached normally.
4. `ExecuteInboundFunds` → `depositPRC20` → `CallPRC20Deposit` mints the full amount every time, with no code path anywhere comparing minted totals to `LiquidityCap`.
5. Total PRC20 supply now exceeds the declared cap with no error, no circuit breaker, and no admin alert — confirmed by the absence of any `LiquidityCap` reference in `x/uexecutor/keeper/**` (only `ValidateBasic`'s non-empty string check and protobuf marshal code reference the field anywhere in the codebase).

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

func (k Keeper) CallPRC20Deposit(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // sender: module account
		handlerAddr,        // destination
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20Token",
		prc20Address,
		amount,
		to,
	)
}

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}
