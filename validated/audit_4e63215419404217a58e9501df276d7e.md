**Reasoning:**

The exploit premise assumes there's a state where `ConfigShadowV1` exists "with an unset grace period" that could be confused with "no config resource exists." That state doesn't exist in this code. `ConfigShadowV1` requires `grace_period_secs: u64` as a mandatory field with no `Option` wrapper — it's always a concrete value, set at construction time via `new_shadow_v1()`. [1](#0-0) 

The `grace_period_secs()` function has exactly three possible outcomes, none of which are ambiguous with each other:
1. No `ChunkyDKGConfig` resource exists at `@aptos_framework` → `option::none()`.
2. Resource exists but is `ConfigOff` or `ConfigV1` variant (not shadow mode) → falls through to `option::none()`.
3. Resource exists and is `ConfigShadowV1` → `option::some(shadow_v1.grace_period_secs)` with the actual concrete value. [2](#0-1) 

Cases 1 and 2 are semantically identical: both mean "shadow-mode grace period watchdog is not active," and `None` correctly represents both. There is no "resource-present-with-none" state to distinguish from "resource-absent," because the Move type system doesn't permit a `ConfigShadowV1` instance without a concrete `grace_period_secs` value — the struct field isn't optional. The Rust-side mirror confirms the same invariant: `ConfigShadowV1` always carries a plain `u64`. [3](#0-2) 

Separately, ledger-version binding for any view-function call (including this one) is handled generically by the API/state-view layer, which resolves the queried state at a specific requested version — this function's return value doesn't independently encode or need to encode version/object binding; that's orthogonal to the `Option` semantics being questioned here.

Since the described "ambiguous state" cannot occur, there is no unprivileged-input path that can cause an authenticated caller to misbind a response to the wrong ledger object/version/proof context based on this function's behavior. This does not meet the state-integrity gate (no corrupted committed state, no wrong proof/root/version binding, no hard-fork divergence) — it's a false premise about the possible state space, not an actual vulnerability.
