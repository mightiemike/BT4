### Title
Contract-address deployment guard permits deployment onto the reserved Alias Contract Address (0x2) - ([File: crates/starknet_api/src/core.rs])

### Summary
`ContractAddress::validate` in `starknet_api` only excludes addresses `<= 0x1` (the block-hash table address) from the "valid external contract address" range, but the protocol reserves three special addresses — `BLOCK_HASH_CONTRACT_ADDRESS = 0x1`, `ALIAS_CONTRACT_ADDRESS = 0x2`, and `RESERVED_CONTRACT_ADDRESS = 0x3` — as documented in `crates/apollo_starknet_os_program/.../constants.cairo`. This mirrors the reported bug class: a path/address exclusion guard that omits part of the sensitive range it was meant to protect (the credential-store analog here is the alias-contract storage that backs stateful compression).

### Finding Description
`ContractAddress::validate` computes:
```
value > BLOCK_HASH_TABLE_ADDRESS.0.0 (i.e. value > 1) && value < L2_ADDRESS_UPPER_BOUND
``` [1](#0-0) 

This means addresses `0x2` (`ALIAS_CONTRACT_ADDRESS`) and `0x3` (`RESERVED_CONTRACT_ADDRESS`) pass this "valid address" check even though the OS constants reserve them: [2](#0-1) 

The only place that actually excludes deployment onto `ALIAS_CONTRACT_ADDRESS`/`RESERVED_CONTRACT_ADDRESS` (in addition to `BLOCK_HASH_CONTRACT_ADDRESS` and `ORIGIN_ADDRESS`) is a separate, narrower guard inside the Cairo `deploy_contract` function in the Starknet OS program, which explicitly checks the deployed `contract_address` against all four reserved constants via a product-is-nonzero assertion: [3](#0-2) 

`ContractAddress::validate` is a different, independent guard used broadly at the Rust/API layer (transaction field validation), and it does not encode the same reserved set — it stops after excluding `0x1`. If any transaction validation path (e.g. gateway/stateless validation of `sender_address`, `contract_address_salt`-derived deploy address, or L1 handler `to_address`) relies on `ContractAddress::validate` as its sole check for "not a reserved/special address" rather than on the stricter Cairo OS-level exclusion, an attacker-controlled address of `0x2` or `0x3` will be accepted as "valid" at that layer even though it is one of the three protocol-reserved addresses.

### Impact Explanation
If `0x2`/`0x3` addresses are treated as ordinary valid contract addresses anywhere state-mutating logic depends on `ContractAddress::validate()` alone (rather than the Cairo-level 4-way exclusion), an attacker could get storage writes routed to the alias-contract address's storage domain, corrupting the alias-counter/alias-mapping (`ALIAS_COUNTER_STORAGE_KEY`, alias entries) used by `allocate_aliases_in_storage`/`AliasCompressor` for stateful compression: [4](#0-3) [5](#0-4) 
Corrupting the alias contract's counter or mapping (e.g. resetting the counter, colliding aliases) would cause `AliasCompressor::compress_address`/`compress_storage_key` to produce different alias mappings for honest full nodes vs. the OS re-execution/committed state, leading to state-root divergence or a `MissedAlias` failure that halts OS re-execution — i.e., wrong committed root / honest-node divergence, which matches the required impact bar.

### Likelihood Explanation
This requires confirming that some transaction admission/state-mutation path actually calls `ContractAddress::validate()` as the only reserved-address check and that this path is reachable without going through the stricter Cairo `deploy_contract` product-check (e.g., normal storage writes via `set_storage_at`/syscalls to an already-"valid" address `0x2`, or a deploy path that doesn't re-derive the OS-level check). I was not able to fully trace every call site of `ContractAddress::validate()` in the given iterations (only `abi_utils.rs`, `accessed_keys.rs`, and `blockifier_versioned_constants.rs` were inspected in depth; the gateway `stateless_transaction_validator.rs` matches were not read in full before the tool budget ran out). Given the uncertainty about whether any reachable, unprivileged path relies on this specific incomplete guard as the sole protection (versus defense-in-depth alongside the Cairo-level check), likelihood is **not confirmed** with the available evidence.

### Recommendation
- Read the full call sites of `ContractAddress::validate()` in `crates/apollo_gateway/src/stateless_transaction_validator.rs` and other gateway/mempool validation code to confirm whether it is used as a standalone guard against reserved addresses.
- If confirmed, widen `ContractAddress::validate` to reject the full reserved range (`0x1`–`0x3`, i.e. up through `RESERVED_CONTRACT_ADDRESS`) rather than only `<= BLOCK_HASH_TABLE_ADDRESS (0x1)`, keeping it consistent with the OS-level `deploy_contract` reserved-address check.

### Proof of Concept
Not able to construct a concrete end-to-end PoC transaction within the available tool budget, because the exact reachable caller of `ContractAddress::validate()` that would allow a transaction with `sender_address`/`contract_address` = `0x2` or `0x3` to bypass reserved-address exclusion was not fully verified. This should be validated by tracing all callers of `ContractAddress::validate` (especially in `apollo_gateway::stateless_transaction_validator`) before treating this as a confirmed, exploitable analog.

impl ContractAddress {
    /// Validates the contract address is in the valid range for external access.
    /// The lower bound is above the special saved addresses and the upper bound is congruent with
    /// the storage var address upper bound.
    pub fn validate(&self) -> Result<(), StarknetApiError> {
        let value = self.0.0;
        let l2_address_upper_bound = Felt::from(*L2_ADDRESS_UPPER_BOUND);
        if (value > BLOCK_HASH_TABLE_ADDRESS.0.0) && (value < l2_address_upper_bound) {
            return Ok(());
        }

        Err(StarknetApiError::OutOfRange { string: format!("[0x2, {l2_address_upper_bound})") })
    }

impl<S: StateReader> AliasCompressor<'_, S> {
    fn compress_address(
        &self,
        contract_address: &ContractAddress,
    ) -> CompressionResult<ContractAddress> {
        if should_compress_address(contract_address) {
            Ok(self.get_alias(StorageKey(contract_address.0))?.try_into()?)
        } else {
            Ok(*contract_address)
        }
    }

    fn compress_storage_key(
        &self,
        storage_key: &StorageKey,
        contract_address: &ContractAddress,
    ) -> CompressionResult<StorageKey> {
        if should_compress_storage_key(storage_key, contract_address) {
            Ok(self.get_alias(*storage_key)?.try_into()?)
        } else {
            Ok(*storage_key)
        }
    }

    fn get_alias(&self, alias_key: AliasKey) -> CompressionResult<Alias> {
        let alias = self.state.get_storage_at(self.alias_contract_address, alias_key)?;
        if alias == Felt::ZERO { Err(CompressionError::MissedAlias(alias_key)) } else { Ok(alias) }
    }
