## Analysis

**Binding claimed:** `process_complete_proof(body)` state-advancing effect == applied at most once, i.e. for a fixed proof body, `(last_l2_height_before, last_sequencer_commitment_index_before)` after a second submission must equal the values after the first submission (no double-advance).

**Trace of the code path:**

For `DataOnDa::Aggregate(_, wtxids)`, after the sender check (`blob.sender().as_ref() != batch_prover_da_public_key`), the circuit reconstructs `complete_proof` purely by `ChunkAccessor::<S>::get(*wtxid, ...)` for each `wtxid` in the aggregate, with no bookkeeping that marks chunks as "consumed": [1](#0-0) 

`ChunkAccessor::get` is a pure, non-destructive read — re-running the same lookup for the same `wtxid`s in a later L1 block reconstructs an *identical* `complete_proof` byte string, deterministically. This is not itself a flaw: chunks are content-addressed by `wtxid`, and re-reading them is idempotent.

The reconstructed proof is passed to `process_complete_proof`, which enforces two independent monotonicity guards *before* any state write: [2](#0-1) [3](#0-2) 

Both `last_l2_height` and `last_sequencer_commitment_index` are read from the *previous* light client proof's persisted output at the top of `run_l1_block`, i.e., they reflect state already advanced by the first (legitimate) processing of that same complete proof: [4](#0-3) 

Since a replayed Aggregate (same `wtxids`, same chunk bodies, hence same decompressed `complete_proof` bytes) produces the identical `batch_proof_output_last_l2_height` and `batch_proof_output_last_commitment_index` as the first time it was processed, both guard conditions (`<=`) trigger on the second submission and `process_complete_proof` returns `Err(...)`, which is caught and only logged, causing no JMT writes: [5](#0-4) 

**On the signature-replay premise:** The question also raises whether an attacker without the batch prover's key could forge a *new* Bitcoin transaction carrying the prover's old signature bytes over the identical body (since the signature covers blob body, not tx identity — confirmed by `parse_type_0_body`, which reads `signature`/`public_key`/`chunks` independent of the enclosing transaction): [6](#0-5) 

This is indeed possible — reusing an old valid `(body, signature, public_key)` triple in a freshly-inscribed transaction with a different wtxid will still pass `aggregate.public_key() == prover_da_pub_key && aggregate.get_sig_verified_hash().is_some()` / `blob.sender().as_ref() == batch_prover_da_public_key`, because signature binding is to body bytes, not transaction identity. However, since the replayed body is byte-identical to a previously-processed one, it decompresses to the same `complete_proof`, whose `last_l2_height`/`last_commitment_index` are already **not** strictly greater than the state's current values — so the guards above reject it regardless of the transaction being "new."

**Conclusion:** Both sides of the equality match before and after the replay attempt — `last_l2_height` and `last_sequencer_commitment_index` are unchanged, no `VerifiedStateTransitionForSequencerCommitmentIndex` entries are added, and no state root advances. The lack of a chunk-consumption tracking mechanism is irrelevant because the downstream monotonicity checks in `process_complete_proof` (lines 284 and 318) fully neutralize any replay of an already-applied complete proof, whether reconstructed from re-read chunks or from a signature replayed onto a newly-crafted transaction. This matches the existing test pattern that explicitly verifies `last_l2_height`/`last_sequencer_commitment_index` staying pinned across repeated/overlapping proof submissions: [7](#0-6)

    pub(super) fn parse_type_0_body(
        instructions: &mut dyn Iterator<Item = Result<Instruction<'_>, ParserError>>,
    ) -> Result<ParsedComplete, ParserError> {
        let op_false = read_push_bytes(instructions)?;
        if !op_false.is_empty() {
            // OP_FALSE = OP_PUSHBYTES_0
            return Err(ParserError::UnexpectedOpcode);
        }

        if OP_IF != read_opcode(instructions)? {
            return Err(ParserError::UnexpectedOpcode);
        }

        let signature = read_push_bytes(instructions)?;
        let public_key = read_push_bytes(instructions)?;

        let mut chunks = vec![];

        loop {
            let instr = read_instr(instructions)?;
            match instr {
                PushBytes(chunk) => {
                    if chunk.is_empty() {
                        return Err(ParserError::UnexpectedOpcode);
                    }
                    chunks.push(chunk)
                }
                Op(OP_ENDIF) => break,
                Op(_) => return Err(ParserError::UnexpectedOpcode),
            }
        }

        // Nonce
        let _nonce = read_push_bytes(instructions)?;
        if OP_NIP != read_opcode(instructions)? {
            return Err(ParserError::UnexpectedOpcode);
        }
        // END of transaction
        if instructions.next().is_some() {
            return Err(ParserError::UnexpectedOpcode);
        }

        let body_size: usize = chunks.iter().map(|c| c.len()).sum();
        let mut body = Vec::with_capacity(body_size);
        for chunk in chunks {
            body.extend_from_slice(chunk.as_bytes());
        }

        let signature = signature.as_bytes().to_vec();
        let public_key = public_key.as_bytes().to_vec();

        Ok(ParsedComplete {
            body,
            signature,
            public_key,
        })
