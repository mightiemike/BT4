### Title
Unauthenticated `/v2/resume/:runID` Endpoint Allows Anyone to Re-Trigger and Inject Arbitrary Results Into Suspended Pipeline Runs - (File: core/web/pipeline_runs_controller.go)

### Summary
The Atlas report describes a function reachable by any unprivileged caller that rolls back a deposit's failure status and re-triggers execution without validating whether the underlying error condition (e.g., an invalid receiving address) has actually been resolved, allowing indefinite, costly re-execution of operations that are guaranteed to fail. The closest analog in this chainlink checkout is the `PipelineRunsController.Resume` handler, mounted with **no authentication middleware at all**, which lets any network caller resume/finish a suspended pipeline task and inject its own value/error for that task, restarting run execution without verifying the caller is the legitimate bridge/external adapter that the run was suspended for.

### Finding Description
The route is registered completely outside any auth group: [1](#0-0) 

`Resume` decodes an arbitrary caller-supplied JSON body into a `pipeline.ResumeRequest`, converts it into a `pipeline.Result` (value or error), and forwards it straight to `App.ResumeJobV2` keyed only by the `runID` path param (a task UUID) — with zero authentication and zero validation that the caller is the async bridge/adapter that owns that specific pending task: [2](#0-1) 

`ResumeJobV2` forwards directly into the pipeline runner: [3](#0-2) 

`ResumeRun` then updates the task result and, if the underlying run was `suspended`, restarts execution of the entire pipeline run in a new goroutine: [4](#0-3) 

The only gating check is `orm.UpdateTaskRunResult`'s `WHERE ... pipeline_runs.state in ('running', 'suspended')` clause — it does not verify the caller's identity, does not check whether the previously supplied error is a "permanent" one (e.g., malformed inputs that will always fail), and does not rate-limit or restrict who may resume a given `runID`: [5](#0-4) 

This is structurally the same defect class as the Atlas report: a state-transition/re-execution trigger is exposed without restricting who can invoke it and without validating that the invocation is legitimate or that the underlying condition justifies re-execution — the only difference is that the "authentication" for legitimate use here is an unguessable UUID rather than an explicit credential, and the endpoint accepts the request from *anyone*, not just the adapter that should own that UUID.

### Impact Explanation
Any unauthenticated network caller who obtains or brute-forces/guesses a pending task UUID (e.g., via log/network leakage, timing, or a compromised bridge relay path) can:
- Inject an attacker-controlled value or error into a suspended pipeline task, which is subsequently used to compute the job's final on-chain result (e.g., feeding a fabricated price/answer into an OCR/Flux round, or forcing an ETHTx task down an error path), i.e., misreporting/data tampering.
- Force repeated resumption/restart cycles of the same or other pending runs, driving repeated pipeline (re-)execution and downstream side effects (e.g., additional DB writes, task re-scheduling, wasted node/adapter cycles) — mirroring the "repeated re-execution burden" impact described in the report, since nothing here validates that resuming is appropriate before restarting execution.

### Likelihood Explanation
The endpoint is unauthenticated by design (`unauthedv2` group), and its security currently rests entirely on task UUIDs being unguessable and not otherwise disclosed. Any leak of a pending `runID` (logs, adapter misconfiguration, network observation of the bridge callback URL) is sufficient for exploitation, with no additional secret or session required.

### Recommendation
- Require the resuming caller to present a per-run/per-task secret (not just the UUID) or restrict the endpoint to be callable only from configured bridge adapter addresses/IP allow-lists.
- Add explicit checks in `ResumeRun`/`UpdateTaskRunResult` to validate the caller is authorized for that specific `taskID`, and audit/rate-limit resume attempts per task.

### Proof of Concept
1. Observe or otherwise obtain a pending async task's `runID` (UUID) that is embedded in a bridge adapter's `responseURL` (`http://localhost:6688/v2/resume/<uuid>`), as illustrated in test code that inspects the `X-Chainlink-Pending` callback pattern: [6](#0-5) 
2. Without any credentials, send `PATCH /v2/resume/<uuid>` with an attacker-chosen `{"error": "..."}` or `{"value": "..."}` body.
3. `PipelineRunsController.Resume` accepts the request unauthenticated, calls `ResumeJobV2` → `ResumeRun`, which updates the task result and restarts pipeline execution with attacker-supplied data, as shown in [7](#0-6)  and [4](#0-3) .

// Resume finishes a task and resumes the pipeline run.
// Example:
// "PATCH <application>/jobs/:ID/runs/:runID"
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
}

		Value: value,
		Error: err,
	})
	if err != nil {
		return fmt.Errorf("failed to update task run result: %w", err)
	}

	// TODO: Should probably replace this with a listener to update events
	// which allows to pass in a transactionalised database to this function
	if start {
		// start the runner again
		go func() {
			ctx, cancel := r.chStop.NewCtx()
			defer cancel()
			if _, err := r.Run(ctx, &run, false, nil); err != nil {
				r.lggr.Errorw("Resume run failure", "err", err)
			}
			r.lggr.Debug("Resume run success")
		}()
	}
	return nil
}

func (o *orm) UpdateTaskRunResult(ctx context.Context, taskID uuid.UUID, result Result) (run Run, start bool, err error) {
	if result.OutputDB().Valid && result.ErrorDB().Valid {
		panic("run result must specify either output or error, not both")
	}
	err = o.transact(ctx, func(tx *orm) error {
		sql := `
		SELECT pipeline_runs.*, pipeline_specs.dot_dag_source "pipeline_spec.dot_dag_source", job_pipeline_specs.job_id "job_id"
		FROM pipeline_runs
		JOIN pipeline_task_runs ON (pipeline_task_runs.pipeline_run_id = pipeline_runs.id)
		JOIN pipeline_specs ON (pipeline_specs.id = pipeline_runs.pipeline_spec_id)
		JOIN job_pipeline_specs ON (job_pipeline_specs.pipeline_spec_id = pipeline_specs.id)
		WHERE pipeline_task_runs.id = $1 AND pipeline_runs.state in ('running', 'suspended')
		FOR UPDATE`
		if err = tx.ds.GetContext(ctx, &run, sql, taskID); err != nil {
			return fmt.Errorf("failed to find pipeline run for task ID %s: %w", taskID.String(), err)
		}

		// Update the task with result
		sql = `UPDATE pipeline_task_runs SET output = $2, error = $3, finished_at = $4 WHERE id = $1`
		if _, err = tx.ds.ExecContext(ctx, sql, taskID, result.OutputDB(), result.ErrorDB(), time.Now()); err != nil {
			return fmt.Errorf("failed to update pipeline task run: %w", err)
		}

		if run.State == RunStatusSuspended {
			start = true
			run.State = RunStatusRunning

			sql = `UPDATE pipeline_runs SET state = $2 WHERE id = $1`
			if _, err = tx.ds.ExecContext(ctx, sql, run.ID, run.State); err != nil {
				return fmt.Errorf("failed to update pipeline run state: %w", err)
			}
		}

		return loadAssociations(ctx, tx.ds, []*Run{&run})
	})

	return run, start, err
}
