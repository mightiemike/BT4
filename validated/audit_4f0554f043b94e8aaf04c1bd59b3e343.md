### Title
Uncaught `atob()` exception in `sanitizeHost`/`decodeHost` crashes auth handlers instead of returning `InvalidHostError` - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost` only filters `host` values by a base64 *character-set* regex before calling `decodeHost` (`atob`), but that regex does not enforce valid base64 length/padding, so a value like `host=A` passes the regex yet causes `atob` to throw an uncaught `DOMException`/`TypeError` instead of the typed `InvalidHostError`. Note that `packages/apps/shopify-api/lib/auth/oauth/oauth.ts`'s `callback` function does **not** actually call `sanitizeHost`/`decodeHost` at all, so the premise naming that function is incorrect; however, the underlying bug is real and reachable through other call sites.

### Finding Description
`sanitizeHost` in [1](#0-0)  validates `host` with `base64regex = /^[0-9a-zA-Z+/]+={0,2}$/` and, if it matches, immediately calls `decodeHost(sanitizedHost)`, which is a thin wrapper around the global `atob()`: [2](#0-1) . This regex accepts strings whose length is not a valid base64 length (e.g. a single character `"A"`, or any string whose length mod 4 equals 1), which the WHATWG forgiving-base64 `atob()` algorithm (used by Node's global `atob`) rejects by throwing a `DOMException`/`InvalidCharacterError`. That throw happens *before* the `throwOnInvalid`/`InvalidHostError` logic at the bottom of the function is reached, and it is not wrapped in try/catch anywhere in `sanitizeHost`.

This is reachable by an anonymous caller through `sanitizeHost`'s consumers, notably `validateShopAndHostParams` in the Remix/React Router `authenticate.admin()` flow (`packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-shop-and-host-params.ts`, `packages/apps/shopify-app-react-router/.../validate-shop-and-host-params.ts`), which calls `api.utils.sanitizeHost(url.searchParams.get('host')!)` directly on an unauthenticated request's `host` query parameter before any session/HMAC checks — the crash happens regardless of the `throwOnInvalid` flag value, since the `atob` call is unconditional once the regex passes. It is also reachable via `buildEmbeddedAppUrl`/`getEmbeddedAppUrl` in `packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts`, which calls `sanitizeHost(config)(host, true)` and then separately `decodeHost(host)` again.

The originally cited location, `oauth.ts`'s `callback` function, does not call `sanitizeHost` or `decodeHost` at all — it only uses `sanitizeShop`, `validateHmac`, and `safeCompare` [3](#0-2) , so the exact function named in the question is not the vulnerable path.

### Impact Explanation
An anonymous request to an app's admin-authentication entry route with a crafted `host` parameter (e.g. `host=A`) that matches the base64 charset regex but has invalid base64 length can throw an unhandled `DOMException`/`TypeError` inside `sanitizeHost`. Depending on the host framework's error handling around `authenticate.admin()`/`validateShopAndHostParams`, this results in an unhandled exception in an authentication-adjacent handler rather than the expected typed `InvalidHostError`, which is a fail-open-to-crash condition rather than fail-closed-with-typed-error, matching a DoS-class impact scoped to that request path.

### Likelihood Explanation
No privileged access or secrets are needed — any anonymous client can send a GET request with a crafted `host` query parameter to a route that invokes `sanitizeHost`/`validateShopAndHostParams`/`getEmbeddedAppUrl`. The bug is fully deterministic and repeatable with a single crafted parameter value.

### Recommendation
Tighten `base64regex` in `sanitizeHost` to require a valid base64 length (`length % 4 !== 1`, or full `^(?:[A-Za-z0-9+/]{4})*(?:[A-Za-z0-9+/]{2}==|[A-Za-z0-9+/]{3}=)?$`), and/or wrap the `decodeHost` call in `sanitizeHost` (and in `buildEmbeddedAppUrl`) in a try/catch that treats any decode failure as an invalid host, returning `null` or throwing `InvalidHostError` consistently with the `throwOnInvalid` contract.

import {shopifyApi} from '../..';
import {testConfig} from '../../__tests__/test-config';
import {InvalidHostError} from '../../error';

test('sanitizeHost should not throw a raw atob exception for malformed padding', () => {
  const shopify = shopifyApi(testConfig());

  // "A" passes /^[0-9a-zA-Z+/]+={0,2}$/ but is invalid base64 length (mod 4 == 1)
  expect(() => shopify.utils.sanitizeHost('A', true)).toThrow(InvalidHostError);
  // Currently this throws a DOMException/TypeError from atob(), not InvalidHostError
});
