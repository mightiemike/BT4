### Title
Missing protocol fee in outbound gas-and-fee resolution - (File: x/uexecutor/keeper/gas_fee.go)

### Summary
`GetOutboundTxGasAndFees` queries `UniversalCore.getOutboundTxGasAndFees`, which returns `gasToken`, `gasFee`, `protocolFee`, `gasPrice`, `chainNamespace`, and `gasLimitUsed`. The Go keeper unpacks all six values but deliberately discards `protocolFee` and does not expose it in the returned `GasFeeInfo`. This mirrors the external bug class where an ERC20 path forgets to transfer a service fee that the native path correctly includes.

### Finding Description
In `x/uexecutor/keeper/gas_fee.go`, `GetOutboundTxGasAndFees` calls the `UniversalCore` contract's `getOutboundTxGasAndFees` view. The contract returns six values, including a dedicated `protocolFee` output. The keeper reads `results[2]` into a commented-out local variable with the note "not needed for outbound fields" and the `GasFeeInfo` struct only carries `GasToken`, `GasFee`, `GasPrice`, and `GasLimit`. [1](#0-0)  The contract ABI in `x/uexecutor/types/abi.go` explicitly declares `protocolFee` as a separate `uint256` return value. [2](#0-1) 

### Impact Explanation
If `protocolFee` is intended to be part of the total cost of an outbound, the keeper's omission corrupts gas/fee accounting. Every outbound built from this helper will be underfunded by exactly the `protocolFee` amount, or the protocol will permanently fail to collect that fee. This falls under the allowed impact gate for "corruption of PRC20 or native asset accounting, gas fee accounting" and can constitute an unauthorized refund of the fee portion to the user.

### Likelihood Explanation
The path is reachable without any privileged or malicious-actor assumption. A normal unprivileged user submits an inbound or `MsgExecutePayload` whose payload triggers an outbound; the keeper then calls `GetOutboundTxGasAndFees` to price the outbound. Because the helper always drops `protocolFee`, the undercharge is deterministic and occurs on every outbound that relies on this pricing path.

### Recommendation
Add `ProtocolFee` to `GasFeeInfo` and ensure outbound construction uses `gasFee + protocolFee` (or the total the contract intends) when reserving, deducting, or encoding the outbound's fee budget. Verify the `UniversalCore` contract's intended semantics for `getOutboundTxGasAndFees` to confirm whether `gasFee` already includes `protocolFee` or whether the two must be summed.

### Proof of Concept
1. A user payload executes and triggers an outbound in `x/uexecutor/keeper/create_outbound.go` or `x/uexecutor/keeper/outbound.go`.
2. The keeper calls `GetOutboundTxGasAndFees` for the outbound PRC20.
3. `UniversalCore.getOutboundTxGasAndFees` returns `protocolFee = X` along with `gasFee`.
4. `GetOutboundTxGasAndFees` returns a `GasFeeInfo` containing `GasFee` but no `ProtocolFee` field, so downstream code cannot add `X` to the total.
5. The outbound is constructed with a fee budget of `GasFee` instead of `GasFee + X`, undercharging by `X`.
