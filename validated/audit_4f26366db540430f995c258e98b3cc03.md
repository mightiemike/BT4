Based on my investigation, I've confirmed the pattern: `GetSwapQuote` (`x/uexecutor/keeper/evm.go`) fetches a spot price from Uniswap V3's `QuoterV2.quoteExactInputSingle` at the moment of inbound execution, and `minPCOut` is derived purely as 95% of that same quote — with no independent oracle, TWAP, or off-chain price reference to validate it against, as documented in `app/upgrades/chain-meta/upgrade.go:63-67`. This is the closest structural analog to the HydraDX bug: a "slippage protection" that is computed from a manipulable, single-source price rather than an independent reference, so it bounds loss only relative to itself, not relative to fair value.

### Title
Self-referential slippage bound in GAS inbound auto-swap allows sandwich extraction from depositing users - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/evm.go)

### Summary
`ExecuteInboundGas` / `ExecuteInboundGasAndPayload` compute `minPCOut` as 95% of a same-transaction `GetSwapQuote` call against the live Uniswap V3 pool, then immediately execute `depositPRC20WithAutoSwap` against that same pool. Because the "protection" value is derived from the very price it is supposed to protect against, an unprivileged attacker who manipulates the WPC/PRC20 pool immediately before the module's swap executes can force the deposit to fill at an attacker-favorable price while still passing the `minPCOut` check, extracting value from the depositing user's inbound funds.

### Finding Description
`GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`) is a plain `CallEVM` (commit=false) read of `QuoterV2.quoteExactInputSingle`, reflecting the pool's instantaneous reserves. [1](#0-0) 

`ExecuteInboundGas` uses this quote to compute `minPCOut = quote * 95 / 100` and immediately calls `CallPRC20DepositAutoSwap` with that bound, all within the same keeper call during inbound-vote finalization: [2](#0-1) 

The identical pattern exists for `GAS_AND_PAYLOAD` in `gasAndPayloadDepositAutoSwap`: [3](#0-2) 

and for excess-gas refunds in `applyGasRefund`: [4](#0-3) 

The upgrade changelog confirms this design is intentional and recent — it replaced a prior 0-slippage call with this 5%-of-spot-quote bound: [5](#0-4) 

There is no reference to any TWAP/oracle-anchored price check anywhere in the repository (confirmed via search), so the 5% tolerance is measured only against a value the attacker can move within the same block, not against a fair/independent price — structurally identical to the HydraDX bug where the withdrawal fee was computed relative to a spot price that itself could be steered, rather than being gated against an independent oracle bound.

An unprivileged attacker who holds WPC/PRC20 liquidity-pool-moving capital can, prior to the block containing quorum-finalizing votes for a large GAS/GAS_AND_PAYLOAD inbound (or prior to the outbound gas-refund swap), skew the pool price. `GetSwapQuote` then returns a depressed amount, `minPCOut` is 95% of that depressed value, and `depositPRC20WithAutoSwap` executes at (or near) that depressed price — the victim's PRC20 is swapped into materially less native PC than fair value, with the difference capturable by the attacker via a follow-up trade restoring the pool.

### Impact Explanation
This directly corrupts native-asset accounting for the receiving UEA: an ordinary user's inbound GAS deposit (or the excess-gas refund on any outbound) mints/settles into less native PC than the true value of the bridged tokens, with the shortfall extractable by an unprivileged attacker. This matches "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" in the allowed-impact list and is reachable purely through ordinary user deposits plus ordinary (non-privileged) attacker market activity — no admin, validator, or TSS compromise is required.

### Likelihood Explanation
Requires the attacker to have capital sufficient to move the specific WPC/PRC20 pool's price meaningfully within the 5% band and to time it around inbound-vote quorum finalization or outbound observation — both of which are externally visible (pending votes/outbounds are queryable). Feasibility scales inversely with pool depth; for thinly-liquid PRC20 pairs this is straightforward.

### Recommendation
Anchor `minPCOut` to an independent, time-weighted or externally-sourced reference price (e.g., a TWAP over several blocks, or the same `ChainMeta`/gas-price oracle infrastructure already used elsewhere) rather than deriving it from the same-block spot quote of the pool being swapped against. Alternatively, cap deviation of the spot quote from a longer-window TWAP before allowing the auto-swap to proceed, reverting (not partially executing) if the pool appears to have been recently perturbed.

### Proof of Concept
1. Attacker identifies a PRC20/WPC Uniswap V3 pool with modest liquidity backing a GAS-type external chain used by Push Chain inbound bridging.
2. Attacker submits a large swap on Push Chain's EVM to move the pool price against the expected PRC20→WPC direction, immediately before/within the block where a pending GAS inbound's quorum vote is expected to land (visible via `PendingInbounds`).
3. When quorum finalizes, `ExecuteInboundGas` calls `GetSwapQuote` against the now-skewed pool, computing a depressed `minPCOut` (`x/uexecutor/keeper/execute_inbound_gas.go:134-145`).
4. `CallPRC20DepositAutoSwap` executes the victim's deposit swap at the skewed price, satisfying the artificially depressed `minPCOut`.
5. Attacker reverses their initial swap, realizing the value difference extracted from the victim's deposit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
