### Title
Partial DON fan-out failure leaks node-reachability info and orphans savedCallbacks slots - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` registers a `savedCallback` before fanning a request out to all DON members, then aggregates any `don.SendToNode` errors with `errors.Join` and returns them directly to the caller [1](#0-0) . `gateway.ProcessRequest` propagates that joined error text verbatim into the JSON-RPC error response sent back over the public user HTTP port, and critically never calls `callback.Wait` in that path, so the just-registered `savedCallback` is never resolved [2](#0-1) .

### Finding Description
An unprivileged caller sends a legacy `web_api_trigger` message to the gateway's user-facing port. `HandleLegacyUserMessage` validates the payload, then unconditionally stores the callback in `h.savedCallbacks[msg.Body.MessageId]` before attempting delivery [3](#0-2) . It then loops over every configured DON member and joins any `SendToNode` error into a single `err`, which is returned to the caller of `HandleLegacyUserMessage` [4](#0-3) .

In `gateway.ProcessRequest`, if that returned `err` is non-nil, the handler short-circuits and immediately converts `err.Error()` into the JSON-RPC error body returned to the HTTP client, without ever calling `callback.Wait(ctx)` [2](#0-1) . Two consequences follow directly from this code:

1. **Information disclosure**: because the joined error is surfaced verbatim to the unprivileged caller, differential error content/behavior between a fully-successful fan-out (nil error, request proceeds to `callback.Wait`) and a partially-failed fan-out (non-nil error, immediate failure response) lets an external caller repeatedly probe and infer DON member connectivity/health over time, purely by observing response differences on this public endpoint — no privilege beyond calling the gateway's user API is required.
2. **Orphaned callback slot**: whenever at least one member's `SendToNode` fails, the caller path returns without ever waiting on or removing the callback that was already inserted into `h.savedCallbacks` at line 412. That entry can only be cleaned up by `handleWebAPITriggerMessage` (if some node still manages to respond, which is not guaranteed once the error path has already been taken) or by `pruneCallbacks`, which runs every `CallbackPruneIntervalSec` (default 30s) and only evicts entries older than `CallbackMaxAgeSec` (default 120s) [5](#0-4) . During that window each such request occupies a slot toward `MaxSavedCallbacks` (default 20000) [6](#0-5) , even though the user already received a terminal error response and is not waiting on it.

There is no per-member status returned, no explicit `callback.SendResponse`/removal on the partial-failure path, and no authz/rate-limit check in this file beyond a `// TODO: apply allowlist and rate-limiting here` comment [7](#0-6) , so nothing in the reachable code path prevents either the info leak or the leaked slot.

### Impact Explanation
Scoped impact matches the two items called out in the question: (a) low-severity information disclosure of DON topology/node reachability to unprivileged external callers via observable, differential error text on the public gateway API, and (b) a resource-retention issue where `savedCallbacks` entries outlive their usefulness for up to `CallbackMaxAgeSec` (120s default) on every partially-failed fan-out, inflating occupancy of the bounded `savedCallbacks` map and contributing to eviction pressure (`pruneCallbacks`) against legitimate in-flight requests under sustained partial-failure conditions. This does not by itself grant an auth bypass, secret disclosure, or transaction manipulation.

### Likelihood Explanation
Reaching this code requires only an ordinary, unauthenticated legacy request to the gateway's user HTTP port with `MethodWebAPITrigger` and a valid DON ID — no operator/admin privilege needed. The information-disclosure component is fully attacker-triggerable (the attacker just needs to send requests and observe responses); however, the resource-leak/DoS-amplification component depends on at least one DON member already being disconnected/misconfigured (a naturally-occurring or externally-observed condition rather than something the unprivileged attacker can force), which limits (but does not eliminate) its exploitability — an attacker can time/repeat requests during naturally occurring node flakiness to maximize slot occupancy.

### Recommendation
- Do not aggregate and leak raw per-node `SendToNode` errors to the external caller; log them server-side and return a generic, non-identifying error/status to the caller.
- Track per-member send success within `HandleLegacyUserMessage`; if all sends fail (or after a configurable minimum quorum is not met), explicitly call `callback.SendResponse` (or otherwise remove the entry from `savedCallbacks`) synchronously instead of relying solely on `pruneCallbacks` expiry.
- Ensure `gateway.ProcessRequest` only takes the "return error immediately" path when the callback has been fully retired, so no `savedCallbacks` entry is left registered without either an eventual node response or an explicit cleanup.

### Proof of Concept
Integration test in `core/services/gateway/handlers/capabilities/handler_test.go` style:
1. Configure a DON with 3 members; mock `don.SendToNode` to fail for member 2 (e.g., `errors.New("connection to node <addr2> not found")`) and succeed for members 1 and 3.
2. Call `handler.HandleLegacyUserMessage` with a valid `web_api_trigger` message and assert:
   - The returned `err.Error()` string, when routed through `gateway.ProcessRequest`, is asserted to be present in the raw response bytes returned to the caller (demonstrating leakage of per-node failure text to the external caller).
   - Immediately after the call returns, `len(handler.savedCallbacks)` still contains the message ID (demonstrating the orphaned slot), then assert it is only removed after `CallbackMaxAgeSec` elapses via `pruneCallbacks`, not before.
3. Repeat with all members failing and confirm the same orphaned-slot behavior, and repeat with all members succeeding to show the differential (no immediate error, entry only removed once a node responds) — establishing the observable timing/response difference an attacker could use to fingerprint DON member health.

```go
func (h *handler) pruneCallbacks() {
	h.mu.Lock()
	defer h.mu.Unlock()

	// First, remove expired callbacks.
	maxAge := time.Duration(h.config.CallbackMaxAgeSec) * time.Second
	now := time.Now()
	var expired int
	for id, cb := range h.savedCallbacks {
		if now.Sub(cb.createdAt) > maxAge {
			delete(h.savedCallbacks, id)
			expired++
		}
	}
```
