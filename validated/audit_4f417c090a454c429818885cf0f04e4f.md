**Rationale:**

`Context::get_latest_storage_ledger_info` performs three separate, unsynchronized reads against `self.db`: it first calls `get_latest_ledger_info_with_signatures()` to get the current `LedgerInfoWithSignatures`, then `get_oldest_version_and_block_height()` (backed by `get_first_viable_block`, which derives from the ledger pruner's `min_viable_version`), and finally `get_block_info_by_version(ledger_info.ledger_info().version())` to resolve `block_height` for that *same, already-fixed* version. [1](#0-0) 

Critically, `block_height` is not an independent "latest" lookup — it is deterministically derived from the exact `version()` already captured from the `ledger_info` fetched in step one via `get_block_info_by_version`, so `block_height` and `ledger_version`/`epoch`/`timestamp` are always mutually consistent. [2](#0-1) 

The only field fetched from a logically distinct read is `oldest_block_height`/`oldest_version`, sourced from `get_first_viable_block`, which is driven by the ledger pruner's monotonically-increasing `min_readable_version`/`min_viable_version` counters, not by any restore-mutated snapshot boundary. [3](#0-2) [4](#0-3) 

Restore (`RestoreCoordinator`/`RestoreHandler`) is a forward-only, monotonically-progressing bootstrap process — it appends transactions/state via `restore_utils::save_transactions` and `save_ledger_infos`, it does not rewrite or truncate already-committed ledger data behind the serving cursor. [5](#0-4) [6](#0-5)  Even in the theoretical worst case of a benign timing race between these reads, both `oldest_*` and `block_height`/`ledger_version` values only move forward, so any transient skew is a presentational metadata inconsistency in an informational status field (`LedgerInfo`), not a corruption of committed state, VM output, write set, or any accumulator/JMT proof material. This `LedgerInfo` struct carries no cryptographic proof binding a version to a root — it's just header/index metadata. [7](#0-6) 

Per the review's decision standard, this does not corrupt committed state, proof material, or misbind an authenticated proof-bearing response — it is at most a display/presentation timing artifact in a non-authenticated status field, which is explicitly excluded from scope.

    pub fn get_latest_storage_ledger_info<E: ServiceUnavailableError>(
        &self,
    ) -> Result<LedgerInfo, E> {
        let ledger_info = self
            .get_latest_ledger_info_with_signatures()
            .context("Failed to retrieve latest ledger info")
            .map_err(|e| {
                E::service_unavailable_with_code_no_info(e, AptosErrorCode::InternalError)
            })?;

        let (oldest_version, oldest_block_height) = self.get_oldest_version_and_block_height()?;
        let (_, _, newest_block_event) = self
            .db
            .get_block_info_by_version(ledger_info.ledger_info().version())
            .context("Failed to retrieve latest block information")
            .map_err(|e| {
                E::service_unavailable_with_code_no_info(e, AptosErrorCode::InternalError)
            })?;

        let encryption_key_hex = self
            .get_encryption_key(ledger_info.ledger_info().version())
            .unwrap_or(None)
            .map(hex::encode);

        Ok(LedgerInfo::new(
            &self.chain_id(),
            &ledger_info,
            oldest_version,
            oldest_block_height,
            newest_block_event.height(),
            encryption_key_hex,
        ))
    }

        let min_version = self.get_min_readable_version();
        if self.is_pruner_enabled() {
            let adjusted_window = self
                .prune_window
                .saturating_sub(self.user_pruning_window_offset);
