### Title
Starknet OS `execute_replace_class` omits declared-class and Cairo-version checks enforced by blockifier, causing sequencer/OS state divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The blockifier's Rust implementation of the `replace_class` syscall enforces two invariants before mutating a contract's class hash: (1) the target class hash must be declared, and (2) the target class must be Cairo1 (V1) — otherwise it raises `ForbiddenClassReplacement`. The Cairo implementation of the same syscall inside the Starknet OS (used to re-execute blocks and produce the state-transition proof/commitment) performs neither check.

### Finding Description
`SyscallHandlerBase::replace_class` in the blockifier reads the compiled class for `class_hash` (implicitly failing if undeclared) and explicitly rejects the call with `SyscallExecutionError::ForbiddenClassReplacement` if the target class is not Cairo1: [1](#0-0) 

This mirrors the deprecated-syscalls hint processor, which also reads the compiled class before allowing the class-hash swap: [2](#0-1) 

The corresponding Cairo function inside the Starknet OS, `execute_replace_class`, performs neither check. It directly overwrites the contract's `StateEntry.class_hash` with the caller-supplied `class_hash` from the syscall request, with a TODO acknowledging the missing declared-class check, and with no analog of the Cairo1-only restriction at all: [3](#0-2) 

The equivalent legacy Cairo0 syscall path (`deprecated_execute_syscalls.cairo`) has the identical gap: [4](#0-3) 

Because the Starknet OS is the component that re-executes transactions to compute the authoritative `contract_state_changes` dict that feeds `state_update`/`calculate_global_state_root` in `state.cairo`, any semantic mismatch between blockifier and the OS on whether a given `replace_class` call succeeds or fails is a correctness bug in the reference implementation that is supposed to be behaviorally identical to blockifier: [5](#0-4) 

A single unprivileged account contract can trigger this by invoking `replace_class_syscall` with a `class_hash` argument pointing to either (a) an undeclared class hash, or (b) a declared Cairo0 class hash. In blockifier this call errors out (`StateError::UndeclaredClassHash` or `ForbiddenClassReplacement`), whereas in the OS's Cairo implementation the very same call unconditionally succeeds and rewrites the contract's class hash in `contract_state_changes`.

### Impact Explanation
The Starknet OS's re-execution is the ground truth used to compute the committed contract/class state and ultimately the block's state commitment. If the OS accepts (and applies) a class-hash overwrite that blockifier would reject/revert for the identical transaction, the state diff computed by the OS diverges from the state diff actually applied by the sequencer's blockifier during block building. This is exactly the "wrong committed root or block hash / honest-node divergence" class of impact called out in the report: two components of the same node stack that are required to agree on the outcome of a transaction do not agree, undermining the soundness of the produced state-transition proof and the resulting committed global state root.

### Likelihood Explanation
The path is reachable by any account contract issuing a single `replace_class` syscall with either an undeclared class hash or a Cairo0-declared class hash — no special privilege, staking, or operator/proposer misbehavior is required. The TODO comment in the source (`// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`) confirms the maintainers are aware the check is missing but it had not yet been implemented as of the current codebase state.

### Recommendation
Add the same validations to the OS's `execute_replace_class` (and its deprecated Cairo0 counterpart) that blockifier enforces:
1. Verify a declared class exists for `class_hash` (equivalent of `state.get_compiled_class(class_hash)?` failing on undeclared classes) before writing the new `StateEntry`.
2. Reject the syscall (or emit the equivalent revert semantics) when the target class is not Cairo1, matching blockifier's `ForbiddenClassReplacement`.
Ensure the OS's failure/revert semantics for both conditions match blockifier's exactly (same tag: hard error vs. `Revert{..}` with identical error data) so that re-execution outcomes stay bit-for-bit consistent with the sequencer's execution engine.

### Proof of Concept
1. Deploy any Cairo1 account contract.
2. From that account, send an `INVOKE` transaction that calls a contract exposing `replace_class_syscall(class_hash)`, passing a `class_hash` for either:
   - an undeclared class, or
   - a declared Cairo0 (V0) class.
3. Observe that blockifier execution (`crates/blockifier/src/execution/syscalls/syscall_base.rs::replace_class`) fails the syscall (`StateError::UndeclaredClassHash` / `SyscallExecutionError::ForbiddenClassReplacement`), while feeding the identical transaction trace/hints into the Starknet OS's `execute_replace_class` (`crates/apollo_starknet_os_program/.../syscall_impls.cairo:881-920`) succeeds unconditionally and writes the new class hash into `contract_state_changes`, producing a differing state root from the one blockifier would compute for the same transaction. I was not able to run the Cairo OS test harness directly in this environment to produce an end-to-end divergent-root trace; this PoC outline is based on static analysis of the two implementations described above and should be exercised with the `starknet_os_flow_tests` / `virtual_os_test.rs` harness (which already tests `ReplaceClass` under other conditions, see `crates/starknet_os_flow_tests/src/virtual_os_test.rs:148-181`) to obtain a concrete state-root mismatch.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
