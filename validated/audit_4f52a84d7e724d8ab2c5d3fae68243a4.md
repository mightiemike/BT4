### Title
No unauthorized undelegation possible — `CheckUnDelegateResource` precompile is read-only and `UnDelegateResourceContract` requires owner signature - (File: actuator/src/main/java/org/tron/core/vm/utils/FreezeV2Util.java)

### Summary
The `CheckUnDelegateResource` precompile (`org.tron.core.vm.PrecompiledContracts.CheckUnDelegateResource`) calling `FreezeV2Util.checkUndelegateResource` is a pure read-only query that accepts an arbitrary `target` address and returns computed split values, but it performs no state mutation and no authorization decision. Any subsequent `UnDelegateResourceContract` broadcast is independently validated by transaction-level signature verification (`TransactionCapsule.validateSignature`/`validatePubSignature`) which recovers the signer address from the ECDSA signature and requires it to match the contract's `ownerAddress` field, so an attacker cannot undelegate another account's resources without that account's private key.

### Finding Description
`CheckUnDelegateResource.execute` in `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java` (lines 2177-2207) parses an attacker-supplied `target`, `amount`, and `type`, and calls `FreezeV2Util.checkUndelegateResource(target, amount, type, getDeposit())`. That method (`actuator/src/main/java/org/tron/core/vm/utils/FreezeV2Util.java` lines 195-233) only reads `AccountCapsule` state and `repository.getAccount*UsageBalanceAndRestoreSeconds` values to compute a `Triple<clean, locked, restoreSeconds>` — it never writes to the repository, never checks `msg.sender`, and returns data for any address regardless of caller identity. This is intentional/expected precompile design: like `queryResourceV2`/`queryDelegatableResource`, it's meant to let any caller compute what a hypothetical unDelegate call would resolve to, analogous to reading public account state via `GetAccount` RPC.

The critical safety boundary is not in the precompile — it's enforced independently at the transaction/actuator layer. `UnDelegateResourceActuator.validate()` (actuator/src/main/java/org/tron/core/actuator/UnDelegateResourceActuator.java) reads `ownerAddress` strictly from the `UnDelegateResourceContract` protobuf field, and before any actuator executes, `TransactionCapsule.validateSignature`/`validatePubSignature` (chainbase/src/main/java/org/tron/core/capsule/TransactionCapsule.java lines 650-719, backed by `TransactionUtils.validTransaction`-style comparisons) recovers the signer's address from the raw ECDSA signature bytes and compares it against `getOwner(contract)` (which extracts the `owner_address` field via reflection). If the recovered signer does not equal `ownerAddress`, the transaction fails with a signature/validate exception before `UnDelegateResourceActuator.execute` ever mutates state. Reading data via the precompile provides no way to forge or bypass this signature check — the attacker still needs the target's private key to produce a valid signature over the raw transaction.

### Impact Explanation
None. Reading another account's resource-split data via the precompile has no accounting or authorization impact by itself, and it cannot be chained into an actual undelegation because the actuator-level signature check independently and unconditionally enforces `signer == ownerAddress`.

### Likelihood Explanation
Not applicable — there is no viable exploit path. The precompile is read-only by design (same category as `ResourceV2`, `DelegatableResource`, `ResourceUsage`, `TotalResource`, all of which accept arbitrary addresses since they only expose already-public on-chain accounting data), and broadcasting a contract with a mismatched owner/signer is rejected deterministically at signature validation, independent of what the attacker read off-chain.

### Recommendation
No fix required for this specific concern. If reviewers want defense-in-depth, the existing test coverage (`framework/src/test/java/org/tron/common/runtime/vm/PrecompiledContractsTest.java` `checkUnDelegateResourceTest`) plus actuator-side signature validation already codify the intended behavior; no additional check on `target` is warranted since the precompile's role is read-only analogous to other TVM freezeV2 query precompiles.

  public static Triple<Long, Long, Long> checkUndelegateResource(byte[] address, long amount, long type, Repository repository) {
    if (!VMConfig.allowTvmFreezeV2()) {
      return Triple.of(0L, 0L, 0L);
    }

    if (amount <= 0) {
      return Triple.of(0L, 0L, 0L);
    }

    AccountCapsule accountCapsule = repository.getAccount(address);
    if (accountCapsule == null) {
      return Triple.of(0L, 0L, 0L);
    }

    Pair<Long, Long> usagePair;
    long resourceLimit;
    if (type == 0) {
      usagePair = repository.getAccountNetUsageBalanceAndRestoreSeconds(accountCapsule);
      resourceLimit = accountCapsule.getAllFrozenBalanceForBandwidth();
    } else if (type == 1) {
      usagePair = repository.getAccountEnergyUsageBalanceAndRestoreSeconds(accountCapsule);
      resourceLimit = accountCapsule.getAllFrozenBalanceForEnergy();
    } else {
      return Triple.of(0L, 0L, 0L);
    }

    if (usagePair == null || usagePair.getLeft() == null || usagePair.getRight() == null) {
      return Triple.of(0L, 0L, 0L);
    }

    amount = min(amount, resourceLimit, VMConfig.disableJavaLangMath());
    if (resourceLimit <= usagePair.getLeft()) {
      return Triple.of(0L, amount, usagePair.getRight());
    }

    long clean = (long) (amount * ((double) (resourceLimit - usagePair.getLeft()) / resourceLimit));

    return Triple.of(clean, amount - clean, usagePair.getRight());
  }

  public boolean validatePubSignature(AccountStore accountStore,
      DynamicPropertiesStore dynamicPropertiesStore)
      throws ValidateSignatureException {
    if (!isVerified) {
      if (this.transaction.getSignatureCount() <= 0
              || this.transaction.getRawData().getContractCount() <= 0) {
        throw new ValidateSignatureException("miss sig or contract");
      }
      if (this.transaction.getSignatureCount() > dynamicPropertiesStore
              .getTotalSignNum()) {
        throw new ValidateSignatureException("too many signatures");
      }

      byte[] hash = getTransactionId().getBytes();

      long startNs = System.nanoTime();
      try {
        if (!validateSignature(this.transaction, hash, accountStore, dynamicPropertiesStore)) {
          isVerified = false;
          throw new ValidateSignatureException("sig error");
        }
      } catch (SignatureException | PermissionException | SignatureFormatException e) {
        isVerified = false;
        throw new ValidateSignatureException(e.getMessage());
      } finally {
        logSlowSigVerify(startNs);
      }
      isVerified = true;
    }
    return true;
  }

  /**

  void logSlowSigVerify(long startNs) {
    long costMs = TimeUnit.NANOSECONDS.toMillis(System.nanoTime() - startNs);
    if (costMs > SLOW_SIG_VERIFY_MS) {
      logger.warn("slow verify: txId={}, sigCount={}, cost={} ms",
          getTransactionId(), this.transaction.getSignatureCount(), costMs);
    }
  }

  public boolean validateSignature(AccountStore accountStore,
      DynamicPropertiesStore dynamicPropertiesStore) throws ValidateSignatureException {
    if (!isVerified) {
      //Do not support multi contracts in one transaction
      Transaction.Contract contract = this.getInstance().getRawData().getContract(0);
      if (contract.getType() != ContractType.ShieldedTransferContract) {
        validatePubSignature(accountStore, dynamicPropertiesStore);
      } else {  //ShieldedTransfer
        byte[] owner = getOwnerAddress();
        if (!ArrayUtils.isEmpty(owner)) { //transfer from transparent address
          validatePubSignature(accountStore, dynamicPropertiesStore);
        } else { //transfer from shielded address
          if (this.transaction.getSignatureCount() > 0) {
            throw new ValidateSignatureException("there should be no signatures signed by "
                    + "transparent address when transfer from shielded address");
          }
        }
      }
      isVerified = true;
    }
    return true;
  }
