### Title
Blocked senders are removed from the allowlist ORM but never purged from the in-memory allowlist enforced by `Allow()` - (File: core/services/gateway/handlers/functions/allowlist/allowlist.go)

### Summary
`onchainAllowlist` enforces access to the Functions Gateway handler purely via an in-memory map, `a.allowlist`, which `Allow()` consults on every request [1](#0-0) . When the ToS allow-list contract is on the batch-processing code path (contract version ≥ `v1.1.0`), the node updates that in-memory map only by adding newly-allowed senders, and "removal" of blocked senders is implemented solely against the persistent ORM table, never against the enforced in-memory structure.

### Finding Description
`updateFromContractV1` chooses between two update strategies depending on the ToS contract's version [2](#0-1) . For the batch path (the one used for all current/future contract versions ≥ `v1.1.0`), it calls `updateAllowedSendersInBatches` followed by `syncBlockedSenders`:
- `updateAllowedSendersInBatches`/`updateAllowedSendersBatch` build up `currentAllowedSenderList` and repeatedly call `a.allowlist.Store(&snapshot)` to add newly fetched allowed senders to the in-memory allowlist used by `Allow()` [3](#0-2) .
- `syncBlockedSenders` fetches the contract's blocked-senders list and calls `a.orm.DeleteAllowedSenders(ctx, blockedSendersBatch)` — this only deletes rows from the persisted ORM table; it never touches `a.allowlist` [4](#0-3) .

There is no code path in the batch-processing branch that removes an address from `a.allowlist` once it has been added. The only place that fully replaces/prunes `a.allowlist` is `update()`, which is only invoked from the legacy (non-batch) `else` branch of `updateFromContractV1` or from `loadStoredAllowedSenderList` at node startup [5](#0-4) . This is structurally identical to the Sentinel V2 root cause: an admin action intended to revoke a permission (`toggleKnownAsset` removing a token / here, blocking a sender on-chain) updates one bookkeeping structure (`isKnownAsset` / the ORM table) but not the structure actually consulted for the privileged check (`positionAssets` set / the in-memory `a.allowlist` map).

### Impact Explanation
A sender that is blocked on-chain (revoked from the ToS allow-list contract) continues to be treated as an authorized sender by the Functions Gateway node for as long as the node process runs on the batch code path, since `Allow()` only reads the stale in-memory map. This is an authorization/allow-list bypass: a previously allowed, now-blocked entity retains privileged access to submit Functions requests through the gateway indefinitely (until node restart triggers `loadStoredAllowedSenderList`, which reloads from the ORM — but even that reload draws from the ORM table which itself may still be correctly pruned, yet the live `a.allowlist` in between restarts is never corrected). This directly violates the intended access-revocation guarantee of the allowlist mechanism.

### Likelihood Explanation
Likelihood is high for any deployment where the ToS allow-list contract is at or above `v1.1.0` (the documented minimum for batch processing, `tosContractMinBatchProcessingVersion`) and `OnchainAllowlistConfig.UpdateFrequencySec` is nonzero, i.e., normal periodic operation [6](#0-5) . Any legitimate admin action to block a previously allowed sender will trigger this stale-state condition on the very next periodic update cycle.

### Recommendation
In `syncBlockedSenders`, after deleting blocked senders from the ORM, also remove them from the in-memory allowlist (e.g., load the current `a.allowlist` snapshot, delete the blocked addresses, and `a.allowlist.Store` the result), or restructure the batch update flow so `a.allowlist` is fully reconciled (added + removed) atomically after both `updateAllowedSendersInBatches` and `syncBlockedSenders` complete, mirroring what `update()` does for the non-batch path.

### Proof of Concept
1. Configure `OnchainAllowlistConfig` with a ToS contract at version ≥ `v1.1.0` and periodic updates enabled.
2. Add sender `A` to the on-chain allow-list; on the next update cycle, `updateAllowedSendersBatch` stores `A` into `a.allowlist`, so `Allow(A)` returns `true`.
3. Block sender `A` on-chain (call the contract's block function) so it appears in `GetBlockedSendersInRange`.
4. On the next update cycle, `syncBlockedSenders` calls `a.orm.DeleteAllowedSenders(ctx, [A])`, removing `A` from the ORM table, but `a.allowlist` still contains `A` because no code path removes it there.
5. `Allow(A)` still returns `true` [1](#0-0) , so gateway requests signed by the blocked sender `A` continue to be accepted.

// syncBlockedSenders fetches the list of blocked addresses from the contract in batches
// and removes the addresses from the functions_allowlist table if present
func (a *onchainAllowlist) syncBlockedSenders(ctx context.Context, tosContract *functions_allow_list.TermsOfServiceAllowList, blockNum *big.Int) error {
	count, err := tosContract.GetBlockedSendersCount(&bind.CallOpts{
		Pending:     false,
		BlockNumber: blockNum,
		Context:     ctx,
	})
	if err != nil {
		return errors.Wrap(err, "unexpected error during functions_allow_list.GetBlockedSendersCount")
	}

	throttleTicker := time.NewTicker(time.Duration(a.config.FetchingDelayInRangeSec) * time.Second)
	for idxStart := uint64(0); idxStart < count; idxStart += uint64(a.config.OnchainAllowlistBatchSize) {
		<-throttleTicker.C

		idxEnd := idxStart + uint64(a.config.OnchainAllowlistBatchSize)
		if idxEnd >= count {
			idxEnd = count - 1
		}

		blockedSendersBatch, err := tosContract.GetBlockedSendersInRange(&bind.CallOpts{
			Pending:     false,
			BlockNumber: blockNum,
			Context:     ctx,
		}, idxStart, idxEnd)
		if err != nil {
			return errors.Wrap(err, "error calling GetAllowedSendersInRange")
		}

		err = a.orm.DeleteAllowedSenders(ctx, blockedSendersBatch)
		if err != nil {
			a.lggr.Errorf("failed to delete blocked address from allowed list in storage: %v", err)
		}
	}
	throttleTicker.Stop()

	return nil
}

func (a *onchainAllowlist) update(addrList []common.Address) {
	newAllowlist := make(map[common.Address]struct{})
	for _, addr := range addrList {
		newAllowlist[addr] = struct{}{}
	}
	a.allowlist.Store(&newAllowlist)
	a.lggr.Infow("allowlist updated successfully", "len", len(addrList))
}

func (a *onchainAllowlist) loadStoredAllowedSenderList(ctx context.Context) {
	allowedList := make([]common.Address, 0)
	offset := uint(0)
	for {
		asBatch, err := a.orm.GetAllowedSenders(ctx, offset, a.config.StoredAllowlistBatchSize)
		if err != nil {
			a.lggr.Errorf("failed to get stored allowed senders: %v", err)
			break
		}

		allowedList = append(allowedList, asBatch...)

		if len(asBatch) < int(a.config.StoredAllowlistBatchSize) {
			break
		}
		offset += a.config.StoredAllowlistBatchSize
	}

	a.update(allowedList)
}
