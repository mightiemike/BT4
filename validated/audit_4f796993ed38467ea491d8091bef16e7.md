**Rationale:**

The `enc()` function in question — `ElGamalCurve25519Aes256Gcm::enc` (which calls `Aes256Gcm::generate_nonce(aead_rng)`) — is defined in `crates/aptos-crypto/src/asymmetric_encryption/elgamal_curve25519_aes256_gcm.rs` [1](#0-0) , but it is not invoked anywhere in the production codebase. The only caller found is its own unit test `gen_enc_dec`, which passes `aes_gcm::aead::OsRng` [2](#0-1) . A repo-wide search for `ElGamalCurve25519Aes256Gcm` confirms no other module or crate references this scheme.

The actual production encrypted-transaction path (used by the encrypted mempool / consensus) is `FPTXWeighted`, a completely different threshold-encryption scheme in `crates/aptos-batch-encryption`, whose symmetric encryption step uses `SymmetricKey::encrypt` with `Aes128Gcm` and its own nonce generation via `SymmetricCipher::generate_nonce(rng)` [3](#0-2) . The RNG for this path is seeded via `StdRng::from_entropy()` inside `TransactionFactory::encrypt_payload`, not derived from attacker-controlled transaction content [4](#0-3) .

Since the `Aes256Gcm::enc()` function named in the question has no reachable call path from any unprivileged transaction, package, API, view, bytecode, or proof input as required by the scope rules, and the actually-used encryption/nonce-generation path (`FPTXWeighted`/`SymmetricKey`) does not source its RNG from attacker-controlled data, there is no exploitable nonce-reuse path that could corrupt committed state, proof material, or an authenticated response on mainnet.

    pub fn encrypt<R: RngCore + CryptoRng>(
        &self,
        rng: &mut R,
        plaintext: &impl Plaintext,
    ) -> Result<SymmetricCiphertext> {
        use aes_gcm::KeyInit as _; // putting this in the global scope causes Hmac<Sha256> to be
                                   // ambiguous for some reason

        let key: &Key<SymmetricCipher> = &self.0;

        let cipher = SymmetricCipher::new(key);
        let nonce = SymmetricCipher::generate_nonce(rng); // 96-bits; unique per message
                                                          //
        let mut plaintext_bytes = Vec::new();
        bcs::serialize_into(&mut plaintext_bytes, &plaintext)
            .map_err(|_| BatchEncryptionError::SerializationError)?;

        Ok(SymmetricCiphertext {
            nonce,
            ct_body: cipher
                .encrypt(&nonce, plaintext_bytes.as_ref())
                .map_err(|_| BatchEncryptionError::SymmetricEncryptionError)?,
        })
