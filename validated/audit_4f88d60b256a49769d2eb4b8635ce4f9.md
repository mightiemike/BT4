## Analysis

The reported bug class — an EIP-712/off-chain signature scheme that omits any domain-separation identifier (chain/DON/service) while binding only application data (nonce/value) — has a direct analog in Chainlink's **S4 (Secure Storage Service)** envelope signing scheme used by Chainlink Functions/gateway secrets storage.

### Title
Missing domain separation in `s4.Envelope` signature allows cross-DON/cross-deployment signature replay - (File: `core/services/s4/envelope.go`)

### Summary
`s4.Envelope.Sign`/`GetSignerAddress` compute an Ethereum-prefixed signature over a JSON blob containing only `address`, `slotid`, `payload`, `version`, and `expiration` [1](#0-0) . Nothing in the signed payload identifies which DON, S4 service instance, gateway, or network the signature is authorized for.

### Finding Description
`Storage.Put` (the entry point invoked when a user calls `secrets_set`) validates slot bounds, payload size, and expiration, then recovers the signer strictly from the `Envelope` fields shown above and compares it to `key.Address` [2](#0-1) . There is no DON ID, gateway ID, chain ID, or service-instance identifier included in `ToJson()`, so the exact same signature is valid for any S4-backed service (e.g., different Functions DONs, or environments such as testnet vs. mainnet infrastructure) that shares the same address/slot/version/payload/expiration values, exactly mirroring the `Forwarder._verifySig` root cause: signature validity is scoped only to nonce-like fields (`slotid`/`version`) and a self-declared `expiration`, not to a chain/service-bound domain separator.

Unlike the reported Forwarder bug, S4 does enforce an expiration/deadline check in `Storage.Put` (`ErrPastExpiration`) [3](#0-2) , so the "indefinite validity" half of the original finding does not apply — but the "missing domain separator enabling cross-context replay" half does apply.

### Impact Explanation
An unprivileged attacker who observes a user's `secrets_set` envelope signature (e.g., via gateway logs, a public relay, or a compromised transport leg) can replay that exact signature against a *different* S4-backed DON/service deployment that the victim never authorized for that data, as long as the target service's slot/version/expiration constraints are satisfied. This causes unauthorized writes of the victim's data (and the victim's on-chain identity being falsely attributed as the signer/owner) into a storage context the victim did not intend, i.e., unauthorized privileged action / data tampering under a different trust boundary than the one the user consented to.

### Likelihood Explanation
Reachable by any external, unprivileged user who can observe or intercept a valid envelope signature — no privileged keys or node compromise required. Likelihood depends on multiple S4-backed deployments (multiple Functions DONs/environments) coexisting, which is the norm for Chainlink's multi-DON, multi-network operational model (mirroring the "deployed across multiple chains" condition that raised the original finding to High).

### Recommendation
Bind the signature to a service-specific domain: include a DON ID / service identifier / chain ID (or an EIP-712 domain separator computed on the verifying side rather than user-supplied) inside `Envelope.ToJson()`, and reject envelopes whose declared domain does not match the verifying service's own configured identity.

### Proof of Concept
1. A user signs an `Envelope{Address, SlotID, Payload, Version, Expiration}` for `secrets_set` intended for DON A, per `TestEnvelope`/`generateTestOrmRow` construction pattern [4](#0-3) .
2. The raw signature bytes are captured (e.g., from gateway request logs or network capture).
3. An attacker submits the identical `(key, record, signature)` tuple to DON B's `Storage.Put`, whose ORM/version state independently satisfies `now <= record.Expiration` and version constraints.
4. `envelope.GetSignerAddress(signature)` recovers the same valid signer address because nothing in `ToJson()` differs between DON A and DON B contexts [5](#0-4) , so the write succeeds on DON B without the victim's consent for that specific deployment.

**Note on confidence**: I could not fully trace whether the outer `api.Message.Sign` wrapper (used in the Functions gateway connector handler, seen in `connector_handler_test.go`) independently binds `DonId` in a way that would prevent this replay at the transport layer for the Functions use case specifically — that signature is separate from the inner `s4.Envelope` signature and I was not able to inspect `gateway/common` `Message.Sign` implementation within the available tool budget. If that outer signature does bind `DonId` and is always verified before the inner S4 signature is consulted, the practical exploitability of this specific path may be reduced to only S4 consumers that verify the envelope signature independently of any DON-bound wrapper. This should be verified against `core/services/gateway/common` message signing code before treating this as conclusively exploitable in the Functions flow.

func (e Envelope) ToJson() ([]byte, error) {
	address, err := json.Marshal(e.Address)
	if err != nil {
		return nil, err
	}
	nonNilPayload := e.Payload
	if nonNilPayload == nil {
		// prevent unwanted "null" values in JSON representation
		nonNilPayload = []byte{}
	}
	payload, err := json.Marshal(nonNilPayload)
	if err != nil {
		return nil, err
	}
	js := fmt.Sprintf(`{"address":%s,"slotid":%d,"payload":%s,"version":%d,"expiration":%d}`, address, e.SlotID, payload, e.Version, e.Expiration)
	return []byte(js), nil
```

func (s *storage) Put(ctx context.Context, key *Key, record *Record, signature []byte) error {
	if key.SlotId >= s.contraints.MaxSlotsPerUser {
		return ErrSlotIdTooBig
	}
	if len(record.Payload) > int(s.contraints.MaxPayloadSizeBytes) {
		return ErrPayloadTooBig
	}
	now := s.clock.Now().UnixMilli()
	if now > record.Expiration {
		return ErrPastExpiration
	}
	expSecs := s.contraints.MaxExpirationLengthSec * 1000
	if expSecs > math.MaxInt64 {
		return fmt.Errorf("expiration seconds overflows int64: %d", expSecs)
	}
	if record.Expiration-now > int64(expSecs) {
		return ErrExpirationTooLong
	}

	envelope := NewEnvelopeFromRecord(key, record)
	signer, err := envelope.GetSignerAddress(signature)
	if err != nil || signer != key.Address {
		return ErrWrongSignature
	}
```

func TestEnvelope(t *testing.T) {
	t.Parallel()

	payload := testutils.Random32Byte()
	expiration := time.Now().Add(time.Hour).UnixMilli()
	key := &s4.Key{
		Address: testutils.NewAddress(),
		SlotId:  3,
		Version: 5,
	}
	env := s4.NewEnvelopeFromRecord(key, &s4.Record{
		Payload:    payload[:],
		Expiration: expiration,
	})

	t.Run("signing", func(t *testing.T) {
		privateKey, err := crypto.GenerateKey()
		assert.NoError(t, err)

		sig, err := env.Sign(privateKey)
		assert.NoError(t, err)

		addr, err := env.GetSignerAddress(sig)
		assert.NoError(t, err)

		publicKey := privateKey.Public()
		publicKeyECDSA, ok := publicKey.(*ecdsa.PublicKey)
		assert.True(t, ok)
		assert.Equal(t, crypto.PubkeyToAddress(*publicKeyECDSA), addr)
	})
