### Title
Missing lower-bound validation in `extractDestGasAmountFromMap` allows negative `destGasAmount` to wrap into a maximal `uint32` gas value - ([File: core/capabilities/ccip/ccipsui/msghasher.go])

### Summary
`extractDestGasAmountFromMap`, the shared helper invoked from `ExecutePluginCodecV1.Encode` in `core/capabilities/ccip/ccipsui/executecodec.go`, only rejects `int64` values that exceed `math.MaxUint32` but never rejects negative values. A crafted `DestExecData` that decodes to a negative `int64` `destGasAmount` will silently wrap via `uint32(v)` into a huge unsigned value (e.g. `-1` → `4294967295`), which is then embedded directly into the serialized execute report via `s.U32(destGasAmount)`.

### Finding Description
In the token-amount serialization loop of `Encode` [1](#0-0) , `item.DestExecData` (an attacker-influenced field carried on the cross-chain message for each token transfer) is decoded through `e.extraDataCodec.DecodeTokenAmountDestExecData` into a generic `map[string]any`, then passed to `extractDestGasAmountFromMap` to obtain the `uint32` gas amount that is written into the report with `s.U32(destGasAmount)`.

For the `int64` case (documented as the representation used when "LOOP converts expected uint32 to int64"), the code only checks `v > math.MaxUint32` and returns an error, but performs no check for `v < 0`. If the underlying source-chain decode of `DestExecData` yields a negative `int64` value for the `destGasAmount` field (e.g., if the decoder's schema treats the field as signed for that source chain), the subsequent `uint32(v)` conversion silently wraps around to a large unsigned value near `2^32`, rather than being rejected. This value then flows unchecked into the same-function `s.U32(destGasAmount)` call in `executecodec.go`, embedding an attacker-inflated gas figure directly into the execute report that will be submitted on-chain.

This same helper is also called from `MessageHasherV1.Hash` [3](#0-2) , so the wrapped value additionally feeds into the report's cryptographic message hash, meaning a hash computed over an unintended (wrapped) gas value.

### Impact Explanation
A wrapped, maximal `uint32` `destGasAmount` embedded in the CCIP execute report for a Sui destination causes the destination-chain execute transaction to be constructed with an extreme, attacker-controlled gas parameter for a token transfer leg. This can cause execution failure/denial-of-service of the execute transaction, or otherwise let an attacker bypass intended gas-budget/rate-limit assumptions that rely on `destGasAmount` staying within a sane `uint32` domain — matching the "unsafe transaction submission" / "rate-limit or gas-budget bypass" impact class described in the audit scope.

### Likelihood Explanation
Exploitability requires that the source-chain-specific decoder feeding `DecodeTokenAmountDestExecData` can produce a negative `int64` for the `destGasAmount` field from attacker-supplied raw bytes (e.g., if that chain family's schema treats the field as a signed integer type rather than strictly unsigned). This repository does not contain the concrete decoder implementations for all source chain families in the indexed context, so it cannot be fully confirmed from available code whether a legitimate, unprivileged sender can currently produce such a negative decode result in production configurations. What is confirmed directly from the code is that the validation function itself has an asymmetric bound check (upper-bound only) that violates the stated invariant and would silently mis-convert any negative `int64` input it receives, regardless of origin.

### Recommendation
In `extractDestGasAmountFromMap` (core/capabilities/ccip/ccipsui/msghasher.go, lines 356-360), add an explicit lower-bound check before the upper-bound check, e.g.:
```go
case int64:
    if v < 0 || v > math.MaxUint32 {
        return 0, fmt.Errorf("destGasAmount out of uint32 range, got %d", v)
    }
    return uint32(v), nil
```
Apply the same fix to any other copies of this helper (`ccipevm/msghasher.go`, `ccipevm/gas_helpers.go`, `ccipsolana/gas_helpers.go`, `ccipaptos/msghasher.go`) that share the identical pattern, since they are separate copies rather than a truly shared function.

func extractDestGasAmountFromMap(input map[string]any) (uint32, error) {
	// Iterate through the expected fields in the struct
	for fieldName, fieldValue := range input {
		lowercase := strings.ToLower(fieldName)
		switch lowercase {
		case "destgasamount":
			switch v := fieldValue.(type) {
			case uint32:
				return v, nil
			case int64: // LOOP converts expected uint32 to int64
				if v > math.MaxUint32 {
					return 0, fmt.Errorf("destGasAmount exceeds uint32 max, got %d", v)
				}
				return uint32(v), nil //nolint:gosec // G115: validated to be within uint32 max above
			default:
				return 0, errors.New("invalid type for destgasamount, expected uint32 or int64")
			}
		default:
		}
	}

	return 0, errors.New("invalid token message, dest gas amount not found in the DestExecDataDecoded map")
}
