### Title
Cross-tenant webhook context/admin client forgery via unauthenticated `X-Shopify-Shop-Domain` header - ([File: packages/apps/shopify-app-remix/src/server/authenticate/webhooks/authenticate.ts])

### Summary
The webhook HMAC only authenticates the raw request body against the app's shared client secret; it never binds the signature to the `X-Shopify-Shop-Domain` header. `authenticateWebhookFactory` trusts `check.domain` (taken verbatim from that header) to select which shop's offline session/admin client to hand back, so a valid body+HMAC pair captured for one shop can be replayed with a different domain header to obtain a webhook context and authenticated admin client for a different (victim) shop.

### Finding Description
`validateHmacFromRequestFactory` in `packages/apps/shopify-api/lib/utils/hmac-validator.ts` computes `validHmac = validateHmacString(config, rawBody, hmac, HashFormat.Base64)` — it only signs/verifies `rawBody` against `config.apiSecretKey` (the app-wide client secret, shared across all installs of the app, not shop-specific). [1](#0-0) 

`validateFactory` in `packages/apps/shopify-api/lib/webhooks/validate.ts` calls this HMAC check, and — independently of the HMAC — reads the shop domain straight from the `X-Shopify-Shop-Domain` header via `checkWebhooksHeaders`/`checkEventsHeaders`, returning it as `domain` in the validation result with no cross-check against what was actually signed: [2](#0-1) 

`authenticateWebhookFactory` then uses that unauthenticated `check.domain` value directly to fetch the offline session and build the admin client: [3](#0-2) 

Exploit flow:
1. Attacker installs the app on their own shop A and triggers a real webhook delivery (e.g., via a test event or normal store activity), capturing the exact `rawBody` and its `X-Shopify-Hmac-Sha256` value.
2. Attacker POSTs to the app's webhook route with the identical `rawBody`/HMAC header pair, but replaces `X-Shopify-Shop-Domain` with `victim-shop.myshopify.com`.
3. `validateHmacString` re-computes the HMAC over the unchanged `rawBody` using the app's single shared secret and it matches — HMAC validation succeeds regardless of the domain header.
4. `checkWebhooksHeaders` returns `domain: 'victim-shop.myshopify.com'` as-is.
5. `authenticateWebhookFactory` calls `ensureValidOfflineSession(params, check.domain)` with the forged victim domain, retrieving the victim's stored offline session and constructing an `admin` client authenticated as the victim shop, then hands it to the app's webhook handler.

No existing check (HMAC verification, `safeCompare`, header presence checks) ties the HMAC to the domain header, because Shopify's own webhook HMAC scheme is designed only to authenticate that the payload originated from Shopify/the app (via the shared secret), not to bind it to a specific shop.

### Impact Explanation
This is a cross-tenant authentication/context forgery: an attacker who has legitimate access to only their own shop can cause the app's webhook handler to run app business logic against an arbitrary victim shop's admin session and admin API client (`webhookContext.session`/`webhookContext.admin`), as long as the victim shop's `myshopify.com` domain is known/guessable and has an offline session stored. This matches the "cross-tenant session/data access" and "forged authenticated session" bounty impact classes — the app logic (data reads/writes, GraphQL/REST calls) executes attributed to the wrong shop.

### Likelihood Explanation
- Preconditions are attacker-achievable without any privileged role or secret leak: only requires installing the app on a shop they control (or being sent one legitimate webhook) and knowing/guessing a target `myshopify.com` domain.
- The victim must have an offline session persisted (true for any actively installed app, which is the normal case).
- The replay is a simple HTTP POST with two header/body values copied from a captured request — trivially repeatable and scriptable.
- The only friction is that `rawBody` content is fixed (attacker cannot forge arbitrary payload content for the victim, only replay the exact captured body/topic), and topic/webhookId will still reflect the original event — but `shop`/`session`/`admin` in the resulting `webhookContext` are fully attacker-controlled to point at the victim.

### Recommendation
Do not trust the `X-Shopify-Shop-Domain` (or app/events domain header) as authoritative shop identity from an unauthenticated header. Either:
- Bind the HMAC computation to include the domain (and other identifying headers) rather than only `rawBody`, or
- After locating the offline session by `check.domain`, independently verify shop identity/authorization out-of-band (e.g., validate the session's shop by re-deriving it from a signed/opaque token rather than a plain header), or at minimum reject/flag processing when the domain header cannot be corroborated by another signed source.
Since this mirrors Shopify's real webhook signing scheme (body-only HMAC), the more practical mitigation is for `authenticateWebhookFactory`/`ensureValidOfflineSession` to require additional verification (e.g., confirm the webhook's shop domain against Shopify's registered webhook subscription/shop ID from the payload/topic metadata) before returning a scoped `admin` client, rather than trusting the header alone.

### Proof of Concept
```ts
// Jest-style PoC against authenticateWebhookFactory
import { authenticateWebhookFactory } from '../authenticate';

it('accepts a replayed body/hmac with a swapped shop domain header', async () => {
  // Step 1: capture a real webhook for shop A
  const rawBody = JSON.stringify({ id: 123, some: 'payload' });
  const hmac = await computeRealHmac(apiSecretKey, rawBody); // same secret used for all shops

  // Step 2: forge request with victim shop's domain header
  const forgedRequest = new Request('https://app.example.com/webhooks', {
    method: 'POST',
    headers: {
      'X-Shopify-Topic': 'orders/create',
      'X-Shopify-Hmac-Sha256': hmac,
      'X-Shopify-Shop-Domain': 'victim-shop.myshopify.com', // NOT shop A's domain
      'X-Shopify-Api-Version': '2024-01',
      'X-Shopify-Webhook-Id': 'test-id',
    },
    body: rawBody,
  });

  const authenticate = authenticateWebhookFactory(params);
  const webhookContext = await authenticate(forgedRequest);

  // Assert the forged domain was accepted and an admin client for the victim was returned
  expect(webhookContext.shop).toBe('victim-shop.myshopify.com');
  expect(webhookContext.session?.shop).toBe('victim-shop.myshopify.com');
  expect(webhookContext.admin).toBeDefined();
});
```
Expected (vulnerable) result: the test passes, proving `webhookContext.session`/`admin` are scoped to `victim-shop.myshopify.com` despite the HMAC only having verified `rawBody` originally generated for shop A.
