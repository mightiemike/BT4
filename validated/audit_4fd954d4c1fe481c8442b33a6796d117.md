### Title
Replay-verify comparator omits state-checkpoint hash validation, allowing state-root divergence to go undetected during archive replay - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the sole invariant check used by chunk replay/verify tooling to confirm that a locally re-executed transaction matches an externally supplied (backup/archive) `TransactionInfo`. It validates status, gas, write-set hash (`state_change_hash`), and event root hash, but never compares `state_checkpoint_hash` (nor `hot_state_checkpoint_hash` / `position_state_checkpoint_hash`) against the value computed from local execution.

### Finding Description
`ensure_match_transaction_info` explicitly checks four fields — status, gas_used, write-set hash vs `state_change_hash`, and event root hash vs `event_root_hash` — and then returns `Ok(())` without ever consulting `txn_info.state_checkpoint_hash()`: [1](#0-0) 

The code itself documents the gap via an unresolved `TODO(trading-native)` comment stating that "this comparator ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`), so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution": [2](#0-1) 

This function is the exact gate used by `storage/db-tool/src/replay_on_archive.rs`'s `execute_and_verify`, which re-executes archived transactions locally and calls `ensure_match_transaction_info(version, &expected_txn_infos[idx], ...)` where `expected_txn_infos` comes from the backup/archive stream, not from consensus-signed `LedgerInfo`: [3](#0-2) 

Because only `state_change_hash` (the write-set hash) is checked, and not `state_checkpoint_hash` (the Sparse-Merkle-Tree/state root at checkpoint boundaries), a discrepancy between the locally-computed state root and the state root recorded in the archived `TransactionInfo` will not be flagged as a verification failure. The `state_checkpoint_hash` field is the authenticated summary of the entire world state at a checkpoint boundary — a different, and arguably more critical, invariant than the per-transaction write-set hash, since it accumulates all prior writes rather than only the current transaction's writes: [4](#0-3) 

### Impact Explanation
Replay-verify (`replay_on_archive`) is the tool operators and the Aptos Labs release process use to confirm that a candidate binary/VM produces bit-for-bit identical state versus the historical, presumably-correct chain state stored in backups, prior to declaring compatibility (used to catch consensus/state divergence bugs, including hard-fork-relevant VM changes). Because the comparator silently skips `state_checkpoint_hash`, a VM or storage regression that corrupts the state root — while incidentally producing a write set whose *hash* still matches (e.g., an issue in how the checkpoint SMT is folded across multiple transactions but where each individual transaction's write-set/state_change_hash remains correct) — would pass replay-verify with no reported failure. This directly matches the "Hard-fork-only divergence during commit, replay, restore, or proof verification" and "Authenticated API or state-view output bound to the wrong version, object, or proof context" impact classes, since the state checkpoint hash is precisely the authenticated commitment that downstream proofs/APIs rely on for the correctness of the state root at a version.

### Likelihood Explanation
The comparator's omission is not a rare edge case — it unconditionally applies to every `ensure_match_transaction_info` call, in every replay/verify run, for every transaction that is not itself a discrepancy in status/gas/write-set-hash/event-hash. The gap only becomes an observable safety failure when there is a separate divergence localized to the state-checkpoint computation, but the important point is that the tool designed specifically to catch such divergences has a documented blind spot for exactly that class of bug, defeating the purpose of the safety net at the one point (checkpoint-boundary transactions) where it matters most.

### Recommendation
In `ensure_match_transaction_info`, thread through the locally-computed `state_checkpoint_hash` (and `hot_state_checkpoint_hash` / `position_state_checkpoint_hash` when applicable) and assert equality against `txn_info.state_checkpoint_hash()` (and the V1 equivalents) whenever the transaction is a checkpoint boundary, matching the pattern already used for `state_change_hash` and `event_root_hash`. This requires passing the checkpoint-hash values computed by `DoStateCheckpoint`/`DoLedgerUpdate` into the comparator's call sites (`replay_on_archive.rs`, `chunk_executor/mod.rs`, `aptos-move/cli/src/commands.rs`).

### Proof of Concept
1. In `execute_and_verify` (`storage/db-tool/src/replay_on_archive.rs:349-415`), construct/replay a chunk where the archived `expected_txn_infos[idx].state_checkpoint_hash()` differs from the checkpoint hash that would be computed locally by `DoStateCheckpoint` for the same version (e.g., simulate corruption by mutating the state_checkpoint_hash field of a test `TransactionInfo` while keeping `state_change_hash`/`event_root_hash` correct).
2. Call `executed_outputs[idx].ensure_match_transaction_info(version, &expected_txn_infos[idx], ...)` — because the function never reads `state_checkpoint_hash()`, it returns `Ok(())`.
3. Observe that `Verifier::verify` records no failure and `replay_on_archive` reports a clean pass, even though the state root at that version does not match the archived (would-be-authenticated) value — this is directly confirmed by the source code's own TODO comment acknowledging the exact scenario.     pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

        if cur_txns.is_empty() {
            return Ok(None);
        }

            .execute_block(

                &self

                    end: *current_version + cur_txns.len() as u64,
