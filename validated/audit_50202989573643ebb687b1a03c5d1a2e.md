### Title
Loss of staked TRX during TVM `SUICIDE`: immature `unfrozenV2` (withdrawal-limited) entries are discarded instead of transferred to the inheritor - (File: `actuator/src/main/java/org/tron/core/vm/program/Program.java`)

### Summary
The reported bug class is "merging state into another entity while ignoring the source's withdrawal-limit bookkeeping, causing funds to bypass or be lost relative to that limit." The closest reachable analog in java-tron is the TVM `SUICIDE`/`SUICIDE2` handling, which merges a self-destructing contract's staked/frozen state into an "inheritor" account. When merging, only the already-matured portion of the owner's pending-unfreeze list is forwarded to the inheritor; the remainder (unfrozen amounts still inside their mandatory unfreeze delay, i.e. still subject to the withdrawal limit) is wiped without being credited anywhere.

### Finding Description
`Program.transferFrozenV2BalanceToInheritor` is invoked from both `suicide()` and `suicide2()` when a contract self-destructs, to merge the owner's FreezeV2 state into the inheritor/obtainer account [1](#0-0) [2](#0-1) .

Inside this merge routine, only unfreeze entries whose `unfreezeExpireTime <= nowTimestamp` (i.e., entries that have already passed the mandatory unfreeze delay / withdrawal-limit window) are summed and credited to the inheritor's balance: [3](#0-2) 

Immediately after, `clearOwnerFreezeV2(ownerCapsule)` is called, which unconditionally clears the *entire* `unfrozenV2` list via `ownerCapsule.clearUnfrozenV2()` — including entries whose `unfreezeExpireTime` has **not** yet passed: [4](#0-3) [5](#0-4) 

The immature `UnFreezeV2` entries represent value that is still tracked by the account's withdrawal-limit mechanism (the unfreeze delay enforced elsewhere by `WithdrawExpireUnfreezeProcessor`/`UnfreezeBalanceV2Processor`, see `getTotalWithdrawUnfreeze`) [6](#0-5) . When the owning account merges into the inheritor via `SUICIDE`, this withdrawal-limit state is neither carried over to the inheritor's own `unfrozenV2` list nor credited to any balance — it is simply discarded, exactly mirroring the report's root cause: the merge operation propagates the primary state (frozen/staked balance) but drops the ancillary withdrawal-limit bookkeeping (the pending, not-yet-withdrawable unfreeze records) of the source entity.

### Impact Explanation
Any user can trigger permanent loss of real TRX value: staking (freezing v2) TRX, requesting an unfreeze (entering the unfreeze delay/withdrawal-limit window), then causing (or having) the contract `SUICIDE` before the unfreeze delay expires destroys that pending balance with no compensating credit to either the owner or inheritor. This is an unprivileged, anonymous-reachable accounting-corruption/fund-loss bug via ordinary contract execution (`SUICIDE`/`SUICIDE2` opcodes), not requiring any privileged role.

### Likelihood Explanation
Medium: it requires an account to (a) freeze TRX under FreezeV2, (b) call unfreeze (entering the delay window), and (c) trigger contract self-destruction (or be the target contract of a `SUICIDE`) before the unfreeze delay elapses. This is a normal, unprivileged sequence any user/contract deployer can perform, and TVM freezing/self-destruct features are commonly exercised in production contracts.

### Recommendation
In `transferFrozenV2BalanceToInheritor`, before calling `clearOwnerFreezeV2`, transfer all remaining (not-yet-matured) `UnFreezeV2` entries from the owner to the inheritor's own `unfrozenV2` list (preserving each entry's `unfreezeExpireTime`), rather than discarding them. This mirrors the external report's recommendation of transferring all withdrawal limits/state from the merged-away entity to the surviving entity.

### Proof of Concept
1. Deploy a contract account; call `FreezeBalanceV2` (via TVM `freezeBalanceV2`) to stake TRX for BANDWIDTH.
2. Call `unfreezeBalanceV2` for that stake; this creates an `UnFreezeV2` entry with `unfreezeExpireTime = now + unfreezeDelayDays * FROZEN_PERIOD` (see `calcUnfreezeExpireTime`) [7](#0-6) .
3. Before that expire time is reached, execute `SUICIDE`/`SUICIDE2` from the contract, naming any inheritor address.
4. Observe that `transferFrozenV2BalanceToInheritor` only credits the inheritor with entries where `unfreezeExpireTime <= nowTimestamp` [3](#0-2) , then calls `clearOwnerFreezeV2`, which clears the still-pending entry with no credit issued [5](#0-4)  — the staked value is permanently lost from total supply accounting for that user.

  private List<Protocol.Account.UnFreezeV2> getTotalWithdrawList(List<Protocol.Account.UnFreezeV2> unfrozenV2List, long now) {
