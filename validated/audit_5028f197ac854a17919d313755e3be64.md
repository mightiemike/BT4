## Analysis

The Cooler `maxLTC` bug is fundamentally about a critical value used to gate financial risk (collateralization) being derived from a source that doesn't reflect the current, real, manipulation-resistant market price. The closest analog in Push Chain's scope is not a literal hard-coded constant, but a functionally equivalent problem: **the gas-abstraction auto-swap path uses a single, unprotected spot-price quote from the on-chain Uniswap V3 `QuoterV2` to compute the minimum acceptable swap output, with no TWAP, no deviation check, and no staleness/oracle-manipulation defense** — exactly the "wrong exchange rate feeding a fund-safety threshold" class of bug, just sourced from a manipulable spot AMM instead of a stale constant.

### Title
Gas-abstraction PRC20→WPC auto-swap relies on manipulable spot-price quote for slippage protection, enabling sandwich extraction from protocol-owned liquidity - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`GetSwapQuote` calls the Uniswap V3 `QuoterV2.quoteExactInputSingle` view function to obtain the current spot exchange rate between an inbound PRC20 asset and WPC, then derives `minPCOut = quote * 95 / 100` as slippage protection before executing the real swap via `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas`. [1](#0-0) 
This pattern is used in three separate flows: gas-only inbound deposits, gas+payload inbound deposits, and outbound gas-fee refunds. [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
The quote and the swap execution both read the *live* pool state, and the 95% floor is computed **relative to whatever the pool price is at that instant**, not relative to any independent, manipulation-resistant reference (no TWAP, no external oracle cross-check, no max-deviation-from-recent-price guard). Any unprivileged actor can trade against the same WPC/PRC20 pool (deployed as regular Uniswap V3 pools per the AMM setup) immediately before a known/observable inbound deposit or outbound refund is processed by the module, moving the spot price, then trade back afterward — a classic sandwich against the protocol's own swap. Because `minPCOut` is derived from the *same, already-manipulated* price rather than a trusted baseline, the 5% band does not protect the protocol or the user from that manipulation; it only protects against slippage from the swap's own price impact. Inbound events are publicly observable on the source chain before Push Chain processes them (and even after relaying, before the deposit-triggered swap executes in the deterministic keeper flow), giving an attacker a practical time window to front-run.
Comment evidence in the test setup even acknowledges this class of pool is thin/drainable: "Keep local Solana gas quotes small so repeated Route 3 tests do not drain the tiny WPC/pSOL AMM pool". [5](#0-4) 

### Impact Explanation
Successful sandwiching lets an attacker extract value from the WPC/PRC20 pool (which backs real user gas-abstraction deposits and refunds) at the expense of depositors receiving less native gas than intended, or the protocol paying out more refund value than warranted — a corruption of PRC20/native asset accounting reachable purely through ordinary, unprivileged deposit/refund flows with no validator or relayer collusion required. This matches the in-scope "corruption of PRC20 or native asset accounting ... refund accounting" impact category.

### Likelihood Explanation
The trigger requires only: (1) ability to trade on the public Uniswap V3 pool for the relevant PRC20/WPC pair (open to anyone), and (2) observing/predicting the timing of an inbound gas deposit or outbound refund (source-chain events are public before/while being relayed). No privileged role, validator collusion, or protocol bug beyond the missing manipulation-resistant price check is needed, making this practically reachable by any external actor, especially against low-liquidity pools.

### Recommendation
Do not derive `minPCOut` solely from the instantaneous `QuoterV2` spot quote. Use a manipulation-resistant reference such as a TWAP over a sufficient window (Uniswap V3 pools support `observe`), and/or bound the acceptable price deviation between the spot quote and the TWAP/expected on-chain gas price already tracked via `ChainMeta`, rejecting or reverting swaps whose quote deviates beyond a safe threshold before computing `minPCOut`.

### Proof of Concept
1. Attacker monitors an external chain's gateway for an inbound `GAS`/`GAS_AND_PAYLOAD` deposit of PRC20 token `T` about to be relayed/processed by Push Chain.
2. Attacker submits a large swap on the on-chain `T`/WPC Uniswap V3 pool that moves the pool's spot price unfavorably for the upcoming auto-swap direction.
3. The uexecutor keeper's `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` calls `GetSwapQuote` immediately followed by `CallPRC20DepositAutoSwap`, both against the now-manipulated pool state; `minPCOut = quote * 95 / 100` reflects the manipulated price, so the deposit/refund swap executes at the bad price without reverting. [6](#0-5) 
4. Attacker reverses their initial trade, capturing the price-impact profit funded by the depositor/protocol-owned liquidity.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
