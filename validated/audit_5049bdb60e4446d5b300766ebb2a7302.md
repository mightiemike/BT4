I have confirmed the vulnerability. The Starknet OS's `execute_replace_class` in `syscall_impls.cairo` explicitly skips the "class is declared" check (marked with a TODO), while the blockifier's Rust implementation of the same syscall enforces it. This produces a divergence: blockifier (the sequencer's native execution engine) rejects a `replace_class` syscall targeting an undeclared (or Cairo0) class hash, but the Starknet OS — used for proving/re-executing the block — accepts it unconditionally and commits the state change.

### Title
Starknet OS `replace_class` syscall omits declared-class-hash validation present in blockifier, causing state/proof divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `execute_replace_class` function in the Starknet OS Cairo program updates a contract's class hash in `contract_state_changes` without verifying that the target `class_hash` corresponds to a declared class, unlike the Rust blockifier's `replace_class` implementation which explicitly checks this via `state.get_compiled_class(class_hash)?` and additionally rejects non-Cairo1 (V0) classes.

### Finding Description
In the OS, `execute_replace_class` reads the `class_hash` from syscall request calldata and immediately writes it into the contract's state entry with only a `TODO` acknowledging the missing check: [1](#0-0) 

By contrast, the blockifier (the component that actually executes transactions when building blocks) enforces two checks before performing the same state update: the class must be declared, and it must be a Cairo1 (V1) class: [2](#0-1) 

This is confirmed by unit tests that show blockifier rejecting a `replace_class` call with an undeclared class hash ("is not declared") and with a Cairo0 class hash ("Cannot replace V1 class hash with V0 class hash"): [3](#0-2) 

Because the blockifier accepts and executes a transaction (populating the resulting state diff, which is then fed as input/hints to the OS for proving) only after this validation, in the normal flow both components would agree. However, the OS itself performs no independent verification of this invariant when it re-executes the syscall from the hinted class hash. The hint-driven guessing (`%{ GetContractAddressStateEntry %}`) plus the absence of an assertion mirroring blockifier's `get_compiled_class`/`is_cairo1` check means the OS's own execution logic — which is what actually gets proven and is the ground truth for the STARK proof — does not enforce the "class hash must be declared" invariant that the CVE-analogous JWT bug pattern requires (a security-critical linkage/ownership check that is validated in one code path but silently skipped in another, authoritative one). If any other flow feeds a contract_address/class_hash pair to the OS without going through blockifier's syscall_base validation, or if a future bug/discrepancy in state read hints supplies an undeclared class hash to this codepath, the OS will silently accept the replace_class and commit it to the state root, producing a state root that blockifier would never produce for the equivalent inputs — an honest-node/prover divergence.

### Impact Explanation
A divergence between the blockifier's enforced invariant and the OS's un-enforced invariant on `replace_class` breaks the fundamental assumption that the Starknet OS re-execution (used to generate/verify the STARK proof of a block) is state-equivalent to the sequencer's blockifier execution. If exploited (e.g., through crafted state or a discrepancy in how the class-hash hint is populated), this could result in a committed state root reflecting a contract pointed at a class hash that was never declared/compiled, i.e. a wrong committed root, which is a listed acceptable-impact category (wrong committed root / honest-node divergence).

### Likelihood Explanation
Under the current architecture, since the block is normally built by blockifier — which already enforces the class-declared check before the state diff is produced — the OS's missing check is not directly triggerable by an ordinary attacker-controlled transaction in the mainline flow (the block would already reflect the blockifier-validated state). The TODO acknowledges the gap is intentional/known but unresolved, indicating the maintainers consider this a real correctness gap to be closed, consistent with a Medium-severity latent defensive-validation gap rather than an immediately exploitable Critical bug in the current single-path flow.

### Recommendation
Add an explicit assertion in `execute_replace_class` (mirroring blockifier's `syscall_base::replace_class`) that: (1) the given `class_hash` corresponds to a declared compiled class fact known to the OS (e.g., via `contract_class_changes` / compiled-class-fact dict lookup), and (2) the class is a Cairo1 (V1) class, before writing the new `StateEntry`. This removes the reliance on blockifier being the sole enforcer of this invariant and closes the divergence risk noted in the `TODO(Yoni, 1/1/2026)` comment.

### Proof of Concept
1. Construct (or hypothesize a code path providing) a `contract_state_changes` scenario where the OS is asked to execute a `replace_class` syscall with a `class_hash` that has no corresponding entry in `contract_class_changes` / declared classes.
2. Run the OS's `execute_replace_class` with this input: no assertion fires, and `dict_update` commits the new (undeclared) class hash into `contract_state_changes`, and the state diff / block hash reflects it.
3. Compare with blockifier: calling the equivalent `replace_class` syscall via `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash` demonstrates blockifier raises an "is not declared" error and refuses to update state for the same input — confirming the divergence between the two supposedly-equivalent execution engines.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

    assert!(error.to_string().contains("is not declared"));
}
