### Title
Media notification "source title" spoofing via unvalidated `MediaMetadata` fallback origin - ([File: chrome/android/junit/src/org/chromium/chrome/browser/media/ui/MediaNotificationTitleUpdatedTest.java])

### Summary
The Chrome-on-Android media notification pipeline lets script-provided Media Session metadata override the displayed "origin"/source text shown to the user in the media playback notification when the page's document title is empty, mirroring the CVE-2023-3737 spoofing pattern (media notifications showing attacker-controlled content instead of the true page origin).

### Finding Description
Chromium's media-notification UI is designed to always show the real page origin as a security signal, distinct from the attacker-influenced media title/artist/album fields sourced from the Media Session API (`navigator.mediaSession.metadata`). Tests in `MediaNotificationTitleUpdatedTest.java` show that when the document title is empty, the "source title" component of a `MediaMetadata` object is used both as a fallback display title and to overwrite `mMediaNotificationInfo.origin`, the field that the notification builder renders as the security-relevant subtext (`EXTRA_SUB_TEXT`) shown to the user: [1](#0-0) . This is further demonstrated in `testFallbackTitleUpdatesWhenSourceTitleChanges_WhenPageTitleEmpty`, where changing this metadata field on the fly re-writes both the origin field and the displayed title to arbitrary attacker-supplied strings such as `"first.example.com"` and `"second.example.com"` — values that resemble real origins but are not derived from the actual navigation/document origin: [2](#0-1) . The notification builder itself surfaces `info.origin` directly into the notification's subtext extra, which is exactly the field being overwritten: [3](#0-2) . The `origin` field is populated from tab navigation in the normal case (`simulateNavigation` sets a real `GURL` origin) as shown in `MediaNotificationTestTabHolder.java`: [4](#0-3) , but the "source title" metadata path bypasses this and substitutes a page/script-supplied value whenever the tab title is empty (e.g. an `about:blank` page or any page that clears `document.title`).

I was not able to locate the native/browser-side implementation that populates this "source title" field from the renderer (the `MediaSessionHelper.java`/`MediaSessionTabHelper` Java sources and the underlying `content::MediaMetadata`/Mojo struct definitions were not present in the indexed content, and `GetSourceTitlePlaceholder` in `chrome/browser/media/chrome_media_session_client.cc` only supplies an incognito placeholder, not the normal-mode logic). Given the size limits on the indexed codebase, some relevant files (particularly `MediaSessionHelper.java`, `MediaSessionTabHelper.java`, and the native `media_session.mojom`/`MediaMetadata` struct) could not be retrieved. A full confirmation of whether this "source title" is sanitized/validated against the true document origin before being substituted for `origin` would require inspecting those files directly — a Devin session with full repository access would be needed to confirm the exact provenance and any origin-validation logic that may exist upstream of what is visible in these JUnit tests.

### Impact Explanation
If the "source title" metadata field is attacker-controlled (i.e., set via the standard Media Session Web API from an untrusted page, without validation against the real navigation origin), a malicious page could spoof the notification's origin/subtext to display a misleading trusted-looking string (e.g., a bank or well-known site name) while actually running attacker JavaScript, enabling convincing security-UI (notification) spoofing consistent with the referenced CVE-2023-3737 bug class.

### Likelihood Explanation
Reaching this code path only requires an untrusted page to start a Media Session (playing background media) with an empty `document.title` and to set `MediaMetadata` with a crafted source-title-like value — no special privileges, flags, or user interaction beyond basic media playback and notification permission are required, making this readily reachable from remote web content if the underlying substitution is indeed unvalidated.

### Recommendation
Ensure the notification origin field displayed to the user is always derived from the verified navigation/document origin (e.g., `WebContents::GetLastCommittedOrigin()` equivalent) and never overwritten by script-supplied `MediaMetadata` fields such as source title; if a fallback display string is desired when the title is empty, keep it visually and semantically distinct from the origin/security-indicator text, and audit `MediaSessionHelper`/`MediaSessionTabHelper` and the corresponding native Media Session metadata plumbing to confirm no untrusted value flows into the `origin` field of `MediaNotificationInfo`.

### Proof of Concept
Not fully confirmable from indexed content alone: a page would call `navigator.mediaSession.metadata = new MediaMetadata({title: '', artist: '', album: '', /* source-title equivalent */ ...})` on an `about:blank`-like page with an empty `document.title` while playing media, which per the test `testFallbackTitleFromSourceTitle_WhenPageTitleEmpty` [1](#0-0)  causes the displayed notification origin/subtext to become the attacker-chosen string instead of the real origin. Full exploit confirmation requires inspecting the missing `MediaSessionHelper.java`/native Mojo metadata plumbing to verify there is no origin re-validation before this substitution reaches the UI.

    public void simulateNavigation(String url, boolean isSameDocument) {
        mUrl = url;

        // The following hoop jumping is necessary because loading real GURLs fails under junit.
        GURL gurl = mock(GURL.class);
        when(mWebContents.getVisibleUrl()).thenAnswer(invocation -> gurl);
        GURL gurlOrigin = mock(GURL.class);
        when(gurl.getOrigin()).thenAnswer(invocation -> gurlOrigin);
        when(gurlOrigin.getSpec()).thenAnswer(invocation -> url);

        NavigationHandle navigation =
                NavigationHandle.createForTesting(
                        gurl,
                        /* isInPrimaryMainFrame= */ true,
                        isSameDocument,
                        /* isRendererInitiated= */ false,
                        /* transition= */ 0,
                        /* hasUserGesture= */ false,
                        /* isReload= */ false);

        mMediaSessionTabHelper.mMediaSessionHelper.mWebContentsObserver
                .didStartNavigationInPrimaryMainFrame(navigation);

        navigation.callDidFinishForTesting(gurl);
        mMediaSessionTabHelper.mMediaSessionHelper.mWebContentsObserver
                .didFinishNavigationInPrimaryMainFrame(navigation);
    }
