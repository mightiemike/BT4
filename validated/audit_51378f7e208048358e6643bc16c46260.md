### Title
Unbonded attacker can force unlimited free on-chain account creation via the gasless-message allowlist - (File: `app/ante/account_init_decorator.go`)

### Summary
The external report describes a griefing pattern where an unprivileged actor can trigger a costly, protocol-wide side effect (the withdrawal queue) that is normally reserved for legitimate large transfers, purely by crafting input that satisfies a *type-based* trigger condition rather than an *identity/authorization*-based one. Push Chain has a structurally similar gap in its gasless-transaction admission path: `IsGaslessTx` classifies a transaction as fee-exempt purely by message `TypeURL`, and `AccountInitDecorator` uses that classification to unconditionally create a new on-chain account for the message signer — before the msg-server-level authorization check (bonded Universal Validator) ever runs.

### Finding Description
`txpolicy.IsGaslessTx` whitelists messages such as `MsgVoteInbound`, `MsgVoteOutbound`, and `MsgVoteChainMeta` purely by their protobuf type URL, with no check that the signer is an actual bonded/eligible Universal Validator: [1](#0-0) 

`AccountInitDecorator.AnteHandle` runs in the ante pipeline for any tx classified as gasless. If the signer has no on-chain account yet, it verifies only a trivial account_number=0/sequence=0 signature (something any attacker can produce for a freshly generated keypair) and then unconditionally creates and persists a new account, short-circuiting the rest of the ante chain (skipping normal fee deduction, gas metering, etc.): [2](#0-1) 

The actual authorization check — whether the signer corresponds to a bonded, non-tombstoned Universal Validator — only happens afterwards, inside the `x/uexecutor` message server, once the message reaches `VoteInbound`/`VoteOutbound`/`VoteChainMeta`: [3](#0-2) 

Because the account-creation side effect happens strictly earlier, in the ante handler, an attacker does not need to be a validator at all to trigger it. They only need to:
1. Generate a new keypair.
2. Sign one message with a whitelisted type URL (e.g., `MsgVoteInbound` with arbitrary/garbage `Inbound` fields) using account_number=0, sequence=0.
3. Submit it.

`AccountInitDecorator` will create and persist the account for free (no fee, no gas charged for the write since the decorator returns before fee/gas decorators run) and only *then* does the tx proceed to the msg server, which will reject it because the signer isn't a bonded UV — but the account has already been created and committed to state as a side effect of ante processing.

### Impact Explanation
This is directly analogous to the external report's bug class: an unprivileged actor manipulates a "type/threshold"-based trigger (message allowlist membership) rather than an identity/authorization-based one, to force a costly, chain-wide side effect (permanent state growth in the `auth` module's account store) that was intended to be reserved for a privileged, bounded set of actors (bonded Universal Validators submitting legitimate votes). Because the write is unconditional, free, and repeatable with a fresh keypair each time, an attacker can grow the account store indefinitely at zero on-chain cost, degrading state size and node resource consumption for the whole network — a non-network-level, unprivileged-reachable denial-of-service vector against chain state, consistent with the in-scope "denial of service... reachable without privileged control" impact category.

### Likelihood Explanation
High likelihood of reachability: no special privileges, no validator bonding, no capital outlay, and no interaction with honest validators/nodes is required — only crafting a syntactically valid, minimally-signed transaction whose sole message type matches the gasless allowlist. Keypair generation and a single ante-decorator-level signature are computationally trivial, so the attack can be scripted and repeated at whatever rate the mempool/CheckTx pipeline allows.

### Recommendation
- Move the bonded/eligible-Universal-Validator (or equivalent authorization) check ahead of, or into, the account-initialization short-circuit in `AccountInitDecorator`, so a new account is only auto-created for signers that the underlying gasless message type will actually accept (e.g., re-use `uvalidatorKeeper.IsBondedUniversalValidator` before creating state).
- Alternatively, decouple "is this message type fee-exempt" from "is this signer allowed to skip account funding": require gasless vote messages to originate only from addresses already known to `x/uvalidator`, and reject/charge normally for unknown signers attempting to use the gasless path.
- Consider rate-limiting or fee-charging account auto-creation via the gasless path, independent of the underlying message's ultimate authorization outcome.

### Proof of Concept
1. Generate an arbitrary new secp256k1/ed25519 keypair `K` with derived address `A` that has never been used on Push Chain (no existing `auth` account).
2. Construct a `MsgVoteInbound` (or `MsgVoteOutbound`/`MsgVoteChainMeta`) with `Signer = A` and arbitrary/garbage `Inbound` fields — the content does not need to be valid since it will be rejected downstream.
3. Sign the transaction with `K` using `account_number = 0`, `sequence = 0` (as required by `verifySignatureForNewAccount`), with zero fee and any gas value.
4. Submit the transaction. `AccountInitDecorator` classifies it as gasless via `IsGaslessTx`, sees `A` has no account, verifies the trivial signature, and calls `aid.ak.NewAccountWithAddress` + `SetAccount`, persisting the new account and returning success from the ante handler *before* the message server's bonded-UV check runs.
5. The subsequent msg-server call to `VoteInbound` fails with "universal validator for signer ... is not bonded", but the account creation from step 4 has already been committed.
6. Repeat with a fresh keypair for unbounded, cost-free account creation.

Note: I was unable to fully trace the complete ante-handler decorator ordering (`ante_cosmos.go`/`ante.go`) within the available search budget to confirm whether any earlier decorator (e.g., a `SetUpContextDecorator` gas meter) would impose a gas cost on this specific state write before `AccountInitDecorator` runs; this should be verified directly in `app/ante/ante_cosmos.go` and `app/ante/ante.go` during triage.

// IsGaslessTx checks if a transaction contains only allowed gasless message types
// Returns true if all messages in the transaction are in the allowed gasless message types
func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}

	ctx.Logger().Debug("account init decorator: existing account on gasless tx, passing to next handler",
		"address", sdk.AccAddress(newAccAddr).String(),
	)
	return next(ctx, tx, simulate)
}

// VoteInbound implements types.MsgServer.
func (ms msgServer) VoteInbound(ctx context.Context, msg *types.MsgVoteInbound) (*types.MsgVoteInboundResponse, error) {
	signerAccAddr, err := sdk.AccAddressFromBech32(msg.Signer)
	if err != nil {
		return nil, fmt.Errorf("invalid signer address: %w", err)
	}

	// Convert account to validator operator address
	signerValAddr := sdk.ValAddress(signerAccAddr)

	// Lookup the linked universal validator for this signer
	isBonded, err := ms.k.uvalidatorKeeper.IsBondedUniversalValidator(ctx, msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to check bonded status for signer %s", msg.Signer)
	}
	if !isBonded {
		return nil, fmt.Errorf("universal validator for signer %s is not bonded", msg.Signer)
	}

	isTombstoned, err := ms.k.uvalidatorKeeper.IsTombstonedUniversalValidator(ctx, msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to check tombstoned status for signer %s", msg.Signer)
	}
	if isTombstoned {
		return nil, fmt.Errorf("universal validator for signer %s is tombstoned", msg.Signer)
	}

	// continue with inbound synthetic creation / voting logic here
	err = ms.k.VoteInbound(ctx, signerValAddr, *msg.Inbound)
	if err != nil {
		return nil, err
	}

	return &types.MsgVoteInboundResponse{}, nil
}
