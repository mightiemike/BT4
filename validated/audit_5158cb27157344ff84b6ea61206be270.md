### Title
Batcher `call_contract` view calls run Cairo-Native execution on tokio's default-stack `spawn_blocking` threads, unlike block production's dedicated large-stack worker threads - ([File: crates/apollo_batcher/src/batcher.rs])

### Summary
The Jump Crypto/CosmWasm report describes a stack-overflow class of bug reachable through ordinary user-submitted contract logic. The sequencer already recognizes and explicitly mitigates this exact bug class for block-production execution: Cairo Native compiles Sierra recursion into real native calls that use the OS call stack (unlike the CairoVM, which simulates its stack on the heap), so `WorkerPool` and `TransactionExecutor::execute_txs_sequentially` spawn execution on dedicated threads with a configurable, gas-proportional `stack_size` specifically to guarantee "Out of gas" is hit before the native stack is exhausted. [1](#0-0) [2](#0-1) 

However, the batcher's view-call path (`Batcher::call_contract`, reachable by any unprivileged caller of the batcher's `call_contract` RPC) executes the same `RunnableCompiledClass::V1Native` code path via `call_view_entry_point`, but does so inside `tokio::task::spawn_blocking`, which runs on tokio's blocking thread pool with the **default** (un-configured) thread stack size — not the gas-proportional `stack_size` used by block production's worker pool. [3](#0-2) [4](#0-3) 

### Finding Description
`call_view_entry_point` bounds the call by `VIEW_CALL_MAX_SIERRA_GAS` / `VIEW_CALL_MAX_N_STEPS`, and dispatches to `entry_point_execution::execute_entry_point_call`, which for `RunnableCompiledClass::V1Native` classes invokes `native_entry_point_execution::execute_entry_point_call`, running the AOT-compiled native code directly on the calling thread. [5](#0-4) [6](#0-5) 

The comments in `WorkerPool::start` and `TransactionExecutor::execute_txs_sequentially` explicitly state the reasoning: "When running Cairo natively, the real stack is used and could get overflowed... We pre-allocate the stack here... so it needs to be big enough ahead... The gas upper bound is MAX_POSSIBLE_SIERRA_GAS, and sequencers must not raise it without adjusting the stack size." [7](#0-6) 

This sizing invariant is only enforced for the block-production/worker-pool paths (configured via `batcher_config.static_config.block_builder_config.execute_config.stack_size`, ~60 MB by default). [8](#0-7) 

`Batcher::call_contract`, by contrast, spawns the execution on a generic `tokio::task::spawn_blocking` closure with no stack-size configuration at all, meaning it runs on whatever stack size tokio's blocking-pool threads default to (Rust's default 2 MiB unless overridden elsewhere in the binary), which is far smaller than the ~60 MB the team deliberately provisioned for native recursion headroom. [3](#0-2) 

An attacker can therefore submit a `call_contract` request against a declared Cairo-Native class whose entry point recurses deeply within a single Sierra function (not via `call_contract_syscall`, so the `RecursionDepthGuard`'s 50-deep cross-call limit in `CallEntryPoint::execute` never triggers, since that guard only counts nested `CallEntryPoint::execute` invocations, not intra-function Sierra recursion). [9](#0-8) [10](#0-9) 

The project's own regression test (`test_stack_overflow`) demonstrates this exact scenario is realizable when the stack budget is not comfortably oversized relative to the gas bound: "This function was manually tested with increased maximum gas to ensure it reaches a stack overflow," and confirms Cairo Native recursion, unlike the VM's heap-simulated stack, is genuinely vulnerable absent a correctly proportioned native stack. [11](#0-10) 

### Impact Explanation
If the view-call thread's stack is exhausted before `VIEW_CALL_MAX_SIERRA_GAS`/`VIEW_CALL_MAX_N_STEPS` is reached, native code overrunning its stack causes a process-level SIGSEGV / abort (Rust cannot safely catch a real stack overflow — it is undefined behavior, not a recoverable panic). Since the batcher is a single process also responsible for building and validating blocks, crashing it via an unprivileged, gas-bounded RPC call is a remote, repeatable denial-of-service against block production — "a network unable to confirm new transactions" if this pattern is replicated across sequencers, or at minimum knocks the targeted node's batcher offline.

### Likelihood Explanation
Likelihood depends on whether `VIEW_CALL_MAX_SIERRA_GAS` amortized over the deepest reachable native recursion actually exceeds the tokio blocking thread's real stack budget before gas runs out — this is exactly the balance the team engineers deliberately for the worker-pool path but does not appear to configure for `spawn_blocking`. I was unable to directly verify (within the available tool budget) whether `VIEW_CALL_MAX_SIERRA_GAS` is small enough that native recursion is safely bounded on a default 2 MiB stack, whether Cairo Native is even enabled for view calls in production (`cairo_native_run_config.cairo_native_mode` defaults to `"off"` in `config_schema.json`, but the batcher config example sets it to `"lazy_compilation"`), or whether some other global stack-size override applies to all threads in the node binary (e.g., a `RUST_MIN_STACK` env var set at deployment). This is a **plausible, code-supported medium-severity finding** but not fully proven without runtime verification. [12](#0-11) [13](#0-12) 

### Recommendation
Route `Batcher::call_contract`'s blocking execution through a dedicated thread pool/thread builder with the same `stack_size` invariant used by `WorkerPool`/`TransactionExecutor` (proportional to `VIEW_CALL_MAX_SIERRA_GAS`, analogous to how block production sizes it to `MAX_POSSIBLE_SIERRA_GAS`), instead of the generic `tokio::task::spawn_blocking` pool, whenever the resolved class may run under Cairo Native.

### Proof of Concept
1. Declare and deploy a Cairo 1 contract compiled/whitelisted for Cairo Native (`native_classes_whitelist`) containing a non-tail-recursive entry point (mirroring the existing `test_stack_overflow`/`non_trivial_recursion` test contract pattern) with cost-per-recursion-level low enough that `VIEW_CALL_MAX_SIERRA_GAS` permits enough depth to exceed the default tokio blocking-thread stack.
2. Call the batcher's `call_contract` RPC (`CallContractInput { contract_address, entry_point: "test_stack_overflow", calldata: [large_depth] }`).
3. Observe the batcher process crash (SIGSEGV) instead of returning an `Out of gas`/`ContractCallFailed` error, unlike the equivalent path in block production which is protected by `WorkerPoolConfig::stack_size`.

```rust
// Intended for view-only entry points; any attempted state changes will be discarded.
// Bounded by VIEW_CALL_MAX_SIERRA_GAS and VIEW_CALL_MAX_N_STEPS, since the caller is blocked while
// the call runs, so the budget is sized for a read rather than for a whole transaction.

    state_reader: impl StateReader,
    block_context: Arc<BlockContext>,
    storage_address: ContractAddress,
    entry_point_name: &str,
    calldata: Calldata,

    let mut remaining_gas = VIEW_CALL_MAX_SIERRA_GAS;

    let execute_call = CallEntryPoint {
        entry_point_type: EntryPointType::External,
        entry_point_selector: selector_from_name(entry_point_name),
        calldata,
        class_hash: None,
        code_address: None,
        storage_address,
        caller_address: ContractAddress::default(),
        call_type: CallType::Call,
        initial_gas: remaining_gas.0,
    };

    // Create a dummy transaction info, since we are not in a context of a real transaction.
    let tx_context =
        Arc::new(TransactionContext { block_context, tx_info: TransactionInfo::default() });

    let limit_steps_by_resources = false;

        tx_context,
        ExecutionMode::Execute,

    context.cap_remaining_steps(VIEW_CALL_MAX_N_STEPS);

    execute_call.non_reverting_execute(&mut state, &mut context, &mut remaining_gas.0)
```

```rust
// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
```

```rust
pub fn execute_entry_point_call(
    call: ExecutableCallEntryPoint,
    compiled_class: NativeCompiledClassV1,
    state: &mut dyn State,
    context: &mut EntryPointExecutionContext,
) -> Result<CallInfo, EntryPointExecutionError> {
    let entry_point = compiled_class
        .get_entry_point(&call.type_and_selector())
        .map_err(EntryPointExecutionError::from)?;

    let mut syscall_handler: NativeSyscallHandler<'_> =
        NativeSyscallHandler::new(call, state, context);

    let gas_costs = &syscall_handler.base.context.gas_costs();
    let builtin_costs = BuiltinCosts {
        // todo(rodrigo): Unsure of what value `const` means, but 1 is the right value.
        r#const: 1,
        pedersen: gas_costs.builtins.pedersen,
        bitwise: gas_costs.builtins.bitwise,
        ecop: gas_costs.builtins.ecop,
        poseidon: gas_costs.builtins.poseidon,
        add_mod: gas_costs.builtins.add_mod,
        mul_mod: gas_costs.builtins.mul_mod,
        blake: gas_costs.builtins.blake,
    };

    // Pre-charge entry point's initial budget to ensure sufficient gas for executing a minimal
    // entry point code. When redepositing is used, the entry point is aware of this pre-charge
    // and adjusts the gas counter accordingly if a smaller amount of gas is required.
    let initial_budget = syscall_handler.base.context.gas_costs().base.entry_point_initial_budget;
    let call_initial_gas = syscall_handler
        .base
        .call
        .initial_gas
        .checked_sub(initial_budget)
        .ok_or(PreExecutionError::InsufficientEntryPointGas)?;

    let execution_result = compiled_class.executor.run(
        entry_point.selector.0,
        &syscall_handler.base.call.calldata.0.clone(),
        call_initial_gas,
        Some(builtin_costs),
        &mut syscall_handler,
    );
```
