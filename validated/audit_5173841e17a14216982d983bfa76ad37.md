### Title
Malformed-payload `capabilities.Response` in `HandleGatewayMessage` silently drops a pending `HandleSingleNodeRequest` caller, causing a full-timeout DoS - ([File: core/capabilities/webapi/outgoing_connector_handler.go])

### Summary
`OutgoingConnectorHandler.HandleGatewayMessage` unmarshals `body.Payload` into `capabilities.Response` for the `MethodWebAPITarget`, `MethodComputeAction`, and `MethodWorkflowSyncer` methods before forwarding the message to the waiting caller's channel. If unmarshalling fails, the function logs an error and does `return nil` without ever sending anything on `ch`, so the paired `HandleSingleNodeRequest` blocks until its full context timeout instead of returning an error immediately.

### Finding Description
In `HandleGatewayMessage` [1](#0-0) , once `hc.ValidatedMessageFromReq` succeeds and a pending channel is found via `c.responses.get(body.MessageId)`, the handler enters the method-specific branch: [2](#0-1) 

For the three known methods, `json.Unmarshal(body.Payload, &payload)` is only used to validate that the payload parses into `capabilities.Response`; the parsed `payload` variable is discarded and the original `msg` is what's sent on success. But on unmarshal failure, the code does `return nil` at line 359 with no write to `ch` and no error message pushed back — unlike the rate-limit path a few lines above (lines 334–348), which builds and sends a `MethodInternalError` message on `ch` when validation fails. This asymmetry means a syntactically valid, correctly signed message with a corrupted JSON `Payload` is silently dropped.

On the caller side, `handleSingleNodeRequest` only resolves via `case resp := <-ch:` or `case <-ctx.Done():` [3](#0-2) . If `ch` never receives, the call blocks for the full `req.TimeoutMs` (default 20s) plus 100ms margin [4](#0-3)  before returning `context.DeadlineExceeded`.

`HandleGatewayMessage` is invoked from `gatewayConnector.readLoop`, which dispatches whatever a connected Gateway sends over its established, mutually-authenticated WebSocket connection directly into the registered handler for the message's method [5](#0-4) . The only checks performed before reaching the vulnerable branch are structural JSON-RPC validation and message signature/shape validation in `ValidatedMessageFromReq`/`msg.Validate()` [6](#0-5)  and a per-sender/global rate limiter [7](#0-6)  — neither of which validates that `Payload` is a well-formed `capabilities.Response`. For `MethodWebAPITarget` in particular, the `Payload` content ultimately originates from an external HTTP target fetched by the Gateway on the workflow's behalf; that target is attacker-influenced content (an untrusted webhook/URL specified in a workflow spec), so an attacker who controls the response body of a fetched webAPI target (not the Gateway's signing key, and not privileged access to the node) can cause the Gateway to relay a validly-routed, matching-`MessageId` message whose `Payload` is not valid JSON for `capabilities.Response`, triggering the silent drop.

### Impact Explanation
This is a targeted, reliable DoS against a specific pending workflow/webAPI-target request: the calling goroutine in `HandleSingleNodeRequest` is stalled for up to `req.TimeoutMs` (default 20s, but caller-configurable and potentially large) for every malformed response, with no automatic retry logic in this handler (`// TODO: handle retries` comment confirms none exists). This matches "denial of service, degraded node availability" — repeated occurrences (e.g., a compromised or malicious external target consistently returning malformed responses for outgoing web-target fetches) can hold workflow execution to timeout every single call, materially degrading throughput/availability of affected workflows without any privileged access.

### Likelihood Explanation
Feasibility is high and requires no privileged credentials: an attacker who controls the content returned by a `MethodWebAPITarget` fetch target (or otherwise causes a matching, correctly-routed response with corrupted `Payload` for a live `messageID`) can trigger this deterministically and repeatedly, since the vulnerable code path performs no payload-shape validation before deciding whether to notify the caller versus dropping silently.

### Recommendation
On unmarshal failure in the `MethodWebAPITarget`/`MethodComputeAction`/`MethodWorkflowSyncer` branch, mirror the rate-limit error path: construct and send a `MethodInternalError` message (or otherwise push an error) onto `ch` before returning, so `HandleSingleNodeRequest` unblocks promptly with an explicit error instead of relying on context timeout. Ensure the `select { case ch <- errMsg: case <-ctx.Done(): }` pattern is used to avoid blocking indefinitely on a full channel.

### Proof of Concept
Unit test in `core/capabilities/webapi`:
1. Construct an `OutgoingConnectorHandler` with a fake `connector.GatewayConnector` (mock) sufficient to satisfy `handleSingleNodeRequest`'s calls (`DonID`, `SignMessage`, `awaitConnection`/`AwaitConnection`, `GatewayIDs`, `SendToGateway`).
2. In a goroutine, call `HandleSingleNodeRequest(ctx, messageID, req)` with a short `req.TimeoutMs` (e.g., 200ms) so the test completes quickly.
3. Once the request is registered (channel created via `responses.new`), synchronously call `HandleGatewayMessage(ctx, gatewayID, req)` with a `jsonrpc.Request` whose `Method` is `capabilities.MethodWebAPITarget`, `ID` equal to `messageID`, and `Params` containing an `api.Message` with `Payload: json.RawMessage("{not-valid-json")` and a signature/sender that passes `ValidatedMessageFromReq` and the incoming rate limiter.
4. Assert that `HandleSingleNodeRequest` returns quickly (well before the 200ms timeout) with a non-nil error (e.g., "unknown internal error" or similar), rather than returning `context.DeadlineExceeded` after the full timeout — demonstrating the fix. Under current code, the test would show the call blocking until `context.DeadlineExceeded` at ~200ms, confirming the vulnerability.

func (c *OutgoingConnectorHandler) HandleGatewayMessage(ctx context.Context, gatewayID string, req *jsonrpc.Request[json.RawMessage]) error {
	msg, err := hc.ValidatedMessageFromReq(req)
	if err != nil {
		c.lggr.Errorw("failed to validate request", "err", err, "gatewayID", gatewayID)
		return nil
	}
	body := &msg.Body
	l := logger.With(c.lggr, "gatewayID", gatewayID, "method", body.Method, "messageID", msg.Body.MessageId)

	ch, ok := c.responses.get(body.MessageId)
	if !ok {
		l.Warnw("no response channel found; this may indicate that the node timed out the request")
		return nil
	}

func (c *gatewayConnector) readLoop(gatewayState *gatewayState) {
	defer c.closeWait.Done()
	ctx, cancel := c.shutdownCh.NewCtx()
	defer cancel()

	for {
		select {
		case <-c.shutdownCh:
			return
		case item := <-gatewayState.conn.ReadChannel():
			var req jsonrpc.Request[json.RawMessage]
			err := json.Unmarshal(item.Data, &req)
			if err != nil {
				c.lggr.Errorw("parse error when reading from Gateway", "id", gatewayState.config.ID, "err", err)
				break
			}
			c.handlersMu.RLock()
			handler, exists := c.handlers[req.Method]
			c.handlersMu.RUnlock()
			if !exists {
				c.lggr.Errorw("no handler for method", "id", gatewayState.config.ID, "method", req.Method)
				break
			}
			// do not break on error. HandleGatewayMessage handles errors
			// by sending a response back to the Gateway.
			err = handler.HandleGatewayMessage(ctx, gatewayState.config.ID, &req)
			if err != nil {
				c.lggr.Warnw("failed to handle message from Gateway", "id", gatewayState.config.ID, "method", req.Method, "err", err)
			}
		}
	}

func ValidatedMessageFromReq(req *jsonrpc.Request[json.RawMessage]) (*api.Message, error) {
	if req.Version != "2.0" {
		return nil, errors.New("incorrect jsonrpc version")
	}
	if req.Method == "" {
		return nil, errors.New("empty method field")
	}
	if req.Params == nil {
		return nil, errors.New("missing params attribute")
	}
	var m api.Message
	err := json.Unmarshal(*req.Params, &m)
	if err != nil {
		return nil, fmt.Errorf("failed to unmarshal request params: %w", err)
	}
	m.Body.Method = req.Method
	m.Body.MessageId = req.ID
	err = m.Validate()
	if err != nil {
		return nil, err
	}
	return &m, nil
}
