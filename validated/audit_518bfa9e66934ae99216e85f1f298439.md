### Title
Unbounded recursion over attacker-controlled `bytecode_segment_lengths` nested structure during declare-time CASM hash verification can crash sequencer nodes - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
The Pillow advisory describes a bug class where an API recursively unpacks an attacker-supplied nested list into a fixed structure without validating its shape/depth, leading to memory corruption. The closest reachable analog in this codebase is `CasmContractClass::bytecode_segment_lengths`, a `NestedIntList` (`Leaf`/`Node(Vec<NestedIntList>)`) tree that is part of the contract class submitted directly by a contract declarer in a `DeclareV2`/`DeclareV3` transaction, and is processed via unbounded recursion during compiled-class-hash computation.

### Finding Description
`DeclareV3Transaction`/`DeclareV2Transaction` carry a full `ContractClass` (including, for Cairo1, a `CasmContractClass`) supplied by the sender. [1](#0-0) 
`CasmContractClass.bytecode_segment_lengths: Option<NestedIntList>` is deserialized as-is from that payload, with no depth or shape validation. [2](#0-1) 

When `block_casm_hash_v1_declares` is enabled, `DeclareTransaction::run_execute` calls `check_compile_class_hash_v2_declaration`, which computes `casm.hash(&HashVersion::V2)` directly on the attacker-supplied `CasmContractClass`. [3](#0-2) [4](#0-3) 

That hash computation walks the `NestedIntList` tree with plain recursion and no depth bound: [5](#0-4) 
`bytecode_hash_node` recurses once per `Node` level via `iter_children()`, so an attacker can submit a `bytecode_segment_lengths` value nested to an extreme depth (e.g., `Node([Node([Node([...Leaf(0)...])])])`) while keeping the actual `bytecode` tiny. Each recursion level costs one stack frame with no depth check, so sufficiently deep nesting exhausts the thread stack and aborts the process (Rust stack overflows are not catchable panics — they abort the process).

This mirrors the Pillow bug class: an externally supplied nested structure is recursively consumed without bounding its depth/shape before it reaches a resource with fixed capacity (there: a coordinate buffer; here: the call stack).

### Impact Explanation
Since `check_compile_class_hash_v2_declaration` runs during transaction execution (post-inclusion, as part of block building/re-execution) on every node that processes the block — sequencer building it, validators re-executing it, and full nodes replaying it — a single malicious declare transaction can deterministically crash every honest node that processes it. This can halt block production/consensus (a network unable to confirm new transactions), which is within the accepted impact categories.

### Likelihood Explanation
The `bytecode_segment_lengths` field is fully attacker-controlled at the RPC/gateway level (it's part of the CASM contract class the declarer submits), and I did not find any depth or size limit enforced on it in the stateless transaction validator or gateway (`crates/apollo_gateway/src/stateless_transaction_validator.rs`) — the only calldata-related bound found there is `validate_tx_extended_calldata_size`, which does not cover `bytecode_segment_lengths`. [6](#0-5) 
Reaching the vulnerable path requires the `block_casm_hash_v1_declares` feature flag to be enabled and a V3+ declare transaction, which limits certainty about default exposure in the currently deployed configuration.

### Recommendation
- Enforce a maximum nesting depth (and/or maximum node count) on `NestedIntList`/`bytecode_segment_lengths` during stateless validation of declare transactions, before it is ever hashed or otherwise recursed over.
- Convert `bytecode_hash_node`, `NestedFeltCounts::new_inner`, and `create_bytecode_segment_structure_inner` to iterative (explicit stack/queue based) implementations, or bound recursion depth explicitly and return an error instead of recursing unboundedly.
- Add fuzz/unit tests with deeply nested `NestedIntList` structures to confirm the fix bounds resource usage.

### Proof of Concept
Not independently executed (no sandbox access in this session); the following outlines the trigger path based on code inspection:
1. Craft a `DeclareV3Transaction` whose `contract_class` is a `CasmContractClass` with a tiny `bytecode` (e.g., `[0x1]`) but `bytecode_segment_lengths` set to a deeply right-nested structure, e.g. `Node([Node([Node([...(N times)...Leaf(1)...])])])` for N in the hundreds of thousands.
2. Submit the transaction so it reaches execution with `block_casm_hash_v1_declares` enabled, invoking `DeclareTransaction::run_execute` → `check_compile_class_hash_v2_declaration` → `casm.hash(&HashVersion::V2)` → `bytecode_hash` → `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs:111-132`).
3. The recursive call `bytecode_hash_node::<H, NL>(iter, child)` at line 125 recurses N times with no depth guard, exhausting the stack and aborting the process on every node that executes/re-executes the block containing this transaction. [7](#0-6)

    /// Verifies that the compiled class hash field in the declare tx,
    /// is compiled_class_hash_v2 of the compiled contract.
    pub fn check_compile_class_hash_v2_declaration(&self) -> Result<(), StarknetApiError> {
        let compiled_class = &self.class_info.contract_class;
        let compiled_class_hash_v2 = match &compiled_class {
            ContractClass::V0(_) => return Ok(()),
            ContractClass::V1((casm, _)) => casm.hash(&HashVersion::V2),
        };
        let compiled_class_hash = self.compiled_class_hash();
        if compiled_class_hash_v2 != compiled_class_hash {
            let err_var = CasmHashMismatch {
                hash: self.class_hash(),
                actual: compiled_class_hash,
                expected: compiled_class_hash_v2,
            };
            return Err(StarknetApiError::DeclareTransactionCasmHashMissMatch(Box::new(err_var)));
        }
        Ok(())
    }

/// Computes the hash of a bytecode segment. See the documentation of `bytecode_hash_node` in
/// the Starknet OS.
/// Returns the length of the processed segment and its hash.
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

                calldata_length: total_length,
                max_calldata_length: self.config.max_calldata_length,

    }
