### Title
Self-destructed contract's own account reset is invisible to `calc_diff_size`, letting a transaction push unpaid state-diff bytes to DA - (File: `crates/evm/src/evm/handler.rs`)

### Summary
`calc_diff_size` (invoked from `CitreaHandler::output` in `crates/evm/src/evm/handler.rs`) walks `JournalEntry::AccountDestroyed` and only marks the *target* of a `SELFDESTRUCT` transfer as `account_info_changed`, never the destructed `address` itself. [1](#0-0)  However `EvmDb::commit` in `crates/evm/src/evm/db_commit.rs` unconditionally resets the destructed account's `AccountInfo` to `DbAccountInfo::default()` and writes it to state whenever `account.is_selfdestructed()` is true (for `citrea_spec >= SpecId::TangeloSelfdestructFix`), regardless of whether the contract was created in the same tx. [2](#0-1)  This is a real, committed state write that will end up in the DA diff, but it is never counted in `TxInfo::l1_diff_size`.

### Finding Description
The invariant claimed is:
`TxInfo::l1_diff_size` (charged to the sender, set in `CitreaHandler::output`) == actual bytes committed to the state diff / DA blob for that transaction (produced by `EvmDb::commit` via `db_commit.rs`). [3](#0-2) 

Trace:
1. `calc_diff_size` builds `account_changes: BTreeMap<Address, AccountChange>` purely from `JournaledState::journal` entries (`NonceChange`, `BalanceTransfer`, `StorageChanged`, `CodeChange`, `AccountCreated`, `AccountDestroyed`). [4](#0-3) 
2. For `AccountDestroyed { address, target, was_destroyed, had_balance }`, when the account was not already destroyed earlier in the same tx, the code only marks `target` as changed if `address != target && !had_balance.is_zero()`. The destructing `address` is never added to `account_changes` by this branch. [1](#0-0) 
3. If `address` was not otherwise touched in the same tx (e.g. it is an already-deployed contract merely being called and then self-destructing, with no nonce/storage/code change of its own), it never enters `account_changes` at all, so it contributes `0` to the computed `diff_size`, and thus `0` to `TxInfo::l1_diff_size` and the `l1_fee` charged in `output`. [5](#0-4) 
4. Independently, `EvmDb::commit` (invoked when the EVM's `state` is written to the `WorkingSet`) checks `account.is_selfdestructed()` and, for the modern spec, calls `self.evm.account_set(&address, &DbAccountInfo::default(), self.working_set)` — an actual write of `address`'s account info (balance/nonce/code_hash reset) into rollup state, which is exactly the kind of write `DB_ACCOUNT_SIZE_* + DB_ACCOUNT_KEY_SIZE` accounts for elsewhere in `calc_diff_size`. [6](#0-5)  Note this reset fires for *any* selfdestruct under `TangeloSelfdestructFix`, not only "created-and-destroyed-in-same-tx" as the comment claims — the code has no `is_created()`/same-tx check at all.
5. This write ends up in the `WorkingSet`'s read/write log and therefore in the JMT state diff that is posted to DA, but was never added to `account_based_diff` in `calc_diff_size`.

Attacker's exact transaction: deploy (in an earlier block) a helper contract holding a non-trivial cBTC balance, whose fallback/selector calls `SELFDESTRUCT(beneficiary)`. In a later single transaction, call into that contract (optionally via many nested `CALL`s to multiple such pre-existing helper contracts, using `value`/`gas` to control how many are touched) so that each self-destructs, transferring balance to a `beneficiary`. Each of these produces a genuine `DbAccountInfo::default()` write for the destructed contract address that is never included in the account_changes computed by `calc_diff_size`, so the sender is not charged for it.

Existing guards do not catch this: `calc_diff_size` only inspects the journal, not the final `EvmDb::commit` behavior, and there is no cross-check between `TxInfo::l1_diff_size` and what is actually written to the `WorkingSet`/DA diff.

### Impact Explanation
Every user transaction that self-destructs an already-deployed (not created-in-same-tx) contract commits an uncharged account-info write to the state diff that will be included in the batch's DA blob, while `L1_FEE_VAULT` under-collects the corresponding fee. This is repeatable per self-destructed contract and can be amplified by nested calls that self-destruct many pre-deployed contracts in one transaction, scaling the uncharged bytes with the number of destructed contracts touched (bounded only by gas limit). The result is a systemic leak where DA-posting costs incurred by the sequencer/protocol are not recovered from the responsible sender, i.e., value that should flow into `L1_FEE_VAULT` (and ultimately cover Bitcoin inscription costs) is withheld — an under-collection of protocol/vault revenue proportional to attacker activity, deterministic and identical across all honest nodes (since `calc_diff_size` is pure state-machine logic executed identically everywhere), so it does not cause node/prover divergence but does cause systemic fee under-collection.

### Likelihood Explanation
No special privileges are required: any unprivileged user can deploy a contract, fund it, and call `SELFDESTRUCT` from a later transaction. The only cost is normal gas and the (now discounted) L1 fee itself. This is trivially and repeatably reachable on every Citrea deployment running post-`TangeloSelfdestructFix` spec.

### Recommendation
In `calc_diff_size`'s handling of `JournalEntry::AccountDestroyed`, also mark the destructing `address` itself as `account_info_changed` whenever `EvmDb::commit` will actually reset/write its `AccountInfo` (i.e., whenever `is_selfdestructed()` will trigger a DB write under the active spec), mirroring the exact condition used in `crates/evm/src/evm/db_commit.rs`. More robustly, compute `l1_diff_size` from the same source of truth used by `EvmDb::commit` (the final `Account`/`state` map with `is_touched()`/`is_selfdestructed()` flags) rather than reconstructing it independently from raw journal entries, to guarantee the charged size and the committed diff can never diverge for any future `JournalEntry` variant or commit-path change.

/// Calculates the diff of the modified state.
#[cfg_attr(feature = "native", instrument(level = "trace", skip_all))]
fn calc_diff_size<CTX>(context: &mut CTX) -> usize
where
    CTX: CitreaContextTr,
{
    let (journaled_state, tx) = (context.journal_ref(), context.tx());

    // For each call there is a journal entry.
    // We need to iterate over all journal entries to get the size of the diff.
    let journal = journaled_state.journal.iter().flatten();
    let state = &journaled_state.state;

    #[derive(Default)]
    struct AccountChange<'a> {
        storage_changes: BTreeSet<&'a U256>,
        account_info_changed: bool, // implies balance, nonce or code_hash changed
    }

    let mut account_changes: BTreeMap<&Address, AccountChange<'_>> = BTreeMap::new();

    // tx.from always has `account_info_changed` because its nonce is incremented
    let tx_caller = tx.caller();
    let from = account_changes.entry(&tx_caller).or_default();
    from.account_info_changed = true;

    // Special handling for eip7702 transactions
    // as there is no journal entry for changes on the authority

    // collecting then consuming the iterator
    // to avoid borrowing issues
    // also not doing tx type check as authorization_list will return empty list
    let auths = tx
        .authorization_list()
        .filter_map(|auth| {
            let delegated_to = auth.address();
            let authority = auth.authority();
            authority.map(|authority| (authority, delegated_to))
        })
        .collect::<Vec<_>>();

    for (authority, delegated_to) in &auths {
        // if returns None, the authorization failed at one of the following checks:
        // - if the chain id check failed
        // - if nonce was u64::MAX
        // - if the signer couldn't be recovered <-- this case is not possible as we checked this on the above
        //   if let
        if let Some(authority_in_state) = journaled_state.state.get(authority) {
            // if the final code of the authority is equal to delegated address
            // or the delegated address is zero and the account code hash is KECCAK_EMPTY
            // we know the authorization went through
            if (delegated_to == &Address::ZERO && authority_in_state.info.code_hash == KECCAK_EMPTY)
                || authority_in_state
                    .info
                    .code
                    .as_ref()
                    .is_some_and(|code| *code == Bytecode::new_eip7702(*delegated_to))
            {
                // we set account changed for the authority
                let account = account_changes.entry(authority).or_default();
                account.account_info_changed = true;
            }
        }
    }

    for entry in journal {
        match entry {
            JournalEntry::NonceChange { address } => {
                let account = account_changes.entry(address).or_default();
                account.account_info_changed = true;
            }
            JournalEntry::BalanceTransfer { from, to, .. } => {
                // No need to check balance for 0 value sent, revm does not add it to the journal
                let from = account_changes.entry(from).or_default();
                from.account_info_changed = true;
                let to = account_changes.entry(to).or_default();
                to.account_info_changed = true;
            }
            JournalEntry::StorageChanged { address, key, .. } => {
                let account = account_changes.entry(address).or_default();
                account.storage_changes.insert(key);
            }
            JournalEntry::CodeChange { address } => {
                let account = account_changes.entry(address).or_default();
                account.account_info_changed = true;
            }
            // Only added to the journal on smart contract creation
            JournalEntry::AccountCreated { address } => {
                let account = account_changes.entry(address).or_default();
                account.account_info_changed = true;
            }
            JournalEntry::AccountDestroyed {
                address,
                target,
                was_destroyed,
                had_balance,
            } => {
                // This event is produced only if acc.is_created() || !is_cancun_enabled
                // State is not changed:
                // * if we are after Cancun upgrade and
                // * Selfdestruct account that is created in the same transaction and
                // * Specify the target is same as selfdestructed account. The balance stays unchanged.

                if *was_destroyed {
                    // It was already destroyed before in the log, no need to do anything.
                    continue;
                }

                // transferred balance causes account diff change on target
                if address != target && !had_balance.is_zero() {
                    // mark changes to the target account
                    let target = account_changes.entry(target).or_default();
                    target.account_info_changed = true;
                }
            }
            _ => {}
        }
    }
