### Title
Empty-but-non-`None` signer set drives the Nakamoto approval threshold to 0, letting a block be accepted with zero signer signatures - (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
The Sherlock finding is a "zero participants → degenerate divide/flow-rate becomes 0 → check silently passes" bug class. The analogous consensus-critical equality in this repo is `NakamotoBlockHeader::verify_signer_signatures`, which must guarantee that a block is approved only if signers holding at least `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` (70%) of the total signing weight actually signed it. If `total_signing_weight()` can be `0` while `reward_set.signers()` is still `Some(vec![])` (i.e. an empty-but-present list, distinct from `None`), the computed threshold becomes `0`, and the "not enough signatures" check `total_weight_signed < threshold` trivially passes for `total_weight_signed == 0`. A block with **no signer signatures at all** would then satisfy `verify_signer_signatures`.

### Finding Description
`RewardSet::total_signing_weight()` in `stackslib/src/chainstate/stacks/boot/mod.rs:495-503` only errors when `self.signers()` returns `None`; if `signers()` returns `Some(&vec![])` it silently folds over an empty iterator and returns `Ok(0)`.

`NakamotoBlockHeader::verify_signer_signatures` (`stackslib/src/chainstate/nakamoto/mod.rs:1096-1190`) computes:
```
let total_weight = reward_set.total_signing_weight().map_err(|_| ChainstateError::NoRegisteredSigners(0))?;
...
let threshold = Self::compute_voting_weight_threshold(total_weight)?;
if total_weight_signed < threshold { return Err(...) }
```
`compute_voting_weight_threshold` (`stackslib/src/chainstate/nakamoto/mod.rs:1194-1207`) computes `threshold = ceil(total_weight * 7 / 10)`. For `total_weight == 0`, `threshold == 0`. Since `total_weight_signed` starts at `0` and the loop over `self.signer_signature` (which can be empty) never executes, `0 < 0` is `false`, and the function returns `Ok(0)` — the block is treated as validly signed with **zero actual signer participation**.

The remaining question is reachability of `signers() == Some(vec![])`:
- For PoX-5 (`pox_5_compute_and_update_signers` in `stackslib/src/chainstate/nakamoto/signer_set.rs:744-820`), the code explicitly checks `if signer_set.is_empty() { return Err(...) }`, so this path is guarded.
- For V0/PoX-4 (`StacksChainState::make_signer_set`, `stackslib/src/chainstate/stacks/boot/mod.rs:1020-1072`), the filter only drops individual entries whose `weight == 0` (`stacked_amt / threshold == 0`); there is **no check that the resulting `signer_set` Vec is non-empty** before it is wrapped in `Some(signer_set)` and returned. If the computed `threshold` is large enough relative to every individual stacker's `amount_stacked` (e.g., due to a degenerate/very-high reward threshold relative to actual participation), every entry can floor to `weight == 0`, and the function returns `Some(vec![])` rather than `None`. This is distinct from the `entries.is_empty()` early-return at the top of the function, which only guards against *no PoX entries at all*, not against *entries whose computed weight is uniformly zero*.

This mirrors the FluidLocker/Sherlock root cause exactly: a "zero participants" edge case where a downstream rate/threshold degenerates to `0` and a guard (`< threshold`) that should block the vacuous case instead vacuously passes.

### Impact Explanation
If this state is reached, `verify_signer_signatures` would accept a Nakamoto block validated by zero real signer signatures, i.e. a block for which no honest quorum actually attested to validity. This is a "signer weight below threshold" divergence — the network-wide equality that "an accepted block was actually approved by ≥70% signing weight" is broken. Depending on which code path consumes this (block acceptance, StackerDB coordination), this could let a malicious miner produce and have accepted a block without any legitimate signer approval — a Critical-class outcome (invalid block accepted network-wide) if reachable, or High if it is bounded to a coordination edge case (e.g., a stalled/degenerate reward-cycle transition) rather than the mainline path.

### Likelihood Explanation
Likelihood is **uncertain/low-to-moderate** and could not be fully confirmed within available context: it depends on whether `StacksChainState::make_signer_set`'s threshold/entries computation can realistically produce a non-empty `entries` list where every individual `stacked_amt / threshold` floors to `0` for the legacy PoX-4/V0 reward-set path in production configurations (this is the classic "degenerate floor-and-drop" pattern the codebase's own regression test `equal_stakes_exceeding_reward_slots_are_not_all_zeroed` in `stackslib/src/chainstate/nakamoto/tests/signer_set.rs:294-336` was written to fix for the *newer* PoX-5 apportionment scheme — but that fix (largest-remainder / Hare method) was applied only in `pox_5_make_signer_set`, not in the older `StacksChainState::make_signer_set` used for PoX-4/V0). This asymmetry — one path patched against the "all entries floor to zero" bug, the other (older) path not — is the concrete signal that this analog is plausible, but I could not verify within this pass whether calling contexts for the V0 path enforce a minimum-threshold invariant elsewhere that would prevent `entries` all flooring to zero in practice.

### Recommendation
1. In `StacksChainState::make_signer_set` (`stackslib/src/chainstate/stacks/boot/mod.rs:1020`), after building `signer_set`, explicitly check `if signer_set.is_empty() { return None; }` so an all-zero-weight outcome is treated identically to "no signer set" (matching the guard already present in `pox_5_compute_and_update_signers`).
2. In `RewardSet::total_signing_weight()` (`stackslib/src/chainstate/stacks/boot/mod.rs:495`), treat `Some(&vec![])` the same as `None` and return an error, rather than `Ok(0)`.
3. In `compute_voting_weight_threshold` (`stackslib/src/chainstate/nakamoto/mod.rs:1194`), explicitly reject `total_weight == 0` rather than silently producing a `threshold` of `0`.

### Proof of Concept
Conceptual (not runnable without full node harness):
1. Construct a PoX-4/V0 reward cycle where every individual stacker's `amount_stacked` is non-zero but `amount_stacked / threshold == 0` for all stackers (i.e., a threshold computed larger than every individual stack) via `StacksChainState::make_signer_set`.
2. This yields `RewardSet::V0` with `signers: Some(vec![])` (non-`None`, but empty).
3. Call `NakamotoBlockHeader::verify_signer_signatures` on a `NakamotoBlockHeader` with an **empty** `signer_signature` vector against this reward set.
4. `total_signing_weight()` returns `Ok(0)` (`stackslib/src/chainstate/stacks/boot/mod.rs:499-502`); `compute_voting_weight_threshold(0)` returns `Ok(0)` (`stackslib/src/chainstate/nakamoto/mod.rs:1194-1207`); the loop over signatures never runs, leaving `total_weight_signed = 0`; the check `0 < 0` is `false`, so `verify_signer_signatures` returns `Ok(0)` instead of an error — the block is treated as validly signed despite zero signer participation.         let Some(signers) = self.signers() else {
            return Err("Unable to calculate total weight - No signers in reward set".to_string());

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
    }

    #[cfg_attr(test, mutants::skip)]
    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);
    }

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );
}
