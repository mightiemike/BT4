### Title
Undocumented, unbounded 5% AMM slippage tolerance in PRC20↔PC auto-swap paths enables value extraction via same-block price manipulation - (File: x/uexecutor/keeper/execute_inbound_gas.go, execute_inbound_gas_and_payload.go, outbound.go)

### Summary
Every inbound-deposit auto-swap and outbound gas-refund auto-swap on Push Chain computes `minPCOut` as a hardcoded `quote * 95 / 100`, where `quote` is fetched live from a Uniswap-V3-style `QuoterV2.quoteExactInputSingle` on the same PRC20/WPC pool that the swap itself will execute against, in the same transaction. The 5% constant and the underlying pool-manipulation risk are never explained or bounded anywhere in the code, tests, or module docs — this is the direct analog of the Augur report's "undocumented mathematical operations" class of finding: a fund-moving calculation whose rationale and safety envelope were never made explicit, which in this case hides a real value-extraction vector rather than just a readability problem.

### Finding Description
`GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`) queries the price at the moment the swap is about to execute, from the same pool the swap will use. `minPCOut` is then derived from that instantaneous quote with a flat 5% tolerance:
```go
// 5% slippage: minPCOut = quote * 95 / 100
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
```
This pattern is duplicated in three fund-moving flows:
- Inbound `GAS` deposits — `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:104-153`), converting a user's bridged gas-token PRC20 into PC deposited to their UEA.
- Inbound `GAS_AND_PAYLOAD` deposits — `gasAndPayloadDepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:347-379`).
- Outbound excess-gas refunds — `applyGasRefund` (`x/uexecutor/keeper/outbound.go:174-257`), swapping leftover gas-token PRC20 back to PC for the refund recipient.

Because both the quote and the swap execution happen inside the same validator-driven `DerivedEVMCall`/`CallEVM` sequence at the same block, an unprivileged actor with capital who can move the price of the specific PRC20/WPC pool (e.g., a large swap, JIT liquidity add/remove, or any other single-block price shift within the pool the protocol uses for that gas token) can push the AMM price down before the protocol's auto-swap executes. The quote — and therefore `minPCOut` — is computed against that already-depressed price, so the protocol accepts up to 5% less PC than fair value for the swap, and the attacker captures the difference by trading back against the pool after the protocol's swap lands. None of the three call sites document why 5% was chosen, whether the constant scales with amount, or how (if at all) the pool is protected from single-block manipulation — the code silently accepts a fixed, generous slippage band on a live, attacker-influenceable quote.

### Impact Explanation
Each occurrence directly moves protocol- or user-custodied PRC20/PC value (user deposits being auto-swapped into their own UEA, and protocol-refunded excess gas). A pool-price manipulation attack extracts value up to the full 5% tolerance per swap, repeatable per inbound/outbound event, funded from user deposit amounts and from protocol refund reserves — this is unauthorized value extraction/drain reachable through ordinary user-triggered deposit and outbound-refund flows, matching the "corruption of PRC20 or native asset accounting" and "draining of protocol-controlled funds" impact categories.

### Likelihood Explanation
Exploitability depends entirely on the liquidity depth and manipulability of the specific PRC20/WPC pool selected via `GetUniversalCoreQuoterAddress`/`GetDefaultFeeTierForToken` for a given gas token — for low-liquidity or thinly-traded gas tokens (which is plausible for the long tail of supported chains' native gas assets), a modest amount of capital can move price by more than 5% within a single block, making the attack economically viable. The lack of any TWAP, oracle cross-check, or amount-scaled slippage bound means the guard rail is fixed regardless of pool depth, increasing likelihood for exactly the pools most likely to be added over time.

### Recommendation
Document and then fix the underlying assumption: either (a) source the reference price from a manipulation-resistant TWAP oracle rather than a spot `quoteExactInputSingle` call executed in the same block as the swap, (b) tighten and scale the slippage tolerance based on pool depth/trade size rather than a flat 5% constant, or (c) add a circuit breaker that reverts (falling back to the no-swap PRC20 deposit path, which already exists) when the spot quote deviates materially from a recent moving average. At minimum, add explicit inline documentation of the manipulation model this 5% figure is meant to tolerate, per the same recommendation the original Augur report made for undocumented economic calculations.

### Proof of Concept
1. Identify a supported external chain whose gas-token PRC20/WPC pool (looked up via `GetUniversalCoreQuoterAddress` + `GetDefaultFeeTierForToken`) has limited liquidity.
2. Within the block/transaction window before a pending inbound `GAS` or `GAS_AND_PAYLOAD` deposit (or an outbound gas refund) is executed by validators, submit a trade against that pool to depress the PRC20→WPC price.
3. When validators' vote finalizes and triggers `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`/`applyGasRefund`, `GetSwapQuote` returns the manipulated (lower) quote; `minPCOut = quote*95/100` is computed from it and the swap in `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes at that below-fair-value rate.
4. Immediately reverse the initial trade to restore the pool price, capturing the spread between fair value and the manipulated execution price — funded by the user's deposit amount or the protocol's refund reserve.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
