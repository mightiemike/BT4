### Title
Missing L1 recipient address validation in Starknet OS `send_message_to_l1` syscall execution diverges from Blockifier enforcement - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The report describes a bug class where a bridging function fails to validate the destination/recipient before committing an irreversible cross-domain operation, permanently losing funds. The analogous root cause exists in the Starknet sequencer stack: the Rust `Blockifier` enforces that `to_address` in the `send_message_to_l1` syscall is a valid 160-bit Ethereum address (for non-L3 chains), but the Cairo Starknet OS program that re-executes transactions for proving performs no such check at all, for either the Cairo1 or the deprecated Cairo0 syscall path.

### Finding Description
Any unprivileged contract, reachable by any transaction sender, can invoke the `send_message_to_l1` syscall with an arbitrary `to_address` felt. In the Blockifier, this is checked: [1](#0-0) 

and identically in the deprecated syscall handler: [2](#0-1) 

Both paths call `EthAddress::try_from(...)` and reject the call with an "Out of range" error when `to_address` exceeds the 160-bit Ethereum address space, *unless* `chain_info.is_l3` is true. This is confirmed by the existing unit tests: [3](#0-2) [4](#0-3) 

However, the Starknet OS (the Cairo program used to independently re-execute and prove the block, per the "Starknet OS re-execution" scope) implements `send_message_to_l1` for Cairo1 contracts without any address validation whatsoever: [5](#0-4) 

and the deprecated (Cairo0) OS execution path is likewise unchecked: [6](#0-5) 

A grep for `EthAddress` across all `.cairo` sources in the OS package returns zero matches in the OS execution code itself (only in test/feature contracts), confirming the OS never performs this bounds check. The Rust-based SNOS syscall executors used elsewhere also simply return `Ok(...)` for `send_message_to_l1` without inspecting `request.message.to_address`: [7](#0-6) [8](#0-7) 

This produces a semantic gap between the two independent implementations of the same protocol rule that must agree bit-for-bit for the STARK proof to soundly attest to the sequencer's real execution:
- The Blockifier (which the honest sequencer runs to build/validate blocks) reverts a call on a non-L3 chain when `to_address` is out of the valid Ethereum address range, so no `MessageToL1Header` is emitted for that call and the transaction's real execution outcome reflects the revert.
- The Starknet OS (which recomputes execution independently as part of the SNOS re-execution/proving pipeline) has no equivalent check, so if it is fed (via hints or a divergent trace) a call chain that reaches `send_message_to_l1` with an out-of-range `to_address`, it will unconditionally accept it and write the `MessageToL1Header` into the OS-computed `messages_to_l1` output segment, which flows into `output.cairo` and ultimately the block's committed output/state diff.

### Impact Explanation
This is a validation asymmetry between the two required execution engines (Blockifier vs. Starknet OS) for the exact same syscall rule. Per the Starknet architecture, both engines are supposed to produce identical results for identical inputs so that the STARK proof genuinely attests to the sequencer's block. Because the OS omits the check the Blockifier performs, an execution path/trace that the honest Blockifier would revert can be silently accepted by the OS and embedded into the proven output as a legitimate `L2ToL1` message with an invalid Ethereum address. Consequences include:
- Honest-node divergence: a node relying on OS-verified output could accept a block/message set that a node running the Blockifier would never have produced, violating consensus on committed messages.
- Wrong committed root/output: the OS-computed messages-to-L1 commitment (part of the L2 state diff/output sent to L1) could include a message that never should have existed according to protocol rules, corrupting the block's output commitment.
- Concrete loss of funds: if such a malformed/invalid-address `L2ToL1` message (e.g., resulting from a bridging contract call, analogous to the reported `burnAndBridge`) is embedded in the proven output, it can never be consumed on L1 (no valid Ethereum contract exists at an out-of-range address), permanently locking any bridged value tied to that message — mirroring the "irrevocable loss of funds" impact in the original report.

This satisfies the Medium/High bar since it can cause a wrong committed output/root and honest-node divergence, not merely a resource/gas issue.

### Likelihood Explanation
The syscall is reachable by any unprivileged Cairo1 (and Cairo0/deprecated) contract via a single ordinary transaction — no special privileges are required, matching the "unprivileged transaction sender" reachability constraint. The only barrier to exploitation is whatever mechanism feeds the OS its execution trace/hints (normally derived from the same Blockifier run); however, the underlying code-level guarantee that both engines *independently* enforce the same invariant is broken, so the safety of the system currently depends entirely on hint-trustworthiness/consistency rather than the OS's own independent verification — which undermines the very purpose of re-execution/proving. This is a real logic bug rather than a hypothetical: the check is textually present in one implementation and textually absent in the other for the identical syscall and identical validity rule.

### Recommendation
Add the same `EthAddress` range validation (`to_address` must fit in 160 bits, skipped only when `is_l3` is true, matching Blockifier's `chain_info.is_l3` gate) to the Starknet OS Cairo implementations of `send_message_to_l1`:
- `execute_send_message_to_l1` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`
- The deprecated syscall dispatch block in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/deprecated_execute_syscalls.cairo`
- The corresponding Rust SNOS executors (`snos_syscall_executor.rs`, `snos_deprecated_syscall_executor.rs`) should also enforce/propagate the same validation instead of unconditionally returning `Ok(...)`.

Ensure the `is_l3` context flag is threaded into these OS-side execution functions identically to how `chain_info.is_l3` is threaded into the Blockifier, so both engines reject (or both accept) the exact same set of `to_address` values.

### Proof of Concept
1. Deploy a Cairo1 contract on a non-L3 Starknet chain (`is_l3 == false`) that calls the `send_message_to_l1` syscall with `to_address = 0x10000000000000000000000000000000000000000` (161 bits, out of the valid 160-bit Ethereum address range) — the same value used in the existing Blockifier regression test. [9](#0-8) 
2. Submitting this as a normal transaction, the Blockifier rejects it with an "Out of range" error and the call reverts, so no `L2ToL1` message is produced in the real block execution.
3. Independently invoke the Starknet OS's `execute_send_message_to_l1` (as used by the SNOS re-execution/proving flow) with the same `to_address` and payload — because no `EthAddress::try_from`-equivalent check exists in `syscall_impls.cairo`, the call succeeds and a `MessageToL1Header` entry with the invalid `to_address` is written to `outputs.messages_to_l1`. [10](#0-9) 
4. This demonstrates that identical inputs produce divergent accept/reject outcomes between the Blockifier and the OS, confirming the missing validation and the resulting risk of a corrupted/invalid committed L2-to-L1 message output.

// Sends a message to L1.
func execute_send_message_to_l1{range_check_ptr, syscall_ptr: felt*, outputs: OsCarriedOutputs*}(
    contract_address: felt
) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, SendMessageToL1Request*);
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=SEND_MESSAGE_TO_L1_GAS_COST, request_struct_size=SendMessageToL1Request.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    tempvar payload_start = request.payload_start;
    tempvar payload_size = request.payload_end - payload_start;

    assert [outputs.messages_to_l1] = MessageToL1Header(
        from_address=contract_address, to_address=request.to_address, payload_size=payload_size
    );
    memcpy(
        dst=outputs.messages_to_l1 + MessageToL1Header.SIZE, src=payload_start, len=payload_size
    );
    let (outputs) = os_carried_outputs_new(
        messages_to_l1=outputs.messages_to_l1 + MessageToL1Header.SIZE + payload_size,
        messages_to_l2=outputs.messages_to_l2,
    );

    return ();
}
