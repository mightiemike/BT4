Self-referential Uniswap V3 spot-price quote allows sandwich-attack theft of gas-refund/auto-swap value - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The `ZunamiStratBase`/`ZunamiPool` bug class is: a value used to price a mutation of pooled funds is read live at execution time and is not protected against being distorted between the moment it is fetched and the moment it is consumed, letting an attacker capture the resulting mispricing at the expense of the protocol/other users. The Push Chain analog is in the gas-abstraction auto-swap and gas-refund-swap paths of `x/uexecutor`, where `GetSwapQuote` reads a live Uniswap V3 `QuoterV2.quoteExactInputSingle` spot-simulated price and that *same* number is used both as the reference price and as the basis for its own slippage floor (`minPCOut = quote * 95 / 100`), giving no independent protection against price manipulation.

### Finding Description
`GetSwapQuote` in `x/uexecutor/keeper/evm.go` (lines ~500-538) calls the on-chain `QuoterV2.quoteExactInputSingle`, which simulates a swap against the *current* state of the PRC20/WPC Uniswap V3 pool [1](#0-0) . This quote is then used, in `ExecuteInboundGas` (gas top-up auto-swap path) and in `applyGasRefund` (unused-gas refund swap path in `x/uexecutor/keeper/outbound.go`), to compute the *only* slippage protection for the subsequent swap:

```
minPCOut := quote * 95 / 100
CallPRC20DepositAutoSwap(..., fee, minPCOut)   // execute_inbound_gas.go
CallUniversalCoreRefundUnusedGas(..., fee, minPCOut) // outbound.go
``` [2](#0-1) [3](#0-2) 

Because both the "expected" value (`quote`) and the "protection" (`minPCOut`) derive from the identical spot read taken immediately before the swap executes, an attacker who can insert their own transaction into the Push Chain EVM mempool/block ahead of (and after) the module-originated `DerivedEVMCall` can manipulate the pool's reserves just before the quote is read, causing the quote (and thus `minPCOut`) to reflect a depressed exchange rate. The module's swap then executes at that manipulated rate; the attacker's follow-up transaction restores the pool price and captures the difference. This is the classic sandwich pattern against AMM spot-price quoters, and here it is structurally guaranteed to succeed because there is no TWAP, no external price bound, and no minimum-output floor independent of the manipulated quote itself.

This directly parallels the audited bug: a value (LP token price / swap quote) fetched at execution time is used to determine how much value moves through an accounting boundary (share minting / PRC20↔native swap) without any protection against that value having been distorted by the very actor who benefits from the distortion.

### Impact Explanation
A successful sandwich against `ExecuteInboundGas`'s auto-swap or `applyGasRefund`'s swap-refund extracts value that should have gone to: (a) the gas-abstraction user (who ends up with less PC gas top-up than the honest exchange rate would provide), or (b) the outbound sender being refunded unused gas (who receives less PC than entitled). The value is siphoned to whichever unprivileged party front-runs/back-runs the module's derived EVM call. This falls under "corruption of ... gas fee accounting, refund accounting" and "unauthorized module-originated EVM execution" producing an incorrect state transition, both explicitly in scope. Funds are not permanently frozen but real value is misrouted from the protocol/user to an attacker on every occurrence, and it is repeatable at will whenever gas top-ups or gas refunds with swaps occur.

### Likelihood Explanation
Likelihood is bounded by two factors: (1) it requires the attacker to control transaction ordering relative to the module's own `DerivedEVMCall` within the block containing/observing the vote-finalization message — which is plausible for anyone who can see pending inbound-vote-threshold transactions and submit their own EVM transactions against the same block (an ordinary unprivileged capability, not requiring validator/relayer privilege); and (2) it requires meaningful liquidity depth constraints on the underlying pool to make the sandwich profitable, which is an economic rather than a code condition. Given the module performs this swap synchronously and deterministically from a widely observable trigger (vote threshold reached / outbound observed), and the fix (95% floor derived from the same quote) provides no real protection, the likelihood of a profitable attack is non-negligible whenever swap amounts and pool depth make it worthwhile.

### Recommendation
Do not derive the slippage floor from the same just-fetched spot quote used for execution. Use a manipulation-resistant reference price (e.g., a TWAP over multiple blocks from the Uniswap V3 pool's `observe`, or a registry-configured/oracle price bound) to compute `minPCOut`, independent of the instantaneous `quoteExactInputSingle` call. Alternatively, cap the maximum allowed deviation between the instantaneous quote and a longer-window reference price before allowing the auto-swap/refund-swap to proceed, and abort/fall back to the no-swap path (already present as a fallback in `applyGasRefund`) if deviation exceeds a safe threshold.

### Proof of Concept
Conceptual sequence (cannot be executed without a live devnet, but structurally sound given the code above):
1. Attacker observes a pending `MsgVoteInbound`/`MsgVoteOutbound` set that is about to cross the 2/3 threshold, which will trigger `ExecuteInboundGas` or `applyGasRefund`'s swap-refund path for a known PRC20/WPC pair and amount.
2. Attacker submits a large EVM swap on the same PRC20/WPC Uniswap V3 pool in the same or immediately preceding block, depressing the PRC20→WPC price.
3. The validator's threshold-triggering transaction executes, and `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`) returns the depressed quote; `minPCOut` is computed as 95% of that same depressed quote, so the subsequent `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` swap executes at the manipulated rate without reverting.
4. Attacker immediately reverses their initial swap, restoring the pool price and pocketing the spread that was extracted from the module's swap, which delivered less WPC/PC than the fair-market rate to the ultimate recipient (gas top-up user or refund recipient).

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
