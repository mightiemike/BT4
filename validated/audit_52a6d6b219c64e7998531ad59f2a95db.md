### Title
Unbounded recursive JSON parsing/serialization of a declared Cairo 0 class's ABI/hints can stack-overflow the sequencer/OS host process - (File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs)

### Summary
`compute_cairo_hinted_class_hash` / `compute_deprecated_class_hash` deserialize a user-declared Cairo 0 `ContractClass` into `CairoContractDefinition`, whose `abi`, `identifiers`, `reference_manager`, and `hints`/`attributes` fields are typed as raw, schema-less `serde_json::Value`, and then recursively normalize the value tree with `sort_json_value`. Both `serde_json`'s recursive-descent `Value` deserializer and the hand-written `sort_json_value` function recurse once per nesting level of attacker-controlled JSON with no depth limit, matching the CVE-2021-28903 bug class (`lyxml_parse_elem` unbounded recursive-descent parsing causing a native stack overflow).

### Finding Description
`CairoContractDefinition` is defined with untyped, schema-less JSON fields: [1](#0-0) 

These fields (`abi`, `program.identifiers`, `program.reference_manager`, `program.hints` values, `attributes[].accessible_scopes`/`flow_tracking_data`) accept arbitrarily nested `serde_json::Value` trees. `compute_cairo_hinted_class_hash` re-serializes the whole `ContractClass`, then recursively sorts every JSON object with `sort_json_value`, and finally re-deserializes it into `CairoContractDefinition`: [2](#0-1) [3](#0-2) 

`sort_json_value` is a plain recursive function with no depth guard - each nested JSON array/object adds one native stack frame, and `serde_json::from_slice`'s built-in recursive-descent `Value` parser exhibits the same unbounded-recursion behavior that CVE-2021-28903 describes for `lyxml_parse_elem`. This code path is invoked by `compute_deprecated_class_hash`, which is used to compute the (Pedersen) class hash of a declared Cairo 0 contract as part of Starknet OS hint processing: [4](#0-3) 

Because Cairo 0 (deprecated) `Declare` transactions carry the full `program`/`abi` JSON supplied by the declaring account, an attacker can craft a class definition whose ABI or program-metadata fields contain a deeply nested JSON array/object (e.g. `[[[[[...]]]]]` thousands of levels deep). This class is a valid input as far as the flat `sierra_program`/`bytecode`-style validation is concerned (the gateway's stateless validators mainly bound Sierra program length/version, not the shape of deprecated-class JSON metadata), and once the sequencer or a re-executing/proving node needs to compute this class's hinted/deprecated class hash — which happens during OS execution/re-execution of the transaction that declares or uses the class — the recursive `sort_json_value`/`serde_json` parsing recurses into the attacker-controlled depth and can exhaust the native call stack, crashing the process (SIGSEGV / abort), analogous to the `lyxml_parse_elem` recursion described in CVE-2021-28903.

### Impact Explanation
A crash of the sequencer/full-node/OS re-execution process while processing a single declare transaction constitutes a denial-of-service against the block-building/proving pipeline: the process aborts, in-flight state is lost, and (depending on deployment) it can repeatedly be triggered by resubmitting the same malicious declare transaction whenever any honest node attempts to compute the class hash (gateway validation, execution, or STARK-proof re-execution), potentially halting the network's ability to confirm new transactions until the input is filtered out-of-band. This matches the "network unable to confirm new transactions" acceptance criterion for a High-severity finding.

### Likelihood Explanation
Likelihood is Medium-to-High from a bug-class perspective (unbounded recursion on attacker-controlled JSON depth is a well-known, easily-triggered pattern), but I was not able to fully confirm within the available context (1) the exact stack size configured for the OS-hint/re-execution thread that runs `compute_deprecated_class_hash`, and (2) whether the gateway's stateless transaction validator enforces any bound on nested JSON depth of the deprecated `abi`/`program` fields for Cairo 0 declares before they reach this code (only Sierra-version/length/proof-size checks were found for the Cairo 1 path in `stateless_transaction_validator.rs`). These are important preconditions to fully validate exploitability and severity, and would need explicit verification against the live gateway/OS code paths.

### Recommendation
- Enforce a strict maximum nesting depth (and/or use an iterative/heap-based approach) when parsing and re-serializing the `abi`, `identifiers`, `reference_manager`, and `hints`/`attributes` fields of a declared Cairo 0 `ContractClass`, both in `serde_json::from_slice`/`serde_json::to_value` calls and in the custom `sort_json_value` recursion in `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs`.
- Reject (at gateway stateless validation time, before the class is admitted to the mempool or committed) any declared class whose JSON metadata exceeds a configured depth/size limit, mirroring the existing `validate_sierra_version`/`validate_class_length` checks in `crates/apollo_gateway/src/stateless_transaction_validator.rs`.
- Alternatively/additionally, run the hinted-class-hash computation on a bounded, pre-sized stack (similar to the `stack_size` guard already used for Cairo Native recursion in `crates/blockifier/src/blockifier/transaction_executor.rs`) so that stack exhaustion produces a controlled error rather than a process crash.

### Proof of Concept
Construct a Cairo 0 `DECLARE` transaction whose `contract_class.abi` (or `program.identifiers` / `program.reference_manager` / a hint's payload) is a deeply nested JSON array, e.g.:
```json
{
  "program": { ... valid minimal Cairo0 program fields ..., "hints": {} },
  "abi": [[[[[ ... nested tens of thousands of levels deep ... ]]]]],
  "entry_points_by_type": { "CONSTRUCTOR": [], "EXTERNAL": [], "L1_HANDLER": [] }
}
```
Submit this class via `DECLARE`. When any node computes `compute_deprecated_class_hash`/`compute_cairo_hinted_class_hash` for this class (gateway validation of `class_hash`, execution, or OS re-execution), the recursive `sort_json_value` call and/or the `serde_json` `Value` deserializer will recurse to the crafted depth and overflow the native stack, crashing the process. Exact reproduction (choosing the nesting depth relative to the process's stack size) would require running the code, which was not possible in this read-only analysis.

/// Recursively sorts all JSON objects by their keys.
/// This ensures deterministic serialization regardless of the `preserve_order` feature in
/// serde_json.
fn sort_json_value(value: serde_json::Value) -> serde_json::Value {
    match value {
        serde_json::Value::Object(map) => {
            let sorted: BTreeMap<String, serde_json::Value> =
                map.into_iter().map(|(k, v)| (k, sort_json_value(v))).collect();
            serde_json::Value::Object(sorted.into_iter().collect())
        }
        serde_json::Value::Array(arr) => {
            serde_json::Value::Array(arr.into_iter().map(sort_json_value).collect())
        }
        other => other,
    }
}

pub fn compute_cairo_hinted_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    // Serialize to Value, sort all objects by keys for deterministic output, then to bytes.
    // The sorting is necessary because serde_json with `preserve_order` feature enabled
    // maintains insertion order instead of sorting keys.
    // TODO(Meshi): Compute hinted hashes when loading serialized contracts from storage, before
    // deserializing, to avoid back-and-forth serde.
    let contract_value = serde_json::to_value(contract_class)?;
    let sorted_contract_value = sort_json_value(contract_value);
    let contract_definition_vec = serde_json::to_vec(&sorted_contract_value)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

pub fn compute_deprecated_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    let hinted_class_hash = compute_cairo_hinted_class_hash(contract_class)?;
    let contract_definition_vec = serde_json::to_vec(contract_class)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let FlatEntryPointFelts { external, l1_handler, constructor } =
        get_flat_entry_point_felts(&contract_definition.entry_points_by_type);
    let builtins = ascii_strs_as_felts(&contract_definition.program.builtins);
    let bytecode = hex_strs_as_felts(&contract_definition.program.data);

    let mut hash_state = HashState::<Pedersen>::new();
    hash_state.update_single(&DEPRECATED_COMPILED_CLASS_VERSION);
    hash_state.update_with_hashchain(&external);
    hash_state.update_with_hashchain(&l1_handler);
    hash_state.update_with_hashchain(&constructor);
    hash_state.update_with_hashchain(&builtins);
    hash_state.update_single(&hinted_class_hash);
    hash_state.update_with_hashchain(&bytecode);
    Ok(hash_state.finalize())
