### Title
MFA/WebAuthn second factor is silently bypassed for local admin login when the OIDC authenticator is active - (File: core/sessions/oidcauth/oidc.go)

### Summary
`oidcAuthenticator.CreateSession` handles the "local admin" fallback login path but never consults registered WebAuthn/MFA credentials before minting a session, unlike the equivalent `localauth.orm.CreateSession` flow. Because `oidcAuthenticator.GetUserWebAuthn` is a hardcoded stub that always returns an empty list, the shared `SessionsController.Create` gate (`len(userWebAuthnTokens) > 0`) is always false under OIDC mode, so a user who previously enrolled MFA/WebAuthn (e.g. while local auth was the active provider) has that protection completely dropped as soon as the node is configured to use the OIDC authenticator.

### Finding Description
`core/web/sessions_controller.go:SessionsController.Create` is the single HTTP entrypoint for session creation and decides whether to require a WebAuthn challenge purely based on `sc.App.AuthenticationProvider().GetUserWebAuthn(ctx, sr.Email)`: [1](#0-0) 

When the active `AuthenticationProvider` is the OIDC driver, `GetUserWebAuthn` is implemented as an unconditional stub that ignores the database entirely: [2](#0-1) 

As a result `userWebAuthnTokens` is always empty, `sr.SessionStore`/`sr.WebAuthnConfig` are never populated, and `oidcAuthenticator.CreateSession` is invoked with no MFA context: [3](#0-2) 

`CreateSession` only calls `localLoginFallback`, which checks email (via SQL `lower(email)=lower($1)` plus a constant-time compare) and the bcrypt password hash, and if both pass, unconditionally issues a session row in `oidc_sessions` bound to the user's real role — there is no reference anywhere to `sr.WebAuthnData`, `BeginWebAuthnLogin`, or `FinishWebAuthnLogin`: [4](#0-3) 

Contrast this with `localauth.orm.CreateSession`, which is the reference/expected behavior: after email+password validation it loads `web_authns` rows via `GetUserWebAuthn` and, if any exist, forces a WebAuthn challenge/response round trip (`BeginWebAuthnLogin`/`FinishWebAuthnLogin`) before a session row is ever inserted: [5](#0-4) 

The `web_authns` table and its schema/rows are provider-agnostic — they are written by `SaveWebAuthn` while local auth is active, but nothing purges them or blocks their use if the operator switches `AuthenticationProvider` to OIDC. The OIDC provider's `SaveWebAuthn` is a no-op returning `ErrNotSupported`, but pre-existing rows for the local admin remain in the table and are simply never read by `oidcAuthenticator.GetUserWebAuthn`: [6](#0-5) 

The comment on `CreateSession` confirms this local admin path is an intentionally-supported fallback even when OIDC is configured, so this is a reachable, real production configuration, not a purely theoretical one: [7](#0-6) 

### Impact Explanation
Any attacker who has obtained a valid local-admin email/password (phishing, credential reuse, database/backup leak of the bcrypt hash cracked offline, etc.) but does not possess the registered WebAuthn device can still authenticate and mint a full admin session — and subsequently call `CreateAndSetAuthToken`/`SetAuthToken` to issue a persistent API token bound to that admin principal — as long as the node's `AuthenticationProvider` is OIDC. This breaks the required invariant that MFA state stay bound to the authenticated principal regardless of which authenticator instance handles the request, and directly maps to the "unauthorized access to API tokens, session state, or sensitive node configuration" impact category, since the resulting session/token carries full admin privileges.

### Likelihood Explanation
- Precondition: node is configured with the OIDC authenticator (a supported, documented deployment mode that still permits local-admin fallback login), and the compromised admin account previously had WebAuthn/MFA rows in `web_authns` (typically created while local auth was active, or migrated from an older deployment).
- The attacker only needs valid email+password; no interaction with the SAML/OIDC identity provider, no privileged access, and no code path bypasses beyond normal HTTP login (`POST /sessions`) is required.
- The bug is 100% deterministic — `GetUserWebAuthn` unconditionally returns an empty slice, so the gate in `SessionsController.Create` never triggers under OIDC mode, making this reproducible on every attempt.

### Recommendation
Make `oidcAuthenticator.GetUserWebAuthn` actually query the `web_authns` table (mirroring `localauth.orm.GetUserWebAuthn`) instead of returning a stub, and add the same WebAuthn challenge/verification steps (`sr.WebAuthnData` check, `BeginWebAuthnLogin`/`FinishWebAuthnLogin`) inside `oidcAuthenticator.CreateSession`'s local-admin-fallback branch before inserting into `oidc_sessions`. If MFA is intentionally unsupported for the OIDC local-admin fallback, the local-admin fallback login itself should be disabled/blocked for any account that has WebAuthn credentials enrolled, and this should be explicitly documented/enforced rather than silently dropped.

### Proof of Concept
Integration test plan (Go, using existing test harness in `core/sessions/oidcauth/oidc_test.go` and `core/sessions/localauth/orm_test.go` patterns):
1. Seed a `users` row for `admin@example.com` with a known bcrypt password hash, using `localauth.orm.CreateUser`.
2. Register a WebAuthn credential for that user via `localauth.orm.SaveWebAuthn` (or a direct insert into `web_authns` matching production schema), simulating a prior MFA enrollment.
3. Construct an `oidcAuthenticator` (via `NewOIDCAuthenticator`) pointed at the same datastore.
4. Call `oi.GetUserWebAuthn(ctx, "admin@example.com")` and assert it returns a non-empty list matching the DB row — this assertion will fail against current code (always returns `[]clsessions.WebAuthn{}`), demonstrating the gap.
5. Call `oi.CreateSession(ctx, clsessions.SessionRequest{Email: "admin@example.com", Password: "<correct-password>"})` with `WebAuthnData` deliberately left empty (i.e., no MFA response supplied).
6. Assert that current code returns a valid, non-empty `sessionID` with no error (successful login without any WebAuthn challenge), then compare against `localauth.orm.CreateSession` with an identical setup, which is expected to instead return a WebAuthn challenge JSON payload error (per its `sr.WebAuthnData == ""` branch), proving the divergence in enforced invariants between the two `AuthenticationProvider` implementations for the same principal/credential state.

// flow, a separate /oidc-login route is defined which handles the redirect to the
// configured provider
func (oi *oidcAuthenticator) CreateSession(ctx context.Context, sr clsessions.SessionRequest) (string, error) {
	foundUser, err := oi.localLoginFallback(ctx, sr)
	if err != nil {
		return "", err
	}

	sanitizedEmail := strings.ReplaceAll(sr.Email, "\n", "")
	sanitizedEmail = strings.ReplaceAll(sanitizedEmail, "\r", "")
	oi.lggr.Infof("Successful local admin login request for user %s - %s", sanitizedEmail, foundUser.Role)

	// Save local admin session, user, and role to sessions table
	// Sessions are set to expire after the duration + creation date elapsed
	session := clsessions.NewSession()
	_, err = oi.ds.ExecContext(ctx,
		"INSERT INTO oidc_sessions (id, user_email, user_role, created_at) VALUES ($1, $2, $3, now())",
		session.ID,
		strings.ToLower(sr.Email),
		foundUser.Role,
	)
	if err != nil {
		oi.lggr.Errorf("unable to create new session in oidc_sessions table %v", err)
		return "", fmt.Errorf("error creating local OIDC session: %w", err)
	}

	oi.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": sr.Email})

	return session.ID, nil
}

// localLoginFallback tests the credentials provided against the 'local' authentication method
// This covers the case of local CLI API calls requiring local login separate from the OIDC server
func (oi *oidcAuthenticator) localLoginFallback(ctx context.Context, sr clsessions.SessionRequest) (clsessions.User, error) {
	var user clsessions.User
	err := oi.ds.GetContext(ctx, &user, SQLSelectUserbyEmail, sr.Email)
	if err != nil {
		return user, err
	}
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		oi.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return user, errors.New("invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		oi.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return user, errors.New("invalid password")
	}

	return user, nil
}

func (o *orm) CreateSession(ctx context.Context, sr sessions.SessionRequest) (string, error) {
	user, err := o.FindUser(ctx, sr.Email)
	if err != nil {
		return "", err
	}
	lggr := o.lggr.With("user", user.Email)
	lggr.Debugw("Found user")

	// Do email and password check first to prevent extra database look up
	// for MFA tokens leaking if an account has MFA tokens or not.
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		o.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		o.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return "", pkgerrors.New("Invalid password")
	}

	// Load all valid MFA tokens associated with user's email
	uwas, err := o.GetUserWebAuthn(ctx, user.Email)
	if err != nil {
		// There was an error with the database query
		lggr.Errorf("Could not fetch user's MFA data: %v", err)
		return "", pkgerrors.New("MFA Error")
	}

	// No webauthn tokens registered for the current user, so normal authentication is now complete
	if len(uwas) == 0 {
		lggr.Infof("No MFA for user. Creating Session")
		session := sessions.NewSession()
		_, err = o.ds.ExecContext(ctx, "INSERT INTO sessions (id, email, last_used, created_at) VALUES ($1, $2, now(), now())", session.ID, user.Email)
		o.auditLogger.Audit(audit.AuthLoginSuccessNo2FA, map[string]any{"email": sr.Email})
		return session.ID, err
	}

	// Next check if this session request includes the required WebAuthn challenge data
	// if not, return a 401 error for the frontend to prompt the user to provide this
	// data in the next round trip request (tap key to include webauthn data on the login page)
	if sr.WebAuthnData == "" {
		lggr.Warnf("Attempted login to MFA user. Generating challenge for user.")
		options, webauthnError := sessions.BeginWebAuthnLogin(user, uwas, sr)
		if webauthnError != nil {
			lggr.Errorf("Could not begin WebAuthn verification: %v", webauthnError)
			return "", pkgerrors.New("MFA Error")
		}

		j, jsonError := json.Marshal(options)
		if jsonError != nil {
			lggr.Errorf("Could not serialize WebAuthn challenge: %v", jsonError)
			return "", pkgerrors.New("MFA Error")
		}

		return "", pkgerrors.New(string(j))
	}

	// The user is at the final stage of logging in with MFA. We have an
	// attestation back from the user, we now need to verify that it is
	// correct.
	err = sessions.FinishWebAuthnLogin(user, uwas, sr)

	if err != nil {
		// The user does have WebAuthn enabled but failed the check
		o.auditLogger.Audit(audit.AuthLoginFailed2FA, map[string]any{"email": sr.Email, "error": err})
		lggr.Errorf("User sent an invalid attestation: %v", err)
		return "", pkgerrors.New("MFA Error")
	}
