Found the concrete analog. `receipt_filter_fn` in `runtime/runtime/src/congestion_control.rs` calls `.unwrap()` on `receipt.get_receipt().receiver_shard_id(&shard_layout)`, and `receiver_shard_id` (`core/primitives/src/receipt.rs`) returns `Err(EpochError::ShardingError(...))` for a `GlobalContractDistributionReceipt` whose `target_shard` is not in the current layout and has no descendant in `resolve_to_current_shard`. This mirrors the CVE-2022-41860 bug class exactly: an unrecognized/stale value reaches a lookup, the lookup fails, and the failure is not checked before being dereferenced — causing a crash (here, an `unwrap()` panic instead of a null-pointer deref, but functionally the same "unchecked lookup failure crashes the server" pattern).

### Title
Delayed `GlobalContractDistribution` receipt crashes chunk processing via unchecked `receiver_shard_id().unwrap()` after repeated resharding - (File: `runtime/runtime/src/congestion_control.rs`)

### Summary
`DelayedReceiptQueueWrapper::receipt_filter_fn` unwraps the result of `Receipt::receiver_shard_id`, which can return `Err` for a `GlobalContractDistributionReceipt` whose `target_shard` no longer exists in the current shard layout and cannot be resolved to a descendant shard. If such a receipt sits in the delayed queue across two or more resharding events, popping it during `process_delayed_receipts` panics the node.

### Finding Description
`receipt_filter_fn` at [1](#0-0)  calls `.unwrap()` directly on the `Result` from `receiver_shard_id`. `receiver_shard_id`, defined at [2](#0-1) , explicitly returns `Err(EpochError::ShardingError(...))` when a `GlobalContractDistribution` receipt's `target_shard` is neither in the current shard layout nor resolvable via `shard_layout.resolve_to_current_shard(target_shard)` — i.e., when the shard's split history no longer reaches that ancestor shard id. This is reachable because a `GlobalContractDistribution` receipt (created by an ordinary global-contract deploy transaction, forwarded shard-by-shard via `forward_distribution_next_shard` in `runtime/runtime/src/global_contracts.rs`) can be pushed into the delayed-receipt queue (`process_incoming_receipts`, `runtime/runtime/src/lib.rs:2694-2733`) and remain there across multiple resharding generations if the shard stays congested. `receipt_filter_fn` is invoked from `DelayedReceiptQueueWrapper::pop`, which is used by `process_delayed_receipts` (`runtime/runtime/src/lib.rs:2570-2663`) every time delayed receipts are drained — a path any unprivileged account can influence purely by deploying a global contract and keeping a shard busy long enough for two shard splits to occur.

The repo already contains a regression test, `test_stale_global_contract_distribution_after_double_resharding` in [3](#0-2) , whose comment explicitly states: "If the vulnerability exists, processing the stale GlobalContractDistribution receipt will panic in `receipt_filter_fn()` when `receiver_shard_id()` fails to remap the old target_shard after two resharding generations," and asserts the chain does not stall. This test documents the exact panic path described above; I could not verify from the index whether `resolve_to_current_shard` in `core/primitives/src/shard_layout/v3.rs` has actually been hardened to always succeed for any number of resharding generations, or whether the `unwrap()` in `receipt_filter_fn` has been removed/guarded — that would determine whether the panic is still reachable in this exact snapshot.

### Impact Explanation
A panic inside `process_delayed_receipts` during chunk application halts chunk production/validation for the affected shard on every node that processes it, since the same delayed-queue state and shard layout apply deterministically across honest validators — this is a transaction/receipt-triggered chain halt, not a benign local crash, satisfying the "transaction-triggered halt" acceptance criterion.

### Likelihood Explanation
Reaching the `Err` branch requires two consecutive resharding events to occur while the same `GlobalContractDistributionReceipt` remains delayed (i.e., the receipt's `target_shard` must age past the shard layout's split-history depth). This requires sustained congestion/timing conditions and dynamic resharding to be enabled, making it a real but non-trivial-to-trigger scenario — it is not a single-transaction instant panic, but it is triggerable by an ordinary global-contract deployer with no special privileges by congesting a shard through normal `FunctionCall` transactions.

### Recommendation
Replace the `.unwrap()` calls in `receipt_filter_fn` with proper error propagation (`?` returning `Result<bool, RuntimeError>` or equivalent), and ensure `resolve_to_current_shard`/the shard-layout split history retains enough depth to resolve `target_shard` for any receipt that could plausibly still be delayed across multiple resharding generations, or evict/re-target stale `GlobalContractDistribution` receipts before they become unresolvable.

### Proof of Concept
1. Deploy a global contract from an account on shard S_A via a normal `deploy_global_contract` transaction, creating a `GlobalContractDistributionReceipt` with `target_shard = S_A`.
2. Congest shard S_A (e.g., repeated `burn_gas_raw` calls) so the distribution receipt is pushed into the delayed-receipt queue instead of being processed immediately (`runtime/runtime/src/lib.rs` incoming-receipt admission logic).
3. Trigger two sequential dynamic-resharding splits of S_A's descendant shards while the receipt remains delayed, as done in `test_stale_global_contract_distribution_after_double_resharding` ( [4](#0-3) ).
4. Stop congesting and let the delayed queue drain; `DelayedReceiptQueueWrapper::pop` calls `receipt_filter_fn`, which calls `receiver_shard_id().unwrap()` on the now-unresolvable `target_shard`, panicking and halting the chain for that shard.

    pub fn receiver_shard_id(&self, shard_layout: &ShardLayout) -> Result<ShardId, EpochError> {
        let shard_id = match self.receipt() {
            ReceiptEnum::Action(_)
            | ReceiptEnum::ActionV2(_)
            | ReceiptEnum::Data(_)
            | ReceiptEnum::PromiseYield(_)
            | ReceiptEnum::PromiseYieldV2(_)
            | ReceiptEnum::PromiseResume(_) => {
                shard_layout.account_id_to_shard_id(self.receiver_id())
            }
            ReceiptEnum::GlobalContractDistribution(receipt) => {
                let target_shard = receipt.target_shard();
                if shard_layout.shard_ids().contains(&target_shard) {
                    target_shard
                } else {
                    // The target shard may be from an arbitrarily old layout (the receipt could
                    // have been delayed across multiple resharding events). resolve_to_current_shard
                    // will find a shard descendant in the current layout.
                    let Some(current_shard) = shard_layout.resolve_to_current_shard(target_shard)
                    else {
                        return Err(EpochError::ShardingError(format!(
                            "Shard {target_shard} does not exist in the shard layout or its split history",
                        )));
                    };
                    current_shard
                }
            }
        };
        Ok(shard_id)
    }

#[test]
#[cfg_attr(feature = "protocol_feature_spice", ignore)]
fn test_stale_global_contract_distribution_after_double_resharding() {
    init_test_logger();

    // The fix only works with V3 shard layouts (dynamic resharding).
    // With static resharding, the shard layout doesn't maintain a full split history.
    if !ProtocolFeature::DynamicResharding.enabled(PROTOCOL_VERSION) {
        return;
    }

    let epoch_length: BlockHeightDelta = 10;
    let base_boundary_accounts = create_account_ids(["user2", "user3"]).to_vec();
    let base_shard_layout = ShardLayout::multi_shard_custom(base_boundary_accounts, 3);
    let deploy_user: AccountId = create_account_id("user0");
    let users = create_account_ids(["user0", "user1", "user2", "user3", "user4", "user5"]).to_vec();
    let validators_spec = create_validators_spec(1, 0);
    let clients = validators_spec_clients(&validators_spec);
    let chunk_producer = clients[0].clone();
    let gas_limit = Gas::from_teragas(300);
    let base_pv = PROTOCOL_VERSION - 1;

    // Configure dynamic resharding to force-split two shards sequentially.
    // The first split targets the shard containing deploy_user (user0), so the
    // GlobalContractDistribution receipt becomes stale after two layout transitions.
    let first_split_shard = base_shard_layout.account_id_to_shard_id(&deploy_user);
    let second_split_shard = base_shard_layout.account_id_to_shard_id(&create_account_id("user4"));
    assert_ne!(first_split_shard, second_split_shard);

    let dynamic_config = DynamicReshardingConfig {
        memory_usage_threshold: u64::MAX,
        min_child_memory_usage: u64::MAX,
        max_number_of_shards: 100,
        min_epochs_between_resharding: 1.try_into().unwrap(),
        force_split_shards: vec![first_split_shard, second_split_shard],
        block_split_shards: vec![],
    };

    let genesis = TestLoopBuilder::new_genesis_builder()
        .protocol_version(base_pv)
        .validators_spec(validators_spec)
        .shard_layout(base_shard_layout.clone())
        .epoch_length(epoch_length)
        .gas_limit(gas_limit)
        .add_user_accounts_simple(&users, Balance::from_near(1_000_000))
        .build();
    let base_epoch_config = TestEpochConfigBuilder::from_genesis(&genesis).build();

    let mut dynamic_epoch_config = base_epoch_config.clone();
    dynamic_epoch_config.shard_layout_config =
        ShardLayoutConfig::Dynamic { dynamic_resharding_config: dynamic_config };

    let epoch_config_store = EpochConfigStore::test(BTreeMap::from([
        (base_pv, Arc::new(base_epoch_config)),
        (base_pv + 1, Arc::new(dynamic_epoch_config)),
    ]));

    let mut env = TestLoopBuilder::new()
        .genesis(genesis)
        .clients(clients)
        .epoch_config_store(epoch_config_store)
        .gc_num_epochs_to_keep(5)
        .build();

    // Step 1: Deploy the test contract on user0's account so we can call burn_gas_raw.
    {
        let node = env.node_for_account(&chunk_producer);
        let tx = node.tx_deploy_test_contract(&deploy_user);
        node.submit_tx(tx);
    }
    env.runner_for_account(&chunk_producer).run_for_number_of_blocks(2);

    // Step 2: Deploy a global contract from user0. This creates a
    // GlobalContractDistribution receipt with target_shard = user0's shard (S_A),
    // which is the shard that will be split in the first resharding.
    {
        let node = env.node_for_account(&chunk_producer);
        let code = ContractCode::new(near_test_contracts::rs_contract().to_vec(), None);
        let tx = node.tx_deploy_global_contract(
            &deploy_user,
            code.code().to_vec(),
            GlobalContractDeployMode::CodeHash,
        );
        node.submit_tx(tx);
    }

    // Step 3: Saturate compute on user0's shard every block so that the
    // GlobalContractDistribution receipt (arriving as incoming) gets pushed to
    // the delayed queue and stays there through both resharding events.
    //
    // Each burn_gas_raw call burns slightly more than half the gas limit, so
    // two local receipts exhaust the chunk's compute budget. We submit 3 per
    // block to ensure at least 2 are processed as local receipts.
    let gas_to_burn = gas_limit.checked_div(2).unwrap().checked_add(Gas::from_gas(1)).unwrap();
    let initial_num_shards = base_shard_layout.num_shards();
    let target_num_shards = initial_num_shards + 2; // after two splits

    let start_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };

    // Keep saturating until both resharding events complete. Dynamic resharding has a
    // 2-epoch proposal-to-activation pipeline, so we need enough epochs for both splits.
    let max_saturation_height = start_height + epoch_length * 12;
    let mut both_splits_done = false;
    for target_height in (start_height + 1)..=max_saturation_height {
        // Submit 3 heavy transactions to saturate this block's compute budget.
        {
            let node = env.node_for_account(&chunk_producer);
            for _ in 0..3 {
                let tx = node.tx_call(
                    &deploy_user,
                    &deploy_user,
                    "burn_gas_raw",
                    gas_to_burn.as_gas().to_le_bytes().to_vec(),
                    Balance::ZERO,
                    gas_limit,
                );
                node.submit_tx(tx);
            }
        }
        env.runner_for_account(&chunk_producer).run_until_head_height(target_height);

        // Check if both resharding events have completed.
        let node = env.node_for_account(&chunk_producer);
        let epoch_id = node.client().chain.chain_store().head().unwrap().epoch_id;
        let current_layout = node.client().epoch_manager.get_shard_layout(&epoch_id).unwrap();
        if current_layout.num_shards() >= target_num_shards {
            both_splits_done = true;
            break;
        }
    }
    assert!(both_splits_done, "both shard splits did not complete within the allotted blocks");

    // Step 4: Stop saturating. Let the delayed queue drain.
    // If the vulnerability exists, processing the stale GlobalContractDistribution
    // receipt will panic in receipt_filter_fn() when receiver_shard_id() fails
    // to remap the old target_shard after two resharding generations.
    let current_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };
    let drain_end = current_height + epoch_length * 2;
    env.runner_for_account(&chunk_producer).run_until_head_height(drain_end);

    let head_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };
    assert!(
        head_height >= drain_end,
        "chain stalled at height {}; expected >= {} (likely panicked processing stale receipt)",
        head_height,
        drain_end
    );
}
