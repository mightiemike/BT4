### Title
Open redirect via unauthenticated `exitIframe` query parameter reaching `renderAppBridge`'s `window.open` - (File: `packages/apps/shopify-app-remix/src/server/authenticate/admin/authenticate.ts` / `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/render-app-bridge.ts`)

### Summary
`respondToExitIframeRequest` in `authenticate.ts` reads the `exitIframe` query parameter directly from an unauthenticated request and forwards it, unmodified, as `redirectTo.url` into `renderAppBridge`. `sanitizeRedirectUrl` (used by `renderAppBridge`) only validates protocol (http/https), rejects file URIs and whitespace, but never checks that the resulting URL's host matches `config.appUrl`'s host, so an absolute attacker-controlled URL passes through unchanged and is emitted verbatim inside `window.open(...)`.

### Finding Description
In `authenticate.ts`, before any session-token or shop authentication occurs, `respondToExitIframeRequest` is invoked as part of `authenticateAdmin`: [1](#0-0) 
It extracts `exitIframe` straight from `url.searchParams` with a non-null assertion and no allow-list check, then calls `renderAppBridge(params, request, {url: destination})`.

`renderAppBridge` passes this value to `sanitizeRedirectUrl(config.appUrl, redirectTo.url)`: [2](#0-1) 

`sanitizeRedirectUrl`/`isSafe` only rejects: non-string values, `///` file-URI patterns, whitespace, invalid relative paths (`//` in pathname), and non-http(s) protocols; it never compares `url.hostname`/`url.origin` against the `domain` argument (`config.appUrl`): [3](#0-2) 

Because `new URL(absoluteUrl, base)` returns the absolute URL untouched when `redirectUrl` is itself a full `https://...` URL, passing `exitIframe=https://evil.example.com/phish` yields `destination = https://evil.example.com/phish`, which is then embedded verbatim into the emitted HTML:
```
<script>window.open("https://evil.example.com/phish", "_top")</script>
```
This script executes in the merchant's browser at `_top` target, i.e. it navigates the top-level (parent) window — the same window that hosts the Shopify Admin iframe context — away to the attacker's domain. The existing checks (`sanitizeShop`, `sanitizeHost`, HMAC/session-token validation) are not invoked on this code path because it fires before `validateShopAndHostParams`/session-token checks in `authenticateAdmin`, and none of those checks constrain the `exitIframe` parameter's target host anyway.

### Impact Explanation
This is an open redirect reachable by an unauthenticated attacker through a crafted link (`https://<merchant-app-domain>/<exitIframePath>?exitIframe=https://evil.example.com/phish&shop=...`). Since the redirect happens via `_top` window navigation from within what a merchant believes is their trusted embedded-admin context, it can be used for phishing (fake login/consent pages) and, combined with social engineering, could facilitate credential or session-token capture on the attacker's page. It maps to Shopify's "open redirect" impact class; it does not directly leak signed session tokens or bypass HMAC/OAuth validation, so the impact is capped at phishing/open-redirect severity rather than direct token theft.

### Likelihood Explanation
Fully attacker-triggerable with no privileges: the `exitIframe` path is reachable pre-authentication (before shop/host/session-token validation), requires only that the app use default `shopify-app-remix`/`shopify-app-react-router` configuration and the default `exitIframePath` route, and needs no secrets. The attacker only needs to get a merchant to click a crafted link — a realistic phishing vector.

### Recommendation
In `sanitizeRedirectUrl`/`isSafe`, enforce that the parsed URL's origin/hostname equals the `domain` (or a per-shop-scoped allow-list such as `https://<shop>.myshopify.com` / `admin.shopify.com`) for the `exitIframe` and other request-derived redirect targets, rejecting any cross-origin absolute URL by default unless explicitly allow-listed.

export function renderAppBridge(
  {config}: BasicParams,
  request: Request,
  redirectTo?: RedirectToOptions,
): never {
  let redirectToScript = '';
  if (redirectTo) {
    const destination = sanitizeRedirectUrl(config.appUrl, redirectTo.url);

    const target = redirectTo.target ?? '_top';

    redirectToScript = `<script>window.open(${JSON.stringify(
      destination.toString(),
    )}, ${JSON.stringify(target)})</script>`;
  }

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
