### Title
Starknet OS `replace_class` syscall execution omits declared-class and Cairo-version validation enforced by blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The blockifier's `replace_class` syscall implementation enforces two safety checks before allowing a contract to change its own class hash: (1) the target class hash must be declared, and (2) it must be a Cairo v1 class (not a V0/deprecated downgrade). The Starknet OS Cairo re-execution path that replays the same syscall during proving/verification omits both checks — the declared-class check is left as an explicit unimplemented `TODO`, and the Cairo1-only restriction is absent entirely.

### Finding Description
In the blockifier (the engine used by the sequencer to build and commit blocks), `replace_class` is implemented as: [1](#0-0) 

which reads the compiled class (failing if undeclared) and rejects any class that is not Cairo1 with `ForbiddenClassReplacement`. The deprecated (Cairo0) syscall path enforces the declared-class check as well: [2](#0-1) 

The Starknet OS — which re-executes transactions in Cairo to produce/verify the STARK proof of the block's state transition — implements the same syscall without either guard. For the Cairo1 execution path: [3](#0-2) 

Line 902 explicitly states: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` — the check is acknowledged as missing but not implemented, and no Cairo-version restriction exists at all. The Cairo0 (`deprecated_execute_syscalls.cairo`) execution of `replace_class` similarly performs the state-entry update with no declared-class check whatsoever: [4](#0-3) 

Because `replace_class` is a syscall any deployed contract can invoke on itself via a normal `__execute__`/entry-point call reached from an unprivileged transaction, an attacker-controlled or buggy account/contract can pass an arbitrary (undeclared) or a deprecated (Cairo0) class hash as the syscall argument.

### Impact Explanation
This is the analog of the external report's core bug class: an unprivileged caller can drive a state-mutating reference update (here, the contract's `class_hash`, analogous to `FeeSplitter`'s `curves` reference) through a path that lacks the validation its sibling/authoritative path enforces. Concretely:
- The blockifier, which computes the canonical state diff committed to storage and the Patricia state tree, will reject (revert the call) a `replace_class` to an undeclared class hash or a Cairo0 downgrade.
- The Starknet OS, which re-executes the same transaction to produce the proof that attests to the block's state transition, will accept it and write the state entry unconditionally.

This produces a state-transition divergence between the sequencer's blockifier execution and the OS's re-execution/proving of the identical transaction and calldata. Depending on how outputs are reconciled, this can result in an incorrect state root/class hash being proven relative to what was actually committed, or an account's class being silently downgraded to a class without the safety semantics (e.g., validation logic) that the Cairo1-only restriction is designed to preserve — an unauthorized change to account/contract semantics reachable from a single unprivileged transaction.

### Likelihood Explanation
`replace_class` is a standard syscall exposed to every deployed contract; no special privilege, staking, operator, or network position is required — only a transaction that reaches a contract entry point invoking the syscall with attacker-chosen calldata (an undeclared class hash, or a Cairo0 class hash). This is directly reachable by any transaction sender or contract deployer.

### Recommendation
Implement the same validation in the Starknet OS Cairo code as in the blockifier:
1. In `syscall_impls.cairo`'s `execute_replace_class`, assert the target `class_hash` is present in `contract_class_changes`/declared classes (resolve the `TODO(Yoni, 1/1/2026)`), and reject replacement with a non-Cairo1 (V0) class hash, matching `ForbiddenClassReplacement` in the blockifier.
2. In `deprecated_execute_syscalls.cairo`'s `execute_replace_class`, add the equivalent declared-class check.
3. Add regression tests ensuring OS re-execution rejects `replace_class` calls that the blockifier rejects, for both undeclared class hashes and Cairo0 downgrades, to keep the two execution engines consistent.

### Proof of Concept
1. Deploy a Cairo1 contract that exposes an entry point calling `replace_class_syscall(class_hash)` with a caller-supplied `class_hash` (e.g., `test_replace_class` in the test feature contract): [5](#0-4) 
2. Submit a transaction from an unprivileged account invoking this entry point with an undeclared `class_hash` or with the class hash of a Cairo0 contract.
3. In blockifier execution, the call reverts/errors: `"is not declared"` or `"Cannot replace V1 class hash with V0 class hash"`, verified by the existing test: [6](#0-5) 
4. When the same transaction and calldata are re-executed by the Starknet OS Cairo program (`syscall_impls.cairo::execute_replace_class`), no equivalent check exists (see the `TODO` at line 902), so the state entry's `class_hash` is updated unconditionally — producing a different state diff/result than the blockifier for the identical transaction.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
