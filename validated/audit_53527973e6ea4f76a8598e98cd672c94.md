## Analysis

The NextGen bug's root cause is a price/amount calculation that trusts a mutable, attacker-influenceable piece of on-chain state (circulating supply) as if it only reflected a controlled prior step, letting an out-of-band action skew the outcome for a later flow. The closest reachable analog in Push Chain's scoped code is the swap-quote based slippage protection used for PRC20 auto-swaps and gas refunds, which reads a live/manipulable Uniswap V3 spot price rather than a time-weighted price, and derives its own "safety" bound from that same manipulable number.

### Title
Spot-price `GetSwapQuote` self-referential slippage bound lets an unprivileged trader manipulate PRC20 auto-swap and gas-refund pricing - (File: `x/uexecutor/keeper/evm.go`)

### Summary
`GetSwapQuote` fetches a live spot-price quote from Uniswap V3's `QuoterV2.quoteExactInputSingle` with no TWAP and no external sanity bound. [1](#0-0)  Every caller then derives its own "slippage protection" (`minPCOut = quote * 95 / 100`) directly from that same spot quote, in the `GAS`/`GAS_AND_PAYLOAD` inbound auto-swap path, the `GAS_AND_PAYLOAD` execution path, and the successful-outbound gas refund path. [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
The bound is computed from the manipulated number itself, so it can never actually reject a manipulated price — it only protects against price drift between the quote call and the swap call, both of which happen back-to-back inside the same keeper execution.

An unprivileged actor with no protocol privilege can submit an ordinary EVM swap transaction against the same Uniswap V3 pool (`prc20 <-> WPC`) earlier in the same block, moving the pool's spot price before the Universal Validators' `MsgVoteInbound`/`MsgVoteOutbound` quorum-finalizing transaction lands and triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`/`handleSuccessfulOutbound`. Because Cosmos SDK blocks execute transactions in proposer-chosen order and there is no mempool-private ordering guarantee for the attacker's swap vs. the validator's vote tx, the attacker can reliably land their price-moving swap before the module's auto-swap or refund swap in the same block. `GetSwapQuote` then returns the already-skewed price, `minPCOut` is derived from that skewed price, and `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` execute at the manipulated rate — extracting value from the depositor/refund recipient with no failure or revert, since the "protection" always passes (it was computed from the same corrupted number it is supposed to guard against).

This mirrors the NextGen root cause precisely: a pricing formula assumes the only state feeding it is legitimate flow-specific accumulation (there, "prior periodic mints"; here, "the pool's true price"), while in fact an unrelated, unprivileged, easily triggered action (an airdrop there; an ordinary swap here) can distort that same state right before the dependent calculation runs, producing an unintended and harmful price for the honest party.

### Impact Explanation
Every `GAS`/`GAS_AND_PAYLOAD` inbound deposit-and-autoswap, and every successful-outbound gas refund swap, converts protocol/user-held PRC20 into PC (or vice versa) at a price an unprivileged attacker can bias in their favor within the same block, resulting in user/protocol funds being permanently lost to the value extracted by the manipulator. This satisfies the in-scope impact "permanent loss ... of user or protocol-controlled funds" and "corruption of ... gas fee accounting, refund accounting."

### Likelihood Explanation
The trigger requires no privilege, no validator collusion, and no cryptographic break — only an ordinary swap transaction against the same liquidity pool timed to land in the same block before the vote-triggered execution, which any user can attempt repeatedly at low cost, particularly on chains/pools with modest liquidity depth (most PRC20/WPC pools here are protocol-bootstrapped).

### Recommendation
Do not derive the slippage bound from the same spot quote being protected against; use a TWAP-based Uniswap V3 oracle observation (or a governance/registry-configured max acceptable deviation from a recent TWAP) as the reference price, and reject the auto-swap/refund (falling back to the no-swap path, which already exists) if the spot quote deviates from the TWAP beyond a fixed tolerance.

### Proof of Concept
1. Attacker holds/borrows PRC20 and WPC and observes a pending `GAS_AND_PAYLOAD` inbound with a sizeable `amount` about to reach UV quorum.
2. In the same block, before the quorum-finalizing `MsgVoteInbound` lands, attacker submits a large swap on the `prc20/WPC` Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`, pushing the spot price so that `quoteExactInputSingle` under-reports the PC value of `prc20`. [5](#0-4) 
3. Validators' vote tx finalizes; `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` calls `GetSwapQuote` and computes `minPCOut = quote * 95 / 100` from the now-skewed quote, then calls `CallPRC20DepositAutoSwap`. [2](#0-1) 
4. The deposit swap executes at the manipulated pool price, delivering less PC to the recipient's UEA than the fair-value amount; attacker reverses their price-moving swap afterward, capturing the difference as arbitrage profit at the depositor's expense.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
```
