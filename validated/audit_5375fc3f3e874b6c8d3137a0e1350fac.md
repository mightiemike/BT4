### Title
Outbound `TxID` from user-triggered `UniversalTxOutboundEvent` shares an unchecked global ID namespace with system-derived outbound IDs, allowing collision/overwrite of pending outbounds - (File: x/uexecutor/keeper/create_outbound.go)

### Summary
`x/uexecutor` issues outbound IDs through two structurally different paths, exactly mirroring the `RuniverseLand.mint()` vs `mintTokenId()` pattern: one path derives the ID deterministically from internal state, the other accepts an externally-supplied value with no uniqueness check against the other path's ID space. Both IDs are written into the same global `PendingOutbounds` collection and the same `OutboundTx.Id` field used for ballot lookups, with no cross-check for collisions.

### Finding Description
Normal outbound creation reads the destination chain, amount, sender, gas parameters, and crucially the `TxID` field straight out of the `UniversalTxOutboundEvent` log emitted by the `UniversalGatewayPC` contract during payload execution (a flow reachable by any user through `CallUEAExecutePayload` / `CallExecuteUniversalTx`): [1](#0-0) [2](#0-1) 

Two other outbound flows compute their `Id` deterministically via SHA-256 over internal fields, with no dependency on `event.TxID`: [3](#0-2) 

All three kinds of outbounds are appended to `utx.OutboundTx` and indexed into the same `PendingOutbounds` map keyed purely by `outbound.Id`, with an unconditional `Set` — no existence check, no error if the key is already occupied: [4](#0-3) 

Later, `VoteOutbound` resolves an outbound purely by matching `Id` inside a given `utxId`'s `OutboundTx` slice, and independently removes the `PendingOutbounds` entry by the bare `outboundId` string: [5](#0-4) [6](#0-5) 

If an attacker-influenced `UniversalTxOutboundEvent` produces a `TxID` that collides with the `Id` already assigned to a pending `INBOUND_REVERT` or `RESCUE_FUNDS` outbound (or another pending regular outbound belonging to a different `UniversalTx`), `attachOutboundsToUtx` will silently overwrite that victim outbound's `PendingOutboundEntry` (`UniversalTxId`, `SigningDeadline`, `CreatedAt`) in the shared `PendingOutbounds` map — the exact same class of bug as `RuniverseLand.sol`, where one ID-issuing path (`mintTokenId`, arbitrary) was never checked against the other (`mint`, counter-derived), except here the outcome is silent state corruption/overwrite rather than a revert, which is a materially worse variant of the same root cause.

### Impact Explanation
If exploitable, this could redirect or destroy the `PendingOutbounds` bookkeeping for a legitimate, already-in-flight outbound (e.g. a rescue-funds or inbound-revert refund waiting on TSS signing), causing that outbound's signing-deadline tracking/expiry sweep to point at the wrong `UniversalTxId`, or to disappear from the pending index prematurely if the colliding outbound later finalizes and calls `PendingOutbounds.Remove`. This falls under "permanent freezing … of user or protocol-controlled funds" and "corruption of … canonical UniversalTx state" in the allowed-impact list, since the victim outbound's TSS coordination record would be corrupted/unreachable through the normal pending-outbound index while honest validators are otherwise behaving correctly.

### Likelihood Explanation
This is uncertain and could not be fully verified in this session. The Go-side code confirms `outbound.Id` for standard outbounds is taken verbatim from the decoded event log field (`event.TxID`) with no re-derivation or uniqueness enforcement, and that `PendingOutbounds.Set` never checks for an existing key. What I could not verify from the indexed codebase is the exact Solidity implementation of `UniversalGatewayPC`'s outbound-emitting function — specifically whether `txId` is fully caller-chosen, or itself hash-derived from caller-controlled inputs (which would require a SHA-256 preimage/second-preimage against `GetOutboundRevertId`/`GetRescueFundsOutboundId`'s digest, making direct collision infeasible but still leaving open collisions between two ordinary user-triggered outbounds sharing an accidentally-reused or attacker-chosen `TxID`). The severity therefore hinges on contract-level input validation I did not have access to; if `txId` is even partially caller-supplied without domain separation from the `REVERT`/`RESCUE` domains, exploitation is straightforward.

### Recommendation
- Before calling `k.PendingOutbounds.Set` in `attachOutboundsToUtx`, check `k.PendingOutbounds.Has(ctx, outbound.Id)` and reject (or namespace) the outbound if the ID is already in use, mirroring how `CreateUniversalTx` already rejects on key collision.
- Ensure `outbound.Id` values sourced from `event.TxID` cannot collide with the deterministic `REVERT`/`RESCUE` ID domains — either by validating that on-chain gateway `txId` generation is itself domain-separated and non-forgeable, or by prefixing/namespacing IDs by their `TxType` before using them as the `PendingOutbounds` key.
- Add an explicit invariant check in `attachOutboundsToUtx` that no two outbounds across the entire node state ever share the same `Id`, independent of which code path produced them.

### Proof of Concept
Not independently confirmed in this session — verification requires inspecting the `UniversalGatewayPC` Solidity contract's outbound-emitting function to determine whether `txId` in `UniversalTxOutboundEvent` is attacker-chosen or hash-derived, and then constructing a payload/withdrawal call that emits a `TxID` equal to a target victim outbound's `Id` (e.g. one already computed by `GetRescueFundsOutboundId`) to observe the silent `PendingOutbounds` overwrite in `attachOutboundsToUtx`. A Devin session with terminal/filesystem access to the Solidity contract sources and a local test harness would be needed to complete this proof.

func (k Keeper) attachOutboundsToUtx(
	ctx sdk.Context,
	utxId string,
	outbounds []*types.OutboundTx,
	revertMsg string, // revert msg if the outbound is for a inbound revert
) error {

	if len(outbounds) == 0 {
		return nil
	}
	return k.UpdateUniversalTx(ctx, utxId, func(utx *types.UniversalTx) error {

		for _, outbound := range outbounds {

			utx.OutboundTx = append(utx.OutboundTx, outbound)

			// Compute signature expiry deadline for the destination chain.
			var signingDeadline int64
			if chainCfg, err := k.uregistryKeeper.GetChainConfig(ctx, outbound.DestinationChain); err == nil {
				if chainCfg.TssSigningDeadline != nil && *chainCfg.TssSigningDeadline > 0 {
					signingDeadline = ctx.BlockTime().Unix() + int64(chainCfg.TssSigningDeadline.Seconds())
				}
			}

			// Write to pending outbounds index (inside UpdateUniversalTx closure for atomicity)
			if err := k.PendingOutbounds.Set(ctx, outbound.Id, types.PendingOutboundEntry{
				OutboundId:      outbound.Id,
				UniversalTxId:   utxId,
				CreatedAt:       ctx.BlockHeight(),
				SigningDeadline: signingDeadline,
			}); err != nil {
				return fmt.Errorf("failed to set pending outbound index for %s: %w", outbound.Id, err)
			}

// GetOutboundRevertId generates a deterministic outbound ID for an inbound-revert
// outbound. sourceChain is the CAIP-2 identifier of the chain the inbound came from
// (e.g. "eip155:1"); logIndex disambiguates multiple bridge events in the same
// source tx. This ID is also used as the subTxId on the source-chain gateway call,
// providing replay protection — so it must be unique per inbound event.
func GetOutboundRevertId(sourceChain, inboundTxHash, logIndex string) string {
	data := fmt.Sprintf("%s:%s:%s:REVERT", sourceChain, inboundTxHash, logIndex)
	hash := sha256.Sum256([]byte(data))
	return hex.EncodeToString(hash[:])
}

// GetRescueFundsOutboundId generates a deterministic outbound ID for a rescue-funds
// outbound. pushChainCaip is the CAIP-2 identifier of Push Chain (e.g. "eip155:2240"),
// mirroring the convention used by GetPcUniversalTxKey. This ID is also used as the
// subTxId on the source-chain gateway call, providing replay protection.
func GetRescueFundsOutboundId(pushChainCaip string, pcTxHash string, logIndex string) string {
	data := fmt.Sprintf("%s:%s:%s:RESCUE", pushChainCaip, pcTxHash, logIndex)
	hash := sha256.Sum256([]byte(data))
	return hex.EncodeToString(hash[:])
}
