Based on my research, I found a concrete, reachable analog of the reported bug class in Push Chain's own EVM-integration code.

### Title
Unprivileged front-running of `FactoryV1.initialize()` allows hijack of the UEA Factory contract ownership - (File: `x/uexecutor/keeper/genesis.go`)

### Summary
The reported bug is about an upgradeable contract whose ownership-initialization guard is missing, letting an attacker claim ownership after deployment. Push Chain's own genesis code has the same class of defect in production: the UEA Factory proxy is deployed with bytecode only, and `initialize(address initialOwner)` is never called by the chain itself. Anyone can call it first.

### Finding Description
`x/uexecutor/keeper/genesis.go` deploys the Factory system contracts on fresh genesis via `deployFactoryEA`, which chains three steps: `deployFactoryImplContract`, `deployProxyAdminContract`, `deployFactoryProxy`. [1](#0-0) 

None of these steps calls `initialize` on the Factory. The Factory ABI exposes `initialize(address initialOwner)` (selector `c4d66de8`, visible embedded in `FactoryImplRuntimeBytecode`) as a standard external nonpayable function. [2](#0-1) [3](#0-2) 

The only place in the entire repository that calls `initialize` on the Factory is `test/utils/contracts_setup.go`'s `setupFactoryContract`, which is test-only harness code, not production genesis or any keeper flow: [4](#0-3) 

By contrast, the sibling `uregistry` and other reserved system contracts explicitly hard-code the `ProxyAdmin` owner slot directly at deploy time via `SetState`, bypassing an `initialize()` call entirely: [5](#0-4) [6](#0-5) 

But the Factory's *own* owner (distinct from the ProxyAdmin owner) is set purely through the Solidity-level `initialize()` call, which nothing in the on-chain Go code ever invokes after genesis. This is functionally identical to the reported issue: an upgradeable/ownable contract deployed without its owner-initialization guard being exercised by the deployer, leaving an initialization window open to anyone.

### Impact Explanation
The Factory (`FACTORY_PROXY_ADDRESS_HEX = 0x00…ea`) is the canonical contract the `uexecutor` module calls into for `deployUEA`, `registerNewChain`, `registerUEA`, and `setUEAProxyImplementation`. [7](#0-6) [8](#0-7) 

If `initialize` truly follows the OZ/Solady one-shot-initializer pattern and is left uncalled by genesis, the very first external transaction that calls `initialize(attacker)` against the deployed Factory proxy becomes its owner. From there, an attacker-owned Factory could call `setUEAProxyImplementation` to point every subsequently deployed UEA proxy at a malicious implementation, or manipulate `registerNewChain`/`registerUEA` mappings — both of which are gateways to user funds held in Universal Executor Accounts. This matches the in-scope impact category of "unauthorized UEA … execution" and "unauthorized module-originated EVM execution."

### Likelihood Explanation
This requires no privileged access — any account capable of submitting an EVM transaction on Push Chain (or an unprivileged `DerivedEVMCall`-equivalent path) could call `initialize` on the known, hardcoded Factory address the instant the chain starts, before any legitimate admin transaction does so, since the code path that would call `initialize()` with the correct owner does not exist in production genesis/keeper code at all (only in test fixtures).

### Recommendation
Add a production-path call to `initialize(<intended owner, e.g. gov/authority address>)` immediately after `deployFactoryEA` completes in `x/uexecutor/keeper/genesis.go`'s `InitGenesis`, atomically within the same genesis transaction so no external actor can observe an uninitialized window. Alternatively, hard-code the Factory owner storage slot directly at deploy time (as is already done for the `ProxyAdmin` owner slot) rather than relying on a separately-callable `initialize` function.

### Proof of Concept
1. Start a fresh Push Chain node from genesis; `x/uexecutor` genesis deploys the Factory proxy/impl/admin contracts via `deployFactoryEA`, but issues no `initialize` call.
2. Before the legitimate operator submits any transaction calling `FactoryV1.initialize(legitimateOwner)`, an attacker submits an EVM transaction calling `initialize(attackerAddress)` against `0x00000000000000000000000000000000000000eA`.
3. If the underlying Solidity contract only guards against *re*-initialization (not first-caller-wins), the attacker becomes the Factory owner.
4. The attacker then calls `setUEAProxyImplementation(maliciousImpl)`, redirecting every future UEA deployed by `uexecutor` to attacker-controlled logic. [1](#0-0)

func setupFactoryContract(
	t *testing.T,
	app *app.ChainApp,
	ctx sdk.Context,
	factoryABI abi.ABI,
	opts AppSetupOptions,
	accounts TestAccounts,
) error {
	factoryAddr := opts.Addresses.FactoryAddr
	owner := common.BytesToAddress(accounts.DefaultAccount.GetAddress().Bytes())

	// Check initial factory owner
	ownerResult, err := app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after genesis: %s", common.BytesToAddress(ownerResult.Ret).Hex())

	// Initialize factory with owner

	// Verify owner is set
	ownerResult, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after initialization: %s", common.BytesToAddress(ownerResult.Ret).Hex())

func deployProxyAdminContract(ctx context.Context, evmKeeper types.EVMKeeper, proxyAdminContractAddress string, runtimeBytecode []byte) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	proxyAdminAddress := common.HexToAddress(proxyAdminContractAddress)
	owner := common.HexToAddress(types.PROXY_ADMIN_OWNER_ADDRESS_HEX)

	// Compute the code hash from the runtime bytecode
	codeHash := crypto.Keccak256(runtimeBytecode)

	// Create the EVM account object
	evmAccount := statedb.Account{
		Nonce:    1,                // to prevent tx nonce=0 conflicts
		Balance:  new(uint256.Int), // zero balance by default
		CodeHash: codeHash,         // link to deployed code
	}

	// Set the EVM account with the proxy admin contract
	err := evmKeeper.SetAccount(sdkCtx, proxyAdminAddress, evmAccount)
	if err != nil {
		panic("failed to set proxy admin contract account: " + err.Error())
	}

	// Store the runtime bytecode linked to the code hash
	evmKeeper.SetCode(sdkCtx, codeHash, runtimeBytecode)

	// Initialize storage slot 0 (Ownable.owner) with the owner address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAdminAddress, common.Hash{}, common.LeftPadBytes(owner.Bytes(), 32))
}

// CallFactoryToDeployUEA deploys a new UEA using factory contract
// Returns deployment response or error if deployment fails
func (k Keeper) CallFactoryToDeployUEA(
	ctx sdk.Context,
	from, factoryAddr common.Address,
	universalAccount *types.UniversalAccountId,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: deployUEA",
		"factory", factoryAddr.Hex(),
		"chain_namespace", universalAccount.ChainNamespace,
		"chain_id", universalAccount.ChainId,
		"owner", universalAccount.Owner,
	)

	abi, err := types.ParseFactoryABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse factory ABI")
	}

	abiUniversalAccount, err := types.NewAbiUniversalAccountId(universalAccount)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal account")
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,        // who is sending the transaction
		factoryAddr, // destination: FactoryV1 contract
		big.NewInt(0),
		nil,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"deployUEA",
		abiUniversalAccount,
	)
}
