### Title
Vote program `authorize()` allows setting the authorized withdrawer/voter to `Pubkey::default()` with no zero-address check, permanently bricking control of the vote account - ([File: programs/vote/src/vote_state/mod.rs])

### Summary
`vote_state::authorize()`, invoked from `programs/vote/src/vote_processor.rs` on every `VoteInstruction::Authorize`/`AuthorizeChecked` instruction, sets the new authorized staker/voter/withdrawer directly from the client-supplied `authorized: &Pubkey` argument without ever validating that it is non-zero (`Pubkey::default()`).

### Finding Description
For `VoteAuthorize::Withdrawer`, the code path is: [1](#0-0) 
which calls `vote_state.set_authorized_withdrawer(*authorized)` after only checking the current withdrawer signed — there is no check that `authorized != Pubkey::default()`.

For `VoteAuthorize::Voter`, the new authority is passed straight into `set_new_authorized_voter`: [2](#0-1) 
Again, no validation rejects the zero pubkey (or any other unspendable/unreachable address) as the new authorized voter.

This mirrors the reported bug class exactly: an unprivileged but currently-authorized signer (the current withdrawer/voter, an ordinary client) can call the `Authorize`/`AuthorizeChecked` instruction (dispatched in `programs/vote/src/vote_processor.rs`, e.g. lines 315-333 for `AuthorizeChecked`) with `new_authorized_pubkey = Pubkey::default()`. Nothing in `vote_processor.rs` or `vote_state::authorize` rejects the all-zero pubkey before it is persisted into vote state via `vote_state.set_vote_account_state(vote_account)`.

### Impact Explanation
If the authorized withdrawer is set to `Pubkey::default()`, no key can ever sign as the withdrawer again, since `Pubkey::default()` has no corresponding private key. This permanently locks:
- The ability to change the authorized voter or withdrawer again (both require the current withdrawer's or voter's signature per `authorize()`).
- The ability to withdraw the vote account's lamports (`Withdraw` instruction requires the withdrawer's signature).
- The ability to close the vote account.

The account's lamports and voting participation become permanently frozen/unusable. This is a real, if self-inflicted, loss-of-funds/loss-of-control condition reachable directly by an ordinary client via a standard instruction (no special privilege required), which fits the "concrete theft of funds/lamport inflation or loss" acceptance criterion (loss/permanent lock of funds).

### Likelihood Explanation
Likelihood is low-to-moderate: this requires the current authority to submit an authorize transaction with the zero pubkey, which would normally be a user/tooling mistake (e.g., a bug in an integrating wallet, a script defaulting an uninitialized `Pubkey` variable to `Pubkey::default()`, or a malformed CLI/RPC call). It is not attacker-initiated against a victim (the current authority must sign it), so it's primarily a "fat-fingering"/tooling-bug risk rather than an actively exploitable attack against a third party. This matches the original report's characterization of the bug class (accidental self-inflicted loss due to missing zero-address validation).

### Recommendation
In `vote_state::authorize()` (`programs/vote/src/vote_state/mod.rs`), reject `authorized == Pubkey::default()` for all three arms (`Voter`, `Withdrawer`, `VoterWithBLS`) before calling `set_new_authorized_voter`/`set_authorized_withdrawer`, returning `InstructionError::InvalidArgument` (or a dedicated `VoteError`) instead of silently persisting an unusable authority.

### Proof of Concept
1. Client controls the current authorized withdrawer key `W` for vote account `V`.
2. Client submits `VoteInstruction::Authorize(Pubkey::default(), VoteAuthorize::Withdrawer)` signed by `W`, dispatched through `programs/vote/src/vote_processor.rs` to `vote_state::authorize()`.
3. `verify_authorized_signer(vote_state.authorized_withdrawer(), signers)` succeeds (W is the legitimate current withdrawer).
4. `vote_state.set_authorized_withdrawer(Pubkey::default())` executes with no zero-address check, and the new state is persisted via `set_vote_account_state`.
5. From this point on, no `Withdraw` or subsequent `Authorize(Withdrawer)` instruction can ever be validly signed, since no keypair corresponds to `Pubkey::default()`; the vote account's lamports and control are permanently locked. [3](#0-2) [4](#0-3)

/// Authorize the given pubkey to withdraw or sign votes. This may be called multiple times,
/// but will implicitly withdraw authorization from the previously authorized
/// key
pub fn authorize<S: std::hash::BuildHasher, F>(
    vote_account: &mut BorrowedInstructionAccount,
    target_version: VoteStateTargetVersion,
    authorized: &Pubkey,
    vote_authorize: VoteAuthorize,
    signers: &HashSet<Pubkey, S>,
    clock: &Clock,
    is_vote_authorize_with_bls_enabled: bool,
    consume_pop_compute_units: F,
) -> Result<(), InstructionError>
where
    F: FnOnce() -> Result<(), InstructionError>,
{
    let mut vote_state = get_vote_state_handler_checked(vote_account, target_version)?;

    match vote_authorize {
        VoteAuthorize::Voter => {
            if is_vote_authorize_with_bls_enabled && vote_state.has_bls_pubkey() {
                return Err(InstructionError::InvalidInstructionData);
            }
            let authorized_withdrawer_signer =
                verify_authorized_signer(vote_state.authorized_withdrawer(), signers).is_ok();

            vote_state.set_new_authorized_voter(
                authorized,
                clock.epoch,
                clock
                    .leader_schedule_epoch
                    .checked_add(1)
                    .ok_or(InstructionError::InvalidAccountData)?,
                None,
                |epoch_authorized_voter| {
                    // current authorized withdrawer or authorized voter must say "yay"
                    if authorized_withdrawer_signer {
                        Ok(())
                    } else {
                        verify_authorized_signer(&epoch_authorized_voter, signers)
                    }
                },
            )?;
        }
        VoteAuthorize::Withdrawer => {
            // current authorized withdrawer must say "yay"
            verify_authorized_signer(vote_state.authorized_withdrawer(), signers)?;
            vote_state.set_authorized_withdrawer(*authorized);
        }
