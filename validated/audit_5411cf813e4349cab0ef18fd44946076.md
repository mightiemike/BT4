## Analysis

Push Chain has a direct structural analog to Sherlock M-5. The `x/uexecutor` module implements a `PendingInbounds` ballot-recovery escape hatch (`RecomputeBallotQuorum` + `RevertStuckInbound`) that lets governance recover funds when an *inbound* ballot can never reach quorum, but the exact same failure mode on the **outbound** leg — funds that have already left Push Chain custody and are waiting on a destination-chain confirmation vote — has **no equivalent invalidation/refund path at all**, and this is explicitly documented as an accepted gap rather than a bug.

- The `x/uvalidator` generic ballot machine (`VoteOnBallot`) finalizes as `PASSED`/`REJECTED`/`EXPIRED` the same way for every ballot type, including `OUTBOUND_TX`. [1](#0-0) 
- `BallotHooks.AfterBallotTerminal` only handles `INBOUND_TX`; outbound terminal transitions are explicitly skipped, meaning `PendingOutbounds` entries are never cleaned up or resolved when the outbound ballot expires. [2](#0-1) 
- The `x/uexecutor` README documents this as intentional: outbound entries "persist until validators reach consensus," ballot expiry "does NOT remove the entry," and "there is no safe automatic resolution... resolution is governance-driven, not chain-driven." [3](#0-2) 
- Confirmed by test: `TestBallotExpiry_DoesNotRemovePendingOutbound` proves the outbound entry survives ballot expiry with no compensating action. [4](#0-3) 
- Meanwhile, the inbound side has a concrete admin recovery flow: `RecomputeBallotQuorum` (drives a stuck ballot to `EXPIRED` when eligible voters drop to zero) followed by `RevertStuckInbound` (creates a refund outbound). [5](#0-4) [6](#0-5) 
- No `MsgRevertStuckOutbound` or any equivalent message exists — `grep` for `RevertStuckOutbound|StuckOutbound|CancelOutbound|InvalidateOutbound` returns nothing in the codebase.
- `VoteOutbound` only removes the `PendingOutbounds` entry and finalizes the outbound (including refund-on-failure via `handleFailedOutbound`) on ballot `PASSED`; there is no code path reachable if the ballot never passes. [7](#0-6) 

### Why this matches the M-5 root cause exactly
`RecomputeBallotQuorum` is generic and *can* technically be called by the admin on a stuck `OUTBOUND_TX` ballot, marking it `EXPIRED` when eligible voters hit zero (e.g., after UV churn/unbonding — a normal, non-malicious operational event, not an attacker action). [8](#0-7)  But once `EXPIRED`, there is **no subsequent function** (unlike `RevertStuckInbound` for inbounds) that converts that terminal state into a refund/mint-back of the bridged assets. The `OutboundTx` record and its `PendingOutbounds` index entry are permanently orphaned — even the Protocol Owner/admin has no way to invalidate the outbound and release the underlying funds, precisely the missing-invalidation-mechanism pattern from the Sherlock report.

### Impact
Funds already committed to an outbound (bridged tokens burned/escrowed on Push Chain awaiting destination-chain delivery, `TxType_FUNDS`/`FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD`) become **permanently unrecoverable** if the associated UV set can never reach quorum on the observation ballot — whether due to natural validator churn, an unresolvable destination-chain state, or divergent variants that never converge. This is squarely in the allowed-impact category of "permanent freezing... of user or protocol-controlled funds," reachable through ordinary user bridging activity with no privileged or malicious actor required to trigger the *initial* stuck condition — only the (documented, currently unaddressed) absence of a recovery path once it occurs.

### Caveat
This is an explicitly acknowledged design decision in the current codebase (README calls out the double-pay/double-delivery risk of any automatic resolution), not an accidental oversight — the same posture as the original Sherlock M-5 finding, which was also "acknowledged... won't be fixed at this time." Whether this rises to a reportable finding depends on whether the judging program treats acknowledged/won't-fix design gaps as in-scope for this analog scan; if it does, the missing `RevertStuckOutbound`/outbound-invalidation counterpart to `RevertStuckInbound` is the concrete gap to close.

### Generic Ballot Machine

Every crosschain observation (in `x/uexecutor` and `x/utss`) is voted through this single mechanism:

```go
ballot, finalized, isNew, err := k.VoteOnBallot(
    ctx,
    ballotId,           // canonical hash of the observation
    ballotType,         // INBOUND | OUTBOUND | CHAIN_META | TSS_EVENT | FUND_MIGRATION
    voter,              // signer's bech32 address
    voteResult,         // SUCCESS | FAILURE
    eligibleVoters,     // snapshot of UVs at ballot creation
    votesNeeded,        // threshold (caller decides 2/3, 100%, simple majority, ...)
    expiryAfterBlocks,  // ballot auto-expires after this many blocks
)
```

A ballot is created lazily on the first vote, indexed in `ActiveBallotIDs`, and finalizes the moment either:
- `yesVotes >= votingThreshold` -> `BALLOT_STATUS_PASSED`
- `eligibleVoters - noVotes < votingThreshold` (the threshold is now mathematically unreachable) -> `BALLOT_STATUS_REJECTED`

On finalization, the ballot is moved from `ActiveBallotIDs` -> `FinalizedBallotIDs`. Expired ballots that never reached threshold are moved to `ExpiredBallotIDs`.

// RecomputeBallotQuorum rebuilds a pending ballot's eligible-voter list and
// voting threshold against the current eligible-voter set, preserving votes
// from voters still eligible and dropping votes from voters no longer eligible.
//
// If the recomputed eligible count is zero, the ballot is marked EXPIRED (no
// path to finalization). Otherwise it stays PENDING with the new parameters;
// downstream UVs must re-vote on the same ballot to trigger finalize+execute
// via the normal flow.
//
// Returns the old/new counts and threshold for the response.
func (k Keeper) RecomputeBallotQuorum(ctx context.Context, ballotID string) (
	oldEligibleCount, newEligibleCount, oldThreshold, newThreshold int64,
	newStatus types.BallotStatus,
	err error,
) {
	ballot, err := k.Ballots.Get(ctx, ballotID)
	if err != nil {
		return 0, 0, 0, 0, 0, fmt.Errorf("ballot %s not found: %w", ballotID, err)
	}

	if ballot.Status != types.BallotStatus_BALLOT_STATUS_PENDING {
		return 0, 0, 0, 0, 0, fmt.Errorf("ballot %s is not pending (status=%s); only pending ballots can be recomputed", ballotID, ballot.Status.String())
	}

	oldEligibleCount = int64(len(ballot.EligibleVoters))
	oldThreshold = ballot.VotingThreshold

	// Build the current eligible-voter set in the same valoper-bech32 format
	// the ballot already uses. The voting flow (VoteOnInboundBallot/VoteOnOutboundBallot)
	// passes CoreValidatorAddress strings directly into VoteOnBallot, so the
	// stored EligibleVoters list contains valoper bech32 addresses.
	eligibleUVs, err := k.GetEligibleVoters(ctx)
	if err != nil {
		return 0, 0, 0, 0, 0, fmt.Errorf("failed to fetch eligible voters: %w", err)
	}

	newVoters := make([]string, 0, len(eligibleUVs))
	for _, uv := range eligibleUVs {
		if uv.IdentifyInfo == nil || uv.IdentifyInfo.CoreValidatorAddress == "" {
			k.Logger().Warn("recompute: skipping UV with missing identity info")
			continue
		}
		newVoters = append(newVoters, uv.IdentifyInfo.CoreValidatorAddress)
	}
	newEligibleCount = int64(len(newVoters))

	// Zero eligible voters: no path to finalization. Mark EXPIRED.
	if newEligibleCount == 0 {
		if err := k.MarkBallotExpired(ctx, ballotID); err != nil {
			return 0, 0, 0, 0, 0, fmt.Errorf("failed to mark ballot expired on zero-eligible recompute: %w", err)
		}
		k.Logger().Info("ballot recompute: zero eligible voters → marked expired",
			"ballot_id", ballotID,
			"old_eligible", oldEligibleCount,
		)
		return oldEligibleCount, 0, oldThreshold, 0, types.BallotStatus_BALLOT_STATUS_EXPIRED, nil
	}

// RevertStuckInbound creates an INBOUND_REVERT outbound for an inbound whose
// ballot has expired without finalizing. The revert outbound enters the normal
// PendingOutbounds flow; UVs sign it via TSS and broadcast it to the source
// chain, refunding the user.
//
// Strict precondition: the ballot for the supplied inbound must be in EXPIRED
// state. Admin must run MsgRecomputeBallotQuorum first to drive a stuck ballot
// to EXPIRED if it isn't already (recompute auto-expires when no eligible
// voters remain).
//
// Returns the new UTX ID and revert outbound ID for telemetry.
func (k Keeper) RevertStuckInbound(ctx context.Context, inbound types.Inbound) (utxId, outboundId string, err error) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Same canonical form as the vote path, so the admin-supplied payload
	// derives the same ballot key / UTX key the votes did.
	inbound.Canonicalize()

	if vErr := inbound.ValidateBasic(); vErr != nil {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, vErr.Error())
	}

	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, fmt.Sprintf("failed to derive ballot key: %s", err))
	}

	ballot, err := k.uvalidatorKeeper.GetBallot(ctx, ballotKey)
	if err != nil {
		return "", "", errors.Wrap(sdkErrors.ErrNotFound, fmt.Sprintf("ballot for inbound not found (key=%s): %s", ballotKey, err))
	}

	if ballot.Status != uvalidatortypes.BallotStatus_BALLOT_STATUS_EXPIRED {
		return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest,
			fmt.Sprintf("ballot %s status is %s; admin revert requires EXPIRED (use MsgRecomputeBallotQuorum to drive a stuck pending ballot to EXPIRED)",
				ballotKey, ballot.Status.String()))
	}
