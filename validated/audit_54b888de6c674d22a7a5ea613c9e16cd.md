### Title
Open Redirect via Protocol-Relative URL in `sanitizeRedirectUrl`/`isSafe` - ([File: packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts])

### Summary
`isSafe()` in `validate-redirect-url.ts` validates a redirect target's protocol, presence of file-URI markers (`///`), and double-slash pathnames, but never checks that the resolved URL's hostname matches the app's configured domain. A protocol-relative input such as `//attacker.com/steal` resolves against `config.appUrl` to a fully qualified `https://attacker.com/steal` URL that passes every check, producing an open redirect.

### Finding Description
`sanitizeRedirectUrl(domain, redirectUrl, options)` calls `isSafe(domain, redirectUrl, requireSSL)` and, if it returns true, returns `new URL(redirectUrl, domain)`. [1](#0-0) 

Inside `isSafe`:
- `FILE_URI_MATCH` (`/\/\/\//`) only rejects three-or-more consecutive slashes (`///path`), not the two-slash protocol-relative form (`//host/path`).
- `url = new URL(redirectUrl, domain)` resolves `//attacker.com/steal` against `domain` (e.g. `https://my-app.example`), and per the WHATWG URL spec a protocol-relative reference inherits the base's *scheme* but uses the new authority (`attacker.com`) as the host — yielding `https://attacker.com/steal`.
- `INVALID_RELATIVE_URL` (`/[/\\][/\\]/`) is tested against `url.pathname` (`/steal`), which no longer contains the doubled slashes that were in the original input, so this check is bypassed for protocol-relative payloads.
- `VALID_PROTOCOLS` only checks `url.protocol` (`https:`), which passes since the scheme was inherited from `domain`.
- There is no check anywhere that `url.hostname`/`url.host`/`url.origin` matches `domain`'s host. [2](#0-1) 

This function is the sole guard used by `renderAppBridge()` before emitting a `window.open(destination, target)` script for embedded/bounce redirects, and is invoked with attacker-influenced `redirectTo.url` (the argument merchants/app developers pass into `redirect()`, which itself is exposed to app routes handling requests from customers/merchants): [3](#0-2) 

The existing unit tests for this helper only cover file-URI (`///path`), whitespace, invalid protocol, and same/host-implicit relative paths — none of them exercise the two-slash protocol-relative case, confirming the gap is untested: [4](#0-3) 

### Impact Explanation
An attacker who can influence any string passed into `shopify.redirect(...)` (e.g. an app route that forwards a `next`/`return_to` query parameter without an explicit allow-list) can redirect a merchant's/customer's embedded admin session to an attacker-controlled origin. Because `redirect.ts` forwards existing query params (including `shop`, `host`, and potentially `id_token`) onto same-origin destinations before this check runs, and because `sanitizeRedirectUrl` performs no hostname pinning, an attacker-crafted destination bypasses the intended `DESTINATION_ALLOWLIST` invariant, resulting in a classic open redirect (Shopify bounty class: Open Redirect / potential token leakage to third-party host).

### Likelihood Explanation
Exploitability depends entirely on host app code passing untrusted, un-allow-listed input into `redirect()` — this is not enforced by the library itself, and this is a real and common anti-pattern (e.g., `next`/`return_to` params). No secrets, privileged roles, or non-default configuration are required beyond the app accepting a redirect target from user input; the underlying `sanitizeRedirectUrl` bug is present in default configuration and is triggerable by any unprivileged client capable of hitting a vulnerable route with a query string.

### Recommendation
In `isSafe()`, explicitly reject protocol-relative inputs (e.g. add a check `/^\/\//.test(redirectUrl)` on the raw string before resolving), and/or validate that the resolved `url.host`/`url.origin` equals `new URL(domain).host`/`origin` (i.e., enforce the intended `DESTINATION_ALLOWLIST` by hostname, not just protocol/pathname patterns).

```typescript
function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
```

```typescript
export function sanitizeRedirectUrl<OptionsArg extends Options>(
  domain: string,
  redirectUrl: unknown,
  options: OptionsArg = {} as OptionsArg,
): SanitizedRedirectUrl<OptionsArg> {
  if (isSafe(domain, redirectUrl, options.requireSSL)) {
    return new URL(redirectUrl, domain) as SanitizedRedirectUrl<OptionsArg>;
  } else if (options.throwOnInvalid === false) {
    return undefined as SanitizedRedirectUrl<OptionsArg>;
  } else {
    throw new ShopifyError('Invalid URL. Refusing to redirect');
  }
}
```
