### Title
Stale interest index cached across a pause/unpause toggle within one block causes temporary freezing of accrued yield - (File: mainnet/contracts/market/v0-4-market.clar)

### Summary
`market.clar` caches vault liquidity/borrow indexes per `{ timestamp: stacks-block-time, aid }` to save cross-contract calls in `accrue-and-cache`. The vaults' `accrue` function, when the `accrue` pause flag is set, is designed to "pass through" the current (unaccrued) index instead of reverting [1](#0-0) . Because the market's cache key is keyed only by block timestamp and asset id, and not by pause state, a stale (unaccrued) index fetched while a vault is paused gets written into the cache for that block and is then reused for the rest of the block even after the vault is unpaused in a later transaction of the same block.

### Finding Description
`accrue-and-cache` in `v0-4-market.clar` fetches the vault's index once per block and stores it under `{ timestamp: stacks-block-time, aid: aid }`: [2](#0-1) . This is a within-block cache whose only invalidation trigger is a new `stacks-block-time`, as documented: "Cache is automatically invalidated each block... New block → new timestamp → cache miss → fresh accrual" [3](#0-2) .

The vault's own `accrue` function has a pause bypass: when `(get accrue states)` is true, it returns the current `index`/`lindex` unchanged instead of computing `next-index`/`next-liquidity-index` and instead of reverting: [1](#0-0) . The same pattern exists identically in `v0-vault-sbtc.clar` and the other vault contracts [4](#0-3) .

Sequence within a single block:
1. Admin pauses accrual for a vault (`accrue: true` in `pause-states`).
2. A user transaction (e.g. `borrow`, `collateral-add`, `repay`) triggers `market.clar`'s `accrue-and-cache` for that asset. This is a cache MISS, so it calls the vault's `accrue`, which — because paused — returns the stale/unaccrued `index`/`lindex` pair without reverting. This stale pair is stored in `index-cache` keyed by the current block timestamp.
3. Still within the same block, admin unpauses accrual.
4. A later transaction in the same block performs another market operation on the same asset. `accrue-and-cache` now hits the cache from step 2 (same timestamp key) and returns the stale, unaccrued index — even though the vault is no longer paused and a fresh accrual would now be legitimate.

This is exactly the "a pause that passes through instead of reverting" analog combined with "a cached value not invalidated when its source moves" (the pause state changes but the cache key doesn't reflect it), reachable in `v0-4-market.clar`'s hot paths (`borrow`, `repay`, `collateral-add`) which all call `accrue-and-cache`/`accrue-user-debts`/`accrue-user-collateral` [5](#0-4) .

### Impact Explanation
The direct consequence is that legitimately-accrued borrow/supply interest for that vault is silently dropped for the remainder of the block once this stale value is cached — positions computed against health checks, borrow amounts, and liquidity-index-derived collateral valuations for zTokens all use the frozen (pre-unpause) index rather than the correct one. This is a temporary freezing of accrued interest/yield for affected users during that block (impact aligns with "temporary freezing of funds" / "theft of unclaimed yield" categories), since interest that should have accrued is not reflected until the next block's fresh cache.

### Likelihood Explanation
This requires a pause/unpause toggle of `accrue` to occur within the same block as normal user activity on that vault — an admin-driven event. It does not require DAO compromise, only a routine pause/unpause operational sequence colliding with ordinary transactions in the same block, so likelihood is low but non-zero, and entirely accidental/operational rather than requiring an attacker to compromise privileged keys.

### Recommendation
Include the pause state (or a monotonically increasing "epoch"/version counter incremented on every pause/unpause transition) in the `index-cache` key, or invalidate/clear the relevant cache entries whenever `pause-states` for `accrue` changes, so that a stale unaccrued index fetched while paused cannot be reused after the vault is unpaused within the same block.

### Proof of Concept
1. Block N, Tx 1 (admin): `set-pause-states` (or equivalent) sets `accrue: true` for vault X.
2. Block N, Tx 2 (any user): calls `market.borrow`/`collateral-add` referencing asset X → `accrue-and-cache` cache MISS → calls vault X `accrue` → paused branch returns unchanged `{index, lindex}` → market caches this stale pair under `{timestamp: T, aid: X}`.
3. Block N, Tx 3 (admin): unsets `accrue` pause for vault X.
4. Block N, Tx 4 (any user): calls another market operation touching asset X → `accrue-and-cache` cache HIT on `{timestamp: T, aid: X}` → returns the stale pre-unpause index instead of a freshly accrued one, even though the vault is no longer paused.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
