### Title
Legacy `make_signer_set` floor-only apportionment can zero out eligible signer weights, dropping stakers from the reward/signer set - (File: stackslib/src/chainstate/stacks/boot/mod.rs)

### Summary
`StacksChainState::make_signer_set` (used to build the PoX signer set / `RewardSetV0.signers`) computes each signer's weight as a pure floor division `stacked_amt / threshold` and drops any signer whose weight floors to zero, with no remainder-based correction. The Nakamoto codebase already documents and fixes this exact defect in a sibling function, `NakamotoSigners::pox_5_make_signer_set` (largest-remainder/"Hare" method), whose comments explicitly describe the bug this analog exploits: "when more than `reward_slots` distinct signers hold roughly equal stake, every base weight floors to 0, and without the leftover round the entire signer set could be dropped." `make_signer_set` in `boot/mod.rs` retains the un-fixed floor-and-drop scheme.

### Finding Description
`make_signer_set` (`stackslib/src/chainstate/stacks/boot/mod.rs:1020-1072`) aggregates `amount_stacked` per `signing_key` and then computes:
```rust
let weight = u32::try_from(stacked_amt / threshold)
    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
if weight == 0 {
    return None;
}
``` [1](#0-0) 

If a signer's aggregated `stacked_amt` is less than `threshold`, integer division rounds to 0 and the entry is silently filtered out of the signer set entirely — the equality "every unprivileged stacker who committed STX for signing receives a signer slot proportional to their stake" is broken: a legitimately-stacked minority participant gets zero representation instead of a fractional/rounded share.

Contrast with the already-fixed sibling implementation for PoX-5, `pox_5_make_signer_set` (`stackslib/src/chainstate/nakamoto/signer_set.rs:822-928`), which explicitly computes a `base` weight via floor division, then distributes the `leftover = reward_slots - assigned` slots to entries by largest fractional remainder (ties broken deterministically by `signing_key`) so that "the entire signer set" is not "dropped" in degenerate cases: [2](#0-1) 

This fix was validated by a regression test, `equal_stakes_exceeding_reward_slots_are_not_all_zeroed`, which reproduces exactly the scenario where N signers with equal stake all floor to weight 0 under a naive floor scheme: [3](#0-2) 

`make_signer_set` in `boot/mod.rs` has no equivalent remainder-redistribution step, so the same degenerate mode (all-equal or near-threshold small stakes causing the entire computed signer set to collapse to fewer signers than it should, or specific signers to be dropped entirely) remains reachable through this code path. Because it is invoked as part of `RewardSet::V0` construction (`stackslib/src/chainstate/stacks/boot/mod.rs:1183-1190`), any single unprivileged stacker whose stacked amount is below `threshold` (which itself scales with total participation via `get_threshold_from_participation`, `stackslib/src/chainstate/stacks/boot/mod.rs:1193-1209`) is unilaterally excluded from the signer set for a reward cycle, with no compensating remainder mechanism.

### Impact Explanation
All nodes execute the same deterministic function on the same PoX-4 stacking data, so this does not itself cause a state root/consensus divergence between honest nodes — every node reaches the same (flawed) `RewardSetV0`. The impact is instead a deterministic loss of signer-set participation/reward eligibility for minority stackers: an unprivileged staker who commits STX for signing can have their entire stake's signer weight rounded away to zero and be excluded from the reward-cycle's signer set, forfeiting any signing rewards/duties for that cycle despite having a legitimate, correctly-computed non-zero economic stake. This matches the report's H-04 pattern of "too little X compared to others" being rounded to zero and having the corresponding entitlement discarded rather than deferred or redistributed. This is bounded to signer-reward loss for the affected minority stacker(s) rather than a chain split, since the computation is deterministic and agreed-upon network-wide.

### Likelihood Explanation
This is unprivileged and minority-triggerable: any single stacker (or several with near-equal small stakes) that stacks in PoX-4 with an amount below the reward-cycle `threshold` naturally triggers the bug without needing majority participation, collusion, or any additional privileged action — it requires only ordinary use of the stacking mechanism, exactly as the already-fixed `pox_5_make_signer_set` regression test demonstrates is a realistic, not merely theoretical, degenerate case for the sibling code path.

### Recommendation
Port the largest-remainder ("Hare") apportionment used in `pox_5_make_signer_set` (`stackslib/src/chainstate/nakamoto/signer_set.rs`) into `make_signer_set` (`stackslib/src/chainstate/stacks/boot/mod.rs`): compute `base = stacked_amt / threshold` and `remainder = stacked_amt % threshold` for each signer, then distribute any leftover slots (`reward_slots - sum(base)`) to entries with the largest remainder (tie-broken deterministically by `signing_key`) instead of unconditionally dropping zero-weight entries.

### Proof of Concept
1. Configure a reward cycle where `threshold` (from `get_threshold_from_participation`, `boot/mod.rs:1193-1209`) is computed from total liquid/participating STX.
2. Have N distinct signers each stack an amount `stacked_amt < threshold` (e.g., all equal, each below threshold) via PoX-4 `stack-stx`/`stack-extend`/`delegate-stack-stx`.
3. When the reward set is computed, `make_signer_set` (`boot/mod.rs:1051-1065`) computes `weight = stacked_amt / threshold == 0` for every entry and filters all of them out via `if weight == 0 { return None; }`.
4. Result: the resulting `RewardSetV0.signers` is empty (or missing legitimately-stacked minority signers) for the cycle, even though the equivalent PoX-5 apportionment function (`pox_5_make_signer_set`) — proven by the `equal_stakes_exceeding_reward_slots_are_not_all_zeroed` test (`nakamoto/tests/signer_set.rs:294-335`) — would instead award slots to exactly `reward_slots` signers via the largest-remainder round. This demonstrates the concrete, reproducible loss of signer participation/rewards in `make_signer_set` that the fixed sibling function no longer exhibits.

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
