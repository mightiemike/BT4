Confirmed: `respondToExitIframeRequest` runs unconditionally, before any session/auth check, on every request matching `config.auth.exitIframePath` — so any anonymous request can trigger it.

### Title
Open redirect in the App Bridge exit-iframe handler due to missing origin check in `sanitizeRedirectUrl` - (File: `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts`)

### Summary
The `AaveV3YieldSource.claimRewards()` bug lets a caller redirect a sensitive value (Aave rewards) to an arbitrary, caller-supplied address because the destination is never validated against a trusted registry. The same "attacker-controlled destination, insufficiently validated" pattern exists in the `shopify-app-remix`/`shopify-app-react-router` exit-iframe flow: the `exitIframe` query parameter is taken directly from an anonymous, pre-authentication HTTP request and passed through `sanitizeRedirectUrl()`, which validates the URL's *protocol* but never checks that its *origin* matches the app's own origin.

### Finding Description
When a document request's path matches `config.auth.exitIframePath`, `respondToExitIframeRequest` is invoked unconditionally, before any session/authentication logic: [1](#0-0) 

It reads the `exitIframe` query parameter straight from the URL and passes it to `renderAppBridge`: [2](#0-1) 

`renderAppBridge` calls `sanitizeRedirectUrl(config.appUrl, redirectTo.url)` and embeds the result directly into an inline `<script>` that calls `window.open(destination, target)`: [3](#0-2) 

`sanitizeRedirectUrl`/`isSafe` only rejects `file://` URIs, whitespace, protocol-relative/backslash tricks in the pathname, and non-`http(s)` protocols. It never verifies that the resulting URL's origin equals `config.appUrl`'s origin: [4](#0-3) 

The only recorded negative test case exercises the `file://` rejection path, not cross-origin `https://` URLs: [5](#0-4) 

The identical pattern (`respondToExitIframeRequest` → `renderAppBridge` → `sanitizeRedirectUrl`) exists in `shopify-app-react-router`: [6](#0-5) [7](#0-6) 

### Impact Explanation
Any anonymous requester can craft `GET {authPathPrefix}/exit-iframe?exitIframe=https://evil.example&shop=<any>` (no session, no HMAC, no signature required, since this runs before `strategy.authenticate`). The app responds with HTML containing App Bridge's script tag plus `window.open("https://evil.example", "_top")`, executed inside the merchant's browser while the app is (or appears to be) embedded in Shopify Admin. This is a classic open redirect from a trusted app domain, which can be used for phishing (redirecting a merchant who trusts the app's domain to an attacker-controlled look-alike Shopify OAuth/login page) or to break out of the iframe to an attacker page as part of a larger OAuth/session-token theft chain.

### Likelihood Explanation
High reachability: no authentication, cookies, or valid session token are required to hit this code path — merely knowing/guessing the `exitIframePath` (a fixed, low-entropy, documented path such as `/auth/exit-iframe`) and appending an `exitIframe` query parameter. This satisfies the "open redirect" acceptance criterion from an anonymous HTTP request.

### Recommendation
In `sanitizeRedirectUrl`/`isSafe`, in addition to protocol/format checks, enforce that the resolved URL's origin equals the app's own origin (`new URL(config.appUrl).origin`) unless the destination is a Shopify-owned domain that the app is explicitly allowed to bounce to (e.g., via an allow-list similar to `sanitizeHost`'s domain regex for `myshopify.com`/`shopify.com`). Reject any destination whose origin does not match one of the allowed origins before embedding it into the `window.open` script.

### Proof of Concept
```
GET /auth/exit-iframe?exitIframe=https%3A%2F%2Fattacker.example&shop=my-shop.myshopify.com HTTP/1.1
Host: my-app.example.com
```
Response body includes:
```html
<script data-api-key="..." src="https://cdn.shopify.com/shopifycloud/app-bridge.js"></script>
<script>window.open("https://attacker.example/", "_top")</script>
```
This is served with no authentication required, confirmed by `respondToExitIframeRequest` executing before `strategy.authenticate` in `authenticateAdmin` [1](#0-0) , and by `isSafe` never checking origin equality [8](#0-7) .

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}

export function sanitizeRedirectUrl<OptionsArg extends Options>(
  domain: string,
  redirectUrl: unknown,
  options: OptionsArg = {} as OptionsArg,
): SanitizedRedirectUrl<OptionsArg> {
  if (isSafe(domain, redirectUrl, options.requireSSL)) {
    return new URL(redirectUrl, domain) as SanitizedRedirectUrl<OptionsArg>;
  } else if (options.throwOnInvalid === false) {
    return undefined as SanitizedRedirectUrl<OptionsArg>;
  } else {
    throw new ShopifyError('Invalid URL. Refusing to redirect');
  }

export function renderAppBridge(
  {api, config}: BasicParams,
  request: Request,
  redirectTo?: RedirectToOptions,
): never {
  let redirectToScript = '';
  if (redirectTo) {
    const destination = sanitizeRedirectUrl(config.appUrl, redirectTo.url);

    const target = redirectTo.target ?? '_top';

    redirectToScript = `<script>window.open(${JSON.stringify(
      destination.toString(),
    )}, ${JSON.stringify(target)})</script>`;
  }

  const responseHeaders = new Headers({
    'content-type': 'text/html;charset=utf-8',
  });
  const isEmbeddedApp = config.distribution !== AppDistribution.ShopifyAdmin;
  // Sanitize the shop param before using it in response headers (e.g. CSP
  // frame-ancestors, Link preconnect). An attacker-controlled `?shop=evil.com`
  // must not end up in security-sensitive headers.
  const shop = api.utils.sanitizeShop(
    new URL(request.url).searchParams.get('shop')!,
  );
  addDocumentResponseHeaders(responseHeaders, isEmbeddedApp, shop);

  throw new Response(
    `
      <script data-api-key="${config.apiKey}" src="${appBridgeUrl()}"></script>
      ${redirectToScript}
    `,
    {headers: responseHeaders},
  );
}
