### Title
Panic (index-out-of-range) on short DestExecData in Solana ExtraDataDecoder.DecodeDestExecDataToMap - ([File: core/capabilities/ccip/ccipsolana/extradatacodec.go])

### Summary
`ExtraDataDecoder.DecodeDestExecDataToMap` in `ccipsolana` calls `binary.BigEndian.Uint32(destExecData)` directly on attacker-influenced bytes without validating that the slice is at least 4 bytes long. Unlike the equivalent EVM (`abiDecodeUint32`) and Aptos (`des.Remaining() != 4` check) implementations, this function has no length guard, so a `destExecData` slice shorter than 4 bytes causes a runtime panic instead of a returned error.

### Finding Description
`DecodeDestExecDataToMap` is part of the `SourceChainExtraDataCodec` interface, defined at [1](#0-0) , used to decode `TokenAmounts[].DestExecData` byte payloads that originate from source-chain message data relayed through CCIP OCR reporting/execution paths. Both other chain-family implementations defensively validate length before performing fixed-width decoding:

- EVM: delegates to `abiDecodeUint32`, returning an error on failure [2](#0-1) .
- Aptos: explicitly checks `des.Remaining() != 4` before calling `des.U32()` [3](#0-2) .

The Solana implementation, however, has no such check: [4](#0-3) 

`binary.BigEndian.Uint32` internally indexes `b[3]` unconditionally (via the standard library implementation), so any slice shorter than 4 bytes triggers an index-out-of-range panic. Since `destExecData` is data that comes from the cross-chain message and is not sanitized/length-checked prior to reaching this decoder, a value with length 0–3 bytes reaching this code path will crash the calling goroutine.

### Impact Explanation
A panic in this path, if not recovered upstream, crashes the node process or goroutine handling CCIP commit/execute plugin processing for Solana-sourced lanes — a node-wide denial of service for CCIP report generation/execution on affected lanes. This matches the "denial of service" bounty impact category for CCIP/OCR-reachable code paths.

### Likelihood Explanation
The precondition is only that a message on a Solana-sourced CCIP lane carries a `TokenAmounts[].DestExecData` field shorter than 4 bytes. I was not able to fully trace, within the remaining tool budget, the exact call site(s) that invoke `ExtraDataDecoder.DecodeDestExecDataToMap` at runtime (versus test/mocks) to confirm whether upstream validation (e.g., in `extradatacodecregistry.go` or the execute/commit report-building code) already filters malformed `destExecData` before it reaches this function, or whether a `recover()` wraps this call in the plugin runtime. This uncertainty affects confidence in real-world reachability and whether a panic here would crash the whole node process versus being caught by a panic-recovery wrapper elsewhere in the OCR/plugin runtime.

### Recommendation
Add an explicit length check in `DecodeDestExecDataToMap` for `ccipsolana`, mirroring the Aptos/EVM implementations, e.g.:
```go
func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
    if len(destExecData) != 4 {
        return nil, fmt.Errorf("dest exec data invalid length: %d, should be 4 bytes", len(destExecData))
    }
    return map[string]any{
        svmDestExecDataKey: binary.BigEndian.Uint32(destExecData),
    }, nil
}
```

Unit test in `core/capabilities/ccip/ccipsolana/extradatacodec_test.go`:
```go
func TestDecodeDestExecDataToMap_ShortInput(t *testing.T) {
    d := ExtraDataDecoder{}
    for _, tc := range [][]byte{{}, {0x01}, {0x01, 0x02}, {0x01, 0x02, 0x03}} {
        _, err := d.DecodeDestExecDataToMap(tc)
        require.Error(t, err) // currently panics instead
    }
}
```
Fuzz test:
```go
func FuzzDecodeDestExecDataToMap(f *testing.F) {
    d := ExtraDataDecoder{}
    f.Fuzz(func(t *testing.T, data []byte) {
        defer func() {
            if r := recover(); r != nil {
                t.Fatalf("panic on input len=%d: %v", len(data), r)
            }
        }()
        _, _ = d.DecodeDestExecDataToMap(data)
    })
}
```
Expected: current code panics for `len(destExecData) < 4`; after the fix, it returns an error instead.

func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
	des := bcs.NewDeserializer(destExecData)
	if des.Remaining() != 4 {
		return nil, fmt.Errorf("dest exec data invalid length: %d, should be 4 bytes", des.Remaining())
	}

	destGasAmount := des.U32()
	if des.Error() != nil {
		return nil, fmt.Errorf("decode dest gas amount: %w", des.Error())
	}

	return map[string]any{aptosDestExecDataKey: destGasAmount}, nil
}
