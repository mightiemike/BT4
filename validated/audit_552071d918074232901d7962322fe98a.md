## Finding

### Title
Gasless GAS / GAS_AND_PAYLOAD deposits and outbound gas refunds are auto-swapped at manipulable spot AMM price with only a fixed 5% slippage bound, allowing sandwich extraction of user value - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
The Olympus M-2 report is about a system that checks a user's deposit/withdraw ratio against a *live pool price* rather than a fixed entry snapshot, letting arbitrageurs shift the pool and grieve the next naive depositor/withdrawer. Push Chain's `uexecutor` module has a structurally identical pattern: whenever it needs to convert a bridged native/gas token into PC, it fetches a Uniswap V3 `QuoterV2` **spot** quote at execution time and applies a fixed ±5% slippage tolerance, then commits the swap. There is no snapshot/entry-price comparison and no TWAP — the "fair" conversion price is whatever the AMM pool happens to be at the exact block the deposit or refund executes.

### Finding Description
In `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:118-153`), the flow to convert a bridged native gas-token inbound into PC is:
1. `GetSwapQuote` reads the current spot quote from `QuoterV2.quoteExactInputSingle` [1](#0-0) .
2. `minPCOut` is computed as `quote * 95 / 100` — a flat 5% slippage tolerance, with no reference to any independent price oracle or prior entry price [2](#0-1) .
3. `CallPRC20DepositAutoSwap` executes the swap using that `minPCOut` bound [3](#0-2) .

The identical pattern is duplicated in `gasAndPayloadDepositAutoSwap` for `GAS_AND_PAYLOAD` inbounds [4](#0-3) , and again in `applyGasRefund` for outbound excess-gas refunds, which also fetches a spot quote and applies the same 95% floor before calling `refundUnusedGas` [5](#0-4) .

All three paths are reachable by an ordinary, unprivileged user: any external-chain transaction that triggers a `TxType_GAS` or `TxType_GAS_AND_PAYLOAD` inbound (gasless `MsgVoteInbound` submitted by UVs on the user's behalf, per the `x/uexecutor` README [6](#0-5) ), and every successful outbound with excess gas triggers `applyGasRefund`.

Because the conversion is computed against the pool's spot price at the moment of on-chain execution rather than a stable, entry-time-anchored, or oracle-anchored value, an attacker who can move the WPC/gas-token Uniswap V3 pool price within the tolerance window (any block up to and including the block where the finalizing vote/observation lands, since tx ordering within a Cosmos block is influenced by gas price and mempool position) can shift the spot price by close to (or beyond, for illiquid pools) 5% just before the deposit/refund swap executes, capture the difference by arbing back afterward, and leave the victim with up to ~5% less PC than a fair conversion would produce — mirroring exactly the Olympus M-2 mechanism where naive depositors/withdrawers are charged the AMM's momentary imbalance rather than a fair, snapshot-based rate.

### Impact Explanation
Users bridging native/gas tokens through `GAS` or `GAS_AND_PAYLOAD` inbounds, and any user whose outbound triggers an excess-gas refund, can have PC value skimmed by an unprivileged party who transiently shifts the relevant Uniswap V3 pool. The loss is bounded by the 5% slippage tolerance per event but is systematic and repeatable against every unprotected deposit/refund, and worsens for thinly-liquid PRC20/WPC pools where 5% price impact is cheap to produce. This falls squarely within the allowed impact of "corruption of ... gas fee accounting, refund accounting ... or canonical UniversalTx state" and "misrouting of value" via the registry/accounting path, triggered purely by ordinary unprivileged user/attacker action with no privileged assumption.

### Likelihood Explanation
Likelihood is moderate: it requires the attacker to identify low-liquidity WPC/gas-token pools and to time a swap so that it lands in the same or an adjacent block as the deposit/refund's `GetSwapQuote`+`CallPRC20DepositAutoSwap` (or `getSwapQuoteForRefund`+`CallUniversalCoreRefundUnusedGas`) sequence. Since `MsgVoteInbound`/`MsgVoteOutbound` transactions (and their resulting deterministic execution) are visible in the mempool/block builder, an attacker can predict when quorum will finalize and front-run with a same-block price-moving swap, then back-run to capture the arb — a standard MEV/sandwich pattern requiring no validator or admin compromise.

### Recommendation
Replace the raw AMM spot quote used for `minPCOut` with a manipulation-resistant reference (e.g., a TWAP over several blocks, or Push Chain's own `ChainMeta`/oracle price where applicable) and/or tighten slippage bounds dynamically based on pool depth. Alternatively, record an entry-time expected-output snapshot (comparable to the recommendation in the Olympus report) and only allow the pool-vs-oracle differential to be captured as protocol revenue when it demonstrably exceeds normal price drift, rather than applying a flat percentage tolerance to whatever the spot price is at execution time.

### Proof of Concept
1. Identify a low-liquidity WPC/PRC20(gas-token) Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetSwapQuote`.
2. Observe a pending `MsgVoteInbound` (3rd/quorum vote) for a `TxType_GAS` inbound, or a pending `MsgVoteOutbound` that will trigger `applyGasRefund`.
3. Submit a large same-block swap against the WPC/gas-token pool to move the spot price so that the *true* fair conversion is ~5%+ worse than pre-manipulation, while staying within the code's fixed `minPCOut = quote * 95/100` bound so the deposit/refund swap does not revert.
4. Let the deposit/refund execute at the manipulated price via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`.
5. Reverse the initial swap to restore the pool, capturing the price differential extracted from the victim's deposit/refund.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
