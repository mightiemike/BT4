### Title
Panic on unsupported Cairo primitive gas-cost lookup halts block building for the whole batch - (File: crates/blockifier/src/bouncer.rs)

### Summary
The Starknet analog of the reported "missing `AprOracle` entry blocks `DebtManager.sortLendersWithAPR`" bug class is a lookup into a fixed cost table that is expected — but not guaranteed — to always contain an entry for every key that can be produced during transaction execution. In `AprOracle`, an unindexed lender causes `getExpectedApr` to `revert`, which halts the caller's iteration. In the sequencer, `cairo_primitives_to_gas` performs an unconditional `.unwrap()` on `BuiltinGasCosts::get_cairo_primitive_gas_cost(name)`, which returns `Err` for the `segment_arena` and `output` builtins [1](#0-0) . If per-transaction builtin usage counters (`tx_builtin_counters`) ever include one of these unsupported primitives, the `.unwrap()` in `cairo_primitives_to_gas` panics [2](#0-1) .

### Finding Description
`Bouncer::try_update` is invoked for every transaction that the batcher folds into a block proposal, calling `get_tx_weights`, which in turn calls `cairo_primitives_to_gas` to translate the transaction's Cairo-primitive usage counters into a proving-gas figure [3](#0-2) .

`cairo_primitives_to_gas` iterates the `CairoPrimitiveCounterMap` collected from the transaction's execution and looks up each primitive's gas cost via `cairo_primitives_gas_costs.get_cairo_primitive_gas_cost(name).unwrap()`:
```
let cairo_primitive_weight =
    cairo_primitives_gas_costs.get_cairo_primitive_gas_cost(name).unwrap();
``` [4](#0-3) 

`get_cairo_primitive_gas_cost` dispatches to `get_builtin_gas_cost`, which explicitly returns an `Err` (not a valid gas value) for two builtin kinds:
```
BuiltinName::segment_arena => return Err(GasCostsError::VirtualBuiltin),
BuiltinName::output => {
    return Err(GasCostsError::UnsupportedBuiltinInCairo1 { builtin: *builtin });
}
``` [5](#0-4) 

Unlike the analogous helper `get_cairo_primitive_fee_cost` in `fee_utils.rs`, which handles the `Result` from the lookup (panicking with a descriptive message only for genuinely missing keys, not designed-out variants) [6](#0-5) , `cairo_primitives_to_gas` unconditionally unwraps the `Result`, converting any `Err` return — including the intentionally-unsupported `segment_arena`/`output` cases — into a hard panic. This is structurally identical to the `AprOracle` situation: a table lookup that is assumed to always succeed, embedded inside a per-item loop that processes an attacker-influenced set of keys (here, Cairo primitives actually used during a submitted transaction's execution), where a single missing/unsupported entry crashes the entire processing pass rather than returning a typed error to the caller.

The Bouncer/Cairo-primitives accounting path runs for every accepted transaction on the batcher's block-building hot path (`try_update`/`verify_tx_weights_within_max_capacity`), which is reachable purely from the content of user-submitted transactions being executed by the blockifier; there is no privileged-actor precondition.

### Impact Explanation
If `segment_arena` or `output` ever appears as a key in the `CairoPrimitiveCounterMap` derived from real VM execution resources for a transaction (e.g., due to how OS/VM builtin counters are constructed, a bug in filtering, or a future protocol change that surfaces these keys), the resulting `Result::unwrap()` panics inside the batcher process while it is building or validating a block. Because this is an unconditional Rust panic (not a caught `TransactionExecutionError`), it terminates the executing task/process rather than being reported as a per-transaction execution failure, which can halt block production for the node hitting this code path — a liveness/availability issue for that sequencer instance analogous to the reported DoS-of-sorting bug. The severity depends on whether `segment_arena`/`output` counters can actually reach this map in practice from ordinary or crafted transactions; if reachable, this is a High-severity liveness bug for the sequencer.

### Likelihood Explanation
Likelihood is uncertain and could not be fully confirmed within the available tooling: the two "unsupported" builtins (`segment_arena`, `output`) are typically VM-internal (segment arena bookkeeping) or classically Cairo-0 output builtin, and the existing filters in native-execution builtin counting (`builtin_stats_to_primitive_counters`) explicitly whitelist only the supported builtins/opcodes, which suggests the VM (non-native) execution path may similarly exclude these before constructing `tx_builtin_counters` [7](#0-6) . I was unable to locate and fully trace the VM (non-native) code path that populates `tx_builtin_counters` passed into `Bouncer::try_update` to determine conclusively whether `segment_arena`/`output` can leak into that map for a standard CASM/VM-executed transaction. This is the key uncertainty for this finding; confirming or ruling out reachability requires tracing `ExecutionResources`/`builtin_instance_counter` construction in the CASM/VM execution path (as opposed to the Cairo-native path already inspected) and any state-diff/CASM-hash computation resource paths that also feed into `CairoPrimitiveCounterMap` via `get_executed_class_hashes`/`class_hash_to_casm_hash_computation_resources`.

### Recommendation
Change `cairo_primitives_to_gas` (and any other unconditional `.unwrap()` on `get_cairo_primitive_gas_cost`) to handle the `Result` explicitly: either filter out/ignore virtual or unsupported builtins before the fold (mirroring the native-execution whitelist approach), or propagate a typed `TransactionExecutionError`/`TransactionExecutorError` instead of panicking, consistent with the surrounding fallible (`TransactionExecutorResult`) architecture of `Bouncer::try_update` and `get_tx_weights`. This ensures a single transaction with unexpected builtin usage causes that transaction to be rejected/excluded rather than crashing the batcher process for the whole block.

### Proof of Concept
Not fully constructible from static analysis alone given the tooling limitations noted above. The panic trigger is direct and mechanical once the precondition is met:
```rust
// crates/blockifier/src/bouncer.rs
let cairo_primitive_weight =
    cairo_primitives_gas_costs.get_cairo_primitive_gas_cost(name).unwrap(); // panics if name == segment_arena or output
```
A concrete PoC would require demonstrating a code path (e.g., a specific CASM execution or `class_hash_to_casm_hash_computation_resources` computation) that inserts a `CairoPrimitiveName::Builtin(BuiltinName::segment_arena)` or `CairoPrimitiveName::Builtin(BuiltinName::output)` entry into the `CairoPrimitiveCounterMap`/`tx_builtin_counters` passed to `Bouncer::try_update`, which was not confirmed within the scope of this analysis.

impl BuiltinGasCosts {
    fn get_builtin_gas_cost(&self, builtin: &BuiltinName) -> Result<u64, GasCostsError> {
        let gas_cost = match *builtin {
            BuiltinName::range_check => self.range_check,
            BuiltinName::pedersen => self.pedersen,
            BuiltinName::bitwise => self.bitwise,
            BuiltinName::ec_op => self.ecop,
            BuiltinName::keccak => self.keccak,
            BuiltinName::poseidon => self.poseidon,
            BuiltinName::range_check96 => self.range_check96,
            BuiltinName::add_mod => self.add_mod,
            BuiltinName::mul_mod => self.mul_mod,
            BuiltinName::ecdsa => self.ecdsa,
            BuiltinName::segment_arena => return Err(GasCostsError::VirtualBuiltin),
            BuiltinName::output => {
                return Err(GasCostsError::UnsupportedBuiltinInCairo1 { builtin: *builtin });
            }
        };

        Ok(gas_cost)
    }

    fn get_opcode_gas_cost(&self, opcode: &OpcodeName) -> u64 {
        match opcode {
            OpcodeName::blake => self.blake,
        }
    }

    /// Returns the gas cost for any Cairo primitive (builtin or opcode).

        &self,
        primitive: &CairoPrimitiveName,

        match primitive {
            CairoPrimitiveName::Builtin(builtin) => self.get_builtin_gas_cost(builtin),
            CairoPrimitiveName::Opcode(opcode) => Ok(self.get_opcode_gas_cost(opcode)),
        }
    }

pub fn cairo_primitives_to_gas(
    cairo_primitives_counters: &CairoPrimitiveCounterMap,
    // NOTE: 'blake' is currently the only supported opcode, by being included in the
    // builtin_gas_costs.
    cairo_primitives_gas_costs: &BuiltinGasCosts,
) -> GasAmount {
    let cairo_primitives_gas =
        cairo_primitives_counters.iter().fold(0u64, |accumulated_gas, (name, &count)| {
            let cairo_primitive_weight =
                cairo_primitives_gas_costs.get_cairo_primitive_gas_cost(name).unwrap();
            cairo_primitive_weight
                .checked_mul(u64_from_usize(count))
                .and_then(|builtin_gas| accumulated_gas.checked_add(builtin_gas))
                .unwrap_or_else(|| {
                    panic!(
                        "Overflow while converting cairo primitives counters to gas.\nCairo \
                         primitive: {name:?}, Weight: {cairo_primitive_weight}, Count: {count}, \
                         Accumulated gas: {accumulated_gas}"
                    )
                })
        });

    GasAmount(cairo_primitives_gas)
}

/// Returns the fee cost for a given Cairo primitive (builtin or opcode).
fn get_cairo_primitive_fee_cost(
    cairo_primitive: &CairoPrimitiveName,
    builtin_fee_costs: &BTreeMap<BuiltinName, ResourceCost>,
    versioned_constants: &VersionedConstants,
) -> ResourceCost {
    match cairo_primitive {
        CairoPrimitiveName::Builtin(builtin) => {
            *builtin_fee_costs.get(builtin).unwrap_or_else(|| {
                panic!("Builtin {builtin} not found in versioned constants.");
            })
        }
        CairoPrimitiveName::Opcode(OpcodeName::blake) => {
            // Blake cost comes from the builtin gas costs in versioned constants.
            let blake_sierra_gas_cost = versioned_constants.os_constants.gas_costs.builtins.blake;
            let blake_l1_gas_cost = versioned_constants
                .sierra_gas_to_l1_gas_amount_round_up(GasAmount(blake_sierra_gas_cost));

            Ratio::from_integer(blake_l1_gas_cost.0)
        }
    }
}

/// Converts native `BuiltinStats` into a unified `CairoPrimitiveCounterMap` (builtins + opcodes).
fn builtin_stats_to_primitive_counters(stats: BuiltinStats) -> CairoPrimitiveCounterMap {
    let builtins = [
        (BuiltinName::range_check, stats.range_check),
        (BuiltinName::pedersen, stats.pedersen),
        (BuiltinName::bitwise, stats.bitwise),
        (BuiltinName::ec_op, stats.ec_op),
        (BuiltinName::poseidon, stats.poseidon),
        (BuiltinName::range_check96, stats.range_check96),
        (BuiltinName::add_mod, stats.add_mod),
        (BuiltinName::mul_mod, stats.mul_mod),
    ];
    let opcodes = [(OpcodeName::blake, stats.blake)];

    builtins
        .into_iter()
        .map(|(builtin_name, count)| (builtin_name.into(), count))
        .chain(
            opcodes
                .into_iter()
                .map(|(opcode_name, count): (OpcodeName, _)| (opcode_name.into(), count)),
        )
        .filter(|(_, count)| *count > 0)
        .collect()
}
