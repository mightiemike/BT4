## Analog Found

### Title
Starknet OS `replace_class` syscall skips the "class must be declared" check that the Blockifier enforces, causing sequencer/OS execution divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Postgres CVE's root cause is a missing authorization/validity check when a low-privilege action creates a *dependency* on an object (a type), which other, expected-to-be-checked code paths assumed was already validated. The Starknet analog is `replace_class` (a syscall any deployed contract can invoke): the Blockifier (used by the sequencer to build/execute blocks) requires the target `class_hash` to already be a *declared* class before allowing a contract to point to it, but the Starknet OS Cairo implementation of the same syscall omits this check entirely, as marked by an explicit `TODO` in the code.

### Finding Description
In the Blockifier, `replace_class` explicitly reads the target class to force validation that it is declared before mutating contract state: [1](#0-0) 

Blockifier tests confirm an undeclared class hash is rejected with an "is not declared" error, and even declared-but-wrong-version class hashes are rejected (`ForbiddenClassReplacement`): [2](#0-1) [3](#0-2) 

In contrast, the Starknet OS's Cairo implementation of the *same* syscall (used for state-transition re-execution / proving and for computing the committed state root) performs no such check — it directly overwrites the contract's `class_hash` in `contract_state_changes` and explicitly documents the missing check as a TODO: [4](#0-3) 

The comment at line 903, "TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash," is a direct admission that the dependency (contract → class_hash pointer) is created without verifying the referenced object (the class) is legitimately declared — structurally identical to the CVE's root cause of "creating a dependency ... did not [check the privilege/validity]".

### Impact Explanation
Any unprivileged contract can call `replace_class_syscall(class_hash)` with an arbitrary, undeclared `class_hash`. During real-time sequencing, the Blockifier will reject/revert this call because the class is not declared. However, if the same transaction is re-executed by the Starknet OS (for proving or state-root computation), the OS will silently accept it and commit the contract's class_hash pointer to a class that was never declared. This is an execution-semantics divergence between the two engines that are supposed to compute an identical state transition:
- It can cause a wrong committed state root / block hash to be produced by the OS relative to what the Blockifier-based sequencer executed, or an inability to reconcile proven output with the sequencer-committed state.
- Contracts could end up permanently pointing to a class hash with no compiled code, which can permanently break the contract (denial of service on the contract's future calls) if this state ever gets committed/proven with a different `contract_class_changes` interpretation than the sequencer's.

This falls under the allowed impact categories: wrong committed root/block hash and honest-node divergence.

### Likelihood Explanation
The path is trivially reachable by any account: deploy or reuse a contract exposing the `replace_class` syscall and invoke it with an undeclared class hash — no special privileges, keys, or timing needed. The severity depends on whether some other stage of the OS pipeline (e.g., final state-diff validation, aliasing, or commitment building) independently re-checks that all `class_hash_to_compiled_class_hash` / contract class assignments correspond to declared classes; I was not able to fully trace every downstream consumer of `contract_state_changes` in the OS within the available context to rule this out with certainty. The explicit TODO strongly suggests this check is genuinely absent at the syscall level, matching the CVE's "missing authorization check on a dependency-creating operation" bug class, but confirmation of whether a later state-diff-level check exists that would prevent an actual committed inconsistency was not completed.

### Recommendation
Add the missing check in `execute_replace_class` in `syscall_impls.cairo` (and its deprecated counterpart in `deprecated_execute_syscalls.cairo`) to assert that `class_hash` corresponds to a declared class (mirroring the Blockifier's `get_compiled_class` check), and reject/revert otherwise, keeping OS and Blockifier semantics consistent.

### Proof of Concept
1. Deploy a contract exposing `test_replace_class(class_hash)` (as in `test_contract.cairo`).
2. Submit an invoke transaction calling `replace_class_syscall` with a `class_hash` that has never been declared on-chain.
3. Blockifier execution (sequencer) reverts the transaction with "... is not declared."
4. Starknet OS re-execution of the identical transaction (via `execute_replace_class` in `syscall_impls.cairo`) does not perform this check and unconditionally updates `contract_state_changes` to point the contract at the undeclared class hash, producing a different result/state-diff than the sequencer's execution. // Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
