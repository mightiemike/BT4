### Title
Client-side proof verification runs the STARK/circuit verifier before signature/nonce/balance authentication, allowing unauthenticated CPU-exhaustion via unbounded concurrent `add_transaction` calls - ([File: crates/apollo_gateway/src/gateway.rs])

### Summary
The Telegram webhook advisory's root cause is generic: expensive per-request work (body read + JSON parse) is performed before the authentication check (`x-telegram-bot-api-secret-token`), so an unauthenticated caller can force costly work merely by connecting. The sequencer gateway has the same ordering defect for `Invoke` transactions carrying client-side `proof_facts`/`proof`: the STARK/circuit proof verification (`starknet_proof_verifier::verify_proof`) is executed during `add_tx_inner` immediately after stateless (format-only) validation, and *before* any signature verification, nonce check, or balance check happens in the stateful validator's `__validate__` call.

### Finding Description
In `GenericGateway::add_tx_inner` [1](#0-0) , the flow for an `Invoke` transaction with non-empty `proof_facts` is:

1. `self.stateless_tx_validator.validate(&tx)` — only checks format/size bounds (calldata length, signature length, proof size, DA modes); it does **not** verify the ECDSA/account signature [2](#0-1) .
2. `self.convert_rpc_tx_to_internal_and_executable_txs(...)` is called, which invokes `await_verification_task_and_extract_proof_data`, which awaits the spawned `verification_task` [3](#0-2) .
3. That task runs `TransactionConverter::run_proof_verification`, which (when the proof isn't already cached) calls `starknet_proof_verifier::verify_proof` inside `spawn_blocking` [4](#0-3) . This executes `privacy_circuit_verify_v1::verify_recursive_circuit`, a CPU-intensive recursive STARK/circuit verification [5](#0-4) .
4. Only **after** this proof verification completes does the code proceed to `stateful_tx_validator_factory.instantiate_validator(...)` and `extract_state_nonce_and_run_validations`, which is where the actual account signature is checked via the `__validate__` entry point (`run_validate_entry_point`) [6](#0-5) [7](#0-6) .

So a completely unauthenticated caller — anyone can call `add_transaction` on the public gateway — can submit an `Invoke` V3 transaction with a garbage/mismatched but well-formed-looking `proof` blob and arbitrary `proof_facts` (only length-bounded by `max_proof_size`/`max_calldata_length`, not content-validated), forcing the node to run a full circuit verification before it ever checks whether the sender's signature is valid, whether the sender account exists, or whether it can pay fees. Unlike the declare path — which the developers explicitly recognized as a resource-exhaustion risk and bounded with a `declare_compilation_semaphore` / `max_concurrent_declare_compilations` (default 40, documented at `crates/apollo_gateway_config/src/config.rs:27-38`) — there is **no equivalent concurrency cap on proof verification**. Every `add_tx` call for a proof-carrying invoke unconditionally spawns a verification task with no semaphore, no proof cost pre-check, and no throttling tied to account/signature validity.

### Impact Explanation
Because proof verification runs unconditionally and unbounded in concurrency before any authentication (signature/nonce/balance), an attacker can flood the gateway with invoke transactions carrying maximum-size garbage proofs/proof_facts from unfunded, nonexistent, or spoofed sender addresses. Each such request consumes a `spawn_blocking` worker thread running full recursive-STARK verification, exhausting the node's CPU/thread pool. Because there is no bound (unlike the declare-compilation semaphore), a sustained flood can starve the gateway's ability to process legitimate transactions — a live-ness/availability failure of the transaction-ingestion path, i.e., the sequencer becoming unable to confirm new transactions.

### Likelihood Explanation
Trivially reachable by any unprivileged external caller via a single JSON-RPC `add_transaction` call — no valid signature, funded account, or prior state required, since the stateless validator does not check signature validity and the proof verification runs before stateful checks. The proof/proof_facts fields only need to satisfy shallow length/format bounds enforced by `StatelessTransactionValidator` (see `validate_proof_size`, `validate_client_side_proving_allowed`) [8](#0-7) , not actual proof correctness.

### Recommendation
Move real signature/account authentication (or at minimum a cheap nonce/account-existence pre-check) ahead of proof verification, or bound proof-verification concurrency the same way declare compilation is bounded (a `max_concurrent_proof_verifications` semaphore in `GatewayConfig`, mirroring `declare_compilation_semaphore`), rejecting excess requests immediately rather than performing the expensive verification.

### Proof of Concept
1. Craft an `RpcInvokeTransaction::V3` with `sender_address` set to an arbitrary (unfunded/nonexistent) address, an invalid `signature`, and `proof_facts`/`proof` fields populated up to `max_proof_size`/`max_calldata_length` with arbitrary bytes that pass only the shallow structural checks in `verify_proof` (e.g., valid `ProofVersion::V1` marker plus `proof_facts` length ≥ 3, as required by `reconstruct_output_preimage`) [9](#0-8) .
2. Submit many such transactions concurrently to the gateway's `add_transaction` endpoint from different (spoofed) sender addresses/nonces so they aren't deduplicated by the mempool.
3. Each request reaches `run_proof_verification` → `verify_recursive_circuit` in a `spawn_blocking` task before any signature/nonce/balance check runs, consuming CPU/thread-pool resources; with no concurrency limit, sustained submission degrades or exhausts the gateway's capacity to process legitimate transactions.

    async fn add_tx_inner(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        let mut metric_counters = GatewayMetricHandle::new(&tx, &p2p_message_metadata);
        metric_counters.count_transaction_received();
        if let RpcTransaction::Invoke(RpcInvokeTransaction::V3(ref inv)) = tx {
            if !inv.proof_facts.is_empty() {
                metric_counters.count_private_transaction_received();
            }
        }
        let is_p2p = p2p_message_metadata.is_some();

        if let RpcTransaction::Declare(ref declare_tx) = tx {
            if let Err(e) = self.check_declare_permissions(declare_tx) {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        }

        // Perform stateless validations.
        self.stateless_tx_validator.validate(&tx)?;

        let tx_signature = tx.signature().clone();

        // Declare conversions overload the compiler component's CPU and memory. Reject declares if
        // there are too many declares compiling in parallel. The permit is held only across
        // compilation and released before stateful validation.
        let compilation_permit = if matches!(tx, RpcTransaction::Declare(_)) {
            Some(self.declare_compilation_semaphore.try_acquire().map_err(|_| {
                let error = StarknetError::too_many_concurrent_declare_compilations();
                metric_counters.record_add_tx_failure(&error);
                error
            })?)
        } else {
            None
        };

        let (internal_tx, executable_tx, proof_data) =
            self.convert_rpc_tx_to_internal_and_executable_txs(tx, &tx_signature).await?;
        drop(compilation_permit);

        let mut stateful_transaction_validator = self
            .stateful_tx_validator_factory
            .instantiate_validator(self.config.dynamic_config.native_classes_whitelist.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let nonce = stateful_transaction_validator
            .extract_state_nonce_and_run_validations(&executable_tx, self.mempool_client.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

    /// Runs proof verification: checks if the proof already exists, and if not, verifies it.
    /// Returns `true` if verification was performed, `false` if skipped (proof already stored).
    /// This is the shared verification logic used by both gateway and consensus flows.
    async fn run_proof_verification(
        proof_facts: ProofFacts,
        proof: Proof,
        proof_manager_client: SharedProofManagerClient,
    ) -> Result<bool, TransactionConverterError> {
        let contains_proof = proof_manager_client.contains_proof(proof_facts.clone()).await?;

        if contains_proof {
            return Ok(false);
        }

        let proof_facts_hash = proof_facts.hash();
        let verify_start = Instant::now();
        tokio::task::spawn_blocking(move || {
            starknet_proof_verifier::verify_proof(proof_facts, proof)
        })
        .await
        .expect("proof verification task panicked")?;
        let verify_duration = verify_start.elapsed();
        PROOF_VERIFICATION_LATENCY.record(verify_duration.as_secs_f64());
        info!(
            "Proof verification took: {verify_duration:?} for proof facts hash: \
             {proof_facts_hash:?}"
        );

        Ok(true)
    }

pub fn reconstruct_output_preimage(
    proof_facts: &ProofFacts,
) -> Result<Vec<Felt>, VerifyProofError> {
    // Proof facts must contain at least [PROOF_VERSION_V*, variant, program_hash].
    if proof_facts.0.len() < 3 {
        return Err(VerifyProofError::ProofFactsTooShort { length: proof_facts.0.len() });
    }
    // Skip PROOF_VERSION_V* (index 0) and variant (index 1).
    let task_content = &proof_facts.0[2..];
    let output_size = Felt::from(
        u64::try_from(task_content.len() + 1).expect("task content length exceeds u64::MAX"),
    );
    Ok([Felt::ONE, output_size].into_iter().chain(task_content.iter().copied()).collect())
}

/// Verifies a submitted proof against the proof facts using the circuit verifier.
///
/// The first element of `proof_facts` must be V1, verified via `privacy-circuit-verify-v1`.
pub fn verify_proof(proof_facts: ProofFacts, proof: Proof) -> Result<(), VerifyProofError> {
    // Reject empty proof payloads before running the verifier.
    if proof.is_empty() {
        return Err(VerifyProofError::EmptyProof);
    }

    let proof_version_felt = proof_facts.0.first().copied().unwrap_or_default();
    let proof_version = ProofVersion::try_from(proof_version_felt)
        .map_err(|()| VerifyProofError::InvalidProofVersion { actual: proof_version_felt })?;

    let output_preimage = reconstruct_output_preimage(&proof_facts)?;
    // TODO(Avi): Avoid cloning the proof.
    let proof_bytes = proof.0.to_vec();

    match proof_version {
        // V0 proofs are no longer verifiable: the v0 circuit was removed. V0 proof facts are only
        // tolerated by the blockifier (gated per protocol version) for replaying historical blocks.
        ProofVersion::V0 => {
            return Err(VerifyProofError::InvalidProofVersion { actual: proof_version_felt });
        }
        ProofVersion::V1 => {
            let proof_output = privacy_circuit_verify_v1::PrivacyProofOutput {
                proof: proof_bytes,
                output_preimage,
            };
            privacy_circuit_verify_v1::verify_recursive_circuit(&proof_output)
                .map_err(|e| VerifyProofError::Verification(e.to_string()))?;
        }
    }

    Ok(())
}

    #[sequencer_latency_histogram(GATEWAY_VALIDATE_TX_LATENCY, true)]
    async fn run_validate_entry_point(
        &mut self,
        executable_tx: &ExecutableTransaction,
        skip_validate: bool,
    ) -> StatefulTransactionValidatorResult<()> {
        let only_query = false;
        let charge_fee = enforce_fee(executable_tx, only_query);
        let strict_nonce_check = false;
        let execution_flags =
            ExecutionFlags { only_query, charge_fee, validate: !skip_validate, strict_nonce_check };

        let account_tx = AccountTransaction { tx: executable_tx.clone(), execution_flags };

        // Build block context.
        let mut versioned_constants = VersionedConstants::get_versioned_constants(
            self.config.versioned_constants_overrides.clone(),
        );
        // The validation of a transaction is not affected by the casm hash migration.
        versioned_constants.disable_casm_hash_migration();

        let mut block_info = self.gateway_fixed_block_state_reader.get_block_info().await?;
        block_info.block_number = block_info.block_number.unchecked_next();
        let block_context = BlockContext::new(
            block_info,
            self.chain_info.clone(),
            versioned_constants,
            BouncerConfig::max(),
        );

        // Move state into the blocking task and run CPU-heavy validation.
        let state_reader_and_contract_manager = self.take_state_reader_and_contract_manager();

        let cur_span = Span::current();
        #[allow(clippy::result_large_err)]
        tokio::task::spawn_blocking(move || {
            cur_span.in_scope(|| {
                let state = CachedState::new(state_reader_and_contract_manager);
                let mut blockifier_validator = StatefulValidator::create(state, block_context);
                blockifier_validator.validate(account_tx)
            })
        })
        .await
        .map_err(|e| StarknetError {
            code: StarknetErrorCode::UnknownErrorCode(
                "StarknetErrorCode.InternalError".to_string(),
            ),
            message: format!("Blocking task join error when running the validate entry point: {e}"),
        })?
        .map_err(|e| StarknetError {
            code: StarknetErrorCode::KnownErrorCode(KnownStarknetErrorCode::ValidateFailure),
            message: e.to_string(),
        })?;
        Ok(())
