## Analysis

The external report describes an access-control failure that lets an unprivileged actor escalate privileges and manipulate protected state. Mapping this bug class onto the sequencer's transaction-execution surface, the closest reachable analog is a **missing declared-class check in the Starknet OS's `replace_class` syscall handler**, which diverges from the equivalent (and correctly-checked) implementation in the native execution client (blockifier).

### Title
Missing declared-class validation in Starknet OS `replace_class` syscall causes execution divergence from blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
Any contract can invoke the `replace_class` syscall as part of a single submitted transaction. Native blockifier enforces that the target `class_hash` corresponds to a declared (and, for the Cairo1 path, Cairo1-typed) class before mutating contract state, but the Starknet OS Cairo implementation re-executed for proving performs no such check, and the corresponding Rust-side OS hint stubs unconditionally succeed as well.

### Finding Description
In blockifier, `replace_class` is guarded on both syscall paths:
- Cairo1 path: `SyscallHandlerBase::replace_class` calls `self.state.get_compiled_class(class_hash)?` and additionally rejects non-Cairo1 classes via `ForbiddenClassReplacement`. [1](#0-0) 
- Cairo0 (deprecated) path: `replace_class` in the deprecated hint processor calls `syscall_handler.state.get_compiled_class(request.class_hash)?` before writing the new class hash. [2](#0-1) 

In contrast, the Starknet OS Cairo program's implementation of the same syscall omits this check entirely, as explicitly flagged by a TODO in the code: [3](#0-2) 

The deprecated (Cairo0) OS syscall path has the identical gap: [4](#0-3) 

The Rust-side OS hint processors that back these Cairo hints similarly perform no validation and unconditionally return success: [5](#0-4) [6](#0-5) 

For comparison, blockifier's own tests confirm the intended, enforced behavior — a `replace_class` call to an undeclared class hash must fail with an explicit "is not declared" error: [7](#0-6) 

### Impact Explanation
Because the OS is the component that re-executes transactions to produce the state transition that gets proven and ultimately committed on L1, any semantic gap between blockifier (used by the sequencer/proposer to build blocks) and the OS (used to prove them) is a correctness bug of the highest severity class: it can produce a state root that does not match what an honest full node computes from the same block, i.e., **honest-node divergence** and a **wrong committed root**. Concretely: a contract that calls `replace_class_syscall` with an undeclared (or arbitrary garbage) class hash will have that call fail in blockifier (`UndeclaredClassHash`/`ForbiddenClassReplacement`), reverting that execution step, while the OS silently accepts the same call and commits the contract's `class_hash` to the invalid value in `contract_state_changes`. This is also an **unauthorized account action**: a contract's class pointer can be corrupted to a value that was never validated as a legitimate declared class, deviating from the access-control invariant that only declared classes can back a contract's code.

### Likelihood Explanation
The `replace_class` syscall is available to any Cairo0 or Cairo1 contract via a normal external call — no special privilege, staking, or operator access is required. An attacker only needs to deploy or use a contract that invokes `replace_class_syscall`/`replace_class` with a crafted, undeclared `class_hash`, which is directly reachable from a single submitted `INVOKE` transaction's `__execute__` flow. The check gap is unconditional (governed only by the presence of the syscall, not by any feature flag), and is explicitly acknowledged as an outstanding TODO in the OS source, indicating the OS-side enforcement was never implemented.

### Recommendation
Add the same declared-class (and, for the Cairo1 syscall, Cairo1-type) validation to the Starknet OS's `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring blockifier's `get_compiled_class` / `is_cairo1` checks, and enforce equivalent validation in the Rust-side `snos_syscall_executor.rs` and `snos_deprecated_syscall_executor.rs` hint stubs so that the OS rejects (or reverts, consistent with blockifier's error propagation) any `replace_class` call targeting an undeclared class hash.

### Proof of Concept
1. Deploy a Cairo1 contract exposing an external entry point that invokes `replace_class_syscall(class_hash)` with an attacker-supplied `class_hash` that is guaranteed to be undeclared (e.g., a random felt not corresponding to any declared class).
2. Submit an `INVOKE` transaction calling this entry point.
3. In blockifier (used by the sequencer to build/validate the block), `SyscallHandlerBase::replace_class` calls `get_compiled_class(class_hash)`, which returns `StateError::UndeclaredClassHash`, causing that call (and typically the whole `__execute__` step) to fail/revert.
4. When the Starknet OS re-executes the same block for proving, `execute_replace_class` in `syscall_impls.cairo` (and the Rust-side `snos_syscall_executor::replace_class` stub) perform no declared-class check and unconditionally update `contract_state_changes` with the undeclared `class_hash`, and return success.
5. Result: the OS's computed final state (and therefore the state root it proves) sets the calling contract's class hash to an undeclared value and reports the call as successful, while blockifier's execution (and hence the real network state as observed by honest full nodes) reverted the call — a direct divergence between the block-building client and the proving client for the identical transaction and block.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
