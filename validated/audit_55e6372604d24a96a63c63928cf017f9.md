## Finding

Unbounded recursion over a declarer-influenced `NestedIntList` tree (`bytecode_segment_lengths`) is used both to compute the CASM compiled-class hash and to build the bytecode-segment structure used by the Starknet OS, with no recursion-depth guard anywhere in the call chain.

### Title
Uncontrolled recursion computing compiled-class hash / bytecode-segment structure from a declared class's `bytecode_segment_lengths` - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs])

### Summary
`CasmContractClass::bytecode_segment_lengths` is a `NestedIntList` (an arbitrarily nested tree of `Leaf`/`Node` variants) that is produced when the sequencer compiles a declarer-submitted Sierra program to CASM. This structure is later walked recursively, with no depth bound, in at least two in-process (non-sandboxed) code paths that every node must execute for every declared class: computing the compiled-class hash, and building the bytecode-segment structure consumed by the Starknet OS.

### Finding Description
`bytecode_hash_node` recurses once per tree level with no depth check: [1](#0-0) . It is invoked by `CasmContractClass::hash`, which is called:
- In `SierraCompiler::compile` immediately after Sierra→CASM compilation, **outside** the resource-limited compiler subprocess: [2](#0-1) . Note that `compile_with_args` applies CPU-time/memory `ResourceLimits` only to the external compiler binary invocation, not to this in-process hashing step.
- In `DeclareTransaction::check_compile_class_hash_v2_declaration`, run during blockifier transaction execution: [3](#0-2) .
- In the gateway/mempool transaction-conversion path that validates a submitted `compiled_class_hash` against the recomputed hash (`ValidateCompiledClassHashError::CompiledClassHashMismatch`), in `apollo_transaction_converter/src/transaction_converter.rs`.

Separately, the Starknet OS builds an equivalent recursive structure with the same unbounded pattern:
`create_bytecode_segment_structure_inner` recurses once per `NestedIntList::Node` with no depth check: [4](#0-3) . This is exercised during Starknet OS re-execution/proving of every block that touches the declared class.

Unlike Sierra-to-CASM compilation itself — which is deliberately isolated in a subprocess with `ResourceLimits` (CPU time, memory) specifically because it is untrusted-input-driven — the post-compilation hashing and OS bytecode-segment construction run in-process, unsandboxed, and are reached on the hot path of every declare transaction (gateway validation, blockifier execution) and every OS re-execution of a block containing that class.

### Impact Explanation
A contract declarer who can craft a Sierra program whose compiled CASM bytecode segmentation is deeply nested (segmentation is a tree the compiler builds along function/branch boundaries) can cause `bytecode_hash_node` / `create_bytecode_segment_structure_inner` to recurse to a depth proportional to that nesting. Because these recursive functions run in-process without a depth guard, sufficiently deep nesting can exhaust the call stack and crash the process performing validation — the gateway process during declare submission, the batcher/blockifier during execution, or the Starknet OS re-execution/proving process. A crash in these components is a denial-of-service that can prevent the network from confirming new transactions (gateway/mempool crash) or halt block building/re-execution (blockifier/OS crash), satisfying the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Likelihood is uncertain without confirming exactly how deep a nesting `bytecode_segment_lengths` the real cairo-lang compiler can be made to emit for a class within the `max_bytecode_size` bound enforced during compilation (`SierraCompilationConfig::max_bytecode_size`, see `crates/apollo_compile_to_casm/src/compiler.rs`). The compile-time subprocess enforces size/CPU/memory limits on the *compilation* step but places no explicit bound on the *depth* of the resulting `bytecode_segment_lengths` tree, and none of the downstream consumers (hash computation, OS segment builder) validate or cap that depth either. This mirrors the reported SQLFluff bug class exactly (CWE-674: recursive processing of attacker-influenced nested structure with no configurable/enforced recursion limit).

### Recommendation
- Add an explicit, enforced maximum recursion depth (and/or convert to an iterative/stack-based traversal) in `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs`) and in `create_bytecode_segment_structure_inner` (`crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`).
- Validate `bytecode_segment_lengths` depth (and shape) immediately after Sierra-to-CASM compilation, before the class is admitted to the gateway/mempool or stored, rejecting classes that exceed the depth bound.
- Ensure any such validation/hashing that must remain recursive runs with the same resource isolation (subprocess + resource limits) currently applied to Sierra-to-CASM compilation, rather than in-process on the gateway/blockifier/OS hot path.

### Proof of Concept
Not independently constructed — this requires confirming, using the actual `cairo-lang` Sierra-to-CASM compiler, that a Sierra program within `max_bytecode_size` can produce a `bytecode_segment_lengths` `NestedIntList` with a nesting depth large enough (e.g., tens of thousands of levels) to overflow a typical thread stack when passed through `bytecode_hash_node` / `create_bytecode_segment_structure_inner`. This verification requires running the actual compiler toolchain, which was not available in this read-only code search; a Devin session with the ability to build and run the `apollo_compile_to_casm` and `starknet_api` crates would be needed to confirm achievable nesting depth and reproduce a stack overflow.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

        let compiled_class = &self.class_info.contract_class;
        let compiled_class_hash_v2 = match &compiled_class {

            ContractClass::V1((casm, _)) => casm.hash(&HashVersion::V2),
        };
        let compiled_class_hash = self.compiled_class_hash();
        if compiled_class_hash_v2 != compiled_class_hash {

                hash: self.class_hash(),
                actual: compiled_class_hash,
                expected: compiled_class_hash_v2,
            };
            return Err(StarknetApiError::DeclareTransactionCasmHashMissMatch(Box::new(err_var)));
        }
        Ok(())
    }

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}
