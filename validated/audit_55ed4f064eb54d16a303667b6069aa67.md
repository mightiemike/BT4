### Title
Instantaneous Uniswap V3 quote used both to compute and to protect PRC20→PC auto-swaps allows sandwich extraction of user/protocol funds - ([File: x/uexecutor/keeper/evm.go])

### Summary
Push Chain's inbound gas/deposit auto-swap path and the outbound gas-refund path both derive their swap price from `QuoterV2.quoteExactInputSingle`, which reflects the *instantaneous* reserves of the on-chain Uniswap V3 pool at execution time [1](#0-0) . The resulting quote is used to compute the slippage-protection value `minPCOut` (95% of quote) and is then passed, in the same keeper call sequence, into the actual swap-executing call `depositPRC20WithAutoSwap` / `refundUnusedGas` [2](#0-1) [3](#0-2) [4](#0-3) . This is the same bug class as the external report: a `slot0`/quoter-derived instantaneous price is used to both size and bound a financial action executed in the same transaction/block, so the "slippage protection" only protects against divergence *from the manipulated baseline*, not against the manipulation itself.

### Finding Description
`GetSwapQuote` performs a static call to Uniswap V3's `QuoterV2.quoteExactInputSingle`, whose output is derived from the pool's current tick/liquidity/`sqrtPriceX96` — i.e., instantaneous, single-block state, with no TWAP [1](#0-0) . Every caller of this function computes `minPCOut = quote * 95 / 100` immediately afterward and feeds it straight into the swap-executing derived EVM call within the same keeper function, with no intervening block boundary and no re-check against any external reference price:

- `ExecuteInboundGas` (GAS route): quote → 5% slippage → `CallPRC20DepositAutoSwap` [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD route): identical pattern [5](#0-4) 
- `applyGasRefund` (outbound gas refund route): identical pattern via `getSwapQuoteForRefund` → `CallUniversalCoreRefundUnusedGas` [6](#0-5) 

Because the quote and the swap execution read the same pool state (there is no time separation and no TWAP oracle — a repo-wide search for "TWAP" found no matches in swap-related code), an attacker can sandwich these module-originated derived EVM calls:
1. Push the Uniswap V3 pool's PRC20/WPC price down just before the module's deposit/refund-swap tx is included in a block (a large swap in the same direction the module will trade).
2. The module reads the manipulated instantaneous price via `GetSwapQuote`, computes a `minPCOut` that is 95% of the *already-depressed* quote — this bound is then trivially satisfied by the equally-depressed actual swap output.
3. The module's swap executes at the manipulated price, delivering far less WPC/PC to the user's UEA (or to the gas-refund recipient) than a fair TWAP-based price would.
4. The attacker reverses their initial swap afterward, capturing the value that would otherwise have gone to the depositor/refund recipient.

This is triggered by ordinary, unprivileged user activity — any user depositing gas/funds cross-chain (`TxType::GAS`, `GAS_AND_PAYLOAD`) or any outbound whose unused gas is refunded with a swap — with no validator, admin, or TSS privilege required by the attacker. The attacker only needs the ability to submit ordinary EVM transactions against the same Uniswap V3 pool on Push Chain in the block(s) surrounding the module's derived swap call.

### Impact Explanation
This directly causes **user/protocol fund loss**: depositors receive less PC/WPC than they should for their deposited gas tokens, and gas-refund recipients receive a smaller refund than warranted, with the difference captured by the attacker via arbitrage. This falls squarely within "stealing, draining ... of user or protocol-controlled funds" in the allowed impact gate, is reachable from default/ordinary user deposit and outbound flows (`x/uexecutor`), and does not require any malicious validator, node, or privileged actor — only an unprivileged attacker able to trade against the pool.

### Likelihood Explanation
High. The vulnerable pattern (quote-then-swap with no time separation and a fixed 5% band) exists on three separate call sites (inbound GAS, inbound GAS_AND_PAYLOAD, outbound refund), and each is triggered by routine, attacker-observable user actions (deposits are visible pending in the mempool/inbound-voting pipeline before execution, and outbound gas refunds occur predictably after outbound finalization). A 5% band is well within normal single-block AMM manipulation capability for pools with moderate liquidity, and JIT liquidity/flash-swap techniques (as cited in the original report) make this economically feasible without needing large standing capital.

### Recommendation
- Do not derive `minPCOut` from the same instantaneous `QuoterV2` quote that will be consumed immediately by the swap; instead use a Uniswap V3 TWAP (with a sufficiently large window, e.g. ≥ 15–30 minutes as recommended in the referenced report) or an independent price reference (e.g., the validator-voted `ChainMeta`/`GasPrice` median oracle already present in `x/uexecutor`) to bound acceptable slippage.
- Alternatively, widen protection by capping the deviation of the instantaneous quote against a TWAP baseline, rejecting the swap (and falling back to the no-swap PRC20 deposit path) if the two diverge beyond a safe threshold.
- Consider batching/delaying swap execution or adding commit-reveal / minimum time-in-mempool protections to reduce same-block sandwichability of module-originated derived swaps.

### Proof of Concept
1. Attacker monitors Push Chain's inbound-voting pipeline (`MsgVoteInbound`) or pending outbound gas-refund events for an upcoming `depositPRC20WithAutoSwap` / `refundUnusedGas` derived call for a given PRC20/WPC pair and pool.
2. Immediately before the module's finalizing transaction is expected to land (e.g., positioning a transaction with higher priority fee in the same block, or acting when a UV vote finalizes a ballot), the attacker sells a large amount of the PRC20 gas token into the WPC pool, depressing its instantaneous price.
3. The keeper calls `GetSwapQuote` [7](#0-6) , obtaining a depressed `amountOut`; it computes `minPCOut = quote*95/100` [8](#0-7)  and calls `CallPRC20DepositAutoSwap`, which executes against the still-depressed pool and satisfies the equally-depressed `minPCOut`.
4. Attacker immediately buys back the PRC20/sells WPC to restore the pool price, realizing a profit equal to the value diverted from the deposit/refund recipient.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
