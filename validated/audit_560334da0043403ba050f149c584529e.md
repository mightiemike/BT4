### Title
Unbounded recursive JSON deserialization of untrusted `Program` fields in declare transactions enables stack-overflow DoS - (File: `crates/starknet_api/src/deprecated_contract_class.rs`)

### Summary
`starknet_api::deprecated_contract_class::Program`, which is embedded in every Cairo0 (`DECLARE` v0/v1) transaction submitted by any unprivileged account, stores several fields (`attributes`, `hints`, `identifiers`, `reference_manager`, `debug_info`, `data`, `builtins`) as raw, untyped `serde_json::Value` [1](#0-0) . `serde_json::Value`'s deserializer recurses once per nesting level of arrays/objects with no depth limit, so an attacker can submit a small, size-limit-compliant declare transaction whose `program` JSON contains extremely deep nesting (e.g. `[[[[...]]]]`) to blow the deserializing thread's stack. This is directly analogous to the reported Furnace FUR→VGM converter bug: an untrusted, attacker-controlled "converter"/parser recurses without a depth bound and crashes the process.

### Finding Description
Declare v0/v1 transactions (`DeclareV1Transaction` / `BroadcastedDeclareV1Transaction`) carry a `DeprecatedContractClass` whose `program` field is the `Program` struct above [2](#0-1) [3](#0-2) . These transactions are decoded from raw JSON that any external sender fully controls before any Sierra/CASM-specific size checks apply. Downstream, `sn_api_to_cairo_vm_program` calls `serde_json::from_value` on the raw `identifiers`, `hints`, and `reference_manager` values while converting the class for execution [4](#0-3) ; deserializing/re-serializing this data (e.g. via `serde_json::to_value`/parsing during initial transaction ingestion, hashing, or storage) recurses over the entire nested structure without any depth guard, unlike the CASM/Sierra compilation path, which runs in a resource-limited subprocess and cannot crash the sequencer itself [5](#0-4) . There is no equivalent isolation or recursion-depth protection for this deserialization step, which happens in-process (e.g. in the HTTP server, gateway, or blockifier when handling the transaction).

The only size constraint applied at ingestion is `max_request_body_size` on the HTTP server [6](#0-5) , which bounds total bytes but not JSON nesting depth — a payload of only a few hundred KB can encode hundreds of thousands of nested array levels (`"["` repeated N times, `"]"` repeated N times), which is enough to exhaust a typical thread stack (commonly 2–8 MB) well before hitting any byte-size limit.

### Impact Explanation
A stack overflow in Rust aborts the whole process (it cannot be caught with `panic::catch_unwind`), so any node component that deserializes this attacker-controlled JSON (gateway, HTTP server, or a sequencer/validator ingesting the declare transaction) can be crashed by a single unprivileged, correctly-signed declare v0/v1 transaction. If exploited against enough sequencer/validator instances simultaneously (e.g., via the mempool disseminating the same transaction), this can prevent the network from confirming new transactions — a network-availability impact.

### Likelihood Explanation
Likelihood is limited by whether the network still accepts new Cairo0 (`DECLARE` v0/v1) contract-class declarations; if v0/v1 declares are still processed in this deployment, any account holding funds/permission to submit a declare transaction can trigger this without any special privilege, and constructing the malicious deeply-nested JSON payload is trivial and inexpensive.

### Recommendation
- Reject `Program` payloads whose JSON nesting depth exceeds a small, sane bound before performing any `serde_json` (de)serialization of `identifiers`/`hints`/`reference_manager`/`attributes`/`debug_info` fields, e.g. by validating with a depth-limited JSON parser (such as `serde_stacker`/`serde_json` with an explicit recursion-limit wrapper) at the point the transaction is first parsed.
- Alternatively, run such untrusted deserialization on a dedicated thread with a bounded, generous stack combined with an explicit depth check, or reject the transaction with an isolated, catchable error rather than allowing unbounded native recursion.
- Apply the same treatment anywhere else `serde_json::Value` is used to hold structurally-unbounded, attacker-controlled data reachable from a transaction (e.g. other free-form `Value` fields in class/program structures).

### Proof of Concept
1. Craft a `DECLARE` v0/v1 transaction (or `BroadcastedDeclareV1Transaction` via RPC) whose `contract_class.program` JSON sets `identifiers` (or `hints`/`reference_manager`/`attributes`) to a deeply nested array, e.g. `"[" * 500000 + "]" * 500000` (well under typical `max_request_body_size`).
2. Submit the transaction to the gateway/HTTP server (`apollo_http_server`) or directly to a component that deserializes `starknet_api::deprecated_contract_class::Program`.
3. Observe that `serde_json`'s recursive descent parser/`Value` construction recurses proportionally to nesting depth, exhausting the thread's stack and aborting the process handling the request — a denial of service triggerable by a single unprivileged transaction sender.

```rust
pub fn sn_api_to_cairo_vm_program(program: DeprecatedProgram) -> Result<Program, ProgramError> {
    let identifiers = serde_json::from_value::<HashMap<String, Identifier>>(program.identifiers)?;
    let builtins = serde_json::from_value(program.builtins)?;
    let data = deserialize_array_of_bigint_hex(program.data)?;
    let hints = serde_json::from_value::<HashMap<usize, Vec<HintParams>>>(program.hints)?;
    let main = None;
    let error_message_attributes = match program.attributes {
        serde_json::Value::Null => vec![],
        attributes => serde_json::from_value::<Vec<Attribute>>(attributes)?
            .into_iter()
            .filter(|attr| attr.name == "error_message")
            .collect(),
    };

    let instruction_locations = None;
    let reference_manager = serde_json::from_value::<ReferenceManager>(program.reference_manager)?;

    let program = Program::new(
        builtins,
        data,
        main,
        hints,
        reference_manager,
        identifiers,
        error_message_attributes,
        instruction_locations,
    )?;

    Ok(program)
```

```rust
pub fn compile_with_args(
    compiler_binary_path: &Path,
    contract_class: ContractClass,
    additional_args: &[&str],
    resource_limits: ResourceLimits,
) -> Result<Vec<u8>, CompilationUtilError> {
    // Create a temporary file to store the Sierra contract class.
    let serialized_contract_class = serde_json::to_string(&contract_class)?;

    let mut temp_file = NamedTempFile::new()?;
    temp_file.write_all(serialized_contract_class.as_bytes())?;
    let temp_file_path = temp_file.path().to_str().ok_or(CompilationUtilError::UnexpectedError(
        "Failed to get temporary file path".to_owned(),
    ))?;

    // Set the parameters for the compile process.
    let mut command = Command::new(compiler_binary_path.as_os_str());
    command.arg(temp_file_path).args(additional_args);

    // Apply the resource limits to the command.
    resource_limits.apply(&mut command);

    // Run the compile process.
    let compile_output = command.output()?;

    if !compile_output.status.success() {
        let stderr_output = String::from_utf8(compile_output.stderr)
            .unwrap_or_else(|_| "Failed to decode stderr output".to_string());

        let error_message = format_compiler_error(&stderr_output, &compile_output.status);
        return Err(CompilationUtilError::CompilationError(error_message));
    }
    Ok(compile_output.stdout)
}
```
