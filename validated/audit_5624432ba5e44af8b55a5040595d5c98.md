### Title
Starknet OS `replace_class` syscall omits the declared-class check enforced by blockifier, causing state-root divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall unconditionally accepts any `class_hash` and writes it into `contract_state_changes`, while the sequencer's actual transaction executor (`blockifier`) requires the target class to be declared before allowing the replacement. This is the sequencer analog of "logic contract relies on code not re-executed by the proxy": here, one code path (blockifier, which builds blocks) enforces an invariant that the other code path (the SNOS Cairo program, which re-executes transactions to compute the committed state root) does not re-enforce, producing two different results for the identical transaction.

### Finding Description
`blockifier`'s syscall handlers for `replace_class` explicitly validate that the target class hash is declared before mutating state: [1](#0-0) 

This check is exercised and confirmed by a unit test that expects an `"is not declared"` error for an undeclared class hash: [2](#0-1) 

The native and Cairo1 `replace_class` handlers route through the same shared `SyscallHandlerBase::replace_class`, which is the code path performing this declared-class validation: [3](#0-2) [4](#0-3) 

In contrast, the Starknet OS's own Cairo implementation of the same syscall (used to independently re-execute contract bytecode for producing the block's state diff / state commitment during proving) performs **no such check**. The `execute_replace_class` function in the current (Cairo1) syscall path carries an explicit acknowledgment of the missing validation: [5](#0-4) 

The deprecated (Cairo0) OS syscall path has the identical gap — it directly updates the contract's `state_entry.class_hash` to the requested value with no verification that the class is declared at all: [6](#0-5) 

The OS is not merely trusting an external hint for this decision — it is directly executing the actual contract bytecode and its own syscall implementation to determine success/failure of the syscall, mirroring `blockifier`'s job for block-building. Because the OS's implementation of `execute_replace_class` lacks the "is class declared" gate that blockifier's implementation has, the OS will treat a `replace_class` call to an undeclared class hash as **successful**, whereas blockifier (the sequencer that actually built/applied the block) treats the identical call as a **failure** (reverting the call/transaction).

### Impact Explanation
The Starknet OS's execution output feeds directly into the block's state diff, Patricia tree updates, and ultimately the committed state root / block hash produced as part of proving and settlement. If an unprivileged contract issues a `replace_class` syscall with an undeclared class hash:
- `blockifier` (actual sequencer execution) rejects/reverts the syscall, so the class hash of that contract is left unchanged in the state actually maintained by the chain.
- The Starknet OS re-execution of the same transaction accepts the syscall, applies `contract_state_changes` setting that contract's class hash to the undeclared value, and this diff gets committed into the state tree / proven output.

This is a "wrong committed root" / honest-node divergence bug: the state root computed via the OS's re-execution path would not match the actual state that blockifier and full nodes maintain for the same transaction, breaking the fundamental invariant that block execution results (as recorded on-chain) must equal the proven Starknet OS execution results. Depending on how divergent outputs are handled (e.g. proof/commitment mismatch, or a corrupted committed state being accepted), this can lead to: chain state corruption for the affected contract (permanently pointing to a non-existent/undeclared class), inability to reconcile state roots between the sequencer and prover, or de-facto freezing/incorrect execution for downstream calls to that contract.

### Likelihood Explanation
The path is trivially reachable by any unprivileged account or contract: `replace_class` is a public syscall usable by ordinary Cairo1/Cairo0 contract code inside a single invoke transaction, requiring only an arbitrary, undeclared felt as `class_hash`. No special privileges, staking, or operator access are needed — an attacker only needs to deploy or call an existing contract that invokes `replace_class(undeclared_hash)`.

### Recommendation
Add the same "class is declared" validation to the Starknet OS's `execute_replace_class` implementations (both the Cairo1 path in `syscall_impls.cairo` and the deprecated Cairo0 path in `deprecated_execute_syscalls.cairo`) that `blockifier`'s `SyscallHandlerBase::replace_class` / deprecated syscall handler perform, i.e., verify a corresponding entry exists in `contract_class_changes` / declared classes before writing the new `StateEntry.class_hash`, and fail the syscall (matching blockifier's revert behavior) when it does not. This resolves the TODO already present at `syscall_impls.cairo:902` and removes the divergence between sequencer execution and OS re-execution.

### Proof of Concept
1. Deploy a Cairo1 contract exposing an external function that calls the `replace_class` syscall with an arbitrary felt as `class_hash` (no prior `declare` transaction for that hash).
2. Submit an invoke transaction calling that function from any unprivileged account.
3. Observe that `blockifier`'s `SyscallHandlerBase::replace_class` (reached via `crates/blockifier/src/execution/syscalls/hint_processor.rs:685-693` and `crates/blockifier/src/execution/native/syscall_handler.rs:395-406`) fails with `StateError::UndeclaredClassHash`, causing the call/transaction to revert — matching the negative-flow assertion in `crates/blockifier/src/execution/deprecated_syscalls/deprecated_syscalls_test.rs:375-391`.
4. Feed the identical transaction/trace to the Starknet OS re-execution (`execute_replace_class` in `crates/apollo_starknet_os_program/.../execution/syscall_impls.cairo:881-920`), and observe it unconditionally updates `contract_state_changes` with the undeclared class hash and returns success, with no analogous failure path — producing a state diff for that contract that blockifier's actual execution never produced.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
