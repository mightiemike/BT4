### Title
Unbounded permanent disk growth from Declare transactions that fail post-compilation stateful validation - (File: crates/apollo_gateway/src/gateway.rs)

### Summary
The gateway persists a declared Sierra/CASM class to disk (via `ClassManager::add_class` → `FsClassStorage::set_class`) before running stateful validation (nonce, fee, balance, `__validate__`). Since class hashes are content-addressed and unique per Sierra program, an attacker can submit a stream of syntactically distinct but otherwise cheap/invalid Declare transactions, each compiling and permanently writing a new class to disk, while every one is rejected before ever reaching the mempool. There is no garbage collection or eviction path for classes in `FsClassStorage`, so disk usage grows without bound as long as the attacker keeps submitting new classes, analogous to CVE-2025-54605 in Bitcoin Core where invalid blocks could be used to fill disk before full validation.

### Finding Description
`GenericGateway::add_tx_inner` in [1](#0-0)  performs, in order:
1. Stateless validation only (`self.stateless_tx_validator.validate(&tx)`), which checks structural bounds (size, resource bounds, sorted entry points) but not nonce, balance, fee sufficiency, or account signature/`__validate__`.
2. `self.convert_rpc_tx_to_internal_and_executable_txs(...)`, which for Declare transactions calls into the class manager's `add_class`, triggering Sierra→CASM compilation and a **permanent** write to `FsClassStorage`.
3. Only afterwards does `extract_state_nonce_and_run_validations` run the actual stateful checks (nonce correctness, fee bounds, balance, `__validate_declare__`) — see [2](#0-1) .

If stateful validation fails, `add_tx_inner` returns an error and the transaction is never forwarded to the mempool (confirmed by the test `add_tx_returns_error_when_extract_state_nonce_and_run_validations_fails` in [3](#0-2) ). However, the class write already happened.

`ClassManager::add_class` in [4](#0-3)  checks for an existing hash, compiles the class, then unconditionally calls `self.classes.set_class(...)`, persisting it. `FsClassStorage::set_class`/`write_class_atomically` in [5](#0-4)  writes the Sierra and CASM files to a content-addressed directory on disk and marks it as existent — with no expiry, TTL, or reference to whether the originating transaction was ever accepted into a block or even the mempool.

A search of the codebase confirms there is no deletion, eviction, or garbage-collection path for classes in `FsClassStorage` or `CachedClassStorage` (`delete_class`/`remove_class`/`evict*class` patterns return zero matches repo-wide). Once written, a class occupies disk space forever, whether or not it was ever declared on-chain.

The only mitigation present is `declare_compilation_semaphore`, which bounds *concurrent* compilations (see [6](#0-5) , `crates/apollo_gateway/src/gateway.rs:243-251`), and per-class size limits (`max_contract_bytecode_size`, `max_contract_class_object_size`, `max_compiled_contract_class_object_size`, default ~4MB) — none of which bound total cumulative disk usage over time or across the class hash space.

### Impact Explanation
This does not corrupt state or forge funds, but it lets any unprivileged sender (no balance or fee required — the tx is rejected for fee/nonce/balance *after* the class is already written) permanently consume sequencer node disk space via repeated Declare submissions with unique classes (trivially generated by varying a constant/dummy in the Sierra program to get a new class hash), each up to the max class size (~4MB Sierra + compiled CASM). Sustained abuse can exhaust disk on gateway/class-manager nodes, causing service degradation or crashes — a resource-exhaustion condition that can eventually impair the network's ability to accept new transactions on affected nodes, which the rules explicitly recognize as impactful ("a network unable to confirm new transactions").

### Likelihood Explanation
High feasibility: the attacker needs no funds and no account state at all, since failure occurs at the nonce/fee/balance/`__validate_declare__` stage, after compilation and disk persistence have already occurred. Each unique class hash requires only minor Sierra program content variation, and Declare submissions rejected this way don't even need to be valid enough to reach the mempool — they are limited only by the gateway's per-node compilation concurrency limit and the network's ability to submit new RPC requests, not by any anti-spam economic cost. Repeating this indefinitely produces continuous unbounded disk growth.

### Recommendation
Defer persistent class storage writes until after all stateful validation succeeds (or at minimum until the transaction is admitted into the mempool), or add class storage garbage collection / total-size or per-account-hour rate limits, and/or require a light proof-of-work/economic cost for class compilation/storage prior to full stateful admission.

### Proof of Concept
1. Attacker crafts N syntactically distinct Sierra programs (each valid enough to pass `validate_class_length`/`validate_entry_points_sorted_and_unique`/version checks) that each hash to a unique `ClassHash`, e.g. by varying an unused literal/entry-point ordering.
2. For each, submit a Declare V3 transaction from a never-funded or nonce-mismatched sender address so it always fails at `extract_state_nonce_and_run_validations` (e.g., `InvalidTransactionNonce` or insufficient balance/fee).
3. Observe: `add_tx_inner` ( [7](#0-6) ) has already invoked `convert_rpc_tx_to_internal_and_executable_txs` → `ClassManager::add_class` → `FsClassStorage::set_class`, permanently writing Sierra+CASM files to `<persistent_root>/<hash_prefix>/<hash_prefix>/<class_hash>/{sierra,casm}` before the nonce/fee validation error is returned to the caller.
4. Repeat with new unique classes; disk usage under the class-manager's `persistent_root` grows monotonically with no corresponding cleanup, regardless of the fact that none of the submitted transactions were ever admitted to the mempool or included in a block.

    async fn add_tx_inner(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        let mut metric_counters = GatewayMetricHandle::new(&tx, &p2p_message_metadata);
        metric_counters.count_transaction_received();
        if let RpcTransaction::Invoke(RpcInvokeTransaction::V3(ref inv)) = tx {
            if !inv.proof_facts.is_empty() {
                metric_counters.count_private_transaction_received();
            }
        }
        let is_p2p = p2p_message_metadata.is_some();

        if let RpcTransaction::Declare(ref declare_tx) = tx {
            if let Err(e) = self.check_declare_permissions(declare_tx) {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        }

        // Perform stateless validations.
        self.stateless_tx_validator.validate(&tx)?;

        let tx_signature = tx.signature().clone();

        // Declare conversions overload the compiler component's CPU and memory. Reject declares if
        // there are too many declares compiling in parallel. The permit is held only across
        // compilation and released before stateful validation.
        let compilation_permit = if matches!(tx, RpcTransaction::Declare(_)) {
            Some(self.declare_compilation_semaphore.try_acquire().map_err(|_| {
                let error = StarknetError::too_many_concurrent_declare_compilations();
                metric_counters.record_add_tx_failure(&error);
                error
            })?)
        } else {
            None
        };

        let (internal_tx, executable_tx, proof_data) =
            self.convert_rpc_tx_to_internal_and_executable_txs(tx, &tx_signature).await?;
        drop(compilation_permit);

        let mut stateful_transaction_validator = self
            .stateful_tx_validator_factory
            .instantiate_validator(self.config.dynamic_config.native_classes_whitelist.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let nonce = stateful_transaction_validator
            .extract_state_nonce_and_run_validations(&executable_tx, self.mempool_client.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

    pub async fn add_class(&mut self, class: RawClass) -> ClassManagerResult<ClassHashes> {
        let sierra_class = SierraContractClass::try_from(&class)?;
        let class_hash = sierra_class.calculate_class_hash();
        if let Ok(Some(executable_class_hash_v2)) =
            self.classes.get_executable_class_hash_v2(class_hash)
        {
            // Class already exists.
            return Ok(ClassHashes { class_hash, executable_class_hash_v2 });
        }

        let compilation_start_time = Instant::now();
        let (raw_executable_class, executable_class_hash_v2) =
            self.compiler.compile(class.clone()).await.map_err(|err| match err {
                SierraCompilerClientError::SierraCompilerError(error) => {
                    ClassManagerError::SierraCompiler { class_hash, error }
                }
                SierraCompilerClientError::ClientError(error) => {
                    ClassManagerError::Client(error.to_string())
                }
            })?;
        debug!(
            %class_hash,
            compiled_class_hash = %executable_class_hash_v2,
            compilation_elapsed_ms = compilation_start_time.elapsed().as_millis(),
            class_size_bytes =
                class.size().map_or("Failed to get class size".to_owned(), |size| size.to_string()),
            casm_size_bytes =
                raw_executable_class.size().map_or("Failed to get casm size".to_owned(), |size| size.to_string()),
            "Finished compiling class."
        );

        self.validate_class_length(&raw_executable_class)?;
        Self::validate_class_version(&sierra_class)?;
        self.classes.set_class(
            class_hash,
            class,
            executable_class_hash_v2,
            raw_executable_class,
        )?;

        let class_hashes = ClassHashes { class_hash, executable_class_hash_v2 };
        Ok(class_hashes)
    }

    fn write_class_atomically(
        &self,
        class_id: ClassId,
        class: RawClass,
        executable_class: RawExecutableClass,
    ) -> FsClassStorageResult<()> {
        // Write classes to a temporary directory.
        let (_tmp_root, tmp_dir) = self.create_tmp_dir(class_id)?;
        class.write_to_file(concat_sierra_filename(&tmp_dir))?;
        executable_class.write_to_file(concat_executable_filename(&tmp_dir))?;

        self.rename_to_persistent_dir(tmp_dir, class_id)
    }

    fn write_deprecated_class_atomically(
        &self,
        class_id: ClassId,
        class: RawExecutableClass,
    ) -> FsClassStorageResult<()> {
        // Write class to a temporary directory.
        let (_tmp_root, tmp_dir) = self.create_tmp_dir(class_id)?;
        class.write_to_file(concat_deprecated_executable_filename(&tmp_dir))?;

        self.rename_to_persistent_dir(tmp_dir, class_id)
    }

    /// Atomically moves the staged class directory `tmp_dir` into its content-addressed persistent
    /// directory.
    ///
    /// Recovers from a previous partial write: a crash between this rename and committing the
    /// existence marker (see `FsClassStorage::set_class`) can leave an orphaned, non-empty
    /// persistent directory. `std::fs::rename` refuses to replace a non-empty directory and fails
    /// with `ENOTEMPTY`, which permanently wedges sync on the class. Callers reach this only when
    /// the existence marker is absent, and the directory is named by the class hash, so an existing
    /// directory holds the same class; removing it lets the rename proceed and the marker get
    /// written, restoring filesystem/marker consistency.
    fn rename_to_persistent_dir(
        &self,
        tmp_dir: PathBuf,
        class_id: ClassId,
    ) -> FsClassStorageResult<()> {
        let persistent_dir = self.get_persistent_dir_with_create(class_id)?;
        if persistent_dir.exists() {
            warn!("Recovering orphaned class dir from a prior partial write: {persistent_dir:?}");
            std::fs::remove_dir_all(&persistent_dir)?;
        }
        std::fs::rename(tmp_dir, persistent_dir)?;

        Ok(())
    }
}

impl ClassStorage for FsClassStorage {
    type Error = FsClassStorageError;

    #[instrument(skip(self, class, executable_class), level = "debug", ret, err)]
    fn set_class(
        &mut self,
        class_id: ClassId,
        class: RawClass,
        executable_class_hash_v2: ExecutableClassHash,
        executable_class: RawExecutableClass,
    ) -> Result<(), Self::Error> {
        if self.contains_class(class_id)? {
            return Ok(());
        }

        self.write_class_atomically(class_id, class, executable_class)?;
        self.mark_class_id_as_existent(class_id, executable_class_hash_v2)?;

        Ok(())
    }
