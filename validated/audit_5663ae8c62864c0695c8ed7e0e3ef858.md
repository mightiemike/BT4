## Title
Missing declared-class validation in the Starknet OS's `execute_replace_class` allows Sierra re-execution divergence from the blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The blockifier's native (Rust) implementation of the `ReplaceClass` syscall requires that the target `class_hash` be a previously declared class before allowing a contract to replace its own class hash. The Starknet OS Cairo implementation of the same syscall, used for proving/re-executing the block, does **not** perform this check — the code contains an explicit `TODO` acknowledging the missing validation.

### Finding Description
In the blockifier's syscall handler, `replace_class` explicitly verifies the class is declared before mutating state: [1](#0-0) 

The equivalent Cairo implementation used by the Starknet OS for the current (non-deprecated) syscall path does not perform this check, and the missing check is explicitly flagged with a TODO comment: [2](#0-1) 

Specifically, line 902 states `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` before proceeding to unconditionally overwrite the contract's `class_hash` in `contract_state_changes`. This function is reachable from any contract executing the `replace_class_syscall` (as exercised in feature-contract tests), which any unprivileged transaction sender can trigger by invoking a contract that calls this syscall: [3](#0-2) 

The deprecated (Cairo0) OS syscall path has the same gap (no declared-class check at all): [4](#0-3) 

### Impact Explanation
This is a "missing authorization/validation" bug class analogous to the referenced Mattermost advisory (an operation is permitted without the check that should gate it). In the sequencer's architecture, the blockifier (used for live block building/consensus) rejects a `replace_class` call to an undeclared class hash with a `StateError`, while the Starknet OS (used for Cairo-program based re-execution/proving of the same block) would accept it and commit the corresponding state change without validating that the class actually exists. This creates a discrepancy between the two execution engines for identical transaction input, i.e., a case where the OS's committed state (state root reachable through `contract_state_changes` and eventually the Patricia tree commitment in `crates/apollo_starknet_os_program/.../state/commitment.cairo`) can diverge from the blockifier-computed state, or allow a contract to point to a class hash that was never declared. Such state/proof divergence between the sequencer's execution and the OS's re-execution/proof can lead to wrong committed state roots or proof failures, undermining the network's ability to confirm blocks consistently.

### Likelihood Explanation
Any account/contract can trigger `replace_class_syscall` with an arbitrary, undeclared class hash via a normal invoke transaction — no special privileges are required, as demonstrated by the standard feature-contract test path. The condition is trivially reachable by a single transaction sender.

### Recommendation
Add the missing check in `execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo` (and confirm equivalent enforcement in the deprecated syscalls path) to verify that the target `class_hash` is present in `contract_class_changes`/declared classes before permitting the state update, mirroring the blockifier's `get_compiled_class` check in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`.

### Proof of Concept
1. Deploy/declare a contract exposing `replace_class_syscall` (e.g., the `test_contract.cairo` feature contract).
2. Submit an invoke transaction calling `replace_class_syscall` with a `class_hash` that has never been declared.
3. Observe that blockifier execution fails (`StateError::UndeclaredClassHash`), while the Starknet OS's `execute_replace_class` (syscall_impls.cairo) would apply the state update without erroring, since the declared-class check is absent (see the TODO at line 902).

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
