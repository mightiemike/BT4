### Title
Unhandled `TypeError` thrown by `sanitizeHost` when a crafted base64 `host` param decodes to characters invalid in a URL host - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost` validates the `host` parameter only with a loose base64 charset regex before feeding the decoded bytes straight into `new URL()`, with no `try/catch`. An unprivileged attacker can supply a `host` value that is valid base64 (passing the regex) but decodes into bytes/characters that the WHATWG `URL` parser rejects (e.g. control characters), causing `new URL()` to throw an uncaught `TypeError` that propagates out of `sanitizeHost` into any caller (e.g. `validateShopAndHostParams` in the Remix/React Router packages, or `redirect-to-auth.ts` in shopify-app-express) that invokes it directly.

### Finding Description
`sanitizeHost` first checks the raw `host` string against `/^[0-9a-zA-Z+/]+={0,2}$/` [1](#0-0) , but this only validates the base64 *alphabet*, not the decoded content. It then immediately calls `new URL(`https://${decodeHost(sanitizedHost)}`)` with no surrounding `try/catch` [2](#0-1) . `decodeHost` is a thin wrapper around `atob` [3](#0-2) .

Because the base64 alphabet has no structural correlation to what makes a valid URL hostname, an attacker can choose base64 input (e.g. `Buffer.from('\x00\x01\x02').toString('base64')` → `"AAEC"`) that passes the regex but decodes to raw control characters. When concatenated into `https://\x00\x01\x02`, the WHATWG URL parser throws `TypeError: Invalid URL`, which is not caught anywhere in `sanitizeHost`.

Several call sites invoke `api.utils.sanitizeHost(...)` directly on request-derived, attacker-controlled query parameters without wrapping the call in a try/catch: `validateShopAndHostParams` (used in the `authenticate.admin` flow for shopify-app-remix and shopify-app-react-router) [4](#0-3)  and `redirectToAuth`'s `clientSideRedirect` in shopify-app-express [5](#0-4) . If the framework/runtime doesn't already have a catch-all error boundary around the request, this results in an unhandled exception for that single request. The existing unit tests for `sanitizeHost` only exercise well-formed ASCII "host-like" strings, not control-byte or otherwise URL-hostile decoded payloads [6](#0-5) , so this gap is not covered.

### Impact Explanation
Scoped impact is a per-request denial of service / crash (uncaught exception → 500, or process crash if the host runtime has no global error handler) triggerable by a single anonymous HTTP request with a crafted `host` query parameter, with no authentication, secret, or prior session required. This matches a DoS-in-auth-handler impact class rather than data compromise — it does not by itself allow session forgery, token theft, or cross-tenant access.

### Likelihood Explanation
Trivial to trigger: attacker only needs to send a GET request to any embedded-app authenticate/login route with `?host=AAEC` (or similar base64-encoded control-byte payload) and no shop/session state is needed. It is fully repeatable and requires no privileges.

### Recommendation
Wrap the `new URL(...)` construction (and ideally the `atob` call) in `sanitizeHost` in a `try/catch`, returning/throwing `InvalidHostError`/`null` on failure just as is done for other invalid-host cases, rather than letting the underlying `TypeError` propagate.

### Proof of Concept
```ts
import {shopifyApi} from '../..';
import {testConfig} from '../../__tests__/test-config';

test('sanitizeHost should not throw on malformed decoded host', () => {
  const shopify = shopifyApi(testConfig());
  const maliciousHost = Buffer.from('\x00\x01\x02').toString('base64'); // "AAEC"

  // Currently throws TypeError: Invalid URL instead of returning null
  expect(() => shopify.utils.sanitizeHost(maliciousHost)).not.toThrow();
  expect(shopify.utils.sanitizeHost(maliciousHost)).toBeNull();
});
```
Equivalent HTTP PoC: `GET /auth?shop=test.myshopify.com&host=AAEC` against a Remix/React Router app using `authenticate.admin`, which calls `validateShopAndHostParams` → `sanitizeHost('AAEC')` and throws unhandled.
