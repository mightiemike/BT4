## Answer

**No vulnerability found for this question.**

### Analysis

The equality claimed to be the "only link" (`VRFSeed::from_proof(proof_of_last_tenure-START_block) == new_seed_of_next_tenure-start's block-commit`, checked via `validate_vrf_seed`/`check_block_commit_vrf_seed` gated by `is_new_tenure`) is real: `NakamotoChainState::append_block` only calls `check_block_commit_vrf_seed` when `is_new_tenure` is true [1](#0-0) , and `check_normal_coinbase_tx` is a no-op when there is no coinbase, i.e. for tenure-extend blocks [2](#0-1) .

However, VRF-seed continuity is not the only guard on tenure-extend blocks, and the specific attack the question proposes — inserting a forged tenure-extend block "signed by a different miner" — is independently blocked by two other checks that are applied to *every* block, extend or not:

1. **`check_miner_signature`**: `validate_normal_nakamoto_block_burnchain` derives `miner_pubkey_hash160` from the *leader key of the block-commit that won the sortition for the block's own consensus hash* (looked up via `get_leader_key_at` on the block-commit tied to that specific consensus hash), then calls `check_miner_signature` against that hash [3](#0-2) . Since a tenure-extend block must carry the *same* `consensus_hash` as its parent tenure-start block (enforced by `is_wellformed_tenure_extend_block` and `check_tenure_tx`) [4](#0-3) [5](#0-4) , the required signer hash160 is fixed to the *legitimate* tenure's registered leader key. `check_miner_signature` recovers the actual signer from the block's ECDSA signature and rejects any mismatch [6](#0-5) . A forged extend block "signed by a different miner" fails this check unless the attacker holds the legitimate miner's private signing key — which is explicitly out of scope for an unprivileged attacker.

2. **`check_tenure_continuity`**: this requires that the block's parent be the *current highest-known ongoing tenure* with a matching `tenure_id_consensus_hash`, not merely any historical tenure with a matching consensus hash [7](#0-6) . This prevents splicing an extend block in between two already-finalized, VRF-chained tenure-start blocks after the fact — the extend block must be built directly on the then-current tip, so inserting it "between" two legitimate tenures requires it to fork the chain at that point, which then requires it to win canonical-fork selection on top of the existing burn-weight-backed chain (an economic/majority concern, out of scope).

Both checks were explicitly validated against forged/altered `tenure_consensus_hash`/`prev_tenure_consensus_hash` fields in the existing test suite [8](#0-7)  and continuity-mismatch cases [9](#0-8) , confirming the guards function as described.

Since the attacker cannot produce a valid signature over the forged extend block without the legitimate miner's private key, and cannot splice the block into an already-canonical position without a majority-stake reorg, the scoped Critical/High impact (chain split, invalid block accepted network-wide) does not materialize. The VRF-seed-only-at-coinbase gating is real but does not create an exploitable gap because signature and continuity checks independently cover tenure-extend blocks.

    /// Verify that if this block has a coinbase, that its VRF proof is consistent with the leader
    /// public key's VRF key. If there is no coinbase tx, then this is a no-op.
    fn check_normal_coinbase_tx(
        &self,
        leader_vrf_key: &VRFPublicKey,
        sortition_hash: &SortitionHash,
    ) -> Result<(), ChainstateError> {
        assert!(!self.is_shadow_block());

        // If this block has a coinbase, then verify that its VRF proof was generated by this
        // block's miner.  We'll verify that the seed of this block-commit was generated from the
        // parnet tenure's VRF proof via the `validate_vrf_seed()` method, which requires that we
        // already have the parent block.
        if let Some(coinbase_tx) = self.get_coinbase_tx() {
            let (_, _, vrf_proof_opt) = coinbase_tx
                .try_as_coinbase()
                .expect("FATAL: `get_coinbase_tx()` did not return a coinbase");

            let vrf_proof = vrf_proof_opt.ok_or(ChainstateError::InvalidStacksBlock(
                "Nakamoto coinbase must have a VRF proof".into(),
            ))?;

            // this block's VRF proof must have been generated from the last sortition's sortition
            // hash (which includes the last commit's VRF seed)
            let valid = match VRF::verify(leader_vrf_key, vrf_proof, sortition_hash.as_bytes()) {
                Ok(v) => v,
                Err(e) => {
                    warn!(
                        "Invalid Stacks block header {}: failed to verify VRF proof: {}",
                        self.header.block_hash(),
                        e
                    );
                    false
                }
            };

            if !valid {
                warn!("Invalid Nakamoto block: leader VRF key did not produce a valid proof";
                    "consensus_hash" => %self.header.consensus_hash,
                    "stacks_block_hash" => %self.header.block_hash(),
                    "stacks_block_id" => %self.header.block_id(),
                    "leader_public_key" => %leader_vrf_key.to_hex(),
                    "sortition_hash" => %sortition_hash
                );
                return Err(ChainstateError::InvalidStacksBlock(
                    "Invalid Nakamoto block: leader VRF key did not produce a valid proof".into(),
                ));
            }
        }
        Ok(())
    }

    pub(crate) fn check_tenure_continuity<SDBI: StacksDBIndexed>(
        headers_conn: &mut SDBI,
        parent_ch: &ConsensusHash,
        block_header: &NakamotoBlockHeader,
    ) -> Result<bool, ChainstateError> {
        // block must have the same consensus hash as its parent
        if block_header.is_first_mined() || parent_ch != &block_header.consensus_hash {
            test_debug!("Block is discontinuous with tenure: either first-mined or has a different tenure ID";
                        "parent_ch" => %parent_ch,
                        "block_header.consensus_hash" => %block_header.consensus_hash,
                        "is_first_mined()" => block_header.is_first_mined(),
            );
            return Ok(false);
        }

        // block must be in the same tenure as the highest-processed tenure.
        let Some(highest_tenure) =
            Self::get_ongoing_tenure(headers_conn, &block_header.parent_block_id)?
        else {
            // no tenures yet, so definitely not continuous
            test_debug!("Block is discontinuous with tenure: no ongoing tenure";
                        "block_header.parent_block_id" => %block_header.parent_block_id,
            );
            return Ok(false);
        };

        if &highest_tenure.tenure_id_consensus_hash != parent_ch {
            // this block is not in the highest-known tenure, so it can't be continuous
            test_debug!("Block is discontinuous with tenure: parent is not in current tenure";
                        "parent_ch" => %parent_ch,
                        "highest_tenure.tenure_id_consensus_hash" => %highest_tenure.tenure_id_consensus_hash,
            );
            return Ok(false);
        }

        Ok(true)
    }
