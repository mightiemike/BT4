## Analysis

`determineEventType` and `processSignatureBatch` in `universalClient/chains/svm/event_listener.go` classify inbound SVM gateway events purely by scanning **every** log line of any transaction that merely references the gateway address, without verifying which program actually emitted a given `Program data:` line. [1](#0-0) 

`processSignatureBatch` fetches the full transaction via `GetTransaction`, then iterates `tx.Meta.LogMessages` unconditionally, calling `determineEventType` on every log line in the transaction: [2](#0-1) 

`determineEventType` itself only checks the `"Program data: "` string prefix and matches the first 8 decoded bytes against a discriminator table; it has no notion of *which program* emitted the log: [3](#0-2) 

Transactions are selected via `GetSignaturesForAddress(ctx, gatewayAddr, beforeSig)` in `processSlotRange`, which is Solana's standard "any account referenced in the tx" filter — the gateway address does not need to be the *invoked* program, only present somewhere in the account list of some instruction: [4](#0-3) 

Because Solana log messages are a flat, ordered list on the transaction and the listener does not track the `Program <id> invoke [depth]` / `Program <id> success` boundaries to attribute a `Program data:` line to the actual gateway program invocation, any other program included in the same transaction (fully attacker-controlled, e.g. the attacker's own deployed program) can emit a `sol_log_data`/`emit!` log with the exact 8-byte discriminator matching `send_funds` (Anchor discriminators are deterministic and public), followed by an attacker-chosen 32-byte `sender`, 20-byte `recipient`, 32-byte `bridge_token`, `bridge_amount`, arbitrary `payload`, and revert fields — exactly the layout `decodeUniversalTxEvent`/`parseSendFundsEvent` expect: [5](#0-4) 

This forged log is real, deterministic, on-chain data — every honest Universal Validator's stock `universalClient` will independently derive the identical fabricated `send_funds` event when scanning the same transaction, because the bug is in the shared client code, not in any validator's behavior. That satisfies "honest-validator" convergence: the ballot/voting layer (`VoteInbound` → `VoteOnInboundBallot` → 2/3+ quorum → `UniversalTx` creation with PRC20 mint/payload execution) works exactly as designed once fed the forged observation. ### Title
Unauthenticated `Program data:` log scanning lets an attacker forge SVM gateway `send_funds` events without invoking the gateway program - (File: universalClient/chains/svm/event_listener.go)

### Summary
`determineEventType`/`processSignatureBatch` classify inbound gateway events by scanning all log lines of any transaction that merely *references* the gateway address (per `GetSignaturesForAddress` semantics), matching solely on an 8-byte discriminator prefix inside a `"Program data: "` log line. There is no check that the log line was emitted from within the gateway program's own CPI invocation frame. Anchor event discriminators are deterministic/public, so an attacker can deploy their own trivial program, invoke it in the same transaction that references the gateway address account (as a harmless, non-executed account reference), and have that attacker program emit a `sol_log_data` line with the `send_funds` discriminator followed by fully attacker-chosen `sender`, `recipient`, `bridge_token`, `bridge_amount`, `payload`, and revert fields matching the exact Borsh layout `decodeUniversalTxEvent` expects.

### Finding Description
Because log attribution to the emitting program is not enforced, the event listener cannot distinguish a genuine gateway-emitted event from an attacker-fabricated log line placed anywhere in a transaction that superficially "touches" the gateway address. This is real, deterministic on-chain data, so every honest Universal Validator running the stock `universalClient` binary derives the same forged `send_funds` event, votes it via `MsgVoteInbound`, and — once 2/3+ quorum is reached — the core validator executes it: minting PRC20 to the attacker-chosen recipient/UEA and running the attacker-chosen payload, with none of it backed by an actual token deposit/lock on Solana.

### Impact Explanation
This allows an unprivileged external attacker to mint PRC20 tokens (or trigger gas top-ups / payload execution) on Push Chain out of thin air, without ever calling the real gateway `send_funds` instruction or transferring any real asset on Solana — a direct unauthorized-mint / fund-creation vulnerability.

### Likelihood Explanation
High: it requires only a single self-deployed Solana program and one transaction; no validator, relayer, or admin compromise is needed. The forged event is deterministically reproduced by every honest node running the current client code.

### Recommendation
Bind `Program data:` log extraction to the actual invoking program by tracking `Program <id> invoke [depth]` / `Program <id> success|failed` boundaries in `tx.Meta.LogMessages` and only accepting `Program data:` lines that fall within the gateway program's own invocation frame (matching `el.gatewayAddress`), rather than scanning the flat log list unconditionally.

### Proof of Concept
1. Deploy an attacker-controlled Solana program `Evil` that, when invoked, calls `sol_log_data(discriminator || fake_sender || fake_recipient || fake_token || fake_amount || payload_len || payload || revert_fields)` using the publicly known `send_funds` discriminator.
2. Submit one transaction containing: (a) an instruction invoking `Evil` with the crafted log, and (b) any instruction that lists the gateway program's address as an account (satisfying `GetSignaturesForAddress(gatewayAddr, ...)`), without actually invoking the gateway's `send_funds` instruction.
3. Every UV's `EventListener.processSignatureBatch` fetches this transaction, iterates all `LogMessages`, and `determineEventType` matches the discriminator, producing a fabricated inbound `send_funds` event with attacker-chosen recipient/amount/payload.
4. UVs vote `MsgVoteInbound`; quorum passes; `x/uexecutor` mints PRC20 to the attacker's chosen recipient and/or executes the attacker's payload — with no corresponding real value locked on Solana.

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

func decodeUniversalTxEvent(data []byte, logger zerolog.Logger) (*common.UniversalTx, error) {
	if len(data) < 120 {
		logger.Warn().
			Int("data_len", len(data)).
			Msg("data might be too short for complete TxWithFunds event")
	}

	offset := 8
	payload := &common.UniversalTx{}

	// Parse sender (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for sender")
	}
	sender := solana.PublicKey(data[offset : offset+32])
	// Convert sender to hex format
	senderHex, err := base58ToHex(sender.String())
	if err != nil {
		logger.Warn().Err(err).Msg("failed to convert sender to hex, using base58")
		payload.Sender = sender.String()
	} else {
		payload.Sender = senderHex
	}
	offset += 32

	// Parse recipient (20 bytes - byte20 format)
	if len(data) < offset+20 {
		return nil, fmt.Errorf("not enough data for recipient")
	}
	// Convert 20 bytes to hex string (0x + 40 hex chars)
	recipientBytes := data[offset : offset+20]
	payload.Recipient = "0x" + hex.EncodeToString(recipientBytes)
	offset += 20

	// Parse bridge_token (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for bridge_token")
	}
	bridgeToken := solana.PublicKey(data[offset : offset+32])
	payload.Token = bridgeToken.String()
	offset += 32

	// Parse bridge_amount (8 bytes)
	if len(data) < offset+8 {
		return nil, fmt.Errorf("not enough data for bridge_amount")
	}
	bridgeAmount := binary.LittleEndian.Uint64(data[offset : offset+8])
	payload.Amount = fmt.Sprintf("%d", bridgeAmount)
	offset += 8

func (k Keeper) VoteOnInboundBallot(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	inbound types.Inbound,
) (isFinalized bool,
	isNew bool,
	err error) {
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return false, false, err
	}

	universalValidatorSet, err := k.uvalidatorKeeper.GetEligibleVoters(ctx)
	if err != nil {
		return false, false, err
	}

	// number of validators
	totalValidators := len(universalValidatorSet)

	// votesNeeded = ceil(2/3 * totalValidators)
	// >2/3 quorum similar to tendermint
	votesNeeded := (types.VotesThresholdNumerator*totalValidators)/types.VotesThresholdDenominator + 1

	k.Logger().Debug("voting on inbound ballot",
		"ballot_key", ballotKey,
		"validator", universalValidator.String(),
		"total_validators", totalValidators,
		"votes_needed", votesNeeded,
	)

	// Convert []sdk.ValAddress → []string
	universalValidatorSetStrs := make([]string, len(universalValidatorSet))
	for i, v := range universalValidatorSet {
		universalValidatorSetStrs[i] = v.IdentifyInfo.CoreValidatorAddress
	}

	// Step 2: Call VoteOnBallot for this inbound synthetic
	_, isFinalized, isNew, err = k.uvalidatorKeeper.VoteOnBallot(
		ctx,
		ballotKey,
		uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
		universalValidator.String(),
		uvalidatortypes.VoteResult_VOTE_RESULT_SUCCESS,
		universalValidatorSetStrs,
		int64(votesNeeded),
		int64(types.DefaultExpiryAfterBlocks),
	)
	if err != nil {
		return false, false, err
	}

	if isNew {
		k.Logger().Debug("inbound ballot created", "ballot_key", ballotKey)
	}
	if isFinalized {
		k.Logger().Info("inbound ballot finalized", "ballot_key", ballotKey, "source_chain", inbound.SourceChain)
	}

	return isFinalized, isNew, nil
