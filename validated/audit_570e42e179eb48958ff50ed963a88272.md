### Title
Signer global-state agreement threshold uses floor division while the Nakamoto block-approval threshold uses ceiling division, letting sub-70% weight be treated as consensus - (File: `libsigner/src/v0/signer_state.rs`)

### Summary
`GlobalStateEvaluator::reached_agreement`, which the signer set uses to decide when it has reached global consensus on the current miner, protocol version, and transaction-replay set, computes the 70% supermajority threshold with **floor** division. The chain-consensus-critical threshold used to actually accept a Nakamoto block's signatures, `NakamotoBlockHeader::compute_voting_weight_threshold`, computes the same nominal 70% with **ceiling** division. For any `total_weight` where `total_weight * 7` is not a multiple of 10, these two thresholds differ by exactly 1, so a vote weight that the signer network treats as "having reached agreement" can be strictly less than the weight actually required by the chain to approve a block. This is the same bug class as the reported Go `Root()`/Solidity `root()` divergence: two implementations of what should be an identical boundary check disagree at the boundary.

### Finding Description
The chain-consensus threshold is computed with an explicit ceiling adjustment: [1](#0-0) 

The signer-side "global agreement" threshold used for determining the canonical miner state, supported protocol version, and transaction-replay set uses plain floor division of the same nominal 70% constant, `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`: [2](#0-1) 

Both functions are built from the exact same constant (`NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD == 7`, i.e. 70%) but round differently:
- `compute_voting_weight_threshold`: `(total_weight * 7) / 10`, plus `+1` whenever there is a remainder (ceiling).
- `reached_agreement`: `vote_weight >= (total_weight * 7) / 10` (floor, no ceiling adjustment).

Example: `total_weight = 13`. `13 * 7 = 91`. `91 / 10 = 9` with remainder `1`.
- `compute_voting_weight_threshold(13) = 9 + 1 = 10` (≈76.9% of weight required).
- `reached_agreement` accepts any `vote_weight >= 9` (≈69.2% of weight), i.e. one unit of weight *less* than what the chain requires to accept a Nakamoto block.

`reached_agreement` is the sole gate for `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which in turn determines the globally-agreed current miner and transaction-replay set): [3](#0-2) 

So whenever the signer set's total weight is not an exact multiple of 10 (the common case for any real-world weight distribution), a coalition holding strictly less than the true 70% supermajority required by the node-side `verify_signer_signatures`/`compute_voting_weight_threshold` check can nonetheless be recognized by every signer as having reached "global agreement" on which miner is canonical or which transaction-replay set is in effect.

### Impact Explanation
This is a "signer weight below threshold" divergence: the off-chain signer coordination layer accepts a sub-quorum weight as sufficient for determining the canonical miner/tx-replay state, while the on-chain, consensus-critical acceptance of a block's signatures requires strictly more weight (`compute_voting_weight_threshold`, used by `NakamotoBlockHeader::verify_signer_signatures`). The two computations are meant to encode the same "70% supermajority" invariant, and their silent divergence at non-round totals means the signer network's notion of "consensus reached" is systematically looser than what the chain will actually accept. This can cause signers to commit to a "globally agreed" current miner or transaction-replay set backed by less real weight than the network's own signing threshold demands, producing state decisions (mining-key adoption, replay-set application) that are not backed by the same supermajority the chain itself enforces. Per the given severity bands this is a High-impact minority/near-minority weight divergence bounded to signer coordination and reward/mining-state agreement, not a full chain split, since block finality itself still goes through the correctly-computed `compute_voting_weight_threshold`.

### Likelihood Explanation
The divergence is deterministic and requires no attacker action beyond having a signer set whose total weight is not a multiple of 10 (true for essentially any real weight distribution, e.g. per-address integer weights). It is always latent whenever `total_weight * 7 mod 10 != 0`; no special adversarial input is needed to trigger the 1-unit gap, only a normal signer-weight configuration.

### Recommendation
- Short term: make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use the same ceiling-based rounding as `NakamotoBlockHeader::compute_voting_weight_threshold` (or, better, have both call a single shared threshold function) so that "global agreement" and "block approval" always require the identical minimum weight.
- Long term: consolidate the 70%/30% supermajority computation into one shared, well-tested helper used by both `stackslib` (chain consensus) and `libsigner` (signer coordination), and add property tests asserting `reached_agreement(w) == (w >= compute_voting_weight_threshold(total_weight))` for all `total_weight` in a wide range, to catch any future rounding drift between the two implementations, mirroring the recommendation from the original report to add property testing across parallel implementations of the same boundary check.

### Proof of Concept
1. Configure a signer set with `total_weight = 13` (e.g., 13 signers of weight 1 each, or any other weight assignment summing to 13).
2. Have signers whose combined weight is exactly `9` submit matching `StateMachineUpdate`s (e.g. agreeing on the same `current_miner`/`tx_replay_set`).
3. `GlobalStateEvaluator::reached_agreement(9)` evaluates `9 >= (13*7)/10 = 9` → `true`: the signer network treats this as globally agreed state, per: [4](#0-3) 
4. Meanwhile `NakamotoBlockHeader::compute_voting_weight_threshold(13)` returns `10` (ceiling of `91/10`), so a block signed by only weight `9` would be rejected by `verify_signer_signatures`: [5](#0-4) 
5. This demonstrates the two "70% supermajority" checks disagree by one unit of weight for `total_weight = 13`, and analogous gaps recur for any `total_weight` where `total_weight * 7 mod 10 != 0`.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
