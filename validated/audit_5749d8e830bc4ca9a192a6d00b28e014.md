Based on my research, I found a solid analog to the H-3 pattern in Push Chain's gas refund path.

## Analysis

The H-3 report's core pattern is: **value legitimately owed to a party accrues in a system, but the code path meant to release/claim it can fail, and there's no mechanism to retry or reclaim it — resulting in permanent loss.**

In Push Chain, the `applyGasRefund` function in [1](#0-0)  computes excess gas (`gasFee - gasFeeUsed`) owed back to a user after outbound execution, and attempts two paths to deliver it: a swap-based refund via `CallUniversalCoreRefundUnusedGas(..., withSwap=true, ...)`, falling back to a non-swap direct PRC20 deposit if the swap path fails.

Critically, if **both** the swap and no-swap `CallUniversalCoreRefundUnusedGas` calls fail (e.g., `UniversalCore` reverts due to insufficient liquidity, PRC20 mint/deposit failure, or any transient EVM error), the code does: [2](#0-1) 
```go
resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
if err != nil {
    refundPcTx.Status = "FAILED"
    refundPcTx.ErrorMsg = err.Error()
} else {
    ...
}
outbound.PcRefundExecution = refundPcTx
outbound.RefundSwapError = swapFallbackReason
```

`FinalizeOutbound` — the only caller of `applyGasRefund` — runs exactly once, triggered from outbound-vote ballot finalization [3](#0-2) . After this single attempt, the outbound record is simply persisted with `PcRefundExecution.Status = "FAILED"` via `UpdateOutbound`. I found no message handler, retry endpoint, or scheduled job anywhere in the codebase (`grep` for `Retry`/`MsgRetry` returned nothing) that re-attempts a failed refund. The excess gas amount that was already deducted from the user on the external chain (and is owed back per protocol accounting) is recorded as un-refunded with no further code path to reclaim it — it is permanently stuck/lost from the user's perspective, matching the "yield/value accrues but can never be claimed" bug class.

This differs from the analogous bridged-funds revert path (`handleFailedOutbound`'s `CallPRC20Deposit`), which explicitly calls `k.AbortOutbound(...)` with `Status_ABORTED` for manual intervention on failure [4](#0-3)  — i.e., the protocol *does* have a recognized "needs manual recovery" pattern elsewhere, but `applyGasRefund` does not use it; it just silently records `FAILED` and moves on.

### Title
Permanently unclaimable excess gas refund on outbound finalization — (File: x/uexecutor/keeper/outbound.go)

### Summary
`applyGasRefund`, invoked once per outbound from `FinalizeOutbound`, computes an excess-gas amount owed to the user and attempts to deliver it via `CallUniversalCoreRefundUnusedGas` (swap path, then no-swap fallback). If both EVM calls fail, the function records `PcRefundExecution.Status = "FAILED"` and returns without aborting the outbound or scheduling retry. No other code path (message handler, keeper function, or scheduled job) re-attempts this refund, so the excess gas amount becomes permanently unrecoverable within protocol accounting.

### Finding Description
`FinalizeOutbound` calls `handleSuccessfulOutbound`/`handleFailedOutbound`, both of which call `applyGasRefund` exactly once [5](#0-4) . Inside `applyGasRefund`, when `gasFee > gasFeeUsed`, the refund amount is computed and two on-chain calls are attempted in sequence — a swap-based refund and (only if that call errors) a no-swap fallback [6](#0-5) . If the fallback call also errors (e.g., `UniversalCore.refundUnusedGas` reverts due to PRC20 mint failure, gas token misconfiguration, or any transient state), the function sets `refundPcTx.Status = "FAILED"` and stores it on `outbound.PcRefundExecution`, then returns normally via `UpdateOutbound`. Unlike the bridged-funds revert path, which calls `AbortOutbound` (a distinct, explicitly-recoverable admin state) on failure, the gas-refund failure path leaves the outbound in its normal terminal status (`OBSERVED`/`REVERTED`) with no flag indicating manual intervention is required, and with no keeper method or message type anywhere in the repository to retry the refund call.

### Impact Explanation
This causes a legitimate accounting loss: gas fees the user overpaid (already deducted from them on the external/destination chain) are computed as owed back but never delivered, and the protocol has no path to correct this after the single attempt fails. This falls within the "permanent loss of protocol/user-controlled funds" and "corruption of gas fee accounting / refund accounting" impact categories.

### Likelihood Explanation
Triggerable purely by ordinary usage: any external-chain transaction where the actual gas consumed is less than the pre-charged `gasFee` (a normal, expected occurrence for outbound execution) combined with a transient failure of the on-chain `UniversalCore.refundUnusedGas` call (e.g., swap liquidity unavailable, PRC20 balance/allowance issue, EVM gas estimation edge case). No privileged actor or malicious validator is required — an honest validator quorum finalizing the outbound is sufficient to reach this code path.

### Recommendation
On failure of both refund attempts, either (a) mark the outbound with an explicit recoverable/aborted-style status distinct from normal terminal states, and add a keeper method/message (e.g., `MsgRetryGasRefund`) that permissionless or admin actors can call to re-attempt `CallUniversalCoreRefundUnusedGas` using the already-recorded `refundAmount`/`gasToken`/`recipient`, or (b) escrow/hold the refund amount in a queryable pending-refunds store keyed by outbound ID so it can be swept later, rather than only recording a terminal `FAILED` string with no follow-up mechanism.

### Proof of Concept
1. Set up an outbound whose `GasFee` (e.g., 111) exceeds the observed `GasFeeUsed` (e.g., 50), as in the existing test `TestGasFeeRefund/refund execution recorded when gasFee exceeds gasFeeUsed` [7](#0-6) .
2. Force `CallUniversalCoreRefundUnusedGas` to fail on both the swap and no-swap paths (e.g., mock `UniversalCore` to always revert `refundUnusedGas`, or set an invalid `gasToken`/insufficient PRC20 liquidity).
3. Observe that `applyGasRefund` sets `outbound.PcRefundExecution.Status = "FAILED"` and `outbound.RefundSwapError` is populated, but `outbound.OutboundStatus` remains a normal terminal value (`OBSERVED`/`REVERTED`), not `ABORTED`.
4. Confirm there is no subsequent message type or keeper call anywhere in `x/uexecutor` capable of re-invoking `applyGasRefund`/`CallUniversalCoreRefundUnusedGas` for this outbound — the excess gas amount is permanently unrecoverable in protocol state.

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
