### Title
Below-threshold signer's stale reward-per-token snapshot leaks STX-only rewards to stakers of a signer that never entered the reward set - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
`pox-5.clar` tracks whether a signer has crossed `SIGNER_SET_MIN_USTX` for a reward cycle via `add-staker-to-signer-cycles`, which only calls `add-signer-to-set-for-cycle` and updates `total-shares-staked-for-cycle` when the signer's cumulative delegated amount first crosses the threshold [1](#0-0) . A signer whose aggregate stake never crosses `SIGNER_SET_MIN_USTX` is never added to the reward set for that cycle and should have zero shares/earnings. A regression test in the mitigation/companion test suite demonstrates that a "settle-rewards" style claim path can still advance a below-threshold signer's global reward-per-token snapshot for a cycle it never contributed to, letting one of its stakers (Alice, staked via `signer1`, which stays below `SIGNER_SET_MIN_USTX`) collect STX-only rewards for a cycle her signer was never a member of [2](#0-1) .

### Finding Description
The equality being broken is: *a staker's claimable reward for cycle N must equal zero when their signer's shares-staked-for-cycle N is zero (i.e., the signer never crossed `SIGNER_SET_MIN_USTX` and was never added via `add-signer-to-set-for-cycle`)*. The test explicitly sets up a scenario where `signer1`'s combined bond + STX-only stake stays under `SIGNER_SET_MIN_USTX` for cycle 1, and confirms via `isSignerInCycle` / `getSignerSharesStakedForCycle` that `signer1` has zero shares and is not a cycle-1 member [3](#0-2) . A second, independently-above-threshold signer (`signer2`) is used purely to advance the *global* STX-only rewards-per-token accumulator for cycle 1 so that the bug isn't masked by an all-zero global rate [4](#0-3) . Triggering a bond claim on `signer1` (`claimRewards`) runs the settle-rewards code path on `signer1`'s STX-only cycle-1 bucket even though `shares == 0`, and this corrupts the stored `signer-rewards-per-token-for-cycle` snapshot by advancing it past the window during which `signer1` earned nothing. Because `getEarnedStakerRewards` for `alice` (a staker delegated to `signer1`) is computed against this corrupted snapshot, she is credited nonzero rewards for a cycle her signer never contributed to [5](#0-4) .

The root cause is that the settle/claim logic does not gate the reward-per-token snapshot update on the signer actually having nonzero `shares-staked-for-cycle` (equivalently, on the signer having crossed the `SIGNER_SET_MIN_USTX` threshold recorded by `add-staker-to-signer-cycles`) [1](#0-0) . Any staker attached to any below-threshold signer can independently trigger the claim path to desynchronize their own snapshot, causing the contract to compute a positive earned amount out of thin air.

### Impact Explanation
This causes STX-only stakers on a signer that never met the minimum threshold (and thus never entered the on-chain reward set / never contributed real burn-weight or signing capacity) to receive rewards that should have flowed only to signers/stakers who were actually part of the reward set. This is a reward mis-payment bounded to the STX-only reward pool for the affected cycle — funds that were earned by legitimate (threshold-crossing) signers' stakers are instead diverted to a staker of an ineligible signer. This matches a "High" impact class: a minority-triggerable reward mis-payment bounded to a specific fee/reward pool, without requiring node-operator or admin privileges.

### Likelihood Explanation
Any single staker can set this up unilaterally and unprivileged: stake just under `SIGNER_SET_MIN_USTX` to a signer, wait for another (unrelated) signer's activity to advance the global STX-only reward-per-token rate, and then trigger any claim/settle call touching the under-threshold signer's cycle bucket. The test needs no majority or colluding validators — it's triggered entirely by the reporting user's own transactions (`registerForBond`, `stake`, `claimRewards`) [6](#0-5) , making this minority/single-actor triggerable.

### Recommendation
In the settle/claim code path that updates `signer-rewards-per-token-for-cycle` (or equivalent snapshot state) for a signer/cycle bucket, skip advancing the snapshot when the signer's `shares-staked-for-cycle` for that reward cycle is zero, mirroring the same threshold gate already enforced in `add-staker-to-signer-cycles` (only signers whose delegated stake reaches `SIGNER_SET_MIN_USTX` should ever have their per-cycle reward snapshot mutated) [1](#0-0) . Additionally, `getEarnedStakerRewards` should verify the signer was a registered member of the cycle's reward set (`isSignerInCycle`) before crediting any STX-only earnings, rather than relying solely on the potentially-corrupted global rate snapshot.

### Proof of Concept
The existing regression test reproduces the issue end-to-end and should be used as the PoC: register `signer1` with a below-threshold bond staker (`bob`) plus a below-threshold STX-only staker (`alice`), register `signer2` with an above-threshold STX-only staker (`charlie`) to move the global rate, fund and settle rewards for cycle 1, then trigger `claimRewards` on `signer1`'s bond; the test asserts `alice`'s earned STX-only rewards must remain `0` post-claim, and documents that this assertion fails on the unfixed code [2](#0-1) .

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
