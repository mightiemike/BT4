### Title
Unsanitized `shop` query parameter used for OAuth begin/redirect after `sanitizeShop` validation result is discarded - ([File: packages/apps/shopify-app-remix/src/server/authenticate/admin/strategies/auth-code-flow.ts])

### Summary
In `AuthCodeFlowStrategy.ensureInstalledOnShop`, the shop parameter is validated via `validateShopAndHostParams` (which internally calls `api.utils.sanitizeShop`), but the sanitized/transformed return value is discarded. The code then re-reads the raw, unsanitized `shop` query parameter directly from the URL and uses that raw value for security-relevant operations (building OAuth `beginAuth` redirects, exit-iframe redirects, and offline session lookups).

### Finding Description
`validateShopAndHostParams` calls `api.utils.sanitizeShop(url.searchParams.get('shop')!)` purely to check `if (!shop) throw ...` — it never returns or propagates the sanitized value to its caller: [1](#0-0) 

Immediately after calling this validator, `ensureInstalledOnShop` re-reads the shop parameter directly from the raw URL instead of using the sanitized/transformed value, and this raw `shop` is then used to drive `redirectWithExitIframe`, `beginAuth`, and offline session id lookups: [2](#0-1) 

This is the same bug class as the referenced report: a value is validated/transformed by a dedicated function (`sanitizeShop`, analogous to the swap in `_deposit`), but the caller discards that transformed result and instead uses the original untransformed input for the subsequent security-sensitive operation (analogous to `_repay` using the pre-swap amount).

`sanitizeShop` is not a pure format check — when `config.domainTransformations` is configured, it can *rewrite* the shop domain (e.g., mapping a public/UI domain to an internal API domain) via `applyDomainTransformations`, and it also normalizes shop-admin URL format (`admin.<domain>/store/<name>`) into the legacy `<name>.<domain>` form via `shopAdminUrlToLegacyUrl`: [3](#0-2) 

Because `ensureInstalledOnShop` uses the raw, non-transformed `url.searchParams.get('shop')` value (line 120) instead of the validated/transformed result, any app configured with `domainTransformations` (a supported, documented feature) will build the OAuth `beginAuth` redirect URL, the exit-iframe redirect, and `getOfflineId` session lookups against the raw/untransformed shop domain rather than the domain that was actually validated. This mismatch means:
- The value that passed the security check (sanitizedShop) is not what is actually used to construct the OAuth begin URL / session id, defeating the purpose of validating it in the first place.
- If a shop-admin-URL style value (`admin.<domain>/store/<name>`) is supplied, sanitization would normalize it to `<name>.<domain>` for legitimate use, but the raw admin-URL-style string is instead passed on to `beginAuth`/`redirectWithExitIframe`/`getOfflineId`, producing an inconsistent/incorrect shop identity downstream from what was actually validated.

### Impact Explanation
The validated value and the value actually used for OAuth flow initiation and session lookup diverge. For apps that use `domainTransformations` (an officially supported config option intended precisely for domain remapping/security), the trust boundary check (`sanitizeShop`) becomes decorative because the transformed/normalized domain is dropped and the raw request-controlled domain string flows into `beginAuth` (which builds the `/admin/oauth/authorize` redirect and OAuth callback plumbing) and into `api.session.getOfflineId(shop)`. This can result in session id / OAuth flow being keyed off an unvalidated string, distinct from the shop value that was actually confirmed to satisfy the sanitization/transformation rules — a session-storage/OAuth-flow key mismatch stemming from unpiloted trust-boundary crossing of anonymous request input.

### Likelihood Explanation
This path is reachable by any anonymous document request to the app (no auth required) that omits the session-token header, since `ensureInstalledOnShop` is invoked directly from `respondToOAuthRequests` for non-session-token requests. It is triggered purely by supplying a crafted `shop` query parameter, requiring no privileged access. It manifests concretely only when `domainTransformations` or shop-admin-URL normalization is in play, which narrows real-world exposure to apps using that specific (documented) configuration feature.

### Recommendation
In `ensureInstalledOnShop` (and any other caller of `validateShopAndHostParams`), capture and reuse the sanitized shop value instead of re-reading the raw query parameter:
```ts
const shop = api.utils.sanitizeShop(url.searchParams.get('shop')!, true)!;
```
and pass this `shop` (not the raw `url.searchParams.get('shop')`) into `redirectWithExitIframe`, `beginAuth`, `getOfflineSessionId`/`getOfflineId`, and subsequent logic, mirroring the fix recommended in the referenced report of always using the post-transformation value for downstream security-critical operations rather than the original user input.

### Proof of Concept
Not independently reproducible from the index alone — verifying the end-to-end impact requires configuring `domainTransformations` and tracing a live request through `respondToOAuthRequests` → `ensureInstalledOnShop` → `beginAuth`/`getOfflineId` to confirm the raw vs. sanitized shop divergence at runtime. This would need a running instance/test harness (e.g., a Devin session) to construct and execute such a test, which is outside the scope of static code review here.

```typescript
export function validateShopAndHostParams(
  params: BasicParams,
  request: Request,

  const {api, config, logger} = params;

    const url = new URL(request.url);
    const shop = api.utils.sanitizeShop(url.searchParams.get('shop')!);
    if (!shop) {
      logger.debug('Missing or invalid shop, redirecting to login path', {
```

```typescript
  private async ensureInstalledOnShop(request: Request) {
    const {api, config, logger} = this;

    validateShopAndHostParams({api, config, logger}, request);

    const url = new URL(request.url);
    let shop = url.searchParams.get('shop');

    // Ensure app is installed
    logger.debug('Ensuring app is installed on shop', {shop});

    if (!(await this.hasValidOfflineId(request))) {
      logger.info("Could not find a shop, can't authenticate request");
      throw new Response(undefined, {
        status: 400,
        statusText: 'Bad Request',
      });
    }

    const offlineSession = await this.getOfflineSession(request);
    const isEmbedded = url.searchParams.get('embedded') === '1';

    if (!offlineSession) {
      logger.info("Shop hasn't installed app yet, redirecting to OAuth", {
        shop,
      });
      if (isEmbedded) {
        redirectWithExitIframe({api, config, logger}, request, shop!);
      } else {
        throw await beginAuth({api, config, logger}, request, false, shop!);
      }
    }

    shop = shop || offlineSession.shop;
```

```typescript
export function sanitizeShop(config: ConfigInterface) {
  return (shop: string, throwOnInvalid = false): string | null => {
    let shopUrl = shop;
    const domainsRegex = [
      'myshopify\\.com',
      'shopify\\.com',
      'myshopify\\.io',
      'shop\\.dev',
    ];

    // Add domains from transformations (both source and target)
    if (config.domainTransformations) {
      domainsRegex.push(...getTransformationDomains(config));
    }

    const shopUrlRegex = new RegExp(
      `^[a-zA-Z0-9][a-zA-Z0-9-_]*\\.(${domainsRegex.join('|')})[/]*$`,
    );

    const shopAdminRegex = new RegExp(
      `^admin\\.(${domainsRegex.join('|')})/store/([a-zA-Z0-9][a-zA-Z0-9-_]*)$`,
    );

    const isShopAdminUrl = shopAdminRegex.test(shopUrl);
    if (isShopAdminUrl) {
      shopUrl = shopAdminUrlToLegacyUrl(shopUrl) || '';
    }

    const sanitizedShop = shopUrlRegex.test(shopUrl) ? shopUrl : null;
    if (!sanitizedShop && throwOnInvalid) {
      throw new InvalidShopError('Received invalid shop argument');
    }

    if (sanitizedShop && config.domainTransformations) {
      return applyDomainTransformations(sanitizedShop, config);
    }

    return sanitizedShop;
  };
```
