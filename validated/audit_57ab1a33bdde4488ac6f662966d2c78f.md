### Title
Unchecked fee-transfer execution result allows a transaction to be accepted as fee-paid even when the ERC20 fee transfer call reverts internally - (File: `crates/blockifier/src/transaction/account_transaction.rs`)

### Summary
`AccountTransaction::execute_fee_transfer` builds a `CallEntryPoint` for the fee-token `transfer` entry point and invokes it with `CallEntryPoint::execute(...)`, not `CallEntryPoint::non_reverting_execute(...)`. [1](#0-0) 
`execute()` only returns an `Err` when the Cairo VM run itself errors out; if the called entry point runs to completion but internally reverts/panics (Cairo1 style), the call returns `Ok(CallInfo)` with `call_info.execution.failed == true`, and that flag is never inspected by the caller. [2](#0-1) 
The dedicated helper `non_reverting_execute` exists precisely to convert this "failed" flag into an `EntryPointExecutionError`, but `execute_fee_transfer` does not use it. [3](#0-2) 

### Finding Description
`handle_fee` calls `execute_fee_transfer` (or `concurrency_execute_fee_transfer`, which itself delegates to `execute_fee_transfer`) to run the ERC20 `transfer` entry point on the fee token contract, transferring `actual_fee` from the sender to the sequencer address. [4](#0-3) 
The result is simply mapped and returned as `Ok(Some(fee_transfer_call_info))` regardless of whether the transfer actually succeeded: [5](#0-4) 

Contrast this with the analogous "must-not-revert" call sites in the Starknet OS Cairo code, where the return data of a non-reverting call is explicitly checked (`assert retdata[0] = VALIDATED`) after invoking `non_reverting_select_execute_entry_point_func` for `__validate__`/`__validate_deploy__`/`__validate_declare__`: [6](#0-5) 
The OS's `charge_fee` function that performs the equivalent fee transfer similarly discards the return values of `non_reverting_select_execute_entry_point_func` without checking a "success" retdata value: [7](#0-6) 

For the production/system ERC20 fee-token contract implemented in Cairo0 (`ERC20.cairo`), failures materialize as VM-level `assert` failures, which do propagate as an `Err` from `.execute()` and are therefore caught. The gap specifically matters for a Cairo1-implemented `transfer`/`__execute__`/fee-token style entry point (or any inner code path reachable from the transfer entry point) that can *panic/revert* in the Sierra/Cairo1 sense — i.e., produce `PANIC` retdata and set `execution.failed = true` — without the outer Cairo-VM run itself erroring. In that case `execute_fee_transfer` returns `Ok(CallInfo{execution:{failed:true, ...}})`, `handle_fee` wraps it in `Ok(Some(...))`, and the calling transaction machinery (`run_non_revertible`/`run_revertible` paths) proceeds to treat the fee phase as completed rather than aborting or reverting the transaction, even though no state-changing balance transfer actually occurred (a revert/panic in Cairo1 discards the write-set of that call).

### Impact Explanation
If reachable (i.e., if the actual configured fee-token class or a nested call it makes can revert internally under attacker-controlled conditions rather than triggering a top-level `EntryPointExecutionError`), a transaction sender could have their fee "charged" from the accounting standpoint (the sequencer proceeds as if `actual_fee` was collected, includes the `fee_transfer_call_info` in the receipt, and finalizes/commits the transaction) without the sequencer's balance actually increasing. This is a fee-bypass / unauthorized value-transfer-skip: the sender obtains execution of their transaction while the network fails to collect real payment, a concrete loss of funds for the sequencer/network. All honest nodes execute the same deterministic logic, so this does not cause a chain fork by itself, but it is a systemic fee-collection failure reachable from an ordinary submitted transaction.

### Likelihood Explanation
Likelihood is constrained by whether the deployed fee-token contract (or a contract it delegates to) can, under some code path, revert in the Cairo1 "return failed flag without VM error" sense rather than via a hard assert. For the shipped Cairo0 `ERC20.cairo` used in tests/resources, this is unlikely since balance/allowance checks use `assert`, which manifests as a VM error and is caught by `.execute()`'s `Err` path. However, the blockifier is generic over the actual class deployed at the fee-token address, and any future or alternate (Cairo1) fee-token implementation, or upgrade path, that uses `panic!`/`Result::Err` conventions instead of raw asserts would immediately expose this gap, since nothing in `execute_fee_transfer` validates `call_info.execution.failed`. I could not fully confirm from the available index whether any additional post-processing (e.g., resource/state-diff reconciliation) elsewhere independently detects a no-op transfer; based on the code read, no such check exists in the `handle_fee`/`execute_fee_transfer` path.

### Recommendation
Use `CallEntryPoint::non_reverting_execute` (or explicitly check `call_info.execution.failed` and propagate a `TransactionFeeError`) in `execute_fee_transfer`, mirroring the pattern already used for `__validate__` calls and available via `non_reverting_execute` in `entry_point.rs`, so that any internally-reverted fee transfer is treated as a failure and the transaction is rejected/reverted rather than accepted as fee-paid.

### Proof of Concept
Conceptual PoC (cannot be executed without live test harness access):
1. Deploy a Cairo1 fee-token contract at the chain's configured fee-token address whose `transfer` entry point can be made to internally `panic!`/return `Result::Err` under some caller-controlled condition (e.g., a crafted calldata value) without triggering a VM-level `assert`/OOG error.
2. Submit an ordinary `INVOKE` transaction from an account whose balance is insufficient or that otherwise triggers the crafted revert condition in `transfer`.
3. Observe that `execute_fee_transfer` returns `Ok(CallInfo{execution:{failed:true,...}})` (line 588-590 above), `handle_fee` wraps it as `Ok(Some(...))` (line 526-548), and the transaction is not rejected on this basis — i.e., no `TransactionFeeError` is raised and no revert of the fee-charging phase happens — despite the underlying storage write to the sequencer's balance key never being committed.
4. Compare against `non_reverting_execute` (line 240-271), which would have surfaced `EntryPointExecutionError::ExecutionFailed` for the identical `call_info.execution.failed == true` state.

    fn execute_fee_transfer(
        state: &mut dyn State,
        tx_context: Arc<TransactionContext>,
        actual_fee: Fee,
    ) -> TransactionExecutionResult<CallInfo> {
        // The least significant 128 bits of the amount transferred.
        let lsb_amount = Felt::from(actual_fee.0);
        // The most significant 128 bits of the amount transferred.
        let msb_amount = Felt::ZERO;

        let TransactionContext { block_context, tx_info } = tx_context.as_ref();
        let storage_address = tx_context.fee_token_address();
        // The fee contains the cost of running this transfer, and the token contract is
        // well known to the sequencer, so there is no need to limit its run.
        let mut remaining_gas_for_fee_transfer =
            block_context.versioned_constants.os_constants.gas_costs.base.default_initial_gas_cost;
        let fee_transfer_call = CallEntryPoint {
            class_hash: None,
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector_from_name(constants::TRANSFER_ENTRY_POINT_NAME),
            calldata: calldata![
                *block_context.block_info.sequencer_address.0.key(), // Recipient.
                lsb_amount,
                msb_amount
            ],
            storage_address,
            caller_address: tx_info.sender_address(),
            call_type: CallType::Call,

            initial_gas: remaining_gas_for_fee_transfer,
        };
        let mut context = EntryPointExecutionContext::new_invoke(
            tx_context,
            true,
            SierraGasRevertTracker::new(GasAmount(remaining_gas_for_fee_transfer)),
        );

        Ok(fee_transfer_call
            .execute(state, &mut context, &mut remaining_gas_for_fee_transfer)
            .map_err(|error| Box::new(TransactionFeeError::ExecuteFeeTransferError(error)))?)
    }

impl CallEntryPoint {
    pub fn execute(
        mut self,
        state: &mut dyn State,
        context: &mut EntryPointExecutionContext,
        remaining_gas: &mut u64,
    ) -> EntryPointExecutionResult<CallInfo> {
        let tx_context = &context.tx_context;
        let strip_vm_frames = context.versioned_constants().strip_vm_frames_in_sierra_gas;
        let mut decrement_when_dropped = RecursionDepthGuard::new(
            context.current_recursion_depth.clone(),
            context.versioned_constants().max_recursion_depth,
        );
        decrement_when_dropped
            .try_increment_and_check_depth()
            .map_err(|e| e.annotated(TrackedResource::CairoSteps, strip_vm_frames))?;

        // Validate contract is deployed.
        let storage_class_hash = state.get_class_hash_at(self.storage_address).map_err(|e| {
            EntryPointExecutionError::from(e)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames)
        })?;
        if storage_class_hash == ClassHash::default() {
            return Err(EntryPointExecutionError::from(
                PreExecutionError::UninitializedStorageAddress(self.storage_address),
            )
            .annotated(TrackedResource::CairoSteps, strip_vm_frames));
        }

        let class_hash = match self.class_hash {
            Some(class_hash) => class_hash,
            None => storage_class_hash, // If not given, take the storage contract class hash.
        };
        // Hack to prevent version 0 attack on argent accounts.
        if tx_context.tx_info.version() == TransactionVersion::ZERO
            && class_hash
                == ClassHash(
                    Felt::from_hex(FAULTY_CLASS_HASH).expect("A class hash must be a felt."),
                )
        {
            return Err(EntryPointExecutionError::from(PreExecutionError::FraudAttempt)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames));
        }
        // Add class hash to the call, that will appear in the output (call info).
        self.class_hash = Some(class_hash);
        let compiled_class = state.get_compiled_class(class_hash).map_err(|e| {
            EntryPointExecutionError::from(e)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames)
        })?;

        context.revert_infos.0.push(EntryPointRevertInfo::new(
            self.storage_address,
            storage_class_hash,
            context.n_emitted_events,
            context.n_sent_messages_to_l1,
        ));

        // This is the last operation of this function.
        execute_entry_point_call_wrapper(
            self.into_executable(class_hash),
            compiled_class,
            state,
            context,
            remaining_gas,
        )
    }

    /// Similar to `execute`, but returns an error if the outer call is reverted.
    pub fn non_reverting_execute(
        self,
        state: &mut dyn State,
        context: &mut EntryPointExecutionContext,
        remaining_gas: &mut u64,
    ) -> EntryPointExecutionResult<CallInfo> {
        let execution_result = self.execute(state, context, remaining_gas);
        if let Ok(call_info) = &execution_result {
            // Update revert gas tracking (for completeness - value will not be used unless the tx
            // is reverted).
            context.sierra_gas_revert_tracker.update_with_next_remaining_gas(
                call_info.tracked_resource,
                GasAmount(*remaining_gas),
            );
            // If the execution of the outer call failed, revert the transction.
            if call_info.execution.failed {
                return Err(EntryPointExecutionError::ExecutionFailed {
                    error_trace: extract_trailing_cairo1_revert_trace(
                        call_info,
                        Cairo1RevertHeader::Execution,
                    ),
                }
                .annotated(
                    call_info.tracked_resource,
                    context.versioned_constants().strip_vm_frames_in_sierra_gas,
                ));
            }
        }

        execution_result
    }
