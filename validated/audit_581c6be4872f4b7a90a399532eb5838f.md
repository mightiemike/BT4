### Title
Paused `accrue` silently skips protocol reserve-fee minting while interest still accrues to withdrawing users - (File: `mainnet/contracts/vault/v0-vault-stx.clar` and sibling vault contracts)

### Summary
Every vault contract (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`) implements `accrue` with a pause branch that returns `(ok ...)` as a pass-through instead of reverting when accrual is paused:

```clarity
(define-public (accrue)
  (let ((states (var-get pause-states)) (idx (var-get index)) (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let (... (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            ...
            (if (> treasury-lp u0) (try! (ft-mint? zft treasury-lp .dao-treasury)) false)
            ...))))
``` [1](#0-0) 

This mirrors the reported bug class: a code path that is supposed to enforce a protocol fee/cut but instead is short-circuited (there, commented-out checks; here, a pause branch) so the fee-bearing side effect (minting `treasury-lp` reserve shares to `dao-treasury`) never executes, while the value-bearing operation (share price appreciation from accrued interest) proceeds unaffected.

### Finding Description
`deposit` and `redeem` always call `(try! (accrue))` first [2](#0-1) , and share conversion uses `convert-to-assets-preview`, which is built on `total-assets-preview` and `debt-preview`:

```clarity
(define-private (debt-preview)
  (calc-cumulative-debt (var-get principal-scaled) (next-index)))

(define-private (total-assets-preview)
  (let ((current-assets (var-get assets)) (debt (debt-preview)) (borrowed (var-get total-borrowed))
        (interest (if (> debt borrowed) (- debt borrowed) u0)))
    (+ current-assets interest)))
``` [3](#0-2) 

`next-index` computes the interest-adjusted index purely from elapsed time/utilization, independent of the `pause-states` flag - it is not gated by whether `accrue` is paused. Therefore `total-assets-preview`/`convert-to-assets-preview` keep including the full economic interest that "should" have accrued, and suppliers redeeming shares receive the benefit of that interest.

However, the *only* place the protocol's cut of that interest is realized is inside the non-paused branch of `accrue`, where `reserve-inc`/`treasury-lp` is computed from the *actual* `index`/`next-index` delta and minted to `.dao-treasury`:
```clarity
(reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
(treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0))
...
(if (> treasury-lp u0) (try! (ft-mint? zft treasury-lp .dao-treasury)) false)
``` [4](#0-3) 

When `accrue` is paused, this branch is skipped entirely and `index`/`lindex`/`assets`/`last-update` are never advanced - the treasury mint that is supposed to capture the reserve factor never happens for interest accrued during the paused window. Yet nothing prevents `deposit`/`redeem`/`transfer` from being called while accrual is paused: each just calls `(try! (accrue))`, gets the pass-through `(ok {index: idx, lindex: lidx})`, and continues using `convert-to-assets-preview`, which still reflects time-based interest via `next-index`/`debt-preview`. This is the same class of bug as the report: a designed fee-capture step (`treasury-lp` mint / InterPol's reward-fee check) is bypassed on a specific code path while the value-transfer operation it is supposed to gate proceeds unimpeded.

### Impact Explanation
This results in theft of unclaimed protocol yield: the reserve factor (protocol's cut of interest, minted as vault shares to `.dao-treasury`) is permanently lost for any interest period that elapses while `accrue` is paused, while suppliers can still redeem at a share price reflecting that same interest. This matches the in-scope "High" impact category: theft of unclaimed yield or royalties.

### Likelihood Explanation
Likelihood depends on the pause window being active and users redeeming during/after it. Whether `accrue` pausing itself is an intended "deliberate safety design decision" (which would put it out of scope per the rules) could not be fully confirmed — I was unable to open the full vault contract to check documentation/comments explaining the pause states or their intended use with the tools available in this final iteration. This uncertainty should be resolved by reviewing `mainnet/contracts/vault/v0-vault-stx.clar` pause-state setter and its accompanying documentation directly.

### Recommendation
Either (a) make `next-index`/`debt-preview`/`total-assets-preview` respect the paused state so that no interest (and therefore no fee) accrues economically while `accrue` is paused, keeping share pricing and reserve minting consistent, or (b) have the pause branch still compute and mint the pending `treasury-lp` reserve based on `next-index` before short-circuiting, so no reserve fee window is lost. The two values (economic interest exposed to depositors/redeemers vs. interest captured for reserve minting) must be derived from the same "index" source and both be equally affected by the pause flag.

### Proof of Concept
1. DAO/admin pauses accrual on a vault (e.g. `v0-vault-usdc`) via `pause-states` (sets `accrue: true`). [5](#0-4) 
2. Time passes; utilization causes real interest to accumulate as measured by `next-index`.
3. A supplier calls `redeem`, which calls `(try! (accrue))` — pause branch returns the stale `{index, lindex}` without minting any `treasury-lp` to `.dao-treasury` and without updating `assets`/`last-update`. [6](#0-5) 
4. `convert-to-assets-preview(amount)` is computed from `total-assets-preview`, which still uses `debt-preview` → `next-index`, i.e., it still includes the interest that accrued during the paused window. [7](#0-6) 
5. The supplier receives `inkind` underlying tokens reflecting the full accrued interest, but the protocol's reserve-factor cut of that interest was never minted to `.dao-treasury` because step 3's `accrue` call was a no-op pass-through — the fee is permanently lost for that interest window.
