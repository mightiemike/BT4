**Analysis:**

Both `get_num_available_chunks()` (returning `AVAILABLE_BALANCE_CHUNKS = 8`) and the base `B = CHUNK_UPPER_BOUND = 65536` used inside `get_b_powers` are compile-time constants defined in `confidential_balance.move`, not values stored in on-chain state that could silently drift per-account. [1](#0-0) [2](#0-1) 

For this exploit to matter, a framework upgrade would have to change `AVAILABLE_BALANCE_CHUNKS`/`CHUNK_SIZE_BITS`. Such a change requires a privileged, governance-approved framework publish — which the Decision Standard explicitly excludes ("Reject anything that depends on trusted operator mistakes alone" and "privileged governance or admin assumptions" is listed as out of scope).

Even setting that aside, the code path defends against exactly the scenario the proof idea describes. `new_withdrawal_statement` builds the statement from `compressed_old_balance.get_compressed_P()`/`get_compressed_R()`, whose vector lengths are fixed at the time the balance was constructed (via `new_compressed_available_from_p_r_r_aud` → `assert_correct_num_chunks`, which asserts `p.length() == expected_chunks` against the *current* `AVAILABLE_BALANCE_CHUNKS`). [3](#0-2) 

Then `assert_withdraw_statement_is_well_formed` independently recomputes `ell = get_num_chunks()` (the *current* constant) and asserts the total point count in the statement matches `3 + 4*ell + …`. [4](#0-3) 

This check is invoked both at statement-construction time and again inside `psi`/`assert_verifies` before homomorphism evaluation. [5](#0-4) [6](#0-5) [7](#0-6) 

So if a stale on-chain balance was chunked under an old `ell` different from the currently deployed `ell`, the vector length mismatch is caught by an explicit `abort` (`e_wrong_num_points`/`E_WRONG_NUM_CHUNKS`) before any base-power multiplication (`get_b_powers(ell)`) is applied to it — there is no code path where `f()`'s `⟨B, old_P⟩` term is computed against a chunk vector of the wrong length, because the lengths are asserted equal to `ell` upstream in both statement construction and verification. There is no mechanism for "mixed-base-power" reconstruction to occur; the mismatch is a hard abort, not a silent scalar corruption — exactly what the proof idea anticipates, confirming rejection rather than exploitation.

Additionally, `AVAILABLE_BALANCE_CHUNKS`/`CHUNK_SIZE_BITS` are asserted for internal consistency at module init (`init_module`), further reinforcing that any change to these constants is a deliberate, reviewed, governance-gated upgrade decision, not something reachable from unprivileged transaction/proof input. [8](#0-7)
