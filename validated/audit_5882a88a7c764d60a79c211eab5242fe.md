### Title
Starknet OS `execute_replace_class` sets a contract's class hash without verifying the class was declared, unlike the Blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Cairo-1 `replace_class` syscall implementation in the Starknet OS program writes an arbitrary, prover-supplied `class_hash` into a contract's state entry without any check that the class hash corresponds to a declared class. This mirrors the reported bug class ("unrestricted setting of a variable" due to a missing authorization/precondition check): the Blockifier's Rust implementation of the same syscall enforces the invariant, but the Cairo OS re-execution path — which is one of the accepted sequencer-reachable paths for this scan — does not.

### Finding Description
In the Starknet OS Cairo program, `execute_replace_class` reads the request's `class_hash` and directly builds a new `StateEntry` with it, updating `contract_state_changes` — with only a `TODO` acknowledging the missing check: [1](#0-0) 

The comment at line 902 explicitly states: *"TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash."* No such check exists anywhere in this function — the state entry hint (`%{ GetContractAddressStateEntry %}`) and the write are performed unconditionally.

By contrast, the Blockifier's Rust `replace_class` syscall handler enforces exactly this invariant before mutating state: [2](#0-1) 

This is confirmed by tests that assert the Blockifier rejects `replace_class` with an undeclared class hash ("is not declared"): [3](#0-2) [4](#0-3) 

The deprecated Cairo-0 OS implementation (`execute_replace_class` in `deprecated_execute_syscalls.cairo`) has the identical gap — it also writes the new class hash unconditionally with no declared-class check: [5](#0-4) 

### Impact Explanation
The Starknet OS is the program executed (and proven) to re-validate a block's state transition — it is one of the accepted "reachable sequencer paths" per the scope rules. If the OS's constraints do not enforce that a `replace_class` target is a declared class, the OS can be made to accept (and prove valid) a state transition in which a contract's class hash is set to an undeclared/nonexistent class. This diverges from the invariant enforced by the actual execution engine (Blockifier), which is the source of truth for what the "honest" state transition should be. Such asymmetry between what the Blockifier permits during real transaction execution and what the OS's arithmetic constraints permit during proof generation/verification is a classic soundness gap for a re-execution/proving system: it means the OS's set of "provable" state transitions is broader than the Blockifier's set of "correct" state transitions, undermining the guarantee that a valid OS proof corresponds to a state transition an honest node would actually produce. This can manifest as a wrong committed root/class-hash entry being provably accepted, i.e., honest-node divergence at the OS re-execution layer.

### Likelihood Explanation
The gap is unconditionally present in the code (not behind a flag) and is explicitly flagged as an open TODO by the developers, confirming it is a known, unresolved omission rather than a design decision. `replace_class` is a syscall directly callable by any Cairo-1 contract (see `test_replace_class` in test fixtures), so the code path is reachable from ordinary contract execution triggered by a single invoke transaction. The only mitigating factor is that under normal (honest) sequencer operation, the Blockifier's own check would already reject an undeclared-class replace_class before such a state ever reaches the OS trace generation step; exploiting the OS-side gap in isolation would require the sequencer/prover's OS input construction to diverge from actual Blockifier-validated execution. Given the explicit developer TODO acknowledging the missing constraint, likelihood is assessed as the OS's constraint set is provably weaker than intended, which is the core soundness defect being reported, independent of whether current tooling always feeds it Blockifier-validated data.

### Recommendation
Add an explicit constraint in `execute_replace_class` (both the Cairo-1 `syscall_impls.cairo` and the deprecated Cairo-0 `deprecated_execute_syscalls.cairo` implementations) requiring proof that the target `class_hash` is a declared class before permitting the `StateEntry` update — mirroring the check already performed in the Blockifier (`syscall_handler.state.get_compiled_class(request.class_hash)?`). This should be done via a Cairo-level assertion validated against the class commitment/tree, not merely a hint, so that no valid proof can be produced for a `replace_class` targeting an undeclared class hash.

### Proof of Concept
Not independently executable from the indexed code alone (constructing and running an OS re-execution test requires the full `starknet_os_flow_tests` harness). Conceptually:
1. A contract calls `replace_class_syscall(class_hash)` with a `class_hash` that has never been declared (as exercised functionally by the Blockifier-side negative test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`, which the Blockifier correctly rejects).
2. If the OS execution trace for this call were constructed with the corresponding hint (`GetContractAddressStateEntry`) without going through the Blockifier's declared-class check, `execute_replace_class` in `syscall_impls.cairo` would accept it and update `contract_state_changes` with the undeclared class hash, since no Cairo-level assertion exists to reject it — confirming the constraint gap described above.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
