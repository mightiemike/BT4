### Title
Off-chain heartbeat requests forward attacker-chosen `SubscriptionId` to the External Adapter without any on-chain ownership check - ([File: core/services/functions/connector_handler.go])

### Summary
`functionsConnectorHandler.handleHeartbeat` only validates that `RequestInitiator` and `SubscriptionOwner` in the attacker-supplied `OffchainRequest` equal the gateway-authenticated sender address, but it never verifies that the attacker-chosen `SubscriptionId` is actually owned by that sender on-chain. This unchecked `SubscriptionId` is propagated unmodified through `functionsListener.HandleOffchainRequest` / `handleRequest` into `ExternalAdapterClient.RunComputation`, misrepresenting the billing/quota context sent to the EA.

### Finding Description
In `core/services/functions/connector_handler.go`, `handleHeartbeat` (lines 240-262) performs these checks on the unmarshalled `OffchainRequest`:
- `allowedHeartbeatInitiators` allowlist check on `requestBody.Sender`
- `bytes.Equal(request.RequestInitiator, fromAddr.Bytes())`
- `bytes.Equal(request.SubscriptionOwner, fromAddr.Bytes())`
- Timestamp freshness check [1](#0-0) 

None of these checks touch `request.SubscriptionId`, which is a `uint64` fully controlled by the attacker via the JSON payload (`OffchainRequest.SubscriptionId`) [2](#0-1) . The request is then forwarded via `handleOffchainRequest` to `l.listener.HandleOffchainRequest` [3](#0-2) .

In `core/services/functions/listener.go`, `HandleOffchainRequest` validates only address length and timestamp, never subscription ownership, then calls `handleRequest` directly with `request.SubscriptionId`: [4](#0-3) 

`handleRequest` in turn calls `eaClient.RunComputation(ctx, requestIDStr, ..., subscriptionOwner.Hex(), subscriptionId, ...)`: [5](#0-4) 

Finally, `RunComputation` in `core/services/functions/external_adapter_client.go` marshals `subscriptionOwner` and `subscriptionId` directly into the `requestPayload` sent to the external adapter, with no cross-check that the two values correspond to a real on-chain relationship: [6](#0-5) 

By contrast, the `MethodSecretsSet` path in the same handler at least calls `h.subscriptions.GetMaxUserBalance(fromAddr)` to check the sender has a subscription with sufficient balance before proceeding [7](#0-6) , but the heartbeat/off-chain-request path performs no equivalent check against `h.subscriptions` (the `fsub.OnchainSubscriptions` component) to confirm that the specific `SubscriptionId` in the request belongs to `fromAddr`.

Root cause: `SubscriptionOwner`/`RequestInitiator` identity is bound to the gateway-authenticated sender, but `SubscriptionId` is never bound to that sender via an on-chain lookup (e.g. `OnchainSubscriptions`), even though it is forwarded to the EA as if it were part of a verified billing context.

### Impact Explanation
An attacker who is any allowlisted, gateway-authenticated user (no elevated privilege required beyond being an `allowedHeartbeatInitiators` entry / allowlisted sender) can submit a heartbeat `OffchainRequest` with their own address as `SubscriptionOwner`/`RequestInitiator` but with an arbitrary `SubscriptionId` (e.g., a victim's real subscription ID). This value is forwarded as-is to the external adapter's `run_computation` endpoint. If the EA uses `subscriptionId` (alone or in combination with `subscriptionOwner`) for quota/rate-limit/billing decisions, the attacker can consume or interfere with another subscription's allocation—an unauthorized use of billing/quota resources at the EA layer. This matches a rate-limit/quota bypass / unauthorized resource-use impact class.

### Likelihood Explanation
High feasibility: the attacker needs only to be an allowlisted gateway user (a standard, unprivileged precondition already assumed satisfiable) and to guess or observe a valid `SubscriptionId` (subscription IDs are typically small sequential on-chain integers, not secrets). No signature forgery, key compromise, or race condition is required—only crafting the JSON `OffchainRequest` payload with an arbitrary `SubscriptionId`. The path is fully reachable through the documented `handleHeartbeat`/`HandleOffchainRequest` call chain and is repeatable on every heartbeat request.

### Recommendation
Before forwarding `request.SubscriptionId` to `handleRequest`/`RunComputation`, verify on-chain (via the existing `fsub.OnchainSubscriptions` / `subscriptions` component already available to `functionsConnectorHandler`) that `SubscriptionId` is actually owned by `fromAddr`—e.g., an ownership lookup analogous to `GetMaxUserBalance` but keyed to the specific `SubscriptionId`, rejecting the heartbeat request with an error response if ownership doesn't match, mirroring the pattern already used for `MethodSecretsSet`.

### Proof of Concept
Unit test extension of `TestFunctionsConnectorHandler`/`TestFunctionsListener_HandleOffchainRequest_*` (`core/services/functions/connector_handler_test.go`, `core/services/functions/listener_test.go`):
1. Construct an `OffchainRequest` with `RequestInitiator = SubscriptionOwner = attackerAddr.Bytes()` (passes both `bytes.Equal` checks) but `SubscriptionId = victimSubscriptionID` (a subscription actually owned by a different address, e.g. as tracked by a `fsub.OnchainSubscriptions` mock/ORM).
2. Call `handler.HandleGatewayMessage` (or directly `uni.service.HandleOffchainRequest`) with this request.
3. Assert that `eaClient.RunComputation` is invoked with `subscriptionId == victimSubscriptionID` and `subscriptionOwner == attackerAddr.Hex()` and that no call is made to any on-chain subscription ownership verification method rejecting the mismatch, and that the call `require.NoError` succeeds — demonstrating the payload sent to the EA misrepresents the billing relationship, since `victimSubscriptionID` is not actually owned by `attackerAddr`.

```go
func (l *functionsListener) HandleOffchainRequest(ctx context.Context, request *OffchainRequest) error {
	if request == nil {
		return errors.New("HandleOffchainRequest: received nil request")
	}
	if len(request.RequestId) != RequestIDLength {
		return fmt.Errorf("HandleOffchainRequest: invalid request ID length %d", len(request.RequestId))
	}
	if len(request.SubscriptionOwner) != common.AddressLength || len(request.RequestInitiator) != common.AddressLength {
		return errors.New("HandleOffchainRequest: SubscriptionOwner and RequestInitiator must be set to valid addresses")
	}
	if request.Timestamp < uint64(time.Now().Unix()-int64(l.pluginConfig.RequestTimeoutSec)) {
		return errors.New("HandleOffchainRequest: request timestamp is too old")
	}

	var requestId RequestID
	copy(requestId[:], request.RequestId[:32])
	subscriptionOwner := common.BytesToAddress(request.SubscriptionOwner)
	senderAddr := common.BytesToAddress(request.RequestInitiator)
	emptyTxHash := common.Hash{}
	zeroCallbackGasLimit := uint32(0)
	newReq := &Request{
		RequestID:        requestId,
		RequestTxHash:    &emptyTxHash,
		ReceivedAt:       time.Now(),
		Flags:            []byte{},
		CallbackGasLimit: &zeroCallbackGasLimit,
		// use sender address in place of coordinator contract to keep batches uniform
		CoordinatorContractAddress: &senderAddr,
		OnchainMetadata:            []byte(OffchainRequestMarker),
	}
	if err := l.pluginORM.CreateRequest(ctx, newReq); err != nil {
		if errors.Is(err, ErrDuplicateRequestID) {
			l.logger.Warnw("HandleOffchainRequest: received duplicate request ID", "requestID", formatRequestId(requestId), "err", err)
		} else {
			l.logger.Errorw("HandleOffchainRequest: failed to create a DB entry for new request", "requestID", formatRequestId(requestId), "err", err)
		}
		return err
	}
	return l.handleRequest(ctx, requestId, request.SubscriptionId, subscriptionOwner, RequestFlags{}, &request.Data)
```

```go
func (ea *externalAdapterClient) RunComputation(
	ctx context.Context,
	requestId string,
	jobName string,
	subscriptionOwner string,
	subscriptionId uint64,
	flags RequestFlags,
	nodeProvidedSecrets string,
	requestData *RequestData,
) (userResult, userError []byte, domains []string, err error) {
	requestData.Secrets = nil // secrets are passed in nodeProvidedSecrets

	payload := requestPayload{
		Endpoint:            "lambda",
		RequestId:           requestId,
		JobName:             jobName,
		SubscriptionOwner:   subscriptionOwner,
		SubscriptionId:      subscriptionId,
		Flags:               flags,
		NodeProvidedSecrets: nodeProvidedSecrets,
		Data:                requestData,
	}

	userResult, userError, domains, err = ea.request(ctx, payload, requestId, jobName, "run_computation")
	if err != nil {
		return nil, nil, nil, errors.Wrap(err, "error running computation")
	}

	return userResult, userError, domains, nil
}
```
