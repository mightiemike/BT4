## Finding [1](#0-0) 

The reported Curve bug is a "divide-before-multiply" ordering error that truncates precision. Push Chain has a structurally identical bug in `CalculateGasCost`, but the truncation is far more severe because it scales with `gasUsed` rather than being a bounded rounding error.

### Title
Premature truncation of `baseFee` in `CalculateGasCost` causes systematic under-charging of user gas fees - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`Keeper.CalculateGasCost` divides `baseFee` (an 18-decimal `LegacyDec`) down to a whole "upc" integer **before** multiplying by `gasUsed`, instead of multiplying first and dividing once at the end. This is the same "incorrect order of math operations" bug class as the Curve report, except here the lost precision is proportional to `gasUsed`, not bounded to a single unit.

### Finding Description
In `CalculateGasCost`: [2](#0-1) 

```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))   // truncate BEFORE multiplying
...
effectiveGasPrice := new(big.Int).Set(baseFeeBig)
gasUsedBig := new(big.Int).SetUint64(gasUsed)
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)  // multiply AFTER truncation
```

The comment at lines 54-56 asserts "the base fee is always a whole number of upc — no fractional upc exists," but `baseFee` comes from `feemarketKeeper.GetBaseFee` [3](#0-2) , which is Cosmos EVM's AIMD/EIP-1559-style fee-market base fee. That value is adjusted every block by percentage-based deltas (`baseFee * gasUsedDelta / (elasticityMultiplier * baseFeeChangeDenominator)`), so in general it is **not** an exact multiple of `1e18` — it routinely carries a fractional-upc remainder in its `LegacyDec` representation.

Let `baseFee_wei = n*1e18 + r` where `0 ≤ r < 1e18`. The mathematically correct EIP-1559 cost is:
```
correct = floor(baseFee_wei * gasUsed / 1e18) = n*gasUsed + floor(r*gasUsed/1e18)
```
The current code computes:
```
buggy = floor(baseFee_wei/1e18) * gasUsed = n*gasUsed
```
The difference, `floor(r*gasUsed/1e18)`, can approach `gasUsed` itself when `r` is close to `1e18`. Unlike the Curve report (where the loss is bounded to sub-unit rounding), this loss **scales with gas used**, which can be in the millions for a `MsgExecutePayload` transaction.

### Impact Explanation
`CalculateGasCost`'s result feeds directly into `DeductGasFeesFromReceipt`, which burns exactly that computed amount from the user's account: [4](#0-3) . Any unprivileged user submitting a normal `executeUniversalTx`/`MsgExecutePayload` transaction is charged `floor(baseFee/1e18) * gasUsed` instead of the true EIP-1559 fee, systematically under-paying protocol gas fee revenue whenever the on-chain base fee has a non-integer-upc component (which is the common case as the AIMD fee-market adjusts base fee continuously). This is corruption of gas fee accounting reachable purely through ordinary user transaction submission, with no privileged actor required.

### Likelihood Explanation
High. The base fee is adjusted by the fee-market module every block using percentage-based math, so it will very commonly not be an exact multiple of `1e18`; every `MsgExecutePayload` executed during such a block underpays gas fees. No special conditions or attacker crafting are needed beyond normal transaction submission.

### Recommendation
Multiply before dividing, dividing only once at the end, matching the Curve fix pattern:
```go
gasUsedBig := new(big.Int).SetUint64(gasUsed)
gasCostWei := new(big.Int).Mul(baseFee.BigInt(), gasUsedBig) // baseFee still in 1e18-scaled wei
gasCost := new(big.Int).Div(gasCostWei, big.NewInt(1e18))
```
This computes `floor(baseFee_wei * gasUsed / 1e18)` directly, bounding the truncation error to less than 1 upc regardless of `gasUsed`.

### Proof of Concept
1. Let the fee-market base fee (from `GetBaseFee`) settle, after normal AIMD adjustment over several blocks, at `baseFee = N.999999999999999999` upc (i.e. `baseFee_wei = N*1e18 + (1e18-1)`).
2. A user submits `MsgExecutePayload` with `gasLimit`/`maxFeePerGas` sufficient to cover `N+1` upc/gas, and the payload consumes `gasUsed = 5,000,000`.
3. `CalculateGasCost` truncates `baseFeeBig` to `N` before multiplying: `gasCost = N * 5,000,000`.
4. The mathematically correct cost is `floor((N*1e18 + 1e18 - 1) * 5,000,000 / 1e18) ≈ (N+1) * 5,000,000 - 1`.
5. The user is undercharged by nearly `5,000,000` upc versus the correct EIP-1559 fee — an underpayment proportional to gas used rather than a negligible rounding error.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}
