## Finding

### Title
`TransactionOutput::ensure_match_transaction_info` never validates state/hot-state/position-state checkpoint hashes, letting replay-verify and chunk-executor commit paths accept a `TransactionOutput` whose durable state diverges from the authenticated `TransactionInfo` - (File: `types/src/transaction/mod.rs`)

### Summary
The bug-class analog to the ERC4626 "accrual skipped for the wrong party" report is: an integrity-checking routine intentionally covers only *some* of the parties/fields that must agree, silently letting the omitted one diverge. Here, `TransactionOutput::ensure_match_transaction_info` — the function used by the chunk executor to confirm that a locally re-executed `TransactionOutput` matches a trusted, accumulator-authenticated `TransactionInfo` before committing it to durable storage — validates status, gas, write-set hash, and event-root hash, but explicitly skips `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash`. The code itself documents this gap with a `TODO(trading-native)` comment.

### Finding Description
`ensure_match_transaction_info` is defined at [1](#0-0)  and checks:
- execution status
- gas used
- write-set hash vs `txn_info.state_change_hash()`
- event-root hash vs `txn_info.event_root_hash()`

but then contains:
```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
Ok(())
``` [2](#0-1) 

This function is the sole per-transaction sanity check used by `ChunkExecutorInner::verify_execution`, which is invoked from `remove_and_replay_epoch` in the chunk-executor's replay path (used by backup restore's replay-with-verification and by `db-tool replay-on-archive`): [3](#0-2) 

The replay path re-executes transactions via the VM, obtains a fresh `ExecutionOutput` (which includes newly computed state, hot-state, and position-state checkpoints via `DoStateCheckpoint`, see [4](#0-3) ), and is expected to compare the result against the externally supplied, ledger-info-authenticated `TransactionInfo` entries before persisting anything. Because `ensure_match_transaction_info` omits the checkpoint-hash fields, a local execution/storage divergence in the state/hot-state/position-state Sparse-Merkle roots is never caught here: the check reports success, and the (mismatched) locally computed `TransactionOutput`/state gets committed to durable storage alongside the previously-trusted `TransactionInfo` and accumulator, corrupting the ledger's internal state-vs-proof consistency without detection.

### Impact Explanation
This breaks the invariant required by the "Proof And Storage Pivots" section: *"VM outputs, transaction infos, events, and write sets must survive executor-to-storage handoff unchanged"* and *"replay paths ... must not reinterpret committed data into a different ledger state."* A divergence between the locally-computed state/position/hot-state Merkle roots and the authenticated `state_checkpoint_hash`/`position_state_checkpoint_hash` in the accepted `TransactionInfo` is exactly the class of hard-fork-only, silent-corruption bug this task is scoped to find: replay/restore/verification tooling (db-tool `replay_on_archive`, backup restore with verification) can report success while durable state diverges from the version proven correct by the accumulator/ledger-info signatures. Any node or backup consumer relying on this check for integrity assurance would unknowingly persist and later serve state/proofs that do not match the canonical, signed ledger — a "committed state that differs from the correct VM result" / "authenticated ... output bound to the wrong ... proof context" impact.

### Likelihood Explanation
The gap is triggered whenever the position-state/hot-state (or, if extended, main state) checkpoint computation diverges between the source of truth (backup archive, or a syncing peer) and local re-execution — e.g., due to a native/position-state computation bug, an unhandled protocol-version difference, or an in-progress feature flag (`COMPUTE_TRADING_NATIVE_STATE_ROOTS`) being enabled on one side but not fully validated on the other. This is not an attacker-controlled exploit against consensus (the `TransactionInfo` fields remain accumulator-authenticated), but it is a real, code-acknowledged verification gap in a security-critical commit/replay-verification code path, actively guarded against by the author's own comment, and is currently unguarded.

### Recommendation
Extend `ensure_match_transaction_info` to also compare the locally computed `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present in `txn_info`) against values computed from the corresponding `ExecutionOutput`/`DoStateCheckpoint` results before the chunk executor is allowed to report `verify_execution` success, as the existing TODO already prescribes — this should be done prior to enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS` in any environment that relies on `verify_execution_mode.should_verify()` for integrity guarantees.

### Proof of Concept
Not independently exploitable as an attacker-controlled PoC without access to a divergent state computation; the root cause is demonstrated directly by the code path:
1. `execution/executor/src/chunk_executor/mod.rs` `verify_execution` (lines 684-706) calls `txn_out.ensure_match_transaction_info(...)` as the only correctness gate before committing replayed transactions.
2. `ensure_match_transaction_info` (`types/src/transaction/mod.rs` lines 2139-2203) omits checkpoint-hash comparison, as documented by its own `TODO(trading-native)` comment (lines 2197-2202).
3. Any local computation of `state_checkpoint_hash`/`position_state_checkpoint_hash` that differs from the authenticated `TransactionInfo` supplied by backup/replay input will pass this check unnoticed, and the divergent local state is committed to durable storage in `remove_and_apply`/chunk commit.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())

    fn get_state_checkpoint_hashes(
        execution_output: &ExecutionOutput,
        known_state_checkpoints: Option<Vec<Option<HashValue>>>,
        computed_last_checkpoint_hash: HashValue,
        label: &str,
    ) -> Result<Vec<Option<HashValue>>> {
        let _timer = OTHER_TIMERS.timer_with(&[&format!("get_{label}_checkpoint_hashes")]);

        let num_txns = execution_output.to_commit.len();
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();

        if let Some(known) = known_state_checkpoints {
            ensure!(
                known.len() == num_txns,
                "Bad number of known {label} hashes. {} vs {}",
                known.len(),
                num_txns,
            );
            if let Some(idx) = last_checkpoint_index {
                ensure!(
                    known[idx] == Some(computed_last_checkpoint_hash),
                    "{label} root hash mismatch with known hashes passed in. {:?} vs {:?}",
                    known[idx],
                    Some(computed_last_checkpoint_hash),
                );
            }
            Ok(known)
        } else {
            if !execution_output.is_block {
                // We should enter this branch only in test.
                execution_output.to_commit.ensure_at_most_one_checkpoint()?;
            }

            let mut out = vec![None; num_txns];
            if let Some(index) = last_checkpoint_index {
                out[index] = Some(computed_last_checkpoint_hash);
            }
            Ok(out)
        }
    }
