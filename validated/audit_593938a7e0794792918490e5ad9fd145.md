### Title
Insufficient-energy guard in `useEnergy` bypassed when `AllowTvmFreeze=1` and `supportUnfreezeDelay=false` - ([File: chainbase/src/main/java/org/tron/core/db/EnergyProcessor.java])

### Summary
`useEnergy(AccountCapsule, long, long)` only rejects an over-limit energy request when **all three** conditions hold simultaneously: `energy > (energyLimit - newEnergyUsage)`, `getAllowTvmFreeze() == 0`, and `!supportUnfreezeDelay()`. In the intermediate chain-parameter state where `AllowTvmFreeze == 1` but `supportUnfreezeDelay()` is still `false` (a legitimate, reachable configuration during the TVM-freeze-v2 rollout window), the `getAllowTvmFreeze() == 0` conjunct is false, so the guard's `return false` branch can never execute regardless of how far `energy` exceeds `energyLimit`.

### Finding Description [1](#0-0) 

Walking through `useEnergy`:
- `energyLimit` is computed from `calculateGlobalEnergyLimit(accountCapsule)`, which reflects the account's real frozen/delegated energy weight. [2](#0-1) 
- `newEnergyUsage` is the account's already-consumed energy after decay/recovery.
- The insufficiency guard is:
```java
if (energy > (energyLimit - newEnergyUsage)
    && dynamicPropertiesStore.getAllowTvmFreeze() == 0
    && !dynamicPropertiesStore.supportUnfreezeDelay()) {
  return false;
}
```
This is an AND of three terms. When `getAllowTvmFreeze() == 1` (regardless of `supportUnfreezeDelay`), the second conjunct is `false`, so the whole expression short-circuits to `false` and the method never returns early — even though `energy` may vastly exceed the account's remaining capacity.
- Execution falls through unconditionally to:
```java
newEnergyUsage = increase(newEnergyUsage, energy, now, now); // or the supportUnfreezeDelay() branch
accountCapsule.setEnergyUsage(newEnergyUsage);
...
accountStore.put(accountCapsule.createDbKey(), accountCapsule);
``` [3](#0-2) 
so `newEnergyUsage` is persisted to the account's `AccountResource.energyUsage` field with no cap, and the method returns `true` (success) instead of `false`.

The precondition (`AllowTvmFreeze=1`, `supportUnfreezeDelay=false`) is a valid, non-hypothetical chain-parameter state that exists between the enabling of TVM-freeze-v2 features and the later enabling of unfreeze-delay support, so this is not a dead code path.

### Impact Explanation
An unprivileged attacker submitting a `TriggerSmartContract` transaction whose execution requests energy far in excess of `calculateGlobalEnergyLimit(accountCapsule)` will have that inflated usage recorded to their own `AccountResource.energyUsage` without being rejected. This breaks the accounting invariant that usage must stay within the frozen/delegated energy limit, corrupting per-account resource bookkeeping and (via `dynamicPropertiesStore.saveBlockEnergyUsage`, gated by `AllowAdaptiveEnergy==1`) potentially skewing the network-wide adaptive energy limit calculation used by `updateAdaptiveTotalEnergyLimit()`/`updateTotalEnergyAverageUsage()`, which affects every account's available energy on the network. It also allows an attacker to record energy consumption beyond what they legitimately own, without the transaction being rejected for insufficient resources.

### Likelihood Explanation
Requires only the chain parameter state `AllowTvmFreeze=1` and `supportUnfreezeDelay=false` — a normal, documented intermediate configuration reachable via committee proposals during protocol version transitions, not requiring attacker privilege. Once in that state, any account can trigger the bug with a single contract call requesting energy above its limit; fully repeatable and deterministic.

### Recommendation
Change the guard so the insufficiency check is independent of the freeze-mode flags, e.g.:
```java
if (energy > (energyLimit - newEnergyUsage)) {
  return false;
}
```
(reintroducing/enforcing the check for all flag combinations), or explicitly define the intended alternate accounting path for the `AllowTvmFreeze=1 && !supportUnfreezeDelay()` case with an equivalent bound check before persisting `newEnergyUsage`.

  public boolean useEnergy(AccountCapsule accountCapsule, long energy, long now) {

    long energyUsage = accountCapsule.getEnergyUsage();

    long energyLimit = calculateGlobalEnergyLimit(accountCapsule);

    if (!dynamicPropertiesStore.supportUnfreezeDelay()) {
      newEnergyUsage = increase(energyUsage, 0, latestConsumeTime, now);

          latestConsumeTime, now);
    }

    if (energy > (energyLimit - newEnergyUsage)
        && dynamicPropertiesStore.getAllowTvmFreeze() == 0
        && !dynamicPropertiesStore.supportUnfreezeDelay()) {
      return false;
    }

  public long calculateGlobalEnergyLimit(AccountCapsule accountCapsule) {
    long frozeBalance = accountCapsule.getAllFrozenBalanceForEnergy();
    if (dynamicPropertiesStore.supportUnfreezeDelay()) {
      return calculateGlobalEnergyLimitV2(frozeBalance);
    }
    if (frozeBalance < TRX_PRECISION) {
      return 0;
    }

    long totalEnergyLimit = dynamicPropertiesStore.getTotalEnergyCurrentLimit();
    long totalEnergyWeight = dynamicPropertiesStore.getTotalEnergyWeight();
    if (dynamicPropertiesStore.allowNewReward() && totalEnergyWeight <= 0) {
      return 0;
    } else {
      assert totalEnergyWeight > 0;
    }
    if (hardenCalculation()) {
      return calculateGlobalLimitV1(frozeBalance, totalEnergyLimit, totalEnergyWeight);
    }
    long energyWeight = frozeBalance / TRX_PRECISION;
    return (long) (energyWeight * ((double) totalEnergyLimit / totalEnergyWeight));
  }
