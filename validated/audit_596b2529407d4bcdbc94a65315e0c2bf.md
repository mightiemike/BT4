### Title
Case-insensitive AccountId index allows front-running/squatting of case-variant account names - (File: chainbase/src/main/java/org/tron/core/store/AccountIdIndexStore.java)

### Summary
`AccountIdIndexStore` lower-cases the `accountId` key for uniqueness checks (`getLowerCaseAccountId`, lines 23-27), while `SetAccountIdActuator.execute` stores the attacker-supplied original-case bytes in `AccountCapsule` via `setAccountId` [1](#0-0) . This lets an unprivileged attacker register any case-variant of a name first, permanently blocking the case-sensitive owner from ever claiming that name because `accountIdIndexStore.has(accountId)` in `validate()` will match on a case-insensitive basis [2](#0-1) .

### Finding Description
`AccountIdIndexStore.put`, `get`, and `has` all normalize the key to lowercase before touching the underlying store [3](#0-2) . `SetAccountIdActuator.validate()` calls `accountIdIndexStore.has(accountId)` (case-insensitive) to reject duplicates, and once that passes, `execute()` unconditionally writes the exact case-sensitive bytes the caller supplied to `AccountCapsule.setAccountId()` and indexes it via `accountIdIndexStore.put(account)` [4](#0-3) . There is no per-owner reservation or preimage-commitment mechanism, so any unprivileged, funded account can broadcast a `SetAccountIdContract` transaction naming any case variant of a string before the intended owner does. Once set, `account.getAccountId() != null && !isEmpty()` blocks any further changes for the true target (each account can set its id only once) [5](#0-4) , and the lowercase collision in `accountIdIndexStore.has` permanently denies every other account (including the "rightful" owner) from ever claiming any casing of that name. Existing checks (`TransactionUtil.validAccountId`, `DecodeUtil.addressValid`, signature/permission checks) do not address this because they only validate charset/length/address format, not name ownership or case-canonicalization consistency between storage and lookup.

### Impact Explanation
The impact is limited to denial of a cosmetic identifier: `accountId` is used only for account discovery via `Wallet.getAccountById`/`GetAccountById` RPC and HTTP endpoints; it carries no funds, no permission weight, and no consensus-critical role. The scoped impact is that a victim can be permanently prevented from claiming any case variant of an account name they wanted, which is a naming/griefing DoS on a non-critical identifier feature, not an asset, authorization, or consensus impact.

### Likelihood Explanation
Exploitation only requires broadcasting a normal, cheap `SetAccountIdContract` transaction (cost is minimal - `calcFee()` returns 0, bandwidth cost only) [6](#0-5) , from any funded account, with no special privileges. It is fully repeatable/deterministic given `AccountIdIndexStoreTest.testCaseInsensitive`-style behavior and `SetAccountIdActuatorTest.nameAlreadyUsed` confirming the "This id has existed" rejection path.

### Recommendation
Make the stored `accountId` canonical form consistent with the index: either (a) store the lowercased form in `AccountCapsule` as well so display and lookup are consistent, or (b) preserve the original case in storage but keep the case-insensitive uniqueness check as an intentional design choice and document it (if this is desired behavior, no fix needed beyond documentation). If case-sensitivity of display is required while uniqueness must remain case-insensitive, this is inherent to the current design and the "vulnerability" is best characterized as a minor griefing quirk on a non-critical feature rather than an actionable security bug requiring a code fix under this bounty's asset/consensus/RPC-DoS scope.

  private static byte[] getLowerCaseAccountId(byte[] bsAccountId) {
    return ByteString
        .copyFromUtf8(ByteString.copyFrom(bsAccountId).toStringUtf8().toLowerCase(Locale.ROOT))
        .toByteArray();
  }

  public void put(AccountCapsule accountCapsule) {
    byte[] lowerCaseAccountId = getLowerCaseAccountId(accountCapsule.getAccountId().toByteArray());
    super.put(lowerCaseAccountId, new BytesCapsule(accountCapsule.getAddress().toByteArray()));
  }

  public byte[] get(ByteString name) {
    BytesCapsule bytesCapsule = get(name.toByteArray());
    if (Objects.nonNull(bytesCapsule)) {
      return bytesCapsule.getData();
    }
    return null;
  }

  @Override
  public BytesCapsule get(byte[] key) {
    byte[] lowerCaseKey = getLowerCaseAccountId(key);
    byte[] value = revokingDB.getUnchecked(lowerCaseKey);
    if (ArrayUtils.isEmpty(value)) {
      return null;
    }
    return new BytesCapsule(value);
  }

  @Override
  public boolean has(byte[] key) {
    byte[] lowerCaseKey = getLowerCaseAccountId(key);
    byte[] value = revokingDB.getUnchecked(lowerCaseKey);
    return !ArrayUtils.isEmpty(value);
  }
