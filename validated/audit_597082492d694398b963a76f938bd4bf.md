### Title
Unsanitized `GasToken` address from user-triggered outbound event lets an attacker drive privileged module-signed `refundUnusedGas` calls against an arbitrary, non-registry-validated contract - (File: `x/uexecutor/keeper/create_outbound.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`BuildOutboundsFromReceipt` decodes the `UniversalTxOutbound` EVM event and validates the bridged asset (`event.Token`) against the `uregistry` PRC20 index before storing it, but the sibling field `event.GasToken` is copied straight onto `OutboundTx.GasToken` with **no equivalent registry check**. That unvalidated address is later handed, as-is, to `applyGasRefund`, which uses it as the sender-privileged argument to `CallUniversalCoreRefundUnusedGas` — a `DerivedEVMCall` issued *as the `uexecutor` module account* — as well as to `GetDefaultFeeTierForToken`/`getSwapQuoteForRefund`. This is the same bug class as the reported `farmToken` issue: an address supplied by an untrusted caller is used directly in a privileged/state-changing flow without whitelisting.

### Finding Description
In `BuildOutboundsFromReceipt` (`x/uexecutor/keeper/create_outbound.go:59-91`):

```go
tokenCfg, err := k.uregistryKeeper.GetTokenConfigByPRC20(ctx, event.ChainId, event.Token) // validated
...
outbound := &types.OutboundTx{
    ...
    Prc20AssetAddr: event.Token,     // validated via registry above
    GasToken:       event.GasToken,  // NOT validated against uregistry at all
    ...
}
``` [1](#0-0) 

`event.GasToken` is decoded verbatim from `UniversalTxOutbound` log data emitted on Push Chain's own EVM by `UniversalGatewayPC`: [2](#0-1) 

That event is produced as a side effect of executing a user's `UniversalPayload` through their UEA (or a CEA's `executeUniversalTx`) — i.e. attacker-controlled call data ultimately reaches the gateway contract's outbound-emitting function and its `gasToken` parameter, with no chain-level constraint tying it to a registered PRC20.

Later, once the outbound is voted successful/failed, `applyGasRefund` uses `outbound.GasToken` unchecked:

```go
gasToken := common.HexToAddress(outbound.GasToken)
fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
...
resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
...
resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
``` [3](#0-2) 

`CallUniversalCoreRefundUnusedGas` performs a `DerivedEVMCall` with `isModuleSender=true`, meaning the `uexecutor` module account itself signs and sends the call to `UniversalCore.refundUnusedGas(gasToken, amount, recipient, withSwap, fee, minPCOut)`: [4](#0-3) 

This mirrors the report's `farmToken` pattern exactly: a caller-supplied address is passed into a fund-moving/privileged function without a whitelist or registry check, unlike the sibling `Token`/`Prc20AssetAddr` field which *is* checked via `GetTokenConfigByPRC20`.

### Impact Explanation
Because `GasToken` skips the registry whitelist that every other asset-address field in this flow goes through, the `uexecutor` module account can be made to issue a real, module-signed EVM transaction to `UniversalCore.refundUnusedGas` targeting an attacker-chosen contract address rather than a legitimate registered PRC20. Depending on `UniversalCore`'s implementation (external contract, not in this repo's scope), this can result in:
- the module unintentionally invoking arbitrary contract logic as `msg.sender = uexecutor module account` (module-originated EVM execution with unauthenticated target/asset), and/or
- PRC20 accounting corruption if the no-swap fallback path treats an arbitrary attacker-supplied address as if it were a real PRC20 and mints/deposits `refundAmount` to a caller-controlled recipient.

This falls squarely under the allowed impacts: "corruption of PRC20 or native asset accounting... token mapping" and "unauthorized module-originated EVM execution... in universal execution flows," reachable purely by an unprivileged user submitting a payload that triggers the gateway's outbound event with a crafted `gasToken`.

### Likelihood Explanation
The trigger requires only an ordinary user-initiated payload flow that results in a `UniversalTxOutbound` event with `gasFee > 0` (so `applyGasRefund` has excess gas to refund) and an attacker-chosen `gasToken` field — no validator collusion, no privileged role, and no special timing is needed. The asymmetry with `event.Token` (which is checked) versus `event.GasToken` (which is not) suggests this is an oversight rather than an intentional design choice, increasing confidence this is a genuine gap rather than a defended invariant.

### Recommendation
Validate `event.GasToken` against `uregistryKeeper` (e.g. require it to resolve via `GetTokenConfigByPRC20` for the relevant chain, or restrict it to a small allow-listed set of protocol gas tokens) before storing it on `OutboundTx.GasToken`, mirroring the existing check already performed for `event.Token`/`Prc20AssetAddr`. Reject or fall back to a safe default outbound configuration if the supplied `gasToken` does not resolve to a registered PRC20.

### Proof of Concept
1. An attacker submits a `MsgExecutePayload` (gasless, callable by anyone) whose payload calls into the UEA, which in turn triggers the gateway contract's bridge/outbound function with an attacker-chosen `gasToken` argument (any 20-byte address, not necessarily a registered PRC20) and a non-zero `gasFee`.
2. `EVMHooks.PostTxProcessing` → `CreateUniversalTxFromReceiptIfOutbound` → `BuildOutboundsFromReceipt` decodes the emitted `UniversalTxOutbound` log and stores `outbound.GasToken = event.GasToken` unchecked [5](#0-4) .
3. Once Universal Validators vote the outbound as observed with `gas_fee_used < gas_fee` (a value the attacker can influence by keeping the destination-chain gas usage low), `handleSuccessfulOutbound` → `applyGasRefund` runs and calls `CallUniversalCoreRefundUnusedGas(ctx, gasToken, ...)` using the attacker-supplied `gasToken` address, with the `uexecutor` module account as the EVM sender [6](#0-5) .

```go
func (k Keeper) CallUniversalCoreRefundUnusedGas(
	ctx sdk.Context,
	gasToken common.Address,
	amount *big.Int,
	recipient common.Address,
	withSwap bool,
	fee *big.Int,
	minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	// fee is uint24 in Solidity — pass as *big.Int (go-ethereum ABI packs non-standard widths as *big.Int)
	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress,
		handlerAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"refundUnusedGas",
		gasToken,
		amount,
		recipient,
		withSwap,
		fee,
		minPCOut,
	)
}
