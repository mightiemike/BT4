### Title
Transaction backup restore accepts unverified `write_set` for proof-verified transactions, allowing corrupted state to be committed for pre-replay versions - (File: `storage/backup/backup-cli/src/backup_types/transaction/restore.rs`)

### Summary
The transaction-backup restore path verifies transactions, events, and transaction infos against the accumulator proof, but it never checks that the `write_set` read from the backup file actually matches `txn_info.state_change_hash()`. For any version restored via the "save-before-replay" path (i.e., versions that are not re-executed by the chunk executor), the unverified `write_set` is written straight into durable storage and used to compute state, so a corrupted or malicious backup artifact can silently commit a wrong ledger state that still appears to carry a validly-proven `TransactionInfo`.

### Finding Description
`LoadedChunk::load` reads `txns`, `txn_infos`, `event_vecs`, and `write_sets` from the backup file, then builds a `TransactionListWithProofV2` from `txns` + `event_vecs` + `TransactionInfoListWithProof` and calls `.verify(...)`: [1](#0-0) 

Critically, `write_sets` is **not** part of the object being verified — it is loaded independently and stored in `LoadedChunk` untouched: [2](#0-1) 

The generic `TransactionListWithProofV2::verify` only checks transaction hashes, transaction-info proof-of-inclusion, and (if present) event root hashes; it has no knowledge of `write_set` at all: [3](#0-2) 

By contrast, the sibling type used for transaction **output** backups explicitly binds the write set to the transaction info via `state_change_hash`: [4](#0-3) 

This check has no analog for the transaction-backup format. For versions that are restored via `save_before_replay_version` (i.e., versions before the `replay_from_version` cutoff, or whenever no replay is requested), the raw `write_sets` are handed to `RestoreHandler::save_transactions` / `save_transactions_and_replay_kv`, which pass them unmodified into `restore_utils::save_transactions_impl`: [5](#0-4) [6](#0-5) 

`save_transactions_impl` persists `write_sets` into `WriteSetDb` and, for `kv_replay`, feeds them straight into `calculate_state_and_put_updates`, which derives and commits the new Jellyfish-Merkle state directly from these write sets: [7](#0-6) 

None of this code path re-derives or checks `state_change_hash` against the write set before committing it, so a backup file whose `write_set` records have been swapped, corrupted, or maliciously crafted (while the accompanying `TransactionInfo`/proof remain internally consistent and unmodified) will pass `LoadedChunk::load`'s verification and be committed as durable ledger state and JMT leaves.

### Impact Explanation
This breaks the "VM outputs, transaction infos, events, and write sets must survive executor-to-storage handoff unchanged" and "restore paths must not reinterpret committed data into a different ledger state" invariants. An operator restoring from a compromised or corrupted backup source (e.g. a malicious/compromised backup storage backend, a supply-chain-tampered archive, or bit corruption not caught because the field is unchecked) can have the DB accept a `write_set` that does not correspond to what was actually executed for that transaction, while the transaction, hash, and proof metadata still validate. This directly corrupts state values (account balances, resources, table entries) at the version being restored, with no re-execution to catch the mismatch (re-execution only happens for versions at/after `replay_from_version`). Because JMT state and pruners are updated from this corrupted write set, the wrong values become part of durable, versioned ledger state.

### Likelihood Explanation
This requires the restoring node to source backup data from a backend/manifest that is not fully trusted or that can be corrupted, which is a realistic scenario for full-node/validator operators restoring from third-party or shared backup storage (this is exactly the class of "authenticated backup response" data that should be proof-bound). The bug is not reachable from normal execution; it is scoped to the backup/restore tooling and only manifests for the "save-before-replay" segment of a restore (default is to restore the full DB from a backup with no replay window, so this segment can cover the entire restored history).

### Recommendation
In `LoadedChunk::load` (or in `TransactionListWithProofV2::verify`/`TransactionInfoListWithProof`), verify each `write_set`'s hash against the corresponding `txn_info.state_change_hash()` before accepting the chunk, mirroring the check already performed in `TransactionOutputListWithProof::verify`. Reject the chunk (`bail!`) on mismatch instead of silently persisting it.

### Proof of Concept
1. Take a valid transaction backup chunk file (format V0/V1) containing `(txn, txn_info, events, write_set)` tuples.
2. Replace one record's `write_set` bytes with an attacker-chosen `WriteSet` (leave `txn`, `txn_info`, and `events` untouched so the proof/hash checks still pass).
3. Run `TransactionRestoreController` against this tampered manifest with `replay_from_version` unset (full non-replay restore).
4. `LoadedChunk::load` succeeds because `verify()` only checks `txns`/`events`/proof, not `write_sets`.
5. `save_before_replay_version` calls `restore_handler.save_transactions(...)` with the tampered write set, which is committed via `restore_utils::save_transactions_impl` into `WriteSetDb` and, when `kv_replay` is used, into the Jellyfish Merkle state — producing a durable ledger state that diverges from what the VM actually produced for that transaction, with no error raised anywhere in the pipeline.

    pub fn verify(
        &self,
        ledger_info: &LedgerInfo,
        first_transaction_version: Option<Version>,
    ) -> Result<()> {
        // Verify the first transaction versions match
        ensure!(
            self.get_first_transaction_version() == first_transaction_version,
            "First transaction version ({:?}) doesn't match given version ({:?}).",
            self.get_first_transaction_version(),
            first_transaction_version,
        );

        // Verify the lengths of the transactions and transaction infos match
        ensure!(
            self.proof.transaction_infos.len() == self.get_num_transactions(),
            "The number of TransactionInfo objects ({}) does not match the number of \
             transactions ({}).",
            self.proof.transaction_infos.len(),
            self.get_num_transactions(),
        );

        // Verify the transaction hashes match those of the transaction infos
        self.transactions
            .par_iter()
            .zip_eq(self.proof.transaction_infos.par_iter())
            .map(|(txn, txn_info)| {
                let txn_hash = txn.committed_hash();
                ensure!(
                    txn_hash == txn_info.transaction_hash(),
                    "The hash of transaction does not match the transaction info in proof. \
                     Transaction hash: {:x}. Transaction hash in txn_info: {:x}.",
                    txn_hash,
                    txn_info.transaction_hash(),
                );
                Ok(())
            })
            .collect::<Result<Vec<_>>>()?;

        // Verify the transaction infos are proven by the ledger info.
        self.proof
            .verify(ledger_info, self.get_first_transaction_version())?;

        // Verify the events if they exist.
        if let Some(event_lists) = &self.events {
            ensure!(
                event_lists.len() == self.get_num_transactions(),
                "The length of event_lists ({}) does not match the number of transactions ({}).",
                event_lists.len(),
                self.get_num_transactions(),
            );
            event_lists
                .into_par_iter()
                .zip_eq(self.proof.transaction_infos.par_iter())
                .map(|(events, txn_info)| verify_events_against_root_hash(events, txn_info))
                .collect::<Result<Vec<_>>>()?;
        }

        Ok(())
    }

/// A helper function that saves the transactions to the given change set
pub(crate) fn save_transactions_impl(
    state_store: Arc<StateStore>,
    ledger_db: Arc<LedgerDb>,
    first_version: Version,
    txns: &[Transaction],
    persisted_aux_info: &[PersistedAuxiliaryInfo],
    txn_infos: &[TransactionInfo],
    events: &[Vec<ContractEvent>],
    write_sets: &[WriteSet],
    ledger_db_batch: &mut LedgerDbSchemaBatches,
    state_kv_batches: &mut ShardedStateKvSchemaBatch,
    kv_replay: bool,
) -> Result<()> {
    for (idx, txn) in txns.iter().enumerate() {
        ledger_db.transaction_db().put_transaction(
            first_version + idx as Version,
            txn,
            /*skip_index=*/ false,
            &mut ledger_db_batch.transaction_db_batches,
        )?;
    }

    for (idx, aux_info) in persisted_aux_info.iter().enumerate() {
        PersistedAuxiliaryInfoDb::put_persisted_auxiliary_info(
            first_version + idx as Version,
            aux_info,
            &mut ledger_db_batch.persisted_auxiliary_info_db_batches,
        )?;
    }

    for (idx, txn_info) in txn_infos.iter().enumerate() {
        TransactionInfoDb::put_transaction_info(
            first_version + idx as Version,
            txn_info,
            &mut ledger_db_batch.transaction_info_db_batches,
        )?;
    }

    ledger_db
        .transaction_accumulator_db()
        .put_transaction_accumulator(
            first_version,
            txn_infos,
            &mut ledger_db_batch.transaction_accumulator_db_batches,
        )?;

    ledger_db.event_db().put_events_multiple_versions(
        first_version,
        events,
        &mut ledger_db_batch.event_db_batches,
    )?;

    for (idx, txn_events) in events.iter().enumerate() {
        for event in txn_events {
            if let Some(event_key) = event.event_key() {
                if *event_key == new_block_event_key() {
                    LedgerMetadataDb::put_block_info(
                        first_version + idx as Version,
                        event,
                        &mut ledger_db_batch.ledger_metadata_db_batches,
                    )?;
                }
            }
        }
    }
    // insert changes in write set schema batch
    for (idx, ws) in write_sets.iter().enumerate() {
        WriteSetDb::put_write_set(
            first_version + idx as Version,
            ws,
            &mut ledger_db_batch.write_set_db_batches,
        )?;
    }

    if kv_replay && first_version > 0 && state_store.get_usage(Some(first_version - 1)).is_ok() {
        let (ledger_state, _hot_state_updates) = state_store.calculate_state_and_put_updates(
            &StateUpdateRefs::index_write_sets(first_version, write_sets, write_sets.len(), vec![]),
            &mut ledger_db_batch.ledger_metadata_db_batches, // used for storing the storage usage
            state_kv_batches,
        )?;
        // n.b. ideally this is set after the batches are committed
        state_store.set_state_ignoring_summary(ledger_state);
    }
