## Finding: Confirmed — SVM gateway event forgery via unauthenticated log-text parsing

### Title
Unauthenticated `Program data:` log parsing lets an unprivileged Solana user forge gateway events (`send_funds`, `finalize_universal_tx`, `revert_universal_tx`, `funds_rescued`) - (File: `universalClient/chains/svm/event_listener.go`, `universalClient/chains/svm/event_parser.go`)

### Summary
`determineEventType` classifies a Solana transaction's log line purely from its text content and an 8-byte discriminator decoded from a base64 `"Program data: "` line, with no check that the log actually originated from an instruction invoking the configured gateway program.

### Finding Description
`processSignatureBatch` fetches transaction signatures via `GetSignaturesForAddress(gatewayAddr, ...)`, which returns any signature where the gateway address merely appears among a transaction's account keys — it does not require the gateway program to have been invoked. For every such transaction, the listener then iterates **every log line in `tx.Meta.LogMessages`**, regardless of which program (or CPI depth) produced it: [1](#0-0) 

`determineEventType` only checks the `"Program data: "` prefix and the first 8 bytes of the base64-decoded payload against a discriminator table; it never verifies the emitting program ID: [2](#0-1) 

The follow-on parsers (`parseSendFundsEvent`, `parseOutboundObservationEvent`, `decodeUniversalTxEvent`) likewise trust the raw bytes to contain attacker-controlled `sender`, `recipient`, `token`, `amount`, `sub_tx_id`, `universal_tx_id`, `revert_recipient`, and `tx_type` fields with no cross-check against actual token movement or PDA state: [3](#0-2) [4](#0-3) 

Because Solana's `sol_log_data` syscall (which produces `"Program data: "` lines) can be invoked by **any** program executed within the same transaction, an unprivileged attacker can:
1. Include the real gateway address as a referenced account (even read-only, unrelated to any actual gateway instruction) so the transaction is returned by `GetSignaturesForAddress`.
2. In the same transaction, invoke their own deployed program that emits a forged `"Program data: <base64>"` log whose first 8 bytes match a legitimate discriminator (`send_funds`, `finalize_universal_tx`, `revert_universal_tx`, `funds_rescued`) and whose remaining bytes encode attacker-chosen fields (arbitrary recipient/UEA address, token, amount, or arbitrary `sub_tx_id`/`universal_tx_id` for finalize/revert).

Since every honest universal validator runs this identical listener code against the same public Solana RPC data, all of them will independently parse and store the same forged `store.Event`, causing honest nodes to converge on a ballot backed by fabricated data rather than by an actual gateway-authenticated deposit or outbound execution.

### Impact Explanation
A forged `send_funds` event can claim an inbound deposit that never actually moved funds into gateway custody, which — if it reaches ballot finalization on Push Chain — can drive unauthorized PRC20/native minting for an attacker-chosen recipient with no real backing asset. A forged `finalize_universal_tx`/`revert_universal_tx`/`funds_rescued` event can spoof `sub_tx_id`/`universal_tx_id` values to trigger release or refund accounting for a transaction the attacker did not legitimately create. This falls squarely in the "unauthorized mint/release/refund" impact category and, since it corrupts what *honest* validators independently observe and vote on, it is not gated by any malicious-validator assumption.

### Likelihood Explanation
This requires only an unprivileged Solana account, one crafted transaction with two instructions (a benign reference to the gateway account plus a call to an attacker-deployed program), and knowledge of the discriminator table (which is derived from public gateway method identifiers). No privileged role, relayer, or validator collusion is needed.

### Recommendation
`determineEventType`/`ParseEvent` must bind each parsed log line to the specific instruction/program invocation that produced it — e.g., by tracking Solana's `"Program <address> invoke [depth]"` / `"Program <address> success"` bracketing in `LogMessages` (or by using `tx.Meta.InnerInstructions`/`LogTruncated` with proper program-id attribution rather than `GetTransaction`'s flat log array) and rejecting any `Program data:` line that does not fall within a bracket whose program ID equals `el.gatewayAddress`. Additionally, downstream finalization logic should independently verify economic invariants (e.g., that a `send_funds` inbound event corresponds to an actual balance change in the gateway PDA/vault) before it can reach terminal vote state, rather than trusting log-decoded fields alone.

### Proof of Concept
1. Deploy an arbitrary "attacker" Solana program that calls `sol_log_data` with a payload whose first 8 bytes equal `hex(lowercase)` of a configured discriminator (e.g., `send_funds`'s `EventIdentifier`), followed by a Borsh-style body: `sender(32)`, `recipient(20, attacker EVM/PRC20 address)`, `bridge_token(32)`, `bridge_amount(8, u64 arbitrary)`, `data_len(4)=0`, `revert_recipient(32)`, `tx_type(1)`.
2. In the same transaction, add a no-op/read-only reference to the real gateway program address (e.g., pass it as an extra account in a `System Program` no-op instruction) so `GetSignaturesForAddress(gatewayAddr, ...)` returns this signature.
3. Submit the transaction to the target Solana cluster from an unprivileged wallet.
4. Observe that `EventListener.processSignatureBatch` → `determineEventType` → `ParseEvent` produce a `store.Event` with `Type=store.EventTypeInbound`, `Status=store.StatusPending`, and `EventData` containing the attacker-chosen recipient/token/amount — despite the real gateway program never having executed any instruction in this transaction.
5. Compare the raw Solana `Program data:` bytes (attacker's forged payload) against the resulting `store.Event` JSON to confirm the fields are accepted verbatim with no program-identity check.

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

func parseSendFundsEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	if len(decoded) < 8 {
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing sendFunds event")

	// Create store.Event
	event := &store.Event{
		EventID:           eventID,
		BlockHeight:       slot,
		Type:              store.EventTypeInbound, // Gateway events from external chains are INBOUND
		Status:            store.StatusPending,
		ExpiryBlockHeight: 0, // Will be set based on confirmation type if needed
	}

	// Parse event data from this log
	parseUniversalTxEvent(event, decoded, logIndex, chainID, logger)

	return event
}

func decodeUniversalTxEvent(data []byte, logger zerolog.Logger) (*common.UniversalTx, error) {
	if len(data) < 120 {
		logger.Warn().
			Int("data_len", len(data)).
			Msg("data might be too short for complete TxWithFunds event")
	}

	offset := 8
	payload := &common.UniversalTx{}

	// Parse sender (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for sender")
	}
	sender := solana.PublicKey(data[offset : offset+32])
	// Convert sender to hex format
	senderHex, err := base58ToHex(sender.String())
	if err != nil {
		logger.Warn().Err(err).Msg("failed to convert sender to hex, using base58")
		payload.Sender = sender.String()
	} else {
		payload.Sender = senderHex
	}
	offset += 32

	// Parse recipient (20 bytes - byte20 format)
	if len(data) < offset+20 {
		return nil, fmt.Errorf("not enough data for recipient")
	}
	// Convert 20 bytes to hex string (0x + 40 hex chars)
	recipientBytes := data[offset : offset+20]
	payload.Recipient = "0x" + hex.EncodeToString(recipientBytes)
	offset += 20

	// Parse bridge_token (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for bridge_token")

	offset += 32

		return nil, fmt.Errorf("not enough data for bridge_amount")
