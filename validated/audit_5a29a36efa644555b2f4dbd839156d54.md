### Title
Missing null-check on `AccountStore#getUnchecked` inside per-block reward-payment loop can NPE-crash block processing - ([File: chainbase/src/main/java/org/tron/core/service/MortgageService.java])

### Summary
`MortgageService.payStandbyWitness()` iterates over every standby witness and calls `payReward()` → `adjustAllowance()` for each one, unconditionally, on every single block. The inner `adjustAllowance(AccountStore, byte[], long)` fetches the witness's account with `accountStore.getUnchecked(accountAddress)` and immediately dereferences it (`account.getAllowance()`) with no null check. This mirrors the reported bug class of "external/state calls inside a loop that are not defensively checked, where a single failing iteration can abort the whole batch" — except here the "batch" is deterministic block-reward processing run by every full node, so an unhandled `NullPointerException` for any single standby witness aborts block application chain-wide rather than a single transaction.

### Finding Description
`MortgageService.payStandbyWitness()` loops over all standby witnesses and pays each one via `payReward()`: [1](#0-0) 

`payReward()` calls `adjustAllowance(byte[], long)`, which only catches `BalanceInsufficientException`, not `NullPointerException`: [2](#0-1) [3](#0-2) 

The wrapped overload fetches the account with `getUnchecked` (which returns `null` on a missing/unparseable key rather than throwing) and dereferences it without a null guard: [4](#0-3) [5](#0-4) 

This code path is invoked unconditionally on every block via `Manager.payReward()`: [6](#0-5) 

The analogous helper `VoteRewardUtil.adjustAllowance` (used by the TVM `WITHDRAWREWARD` opcode path) has the identical unguarded pattern: [7](#0-6) 

If any address processed inside these loops does not have a resolvable `AccountCapsule` (e.g., due to a missing/corrupted account record, a witness whose account entry cannot be deserialized, or any state divergence that produces a `null` from `getUnchecked`), `account.getAllowance()` throws `NullPointerException`. Because `payStandbyWitness()`/`payReward()` run inside block-completion logic (`Manager.payReward`), an uncaught exception here propagates up through block processing on **every node that applies the block**, which is a protocol-level DoS/consensus-halt condition rather than a single reverted transaction.

### Impact Explanation
Unlike the original Solidity finding — where a single reverting external call in a loop only fails one transaction — this analog is worse in class because the loop executes deterministically as part of consensus-critical block reward distribution. A crash here is not contained to one transaction; it can abort block application on all nodes that reach the same code path, producing a chain-wide denial of service / halt. This falls under "DoS via ... protocol implementation" in the accepted impact categories.

### Likelihood Explanation
Likelihood is **uncertain/low-to-moderate** and could not be fully confirmed from the indexed code: TRON's normal witness-registration invariants require an account to already exist before it can become a witness, so under expected conditions every standby witness should have a resolvable `AccountCapsule`. I was not able to locate, within the available index, a concrete unprivileged path that forces a witness's `AccountCapsule` to become unresolvable (deleted/corrupted) at the exact moment `payStandbyWitness()`/`payReward()` runs. The vulnerable code pattern (unguarded `getUnchecked()` dereference inside an unconditional per-block loop, only catching `BalanceInsufficientException`) is confirmed and real, but whether it is externally triggerable by an anonymous actor is not established here.

### Recommendation
- Add a null check after every `accountStore.getUnchecked(...)` / `repository.getAccount(...)` call inside `MortgageService.adjustAllowance`, `MortgageService.payReward`, `MortgageService.payStandbyWitness`, and `VoteRewardUtil.adjustAllowance`; skip/log the offending entry instead of dereferencing a possibly-null capsule.
- Wrap the per-witness reward logic in `payStandbyWitness()` (and the analogous loop in `IncentiveManager.reward`) in a per-iteration try/catch so one bad entry cannot abort the whole reward-distribution pass for the block/maintenance cycle.
- Add defensive assertions/tests ensuring every witness address in `WitnessStore` always has a corresponding, parseable `AccountCapsule` before it can enter the standby/active witness set.

### Proof of Concept
Not independently verified end-to-end due to indexing limits — the concrete precondition (a standby witness whose `AccountCapsule` cannot be resolved via `AccountStore.getUnchecked`) was not confirmed as reachable from an anonymous transaction in the code available. Conceptually:
1. Get a witness address into the standby-witness set (`WitnessStore.getWitnessStandby`) while ensuring/forcing its `AccountStore` entry is missing or fails `of(value)` deserialization.
2. On the next block, `Manager.payReward()` → `MortgageService.payStandbyWitness()` iterates witnesses and calls `payReward(w.getAddress(), pay)` → `adjustAllowance(witnessAddress, brokerageAmount)` → `adjustAllowance(accountStore, accountAddress, amount)`.
3. `accountStore.getUnchecked(accountAddress)` returns `null`; `account.getAllowance()` throws `NullPointerException`, uncaught in `adjustAllowance(byte[], long)`, propagating out of block-reward processing.

  public void adjustAllowance(AccountStore accountStore, byte[] accountAddress, long amount)
      throws BalanceInsufficientException {
    AccountCapsule account = accountStore.getUnchecked(accountAddress);
    long allowance = account.getAllowance();
    if (amount == 0) {
      return;
    }

    if (amount < 0 && allowance < -amount) {
      throw new BalanceInsufficientException(
          String.format("%s insufficient balance, amount: %d, allowance: %d",
              StringUtil.createReadableString(accountAddress), amount, allowance));
    }
    account.setAllowance(allowance + amount);
    accountStore.put(account.createDbKey(), account);
  }

  private void payReward(BlockCapsule block) {
    WitnessCapsule witnessCapsule =
        chainBaseManager.getWitnessStore().getUnchecked(block.getInstance().getBlockHeader()
            .getRawData().getWitnessAddress().toByteArray());
    if (getDynamicPropertiesStore().allowChangeDelegation()) {
      mortgageService.payBlockReward(witnessCapsule.getAddress().toByteArray(),
          getDynamicPropertiesStore().getWitnessPayPerBlock());
      mortgageService.payStandbyWitness();

      if (chainBaseManager.getDynamicPropertiesStore().supportTransactionFeePool()) {
        long transactionFeeReward = floorDiv(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool(),
                Constant.TRANSACTION_FEE_POOL_PERIOD,
            chainBaseManager.getDynamicPropertiesStore().disableJavaLangMath());
        mortgageService.payTransactionFeeReward(witnessCapsule.getAddress().toByteArray(),
            transactionFeeReward);
        chainBaseManager.getDynamicPropertiesStore().saveTransactionFeePool(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool()
                - transactionFeeReward);
      }
    } else {
      byte[] witness = block.getWitnessAddress().toByteArray();
      AccountCapsule account = getAccountStore().get(witness);
      account.setAllowance(account.getAllowance()
          + chainBaseManager.getDynamicPropertiesStore().getWitnessPayPerBlock());

      if (chainBaseManager.getDynamicPropertiesStore().supportTransactionFeePool()) {
        long transactionFeeReward = floorDiv(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool(),
                Constant.TRANSACTION_FEE_POOL_PERIOD,
            chainBaseManager.getDynamicPropertiesStore().disableJavaLangMath());
        account.setAllowance(account.getAllowance() + transactionFeeReward);
        chainBaseManager.getDynamicPropertiesStore().saveTransactionFeePool(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool()
                - transactionFeeReward);
      }

      getAccountStore().put(account.createDbKey(), account);
    }
  }
