Based on my investigation, I found a concrete analog to the Cork `VaultPoolLib::reserve()` bug in this repository's gas-refund flow.

### Title
Excess outbound gas fee becomes permanently untracked/stuck when both swap and no-swap refund attempts fail - (File: x/uexecutor/keeper/outbound.go)

### Summary
The Cork bug pattern is: leftover value (`Pa`) computed during a lifecycle transition (LP liquidation) is recorded/attributed but the code path that is supposed to eventually deal with it (`rationedToAmm`) never actually processes that specific bucket, so the value sits forever with no code path to reclaim it. The same "compute the leftover, attempt to move it once, and if that single attempt fails just record FAILED and move on forever" pattern exists in `applyGasRefund` in `x/uexecutor/keeper/outbound.go`.

### Finding Description
When an outbound finalizes (`FinalizeOutbound` → `handleFailedOutbound`/`handleSuccessfulOutbound`), `applyGasRefund` computes `refundAmount = gasFee - gasFeeUsed` [1](#0-0)  and attempts to return it to the user, first via a Uniswap-swap-based refund and, if that fails, via a "no-swap" fallback that deposits PRC20 directly [2](#0-1) .

If the no-swap fallback call to `CallUniversalCoreRefundUnusedGas` also fails, the code simply records `refundPcTx.Status = "FAILED"` with the error message and attaches it to `outbound.PcRefundExecution`, then returns [3](#0-2) . Crucially, this failure does **not** propagate: `handleFailedOutbound` and `handleSuccessfulOutbound` both call `applyGasRefund` and then unconditionally call `k.UpdateOutbound(ctx, utxId, outbound)`, persisting the outbound as `REVERTED`/`OBSERVED` (a terminal state) regardless of whether the refund succeeded [4](#0-3) .

There is no retry mechanism, no queue of "pending refunds," and no admin/keeper flow that revisits a `PcRefundExecution.Status == "FAILED"` outbound to reattempt the refund — a global search for `RetryRefund` and similar patterns turned up nothing. Once the outbound reaches its terminal status, the excess gas amount that was already deducted/held (as PRC20 or bridged token accounting inside the `UniversalCore`/UE module) is never revisited, exactly analogous to Cork's `VaultPoolLib::rationedToAmm()` never processing the `Pa` bucket after it was set aside.

### Impact Explanation
Whenever the swap-based refund and the fallback no-swap refund both fail (e.g., transient EVM call failure, price/slippage protection tripping `minPCOut`, quoter revert, or `UniversalCore` insufficient liquidity/balance), the excess gas fee that belongs to the user is permanently lost from their perspective — it is not returned to them and there is no mechanism to trigger the refund again. This is a fund-loss condition reachable through ordinary, unprivileged use: any user whose outbound consumes less gas than budgeted (a normal occurrence) is subject to this failure mode whenever the refund call happens to fail on either path.

### Likelihood Explanation
Likelihood is moderate: `applyGasRefund` runs for every finalized outbound (both success and failure paths) whenever `gasFee > gasFeeUsed`, which is the common case since gas fees are pre-budgeted. The refund call is a synchronous cross-contract EVM call (`DerivedEVMCall` into `UniversalCore.refundUnusedGas`) whose success depends on external conditions (swap liquidity/quote validity, module account state) that are not fully within the node's control, so transient failures of both the swap and no-swap paths are plausible in production, especially under gas-token liquidity stress.

### Recommendation
Do not silently terminate on refund failure. When both the swap and no-swap refund attempts fail, either:
1. Keep the outbound (or a dedicated retry record) in a non-terminal/pending-refund state and re-enter it into a periodic retry queue (similar to `PendingOutbounds`) until the refund succeeds, or
2. Escalate to `AbortOutbound`-style manual intervention (as already done for failed re-mints in `handleFailedOutbound`) rather than treating a failed refund as an implicitly closed, unrecoverable case.

### Proof of Concept
1. Set up an outbound (FUNDS or GAS_AND_PAYLOAD) with `GasFee` (budgeted) greater than the eventual `GasFeeUsed` reported via `MsgVoteOutbound`, as in `test/integration/uexecutor/gas_fee_refund_test.go` [5](#0-4) .
2. Configure the environment so `GetDefaultFeeTierForToken`/`getSwapQuoteForRefund` fail (simulating no configured fee tier or quoter unavailability) — this is already exercised by the "swap fallback reason stored when swap refund fails" test [6](#0-5) .
3. Additionally make the no-swap fallback (`CallUniversalCoreRefundUnusedGas` with `withSwap=false`) fail (e.g., `UniversalCore` module account has insufficient PRC20/PC balance for the excess amount).
4. Observe that `outbound.PcRefundExecution.Status == "FAILED"` and `outbound.OutboundStatus` is still set to a terminal value (`REVERTED` or stays `OBSERVED`) via `UpdateOutbound`, with no subsequent code path ever revisiting this outbound to retry the refund — the excess gas fee is permanently unaccounted for.

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
