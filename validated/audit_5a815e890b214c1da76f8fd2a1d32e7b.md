### Title
Truncating division of `LegacyDec` base fee to zero causes free (unbilled) universal payload execution - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` in `x/uexecutor/keeper/fees.go` converts the feemarket's `LegacyDec` base fee into an "upc" amount using an integer `Div` by `1e18` rather than proper `LegacyDec` rounding/scaling helpers [1](#0-0) . This mirrors the reported bug class: a hand-rolled precision/rounding step that can silently truncate a small positive value down to zero, producing an incorrect "free" outcome instead of the expected non-zero cost.

### Finding Description
`DeductGasFeesFromReceipt` reads the current EIP-1559 base fee via `k.feemarketKeeper.GetBaseFee(sdkCtx)` and feeds it into `CalculateGasCost` to compute the gas cost billed to the UEA/CEA account after every universal payload execution [2](#0-1) . Inside `CalculateGasCost`, the code assumes "the base fee is always a whole number of upc -- no fractional upc exists" and unwraps the `LegacyDec` by doing `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`, i.e. plain truncating integer division [1](#0-0) .

This assumption is not enforced anywhere in the scoped code: `GetBaseFee` returns whatever `LegacyDec` the feemarket module's EIP-1559 controller has computed for the current block, and that value is the result of proportional adjustments (elasticity multiplier, gas-used/gas-target ratios, base-fee-change denominator) each block — arithmetic that routinely produces non-integer `upc` amounts (fractional `LegacyDec` values below `1e18` in the low digits, or a `LegacyDec` whose whole-upc part underflows to `0` if the base fee itself decays to sub-1-upc levels, e.g., after a period of low gas usage). Whenever the base fee's fractional-upc remainder pushes the true value under `1` full `upc` unit (or the base fee decays toward zero, which EIP-1559-style controllers allow), `baseFeeBig.Div(..., 1e18)` truncates to `0`. `effectiveGasPrice` is then `0`, so `gasCost := effectiveGasPrice * gasUsed` is `0` regardless of how much gas the executed universal payload actually consumed [3](#0-2) .

Back in `DeductGasFeesFromReceipt`, a `gasCost.Sign() <= 0` short-circuits the whole billing path and returns `nil` (success, no fee taken) [4](#0-3) . This is invoked from `ExecutePayloadV2`, the function that executes a `DerivedEVMCall`-style universal payload against a UEA and is specifically wrapped in a cache-context precisely to prevent "free execution" if fee deduction fails [5](#0-4) . That safeguard only protects against *failed* deduction; a deduction that *succeeds* while computing `0` is invisible to it — the EVM state change from `CallUEAExecutePayload` is committed via `writeCache()` with zero gas actually collected.

### Impact Explanation
When the truncation condition is hit, any unprivileged user submitting a universal payload for execution via a UEA/CEA gets their arbitrary EVM call executed for free, with real `GasUsed` but zero `upc` burned. This is a protocol-level underpayment/loss for the fee-burning mechanism used to price universal execution, directly reachable from the default inbound/payload-execution flow (`ExecutePayloadV2` → `DeductGasFeesFromReceipt` → `CalculateGasCost`), without any validator, TSS, or admin involvement — matching the "unauthorized module-originated EVM execution"/"corruption of gas fee accounting" impact categories in the target scope.

### Likelihood Explanation
Exploitability depends entirely on the feemarket base fee's actual numeric behavior, which lives in the external `github.com/cosmos/evm` feemarket keeper (not itself part of this repo, so its exact adjustment formula/precision could not be directly inspected in this review). Genesis/test configs in this repo set the base fee to large integer `upc` values (e.g. `1000000000` upc) [6](#0-5) , so under typical configured minimums the truncation bug would not manifest immediately. However, EIP-1559-style base fee controllers are proportional/multiplicative and can decay the base fee toward very small (sub-1-upc) `LegacyDec` values after sustained low gas usage, or leave non-zero fractional remainders after adjustment — and the code's in-repo comment explicitly (and incorrectly) assumes this can never happen. Because the root-cause code (the truncating `Div`) lives in scoped, custom Push Chain code and the precondition (a small/fractional base fee) is a plausible, attacker-unprivileged consensus state rather than a privileged action, this is a genuine analog of the reported bug class, though likelihood is contingent on base-fee dynamics that could not be fully confirmed from this codebase alone.

### Recommendation
- Do not assume the base fee is always a whole `upc` integer. Use `LegacyDec.Ceil().RoundInt()` (as is already done correctly for the ante-handler min-gas-price check in `app/cosmos/min_gas_price.go`) instead of a truncating raw `big.Int` `Div` [7](#0-6) .
- After computing `gasCost`, assert it is non-zero whenever `gasUsed > 0` and the base fee itself is non-zero; if truncation would produce `0` from a genuinely positive base fee, round up (ceil) rather than down so the protocol never bills `0` for non-zero consumed gas.
- Add an explicit round-trip test feeding a fractional/sub-1-upc `LegacyDec` base fee into `CalculateGasCost` to confirm the returned `gasCost` is never `0` when `gasUsed > 0` and `baseFee > 0`.

### Proof of Concept
1. Assume the feemarket base fee decays (via the external EIP-1559 controller) to a `LegacyDec` value below `1 upc`, e.g. `baseFee = 0.5` upc, whose internal `BigInt()` representation is `5 * 10^17`.
2. A user submits a universal payload executed via `ExecutePayloadV2` → `CallUEAExecutePayload`, consuming real EVM gas (`receipt.GasUsed > 0`).
3. `DeductGasFeesFromReceipt` calls `CalculateGasCost(baseFee, ...)`; inside, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` computes `5*10^17 / 10^18 = 0` (integer division) [1](#0-0) .
4. `effectiveGasPrice = 0`, so `gasCost = 0 * gasUsed = 0` [8](#0-7) .
5. `DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns `nil` without burning any fee [4](#0-3) ; `ExecutePayloadV2` then commits the executed EVM call via `writeCache()` [9](#0-8) , granting the user free universal execution.

Note: I was unable to inspect the external `github.com/cosmos/evm` feemarket module's exact base-fee update arithmetic in this repository's index to conclusively prove sub-1-upc/fractional base fees occur in production; this should be independently verified (or the guard added regardless as defense-in-depth) since the vendored dependency source is outside this repo's indexed scope.

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
```

```go
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr
	}

	// Both succeeded — commit EVM state and fee deduction together.
	writeCache()
```
