### Title
Starknet OS `execute_replace_class` skips the "class is declared" check enforced by blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The reported bug class is "an action that should be restricted to a valid/qualified target (active validators) is not actually restricted, allowing operations against invalid targets." The closest reachable analog in this sequencer is the `replace_class` syscall: blockifier (the Rust execution engine that actually builds blocks) requires the new class hash to be a *declared* class before allowing `replace_class` to succeed, but the Starknet OS Cairo implementation used for re-execution/proving performs no such check.

### Finding Description
In blockifier, `replace_class` explicitly enforces that the target class hash is declared before mutating state: [1](#0-0) 
which calls `syscall_handler.state.get_compiled_class(request.class_hash)?` and fails (returning `StateError::UndeclaredClassHash`) if the class was never declared, as verified by the dedicated tests: [2](#0-1) [3](#0-2) 

The Cairo Starknet OS implementation of the same syscall, however, contains an explicit acknowledged gap: [4](#0-3) 
Line 902 literally states: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The function proceeds directly to write a new `StateEntry` with the (unverified) `class_hash` into `contract_state_changes` without ever checking declaration status. The older/deprecated OS syscall path has the identical unchecked behavior: [5](#0-4) 

This is a known, intentional design limitation of the OS elsewhere too — the fuzz test feature contract explicitly documents that the OS "does not prove class hashes do not exist" for similar operations such as `deploy_syscall` targeting a nonexistent class: [6](#0-5) 

Because blockifier is the execution engine that actually builds the block, and the Starknet OS is used to independently re-execute/verify the same transaction trace to produce the block's STARK proof, any place where the two engines apply different validation rules for the *same* syscall is a correctness hazard: the OS must reproduce exactly the state transition (and revert/failure behavior) that blockifier produced when building the block, or the OS-computed state commitment/block hash will not match the one blockifier actually committed.

### Impact Explanation
If blockifier rejects (reverts/fails) a transaction because `replace_class` targets an undeclared class hash, but the OS re-execution of the identical transaction does not perform this check and instead succeeds in writing the new (undeclared) class hash to `contract_state_changes`, the OS-derived state diff/root for that block will diverge from the state diff/root blockifier actually committed on-chain. This falls squarely into "wrong committed root or block hash" / "honest-node divergence," since the OS's re-execution is the basis for proof generation and, ultimately, network-wide validation of block correctness.

### Likelihood Explanation
Reaching `replace_class` requires nothing more than a normal, unprivileged Cairo1 contract invocation containing a `replace_class_syscall` call with an attacker-chosen, undeclared class hash — fully reachable from a single submitted transaction with no special privileges. However, the actual severity depends on details not fully verifiable from the available Cairo/Rust snippets alone: (1) whether a `replace_class` failure in blockifier is "unrecoverable" (aborts the whole transaction, matching the `DeployNonExisting`/`LibraryCallNonExisting` "unrecoverable, not provable" pattern noted in the fuzz test) versus a catchable/library-scoped error, and (2) whether the OS's hint-driven `GetContractAddressStateEntry`/prover-side inputs are constrained elsewhere (e.g., by a separate declared-class consistency check performed at a different stage of OS execution, such as final state-diff commitment) that would still catch this before block hash computation. I could not fully trace those OS-side invariants within the available index, so this should be treated as a **credible but not fully confirmed** divergence risk requiring deeper verification (e.g., actually running blockifier vs. OS re-execution on a crafted transaction) before treating it as a confirmed critical/high bug.

### Recommendation
Implement the check called out by the existing TODO: before writing the new `StateEntry` in `execute_replace_class` (both the current syscall_impls.cairo version and the deprecated_execute_syscalls.cairo version), verify that `class_hash` corresponds to a declared class (mirroring blockifier's `get_compiled_class` check), and fail/panic consistently with blockifier's behavior on undeclared class hashes so that OS re-execution can never silently diverge from actual block-building execution.

### Proof of Concept
1. Deploy a Cairo1 contract exposing an entry point that calls `replace_class_syscall(class_hash)` with a caller-supplied `class_hash` (e.g., `test_replace_class`, as used in blockifier's own tests: [7](#0-6) ).
2. Submit an invoke transaction calling this entry point with an undeclared, arbitrary class hash (e.g., `0x1234`, never declared on-chain).
3. In blockifier's block-building execution, this call fails with `StateError::UndeclaredClassHash` (per the same test), so the transaction reverts/fails and no class-hash state change is committed.
4. Feed the identical transaction/trace to the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo`); because the OS does not check declaration status (per the TODO at line 902), if the OS's control flow reaches this point with the same hinted state entry, it would write the new (undeclared) class hash into `contract_state_changes` unconditionally, producing a state diff inconsistent with what blockifier actually committed.
5. Confirming full exploitability requires validating step 4 against blockifier's actual failure semantics (unrecoverable vs. revertible) and any OS-side safety net not visible in the reviewed files — this is flagged as unverified in the Likelihood section above.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
