Stale/unrevoted push-oracle gas price accepted without freshness check in fee, revert, and TSS fund-migration accounting - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/gas_fee.go`, `x/uexecutor/keeper/chain_meta.go`, `x/utss/keeper/msg_initiate_fund_migration.go`)

### Summary
Push Chain's `ChainMeta` gas-price oracle (`x/uexecutor`) is a validator-push oracle analogous to the "Pyth vs. fallback" pattern in the source report: UVs periodically vote a gas price/height (`VoteChainMeta`), and stale (>300s) votes are excluded only from the *median computation* on the write path. Every consumer of the resulting on-chain value (`gasPriceByChainNamespace`, `l1GasFeeByChainNamespace`, `tssFundMigrationGasLimitByChainNamespace` on `UniversalCore`) reads the last-applied value with **no freshness check whatsoever**, even though a `timestampObservedAtByChainNamespace` view exists on the contract and is never called from Go code.

### Finding Description
`VoteChainMeta` in `x/uexecutor/keeper/chain_meta.go` filters votes older than `chainMetaVoteStalenessSeconds` (300s) out of the `fresh` pool used to compute the median [1](#0-0) . Crucially, if `len(fresh) == 0` (all validators' last votes have aged out — e.g., because the off-chain gas-price fetchers/`ChainMetaOracle` stalled, an RPC endpoint died, or the interval configuration drifted), the keeper simply records the vote and returns **without calling `CallUniversalCoreSetChainMeta`** [2](#0-1) . The last value written to `UniversalCore` therefore persists indefinitely — it is never invalidated, zeroed, or flagged as stale on-chain.

Every downstream consumer reads this potentially arbitrarily-old value with no staleness gate:
- `GetGasPriceByChain`, `GetL1GasFeeByChain`, `GetTssFundMigrationGasLimitByChain` in `x/uexecutor/keeper/evm.go` call the contract's `gasPriceByChainNamespace` / `l1GasFeeByChainNamespace` / `tssFundMigrationGasLimitByChainNamespace` views directly and return the raw value [3](#0-2) [4](#0-3) .
- `GetOutboundTxGasAndFees` (used by `buildRevertOutbound` and by outbound gas/fee attachment) unpacks `gasPrice`/`gasFee` from `getOutboundTxGasAndFees` with no staleness check, and these values are written directly into `OutboundTx.GasFee`/`GasPrice`, which drive PRC20 gas deduction/refund logic [5](#0-4) .
- `InitiateFundMigration` fetches `gasPrice`, `gasLimit`, and `l1GasFee` from the same stale-capable source and bakes them into the `FundMigration` record used to build and sign the actual TSS-signed migration transaction that sweeps funds from the old TSS key to the new one [6](#0-5) .
- The ABI exposes a `timestampObservedAtByChainNamespace` view specifically meant to answer "how fresh is this?" [7](#0-6) , but it is never invoked anywhere in the Go codebase outside its own ABI declaration — confirmed by search returning only the ABI definition file.

This is the same root-cause class as the external report: a push-type value that can silently go stale is consumed by financial logic (fee deduction, gas refund computation, TSS fund-migration transaction construction) without any deviation/staleness gate, creating an arbitrage/mispricing window that a normal unprivileged user can trigger simply by transacting during a period when the oracle has stopped receiving fresh votes (e.g., degraded RPC connectivity to the external chain, oracle worker restart, or a long period without price movement causing infrequent re-votes past the 300s window).

### Impact Explanation
If the real-world gas price on the destination chain rises while the on-chain `ChainMeta` price is stuck at an old (lower) value, `GetOutboundTxGasAndFees`/`applyGasRefund` will under-collect gas fees from users relative to what UVs must actually spend broadcasting outbound/revert/rescue transactions, and `InitiateFundMigration` will similarly under-provision `GasLimit`/`GasPrice`/`L1GasFee` for a TSS-signed migration transaction sweeping the vault balance — risking an underfunded or stuck migration transaction, or a mismatch between the computed transfer amount (`balance - gas - L1`) and reality. Because the impact is bounded by external gas-price economics rather than a direct unauthorized mint/drain, this sits closer to protocol-level fee mispricing / value misrouting than a wholesale fund-theft primitive; the fund-migration signing hash is independently reconstructed and cross-checked in `verifyFundMigrationSigningRequest`, which limits (but does not eliminate) the blast radius since the actual transferred amount is still derived from the stale gas price/limit inputs.

### Likelihood Explanation
Triggering requires no privileged access — an ordinary user submitting cross-chain transactions during a genuine oracle staleness window (validator gas-price workers down, RPC outage, or simply a long quiet period exceeding 300s without a re-vote) is sufficient; no malicious validator/relayer/oracle collusion is needed, satisfying the "unprivileged attacker" gate. However, actually profiting requires the real external gas price to have moved meaningfully while the Push-Chain-side value sits frozen, which is an opportunistic/timing-dependent condition rather than something an attacker can force at will.

### Recommendation
Read-side consumers (`GetGasPriceByChain`, `GetL1GasFeeByChain`, `GetTssFundMigrationGasLimitByChain`, `GetOutboundTxGasAndFees`) should call `timestampObservedAtByChainNamespace` (or store/expose a Go-side `LastAppliedChainHeight`/staleness timestamp already present in `ChainMeta.StoredAts`) and reject or degrade gracefully (e.g., pause outbound/gas-fee-dependent flows, widen slippage/markup, or require fresh re-votes) when the observed-at timestamp exceeds a defined staleness bound, mirroring the write-side `chainMetaVoteStalenessSeconds` gate. Additionally, `VoteChainMeta`'s `len(fresh) == 0` branch should actively signal staleness on-chain (e.g., via an explicit "stale" status field or event) rather than silently leaving the last value untouched.

### Proof of Concept
Not independently reproducible from static analysis alone — the vulnerability is a missing validation (absence of a call to `timestampObservedAtByChainNamespace`) rather than a broken computation, so no single crafted transaction demonstrates it; exploitation requires an actual real-world gas-price divergence coinciding with an oracle staleness window, which cannot be constructed in a unit-test PoC without simulating external-chain price movement. This is flagged as an assessment gap: a Devin session with access to the full `UniversalCore` Solidity contract and a testnet/regtest environment would be needed to construct an end-to-end PoC showing under-collection of gas fees or an underfunded fund-migration transaction.

// GetGasPriceByChain reads the gas price for a chain from the UniversalCore contract.
func (k Keeper) GetGasPriceByChain(ctx sdk.Context, chainNamespace string) (*big.Int, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, abi, ueModuleAccAddress, handlerAddr, false, nil, "gasPriceByChainNamespace", chainNamespace)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call gasPriceByChainNamespace")
	}

	results, err := abi.Methods["gasPriceByChainNamespace"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack gasPriceByChainNamespace result")
	}

	return results[0].(*big.Int), nil
}

func (k Keeper) GetOutboundTxGasAndFees(ctx sdk.Context, prc20 common.Address, gasLimitWithBaseLimit *big.Int) (*GasFeeInfo, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
}
