## Analog Identified

The RizLeverager bug is a classic "**repeated integer-division truncates a per-operation fee to zero**" pattern. The direct analog in Push Chain's scoped Go code is in the recipient gas-fee accounting used for inbound `executeUniversalTx` calls, in `x/uexecutor/keeper/fees.go`.

### Title
Recipient Gas-Fee Truncation to Zero in `CalculateGasCost` Lets Inbound Payload Execution Run Uncharged - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` unwraps the feemarket's `LegacyDec` base fee to a raw integer "upc" amount using a plain, non-rounding integer division (`baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`), then multiplies by `gasUsed` to compute what a CEA/UEA recipient owes for EVM execution consumed on its behalf. Whenever the network's current base fee (as tracked by the feemarket module) is less than 1 whole `upc` unit, this division truncates the effective gas price to `0`, making the entire computed `gasCost` `0` regardless of how much gas was actually consumed.

### Finding Description [1](#0-0) 

`CalculateGasCost` documents its own assumption that "the base fee is always a whole number of upc," but nothing enforces this. The feemarket's EIP-1559-style base-fee adjustment algorithm changes the base fee by fractional increments (percentage-based up/down adjustment per block), so the `LegacyDec` value can easily land on a non-integer-upc value (e.g. `0.875` upc). When that happens, `baseFeeBig` (the internal `1e18`-scaled representation) is smaller than `1e18`, and the `Div` truncates it to `0`.

`DeductGasFeesFromReceipt` then calls this function and only skips deduction if the *result* is `<= 0`; there is no `Ceil()` or minimum-charge safeguard analogous to what's used elsewhere in the same codebase (e.g. `app/ante/validator_tx_fee.go` and `app/cosmos/min_gas_price.go`, both of which explicitly `Ceil()` when computing required fees to avoid this exact class of bug): [2](#0-1) [3](#0-2) 

The recipient of an inbound `FUNDS_AND_PAYLOAD` universal payload (an ordinary, unprivileged CEA/UEA target contract on Push Chain, reachable through the default inbound-voting → `executeUniversalTx` flow) is charged via `DeductAndBurnFees` for gas actually consumed by its own contract logic. If the truncation condition holds, this charge is always `0` — the contract's EVM execution (storage writes, external calls, etc.) proceeds and is committed, but the "gas cost" siphoned from the recipient's upc balance and burned is zero, no matter how much gas was consumed.

### Impact Explanation
This breaks the "gas fee accounting must be proportional to gas used" invariant explicitly called out in scope ("corruption of ... gas fee accounting"). Any unprivileged actor with a smart-contract recipient of inbound universal payloads can consume unlimited EVM execution for that recipient with zero fee burn whenever the network base fee sits below 1 whole `upc` — a condition that arises naturally under low chain congestion via ordinary EIP-1559-style base-fee decay, not through any privileged action. This is a systemic, silent gas-fee bypass (not a one-off rounding dust issue): once base fee drops under the 1-upc threshold, *every* inbound contract-call recipient is charged zero, persistently, until base fee climbs back above the threshold — enabling free, unmetered compute consumption at the recipient's expense-avoidance and the protocol's/network's cost.

### Likelihood Explanation
High. No attacker action beyond normal inbound payload submission is required — the exploitable condition (base fee `< 1e18` in `LegacyDec` terms) is a routine consequence of the feemarket's percentage-based fee adjustment mechanism during any period of low network usage, which is expected behavior for a fee market, not an edge case requiring adversarial manipulation of the fee mechanism itself.

### Recommendation
Round the effective gas price calculation up (ceiling) rather than truncating, consistent with the pattern already used in `app/ante/validator_tx_fee.go` and `app/cosmos/min_gas_price.go`:
- Compute `gasCost` using `LegacyDec` multiplication and `.Ceil().RoundInt()` (or equivalent) instead of first truncating `baseFee` to an integer via raw `big.Int` division.
- Alternatively, only skip the deduction if `gasUsed == 0`, and otherwise guarantee a minimum charge of `1` unit whenever `gasUsed > 0` and `baseFee > 0`.

### Proof of Concept
1. Let feemarket base fee decay (via normal low-congestion operation) to a `LegacyDec` value below `1.0` (e.g., `0.9` upc-equivalent).
2. An unprivileged user submits an inbound bridge transaction with `TxType_FUNDS_AND_PAYLOAD` targeting their own deployed contract, whose payload performs storage-heavy execution consuming significant `gasUsed`.
3. Honest validators vote and finalize the inbound; `DeductGasFeesFromReceipt` → `CalculateGasCost` computes `effectiveGasPrice = baseFeeBig.Div(_, 1e18) = 0`, so `gasCost = 0`.
4. `DeductAndBurnFees` is skipped/burns `0`; the contract's execution is fully applied on-chain (as confirmed by existing tests such as `test/integration/uexecutor/inbound_cea_smart_contract_test.go`'s "gas fees deducted from smart contract recipient" case, which currently only asserts fees are *reduced*, not that they are non-zero in this scenario) with no cost to the recipient. func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
