Based on my investigation, I found a concrete on-chain analog to the flash-loan risk mitigation weakness in the "gas abstraction" auto-swap flow, which relies on a live Uniswap V3 spot-price quote with a fixed slippage tolerance instead of any manipulation-resistant pricing mechanism.

### Title
Gas-abstraction auto-swap uses a manipulable spot-price quote with fixed 5% slippage, allowing an unprivileged attacker to sandwich `GAS`/`GAS_AND_PAYLOAD` inbound execution and drain value from the deposit swap - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/evm.go`)

### Summary
For `GAS` and `GAS_AND_PAYLOAD` inbound types, `x/uexecutor` deposits a user's bridged gas-token PRC20 and immediately auto-swaps it to native PC via `UniversalCore.depositPRC20WithAutoSwap`. The minimum acceptable output (`minPCOut`) is derived by calling `QuoterV2.quoteExactInputSingle` for a live spot-price quote and applying a flat 5% slippage buffer [1](#0-0) , then executing the swap against that same manipulable pool [2](#0-1) . Unlike the Gro report where an *optional, owner-controlled* EOA-only gate was the (weak) flash-loan mitigation, here there is no gate or TWAP protection at all — the module trusts the instantaneous QuoterV2 output as ground truth and only bounds slippage relative to that same, attacker-influenceable number.

### Finding Description
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96 = 0`, which returns the current spot-price-derived quote of the pool, not a time-weighted average [3](#0-2) . `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap` then compute `minPCOut = quote * 95 / 100` and pass it straight into `CallPRC20DepositAutoSwap` in the very same keeper call [4](#0-3) [5](#0-4) .

Because both the quote and the swap read the same on-chain pool state at essentially the same point in block execution, the 5% slippage tolerance only protects against noise between quote and execution — it provides zero protection against an attacker who has already moved the pool's spot price before the inbound's finalizing `MsgVoteInbound` transaction lands. An unprivileged actor can:
1. Observe a pending cross-chain deposit destined to trigger `GAS`/`GAS_AND_PAYLOAD` processing (or simply pre-position ahead of routine gas-abstraction traffic, since these deposits are a normal, frequent, permissionless user flow).
2. Submit an ordinary swap against the same PRC20/WPC Uniswap V3 pool, in the same block and ordered before the validator's quorum-reaching `MsgVoteInbound`, to push the spot price down.
3. Let the module's `GetSwapQuote` read the manipulated price and compute a `minPCOut` based on it — the "protection" tracks the manipulated price rather than a fair market price.
4. Optionally reverse the price move afterward (sandwich), extracting the difference between the fair value and the manipulated execution price from the protocol-controlled swap.

This mirrors the root cause in the referenced report: an "optional"/incomplete guard (there, EOA-only; here, a 5%-off-current-quote check) is trusted as the sole flash-loan/price-manipulation defense for a protocol operation that moves real value, while the underlying oracle/quote source itself remains attacker-reachable and unauthenticated against manipulation.

### Impact Explanation
Each `GAS`/`GAS_AND_PAYLOAD` inbound execution is an automatic, permissionless, module-driven swap of protocol/user PRC20 into native PC [6](#0-5) . If the spot price can be manipulated immediately before this swap executes, the recipient UEA/account receives less PC than fair value, and the difference is captured by the attacker from the pool/protocol liquidity — this is a direct corruption of PRC20/native asset accounting reachable by an ordinary unprivileged user performing standard swaps on the same DEX pool, satisfying the "corruption of PRC20 or native asset accounting" allowed-impact category.

### Likelihood Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound (a routine, expected transaction type for gas abstraction) goes through this exact code path with no per-swap deadline enforcement at the module layer (`deadline = 0` lets the contract fall back to its own default) [7](#0-6)  and no TWAP or oracle cross-check. Any user who can trade on the underlying Uniswap V3 pool (an unprivileged, permissionless action) can attempt this, and the attack requires no validator/relayer collusion — it only requires ordinary transaction ordering within a block that includes the finalizing vote.

### Recommendation
Replace or supplement the spot `quoteExactInputSingle` call with a TWAP-based price check (e.g., pool `observe`/cumulative-tick averages over a meaningful window) and reject swaps whose spot price deviates beyond a bounded threshold from the TWAP, rather than deriving `minPCOut` purely from the same spot quote being executed against.

### Proof of Concept
1. Identify the PRC20↔WPC Uniswap V3 pool used for a given gas token via `GetUniversalCoreQuoterAddress`/`GetDefaultFeeTierForToken` [8](#0-7) .
2. As an ordinary user, submit a large swap into that pool to depress the PRC20 price relative to WPC, timed to land in the same block before the validator's quorum `MsgVoteInbound` for a pending `GAS`/`GAS_AND_PAYLOAD` inbound.
3. The module's `GetSwapQuote` reads the depressed price and computes `minPCOut` at 95% of that depressed quote [9](#0-8) ; `CallPRC20DepositAutoSwap` executes at the same depressed price.
4. Reverse the initial swap in the same or a following block, realizing the difference between fair value and the manipulated execution price at the expense of the deposited PRC20/PC accounting.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
