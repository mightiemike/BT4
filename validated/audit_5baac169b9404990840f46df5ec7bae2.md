### Title
Truncating base-fee normalization in `CalculateGasCost` causes silent zero-cost gas fee deduction for UEA payload execution - (File: x/uexecutor/keeper/fees.go)

### Summary
`DeductGasFeesFromReceipt` charges the executing UEA/CEA-recipient for the EVM gas consumed by a `MsgExecutePayload` execution, using `CalculateGasCost` to derive the fee. That function divides the fee-market base fee (an 18-decimal-precision `LegacyDec`, i.e. wei-denominated) by `1e18` a second time before multiplying by `gasUsed`. For any realistic EVM base fee (tens of gwei, i.e. far below `10^18` wei), this integer division truncates to zero, making `effectiveGasPrice == 0` and thus `gasCost == 0`. `DeductGasFeesFromReceipt` treats `gasCost.Sign() <= 0` as "nothing to charge" and silently returns `nil` — the analog of the Lido `wstETHAmount == 0` case where a computed conversion result can legitimately be zero and the code proceeds without any guard or revert.

### Finding Description
`CalculateGasCost` in [1](#0-0)  computes gas cost as follows: [2](#0-1) 

`baseFee` comes from `k.feemarketKeeper.GetBaseFee(sdkCtx)` [3](#0-2) , which in cosmos-evm-based chains returns the base fee expressed directly in the smallest EVM unit (wei-equivalent for a token with 18 decimals) via `LegacyDec` (which itself has 18 decimal-place internal precision, unrelated to the semantic scale of the value it stores). The code comment asserts that `baseFee.BigInt()` needs a division by `1e18` to "unwrap the LegacyDec encoding," but this conflates `LegacyDec`'s internal decimal-place representation with the token's own 18-decimal denomination. In practice, the resulting `baseFeeBig` after `.BigInt()` already represents the fee in the token's minimal (wei-equivalent) unit; dividing it again by `1e18` shrinks any base fee below `10^18` wei/gas (i.e., anything less than an artificial 1-upc-per-gas-unit price — several orders of magnitude above realistic gas prices, which are typically in the `10^9`–`10^10` wei range) straight to `0`.

`effectiveGasPrice` is then set to this truncated `baseFeeBig` [4](#0-3) , and `gasCost = effectiveGasPrice * gasUsed` [5](#0-4) . Since `effectiveGasPrice` is `0`, `gasCost` is always `0` for any realistic base fee.

Downstream, `DeductGasFeesFromReceipt` treats this as "nothing to bill" and returns success without deducting or burning any coin: [6](#0-5) 

This path is reached from `ExecutePayloadV2` [7](#0-6) , which is invoked by the fully unprivileged, gasless `MsgExecutePayload` message documented in `app/txpolicy/gasless.go` [8](#0-7) . Any external address can submit `MsgExecutePayload` for any UEA with a valid `verificationData`, and the same zero-cost path is also exercised for CEA smart-contract recipients via `DeductGasFeesFromReceipt` in `execute_inbound_gas_and_payload.go` and `execute_inbound_funds_and_payload.go` [9](#0-8) [10](#0-9) .

### Impact Explanation
This corrupts the gas-fee accounting invariant that the module's own README documents (UEA-executed EVM gas must be deducted from the UEA balance via `DeductGasFeesFromReceipt`). Because `gasCost` silently evaluates to zero for all realistic base fees, arbitrary EVM computation triggered via `MsgExecutePayload` (and CEA `executeUniversalTx` calls) executes for free regardless of `gasUsed`, letting any unprivileged actor consume unbounded validator compute through repeated `MsgExecutePayload` submissions without ever paying the intended fee — a resource-exhaustion / fee-evasion vector reachable through the ordinary, documented user-submission path, with no privileged assumption required.

### Likelihood Explanation
High. `MsgExecutePayload` is a normal gasless message any account can submit (no bonding or admin role required), the target UEA merely needs a valid owner-signed payload the attacker doesn't even need to own, and the truncation triggers deterministically for every network-realistic base fee value — it is not an edge case requiring adversarial market manipulation.

### Recommendation
Remove the erroneous extra `1e18` division in `CalculateGasCost`; use `baseFee.BigInt()` directly (or the correctly-scaled token-unit value) as `effectiveGasPrice`, and additionally guard `DeductGasFeesFromReceipt` so that `gasUsed > 0` combined with a non-nil receipt but `gasCost == 0` is investigated/rejected rather than silently treated as a no-op — mirroring the recommended `require(amount > 0)` pattern from the source report, adapted to "require fee > 0 whenever gas was actually consumed."

### Proof of Concept
1. Configure the feemarket with a realistic base fee, e.g. `20 gwei = 20_000_000_000` (`2×10^10`), represented as `sdkmath.LegacyDec` via `GetBaseFee`.
2. Submit a `MsgExecutePayload` (gasless, callable by any account) targeting a UEA with a valid `verificationData`/payload that consumes non-trivial `GasUsed` (e.g. 100,000 gas) — reachable in `ExecutePayloadV2` [11](#0-10) .
3. Trace `CalculateGasCost(baseFee=2×10^10, ...)`: `baseFeeBig.Div(baseFeeBig, 1e18)` → `0`; `effectiveGasPrice = 0`; `gasCost = 0 * 100000 = 0`.
4. `DeductGasFeesFromReceipt` hits `if gasCost.Sign() <= 0 { return nil }` [12](#0-11)  and returns success without calling `DeductAndBurnFees`.
5. Repeat step 2 arbitrarily many times at zero cost to the caller — confirmable by observing the UEA's/recipient's `upc` balance is unchanged across repeated executions with non-zero `GasUsed`.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}
