## Finding: Missing program-invocation binding allows forged gateway events via unrelated logs in the same transaction

### Title
Unauthenticated log-to-program binding lets an unprivileged actor forge `sendFunds`/outbound gateway events, resulting in fabricated inbound observations - (File: `universalClient/chains/svm/event_listener.go`, `universalClient/chains/svm/event_parser.go`)

### Summary
`processSignatureBatch` in `event_listener.go` iterates over **every** log line of any transaction that merely references the gateway address as an account key, and `determineEventType`/`ParseEvent` in `event_parser.go` classify a log purely by decoding its base64 bytes and matching the first 8 bytes against a discriminator table — with no check that the log was actually emitted by an invocation of the gateway program itself.

### Finding Description
`processSignatureBatch` fetches transactions returned by `GetSignaturesForAddress(gatewayAddr, ...)` and then loops blindly over `tx.Meta.LogMessages`: [1](#0-0) 

`determineEventType` only checks the `"Program data: "` prefix and decodes/matches the discriminator bytes — it never checks which program actually emitted the log (Solana log output records program invocation boundaries as separate `Program <id> invoke [n]` / `Program <id> success` lines, which are not parsed or correlated here): [2](#0-1) 

`ParseEvent` and `parseSendFundsEvent`/`parseOutboundObservationEvent` likewise only look at the log string content, not its provenance: [3](#0-2) 

`GetSignaturesForAddress` on Solana returns any transaction where the target pubkey appears as an account key in any instruction — it does not require that pubkey to be an executed program ID. An unprivileged actor can therefore submit a single transaction that:
1. Includes the gateway program's address as an inert, unused account reference in one instruction (so the transaction is indexed under the gateway address), and
2. Invokes their own attacker-deployed program in a separate instruction of the same transaction, which calls `sol_log_data`/`emit!` to produce an arbitrary `"Program data: <base64>"` log whose first 8 bytes match the `send_funds` (or `finalize_universal_tx`/`revert_universal_tx`) discriminator, followed by fully attacker-chosen sender, recipient, bridge token, and bridge amount fields.

Because the listener does not verify that the matching log was emitted from within the gateway program's own invocation frame, this forged log is accepted, decoded via `decodeUniversalTxEvent`, and stored as a `store.Event` with `Type: store.EventTypeInbound` (or Outbound) and `Status: store.StatusPending` — with attacker-controlled `Sender`, `Recipient`, `Token`, and `Amount` — despite no real deposit/lock having occurred on the Solana gateway program. [4](#0-3) 

This is deterministically reproducible: because the forged log is genuinely present in immutable on-chain transaction data, every honest Universal Validator running this same code independently observes and decodes the identical forged event, so honest-validator consensus assumptions are not violated by malicious peers — the bug is in the client's authentication of log provenance, not in validator honesty.

Regarding the specific truncation angle in the question (`decodeUniversalTxEvent` returning a "successful" partial payload — `payload, nil` — when trailing fields like `RawPayload`, `RevertFundRecipient`, `TxType`, `VerificationData`, or `FromCEA` are missing): the core financial fields (`Sender`, `Recipient`, `Token`, `Amount`) are all fixed-offset and fully parsed *before* any of the truncation-tolerant code paths are reached (offset ≤ 92 of the required ≥120/97 bytes), so truncation alone cannot corrupt the amount/recipient/token used for minting/releasing funds. That specific truncation mechanism does not by itself demonstrate fund-level impact.

### Impact Explanation
An unauthorized `sendFunds` inbound event (or a forged `finalize_universal_tx`/`revert_universal_tx` outbound observation) with attacker-chosen recipient/amount/token can be accepted into the event pipeline without any real Solana-side deposit or lock, which — if it clears downstream ballot/voting logic in the `x/` module without an independent on-chain fund-lock check — leads to unauthorized minting/release of PRC20 or native value on Push Chain, i.e. direct fund creation from nothing.

### Likelihood Explanation
High from the listener's perspective: deploying an arbitrary Solana program and crafting a transaction with two instructions (one referencing the gateway address, one invoking the attacker's program to emit the fake log) is fully within reach of an unprivileged actor and requires no special access. The overall severity, however, depends on whether the `x/` module's inbound-vote finalization logic performs any additional on-chain corroboration (e.g., checking an actual vault balance delta or requiring the event to originate from a specific instruction/program invocation index) before minting — that downstream check was not available to verify in the indexed code.

### Recommendation
Bind each parsed log to its actual emitting program by tracking Solana's `Program <id> invoke [n]` / `Program <id> success` bracketing lines (or using `tx.Meta.InnerInstructions`/instruction-level log grouping) and only treat `"Program data: ..."` lines that occur within a frame whose program ID equals the configured gateway address as candidate gateway events. Reject any log encountered outside a confirmed gateway-program invocation frame.

### Proof of Concept
1. Deploy an attacker-controlled Solana program that calls `sol_log_data` with bytes `[send_funds_discriminator || attacker_sender(32) || attacker_recipient(20) || attacker_token(32) || attacker_amount(8) || ...]`.
2. Build one transaction with instruction A referencing the real gateway program's pubkey as a read-only, unused account (any instruction accepting extra accounts, or a no-op instruction to a program that ignores extras), and instruction B invoking the attacker's program from step 1.
3. Submit the transaction; it now appears in `GetSignaturesForAddress(gatewayAddr, ...)` results.
4. `processSignatureBatch` fetches the transaction and iterates all `LogMessages`; `determineEventType`/`ParseEvent` matches the forged discriminator and produces a `store.Event` of type Inbound with attacker-controlled `Sender`/`Recipient`/`Token`/`Amount`, with `Status: store.StatusPending`, without any real fund movement having occurred on Solana. func (el *EventListener) processSignatureBatch(
	ctx context.Context,
	batch []*solanarpc.TransactionSignature,
	fromSlot, toSlot uint64,
) (uint64, error) {
	var processed uint64
	for _, sig := range batch {
		if sig.Slot < fromSlot {
			continue
		}
		if sig.Slot > toSlot {
			continue
		}
		processed++

		// Get transaction details
		tx, err := el.rpcClient.GetTransaction(ctx, sig.Signature)
		if err != nil {
			el.logger.Error().
				Err(err).
				Str("signature", sig.Signature.String()).
				Msg("failed to get transaction")
			continue
		}

		// Process each log in the transaction
		if tx != nil && tx.Meta != nil && len(tx.Meta.LogMessages) > 0 {
			for logIndex, log := range tx.Meta.LogMessages {
				// Determine event type based on discriminator
				eventType := el.determineEventType(log)
				if eventType == "" {
					continue
				}

				// Parse gateway event from individual log
				event := ParseEvent(log, sig.Signature.String(), sig.Slot, uint(logIndex), eventType, el.chainID, el.logger)
				if event != nil {
					// Insert event if it doesn't already exist
					if stored, err := el.chainStore.InsertEventIfNotExists(event); err != nil {
						el.logger.Error().
							Err(err).
							Str("event_id", event.EventID).
							Str("type", event.Type).
							Uint64("slot", event.BlockHeight).
							Msg("failed to store event")
					} else if stored {
						el.logger.Debug().
							Str("event_id", event.EventID).
							Str("type", event.Type).
							Uint64("slot", event.BlockHeight).
							Str("confirmation_type", event.ConfirmationType).
							Msg("stored new event")
					}
				}
			}
		}
	}

	return processed, nil
}

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

func ParseEvent(log string, signature string, slot uint64, logIndex uint, eventType string, chainID string, logger zerolog.Logger) *store.Event {
	switch eventType {
	case EventTypeSendFunds:
		return parseSendFundsEvent(log, signature, slot, logIndex, chainID, logger)
	case EventTypeFinalizeUniversalTx, EventTypeRevertUniversalTx, EventTypeFundsRescued:
		return parseOutboundObservationEvent(log, signature, slot, logIndex, chainID, logger)
	default:
		logger.Debug().
			Str("event_type", eventType).
			Str("signature", signature).
			Msg("unknown event type, skipping")
		return nil
	}
}

// parseSendFundsEvent parses a sendFunds event as UniversalTx
func parseSendFundsEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	if len(decoded) < 8 {
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing sendFunds event")

	// Create store.Event
	event := &store.Event{
		EventID:           eventID,
		BlockHeight:       slot,
		Type:              store.EventTypeInbound, // Gateway events from external chains are INBOUND
		Status:            store.StatusPending,
		ExpiryBlockHeight: 0, // Will be set based on confirmation type if needed
	}

	// Parse event data from this log
	parseUniversalTxEvent(event, decoded, logIndex, chainID, logger)

	return event
}

func decodeUniversalTxEvent(data []byte, logger zerolog.Logger) (*common.UniversalTx, error) {
	if len(data) < 120 {
		logger.Warn().
			Int("data_len", len(data)).
			Msg("data might be too short for complete TxWithFunds event")
	}

	offset := 8
	payload := &common.UniversalTx{}

	// Parse sender (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for sender")
	}
	sender := solana.PublicKey(data[offset : offset+32])
	// Convert sender to hex format
	senderHex, err := base58ToHex(sender.String())
	if err != nil {
		logger.Warn().Err(err).Msg("failed to convert sender to hex, using base58")
		payload.Sender = sender.String()
	} else {
		payload.Sender = senderHex
	}
	offset += 32

	// Parse recipient (20 bytes - byte20 format)
	if len(data) < offset+20 {
		return nil, fmt.Errorf("not enough data for recipient")
	}
	// Convert 20 bytes to hex string (0x + 40 hex chars)
	recipientBytes := data[offset : offset+20]
	payload.Recipient = "0x" + hex.EncodeToString(recipientBytes)
	offset += 20

	// Parse bridge_token (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for bridge_token")
	}
	bridgeToken := solana.PublicKey(data[offset : offset+32])
	payload.Token = bridgeToken.String()
	offset += 32

	// Parse bridge_amount (8 bytes)
	if len(data) < offset+8 {
		return nil, fmt.Errorf("not enough data for bridge_amount")
	}
	bridgeAmount := binary.LittleEndian.Uint64(data[offset : offset+8])
	payload.Amount = fmt.Sprintf("%d", bridgeAmount)
	offset += 8
