## Finding: Missing TWAP protection on protocol-computed swap slippage in universal execution auto-swap paths

### Title
Spot-price (non-TWAP) Uniswap V3 quote used to compute `minPCOut` in universal-execution auto-swap and gas-refund flows enables sandwich/price-manipulation extraction of protocol-controlled swap value - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The external report's bug class is "a dynamically-priced trade is executed without adequate protection against price movement between quote and execution." Push Chain's own analog exists in the `x/uexecutor` universal-execution deposit and gas-refund flows: when a GAS/GAS_AND_PAYLOAD inbound is finalized, or when unused outbound gas is refunded, the module swaps a PRC20 for native PC via UniswapV3 using a `minPCOut` bound. That bound is not user-supplied, and it is not derived from a manipulation-resistant price source — it comes from a single, same-block spot quote (`QuoterV2.quoteExactInputSingle`) with a fixed 5% tolerance baked in by the protocol.

### Finding Description
`k.GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `commit=false`, reading the pool's current spot reserves at the moment of execution: [1](#0-0) 

This spot quote is then discounted by a hardcoded 5% and passed straight into `depositPRC20WithAutoSwap`'s `minPCOut` parameter in `ExecuteInboundGas`: [2](#0-1) 

and identically in the GAS_AND_PAYLOAD path: [3](#0-2) 

and again in the outbound gas-refund swap: [4](#0-3) 

Unlike the reported `early-purchase` bug, Push Chain does compute *a* slippage bound — but it is (a) fixed at 5% rather than owner/user-configurable, and (b) sourced from an un-averaged, single-block AMM spot price rather than a TWAP or externally-validated oracle. The upgrade log documents this was intentionally added to "replace the previous 0-slippage call," confirming the protocol is aware of price-movement risk in this exact code path but only mitigated it with a flat percentage band on a manipulable spot price: [5](#0-4) 

Because the pool referenced is the same Uniswap V3 pool the `UniversalCore` system contract deploys/uses for all PRC20 <-> PC conversion, and any unprivileged account can trade against it in the public EVM mempool, an attacker can push the pool's spot price against the module immediately before the block that executes the deposit/refund swap, then trade back afterward. The 5% band only limits — it does not eliminate — the extractable value; on any inbound/refund large enough relative to pool depth, the attacker can capture value up to (and the module can lose value up to) the full 5% tolerance, which is user/protocol-controlled fund value flowing out of the swap that mints PRC20/PC into UEAs or refund recipients.

### Impact Explanation
This corrupts PRC20/native asset accounting for the affected `UniversalTx`: the recipient UEA (for deposit auto-swap) or the outbound refund recipient (for gas refund) receives less native PC than an honest, unmanipulated market price would have produced, with the difference extracted by the attacker via the sandwich trade. This is a protocol-controlled-funds loss reachable purely through ordinary, unprivileged interaction with the public EVM mempool (no validator, relayer, or admin collusion required), matching the in-scope impact "stealing ... of user or protocol-controlled funds" and "corruption of PRC20 or native asset accounting."

### Likelihood Explanation
Requires the attacker to (1) observe/predict when a sizeable GAS or GAS_AND_PAYLOAD inbound will finalize (ballot votes and pending inbounds are all publicly queryable) or when an outbound refund will be processed, and (2) have enough capital/liquidity awareness relative to the Uniswap V3 pool depth to move price meaningfully within the 5% band, and (3) get transaction ordering around the module's swap (feasible in a permissionless EVM mempool via gas-price bidding, since block proposers order transactions by submission and no protection against front-running exists here). This is a fairly standard, well-understood sandwich pattern against spot-quote AMM usage, making it realistically exploitable, though the value extracted per event is bounded by the 5% tolerance and pool depth — so severity scales with pool liquidity and inbound size rather than being unbounded.

### Recommendation
- Replace or supplement the single-block spot `quoteExactInputSingle` call with a TWAP-based quote (e.g., `observe()`/`slot0` cumulative tick averaging over a window) so the reference price cannot be manipulated by a single adjacent transaction.
- Consider tightening or making the slippage tolerance configurable/governance-controlled rather than a hardcoded 5%, and/or capping the absolute value at risk per swap.
- Where feasible, execute the quote-then-swap sequence with additional protections (e.g., limit order size relative to pool liquidity, or route through a pool with sufficient depth/oracle-grade TWAP support) to bound attacker profit independent of pool depth assumptions.

### Proof of Concept
1. Monitor `PendingInbounds`/ballot state via the `uexecutor` query API for a GAS or GAS_AND_PAYLOAD inbound nearing quorum, or watch for outbound observations that will trigger `applyGasRefund`.
2. Submit an EVM transaction against the Uniswap V3 pool used by `UniversalCore` (address exposed via `GetUniversalCoreQuoterAddress`/`WPC`) to push the PRC20/PC spot price down just before the block that will execute the finalizing `MsgVoteInbound`/outbound-observation transaction, using normal gas-price bidding to get favorable ordering.
3. Let the module's `GetSwapQuote` -> `CallPRC20DepositAutoSwap` (or `CallUniversalCoreRefundUnusedGas`) execute against the manipulated spot price; the swap still passes because it only needs to clear `minPCOut = manipulated_quote * 0.95`.
4. Submit a reverse trade immediately after to restore price and realize the price-impact difference as profit, funded by the protocol swap's reduced output.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
```

```go
// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
```
