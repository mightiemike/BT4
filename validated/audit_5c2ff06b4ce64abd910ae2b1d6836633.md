## Analysis

The external report's bug class — "storage bloat via near-zero-cost account creation" — maps directly onto Push Chain's gasless account-bootstrap path implemented in `app/ante/account_init_decorator.go`.

### The analog

Push Chain's `AccountInitDecorator` [1](#0-0)  only activates for gasless transactions, as determined by `txpolicy.IsGaslessTx` [2](#0-1) . The gasless allowlist includes `MsgExecutePayload` and `MsgMigrateUEA`, both explicitly documented as callable by *any* account, not just Universal Validators: "Any account may submit the message." [3](#0-2) 

When the decorator sees a gasless tx from a signer address with no on-chain account, it verifies the (real, attacker-owned) signature against `account_number=0, sequence=0`, then does this: [4](#0-3) 

Critically, on success it calls `return ctx, nil` — it does **not** call `next(...)`. This is intentional per the inline comment ("bypass rest of ante chain (especially gas and signature verification) here"), but the effect is that for a brand-new account, the entire remainder of the ante chain — `DeductFeeDecorator` (already a no-op for gasless txs, per `app/ante/fee.go`), `MinGasPriceDecorator`, tx-size gas consumption, and standard signature/sequence bookkeeping — is skipped entirely. `baseapp` still commits the ante-handler's write-cache (the new `BaseAccount`) regardless of whether the subsequent `RunMsgs` succeeds or fails, which is standard Cosmos SDK fee/ante semantics.

`MsgExecutePayload.ValidateBasic()` requires only structurally well-formed fields — no funded UEA, no valid signature over the payload itself, no chain config lookup — so an attacker can trivially construct a message that satisfies `ValidateBasic()` and let the deeper business logic reject it afterward (e.g. the documented `"UEA is not deployed"` rejection path, confirmed in `test/integration/uexecutor/execute_payload_test.go`). By the time that failure occurs, the `BaseAccount` for the throwaway signer address is already permanently persisted in the `x/auth` store.

Unlike a Substrate/`pallet-balances` account, a Cosmos SDK `x/auth` account has **no Existential Deposit or reaping mechanism at all** — once created, it is never automatically pruned regardless of balance. Combined with the gasless bypass, this means an unprivileged attacker can generate unlimited keypairs and, for each one, submit a single gasless `MsgExecutePayload` (or `MsgMigrateUEA`) that:
- pays no Cosmos tx fee (`DeductFeeDecorator` skip),
- is exempt from the FeeMarket minimum gas price check (`MinGasPriceDecorator` skip),
- bypasses the ante chain's standard gas-consumption/signature-verification decorators entirely for that first tx,
- and permanently persists a new `BaseAccount` even when the wrapped message itself fails.

This is the direct on-chain analog of the Pink runtime's near-zero Existential Deposit: a mechanism intended to enable convenience (letting a freshly keygen'd UV vote without prefunding, or letting a UEA owner's payload be delivered gaslessly) inadvertently removes *all* cost from account creation for any unprivileged party, enabling unbounded `x/auth` state growth.

### Title
Unbounded free `x/auth` account creation via the gasless `AccountInitDecorator` bypass — (File: `app/ante/account_init_decorator.go`)

### Summary
The `AccountInitDecorator`, gated only by `txpolicy.IsGaslessTx`, creates a persistent on-chain `BaseAccount` for any never-before-seen signer address submitting a gasless `MsgExecutePayload` or `MsgMigrateUEA`, both of which are explicitly open to any (unprivileged, unbonded) account. Account creation happens with zero Cosmos fee, no minimum-gas-price enforcement, and is committed independently of whether the wrapped message subsequently fails. Since Cosmos SDK accounts have no existential-deposit/reaping analog, an attacker can permanently bloat the `x/auth` KV-store at effectively zero on-chain cost by mass-generating throwaway keypairs and submitting one trivially `ValidateBasic`-passing gasless message per address.

### Finding Description
`app/ante/account_init_decorator.go` special-cases gasless transactions: if the sole signer has no existing account, it verifies the signature against `accNum=0/sequence=0` and calls `NewAccountWithAddress`/`SetAccount`, then returns early without invoking the rest of the ante chain. [4](#0-3)  The gasless allowlist that unlocks this path includes `MsgExecutePayload` and `MsgMigrateUEA` [5](#0-4) , both of which the module's own documentation states may be submitted by any account: "Any account may submit the message." [6](#0-5)  `DeductFeeDecorator` independently skips fee deduction for gasless txs [7](#0-6) , and `MinGasPriceDecorator` skips the FeeMarket minimum-fee check per the module documentation [8](#0-7) . `MsgExecutePayload.ValidateBasic()` requires only structurally valid fields (non-nil `UniversalAccountId`/`UniversalPayload`, well-formed hex `VerificationData`) — no funded account, no valid EVM-level signature, no chain registration — before it reaches the message handler, where it can legitimately fail (e.g. `"UEA is not deployed"`) without unwinding the already-committed ante-stage account creation. [9](#0-8)  Cosmos SDK `x/auth` accounts, unlike Substrate balances accounts, have no existential-deposit-driven reaping, so every such account persists indefinitely in state.

### Impact Explanation
This enables unbounded growth of the `x/auth` account store by an unprivileged external attacker at effectively zero on-chain monetary cost (no fee, no minimum balance, no gas-price floor). Sustained abuse increases state size and the associated IAVL/iterator overhead for all nodes, degrading state-sync, snapshotting, and export/import performance over time — a persistent, non-network-level denial-of-service vector reachable purely through ordinary unprivileged transaction submission, matching the report's core "bloat attack" pattern of paying near-zero to inflict cumulative and durable storage/resource cost on the network.

### Likelihood Explanation
High. No privileged role, validator bonding, or key compromise is required — only the ability to generate keypairs and broadcast gasless transactions, which is exactly the intended unprivileged use case for `MsgExecutePayload`/`MsgMigrateUEA`. The attack is fully automatable and scales linearly with the number of transactions the attacker is willing to broadcast.

### Recommendation
Introduce a bounded cost for first-time account creation via the gasless path — e.g., require the new-account bootstrap to still pass through minimum gas-price/tx-size gas consumption (so broadcasting is not entirely free even though no bank transfer occurs), rate-limit `AccountInitDecorator` invocations per block/IP at the mempool layer, and/or restrict which gasless message types are allowed to trigger account auto-creation to those that cannot be trivially spammed with `ValidateBasic`-only payloads (e.g. require a minimum-effort precondition, such as proof the target UEA/chain config already exists, before the decorator persists the new account).

### Proof of Concept
1. Generate a fresh secp256k1 keypair `(sk_i, addr_i)` not present in `x/auth`.
2. Construct `MsgExecutePayload{Signer: addr_i, UniversalAccountId: <any well-formed struct>, UniversalPayload: <any well-formed struct>, VerificationData: "0x00"}` — satisfies `ValidateBasic()` per [9](#0-8)  without requiring any deployed/funded UEA.
3. Sign the tx with `sk_i` using `account_number=0, sequence=0`; broadcast with `fee=0`, `gas` arbitrary.
4. `AccountInitDecorator` verifies the signature, creates and persists `BaseAccount(addr_i)`, and returns before fee/gas ante checks run [4](#0-3) .
5. `RunMsgs` executes `MsgExecutePayload`; it fails (e.g. `"UEA is not deployed"`, per the documented rejection path in `test/integration/uexecutor/execute_payload_test.go`), but the account created in step 4 is not rolled back.
6. Repeat steps 1–5 with a new keypair each time — each iteration permanently adds one `BaseAccount` entry to `x/auth` state for zero Cosmos fee and no minimum balance.

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}

func (msg *MsgExecutePayload) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate universal payload
	if msg.UniversalPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal payload cannot be nil")
	}

	// Validate verificationData
	if len(msg.VerificationData) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "verificationData cannot be empty")
	}
	if _, err := hex.DecodeString(strings.TrimPrefix(msg.VerificationData, "0x")); err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid verificationData hex")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate universal payload structure
	if err := msg.UniversalPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universal payload")
	}

	return nil
