## Title
Fixed 5% slippage tolerance computed from a manipulable spot-price Uniswap V3 quote enables sandwich-attack value extraction on inbound gas swaps and outbound gas refunds - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Every module-originated PRC20→WPC (or gasToken→WPC) auto-swap on Push Chain — inbound gas top-ups, inbound gas+payload deposits, and outbound excess-gas refunds — derives its slippage floor (`minPCOut`) from a single, immediately-preceding spot-price quote fetched via Uniswap V3 `QuoterV2.quoteExactInputSingle`, then applies a flat, hardcoded 5% tolerance (`quote * 95 / 100`) with no user-configurable or size-aware bound. This is the same bug class as the Radiant report: an unprivileged actor can move the underlying pool's spot price immediately before the module executes its own swap, causing the "protected" quote itself to be manipulated, and then reverse the manipulation afterward to capture the difference — all without the swap ever reverting, since the slippage floor is calculated off the same manipulated price.

### Finding Description
`GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`) performs a static (`commit=false`) call into `QuoterV2.quoteExactInputSingle`, which is a spot-price simulation against the pool's current reserves/tick — not a TWAP or any manipulation-resistant oracle: [1](#0-0) 

This quote is used, unmodified except for a hardcoded 5% haircut, to compute `minPCOut` in three separate call sites:
- `ExecuteInboundGas` (gas-only inbound top-up): [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (gas+payload inbound): [3](#0-2) 
- `applyGasRefund` (outbound excess-gas refund, swap leg): [4](#0-3) 

In each case, the sequence is: (1) read the current pool price via `quoteExactInputSingle`, (2) apply a fixed 5% discount, (3) immediately execute the real swap (`CallPRC20DepositAutoSwap` or `CallUniversalCoreRefundUnusedGas`) against that same floor. Both the quote read and the swap execution happen deterministically as part of module-triggered EVM calls (ballot finalization / inbound execution / outbound vote finalization), which run in-band with ordinary block processing. An unprivileged attacker can submit an ordinary swap transaction against the same Uniswap V3 pool (PRC20/gasToken ↔ WPC) in an earlier position of the same block (or a preceding block) to push the spot price down, then let the module's own swap execute against that depressed price with only a 5% margin, then submit a reverse trade afterward to restore the pool and capture the extracted value. Because the tolerance is fixed at 5% regardless of trade size, pool depth, or the amount actually being deposited/refunded, this is directly exploitable for any inbound/refund swap whose value exceeds the cost of moving the pool by up to 5%.

This mirrors the original Radiant finding precisely: a chain of swaps each individually bounded by a fixed, non-adaptive slippage percentage (0–20% in Radiant vs. a flat 5% here), where the underlying price reference used to compute the floor is itself attacker-influenceable, allowing compounded or repeated value extraction "up to the maximum slippage tolerance at all times."

### Impact Explanation
This falls within the required "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting... reachable from ordinary user deposits" impact category. A successful sandwich causes:
- Inbound gas swaps (`ExecuteInboundGas`, gas+payload path): the user's cross-chain gas top-up mints materially less native PC than the honest market rate would produce, i.e. partial fund loss borne by the depositing user, captured by the attacker.
- Outbound gas refunds (`applyGasRefund`): the unused-gas refund owed back to the sender/fund-recipient is diminished by up to ~5% per occurrence, again captured by the attacker via the sandwich.

Because this can be repeated on every qualifying inbound/outbound with no per-user configurability and no protocol-level cap tighter than 5% for small trades, it is a systemic, repeatable value-leak from user/protocol funds to an unprivileged attacker.

### Likelihood Explanation
High. No privileged access is required — the attacker only needs to trade against the same public Uniswap V3 pool that Push Chain's `UniversalCore` contract routes through, and time an ordinary swap to land before the module-triggered swap in block ordering (proposer transaction ordering, or simply being an earlier tx in the mempool for the block containing the triggering vote). The 5% margin is generous relative to the price impact achievable on lower-liquidity PRC20/WPC pools, making this practical rather than theoretical.

### Recommendation
Do not compute `minPCOut` from a single spot-price `quoteExactInputSingle` call taken immediately before swap execution. Instead:
- Use a manipulation-resistant reference price (e.g., a TWAP over multiple blocks, or an external price oracle) to bound acceptable slippage.
- Scale the acceptable slippage tolerance to trade size / pool depth rather than a single flat 5% for all amounts.
- Consider making the max slippage tolerance a governance-configurable parameter with a hard ceiling, and reject swaps whose realized price deviates beyond a stricter bound for small notional amounts, analogous to Radiant's fix of introducing user-configurable, capped slippage settings.

### Proof of Concept
1. Identify the Uniswap V3 PRC20/WPC (or gasToken/WPC) pool used by `UniversalCore` for a given inbound token (via `defaultFeeTier`/`WPC` getters in `x/uexecutor/keeper/evm.go`).
2. Submit a large swap against that pool to depress the PRC20→WPC spot price just before a pending inbound (already voted/quorum-reached) is executed, or before the outbound vote that triggers `applyGasRefund` finalizes.
3. When `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`/`applyGasRefund` runs, `GetSwapQuote` returns the manipulated (lower) quote; `minPCOut = quote * 95 / 100` is computed off that manipulated value, so `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` executes successfully at the bad price instead of reverting.
4. Immediately swap back in the opposite direction to restore the pool price, realizing the price-impact spread as profit at the expense of the depositing/refunded user.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}
```
