Based on my investigation, this is exactly analogous to the external bug's root cause: a verification function silently omits checking a component of the value it is supposed to validate, allowing incorrect/divergent committed state to be accepted as matching.

### Title
`verify_execution`'s replay check (`ensure_match_transaction_info`) never validates state/hot-state/position checkpoint hashes, letting execution-verification silently pass despite state-root divergence - (File: `types/src/transaction/mod.rs`, `execution/executor/src/chunk_executor/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` [1](#0-0)  is the sole comparator used by `ChunkExecutorInner::verify_execution` when replaying/re-executing transactions against a trusted `TransactionInfo` list (from backup/db-tool/CLI/debugger replay paths) [2](#0-1) . It checks status, gas used, write-set hash, and event root hash, but a code comment openly documents that it skips the state checkpoint hash, hot-state checkpoint hash, and `position_state_checkpoint_hash`: [3](#0-2) .

### Finding Description
Just as the external report's `_underlyingRefPerTok` claimed to represent a rate but silently used an incomplete/wrong proxy (cbETH/stakedETH instead of cbETH/ETH), `ensure_match_transaction_info` claims ("does not match TransactionInfo") to validate that a locally re-executed `TransactionOutput` matches the trusted, proof-authenticated `TransactionInfo`, but it only proves 3 of the (up to) 7 committed fields. The state checkpoint hash (world-state Sparse Merkle root at that version), hot-state checkpoint hash, and the newer `position_state_checkpoint_hash` (trading-native state root) are never recomputed or compared here [4](#0-3) . These are exactly the fields that `TransactionInfoV1` was extended to carry [5](#0-4) , and `assemble_transaction_infos` computes them from live execution during normal block commit [6](#0-5)  — showing the DB/consensus path treats these hashes as first-class, security-relevant commitments, unlike the ad-hoc comparator.

### Impact Explanation
`verify_execution` is the code path that is explicitly meant to catch VM/state divergence during chunk replay (used by `aptos-debugger`, the CLI, and `db-tool replay-on-archive`) [7](#0-6) . If a node's local re-execution of a historical transaction produces a different state root (state checkpoint hash) than what is recorded on-chain — due to a VM/state-computation bug, corrupted local state, or a non-determinism bug — this comparator will report success anyway, because the state root is simply never checked. This is a textbook "hard-fork-only divergence during commit, replay, restore, or proof verification" scenario called out in the task's required impacts: the tooling designed to detect exactly this class of divergence has an unpatched blind spot. This can mask a real chain split/consensus bug until it manifests elsewhere (e.g., an actual consensus fork), at which point replay-verification tooling that should have caught the discrepancy in advance gave a false "matches" result.

### Likelihood Explanation
This is not a hypothetical: it is an acknowledged gap in the code itself (see the `// TODO(trading-native):` comment), meaning the omission is already known internally, but it has not yet been fixed and is guarded only by a future feature flag (`COMPUTE_TRADING_NATIVE_STATE_ROOTS`) that does not retroactively cover the pre-existing state/hot-state checkpoint hash gap [3](#0-2) . Any bug that corrupts state-tree computation while leaving the write-set/events bytes and gas/status intact (plausible for JMT/state-summary bugs, since write-set hash only covers the transaction's own write ops, not the derived global tree) will not be caught by `verify_execution`, silently degrading the guarantee that "replay-verify" tooling is supposed to provide.

### Recommendation
Extend `ensure_match_transaction_info` to also recompute and compare the state checkpoint hash (and hot-state / position-state checkpoint hashes when present) against `txn_info.state_checkpoint_hash()` / `hot_state_checkpoint_hash()` / `position_state_checkpoint_hash()`, at least whenever the transaction is a checkpoint transaction (`state_checkpoint_hash().is_some()`), before removing or gating the current `TODO` behind `COMPUTE_TRADING_NATIVE_STATE_ROOTS`.

### Proof of Concept
Not independently exploitable by an unprivileged network attacker (this is a local/replay-verification tooling gap, not a consensus-facing acceptance of forged proofs — the accumulator/`TransactionInfo` itself remains BFT-signed and authenticated). The concrete “corrupted value silently accepted” is: `verify_execution` returns `Ok` for a locally re-executed `TransactionOutput` whose actual resulting state root differs from `txn_info.state_checkpoint_hash()`, because [8](#0-7)  never inspects that field. I could not find any other call site in the replay/verify path (`aptos-debugger`, `db-tool/replay_on_archive`, CLI `commands.rs`) that independently re-derives and compares the state checkpoint hash for these flows in this snapshot of the repo; confirming that would require further tracing of those three call sites, which I was not able to fully complete given tool budget.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn verify_execution(
        &self,
        transactions: &[Transaction],
        persisted_aux_info: &[PersistedAuxiliaryInfo],
        transaction_infos: &[TransactionInfo],
        write_sets: &[WriteSet],
        event_vecs: &[Vec<ContractEvent>],
        begin_version: Version,
        end_version: Version,
        verify_execution_mode: &VerifyExecutionMode,
    ) -> Result<Version> {
        // Execute transactions.
        let parent_state = self.commit_queue.lock().latest_state().clone();
        let state_view = self.state_view(parent_state.latest())?;
        let txns = transactions
            .iter()
            .take((end_version - begin_version) as usize)
            .cloned()
            .map(|t| t.into())
            .collect::<Vec<SignatureVerifiedTransaction>>();

        let auxiliary_info = persisted_aux_info
            .iter()
            .take((end_version - begin_version) as usize)
            .map(|persisted_aux_info| AuxiliaryInfo::new(*persisted_aux_info, None))
            .collect::<Vec<_>>();
        let onchain_config = chunk_onchain_config(&state_view)?;
        let execution_output = DoGetExecutionOutput::by_transaction_execution::<V>(
            &V::new(),
            txns.into(),
            auxiliary_info,
            &parent_state,
            state_view,
            onchain_config,
            TransactionSliceMetadata::chunk(begin_version, end_version),
        )?;
        // not `zip_eq`, deliberately
        for (version, txn_out, txn_info, write_set, events) in multizip((
            begin_version..end_version,
            &execution_output.to_commit.transaction_outputs,
            transaction_infos.iter(),
            write_sets.iter(),
            event_vecs.iter(),
        )) {
            if let Err(err) = txn_out.ensure_match_transaction_info(
                version,
                txn_info,
                Some(write_set),
                Some(events),
            ) {
                return if verify_execution_mode.is_lazy_quit() {
                    error!("(Not quitting right away.) {}", err);
                    verify_execution_mode.mark_seen_error();
                    Ok(version + 1)
                } else {
                    Err(err)
                };
            }
        }
        Ok(end_version)
