### Title
DonId spoofing via silent truncation/collision in gateway handshake auth-header encoding - (File: core/services/gateway/network/handshake.go)

### Summary
The gateway node-authentication handshake packs the `DonId` and `GatewayId` fields into fixed-size byte slots using `common.StringToAlignedBytes`/`common.AlignedBytesToString`. These helper functions silently truncate on overflow and truncate at the first NUL byte on decode, with no length validation performed anywhere in the packing/unpacking path. This is the same bug class as the UMA `_uintToBytes` report: undocumented fixed-size encoding, no bounds checking, and silent collisions for values that exceed the slot size or contain the delimiter byte.

### Finding Description
`StringToAlignedBytes` copies an arbitrary-length string into a fixed-size byte buffer using Go's `copy`, which silently drops any bytes beyond `size` instead of erroring: [1](#0-0) 

The reverse function `AlignedBytesToString` truncates at the first zero byte it finds, again without validating that the encoded content is well-formed: [2](#0-1) 

Both helpers are used to build and parse the `DonId`/`GatewayId` fields of the node-authentication handshake, which is the trust boundary that determines which DON a connecting node is authenticated as: [3](#0-2) 

Because `StringToAlignedBytes` silently truncates any `DonId` longer than `HandshakeDonIdLen` bytes, two distinct DON identifiers that share a common prefix of length `HandshakeDonIdLen` (or that differ only after an embedded NUL byte) will serialize to byte-for-byte identical auth-header payloads. Since `AlignedBytesToString` on the verifier side reconstructs the (identical, truncated) string for both cases, the gateway's connection manager cannot distinguish between the two original DonId values — it only ever sees the truncated/collided form used for routing the authenticated connection to the correct DON's connection manager (`ErrAuthInvalidDonId` check in `connectionmanager.go`).

### Impact Explanation
A node operator who legitimately controls a node registered to one DON, but who is not authorized on another DON, can craft an auth header whose `DonId` field truncates/collides with the target DON's identifier. If the deployment allows DonId values close to (or embedding a NUL within) the `HandshakeDonIdLen` boundary, the gateway would associate the connection with the wrong DON's connection manager and service routing, potentially granting the node visibility into or interaction with messages/capabilities scoped to a DON it should not have access to. This is a node-identity/authorization confusion at the gateway trust boundary rather than a purely cosmetic bug.

### Likelihood Explanation
Exploitability depends on operational factors not fully verifiable from static inspection alone (exact value of `HandshakeDonIdLen`, whether DON IDs in real deployments are long/similar enough to collide, and whether `connectionmanager.go`'s DON-matching logic performs any additional validation beyond the truncated string comparison). I was not able to fully trace `connectionmanager.go`'s `StartHandshake` DON-matching implementation before running out of iterations, so likelihood should be treated as moderate/unconfirmed rather than proven end-to-end. The root-cause code pattern (silent truncation with no bounds check, no length validation, no rejection of NUL bytes despite the "can't have any 0x0 characters" comment) is confirmed and directly mirrors the reported bug class.

### Recommendation
- Add explicit length validation in `StringToAlignedBytes` that rejects (rather than silently truncates) any input longer than `size`.
- Reject any input containing a `0x00` byte instead of relying on an unenforced comment.
- Add unit tests covering boundary/overflow/NUL-byte cases for `StringToAlignedBytes`/`AlignedBytesToString`, and specifically for `PackAuthHeader`/`UnpackSignedAuthHeader` to prove no two distinct `DonId`/`GatewayId` values can encode to the same bytes.
- Consider using a length-prefixed or delimiter-safe encoding for these identity fields instead of NUL-padded fixed slots.

### Proof of Concept
Conceptual (not executed): given `HandshakeDonIdLen = N`, construct two DonId strings `A` (length ≤ N, valid ASCII) and `B = A + "extra-suffix"` (length > N). `PackAuthHeader({DonId: A, ...})` and `PackAuthHeader({DonId: B, ...})` produce identical encoded bytes for the DonId slot because `StringToAlignedBytes` truncates `B` to its first N bytes, which equal `A` padded. Both `UnpackSignedAuthHeader` calls will therefore report `elems.DonId == A`, even though the signer intended to authenticate for DON `B`. The exact `HandshakeDonIdLen` value and how the gateway's connection manager subsequently authorizes/routes based on `elems.DonId` were not fully verified in this session; this should be validated against `core/services/gateway/network/constants.go` and `core/services/gateway/connectionmanager.go` in a follow-up.

	copy(aligned, input)
	return aligned
}

func AlignedBytesToString(data []byte) string {
	idx := slices.IndexFunc(data, func(b byte) bool { return b == 0 })
	if idx == -1 {
		return string(data)
	}
	return string(data[:idx])
}

func PackAuthHeader(elems *AuthHeaderElems) []byte {
	packed := common.Uint32ToBytes(elems.Timestamp)
	packed = append(packed, common.StringToAlignedBytes(elems.DonId, HandshakeDonIdLen)...)
	packed = append(packed, common.StringToAlignedBytes(elems.GatewayId, HandshakeGatewayURLLen)...)
	return packed
}

func UnpackSignedAuthHeader(data []byte) (elems *AuthHeaderElems, signer []byte, err error) {
	if len(data) != HandshakeAuthHeaderLen {
		return nil, nil, fmt.Errorf("auth header length is invalid (expected: %d, got: %d)", HandshakeAuthHeaderLen, len(data))
	}
	elems = &AuthHeaderElems{}
	offset := 0
	elems.Timestamp = common.BytesToUint32(data[offset : offset+HandshakeTimestampLen])
	offset += HandshakeTimestampLen
	elems.DonId = common.AlignedBytesToString(data[offset : offset+HandshakeDonIdLen])
	offset += HandshakeDonIdLen
	elems.GatewayId = common.AlignedBytesToString(data[offset : offset+HandshakeGatewayURLLen])
	offset += HandshakeGatewayURLLen
	signature := data[offset:]
	signer, err = common.ExtractSigner(signature, data[:len(data)-HandshakeSignatureLen])
	return
}
