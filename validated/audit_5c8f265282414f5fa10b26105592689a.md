### Title
Starknet OS `execute_replace_class` skips the "class must be declared" check enforced by the Blockifier, causing OS/Blockifier execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `ReplaceClass` syscall is implemented twice in the sequencer stack: once in Rust inside the Blockifier (used to execute/validate transactions and build blocks) and once in Cairo inside the Starknet OS program (used to independently re-execute transactions when generating the state-transition proof / commitment). The Blockifier implementation explicitly requires that the target `class_hash` be a *declared* class before allowing the replacement, but the Starknet OS Cairo implementation has this check commented out as an open `TODO`, meaning it will silently perform the replacement even for an undeclared class hash.

### Finding Description
The Blockifier's Cairo1 syscall implementation for `ReplaceClass` (used by both the CASM/VM and Native execution paths) enforces that the class hash be declared, and rejects with an `"is not declared"` error otherwise: [1](#0-0) 

The same check exists in the deprecated (Cairo0) syscall path, where the comment makes the intent explicit: [2](#0-1) 

The Native execution handler routes through the same shared `base.replace_class`, inheriting this same check: [3](#0-2) 

However, the Starknet OS's own Cairo implementation of `execute_replace_class` (used during re-execution for proving / state commitment) has an explicit TODO marking that the equivalent validation is *not implemented*: [4](#0-3) 

Specifically, at line 902 the code proceeds directly to update `contract_state_changes` with the new (unverified) class hash without checking that a compiled class exists for it: [5](#0-4) 

The deprecated OS syscall path (`deprecated_execute_syscalls.cairo`) has the same gap — it also updates state unconditionally with no declared-class check: [6](#0-5) 

This is analogous to the reported bug class: two logically-equivalent enforcement points (in the Arcadia report, two Registries with different `minUsdValue` risk parameters; here, two independent implementations of the same syscall semantics — Blockifier vs. Starknet OS) can disagree, and the code path that is supposed to keep them in sync (a validation added in one place) was never mirrored in the other. Just as the account's health status could silently diverge from what the old/new registry parameters implied, the OS's computed post-state can silently diverge from what the Blockifier decided during actual block execution.

### Impact Explanation
If a contract invokes `replace_class_syscall` with a class hash that has not been declared:
- The Blockifier (the code path used by the sequencer to execute the transaction and build the block) will reject/revert this call, since `syscall_base.rs`/`hint_processor.rs` enforce the declared-class check (confirmed by the `undeclared_class_hash` test).
- The Starknet OS (the code path used to independently re-derive the state diff for proving/state commitment) has no such check, and will happily apply the class replacement to `contract_state_changes` regardless of whether the class is declared.

Because the OS's re-execution is the authoritative source for the state commitment/root that is ultimately proven and committed, any divergence between what the Blockifier decided (revert, no state change) and what the OS computes (success, state change applied) is a correctness bug in the state-transition function used for proving. This falls under "wrong committed root" / "honest-node divergence" — the OS could, in principle, compute a different post-state than the state the sequencer actually produced and broadcast, or (if the OS is also used to validate the sequencer's claimed diff against re-execution) cause proof generation to fail or produce a state root that does not correspond to Blockifier's actual state transition.

### Likelihood Explanation
This is trivially reachable by a single unprivileged transaction: any deployed Cairo1 (or Cairo0, via the deprecated syscall) contract can call `replace_class_syscall(<any felt>)` with an undeclared class hash. No special privileges, staking, or operator access is required — it's a standard syscall available to any contract during normal execution.

### Recommendation
Add the equivalent "class must be declared" check to the Starknet OS's Cairo implementations of `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring the check already present in the Blockifier's Rust implementation (`syscall_base.rs` / `hint_processor.rs`), before mutating `contract_state_changes`. This TODO should be resolved and covered by a regression test asserting that the OS rejects (or reverts consistently with the Blockifier) a `replace_class` targeting an undeclared class hash.

### Proof of Concept
1. Deploy a Cairo1 contract exposing a function that calls `replace_class_syscall(class_hash)` with an arbitrary, never-declared `class_hash`.
2. Submit an invoke transaction calling this function.
3. Observe that the Blockifier reverts/rejects the call with `"is not declared"` (as shown in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash`), so the block built by the sequencer reflects a reverted/failed call.
4. Inspect `execute_replace_class` in `syscall_impls.cairo` (and the deprecated counterpart) used by the Starknet OS: no declared-class check is performed before the `dict_update` call that mutates `contract_state_changes`, so an independent re-execution/trace-generation of the same syscall (absent the Blockifier's guard) would apply the class hash change unconditionally.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
