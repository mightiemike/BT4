### Title
Free CPU-exhaustion DOS via unpriced zk-SNARK proof verification in `ShieldedTransferActuator` - (File: `actuator/src/main/java/org/tron/core/actuator/ShieldedTransferActuator.java`)

### Summary
Pure shield-to-shield `ShieldedTransferContract` transactions (no `transparent_from_address`/`transparent_to_address`) require **zero signatures** and are explicitly **exempted from bandwidth/fee accounting**. This lets any unprivileged network participant submit transactions containing bogus `SpendDescription`/`ReceiveDescription` zk-SNARK proofs that force every full node to execute expensive native Sapling pairing-check crypto (`librustzcashSaplingCheckSpend`/`CheckOutput`/`FinalCheck`) with **no monetary cost or resource deduction**, exactly the same "unpriced proof verification" pattern flagged in the Aleo `split`-transaction report.

### Finding Description
The transaction pipeline in `Manager.processTransaction` performs, in order: `validateTapos` → `validateCommon` → `validateDup` → `validateSignature` → `consumeBandwidth` → `consumeMultiSignFee`/`consumeMemoFee` → `trace.exec()` (which invokes the actuator's `validate()`/`execute()`). [1](#0-0) 

For a pure shielded transfer with no transparent addresses, `TransactionCapsule.validateSignature` requires the signature count to be **zero** — i.e., no cryptographic signature cost is incurred at all: [2](#0-1) 

`BandwidthProcessor.consume` explicitly **skips** `ShieldedTransferContract` from bandwidth/fee accounting entirely (`continue`), meaning `consumeBandwidth` charges nothing for this contract type before the expensive validation runs: [3](#0-2) 

Only after these free/no-op checks does `trace.exec()` reach `ShieldedTransferActuator.validate()`, which runs the actual costly zk-SNARK verification (`checkProof`) calling native elliptic-curve pairing operations (`librustzcashSaplingCheckSpend`, `librustzcashSaplingCheckOutput`, `librustzcashSaplingFinalCheck`) for every spend/receive description supplied — before any balance/fee is touched: [4](#0-3) 

The internal shielded-pool "fee" (`calcFee`) is only actually applied inside `execute()`, which is reached **only if the proof already passed**: [5](#0-4) 

Thus, exactly like the Aleo `split`-proof bug — where the fee is embedded inside the same operation being proven rather than charged upfront/independently — an attacker pays nothing (no signature, no bandwidth fee) to force every validating node to execute the expensive Sapling proof-verification routine, which fails only after the CPU work has already been spent.

### Impact Explanation
An attacker can flood the p2p network with many distinct `ShieldedTransferContract` transactions (unique garbage `zkproof`/`valueCommitment`/`nullifier` bytes of the correct byte-length to pass structural checks, no transparent addresses, zero signatures) at effectively zero cost. Each transaction forces every full node/witness that receives it to run multiple native elliptic-curve pairing checks in `checkProof` before rejection. At scale this can degrade witness block-production performance and full-node responsiveness — a CPU-exhaustion DOS vector reachable by any unprivileged user, with no balance, stake, or signature required.

### Likelihood Explanation
High. Constructing a structurally valid but cryptographically invalid `ShieldedTransferContract` requires no special privilege, no funds (fee/bandwidth checks are bypassed for this contract type), and no valid signature. The `shieldedTransInPendingMaxCounts` limit only throttles per-node pending queue depth and does not prevent continuous resubmission of fresh, distinct fake transactions network-wide.

### Recommendation
Require a minimal, cheaply-verifiable cost (bandwidth consumption and/or a small mandatory fee charged independent of proof validity) for all `ShieldedTransferContract` transactions — including pure shield-to-shield transfers — before the expensive `checkProof` zk-SNARK verification is attempted, so that invalid-proof submissions are not free to broadcast repeatedly. Remove or restrict the `ShieldedTransferContract` bandwidth-skip in `BandwidthProcessor.consume`.

### Proof of Concept
1. Construct a `ShieldedTransferContract` with empty `transparent_from_address`/`transparent_to_address`, `from_amount`/`to_amount` = 0, one `SpendDescription` (192-byte garbage `zkproof`, random 32-byte `nullifier`/`anchor`/`rk`/`valueCommitment`, 64-byte garbage `spendAuthoritySignature`) and one `ReceiveDescription` with correctly sized but random `cEnc`/`cOut`/`zkproof`.
2. Wrap in a `Transaction` with zero signatures and broadcast via `TronNetDelegate.pushTransaction` → `Manager.pushTransaction`.
3. Observe the transaction passes `validateTapos`, `validateCommon`, `validateDup`, `validateSignature` (0 sigs required) and `consumeBandwidth` (skipped for `ShieldedTransferContract`) at zero cost, then reaches `ShieldedTransferActuator.checkProof`, which invokes the native Sapling pairing checks before ultimately failing.
4. Repeat with many unique garbage payloads to consume node CPU cycles for free.

  private void checkProof(List<SpendDescription> spendDescriptions,
      List<ReceiveDescription> receiveDescriptions, long fee) throws ZkProofValidateException {
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    ZKProofStore proofStore = chainBaseManager.getProofStore();
    if (proofStore.has(tx.getTransactionId().getBytes())) {
      if (proofStore.get(tx.getTransactionId().getBytes())) {
        return;
      } else {
        throw new ZkProofValidateException("record is fail, skip proof", false);
      }
    }

    byte[] signHash = getShieldTransactionHashIgnoreTypeException(tx.getInstance());

    if (CollectionUtils.isNotEmpty(spendDescriptions)
        || CollectionUtils.isNotEmpty(receiveDescriptions)) {
      long ctx = JLibrustzcash.librustzcashSaplingVerificationCtxInit();
      try {
        for (SpendDescription spendDescription : spendDescriptions) {
          if (!JLibrustzcash.librustzcashSaplingCheckSpend(
              new CheckSpendParams(ctx,
                  spendDescription.getValueCommitment().toByteArray(),
                  spendDescription.getAnchor().toByteArray(),
                  spendDescription.getNullifier().toByteArray(),
                  spendDescription.getRk().toByteArray(),
                  spendDescription.getZkproof().toByteArray(),
                  spendDescription.getSpendAuthoritySignature().toByteArray(),
                  signHash)
          )) {
            throw new ZkProofValidateException("librustzcashSaplingCheckSpend error", true);
          }
        }

        for (ReceiveDescription receiveDescription : receiveDescriptions) {
          if (receiveDescription.getCEnc().size() != ZC_ENCCIPHERTEXT_SIZE
              || receiveDescription.getCOut().size() != ZC_OUTCIPHERTEXT_SIZE) {
            throw new ZkProofValidateException("Cout or CEnc size error", true);
          }
          if (!JLibrustzcash.librustzcashSaplingCheckOutput(
              new CheckOutputParams(ctx,
                  receiveDescription.getValueCommitment().toByteArray(),
                  receiveDescription.getNoteCommitment().toByteArray(),
                  receiveDescription.getEpk().toByteArray(),
                  receiveDescription.getZkproof().toByteArray())
          )) {
            throw new ZkProofValidateException("librustzcashSaplingCheckOutput error", true);
          }
        }

        long valueBalance;
        long totalShieldedPoolValue = dynamicStore
            .getTotalShieldedPoolValue();
        try {
          valueBalance = addExact(subtractExact(
              shieldedTransferContract.getToAmount(),
              shieldedTransferContract.getFromAmount()), fee);
          totalShieldedPoolValue = subtractExact(
              totalShieldedPoolValue, valueBalance);
        } catch (ArithmeticException e) {
          logger.debug(e.getMessage(), e);
          throw new ZkProofValidateException(e.getMessage(), true);
        }

        if (totalShieldedPoolValue < 0) {
          throw new ZkProofValidateException("shieldedPoolValue error", true);
        }

        if (!JLibrustzcash.librustzcashSaplingFinalCheck(

                valueBalance,
                shieldedTransferContract.getBindingSignature().toByteArray(),
                signHash)

          throw new ZkProofValidateException("librustzcashSaplingFinalCheck error", true);
        }
      } catch (ZksnarkException e) {
        throw new ZkProofValidateException(e.getMessage(), true);
      } finally {
        JLibrustzcash.librustzcashSaplingVerificationCtxFree(ctx);
      }
    }

    recordProof(tx.getTransactionId(), true);
  }
