### Title
Unbounded recursion in `bytecode_hash_node` during compiled-class-hash verification causes sequencer stack overflow - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
`bytecode_hash_node` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs:111-132` recursively walks a `NestedIntList` describing the CASM bytecode-segment structure with no depth limit, mirroring the NanaZip ROMFS bug class: "deeply nested directories cause unbounded recursion (stack overflow)". This function is invoked on every `DeclareTransaction` V3 whose `block_casm_hash_v1_declares` flag is set, via `CasmContractClass::hash(&HashVersion::V2)`, reached through `check_compile_class_hash_v2_declaration` (`crates/starknet_api/src/executable_transaction.rs:228-244`), which is called from `DeclareTransaction::run_execute` (`crates/blockifier/src/transaction/transactions.rs:184-188`) before the compiled-class-hash equality check ever occurs.

### Finding Description
The `CasmContractClass` hashed here is produced by the sequencer's own Sierra→CASM compiler subprocess (`crates/apollo_compile_to_casm/src/compiler.rs`) from the Sierra program supplied by the declarer in the transaction. The compiler's `bytecode_segment_lengths` field is a `NestedIntList` (`cairo_lang_starknet_classes::NestedIntList`) that mirrors the nesting of functions/branches in the compiled bytecode. Its nesting depth is driven by the structure of the user-supplied Sierra program (e.g., deeply nested `match`/branch chains or nested function calls), and there is no explicit limit enforced on segment-tree depth independent of `max_bytecode_size` — an attacker can construct a Sierra program that compiles to a bytecode whose segment structure is nested to depth proportional to the number of instructions rather than the raw size, i.e., each nesting level can consume as little as a single instruction.

`bytecode_hash_node` recurses once per nesting level with no depth guard:

Unlike `blockifier`'s `CallEntryPoint::execute`, which enforces `RecursionDepthGuard`/`max_recursion_depth` on Cairo call recursion, and unlike `NestedFeltCounts::new_inner` in `crates/blockifier/src/execution/contract_class.rs`, which asserts `segmentation_depth <= 1` (rejecting deep structures outright), `bytecode_hash_node` has no analogous protection. It is reachable directly from `check_compile_class_hash_v2_declaration`, which every declaring node executes deterministically as part of block execution/validation (both proposer and honest re-executing/validating nodes), before mempool/gateway-level fee or resource metering could bound the call — the recursion happens purely in native Rust stack frames, not Cairo VM steps, so Cairo step/gas limits do not protect it.

### Impact Explanation
If an attacker crafts a Sierra program whose compiled CASM bytecode-segment tree is deep enough (thousands of nested single-instruction segments) to exceed the sequencer process's stack size, invoking `bytecode_hash_node` on it during `check_compile_class_hash_v2_declaration` will overflow the stack and abort/crash the sequencer process handling that declare transaction. Because this code path runs deterministically on any node executing/validating the same block (proposer, honest re-executing nodes, and Starknet OS re-execution equivalents that rely on the same class-hash consistency), a successfully included malicious declare transaction can cause honest-node divergence or repeated crashes across the network, i.e., the network becomes unable to confirm new transactions — a network-availability impact.

### Likelihood Explanation
Likelihood is limited by whether an attacker can craft a Sierra program that (a) passes gateway/compiler validation and size limits (`max_bytecode_size`, audited-libfuncs checks), and (b) produces a segment tree deep enough to overflow the stack under `RUST_MIN_STACK` settings (4 MiB is configured for the `native_blockifier` crate per `crates/native_blockifier/.cargo/config.toml`). Since segmentation follows the program's function/branch structure rather than raw byte count, an attacker with unbounded control over Sierra program structure (via any account able to submit a `DECLARE` transaction) has a plausible path to construct such a program, making this reachable by any single unprivileged declare transaction.

### Recommendation
Add an explicit maximum nesting-depth check (or convert to an iterative/worklist traversal) in `bytecode_hash_node` (and its blockifier gas-estimation counterpart `NestedFeltCounts::new_inner`/`bytecode_hash_node` in `crates/blockifier/src/execution/contract_class.rs` and `crates/blockifier/src/execution/casm_hash_estimation.rs`) before Sierra→CASM compilation output is trusted for hashing, rejecting `NestedIntList` structures beyond a bounded depth (consistent with the existing `segmentation_depth <= 1` assumption already made elsewhere in the codebase), and validate this bound directly on the compiler's output at declaration time rather than assuming it structurally.

### Proof of Concept
1. Craft a Cairo1/Sierra source whose compiled body is structured as `N` nested match/if branches each guarding a single Cairo instruction (or otherwise induce the Sierra→CASM compiler to emit a `bytecode_segment_lengths` `NestedIntList::Node` chain nested `N` levels deep), keeping total bytecode size under `max_bytecode_size`.
2. Submit this class in a `DECLARE` V3 transaction with `block_casm_hash_v1_declares` enabled.
3. During `DeclareTransaction::run_execute` (`crates/blockifier/src/transaction/transactions.rs:184-188`), the sequencer compiles the Sierra program to CASM and calls `check_compile_class_hash_v2_declaration`, which calls `casm.hash(&HashVersion::V2)` → `bytecode_hash` → `bytecode_hash_node`, recursing `N` times with no depth bound.
4. For sufficiently large `N` (bounded only by total instruction count, not raw nesting-independent size), the native call stack overflows and the sequencer process handling this transaction crashes.

```rust
/// Computes the hash of a bytecode segment. See the documentation of `bytecode_hash_node` in
/// the Starknet OS.
/// Returns the length of the processed segment and its hash.
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}
```
