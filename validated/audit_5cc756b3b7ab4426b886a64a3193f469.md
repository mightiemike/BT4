### Title
OAuth `state` Nonce Cookie Has No Server-Side Expiry Enforcement, Extending the CSRF Window Indefinitely - (File: packages/apps/shopify-api/runtime/http/cookies.ts)

### Summary
The OAuth `begin()` flow sets the `shopify_app_state` nonce cookie with a `Set-Cookie` `expires` attribute of 60 seconds, intending to bound the window in which an OAuth callback can be completed. However, the actual server-side check used to accept that cookie during `callback()` — `Cookies.getAndVerify()` / `isSignedCookieValid()` — only verifies the HMAC signature of the cookie value; it never inspects or compares against any expiry/creation timestamp. Just like the TaikoL1 report where the intended `cooldownWindow` boundary was never independently re-checked at the point of use (`verifyBlocks()`), here the intended 60-second OAuth nonce freshness window is never independently re-checked at the point of use (`callback()`), and enforcement is delegated entirely to the client (browser) honoring the `expires` header.

### Finding Description
In `begin()`, the state nonce cookie is created with a hard expiry: [1](#0-0) 

In `callback()`, that cookie is read back and validated purely by signature match, with no timestamp comparison at all: [2](#0-1) 

The underlying `getAndVerify`/`isSignedCookieValid` implementation confirms this — it checks only that the cookie value and its `.sig` companion exist and that the signature matches one of the configured keys; the `expires`/`maxAge` fields recorded in `CookieData` are used only when building the `Set-Cookie` header, not when validating an incoming cookie: [3](#0-2) 

Because the signature (`createCookieSignature`) is computed only over the cookie value (the nonce string) and not over any embedded timestamp, any client, proxy, extension, cached response, or replay mechanism that retains and resends the originally-issued `shopify_app_state`/`shopify_app_state.sig` cookie pair past the intended 60-second window will still pass `isSignedCookieValid` and be treated as fresh by `callback()`. The only enforcement of "nonce freshness" is the browser choosing to stop sending an expired cookie — a client-side, non-authoritative control, exactly analogous to relying on the owner's `pauseProving()`/`unpause` cadence rather than an on-chain, independently-checked `unpauseTime` boundary.

### Impact Explanation
The 60-second expiry on the `state` cookie exists to bound the OAuth CSRF window: after that time, the nonce should no longer be accepted as proof that the pending OAuth transaction was recently and legitimately initiated by that user-agent. Because this window is not enforced server-side, an attacker who can get a stale-but-signature-valid `state` cookie replayed to the callback endpoint (e.g. via cookie retention in shared browsers/proxies, cached HTTP responses, or long-lived automation/testing tooling that does not purge expired cookies) can complete or race an OAuth callback well beyond the intended freshness bound, undermining the anti-CSRF guarantee the nonce is meant to provide.

### Likelihood Explanation
Exploitation requires only an unauthenticated actor able to deliver a previously-issued, still-validly-signed `shopify_app_state` cookie/signature pair alongside a matching `state` query parameter to the `/callback` route after the intended 60-second window — no privileged access, no secret leakage, and no cryptographic break of the HMAC is needed, since the check simply never looks at time. The main constraint is the attacker (or the environment they control) must actually still possess/replay that cookie past expiry, which is realistic in shared-browser, proxy-caching, or non-standard client scenarios.

### Recommendation
Embed an issuance timestamp into the signed cookie payload (or store one server-side keyed by the nonce) and have `callback()`/`isSignedCookieValid()` independently reject cookies whose age exceeds the intended TTL, rather than relying solely on the `Set-Cookie` `expires` attribute being honored by the client — mirroring the TaikoL1 fix of tracking an explicit `unpauseTime` and checking it at the point of use instead of only bounding the window at issuance time.

### Proof of Concept
1. Legitimate user begins OAuth: server sets `shopify_app_state=NONCE; shopify_app_state.sig=SIG` with `expires` = now + 60s.
2. A mechanism outside the app's control (shared browser profile, caching proxy, browser extension, stale automation session, etc.) retains this cookie pair beyond the 60-second window instead of purging it.
3. More than 60 seconds later, a request is sent to the OAuth `callback` endpoint with `?shop=...&state=NONCE&hmac=...&code=...` and the retained `Cookie: shopify_app_state=NONCE; shopify_app_state.sig=SIG` header attached.
4. `cookies.getAndVerify(STATE_COOKIE_NAME)` in `oauth.ts` calls `isSignedCookieValid`, which only checks the HMAC signature match (`packages/apps/shopify-api/runtime/http/cookies.ts` lines 205-236) — it succeeds despite the cookie being well past its intended 60-second freshness window, and `validQuery` then only compares `state` equality, allowing the callback to proceed as if the nonce were fresh.

  async getAndVerify(name: string): Promise<string | undefined> {
    const value = this.get(name);
    if (!value) return undefined;
    if (!(await this.isSignedCookieValid(name))) {
      return undefined;
    }
    return value;
  }

  private get canSign() {
    return this.keys?.length > 0;
  }

  set(name: string, value: string, opts: Partial<CookieData> = {}): void {
    this.outgoingCookieJar[name] = {
      ...opts,
      name,
      value,
    };
    this.updateHeader();
  }

  async setAndSign(
    name: string,
    value: string,
    opts: Partial<CookieData> = {},
  ): Promise<void> {
    if (!this.canSign) {
      throw Error('No keys provided for signing.');
    }
    this.set(name, value, opts);
    const sigName = `${name}.sig`;
    const signature = await createCookieSignature(this.keys[0], value);
    this.set(sigName, signature, opts);
    this.updateHeader();
  }

  async isSignedCookieValid(cookieName: string): Promise<boolean> {
    const signedCookieName = `${cookieName}.sig`;
    if (
      !this.cookieExists(cookieName) ||
      !this.cookieExists(signedCookieName)
    ) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }
    const cookieValue = this.get(cookieName);
    const signature = this.get(signedCookieName);

    if (!cookieValue || !signature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    const allCheckSignatures = await Promise.all(
      this.keys.map((key) => createCookieSignature(key, cookieValue)),
    );

    const validSignature = allCheckSignatures.some((checkSignature) =>
      safelyCompareSignatures(checkSignature, signature),
    );

    if (!validSignature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    return true;
  }
