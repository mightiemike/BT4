### Title
Replay-verification skips authenticated position/hot-state checkpoint hashes, allowing corrupted trading-native state to pass as verified - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the function used by replay/verify tooling (`storage/db-tool/src/replay_on_archive.rs`, `aptos-move/cli/src/commands.rs`) to confirm that a locally re-executed `TransactionOutput` matches the authenticated `TransactionInfo` fetched from an archive/ledger. As written, it checks status, gas used, write-set hash, and event root hash, but explicitly does **not** check the state checkpoint hash, hot-state checkpoint hash, or `position_state_checkpoint_hash` fields of `TransactionInfoV1`.

### Finding Description [1](#0-0)  shows `ensure_match_transaction_info` validating `status`, `gas_used`, `write_set_hash`, and `event_root_hash` against the `TransactionInfo`, then has a `TODO(trading-native)` comment stating:

> "this comparator ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`), so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution."

The commit path itself correctly assembles and verifies these checkpoint hashes when producing `TransactionInfo` (see `assemble_transaction_infos` in [2](#0-1) , and `compute_position_checkpoint` in [3](#0-2) ), and these checkpoint hashes are the values that get committed into `TransactionInfoV1` and folded into the transaction accumulator (the consensus-authenticated root). The `COMPUTE_TRADING_NATIVE_STATE_ROOTS` feature flag description in [4](#0-3)  explicitly states this root "is consensus-verified" once the feature is on.

The gap is that the replay-verification consumer (`ensure_match_transaction_info`), which is the tool meant to independently confirm an archived/replayed ledger segment is internally consistent, does not re-derive or compare `state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, or `position_state_checkpoint_hash()` against what local execution computes. So a corrupted or malicious position/hot-state root value baked into a stored `TransactionInfoV1` (e.g., a tampered backup, a bug in `compute_position_checkpoint`, or a node with divergent native-position/hot-state logic) would not be caught by this comparator, even though the write-set and events line up.

### Impact Explanation
This is a proof/commitment-integrity gap in the state-verification pivot area explicitly called out by the task (accumulators, checkpoint hashes, replay paths must preserve deterministic proof binding). If `COMPUTE_TRADING_NATIVE_STATE_ROOTS` / `HOT_STATE_ROOT_IN_TXN_INFO` are enabled, an archived or replayed segment whose `position_state_checkpoint_hash` or hot-state checkpoint hash is wrong (from storage corruption, a backup/restore bug, or a bug elsewhere in the position-tree/hot-state pipeline) would be silently reported as a "successful replay" by tooling relying on `ensure_match_transaction_info`, masking a genuine state divergence in a supposedly consensus-verified root. This undermines the guarantee that replay-verify tooling is a trustworthy detector of ledger corruption for these newer state roots.

### Likelihood Explanation
Low-to-moderate today: the affected roots (`compute_trading_native_state_roots`, `hot_state_root_in_txn_info`) are new/feature-gated (flags 122/123), off by default per `BlockExecutorConfigFromOnchain::new*` constructors (all default `false`, see [5](#0-4) ). The gap only matters for chains that have enabled these flags and rely on `ensure_match_transaction_info`-based replay verification to catch such divergences; the comment itself acknowledges it as a known, currently-open TODO rather than something already exploited. I could not fully trace whether other call sites (e.g. `storage/db-tool/src/replay_on_archive.rs`) perform any supplementary checkpoint-hash validation of their own that might compensate; this would need to be checked in the actual `replay_on_archive.rs` body before concluding no other safety net exists.

### Recommendation
Extend `ensure_match_transaction_info` (or its callers) to also compare `state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, and `position_state_checkpoint_hash()` (when present in a `TransactionInfoV1`) against locally recomputed values before declaring a replayed segment verified, closing the gap noted in the existing TODO.

### Proof of Concept
Conceptual: enable `COMPUTE_TRADING_NATIVE_STATE_ROOTS`; craft or corrupt a stored `TransactionInfoV1` so that `write_set`/`events`/`status`/`gas_used` still match a given `TransactionOutput`, but `position_state_checkpoint_hash` is wrong (mismatched from the real position-tree root). Run replay verification through `ensure_match_transaction_info`; the mismatch in the position-tree/hot-state checkpoint hash is not checked and the tool reports success, per the code path cited above.

**Caveat**: I was not able to inspect the full body of `storage/db-tool/src/replay_on_archive.rs` or `aptos-move/cli/src/commands.rs` in this session (only found via grep, not read in full) to confirm there is no independent, redundant checkpoint-hash check performed there that would neutralize this gap. This should be verified before treating the finding as conclusively exploitable end-to-end.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn compute_position_checkpoint(
        execution_output: &ExecutionOutput,
        parent: Option<&LedgerWithSummary<PositionStateWithSummary>>,
        persisted: &ProvablePositionStateSummary,
        known_position_state_checkpoints: Option<Vec<Option<HashValue>>>,
    ) -> Result<(
        LedgerWithSummary<PositionStateWithSummary>,
        Vec<Option<HashValue>>,
    )> {
        let _timer = OTHER_TIMERS.timer_with(&["get_position_checkpoint_hashes"]);

        let num_txns = execution_output.to_commit.len();
        let first_version = execution_output.first_version;
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();
        let base_summary = persisted.summary();
        // No in-memory parent at genesis / first block after enabling: seed
        // from the pre-committed position tip (covers committed writes the
        // merklized snapshot may lag).
        let parent_latest =
            parent.map_or_else(|| persisted.base().latest().clone(), |p| p.latest().clone());
        let parent_last_checkpoint = parent.map_or_else(
            || persisted.base().last_checkpoint().clone(),
            |p| p.last_checkpoint().clone(),
        );

        // Empty chunk: nothing to extend (avoids the `num_txns - 1` underflow).
        if num_txns == 0 {
            let summary = LedgerWithSummary::from_latest_and_last_checkpoint(
                parent_latest,
                parent_last_checkpoint,
            );
            return Ok((summary, vec![]));
        }

        // Collapse position writes (latest-per-key) over a version range into
        // SMT leaf updates.
        let collect = |range: std::ops::Range<usize>| -> Vec<(HashValue, PositionSlot)> {
            let mut latest: HashMap<HashValue, PositionSlot> = HashMap::new();
            for i in range {
                for (key, op) in execution_output.to_commit.transaction_outputs[i]
                    .write_set()
                    .native_position_iter()
                {
                    let value_hash = op.as_write_op().as_state_value_opt().map(StateValue::hash);
                    latest.insert(key.hash(), PositionSlot {
                        state_key: key.clone(),
                        value_hash,
                        value: None,
                    });
                }
            }
            latest.into_iter().collect()
        };

        let (new_latest, new_last_checkpoint) = if let Some(ci) = last_checkpoint_index {
            let checkpoint_version = first_version + ci as u64;
            let new_ckpt = parent_latest.extend(
                checkpoint_version,
                collect(0..ci + 1),
                base_summary,
                persisted,
            )?;
            if ci + 1 == num_txns {
                (new_ckpt.clone(), new_ckpt)
            } else {
                let last_version = first_version + num_txns as u64 - 1;
                let new_latest = new_ckpt.extend(
                    last_version,
                    collect(ci + 1..num_txns),
                    base_summary,
                    persisted,
                )?;
                (new_latest, new_ckpt)
            }
        } else {
            // No checkpoint in this chunk: only the latest advances.
            let last_version = first_version + num_txns as u64 - 1;
            let new_latest = parent_latest.extend(
                last_version,
                collect(0..num_txns),
                base_summary,
                persisted,
            )?;
            (new_latest, parent_last_checkpoint)
        };

        // Per-tx hash vector + known-hash validation (shared with main/hot state).
        let hashes = Self::get_state_checkpoint_hashes(
            execution_output,
            known_position_state_checkpoints,
            new_last_checkpoint.root_hash(),
            "position_state",
        )?;

        let summary =
            LedgerWithSummary::from_latest_and_last_checkpoint(new_latest, new_last_checkpoint);
        Ok((summary, hashes))
