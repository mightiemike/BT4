### Title
Starknet OS `replace_class` syscall omits the declared-class and Cairo-version checks enforced by the Blockifier, causing state-commitment divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The AlexLab exploit succeeded because the protocol's on-chain verification logic failed to confirm that a token/contract genuinely deserved the permissions it was granted before mutating protected state (vault balances). The Starknet analog is the `replace_class` syscall implementation inside the Starknet OS Cairo program: it writes an attacker/user-supplied `class_hash` directly into a contract's `StateEntry` without verifying that the class hash was ever declared, or that it is a valid Cairo1 target — checks that the Rust Blockifier (the component that actually builds/executes blocks) *does* perform. This creates a soundness gap between the executor that decides transaction outcomes at block-building time and the OS that re-executes the block to produce the committed state root used for the block hash / proof.

### Finding Description
Any contract can invoke `replace_class` (`replace_class_syscall`) during its own execution — this is a permissionless capability reachable from a single, ordinary invoke transaction, not an operator/prover-only action.

In the Blockifier (used by the sequencer to execute and build blocks), `replace_class` is properly guarded: [1](#0-0) 
It (1) ensures the class hash is declared by reading it (`get_compiled_class`, which fails for undeclared classes) and (2) rejects the replacement with `ForbiddenClassReplacement` if the class is not Cairo1.

However, the corresponding Starknet OS Cairo implementation, which is what the network's provers/re-executors run to produce the committed state (Patricia tree root and block hash), performs neither check. It contains an explicit acknowledgement that the check is missing: [2](#0-1) 
The function blindly builds a new `StateEntry` with the caller-supplied `class_hash` and commits it via `dict_update`, with no validation that the class was declared and no check that it is a Cairo1 class. The legacy/deprecated syscall path in the OS has the identical gap: [3](#0-2) 

Just as AlexLab's vault trusted a self-listed token's transfer function without verifying it was legitimate, the OS trusts the `class_hash` argument of `replace_class` without verifying it references a real, declared class of the correct version — the exact same class of bug (missing verification before a state-mutating action that a privileged component elsewhere in the system does verify).

### Impact Explanation
Because the Blockifier rejects `replace_class` calls with an undeclared or wrong-version class hash (returning an execution error that fails/reverts the transaction), while the OS would silently accept and commit such a change, the two components can produce different outcomes for the same transaction:
- If a transaction manages to reach OS re-execution with a class hash that the Blockifier would have refused, the OS will still write it into `contract_state_changes`, producing a state root/block hash that a Blockifier-based node computing the same block would not produce — an honest-node/state-commitment divergence.
- A contract's `class_hash` in the state tree could be set to an undeclared felt value with no compiled class backing it, effectively bricking the contract (permanent freezing of the contract's logic since no class can be found for such a hash), or set to a Cairo0 class where a Cairo1 class is required, silently changing execution semantics in the OS's model of the world.
- Since the OS's output underlies the proven/committed state (used for L1 state root and block hash finality), this can produce a wrong committed root relative to what the sequencer's execution decided, matching the "wrong committed root or block hash / honest-node divergence" impact class.

### Likelihood Explanation
`replace_class` is a syscall available to any deployed contract and reachable in a single ordinary invoke transaction from an unprivileged sender — no special privileges, staking, or operator/prover role are required to trigger the call. The missing check is unconditional (not gated behind rare configuration), and the OS file itself flags the check as an outstanding TODO, confirming the gap is real and currently present in the OS execution path, not merely a hypothetical.

### Recommendation
Add the same two checks the Blockifier performs to both OS `execute_replace_class` implementations (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`):
1. Verify the target `class_hash` corresponds to a declared class (e.g., assert a class-hash-to-compiled-class fact/commitment exists for it) before permitting the `dict_update`.
2. Verify the declared class is of the expected Cairo version (reject replacement to a Cairo0 class), matching `ForbiddenClassReplacement` semantics in the Blockifier.
Both OS code paths should fail (and propagate a revert/failure) consistently with how the Blockifier fails, to keep the two execution models in lockstep and preserve state-commitment soundness.

### Proof of Concept
1. Declare (or reference an intentionally undeclared) class hash `H` that is either never declared or is a Cairo0 class.
2. From any contract, invoke `replace_class_syscall(H)`.
3. In the Blockifier execution path, `self.base.replace_class(H)` calls `state.get_compiled_class(H)?` which errors for an undeclared class (or returns `ForbiddenClassReplacement` for a Cairo0 target), causing the transaction/call to fail as expected — see `crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`.
4. If the same call/transaction data is instead processed through the Starknet OS `execute_replace_class` path (`syscall_impls.cairo:881-920` or `deprecated_execute_syscalls.cairo:307-329`), no equivalent check exists: the OS unconditionally writes `new_state_entry` with `class_hash=H` into `contract_state_changes`, producing a state entry/state root inconsistent with what the Blockifier would have allowed.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
