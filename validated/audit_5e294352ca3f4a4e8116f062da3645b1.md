Based on my research, I found a valid analog. The Push Chain codebase implements a gas-price/chain-meta oracle system that is directly analogous to the Chainlink `latestRoundData()` price feed pattern from the bug report. Critically, the staleness protection exists only at the **vote/write** side of the oracle, not at the **read/consumption** side where the price is actually used for fund-affecting fee accounting.

### Title
Gas price oracle staleness is enforced only at vote time, not at consumption time for fee accounting - (File: x/uexecutor/keeper/gas_fee.go, x/uexecutor/keeper/evm.go, x/uexecutor/keeper/build_revert_outbound.go)

### Summary
The `x/uexecutor` module maintains a validator-voted gas-price/chain-meta oracle (`ChainMeta`) with an explicit staleness window (`chainMetaVoteStalenessSeconds = 300`) enforced when validators *vote* on prices [1](#0-0) . However, once the median price is written on-chain via `CallUniversalCoreSetChainMeta`, all downstream fee-accounting consumers (`GetOutboundTxGasAndFees`, `GetGasPriceByChain`, `GetGasFeeInfoForRevertOutbound`) read the value directly from the `UniversalCore` EVM contract with **no freshness check at read time** [2](#0-1) [3](#0-2) . The contract even exposes a `timestampObservedAtByChainNamespace` view function specifically for this purpose [4](#0-3) , but this function is never called from any Go keeper code — no code reference to it exists outside `abi.go`.

### Finding Description
The chain-level price staleness guard in `VoteChainMeta` only prevents a stale *vote* from being counted toward the median (`age <= chainMetaVoteStalenessSeconds`) [5](#0-4) . Once bootstrapped, the median value is written into `UniversalCore` and persists indefinitely as the "current" gas price until the next validator vote updates it [6](#0-5) . If universal validators stop voting for a chain (e.g. an RPC outage on the destination chain, a chain being deprioritized, or a targeted network partition against the `ChainMetaOracle` component in `universalClient/chains/evm/chain_meta_oracle.go`), the on-chain gas price simply freezes at its last-written value with no on-chain mechanism to detect or reject staleness on read.

Every fee-affecting read path — `GetOutboundTxGasAndFees` (used to compute `gasFee`/`gasPrice`/`gasLimit` for real outbound transactions) [7](#0-6) , `GetGasFeeInfoForRevertOutbound` (used for revert/refund flows) [8](#0-7) , and `GetGasPriceByChain` — calls into the `UniversalCore` contract with a plain `view` call and accepts whatever value is returned, without checking `timestampObservedAtByChainNamespace` against the current block time.

This mirrors the reported bug class exactly: `latestRoundData()`-style price data is consumed without validating that the "round"/observation is fresh, even though the freshness data (`timestampObservedAt`) is available on-chain.

### Impact Explanation
An unprivileged user cannot directly control which price is read, but they can benefit from or be harmed by a stale gas price during normal outbound/refund flows: if the true destination-chain gas price rises sharply while the oracle is stale (low), relayer-funded `gasFee` charged to users on outbound/revert transactions will be under-collected, causing protocol-side gas subsidization/loss; if the destination gas price falls while the oracle is stale (high), the excess-gas refund logic (`applyGasRefund`) computed from `gasFee - gasFeeUsed` [9](#0-8)  will overpay users relative to actual destination-chain cost, systematically draining the protocol's relayer-fee reserve. This directly affects gas-fee/refund accounting invariants in scope (protocol-controlled funds, refund accounting).

### Likelihood Explanation
Likelihood is moderate: it requires the `ChainMetaOracle` votes for a specific chain to stop being fresh (e.g. RPC downtime on that external chain, node connectivity issues, or a chain simply having sparse traffic so no validator revotes for an extended period), which is a plausible operational condition rather than an attacker-controlled trigger. Because the check exists on the vote path but is silently absent on the consumption path, the protocol has no fallback or alert when a chain's price becomes stale in practice, unlike the report's Chainlink case where a compromised/stalled feed is the trigger.

### Recommendation
Read `timestampObservedAtByChainNamespace(chainNamespace)` alongside `gasPriceByChainNamespace` at every fee-computation call site (`GetOutboundTxGasAndFees`, `GetGasPriceByChain`, `GetGasFeeInfoForRevertOutbound`) and reject or flag transactions when `block.timestamp - timestampObservedAt` exceeds a defined staleness threshold (e.g. reuse `chainMetaVoteStalenessSeconds` or a per-chain configurable value), mirroring the report's `answeredInRound >= roundID` / `timestamp != 0` pattern for Chainlink feeds.

### Proof of Concept
1. Universal validators stop submitting `MsgVoteChainMeta` for a given destination chain (e.g. simulate an RPC outage in the `ChainMetaOracle` client for that chain).
2. The last-written price in `UniversalCore.gasPriceByChainNamespace` remains frozen indefinitely; `timestampObservedAtByChainNamespace` grows stale but is never consulted.
3. A user submits a cross-chain outbound (or an inbound that triggers a revert) for that chain; `k.GetOutboundTxGasAndFees` / `k.GetGasFeeInfoForRevertOutbound` read the frozen price with no staleness check [10](#0-9) .
4. If the real-world gas price has since diverged significantly, the computed `gasFee`/refund amount misrepresents actual cost, causing systematic over- or under-collection versus the destination chain's true price.

// Pass gasLimitWithBaseLimit=0 to use the contract's baseLimit.
func (k Keeper) GetOutboundTxGasAndFees(ctx sdk.Context, prc20 common.Address, gasLimitWithBaseLimit *big.Int) (*GasFeeInfo, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
}
