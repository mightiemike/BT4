### Title
`ensure_match_transaction_info` skips `position_state_checkpoint_hash` (and hot-state checkpoint hash) comparison, letting a divergent position/hot-state Merkle root pass replay and chunk-executor verification - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the single self-consistency check used by state-sync's chunk executor and by `db-tool replay-on-archive`/debugger to confirm that a locally re-executed transaction output matches the already-authenticated `TransactionInfo` for that version before the output is treated as verified and committed/reported. The function only compares status, gas, `write_set` hash, and event root hash. It explicitly does **not** compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or the newer `position_state_checkpoint_hash`, a gap the code itself documents as a known limitation.

### Finding Description
`ensure_match_transaction_info` builds `write_set_hash` and `event_root_hash` from the locally produced `TransactionOutput` and asserts equality against `txn_info.state_change_hash()` / `txn_info.event_root_hash()`, but stops there: [1](#0-0) 

The trailing comment is explicit about the consequence:
```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
``` [2](#0-1) 

This function is the safety gate used in two integrity-relevant paths:
- Chunk-executor state-sync replay verification (`verify_execution`), which re-executes a batch of transactions against locally derived state and only proceeds/commits once `ensure_match_transaction_info` succeeds: [3](#0-2) 
- `db-tool`'s `replay_on_archive` verifier, which is the operational tool used to detect state divergence against an authenticated archive: [4](#0-3) 

The new "native position" (trading-native) feature computes an additional Merkle root (`position_state_checkpoint_hash`) alongside the existing state/hot-state checkpoint roots, tracked per-chunk in `StateCheckpointOutput`: [5](#0-4) 
and produced during checkpointing in `DoStateCheckpoint::compute_position_checkpoint`, which independently rebuilds the position SMT from local write sets: [6](#0-5) 

Because `ensure_match_transaction_info` never checks `position_state_checkpoint_hash` (nor `state_checkpoint_hash`/`hot_state_checkpoint_hash`) against the authenticated `TransactionInfo`, any local corruption or divergence in the position-state Merkle computation (bug in `compute_position_checkpoint`, storage bit-flip, incorrect SMT base, etc.) is silently accepted as "verified" by both the state-sync chunk executor and the replay-verify tool.

### Impact Explanation
This breaks a proof/commitment integrity invariant on the state-commitment gate: an authenticated per-transaction commitment (`TransactionInfo.position_state_checkpoint_hash`) is not actually checked against locally derived state before that state is persisted/served. A node whose position-state root has silently diverged from consensus-committed truth will:
- Commit local ledger data (`position_state_summary`) that does not match the checkpoint hash the network actually agreed on, corrupting durable state for the native-position/trading subsystem.
- Continue to serve authenticated proofs/API responses for position state bound to a root that is wrong, since nothing flags the divergence.
- Have this divergence go undetected specifically by `replay_on_archive`, the tool operators rely on to catch exactly this class of bug before or after mainnet rollout.

This matches the required "wrong ... proof ... accepted as valid" and "committed state that differs from correct VM result" impact categories, scoped to the position-state feature path.

### Likelihood Explanation
The severity is real but the current blast radius is bounded by feature-gating: `position_state_checkpoint_hashes`/`compute_position_checkpoint` only run when the native-position/trading feature (`compute_trading_native_state_roots`) is enabled, and the code comment itself instructs to fix this **before** enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, implying it is not yet enabled on mainnet. I could not fully confirm the current on/off state of this feature flag on mainnet within the available search budget — this should be verified before assigning final severity. If the feature is (or becomes) active, likelihood of the gap mattering is high, since it is a missing check on the exact invariant the report doc identifies as necessary, not a hypothetical.

### Recommendation
Extend `ensure_match_transaction_info` to also compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present) between the locally computed value and `txn_info`'s authenticated fields, and fail replay/chunk-sync verification on mismatch — precisely as the existing TODO comment prescribes — before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is turned on for any network.

### Proof of Concept
1. Enable (or simulate enabling) the native-position feature so `execution_output.compute_trading_native_state_roots` is true, producing `position_state_checkpoint_hashes` in `StateCheckpointOutput`.
2. Introduce (or trigger via a genuine bug) a divergence in `DoStateCheckpoint::compute_position_checkpoint`'s SMT extension logic (e.g., wrong `base_summary`/persisted position base after a restart), producing a different `position_state_checkpoint_hash` than the value in the authenticated `TransactionInfo` for that version.
3. Run `db-tool replay_on_archive` or trigger chunk-executor state-sync verification (`ChunkExecutor::verify_execution`) over that version range.
4. Observe that `ensure_match_transaction_info` (`types/src/transaction/mod.rs:2139-2203`) returns `Ok(())` despite the position root mismatch, because it never inspects `position_state_checkpoint_hash`, so the divergent state is accepted as verified and committed.

    fn compute_position_checkpoint(
        execution_output: &ExecutionOutput,
        parent: Option<&LedgerWithSummary<PositionStateWithSummary>>,
        persisted: &ProvablePositionStateSummary,
        known_position_state_checkpoints: Option<Vec<Option<HashValue>>>,
    ) -> Result<(
        LedgerWithSummary<PositionStateWithSummary>,
        Vec<Option<HashValue>>,
    )> {
        let _timer = OTHER_TIMERS.timer_with(&["get_position_checkpoint_hashes"]);

        let num_txns = execution_output.to_commit.len();
        let first_version = execution_output.first_version;
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();
        let base_summary = persisted.summary();
        // No in-memory parent at genesis / first block after enabling: seed
        // from the pre-committed position tip (covers committed writes the
        // merklized snapshot may lag).
        let parent_latest =
            parent.map_or_else(|| persisted.base().latest().clone(), |p| p.latest().clone());
        let parent_last_checkpoint = parent.map_or_else(
            || persisted.base().last_checkpoint().clone(),
            |p| p.last_checkpoint().clone(),
        );

        // Empty chunk: nothing to extend (avoids the `num_txns - 1` underflow).
        if num_txns == 0 {
            let summary = LedgerWithSummary::from_latest_and_last_checkpoint(
                parent_latest,
                parent_last_checkpoint,
            );
            return Ok((summary, vec![]));
        }

        // Collapse position writes (latest-per-key) over a version range into
        // SMT leaf updates.
        let collect = |range: std::ops::Range<usize>| -> Vec<(HashValue, PositionSlot)> {
            let mut latest: HashMap<HashValue, PositionSlot> = HashMap::new();
            for i in range {
                for (key, op) in execution_output.to_commit.transaction_outputs[i]
                    .write_set()
                    .native_position_iter()
                {
                    let value_hash = op.as_write_op().as_state_value_opt().map(StateValue::hash);
                    latest.insert(key.hash(), PositionSlot {
                        state_key: key.clone(),
                        value_hash,
                        value: None,
                    });
                }
            }
            latest.into_iter().collect()
        };

        let (new_latest, new_last_checkpoint) = if let Some(ci) = last_checkpoint_index {
            let checkpoint_version = first_version + ci as u64;
            let new_ckpt = parent_latest.extend(
                checkpoint_version,
                collect(0..ci + 1),
                base_summary,
                persisted,
            )?;
            if ci + 1 == num_txns {
                (new_ckpt.clone(), new_ckpt)
            } else {
                let last_version = first_version + num_txns as u64 - 1;
                let new_latest = new_ckpt.extend(
                    last_version,
                    collect(ci + 1..num_txns),
                    base_summary,
                    persisted,
                )?;
                (new_latest, new_ckpt)
            }
        } else {
            // No checkpoint in this chunk: only the latest advances.
            let last_version = first_version + num_txns as u64 - 1;
            let new_latest = parent_latest.extend(
                last_version,
                collect(0..num_txns),
                base_summary,
                persisted,
            )?;
            (new_latest, parent_last_checkpoint)
        };

        // Per-tx hash vector + known-hash validation (shared with main/hot state).
        let hashes = Self::get_state_checkpoint_hashes(
            execution_output,
            known_position_state_checkpoints,
            new_last_checkpoint.root_hash(),
            "position_state",
        )?;

        let summary =
            LedgerWithSummary::from_latest_and_last_checkpoint(new_latest, new_last_checkpoint);
        Ok((summary, hashes))
    }
