### Title
Unbounded, permanent per-key `ProgramCache` entries force O(total-programs-ever-deployed) work on every rerooting — one-time deploy fee buys recurring cost per validator forever - ([File: program-runtime/src/loaded_programs.rs])

### Summary
`ProgramCache::prune()` iterates and reconstructs (`filter().cloned().collect()`) the `second_level: Vec<Arc<ProgramCacheEntry>>` for *every* key in the `entries: HashMap<Pubkey, Vec<...>>` index on every call, and this call happens on every root advance [1](#0-0) . Because there is no mechanism that removes a key from `entries` when its program account is simply left untouched (eviction only unloads bytecode in place, it does not remove the map entry, and `remove_programs`/`prune_by_deployment_slot` are only invoked for CPI-migration and dead/duplicate-slot purges, not for ordinary account closure), an attacker who deploys many cheap, never-reused programs causes the `entries` map — and thus the per-root prune cost — to grow monotonically and never shrink back.

### Finding Description
`ProgramCache::prune` is called from `Bank::prune_program_cache` → `BankForks::prune_program_cache`, which is invoked on every new root via `set_bank_forks_root` / `check_and_handle_new_root` (i.e., roughly once per confirmed slot) [2](#0-1) [3](#0-2) [4](#0-3) .

Inside `prune()`, the outer `for second_level in entries.values_mut()` loop touches **every key currently present in the cache index**, regardless of whether that program has ever been executed again since deployment, doing a `.iter().rev().filter(...).cloned().collect()` pass plus a `.reverse()` on the (usually 1-element) `Vec` for each key [5](#0-4) . This is O(total number of distinct keys in the index) per call, unconditionally, on every root.

Crucially, nothing removes a key from `entries` just because the corresponding program is never used again or its account is later closed:
- `evict_using_random_selection`/`unload_program_entry` only replace `ProgramCacheEntryType::Loaded` with `Unloaded` in place; they keep the `Vec` entry (and thus the `Pubkey` key) in the map [6](#0-5) .
- The only paths that actually delete entries from `entries` are `prune_by_deployment_slot` (called when purging duplicate/dead blockstore slots, not for ordinary unused programs) [7](#0-6) , `remove_programs` (only used by BPF-loader-to-core migration) and `remove_programs_with_no_entries` (only fires when a key's `Vec` becomes fully empty, which for a live, un-orphaned single deployment never happens) [8](#0-7) .

Because a normal deployment on the live fork is never "orphaned" and never falls to zero versions, its key is retained by `prune()`'s own filter (`entry.deployment_slot >= new_root_slot` / `BlockRelation::Ancestor` branches keep it) forever [9](#0-8) . An unprivileged attacker only needs to pay the one-time deploy fee (transaction fees + rent-exempt reserve, which is refundable/lockable, not destroyed) for each of thousands of tiny, distinct program keys. Every one of those keys then costs every validator a small amount of CPU/allocation work on literally every subsequent root, in perpetuity, since the cache never forgets an un-orphaned key.

The narrower `retain_flags` Vec<bool> allocation block is gated behind `new_environment.is_some()`, which only fires at epoch boundaries (via `epoch_boundary_preparation.reroot(...)` in `Bank::prune_program_cache`), so that specific sub-cost is bounded to once-per-epoch rather than every root [10](#0-9) [11](#0-10) . However, the unconditional outer filter/clone/collect/reverse pass over every key (lines 519-561) does run every root and is the actual source of unbounded, permanent per-root cost scaling with the total number of distinct keys ever deployed and never orphaned/migrated.

### Impact Explanation
This is a disproportionate, unbounded background-cleanup cost: the attacker's one-time fee for creating N cheap, distinct program accounts causes O(N) extra allocation/iteration work on **every future root**, for the lifetime of the cluster (or until those programs are somehow migrated to core-BPF or land on a pruned/orphaned fork). This matches the "background rerooting slow-down proportional to attacker's cheap account creation, not CU spent" impact category — a validator availability/performance-degradation issue rather than a correctness bug, since the cache remains logically correct (extract/lookup semantics are unaffected), only expensive.

### Likelihood Explanation
Fully feasible for an unprivileged attacker: deploy many small BPF programs (each requiring only a minimal ELF and rent-exempt deposit), never invoke them again, and let the cluster continue rooting normally. No validator/leader/staking control or special timing is required — this happens automatically as part of every `set_root`/`prune_program_cache` call and accumulates over the lifetime of the chain as more one-off/garbage programs are deployed by anyone. This is directly reproducible in a unit/benchmark test against `ProgramCache::prune`.

### Recommendation
Bound the per-root work independent of total historical distinct-key count, e.g.:
- Track and periodically evict/garbage-collect keys whose `second_level` has been `Unloaded`/inactive for a long time and is not on an active fork boundary case, rather than only removing keys when the `Vec` is fully empty.
- Consider maintaining a separate lightweight index of "keys that need orphan-fork checking this root" (i.e., keys touched since the previous prune) instead of unconditionally re-scanning the entire `entries` map every root.
- Cap total distinct keys retained in `entries` (similar to the `MAX_LOADED_ENTRY_COUNT`/`shrink_to_percent` eviction cap that exists for loaded bytecode) and actually remove least-recently-used, non-active keys from the map instead of merely marking them `Unloaded` in place.

### Proof of Concept
Rust benchmark/integration test plan against `program-runtime/src/loaded_programs.rs`:
```rust
#[test]
fn bench_prune_scales_with_total_distinct_keys() {
    // Build increasingly large ProgramCache instances (e.g. 1_000, 10_000, 100_000 distinct
    // Pubkey keys), each with a single deployment_slot entry that is never re-referenced
    // and sits on the "live" fork (BlockRelation::Ancestor / Equal), simulating an attacker
    // who deployed many cheap, unused programs.
    for n in [1_000usize, 10_000, 100_000] {
        let mut cache = ProgramCache::<TestForkGraph>::new(0);
        let env = get_mock_program_runtime_environment();
        let fork_graph = Arc::new(RwLock::new(TestForkGraph { relation: BlockRelation::Ancestor }));
        cache.set_fork_graph(Arc::downgrade(&fork_graph));
        for _ in 0..n {
            let key = Pubkey::new_unique();
            cache.assign_program(&env, key, 0, new_test_entry(0));
        }
        let start = std::time::Instant::now();
        cache.prune(1, None, &fork_graph.read().unwrap());
        let elapsed = start.elapsed();
        println!("n={n} prune_elapsed={elapsed:?}");
        // Assert near-linear (unbounded) growth with n, demonstrating the map is never
        // shrunk despite none of these keys ever being used again, and that prune's cost
        // to every future root scales with n indefinitely.
    }
}
```
Expected result: wall-clock time of `prune()` scales roughly linearly with the number of distinct never-reused keys, and repeated calls to `prune()` on subsequent simulated roots continue to pay this same O(n) cost indefinitely because none of the unused keys are ever removed from `entries`.

    /// This function removes the given entry for the given program from the cache.
    /// The function expects that the program and entry exists in the cache. Otherwise it'll panic.
    fn unload_program_entry(
        &mut self,
        id: Pubkey,
        _last_modification_slot: Slot,
        remove_entry: &Arc<ProgramCacheEntry>,
    ) {
        match &mut self.index {
            IndexImplementation::V1 { entries, .. } => {
                let second_level = entries.get_mut(&id).expect("Cache lookup failed");
                let candidate = second_level
                    .iter_mut()
                    .find(|entry| Arc::ptr_eq(entry, remove_entry))
                    .expect("Program entry not found");

                // Only loaded entries shall be unloaded by eviction.
                if let ProgramCacheEntryType::Loaded(_) = candidate.program
                    && let Some(unloaded) = candidate.to_unloaded()
                {
                    if candidate.stats.uses.load(Ordering::Relaxed) == 1 {
                        self.stats.one_hit_wonders.fetch_add(1, Ordering::Relaxed);
                    }
                    self.stats
                        .evictions
                        .entry(id)
                        .and_modify(|c| *c = c.saturating_add(1))
                        .or_insert(1);
                    *candidate = Arc::new(unloaded);
                }
            }
        }
    }

    fn remove_programs_with_no_entries(&mut self) {
        match &mut self.index {
            IndexImplementation::V1 { entries, .. } => {
                let num_programs_before_removal = entries.len();
                entries.retain(|_key, second_level| !second_level.is_empty());
                if entries.len() < num_programs_before_removal {
                    self.stats.empty_entries.fetch_add(
                        num_programs_before_removal.saturating_sub(entries.len()) as u64,
                        Ordering::Relaxed,
                    );
                }
            }
        }
    }
