## Title
Unbounded Gzip Decompression in RPC `decompress_program` Enables Zip-Bomb Memory-Exhaustion DoS - (File: `crates/apollo_rpc/src/v0_8/api/mod.rs`)

### Summary
The `decompress_program` helper used to convert a user-submitted, base64/gzip-compressed Cairo0 `program` field (as part of a `BroadcastedDeclareV1Transaction`) into an in-memory `Program` performs **unbounded** decompression via `GzDecoder::read_to_end`, with no size or time limit, exactly mirroring the Wazuh `fdecompress_files()` zip-bomb class of bug.

### Finding Description
`decompress_program` decodes the caller-supplied base64 string and streams it through a `flate2::bufread::GzDecoder` directly into a growing `Vec<u8>` with `read_to_end`, with an explicit unresolved `TODO(dan): add time and size limits.` comment acknowledging the missing guard: [1](#0-0) 

This function is reached from `user_deprecated_contract_class_to_sn_api`, which is invoked when converting a `BroadcastedDeclareV1Transaction` (an unprivileged, user-controlled RPC input) into an `ExecutableTransactionInput::DeclareV1`: [2](#0-1) 

That conversion is triggered by the public `starknet_estimateFee` JSON-RPC method, which accepts a list of `BroadcastedTransaction` from any caller and converts each via `tx.try_into()` before executing it in a `spawn_blocking` task: [3](#0-2) 

By contrast, every other decompression path in the codebase enforces a bound: the gateway's Sierra-class path uses `decode_and_decompress_with_size_limit`, which bounds the `GzDecoder` read via `.take(max_size + 1)`: [4](#0-3) 

and storage-side compression enforces `MAX_DECOMPRESSED_SIZE` (256 MB): [5](#0-4) 

`decompress_program`, however, was never updated to use these bounded primitives, leaving a genuine unbounded-decompression gap.

### Impact Explanation
A caller of the public `starknet_estimateFee` RPC method can submit a `DECLARE` V1 transaction whose `contract_class.program` field is a small, highly-compressed gzip payload (a "zip bomb") that expands to gigabytes in memory. Because `read_to_end` has no cap, this forces the node process to allocate unbounded memory per request, exhausting RAM and causing the RPC/node process to crash or become unresponsive — a denial-of-service against the node servicing that RPC endpoint. This directly matches "a network unable to confirm new transactions" if the affected process also participates in gateway/mempool serving on the same node deployment.

### Likelihood Explanation
The endpoint is public, requires no special privileges or keys, and the exploit input (a valid base64 + gzip encoded JSON) is trivial to construct. No stateful preconditions (balance, nonce, prior class declaration) are needed since `estimate_fee` does not require the transaction to ever be included in a block.

### Recommendation
Replace the raw `GzDecoder::read_to_end` call in `decompress_program` with the existing bounded utility (`decode_and_decompress_with_size_limit` / a `.take(max_size)` wrapped reader), enforcing the same `MAX_CAIRO0_PROGRAM_SIZE`-style limit already used elsewhere (e.g. `crates/apollo_protobuf/src/converters/class.rs`), and resolve the outstanding `TODO(dan)` comment.

### Proof of Concept
1. Craft a JSON payload representing a `BROADCASTED_DECLARE_TXN_V1` with a `contract_class.program` field set to the base64 encoding of a gzip "quine"/zip-bomb (e.g., a few KB of compressed data expanding to several GB).
2. Send it to the node's `starknet_estimateFee` JSON-RPC endpoint.
3. Observe `decompress_program` (`crates/apollo_rpc/src/v0_8/api/mod.rs:671`) attempting to fully materialize the decompressed payload in memory, causing memory exhaustion / OOM kill of the serving process. [1](#0-0)

pub(crate) fn decompress_program(
    base64_compressed_program: &String,
) -> Result<Program, ErrorObjectOwned> {
    base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    let compressed_data =
        base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    // TODO(dan): add time and size limits.
    let mut decoder = GzDecoder::new(compressed_data.as_slice());
    let mut decompressed = Vec::new();
    decoder.read_to_end(&mut decompressed).map_err(internal_server_error)?;
    serde_json::from_reader(decompressed.as_slice()).map_err(internal_server_error)
}

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
