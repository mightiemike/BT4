### Title
Stale Cache Bypass for Cairo0 Contract Class Declaration Checks - (File: `crates/blockifier/src/state/state_reader_and_contract_manager.rs`)

### Summary
The global, cross-block `ContractClassManager` cache used by the sequencer to serve compiled contract classes only re-validates declaration status against the authoritative state reader for Cairo1 classes. Cairo0 (`RunnableCompiledClass::V0`) cache hits are returned unconditionally, with no re-check that the class is still declared in the current committed state. This is analogous to the OpenFGA bug where a `Check`/`ListObjects` cache entry can be served without accounting for state that has since changed (there, a tuple cycle plus TTL cache; here, a reverted/uncommitted declare plus a long-lived global cache), producing an authorization decision ("this class is declared/usable") that no longer reflects ground truth.

### Finding Description
`StateReaderAndContractManager::get_compiled_from_class_manager` explicitly guards against serving stale cache entries for non-Cairo0 classes: [1](#0-0) 

```
match &runnable_class {
    RunnableCompiledClass::V0(_) => {}
    _ => {
        // The Cairo1 class is cached; verify it is declared,
        // since existence in the cache does not guarantee that
        // (it might contain a declared class from a reverted block, for example).
        if !self.state_reader.is_declared(class_hash)? {
            return Err(StateError::UndeclaredClassHash(class_hash));
        }
    }
}
```

The comment itself documents the threat model: the `contract_class_manager` cache is global/long-lived and can retain entries for classes that were populated speculatively (e.g., declared during execution of a candidate block, or a block that is later reverted) but never actually committed. The mitigation (calling `self.state_reader.is_declared(class_hash)`) is applied only to the `_` branch (Cairo1/V1/Native), not to the `RunnableCompiledClass::V0(_)` branch (Cairo0). The `FetchCompiledClasses::is_declared` trait doc even states "Cairo 0 classes always return `false`" [2](#0-1) , meaning the check couldn't have been used for Cairo0 as-is, but no equivalent "is this class hash currently declared" check exists for the Cairo0 path.

Consequently, once a Cairo0 class hash has been placed into the cache (e.g., during declare-transaction validation in the gateway's `StatefulTransactionValidator` [3](#0-2) , or during speculative block building), a subsequent lookup of that class hash returns the cached compiled class as valid without ever consulting the state reader to confirm the class is still declared in the committed state.

### Impact Explanation
If a candidate declare transaction (or a declare that is later reorged/rejected/rebuilt) populates this shared, cross-block cache with a Cairo0 class, any later transaction referencing that class hash (e.g., a `deploy`/`replace_class`/`invoke` flow that should fail with `UndeclaredClassHash`) can instead succeed on nodes that happen to hold the stale cache entry, while honest nodes without that cache entry correctly reject it. This creates:
- Honest-node divergence: nodes with a warm cache accept execution paths that nodes with a cold cache reject, since the class-declared invariant is not being consistently enforced from the single source of truth (state).
- Unauthorized use of a never-committed (undeclared) contract class in execution, which can affect the resulting state diff/commitment for the block being built.

### Likelihood Explanation
The cache (`ContractClassManager`/`TrivialClassManager`/`NativeClassManager`) is shared and long-lived across the gateway's stateful validation and the batcher's block-building/re-validation paths [4](#0-3) , and is only explicitly cleared on revert in the legacy `native_blockifier` Python bridge path [5](#0-4) , not necessarily in every code path where a speculative or rejected declare of a Cairo0 class could populate it. An attacker only needs to submit a Cairo0 declare transaction that gets speculatively processed/cached and subsequently is not (or not yet) reflected in committed state, then submit a follow-up transaction referencing that class hash.

### Recommendation
Apply the same re-validation used for the Cairo1 branch to the `RunnableCompiledClass::V0(_)` branch: add (or extend) a state-reader check (e.g., a `is_declared_cairo0`/generalized `is_class_hash_declared`) that is queried on every cache hit for Cairo0 classes too, so that `get_compiled_from_class_manager` never returns a class as usable purely from cache without confirming declaration against the authoritative state reader.

### Proof of Concept
1. Submit (or have the batcher speculatively execute) a `Declare` transaction for a Cairo0 contract class `C` with hash `class_hash`. This causes `get_compiled_from_class_manager` to populate the global cache via `contract_class_manager.set_and_compile(class_hash, ...)` [6](#0-5) .
2. Ensure this declare is not committed to state (e.g., the candidate block/proposal containing it is dropped, reorged, or the declare tx itself is later rejected/never finalized), so `state_reader.is_declared(class_hash)` (conceptually) would return false / the class does not exist in committed storage.
3. Submit a follow-up transaction (e.g., another declare-dependent flow, or a call that requires `class_hash` to be declared) that triggers `get_compiled_class(class_hash)` again on a node holding the warm cache.
4. Observe that because `RunnableCompiledClass::V0(_)` hits the cache branch with no declaration re-check, the transaction proceeds as if `class_hash` were declared, whereas a node without the cached entry (cold cache) would call `state_reader.get_compiled_classes` and correctly fail since the class was never committed — producing divergent execution/state results between the two nodes.

impl<S: FetchCompiledClasses> StateReaderAndContractManager<S> {
    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }
