Confirmed: `ForbidTransferToContract` is enforced only in `TransferActuator.validate()` ( [1](#0-0) ) and `TransferAssetActuator.validate()` ( [2](#0-1) ), but the semantically equivalent internal TVM transfer-validation helper used by contract opcodes (`transferToken`, internal `CALL` with value, `suicide`) has no such check at all.

### Title
`ForbidTransferToContract` switch is bypassed by TVM internal transfers/`suicide` - (File: `actuator/src/main/java/org/tron/core/vm/VMUtils.java`, `actuator/src/main/java/org/tron/core/vm/program/Program.java`)

### Summary
`ForbidTransferToContract` is a governance-controlled switch (`DynamicPropertiesStore.getForbidTransferToContract()`) intended to prevent TRX/TRC10 assets from being sent to smart-contract accounts through the top-level transfer actuators, protecting version-1 contracts that cannot safely receive value. This mirrors the "pause" concept in the external report: a restriction is enforced on one entry point but bypassable through a different entry point that reaches the same underlying effect. In java-tron, the check exists only in `TransferActuator.validate()` and `TransferAssetActuator.validate()`, but is completely absent from `VMUtils.validateForSmartContract()` (used for internal TRX and TRC10 transfers originating from contract code, e.g. the `transferToken`/`CALL` opcodes) and from `Program.suicide()`/`Program.suicide2()`, which move TRX and all TRC10 balances to an arbitrary "obtainer" address via `MUtil.transfer`/`MUtil.transferAllToken` with no contract-destination restriction at all.

### Finding Description
`TransferActuator.validate()` and `TransferAssetActuator.validate()` both gate top-level transfers to contract accounts behind `dynamicStore.getForbidTransferToContract() == 1`: [1](#0-0) [2](#0-1) 

However, the internal transfer validator used by the TVM for value/asset movements caused by contract execution never performs this check: [3](#0-2) [4](#0-3) 

Likewise, `Program.suicide()`/`suicide2()` transfer the full TRX balance and all TRC10 token balances of a self-destructing contract to an arbitrary address (which can be another contract) with no `ForbidTransferToContract`-style restriction: [5](#0-4) 

Because a smart contract's internal `CALL` (value transfer), `transferToken`, or `selfdestruct(target)` all route through these unrestricted code paths instead of through `TransferActuator`/`TransferAssetActuator`, any account can deploy a helper contract that forwards TRX or TRC10 tokens (or self-destructs) to a target smart-contract address, achieving exactly the transfer that the top-level actuators are configured to reject.

### Impact Explanation
When `ALLOW ForbidTransferToContract` (or equivalently `getAllowTvmCompatibleEvm` combined restriction for version-1 contracts) is enacted network-wide via governance to protect contracts unable to handle received value/tokens, this protection can be trivially circumvented by anyone using a one-line proxy contract. This defeats the safety guarantee the switch is supposed to provide and can lead to funds/tokens being stranded or mishandled in contracts that were never expected to receive them, which is an accounting/asset-safety issue reachable from an ordinary broadcast transaction (deploying and triggering a contract).

### Likelihood Explanation
Likelihood is high: no privileged role is required. Any user can deploy a trivial contract whose fallback/function performs a `call{value: x}(target)`, `target.transferToken(...)`, or `selfdestruct(target)`, all of which are ordinary TVM opcodes unaffected by the `ForbidTransferToContract` switch.

### Recommendation
Enforce the `ForbidTransferToContract` (and related `AllowTvmCompatibleEvm` version-1 contract) checks inside `VMUtils.validateForSmartContract()` and inside `Program.suicide()`/`suicide2()` before transferring TRX or TRC10 balances to a destination account of `AccountType.Contract`, mirroring the checks already present in `TransferActuator` and `TransferAssetActuator`.

### Proof of Concept
1. Governance enacts `ForbidTransferToContract = 1` via `ProposalCreateActuator`, so `dynamicStore.getForbidTransferToContract() == 1`.
2. Deploy `ContractB` (a plain, non-payable-restricted contract) as the intended "protected" target, and deploy `ContractA` with a function `forward(address target) payable { target.call{value: msg.value}(""); }` or, for TRC10, `target.transferToken(amount, tokenId)`.
3. Call `TransferActuator`/`TransferAssetActuator` directly against `ContractB` — this fails with `"Cannot transfer TRX to a smartContract."` / `"Cannot transfer asset to smartContract."` as expected ( [1](#0-0) ).
4. Instead, call `TriggerSmartContract` on `ContractA.forward(ContractB)` with value/token attached. Because `VMUtils.validateForSmartContract` performs no `ForbidTransferToContract` check ( [3](#0-2) ), the internal `CALL`/`transferToken` succeeds and `ContractB` receives the TRX/TRC10, bypassing the governance-enacted restriction. The same bypass is achievable via `ContractA` self-destructing with `ContractB` as the inheritor ( [5](#0-4) ).

      byte[] toAddress, long amount) throws ContractValidateException {
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid ownerAddress!");
    }
    if (!DecodeUtil.addressValid(toAddress)) {
      throw new ContractValidateException("Invalid toAddress!");
    }

    if (Arrays.equals(toAddress, ownerAddress)) {
      throw new ContractValidateException("Cannot transfer TRX to yourself.");
    }

    AccountCapsule ownerAccount = deposit.getAccount(ownerAddress);
    if (ownerAccount == null) {
      throw new ContractValidateException("Validate InternalTransfer error, no OwnerAccount.");
    }

    AccountCapsule toAccount = deposit.getAccount(toAddress);
    if (toAccount == null) {
      throw new ContractValidateException(
          "Validate InternalTransfer error, no ToAccount. And not allowed to create an account in a smartContract.");
    }

    long balance = ownerAccount.getBalance();

    if (amount < 0) {
      throw new ContractValidateException("Amount must be greater than or equals 0.");
    }

    try {
      if (balance < amount) {
        throw new ContractValidateException(
            "Validate InternalTransfer error, balance is not sufficient.");
      }

      addExact(toAccount.getBalance(), amount, VMConfig.disableJavaLangMath());
    } catch (ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }

    return true;
  }

  public static boolean validateForSmartContract(Repository deposit, byte[] ownerAddress,
      byte[] toAddress, byte[] tokenId, long amount) throws ContractValidateException {
    if (deposit == null) {
      throw new ContractValidateException("No deposit!");
    }

    byte[] tokenIdWithoutLeadingZero = ByteUtil.stripLeadingZeroes(tokenId);

    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid ownerAddress");
    }
    if (!DecodeUtil.addressValid(toAddress)) {
      throw new ContractValidateException("Invalid toAddress");
    }

    if (amount <= 0) {
      throw new ContractValidateException("Amount must greater than 0.");
    }

    if (Arrays.equals(ownerAddress, toAddress)) {
      throw new ContractValidateException("Cannot transfer asset to yourself.");
    }

    AccountCapsule ownerAccount = deposit.getAccount(ownerAddress);
    if (ownerAccount == null) {
      throw new ContractValidateException("No owner account!");
    }

    if (deposit.getAssetIssue(tokenIdWithoutLeadingZero) == null) {
      throw new ContractValidateException("No asset !");
    }
    if (!Commons.getAssetIssueStoreFinal(deposit.getDynamicPropertiesStore(),
        deposit.getAssetIssueStore(), deposit.getAssetIssueV2Store())
        .has(tokenIdWithoutLeadingZero)) {
      throw new ContractValidateException("No asset !");
    }

    Long assetBalance = ownerAccount.getAsset(deposit.getDynamicPropertiesStore(),
            ByteArray.toStr(tokenIdWithoutLeadingZero));
    if (null == assetBalance || assetBalance <= 0) {
      throw new ContractValidateException("assetBalance must greater than 0.");
    }
    if (amount > assetBalance) {
      throw new ContractValidateException("assetBalance is not sufficient.");
    }

    AccountCapsule toAccount = deposit.getAccount(toAddress);
    if (toAccount != null) {
      assetBalance = toAccount.getAsset(deposit.getDynamicPropertiesStore(),
              ByteArray.toStr(tokenIdWithoutLeadingZero));
      if (assetBalance != null) {
        try {
          addExact(assetBalance, amount,
              VMConfig.disableJavaLangMath()); //check if overflow
        } catch (Exception e) {
          logger.debug(e.getMessage(), e);
          throw new ContractValidateException(e.getMessage());
        }
      }
    } else {
      throw new ContractValidateException(
          "Validate InternalTransfer error, no ToAccount. And not allowed to create account in smart contract.");
    }

    return true;
  }
