### Title
Open Redirect via unvalidated `exitIframe` query parameter — ([File: packages/apps/shopify-app-react-router/src/server/authenticate/admin/authenticate.ts] / [File: packages/apps/shopify-app-react-router/src/server/authenticate/admin/helpers/validate-redirect-url.ts])

### Summary
The `exitIframe` query parameter handled by the library's built-in `/auth/exit-iframe` route is passed unsanitized (beyond protocol/whitespace checks) into `window.open()` on an auto-rendered HTML page, reachable by an anonymous, unauthenticated HTTP request. `sanitizeRedirectUrl` verifies the URL has a safe *format* (no `file://`, no whitespace, `http(s)` protocol) but never verifies the destination's *origin* matches the app, which is the same class of flaw as the reported bridge issue: a "destination" check exists (protocol/shape validity) but the actual target's legitimacy/existence relative to the current context is never verified.

### Finding Description
`respondToExitIframeRequest` reads the `exitIframe` param straight from the request URL and forwards it to `renderAppBridge` before any session/authentication is established: [1](#0-0) 

`renderAppBridge` sanitizes the URL via `sanitizeRedirectUrl(config.appUrl, redirectTo.url)` and then embeds it directly in an inline `<script>` that calls `window.open`: [2](#0-1) 

The sanitizer only checks protocol/shape, not origin — `new URL(redirectUrl, domain)` will happily resolve to an attacker's absolute URL (e.g. `https://evil.example.com`) rather than being forced onto `domain`: [3](#0-2) 

This mirrors the audited bridge bug: `bridgeAsset`/`bridgeMessage` checked that `destinationNetwork != networkID` but never checked the destination was *valid/legitimate*; here `sanitizeRedirectUrl` checks the URL is *well-formed* (safe protocol, no `file://`) but never checks the destination is the *same, legitimate origin* as `config.appUrl`. This is confirmed by the library's own generated documentation, which explicitly warns that the underlying `redirect` helper "does not validate the destination URL": [4](#0-3) 

Unlike the `redirect()` helper (only reachable from within an already-authenticated `authenticate.admin` context, and meant for app-developer-controlled URLs), `respondToExitIframeRequest` is invoked unconditionally for any request whose path ends in `config.auth.exitIframePath` (default `/auth/exit-iframe`), before `getSessionTokenContext`/session loading occurs, making it reachable by anonymous requests.

### Impact Explanation
An attacker can craft a link to the merchant-facing app's own domain (e.g. `https://<merchant-app>/auth/exit-iframe?exitIframe=https://evil.example.com&shop=<shop>.myshopify.com`) that the target's browser will load. The app renders a trusted-looking page (served from the real app origin, matching CSP/App Bridge script) that immediately opens the attacker's URL via `window.open(..., '_top')`. This is a classic open redirect served from the legitimate app origin, useful for phishing (stealing OAuth/session credentials by redirecting to a fake Shopify login), bypassing origin-based allow-lists, or chaining with other flows that trust the app's own domain in redirect targets.

### Likelihood Explanation
High for exposure, moderate for exploit impact: the route is unauthenticated and requires only a single crafted URL to a real, already-installed app instance — no privileged actor, no leaked secret, no MITM required. The test suite confirms absolute cross-protocol/host URLs pass through as long as they use `http`/`https` and aren't malformed (`file:///not/allowed/path` is rejected, but `https://evil.com` is not): [5](#0-4) 

### Recommendation
In `sanitizeRedirectUrl` (and equivalently in `shopify-app-remix`'s copy), enforce that the resolved URL's origin matches `domain` (`config.appUrl`) unless the caller explicitly opts into an external redirect (e.g. via an allow-list), rather than merely validating protocol/whitespace/file-uri shape. At minimum, `respondToExitIframeRequest` should restrict `exitIframe` to same-origin/relative paths only, since it is driven entirely by untrusted user input prior to authentication.

### Proof of Concept
```
GET /auth/exit-iframe?exitIframe=https%3A%2F%2Fevil.example.com&shop=test-shop.myshopify.com HTTP/1.1
Host: legitimate-app.example.com
```
Response (200, served from the legitimate app origin) contains:
```html
<script data-api-key="..." src="https://cdn.shopify.com/shopifycloud/app-bridge.js"></script>
<script>window.open("https://evil.example.com/", "_top")</script>
```
confirmed against the existing test fixture pattern that exercises this exact code path with an attacker-supplied `exitIframe` value: [5](#0-4) 

**Caveat:** I could not fully verify from the index alone whether `config.appUrl`'s scheme/host is ever cross-checked elsewhere in the pipeline (e.g., at a CSP or reverse-proxy layer) before this response reaches the browser; a Devin session with full repo/runtime access would be needed to confirm there is no additional origin enforcement layer outside the indexed files.

export function renderAppBridge(
  {api, config}: BasicParams,
  request: Request,
  redirectTo?: RedirectToOptions,
): never {
  let redirectToScript = '';
  if (redirectTo) {
    const destination = sanitizeRedirectUrl(config.appUrl, redirectTo.url);

    const target = redirectTo.target ?? '_top';

    redirectToScript = `<script>window.open(${JSON.stringify(
      destination.toString(),
    )}, ${JSON.stringify(target)})</script>`;
  }

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
