## Finding [1](#0-0) 

### Title
Unbounded recursion in compiled-class-hash computation over attacker-controlled `bytecode_segment_lengths` causes gateway/sequencer stack overflow (DoS) - (File: crates/starknet_api/src/contract_class/compiled_class_hash.rs)

### Summary
The bug class reported for `eml_parser` is a recursive-descent parser that processes deeply nested attacker-supplied structures without any recursion-depth guard, causing the process to exhaust its call stack and crash while handling a single piece of untrusted input. The sequencer has a direct analog: `bytecode_hash_node`, which recursively walks a `NestedIntList` (`bytecode_segment_lengths`) taken straight from an attacker-declared `CasmContractClass`, with no depth check, no iterative fallback, and no dedicated stack allocation — unlike other recursive paths in this codebase (e.g. Cairo-Native call recursion, which is run on a purpose-sized thread stack, see `crates/blockifier/src/blockifier/transaction_executor.rs:310-345`).

### Finding Description
When the gateway compiles a declared Sierra class, `SierraCompiler::compile` first invokes the Sierra→CASM compiler binary in a resource-limited subprocess, but then computes the compiled-class hash **in-process, on the gateway's own thread**, with no sandboxing: [2](#0-1) 

That hash computation calls `HashableCompiledClass::hash`, which calls `bytecode_hash`, which recurses through `bytecode_hash_node` once per nesting level of `bytecode_segment_lengths: Option<NestedIntList>`: [3](#0-2) 

`NestedIntList` is a `Leaf(usize) | Node(Vec<NestedIntList>)` enum that is produced by the (subprocess-isolated) Sierra→CASM compiler from the structure of the submitted Sierra program's functions/branches, then serialized back into the `CasmContractClass` JSON that the gateway process deserializes and hashes: [4](#0-3) 

The `bytecode_hash_node` recursion has **no depth limit and no iterative rewrite**; each nesting level in `Node(Vec<NestedIntList>)` adds one native stack frame. Because a declare transaction may submit a Sierra program up to the configured size limits (`max_contract_bytecode_size` = 81920, `max_contract_class_object_size` ≈ 4 MB), an attacker can craft a contract whose control-flow/function structure forces the compiler to emit a segment tree that is deeply nested (proportional to nested function/branch structure rather than bytecode length), driving `bytecode_hash_node`'s recursion depth high enough to overflow the gateway process's native stack.

Unlike a Python `RecursionError` (which is at least catchable), a native Rust stack overflow from unbounded recursion is generally **not catchable** — it aborts the process outright. This makes the sequencer analog strictly more severe than the original `eml_parser` report: instead of one malformed email failing to parse, one malicious declare transaction can crash the entire gateway/sequencer process handling it.

### Impact Explanation
A single declare transaction, submittable by any unprivileged user, can crash the gateway/batcher process performing compiled-class-hash computation, since this hash routine runs unsandboxed and with the default thread stack (unlike Cairo-Native execution, which is deliberately isolated on a stack-sized thread per `crates/blockifier/src/blockifier/transaction_executor.rs:310-345`, and unlike Cairo call recursion, which is capped by `RecursionDepthGuard`/`max_recursion_depth`, see `crates/blockifier/src/execution/entry_point.rs:706-733`). A crash of the gateway/sequencer process directly impacts the network's ability to accept and confirm new transactions until the process is restarted, and can be repeated indefinitely by resubmitting the crafted declare transaction — a repeatable denial-of-service against transaction admission.

### Likelihood Explanation
Likelihood is high: the only prerequisite is submitting a syntactically valid declare transaction whose Sierra program compiles successfully but yields a deeply nested `bytecode_segment_lengths` tree; no privileged role, staking, or special network position is required — a single external declare transaction sender can reach this path via the normal gateway validation/compilation flow (`crates/apollo_compile_to_casm/src/lib.rs:60-74`).

### Recommendation
- Convert `bytecode_hash_node` (and the analogous `NestedFeltCounts::new_inner` / `create_bytecode_segment_structure_inner` recursions in `crates/blockifier/src/execution/contract_class.rs` and `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`) to an explicit iterative (stack-based) algorithm, or add an enforced maximum nesting depth check before recursing, returning a compilation/validation error instead of recursing unboundedly.
- Alternatively, run the compiled-class-hash computation on a thread with an explicitly bounded/pre-allocated stack, similar to the pattern already used for Cairo-Native execution in `crates/blockifier/src/blockifier/transaction_executor.rs`, and treat stack exhaustion as a rejectable/reportable error rather than a process abort.

### Proof of Concept
1. Author a Sierra program (staying within `max_contract_bytecode_size`/`max_contract_class_object_size`) with a deeply nested function/branch structure (e.g., thousands of nested inline function calls or match branches) so that the Sierra→CASM compiler produces a `bytecode_segment_lengths` value that is a deeply nested `NestedIntList::Node` chain rather than a flat list.
2. Submit this class via a `DECLARE` transaction to the gateway.
3. The gateway's `SierraCompiler::compile` subprocess-compiles the Sierra to CASM successfully (subprocess resource limits are not violated), then calls `executable_class.hash(&HashVersion::V2)` in-process (`crates/apollo_compile_to_casm/src/lib.rs:69`), which recurses through `bytecode_hash_node` for every nesting level with no depth check, exhausting the gateway process's stack and crashing it.

/// Computes the hash of a bytecode segment. See the documentation of `bytecode_hash_node` in
/// the Starknet OS.
/// Returns the length of the processed segment and its hash.
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}
