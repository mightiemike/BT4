## Analysis

The ENS bug's root cause was that an *invariant enforced on the normal path* (fuse-burn requires `ens.owner(node) == NameWrapper`) was silently skippable through an *alternate path* (unwrap → external registry mutation → re-wrap) that never re-checked the invariant. Push Chain has a structurally identical pattern in the gasless bootstrap ante decorator. [1](#0-0) 

### Title
Unauthenticated impersonation of any never-yet-transacted gasless signer (including bonded Universal Validators) via `AccountInitDecorator`'s missing pubkey–address binding check — (File: `app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator.verifySignatureForNewAccount` verifies a transaction's signature using the **attacker-supplied `sig.PubKey`** against a `SignerData.Address` taken from the **message's `Signer` string field** — without ever checking that the pubkey's derived address actually equals that claimed signer address. Any account that has never transacted on-chain (`HasAccount == false`), including a freshly bonded Universal Validator's hot key (explicitly the intended pre-fund bootstrap case per `app/README.md`), can be impersonated by an attacker who signs with their own arbitrary keypair while setting `Signer` to the victim's address.

### Finding Description
In the normal Cosmos-SDK ante pipeline, `SetPubKeyDecorator` binds a pubkey to an address (`pubKey.Address() == signer`) before `SigVerificationDecorator` trusts that pubkey. `AccountInitDecorator` short-circuits this entire chain for gasless transactions targeting brand-new accounts: [2](#0-1) 

`GetSigners()` for the gasless message types (`MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`, `MsgExecutePayload`) derives the signer strictly from the bech32 `Signer` string field, independent of any cryptographic key: [3](#0-2) 

`verifySignatureForNewAccount` then builds `SignerData{Address: newAccAddr, PubKey: <attacker's pubkey>}` and calls `authsigning.VerifySignature`, which only checks that the signature bytes are cryptographically valid for that sign-doc/pubkey pair — it does **not** verify `pubKey.Address() == newAccAddr`. An attacker who knows a target address that has no on-chain account yet (e.g., a bonded UV's hot key that hasn't cast its first vote — the exact scenario this decorator was built to support) can:

1. Set `Signer = <target address>` in a gasless message.
2. Sign the tx with their own unrelated private key.
3. Submit it. `HasAccount(target)` is false, so `AccountInitDecorator` runs `verifySignatureForNewAccount`, which succeeds because the check never ties the pubkey to the address.
4. The decorator creates the account at `target` with `sequence=1` and returns `ctx, nil`, **bypassing** `SetPubKeyDecorator`, `SigVerificationDecorator`, and `IncrementSequenceDecorator`.
5. The message reaches the module handler, which only checks `IsBondedUniversalValidator(ctx, msg.Signer)` / `IsTombstonedUniversalValidator` — both satisfied because `Signer` really is the legitimate bonded UV address, even though the attacker never held its key. [4](#0-3) 

### Impact Explanation
This lets an unprivileged attacker forge a single authenticated vote/action as an arbitrary bonded-but-not-yet-active Universal Validator, injecting it into `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, or `MsgVoteFundMigration` — messages that gate ballot finalization for inbound/outbound execution, chain-meta (gas price/height) updates, and TSS key/fund-migration lifecycle. It directly breaks the "only bonded, honest UVs may vote" invariant required by the audit scope's honest-validator finalization path, and consumes/corrupts the intended one-time bootstrap slot for that validator's real hot key. Depending on quorum size and timing, this can skew ballot convergence toward attacker-favored outcomes.

### Likelihood Explanation
Exploitable by any unprivileged external account with no special access: it only requires knowing a target UV hot-key address that has not yet transacted (addresses are typically discoverable via validator/UV set queries) and the ability to submit an ordinary signed Cosmos transaction. No relayer/validator/admin privilege is needed to trigger it.

### Recommendation
In `verifySignatureForNewAccount`, before accepting the signature, verify that `pubKey.Address()` (bech32 sdk.AccAddress derived from the provided pubkey) equals `newAccAddr` (the `Signer`/`GetSigners()[0]` value), mirroring the check `SetPubKeyDecorator` performs on the normal path. Reject the transaction if they don't match.

### Proof of Concept
1. Identify a bonded Universal Validator hot-key address `V` that has never submitted a transaction (`HasAccount(V) == false`) — the documented bootstrap scenario.
2. Attacker generates an unrelated keypair `(skA, pkA)`.
3. Attacker builds `MsgVoteInbound{Signer: V, Inbound: <attacker-chosen fabricated inbound>}`, wraps it in a tx, and signs using `skA` with `account_number=0, sequence=0` (the hardcoded values `AccountInitDecorator` uses for any never-seen address).
4. Submit the tx. `AccountInitDecorator.AnteHandle` sees `IsGaslessTx==true`, `HasAccount(V)==false`, calls `verifySignatureForNewAccount`, which succeeds (no address/pubkey binding check), creates the account at `V`, and returns early — bypassing all further signature-verification decorators.
5. `x/uexecutor.msgServer.VoteInbound` executes with `msg.Signer == V`, passing `IsBondedUniversalValidator(V)==true`, recording a vote attributed to `V` that the attacker fabricated without ever possessing `V`'s private key.

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}

	ctx.Logger().Debug("account init decorator: existing account on gasless tx, passing to next handler",
		"address", sdk.AccAddress(newAccAddr).String(),
	)
	return next(ctx, tx, simulate)
}

func (aid AccountInitDecorator) verifySignatureForNewAccount(ctx sdk.Context, tx sdk.Tx, simulate bool) error {
	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	// stdSigs contains the sequence number, account number, and signatures.
	// When simulating, this would just be a 0-length slice.
	sigs, err := sigTx.GetSignaturesV2()
	if err != nil {
		return err
	}

	signers, err := sigTx.GetSigners()
	if err != nil {
		return err
	}

	// check that signer length and signature length are the same
	if len(sigs) != len(signers) {
		return errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "invalid number of signer;  expected: %d, got %d", len(signers), len(sigs))
	}

	newAccAddr := sdk.AccAddress(signers[0])
	for _, sig := range sigs {
		pubKey := sig.PubKey
		if pubKey == nil {
			return errorsmod.Wrap(sdkerrors.ErrInvalidPubKey, "pubkey is not provided in signature")
		}

		// retrieve signer data
		chainID := ctx.ChainID()
		var accSequence uint64 = 0
		var accNum uint64 = 0

		// no need to verify signatures on recheck tx
		if !simulate && !ctx.IsReCheckTx() && ctx.IsSigverifyTx() {
			anyPk, _ := codectypes.NewAnyWithValue(pubKey)

			signerData := txsigning.SignerData{
				Address:       newAccAddr.String(),
				ChainID:       chainID,
				AccountNumber: accNum,
				Sequence:      accSequence,
				PubKey: &anypb.Any{
					TypeUrl: anyPk.TypeUrl,
					Value:   anyPk.Value,
				},
			}
			adaptableTx, ok := tx.(authsigning.V2AdaptableTx)
			if !ok {
				return fmt.Errorf("expected tx to implement V2AdaptableTx, got %T", tx)
			}
			txData := adaptableTx.GetSigningTxData()
			ctx.Logger().Debug("account init decorator: verifying signature for new account",
				"address", newAccAddr.String(),
				"chain_id", chainID,
				"acc_num", accNum,
				"sequence", accSequence,
			)
			err = authsigning.VerifySignature(ctx, pubKey, signerData, sig.Data, aid.signModeHandler, txData)
			if err != nil {
				var errMsg string
				if OnlyLegacyAminoSigners(sig.Data) {
					// If all signers are using SIGN_MODE_LEGACY_AMINO, we rely on VerifySignature to check account sequence number,
					// and therefore communicate sequence number as a potential cause of error.
					errMsg = fmt.Sprintf("signature verification failed; please verify account number (%d), sequence (%d) and chain-id (%s)", accNum, accSequence, chainID)
				} else {
					errMsg = fmt.Sprintf("signature verification failed; please verify account number (%d) and chain-id (%s): (%s)", accNum, chainID, err.Error())
				}
				ctx.Logger().Debug("account init decorator: signature invalid for new account",
					"address", newAccAddr.String(),
					"chain_id", chainID,
				)
				return errorsmod.Wrap(sdkerrors.ErrUnauthorized, errMsg)

			}
		} else {
			ctx.Logger().Debug("account init decorator: skipping signature verification",
				"address", newAccAddr.String(),
				"simulate", simulate,
				"is_recheck_tx", ctx.IsReCheckTx(),
				"is_sigverify_tx", ctx.IsSigverifyTx(),
			)
		}
	}
	return nil
