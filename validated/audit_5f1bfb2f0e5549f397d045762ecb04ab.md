### Title
Unbounded, unbatched `VotesStore` iteration in `MaintenanceManager.doMaintenance()`/`countVote()` allows a DoS of epoch finalization - (File: `consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java`)

### Summary
The Sherlock finding describes `Voter::_processPendingRemovals()` processing an entire attacker-controlled array in one call with no batch limit, letting an attacker who registers many auto-voters and drains their balance blow up gas at `finalize()` and permanently stall reward distribution. The java-tron analog is `MaintenanceManager.doMaintenance()` → `countVote()`, which iterates the *entire* `VotesStore` in a single, unbatched pass every maintenance cycle, and any TRON account with `tronPower > 0` can create one entry in that store simply by calling `VoteWitnessContract`.

### Finding Description
`MaintenanceManager.doMaintenance()` is invoked automatically from `applyBlock()` whenever a block crosses the maintenance boundary [1](#0-0) . It unconditionally calls `countVote(votesStore)`, which walks a full DB iterator over `VotesStore` with **no batching, no size cap, and no early-exit** — every account that has ever voted since the last epoch is processed and deleted in the same call: [2](#0-1) .

Any unprivileged user can add an entry to `VotesStore` for essentially the cost of activating an account and freezing a minimal amount for TRON Power, then calling `VoteWitnessContract` (handled by `VoteWitnessActuator.countVoteAccount`) which writes one `VotesCapsule` per unique owner address into `VotesStore`, with no dedup/limit on the number of *distinct voting accounts*, only on votes-per-transaction (`MAX_VOTE_NUMBER`) [3](#0-2) . The same lack of a batch/pagination argument is also present in the read-path duplicate of this logic, `Wallet.countVote()` used by `getPaginatedNowWitnessList` [4](#0-3) .

Unlike freeze/unfreeze bookkeeping structures, which are explicitly bounded (e.g. `UnfreezeBalanceV2Actuator.UNFREEZE_MAX_TIMES = 32` caps the size of each account's own unfreeze list [5](#0-4) ), there is no analogous cap on the *number of distinct accounts* that can populate `VotesStore` before a maintenance cycle fires. This is the direct structural analog of the reported `Voter::_processPendingRemovals()` bug: a single, unbatched loop over an attacker-inflatable collection, executed automatically as part of a critical periodic finalization step.

### Impact Explanation
Because `doMaintenance()` runs synchronously inside block application on every full node (as opposed to being gas-metered like a TVM call), an attacker who cheaply registers a very large number of voting accounts (or reuses accounts across epochs) can inflate the cost of `countVote()` to the point where maintenance processing takes excessively long, risking missed block production deadlines and consensus/liveness degradation network-wide — a strictly worse outcome than the original report's "stuck rewards," since it affects block production timing for every node rather than a single contract's accounting.

### Likelihood Explanation
Reachable by any unprivileged account: creating an account and freezing a minimal balance for TRON Power, then submitting `VoteWitnessContract`, are ordinary, permissionless operations. No privileged role is required, and the vulnerable code path (`doMaintenance`) executes automatically and periodically (every maintenance cycle) without any actor's discretion, guaranteeing the attacker-created backlog will be processed in one unbatched step.

### Recommendation
Add a batch/limit mechanism to `MaintenanceManager.countVote()` (and the duplicate logic in `Wallet.countVote()`), e.g., process `VotesStore` entries across multiple maintenance ticks or cap/charge for the number of distinct voting accounts processed per epoch, mirroring the bounded design already used for `UnfreezeBalanceV2` lists.

### Proof of Concept
1. Attacker programmatically creates N new accounts, activating each with the minimum required balance.
2. For each account, freeze a minimal amount to obtain `tronPower > 0`, then submit a `VoteWitnessContract` transaction voting for any existing witness — this creates one entry in `VotesStore` per account via `VoteWitnessActuator.countVoteAccount` [3](#0-2) .
3. Repeat for a sufficiently large N (bounded only by attacker's willingness to pay account-activation/freeze costs, not by any protocol-side cap).
4. When the next maintenance boundary is crossed, `MaintenanceManager.applyBlock()` triggers `doMaintenance()` → `countVote()`, which must iterate and delete all N entries in one unbatched pass [2](#0-1) , inflating block-processing time for that block on every full node.

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }

  private void countVoteAccount(VoteWitnessContract voteContract) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }
