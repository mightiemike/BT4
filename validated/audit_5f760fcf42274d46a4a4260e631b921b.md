### Title
Fixed 5% slippage on same-block Uniswap-quote swaps enables sandwich extraction of user deposit and gas-refund value - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The Frankencoin `notifyLoss` report is fundamentally about an attacker exploiting *predictable, pending, discrete value-changing events* by acting around them in the mempool to extract value that the honest protocol logic assumed no one could front-run. Push Chain's uexecutor module has an analogous pattern: every PRC20-deposit-with-autoswap and every excess-gas refund is executed as a Uniswap-V3-style swap whose slippage bound is derived from a quote fetched in the *same* keeper call, with a hardcoded 5% tolerance and no time-weighted price protection.

### Finding Description
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` synchronously right before the swap executes, and the resulting `minPCOut` is always `quote * 95 / 100`: [1](#0-0) [2](#0-1) 

Both swaps (inbound deposit auto-swap and outbound gas refund swap) are triggered deterministically by ordinary, unprivileged user-visible transactions:
- The deposit auto-swap runs when an inbound ballot finalizes inside `ExecuteInboundGas`, itself driven by `MsgVoteInbound` reaching quorum [3](#0-2) .
- The gas-refund swap runs when an outbound ballot finalizes inside `handleSuccessfulOutbound`/`handleFailedOutbound` → `applyGasRefund`, driven by `MsgVoteOutbound` [4](#0-3) .

Both `MsgVoteInbound` and `MsgVoteOutbound` are ordinary Cosmos SDK transactions submitted via `authz.MsgExec` and are visible in the mempool before inclusion (there is no whitelist/private-mempool gate analogous to what the Frankencoin report recommends for `MintingHub::end`). An unprivileged attacker monitoring the mempool can see that a specific quorum-completing vote is about to land, know precisely which PRC20/gas token will be swapped and roughly how much, and sandwich the resulting swap: push the pool price against the victim swap immediately before it executes, letting the module's swap consume the full 5% slippage budget, then revert the price immediately after, capturing the difference. Because `minPCOut` is computed from a quote taken in the same logical operation rather than from an external TWAP or a caller-supplied bound reflecting real market conditions, the 5% tolerance is not a defense against MEV — it is the exact size of the extractable value on every swap.

### Impact Explanation
This directly corrupts native/PRC20 asset accounting and refund accounting: the amount of PC ultimately credited to the user's UEA (for a `FUNDS`/`FUNDS_AND_PAYLOAD` deposit) or the amount refunded to a user for excess destination-chain gas (`PcRefundExecution`) can be silently reduced by up to 5% per swap, transferred to an unprivileged attacker executing an ordinary sandwich trade — a real value drain of user/protocol-adjacent funds reachable purely from default vote-triggered execution, matching the allowed-impact categories "corruption of ... gas fee accounting, refund accounting" and "draining ... of user or protocol-controlled funds."

### Likelihood Explanation
Every `FUNDS`/`FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` inbound deposit that goes through auto-swap, and every outbound whose observed `gas_fee_used` is less than the pre-paid `gas_fee`, triggers this swap path. Since UV votes are broadcast as normal transactions and quorum-completing votes are predictable (the attacker just needs to see 2/3 of votes already recorded), the sandwich window is realistically capturable by any address running a bot, with no special privileges, matching the unprivileged-attacker constraint of the scope.

### Recommendation
Do not derive slippage protection from a same-transaction quote. Use a time-weighted average price (TWAP) from the underlying AMM (or an external oracle) to bound `minPCOut`, tighten the tolerance to reflect genuine short-term volatility rather than a flat 5%, and/or route these module-initiated swaps through a mechanism (e.g., batching, private submission, or a commit-reveal on outbound vote inclusion) that removes the predictable mempool signal an attacker uses to time the sandwich.

### Proof of Concept
1. Attacker watches the mempool/tx stream for `MsgVoteInbound` (or `MsgVoteOutbound`) messages voting on a specific `utx_id`/`outbound_id`, and tracks vote counts to know when the 2/3+ quorum-completing vote is about to be submitted.
2. Just before that vote lands, attacker submits a large swap on the same Uniswap V3 pool (`gasToken`/PRC20 → WPC or vice versa) to move the price unfavorably for the upcoming module swap.
3. The quorum-completing vote executes `ExecuteInboundGas`/`applyGasRefund`, which calls `GetSwapQuote` against the now-skewed pool and computes `minPCOut = quote * 95/100` — comfortably inside the attacker's manipulated range — then executes `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` with `withSwap=true`, filling at the worse price.
4. Attacker immediately reverses their initial swap, capturing the price difference (bounded by, and up to, the 5% slippage the protocol allows), funded by the victim user's deposit or gas refund.

// VoteOutbound is for uvalidators for voting on observed outbound tx on external chain
func (k Keeper) VoteOutbound(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	utxId string,
	outboundId string,
	observedTx types.OutboundObservation,
) error {
	k.Logger().Info("vote outbound received",
		"validator", universalValidator.String(),
		"utx_id", utxId,
		"outbound_id", outboundId,
		"obs_success", observedTx.Success,
	)

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Step 1: Fetch UniversalTx
	utx, found, err := k.GetUniversalTx(ctx, utxId)
	if err != nil {
		return err
	}
	if !found {
		return fmt.Errorf("UniversalTx not found: %s", utxId)
	}
	if utx.OutboundTx == nil {
		return fmt.Errorf("no outbound tx found in UniversalTx %s", utxId)
	}

	// Step 2: Find outbound by id
	var outbound types.OutboundTx
	found = false
	for _, ob := range utx.OutboundTx {
		if ob.Id == outboundId {
			outbound = *ob
			found = true
			break
		}
	}
	if !found {
		return fmt.Errorf("outbound %s not found in UniversalTx %s", outboundId, utxId)
	}
