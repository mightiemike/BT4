### Title
Ancient-slot squash can trip `debug_assert!` (and silently lose tombstones in release) when `latest_full_snapshot_slot` lags the ancient boundary - (File: accounts-db/src/ancient_append_vecs.rs)

### Summary
`combine_ancient_slots_packed` selects slots to squash purely based on slot age vs. `oldest_non_ancient_slot` (derived from the current slot and `ancient_append_vec_offset`), with no dependency on `latest_full_snapshot_slot`. Since `shrink_collect` (called from `calc_accounts_to_combine`) decides whether a zero-lamport tombstone must be carried forward based solely on `slot <= latest_full_snapshot_slot`, a slot can become "ancient" while still being newer than the latest full snapshot slot, producing a non-empty `tombstones_to_carry_forward` that reaches `finish_combine_ancient_slots_packed_internal` and violates its `debug_assert!`.

### Finding Description
`combine_ancient_slots_packed` → `combine_ancient_slots_packed_internal` selects candidate slots via `get_sorted_potential_ancient_slots`/`get_oldest_non_ancient_slot`, both functions of `epoch_schedule` and the current slot only [1](#0-0) . It never checks `latest_full_snapshot_slot`. Inside `combine_ancient_slots_packed_internal`, `calc_accounts_to_combine` calls `self.shrink_collect::<ShrinkCollectAliveSeparatedByRefs<'_>>(...)` for every ancient slot's storage [2](#0-1) .

`shrink_collect` computes `can_purge_zero_lamport_single_ref = self.can_purge_zero_lamport_single_ref_after_shrink(slot)` and, if false, pushes any existing tombstone offsets into `tombstones_to_carry_forward` instead of dropping them [3](#0-2) . That gate is: `self.latest_full_snapshot_slot().is_none_or(|latest| slot <= latest)` [4](#0-3) .

`finish_combine_ancient_slots_packed_internal` then asserts every `shrink_collect.tombstones_to_carry_forward` is empty, with a comment claiming "Ancient squash only runs on slots far older than the latest full snapshot" — but nothing in the reachable code enforces that relationship [5](#0-4) .

Attacker path: an unprivileged user creates an account, later zeroes it (closes it) at a slot that is both (a) old enough to fall past `oldest_non_ancient_slot` (i.e., "ancient") and (b) newer than the validator's `latest_full_snapshot_slot`. This is entirely plausible under normal validator operation because full-snapshot cadence (`--full-snapshot-interval-slots`) is independent of, and can be configured larger than, the ancient-append-vec boundary (`slots_per_epoch - ancient_append_vec_offset`), or snapshotting can simply be paused/slow. A prior shrink of that slot (or an older slot whose tombstone offset carried into this storage) must have already recorded a tombstone offset on the storage (via `batch_insert_tombstone_offsets`, as shown in `test_shrink_collect_carries_forward_existing_tombstones`) so that `shrink_collect` finds a non-empty `tombstone_offsets` for the storage being combined [6](#0-5) .

The existing invariant comment/guard is only documentation, not code — there is no assertion, filter, or slot-selection logic anywhere in `get_sorted_potential_ancient_slots`, `calc_ancient_slot_info`, or `filter_ancient_slots` that excludes slots newer than `latest_full_snapshot_slot` from ancient combination.

### Impact Explanation
In debug builds, this is a reachable `debug_assert!` panic in `finish_combine_ancient_slots_packed_internal`, causing a validator using a debug build to halt — matching the "attacker can trigger a panic ... inside AccountsDB ... and halt validators" scope. In release builds (where `debug_assert!` compiles out), the tombstone is silently dropped: `write_packed_storages`/`write_ancient_accounts` have no tombstone-carrying logic, so the zero-lamport deletion marker for that pubkey is lost from the new packed ancient storage. This can cause the deletion to not be propagated via subsequent incremental snapshots relying on that tombstone, producing snapshot-vs-replay/incremental-snapshot divergence for that account's presence, matching the "silent tombstone loss enabling incremental-snapshot deletion divergence" impact category.

### Likelihood Explanation
Feasibility depends on config/timing, not privilege: an unprivileged user only needs to create and zero an account they own. The precondition that `latest_full_snapshot_slot` trails behind the ancient boundary requires either an operator config with a large full-snapshot interval or a snapshot-generation slowdown — both plausible non-adversarial validator states, not something the attacker directly controls, but something the attacker can wait for/target opportunistically since ancient-slot combination runs continually in the background (`shrink_ancient_slots`). The repeatability is bounded by needing (1) a slot to become ancient while (2) still above `latest_full_snapshot_slot`, and (3) a prior shrink having already recorded the tombstone offset — this is a real, reachable combination based on existing unit tests demonstrating each piece in isolation, but the full combined "ancient + tombstone-not-yet-purgeable" state is not exercised by any existing test (`test_combine_ancient_slots_packed_internal`, `test_finish_combine_ancient_slots_packed_internal` do not use tombstones).

### Recommendation
Either (a) prevent slots newer than `latest_full_snapshot_slot` from being selected as ancient-squash candidates (e.g., filter in `get_sorted_potential_ancient_slots`/`calc_ancient_slot_info`), or (b) make `finish_combine_ancient_slots_packed_internal`/the ancient write path actually handle `tombstones_to_carry_forward` (rewrite tombstones into the packed storage, mirroring what shrink does), rather than relying on an unenforced comment-only invariant plus a `debug_assert!`.

/// `shrink_collect` must recognize tombstone offsets already recorded on a storage (carried
/// forward by a prior shrink) and route them into `tombstones_to_carry_forward`: rewritten while
/// the slot is newer than the latest full snapshot, and dropped once the snapshot advances past it.
#[test]
fn test_shrink_collect_carries_forward_existing_tombstones() {
    let accounts_db = AccountsDb::new_for_tests_with_config(Vec::new(), DEFAULT_ACCOUNTS_DB_CONFIG);
    let slot = 2;
    // Latest full snapshot older than `slot`: tombstones are not yet purgeable.
    accounts_db.set_latest_full_snapshot_slot(slot - 1);

    let alive_pubkey = Pubkey::new_unique();
    let tombstone_pubkey = Pubkey::new_unique();
    let alive_account = AccountSharedData::new(1, 0, &Pubkey::default());
    let zero_lamport_account = AccountSharedData::new(0, 0, &Pubkey::default());

    let (_temp_dirs, paths) = get_temp_accounts_paths(1).unwrap();
    let storage = Arc::new(AccountStorageEntry::new(
        &paths[0],
        slot,
        100,
        DEFAULT_FILE_SIZE,
        accounts_db.accounts_file_provider,
    ));
    // An ordinary alive account, present in the index.
    append_single_account_with_default_hash(
        &storage,
        &alive_pubkey,
        &alive_account,
        true,
        Some(&accounts_db.accounts_index),
    );
    // A zero-lamport account physically in the storage but NOT in the index: i.e. a tombstone
    // carried forward by a prior shrink of an even-older storage.
    append_single_account_with_default_hash(
        &storage,
        &tombstone_pubkey,
        &zero_lamport_account,
        true,
        None,
    );
    accounts_db.storage.insert(Arc::clone(&storage));
    accounts_db.add_root(slot);

    // Record the tombstone account's offset on the storage's tombstone list, as a prior shrink
    // would have.
    let mut tombstone_offset = None;
    storage
        .accounts
        .scan_accounts_without_data(|offset, account| {
            if account.pubkey == &tombstone_pubkey {
                tombstone_offset = Some(offset);
            }
        })
        .unwrap();
    storage.batch_insert_tombstone_offsets([tombstone_offset.unwrap()]);
    assert_eq!(storage.num_zero_lamport_single_ref_accounts(), 1);

    // Newer than the latest full snapshot: the tombstone must be carried forward, not dropped and
    // not mis-routed into the alive set.
    let mut unique_accounts =
        accounts_db.get_unique_accounts_from_storage_for_shrink(&storage, &ShrinkStats::default());
    let shrink_collect = accounts_db.shrink_collect::<AliveAccounts<'_>>(
        &storage,
        &mut unique_accounts,
        &ShrinkStats::default(),
    );
    assert_eq!(shrink_collect.tombstones_to_carry_forward.len(), 1);
    assert!(shrink_collect.tombstones_total_bytes > 0);
    assert_eq!(
        shrink_collect
            .alive_accounts
            .accounts
            .iter()
            .map(|account| *account.pubkey())
            .collect::<Vec<_>>(),
        vec![alive_pubkey],
    );

    // Once the full snapshot advances to `slot`, the tombstone is purgeable and must be dropped
    // rather than carried forward.
    accounts_db.set_latest_full_snapshot_slot(slot);
    let mut unique_accounts =
        accounts_db.get_unique_accounts_from_storage_for_shrink(&storage, &ShrinkStats::default());
    let shrink_collect = accounts_db.shrink_collect::<AliveAccounts<'_>>(
        &storage,
        &mut unique_accounts,
        &ShrinkStats::default(),
    );
    assert!(shrink_collect.tombstones_to_carry_forward.is_empty());
    assert_eq!(shrink_collect.tombstones_total_bytes, 0);
}
