## Finding: Confirmed — Silent Empty Gas Fields in Revert Outbound Can Permanently Stall Refunds

The code path in `x/uexecutor/keeper/build_revert_outbound.go` confirms the exploit hypothesis.

### Finding Description

`buildRevertOutbound` builds the `INBOUND_REVERT` outbound and attempts to populate gas fields via `k.GetGasFeeInfoForRevertOutbound`, but on **any** failure (token config lookup failure, missing `NativeRepresentation.ContractAddress`, or an error from the `getOutboundTxGasAndFees` EVM call), it logs a warning and returns the outbound anyway with `GasToken`/`GasFee`/`GasPrice`/`GasLimit` left as empty strings: [1](#0-0) 

This outbound is then committed to state as `Status_PENDING` via `attachOutboundsToUtx` and indexed into `PendingOutbounds` for UV/relayer pickup, exactly as demonstrated by the happy-path test asserting `PendingOutbounds` indexing on outbound creation: [2](#0-1) 

Once this pending outbound reaches the `universalClient`, `GetOutboundSigningRequest` (EVM path) explicitly rejects it: [3](#0-2) 

`gasPrice.Sign() == 0` is true for an empty string parsed via `SetString`, so this returns `"gas price is zero or missing in outbound event"` and the relayer can never build/sign a valid transaction for this outbound. There is no code path shown that marks such an outbound as `ABORTED`, retries the gas lookup, or otherwise removes/flags it — it simply remains `PENDING` in `PendingOutbounds` forever, since `buildRevertOutbound` fetches gas fields once, at creation time, and stores whatever it got (including nothing).

This same helper is reused from every revert-triggering call site (`ExecuteInboundFunds`, `ExecuteInboundFundsAndPayload`, `ExecuteInboundGas`, `ExecuteInboundGasAndPayload`, `RevertStuckInbound`), so the flaw is systemic to the revert path, not a single call site.

### Impact Explanation

Any inbound whose primary execution fails (deposit/payload/swap failure) triggers a revert outbound to refund the user. If, at that same moment, the `UniversalCore.getOutboundTxGasAndFees` EVM call also fails or the token's `NativeRepresentation.ContractAddress` is unset/misconfigured, the resulting refund outbound is created with empty gas fields and is **permanently unbroadcastable** by the `universalClient`, since `GetOutboundSigningRequest` rejects zero/missing gas price. The user's funds intended for refund become stuck indefinitely with no automated recovery — a genuine fund-freezing condition reachable purely from ordinary deposit/payload flows without any privileged actor.

### Likelihood Explanation

Requires the primary execution to fail *and* the gas-fee EVM call to fail concurrently. This is plausible under real operational conditions (e.g., a token whose `UniversalCore` gas configuration for a given destination chain namespace is incomplete, or transient EVM call issues) — it does not require malicious validators, TSS signers, or admins, only an ordinary user deposit that happens to fail under these conditions. Likelihood is moderate rather than trivially attacker-forced on demand, since the attacker cannot directly control `UniversalCore`'s internal gas configuration for arbitrary PRC20s, but can cause their own deposit to fail (e.g., malformed payload) and thereby land in this code path whenever the secondary gas-fee condition is also unmet.

### Recommendation

`buildRevertOutbound` should not silently proceed with empty gas fields. On `GetGasFeeInfoForRevertOutbound` failure it should either: (1) mark the outbound `Status_ABORTED` with `AbortReason` set instead of `PENDING`, so it is excluded from `PendingOutbounds` and the failure is surfaced/queryable; or (2) defer outbound creation and retry the gas lookup on a subsequent block via an explicit retry/backoff mechanism, only publishing to `PendingOutbounds` once gas fields are populated. Additionally, `attachOutboundsToUtx`/`create_outbound.go` should validate that `GasPrice`/`GasFee`/`GasToken`/`GasLimit` are non-empty before accepting an outbound into `PendingOutbounds`, closing the gap at the last line of defense.

### Proof of Concept

1. Register a token config in `uregistry` whose `NativeRepresentation.ContractAddress` is valid but for which `UniversalCore.getOutboundTxGasAndFees` reverts for the relevant destination chain namespace (e.g., missing `baseGasLimitByChainNamespace` entry) — or force `k.evmKeeper.CallEVM` to error in a unit test.
2. Submit/vote an inbound for that asset whose deposit fails (e.g., malformed recipient/payload), triggering `ExecuteInboundFunds` → `buildRevertOutbound`.
3. Assert that `GetGasFeeInfoForRevertOutbound` returns an error, and that the resulting `OutboundTx` in `PendingOutbounds` has empty `GasToken`/`GasFee`/`GasPrice`/`GasLimit` and `Status_PENDING`.
4. Feed the corresponding `OutboundCreatedEvent` into `universalClient/chains/evm.TxBuilder.GetOutboundSigningRequest` and observe the `"gas price is zero or missing in outbound event"` error — confirming the outbound can never be signed/broadcast, i.e., permanently stuck. [4](#0-3) [5](#0-4)

package keeper

import (
	sdk "github.com/cosmos/cosmos-sdk/types"
	"github.com/pushchain/push-chain-node/x/uexecutor/types"

// buildRevertOutbound creates an INBOUND_REVERT outbound with gas fields populated
// from the UniversalCore contract via getOutboundTxGasAndFees.
func (k Keeper) buildRevertOutbound(sdkCtx sdk.Context, inbound *types.Inbound) *types.OutboundTx {
	recipient := inbound.Sender
	if inbound.RevertInstructions != nil && inbound.RevertInstructions.FundRecipient != "" {
		recipient = inbound.RevertInstructions.FundRecipient
	}

	outbound := &types.OutboundTx{
		DestinationChain:  inbound.SourceChain,
		Recipient:         recipient,
		Amount:            inbound.Amount,
		ExternalAssetAddr: inbound.AssetAddr,
		Sender:            inbound.Sender,
		TxType:            types.TxType_INBOUND_REVERT,
		OutboundStatus:    types.Status_PENDING,
		Id:                types.GetOutboundRevertId(inbound.SourceChain, inbound.TxHash, inbound.LogIndex),
	}

	// Look up the PRC20 address for this external token
	tokenCfg, err := k.uregistryKeeper.GetTokenConfig(sdkCtx, inbound.SourceChain, inbound.AssetAddr)
	if err != nil || tokenCfg.NativeRepresentation == nil || tokenCfg.NativeRepresentation.ContractAddress == "" {
		k.Logger().Warn("failed to get PRC20 for revert outbound gas lookup, proceeding without gas fields",
			"chain", inbound.SourceChain,
			"asset", inbound.AssetAddr,
			"error", err,
		)
		return outbound
	}

	// Fetch gas fields from UniversalCore.getOutboundTxGasAndFees(prc20, 0)
	// 0 means use the contract's baseLimit for this chain
	gasToken, gasFee, gasPrice, gasLimit, err := k.GetGasFeeInfoForRevertOutbound(sdkCtx, tokenCfg.NativeRepresentation.ContractAddress)
	if err != nil {
		k.Logger().Warn("failed to fetch gas fee info for revert outbound, proceeding without gas fields",
			"chain", inbound.SourceChain,
			"prc20", tokenCfg.NativeRepresentation.ContractAddress,
			"error", err,
		)
		return outbound
	}

	outbound.GasToken = gasToken
	outbound.GasFee = gasFee
	outbound.GasPrice = gasPrice
	outbound.GasLimit = gasLimit

	return outbound
}

func (tb *TxBuilder) GetOutboundSigningRequest(
	ctx context.Context,
	data *uetypes.OutboundCreatedEvent,
	nonce uint64,
) (*common.UnsignedSigningReq, error) {
	if data == nil {
		return nil, fmt.Errorf("outbound event data is nil")
	}
	if data.TxID == "" {
		return nil, fmt.Errorf("txID is required")
	}
	if data.DestinationChain == "" {
		return nil, fmt.Errorf("destinationChain is required")
	}

	gasPrice := new(big.Int)
	if data.GasPrice != "" {
		if _, ok := gasPrice.SetString(data.GasPrice, 10); !ok {
			return nil, fmt.Errorf("invalid gas price in event data: %s", data.GasPrice)
		}
	}
	if gasPrice.Sign() == 0 {
		return nil, fmt.Errorf("gas price is zero or missing in outbound event")
	}
