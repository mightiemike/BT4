## Title
Missing price-deviation check in `GAS_AND_PAYLOAD`/gas-abstraction autoswap allows AMM spot-price manipulation to drain protocol-owned WPC liquidity - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The Usual report describes a protocol that relies on a single, manipulable exchange-rate source with no on-chain deviation/cross-check against an independent reference price, letting an attacker exploit a stale/favorable rate to extract more value than deposited. Push Chain's gas-abstraction autoswap path has the same structural flaw: it fetches a swap quote from an on-chain Uniswap-V3-style `QuoterV2` (a spot-price AMM) and immediately executes the swap using only a fixed 5% slippage band derived from that same quote, with no cross-check against `ChainMeta`/oracle price data or any TWAP.

### Finding Description
When an inbound `GAS_AND_PAYLOAD` deposit is finalized, `ExecuteInboundGas` [1](#0-0)  drives a deposit+autoswap flow. It looks up the Uniswap-style quoter/fee tier, then calls `GetSwapQuote`, which performs a `quoteExactInputSingle` static call directly against the on-chain AMM pool [2](#0-1) . Immediately afterward, the code computes `minPCOut` as a flat 5% slippage off that same just-fetched quote and executes the real swap via `CallPRC20DepositAutoSwap` [3](#0-2) .

Both the quote and the actual swap read the identical pool state, so the 5% band only protects against price movement between the two EVM calls within the same tx — it provides **no protection against the pool's spot price itself having been manipulated earlier in the same block** (e.g., via a large swap submitted by an unprivileged attacker just before the finalizing validator's vote transaction lands). There is no cross-check of the AMM quote against `ChainMeta`/gas-price oracle data [4](#0-3)  or any external reference/TWAP, mirroring the exact "no on-chain deviation check for the value used in an exchange" bug class from the source report.

### Impact Explanation
An attacker who can influence the WPC/PRC20 pool price within the same block as the autoswap execution can cause the protocol's `UNIVERSAL_CORE`/Handler contract to release more WPC (or accept less PRC20-equivalent value) than fair market value during `depositPRC20WithAutoSwap`, since the "expected" price and the enforced slippage are both derived from the manipulated pool itself. This directly drains protocol-owned liquidity/WPC reserves used for gas abstraction — an unauthorized, unprivileged loss of protocol-controlled funds, matching the "stealing/draining ... protocol-controlled funds" and "corruption of ... gas fee accounting" allowed-impact categories.

### Likelihood Explanation
Exploitability depends on the attacker's ability to get a price-moving transaction ordered immediately before the finalizing vote/execution transaction within the same block, and on the depth/liquidity of the specific PRC20/WPC pool and the size of the deposit being auto-swapped. This is a classic AMM spot-price sandwich pattern, feasible for any unprivileged party observing pending inbound votes, but its magnitude is bounded by available pool liquidity and by the fixed 5% band, making it a real but not unconditionally severe risk.

### Recommendation
Do not rely solely on the AMM's own spot quote for slippage protection. Cross-check the `QuoterV2` price against an independent reference (e.g., a TWAP over the same pool, or the `ChainMeta`-reported gas/price data) and bound acceptable deviation between them before executing `CallPRC20DepositAutoSwap`; reduce reliance on a flat percentage computed purely from the manipulable spot price, and consider capping single-block price impact for autoswap executions.

### Proof of Concept
1. Attacker monitors mempool/block production for an about-to-finalize `GAS_AND_PAYLOAD` inbound vote (3rd of 3 validators, see `TestInboundCEAGasAndPayload`-style flow) [5](#0-4) .
2. Attacker submits (and gets included earlier in the same block) a large swap against the PRC20/WPC pool used by `UNIVERSAL_CORE`, pushing the pool's spot price so that `quoteExactInputSingle` returns an inflated WPC amount for the pending deposit.
3. The finalizing vote transaction triggers `ExecuteInboundGas` → `GetSwapQuote` → `CallPRC20DepositAutoSwap`, which executes at the manipulated price with only the fixed 5% slippage guard from `x/uexecutor/keeper/execute_inbound_gas.go` lines 142-153.
4. Attacker reverses their price-moving swap afterward in the same or a subsequent transaction, realizing profit extracted from the protocol's WPC/PRC20 liquidity while the legitimate depositor/protocol absorbs the loss.

func (k Keeper) GetGasPriceByChain(ctx sdk.Context, chainNamespace string) (*big.Int, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()

		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, abi, ueModuleAccAddress, handlerAddr, false, nil, "gasPriceByChainNamespace", chainNamespace)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call gasPriceByChainNamespace")
	}

	results, err := abi.Methods["gasPriceByChainNamespace"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack gasPriceByChainNamespace result")
	}

	return results[0].(*big.Int), nil
}

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
