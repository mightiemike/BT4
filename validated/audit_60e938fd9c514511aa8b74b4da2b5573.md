## Title
On-chain quote-then-swap for gas refunds/top-ups is sandwichable by unprivileged MEV, draining value from users during `refundUnusedGas` and `PRC20DepositAutoSwap` - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
The external report's "slurp can be frontrun with fee increase" bug class is about a value-affecting parameter being fetched live and then acted upon, letting an adversary move that parameter between the read and the use to steal yield. Push Chain's uexecutor module has a direct analog: `GetSwapQuote` reads a live Uniswap V3 `QuoterV2` price for a PRC20→WPC swap, and the module then executes that exact swap with only a fixed 5% slippage bound (`minPCOut = quote * 95/100`). Because the pool price is fully attacker-controllable on-chain state (any ordinary trader can move it), and there is no oracle/TWAP protection, an unprivileged actor can sandwich the module's swap and capture value up to the slippage tolerance, at the expense of the user whose gas top-up or gas refund is being swapped.

### Finding Description
Three flows follow the identical "fetch quote, then swap at 95% of that quote" pattern:

- `x/uexecutor/keeper/execute_inbound_gas.go` (`ExecuteInboundGas`), lines around 126-148: fetches `fee` and `quote` via `k.GetDefaultFeeTierForToken` / `k.GetSwapQuote`, then calls `k.CallPRC20DepositAutoSwap(..., minPCOut)` with `minPCOut = quote*95/100`. [1](#0-0) 

- `x/uexecutor/keeper/execute_inbound_gas_and_payload.go` (`gasAndPayloadDepositAutoSwap`), lines 347-379: identical pattern for GAS_AND_PAYLOAD inbound route. [2](#0-1) 

- `x/uexecutor/keeper/outbound.go` (`applyGasRefund` → `getSwapQuoteForRefund`), lines 213-234: on a successful outbound observation, excess gas fee is refunded by swapping the gas token back to PC native using the same live-quote/95%-slippage pattern before calling `CallUniversalCoreRefundUnusedGas`. [3](#0-2) 

`GetSwapQuote` itself is a plain `quoteExactInputSingle` view call against the live AMM pool state, with no staleness check, no TWAP, and no comparison against any external reference price: [4](#0-3) 

The 5% slippage bound is a hardcoded constant applied uniformly regardless of trade size or pool depth, so it does not protect against price manipulation — it only caps loss at 5% per swap, which any attacker moving the pool price by more than 5% (trivial on a thin Push Chain-native AMM pool) can extract in full each time this code path runs.

This is unprivileged and user-reachable: any GAS or GAS_AND_PAYLOAD inbound (triggered by an ordinary user's cross-chain deposit) and any successful outbound with excess gas (triggered by ordinary bridging activity) causes the module to execute one of these quote-then-swap sequences. A trader watching the mempool/pending UV votes for these events can:
1. Push the PRC20/WPC pool price adversarially with a swap immediately before the module's swap executes,
2. Let the module's `GetSwapQuote` read the manipulated price and swap at up to 5% worse execution than fair value,
3. Reverse their initial trade afterward, capturing the difference — a classic sandwich attack, requiring no privileged role, no validator collusion, no admin key.

### Impact Explanation
Each sandwiched swap directly reduces the PC-denominated amount credited to the end user (either the gas top-up recipient on inbound, or the fund/gas-refund recipient on outbound), with the difference captured by the attacker. This is unauthorized draining of user-controlled funds via corrupted refund/deposit accounting, reachable purely through ordinary deposit/inbound and outbound-observation flows — matching the in-scope impact "stealing, draining ... of user or protocol-controlled funds" and "corruption of ... refund accounting". Because this executes on every qualifying inbound/outbound, it is a repeatable value leak rather than a one-off.

### Likelihood Explanation
High. No privileged access or validator collusion is required — only the ability to submit ordinary swap transactions against the PRC20/WPC pool, which any user can do. The trigger condition (a pending GAS/GAS_AND_PAYLOAD inbound or a successful outbound with `gasFee > gasFeeUsed`) is externally observable, and pool liquidity on a newly-supported gas token is likely to be thin, making >5% price impact from a single manipulative trade realistic and cheap.

### Recommendation
Do not rely solely on the AMM's own instantaneous quote as the reference price for slippage bounds. Options: use a manipulation-resistant reference (e.g., a TWAP over multiple blocks, or the already-tracked `GetGasPriceByChain`/oracle-fed gas price data used elsewhere in `x/uexecutor/keeper/evm.go`) to sanity-check the quote before accepting it; tighten or dynamically size the slippage bound based on trade size vs. pool depth; and/or route these mandatory swaps through a protected execution path (e.g., commit-reveal, or batching) that removes the attacker's ability to observe and react to the exact swap parameters before they execute.

### Proof of Concept
1. Attacker monitors pending inbound observations / outbound vote finalizations for a GAS or GAS_AND_PAYLOAD transfer that will trigger `ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap`, or an outbound with excess `gasFee` that will trigger `applyGasRefund`.
2. Immediately before the triggering transaction/vote is included, attacker submits a large swap against the same PRC20/WPC Uniswap V3 pool used by `GetSwapQuote`, moving the price against the module's upcoming swap direction.
3. The module calls `GetSwapQuote` (reads manipulated price) and executes `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` with `minPCOut` computed from that manipulated quote (95% of it) — the swap succeeds at up to 5% worse rate than the pre-manipulation price.
4. Attacker reverses their initial swap, netting the price-impact difference as profit, funded by the reduced PC amount credited to the legitimate user/recipient. [3](#0-2) [1](#0-0)

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
