### Title
Legacy `make_signer_set` floor-division can zero out an entire signer set, causing Nakamoto block signature verification to require zero signatures — (File: `stackslib/src/chainstate/stacks/boot/mod.rs`)

### Summary
The report's bug class is "integer-division truncation causes a legitimate share/weight to become 0, defeating the payout/threshold logic." The concrete analog in this repo is `StacksChainState::make_signer_set` (the pre-PoX-5 signer-weight apportionment used by `make_reward_set`/`pox_4_compute_and_update_signers`), which computes each signer's weight as `stacked_amt / threshold` and drops any signer whose weight floors to 0. Unlike the newer `pox_5_make_signer_set` (Hare/largest-remainder method), this legacy function has no fallback for the degenerate case where **every** signer's weight floors to 0. In that case it returns `Some(vec![])` (an empty-but-`Some` signer list) rather than `None`. This empty-but-populated signer list is then accepted downstream by `NakamotoBlockHeader::verify_signer_signatures`, which computes `total_weight = 0` and `threshold = compute_voting_weight_threshold(0) = 0`, making the check `total_weight_signed < threshold` (`0 < 0`) false — i.e., a Nakamoto block is accepted as validly signed with **zero signer signatures**.

### Finding Description
`make_signer_set` (`stackslib/src/chainstate/stacks/boot/mod.rs:1020-1073`) aggregates stacked amounts per signing key and computes:
```rust
let weight = u32::try_from(stacked_amt / threshold)...;
if weight == 0 { return None; }
``` [1](#0-0) 

This is exactly the "floor-and-drop" scheme that the newer `pox_5_make_signer_set` explicitly documents as buggy and replaces with a Hare/largest-remainder allocation: [2](#0-1) 
The accompanying regression test states the old scheme's failure mode directly: *"The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every signer's weight floored to 0 and the entire set was dropped -- stalling the chain."* [3](#0-2) 

Crucially, when `make_signer_set` is invoked with a non-empty `entries` list whose signing keys all floor to weight 0, `first_entry` exists and `expects_signing_keys` is true, so the function does **not** return `None` — it returns `Some(vec![])`, an empty-but-populated `Vec`. This is then stored as `RewardSetV0.signers = Some(vec![])` by `make_reward_set` (`stackslib/src/chainstate/stacks/boot/mod.rs:1085-1191`, calling `Self::make_signer_set(threshold, &addresses)` at line 1095).

Downstream, `NakamotoBlockHeader::verify_signer_signatures` treats `Some(vec![])` as a valid ("has signers") reward set:
```rust
let Some(signers) = reward_set.signers() else {
    return Err(...);  // only triggers when signers() is None
};
...
let total_weight = reward_set.total_signing_weight()...;  // = 0 for empty vec
...
let threshold = Self::compute_voting_weight_threshold(total_weight)?;  // = 0
if total_weight_signed < threshold { return Err(...) }  // 0 < 0 is false → passes
``` [4](#0-3) 
`total_signing_weight` on an empty signer vec correctly returns `Ok(0)` (fold over empty iterator), and `compute_voting_weight_threshold(0)` correctly returns `0` (ceiling of 0): [5](#0-4) [6](#0-5) 

The net effect: if the aggregated per-signing-key stacked amounts for a reward cycle all floor to less than the PoX threshold (a plausible outcome when many distinct signing keys hold roughly-equal, moderate stakes relative to `POX_MAXIMAL_SCALING`/`get_reward_threshold_and_participation`), the resulting Waterfall-independent (V0/PoX-4) reward set silently degrades to a "0 total weight, 0 threshold" regime, and `verify_signer_signatures` will accept **any** Nakamoto block header for that reward cycle regardless of how many (zero or more) signatures it carries. This breaks the core consensus equality that "a committed Stacks block must carry signatures from ≥70% of signer weight" — the equality collapses to a vacuous `0 ≥ 0`.

### Impact Explanation
This is a Critical-class issue per the stated criteria ("an invalid block accepted... network-wide"): every node applies the identical (buggy) rule, so the entire network would accept unsigned/undersigned Nakamoto blocks for the affected reward cycle, defeating the signer-set consensus mechanism that Nakamoto relies on for block finality. It is not merely a chain stall (the `pox_5` fix explicitly targets stalls); it is a silent security-check bypass with no attacker collusion (unprivileged: any miner can submit a block with 0 or too few signatures once the degenerate reward set is in effect for a cycle).

### Likelihood Explanation
Requires the specific PoX-4/V0 signer-set computation path (`make_signer_set` in `stackslib/src/chainstate/stacks/boot/mod.rs`) to be exercised with a reward cycle where every distinct signing key's aggregated stacked amount floors below the computed per-slot threshold. This is more likely on lower-participation networks (e.g., testnets, early mainnet PoX-4 cycles, or networks with numerous small-to-medium signers) than a hand-wavy "impossible in an ideal scenario" dismissal — the same "10,000,000,000 token supply" style objection from the original report does not generalize here, since the threshold and stacked amounts are governed by real, historically-observed stacking distributions rather than an astronomically large hypothetical. I was not able to fully verify from the index whether `make_signer_set`'s callers guard against this degenerate case elsewhere in the reward-cycle-selection pipeline (e.g., a possible "not enough participation → RewardSet::empty()" fallback checked in `get_reward_set_epoch2`, which does exist for the *aggregate* participation threshold but does not protect against the *per-signer* floor-to-zero scenario when overall participation is still healthy but stake is fragmented across many keys).

### Recommendation
Backport the Hare/largest-remainder allocation logic from `pox_5_make_signer_set` (`stackslib/src/chainstate/nakamoto/signer_set.rs:822-928`) into the legacy `make_signer_set` (`stackslib/src/chainstate/stacks/boot/mod.rs:1020-1073`), guaranteeing that total assigned weight always exactly matches `reward_slots` and that a non-empty entries list can never floor to an entirely empty (but `Some`) signer vector. As defense-in-depth, `verify_signer_signatures` should treat `Some(vec![])` identically to `None` (i.e., reject blocks against a reward set with zero total signing weight) rather than silently deriving a `threshold = 0`.

### Proof of Concept
1. Configure/observe a PoX-4 (V0) reward cycle where N distinct signing keys each aggregate to an amount `A` such that `A / threshold == 0` for all of them (e.g., threshold computed via `get_reward_threshold_and_participation` at `stackslib/src/chainstate/stacks/boot/mod.rs:1211-1243` is set higher than any individual signer's aggregated stake, while overall `participation`/`liquid_ustx` still passes `enough_participation` in `get_reward_set_epoch2`, `stackslib/src/chainstate/coordinator/mod.rs:368-455`).
2. `make_signer_set` filters every entry out (`weight == 0`), returning `Some(vec![])`; `make_reward_set` stores this as `RewardSetV0.signers = Some(vec![])`.
3. A miner constructs a Nakamoto block header for this reward cycle with `signer_signature = vec![]` (no signer signatures at all).
4. `verify_signer_signatures` computes `total_weight = 0`, `threshold = compute_voting_weight_threshold(0) = 0`, and the check `total_weight_signed (0) < threshold (0)` is `false`, so the function returns `Ok(0)` — the block is accepted as validly signed by every node in the network, without any signer having produced a signature.

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );
}

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
