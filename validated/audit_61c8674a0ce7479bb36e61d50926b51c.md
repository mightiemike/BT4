Confirmed: `LiquidityCap` is a field in `TokenConfig` (defined in `x/uregistry/types/token_config.go`), required to be non-empty by `ValidateBasic`, but it is never read or enforced anywhere in the deposit/mint execution path (`x/uexecutor/keeper/handler.go` `depositPRC20`, `x/uexecutor/keeper/evm.go` `CallPRC20Deposit`/`CallPRC20DepositAutoSwap`, or `x/uregistry/keeper`). This is a direct structural analog to the bug report's core issue: a cap field exists in configuration/schema but is not actually enforced at the value-transfer point, so PRC20 minting driven by inbound deposits is functionally uncapped per token.### Title
Per-token `LiquidityCap` in `TokenConfig` is validated but never enforced at PRC20 mint time - ([File: x/uexecutor/keeper/handler.go])

### Summary
`x/uregistry`'s `TokenConfig` schema defines a `LiquidityCap` field that is required to be a non-empty value by `ValidateBasic` [1](#0-0) , and admin-authored config JSON files populate it with concrete numeric caps (e.g. `"liquidity_cap": "1000000000000000000000000"`) [2](#0-1) . However, the field is never read anywhere in the actual PRC20 minting path. The deposit path (`depositPRC20` -> `CallPRC20Deposit` -> `DerivedEVMCall("depositPRC20Token", ...)`) mints the PRC20 amount exactly as reported in the finalized `Inbound.Amount`, with no lookup of, or comparison against, `TokenConfig.LiquidityCap` or any running total-minted counter. [3](#0-2) [4](#0-3) 

### Finding Description
The Push Chain analog of the "no cap on borrowable/mintable value" bug class is this liquidity-cap field: it exists precisely to bound how much synthetic PRC20 value can exist for a given external token, but it is dead configuration.

- `ValidateBasic` on `TokenConfig` treats `LiquidityCap` as a mandatory, non-empty string, implying it is meant to be a meaningful economic control. [5](#0-4) 
- `x/uregistry`'s own README describes it only as a stored field ("symbol, decimals, native PRC20 representation, liquidity cap, ..."), with no mention of enforcement anywhere in the module. [6](#0-5) 
- The registry only exposes read helpers (`GetTokenConfig`, `GetTokenConfigByPRC20`) that `x/uexecutor` consumes; there is no keeper method or check anywhere in `x/uregistry/keeper` that inspects, decrements, or accumulates against `LiquidityCap`. A grep across `x/uregistry/keeper/**` and `x/uexecutor/**` for `LiquidityCap` returns zero hits outside protobuf marshal/unmarshal code and tests.
- `depositPRC20` (the sole path that turns an `Inbound.Amount` into a mint call) resolves the token's PRC20 contract address from `TokenConfig.NativeRepresentation`, parses the amount, and calls `CallPRC20Deposit` directly — no cap check exists between amount parsing and the mint call. [3](#0-2) 
- Once ballot quorum is reached (honest UVs, no privileged assumption needed), the mint is unconditional and repeatable per new inbound tx hash; the integration test suite explicitly demonstrates unbounded accumulation: "multiple solana FUNDS inbounds accumulate balance" shows two inbounds simply doubling the minted PRC20 balance with no cap check anywhere in the flow. [7](#0-6) 
- `ValidateForExecution` (the pre-execution gate that runs after ballot finalization) validates amount format/sign and payload shape only — it has no per-token cumulative-supply or liquidity-cap check. [8](#0-7) 

This mirrors the external report's root cause exactly: a designed cap exists on paper/config but is not wired into the value-creation path, so the amount of synthetic asset that can be minted against a token is unbounded in practice, constrained only by how much value an ordinary user actually bridges in through the honest gateway/vault flow.

### Impact Explanation
Because `LiquidityCap` is unenforced, any legitimate/ordinary bridging of a token can grow PRC20 supply for that token without bound, independent of what governance intended as a safe ceiling for that asset (e.g., to limit exposure to a token with shallow on-Push liquidity, or to cap the systemic risk of any single external vault/token pair). This corrupts the "PRC20 accounting must respect the registered per-token liquidity cap" invariant described in the Registry/accounting scope. Combined with any downstream mechanism relying on that cap (auto-swap accounting, DEX pools seeded with those PRC20s, gas-token selection), an oversized single-token position can be leveraged to extract disproportionate value from thin on-chain liquidity (buying out pools, draining paired assets) — the same "kill the token economics" pattern the original report describes for Note, just transposed to PRC20 liquidity caps instead of a lending-market borrow cap. This does not require malicious validators, malicious relayers, or any privileged actor — only ordinary, honestly-observed inbound deposits at scale.

### Likelihood Explanation
High likelihood of the underlying condition (the cap is trivially unenforced in all code paths reviewed) but the exploitation is contingent on real economic value moving through the gateway on the source chain (an attacker needs to actually deposit funds), so it is not a "free" attack — similar to the judge's Medium-severity rationale in the original report (no external arbitrage needed, but real value/positioning is required to make it profitable). It is reachable via the default, unprivileged inbound submission path with only honest validators and nodes.

### Recommendation
Enforce `TokenConfig.LiquidityCap` in the PRC20 mint path: before calling `CallPRC20Deposit`/`CallPRC20DepositAutoSwap` in `x/uexecutor/keeper/handler.go`, look up the token's current minted/circulating PRC20 supply (or maintain a running per-token minted-total in `x/uregistry` or `x/uexecutor` state) and reject/queue-for-failure any deposit that would push the total past `LiquidityCap`, producing a `FAILED` `PCTx` + revert outbound rather than silently minting. Alternatively, if `LiquidityCap` is intentionally not yet wired up as a v1 placeholder, this should be explicitly documented as a known limitation, since `ValidateBasic` currently implies it is an active safety control.

### Proof of Concept
1. Register a `TokenConfig` for chain `eip155:11155111` / token USDC with `LiquidityCap = "1000000000000000000000000"` (1,000,000 * 1e18) as in the existing test fixtures. [9](#0-8) 
2. Submit repeated `Inbound` FUNDS observations (as an ordinary user bridging real funds through the honest gateway) for amounts that, cumulatively, exceed the configured `LiquidityCap` by any factor.
3. Have the (honest) Universal Validator set vote each inbound to quorum via `MsgVoteInbound`, exactly as the existing integration test `TestSolanaInboundFunds` / "multiple solana FUNDS inbounds accumulate balance" does. [7](#0-6) 
4. Observe that `depositPRC20` mints the full requested amount every time with no rejection, and the PRC20 `balanceOf` for the recipient keeps growing unboundedly past `LiquidityCap`, confirming the cap is decorative only.

// ValidateBasic performs sanity checks on the TokenConfig
func (p TokenConfig) ValidateBasic() error {
	if strings.TrimSpace(p.Chain) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "chain cannot be empty")
	}

	if strings.TrimSpace(p.Address) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "token contract address cannot be empty")
	}

	// Enforce a parseable address for the chain's namespace (e.g. 20-byte hex
	// for eip155, base58 for solana) so every registration lands on the
	// canonical storage key.
	if _, err := utils.CanonicalizeAddressByNamespace(p.Chain, p.Address); err != nil {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid token address for chain %s: %s", p.Chain, err)
	}

	if strings.TrimSpace(p.Name) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "token name cannot be empty")
	}

	if strings.TrimSpace(p.Symbol) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "token symbol cannot be empty")
	}

	if p.Decimals == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "decimals must be greater than zero")
	}

	// Validate token_type is within known enum range
	if _, ok := TokenType_name[int32(p.TokenType)]; !ok {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid token_type: %v", p.TokenType)
	}

	if strings.TrimSpace(p.LiquidityCap) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "liquidity_cap cannot be empty")
	}

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

func (k Keeper) CallPRC20Deposit(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // sender: module account
		handlerAddr,        // destination
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20Token",
		prc20Address,
		amount,
		to,
	)
}

// ValidateForExecution checks fields that are required for actual execution of the inbound.
// Called after ballot finalization, before ExecuteInbound. Failures here produce a failed
// PCTx and (for non-isCEA) a revert outbound, rather than dropping the vote.
func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}
