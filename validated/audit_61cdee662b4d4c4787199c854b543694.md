### Title
Divergent 70%-threshold rounding between `NakamotoBlockHeader::compute_voting_weight_threshold` and `GlobalStateMachineEvaluator::reached_agreement`/`reached_disagreement` - (File: `stackslib/src/chainstate/nakamoto/mod.rs`, `libsigner/src/v0/signer_state.rs`)

### Summary
This is the same bug class as the Astaria `ERC4626Cloned.deposit`/`mint` finding: two code paths are supposed to enforce the *same* logical predicate ("has ≥70% of signer weight been reached?") but implement it with different rounding rules, so for certain `total_weight` values the two paths disagree on the exact boundary.

### Finding Description
The canonical, chain-validating threshold used when a Nakamoto block header's signatures are checked is `NakamotoBlockHeader::compute_voting_weight_threshold`, which computes a **ceiling** of `total_weight * 7 / 10`: [1](#0-0) 

Separately, `GlobalStateMachineEvaluator::reached_agreement` / `reached_disagreement` in the signer library compute the same nominal 70%/30% split using plain integer division, which **truncates (floors)** rather than rounds up: [2](#0-1) 

For any `total_weight` where `total_weight * 7` is not evenly divisible by 10, the two formulas diverge by exactly 1: `compute_voting_weight_threshold` requires `floor(total_weight*7/10) + 1`, while `reached_agreement` accepts `floor(total_weight*7/10)`. For example, with `total_weight = 13`: `13*7 = 91`; `compute_voting_weight_threshold` returns `91/10 + 1 = 10`, while `reached_agreement(9)` returns `true` because `9 >= 91/10 = 9`. A weight of exactly 9 is judged "agreement reached" by the signer-side state-machine evaluator but would be judged "insufficient" by the on-chain header-verification threshold used in `verify_signer_signatures`: [3](#0-2) 

Because `verify_signer_signatures` is the authoritative check against which `NakamotoBlockHeader::compute_voting_weight_threshold` is applied (the same helper used both for header verification and by the miner-side coordinator to size `weight_threshold` — see the pre-commit weight logging path calling `NakamotoBlockHeader::compute_voting_weight_threshold` directly) [4](#0-3) , the block-acceptance path and the signer-set `GlobalStateMachineEvaluator` are two independently-computed "≥70%" gates over the same input, exactly mirroring the deposit/mint asymmetry: one gate is stricter (ceiling) and one is looser (floor).

### Impact Explanation
`GlobalStateMachineEvaluator::reached_agreement`/`reached_disagreement` are used to determine when the signer set has reached global consensus on protocol-version/tx-replay-set state (per the "Get the global transaction replay set" logic adjacent to these functions). If this evaluator can declare "agreement reached" at a weight one unit below what the equivalent header-verification threshold would require, a minority of signers (exactly the 1-unit gap, boundable by an attacker controlling that slice of weight) can cause the signer fleet to disagree about whether global agreement (e.g., on the active tx-replay set or protocol version) has actually been reached, versus what a node checking block-header signer weight via `compute_voting_weight_threshold` would compute. This is a rounding-boundary divergence bounded to a single weight unit, not a full block-signature forgery, so it falls into the "temporary tip/state disagreement" bucket rather than a chain split.

### Likelihood Explanation
Triggering requires only that `total_weight * 7 mod 10 != 0`, which is common for arbitrary signer weight distributions (not every reward cycle will have `total_weight` divisible by 10/gcd(10,7)=10), and requires no majority — only that some signers' combined weight sits exactly in the 1-unit gap between the floor and ceiling thresholds. No privileged action or additional key is needed; it triggers naturally from normal weight distributions.

### Recommendation
Have `GlobalStateMachineEvaluator::reached_agreement`/`reached_disagreement` delegate to the same `NakamotoBlockHeader::compute_voting_weight_threshold` (ceiling) function used by chain-validation, or otherwise unify the two independent threshold formulas so they always agree on the same weight boundary.

### Proof of Concept
Given `total_weight = 13`:
- `NakamotoBlockHeader::compute_voting_weight_threshold(13)` → `13*7=91`, `91%10=1≠0` → ceil=1 → `91/10 + 1 = 10`.
- `GlobalStateMachineEvaluator::reached_agreement(9)` on `total_weight=13` → `9 >= (13*7)/10 = 9` → `true`.

Thus a vote weight of 9 is treated as "agreement reached" by the signer-side evaluator while the equivalent on-chain threshold (`compute_voting_weight_threshold`) would require weight ≥ 10 — the two "70%" checks disagree by exactly one weight unit for this `total_weight`, reproducing the deposit/mint inconsistency pattern from the source report.

**Confidence caveat:** I was not able to fully trace, within the available tool budget, every call site that consumes `reached_agreement`/`reached_disagreement` (e.g., whether its output ever gates a block-acceptance decision directly versus only informational/replay-set state), nor confirm whether `signer_coordinator.rs`'s `weight_threshold` field is always initialized via `compute_voting_weight_threshold` in all code paths. This should be verified against the full call graph before treating the impact rating as final.

```rust
    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
```

```rust
    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
```
