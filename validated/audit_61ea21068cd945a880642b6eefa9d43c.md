### Title
Webhook HMAC excludes shop/topic headers, allowing cross-tenant session deletion via `APP_UNINSTALLED` replay - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
The webhook signature verification only authenticates the raw request body against the app's single shared `apiSecretKey`; it never binds the signature to the `X-Shopify-Shop-Domain` or `X-Shopify-Topic` headers. Any merchant/customer who can obtain one genuine `(rawBody, X-Shopify-Hmac-Sha256)` pair delivered to the app (from any topic, for any shop that uses the app) can replay that exact body+HMAC to the app's webhook endpoint while swapping in an attacker-chosen `X-Shopify-Topic: APP_UNINSTALLED` and `X-Shopify-Shop-Domain: <victim-shop>` header. Because these headers aren't covered by the HMAC, the signature still validates, and the built-in `deleteAppInstallationHandler`/`AppInstallations.delete` will wipe out the victim shop's stored offline/online sessions.

### Finding Description
This mirrors the Coded Estate `burn` bug: an action ("burn"/"uninstall") is executed based on incomplete authorization checks (ownership only / body HMAC only), deleting shared/other-party state (rental deposits / another shop's sessions) that the action's real scope should never have touched. Here, `validateHmacFromRequestFactory` (`packages/apps/shopify-api/lib/utils/hmac-validator.ts:168-201`) validates only `rawBody` against the HMAC header, and `validateFactory` (`packages/apps/shopify-api/lib/webhooks/validate.ts:46-76`) does nothing to tie the `domain`/`topic` headers to that signature. `callWebhookHandlers` (`packages/apps/shopify-api/lib/webhooks/process.ts:146-156`) then trusts `webhookCheck.topic` and `webhookCheck.domain` straight from headers when invoking handlers. The default Express integration wires `APP_UNINSTALLED` to `deleteAppInstallationHandler`, which calls `AppInstallations.delete(shop)` — this looks up and deletes **every session** for the shop named in the (unauthenticated) header, with no cross-check against the signed payload's shop.

### Impact Explanation
A single merchant/customer of a multi-tenant app who has captured any legitimate webhook delivery (even an unrelated, low-sensitivity topic like `PRODUCTS_UPDATE`) sent to their own shop can forge an `APP_UNINSTALLED` event for a *different* shop that installed the same app, deleting that victim's offline/online session and forcing it to lose its ability to serve API calls / trigger re-auth — effectively a cross-tenant denial of service analogous to the renters' stuck funds in the original report: the victim's data is destroyed through an operation that never validated it actually applied to them.

### Likelihood Explanation
Exploitation requires only one valid `(rawBody, hmac)` pair from a real webhook the app already sends to any shop (many apps forward multiple topics, and some webhook bodies may even be predictable/replayable across shops if body content is small or attacker-influenced), plus knowledge of the victim's `myshopify.com` domain, which is often public. No secret material or MITM is needed since the header fields are simply unauthenticated inputs to a privileged deletion path.

### Recommendation
Bind the shop domain and topic into the HMAC-verified data (or independently verify the `X-Shopify-Shop-Domain`/`X-Shopify-Topic` headers against the payload, e.g. by requiring topics to be embedded/checked in the JSON body where Shopify provides them) before dispatching to handlers, and have `deleteAppInstallationHandler`/`AppInstallations.delete` confirm the shop parameter it receives is consistent with the verified webhook payload before deleting sessions.

### Proof of Concept
1. App is installed on Shop A (attacker) and Shop B (victim), sharing the same `apiSecretKey`.
2. Attacker captures any webhook delivery received for Shop A, e.g. `X-Shopify-Topic: PRODUCTS_UPDATE`, body `B`, `X-Shopify-Hmac-Sha256: H` (valid because `H = HMAC(apiSecretKey, B)`).
3. Attacker POSTs to the app's webhook endpoint with the same body `B` and header `X-Shopify-Hmac-Sha256: H`, but sets `X-Shopify-Topic: APP_UNINSTALLED` and `X-Shopify-Shop-Domain: shop-b.myshopify.com`.
4. `validateHmacFromRequestFactory` only checks `HMAC(apiSecretKey, B) == H`, which passes.
5. `callWebhookHandlers` dispatches to the `APP_UNINSTALLED` handler with `domain = "shop-b.myshopify.com"` from the header.
6. `deleteAppInstallationHandler` → `AppInstallations.delete("shop-b.myshopify.com")` deletes Shop B's sessions, even though Shop B never sent an uninstall event and the attacker never had access to Shop B.

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }
