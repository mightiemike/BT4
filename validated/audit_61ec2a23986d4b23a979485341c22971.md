### Title
`ensure_match_transaction_info` omits checkpoint-hash comparisons, letting replay-verify accept a divergent authenticated state root - (File: types/src/transaction/mod.rs)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the integrity check used by replay/verification tooling (e.g. `storage/db-tool/src/replay_on_archive.rs`) to confirm a locally re-executed `TransactionOutput` matches the authenticated `TransactionInfo` pulled from a trusted backup/archive. The function validates status, gas, write-set hash, and event root hash, but explicitly and admittedly skips comparing `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` — the fields that actually commit the post-execution state/position Merkle roots into the ledger accumulator via `TransactionInfoV1`.

### Finding Description
`ensure_match_transaction_info` in [1](#0-0)  checks:
- `status` vs `txn_info.status()`
- `gas_used` vs `txn_info.gas_used()`
- `write_set_hash` (`CryptoHash::hash(self.write_set())`) vs `txn_info.state_change_hash()`
- `event_root_hash` vs `txn_info.event_root_hash()`

It then has a `TODO(trading-native)` comment that says verbatim: [2](#0-1) 
stating this comparator "ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`), so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution."

`TransactionInfo::V1` carries `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` fields [3](#0-2) , which are the Merkle roots that get folded into the transaction-info hash and, transitively, the ledger transaction accumulator root that is signed by validators in `LedgerInfo`. These fields are populated when `COMPUTE_TRADING_NATIVE_STATE_ROOTS` / `HOT_STATE_ROOT_IN_TXN_INFO` feature flags (both defined in [4](#0-3)  and neither present in `FeatureFlag::default_features()` [5](#0-4) , i.e. currently off by default) are enabled.

The only caller I could confirm in the codebase is `storage/db-tool/src/replay_on_archive.rs`, which calls `ensure_match_transaction_info` per-transaction to decide whether replayed execution matches the backup-derived `expected_txn_infos` [6](#0-5) . Because the checkpoint-hash fields are never compared, this replay-verify path will report success (no error, no failed txns) even if the locally computed `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` differ from the trusted/authenticated values stored in the backup — i.e., a state root divergence between the archived (validator-signed) ledger and locally-replayed execution goes undetected.

### Impact Explanation
This is a proof/verification-integrity gap: the function whose entire purpose is to assert "does my locally computed result match the authenticated transaction info" silently omits the state-commitment fields that are the actual proof-bound roots once `TransactionInfoV1`/trading-native/hot-state features are turned on. If those features are enabled (they are explicitly gated as in-progress/rollout features, not permanently disabled), a bug in state checkpoint or hot-state root computation, or a maliciously/accidentally corrupted state snapshot restored into an archive node, would not be caught by `replay_on_archive`'s automated integrity check. This directly matches the "hard-fork-only divergence during commit, replay, restore, or proof verification" and "authenticated API or state-view output bound to the wrong version/root" categories in the gate, since replay-verify is a primary tool for detecting exactly this class of divergence before it reaches consensus-relevant assumptions.

### Likelihood Explanation
The gap only manifests once `COMPUTE_TRADING_NATIVE_STATE_ROOTS` / `HOT_STATE_ROOT_IN_TXN_INFO` (and `TRANSACTION_INFO_V1`) are enabled — currently they are not in `default_features()`, so the immediate exploitability window is limited to future/staged mainnet activation of these features. However, the code is present today, unguarded by any lower-severity fallback check, and the comment is an explicit acknowledgment by the developers of a known, currently-unaddressed gap ("Validate the checkpoint hashes here before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`"), meaning the feature could be turned on before this validation is added.

### Recommendation
Extend `ensure_match_transaction_info` to compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present on `TransactionInfoV1`) against the locally computed equivalents, and treat mismatches as hard errors, before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS` / `HOT_STATE_ROOT_IN_TXN_INFO` on any network. Add a corresponding replay-verify test that intentionally corrupts one of the checkpoint hashes and confirms `replay_on_archive`/`ensure_match_transaction_info` reports a failure.

### Proof of Concept
Not independently reproducible without an environment where `TRANSACTION_INFO_V1` + `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/`HOT_STATE_ROOT_IN_TXN_INFO` are enabled (they are off by default per `FeatureFlag::default_features()`). Conceptually: construct two `TransactionOutput`s that produce identical `write_set`/`events`/`gas_used`/`status` but whose downstream `state_checkpoint_hash` (or `hot_state_checkpoint_hash`/`position_state_checkpoint_hash`) differ; call `ensure_match_transaction_info` with a `TransactionInfo::V1` carrying one of the hashes and observe it returns `Ok(())` despite the checkpoint hash mismatch, confirming the check is bypassed. I was not able to execute this in the current environment (no runtime access), so this is based on direct code inspection of the comparator logic and the explicit TODO acknowledging the gap rather than a live-run PoC.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
