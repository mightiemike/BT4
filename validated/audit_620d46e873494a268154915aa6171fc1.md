### Title
NullPointerException in `validateSignature()` when multisign witness account is absent from `AccountStore` - ([File: chainbase/src/main/java/org/tron/core/capsule/BlockCapsule.java])

### Summary
`BlockCapsule.validateSignature()` declares it only throws `ValidateSignatureException`, but when `getAllowMultiSign() == 1` it calls `accountStore.get(witnessAccountAddress).getWitnessPermissionAddress()` without a null check [1](#0-0) . An attacker-crafted or relayed block whose `witness_address` refers to a non-existent account causes `accountStore.get(...)` to return `null`, and the subsequent `.getWitnessPermissionAddress()` call throws an unchecked `NullPointerException` instead of the expected checked `ValidateSignatureException`.

### Finding Description
The method signature promises `throws ValidateSignatureException` as its only failure mode [2](#0-1) , and the only caught exception inside the try block is `SignatureException` [3](#0-2) . The multisign branch does:
```java
byte[] witnessPermissionAddress = accountStore.get(witnessAccountAddress).getWitnessPermissionAddress();
```
with no null-check on the result of `accountStore.get(witnessAccountAddress)` [4](#0-3) . Since `witnessAccountAddress` is taken directly from the untrusted `BlockHeader.raw.witness_address` field, an attacker who crafts or relays a `BlockMessage` with a `witness_address` pointing to an address that has no corresponding `AccountCapsule` in `AccountStore` will trigger a `null` return and an NPE, bypassing the intended clean failure path (`ValidateSignatureException`).

Reachability: blocks arrive via P2P through `BlockMsgHandler.processMessage()` → `processBlock()` → `tronNetDelegate.processBlock(block, false)` [5](#0-4) , which internally reaches block validation/consensus code that calls `validateSignature()` (12 call sites exist in `Manager.java`). Note that in this specific handler, `tronNetDelegate.processBlock` is wrapped in a broad `catch (Exception e)` [6](#0-5) , which would swallow the NPE and merely log a warning for this particular advertised-block path — limiting (but not eliminating) the DoS impact for that specific caller. However, this generic-`Exception` catch is a coincidental mitigation, not an intended contract, and other call sites of `validateSignature()` inside `Manager.java` (e.g., sync path via `SyncService.processBlock`, or internal consensus/witness scheduling validation) were not fully confirmed to have equivalent blanket exception handling; a `ValidateSignatureException`-only `catch` clause at any such site would not catch the NPE, and it would propagate as an unhandled runtime exception on that thread.

### Impact Explanation
An unhandled NPE at a block-validation call site not protected by a generic `Exception` catch could crash or corrupt the state of that processing thread on any full node with `allowMultiSign` enabled, since the exception type deviates from the declared/expected `ValidateSignatureException` contract. Even where callers do catch broadly (as in `BlockMsgHandler`), relying on generic exception swallowing to mask a root-cause bug is fragile and inconsistent across the codebase, and any future/alternate call path that assumes only `ValidateSignatureException` can be thrown is exposed to a crash.

### Likelihood Explanation
Preconditions are: (1) the chain has multisign enabled (`getAllowMultiSign() == 1`), which is an on-chain proposal-controlled parameter, not an admin/local setting; and (2) the attacker needs to craft/relay a block header with a `witness_address` value that does not correspond to any existing account — trivially achievable since block header bytes are attacker-supplied over P2P. This is fully repeatable and deterministic once multisign is enabled on a live network.

### Recommendation
Add a null check on `accountStore.get(witnessAccountAddress)` in the multisign branch of `validateSignature()` and throw `ValidateSignatureException` (e.g., "witness account not exists") instead of allowing an NPE to propagate:
```java
AccountCapsule witnessAccount = accountStore.get(witnessAccountAddress);
if (witnessAccount == null) {
  throw new ValidateSignatureException("witness account not exists");
}
byte[] witnessPermissionAddress = witnessAccount.getWitnessPermissionAddress();
```

```java
public void testValidateSignatureNpeOnMissingWitnessAccount() throws Exception {
  DynamicPropertiesStore dynamicPropertiesStore = mock(DynamicPropertiesStore.class);
  when(dynamicPropertiesStore.getAllowMultiSign()).thenReturn(1L);

  AccountStore accountStore = mock(AccountStore.class);
  when(accountStore.get(any(byte[].class))).thenReturn(null); // witness address absent

  BlockCapsule blockCapsule = new BlockCapsule(1, Sha256Hash.ZERO_HASH, System.currentTimeMillis(),
      ByteString.copyFrom(ByteArray.fromHexString("41abababababababababababababababababababab")));
  blockCapsule.sign(privateKeyBytes); // sign with any key so signatureToAddress succeeds

  // Expected: ValidateSignatureException, not NullPointerException
  assertThrows(ValidateSignatureException.class,
      () -> blockCapsule.validateSignature(dynamicPropertiesStore, accountStore));
}
```
Currently this test would fail with a `NullPointerException` rather than throwing `ValidateSignatureException`, confirming the defect.
