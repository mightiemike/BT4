### Title
Unbounded native recursion in compiled-class-hash computation causes stack-exhaustion crash on declare - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
`bytecode_hash_node` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs` recurses once per level of the CASM bytecode-segment tree (`NestedIntList`/`HashableNestedIntList`) with no depth bound, mirroring the Xen `xenstored` bug class (CVE-2022-42321) where unbounded recursion driven by attacker-controlled input exhausts the stack. The segment tree's nesting depth is derived from the structure of the Sierra→CASM-compiled contract that any account can submit via a `DECLARE` transaction, so a contract author fully controls how deep this tree is.

### Finding Description
`bytecode_hash_node` recursively descends into `node.iter_children()` for every non-leaf segment, with recursion depth equal to the nesting depth of the segment structure and no explicit limit: [1](#0-0) 

This is invoked by `hash_inner`, which every `HashableCompiledClass::hash` call reaches: [2](#0-1) 

The compiled-class hash is computed on the unprivileged, attacker-supplied class in multiple sequencer-reachable paths:
- During `SierraCompiler::compile`, part of the gateway/class-manager Sierra→CASM pipeline that runs on every declared class before it is ever executed: [3](#0-2) 
- During declare-transaction validation in the executable-transaction layer, which recomputes the hash directly from the submitted CASM to check it against the value supplied in the transaction: [4](#0-3) 
- During blockifier's `try_declare` execution path for `DeclareTransaction::V2`/`V3`, exercised on every declare in a block: [5](#0-4) 

The bytecode-segment nesting depth comes directly from `cairo_lang_starknet_classes::casm_contract_class::CasmContractClass`'s segmentation of the compiled bytecode, which reflects the function/branch structure of the declared Sierra program — a structure entirely controlled by the class declarer. The only externally enforced constraint at compile time is a total-size cap (`max_bytecode_size`), not a nesting-depth cap: [6](#0-5) 

Because segments can be made arbitrarily small while nested arbitrarily deep, an attacker can trade size for depth within the size budget, producing a segment tree deep enough to overflow the native call stack when `bytecode_hash_node` recurses on it.

### Impact Explanation
Reaching this code path with a sufficiently deep segment tree overflows the thread stack, which in Rust is an unrecoverable abort (SIGSEGV/`process abort`), not a catchable error like a panic. Since compiled-class-hash computation runs unconditionally on submitted classes in the class-manager/gateway compile pipeline and again during declare execution/validation in every full node and sequencer that processes the block, this can crash the class-manager component, the gateway, and/or the blockifier/full-node process handling the block — a network-wide denial of service preventing new transactions from being confirmed, matching the required "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Any account able to submit a `DECLARE` transaction (an ordinary, unprivileged sender) can craft a Sierra contract whose compiled bytecode segmentation is deeply nested (e.g., via deeply nested `match`/`if` branches), then declare it. No special privileges, timing, or race conditions are required — this is a straightforward, deterministic trigger reachable from a single transaction.

### Recommendation
Bound the recursion in `bytecode_hash_node` (and any equivalent segment-walking code) by either converting it to an explicit iterative/worklist algorithm (as already done for the analogous Patricia-tree traversal code), or by enforcing and validating a maximum nesting depth for `NestedIntList`/CASM bytecode segment structures at compile time before hashing, rejecting classes that exceed it.

### Proof of Concept
1. Author a Cairo 1 contract whose entry point contains a chain of deeply nested conditional branches (e.g., thousands of nested `if`/`match` arms), keeping total bytecode size under `max_bytecode_size` by making each branch trivially small.
2. Compile it to CASM; the resulting `CasmContractClass.bytecode_segment_lengths` (`NestedIntList`) mirrors this nesting depth.
3. Submit the class via a `DECLARE` (or via the class-manager's `add_class`/`SierraCompiler::compile` path). The subsequent `hash(&HashVersion::V2)` call recurses through `bytecode_hash_node` once per nesting level, exhausting the stack and aborting the process handling compilation/validation.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

    /// is compiled_class_hash_v2 of the compiled contract.
    pub fn check_compile_class_hash_v2_declaration(&self) -> Result<(), StarknetApiError> {
        let compiled_class = &self.class_info.contract_class;
        let compiled_class_hash_v2 = match &compiled_class {
            ContractClass::V0(_) => return Ok(()),
            ContractClass::V1((casm, _)) => casm.hash(&HashVersion::V2),
        };
        let compiled_class_hash = self.compiled_class_hash();
        if compiled_class_hash_v2 != compiled_class_hash {
            let err_var = CasmHashMismatch {
                hash: self.class_hash(),
                actual: compiled_class_hash,
                expected: compiled_class_hash_v2,
            };
            return Err(StarknetApiError::DeclareTransactionCasmHashMissMatch(Box::new(err_var)));
        }
        Ok(())
    }
