### Title
Zero-signer reward set bypasses `verify_signer_signatures`'s existence check, permitting unsigned Nakamoto blocks to pass static validation - (File: `stackslib/src/chainstate/nakamoto/mod.rs`)

### Summary
`NakamotoBlockHeader::verify_signer_signatures` only guards against a reward set whose `signers()` returns `None`, but never checks for the case where `signers()` returns `Some(&vec![])` (i.e., a non-`None`, empty signer list). When the effective signer set is empty, `total_signing_weight()` returns `0`, and `compute_voting_weight_threshold(0)` also evaluates to `0`. A block with zero signatures then satisfies `total_weight_signed (0) < threshold (0)` as `false`, so the function returns `Ok(0)` — i.e., it reports the block as validly signed even though no signer ever signed it.

### Finding Description
The check in `verify_signer_signatures` is: [1](#0-0) 
This only rejects `None`; it does not reject `Some(empty_vec)`. The threshold is derived purely from the summed weight: [2](#0-1) [3](#0-2) 
and the final comparison: [4](#0-3) 
With an empty (but `Some`) signer set, `total_weight = 0`, `threshold = 0`, and the `for signature in self.signer_signature.iter()` loop simply never executes (an empty `signer_signature` vector is perfectly legal), so `total_weight_signed = 0`. The comparison `0 < 0` is false, so the function returns `Ok(0)` — success — for a block carrying **zero signatures**.

The root cause is that `RewardSet::total_signing_weight()` and `RewardSet::signers()` do not distinguish "no signer info at all" from "a computed, valid-but-empty signer set": [5](#0-4) 
And critically, `StacksChainState::make_signer_set` can legitimately return `Some(vec![])` — not `None` — whenever there is at least one non-signing-key-less entry but every candidate's weight rounds down to zero (i.e., every stacker's `stacked_amt / threshold` floors to `0`): [6](#0-5) 
This is reachable during normal PoX-4 reward-set computation: `pox_4_compute_and_update_signers` computes `reward_set` via `make_reward_set`/`make_signer_set` and stores it as-is (there is no `signer_set.is_empty()` abort here, unlike the analogous PoX-5 path which does check and hard-errors): [7](#0-6) 
compare to the PoX-5 path, which explicitly guards against this exact condition: [8](#0-7) 
This asymmetry (PoX-5 guards, PoX-4/`verify_signer_signatures` does not) is precisely the "incomplete validation of an emptiness case" pattern described in the reference CVE (`RaggedTensorToVariant` missing the empty-splits case) — a check written for `None`/absence but not for the logically-equivalent-but-technically-present empty collection.

### Impact Explanation
If a reward cycle's computed signer set legitimately (or via extremely low/fragmented stacking participation) becomes empty while `reward_set.signers()` still returns `Some(&vec![])` rather than `None`, every honest node evaluating `verify_signer_signatures` for that tenure will independently compute `threshold = 0` and accept a Nakamoto block carrying **no signer signatures at all** as validly approved. This breaks the core Nakamoto consensus invariant that a block must be affirmatively approved by signers holding a threshold-weighted majority of stacked STX — instead any miner could push a block through static validation unilaterally. Because every node applies the same buggy arithmetic, this is not merely local misbehavior; it is a network-wide "invalid block accepted" condition, matching the Critical impact category (invalid block accepted network-wide bypassing signer approval).

### Likelihood Explanation
This does not require a majority-controlled attack — it is a latent validation-logic gap that gets triggered purely by the *shape* of the on-chain reward set data (empty-but-`Some`), which can arise from ordinary PoX-4 stacking participation dynamics (all candidate signer weights floor to zero) with no attacker action needed on the signature-checking side once that reward-set state exists. The severity is bounded by how plausible it is in practice for a reward cycle to end up with a non-`None`, zero-length signer list; I was not able to fully trace every downstream gate (e.g., whether `load_nakamoto_reward_set_for_tenure` or the coordinator rejects an empty reward set earlier in the pipeline before `verify_signer_signatures` is reached) due to remaining budget, so likelihood should be treated as **plausible but unconfirmed end-to-end** without further tracing of `stackslib/src/chainstate/nakamoto/coordinator/mod.rs`.

### Recommendation
In `verify_signer_signatures`, explicitly reject an empty signer set in addition to `None`:
```rust
let Some(signers) = reward_set.signers().filter(|s| !s.is_empty()) else {
    return Err(ChainstateError::InvalidStacksBlock("No signers in the reward set".to_string()));
};
```
Additionally, mirror the PoX-5 hard-abort (`signer_set.is_empty()` → `PoxNoRewardCycle`) in the PoX-4 path (`pox_4_compute_and_update_signers`) so an empty-but-computed signer set can never be persisted as a valid reward set in the first place.

### Proof of Concept
Conceptual reproduction (would need to be validated against the coordinator/reward-set-loading pipeline in a live test harness):
1. Configure a PoX-4 reward cycle where all stackers' `amount_stacked / threshold` floors to `0` (e.g., many stackers each individually below one reward slot's worth of STX, with none aggregating over the threshold), so `StacksChainState::make_signer_set` returns `Some(vec![])` (see test coverage of this function's threshold-flooring behavior in `stackslib/src/chainstate/stacks/boot/signers_tests.rs` lines 43-108, which exercises the floor-to-zero-weight filtering, though not the resulting empty-vec-but-Some outcome specifically).
2. This reward set is written to the `.signers` boot contract and used as the tenure's `RewardSet`.
3. A miner proposes a `NakamotoBlock` with `signer_signature: vec![]`.
4. `verify_signer_signatures` computes `total_weight = 0`, `threshold = compute_voting_weight_threshold(0) = 0`, loop over empty `signer_signature` leaves `total_weight_signed = 0`, and `0 < 0` is `false`, so the function returns `Ok(0)` — the block is treated as validly signed by the network with zero actual signer approval.

    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
