## Analysis Result



### Title
Starknet OS `replace_class` syscall omits declared-class-hash check present in Blockifier, causing state/root divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Blockifier's native `replace_class` syscall handler requires the target `class_hash` to correspond to an already-declared contract class before it updates a contract's class assignment. The Starknet OS's Cairo re-implementation of the same syscall (`execute_replace_class`) skips this check entirely — the check is explicitly marked as a `TODO` in the OS code. This means a contract-triggered `replace_class(class_hash=X)` with an undeclared/arbitrary `X` reverts under Blockifier but succeeds unconditionally in the OS's independent re-execution, causing the two engines to compute different final states for the same transaction.

### Finding Description
Blockifier's `replace_class` implementation reads the compiled class for the requested hash and fails the syscall if it's undeclared, before mutating storage: [1](#0-0) 
The same check exists in the newer syscalls path — the `SyscallExecutionError` type even defines a dedicated `ForbiddenClassReplacement` variant for related validation, and tests confirm the "is not declared" revert behavior for both cairo0 and cairo1 flows: [2](#0-1) [3](#0-2) 

In contrast, the Starknet OS's Cairo implementation of the identical syscall directly overwrites the contract's `class_hash` field in `contract_state_changes` without ever checking that the class is declared. The omission is explicitly flagged in the code itself: [4](#0-3) 
The same unchecked pattern exists in the deprecated (Cairo0) syscall execution path: [5](#0-4) 

Because the OS's contract-state commitment computation only hashes `class_hash`, `storage_root`, and `nonce` — with no independent verification that `class_hash` is a declared class in the class tree — there is no secondary safety net catching this divergence during commitment/root computation: [6](#0-5) 

### Impact Explanation
A contract that calls `replace_class` with an undeclared (or entirely bogus) class hash will have its call **reverted** when Blockifier executes/simulates the block (used by the sequencer for block building and receipts), but the **same transaction succeeds unconditionally** when the Starknet OS independently re-executes the block to produce the state-transition proof. This produces a concrete honest-node divergence: the state root (and thus block hash) computed by the OS for proving purposes differs from the state actually committed by the sequencer via Blockifier for the same block of transactions. Depending on which artifact is treated as authoritative downstream, this can result in either a permanently corrupted contract (assigned a nonexistent/undeclared class hash in the committed root) or an inability to produce a valid proof matching the sequencer's claimed state, halting the network's ability to confirm new transactions.

### Likelihood Explanation
This is trivially reachable by any account contract: simply invoke the `replace_class` syscall with a `class_hash` argument that has never been declared (e.g., a random felt). No special privileges, staking, or multi-party coordination is required — a single submitted transaction from any account is sufficient to trigger divergent behavior between the two execution engines.

### Recommendation
Add the same "class must be declared" check to the OS's `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` path) that Blockifier already performs, mirroring the exact revert semantics (including rejecting Cairo0 class hashes being assigned to Cairo1 contracts) so that the OS's re-execution is behaviorally identical to Blockifier's.

### Proof of Concept
1. Deploy any account/contract exposing a call to the `replace_class` syscall (e.g., the existing `test_replace_class` entry point in the test contract).
2. Submit an INVOKE transaction that calls `test_replace_class(class_hash=<undeclared_felt>)`.
3. Under Blockifier (sequencer execution), the inner call reverts with "... is not declared" as shown in the existing tests: [7](#0-6) 
4. Under the Starknet OS's `execute_replace_class`, no such check exists (see TODO at line 902), so the same transaction is treated as succeeding, and `contract_state_changes` is updated with the undeclared class hash, yielding a state root inconsistent with what Blockifier computed.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
