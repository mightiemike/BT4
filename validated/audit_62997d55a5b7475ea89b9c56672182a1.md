## Finding

### Title
Unauthenticated `citrea_haltCommitments` / `citrea_resumeCommitments` RPC methods allow any caller to halt sequencer commitment production - (File: crates/sequencer/src/rpc.rs)

### Summary
The sequencer exposes `citrea_haltCommitments` and `citrea_resumeCommitments` as public JSON-RPC methods that directly mutate the sequencer's commitment-production state, with no authentication or authorization check.

### Finding Description
The sequencer RPC server binds to a configurable, often externally-reachable, address/port (e.g., `0.0.0.0:8080` in `resources/configs/mainnet/rollup_config.toml` and `resources/configs/testnet/rollup_config.toml`) via `start_rpc_server` in `crates/common/src/rpc/server.rs`. All requests pass through the `Auth` middleware defined in `crates/common/src/rpc/auth.rs`, but that middleware only checks the API key for a hardcoded allowlist: [1](#0-0) 
`PROTECTED_METHODS` only contains `backup_create`, `backup_validate`, `backup_info` — every other method, including `citrea_haltCommitments` and `citrea_resumeCommitments`, bypasses the API-key check entirely: [2](#0-1) 

These two methods are declared in the public `SequencerRpc` trait and implemented without any caller check: [3](#0-2) [4](#0-3) 

Calling `halt_commitments` simply forwards a `SequencerRpcMessage::HaltCommitments` signal to the sequencer runner over an unbounded channel, unconditionally, for any caller. There is no signature check, no owner/operator check, and no restriction tying the call to the sequencer's own key — unlike the analogous `SDLVesting::stakeReleasableTokens` bug where any unprivileged caller could invoke a function meant to be restricted to a trusted bot.

### Impact Explanation
This matches the "High" impact criterion explicitly listed in scope: *"an unauthenticated JSON-RPC call that mutates node state or bypasses `Auth`"*. Any network client that can reach the sequencer's RPC port can call `citrea_haltCommitments`, halting sequencer commitment production indefinitely (until someone calls `citrea_resumeCommitments`), without needing the sequencer's private key, operator role, or an API key. Because the RPC server can be bound to `0.0.0.0` per the shipped mainnet/testnet configs, this is reachable by any unprivileged external caller, not just a local operator.

### Likelihood Explanation
High. No preconditions beyond network reachability to the RPC endpoint are required; both methods take no arguments and perform no validation whatsoever before mutating sequencer state.

### Recommendation
Add `citrea_haltCommitments` and `citrea_resumeCommitments` (and any other state-mutating operational RPC method not intended for public use) to the `PROTECTED_METHODS` list in `crates/common/src/rpc/auth.rs` so they require the configured `api_key`, or restrict them to a dedicated internal-only RPC listener that is not bound to a public interface.

### Proof of Concept
1. Deploy a sequencer node with `rpc.bind_host = "0.0.0.0"` (as in the shipped `resources/configs/mainnet/rollup_config.toml` / `resources/configs/testnet/rollup_config.toml`).
2. From any external host with no credentials, send:
```json
{"jsonrpc":"2.0","id":1,"method":"citrea_haltCommitments","params":[]}
```
3. The `Auth` middleware passes the request through untouched because the method name is not in `PROTECTED_METHODS`.
4. `SequencerRpcServerImpl::halt_commitments` sends `SequencerRpcMessage::HaltCommitments` unconditionally, halting the sequencer's L1 commitment posting.
5. Sequencer commitment production remains halted until an attacker (or anyone) chooses to call `citrea_resumeCommitments`, or the operator notices and manually restarts/investigates.

```rust
    /// Halt sequencer commitments
    async fn halt_commitments(&self) -> RpcResult<()> {
        debug!("Sequencer: citrea_haltCommitments");
        self.context
            .rpc_message_tx
            .send(SequencerRpcMessage::HaltCommitments)
            .map_err(|e| internal_rpc_error(format!("Could not send halt commitments signal: {e}")))
    }

    /// Resume sequencer commitments
    async fn resume_commitments(&self) -> RpcResult<()> {
        debug!("Sequencer: citrea_resumeCommitments");
        self.context
            .rpc_message_tx
            .send(SequencerRpcMessage::ResumeCommitments)
            .map_err(|e| {
                internal_rpc_error(format!("Could not send resume commitments signal: {e}"))
            })
    }
```
