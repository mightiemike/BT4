### Title
Unbounded duplicate-entry growth in KV session storage's shop-session index due to missing existence check in `addShopIds` - (File: packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts)

### Summary
`KVSessionStorage.storeSession()` calls `addShopIds()` on every session store, which unconditionally appends the session id to the shop's session-id-list key without checking whether it is already present, unlike the sibling `RedisSessionStorage.addKeyToShopList()` implementation, which explicitly checks `if (!idKeysArray.includes(idKey))` before pushing. [3](#0-2) [4](#0-3) [5](#0-4) 

### Finding Description
`storeSession()` is invoked for both offline and (embedded) online sessions using deterministic, reusable session ids (`offline_${shop}`, `${shop}_${userId}`) rather than a fresh random id each time. [1](#0-0)  Any code path that re-persists a session with the same id — such as OAuth being re-run, a token refresh, or repeated calls that re-store an already-existing session — triggers `addShopIds(shop, [session.id])`, which does:
```
const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
await this.namespace.put(key, JSON.stringify([...shopIds, ...ids]));
```
This appends the same id again without checking for existence, so the `shop:<shop>` KV list grows by one duplicate entry every time `storeSession` runs for that shop/session id. [4](#0-3) 

`removeShopIds`, used on `deleteSession`, filters out all matching entries at once, so a single delete does clear duplicates, but as long as `storeSession` keeps being called (which happens far more often than `deleteSession`, e.g. every OAuth re-install or online-token refresh cycle), the array keeps growing unbounded between deletes. [6](#0-5) 

This directly mirrors the reported bug class: an "add" path that lacks a pre-existence check for an id in a list, paired with a "remove" path that behaves inconsistently with how the list was populated, causing an ever-growing, stale-data-polluted collection that is iterated over in normal request handling.

### Impact Explanation
`findSessionsByShop()` reads this same duplicated id array and loads (and returns) the session once per duplicate id entry, so callers that depend on it — including `shopify-app-express`'s `AppInstallations.includes()`/`delete()`, used by the `ensureInstalledOnShop` auth middleware to decide whether to force a re-auth redirect — perform redundant KV reads and iterate a growing, duplicated array on every request through that middleware. [7](#0-6) [8](#0-7) [9](#0-8) 

Because Cloudflare KV values (and read/write operations) have practical size limits, an ever-growing per-shop id array driven purely by ordinary re-authentication/token-refresh traffic from a single merchant or their app users can eventually degrade or fail this list read/write, resulting in denial-of-service style failures in the installed-app check / auth flow for that shop (repeated forced re-auth redirects or storage errors), and in the interim causes measurable resource/gas-equivalent (KV I/O and CPU) waste on every request.

### Likelihood Explanation
Reaching this requires no privilege beyond being the shop's own merchant or an app user going through normal, repeated OAuth/online-token flows (each online-session refresh reuses the same deterministic session id), so it is triggerable purely by unprivileged, expected app usage over time — no attacker interaction with another tenant's data is needed, but the growth is deterministic and guaranteed to occur under the KV storage adapter whenever sessions are re-stored, which is a normal, frequent occurrence in production apps.

### Recommendation
In `packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`, update `addShopIds()` to check for existing entries before appending, matching the pattern already used in `RedisSessionStorage.addKeyToShopList()`:
```ts
private async addShopIds(shop: string, ids: string[]) {
  const key = this.getShopSessionIdsKey(shop);
  const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
  const merged = Array.from(new Set([...shopIds, ...ids]));
  await this.namespace.put(key, JSON.stringify(merged));
}
``` [4](#0-3) 

### Proof of Concept
1. Configure `shopify-app-express` (or any app) with `KVSessionStorage` as the session storage backend.
2. As a normal merchant, complete OAuth for `shop.myshopify.com` (offline session, id `offline_shop.myshopify.com`) — `storeSession` runs, `shop:shop.myshopify.com` KV key becomes `["offline_shop.myshopify.com"]`.
3. Trigger any flow that re-stores the same session with the same id again (e.g., re-running OAuth for the same shop, which is a legitimate, unprivileged action available to the shop owner, or an online-session refresh reusing `${shop}_${userId}`).
4. Observe that `shop:shop.myshopify.com` now contains `["offline_shop.myshopify.com","offline_shop.myshopify.com"]` — the duplicate is never de-duplicated by `addShopIds`. [3](#0-2) 
5. Call `findSessionsByShop('shop.myshopify.com')` and observe the same session object returned twice, confirming the list-growth/duplication behavior that will only be fully cleared by an explicit `deleteSession` call — repeating step 3 without ever deleting causes unbounded growth of the KV list value over the life of the shop's installation.
