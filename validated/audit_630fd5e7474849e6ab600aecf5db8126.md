### Title
Stale liquidity-index cache lets a same-block debt socialization bypass the vault's writedown - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`v0-4-market.clar` caches vault `{index, lindex}` per `{stacks-block-time, aid}` via `accrue-and-cache` so multiple operations touching the same asset in one block avoid repeated cross-contract `accrue` calls. [1](#0-0)  The cache is populated the first time an asset is touched in a block and is blindly returned on every subsequent hit for that block, with no invalidation hook tied to state-changing vault events such as `socialize-debt`, which can rewrite `lindex` directly outside of the normal per-block `accrue` path. [2](#0-1) 

### Finding Description
`accrue-and-cache` reads `index-cache` keyed by `{timestamp: stacks-block-time, aid}`; on a miss it calls the vault's `accrue`, which mutates and returns `{index, lindex}`, and stores that result for the remainder of the block. [1](#0-0)  This is used throughout collateral/debt accrual (`accrue-user-debts`, `accrue-collateral-asset`) to price positions for health checks in `collateral-add`, `collateral-remove`, and other market entry points. [3](#0-2) 

The vault also exposes `socialize-debt`, which writes `lindex` down directly (`(var-set lindex new-lindex))`) to reflect a bad-debt loss, independent of the timestamp-gated `accrue` flow. [2](#0-1)  If, within the same block, one transaction has already caused `accrue-and-cache` to populate `index-cache` for an asset (cache HIT path), and a later transaction in that same block triggers `socialize-debt` on the vault (writing down `lindex` to reflect insolvency), any subsequent market operation in that same block that reads the asset's price/collateral value via `accrue-and-cache` will hit the stale cache entry and use the pre-writedown `lindex` instead of the vault's now-lower `lindex`. [1](#0-0)  This is a same-block "cached value not invalidated when its source moves" pattern: the cache's invalidation is keyed solely to `stacks-block-time`, not to the actual mutation events on the vault (`socialize-debt`, or the treasury mint / index bump inside `accrue` when called directly by the vault's own borrow/repay functions bypassing the market's cache write).

### Impact Explanation
Positions that use the affected asset as rehypothecated (ztoken) collateral would be overvalued for the remainder of the block relative to the true, written-down `lindex`, letting users borrow against inflated collateral value or avoid liquidation health checks that should have failed. Because `socialize-debt` exists specifically to realize the vault's insolvency, a stale cached `lindex` translates directly into other users' unclaimed yield/principal being temporarily mis-valued and extractable — this lands in the temporary freezing/mis-pricing of unclaimed yield bucket at minimum, and can enable actual extraction of value in excess of what should be available once debt has been socialized, which raises it toward permanent freezing/loss of funds for the vault's remaining depositors.

### Likelihood Explanation
This requires `socialize-debt` to actually be invoked (a permissioned/DAO-triggered bad-debt write-down) within the same block as other market activity that already warmed the cache and that later reads it — a plausible but relatively rare operational sequence, since `socialize-debt` is not a routine user action. The precise call sites and authorization gating of `socialize-debt` from the market side were not fully traced in the available index (I could not confirm whether the market ever calls `socialize-debt` itself in the same transaction as a cache read, versus it being an independent, separately-authorized vault-only entry point), so the exact reachability/likelihood carries some uncertainty.

### Recommendation
Invalidate or bypass `index-cache` whenever a vault event other than the normal timestamp-driven `accrue` changes `index`/`lindex` (e.g., have `socialize-debt` also update/clear the market's cache entry for that block, or have the market re-read directly from the vault instead of trusting the cache after any privileged vault mutation). Alternatively, tie the cache key to a vault-side monotonically increasing "state version" rather than purely to `stacks-block-time`, so any out-of-band mutation forces a fresh `accrue-and-cache` read within the same block.

### Proof of Concept
1. Block N, tx 1: A market operation (e.g. `collateral-add` for a ztoken) calls `accrue-and-cache(aid)`, cache miss, stores `{index, lindex}` for `{timestamp: T, aid}`. [1](#0-0) 
2. Block N, tx 2: An authorized caller invokes the vault's `socialize-debt`, writing `lindex` down to reflect a realized loss. [2](#0-1) 
3. Block N, tx 3: Another user calls a market entry point (e.g. `collateral-remove` or a borrow) that prices the same ztoken via `accrue-and-cache(aid)`; because the cache entry for `{T, aid}` already exists, the stale pre-write-down `lindex` is returned instead of the true post-socialization value. [4](#0-3) 
4. The user's health/capacity checks are computed against the inflated collateral value, allowing them to withdraw collateral or avoid liquidation that should have been blocked under the true, written-down state.

```text
(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
```

```text
(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
```
