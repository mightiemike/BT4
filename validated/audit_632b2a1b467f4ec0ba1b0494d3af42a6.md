GlobalRateLimiter keys solely on `HttpServletRequest.getRemoteAddr()` / gRPC transport address, causing shared-fate DoS behind reverse proxies - ([File: framework/src/main/java/org/tron/core/services/ratelimiter/RuntimeData.java])

### Summary
`RuntimeData` derives the rate-limiting key exclusively from the raw TCP peer address (`getRemoteAddr()` for HTTP, `Grpc.TRANSPORT_ATTR_REMOTE_ADDR` for gRPC), with no `X-Forwarded-For`/`X-Real-IP` awareness. `GlobalRateLimiter.loadIpLimiter` and `IPQPSRateLimiterAdapter` use this single address string as the cache key for a per-IP `RateLimiter` bucket shared by every request behind that address.

### Finding Description
`RuntimeData(Object o)` sets `address = ((HttpServletRequest) o).getRemoteAddr()` for HTTP requests, and the equivalent for gRPC calls. [1](#0-0) 

`GlobalRateLimiter.tryAcquire`/`acquire` and `IPQPSRateLimiterAdapter` both call `runtimeData.getRemoteAddr()` and load/create a single shared `RateLimiter` per that address key via `loadIpLimiter`, backed by a `Cache<String, RateLimiter>`. [2](#0-1) 

Both `RateLimiterServlet.service` (HTTP path) and `RateLimiterInterceptor.interceptCall` (gRPC path) build `RuntimeData` directly from the inbound request/call and pass it into the per-endpoint (`IRateLimiter`) and global rate limiters. [3](#0-2) [4](#0-3) 

When the node is deployed behind a reverse proxy/load balancer, `getRemoteAddr()` returns the proxy's IP for every client. Because no header-based real-client extraction exists, all proxied clients collapse to the same cache key, and one attacker can exhaust the shared per-IP token bucket, causing legitimate co-located clients' requests to be rejected ("lack of computing resources" / gRPC `RESOURCE_EXHAUSTED`) regardless of their own request rate. None of the existing checks (`validateSignature`, permission weights, `DecodeUtil.addressValid`, actuator `validate()`, fork gates, energy/bandwidth accounting) are relevant here since this is a pre-actuator, transport-layer rate-limiting decision.

### Impact Explanation
This causes denial of service to legitimate clients sharing a reverse-proxy ingress IP with an attacker — matching the "DoS via RPC-API" bounty impact class. The impact is scoped to shared-proxy deployments; it does not cause consensus divergence, asset loss, or key compromise.

### Likelihood Explanation
Precondition: the full node's HTTP/gRPC API is exposed via a reverse proxy or load balancer without header-based client identification being implemented in the node — a common and realistic hosting pattern for public/API-gateway full nodes. The attacker needs no privileges: any unprivileged client that can reach the shared proxy endpoint can send bursts to exhaust the proxy-IP's `RateLimiter` bucket at essentially zero cost (no transaction fees, no signed transaction required, just HTTP/gRPC calls). The attack is trivially repeatable since the token bucket recovers per QPS setting and can be re-exhausted continuously.

### Recommendation
Support optional, explicitly-configured trusted-proxy header parsing (e.g., `X-Forwarded-For`/`X-Real-IP`) in `RuntimeData`, gated behind a config flag enabled only when the node operator confirms a trusted proxy chain, so the real client IP (or a per-session/API-key identity) is used as the rate-limit key instead of the proxy's address. Alternatively, document that IP-based limiting is only meaningful for direct-connection deployments and recommend proxy-level per-client rate limiting when fronting with a load balancer.

### Proof of Concept
```java
package org.tron.core.services.ratelimiter;

import static org.junit.Assert.assertFalse;
import static org.junit.Assert.assertTrue;
import static org.mockito.Mockito.mock;
import static org.mockito.Mockito.when;

import javax.servlet.http.HttpServletRequest;
import org.junit.Test;

public class GlobalRateLimiterSharedProxyTest {

  @Test
  public void oneAttackerExhaustsSharedProxyIpBucket() {
    // Simulate two distinct clients behind the same reverse proxy: same getRemoteAddr()
    HttpServletRequest attackerReq = mock(HttpServletRequest.class);
    when(attackerReq.getRemoteAddr()).thenReturn("10.0.0.1"); // proxy IP
    HttpServletRequest victimReq = mock(HttpServletRequest.class);
    when(victimReq.getRemoteAddr()).thenReturn("10.0.0.1"); // same proxy IP

    RuntimeData attacker = new RuntimeData(attackerReq);
    RuntimeData victim = new RuntimeData(victimReq);

    // Attacker bursts requests until the shared per-IP bucket for "10.0.0.1" is exhausted.
    boolean attackerAcquired = true;
    for (int i = 0; i < 1000 && attackerAcquired; i++) {
      attackerAcquired = GlobalRateLimiter.tryAcquire(attacker);
    }

    // Victim, a different real client behind the same proxy, is now denied
    // even though the victim made no prior requests.
    boolean victimAcquired = GlobalRateLimiter.tryAcquire(victim);
    assertFalse("Victim should be denied due to shared IP bucket exhaustion", victimAcquired);
  }
}
```
Expected result: the victim's request is denied purely because it shares the proxy's `getRemoteAddr()` value with the attacker, demonstrating the rate limiter's unit of accountability does not match the real client identity.

  public static boolean tryAcquire(RuntimeData runtimeData) {
    String ip = runtimeData.getRemoteAddr();
    if (!Strings.isNullOrEmpty(ip)) {
      RateLimiter r = loadIpLimiter(ip);
      if (r == null || !r.tryAcquire()) {
        return false;
      }
    }
    return rateLimiter.tryAcquire();
  }

  public static boolean acquire(RuntimeData runtimeData) {
    String ip = runtimeData.getRemoteAddr();
    if (!Strings.isNullOrEmpty(ip)) {
      RateLimiter r = loadIpLimiter(ip);
      if (r == null) {
        return false;
      }
      r.acquire();
    }
    rateLimiter.acquire();
    return true;
  }

  public static boolean acquirePermit(RuntimeData runtimeData) {
    return Args.getInstance().isRateLimiterApiNonBlocking()
        ? tryAcquire(runtimeData)
        : acquire(runtimeData);
  }

  private static RateLimiter loadIpLimiter(String ip) {
    try {
      // cache.get is atomic: only one loader executes per key under concurrent requests,
      // preventing multiple RateLimiter instances from being created for the same IP.
      return cache.get(ip, () -> RateLimiter.create(IP_QPS));
    } catch (Exception e) {
      logger.warn("Failed to load IP rate limiter for {}, denying request: {}",
          ip, e.getMessage());
      return null;
    }
  }
