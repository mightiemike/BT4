### Title
Starknet OS `execute_replace_class` does not validate that the new class hash is declared before applying the class-hash update, causing OS/blockifier state divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Cairo1 `replace_class` syscall handler inside the Starknet OS program updates a contract's `class_hash` in `contract_state_changes` without checking that the supplied `class_hash` corresponds to a declared class. The blockifier (the sequencer's actual execution engine) performs this check and rejects/reverts such calls, but the OS re-execution path (used to build the STARK proof of the block/state transition) does not, per an explicit TODO in the code.

### Finding Description
`execute_replace_class` in the OS program reads the requested `class_hash` from the syscall request and immediately builds a new `StateEntry` with that class hash, updating `contract_state_changes` — with only a TODO noting the missing validation: [1](#0-0) 

Note line 902: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` — no assertion enforces that the class is actually declared before the state entry is mutated.

The deprecated (Cairo0) syscall path exhibits the same gap — no declared-class check at all: [2](#0-1) 

In contrast, the actual blockifier execution engine used by the sequencer to build blocks *does* enforce this check, as demonstrated by its syscall tests: [3](#0-2) [4](#0-3) 

Any unprivileged contract can invoke `replace_class_syscall` on itself with an arbitrary, undeclared class hash (this is a permissionless syscall, reachable from ordinary INVOKE transactions). When the blockifier executes such a call during real block building, it errors out with "is not declared" and the call fails, causing the enclosing transaction to revert (the class-hash mutation is rolled back, only the base fee is charged, and the transaction is marked REVERTED in the receipts/state diff). The block's state diff therefore never contains this invalid class-hash update.

However, when the Starknet OS re-executes the same block's transactions to independently derive and prove the resulting state (a core part of Starknet's proof pipeline, distinct from and not trusting the sequencer's blockifier decisions), its own `execute_replace_class` implementation lacks the declared-class check. If the OS's interpretation of the contract bytecode reaches this syscall, it will apply the class-hash change unconditionally and continue execution as if it succeeded, rather than reproducing the revert that blockifier produced. This is a genuine logic divergence between the two independent execution engines that are supposed to compute the exact same state transition for the exact same transaction.

### Impact Explanation
This divergence between blockifier and the Starknet OS's replace_class handling can cause the OS to compute a different final contract state (and hence a different state root / block hash) than what the sequencer actually committed on-chain, for the same set of transactions. This falls squarely into "wrong committed root or block hash" / "honest-node divergence" impact categories: the OS proof would not match the actual sequencer-produced state, undermining the correctness guarantee that L1 verification is supposed to provide. It is reachable purely from an ordinary user's transaction calling a permissionless syscall on their own contract with an undeclared class hash — no privileged actor, staker, prover, or malicious operator is required.

### Likelihood Explanation
Likelihood is moderate-to-high in terms of reachability (any account/contract can trivially call `replace_class_syscall` with a bogus class hash — this requires no special privileges), but the actual proof-blocking consequence depends on how the OS's execution/proving pipeline handles the mismatch (whether some other consistency check elsewhere would catch the mismatch and cause the OS run to fail rather than silently produce a wrong but accepted proof). The explicit TODO comment in production code confirms the check is currently absent and known-missing, which is a concrete root cause rather than speculation.

### Recommendation
Add validation in `execute_replace_class` (and its Cairo0 counterpart `execute_replace_class` in `deprecated_execute_syscalls.cairo`) mirroring the blockifier's behavior: verify that the given `class_hash` corresponds to a declared class (and matches expected class version constraints, e.g. rejecting V0 hashes for V1 contracts, as blockifier does) before mutating `contract_state_changes`. If undeclared, the OS must produce the same failure/revert semantics that blockifier produces for the same call, ensuring both execution engines remain in lockstep.

### Proof of Concept
1. Deploy any Cairo1 contract exposing a `test_replace_class(class_hash)` entry point that calls `replace_class_syscall(class_hash)` (same pattern as the existing test contract used in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
2. Submit an ordinary INVOKE transaction from any unprivileged account calling this entry point with an arbitrary/undeclared `class_hash` (e.g., `felt!(1234_u16)`).
3. Sequencer's blockifier execution rejects the call ("... is not declared"), causing the transaction to revert; the block's committed state diff has no class-hash change for this contract.
4. When the Starknet OS independently re-executes this same transaction/block for proof generation, its `execute_replace_class` (lacking the declared-class check) applies the class-hash mutation unconditionally and proceeds as if the call succeeded — producing a different resulting state/state root than what the sequencer actually committed for that block.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
