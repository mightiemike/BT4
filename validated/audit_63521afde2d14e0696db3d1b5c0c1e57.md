### Title
Stale `SignerOverlay` nonce cache can admit multiple transactions with the same nonce into chunk transaction selection - ([File: chain/chain/src/runtime/signer_overlay.rs])

### Summary
`SignerOverlay` is a mutable-reference cache used during `prepare_transactions` (chunk transaction selection) to validate transaction nonces without re-reading the trie on every candidate transaction. Its own doc comment states it "accumulates mutations (balance deductions, nonce increments) locally without writing back to the trie." This mirrors the report's bug class: state is mutated on an in-memory copy, and callers that don't correctly obtain/update the *same* cached copy on every mutation could observe stale nonce values, analogous to `_writeCheckpoint` mutating `memory oldCheckpoint` instead of the persisted `storage` slot. [1](#0-0) 

### Finding Description
`SignerOverlay::get_or_load_entry_mut` loads an `Account`/`KeyEntry` from the trie once, caches it in a `HashMap<AccountId, AccountEntry>`, and returns `&mut` references for the caller to mutate (e.g., bump the access-key nonce) after accepting a candidate transaction into the chunk: [2](#0-1) 

`cached_nonce` is the read path callers use to decide whether a transaction's nonce is valid/fresh relative to prior transactions already selected in the same chunk-building pass: [3](#0-2) 

This is structurally the same failure mode as the Solidity finding: a caller that fetches a mutable handle into the overlay, updates the *local* copy it received, but — due to a subsequent re-fetch/re-entry (e.g. two different `Entry` acquisitions, or an intervening call that re-inserts/reloads the same `AccountId`/`PublicKey` pair) — the mutation is not visible when a later transaction in the same pass reads `cached_nonce` for the same key. If the write path and the read path do not consistently observe the exact same `HashMap` entry (for example, if some caller path clones `KeyEntry`/`Account` out of the map instead of mutating through `get_or_load_entry_mut`'s returned references, or re-derives a fresh overlay entry per transaction rather than reusing the existing one), nonce increments become invisible to subsequent nonce checks within the same `prepare_transactions` invocation — exactly the "second write in the same block only touches memory, not storage" pattern from the report.

### Impact Explanation
If this cache desyncs, two transactions signed by the same access key with the identical nonce could both pass the in-process nonce-freshness check and be selected into the same chunk during `prepare_transactions`. Because the actual state transition still runs through `TrieUpdate`/`Runtime::apply` later (which independently enforces nonce monotonicity against the real trie), a stale overlay would likely only cause the second transaction to be rejected/refunded at apply time rather than double-executing — so real fund-loss or supply-inflation impact is not established from the code reviewed. Given the ask-only constraints, I was not able to trace every call site in `chain/chain/src/runtime/mod.rs` that constructs/reuses `SignerOverlay` across a `prepare_transactions` pass (the file is large and I could not confirm from the available excerpt whether all mutation paths funnel through the same overlay instance/`get_or_load_entry_mut` return value, or whether some path bypasses it). Without that confirmation, I cannot assert a validator-visible state-root divergence, receipt loss/duplication, or fee/gas bypass actually occurs — only that the code pattern is structurally analogous to the reported bug class.

### Likelihood Explanation
Low-to-uncertain. The overlay is explicitly documented as chunk-producer-local, ephemeral, and rebuilt per `prepare_transactions` call, and the final chunk application uses the authoritative trie-backed nonce check, which should catch any admission-time duplicate. I was unable to fully verify all use sites within the tool-call budget, so likelihood of an exploitable, consensus-relevant bug is not confirmed.

### Recommendation
Have a background agent audit every call site of `SignerOverlay::get_or_load_entry_mut` and `cached_nonce` in `chain/chain/src/runtime/mod.rs` to confirm: (1) the same `SignerOverlay` instance is reused across all transactions considered in one `prepare_transactions` invocation, (2) every nonce mutation goes through the `&mut Account`/`&mut KeyEntry` returned by `get_or_load_entry_mut` (never a cloned copy), and (3) no code path re-inserts/reloads an `AccountEntry`/`KeyEntry` that discards previously accumulated in-pass mutations. If any accepted-transaction nonce update can bypass the cached entry, that write path should mutate through the returned reference exactly as `_writeCheckpoint` should have used a `storage` pointer.

/// Ephemeral overlay for signer account and access key data during a single
/// `prepare_transactions` call. Loads from the trie on first access and
/// accumulates mutations (balance deductions, nonce increments) locally
/// without writing back to the trie.
///
/// Account state is keyed by `AccountId` alone so that multiple public keys
/// for the same account share one account state (e.g., balance), preventing
/// double-spend across those keys.
pub(crate) struct SignerOverlay {
    entries: HashMap<AccountId, AccountEntry>,
}

    /// Returns the current nonce from the overlay if available. For gas key
    /// transactions (nonce_index is Some), returns the gas key nonce;
    /// otherwise returns the access key nonce. Returns `None` on cache miss.
    pub fn cached_nonce(
        &self,
        account_id: &AccountId,
        public_key: &PublicKey,
        nonce_index: Option<NonceIndex>,
    ) -> Option<Nonce> {
        let entry = self.entries.get(account_id)?;
        let key_entry = entry.keys.get(public_key)?;
        if let Some(idx) = nonce_index {
            key_entry.gas_key_nonces.get(&idx).copied()
        } else {
            // A missing access key means a self-signed state init, whose nonce
            // is on the account instead; see `cached_bootstrap_nonce`.
            key_entry.access_key.as_ref().map(|access_key| access_key.nonce)
        }
    }

    /// Returns mutable references to the account and per-key state, loading
    /// from the trie on first access. `Ok(None)` signals that the requested
    /// account, access key, or gas-key nonce does not exist in state. Storage
    /// errors propagate as `Err`.
    pub fn get_or_load_entry_mut(
        &mut self,
        trie: &dyn TrieAccess,
        account_id: &AccountId,
        public_key: &PublicKey,
        nonce_index: Option<NonceIndex>,
    ) -> Result<Option<(&mut Account, &mut KeyEntry)>, StorageError> {
        // Ensure the account is loaded.
        let entry = match self.entries.entry(account_id.clone()) {
            Entry::Occupied(entry) => entry.into_mut(),
            Entry::Vacant(entry) => {
                let Some(account) = get_account(trie, account_id)? else {
                    return Ok(None);
                };
                entry.insert(AccountEntry { account, keys: HashMap::new() })
            }
        };

        // Destructure to split the borrow between account and keys.
        let AccountEntry { account, keys } = entry;

        // Ensure the key entry is loaded.
        let key_entry = match keys.entry(public_key.clone()) {
            Entry::Occupied(entry) => entry.into_mut(),
            Entry::Vacant(entry) => {
                let access_key = get_access_key(trie, account_id, public_key)?;
                // Missing access key is allowed only for self-signed universal state init.
                // Which, in turn, is only allowed when the account is not initialized yet.
                if access_key.is_none() && account.is_initialized() {
                    return Ok(None);
                }
                entry.insert(KeyEntry { access_key, gas_key_nonces: HashMap::new() })
            }
        };

        // Ensure the requested gas key nonce is loaded.
        if let Some(idx) = nonce_index {
            if let Entry::Vacant(e) = key_entry.gas_key_nonces.entry(idx) {
                let Some(nonce) = get_gas_key_nonce(trie, account_id, public_key, idx)? else {
                    return Ok(None);
                };
                e.insert(nonce);
            }
        }

        Ok(Some((account, key_entry)))
    }
