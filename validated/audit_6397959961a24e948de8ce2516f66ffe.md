### Title
Starknet OS `replace_class` syscall execution omits the "class must be declared" check enforced by the Blockifier, causing state-root divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The external report's core bug class is "insecure/inconsistent upgrade logic that lacks safeguards, allowing the implementation pointer to diverge from what the trusted logic expects." The closest reachable analog on Starknet is the `replace_class` syscall, which is Starknet's native "class upgrade" mechanism — any contract can call it to change its own class hash. The sequencer's execution engine (`blockifier`) enforces that the target class hash must already be declared, but the Starknet OS's Cairo re-execution of the same syscall does not perform this validation, creating a state divergence between block production and OS re-execution/proving.

### Finding Description
When a contract calls `replace_class_syscall`, the Blockifier's implementation validates the class hash is declared and rejects the syscall with an `"is not declared"` error otherwise, as directly demonstrated by the test `undeclared_class_hash` in [1](#0-0) , and by the analogous Cairo0 path test `test_replace_class` in [2](#0-1) .

However, the Starknet OS's own Cairo implementation of `execute_replace_class`, used to re-execute/verify transactions when building the OS-side state diff and committed root, contains an explicit `TODO` marking that this exact check is not implemented, and unconditionally updates `contract_state_changes` with the new (potentially undeclared) class hash: [3](#0-2) 

The same unconditional pattern (no declared-class check) exists in the deprecated syscalls execution path used by the OS: [4](#0-3) 

Because a Cairo1 contract can wrap `replace_class_syscall` in a `try/catch` (via `SyscallResultTrait`), a malicious but otherwise unprivileged transaction sender can craft a contract that calls `replace_class_syscall` with an undeclared class hash and catches the resulting error. In the Blockifier's execution (used by the sequencer/batcher to build and commit the block), the syscall fails and is caught — the class hash is never changed, and the transaction succeeds with the class unchanged. When the Starknet OS re-executes this same transaction (during proving / state-diff derivation for the committed root), the OS applies the class-hash change unconditionally due to the missing check, mutating `contract_state_changes` for that contract's class hash.

### Impact Explanation
This produces a genuine root-cause divergence: the state diff (and therefore committed Patricia root / block hash) computed by the OS for this block will disagree with the state actually committed by the sequencer's Blockifier execution for the same transaction. This falls squarely into "wrong committed root or block hash" / "honest-node divergence" — the OS-verified state can silently diverge from the sequencer-committed state without either path throwing an error, since both paths "succeed," just with different final class hashes for the contract. This can be triggered by a single unprivileged invoke transaction from any account, with no special privileges required.

### Likelihood Explanation
The syscall (`replace_class`) is a normal, permissionless Starknet feature reachable via any invoke transaction and any deployed Cairo1 contract that wraps the syscall in error-handling. The only requirement is calling it with a not-yet-declared (or otherwise invalid) class hash while catching the resulting syscall error — an operation fully controllable and repeatable by any transaction sender with no cooperation from block proposers, operators, or other privileged actors.

### Recommendation
Add the same "class hash must be declared" (and V0/V1 compatibility) validation to the Starknet OS's `execute_replace_class` implementations (both the deprecated and current syscall execution paths) as already exists in the Blockifier, so that OS re-execution and Blockifier execution reject/accept `replace_class` identically for every input. Resolve the outstanding `TODO(Yoni, 1/1/2026)` before this divergence can be exploited in production.

### Proof of Concept
1. Deploy a Cairo1 contract with an external function that calls `replace_class_syscall(undeclared_class_hash)` inside a `match`/`unwrap_syscall` alternative that swallows the failure (e.g., using `.unwrap_syscall()` replaced with manual `Result` handling to continue execution on error).
2. Submit an invoke transaction calling that function with an undeclared `class_hash`.
3. Observe: Blockifier (sequencer) execution — the inner `replace_class` syscall fails with `"is not declared"` (per [5](#0-4) ), is caught by the contract, and the top-level transaction succeeds with no class-hash change recorded in the committed state diff.
4. Feed the same transaction through the Starknet OS/prover re-execution path (`execute_replace_class` in [6](#0-5) ) — since no declared-class check exists there, `contract_state_changes` is unconditionally updated with the new class hash, producing a different final state diff/root than what the Blockifier committed for the same block.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
