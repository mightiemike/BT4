## Title
Sandwichable spot-price swap quote used for gas-abstraction auto-swap and gas refunds enables value extraction from user deposits - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

## Summary
The `_getCollateral`-style spot-price bug in the external report has a direct analog in `GetSwapQuote`, which calls Uniswap V3 `QuoterV2.quoteExactInputSingle` against the pool's current (spot) reserves/price rather than a manipulation-resistant TWAP [1](#0-0) . This quote is used both to execute the swap **and** to derive its own minimum-output slippage guard, so an attacker who has already skewed the pool price before this keeper logic runs pays no penalty from the "protection."

## Finding Description
`ExecuteInboundGas` — the gas-abstraction path that runs when a user's inbound deposit needs to be auto-swapped into PC — fetches a quote and then computes `minPCOut` as 95% of *that same* quote before calling `CallPRC20DepositAutoSwap`: [2](#0-1) 

The identical pattern recurs in `applyGasRefund`, which swaps excess gas-token refunds back to PC via `getSwapQuoteForRefund` → `GetSwapQuote`, again computing `minPCOut` from the manipulable quote itself: [3](#0-2) 

Both rely on `GetSwapQuote`, which invokes `quoteExactInputSingle` with `sqrtPriceLimitX96 = 0` — a pure current-state simulation, not a TWAP: [1](#0-0) 

Because the "slippage protection" (`minPCOut`) is derived from the very same spot quote used to execute the swap, it only guards against price movement *after* the quote is taken — it does nothing to prevent an attacker from pre-skewing the AMM pool before the keeper-driven swap executes. This is functionally the same defect class as the reported GammaVault issue: using an on-demand spot price for a value-bearing calculation with no TWAP or manipulation-resistant fallback.

## Impact Explanation
An unprivileged external actor can manipulate the on-chain WPC/PRC20 pool price (a large swap in the block(s) preceding validator finalization of an inbound or outbound observation) so that when `ExecuteInboundGas` or `applyGasRefund` run, the resulting `quoteExactInputSingle` call returns a depressed output amount. Since `minPCOut` is computed from that same depressed quote, the swap executes and "succeeds" even though the user's deposited PRC20/gas-token is swapped for far less PC than fair value — the attacker (who reverses their pool skew afterward, e.g. via arbitrage) captures the difference. This corrupts native/PRC20 asset accounting and gas-refund accounting for ordinary user deposits and gas-abstraction flows, falling under the allowed "corruption of PRC20 or native asset accounting... refund accounting" and "unauthorized module-originated EVM execution" impact categories, since the module (`ue` account) executes value-losing EVM calls on the user's behalf based on manipulated data.

## Likelihood Explanation
Likelihood is Medium: the attack requires no privileged access — only capital to move the pool and awareness of when a given inbound/outbound is about to be finalized (predictable, since these auto-swap steps run deterministically once UVs vote in the relevant inbound/outbound event). Liquidity depth of the deployed WPC pool determines feasibility/profitability, similar to the original GammaVault report's likelihood rating.

## Recommendation
Do not derive the slippage bound (`minPCOut`) from the same instantaneous quote used to execute the swap. Use a TWAP-based reference price (or an independently-configured, validator-attested acceptable price band) to bound `minPCOut`, and/or require the value to fall within a tolerance of a longer-window observed price before allowing the auto-swap/refund-swap to proceed, deferring or aborting (with fallback to no-swap deposit, which already exists as a code path) if the spot quote deviates too far from the TWAP reference.

## Proof of Concept
1. Attacker observes an inbound deposit (`TxType_GAS`/`GAS_AND_PAYLOAD`) is pending finalization, which will trigger `ExecuteInboundGas`.
2. Shortly before the module's `CallEVM("quoteExactInputSingle", ...)` call executes (predictable block/height since it runs synchronously once validators finalize the inbound), attacker swaps a large amount into the WPC/PRC20 pool to depress the PRC20→WPC price.
3. `GetSwapQuote` returns the depressed `amountOut`; `minPCOut` is computed as `95%` of this already-bad quote [4](#0-3) .
4. `CallPRC20DepositAutoSwap` executes the swap at the depressed price, minting the user far less PC than the fair-value amount.
5. Attacker reverses their pool position (arbitrage), pocketing the value difference extracted from the user's deposit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
