### Title
Unbounded loop over attacker-controlled duplicate query parameters in HMAC validation causes pre-authentication CPU cost amplification - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
This is the same bug class as the analog report: a `for` loop that iterates over an entire input collection whose size is fully controlled by an untrusted, anonymous caller, with no cap on the number of iterations. In `shopify-app-js`, the `normalizeQuery` function inside the HMAC/signature validator loops over every entry of the raw `URLSearchParams` object built directly from the incoming request's query string, before the request's signature has been verified.

### Finding Description
`normalizeQuery` in [1](#0-0)  iterates once per query-string entry with no upper bound on the number of parameters or on repeated keys:

```
for (const [key, value] of query.entries()) {
  ...
  normalizedQuery[key] = `${existingValue},${value}`;
}
```

For the `appProxy` signator, only four reserved keys (`hmac`, `shop`, `signature`, `timestamp`) are protected against repetition [2](#0-1) ; any other query key can be repeated an arbitrary number of times, and each repetition triggers another string-accumulation step inside the loop, all executed *before* `validateHmac` performs the actual signature comparison at [3](#0-2) .

This function is reached directly from the public, unauthenticated App Proxy request-authentication handler, which builds a `URLSearchParams` straight from the incoming request URL and hands it to `validateHmac` prior to any authentication check: [4](#0-3) [5](#0-4) 

Because the loop bound is the number of query parameters supplied by the caller, and there is no maximum enforced anywhere in the library (`hmac-validator.ts`, `authenticateAppProxyFactory`), an attacker who can reach the app-proxy endpoint with a large/crafted query string controls the amount of pre-auth work the server performs — mirroring the analog's core problem of "no hard cap on iteration count for a loop bounded by attacker-supplied input."

### Impact Explanation
An attacker sending a single crafted HTTP request to the app's public app-proxy route with a very large number of duplicate query parameters forces the server to perform proportional (and, depending on the runtime's string-concatenation behavior, potentially super-linear) work inside `normalizeQuery` before any signature check fails. This consumes CPU/memory on the request-authentication path for every request, independent of whether the request is legitimately signed by Shopify, which can degrade or exhaust server resources handling that route (DoS of an auth/request-verification handler).

### Likelihood Explanation
The severity is bounded in practice by the maximum URL/query length enforced by the underlying HTTP server/runtime (e.g., Node/Express, Cloudflare Workers), which is not controlled by `shopify-app-js` itself. Where the hosting runtime allows large query strings or bodies-as-query, the amplification is directly proportional to attacker input size with zero authentication required, making this reachable by any anonymous request to the app's public app-proxy endpoint.

### Recommendation
Enforce an explicit maximum number of query parameters (and/or maximum aggregate query-string length) before entering the `normalizeQuery` loop in `hmac-validator.ts`, rejecting requests that exceed the cap with a `400 Bad Request` prior to doing any per-parameter processing. Consider capping duplicate-key accumulation length as well, so total work is bounded regardless of caller-supplied repetition.

### Proof of Concept
1. Deploy an app using `shopify-app-remix` (or `shopify-app-react-router`) with an app proxy route configured.
2. Send `GET /apps/<proxy-path>?shop=test.myshopify.com&timestamp=<now>&x=a&x=a&x=a...` (repeat `x=a` a very large number of times, limited only by the hosting server's URL/body size limits) without a valid `signature`.
3. Observe that `authenticateAppProxyFactory` → `validateAppProxyHmac` → `api.utils.validateHmac` → `normalizeQuery` processes every repeated `x` parameter and performs string concatenation for each one before ultimately rejecting the request for an invalid signature, consuming CPU proportional to the attacker-chosen parameter count on every such request.

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}

async function validateAppProxyHmac(
  params: BasicParams,
  url: URL,
): Promise<boolean> {
  const {api, logger} = params;

  try {
    let searchParams = new URLSearchParams(url.search);
    if (!searchParams.get('index')) {
      searchParams.delete('index');
    }

    let isValid = await api.utils.validateHmac(searchParams, {
      signator: 'appProxy',
    });

    if (!isValid) {
      const cleanPath = url.pathname
        .replace(/^\//, '')
        .replace(/\/$/, '')
        .replaceAll('/', '.');
      const data = `routes%2F${cleanPath}`;

      searchParams = new URLSearchParams(
        `?_data=${data}&${searchParams.toString().replace(/^\?/, '')}`,
      );

      isValid = await api.utils.validateHmac(searchParams, {
        signator: 'appProxy',
      });

      if (!isValid) {
        const searchParams = new URLSearchParams(
          `?_data=${data}._index&${url.search.replace(/^\?/, '')}`,
        );

        isValid = await api.utils.validateHmac(searchParams, {
          signator: 'appProxy',
        });
      }
    }
