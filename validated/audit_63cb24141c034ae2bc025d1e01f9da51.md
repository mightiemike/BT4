### Title
Unbounded full exchange-store iteration/sort per request in `listExchanges` gRPC endpoint enables cheap RPC-cost-amplification DoS - ([File: framework/src/main/java/org/tron/core/Wallet.java])

### Summary
`Wallet.getExchangeList()`, exposed via the `listExchanges` gRPC method, calls `ExchangeStore.getAllExchanges()` which streams and fully sorts the *entire* exchange store on every single call with no offset/limit bound. Since `ExchangeCreateContract` lets any funded account cheaply grow the exchange store, and the gRPC rate limiter only throttles by request count (QPS) rather than by response/serving cost, an attacker can inflate the store and then flood the unbounded `listExchanges` endpoint to impose disproportionate CPU cost per request.

### Finding Description
- `ExchangeStore.getAllExchanges()` performs `Streams.stream(iterator())...sorted(...)` over the full underlying RocksDB store with no pagination, so its cost is O(N log N) in the number of exchanges stored: [1](#0-0) 
- `Wallet.getExchangeList()` calls this unbounded method directly and serializes every entry into the response: [2](#0-1) 
- The gRPC service handler `listExchanges` invokes `wallet.getExchangeList()` on every call with no size cap: [3](#0-2) 
- By contrast, `getPaginatedExchangeList` bounds cost via `EXCHANGE_COUNT_LIMIT_MAX` and does per-key lookups (not a full-store scan), so it is not vulnerable to the same amplification: [4](#0-3) 
- An attacker can grow the exchange store cheaply: `ExchangeCreateActuator.validate()`/`execute()` only require the fixed `getExchangeCreateFee()` and minimal positive token balances — no cap exists on the total number of exchanges an account (or the network) can create: [5](#0-4) [6](#0-5) 
- The gRPC `RateLimiterInterceptor` throttles calls purely by count (QPS strategies: `DefaultBaseQqsAdapter`, `QpsRateLimiterAdapter`, `IPQPSRateLimiterAdapter`, `GlobalPreemptibleAdapter`), with no notion of per-request server-side cost or response size: [7](#0-6)  This confirms the metering-faithfulness gap: cheap-to-send requests to `listExchanges` are not throttled proportionally to their expensive-to-serve cost.

### Impact Explanation
This matches the "DoS via RPC-API" bounty class: concurrent calls to `listExchanges` against an inflated exchange store force the node to repeatedly perform full-store iteration, sorting, and protobuf serialization, consuming CPU/memory disproportionate to the trivial cost of sending the request. Sustained abuse can degrade RPC responsiveness for legitimate users on the targeted full node/witness node's RPC interface.

### Likelihood Explanation
- Precondition: attacker only needs an ordinary funded account and enough TRX to repeatedly pay `EXCHANGE_CREATE_FEE` (a fixed, unprivileged, on-chain fee) to grow the store — no privileged role required.
- The `listExchanges` RPC is a default read-only public gRPC method with no offset/limit parameter to cap cost, unlike its paginated sibling.
- Repeatable indefinitely as long as attacker funds `ExchangeCreateContract` transactions and concurrently issues `listExchanges` calls; the per-endpoint QPS limiter does not scale with the actual serving cost, so the attack is not mitigated by existing rate limiting.
- Severity is moderate/bounded by node CPU capacity and by the fact that RocksDB-backed iteration is nevertheless a real, measurable, unmetered CPU sink that grows with a state variable fully controlled by the attacker (exchange count).

### Recommendation
- Cap or paginate `getExchangeList()`/`listExchanges` similarly to `getPaginatedExchangeList` (e.g., always apply an `EXCHANGE_COUNT_LIMIT_MAX`-style bound, or deprecate/limit the unbounded `listExchanges` API in favor of the paginated one).
- Avoid full in-memory sort on every call; cache/pre-sort the list and invalidate incrementally, or maintain a secondary sorted index.
- Optionally, add cost-aware / response-size-aware rate limiting (not just QPS) for expensive read endpoints.

### Proof of Concept
Request-level PoC (conceptual, requires funded account + running node):
1. From an unprivileged funded account, broadcast M `ExchangeCreateContract` transactions (each just above minimum token balances, paying the fixed `EXCHANGE_CREATE_FEE`) to grow the exchange store to a large N.
2. Concurrently issue gRPC `listExchanges` (EmptyMessage) calls in a tight loop from multiple unauthenticated clients.
3. Measure server-side CPU time per `listExchanges` call as N grows (correlate exchange-store size to per-request latency/CPU).
4. Expected result if vulnerable: per-request CPU time grows roughly linearly/superlinearly with N and is not throttled beyond the fixed per-endpoint QPS limit, demonstrating unmetered cost amplification — this is directly attributable to the unbounded `Streams.stream(iterator())...sorted(...)` call in `ExchangeStore.getAllExchanges()` [8](#0-7)  invoked from `Wallet.getExchangeList()` [2](#0-1) .

  public ExchangeList getPaginatedExchangeList(long offset, long limit) {
    if (limit < 0 || offset < 0) {
      return null;
    }

    long latestExchangeNum = chainBaseManager.getDynamicPropertiesStore()
        .getLatestExchangeNum();
    if (latestExchangeNum <= offset) {
      return null;
    }
    limit =
        limit > EXCHANGE_COUNT_LIMIT_MAX ? EXCHANGE_COUNT_LIMIT_MAX : limit;
    long end = offset + limit;
    end = end > latestExchangeNum ? latestExchangeNum : end;

    ExchangeList.Builder builder = ExchangeList.newBuilder();
    ImmutableList<Long> rangeList = ContiguousSet
        .create(Range.openClosed(offset, end), DiscreteDomain.longs())
        .asList();
    rangeList.stream().map(ExchangeCapsule::calculateDbKey).map(key -> {
      try {
        return getExchangeStoreFinal(chainBaseManager.getDynamicPropertiesStore(),
            chainBaseManager.getExchangeStore(),
            chainBaseManager.getExchangeV2Store()).get(key);
      } catch (Exception ex) {
        return null;
      }
    }).filter(Objects::nonNull)
        .forEach(exchangeCapsule -> builder
            .addExchanges(exchangeCapsule.getInstance()));
    return builder.build();

  }

  public void init(Server server) {
    // add default
    for (ServerServiceDefinition service : server.getServices()) {
      for (ServerMethodDefinition<?, ?> method : service.getMethods()) {
        container.add(KEY_PREFIX_RPC, method.getMethodDescriptor().getFullMethodName(),
            new DefaultBaseQqsAdapter(QpsStrategy.DEFAULT_QPS_PARAM));
      }
    }

    Map<String, RpcRateLimiterItem> map = Args.getInstance()
        .getRateLimiterInitialization().getRpcMap();

    for (Map.Entry<String, RpcRateLimiterItem> entry : map.entrySet()) {
      RpcRateLimiterItem item = entry.getValue();

      String cName = item.getStrategy();
      String component = item.getComponent();

      if ("".equals(cName)) {
        continue;
      }

      String params = item.getParams();

      Object obj;

      // init the rpc api rate limiter.
      try {
        Class<?> cls;
        Constructor constructor;
        switch (cName) {
          case "GlobalPreemptibleAdapter":
            cls = org.tron.core.services.ratelimiter.adapter.GlobalPreemptibleAdapter.class;
            constructor = cls.getConstructor(String.class);
            obj = constructor.newInstance(params);
            container.add(KEY_PREFIX_RPC, component, (IRateLimiter) obj);
            break;
          case "QpsRateLimiterAdapter":
            cls = org.tron.core.services.ratelimiter.adapter.QpsRateLimiterAdapter.class;
            constructor = cls.getConstructor(String.class);
            obj = constructor.newInstance(params);
            container.add(KEY_PREFIX_RPC, component, (IRateLimiter) obj);
            break;

            constructor = cls.getConstructor(String.class);
            obj = constructor.newInstance(params);

            break;
          default:
            throw new Exception("undefined rate limiter adaptor");
        }

        logger.warn("the rate limiter adaptor {} is undefined.", cName);
      }
    }

  @Override
  public <ReqT, RespT> Listener<ReqT> interceptCall(ServerCall<ReqT, RespT> call, Metadata headers,
      ServerCallHandler<ReqT, RespT> next) {

    String methodMeterName = MetricsKey.NET_API_DETAIL_QPS
        + call.getMethodDescriptor().getFullMethodName();
    MetricsUtil.meterMark(MetricsKey.NET_API_QPS);
    MetricsUtil.meterMark(methodMeterName);

    IRateLimiter rateLimiter = container
        .get(KEY_PREFIX_RPC, call.getMethodDescriptor().getFullMethodName());

    Listener<ReqT> listener = new ServerCall.Listener<ReqT>() {};

    RuntimeData runtimeData = new RuntimeData(call);
    // Check per-endpoint first to avoid consuming global IP/QPS quota for requests
    // that would be rejected by the per-endpoint limiter anyway. acquirePermit()
    // chooses blocking or non-blocking semantics based on rate.limiter.apiNonBlocking.
    boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
    boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);

    if (!acquireResource) {
      // Release the per-endpoint permit when global rejected, to avoid semaphore leak.
      if (rateLimiter instanceof IPreemptibleRateLimiter && perEndpointAcquired) {
        ((IPreemptibleRateLimiter) rateLimiter).release();
      }
      call.close(Status.fromCode(Code.RESOURCE_EXHAUSTED), new Metadata());
      return listener;
    }
