**Analysis:**

`EventSchema`'s value type is `ContractEvent`, not `CoinRegisterEvent` directly [1](#0-0) . `ContractEvent` is a Rust enum with two variants, `V1` and `V2` [2](#0-1) . BCS serialization of a Rust enum always prefixes the payload with an unambiguous ULEB128 variant index, so `bcs::from_bytes::<ContractEvent>(data)` in `decode_value` deterministically reconstructs the exact same variant (`V1` or `V2`) that was serialized by `encode_value` — there is no schema collision or "ambiguous" branch to mismatch into [3](#0-2) .

Within each variant, the Move-level event type is identified by an explicit `type_tag: TypeTag` field that is stored as data alongside a raw `event_data: Vec<u8>` byte blob — it is not inferred by matching during BCS decode [4](#0-3) . `CoinRegisterEvent` itself is a plain struct serialized/deserialized independently via `bcs::from_bytes`/`bcs::to_bytes` at the higher (Move/API) layer, using its own `try_from_bytes` and its fixed `COIN_REGISTER_EVENT_TYPE` tag `0x1::account::CoinRegisterEvent` [5](#0-4) . The `TypeTag` is written explicitly by the VM at event-emission time and carried through unchanged into storage; it is never re-derived or pattern-matched against candidate struct types during `decode_value`, so there is no mechanism by which an unprivileged caller could cause BCS bytes for one struct to be silently reinterpreted as a different struct at the storage layer.

The premise that `decode_value` performs "ambiguous `TypeTag` matching" that could misdecode a stored event into a different type does not hold: `ContractEvent`'s BCS encoding is a self-describing, variant-tagged wrapper carrying its own `type_tag` and opaque `event_data` bytes, and both `encode_value`/`decode_value` are simple round-trip BCS operations with no branching on content. Any actual type interpretation of `event_data` happens outside this schema, in code that reads the `type_tag` field itself (a value under the emitting Move module's control, not attacker-forgeable across arbitrary types since it originates from VM `emit_event` calls tied to the declared struct type).
