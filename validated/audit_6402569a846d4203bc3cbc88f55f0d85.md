### Title
`IsBondedUniversalValidator` never checks `LifecycleInfo.CurrentStatus`, allowing a UV in `PENDING_LEAVE` (already removed by admin) to keep voting on inbound/outbound/chain-meta/TSS/fund-migration ballots - ([File: x/uvalidator/keeper/voting.go])

### Summary
Every vote entry point in Push Chain (`x/uexecutor.VoteInbound/VoteOutbound/VoteChainMeta`, `x/utss.VoteTssKeyProcess/VoteFundMigration`) gates admission with exactly two checks: `IsBondedUniversalValidator` and `IsTombstonedUniversalValidator`. Neither of these two functions inspects the validator's `LifecycleInfo.CurrentStatus`, so a Universal Validator that has been administratively removed (transitioned `ACTIVE -> PENDING_LEAVE` via `RemoveUniversalValidator`) but has not yet completed the `PENDING_LEAVE -> INACTIVE` transition (which only happens later, when a `QUORUM_CHANGE`/`KEYGEN` TSS process finalizes) is still treated as an authorized voter. This is the exact bug class from M-10: an entity that has been removed from the "real" voter set can still vote because the admission check only verifies "has an account/bonded-and-not-tombstoned" instead of "is currently an active member of the voter set."

### Finding Description
`IsBondedUniversalValidator` in [1](#0-0)  performs only three checks:
1. the validator is present in `UniversalValidatorSet` (`HasUniversalValidatorInSet`)
2. the underlying core validator exists in the staking module
3. the underlying core validator is `Bonded`

It never reads `val.LifecycleInfo.CurrentStatus`. Compare this to `GetEligibleVoters`, which explicitly filters the voter set to `ACTIVE`/`PENDING_JOIN` and excludes everything else (including `PENDING_LEAVE`): [2](#0-1) .

`IsTombstonedUniversalValidator` similarly only consults the slashing keeper's tombstone flag for the underlying core validator's consensus address: [3](#0-2) . It says nothing about UV lifecycle status either.

`RemoveUniversalValidator` moves an `ACTIVE` validator to `PENDING_LEAVE` — it does **not** remove the entry from `UniversalValidatorSet`, does not unbond the underlying core validator, and does not tombstone it: [4](#0-3) . The validator only becomes `INACTIVE` later, when a subsequent `QUORUM_CHANGE`/`KEYGEN` TSS process finalizes and the validator is found absent from the new key's participant set: [5](#0-4) .

Every vote message server handler uses the same two-check pattern before delegating to the ballot logic, e.g.: [6](#0-5) [7](#0-6) 

Because `PENDING_LEAVE` validators pass both `IsBondedUniversalValidator` (still in `UniversalValidatorSet`, still bonded on the staking module) and `IsTombstonedUniversalValidator` (not tombstoned), their `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, and `MsgVoteFundMigration` transactions are all accepted by the message-server layer, even though `GetEligibleVoters` — the function that is supposed to represent "currently a legitimate voter" — explicitly excludes `PENDING_LEAVE`.

Whether this admission gap translates into an actually-counted, ballot-altering vote depends on how each ballot's `voters`/threshold list is constructed at ballot-creation time (`x/uexecutor/keeper/voting.go`, not fully retrieved before the tool budget ran out). If a ballot's voter/threshold snapshot is taken independently per-message (e.g., always including whoever is in `UniversalValidatorSet` rather than filtering through `GetEligibleVoters`), the `PENDING_LEAVE` validator's vote is fully counted and can affect ballot finalization (inbound minting, outbound authorization, chain-meta gas price updates, TSS key finalization, or fund-migration success/failure records). Even in the more conservative case where `Ballot.AddVote` only accepts votes from an address present in a fixed `voters` snapshot taken at ballot creation, a validator that was `ACTIVE` (and thus included in that snapshot) at the time the ballot was created, but transitions to `PENDING_LEAVE` mid-flight, would still have their vote validly accepted per the snapshot **and** would still pass the message-server gate — meaning the removal has no real-time effect on their voting rights until the underlying core validator is separately unbonded/tombstoned or a later TSS quorum-change event catches up.

### Impact Explanation
An admin-removed (but not yet slashed/unbonded) Universal Validator retains voting power on all five gasless vote message types after removal has been "requested." Because these ballots directly drive minting of PRC20s on inbound finalization, authorization of outbound fund releases, gas-price/chain-meta updates used for fee accounting, and TSS key/fund-migration state transitions, an attacker who is removed for cause (e.g., detected misbehavior, insufficient stake, policy violation) can continue influencing ballot outcomes during the gap between `RemoveUniversalValidator` and the next TSS quorum-change finalization — directly matching the "removed observers are still able to vote" bug class and its associated risk of unauthorized state transitions in the universal execution flow.

### Likelihood Explanation
Likelihood is bounded by how the codebase actually tracks per-ballot voter eligibility (unconfirmed here — the exact `x/uexecutor/keeper/voting.go` logic that determines `eligibleVoters`/threshold for inbound/outbound/chain-meta ballots was not retrieved before the tool budget was exhausted). If `GetEligibleVoters` (which correctly filters `PENDING_LEAVE`) is used at ballot-creation for every ballot type, the vote might still be *submitted* successfully (passing the message-server gate) but rejected or ignored at the ballot layer, reducing severity to a spurious-tx/DoS-adjacent nuisance rather than a state-corrupting vote. The clearest, verified gap is that the **admission check itself** (`IsBondedUniversalValidator` + `IsTombstonedUniversalValidator`) does not encode lifecycle status, unlike `GetEligibleVoters`, which is an inconsistency in the codebase's own invariant model.

### Recommendation
Add an explicit lifecycle-status check (mirroring `GetEligibleVoters`'s `ACTIVE`/`PENDING_JOIN` allow-list) inside `IsBondedUniversalValidator` (or a new `CheckUniversalValidatorCanVote` helper used uniformly across `x/uexecutor` and `x/utss` message servers), rather than relying solely on staking-bonded + not-tombstoned. This closes the gap between "removed from the voter set" and "unable to vote," consistent with the Sherlock M-10 fix pattern (`CheckObserverCanVote`).

### Proof of Concept
Not independently confirmed end-to-end due to tool-call budget exhaustion before inspecting `x/uexecutor/keeper/voting.go`'s ballot-voter-snapshot logic and `types.Ballot.AddVote`'s voter-membership enforcement. The verified root cause is:
1. Admin calls `MsgRemoveUniversalValidator` on an `ACTIVE` UV → status becomes `PENDING_LEAVE`, entry stays in `UniversalValidatorSet`, underlying validator remains bonded and non-tombstoned [4](#0-3) .
2. That validator calls `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta`/`MsgVoteTssKeyProcess`/`MsgVoteFundMigration`. Both admission checks pass: `IsBondedUniversalValidator` returns `true` (no status check) [1](#0-0) , `IsTombstonedUniversalValidator` returns `false` [3](#0-2) .
3. This contrasts with `GetEligibleVoters`, which is the codebase's own authoritative "who may currently vote" filter and explicitly excludes `PENDING_LEAVE` [2](#0-1) .

To fully confirm ballot-level impact (whether the vote is actually tallied toward finalization or only accepted-then-discarded), a Devin session with full repository access should trace `x/uexecutor/keeper/voting.go`'s vote-processing path and `types.Ballot.AddVote` to determine whether the per-ballot voter snapshot is independently re-validated against `GetEligibleVoters` at vote time.

func (k Keeper) IsBondedUniversalValidator(ctx context.Context, universalValidator string) (bool, error) {
	k.Logger().Debug("checking bonded status of universal validator", "validator", universalValidator)

	accAddr, err := sdk.AccAddressFromBech32(universalValidator)
	if err != nil {
		return false, fmt.Errorf("invalid signer address: %w", err)
	}

	valAddr := sdk.ValAddress(accAddr)

	// Check if the universal validator is in the registered set
	exists, err := k.HasUniversalValidatorInSet(ctx, valAddr)
	if err != nil {
		return false, fmt.Errorf("failed to check universal validator set: %w", err)
	}
	if !exists {
		k.Logger().Debug("validator not found in universal validator set", "validator", universalValidator)
		return false, fmt.Errorf("validator %s not present in the registered universal validators set", valAddr.String())
	}

	// Ensure the universal validator exists in the staking module
	validator, err := k.StakingKeeper.GetValidator(ctx, valAddr)
	if err != nil {
		return false, fmt.Errorf("core validator not found: %w", err)
	}

	// Check that the validator is in bonded status
	if !validator.IsBonded() {
		k.Logger().Debug("universal validator is not bonded", "validator", universalValidator)
		return false, nil // exists but not bonded
	}

	k.Logger().Debug("universal validator is bonded", "validator", universalValidator)
	return true, nil
}

func (k Keeper) IsTombstonedUniversalValidator(ctx context.Context, universalValidator string) (bool, error) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Debug("checking tombstoned status of universal validator", "validator", universalValidator)

	accAddr, err := sdk.AccAddressFromBech32(universalValidator)
	if err != nil {
		return false, fmt.Errorf("invalid signer address: %w", err)
	}

	valAddr := sdk.ValAddress(accAddr)

	// Check if the universal validator exists in the set
	exists, err := k.HasUniversalValidatorInSet(ctx, valAddr)
	if err != nil {
		return false, fmt.Errorf("failed to check universal validator set: %w", err)
	}
	if !exists {
		k.Logger().Debug("validator not found in universal validator set", "validator", universalValidator)
		return false, fmt.Errorf("validator %s not present in the registered universal validators set", valAddr.String())
	}

	// Query the validator
	validator, err := k.StakingKeeper.GetValidator(sdkCtx, valAddr)
	if err != nil {
		return false, fmt.Errorf("core validator not found: %w", err)
	}

	// Get consensus address and check tombstoned status via slashing keeper
	consAddress, err := validator.GetConsAddr()
	if err != nil {
		return false, fmt.Errorf("failed to get consensus address: %w", err)
	}

	isTombstoned := k.SlashingKeeper.IsTombstoned(sdkCtx, consAddress)
	k.Logger().Debug("universal validator tombstone status",
		"validator", universalValidator,
		"is_tombstoned", isTombstoned,
	)
	return isTombstoned, nil
}
