### Title
Cross-denomination subtraction in `applyGasRefund` silently zeroes out legitimate user gas refunds - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
This report maps the C4 H-06 "balance sheet doesn't account for price/unit differences between tokens" bug class onto Push Chain's outbound gas-refund accounting. `applyGasRefund` subtracts `obs.GasFeeUsed` (voted by Universal Validators, documented as destination-chain **native wei**) from `outbound.GasFee` (denominated in an arbitrary PRC20 `GasToken` chosen by the `UniversalCore` contract at outbound-creation time) without any unit/price normalization, mirroring the original bug where a vault's balance sheet summed heterogeneous tokens as if they were fungible units of value.

### Finding Description
`outbound.GasFee` and `outbound.GasToken` are populated straight from the decoded `UniversalTxOutbound` EVM event when the outbound is created: [1](#0-0) 
The event's `GasFee` field is explicitly documented as "amount of GasToken paid to relayer" — i.e. denominated in whatever PRC20 `GasToken` the contract selected, not necessarily in destination-chain native wei: [2](#0-1) 

Separately, `obs.GasFeeUsed` — the value Universal Validators vote in via `MsgVoteOutbound` — is documented in the `universalClient` event struct as "gas fee used in **wei** (decimal string)": [3](#0-2) 
and it is populated directly from the observed on-chain event with no conversion applied before being submitted as the vote: [4](#0-3) 

`applyGasRefund` then does a raw `big.Int` subtraction between these two values to determine the refund amount, with no lookup of `GasToken`'s price/decimals relative to the destination chain's native currency: [5](#0-4) 

If `GasToken` is not a 1:1, same-decimals wrapper of the destination chain's native gas currency (e.g. it is a USDC-denominated PRC20 rather than a wrapped-native PRC20), `GasFee` (small USDC-like magnitude, e.g. ~10^6 units) will systematically be smaller than `GasFeeUsed` (native wei magnitude, e.g. ~10^15–10^18), causing `gasFee.Cmp(gasFeeUsed) <= 0` to always be true: [6](#0-5) 
This silently skips the refund path entirely — the excess gas fee prepaid by the user in `GasToken` is retained/lost rather than refunded, on every outbound where the units mismatch. Conversely, if the roles were reversed (a low-decimal/high-value `GasToken` vs. a low-value native currency), the same code could compute and pay out an inflated refund, over-draining the protocol's `UniversalCore` gas reserves. `MsgVoteOutbound.ValidateBasic` performs no unit/format cross-check between `GasFeeUsed` and the outbound's recorded `GasFee`/`GasToken`: [7](#0-6) 

This is called for both successful and failed (reverted) outbounds, so the effect is systemic across the outbound-finalization path, not a one-off edge case: [8](#0-7) [9](#0-8) 

### Impact Explanation
This falls under the in-scope "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" impact. If `GasToken` is genuinely a differently-priced/differently-scaled asset than the destination chain's native currency, ordinary honest users who overpay gas on the destination chain (a routine occurrence — `outbound.GasFee` is an estimate baked in at outbound-creation time, while `GasFeeUsed` is the actual consumption) never receive their legitimately owed refund, or in the reverse-scaling case the protocol over-pays refunds from `UniversalCore`'s reserves to any outbound triggerer, both without any privileged action, purely from ordinary honest-validator voting on ordinary user-initiated outbounds.

### Likelihood Explanation
Whether this is exploitable depends on a fact I could not fully confirm from the indexed code: whether `GasToken` (chosen by `UniversalCore.getOutboundTxGasAndFees`, sourced from `gasTokenPRC20ByChainNamespace`) is guaranteed to be a same-decimals wrapped-native token for every destination chain, or can be an independently priced/scaled PRC20. The Solidity implementation of `UniversalCore` and `gasTokenPRC20ByChainNamespace` is not present in this repository's indexed Go code (only the ABI signature is), so I could not verify the actual token semantics on-chain. If `GasToken` is always the destination chain's wrapped-native asset with matching decimals, `GasFee` and `GasFeeUsed` would in fact be comparable units and this finding would not hold.

### Recommendation
Do not directly subtract `obs.GasFeeUsed` (native wei) from `outbound.GasFee` (`GasToken`-denominated) without first confirming/normalizing units. Either (a) require Universal Validators to report `GasFeeUsed` in the same `GasToken` denomination as recorded on the outbound (converted via the same swap/quote logic used for building the outbound), or (b) explicitly convert `GasFee` to native-wei terms (or vice versa) before comparison, consistent with how `applyGasRefund`'s own swap-refund path already treats `GasToken` as a distinct-priced asset from PC native currency.

### Proof of Concept
Not independently executable from the indexed code alone (the `UniversalCore` Solidity contract that determines `GasToken` semantics is out of scope for this Go-code index). The logical PoC path is:
1. An outbound is created with `GasToken` set to a PRC20 whose raw units are small relative to wei (e.g. 6-decimal stablecoin) and `GasFee` = e.g. `2000000` (2 USDC-equivalent).
2. The destination-chain relayer reports `GasFeeUsed` = actual wei spent, e.g. `1500000000000000` (0.0015 ETH — a routine gas cost, but astronomically larger in raw integer terms than the `GasFee` value).
3. `applyGasRefund` computes `gasFee.Cmp(gasFeeUsed) <= 0` → true → refund skipped every time, confirmable via `test/integration/uexecutor/gas_fee_refund_test.go`'s existing refund-computation tests by substituting a small `GasFee`/large `GasFeeUsed` pair and observing `PcRefundExecution` stays `nil`. // buildOutboundObservation builds an OutboundObservation from event metadata and parsed outbound data
func (ep *EventProcessor) buildOutboundObservation(event *store.Event, outboundData *OutboundEvent) (*uexecutortypes.OutboundObservation, error) {
	// Extract txHash from EventID (format: "txHash:logIndex" or "signature:logIndex")
	txHash := ""
	parts := strings.Split(event.EventID, ":")
	if len(parts) > 0 {
		txHash = parts[0]
	}

	// Convert txHash to hex format if it's in base58
	txHashHex, err := ep.base58ToHex(txHash)
	if err != nil {
		ep.logger.Warn().
			Str("tx_hash", txHash).
			Err(err).
			Msg("failed to convert txHash to hex, using original value")
		txHashHex = txHash
	}

	gasFeeUsed := "0"
	if outboundData.GasFeeUsed != "" {
		gasFeeUsed = outboundData.GasFeeUsed
	}

	observation := &uexecutortypes.OutboundObservation{
		Success:     true,
		BlockHeight: event.BlockHeight,
		TxHash:      txHashHex,
		ErrorMsg:    "",
		GasFeeUsed:  gasFeeUsed,
	}

	return observation, nil

func (k Keeper) FinalizeOutbound(ctx context.Context, utxId string, outbound types.OutboundTx) error {
	// If not observed yet, do nothing
	if outbound.OutboundStatus != types.Status_OBSERVED {
		return nil
	}

	obs := outbound.ObservedTx
	if obs == nil {
		return nil
	}

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Info("finalizing outbound",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"success", obs.Success,
		"dest_chain", outbound.DestinationChain,
		"tx_type", outbound.TxType.String(),
	)

	if !obs.Success {
		return k.handleFailedOutbound(sdkCtx, utxId, outbound, obs)
	}

	return k.handleSuccessfulOutbound(sdkCtx, utxId, outbound, obs)
}

// ValidateBasic does a sanity check on the provided data.
func (msg *MsgVoteOutbound) ValidateBasic() error {
	// validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// tx_id must be non-empty
	if strings.TrimSpace(msg.TxId) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_id cannot be empty")
	}

	// utx_id must be non-empty
	if strings.TrimSpace(msg.UtxId) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "utx_id cannot be empty")
	}

	// observed_tx must NOT be nil
	if msg.ObservedTx == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "observed_tx cannot be nil")
	}

	// Validate observed_tx content
	obs := msg.ObservedTx

	// gas_fee_used is always required — the external chain consumes gas regardless
	// of success or failure, and excess gas must be refundable in both cases.
	if strings.TrimSpace(obs.GasFeeUsed) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest,
			"observed_tx.gas_fee_used is required")
	}

	if obs.Success {
		// Success additionally requires tx_hash and block_height.
		if strings.TrimSpace(obs.TxHash) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidRequest,
				"observed_tx.tx_hash required when success=true")
		}
		if obs.BlockHeight == 0 {
			return errors.Wrap(sdkerrors.ErrInvalidRequest,
				"observed_tx.block_height must be > 0 when success=true")
		}
	} else {
		// Failure case: tx_hash MAY be empty.
		// BUT if tx_hash is present, block_height must be > 0.
		if strings.TrimSpace(obs.TxHash) != "" && obs.BlockHeight == 0 {
			return errors.Wrap(sdkerrors.ErrInvalidRequest,
				"observed_tx.block_height must be > 0 when tx_hash is provided")
		}
	}

	return nil
}
