### Title
`TransactionOutput::ensure_match_transaction_info` never validates state/hot-state/position-state checkpoint hashes, letting replay-verify accept a corrupted state root - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the authenticated-integrity gate that is supposed to prove a locally-computed `TransactionOutput` matches the `TransactionInfo` recorded (and accumulator-committed) on the authenticated ledger. It checks status, gas, the write-set hash, and the event-root hash, but it never checks `txn_info.state_checkpoint_hash()`, the hot-state checkpoint hash, or `position_state_checkpoint_hash` against the state root actually produced by local execution. This gap is acknowledged directly in the code's own `TODO(trading-native)` comment.

### Finding Description
`TransactionInfo` carries multiple checkpoint-hash fields that authenticate different state roots at a version: the main state root (`state_checkpoint_hash`), the hot-state root, and — with the new native-position/trading feature — `position_state_checkpoint_hash`, computed in `execution/executor/src/workflow/do_state_checkpoint.rs` (`DoStateCheckpoint::compute_position_checkpoint`, `get_state_checkpoint_hashes`). These hashes are the only cryptographic binding between "what the VM/execution pipeline actually computed as new state" and "what is authenticated on chain via the transaction accumulator" (`accumulator_root_hash` covers `TransactionInfo::hash()`, which embeds these checkpoint hashes).

`TransactionOutput::ensure_match_transaction_info` (types/src/transaction/mod.rs, ~lines 2139-2204) is the function meant to assert this binding when replaying/re-executing against archived data (e.g. via db-tool's `replay_on_archive`), but its body only verifies:
- `status == txn_info.status()`
- `gas_used == txn_info.gas_used()`
- `write_set_hash == txn_info.state_change_hash()`
- `event_root_hash == txn_info.event_root_hash()`

and then returns `Ok(())` unconditionally, with an explicit comment admitting the omission: [1](#0-0) 

```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
Ok(())
```

Because the state-checkpoint hashes are never compared, if local re-execution produces a *different* state root than the one authenticated via the accumulator (whether from a genuine bug in `DoStateCheckpoint::compute_position_checkpoint`'s SMT extension logic, a storage/restore inconsistency, or a divergent node), this integrity gate silently reports success. The same struct/field (`state_checkpoint_hash`, `position_state_checkpoint_hash`) is exactly the value that downstream authenticated flows (state sync `bootstrapper.rs`, restore, JMT/position summaries) rely on being correct — but the one code path whose explicit job is to catch a mismatch between recomputed state and the recorded/authenticated root does not do so.

### Impact Explanation
This breaks the "committed state must match VM result" and "hard-fork-only divergence during commit/replay/restore/proof verification must be caught" invariants required by the state-integrity gate. Replay-verify tooling (`db-tool replay_on_archive`, and any other caller of `ensure_match_transaction_info`) is the safety net used to detect exactly this class of divergence — e.g., after a storage bug, an inconsistent hot-state/position-state update, or a subtly wrong state-root computation. With this check silently skipped, such divergences (including specifically the newly introduced `position_state_checkpoint_hash` for the native trading/position feature, guarded by `COMPUTE_TRADING_NATIVE_STATE_ROOTS`) can go undetected, masking a wrong accepted state root as a "successful" replay. This is a high-impact proof-integrity defect: it defeats the authenticated-response guarantee that state roots bound to a version are actually verified against locally recomputed values.

### Likelihood Explanation
The gap is deterministic and always present for any caller of `ensure_match_transaction_info` — no attacker interaction is required to trigger the missing check; it fires (or rather, fails to fire) any time there is a legitimate divergence between recomputed state roots and recorded `TransactionInfo` checkpoint hashes. The condition under which this matters in practice (state root actually diverging) requires another root cause (e.g., a bug in `compute_position_checkpoint`'s SMT extension across checkpoints, or storage corruption), but the detection mechanism meant to catch it is confirmed broken by the code's own comment, independent of how that divergence arises.

### Recommendation
Extend `ensure_match_transaction_info` to also compare the locally computed state-checkpoint hash(es) — including hot-state and `position_state_checkpoint_hash` — against the corresponding fields on `txn_info`, returning an error on mismatch, before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (and hot-state root authentication) are relied upon in production/replay-verify workflows.

### Proof of Concept
Not applicable as an exploit PoC — this is a detection-gap finding proven directly by the source: [2](#0-1)  shows `ensure_match_transaction_info` omitting checks over `state_checkpoint_hash`/`position_state_checkpoint_hash`, and [3](#0-2)  shows these are exactly the hashes computed for the native-position/trading feature that this comparator is supposed to, but does not, validate.

**Note on completeness:** I was not able to fully enumerate every caller of `ensure_match_transaction_info` (e.g., confirm whether `db-tool`'s `replay_on_archive` is its only consumer, or whether other call sites independently re-check the state-checkpoint hash elsewhere) within the available tool budget. If another caller performs that check redundantly, the practical severity would be reduced to defense-in-depth loss rather than a complete detection bypass; this should be verified with a full call-site search (`grep -r "ensure_match_transaction_info"`) before treating this as fully unmitigated.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
