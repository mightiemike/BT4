### Title
Unauthenticated panic (DoS) via negative `strings.Repeat` count in `normalizeHex` when `workflowID`/`workflowOwner` lacks `0x` prefix but has full hex length - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`validateHexInput` compares the *raw* input length (including any `0x` prefix) against `workflowIDLength`/`workflowOwnerLength`, but it accepts inputs that never had a `0x` prefix as long as their raw length is `<= expectedLength`. `normalizeHex` then computes `expectedHexLength - len(hexStr)` after stripping a `0x` prefix that never existed, which can go negative and cause `strings.Repeat` to panic.

### Finding Description
`validateWorkflowID`/`validateWorkflowOwner` call `validateHexInput(input, workflowIDLength)` (66) / `workflowOwnerLength` (42) at [1](#0-0) . This function only checks `len(input) > expectedLength` (rejecting too-long input) and that `hex.DecodeString` succeeds on the string after trimming an optional `0x` prefix; it does not require the `0x` prefix to be present, and does not enforce a minimum/expected length.

Because `x` is not a valid hex digit, a string of pure hex characters (0-9a-f) with **no** `0x` prefix can be exactly `workflowIDLength` (66) or `workflowOwnerLength` (42) characters long — e.g. 66 hex chars for `workflowID`, decoding to 33 bytes — and will pass `validateHexInput` since `len(input) == expectedLength` and `hex.DecodeString` succeeds on an even-length hex-only string.

For the above 66-char, no-prefix input: `hexStr = TrimPrefix(input, "0x")` is a no-op (input never had `0x`), so `len(hexStr) == 66`. `expectedHexLength = 66 - 2 = 64`. `strings.Repeat("0", 64-66)` = `strings.Repeat("0", -2)`, which panics with `"strings.Repeat: negative count"`. The same applies to `workflowOwner` with a 42-character, no-`0x`-prefix hex string (`expectedHexLength = 40`, `len(hexStr) = 42`).

This is directly reachable by any unauthenticated caller sending an HTTP trigger request (`workflows.execute`) with a crafted `workflow.workflowID` or `workflow.workflowOwner` value — no signature/auth check occurs before `resolveWorkflowID` runs (`authorizeRequest` happens *after* `resolveWorkflowID` in `HandleUserTriggerRequest`, at [4](#0-3) ). No panic-recovery wrapper was found anywhere in `core/services/gateway/handlers/capabilities/v2/` (only a test file references `recover()`), so a panic here is not caught locally.

### Impact Explanation
A crafted, otherwise well-formed HTTP trigger request causes a runtime panic in the gateway node-side handler goroutine before any authorization/signature verification. If this goroutine is not wrapped with panic recovery further up the call stack (e.g., in the JSON-RPC dispatcher or HTTP server), this can crash the gateway process serving the DON, resulting in denial of service for all workflows behind that gateway — reachable by any unauthenticated caller able to submit an HTTP trigger request.

### Likelihood Explanation
Trivial to trigger: the attacker only needs to send a single JSON-RPC `workflows.execute` request with `workflow.workflowID` set to a 66-character lowercase hex string without a `0x` prefix (or `workflow.workflowOwner` set to a 42-character no-prefix hex string). No authentication, signature, or prior state is required, and the request format is otherwise valid per the schema. This is fully repeatable and deterministic.

### Recommendation
In `normalizeHex`, clamp/validate before padding: reject (or truncate/error) when `len(hexStr) > expectedHexLength` instead of calling `strings.Repeat` with a potentially negative count. Additionally, tighten `validateHexInput` to require the `0x` prefix explicitly (or to check the decoded byte length against the expected byte length, e.g., 32 bytes for workflow ID / 20 bytes for workflow owner) rather than only checking overall string length loosely. Add a bounds check such as:
```go
func normalizeHex(input string, length int) string {
    hexStr := strings.TrimPrefix(input, "0x")
    expectedHexLength := length - 2
    if len(hexStr) > expectedHexLength {
        // treat as invalid input rather than panicking
    }
    ...
}
```

func validateHexInput(input string, expectedLength int) error {
	if input != strings.ToLower(input) {
		return errors.New("must be lowercase")
	}

	if len(input) > expectedLength {
		return fmt.Errorf("hex string too long: expected at most %d characters, got %d", expectedLength, len(input))
	}

	hexStr := strings.TrimPrefix(input, "0x")
	_, err := hex.DecodeString(hexStr)
	if err != nil {
		return errors.New("must be a valid hex string")
	}

	return nil
}
