### Title
Poison-microblock check accepts a malleated duplicate signature of a single signing event as proof of equivocation - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`)

### Summary
`StacksChainState::check_microblock_header_signer` only verifies that two microblock headers recover to the same public-key hash; it never checks that the two headers actually commit to different signed content. Because ECDSA/secp256k1 signatures are malleable (`s -> n-s` with a flipped recovery id yields a second syntactically valid signature over the *same* message that recovers the same pubkey), an attacker who observes a single, honestly-signed microblock header can derive a second header with identical `sequence`/`prev_block`/`tx_merkle_root` but a different signature, and submit both as `PoisonMicroblock` material.

### Finding Description
The broken equality is: the code treats **"pkh1 == pkh2 (via `check_recover_pubkey`)"** as equivalent to **"the miner independently signed two distinct microblocks at the same position (a genuine equivocation)"**. These are not the same thing.

```
stackslib/src/chainstate/stacks/db/transactions.rs:686-713
fn check_microblock_header_signer(
    mblock_hdr_1: &StacksMicroblockHeader,
    mblock_hdr_2: &StacksMicroblockHeader,
) -> Result<Hash160, Error> {
    let pkh1 = mblock_hdr_1.check_recover_pubkey()...
    let pkh2 = mblock_hdr_2.check_recover_pubkey()...
    if pkh1 != pkh2 { ... return Err(...) }
    Ok(pkh1)
}
``` [1](#0-0) 

There is no check anywhere in this function, nor in its only caller `handle_poison_microblock`, that the two headers differ in committed content (e.g. `tx_merkle_root`) or even that `mblock_hdr_1.block_hash() != mblock_hdr_2.block_hash()`. The caller proceeds directly from the pubkey-hash comparison to looking up `pubkh`'s microblock height and recording a poison report keyed only on `mblock_header_1.sequence`: [2](#0-1) [3](#0-2) 

Because ECDSA signatures over secp256k1 are malleable, given one real signature `(r, s, recid)` produced by the honest miner over a message `m`, `(r, n-s, recid^1)` is also a valid signature for `m` that recovers to the identical public key. An attacker can therefore take one genuinely-signed header `H` (broadcast on the wire, and thus public), construct `H'` with the same `sequence`, `prev_block`, `tx_merkle_root`, but the malleated signature, and submit `(H, H')` as the two headers of a `PoisonMicroblock` transaction payload. `check_recover_pubkey()` on `H'` recovers the same `pkh` as `H`, so `pkh1 == pkh2` holds, and `check_microblock_header_signer` returns `Ok(pkh1)` even though the miner only performed one signing operation. No downstream check (sequence-match, `block_hash()` inequality, or content inequality) exists to reject this pair as "not an equivocation."

### Impact Explanation
This does not cause two honest nodes to disagree — the outcome is deterministic under the shared consensus rules, so it is not a chain split. It does, however, let an unprivileged attacker forge "poison" evidence against a miner who signed only one microblock, causing the honest miner's future coinbase at that block height to be flagged as slashed once `MINER_REWARD_MATURITY` passes, and diverting the poison "commission" to the attacker's `sender_principal`. This matches the rubric's **High** category ("a poison or reward mis-payment bounded to fees"): an unjust reward mis-payment/loss triggered by a minority (single) attacker, not a consensus divergence.

### Likelihood Explanation
The attacker needs no privileged role: they only need to observe one legitimately broadcast, signed microblock header from any miner (trivially available from the P2P network) and perform a standard secp256k1 signature malleation (negate `s` mod `n`, flip the recovery id) — a purely local, off-chain computation requiring no stake, no BTC spend, and no cooperation from other parties. This is fully repeatable against any miner who has signed at least one microblock, and requires only a single Stacks transaction submission (`PoisonMicroblock` payload) once the maturity window condition (`mblock_pubk_height` not yet matured) is satisfied — a condition attacker can wait for or target opportunistically.

### Recommendation
In `check_microblock_header_signer` (or immediately in `handle_poison_microblock` before any state is read/written), add an explicit distinctness check on the *signed content* rather than just the recovered pubkey hash: require `mblock_hdr_1.sequence == mblock_hdr_2.sequence` (same slot) **and** that the pre-signature sighash / committed fields (`prev_block`, `tx_merkle_root`, `version`) actually differ between the two headers (i.e., verify a genuine equivocation on content, not merely a different signature encoding of the same message). Rejecting pairs whose signing message (sighash, not the raw signature bytes or `block_hash()` which includes the signature) is identical closes the malleability path.

### Proof of Concept
Rust integration test plan (in `stackslib/src/chainstate/stacks/db/transactions.rs` test module or a new test):
1. Generate a `StacksPrivateKey` for miner `M`, construct a `StacksMicroblockHeader` `H` with fixed `sequence`, `prev_block`, `tx_merkle_root`, and sign it with `M` (one genuine signing operation) via `H.sign(&privk)`.
2. From `H.signature` extract `(r, s, recid)`; compute the secp256k1-order `n`; derive `s' = n - s` and `recid' = recid ^ 1`; construct `H'` identical to `H` in all fields except `signature = (r, s', recid')`.
3. Assert `H.block_hash() != H'.block_hash()` (different signature bytes) but `H.check_recover_pubkey().unwrap() == H'.check_recover_pubkey().unwrap()` (malleability confirmed, same recovered pubkey hash).
4. Call `StacksChainState::check_microblock_header_signer(&H, &H')` and assert that it currently returns `Ok(pkh)` — demonstrating the false-positive poison acceptance from a single genuine signing event.
5. Assert the *desired* fixed behavior: after adding a sighash/content-equality guard, the same call should return `Err(Error::InvalidStacksTransaction(...))` because `H` and `H'` sign the identical message and do not represent two independent signing acts.

                false,
            )

            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
