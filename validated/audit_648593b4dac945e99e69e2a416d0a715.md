### Title
Unbounded gzip decompression of user-supplied Cairo0 program in RPC `decompress_program` enables decompression-bomb DoS - (File: crates/apollo_rpc/src/v0_8/api/mod.rs)

### Summary
`decompress_program` in [1](#0-0)  base64-decodes and gzip-decompresses a caller-controlled string into an unbounded `Vec<u8>` buffer with no size cap or read limit, unlike the equivalent gateway-side decompression paths that explicitly enforce a maximum decompressed size.

### Finding Description
The function reads an attacker-supplied base64 string, decodes it, and streams it through `flate2::bufread::GzDecoder::read_to_end` into an in-memory `Vec<u8>` with no bound on the resulting size: [2](#0-1) 
The inline `TODO(dan): add time and size limits.` comment confirms this is an acknowledged, unaddressed gap. This is the same bug class as CVE-2016-1372 (crafted archive causing unbounded resource consumption/crash during decompression) — a decompression routine that trusts external input without capping output size or time.

By contrast, other decompression call sites in the codebase that process untrusted, network-supplied data (e.g., declared Sierra programs from the deprecated gateway and stateless validator) are hardened with explicit size limits, e.g. `decompress_with_size_limit` / `decode_and_decompress_with_size_limit` in [3](#0-2)  and `DeprecatedGatewaySierraContractClass::convert_to_sierra_contract_class` in [4](#0-3) , which bound decompressed size before allocation. `decompress_program` lacks this protection, deviating from the codebase's established defensive pattern for exactly this kind of untrusted-compressed-input handling.

`decompress_program` operates on a base64-compressed `program` field that originates from RPC-callers submitting Cairo0 (`BroadcastedDeclareV1Transaction`) contract classes to simulate/trace/estimate-fee style JSON-RPC methods (imported types `BroadcastedDeclareTransaction`, `BroadcastedDeclareV1Transaction` in the same file, used for `ExecutableTransactionInput` handling) — this is caller-supplied data reachable by any unprivileged RPC client, not a trusted-operator-only path.

### Impact Explanation
A malicious RPC caller can submit a small, highly-compressed gzip payload (a decompression bomb) as the `program` field of a broadcasted Cairo0 declare transaction to any RPC endpoint that calls `decompress_program` (e.g. fee estimation / simulation / trace endpoints). Because there is no cap on decompressed size, the node will attempt to allocate an arbitrarily large buffer, leading to memory exhaustion and process crash (denial of service) of the sequencer/full-node RPC service. This does not corrupt state or commitments, but it satisfies the "network unable to confirm new transactions" impact bar if it affects a sequencer process serving RPC and execution.

### Likelihood Explanation
High: any unprivileged JSON-RPC client can submit a crafted request; no authentication, fee payment, or on-chain transaction is required to reach this decompression call, and gzip bombs achievable with typical ~1000x+ compression ratios are trivial to construct.

### Recommendation
Apply the same bounded-decompression pattern already used elsewhere in the codebase (e.g. `decompress_with_size_limit`): wrap `GzDecoder::read_to_end` with a `Read::take(max_size + 1)` and reject inputs whose decompressed length exceeds a configured maximum, returning an RPC error instead of continuing to allocate. Add both a size limit and (optionally) a decompression time/step limit as the existing TODO already suggests.

### Proof of Concept
1. Craft a gzip payload that decompresses to a very large buffer (e.g. gigabytes) from a small compressed input (a "zip bomb"), base64-encode it.
2. Submit an RPC request (e.g. `starknet_estimateFee`, `starknet_simulateTransactions`, or `starknet_traceTransaction`-equivalent flow) containing a `BroadcastedDeclareV1Transaction` whose `contract_class.program` field is set to the crafted base64 string.
3. The node calls `decompress_program`, which decompresses without bound, exhausting memory and crashing or hanging the node process — a denial of service triggered by a single unprivileged RPC call.

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}

    value: &str,
