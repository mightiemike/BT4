### Title
L2-to-L1 / L1-to-L2 message gas cost overestimation via flat `GAS_PER_MEMORY_WORD` in `MessageResources::get_starknet_gas_cost` causes legitimate large-payload messages to be permanently rejected as `TransactionTooLarge` - (File: crates/blockifier/src/fee/resources.rs)

### Summary
`MessageResources::get_starknet_gas_cost` charges every felt/word of the L1<->L2 message segment at a flat `GAS_PER_MEMORY_WORD` (16 gas/byte × 32 bytes = 512 gas per felt), with no discount for zero-valued felts, unlike the sibling function `get_da_gas_cost`, which explicitly discounts zero bytes via `get_calldata_word_cost`. This flat overestimation feeds directly into `BouncerWeights.l1_gas`, which is checked per single transaction against the immutable `block_max_capacity.l1_gas` bound. A transaction whose real L1 execution cost would be small (mostly-zero payload) but whose nominal message length is large can be permanently rejected with `TransactionTooLarge`, because a single-transaction check against a fixed cap can never be satisfied — this exactly mirrors the reported `baseGas()` overestimation bug class where a flat calldata gas rate ignoring zero-bytes makes an otherwise-executable, real-cost-cheap message permanently un-includable.

### Finding Description
`MessageResources::get_starknet_gas_cost` computes the L1 gas usage of a transaction's L1<->L2 messages as: [1](#0-0) 

It multiplies `message_segment_length` (a felt/word count that includes the L1-handler payload size or L2-to-L1 payload sizes) directly by `eth_gas_constants::GAS_PER_MEMORY_WORD`: [2](#0-1) 

This is a flat, content-independent per-word charge. Contrast this with `get_da_gas_cost`, in the same file, which explicitly accounts for the fact that many bytes in a state update are zero and uses `get_calldata_word_cost(n_nonzero_bytes)` to discount for it: [3](#0-2) [4](#0-3) 

The `message_segment_length` used for the L1<->L2 message gas cost is purely a length (`L1_TO_L2_MSG_HEADER_SIZE + payload_size` or `L2_TO_L1_MSG_HEADER_SIZE + payload_length`), with no distinction between zero-valued felts and nonzero felts: [5](#0-4) 

The resulting overestimated `l1_gas` (via `message_starknet_l1gas`) is placed directly into `BouncerWeights.l1_gas`: [6](#0-5) 

This `BouncerWeights` is checked, per single transaction (not just cumulative block state), against the fixed `block_max_capacity` via `within_max_capacity_or_err`/`verify_tx_weights_within_max_capacity`, both of which raise `TransactionTooLarge` and are wired into `TransactionalState`/`transaction_execution.rs`: [7](#0-6) [8](#0-7) [9](#0-8) 

Because `block_max_capacity.l1_gas` is a fixed configuration value (default 2,500,000, per `config_schema.json`), any single transaction whose computed `message_starknet_l1gas` alone exceeds this cap will always return `TransactionTooLarge`, regardless of block state — it can never be included in any block, ever. If the flat per-word rate overestimates the true cost of a large, mostly-zero-payload message (e.g., a padded/structured payload sent to L1 via an `L1_HANDLER` triggering transaction, or a large L2-to-L1 message emitted by a contract), a message that would be economically/structurally reasonable is nonetheless permanently excluded from block production — directly analogous to the reported `baseGas()` issue.

### Impact Explanation
A transaction (e.g. an L2 contract emitting a large L2-to-L1 withdrawal/payment message with a sparse/zero-heavy payload) that legitimately needs to reach L1 can be permanently unable to be included in any block once its nominal `message_segment_length * GAS_PER_MEMORY_WORD` exceeds `block_max_capacity.l1_gas`. Since the per-single-tx check compares tx weights directly against the fixed cap (not cumulative block usage), there is no way for such a transaction to ever pass, freezing whatever L2-side state changes/side effects were intended to trigger the L1 message, and preventing the L1 message from ever being emitted/finalized — a form of permanent denial of service / freezing of the message-passing path reachable by any ordinary contract call that emits a large L2-to-L1 message or is invoked as an L1 handler with a large payload.

### Likelihood Explanation
Reachable by any unprivileged L2 contract call that sends a large L2-to-L1 message (via `send_message_to_l1` syscall) or is an L1-handler transaction consuming a large L1-to-L2 message payload — both are entirely within reach of a single transaction submitted by any user/contract, no privileged role required. The condition (payload length large enough that `message_segment_length * GAS_PER_MEMORY_WORD` exceeds `block_max_capacity.l1_gas`, e.g. `2_500_000 / 512 ≈ 4883` felts) is attainable with realistic large payloads (e.g., batched cross-chain calls, large arrays).

### Recommendation
Compute the L1<->L2 message gas cost the same way `get_da_gas_cost` computes state-diff gas cost — i.e., account for zero vs. nonzero bytes/felts in the payload via `get_calldata_word_cost`, rather than a flat `GAS_PER_MEMORY_WORD` per word regardless of content. Alternatively/additionally, ensure the bouncer's "transaction too large" check is based on realistic cost rather than a pessimistic upper bound that can make legitimate messages permanently un-includable, and document/enforce a maximum payload size for L1<->L2 messages at the syscall/transaction-validation layer so that failure happens early and deterministically rather than perpetually at block-building time.

### Proof of Concept
Not independently executed against a running node in this analysis; the flow was traced statically:
1. A contract on L2 emits an L2-to-L1 message with a large, mostly-zero payload (`payload.len()` large, e.g. thousands of felts, values mostly `Felt::ZERO`).
2. `get_message_segment_length` computes `message_segment_length = L2_TO_L1_MSG_HEADER_SIZE + payload_length` — same result whether the payload is all zeros or all nonzero. [10](#0-9) 
3. `MessageResources::get_starknet_gas_cost` multiplies this length by the flat `GAS_PER_MEMORY_WORD` (512), producing `l1_gas` proportional to felt count, not actual content/DA cost. [1](#0-0) 
4. This inflated `l1_gas` becomes `BouncerWeights.l1_gas` via `get_tx_weights`. [11](#0-10) 
5. `verify_tx_weights_within_max_capacity`/`within_max_capacity_or_err` compares this single-transaction weight against the fixed `block_max_capacity.l1_gas` (default `2,500,000`), returning `TransactionTooLarge` if exceeded — a state the transaction can never escape since the comparison does not depend on remaining block capacity for a per-tx check. [8](#0-7) [12](#0-11) 

I was unable to fully trace, within the available tool budget, exactly where `TransactionTooLarge` errors surface back to the gateway/mempool admission path (to confirm whether such a transaction is rejected at submission time versus only at block-building time), so the precise point at which the "permanent freeze" manifests (mempool rejection vs. batcher exclusion after fee has been paid) is not fully confirmed here.

/// Returns the gas cost of data availability on L1.
pub fn get_da_gas_cost(state_changes_count: &StateChangesCount, use_kzg_da: bool) -> GasVector {
    let onchain_data_segment_length = get_onchain_data_segment_length(state_changes_count);

    let (l1_gas, blob_gas) = if use_kzg_da {
        (
            0_u8.into(),
            u64_from_usize(
                onchain_data_segment_length * eth_gas_constants::DATA_GAS_PER_FIELD_ELEMENT,
            )
            .into(),
        )
    } else {
        // TODO(Yoni, 1/5/2024): count the exact amount of nonzero bytes for each DA entry.
        let naive_cost = onchain_data_segment_length * eth_gas_constants::SHARP_GAS_PER_DA_WORD;

        // For each modified contract, the expected non-zeros bytes in the second word are:
        // 1 bytes for class hash flag; 2 for number of storage updates (up to 64K);
        // 3 for nonce update (up to 16M).
        let modified_contract_cost = eth_gas_constants::get_calldata_word_cost(1 + 2 + 3);
        let modified_contract_discount =
            eth_gas_constants::GAS_PER_MEMORY_WORD - modified_contract_cost;
        let mut discount = state_changes_count.n_modified_contracts * modified_contract_discount;

        // Up to balance of 8*(10**10) ETH.
        let fee_balance_value_cost = eth_gas_constants::get_calldata_word_cost(12);
        discount += eth_gas_constants::GAS_PER_MEMORY_WORD - fee_balance_value_cost;

        // Cost must be non-negative after discount.
        let gas = naive_cost.saturating_sub(discount);

        (u64_from_usize(gas).into(), 0_u8.into())
    };

    GasVector { l1_gas, l1_data_gas: blob_gas, ..Default::default() }
}

pub fn get_message_segment_length(
    l2_to_l1_payload_lengths: &[usize],
    l1_handler_payload_size: Option<usize>,
) -> usize {
    // Add L2-to-L1 message segment length; for each message, the OS outputs the following:
    // to_address, from_address, payload_size, payload.
    let mut message_segment_length = l2_to_l1_payload_lengths
        .iter()
        .map(|payload_length| constants::L2_TO_L1_MSG_HEADER_SIZE + payload_length)
        .fold(0, |accumulator, length| {
            usize::checked_add(accumulator, length).expect(
                "Sending a message to L1 costs gas proportional to payload, so total cannot \
                 exceed usize.",
            )
        });

    if let Some(payload_size) = l1_handler_payload_size {
        // The corresponding transaction is of type L1 handler; add the length of the L1-to-L2
        // message sent by the sequencer (that will be outputted by the OS), which is of the
        // following format: from_address=calldata[0], to_address=contract_address,
        // nonce, selector, payload_size, payload=calldata[1:].
        message_segment_length += constants::L1_TO_L2_MSG_HEADER_SIZE + payload_size;
    }

    message_segment_length
}

#[allow(clippy::too_many_arguments)]
pub fn get_tx_weights<S: StateReader>(
    state_reader: &S,
    executed_class_hashes: &HashSet<ClassHash>,
    n_visited_storage_entries: usize,
    tx_resources: &TransactionResources,
    state_changes_keys: &StateChangesKeys,
    versioned_constants: &VersionedConstants,
    tx_cairo_primitives_counters: &CairoPrimitiveCounterMap,
    bouncer_config: &BouncerConfig,
    receipt_l2_gas: GasAmount,
) -> TransactionExecutionResult<TxWeights> {
    let message_resources = &tx_resources.starknet_resources.messages;
    let message_starknet_l1gas = usize_from_u64(message_resources.get_starknet_gas_cost().l1_gas.0)
        .expect("This conversion should not fail as the value is a converted usize.");

    // Casm hash resources.
    let class_hash_to_casm_hash_computation_resources =
        map_class_hash_to_casm_hash_computation_resources(state_reader, executed_class_hashes)?;

    // Patricia update + transaction resources.
    let patricia_update_resources = get_patricia_update_resources(
        n_visited_storage_entries,
        // TODO(Yoni): consider counting here the global contract tree and the aliases as well.
        state_changes_keys.storage_keys.len(),
    );
    let vm_resources =
        &tx_resources.computation.total_extended_vm_resources() + &patricia_update_resources;

    // Builtin gas costs for stone and for stwo.
    let sierra_builtin_gas_costs = &versioned_constants.os_constants.gas_costs.builtins;
    let proving_builtin_gas_costs = &bouncer_config.builtin_gas_costs();

    // Casm hash migration resources.
    let migration_data = CasmHashMigrationData::from_state(
        state_reader,
        executed_class_hashes,
        versioned_constants,
    )?;
    // Total state changes keys are the sum of marginal state changes keys and the
    // migration state changes.
    let mut total_state_changes_keys = StateChangesKeys {
        compiled_class_hash_keys: migration_data.class_hashes_to_migrate.keys().cloned().collect(),
        ..Default::default()
    };
    total_state_changes_keys.extend(state_changes_keys);

    // Migration occurs once per contract and is not included in the CASM hash computation, which
    // is performed every time a contract is loaded.
    let sierra_migration_gas = migration_data.to_gas(sierra_builtin_gas_costs, versioned_constants);
    let proving_migration_gas =
        migration_data.to_gas(proving_builtin_gas_costs, versioned_constants);

    // Sierra gas computation.
    let (total_sierra_gas, casm_hash_computation_data_sierra_gas, vm_resources_sierra_gas) =
        compute_sierra_gas(
            &vm_resources,
            sierra_builtin_gas_costs,
            versioned_constants,
            tx_resources,
            sierra_migration_gas,
            &class_hash_to_casm_hash_computation_resources,
        );

    // Proving gas computation.
    let cairo_primitives_for_proving_gas = get_cairo_primitives_for_proving_gas_computation(
        patricia_update_resources.prover_builtins(),
        tx_resources.computation.os_vm_resources.prover_builtins(),
        tx_cairo_primitives_counters,
    );

    let (total_proving_gas, casm_hash_computation_data_proving_gas) = compute_proving_gas(
        &cairo_primitives_for_proving_gas,
        vm_resources_sierra_gas,
        versioned_constants,
        proving_builtin_gas_costs,
        sierra_builtin_gas_costs,
        proving_migration_gas,
        &class_hash_to_casm_hash_computation_resources,
    );

    let bouncer_weights = BouncerWeights {
        l1_gas: message_starknet_l1gas,
        message_segment_length: message_resources.message_segment_length,
        n_events: tx_resources.starknet_resources.archival_data.event_summary.n_events,
        state_diff_size: get_onchain_data_segment_length(&total_state_changes_keys.count()),
        sierra_gas: total_sierra_gas,
        n_txs: 1,
        proving_gas: total_proving_gas,
        receipt_l2_gas,
    };
