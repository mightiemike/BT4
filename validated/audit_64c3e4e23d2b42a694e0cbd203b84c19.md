## Title
`ValidateMultiSign` precompiled contract (TVM opcode `validatemultisign`) computes signature hash without chain/domain binding, enabling cross-chain signature replay - (File: `actuator/src/main/java/org/tron/core/vm/PrecompiledContracts.java`)

## Summary
The `ValidateMultiSign` precompiled contract, exposed to TVM smart contracts via the `validatemultisign` builtin, authorizes actions by recovering signer addresses from a hash computed purely as `sha256(address || permissionId || data)`. There is no chain identifier, contract-instance identifier, or nonce baked into this hash by the precompile itself — domain separation is left entirely to whatever the calling contract chooses to put into the caller-supplied `data` field. This mirrors exactly the `mintBySignature` bug class described in the report: a signature-based authorization primitive with no EIP-712-style domain separator, allowing a valid signature produced for use on one chain/context to be replayed on another chain/context where the same account address, permission id, and `data` exist.

## Finding Description
`ValidateMultiSign.execute()` builds the message to verify as: [1](#0-0) 

```
DataWord[] words = DataWord.parseArray(rawData);
byte[] address = words[0].toTronAddress();
int permissionId = words[1].intValueSafe();
byte[] data = words[2].getData();

byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
byte[] hash = Sha256Hash.hash(CommonParameter.getInstance().isECKeyCryptoEngine(), combine);
```

It then recovers the signer for each supplied signature against this `hash` and accumulates `Permission` key weights until the permission's `threshold` is met: [2](#0-1) 

There is no `chainId`, contract address of the caller, nonce, or any TIP/EIP-712-style domain separator mixed into `hash` by the precompile. The only inputs are the target account's `address`, its `permissionId`, and an arbitrary `data` blob fully controlled by the invoking smart contract. This is structurally identical to the reported `mintBySignature` flaw: signature validity is not scoped to a specific chain or deployment, so any contract built on top of `validatemultisign` (multisig wallets, permit-style token approvals/mints, escrow release logic, etc.) that does not itself embed a chain-specific salt inside `data` inherits full cross-chain (and cross-fork/cross-testnet) replayability.

Because java-tron account addresses and permission structures (`Permission`, `Key` lists, `threshold`) are deterministic and portable across the TRON mainnet, public testnets (Nile/Shasta), and any private/forked chain using the same genesis/account state, a user holding the same keys and permission setup on multiple chains can have a signature produced for one chain's contract call replayed verbatim on another chain's identical contract, exactly matching Scenario 1 in the external report.

## Impact Explanation
Any TVM contract relying on `validatemultisign` for authorization (multisig approvals, signature-gated mint/transfer/withdraw logic) without independently adding chain-specific or contract-specific entropy to `data` is exposed to replay: an attacker who captures a signature intended for use on one chain/instance can resubmit it on another chain/instance sharing the same account/permission state, causing unauthorized minting, transfers, or approvals to be replayed — a direct authorization/accounting impact.

## Likelihood Explanation
Exploitation requires: (1) a contract built on `validatemultisign` that does not itself embed chain/contract-domain separation in the signed `data`, and (2) the same account address + permission configuration existing/being reachable on more than one chain or fork. Given TRON's ecosystem includes mainnet plus multiple public testnets and forkable/private chains sharing identical account and permission semantics, and given that domain separation is *not* enforced by the precompile itself (only advisory, left to dApp developers), likelihood of at least one downstream contract being vulnerable is realistic, mirroring exactly why the original report flagged the missing domain separator as a real, fixable defect rather than theoretical.

## Recommendation
Extend the hash computed inside `ValidateMultiSign.execute()` to include chain-binding data, e.g. incorporate the network's `chainId`/genesis block hash (available via `CommonParameter`/`DynamicPropertiesStore`) into `combine` alongside `address`, `permissionId`, and `data`, similar to EIP-712's domain separator. At minimum, document prominently that `data` passed to `validatemultisign` MUST include chain-id and replay-protection nonces, and consider providing a standard helper/opcode that automatically mixes in `chainId` so downstream TVM contract authors cannot omit it by mistake.

## Proof of Concept
1. Deploy an identical TRC20/TRC721-style contract on two java-tron based chains (e.g., mainnet and a testnet, or two forks sharing genesis) that both use `validatemultisign` to gate a `mintBySignature`-like function, encoding only `(recipient, tokenId)` in `data` without chain id.
2. Alice's multisig account (same address, same `Permission`/keys on both chains) signs a mint authorization for Bob on chain A: `hash = sha256(address || permissionId || data)`, satisfying the permission threshold via `TransactionCapsule.getWeight` checks in `ValidateMultiSign.execute()`.
3. Bob submits the same signature bytes to the identical contract on chain B. Because `hash` is chain-agnostic and `account`/`permission` state matches, `ValidateMultiSign` returns `dataOne()` (success) again on chain B, letting Bob replay the same mint authorization to mint an additional token there.   public static class ValidateMultiSign extends PrecompiledContract {

    private static final int ENGERYPERSIGN = 1500;
    private static final int MAX_SIZE = 5;
    private static final int ABI_HEADER_WORDS = 5;
    private static final int ABI_ITEM_WORDS = 5;


    @Override
    public long getEnergyForData(byte[] data) {
      long cnt = (data.length / WORD_SIZE - 5) / 5;
      // one sign 1500, half of ecrecover
      return cnt * ENGERYPERSIGN;
    }

    @Override
    public Pair<Boolean, byte[]> execute(byte[] rawData) {
      if (VMConfig.allowTvmOsaka()
          && !isValidAbiEncoding(rawData, ABI_HEADER_WORDS, ABI_ITEM_WORDS)) {
        return Pair.of(false, EMPTY_BYTE_ARRAY);
      }
      DataWord[] words = DataWord.parseArray(rawData);
      byte[] address = words[0].toTronAddress();
      int permissionId = words[1].intValueSafe();
      byte[] data = words[2].getData();

      byte[] combine = ByteUtil.merge(address, ByteArray.fromInt(permissionId), data);
      byte[] hash = Sha256Hash.hash(CommonParameter
          .getInstance().isECKeyCryptoEngine(), combine);

      if (VMConfig.allowTvmSelfdestructRestriction()) {
        int sigArraySize = words[words[3].intValueSafe() / WORD_SIZE].intValueSafe();
        if (sigArraySize > MAX_SIZE) {
          return Pair.of(true, DATA_FALSE);
        }
      }
      byte[][] signatures = VMConfig.allowTvmSelfdestructRestriction() ?
          extractSigArray(words, words[3].intValueSafe() / WORD_SIZE, rawData) :
          extractBytesArray(words, words[3].intValueSafe() / WORD_SIZE, rawData);

      if (signatures.length == 0 || signatures.length > MAX_SIZE) {
        return Pair.of(true, DATA_FALSE);
      }

      AccountCapsule account = this.getDeposit().getAccount(address);
      if (account != null) {
        try {
          Permission permission = account.getPermissionById(permissionId);
          if (permission != null) {
            //calculate weight
            long totalWeight = 0L;
            List<byte[]> executedSignList = new ArrayList<>();
            for (byte[] sign : signatures) {
              byte[] recoveredAddr = recoverAddrBySign(sign, hash);

              sign = merge(recoveredAddr, sign);
              if (ByteArray.matrixContains(executedSignList, recoveredAddr)) {
                if (ByteArray.matrixContains(executedSignList, sign)) {
                  continue;
                }
                MUtil.checkCPUTime();
              }
              long weight = TransactionCapsule.getWeight(permission, recoveredAddr);
              if (weight == 0) {
                //incorrect sign
                return Pair.of(true, DATA_FALSE);
              }
              totalWeight += weight;
              executedSignList.add(sign);
              executedSignList.add(recoveredAddr);
            }

            if (totalWeight >= permission.getThreshold()) {
              return Pair.of(true, dataOne());
            }
          }
        } catch (Throwable t) {
          if (t instanceof OutOfTimeException) {
            throw t;
          }
          logger.info("ValidateMultiSign error:{}", t.getMessage());
        }
      }
      return Pair.of(true, DATA_FALSE);
    }
  }
