### Title
Unsandboxed AOT execution of attacker-controlled machine code compiled from a declared Sierra class - (File: `crates/blockifier/src/execution/native/entry_point_execution.rs`)

### Summary
The EspoCRM CVE involves an authenticated but unprivileged user uploading a crafted archive that is processed by the server and results in arbitrary PHP code execution. The structural analog in this codebase is Cairo Native: any unprivileged account can submit a `Declare` transaction with an attacker-crafted Sierra program; once compiled (via the sandboxed AOT compiler subprocess), the resulting native (AOT) machine code is loaded and *executed in-process*, unsandboxed, by the sequencer/batcher whenever the class is invoked — unlike the CASM path which always runs inside the safe Cairo VM interpreter.

### Finding Description
`Declare` transactions are reachable from any unprivileged sender: `DeclareTransaction::create` in `crates/starknet_api/src/executable_transaction.rs:201-212` only requires the Sierra program plus a valid hash/signature, and stateless validation (`crates/apollo_gateway/src/stateless_transaction_validator.rs:280-291`) checks size/version limits only.

When Cairo Native mode is enabled (`cairo_native_mode` != `Off`, see `crates/blockifier/src/blockifier/config.rs:256-261` and `apollo_node/resources/config_schema.json`), the class manager triggers compilation via `SierraToNativeCompiler::compile` (`crates/apollo_compile_to_native/src/compiler.rs:34-61`). This compilation step is process-isolated with CPU/memory/file-size limits (`ResourceLimits`, `apollo_compilation_utils/src/compiler_utils.rs`), similar to the Sierra→CASM path.

However, the *output* of this compilation — the `AotContractExecutor` — is then executed **directly in the sequencer/batcher/gateway process**, not in a sandboxed subprocess, by `native_entry_point_execution::execute_entry_point_call` in `crates/blockifier/src/execution/native/entry_point_execution.rs:23-77`, specifically the call `compiled_class.executor.run(...)` at line 60. This runs attacker-supplied AOT-compiled native machine code inline in-process, with only the Sierra/CASM libfunc allowlist (`allowed_libfuncs.json`) and the audited-libfuncs compiler flag as a safety boundary — a boundary that is a compile-time/type-system guarantee from the Cairo compiler, not a runtime sandbox around the resulting native code.

This mirrors the EspoCRM bug class precisely: a lower-privileged actor supplies input (Sierra "source", analogous to an uploaded zip) that is transformed by a trusted pipeline (native AOT compiler, analogous to the update/extraction routine) into an executable artifact that is then run with the full privileges of the processing service (the sequencer process), rather than in an isolated interpreter/sandbox as the CASM/VM path guarantees.

The `native_classes_whitelist` mechanism (`crates/blockifier/src/blockifier/config.rs:188-254`, `NativeClassesWhitelist::contains`) only gates *which* class hashes are permitted to run natively — it does not add any additional sandboxing/isolation around the native execution path itself; when `NativeClassesWhitelist::All` is configured (the schema default for some deployments), any declared class runs natively unconditionally.

### Impact Explanation
If the Cairo Native compiler (`cairo-native`/MLIR toolchain) or the generated machine code contains any bug that escapes the abstract-machine model it is supposed to emulate (memory-safety bug in generated code, a libfunc lowering bug, JIT/AOT codegen bug, etc.), a malicious declarer can exploit it to execute arbitrary native code with the privileges of the sequencer/batcher process. Because the batcher/gateway processes are the ones building blocks, computing state commitments, and running the transaction executor, code execution there can corrupt in-memory state, produce a wrong committed state root/block hash relative to honest nodes not running native execution (or running a different compiler version), or crash/hang the sequencer, i.e., contribute to network inability to confirm new transactions. This is qualitatively the same escalation path as the EspoCRM PHP RCE (crafted "uploaded" artifact → code execution in the trusted service), scaled to a blockchain sequencer's honest-node consensus guarantees.

### Likelihood Explanation
Reaching this code path requires only sending a standard, unprivileged `Declare` transaction; no special role or node cooperation is needed. The likelihood of the attack succeeding depends entirely on whether the Cairo Native compiler/runtime (an external, actively-developed component `cairo_native::executor::AotContractExecutor`) has an exploitable codegen or memory-safety bug for some crafted Sierra input — this is plausible given the complexity of AOT-compiling an interpreted intermediate language to native code, and is exactly the class of risk that led to `only-native`/whitelisting features and the resource-limited *compilation* sandbox already present. The compilation-time sandbox does not protect against the compiled artifact itself misbehaving at run time, which is the actual gap.

### Recommendation
- Treat native-compiled contract execution as untrusted code execution: run `AotContractExecutor::run` inside a process-level sandbox (seccomp/gVisor/separate worker process with restricted syscalls) rather than in the sequencer/batcher's main process, mirroring the isolation already applied to the *compiler* subprocess.
- Ensure `native_classes_whitelist` defaults to a conservative, explicitly-curated list rather than `All` in production configurations, and require additional auditing before adding classes.
- Add fuzzing/differential-testing between CASM (Cairo VM) execution and native execution outputs for a wide corpus of adversarial Sierra programs to catch codegen divergence or unsafety before enabling native execution broadly.
- Consider maintaining `only-native` off by default and always falling back to a memory-safe interpreter path unless the operator has fully vetted the native toolchain version in use.

### Proof of Concept
1. An unprivileged account submits a `Declare` (V3) transaction whose Sierra program is engineered to trigger a memory-safety or code-generation bug in the `cairo-native` AOT backend for the configured compiler version (e.g., an edge case in libfunc lowering, out-of-bounds array/segment handling, or builtin-cost miscalculation) — such Sierra can still validate against `allowed_libfuncs.json` and the stateless Sierra-version/size checks in `stateless_transaction_validator.rs`.
2. The declare is accepted by the gateway/class manager; if `cairo_native_mode` is `WaitOnCompilation`/`LazyCompilation` and the class hash is in the effective `native_classes_whitelist`, `SierraToNativeCompiler::compile` produces an `AotContractExecutor` (`apollo_compile_to_native/src/compiler.rs:34-61`).
3. Any subsequent `Invoke` transaction that calls into this class triggers `native_entry_point_execution::execute_entry_point_call` (`crates/blockifier/src/execution/native/entry_point_execution.rs:60`), running `compiled_class.executor.run(...)` in-process.
4. If the crafted Sierra triggers the targeted native-codegen bug, the resulting memory corruption/native-code execution happens with the full privileges of the sequencer/batcher process — analogous to the EspoCRM crafted-zip-to-RCE chain.

Note: I could not directly inspect the internal implementation of `cairo_native::executor::AotContractExecutor::run` (external crate) to confirm a specific concrete memory-safety bug; this analysis establishes the reachable, unsandboxed-execution architecture as the root cause and structural analog, not a proven concrete exploit primitive inside `cairo-native` itself.     pub fn ser_param(&self) -> (String, SerializedParam) {
        ser_param(
            "native_classes_whitelist",
            &self,
            Self::SER_PARAM_DESCRIPTION,
            ParamPrivacyInput::Public,
        )
    }
}

impl<'de> Deserialize<'de> for NativeClassesWhitelist {
    fn deserialize<D>(deserializer: D) -> Result<Self, D::Error>
    where
        D: Deserializer<'de>,
    {
        let raw: String = <String as serde::Deserialize>::deserialize(deserializer)?;

        if raw == "All" {
            return Ok(NativeClassesWhitelist::All);
        }
        // Support stringified JSON array: "[\"0x..\", \"0x..\"]"
        match serde_json::from_str::<Vec<ClassHash>>(&raw) {
            Ok(vec) => Ok(NativeClassesWhitelist::Limited(vec)),
            Err(_) => Err(de::Error::custom(format!(
                "invalid native_classes_whitelist string: expected \"All\" or stringified JSON \
                 array, (i.e., \"[\\\"0x..\\\", \\\"0x..\\\"]\") got: {}",
                raw
            ))),
        }
    }
}

impl Serialize for NativeClassesWhitelist {
    fn serialize<S>(&self, serializer: S) -> Result<S::Ok, S::Error>
    where
        S: Serializer,
    {
        match self {
            NativeClassesWhitelist::All => serializer.serialize_str("All"),
            NativeClassesWhitelist::Limited(vec) => {
                let json = serde_json::to_string(vec)
                    .expect("Failed to stringify whitelist to JSON array");
                serializer.serialize_str(&json)
            }
        }
    }
}

impl NativeClassesWhitelist {
    pub fn contains(&self, class_hash: &ClassHash) -> bool {
        match self {
            NativeClassesWhitelist::All => true,
            NativeClassesWhitelist::Limited(contracts) => contracts.contains(class_hash),
        }
    }
}

    pub fn compile(
        &self,

    ) -> Result<AotContractExecutor, CompilationUtilError> {
        let compiler_binary_path = &self.path_to_binary;

        let output_file = NamedTempFile::new()?;

        let resource_limits = ResourceLimits::new(

            self.config.max_file_size,
            Some(self.config.max_memory_usage),
        );
        let _stdout = compile_with_args(
            compiler_binary_path,
            contract_class,
            &additional_args,
            resource_limits,
        )?;

        Ok(AotContractExecutor::from_path(output_file.path())
            .map_err(|e| CompilationUtilError::CompilationError(e.to_string()))?
            .unwrap())
    }

pub fn execute_entry_point_call(
    call: ExecutableCallEntryPoint,
    compiled_class: NativeCompiledClassV1,
    state: &mut dyn State,
    context: &mut EntryPointExecutionContext,
) -> Result<CallInfo, EntryPointExecutionError> {
    let entry_point = compiled_class
        .get_entry_point(&call.type_and_selector())
        .map_err(EntryPointExecutionError::from)?;

    let mut syscall_handler: NativeSyscallHandler<'_> =
        NativeSyscallHandler::new(call, state, context);

    let gas_costs = &syscall_handler.base.context.gas_costs();
    let builtin_costs = BuiltinCosts {
        // todo(rodrigo): Unsure of what value `const` means, but 1 is the right value.
        r#const: 1,
        pedersen: gas_costs.builtins.pedersen,
        bitwise: gas_costs.builtins.bitwise,
        ecop: gas_costs.builtins.ecop,
        poseidon: gas_costs.builtins.poseidon,
        add_mod: gas_costs.builtins.add_mod,
        mul_mod: gas_costs.builtins.mul_mod,
        blake: gas_costs.builtins.blake,
    };

    // Pre-charge entry point's initial budget to ensure sufficient gas for executing a minimal
    // entry point code. When redepositing is used, the entry point is aware of this pre-charge
    // and adjusts the gas counter accordingly if a smaller amount of gas is required.
    let initial_budget = syscall_handler.base.context.gas_costs().base.entry_point_initial_budget;
    let call_initial_gas = syscall_handler
        .base
        .call
        .initial_gas
        .checked_sub(initial_budget)
        .ok_or(PreExecutionError::InsufficientEntryPointGas)?;

    let execution_result = compiled_class.executor.run(
        entry_point.selector.0,
        &syscall_handler.base.call.calldata.0.clone(),
        call_initial_gas,
        Some(builtin_costs),
        &mut syscall_handler,
    );

    syscall_handler.finalize();

    let call_result = execution_result.map_err(EntryPointExecutionError::NativeUnexpectedError)?;

    if let Some(error) = syscall_handler.unrecoverable_error {
        return Err(EntryPointExecutionError::NativeUnrecoverableError(Box::new(error)));
    }

    create_callinfo(call_result, syscall_handler)
}

    pub fn get_runnable(

        native_classes_whitelist: &NativeClassesWhitelist,

        let cached_class = self.class_cache.get(class_hash)?;
        if let CompiledClasses::V1(..) = cached_class {
            // When native mode is WaitOnCompilation, all V1 classes should have been
            // compiled to native synchronously. A V1 cache entry indicates a pipeline bug.
            assert_ne!(
                self.cairo_native_mode(),
                CairoNativeMode::WaitOnCompilation,
                "Manager did not wait on native compilation."
            );
        }

        let cached_class = match cached_class {
            CompiledClasses::V1Native(CachedCairoNative::Compiled(native))
                if !native_classes_whitelist.contains(class_hash) =>
            {
                CompiledClasses::into_non_native_class(native)
            }
            CompiledClasses::V1Native(..) | CompiledClasses::V1(..) | CompiledClasses::V0(..) => {
                cached_class
            }
        };

        Some(cached_class.to_runnable())
    }
