### Title
Global Contract Storage Fee Burned in Full on Every Re-Deploy Without Checking Existing Storage — (File: `runtime/runtime/src/global_contracts.rs`)

### Summary

`action_deploy_global_contract` unconditionally burns `global_contract_storage_amount_per_byte × code.len()` from the deployer's balance on every invocation, with no check whether the target trie key already holds a contract. For `AccountId`-mode re-deploys the deployer pays the full storage burn again for a slot already occupied; for `CodeHash`-mode, every account that deploys identical code pays the full burn for a single shared storage entry. The burned tokens are irrecoverable.

### Finding Description

In `runtime/runtime/src/global_contracts.rs`, `action_deploy_global_contract` computes and burns the storage cost unconditionally:

```rust
let storage_cost = apply_state
    .config.fees.storage_usage_config
    .global_contract_storage_amount_per_byte
    .saturating_mul(deploy_contract.code.len() as u128);
let Some(updated_balance) = account.amount().checked_sub(storage_cost) else { … };
result.tokens_burnt =
    result.tokens_burnt.checked_add(storage_cost).ok_or(IntegerOverflowError)?;
account.set_amount(updated_balance);
``` [1](#0-0) 

There is no read of `TrieKey::GlobalContractCode { identifier }` before charging. The function then calls `initiate_distribution`, which increments the per-identifier nonce and emits a fresh `GlobalContractDistributionReceipt` regardless of whether the code was already stored. [2](#0-1) 

**`AccountId` mode** — the trie key is `GlobalContractCode { AccountId(deployer) }`. A re-deploy overwrites the existing entry with new code, but the storage burn for the old code is not refunded and the new storage burn is charged in full. The deployer pays `storage_cost` on every upgrade.

**`CodeHash` mode** — the trie key is `GlobalContractCode { CodeHash(H) }`. Multiple accounts deploying the same code (same hash `H`) each pay `global_contract_storage_amount_per_byte × code.len()`, but `apply_distribution_current_shard` writes the code to the same trie key each time:

```rust
state_update.set(trie_key, global_contract_data.code().to_vec());
``` [3](#0-2) 

The nonce check (`check_and_update_nonce`) only prevents *stale* (lower-nonce) receipts from overwriting newer ones; it does not prevent a second account from paying for storage that is already occupied. [4](#0-3) 

The `global_contract_storage_amount_per_byte` parameter lives in `StorageUsageConfig` alongside `storage_amount_per_byte` for regular storage, confirming it is intended as a one-time storage cost, not a per-deploy distribution fee (which is already covered by the gas fees `action_deploy_global_contract` and `action_deploy_global_contract_per_byte`). [5](#0-4) 

The mainnet value is `0.0001 N/byte` (set in `77.yaml`): [6](#0-5) 

### Impact Explanation

The deployer's balance is permanently reduced by `global_contract_storage_amount_per_byte × code.len()` on every deploy, even when no new storage is consumed. At `0.0001 N/byte`:

- A 1 MB contract costs **100 N** per deploy call.
- A 4 MB contract (protocol maximum) costs **400 N** per deploy call.

An account that upgrades its `AccountId`-mode global contract `N` times loses `N × storage_cost` in burned tokens beyond what the actual storage requires. For `CodeHash` mode, `K` accounts deploying the same code collectively lose `(K−1) × storage_cost` in excess burned tokens. The burned tokens reduce total supply and are irrecoverable by the deployer. This constitutes a direct, unprivileged-user-triggered loss of funds.

### Likelihood Explanation

`AccountId`-mode re-deploys are the standard contract upgrade pattern for global contracts. Any account that upgrades its global contract triggers the over-charge. `CodeHash`-mode over-charging requires multiple accounts to deploy identical code, which is realistic for shared library contracts. Both paths are reachable by ordinary user-submitted transactions with no privileged assumptions.

### Recommendation

Before charging the storage cost, check whether the contract already exists in state. For `AccountId` mode, read the existing code length and charge only the delta (new cost minus already-paid cost). For `CodeHash` mode, skip the storage burn entirely if the key already exists:

```rust
let trie_key = TrieKey::GlobalContractCode { identifier: id.clone().into() };
let already_exists = state_update.contains_key(&trie_key, AccessOptions::DEFAULT)?;
if !already_exists {
    // charge and burn storage_cost
}
```

For `AccountId` mode with code size changes, read the old code length from state and charge only `max(0, new_cost − old_cost)`.

### Proof of Concept

**`AccountId` mode (re-deploy over-charge):**

1. `alice.near` deploys a 1 MB global contract in `AccountId` mode. `action_deploy_global_contract` burns 100 N from Alice's balance. Code stored at `GlobalContractCode { AccountId("alice.near") }`.
2. Alice re-deploys (upgrades) the same or a different 1 MB contract. `action_deploy_global_contract` burns another 100 N from Alice's balance. The old code is overwritten.
3. Alice's balance is reduced by 200 N total, but only 100 N worth of storage is occupied at any point. The first 100 N burn is wasted.
4. After `N` upgrades, Alice has lost `N × 100 N` in excess burned tokens.

**`CodeHash` mode (shared-code over-charge):**

1. Account A deploys code X (1 MB, hash H) in `CodeHash` mode. Burns 100 N from A. Code stored at `GlobalContractCode { CodeHash(H) }`.
2. Account B deploys the same code X (hash H). Burns 100 N from B. `apply_distribution_current_shard` overwrites `GlobalContractCode { CodeHash(H) }` with identical data.
3. Total burned: 200 N. Actual storage occupied: one 1 MB slot (100 N worth). Excess burned: 100 N.
4. With `K` accounts deploying the same code, excess burned = `(K−1) × 100 N`.

    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())

    // Increment the nonce and write it to state immediately to prevent multiple

fn check_and_update_nonce(
    global_contract_data: &GlobalContractDistributionReceipt,
    identifier: &GlobalContractCodeIdentifier,
    state_update: &mut TrieUpdate,
) -> Result<bool, RuntimeError> {
    let nonce_key = TrieKey::GlobalContractNonce { identifier: identifier.clone() };
    let stored_nonce = get_nonce(state_update, &nonce_key)?;
    let incoming_nonce = global_contract_data.nonce();

    // Allow the same nonce since the nonce is updated immediately when
    // initiating distribution to prevent multiple distributions with the same
    // nonce from being initiated.
    if incoming_nonce < stored_nonce {
        return Ok(false);
    }

    set_nonce(state_update, nonce_key, incoming_nonce);
    Ok(true)
}
```
