### Title
Path/query injection into embedded app URL via `sanitizeHost` hostname-only validation - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost` only validates the `hostname` component of `new URL('https://' + decodeHost(host))`, ignoring any path/query/fragment present in the decoded string. `buildEmbeddedAppUrl` then re-decodes the raw `host` and splices the *entire* decoded string verbatim into a template literal, so an attacker-controlled path/query suffix survives validation and is injected into the resulting embedded-app URL, which is then used as a redirect target.

### Finding Description
`sanitizeHost` (`packages/apps/shopify-api/lib/utils/shop-validator.ts:52-91`) does:
```
const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);
```
and only checks `hostname` against `\.(myshopify\.com|...)$`. It never checks that the decoded string is *only* a hostname — it can also contain a path, query, or fragment.

`buildEmbeddedAppUrl` (`packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts:44-52`) does:
```
sanitizeHost(config)(host, true);
const decodedHost = decodeHost(host);
return `https://${decodedHost}/apps/${config.apiKey}`;
```
It calls `sanitizeHost` only for its side effect (throwing on invalid), discards the validated `hostname`, and instead re-decodes the raw base64 `host` again, using the **full raw decoded string** (not the parsed `hostname`) in the URL template.

Attacker flow: the `host` query parameter is fully attacker-controlled and unauthenticated (no HMAC required for this param on this code path — `getEmbeddedAppUrl`/`buildEmbeddedAppUrl` do not validate an HMAC or signed context). An attacker crafts `host = base64("victim.myshopify.com/../../evil?x=1")`. `new URL('https://victim.myshopify.com/../../evil?x=1').hostname` is `victim.myshopify.com`, which passes the `.myshopify.com$` regex, so `sanitizeHost` treats it as valid. But `decodedHost` used in the final template is the raw string `victim.myshopify.com/../../evil?x=1`, producing:
```
https://victim.myshopify.com/../../evil?x=1/apps/<apiKey>
```
This injects attacker-controlled path/query content into a URL string that downstream code (e.g. `redirectToShopifyOrAppRoot` in `packages/apps/shopify-app-express/src/middlewares/redirect-to-shopify-or-app-root.ts:22-36`) passes directly to `res.redirect(redirectUrl)`.

### Impact Explanation
This is a URL-construction/injection flaw in the embedded-app redirect helper. Because `..` segments and query strings are attacker-controlled inside a string that is used as a redirect `Location`, an attacker can manipulate the resulting redirect path (e.g., pointing to a different path/query on the same host, or appending arbitrary content). This falls short of a cross-origin open redirect in the classic sense (the `@`-based host confusion the question suggested does not work, since `new URL` would move `attacker.com` into `hostname` and fail the origin check), but it is a real allowlist-bypass bug: `sanitizeHost` validates one string while a *different, unvalidated* raw string is what actually gets embedded in the URL, breaking the intended "hostname must end in an allowed Shopify domain" invariant for the final URL content.

### Likelihood Explanation
Trivially reachable by any unauthenticated caller who can set the `host` query parameter on any endpoint that calls `getEmbeddedAppUrl`/`redirectToShopifyOrAppRoot` (e.g., after OAuth/install flow redirects). No secret, session, or privileged role is required — just base64-encoding a crafted string.

### Recommendation
In `buildEmbeddedAppUrl`, use the already-validated `hostname` from `sanitizeHost`'s internal `URL` parse (or re-parse `decodedHost` and use only `.hostname`) instead of splicing the raw decoded string into the template. Alternatively, harden `sanitizeHost` to reject decoded host strings containing `/`, `?`, or `#` characters outright (i.e., require the decoded value to equal the parsed `hostname` exactly).

### Proof of Concept
```ts
import {buildEmbeddedAppUrl} from '../get-embedded-app-url';
// host = base64("victim.myshopify.com/../../evil?x=1")
const host = Buffer.from('victim.myshopify.com/../../evil?x=1').toString('base64');
const url = buildEmbeddedAppUrl(testConfig)(host);
// Fails safety expectation: contains attacker-controlled path/query segments
expect(url).not.toMatch(/evil/);
```

export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }

    return sanitizedHost;
  };
}

export function buildEmbeddedAppUrl(
  config: ConfigInterface,
): BuildEmbeddedAppUrl {
  return (host: string): string => {
    sanitizeHost(config)(host, true);
    const decodedHost = decodeHost(host);

    return `https://${decodedHost}/apps/${config.apiKey}`;
  };
