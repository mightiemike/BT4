Confirmed: `L1GasPriceProvider` selects each feed's oracle client via `ExchangeRateOracleSource` in config, and `build_exchange_rate_oracle_client` chooses between the on-chain `ChainlinkOracleClient` (fully validated) and the HTTP-based `ExchangeRateOracleClient` (missing bounds/staleness validation) per feed [1](#0-0) .

### Title
Missing sanity/staleness validation of HTTP exchange-rate oracle response allows a manipulated or stale ETH/STRK price to be committed into block info - (File: `crates/apollo_l1_gas_price/src/exchange_rate_oracle.rs`)

### Summary
`ExchangeRateOracleClient::fetch_rate` resolves each HTTP response through `resolve_query`, which only checks that the JSON parses, that `price` is present and non-zero, and that `decimals` equals `EXCHANGE_RATE_DECIMALS` [2](#0-1) . Unlike the on-chain Chainlink path, this HTTP path never validates the returned price's freshness or plausibility against sane bounds.

### Finding Description
The on-chain Chainlink oracle client (`read_feed`) treats a feed's answer as untrusted external data and applies three independent guards before it is used: a non-zero-answer check, a staleness check (`updated_at` vs block timestamp), a future-dated check, and finally an absolute sanity-bounds check via `check_rate_bounds` [3](#0-2) . The `rate_bounds.rs` comment explicitly states these absolute bounds exist because "consensus checks that validators agree with each other, never that the agreed value is sane" [4](#0-3) .

The HTTP-based `ExchangeRateOracleClient`, selectable as an alternative `ExchangeRateOracleSource` for either the ETH/STRK or STRK/USD feed [5](#0-4) , has none of these guards: `resolve_query` never inspects any timestamp in the API's own response, never bounds the parsed `rate` against a sane minimum/maximum, and never calls `check_rate_bounds` [2](#0-1) . The only "freshness" mechanism is the client requesting a `timestamp` query parameter and quantizing/caching by that requested timestamp [6](#0-5)  — nothing forces the server to honor that parameter or return data actually dated to it, and the client performs no independent check on the response.

This directly mirrors the reported bug class ("Missing validations for return value of oracle data feed" / missing `updatedAt` check): the return value of an external price source is consumed with no freshness or bounds validation, only a superficial format check.

### Impact Explanation
The fetched rate feeds `get_l1_prices_in_fri_and_wei_and_conversion_rate` in the consensus orchestrator, which converts L1 gas prices from wei to FRI and is embedded into `ConsensusBlockInfo`/`ProposalInit`, ultimately used to build the committed block's gas-price fields [7](#0-6) . A stale or implausible rate (accepted because no staleness/bounds check exists) can:
- Cause incorrect fee accounting for every transaction in the block (wrong `l1_gas_price_fri`/`l2_gas_price_wei` derived via `calculate_eth_to_fri_rate` and `fri_to_wei`) [8](#0-7) .
- Because different sequencer nodes independently poll the HTTP endpoint(s) (`url_header_list`, potentially multiple distinct URLs with failover) with no shared source-of-truth check, a validator computing/validating a proposal could accept or reject differently from the proposer if it queried a different or staler oracle answer that any bounds/staleness check would otherwise have normalized or rejected — this can lead to honest-node divergence on the committed block's gas-price fields.

### Likelihood Explanation
Likelihood is moderate: the HTTP oracle client is only exercised when `ExchangeRateOracleSource` is configured to use the HTTP-based client rather than the on-chain Chainlink client; I could not fully confirm from the index which source is the deployed default. The vulnerable code path is exercised on every price fetch when that configuration branch is active, without requiring any special privilege from a transaction sender — it is purely a gap in server-response validation on a path already reachable by ordinary block-building/proposal flow.

### Recommendation
Apply the same guards used for the Chainlink path to the HTTP oracle response in `resolve_query`/`fetch_rate`:
- Require the API response to include an explicit `updated_at`/timestamp field and validate it against the requested/block timestamp with the same staleness and future-dated checks used in `read_feed` [9](#0-8) .
- Apply `check_rate_bounds` (or equivalent absolute sanity bounds) to the parsed `rate` in `resolve_query` before returning/caching it, matching `rate_bounds.rs` [10](#0-9) .

### Proof of Concept
1. Configure `ExchangeRateOracleSource` to use the HTTP-based `ExchangeRateOracleClient` for the ETH/STRK or STRK/USD feed.
2. Have the configured URL (or a compromised/misbehaving endpoint reachable via the configured `url_header_list`) return `{"price": "0x<attacker-chosen-hex>", "decimals": 18}` — any non-zero value passes `resolve_query` regardless of how stale or implausible it is [11](#0-10) .
3. This value is cached and returned by `fetch_rate` for the requested quantized timestamp with no independent staleness or bounds check, then flows into `eth_to_fri_rate` / `get_l1_prices_in_fri_and_wei_and_conversion_rate`, directly affecting the FRI gas prices committed into the block's `ConsensusBlockInfo`.

Note: I was unable to verify from the indexed code which `ExchangeRateOracleSource` (Chainlink vs HTTP) is the actual production default, since the config selection logic in `apollo_l1_gas_price_config/src/config.rs` was only partially retrieved. If the HTTP client is not the deployed default/is disabled entirely in production, likelihood should be reassessed downward.

fn resolve_query(
    body: String,
    metrics: &ExchangeRateOracleMetrics,
) -> Result<ExchangeRate, ExchangeRateOracleClientError> {
    let Ok(json): Result<serde_json::Value, _> = serde_json::from_str(&body) else {
        return Err(ExchangeRateOracleClientError::ParseError(format!(
            "Failed to parse JSON: {body}"
        )));
    };
    // Extract price from API response. Also returns MissingFieldError if value is not a string.
    let price = match json.get("price").and_then(|v| v.as_str()) {
        Some(price) => price,
        None => {
            return Err(ExchangeRateOracleClientError::MissingFieldError(
                "price".to_string(),
                body,
            ));
        }
    };
    let rate = u128::from_str_radix(price.trim_start_matches("0x"), 16).map_err(|e| {
        ExchangeRateOracleClientError::ParseError(format!("Failed to parse price {price}: {e}"))
    })?;
    if rate == 0 {
        return Err(ExchangeRateOracleClientError::InvalidRateError(
            "rate must be non-zero".to_string(),
        ));
    }
    let decimals = match json
        .get("decimals")
        .and_then(|value| value.as_u64())
        .and_then(|value| u32::try_from(value).ok())
    {
        Some(decimals) => decimals,
        None => {
            return Err(ExchangeRateOracleClientError::MissingFieldError(
                "decimals".to_string(),
                body,
            ));
        }
    };
    if decimals != EXCHANGE_RATE_DECIMALS {
        return Err(ExchangeRateOracleClientError::InvalidDecimalsError(
            EXCHANGE_RATE_DECIMALS,
            decimals,
        ));
    }
    metrics.record_success(rate);
    Ok(rate)
}

pub(crate) fn check_rate_bounds(
    rate: ExchangeRate,
    bounds: RateBounds,
) -> Result<(), ExchangeRateOracleClientError> {
    if rate < bounds.minimum_rate || rate > bounds.maximum_rate {
        return Err(ExchangeRateOracleClientError::RateOutOfBoundsError {
            pair: bounds.pair,
            rate,
            min_rate: bounds.minimum_rate,
            max_rate: bounds.maximum_rate,
        });
    }
    Ok(())
}
