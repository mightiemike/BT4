## Finding: Unhandled exception (DoS) in `decodeHost` via malformed `host` query parameter

### Title
Unvalidated base64 length allows `atob()` to throw an uncaught exception in `decodeHost`, crashing auth/embedded-URL handlers - (`packages/apps/shopify-api/lib/auth/decode-host.ts`)

### Summary
`decodeHost` decodes the `host` query parameter using the browser/runtime `atob()` primitive without any error handling [1](#0-0) . The only gate in front of it, `sanitizeHost`, validates the `host` string with a regex that only checks the allowed base64 *character set* and optional `=` padding, but never validates that the string has base64-conformant length/padding: `^[0-9a-zA-Z+/]+={0,2}$` [2](#0-1) . This mirrors the CVE-2020-35909 bug class: a decode function that is expected to fail gracefully on malformed input instead throws an unexpected, unhandled exception.

### Finding Description
`buildEmbeddedAppUrl` calls `sanitizeHost(config)(host, true)` and then unconditionally calls `decodeHost(host)` right after, with no try/catch around either call: [3](#0-2) 

`sanitizeHost` itself also calls `decodeHost` directly inside its own validation logic to build a `URL`, again without a try/catch: [4](#0-3) 

Because the regex `^[0-9a-zA-Z+/]+={0,2}$` only restricts the character set, a caller can supply a syntactically "valid-looking" base64 string whose length is not a proper multiple of 4 (e.g. a single character like `"A"`, or any string of length `4k+1`). In strict `atob()` implementations (the WHATWG/browser `atob`, and some polyfills used for non-Node runtimes such as Cloudflare Workers), such input causes `atob` to throw `InvalidCharacterError`/`DOMException` synchronously rather than returning an empty/garbage value. Since neither `sanitizeHost` nor `buildEmbeddedAppUrl`/`getEmbeddedAppUrl` wrap the `atob` call in error handling, this exception propagates uncaught out of the auth/embedded-URL helper.

`host` is an anonymous, attacker-controlled query parameter read directly from the incoming request URL in `getEmbeddedAppUrl`: [5](#0-4) 

This function, along with `sanitizeHost`, is invoked from framework-level auth/redirect helpers such as `validate-shop-and-host-params.ts` and `redirect-to-shopify-or-app-root.ts` in the Express/Remix/React Router packages, all of which run before any session/HMAC check — i.e., reachable by any anonymous HTTP request that includes a `host` parameter.

### Impact Explanation
An anonymous request with a crafted `host` query parameter (base64-alphabet characters but wrong length/padding) reaches `sanitizeHost`/`decodeHost` before authentication is established. If the runtime's `atob` throws on malformed input (as browser/WHATWG-compliant polyfills do), the exception is unhandled by the library code, causing the request-handling middleware/loader to fail with an unhandled promise rejection/exception. Depending on the framework's top-level error handling, this can manifest as repeated 500s or process-level crashes when triggered at scale — a denial-of-service against the app's authentication entry points (`/auth`, embedded-app redirect handlers).

### Likelihood Explanation
Likelihood is dependent on the JS runtime's `atob` implementation being strict about base64 padding (true for the WHATWG `atob` spec and most non-Node polyfills; Node's own `Buffer`-based decode is comparatively lenient). Because `host` is a plain, unauthenticated query parameter checked only by a loose regex, exploitation requires no privileges, secrets, or prior session — only sending a single crafted GET request to the auth/embedded-app-url endpoints.

### Recommendation
Wrap `atob(host)` in `decodeHost` (and its call sites in `sanitizeHost`/`buildEmbeddedAppUrl`) with a try/catch, returning `null`/throwing the existing `InvalidHostError` on failure instead of letting the underlying `DOMException`/`InvalidCharacterError` propagate. Additionally, tighten the `base64regex` in `sanitizeHost` to enforce a length that is a multiple of 4 with correct padding placement, rather than only validating the character set.

### Proof of Concept
1. Send `GET /auth?shop=test-shop.myshopify.com&host=A` (or any base64-alphabet string whose length mod 4 is 1, e.g. `"A"`, `"ABCDE"`) to an app route that calls `getEmbeddedAppUrl`/`buildEmbeddedAppUrl` or `sanitizeHost` (e.g. `redirect-to-shopify-or-app-root.ts`, `validate-shop-and-host-params.ts`).
2. `sanitizeHost` regex `^[0-9a-zA-Z+/]+={0,2}$` matches `"A"`, so it proceeds to call `decodeHost("A")`, i.e. `atob("A")`.
3. On runtimes with a strict/WHATWG-compliant `atob`, this throws `InvalidCharacterError`/`DOMException`, which is not caught anywhere in `sanitizeHost` or `getEmbeddedAppUrl`/`buildEmbeddedAppUrl`, resulting in an unhandled exception in the request path.
