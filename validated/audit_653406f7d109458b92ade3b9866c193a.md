### Title
`h.savedCallbacks` map keyed by attacker-controlled `MessageId` allows response hijacking/denial via collision - (File: core/services/gateway/handlers/capabilities/handler.go)

### Summary
`HandleLegacyUserMessage` stores each user's callback in the shared map `h.savedCallbacks` keyed solely by `msg.Body.MessageId`, a value that originates directly from the client-supplied JSON-RPC request `ID` with no per-requester namespacing or uniqueness check. An unauthenticated attacker can submit a `web_api_trigger` request with the same `MessageId` as a victim's in-flight request, silently overwriting the victim's stored callback and causing the eventual node response to be delivered to the attacker instead of the victim (or lost entirely).

### Finding Description
The JSON-RPC request `ID` is taken as-is from the untrusted HTTP request and propagated into `msg.Body.MessageId` in `gateway.ProcessRequest` (`core/services/gateway/gateway.go`, `jsonRequest.ID` -> `msg.Body.MessageId` via `codec.DecodeJSONRequest`), with the only guard being a length check (`len(jsonRequest.ID) > 200`). [1](#0-0) 

`HandleLegacyUserMessage` then unconditionally assigns into the shared map without checking for an existing entry: [2](#0-1) 

The comment directly above this code path confirms no allowlist or rate-limiting is enforced to prevent this kind of abuse: [3](#0-2) 

When a node later responds, `handleWebAPITriggerMessage` looks up and deletes the callback purely by `MessageId`, and delivers the first response received to whatever callback is currently stored under that key: [4](#0-3) 

Exploit flow: victim sends a `web_api_trigger` request with `MessageId = X`; the gateway stores `savedCallbacks[X] = victimCallback` and forwards the request to all DON members. Before the node responds, the attacker sends a second `web_api_trigger` request also using `MessageId = X`; the gateway overwrites `savedCallbacks[X] = attackerCallback` and forwards the attacker's request to the DON members as well. When a node responds with `MessageId = X` (whichever request it happens to process/respond to first), `handleWebAPITriggerMessage` looks up `savedCallbacks[X]`, finds the attacker's callback (since it was inserted last), deletes the entry, and calls `attackerCallback.SendResponse(...)`. The victim's `callback.Wait(ctx)` in `gateway.ProcessRequest` will then time out (denial) since its entry was deleted/replaced, or in a race where the node responds to the victim's own request but the map already holds the attacker's callback, the victim's response payload is delivered to the attacker (hijack/disclosure of response body).

No existing check stops this: there is no per-session/per-requester binding of `MessageId`, no signature check tying the ID to a session, and no uniqueness enforcement before overwriting the map entry.

### Impact Explanation
This enables cross-request response confusion for the `web_api_trigger` legacy Gateway path: an unauthenticated attacker can cause denial of service (victim requests time out) or hijack another user's response payload by choosing a colliding `MessageId`. This matches Chainlink bounty impact categories for "misreporting/data tampering" or availability impact on gateway-mediated workflow trigger responses, since response payloads reaching the wrong party can leak trigger execution results intended for another caller.

### Likelihood Explanation
Highly feasible: `MessageId` is fully attacker-controlled (only constrained to ≤200 chars), requires no authentication, and the race window is only the round-trip time to the DON nodes and back (up to `CallbackMaxAgeSec`, default 120s), which is easily exploitable by an attacker who can predict or observe a victim's chosen `MessageId` (e.g., low-entropy or application-generated sequential IDs) or simply flood with a fixed/guessed ID to win common races. The explicit `TODO: apply allowlist and rate-limiting here` comment confirms this is a known, unaddressed gap.

### Recommendation
Namespace `savedCallbacks` keys by a value the gateway itself controls and that is unique per accepted user request (e.g., combine `MessageId` with a server-generated nonce/session identifier, or use a monotonically-generated internal key returned to the caller), and reject/collide-detect before insertion — e.g., check `if _, exists := h.savedCallbacks[msg.Body.MessageId]; exists { return error }` under the lock in `HandleLegacyUserMessage`, so a colliding `MessageId` is rejected rather than silently overwriting an in-flight callback.

### Proof of Concept
Unit test in `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` with a stubbed `handlers.DON` (`SendToNode` succeeding as no-op) and two mock `handlers.Callback` (`victimCb`, `attackerCb`), each recording whether `SendResponse` was invoked and with what payload.
2. Call `h.HandleLegacyUserMessage(ctx, msgWithID("X"), victimCb)`.
3. Call `h.HandleLegacyUserMessage(ctx, msgWithID("X"), attackerCb)` (same `MessageId`, before any node response is processed).
4. Assert `h.savedCallbacks["X"].Callback == attackerCb` (victim's callback silently dropped).
5. Invoke `h.handleWebAPITriggerMessage(ctx, nodeResponseMsgWithID("X"), nodeAddr)` once, simulating a single node response.
6. Assert `attackerCb.SendResponse` was called with the node's response payload, and `victimCb.SendResponse` was never called — demonstrating the victim's original request/response cycle is hijacked/dropped.

func (g *gateway) ProcessRequest(ctx context.Context, rawRequest []byte, auth string) (rawResponse []byte, httpStatusCode int) {
	// decode
	jsonRequest, err := jsonrpc2.DecodeRequest[json.RawMessage](rawRequest, auth)
	if err != nil {
		return newError("", api.UserMessageParseError, err.Error())
	}
	msg, err := g.codec.DecodeJSONRequest(jsonRequest)
	if err != nil {
		return newError(jsonRequest.ID, api.UserMessageParseError, err.Error())

		// Arbitrary limit to prevent abuse

	}

func (h *handler) handleWebAPITriggerMessage(ctx context.Context, msg *api.Message, nodeAddr string) error {
	h.mu.Lock()
	savedCb, found := h.savedCallbacks[msg.Body.MessageId]
	delete(h.savedCallbacks, msg.Body.MessageId)
	h.mu.Unlock()

	if found {
		// Send first response from a node back to the user, ignore any other ones.
		// TODO: in practice, we should wait for at least 2F+1 nodes to respond and then return an aggregated response
		// back to the user.
		codec := api.JsonRPCCodec{}
		return savedCb.SendResponse(handlers.UserCallbackPayload{RawResponse: codec.EncodeLegacyResponse(msg), ErrorCode: api.NoError})
	}
	return nil
}
