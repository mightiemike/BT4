## Title
Zero-sentinel ambiguity in `AccountCapsule.getWindowSize()`/`getWindowSizeV2()` causes wrong resource window fallback, mirroring the Twav zero-timestamp bug class — ([File: chainbase/src/main/java/org/tron/core/capsule/AccountCapsule.java])

### Summary
`AccountCapsule.getWindowSize()` and `getWindowSizeV2()` treat a stored `windowSize == 0` as a sentinel meaning "field never initialized" and silently substitute the default full-window value (`WINDOW_SIZE_MS / BLOCK_PRODUCED_INTERVAL`, i.e. 28800 slots / 24h). However, `windowSize` is also a value legitimately computed and persisted by `ResourceProcessor.getNewWindowSize()`, using plain truncating integer division, which can genuinely evaluate to `0`. When that happens, the next read of `getWindowSize()` mistakes the real computed value for "uninitialized" and substitutes the full default window instead — exactly the same "value that is both a sentinel and a legitimately-reachable state" bug class as the Nibbl `Twav._getTwav()` finding, where `timestamp` (used as an "initialized" sentinel) could legitimately equal `0` after modulo wraparound.

### Finding Description
`getWindowSize()`/`getWindowSizeV2()`: [1](#0-0) 

use `windowSize == 0` to detect "field never set" (legacy accounts predating the window-size feature) and fall back to the default full window. This is by design for backward compatibility, but the same field is also written by live arithmetic in `ResourceProcessor`: [2](#0-1) 

`newWindowSize` here is produced by `getNewWindowSize`, which — unlike the V2 counterpart — performs **plain truncating division**, not ceiling division: [3](#0-2) 

```java
private long getNewWindowSize(long lastUsage, long lastWindowSize, long usage,
    long windowSize, long newUsage) {
  ...
  return (lastUsage * lastWindowSize + usage * windowSize) / newUsage;
}
```

Because this is a floor division, whenever `numerator = lastUsage*lastWindowSize + usage*windowSize` is smaller than `newUsage` (a scenario that can arise from small `lastUsage`/`usage` relative to `newUsage`, particularly right after delegation/undelegation churn or near end-of-window recovery), the result truncates to exactly `0`. That `0` is then persisted via `accountCapsule.setNewWindowSize(resourceCode, newWindowSize)`: [4](#0-3) 

The V2 path (`increaseV2`) avoids this because `getNewWindowSize`'s V2 analog uses `divideCeilExact`/ceiling `divideCeil`, which never rounds a positive numerator down to `0`: [5](#0-4) [6](#0-5) 

So the vulnerable path is specifically the legacy (V1) `increase()`/`unDelegateIncrease()` flow — reachable when `supportUnfreezeDelay()` is enabled but `supportAllowCancelAllUnfreezeV2()` is not (a historically valid, committee-gated network configuration), or via `unDelegateIncrease`'s identical `getNewWindowSize` call: [7](#0-6) 

Once `windowSize` is persisted as `0`, every subsequent call to `getWindowSize(resourceCode)` on that account (used throughout resource recovery, decay, and balance calculations, e.g. `recovery()`, `increase()`, `getAccountEnergyUsageBalanceAndRestoreSeconds`) silently substitutes the default 28800-slot (24h) window instead of the true near-zero window that was actually computed: [8](#0-7) 

### Impact Explanation
This is a resource/energy accounting corruption bug reachable purely through normal, unprivileged transactions (freeze/delegate/undelegate resource contracts and ordinary contract execution that consumes bandwidth/energy). Mistaking a legitimately-computed `windowSize = 0` for "uninitialized" silently reinstates the full 24-hour default window on the account's resource-recovery model. This skews the decay/recovery math (`increase()`'s `lastTime + oldWindowSize > now` branch, and `recovery()`), which can materially change how much bandwidth/energy an account is calculated to have available or recovered — a resource-accounting divergence that affects fee/energy metering fairness and could be leveraged to obtain more available energy/bandwidth than the account should legitimately have, or corrupt delegated-resource bookkeeping between owner/receiver accounts.

### Likelihood Explanation
Reaching `newWindowSize == 0` requires the legacy V1 resource-delegation path (`supportUnfreezeDelay` on, `supportAllowCancelAllUnfreezeV2` off) and specific but not implausible usage/time ratios that make the floor-division numerator smaller than `newUsage`. This is a narrower window than the original Nibbl finding (which triggered on any 4th+ observation once `cumulativeValuation`'s block-number-derived timestamp wrapped modulo 2^32), but it is fully unprivileged and requires no special access — only ordinary delegate/undelegate/freeze transactions timed appropriately.

### Recommendation
- Do not overload `windowSize == 0` as both "field never migrated" and a legitimate computed value. Use an explicit separate flag (e.g. a boolean "windowSizeInitialized"/`windowOptimized`-style flag, which the codebase already has a precedent for) instead of inferring legacy state from the numeric value.
- Alternatively, make `getNewWindowSize()` use ceiling division (matching the V2 implementation) so a positive numerator can never round down to `0`, and additionally clamp any computed `newWindowSize` to a minimum of `1` before persisting, eliminating the ambiguous `0` state entirely.

### Proof of Concept
1. Enable `supportUnfreezeDelay` (unfreeze-delay days > 0) while `supportAllowCancelAllUnfreezeV2` remains disabled, so `ResourceProcessor.increase()`/`unDelegateIncrease()` (V1) executes instead of the V2 variants.
2. Arrange account usage/time state such that `remainUsage`, `remainWindowSize`, and `usage`/`windowSize` combine so that `(lastUsage*lastWindowSize + usage*windowSize) < newUsage` in `getNewWindowSize` — e.g. very small `usage`/`lastUsage` relative to the configured global `windowSize` (28800) — causing the truncating division to yield `0`.
3. Observe `accountCapsule.setNewWindowSize(resourceCode, 0)` is persisted.
4. On the next resource operation, `AccountCapsule.getWindowSize()` reads the stored `0` and returns `WINDOW_SIZE_MS / BLOCK_PRODUCED_INTERVAL` (28800) instead of the actual computed remaining window, producing a resource recovery/decay calculation inconsistent with the real state — analogous to `Twav._getTwav()` returning a wrong (zero-fallback) result when a legitimately-recurring zero value is misread as "uninitialized."

  public long increaseV2(AccountCapsule accountCapsule, ResourceCode resourceCode,
      long lastUsage, long usage, long lastTime, long now) {
    long oldWindowSizeV2 = accountCapsule.getWindowSizeV2(resourceCode);
    long oldWindowSize = accountCapsule.getWindowSize(resourceCode);
    long averageLastUsage;
    long averageUsage;
    if (hardenCalculation()) {
      BigInteger biPrecision = BigInteger.valueOf(this.precision);
      averageLastUsage = divideCeilExact(
          BigInteger.valueOf(lastUsage).multiply(biPrecision),
          BigInteger.valueOf(oldWindowSize));
      averageUsage = divideCeilExact(
          BigInteger.valueOf(usage).multiply(biPrecision),
          BigInteger.valueOf(this.windowSize));
    } else {
      averageLastUsage = divideCeil(lastUsage * this.precision, oldWindowSize);
      averageUsage = divideCeil(usage * this.precision, this.windowSize);
    }

    if (lastTime != now) {
      if (lastTime + oldWindowSize > now) {
        long delta = now - lastTime;
        double decay = (oldWindowSize - delta) / (double) oldWindowSize;
        averageLastUsage = round(averageLastUsage * decay,
            this.disableJavaLangMath());
      } else {
        averageLastUsage = 0;
      }
    }

    long newUsage = getUsage(averageLastUsage, oldWindowSize, averageUsage, this.windowSize);
    long remainUsage = getUsage(averageLastUsage, oldWindowSize);
    if (remainUsage == 0) {
      accountCapsule.setNewWindowSizeV2(resourceCode, this.windowSize * WINDOW_SIZE_PRECISION);
      return newUsage;
    }

    long remainWindowSize = oldWindowSizeV2 - (now - lastTime) * WINDOW_SIZE_PRECISION;
    long newWindowSize;
    if (hardenCalculation()) {
      BigInteger biNewWindowSize = BigInteger.valueOf(remainUsage)
          .multiply(BigInteger.valueOf(remainWindowSize))
          .add(BigInteger.valueOf(usage)
              .multiply(BigInteger.valueOf(this.windowSize))
              .multiply(BigInteger.valueOf(WINDOW_SIZE_PRECISION)));
      newWindowSize = divideCeilExact(biNewWindowSize, BigInteger.valueOf(newUsage));
    } else {
      newWindowSize = divideCeil(
          remainUsage * remainWindowSize + usage * this.windowSize * WINDOW_SIZE_PRECISION,
          newUsage);
    }
    newWindowSize = min(newWindowSize, this.windowSize * WINDOW_SIZE_PRECISION,
        this.disableJavaLangMath());
    accountCapsule.setNewWindowSizeV2(resourceCode, newWindowSize);
    return newUsage;
  }

    long newOwnerUsage = ownerUsage + transferUsage;
    // mean ownerUsage == 0 and transferUsage == 0

  private long getNewWindowSize(long lastUsage, long lastWindowSize, long usage,
      long windowSize, long newUsage) {
    if (hardenCalculation()) {
      BigInteger bi = BigInteger.valueOf(lastUsage).multiply(BigInteger.valueOf(lastWindowSize))
          .add(BigInteger.valueOf(usage).multiply(BigInteger.valueOf(windowSize)));
      return bi.divide(BigInteger.valueOf(newUsage)).longValueExact();
    }
    return (lastUsage * lastWindowSize + usage * windowSize) / newUsage;
  }
