### Title
Self-referential 5% slippage bound on gas-abstraction PRC20→WPC auto-swap enables sandwich extraction from user deposits - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
Both `ExecuteInboundGas` and `gasAndPayloadDepositAutoSwap` fetch a live Uniswap-V3-style quote for the bridged PRC20→WPC swap and immediately derive `minPCOut` as a flat 95% of that same quote, then execute the swap in the same call. Because the "slippage protection" reference price is read from the manipulable on-chain pool at execution time rather than from a user-committed or oracle-anchored price, it does not protect the depositor against price manipulation — it only protects the *last-computed, already-manipulated* price. This is the same root-cause pattern as the Malt `UniswapHandler.addLiquidity` bug: a hardcoded percentage slippage bound computed from data the function itself is about to consume, giving no real protection.

### Finding Description
In `x/uexecutor/keeper/execute_inbound_gas.go`: [1](#0-0) 

and duplicated in `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`: [2](#0-1) 

the flow is:
1. `k.GetSwapQuote(...)` calls `QuoterV2.quoteExactInputSingle` synchronously against the live pool state [3](#0-2) .
2. `minPCOut := quote * 95 / 100` is computed from that same just-fetched quote.
3. `k.CallPRC20DepositAutoSwap(...)` immediately executes the swap using `minPCOut` as the floor [4](#0-3) .

Steps 1 and 3 happen inside the same Cosmos SDK message execution (triggered by the validator vote that finalizes the inbound), so there is no gap for legitimate price movement to invalidate the quote — but there *is* a window for an attacker to manipulate the underlying pool with a transaction ordered earlier in the same block (a classic front-run), because the AMM pool used by `UniversalCore` for PRC20↔WPC swaps is a normal permissionless Uniswap-V3-style pool (see pool/router setup in `test/utils/contracts_setup.go` and the `UniversalCore` ABI's `uniswapV3Quoter`/`WPC` accessors). An attacker who trades against the pool immediately before the validator-triggered deposit transaction depresses the quoted price; the module then computes `minPCOut` from that depressed price and executes the swap, which trivially satisfies the ineffective 95% floor. The attacker then back-runs to restore the price, capturing the price impact that should have gone to (or been protected for) the depositing user. Every `GAS` and `GAS_AND_PAYLOAD` inbound that triggers gas-abstraction auto-swap is exposed, and the value extracted comes directly out of the user's bridged/converted funds — this is fund-accounting corruption reachable purely through an unprivileged user's ordinary submission of transactions around the honestly-processed inbound vote finalization, matching the in-scope "corruption of ... token mapping ... canonical UniversalTx state" and "unauthorized ... release ... of user or protocol-controlled funds" categories.

### Impact Explanation
Because `minPCOut` is derived from the same pool state it is meant to police, an attacker can sandwich the deposit-time auto-swap to extract value from the user's converted PRC20 balance on every gas-abstraction inbound. This directly reduces the native PC/gas amount actually credited to the user's UEA relative to fair value, i.e., unauthorized value transfer out of protocol/user-controlled swap proceeds, with no requirement for validator, TSS, or admin misbehavior — only an unprivileged actor able to submit ordinary EVM transactions against the same pool ahead of the inbound-finalizing transaction.

### Likelihood Explanation
The precondition is a public, permissionless liquidity pool with limited depth (typical for early-stage PRC20/WPC pairs) and a public mempool/block-proposal window in which an attacker can order a manipulation transaction ahead of the validators' inbound-vote-finalizing transaction. This is a standard sandwich/MEV setup and does not require compromising any validator, TSS participant, or admin key — it is exploitable by any user who observes pending inbound processing and can get a transaction included earlier in the same block.

### Recommendation
Do not derive the slippage floor from a quote fetched in the same execution path as the swap. Instead:
- Use a TWAP or a validated, longer-window oracle price as the reference for `minPCOut`, or
- Let the true "fair" conversion rate be fixed at the point the inbound was originally observed/voted (so it cannot be moved by a same-block front-run), or
- Cap the maximum price impact allowed per swap independent of the just-read spot quote, and/or route through pools with minimum-liquidity guarantees, and add commit/reveal or randomized execution ordering protections to reduce front-running feasibility.

### Proof of Concept
1. Attacker monitors the mempool/validator set for a pending `MsgVoteInbound` that will finalize a `GAS_AND_PAYLOAD` (or `GAS`) inbound requiring PRC20→WPC auto-swap.
2. Attacker submits a large PRC20→WPC (or WPC→PRC20, depending on direction needed) swap against the same `UniversalCore` pool, ordered to land in the block immediately before the validators' finalizing vote transaction, depressing the effective exchange rate for PRC20→WPC.
3. When the vote quorum is reached in that block, `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap` calls `GetSwapQuote` against the now-manipulated pool state, computes `minPCOut = quote*95/100` from the manipulated quote, and executes `CallPRC20DepositAutoSwap`, which succeeds because the floor was computed from the manipulated price rather than a fair reference price.
4. Attacker submits a back-run transaction restoring the pool to its prior state, netting the price-impact profit that came out of the value that should have been converted for the depositing user.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
