### Title
Sandwichable spot-price slippage protection in module-executed autoswap deposits enables fund extraction from users during GAS/GAS_AND_PAYLOAD inbound execution - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
The external report's core lesson is that trusting a value derived from an attacker-influenceable external call (a swap's slippage bound) instead of verifying real balances lets a semi-trusted actor extract value beyond the intended surplus. Push Chain's `x/uexecutor` module reproduces the same weak-slippage pattern, but the attacker class is broader: any unprivileged holder of the relevant PRC20/WPC pair on Push Chain can exploit it, because the price used for slippage protection is the AMM's own spot price, fetched moments before the module executes the real swap in the same code path.

### Finding Description
When an inbound of type `GAS` or `GAS_AND_PAYLOAD` finalizes (quorum reached on `MsgVoteInbound`), the keeper auto-swaps the deposited PRC20 into WPC/PC for the recipient UEA:

- `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:126-152`) and `gasAndPayloadDepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:348-379`) both:
  1. Fetch a spot quote via `GetSwapQuote`, which is a static `CallEVM` to `QuoterV2.quoteExactInputSingle` against the live on-chain Uniswap-style pool [1](#0-0) .
  2. Apply a fixed 5% tolerance: `minPCOut = quote * 95 / 100` [2](#0-1) .
  3. Immediately execute the real swap via `CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap` on the `UNIVERSAL_CORE` handler contract, passing that `minPCOut` as the only slippage guard [3](#0-2) .

The same pattern also protects the outbound gas-refund swap path: `applyGasRefund` in `x/uexecutor/keeper/outbound.go` fetches a quote via `getSwapQuoteForRefund` and applies the identical `95/100` spot-derived bound before calling `CallUniversalCoreRefundUnusedGas` with `withSwap=true` [4](#0-3) .

Because both the quote and the swap execute against the same live, publicly tradeable AMM pool on Push Chain (not an external chain, not a privileged contract), any unprivileged user can move the pool's spot price between the quote read and the module's swap execution:
- Front-run: submit a large swap against the same pool in a transaction ordered immediately before the validator's quorum-crossing `MsgVoteInbound` (or before the `MsgVoteOutbound` that triggers the refund) within the same block, driving the price outside the fixed 5% band before the module's own swap executes.
- Back-run/exit: reverse the trade immediately after, capturing the spread while the module-executed swap absorbs the manipulated price.

This is structurally the same defect as the periphery-manager report: a security-critical accounting boundary (slippage protection meant to bound loss during a swap) is derived from a value the attacker can move, rather than from a manipulation-resistant reference (e.g., TWAP) or a `balanceOf`-based post-check. The difference is that here the "semi-trusted actor" of the original report is replaced by an ordinary, unprivileged Push Chain user who only needs capital to trade against the pool — no validator, TSS, or registry privilege is required.

### Impact Explanation
An unprivileged attacker can extract value from users bridging funds via `GAS`/`GAS_AND_PAYLOAD` inbounds (and from the protocol's own excess-gas refund flow on outbounds), by sandwiching the module's autoswap execution. Because `minPCOut` is derived from the same manipulable spot price, the fixed 5% tolerance does not prevent the attacker from capturing most or all of that spread on every swap the module executes — this directly reduces the PC amount credited to the victim's UEA (`ExecuteInboundGas`/`ExecuteInboundGasAndPayload`) or the refund amount credited on outbound gas refunds, i.e., unauthorized extraction of user/protocol-controlled fund value through a user-reachable, deterministic execution path.

### Likelihood Explanation
High for an economically motivated attacker: the pool involved (PRC20 gas-token ↔ WPC) is public and tradeable by anyone on Push Chain; the trigger (an inbound/outbound vote reaching quorum) is externally observable in the mempool before it lands, and the swap parameters (fixed 95% tolerance, spot quote) provide no manipulation resistance. No validator, TSS, or admin privilege is needed — only capital and normal transaction submission.

### Recommendation
- Replace the spot-price `QuoterV2.quoteExactInputSingle` reference with a manipulation-resistant price source (TWAP oracle, or a governance-configured reference price) for computing `minPCOut` in both `gasAndPayloadDepositAutoSwap`/`ExecuteInboundGas` and `applyGasRefund`.
- Tighten and/or make the slippage tolerance risk-adjusted rather than a flat 5%, and consider capping the maximum swap size relative to pool depth.
- As defense-in-depth, verify the actual WPC/PC amount received via `balanceOf` (pre/post) rather than relying solely on the handler contract's internal enforcement of `minPCOut`, so that any future changes to the handler's swap-return trust model don't reintroduce the exact class of bug described in the external report.

### Proof of Concept
1. Attacker monitors the Push Chain mempool for a `MsgVoteInbound` (or `MsgVoteOutbound`) that will cross quorum for a `GAS`/`GAS_AND_PAYLOAD` inbound (or an outbound with excess gas to refund) whose auto-swap targets a PRC20↔WPC pool with shallow liquidity.
2. Attacker submits a transaction that swaps a large amount of PRC20 into WPC (or vice versa) in the same pool, ordered immediately before the quorum-crossing vote transaction, moving the spot price by more than 5%.
3. The quorum-crossing vote executes `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` (or `applyGasRefund`), which calls `GetSwapQuote` against the now-manipulated pool state and computes `minPCOut = quote * 95/100` off that manipulated price [5](#0-4) .
4. `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes the real swap at the manipulated price, still satisfying the manipulated `minPCOut`, crediting the victim's UEA (or refund recipient) with less PC than the true market rate.
5. Attacker reverses their initial trade in a subsequent transaction, capturing the price difference extracted from the victim's swap.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```

```go
// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
```
