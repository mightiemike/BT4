### Title
Unbounded gzip decompression (zip-bomb) via `starknet_estimateFee`/`starknet_call` broadcasted DeclareV1 contract class — ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
The `decompress_program` helper in the JSON-RPC execution path decodes and gzip-decompresses a user-supplied, base64-encoded `program` field from a `BroadcastedDeclareV1Transaction` with no time or size limit, unlike the analogous size-limited decompression utilities used elsewhere in the codebase (e.g. `decode_and_decompress_with_size_limit`). This matches the bug class in the reported CVE-2026-48586 (Apache Thrift `TZlibTransport` unbounded decompression / data amplification).

### Finding Description
`decompress_program` reads an attacker-controlled base64 string, decodes it, and streams it through `flate2::bufread::GzDecoder::read_to_end` into an unbounded `Vec<u8>`: [1](#0-0) 

The `// TODO(dan): add time and size limits.` comment confirms no limit is enforced. This function is reached from `user_deprecated_contract_class_to_sn_api`, invoked when converting a `BroadcastedDeclareTransaction::V1` into an `ExecutableTransactionInput` for local (fee-estimation/simulation/trace) execution triggered via RPC calls such as `starknet_estimateFee`, `starknet_simulateTransactions`, or `starknet_traceTransaction`-style broadcasted paths: [2](#0-1) 

By contrast, the equivalent decompression paths used for gateway-submitted declare transactions (`decode_and_decompress_with_size_limit`) and for P2P class propagation (`MAX_CAIRO0_PROGRAM_SIZE` check in `crates/apollo_protobuf/src/converters/class.rs`) are explicitly bounded: [3](#0-2) [4](#0-3) 

This shows the codebase is aware of, and generally mitigates, this exact bug class — except in this one RPC execution code path.

### Impact Explanation
A small, highly-compressed gzip payload (a "zip bomb") submitted as the `program` field of a `BroadcastedDeclareV1Transaction` in an RPC request (e.g., `starknet_estimateFee`, `starknet_simulateTransactions`) can expand to gigabytes in memory during decompression before any size check occurs, since none exists. This can exhaust node memory/CPU on the RPC-serving node, causing denial of service to that node's transaction estimation/simulation capability. This is a network-availability-impacting bug reachable by any unprivileged RPC caller with a crafted request; per the scope rules this is a resource-exhaustion path on a single node's RPC service rather than a consensus-level state-corruption bug, so it should be evaluated primarily as a targeted RPC DoS rather than a network-wide inability to confirm transactions (the gateway's own declare submission path is size-limited separately via `decode_and_decompress_with_size_limit`, so mempool admission itself is not directly affected by this specific function).

### Likelihood Explanation
High likelihood: the vulnerable function is directly reachable by any external caller of the public JSON-RPC `estimateFee`/`simulateTransactions` methods with a `DECLARE` V1 broadcasted transaction, requires no special privileges, and the missing limit is explicitly flagged by a TODO comment in the code, confirming the maintainers are aware but have not yet remediated it.

### Recommendation
Replace the unbounded `GzDecoder::read_to_end` in `decompress_program` (crates/apollo_rpc/src/v0_8/api/mod.rs) with a size-limited decompression, mirroring `decompress_with_size_limit`/`decode_and_decompress_with_size_limit` in `crates/starknet_api/src/compression_utils.rs` (which uses `.take(max_size + 1)` and errors if the result exceeds the limit), and apply a similar bound to time spent decompressing.

### Proof of Concept
1. Craft a gzip stream that decompresses to several hundred MB–GB from a tiny compressed payload (a classic zip bomb, e.g. repeating zero bytes compressed with `flate2`), then base64-encode it.
2. Submit an RPC request to `starknet_estimateFee` (or `starknet_simulateTransactions`) with a `DECLARE` transaction of version 1 whose `contract_class.program` field is set to this base64 string.
3. Observe that `decompress_program` (crates/apollo_rpc/src/v0_8/api/mod.rs:671-682) decodes and fully decompresses the payload into memory with no size/time bound, causing large memory allocation and CPU usage on the RPC node before any validation occurs. [1](#0-0)

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
