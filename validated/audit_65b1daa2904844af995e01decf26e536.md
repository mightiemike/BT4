### Title
`CalculateGasCost` floors `baseFee` to whole-`upc` before multiplying by `gasUsed`, systematically under-charging UEA gas fee accounting - (File: x/uexecutor/keeper/fees.go)

### Summary
`x/uexecutor/keeper/fees.go`'s `CalculateGasCost` divides `baseFee` down to a whole `upc` integer (`baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`) *before* multiplying by `gasUsed`, instead of multiplying first and rounding once at the end. This is the same class of bug as the FluxToken report: an intermediate division is performed ahead of a multiplication that should have consumed the full-precision value, discarding a fractional remainder that gets amplified by the multiplier (`gasUsed`, potentially in the tens of millions).

### Finding Description
`CalculateGasCost` is documented as implementing "Total Fee = gasUsed × Effective Gas Price": [1](#0-0) 

```go
func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec, ...
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: ... the base fee is always a whole number of upc -- no fractional upc exists.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
	...
```

`baseFee.BigInt()` returns the internal fixed-point representation of the `LegacyDec` (i.e. `realValue * 10^18`). The comment asserts the fee-market's `BaseFee` is "always a whole number of upc," but nothing in this repository enforces that invariant — the base fee is a `LegacyDec` sourced from `FeeMarketKeeper.GetBaseFee` (`x/uexecutor/types/expected_keepers.go`), and Cosmos-EVM's feemarket EIP-1559 elasticity adjustment (external dependency, not vendored here) recomputes the base fee every block via decimal ratio math (`baseFee ± baseFee*gasUsedDelta/gasTarget/changeDenominator`), which will generically produce fractional-`upc` `LegacyDec` values, not exact multiples of `10^18`.

Later, `gasCost = effectiveGasPrice * gasUsed` is computed using the already-truncated `baseFeeBig`: [2](#0-1) 

Because the truncation happens on `baseFee` alone and only afterward is the (already-truncated) value multiplied by `gasUsed`, any fractional-`upc` remainder in the true base fee is dropped once and then effectively multiplied away — instead of the mathematically correct order of `floor(baseFee_asDec * gasUsed)`, which preserves the fractional contribution across the multiplication and only rounds once at the very end. This exactly mirrors the reported `FluxToken.getClaimableFlux` pattern: "multiplication on result of division."

This function feeds `DeductGasFeesFromReceipt`, which is the sole place where EVM execution gas is deducted from a UEA's `upc` balance and burned for `MsgExecutePayload` / module-originated `DerivedEVMCall` execution: [3](#0-2) 

Per the module's own documentation, this is the authoritative gas-fee-accounting path for owner-authorized payload execution: "the actual EVM execution gas is deducted from this UEA's balance (`DeductGasFeesFromReceipt`)." [4](#0-3) 

### Impact Explanation
Every `MsgExecutePayload` gas deduction (a gasless, unprivileged, user-reachable message per `x/uexecutor/README.md`) is computed via this truncate-then-multiply order. Whenever the network base fee (a `LegacyDec`) holds a non-zero fractional-`upc` component — the expected steady state under any EIP-1559-style elastic base-fee adjustment — the protocol under-collects and under-burns gas fees relative to the value it should charge, for every payload execution, proportional to `gasUsed` (which can be up to millions of gas units per call). This is a systematic corruption of gas fee accounting/burn accounting: value that should be extracted from the UEA and burned is instead permanently left with the UEA owner. This matches the in-scope impact category "corruption of ... gas fee accounting, refund accounting ... or canonical UniversalTx state," reachable purely through ordinary unprivileged `MsgExecutePayload` submission with no validator, relayer, or admin involvement.

### Likelihood Explanation
The trigger requires no attacker action beyond normal use of `MsgExecutePayload` — it fires automatically whenever `FeeMarketKeeper.GetBaseFee` returns a non-exact-`upc` `LegacyDec`, which is the generic/expected output of any continuously-adjusting EIP-1559 base fee mechanism over time (rather than the special-cased genesis value hard-coded as a round number in test/genesis scripts). Because the feemarket module's adjustment algorithm is external (Cosmos-EVM dependency) and not something this repository controls or normalizes to whole-`upc` values before storing, the precondition (`baseFee` not landing on an exact multiple of `10^18`) is very likely to occur under real network conditions, though I could not directly inspect the vendored feemarket base-fee-update implementation in this scoped repository to give a hard guarantee that it never keeps the value floor-aligned to `upc`.

### Recommendation
Perform the multiplication first, using the full-precision `LegacyDec` (or by scaling `gasUsed` into the `LegacyDec` domain), and only convert/truncate to an integer `upc` amount once, at the very end:

```go
effectiveGasPriceDec := baseFee // full precision, no early Div by 1e18
gasCostDec := effectiveGasPriceDec.MulInt64(int64(gasUsed))
gasCost := gasCostDec.TruncateInt().BigInt() // single truncation at the end
```
This mirrors the report's fix pattern of grouping all multiplications before any division/truncation, ensuring gas fee accounting is not systematically short-changed.

### Proof of Concept
Given `baseFee` (as `sdkmath.LegacyDec`) = `1_500_000_000.999999999999999999` upc (a plausible post-adjustment value) and `gasUsed = 21_000_000`:

- Current code: `baseFeeBig.Div(..., 1e18)` → `1_500_000_000` (fraction dropped) → `gasCost = 1_500_000_000 * 21_000_000 = 31,500,000,000,000,000` upc.
- Correct order: `gasCost = floor(1_500_000_000.999999999999999999 * 21_000_000) = 31,500,000,020,999,999` upc (approximately).
- Difference: ≈ `20,999,999` upc under-charged/under-burned for this single execution — repeated for every `MsgExecutePayload` call while the base fee carries a fractional-`upc` component.

Note: I was unable to inspect the vendored Cosmos-EVM feemarket base-fee update algorithm within this repository's index to conclusively prove the fractional-`upc` precondition always arises in production; this should be verified against the actual `x/feemarket` dependency version pinned in `go.mod` before treating this as a confirmed, exploitable finding versus a defensive hardening item.

```go
// CalculateGasCost calculates the gas cost based on EIP-1559 fee mechanism:
// 1. Effective Gas Price = min(maxFeePerGas, baseFee + maxPriorityFeePerGas)
// 2. Total Fee = gasUsed × Effective Gas Price
// Parameters:
// - baseFee: current network base fee
// - maxFeePerGas: maximum total fee user is willing to pay
// - maxPriorityFeePerGas: maximum tip to validator
// - gasUsed: amount of gas consumed
func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
```

```go
// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```

```markdown
### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```
