### Title
App Proxy HMAC canonicalization collision allows forging `logged_in_customer_id` and other trusted query parameters - ([File: packages/apps/shopify-api/lib/utils/hmac-validator.ts])

### Summary
The App Proxy signature scheme concatenates query key/value pairs with no delimiter between distinct pairs, which is the same class of "canonicalization mismatch" flaw described in the external report (an incorrectly-constructed hashed-message preimage that breaks the intended one-to-one mapping between structured data and its signed representation). Because there is no separator, two different parameter maps can produce byte-identical canonical strings and therefore identical valid HMACs, letting an attacker split a value into a fabricated extra key (e.g. `logged_in_customer_id`) while keeping a genuinely Shopify-issued signature valid.

### Finding Description
`stringifyQueryForAppProxy` builds the string that is HMAC-signed by simply sorting keys alphabetically and concatenating `key=value` for each pair with **no separator between pairs**: [1](#0-0) 

This is used both to compute the signature on the app side (`generateLocalHmac`) and to validate incoming app-proxy requests via `validateHmac`: [2](#0-1) 

Only `hmac`, `shop`, `signature`, and `timestamp` are protected against duplication/splitting; arbitrary application parameters (including `logged_in_customer_id`) are not: [3](#0-2) [4](#0-3) 

Because the canonical string has no delimiter between `key=value` entries, a parameter map `{a: "1", b: "2"}` and a map `{a: "1b", <no b key>}`... more concretely `{extra: "1logged_in_customer_id=999", shop, timestamp}` and `{extra: "1", logged_in_customer_id: "999", shop, timestamp}` produce the **exact same canonical text**:
```
extra=1logged_in_customer_id=999shop=...timestamp=...
```
The first map is a legitimate anonymous app-proxy request (no `logged_in_customer_id` key at all — the digits happen to live inside the `extra` value) that Shopify will genuinely sign using the identical concatenation scheme. The second map is a request an attacker crafts directly against the app's public proxy endpoint (this endpoint is just a normal HTTP route reachable by anyone, not network-restricted to Shopify — the entire trust boundary is the HMAC check performed by `authenticateAppProxyFactory`): [5](#0-4) 

An attacker who first obtains a genuinely Shopify-signed anonymous app-proxy request containing `extra=1logged_in_customer_id=999` can copy that `signature` value and replay it against the app's endpoint with the value split into a real `logged_in_customer_id=999` key. `validateHmac` recomputes the same canonical string from the new (split) real parameters and accepts the forged signature, because the recomputation is purely a function of the received query, not of what Shopify actually intended to sign.

Downstream code trusts `logged_in_customer_id` taken directly from the validated request's query string as an authenticated identity signal, per the project's own documented usage pattern: [6](#0-5) 

### Impact Explanation
An unauthenticated attacker can forge the value of `logged_in_customer_id` (or any other application-defined app-proxy parameter) while presenting a signature that will pass `validateHmac`. Apps that follow the documented pattern of reading `logged_in_customer_id` from the query string to identify the customer for personalization, order lookups, or gated content will treat the attacker as an arbitrary chosen customer — a cross-tenant/customer impersonation vulnerability. It does not require possession of the API secret; it only requires (1) the ability to make one legitimate anonymous app-proxy call with a crafted parameter value, and (2) the ability to hit the app's proxy endpoint directly (which is a plain public HTTP endpoint whose only real access control is the signature check).

### Likelihood Explanation
Exploitation requires reachable app-proxy endpoints that consume `logged_in_customer_id` (or similar parameters) from the query string for authorization/identity decisions — a pattern explicitly recommended in this repository's own documentation. The attacker needs no credentials, only the ability to browse the storefront (to generate a Shopify-signed request with a crafted parameter value) and to send a raw HTTP request to the app's public endpoint. Likelihood is moderate: it depends on the specific character choices lining up with alphabetical key ordering and on the app trusting that field, but the primitive itself (delimiter-less canonicalization) is present in all app-proxy signature validation paths in this library.

### Recommendation
Change `stringifyQueryForAppProxy` (and the mirrored inline implementation used in tests/other packages) to use an unambiguous canonical encoding that includes explicit separators and length-prefixing or escaping of `=`/`&` characters within values, e.g. join pairs with `&` and percent-encode both keys and values before concatenation, matching an unambiguous, injective serialization. Additionally, reject/percent-decode-validate any application parameter whose decoded value itself contains `key=value`-shaped substrings that could be conflated with adjacent parameters, and treat sensitive parameters like `logged_in_customer_id` with the same duplication/collision hardening currently reserved for `hmac`/`shop`/`signature`/`timestamp`.

### Proof of Concept
1. Attacker (anonymous storefront visitor) requests the app-proxy URL:
   `https://shop.myshopify.com/apps/my_app?extra=1logged_in_customer_id=999`
   Shopify appends `shop`, `timestamp`, and computes `signature` over the canonical string
   `extra=1logged_in_customer_id=999shop=shop.myshopify.comtimestamp=<T>`
   and forwards this to the app; this is a legitimate, correctly-signed request with **no** real `logged_in_customer_id` key.
2. Attacker records the resulting `signature` value `S`.
3. Attacker sends a direct HTTP GET to the app's public proxy route (bypassing Shopify):
   `https://myapp.example.com/apps/my_app?extra=1&logged_in_customer_id=999&shop=shop.myshopify.com&timestamp=<T>&signature=S`
4. `validateHmac` (via `stringifyQueryForAppProxy`) recomputes the canonical string from these four real parameters, sorted alphabetically: `extra=1logged_in_customer_id=999shop=shop.myshopify.comtimestamp=<T>` — byte-identical to step 1 — so `safeCompare` succeeds and the request is accepted as authentic.
5. `authenticateAppProxyFactory` proceeds, and app code reading `url.searchParams.get('logged_in_customer_id')` sees `"999"`, treating the anonymous attacker as customer `999`, despite Shopify never having certified that identity for this request. [1](#0-0)

function stringifyQueryForAppProxy(query: AuthQuery): string {
  return Object.entries(query)
    .sort(([val1], [val2]) => val1.localeCompare(val2))
    .reduce((acc, [key, value]) => {
      return `${acc}${key}=${Array.isArray(value) ? value.join(',') : value}`;
    }, '');
}

export function generateLocalHmac(config: ConfigInterface) {
  return async (
    params: AuthQuery,
    signator: HMACSignator = 'admin',
  ): Promise<string> => {
    const {hmac: _hmac, signature: _signature, ...query} = params;

    const queryString =
      signator === 'admin'
        ? stringifyQueryForAdmin(query)
        : stringifyQueryForAppProxy(query);

    return createSHA256HMAC(config.apiSecretKey, queryString, HashFormat.Hex);
  };
}

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}
