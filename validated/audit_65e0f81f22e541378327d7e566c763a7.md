### Title
Unbounded `io.ReadAll` on unauthenticated `/plugins/:name/debug/pprof/symbol` POST body enables memory-exhaustion DoS - ([File: core/web/loop_registry.go])

### Summary
`LoopRegistryServer.pluginPPROFPOSTSymbolHandler` reads the entire HTTP request body into memory via `io.ReadAll(gc.Request.Body)` before forwarding it to the internal LOOP plugin's pprof symbol endpoint, with no request size limit imposed anywhere in the call path. An attacker who can reach this route can send an arbitrarily large (or slow, chunked) POST body to force the node to allocate memory proportional to the attacker-supplied payload.

### Finding Description
The handler at [1](#0-0)  resolves the target plugin, builds the forwarding URL, and then does:
```go
body, err := io.ReadAll(gc.Request.Body)
```
There is no `http.MaxBytesReader`, `io.LimitReader`, or Gin `MaxMultipartMemory`-style guard applied to `gc.Request.Body` before this read, and a search of `core/web` confirms no size-limiting constructs (`MaxBytesReader`, `LimitReader`, `ContentLength` checks) are used anywhere in this file or its siblings. Once fully buffered, the body is wrapped in a `bytes.NewReader` and forwarded through `doRequest`, which itself also buffers the response body fully via `io.ReadAll(res.Body)` at [2](#0-1) , compounding the memory pressure. The design intent of the plugin registry endpoints (per the comment "this endpoint is internal btw the node and plugin") is to proxy Prometheus/pprof scraping traffic from the node's externally reachable HTTP server to internal LOOP plugin ports, meaning the route is exposed on the main web server surface alongside `/discovery` and `/plugins/:name/metrics`.

### Impact Explanation
A single attacker request with a multi-gigabyte body (or many concurrent large-body requests) causes the node process to allocate memory equal to the request size for each in-flight request, with no cap. This can drive the node's RSS to the point of OOM-kill or severe GC pressure, producing a node-wide availability (DoS) impact — consistent with the "Denial of Service" bounty category for the chainlink node's HTTP surface.

### Likelihood Explanation
Exploitation requires no authentication, no valid session/API key, and no special plugin knowledge beyond a registered plugin name (or even an invalid one is checked only after body read is deferred — actually the plugin-existence check happens before the read, so an attacker needs a valid registered LOOP plugin name, e.g. a well-known plugin like `median`). The attack is trivially repeatable and can be automated/fuzzed by simply increasing payload size, making likelihood high once the route is confirmed reachable without auth.

### Recommendation
Wrap `gc.Request.Body` with `http.MaxBytesReader(gc.Writer, gc.Request.Body, <reasonable limit, e.g. a few MB>)` before calling `io.ReadAll`, and return `413 Request Entity Too Large` on read errors caused by exceeding the limit. Apply the same bound to `doRequest`'s response-body read to prevent equivalent amplification from a compromised or misbehaving plugin.

### Proof of Concept
Integration test plan:
1. Register a fake LOOP plugin in `plugins.LoopRegistry` pointing at a local HTTP test server on an ephemeral port.
2. Issue `POST /plugins/<name>/debug/pprof/symbol` with a body of several hundred MB (streamed, not pre-buffered, to simulate a real attacker) via `httptest` or a live server.
3. Measure process memory (e.g. via `runtime.MemStats` or OS RSS) before and during the request; assert that memory grows roughly linearly with body size and that no limit rejects the request before `io.ReadAll` completes.
4. Repeat with a body exceeding the intended limit after the fix is applied and assert the handler returns `413` promptly without buffering the full body.

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
```
