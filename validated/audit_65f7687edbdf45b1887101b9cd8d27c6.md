### Title
Punished Nakamoto miner still collects full transaction-fee revenue via unconditional `parent_fees` payout - (File: stackslib/src/chainstate/stacks/db/accounts.rs)

### Summary
`StacksChainState::calculate_miner_reward` computes a `punished` flag from a poison-microblock report and uses it to zero out `anchored_fees`/`streamed_confirmed_fees` in the `MinerPaymentTxFees::Epoch2` branch, but the `MinerPaymentTxFees::Nakamoto { parent_fees }` branch unconditionally returns `(0, parent_fees, 0)` without ever consulting `punished`. Because Nakamoto's fee-accounting model defers a tenure's transaction fees to be paid as `parent_fees` during the *next* tenure's reward maturation, the convicted miner's own fee revenue is never gated by its own punishment status at all — it is paid out later, unconditionally, when the child tenure's schedule matures.

### Finding Description
The claimed equality is: `convicted_miner_total_payout == coinbase_commission_to_reporter_only`, i.e. `reward_paid_to_cheater(tx_fees) == 0` for a `punished == true` miner.

In `calculate_miner_reward` (accounts.rs:906-945), for a Nakamoto participant:
```
MinerPaymentTxFees::Nakamoto { parent_fees } => {
    // in nakamoto, tx fees in the payment schedule correspond to the
    //  tx fees of the *parent tenure* ...
    (0, parent_fees, 0)
}
``` [1](#0-0) 

The resulting `(0, parent_fees, 0)` tuple is destructured as `(tx_fees_anchored, parent_tx_fees_streamed_produced, tx_fees_streamed_confirmed)`. `parent_tx_fees_streamed_produced` is assigned to `parent_miner_reward.tx_fees_streamed_produced`, credited to `parent.address` — a *different* payment schedule from `participant`: [2](#0-1) 

Because Nakamoto fees for a tenure are only known once the succeeding tenure begins, tenure N's real fee revenue is never realized in tenure N's own maturation call (its own `tx_fees_anchored`/`tx_fees_streamed_confirmed` are hard-coded `0` regardless of `punished`). Instead, it is realized later, as `parent_fees`, when tenure N+1's schedule matures and tenure N's miner is passed in as the `parent` argument: [3](#0-2) 

At that later call, `punished` is computed from `poison_recipient_opt` looked up via `get_poison_microblock_report(clarity_tx, reward_height)` for tenure N+1's reward height, reflecting whether *tenure N+1's* miner was punished — not tenure N's miner: [4](#0-3) 

Thus, if tenure N's miner M was convicted via poison-microblock report (punished during N's own maturation, zeroing coinbase-only, since Nakamoto's own-fee fields are already hard-zero at that call), M's actual tenure-N transaction fees are still transferred to M's address in full when tenure N+1 matures, because that payout path never re-checks M's punishment. Unlike the Epoch2 branch, where `anchored_fees` and `streamed_confirmed_fees` are the *actual* fee payout gated inline by `punished` in the same call as the participant being punished, the Nakamoto branch defers the actual money movement to a separate call where the punishment check is against the wrong participant.

### Impact Explanation
This is a reward mis-payment bounded to transaction fees (not the coinbase, not consensus-critical state), matching the "reward mis-payment bounded to fees" category. The convicted miner retains full tx-fee revenue for the poisoned tenure while only forfeiting the coinbase share, breaking `reward_paid_to_cheater == 0`. No chain split, no invalid block acceptance, and no state-root divergence result — all nodes compute the same (mistaken) payout deterministically, so this does not cause disagreement between honest nodes, only an economically incorrect reward that every node agrees on.

### Likelihood Explanation
Reachability of this path depends on whether a poison-microblock report can actually be filed against a genuinely Nakamoto-native tenure. Poison-microblock evidence is fundamentally about forking a *microblock stream*, and Nakamoto tenures do not produce microblocks at all — the `MinerPaymentTxFees::Nakamoto` variant and its "fees deferred to the next tenure" design exists specifically because Nakamoto tenures don't have the epoch2 microblock/anchor-block split. I was unable to confirm within the available context whether `get_poison_microblock_report`/poison-microblock transactions can be validly submitted and matured against a purely-Nakamoto miner's payment schedule (as opposed to only applying during the epoch2→Nakamoto transition, which is explicitly out of scope per the audit rules as "epoch2x/neon machinery"). If poison-microblock reports cannot target genuinely Nakamoto tenures, `punished == true` combined with `MinerPaymentTxFees::Nakamoto` for the *same* participant may never co-occur in reachable production states, which would make this code path unreachable/dead rather than exploitable.

### Recommendation
If poison-microblock convictions can reach Nakamoto-native tenures, track the punishment status against the tenure that earned the fees (tenure N), not the tenure being matured (N+1), and zero `parent_fees` in the `MinerPaymentTxFees::Nakamoto` branch when the *parent* miner (not `participant`) was punished for its own tenure. This requires threading a "was-parent-punished" boolean into `calculate_miner_reward` (looked up via `get_poison_microblock_report` at the parent's own reward height) rather than relying solely on the `punished` flag computed for the current participant.

### Proof of Concept
Rust integration test plan (nakamoto coordinator/reward test harness):
1. Build a 2-tenure Nakamoto chain: tenure N mined by miner M with known transaction fees F, tenure N+1 mined by a different miner.
2. Submit a valid poison-microblock report against M's tenure N (or the mechanism applicable in-repo) before tenure N's reward matures.
3. Advance the chain past `MINER_REWARD_MATURITY` for tenure N, then further to mature tenure N+1's schedule (which carries `parent_fees = F` for M).
4. Call `StacksChainState::find_mature_miner_rewards` for both maturation heights and inspect the returned `MinerReward`s for M.
5. Assert the broken equality: at tenure N's maturation, `miner_reward.tx_fees_anchored == 0` and `tx_fees_streamed_confirmed == 0` (expected, already true), but at tenure N+1's maturation, assert `parent_miner_reward.address == M.address` and `parent_miner_reward.tx_fees_streamed_produced == F` (nonzero) — demonstrating M receives fee revenue F despite being `punished` for tenure N, i.e. `reward_paid_to_cheater(tx_fees) == F != 0`.
