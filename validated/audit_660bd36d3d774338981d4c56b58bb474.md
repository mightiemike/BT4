### Title
Pre-authentication Stack Overflow via Unbounded Recursive JSON Deserialization of Declare-v1 `Program` Fields - (File: `crates/starknet_api/src/deprecated_contract_class.rs`)

### Summary
The deprecated Cairo-0 `Program` struct deserializes multiple fields (`attributes`, `builtins`, `compiler_version`, `data`, `debug_info`, `hints`, `identifiers`, `main_scope`, `prime`, `reference_manager`) as raw, untyped `serde_json::Value` [1](#0-0) . `serde_json::Value`'s deserializer is a recursive-descent parser with no built-in depth limit, so a small, deeply-nested JSON payload placed in any of these fields can drive unbounded native-stack recursion and crash the process — the same bug class described in the MongoDB advisory (BIT-mongodb-2025-6710 / CVE-2025-6710).

### Finding Description
This `Program` type is populated when an unprivileged client broadcasts a Cairo-0 (deprecated) `DECLARE` transaction. The RPC path `BroadcastedDeclareV1Transaction` accepts a `contract_class: DeprecatedContractClass` field containing a gzip+base64-compressed program string [2](#0-1) . When converting this broadcasted transaction for execution, `user_deprecated_contract_class_to_sn_api` calls `decompress_program` on the client-supplied blob and assigns the result directly into `starknet_api::deprecated_contract_class::ContractClass.program` [3](#0-2) .

`decompress_program` base64-decodes and gunzips the attacker-supplied bytes and feeds them straight into `serde_json::from_reader`, with an explicit TODO acknowledging the missing protections:
```
// TODO(dan): add time and size limits.
let mut decoder = GzDecoder::new(compressed_data.as_slice());
...
serde_json::from_reader(decompressed.as_slice()).map_err(internal_server_error)
``` [4](#0-3) 

Because the target fields are typed as `serde_json::Value` rather than concrete, depth-bounded structs, the parser will recurse once per array/object nesting level regardless of overall payload size. Gzip compression allows an attacker to submit a very small compressed payload (e.g., tens of KB) that decompresses into an extremely deeply nested JSON structure (millions of `[` characters), which is exactly the amplification vector highlighted in the MongoDB report. This parsing occurs before any signature validation, fee check, or resource/gas accounting is performed on the transaction, so it is reachable pre-authorization by any network client able to submit an RPC request.

### Impact Explanation
A crafted declare-v1 transaction can crash the RPC/gateway process handling the broadcast before any admission control (fee charge, signature check, nonce check) is applied. This is a liveness/availability issue on the affected node: repeated submission can be used to force a target sequencer/full-node process to restart, and if targeted broadly, can contribute to a network being unable to confirm new transactions during the disruption window.

### Likelihood Explanation
The path is reachable from a single unauthenticated request over the RPC/gateway HTTP interface — no funds, valid signature, or prior state are required to trigger the vulnerable deserialization, since it happens before those checks are performed on the parsed structures. The only requirement is producing a small compressed blob decompressing to deeply nested JSON, which is straightforward to construct.

### Recommendation
- Replace the raw `serde_json::Value` fields in `Program` with strongly-typed, depth-bounded structures, or
- Deserialize with a JSON parser/config that enforces a maximum nesting depth (e.g. `serde_json::Deserializer` with a depth-limited wrapper, or reject inputs whose bracket/brace nesting exceeds a small bound before full parsing), and
- Enforce the size/time limits already flagged by the `// TODO(dan): add time and size limits.` comment in `decompress_program` before invoking `serde_json::from_reader`, including limiting decompressed size and validating structural depth prior to full deserialization.

### Proof of Concept
1. Construct a JSON document `{"data": "<huge sequence of nested arrays, e.g. \"[[[[[...]]]]]\" repeated hundreds of thousands of times>", "builtins": [], "identifiers": {}, "main_scope": "", "prime": "", "reference_manager": {}, "hints": {}}` matching the `Program` schema, keeping most fields minimal and putting the deep nesting into one `serde_json::Value`-typed field such as `debug_info` or `attributes`.
2. Gzip-compress and base64-encode this JSON to keep the wire payload small.
3. Submit a `BroadcastedDeclareV1Transaction` (or the deprecated-gateway equivalent) to the node's RPC/gateway `add_transaction`/`starknet_addDeclareTransaction` endpoint with `contract_class.program` set to this compressed blob.
4. `decompress_program` decompresses and calls `serde_json::from_reader`, which recurses proportionally to the nesting depth and overflows the native stack, crashing the serving process — before signature or fee validation is reached.

pub(crate) fn decompress_program(
    base64_compressed_program: &String,
) -> Result<Program, ErrorObjectOwned> {
    base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    let compressed_data =
        base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    // TODO(dan): add time and size limits.
    let mut decoder = GzDecoder::new(compressed_data.as_slice());
    let mut decompressed = Vec::new();
    decoder.read_to_end(&mut decompressed).map_err(internal_server_error)?;
    serde_json::from_reader(decompressed.as_slice()).map_err(internal_server_error)
}
