### Title
Shared global free-bandwidth pool can be drained by unprivileged transactions, denying free-tier access to legitimate users - (File: `chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java`)

### Summary
The reported Pontis bug is a class of "shared, limited, first-come-first-served resource" that any unprivileged actor can exhaust to deny legitimate users access to that resource. The closest reachable analog in java-tron is the global `PUBLIC_NET_LIMIT` free-bandwidth pool consumed inside `useFreeNet()` in `BandwidthProcessor`. This pool is a single global counter (`PUBLIC_NET_USAGE`/`PUBLIC_NET_LIMIT`) that every broadcast transaction from every account competes for on a strict first-come-first-served basis, with no per-user reservation or fairness mechanism.

### Finding Description
`BandwidthProcessor.consume()` is reached for every broadcast transaction (an anonymous/unprivileged path, since any account can submit a transaction) and tries `useAccountNet` first, then falls back to `useFreeNet` before charging a fee: [1](#0-0) 

`useFreeNet()` checks and increments a single **global** counter (`publicNetUsage` bounded by `publicNetLimit`) shared by all accounts on the chain, in addition to the per-account `freeNetUsage`/`freeNetLimit`: [2](#0-1) 

The global counters are persisted via `savePublicNetUsage`/`getPublicNetUsage`/`getPublicNetLimit` in `DynamicPropertiesStore`: [3](#0-2) 

Just as the Pontis contract's `getAndMarkKeyUtxo()` decrements a shared counter (`totalAmountKeyUtxo`/`currentKeyUtxo`) on a first-come-first-served basis without checking whether the caller is the intended beneficiary, `useFreeNet()` decrements the shared `publicNetLimit` pool without any check that the caller is the account for whom the free allowance was "intended." Any account (including freshly created ones needing no frozen balance) can flood the network with minimum-cost transactions that fall through to `useFreeNet()`, consuming the entire global `publicNetLimit` before legitimate users' transactions are processed in the same recovery window.

### Impact Explanation
Once `publicNetUsage` reaches `publicNetLimit` (see the guard at `chainBaseManager.getDynamicPropertiesStore().getPublicNetUsage()`/`getPublicNetLimit()` inside `useFreeNet()`), `useFreeNet()` returns `false` for every other account for the remainder of the current time window (bounded by `increase()`/`latestConsumeTime` recovery logic), forcing them into `useTransactionFee()` or, if insufficient balance, rejection with `AccountResourceInsufficientException`: [4](#0-3) 
This is a temporary denial of the free-tier bandwidth core function for legitimate, low-balance users, mirroring the Pontis bug class where a limited shared allocation intended for specific users can be exhausted by unrelated, minimally-costed actors.

### Likelihood Explanation
Any account can trigger this path since `useFreeNet` requires no special privilege, frozen balance, or stake — only that the transaction falls through `useAccountNet` (i.e., zero/insufficient frozen bandwidth). The attacker's cost is bounded only by however many free/cheap transactions they can broadcast before the pool refills, analogous to the Pontis team's own "high fees deter attacker" risk-acceptance rationale — in TRON's case the cost per attack transaction is also very low or zero within `freeNetLimit`.

### Recommendation
Consider per-account rate limiting or reputation/priority weighting for consumption of the shared `PUBLIC_NET_LIMIT` pool (e.g., proportional allocation, minimum stake/age requirements, or per-address quotas within the global pool) so that a single low-cost actor cannot monopolize the shared free-bandwidth allowance and deny it to other accounts within the same recovery window.

### Proof of Concept
1. Attacker controls or creates many accounts with zero frozen bandwidth (no TRX freeze required).
2. Each account broadcasts a minimal transaction (e.g., a `TransferContract`) that falls through `useAccountNet` (no frozen bandwidth) into `useFreeNet`.
3. `useFreeNet()` increments the shared `publicNetUsage` (`chainBaseManager.getDynamicPropertiesStore().savePublicNetUsage(...)`, line 542) until it reaches `publicNetLimit`.
4. Subsequent legitimate accounts calling the same code path get `bytes > (publicNetLimit - newPublicNetUsage)` (line 526) and `useFreeNet` returns `false`, forcing them to `useTransactionFee` or fail with `AccountResourceInsufficientException` (lines 172-177) until the pool naturally recovers over the `PUBLIC_NET_TIME` window.   private boolean useFreeNet(AccountCapsule accountCapsule, long bytes, long now) {

    long freeNetLimit = chainBaseManager.getDynamicPropertiesStore().getFreeNetLimit();
    long freeNetUsage = accountCapsule.getFreeNetUsage();
    long latestConsumeFreeTime = accountCapsule.getLatestConsumeFreeTime();
    long newFreeNetUsage = increase(freeNetUsage, 0, latestConsumeFreeTime, now);

    if (bytes > (freeNetLimit - newFreeNetUsage)) {
      logger.debug("Free net usage is running out."
              + " Bytes: {}, freeNetLimit: {}, newFreeNetUsage: {}.",
          bytes, freeNetLimit, newFreeNetUsage);
      return false;
    }

    long publicNetLimit = chainBaseManager.getDynamicPropertiesStore().getPublicNetLimit();
    long publicNetUsage = chainBaseManager.getDynamicPropertiesStore().getPublicNetUsage();
    long publicNetTime = chainBaseManager.getDynamicPropertiesStore().getPublicNetTime();

    long newPublicNetUsage = increase(publicNetUsage, 0, publicNetTime, now);

    if (bytes > (publicNetLimit - newPublicNetUsage)) {
      logger.debug("Free public net usage is running out."
              + " Bytes: {}, publicNetLimit: {}, newPublicNetUsage: {}.",
          bytes, publicNetLimit, newPublicNetUsage);
      return false;
    }

    latestConsumeFreeTime = now;
    long latestOperationTime = chainBaseManager.getHeadBlockTimeStamp();
    publicNetTime = now;
    newFreeNetUsage = increase(newFreeNetUsage, bytes, latestConsumeFreeTime, now);
    newPublicNetUsage = increase(newPublicNetUsage, bytes, publicNetTime, now);
    accountCapsule.setFreeNetUsage(newFreeNetUsage);
    accountCapsule.setLatestConsumeFreeTime(latestConsumeFreeTime);
    accountCapsule.setLatestOperationTime(latestOperationTime);

    chainBaseManager.getDynamicPropertiesStore().savePublicNetUsage(newPublicNetUsage);
    chainBaseManager.getDynamicPropertiesStore().savePublicNetTime(publicNetTime);
    chainBaseManager.getAccountStore().put(accountCapsule.createDbKey(), accountCapsule);
    return true;

  public void savePublicNetUsage(long publicNetUsage) {
    this.put(DynamicResourceProperties.PUBLIC_NET_USAGE,
        new BytesCapsule(ByteArray.fromLong(publicNetUsage)));
  }

  public long getPublicNetUsage() {
    return Optional.ofNullable(getUnchecked(DynamicResourceProperties.PUBLIC_NET_USAGE))
        .map(BytesCapsule::getData)
        .map(ByteArray::toLong)
        .orElseThrow(
            () -> new IllegalArgumentException("not found PUBLIC_NET_USAGE"));
  }
