### Title
Zero-Rounded Debt Amount Bypasses Proportional Collateral Capping in Liquidation - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
In the liquidation pipeline, `scale-debt-for-liquidation` decides whether collateral must be scaled down proportionally to a *capped* debt amount by comparing `scaled-to-remove` to `scaled-debt`. When `debt-final` (computed upstream) rounds down to zero due to integer division, `scaled-debt` also becomes zero, and the equality `scaled-to-remove < scaled-debt` (`0 < 0`) evaluates to `false`. This causes the "capped" branch to be skipped, so `coll-final` is left at the full, un-scaled `coll-actual` while `debt-to-repay` is `0`. A liquidator can therefore receive full collateral while repaying no debt — the exact analog of the referenced `Limbo.sol` bug where `adjustedRectangle == 0` causes `excessSCX` to be miscalculated and nothing gets deducted.

### Finding Description
The liquidation math is a multi-step pipeline of private helpers in `mainnet/contracts/market/v0-4-market.clar`:

1. `process-debt-asset` computes `debt-actual` and `debt-actual-usd` (capped at `max-debt-usd`). [1](#0-0) 

2. `process-collateral-asset` computes `coll-expected`/`coll-actual` in the collateral asset's own decimals/price, capped at the user's balance. [2](#0-1) 

3. `calc-final-liquidation-amounts` recomputes `debt-final` from `debt-final-usd`, using the *debt* asset's own decimals/price. [3](#0-2) 

4. `scale-debt-for-liquidation` converts `debt-final` to scaled units (`scaled-debt = mul-div-down debt-final INDEX-PRECISION borrow-index`), caps it against `curr-scaled` to get `scaled-to-remove`, and only shrinks `coll-final` proportionally **if** `scaled-to-remove < scaled-debt`: [4](#0-3) 

Because `debt-final`, `coll-actual`, and `scaled-debt` are each computed independently through separate decimal/price/index conversions (dust-sized debt USD amounts round to `0` after `mul-div-down` while the corresponding `coll-actual`, computed from a different asset's price/decimals, need not round to zero), it is possible for `scaled-debt` to equal `0` while `coll-actual` remains strictly positive. In that case:
- `scaled-to-remove = min(curr-scaled, 0) = 0`
- `debt-to-repay = mul-div-up(0, borrow-index, INDEX-PRECISION) = 0`
- The guard `(< scaled-to-remove scaled-debt)` = `(< 0 0)` = `false`, so `coll-final` is **not** scaled down and remains the full (uncapped) `coll-actual`.

This mirrors the reported pattern precisely: an intermediate quantity (`adjustedRectangle` / here `scaled-debt`) collapsing to zero silently disables the deduction/scaling logic that depends on strict inequality against that same zero value, instead of using a `<=` comparison or an explicit zero/underflow guard.

### Impact Explanation
If `scaled-debt` rounds to zero while `coll-actual` is nonzero, a liquidator repays `0` debt tokens (`debt-to-repay = 0`) yet still receives the full, un-scaled collateral amount `coll-final = coll-actual`. This is direct theft of user funds at rest (the borrower's collateral) with no counterbalancing debt repayment — a Critical-impact finding under the direct-theft-of-user-funds category.

### Likelihood Explanation
Triggering requires a liquidation where the computed debt-side USD/token conversion rounds to zero while the collateral-side conversion does not — most readily achievable with a dust-value `debt-amount` argument on an asset whose `debt-price`/`debt-decimals` combination makes `mul-div-down` truncate to zero, combined with a collateral asset of different decimals/price where `coll-actual` remains positive. Since `liquidate` is a permissionless entry point taking an attacker-chosen `debt-amount`, the interleaving is achievable within a single transaction/single call and does not require any privileged access, DAO action, or multi-party interference.

### Recommendation
In `scale-debt-for-liquidation`, replace the strict inequality with a check that also accounts for the zero-debt case, or add an explicit guard rejecting/short-circuiting when `scaled-debt == u0` (and, symmetrically, `debt-to-repay == u0`) before releasing any collateral — analogous to the recommended `require(adjustedRectangle != 0)` fix in the reference report. At minimum, change the capping condition to `(<= scaled-to-remove scaled-debt)` combined with an assertion that `debt-to-repay > u0` before any nonzero `coll-final` is authorized.

### Proof of Concept
1. Attacker calls `liquidate` on a position with a very small `debt-amount` for a debt asset whose `debt-price`/`debt-decimals` cause `debt-usd` to be tiny.
2. `process-debt-asset` and `calc-final-liquidation-amounts` propagate this into a `debt-final` that, after `mul-div-down debt-final-usd (pow u10 debt-decimals) debt-price`, still rounds to a small nonzero token amount, but small enough that `mul-div-down debt-final INDEX-PRECISION borrow-index` in `scale-debt-for-liquidation` rounds down to `scaled-debt = u0` (possible when `borrow-index > debt-final * INDEX-PRECISION`). [5](#0-4) 
3. `coll-actual` (from `process-collateral-asset`, computed via the collateral asset's own price/decimals) is nonzero because the collateral asset's conversion factor differs from the debt asset's.
4. In `scale-debt-for-liquidation`, `scaled-to-remove = u0`, `debt-to-repay = u0`, and the guard `(< scaled-to-remove scaled-debt)` = `(< u0 u0)` is `false`, so `coll-final = coll-actual` (unscaled, full amount). [6](#0-5) 
5. The liquidation executes: attacker's `debt-to-repay` transfer is `0` while they receive `coll-final = coll-actual` collateral, extracting collateral for free.

(define-private (scale-debt-for-liquidation
  (debt-final uint)
  (coll-actual uint)
  (curr-scaled uint)
  (asset-id uint))
  (let (;; convert debt amount to scaled units for storage
        (borrow-index (get index (unwrap-panic (get-cached-indexes asset-id))))
        (scaled-debt (mul-div-down debt-final INDEX-PRECISION borrow-index))
        ;; cap at current debt (prevent over-repayment)
        (scaled-to-remove (if (> scaled-debt curr-scaled) curr-scaled scaled-debt))
        (debt-to-repay (mul-div-up scaled-to-remove borrow-index INDEX-PRECISION))
        ;; If debt was capped, scale collateral proportionally
        (coll-final (if (< scaled-to-remove scaled-debt)
                        (mul-div-down coll-actual scaled-to-remove scaled-debt)
                        coll-actual)))
    {
      scaled-to-remove: scaled-to-remove,
      debt-to-repay: debt-to-repay,
      coll-final: coll-final
    }))
