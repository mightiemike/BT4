### Title
Ethereum deployer private key accepted via `--deployer-key` command-line flag exposes it to local users - (File: `core/scripts/cre/reconciler/cmd.go`)

### Summary
The CRE reconciler CLI tool (used to deploy contracts, register capabilities on-chain, and configure Chainlink nodes for a Griddle-deployed nodeset) accepts a raw hex-encoded Ethereum private key via the `--deployer-key` command-line flag. Any local user on the host running the reconciler can read this key from `/proc/<pid>/cmdline`, `ps`, or similar tooling, exactly matching the Peggo bug class described in the external report.

### Finding Description
The flag is registered as a plain string CLI argument: [1](#0-0) 
and is declared alongside the rest of the shared CLI flags: [2](#0-1) 

The flag value is passed straight into `NewReconciler`, stored on the `Reconciler` struct as `deployerKey string`, and used (falling back to the well-known Anvil dev key only if empty) to build the on-chain transactor used to deploy/configure contracts: [3](#0-2) 

On Linux, any unprivileged local user can inspect another user's process arguments via `/proc/<pid>/cmdline` or `ps aux` unless `hidepid=2` is configured — the exact root cause identified in the Peggo report. Because the key is supplied as a bare CLI argument rather than being read from a file, environment variable with restricted permissions, or keyring, it is trivially exposed to any co-located user while the reconciler process is running.

Notably, this exact weakness is already flagged as a known, unresolved issue in the repo's own TODO backlog for this tool, which explicitly recommends moving to env-var-based per-chain keys and warns "Never log the keys": [4](#0-3) 

### Impact Explanation
An attacker with any unprivileged shell access on the same host (a CI runner, shared ops/bastion box, or Kubernetes node running the reconciler) can read the deployer's Ethereum private key from process listings while `reconciler apply` is running. Since this key signs on-chain deployment and configuration transactions for the CapabilitiesRegistry/WorkflowRegistry and other CRE contracts, compromise of the key allows an attacker to impersonate the deployer, submit unauthorized on-chain transactions, or drain any funds held by that address.

### Likelihood Explanation
Likelihood is moderate-to-high in shared or multi-tenant operational environments (CI pipelines, shared bastion hosts, Kubernetes nodes where `hidepid` is not set), since the flag is documented as a normal way to invoke the tool and defaults are provided only as a fallback rather than the primary path.

### Recommendation
Remove the `--deployer-key` command-line flag and instead source the private key from an environment variable read with restricted process/file permissions, a mounted secret file, or a keyring/KMS. If an environment variable is used, ensure it is never logged, and document that the CLI flag path is deprecated (this aligns with the reconciler's own TODO item H1, which already proposes `PRIVATE_KEY_<CHAIN_ID>` env vars in place of `--deployer-key`).

### Proof of Concept
1. On a shared Linux host without `hidepid=2,gid=0` proc mount options, run:
   `reconciler apply --desired cre/desired.toml --state cre/state.toml --deployer-key=<hex_private_key>`
2. As a second, unprivileged local user, run `ps aux | grep reconciler` or `cat /proc/<pid>/cmdline | tr '\0' ' '`.
3. Observe the full `--deployer-key` value, including the plaintext private key, in the output.

// NewReconciler creates a Reconciler from the CLI flags.
func NewReconciler(desiredPath, statePath, kubeconfig, env string, confirm, restartWorkerPods, waitAtBreakpoint bool, deployerKey string, log zerolog.Logger) (*Reconciler, error) {
	log.Info().Str("desired", desiredPath).Str("state", statePath).Msg("Loading desired state")

	ds, err := domain.LoadDesiredState(desiredPath)
	if err != nil {
		return nil, errors.Wrap(err, "failed to load desired state")
	}

	log.Info().Str("chartDir", ds.Infra.ChartValues).Str("env", env).Msg("Loading chart values from griddle.yaml")
	cv, err := domain.LoadChartValues(ds.Infra.ChartValues, env)
	if err != nil {
		return nil, errors.Wrap(err, "failed to load chart values")
	}
	log.Info().Int("nodes", len(cv.Nodes)).Str("namespace", cv.Namespace).Msg("Chart values loaded")

	// Cross-validate: each DON's name and node membership must exactly match
	// what Griddle registered with JD (chainlink-node.registerNodes.labels.don-name),
	// since that's the label JD job-proposal filters actually match against.
	if err = validateDONNamesAgainstChart(ds, cv); err != nil {
		return nil, errors.Wrap(err, "desired.toml does not match Griddle chart values")
	}

	// Load state
	state, err := domain.LoadState(statePath)
	if err != nil {
		return nil, errors.Wrap(err, "failed to load state")
	}
	if state == nil {
		state = &domain.StateFile{}
		log.Info().Msg("No existing state file — starting fresh")
	} else {
		log.Info().Str("phase", string(state.Phase)).Msg("Resuming from state")
	}

	// Create K8s client
	var k8s *infra.K8sClient
	if kubeconfig == "" {
		// Try KUBECONFIG env, then ~/.kube/config
		kubeconfig = os.Getenv("KUBECONFIG")
	}
	k8s, err = infra.NewK8sClient(kubeconfig, cv.Namespace, log)
	if err != nil {
		log.Warn().Err(err).Msg("K8s client creation failed — node discovery will be limited")
	} else {
		log.Info().Str("namespace", cv.Namespace).Msg("K8s client connected")
	}

	if deployerKey == "" {
		deployerKey = blockchain.DefaultAnvilPrivateKey
	}

	return &Reconciler{
		desired:           ds,
		state:             state,
		statePath:         statePath,
		cv:                cv,
		k8s:               k8s,
		nodeDialer:        clNodeDialer{},
		deployerKey:       deployerKey,
		log:               log,
		confirm:           confirm,
		restartWorkerPods: restartWorkerPods,
		waitAtBreakpoint:  waitAtBreakpoint,
	}, nil
}
