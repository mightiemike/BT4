## Analysis

The report's bug class is: **a fund-moving call returns a success/amount value that the caller never checks — only the "did-it-revert" error path is checked**, so a call that completes without reverting but signals `false`/`0` results in silently lost or unminted funds.

The Push Chain analog is in the module-as-sender deposit path used to mint PRC20 tokens for cross-chain inbound funds.

### Finding Description

`CallPRC20Deposit` and `CallPRC20DepositAutoSwap` invoke the `UniversalCore` handler contract's `depositPRC20Token` / `depositPRC20WithAutoSwap` methods via `DerivedEVMCall`, which returns `(*evmtypes.MsgEthereumTxResponse, error)`: [1](#0-0) [2](#0-1) 

The consuming code (`depositPRC20`, and the inbound execution flows) treats the deposit as successful purely based on whether the Go-level `err` is `nil` — it never inspects `receipt.Ret` (the ABI-encoded return payload of the call) for a success flag: [3](#0-2) [4](#0-3) 

The PRC20-family ABI entries in this codebase consistently model `deposit`, `burn`, and `transfer` as functions with a `bool` return value rather than an implicit revert-only contract: [5](#0-4) 

`DerivedEVMCall`/`err` only signals an EVM-level revert; it says nothing about the ABI-encoded boolean the handler contract returns for `depositPRC20Token`/`depositPRC20WithAutoSwap`. If the underlying `UniversalCore`/PRC20 mint logic can return `false` without reverting (e.g., a token's `LiquidityCap` is reached, as tracked in `TokenConfig.LiquidityCap` used by these deposit paths, or another internal guard chooses to fail soft rather than revert), the keeper still marks the PCTx as `"SUCCESS"`: [6](#0-5) 

Because the deposit is recorded as `SUCCESS`, non-CEA inbounds do not get an `INBOUND_REVERT` outbound created, and `AttachRescueOutboundFromReceipt` explicitly refuses to rescue funds once the first PCTx is `SUCCESS`: [7](#0-6) 

### Impact Explanation

If the deposit call returns `false` without reverting, the recipient (UEA or EOA) never receives the PRC20 tokens, yet the `UniversalTx` is finalized as `SUCCESS`, no revert outbound is created, and the rescue-funds path is blocked because it only fires when the deposit PCTx explicitly failed. The bridged value is effectively burned — the source-chain funds are consumed (or already locked pending consensus) but no compensating PRC20 balance is minted on Push Chain and no path exists to recover it. This is a permanent loss of user/protocol-controlled funds, matching the "in-scope" invariant around PRC20 accounting and inbound fund crediting.

### Likelihood Explanation

This requires the `UniversalCore` handler's deposit/mint logic to have at least one code path that legitimately returns `false` instead of reverting (e.g., a soft liquidity-cap check, a paused/disabled token path, or similar). I was not able to fully confirm from the indexed Go repository whether the Solidity handler implementation guarantees "always revert, never return false" for `depositPRC20Token`/`depositPRC20WithAutoSwap` — that logic lives in `push-chain-core-contracts`, which is outside this repo's index. The Go-side keeper code, in isolation, structurally reproduces the reported anti-pattern (checking only the call error, never the returned boolean), so the residual risk is entirely contingent on the Solidity contract's behavior.

### Recommendation

Decode `receipt.Ret` from `DerivedEVMCall` for `depositPRC20Token` / `depositPRC20WithAutoSwap` (and similarly for `refundUnusedGas` / `executeUniversalTx` where a boolean/status is returned) and treat a `false` return the same as an error — i.e., surface it as `execErr`/`FAILED` PCTx status and route it through the existing revert/rescue machinery, rather than relying solely on the absence of a Go-level `err`.

### Proof of Concept

Not independently reproducible from this repository alone, since the exact conditions under which the `UniversalCore` Solidity contract would return `false` instead of reverting live in `push-chain-core-contracts` (out of index). The Go-side gap itself is directly demonstrable by inspecting `depositPRC20`/`CallPRC20Deposit` and confirming no branch inspects `receipt.Ret` for the ABI-declared boolean output before marking the PCTx `"SUCCESS"`.

// Calls Handler Contract to deposit prc20 tokens
func (k Keeper) CallPRC20Deposit(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // sender: module account
		handlerAddr,        // destination
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20Token",
		prc20Address,
		amount,
		to,
	)
}

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}
