### Title
OAuth begin nonce cookie (`shopify_app_state`) is scoped by `callbackPath` instead of per-shop, causing cross-tenant nonce clobbering in multi-shop non-embedded apps - (File: `packages/apps/shopify-api/lib/auth/oauth/oauth.ts`)

### Summary
The Convex report describes a shared/global accounting slot (`reward.remaining`) that is meant to be tracked per logical unit (per pool) but is actually clobbered by unrelated concurrent operations sharing the same reward token, corrupting state and breaking subsequent calls. The analogous defect in `shopify-app-js` is in the OAuth "begin" handler: the CSRF nonce cookie (`shopify_app_state`) is written with `path: callbackPath` [1](#0-0)  — a value that is identical for every shop in a typical non-embedded app (a single fixed `/auth/callback` route). This is the same class of "shared slot meant to be per-tenant, but keyed by something coarser" bug that the maintainers already had to fix for the *session* cookie via the new `cookiePath` option.

### Finding Description
When `begin()` is invoked for shop A, it sets a signed cookie `shopify_app_state` scoped to `path: callbackPath` [1](#0-0) . If the same browser starts a second OAuth flow for shop B (e.g., a second tab/app instance, or the app supports multiple shops as documented in the changelog scenario), `begin()` sets a new `shopify_app_state` cookie with the exact same name and exact same path, silently overwriting shop A's nonce cookie — because the path only depends on `callbackPath`, not on `shop`.

This mirrors the confirmed root cause the maintainers already fixed for the *session* cookie: "all shops shared a single `shopify_app_session` cookie at `path=/`, so authenticating a new shop would silently overwrite the previous shop's session," fixed via the new `cookiePath` config option [2](#0-1)  and the accompanying `cookiePath` config documentation [3](#0-2) . However, that fix was only applied to the callback's session-cookie write path [4](#0-3) , not to the `begin()` nonce cookie, which still uses the shop-independent `callbackPath`.

When shop A's OAuth callback later arrives at Shopify's redirect, `callback()` reads and verifies `stateFromCookie` [5](#0-4)  and compares it against the `state` query param via `safeCompare` in `validQuery` [6](#0-5) . Because the cookie was clobbered by shop B's more recent `begin()` call, the comparison fails, and the flow throws `InvalidOAuthError`, aborting shop A's install/login. This is the exact "shared, unscoped state gets overwritten by an unrelated concurrent operation" defect from the report, applied to the CSRF nonce rather than a reward balance.

### Impact Explanation
For any non-embedded, multi-shop-capable app (the precise scenario the maintainers called out when adding `cookiePath`), concurrent OAuth flows for different shops in the same browser will corrupt each other's CSRF nonce cookie, causing the OAuth callback to fail with `InvalidOAuthError` or `CookieNotFound` for one of the shops. This is a denial-of-service of the authentication handler for legitimate, unprivileged users attempting normal multi-tenant usage, directly reachable from an anonymous browser session performing the documented OAuth flow.

### Likelihood Explanation
This is highly likely to occur in practice for any deployment matching the exact use case the `cookiePath` feature was built for (multiple shops open in separate tabs of the same non-embedded app), since it requires no attacker action — just two normal OAuth flows started closely together in the same browser profile.

### Recommendation
Scope the `begin()` nonce cookie's path the same way the session cookie now is — i.e., accept/derive a per-shop path (or otherwise namespace the cookie by shop) for `STATE_COOKIE_NAME`, consistent with the `cookiePath` option already used for `SESSION_COOKIE_NAME` in `callback()` [7](#0-6) .

### Proof of Concept
1. Configure a non-embedded app without a shop-specific `cookiePath` (default `path: '/'` for session cookie is not directly relevant here; the relevant fixed value is `callbackPath` for the state cookie), with `callbackPath` fixed (e.g., `/auth/callback`) for all shops.
2. In one browser, open `/auth?shop=shopA.myshopify.com`. `begin()` sets `shopify_app_state` at `path=/auth/callback` with nonce N_A [1](#0-0) .
3. In another tab of the same browser, open `/auth?shop=shopB.myshopify.com`. `begin()` overwrites the same `shopify_app_state` cookie at the same path with nonce N_B.
4. Complete Shopify's OAuth redirect back for shop A with `state=N_A`. `callback()` reads the cookie, now containing N_B, and `safeCompare(query.state, stateFromCookie)` fails [6](#0-5) , throwing `InvalidOAuthError` and blocking shop A's installation/login.

- c439dab: Add `cookiePath` config option for multi-shop non-embedded apps

  Non-embedded apps that need to support multiple shops simultaneously in
  separate browser tabs were affected by a cookie collision: all shops shared
  a single `shopify_app_session` cookie at `path=/`, so authenticating a new
  shop would silently overwrite the previous shop's session.

  The new optional `cookiePath` config option lets you scope the session
  cookie to a shop-specific URL prefix, so each shop's cookie coexists
  independently in the browser.

  ```ts
  // Static path (default behaviour, unchanged)
  cookiePath: '/';

  // Factory function — recommended for multi-shop apps
  cookiePath: (session) => `/shops/${session.shop}/`;
  ```

  **Requirement:** the configured path must match your app's URL structure.
  Each shop must be served under a distinct URL prefix for the browser to
  deliver the correct cookie per request.
```

   * The path to use for the OAuth session cookie in non-embedded apps.
   *
   * By default the cookie is written with `path: '/'`, making it domain-wide.
   * This means that when a user authenticates multiple shops in separate tabs,

   * // Static path (single-shop apps or apps with no shop-specific routing)
   * cookiePath: '/'
   *
   * @example
   * // Factory function (multi-shop non-embedded apps)
   * cookiePath: (session) => `/shops/${session.shop}/`
   *
   * @defaultValue `'/'`
