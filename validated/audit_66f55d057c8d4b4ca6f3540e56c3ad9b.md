### Title
`accept_new_txs` admission-control pause is not enforced on the mempool-P2P ingestion path into the Gateway - (File: `crates/apollo_mempool_p2p/src/runner/mod.rs`)

### Summary
The sequencer exposes a "pause new transactions" admission-control flag (`HttpServerDynamicConfig.accept_new_txs`) that operators use to stop a node from admitting new transactions into its mempool/pipeline. This flag is checked only on the HTTP ingestion path, not on the second path into the same `Gateway::add_tx`/mempool-admission logic used by the mempool-P2P runner.

### Finding Description
`add_rpc_tx` and `add_tx` in the HTTP server explicitly gate transaction admission behind the dynamic config flag before forwarding to the gateway: [1](#0-0) [2](#0-1) 

`check_new_transactions_are_allowed` returns `HttpServerError::DisabledError()` when `accept_new_txs` is false: [3](#0-2) 

However, the same `Gateway::add_tx` entrypoint is also reachable directly from the `MempoolP2pRunner`, which forwards every transaction received via network gossip straight to the gateway client with no admission-pause check at all: [4](#0-3) 

Inside the gateway itself (`GenericGateway::add_tx_inner`), there is no check of `accept_new_txs` or any equivalent pause state — it always runs stateless/stateful validation and forwards to the mempool once validation passes: [5](#0-4) 

Because `accept_new_txs` lives only in the HTTP server's per-node `AppState`/`HttpServerDynamicConfig`, it never propagates to the `Gateway` component or the `MempoolP2pRunner`. As a result, "pausing" transaction admission by flipping `accept_new_txs` to `false` (e.g., an operator draining a node for maintenance, capacity control, or emergency mitigation) only blocks the local HTTP `/gateway/add_transaction` and `/gateway/add_rpc_transaction` endpoints; the same node keeps admitting transactions gossiped from peers through the P2P path directly into its `Gateway`/mempool.

### Impact Explanation
This breaks the intended semantics of the pause mechanism: an operator relying on `accept_new_txs=false` to stop the local mempool/pipeline from accepting new work (e.g., to prevent block proposals from including new transactions during a controlled halt, upgrade, or incident response) will still have their mempool populated and can still propose/validate blocks containing "new" transactions admitted via gossip. This is a functional/availability-control bypass analogous to the reported bug class (a state-changing action proceeding despite an active pause), reachable purely by an unprivileged party submitting a transaction to any other node in the network, which then gossips it to the paused node. This does not require a malicious peer or p2p exploit — it is simply the P2P-forwarding code path never consulting the pause flag that the HTTP path enforces.

### Likelihood Explanation
High likelihood of occurring whenever `accept_new_txs` is toggled off while the mempool-P2P component remains active (its default execution mode is enabled) — any transaction broadcast by peers, including ones submitted by ordinary unprivileged users on other honest nodes, will bypass the pause. No special conditions or malicious behavior are required beyond normal transaction gossip.

### Recommendation
Propagate the `accept_new_txs` (or an equivalent pause) state into the `Gateway`/`GenericGateway` component itself (e.g., via `GatewayConfig`'s dynamic config or a shared config-manager value), and check it inside `add_tx_inner` before performing validation/forwarding, so both the HTTP-originated and P2P-originated paths are gated consistently. Alternatively, have `MempoolP2pRunner` consult the same dynamic-config source before invoking `gateway_client.add_tx`.

### Proof of Concept
1. Operator sets `accept_new_txs=false` on Node A via the config manager, intending to stop Node A from admitting new transactions.
2. Node A's HTTP `/gateway/add_transaction` now rejects all submissions with `DisabledError` [3](#0-2) .
3. An unprivileged user submits a valid transaction to Node B (which has `accept_new_txs=true`).
4. Node B's mempool P2P propagator broadcasts the transaction over the network.
5. Node A's `MempoolP2pRunner` receives the broadcast and calls `gateway_client.add_tx(GatewayInput { rpc_tx, message_metadata })` unconditionally [6](#0-5) .
6. Node A's `Gateway::add_tx_inner` performs no pause check and, upon successful validation, forwards the transaction to Node A's local mempool [7](#0-6) .
7. The transaction is now in Node A's mempool despite the operator's intent to pause new-transaction admission on Node A.

    async fn add_tx_inner(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        let mut metric_counters = GatewayMetricHandle::new(&tx, &p2p_message_metadata);
        metric_counters.count_transaction_received();
        if let RpcTransaction::Invoke(RpcInvokeTransaction::V3(ref inv)) = tx {
            if !inv.proof_facts.is_empty() {
                metric_counters.count_private_transaction_received();
            }
        }
        let is_p2p = p2p_message_metadata.is_some();

        if let RpcTransaction::Declare(ref declare_tx) = tx {
            if let Err(e) = self.check_declare_permissions(declare_tx) {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        }

        // Perform stateless validations.
        self.stateless_tx_validator.validate(&tx)?;

        let tx_signature = tx.signature().clone();

        // Declare conversions overload the compiler component's CPU and memory. Reject declares if
        // there are too many declares compiling in parallel. The permit is held only across
        // compilation and released before stateful validation.
        let compilation_permit = if matches!(tx, RpcTransaction::Declare(_)) {
            Some(self.declare_compilation_semaphore.try_acquire().map_err(|_| {
                let error = StarknetError::too_many_concurrent_declare_compilations();
                metric_counters.record_add_tx_failure(&error);
                error
            })?)
        } else {
            None
        };

        let (internal_tx, executable_tx, proof_data) =
            self.convert_rpc_tx_to_internal_and_executable_txs(tx, &tx_signature).await?;
        drop(compilation_permit);

        let mut stateful_transaction_validator = self
            .stateful_tx_validator_factory
            .instantiate_validator(self.config.dynamic_config.native_classes_whitelist.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let nonce = stateful_transaction_validator
            .extract_state_nonce_and_run_validations(&executable_tx, self.mempool_client.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let proof_archive_handle = self
            .store_proof_and_spawn_archiving(proof_data, internal_tx.tx_hash, is_p2p)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let gateway_output = create_gateway_output(&internal_tx);

        let add_tx_args = AddTransactionArgsWrapper {
            args: AddTransactionArgs::new(internal_tx, nonce),
            p2p_message_metadata,
        };

        // Await as late as possible for proof archiving before sending the transaction to the
        // mempool.
        Self::await_proof_archiving(proof_archive_handle)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let mempool_client_result = self.mempool_client.add_tx(add_tx_args).await;
        match mempool_client_result_to_deprecated_gw_result(&tx_signature, mempool_client_result) {
            Ok(()) => {}
            Err(e) => {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        };

        metric_counters.transaction_sent_to_mempool();

        Ok(gateway_output)
    }
