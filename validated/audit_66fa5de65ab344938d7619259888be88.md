## Analog Found: ChainMeta Gas-Price Oracle Loses Quorum Protection After Bootstrap

### Title
Gas-price/chain-height oracle anchor (`LastAppliedChainHeight`) can be redefined by a single stale-recovery vote after bootstrap, with no deviation check against the prior value - (File: `x/uexecutor/keeper/chain_meta.go`)

### Summary
The reported `OracleAdapterV4` bug is: even when the contract detects a divergence between price feeds (tripping the circuit breaker), it still commits the disputed value into `lastGoodPrice`, the anchor other logic later trusts. The closest analog in Push Chain is `VoteChainMeta`, which maintains `ChainMeta.LastAppliedChainHeight` (and the mirrored EVM gas-price oracle) as the trusted anchor for gas pricing used across the protocol. Like `lastGoodPrice`, this anchor is written without any check that the value committing it is actually corroborated, once the initial bootstrap gate is passed.

### Finding Description
`VoteChainMeta` enforces a minimum-fresh-vote quorum (`chainMetaMinVotesForFirstWrite = 3`) **only** on the very first EVM write (`!bootstrapped`) [1](#0-0) . After that, every subsequent vote recomputes the median purely from whichever votes are still "fresh" (stored within `chainMetaVoteStalenessSeconds` = 300s) [2](#0-1) , with **no re-imposed minimum count and no deviation/outlier check** between the new median and the prior `LastAppliedChainHeight`/price before it is pushed to the EVM oracle and persisted as the new anchor [3](#0-2) .

If most Universal Validators' votes simply age past the 300-second staleness window (normal operational lag, RPC hiccups, or a temporarily quiet chain) while a single validator re-votes, that one validator's report alone becomes the "fresh" pool and is written straight to the trusted anchor — exactly the "update the anchor with an uncorroborated value" pattern from the report, just without an explicit circuit-breaker being tripped first (there isn't one at all here).

This is directly demonstrated by the existing integration test: after 3 validators agree at ~[100,200,300], once their votes go stale, a single re-vote of `900` (a large divergence from the prior consensus) becomes the value applied to `LastAppliedChainHeight` and pushed on-chain via `gasPriceByChainNamespace` [4](#0-3) .

### Impact Explanation
This gas-price/chain-height anchor is consumed elsewhere in the accounting path — for example `x/utss` fund migration populates `GasLimit`/`GasPrice`/`L1GasFee` from the same UniversalCore per-chain mappings that `VoteChainMeta` writes [5](#0-4) . A single uncorroborated vote silently redefining the network-wide gas price/chain-height anchor corrupts downstream gas-fee accounting (fund migration fee estimation, and any other consumer of `gasPriceByChainNamespace`/`chainHeightByChainNamespace`) without requiring any malicious or privileged actor — it can occur under ordinary operational timing alone.

### Likelihood Explanation
Medium-to-low: it requires the "fresh" window (300s) to empty out to a single voter, which depends on validator vote cadence/liveness rather than a directly attacker-triggered action. It does not require any malicious validator, collusion, or privileged access — only normal timing where most UVs haven't refreshed their vote within 5 minutes while one has.

### Recommendation
- Re-apply a minimum-fresh-vote quorum check (not just on first bootstrap) before allowing any EVM oracle write / `LastAppliedChainHeight` update.
- Add a deviation check between the newly computed median and the previously applied value; if it exceeds a safe threshold, hold at the prior value (or require additional corroborating votes) rather than immediately committing the outlier, mirroring the audit's recommendation to not anchor on disputed data.

### Proof of Concept
See the existing regression test that already documents this exact behavior: `TestVoteChainMetaIntegration/stale_votes_excluded_from_median` [6](#0-5)  — 3 validators establish a median of ~200 from [100,300,200]; after their votes go stale, a single re-vote of `900` alone becomes the new applied median, verified directly against the EVM contract state.

	t.Run("stale votes excluded from median", func(t *testing.T) {
		testApp, ctx, uvals, vals := setupVoteChainMetaTest(t, 3)

		coreAccs := make([]string, 3)
		for i := range vals {
			coreVal, _ := sdk.ValAddressFromBech32(vals[i].OperatorAddress)
			coreAccs[i] = sdk.AccAddress(coreVal).String()
		}

		// All 3 validators vote at T. Heights 1, 2, 3 to pass lastApplied checks.
		require.NoError(t, utils.ExecVoteChainMeta(t, ctx, testApp, uvals[0], coreAccs[0], chainId, 100, 1))
		require.NoError(t, utils.ExecVoteChainMeta(t, ctx, testApp, uvals[1], coreAccs[1], chainId, 300, 2))
		require.NoError(t, utils.ExecVoteChainMeta(t, ctx, testApp, uvals[2], coreAccs[2], chainId, 200, 3))

		// After all 3 votes at T: sorted prices [100,200,300], upper median=200. lastApplied = median height = 2.
		stored, _, _ := testApp.UexecutorKeeper.GetChainMeta(ctx, chainId)
		require.Equal(t, uint64(2), stored.LastAppliedChainHeight)

		// Advance block time by 301 seconds — old votes become stale.
		ctx = ctx.WithBlockTime(ctx.BlockTime().Add(301 * time.Second))

		// val0 re-votes with price=900, height=3 (> lastApplied=2).
		// Only this fresh vote contributes to the new median.
		require.NoError(t, utils.ExecVoteChainMeta(t, ctx, testApp, uvals[0], coreAccs[0], chainId, 900, 3))

		stored, found, err := testApp.UexecutorKeeper.GetChainMeta(ctx, chainId)
		require.NoError(t, err)
		require.True(t, found)
		// LastAppliedChainHeight should now be 3 (only fresh vote: height=3)
		require.Equal(t, uint64(3), stored.LastAppliedChainHeight)

		// Verify the applied price via EVM contract — only val0's fresh vote (900) should have been used,
		// not the stale votes (100, 300). MedianIndex on the stored entry reflects the full-slice
		// median, so we must query the contract directly for the actually-applied value.
		universalCoreAddr := utils.GetDefaultAddresses().HandlerAddr
		ucABI, err := uexecutortypes.ParseUniversalCoreABI()
		require.NoError(t, err)
		caller, _ := testApp.UexecutorKeeper.GetUeModuleAddress(ctx)
		res, err := testApp.EVMKeeper.CallEVM(ctx, ucABI, caller, universalCoreAddr, false, nil, "gasPriceByChainNamespace", chainId)
		require.NoError(t, err)
		appliedPrice := new(big.Int).SetBytes(res.Ret)
		require.Equal(t, new(big.Int).SetUint64(900), appliedPrice, "stale votes must not influence the applied median price")
	})
