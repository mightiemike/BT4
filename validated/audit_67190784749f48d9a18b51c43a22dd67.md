### Title
Missing "class must be declared" check in the Starknet OS `execute_replace_class` allows sequencer/OS execution divergence on `replace_class` - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Blockifier (the sequencer's actual transaction-execution engine) rejects the `replace_class` syscall when the target `class_hash` is not a declared Cairo1 class. The Starknet OS's Cairo re-implementation of the same syscall, used to re-execute the block for proving/state-commitment purposes, does not perform this check — it is marked with an explicit `TODO` and unconditionally overwrites the contract's class hash. This is directly analogous to the Punk Protocol root cause: a state-mutating operation (`forgeAddress`/class-hash assignment) is executed without the modifier/validation that the rest of the system assumes is enforced.

### Finding Description
`syscall_base.rs::replace_class` in the Blockifier explicitly validates that the class is declared and is a Cairo1 class before mutating state: [1](#0-0) 

The Starknet OS's Cairo implementation of the identical syscall (`execute_replace_class` in `syscall_impls.cairo`), which is executed by the prover when re-running the block to produce the state diff / proof that ultimately determines the committed root, performs no such check — the comment explicitly flags this as unimplemented: [2](#0-1) 

The legacy/deprecated Cairo0 syscall path in the OS has the identical gap (no check at all, not even a TODO): [3](#0-2) 

Blockifier's own tests confirm the check is load-bearing for consensus: an undeclared-class `replace_class` call is rejected with `"is not declared"`, and a Cairo0-class replacement is rejected with `"Cannot replace V1 class hash with V0 class hash"`: [4](#0-3) 

Because the sequencer builds the block (and decides whether a transaction reverts) using the Blockifier, while the Starknet OS re-executes the same transactions in Cairo to produce the final state diff / commitment for proving, a transaction that calls `replace_class` with an undeclared (or Cairo0) class hash will be **rejected/reverted by the Blockifier** but **silently accepted by the OS**, since the OS lacks the "declared and Cairo1" gate. This creates a divergence between what the sequencer committed (based on Blockifier's revert decision) and what the OS computes when re-executing/proving the same block.

### Impact Explanation
This maps to the "wrong committed root or block hash / honest-node divergence" impact category. If the OS accepts a `replace_class` to an undeclared class hash that the Blockifier would have reverted, the OS's re-execution produces a different state diff (and therefore a different Patricia root/state commitment) than what the sequencer's Blockifier execution produced and broadcast for that block. This is a correctness/consensus-safety gap for the proving pipeline that turns the block's committed state into an unprovable or incorrectly-provable state, and — because the class hash pointed at by the OS's uncontrolled write need never correspond to any real compiled class — could permit assigning an arbitrary/unvalidated class hash to a contract's storage entry inside the OS's execution model, which the OS may then treat as authoritative for subsequent contract-address/class-hash reads within the same block trace.

### Likelihood Explanation
Reachable directly from any unprivileged contract via `replace_class_syscall`/`replace_class` (Cairo1 and legacy syscall paths) with a `class_hash` argument fully controlled by the caller — no special privileges are needed, matching the "unauthorized account action" surface listed in the rules (analogous to the attacker controlling `forgeAddress` via `initialize()`). The gap is explicitly acknowledged in the code via a `TODO(Yoni, 1/1/2026)` comment, indicating the maintainers are aware the check is currently missing in the OS implementation.

### Recommendation
Add the same "class hash must be declared, and must not be replaced with a Cairo0 class" validation to `execute_replace_class` in `syscall_impls.cairo` (and the legacy Cairo0 path in `deprecated_execute_syscalls.cairo`) that already exists in `crates/blockifier/src/execution/syscalls/syscall_base.rs`, ensuring the OS's revert/acceptance behavior for `replace_class` is identical to the Blockifier's, so that the sequencer and the OS re-execution never diverge on this syscall.

### Proof of Concept
I could not fully verify at what stage (if any) an out-of-band commitment validator (e.g., `crates/starknet_transaction_prover/src/running/committer_utils.rs::validate_virtual_os_state_diff`) might catch an undeclared class hash before final commitment, as I ran out of tool iterations to inspect that function's body. This is a caveat on the exploitability/likelihood of the finding: if a downstream validator rejects state diffs containing undeclared class hashes, the practical impact would be reduced to a proving failure/DoS rather than a silently wrong committed root. A concrete PoC would be: an unprivileged contract calls `replace_class_syscall(undeclared_class_hash)`; observe the Blockifier reverts the call with `"is not declared"` (per `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`), while tracing the OS Cairo hint execution of `execute_replace_class` shows no equivalent rejection path before the `dict_update` write.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
