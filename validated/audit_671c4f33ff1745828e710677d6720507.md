### Title
Unbounded `PendingInbounds` Walk in `AfterBallotTerminal` Enables Quadratic-Cost DoS on Universal Execution Finalization - (File: `x/uexecutor/keeper/ballot_hooks.go`)

### Summary
`PoolCommitter`'s DoS stemmed from an unbounded, iteratively-executed commit queue with no per-item minimum size. Push Chain's `x/uexecutor` module has a structurally identical pattern: every inbound observation (triggered by an ordinary, unprivileged external-chain deposit with no enforced minimum amount) creates an entry in the `PendingInbounds` collection, and every single ballot terminal transition — which fires automatically once validators vote — performs a full linear `Walk` over the *entire* `PendingInbounds` map to find the matching entry. As an attacker floods the source-chain gateway with many low-value inbound events, this lookup cost grows with the size of the pending set, and total processing cost across all attacker-induced ballots grows quadratically, degrading (and potentially exhausting) `DeliverTx` gas for wholly unrelated, honest inbound votes.

### Finding Description
`Inbound.ValidateForExecution` in `x/uexecutor/types/inbound.go` only requires `amount` to be non-negative, and explicitly permits `amount == 0` for `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` tx types: [1](#0-0) 
There is no minimum-value floor comparable to a "minimum commit size."

Each unique inbound (`source_chain:tx_hash:log_index`) is recorded into the `PendingInbounds` collection on the first validator vote via `RecordInboundVote`, which appends a new entry/variant keyed by the derived `utx_key`/`ballot_id`: [2](#0-1) 

When a validator vote finalizes the underlying ballot in `x/uvalidator`, `fireBallotTerminalHook` synchronously calls into `x/uexecutor`'s `BallotHooks.AfterBallotTerminal`: [3](#0-2) 

`afterInboundBallotTerminal` locates the owning entry by performing a full, unbounded `Walk` over *all* entries in `PendingInbounds`, explicitly justified in-code by the assumption that "the pending set is small and transient": [4](#0-3) 

That assumption is attacker-controllable: an unprivileged user can generate an arbitrary number of distinct, cheap gateway events on any supported source chain (each with a unique `tx_hash`/`log_index`, satisfying only `amount > 0`, or `amount == 0` for payload types), causing Universal Validators to vote each one via `MsgVoteInbound` in the normal course of their honest duty. Each such vote grows `PendingInbounds` by one entry before its own ballot finalizes. Because ballot finalization (and thus the `Walk`) fires once per ballot, and the queue keeps growing while older/newer entries are concurrently pending (finalization requires waiting on 2/3+ votes and possibly multiple blocks), the cost of each `AfterBallotTerminal` invocation scales with the live size of `PendingInbounds`, and the aggregate cost across N attacker-seeded entries is O(N²).

This directly mirrors the reported bug class: no minimum commit/deposit size, and an unbounded queue walked/iterated on every settlement event, driving up gas costs for the routine per-block/per-tx processing that all validators and users depend on.

### Impact Explanation
This is a non-network-level, chain-state-based denial of service reachable by any unprivileged actor who can submit low-value/zero-value transactions to a supported source-chain gateway. As `PendingInbounds` grows, `MsgVoteInbound` processing (which honest, non-malicious Universal Validators must perform for every legitimate user's inbound, including funds deposits) becomes progressively more expensive per finalizing vote. In the worst case this can push `DeliverTx` gas consumption for inbound-vote transactions toward the block gas limit, causing vote transactions to fail, throttling/blocking the finalization of legitimate user inbounds (deposits, PRC20 mints, payload execution) — a material state-safety/availability impact on the universal execution finalization path, without requiring any privileged actor.

### Likelihood Explanation
Triggering requires only the ability to submit ordinary (non-privileged) transactions on an external supported chain to the gateway contract, which is the standard user-facing entry point for the whole crosschain bridge. No admin, validator, or TSS compromise is needed — Universal Validators behave honestly and simply relay/vote on what they observe, which is exactly the trigger. The only friction is the source-chain gas cost of generating many events and the source-chain block-confirmation wait before UVs vote, both of which are inexpensive relative to potential chain-wide disruption, similar to the original report's economic framing.

### Recommendation
- Enforce a minimum `amount` for `FUNDS`/`GAS` (and consider a minimum for zero-amount payload types, e.g., minimum fee/gas requirement) in `Inbound.ValidateForExecution` to raise the cost of generating spam inbound events.
- Bound `PendingInbounds` size/age (e.g., cap concurrent pending entries per source chain/sender, or evict/reject beyond a max) to prevent unbounded growth.
- Replace the linear `Walk` in `afterInboundBallotTerminal` with a direct lookup (e.g., an auxiliary index from `ballot_id` → `utx_key`) so the terminal-hook cost is O(1) regardless of pending-set size, removing the reliance on the "pending set is small" assumption.

### Proof of Concept
1. An attacker (no privileged role required) repeatedly calls the source-chain gateway contract with the minimum allowed non-zero amount (or amount `0` for `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD`), each with a unique tx hash/log index, at negligible source-chain gas cost.
2. Universal Validators, acting honestly per protocol, observe and submit `MsgVoteInbound` for each event; `RecordInboundVote` (`x/uexecutor/keeper/inbound.go`) adds a new `PendingInboundEntry` per event.
3. As votes accumulate and each ballot finalizes, `AfterBallotTerminal` → `afterInboundBallotTerminal` (`x/uexecutor/keeper/ballot_hooks.go:86`) walks the full, ever-growing `PendingInbounds` collection to resolve each ballot.
4. Repeating steps 1–3 at scale drives the per-vote processing cost upward across the network, degrading throughput/finalization for all concurrent legitimate inbound votes and deposits without any single "flagship" transaction exceeding limits individually — the compounding cost across the flood is the attack.

func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

func (k Keeper) RecordInboundVote(
	ctx context.Context,
	inbound types.Inbound,
	voter string,
	ballotID string,
) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	height := uint64(sdkCtx.BlockHeight())
	utxKey := types.GetInboundUniversalTxKey(inbound)

	entry, err := k.PendingInbounds.Get(ctx, utxKey)
	if err != nil && !errors.Is(err, collections.ErrNotFound) {
		return err
	}
	if errors.Is(err, collections.ErrNotFound) {
		entry = types.PendingInboundEntry{
			UtxKey:          utxKey,
			CreatedAtHeight: height,
		}
	}

func (h BallotHooks) afterInboundBallotTerminal(
	ctx context.Context,
	ballotID string,
	status uvalidatortypes.BallotStatus,
) error {
	// Ballot IDs are one-way canonical digests (not reversible), so locate
	// the owning audit-trail entry by scanning PendingInbounds for the
	// variant carrying this ballot ID. The pending set is small and
	// transient, and this hook only fires on terminal transitions.
	var (
		utxKey string
		entry  types.PendingInboundEntry
		found  bool
	)
	err := h.k.PendingInbounds.Walk(ctx, nil, func(key string, e types.PendingInboundEntry) (bool, error) {
		for _, v := range e.Variants {
			if v.BallotId == ballotID {
				utxKey, entry, found = key, e, true
				return true, nil
			}
		}
		return false, nil
	})
	if err != nil {
		return err
	}
