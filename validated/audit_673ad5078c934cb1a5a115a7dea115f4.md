### Title
Unbounded free account creation via gasless-tx first-use `AccountInitDecorator` enables state-bloat DoS - (File: `app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator` lets any never-before-seen address create a real on-chain `BaseAccount` at zero cost, as long as the address is the sole signer of a transaction whose messages are all in the gasless whitelist (`app/txpolicy/gasless.go`), and the tx carries a self-consistent signature verified against a hard-coded `account_number=0, sequence=0`. Because this decorator runs in the AnteHandler and precedes fee/gas checks that are themselves skipped for gasless txs, an attacker can mint unlimited fresh keypairs off-chain (free) and submit unlimited such transactions to permanently grow validator state with zero economic cost, even when the wrapped message itself is garbage and fails downstream execution.

### Finding Description
`app/ante/account_init_decorator.go` runs before all signature-verification decorators in the Cosmos ante chain [1](#0-0) . For a gasless transaction (`MsgExecutePayload`, `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration` per `IsGaslessTx`) whose sole signer has no existing account, it:

1. Verifies the tx signature against a hard-coded `account_number=0, sequence=0` (not the real, monotonically-assigned account number) [2](#0-1) .
2. On success, unconditionally creates the account and writes it to state: `acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr); acc.SetSequence(1); aid.ak.SetAccount(ctx, acc)` [3](#0-2) .

`MsgVoteFundMigration`/`MsgVoteInbound`/etc. are the intended use case (funding a fresh Universal Validator hot key for its first vote), but `MsgExecutePayload` is explicitly documented as callable by "any account" with no `Signer == Owner` binding requirement [4](#0-3) . Its `ValidateBasic` only requires a valid bech32 signer, a non-nil `UniversalAccountId`/`UniversalPayload`, and a hex-decodable `VerificationData` string — none of which need to correspond to any real UEA, owner, or valid signature [5](#0-4) .

Because `MinGasPriceDecorator` and `DeductFeeDecorator` both explicitly bypass their checks for gasless txs [6](#0-5) [7](#0-6) , there is no fee, minimum-gas-price, or pre-funding requirement anywhere in the pipeline for this class of transaction. In standard Cosmos SDK `runTx`, AnteHandler-side state writes (via the ante `CacheMultiStore`) are committed to the parent store as soon as the AnteHandler chain succeeds, independent of whether the subsequent message execution (`runMsgs`) later fails and is rolled back. This means the account object created by `AccountInitDecorator` survives on-chain even when the wrapped `MsgExecutePayload` is intentionally garbage (e.g., an invalid `UniversalAccountId.Owner`, or `VerificationData` that will never recover to any real UEA owner) and reverts during message handling.

### Impact Explanation
An unprivileged external attacker can generate arbitrary numbers of throwaway keypairs offline (computationally free) and, for each one, submit a single self-signed, gasless `MsgExecutePayload` transaction with garbage contents. Every such transaction permanently writes one new `BaseAccount` into the auth module's KV store at zero cost — no minimum gas price, no fee, no pre-funding, and no economic deterrent whatsoever, since the whole point of the gasless whitelist is that no balance is required. This is unauthorized, unbounded state growth reachable via ordinary unprivileged transaction submission, matching the in-scope "denial of service ... reachable without privileged control" and "corruption of ... canonical state" impact classes. Sustained abuse inflates chain state size (and therefore snapshot/sync/IAVL-proof costs for every full node and light client) indefinitely, degrading the network's operational health without requiring the attacker to hold or spend any PC tokens.

### Likelihood Explanation
High. The attack requires no special access, no validator status, and no capital — only the ability to generate Ed25519/secp256k1 keypairs and broadcast transactions, which any internet participant can do. `MsgExecutePayload` is explicitly designed to accept "any account" as `Signer`, so the entry point is intentionally open to the public. The only "cost" to the attacker is CPU time to generate keys and bandwidth to broadcast — both negligible compared to the permanent on-chain storage burden imposed on every node.

### Recommendation
- Rate-limit or economically gate first-use account creation for gasless txs, e.g., require a minimal non-zero fee/deposit specifically for the account-creation path even though the wrapped message itself is fee-exempt, or cap the number of new-account creations processable per block from unbonded/unknown signers.
- Restrict the gasless allowlist so that account auto-creation via `AccountInitDecorator` only applies to messages whose signer is provably a bonded Universal Validator (e.g., `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`), and exclude `MsgExecutePayload` (whose `Signer` is explicitly untrusted/arbitrary) from triggering free account creation.
- Alternatively, defer the `SetAccount` write for `MsgExecutePayload`-triggered first-use signers until after the wrapped message successfully executes, so failed/garbage payloads do not leave permanent state artifacts.

### Proof of Concept
1. Generate N fresh secp256k1/ed25519 keypairs offline; none hold any PC balance.
2. For each keypair, build one `MsgExecutePayload` with a bogus `UniversalAccountId`/`UniversalPayload`/`VerificationData` (any hex-decodable garbage that passes `ValidateBasic`) signed by that keypair as `Signer`, with `account_number=0, sequence=0`, and zero fee.
3. Broadcast each tx. `IsGaslessTx` returns true (single whitelisted message) → `MinGasPriceDecorator`/`DeductFeeDecorator` skip their checks → `AccountInitDecorator` sees `HasAccount==false`, verifies the self-signature at acc=0/seq=0 (trivially valid, since the attacker controls the key), and calls `SetAccount`, permanently creating the account in state.
4. The subsequent `ExecutePayload` message handler will fail (invalid UEA/owner/signature) and revert its own state changes, but the account object created in step 3 remains in state (per standard Cosmos SDK `runTx` semantics: AnteHandler writes commit independent of `runMsgs` outcome).
5. Repeat with N large; verify auth module account count grows unboundedly with zero PC spent by the attacker.

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.

// ValidateBasic does a sanity check on the provided data.
func (msg *MsgExecutePayload) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate universal payload
	if msg.UniversalPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal payload cannot be nil")
	}

	// Validate verificationData
	if len(msg.VerificationData) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "verificationData cannot be empty")
	}
	if _, err := hex.DecodeString(strings.TrimPrefix(msg.VerificationData, "0x")); err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid verificationData hex")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate universal payload structure
	if err := msg.UniversalPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universal payload")
	}

	return nil
}
