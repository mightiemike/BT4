## Analysis

The Pyth report's core issue — relying on an oracle price without any bound/sanity check on how much that price can be trusted — has a direct analog in Push Chain's own on-chain price source: the Uniswap V3 `QuoterV2` used to compute `minPCOut` for PRC20-autoswap and gas-refund swaps.

`GetSwapQuote` in [1](#0-0)  fetches a single, instantaneous spot quote from `quoteExactInputSingle` with `SqrtPriceLimitX96: 0` (no price-limit bound) and no TWAP, no liquidity-depth check, and no deviation/confidence check against any secondary reference price. The `minPCOut` slippage bound is then derived from that very same manipulable value with a flat 5%: [2](#0-1) 

The same pattern repeats for `GAS_AND_PAYLOAD` inbounds [3](#0-2)  and for the outbound gas-fee refund path [4](#0-3) .

Because the "confidence interval" equivalent (a bound on how far the quote may have been pushed from fair value, e.g. TWAP-vs-spot deviation) is never checked, an attacker who can move the pool's spot price in a transaction that lands in the same block just before the core validator's inbound-execution/ballot-finalization transaction can force `quoteExactInputSingle` to return a distorted `amountOut`. Since `minPCOut` is mechanically derived from that same distorted number (`quote * 95 / 100`), the protocol-executed `depositPRC20WithAutoSwap` / `refundUnusedGas` swap will still "pass" its own slippage check while executing at a manipulated price — extracting real PC/WPC value from the pool (or shortchanging the recipient) at the attacker's discretion. This requires no malicious validator, relayer, or admin: an ordinary user submits (a) a manipulating swap against the public Uniswap V3 pool and (b) the cross-chain deposit that becomes the `GAS`/`GAS_AND_PAYLOAD` inbound; UV votes on the deposit event are honest and accurate — the exploit lives entirely in the swap-quoting logic in scoped `x/uexecutor` code, not in the observation/voting layer.

This satisfies the allowed-impact gate ("corruption of ... refund accounting", "misroute value") via an unprivileged, ordinary-user-reachable trigger, and is a clean bug-class analog to the Pyth confidence-interval report: a price is consumed and immediately used to gate value transfer with no bound on how manipulated/uncertain that price may be.

### Title
Unbounded spot-price swap quote lets an attacker manipulate `minPCOut` and drain value from autoswap/gas-refund paths - (File: x/uexecutor/keeper/evm.go)

### Summary
`GetSwapQuote` reads a raw, single-block spot quote from Uniswap V3's `QuoterV2` and this value is used, unchecked, to derive the `minPCOut` slippage floor for every protocol-driven PRC20→PC swap (`CallPRC20DepositAutoSwap`, `CallUniversalCoreRefundUnusedGas`). There is no TWAP comparison, no maximum price-impact bound, and no minimum-liquidity guard — the same underlying flaw as ignoring Pyth's confidence interval: consuming a price feed without validating how trustworthy/manipulable it currently is.

### Finding Description
`GetSwapQuote` ( [5](#0-4) ) calls `quoteExactInputSingle` with no `sqrtPriceLimitX96` bound and returns whatever the pool's instantaneous state yields. All three call sites that consume this quote apply the same fixed 5% derivation and pass it straight into the swap call as the enforced minimum output:
- `ExecuteInboundGas` (GAS inbound route): [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound route): [6](#0-5) 
- `applyGasRefund` (outbound excess-gas refund route): [7](#0-6) 

Because `minPCOut` is computed from the exact same on-chain state that the swap subsequently executes against (same keeper call, same block), an attacker who moves the pool price shortly beforehand (a normal, permissionless EVM transaction against the public AMM pool) forces both the "reference" quote and the executed swap to reflect the manipulated price. The 5% band only protects against price movement *between* the quote and execution — it provides zero protection against the quote itself being wrong.

### Impact Explanation
A successful manipulation lets an attacker extract PC/WPC liquidity from the pool that backs the protocol's autoswap and refund flows, or force undervalued swaps that shortchange legitimate depositors, at the cost of the manipulator's own capital plus gas. Since the swap recipient in the exploited path can be the attacker's own UEA (for `GAS`/`GAS_AND_PAYLOAD` inbounds they themselves originate), this is a direct path to unauthorized value extraction from a protocol-controlled swap, matching the "unauthorized... refund of user or protocol-controlled funds" and "corruption of ... refund accounting" impact categories.

### Likelihood Explanation
Triggering the underlying inbound (GAS / GAS_AND_PAYLOAD deposit) is fully permissionless and cheap. Manipulating a Uniswap V3 pool's spot price is a standard, well-understood technique, especially for lower-liquidity pairs (new PRC20 listings are exactly this kind of pair). The main uncertainty is transaction-ordering control within the block that finalizes the ballot/executes the swap, which depends on the core validator's mempool/ordering behavior, but does not require any validator, relayer, or admin collusion — it is a pure ordinary-user attack against public on-chain state.

### Recommendation
Do not use a single raw spot quote as the basis for the enforced slippage floor. Options: (1) compare the spot quote against a time-weighted average price (TWAP) from the same pool and revert/fallback if deviation exceeds a configured threshold (the Pyth-equivalent of `σ/p` sanity check), (2) require a caller-/config-supplied maximum acceptable price impact independent of the observed quote, (3) source the reference price from multiple pools/oracles and cross-check, or (4) enforce a minimum pool liquidity/TVL floor before trusting `quoteExactInputSingle` for value-bearing swaps.

### Proof of Concept
1. Attacker identifies (or seeds) a low-liquidity Uniswap V3 pool for `PRC20↔WPC` used by `defaultFeeTier`/`GetSwapQuote`.
2. Attacker submits an ordinary EVM transaction that swaps heavily against this pool to push the spot price in the attacker's favor.
3. In the same block, attacker's own source-chain deposit (already observed/voted honestly by UVs) reaches ballot finalization, triggering `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, which calls `GetSwapQuote` against the now-manipulated pool and computes `minPCOut = quote*0.95`.
4. `CallPRC20DepositAutoSwap` executes against the still-manipulated pool state, delivering an inflated PC amount to the attacker's UEA relative to the token's fair value.
5. Attacker reverses the initial manipulating swap (or lets arbitrageurs do it), pocketing the difference extracted from the pool.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
