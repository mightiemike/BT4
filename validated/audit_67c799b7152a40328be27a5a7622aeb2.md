## Title
Replay/backup verification tool silently accepts committed output whose authenticated position-state checkpoint hash diverges from local execution - ([File: types/src/transaction/mod.rs])

### Summary
`TransactionOutput::ensure_match_transaction_info`, used by replay-verification tooling (`storage/db-tool/src/replay_on_archive.rs`, `execution/executor/src/chunk_executor/mod.rs`, `aptos-move/cli/src/commands.rs`) to check that a locally re-executed transaction output matches the authenticated `TransactionInfo` committed on-chain, only checks status, gas used, write-set hash, and event-root hash. It does **not** compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` against locally computed values. [1](#0-0) 

### Finding Description
`ensure_match_transaction_info` is the integrity gate that binds a locally executed `TransactionOutput` to the authenticated `TransactionInfo` (and, transitively, to the accumulator root and ledger info that was signed by validators). It explicitly checks gas, status, write-set hash (`state_change_hash`) and `event_root_hash`, but the code contains its own developer-authored admission of the gap:

```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
Ok(())
``` [2](#0-1) 

This matters because `TransactionInfoV1` now carries three separate Merkle roots that must all be reproduced deterministically by every replaying node: `state_checkpoint_hash` (main state SMT), `hot_state_checkpoint_hash` (hot state root), and `position_state_checkpoint_hash` (native "trading position" state root, gated by `COMPUTE_TRADING_NATIVE_STATE_ROOTS`). [3](#0-2) [4](#0-3) 

Because `ensure_match_transaction_info` is the sole per-transaction consistency check in the replay-verify tools (`replay_on_archive`, chunk-executor replay path, and the CLI `replay` command), a divergence in position-state (or state/hot-state) root computation between the executing node and a replaying node/archive is invisible to these tools: they will report `Ok(())` even though the locally computed position state root differs from the one embedded in the signed `TransactionInfo`. This breaks the "committed state must survive executor-to-storage/replay handoff unchanged" and "authenticated proof context bound to the right root" invariants specifically for the position/native-state root, since the verification path that is supposed to catch such divergence does not check it.

### Impact Explanation
If `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (or hot-state root) computation has any non-determinism or implementation bug between validator execution and replay/backup-verify tooling, this gap means:
- `storage/db-tool/src/replay_on_archive.rs`'s replay-verify workflow, which is relied upon to catch state-divergence bugs before or after they reach mainnet, will not detect corruption of the position state root or hot state root.
- Backup/restore verification (`VerifyCoordinator` / `TransactionRestoreBatchController` which uses `VerifyExecutionMode`) built on top of the same output-matching primitive could similarly miss such a divergence, silently accepting bad restored/replayed data as consistent.

This is a genuine gap in a state-integrity detection mechanism (not the commit path itself), so its severity is bounded by the fact that it does not itself corrupt data — it only fails to detect a divergence that must originate from a separate root-cause bug in position/hot-state root computation. Given the explicit TODO gating this on `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, the feature appears not yet enabled on mainnet, so current impact is best characterized as a latent verification blind spot rather than an active mainnet corruption, but it directly affects the accuracy of the tooling relied upon to catch "wrong accumulator root" style regressions for this feature area.

### Likelihood Explanation
Likelihood of this specific detection gap causing an undetected divergence depends entirely on `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/hot-state-root-in-txn-info being enabled and on some other bug independently producing a wrong root; I could not confirm from the available index whether this feature flag is currently active on mainnet. The code's own inline comment confirms the gap is real and known but explicitly deferred ("Validate the checkpoint hashes here before enabling COMPUTE_TRADING_NATIVE_STATE_ROOTS"), suggesting the team is aware and intends to fix it before the feature ships broadly.

### Recommendation
Extend `ensure_match_transaction_info` to also compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present in the corresponding `TransactionInfo` variant) against the locally computed roots, and fail replay/backup verification if any mismatch occurs, consistent with the write-set and event-root checks already performed. This should be completed before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled on mainnet.

### Proof of Concept
Not applicable as an exploit PoC — this is a verification-logic gap, not an exploitable state-corruption primitive by itself. The "PoC" is the code-documented condition: enable `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/`HOT_STATE_ROOT_IN_TXN_INFO`, construct a `TransactionOutput` whose write set and events match the committed `TransactionInfo` but whose locally-computed `position_state_checkpoint_hash` (or hot-state root) differs, and observe that `ensure_match_transaction_info` (and thus `replay_on_archive`) returns `Ok(())` instead of surfacing the mismatch.     pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
