**Analysis:**

The `Ciphertext` struct in `ristretto255_elgamal.move` only has the `drop` ability — it explicitly lacks `store` and `key` [1](#0-0) . This means a raw `Ciphertext` (the type returned/consumed by `ciphertext_into_points`, `ciphertext_as_points`, and `ciphertext_from_points`) can never be placed into global storage or a write set directly — it can only exist as a transient value within a transaction's execution. Only `CompressedCiphertext`, which holds `CompressedRistretto` fields, has the `store` ability [2](#0-1) , and reaching that type requires going through `compress_ciphertext`, which simply compresses whatever `left`/`right` fields the caller already assembled [3](#0-2) .

The functions in question are intentionally public, generic accessor/constructor pairs that let calling code freely move data in and out of the `left`/`right` fields [4](#0-3) . The module itself imposes no semantic distinction between `left` and `right` beyond documentation comments — the "value-commitment vs. randomness-commitment" meaning is a convention established by whatever downstream application module uses this library, not an invariant enforced (or violatable) here. A search of the codebase found no consumer module (e.g., a confidential-asset or veiled-coin module) in this repository that calls `ciphertext_into_points`, `ciphertext_as_points`, or `ciphertext_from_points` to construct and persist stored ciphertext state — these functions are unused outside this file and its spec file [5](#0-4) .

Since:
1. `Ciphertext` cannot be committed to the write set (no `store`/`key`),
2. there is no application-layer module in this codebase that uses these accessors to build and persist a `CompressedCiphertext` from swapped points, and
3. the "left/right" semantics are a caller convention, not a module-enforced invariant that these functions bypass,

there is no demonstrable path from unprivileged transaction input, through this module, into a corrupted committed state value, proof artifact, or authenticated response on mainnet.
