### Title
Unbounded webhook body buffering before HMAC validation enables memory/CPU exhaustion DoS - (File: packages/apps/shopify-app-remix/src/server/authenticate/webhooks/authenticate.ts)

### Summary
`authenticateWebhookFactory`'s `authenticate()` calls `await request.text()` to fully buffer the request body into memory before any HMAC or size validation occurs. Since no `Content-Length` or streaming size cap is enforced anywhere in the call chain, an anonymous attacker can POST an arbitrarily large body to any public webhook endpoint and force the app process to allocate and hold that entire payload in memory, and later run `createSHA256HMAC`/`JSON.parse` over it, causing resource exhaustion shared across all shops on that process.

### Finding Description
In `authenticate()`, the flow is: [1](#0-0) 
`request.text()` reads and buffers the entire body regardless of size, and only afterward is `api.webhooks.validate({rawBody, rawRequest: request})` invoked. Tracing into the shared library, `validateFactory` in `packages/apps/shopify-api/lib/webhooks/validate.ts` immediately forwards `rawBody` to `validateHmacFromRequestFactory` [2](#0-1) , which only checks `rawBody.length` for emptiness (not for an upper bound) before running HMAC comparison [3](#0-2) . There is no `Content-Length` check, no streaming read with a byte cap, and no configuration option for a max body size anywhere in the codebase (confirmed by searching for `Content-Length`/`maxBodySize`/body-size guards, which found no such enforcement in library source). The same unbounded pattern (`await request.text()` prior to validation) is repeated in the `flow` and `fulfillment-service` authenticate handlers in both the `shopify-app-remix` and `shopify-app-react-router` packages, meaning this is a systemic library-level gap, not host-app misconfiguration. An unprivileged attacker (anonymous internet client) can reach any of these public webhook/flow/fulfillment-service endpoints without any secret or privileged role, so the full trust boundary crossing is present.

### Impact Explanation
A crafted POST with a multi-hundred-MB (or larger, streamed) body causes the Node/Remix/React-Router process to buffer that payload fully in memory via `request.text()`, then perform `createSHA256HMAC` and `JSON.parse` over the oversized string. Repeated or concurrent requests can exhaust heap memory or CPU, crashing or hanging the process and causing denial of service for every shop whose sessions/webhooks are served by that shared app instance. This matches the "Denial of Service in authentication/webhook handler" impact class since the affected code path is squarely the auth/webhook verification entry point and requires no valid HMAC or session to trigger — the crash occurs before HMAC is checked.

### Likelihood Explanation
Highly feasible and repeatable: the endpoint is public (any registered webhook URL, flow, or fulfillment-service endpoint), requires only a raw HTTP POST with no valid signature, headers, or shop context, and the vulnerable line (`await request.text()`) executes unconditionally for every POST before the 401 "InvalidHmac" branch can even be reached. No non-default configuration, rate-limiting bypass, or secret is needed — only network access to the deployed app's webhook route.

### Recommendation
Enforce a body-size limit before/while buffering the request: check `Content-Length` against a configurable maximum and reject with 413 if exceeded, and/or use a streaming reader (`request.body.getReader()`) with a byte-count cap that aborts the read once the limit is exceeded, before calling `request.text()`/`api.webhooks.validate()`. Apply the same fix consistently to the `flow` and `fulfillment-service` authenticate handlers in both `shopify-app-remix` and `shopify-app-react-router`.

      'X-Shopify-Api-Version': '2024-01',
      'X-Shopify-Webhook-Id': '123',
    },
    body: hugeBody,
  });

  const authenticate = authenticateWebhookFactory(mockParams);

  const memBefore = process.memoryUsage().heapUsed;
  await expect(authenticate(request)).rejects.toThrow(); // eventually 401 InvalidHmac
  const memAfter = process.memoryUsage().heapUsed;

  // Demonstrates the full 500MB body was buffered into memory
  // (memAfter - memBefore) approaches HUGE_SIZE, proving no size cap

  expect(memAfter - memBefore).toBeGreaterThan(HUGE_SIZE * 0.8);

  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs

    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);

      config,
