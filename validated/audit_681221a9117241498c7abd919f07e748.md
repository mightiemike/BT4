### Title
Unvalidated `RevertInstructions.FundRecipient` allows refund/gas-refund to `0x0`, permanently burning bridged funds - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/build_revert_outbound.go`)

### Summary
`Inbound.RevertInstructions.FundRecipient` is a free-form, user-supplied string that originates from the external-chain deposit event and is never validated to be a well-formed, non-zero EVM address anywhere in the inbound/outbound pipeline. It is used directly as the destination of PRC20 re-mints (`handleFailedOutbound`) and of gas-fee refunds (`applyGasRefund`), so a value like `0x0000000000000000000000000000000000000000` results in the bridged tokens (or the swapped-back native PC) being minted/sent to the zero address instead of the depositor, exactly the same failure class as the referenced Badger `sweepRewardToken()`/`bribesProcessor==0x0` bug: an unchecked destination address consumes the transfer with no on-chain guard.

### Finding Description
`Inbound.Canonicalize()` only lenient-canonicalizes `RevertInstructions.FundRecipient` via `utils.LenientCanonicalizeAddress` — this accepts and canonicalizes the valid-but-degenerate zero address without error, and falls back to the raw trimmed string for anything unparseable: [1](#0-0) 

Neither `ValidateBasic` nor `ValidateForExecution` on `Inbound` ever inspects `RevertInstructions`/`FundRecipient` — they validate `Sender`, `Recipient`, `Amount`, `AssetAddr`, and payload fields but never check the revert-fund destination: [2](#0-1) [3](#0-2) 

`buildRevertOutbound` (used both on execution failure and on `RevertStuckInbound`) unconditionally prefers `FundRecipient` over `Sender` whenever it is a non-empty string, with no zero-address or format check: [4](#0-3) 

`handleFailedOutbound` re-derives the same unchecked recipient and mints the bridged PRC20 amount directly to it: [5](#0-4) 

`applyGasRefund` independently repeats the exact same unchecked pattern for excess-gas refunds, calling `CallUniversalCoreRefundUnusedGas` with `common.HexToAddress(refundRecipient)`: [6](#0-5) 

`OutboundTx.ValidateBasic` (which does run before persisting an outbound) checks `Sender` and `Recipient` are non-empty valid addresses but does **not** re-validate whatever value was placed into `Recipient` from `RevertInstructions.FundRecipient` against the zero address: [7](#0-6) 

### Impact Explanation
An unprivileged, ordinary bridge user constructs their own deposit event on the source chain with `revert_instructions.fund_recipient = 0x000...000` (or any similarly degenerate value that still passes `IsHexAddress`), submits a payload that is designed to fail PC execution (e.g., malformed calldata, insufficient gas, or a reverting contract call), and is non-isCEA. When the honest validator set finalizes the inbound and execution fails, the node builds a revert outbound whose `Recipient` is the attacker-chosen zero address, and on the corresponding outbound-failure/gas-refund path (`handleFailedOutbound`/`applyGasRefund`) it mints the re-bridged PRC20 principal and/or the swapped/refunded gas fee to `0x0` on Push Chain — the tokens are permanently and irrecoverably lost (burned), matching the "permanent loss of user- or protocol-controlled funds" allowed-impact category. Because `FundRecipient` is populated straight from attacker-controlled inbound data with no bounds/format/zero check anywhere in the validation chain, this is fully reachable through the default deposit → vote → finalize → execute → revert flow with only honest validators/nodes involved.

### Likelihood Explanation
High: the field is attacker-supplied on every deposit and passes unmodified through `Canonicalize`, `ValidateBasic`, `ValidateForExecution`, and `OutboundTx.ValidateBasic` because none of them constrain it. No privileged actor, governance, or malicious validator/relayer is required — a single ordinary user (or an attacker griefing another user's deposit, if the field can be independently attacker-supplied at the gateway level, which is a question of gateway contract design but is not constrained on this node's side) can trigger the loss deterministically by making PC execution fail.

### Recommendation
Add explicit validation of `RevertInstructions.FundRecipient` in `Inbound.ValidateForExecution()` (and/or in `OutboundTx.ValidateBasic()` before the outbound is persisted): if non-empty, it must be a syntactically valid, non-zero address for the destination namespace (reject `0x000...000`, empty-after-trim, or malformed values), falling back to `Sender` on any such invalid value rather than propagating it into `buildRevertOutbound`/`handleFailedOutbound`/`applyGasRefund`.

### Proof of Concept
1. User submits a source-chain deposit (`FUNDS_AND_PAYLOAD`, non-isCEA) whose event encodes `revert_instructions.fund_recipient = "0x0000000000000000000000000000000000000000"` and a `universal_payload` calling a contract with an invalid selector so PC execution reverts (this exact revert trigger is already exercised in `TestVoteInboundValidation`).
2. Validators vote and reach quorum; `Inbound.Canonicalize()` accepts the zero address unchanged, `ValidateForExecution()` does not reject it.
3. Execution fails; `buildRevertOutbound` sets `outbound.Recipient = "0x0000...0000"` per [4](#0-3) .
4. When the failed-outbound/refund path runs, `handleFailedOutbound`/`applyGasRefund` call `CallPRC20Deposit`/`CallUniversalCoreRefundUnusedGas` with `common.HexToAddress("0x0000...0000")`, minting/refunding the bridged principal or gas rebate to the zero address, permanently burning the funds instead of returning them to the depositor.

func (p Inbound) ValidateBasic() error {
	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)
	if chain == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}
	if !strings.Contains(chain, ":") {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain must be in CAIP-2 format <namespace>:<reference>")
	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")
	}

	// Validate sender — needed for revert recipient fallback
	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	// Validate log_index — needed for UTX key
	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}

	// Validate tx_type enum — needed to route execution
	if _, ok := TxType_name[int32(p.TxType)]; !ok || p.TxType == TxType_UNSPECIFIED_TX {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid tx_type: %v", p.TxType)
	}

	return nil
}

func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
