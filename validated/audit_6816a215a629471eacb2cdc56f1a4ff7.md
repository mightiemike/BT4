## Finding: Raw Solidity `TX_TYPE` byte stored as `TxType` without going through `SolidityTxTypeToProto`

### Title
Universal Client inbound event parsers store raw Solidity TX_TYPE ordinal into `TxType` field without conversion — (File: `universalClient/chains/evm/event_parser.go`, `universalClient/chains/svm/event_parser.go`)

### Summary
`x/uexecutor/types/tx_type.go`'s `SolidityTxTypeToProto` exists precisely to translate the Solidity `TX_TYPE` enum (0=GAS,1=GAS_AND_PAYLOAD,2=FUNDS,3=FUNDS_AND_PAYLOAD,4=RESCUE_FUNDS,5=INBOUND_REVERT) into the Cosmos `TxType` proto enum (0=UNSPECIFIED,1=GAS,2=GAS_AND_PAYLOAD,3=FUNDS,...) because their ordinals deliberately diverge [1](#0-0) . This function is correctly invoked at the two outbound/rescue log-decoding sites in `x/uexecutor/types/gateway_pc_event_decode.go` [2](#0-1) [3](#0-2) .

However, the **inbound `sendFunds`/`send_funds` event parsers** in `universalClient` — the code path that a UV runs when observing a user's gateway deposit on an external EVM or SVM chain — read the same raw Solidity `TX_TYPE` byte and assign it directly into `common.UniversalTx.TxType` (a plain `uint`) with **no call to `SolidityTxTypeToProto`**:

- EVM: `payload.TxType = uint(new(big.Int).SetBytes(w).Uint64())` [4](#0-3) 
- SVM: `txType := data[offset]; payload.TxType = uint(txType)` [5](#0-4) 

Both files even build fast/standard confirmation-type decisions off the *raw Solidity* values 0/1 (`GAS`/`GAS_AND_PAYLOAD` in Solidity numbering) rather than the proto numbering [6](#0-5) [7](#0-6) , confirming that this intermediate `TxType` field is deliberately kept in **Solidity ordinal space**, not proto space.

### Finding Description
This is exactly the "raw-cast consumer" scenario in the audited question: the field is named `TxType` and is superficially indistinguishable from the final Cosmos `types.TxType` used in `Inbound.TxType` (which drives ballot finalization, UTX classification, and execution routing in `x/uexecutor`). If any downstream code that turns this intermediate `common.UniversalTx` (e.g. in the corresponding `tx_builder.go` files for EVM/SVM) treats `payload.TxType` as if it were already the proto ordinal — instead of re-applying `SolidityTxTypeToProto` — a user-supplied `TX_TYPE=2` (Solidity `FUNDS`) would be submitted as proto ordinal `2` (`GAS_AND_PAYLOAD`), and so on for every non-zero value, since the two enumerations never agree past index 0/1 depending on interpretation.

I was not able to fully trace `universalClient/chains/evm/tx_builder.go` and `universalClient/chains/svm/tx_builder.go` (the modules that presumably construct the final `MsgVoteInbound.Inbound.TxType` from this intermediate event) within the available tool budget, so I cannot confirm with certainty whether those builders re-apply `SolidityTxTypeToProto` before submitting the vote, or whether they propagate the raw value directly.

### Impact Explanation
If the raw value is propagated uncorrected into `Inbound.TxType`, honest UVs would converge on a ballot with the wrong `TxType` semantics for every non-`GAS` inbound (since `ValidateForExecution` and `NormalizeForTxType` in `x/uexecutor/types/inbound.go` branch entirely on `p.TxType` to decide fund routing, payload decoding, and recipient handling) [8](#0-7) [9](#0-8) . This could misroute a `FUNDS` transfer as `GAS_AND_PAYLOAD`, corrupting UTX accounting and fund routing exactly as the question describes — a materially impactful, unprivileged, user-triggerable classification bug reachable through an ordinary gateway deposit.

### Likelihood Explanation
Medium — contingent entirely on the unverified behavior of `tx_builder.go`. The design intent (a dedicated `SolidityTxTypeToProto` helper, used elsewhere) argues this conversion is *supposed* to happen at vote-construction time, but I could not confirm it is actually invoked on this particular field before the `MsgVoteInbound` is submitted.

### Recommendation
Confirm (and if missing, add) an explicit `SolidityTxTypeToProto(uint8(payload.TxType))` conversion at the point where `common.UniversalTx.TxType` from `universalClient/chains/evm/event_parser.go` and `universalClient/chains/svm/event_parser.go` is turned into the `Inbound.TxType` proto field used in `MsgVoteInbound` (likely in the corresponding `tx_builder.go` files). Consider renaming the intermediate field (e.g. `SolidityTxType`) to make the ordinal space unambiguous and prevent silent raw-cast bugs.

### Proof of Concept
Feeding the Solidity ordinals 0–5 through `SolidityTxTypeToProto` versus a naive `TxType(rawByte)` cast diverges for every non-`GAS` value (Solidity `1=GAS_AND_PAYLOAD` → proto `1=GAS`; Solidity `2=FUNDS` → proto `2=GAS_AND_PAYLOAD`; etc.) as defined in `x/uexecutor/types/tx_type.go` [10](#0-9) . The concrete unconverted-raw-value assignment exists today in `universalClient/chains/evm/event_parser.go:266` and `universalClient/chains/svm/event_parser.go:325`; whether this raw value later reaches `Inbound.TxType` uncorrected depends on code in `tx_builder.go` that was not verifiable within this review's tool budget and should be manually confirmed.

**Note:** Because the ultimate consumer (`tx_builder.go`) could not be inspected, this should be treated as a **flagged area requiring confirmation** rather than a fully proven exploit chain — recommend a Devin session or manual review of `universalClient/chains/evm/tx_builder.go` and `universalClient/chains/svm/tx_builder.go` to close this gap definitively.

package types

// Solidity TX_TYPE (uint8) → Cosmos TxType
func SolidityTxTypeToProto(txTypeUint8 uint8) TxType {
	switch txTypeUint8 {
	case 0:
		return TxType_GAS
	case 1:
		return TxType_GAS_AND_PAYLOAD
	case 2:
		return TxType_FUNDS
	case 3:
		return TxType_FUNDS_AND_PAYLOAD
	case 4:
		return TxType_RESCUE_FUNDS
	case 5:
		return TxType_INBOUND_REVERT
	default:
		return TxType_UNSPECIFIED_TX
	}
}

func (p *Inbound) NormalizeForTxType() error {
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		// Payload types: recipient is only meaningful when isCEA
		if !p.IsCEA {
			p.Recipient = EvmZeroAddress
		}
		// Always clear universal_payload — whatever the UV sends is ignored.
		// Core validator decodes from raw_payload.
		p.UniversalPayload = nil

		// Decode raw_payload → universal_payload
		if p.RawPayload != "" {
			decoded, err := DecodeRawPayload(p.RawPayload, p.SourceChain)
			if err != nil {
				return fmt.Errorf("failed to decode raw payload: %w", err)
			}
			if decoded == nil {
				return fmt.Errorf("raw_payload decoded to nil for payload tx type")
			}
			p.UniversalPayload = decoded
			p.RawPayload = "" // clear after successful decode to save storage
		}
	default:
		// Non-payload types: payload is not used
		p.UniversalPayload = nil
		p.VerificationData = ""
		p.RawPayload = ""
	}
	return nil
}

func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}
