### Title
Unbounded-length `DestExecData` causes index-out-of-range panic in `ccipsolana.ExtraDataDecoder.DecodeDestExecDataToMap`, crashing the SVM OCR transmit path - ([File: core/capabilities/ccip/ccipsolana/extradatacodec.go])

### Summary
`ccipsolana.ExtraDataDecoder.DecodeDestExecDataToMap` calls `binary.BigEndian.Uint32(destExecData)` on attacker-controlled `TokenAmounts[].DestExecData` with no length check, unlike the sibling EVM implementation which uses ABI decoding that returns a bounds-checked error. This is reachable from `decodeExecData` in `core/capabilities/ccip/ocrimpls/svm_contract_transmitter.go`, which is invoked from `SVMExecCalldataFunc` in the OCR3 transmit path for every node processing an execute report whose source chain is Solana/SVM.

### Finding Description
`decodeExecData` (core/capabilities/ccip/ocrimpls/svm_contract_transmitter.go:126-153) iterates `message.TokenAmounts` and calls `codec.DecodeTokenAmountDestExecData(tokenAmount.DestExecData, sourceChainSelector)` for each token amount in an `ExecuteReportInfo` that was decoded straight from the OCR report bytes (`ccipocr3.DecodeExecuteReportInfo(report.Info)`), i.e., from data that originates from CCIP message content and is not independently validated for length. The dispatch bundle (`ExtraDataCodecMap`, from `chainlink-common`) routes the call to the codec registered for the source chain's family; for Solana-sourced messages that is `ccipsolana.ExtraDataDecoder`.

`ccipsolana.ExtraDataDecoder.DecodeDestExecDataToMap` (core/capabilities/ccip/ccipsolana/extradatacodec.go:86-90):
```go
func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
	return map[string]any{
		svmDestExecDataKey: binary.BigEndian.Uint32(destExecData),
	}, nil
}
```
performs no length validation before calling `binary.BigEndian.Uint32`, which requires the slice to be at least 4 bytes; Go's standard library panics with an index-out-of-range error if `len(destExecData) < 4`.

This contrasts directly with the EVM equivalent, `ccipevm.ExtraDataDecoder.DecodeDestExecDataToMap` (core/capabilities/ccip/ccipevm/extradatacodec.go:26-35), which calls `abiDecodeUint32`, an ABI-based decode that returns a proper `error` ("length insufficient 4 require 32") instead of panicking — confirmed by the existing test in `core/capabilities/ccip/ocrimpls/contract_transmitter_test.go:257-292`, which asserts a bounds-checked error message for EVM-sourced short `DestExecData`. No equivalent length guard or test exists for the Solana-family decoder.

Since `decodeExecData`/`SVMExecCalldataFunc` runs during OCR3 report transmission (`ToCalldataFunc` used by `ccipTransmitter`), a malformed/short `DestExecData` field for a message whose source chain family is Solana reaches the unguarded `binary.BigEndian.Uint32` call and panics, crashing the node process (absent a top-level recover in that specific call path).

### Impact Explanation
A panic in `DecodeDestExecDataToMap`, if unrecovered, crashes the goroutine/process executing OCR report transmission for the SVM offramp, since this code sits in the shared, privileged commit/execute transmit path used by every node operator processing that report. This matches a denial-of-service impact against the OCR transmission logic of the DON, potentially disrupting execution of legitimate CCIP messages destined for/from Solana until nodes recover or the message is otherwise invalidated upstream.

### Likelihood Explanation
Exploitability depends on whether a report containing a message with source chain family Solana and a `DestExecData` shorter than 4 bytes can pass upstream validation (e.g., commit-plugin/message validation, `ShouldAcceptAttestedReport`) before reaching `decodeExecData`. I could not verify within the available index whether such upstream length validation exists elsewhere in the OCR3 plugin pipeline (e.g., report validation prior to transmission) that would reject a short `DestExecData` before it reaches this code — this is a gap in my analysis given tool-call limits. If no such validation exists, this is trivially and repeatably triggerable by any party able to influence CCIP message content that ends up encoded into an accepted report (e.g., a malicious/compromised source-chain message), requiring no privileged access to the node itself.

### Recommendation
Add an explicit length check in `ccipsolana.ExtraDataDecoder.DecodeDestExecDataToMap` before calling `binary.BigEndian.Uint32`, e.g.:
```go
func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
	if len(destExecData) < 4 {
		return nil, fmt.Errorf("dest exec data too short: %d, should be at least 4 bytes", len(destExecData))
	}
	return map[string]any{
		svmDestExecDataKey: binary.BigEndian.Uint32(destExecData),
	}, nil
}
```
This mirrors the bounds-checked behavior already present in the EVM decoder and ensures `decodeExecData`/`SVMExecCalldataFunc` return a normal error instead of panicking.

func decodeExecData(report ccipocr3.ExecuteReportInfo, codec ccipocr3.ExtraDataCodecBundle) (ccipcommon.ExtraDataDecoded, error) {
	// only one report one message, since this is a stop-gap solution for solana
	if len(report.AbstractReports) != 1 {
		return ccipcommon.ExtraDataDecoded{}, fmt.Errorf("unexpected report length, expected 1, got %d", len(report.AbstractReports))
	}
	if len(report.AbstractReports[0].Messages) != 1 {
		return ccipcommon.ExtraDataDecoded{}, fmt.Errorf("unexpected message length, expected 1, got %d", len(report.AbstractReports[0].Messages))
	}
	message := report.AbstractReports[0].Messages[0]
	extraDataDecoded := ccipcommon.ExtraDataDecoded{}

	var err error
	extraDataDecoded.ExtraArgsDecoded, err = codec.DecodeExtraArgs(message.ExtraArgs, report.AbstractReports[0].SourceChainSelector)
	if err != nil {
		return ccipcommon.ExtraDataDecoded{}, fmt.Errorf("failed to decode extra args: %w", err)
	}
	// stopgap solution for missing extra args for Solana. To be replaced in the future.
	destExecDataDecoded := make([]map[string]any, len(message.TokenAmounts))
	for i, tokenAmount := range message.TokenAmounts {
		destExecDataDecoded[i], err = codec.DecodeTokenAmountDestExecData(tokenAmount.DestExecData, report.AbstractReports[0].SourceChainSelector)
		if err != nil {
			return ccipcommon.ExtraDataDecoded{}, fmt.Errorf("failed to decode token amount dest exec data: %w", err)
		}
	}
	extraDataDecoded.DestExecDataDecoded = destExecDataDecoded

	return extraDataDecoded, nil
}
