## Title
Webhook shop-domain header is not covered by the HMAC signature, allowing cross-tenant webhook spoofing - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
`shopify.webhooks.validate`/`process` authenticate an inbound webhook solely by re-computing an HMAC over the **raw request body** using the app's shared `apiSecretKey`. The `X-Shopify-Shop-Domain` (and topic/webhook-id) headers that identify *which tenant* the webhook belongs to are never included in that signature, yet they are trusted as-is and used to look up and hand back an authenticated admin session for that shop. This mirrors the root cause of the reported Magnetar bug: the code authenticates one piece of data (the caller/body) but then performs a privileged, tenant-scoped action using a different, unverified value (the domain header vs. the signed data / the `msg.sender` vs. `data.user`).

### Finding Description
The webhook HMAC check is implemented in `validateHmacFromRequestFactory`, which only hashes `rawBody`: [1](#0-0) 

It never folds any header (domain, topic, webhookId, apiVersion) into the signed material — only `createSHA256HMAC(config.apiSecretKey, rawBody, ...)` is compared against the `X-Shopify-Hmac-Sha256` header.

Separately, `checkWebhooksHeaders`/`checkEventsHeaders` read the `domain`, `topic`, and `webhookId` directly from unauthenticated headers and pass them through untouched as the "valid" result once the (body-only) HMAC check passes: [2](#0-1) [3](#0-2) 

Downstream, both the Remix and React Router webhook `authenticate()` helpers take `check.domain` at face value and use it to load an **offline session with a real access token**, then hand back an authenticated `admin` API client scoped to that shop: [4](#0-3) 

Because `apiSecretKey` is the *same secret for every shop that has the app installed* (it's an app-level, not a shop-level, secret), any merchant who has legitimately installed the app can:
1. Install the app on their own store and receive a real webhook delivery with a valid HMAC (computed by Shopify over that body with the app's shared secret).
2. Replay that HTTP request to the app's webhook endpoint, changing only the `X-Shopify-Shop-Domain` header to a victim shop that also has the app installed (and optionally the topic/webhook-id headers).
3. Because the HMAC never covered those headers, the signature still validates.
4. The webhook handler is invoked with `shop`/`domain` set to the victim's shop and — if an offline session exists for that shop — is handed an authenticated `admin` client for the victim, and any app business logic keyed off `shop` runs against the victim's data using the attacker-supplied body.

### Impact Explanation
This allows a low-privilege, already-onboarded merchant (an "unprivileged actor" from the app's perspective, not a Shopify-trusted party) to forge webhook deliveries that the app accepts as coming from a different, victim shop. Depending on what the app's webhook handlers do (e.g., write victim-shop data, trigger billing/inventory changes, or use the returned `admin` client to make Admin API calls "as" the victim shop), this is a cross-tenant confused-deputy: the attacker controls the payload while the app treats it as trusted, shop-scoped input for another tenant, and hands out an authenticated admin session for that tenant to the handler.

### Likelihood Explanation
Any merchant who installs the app can capture one legitimately-signed webhook body/HMAC pair from their own store (trivial, no secret disclosure required) and replay it with a forged domain header at will. No special access, leaked secrets, or MITM position is needed — this is reachable directly by an unprivileged installed merchant against the app's public webhook endpoint.

### Recommendation
Bind the tenant-identifying values (`domain`/shop, and ideally `topic`/`webhookId`) into the authenticated material, e.g. by requiring the HMAC to be computed/verified over `headers + body` (or by looking up the shop's own per-shop secret/offline token first and independently confirming that the value in `X-Shopify-Shop-Domain` matches a shop for which this exact HMAC could only have been produced), instead of trusting the header verbatim once a body-only HMAC succeeds.

### Proof of Concept
1. Install the target app on `attacker.myshopify.com` and register the app for a webhook topic (e.g. `PRODUCTS_CREATE`).
2. Capture a real delivery: body `B`, header `X-Shopify-Hmac-Sha256: H` (valid because `H = HMAC(apiSecretKey, B)`), header `X-Shopify-Shop-Domain: attacker.myshopify.com`.
3. Send a POST to the app's webhook endpoint with the same body `B` and same `H`, but `X-Shopify-Shop-Domain: victim.myshopify.com` (a store known to have the app installed).
4. `validateHmacFromRequest` recomputes `HMAC(apiSecretKey, B)` — matches `H`, so `valid: true` is returned along with `domain: 'victim.myshopify.com'` taken straight from the attacker-controlled header, per `checkWebhooksHeaders` [5](#0-4) .
5. `authenticateWebhookFactory` loads `victim.myshopify.com`'s offline session and constructs an authenticated `admin` client for it, invoking the app's webhook business logic as if it were a legitimate event from the victim shop [6](#0-5) .

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };

export function validateFactory(config: ConfigInterface) {
  return async function validate({
    rawBody,
    ...adapterArgs
  }: WebhookValidateParams): Promise<WebhookValidation> {
    const request: NormalizedRequest =
      await abstractConvertRequest(adapterArgs);

    const webhookType = detectWebhookType(request.headers);

    const validHmacResult = await validateHmacFromRequestFactory(config)({
      type: HmacValidationType.Webhook,
      rawBody,
      webhookType,
      ...adapterArgs,
    });

    if (!validHmacResult.valid) {
      if (validHmacResult.reason === ValidationErrorReason.InvalidHmac) {
        const log = logger(config);
        await log.debug(
          "Webhook HMAC validation failed. Please note that events manually triggered from a store's Notifications settings will fail this validation. To test this, please use the CLI or trigger the actual event in a development store.",
        );
      }
      return validHmacResult;
    }

    return checkWebhookHeaders(request.headers, webhookType);
  };
}

function checkWebhooksHeaders(
  headers: Headers,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };

  const name = getHeader(headers, headerNames.name);
  if (name) fields.name = name;

  const triggeredAt = getHeader(headers, headerNames.triggeredAt);
  if (triggeredAt) fields.triggeredAt = triggeredAt;

  const eventId = getHeader(headers, headerNames.eventId);
  if (eventId) fields.eventId = eventId;

  return {valid: true, ...fields};
}
