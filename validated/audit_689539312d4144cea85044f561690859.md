### Title
Unauthenticated CPU exhaustion via unbounded zk-SNARK proof generation in `createShieldedTransactionWithoutSpendAuthSig` / `createShieldedContractParametersWithoutAsk` before any signature check - ([File: framework/src/main/java/org/tron/core/Wallet.java])

### Summary
Both `Wallet#createShieldedTransactionWithoutSpendAuthSig` (via `ZenTransactionBuilder#buildWithoutAsk`/`build`) and `Wallet#createShieldedContractParametersWithoutAsk` perform full Sapling zk-SNARK proof generation (`JLibrustzcash` spend/output proofs) for every entry in the attacker-supplied `shieldedSpends`/`shieldedReceives` lists before any spend-authorization signature or on-chain fee/broadcast check occurs. The only gate is a global boolean feature flag (`checkAllowShieldedTransactionApi`), not per-caller authentication or payment, and the HTTP servlets are protected only by generic QPS-based rate limiting that does not account for the CPU cost of large spend/receive lists.

### Finding Description
`createShieldedTransactionWithoutSpendAuthSig` is reachable unauthenticated via gRPC (`RpcApiService#createShieldedTransactionWithoutSpendAuthSig`) [1](#0-0)  and via HTTP (`CreateShieldedTransactionWithoutSpendAuthSigServlet#doPost`) [2](#0-1) .

The wallet method only calls `checkAllowShieldedTransactionApi()` (a global config toggle), performs basic input-presence/amount checks, and then iterates over all attacker-supplied `shieldedSpends`/`shieldedReceives` entries to add them to a `ZenTransactionBuilder`, finally calling `builder.buildWithoutAsk()`: [3](#0-2) . Nothing in this path bounds the number of `shieldedSpends`/`shieldedReceives` entries or checks a spend-authorization signature — the `ask` is deliberately absent from this "WithoutAsk" flow and is only supplied by the client afterward via `createSpendAuthSig`.

`ZenTransactionBuilder#build` (called by `buildWithoutAsk`) loops over every registered spend and receive and invokes `generateSpendProof`/`generateOutputProof`, which call into `librustzcash` (`JLibrustzcashSaplingProvingCtxInit`, proof generation, `librustzcashSaplingBindingSig`) — genuinely expensive zk-SNARK computations — for each list element, with no cap observed on list length in this method: [4](#0-3) .

By contrast, the TRC20 sibling `createShieldedContractParametersWithoutAsk` does impose a hard structural cap of at most 2 spends and 2 receives (`spendSize < 3`, `receiveSize < 3`), otherwise it throws `ContractValidateException("invalid shielded TRC-20 parameters")`: [5](#0-4) . This bounds worst-case proof-generation cost for that specific endpoint to a small constant, undermining the "maximal shieldedSpends/shieldedReceives" premise for that call specifically — but the equivalent cap does not appear present for `createShieldedTransactionWithoutSpendAuthSig`.

The only mitigating control found is `RateLimiterServlet`, which applies per-endpoint and global QPS-based rate limiting on the HTTP path: [6](#0-5) . This limiter counts requests, not proof-generation cost, so an attacker within the QPS budget can still submit a request with a large `shielded_spends`/`shielded_receives` array (bounded only by message-size/JSON parsing limits), forcing disproportionate CPU work per accepted request. No equivalent rate limiting or list-size validation was found for the gRPC service implementation in `RpcApiService.java` itself.

### Impact Explanation
An unauthenticated caller (once `allowShieldedTransactionApi`/`allowShieldedTRC20Transaction` is enabled, which is a documented node operating mode, not a privilege the attacker needs) can submit crafted `PrivateParametersWithoutAsk`/`PrivateShieldedTRC20ParametersWithoutAsk` requests with garbage note data and many spend/receive entries. Each accepted request forces the node to run multiple librustzcash zk-SNARK proof generations synchronously, which is CPU-intensive, before any failure occurs (proof generation happens unconditionally; there is no upfront signature or fee check to reject bad requests cheaply). Repeated submission can degrade node responsiveness — a CPU-exhaustion DoS scoped to the shielded-transaction-construction RPC surface.

### Likelihood Explanation
Feasible only when shielded transaction support is enabled on the node (stated precondition). The HTTP path is throttled by QPS-based `RateLimiterServlet`, which somewhat limits (but does not eliminate) the attack, since cost-per-request is not factored into the throttle. No such throttle was located for the gRPC path in this codebase area. The TRC20 variant's built-in 2-spend/2-receive cap meaningfully reduces (but for the non-TRC20 `createShieldedTransactionWithoutSpendAuthSig`, no equivalent cap was found), so repeatable, budget-controllable CPU cost amplification is realistic there.

### Recommendation
- Enforce an explicit maximum on `shieldedSpends`/`shieldedReceives` list sizes in `createShieldedTransactionWithoutSpendAuthSig` (mirroring the `<3` cap already used in `createShieldedContractParametersWithoutAsk`) before any proof generation is attempted.
- Add cost-aware rate limiting (e.g., limit total spends/receives processed per IP per time window, not just request count) for both the gRPC and HTTP shielded-transaction-construction endpoints.
- Consider requiring a lightweight, cheap validation pass (e.g., structural/format checks that can reject clearly-invalid `ak`/`nsk`/`rcm`/payment-address inputs) prior to invoking `librustzcash` proof generation.

@Test
public void testUnboundedShieldedSpendsCauseExpensiveProofGeneration() throws Exception {
    Args.getInstance().setAllowShieldedTransactionApi(true);
    Wallet wallet = new Wallet();

    PrivateParametersWithoutAsk.Builder builder = PrivateParametersWithoutAsk.newBuilder();
    builder.setAk(ByteString.copyFrom(new byte[32]));
    builder.setNsk(ByteString.copyFrom(new byte[32]));
    builder.setOvk(ByteString.copyFrom(new byte[32]));

    // Add a large number of spend notes (e.g., 100+) with syntactically valid
    // but semantically bogus payment addresses/rcm/vouchers.
    for (int i = 0; i < 100; i++) {
        builder.addShieldedSpends(buildFakeSpendNote(i));
    }
    builder.addShieldedReceives(buildFakeReceiveNote());

    long start = System.nanoTime();
    try {
        wallet.createShieldedTransactionWithoutSpendAuthSig(builder.build());
    } catch (Exception ignored) {
        // Expected to eventually fail (e.g., proof/verification failure),
        // but only AFTER performing proof generation for every spend.
    }
    long elapsedMs = (System.nanoTime() - start) / 1_000_000;

    // Assert that elapsed time scales with the number of spends
    // (demonstrating proof generation is performed per spend before rejection),
    // and compare against a single-spend baseline to show near-linear cost growth
    // with no enforced upper bound.
    Assert.assertTrue("Expected proof-generation cost to scale with spend count",
        elapsedMs > SINGLE_SPEND_BASELINE_MS * 50);
}

Expected result: CPU time grows roughly linearly with the attacker-controlled spend count, with no `ContractValidateException` thrown early for exceeding a size limit — confirming the endpoint performs unbounded, underpriced cryptographic work before any authorization/signature check.

  public TransactionCapsule createShieldedTransactionWithoutSpendAuthSig(
      PrivateParametersWithoutAsk request)
      throws ContractValidateException, ZksnarkException, BadItemException {
    checkAllowShieldedTransactionApi();

    ZenTransactionBuilder builder = new ZenTransactionBuilder(this);

    // set timeout
    long timeout = request.getTimeout();
    if (timeout < 0) {
      throw new ContractValidateException("Timeout must >= 0");
    }
    builder.setTimeout(timeout);

    byte[] transparentFromAddress = request.getTransparentFromAddress().toByteArray();
    byte[] ak = request.getAk().toByteArray();
    byte[] nsk = request.getNsk().toByteArray();
    byte[] ovk = request.getOvk().toByteArray();

    if (ArrayUtils.isEmpty(transparentFromAddress) && (ArrayUtils.isEmpty(ak) || ArrayUtils
        .isEmpty(nsk) || ArrayUtils.isEmpty(ovk))) {
      throw new ContractValidateException("No input address");
    }

    long fromAmount = request.getFromAmount();
    if (!ArrayUtils.isEmpty(transparentFromAddress) && fromAmount <= 0) {
      throw new ContractValidateException("Input amount must > 0");
    }

    List<SpendNote> shieldedSpends = request.getShieldedSpendsList();
    if (!(ArrayUtils.isEmpty(ak) || ArrayUtils.isEmpty(nsk) || ArrayUtils.isEmpty(ovk))
        && shieldedSpends.isEmpty()) {
      throw new ContractValidateException("No input note");
    }

    List<ReceiveNote> shieldedReceives = request.getShieldedReceivesList();
    byte[] transparentToAddress = request.getTransparentToAddress().toByteArray();
    if (shieldedReceives.isEmpty() && ArrayUtils.isEmpty(transparentToAddress)) {
      throw new ContractValidateException("No output address");
    }

    long toAmount = request.getToAmount();
    if (!ArrayUtils.isEmpty(transparentToAddress) && toAmount <= 0) {
      throw new ContractValidateException("Output amount must > 0");
    }

    checkCmValid(shieldedSpends, shieldedReceives);

    try {
      // add
      if (!ArrayUtils.isEmpty(transparentFromAddress)) {
        builder.setTransparentInput(transparentFromAddress, fromAmount);
      }

      if (!ArrayUtils.isEmpty(transparentToAddress)) {
        builder.setTransparentOutput(transparentToAddress, toAmount);
      }

      // from shielded to public, without shielded receive, will create a random shielded address
      if (!shieldedSpends.isEmpty()
          && !ArrayUtils.isEmpty(transparentToAddress)
          && shieldedReceives.isEmpty()) {
        shieldedReceives = new ArrayList<>();
        ReceiveNote receiveNote = createReceiveNoteRandom(0);
        shieldedReceives.add(receiveNote);
      }

      // input
      if (!(ArrayUtils.isEmpty(ak) || ArrayUtils.isEmpty(nsk) || ArrayUtils.isEmpty(ovk))) {
        for (SpendNote spendNote : shieldedSpends) {
          GrpcAPI.Note note = spendNote.getNote();
          PaymentAddress paymentAddress = KeyIo.decodePaymentAddress(
              note.getPaymentAddress());
          if (paymentAddress == null) {
            throw new ZksnarkException(PAYMENT_ADDRESS_FORMAT_WRONG);
          }
          Note baseNote = new Note(paymentAddress.getD(),
              paymentAddress.getPkD(), note.getValue(), note.getRcm().toByteArray());

          IncrementalMerkleVoucherContainer voucherContainer =
              new IncrementalMerkleVoucherCapsule(
                  spendNote.getVoucher()).toMerkleVoucherContainer();
          builder.addSpend(ak,
              nsk,
              ovk,
              baseNote,
              spendNote.getAlpha().toByteArray(),
              spendNote.getVoucher().getRt().toByteArray(),
              voucherContainer);
        }
      }

      // output
      shieldedOutput(shieldedReceives, builder, ovk);

      return builder.buildWithoutAsk();
    } catch (ArithmeticException e) {
      throw new ZksnarkException("shielded amount overflow", e);
    } catch (ZksnarkException e) {
      logger.error("createShieldedTransaction exception, error is {}", e.toString());
      throw e;
    }
  }

  public TransactionCapsule build(boolean withAsk) throws ZksnarkException {
    TransactionCapsule transactionCapsule;
    long ctx = JLibrustzcash.librustzcashSaplingProvingCtxInit();

    try {
      // Create SpendDescriptions
      for (SpendDescriptionInfo spend : spends) {
        SpendDescriptionCapsule spendDescriptionCapsule = generateSpendProof(spend, ctx);
        contractBuilder.addSpendDescription(spendDescriptionCapsule.getInstance());
      }

      // Create OutputDescriptions
      for (ReceiveDescriptionInfo receive : receives) {
        ReceiveDescriptionCapsule receiveDescriptionCapsule = generateOutputProof(receive, ctx);
        contractBuilder.addReceiveDescription(receiveDescriptionCapsule.getInstance());
      }

      // Empty output script
      byte[] dataHashToBeSigned; //256
      transactionCapsule = wallet.createTransactionCapsuleWithoutValidate(
          contractBuilder.build(), ContractType.ShieldedTransferContract, timeout);

      dataHashToBeSigned = TransactionCapsule
          .getShieldTransactionHashIgnoreTypeException(transactionCapsule.getInstance());

      if (dataHashToBeSigned == null) {
        throw new ZksnarkException("cal transaction hash failed");
      }

      // Create spendAuth and binding signatures
      if (withAsk) {
        createSpendAuth(dataHashToBeSigned);
      }

      byte[] bindingSig = new byte[64];
      JLibrustzcash.librustzcashSaplingBindingSig(
          new BindingSigParams(ctx,
              valueBalance,
              dataHashToBeSigned,
              bindingSig)
      );
      contractBuilder.setBindingSignature(ByteString.copyFrom(bindingSig));
    } catch (ZksnarkException e) {
      throw e;
    } finally {
      JLibrustzcash.librustzcashSaplingProvingCtxFree(ctx);
    }

  @Override
  protected void service(HttpServletRequest req, HttpServletResponse resp)
      throws ServletException, IOException {

    RuntimeData runtimeData = new RuntimeData(req);
    IRateLimiter rateLimiter = container.get(KEY_PREFIX_HTTP, getClass().getSimpleName());

    // Check per-endpoint first to avoid consuming global IP/QPS quota for requests
    // that would be rejected by the per-endpoint limiter anyway. acquirePermit()
    // chooses blocking or non-blocking semantics based on rate.limiter.apiNonBlocking.
    boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
    boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);

    String contextPath = req.getContextPath();
    String url = Strings.isNullOrEmpty(req.getServletPath())
        ? MetricLabels.UNDEFINED : contextPath + req.getServletPath();
    // int64_as_string is honored only on GET requests (URL query). POST is intentionally
    // unsupported because reading the body here would consume request.getReader() and
    // break downstream servlets that read it themselves.
    if ("GET".equalsIgnoreCase(req.getMethod())) {
      JsonFormat.setInt64AsString(Util.getInt64AsString(req));
    }
    try {
      resp.setContentType("application/json; charset=utf-8");

      if (acquireResource) {
        Histogram.Timer requestTimer = Metrics.histogramStartTimer(
            MetricKeys.Histogram.HTTP_SERVICE_LATENCY, url);
        super.service(req, resp);
        Metrics.histogramObserve(requestTimer);
      } else {
        resp.getWriter()
            .println(Util.printErrorMsg(new IllegalAccessException("lack of computing resources")));
      }
    } catch (ServletException | IOException | BadMessageException e) {
      throw e;
    } catch (Exception unexpected) {
      logger.error("Http Api {}, Method:{}. Error：", url, req.getMethod(), unexpected);
    } finally {
      // CRITICAL: this clear pairs with the setInt64AsString call above. Removing it
      // will leak int64_as_string state across requests on reused Tomcat threads,
      // producing intermittent quoted/unquoted output that is very hard to debug.
      JsonFormat.clearInt64AsString();
      // Release whenever the per-endpoint permit was acquired (covers both the normal
      // completion path and the case where GlobalRateLimiter rejected the request).
      if (rateLimiter instanceof IPreemptibleRateLimiter && perEndpointAcquired) {
        ((IPreemptibleRateLimiter) rateLimiter).release();
      }
    }
