### Title
Gas-abstraction and gas-refund swaps use unprotected instantaneous AMM quotes with fixed 5% slippage, enabling sandwich attacks on ordinary users' deposits/refunds - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/outbound.go)

### Summary
`ExecuteInboundGas` (and `ExecuteInboundGasAndPayload`) and `applyGasRefund` both fetch an "expected output" quote from `QuoterV2.quoteExactInputSingle` via `GetSwapQuote` [1](#0-0)  and immediately use it to compute `minPCOut` as `quote * 95 / 100` — a flat 5% slippage tolerance with no TWAP or external price validation [2](#0-1) . This is structurally the same class of bug as the reported `getBPTExpected` issue: an unprotected, manipulable spot price feeds a min-output check that gates fund movement, with no additional oracle cross-check.

### Finding Description
When a user deposits gas on a source chain, once UVs finalize the inbound, `ExecuteInboundGas` deploys/looks up the UEA, then calls `GetUniversalCoreQuoterAddress`, `GetUniversalCoreWPCAddress`, `GetDefaultFeeTierForToken`, and `GetSwapQuote` to compute a `minPCOut` slippage floor before calling `CallPRC20DepositAutoSwap`, which performs `depositPRC20WithAutoSwap` on the `UniversalCore` contract using the on-chain Uniswap-V3-style pool [3](#0-2) . The same pattern is reused for outbound gas refunds in `applyGasRefund`, which calls `GetDefaultFeeTierForToken` and `getSwapQuoteForRefund` (wrapping `GetSwapQuote`) to compute `minPCOut` before `CallUniversalCoreRefundUnusedGas` [4](#0-3) .

Both quote and swap execute in the same block, but as separate, non-atomic EVM calls (`CallEVM` for the quote, then `DerivedEVMCall` for the swap) driven from Cosmos message handling, which is sequential per transaction — meaning any ordinary user able to place a transaction against the underlying WPC/gas-token pool immediately before the block containing the inbound-vote-finalizing transaction (or before it within the same block, depending on mempool ordering/priority) can move the spot price used by `quoteExactInputSingle`. Because `minPCOut` is derived from that same manipulated spot price with only a fixed 5% band, the floor does not protect the victim from price manipulation that already occurred before the quote was read — it only bounds further slippage after the (already-skewed) quote. An attacker with no privileged role (not a validator, UV, or TSS participant) can therefore sandwich ordinary users' gas top-up swaps or outbound gas refunds, extracting value from the swap executed on the user's behalf by the `uexecutor` module account.

This mirrors the reported root cause precisely: a min/max amount derived from a live, unauthenticated price source (here, an on-chain AMM spot quote rather than an external oracle) without any independent sanity check (TWAP, external price feed, or governance-set bound), used to gate value-moving operations for ordinary users.

### Impact Explanation
A successful sandwich reduces the PC amount an ordinary depositor receives from a gas-abstraction swap, or the amount refunded to a user after an outbound completes, effectively transferring value from the user (and indirectly the protocol, which executes the swap on their behalf via the module account) to the attacker. This falls under "corruption of ... gas fee accounting, refund accounting ... or canonical UniversalTx state" and unauthorized value extraction from user-facing swap flows reachable by an ordinary, unprivileged user's own deposit/withdrawal actions — no validator, TSS, or admin collusion required.

### Likelihood Explanation
Exploitability depends on the attacker's ability to get a manipulation transaction ordered immediately before the victim's inbound-execution transaction and a corrective transaction immediately after, within the liquidity available in the WPC/gas-token pool. This is a classic, well-understood MEV pattern against on-chain AMMs and is realistic wherever mempool visibility or priority-fee bidding allows transaction ordering influence, without needing any protocol-privileged role.

### Recommendation
Do not derive `minPCOut` purely from the instantaneous `quoteExactInputSingle` result. Use a time-weighted average price (TWAP) from the pool, cross-check against a governance-configured reference price/bound, and/or require a caller-supplied slippage-protected minimum with a maximum allowed deviation from a trusted price, similar to how Origin Protocol moved MEV defense to an external `ValueChecker` combined with sanity bounds that work without solely relying on the manipulable quote.

### Proof of Concept
1. Attacker observes an inbound gas-deposit (or outbound gas-refund) that will trigger `ExecuteInboundGas`/`applyGasRefund` for a given PRC20 gas token against the WPC pool.
2. Attacker submits a large swap against the same Uniswap-V3-style pool to move the spot price down for `tokenIn=PRC20, tokenOut=WPC`, timed to land immediately before the transaction that finalizes/executes the victim's inbound or outbound.
3. `GetSwapQuote` (`quoteExactInputSingle`) returns a depressed `amountOut`; `minPCOut = quote * 95 / 100` is computed from this depressed value [5](#0-4) .
4. `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes the swap at the manipulated price, succeeding because `minPCOut` was computed from the same manipulated quote.
5. Attacker reverses their position with a back-run swap, capturing the spread; the victim receives materially less PC than fair value for their gas top-up/refund.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
