Confirmed the key finding: `RevertStuckInbound` in `x/uexecutor/keeper/admin_revert.go:47-51` hard-requires `BALLOT_STATUS_EXPIRED` and explicitly rejects any other status, including `BALLOT_STATUS_REJECTED`. Test evidence (`TestBallotHook_SingleVariantRejectedRoutesToExpiredInbounds`) confirms that an inbound whose ballot is legitimately finalized as `REJECTED` (honest UVs voting `FAILURE`, e.g. because the on-chain observation was malformed, disputed, or simply didn't reach consensus as a success) is moved into `ExpiredInbounds` — the very same terminal audit-trail store used for `EXPIRED` ballots — but **the only recovery path (`MsgRevertStuckInbound`) refuses to process it** because it checks the *ballot's* live status, not the `ExpiredInbounds` entry, and a `REJECTED` ballot is a valid terminal state that never becomes `EXPIRED`.

### Title
Permanent freezing of user funds for REJECTED inbound ballots — no refund path exists (analogous to Blast's missing gas-mode re-enable) - (File: x/uexecutor/keeper/admin_revert.go)

### Summary
`MsgVoteInbound`/`VoteOnBallot` can legitimately finalize an inbound ballot as `BALLOT_STATUS_REJECTED` through ordinary honest-validator voting (2/3+ voting `FAILURE`). Once rejected, the per-variant audit trail is moved to `ExpiredInbounds` [1](#0-0) , but the chain's only inbound-refund mechanism, `RevertStuckInbound`, strictly requires the ballot to be in `BALLOT_STATUS_EXPIRED` and errors out otherwise [2](#0-1) . A `REJECTED` ballot never transitions to `EXPIRED` (it is already terminal), so no code path — automatic or admin-driven — can ever refund the user whose funds are already locked in the source-chain gateway. This mirrors the Blast bug's structural flaw: a terminal, admin/consensus-driven state transition (VOID gas mode / REJECTED ballot) permanently forecloses the only remediation mechanism (claimable gas mode / stuck-inbound revert), because no code path exists to bring the object back to a recoverable state.

### Finding Description
Every `Inbound` observed by Universal Validators is voted on via the generic ballot machine in `x/uvalidator` [3](#0-2) . A ballot finalizes as `PASSED` once the threshold of `SUCCESS` votes is reached, or as `REJECTED` the moment enough `FAILURE` votes make `PASSED` mathematically unreachable — this is normal, honest-validator behavior, not an attack or privileged action; it can be triggered by validators observing that the source-chain event fails their own validation criteria.

When this happens for an `INBOUND_TX` ballot, `BallotHooks.afterInboundBallotTerminal` moves the audit-trail entry into `ExpiredInbounds`, treating `REJECTED` identically to `EXPIRED` for bookkeeping purposes [4](#0-3) . Critically, at no point does `VoteInbound` create a `UniversalTx` for a `REJECTED` ballot the way it does for `PASSED` (which always creates a UTX, even on execution failure, specifically "so the user can always query what happened to their cross-chain tx instead of having funds silently stuck in the gateway contract" [5](#0-4) ).

The only remediation entry point, `RevertStuckInbound`, is gated strictly on the ballot being `EXPIRED`:
```go
if ballot.Status != uvalidatortypes.BallotStatus_BALLOT_STATUS_EXPIRED {
    return "", "", errors.Wrap(sdkErrors.ErrInvalidRequest, ...)
}
``` [2](#0-1) 

A `REJECTED` ballot can never satisfy this check because `BallotStatus` is a one-way terminal field — `MarkBallotFinalized` writes `REJECTED` permanently [6](#0-5)  and there is no code path anywhere in `x/uvalidator` or `x/uexecutor` that converts a `REJECTED` ballot into `EXPIRED` or synthesizes a UTX/refund for it. `AllExpiredInbounds` is documented as being "consumed by the future escape-hatch refund flow" [7](#0-6) , confirming that this flow is not yet implemented for either `EXPIRED` or `REJECTED` entries beyond the admin-only `EXPIRED`-gated `RevertStuckInbound`.

### Impact Explanation
Any inbound whose ballot is finalized `REJECTED` by honest, otherwise-correct Universal Validators results in permanent, unrecoverable loss of the user's deposited funds: the funds are already locked in the source-chain gateway (the deposit already happened), no `UniversalTx` is ever created to track or refund them, and the sole admin escape hatch explicitly refuses to act on anything but `EXPIRED` ballots. This falls squarely within "permanent freezing... of user or protocol-controlled funds" in the allowed impact set, reachable purely from a user's own inbound deposit interacting with the honest-validator voting flow — no malicious validator, admin, or governance action is required to reach the broken terminal state.

### Likelihood Explanation
`REJECTED` is a first-class, well-tested terminal ballot outcome (`TestIntegration_CheckIfFinalizingVote`, `TestIntegration_VoteOnBallot` both explicitly exercise it [8](#0-7) ), and is reachable whenever a meaningful minority of bonded UVs vote `FAILURE` on a legitimate inbound (e.g., differing interpretation of confirmation depth, a race between two variants where the wrong one gets enough `FAILURE` votes, or a validator bug causing systematic false negatives on an otherwise-valid deposit). This does not require any adversarial behavior — it is a foreseeable outcome of ordinary distributed observation.

### Recommendation
Extend `RevertStuckInbound` (or add an equivalent path) to also accept ballots in `BALLOT_STATUS_REJECTED`, and/or automatically synthesize a refund `UniversalTx`/outbound the moment `BallotHooks.afterInboundBallotTerminal` routes an entry into `ExpiredInbounds` for either `EXPIRED` or `REJECTED` variants, rather than depending solely on a future, not-yet-implemented "escape-hatch refund flow" and an admin-only, `EXPIRED`-only manual trigger.

### Proof of Concept
1. A user deposits funds on an external chain via the gateway, generating a legitimate `Inbound` event.
2. A supermajority (but not all) of bonded, honest Universal Validators submit `MsgVoteInbound` with `VoteResult_VOTE_RESULT_FAILURE` for this inbound (e.g., due to a validator-side interpretation difference on a borderline/malformed but real event) such that the voting threshold for `PASSED` becomes mathematically unreachable.
3. `VoteOnBallot`/`CheckIfFinalizingVote` finalizes the ballot as `BALLOT_STATUS_REJECTED` (see `TestIntegration_CheckIfFinalizingVote` "finalizing NO (REJECTED)" case).
4. `BallotHooks.afterInboundBallotTerminal` moves the entry to `ExpiredInbounds` (see `TestBallotHook_SingleVariantRejectedRoutesToExpiredInbounds`), and no `UniversalTx` is ever created for this inbound.
5. The admin (or anyone) calls `MsgRevertStuckInbound` for this inbound; `RevertStuckInbound` rejects it with `"ballot status is REJECTED; admin revert requires EXPIRED"`.
6. The user's deposited funds are permanently unrecoverable — no code path in the repository can ever refund them.

func (k Keeper) VoteOnBallot(
	ctx context.Context,
	id string,
	ballotType types.BallotObservationType,
	voter string,
	voteResult types.VoteResult,
	voters []string,
	votesNeeded int64,
	expiryAfterBlocks int64,
) (
	ballot types.Ballot,
	isFinalized bool,
	isNew bool,
	err error) {

	k.Logger().Debug("vote on ballot",
		"ballot_id", id,
		"ballot_type", ballotType.String(),
		"voter", voter,
		"vote_result", voteResult.String(),
		"votes_needed", votesNeeded,
	)

	ballot, isNew, err = k.GetOrCreateBallot(ctx, id, ballotType, voters, votesNeeded, expiryAfterBlocks)
	if err != nil {
		return ballot, false, false, errors.Wrap(err, "Error while voting on the ballot")
	}

	// reject votes on ballots whose nominal expiry has passed
	currentHeight := sdk.UnwrapSDKContext(ctx).BlockHeight()
	if ballot.IsExpired(currentHeight) {
		// Transition PENDING ballots to EXPIRED so subsequent reads see the
		// canonical status and the secondary indexes stay consistent. Already
		// non-PENDING ballots fall through to the Status check below for the
		// existing "already X" error message.
		if ballot.Status == types.BallotStatus_BALLOT_STATUS_PENDING {
			if mErr := k.MarkBallotExpired(ctx, id); mErr != nil {
				return ballot, false, isNew, errors.Wrap(mErr, "failed to mark ballot expired during late-vote rejection")
			}
			k.Logger().Warn("late vote rejected, ballot marked expired",
				"ballot_id", id,
				"expiry_height", ballot.BlockHeightExpiry,
				"current_height", currentHeight,
				"voter", voter,
			)
			return ballot, false, isNew, fmt.Errorf("ballot %s expired at height %d (current %d)", id, ballot.BlockHeightExpiry, currentHeight)
		}
	}

	if ballot.Status != types.BallotStatus_BALLOT_STATUS_PENDING {
		k.Logger().Warn("ballot is not in pending state, cannot vote",
			"ballot_id", id,
			"ballot_status", ballot.Status.String(),
			"voter", voter,
		)
		return ballot, false, false, fmt.Errorf("ballot %s is already %s", id, ballot.Status.String())
	}

	if isNew {
		k.Logger().Debug("created new ballot", "ballot_id", id, "ballot_type", ballotType.String())
		err := k.ActiveBallotIDs.Set(ctx, id)
		if err != nil {
			return ballot, false, false, errors.Wrap(err, "Error while voting on the ballot")
		}
	}

	ballot, err = k.AddVoteToBallot(ctx, ballot, voter, voteResult)
	if err != nil {
		return ballot, false, isNew, err
	}

	ballot, isFinalizing, err := k.CheckIfFinalizingVote(ctx, ballot)
	if err != nil {
		return ballot, false, false, err
	}

	return ballot, isFinalizing, isNew, nil
}
