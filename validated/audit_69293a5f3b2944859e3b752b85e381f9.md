### Title
`accrue` pauses interest accrual by silently returning stale indexes instead of reverting, letting borrow/repay/redeem proceed with a health check based on outdated data — ([File: mainnet/contracts/vault/v0-vault-stx.clar] and mirrored in v0-vault-sbtc.clar, v0-vault-usdc.clar, v0-vault-usdh.clar, v0-vault-ststx.clar, v0-vault-ststxbtc.clar)

### Summary
Every vault's `accrue` function, when the `accrue` pause flag is set, returns `(ok { index: idx, lindex: lidx })` using the *old*, unrefreshed `index`/`lindex` values instead of reverting the caller with `ERR-PAUSED` [1](#0-0) . This "pass-through" is exactly the analog class called out in the scan rules: a pause that passes through instead of reverting. Because `accrue` is called (and its return value trusted as fresh) at the start of `system-borrow`, `system-repay`, `redeem`, and by `market.clar`'s `accrue-and-cache`/`accrue-user-debts`/`accrue-user-collateral` for health-check and price/index calculations, pausing accrual does not block operations — it just makes every downstream caller silently compute health, debt, and collateral value using stale interest indexes while state-changing operations (`borrow`, `repay`, `redeem`, collateral valuation) continue to execute normally.

### Finding Description
The `accrue` function is structured as:
```clarity
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let (...)
            ...
            (ok { index: next, lindex: nliq })))))
``` [2](#0-1) 

This function is invoked unconditionally at the top of `system-borrow` and `system-repay` (bound via `(u (try! (accrue)))`), and inside `redeem` [3](#0-2) . None of these downstream functions check whether `accrue` was actually paused — they treat the returned `{index, lindex}` as authoritative regardless. The same pattern is used by `market.clar`'s `accrue-and-cache`, which the `borrow`, `collateral-add`, `collateral-remove` and liquidation flows rely on to compute `debt-value`/`collateral-value` for the `is-healthy`/`is-healthy-with-mask` checks [4](#0-3) .

Root cause: the guard (`accrue` pause flag) is checked, but instead of the guarded value being rejected (revert), the *stale* value is substituted and returned as `ok`. All callers that gate mutation on the health check (using this returned/cached index) proceed to mutate state — mint/burn shares, transfer underlying tokens, add/remove scaled debt — using health numbers computed off an index that has not accounted for elapsed time/interest since `last-update`. In effect the "clock" driving compounding interest is frozen for as long as `accrue` is paused, but borrowing, repaying, redeeming, and liquidation math still run using the frozen index as if it were current.

### Impact Explanation
While pausing `accrue` is presented as a deliberate pause switch, the failure mode is not "operations halt" (the intended semantics of a pause) but "operations silently continue on stale interest data." During the pause window:
- Borrowers can `borrow` and `repay` while interest fails to accrue, effectively freezing debt growth for borrowers system-wide (a freezing/theft-of-yield vector for suppliers, since underlying yield the protocol/suppliers are owed via `next-index`/`fee-reserve` growth stops accruing even though the position remains open and vault operations continue).
- `redeem`/`collateral-remove` health calculations use `debt-value` derived from the stale index, so a position that should have become unhealthy due to accrued interest can still pass `is-healthy` checks and allow collateral withdrawal, temporarily freezing/misallocating the true value of protocol reserves (`fee-reserve`→treasury ztoken minting is skipped for the whole pause duration since the mint of `treasury-lp` only happens in the "not paused" branch).
- This lands on the **High** impact bucket: theft/permanent-or-temporary freezing of unclaimed yield (the treasury/supplier side loses accrued reserve fee for the duration accrue is paused, and it cannot be recovered retroactively since accrual restarts only from the moment unpause occurs, based on `last-update` moving forward without ever "catching up" the missed interval).

### Likelihood Explanation
This requires the `accrue` pause flag being set (an admin/DAO action via `set-pause-*` type functions) while borrow/repay/redeem activity continues — which is plausible during normal incident-response pausing (e.g., pausing accrual only, intending other operations to continue) since the vault clearly supports independent pause flags per operation (`deposit`, `redeem`, `borrow`, `repay`, `accrue`, `flashloan`). Any operator who pauses only `accrue` (e.g., to freeze interest during an oracle incident) will unintentionally allow the described mismatch, since `accrue`-pausing is designed to be independently toggleable from `borrow`/`repay`/`redeem`.

### Recommendation
Do not let paused `accrue` return stale values as `ok`. Either:
1. Have `accrue` return an explicit error while paused, and have all callers (`system-borrow`, `system-repay`, `redeem`, and `market.clar`'s `accrue-and-cache`) `try!`-propagate this error so the whole state-changing operation reverts instead of silently proceeding on stale data, or
2. If the intent is genuinely to freeze interest accrual system-wide while still permitting borrow/repay/redeem, explicitly document and gate all dependent health/price computations to treat the frozen index consistently, and ensure `last-update` still reflects the freeze so that when unpaused, missed interest is either intentionally forfeited (documented) or captured, not just silently dropped.

### Proof of Concept
1. DAO/operator calls the vault's pause-setter to set `accrue: true` in `pause-states`, leaving `borrow`, `repay`, `redeem` unpaused.
2. Time passes (multiple blocks); the "true" interest index (`next-index`) would have increased substantially, but `index`/`lindex` data vars remain frozen since `accrue`'s paused branch never calls `var-set index`/`var-set lindex`/`var-set last-update`.
3. A borrower with an outstanding debt position calls `market.clar`'s `borrow` or `repay`, which calls `accrue-and-cache` → vault's `accrue`, which returns the stale `index` because `accrue` is paused [4](#0-3) .
4. Market's health check (`is-healthy`/`is-healthy-with-mask`) uses `debt-value` computed from this stale `index`, understating true debt; the borrower is judged healthy and permitted to borrow further or withdraw collateral that would be disallowed under the true, unfrozen index.
5. Meanwhile, the vault's `fee-reserve`→`treasury-lp` mint (supplier-side yield) is skipped entirely for the duration of the pause since it only executes in the "not paused" branch, permanently losing that portion of reserve fee accrual for the frozen interval since accrual restarts from `stacks-block-time` at unpause with no backfill.

I was not able to fully trace the exact pause-setter function names/permissions (e.g., which DAO call sets `accrue: true` independently) within the available index snippets, so the precise authorization path for triggering the pause state is not fully confirmed here — this would need to be verified directly in the vault's `set-pause-*` public function in the full file.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
