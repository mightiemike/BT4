### Title
Missing "class must be declared" check in Starknet OS `execute_replace_class` causes divergence from Blockifier execution and can corrupt committed state - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handler inside the Starknet OS (SNOS) Cairo program applies the state class-hash change unconditionally, without verifying that the target `class_hash` corresponds to a declared class. The equivalent Rust implementation used by the actual sequencer execution engine (`blockifier`) performs this exact check and additionally restricts replacement to Cairo1 classes. This creates a semantic gap between the component that actually executes transactions (blockifier, which decides what goes into a block) and the component that re-derives/proves the resulting state transition (the OS), analogous to the reported "unprotected public function" bug class where a state-mutating operation is missing an authorization/validity guard that exists in the reference implementation.

### Finding Description
`execute_replace_class` in `syscall_impls.cairo` writes a new `StateEntry` with the caller-supplied `class_hash` directly, with an explicit acknowledgement that the check is missing: [1](#0-0) 

By contrast, the blockifier's real syscall implementation (which is what actually gates state changes admitted into a block) enforces that the class is declared and is a Cairo1 class before allowing the replacement: [2](#0-1) 

The deprecated (Cairo0) blockifier syscall handler enforces the same "must be declared" invariant: [3](#0-2) 

The OS's own deprecated-syscall counterpart, `execute_replace_class` in `deprecated_execute_syscalls.cairo`, likewise performs the state-dict update without checking that the class is declared: [4](#0-3) 

The OS's job is to re-derive the state commitment from the same list of transactions the sequencer executed, and any account contract can invoke `replace_class_syscall` from an `__execute__` context reachable by an ordinary INVOKE transaction sender (see test contract usage of `replace_class_syscall`): [5](#0-4) 

Because the guard exists only on the blockifier side and not in the Cairo OS program that is used to compute/attest the state transition, the two components can disagree about the outcome of the same transaction whenever the hint-provided state entry / prover input does not itself enforce the same rule that blockifier enforces at execution time.

### Impact Explanation
If the OS accepts (and commits) a `replace_class` state update that blockifier itself would have rejected/reverted (undeclared class hash, or a Cairo0 class hash which blockifier explicitly forbids via `ForbiddenClassReplacement`), the state root computed/attested by the OS diverges from the state actually produced by the sequencer's execution engine. This can manifest as:
- A wrong committed state root / block hash (the OS proof attests to a state transition inconsistent with the protocol rule enforced in blockifier).
- Permanent freezing of funds in the affected contract: if a class hash is written that is not backed by any declared/compiled class, subsequent calls that need to load the class for that contract will fail, effectively bricking the contract's callable logic (and thus permanently locking any funds held by it).
- Honest-node divergence between nodes that trust the OS-derived output versus nodes that trust blockifier's block-execution output.

### Likelihood Explanation
The `replace_class` syscall is reachable directly by ordinary account contracts within their own `__execute__` context (no special privilege required); an attacker just needs to control (or reach) a contract entry point that calls `replace_class_syscall` with an attacker-chosen `class_hash`. Whether this is fully exploitable in practice depends on how tightly the hint program that supplies `GetContractAddressStateEntry`/related prover inputs is otherwise constrained elsewhere, and whether the "TODO" gap is closed by cross-checks in the surrounding declare/commitment logic. The explicit "TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash." comment in production OS code is direct evidence that this validation is currently absent and acknowledged as a gap in this repository, making the underlying bug class (missing validity check on a state-mutating operation reachable from an unprivileged transaction) concretely present.

### Recommendation
Add the same "class must be declared" (and, to match blockifier semantics, "class must be Cairo1") check in `execute_replace_class` in `syscall_impls.cairo` (and audit the deprecated counterpart in `deprecated_execute_syscalls.cairo`) before performing the `dict_update` that mutates `contract_state_changes`, mirroring the checks already present in `crates/blockifier/src/execution/syscalls/syscall_base.rs::replace_class` and `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs::replace_class`. This closes the semantic gap between block execution and OS-based state re-derivation/proving.

### Proof of Concept
Not directly executable as a standalone PoC from static analysis; the concrete reachable path is:
1. Deploy/act as any account contract with an entry point that calls `replace_class_syscall(class_hash)` with a `class_hash` that is not declared (or is a Cairo0 class), e.g. as exercised in the test contract's `test_forbidden_syscall_in_virtual_mode` / `fuzz_revert.cairo` `Scenario::ReplaceClass` path: [5](#0-4) 
2. In blockifier's real execution path, this call is expected to fail/revert due to the declared-class and Cairo1-only checks in `syscall_base.rs::replace_class`.
3. In the Starknet OS's Cairo re-execution of the same syscall (`syscall_impls.cairo::execute_replace_class`), no equivalent check exists, so the state dictionary is updated unconditionally, as shown at [6](#0-5) , demonstrating the divergence in enforced invariants between the two components that must otherwise agree on the resulting state commitment.

```rust
    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
```
