### Title
Unauthenticated JSON-RPC methods `citrea_haltCommitments` / `citrea_resumeCommitments` mutate sequencer state without any `Auth`/API-key check - (File: crates/sequencer/src/rpc.rs)

### Summary
The sequencer exposes `citrea_haltCommitments` and `citrea_resumeCommitments` as public JSON-RPC methods that mutate the sequencer's commitment-publishing state, but neither method is protected by the node's `Auth` middleware or any caller/ownership check, unlike the analogous access-control bug in the external report where a protected resource became reachable without the correct owner-bound credential.

### Finding Description
The sequencer's RPC middleware only special-cases three method names for API-key enforcement: [1](#0-0) 

Every other registered method — including `SequencerRpc::halt_commitments` and `SequencerRpc::resume_commitments` — is passed straight through to the handler with no authentication check: [2](#0-1) 

These two methods are defined and implemented with no internal permission check either — they unconditionally forward a control message to the sequencer runner: [3](#0-2) [4](#0-3) [5](#0-4) 

By contrast, `citrea_testPublishBlock` at least gates itself behind `self.context.test_mode`: [6](#0-5) 

and the only methods actually wired into the `Auth` layer's API-key gate are the `backup_*` methods, applied in `start_rpc_server`: [7](#0-6) 

This mirrors the report's bug class — a state-mutating/sensitive endpoint reachable without possessing the credential that is supposed to scope access to it — except here the missing binding is between "caller possesses the sequencer operator's API key" and "caller may mutate the sequencer's commitment-halt state," rather than an org-scoped KYC record.

### Impact Explanation
`halt_commitments`/`resume_commitments` toggle whether the sequencer continues publishing sequencer commitments to the DA layer (consumed in `crates/sequencer/src/runner.rs` and `crates/sequencer/src/commitment/service.rs`). Any unauthenticated caller with network access to the sequencer's JSON-RPC port can invoke `citrea_haltCommitments` to stop the sequencer's commitment pipeline, or `citrea_resumeCommitments` to resume it — an unauthenticated call that mutates node/rollup-relevant control state, which is explicitly listed as a High-severity impact category (an unauthenticated JSON-RPC call that mutates node state or bypasses `Auth`).

### Likelihood Explanation
No secret, prior exploit chain, or role is required — the method names and lack of gating are directly visible in `PROTECTED_METHODS`, and the RPC is reachable by anyone who can reach the sequencer's JSON-RPC endpoint, exactly the "unprivileged attacker" class the scan is scoped to. Likelihood is high wherever the sequencer's RPC port is reachable by non-operator callers.

### Recommendation
Add `citrea_haltCommitments` and `citrea_resumeCommitments` (and any other sequencer-control methods that mutate operational state) to `PROTECTED_METHODS` in `crates/common/src/rpc/auth.rs`, or otherwise require the operator API key / an explicit caller-authorization check inside `SequencerRpcServerImpl::halt_commitments` / `resume_commitments` before forwarding `SequencerRpcMessage::HaltCommitments` / `ResumeCommitments`.

### Proof of Concept
1. Start a sequencer with `RPC_API_KEY` configured (or unset) and its JSON-RPC endpoint reachable.
2. As an unauthenticated client, call:
   ```
   curl -X POST -H "Content-Type: application/json" \
     -d '{"jsonrpc":"2.0","id":1,"method":"citrea_haltCommitments","params":[]}' \
     http://<sequencer-rpc>:<port>
   ```
3. Because `citrea_haltCommitments` is absent from `PROTECTED_METHODS` in `crates/common/src/rpc/auth.rs:11`, the `Auth` middleware forwards the call directly (`crates/common/src/rpc/auth.rs:36-38`) to `SequencerRpcServerImpl::halt_commitments` (`crates/sequencer/src/rpc.rs:407-414`), which sends `SequencerRpcMessage::HaltCommitments` with no authorization check — succeeding without any API key, unlike `backup_create`/`backup_validate`/`backup_info`, which return `401` under the same conditions.
