### Title
Sender Can Invalidate a Pending Meta Transaction by Nonce Bump, Causing Relayer Gas Loss — (`runtime/runtime/src/actions.rs`)

---

### Summary

In nearcore's meta transaction system (NEP-366), a `DelegateAction` is signed off-chain by the sender and carries a nonce that is validated against the sender's on-chain access key nonce at execution time. Because the relayer pays gas for the outer transaction before the inner `DelegateAction` is validated on the sender's shard, a malicious sender can deliberately invalidate a pending meta transaction by submitting any regular transaction with the same access key first. This causes the relayer to lose the gas already burned for the outer transaction with no compensation, and the inner actions never execute.

---

### Finding Description

The `DelegateAction` struct embeds a `nonce` field that must be strictly greater than the sender's current access key nonce at the time the receipt is processed on the sender's shard. [1](#0-0) 

The enforcement happens in `validate_delegate_action_key`: [2](#0-1) 

The nonce is read live from the trie at receipt-execution time, not at transaction-submission time. The relayer's outer transaction is charged (gas burned) when it is converted to a receipt on the relayer's shard. Only later, when the receipt reaches the sender's shard, is the `DelegateAction` nonce validated.

**Attack sequence:**

1. Alice reads her current access key nonce `N` and signs a `DelegateAction` with `nonce = N + 1`.
2. Alice hands the `SignedDelegateAction` to a relayer.
3. The relayer wraps it in an outer transaction and submits it. Gas is charged and `SEND` costs are burned immediately on the relayer's shard.
4. Before the receipt reaches Alice's shard, Alice submits any regular transaction using the same access key with `nonce = N + 1` (e.g., a trivial self-transfer). This increments `ak_nonce` to `N + 1`.
5. The relayer's receipt arrives at Alice's shard. `validate_delegate_action_key` reads `current_nonce = N + 1` and checks `delegate_nonce (N+1) <= current_nonce (N+1)` → **true** → `DelegateActionInvalidNonce` is returned.
6. The inner actions never execute. The relayer has already lost the `SEND(relayer→Alice)` cost plus the `EXEC` cost for the delegate action itself.

The nonce update path that the attacker exploits is the standard access key nonce update in `verify_and_charge_tx_ephemeral`: [3](#0-2) 

Any transaction signed with the same key — a dust transfer, an `AddKey`/`DeleteKey`, a no-op function call — is sufficient to bump the nonce and invalidate the pending `DelegateAction`.

The nearcore documentation acknowledges the general trust problem but does not close this specific attack vector: [4](#0-3) 

---

### Impact Explanation

**Loss of funds (relayer).** The relayer loses the gas burned for the outer transaction — specifically the `SEND` cost from the relayer's shard to Alice's shard and the `EXEC` cost for the delegate action on Alice's shard — with no refund path. If the inner actions carried an attached deposit (e.g., a `Transfer`), the deposit is also at risk depending on the refund predecessor at the point of failure.

**Fee payment bypass.** If the `DelegateAction` included a fee payment to the relayer (the canonical FT-fee pattern), the sender can abort the entire meta transaction after the relayer has committed gas, receiving the service without paying the fee.

**Repeated exploitation.** The attack costs the sender only the gas for one cheap transaction per meta transaction invalidated. On NEAR's low-fee L1 and any L2 deployment, this is economically viable to repeat indefinitely.

---

### Likelihood Explanation

Any account that has signed a `DelegateAction` and handed it to a relayer retains full control over its own access key nonce. No special privilege, validator access, or mempool visibility is required. The sender simply submits a cheap transaction in the same block or the next block before the relayer's receipt is processed. Because NEAR processes transactions and receipts in separate phases within a chunk, the window for this race is reliably exploitable.

---

### Recommendation

1. **Separate nonce namespace for delegate actions.** Introduce a dedicated nonce counter for `DelegateAction` that is not shared with regular transactions signed by the same key. This is the structural fix: bumping the regular transaction nonce would not affect the delegate nonce.

2. **Commit-reveal or pre-registration.** Require the sender to register the `DelegateAction` hash on-chain before the relayer submits, so the relayer can verify commitment before paying gas.

3. **Relayer-side nonce (already discussed in docs).** Use the relayer's access key nonce for replay protection instead of the sender's, accepting the documented trade-off that concurrent meta transactions from different senders share a counter.

---

### Proof of Concept

```
# State: Alice's access key nonce = 5

# Step 1: Alice signs DelegateAction(nonce=6, actions=[ft_transfer(relayer, fee), ft_transfer(john, 10)])
# Step 2: Alice sends SignedDelegateAction to relayer off-chain

# Step 3: Relayer submits outer tx (nonce=100, signer=relayer, receiver=alice, actions=[Delegate(signed_da)])
#         → Gas charged at relayer shard; SEND cost burned immediately

# Step 4: Alice submits regular tx (nonce=6, signer=alice, receiver=alice, actions=[Transfer(1 yocto)])
#         → Included in same or next chunk; alice.ak_nonce becomes 6

# Step 5: Relayer's receipt reaches Alice's shard
#         validate_delegate_action_key:
#           current_nonce = get_access_key(alice, pubkey).nonce  // = 6
#           delegate_nonce = 6
#           6 <= 6  →  DelegateActionInvalidNonce
#         Inner actions never execute.

# Result: Relayer lost SEND + EXEC gas. Alice paid ~1 yocto + cheap tx gas.
#         Relayer received no fee. John received no transfer.
```

The exact gas burned by the relayer is `SEND(relayer→alice, not_sir)` + `EXEC(delegate_action)`, both non-zero and non-refundable once the receipt has been created. [5](#0-4) [6](#0-5) [7](#0-6)

fn validate_delegate_action_key(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    delegate_action: VersionedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let sender_id = delegate_action.sender_id();
    let public_key = delegate_action.public_key();
    // 'sender_id' account existence must be checked by a caller
    let mut access_key = match get_access_key(state_update, sender_id, public_key)? {
        Some(access_key) => access_key,
        None => {
            result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                InvalidAccessKeyError::AccessKeyNotFound {
                    account_id: sender_id.clone(),
                    public_key: public_key.clone().into(),
                },
            )
            .into());
            return Ok(());
        }
    };

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
    };

    if delegate_nonce.nonce() <= current_nonce {
        result.result = Err(ActionErrorKind::DelegateActionInvalidNonce {
            delegate_nonce: delegate_nonce.nonce(),
            ak_nonce: current_nonce,
        }
        .into());
        return Ok(());
    }
