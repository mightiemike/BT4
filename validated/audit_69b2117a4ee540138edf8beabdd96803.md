Beyond that mismatch, tracing the actual `PackedAncientStorage::pack` implementation shows the packing loop always makes forward progress and cannot silently drop or duplicate accounts, even at ideal-size boundaries:

- The fast path (`bytes_total_with_this_slot <= ideal_size`) consumes an entire alive-accounts set at once, which is size-safe by construction. [1](#0-0) 
- The slow, per-account path only breaks (`full = true`) without consuming an account when `new_size > ideal_size && bytes_total > 0`, i.e., only after at least one account has already been committed to the current storage. When `bytes_total == 0` (first account of a fresh storage), the account is unconditionally included even if it alone exceeds `ideal_size`, guaranteeing that a single oversized account is still emitted rather than dropped. [2](#0-1) 
- `partial_inner_index` is only left unadvanced when `full` is set, but in that case the same account is retried from `bytes_total == 0` on the next outer loop iteration, so it is never skipped, and the outer loop only terminates when the iterator is exhausted and `accounts_to_write` is empty.
