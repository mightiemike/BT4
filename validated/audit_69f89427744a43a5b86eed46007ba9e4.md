### Title
Unbounded, non-deduplicated growth of the per-shop session-ID index causes DoS of `findSessionsByShop` and downstream auth/uninstall handlers - (File: `packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`)

### Summary
`KVSessionStorage` (and, to a lesser degree, the Redis, DynamoDB and CSV example adapters) maintain a per-shop index of session IDs (`shop:<shop>` key) that is read and appended to on every call to `storeSession`, with no deduplication, cap, or pagination. Because `storeSession` is invoked on essentially every authenticated request that needs to (re-)issue or refresh a session — e.g. `performTokenExchange` in `shopify-app-express` — a single merchant/customer can trigger unbounded, duplicate-laden growth of this array. `findSessionsByShop`, which is relied on by `AppInstallations.includes`/`AppInstallations.delete` (used by the `APP_UNINSTALLED` webhook handler) and other session lookups, then has to fetch and iterate the entire unbounded list, degrading or ultimately DoS-ing the authentication/uninstall handling path. This mirrors the reported bug class: "no limit on array elements nor pagination" leading to DoS of key lookup/view functions.

### Finding Description
`KVSessionStorage.storeSession` unconditionally appends the session ID to the shop's index list every time it is called: [1](#0-0) 

The append itself has no de-duplication or size limit: [2](#0-1) 

`findSessionsByShop` then reads this same unbounded list and calls `loadSession` for every entry (including duplicates), with no pagination: [3](#0-2) 

`storeSession` is called from a normal, unprivileged, per-request authentication path — `performTokenExchange`, which runs whenever a request's local session is missing or inactive (e.g., token refresh, re-embed, or simply hitting the app repeatedly with an expired/near-expiry session): [4](#0-3) 

Since the offline session ID is deterministic (`offline_<shop>`), each of these calls re-adds the *same* ID to the shop index without ever deduplicating it, so the index only ever grows. The same applies to non-embedded, online sessions, whose IDs are `crypto.randomUUID()`-generated on every OAuth callback completion, guaranteeing genuinely unique new entries per authentication cycle: [5](#0-4) 

`findSessionsByShop` is consumed by `AppInstallations.includes`/`AppInstallations.delete`, which are used by the `APP_UNINSTALLED` webhook handler to determine and clean up install state: [6](#0-5) [7](#0-6) 

As the shop index grows without bound, `findSessionsByShop` must fetch and sequentially resolve an ever-larger (and duplicate-laden) list of session IDs, causing increasing latency, memory pressure, and eventually failure/timeout of the uninstall webhook handler and any other caller of `findSessionsByShop`/`AppInstallations`.

### Impact Explanation
This is a Denial-of-Service of an authentication-adjacent handler: the `APP_UNINSTALLED` cleanup path (and any other consumer of `findSessionsByShop`) can be degraded or rendered unusable for a specific shop by that shop's own normal (or deliberately repeated) authentication traffic, because the storage layer performs unbounded, non-deduplicated appends with no pagination on read. This matches the reported bug class (unpaginated, unbounded arrays causing DoS of lookup/view functionality) applied to shopify-app-js's session-storage/auth-handler surface rather than to on-chain view functions.

### Likelihood Explanation
High for the KV adapter's basic case: `storeSession` is called on ordinary, unprivileged request flows (token exchange, OAuth callback) that any merchant/customer interacting with the app can trigger repeatedly without any special privilege, and there is no cap, dedup, or pagination anywhere in the write or read path.

### Recommendation
- De-duplicate session IDs before appending in `addShopIds` (and equivalent logic in other adapters that don't already dedup, e.g. compare against Redis's `idKeysArray.includes(idKey)` check which KV lacks).
- Cap and/or paginate `findSessionsByShop` reads, and prune stale/expired session IDs from the per-shop index as part of `storeSession`/cleanup.
- Ensure `AppInstallations.includes`/`delete` and the `APP_UNINSTALLED` handler operate against a bounded, paginated view rather than materializing the full session list.

### Proof of Concept
1. Deploy an app using `KVSessionStorage` with an embedded app configuration where `useOnlineTokens` triggers frequent `performTokenExchange` calls, or a non-embedded app where the online OAuth flow is repeatable.
2. As a normal merchant/customer, repeatedly force the app into the "no valid session" branch (e.g., let sessions approach `WITHIN_MILLISECONDS_OF_EXPIRY` or repeatedly complete OAuth), causing many calls to `config.sessionStorage.storeSession(...)`.
3. Each call appends to the `shop:<shop>` KV entry via `addShopIds` without dedup; the entry grows without bound.
4. Trigger `APP_UNINSTALLED` (or any other code path calling `findSessionsByShop`); observe `loadSession` being invoked once per (duplicated) entry, causing linearly increasing latency/resource consumption until the handler times out or fails.

  public async findSessionsByShop(shop: string): Promise<Session[]> {
    const sessionIds = await this.namespace.get<string[]>(
      this.getShopSessionIdsKey(shop),
      {type: 'json'},
    );

    if (!sessionIds) {
      return [];
    }

    return Promise.all(
      sessionIds.map(async (id) => (await this.loadSession(id))!),
    );
  }

  private async addShopIds(shop: string, ids: string[]) {
    const key = this.getShopSessionIdsKey(shop);
    const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
    await this.namespace.put(key, JSON.stringify([...shopIds, ...ids]));
  }

  async includes(shopDomain: string): Promise<boolean> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      for (const session of shopSessions) {
        if (session.accessToken) return true;
      }
    }
    return false;
  }

  async delete(shopDomain: string): Promise<void> {
    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      await this.sessionStorage.deleteSessions!(
        shopSessions.map((session: Session) => session.id),
      );
    }
  }
