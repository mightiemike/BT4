### Title
Unprivileged attacker can drain any smart contract's native UPC balance via forged CEA inbound gas-fee deduction - (File: x/uexecutor/keeper/execute_inbound_funds_and_payload.go)

### Summary
The Augur bug lets an attacker supply an untrusted parameter (`_universe`) that a "trusted" module (`MarketFactory`) uses to move a victim's approved funds without the victim's consent. The Push Chain analog is the CEA (Contract-Executable-Address) inbound path in `x/uexecutor`: the `Inbound.Recipient` and `Inbound.UniversalPayload` fields are attacker-controlled (derived from an event the attacker themselves emits on an external chain), yet the executor treats any non-UEA contract at that recipient address as a legitimate "CEA" target, calls `executeUniversalTx` on it, and then unconditionally debits real native `upc` gas fees from that contract's own balance — with no check that the contract opted in to be a CEA recipient or authorized this call.

### Finding Description
`ExecuteInboundFundsAndPayload` (and its `GAS_AND_PAYLOAD` sibling `ExecuteInboundGasAndPayload`) resolves `isCEA` recipients purely by address shape and bytecode presence: [1](#0-0) 

If the recipient is not a registered UEA but has non-empty code (`isSmartContract = true`), the module deposits PRC20 and then calls `executeUniversalTx` on that arbitrary contract with attacker-chosen payload bytes, followed by gas-fee deduction from the recipient's own balance in the same cached scope: [2](#0-1) 

`DeductGasFeesFromReceipt` then burns `effectiveGasPrice * gasUsed` from the recipient's native `upc` balance based on `MaxFeePerGas`/`GasLimit` taken from `utx.InboundTx.UniversalPayload` — a field decoded from the attacker's own raw inbound event, not signed or approved by the recipient contract in any way: [3](#0-2) 

Crucially, unlike the UEA path where `executeUniversalTx` on the owner's UEA contract enforces a cryptographic signature check before any state/fund movement (documented explicitly as the safety guarantee for `Signer ≠ Owner`): [4](#0-3) 

...the CEA/smart-contract branch has **no equivalent authorization gate**. There is no registry of which contracts have opted in to receive CEA calls, and no verification that the "sender"/payload actually originated from, or was authorized by, the target contract's owner. Anyone can trigger an inbound (by calling the gateway on any inbound-enabled external chain) specifying:
- `Recipient` = any existing Push Chain contract address that holds a native `upc` balance and is not a UEA,
- `UniversalPayload.Data` = arbitrary calldata,
- `UniversalPayload.MaxFeePerGas` / `GasLimit` = attacker-chosen values.

Honest Universal Validators will observe and vote this exactly as submitted (they are "dumb relays" per the inbound validation pipeline docs), so the ballot passes with entirely honest validators — no validator or node compromise is required. If the target contract's fallback/receive logic (or a matching selector) does not outright revert the `executeUniversalTx` call, the module still charges real gas fees out of that contract's PC-chain balance via `k.DeductAndBurnFees`, i.e. it drains a third party's on-chain funds triggered solely by an attacker-authored source-chain transaction.

This mirrors the Augur pattern precisely: a module (`MarketFactory`/`x/uexecutor`) treats an attacker-supplied identifier (`_universe`/`Recipient`) as sufficiently trusted to authorize movement of a victim's funds, because the "trusted" transfer authority (`Augur.trustedTransfer`/`k.DeductAndBurnFees`) does not re-validate that the counterparty actually consented.

### Impact Explanation
This allows unprivileged draining/loss of user- or protocol-controlled native `upc` funds from any qualifying smart contract on Push Chain (funds accounting corruption / unauthorized burn), reachable purely through ordinary, honestly-relayed external-chain deposits — squarely in scope ("corruption of ... gas fee accounting ... reachable from ordinary user deposits ... alone"). Repeated invocation against the same contract can be used to grief/drain its balance entirely, and because `writeCache()`/burn happens even though the contract never asked to be called, this is an unauthorized, module-originated fund movement.

### Likelihood Explanation
The trigger requires no privileged role: any address can submit a qualifying event on any chain that `x/uregistry` marks inbound-enabled, targeting any deployed non-UEA contract holding `upc`. The main precondition (a target contract whose fallback doesn't revert on an unexpected call) is common for many contract types (proxies, contracts with permissive fallbacks, multisigs, etc.), making this practically reachable rather than purely theoretical.

### Recommendation
Require the CEA recipient contract to explicitly opt in (e.g., via a registry/allowlist maintained in `x/uregistry`, or an on-chain marker interface the contract must implement and that the keeper verifies before calling `executeUniversalTx`), similar to how the UEA path gates fund movement behind a cryptographic signature check. At minimum, do not deduct gas fees from a contract that never authorized/expected to be a CEA recipient — e.g., only allow `DeductGasFeesFromReceipt` to run against contracts registered as legitimate CEA recipients, mirroring the Augur fix pattern of validating that the attacker-supplied identifier corresponds to a known, trusted entity before granting it the ability to move funds.

### Proof of Concept
Conceptual PoC (not fully verified end-to-end due to index limitations on gateway/event-decoding internals):
1. Attacker deploys/identifies an existing Push Chain contract `V` (not a UEA) holding a non-trivial `upc` balance, whose fallback function does not revert on arbitrary calldata (e.g. a payable-fallback proxy or a contract with a catch-all function).
2. On any inbound-enabled external chain, attacker calls the Gateway contract's deposit method with `recipient = V`, `isCEA = true`, `tx_type = FUNDS_AND_PAYLOAD`, and a crafted `UniversalPayload` (`Data`, `MaxFeePerGas`, `GasLimit` of attacker's choosing).
3. Honest Universal Validators observe this real event and vote `MsgVoteInbound` exactly as emitted — ballot passes with 2/3 honest votes.
4. `ExecuteInboundFundsAndPayload` sees `isCEA=true`, resolves `V` as a smart contract (not UEA), deposits PRC20, then calls `CallExecuteUniversalTx` on `V` with attacker's payload.
5. If `V`'s call does not revert, `DeductGasFeesFromReceipt` burns real gas cost from `V`'s native `upc` balance — funds `V`'s owner never authorized to spend, as verified in the code path [5](#0-4)  and [6](#0-5) .

// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}

#### Where authorization actually lives

The cryptographic binding is enforced inside the UEA contract's `executeUniversalTx` (see [`UEA_EVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_EVM.sol#L145) and [`UEA_SVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_SVM.sol)):

1. The contract holds the owner's public key as **immutable bytes** set at UEA deployment via `initialize(_id, _factory)`. There is no code path that mutates this after init.
2. `executeUniversalTx(payload, signature)` verifies the `signature` (passed in as `MsgExecutePayload.VerificationData`) against this stored owner — ECDSA recovery for EVM-origin owners, the Ed25519 precompile (`0x00…00ca`) for SVM-origin owners.
3. The signed payload hash includes a contract-tracked `nonce` (monotonic per UEA) and optional `deadline`, providing replay and freshness protection.
4. If signature verification fails, the contract reverts. The revert propagates as `execErr` from `CallUEAExecutePayload`; the keeper returns the error from `ExecutePayload`; the entire Cosmos transaction (including any partial gas-fee deduction) rolls back atomically. **No state changes survive a failed signature check.**

#### Why this is safe under `Signer ≠ Owner`

An attacker submitting `MsgExecutePayload` with their own `Signer` and a victim's `UniversalAccountId` produces no exploitable outcome:

- The factory resolves the victim's UEA address from the embedded `UniversalAccountId` — correct.
- `evmFrom` (derived from `Signer`) becomes the EVM-level `msg.sender` of the call to the UEA. Since `evmFrom != UNIVERSAL_EXECUTOR_MODULE` (`0x14191Ea54B4c176fCf86f51b0FAc7CB1E71Df7d7`), the contract enforces the signature check.
- The attacker cannot forge `VerificationData` that recovers to the victim's owner key.
- The contract reverts → the keeper returns an error → the Cosmos transaction reverts in full.
- Net effect: zero state change. No EVM gas is charged to the victim UEA (the deduction is rolled back with the rest of the transaction). The submission costs the attacker nothing on chain (gasless), but also achieves nothing.
