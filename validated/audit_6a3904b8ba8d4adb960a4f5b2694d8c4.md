### Title
Sandwichable spot-price swap quote enables value extraction from protocol-controlled gas-abstraction swaps - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
Push Chain's gas-abstraction auto-swap flow (`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, `applyGasRefund`) computes a slippage-protected minimum output for an on-chain PRC20→WPC swap, but the "protection" is derived from a same-block spot-price quote (`GetSwapQuote` → Uniswap `QuoterV2.quoteExactInputSingle`) rather than a TWAP or a caller/user-specified bound. This is the same root cause the external report describes for `addLiquidity`/`removeLiquidity`: the amount used to compute the guardrail is fetched at execution time from a manipulable price, so the guardrail itself can be manipulated by an unprivileged actor to still permit an unfavorable execution price.

### Finding Description
When an inbound of type `GAS` or `GAS_AND_PAYLOAD` is executed, or when unused gas is refunded on outbound completion, the protocol performs an automatic swap of the deposited PRC20 gas token into WPC via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`: [1](#0-0) 

The `minPCOut` slippage floor is computed inline from `GetSwapQuote`, which is a live spot-price read of the AMM pool in the very transaction that performs the swap: [2](#0-1) 

The same pattern (fetch quote → 95% floor → immediate swap, all in one call) repeats in `gasAndPayloadDepositAutoSwap` and in `applyGasRefund`: [3](#0-2) [4](#0-3) 

An unprivileged attacker who can move the underlying Uniswap V3 pool's spot price in the same block (a swap, flash loan, or JIT liquidity change) can:
1. Push the pool price to an unfavorable rate,
2. Trigger — or wait for — the honest-validator-driven `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`/outbound-refund flow to run (these flows execute automatically once inbound/outbound consensus is reached and are not gated by any external caller-supplied minimum), and
3. Because the 5% slippage floor is derived from the already-manipulated quote, the swap executes and passes its own check even though the user (the UEA/gas-payer) receives materially less WPC than the true market rate would provide,
4. Restore the pool price afterward to complete the sandwich, capturing the difference.

There is no user-controlled or externally supplied price limit / minimum-out parameter anywhere in this flow — the guardrail is entirely self-referential (quote now, accept 95% of that same now-quote).

### Impact Explanation
This directly corrupts PRC20/native asset accounting and gas fee accounting on ordinary, unprivileged user deposits: the amount of WPC actually credited toward a user's gas balance (or refunded on outbound completion) can be worse than fair value, resulting in an effective, repeatable value transfer from users/protocol to the attacker executing the sandwich. This falls under "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" in the allowed-impact scope, triggered purely by an unprivileged attacker manipulating a public AMM pool around an honest-validator-executed inbound/outbound — no privileged or malicious-validator behavior is required.

### Likelihood Explanation
Exploitability depends on the liquidity depth of the specific PRC20/WPC Uniswap V3 pool and the size of the inbound-triggered swap, and it requires precise timing to land the manipulation and the protocol's swap transaction in the same block/sandwich window (achievable via MEV/searcher infrastructure or, on chains without strict MEV protection, straightforward front-running of the validator's broadcast transaction). Given the 5% band is fairly generous and self-referential, the attack is economically feasible whenever pool liquidity is thin relative to swap size.

### Recommendation
- Use a TWAP-based or otherwise manipulation-resistant reference price (not a single-block spot quote) to bound `minPCOut`, or
- Fetch the quote from a source that cannot be moved atomically by the same actor executing the swap (e.g., Chain Meta Oracle-style multi-validator median, or a longer observation window),
- Consider tightening the slippage tolerance and/or making it configurable via governance-controlled parameters rather than hardcoded 95%,
- Where feasible, add a max staleness/deviation check between the discovered quote and a longer-horizon TWAP before allowing the swap to proceed.

### Proof of Concept
1. Attacker identifies the PRC20/WPC Uniswap V3 pool used by `GetDefaultFeeTierForToken`/`GetSwapQuote` for a given gas token.
2. Attacker submits a large swap against that pool to skew the spot price unfavorably for PRC20→WPC conversion.
3. In the same block (or immediately before), a Universal Validator broadcasts the `MsgVoteInbound`/`MsgVoteOutbound` finalization that triggers `ExecuteInboundGas` → `CallPRC20DepositAutoSwap`, or an outbound completion triggers `applyGasRefund` → `CallUniversalCoreRefundUnusedGas` with `withSwap=true`.
4. `GetSwapQuote` returns the manipulated price; `minPCOut = quote * 95/100` is computed from that same manipulated value, so it does not block the unfavorable trade.
5. The auto-swap executes at the bad price, and the attacker reverses their initial swap, netting the difference at the expense of the gas-payer/refund-recipient's expected WPC amount.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
