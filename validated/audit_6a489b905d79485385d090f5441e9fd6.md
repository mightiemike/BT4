### Title
Single-transaction "flash freeze/vote" can drain historical Super Representative rewards via `VoteRewardUtil.withdrawReward` - (File: actuator/src/main/java/org/tron/core/vm/utils/VoteRewardUtil.java)

### Summary
The bug-class described in the report — using a "flash" primitive that grants a large, ephemeral balance within a single transaction to manipulate a `redeem`-style function that assumes the balance was held over time — has a direct analog in java-tron's TVM-exposed staking/voting native contracts. A smart contract can call `freezeBalanceV2` → `voteWitness` → `withdrawReward` → `unfreezeBalanceV2` all within one transaction. Because reward accounting is based on the account's *current* vote weight applied across the *entire historical* cycle range since the account's (default, uninitialized) `beginCycle`, an attacker can borrow/self-fund a large TRX amount, freeze it for voting power for a single transaction, and immediately redeem rewards accrued by the witness over potentially many past cycles it never actually participated in, then unfreeze to recover the principal — extracting value from the shared reward pool without real economic exposure.

### Finding Description
The relevant TVM opcodes are wired directly to native processors that can all be invoked by contract code in one call chain: [1](#0-0) [2](#0-1) 

These map to `Program.freezeBalanceV2`, `Program.voteWitness`, and `Program.withdrawReward`, each of which validates and commits synchronously within the same transaction: [3](#0-2) [4](#0-3) 

The reward computation itself, `VoteRewardUtil.withdrawReward` (used both by the actuator path and the TVM native-contract path via `WithdrawRewardProcessor`), computes reward for the range `[beginCycle, endCycle)` using the **current** vote list of the account rather than a historical snapshot of votes actually held during those cycles: [5](#0-4) [6](#0-5) 

`beginCycle` defaults to `0` for any account that has never voted (no persisted delegation record), and `endCycle` is advanced to `currentCycle` on first use: [7](#0-6) [8](#0-7) 

`computeReward` then multiplies the *current* `userVote` (the vote count the attacker just cast using freshly-frozen TronPower) by `deltaVi = endVi - beginVi`, where `beginVi`/`endVi` reflect the witness's accumulated reward-per-vote across essentially its whole history (since `beginCycle-1 = -1` for a fresh account), not just the period the attacker actually held the vote: [6](#0-5) 

This mirrors the reported bug class precisely: `freezeBalanceV2` acts as the "flash mint" (grants large, ephemeral voting power funded transiently within one transaction), `voteWitness` establishes the position, and `withdrawReward` acts as the unguarded "redeem" that pays out based on a manipulable, non-time-weighted invariant (current vote count applied over unrelated historical deltaVi), all reachable purely through TVM opcodes without any privileged role, then `unfreezeBalanceV2` (the "burn") returns the principal.

### Impact Explanation
If exploitable, this allows unauthorized extraction of Super Representative (SR)/voter reward pool funds proportional to `deltaVi * temporarily_held_vote_count`, i.e., asset/accounting corruption: an attacker's temporarily-frozen TRX can siphon rewards that rightfully belong to long-term voters who held votes throughout the historical cycles, directly draining the `allowance` balances funded by `MortgageService.payReward`/`delegationStore.addReward`. This is a concrete asset/accounting corruption vector reachable from any account via an ordinary contract call — no privileged actor, leaked key, or malicious peer required.

### Likelihood Explanation
Reachability is high in principle: `freezeBalanceV2`, `voteWitness`, and `withdrawReward` are all exposed as standard TVM opcodes callable by any contract in any broadcast transaction, and the vulnerable code path (`computeReward` using current votes across a wide historical cycle range for accounts with default `beginCycle = 0`) is exercised on every fresh voter's first `withdrawReward` call. However, whether this results in profit depends on the magnitude of `deltaVi` accumulated by the target witness prior to `currentCycle` (which could be very large for long-lived witnesses) versus the cost of freezing TRX for one transaction (only the TRX itself, immediately recoverable via `unfreezeBalanceV2` net of any unfreeze-delay/lockup enforced by `UnfreezeBalanceV2Actuator`/`calcUnfreezeExpireTime`). I was not able to fully verify from the index whether an unfreeze-delay (`FROZEN_PERIOD`/`unfreezeDelayDays`) prevents the attacker from reclaiming the frozen principal within the same transaction/block, which would reduce (but not eliminate, since capital can be reused across multiple blocks while still amortized against a single reward claim) the practical severity — this needs confirmation via a full Devin session with test execution.

### Recommendation
- **Short term:** In `VoteRewardUtil.computeReward` (and the equivalent `MortgageService.computeReward`), do not apply the account's *current* vote count over cycle ranges the account did not actually hold votes for. Track and use per-cycle vote snapshots (similar to the `beginCycle+1 == endCycle` single-cycle branch that already uses `getAccountVote`) for the entire `[beginCycle, endCycle)` range, or require `beginCycle` to be initialized to `currentCycle` (not `0`) upon first vote so no historical `deltaVi` window predates the account's actual participation.
- **Long term:** Avoid reward formulas that let a single transaction's ephemeral resource state (frozen TronPower) retroactively apply to reward periods the account was not part of; enforce time-weighted or cycle-snapshot-based accounting consistently across all reward computation paths (`VoteRewardUtil`, `MortgageService`).

### Proof of Concept
1. Deploy a contract with sufficient TRX balance (attacker-controlled).
2. In a single transaction, the contract calls the TVM opcode sequence:
   - `freezeBalanceV2(largeAmount, TRON_POWER)` — via `Program.freezeBalanceV2` [3](#0-2) 
   - `voteWitness([targetWitness], [largeVoteCount])` — via `Program.voteWitness` [9](#0-8) 
   - `withdrawReward()` — via `Program.withdrawReward`, which internally calls `VoteRewardUtil.withdrawReward` and computes reward using `computeReward(0, currentCycle, accountCapsule, repository)` with the just-cast `largeVoteCount` multiplied against `deltaVi` accumulated by `targetWitness` since genesis/cycle 0 [5](#0-4) 
   - `unfreezeBalanceV2(largeAmount, TRON_POWER)` to reclaim principal.
3. Compare `allowance`/balance gained to what a legitimate voter would earn for one cycle's worth of voting to confirm disproportionate reward extraction.

Note: full confirmation requires running this sequence against a test node (e.g., via `FreezeV2Test`/`VoteTest` harnesses already present in the repo) to verify whether `unfreezeDelayDays` blocks immediate principal recovery, and to measure the exact reward delta — recommend a Devin session to execute and validate this PoC end-to-end.

  public static void freezeAction(Program program) {
    // after allow vote, check static
    if (VMConfig.allowTvmVote() && program.isStaticCall()) {
      throw new Program.StaticCallModificationException();
    }
    // 0 as bandwidth, 1 as energy
    DataWord resourceType = program.stackPop();
    DataWord frozenBalance = program.stackPop();
    DataWord receiverAddress = program.stackPop();

    if (VMConfig.allowTvmFreezeV2()) {
      // after v2 activated, we just push zero to stack and do nothing
      program.stackPush(DataWord.ZERO());
    } else {
      boolean result = program.freeze(receiverAddress, frozenBalance, resourceType );
      program.stackPush(result ? DataWord.ONE() : DataWord.ZERO());
    }
    program.step();
  }

    if (VMConfig.allowTvmVote() && program.isStaticCall()) {
      throw new Program.StaticCallModificationException();
    }

    DataWord resourceType = program.stackPop();
    DataWord receiverAddress = program.stackPop();

    boolean result = program.unfreeze(receiverAddress, resourceType);
    program.stackPush(result ? DataWord.ONE() : DataWord.ZERO());
    program.step();
  }

  public boolean voteWitness(int witnessArrayOffset, int witnessArrayLength,
      int amountArrayOffset, int amountArrayLength) {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, null, 0, null,
        "voteWitness", nonce, null);

    if (memoryLoad(witnessArrayOffset).intValueSafe() != witnessArrayLength ||
        memoryLoad(amountArrayOffset).intValueSafe() != amountArrayLength) {
      logger.warn("TVM VoteWitness: memory array length do not match length parameter!");
      throw new BytecodeExecutionException(
          "TVM VoteWitness: memory array length do not match length parameter!");
    }

    if (witnessArrayLength != amountArrayLength) {
      logger.warn("TVM VoteWitness: witness array length {} does not match amount array length {}",
          witnessArrayLength, amountArrayLength);
      return false;
    }

    try {
      VoteWitnessParam param = new VoteWitnessParam();
      param.setVoterAddress(owner);
      byte[] witnessArrayData = memoryChunk(
          addExact(witnessArrayOffset, DataWord.WORD_SIZE,  VMConfig.disableJavaLangMath()),
          multiplyExact(witnessArrayLength, DataWord.WORD_SIZE,  VMConfig.disableJavaLangMath()));
      byte[] amountArrayData = memoryChunk(
          addExact(amountArrayOffset, DataWord.WORD_SIZE,  VMConfig.disableJavaLangMath()),
          multiplyExact(amountArrayLength, DataWord.WORD_SIZE,  VMConfig.disableJavaLangMath()));

      for (int i = 0; i < witnessArrayLength; i++) {
        DataWord witness = new DataWord(Arrays.copyOfRange(witnessArrayData,
            i * DataWord.WORD_SIZE, (i + 1) * DataWord.WORD_SIZE));
        DataWord amount = new DataWord(Arrays.copyOfRange(amountArrayData,
            i * DataWord.WORD_SIZE, (i + 1) * DataWord.WORD_SIZE));
        param.addVote(witness.toTronAddress(), amount.sValue().longValueExact());
      }
      if (internalTx != null) {
        internalTx.setExtra(param.toJsonStr());
      }

      VoteWitnessProcessor processor = new VoteWitnessProcessor();
      processor.validate(param, repository);
      processor.execute(param, repository);
      repository.commit();
      return true;
    } catch (ContractValidateException e) {
      logger.warn("TVM VoteWitness: validate failure. Reason: {}", e.getMessage());
    } catch (ContractExeException e) {
      logger.warn("TVM VoteWitness: execute failure. Reason: {}", e.getMessage());
    } catch (ArithmeticException e) {
      logger.warn("TVM VoteWitness: int or long out of range. caused by: {}", e.getMessage());
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return false;
  }

  public static void withdrawReward(byte[] address, Repository repository) {
    if (!VMConfig.allowTvmVote()) {
      return;
    }
    AccountCapsule accountCapsule = repository.getAccount(address);
    long beginCycle = repository.getBeginCycle(address);
    long endCycle = repository.getEndCycle(address);
    long currentCycle = repository.getDynamicPropertiesStore().getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = repository.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = repository.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account, repository);
        adjustAllowance(address, reward, repository);
        reward = 0;
      }
      beginCycle += 1;
    }
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      repository.updateBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule, repository);
      adjustAllowance(address, reward, repository);
    }
    repository.updateBeginCycle(address, endCycle);
    repository.updateEndCycle(address, endCycle + 1);
    repository.updateAccountVote(address, endCycle, accountCapsule);
  }

  private static long computeReward(long beginCycle, long endCycle,
                                    AccountCapsule accountCapsule, Repository repository) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    for (Protocol.Vote vote : accountCapsule.getVotesList()) {
      byte[] srAddress = vote.getVoteAddress().toByteArray();
      BigInteger beginVi = repository.getDelegationStore().getWitnessVi(beginCycle - 1, srAddress);
      BigInteger endVi = repository.getDelegationStore().getWitnessVi(endCycle - 1, srAddress);
      BigInteger deltaVi = endVi.subtract(beginVi);
      if (deltaVi.signum() <= 0) {
        continue;
      }
      long userVote = vote.getVoteCount();
      reward += deltaVi.multiply(BigInteger.valueOf(userVote))
          .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
    }
    return reward;
  }
