### Title
Unguarded subtraction in `calc-treasury-lp-preview` can underflow and permanently brick `accrue`, freezing all vault deposits/redeems/borrows/repays - (File: `mainnet/contracts/vault/v0-vault-stx.clar` and its per-asset counterparts)

### Summary
The `calc-treasury-lp-preview` helper computes the treasury's share of accrued interest by dividing `reserve-inc` by `(- ta-preview reserve-inc)`. Unlike every other subtraction of the same shape in the same file, this one is **not** clamped with a `(if (> a b) (- a b) u0)` guard. If `reserve-inc` (a fee computed from this block's raw index delta) ever exceeds `ta-preview` (total assets including only interest that is *strictly positive* after rounding), the subtraction underflows and the transaction aborts with a runtime arithmetic error. Because `accrue` is invoked with `(try! (accrue))` as the very first step of `deposit`, `redeem`, `system-borrow`, `system-repay`, and `flashloan`, a single underflowing call permanently blocks every user-facing entry point of the vault — an exact structural analog of the Dyad `UnboundedKerosineVault::assetPrice` bug, where an unguarded `tvl - dyad.totalSupply()` reverted and stranded Kerosene deposits.

### Finding Description [1](#0-0) 

`total-assets`/`total-assets-preview` compute accrued-but-uncollected interest with a safe clamp:
```
(interest (if (> debt borrowed) (- debt borrowed) u0))
```
but `calc-treasury-lp-preview` computes the treasury fee share with **no equivalent clamp**:
```
(define-private (calc-treasury-lp-preview)
  (let ((debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
        (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
        (ta-preview (total-assets-preview)))
    (if (> reserve-inc u0)
        (mul-div-down reserve-inc (total-supply) (- ta-preview reserve-inc))  ;; <-- unguarded
        u0)))
```
`debt-delta`/`reserve-inc` are derived from a **raw, single-step, `mul-div-down`** comparison of `old-debt`/`new-debt` (built directly from `principal-scaled` and `index`), while `ta-preview`'s `interest` term is derived from `debt-preview` (built with `calc-cumulative-debt`, which rounds **up** via `mul-div-up`) minus `total-borrowed`, clamped to zero. Because the two figures are computed with different rounding rules and against different reference points (`old-debt`/`new-debt` vs. `borrowed`), they are not guaranteed to move in lockstep: [2](#0-1) 
`system-repay` synchronizes `total-borrowed` using `total-debt()` (rounded **up**) while `calc-treasury-lp-preview`'s `old-debt` uses the same principal/index pair rounded **down**. At high utilization (`assets` at or near `u0`), this rounding mismatch lets `interest` (in `ta-preview`) settle at `u0` (because `borrowed >= debt` under the down-rounded comparison) while `debt-delta`/`reserve-inc` for the elapsed period remain strictly positive. In that state, `ta-preview == u0 + u0 == u0` (or a very small `current-assets`) while `reserve-inc > 0`, so `(- ta-preview reserve-inc)` underflows.

This mirrors the Dyad H-08 pattern precisely: a numerator/denominator subtraction that is safe "most of the time" but is not defensively clamped, so a value that legitimately can move below the subtrahend causes every dependent call to revert.

### Impact Explanation
`accrue` is the mandatory first step of every state-changing vault entry point: [3](#0-2) 
`deposit` and `redeem` both call `(try! (accrue))` before anything else, and the same pattern is used in `system-borrow`, `system-repay`, and `flashloan`. Once `calc-treasury-lp-preview` underflows for a given vault, `accrue` reverts unconditionally on every subsequent call (the underflow condition, driven by 100% utilization and rounding drift between `total-borrowed` and the raw index-delta, does not self-heal by simply calling the function again), which means:
- Users cannot `deposit` or `redeem` from that vault.
- The market cannot `borrow` or `repay` against that vault (since `system-borrow`/`system-repay` are blocked).
- Collateral routed through that vault's zToken becomes unusable for withdrawal via the market's `collateral-remove`/vault-redeem path.

This is a temporary freezing of user funds (deposits, zToken redemptions, and dependent collateral) at the vault level — the same impact class the Dyad report was rated for (temporary freezing of funds due to an unguarded subtraction reverting until an external condition changes).

### Likelihood Explanation
The trigger requires the vault to reach high utilization (assets pool near zero, i.e., most of the underlying repeatedly borrowed out) combined with the rounding-induced state where `total-borrowed >= debt` under the down-rounded formula while the down-rounded index step (`debt-delta`) is still positive for the elapsed period since `accrue` was last called. High utilization is a normal, protocol-expected operating condition (near-max borrowing is explicitly a target state for a lending market), and the rounding drift accumulates naturally from the repeated `mul-div-up` (in `system-repay`/`total-debt`) vs `mul-div-down` (in `calc-treasury-lp-preview`) mismatch on the same state variables. No privileged action or external oracle manipulation is needed — only normal borrow/repay/time-elapsed activity in a single subsequent `accrue`-triggering call.

### Recommendation
Apply the same defensive clamp used elsewhere in the file to the treasury-fee denominator:
```clarity
(define-private (calc-treasury-lp-preview)
  (let ((debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
        (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
        (ta-preview (total-assets-preview))
        (safe-reserve-inc (if (> reserve-inc ta-preview) ta-preview reserve-inc)))
    (if (> safe-reserve-inc u0)
        (mul-div-down safe-reserve-inc (total-supply) (- ta-preview safe-reserve-inc))
        u0)))
```
Additionally, reconcile the rounding convention: use the same `mul-div-up`/`calc-cumulative-debt` formula for `old-debt`/`new-debt` inside `calc-treasury-lp-preview` as is used to synchronize `total-borrowed` in `system-repay`/`total-debt`, to eliminate the structural drift between the two quantities rather than only patching the symptom.

### Proof of Concept
Conceptual sequence (per affected vault, e.g. `v0-vault-stx.clar`):
1. Borrow underlying up to (or very near) 100% utilization via `system-borrow`, driving `assets` (the vault's idle cash) to `u0` while `total-borrowed` and `principal-scaled` track the outstanding loan.
2. Perform a partial `system-repay`. `total-borrowed` is updated using `total-debt()` (`mul-div-up`-rounded), so `total-borrowed` ends up rounded to be `>=` the `mul-div-down`-rounded `old-debt` that `calc-treasury-lp-preview` will independently recompute from the same `principal-scaled`/`index` pair.
3. Let a block/time elapse without calling `accrue` (any subsequent call to `deposit`, `redeem`, `system-borrow`, `system-repay`, or `flashloan` triggers it). `next-index` advances, so `new-debt > old-debt` and `debt-delta > 0`, giving `reserve-inc > 0` inside `calc-treasury-lp-preview`.
4. Because `borrowed >= debt` under the down-rounded comparison, `total-assets-preview`'s `interest` clamps to `u0`, so `ta-preview == current-assets` (near `u0` at high utilization).
5. Any user calls `deposit` or `redeem` (or the market calls `borrow`/`repay`) on this vault. The nested `(try! (accrue))` evaluates `calc-treasury-lp-preview`, which computes `(- ta-preview reserve-inc)` with `reserve-inc > ta-preview`, causing an arithmetic underflow and aborting the transaction.
6. Every subsequent call to any of `deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan` on this vault reverts identically, since they all execute `(try! (accrue))` first — the vault, and any collateral routed through its zToken, is stuck until the DAO/executor intervenes (e.g., via a manual state-correcting call), analogous to Kerosene being stuck until TVL exceeded Dyad's supply in the original finding.
