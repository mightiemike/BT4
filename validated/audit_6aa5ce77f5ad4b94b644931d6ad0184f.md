Based on my research, the relevant class of vulnerability does have a concrete analog in this codebase, in the protocol's own on-chain swap logic (not a user-supplied slippage parameter, but a spot-quote-based slippage that is fetched and consumed atomically in the same block as fully mempool-visible trigger transactions).

### Title
Gas-abstraction and gas-refund swaps use a same-block spot quote with fixed 5% slippage, allowing unprivileged sandwich extraction from user funds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The original report (`H-6`) concerns a caller-controlled `amountOutMinimum` that lets an attacker sandwich a Uniswap swap executed on behalf of a victim `account`. Push Chain does not expose a user-settable slippage parameter, but it has a structurally similar pattern: `ExecuteInboundGas` and `applyGasRefund` fetch a live Uniswap-style quote via `GetSwapQuote` and immediately execute the swap in the same keeper call, protected only by a fixed `minPCOut = quote * 95 / 100`.

### Finding Description
In `ExecuteInboundGas` [1](#0-0) , the quote used to bound the swap is fetched from `GetSwapQuote` and consumed to compute `minPCOut` right before calling `CallPRC20DepositAutoSwap`, all inside the same block/transaction that processes the finalizing `MsgVoteInbound`. The same pattern exists for gas refunds in `applyGasRefund` [2](#0-1) , triggered by the finalizing `MsgVoteOutbound`.

Both the finalizing `MsgVoteInbound`/`MsgVoteOutbound` transactions are gasless, whitelisted messages [3](#0-2)  submitted by Universal Validators and are visible in the mempool prior to block inclusion (this is honest-validator behavior, not a malicious-UV assumption — the vote content itself is legitimate). Because Push Chain does not implement a mempool that hides pending transactions, an unprivileged attacker can observe a pending finalizing vote, infer that a PRC20→PC (or gas-token→PC) swap with a fixed 5% band is about to execute against the on-chain quoter/AMM pool, and sandwich it: manipulate the pool price up to the edge of the 5% band immediately before the vote lands, let the module's swap execute at the manipulated spot price, then reverse the price afterward. The `95/100` slippage bound is a static percentage of a manipulable spot price rather than being anchored to a TWAP or an oracle, so it does not meaningfully limit extraction on thin pools.

### Impact Explanation
Every gas-abstraction inbound (`TxType` gas-swap) and every outbound gas refund with swap enabled routes user or protocol-controlled PRC20/native value through this pattern. An attacker can systematically extract up to the 5% slippage allowance from ordinary users' cross-chain gas conversions on every occurrence, which is a repeatable, unprivileged value-extraction path against protocol-controlled swap accounting (`PcTx`/`PcRefundExecution` records reflect a worse-than-fair execution price). This falls within the allowed impact of "corruption of ... gas fee accounting, refund accounting ... reachable from ordinary user deposits ... alone."

### Likelihood Explanation
High/likely on any chain with public mempool visibility and non-trivial DEX pool for the gas token / WPC pair: the trigger conditions (an honest UV's finalizing vote) occur automatically and routinely for every inbound/outbound with a gas leg, and the swap parameters (quote, `fee`, `amount`) are all derivable off-chain by watching `GetTokenConfig`/`ChainConfigs` state and the pending vote in mempool.

### Recommendation
Do not derive the slippage bound from a spot quote fetched in the same atomic call as the swap execution. Use a TWAP-based or otherwise manipulation-resistant reference price (or a governance/oracle-set price band) to compute `minPCOut`, and/or execute these swaps through a private/protected submission path that is not observable pre-confirmation, and/or tighten the slippage tolerance and add circuit breakers keyed to pool liquidity depth for the specific gas-token pairs.

### Proof of Concept
1. Attacker monitors the mempool for a `MsgVoteInbound` (or `MsgVoteOutbound`) that will cross the ballot threshold for a `TxType_GAS`/`GAS_AND_PAYLOAD` inbound (or an outbound with a gas refund).
2. Before that transaction lands, attacker submits a swap on the underlying Uniswap-V3-style pool (identified via `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`/`GetDefaultFeeTierForToken`) to push the spot price against the direction of the upcoming protocol swap, up to just inside the 5% band (`minPCOut = quote*95/100` in [4](#0-3) ).
3. The finalizing vote transaction executes, triggering `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` with `minPCOut` computed off the now-manipulated quote, so the swap still succeeds but at the worse price.
4. Attacker submits a reversing trade to restore the pool price and realizes profit equal to the price impact they caused, up to the 5% band, at the expense of the user's converted gas value. [5](#0-4) [6](#0-5)

func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
