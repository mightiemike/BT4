### Title
Signature-acceptance path skips the local `block_info.valid` check enforced on the pre-commit path - ([File: stacks-signer/src/v0/signer.rs])

### Summary
`Signer::handle_block_pre_commit` explicitly requires `block_info.valid.unwrap_or(false)` to be true before it will tally a peer's pre-commit toward the 70% threshold or act on it [1](#0-0) . `Signer::store_and_process_block_signature`, which is invoked from `handle_block_signature` when this signer receives a `BlockAccepted` signature from a peer that has already been recorded as "committed," performs no equivalent check on `block_info.valid` before counting the signer's weight, computing `total_signature_weight`, and — once `min_weight` is reached — calling `mark_locally_accepted` and `broadcast_signed_block` [2](#0-1) .

### Finding Description
The two-phase-commit signer flow is supposed to gate every weight-accumulating action on the local validity verdict for the block (`block_info.valid`), mirroring the DNSSEC-result pattern in the external report: a validity/authenticity signal is computed, but only some downstream consumers check it before acting on the associated data.

- In `handle_block_pre_commit`, the guard is explicit: `if !block_info.valid.unwrap_or(false) { ... return; }` before any pre-commit weight is used to gate a signature [1](#0-0) .
- In `store_and_process_block_signature`, a signature from a peer is only routed back into `handle_block_pre_commit` (and thus subjected to the `valid` check) when `has_committed(...)` is false for that signer [3](#0-2) . If the signer has already been recorded as having committed (`has_committed` true), the incoming `BlockAccepted` signature is stored and its weight is added to `total_signature_weight` unconditionally — with no re-check of the current `block_info.valid` state — before the threshold comparison and eventual `broadcast_signed_block` call [4](#0-3) .
- Meanwhile, `block_info.valid` is explicitly documented as mutable/resettable: a fresh proposal for the same block hash can reset `valid` to `None` ("If we received a new proposal for it that we wished to consider, we would have reset valid to None") [5](#0-4) , and `check_block_against_signer_db_state` can flip a previously-valid block to rejected as chain state changes [6](#0-5) .

Because `store_and_process_block_signature` never re-reads `block_info.valid` for the "already committed" branch, a block whose local validity verdict has since become `None`/`false` can still have its accumulated signature weight cross the 70% threshold and be locally-accepted and rebroadcast to the attached stacks-node — purely because earlier signatures were received while `valid` was still `true`/unset-but-accepted. This is a validation-verdict divergence: the same signer instance enforces the "valid" gate on one code path (pre-commit) but not on the structurally equivalent code path (signature tally) that produces the actual broadcast action.

### Impact Explanation
This falls into the allowed "validation verdict two nodes disagree on" / signer-weight-from-the-wrong-state category. If a signer's local state re-evaluates a previously-accepted block as invalid or unknown (via a re-proposal reset or a state re-check) while other signers' earlier signatures are still on file, the local signer can broadcast a block to its stacks-node that it no longer believes is valid, without the guard that the pre-commit path enforces. The direct effect is limited to this signer's own post to its own node (`handle_post_block`), and the node performs independent signature verification against the reward set via `verify_signer_signatures`, so acceptance still ultimately depends on real weight/signature validity at the node level, bounding the blast radius. Still, this produces a genuine internal-state/enforcement inconsistency that is minority-triggerable at the signer layer (a signer's own local view diverging from the pre-commit-gated view) and is unambiguously not covered by the "already checked" pre-commit code path.

### Likelihood Explanation
Triggering requires a specific race: a signer already recorded as "committed" for a block, followed by a local re-validation event (new proposal for the same hash, or a state re-check) that would have flipped/cleared `block_info.valid`, followed by a signature (rather than pre-commit) message arriving for that same block. The signer test suite already demonstrates the project is aware of and actively tests exactly this kind of race for the pre-commit path (`signer_waits_for_validation_before_signing`) [7](#0-6) , but no analogous test exists guarding `store_and_process_block_signature`/`handle_block_signature` against acting on a stale/invalidated `block_info.valid`. This suggests the asymmetry is a real gap rather than an intentionally-covered case.

### Recommendation
Add the same `block_info.valid.unwrap_or(false)` (or equivalent freshness) check inside `store_and_process_block_signature` before counting a peer's signature weight toward the threshold and before calling `mark_locally_accepted`/`broadcast_signed_block`, so that both the pre-commit and signature-tally code paths enforce identical validity gating.

### Proof of Concept
Not independently reproducible from static analysis alone — this requires exercising the exact race between a `block_info.valid` reset (new proposal / re-check) and receipt of a `BlockAccepted` message from an already-"committed" peer for the same `block_hash`, which needs the running signer test harness (`stacks-signer/src/v0/tests.rs`) to construct precisely. I was not able to fully confirm from the index alone whether some other guard elsewhere in the event-processing loop (outside the two functions cited) additionally screens this state before the signature event reaches `handle_block_signature`; a Devin session with full test-harness access would be needed to build and run a concrete repro.

    /// Store the block acceptance signature and check if we have reached a consensus decision on the block because of it. If we have, update the block state accordingly and broadcast the block if accepted.
    fn store_and_process_block_signature(
        &mut self,
        stacks_client: &StacksClient,
        sortition_state: &mut Option<SortitionsView>,
        block_info: &mut BlockInfo,
        signer_address: &StacksAddress,
        signature: &MessageSignature,
    ) {
        let block_hash = &block_info.signer_signature_hash();
        // signature is valid! store it.
        // if this returns false, it means the signature already exists in the DB, so just return.
        if !self
            .signer_db
            .add_block_signature(block_hash, signer_address, signature)
            .unwrap_or_else(|_| panic!("{self}: Failed to save block signature"))
        {
            return;
        }

        // If this isn't our own signature and we haven't seen a pre-commit from this signer yet, try treating it as a pre-commit in case the caller is running an outdated version
        if signer_address != &self.stacks_address && !self.signer_db.has_committed(block_hash, signer_address).inspect_err(|e| warn!("Failed to check if pre-commit message already considered for {signer_address:?} for {block_hash}: {e}")).unwrap_or(false) {
            self.handle_block_pre_commit(stacks_client, sortition_state, signer_address, block_hash);
            return;
        }

        if block_info.signed_group.is_some() {
            // We have already processed this block to the accepted state. Adding more signatures will not change anything so nothing to check.
            return;
        }
        // do we have enough signatures to broadcast?
        // i.e. is the threshold reached?
        let signatures = self
            .signer_db
            .get_block_signatures(block_hash)
            .unwrap_or_else(|_| panic!("{self}: Failed to load block signatures"));

        // put signatures in order by signer address (i.e. reward cycle order)
        let addrs_to_sigs: HashMap<_, _> = signatures
            .into_iter()
            .filter_map(|sig| {
                let Ok(public_key) = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                    block_hash.bits(),
                    &sig,
                ) else {
                    return None;
                };
                let addr = StacksAddress::p2pkh(self.mainnet, &public_key);
                Some((addr, sig))
            })
            .collect();

        let signature_weight = self.signer_weights.get(signer_address).unwrap_or(&0);
        let total_signature_weight = self.compute_signature_signing_weight(addrs_to_sigs.keys());
        let total_weight = self.compute_signature_total_weight();

        let min_weight = NakamotoBlockHeader::compute_voting_weight_threshold(total_weight)
            .unwrap_or_else(|_| {
                panic!("{self}: Failed to compute threshold weight for {total_weight}")
            });

        if min_weight > total_signature_weight {
            info!("{self}: Received block acceptance, but have not yet reached the acceptance threshold.";
                "signer_signature_hash" => %block_hash,
                "signature_weight" => signature_weight,
                "consensus_hash" => %block_info.block.header.consensus_hash,
                "block_height" => block_info.block.header.chain_length,
                "total_weight_approved" => total_signature_weight,
                "total_weight" => total_weight,
                "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
            );
            return;
        }
        info!("{self}: have reached the block acceptance threshold";
            "signer_signature_hash" => %block_hash,
            "signature_weight" => signature_weight,
            "consensus_hash" => %block_info.block.header.consensus_hash,
            "block_height" => block_info.block.header.chain_length,
            "total_weight_approved" => total_signature_weight,
            "total_weight" => total_weight,
            "percent_approved" => (total_signature_weight as f64 / total_weight as f64 * 100.0),
        );

        // have enough signatures to broadcast!
        // move block to LOCALLY accepted state.
        // It is only considered globally accepted IFF we receive a new block event confirming it OR see the chain tip of the node advance to it.
        if let Err(e) = block_info.mark_locally_accepted(true) {
            if !block_info.has_reached_consensus() {
                warn!("{self}: Failed to mark block as locally accepted: {e:?}");
            }
        }
        let _ = self.signer_db.insert_block(block_info).map_err(|e| {
            warn!("Failed to set group threshold signature timestamp for {block_hash}: {e:?}");
            panic!("{self} Failed to write block to signerdb: {e}");
        });
        self.broadcast_signed_block(stacks_client, block_info.block.clone(), &addrs_to_sigs);
    }
