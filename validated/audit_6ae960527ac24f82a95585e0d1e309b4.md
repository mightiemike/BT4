### Title
Global-contract "AccountId" identifier can be reclaimed after owner account deletion, allowing an unrelated party to hijack the code that all `GlobalByAccount`-referencing accounts run - ([File: runtime/runtime/src/global_contracts.rs])

### Summary
`DeployGlobalContractAction` in `GlobalContractDeployMode::AccountId` mode publishes contract code under a `GlobalContractIdentifier::AccountId(deployer_account_id)` key, and any account can later opt in via `UseGlobalContractAction`, storing `AccountContract::GlobalByAccount(deployer_account_id)` on itself. This is deliberately mutable "by design" so the *original* owner can push updates to every consuming account. The problem is that the identifier is bound only to an `AccountId` string, not to any persistent ownership/identity token, and the underlying code storage (`TrieKey::GlobalContractCode`) is a wholly separate trie entry from the owner `Account` object. If the owner account is deleted (`DeleteAccountAction`) and the account id later becomes claimable by a different, unrelated party (e.g., a long top-level account id, which anyone may create per `action_create_account`'s length-based registrar bypass), that new claimant can call `DeployGlobalContractAction` again with the same `AccountId` mode and silently overwrite the code that every existing `GlobalByAccount` consumer resolves to on their next `FunctionCall`.

### Finding Description
- `action_deploy_global_contract` / `initiate_distribution` derive the storage key purely from the calling `account_id` when `deploy_mode == AccountId`: `GlobalContractIdentifier::AccountId(account_id.clone())` [1](#0-0) . The resulting code is written to `TrieKey::GlobalContractCode { identifier }` [2](#0-1)  — a trie location keyed only by the identifier value, independent of the `Account` record for that id.
- Consumers opt in via `use_global_contract`, which just checks that a `GlobalContractCode` entry exists for the identifier and stores `AccountContract::GlobalByAccount(id)` on themselves [3](#0-2) . Nothing ties this reference to the *current* controller of that `AccountId`; it is purely dynamic — every future `FunctionCall` re-resolves the code via `RuntimeContractIdentifier::resolve` → `GlobalContractIdentifier::hash`/`code`, which looks up whatever is currently stored under that identifier at call time [4](#0-3) [5](#0-4) . This is confirmed by the test `test_global_contract_update`, which shows that redeploying under `AccountId` mode changes behavior for accounts that already ran `UseGlobalContract` for that id, with no re-consent required [6](#0-5) .
- `action_delete_account` has no check preventing deletion of an account that owns (has deployed) a `GlobalContractDeployMode::AccountId` global contract still referenced by other accounts. It only bounds by storage size and gas-key balance, then unconditionally removes the account (`*account = None`) [7](#0-6) . The `GlobalContractCode`/`GlobalContractNonce` trie entries for that identifier are untouched by account deletion because they live at a separate `TrieKey`, not under the account's own storage.
- Account-id reclamation: `action_create_account` permits creation of a top-level account id whenever its length is `>= min_allowed_top_level_account_length`, with **no registrar or prior-owner restriction** — the registrar check only applies to short (`< min_allowed_top_level_account_length`) top-level ids [8](#0-7) . Thus a long top-level account id, once freed by `DeleteAccount`, can be re-created by literally anyone.

Putting these together: an attacker (or even an honest owner who deletes their account thinking it is inert) frees the `AccountId` identifier; any third party recreates that exact account id and issues a fresh `DeployGlobalContractAction` in `AccountId` mode. Every account that had earlier executed `UseGlobalContractAction` referencing the old owner's id (and never opted out) will transparently start executing the new claimant's arbitrary WASM the next time a `FunctionCall` receipt targets them — with the *consuming* account's own balance/storage/access-key context. This is the direct nearcore analog to the Biconomy `SmartAccount` implementation-contract-destruction bug: a shared "implementation" (here, code identified by `AccountId`) can be orphaned and then hijacked by an unrelated party, silently repointing every dependent "proxy" account (`GlobalByAccount` consumer) at attacker-controlled logic.

### Impact Explanation
Any account that adopted a `GlobalByAccount` contract keyed by an account id that is later deleted and reclaimed will unknowingly execute attacker-supplied WASM on its next call. Because the contract runs with the consuming account's own balance and storage context (standard NEAR contract execution model), the attacker's injected code can transfer away the consuming account's NEAR balance, corrupt its contract storage, or otherwise act with full contract-level authority over it — i.e., concrete unauthorized value movement / invalid state transition, mirroring the "complete freezing/hijacking of all dependent wallets" impact in the source report. Any number of downstream accounts across all shards (global contracts propagate network-wide) can be affected simultaneously, since they all resolve the same shared identifier.

### Likelihood Explanation
Reachable purely through ordinary, unprivileged transactions: `DeployGlobalContractAction` (AccountId mode) and `UseGlobalContractAction` are both regular actions any signer can submit, `DeleteAccountAction` is self-service, and creating a long top-level account id requires no special permission (`action_create_account`'s registrar gate is bypassed once the id is long enough). No validator, network, or operator privilege is required — only ordinary transaction crafting by a signer/deployer, matching the required threat model (unprivileged transaction signer / contract deployer).

### Recommendation
- Bind the `AccountId`-mode global-contract identifier's lifecycle to the owning account: either forbid `DeleteAccountAction` for an account that has an active `GlobalContractCode` entry under its id while any account still references it, or better, make `GlobalContractIdentifier::AccountId` resolution invalidate/orphan (rather than silently keep serving) code once the owning account no longer exists.
- Alternatively, make the identifier immutable-safe by binding it to something that cannot be reclaimed by an unrelated party after deletion (e.g., include a monotonically-increasing "generation"/creation nonce of the account in the identifier, or disallow recreation of a top-level account id that ever owned a global contract).
- At minimum, document/require that consumers periodically re-validate (or automatically drop) `GlobalByAccount` references once the owning account is deleted, and add an explicit protocol check that rejects `DeployGlobalContractAction(AccountId)` from an account id that is "freshly created" if a `GlobalContractCode`/`GlobalContractNonce` entry already exists for that identifier from a *different* underlying account lineage.

### Proof of Concept
1. Attacker/owner `X` (a long top-level account id, creatable by anyone) issues `DeployGlobalContractAction { code: benign_code, deploy_mode: AccountId }`, populating `GlobalContractCode{ AccountId(X) }` [9](#0-8) .
2. Victim accounts `V1..Vn` each issue `UseGlobalContractAction { contract_identifier: AccountId(X) }`, setting their `AccountContract` to `GlobalByAccount(X)` [3](#0-2) .
3. `X` issues `DeleteAccountAction` on itself; `action_delete_account` deletes the `Account` record for `X` but leaves the `GlobalContractCode{ AccountId(X) }` trie entry intact [7](#0-6) .
4. Any other actor `Y` issues `CreateAccountAction` for the same top-level id `X` — allowed unconditionally for sufficiently long top-level ids [8](#0-7)  — then issues `DeployGlobalContractAction { code: malicious_code, deploy_mode: AccountId }` from account `X`, overwriting `GlobalContractCode{ AccountId(X) }` (the nonce mechanism only prevents stale/duplicate distributions, not a legitimate new deployer, per `test_global_contract_update` behavior) [6](#0-5) .
5. Any subsequent `FunctionCall` receipt to `V1..Vn` resolves via `RuntimeContractIdentifier::resolve`/`GlobalContractAccessExt::code` to the new malicious code and executes it under each victim's own balance/storage context [10](#0-9) , with no further action or consent from `V1..Vn`.

pub(crate) fn action_deploy_global_contract(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    apply_state: &ApplyState,
    deploy_contract: &DeployGlobalContractAction,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let _span = tracing::debug_span!(target: "runtime", "action_deploy_global_contract").entered();

    let storage_cost = apply_state
        .config
        .fees
        .storage_usage_config
        .global_contract_storage_amount_per_byte
        .saturating_mul(deploy_contract.code.len() as u128);
    let Some(updated_balance) = account.amount().checked_sub(storage_cost) else {
        result.result = Err(ActionErrorKind::LackBalanceForState {
            account_id: account_id.clone(),
            amount: storage_cost,
        }
        .into());
        return Ok(());
    };
    result.tokens_burnt =
        result.tokens_burnt.checked_add(storage_cost).ok_or(IntegerOverflowError)?;
    account.set_amount(updated_balance);

    initiate_distribution(
        state_update,
        account_id.clone(),
        deploy_contract.code.clone(),
        &deploy_contract.deploy_mode,
        apply_state.shard_id,
        result,
    )?;

    Ok(())
}

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };
    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract).or_inconsistent_state(account_id)?;
    Ok(())

impl RuntimeContractIdentifier {
    /// Resolve a contract identifier from an account's contract field.
    ///
    /// Returns `RuntimeContractIdentifier::None` if the account has no contract deployed.
    pub(crate) fn resolve(
        account_id: &AccountId,
        account_contract: AccountContract,
        state_update: &TrieUpdate,
        chain_id: &str,
        access: AccessOptions,
    ) -> Result<Self, StorageError> {
        let local_hash = match GlobalContractIdentifier::try_from(account_contract) {
            Ok(gci) => {
                let code_hash = gci.clone().hash(state_update, access)?;
                return Ok(RuntimeContractIdentifier::Global { code_hash, identifier: gci });
            }
            Err(ContractIsLocalError::NotDeployed) => return Ok(RuntimeContractIdentifier::None),
            Err(ContractIsLocalError::Deployed(local_hash)) => local_hash,
        };

        if account_id.get_account_type() == AccountType::EthImplicitAccount {
            // Accounts that look like eth implicit accounts and have existed prior to the
            // eth-implicit accounts protocol change (these accounts are discussed in the
            // description of #11606) may have something else deployed to them. Only return
            // something here if the accounts have a wallet contract hash. Otherwise use the
            // regular path to grab the deployed contract.
            if LegacyEthWallet::resolve(local_hash).is_some() {
                // ETH implicit wallet accounts use global contracts, including
                // those created in old protocol versions.
                let global_hash = eth_wallet_global_contract_hash(chain_id);
                return Ok(RuntimeContractIdentifier::Global {
                    code_hash: global_hash,
                    identifier: GlobalContractIdentifier::CodeHash(global_hash),
                });
            }
        }

        Ok(RuntimeContractIdentifier::AccountLocal {
            code_hash: local_hash,
            account_id: account_id.clone(),
        })
    }

fn test_global_contract_update() {
    let mut env = GlobalContractsTestEnv::setup(Balance::from_near(1000));
    let use_accounts = [env.account_shard_0.clone(), env.account_shard_1.clone()];

    env.deploy_trivial_global_contract(GlobalContractDeployMode::AccountId);

    for account in &use_accounts {
        env.use_global_contract(
            account,
            GlobalContractIdentifier::AccountId(env.deploy_account.clone()),
        );

        // Currently deployed trivial contract doesn't have any methods,
        // so we expect any function call to fail with MethodNotFound error
        let call_tx = env.call_global_contract_tx(account.clone(), account.clone());
        let call_outcome = env.execute_tx(call_tx);
        assert_matches!(
            call_outcome.status,
            FinalExecutionStatus::Failure(TxExecutionError::ActionError(ActionError {
                kind: ActionErrorKind::FunctionCallError(FunctionCallError::MethodResolveError(
                    MethodResolveError::MethodNotFound
                )),
                index: _
            }))
        );
    }

    env.deploy_global_contract(GlobalContractDeployMode::AccountId);

    for account in &use_accounts {
        // Function call should be successful after deploying rs contract
        // containing the function we call here
        env.assert_call_global_contract_success(account.clone(), account.clone());
    }
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}
