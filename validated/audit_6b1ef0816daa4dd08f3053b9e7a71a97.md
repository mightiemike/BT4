### Title
Unprotected instantaneous-spot-price swap quote enables value extraction on PRC20→WPC auto-swap deposits - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The reported bug class is: a price/rate formula is computed from a manipulable instantaneous value and then fed into fee/slippage-protection logic without accounting for the fact that the underlying rate itself can be moved by an attacker before use. Push Chain's PRC20-to-WPC auto-swap deposit path has the same structural flaw: `minPCOut` (the user/protocol's slippage floor) is derived from a single live AMM quote (`GetSwapQuote` → `quoteExactInputSingle`) taken at execution time, with only a fixed 5% tolerance and no TWAP or oracle cross-check.

### Finding Description
When a GAS or GAS_AND_PAYLOAD inbound is executed, the keeper:
1. Fetches the fee tier via `GetDefaultFeeTierForToken` [2](#0-1) .
2. Fetches an instantaneous quote via `GetSwapQuote`, which calls the Uniswap V3 `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96 = 0` (no price bound) [1](#0-0) .
3. Computes `minPCOut = quote * 95 / 100` — a flat 5% slippage tolerance based on whatever the pool's spot price happens to be at that instant [3](#0-2)  and [4](#0-3) .
4. Executes `depositPRC20WithAutoSwap` on-chain with that `minPCOut` as the only downstream protection, and `deadline = 0` (contract default) [5](#0-4) .

Because the quote and the swap execution both reference the *current* pool reserves rather than a time-weighted or otherwise attacker-resistant reference price, an unprivileged actor who can trade against the same PRC20/WPC pool (a standard Uniswap V3 pool deployed by the protocol, per `e2e-tests/setup.sh` pool-creation flow) can move the spot price immediately before their own — or another user's — inbound is executed by Universal Validators. Since `minPCOut` is computed from that same manipulated price with only a 5% band, the auto-swap can be forced to execute at an attacker-favorable rate, extracting value from the pool (and thus from the protocol/other depositors) via a classic sandwich pattern. The identical spot-price-derived quote is reused for gas refunds via `getSwapQuoteForRefund` → `applyGasRefund` [6](#0-5) , so the same manipulation vector applies to outbound gas-refund swaps as well.

### Impact Explanation
This falls under "corruption of PRC20 or native asset accounting" and "unauthorized ... release ... of user or protocol-controlled funds" in the allowed impact gate: an unprivileged attacker manipulating the pool price around inbound-deposit or outbound-refund execution can cause the protocol-controlled Uniswap pool (or the `to`/refund recipient) to receive fewer PC/WPC tokens than the true fair-value quote, draining value on every auto-swap that executes during the manipulated window. This does not require any malicious validator or privileged actor — only ordinary swap transactions against the public pool timed around inbound processing.

### Likelihood Explanation
Likelihood depends on (a) the PRC20/WPC pools having limited liquidity (plausible for newer/low-cap PRC20 assets) relative to the deposit size, and (b) an attacker being able to predict or influence transaction ordering around when Universal Validators execute a given inbound (e.g., attacking their own large inbound deposit, since they control its timing and the trigger conditions). Both conditions are realistic in a live deployment with shallow pools, making this a practically exploitable, medium-to-high likelihood issue rather than a purely theoretical one.

### Recommendation
Do not rely solely on an instantaneous `quoteExactInputSingle` call for slippage protection. Options: (1) use a TWAP-based reference price (e.g., Uniswap V3 `observe`) as the basis for `minPCOut` instead of the spot quote, (2) set `SqrtPriceLimitX96` to a bounded value derived from a trusted external reference rather than `0`, or (3) cap the deposit amount relative to pool depth / require minimum liquidity before allowing auto-swap, combined with a real deadline instead of `deadline = 0`.

### Proof of Concept
1. Deployer creates a PRC20/WPC pool with modest liquidity (as done in `e2e-tests/setup.sh` `create-pool` step).
2. Attacker submits a large swap directly against the pool (any EVM caller can interact with a standard Uniswap V3 pool) to move the spot price unfavorably for the upcoming deposit.
3. Attacker (or a colluding party) triggers/awaits a GAS or GAS_AND_PAYLOAD inbound whose `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` path calls `GetSwapQuote` while the price is still skewed [7](#0-6) .
4. `minPCOut` is computed from the skewed quote with only 5% tolerance, so `depositPRC20WithAutoSwap` executes at the manipulated rate instead of reverting.
5. Attacker reverses their initial swap, capturing the price difference at the expense of the pool/protocol.

Note: I could not find a TWAP or on-chain oracle cross-check anywhere in the codebase's swap-quote path, and the index does not include the actual Solidity source for `UniversalCore`/`QuoterV2`/the pool contracts (they live in a separate `push-chain-core-contracts`-style repo referenced only via ABI here) — a full assessment of contract-level slippage/deadline enforcement would require reviewing that repository directly, which is outside what I can access here.

func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,

	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)

	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
