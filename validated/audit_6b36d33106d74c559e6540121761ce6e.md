### Title
Recursion-depth limit is silently reset to the default on every message/group field decoded via `unmarshalOptions.Options()` + `UnmarshalState`, permitting unbounded recursive-descent stack growth - ([File: internal/impl/decode.go])

### Summary
`internal/impl/decode.go`'s `unmarshalOptions.Options()` converts the internal `unmarshalOptions` (which carries a live, already-decremented `depth` counter) into a `proto.UnmarshalOptions` value, but it never copies the `depth` field into `RecursionLimit`. Every codec path that unmarshals a nested message/group by going back through the high-level `proto.UnmarshalOptions.UnmarshalState` API (e.g. `consumeMessageSliceValue`, `consumeGroupSliceValue`, `consumeGroupSlice` in `internal/impl/codec_field.go`) therefore hands off with `RecursionLimit == 0`. `proto.UnmarshalOptions.UnmarshalState` treats `RecursionLimit == 0` as "unset" and resets it to `protowire.DefaultRecursionLimit` [1](#0-0) . As a result, the caller's accumulated recursion depth is discarded and refilled to the full default limit at every such boundary, defeating the purpose of the recursion-depth check and allowing the real Go call stack to grow without any effective bound for a suitably deep chain of repeated message/group fields.

### Finding Description
`internal/impl/decode.go` defines the depth-tracking type used by the fast/reflection-based unmarshal path: [2](#0-1) 

Note that `Options()` copies `Merge`, `AllowPartial`, `DiscardUnknown`, `Resolver`, `NoLazyDecoding` — but not `depth`/`RecursionLimit`.

Multiple codec functions for message-typed and group-typed fields rely on this conversion to recurse into a nested message via the public `proto.UnmarshalOptions.UnmarshalState`: [3](#0-2) [4](#0-3) [5](#0-4) 

`proto.UnmarshalOptions.UnmarshalState` is the sole boundary where `RecursionLimit` gets applied to a new `Depth`: [6](#0-5) 

Because `Options()` never sets `RecursionLimit`, it is always `0` on entry to `UnmarshalState`, which unconditionally treats that as "not configured" and substitutes `protowire.DefaultRecursionLimit`. The net effect: every time the fast-path decoder hands a nested message/group off to `UnmarshalState` (which happens for every element of a repeated message field, every group field, and every group-list element), the "remaining depth" the caller had already spent tracking is thrown away and a fresh full budget is granted. The depth decrement that *does* happen correctly inside `mi.unmarshalPointer` (`internal/impl/decode.go:103-107`) [7](#0-6)  only bounds recursion *within* a single `UnmarshalState` call tree, not across these repeated resets. A crafted message that nests, e.g., a repeated message field or a proto2 group field inside itself far beyond `protowire.DefaultRecursionLimit` levels will cause the Go call stack (`mi.unmarshalPointer` → codec `unmarshal` func → `UnmarshalState` → `mi.unmarshal` → `mi.unmarshalPointer` → …) to grow proportionally to the total nesting depth in the wire data, not to any bounded constant, because the "budget" resets at each such boundary instead of being carried through cumulatively.

This is the direct analog of the reported libmysofa bug class: an "does not properly restrict recursive function calls" defect where a depth/recursion counter exists but fails to be enforced across a call boundary, leading to stack consumption proportional to attacker-controlled input structure.

### Impact Explanation
An attacker who can supply arbitrary serialized protobuf bytes to any endpoint that calls `proto.Unmarshal`/`(UnmarshalOptions).Unmarshal` on a message containing a repeated message field or a proto2 group field (directly or transitively, self-referential nesting) can trigger unbounded native-stack recursion during decode, crashing the process (goroutine stack overflow is fatal and unrecoverable in Go) — a denial-of-service against the parsing service on an ordinary, unprivileged request path using the default binary unmarshaler.

### Likelihood Explanation
Reachable with a fully trusted schema and the default `proto.Unmarshal` binary decode path — no custom resolver, no malicious peer beyond supplying bytes, and no privileged caller is required. Any message type containing a repeated/self-referential message field (extremely common) or a group field is exploitable. The bug is in the generic dispatch code path used for essentially every non-trivial message, making it broadly reachable.

### Recommendation
Propagate the caller's remaining recursion budget through `unmarshalOptions.Options()` by setting `RecursionLimit: o.depth` on the returned `proto.UnmarshalOptions`, and/or change `proto.UnmarshalOptions.UnmarshalState` to only apply the `DefaultRecursionLimit` fallback when the caller is a top-level, non-nested invocation (e.g., distinguish "unset" from "zero remaining budget," perhaps via a sentinel or a `Depth` field that is always explicitly threaded rather than relying on zero-value semantics of `RecursionLimit`).

### Proof of Concept
Given a proto2 message type with a self-referential group field (or, equivalently, a message with a repeated message field of its own type), construct wire bytes nesting the group/message field `N` times, where `N` is many multiples of `protowire.DefaultRecursionLimit` (e.g., a few million). Call:
```go
m := &pb2.GroupMessage{}
err := proto.Unmarshal(deeplyNestedBytes, m)
```
Because each level's dispatch through `consumeGroupSlice`/`consumeGroupSliceValue`/`consumeMessageSliceValue` → `opts.Options().UnmarshalState(...)` resets the depth counter to `protowire.DefaultRecursionLimit` instead of continuing to decrement a cumulative counter, the recursive Go call chain grows with the full nesting depth of the wire input rather than being capped at `DefaultRecursionLimit`, resulting in a fatal stack overflow instead of the expected `errRecursionDepth` error.

func (o UnmarshalOptions) UnmarshalState(in protoiface.UnmarshalInput) (protoiface.UnmarshalOutput, error) {

func consumeGroupSlice(b []byte, p pointer, num protowire.Number, wtyp protowire.Type, goType reflect.Type, opts unmarshalOptions) (out unmarshalOutput, err error) {
	if wtyp != protowire.StartGroupType {
		return out, errUnknown
	}
	b, n := protowire.ConsumeGroup(num, b)
	if n < 0 {
		return out, errDecode
	}
	mp := reflect.New(goType.Elem())
	o, err := opts.Options().UnmarshalState(protoiface.UnmarshalInput{
		Buf:     b,
		Message: asMessage(mp).ProtoReflect(),
	})
	if err != nil {
		return out, err
	}
	p.AppendPointerSlice(pointerOfValue(mp))
	out.n = n
	out.initialized = o.Flags&protoiface.UnmarshalInitialized != 0
	return out, nil
}
