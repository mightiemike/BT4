### Title
Per-token `Enabled` flag in `TokenConfig` is never enforced in the inbound deposit / outbound withdrawal execution paths - ([File: x/uexecutor/keeper/handler.go])

### Summary
`uregistry.TokenConfig` carries an `enabled` field explicitly documented as "Whether this token is enabled for minting/bridging" [1](#0-0) , giving the admin a way to deactivate a specific token independent of the chain it lives on. However, none of the execution paths that mint PRC20s on inbound or resolve the token for outbound withdrawal check this flag — only the chain-level `ChainEnabled.IsInboundEnabled` / `IsOutboundEnabled` flags are validated. This is the exact analog of the Aave `[H03]` bug: one axis of "is this reserve/token allowed" is checked, the other (per-token deactivation) is silently ignored, so a token that the admin marked disabled can still be minted/moved through the standard user-facing flow.

### Finding Description
`depositPRC20` (the function that mints PRC20 into a recipient on every inbound funds path) fetches the `TokenConfig` and only validates that `NativeRepresentation` exists before calling `CallPRC20Deposit` — it never inspects `tokenConfig.Enabled`: [2](#0-1) 

The only enablement gate exercised anywhere in `x/uexecutor` is the chain-level one, checked in `VoteInbound` (`IsChainInboundEnabled`) and in `BuildOutboundsFromReceipt` (`IsChainOutboundEnabled`): [3](#0-2) [4](#0-3) 

`BuildOutboundsFromReceipt`, which resolves the external asset via `GetTokenConfigByPRC20` when building an outbound (withdrawal back to the external chain), likewise never checks `tokenCfg.Enabled` before attaching the outbound and queuing it for TSS signing: [5](#0-4) 

`GetChainConfig`/`IsChainInboundEnabled`/`IsChainOutboundEnabled` in `x/uregistry` only look at `ChainConfig.Enabled`, never at the per-token `Enabled` bit on the corresponding `TokenConfig`: [6](#0-5) 

A repo-wide search confirms `TokenConfig.Enabled` is set only in test fixtures/admin messages and read nowhere in `x/uexecutor` execution logic — the field is entirely decorative at runtime.

### Impact Explanation
If an admin disables a token via `MsgUpdateTokenConfig` (e.g., because the external token contract is compromised, deprecated, or being sunset, or the native-representation PRC20 mapping needs to be frozen mid-migration) with the expectation that no further minting/bridging can occur on it, an ordinary unprivileged user can still:
- Send inbound funds using that token's `AssetAddr` — `VoteInbound` only checks chain-level inbound enablement, so the ballot finalizes and `depositPRC20` still mints the PRC20 into the user's UEA/EOA, defeating the intended freeze.
- Trigger the corresponding outbound/withdrawal path — `BuildOutboundsFromReceipt` still resolves the disabled token via `GetTokenConfigByPRC20` and queues a real outbound for TSS signing and eventual release of the underlying external asset, even though the token was marked `enabled = false`.

This directly maps to the "unauthorized mint" / "corruption of PRC20 accounting" / "unauthorized release of user or protocol-controlled funds" categories in scope, because the deactivation flag exists specifically to stop minting/bridging for that token and is silently bypassed by ordinary user-submitted inbound/outbound flows with only honest validators involved.

### Likelihood Explanation
High reachability: the trigger is a completely ordinary inbound deposit or contract-driven outbound withdraw using an asset address that maps to a `TokenConfig` with `Enabled = false`. No privileged action, malicious validator, or TSS compromise is required — only an admin action (disabling a token) that is expected to be a security control, which then has no actual enforcement anywhere in the execution engine.

### Recommendation
Add an explicit `tokenConfig.Enabled` check in `depositPRC20` (`x/uexecutor/keeper/handler.go`) before minting, causing inbound processing to fail/revert for disabled tokens, and add the same check in `BuildOutboundsFromReceipt` (`x/uexecutor/keeper/create_outbound.go`) before constructing/attaching an outbound for a disabled token, so both mint and release/withdraw paths honor the registry's per-token deactivation flag.

### Proof of Concept
1. Admin registers a `ChainConfig` with `Enabled.IsInboundEnabled = true` and a `TokenConfig` for `USDC` on that chain with `Enabled = true` and a valid `NativeRepresentation.ContractAddress` (PRC20 address).
2. Admin later calls `MsgUpdateTokenConfig` to set `Enabled = false` on that `TokenConfig` (intending to stop further bridging of USDC) while leaving the chain itself enabled.
3. An ordinary user submits (via validators voting) an `Inbound` with `TxType_FUNDS` and `AssetAddr` = the disabled USDC address.
4. `VoteInbound` only checks `IsChainInboundEnabled` (true) and proceeds; on quorum, `ExecuteInboundFunds` → `depositPRC20` fetches the `TokenConfig` (still resolvable via `GetTokenConfig`), sees `NativeRepresentation != nil`, and calls `CallPRC20Deposit`, minting PRC20 into the recipient despite `Enabled == false`.
5. Symmetrically, a UEA/CEA contract execution that emits a `UniversalTxOutbound` event referencing this same disabled token's PRC20 address will have `BuildOutboundsFromReceipt` resolve it via `GetTokenConfigByPRC20` and create a real pending outbound routed to TSS signing, again with no `Enabled` check blocking it.

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

// IsChainInboundEnabled checks if inbound is enabled for a given chain
func (k Keeper) IsChainInboundEnabled(ctx context.Context, chain string) (bool, error) {
	config, err := k.GetChainConfig(ctx, chain)
	if err != nil {
		if errors.Is(err, collections.ErrNotFound) {
			// chain not found
			return false, nil
		}
		return false, err
	}
	if config.Enabled == nil {
		return false, nil
	}
	return config.Enabled.IsInboundEnabled, nil
}

// IsChainOutboundEnabled checks if outbound is enabled for a given chain
func (k Keeper) IsChainOutboundEnabled(ctx context.Context, chain string) (bool, error) {
	config, err := k.GetChainConfig(ctx, chain)
	if err != nil {
		if errors.Is(err, collections.ErrNotFound) {
			// chain not found
			return false, nil
		}
		return false, err
	}
	if config.Enabled == nil {
		return false, nil
	}
	return config.Enabled.IsOutboundEnabled, nil
}
