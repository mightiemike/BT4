## Finding

### Title
Replay-verification silently accepts and commits mismatched transaction outputs in lazy-quit mode - (File: execution/executor/src/chunk_executor/mod.rs)

### Summary
`TransactionReplayer::verify_execution` re-executes backed-up transactions with the real VM and compares the result against the persisted `TransactionInfo`/`WriteSet` taken from the backup using `ensure_match_transaction_info`. When run with `lazy_quit` enabled, a mismatch is only logged and recorded via `mark_seen_error()`, then the function returns `Ok(version + 1)` as if verification succeeded. The caller (`remove_and_replay_epoch`) proceeds to `remove_and_apply` the (unverified, potentially wrong) backup transaction info/write set into the local DB. The `seen_error` flag that is supposed to convey "verification actually failed" is never read by any of the callers (`ReplayVerifyCoordinator`, `RestoreCoordinator`, `VerifyCoordinator`, `db-tool` replay/restore commands), so the overall replay/verify/restore pipeline reports success even though a transaction that does not match real VM execution was committed to durable storage.

### Finding Description
`verify_execution` [1](#0-0)  re-executes a batch of backup transactions and checks equality with `ensure_match_transaction_info` against the recorded `transaction_infos` and `write_sets` coming from the backup archive. On mismatch, instead of aborting: [2](#0-1) 

```
if let Err(err) = txn_out.ensure_match_transaction_info(...) {
    return if verify_execution_mode.is_lazy_quit() {
        error!("(Not quitting right away.) {}", err);
        verify_execution_mode.mark_seen_error();
        Ok(version + 1)
    } else {
        Err(err)
    };
}
```

The `Ok(version + 1)` return value is treated by `remove_and_replay_epoch` exactly like a successful verification: it is fed to `remove_and_apply` [3](#0-2) , which commits the *backup-supplied* `TransactionInfo`/`WriteSet` for that version (not the freshly-computed VM output) into the chunk to be persisted.

The `seen_error` `AtomicBool` set by `mark_seen_error()` is defined in `VerifyExecutionMode` [4](#0-3) , but a codebase-wide search shows the only occurrence of `seen_error()`/`mark_seen_error()` usage is inside `chunk_executor/mod.rs` itself — none of the call sites that drive replay/restore/verify (`storage/backup/backup-cli/src/coordinators/replay_verify.rs`, `storage/backup/backup-cli/src/coordinators/restore.rs`, `storage/backup/backup-cli/src/coordinators/verify.rs`, `storage/db-tool/src/replay_verify.rs`, `storage/db-tool/src/restore.rs`) ever calls `.seen_error()` to check whether a mismatch occurred and to fail the overall operation. `ReplayVerifyCoordinator::run` only treats `Err` results from `run_impl()` as failure [5](#0-4) , and since `verify_execution` returns `Ok(...)` in lazy-quit mode, no error ever surfaces.

### Impact Explanation
In lazy-quit replay-verify mode, a backup-supplied `TransactionInfo`/`WriteSet` whose content diverges from what the real VM would compute (e.g., corrupted backup, tampered archive, or a non-deterministic/incorrect historical execution) is committed to the target database and the overall coordinator reports success, since the recorded divergence (`seen_error`) is never consulted. This directly violates the required invariant that "committed state must not differ from the correct VM result" and that replay/restore paths must not "reinterpret committed data into a different ledger state." An operator running `aptos db-tool replay-verify` (or `restore`, which shares the same code path) with lazy-quit could unknowingly restore/replay a database containing incorrect ledger state while the tool exits with success, defeating the entire purpose of replay verification as an integrity check for backups.

### Likelihood Explanation
`lazy_quit` is an explicit, supported mode (`set_lazy_quit`), used intentionally so that `replay-verify` continues past known-bad ranges to collect all mismatches instead of stopping at the first one. The bug is that this "collect and report later" design never actually reports later — the collected `seen_error` signal is dead code as far as the CLI/coordinator success/failure determination goes. This requires no attacker interaction beyond corrupting/crafting the backup archive being replayed (a plausible scenario for supply-chain/backup-integrity checks), and the exposure is triggered on every use of `replay-verify`/`restore` with lazy-quit enabled.

### Recommendation
- After batch/epoch replay completes (e.g., in `ReplayVerifyCoordinator::run_impl`, `RestoreCoordinator::run_impl`, and the corresponding `db-tool` commands), check `verify_execution_mode.seen_error()` and return an error if `true`, instead of silently exiting with `Ok(())`.
- Alternatively, do not commit the mismatched transaction (skip applying `remove_and_apply` for those versions) unless the operator has explicitly opted into "skip known-broken versions" via `txns_to_skip`.
- Ensure any tool relying on `VerifyExecutionMode::Verify { lazy_quit: true, .. }` propagates a non-zero exit code / hard failure when `seen_error` was ever set.

### Proof of Concept
1. Prepare a transaction backup manifest where at least one `TransactionInfo`/`WriteSet` entry has been altered from what the real VM execution for that transaction would produce (a corrupted/malicious backup).
2. Run `aptos db-tool replay-verify` (or the backup-cli `verify`/`restore` command) with lazy-quit verification enabled, targeting a version range that includes the tampered transaction.
3. Observe: `verify_execution` logs `"(Not quitting right away.) ..."` for the mismatch and calls `mark_seen_error()`, but returns `Ok(version + 1)`.
4. `remove_and_apply` commits the tampered `TransactionInfo`/`WriteSet` into the target DB.
5. The coordinator (`ReplayVerifyCoordinator::run`) completes with `Ok(())` and logs "exiting with success", because `seen_error()` is never checked — despite the DB now containing a transaction whose committed state does not match genuine VM execution.

    fn verify_execution(
        &self,
        transactions: &[Transaction],
        persisted_aux_info: &[PersistedAuxiliaryInfo],
        transaction_infos: &[TransactionInfo],
        write_sets: &[WriteSet],
        event_vecs: &[Vec<ContractEvent>],
        begin_version: Version,
        end_version: Version,
        verify_execution_mode: &VerifyExecutionMode,
    ) -> Result<Version> {
        // Execute transactions.
        let parent_state = self.commit_queue.lock().latest_state().clone();
        let state_view = self.state_view(parent_state.latest())?;
        let txns = transactions
            .iter()
            .take((end_version - begin_version) as usize)
            .cloned()
            .map(|t| t.into())
            .collect::<Vec<SignatureVerifiedTransaction>>();

        let auxiliary_info = persisted_aux_info
            .iter()
            .take((end_version - begin_version) as usize)
            .map(|persisted_aux_info| AuxiliaryInfo::new(*persisted_aux_info, None))
            .collect::<Vec<_>>();
        let onchain_config = chunk_onchain_config(&state_view)?;
        let execution_output = DoGetExecutionOutput::by_transaction_execution::<V>(
            &V::new(),
            txns.into(),
            auxiliary_info,
            &parent_state,
            state_view,
            onchain_config,
            TransactionSliceMetadata::chunk(begin_version, end_version),
        )?;
        // not `zip_eq`, deliberately
        for (version, txn_out, txn_info, write_set, events) in multizip((
            begin_version..end_version,
            &execution_output.to_commit.transaction_outputs,
            transaction_infos.iter(),
            write_sets.iter(),
            event_vecs.iter(),
        )) {
            if let Err(err) = txn_out.ensure_match_transaction_info(
                version,
                txn_info,
                Some(write_set),
                Some(events),
            ) {
                return if verify_execution_mode.is_lazy_quit() {
                    error!("(Not quitting right away.) {}", err);
                    verify_execution_mode.mark_seen_error();
                    Ok(version + 1)
                } else {
                    Err(err)
                };
            }
        }
        Ok(end_version)
    }

#[derive(Clone)]
pub enum VerifyExecutionMode {
    NoVerify,
    Verify {
        txns_to_skip: Arc<BTreeSet<Version>>,
        lazy_quit: bool,
        seen_error: Arc<AtomicBool>,
    },
}

impl VerifyExecutionMode {
    pub fn verify_all() -> Self {
        Self::Verify {
            txns_to_skip: Arc::new(BTreeSet::new()),
            lazy_quit: false,
            seen_error: Arc::new(AtomicBool::new(false)),
        }
    }

    pub fn verify_except(txns_to_skip: Vec<Version>) -> Self {
        Self::Verify {
            txns_to_skip: Arc::new(txns_to_skip.into_iter().collect()),
            lazy_quit: false,
            seen_error: Arc::new(AtomicBool::new(false)),
        }
    }

    pub fn txns_to_skip(&self) -> Arc<BTreeSet<Version>> {
        match self {
            VerifyExecutionMode::NoVerify => Arc::new(BTreeSet::new()),
            VerifyExecutionMode::Verify { txns_to_skip, .. } => txns_to_skip.clone(),
        }
    }

    pub fn set_lazy_quit(mut self, is_lazy_quit: bool) -> Self {
        if let Self::Verify {
            ref mut lazy_quit, ..
        } = self
        {
            *lazy_quit = is_lazy_quit
        }
        self
    }

    pub fn is_lazy_quit(&self) -> bool {
        match self {
            VerifyExecutionMode::NoVerify => false,
            VerifyExecutionMode::Verify { lazy_quit, .. } => *lazy_quit,
        }
    }

    pub fn mark_seen_error(&self) {
        match self {
            VerifyExecutionMode::NoVerify => unreachable!("Should not call in no-verify mode."),
            VerifyExecutionMode::Verify { seen_error, .. } => {
                seen_error.store(true, Ordering::Relaxed)
            },
        }
    }

    pub fn should_verify(&self) -> bool {
        !matches!(self, Self::NoVerify)
    }

    pub fn seen_error(&self) -> bool {
        match self {
            VerifyExecutionMode::NoVerify => false,
            VerifyExecutionMode::Verify { seen_error, .. } => seen_error.load(Ordering::Relaxed),
        }
    }
