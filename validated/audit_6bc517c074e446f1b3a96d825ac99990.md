### Title
Missing Minimum-Remaining-Balance Check Allows Dust Delegated Resource Positions via Partial `UnDelegateResourceContract` - (File: `actuator/src/main/java/org/tron/core/actuator/UnDelegateResourceActuator.java`)

### Summary
`DelegateResourceActuator`/`DelegateResourceProcessor` enforce a minimum of 1 TRX (`TRX_PRECISION`) when a user creates a delegated-resource position, but the corresponding withdrawal path, `UnDelegateResourceActuator`/`UnDelegateResourceProcessor`, only checks that the requested amount is positive and does not exceed the delegated balance. This mirrors the reported Vault.sol issue: the minimum-size invariant is validated only at deposit/creation time and can be silently violated by a partial withdrawal, leaving a dust-sized position on-chain.

### Finding Description
On delegation, `DelegateResourceActuator.validate()` requires `delegateBalance >= TRX_PRECISION` ("delegateBalance must be greater than or equal to 1 TRX"): [1](#0-0) 

The same 1-TRX floor is duplicated in the native/TVM path `DelegateResourceProcessor.validate()`: [2](#0-1) 

However, `UnDelegateResourceActuator.validate()` (the partial-withdrawal path) only checks `unDelegateBalance <= 0` and that enough delegated balance exists to cover the requested amount — there is no check that the *remaining* delegated balance stays at or above the 1 TRX minimum, or that the withdrawal must be all-or-nothing: [3](#0-2) 

The same absence of a floor check exists in the native-contract path used from TVM (`UnDelegateResourceProcessor.validate`), reachable via the `unDelegateResource` opcode handler in `Program.java`: [4](#0-3) [5](#0-4) 

In `UnDelegateResourceActuator.execute()`, the underlying `DelegatedResourceCapsule` is only deleted from `DelegatedResourceStore` when both the unlocked and locked frozen balances for bandwidth and energy are exactly `0`; any nonzero remainder — including 1 sun — keeps the record alive: [6](#0-5) 

As a result, a user can: (1) delegate exactly 1 TRX (the enforced minimum) to a receiver via `DelegateResourceContract`, then (2) immediately submit `UnDelegateResourceContract` for `1 TRX - 1 sun`, which passes validation because it is `> 0` and `<= delegateBalance`. This leaves a dust-sized (1 sun) `DelegatedResourceCapsule` entry, bypassing the intended 1-TRX minimum floor that `DelegateResourceActuator` otherwise enforces.

### Impact Explanation
This bypasses the protocol's own "delegateBalance must be greater than or equal to 1 TRX" invariant, letting any account create and retain a resource-delegation record below the minimum economic size. While the current `DelegatedResourceAccountIndexStore` is key-value based (per owner/receiver pair) rather than an unbounded list, the underlying accounting invariant (minimum position size) is still violated at low cost, letting an actor cheaply litter `DelegatedResourceStore` with sub-minimum, effectively-dead positions tied to many receiver addresses, degrading the intended guarantee that delegated positions are always economically meaningful. This is an accounting/invariant-corruption issue analogous to the reported Vault bug, though its severity is lower than the original report because there is no unbounded per-account list growth in the current store design.

### Likelihood Explanation
The path is reachable by any unprivileged account via ordinary broadcast transactions (`DelegateResourceContract` followed by `UnDelegateResourceContract`) or via TVM contract calls to the corresponding native contract, requiring no privileged role — only the minimal TRX amount to freeze/delegate once. This makes exploitation straightforward and cheap.

### Recommendation
In `UnDelegateResourceActuator.validate()` / `UnDelegateResourceProcessor.validate()`, after computing the delegated balance, require either that the requested `unDelegateBalance` equals the entire remaining delegated balance for that resource, or that `delegateBalance - unDelegateBalance` is `0` or `>= TRX_PRECISION`, mirroring the minimum check already enforced in `DelegateResourceActuator`/`DelegateResourceProcessor`.

### Proof of Concept
1. Account A freezes ≥1 TRX for BANDWIDTH/ENERGY via `FreezeBalanceV2Contract`.
2. Account A submits `DelegateResourceContract` delegating exactly `1 TRX` (`TRX_PRECISION`) to receiver B — this passes `DelegateResourceActuator.validate()`'s minimum check at `actuator/src/main/java/org/tron/core/actuator/DelegateResourceActuator.java:147-150`.
3. Account A submits `UnDelegateResourceContract` with `unDelegateBalance = TRX_PRECISION - 1`. This passes `UnDelegateResourceActuator.validate()` since it only checks `unDelegateBalance > 0` and `<= delegateBalance` at `actuator/src/main/java/org/tron/core/actuator/UnDelegateResourceActuator.java:265-283`, with no remaining-minimum check.
4. Resulting `DelegatedResourceCapsule` for (A, B) now holds `1` sun of delegated balance, below the protocol's intended 1-TRX minimum, and is not deleted since the balance is nonzero (`actuator/src/main/java/org/tron/core/actuator/UnDelegateResourceActuator.java:170-176`).

  public boolean unDelegateResource(
      DataWord receiverAddress, DataWord unDelegateBalance, DataWord resourceType) {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();
    byte[] receiver = receiverAddress.toTronAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, receiver,
        unDelegateBalance.longValue(), null,
        "unDelegateResourceOf" + convertResourceToString(resourceType), nonce, null);

    try {
      UnDelegateResourceParam param = new UnDelegateResourceParam();
      param.setOwnerAddress(owner);
      param.setReceiverAddress(receiver);
      param.setUnDelegateBalance(unDelegateBalance.sValue().longValueExact());
      param.setResourceType(parseResourceCodeV2(resourceType));

      UnDelegateResourceProcessor processor = new UnDelegateResourceProcessor();
      processor.validate(param, repository);
      processor.execute(param, repository);
      repository.commit();
      return true;
    } catch (ContractValidateException e) {
      logger.warn("TVM UnDelegateResource: validate failure. Reason: {}", e.getMessage());
    } catch (ArithmeticException e) {
      logger.warn("TVM UnDelegateResource: balance out of long range.");
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return false;
  }
