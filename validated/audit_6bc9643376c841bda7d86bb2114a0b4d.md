### Title
Confidential relay gateway forwards attacker-chosen `jsonrpc.Request.Method` to every DON node before method whitelisting is enforced - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` never validates `req.Method` against the two allowed methods (`MethodSecretsGet`, `MethodCapabilityExec`) before queuing the request and fanning it out to every DON node. Method validation happens only in `bundler.Bundle`'s `switch req.Method` (in `core/services/gateway/handlers/confidentialrelay/bundler.go`), which is invoked only after node responses start arriving in `HandleNodeMessage`/expiry paths, i.e. strictly after `fanOutToNodes` has already sent the raw, attacker-controlled request to every relay node.

### Finding Description
`HandleJSONRPCUserMessage` (core/services/gateway/handlers/confidentialrelay/handler.go:349-366) performs only two checks — `req.ID` non-empty and length ≤ 200 — then calls `h.newActiveRequest(req, callback)` and `h.fanOutToNodes(ctx, l, ar)`. Neither of these functions, nor anything upstream, checks `req.Method`. `fanOutToNodes` (handler.go:618-652) iterates `h.donConfig.Members` and calls `h.don.SendToNode(sendCtx, node.Address, &ar.req)` for every member, forwarding `ar.req` — including whatever attacker-supplied `Method` and `Params` were sent — verbatim.

The only place `req.Method` is checked against the whitelist is `bundler.Bundle`'s `switch req.Method { case MethodSecretsGet: ...; case MethodCapabilityExec: ...; default: return nil, fmt.Errorf("%w: %q", errUnknownMethod, req.Method) }` (bundler.go:118-163). This function is only invoked from `HandleNodeMessage` (handler.go:424) and the expiry/grace sweep paths (`removeExpiredRequests`, `forwardAfterGrace`), all of which run strictly after `fanOutToNodes` has already dispatched the request to the DON.

Route-level analysis confirms reachability: `gateway.ProcessRequest` (core/services/gateway/gateway.go:218-292) dispatches to `h.HandleJSONRPCUserMessage`, where `h` may be a `multiHandler` (core/services/gateway/multihandler.go). `multiHandler.getHandler` (multihandler.go:80-96) contains a shortcut: `if len(m.typeToHandler) == 1 { for _, handler := range m.typeToHandler { return handler, nil } }` — when a gateway service is configured with only the confidential-relay handler (a realistic single-handler-per-service setup, per the comment in gateway.go:118 "each handler is associated with a single service"), this shortcut bypasses the `methodToHandler` lookup entirely, so an arbitrary `Method` value is routed straight into the confidentialrelay handler without any whitelist check at the routing layer either.

The declared `Methods()` (handler.go:341-343) returning `[MethodSecretsGet, MethodCapabilityExec]` is registered only in `methodToHandler` for whitelisting in the multi-handler path; it is not consulted in the single-handler routing shortcut nor inside `handler.HandleJSONRPCUserMessage` itself.

### Impact Explanation
An unprivileged attacker reaching the gateway's user-facing endpoint can submit a JSON-RPC request with `Method` set to an arbitrary string and arbitrary `Params`, and have it forwarded verbatim over the node websocket connection (`don.SendToNode`) to every member of the confidential-relay DON before any server-side rejection occurs. This is unauthorized delivery of unvalidated, attacker-controlled RPC calls to privileged relay-node execution surfaces — the exact "untrusted input reaching privileged remote-node execution paths without method whitelisting" scenario. Concrete impact is bounded by what the relay-node-side dispatcher does with an unrecognized method (probing/DoS/unexpected-code-path execution on nodes), but the gateway itself fails to enforce the invariant that only `MethodSecretsGet`/`MethodCapabilityExec` requests are relayed.

### Likelihood Explanation
Fully reachable by any unprivileged caller with network access to the gateway's user HTTP endpoint; no privileged credentials, keys, or social engineering needed. The bug is deterministic and 100% repeatable — every request with a non-whitelisted `Method` and a well-formed `ID` will pass `HandleJSONRPCUserMessage`'s checks and be fanned out before rejection.

### Recommendation
Validate `req.Method` against the whitelist (`MethodSecretsGet`, `MethodCapabilityExec`) at the top of `handler.HandleJSONRPCUserMessage`, before `newActiveRequest`/`fanOutToNodes` are called, returning `api.UnsupportedMethodError` immediately for any other method. Additionally, fix `multiHandler.getHandler`'s single-handler shortcut to still enforce `methodToHandler` membership (or otherwise ensure `Methods()` is consulted) rather than blindly returning the sole registered handler regardless of the requested method.

func (h *handler) HandleJSONRPCUserMessage(ctx context.Context, req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) error {
	if req.ID == "" {
		return errors.New("request ID cannot be empty")
	}
	if len(req.ID) > 200 {
		return errors.New("request ID is too long: " + strconv.Itoa(len(req.ID)) + ". max is 200 characters")
	}

	l := logger.With(h.lggr, "method", req.Method, "requestID", req.ID)
	l.Debugw("handling confidential relay request")

	ar, err := h.newActiveRequest(req, callback)
	if err != nil {
		return err
	}

	return h.fanOutToNodes(ctx, l, ar)
}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

	numNodeErrors := nodeErrors.Load()
	remainingPossibleResponses := len(h.donConfig.Members) - int(numNodeErrors)
	if remainingPossibleResponses < h.donConfig.F+1 && numNodeErrors > 0 {
		return h.sendResponseAndClearRequest(ctx, ar, h.constructErrorResponse(ar.req, api.FatalError, errors.New("failed to forward user request to nodes")))
	}

	l.Debugw("successfully forwarded request to relay nodes")
	return nil
}

func (b *bundler) Bundle(req jsonrpc.Request[json.RawMessage], resps map[string]jsonrpc.Response[json.RawMessage], l logger.Logger) (*BundleSummary, error) {
	summary := newBundleSummary(len(resps))

	switch req.Method {
	case relaytypes.MethodSecretsGet:
		out := make([]relaytypes.SignedSecretsResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedSecretsResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable secrets response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedSecretsResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode secrets response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	case relaytypes.MethodCapabilityExec:
		out := make([]relaytypes.SignedCapabilityResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedCapabilityResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable capability response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedCapabilityResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode capability response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	default:
		return nil, fmt.Errorf("%w: %q", errUnknownMethod, req.Method)
	}

func (m *multiHandler) HandleJSONRPCUserMessage(ctx context.Context, jsonRequest jsonrpc.Request[json.RawMessage], callback handlers.Callback) error {
	h, err := m.getHandler(jsonRequest.Method)
	if err != nil {
		return fmt.Errorf("failed to get handler for method %s: %w", jsonRequest.Method, err)
	}

	return h.HandleJSONRPCUserMessage(ctx, jsonRequest, callback)
}

func (m *multiHandler) HandleNodeMessage(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h, err := m.getHandler(resp.Method)
	if err != nil {
		return fmt.Errorf("failed to get handler for method %s: %w", resp.Method, err)
	}

	return h.HandleNodeMessage(ctx, resp, nodeAddr)
}

func (m *multiHandler) getHandler(method string) (handlers.Handler, error) {
	// If there's only one handler, return it directly.
	// This preserves backwards compatibility for cases where the method
	// isn't specified on responses (and for cases where only one handler is registered more generally).
	if len(m.typeToHandler) == 1 {
		for _, handler := range m.typeToHandler {
			return handler, nil
		}
	}

	handler, ok := m.methodToHandler[method]
	if !ok {
		return nil, errors.New("no handler found for method " + method)
	}

	return handler, nil
}
