## Analysis

The reported bug is "an authority-controlled address field is accepted without format validation, causing permanent loss of control/funds." Tracing this bug class through Push Chain's `x/uexecutor` module surfaces a real analog in the revert/refund recipient path.

`RevertInstructions.FundRecipient` (the address that receives re-minted PRC20 tokens when an inbound is stuck or an outbound fails) is **never validated for address format**, unlike `Inbound.Recipient`, `OutboundTx.Sender`, and `MsgUpdateParams.Params.Admin`, all of which go through `utils.IsValidAddress(..., utils.HEX/COSMOS)` before being persisted or acted on [1](#0-0) .

`Inbound.Canonicalize()` only *canonicalizes* `RevertInstructions.FundRecipient` via `utils.LenientCanonicalizeAddress`, explicitly documented as "lenient... unparseable values are kept trimmed, never rejected" [2](#0-1) . There is no corresponding `RevertInstructions.ValidateBasic()` and no execution-time check anywhere (confirmed by search — no such validator exists), unlike the parallel `Inbound.Recipient` field which is explicitly checked with `utils.IsValidAddress(p.Recipient, utils.HEX)` in `ValidateForExecution()` [3](#0-2) .

That unvalidated value is later consumed directly as the fund destination in two places:
- `buildRevertOutbound`, which sets `outbound.Recipient = inbound.RevertInstructions.FundRecipient` verbatim [4](#0-3) .
- `handleFailedOutbound`, which re-mints bridged funds by calling `k.CallPRC20Deposit(ctx, ..., common.HexToAddress(recipient), amount)` where `recipient` comes straight from `outbound.RevertInstructions.FundRecipient` [5](#0-4) .

`common.HexToAddress` (go-ethereum) silently truncates/left-pads any string that isn't valid 20-byte hex rather than erroring — an attacker-controlled non-hex or malformed `FundRecipient` (e.g. Solana base58 for a cross-VM inbound, or a garbage string) resolves to an unintended address, most commonly the zero address, when funds are minted back.

## Title
Unvalidated `RevertInstructions.FundRecipient` allows permanent loss of re-minted refund/revert funds - (File: x/uexecutor/keeper/outbound.go)

## Summary
Unlike every other address-carrying field in `x/uexecutor` (`Inbound.Recipient`, `OutboundTx.Sender`, `MsgUpdateParams.Admin`), the attacker-supplied `RevertInstructions.FundRecipient` field is never format-validated before being used as the destination of a PRC20 re-mint. Canonicalization is explicitly "lenient" and never rejects malformed values, and there is no `ValidateBasic`/`ValidateForExecution` check on this specific field.

## Finding Description
An inbound crossing observation includes an optional `RevertInstructions{ FundRecipient string }` supplied as part of the source-chain event payload observed by validators [6](#0-5) . Once ballot quorum is reached, this value flows unchanged into `buildRevertOutbound`/`handleFailedOutbound` and is passed to `common.HexToAddress()` when re-minting bridged funds via `CallPRC20Deposit` [7](#0-6) . `Inbound.ValidateForExecution()` validates `p.Recipient` with `utils.IsValidAddress(p.Recipient, utils.HEX)` for FUNDS/GAS types, but performs no equivalent check on `p.RevertInstructions.FundRecipient` [8](#0-7) . The canonicalization step is documented to intentionally never reject the value [9](#0-8) .

## Impact Explanation
Because `common.HexToAddress` does not error on malformed input, a malformed `FundRecipient` resolves to an unintended (frequently zero) address. When the associated inbound gets stuck, or an outbound subsequently fails and is reverted, the protocol re-mints the user's bridged PRC20 tokens to that unintended address instead of the intended refund destination — a permanent, unrecoverable loss of user funds, matching the in-scope "permanent loss ... of user or protocol-controlled funds" impact.

## Likelihood Explanation
`RevertInstructions` is part of the `Inbound` struct observed and voted on by honest validators from source-chain event data; the value itself is attacker-influenced (it comes from the transaction/payload the depositing user constructs on the source chain). No special validator misbehavior is required — an unprivileged user submitting a malformed source-chain event triggers this path only when a revert is later needed (stuck-inbound admin action or outbound failure), so the likelihood is moderate/conditional rather than immediate at vote time.

## Recommendation
Add an explicit format check for `RevertInstructions.FundRecipient` in `Inbound.ValidateForExecution()` and in `OutboundTx.ValidateBasic()` wherever `RevertInstructions` is present, mirroring the existing `utils.IsValidAddress(..., utils.HEX)` check applied to `Inbound.Recipient`. Reject (or fall back to `inbound.Sender`, as already done when `FundRecipient` is empty) whenever the supplied value is not a valid 20-byte hex address, rather than silently canonicalizing it and passing it to `common.HexToAddress`.

## Proof of Concept
1. Submit/observe an inbound (`FUNDS` type) with `RevertInstructions.FundRecipient = "not-a-valid-hex-address"`.
2. Validators reach quorum; `Canonicalize()` leaves the malformed value trimmed but unrejected [10](#0-9) .
3. Trigger a revert path (e.g., stuck-inbound admin revert or a failed outbound) so `buildRevertOutbound`/`handleFailedOutbound` runs.
4. `common.HexToAddress("not-a-valid-hex-address")` resolves to an unintended address (typically the zero address) rather than erroring.
5. `CallPRC20Deposit` mints the bridged amount to that unintended address — funds are permanently unrecoverable by the original depositor.

// Canonicalize normalizes encoding-variant fields in place (per source-chain
// namespace) so the same event from any observer is byte-identical across
// ballot keys, UTX keys and registry lookups. Lenient (unparseable values are
// kept trimmed, never rejected) because the vote path must always record a
// UTX — execution-level validation rejects malformed inbounds later.
func (p *Inbound) Canonicalize() {
	p.SourceChain = strings.TrimSpace(p.SourceChain)
	p.TxHash = utils.LenientCanonicalizeTxHash(p.SourceChain, p.TxHash)
	p.Sender = utils.LenientCanonicalizeAddress(p.SourceChain, p.Sender)
	p.AssetAddr = utils.LenientCanonicalizeAddress(p.SourceChain, p.AssetAddr)
	// Recipient lives on Push Chain (EVM) regardless of source chain.
	p.Recipient = utils.LenientCanonicalizeEVMAddress(p.Recipient)
	p.LogIndex = strings.TrimSpace(p.LogIndex)
	p.Amount = strings.TrimSpace(p.Amount)
	p.RawPayload = utils.CanonicalizeHexBlob(p.RawPayload)
	p.VerificationData = utils.CanonicalizeHexBlob(p.VerificationData)
	if p.RevertInstructions != nil {
		// Refunds return to the source chain.
		p.RevertInstructions.FundRecipient = utils.LenientCanonicalizeAddress(p.SourceChain, p.RevertInstructions.FundRecipient)
	}
}

// ValidateForExecution checks fields that are required for actual execution of the inbound.
// Called after ballot finalization, before ExecuteInbound. Failures here produce a failed
// PCTx and (for non-isCEA) a revert outbound, rather than dropping the vote.
func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a

func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)
