## Analog Found: Spot-Price Manipulation of the Uniswap V3 Auto-Swap Path Used for GAS Inbound Accounting

### Title
Unprotected spot-price quote used as its own slippage floor allows sandwich manipulation of `depositPRC20WithAutoSwap` on GAS / GAS_AND_PAYLOAD inbounds - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
The externally reported bug class is a first-depositor/donation attack that lets an attacker manipulate an internally computed exchange-rate (share price) so that the *very same call path* that computes the price also consumes it, defeating any protective check. The closest reachable analog in Push Chain is `Keeper.GetSwapQuote`, which fetches a live Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote and then derives the "slippage protection" (`minPCOut`) directly from that same, freshly-read, manipulable quote, rather than from an independent/TWAP reference price.

### Finding Description
`GetSwapQuote` in [1](#0-0)  calls `QuoterV2.quoteExactInputSingle` for the `prc20 -> wpc` pair with no price-impact bound and no TWAP/oracle cross-check. Both `ExecuteInboundGas` and `gasAndPayloadDepositAutoSwap` immediately turn that quote into the swap's own floor: [2](#0-1) 

```go
quote, execErr = k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
...
// 5% slippage: minPCOut = quote * 95 / 100
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
receipt, execErr = k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
```

The same pattern repeats in `gasAndPayloadDepositAutoSwap` [3](#0-2)  and in the outbound gas refund path `applyGasRefund` / `getSwapQuoteForRefund` [4](#0-3) .

Because `minPCOut` is 95% of a quote read at the instant of execution (not a historical/TWAP price, not a value supplied or agreed to by the user ahead of time), an attacker who moves the pool's spot price downward immediately before this module-originated swap executes causes the "slippage protection" to move down with it — it protects only against a further 5% move from the already-manipulated price, not against the manipulation itself. This is structurally the same defect class as the reported backstop bug: a value that should reflect fair, un-manipulated state (share price / swap price) is computed and consumed atomically from attacker-influenced pool state, so the intended protection is illusory.

`ExecuteInboundGas` / `ExecuteInboundGasAndPayload` run automatically the moment UV vote quorum is reached (module-originated `DerivedEVMCall`, `isModuleSender=true`, per [5](#0-4) ). An unprivileged actor watching for the third confirming `MsgVoteInbound` in the mempool can front-run/sandwich that block with ordinary DEX trades against the same Uniswap V3 pool (no special privilege — anyone can trade on the pool), depressing `prc20 -> wpc` spot price, letting the module's auto-swap execute at that depressed price, and then reversing the trade to extract the difference.

### Impact Explanation
A successful sandwich causes the recipient UEA (an ordinary, unprivileged user's inbound GAS/GAS_AND_PAYLOAD deposit) to receive materially less PC than fair value, while the attacker profits the difference from the AMM pool. This is a corruption of gas-fee/token-swap accounting reachable purely through ordinary user deposit flows and public AMM trades, matching the "corruption of ... gas fee accounting ... token mapping" and "stealing ... of user or protocol-controlled funds" impact categories. The magnitude scales with pool liquidity depth; Push Chain's own e2e tooling seeds pools with very small liquidity (`pool_token_amount`/`pool_wpc_amount` on the order of 1–4 units, per `e2e-tests/setup.sh`), illustrating how shallow these pools can realistically be, which would make such manipulation cheap.

### Likelihood Explanation
Exploitation requires only: (1) an unprivileged wallet capable of swapping on the public Uniswap V3 pool, and (2) the ability to time a transaction relative to the block that finalizes UV vote quorum for someone else's inbound — both are ordinary, permissionless capabilities. The attack does not require compromising any validator, TSS participant, or admin key.

### Recommendation
Do not derive `minPCOut` from a spot quote fetched in the same execution path that consumes it. Use a time-weighted average price (TWAP) from the pool (or an independent oracle) to bound acceptable slippage, or require an externally supplied/pre-agreed `minPCOut` that cannot be recomputed from manipulated same-block state, and consider bounding maximum acceptable price impact independent of the current spot quote.

### Proof of Concept
1. Observe a pending `MsgVoteInbound` for `TxType_GAS`/`GAS_AND_PAYLOAD` that will reach 2-of-3 (or configured) quorum in the next block, triggering `ExecuteInboundGas`.
2. In the same block (or immediately prior), submit a large swap on the `prc20/WPC` Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`, pushing the `prc20 -> wpc` spot price down.
3. When quorum lands, `GetSwapQuote` returns the depressed quote; `minPCOut = quote * 95/100` is computed from that depressed value, so `CallPRC20DepositAutoSwap` executes and succeeds at the bad price.
4. Reverse the initial swap to restore price, capturing the spread; the deposit recipient's UEA receives less PC than fair value would have provided.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)

When `x/uexecutor` itself needs to issue an EVM call (deposit PRC20s, push chain-meta, refund unused gas, ...) the sender is the `uexecutor` module account.
