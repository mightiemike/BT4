### Title
Sandwichable AMM quote used as both the swap execution price and its own slippage protection in gas-abstraction auto-swap - (File: x/uexecutor/keeper/execute_inbound_gas.go)

### Summary
`ExecuteInboundGas` computes a Uniswap V3 swap quote and derives its own slippage-protection bound (`minPCOut`) from that same, attacker-manipulable, at-execution AMM state, mirroring the reported pattern where a protective value (auction floor price) is computed from mutable on-chain state that an unprivileged actor can move immediately before the protected operation executes.

### Finding Description
When a user deposits a gas token cross-chain, `ExecuteInboundGas` swaps the deposited PRC20 for WPC on behalf of the user's UEA: [1](#0-0) 

The flow is:
1. `k.GetSwapQuote(...)` calls `QuoterV2.quoteExactInputSingle` against the live pool state to get `quote` [2](#0-1) .
2. `minPCOut` is derived directly from that same `quote` with a flat 5% slippage buffer: `minPCOut = quote * 95 / 100` [3](#0-2) .
3. `k.CallPRC20DepositAutoSwap(...)` then executes the deposit + swap using this `minPCOut` as the only protection [4](#0-3) .

Because the quote and the protection bound are computed from the identical, instantaneous, on-chain pool price at the moment the module-originated swap executes, the "protection" offers no real defense against price manipulation performed immediately beforehand — this is structurally the same flaw as the reported `currentRFV`/auction issue, where the floor value and the value used to validate it are both derived from the same manipulable state at the same moment. An unprivileged attacker can submit ordinary swap transactions against the same PRC20/WPC pool (a standard, permissionless Uniswap V3 pool referenced via `uniswapV3Quoter`/`WPC`/`defaultFeeTier` in `UniversalCore`) to push the pool price down just before the ballot-finalized inbound executes `ExecuteInboundGas`, then reverse the swap afterward (classic sandwich). The victim's auto-swap will still pass the `minPCOut` check because that check was derived from the manipulated price itself, not from a market-fair reference or a quote captured before the manipulation window.

`getSwapQuoteForRefund`, used for outbound gas-token refund swaps, follows the identical pattern (quote computed at execution time, immediately consumed) [5](#0-4) , so the same class of issue recurs on the refund path.

### Impact Explanation
This directly corrupts PRC20/native asset accounting for the depositing user's UEA: the amount of WPC actually credited can be pushed down to just above the artificially-suppressed floor, while the attacker captures the difference via the reversing swap — a value-extraction/drain of user funds executed by an unprivileged actor, matching the in-scope "corruption of PRC20 or native asset accounting" and "unauthorized ... drain ... of user or protocol-controlled funds" impact categories. Because gas-abstraction deposits underlie normal user gas funding, users can also receive materially less WPC than expected for subsequent transactions.

### Likelihood Explanation
Likelihood is High: the underlying pool (`uniswapV3Quoter`/WPC pair referenced by `UniversalCore`) is a standard permissionless AMM reachable by any address; no privileged role is required to submit swaps that move its price. The only constraint is timing the sandwich around the block in which the inbound ballot finalizes and `ExecuteInboundGas` runs, which is observable on-chain (pending/queued inbound votes) before finalization, exactly analogous to the front-run window described in the source report.

### Recommendation
Do not derive the slippage-protection bound from the same instantaneous quote used to execute the swap. Options:
- Capture and commit a reference price (e.g., a TWAP from the pool, or a price recorded at inbound observation/vote time before it can be influenced by the same actor) and validate deviation against that reference rather than against a live spot quote fetched immediately before execution.
- Allow inbound-specific `minPCOut`/max-slippage parameters to be set from a validator-attested value at vote time, so a single attacker cannot both set and satisfy the bound in the same transaction window.
- Consider using a TWAP oracle instead of `quoteExactInputSingle` spot-quote for both the executed price and the protection check.

### Proof of Concept
1. Attacker observes a pending gas-abstraction inbound (e.g., a user deposit on an external chain that is being relayed and voted on by Universal Validators, destined for `ExecuteInboundGas`).
2. Shortly before ballot finalization is expected to trigger `ExecuteInboundGas` (or within the same block, if achievable), attacker submits an ordinary large swap on the PRC20/WPC Uniswap V3 pool referenced by `UniversalCore.uniswapV3Quoter()`/`WPC()` to depress the PRC20→WPC price.
3. Ballot finalizes; `ExecuteInboundGas` calls `GetSwapQuote` which now returns the manipulated (low) quote, and `minPCOut = quote*95/100` is computed from that same depressed value [6](#0-5) .
4. `CallPRC20DepositAutoSwap` executes with the depressed `minPCOut`, succeeding and crediting the victim's UEA far less WPC than the pre-manipulation market price would have yielded [7](#0-6) .
5. Attacker reverses their initial swap, extracting the price difference as profit — net drain from the victim's deposit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
