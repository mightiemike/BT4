### Title
Wallet Contract `has_in_flight_tx` flag can become permanently stuck `true` if a promise callback fails after resetting the flag but before completing execution - ([File: runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs])

### Summary
The `near-wallet-contract` (the contract deployed on ETH-implicit accounts, per NEP-518) implements a multi-step promise/callback chain for `rlp_execute`, guarded by a `has_in_flight_tx` boolean that is meant to prevent overlapping in-flight transactions. This flag is set to `true` optimistically before a promise chain is scheduled and is only reset to `false` as the *first* statement inside each callback (`address_check_callback`, `nep_141_storage_balance_callback`, `rlp_execute_callback`, `ban_relayer`). Because NEAR only commits state changes from a `FunctionCall` action on *successful* completion of that action, if any of these callbacks fails to complete (e.g. runs out of the gas that was attached to it, or panics later in its body) after resetting the flag, the entire state transition of that receipt — including the flag reset — is discarded. This leaves `has_in_flight_tx = true` permanently, since `rlp_execute` unconditionally rejects new calls whenever the flag is set, and only the callbacks can ever clear it.

### Finding Description
The invariant documented on the struct is:
`has_in_flight_tx` must be `true` when a mutable method returns a promise and `false` otherwise. [1](#0-0) 

`rlp_execute` refuses any call while the flag is `true`: [2](#0-1) 

Each callback resets the flag as its *first* line, before doing any fallible work (JSON deserialization of an external contract's response, additional promise creation, or dispatching the user's original action): [3](#0-2) [4](#0-3) [5](#0-4) 

Callback gas budgets are computed once, at the moment the original promise chain is scheduled, from a fixed constant plus the user-declared `action.gas()`: [6](#0-5) [7](#0-6) 

Per NEAR runtime semantics, storage/state updates made during a `FunctionCall` action are only applied when the call succeeds: [8](#0-7) 

This is directly analogous to the reported "callbacks should be validated" issue: a hook (`rlp_execute`'s in-flight guard) is implemented on the assumption that a callback will always run to completion and clear the guard, but nothing in the protocol or contract guarantees that the specific callback invocation which sets `has_in_flight_tx = true` will ever successfully finish. If the callback branch is more expensive than the fixed static-gas budget accounts for (e.g., an external NEP-141 token or the address registrar returns an unusually large/expensive response, or the nested `action_to_promise`/`Promise::new(...).function_call(...).function_call(...)` chain triggers extra receipt-creation costs not covered by the reserved gas), the callback function itself can run out of gas or otherwise fail after the flag reset but before the receipt finishes — reverting the whole state change, including the reset.

### Impact Explanation
Once `has_in_flight_tx` gets stuck at `true` without a corresponding promise actually still in flight, `rlp_execute` will reject every future call with `"transaction already in progress"`, forever. There is no method exposed to manually clear the flag. This effectively and permanently freezes the ETH-implicit account: none of its NEAR balance, NEP-141 tokens, or contract permissions reachable only via `rlp_execute` can ever be moved or used again. This matches the allowed "permanently frozen funds" impact category, reachable purely from an ordinary `FunctionCall` transaction issued by any relayer/signer (no privileged or validator access required).

### Likelihood Explanation
This requires a specific gas-accounting edge case: the callback execution must fail (OOG or panic) strictly after the `has_in_flight_tx = false` line executes but the receipt as a whole must not succeed. This is plausible whenever the callback branch's actual cost (deserializing a large/malformed response from an external, possibly adversarial contract such as `address_registrar` or the NEP-141 `token_id`, or the cost of the additional nested promise/receipt creation in `nep_141_storage_balance_callback`) exceeds the fixed constants (`ADDRESS_CHECK_CALLBACK_GAS`, `NEP_141_STORAGE_BALANCE_CALLBACK_GAS`, `RLP_EXECUTE_CALLBACK_GAS`) reserved at scheduling time. Because these constants are fixed rather than derived from worst-case costs of arbitrary external contracts, and because target contracts (NEP-141 tokens, registrar) are not trusted/verified, a malicious or unusual external contract can be used to reliably trigger this. I was not able to fully verify from static inspection alone the exact numeric margin between the reserved static gas and worst-case execution cost of each callback body (this would require executing/profiling the compiled contract, which is outside the scope of this read-only analysis), so the precise reliability of triggering the OOG condition is uncertain and should be confirmed with targeted gas-profiling tests.

### Recommendation
- Make the "in-flight" guard resilient to partial callback failures: e.g., reset `has_in_flight_tx` using a mechanism that is not itself part of the same fallible execution (such as a dedicated, minimal-gas, always-succeeding cleanup step scheduled with `PromiseResult`-independent guaranteed gas), or use a timeout-based recovery path (analogous to `PromiseYieldTimeout`) that allows the flag to be cleared after a bounded number of blocks even if no callback ever completes.
- Reserve callback gas budgets based on the worst-case cost of every code path within the callback (including failure/deserialization branches and additional nested promise creation), not just the common-case cost, or reject external target contracts whose responses could blow the budget before scheduling the callback.
- Add an explicit escape hatch (e.g., a nonce/height-gated "force clear" of `has_in_flight_tx`) so a stuck account is not permanently unusable.

### Proof of Concept
Conceptual reproduction (requires gas-profiling to pick exact constants, not fully validated in this read-only review):
1. Deploy a NEP-141-like or address-registrar-like contract at the address `rlp_execute` will call, whose response is a large/oddly-shaped payload that is expensive to `serde_json::from_slice` inside `address_check_callback`/`nep_141_storage_balance_callback`, or that causes the callback's own additional `action_to_promise`/nested `Promise::new(...).function_call(...).function_call(...)` scheduling to exceed the gas remaining after the static budget (`ADDRESS_CHECK_CALLBACK_GAS` / `NEP_141_STORAGE_BALANCE_CALLBACK_GAS`) is consumed by the preceding external call.
2. Submit a normal, correctly-signed `rlp_execute` transaction from any account (no special privilege) targeting that contract, causing `has_in_flight_tx` to be set `true` [9](#0-8)  and the promise chain including one of the vulnerable callbacks to be scheduled [7](#0-6) .
3. When the callback executes, it resets the flag first [10](#0-9)  then runs out of gas or panics before the `FunctionCall` action completes; per NEAR semantics the whole state change (including the flag reset) is discarded [8](#0-7) .
4. Any subsequent `rlp_execute` call on this account now permanently fails with `"transaction already in progress"` [11](#0-10) , freezing the account.

    #[private]
    pub fn address_check_callback(
        &mut self,
        target: AccountId,
        action: near_action::Action,
        caller_deposit: Option<CallerDeposit>,
    ) -> PromiseOrValue<ExecuteResponse> {
        self.has_in_flight_tx = false;
        let maybe_account_id: Option<AccountId> = match env::promise_result(0) {
            PromiseResult::Failed => {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Call to Address Registrar contract failed".into()),
                });
            }
            PromiseResult::Successful(value) => match serde_json::from_slice(&value) {
                Ok(x) => x,
                Err(_) => {
                    return PromiseOrValue::Value(ExecuteResponse {
                        success: false,
                        success_value: None,
                        error: Some("Unexpected response from account registrar".into()),
                    });
                }
            },
        };
        let current_account_id = env::current_account_id();
        let promise = if maybe_account_id.is_some() {
            // We intentionally do not increment the nonce in this case because the
            // error is caused by a faulty relayer, not the user. An honest relayer
            // may still be able to successfully send the user's intended transaction.
            if env::signer_account_id() == current_account_id {
                create_ban_relayer_promise(current_account_id)
            } else {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Invalid target: target is address corresponding to existing named account_id".into()),
                });
            }
        } else {
            // We must increment the nonce at this point to prevent replay of the transaction.
            // Recall that the nonce was not incremented in `inner_rlp_execute` in the case that
            // the registrar contract was called (i.e. in the case we end up inside this callback).
            self.nonce = self.nonce.saturating_add(1);
            let ext =
                WalletContract::ext(current_account_id).with_static_gas(RLP_EXECUTE_CALLBACK_GAS);
            match action_to_promise(target, action)
                .map(|p| p.then(ext.rlp_execute_callback(caller_deposit)))
            {
                Ok(p) => p,
                Err(e) => {
                    return PromiseOrValue::Value(e.into());
                }
            }
        };
        self.has_in_flight_tx = true;
        PromiseOrValue::Promise(promise)
    }

                Ok(x) => x,

                        success_value: None,

                    });
                }
            },
        };
        let current_account_id = env::current_account_id();
        let ext = WalletContract::ext(current_account_id).with_static_gas(RLP_EXECUTE_CALLBACK_GAS);
        let promise = match maybe_storage_balance {
            Some(_) => {
                // receiver_id is registered so we can send the transfer
                // without additional actions. Note: in the standard NEP-141
                // implementation it is impossible to have `Some` storage balance,
                // but have it be insufficient to transact.
                match action_to_promise(token_id, action)
                    .map(|p| p.then(ext.rlp_execute_callback(caller_deposit)))
                {
                    Ok(p) => p,
                    Err(e) => {
                        return PromiseOrValue::Value(e.into());
                    }
                }
            }
            None => {
                // receiver_id is not registered so we must call `storage_deposit` first.
                let storage_deposit_args =
                    format!(r#"{{"account_id": "{receiver_id}"}}"#).into_bytes();
                let transfer_function_call = match action {
                    near_action::Action::FunctionCall(x) => x,
                    _ => {
                        return PromiseOrValue::Value(ExecuteResponse {
                            success: false,
                            success_value: None,
                            error: Some(
                                "Expected function call action to perform NEP-141 transfer".into(),
                            ),
                        });
                    }
                };
                Promise::new(token_id)
                    .function_call(
                        "storage_deposit".into(),
                        storage_deposit_args,
                        NEP_141_STORAGE_DEPOSIT_AMOUNT,
                        NEP_141_STORAGE_DEPOSIT_GAS,
                    )
                    .function_call(
                        transfer_function_call.method_name,
                        transfer_function_call.args,
                        transfer_function_call.deposit,
                        transfer_function_call.gas,
                    )
                    .then(ext.rlp_execute_callback(caller_deposit))
            }
        };
        self.has_in_flight_tx = true;
        PromiseOrValue::Promise(promise)
    }

    #[private]
    pub fn rlp_execute_callback(
        &mut self,
        caller_deposit: Option<CallerDeposit>,
    ) -> ExecuteResponse {
        self.has_in_flight_tx = false;
        let n = env::promise_results_count();

        if n == 0 {
            // `rlp_execute_callback` is called directly in the case of an emulated self-transfer.
            return ExecuteResponse { success: true, success_value: None, error: None };
        } else if n > 1 {
            return ExecuteResponse {
                success: false,
                success_value: None,
                error: Some(format!(
                    "Invariant violation: this callback comes after a single promise. n={n}"
                )),
            };
        }

        match env::promise_result(0) {
            PromiseResult::Failed => {
                // The cross-contract call failed, refund the caller if needed
                if let Some(CallerDeposit { account_id, yocto_near }) = caller_deposit {
                    let refund_promise = env::promise_batch_create(&account_id);
                    env::promise_batch_action_transfer(
                        refund_promise,
                        NearToken::from_yoctonear(yocto_near.into()),
                    );
                }

                ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Failed Near promise".into()),
                }
            }
            PromiseResult::Successful(value) => {
                ExecuteResponse { success: true, success_value: Some(value), error: None }
            }
        }
    }

    #[private]
    pub fn ban_relayer(&mut self) -> ExecuteResponse {
        self.has_in_flight_tx = false;
        ExecuteResponse {
            success: false,
            success_value: None,
            error: Some("Error: faulty relayer".into()),
        }
    }
