### Title
Starknet OS `execute_replace_class` omits the "class must be declared" check enforced by native Blockifier, causing execution divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/deprecated_execute_syscalls.cairo])

### Summary
The `replace_class` syscall lets any contract change the class (implementation) associated with its own storage address — this is the Starknet analog of a proxy contract's "upgrade" mechanism, the exact primitive abused in the USPD "CPIMP" incident where an attacker swapped in a malicious implementation. Native Blockifier (the sequencer's execution engine that actually decides which transactions succeed and what goes into the block) requires the target class hash to be a *declared* class before allowing the replacement. The Starknet OS (the Cairo re-execution engine used to prove/verify blocks) has the identical syscall implemented **without** that check, and the omission is explicitly marked by an unresolved TODO in the code.

### Finding Description
Native Blockifier's deprecated `replace_class` syscall handler explicitly reads the target class to ensure it is declared before mutating the caller's class hash: [1](#0-0) 

The corresponding Starknet OS Cairo implementations — both the deprecated syscall path and the modern syscall path — perform the state-entry class-hash overwrite unconditionally, with a comment acknowledging the missing validation: [2](#0-1) [3](#0-2) 

Note line 902 of `syscall_impls.cairo`: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` — confirming the check is known-missing and unresolved as of the reported incident window.

By contrast, the Rust `StateError::UndeclaredClassHash` guard exists precisely to prevent contracts from being pointed at non-existent/undeclared bytecode: [4](#0-3) 
and is exercised by existing Blockifier tests confirming the "is not declared" revert behavior for `replace_class`: [5](#0-4) 

### Impact Explanation
Any unprivileged contract deployer/caller can invoke `replace_class` with an undeclared class hash from a contract they control. Native Blockifier — the engine that determines the actual state transition included/committed in the block — will reject/revert this call because the class hash is not declared. But the Starknet OS, which re-executes the same transaction (used for proving and for OS-based re-execution/verification, exercised throughout `starknet_os_flow_tests` and `starknet_os`), will accept it unconditionally and commit the undeclared class hash into `contract_state_changes` for that contract. This produces two different outcomes (revert vs. success/state mutation) for the identical transaction between the two engines that are required to agree bit-for-bit on the resulting state diff/state commitment. This is an honest-node divergence / wrong committed state root class of bug: the OS's Patricia-tree state update for the affected contract will not match what Blockifier actually produced and what the block header commits to, undermining the guarantee that OS re-execution reproduces the sequencer's committed state, and can render blocks containing such a transaction unprovable or produce a mismatched committed root.

### Likelihood Explanation
High reachability: this requires nothing more than deploying/declaring a trivial contract that invokes `replace_class` (deprecated Cairo0 selector or the modern Cairo1 syscall) with an arbitrary undeclared class hash, then sending a single ordinary invoke transaction calling it. No special privileges, staking, or operator access are needed — it is reachable purely from an unprivileged transaction sender/contract deployer, matching the in-scope reachability criteria. The bug is also explicitly flagged as an open TODO in the code, confirming it is a known, currently-unaddressed gap rather than a speculative issue.

### Recommendation
Add the same "class must be declared" check that exists in native Blockifier's `replace_class` handler to both Starknet OS Cairo implementations (`execute_replace_class` in `deprecated_execute_syscalls.cairo` and in `syscall_impls.cairo`) before the `dict_update` that mutates the contract's state entry — i.e., verify the guessed `compiled_class_fact`/class declaration for `class_hash` exists in `contract_class_changes` prior to accepting the new state entry, mirroring the Rust `get_compiled_class` check, so both execution engines reject the same invalid `replace_class` calls identically.

### Proof of Concept
1. Deploy a Cairo0 (or Cairo1) contract whose entry point invokes the `REPLACE_CLASS` syscall with a `class_hash` value that has never been declared on-chain (e.g., a fresh, never-declared felt).
2. Submit an ordinary Invoke transaction calling that entry point.
3. Native Blockifier execution: `execute_deprecated_syscalls`/`syscall_base` path calls `state.get_compiled_class(request.class_hash)` (see `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:801`), which fails with `StateError::UndeclaredClassHash`, causing the call/transaction to revert — this is what actually gets committed to the block.
4. Starknet OS re-execution of the identical transaction: `execute_replace_class` (see `deprecated_execute_syscalls.cairo:307-329` / `syscall_impls.cairo:881-920`) performs no declared-class check and unconditionally updates the contract's state entry to the undeclared class hash — producing a state diff for this contract that disagrees with what Blockifier committed.
5. Comparing the two engines' outputs for the same transaction demonstrates the divergence (revert vs. successful class overwrite), which is the vulnerable behavior.

func execute_replace_class{contract_state_changes: DictAccess*, revert_log: RevertLogEntry*}(
    contract_address, syscall_ptr: ReplaceClass*

    alloc_locals;
    let class_hash = syscall_ptr.class_hash;

    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),

    );
    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}

        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.

        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

        key=contract_address,

        new_value=cast(new_state_entry, felt),
    );
