### Title
`check_microblock_header_signer` accepts malleated/duplicate signatures as proof of equivocation, enabling reward theft via `PoisonMicroblock` - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`check_microblock_header_signer` in `stackslib/src/chainstate/stacks/db/transactions.rs` only checks that `mblock_header_1.check_recover_pubkey()` and `mblock_header_2.check_recover_pubkey()` yield the same `Hash160`, and never checks that the two headers actually differ in the fields that would prove double-signing (`tx_merkle_root`/`prev_block`). Because `check_recover_pubkey()` uses `recover_to_pubkey_without_validating_low_s`, an attacker who observes a single honestly-signed microblock header can trivially produce a second, still-recoverable signature over the *same* digest (ECDSA malleability: flipping `s -> n-s` and the recovery id), yielding two "headers" that recover to the same `pubkh` without the miner ever equivocating.

### Finding Description
The function's contract is "were these two headers signed by the same key?" — it does not verify that the headers represent conflicting microblocks (different `tx_merkle_root` or content) at the claimed sequence: [1](#0-0) 

`check_recover_pubkey()` explicitly skips low-S validation, so a malleated signature (same digest, different `(r,s,v)` encoding) is accepted as valid and recovers to the identical `Hash160`: [2](#0-1) [3](#0-2) 

`handle_poison_microblock` calls `check_microblock_header_signer`, then immediately looks up `mblock_pubk_height` and slashes/reports the miner keyed only by `pubkh`, using `mblock_header_1.sequence` for the report, with no check that `mblock_header_1` and `mblock_header_2` actually differ in `tx_merkle_root`/`prev_block`: [4](#0-3) [5](#0-4) 

Separately, the only place that checks header equivalence (`sequence`, `prev_block`, `version`) is the mempool admission path, which — notably — also never requires `tx_merkle_root` to differ, so even byte-identical headers with differently-encoded (malleated) signatures pass: [6](#0-5) 

The equality the code should enforce — "a slashed miner `pubkh` == a miner who actually produced two microblocks with distinct content at the same sequence" — is broken, because the code only enforces "the two supplied signatures recover to the same key," which is trivially satisfiable via signature malleability on a single legitimately observed signature, with no attacker private-key knowledge required.

### Impact Explanation
This lets an unprivileged attacker frame any miner whose microblock `pubkh` was registered within `MINER_REWARD_MATURITY` blocks of the current tip, causing that miner's coinbase to be treated as poisoned/slashed and the reporter (attacker) to be recorded as entitled to the commission — i.e., reward theft/redirection from an innocent, honest miner. This is a reward-loss/misappropriation bug matching the Critical category (reward theft from a matured coinbase) since it can strip an honest, non-equivocating miner of their reward using only public information (one broadcast signature) and no stake or privileged role.

### Likelihood Explanation
Preconditions are met continuously in normal operation: any miner who has produced at least one microblock has a `pubkh` recorded via `insert_microblock_pubkey_hash`, and the exploit window is any time before `MINER_REWARD_MATURITY` elapses (the standard maturity window, not an unusual edge case). The attack requires no BTC spend, no stake, and no privileged role — only broadcasting a single crafted `PoisonMicroblock` transaction with a malleated signature derived from a public, already-observed microblock header. It is trivially repeatable against every actively mining miner.

### Recommendation
`check_microblock_header_signer` (and/or `handle_poison_microblock`) must additionally verify that the two headers represent genuinely conflicting microblocks at the same sequence — e.g., require `mblock_header_1.sequence == mblock_header_2.sequence`, `mblock_header_1.prev_block == mblock_header_2.prev_block`, and that they differ in `tx_merkle_root` (or otherwise are not merely two different signature encodings of the same message). Additionally, `check_recover_pubkey` should enforce low-S normalization (reject malleated high-S signatures) to close the malleability vector entirely.

### Proof of Concept
Rust integration test plan:
1. Generate a miner key, sign a legitimate `StacksMicroblockHeader` `h1` (sequence `N`, some `tx_merkle_root`), and register its `pubkh` via the normal microblock-processing path so `get_microblock_pubkey_hash_height` returns `Some(height)`.
2. Construct `h2` as a byte-for-byte copy of `h1`'s header fields (`version`, `sequence`, `prev_block`, `tx_merkle_root`), but derive `h2.signature` by malleating `h1.signature`: parse `(r, s, rec_id)`, compute `s' = n - s`, flip `rec_id` accordingly to keep it a valid recoverable signature over the same digest.
3. Call `StacksChainState::check_microblock_header_signer(&h1, &h2)` and assert it returns `Ok(pubkh)` even though `h1.tx_merkle_root == h2.tx_merkle_root` (no real conflict).
4. Call `handle_poison_microblock` (or the full transaction-processing path with a `TransactionPayload::PoisonMicroblock(h1, h2)`) from an attacker-controlled sender principal, and assert it succeeds, inserting a poison report and crediting the attacker as reporter — asserting the broken equality: "slashed miner `pubkh`" equals "miner who never equivocated" (`h1.tx_merkle_root == h2.tx_merkle_root` and `h1.prev_block == h2.prev_block`), which should have caused rejection instead.

    /// Given two microblock headers, were they signed by the same key?
    /// Return the pubkey hash if so; return Err otherwise
    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }

    pub fn check_recover_pubkey(&self) -> Result<Hash160, AuthError> {
        let mut bytes = vec![];
        self.serialize(&mut bytes, true)
            .expect("BUG: failed to serialize to a vec");
        let digest = Sha512Trunc256Sum::from_data(&bytes[..]);

        let mut pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            digest.as_bytes(),
            &self.signature,
        )
        .map_err(|_ve| {
            AuthError::VerifyingError(
                "Failed to verify signature: failed to recover public key".to_string(),
            )
        })?;

        pubk.set_compressed(true);
        Ok(Hash160::from_node_public_key(&pubk))
    }
