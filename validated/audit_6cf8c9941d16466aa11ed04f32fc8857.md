### Title
Unbounded Growth of the Exchange/Asset-Issue Stores Enables Anonymous-API DoS via Full-Table Iteration - (File: framework/src/main/java/org/tron/core/Wallet.java)

### Summary
Any unprivileged account can create an unlimited number of `Exchange` (and `AssetIssue`) records on-chain by broadcasting `ExchangeCreateContract`/`AssetIssueContract` transactions, since there is no cap on the total count of exchanges/assets that can exist. The un-paginated `ListExchanges`/`GetAssetIssueList` RPC and HTTP endpoints then iterate the *entire* underlying store on every anonymous call, which is directly analogous to the reported "list can endlessly grow" bug class: an attacker-controlled, ever-growing list that is fully scanned in a single call/transaction.

### Finding Description
`ExchangeCreateActuator.doValidate()`/`execute()` allows any account with sufficient balance to create a new exchange; there is no limit on the total number of exchanges that can be created system-wide, only a per-account balance/fee check [1](#0-0) . Each successful call increments `LatestExchangeNum` and persists a new record into `ExchangeStore`/`ExchangeV2Store` [2](#0-1) .

`ExchangeStore.getAllExchanges()` iterates every entry in the store with no bound [3](#0-2) . `Wallet.getExchangeList()` calls this unbounded getter and builds a response containing every exchange ever created [4](#0-3) . This is exposed to anonymous callers via:
- the `ListExchanges` gRPC method [5](#0-4) 
- the `/wallet/listexchanges` HTTP servlet, which has no offset/limit parameters, unlike the paginated variant [6](#0-5) 

The same pattern exists for assets: `AssetIssueActuator` lets any account (once) create a new `AssetIssueContract` [7](#0-6) , and `Wallet.getAssetIssueList()` (backing `GetAssetIssueList`/`GetAssetIssueListServlet`) iterates `getAllAssetIssues()` over the full, unbounded asset store on every call [8](#0-7) .

While java-tron does provide paginated alternatives (`GetPaginatedExchangeList`, `GetPaginatedAssetIssueList`) [9](#0-8) , the non-paginated `ListExchanges`/`GetAssetIssueList` endpoints remain reachable by any anonymous RPC/HTTP client and their cost is proportional to the total number of exchanges/assets ever created — a quantity that grows without limit as long as accounts keep paying the creation fee, exactly mirroring the reported bug class of an ever-growing list with no removal mechanism that gets fully iterated.

### Impact Explanation
As the number of exchanges/assets grows (each requiring only a modest, fixed TRX fee), repeated calls to `ListExchanges`/`GetAssetIssueList` become increasingly expensive in CPU, memory, and network bandwidth for the full node serving them. Because the endpoints require no privileged credentials, an attacker can (a) inflate the store size cheaply over time by broadcasting many `ExchangeCreateContract`/`AssetIssueContract` transactions, and (b) then repeatedly hit the non-paginated list endpoints to degrade or exhaust node resources (DoS) for other API consumers, since each call fully serializes the entire store into a single gRPC/HTTP response.

### Likelihood Explanation
Likelihood is moderate: creating exchanges/assets costs a configurable but bounded TRX fee (`ExchangeCreateFee`, `AssetIssueFee`), so an attacker with sufficient funds can grow the list over time without needing any privileged role. The list-all endpoints are unauthenticated and rate-limited only generically (`RateLimiterServlet`), not by response size, so the exploitation path is straightforward once the underlying store is large.

### Recommendation
- Deprecate/remove or hard-cap the non-paginated `ListExchanges` and `GetAssetIssueList` RPC/HTTP endpoints (`Wallet.getExchangeList()`, `Wallet.getAssetIssueList()`), forcing clients to use the already-existing paginated equivalents with an enforced maximum page size.
- Alternatively, add an internal maximum result size/timeout to `ExchangeStore.getAllExchanges()`/asset store equivalents so a single anonymous request cannot force a full-store scan and serialization.
- Consider imposing an increasing creation fee or a global cap to slow unbounded growth of the exchange/asset lists.

### Proof of Concept
1. Repeatedly broadcast `ExchangeCreateContract` transactions from one or more funded accounts to inflate `ExchangeStore`/`ExchangeV2Store` to a very large size (each call only needs to satisfy the balance/fee checks in `ExchangeCreateActuator.doValidate()`).
2. Once the store is large, call the anonymous HTTP endpoint `POST /wallet/listexchanges` (or gRPC `ListExchanges`) repeatedly; each call triggers `ExchangeStore.getAllExchanges()`, iterating and serializing the entire store, consuming disproportionate CPU/memory/bandwidth on the serving node compared to the paginated `GetPaginatedExchangeList` alternative.
3. Repeat with `AssetIssueContract`/`GetAssetIssueList` for the equivalent effect on the asset-issue store.

  private boolean doValidate() throws ContractValidateException {
    if (this.any == null) {
      throw new ContractValidateException(ActuatorConstant.CONTRACT_NOT_EXIST);
    }
    if (chainBaseManager == null) {
      throw new ContractValidateException(ActuatorConstant.STORE_NOT_EXIST);
    }
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (!this.any.is(ExchangeCreateContract.class)) {
      throw new ContractValidateException(
          "contract type error,expected type [ExchangeCreateContract],real type[" + any
              .getClass() + "]");
    }
    final ExchangeCreateContract contract;
    try {
      contract = this.any.unpack(ExchangeCreateContract.class);
    } catch (InvalidProtocolBufferException e) {
      throw new ContractValidateException(e.getMessage());
    }

    byte[] ownerAddress = contract.getOwnerAddress().toByteArray();
    String readableOwnerAddress = StringUtil.createReadableString(ownerAddress);

    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid address");
    }

    if (!accountStore.has(ownerAddress)) {
      throw new ContractValidateException("account[" + readableOwnerAddress + NOT_EXIST_STR);
    }

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    if (accountCapsule.getBalance() < calcFee()) {
      throw new ContractValidateException("No enough balance for exchange create fee!");
    }

  public ExchangeList getPaginatedExchangeList(long offset, long limit) {
    if (limit < 0 || offset < 0) {
      return null;
    }

    long latestExchangeNum = chainBaseManager.getDynamicPropertiesStore()
        .getLatestExchangeNum();
    if (latestExchangeNum <= offset) {
      return null;
    }
    limit =
        limit > EXCHANGE_COUNT_LIMIT_MAX ? EXCHANGE_COUNT_LIMIT_MAX : limit;
    long end = offset + limit;
    end = end > latestExchangeNum ? latestExchangeNum : end;

    ExchangeList.Builder builder = ExchangeList.newBuilder();
    ImmutableList<Long> rangeList = ContiguousSet
        .create(Range.openClosed(offset, end), DiscreteDomain.longs())
        .asList();
    rangeList.stream().map(ExchangeCapsule::calculateDbKey).map(key -> {
      try {
        return getExchangeStoreFinal(chainBaseManager.getDynamicPropertiesStore(),
            chainBaseManager.getExchangeStore(),
            chainBaseManager.getExchangeV2Store()).get(key);
      } catch (Exception ex) {
        return null;
      }
    }).filter(Objects::nonNull)
        .forEach(exchangeCapsule -> builder
            .addExchanges(exchangeCapsule.getInstance()));
    return builder.build();

  }
