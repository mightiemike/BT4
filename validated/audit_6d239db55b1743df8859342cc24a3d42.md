## Missing declared-class validation in Starknet OS `replace_class` syscall allows sequencer/OS state divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Mattermost CVE describes an authorization endpoint that fails to re-validate a security-relevant precondition (target channel's current team) before performing a state-mutating action, letting a scoped admin act outside their authorized scope. The closest reachable analog in this sequencer is in the Starknet OS's Cairo implementation of the `replace_class` syscall: the OS never re-validates that the class hash being written is actually a declared class, even though the Rust/blockifier execution path (used by the sequencer to build blocks) enforces this check. This creates a state-transition rule that is enforced on one path (blockifier) but not the other (Starknet OS re-execution), a precondition-validation gap directly analogous to the reported bug class.

### Finding Description
Any Cairo1 contract can invoke the `replace_class` syscall to change its own class hash. In the blockifier (used by the sequencer/batcher when actually executing transactions and building blocks), this is guarded: [1](#0-0) 

which calls `self.state.get_compiled_class(class_hash)?` — this returns `StateError::UndeclaredClassHash` and reverts the transaction if the class was never declared.

However, in the Starknet OS Cairo program — which independently re-executes the block to produce the STARK proof of the block's state transition — the equivalent `execute_replace_class` function performs no such check. The code contains an explicit acknowledgment of the missing validation: [2](#0-1) 

Note line 902: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The function reads the current `StateEntry` via the `GetContractAddressStateEntry` hint and unconditionally overwrites `class_hash` in the contract's state entry, updating `contract_state_changes` without ever consulting `contract_class_changes` to confirm the target `class_hash` was declared.

The legacy/deprecated syscall path exhibits the identical gap: [3](#0-2) 

By contrast, the deprecated (Cairo0) blockifier syscall handler does perform the check: [4](#0-3) 

This means the "declared class" precondition — a scope/authorization-like invariant restricting which class hashes a contract may adopt — is validated by the component that decides which transactions are included/reverted in a block (blockifier), but is not re-validated by the component that proves the block's correctness (Starknet OS). This is structurally the same class of bug as the reported CVE: a precondition checked at one point in the system is not re-checked at the point where the actual state-mutating action is committed.

### Impact Explanation
If a transaction performs `replace_class` with an undeclared class hash:
- The blockifier (sequencer execution) raises `StateError::UndeclaredClassHash` and the transaction reverts, producing a specific state diff (fee charged, no class-hash change) as part of the committed block.
- The Starknet OS, when re-executing the same block to generate the proof, will not detect this condition and will instead write the new (undeclared) class hash into `contract_state_changes` unconditionally, non-reverting.

This produces a **state root / execution divergence between the sequencer's block and the OS-generated proof of that block**. Since the OS's output feeds directly into the committed state commitment and block hash, this divergence can result in an incorrect committed state root, breaking the invariant that the OS faithfully reproduces the block-execution result, and potentially leading to inability to correctly prove/verify blocks or acceptance of an incorrect state commitment. It also means a contract can silently "adopt" a still-undeclared class hash in the OS's view of state without the fee-charging/error-handling behavior of blockifier, causing honest divergence between the two normally-equivalent execution engines.

### Likelihood Explanation
Reaching this path requires only a standard Cairo1 contract invoking `replace_class` with an arbitrary (undeclared) class hash — no special privileges, no admin capability, and no race condition beyond simply submitting a transaction. Because the vulnerable code is explicitly marked with a "TODO" acknowledging the missing check, the condition is deterministic and trivially triggerable by any transaction sender able to call a contract that executes `replace_class`.

### Recommendation
Add a declared-class check in `execute_replace_class` in both `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring the blockifier's behavior: before writing the new `class_hash` into `contract_state_changes`, verify (via `contract_class_changes`/the declared-classes dictionary) that the target class hash has been declared, and revert/fail the syscall consistently with blockifier's `UndeclaredClassHash` handling if not.

### Proof of Concept
1. Deploy any Cairo1 account/contract exposing a function that calls the `replace_class` syscall with a caller-supplied `class_hash` (e.g. the existing `test_replace_class` test entry point used in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
2. Submit a transaction invoking that function with an arbitrary, never-declared `class_hash`.
3. Under blockifier/sequencer execution, the transaction reverts with `StateError::UndeclaredClassHash` (see `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`, `undeclared_class_hash` test) — this is the state committed in the block.
4. Under the Starknet OS re-execution (`execute_replace_class` in `syscall_impls.cairo`), the same undeclared `class_hash` is written into `contract_state_changes` without any validation, since no check exists at line 902's TODO, producing a differing state transition for the OS proof versus the blockifier-committed block.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
