## Title
Deposit auto-swap slippage protection derived from a manipulable single-block spot quote (no TWAP / independent price reference) - (File: `x/uexecutor/keeper/evm.go`)

### Summary
Push Chain's `GAS` and `GAS_AND_PAYLOAD` inbound execution routes swap a user's minted PRC20 for native `PC` (via `depositPRC20WithAutoSwap`) using a `minPCOut` slippage bound that is itself derived from the very same manipulable spot price it is meant to protect against. This is the same root-cause class as the reported `_getLastPrice` bug (an external price input consumed without freshness/manipulation-resistance checks) — except the manipulable source here is an on-chain Uniswap V3 `QuoterV2` spot quote rather than a Chainlink feed, and the vulnerable value is `minPCOut` guarding user deposit funds rather than an oracle price.

### Finding Description
`Keeper.GetSwapQuote` ( [1](#0-0) ) calls `QuoterV2.quoteExactInputSingle` with `commit=false` to obtain the current spot output amount for a `prc20 → wpc` swap. This is a single point-in-time AMM quote, not a TWAP or externally validated price.

Both `ExecuteInboundGas` and `gasAndPayloadDepositAutoSwap` then compute the slippage floor directly from this same spot quote: [2](#0-1) [3](#0-2) 

```go
// 5% slippage: minPCOut = quote * 95 / 100
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
receipt, execErr = k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
```

Because `quote` and `minPCOut` are both computed from the pool's *current* state at the moment the module executes the swap, an attacker who moves the pool's spot price beforehand (a large swap in the `prc20/wpc` Uniswap V3 pool) causes `GetSwapQuote` to return an already-depressed value. The "5% slippage protection" therefore only bounds movement *after* the manipulated read — it provides zero protection against the price having been pushed down *before* the read, since there is no independent reference price (no TWAP oracle, no `ChainMeta`-style external price feed) to detect the discrepancy. This mirrors the reported bug class exactly: a price input is consumed by security-critical logic (a fund-affecting minimum-output guard) without validating it against staleness/manipulation.

The same pattern also appears in the gas-refund swap path, `applyGasRefund`: [4](#0-3) 

### Impact Explanation
An unprivileged attacker who can trade against the protocol's `prc20/wpc` pool can extract value from every honest user's `GAS`/`GAS_AND_PAYLOAD` inbound deposit that gets routed through `CallPRC20DepositAutoSwap`, and from gas refunds routed through `CallUniversalCoreRefundUnusedGas` with `withSwap=true`. This directly reduces user-controlled PC output on deposit (partial loss/drain of user funds during the automated swap), matching the in-scope impact of "corruption of ... gas fee accounting, refund accounting ... token mapping" and "draining ... of user or protocol-controlled funds" via the universal execution deposit path.

### Likelihood Explanation
Likelihood depends on the pool's liquidity depth and the attacker's ability to time a manipulating trade close to the module's swap execution (which happens once an inbound's votes finalize, a predictable, publicly observable on-chain event on Push Chain itself). Since Push Chain trading on its own system-deployed AMM is presumably permissionless, and the swap execution is not shielded from same-block ordering effects, an attacker able to submit transactions ahead of finalization-triggered swaps (or simply during periods of low liquidity) can realize this without any privileged access.

### Recommendation
Do not derive the slippage floor solely from the same at-execution spot quote. Use a manipulation-resistant reference — e.g., a time-weighted average price (TWAP) from the Uniswap V3 pool's observation window, or bound `minPCOut` against an independently maintained reference price (analogous to `ChainMeta`'s staleness/median-vote design already used for gas price), and/or cap maximum acceptable deviation between the spot quote and the TWAP before allowing the swap to proceed.

### Proof of Concept
1. Attacker observes a pending inbound (`GAS`/`GAS_AND_PAYLOAD`) about to reach vote finality on `x/uexecutor`.
2. Immediately before/alongside the module's finalization-triggered EVM execution, attacker submits a large swap into the `prc20/wpc` Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetSwapQuote`, depressing the pool's spot price for `prc20 → wpc`.
3. `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502`) returns the depressed `quote`; `minPCOut = quote * 95/100` inherits the manipulated depression.
4. `CallPRC20DepositAutoSwap` executes the module's swap against this manipulated price, and the user's UEA receives fewer `PC` tokens than a fair-price swap would have produced — the difference is captured by the attacker's pool position (classic AMM sandwich, enabled here because the "slippage guard" isn't anchored to any manipulation-resistant reference).

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
```
