### Title
Fixed 300-second chain-meta vote staleness window is not scaled to each chain's own oracle cadence, corrupting gas-price/height medians used for refund and swap accounting - (File: `x/uexecutor/keeper/chain_meta.go`)

### Summary
`VoteChainMeta` filters votes into the median calculation using a single hardcoded constant, `chainMetaVoteStalenessSeconds = 300`, applied identically to every chain, regardless of how frequently that specific chain's own `ChainMetaOracle` actually refreshes its data. [1](#0-0) 
This is the direct on-chain analog of the reported Chainlink issue: instead of a per-feed heartbeat, one global timeout constant is used to decide whether observed data is still "fresh," even though different chains configure very different actual update intervals via `ChainConfig.GasOracleFetchInterval` (as low as 10s in tests, or minutes/hours for others). [2](#0-1) [3](#0-2) 

### Finding Description
Each Universal Validator independently runs a `ChainMetaOracle` per chain that polls gas price/block height on its own configurable interval (`gasPriceIntervalSeconds`, sourced from `ChainConfig.GasOracleFetchInterval`) and submits `VoteChainMeta` transactions. [4](#0-3) 
On-chain, `VoteChainMeta` stores each validator's vote with a `storedAt` timestamp and, when computing the median that drives the actual `UniversalCore` gas-price/chain-height oracle write, only excludes votes older than the single fixed `chainMetaVoteStalenessSeconds` (300s) constant — it does not consult the chain's own configured fetch interval at all: [5](#0-4) 

Because this constant is chain-agnostic, exactly like Chainlink's `RESPONSE_TIMEOUT`, it produces the same class of defect described in the report: for chains whose true observation cadence is faster than the fixed window, a 5-minute-old vote is still accepted as "fresh" and mixed into the median together with much newer votes, even though market conditions (gas price) may have already moved materially in that time. Conversely, for chains that legitimately need more time between honest updates, the same fixed window can cause fewer than the minimum quorum (`chainMetaMinVotesForFirstWrite = 3`) of votes to ever be simultaneously "fresh," since older-but-still-legitimate votes get dropped from the pool before a validator's next honest update arrives. [6](#0-5) 

This oracle value is not cosmetic — `GetGasPriceByChain` reads the resulting on-chain median directly and it feeds into value-affecting flows: the excess-gas-fee refund computation on outbound finalization and the Uniswap V3 QuoterV2-based `minPCOut` slippage bound used on `GAS`/`GAS_AND_PAYLOAD` inbound routes, both documented in the chain-meta upgrade handler. [7](#0-6) [8](#0-7) 

### Impact Explanation
With every validator behaving honestly, the aggregation logic itself allows stale-relative-to-cadence data into the price median because staleness is judged against a fixed global constant instead of each chain's actual observation frequency. For a fast-updating/volatile chain, this can bias the median gas price/chain height toward outdated values for up to five minutes, which propagates into: (1) the automatic gas fee refund paid back to users/fund recipients after an outbound observation, and (2) the minimum-output slippage bound computed for auto-swap deposits. Either can cause users to receive an incorrect (over- or under-) refund amount, or have their deposit swap execute against a stale price bound — a corruption of gas-fee/refund accounting reachable purely from ordinary user deposit/outbound flows, with no malicious validator or privileged actor required, matching the in-scope "corruption of ... gas fee accounting, refund accounting" impact.

### Likelihood Explanation
The staleness window is a compile-time constant with no per-chain override, so this triggers deterministically whenever a chain's configured fetch interval diverges materially from the fixed 300-second window — a condition governed only by ordinary `ChainConfig` values and normal validator timers, not by any adversarial input. This makes the flawed convergence path reachable in every normal operating cycle for a chain whose cadence differs from the assumption baked into the constant.

### Recommendation
Replace the single `chainMetaVoteStalenessSeconds` constant with a per-chain value derived from `ChainConfig.GasOracleFetchInterval` (e.g., some multiple of the configured fetch interval), so the freshness window scales with each chain's actual data-update cadence instead of using one global assumption for all chains, mirroring the report's recommendation to store the timeout per oracle rather than as a shared constant.

### Proof of Concept
1. Configure chain `eip155:X` with a short `GasOracleFetchInterval` (e.g., 10s), so validators legitimately refresh gas price roughly every 10 seconds.
2. Three honest validators vote at `t=0` with the true market price; the oracle bootstraps and writes the median.
3. Market gas price genuinely spikes at `t=60`. Only validator A has since re-polled and re-voted (per its 10s interval) with the new higher price; validators B and C's `t=0` votes are still within the fixed 300s window and remain classified as "fresh."
4. `VoteChainMeta`'s median computation at `t=60` still includes B and C's stale `t=0` votes alongside A's fresh vote, producing a median that does not reflect the actual current price for this fast-cadence chain — as shown by the existing staleness test only exercising the 300s boundary itself, not chain-specific cadence. [9](#0-8) 
5. This skewed median is then read via `GetGasPriceByChain`/`ChainMeta` for refund and swap-slippage computations, causing an incorrect fund-affecting outcome despite fully honest validator behavior.

	// chainMetaVoteStalenessSeconds is the maximum age (in seconds) of a stored vote
	// that is still eligible to be included in the median calculation.
	chainMetaVoteStalenessSeconds uint64 = 300

	// len/2 = 1) is the middle value, which is robust against a single
	// outlier on either side. After bootstrap (LastAppliedChainHeight > 0),
	// the normal median-on-each-fresh-vote behaviour applies.
	chainMetaMinVotesForFirstWrite int = 3

// fetchAndVoteChainMeta periodically fetches gas price and votes on it
func (g *ChainMetaOracle) fetchAndVoteChainMeta(ctx context.Context) {
	defer g.wg.Done()

	// Get gas oracle fetch interval from config
	interval := g.getChainMetaOracleFetchInterval()
	if interval <= 0 {
		interval = 30 * time.Second
	}

	ticker := time.NewTicker(interval)
	defer ticker.Stop()

	g.logger.Debug().
		Dur("interval", interval).
		Msg("starting gas price fetching and voting")

	for {
		select {
		case <-ctx.Done():
			g.logger.Debug().Msg("context cancelled, stopping gas price fetcher")
			return
		case <-g.stopCh:
			g.logger.Debug().Msg("stop signal received, stopping gas price fetcher")
			return
		case <-ticker.C:
			// Fetch current gas price
			gasPrice, err := g.rpcClient.GetGasPrice(ctx)
			if err != nil {
				g.logger.Error().Err(err).Msg("failed to fetch gas price")
				continue
			}

			// Log the gas price
			g.logger.Debug().
				Str("chain", g.chainID).
				Str("gas_price", gasPrice.String()).
				Msg("fetched gas price")

			// Get current block number
			blockNumber, err := g.rpcClient.GetLatestBlock(ctx)
			if err != nil {
				g.logger.Error().Err(err).Msg("failed to get latest block number")
				continue
			}

			// Apply markup to gas price to handle spikes
			if g.gasPriceMarkupPercent > 0 {
				markup := new(big.Int).Mul(gasPrice, big.NewInt(int64(g.gasPriceMarkupPercent)))
				markup.Div(markup, big.NewInt(100))

			// Vote on chain meta (gas price + block height)

// GetGasPriceByChain reads the gas price for a chain from the UniversalCore contract.
func (k Keeper) GetGasPriceByChain(ctx sdk.Context, chainNamespace string) (*big.Int, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, abi, ueModuleAccAddress, handlerAddr, false, nil, "gasPriceByChainNamespace", chainNamespace)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call gasPriceByChainNamespace")
	}

	results, err := abi.Methods["gasPriceByChainNamespace"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack gasPriceByChainNamespace result")
	}

	return results[0].(*big.Int), nil
}
