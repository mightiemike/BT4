### Title
Missing declared-class validation in Starknet OS `execute_replace_class` allows state-root divergence from Blockifier execution - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall unconditionally writes the requested `class_hash` into the contract's state entry without validating that the class hash corresponds to a previously declared contract class. The Blockifier (the execution engine used by the sequencer to build and execute blocks) enforces this check and reverts the transaction if the class is undeclared. This mismatch between the two execution engines is analogous to the reported `replacePool()` bug, where the "old"/target value's validity was never checked before the state-mutating replacement was performed, allowing the check enforced elsewhere in the system to be bypassed.

### Finding Description
In the Blockifier, `replace_class` explicitly requires the target class to be declared before mutating state: [1](#0-0) 

and Cairo1 native/VM syscall execution routes through the same base validation (`self.base.replace_class(...)`, which reads the compiled class and errors with `UndeclaredClassHash` if it doesn't exist), which is exercised by the negative-flow test explicitly checking that an undeclared class hash is rejected with "is not declared": [2](#0-1) 

In contrast, the Starknet OS's Cairo implementation of the same syscall performs no such check — the TODO comment on line 902 explicitly acknowledges the missing validation, and the state entry's `class_hash` is overwritten directly from the syscall request: [3](#0-2) 

The deprecated (Cairo0) syscall path in the OS has the identical gap: [4](#0-3) 

This mirrors the reported Vader bug class: a state-mutating "replace" operation is performed without validating that the target of the replacement satisfies the invariant (`oldToken` curated / `class_hash` declared) that is enforced elsewhere in the system (`curatePool()` / Blockifier's `replace_class`), allowing that invariant to be silently bypassed through the alternate code path.

### Impact Explanation
The Starknet OS is the re-execution engine responsible for computing the state diff/root that is proven and ultimately verified on L1. If a transaction invokes `replace_class` with an undeclared class hash, the Blockifier (used by the sequencer to build/validate the block) will revert that transaction (state changes rolled back, only fee charged), matching the expected `UndeclaredClassHash` error semantics. Because the OS does not perform the equivalent check, when the OS re-executes the same transaction it will not revert — it will unconditionally apply the class-hash change to `contract_state_changes`. This produces a different state diff (and consequently a different computed state root) than the one the sequencer actually committed, i.e., a genuine committed-root mismatch / honest-node divergence between the online execution (Blockifier) and the OS's re-execution used for proving.

### Likelihood Explanation
Any contract can invoke the `replace_class` syscall from ordinary contract code with an attacker-chosen (including undeclared) `class_hash`. No special privileges are required beyond deploying/invoking a contract that calls this syscall — a standard, unprivileged transaction path.

### Recommendation
Add an explicit "class is declared" check in the OS's `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) before mutating `contract_state_changes`, mirroring the Blockifier's `get_compiled_class`/`UndeclaredClassHash` check, and revert (as `CHANGE_CLASS_ENTRY`/entry-point failure) when the class hash is not declared, so that the OS's execution semantics remain consistent with the Blockifier's for all inputs.

### Proof of Concept
1. Deploy a contract that calls the `replace_class` syscall with an arbitrary, never-declared `class_hash` (as done in the Blockifier test `undeclared_class_hash` at `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
2. In the Blockifier/sequencer, this transaction execution reverts with `UndeclaredClassHash` — no class-hash state change is persisted (only fee is charged).
3. When the Starknet OS re-executes the identical block/transaction via `execute_replace_class` in `syscall_impls.cairo`, no declared-class check exists, so the OS unconditionally writes the new (undeclared) `class_hash` into `contract_state_changes`, producing a state diff differing from the one the sequencer actually committed for that block.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
