### Title
All-or-nothing ancient-slot squashing repeatedly discards completed shrink work when multi-ref accounts can't be packed - ([File: accounts-db/src/ancient_append_vecs.rs])

### Summary
The external report describes a griefing pattern: a batch operation performs substantial work on multiple sub-items, but a single failing item causes the whole batch to be aborted atomically, wasting all the work already done (`handleOps`/`multiSend`, all-or-nothing revert). The analogous pattern in `agave` exists in `AccountsDb::combine_ancient_slots_packed_internal`, which is called periodically by `AccountsBackgroundService` via `shrink_ancient_slots` and is reachable simply by any unprivileged user creating enough accounts/transactions to shape the ancient-slot population.

### Finding Description
`combine_ancient_slots_packed_internal` [1](#0-0)  performs, in order:
1. `collect_sort_filter_ancient_slots` — scans and sorts candidate ancient slots.
2. `get_unique_accounts_from_storage_for_combining_ancient_slots` — reads every account from every candidate ancient storage into memory [2](#0-1) .
3. `calc_accounts_to_combine` — looks up every account's refcount in the accounts index and partitions accounts into single-ref vs. multi-ref groups (`shrink_collect` per storage) [3](#0-2) .
4. `PackedAncientStorage::pack` — computes a full packing plan for all "single-ref" and "movable multi-ref" accounts.

Only *after* all this work is `many_ref_accounts_can_be_moved` checked; if it returns `false` (multi-ref accounts exist whose current slot is higher than the highest available target slot), the function returns immediately, discarding steps 2–4 entirely [4](#0-3) . The same all-or-nothing discard happens again after packing, if `pack.len() > accounts_to_combine.target_slots_sorted.len()` [5](#0-4) . In both cases none of the computed state is memoized or excluded from consideration in the next call — `best_ancient_slots_to_shrink` is the only thing preserved and it's unrelated to the packing failure.

This is invoked from `shrink_ancient_slots`, which `AccountsBackgroundService`'s main loop calls essentially every time `should_clean` is true (interval based) [6](#0-5) , and it recomputes the same candidate slot set (`get_sorted_potential_ancient_slots`) each time [7](#0-6) . If an attacker (any unprivileged user) can arrange for a set of pubkeys to have multiple rooted, un-cleaned versions ("many refs") that live in slots newer than the pool of "ancient" target slots that would need to receive them, `many_ref_accounts_can_be_moved` will keep returning `false` on every periodic invocation, forcing the validator to repeat the full "scan all ancient storages + read all account data + refcount-scan the index + build packing plan" computation over and over with zero forward progress, for as long as that account layout persists.

### Impact Explanation
This is a disproportionate, repeated CPU/I-O cost analog to the `handleOps`/`multiSend` griefing pattern: expensive work is fully performed and then thrown away atomically because of one blocking condition, and the triggering condition is not resolved or excluded from the next attempt, so the waste repeats indefinitely on the validator's background maintenance path. Because this runs inside `AccountsBackgroundService`, sustained triggering degrades a validator's background thread pool utilization and disk I/O without any compensating progress on shrinking/ancient packing, which could compound over time (unshrunk ancient storages continue to accumulate, further growing the wasted per-iteration scan cost).

### Likelihood Explanation
Reaching the "many-ref, un-movable" precondition requires influencing the accounts index refcount landscape of already-rooted, unclean, aging slots. This is possible via ordinary account writes without any special privileges; however, precisely engineering the slot arithmetic so that `many_ref_accounts_can_be_moved` reliably returns `false` on *every* subsequent background pass (rather than resolving after one or two rounds as clean/shrink naturally progresses) requires careful, sustained account/slot shaping, and the validator's normal `clean_accounts` process runs concurrently and may reduce refcounts over time. This makes the finding plausible but not trivially reproducible as a persistent DoS without further engineering of the account layout.

### Recommendation
- Cache/memoize `get_unique_accounts_from_storage_for_combining_ancient_slots` and `calc_accounts_to_combine` results (or at least the refcount/multi-ref classification) across calls so that a `many_ref_accounts_can_be_moved`/pack-overflow failure does not force redoing the full storage scan on the next background iteration when the underlying storages haven't changed.
- When `many_ref_accounts_can_be_moved` or the packing-capacity check fails, track/exclude the specific offending slots (similar to how `truncate_to_max_storages`/`filter_ancient_slots` already exclude certain slots) so repeated calls make incremental progress on the remaining, movable slots instead of aborting the entire batch.
- Add metrics/alerting on repeated `combine_ancient_slots_packed_internal` early-return counts so operators can detect sustained wasted-work conditions.

### Proof of Concept
Not directly exploitable via a single call/transaction; requires constructing an account/slot layout (many pubkeys stored across multiple non-cleaned, rooted slots such that their "many-refs newest" slot exceeds the available ancient target slots) that is sustained across multiple `AccountsBackgroundService` shrink-ancient iterations. Concretely: repeatedly re-store the same set of pubkeys across many slots without letting `clean_accounts` fully resolve them to single-ref before the `ancient_append_vec_offset` boundary passes, so that on each `shrink_ancient_slots()` call, `combine_ancient_slots_packed_internal` performs the full scan/collect/pack computation ( [8](#0-7) ) and then discards it at the `many_ref_accounts_can_be_moved` check.

    fn combine_ancient_slots_packed_internal(
        &self,
        sorted_slots: Vec<Slot>,
        mut tuning: PackedAncientStorageTuning,
        metrics: &mut SquashStatsSub,
    ) {
        self.shrink_ancient_stats
            .slot
            .store(*sorted_slots.first().unwrap_or(&0), Ordering::Relaxed);
        self.shrink_ancient_stats
            .slots_considered
            .fetch_add(sorted_slots.len() as u64, Ordering::Relaxed);
        let mut ancient_slot_infos =
            self.collect_sort_filter_ancient_slots(sorted_slots, &mut tuning);
        self.shrink_ancient_stats
            .ideal_storage_size
            .store(tuning.ideal_storage_size.into(), Ordering::Relaxed);

        std::mem::swap(
            &mut *self.best_ancient_slots_to_shrink.write().unwrap(),
            &mut ancient_slot_infos.best_slots_to_shrink,
        );

        if ancient_slot_infos.all_infos.is_empty() {
            return; // nothing to do
        }
        let mut accounts_per_storage = self
            .get_unique_accounts_from_storage_for_combining_ancient_slots(
                &ancient_slot_infos.all_infos[..],
            );

        let mut accounts_to_combine = self.calc_accounts_to_combine(
            &mut accounts_per_storage,
            &tuning,
            IncludeManyRefSlots::Skip,
        );
        metrics.unpackable_slots_count += accounts_to_combine.unpackable_slots_count;

        let mut many_refs_newest = accounts_to_combine
            .accounts_to_combine
            .iter_mut()
            .filter_map(|alive| {
                let newest_alive =
                    std::mem::take(&mut alive.alive_accounts.many_refs_this_is_newest_alive);
                (!newest_alive.accounts.is_empty()).then_some(newest_alive)
            })
            .collect::<Vec<_>>();

        // Sort highest slot to lowest slot. This way, we will put the multi ref accounts with the highest slots in the highest
        // packed slot.
        many_refs_newest.sort_unstable_by_key(|b| cmp::Reverse(b.slot));
        metrics.newest_alive_packed_count += many_refs_newest.len();

        if !Self::many_ref_accounts_can_be_moved(
            &many_refs_newest,
            &accounts_to_combine.target_slots_sorted,
            &tuning,
        ) {
            datapoint_info!("shrink_ancient_stats", ("high_slot", 1, i64));
            log::info!(
                "unable to ancient pack: highest available slot: {:?}, lowest required slot: {:?}",
                accounts_to_combine.target_slots_sorted.last(),
                many_refs_newest.last().map(|accounts| accounts.slot)
            );
            return;
        }

        // for the accounts which are one ref and can be put anywhere, we want to put the accounts from the LARGEST storages at the end.
        // This causes us to keep the accounts we're re-packing from already existing ancient storages together with other normal one ref accounts.
        // The alternative could cause us to mix newly ancient slots produced by flush (containing accounts touched more recently) with previously
        // packed ancient storages which over time contained enough dead accounts that the storage needed to be shrunk by being re-packed.
        // The end result of this sort should cause older, colder accounts (previously packed into large storages and then re-packed/shrunk) to
        // be re-packed together with other older/colder accounts.
        accounts_to_combine
            .accounts_to_combine
            .sort_unstable_by_key(|a| a.written_bytes);

        // pack the accounts with 1 ref or refs > 1 but the slot we're packing is the highest alive slot for the pubkey.
        // Note the `chain` below combining the 2 types of refs.
        let pack = PackedAncientStorage::pack(
            many_refs_newest.iter().chain(
                accounts_to_combine
                    .accounts_to_combine
                    .iter()
                    .map(|shrink_collect| &shrink_collect.alive_accounts.one_ref),
            ),
            tuning.ideal_storage_size,
        );

        if pack.len() > accounts_to_combine.target_slots_sorted.len() {
            // Not enough slots to contain the accounts we are trying to pack.
            return;
        }

        let write_ancient_accounts = self.write_packed_storages(&accounts_to_combine, pack);

        self.finish_combine_ancient_slots_packed_internal(
            accounts_to_combine,
            write_ancient_accounts,
            metrics,
        );
    }

                    unique_accounts,

            })

    /// get a sorted list of slots older than an epoch
    /// squash those slots into ancient append vecs
    pub fn shrink_ancient_slots(&self, epoch_schedule: &EpochSchedule) {
        if self.ancient_append_vec_offset.is_none() {
            return;
        }

        let oldest_non_ancient_slot = self.get_oldest_non_ancient_slot(epoch_schedule);
        let can_randomly_shrink = true;
        let (sorted_slots, select_slots_us) =
            measure_us!(self.get_sorted_potential_ancient_slots(oldest_non_ancient_slot));
        self.shrink_ancient_stats
            .select_slots_us
            .fetch_add(select_slots_us, Ordering::Relaxed);
        self.combine_ancient_slots_packed(sorted_slots, can_randomly_shrink);
    }
