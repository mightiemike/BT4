### Title
Inbound gas-swap `minPCOut` slippage floor is derived from the same manipulable spot price it's meant to protect against - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/evm.go)

### Summary
The external report's root cause — a "protected" position value computed from spot-price-derived amounts instead of a validated reference price — has a direct analog in Push Chain's `GAS` / `GAS_AND_PAYLOAD` inbound execution flow. `GetSwapQuote()` calls Uniswap V3 `QuoterV2.quoteExactInputSingle`, which returns the **current spot price** of the PRC20→WPC pool. This spot-derived quote is used to compute `minPCOut` (95% of quote), which is then passed straight back into the actual on-chain swap (`depositPRC20WithAutoSwap` → `CallPRC20DepositAutoSwap`) executed moments later. There is no TWAP, no Chainlink cross-check, and no independent reference price anywhere in this path — unlike even the original (flawed) `V3Oracle` which at least ran `_checkPoolPrice()` against Chainlink.

### Finding Description
For `TxType.GAS` and `GAS_AND_PAYLOAD` inbounds, the keeper executes a module-driven swap of the user's deposited PRC20 into the native gas token (WPC/PC) as part of the same inbound-execution transaction: [1](#0-0) 

The quote is fetched from the Uniswap V3 QuoterV2 contract: [2](#0-1) 

and the resulting `minPCOut` (a naive 5%-slippage floor computed from that same spot quote) is passed into the real swap call: [3](#0-2) 

The identical pattern is used for gas refunds: [4](#0-3) 

Both the "acceptable price" (`quote`) and the "actual execution price" (the on-chain swap) are read from the **exact same pool at essentially the same block**, with no TWAP window and no external reference price (Chainlink or otherwise) to detect manipulation. This is architecturally the same flaw the report describes: an "amount" (here, `minPCOut`) that should protect the user's economic outcome is derived from the manipulable spot price of the very AMM pool it's meant to guard against, rather than from an independently validated price.

### Impact Explanation
Because `quote`/`minPCOut` and the swap execution price come from the same pool at nearly the same moment, an attacker who moves the PRC20/WPC pool price immediately before this module-driven swap executes (e.g., via a large trade positioned just ahead of the inbound-finalizing transaction in the same block) can depress the spot price so that `minPCOut` itself reflects the manipulated (bad) price. The protocol's own swap then executes at that manipulated rate without violating its own slippage check, because the check was computed from the same corrupted price. The result is the user's deposited funds are auto-swapped into materially less native gas token than a fair market rate would produce — a direct, unauthorized value loss for the depositor (in scope: "corruption of PRC20 or native asset accounting… gas fee accounting… reachable from ordinary user deposits… default transaction submission paths alone"). The attacker profits by arbitraging the pool back afterward (classic sandwich), extracting value that should have gone to the depositing user / protocol.

### Likelihood Explanation
Exploitability depends on: (1) the PRC20/WPC Uniswap V3 pool having low enough liquidity to move materially with a single trade, and (2) the attacker being able to position their manipulation trade immediately before the inbound-execution transaction within the same block (mempool positioning / MEV, which does not require validator or governance privilege — any unprivileged trader can attempt this). Push Chain's own gateway/deposit pools for gas-abstraction swaps are likely to have thinner liquidity than a mature venue, making this more practically exploitable than the original C4 finding, which needed a flash loan against deep DeFi liquidity. This is assessed as Medium-to-High likelihood given no code-level mitigation exists at all (no TWAP, no oracle bound), in contrast to the original report where `_checkPoolPrice()` at least provided partial protection.

### Recommendation
Do not compute the slippage floor purely from an instantaneous `quoteExactInputSingle` spot call against the same pool that immediately executes the swap. Options:
- Use a Uniswap V3 TWAP (time-weighted average, over a meaningful window) as the reference price for computing `minPCOut`, and additionally bound the acceptable deviation between the TWAP and current spot price before allowing the swap to proceed (revert or fallback to no-swap deposit if the deviation is too large) — mirroring the `_checkPoolPrice()` pattern from the original finding.
- Alternatively, source the reference price from a validator-attested / governance-configured price oracle independent of the swap-execution pool, so the same block/attacker cannot simultaneously corrupt both the reference and execution price.
- Consider enforcing a protocol-level maximum acceptable price impact per swap, independent of the pool's own quote.

### Proof of Concept
1. Attacker identifies the PRC20↔WPC Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress` for a given gas-token PRC20, and observes it has moderate/low liquidity.
2. Attacker submits a large sell of PRC20 into WPC (or vice versa) to push the pool's spot price down, timed to land in the same block just before a pending `MsgVoteInbound` that will finalize a `GAS`/`GAS_AND_PAYLOAD` inbound (the attacker can front-run any pending inbound vote they observe in the mempool, since UV votes and the resulting execution happen atomically in `VoteInbound`).
3. When the vote finalizes, `ExecuteInboundGas` calls `GetSwapQuote` → gets the manipulated (low) quote → computes `minPCOut = quote * 0.95` (also artificially low) → calls `CallPRC20DepositAutoSwap` with that `minPCOut`.
4. The module's swap executes at the manipulated spot price, minting the user/UEA far less native PC/WPC than a fair-price swap would have produced.
5. Attacker then reverses their initial trade, restoring the pool price and capturing the difference extracted from the module's swap as profit, while the depositing user permanently receives fewer funds than deposited value should provide. [5](#0-4) [2](#0-1)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
