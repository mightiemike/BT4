The java-tron market actuators (`MarketSellAssetActuator`, `MarketCancelOrderActuator`) compute fees dynamically via `calcFee()` calling `dynamicStore.getMarketSellFee()` / `getMarketCancelFee()` at the time each transaction executes, rather than storing a `feePerc` on the order/offer and later re-validating it with an exact-match comparison against a possibly-changed global fee. [1](#0-0) [2](#0-1) 

The `MarketOrderCapsule` order book entries carry the sell/buy token quantities and state, but there is no stored per-order fee percentage field that is compared against the current global fee to determine validity — fees are simply charged at the current rate whenever an action (create/cancel/match) occurs, so a change in `MARKET_SELL_FEE` or `MARKET_CANCEL_FEE` cannot retroactively invalidate existing resting orders. The bug-class described in the report (an offer storing a fixed `feePerc` that is exact-matched against a mutable global fee, causing valid lower-fee offers to become invalid) has no counterpart in this exchange/market implementation.
