### Title
Integer-truncation of `baseFee` in `CalculateGasCost` zeroes out payload-execution gas billing, enabling free/unbounded UEA execution when the fee-market base fee is below 1 upc - (File: `x/uexecutor/keeper/fees.go`)

### Summary
The external report's core lesson is that a decaying rate/price with no enforced floor can collapse toward zero and make a protected operation effectively free, breaking an economic invariant. In Push Chain's `x/uexecutor` module, `CalculateGasCost` performs an integer division of the EIP-1559-style `baseFee` by `1e18` to "unwrap" the `LegacyDec` encoding [1](#0-0) . Any `baseFee` value under `1e18` (i.e. less than one whole `upc`, the smallest denomination) truncates to `0`, silently zeroing the gas cost charged to a UEA payload executor regardless of actual `GasUsed`.

### Finding Description
`ExecutePayloadV2` executes an EVM call on behalf of the user's UEA via `CallUEAExecutePayload` and then attempts to recover the incurred gas cost from the UEA's own balance via `DeductGasFeesFromReceipt` inside the same cached context [2](#0-1) .

`DeductGasFeesFromReceipt` fetches the current network `baseFee` from the fee-market keeper and calls `CalculateGasCost` [3](#0-2) :

```go
baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
...
gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
...
if gasCost.Sign() <= 0 {
    return nil
}
```

Inside `CalculateGasCost`, the `baseFee` (a `LegacyDec`, an 18-decimal fixed-point encoding) is unwrapped with plain integer division:

```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
...
effectiveGasPrice := new(big.Int).Set(baseFeeBig)
...
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)
``` [4](#0-3) 

Because `upc` is already the smallest atomic denomination (like wei), any legitimate base fee below 1 whole `upc` (which is entirely plausible under normal EIP-1559 dynamics for a low-congestion network, exactly the kind of degraded/quiet-network condition referenced in the external report) is floored to `0` by `big.Int.Div`. `effectiveGasPrice` becomes `0`, so `gasCost = 0 * gasUsed = 0` no matter how much gas the payload execution actually consumed. `DeductGasFeesFromReceipt` then treats `gasCost.Sign() <= 0` as a no-op success and returns `nil`, so `DeductAndBurnFees` is never invoked and no `upc` is transferred to, or burned by, the module account [5](#0-4) .

This mirrors the external bug's root cause precisely: a value that legitimately decays toward zero under ordinary/degraded network conditions (there `ibRatio`, here `baseFee`) is used without a floor/minimum, and once it crosses under the smallest representable unit, the dependent economic charge (bond redemption cost / gas cost) silently becomes free.

### Impact Explanation
Any unprivileged user submitting `MsgExecutePayload` (routed to `ExecutePayloadV2`) whenever the fee-market `baseFee` is below `1e18` (i.e., below 1 `upc`) pays zero gas cost for arbitrary EVM execution through their UEA, regardless of the actual `GasUsed` reported in the receipt. Since UEA execution can invoke arbitrary EVM computation (bounded only by the payload's `GasLimit`), this allows repeated free execution/spam of computationally expensive calls with no fee recovery, undermining the fee-accounting invariant that gas consumed must be paid for. This falls squarely within the allowed impact of "corruption of ... gas fee accounting ... reachable from ordinary user deposits, payloads, contracts, or default transaction submission paths alone," and can be leveraged for low-cost/no-cost DoS-style resource consumption against the chain since execution work is performed but never billed.

### Likelihood Explanation
The trigger condition (`baseFee < 1e18`, i.e. under 1 whole `upc`) is not a privileged or adversarial network condition — it is a normal steady-state outcome of an EIP-1559-style fee market during periods of low block utilization, which the fee market is explicitly designed to produce. Devnet/testnet genesis configs in this repo set base fee to large values (e.g. `1e9` `upc`), but the dynamic AIMD adjustment in the fee-market module can decrease `baseFee` over time toward its floor; if that floor (or organic decay) is ever below `1e18`, this bug triggers deterministically for every payload execution, with no attacker action needed beyond normal `MsgExecutePayload` submission.

### Recommendation
Do not floor-truncate the sub-unit fraction of `baseFee` to zero. Compute `gasCost` using the full-precision `LegacyDec`/`big.Int` representation of `baseFee` (i.e., keep gas price in the same 1e18-scaled unit as `baseFee` throughout the multiplication, then round only the final `upc` amount, using `Ceil()` rather than floor-division on the price itself), analogous to how `MinGasPriceDecorator` computes required fees via `Mul(...).Ceil().RoundInt()` [6](#0-5) . Additionally, enforce a protocol-level minimum billable gas cost (or minimum `baseFee` floor) so that gas consumption can never resolve to a zero charge when `GasUsed > 0`.

### Proof of Concept
1. Set/allow the fee-market `baseFee` to any value `v` such that `0 < v < 1e18` (e.g., `v = 500000000000000000` representing 0.5 `upc`) — a value fully reachable through the fee market's normal EIP-1559 adjustment under low network utilization.
2. Submit `MsgExecutePayload` for a UEA whose `UniversalPayload.MaxFeePerGas >= 0` (any nonzero value clears the `maxFeePerGas < baseFeeBig` check since `baseFeeBig` is already truncated to `0`), with a payload that consumes substantial `GasUsed` (e.g. a compute-heavy call within `GasLimit`).
3. `ExecutePayloadV2` → `CallUEAExecutePayload` executes and returns a receipt with `GasUsed > 0`.
4. `DeductGasFeesFromReceipt` calls `CalculateGasCost(baseFee, ...)`; `baseFeeBig.Div(baseFeeBig, 1e18)` yields `0`; `effectiveGasPrice = 0`; `gasCost = 0`.
5. `gasCost.Sign() <= 0` short-circuits to `return nil` — `DeductAndBurnFees` is never called [7](#0-6) .
6. The EVM state change (`writeCache()`) is committed with zero `upc` deducted or burned from the UEA, confirming free execution of arbitrary gas-consuming payloads whenever `baseFee < 1e18`.

Note: I was not able to fully verify within index limits whether the fee-market module's `min-gas-price`/decay floor parameter is guaranteed in production deployments to always stay ≥ `1e18`; if such a floor is enforced elsewhere (e.g., in `x/feemarket` params validation) that this repo's index does not surface, it would reduce/eliminate reachability of this condition. I recommend a Devin session with full repository access to check `x/feemarket` (if vendored) or its config defaults to confirm whether `baseFee` can organically fall below `1e18` in a live deployment.

// DeductAndBurnFees deducts gas fees from the user's smart account and burns them.
// The process happens in two steps:
// 1. Transfer coins from user account to module account
// 2. Burn coins from module account
// Returns error if either transfer or burn fails
func (k Keeper) DeductAndBurnFees(ctx context.Context, from sdk.AccAddress, gasCost *big.Int) error {
	amt := sdkmath.NewIntFromBigInt(gasCost)
	coin := sdk.NewCoin(pchaintypes.BaseDenom, amt)

	k.Logger().Debug("deducting and burning fees",
		"from", from.String(),
		"gas_cost", gasCost.String(),
		"denom", pchaintypes.BaseDenom,
	)

	err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, from, types.ModuleName, sdk.NewCoins(coin))
	if err != nil {
		return err
	}

	return k.bankKeeper.BurnCoins(ctx, types.ModuleName, sdk.NewCoins(coin))
}

	// Step 2: Wrap EVM execution + fee deduction in a CacheContext so they
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr
	}

	// Both succeeded — commit EVM state and fee deduction together.
	writeCache()
