### Title
Failed fund re-mint on outbound revert permanently skips independent gas refund, causing loss of user gas fees - (File: x/uexecutor/keeper/outbound.go)

### Summary
`handleFailedOutbound` couples two independent accounting operations — re-minting bridged funds back to the revert recipient, and refunding excess destination-chain gas fees — into a single all-or-nothing code path. If the fund re-mint call fails for any reason (including a zero-value transfer/mint being rejected by the underlying contract, the same bug class as the source report), the function returns early via `AbortOutbound` and **never executes** the independent gas-refund step, permanently forfeiting the user's already-known excess gas fee.

### Finding Description
In `handleFailedOutbound` [1](#0-0) , for `TxType_FUNDS`, `TxType_GAS_AND_PAYLOAD`, and `TxType_FUNDS_AND_PAYLOAD` outbounds, the keeper unconditionally calls `k.CallPRC20Deposit(ctx, prc20, recipient, amount)` to re-mint the bridged token amount back to the sender/revert-recipient, without first checking whether `amount` is zero: [2](#0-1) .

The codebase itself documents and tests that zero-amount `GAS_AND_PAYLOAD` and `FUNDS_AND_PAYLOAD` inbound/outbound flows are a legitimate, intentionally-supported case (an unprivileged user simply submits a gas-top-up-only or payload-only cross-chain transaction with `Amount: "0"`) [3](#0-2) . Such an outbound can subsequently fail on the destination chain (an attacker/user can craft a payload that predictably reverts on execution), triggering the honest-validator-observed failure path into `handleFailedOutbound`.

If the zero-value call into `CallPRC20Deposit` (which ultimately calls `depositPRC20Token` on the `UniversalCore`/PRC20 contract via `DerivedEVMCall` [4](#0-3) ) reverts — the same class of "revert on zero-value transfer" behavior flagged in the source report — the Go code takes the `err != nil` branch:

```go
if err != nil {
    pcTx.Status = "FAILED"
    pcTx.ErrorMsg = err.Error()
    outbound.PcRevertExecution = &pcTx
    return k.AbortOutbound(ctx, utxId, outbound,
        fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
}
``` [5](#0-4) 

This `return` short-circuits execution before reaching `k.applyGasRefund(ctx, &outbound, obs)` [6](#0-5) , which is the code path responsible for returning the user's excess destination-chain gas fee (`gasFee - gasFeeUsed`) computed from the honestly-observed `obs.GasFeeUsed` [7](#0-6) . The two operations (fund re-mint vs. gas refund) have no on-chain dependency on each other — the gas fee is owed to the user regardless of whether the funds re-mint succeeds — yet the code structure makes the gas refund conditional on the unrelated re-mint leg succeeding.

### Impact Explanation
The outbound is marked `ABORTED` and requires manual intervention [8](#0-7) , but the excess gas refund is never attempted, retried, or recorded — it is silently and permanently skipped. This is a permanent loss of protocol/user-owed funds (the already-known refund amount) reachable purely through the honest-validator-observed failure path, without any privileged actor involved, matching the in-scope impact "permanent loss ... of user or protocol-controlled funds."

### Likelihood Explanation
The zero-amount `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` case is explicitly supported and tested, so an unprivileged user can construct such an inbound/outbound. Causing the corresponding outbound to fail on the destination chain (e.g. a payload call that reverts) is also user-controlled. The likelihood that the specific zero-value mint call reverts depends on the (out-of-scope, Solidity) `depositPRC20Token`/`UniversalCore` implementation, which cannot be verified from this repository, but the structural bug — any re-mint failure unconditionally skipping the independent gas refund — is a certain, reproducible defect in the Go orchestration logic regardless of the exact trigger.

### Recommendation
Decouple the fund re-mint and gas-refund steps in `handleFailedOutbound` so a failure in one does not prevent the other from running: perform (or attempt) `applyGasRefund` unconditionally before/independently of the `AbortOutbound` early return, and additionally skip the `CallPRC20Deposit` call entirely when `amount` is zero (mirroring the source report's recommended non-zero-value guard), since there is nothing to re-mint in that case.

### Proof of Concept
1. Submit an inbound with `TxType_GAS_AND_PAYLOAD` (or `FUNDS_AND_PAYLOAD`) and `Amount: "0"`, per the supported zero-amount flow [9](#0-8) , which produces a corresponding outbound with `Amount = "0"` and non-empty `GasFee`.
2. Craft the payload/target such that execution fails on the destination chain, and have honest UVs vote `MsgVoteOutbound` with `success=false` and a `gas_fee_used` less than `gas_fee` (so a nonzero refund is owed) — mirroring the harness in `gas_fee_refund_test.go` [10](#0-9) .
3. `handleFailedOutbound` is invoked; the zero-amount `CallPRC20Deposit` call fails (contract-dependent), causing an early `return k.AbortOutbound(...)` before `applyGasRefund` runs.
4. Observe: `outbound.OutboundStatus == ABORTED`, `outbound.PcRefundExecution == nil`, and the user's excess gas fee is never refunded, with no automatic remediation path in the keeper code.

func (k Keeper) AbortOutbound(ctx context.Context, utxId string, outbound types.OutboundTx, reason string) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	outbound.OutboundStatus = types.Status_ABORTED
	outbound.AbortReason = reason

	if err := k.UpdateOutbound(ctx, utxId, outbound); err != nil {
		return err
	}

	// Defensively remove from pending index (may already be removed by caller)
	_ = k.PendingOutbounds.Remove(ctx, outbound.Id)

	// Emit event for monitoring/alerting
	sdkCtx.EventManager().EmitEvent(sdk.NewEvent(
		"outbound_aborted",
		sdk.NewAttribute("utx_id", utxId),
		sdk.NewAttribute("outbound_id", outbound.Id),
		sdk.NewAttribute("abort_reason", reason),
	))

	return nil
}

func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}

	outbound.OutboundStatus = types.Status_REVERTED
	k.Logger().Info("outbound reverted",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)

	// Refund excess gas regardless of tx type — gas was consumed on the external
	// chain whether the execution succeeded or failed.
	k.applyGasRefund(ctx, &outbound, obs)

	return k.UpdateOutbound(ctx, utxId, outbound)
}

func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {

// Calls Handler Contract to deposit prc20 tokens
func (k Keeper) CallPRC20Deposit(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // sender: module account
		handlerAddr,        // destination
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20Token",
		prc20Address,
		amount,
		to,
	)
}
