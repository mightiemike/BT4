### Title
Missing tx-ingestion pause enforcement in `Gateway::add_tx_inner` allows P2P-relayed transactions to bypass the HTTP server's `accept_new_txs` gate - (File: `crates/apollo_gateway/src/gateway.rs`)

### Summary
The sequencer's mechanism for pausing new-transaction admission (`accept_new_txs` in `HttpServerDynamicConfig`) is enforced only at the HTTP server layer, not inside the `Gateway` component itself. Transactions that reach the `Gateway` via the mempool-P2P runner (i.e., relayed from other sequencer/peer nodes) call `GatewayClient::add_tx` directly, completely bypassing the HTTP-side check and reaching mempool admission even while the node operator has "paused" new transaction ingestion.

### Finding Description
The pause flag is checked exclusively in the HTTP handlers: [1](#0-0) [2](#0-1) 
via `check_new_transactions_are_allowed`: [3](#0-2) 

However, `Gateway::add_tx` / `add_tx_inner` — the actual entry point that performs stateless/stateful validation and forwards the transaction to the mempool — contains no such check: [4](#0-3) 

This same `Gateway::add_tx` path is reached directly by `MempoolP2pRunner`, which forwards transactions received from other peers to the gateway client without any pause/backpressure gate other than a concurrency semaphore: [5](#0-4) 

Both HTTP handlers (`add_rpc_tx`, `add_tx`) call the same `accept_new_txs` check consistently — so unlike the referenced report, no single HTTP function is "missing" the guard. The gap is architectural: the guard exists at one ingress (HTTP) but not at the shared component (`Gateway`) that is also reachable via a second ingress (P2P relay), analogous to a `Pausable` check applied to one deployer/creation function but not to a sibling function that reaches the same privileged state-changing logic.

### Impact Explanation
When an operator sets `accept_new_txs = false` (e.g., during an incident, congestion-control action, or planned pause) to stop the sequencer from admitting new transactions via its public HTTP endpoint, transactions gossiped from other sequencer nodes over the mempool-P2P topic are still accepted into the local mempool via `Gateway::add_tx`, since that code path never consults `accept_new_txs`. This defeats the intended safety/control mechanism: the sequencer will keep validating and pooling new transactions (consuming CPU/memory/mempool capacity, and potentially proceeding to block-building/inclusion) despite the pause, undermining an operational control that is meant to halt mempool admission network-wide for that node.

### Likelihood Explanation
Likelihood is high in any deployment where the mempool-P2P component is enabled (the default multi-sequencer topology, per `crates/apollo_mempool_p2p/src/lib.rs` and `crates/apollo_node/src/components.rs`), since ordinary transaction propagation between sequencer nodes continuously feeds the `Gateway` through this path. No malicious actor is required — normal p2p transaction gossip from legitimate senders is sufficient to trigger the bypass whenever the HTTP pause is engaged.

### Recommendation
Move (or duplicate) the `accept_new_txs`/pause check into the `Gateway` component itself (e.g., at the start of `GenericGateway::add_tx` or `add_tx_inner`), so it applies uniformly regardless of whether the transaction originates from the HTTP server or from the mempool-P2P runner. The dynamic-config pause signal should be threaded into the `Gateway`'s config (similar to how `HttpServerDynamicConfig` is polled), and both the HTTP and P2P ingress paths should be gated by the same check.

### Proof of Concept
1. Operator sets `http_server_config.dynamic_config.accept_new_txs = false` via the config manager, intending to stop the node from admitting new transactions.
2. HTTP clients calling `/gateway/add_rpc_transaction` or `/gateway/add_transaction` correctly receive `HttpServerError::DisabledError` (per `check_new_transactions_are_allowed`).
3. A peer sequencer node continues broadcasting `RpcTransactionBatch` messages over the `apollo_mempool_transaction_propagation` topic.
4. `MempoolP2pRunner::start` receives these messages and calls `gateway_client.add_tx(GatewayInput { rpc_tx, message_metadata })` directly (`crates/apollo_mempool_p2p/src/runner/mod.rs:120-127`), with no reference to `accept_new_txs`.
5. `Gateway::add_tx` → `add_tx_inner` executes normal validation and calls `self.mempool_client.add_tx(...)`, admitting the transaction into the local mempool — despite the operator's pause — proving the enforcement gap.

    async fn add_tx_inner(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        let mut metric_counters = GatewayMetricHandle::new(&tx, &p2p_message_metadata);
        metric_counters.count_transaction_received();
        if let RpcTransaction::Invoke(RpcInvokeTransaction::V3(ref inv)) = tx {
            if !inv.proof_facts.is_empty() {
                metric_counters.count_private_transaction_received();
            }
        }
        let is_p2p = p2p_message_metadata.is_some();

        if let RpcTransaction::Declare(ref declare_tx) = tx {
            if let Err(e) = self.check_declare_permissions(declare_tx) {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        }

        // Perform stateless validations.
        self.stateless_tx_validator.validate(&tx)?;

        let tx_signature = tx.signature().clone();

        // Declare conversions overload the compiler component's CPU and memory. Reject declares if
        // there are too many declares compiling in parallel. The permit is held only across
        // compilation and released before stateful validation.
        let compilation_permit = if matches!(tx, RpcTransaction::Declare(_)) {
            Some(self.declare_compilation_semaphore.try_acquire().map_err(|_| {
                let error = StarknetError::too_many_concurrent_declare_compilations();
                metric_counters.record_add_tx_failure(&error);
                error
            })?)
        } else {
            None
        };

        let (internal_tx, executable_tx, proof_data) =
            self.convert_rpc_tx_to_internal_and_executable_txs(tx, &tx_signature).await?;
        drop(compilation_permit);

        let mut stateful_transaction_validator = self
            .stateful_tx_validator_factory
            .instantiate_validator(self.config.dynamic_config.native_classes_whitelist.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let nonce = stateful_transaction_validator
            .extract_state_nonce_and_run_validations(&executable_tx, self.mempool_client.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let proof_archive_handle = self
            .store_proof_and_spawn_archiving(proof_data, internal_tx.tx_hash, is_p2p)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let gateway_output = create_gateway_output(&internal_tx);

        let add_tx_args = AddTransactionArgsWrapper {
            args: AddTransactionArgs::new(internal_tx, nonce),
            p2p_message_metadata,
        };

        // Await as late as possible for proof archiving before sending the transaction to the
        // mempool.
        Self::await_proof_archiving(proof_archive_handle)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let mempool_client_result = self.mempool_client.add_tx(add_tx_args).await;
        match mempool_client_result_to_deprecated_gw_result(&tx_signature, mempool_client_result) {
            Ok(()) => {}
            Err(e) => {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        };

        metric_counters.transaction_sent_to_mempool();

        Ok(gateway_output)
    }
