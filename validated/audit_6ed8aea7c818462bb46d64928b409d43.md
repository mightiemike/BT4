### Title
Null JSON fields for boxed `Long`/`Integer` request parameters cause auto-unboxing `NullPointerException` in JSON-RPC transaction builder - (File: `framework/src/main/java/org/tron/core/services/jsonrpc/types/BuildArguments.java`)

### Summary
`BuildArguments` is the Jackson-deserialized DTO used to build transactions from unauthenticated JSON-RPC requests (`eth_call`, `eth_sendTransaction`-style flows, and other endpoints that construct contract calls from client-supplied JSON). Several of its fields are boxed types (`Long tokenId`, `Long tokenValue`, `Long consumeUserResourcePercent`, `Long originEnergyLimit`, `Integer permissionId`) initialized with non-null defaults (`0L`, `0`), but Jackson binds an explicit JSON `null` value directly onto the field via the setter, overwriting the default and leaving the field truly `null` at runtime — exactly the bug class described in the external report (Go struct tags don't enforce non-null JSON values; the same holds for Java field defaults being overwritten by explicit `null` during deserialization).

### Finding Description
`BuildArguments` declares: [1](#0-0) 

These fields are given non-null default values in the field initializers, but that default is only used when the JSON key is *absent*. When the JSON payload contains the key with an explicit `null` value (e.g. `{"tokenId": null}`), Jackson's default `ObjectMapper` behavior calls the setter with `null`, which replaces the field's default and leaves it `null`.

`getContractType(Wallet)` calls `availableTransferAsset()`: [2](#0-1) 

`availableTransferAsset()` performs `tokenId > 0 && tokenValue > 0`, which auto-unboxes the `Long` fields. If either `tokenId` or `tokenValue` is `null` (via an explicit JSON `null`), this throws a `NullPointerException` during auto-unboxing — mirroring the reported bug where a `*big.Int` field surviving JSON `null` deserialization panics on a nil-dereference in `Cmp`.

### Impact Explanation
`getContractType` is invoked while building a transaction from client-supplied JSON-RPC parameters, i.e., on an unauthenticated/anonymous request path. An uncaught `NullPointerException` thrown out of this code path in a servlet/RPC handler is a denial-of-service pattern: at minimum it produces an unhandled request failure, and depending on how the surrounding HTTP servlet handles uncaught runtime exceptions, repeated triggering can degrade or crash request-handling threads, consistent with the "malicious request can crash the server" bug class from the report.

### Likelihood Explanation
Reaching this code only requires sending a crafted JSON body with an explicit `"tokenId": null` (or `"tokenValue": null`) to whichever endpoint deserializes into `BuildArguments`/`CallArguments`-derived flows and calls `getContractType`. No authentication or special privileges are required — this is a plain external, anonymous HTTP/JSON-RPC request, matching the required "unprivileged, anonymous RPC request" root cause. I could not fully trace the exact HTTP servlet entry point (`TronJsonRpcImpl.java` contains references but I was unable to open it within the available iterations) to confirm whether an outer try/catch already converts arbitrary `RuntimeException`s to a JSON-RPC error response before this hardens into a full DoS — this should be verified before treating impact as confirmed-critical.

### Recommendation
Add explicit null checks in `availableTransferAsset()` (and any other unboxing usage of `tokenId`, `tokenValue`, `consumeUserResourcePercent`, `originEnergyLimit`, `permissionId`) before comparing/unboxing, e.g. `tokenId != null && tokenId > 0`. Alternatively, configure Jackson deserialization (e.g., `@JsonSetter(nulls = Nulls.SKIP)` on these fields, or a module-level `JsonSetter.Value` default) so an explicit JSON `null` does not override the field's intended default value.

  public ContractType getContractType(Wallet wallet) throws JsonRpcInvalidRequestException,
      JsonRpcInvalidParamsException {
    // Fail fast on bad hex / conflict before the state lookup;
    // calldataEquals relies on resolveData() having validated hex first.
    String resolvedData = resolveData();
    validateCallDataConflict();

    ContractType contractType;

    // to is null
    if (paramStringIsNull(to)) {
      // data is null
      if (paramStringIsNull(resolvedData)) {
        throw new JsonRpcInvalidRequestException("invalid json request");
      }

      contractType = ContractType.CreateSmartContract;
    } else {
      // to is not null
      byte[] contractAddressData = addressCompatibleToByteArray(to);
      BytesMessage.Builder build = BytesMessage.newBuilder();
      BytesMessage bytesMessage = build.setValue(ByteString.copyFrom(contractAddressData)).build();
      SmartContract smartContract = wallet.getContract(bytesMessage);

      // check if to is smart contract
      if (smartContract != null) {
        contractType = ContractType.TriggerSmartContract;
      } else {
        // tokenId and tokenValue: trc10, value: TRX
        if (availableTransferAsset()) {
          contractType = ContractType.TransferAssetContract;
        } else {
          if (StringUtils.isNotEmpty(value)) {
            contractType = ContractType.TransferContract;
          } else {
            throw new JsonRpcInvalidRequestException("invalid json request");
          }
        }
      }
    }

    return contractType;
  }
