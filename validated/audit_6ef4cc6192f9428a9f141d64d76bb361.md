### Title
Slippage bound derived from unvalidated on-chain Uniswap V3 spot quote allows value extraction / zero-output swaps in inbound gas-abstraction auto-swap - ([File: x/uexecutor/keeper/evm.go])

### Summary
The external report's root cause is: an oracle read (`latestAnswer`) that can legitimately return `0` or a stale/manipulable value is trusted directly by business logic to compute economic values, with no freshness or sanity check, and the wrong value can zero out an economic control (token cost). The equivalent pattern exists in Push Chain's `x/uexecutor` gas-abstraction auto-swap flow: the "price oracle" is `Keeper.GetSwapQuote`, a live call to the Uniswap V3 `QuoterV2.quoteExactInputSingle` function, and its output is used, unchecked, to compute `minPCOut`, the only slippage/anti-manipulation guard for a real on-chain swap of user funds.

### Finding Description
`Keeper.GetSwapQuote` performs a static `CallEVM` to the QuoterV2 contract and returns `amountOut` (the `quote`) with no validation that it is non-zero or "fresh"/uncontaminated: [1](#0-0) .

This value is consumed directly in `ExecuteInboundGas` (and the analogous `gasAndPayloadDepositAutoSwap` path) to compute the swap's minimum-output guard with a flat 5% haircut and passed straight to `CallPRC20DepositAutoSwap`, with no check that `quote > 0`: [2](#0-1) 

The same unguarded pattern is duplicated for outbound refunds: [3](#0-2)  and for the `GAS_AND_PAYLOAD` inbound route: [4](#0-3) .

Because `quoteExactInputSingle` reads the pool's *current spot state* (the same state the swap itself will execute against), using it as the sole source for `minPCOut` is a self-referential price check: it protects against nothing that happens in the same block. If the pool has thin liquidity or has just been drained/skewed by an attacker-submitted transaction immediately before the module-originated auto-swap executes, `GetSwapQuote` will return a low or even `0` value, `minPCOut` becomes `0` (or near-zero), and `CallPRC20DepositAutoSwap`/`refundUnusedGas` will accept the swap output regardless of how little PC the user actually receives back. This directly parallels the "oracle returns 0 and breaks all downstream logic" defect from the report — except here the broken value silently strips slippage protection from a value-transfer path that mints/refunds funds to end users, rather than reverting.

### Impact Explanation
This flow is reached from ordinary, unprivileged user activity: any user depositing native gas-token assets cross-chain triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, and successful/failed outbound observation triggers `applyGasRefund` — both module-originated, automatic paths with no admin involvement. If the underlying Uniswap V3 pool for a given PRC20 gas token is thin or can be manipulated in the same block (e.g., via a preceding swap by the attacker, who is not assumed malicious/privileged, merely an ordinary trader), the computed `minPCOut` collapses toward `0`, letting the auto-swap execute at an arbitrarily bad price. This drains value from the protocol/user funds involved in the swap (PRC20 or native PC accounting corruption), matching the in-scope impact of "corruption of PRC20 or native asset accounting" and "unauthorized ... release ... of user or protocol-controlled funds."

### Likelihood Explanation
Likelihood depends on pool depth for each configured gas token's Uniswap V3 pair; for newly-listed or thinly-traded PRC20/WPC pairs (common on a young chain), a single attacker-controlled swap immediately preceding the protocol's auto-swap can trivially depress the quote to near-zero, and the protocol has no other check to reject the resulting near-zero `minPCOut`. This requires no validator, TSS, or admin collusion — a lone unprivileged user can trigger and profit from it.

### Recommendation
Do not derive the slippage bound solely from the same-block spot quote of the pool being swapped against. Instead:
- Use a time-weighted average price (TWAP) from the pool (Uniswap V3 supports this via `observe`), or an independent price reference, to compute `minPCOut`.
- Add an explicit sanity check rejecting `quote == 0` (or below a configured minimum) before proceeding with the swap, falling back to the no-swap PRC20 deposit path instead of allowing a near-zero-output swap.
- Consider bounding the acceptable deviation between the spot quote and a longer-window reference price, analogous to checking `updatedAt`/`answeredInRound` freshness in the original report.

### Proof of Concept
1. Attacker identifies a gas-token PRC20 with a low-liquidity Uniswap V3 pool used for gas-abstraction auto-swap (`WPC`/gas-token pair from `GetUniversalCoreWPCAddress`/`GetDefaultFeeTierForToken`).
2. Attacker submits a large swap against that pool immediately before (or in the same block, via MEV/back-running) a pending cross-chain gas-abstraction deposit is executed by `ExecuteInboundGas`.
3. `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) now returns a depressed `amountOut`; `minPCOut = quote*95/100` is correspondingly depressed, potentially near `0`.
4. `CallPRC20DepositAutoSwap` executes the swap with this negligible floor, so the module accepts whatever the manipulated pool returns — an amount far below fair value.
5. Attacker (who set up the counter-liquidity or arbitrage position) captures the difference; the user/protocol absorbs the loss, with no revert and no on-chain signal that anything went wrong, mirroring the "silently returns 0 / breaks logic without reverting" defect class in the source report.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {

		return nil, err
	}

	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err

	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
