### Title
Unbounded recursion over attacker-controlled `NestedIntList` bytecode-segment structure causes stack-overflow DoS in compiled-class hashing and Starknet OS re-execution - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs], [File: crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs])

### Summary
`CasmContractClass::bytecode_segment_lengths` is a recursive `NestedIntList` (`Leaf(usize) | Node(Vec<NestedIntList>)`) that is walked with plain, depth-unbounded recursive functions in at least two security-critical paths reachable from a class declaration: compiled-class hash computation (`bytecode_hash_node`) and Starknet OS bytecode-segment structure construction (`create_bytecode_segment_structure_inner`). Neither function checks or limits nesting depth. This is the same bug class as CVE-2022-45688 (unbounded recursive descent over an attacker-influenced nested structure causing a native stack overflow).

### Finding Description
`bytecode_segment_lengths` is produced when the gateway compiles a declarer-submitted Sierra program to CASM (Sierra→CASM compilation step). Its structure/depth is a function of the Sierra program's control-flow/segmentation the compiler derives from the submitted program, i.e. it is influenced by the class declarer even though it isn't literal user-supplied JSON.

Once compiled, the resulting `CasmContractClass` (with its `NestedIntList`) is consumed, without any depth check, in:

1. `bytecode_hash_node` (compiled-class hashing, used to verify/derive `CompiledClassHash`): [1](#0-0) 
This function recurses once per `Node` level with no depth check, called from `bytecode_hash` → `hash_inner` → `HashableCompiledClass::hash`, which is invoked during declare-transaction execution to verify the declarer-supplied `compiled_class_hash` (`check_compile_class_hash_v2_declaration`) and elsewhere (`get_compiled_class_hash_v2`, native_blockifier storage sync): [2](#0-1) [3](#0-2) 

2. `create_bytecode_segment_structure_inner` (Starknet OS re-execution), also unbounded recursion: [4](#0-3) 
called from the OS hint `load_classes_and_create_bytecode_segment_structures`, which is invoked while re-executing/proving a block that contains the declared class: [5](#0-4) 

Notably, elsewhere in the codebase the blockifier explicitly *limits* an analogous nested structure to a single level of nesting with an `assert!(segmentation_depth <= 1, ...)`: [6](#0-5) 
This shows the team recognized the need to bound recursion depth for this kind of nested segment data in one call site, but the depth bound was not applied consistently to the hash-computation path or the Starknet OS path, leaving both open to unbounded recursion on a deeply nested `NestedIntList`.

No size/depth validation of `bytecode_segment_lengths` (as opposed to the flat `bytecode` length or `contract_class_object_size`) exists in the stateless gateway validator: [7](#0-6) 
which only bounds `sierra_program.len()` and the serialized JSON size of the *Sierra* class, not the depth of the *compiled* CASM's segment tree.

### Impact Explanation
A crafted Sierra program that compiles to a `CasmContractClass` with a sufficiently deep `bytecode_segment_lengths` nesting will, when hashed (during declare-tx validation/execution, or state-sync) or when processed by the Starknet OS hint `load_classes_and_create_bytecode_segment_structures` during block re-execution/proving, cause deep native-stack recursion. Once recursion exceeds the thread's stack size, the process crashes with a stack overflow (SIGSEGV / abort), rather than returning a graceful error. This is a process-crashing Denial of Service: any sequencer/full-node/prover process that hashes or re-executes the offending declared class will crash, which can halt block production/verification for that class's declare transaction and any subsequent block that revalidates it — matching "a network unable to confirm new transactions" for the affected node(s). This is reachable purely from a class declarer submitting one `declare` transaction, no privileged access required.

### Likelihood Explanation
Reaching this requires the declarer to submit a Sierra program that the compiler will segment into a very deep tree, which needs some understanding of the segmentation algorithm in `cairo-lang-starknet-classes`, but no privileged access, and the segmentation is fully deterministic given the submitted Sierra bytecode/control flow. The lack of any depth cap (contrasted with the explicit depth-1 cap enforced elsewhere in the blockifier for a related structure) indicates the deep-nesting case was not defended against on these two code paths. Given size limits on `sierra_program`/`contract_class_object_size` bound the total bytecode but not tree depth specifically, an attacker has room to trade off segment count vs. depth to maximize recursion depth within the size budget.

### Recommendation
- Add an explicit maximum recursion depth check (mirroring the `assert!(segmentation_depth <= 1, ...)` pattern already used in `blockifier/src/execution/contract_class.rs`) to `bytecode_hash_node` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs` and to `create_bytecode_segment_structure_inner` in `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`, returning a validation error instead of panicking/recursing past the limit.
- Alternatively/additionally, convert both functions to iterative (explicit stack/work-list based) traversal so depth is bounded only by available heap, not native stack.
- Validate `bytecode_segment_lengths` depth/shape immediately after Sierra→CASM compilation in the gateway (stateless/compilation validation step), rejecting classes whose segment tree exceeds a sane maximum depth, before the class is admitted to the mempool or hashed.

### Proof of Concept
Conceptual PoC (cannot be executed in this environment, but the code path is deterministic):
1. Author a Sierra program whose control-flow/segmentation causes the compiler to emit a `CasmContractClass.bytecode_segment_lengths` value equivalent to `NestedIntList::Node(vec![NestedIntList::Node(vec![NestedIntList::Node(...)])])` nested to a depth of e.g. 100,000+ (achievable within the existing `max_contract_bytecode_size`/`max_contract_class_object_size` gateway limits by keeping each segment minimal, e.g. `Leaf(1)`, while maximizing nesting depth).
2. Submit this class via a `DECLARE` transaction (`RpcDeclareTransaction::V3`) through the gateway (`add_tx` → `stateless_transaction_validator.validate` → Sierra→CASM compilation).
3. During execution, `DeclareTransaction::run_execute` → `check_compile_class_hash_v2_declaration` → `casm.hash(&HashVersion::V2)` → `bytecode_hash` → `bytecode_hash_node` recurses once per nesting level with no depth check, exhausting the thread stack and crashing the process: [8](#0-7) 
4. If the class instead reaches a block that gets re-executed by the Starknet OS/prover, `load_classes_and_create_bytecode_segment_structures` → `create_bytecode_segment_structure` → `create_bytecode_segment_structure_inner` similarly recurses unbounded and crashes the OS re-execution/proving process.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

/// Returns the compiled class hash (v2) of the given class hash.

    }

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Hint extensions.
pub(crate) fn load_classes_and_create_bytecode_segment_structures<S: StateReader>(
    hint_processor: &mut SnosHintProcessor<'_, S>,
    mut ctx: HintContext<'_>,
) -> OsHintExtensionResult {
    let identifier_getter = ctx.program;
    let mut hint_extension = HintExtension::new();
    let mut compiled_class_facts_ptr = ctx.vm.add_memory_segment();
    let mut bytecode_segment_structures = BTreeMap::new();
    // Insert n_compiled_class_facts, compiled_class_facts.
    ctx.insert_value(Ids::CompiledClassFacts, compiled_class_facts_ptr)?;
    ctx.insert_value(Ids::NCompiledClassFacts, hint_processor.compiled_classes.len())?;
    // Iterate only over cairo 1 classes.
    for (compiled_class_hash, compiled_class) in hint_processor.compiled_classes.iter() {
        let compiled_class_fact = CompiledClassFact { compiled_class_hash, compiled_class };
        compiled_class_fact.load_into(
            ctx.vm,
            identifier_getter,
            compiled_class_facts_ptr,
            &ctx.program.constants,
        )?;

        // Compiled classes are expected to end with a `ret` opcode followed by a pointer to
        // the builtin costs.
        let bytecode_ptr_address = get_address_of_nested_fields_from_base_address(
            compiled_class_facts_ptr,
            CairoStruct::CompiledClassFact,
            ctx.vm,
            &["compiled_class", "bytecode_ptr"],
            identifier_getter,
        )?;
        let bytecode_ptr = ctx.vm.get_relocatable(bytecode_ptr_address)?;
        let builtin_costs = ctx.get_ptr(Ids::BuiltinCosts)?;
        let encoded_ret_opcode = 0x208b7fff7fff7ffe;
        let data = [encoded_ret_opcode.into(), builtin_costs.into()];
        ctx.vm.load_data((bytecode_ptr + compiled_class.bytecode.len())?, &data)?;

        // Extend hints.
        for (rel_pc, hints) in compiled_class.hints.iter() {
            let abs_pc = Relocatable::from((bytecode_ptr.segment_index, *rel_pc));
            hint_extension.insert(abs_pc, hints.iter().map(|h| any_box!(h.clone())).collect());
        }

        bytecode_segment_structures.insert(
            *compiled_class_hash,
            create_bytecode_segment_structure(
                &compiled_class.bytecode.iter().map(|x| Felt::from(&x.value)).collect::<Vec<_>>(),
                compiled_class.get_bytecode_segment_lengths(),
            )?,
        );

    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
    }
