### Title
Unbounded, non-deduplicated growth of per-shop session-id index enables DoS of session storage/auth handlers - (File: `packages/apps/session-storage/shopify-app-session-storage-kv/src/kv.ts`)

### Summary
`KVSessionStorage.storeSession` calls `addShopIds`, which appends the session id to the `shop:<shop>` index array on every call without checking whether the id already exists in the array. [1](#0-0) [2](#0-1)  Because online session ids are deterministic (`shop_userId`) and every OAuth completion (i.e., every time a merchant/staff user re-authenticates) invokes `storeSession` again for the same id, the shop's index array grows by one duplicate entry per authentication with no cap and no dedup.

### Finding Description
This mirrors the LlamaPolicy DoS pattern: a routine, unprivileged, repeatable action (there: creating a Llama governance action; here: completing OAuth as an online/embedded session) writes into an unbounded list with no rate limit or size check, eventually breaking a downstream consumer of that list.

- `storeSession` is called at the end of every OAuth callback via `createSession`, and online session ids are derived deterministically from `getJwtSessionId(shop, userId)`, meaning the same id is reused across repeated logins by the same user. [3](#0-2) [4](#0-3) 
- `addShopIds` unconditionally concatenates new ids onto the existing array and persists it back to the KV key `shop:<shop>` — there is no `Set`/dedup logic and no bound on array length. [2](#0-1) 
- This index is later read in full by `findSessionsByShop`, which loads **every** id in the array (duplicates included) via `Promise.all`, and this function is depended upon by app-uninstall/session cleanup logic (`AppInstallations.includes`/`AppInstallations.delete`), which is invoked from the webhook-driven app-uninstalled handler. [5](#0-4) [6](#0-5) 

Repeated re-authentication by a single, unprivileged merchant/staff user (a completely normal, unthrottled action — no login limiting exists in `begin`/`callback` beyond a bot check) can therefore inflate the `shop:<shop>` array without bound. [7](#0-6) 

### Impact Explanation
As the index array grows unbounded:
- KV value-size limits can eventually be hit on `put`, causing `storeSession`/`addShopIds` to fail for that shop, which can break subsequent OAuth completions for the tenant.
- `findSessionsByShop` becomes progressively more expensive (duplicate reads via `Promise.all`), which is used by uninstall/cleanup flows (`AppInstallations.includes`/`delete`), degrading or breaking webhook-triggered session cleanup and app-uninstall processing for that shop — a DoS on an auth/session-management code path, analogous to the referenced report's DoS of the policy/role-change mechanism.
- The attack is achievable by any single already-authenticated user of an app (no elevated privilege) by simply repeating the OAuth flow, i.e., the low-cost, linear-cost DoS vector cited as the reason the original finding was rated Medium.

### Likelihood Explanation
Medium: the KV session storage adapter is one of several official storage packages shipped in this repo and is intended for production use (e.g., Cloudflare Workers apps). The trigger requires no special privilege — an app user simply needs to visit/complete the OAuth flow repeatedly (a script hitting `/auth`/`/auth/callback` in a loop), which is unauthenticated from the app's perspective at the time `begin`/`callback` execute. There is no rate limiting on the OAuth begin/callback endpoints beyond a `isbot` check. [8](#0-7) 

### Recommendation
In `KVSessionStorage.addShopIds` (and `removeShopIds`), deduplicate before persisting — e.g., use a `Set` to merge ids, or check `includes` before appending — and consider adding an upper bound / TTL-based pruning of stale ids in the shop index, mirroring the general recommendation from the referenced report to cap unbounded growth from repeated actions by a single actor. [2](#0-1) 

### Proof of Concept
1. Configure an embedded app using `KVSessionStorage` for session persistence.
2. As a single authorized staff user of an installed shop, repeatedly trigger the OAuth online-access flow (hit `/auth?shop=...` then complete `/auth/callback`) many times in a loop — each completion calls `shopify.auth.callback` → `createSession` → `storeSession`. [4](#0-3) 
3. Each call appends the same deterministic `shop_userId` id again to the KV array under `shop:<shop>` via `addShopIds`, since there is no dedup check. [2](#0-1) 
4. Observe the `shop:<shop>` KV value growing linearly with each login; eventually `findSessionsByShop` performs a proportionally growing number of duplicate reads, and/or the `put` call fails once KV's per-value size limit is reached, breaking `AppInstallations.includes`/`delete` (used in uninstall webhook cleanup) for that shop. [6](#0-5)

  private async addShopIds(shop: string, ids: string[]) {
    const key = this.getShopSessionIdsKey(shop);
    const shopIds = (await this.namespace.get<string[]>(key, 'json')) ?? [];
    await this.namespace.put(key, JSON.stringify([...shopIds, ...ids]));
  }

    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);
    if (shopSessions.length > 0) {
      for (const session of shopSessions) {
        if (session.accessToken) return true;
      }

    const shopSessions =
      await this.sessionStorage.findSessionsByShop!(shopDomain);

      await this.sessionStorage.deleteSessions!(
        shopSessions.map((session: Session) => session.id),

export function begin(config: ConfigInterface): OAuthBegin {
  return async ({
    shop,
    callbackPath,
    isOnline,
    ...adapterArgs
  }: BeginParams): Promise<AdapterResponse> => {
    throwIfCustomStoreApp(
      config.isCustomStoreApp,
      'Cannot perform OAuth for private apps',
    );

    const log = logger(config);
    log.info('Beginning OAuth', {shop, isOnline, callbackPath});

    const request = await abstractConvertRequest(adapterArgs);
    const response = await abstractConvertIncomingResponse(adapterArgs);

    let userAgent = request.headers['User-Agent'];
    if (Array.isArray(userAgent)) {
      userAgent = userAgent[0];
    }
    if (isbot(userAgent)) {
      logForBot({request, log, func: 'begin'});
      response.statusCode = 410;
      return abstractConvertResponse(response, adapterArgs);
    }

    const cookies = new Cookies(request, response, {
      keys: [config.apiSecretKey],
      secure: true,
    });

    const state = nonce();

    await cookies.setAndSign(STATE_COOKIE_NAME, state, {
      expires: new Date(Date.now() + 60000),
      sameSite: 'lax',
      secure: true,
      path: callbackPath,
    });

    const scopes = config.scopes ? config.scopes.toString() : '';
    const query = {
      client_id: config.apiKey,
      scope: scopes,
      redirect_uri: `${config.hostScheme}://${config.hostName}${callbackPath}`,
      state,
      'grant_options[]': isOnline ? 'per-user' : '',
    };
    const processedQuery = new ProcessedQuery();
    processedQuery.putAll(query);

    const cleanShop = sanitizeShop(config)(shop, true)!;
    const redirectUrl = `https://${cleanShop}/admin/oauth/authorize${processedQuery.stringify()}`;
    response.statusCode = 302;
    response.statusText = 'Found';
    response.headers = {
      ...response.headers,
      ...cookies.response.headers!,
      Location: redirectUrl,
    };

    log.debug(`OAuth started, redirecting to ${redirectUrl}`, {shop, isOnline});

    return abstractConvertResponse(response, adapterArgs);
  };
