### Title
Open Redirect via Missing Origin/Domain Check in `sanitizeRedirectUrl` — ([File: packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts])

### Summary
`sanitizeRedirectUrl` is meant to validate that a redirect destination stays "safe" relative to a given `domain`, but — exactly like the `mint_position` bug where `lower < upper` is never validated even though downstream tick-math code implicitly assumes it — this function never validates the invariant its callers assume: that the resulting URL's **origin matches `domain`**. It only checks protocol, absence of `file://`/whitespace, and double-slash path patterns, then blindly does `new URL(redirectUrl, domain)`. Because `URL(url, base)` ignores `base` whenever `url` is already absolute, an attacker-supplied absolute URL to any external HTTPS host passes every check.

### Finding Description
`isSafe()` in [1](#0-0)  validates:
- not a `file:///` URI
- no whitespace
- parses as a `URL` against the base `domain`
- pathname has no `//` sequences
- protocol is `http:`/`https:` (optionally forcing `https:` only)

It never checks `url.origin === new URL(domain).origin` (or otherwise pins the host to `domain`). The exported `sanitizeRedirectUrl` [2](#0-1)  then returns `new URL(redirectUrl, domain)` as "sanitized" — but if `redirectUrl` is itself absolute (e.g. `https://evil.example.com/phish`), the JS `URL` constructor discards `domain` entirely and returns the attacker's own absolute URL untouched.

This function is used by `renderAppBridge` to build a `window.open(destination, target)` redirect script served directly to the browser: [3](#0-2) . The `redirectTo.url` value passed into `renderAppBridge` traces back to the `exitIframe` query-string parameter on the app's `/auth/exit-iframe` route, which is directly attacker-controlled and reachable by any unauthenticated request/link click — confirmed by the existing test suite, which only asserts rejection of `file:///...` URLs and acceptance of relative paths, never testing (or rejecting) a cross-origin absolute `https://` URL: [4](#0-3) . The identical helper/pattern exists in the React Router package: [5](#0-4) .

### Impact Explanation
An attacker can craft a link such as `https://<merchant-app>/auth/exit-iframe?exitIframe=https%3A%2F%2Fattacker.example.com%2Fphish&shop=<any-shop>.myshopify.com`. When a merchant/admin clicks it (e.g. from inside the Shopify Admin iframe or directly), the app renders App Bridge and executes `window.open("https://attacker.example.com/phish", "_top")`, redirecting the top-level browser window away from the legitimate app to an attacker-controlled page. This is a classic open-redirect that can be used for OAuth-adjacent phishing (the target page can mimic a Shopify login/consent screen to harvest credentials or session tokens) — no privileged actor or leaked secret is required, and it is reachable from a single unauthenticated request just as in the original report where an unprivileged actor bypassed an implicit ordering invariant that other trusted code paths relied on.

### Likelihood Explanation
High. The `/auth/exit-iframe` route and `renderAppBridge` are core, always-mounted parts of `shopify-app-remix`/`shopify-app-react-router` embedded-app authentication flow, triggered on ordinary navigation/re-auth bounces. Exploitation requires only that a merchant click a link containing the `exitIframe` parameter — no authentication, no HMAC bypass, and no race condition needed.

### Recommendation
In `isSafe()` (both `shopify-app-remix` and `shopify-app-react-router` copies of `validate-redirect-url.ts`), enforce that the resolved URL's origin equals the trusted `domain`'s origin for any absolute redirect target, i.e. add:
```ts
const domainOrigin = new URL(domain).origin;
if (url.origin !== domainOrigin) {
  return false;
}
```
before returning `true`, unless the app explicitly opts into cross-origin redirects via an allowlist. This restores the invariant the rest of the redirect logic (and the `renderAppBridge` `window.open` call) implicitly assumes.

### Proof of Concept
1. Deploy a `shopify-app-remix` (or `shopify-app-react-router`) embedded app with default config.
2. As an unauthenticated actor, send/host a link:
   ```
   https://<app-host>/auth/exit-iframe?exitIframe=https%3A%2F%2Fattacker.example.com%2Fphish&shop=example.myshopify.com
   ```
3. Observe the HTML response contains:
   ```html
   <script>window.open("https://attacker.example.com/phish", "_top")</script>
   ```
   confirming `sanitizeRedirectUrl(config.appUrl, "https://attacker.example.com/phish")` did not reject the cross-origin absolute URL (contrast with the existing test that only proves `file:///...` is rejected: [4](#0-3) ).
4. A victim merchant clicking the link is redirected out of the legitimate app to the attacker's page.

function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
