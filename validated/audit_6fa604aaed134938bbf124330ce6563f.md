## Finding: Spot-price Uniswap V3 quote enables sandwich extraction of user inbound funds during gas-abstraction auto-swap

Push Chain's native analog to the bonding-curve MEV report is the **`GetSwapQuote` → `CallPRC20DepositAutoSwap`** sequence used to convert a bridged-in gas token into native PC on behalf of the user, and the mirror-image refund path in `applyGasRefund`.

### Title
Unbounded spot-price slippage tolerance in `uexecutor` auto-swap lets an unprivileged attacker sandwich inbound GAS/GAS_AND_PAYLOAD deposits - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
For `TxType_GAS` and `TxType_GAS_AND_PAYLOAD` inbounds, the core validator fetches a Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote and derives `minPCOut = quote * 95 / 100` — a fixed 5% band around whatever the pool's instantaneous price is at execution time [1](#0-0) . This same pattern is reused for the excess-gas refund swap in `applyGasRefund` [2](#0-1) . There is no TWAP, no price-impact cap, and no minimum-liquidity check — `GetSwapQuote` is a plain, un-cached spot call to `QuoterV2` [3](#0-2) .

### Finding Description
The inbound execution (quote fetch + swap) runs atomically inside a single keeper call, triggered the moment a `MsgVoteInbound` finalizes the ballot (2/3 UV threshold reached) [4](#0-3) . Because Push Chain is a normal CometBFT/EVM chain, the finalizing vote transaction sits in the mempool like any other transaction before being included in a block, and any unprivileged account can submit ordinary EVM swap transactions against the same PRC20↔WPC Uniswap V3 pool used by `QuoterV2`.

An attacker (no special role required) can:
1. Observe a pending `MsgVoteInbound` transaction that will finalize an inbound ballot of type GAS/GAS_AND_PAYLOAD (or an outbound observation that will trigger `applyGasRefund`).
2. Submit a large swap against the PRC20/WPC pool immediately before it in the same block, pushing the spot price in the direction that inflates `quote`.
3. Let the finalizing transaction execute — `GetSwapQuote` reads the now-manipulated spot price, computes `minPCOut = quote*0.95`, and `CallPRC20DepositAutoSwap` executes against the manipulated pool, still satisfying the (also-manipulated) floor.
4. Submit a reverse swap immediately after to restore the pool price, capturing the value transferred out of the user's bridged deposit.

Because `minPCOut` is derived from the same manipulated price it's meant to protect against, the 5% band gives no real protection — it only bounds slippage relative to an already-corrupted reference price, exactly the "consumer surplus" MEV pattern described in the source report. There is no honest-price benchmark (TWAP), no block-delay/freeze between quoting and swapping, and no cap on price impact per trade.

### Impact Explanation
Every GAS / GAS_AND_PAYLOAD inbound deposit, and every excess-gas refund, funds a Uniswap V3 swap that is economically executed at attacker-influenced prices instead of fair market prices. This is a direct, repeatable value extraction from user-owned bridged funds (the amount of PC ultimately credited to the recipient UEA can be pushed as low as `quote*0.95` under an attacker-inflated `quote`), i.e. partial draining of protocol/user-controlled funds on essentially every inbound gas-abstraction swap, particularly in the low-liquidity PRC20/WPC pools that are typical for newly bridged assets.

### Likelihood Explanation
High. No privileged role is needed — sandwiching a visible pending transaction against a low-liquidity pool with ordinary EVM transactions is a well-known, cheap, and automatable MEV strategy. The vulnerability triggers on the default execution path of every GAS/GAS_AND_PAYLOAD inbound and every gas refund with excess fee, i.e. on ordinary user bridge activity with no attacker-side privilege beyond capital to move the pool.

### Recommendation
- Use a manipulation-resistant reference price (e.g., a TWAP over several blocks, or an oracle price) instead of the instantaneous `QuoterV2` spot quote to compute `minPCOut`.
- Alternatively/additionally, cap the maximum allowed price impact of the protocol's own swap and abort/hold (rather than proceed at a worse rate) if the underlying pool's recent volatility exceeds a threshold.
- Consider separating quote computation from execution by at least one block (this mirrors the report's "1 block freeze" recommendation), or restricting protocol swaps to designated deep-liquidity pools/pairs with governance-set minimum liquidity guards.

### Proof of Concept
1. Bridge in a GAS inbound for token `T` with a thin `T/WPC` Uniswap V3 pool on Push Chain.
2. Observe the `MsgVoteInbound` transaction from the last required Universal Validator sitting in mempool (2/3 threshold about to be reached).
3. Submit `swapExactTokensForTokens` (attacker capital) against the `T/WPC` pool right before it, in the same block, to inflate `T`'s WPC price.
4. Let the `MsgVoteInbound` land; the keeper's `GetSwapQuote`→`CallPRC20DepositAutoSwap` executes against the inflated price, giving the bridging user fewer WPC than fair value while `minPCOut` is trivially satisfied (it was computed off the same inflated quote).
5. Submit a reverse swap to restore the pool price and realize the arbitrage profit extracted from the user's deposit. [5](#0-4) [6](#0-5)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
