## Title
Spot-price AMM quoting (no TWAP) for deposit/refund auto-swaps enables sandwich-attack value extraction from user deposits and gas refunds - (File: x/uexecutor/keeper/evm.go)

### Summary
The external report describes LP/AMM spot-price manipulation used to compute a critical asset value (LP token price via instantaneous pool reserves), allowing an attacker to inflate/deflate the price within a single block with no counter-risk. Push Chain's `x/uexecutor` module has a structurally identical pattern: `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) queries the *instantaneous* Uniswap V3 `QuoterV2.quoteExactInputSingle` spot price for the internal PRC20↔WPC pool and uses it, with only a fixed 5% slippage buffer, to authorize real on-chain swaps of user-deposited funds and gas refunds.

### Finding Description
Two flows compute `minPCOut` from a single spot-price read and then immediately execute a real swap against the same pool:

1. **Inbound gas/gas-and-payload deposits** — `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:103-153`) and `gasAndPayloadDepositAutoSwap` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:347-379`) call:
   - `GetDefaultFeeTierForToken` → `GetSwapQuote` (spot quote via `quoteExactInputSingle`, `SqrtPriceLimitX96: 0`) [1](#0-0) 
   - `minPCOut := quote * 95 / 100` [2](#0-1) 
   - `CallPRC20DepositAutoSwap` executes the real `depositPRC20WithAutoSwap` swap against the live pool state with only this 5% floor. [3](#0-2) 

2. **Outbound gas refunds** — `applyGasRefund` (`x/uexecutor/keeper/outbound.go:174-256`) performs the identical pattern (`getSwapQuoteForRefund` → 5% slippage → `CallUniversalCoreRefundUnusedGas` with `withSwap=true`) to swap the refunded gas token back to native PC. [4](#0-3) 

There is no TWAP, no oracle cross-check, and no pool-depth/liquidity sanity check anywhere in this path — `grep` for `TWAP`/`observe(` across the repo only matches the same `evm.go`/`abi.go` files that implement this spot-quote logic, confirming no time-weighted protection exists. Because the underlying PRC20/WPC Uniswap V3 pools are protocol-deployed and likely to have limited depth (especially for newly bridged/low-volume tokens), an unprivileged actor can:
- Submit a large swap against the target PRC20/WPC pool in a transaction ordered immediately before the block/transaction in which an inbound deposit (or outbound gas refund) is executed, shifting the spot price beyond the 5% band.
- The subsequent module-triggered auto-swap (`depositPRC20WithAutoSwap` / `refundUnusedGas` with `withSwap=true`) is forced to execute at this attacker-manipulated price since the quote and the swap read the *same*, already-manipulated pool state — the 5% slippage buffer does not protect against pre-existing price displacement, only against price movement between the quote and the swap (which is ~zero here, since both happen back-to-back in the same keeper flow).
- The attacker then reverses their initial swap, extracting the price impact absorbed by the protocol's forced swap of user deposit / refund funds, at the direct expense of the depositor/refund recipient (and indirectly the pool's other LPs).

### Impact Explanation
This directly causes loss of user/protocol-controlled funds: the value a depositor's bridged asset converts to (WPC credited to their UEA) or the value refunded to a sender's account can be reduced below fair market value by a manipulated pool price, with the attacker capturing the difference. This falls squarely within the "Registry and accounting path" and "unauthorized loss of user or protocol-controlled funds" impact categories, mirroring the external report's LP mispricing/Warp-Finance-style value extraction, but here manifesting as sandwichable swaps on deposit and refund paths rather than an LP-token oracle price.

### Likelihood Explanation
Reachable by any unprivileged actor who can (a) hold or acquire enough of the relevant token pair to move the specific PRC20/WPC pool's price beyond ~5%, and (b) time a transaction relative to the block in which an inbound/outbound is finalized and executed — feasible especially for low-liquidity or newly-onboarded token pools, and does not require validator, relayer, or governance privilege. The fixed 5% band is a static, guessable, and often-insufficient bound for thin pools, so likelihood scales inversely with pool depth, which the protocol does not otherwise enforce or monitor.

### Recommendation
Replace or supplement the instantaneous `QuoterV2.quoteExactInputSingle` spot quote with a manipulation-resistant reference price: e.g., a Uniswap V3 TWAP observation over a meaningful window (using `observe()`), a protocol-managed price oracle, or a minimum-liquidity/maximum-price-impact guard before allowing the auto-swap to proceed. Consider also making the slippage tolerance a function of observed pool depth rather than a flat 5%, and adding a circuit breaker that reverts to the no-swap deposit/refund path when quoted price deviates significantly from a TWAP reference.

### Proof of Concept
1. Identify a PRC20/WPC Uniswap V3 pool deployed by `UniversalCore` for a token with low liquidity (`GetUniversalCoreQuoterAddress` / `GetDefaultFeeTierForToken`, `x/uexecutor/keeper/evm.go:422-498`).
2. Front-run: swap a large amount into/out of that pool to shift the spot price beyond 5%.
3. Trigger (or wait for) an inbound `GAS`/`GAS_AND_PAYLOAD` deposit of that token to be finalized/executed (`ExecuteInboundGas`/`ExecuteInboundGasAndPayload`), which internally calls `GetSwapQuote` then `CallPRC20DepositAutoSwap` against the now-manipulated pool state. [5](#0-4) 
4. Back-run: reverse the initial swap, capturing the price impact absorbed by the protocol's forced auto-swap, leaving the depositor's UEA credited with less WPC value than fair market price.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
