### Title
Unvalidated `RevertInstructions.FundRecipient` address routes refunded/re-minted funds to malformed or unintended addresses - (File: `x/uexecutor/types/inbound.go`, `x/uexecutor/keeper/build_revert_outbound.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The external report flags `VestingSplitter.sol` for accepting a contract address without a sanity check, letting the caller redirect the contract's calls to an arbitrary/unintended address. The native analog in Push Chain is `Inbound.RevertInstructions.FundRecipient`: unlike `Inbound.Recipient`, which is explicitly format-checked with `utils.IsValidAddress(p.Recipient, utils.HEX)` in `ValidateForExecution`, `FundRecipient` is never validated for being a well-formed EVM/source-chain address anywhere in the inbound validation pipeline before it is used to route refunded or re-minted PRC20/native tokens.

### Finding Description
`Inbound.RevertInstructions` is a user/attacker-influenced field (originating from source-chain event data observed and voted on by Universal Validators) that carries a `fund_recipient` string [1](#0-0) . During canonicalization it only goes through `LenientCanonicalizeAddress`, which is explicitly documented as never rejecting malformed values ("lenient... unparseable values are kept trimmed, never rejected") [2](#0-1) .

Both `ValidateBasic` (vote-acceptance checks) and `ValidateForExecution` (pre-execution checks) validate `Recipient` with `utils.IsValidAddress(p.Recipient, utils.HEX)` for FUNDS/GAS/CEA paths, but neither function performs any equivalent check on `RevertInstructions.FundRecipient` [3](#0-2) .

This unchecked value is then used directly as the destination of value-moving operations:
- `buildRevertOutbound` sets the INBOUND_REVERT outbound's `Recipient` straight from `FundRecipient` with no format check [4](#0-3) .
- `handleFailedOutbound` passes it straight into `common.HexToAddress(recipient)` to re-mint bridged PRC20 tokens back on a failed outbound [5](#0-4) .
- The rescue-funds outbound-building path does the same [6](#0-5) .

`common.HexToAddress` in go-ethereum does not error on malformed input — it decodes whatever valid hex characters exist and left-pads/truncates the result to 20 bytes, silently producing an address (potentially `0x000...000`, or a completely different address than intended) instead of failing.

### Impact Explanation
If a source-chain event, an admin-triggered `RevertStuckInbound`, or a failed outbound observation carries a malformed or otherwise attacker-influenced `FundRecipient` value, refunded/re-minted PRC20 or native assets can be minted to the zero address or an unintended address instead of the rightful depositor. This is a concrete instance of "unauthorized mint" / "permanent loss" / "permanent freezing" of protocol-bridged funds during the revert/refund accounting path, matching the required impact categories for this scope.

### Likelihood Explanation
Moderate. The field is not directly attacker-supplied on Push Chain itself (it originates through the Universal Validator's decode of source-chain event data), so exploitation depends on how permissive the upstream `universalClient` decoding of `FundRecipient` is for a given source chain, and on the honest-validator assumption holding for everything except this specific unchecked field. Because it is the *only* address-carrying field in `Inbound` that skips the `IsValidAddress` check applied to `Recipient`, it stands out as an inconsistency versus the rest of the validation surface, indicating this is a genuine gap rather than an intentional design choice.

### Recommendation
Add the same `utils.IsValidAddress(p.RevertInstructions.FundRecipient, utils.HEX)` check used for `Recipient` inside `ValidateForExecution` (and/or fall back safely to `Sender` when the recipient fails validation, as already happens when `FundRecipient` is empty), so that a malformed or non-canonical `FundRecipient` cannot silently resolve to the zero address or an unintended address in `buildRevertOutbound`, `handleFailedOutbound`, and `AttachRescueOutboundFromReceipt`.

### Proof of Concept
Not independently reproduced against a running node in this pass; the analysis is based on static tracing of `RevertInstructions.FundRecipient` through `Canonicalize`, `ValidateBasic`, `ValidateForExecution`, `buildRevertOutbound`, and `handleFailedOutbound`. A full PoC would require constructing an `Inbound` with a malformed `RevertInstructions.FundRecipient` (e.g. an odd-length or non-hex string) that still passes `ValidateBasic`/`ValidateForExecution`, driving it to a failed deposit or failed outbound, and observing that `common.HexToAddress` resolves the mint destination to an unintended address — this final confirmation step was not completed due to end of investigation budget.

// Canonicalize normalizes encoding-variant fields in place (per source-chain
// namespace) so the same event from any observer is byte-identical across
// ballot keys, UTX keys and registry lookups. Lenient (unparseable values are
// kept trimmed, never rejected) because the vote path must always record a
// UTX — execution-level validation rejects malformed inbounds later.
func (p *Inbound) Canonicalize() {
	p.SourceChain = strings.TrimSpace(p.SourceChain)
	p.TxHash = utils.LenientCanonicalizeTxHash(p.SourceChain, p.TxHash)
	p.Sender = utils.LenientCanonicalizeAddress(p.SourceChain, p.Sender)
	p.AssetAddr = utils.LenientCanonicalizeAddress(p.SourceChain, p.AssetAddr)
	// Recipient lives on Push Chain (EVM) regardless of source chain.
	p.Recipient = utils.LenientCanonicalizeEVMAddress(p.Recipient)
	p.LogIndex = strings.TrimSpace(p.LogIndex)
	p.Amount = strings.TrimSpace(p.Amount)
	p.RawPayload = utils.CanonicalizeHexBlob(p.RawPayload)
	p.VerificationData = utils.CanonicalizeHexBlob(p.VerificationData)
	if p.RevertInstructions != nil {
		// Refunds return to the source chain.
		p.RevertInstructions.FundRecipient = utils.LenientCanonicalizeAddress(p.SourceChain, p.RevertInstructions.FundRecipient)
	}
}

// ValidateForExecution checks fields that are required for actual execution of the inbound.
// Called after ballot finalization, before ExecuteInbound. Failures here produce a failed
// PCTx and (for non-isCEA) a revert outbound, rather than dropping the vote.
func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}
