## Title
Front-runnable sandwich attack on the fixed 5%-slippage AMM auto-swap used for inbound gas deposits and outbound gas refunds - (File: `x/uexecutor/keeper/gas_fee.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The `SafeguardPool` report's bug class is: a value derived from a price source is fetched and then relied upon for a fund-moving operation with only a tolerance band around it, and an attacker can profitably manipulate the price around that operation because the tolerance band is not tight enough / the price source is not protected against manipulation in the same transaction window. Push Chain has a structurally identical pattern in its GAS and GAS_AND_PAYLOAD inbound-deposit auto-swap and outbound gas-refund auto-swap flows: the module fetches a live spot quote from an on-chain Uniswap-V3-style `QuoterV2` and then executes the swap using only a fixed 5% slippage tolerance derived from that same instantaneous quote, with no TWAP or other manipulation resistance.

### Finding Description
`GetSwapQuote` in [1](#0-0)  calls `QuoterV2.quoteExactInputSingle` to get the current spot-price-derived output amount for a `prc20 → wpc` swap. This quote is immediately used to derive `minPCOut = quote * 95 / 100` (a flat 5% slippage tolerance) and then a swap is executed via `CallPRC20DepositAutoSwap` in the same keeper call, as seen in:
- the GAS inbound auto-swap path in [2](#0-1) 
- the GAS_AND_PAYLOAD auto-swap path `gasAndPayloadDepositAutoSwap` in [3](#0-2) 
- the outbound excess-gas refund swap in `applyGasRefund` in [4](#0-3) 

These auto-swaps are all triggered synchronously as a side effect of an ordinary user-reachable, honest-validator-driven flow: an inbound's `MsgVoteInbound` reaching quorum (`VoteInbound` → `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`), or an outbound's `MsgVoteOutbound` reaching quorum (`VoteOutbound` → `handleSuccessfulOutbound`/`handleFailedOutbound` → `applyGasRefund`). None of these messages are gasless-restricted from mempool visibility, and the underlying pool (reachable via the `UniversalCore`/`QuoterV2` Uniswap-style AMM deployed as a system contract) is a normal on-chain contract that any unprivileged account can trade against in the same block.

Because the quote is a spot price with no TWAP, and the tolerance is a flat 5%, an unprivileged attacker who observes the pending finalizing vote transaction can sandwich it exactly like a peg-toggle front-run in the report: push the pool price against the module's swap direction just before it lands (still within the 5% band so the swap does not revert), let the module's deposit/refund swap execute at the worse price, then reverse the trade afterward to capture the difference. This directly reduces the PC the end-user's UEA receives on GAS/GAS_AND_PAYLOAD deposits and reduces the PC recovered by the refund recipient on outbound gas refunds — an unprivileged attacker skimming value out of ordinary user deposits/refunds without needing any malicious validator, admin, or TSS participant.

### Impact Explanation
Each individual sandwich is bounded by the 5% slippage tolerance, but it is a **guaranteed, repeatable, unprivileged value extraction** from every GAS/GAS_AND_PAYLOAD inbound deposit and every outbound gas refund that goes through the auto-swap path — directly analogous to the report's "guaranteed profit in frontrunning ... assuming a favorable quote is provided." This corrupts PRC20/native asset accounting for the affected user (they receive less PC than the fair-market swap would have produced) and siphons value from Push Chain's own liquidity pool, satisfying the "corruption of ... gas fee accounting, refund accounting ... native asset accounting" allowed-impact category with an unprivileged trigger (an ordinary trader submitting swap transactions timed around visible vote transactions).

### Likelihood Explanation
High. No validator, admin, or TSS collusion is required — only mempool visibility of the finalizing `MsgVoteInbound`/`MsgVoteOutbound` transaction and a swap capability against the same on-chain AMM pool, both of which are available to any unprivileged actor. The 5% band is wide enough to make sandwiching profitable on any pool with normal-to-thin liquidity, and this auto-swap path fires on every GAS-type inbound and every gas-refunding outbound, giving continuous attack surface.

### Recommendation
Do not rely on a same-block spot quote with a flat percentage tolerance for module-originated swaps. Options: use a TWAP-based quote (or a maximum deviation check against a TWAP) before accepting `minPCOut`, tighten and dynamically size the slippage tolerance to current pool depth, or route these mandatory system swaps through a mechanism resistant to same-block manipulation (e.g., a commit-reveal or minimum-liquidity-based cap) rather than a single quote-then-swap call pair.

### Proof of Concept
1. Attacker monitors the mempool for a `MsgVoteInbound` (or `MsgVoteOutbound`) transaction from the last validator needed to reach the 2/3 quorum threshold on an inbound of type GAS or GAS_AND_PAYLOAD (or an outbound whose gas refund will trigger `applyGasRefund`).
2. Attacker front-runs with a large swap against the `UniversalCore`/`QuoterV2` pool in the direction that will make `prc20 → wpc` (or `gasToken → wpc`) output worse.
3. The validator's vote transaction lands, `GetSwapQuote` returns the now-degraded spot price, `minPCOut = quote*95/100` is computed from that degraded price, and `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes the swap at (or above) that degraded but still-passing rate.
4. Attacker back-runs by reversing their trade, capturing the price difference at the expense of the value that should have gone to the end user's UEA balance or refund recipient.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
