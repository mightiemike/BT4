### Title
Parameter Pollution in App Proxy HMAC Validation Allows Customer ID Spoofing via `logged_in_customer_id` - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
The App Proxy HMAC validator normalizes repeated query parameters by joining their values with a comma before hashing, but only rejects duplicates for a small hard-coded set of parameters (`hmac`, `shop`, `signature`, `timestamp`). The security-sensitive `logged_in_customer_id` parameter — which apps are explicitly told in the official docs to trust via `searchParams.get("logged_in_customer_id")` after `authenticate.public.appProxy()` succeeds — is not in that protected set. This is the same class of defect as the reported `abi.encodePacked` collision: a value that is used for both an integrity check (the HMAC canonical string) and a separate downstream security decision (session/customer identity) is encoded/parsed inconsistently between the two paths, letting an attacker who fully controls the wire representation make both paths "agree" on a signature while disagreeing on the actual value trusted by the app.

### Finding Description
`normalizeQuery` in [1](#0-0)  only throws `InvalidHmacError` for duplicate values of keys in `APP_PROXY_SINGLE_VALUE_PARAMS`: [2](#0-1) 

For every other key, including `logged_in_customer_id`, duplicate values are silently merged into a single comma-joined string (`normalizedQuery[key] = `${existingValue},${value}`;`), and that same joining behavior is mirrored again in `stringifyQueryForAppProxy` when building the canonical string that is HMAC'd: [3](#0-2) 

The library's own test suite confirms this is by-design "repeated application params" behavior and that such requests pass validation: [4](#0-3) 

However, the official usage pattern documented for consuming apps reads the customer identity with `URLSearchParams.get()`, which returns only the **first** occurrence of a repeated key, not the comma-joined value used for hashing: [5](#0-4) 

The app-proxy authentication flow itself does nothing to protect `logged_in_customer_id` — it only validates the HMAC and returns, leaving the app to read `logged_in_customer_id` itself afterward: [6](#0-5) 

Because an app-proxy URL's query string originates from a link that an anonymous storefront visitor can construct (adding arbitrary extra query parameters before Shopify appends/forwards its own), a request containing two `logged_in_customer_id` values is a syntactically valid, HMAC-verifiable request under this library's canonicalization scheme — yet the two consumers of that same request (the signature check vs. the app's business logic) disagree on which value is authoritative.

### Impact Explanation
If a consuming app follows the documented pattern of trusting `searchParams.get("logged_in_customer_id")` after a successful `authenticate.public.appProxy()` call to determine "who is this customer," an attacker who can inject an extra `logged_in_customer_id` value ahead of the legitimate one (order-dependent on how the proxied query string is assembled) can cause the app to attribute the request to an arbitrary customer ID while the request's HMAC still validates. This is a cross-tenant/customer identity confusion issue in an authentication handler for anonymous app-proxy requests — the exact class of "accepted forged Shopify request" the analog rules call out.

### Likelihood Explanation
Exploitability depends on whether the concrete deployment/Shopify edge allows a duplicate `logged_in_customer_id` to reach the app (e.g., if Shopify's edge strictly overwrites rather than appends this parameter, the practical duplicate-injection vector is closed at the platform level and not by this library). Within the scope of this codebase, though, `hmac-validator.ts` provides no defense-in-depth for this specific parameter, unlike its explicit protection for `hmac`/`shop`/`signature`/`timestamp`, and the official SDK documentation actively encourages the exact `.get()` pattern that is unsafe if duplication does reach the app.

### Recommendation
Add `logged_in_customer_id` (and ideally `path_prefix`) to `APP_PROXY_SINGLE_VALUE_PARAMS` in [2](#0-1)  so that any duplicate occurrence causes `validateHmac` to reject the request outright, closing the parser-differential gap between HMAC canonicalization and downstream `.get()`-based consumption.

### Proof of Concept
1. An anonymous visitor is served (or constructs) an app-proxy link containing an injected duplicate: `.../apps/proxy/route?logged_in_customer_id=999&...&logged_in_customer_id=<real-value>&shop=...&timestamp=...&signature=...`.
2. `normalizeQuery` merges the two occurrences into `"999,<real-value>"` and `stringifyQueryForAppProxy` hashes that joined value; if this is the actual wire content Shopify's edge forwarded and signed, `validateHmac` returns `true` (as demonstrated by the existing repeated-param test at [4](#0-3) ).
3. The app's loader, following the documented pattern in [5](#0-4) , calls `searchParams.get("logged_in_customer_id")` and receives `"999"` (the attacker-controlled first value) instead of the real authenticated customer ID, despite the request having passed HMAC validation.

function stringifyQueryForAppProxy(query: AuthQuery): string {
  return Object.entries(query)
    .sort(([val1], [val2]) => val1.localeCompare(val2))
    .reduce((acc, [key, value]) => {
      return `${acc}${key}=${Array.isArray(value) ? value.join(',') : value}`;
    }, '');
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}
