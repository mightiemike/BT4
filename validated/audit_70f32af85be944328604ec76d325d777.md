### Title
Same-block AMM price manipulation degrades slippage protection on GAS/GAS_AND_PAYLOAD autoswap deposits - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/evm.go)

### Summary
The external report describes an attacker adding unauthorized value into a vault contract outside its official deposit path, which is later swept in a way that skews an internally trusted accounting figure (Lido share price). The Push Chain analog is the `GAS` and `GAS_AND_PAYLOAD` inbound autoswap path: `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` fetch a live Uniswap V3 quote via `k.GetSwapQuote` and derive `minPCOut` as a fixed 5% slippage band off that single, same-block quote, then immediately execute `CallPRC20DepositAutoSwap` against the same pool [2](#0-1) . Because the quote and the swap execution are two separate EVM calls (not covered by any TWAP or oracle protection), and the pool is an ordinary public Uniswap V3 pool that any unprivileged user can trade against, an attacker can move the pool price between the quote call and the deposit-with-swap call (or across the block boundary that the quorum-triggering vote lands in) to extract value from the user's bridged deposit while still satisfying the loose 5% slippage bound.

### Finding Description
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `commit=false` against the live pool state at the time of finalization [3](#0-2) . Immediately afterward, `minPCOut` is computed as `quote * 95 / 100` (a static 5% slippage tolerance) and passed into `CallPRC20DepositAutoSwap`, which performs the real swap via `depositPRC20WithAutoSwap` on the `UniversalCore` handler contract [4](#0-3) . The same pattern exists in the `GAS_AND_PAYLOAD` path via `gasAndPayloadDepositAutoSwap` [5](#0-4) .

The pool referenced (`prc20`/`WPC` pair, fee tier from `defaultFeeTier[prc20]`) is a standard, publicly tradeable Uniswap V3 pool, not a permissioned or protocol-only contract [6](#0-5) . There is no mechanism (TWAP oracle, price-impact cap tied to pool depth, or same-transaction atomicity guarantee) preventing an unprivileged actor from submitting ordinary swap transactions on Push Chain's own EVM immediately before the inbound-vote-triggering transaction executes, shifting the spot price the module reads. Because the module's only protection is a flat 5% band computed from that same manipulable spot price, an attacker who moves the price down before the quote call (or up before the deposit call) can widen the effective slippage the user's deposit absorbs, extracting value from the deposited bridged funds — analogous to how the Lido vault's balance (used to compute reward/share accounting) can be skewed by unauthorized externally-added value that the "official" mechanism blindly trusts.

### Impact Explanation
User-bridged `GAS`/`GAS_AND_PAYLOAD` inbound funds are auto-swapped into WPC as part of protocol-driven execution with no user-controlled slippage parameter; the only backstop is the module's own 5% band derived from a spot price an unprivileged actor can move. This can result in less value reaching the user's UEA than intended, i.e., partial loss/misappropriation of protocol/user-controlled funds during a standard, unprivileged, user-triggered deposit flow — squarely in scope under "corruption of ... gas fee accounting ... or canonical UniversalTx state" and "unauthorized ... state transitions in universal execution flows."

### Likelihood Explanation
Requires only ordinary EVM transactions against a public AMM pool timed around block inclusion of the vote-finalizing transaction — no validator, TSS, or admin privilege is needed. Feasibility depends on pool liquidity depth and block-proposer/mempool timing assumptions, which somewhat limits reliability, but the underlying protection (flat 5% band on a single spot quote, no TWAP) is a design weakness reachable by any user.

### Recommendation
Use a TWAP-based or otherwise manipulation-resistant price source for `minPCOut` computation rather than a single spot `quoteExactInputSingle` call, and/or fetch the quote atomically within the same EVM call/transaction as the swap execution so no attacker-controlled transaction can be interleaved between quoting and execution.

### Proof of Concept
1. Attacker monitors Push Chain mempool/block production for a pending inbound vote that will trigger `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` for a `prc20`/`WPC` pair with a known pool.
2. Immediately before the finalizing vote transaction is included, attacker submits a large swap on the same Uniswap V3 pool to move the spot price against the pending deposit direction.
3. `k.GetSwapQuote` (evm.go lines 500-538) reads the now-skewed price and `minPCOut` is derived as 95% of that skewed quote.
4. `CallPRC20DepositAutoSwap` executes the deposit swap at the skewed price, delivering the user materially less WPC than fair value would provide; attacker reverses their price-moving trade afterward to realize the extracted value, all without any privileged role.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
