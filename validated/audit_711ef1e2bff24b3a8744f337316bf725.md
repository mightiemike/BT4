### Title
Missing declared-class check in the OS's `execute_replace_class` diverges from Blockifier's validation, risking honest-node state disagreement - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall lets a contract, via an unprivileged `invoke` transaction, swap its own class hash. In Blockifier (the Rust execution engine that determines the actual sequenced block), this is validated: `SyscallHintProcessor::replace_class` calls `self.state.get_compiled_class(class_hash)?` (fails if undeclared) and explicitly rejects non-Cairo1 classes via `is_cairo1(...)` check, returning `SyscallExecutionError::ForbiddenClassReplacement` otherwise. [1](#0-0) 

In the Cairo Starknet OS program (`execute_replace_class` in `syscall_impls.cairo`), the equivalent logic performs **no such check** — it directly writes the caller-supplied `class_hash` into the contract's `StateEntry` with a `TODO` comment acknowledging the gap: [2](#0-1) 

The deprecated (Cairo0) syscall path in the OS (`execute_replace_class` in `deprecated_execute_syscalls.cairo`) has the identical omission.

### Finding Description
`replace_class` is directly reachable from any account's `__execute__` via an ordinary Invoke transaction — no special privileges required (see test harness usage in `test_contract.cairo`, e.g. `syscalls::replace_class_syscall(...)`). [3](#0-2) 

Blockifier's implementation of the syscall enforces two invariants before writing the new class hash into state:
1. The target `class_hash` must correspond to a declared class (`state.get_compiled_class(class_hash)?` errors on `UndeclaredClassHash`).
2. The target class must be Cairo1 (`is_cairo1`) — Cairo0 (V0) classes are forbidden as replacement targets. [1](#0-0) 
This is confirmed by dedicated tests asserting "is not declared" and "Cannot replace V1 class hash with V0 class hash" errors. [4](#0-3) 

The Cairo Starknet OS program — which re-executes the same block to produce/verify the STARK proof and the committed state — implements `execute_replace_class` without performing either check. It reads `request.class_hash`, builds a `new_state_entry` with that raw value, and commits it via `dict_update`, leaving only a `TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment as an admission that the check is missing: [5](#0-4) 

Because Blockifier and the OS are two independent implementations of the same state-transition function that are both meant to agree on execution outcomes (Blockifier sequences/executes the block; the OS re-executes it for proving and is the ground truth checked against the committed block hash by full nodes and provers), any behavioral divergence between them on a reachable code path is a soundness bug. Since Blockifier rejects (reverts) a `replace_class(class_hash)` call when `class_hash` is undeclared or Cairo0, while the OS's Cairo implementation of the exact same syscall unconditionally accepts and commits it, a transaction whose outcome depends on this check (revert vs. success) would be interpreted differently depending on which component evaluates it.

### Impact Explanation
If the OS is used to independently reconstruct/prove the state transition (rather than merely replaying Blockifier's already-computed outputs blindly), this discrepancy means the OS could compute a different final class hash / state entry / revert status for a contract than Blockifier did during actual sequencing — leading to a different state commitment (Patricia tree root) and thus a different block hash than the one produced by the sequencer. This falls squarely under "wrong committed root or block hash" / "honest-node divergence," since two conformant implementations of Starknet's state-transition rules would compute different outputs from the same input transaction.

### Likelihood Explanation
Likelihood is High for triggering the divergent code path itself, since `replace_class` is callable by any account contract with a single Invoke transaction and zero privileges — an attacker only needs to call it with an undeclared or Cairo0 `class_hash`. However, the actual severity depends on operational details not fully verifiable via static code search: whether the OS's acceptance of an unchecked class hash is later caught by a separate, later validation stage (e.g., during Patricia tree / commitment finalization when the class registry is consulted) that would still cause the OS run to fail before it produces a wrong root. I was unable to locate such a downstream check within the reachable OS state-commitment code in this pass, so this should be validated against the state commitment / class registry logic (`state.cairo`, `os.cairo`) before treating this as confirmed-exploitable rather than a latent, TODO-acknowledged soundness gap.

### Recommendation
Port Blockifier's validation logic into the OS's `execute_replace_class` (both the Cairo1 syscall path in `syscall_impls.cairo` and the deprecated path in `deprecated_execute_syscalls.cairo`): verify the supplied `class_hash` corresponds to a declared class (mirroring `state.get_compiled_class`), and reject Cairo0/V0 classes as replacement targets, matching the `ForbiddenClassReplacement` semantics enforced by Blockifier. Resolve the outstanding `TODO(Yoni, 1/1/2026)` before this code path can be considered safe for production proving/re-execution.

### Proof of Concept
Conceptual PoC (cannot be executed without running both Blockifier and the OS program against the same block):
1. Deploy an account contract exposing a `test_replace_class` entry point that calls the `replace_class` syscall with an attacker-controlled `class_hash` (as in `test_contract.cairo`). [6](#0-5) 
2. Submit an Invoke transaction calling this entry point with `class_hash` set to a value that has never been declared (or belongs to a Cairo0 class).
3. In Blockifier, this call fails: `state.get_compiled_class(class_hash)` returns `UndeclaredClassHash` (or `is_cairo1` check fails), causing the syscall/transaction to revert. [7](#0-6) 
4. Feeding the identical transaction/trace into the OS's `execute_replace_class` (Cairo) would not perform this check and would commit the new (undeclared/invalid) class hash into `contract_state_changes` unconditionally. [8](#0-7) 
5. This produces a state/class-hash discrepancy between what Blockifier committed to the block and what the OS would independently derive for the same transaction, which — depending on how the OS's output is consumed downstream (proving / full-node re-verification) — could manifest as a wrong committed root or block hash.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
