### Title
Gateway L2 gas price floor check is skipped for legacy/L1Gas-only resource bounds, allowing trivial bypass of the minimum-fee admission threshold - (File: crates/apollo_gateway/src/stateful_transaction_validator.rs)

### Summary
The gateway enforces a minimum L2 gas price ("fee floor") on incoming transactions before they are accepted into the mempool, intended to prevent underpriced transactions from being admitted. However this floor is only applied to `ValidResourceBounds::AllResources` (V3, all-resource) transactions; transactions submitted with `ValidResourceBounds::L1Gas` bounds explicitly skip the check entirely. Any unprivileged transaction sender can trivially construct a transaction using the L1Gas-only resource-bounds variant to bypass the minimum gas-price admission requirement, analogous to the Y2K report where a user bypasses a fee by routing through an alternate code path (deposit queue) that omits the fee logic applied on the normal path.

### Finding Description
`validate_resource_bounds` calls `validate_tx_l2_gas_price_within_threshold` to reject transactions whose L2 gas price bound is below a configurable percentage of the previous block's L2 gas price: [1](#0-0) 

The check itself only performs validation for the `AllResources` branch and takes no action for the `L1Gas` branch, explicitly commented as "No validation required for legacy transactions": [2](#0-1) 

Because `ValidResourceBounds` is attacker-controlled data embedded directly in the submitted transaction (a V1/legacy-shaped bounds structure vs. a V3 all-resource structure), any sender can choose to submit a transaction that resolves to the `L1Gas` variant to skip this floor entirely — mirroring the Y2K bug class where the fee-application code path can be trivially bypassed by choosing a different call path (`mintDepositInQueue` vs. `_deposit`) for functionally equivalent state changes.

This threshold is the analog of the Y2K "deposit fee" — a fee-like admission gate meant to enforce a floor to keep the mempool/priority-queue economically sound and prevent underpriced spam/low-fee transactions from being treated the same as properly priced ones, and it is configured as a `Public` protocol-level defense (`min_gas_price_percentage`, `validate_resource_bounds`): [3](#0-2) 

### Impact Explanation
This does not directly cause loss of funds or invalid state commitments, but it undermines a resource/economic-security control at the gateway. Because L1Gas-bounds transactions can freely enter the mempool below the intended minimum price floor, an attacker can flood the mempool/priority queue with underpriced transactions that circumvent the safeguard meant to prevent exactly this — potentially degrading fee-market integrity and enabling cheap transaction spam relative to the sequencer's intended pricing policy. Given the "Medium/High only, no resource-only" restriction in scope, this borders on a resource/DoS-adjacent issue rather than a fund-loss or consensus-safety bug; I could not confirm from the available code whether skipping this check leads to a concrete fund loss or network liveness failure (e.g., whether the mempool's core fee-escalation/inclusion logic elsewhere independently re-enforces a price floor for L1Gas transactions). This should be treated as tentative pending further confirmation of downstream effects.

### Likelihood Explanation
High likelihood of exploitation: the resource-bounds "shape" of a transaction (L1Gas vs AllResources) is fully attacker-controlled and requires no special privileges, deployed contracts, or complex sequencing — analogous to the one-line change in call target used in the original Y2K bug (`deposit` → `mintDepositInQueue`). No coordination with sequencer/validator/prover is required.

### Recommendation
Apply the L2 gas price floor validation (or an equivalent minimum-price/fee validation) uniformly regardless of the `ValidResourceBounds` variant, or explicitly document/justify why legacy `L1Gas`-only transactions are exempt and ensure some other equivalent floor is enforced for that code path (e.g., checking `l1_gas` max price against a converted threshold) in `validate_tx_l2_gas_price_within_threshold`.

### Proof of Concept
Not independently reproduced with a running node; based on static code reading:
1. Construct a transaction using legacy/L1Gas-only resource bounds (`ValidResourceBounds::L1Gas`) instead of `AllResources` (V3 with L2 gas bound).
2. Submit it to the gateway with an arbitrarily low L1 gas price bound.
3. `validate_resource_bounds` → `validate_tx_l2_gas_price_within_threshold` matches the `ValidResourceBounds::L1Gas(_)` arm and returns `Ok(())` unconditionally, bypassing the `min_gas_price_percentage` floor that would otherwise reject the transaction under the `AllResources` arm.
4. The transaction is admitted to the mempool despite being priced below the configured minimum threshold.

Note: I was unable to fully trace whether the mempool's separate fee-escalation logic (`crates/apollo_mempool/src/mempool.rs`, `validate_fee_escalation`) or bouncer/priority-queue insertion imposes an independent minimum-price constraint on L1Gas transactions that would mitigate this gap; this should be verified further (e.g., via a Devin session with full repo access) before treating this as conclusively exploitable at High severity.

    // TODO(Arni): Consider running this validation for all gas prices.
    fn validate_tx_l2_gas_price_within_threshold(
        &self,
        tx_resource_bounds: ValidResourceBounds,
        previous_block_l2_gas_price: NonzeroGasPrice,
    ) -> StatefulTransactionValidatorResult<()> {
        match tx_resource_bounds {
            ValidResourceBounds::AllResources(tx_resource_bounds) => {
                let tx_l2_gas_price = tx_resource_bounds.l2_gas.max_price_per_unit;
                let gas_price_threshold_multiplier =
                    Ratio::new(self.config.min_gas_price_percentage.into(), 100_u128);
                let threshold = (gas_price_threshold_multiplier
                    * previous_block_l2_gas_price.get().0)
                    .to_integer();
                if tx_l2_gas_price.0 < threshold {
                    return Err(StarknetError {
                        // We didn't have this kind of an error.
                        code: StarknetErrorCode::UnknownErrorCode(
                            "StarknetErrorCode.GAS_PRICE_TOO_LOW".to_string(),
                        ),
                        message: format!(
                            "Transaction L2 gas price {tx_l2_gas_price} is below the required \
                             threshold {threshold}.",
                        ),
                    });
                }
            }
            ValidResourceBounds::L1Gas(_) => {
                // No validation required for legacy transactions.
            }
        }
        Ok(())

pub struct StatefulTransactionValidatorConfig {
    // If true, ensures the max L2 gas price exceeds (a configurable percentage of) the base gas
    // price of the previous block.
    pub validate_resource_bounds: bool,
    pub max_allowed_nonce_gap: u32,
    pub reject_future_declare_txs: bool,
    pub max_nonce_for_validation_skip: Nonce,
    pub versioned_constants_overrides: Option<VersionedConstantsOverrides>,
    // Minimum gas price as percentage of threshold to accept transactions.
    pub min_gas_price_percentage: u8, // E.g., 80 to require 80% of threshold.
}

impl Default for StatefulTransactionValidatorConfig {
    fn default() -> Self {
        StatefulTransactionValidatorConfig {
            validate_resource_bounds: true,
            max_allowed_nonce_gap: 200,
            reject_future_declare_txs: true,
            max_nonce_for_validation_skip: Nonce(Felt::ONE),
            min_gas_price_percentage: 100,
            versioned_constants_overrides: None,
        }
    }
}
