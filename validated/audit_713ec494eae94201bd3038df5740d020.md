### Title
Starknet OS `execute_replace_class` skips the "class must be declared" check enforced by the Blockifier, enabling state divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Aevo incident stemmed from an upgrade/migration path that changed a contract's implementation without the safety checks the rest of the system relied on, letting an attacker manipulate vault state through an unvalidated class-replacement path. The Starknet analog is the `replace_class` syscall, which lets any deployed contract swap its own `class_hash`. In the Rust Blockifier (the component that actually executes transactions and decides on success/failure), `replace_class` explicitly requires the target class hash to already be declared before mutating state: `syscall_handler.state.get_compiled_class(request.class_hash)?` before `set_class_hash_at` in the deprecated syscalls path. [1](#0-0) 
This is also asserted by the existing negative test that a replace to an undeclared class fails with "is not declared". [2](#0-1) 

However, the Starknet OS's own Cairo re-implementation of the same syscall — used for re-execution/proving the block (Starknet OS re-execution path) — does **not** perform this check. It reads the state entry via a hint and unconditionally writes the new class hash, with an explicit TODO acknowledging the missing validation: [3](#0-2) 

The legacy/deprecated Cairo0 syscall handler in the OS has the identical gap: [4](#0-3) 

### Finding Description
`replace_class` is dispatched from the OS syscall loop for any contract execution: [5](#0-4) 

Its implementation blindly trusts the `class_hash` field supplied in the syscall request and the `GetContractAddressStateEntry` hint, then writes it into `contract_state_changes` without asserting that a corresponding declared class exists in `contract_class_changes`/the class table:
```
let class_hash = request.class_hash;
// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
local state_entry: StateEntry*;
%{ GetContractAddressStateEntry %}
...
dict_update{dict_ptr=contract_state_changes}(...)
```
Because the Starknet OS is the component that re-executes every transaction to prove the block and produce the committed state diff/state root, any check performed only in the Rust Blockifier and not mirrored in the Cairo OS program creates an asymmetry between the two execution engines. The Blockifier is what actually determines whether a transaction reverts (it will reject/re-declare-fail an undeclared class replace), but the OS — which computes the final Patricia-tree state commitment and block hash from the *same* transaction — has no analogous guard. If any path allows a `class_hash` value to reach the OS's `execute_replace_class` without first passing the Blockifier's `get_compiled_class` check (e.g., differing state views between the Blockifier's cached state and the OS's hinted state entries, or future callers of this Cairo function that bypass the Rust-side pre-check), the OS will happily commit an address's class hash to an undeclared/arbitrary value into the state root, since nothing in the constrained Cairo program enforces the invariant that only declared classes may become a contract's active class.

### Impact Explanation
This directly touches the "state reads and aliasing," "Starknet OS re-execution," and "state commitment and Patricia trees" categories explicitly in scope. A missing declared-class invariant enforced only outside the constrained proving program is a structural soundness gap: the guarantee that "every contract's `class_hash` corresponds to a declared class" is a basic Starknet state-validity invariant. If the constrained OS code does not itself enforce it, the STARK proof for a block does not actually prove that invariant — meaning a malicious/incorrectly-behaving Blockifier or a future refactor could produce a state root committing a contract to a non-existent/undeclared class hash, which is a wrong committed state root and a potential honest-node divergence (nodes that independently prove or verify against the invariant would compute different results than nodes trusting the hint blindly).

### Likelihood Explanation
The path is reachable by any unprivileged contract that calls `replace_class` in its own execution context (`syscall_ptr` supplied by the executing contract, callable directly by any transaction sender), matching the class of reachable actor required. The bug is not a hypothetical: it is an explicitly acknowledged gap (`TODO(Yoni, 1/1/2026)`) in the exact syscall responsible for changing a contract's class, present in both the current and deprecated Cairo syscall implementations.

### Recommendation
Add an explicit assertion in `execute_replace_class` (in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that the given `class_hash` exists in `contract_class_changes` (i.e., was declared in this block or a prior one), mirroring the Rust `get_compiled_class` check in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`, before permitting the `dict_update` that changes the contract's class hash. This closes the gap between the enforcement done by the Blockifier and what is actually proven/committed by the Starknet OS.

### Proof of Concept
Not applicable as a runnable exploit from the available static analysis — the issue is a missing invariant check in the constrained Cairo program itself, evidenced directly by the code and its own TODO comment: [6](#0-5) 
Exploitability in production depends on whether any caller can reach `execute_replace_class` in the OS with a `class_hash` that was never validated as declared by the Blockifier beforehand; I was not able to fully trace every call path from `syscall_base.rs`'s (non-deprecated, VM/Native) `replace_class` base implementation to confirm whether it performs an equivalent declared-class check as the deprecated handler does — this specific function body was not located in the indexed code, so it is uncertain whether the current (non-deprecated) syscall handler enforces the same check as the deprecated one.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
