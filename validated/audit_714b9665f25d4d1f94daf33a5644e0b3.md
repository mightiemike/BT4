## Title
Stale vault index cached before an accrue-pause unwind is reused for debt valuation and health checks for the rest of the block - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`market.clar` caches each vault's borrow/liquidity index once per block via `accrue-and-cache`, keyed only by `{timestamp: stacks-block-time, aid}`. The cache is populated from whatever the vault's public `accrue()` returns at that moment. If a vault's `accrue-pause` flag is set, `accrue()` deliberately returns the *frozen* `index`/`lindex` instead of reverting [1](#0-0) . Once that stale pair is cached for the block, nothing re-checks whether the vault's underlying pause state or index later changes within the same block — the cache is only invalidated by the timestamp changing (next block) [2](#0-1) . Because the same cached index is fed directly into debt USD valuation used for health/borrow checks, a stale-then-corrected index can leave the market computing debt as smaller than it truly is for the remainder of the block.

### Finding Description
`accrue-and-cache` in `market.clar` is a pure cache-or-fetch helper: on a cache hit it returns the stored value without any validation that the vault's state hasn't changed since the cache was written; on a miss it calls the vault's public `accrue()` and stores whatever comes back [2](#0-1) .

Each vault's `accrue()` is public and callable by anyone, and when `accrue-pause` is set it takes a "pass-through" path that returns the currently stored `index`/`lindex` unchanged, instead of reverting the call [3](#0-2) . This pattern is repeated identically across every vault (`v0-vault-stx`, `v0-vault-sbtc`, `v0-vault-ststx`, `v0-vault-usdh`, `v0-vault-ststxbtc`) [4](#0-3) .

That cached `index` is not a decorative value — `calculate-asset-notional-value`, which computes the USD value of a user's debt for both health checks and liquidation, converts scaled debt to actual debt using exactly the value returned by `accrue-and-cache`: [5](#0-4) 

Sequence that produces the divergence within one block (`stacks-block-time` unchanged):
1. Vault `V` has `accrue-pause = true`. Some market operation (e.g. `collateral-add`) on account A triggers `accrue-and-cache(V)`; it hits the paused path and caches the frozen `{index: idx_old, lindex: lidx_old}` for `{timestamp: T, aid: V}`.
2. Within the same block `T`, the vault's `accrue-pause` is toggled off (an ordinary operational unpause, not a compromise) and `accrue()` is invoked again — either directly by any caller (it is `public`) or indirectly through another market operation for a different account. This time the pause branch is skipped, `next-index()`/`next-liquidity-index()` compute the true, higher `index`/`lindex` reflecting all interest that accrued while paused, and the vault's on-chain `index`/`lindex`/`last-update` vars are updated to the fresh values [6](#0-5) .
3. Still within block `T`, any market operation for account A (or any other account with debt on `V`) that needs the index calls `accrue-and-cache(V)` again. Because the cache key `{timestamp: T, aid: V}` already exists from step 1, this is a cache HIT: the stale `idx_old` is returned, not the corrected value from step 2.
4. That stale, understated `idx_old` flows into `calculate-asset-notional-value`'s debt-notional computation, producing a debt-USD value lower than the account's true debt [5](#0-4) .

### Impact Explanation
Debt-USD figures computed from the stale cached index feed directly into `is-healthy`/`is-healthy-with-mask`, which gate `borrow`, `collateral-remove`, and liquidation eligibility [7](#0-6) . An understated debt figure lets a position appear healthier than it is, permitting additional borrowing against insufficient collateral or evading liquidation that should otherwise be triggered — i.e., positions can be pushed under-collateralized within the same block the true index was corrected. This is a protocol-insolvency-class impact (accounting divergence that can leave real debt permanently under-collateralized/under-collected).

### Likelihood Explanation
The trigger requires only that a vault transition from a paused-accrual state to an unpaused state within the same block in which a market caller already caused a cache write while paused — a plausible sequencing (e.g., a pause is lifted and a user transaction lands in the same block, or a bot is monitoring for pause-toggle events to sandwich within the block). No DAO compromise is needed; toggling `accrue-pause` is normal operational functionality, and the cache-staleness bug is purely in how `market.clar` trusts a single per-block cache entry without re-validating it against the vault's live state.

### Recommendation
- **Short term:** Invalidate or bypass the `index-cache` entry whenever the underlying vault's pause state changes, or simply do not allow `accrue()`'s pass-through path to populate the market's cache (treat a paused-vault read as a cache miss that must be re-resolved once unpaused).
- **Long term:** Cache on a value that provably reflects the vault's current, non-stale state (e.g. include a monotonically increasing "epoch"/version bumped on every pause/unpause, and key the cache on that alongside the timestamp), rather than assuming per-block staleness is impossible once `accrue-pause` toggles mid-block.

### Proof of Concept
1. Block T: vault-usdc has `accrue-pause = true` (admin-set for maintenance).
2. Attacker/any tx: calls a market function touching account A's USDC debt (e.g. `collateral-add` on an unrelated asset that still requires debt accrual) → `accrue-and-cache(USDC)` caches the frozen `idx_old`/`lidx_old` at `{timestamp: T, aid: USDC}`.
3. Block T (later in same block): admin calls `set-pause` (or equivalent) to unpause vault-usdc's accrual; a subsequent call to `vault-usdc.accrue()` (public, callable by anyone) recomputes and stores the corrected higher `index`.
4. Block T (still same block): attacker calls `market.borrow` (or `collateral-remove`) against a position with USDC debt. `calculate-asset-notional-value` calls `accrue-and-cache(USDC)` again, gets the cache HIT with `idx_old`, and computes a debt-USD figure lower than the position's true debt.
5. The health check in `borrow`/`collateral-remove` passes using the understated debt, allowing the attacker to borrow more or withdraw collateral beyond what the true (corrected) debt index would allow.

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
