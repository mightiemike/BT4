### Title
Proving-gas cost per Cairo primitive floors before multiplying by usage count, causing the bouncer to systematically undercount block proving-gas usage - (File: crates/blockifier/src/bouncer.rs)

### Summary
`BuiltinInstanceLimits::induced_gas_costs` derives a per-instance proving-gas cost by performing an integer division (`proving_gas / limit`) *before* that per-unit cost is later multiplied by a transaction's builtin usage count in `cairo_primitives_to_gas`. This is the same "divide-then-multiply" pattern flagged in the Canto `update_market` finding: computing a per-unit rate via floor division and then multiplying it by a quantity systematically rounds the total down, rather than computing the exact total first and rounding once at the end.

### Finding Description
`BuiltinInstanceLimits::induced_gas_costs` computes, for each Cairo primitive (builtin/opcode), a per-instance proving-gas cost as `floor(proving_gas / limit)`: [1](#0-0) 

This per-unit, already-floored cost (`BuiltinGasCosts`) is exposed via `BouncerConfig::builtin_gas_costs`: [2](#0-1) 

and is subsequently used as `proving_builtin_gas_costs` inside `get_tx_weights`, where it feeds `compute_proving_gas` → `proving_gas_from_cairo_primitives_and_sierra_gas` → `cairo_primitives_to_gas`, which multiplies the already-floored per-unit cost by each transaction's builtin usage count to obtain the total proving-gas weight added to the block's bouncer accumulator: [3](#0-2) 

Mathematically this is exactly the buggy pattern from the reference report:

`(proving_gas / limit) * count` instead of `(proving_gas * count) / limit`

Because `floor(proving_gas/limit)` is computed once and reused across every transaction and every occurrence of that primitive in a block, the rounding-down error accumulates linearly with the number of times that builtin is used across the block, rather than being bounded to a single rounding at the end of the block. For high-limit builtins (e.g. `range_check` with limit `66,666,666` against a `5,000,000,000` proving-gas budget), the per-unit cost is `74` when the exact ratio is `75.0000015`, i.e. essentially the same effect demonstrated in the PoC in the report where `(x/1e18)*1e18` diverges from `(x*1e18)/1e18`.

### Impact Explanation
The bouncer's proving-gas weight (`BouncerWeights.proving_gas`) is a resource-accounting/admission-control field used to determine whether a block/proposal is "full" (`has_room`/`within_max_capacity_or_err`), i.e., it governs how many transactions can be packed into a block relative to the true proving cost of the resulting STARK proof. Because per-primitive proving-gas costs are floored before being multiplied by usage counts, the *reported* accumulated proving-gas for a block can be systematically lower than the *true* proving-gas cost implied by the configured budget and instance limits (analogous to CANTO rewards being paid out less than intended). This means a proposer could pack more Cairo-primitive-heavy transactions into a block than the proving-gas budget was designed to allow, without tripping the bouncer's block-full checks, which is a resource-accounting/bouncer-weight correctness issue exactly in the class the rules permit ("bouncer weights").

The magnitude of the loss depends on `proving_gas % limit` for each builtin and the number of times that builtin is exercised across the block; with builtins that have small limits relative to proving_gas budget (e.g. `ecop`, `keccak`), the relative rounding loss is small, but for high-limit builtins used many times per block (e.g. `range_check`), the aggregate discrepancy between "true" proportional proving-gas usage and the floored, multiplied approximation can be non-negligible over a full block of transactions.

### Likelihood Explanation
This is triggered on every block by ordinary transaction execution — any unprivileged transaction sender whose transaction uses builtins (range_check, pedersen, poseidon, etc.) contributes to this systematic under-accounting; no malicious or privileged behavior is required, only volume of ordinary transactions using the relevant builtins. This makes the miscalculation reachable purely through the sequencer's ordinary block-building path (`get_tx_weights` → `Bouncer::try_update`), which runs for every transaction added to a proposal.

### Recommendation
Avoid pre-flooring per-instance proving-gas costs. Either:
1. Keep the numerator/denominator (`proving_gas`, `limit`) as a `Ratio`/rational and only floor/ceil once when the *total* per-primitive proving-gas contribution for the block is computed (i.e., multiply the exact rational rate by the accumulated count first, then round), mirroring how `ResourceCost`/`Ratio` is already used elsewhere in `fee_utils.rs` (e.g., `calculate_resource_gas_cost`, `sierra_gas_to_l1_gas_amount_round_up`) to avoid this exact class of bug; or
2. Compute `cairo_primitives_to_gas` using `(proving_gas * count) / limit` per primitive (multiply before dividing) instead of `(proving_gas / limit) * count`, and sum the exact totals before any single final rounding.

### Proof of Concept
Using the default `BuiltinInstanceLimits` and the default `proving_gas` budget of `5,000,000,000` (from `crates/starknet_transaction_prover/resources/bouncer_config.json`):
- `range_check` limit = `66,666,666`. Exact ratio = `5,000,000,000 / 66,666,666 ≈ 75.0000015`. `induced_gas_costs` floors this to `75` per instance (verified against the test snapshot at a 6B budget, where `range_check` induced cost is `90` for `6,000,000,000/66,666,666=90.0000018` — floored to `90`): [4](#0-3) 
- If a block contains, say, 1,000,000 `range_check` operations spread across many transactions, the "true" proportional proving-gas contribution would be `1,000,000 * 90.0000018 ≈ 90,000,001.8`, but the floored-then-multiplied approach yields exactly `1,000,000 * 90 = 90,000,000`, undercounting by ~1.8 gas units — a small but real and systematic loss that scales with builtin usage volume and compounds across all 11 builtin/opcode categories every block.

impl BuiltinInstanceLimits {
    /// Induces the per-instance proving-gas cost of each Cairo primitive from its per-block
    /// instance limit: `cost = floor(proving_gas / limit)`.
    pub fn induced_gas_costs(&self, proving_gas: GasAmount) -> BuiltinGasCosts {
        let derive = |limit: NonZeroU64| -> u64 { proving_gas.0 / limit.get() };
        BuiltinGasCosts {
            pedersen: derive(self.pedersen),
            range_check: derive(self.range_check),
            range_check96: derive(self.range_check96),
            poseidon: derive(self.poseidon),
            ecdsa: derive(self.ecdsa),
            ecop: derive(self.ecop),
            bitwise: derive(self.bitwise),
            keccak: derive(self.keccak),
            add_mod: derive(self.add_mod),
            mul_mod: derive(self.mul_mod),
            blake: derive(self.blake),
        }
    }
