### Title
Permissionless `accrue()` on `v0-vault-sbtc` lets an unprivileged caller mutate the vault's real index independently of, and divergently from, `market.clar`'s per-block `index-cache` - ([File: mainnet/contracts/vault/v0-vault-sbtc.clar])

### Summary
`accrue()` in `v0-vault-sbtc.clar` has no caller-authorization check, unlike `system-borrow`/`system-repay`/`socialize-debt` which are all gated by `check-caller-auth`. Because `last-update` is only advanced when an accrual actually changes `index`/`lindex`, an attacker can leave `last-update` stale through a market-driven accrual that happens to be a no-op, mutate utilization via a subsequent (auth-required but attacker-initiated) `borrow`, and then call the vault's `accrue` directly to force a large retroactive interest computation over the stale time window using the *new* post-borrow rate. The vault's on-chain `index`/`lindex` state is thereby updated to a value that diverges from the value already frozen in `market.clar`'s `index-cache` for the same `stacks-block-time`, breaking the intended "single canonical index per block" invariant.

### Finding Description
Sequence within one block, one attacker-controlled principal, chosen nonce ordering:

1. **TX1 - `market.borrow(sBTC, amount1, ...)`** (attacker's own borrow, permissionless entry point):
   - `market.clar` line 1255: `(unused (accrue-and-cache asset-id))`. Cache MISS for `{timestamp: T, aid: sBTC}` → calls `vault-accrue` → `v0-vault-sbtc.accrue()` (lines 833-861). If utilization/rate is zero pre-borrow, `next == idx` and `nliq == lidx`, so per line 858-860 `last-update` is **not** advanced (stays at prior block's timestamp `T0`). The (unchanged) `{index: idx0, lindex: lidx0}` is written into `index-cache` at key `{T, sBTC}` (`v0-4-market.clar` lines 249-257).
   - `market.clar` line 1289: `(try! (vault-system-borrow asset-id amount funds-receiver))` → vault's `system-borrow` (lines 863-898) itself calls `(try! (accrue))` at line 866 first. This recomputes with the *same* pre-borrow state as the cache write (nothing changed yet) → again `next == idx0`, `last-update` remains `T0`. Then `principal-scaled`/`total-borrowed` are increased by `amount1`, so utilization is now non-zero for the rest of the block.
   - Line 1290-1296: `convert-to-scaled-debt` reads the cached `idx0` via `get-cached-indexes` - consistent with the vault's real index at this point (both still `idx0`). No divergence yet inside TX1.

2. **TX2 - attacker calls `v0-vault-sbtc.accrue()` directly** (same block `T`, same attacker, no authorization required - `accrue` has no `check-caller-auth`/`check-dao-auth` guard, contrast lines 833 vs. 875/916/958 which do gate `system-borrow`/`system-repay`/`socialize-debt`):
   - `next-index` (lines 377-388) computes `idx = var-get index = idx0`, `rate = interest-rate()` using the **post-TX1 utilization** (now non-zero, since `total-borrowed` was increased in TX1), and `time-delta = stacks-block-time (T) - last-update (T0)`, which is the **entire stale interval**, not just the time since TX1.
   - Because `rate` is now non-zero and `time-delta` is non-zero, `calc-multiplier-delta` produces `next != idx0`. `accrue()` (lines 849-860) writes `var-set index next`, `var-set lindex nliq`, and `var-set last-update stacks-block-time` - a real, permanent state mutation to the vault's canonical `index`, performed **outside** `market.clar`'s cache path.

3. **TX3 - any further market interaction touching sBTC in the same block** (e.g. a second `borrow`, `repay`, or a health-check-triggering call): `accrue-and-cache(sBTC)` at `{T, sBTC}` is a **cache HIT** (`v0-4-market.clar` lines 249-251) and returns the stale `idx0`/`lidx0` written in TX1, even though the vault's real `index` was just updated to a different value in TX2. Any `v0-market-vault` debt valuation, LTV/health check, or `convert-to-scaled-debt` conversion in TX3 uses `idx0`, while the vault's actual `total-debt`/`total-assets` accounting (used e.g. by `system-repay`, `redeem`, `deposit` share pricing) uses the now-different real `index`.

Root cause: `accrue()` is a plain `define-public` function with **no authorization check**, so any unprivileged principal can force a vault-level accrual outside of `market.clar`'s cache-priming mechanism, and the "only advance `last-update` on change" rule (line 858-860) lets a stale `last-update` silently persist across an intervening state mutation (the attacker's own borrow), so that the eventually-triggered accrual applies a rate that never actually applied over the full time window. The `index-cache`'s single-write-per-timestamp semantics (intended to make one index canonical for the whole block) is bypassed because the direct vault call is a separate cross-contract-invocation path that never touches `index-cache` at all.

### Impact Explanation
The vault's real interest/index accounting and `market.clar`'s frozen per-block valuation of the same asset can diverge within a single block. This breaks the ACCRUAL_EXACTNESS invariant and desynchronizes debt/collateral valuation used for LTV/health checks from the vault's actual ledger (`total-debt`, `total-borrowed`, treasury-LP minting). Depending on which direction the index moves, this can inflate `debt-delta`/`treasury-lp` mint amounts using an unwarranted rate×time product (minting unbacked yield to `.dao-treasury`/LPs), or cause a borrower's on-chain debt to be valued differently by `market.clar` (still using the stale cached index) than by the vault itself for the remainder of the block, corrupting share pricing (`convert-to-shares-preview`/`convert-to-assets-preview`) and debt accounting. This falls under the in-scope Critical category (protocol insolvency from index divergence) since it corrupts the fundamental unit of account (the interest index) that all debt/collateral values are denominated in.

### Likelihood Explanation
The interleaving requires only a single attacker-controlled address issuing multiple of its own transactions in a chosen order within one block (borrow via market, then a direct unauthenticated `accrue()` call on the vault). No DAO, oracle, or multi-user coordination is needed, and `accrue()` is callable by anyone with no cost beyond gas. It does require the specific precondition that an initial market-triggered accrual is a no-op (zero rate/zero utilization at that moment) so `last-update` fails to advance - a state that is realistic in low-utilization/zero-rate curve regions common at pool launch or after large repayments.

### Recommendation
Gate `accrue()` behind the same authorization used for `system-borrow`/`system-repay` (`check-caller-auth`, i.e. only `market.clar`/authorized contracts), or make direct calls route through/update `market.clar`'s `index-cache` atomically so the cached and on-chain index can never diverge within the same `stacks-block-time`. Alternatively, always advance `last-update` to `stacks-block-time` on every `accrue()` invocation (even when `index`/`lindex` don't change), removing the possibility of a stale `last-update` surviving an intervening state mutation.

### Proof of Concept
Clarinet simnet test plan:
1. Deploy `v0-vault-sbtc`, `market.clar`, `v0-assets`, `v0-market-vault`, `v0-egroup` with a rate curve that returns `rate = 0` below some utilization threshold `U*` and `rate > 0` above it.
2. Fund attacker wallet with sBTC and mint/deposit enough zsBTC collateral so a borrow of `amount1` is health-check-valid but keeps utilization at `< U*` pre-borrow (rate 0 at the time of the first accrual).
3. Advance the chain several blocks with utilization at 0 so `last-update` sits behind current time by a large `time-delta`, then in the **target block**:
   a. TX1: attacker calls `market.borrow` for `sBTC`, `amount1`, pushing utilization above `U*` post-borrow; assert `index-cache {timestamp:T, aid:sBTC}` equals `idx0` (unchanged) and vault's `last-update` still equals the prior stale value.
   b. TX2 (same block, next nonce): attacker calls `v0-vault-sbtc.accrue` directly; assert it succeeds without any authorization error, and assert `(get-index)` returned by the vault now differs from `idx0` and from `(get-cached-indexes sBTC)` still recorded in `market.clar`.
   c. TX3 (same block): trigger any market read/write touching `sBTC` (e.g. another `borrow` or `get-notional-evaluation` via `collateral-add`) and assert it still returns/uses `idx0` from cache while `(contract-call? .v0-vault-sbtc get-index)` returns the diverged value - demonstrating the ACCRUAL_EXACTNESS break within one block. (define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
