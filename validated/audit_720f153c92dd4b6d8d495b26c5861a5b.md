### Title
Webhook HMAC validation does not bind the signed body to the `X-Shopify-Shop-Domain` header, allowing cross-tenant session/token access via replay - (File: packages/apps/shopify-api/lib/webhooks/validate.ts)

### Summary
`validateFactory` (`validate.ts`) validates a webhook solely by checking the HMAC over `rawBody` (via `validateHmacFromRequestFactory`/`validateHmacString` in `hmac-validator.ts`), then separately extracts the shop domain from the `X-Shopify-Shop-Domain` header without cross-checking it against anything the HMAC actually covers. That unauthenticated `check.domain` value is passed directly into `ensureValidOfflineSession(params, check.domain)` in `authenticateWebhookFactory`, causing the app to load and use another shop's offline access token.

### Finding Description
The verification flow is:
1. `validateHmacFromRequestFactory` (`packages/apps/shopify-api/lib/utils/hmac-validator.ts:168-201`) computes `createSHA256HMAC(config.apiSecretKey, rawBody, ...)` and compares it to the `X-Shopify-Hmac-Sha256` header value. The input to the HMAC is `rawBody` only — the shop domain header is never included. [1](#0-0) 
2. Once `valid: true` is returned, `validateFactory` calls `checkWebhookHeaders`, which reads `X-Shopify-Shop-Domain` straight out of the (attacker-controlled) request headers and returns it as `domain` in the validation result, with no linkage to the HMAC-verified content. [2](#0-1) 
3. `authenticateWebhookFactory` in shopify-app-remix (and equivalently in shopify-app-react-router) trusts `check.domain` unconditionally and uses it to fetch an offline session/access token: `const session = await ensureValidOfflineSession(params, check.domain);` [3](#0-2) 
4. `ensureValidOfflineSession` performs no additional verification that the domain was cryptographically tied to the request; it simply loads/creates the offline session for whatever shop string it is given. [4](#0-3) 

Because the app's `apiSecretKey` is shared across all shops that install the app, and the HMAC input is only `rawBody`, an attacker who has captured one genuine webhook delivery for shop A (which they control, e.g., their own store) can replay the identical `rawBody` + HMAC while swapping the `X-Shopify-Shop-Domain` header to shop B. The HMAC check still passes (it never looked at the domain), `checkWebhooksHeaders` happily reports `domain: "shop-b.myshopify.com"`, and the app resolves and uses shop B's offline token/session to build an admin client and dispatch the (attacker-supplied) webhook context to app handlers.

The same weakness is present in `packages/apps/shopify-api/lib/webhooks/process.ts`, which passes `webhookCheck.domain` straight into registered `HttpWebhookHandlerWithCallback` callbacks after the same HMAC-only validation. [5](#0-4) 

### Impact Explanation
An attacker who legitimately operates any shop installed on the target app (shop A) can trigger app webhook handlers as if they came from any other shop (shop B) also installed on the same app, causing the app to load and act with shop B's offline access token/session (`ensureValidOfflineSession` → `adminClientFactory`). This is a cross-tenant session/access-token confusion: the attacker cannot choose arbitrary payload content (only replay a payload from a webhook they already received), but they fully control which topic/handler and target shop is invoked, and the app will process that payload using another tenant's session and admin credentials — matching Shopify's "cross-tenant data/state access" bounty class.

### Likelihood Explanation
Requires: (1) the attacker legitimately installed the app on shop A and captured/replayed a single valid webhook delivery, and (2) a second target shop B also installed on the same app. No secret material, MITM, or privileged role is needed beyond normal merchant-level app installation, and HTTP header spoofing on a self-crafted POST is trivial. The attack is repeatable for any webhook the attacker has captured and for any known/discoverable installed shop domain.

### Recommendation
Do not trust the `X-Shopify-Shop-Domain` header as authoritative for authorization purposes independent of the HMAC. At minimum, cross-check the domain against session storage records tied to the actual delivery (e.g., verify the domain corresponds to a shop for which this exact `webhookId`/topic pairing was registered, or bind the domain into an application-level nonce/replay cache keyed by `webhookId` so the same rawBody+hmac cannot be accepted twice for different domains). Track and reject repeated/duplicate `webhookId` values (idempotency/replay protection) regardless of domain, since Shopify already sends a unique `X-Shopify-Webhook-Id` per delivery.

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/webhooks/__tests__/domain-confusion.test.ts
import {shopifyApi, LATEST_API_VERSION} from '../../..';
import {testConfig} from '../../__tests__/test-config';

test('HMAC validation does not bind shop domain', async () => {
  const shopify = shopifyApi(testConfig());
  const rawBody = '{"id":123}';
  const hmac = await shopify.utils.hmac ? undefined : undefined; // compute via createSHA256HMAC(apiSecretKey, rawBody, Base64)

  const baseHeaders = (domain: string) => ({
    'X-Shopify-Topic': 'orders/create',
    'X-Shopify-Hmac-Sha256': /* HMAC computed once, over rawBody, using apiSecretKey */ 'REPLAYED_HMAC',
    'X-Shopify-Shop-Domain': domain,
    'X-Shopify-Api-Version': LATEST_API_VERSION,
    'X-Shopify-Webhook-Id': 'same-id-replayed',
  });

  const resultForShopA = await shopify.webhooks.validate({
    rawBody,
    rawRequest: new Request('https://app.example.com/webhooks', {
      method: 'POST',
      headers: baseHeaders('shop-a.myshopify.com'),
      body: rawBody,
    }),
  });

  const resultForShopB = await shopify.webhooks.validate({
    rawBody, // identical body, identical signature
    rawRequest: new Request('https://app.example.com/webhooks', {
      method: 'POST',
      headers: baseHeaders('shop-b.myshopify.com'), // swapped domain only
      body: rawBody,
    }),
  });

  expect(resultForShopA.valid).toBe(true);
  expect(resultForShopB.valid).toBe(true); // HMAC check passes regardless of domain
  expect((resultForShopA as any).domain).toBe('shop-a.myshopify.com');
  expect((resultForShopB as any).domain).toBe('shop-b.myshopify.com');
  // In authenticateWebhookFactory, resultForShopB.domain is then passed to
  // ensureValidOfflineSession(params, 'shop-b.myshopify.com'), retrieving
  // shop B's offline token despite the request never being authenticated for shop B.
});
```
