## Title
Replay/simulation verification silently skips checkpoint-hash comparison, letting `replay_on_archive` and CLI tooling report a corrupted or diverging state root as a successful replay - ([File: types/src/transaction/mod.rs])

### Summary
`TransactionOutput::ensure_match_transaction_info` is the authenticated-response/replay-integrity check used to confirm that a locally-computed `TransactionOutput` (write set, events, gas, status) matches the `TransactionInfo` recorded on-chain/in a proof. It verifies status, gas, write-set hash, and event-root hash, but explicitly does **not** verify `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` — the very fields that bind a transaction to the authenticated state root. This is a direct structural analog to the external bug's pattern: a value that is supposed to enforce a strict equality/binding invariant is computed/compared incorrectly (there it was a wrong `wadMul`; here it's an incomplete comparator that omits critical fields), causing downstream consumers to treat a wrong result as valid.

### Finding Description
`ensure_match_transaction_info` at [1](#0-0)  checks status, gas_used, write-set hash (`state_change_hash`) and event root hash, but stops there: [2](#0-1) 

The function's own comment states the ignored checkpoint hashes are `state/hot-state` and `position_state_checkpoint_hash`, and that this allows `db-tool`'s `replay_on_archive` to report a successful replay even when the authenticated position state root diverges from local execution.

This matters because `TransactionInfoV1` carries `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` as first-class, committed fields [3](#0-2) , computed by `DoStateCheckpoint::run` from the actual Sparse-Merkle/JMT state summaries, including the "trading-native" position-state root when `execution_output.compute_trading_native_state_roots` is set [4](#0-3) . These checkpoint hashes flow into `TransactionInfo` via `DoLedgerUpdate::run`/`assemble_transaction_infos`, and are what get accumulated into the transaction accumulator root that ledger infos ultimately commit to [5](#0-4) .

`ensure_match_transaction_info` is called from `aptos-debugger`, the Move CLI (`aptos-move/cli/src/commands.rs`), and `storage/db-tool/src/replay_on_archive.rs` — all places that re-execute historical/simulated transactions against an authenticated `TransactionInfo`/proof and are expected to catch any divergence between the locally re-executed state and the archived, signature-verified ledger. Because the comparator never touches the checkpoint-hash fields, any of these tools can locally recompute a *different* state checkpoint root (main state, hot state, or position state) than what was actually committed on-chain, and still declare the replay "matched" as long as the write set/events/gas/status happen to agree.

### Impact Explanation
This breaks the "committed state must match VM re-execution" and "authenticated proof context must be bound to the right root" invariants required by the State-Integrity Gate: a wrong state-checkpoint root (in particular the position/native-trading state root gated by `COMPUTE_TRADING_NATIVE_STATE_ROOTS`) can silently pass replay-verification tooling used to detect consensus/state divergence, hard forks, or storage corruption after restore/replay. In an operational incident (e.g., an upgrade that changes state-checkpoint computation, or storage corruption of the position/hot-state tree), this is precisely the safety net expected to catch a divergent ledger state — and it is a no-op for these three hash fields. This directly matches the "hard-fork-only divergence during commit, replay, restore" and "authenticated API ... output bound to the wrong version/object/proof context" categories in the Required Impacts section.

### Likelihood Explanation
The gap is deterministic and always present — it doesn't require an attacker; it requires only a genuine state divergence to go undetected by tooling that operators/auditors rely on for verifying state integrity (e.g. during a chain upgrade rollout, replaying archived transactions, or investigating a suspected fork). The code itself documents the gap as a known-but-unaddressed TODO, confirming the maintainers are aware the comparator is incomplete but it has not yet been fixed, so the vulnerable code path is live in the referenced commit.

### Recommendation
Extend `ensure_match_transaction_info` to compare `self` (locally computed) checkpoint hashes against `txn_info.state_checkpoint_hash()`, `txn_info.hot_state_checkpoint_hash()` (when present), and `txn_info.position_state_checkpoint_hash()` (when `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled), returning an error on any mismatch, consistent with how write-set and event-root hashes are already validated. Until fixed, `replay_on_archive`, the Move CLI simulate/replay path, and `aptos-debugger` should not be relied upon to detect state-checkpoint-root divergence.

### Proof of Concept
1. Take a transaction whose write set, events, gas, and execution status are correctly reproduced locally, but whose locally recomputed sparse-Merkle/JMT state root (or position-state root under `COMPUTE_TRADING_NATIVE_STATE_ROOTS`) differs from the one embedded in the archived `TransactionInfo` (e.g. due to a bug in state-checkpoint computation, a bad restore, or a storage-schema migration issue).
2. Run `db-tool replay-on-archive` (or the CLI/`aptos-debugger` simulate-with-debugger path) over that version range.
3. `ensure_match_transaction_info` at [6](#0-5)  only checks status/gas/write-set-hash/event-root-hash and returns `Ok(())`, reporting a successful replay even though `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` diverge from the archived `TransactionInfo`.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
