### Title
Unmetered free EVM execution via gasless `MsgExecutePayload` with attacker-controlled `GasLimit` and no minimum-affordability check before execution — (File: `x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`MsgExecutePayload` is unconditionally in the gasless allowlist regardless of signer identity, so it skips both `MinGasPriceDecorator` and `DeductFeeDecorator` in the ante chain. The only payment mechanism is `DeductGasFeesFromReceipt`, called *after* full EVM execution via `CallUEAExecutePayload` has already run with the attacker-supplied `GasLimit`. There is no pre-execution check that the target UEA can actually afford the resulting gas cost. An unprivileged attacker can therefore force full-cost EVM computation (up to whatever `GasLimit` they choose) on every validating node for zero payment, repeatedly, using fresh unfunded UEAs/keys created for free by `AccountInitDecorator`.

### Finding Description
The gasless allowlist in `app/txpolicy/gasless.go` includes `MsgExecutePayload` unconditionally: [1](#0-0) 

Because of this, `MinGasPriceDecorator` and `DeductFeeDecorator` both skip fee-related checks for this message type: [2](#0-1) [3](#0-2) 

`AccountInitDecorator` further lets a brand-new, completely unfunded account submit a gasless tx and get auto-created mid-pipeline, with no balance requirement: [4](#0-3) 

On the execution side, `msgServer.ExecutePayload` forwards directly to `Keeper.ExecutePayload`: [5](#0-4) 

`Keeper.ExecutePayload` runs the full EVM call via `CallUEAExecutePayload` (using the attacker-controlled `UniversalPayload.GasLimit`) *before* any fee is deducted, and only attempts to charge after the computation is already done: [6](#0-5) 

`DeductGasFeesFromReceipt`/`CalculateGasCost` compute the actual cost only from `receipt.GasUsed × effectiveGasPrice` post-execution, with no upfront admission-time affordability check comparable to op-geth's transaction `Cost()`: [7](#0-6) 

`UniversalPayload.ValidateBasic` only checks that numeric fields parse as non-negative uint256 — there is no cap on `GasLimit`: [8](#0-7) 

This is the structural analog of the op-geth bug: the true "cost" of the operation (the EVM computation triggered by `GasLimit`) is not accounted for or verified before the expensive work is performed and admitted into a block. In op-geth, tx-pool admission under-computed `Cost` and let unaffordable transactions occupy the pool and get prioritized, but they reverted for free at execution. Here, admission is skipped entirely (gasless) and the *execution itself* — not just pool occupancy — happens for free against an intentionally unfunded UEA, since only after paying the full EVM computation cost does the code check whether the payer can cover it.

Note: because `Keeper.ExecutePayload` returns an error when `DeductGasFeesFromReceipt` fails, and Cosmos SDK's `baseapp` reverts all state changes for a failing message within a `DeliverTx`, the attacker cannot extract funds or leave persistent bad state — the impact is limited to **wasted computation/CPU cycles across all validating nodes with zero fee paid**, repeated at will.

### Impact Explanation
This is a repeatable, free compute-DoS/griefing vector reachable by any unprivileged external actor:
- No token balance, no bonded validator status, and no privileged role is required — only a locally generated EVM keypair.
- Each attack transaction forces every node to execute EVM code (bounded only by `UniversalPayload.GasLimit`, unconstrained by any on-chain cap) at zero cost, since fee deduction is attempted only after the compute has already been spent and the UEA holds no balance.
- `AccountInitDecorator` allows an unlimited supply of fresh, zero-balance signer accounts to be created for free specifically for gasless messages, so the attack is not bottlenecked by needing a funded account or sequential nonce management on a single account.
- Sustained abuse degrades node performance and block-production throughput, consuming shared validator resources without any compensating fee — a legitimate "reachable without privileged control, non-network-level DoS" per the stated scope.

This does not achieve fund theft, minting, or permanent state corruption (SDK-level tx atomicity rolls back the failed message), so the impact is bounded to denial-of-service / resource-exhaustion griefing rather than the direct fund-loss impact described in the op-geth report.

### Likelihood Explanation
High likelihood of triggerability: the attacker needs only to generate an EVM keypair, sign a `UniversalPayload`+`VerificationData` for their own `UniversalAccountId.Owner` (which they legitimately control since it's their own key), pick a large `GasLimit`, and submit via `MsgExecutePayload`. No special access, funding, or validator collusion is required, and the gasless allowlist and account auto-init explicitly remove the normal cost barriers that would otherwise throttle such spam.

### Recommendation
- Require an upfront, verifiable minimum balance/affordability check on the UEA (or an escrow/pre-charge mechanism) before invoking `CallUEAExecutePayload`, similar to how op-geth's `Cost()` should gate mempool admission before expensive work is performed.
- Cap `UniversalPayload.GasLimit` to a sane maximum in `ValidateBasic`/`ValidateForExecution`.
- Consider restricting the gasless allowlist for `MsgExecutePayload` (e.g., requiring the destination UEA to already hold a minimum balance, or rate-limiting per signer/IP at the mempool level) rather than making it unconditionally gasless for arbitrary unfunded accounts.
- Reconsider whether `AccountInitDecorator` should permit unlimited fresh zero-balance accounts to submit gasless `MsgExecutePayload` without any throttling.

### Proof of Concept
1. Generate a fresh EVM keypair `K` (attacker-controlled, external chain e.g. `eip155:1`).
2. Compute the (undeployed, unfunded) UEA address for `UniversalAccountId{ChainNamespace: "eip155", ChainId: "1", Owner: K.address}`.
3. Craft a `UniversalPayload` with `GasLimit` set to a large value (e.g. `21000000`), `To` pointing at a gas-heavy target contract/loop, and `Value = 0`.
4. Sign `VerificationData` over the payload using `K` (attacker owns this key, so signing is trivial and free).
5. Submit `MsgExecutePayload{Signer: <new bech32 account>, UniversalAccountId, UniversalPayload, VerificationData}` as a gasless transaction; `AccountInitDecorator` creates the signer account for free, `MinGasPriceDecorator`/`DeductFeeDecorator` skip all fee checks because `MsgExecutePayload` is gasless.
6. `Keeper.ExecutePayload` calls `CallUEAExecutePayload`, running full EVM execution up to `GasLimit` gas against the (deployed-on-the-fly or existing) unfunded UEA.
7. `DeductGasFeesFromReceipt` fails (UEA has zero UPC balance) and the message returns an error; the tx fails and rolls back, but the EVM computation for up to `GasLimit` gas has already been executed by every node processing the block, at zero cost to the attacker.
8. Repeat with new keypairs indefinitely to sustain the free-compute DoS.

// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
