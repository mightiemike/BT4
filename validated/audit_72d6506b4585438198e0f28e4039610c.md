### Title
Missing "class must be declared" validation in Starknet OS `execute_replace_class` causes OS/Blockifier state divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS (SNOS) Cairo implementation of the `replace_class` syscall handler, `execute_replace_class`, writes an attacker-supplied `class_hash` into the contract's `StateEntry` without ever checking that this class hash was actually declared. The Rust Blockifier equivalent (`crates/blockifier/src/execution/syscalls/syscall_base.rs`) explicitly performs this check before mutating state. The Cairo OS code even contains an acknowledging `TODO` marking the check as missing.

### Finding Description
`execute_replace_class` in [1](#0-0)  takes `request.class_hash` directly from the syscall request and unconditionally updates `contract_state_changes` with a new `StateEntry` containing that class hash:

```
let class_hash = request.class_hash;

// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
local state_entry: StateEntry*;
%{ GetContractAddressStateEntry %}

tempvar new_state_entry = new StateEntry(
    class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
);
dict_update{dict_ptr=contract_state_changes}(...)
```

The deprecated (Cairo0) syscall path has the identical gap, with no declared-class check at all, in [2](#0-1) .

By contrast, the actual transaction-execution engine (Blockifier, which produces the state diffs/trace that the OS is supposed to re-verify) enforces this invariant strictly:

```rust
pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
    // Ensure the class is declared (by reading it), and of type V1.
    let compiled_class = self.state.get_compiled_class(class_hash)?;
    if !is_cairo1(&compiled_class) {
        return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
    }
    self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
    Ok(())
}
``` [3](#0-2) 

The deprecated hint processor equivalent also enforces the check: [4](#0-3) . Tests confirm Blockifier rejects undeclared/incompatible class hashes with `"is not declared"` / `"Cannot replace V1 class hash with V0 class hash"` errors: [5](#0-4) .

The Starknet OS's job is to re-execute the same block of transactions (via the Cairo VM, driven by hints that mirror the real execution) and independently derive the resulting state/commitment that becomes part of the proven block. Any semantic check that the real Blockifier enforces but that the OS's syscall implementation omits is a soundness gap in the OS's re-execution logic: the OS is fully driven by "hint" values (e.g., `%{ GetContractAddressStateEntry %}`) supplied by the untrusted prover/witness-generation layer, and the only guarantees the OS provides are the assertions actually coded into the Cairo functions. Because `execute_replace_class` does not assert that `class_hash` corresponds to a declared class (unlike the `execute_deploy`/`declare` paths that do wire class hashes through `contract_class_changes`), a malicious prover-controlled OS run (or hint layer bug) could produce a passing OS execution and final state commitment for a `replace_class` syscall using a class hash that was never declared — something the reference Blockifier execution would have reverted. This is exactly analogous to the reported `burn` bug: a state-mutating operation lacks the permission/precondition check that the "authoritative" reference implementation enforces.

### Impact Explanation
If the class-hash-declared invariant is not independently checked in the OS the same way it is checked by the Blockifier, the OS can be made to accept and commit a different state (and different resulting block hash / state root) than what real Blockifier execution would produce for the same transaction stream, once an undeclared class hash is fed through this code path. This is a "wrong committed root or block hash" / "honest-node divergence" class of bug: the STARK-proven state after block execution would silently diverge from the state that would result from correct, spec-compliant execution, since replacing a contract's class hash with an undeclared or class-0 hash corrupts follow-on execution assumptions (e.g., subsequent calls to the contract would resolve to a class hash that has no corresponding compiled/declared class, and yet the OS's bookkeeping would treat it as valid).

### Likelihood Explanation
`replace_class` is a standard syscall reachable from any Cairo1 contract's `__execute__`/external entry points invoked by an ordinary, unprivileged invoke transaction — no special node, prover, or operator privilege is required to trigger the syscall itself. The missing validation is confirmed by an explicit developer `TODO` acknowledging the gap, and by direct comparison against the Blockifier code that performs the check on the exact same operation, making this a concrete, provable discrepancy between the two supposedly-equivalent execution paths rather than a speculative issue.

### Recommendation
Mirror the Blockifier's `replace_class` semantics inside `execute_replace_class` (and the deprecated Cairo0 variant): before writing the new `StateEntry`, assert that `class_hash` is present in `contract_class_changes` (or otherwise provably declared) and, for the Cairo1 syscall, that it is not a Cairo0/deprecated class hash, exactly matching the checks in `crates/blockifier/src/execution/syscalls/syscall_base.rs::replace_class`. Remove the `TODO` only once the assertion is added, and add regression tests exercising undeclared/mismatched class hashes through the OS syscall path analogous to the existing Blockifier `replace_class` syscall tests.

### Proof of Concept
1. Deploy an account/contract that, in its `__execute__`, invokes `replace_class_syscall(undeclared_class_hash)` where `undeclared_class_hash` was never declared in the current or prior blocks (or is a Cairo0 hash, incompatible with `replace_class` per Blockifier rules).
2. Under real Blockifier transaction execution, this call reverts with `"... is not declared"` (see [6](#0-5) ).
3. In the Starknet OS Cairo re-execution path (`execute_replace_class`), no corresponding assertion exists — the function unconditionally writes `class_hash=class_hash` into the new `StateEntry` and updates `contract_state_changes`, as shown at [7](#0-6) .
4. Because the OS's behavior for this syscall is governed only by the hints/assertions coded here, any hint-layer or execution-trace inconsistency that reaches this function with an undeclared `class_hash` will be silently accepted by the OS and baked into the resulting state commitment, producing a state/block-hash divergence from the reference (Blockifier) execution semantics.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,

    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),

    );
