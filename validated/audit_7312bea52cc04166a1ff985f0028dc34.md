### Title
Outbound-disabled check after already-committed UEA payload execution permanently burns bridged funds with no outbound or refund - (File: `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/create_outbound.go`)

### Summary
When an inbound `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` UniversalTx executes a UEA payload that calls the gateway's withdraw/bridge-out function, the EVM state (PRC20 burn + `UniversalTxOutbound` event) is committed via `writeCache()` in `ExecutePayloadV2` **before** the destination chain's outbound-enabled status is checked in `BuildOutboundsFromReceipt`. If outbound is disabled for that destination chain at that moment, outbound creation fails and the burned funds are never re-minted, never queued for TSS signing, and never reverted — this is the direct analog of the SiloAMO `_burnOhm()` -> `MINTR.burnOhm()` pausing bug, where the burn commits irrevocably before the downstream gate (`onlyWhileActive`/outbound-enabled) is evaluated.

### Finding Description
`ExecuteInboundGasAndPayload` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:290-333`) calls:
```go
receipt, err = k.ExecutePayloadV2(ctx, ueModuleAddr, ueaAddr, utx.InboundTx.UniversalPayload, utx.InboundTx.VerificationData)
...
if attachErr := k.AttachOutboundsToExistingUniversalTx(sdkCtx, receipt, utx); attachErr != nil {
    // only records u.RevertError — no compensating action
}
```
`ExecutePayloadV2` (`x/uexecutor/keeper/execute_payload.go:35-56`) runs the UEA call in a `CacheContext`, then unconditionally commits with `writeCache()` once the EVM call and gas-fee deduction succeed — this is where PRC20 tokens get burned by the gateway's withdraw path and the `UniversalTxOutbound` log is emitted.

`AttachOutboundsToExistingUniversalTx` -> `BuildOutboundsFromReceipt` (`x/uexecutor/keeper/create_outbound.go:49-57`) then checks `IsChainOutboundEnabled` for the destination chain extracted from that already-committed log, and hard-fails if it's disabled:
```go
if !outboundEnabled {
    return nil, fmt.Errorf("outbound is disabled for chain %s", event.ChainId)
}
```
Because this check runs strictly after the burn is committed, and the caller only records the error string (`u.RevertError`) with no revert/re-mint logic (unlike `handleFailedOutbound` in `x/uexecutor/keeper/outbound.go:99-161`, which does re-mint PRC20 on outbound failure), the burned value is permanently destroyed with no path back to the user.

### Impact Explanation
This causes unauthorized/unrecoverable burn of user PRC20 funds — a direct, permanent loss of protocol/user-controlled value with no compensating mint or refund path, matching the in-scope impact "permanent loss ... or unauthorized burn ... of user or protocol-controlled funds."

### Likelihood Explanation
The trigger is an ordinary, unprivileged user submitting a normal cross-chain payload (via inbound funds/gas+payload flow or `MsgExecutePayload`) whose UEA-executed payload calls the gateway withdraw function. The `IsOutboundEnabled` flag is a normal, expected operational toggle (analogous to legitimately pausing MINTR in an emergency) — not an attacker action, but a foreseeable state overlap similar to the original report's "MINTR paused during emergency unwind." Any window where outbound is disabled for a chain (e.g., during an incident response, chain deprecation, or routine config update) while inbound payload execution continues will trigger this loss for any user whose payload happens to trigger a gateway withdraw at that time.

### Recommendation
Move the `IsChainOutboundEnabled` check (and any other "would this outbound succeed" checks currently done inside `BuildOutboundsFromReceipt`) to run *before* `ExecutePayloadV2`/`writeCache()` commits the UEA execution, or wrap the whole payload-execution + outbound-attach sequence in a single cache context that is only committed if outbound creation also succeeds. If outbound creation fails after the payload already executed, fall back to minting the PRC20 back to the user (same pattern as `handleFailedOutbound`) instead of merely recording `RevertError`.

### Proof of Concept
1. Admin/governance sets `ChainConfig.Enabled.IsOutboundEnabled = false` for destination chain `eip155:X` (a routine, legitimate toggle, e.g. via `MsgUpdateChainConfig`).
2. A user's inbound `GAS_AND_PAYLOAD` UniversalTx reaches quorum; its `UniversalPayload` calls the UEA which calls the gateway's withdraw method targeting `eip155:X`.
3. `ExecuteInboundGasAndPayload` -> `ExecutePayloadV2` executes the UEA call successfully and calls `writeCache()`, burning the user's PRC20 and emitting `UniversalTxOutbound`.
4. `AttachOutboundsToExistingUniversalTx` -> `BuildOutboundsFromReceipt` sees `IsChainOutboundEnabled(eip155:X) == false` and returns the error `"outbound is disabled for chain eip155:X"`.
5. The UTX only gets `RevertError` set; no outbound is queued, no PRC20 is re-minted. The user's funds are permanently gone with no recovery path (`utx.PcTx` shows `SUCCESS` for payload but no matching outbound ever appears). [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}

	outbound.OutboundStatus = types.Status_REVERTED
	k.Logger().Info("outbound reverted",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)

	// Refund excess gas regardless of tx type — gas was consumed on the external
	// chain whether the execution succeeded or failed.
	k.applyGasRefund(ctx, &outbound, obs)

	return k.UpdateOutbound(ctx, utxId, outbound)
}
