## Title
OS (Starknet OS) `replace_class` syscall re-implementation omits the declared-class binding check enforced by blockifier, enabling prover/state divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handling in the Cairo Starknet OS program (used to re-execute transactions and produce the state-transition proof) does not verify that the target `class_hash` is a declared class, whereas the Rust `blockifier` implementation that actually executes transactions for the sequencer enforces this check. This creates an "opaque, weakly-bound exec target" analogous to the busybox/toybox advisory: the entity that decides whether the call is legitimate (blockifier) and the entity that actually commits/proves the resulting state (the OS) can disagree on whether a given `replace_class` invocation is valid.

### Finding Description
`CallEntryPoint`/syscall execution in the Rust blockifier binds a `replace_class` syscall to a concrete, previously-declared class before mutating state: [1](#0-0) 

and for the deprecated (Cairo0) syscall handler: [2](#0-1) 

Both paths call `state.get_compiled_class(class_hash)`, which returns `StateError::UndeclaredClassHash` if the class was never declared, and the Cairo1 path additionally rejects non-Cairo1 (V0) targets (`ForbiddenClassReplacement`). This is the "exec approval binding" for `replace_class`: it fails closed unless the target is a known, declared, appropriately-versioned class.

The Starknet OS's own Cairo implementation of the same syscall — which is what is actually re-executed and proven for block validity — does **not** perform this check. For the Cairo1 (current) syscall path: [3](#0-2) 

Note the explicit acknowledgement of the missing check at line 902: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The function simply overwrites `state_entry.class_hash` in `contract_state_changes` with whatever `class_hash` felt was supplied, with no lookup into `compiled_class_facts_bundle` and no Cairo0/Cairo1 type check.

The same gap exists in the deprecated OS syscall path: [4](#0-3) 

This is precisely the "opaque multi-call binary" pattern from the advisory: one component (blockifier) makes an approval decision based on strict, verified binding (declared class + correct version); the other component that actually commits the effect (the OS, which produces the STARK proof used to certify the block's state transition) accepts the call without the same binding check.

### Impact Explanation
Because the Starknet OS independently re-executes transactions in Cairo to produce the proof that a block's state transition is correct, any semantic gap between blockifier and the OS on a syscall that mutates committed state (`class_hash` of a contract) can cause the two systems to compute different resulting states for the same transaction:
- If a transaction contains a `replace_class(undeclared_or_invalid_class_hash)` call that blockifier rejects (transaction reverts / syscall errors) but the OS accepts (because it doesn't check declaration), the OS's computed state diff/root will not match the state actually committed by the sequencer.
- This is a concrete case of "wrong committed root" / "honest-node divergence": the proof produced by the OS would not soundly correspond to the sequencer's real execution, undermining the ability of the network to confirm the block via SNARK/STARK proof validation, or allowing a state root to be accepted that does not correspond to the actual (blockifier-enforced) state transition rules.
- Because there is no assertion tying the new `class_hash` to a bundled `CompiledClassFact`, the corrupted state entry can persist with a class hash that was never legitimately declared, which is a form of unauthorized account action / class-hash corruption reachable purely by an unprivileged contract calling `replace_class` with an arbitrary felt.

This satisfies the required impact bar: wrong committed root and honest-node divergence stemming directly from a single contract's syscall invocation.

### Likelihood Explanation
Reachability is trivial and does not require any privileged role: any deployed Cairo1 (or Cairo0) contract can invoke the `replace_class` syscall with an attacker-chosen `class_hash` felt as part of a normal `__execute__`/external call, which is the same reachable surface as `library_call`/`call_contract` in this codebase. The bug is explicitly flagged by a TODO comment in the current source, confirming it is a known, unresolved gap rather than a speculative concern.

### Recommendation
Add the same "declared and appropriately versioned class" binding check to the OS's Cairo `execute_replace_class` (both the current `syscall_impls.cairo` implementation and the deprecated `deprecated_execute_syscalls.cairo` implementation) that blockifier enforces:
- Look up the given `class_hash` in `compiled_class_facts_bundle` (or the equivalent deprecated bundle) and fail/abort the syscall (writing the appropriate failure response, mirroring blockifier's `UndeclaredClassHash`/`ForbiddenClassReplacement` behavior) if it is not present or not of the allowed type.
- Ensure this check is unconditionally exercised before `dict_update` mutates `contract_state_changes`, so that OS re-execution can never accept a `class_hash` transition that blockifier would reject.

### Proof of Concept
1. Deploy a contract `A` (Cairo1) whose `__execute__`/external entry point calls `replace_class_syscall(class_hash)` with a `class_hash` value that has never been declared on-chain.
2. Submit an invoke transaction calling into `A`. In blockifier (real sequencer execution), `state.get_compiled_class(class_hash)` fails with `UndeclaredClassHash`, so the syscall/transaction fails as designed — see the check in `syscall_base.rs::replace_class`.
3. During OS re-execution (used to build the proof for the block containing this transaction), `execute_replace_class` in `syscall_impls.cairo` performs no equivalent lookup and unconditionally updates `contract_state_changes` for `A`'s storage entry with the undeclared `class_hash` (lines 900–917 above), producing a different result than what blockifier computed.
4. This mismatch between the sequencer's authoritative execution and the OS's proven re-execution is the divergence described above.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

        // Not enough gas to execute the syscall.
