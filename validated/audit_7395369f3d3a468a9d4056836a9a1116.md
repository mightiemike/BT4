### Title
Disk-index bucket capacity permanently pinned at attacker-forced historical peak via never-shrinking `Bucket::grow_index` + `Restart` file reuse - (File: `bucket_map/src/bucket.rs`, `bucket_map/src/restart.rs`)

### Summary
`BucketMap::bucket_ix` selects the target index bucket using only the top bits of the pubkey with no per-node randomization, so an unprivileged user can grind pubkeys to concentrate many accounts into one bin. `Bucket::grow_index` only grows (never shrinks) the on-disk index file for that bin, and `RestartableBucket::set_file`/`Restart::get_restartable_buckets` persist and reuse that oversized file by `file_name` across restarts, so the disk footprint never returns to the live-account-proportional size even after all colliding accounts are closed.

### Finding Description
`BucketMap::bucket_ix` computes the bucket index deterministically from the pubkey's leading bits with no salt: `let location = read_be_u64(key.as_ref()); (location >> (u64::BITS - self.max_buckets_pow2 as u32)) as usize` [1](#0-0) . Because this uses only the top `max_buckets_pow2` bits and is identical for every validator (unlike the intra-bucket hash which uses a per-bucket random seed [2](#0-1) ), an attacker can grind pubkeys off-chain to make many self-funded accounts collide into a single bin.

Each account create pushes the bin's `BucketStorage` toward `IndexNoSpace`, triggering `Bucket::grow_index`, which computes `new_capacity = (current_capacity * 110 / 100).max(anticipated_size)` and allocates a strictly larger `BucketStorage` file, applied via `apply_grow_index` [3](#0-2) . There is no corresponding shrink path anywhere in `bucket.rs`/`bucket_storage.rs` (confirmed absent via repo search), so capacity is monotonically non-decreasing regardless of subsequent deletions.

On every successful grow, `self.restartable_bucket.set_file(file_name, self.random)` persists the new (larger) file's id into the memory-mapped restart file [4](#0-3) , and `RestartableBucket::set_file`/`::get` write/read that `file_name` into the shared `Restart` mmap [5](#0-4) . On the next validator startup, `Restart::get_restart_file` reuses the restart file as long as `version`, `buckets`, and `max_search` still match [6](#0-5) , and `Restart::get_restartable_buckets` matches each bucket's stored `file_name` against files found on disk, reattaching the (still oversized) file and deleting only genuinely unmatched files [7](#0-6) . `Bucket::new` then loads that exact file via `BucketStorage::load_on_restart` when a `reuse_path` is present [8](#0-7) , keeping the on-disk capacity at the historical peak forever, independent of the live account count in that bin at any later time.

Deleting the colliding accounts (`Bucket::delete_key` / `BucketMap::delete_key`) only frees the index slot (`self.index.free(elem_ix)`), it does not shrink `BucketStorage` capacity [9](#0-8) . No slot/ancestor, zero-lamport, obsolete-account, or ref-count guard in this path prevents or reverses the growth; those guards operate on account/index-entry validity, not on disk-index bucket sizing.

### Impact Explanation
This is a disproportionate-storage-cost issue: a low-cost sequence of account creates/closes (paid at normal transaction fee/rent rates) permanently inflates one validator-side disk-index file to many multiples of `DEFAULT_CAPACITY_POW2`/original size, with no automatic reclamation, persisting across every future restart via the `Restart` file matching mechanism. This matches the Agave bounty category of "unprivileged attacker forces disproportionate storage/index/scan/hashing/cleanup work vs fees paid" — here specifically disk-index storage amplification that never returns to proportional levels for the life of the validator's data directory.

### Likelihood Explanation
Preconditions are attacker-reachable without any privileged access: disk index must be enabled (`IndexLimit::Minimal`/`Threshold`, an operator config choice already covered as a stated precondition, not attacker-controlled but a legitimate common deployment mode), and the attacker must grind pubkeys to hit one bin's top bits — feasible with commodity hashing power since only `log2(max_buckets)` bits need to match (a small number of bits for typical bucket counts, comparable difficulty to existing vanity-address grinding). The attacker fully controls pubkeys, account creation, sizes, and timing, and the exploit requires no leader/staked/gossip role, no snapshot tampering, and no more than ordinary create/close transactions. It is fully repeatable across restarts and re-attacks since nothing ever shrinks the file.

### Recommendation
Add a shrink/compaction path to `Bucket`'s index management: when a bucket's live entry count (`self.index.count`) drops well below a fraction of its current capacity (e.g., after cleanup/purge or periodically), rebuild the index into a smaller `BucketStorage` sized to the current occupancy (with the same 140%/110% over-allocation headroom used for growth) and update `restartable_bucket.set_file` with the new smaller file, replacing the old oversized file. Alternatively/also, bound `max_buckets_pow2`'s effective bucket-selection entropy or salt `bucket_ix` per-validator (similar to the per-bucket `random` used inside `bucket_index_ix`) to make targeted bin-flooding non-deterministic across validators, reducing the value of grinding a single node's bin.

### Proof of Concept
Rust integration test plan (bucket_map crate):
1. Create a `BucketMapConfig` with `max_buckets = 1` (or grind pubkeys to force collisions into bucket 0) and a `restart_config_file` set, disk `drives` set to a tempdir.
2. Instantiate `BucketMap::new(config)`.
3. Insert N (e.g., 10,000) unique pubkeys all into the same bucket (trivial with `max_buckets = 1`) via `index.insert`, forcing multiple `grow_index` calls; record `stats.index.total_file_size`/`capacity_bytes` (via `BucketMapStats`) — assert it grew well beyond `DEFAULT_CAPACITY_POW2`.
4. Delete all N pubkeys via `index.delete_key`.
5. Drop the `BucketMap` (simulating clean validator shutdown, restart file remains on disk).
6. Recreate `BucketMap::new(config)` with the same `restart_config_file`/`drives` (simulating restart).
7. Assert: `Restart::get_restart_file` succeeds (header/config match) and the bucket's underlying index file size (`BucketStorage::capacity_bytes()`/file length on disk) equals the pre-delete peak size, not a size proportional to the now-zero live entries — i.e., assert capacity did not shrink toward `0`/near-empty despite `index.count == 0`.

Expected assertion failure that proves the bug: `capacity_bytes_after_restart >= capacity_bytes_at_peak` while `live_entry_count == 0`, demonstrating the disk footprint is permanently pinned at the attacker-forced historical peak.

    pub fn grow_index(&self, mut current_capacity: u64) {
        if self.index.contents.capacity() == current_capacity {
            // make sure to grow to at least % more than the anticipated size
            // The indexing algorithm expects to require some over-allocation.
            let anticipated_size = self.anticipated_size * 140 / 100;
            let mut m = Measure::start("grow_index");
            //debug!("GROW_INDEX: {}", current_capacity_pow2);
            let mut count = 0;
            loop {
                count += 1;
                // grow relative to the current capacity
                let new_capacity = (current_capacity * 110 / 100).max(anticipated_size);
                let (mut index, file_name) = BucketStorage::new_with_capacity(
                    Arc::clone(&self.drives),
                    1,
                    std::mem::size_of::<IndexEntry<T>>() as u64,
                    Capacity::Actual(new_capacity),
                    self.index.max_search,
                    Arc::clone(&self.stats.index),
                    Arc::clone(&self.index.count),
                );
                // index may have allocated something larger than we asked for,
                // so, in case we fail to reindex into this larger size, grow from this size next iteration.
                current_capacity = index.capacity();
                let mut valid = true;
                for ix in 0..self.index.capacity() {
                    if !self.index.is_free(ix) {
                        let elem: &IndexEntry<T> = self.index.get(ix);
                        let new_ix =
                            Self::bucket_create_key(&mut index, &elem.key, self.random, true);
                        if new_ix.is_err() {
                            valid = false;
                            break;
                        }
                        let new_ix = new_ix.unwrap();
                        let new_elem: &mut IndexEntry<T> = index.get_mut(new_ix);
                        *new_elem = *elem;
                        index.copying_entry(new_ix, &self.index, ix);
                    }
                }
                if valid {
                    self.stats.index.update_max_size(index.capacity());
                    let mut items = self.reallocated.items.lock().unwrap();
                    items.index = Some(index);
                    self.reallocated.add_reallocation();
                    self.restartable_bucket.set_file(file_name, self.random);
                    break;
                }
            }
            m.stop();
            if count > 1 {
                self.stats
                    .index
                    .failed_resizes
                    .fetch_add(count - 1, Ordering::Relaxed);
            }
            self.stats.index.resizes.fetch_add(1, Ordering::Relaxed);
            self.stats
                .index
                .resize_us
                .fetch_add(m.as_us(), Ordering::Relaxed);
        }

    pub(crate) fn get_restart_file(config: &BucketMapConfig) -> Option<Restart> {
        let path = config.restart_config_file.as_ref()?;
        let metadata = std::fs::metadata(path).ok()?;
        let file_len = metadata.len();

        let expected_len = Self::expected_len(config.max_buckets);
        if expected_len as u64 != file_len {
            // mismatched len, so ignore this file
            return None;
        }

        let file = OpenOptions::new()
            .read(true)
            .write(true)
            .create(false)
            .open(path)
            .ok()?;
        let mmap = unsafe { MmapMut::map_mut(&file).unwrap() };

        let restart = Restart { mmap };
        let header = restart.get_header();
        if header.version != HEADER_VERSION
            || header.buckets != config.max_buckets as u64
            || header.max_search != config.max_search.unwrap_or(MAX_SEARCH_DEFAULT)
        {
            // file doesn't match our current configuration, so we have to restart with fresh buckets
            return None;
        }

        Some(restart)
    }

    pub(crate) fn get_restartable_buckets(
        restart: Option<&Arc<Mutex<Restart>>>,
        drives: &Arc<Vec<PathBuf>>,
        num_buckets: usize,
    ) -> Vec<RestartableBucket> {
        let mut paths = Self::get_all_possible_index_files_in_drives(drives);
        let results = (0..num_buckets)
            .map(|index| {
                let path = restart.and_then(|restart| {
                    let restart = restart.lock().unwrap();
                    let id = restart.get_bucket(index).file_name;
                    paths.remove(&id)
                });
                RestartableBucket {
                    restart: restart.cloned(),
                    index,
                    path,
                }
            })
            .collect();

        paths.into_iter().for_each(|path| {
            // delete any left over files that we won't be using
            _ = fs::remove_file(path.1);
        });

        results
    }
