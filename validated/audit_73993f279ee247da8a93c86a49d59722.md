## Found: nil `*big.Int` dereference in `MsgExecutePayload` gas-fee accounting via empty `UniversalPayload` numeric strings

### Title
Unprivileged `MsgExecutePayload` with an empty `max_fee_per_gas` field panics the chain in `DeductGasFeesFromReceipt` — ([File: x/uexecutor/keeper/fees.go])

### Summary
`UniversalPayload.MaxFeePerGas`, `MaxPriorityFeePerGas`, `GasLimit`, etc. are plain proto3 `string` fields [1](#0-0) . `ValidateBasic()` only checks these fields for validity **when they are non-empty**: `if value != "" { ... }` [2](#0-1) . An empty string for `max_fee_per_gas` therefore passes `ValidateBasic()` cleanly. Later, `NewAbiUniversalPayload` converts these strings to `*big.Int` via `utils.StringToBigInt`, which silently swallows the parse failure and returns `nil`:

```go
func StringToBigInt(s string) *big.Int {
	bi, _ := new(big.Int).SetString(s, 10)
	return bi
}
``` [3](#0-2) 

This is functionally identical to the reported bug class: a field is assumed to be validated/non-nil (here, by an incomplete `ValidateBasic`), but the conversion path silently produces a nil value instead of erroring, and a later `.Cmp()` call panics on that nil pointer.

### Finding Description
The reachable path is:
1. Any unprivileged user submits `MsgExecutePayload` with `UniversalPayload.MaxFeePerGas = ""` (or any other numeric field left empty). `ValidateBasic()` passes because empty values are skipped from the uint256 check [4](#0-3) .
2. The message is gasless (`/uexecutor.v1.MsgExecutePayload` is in the gasless allowlist), so no fee is required from the attacker to submit it [5](#0-4) .
3. `ExecutePayloadV2` calls `CallUEAExecutePayload` (which succeeds — it only checks `GasLimit`, not `MaxFeePerGas`) and then unconditionally calls `DeductGasFeesFromReceipt` [6](#0-5) .
4. `DeductGasFeesFromReceipt` builds `abiPayload` via `NewAbiUniversalPayload`, which converts `MaxFeePerGas` to `nil` since `StringToBigInt("")` returns `nil` [7](#0-6) .
5. `CalculateGasCost` then calls `maxFeePerGas.Cmp(baseFeeBig)` on this nil `*big.Int`:
```go
if maxFeePerGas.Cmp(baseFeeBig) < 0 {
``` [8](#0-7) 

`(*big.Int)(nil).Cmp(...)` panics with a nil-pointer dereference — exactly the failure mode demonstrated in the external report's PoC (`big.NewInt(64).Cmp(nil)` / the inverse: a nil receiver calling `Cmp`).

### Impact Explanation
`DeductGasFeesFromReceipt` runs inside message execution for `MsgExecutePayload`, a gasless message type reachable by any account (no funding required, per the `AccountInitDecorator` first-use bootstrap) [9](#0-8) . A panic during `DeliverTx`/message handling in CometBFT-based chains is typically recovered by the baseapp's panic handler and converted into a failed tx, not necessarily a chain halt — so the primary confirmed impact is a returned application panic for that message (denial of that user-reachable pathway, and potential wasted validator CPU) rather than confirmed full-node crash/halt of honest validators. Without deeper analysis of `baseapp`'s panic recovery configuration in this exact fork, the practical severity should be treated as message-level DoS/panic recovery rather than confirmed chain halt.

### Likelihood Explanation
High for triggering the panic itself — the only requirement is an empty numeric string field in `UniversalPayload`, something entirely within attacker control and not rejected by `ValidateBasic()`. The `UniversalAccountId` and `verificationData` checks in `MsgExecutePayload.ValidateBasic()` don't touch this field [10](#0-9) ; the UEA contract's `executeUniversalTx` signature check happens before fee deduction and doesn't validate `maxFeePerGas` non-emptiness either.

### Recommendation
- Make `UniversalPayload.ValidateBasic()` require the fee-related fields (`max_fee_per_gas`, `gas_limit`) to be non-empty rather than optionally validated.
- Make `NewAbiUniversalPayload` / `utils.StringToBigInt` return an error (not silently `nil`) when `SetString` fails, and propagate that error out of `DeductGasFeesFromReceipt` before any `.Cmp()`/arithmetic is attempted.
- Add explicit nil checks before every `.Cmp()`/`.Sign()` call on values sourced from `NewAbiUniversalPayload`.

### Proof of Concept
Submit a gasless `MsgExecutePayload`:
```go
msg := &uexecutortypes.MsgExecutePayload{
    Signer:             validSigner,
    UniversalAccountId: validUA,
    UniversalPayload: &uexecutortypes.UniversalPayload{
        To:           "0x000000000000000000000000000000000000dead",
        Data:         "0x",
        GasLimit:     "21000",
        MaxFeePerGas: "",     // empty — passes ValidateBasic
        VType:        uexecutortypes.VerificationType_universalTxVerification,
    },
    VerificationData: "abcdef0123456789",
}
```
Once `CallUEAExecutePayload` succeeds and produces a receipt with `GasUsed > 0`, `DeductGasFeesFromReceipt` → `CalculateGasCost` calls `maxFeePerGas.Cmp(baseFeeBig)` where `maxFeePerGas` is `nil`, panicking exactly as `big.NewInt(64).Cmp(nil)` does in the external report's test.

**Note on confidence:** I was unable to trace whether `baseapp`'s recover-middleware in this fork converts this panic into a normal failed-tx response or whether it can escape to crash the node process; that would require inspecting the specific `RecoverMiddleware`/ante recovery configuration, which I did not have direct file access to confirm. The nil-pointer root cause and its exact reachable trigger path, however, are confirmed in the cited code.

func (msg *MsgExecutePayload) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate universal payload
	if msg.UniversalPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal payload cannot be nil")
	}

	// Validate verificationData
	if len(msg.VerificationData) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "verificationData cannot be empty")
	}
	if _, err := hex.DecodeString(strings.TrimPrefix(msg.VerificationData, "0x")); err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid verificationData hex")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate universal payload structure
	if err := msg.UniversalPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universal payload")
	}

	return nil
}
