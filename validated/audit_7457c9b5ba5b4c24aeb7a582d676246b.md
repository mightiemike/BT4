### Title
Exchange transaction fee is deducted from the trader's balance but never credited to the blackhole/fee pool - ([File: actuator/src/main/java/org/tron/core/actuator/ExchangeTransactionActuator.java])

### Summary
`ExchangeTransactionActuator.execute` computes a non‑zero `calcFee()` and subtracts it from the trading account's balance, but unlike every other fee‑charging actuator in the codebase it never forwards that fee to the black‑hole address or the transaction‑fee pool, and never calls `dynamicStore.burnTrx(fee)`. The TRX is simply removed from the owner's balance and disappears from the ledger with no offsetting credit anywhere.

### Finding Description
All other fee‑charging actuators follow the same pattern: subtract the fee from the payer, then either burn it (`dynamicStore.burnTrx(fee)`) or credit it to the black‑hole account, keeping total‑supply accounting consistent: [1](#0-0) [2](#0-1) [3](#0-2) 

`ExchangeTransactionActuator.execute`, however, computes `fee`, subtracts it from the account balance (`subtractExact(accountCapsule.getBalance(), calcFee())`), performs the token swap, persists the account and exchange, and returns — with no burn or black‑hole credit step at all: [4](#0-3) 

The `validate()` method confirms the fee is genuinely charged and enforced (balance must cover `tokenQuant + calcFee()` for TRX-denominated legs, or the account must simply hold at least `calcFee()`): [5](#0-4) [6](#0-5) 

By contrast, `ExchangeWithdrawActuator` explicitly overrides `calcFee()` to return `0`, so it correctly has no accounting gap: [7](#0-6) 

`ExchangeTransactionActuator` does not override `calcFee()` to zero, meaning it inherits/uses a non‑zero fee value (the same shared exchange fee configuration used by `ExchangeCreateActuator`), which is charged but never accounted for anywhere in the ledger — it is effectively deleted from the account's balance with no corresponding increase in the black‑hole balance or `burnTrx` accounting.

### Impact Explanation
This breaks the fundamental invariant that TRX moved out of an account must be accounted for either as a transfer to another account, a burn (`dynamicStore.burnTrx`), or a black‑hole credit. Every `ExchangeTransactionContract` execution silently destroys `calcFee()` TRX from the sum of tracked balances without recording it as burned. This is a consensus‑level accounting corruption bug: any broadcastable, unprivileged transaction (an ordinary trader submitting `ExchangeTransactionContract`) reduces total accounted TRX without the corresponding burn/black‑hole bookkeeping that the rest of the protocol relies on for supply tracking and auditing.

### Likelihood Explanation
High — this occurs on every single `ExchangeTransactionContract` execution as long as `calcFee()` is non‑zero (which it is, since it is not overridden to zero the way `ExchangeWithdrawActuator` explicitly does). No privileged access is required; any account can trigger it by trading on any existing TRX exchange pair.

### Recommendation
Add the missing fee‑disposition step in `ExchangeTransactionActuator.execute`, mirroring `ExchangeCreateActuator`:
```java
if (dynamicStore.supportBlackHoleOptimization()) {
  dynamicStore.burnTrx(fee);
} else {
  adjustBalance(accountStore, accountStore.getBlackhole(), fee);
}
```
placed after the account/exchange state is persisted and before `ret.setStatus(fee, code.SUCESS)`.

### Proof of Concept
1. Create an exchange pair including TRX (`ExchangeCreateContract`), as covered by `ExchangeCreateActuatorTest`.
2. Broadcast an `ExchangeTransactionContract` from any account with sufficient balance to cover `tokenQuant + calcFee()`.
3. Observe in `ExchangeTransactionActuator.execute` (lines 45–107) that `calcFee()` is deducted from `accountCapsule.getBalance()` via `subtractExact`, the account is persisted, but `dynamicStore.burnTrx(fee)` / black‑hole credit is never invoked, in contrast to the identical pattern present in `ExchangeCreateActuator.execute` (lines 120–124) and `TransferActuator.execute` (lines 61–65). The fee amount vanishes from total tracked balances with no burn record.
