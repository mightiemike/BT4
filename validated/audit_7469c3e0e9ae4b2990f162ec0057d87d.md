### Title
Slippage protection for module-driven PRC20→PC swaps is anchored to a manipulable same-block spot price, not an independent reference price - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Every module-originated swap in `x/uexecutor` (gas-abstraction deposit auto-swap on `GAS`/`GAS_AND_PAYLOAD` inbound execution, and the excess-gas refund swap on outbound finalization) computes its `minPCOut` slippage floor from `GetSwapQuote`, a Uniswap V3 `QuoterV2.quoteExactInputSingle` spot-price read taken in the very same keeper invocation, seconds (or less) before the real swap is executed against the same pool [3](#0-2) . There is no TWAP, no external price oracle, and no independent reference price anywhere in the codebase. This is the same fundamental class of bug as the external report (M-01): the "protection" value is derived from a price an attacker can move in the same block, so the 5% band bounds slippage only relative to an already-attacker-influenced price, not to fair market value.

### Finding Description
`ExecuteInboundGas` (for `GAS` inbounds) and `gasAndPayloadDepositAutoSwap` (for `GAS_AND_PAYLOAD` inbounds) both: (1) fetch `quote` via `GetSwapQuote` against the live Uniswap V3 pool for the PRC20/WPC pair using the token's `defaultFeeTier`, and (2) immediately compute `minPCOut = quote * 95 / 100` and pass it to `CallPRC20DepositAutoSwap`, which performs the actual swap on the same pool [4](#0-3) [5](#0-4) . The same pattern recurs in `applyGasRefund` for the gas-refund swap leg [6](#0-5) .

Because the finalizing transaction (`MsgVoteInbound` reaching 2/3+ threshold, or the outbound-vote finalization tx) is a normal, publicly broadcast Cosmos transaction visible in the mempool before block inclusion, an unprivileged actor can observe it and construct an ordinary sandwich: submit a large swap against the same Uniswap V3 pool (in the fee tier returned by `GetDefaultFeeTierForToken`) to push the spot price unfavorably, let the finalizing transaction execute — which reads the now-skewed price via `GetSwapQuote` and derives `minPCOut` from that skewed price, so the module's swap still clears the 5% check — then submit a back-run transaction restoring the price and capturing the difference. Since `minPCOut` is computed from the manipulated price rather than a fair/TWAP reference, the 5% tolerance does not actually bound loss relative to the token's true value; it only bounds loss relative to the price the attacker just set. This directly parallels the external report's root cause (`amountOutMin` derived from an easily-movable spot execution rather than a protected reference), just moved from a 0% band to a 5% band computed on a poisoned input.

This is most exploitable for PRC20 tokens whose Uniswap V3 pool (at the configured `defaultFeeTier`) has thin liquidity, since the swap amount here is fixed by the inbound deposit amount and the attacker only needs to move price temporarily for the single block containing the finalizing transaction.

### Impact Explanation
Successful exploitation causes the protocol/module account (and transitively the recipient UEA, or the refund recipient) to receive less PC than fair market value for the swapped PRC20/gas token, up to the bound allowed before the swap would revert (~5% of the swapped notional per occurrence, per swap site). Because these swaps are triggered automatically and repeatedly by ordinary cross-chain gas-abstraction inbounds and outbound gas refunds, this can be repeated on every eligible inbound/outbound, and it corrupts the "canonical" `UniversalTx`/`OutboundTx` accounting (`PCTx.GasUsed`/deposit outcomes) with under-value fills without any invariant currently catching it. This is a fund-value-loss issue reachable by an unprivileged actor, matching the "unauthorized... unauthorized state transitions... corruption of PRC20 or native asset accounting" impact categories.

### Likelihood Explanation
Moderate. It requires the attacker to (a) monitor the mempool for `MsgVoteInbound`/`MsgVoteOutbound` finalizing transactions and (b) have sufficient capital/flashloan access to move the specific Uniswap V3 pool's price within the target fee tier for one block, then reverse it — standard MEV sandwich mechanics available to any unprivileged chain user given a public mempool and ordinary block construction, with no requirement on malicious validators/relayers/TSS participants.

### Recommendation
Do not derive `minPCOut` solely from a same-transaction spot-price read of the pool being swapped against. Use a manipulation-resistant reference price instead — e.g., a Uniswap V3 TWAP over a meaningful window (`increaseObservationCardinalityNext` + `observe`), a configured external price oracle, or a governance/registry-set reference exchange rate — and only allow a bounded percentage deviation from that reference for `minPCOut`, independent of the same-block spot price. Additionally consider capping single-block swap size relative to pool liquidity/depth for thin pools, and monitoring/alerting when `GetSwapQuote` deviates sharply from the last observed reference price.

### Proof of Concept
1. Attacker monitors the mempool and observes a `MsgVoteInbound` that will cross the 2/3+ UV threshold for a `GAS_AND_PAYLOAD` inbound depositing PRC20 token `X`, which will trigger `gasAndPayloadDepositAutoSwap` swapping `X → WPC` at `X`'s `defaultFeeTier` pool.
2. Attacker submits (front-run, same or earlier block) a large swap `X → WPC` on that exact Uniswap V3 pool, moving the pool's spot price down for `X`.
3. The `MsgVoteInbound` finalizes; `GetSwapQuote` reads the now-depressed spot price; `minPCOut = quote * 95 / 100` is computed from this depressed quote [7](#0-6) ; `CallPRC20DepositAutoSwap` executes the module's swap and clears the (already-low) `minPCOut` check, delivering less WPC/PC than fair value to the recipient UEA.
4. Attacker submits a back-run swap `WPC → X` restoring the pool price, capturing the value difference extracted from the module's swap.
5. Repeat on every eligible `GAS`/`GAS_AND_PAYLOAD` inbound or outbound gas refund touching a thin-liquidity PRC20 pool.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
