### Title
Quadratic-cost mempool queue cleanup in Echonet/FIFO mode enables a per-block CPU DoS on rejected-transaction processing - (File: crates/apollo_mempool/src/fifo_transaction_queue.rs)

### Summary
`FifoTransactionQueue::remove_by_address` and `remove_txs` use `Vec::retain`/`VecDeque::retain`, which perform a full O(n) scan of the entire queue/staged-transactions buffer on every call [1](#0-0) . In `Mempool::remove_rejected_txs`, this O(n) `remove_by_address` call is invoked once per rejected transaction hash in `commit_block` [2](#0-1) , giving O(rejected_txs × queue_len) total work per committed block — the same "for-loop over a storage/collection operation in a hot per-request/per-block path" pattern flagged as the DoS-class root cause in the TangleStaking `_unstake` report (an O(n) removal reachable repeatedly from ordinary user transactions, without any privileged actor).

### Finding Description
`FifoTransactionQueue` stores queued transactions in a `VecDeque<FifoTransaction>` (`queue`) plus a `Vec<FifoTransaction>` (`staged_txs`) [3](#0-2) .

`remove_by_address` removes all entries belonging to one address by scanning the entire `queue` and `staged_txs` with `retain`:
```
fn remove_by_address(&mut self, address: ContractAddress) -> bool {
    let len_before = self.queue.len() + self.staged_txs.len();
    self.queue.retain(|tx| tx.tx_reference.address != address);
    self.staged_txs.retain(|tx| tx.tx_reference.address != address);
    ...
}
``` [1](#0-0) 

This is called from `Mempool::remove_rejected_txs`, which loops over every `tx_hash` in `rejected_tx_hashes` (a set produced by the batcher after block execution/validation) and, for each one found in the pool, calls `self.tx_queue.remove_by_address(tx.contract_address())`:
```
for tx_hash in rejected_tx_hashes {
    if rewound_tx_hashes.contains(&tx_hash) { continue; }
    if let Ok(tx) = self.tx_pool.remove(tx_hash) {
        self.tx_queue.remove_by_address(tx.contract_address());
        ...
    }
}
``` [2](#0-1) 

`remove_rejected_txs` is invoked unconditionally from `commit_block`, which runs after every committed block [4](#0-3) . Because each rejected transaction triggers an independent full-queue scan, the total cost of processing `m` rejected transactions against a queue of length `n` is O(m·n), not O(m+n). An attacker who fills the FIFO mempool with many transactions (bounded by `capacity_in_bytes`, referenced in `apollo_mempool_config/src/config.rs`) and arranges for many of them to be marked "rejected" (e.g., transactions that fail cheaply during validation/execution, which is far cheaper to produce than transactions that consume full execution gas) forces the mempool to perform up to O(n²) comparisons on every block commit.

This mirrors the reported bug class exactly: an unprivileged party can, through nothing more than submitting ordinary transactions, force a linear-scan/removal operation to run repeatedly in a critical per-block hot path, and the cost scales with attacker-controlled queue occupancy rather than with the attacker's own resource consumption.

### Impact Explanation
If enough transactions are simultaneously queued and rejected, the O(n·m) rescanning inflates the CPU time the mempool component spends per committed block. Since mempool processing gates the batcher's ability to pull the next block's candidate transactions, sustained high queue occupancy combined with a steady stream of cheaply-rejected transactions can materially slow block production, degrading the sequencer's ability to confirm new transactions in a timely manner — a resource-exhaustion / availability impact on the sequencing pipeline, not merely an isolated slow call.

### Likelihood Explanation
Likelihood is moderate: the FIFO queue path is used specifically in Echonet/FIFO mempool mode [5](#0-4) , so exposure depends on deployment configuration. The attack requires the mempool to actually hold a large number of transactions from many distinct addresses and for a large fraction to be rejected in the same commit cycle; this is achievable by an ordinary (unprivileged) submitter with no special access, but is bounded by the mempool's `capacity_in_bytes` limit, which caps `n` and thus caps the worst-case quadratic blowup to a deployment-configured maximum rather than being fully unbounded.

### Recommendation
Avoid per-rejected-tx full-queue scans. Batch the removal: collect all rejected transactions' addresses/hashes first, then perform a single O(n) pass over `queue`/`staged_txs` (similar to the batched `remove_txs` already implemented, which builds a hash set of target tx hashes and does one retain pass [6](#0-5) ) instead of calling `remove_by_address` once per rejected transaction. Alternatively, index queued/staged transactions by address (e.g., `HashMap<ContractAddress, Vec<index>>` or similar) so that per-address removal is O(k) in the number of that address's own transactions rather than O(n) in the whole queue.

### Proof of Concept
Conceptual reproduction (cannot be executed without full node access):
1. Configure a node in Echonet/FIFO mempool mode.
2. Submit `n` transactions from `n` distinct addresses up to the mempool's `capacity_in_bytes` limit, all validly queued in `FifoTransactionQueue.queue`.
3. Craft/submit an additional set of `m` transactions engineered to be rejected cheaply during validation (e.g., transactions with bad nonces/signatures that fail before full execution) so they appear in `rejected_tx_hashes` after a block commit.
4. Observe that `Mempool::commit_block` → `remove_rejected_txs` performs `m` separate calls to `FifoTransactionQueue::remove_by_address`, each scanning the full `n`-length `queue`/`staged_txs`, yielding O(n·m) work concentrated in a single `commit_block` invocation — measurable as a CPU/latency spike proportional to `n·m` compared to the batched `remove_txs` path.

            }

                false
            } else {
                true
            }

    #[instrument(skip(self, args))]
    pub fn commit_block(&mut self, args: CommitBlockArgs) {
        let CommitBlockArgs { address_to_nonce, rejected_tx_hashes } = args;
        debug!(
            "Committing block with {} addresses and {} rejected tx to the mempool.",
            address_to_nonce.len(),
            rejected_tx_hashes.len()
        );

        let mut committed_nonce_updates = AddressToNonce::new();
        // Align mempool data to committed nonces.
        for (&address, &next_nonce) in &address_to_nonce {
            self.validate_commitment(address, next_nonce);
            committed_nonce_updates.insert(address, next_nonce);

            // Remove out-of-date transactions, if any.
            // Note: In FIFO mode, get_nonce returns None (committed txs were already popped from
            // queue during get_txs), so this cleanup is skipped.
            if self
                .tx_queue
                .get_nonce(address)
                .is_some_and(|queued_nonce| queued_nonce != next_nonce)
            {
                assert!(
                    self.tx_queue.remove_by_address(address),
                    "Expected to remove address from queue."
                );
            }

            // Remove from pool.
            let n_removed_txs = self.tx_pool.remove_up_to_nonce_when_committed(address, next_nonce);
            metric_count_committed_txs(n_removed_txs);
            self.decrement_stuck_txs_if_gap_account(address, n_removed_txs);

            // Close nonce gap, if exists.
            // In FIFO mode, we handle gap filling when rewinding transactions.
            if !self.is_fifo() && self.tx_queue.get_nonce(address).is_none() {
                if let Some(tx_reference) =
                    self.tx_pool.get_by_address_and_nonce(address, next_nonce)
                {
                    self.insert_to_tx_queue(tx_reference);
                }
            }
        }

        // Commit block and rewind nonces of addresses that were not included in block.
        let addresses_to_rewind = self.state.commit(address_to_nonce.clone());

        let rewound_tx_hashes =
            self.rewind_txs(addresses_to_rewind, &address_to_nonce, &rejected_tx_hashes);
        debug!("Aligned mempool to committed nonces.");

        // Remove rejected transactions from the mempool.
        let mut account_nonce_updates =
            self.remove_rejected_txs(rejected_tx_hashes, &rewound_tx_hashes);

        // Committed nonces should overwrite rejected transactions.
        account_nonce_updates.extend(committed_nonce_updates);

        self.update_accounts_with_gap(account_nonce_updates);
        self.update_state_metrics();
    }
