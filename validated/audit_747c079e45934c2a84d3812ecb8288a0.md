### Title
Unbounded `RawPayload`/`UniversalPayload.Data` size in `MsgVoteInbound` causes unbounded on-chain storage growth and per-vote gas cost - (File: `x/uexecutor/types/inbound.go`, `x/uexecutor/keeper/inbound.go`, `x/uexecutor/keeper/msg_vote_inbound.go`)

### Summary
`MsgVoteInbound.Inbound.RawPayload` (and the decoded `UniversalPayload.Data`) is attacker-controlled — it originates from a source-chain gateway transaction that any unprivileged user can craft — and is stored in full, on-chain, in `PendingInbounds` / `UniversalTx` with no size limit enforced anywhere in validation. This mirrors the reported AMB pattern of writing an unbounded, attacker-sized payload body directly to expensive contract/module storage instead of only committing a bounded proof/reference.

### Finding Description
`MsgVoteInbound.ValidateBasic` only calls `Inbound.ValidateBasic()` [1](#0-0) , which checks that identifying fields (`source_chain`, `tx_hash`, `sender`, `log_index`, `tx_type`) are non-empty but never bounds the size of `RawPayload` or `VerificationData` [2](#0-1) . `UniversalPayload.ValidateBasic()` similarly validates hex-decodability of `Data` but never checks its length [3](#0-2) .

Because `MsgVoteInbound` is gasless-whitelisted (`app/txpolicy/gasless.go`), UVs vote on this message paying no fee, and the message itself carries no protocol-level bound on `Inbound` size [4](#0-3) .

`RecordInboundVote` stores the **entire** `Inbound` struct — including the full `RawPayload` bytes — inside a `types.InboundVariant` appended to `PendingInboundEntry.Variants`, and persists it via `k.PendingInbounds.Set` on every vote [5](#0-4) . This happens once per unique variant per UV vote before ballot finalization even completes. `RawPayload` is only cleared after successful decode into `UniversalPayload`, and only for the two payload-carrying tx types [6](#0-5) ; if decode fails, or for other paths, the raw bytes persist. Even after decode, the resulting `UniversalPayload.Data` (still attacker-controlled and unbounded) is retained as part of the finalized `UniversalTx.InboundTx` record permanently on-chain.

The root cause is structurally identical to the reported bug: a variable-length, attacker-controlled payload body is written wholesale into consensus state (instead of only a bounded commitment/proof + off-chain/calldata payload), with no size ceiling enforced at any validation layer (`ValidateBasic`, ante handler, or execution-time checks).

### Impact Explanation
An unprivileged external attacker can trigger this by initiating a source-chain deposit/gateway transaction with an arbitrarily large payload (the bug report notes payload sizes are only bounded by the AMB/relay message-size limit; here the analogous bound is only the underlying Cosmos/Tendermint tx-size limit, which is far larger than what expensive KV-store writes can economically absorb). Honest UVs, acting correctly, are forced to observe and vote this event via `MsgVoteInbound`, causing the full payload to be written to `PendingInbounds` state (potentially multiple times if variants diverge) and then again into the finalized `UniversalTx`. This:
- Inflates per-vote gas/state costs disproportionately (since `MsgVoteInbound` is gasless, the cost is absorbed by the chain/validators, not the attacker),
- Bloats permanent chain state with attacker-chosen, unbounded blobs,
- Can push individual `MsgVoteInbound` executions toward block gas-limit territory, a similar economic/DoS class to the original report, reachable purely by an ordinary user-initiated deposit with no privileged actor involved.

This is a scoped, non-network-level DoS/state-bloat issue reachable via the default inbound submission path, matching the "Allowed Impact" gate for denial of service caused by ordinary unprivileged user action.

### Likelihood Explanation
High: any user can construct a large payload in the source-chain deposit calldata used to fund a Push Chain gateway event; UVs are required by protocol design to submit whatever the source-chain event contains (validators aren't expected to reject/truncate legitimate-looking events), so the harmful payload flows straight through `VoteInbound` → `RecordInboundVote` → persistent storage without any gate.

### Recommendation
Enforce an explicit maximum length on `Inbound.RawPayload`, `Inbound.VerificationData`, and `UniversalPayload.Data` in `Inbound.ValidateBasic()` / `UniversalPayload.ValidateBasic()`, rejecting the vote before it reaches `RecordInboundVote`. Consider storing only a hash/commitment of `RawPayload` in `PendingInbounds`/`InboundVariant` for audit purposes, with the full bytes carried in calldata/off-chain storage and referenced by hash, consistent with the report's recommendation to commit only a proof on-chain rather than the full payload body.

### Proof of Concept
1. Attacker performs a deposit on a connected source chain through the gateway contract, encoding an oversized calldata payload (e.g., tens of KB) as the deposit's associated payload.
2. Honest UVs observe the event and submit `MsgVoteInbound` with `Inbound.RawPayload` set to the oversized hex blob; `ValidateBasic` passes since no length check exists [2](#0-1) .
3. `VoteInbound` → `RecordInboundVote` writes the full `Inbound` (with the oversized `RawPayload`) into `PendingInboundEntry.Variants` and commits it to the `PendingInbounds` collection on every vote [5](#0-4) .
4. Repeating this with many distinct large-payload deposits produces sustained, gasless, attacker-driven state growth and elevated per-vote gas cost for the chain, with no economic cost to the attacker on Push Chain (the burdened party is the chain/UVs, not the depositor).

func (p Inbound) ValidateBasic() error {
	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)
	if chain == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}
	if !strings.Contains(chain, ":") {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain must be in CAIP-2 format <namespace>:<reference>")
	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")
	}

	// Validate sender — needed for revert recipient fallback
	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	// Validate log_index — needed for UTX key
	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}

	// Validate tx_type enum — needed to route execution
	if _, ok := TxType_name[int32(p.TxType)]; !ok || p.TxType == TxType_UNSPECIFIED_TX {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid tx_type: %v", p.TxType)
	}

	return nil
}

// ValidateBasic does the sanity check on the UniversalPayload fields.
func (p UniversalPayload) ValidateBasic() error {
	// Validate 'to' address
	if strings.TrimSpace(p.To) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "to address cannot be empty")
	}
	if !utils.IsValidAddress(p.To, utils.HEX) {
		return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid to address format: %s", p.To)
	}

	// Validate 'data' is a valid hex string
	if len(p.Data) > 0 {
		if _, err := hex.DecodeString(strings.TrimPrefix(p.Data, "0x")); err != nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid hex data")
		}
	}

	// Validate all numeric string fields as uint256
	uintFields := map[string]string{
		"value":                    p.Value,
		"gas_limit":                p.GasLimit,
		"max_fee_per_gas":          p.MaxFeePerGas,
		"max_priority_fee_per_gas": p.MaxPriorityFeePerGas,
		"nonce":                    p.Nonce,
		"deadline":                 p.Deadline,
	}

	for fieldName, value := range uintFields {
		if value != "" {
			bi, ok := new(big.Int).SetString(value, 10)
			if !ok || bi.Sign() < 0 {
				return errors.Wrapf(sdkerrors.ErrInvalidRequest, "%s must be a valid unsigned integer", fieldName)
			}
		}
	}

	if _, ok := VerificationType_name[int32(p.VType)]; !ok {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid verificationData type: %v", p.VType)
	}

	return nil
}
