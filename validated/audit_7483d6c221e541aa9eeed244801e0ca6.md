### Title
Wallet Contract's `has_in_flight_tx` guard can be permanently stuck at `true`, freezing an ETH-implicit account forever - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
The NEAR Wallet Contract (the contract deployed on every ETH-implicit account to translate Ethereum-style signed transactions into NEAR actions) uses a single boolean flag, `has_in_flight_tx`, to serialize execution: it is set to `true` right before dispatching a cross-contract promise chain and is only cleared back to `false` inside a callback that is supposed to run once that chain resolves. `rlp_execute` — the only public entry point that can move money or call contracts from this account — unconditionally refuses to do anything while `has_in_flight_tx == true`, and there is no other method that resets the flag. If any callback in the promise chain (`address_check_callback`, `nep_141_storage_balance_callback`) fails to complete (panics) after the flag was already committed as `true` from the previous step, the flag can never be cleared again, and the account is permanently unable to transact — an un-cancelable, un-recoverable "stuck order" exactly analogous to Bracket.sol's blacklisted-recipient DOS.

### Finding Description
`rlp_execute` guards all state-changing behavior behind the flag: [1](#0-0) 

The flag's own doc comment states the required invariant explicitly — that it must be `true` exactly while a promise is outstanding and `false` otherwise: [2](#0-1) 

Each intermediate callback resets the flag to `false` on entry and then, if it needs to schedule further cross-account work, sets it back to `true` before returning a `Promise`: [3](#0-2) [4](#0-3) 

Because a NEAR function call's state mutations are only committed if the call succeeds (a panic rolls back the whole receipt, including any earlier `self.has_in_flight_tx = false` assignment in that same execution), any panic that occurs inside one of these callbacks — after the *previous* step already committed `has_in_flight_tx = true` — leaves the persisted flag at `true` forever. There is no other public method that can reset it: `ban_relayer` and `rlp_execute_callback` are the only two functions that ever write `false`, and both are reachable exclusively via the same promise chain that just failed to run. [5](#0-4) 

The static gas budgeted for each of these callbacks is a small, hard-coded constant plus the user-controlled `action.gas()` taken from the signed Ethereum transaction, with only a fixed few-Tgas margin left over for the callback's own bookkeeping (JSON (de)serialization, promise construction, nested `.then()` calls): [6](#0-5) [7](#0-6) [8](#0-7) 

If that fixed margin is ever exceeded (e.g. by an unusually long `receiver_id`, an added future transaction kind with heavier callback logic, or simply an edge case in gas accounting), the callback itself runs out of gas and panics — after the enclosing `has_in_flight_tx = true` from the prior step is already durably committed to state, and before the callback's own `self.has_in_flight_tx = false`/`= true` transition can be committed. The account is now stuck: every future `rlp_execute` call immediately returns `"transaction already in progress, please try again later"` without ever incrementing the nonce or moving funds, and no other entry point exists to clear the flag.

### Impact Explanation
This is the direct analog of the Bracket.sol bug: a per-account guard/state flag that gets set before an operation that is expected to always eventually clear it, but for which the protocol never validates that the "clearing" step is guaranteed to succeed. Once the flag is corrupted, the account (and all NEAR/NEP-141 balances it holds, since the Wallet Contract is the *only* way an ETH-implicit account can move funds — it "cannot be deleted, nor can a full access key be added") is permanently frozen with no admin, owner, or relayer able to recover it. This matches the "permanently frozen funds" acceptance criterion.

### Likelihood Explanation
The path is reachable by an ordinary, unprivileged party: any relayer or the account owner themselves calling `rlp_execute` with a legitimately signed Ethereum transaction that happens to trigger the multi-hop NEP-141 or address-check callback path. No malicious validator, network-layer access, or privileged role is required — only a single submitted transaction/receipt sequence that causes one of the two intermediate callbacks (`address_check_callback`, `nep_141_storage_balance_callback`) to panic after the flag has already been persisted as `true`. Whether this is trivially triggerable today depends on exact gas-cost profiling of those callbacks (not verifiable via static reading alone), but the structural weakness — no independent, panic-safe recovery path for `has_in_flight_tx` — is unconditionally present in the code.

### Recommendation
- Do not gate the flag purely on optimistic "set true / promise chain must eventually flip it back" logic; instead persist enough gas headroom (with an explicit, test-enforced safety margin) for every callback so that legitimate cross-contract calls cannot panic due to gas exhaustion.
- Add a recovery mechanism independent of the promise chain (e.g., a time-boxed "in-flight" timestamp that permits force-clearing the flag after a timeout), similar to how the Bracket.sol fix would require validating the recipient/refund path before locking funds in a pending state.
- Consider making the flag-clearing step (`self.has_in_flight_tx = false`) happen in a dedicated, minimal-gas, panic-resistant final callback that runs regardless of any earlier logic's success/failure, so a bug or gas miscalculation upstream cannot leave the account permanently locked.

### Proof of Concept
Conceptual reproduction (would require gas-cost instrumentation to force the exact panic, but the logical sequence is fully supported by the code):
1. Deploy an ETH-implicit account with the Wallet Contract and register a relayer key, as in `test_wallet_contract_interaction`.
2. Owner signs an Ethereum-style transaction encoding an ERC-20 (NEP-141) transfer to an unregistered `receiver_id`, with `action.gas()` set to a value that satisfies `test_insufficient_gas`-style outer checks but leaves `nep_141_storage_balance_callback`'s own execution with barely more than its fixed constant margin (`NEP_141_STORAGE_BALANCE_CALLBACK_GAS` minus the gas re-delegated to `storage_deposit`/`transfer`/`rlp_execute_callback`) — see constants and call in: [9](#0-8) 
3. Relayer submits the outer `rlp_execute` transaction; `inner_rlp_execute` commits `has_in_flight_tx = true` and dispatches the `storage_balance_of` call, whose callback (`nep_141_storage_balance_callback`) resets the flag to `false`, then attempts to construct the follow-up `storage_deposit` + transfer + `rlp_execute_callback` promise chain and runs out of gas doing so.
4. The callback receipt fails; its state changes (including the `false` write) are rolled back, so the account's persisted `has_in_flight_tx` remains `true` from step 3.
5. Any subsequent call to `rlp_execute` (by owner or any relayer) now unconditionally returns `"Error: transaction already in progress, please try again later."` forever, per the guard at the top of `rlp_execute`: [10](#0-9)

    #[private]
    pub fn address_check_callback(
        &mut self,
        target: AccountId,
        action: near_action::Action,
        caller_deposit: Option<CallerDeposit>,
    ) -> PromiseOrValue<ExecuteResponse> {
        self.has_in_flight_tx = false;
        let maybe_account_id: Option<AccountId> = match env::promise_result(0) {
            PromiseResult::Failed => {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Call to Address Registrar contract failed".into()),
                });
            }
            PromiseResult::Successful(value) => match serde_json::from_slice(&value) {
                Ok(x) => x,
                Err(_) => {
                    return PromiseOrValue::Value(ExecuteResponse {
                        success: false,
                        success_value: None,
                        error: Some("Unexpected response from account registrar".into()),
                    });
                }
            },
        };
        let current_account_id = env::current_account_id();
        let promise = if maybe_account_id.is_some() {
            // We intentionally do not increment the nonce in this case because the
            // error is caused by a faulty relayer, not the user. An honest relayer
            // may still be able to successfully send the user's intended transaction.
            if env::signer_account_id() == current_account_id {
                create_ban_relayer_promise(current_account_id)
            } else {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Invalid target: target is address corresponding to existing named account_id".into()),
                });
            }
        } else {
            // We must increment the nonce at this point to prevent replay of the transaction.
            // Recall that the nonce was not incremented in `inner_rlp_execute` in the case that
            // the registrar contract was called (i.e. in the case we end up inside this callback).
            self.nonce = self.nonce.saturating_add(1);
            let ext =
                WalletContract::ext(current_account_id).with_static_gas(RLP_EXECUTE_CALLBACK_GAS);
            match action_to_promise(target, action)
                .map(|p| p.then(ext.rlp_execute_callback(caller_deposit)))
            {
                Ok(p) => p,
                Err(e) => {
                    return PromiseOrValue::Value(e.into());
                }
            }
        };
        self.has_in_flight_tx = true;
        PromiseOrValue::Promise(promise)
    }

                    });
                }
            },
        };
        let current_account_id = env::current_account_id();
        let ext = WalletContract::ext(current_account_id).with_static_gas(RLP_EXECUTE_CALLBACK_GAS);
        let promise = match maybe_storage_balance {
            Some(_) => {
                // receiver_id is registered so we can send the transfer
                // without additional actions. Note: in the standard NEP-141
                // implementation it is impossible to have `Some` storage balance,
                // but have it be insufficient to transact.
                match action_to_promise(token_id, action)
                    .map(|p| p.then(ext.rlp_execute_callback(caller_deposit)))
                {
                    Ok(p) => p,
                    Err(e) => {
                        return PromiseOrValue::Value(e.into());
                    }
                }
            }
            None => {
                // receiver_id is not registered so we must call `storage_deposit` first.
                let storage_deposit_args =
                    format!(r#"{{"account_id": "{receiver_id}"}}"#).into_bytes();
                let transfer_function_call = match action {
                    near_action::Action::FunctionCall(x) => x,
                    _ => {
                        return PromiseOrValue::Value(ExecuteResponse {
                            success: false,
                            success_value: None,
                            error: Some(
                                "Expected function call action to perform NEP-141 transfer".into(),
                            ),
                        });
                    }
                };
                Promise::new(token_id)
                    .function_call(
                        "storage_deposit".into(),
                        storage_deposit_args,
                        NEP_141_STORAGE_DEPOSIT_AMOUNT,
                        NEP_141_STORAGE_DEPOSIT_GAS,
                    )
                    .function_call(
                        transfer_function_call.method_name,
                        transfer_function_call.args,
                        transfer_function_call.deposit,
                        transfer_function_call.gas,
                    )
                    .then(ext.rlp_execute_callback(caller_deposit))
            }
        };
        self.has_in_flight_tx = true;
        PromiseOrValue::Promise(promise)
    }

    #[private]
    pub fn rlp_execute_callback(
        &mut self,
        caller_deposit: Option<CallerDeposit>,
    ) -> ExecuteResponse {
        self.has_in_flight_tx = false;
        let n = env::promise_results_count();

        if n == 0 {
            // `rlp_execute_callback` is called directly in the case of an emulated self-transfer.
            return ExecuteResponse { success: true, success_value: None, error: None };
        } else if n > 1 {
            return ExecuteResponse {
                success: false,
                success_value: None,
                error: Some(format!(
                    "Invariant violation: this callback comes after a single promise. n={n}"
                )),
            };
        }

        match env::promise_result(0) {
            PromiseResult::Failed => {
                // The cross-contract call failed, refund the caller if needed
                if let Some(CallerDeposit { account_id, yocto_near }) = caller_deposit {
                    let refund_promise = env::promise_batch_create(&account_id);
                    env::promise_batch_action_transfer(
                        refund_promise,
                        NearToken::from_yoctonear(yocto_near.into()),
                    );
                }

                ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Failed Near promise".into()),
                }
            }
            PromiseResult::Successful(value) => {
                ExecuteResponse { success: true, success_value: Some(value), error: None }
            }
        }
    }

    #[private]
    pub fn ban_relayer(&mut self) -> ExecuteResponse {
        self.has_in_flight_tx = false;
        ExecuteResponse {
            success: false,
            success_value: None,
            error: Some("Error: faulty relayer".into()),
        }
    }
