### Title
Floor-and-drop signer-set apportionment in `make_signer_set` can zero out the entire signer set, degrading to a zero-weight/zero-threshold state that requires no signer approval - ([File: stackslib/src/chainstate/stacks/boot/mod.rs])

### Summary
`StacksChainState::make_signer_set` (used by PoX-2/3/4 reward-set computation, called from `make_reward_set`) assigns each aggregated signer a weight of `stacked_amt / threshold` and unconditionally drops any signer whose weight floors to `0`. If the number of distinct signers exceeds `reward_slots` and their stakes are close to equal, *every* signer's weight floors to `0`, and the entire signer set is dropped, exactly the "floor-and-drop" degenerate mode that the codebase's own regression test in `pox_5_make_signer_set` explicitly documents and fixes for PoX-5, but which the older/general `make_signer_set` path still exhibits.

### Finding Description
`make_signer_set` computes, for each aggregated signing key:
```
weight = stacked_amt / threshold   // floor division
if weight == 0 { drop entry }
``` [1](#0-0) 

This is precisely the "floor-and-drop scheme" that the newer PoX-5 implementation deliberately replaced with a largest-remainder ("Hare") allocation, because the naive floor-and-drop scheme can zero out *every* signer's weight when there are more distinct signers than `reward_slots` and stakes are roughly equal: [2](#0-1) 

The codebase even carries a dedicated regression test proving this exact failure mode and its fix — but only for the PoX-5 code path: [3](#0-2) 

`make_signer_set` is reached from `make_reward_set`, which is used by `pox_4_compute_and_update_signers` (and equivalently by PoX-2/PoX-3 flows) to compute the signer set for a reward cycle: [4](#0-3) [5](#0-4) 

Once the resulting signer set is empty, `reward_set.total_signing_weight()` will be `0`, and `NakamotoBlockHeader::compute_voting_weight_threshold(0)` returns `0`. `verify_signer_signatures` then requires `total_weight_signed >= threshold`, i.e. `0 >= 0`, which trivially holds even with **zero signatures**: [6](#0-5) [7](#0-6) 

The equality broken is the one this class of bug always breaks: "signer weight below/above threshold from the correct set." Here the threshold itself collapses to `0` because the weight-apportionment function incorrectly zeroed a nonempty, legitimately-staked signer population, so *no* signer approval is required at all for that reward cycle — any miner-produced Nakamoto block would satisfy `verify_signer_signatures` unconditionally.

### Impact Explanation
This is High/Critical depending on realized conditions: if the degenerate case is hit for a live reward cycle, block signing is silently disabled for that cycle (any block, valid or attacker-crafted, passes signature verification with 0 required weight), which is equivalent to a network-wide acceptance of blocks that were never validated by the signer set - a signer/threshold divergence from the intended protocol invariant that the honest supermajority must approve blocks. This directly matches the allowed impact class "a minority-triggerable sortition/VRF/static-validation divergence" / "an invalid block accepted... network-wide," since it removes the signer gate entirely rather than merely stalling the chain.

### Likelihood Explanation
Triggering requires the aggregated per-signer amounts for a reward cycle to be such that `count(distinct signers) > reward_slots` and every individual stacked amount is `< total_ustx_locked / reward_slots` (i.e., no signer holds more than their even share). This can occur organically whenever a large number of small, roughly-equal stackers register signing keys (common under decentralization-friendly configurations), or be nudged by a single additional low-stake signer registration to push the distinct-signer count just over `reward_slots` while stakes remain near-equal - requiring only an unprivileged stacking transaction with a signing key, not any majority stake or admin action. The fact that the developers already wrote an explicit regression test describing and fixing this exact scenario for PoX-5 confirms it is a real, previously-encountered failure mode, and it appears not to have been backported to the shared `make_signer_set` path used by PoX-2/3/4.

### Recommendation
Port the largest-remainder ("Hare") apportionment logic from `pox_5_make_signer_set` (guaranteeing `weight >= 1` for at least `min(reward_slots, distinct_signers)` signers) into `StacksChainState::make_signer_set`, or otherwise ensure the general reward/signer-set computation can never produce a nonempty stacker population that floors entirely to a zero-weight, zero-threshold signer set.

### Proof of Concept
1. Configure a reward cycle with `reward_slots = R`.
2. Register `R + 1` (or more) distinct signing keys each with stacked amounts approximately equal to `total_ustx_locked / (R + 1)` (all below `threshold = total_ustx_locked / R`, since `threshold` uses the smaller `R`, not `R+1`).
3. Call `make_reward_set` → `make_signer_set`: every entry computes `weight = stacked_amt / threshold == 0` and is filtered out, per `stackslib/src/chainstate/stacks/boot/mod.rs:1051-1065`.
4. The resulting `RewardSet` has no signers; `total_signing_weight() == 0`; `compute_voting_weight_threshold(0) == 0`.
5. Any Nakamoto block for that reward cycle passes `verify_signer_signatures` with zero collected signatures (`0 >= 0`), bypassing signer approval entirely for the cycle — reproduce by unit-testing `NakamotoBlockHeader::verify_signer_signatures` against a `RewardSet` built from step 3's output and an empty `signer_signature` vector, and observe it returns `Ok(0)` instead of erroring.

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
