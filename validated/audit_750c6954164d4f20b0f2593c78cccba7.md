### Title
`handleFailedOutbound` never re-mints funds for a failed `INBOUND_REVERT` outbound, permanently destroying user funds - (File: x/uexecutor/keeper/outbound.go)

### Summary
When an inbound deposit fails to execute on Push Chain, the protocol automatically creates a `TxType_INBOUND_REVERT` outbound to send the bridged funds back to the depositor on the source chain [1](#0-0) . If that revert outbound itself fails to land on the destination (source) chain — for any external-chain reason analogous to Lido's unhandled withdrawal-amount limits (a reverting transfer, a blacklisted/paused token, a dust amount below a destination-chain minimum such as Solana's rent-exemption floor, insufficient gas, etc.) — the finalize logic silently drops the funds instead of restoring them, because `TxType_INBOUND_REVERT` is not one of the tx types re-minted in `handleFailedOutbound`.

### Finding Description
`FinalizeOutbound` routes any `Status_OBSERVED` outbound with `obs.Success == false` to `handleFailedOutbound`, which is supposed to "mint back the bridged tokens to the revert recipient" before marking the outbound `REVERTED`: [2](#0-1) 

The re-mint block is gated by:
```go
if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
    outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {
```
`TxType_INBOUND_REVERT` — the exact tx type used when Push Chain auto-generates a revert outbound after an inbound execution failure — is **not** in this list [3](#0-2) . When this branch is skipped, execution falls straight through to:
```go
outbound.OutboundStatus = types.Status_REVERTED
...
return k.UpdateOutbound(ctx, utxId, outbound)
``` [4](#0-3) 

No PRC20/asset is re-minted to any recipient, and the outbound is finalized as `REVERTED` (not `ABORTED`), so it is not even flagged for manual/admin recovery the way a failed re-mint on the covered tx types would be [5](#0-4) .

This is the direct analog of the Lido H-2 pattern: a downstream, externally-imposed constraint on the terminal step of the "make the user whole again" flow (Lido's withdrawal-amount limits vs. Push Chain's destination-chain execution constraints) causes that terminal step to fail, and — unlike Lido, where the funds were at least stuck in the queue — here the code path actively finalizes the transaction as done while skipping the compensating mint, so the funds are unconditionally lost, not just locked.

### Impact Explanation
This is a permanent, unrecoverable loss of user/protocol-controlled funds reachable via ordinary usage: an unprivileged user's normal deposit can fail downstream for many benign reasons (missing/removed token config, CEA execution failure, payload revert), which per `x/uexecutor/README.md` and `vote_inbound_validation_test.go` automatically produces an `INBOUND_REVERT` outbound [6](#0-5) . If that revert outbound then fails on the destination chain for any reason outside the attacker's or Push Chain's control (destination-chain-level rejection, analogous to Lido's min/max withdrawal enforcement), the bridged value is neither delivered to the user on the external chain nor restored on Push Chain — it disappears from both ledgers. This satisfies the in-scope impact of "permanent loss ... of user or protocol-controlled funds" and "corruption of ... UniversalTx state."

### Likelihood Explanation
Likelihood is meaningful rather than purely theoretical: the `INBOUND_REVERT` path is already exercised by ordinary failure modes (test suite explicitly covers "non-isCEA FUNDS inbound deposit failure DOES create revert outbound") and does not require any privileged action to trigger — a user only needs their inbound execution to fail once (easy, e.g. by targeting an unconfigured token or a reverting payload) and then have the automatically generated revert transaction itself fail on the destination chain (plausible via any transient or asset-specific destination-chain rejection). No malicious validator, admin, or key compromise is needed; the bug is a straightforward code-coverage gap in `handleFailedOutbound`'s type-switch, independent of validator honesty.

### Recommendation
Include `types.TxType_INBOUND_REVERT` (and reassess `RESCUE_FUNDS`/`PAYLOAD` similarly) in the re-mint condition of `handleFailedOutbound`, or add an explicit compensating path for revert-outbound failures. At minimum, a failed `INBOUND_REVERT` outbound must either re-mint the PRC20/native asset back to the original depositor on Push Chain, or be marked `Status_ABORTED` (not `REVERTED`) so it surfaces for manual/admin recovery instead of silently finalizing as a lost transaction.

### Proof of Concept
1. A user's inbound `FUNDS` deposit fails during Push Chain execution (e.g., its token config is unavailable), causing the keeper to auto-create an `OutboundTx` with `TxType: TxType_INBOUND_REVERT` targeting the source chain, per `vote_inbound_validation_test.go` [7](#0-6) .
2. Universal Validators sign and broadcast this revert transaction to the source chain via the standard TSS/broadcaster pipeline.
3. The transaction fails to execute on the source chain for a destination-chain-imposed reason (e.g., transfer reverts, recipient account fails a minimum-balance/rent-exemption check, token is paused/blacklisted).
4. UVs reach quorum on `MsgVoteOutbound` with `ObservedTx.Success = false`.
5. `VoteOutbound` → `FinalizeOutbound` → `handleFailedOutbound` is invoked with `outbound.TxType == TxType_INBOUND_REVERT`.
6. The `if` condition in `handleFailedOutbound` evaluates to `false`, so the re-mint block is skipped entirely; the outbound is marked `Status_REVERTED` with no `PcRevertExecution` and no funds restored anywhere [8](#0-7) .
7. The user's originally bridged funds are permanently gone: not delivered externally, not re-minted on Push Chain, and not flagged `ABORTED` for operator intervention.

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}

	outbound.OutboundStatus = types.Status_REVERTED
	k.Logger().Info("outbound reverted",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)

	// Refund excess gas regardless of tx type — gas was consumed on the external
	// chain whether the execution succeeded or failed.
	k.applyGasRefund(ctx, &outbound, obs)

	return k.UpdateOutbound(ctx, utxId, outbound)
}
