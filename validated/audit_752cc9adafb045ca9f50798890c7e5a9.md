### Title
Attacker-crafted CEA inbound forces an unconsenting recipient smart contract to pay unbounded gas fees for attacker-controlled `executeUniversalTx` execution — (File: `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/execute_inbound_funds_and_payload.go`, `x/uexecutor/keeper/fees.go`)

### Summary
The C4 finding is a gas-griefing bug where a malicious token forces a victim buyer to pay an attacker-inflated, gas-consumption-derived fee that the buyer never agreed to. Push Chain's `isCEA` inbound path has the same structural flaw: an unprivileged external-chain sender fully controls the `Recipient` address, the `UniversalPayload` (including `Data`, `GasLimit`, `MaxFeePerGas`), and the gas actually consumed by `executeUniversalTx`, while the gas cost is billed directly out of the **recipient's own native `upc` balance** via `DeductGasFeesFromReceipt` [1](#0-0) , with no consent, allowlist, or interface check gating which contracts may be targeted.

### Finding Description
For CEA (contract-recipient) inbounds, the keeper only checks whether the attacker-chosen `Recipient` address has code deployed (`GetCodeHash`), and if so, treats it as a valid `executeUniversalTx` target: [2](#0-1) 

There is no `ERC165`/`supportsInterface` check, no opt-in registry, and no allowlist gating which contracts can be dispatched into this flow — confirmed by the absence of any such gating logic in the module (`x/uexecutor`), unlike `x/uregistry`'s allowlist concept used elsewhere. Any deployed contract on Push Chain with a permissive fallback or a function selector that happens to collide with `executeUniversalTx(...)` can be targeted.

Once the recipient is classified as a smart contract, `CallExecuteUniversalTx` dispatches the attacker's `payload` bytes directly into the recipient contract: [3](#0-2) 

Immediately after, the gas actually consumed by that call is billed to the recipient, not the sender/attacker: [4](#0-3) 

`DeductGasFeesFromReceipt` computes `gasCost = effectiveGasPrice * receipt.GasUsed` and burns that amount straight from the recipient's `upc` balance: [5](#0-4) 

The only "cap" is `abiPayload.GasLimit`, which comes from the same attacker-controlled `UniversalPayload` embedded in the `Inbound` — the attacker sets both the ceiling and the actual consumption, and the recipient (a legitimate Push Chain contract owner who never signed or approved anything) has no way to set their own maximum acceptable spend, exactly mirroring the C4 report's core defect: "manual gas accounting... allow users to input a maximum fee/gas cost they are willing to spend," which does not exist here for the victim side.

### Impact Explanation
An unprivileged external-chain attacker can:
1. Send a trivial-value (or zero-value) deposit on any configured source chain (e.g. Sepolia) naming any Push Chain contract address as `Recipient` with `IsCEA=true`.
2. Craft `UniversalPayload.Data` to trigger expensive execution inside that contract (e.g., a fallback function, a loop, or an external call chain) that is honestly observed and relayed by Universal Validators.
3. Cause `CallExecuteUniversalTx` to succeed and consume a large amount of gas.
4. Force `DeductGasFeesFromReceipt` to burn `gasUsed * baseFee` worth of `upc` directly from the victim contract's native balance — funds the victim never earmarked for this purpose and had no way to bound.

This is an unauthorized loss of protocol/user-controlled funds (native `upc`) triggered purely by ordinary, unprivileged inbound submission and honest-validator relaying, matching the in-scope impact "corruption of ... gas fee accounting ... reachable from ordinary user deposits."

### Likelihood Explanation
Any contract deployed on Push Chain that has a non-reverting fallback, a generic `receive`, a proxy delegatecall fallback, or any 4-byte selector collision with the `executeUniversalTx` ABI signature is exploitable — this is common for proxies, multisig wallets, and DeFi routers. The attacker needs no special privileges beyond being able to originate an event on a configured source chain (a normal user action), and the flow is triggered automatically once 2/3 quorum of honest validators observes and votes the inbound, which is the expected/default behavior, not a validator compromise.

### Recommendation
- Require an explicit opt-in / capability check (e.g. `ERC165.supportsInterface` for a dedicated `IExecuteUniversalTx` interface) before treating a recipient contract as CEA-callable.
- Do not derive the billed gas cost from attacker-supplied `UniversalPayload` fields when the recipient did not originate the transaction; instead let the recipient contract declare (on-chain, ahead of time) a maximum gas/fee it is willing to pay per inbound CEA call, and hard-cap billing at that value regardless of the inbound sender's claimed `GasLimit`/`MaxFeePerGas`.
- Consider charging the gas cost of unsolicited/unregistered CEA calls to a protocol-level budget or requiring a bond from the calling module/relay path rather than debiting an unconsenting recipient's balance.

### Proof of Concept
1. Deploy a contract `Victim` on Push Chain with a fallback function that performs an expensive loop (or delegatecalls into attacker-controlled logic), consuming near its `GasLimit` when called with arbitrary calldata, and fund it with `upc`.
2. From a configured external chain, emit a deposit event naming `Victim` as `Recipient`, `IsCEA=true`, `TxType=GAS_AND_PAYLOAD` (or `FUNDS_AND_PAYLOAD`), with `UniversalPayload.Data` crafted to trigger the expensive fallback path, and `GasLimit`/`MaxFeePerGas` set high.
3. Have 3 of 4 validators vote the inbound via `MsgVoteInbound` (simulating honest quorum, as in `test/integration/uexecutor/inbound_cea_smart_contract_test.go`).
4. Observe `ExecuteInboundGasAndPayload`/`ExecuteInboundFundsAndPayload` invoke `CallExecuteUniversalTx` against `Victim`, succeed, and then `DeductGasFeesFromReceipt` burn `upc` from `Victim`'s balance — confirmed by the existing test pattern showing `balanceAfter < balanceBefore` after `executeUniversalTx` [6](#0-5)  — with the attacker having fully chosen the gas-consuming payload and the fee parameters, and `Victim` never having consented to be a CEA recipient.

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}

// CallExecuteUniversalTx calls executeUniversalTx on a smart-contract recipient.
// This is used for isCEA inbounds whose recipient is a deployed contract (not a UEA).
func (k Keeper) CallExecuteUniversalTx(
	ctx sdk.Context,
	recipientAddr common.Address,
	sourceChain string,
	ceaAddress []byte,
	payload []byte,
	amount *big.Int,
	prc20AssetAddr common.Address,
	txId [32]byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	recipientABI, err := types.ParseRecipientContractABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse recipient contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		recipientABI,
		ueModuleAccAddress,
		recipientAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"executeUniversalTx",
		sourceChain,
		ceaAddress,
		payload,
		amount,
		prc20AssetAddr,
		txId,
	)
}

	t.Run("gas fees deducted from smart contract recipient after executeUniversalTx", func(t *testing.T) {
		chainApp, ctx, vals, inbound, coreVals, contractAddr := setupInboundCEASmartContractTest(t, 4)

		// Fund the smart contract with upc so fee deduction can succeed
		contractAccAddr := sdk.AccAddress(contractAddr.Bytes())

		require.NoError(t, chainApp.BankKeeper.MintCoins(ctx, "mint", fundCoins))

		// Reach quorum
		for i := 0; i < 3; i++ {
			valAddr, err := sdk.ValAddressFromBech32(coreVals[i].OperatorAddress)
			require.NoError(t, err)

			err = utils.ExecVoteInbound(t, ctx, chainApp, vals[i], coreValAcc, inbound)

		// Verify executeUniversalTx PCTx has gas_used > 0
