Confirmed: no TWAP/oracle-based price protection exists anywhere in `x/uexecutor` for these swaps — the only price reference used is the same-block `QuoterV2.quoteExactInputSingle` spot quote, with `SqrtPriceLimitX96` hardcoded to `0` (no limit) even at the quoting step [1](#0-0) , and `x/uexecutor` has no `BeginBlocker`/`EndBlocker` — all execution is synchronous inside message handlers, meaning nothing delays or averages the price used [2](#0-1) .

### Title
Auto-swap deposit and gas-refund flows derive `minPCOut` from a same-block manipulable spot quote, enabling sandwich attacks on inbound GAS/GAS_AND_PAYLOAD deposits and outbound gas refunds - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The external report describes `zapWETH` swapping without a price limit, resulting in depositors receiving less value than expected because slippage wasn't checked against a trustworthy reference price. Push Chain's `x/uexecutor` module has an analogous pattern: every PRC20→PC auto-swap (inbound `GAS`, `GAS_AND_PAYLOAD`, and outbound `applyGasRefund`) computes its slippage floor `minPCOut` from a Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote fetched immediately before the swap, with `sqrtPriceLimitX96 = 0` (no price limit) on the quote call itself. Since the "reference price" and the "executed price" are both read from the same manipulable AMM pool in the same block, an attacker can move the pool price with an ordinary EVM trade earlier in the block, causing the module's own quote (and thus the 95%-of-quote `minPCOut` floor) to reflect the manipulated price rather than the honest market price.

### Finding Description
`GetSwapQuote` fetches a spot quote from the pool with no price limit and no time-weighting [3](#0-2) . This quote is used, unmodified, to compute `minPCOut = quote * 95 / 100` right before calling `CallPRC20DepositAutoSwap`, in three separate call sites:
- `ExecuteInboundGas` (TxType `GAS`) [4](#0-3) 
- `gasAndPayloadDepositAutoSwap` (TxType `GAS_AND_PAYLOAD`) [5](#0-4) 
- `applyGasRefund` for outbound gas-fee refunds [6](#0-5) 

Both the inbound execution and the outbound refund are triggered deterministically and synchronously from ordinary Universal Validator vote messages (`MsgVoteInbound` / `MsgVoteOutbound`), which are gasless and processed inline in the message handler — `x/uexecutor` has no `BeginBlocker`/`EndBlocker` to add any protective delay [2](#0-1) . Because Cosmos SDK transactions within a block execute sequentially and the pool being quoted is a normal Uniswap V3 pool on the same EVM, an unprivileged attacker can:
1. Submit an ordinary EVM swap transaction that pushes the PRC20/WPC pool price to an extreme in the attacker's favor, ordered before the `MsgVoteInbound`/`MsgVoteOutbound` transaction that finalizes the swap (block proposers / normal mempool ordering rules apply — no validator collusion needed, since users can pay higher priority fees or the attacker's own tx naturally lands earlier).
2. The module then calls `GetSwapQuote` against the now-manipulated pool and computes `minPCOut` as 95% of that bad quote — a floor that is itself corrupted, so it provides no real protection.
3. `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` (`withSwap=true`) execute the swap at the manipulated price, minting the victim's UEA (or refund recipient) a materially smaller amount of PC than the swap was really worth.
4. The attacker reverses their initial trade in a later transaction in the same block, capturing the spread as risk-free profit extracted directly from the value that should have gone to the depositor / refund recipient.

This mirrors the report's root cause precisely: the swap has "no price limit" in the sense that matters — the limit used (`minPCOut`) is derived from the manipulable pool itself rather than an external/TWAP reference, so it fails to bound the *real* economic slippage. `deadline = big.NewInt(0)` is also always passed, meaning "contract uses its default" deadline rather than a tight one tied to the quote's freshness [7](#0-6) .

### Impact Explanation
Medium-to-High: any user who triggers a `GAS` or `GAS_AND_PAYLOAD` inbound deposit, or whose outbound generates an unused-gas refund, can have the auto-swap leg sandwiched by any unprivileged attacker who can trade on the underlying pool, directly reducing the PC amount credited to their UEA/refund recipient — corruption of native asset/gas accounting reachable purely from ordinary user deposit and refund paths, matching the "unprivileged attacker drains value from user/protocol funds" impact class in scope.

### Likelihood Explanation
Medium: requires the attacker to have capital to move the specific PRC20/WPC pool and to land a trade adjacent to the module's swap in the same block, which is achievable via normal priority-fee bidding on a low-liquidity pool (gas/bridged tokens are plausible candidates for thin liquidity). No validator or TSS compromise is required — only ordinary EVM trading and normal vote-threshold reaching by honest Universal Validators.

### Recommendation
Do not derive the slippage floor from a same-block spot quote off the same pool that will execute the swap. Use a TWAP-based quote (e.g., `OracleLibrary.getQuoteAtTick` averaged over a meaningful window) or an external price reference for computing `minPCOut`, and/or apply a maximum-deviation check between the spot quote and a longer-window TWAP before allowing the auto-swap to proceed, reverting to a no-swap deposit path if the deviation exceeds a safe threshold. Additionally, set an explicit short `deadline` tied to the block/quote freshness rather than always passing `0`.

### Proof of Concept
1. Attacker identifies a `TokenConfig` PRC20 with native representation traded against `WPC` on a Uniswap V3 pool with modest liquidity, configured in `x/uregistry` as a gas token used by `GAS`/`GAS_AND_PAYLOAD` inbound routes.
2. Attacker submits a large EVM swap `TokenIn=WPC → TokenOut=PRC20` (or vice versa, depending on desired direction) immediately before the block that will contain the `MsgVoteInbound` transaction that reaches the 2/3 threshold and triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` for a victim's pending gas-top-up inbound.
3. When the threshold is reached, `GetSwapQuote` (with `SqrtPriceLimitX96=0`) reads the manipulated pool state and returns a bad quote; `minPCOut` is computed as 95% of that bad quote [8](#0-7) .
4. `CallPRC20DepositAutoSwap` executes the swap at the manipulated price, crediting the victim's UEA with less PC than fair value.
5. Attacker submits a reverse trade later in the same block to restore the pool price, realizing the arbitrage profit taken from the victim's deposit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
