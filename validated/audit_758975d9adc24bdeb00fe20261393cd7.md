### Title
Starknet OS `execute_replace_class` omits declared-class validation, causing consensus divergence between Blockifier and OS re-execution - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Cairo `replace_class` syscall handler in the Starknet OS program (used for proof generation / re-execution) writes the requested `class_hash` into `contract_state_changes` without verifying that the class hash was actually declared. The Rust Blockifier implementation of the same syscall (`crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`, function `replace_class`) does enforce this check by calling `get_compiled_class(request.class_hash)` before mutating state, and rejects the transaction with an "is not declared" error otherwise. This asymmetry means a transaction that is rejected/reverted by the sequencer's Blockifier can be accepted by the OS re-execution path, or vice versa.

### Finding Description
`execute_replace_class` in `syscall_impls.cairo` explicitly contains the comment:
```
// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
local state_entry: StateEntry*;
%{ GetContractAddressStateEntry %}
...
``` [1](#0-0) 

It simply constructs a new `StateEntry` with the requested `class_hash` and updates `contract_state_changes`/the revert log — there is no assertion that `class_hash` corresponds to a class that was previously declared in the chain.

In contrast, the equivalent Blockifier (native Rust) implementation used for the sequencer's actual execution path performs this check first:
```rust
fn replace_class(...) -> DeprecatedSyscallResult<ReplaceClassResponse> {
    // Ensure the class is declared (by reading it).
    syscall_handler.state.get_compiled_class(request.class_hash)?;
    syscall_handler.state.set_class_hash_at(syscall_handler.storage_address, request.class_hash)?;
    Ok(ReplaceClassResponse {})
}
``` [2](#0-1) 

and a dedicated Blockifier test confirms the Rust path rejects undeclared class hashes: `test_replace_class` asserts the error message contains `"is not declared"` for calldata `felt!(1234_u16)` (an undeclared hash) before verifying the positive flow with a declared class. [3](#0-2) 

The same missing-check pattern also appears in the deprecated-syscall path of the OS program (`deprecated_execute_syscalls.cairo`), which similarly performs `execute_replace_class` purely via `dict_update` without a declared-class assertion. [4](#0-3) 

Because the Starknet OS Cairo program is the code that is re-executed and proven (the canonical, provable execution used to validate/commit the block, per the "Starknet OS re-execution" reachable path called out in-scope), a discrepancy here means the OS can happily accept and commit a `replace_class` call to an arbitrary/undeclared class hash, while the Blockifier (used by the sequencer during block building/validation) would reject the same transaction. This produces:
- A wrong committed class hash / state entry for the contract (a state-root divergence), since the OS would commit a `class_hash` for a contract that no compiled class exists for, and
- Honest-node divergence: a node relying on OS re-execution as ground truth for block validity could accept a block/transaction that the Blockifier-based sequencer would have reverted, or the prover could produce a "proof" for a state transition that isn't reproducible/valid according to the sequencer's execution semantics.

This is directly reachable by any unprivileged contract invoking the `replace_class` syscall with an arbitrary, never-declared `class_hash` felt — no special privileges are required, matching the "syscalls" and "Starknet OS re-execution" reachable paths explicitly permitted by scope.

### Impact Explanation
If the OS accepts a `replace_class` to an undeclared class hash while the Blockifier rejects it, the state committed by the OS (used for proof generation and the canonical committed state/root) diverges from what the sequencer's Blockifier execution would produce. This is a wrong-committed-root / honest-node-divergence class issue: the contract's class hash in the committed Patricia state would reference a class that doesn't exist as a compiled class, potentially breaking any subsequent calls to that contract (since its code cannot be resolved) and causing inconsistency between the block that consensus/Blockifier validated and the block the prover/OS actually commits and proves. Under the stated Validate criteria ("wrong committed root or block hash, honest-node divergence"), this is Medium-High severity.

### Likelihood Explanation
The bug is trivially reachable: any account or contract with the ability to invoke the `replace_class` syscall (a standard, unprivileged Starknet syscall available to any contract, both via the deprecated Cairo0 path and the modern syscall path) can supply an arbitrary, undeclared felt as `class_hash`. No special setup, permissions, or race condition is needed — a single transaction suffices to exercise this divergent code path in the OS.

### Recommendation
Add an explicit declared-class check in the Cairo OS implementation of `execute_replace_class` (both in `syscall_impls.cairo` and the deprecated path in `deprecated_execute_syscalls.cairo`), mirroring the Blockifier's `get_compiled_class`/`is_declared` check, before writing the new `StateEntry` to `contract_state_changes`. This keeps semantics between the Blockifier and the OS re-execution/proving path consistent and prevents committing state with a class hash that has no corresponding declared class.

### Proof of Concept
1. Deploy any contract exposing the `replace_class` syscall (e.g., the standard `test_replace_class` external function pattern used in feature contracts).
2. Send an `invoke` transaction calling `replace_class` with an arbitrary felt (e.g., `0x1234`) that was never declared on-chain.
3. Under Blockifier (sequencer) execution, this transaction reverts/fails with `"... is not declared"` per `deprecated_syscalls_test.rs::test_replace_class` behavior.
4. Under the Starknet OS Cairo program's `execute_replace_class` (`syscall_impls.cairo:881-920` / `deprecated_execute_syscalls.cairo:307-329`), the same call succeeds unconditionally and commits the undeclared class hash into `contract_state_changes`, since no declared-class assertion exists in that path — demonstrating the divergence between the two execution engines for the identical transaction.

**Note on confidence**: I was not able to independently trace whether an upstream check (e.g., in the hint `GetContractAddressStateEntry` or a separate Sierra/CASM validation pass elsewhere in the OS pipeline) implicitly enforces class declaration before this function is reached, due to tool/iteration limits. The explicit `TODO` comment in the source strongly suggests this validation is genuinely missing, but full confirmation would require tracing the hint implementation and the complete OS transaction flow, which I could not complete within the available iterations.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}

#[test]
fn test_replace_class() {
    // Negative flow.
    let chain_info = &ChainInfo::create_for_testing();
    let test_contract = FeatureContract::TestContract(CairoVersion::Cairo0);
    let empty_contract = FeatureContract::Empty(CairoVersion::Cairo0);
    let mut state = test_state(chain_info, Fee(0), &[(test_contract, 1), (empty_contract, 1)]);
    let test_address = test_contract.get_instance_address(0);
    // Replace with undeclared class hash.
    let calldata = calldata![felt!(1234_u16)];
    let entry_point_call = CallEntryPoint {
        calldata,
        entry_point_selector: selector_from_name("test_replace_class"),
        ..trivial_external_entry_point_new(test_contract)
    };
    let error = entry_point_call.execute_directly(&mut state).unwrap_err().to_string();
    assert!(error.contains("is not declared"));

    // Positive flow.
    let old_class_hash = test_contract.get_class_hash();
    let new_class_hash = empty_contract.get_class_hash();
    assert_eq!(state.get_class_hash_at(test_address).unwrap(), old_class_hash);
    let entry_point_call = CallEntryPoint {
        calldata: calldata![new_class_hash.0],
        entry_point_selector: selector_from_name("test_replace_class"),
        ..trivial_external_entry_point_new(test_contract)
    };
    entry_point_call.execute_directly(&mut state).unwrap();
    assert_eq!(state.get_class_hash_at(test_address).unwrap(), new_class_hash);
}
