### Title
Unbounded recursion in compiled-class bytecode-segment hashing during declare-transaction compilation can crash the sequencer's class-compilation/hashing path - (File: crates/starknet_api/src/contract_class/compiled_class_hash.rs)

### Summary
`bytecode_hash_node` in `starknet_api` and its sibling `create_bytecode_segment_structure_inner` in the Starknet OS hint implementation recursively walk a `NestedIntList`/`HashableNestedIntList` describing the CASM bytecode's segment tree, with no depth limit, mirroring the PoDoFo `ReadArray`/`GetNextVariant`/`ReadDataType` mutual-recursion stack-overflow pattern. Crucially, the recursive hash computation is executed **outside** the resource-limited compiler subprocess, in the same process that handles every declare transaction.

### Finding Description
When a class is declared, `SierraCompiler::compile` first compiles Sierra to CASM inside a sandboxed subprocess with explicit CPU/memory limits (`ResourceLimits`), but then immediately computes the compiled-class hash **in the calling process**, unprotected by any such limits: [1](#0-0) 

That hash computation calls `HashableCompiledClass::hash`, which recurses over the bytecode segment tree with no depth bound: [2](#0-1) 

The same unbounded-recursion pattern exists in the Starknet OS hint code used when building/re-executing blocks, which walks the identical `NestedIntList` structure to construct the bytecode segment tree for hashing during OS execution: [3](#0-2) 

Unlike other known-dangerous recursive paths in the sequencer (e.g., contract-to-contract call chains), which are explicitly guarded by a `RecursionDepthGuard`: [4](#0-3) 

...neither `bytecode_hash_node` nor `create_bytecode_segment_structure_inner` has any equivalent depth check. The `SierraCompilationConfig` only limits total bytecode *size* (`max_bytecode_size`, default 80×1024 felts) and subprocess CPU/memory, not the *nesting depth* of the segment tree that the compiler emits for the compiled class: [5](#0-4) 

Because the segment-tree structure is derived from the (attacker-authored) Sierra program's function/branch layout, a program engineered to produce deeply and degenerately nested segments (a long chain of single-child `Node` wrappers rather than a balanced tree) can make `bytecode_hash_node`/`create_bytecode_segment_structure_inner` recurse proportionally to the number of nesting levels, each frame consuming native stack — analogous to PoDoFo's recursive tokenizer overflowing on deeply nested array structures.

### Impact Explanation
If recursion depth is large enough to exhaust the native stack, the class-manager/compiler-hashing process (and, separately, the OS hint execution used for block building/re-execution) crashes with a stack overflow (SIGSEGV/abort), rather than returning a graceful error. Because compilation and hashing are deterministic, every honest sequencer node processing the same declare transaction (or the same block containing it) hits the identical crash, causing a synchronized liveness failure — the network becomes unable to confirm this and subsequent transactions until the class or the code is fixed, satisfying the "network unable to confirm new transactions" impact criterion. This is a Medium severity issue, matching the source CVE's classification and CVSS profile (low privilege, local trigger, availability impact only).

### Likelihood Explanation
The trigger only requires a single declare transaction (or L1-declared class) containing a Sierra program that compiles successfully but yields a highly imbalanced/deeply nested bytecode segment tree — no elevated privileges, no operator/proposer collusion, and no network-layer attack are needed. The compilation subprocess sandbox (CPU/memory/bytecode-size limits) does not protect the subsequent in-process hash computation or the OS hint recursion, so the resource limits already in place do not mitigate this specific path. Actual exploitability depends on how deep a nesting the upstream `cairo-lang-sierra-to-casm` compiler can be induced to emit within the `max_bytecode_size` bound — this would need to be empirically verified against the compiler's segment-generation logic (external dependency, `cairo-lang-sierra-to-casm`), which is outside this repository's index.

### Recommendation
- Add an explicit maximum recursion/nesting-depth check (mirroring `RecursionDepthGuard` in `crates/blockifier/src/execution/entry_point.rs`) in both `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs`) and `create_bytecode_segment_structure_inner` (`crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`), rejecting classes whose segment tree exceeds a safe depth.
- Alternatively/additionally, convert these functions to iterative (explicit stack-based) traversal to eliminate native stack growth entirely.
- Move the compiled-class-hash computation into the same resource-limited subprocess used for Sierra→CASM compilation, so a crash there does not take down the calling service.

### Proof of Concept
A concrete PoC requires crafting a Sierra program that, after compilation by `cairo-lang-sierra-to-casm`, produces a `CasmContractClass.bytecode_segment_lengths` value shaped as a long chain of nested `NestedIntList::Node(vec![NestedIntList::Node(...)])` wrappers (as illustrated by the test fixtures in `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils_test.rs`, e.g. lines 18-32 show a 2-level nesting), scaled to thousands of levels within the `max_bytecode_size` limit, then submitted as a `DECLARE` transaction; when the class manager calls `.hash(&HashVersion::V2)` (or when the OS hint processor builds the segment structure during block execution), the resulting deep recursion should overflow the native stack. /// Computes the hash of a bytecode segment. See the documentation of `bytecode_hash_node` in
```rust
/// the Starknet OS.
/// Returns the length of the processed segment and its hash.
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}
```

```rust
pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}
```

```rust
// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
```
