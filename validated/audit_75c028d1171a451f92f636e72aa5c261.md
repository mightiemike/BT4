## Analysis

The Beanstalk bug's essential pattern is: **a peg-restoring mint/swap decision is computed from a manipulable, single-block spot AMM price instead of a time-weighted value, so a frontrunner can sandwich the triggering transaction and force the protocol to execute value-moving trades at an attacker-controlled price.**

Push Chain has a structural analog in the gas-fee swap logic in `x/uexecutor`. `GetSwapQuote` calls Uniswap V3's `QuoterV2.quoteExactInputSingle` — a pure spot-price read of the live pool — and the caller immediately turns that quote into a `minPCOut` slippage bound (`quote * 95/100`) that gates a real swap executed moments later in the same call chain: [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

This same pattern is used for both the gasless-inbound deposit swap (`ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap`) and the excess-gas refund swap (`applyGasRefund`). In all three call sites, the quote and the swap execute within the same deterministic state transition triggered by a `MsgVoteInbound`/`MsgVoteOutbound` transaction — so there is no window between quote and swap for slippage protection to matter. The only defense the 5%-slippage bound provides is against price movement *between* those two internal calls (which is zero, since they're sequential within one atomic keeper execution), not against price manipulation that already occurred *before* the validator transaction landed.

### Title
Spot-price Uniswap V3 quote used for gas-swap `minPCOut` allows frontrun sandwich extraction of user/protocol funds - ([File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/outbound.go, x/uexecutor/keeper/execute_inbound_gas.go])

### Summary
The gasless-inbound auto-swap path and the excess-gas-refund path both price PRC20→WPC swaps using `QuoterV2.quoteExactInputSingle`, a live spot-price read of the on-chain Uniswap V3 pool, then bound slippage to only 5% below that same spot quote. Because quote-then-swap happens atomically inside a single validator-quorum-triggered Cosmos transaction, the 5% band only protects against intra-call drift — not against the pool price having already been skewed by an attacker's frontrun swap placed immediately before the finalizing `MsgVoteInbound`/`MsgVoteOutbound` transaction lands.

### Finding Description
`GetSwapQuote` [1](#0-0)  is called with `commit=false` against the pool's current reserves at the moment the validator-quorum transaction executes. Three flows consume it:

1. `ExecuteInboundGas` computes `quote` then immediately calls `CallPRC20DepositAutoSwap` with `minPCOut = quote*95/100` [5](#0-4) .
2. `gasAndPayloadDepositAutoSwap` does the same for `GAS_AND_PAYLOAD` inbounds [6](#0-5) .
3. `applyGasRefund` uses `getSwapQuoteForRefund` (a thin wrapper around the same `GetSwapQuote`) to price the excess-gas refund swap sent to the user/sender [3](#0-2) [4](#0-3) .

An unprivileged attacker who observes a pending inbound-GAS deposit or an outbound gas-refund transaction (both are deterministic, quorum-triggered, and their pending state — pending inbound observations, `OutboundTx.GasFee`/`GasToken` — is publicly queryable/observable before the finalizing validator vote lands) can:
1. Submit a large swap against the same Uniswap V3 pool (PRC20 gas-token ↔ WPC) immediately before the finalizing validator vote transaction is included, skewing the spot price.
2. Let the finalizing transaction execute — `GetSwapQuote` reads the now-skewed price, and the 5% band is computed from that already-bad price, so the protocol-controlled swap executes at the manipulated rate.
3. Reverse the initial swap afterward, capturing the value that the recipient/user should have received.

This directly reduces the PC amount that PRC20-funded users receive on gasless deposits, and reduces the excess-gas refund amount owed to senders on outbound completion — a value-extraction (unauthorized drain) from user/protocol-controlled swap proceeds, exactly mirroring the Beanstalk `sop()` spot-`deltaB` sandwich pattern.

### Impact Explanation
Any inbound `GAS`/`GAS_AND_PAYLOAD` deposit-with-autoswap and any outbound gas-fee refund is exposed. Because these flows are core to Push Chain's gasless UX (funding new UEAs and refunding overpaid relayer gas), a well-capitalized attacker can systematically skim value from every such swap without needing any privileged role — this is user/protocol fund drain reachable via ordinary observation of pending, unprivileged, user-triggered flows.

### Likelihood Explanation
Exploitability depends on the liquidity depth of the specific PRC20/WPC Uniswap V3 pool and the swap amounts involved (typically small per-transaction gas amounts), so the attacker's profit per attack may be limited, similar to the "0.08% of funds" cost noted in the original report. However, the bug is deterministically and repeatably triggerable on every relevant inbound/outbound because there is no TWAP or price-manipulation resistance at all — only a self-referential 5% band computed from the exact same possibly-manipulated read.

### Recommendation
Do not derive `minPCOut` purely from a spot `quoteExactInputSingle` computed at execution time. Instead, bound the acceptable execution price against an independent, harder-to-manipulate reference (e.g., a TWAP observation from the pool, or the `ChainMeta`-style median-of-validator-observed price used elsewhere in this codebase for gas price [7](#0-6) ), and reject/park the swap when spot deviates materially from that reference rather than accepting up to 5% of a value that may already be fully attacker-controlled.

### Proof of Concept
1. Attacker monitors the mempool/pending state for a `MsgVoteInbound` (GAS) or `MsgVoteOutbound` completion that is one vote away from quorum on a chain with a shallow PRC20/WPC pool.
2. Attacker submits a swap on that Uniswap V3 pool moving price against the direction of the protocol's forthcoming swap, timed to land just before the quorum-completing vote transaction.
3. The quorum-completing vote executes `GetSwapQuote` → reads the skewed price → computes `minPCOut = quote*0.95` → executes `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` at that bad rate.
4. Attacker reverses their initial swap, extracting the spread; the deposited UEA or the refund recipient receives less PC than a fair-price execution would have produced.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

	if err != nil {
		return nil, err
	}
	wpcAddr, err := k.GetUniversalCoreWPCAddress(ctx)
	if err != nil {

	}
