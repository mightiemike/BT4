### Title
Inbound gas-swap uses a fixed 5% slippage band computed from a same-transaction Uniswap V3 spot quote, allowing sandwich extraction from protocol-owned WPC/PRC20 pools — ([File: x/uexecutor/keeper/execute_inbound_gas.go])

### Summary
`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund` compute `minPCOut` as a flat `quote * 95 / 100` of a Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote fetched immediately before the protocol-driven swap executes. Because inbound execution runs synchronously inside the ordinary `MsgVoteInbound` transaction (not in a privileged, isolated context), an unprivileged actor can manipulate the underlying WPC/PRC20 pool price with an ordinary transaction placed in the same block immediately before the finalizing vote, causing the module's forced swap to execute against a manipulated price while still satisfying the "5% slippage" check — the check is computed from the very quote the attacker just moved.

### Finding Description
The swap-quote and swap-execution flow is: [1](#0-0) 

`quote` is obtained via a static `CallEVM` (`commit=false`) to `QuoterV2.quoteExactInputSingle`, immediately followed by the real swap `CallPRC20DepositAutoSwap` (`commit=true`) using `minPCOut = quote*95/100`: [2](#0-1) [3](#0-2) 

The same pattern (fixed 95% of a fresh quote) is repeated for `GAS_AND_PAYLOAD` inbounds and for the excess-gas refund swap on outbound observation: [4](#0-3) [5](#0-4) 

Critically, this swap does not run in an isolated, attacker-unreachable context — it runs synchronously as part of processing the finalizing `MsgVoteInbound` transaction, an ordinary Cosmos transaction included in a normal block: [6](#0-5) 

Because the quote and the swap execution happen back-to-back inside the same keeper call but are only protected by a static 5% band against whatever the pool price happens to be *at that moment*, an unprivileged actor can:
1. Observe (or predict, since inbound voting/finalization timing is public/deterministic once quorum is one vote away) that the finalizing `MsgVoteInbound` is about to land in an upcoming block.
2. Submit an ordinary EVM transaction in the same block, ordered before the finalizing vote tx, that swaps against the same Uniswap V3 WPC/PRC20 pool to push the spot price in the attacker's favor (e.g., inflate the PRC20→WPC exchange rate).
3. The module's `GetSwapQuote` call reads this manipulated price and computes `minPCOut` from it; the subsequent swap executes at (or within 5% of) the manipulated price, transferring excess value out of the pool.
4. The attacker reverses the manipulation in a follow-up transaction in the same block, extracting the difference as profit from the pool's liquidity — liquidity that, per `e2e-tests/setup.sh` (`step_create_all_wpc_pools`), is protocol-provisioned WPC/PRC20 liquidity.

This mirrors the reported bug class exactly: a slippage guard that is nominally reasonable (a fixed percentage bound) but is computed from a value the attacker can move within the same atomic execution window, so it fails to bound the *real* economic slippage/loss experienced by the protocol.

### Impact Explanation
An unprivileged attacker can drain value from protocol-owned WPC/PRC20 liquidity pools used for gas-abstraction auto-swaps on every `GAS` / `GAS_AND_PAYLOAD` inbound and on the excess-gas refund path, with no validator or admin collusion required — only ordinary transaction submission and block-position awareness. This is a direct loss of protocol-controlled funds, matching the in-scope impact "stealing, draining ... of user or protocol-controlled funds."

### Likelihood Explanation
Medium: exploitation requires controlling relative transaction ordering within a block (submitting a manipulation tx immediately before/after the finalizing vote tx), which is achievable via gas-price bidding or MEV-style bundling without any privileged role, and the target pools (deployed with bounded, often thin, initial liquidity for gas-abstraction purposes) are more susceptible to short-term price manipulation than large exchange venues.

### Recommendation
Do not derive slippage protection solely from a spot quote taken in the same execution window as the swap. Instead:
- Use a time-weighted average price (TWAP) from the pool (Uniswap V3 supports on-chain TWAP oracles) as the reference price for computing `minPCOut`, rather than the instantaneous `quoteExactInputSingle` result.
- Bound the maximum allowed single-swap price impact independent of the attacker-influenced spot price (e.g., compare against a governance-configured reference price/oracle, not just "95% of whatever the pool says right now").
- Consider restricting or rate-limiting the size of protocol-driven auto-swaps relative to pool depth, and/or route through pools with sufficiently deep, non-manipulable liquidity.

### Proof of Concept
1. Attacker deploys/uses a low-liquidity WPC/PRC20 pool (or one of the genesis-created pools from `step_create_all_wpc_pools`).
2. Attacker prepares an inbound (`GAS` type) that will be voted through by Universal Validators; attacker monitors mempool/vote submission timing to predict which block will contain the quorum-finalizing `MsgVoteInbound`.
3. In that same block, attacker submits (front of) a large swap trade against the WPC/PRC20 pool to skew the spot price favorably for the token being auto-swapped by the protocol.
4. The finalizing `MsgVoteInbound` tx executes `ExecuteInboundGas` → `GetSwapQuote` (reads the now-skewed price) → `CallPRC20DepositAutoSwap` with `minPCOut` computed off that skewed quote — the swap succeeds even though the "true" pre-manipulation slippage tolerance would have been violated.
5. Attacker submits a reverse trade afterward in the same block to restore the price, pocketing the difference extracted from the pool.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
