### Title
`AttachRescueOutboundFromReceipt` creates outbound work for a chain without checking `IsChainOutboundEnabled`, unlike every other outbound-creation path - (File: x/uexecutor/keeper/create_outbound.go)

### Summary
`x/uexecutor` treats "outbound disabled for chain X" as a hard invariant everywhere a new outbound is created — `BuildOutboundsFromReceipt` explicitly calls `k.uregistryKeeper.IsChainOutboundEnabled` and rejects if disabled [1](#0-0) . This invariant is what `x/utss`'s fund-migration flow relies on to safely be able to move TSS funds from an old key to a new key: `InitiateFundMigration` requires outbound to already be disabled and requires zero pending outbounds for the chain before allowing migration to proceed [2](#0-1) . However, `AttachRescueOutboundFromReceipt` — the RESCUE_FUNDS outbound-creation path triggered by a user-initiated `RescueFundsOnSourceChain` gateway event — never calls `IsChainOutboundEnabled` before attaching a new `PendingOutboundEntry` and emitting an `OutboundCreatedEvent` for the destination (source) chain [3](#0-2) .

### Finding Description
`AttachRescueOutboundFromReceipt` decodes a `RescueFundsOnSourceChain` event emitted from the `UniversalGatewayPC` contract and, given eligibility conditions on the original UTX (failed CEA deposit or reverted auto-revert), unconditionally creates a `RESCUE_FUNDS` `OutboundTx`, writes it into `PendingOutbounds`, and appends it to the UTX's `OutboundTx[]` list [4](#0-3) . This is the same category of state mutation as `BuildOutboundsFromReceipt`, which is gated by `IsChainOutboundEnabled` [1](#0-0) , `VoteInbound`, `ExecutePayload`, and the EVM hooks post-processing path, all of which reject with "... is disabled for chain ..." when the flag is false (confirmed by the integration tests in `chain_enabled_test.go` and `evm_hooks_and_outbound_test.go`).

This is the direct structural analog of the vMaia `maxWithdraw`/`maxRedeem` bug: a "gate" function (`IsChainOutboundEnabled`) correctly encodes the paused/disabled state, but one specific state-transition path that should have consulted that gate before allowing a withdrawal-class action does not, silently behaving as if the chain were enabled. In the vMaia bug, `maxWithdraw` returned `balanceOf[user]` instead of `0` when withdrawals were paused; here, `AttachRescueOutboundFromReceipt` creates a real `PendingOutboundEntry`/outbound work item for a chain instead of erroring out with "outbound is disabled" when outbound has been intentionally disabled for that chain.

The trigger is user-reachable: `RescueFundsOnSourceChain` is emitted when "a user initiates a rescue on the source chain" per the event doc comment [5](#0-4) , and the eligibility preconditions (failed CEA deposit, or a `REVERTED` auto-revert outbound) are states an unprivileged user's own inbound can legitimately reach without any privileged actor involvement.

### Impact Explanation
The `IsChainOutboundEnabled=false` + `HasPendingOutboundsForChain=false` pair is exactly the precondition `InitiateFundMigration` checks before allowing TSS funds to be migrated from an old key to a new key for a chain [2](#0-1) . If an unprivileged user can cause a new `PendingOutboundEntry` to be created for that chain via the rescue path *after* those checks pass (or in a window where outbound has just been disabled but a rescue is still processed), a new TSS-signed outbound could be queued/signed against a chain that operators believed had zero outstanding work and disabled outbound — undermining the safety assumption of the fund-migration coordination and potentially producing an outbound signed/routed with stale TSS key material or against a chain intentionally quiesced for migration. At minimum this is an unauthorized state transition (a `PendingOutboundEntry`/`OutboundCreatedEvent`/UTX mutation) that bypasses an explicit chain-level access-control gate that every other code path in the same module respects.

### Likelihood Explanation
Reaching the CEA-failed-deposit or reverted-auto-revert precondition requires only ordinary inbound activity by an unprivileged user (no validator/admin/relayer collusion needed), and calling the gateway's rescue function is a normal user-facing action per the event's own documentation. The only additional condition needed to realize impact is that outbound has been disabled for that chain at the time the rescue receipt is processed (an operator/governance action, not an attacker precondition) — this is a foreseeable operational scenario (e.g., during the TSS fund-migration window that `x/utss` explicitly designs around), making the missing check practically triggerable during exactly the window it matters most.

### Recommendation
Add the same `IsChainOutboundEnabled` check used in `BuildOutboundsFromReceipt` to `AttachRescueOutboundFromReceipt` before attaching the `RESCUE_FUNDS` outbound to the UTX and before writing to `PendingOutbounds`, returning an "outbound is disabled for chain %s" error (mirroring existing behavior) so rescue outbounds cannot be queued for a chain whose outbound path has been intentionally disabled — including during TSS fund-migration windows.

### Proof of Concept
Conceptual reproduction (mirrors existing test scaffolding in `test/integration/uexecutor/rescue_funds_test.go`):
1. Set up a chain config with `IsOutboundEnabled: false` (e.g., as done for governance/migration purposes, analogous to `setupOutboundChainEnabledTest(t, numVals, false)` in `chain_enabled_test.go`).
2. Drive a CEA inbound to a `PcTx[0].Status == "FAILED"` state (or produce a `REVERTED` `INBOUND_REVERT` outbound for a non-CEA inbound), exactly as `setupRescueFundsTest` does.
3. Build a `RescueFundsOnSourceChain` log (as `buildRescueFundsLog` does) for the same UTX and destination chain, and call `chainApp.UexecutorKeeper.AttachRescueOutboundFromReceipt(ctx, receipt, pcTx)`.
4. Observe (unlike the equivalent `BuildOutboundsFromReceipt` call under the same disabled config, which returns `"outbound is disabled for chain ..."` per `evm_hooks_and_outbound_test.go`) that `AttachRescueOutboundFromReceipt` returns `nil` and a new `PENDING` `RESCUE_FUNDS` outbound and `PendingOutboundEntry` are created for the disabled chain — confirming the missing gate.

// AttachRescueOutboundFromReceipt scans the receipt for RescueFundsOnSourceChain events
// emitted by UniversalGatewayPC and, for each one found, attaches a RESCUE_FUNDS outbound
// to the original UTX referenced by the event's universalTxId.
//
// Unlike normal outbounds (which create a new UTX), rescue outbounds are appended to the
// already-existing UTX whose funds are stuck on the source chain.
func (k Keeper) AttachRescueOutboundFromReceipt(
	ctx sdk.Context,
	receipt *evmtypes.MsgEthereumTxResponse,
	pcTx types.PCTx,
) error {
	universalGatewayPC := strings.ToLower(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_GATEWAY_PC"].Address)

	evmChainID, err := utils.ExtractEvmChainID(ctx.ChainID())
	if err != nil {
		return fmt.Errorf("rescue: failed to extract EVM chain ID: %w", err)
	}
	pushChainCaip := fmt.Sprintf("eip155:%s", evmChainID)

	for _, lg := range receipt.Logs {
		if lg.Removed {
			continue
		}
		if strings.ToLower(lg.Address) != universalGatewayPC {
			continue
		}
		if len(lg.Topics) == 0 {
			continue
		}
		if strings.ToLower(lg.Topics[0]) != strings.ToLower(types.RescueFundsOnSourceChainEventSig) {
			continue
		}

		event, err := types.DecodeRescueFundsOnSourceChainFromLog(lg)
		if err != nil {
			return fmt.Errorf("failed to decode RescueFundsOnSourceChain: %w", err)
		}

		// The universalTxId in the event is a 0x-prefixed bytes32 matching our UTX key.
		originalUtxId := strings.TrimPrefix(event.UniversalTxId, "0x")

		originalUtx, found, err := k.GetUniversalTx(ctx, originalUtxId)
		if err != nil {
			return fmt.Errorf("rescue: failed to fetch UTX %s: %w", originalUtxId, err)
		}
		if !found {
			return fmt.Errorf("rescue: original UTX %s not found", originalUtxId)
		}
		if originalUtx.InboundTx == nil {
			return fmt.Errorf("rescue: UTX %s has no inbound tx", originalUtxId)
		}

		// Rescue eligibility differs by inbound type:
		//
		//  CEA inbounds: the deposit (first PCTx) must have failed, meaning the funds
		//  never arrived on Push Chain and are still locked on the source chain.
		//
		//  Non-CEA inbounds: the auto-generated INBOUND_REVERT outbound must exist and
		//  have reached REVERTED status, meaning TSS could not return the funds to the
		//  source chain and they are stuck (held by the gateway contract or in escrow).
		if originalUtx.InboundTx.IsCEA {
			if len(originalUtx.PcTx) == 0 || originalUtx.PcTx[0] == nil || originalUtx.PcTx[0].Status != "FAILED" {
				return fmt.Errorf("rescue: UTX %s CEA deposit did not fail", originalUtxId)
			}
		} else {
			hasRevertedAutoRevert := false
			for _, ob := range originalUtx.OutboundTx {
				if ob != nil && ob.TxType == types.TxType_INBOUND_REVERT && ob.OutboundStatus == types.Status_REVERTED {
					hasRevertedAutoRevert = true
					break
				}
			}
			if !hasRevertedAutoRevert {
				return fmt.Errorf("rescue: UTX %s has no reverted inbound-revert outbound", originalUtxId)
			}
		}

		k.Logger().Info("rescue outbound detected",
			"original_utx_id", originalUtxId,
			"pc_tx_hash", receipt.Hash,
		)

		// Guard against duplicate rescue outbounds: reject if an active rescue
		// (PENDING or OBSERVED) already exists. A REVERTED rescue may be retried.
		for _, ob := range originalUtx.OutboundTx {
			if ob == nil || ob.TxType != types.TxType_RESCUE_FUNDS {
				continue
			}
			if ob.OutboundStatus == types.Status_PENDING || ob.OutboundStatus == types.Status_OBSERVED {
				k.Logger().Warn("rescue outbound rejected: active rescue already exists",
					"original_utx_id", originalUtxId,
					"existing_outbound_id", ob.Id,
				)
				return fmt.Errorf("rescue: UTX %s already has an active rescue outbound (%s)", originalUtxId, ob.Id)
			}
		}

		// Resolve external asset address from PRC20 → token config for the source chain.
		tokenCfg, err := k.uregistryKeeper.GetTokenConfigByPRC20(
			ctx,
			originalUtx.InboundTx.SourceChain,
			event.PRC20,
		)
		if err != nil {
			return fmt.Errorf("rescue: token config not found for PRC20 %s on %s: %w",
				event.PRC20, originalUtx.InboundTx.SourceChain, err)
		}

		// Rescued funds go to the original revert recipient (or the sender as fallback).
		recipient := originalUtx.InboundTx.Sender
		if originalUtx.InboundTx.RevertInstructions != nil &&
			originalUtx.InboundTx.RevertInstructions.FundRecipient != "" {
			recipient = originalUtx.InboundTx.RevertInstructions.FundRecipient
		}

		logIndex := fmt.Sprintf("%d", lg.Index)
		outbound := &types.OutboundTx{
			Id:                types.GetRescueFundsOutboundId(pushChainCaip, receipt.Hash, logIndex),
			DestinationChain:  originalUtx.InboundTx.SourceChain,
			Recipient:         recipient,
			Amount:            originalUtx.InboundTx.Amount,
			ExternalAssetAddr: tokenCfg.Address,
			Prc20AssetAddr:    event.PRC20,
			Sender:            event.Sender,
			GasFee:            event.GasFee.String(),
			GasPrice:          event.GasPrice.String(),
			GasLimit:          event.GasLimit.String(),
			TxType:            types.TxType_RESCUE_FUNDS,
			OutboundStatus:    types.Status_PENDING,
			PcTx: &types.OriginatingPcTx{
				TxHash:   receipt.Hash,
				LogIndex: logIndex,
			},
		}

		// Record the rescue call as a PCTx on the original UTX so the full
		// PC-side history is visible (deposit FAILED → rescue call → outbound).
		if err := k.UpdateUniversalTx(ctx, originalUtxId, func(utx *types.UniversalTx) error {
			utx.PcTx = append(utx.PcTx, &pcTx)
			return nil
		}); err != nil {
			return fmt.Errorf("rescue: failed to record PCTx on UTX %s: %w", originalUtxId, err)
		}

		if err := k.attachOutboundsToUtx(ctx, originalUtxId, []*types.OutboundTx{outbound}, ""); err != nil {
			return fmt.Errorf("rescue: failed to attach outbound to UTX %s: %w", originalUtxId, err)
		}
	}

	return nil
}

// RescueFundsOnSourceChainEvent holds decoded data from the RescueFundsOnSourceChain
// event emitted by UniversalGatewayPC when a user initiates a rescue on the source chain.
type RescueFundsOnSourceChainEvent struct {
	UniversalTxId  string   // 0x-prefixed bytes32 — the original UTX whose funds are stuck
	PRC20          string   // 0x-prefixed address — PRC20 token whose counterpart is locked
	ChainNamespace string   // source chain namespace (e.g. "eip155")
	Sender         string   // 0x-prefixed address — user who initiated the rescue
	TxType         TxType   // always TxType_RESCUE_FUNDS
	GasFee         *big.Int // gas fee charged (in gas-token units)
	GasPrice       *big.Int // gas price on the source chain
	GasLimit       *big.Int // gas limit used for the rescue execution
}
