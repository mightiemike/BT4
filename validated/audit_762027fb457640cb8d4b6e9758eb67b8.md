### Title
Starknet OS `execute_replace_class` omits the declared-class check enforced by the blockifier, enabling honest-node state divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Mattermost CVE is a missing-ownership/authorization check when attaching a resource (a file) to a draft — the code fails to verify a property of the referenced object before acting on it. The sequencer analog is the Starknet OS's Cairo implementation of the `replace_class` syscall, which fails to verify that the class hash a contract requests to replace itself with is actually a *declared* class before writing it into `contract_state_changes`. This validation is explicitly performed by the blockifier's Rust execution path but is missing (with an open `TODO`) in the OS re-execution path used to build/verify proofs.

### Finding Description
The Rust `blockifier` syscall handler for `replace_class` reads the compiled class for `class_hash` (which fails with `StateError::UndeclaredClassHash` if not declared) and additionally rejects Cairo-0 classes, before writing the new class hash to state: [1](#0-0) 

The deprecated syscall handler performs the analogous declared-class check by calling `get_compiled_class`: [2](#0-1) 

In contrast, the Starknet OS's Cairo implementation of the same syscall (`execute_replace_class` in `syscall_impls.cairo`, used for Starknet OS re-execution/proving) directly updates the contract's state entry with the requested `class_hash` and has an explicit unresolved `TODO` noting the missing check: [3](#0-2) 

The older deprecated-syscalls OS implementation (`execute_replace_class` in `deprecated_execute_syscalls.cairo`) has the identical gap — it updates `contract_state_changes` with the caller-supplied `class_hash` without any declared-class lookup: [4](#0-3) 

Because any deployed contract can invoke `replace_class_syscall(class_hash)` from an ordinary transaction (no privileged role required), and the blockifier and the Starknet OS are supposed to compute equivalent state transitions for the same block, this discrepancy is directly reachable by an unprivileged transaction sender/contract.

### Impact Explanation
The blockifier is the reference execution engine that actually builds/executes blocks in the sequencer, while the Starknet OS Cairo program is executed (and proven) to re-derive/attest the same state transition for consensus/L1 verification. If a contract calls `replace_class` with an undeclared (or otherwise invalid, e.g. Cairo-0) class hash:
- The blockifier will reject the transaction (`UndeclaredClassHash` / `ForbiddenClassReplacement`), so the state is never updated and no state diff is produced for this call.
- The Starknet OS path accepts it unconditionally, writing the arbitrary (potentially undeclared/non-existent) class hash into the contract's state entry.

This creates a wrong committed root / honest-node divergence: the OS-computed state root (used for proving block validity and eventually for L1 state commitment) can disagree with the blockifier-computed state root for the same block, or the OS could successfully "prove" a transaction that the sequencer's blockifier would have rejected. Either outcome can result in the network being unable to agree on/confirm the correct state, or in a contract account being left pointing at a garbage/undeclared class hash in the OS-derived state — a form of protocol-level state corruption. This satisfies the "wrong committed root or block hash, honest-node divergence" acceptance criteria.

### Likelihood Explanation
Likelihood is high for reachability: `replace_class_syscall` is available to any deployed contract and needs no special permission, funds, or race condition — a single ordinary invoke transaction from any account/contract that owns a class hash reference (even an unused/undeclared one) triggers the vulnerable code path. The bug is a straightforward missing-validation defect (acknowledged by the code's own `TODO`), not a subtle timing or concurrency issue, making it trivially triggerable once the OS path is exercised (e.g., during proving or re-execution flows).

### Recommendation
Add the same declared-class validation to the Starknet OS `execute_replace_class` implementations (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that the blockifier already performs in `syscall_base.rs`/`hint_processor.rs`:
1. Before updating `contract_state_changes`, verify that `class_hash` exists in `contract_class_changes`/declared-classes dictionary (mirroring `state.get_compiled_class(class_hash)` in the Rust implementation).
2. Reject (or otherwise fail the transaction) when the class is undeclared, matching the blockifier's `UndeclaredClassHash` behavior, so that both execution engines agree on transaction validity and resulting state.
3. Add regression tests in the OS/Cairo test suite mirroring `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`, specifically the `undeclared_class_hash` case, to ensure OS behavior matches blockifier behavior.

### Proof of Concept
1. Deploy any contract exposing a `replace_class_syscall` call path (e.g., the test contract's `test_replace_class`, as used in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
2. Submit an invoke transaction that calls `replace_class_syscall(class_hash)` with a `class_hash` that has never been declared in the state.
3. Under blockifier execution, the transaction reverts/fails with "is not declared" (see `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
4. Under Starknet OS re-execution of the identical transaction (via `execute_replace_class` in `syscall_impls.cairo`), no such check exists — the OS writes the undeclared `class_hash` into `contract_state_changes` for the contract's state entry, producing a different state diff/root than the blockifier for the same transaction.

Note: I was unable to fully trace how the Starknet OS integrates this state-entry write into the final committed root computation (e.g., whether an outer validation elsewhere might later reject an undeclared class before commitment); the code index does not show such a compensating check, and the inline `TODO(Yoni, 1/1/2026)` in the source is the clearest confirmation that this check is acknowledged as missing by the maintainers themselves. A Devin session with full repository access could verify whether any downstream check in the OS output/commitment stage catches this before finalizing the root.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
