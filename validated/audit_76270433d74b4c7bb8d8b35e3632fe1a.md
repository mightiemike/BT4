No vulnerability found for this question.

The reported issue concerns a Solidity smart-contract cache (`addressLookup`/`addressCache` in `MultiInvokerRollup.sol`) that lacks an authorization check, allowing any caller to overwrite a cached address mapping — an access-control flaw specific to that contract's trust model. This has no structural analog in protobuf-go's codebase.

Searching for comparable "cache that can be silently overwritten" patterns in protobuf-go's registration and caching paths shows the opposite of the reported flaw: the relevant registries explicitly guard against overwrites/conflicts rather than allowing them silently.

- `protoregistry.Types.register` checks `prev := r.typesByName[name]; if prev != nil` and returns a conflict error rather than overwriting, unless the caller explicitly opts into a non-default `conflictPolicy` (env var/build flag, not attacker controlled). [1](#0-0) 
- `protoregistry.Types.RegisterExtension` similarly checks `r.extensionsByMessage[message][field] != nil` before registering, returning an error on conflict. [2](#0-1) 
- `protoregistry.Files.RegisterFile` checks `r.descsByName[d.FullName()]` for existing entries and reports a name conflict rather than silently overwriting. [3](#0-2) 
- The internal legacy file descriptor cache (`legacyFileDescCache`) uses `sync.Map.LoadOrStore`, which is inherently overwrite-safe (first writer wins, not overwritten by later callers). [4](#0-3) 

None of these registration/caching paths are reachable from an unprivileged wire-format decode of an untrusted message under a trusted schema — they are invoked at program initialization (`init()` from generated code) or by code explicitly calling registration APIs, not by parsing attacker-controlled bytes via `proto.Unmarshal` or `protojson.Unmarshal`. There is no unprivileged request path in protobuf-go where a decoded field value causes an existing cache/registry entry to be silently overwritten the way `_cacheAddress` does in the Solidity report, so this bug class does not transfer to protobuf-go's trusted-schema decode paths.

func legacyLoadFileDesc(b []byte) protoreflect.FileDescriptor {
	// Fast-path: check whether we already have a cached file descriptor.
	if fd, ok := legacyFileDescCache.Load(&b[0]); ok {
		return fd.(protoreflect.FileDescriptor)
	}

	// Slow-path: decompress and unmarshal the file descriptor proto.
	zr, err := gzip.NewReader(bytes.NewReader(b))
	if err != nil {
		panic(err)
	}
	b2, err := io.ReadAll(zr)
	if err != nil {
		panic(err)
	}

	fd := filedesc.Builder{
		RawDescriptor: b2,
		FileRegistry:  resolverOnly{protoregistry.GlobalFiles}, // do not register back to global registry
	}.Build().File
	if fd, ok := legacyFileDescCache.LoadOrStore(&b[0], fd); ok {
		return fd.(protoreflect.FileDescriptor)
	}
	return fd
}
