## Analysis

The external report's core issue — a state‑modifying function that lacks a validation check present in the intended design (the "authorized" `KEY_K`/`DEV_A` mapping can be set to an inconsistent value because there is no gate on the write) — maps to a concrete gap in the Starknet OS replace-class syscall handling.

### Title
Starknet OS `execute_replace_class` omits the "class must be declared" check enforced by the Blockifier, causing OS/Blockifier execution divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Blockifier (the reference execution engine used by the sequencer to build blocks) enforces that `replace_class` syscall calls only succeed if the target `class_hash` is already a declared class, and additionally that it is a Cairo1 class. This is implemented in `syscall_base.rs`, where `get_compiled_class(class_hash)?` is called before `set_class_hash_at` and errors out with "is not declared" for undeclared classes. The Starknet OS Cairo re-execution path that computes the same syscall for proving/state-commitment purposes, `execute_replace_class` in `syscall_impls.cairo`, contains an explicit `TODO` acknowledging the missing check and unconditionally writes the attacker/caller-supplied `class_hash` into `contract_state_changes` without verifying it is declared. The legacy/deprecated syscall path (`deprecated_execute_syscalls.cairo`) has the identical gap with no check or TODO at all.

Because these are two independently-implemented execution engines that must produce identical outcomes for the same transaction (Blockifier builds the block; the Starknet OS re-executes it to compute/attest the state commitment), any transaction whose only distinguishing behavior is a `replace_class` syscall call with an undeclared class hash will:
- **Revert** (or fail entirely) in Blockifier, since `get_compiled_class` raises `UndeclaredClassHash`.
- **Succeed** in the OS's Cairo re-execution, since the check is entirely absent, silently committing an undeclared/garbage class hash into the contract's state entry.

### Impact Explanation
This is a direct root-cause for honest-node/re-execution divergence: the block built and locally executed by the sequencer (Blockifier) will treat a transaction invoking `replace_class(undeclared_hash)` as reverted, while the Starknet OS, tasked with proving that exact block/transaction set and re-deriving the state commitment, will treat it as a successful state mutation and commit a different `class_hash` entry (and different fee/receipt outcome) for the contract address. This produces:
- A wrong committed state root / block hash relative to what the sequencer actually executed (the classic "wrong committed root" class of bug).
- Potential permanent bricking of the affected contract address, since its `class_hash` is now set to an undeclared/unusable class hash that cannot be executed (denial of contract functionality), an unauthorized state mutation that the transaction sender did not "legitimately" earn per Blockifier's rules.
- Because state commitment/proof generation depends on the OS's version of the state diff, this divergence could make the network unable to reconcile/confirm the block (the prover-computed root would not match Blockifier's actual state), a scenario explicitly named as valid impact in scope.

### Likelihood Explanation
The trigger is trivial and fully reachable by an unprivileged transaction sender: any Cairo1 contract that invokes the `replace_class_syscall` (widely available, e.g., as exercised in `test_replace_class` feature contracts) with an arbitrary/undeclared class hash as calldata will exercise this divergence. No special privileges, prior state, or op assistance are required — a single `invoke` transaction targeting any contract that forwards attacker-controlled calldata into `replace_class_syscall` (or an account/contract implementing this pattern) suffices.

### Recommendation
Add the same declared-class validation in the OS's `execute_replace_class` (both the current `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` variants) that Blockifier already enforces in `syscall_base.rs`: read/verify a `contract_class_changes` (or class-hash storage) entry proving `class_hash` corresponds to an already-declared class before writing the new `StateEntry`, mirroring the assertion pattern already used elsewhere in the OS for enforcing declare-once semantics (e.g., `assert_not_zero`/`dict_update` with `prev_value` checks as seen in `execute_declare_transaction`). Add unit/integration tests asserting OS execution reverts identically to Blockifier when `replace_class` targets an undeclared class hash.

### Proof of Concept
1. Deploy a Cairo1 contract exposing a function that calls `replace_class_syscall(class_hash)` with a caller-supplied `class_hash` (pattern already present in test fixtures, e.g. `test_replace_class`, see [6](#0-5) ).
2. Submit an `invoke` transaction calling this function with an arbitrary undeclared felt as `class_hash` (e.g. `felt!(1234_u16)` as used in the Blockifier's own negative test at [7](#0-6) ).
3. Under Blockifier (sequencer execution), the transaction reverts with `"... is not declared"`, and no `class_hashes` state diff entry is produced for the contract.
4. Feed the identical transaction/block into the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo`), which lacks the check (line 902 TODO) and unconditionally performs `dict_update` on `contract_state_changes` setting `class_hash=class_hash` for the contract — producing a *different*, successful outcome and a different final state root than Blockifier computed for the same block.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
