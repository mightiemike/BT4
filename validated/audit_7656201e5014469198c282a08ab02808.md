## Analysis: Recursive bytecode-segment hashing without depth limit (Rust-native stack overflow analog to CVE-2018-0739)

CVE-2018-0739 is a stack-overflow DoS caused by unbounded recursion while parsing a recursively-defined structure (ASN.1/PKCS7) built from untrusted input, with no depth check. The sequencer contains a direct structural analog: computation of the CASM **compiled class hash** and the **bytecode segment structure** both recurse over a `NestedIntList` tree with **no depth bound**, and that tree's shape is derived from an attacker-declared Sierra program.

### Title
Unbounded recursive bytecode-segment hashing/structuring on attacker-controlled class data can cause native stack overflow (DoS) - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
`bytecode_hash_node` in `starknet_api` recurses once per level of the `NestedIntList` (`bytecode_segment_lengths`) tree that describes how a declared contract's CASM bytecode is segmented, with no recursion-depth guard: [1](#0-0) 

The equivalent Starknet OS hint helper has the same unbounded-recursion shape: [2](#0-1) 

Both are invoked in-process (not inside the sandboxed compiler subprocess) on `NestedIntList` structures that ultimately originate from a Sierra class supplied via a `Declare` transaction and compiled by the sequencer's own `SierraToCasmCompiler`:
- `SierraCompiler::compile` calls `executable_class.hash(&HashVersion::V2)` directly in the compiler service process, after the subprocess-isolated compile step returns: [3](#0-2) 
- The Starknet OS builds the same unbounded tree from `compiled_class.get_bytecode_segment_lengths()` when validating compiled-class facts during (re-)execution/proving: [4](#0-3) 

Notably, the blockifier's own analogous type (`NestedFeltCounts`, used for `CompiledClassV1::hash`) explicitly caps recursion via `assert!(segmentation_depth <= 1, ...)`, showing the depth-limiting pattern is known but was not applied consistently to the `NestedIntList` path used by the Sierra compiler service and the OS: [5](#0-4) 

### Finding Description
When a user submits a `Declare` transaction, the sequencer compiles the Sierra program into a `CasmContractClass` (whose `bytecode_segment_lengths: Option<NestedIntList>` field reflects the compiled program's function/branch structure) and then computes the compiled-class hash in-process: [6](#0-5) 

`bytecode_hash` / `bytecode_hash_node` recurse once per nesting level of this structure with no maximum-depth check, unlike the `RecursionDepthGuard` mechanism used elsewhere in the codebase to bound Cairo call-stack recursion: [7](#0-6) 

A contract declarer who crafts Sierra source producing a program with a deeply/adversarially nested control-flow (branch) structure can cause the compiler to emit a `NestedIntList` with very deep nesting relative to the bytecode size limit (`max_bytecode_size`, e.g. 81920 in current constants: [8](#0-7) ). Computing the hash of this structure then recurses natively in Rust with no depth cap, risking a stack overflow that aborts the process. The same unbounded-depth `create_bytecode_segment_structure_inner` runs during Starknet OS re-execution/proving whenever that declared class is used in a block.

### Impact Explanation
A stack overflow in Rust is an unrecoverable process abort (not a catchable panic). If reachable:
- In the Sierra-to-CASM compiler service (`apollo_compile_to_casm`), it crashes the component responsible for compiling and hashing every declare transaction, degrading/halting declare-transaction admission network-wide if all nodes crash on the same malicious class.
- In the Starknet OS hint path, it can crash the block re-execution/proving pipeline for any block including the malicious declared class, which can prevent the network from confirming new transactions/blocks (matching the accepted impact criterion "a network unable to confirm new transactions").

### Likelihood Explanation
Reachable via a single, ordinary `Declare` transaction (or L1-originated declare where applicable) submitted by any unprivileged declarer — no special privileges, timing, or coordination required. The only requirement is crafting Sierra source that compiles into a CASM program whose control-flow-derived bytecode segmentation is deeply nested, which is feasible within existing bytecode-size limits since the segmentation tree's depth is not otherwise bounded independently of program structure.

### Recommendation
Add an explicit, enforced maximum recursion/nesting depth (mirroring `NestedFeltCounts::new_inner`'s `segmentation_depth <= 1` assertion, or the `RecursionDepthGuard` pattern used for Cairo call stacks) to:
- `bytecode_hash_node` / `bytecode_hash` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs`, and
- `create_bytecode_segment_structure_inner` in `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`.

Reject (with a normal compilation/validation error) any `NestedIntList`/`bytecode_segment_lengths` whose nesting depth exceeds the bound, before recursive hashing/structuring begins. Alternatively, convert these functions to explicit-stack iterative traversal to remove the native-stack dependency entirely.

### Proof of Concept
1. Author a Cairo/Sierra program whose compiled CASM bytecode segmentation (as emitted by `cairo-lang-starknet-classes`) forms a deeply nested `NestedIntList::Node` chain (e.g., via deeply nested branch/function scoping) close to the bytecode-size limit.
2. Submit it as a `Declare` transaction to the sequencer's gateway.
3. Observe that `SierraCompiler::compile` (`crates/apollo_compile_to_casm/src/lib.rs`) invokes `executable_class.hash(&HashVersion::V2)` in-process, driving `bytecode_hash_node`'s unbounded recursion; with sufficient nesting depth this exhausts the thread stack and aborts the compiler-service process.
4. Separately, once such a class is declared and exercised, the Starknet OS's `load_classes_and_create_bytecode_segment_structures` hint invokes `create_bytecode_segment_structure` on the same unbounded structure during block re-execution/proving, exposing the same crash in that component.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
