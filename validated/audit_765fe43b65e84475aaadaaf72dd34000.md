## Analysis

The external report's bug class is: relying on a single DEX/AMM for swap execution (rather than an aggregator or a manipulation-resistant price source) exposes swaps to bad/manipulable rates. Push Chain's `x/uexecutor` module has a direct analog: **all** protocol-driven auto-swaps (gas-abstraction deposits, gas-and-payload deposits, and excess-gas refunds) are quoted and executed against a **single Uniswap V3 pool using its live spot price**, with no TWAP, no aggregator, and no cross-venue check.

### Title
Single-DEX spot-price auto-swap quoting in gas-abstraction/refund flows enables sandwich extraction of user/protocol value - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`GetSwapQuote` sources its price exclusively from `QuoterV2.quoteExactInputSingle` on one configured Uniswap V3 pool, and every downstream `minPCOut` slippage floor (5%) is derived from that same instantaneous quote. Because the quote-then-swap sequence executes against the identical single pool within the same protocol call, an attacker who trades against that pool immediately beforehand can shift the spot price the module reads, causing the subsequent protocol-driven swap (deposit auto-swap or gas refund) to settle at a manipulated price without ever tripping the slippage guard.

### Finding Description
`GetSwapQuote` [1](#0-0)  calls the Uniswap V3 `QuoterV2` for a single hard-coded token/WPC pool via `defaultFeeTier`, returning the pool's current spot-based quote — no TWAP window, no secondary DEX, no aggregator cross-check.

This quote feeds `minPCOut` (`quote * 95 / 100`) which is used as the sole price-protection floor in three flows:
- Gas-abstraction inbound auto-swap: [2](#0-1) 
- Gas-and-payload inbound auto-swap: [3](#0-2) 
- Excess-gas refund swap-back: [4](#0-3) 

In each case, the quote-read (`CallEVM`, `commit=false`) and the actual swap-write (`DerivedEVMCall` → `depositPRC20WithAutoSwap` / `refundUnusedGas`, `commit=true`) happen back-to-back inside the same keeper call, both against the *same* pool. Since `minPCOut` is computed from that pool's own momentary state rather than a manipulation-resistant reference (TWAP or multi-source aggregation), an attacker who moves the pool's price with an ordinary EVM transaction immediately before the module's execution (e.g., front-running the block containing the validator vote that crosses inbound quorum, which is observable public state) forces the protocol's swap to execute at the attacker-influenced price. The 5% band only bounds slippage *relative to the manipulated quote*, not relative to fair market value, so the swap does not revert. The attacker can then reverse their price-moving trade to capture the spread, extracting value from the pool/protocol side of every gas-abstraction deposit or gas refund that routes through `CallPRC20DepositAutoSwap` or `CallUniversalCoreRefundUnusedGas`.

This is directly analogous to the referenced report: using only one DEX venue for swap pricing, with no aggregator/TWAP fallback, subjects `amountOut` to venue-specific price impact and manipulation, but here it materializes as an unprivileged, user-reachable value-extraction vector against protocol/user PRC20↔PC accounting rather than a mere efficiency complaint.

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound execution, and every successful outbound's excess-gas refund, routes real user funds through this single-pool spot-quoted swap. An attacker able to move the pool price transiently can degrade the `amountOut` users/protocol receive on each such swap and capture the difference, corrupting PRC20/native asset accounting and gas-refund accounting for ordinary depositors — this falls under "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" and "unauthorized... unauthorized refund... of user or protocol-controlled funds" in the allowed impact gate.

### Likelihood Explanation
Medium. No privileged role is needed — any address can submit an ordinary swap transaction against the public Uniswap V3 pool used by `UniversalCore`, and can predict/observe when a pending inbound vote is about to cross quorum (chain state is public) or can simply trigger the attack against their own gas-abstraction deposit. It requires capital to move the pool and precise timing within a block, which is a standard, well-understood MEV/sandwich pattern against spot-quoted single-pool oracles.

### Recommendation
Do not derive `minPCOut` solely from a single pool's instantaneous `quoteExactInputSingle` result. Use a manipulation-resistant reference price (e.g., a TWAP over multiple blocks) and/or cross-check against a second liquidity source (a second DEX pool or aggregator quote) before accepting `minPCOut`, and consider capping per-block price deviation for the reference pool used by `GetSwapQuote` / `GetDefaultFeeTierForToken` in `x/uexecutor/keeper/evm.go`.

### Proof of Concept
1. Attacker observes a pending `GAS` inbound (their own or another user's) approaching validator quorum via public `x/uexecutor` state.
2. In the same block (or immediately prior), attacker submits a large swap on the WPC/PRC20 Uniswap V3 pool used by `UniversalCore`, moving the pool's spot price.
3. Validators' vote crosses quorum, `ExecuteInboundGas` runs `GetSwapQuote` [5](#0-4)  against the now-manipulated pool, computes `minPCOut` from that manipulated value, and calls `CallPRC20DepositAutoSwap` [6](#0-5)  which executes without reverting since `minPCOut` matches the manipulated price.
4. Attacker reverses their price-moving trade in the same or next block, capturing the spread extracted from the pool/protocol side of the auto-swap, at the expense of the true value the depositor's UEA should have received.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
