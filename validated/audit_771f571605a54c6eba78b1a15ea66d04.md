### Title
Ancient-slot squashing silently drops carry-forward tombstones when the invariant that they're already purged is violated - ([File: accounts-db/src/ancient_append_vecs.rs])

### Summary
`finish_combine_ancient_slots_packed_internal` assumes that any zero-lamport "tombstone" accounts collected by `shrink_collect` have already been dropped by the time a slot is ancient-squashed, and only guards this assumption with a `debug_assert!`, which compiles out in release builds. If the assumption is violated, the tombstone data is silently discarded during the ancient squash write path instead of being carried forward or explicitly purged from the index/state, analogous to the reported bug class where a partial repayment operation leaves remaining state (liens) unhandled with no explicit cleanup, permanently locking the underlying asset.

### Finding Description
`shrink_collect` records zero-lamport "tombstone" accounts (accounts already removed from the index but whose bytes must be retained so an incremental snapshot can still observe and propagate the deletion) into `tombstones_to_carry_forward` whenever `can_purge_zero_lamport_single_ref_after_shrink(slot)` is false, i.e. whenever `slot` is *not yet* covered by the latest full snapshot: [1](#0-0) 

The normal shrink path (`shrink_storage` / `remove_old_stores_shrink`) correctly rewrites these tombstones into the new storage via `store_tombstones`: [2](#0-1) 

However, the ancient-squash write path, `finish_combine_ancient_slots_packed_internal`, has **no equivalent handling** for `tombstones_to_carry_forward`. It only asserts the list is empty via a `debug_assert!` and comments that this "should" always hold because ancient squash only runs on slots far older than the latest full snapshot: [3](#0-2) 

The comment itself flags the exact risk: *"The squash write path has no tombstone handling, so a non-empty list here would be silently lost."* In a release build, `debug_assert!` is a no-op, so if a slot reaches ancient squashing while it is still newer than (or equal to) `latest_full_snapshot_slot` — e.g., when snapshotting is disabled, delayed, or lagging (full snapshots are taken far less often than the epoch-length threshold that defines "ancient"), — the tombstone bytes for that squashed slot are dropped with **no explicit removal or carry-forward**, exactly mirroring the reported pattern: a partial/incomplete cleanup operation proceeds to "success" without validating that the remaining obligation (here, the tombstone marker) was actually resolved, and without any explicit remediation step.

### Impact Explanation
A tombstone exists specifically so that an incremental snapshot taken after the latest *full* snapshot can still see that a previously non-zero-lamport account (visible in that full snapshot) has since been zeroed out, and can therefore propagate the deletion. If ancient squash silently drops this tombstone instead of carrying it forward:
- The zero-lamport deletion marker disappears from storage without the index being updated to compensate.
- A subsequent incremental snapshot generated relative to the (now stale) full snapshot base will fail to observe the account's zero-lamport state and instead resurrect the account's last known non-zero balance from the full snapshot base.
- This produces a **stale/wrong-version account load** and a **silent balance divergence** on any node that restores from that incremental snapshot versus a node that replayed transactions honestly — a snapshot-vs-replay mismatch that can also manifest as an accounts-hash/bank-hash divergence between nodes.

This falls squarely within the accepted impact categories (stale account loads, silent balance change, honest-node snapshot-vs-replay mismatch) and lives entirely in AccountsDB's snapshot/shrink/clean machinery, matching the scope constraints.

### Likelihood Explanation
The precondition — a slot becoming eligible for ancient squashing while still newer than `latest_full_snapshot_slot` — is not structurally impossible: `latest_full_snapshot_slot` is only advanced when full snapshots are actually generated, whereas "ancient" eligibility is driven purely by slot age relative to the epoch schedule. Any validator configuration or operational condition that delays/suppresses full snapshot generation relative to the epoch-based ancient threshold (long enough to also let `shrink_ancient_slots`/`combine_ancient_slots_packed` run) can trigger the mismatch. Because the guard is a `debug_assert!`, release binaries provide no runtime protection or even a log signal when this occurs, making the corruption silent. The exact scheduling relationship between `shrink_ancient_slots` invocation and full snapshot cadence could not be fully verified within the available tool budget (the definitions of `shrink_ancient_slots` / ancient-slot selection logic were only found referenced in test files, not fully read), so the precise triggering window is not conclusively proven, only strongly suggested by the code's own comment acknowledging the risk.

### Recommendation
Replace the `debug_assert!` in `finish_combine_ancient_slots_packed_internal` with a hard runtime check (`assert!`) that fails loudly rather than silently corrupting state in release builds, or — better — implement explicit tombstone handling in the ancient-squash write path (mirroring `store_tombstones` in `shrink_storage`) so that any carried-forward tombstones are written into the new ancient storage rather than dropped. At minimum, log and refuse to proceed with the squash for any slot where `tombstones_to_carry_forward` is non-empty, so the deletion marker is never lost.

### Proof of Concept
Not independently reproducible from the indexed context alone (the scheduling code that decides when a slot becomes ancient-squash-eligible relative to `latest_full_snapshot_slot` was not fully retrievable). The existing repository test `test_finish_combine_ancient_slots_packed_internal` [4](#0-3)  only exercises the "no tombstones" case; a conceptual PoC would extend this test to seed a tombstone-bearing storage (as done in `test_shrink_collect_carries_forward_existing_tombstones` [5](#0-4) ) with `latest_full_snapshot_slot` set below the squashed slot, then call `combine_ancient_slots_packed` on that slot and observe (in a release build, where the `debug_assert!` is inert) that the resulting ancient storage has zero tombstones while the account is neither in the index nor represented as deleted in storage.

                            db.shrink_candidate_slots.lock().unwrap().insert(slot);

                        } else {
                            assert!(storage.is_none());
                        }
                    });

/// `shrink_collect` must recognize tombstone offsets already recorded on a storage (carried
/// forward by a prior shrink) and route them into `tombstones_to_carry_forward`: rewritten while
/// the slot is newer than the latest full snapshot, and dropped once the snapshot advances past it.
#[test]
fn test_shrink_collect_carries_forward_existing_tombstones() {
    let accounts_db = AccountsDb::new_for_tests_with_config(Vec::new(), DEFAULT_ACCOUNTS_DB_CONFIG);
    let slot = 2;
    // Latest full snapshot older than `slot`: tombstones are not yet purgeable.
    accounts_db.set_latest_full_snapshot_slot(slot - 1);

    let alive_pubkey = Pubkey::new_unique();
    let tombstone_pubkey = Pubkey::new_unique();
    let alive_account = AccountSharedData::new(1, 0, &Pubkey::default());
    let zero_lamport_account = AccountSharedData::new(0, 0, &Pubkey::default());

    let (_temp_dirs, paths) = get_temp_accounts_paths(1).unwrap();
    let storage = Arc::new(AccountStorageEntry::new(
        &paths[0],
        slot,
        100,
        DEFAULT_FILE_SIZE,
        accounts_db.accounts_file_provider,
    ));
    // An ordinary alive account, present in the index.
    append_single_account_with_default_hash(
        &storage,
        &alive_pubkey,
        &alive_account,
        true,
        Some(&accounts_db.accounts_index),
    );
    // A zero-lamport account physically in the storage but NOT in the index: i.e. a tombstone
    // carried forward by a prior shrink of an even-older storage.
    append_single_account_with_default_hash(
        &storage,
        &tombstone_pubkey,
        &zero_lamport_account,
        true,
        None,
    );
    accounts_db.storage.insert(Arc::clone(&storage));
    accounts_db.add_root(slot);

    // Record the tombstone account's offset on the storage's tombstone list, as a prior shrink
    // would have.
    let mut tombstone_offset = None;
    storage
        .accounts
        .scan_accounts_without_data(|offset, account| {
            if account.pubkey == &tombstone_pubkey {
                tombstone_offset = Some(offset);
            }
        })
        .unwrap();
    storage.batch_insert_tombstone_offsets([tombstone_offset.unwrap()]);
    assert_eq!(storage.num_zero_lamport_single_ref_accounts(), 1);

    // Newer than the latest full snapshot: the tombstone must be carried forward, not dropped and
    // not mis-routed into the alive set.
    let mut unique_accounts =
        accounts_db.get_unique_accounts_from_storage_for_shrink(&storage, &ShrinkStats::default());
    let shrink_collect = accounts_db.shrink_collect::<AliveAccounts<'_>>(
        &storage,
        &mut unique_accounts,
        &ShrinkStats::default(),
    );
    assert_eq!(shrink_collect.tombstones_to_carry_forward.len(), 1);
    assert!(shrink_collect.tombstones_total_bytes > 0);
    assert_eq!(
        shrink_collect
            .alive_accounts
            .accounts
            .iter()
            .map(|account| *account.pubkey())
            .collect::<Vec<_>>(),
        vec![alive_pubkey],
    );

    // Once the full snapshot advances to `slot`, the tombstone is purgeable and must be dropped
    // rather than carried forward.
    accounts_db.set_latest_full_snapshot_slot(slot);
    let mut unique_accounts =
        accounts_db.get_unique_accounts_from_storage_for_shrink(&storage, &ShrinkStats::default());
    let shrink_collect = accounts_db.shrink_collect::<AliveAccounts<'_>>(
        &storage,
        &mut unique_accounts,
        &ShrinkStats::default(),
    );
    assert!(shrink_collect.tombstones_to_carry_forward.is_empty());
    assert_eq!(shrink_collect.tombstones_total_bytes, 0);
}
