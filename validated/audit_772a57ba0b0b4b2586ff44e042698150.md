Based on the investigation, I found a concrete on-chain analog to the de-peg valuation flaw: Push Chain's gas-abstraction swap path uses a single unprotected spot-price quote from a Uniswap V3 `QuoterV2` to value the PRC20-to-WPC conversion, exactly the same class of bug as the Sherlock finding (an unvalidated, manipulable price feed used to compute value/slippage bounds for a fund-moving operation).

### Title
Gas-abstraction PRC20→WPC auto-swap uses unprotected single-block QuoterV2 spot price, allowing value extraction via price manipulation - (File: x/uexecutor/keeper/evm.go, execute_inbound_gas.go, execute_inbound_gas_and_payload.go, outbound.go)

### Summary
The inbound `GAS` / `GAS_AND_PAYLOAD` execution paths, and the outbound gas-refund path, compute `minPCOut` for a PRC20→WPC swap by calling `GetSwapQuote`, which reads the current spot price directly from the Uniswap V3 `QuoterV2.quoteExactInputSingle` on-chain contract, then applies a flat 5% slippage tolerance before immediately executing the swap via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`. There is no TWAP, no external price-oracle cross-check, and no bound on the pool's own liquidity depth — the "price" used to value the conversion is whatever the on-chain AMM pool currently reports, which is exactly the same root-cause pattern as the Sherlock M-1 finding (using an unvalidated single-source price for a value-critical conversion instead of a manipulation-resistant or independently-verified price).

### Finding Description
`GetSwapQuote` [1](#0-0)  performs a live `quoteExactInputSingle` call against the configured `UniversalCoreQuoterAddress` and returns the pool's current spot output amount. This value is then used to derive `minPCOut = quote * 95 / 100` and passed straight into `CallPRC20DepositAutoSwap`, all in the same keeper-invoked EVM sequence, in three separate call sites:

- `ExecuteInboundGas` (GAS route) [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD route) [3](#0-2) 
- `applyGasRefund` (outbound gas refund route) [4](#0-3) 

Because this quote/swap sequence is only executed once quorum among universal validators is reached and the inbound/outbound is processed (i.e., at a block height that is not directly attacker-selected but is predictable within a narrow, observable window), an unprivileged actor who also controls (or can cheaply trade against) the WPC/PRC20 pool used by `UniversalCore` can push the pool's spot price in a favorable direction immediately before the module's `depositPRC20WithAutoSwap` / `refundUnusedGas` call executes, then reverse the trade afterward. The 5% slippage buffer is a fixed percentage unrelated to the pool's actual liquidity depth, so for any PRC20/WPC pair with realistic on-chain liquidity relative to inbound/refund sizes, a price move larger than 5% is achievable with a normal swap transaction, well within the reach of an unprivileged external actor and requiring no validator, relayer, or node compromise.

This mirrors the reported bug class precisely: the protocol treats a **spot-queried, single-source, unauthenticated price** as ground truth for a value-critical conversion (there `<quote>/USD` assumed pegged; here `PRC20/WPC` assumed to reflect fair, unmanipulated pool state), without any additional validation (TWAP, external oracle cross-check, or liquidity-aware bounding).

### Impact Explanation
This affects **gas fee accounting / gas token accounting**, which is explicitly in scope ("corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting ... token mapping"). An attacker can manipulate the AMM price around the module's swap execution to extract WPC liquidity from the pool at the expense of the pool's actual value backing, or cause a user's gas top-up / refund to receive materially less WPC than the fair-value amount, corrupting the gas fee/refund accounting the protocol relies on for consistent, fair gas abstraction. Repeated abuse against low-liquidity PRC20/WPC pairs can result in continuous value drain from Push Chain-controlled swap liquidity.

### Likelihood Explanation
Likelihood is elevated because: (1) the swap path is triggered automatically and deterministically whenever any user sends a `GAS` or `GAS_AND_PAYLOAD` inbound or any outbound requires a gas refund — no special conditions are needed; (2) any unprivileged external actor with capital can manipulate a shallow on-chain AMM pool; (3) the fixed 5% slippage tolerance does not scale with pool depth, so it is straightforward for lower-liquidity token pairs to exceed that bound through normal manipulation.

### Recommendation
Do not rely on a single spot-price read from `QuoterV2.quoteExactInputSingle` immediately before executing the swap. Use a time-weighted average price (TWAP) from the pool, cross-check against an independent price source (e.g., the same oracle infrastructure already used for `ChainMeta`/gas price voting by universal validators), and/or scale the slippage tolerance to the pool's real-time liquidity depth so that manipulated spot prices cannot be used to set `minPCOut`.

### Proof of Concept
1. Attacker identifies (or creates) a PRC20/WPC pool on Push Chain's Uniswap-V3-style DEX used by `UniversalCore` with liquidity shallow enough that a swap of size `X` moves the spot price by more than 5%.
2. Attacker sends a normal cross-chain deposit that will trigger `ExecuteInboundGas` (or triggers an outbound gas refund via `applyGasRefund`) with an amount close to `X`.
3. Immediately before the block in which the inbound/outbound is processed (predictable since inbound processing follows deterministic quorum-based finalization), attacker swaps against the PRC20/WPC pool to push the spot price down.
4. `GetSwapQuote` [5](#0-4)  reads the manipulated spot price; `minPCOut` is derived from it with only 5% additional slippage tolerance, so `CallPRC20DepositAutoSwap` [6](#0-5)  executes the swap at the manipulated unfavorable rate.
5. Attacker reverses their manipulation trade afterward, capturing the price movement as profit extracted from the pool that Push Chain's `UniversalCore` swap relies on, at the expense of accurate gas-fee/refund accounting for the affected user and the health of protocol-controlled liquidity.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
