### Title
Pre-`VERSION_4_7_1` fork gate in `TransactionCapsule.checkWeight` keys duplicate-signature detection by raw signature bytes instead of recovered address, allowing a single key's weight to be counted multiple times - (File: `chainbase/src/main/java/org/tron/core/capsule/TransactionCapsule.java`)

### Summary
`TransactionCapsule.checkWeight` deduplicates signatures using a `HashMap` keyed by `base64` (the raw base64 signature string) unless `ForkController.instance().pass(VERSION_4_7_1)` is true, in which case the key is reassigned to `encode58Check(address)`. Before the fork gate passes, two syntactically different but cryptographically valid signatures from the same key (e.g., ECDSA `(r, n-s)` malleable variant, or a signature with the accepted trailing-padding slack tolerated by the loose `sig.size() < 65` check documented in `SignUtils.isValidLength`) recover to the same address yet produce different `base64` strings, so the "has signed twice" check does not trigger and the same key's weight is added twice to `currentWeight`.

### Finding Description
In `checkWeight`:
```
String base64 = TransactionCapsule.getBase64FromByteString(sig);
byte[] address = SignUtils.signatureToAddress(hash, base64, ...);
long weight = getWeight(permission, address);
...
if (ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)) {
  base64 = encode58Check(address);
}
if (addMap.containsKey(base64)) {
  throw new PermissionException(encode58Check(address) + " has signed twice!");
}
addMap.put(base64, weight);
...
currentWeight += weight;
``` [1](#0-0) 

When the fork has not yet passed, `addMap` is keyed by the raw base64-encoded signature bytes rather than the recovered address. Because signature encodings for a fixed ECDSA key/hash are not unique bit-for-bit (canonical vs. non-canonical `s`, differing recovery-id/`v` byte, or accepted padding as noted in `SignUtils.isValidLength`'s comment that "consensus paths ... keep the looser `size < 65` check to remain compatible with historical on-chain signatures that carry trailing padding bytes"), an attacker holding one valid key can supply two (or more) differently-encoded signatures that both recover to the same address via `SignUtils.signatureToAddress`. Each iteration independently looks up `weight = getWeight(permission, address)` for the *same* address and adds it to `currentWeight`, and the `addMap.containsKey(base64)` guard fails to catch the duplicate because the two `base64` strings differ. This lets `currentWeight` reach/exceed `permission.getThreshold()` using only one authorized key, bypassing the multisig weight-threshold invariant. Once fork-gate `VERSION_4_7_1` passes, the code correctly reassigns `base64 = encode58Check(address)` before the dedup check, closing the gap. [2](#0-1) 

This is reachable from any unprivileged account: `checkWeight` is invoked both when broadcasting a transaction for on-chain validation (`validatePubSignature` → `validateSignature`) and off-chain (`TransactionUtil.getTransactionSignWeight`), so a crafted transaction with duplicate-but-differently-encoded signatures for `AccountPermissionUpdateContract` or any owner/active-permission-guarded contract could pass a threshold that a single key's weight should not satisfy. [3](#0-2) 

### Impact Explanation
Concrete impact class: unauthorized account operations / multisig bypass. If exploitable, an attacker controlling a single low-weight key on a multisig permission could satisfy a higher threshold and execute owner-level operations (e.g., reconfiguring account permissions via `AccountPermissionUpdateContract`, or moving funds via `TransferContract`) without the required additional co-signers.

### Likelihood Explanation
The exploitability is strictly gated on `!ForkController.instance().pass(VERSION_4_7_1)`. This is a maintenance-period-activated hard fork tracked in `DynamicPropertiesStore`'s per-version witness-signal stats (`passNew`/`passOld` in `ForkController`), meaning on any long-running network (mainnet, or any established testnet) this fork has almost certainly already been activated for a long time, since it gates behind `latestBlockTime >= hardForkTime` combined with witness signaling, and once passed a fork cannot be "un-passed" going forward under normal operation. [4](#0-3)  I could not fully verify from the indexed context whether this specific chain's current runtime state has already passed `VERSION_4_7_1` (the hard-fork timestamp/rate constant for `VERSION_4_7_1` was not found in the indexed portion of `Parameter.java`), so I cannot definitively confirm whether the vulnerable pre-fork branch is still reachable on the live/target network today. On a network where it has not yet passed (e.g., freshly bootstrapped private/test chain, or a chain that has not reached the fork's hard-fork time/witness-signal threshold), the bug is real and directly reachable by any unprivileged signer with one authorized key, at the cost of only ordinary transaction fees/bandwidth — no privileged role, MITM, or leaked keys required.

### Recommendation
Always key the `addMap` deduplication check by the recovered `address` (or its canonical encoding), not by the raw signature bytes, regardless of fork state — i.e., remove the fork-gated conditional and unconditionally use `encode58Check(address)` (or the raw `address` bytes) as the map key in `checkWeight`. This eliminates the fork-state dependency and prevents any signature-encoding variance from bypassing "has signed twice" detection. [5](#0-4) 

### Proof of Concept
```java
// JUnit sketch targeting TransactionCapsule.checkWeight
@Test
public void testDuplicateKeyDifferentEncodingBypassesDedup() throws Exception {
  ECKey key1 = new ECKey();
  byte[] hash = Sha256Hash.hash(true, "test".getBytes());

  Permission permission = Permission.newBuilder()
      .setType(Permission.PermissionType.Active)
      .setThreshold(2) // requires 2 units of weight
      .addKeys(Protocol.Key.newBuilder()
          .setAddress(ByteString.copyFrom(key1.getAddress()))
          .setWeight(1).build())
      .build();

  // sig1: canonical signature from key1
  ECKey.ECDSASignature sig1 = key1.sign(hash);
  // sig2: malleable/differently-encoded variant of the same signature that
  // still recovers to key1's address (e.g. s -> CURVE.getN().subtract(s),
  // or a different recovery-id byte / padded encoding accepted by the
  // loose `sig.size() < 65` check)
  ByteString sigBytes1 = ByteString.copyFrom(sig1.toByteArray());
  ByteString sigBytes2 = ByteString.copyFrom(mutateEncoding(sig1)); // same address, different bytes

  List<ByteString> sigs = Arrays.asList(sigBytes1, sigBytes2);
  List<ByteString> approveList = new ArrayList<>();

  // simulate pre-fork state (ForkController.pass(VERSION_4_7_1) == false)
  long weight = TransactionCapsule.checkWeight(permission, sigs, hash, approveList);

  // BUG: weight becomes 2 (1+1) from a single key, satisfying threshold=2,
  // even though only one authorized key actually signed.
  Assert.assertTrue(weight >= permission.getThreshold()); // demonstrates bypass
}
```
Expected correct behavior (post-fix, or when `pass(VERSION_4_7_1)` is true): `checkWeight` should throw `PermissionException("... has signed twice!")` for the second signature, and `currentWeight` should never exceed the true number of distinct authorized keys' combined weight. [6](#0-5)

  public static long checkWeight(Permission permission, List<ByteString> sigs, byte[] hash,
      List<ByteString> approveList)
      throws SignatureException, PermissionException, SignatureFormatException {
    long currentWeight = 0;
    if (sigs.size() > permission.getKeysCount()) {
      throw new PermissionException(
          "Signature count is " + (sigs.size()) + " more than key counts of permission : "
              + permission.getKeysCount());
    }
    HashMap addMap = new HashMap();
    for (ByteString sig : sigs) {
      if (sig.size() < 65) {
        throw new SignatureFormatException(
            "Signature size is " + sig.size());
      }
      String base64 = TransactionCapsule.getBase64FromByteString(sig);
      byte[] address = SignUtils
          .signatureToAddress(hash, base64, CommonParameter.getInstance().isECKeyCryptoEngine());
      long weight = getWeight(permission, address);
      if (weight == 0) {
        throw new PermissionException(
            ByteArray.toHexString(hash) + " is signed by " + encode58Check(address)
                + " but it is not contained of permission.");
      }
      if (ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)) {
        base64 = encode58Check(address);
      }
      if (addMap.containsKey(base64)) {
        throw new PermissionException(encode58Check(address) + " has signed twice!");
      }
      addMap.put(base64, weight);
      if (approveList != null) {
        approveList.add(ByteString.copyFrom(address)); //out put approve list.
      }
      currentWeight += weight;
    }
    return currentWeight;
  }
