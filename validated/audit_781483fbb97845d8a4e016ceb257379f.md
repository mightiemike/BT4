### Title
Stale STX-only reward-per-token snapshot lets a below-threshold signer's stakers claim phantom rewards - ([File: stackslib/src/chainstate/stacks/boot/pox-5.clar])

### Summary
The external Ion Protocol report describes a class of bug where an entitlement check (whitelist-gated interest accrual) is enforced at one call site but a different code path (transfer, or here, a co-triggered settlement) lets an unentitled party end up crediting itself as if it had passed the check. The analog in this repo is in `pox-5.clar`'s reward-settlement logic: `settle-rewards`/`calculateRewards` advances a signer's global STX-only `rewards-per-token-for-cycle` snapshot for a reward cycle even when that signer was never a member of the signer set for that cycle (`getSignerSharesStakedForCycle` == 0, `isSignerInCycle` == false). Because per-staker earned STX-only rewards are computed from the delta between the current global rewards-per-token snapshot and the staker's last-seen snapshot, this lets a staker (e.g. Alice) whose signer never contributed to a cycle nonetheless accrue "earned" STX-only rewards for that cycle purely as a side effect of an unrelated sBTC-bond claim being triggered on the same signer/cycle pair.

### Finding Description
`registerForBond`/`stake` and the bookkeeping around it treat "being in the signer set for cycle N" (`isSignerInCycle`) as the gate that determines whether a signer, and therefore its underlying stakers, are eligible to earn STX-only rewards for cycle N — analogous to `onlyWhitelistedLenders` gating who is allowed to earn interest in the Ion report. The equality that should hold is: *a staker's earned STX-only rewards for a cycle must only advance while their signer is a recognized member of that cycle's signer set (`shares staked for cycle > 0`)*.

The regression test `contrib/core-contract-tests/tests/pox-5/pox-5.test.ts:6064-6157` demonstrates that `claimRewards` on a sBTC bond (`testSigner.claimRewards`) runs `settle-rewards` for the STX-only track of the *same signer/cycle pair*, even though that signer (`signer1`) has zero staked shares for that cycle (`isSignerInCycle(signer1, 1) == false`, `getSignerSharesStakedForCycle(signer1, 1, null) == 0`). `settle-rewards` nonetheless advances the per-signer snapshot of the global STX-only rewards-per-token counter for that window, corrupting `signer-rewards-per-token-for-cycle`. The test's global STX-only rewards-per-token line is kept non-zero by an independent above-threshold signer (`signer2`), so the bug isn't masked by an all-zero global value.

The break happens because the code that advances the snapshot does not first check "is this signer actually a participant in this cycle" before writing the new snapshot value — the same "the underlying entitlement check exists at one call site but silently gets bypassed via a different, unprivileged, minority-triggerable path" pattern flagged in the Ion report ("whitelist checked at `supply`, but bypassable via transfer").

### Impact Explanation
This is a reward mis-payment bounded to STX-only reward funds: a staker (`alice`) ends up "owed" STX-only rewards (per `getEarnedStakerRewards`) for a cycle her signer never participated in, meaning funds that should be reserved for legitimately participating signers/stakers of that cycle are diverted. This is not chain-split/consensus-breaking (it's a boot-contract state divergence bounded to reward accounting), so it lands in the "reward mis-payment bounded to fees/rewards" High-severity bucket rather than Critical.

### Likelihood Explanation
Minority-triggerable and unprivileged: any single staker (`bob`) can set up a bond with a tiny STX backing (`registerForBond`) on a signer that is otherwise below `SIGNER_SET_MIN_USTX`, while a second, unrelated staker (`alice`) stakes STX-only on that same under-threshold signer. No majority collusion, no admin key, and no other party's cooperation is required — `bob` alone triggering `claimRewards` on his sBTC bond is sufficient to corrupt the snapshot and unlock phantom rewards for `alice`. The only external prerequisite is that some other signer's above-threshold participation keeps the global STX-only rewards-per-token counter non-zero for that cycle, which is a normal, expected network condition.

### Recommendation
Before `settle-rewards` (or any code path that advances `signer-rewards-per-token-for-cycle` for a given signer/cycle pair) writes a new snapshot, verify the signer holds `shares staked for cycle > 0` / `isSignerInCycle(signer, cycle) == true` for that cycle. If the signer had zero shares in that cycle, either skip the snapshot advance entirely for that signer/cycle, or advance it to a value that reflects zero accrual (so that the staker-side delta computation in `getEarnedStakerRewards` yields zero for that window), matching the actual, on-chain-verifiable signer-set membership rather than being advanced as a side effect of an unrelated bond claim.

### Proof of Concept
See `contrib/core-contract-tests/tests/pox-5/pox-5.test.ts:6064-6157` ("below-threshold signer leaks phantom stx-only rewards via bond co-claim"):
1. `signer1` is set up with an sBTC bond where `bob` is the sole participant, sized under `SIGNER_SET_MIN_USTX`.
2. `alice` stakes STX-only on `signer1`, with combined stake still under `SIGNER_SET_MIN_USTX`, so `isSignerInCycle(signer1, 1) == false` and `getSignerSharesStakedForCycle(signer1, 1, null) == 0`.
3. `signer2` (a different, above-threshold signer) stakes independently so the global STX-only rewards-per-token for cycle 1 is non-zero.
4. `calculateRewards` runs; `signer1`'s STX-only earnings and `alice`'s earned staker rewards are correctly `0`.
5. `testSigner.claimRewards([0n], 1n)` is invoked to settle `bob`'s sBTC bond — this triggers `settle-rewards` on `signer1`'s STX-only cycle-1 state with `shares == 0`, corrupting `signer-rewards-per-token-for-cycle`.
6. After the claim, `rov(testSigner.getEarnedStakerRewards(alice, 1n, null))` is expected to remain `0`, but the comment states this "fails on the unfixed code because the snapshot was advanced past a window signer1 didn't earn in" — i.e., `alice` becomes credited with rewards she never earned. test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
