### Title
Missing declaration check for cached V0 (Cairo 0) compiled classes allows execution of undeclared/stale classes - (File: crates/blockifier/src/state/state_reader_and_contract_manager.rs)

### Summary
`get_compiled_from_class_manager` explicitly re-validates that a cache hit for a Cairo 1 class is still declared before using it, because "existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)". This check is skipped entirely for `RunnableCompiledClass::V0(_)` classes, so a stale cache entry populated by speculative/aborted execution can be returned and executed without ever confirming the class is currently declared — the same class of bug as the reported CVE, where a cached/stale object survives a reset without going through the invalidation/re-validation path.

### Finding Description
`StateReaderAndContractManager::get_compiled_from_class_manager` in [1](#0-0)  checks the global, block-independent `contract_class_manager` cache (`RawClassCache`/`GlobalContractCache`, shared across blocks and speculative executions, see [2](#0-1)  and [3](#0-2) ) before consulting per-block committed state. For `RunnableCompiledClass::V1`/`V1Native` cache hits it re-verifies `self.state_reader.is_declared(class_hash)?` and rejects the class if it is not currently declared: [4](#0-3) 

For `RunnableCompiledClass::V0(_)` the `match` arm is an empty no-op — the class is returned as-is with no declaration check: [5](#0-4) 

This cache is populated during `set_and_compile`/`get_compiled_classes` any time a class hash is looked up while executing a transaction — including transactions that are later aborted (concurrent-execution validation failure, re-execution, or blocks that end up not being committed), per the worker/versioned-state re-execution model in [6](#0-5)  and [7](#0-6) . The cache itself has no concept of "committed" vs "speculative" state and is never invalidated when a transaction/block is rolled back — the comment in the source explicitly acknowledges this for Cairo 1 classes ("it might contain a declared class from a reverted block") but the guard against it is missing for V0 classes.

Because a Cairo 0 class hash is a hash of its own bytecode (content-addressed, independent of any deployment/declaration record), any actor can cause a Cairo 0 class to be pulled into this global cache (e.g., via a `declare` transaction that is validly executed speculatively but whose containing chunk is aborted/re-executed, or via any codepath that calls `get_compiled_class`/`get_compiled_classes` for that hash) without that declaration ever being committed to state. A subsequent, unrelated transaction (e.g., `deploy`/`replace_class`/`library_call` referencing that class hash) that hits this cache will receive and execute the class bytecode via `get_compiled_from_class_manager` while the state's declared-classes table has no record of the class — the check that exists for V1 classes (`is_declared`) is bypassed by construction for V0.

### Impact Explanation
An honest sequencer node could execute (and therefore charge fees for / produce a state diff and receipt for) a call into a "declared" contract class that is not actually recorded as declared in the canonical state. Since only V0 classes are affected and cairo0-classes are functionally simple, the most direct effect is: (a) execution results (storage writes, emitted events, `class_hash_at` behavior via `replace_class`/`deploy` into an undeclared class hash) become dependent on ephemeral speculative-execution cache contents rather than on canonical committed state, which can differ between two honest sequencer instances (one whose cache happened to be warmed by a prior aborted speculative execution of the same class hash, one whose cache was never warmed) — producing a state/receipt divergence between otherwise-honest nodes for a given block, i.e. a consensus-relevant execution divergence. This falls under "honest-node divergence" per the validation criteria. It also weakens the declared-class invariant relied upon elsewhere in the state machine (deployment must verify the class is declared) for the V0 code path specifically.

### Likelihood Explanation
Reachability requires only ordinary transaction submission: a `declare` (or any operation causing a class-hash compiled-class lookup) for a Cairo 0 class hash that gets sped up into the global cache during speculative concurrent execution, followed by that speculative chunk/transaction not being committed (validation abort/re-execution is a normal, frequent occurrence in the block-STM style concurrent executor implemented in `worker_logic.rs`/`versioned_state.rs`), followed by an unrelated transaction referencing the same (uncommitted) class hash. No special privileges beyond being a transaction sender are needed; the trigger conditions (execution abort/re-execution) are a routine part of the concurrent execution scheduler, making this readily reachable in normal operation rather than a rare edge case.

### Recommendation
Apply the same `is_declared` verification to `RunnableCompiledClass::V0` cache hits as is already done for V1/V1Native in `get_compiled_from_class_manager`, i.e. remove the special-cased empty match arm and always confirm declaration status against the authoritative (per-block) state reader before returning a cached compiled class, regardless of Cairo version. Alternatively, key/invalidate the global class cache on commit-only writes so speculative/aborted executions never populate the shared cache used by other transactions/blocks.

### Proof of Concept
Conceptual reproduction (cannot be executed in this read-only analysis; recommend validating in a Devin session):
1. Start a `WorkerExecutor` executing a chunk of transactions concurrently, where transaction A at some `tx_index` calls `get_compiled_class`/`get_compiled_classes` for a Cairo 0 class hash `H` that is not yet declared in committed state (e.g., via a `declare` that itself gets executed speculatively, populating the global `contract_class_manager` cache through `set_and_compile`), per [8](#0-7) .
2. Force transaction A's execution to be invalidated (validation failure due to a preceding transaction's write, triggering `delete_writes`/abort per [9](#0-8) ) so that A's speculative state writes (including the declaration) are rolled back from the versioned state — but the global `contract_class_manager.class_cache` entry for `H` set during step 1 is never cleared (no cache-eviction hook exists on abort).
3. Submit/execute a second, unrelated transaction B that references class hash `H` (e.g. `deploy_syscall`/`library_call_syscall`/`replace_class_syscall`), calling `get_compiled_class(H)`.
4. Observe that `get_compiled_from_class_manager` hits the cache, matches `RunnableCompiledClass::V0(_) => {}` (no declaration check), and returns/executes the cached class even though `state_reader.is_declared(H)` would return `false` — contrasted with the V1 path at [10](#0-9)  which would correctly reject it with `StateError::UndeclaredClassHash`.

impl<S: FetchCompiledClasses> StateReaderAndContractManager<S> {
    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }

    /// Returns the runnable compiled class for the given class hash, if it exists in class_cache.
    pub fn get_runnable(
        &self,
        class_hash: &ClassHash,
        native_classes_whitelist: &NativeClassesWhitelist,
    ) -> Option<RunnableCompiledClass> {
        let cached_class = self.class_cache.get(class_hash)?;
        if let CompiledClasses::V1(..) = cached_class {
            // When native mode is WaitOnCompilation, all V1 classes should have been
            // compiled to native synchronously. A V1 cache entry indicates a pipeline bug.
            assert_ne!(
                self.cairo_native_mode(),
                CairoNativeMode::WaitOnCompilation,
                "Manager did not wait on native compilation."
            );
        }

        let cached_class = match cached_class {
            CompiledClasses::V1Native(CachedCairoNative::Compiled(native))
                if !native_classes_whitelist.contains(class_hash) =>
            {
                CompiledClasses::into_non_native_class(native)
            }
            CompiledClasses::V1Native(..) | CompiledClasses::V1(..) | CompiledClasses::V0(..) => {
                cached_class
            }
        };

        Some(cached_class.to_runnable())
    }
