### Title
Empty/degenerate signer set makes `verify_signer_signatures` accept blocks with zero required and zero provided signatures - ([File: stackslib/src/chainstate/nakamoto/mod.rs])

### Summary
`NakamotoBlockHeader::verify_signer_signatures` computes an approval threshold as a percentage of the reward set's `total_signing_weight`. It never checks that this total weight is non-zero, or that the reward set's signer list is non-empty in a "meaningful" sense (`Some(vec![])` passes the same guard as a real signer list). When the persisted reward-set signer list degenerates to `Some(vec![])` (an empty, but present, list), `total_weight == 0`, the derived threshold is `0`, and zero collected signatures trivially satisfy `total_weight_signed (0) >= threshold (0)`. This is the same bug class as the Gravity bridge finding: no sanity check that a newly-installed validator/signer set's combined power exceeds a meaningful threshold before it is trusted to gate consensus.

### Finding Description
`verify_signer_signatures` only requires `reward_set.signers()` to be `Some(_)`, not non-empty: [1](#0-0) 

It then computes `total_weight` via `RewardSet::total_signing_weight`, which folds over the signer vector and returns `0` for an empty (but `Some`) vector — this is not treated as an error, unlike the `None` case: [2](#0-1) 

The threshold is derived purely as a percentage of `total_weight`: [3](#0-2) 

And the final check is a plain numeric comparison with no floor on `threshold` or `total_weight`: [4](#0-3) 

With `total_weight = 0`, `compute_voting_weight_threshold(0) = 0`. If the block carries zero signatures (`self.signer_signature` empty), the loop that accumulates `total_weight_signed` never executes, so `total_weight_signed = 0`. The final check `0 < 0` is `false`, so the function returns `Ok(0)` — the block is treated as validly signed by the entire (degenerate) signer set, even though not a single real signature was produced or checked.

A `Some(vec![])` signer list is reachable: `StacksChainState::make_signer_set` filters out any signing key whose aggregated `stacked_amt / threshold` floors to `0`, and if every aggregated signing key in a non-empty entry set floors to zero, the function returns `Some(vec![])` rather than `None` (the `None` branch is only taken if the raw `entries` slice itself is empty): [5](#0-4) 

`make_reward_set` (used for PoX-4) stores whatever `make_signer_set` returns directly into `RewardSetV0.signers`, without any extra check that the result is non-empty: [6](#0-5) 

By contrast, the newer PoX-5 code path (`pox_5_compute_and_update_signers`) explicitly detects and rejects this degenerate case: [7](#0-6) 

This shows the developers are aware that an empty signer set is a fatal condition — but the check exists only at reward-set-construction time for PoX-5, and no equivalent floor/rejection exists inside `verify_signer_signatures`/`compute_voting_weight_threshold` itself, nor for the PoX-4 (`pox_4_compute_and_update_signers`) path, which passes `make_signer_set`'s result straight through: [8](#0-7) 

### Impact Explanation
If a reward cycle's persisted `RewardSet` ever has `signers = Some(vec![])` (all aggregated signer stake below the per-slot threshold, i.e., a low-participation degenerate cycle), `verify_signer_signatures` will accept **any** Nakamoto block header for that cycle with **zero** signer signatures, since `threshold == total_weight_signed == 0`. Because every node runs the identical deterministic check, this isn't a fork between nodes — it is a network-wide acceptance of a block that received no real signer approval, defeating the entire signer-quorum security model for that reward cycle (miners could produce/finalize blocks unilaterally). This corresponds to the "an invalid block accepted... network-wide" Critical impact category, since the signer-approval invariant (`weight_signed >= threshold(total_weight)`) is meant to enforce that a real majority of signer weight approved the block, but degenerates to a vacuous truth when `total_weight == 0`.

### Likelihood Explanation
Triggering requires the reward-set-computation logic to produce a non-empty entries list whose every signing key floors to weight `0` under `make_signer_set` (PoX-4 path) — a low-stacking-participation edge case, not requiring any signer/majority collusion or privileged access; it is a property of aggregate stacker behavior in the previous cycle. It is a low-but-nonzero likelihood latent defect, distinguished from the sibling PoX-5 path which the same codebase explicitly guards against, indicating the PoX-4 path (and the shared `verify_signer_signatures`/`compute_voting_weight_threshold` primitive) was left without the analogous defense-in-depth check.

### Recommendation
- In `RewardSet::total_signing_weight` / `verify_signer_signatures`, explicitly treat an empty (but `Some`) signer list as an error (`NoRegisteredSigners`), mirroring the `None` case, rather than silently computing `total_weight = 0`.
- In `compute_voting_weight_threshold`, reject `total_weight == 0` as invalid input instead of silently returning `0`.
- In `pox_4_compute_and_update_signers` / `make_reward_set`, add the same "signer set became empty" fatal check that `pox_5_compute_and_update_signers` already has, and refuse to persist a reward set whose signer list resolved to empty when there were qualifying entries.

### Proof of Concept
1. Construct a PoX-4 reward cycle where every stacker's individually-aggregated signing key has `stacked_amt / threshold == 0` (i.e., all participants stack below the per-slot uSTX threshold, e.g. many stackers just under the minimum but who still show up as `RawRewardSetEntry`s because of the general stacking flow feeding `make_reward_set`).
2. `StacksChainState::make_signer_set` (stackslib/src/chainstate/stacks/boot/mod.rs:1020) filters every entry (`weight == 0`) and returns `Some(vec![])`.
3. `make_reward_set` stores this as `RewardSetV0.signers = Some(vec![])`; `total_signing_weight()` returns `Ok(0)`.
4. A miner builds a `NakamotoBlockHeader` for that reward cycle with `signer_signature = vec![]` (no signatures at all).
5. `verify_signer_signatures` computes `total_weight = 0`, `threshold = compute_voting_weight_threshold(0) = 0`, `total_weight_signed = 0`; the check `0 < 0` is false, so it returns `Ok(0)` — the header is treated as fully signer-approved network-wide despite zero real signatures.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

        Some(signer_set)
    }
