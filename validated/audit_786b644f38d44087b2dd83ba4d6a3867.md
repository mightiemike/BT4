### Title
Same-block sandwich of the auto-swap gas quote lets an attacker steal PC from inbound GAS/GAS_AND_PAYLOAD deposits and outbound gas refunds - ([File: x/uexecutor/keeper/execute_inbound_gas.go], [File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go], [File: x/uexecutor/keeper/outbound.go])

### Summary
The Push Chain node uses a live, permissionless Uniswap V3 pool (deployed via `UniversalCore`) to price PRC20→WPC conversions for inbound gas-token deposits and for excess-gas refunds. The quote and the swap execution both happen on-chain within the flow that runs when a `MsgVoteInbound`/`MsgVoteOutbound` crosses quorum, and the "slippage protection" is only a static 95%-of-quote floor computed from the *manipulated* price itself, not from any independent reference. This mirrors the InfinityPool bug class: a value paid to/received by an unrelated user is derived from mutable, attacker-tradable pool state that can be pushed away from fair value and pushed back in the same block, permanently transferring value away from the victim.

### Finding Description
For `GAS` and `GAS_AND_PAYLOAD` inbound transaction types, `ExecuteInboundGas` and `gasAndPayloadDepositAutoSwap` fetch a swap quote from the Uniswap V3 `QuoterV2` deployed for the `UniversalCore` contract and then execute the swap with only a 5% slippage floor computed from that same quote: [1](#0-0) [2](#0-1) 

The same pattern is used when refunding excess gas fees on a successfully-observed outbound (`applyGasRefund` → `getSwapQuoteForRefund` → `CallUniversalCoreRefundUnusedGas`): [3](#0-2) [4](#0-3) 

`GetSwapQuote` calls `quoteExactInputSingle` on the public Uniswap V3 `QuoterV2` against the live pool reserves for the PRC20/WPC pair, exactly as `pool-manager.js create-pool` provisions in the e2e setup — an ordinary, permissionless AMM pool that anyone can trade against: [5](#0-4) 

Because the pool is a normal permissionless Uniswap V3 pool, an unprivileged attacker can:
1. Observe that a large inbound `MsgVoteInbound` (GAS/GAS_AND_PAYLOAD) is about to reach quorum, or that an outbound observation is about to finalize with an excess-gas refund.
2. Submit an ordinary swap against the PRC20/WPC pool in the same block, immediately before the finalizing vote, moving the pool's spot price so that `quoteExactInputSingle` (and thus `minPCOut`) reflects the manipulated price.
3. Let the node's own deposit-auto-swap or refund execute at that manipulated price — `minPCOut` only guards against price movement between the quote call and the swap call (which happen back-to-back in the same keeper execution with no other transaction interleaving in Cosmos SDK block execution), not against the attacker pre-positioning the price before the quote is even taken.
4. Submit a second ordinary swap right after, in the same block, to restore the pool price and realize the arbitrage profit that was extracted from the victim's deposit/refund.

The victim (the CEA/EOA/UEA recipient of the inbound gas deposit, or the sender/`fund_recipient` receiving an outbound gas refund) ends up with materially less PC than the fair-market conversion of their PRC20/gas-token amount, and that difference is permanently captured by the attacker via the sandwich, exactly like the LP in the original InfinityPool report being griefed by a loan opened and closed within the same block.

### Impact Explanation
This falls under "corruption of PRC20 or native asset accounting … or refund accounting" and "draining … of user or protocol-controlled funds" in the allowed-impact list. The victim's PC output from `depositPRC20WithAutoSwap` or `refundUnusedGas` is not bounded relative to a fair/TWAP price — only relative to a price the attacker themselves can set immediately beforehand — so losses are not capped at a small percentage; they are capped only by the depth of the pool and the attacker's capital, similar to the unbounded loss described in the source report. This is reachable purely from ordinary user deposit flows (any `GAS`/`GAS_AND_PAYLOAD` inbound, or any outbound with unused gas) and ordinary DEX trading, requiring no privileged validator or TSS behavior — honest validators/relayers processing the vote as normal is sufficient for the attack to succeed.

### Likelihood Explanation
Likelihood is high: triggering a swap against a public AMM pool costs only gas and normal trading fees, is fully permissionless, and inbound/outbound gas-swap events are predictable from mempool/finalization timing (the attacker only needs to see the vote that will cross quorum in the current or next block). There is no incentive misalignment protecting the victim — the "5% slippage" guard is computed from the manipulated quote itself, so it does not meaningfully limit the attacker's extractable value.

### Recommendation
Do not derive `minPCOut` solely from a point-in-time `quoteExactInputSingle` call made within the same execution as the swap. Instead:
- Use a time-weighted average price (TWAP) from the pool (or an independent oracle) as the reference price, and compute `minPCOut` as a bounded slippage off that TWAP rather than off the current spot quote.
- Consider enforcing a maximum per-block price deviation check on the pool before allowing deposit-auto-swap/refund execution, or fall back to a no-swap deposit (already implemented as a fallback path) whenever the spot price deviates significantly from the TWAP.
- Alternatively, size liquidity/slippage bounds to real economic guarantees rather than a fixed 5%, and consider disabling auto-swap on chains without deep, TWAP-resistant liquidity.

### Proof of Concept
A concrete PoC requires a running Push Chain node with the full EVM/Uniswap V3 deployment (`UniversalCore`, `QuoterV2`, WPC, and a PRC20/WPC pool) as configured by `e2e-tests/setup.sh`'s `setup-swap`/`create-pool` steps, plus a controllable inbound-voting harness (as in `test/integration/uexecutor/inbound_cea_gas_and_payload_test.go`). The high-level sandwich sequence to demonstrate the finding:
1. Fund an attacker EOA and provide it a normal Uniswap V3 `SwapRouter` position against the same PRC20/WPC pool `UniversalCore` uses (`GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`).
2. Submit the 3 validator votes needed to bring a large `GAS_AND_PAYLOAD` inbound (see `setupInboundCEAGasAndPayloadTest`) to one vote short of quorum.
3. In the same block, have the attacker swap a large amount of WPC into the pool (or PRC20 out of it) to depress the PRC20→WPC quote.
4. Submit the final validator vote so `gasAndPayloadDepositAutoSwap`/`CallPRC20DepositAutoSwap` executes at the manipulated quote (bounded only by the now-poisoned `minPCOut`).
5. In the same block, have the attacker reverse the swap to restore the pool price, capturing the spread as profit while the UEA/recipient's PRC20 was auto-swapped for materially less PC than fair value.
6. Compare the recipient's PC/WPC balance against a control run without the attacker's sandwich trades to quantify the loss, analogous to the balance deltas Bob suffered in the original report.

I was not able to inspect the actual Solidity source of `UniversalCore.depositPRC20WithAutoSwap`/`refundUnusedGas` or the Uniswap V3 pool/router contracts in this index (they live in a separate contracts repo referenced by `e2e-tests/setup.sh`), so I cannot confirm from code whether any additional protections (e.g., a `deadline`/TWAP check) exist inside the Solidity contract itself beyond the `minPCOut` parameter passed in from the Go keeper. This should be verified directly against the `UniversalCore` and Uniswap V3 contract source before treating the PoC as final.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
