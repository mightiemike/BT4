### Title
Unbounded recursion in `create_bytecode_segment_structure_inner` during Starknet OS re-execution allows stack-overflow crash from a crafted declared class - (File: crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs)

### Summary
`create_bytecode_segment_structure_inner` recursively walks a `NestedIntList` (`bytecode_segment_lengths`) taken from a declared contract's `CasmContractClass` with no recursion-depth bound, unlike the analogous blockifier helper `NestedFeltCounts::new_inner`, which explicitly asserts `segmentation_depth <= 1`. This is directly analogous to CVE-2023-41038 (Firebird `SET BIND` stack corruption): an unbounded/unchecked nested structure derived from user-controlled input drives native recursion until the stack is exhausted, crashing the process instead of failing gracefully.

### Finding Description
`create_bytecode_segment_structure_inner` recurses once per level of nesting in `bytecode_segment_lengths`: [1](#0-0) 

There is no depth check anywhere in this function or in its caller `create_bytecode_segment_structure`: [2](#0-1) 

Contrast this with the blockifier's own analogous recursive builder over the same `NestedIntList` type, which enforces a hard depth limit via an `assert!`: [3](#0-2) 

The `bytecode_segment_lengths` field is part of the `CasmContractClass` that results from compiling a declarer-submitted Sierra program (`crates/apollo_gateway/src/stateless_transaction_validator.rs` validates only overall Sierra program length, class object size, sierra version, and entry-point ordering — not the shape/depth of the eventual compiled bytecode segmentation): [4](#0-3) 

`create_bytecode_segment_structure` is invoked via the `LoadClassesAndBuildBytecodeSegmentStructures` hint while the Starknet OS guesses/loads compiled class facts for every declared class touched in a block, an operation explicitly documented as part of the OS's re-execution/validation flow: [5](#0-4) 

If a declarer submits (or an already-declared) Sierra program whose CASM compilation yields a deeply/artificially nested `bytecode_segment_lengths` (e.g., via a long chain of nested function-call segments within the compiler's normal output structure, bounded only by the allowed bytecode size, currently up to `max_contract_bytecode_size = 81920` felts per `crates/apollo_gateway_config/src/config.rs:196`), every node that runs the Starknet OS over a block containing that class (including the sequencer building the block and any node re-executing/proving it) will recurse without bound in native Rust code, exhausting the thread stack and crashing the process — deterministically and reproducibly on every honest node, since the crash occurs before any resource-metering (Cairo steps/gas) is applied; this is pure native recursion outside the VM's gas-metered execution loop.

### Impact Explanation
A stack overflow in native code causes an unrecoverable process abort (SIGSEGV / stack guard page fault), not a catchable Rust panic. Because every honest node performing OS re-execution/proving over the same block would hit the same crash deterministically, this can halt block finalization/re-execution across the network — a "network unable to confirm new transactions" condition, matching the CVSS 7.5/High characterization of the analogous Firebird issue (crash reachable by any unprivileged user submitting one statement/transaction, no privileges required).

### Likelihood Explanation
Reachable directly from a single `DECLARE` transaction by any account (a declarer), or indirectly via any transaction that invokes/loads an already-declared class with a maliciously shaped compiled class. No special privileges, staking, or operator/peer compromise is required — only crafting a Sierra program whose compiled bytecode segmentation is deeply nested, which is plausible within existing size limits (`max_contract_bytecode_size`) since segmentation depth is not otherwise bounded by any gateway or stateless validation check.

### Recommendation
Add an explicit, config-driven maximum recursion/segmentation depth check in `create_bytecode_segment_structure_inner` (and reject/at minimum return an `OsHintError` instead of recursing further), mirroring the `assert!(segmentation_depth <= 1, ...)` guard already present in `blockifier`'s `NestedFeltCounts::new_inner`. Additionally, consider validating the maximum nesting depth of `bytecode_segment_lengths` as part of stateless/stateful declare-transaction validation in the gateway, before the class is admitted to the mempool/state, so malformed/adversarial segment structures are rejected pre-declaration rather than discovered during OS execution.

### Proof of Concept
Not independently executed (index-based analysis only; no build/runtime environment available). Conceptually: craft a Sierra program that compiles (via the standard Cairo-to-Sierra-to-CASM compiler used by the gateway/class-manager) into a `CasmContractClass` whose `bytecode_segment_lengths` is a `NestedIntList::Node` chain nested to a depth sufficient to exceed the default thread stack size (e.g., tens of thousands of levels, achievable within the 81920-felt bytecode budget by maximizing function/segment nesting). Declare this class, then have any node execute `LoadClassesAndBuildBytecodeSegmentStructures` (Starknet OS re-execution/proving path) over a block referencing it; `create_bytecode_segment_structure_inner` recurses once per nesting level with no depth cap, causing a native stack overflow and process crash.

/// Creates the bytecode segment structure from the given bytecode and bytecode segment lengths.
pub(crate) fn create_bytecode_segment_structure(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
) -> Result<BytecodeSegmentNode, OsHintError> {
    let (structure, total_len) =
        create_bytecode_segment_structure_inner(bytecode, bytecode_segment_lengths, 0);
    // Sanity checks.
    if total_len != bytecode.len() {
        return Err(OsHintError::AssertionFailed {
            message: format!(
                "Invalid length bytecode segment structure: {}. Bytecode length: {}.",
                total_len,
                bytecode.len()
            ),
        });
    }

    Ok(structure)
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }

    /// Recursively builds the nested structure and returns it with the number of items consumed.
    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
    }

    fn validate_sierra_version(
        &self,
        sierra_program: &[Felt],
    ) -> StatelessTransactionValidatorResult<()> {
        // Any patch version is valid. (i.e. when check version for upper bound, we ignore the Z
        // part in a version X.Y.Z).
        let mut max_sierra_version = self.config.max_sierra_version;
        max_sierra_version.0.patch = usize::MAX;

        let sierra_version = VersionId::from_sierra_program(sierra_program)?;
        if self.config.min_sierra_version <= sierra_version && sierra_version <= max_sierra_version
        {
            return Ok(());
        }

        Err(StatelessTransactionValidatorError::UnsupportedSierraVersion {
            version: sierra_version,
            min_version: self.config.min_sierra_version,
            max_version: self.config.max_sierra_version,
        })
    }

    fn validate_class_length(
        &self,
        contract_class: &starknet_api::state::SierraContractClass,
    ) -> StatelessTransactionValidatorResult<()> {
        if contract_class.sierra_program.len() > self.config.max_contract_bytecode_size {
            return Err(StatelessTransactionValidatorError::ContractBytecodeSizeTooLarge {
                contract_bytecode_size: contract_class.sierra_program.len(),
                max_contract_bytecode_size: self.config.max_contract_bytecode_size,
            });
        }

        let contract_class_object_size = serde_json::to_string(&contract_class)
            .expect("Unexpected error serializing contract class.")
            .len();
        if contract_class_object_size > self.config.max_contract_class_object_size {
            return Err(StatelessTransactionValidatorError::ContractClassObjectSizeTooLarge {
                contract_class_object_size,
                max_contract_class_object_size: self.config.max_contract_class_object_size,
            });
        }

        Ok(())
