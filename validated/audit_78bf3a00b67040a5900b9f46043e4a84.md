### Title
Slippage bound for gas-abstraction and refund swaps is derived from a manipulable instantaneous Uniswap V3 quote, enabling sandwich extraction of PRC20/PC value - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
The `GAS`, `GAS_AND_PAYLOAD` inbound execution paths and the outbound gas-refund path all compute a swap's minimum-acceptable-output (`minPCOut`) from `GetSwapQuote`, which calls Uniswap V3 `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96 = 0` against the pool's current instantaneous price — not a time-weighted or otherwise manipulation-resistant price. The resulting `minPCOut` is fixed at 95% of that single-block quote and is then used as the slippage floor for the actual swap executed moments later in the same keeper call (`CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`). An unprivileged external actor who can move the PRC20/WPC pool's spot price in the same block (a standard flash-swap/large-swap technique, exactly analogous to the WETH/LBR balance manipulation in the referenced Lybra finding) can depress the quote just enough that the depressed 95% floor is still satisfied by an equally depressed real swap output, then restore the pool price afterward and capture the difference — extracting value from user/protocol PRC20 or PC (WPC) funds during automatic, validator-triggered inbound gas-swap and outbound refund flows.

### Finding Description
`GetSwapQuote` [1](#0-0)  queries `quoteExactInputSingle` on the configured QuoterV2 with no price limit, which simulates the swap against the pool's *current* reserves/tick, i.e., a spot price that any account can move within the same or an adjacent block via ordinary swap transactions on the same AMM pool — no privileged access, no validator collusion, no oracle compromise required.

This spot quote is used in two production, user-reachable flows:
1. `ExecuteInboundGas` (triggered automatically once validators reach quorum on a `GAS` inbound observation) fetches the quote and computes `minPCOut = quote * 95 / 100`, then immediately calls `CallPRC20DepositAutoSwap` which performs the actual on-chain swap using that `minPCOut` as the only protection against price movement. [2](#0-1) 
2. `applyGasRefund` (triggered on outbound finalization to refund unused gas) performs the identical pattern via `getSwapQuoteForRefund` + `CallUniversalCoreRefundUnusedGas`. [3](#0-2) 
3. The `GAS_AND_PAYLOAD` inbound route (`gasAndPayloadDepositAutoSwap`) uses the exact same quote → 95% floor → swap sequence. [4](#0-3) 

Because the quote is read and the swap is executed within the same keeper invocation (not protected by any commit-reveal, TWAP, or external price oracle), the "protection" band (5% slippage) is computed relative to a price that the attacker controls at the moment of quoting. This is structurally identical to the reported Lybra bug: a value used to gate/bound an economically sensitive outcome is derived from directly-manipulable, single-block AMM state rather than a resistant price source. Where the Lybra bug abused this to bypass a reward-eligibility check, here it is abused to narrow/shift the slippage floor so that a sandwiching attacker can extract the difference between the pool's fair price and the manipulated execution price, at the expense of the UEA recipient (for inbound gas swaps) or the refund recipient (for outbound refunds) — i.e., PRC20/PC (WPC) value that should have gone to the user is siphoned to the attacker.

Note that elsewhere in the codebase, the chain-meta gas-price oracle correctly aggregates multiple validators' observations via a median [5](#0-4)  to resist manipulation — but the swap-quote path used for `minPCOut` does not receive equivalent manipulation resistance.

### Impact Explanation
This falls within "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting... or canonical UniversalTx state" and "draining... of user or protocol-controlled funds," reachable purely through ordinary, unprivileged interaction with the public Uniswap V3 pool that backs PRC20↔WPC swaps, combined with the automatic, validator-triggered (not attacker-gated) execution of inbound gas processing and outbound refunds. The attacker does not need to compromise any validator, TSS participant, or admin key — only to trade against the same AMM pool the protocol uses for its swap quote, within the same block window as the deposit/refund execution.

### Likelihood Explanation
Likelihood depends on: (a) the depth/liquidity of the specific PRC20/WPC Uniswap V3 pool (thinner pools, as seen in local test pool setups with very small notional liquidity, are cheaper to move) [6](#0-5) , and (b) whether the attacker can predict/observe when an inbound `GAS`/`GAS_AND_PAYLOAD` execution or outbound refund will land in the same block. Since inbound/outbound execution is deterministic once quorum/finalization conditions are met (mempool-visible or predictable from prior votes), and pool interactions are permissionless, this is realistically exploitable on any PRC20/WPC pool with moderate-to-low liquidity relative to the swap size being processed.

### Recommendation
Do not derive `minPCOut` from a single, same-block spot quote. Use a manipulation-resistant reference price for the slippage floor, such as: a time-weighted average price (TWAP) from the Uniswap V3 pool's oracle observations over a sufficiently long window, or the same validator-aggregated median mechanism already used for chain-meta gas prices, and/or bound the acceptable deviation between the instantaneous quote and that reference price before allowing the swap to proceed (revert instead of swapping into a stale/manipulated instantaneous rate).

### Proof of Concept
1. Attacker identifies a PRC20/WPC Uniswap V3 pool with an inbound `GAS` or `GAS_AND_PAYLOAD` transaction pending quorum finalization (predictable since votes are on-chain and visible before the final quorum vote lands).
2. In the same block (or immediately preceding the finalization tx), attacker submits a large swap against the PRC20/WPC pool to depress the pool's instantaneous price in the direction that lowers `quoteExactInputSingle`'s output for `prc20 → wpc`.
3. `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` calls `GetSwapQuote` [1](#0-0)  against the now-depressed pool, computing a depressed `minPCOut = quote * 95 / 100` [7](#0-6) .
4. `CallPRC20DepositAutoSwap` executes the real swap against the still-depressed pool, satisfying the depressed `minPCOut` easily, delivering fewer WPC tokens to the UEA recipient than fair value.
5. Attacker reverses their initial swap, restoring the pool price and capturing the spread as profit, at the expense of the UEA recipient/protocol.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
