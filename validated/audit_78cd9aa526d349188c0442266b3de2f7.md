### Title
`library_call` syscall bypasses the `Validate`-mode "no external calls" restriction enforced on `call_contract` - (File: crates/blockifier/src/execution/syscalls/hint_processor.rs)

### Summary
During the `__validate__` phase of a transaction, the blockifier explicitly restricts the `call_contract` syscall so that an account can only call itself, preventing account validation logic from depending on arbitrary external contract state. The `library_call` syscall — the Starknet analog of EVM `delegatecall`, which executes another class's bytecode in the caller's own storage/caller context — has no such restriction, allowing a malicious account's `__validate__` to execute the code of *any* already-declared class on the network, completely bypassing the intended sandbox, exactly mirroring the GuardCM `delegatecall` bypass pattern from the reference report.

### Finding Description
In `SyscallExecutor::call_contract` for both the current and deprecated syscall handlers, the code explicitly enforces that during `ExecutionMode::Validate` the target of a `call_contract` must be the calling contract itself: [1](#0-0) [2](#0-1) 

Other read syscalls that could leak block/external state are unconditionally rejected in validate mode via `reject_syscall_in_validate_mode` / `verify_not_in_validate_mode`, e.g. `get_class_hash_at`: [3](#0-2) [4](#0-3) 

This is confirmed by the test suite, which asserts calling any address other than self is forbidden during validation: [5](#0-4) 

However, the `library_call` implementations — which behave like `delegatecall` (same `storage_address`/`caller_address`, but arbitrary `class_hash` supplied directly by the caller) — contain **no `is_validate_mode`/`reject_syscall_in_validate_mode` check at all**, in any of the three syscall backends: [6](#0-5) [7](#0-6) [8](#0-7) 

Because `library_call` takes a `class_hash` directly (bypassing the need for the blocked `get_class_hash_at` lookup) and preserves `storage_address`/`caller_address`, an account's `__validate__` entry point can trivially execute the code of *any other already-declared class* on the network — logic entirely foreign to the account's own declared class — while retaining write access to the account's own storage. This is the precise structural analog of the GuardCM bug: a restriction (`call to arbitrary targets is blocked`) is enforced on one call primitive (`Call`/`call_contract`) but not on the functionally-equivalent alternate primitive (`Delegate`/`library_call`), fully defeating the sandbox's purpose.

### Impact Explanation
The `Validate`-execution-mode restrictions exist specifically to keep an account's `__validate__` self-contained and to prevent transaction validity from depending on external, mutable state — this protects the mempool/gateway and the sequencer's block-building (bouncer) pipeline from transactions that pass cheap validation but behave differently (or fail) at inclusion time, and prevents validation-time griefing/DoS of the sequencer. By using `library_call`, any account contract's `__validate__` can execute arbitrary already-declared class logic under its own address/storage, completely defeating this invariant. This can be leveraged by an unprivileged transaction sender who deploys/declares a colluding account to make validation nondeterministic/state-manipulating in ways the sequencer's design explicitly forbids, undermining mempool admission guarantees and potentially enabling resource-exhaustion or admission-vs-execution divergence attacks against the sequencer — a network-level availability/soundness concern rather than a "no-impact" gap.

### Likelihood Explanation
This is reachable by any unprivileged user: declaring/deploying a custom account class and issuing an ordinary `INVOKE`/validation flow is a standard, permissionless action. No special privileges, node control, or p2p/protocol-level access is required — only a self-authored account contract calling the `library_call` syscall from `__validate__`, which is a completely standard Cairo capability.

### Recommendation
Apply the same `Validate`-mode restriction used for `call_contract` to `library_call` (and `library_call_l1_handler`) in all three backends (`crates/blockifier/src/execution/syscalls/hint_processor.rs`, `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`, `crates/blockifier/src/execution/native/syscall_handler.rs`): either unconditionally reject `library_call` during `ExecutionMode::Validate` (consistent with `get_class_hash_at`/`deploy`/`get_block_hash`), or restrict the supplied `class_hash` to the account's own currently-assigned class hash, matching the "self only" intent already implemented for `call_contract`.

### Proof of Concept
1. Declare and deploy a malicious account contract `A` whose `__validate__` calls the `library_call` syscall with the `class_hash` of an arbitrary, unrelated already-declared class `B` (not `A`'s own class), passing a selector/calldata designed to perform heavy computation, write to `A`'s storage, or branch based on complex logic unrelated to signature checking.
2. Submit an `INVOKE` transaction from `A`. During `perform_validations`/`validate_tx`, the syscall executor processes the `library_call`, and since no `is_validate_mode` check exists (contrast with `call_contract`'s explicit self-only enforcement shown at `hint_processor.rs:530-538`), the call succeeds and executes `B`'s bytecode under `A`'s address/storage.
3. Compare with an equivalent attempt using `call_contract` to `B`'s address instead of `A`'s own address — this fails with `"Unauthorized syscall call_contract in execution mode Validate."` as demonstrated by the existing test at `crates/blockifier/src/transaction/transactions_test.rs:2467-2494`, confirming `library_call` is the unguarded bypass path.

    fn library_call(
        request: LibraryCallRequest,
        vm: &mut VirtualMachine,
        syscall_handler: &mut Self,
        remaining_gas: &mut u64,
    ) -> Result<LibraryCallResponse, Self::Error> {
        let entry_point = CallEntryPoint {
            class_hash: Some(request.class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: request.function_selector,
            calldata: request.calldata,
            // The call context remains the same in a library call.
            storage_address: syscall_handler.storage_address(),
            caller_address: syscall_handler.caller_address(),
            call_type: CallType::Delegate,
            // NOTE: this value might be overridden later on.
            initial_gas: *remaining_gas,
        };

        let retdata_segment = execute_inner_call(entry_point, vm, syscall_handler, remaining_gas)
            .map_err(|error| match error {
            SyscallExecutionError::Revert { .. } => error,
            _ => error.as_lib_call_execution_error(
                request.class_hash,
                syscall_handler.storage_address(),
                request.function_selector,
            ),
        })?;

        Ok(LibraryCallResponse { segment: retdata_segment })
    }

    pub fn get_class_hash_at(
        &mut self,
        contract_address: ContractAddress,
    ) -> SyscallResult<ClassHash> {
        if self.context.execution_mode == ExecutionMode::Validate {
            self.reject_syscall_in_validate_mode("get_class_hash_at")?;
        }

        self.storage_access_tracker.accessed_contract_addresses.insert(contract_address);
        let class_hash = self.state.get_class_hash_at(contract_address)?;
        self.storage_access_tracker.read_class_hash_values.push(class_hash);
        Ok(class_hash)
    }

    fn library_call(
        &mut self,
        class_hash: Felt,
        function_selector: Felt,
        calldata: &[Felt],
        remaining_gas: &mut u64,
    ) -> SyscallResult<Vec<Felt>> {
        self.pre_execute_syscall(
            remaining_gas,
            self.gas_costs().syscalls.library_call.base_syscall_cost(),
            SyscallSelector::LibraryCall,
        )?;

        let class_hash = ClassHash(class_hash);

        let wrapper_calldata = Calldata(Arc::new(calldata.to_vec()));

        let selector = EntryPointSelector(function_selector);

        let entry_point = CallEntryPoint {
            class_hash: Some(class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector,
            calldata: wrapper_calldata,
            // The call context remains the same in a library call.
            storage_address: self.base.call.storage_address,
            caller_address: self.base.call.caller_address,
            call_type: CallType::Delegate,
            initial_gas: *remaining_gas,
        };

        let error_wrapper_function =
            |e: SyscallExecutionError,
             class_hash: ClassHash,
             storage_address: ContractAddress,
             selector: EntryPointSelector| {
                e.as_lib_call_execution_error(class_hash, storage_address, selector)
            };

        Ok(self
            .execute_inner_call(entry_point, remaining_gas, class_hash, error_wrapper_function)?
            .0)
    }
