### Title
Unbounded recursive `serde_json::Value` deserialization of deprecated (Cairo0) `Program` fields allows stack-overflow DoS via a malicious `DECLARE` transaction - (File: `crates/starknet_api/src/deprecated_contract_class.rs`)

### Summary
The `Program` struct used for Cairo0 ("deprecated") contract classes stores several fields (`attributes`, `data`, `debug_info`, `hints`, `identifiers`, `reference_manager`, etc.) as raw `serde_json::Value`, deserialized directly from attacker-supplied JSON via `#[derive(Deserialize)]`. [1](#0-0) 
`serde_json::Value`'s deserializer recurses once per nested array/object with no depth limit, which is exactly the bug class in CVE-2020-9861 (Swift `JSONSerialization` stack overflow on deeply nested JSON). A contract-declarer submitting a `DECLARE` (v1/v2) transaction with a `contract_class.program` containing deeply nested JSON in any of these fields (e.g., `identifiers` or `hints` nested thousands of levels deep) can trigger unbounded stack recursion in the node process handling the transaction.

### Finding Description
`starknet_api::deprecated_contract_class::Program` is the deserialization target for the Cairo0 `contract_class.program` in `DECLARE` transactions accepted both by the JSON-RPC write API (`BroadcastedDeclareV1Transaction.contract_class: DeprecatedContractClass`, see `crates/apollo_rpc/src/v0_8/broadcasted_transaction.rs:70-79`) and by the legacy gateway/starknet-client transaction path (`crates/apollo_starknet_client/src/writer/objects/transaction.rs:202-212`). [2](#0-1) 

Its fields are declared as opaque `serde_json::Value` precisely because the gateway does not want to interpret their structure before hashing/compiling: [1](#0-0) 

`serde_json::Value`'s `Deserialize` implementation is a classic recursive-descent parser: for every nested JSON array or object it recurses into the inner deserializer. There is no configured recursion-depth guard anywhere along this path (unlike, e.g., `apollo_compilation_utils`/gateway paths for Sierra classes, which enforce byte-size limits via `decode_and_decompress_with_size_limit`, but that only bounds total bytes, not nesting depth — a small payload can still have very deep nesting, e.g. `[[[[[...]]]]]` costs 2 bytes per nesting level). Once this JSON reaches `serde_json::from_str`/`from_slice`/`from_value` (used throughout, e.g. `sn_api_to_cairo_vm_program` in `crates/blockifier/src/execution/execution_utils.rs:240-269`, and `compute_cairo_hinted_class_hash` in `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs:154-185`), the recursive parser will blow the thread stack for sufficiently deep nesting, aborting the process (Rust stack overflow is not catchable — it aborts the process, not a recoverable panic).

This differs from the already-mitigated Sierra program stack-overflow class: the sequencer explicitly tests and defends against *execution-time* Cairo recursion (via `RecursionDepthGuard`, `max_recursion_depth`, gas-bounded VM recursion) as seen in `crates/blockifier/src/execution/entry_point.rs:706-733` and the dedicated `test_recursion_depth_exceeded`/`test_stack_overflow` tests. However, no equivalent protection exists for *deserialization-time* recursion of attacker-controlled JSON values embedded in a Cairo0 `Program`.

### Impact Explanation
A stack overflow in Rust aborts the process (SIGABRT/SIGSEGV) — it is not a recoverable error. If the gateway, RPC node, or any batcher/mempool component parses the malicious `contract_class.program` JSON before rejecting the transaction (validation, hashing, or forwarding to storage/blockifier all call into `serde_json::from_value`/`from_str` on these fields), the process crashes. If this deserialization occurs on the sequencer/gateway service handling transaction submission, a single crafted transaction from an unprivileged sender can crash the node process, potentially repeatable against multiple/all gateway or RPC replicas, leading to denial of service — a network unable to confirm new transactions.

### Likelihood Explanation
Likelihood is high for an attacker: constructing deeply nested JSON is trivial and cheap (a few KB of `[` characters can nest to depths well beyond the default OS thread stack, e.g., 100k+ levels), and the fields (`identifiers`, `hints`, `attributes`, `reference_manager`) impose no schema/depth validation before being parsed as generic `Value`. The transaction only needs to pass generic HTTP/JSON-RPC body parsing to reach `serde_json::Value` deserialization of the nested `Program` fields; no signature check gates this recursive parse, since the outer struct itself must be deserialized (which recursively deserializes the nested `Value` fields) before signature verification logic can even run.

### Recommendation
- Add explicit recursion/depth limits when deserializing untrusted JSON into `serde_json::Value` for the deprecated `Program` fields (e.g., use a custom `Deserializer` wrapper enforcing a maximum nesting depth, or a bounded-depth JSON parser) before accepting a `DECLARE` transaction.
- Alternatively (or additionally), run the initial deserialization of `contract_class.program` in a dedicated, size-and-depth-bounded parsing step with `#[serde(deserialize_with = ...)]`, similar to how `sierra_program` size is already bounded via `decode_and_decompress_with_size_limit` in `crates/starknet_api/src/compression_utils.rs`.
- Consider running gateway-side JSON parsing of transaction bodies with a bounded stack/guard thread so a stack overflow in a worker is contained rather than crashing the whole process (defense in depth), or reject inputs whose raw JSON exceeds a conservative bracket/brace-nesting count via a cheap pre-scan before full deserialization.

### Proof of Concept
1. Craft a `DECLARE` v1/v2 JSON-RPC request (`starknet_addDeclareTransaction`) or legacy gateway `DECLARE` transaction whose `contract_class.program.identifiers` (or `.hints`, `.attributes`, `.reference_manager`) field is a deeply nested JSON array, e.g. `"identifiers": [[[[[ ... ]]]]]` nested to a depth of ~200,000 (a few hundred KB payload, well under any max-request-size limit).
2. Submit the request to the gateway/RPC endpoint (`starknet_addDeclareTransaction` handler in `crates/apollo_rpc/src/v0_8/api/mod.rs`, or the legacy `DeprecatedGatewayDeclareTransaction` path in `crates/apollo_http_server`).
3. `serde_json`'s recursive `Value` deserializer recurses once per array/object nesting level while parsing the request body; at sufficient depth this exhausts the thread's stack and aborts the process handling the request, before any signature or fee validation logic executes. pub fn sn_api_to_cairo_vm_program(program: DeprecatedProgram) -> Result<Program, ProgramError> {
    let identifiers = serde_json::from_value::<HashMap<String, Identifier>>(program.identifiers)?;
    let builtins = serde_json::from_value(program.builtins)?;
    let data = deserialize_array_of_bigint_hex(program.data)?;
    let hints = serde_json::from_value::<HashMap<usize, Vec<HintParams>>>(program.hints)?;
    let main = None;
    let error_message_attributes = match program.attributes {
        serde_json::Value::Null => vec![],
        attributes => serde_json::from_value::<Vec<Attribute>>(attributes)?
            .into_iter()
            .filter(|attr| attr.name == "error_message")
            .collect(),
    };

    let instruction_locations = None;
    let reference_manager = serde_json::from_value::<ReferenceManager>(program.reference_manager)?;

    let program = Program::new(
        builtins,
        data,
        main,
        hints,
        reference_manager,
        identifiers,
        error_message_attributes,
        instruction_locations,
    )?;

    Ok(program)
}
