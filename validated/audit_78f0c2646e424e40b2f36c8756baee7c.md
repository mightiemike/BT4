### Title
Recursion-depth check is bypassed on every repeated `group` field, allowing unbounded recursive `Unmarshal` calls and a stack-overflow crash - (File: internal/impl/codec_field.go)

### Summary
`proto.Unmarshal` enforces a recursion-depth counter (`protowire.DefaultRecursionLimit`) that is threaded through `unmarshalOptions.depth` and decremented on every nested message in `mi.unmarshalPointer` [1](#0-0) . However, when decoding a **repeated `group`-encoded field**, `consumeGroupSlice` re-enters the top-level decoder through `opts.Options().UnmarshalState(...)` [2](#0-1) . `unmarshalOptions.Options()` builds a fresh `proto.UnmarshalOptions` that never copies the current recursion budget (`depth`) [3](#0-2) , so `RecursionLimit` is `0`. `proto.UnmarshalOptions.UnmarshalState` then treats `0` as "unset" and resets it to the full `protowire.DefaultRecursionLimit` [4](#0-3) . As a result, every time decoding crosses a repeated-group boundary the recursion counter is silently restored to its maximum value, so the depth check never fires no matter how deeply the message is nested, while the real Go call stack keeps growing with each recursive `unmarshalPointer` → field-coder → `consumeGroupSlice` → `UnmarshalState` → `unmarshalPointer` cycle.

### Finding Description
The intended invariant, mirrored in every other decode path (`protojson`, `prototext`, `proto.unmarshalMessageSlow`, `mi.unmarshalPointer`), is "recursion depth must monotonically decrease across the whole call graph, and unmarshal must fail once the limit is exhausted" [1](#0-0) [5](#0-4) . This is enforced correctly for ordinary singular/repeated message fields and for the direct group unmarshal path used by singular `group` fields, which calls `consumeGroup` while preserving `opts` (and thus `opts.depth`) unchanged [6](#0-5) .

The broken invariant is specific to **repeated** `group` fields (`consumeGroupSlice`). Instead of reusing the caller's `unmarshalOptions` (which carries the decremented `depth`), it converts to `proto.UnmarshalOptions` via `Options()` and calls `UnmarshalState`, entering the top-level `proto.UnmarshalOptions.unmarshal` state machine again [7](#0-6) . Because `Options()` never sets `RecursionLimit`, and `UnmarshalState`/`unmarshal` treat `RecursionLimit == 0` as "use the default" [4](#0-3) [8](#0-7) , the freshly computed `in.Depth = o.RecursionLimit` handed to `methods.Unmarshal` is always `protowire.DefaultRecursionLimit`, completely discarding how many levels of recursion already occurred in the outer call chain.

An attacker who controls the wire bytes for a schema containing a self-referential `repeated group` field (a legitimate proto2 feature the trusted schema owner may define, e.g. `repeated group Node = N { ... }` referencing itself) can nest that group field arbitrarily deep. At every nesting hop the recursion-limit check is satisfied trivially because it always sees a "fresh" budget, so `proto.Unmarshal`/`proto.UnmarshalOptions.Unmarshal` on this trusted message type never returns the `"exceeded maximum recursion depth"` error, while the real Go call stack (`unmarshalPointer` → `unmarshalPointerEager` → group field coder → `consumeGroupSlice` → `Options().UnmarshalState` → `unmarshal` → `methods.Unmarshal` → `unmarshalPointer` …) grows by a full cycle of stack frames per input group level.

### Impact Explanation
This is the same bug class as CVE-2020-11647: a recursion-limiting mechanism that fails to bound actual recursive descent for a specific field/dissector-state combination, allowing a remote, unprivileged, well-formed (schema-valid) message to drive unbounded recursion and crash the process (`fatal error: stack overflow`, unrecoverable via `recover()`), i.e., a Denial of Service against any Go service that calls `proto.Unmarshal`/`proto.UnmarshalOptions.Unmarshal` on attacker-controlled bytes for a message type with a repeated `group` field that is directly or transitively self-referential. This affects availability (`CVSS AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H`), matching the referenced advisory's impact.

### Likelihood Explanation
Requires only: (1) a trusted `.proto` schema that declares a `repeated group` field which is self-referential (directly or through a cycle of message types) — a standard, unremarkable proto2 pattern still supported by protobuf-go for legacy compatibility, and (2) an endpoint that unmarshals unprivileged/untrusted binary bytes into that message with the default binary decoder — the most common, default protobuf-go usage. No malicious peer schema, custom resolver, or descriptor injection is needed; only the wire bytes are attacker-controlled.

### Recommendation
In `consumeGroupSlice` (and any other call sites using `unmarshalOptions.Options()` to re-enter the top-level `proto.UnmarshalOptions` state machine), propagate the current recursion budget instead of letting it reset. Concretely:
- Extend `internal/impl/decode.go`'s `unmarshalOptions.Options()` to carry `depth` into `proto.UnmarshalOptions.RecursionLimit` (mapping `0`/exhausted state unambiguously, e.g. by reserving a sentinel or by not special-casing `RecursionLimit == 0` as "unset").
- Alternatively, have `consumeGroupSlice` decrement/check `opts.depth` itself (as `mi.unmarshalPointer` does) before calling into `UnmarshalState`, and pass the remaining depth explicitly through `protoiface.UnmarshalInput.Depth`, ensuring `proto.UnmarshalOptions.unmarshal` honors an already-provided `Depth` from `UnmarshalState`'s caller rather than recomputing it solely from `o.RecursionLimit`.

### Proof of Concept
```go
package main

import (
	"fmt"

	"google.golang.org/protobuf/encoding/protowire"
	"google.golang.org/protobuf/proto"
	// mygroup.Node is a proto2 message with:
	//   optional group Child = 1 { repeated group Child = 1 {...} }
	// i.e. field 1 is a self-referential "repeated group".
)

func buildNestedGroup(depth int, fieldNum protowire.Number) []byte {
	var b []byte
	// Build innermost group first, then wrap.
	inner := []byte{}
	for i := 0; i < depth; i++ {
		b = protowire.AppendVarint(nil, protowire.EncodeTag(fieldNum, protowire.StartGroupType))
		b = append(b, inner...)
		b = protowire.AppendVarint(b, protowire.EncodeTag(fieldNum, protowire.EndGroupType))
		inner = b
	}
	return inner
}

func main() {
	// depth chosen large enough to overflow the Go goroutine stack
	// (each level costs several real stack frames via
	// unmarshalPointer -> field coder -> consumeGroupSlice ->
	// Options().UnmarshalState -> unmarshal -> methods.Unmarshal).
	payload := buildNestedGroup(2_000_000, 1)

	msg := &mygroup.Node{}
	err := proto.Unmarshal(payload, msg) // expected: "exceeded maximum recursion depth"
	fmt.Println(err)                     // observed: process crashes with
	                                      // "fatal error: stack overflow" before returning
}
```
Because `consumeGroupSlice` resets the recursion budget to `protowire.DefaultRecursionLimit` on every group boundary [7](#0-6)  via `Options()`/`UnmarshalState`'s zero-value reset logic [3](#0-2) [4](#0-3) , `proto.Unmarshal` never returns the recursion-limit error for deeply nested repeated-group input and instead exhausts the goroutine's stack, crashing the process.

func consumeGroupSlice(b []byte, p pointer, num protowire.Number, wtyp protowire.Type, goType reflect.Type, opts unmarshalOptions) (out unmarshalOutput, err error) {
	if wtyp != protowire.StartGroupType {
		return out, errUnknown
	}
	b, n := protowire.ConsumeGroup(num, b)
	if n < 0 {
		return out, errDecode
	}
	mp := reflect.New(goType.Elem())
	o, err := opts.Options().UnmarshalState(protoiface.UnmarshalInput{
		Buf:     b,
		Message: asMessage(mp).ProtoReflect(),
	})
	if err != nil {
		return out, err
	}
	p.AppendPointerSlice(pointerOfValue(mp))
	out.n = n
	out.initialized = o.Flags&protoiface.UnmarshalInitialized != 0
	return out, nil
}
