### Title
Spot-price swap quote with fixed 5% slippage tolerance in inbound gas auto-swap allows sandwich extraction of user deposit value - (File: x/uexecutor/keeper/evm.go)

### Summary
The `GAS` and `GAS_AND_PAYLOAD` inbound execution paths convert a user's bridged gas-token PRC20 into native PC by calling `GetSwapQuote` (a static, single-block Uniswap V3 `QuoterV2.quoteExactInputSingle` read) and then immediately executing the real swap via `CallPRC20DepositAutoSwap`, bounding the output only by a hardcoded `minPCOut = quote * 95 / 100`. The same pattern is reused for the outbound excess-gas refund swap (`applyGasRefund` → `getSwapQuoteForRefund` → `CallUniversalCoreRefundUnusedGas`). Because the quote is a spot read of the on-chain WPC/PRC20 pool taken in the same keeper invocation that the swap executes in, and the tolerance is a fixed 5% regardless of pool depth, any user who can get a manipulating transaction ordered immediately before the inbound-triggered swap (a routine, unprivileged sandwich against a shallow AMM pool) can force the module to consume the depositor's tokens at a distorted price and capture the difference — the same "unbalanced/pmm-style pricing assumed safe at deposit time" root cause as the original Abracadabra finding, just expressed against a Uniswap V3 spot quote instead of a PMM bonding curve.

### Finding Description
`GetSwapQuote` in [1](#0-0)  performs a non-committing `CallEVM` to `QuoterV2.quoteExactInputSingle`, which returns the amount computable from the pool's *current* tick/liquidity state — i.e. a spot price, not a TWAP or otherwise manipulation-resistant oracle.

Both inbound gas-handling paths compute `minPCOut` directly from that spot quote with a fixed percentage haircut: [2](#0-1) [3](#0-2) 

and then submit the real swap in the very same function call via `CallPRC20DepositAutoSwap`: [4](#0-3) 

The identical quote→swap pattern with the same fixed 5% tolerance is reused for excess-gas refunds: [5](#0-4) [6](#0-5) 

Since the swap is executed against a live, attacker-reachable Uniswap V3 pool whose price can be perturbed by ordinary user swap transactions ordered ahead of the module's deposit-triggered transaction within the same block (a well-understood, unprivileged sandwich pattern; no validator or governance collusion is required — only transaction ordering that any user can attempt against a Cosmos/EVM mempool), the "protection" degenerates to a static ±5% band around a price the attacker just set. This mirrors the underlying invariant break in the source report: a pricing computation trusted as safe (there, `buyShares`' initial target/reserve split; here, a single-block spot quote) is not actually protected against attacker-influenced state, and the resulting swap/mint math silently misprices real user funds. E2E tooling in this same repo shows the WPC pools it seeds are intentionally shallow (e.g. `pool_token_amount=1`, `pool_wpc_amount=4`, or `50`/`200` for pSOL — [7](#0-6) ), which is exactly the low-liquidity condition under which a fixed 5% band is trivially breached by a modest attacker trade.

### Impact Explanation
Every `GAS` / `GAS_AND_PAYLOAD` inbound (real user gas top-ups bridged from external chains) and every outbound excess-gas refund routes PRC20→PC value through this quote-then-swap sequence. An attacker who sandwiches the module's swap can extract value directly from the user's bridged principal or from the protocol-held gas token being refunded — a direct "unauthorized... loss" of user/protocol-controlled funds executed through the in-scope `x/uexecutor` universal execution path, without requiring any privileged role.

### Likelihood Explanation
Likelihood depends on: (1) how thin the live WPC/PRC20 pool is (repo's own local setup deliberately seeds very shallow pools), and (2) whether an attacker can get a swap transaction ordered immediately ahead of the module's derived swap within the same block. Because pchaind is EVM-integrated (cosmos-evm), ordinary EVM transactions are gas-price-ordered in the block, giving unprivileged users a realistic (not validator-privileged) lever to influence intra-block ordering relative to the module's derived call. This makes exploitation plausible on any chain/token pair whose on-chain liquidity is not deep relative to typical deposit sizes, which is explicitly the deployment pattern shown in this repository's own tooling.

### Recommendation
- Do not derive `minPCOut` solely from a same-block spot `quoteExactInputSingle` call; use a TWAP-based or multi-block reference price, or clamp against a governance-configured maximum price-impact bound tied to actual pool liquidity rather than a flat 95%.
- Consider widening/enforcing a liquidity-depth check before auto-swapping (skip or fall back to no-swap deposit, as the refund path already does on `swapErr`) when the quoted amount implies price impact beyond a safe threshold for the trade size.
- Where possible, execute quote and swap with a bound on maximum allowable slippage that scales inversely with trade size relative to pool reserves, rather than a constant percentage.

### Proof of Concept
1. Observe (or wait for) a pending inbound of `TxType_GAS` or `GAS_AND_PAYLOAD` that will trigger `ExecuteInboundGas` / `ExecuteInboundGasAndPayload` once UV quorum is reached ( [8](#0-7) ).
2. Submit an EVM transaction with a competitive gas price that swaps a large amount of the same PRC20↔WPC pair on the Uniswap V3 pool immediately ahead of the vote-finalizing transaction, moving the pool's spot price unfavorably for the token being auto-swapped (up to just under whatever the 5% band on the *new* price will tolerate).
3. Let the module's `GetSwapQuote`/`CallPRC20DepositAutoSwap` execute against the now-skewed pool state — `minPCOut` is computed off the already-manipulated price, so the module's swap fully executes at the bad price and mints/sends less PC to the user's UEA than the honest market rate.
4. Submit a follow-up transaction reversing the attacker's initial swap, realizing the price-impact profit while the depositor's funds absorbed the loss.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// getSwapQuoteForRefund fetches a Uniswap quote for the gas token refund swap.
func (k Keeper) getSwapQuoteForRefund(ctx sdk.Context, gasToken common.Address, fee *big.Int, amount *big.Int) (*big.Int, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(ctx)
	if err != nil {
		return nil, err
	}
	wpcAddr, err := k.GetUniversalCoreWPCAddress(ctx)
	if err != nil {
		return nil, err
	}
	return k.GetSwapQuote(ctx, quoterAddr, gasToken, wpcAddr, fee, amount)
}
