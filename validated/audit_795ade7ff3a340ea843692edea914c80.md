### Title
Liquidation pause check only inspects `debt-aid`, letting per-asset pauses on collateral be bypassed - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`liquidate` in `v0-4-market.clar` enforces the liquidation pause/grace-period mechanism by calling `is-liquidation-paused` with only the **debt** asset id. The DAO-controlled per-asset pause map (`liquidation-grace-periods`), however, can be set for *any* asset id, including assets that are used purely as collateral. When the DAO pauses liquidations on a collateral-only asset (e.g. to protect users during an oracle incident on that asset), the pause is silently ignored by `liquidate` because the code never checks the collateral asset's pause/grace state.

### Finding Description
`is-liquidation-paused` computes pause status from a global manual flag, a global grace window, and an **asset-specific** grace window keyed by an arbitrary `asset-id`: [1](#0-0) 

The DAO sets this per-asset pause/grace value through `set-liquidation-grace-period`, which accepts any `id` — there is no restriction that `id` must be a debt-enabled asset; it can be any registered asset, including a collateral-only one: [2](#0-1) 

In `liquidate`, the pause check is invoked with `debt-aid` exclusively: [3](#0-2) 

and the collateral asset id (`coll-aid`) used elsewhere in the same function is never passed to `is-liquidation-paused`: [4](#0-3) 

Because the collateral asset's own grace-period entry is never consulted, a DAO pause intended to stop liquidations of positions collateralized by a specific (e.g. price-compromised) asset has no effect: liquidators can still seize that collateral by choosing any *other, unpaused* debt asset as the `debt-ft` argument. The guard exists (`asserts! (not (is-liquidation-paused debt-aid)) ...`) but it checks the wrong/incomplete set of asset ids, so the pause "passes through" for the collateral side.

### Impact Explanation
This allows liquidators to seize collateral of an asset the DAO explicitly intended to shield from liquidation (typically because its oracle price is stale, manipulated, or under incident review). Liquidation executed against a bad/stale collateral price directly transfers user collateral to the liquidator at an incorrect valuation — this is theft of user funds at rest, matching the Critical impact class (direct theft of user funds / protocol insolvency risk from mispriced collateral seizure), since the very reason for pausing that asset (unreliable price) is what enables the unjust liquidation.

### Likelihood Explanation
This requires no privileged access from the attacker: the DAO must have paused liquidations on a collateral asset via `set-liquidation-grace-period`, and any user/liquidator holding a position collateralized by that asset with debt in a different, unpaused asset can be liquidated (or self-liquidated by a colluding liquidator) despite the pause. Given that per-asset pauses are a documented governance tool for handling oracle incidents, and the omission is a straightforward code-path gap (not requiring any exotic setup), likelihood is moderate-to-high whenever the per-asset pause feature is actually exercised for a collateral-only asset.

### Recommendation
`is-liquidation-paused` should be checked (or the check extended) for **both** `coll-aid` and `debt-aid` in `liquidate` (and in the batch helper `call-liquidate`), e.g.:
```clarity
(asserts! (not (is-liquidation-paused coll-aid)) ERR-LIQUIDATION-PAUSED)
(asserts! (not (is-liquidation-paused debt-aid)) ERR-LIQUIDATION-PAUSED)
```
This ensures a DAO-initiated pause on any asset involved in the liquidation — whether as collateral or debt — is actually enforced.

### Proof of Concept
1. DAO detects an oracle/price issue on asset `X` (used by many users as collateral) and calls `set-liquidation-grace-period X-aid <period>` to pause liquidations touching `X`. [2](#0-1) 
2. A borrower `B` holds `X` as collateral and USDC as debt.
3. A liquidator calls `liquidate` with `collateral-ft = X`, `debt-ft = USDC`.
4. Inside `liquidate`, `coll-aid` is derived from `X` but only `debt-aid` (USDC's id) is passed to `is-liquidation-paused`: [4](#0-3) [3](#0-2) 
5. Since USDC's grace period is not active, `is-liquidation-paused debt-aid` returns `false`, and the liquidation proceeds — seizing `X` collateral — despite the DAO's explicit pause on `X`.

(define-private (is-liquidation-paused (asset-id uint))
  (let ((manual-pause (var-get pause-liquidation))
        (global-grace-end (default-to u0 (map-get? liquidation-grace-periods GLOBAL-LIQUIDATION-GRACE-ID)))
        (asset-grace-end (default-to u0 (map-get? liquidation-grace-periods asset-id)))
        (global-grace-active (< stacks-block-time global-grace-end))
        (asset-grace-active (< stacks-block-time asset-grace-end)))
