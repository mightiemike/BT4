## Finding

### Title
Front-runnable UEA signature consumption forces reverts of batched `MsgExecutePayload`/`MsgMigrateUEA` bundles - (File: x/uexecutor/keeper/msg_execute_payload.go, x/uexecutor/keeper/evm.go, app/txpolicy/gasless.go)

### Summary
`MsgExecutePayload` and `MsgMigrateUEA` are gasless, permissionless-relay messages whose authorization is a single-use, nonce-bound signature (`VerificationData`/`Signature`) checked entirely inside the target UEA's EVM contract (`executeUniversalTx`/`migrateUEA`), not by the Cosmos module itself. Because these UEA contract functions are ordinary public Solidity functions deployed on Push Chain's EVM, any external account can call them directly with the same `(payload, signature)` pair once it is visible in the mempool as `MsgExecutePayload`/`MsgMigrateUEA` calldata. This is structurally identical to Angstrom's `PermitSubmitterHook` bug: `permit()` is callable by anyone, so front-running it consumes the nonce and forces the hook's later `permit()` call to revert.

### Finding Description
`MsgExecutePayload`/`MsgMigrateUEA` are both gasless message types [1](#0-0) , and the gasless policy explicitly allows them to be bundled inside `authz.MsgExec`, requiring only that *every* inner message (including nested ones) be in the whitelist [2](#0-1) . This makes it natural for a relayer to batch several independent users' `MsgExecutePayload`/`MsgMigrateUEA` deliveries into a single `MsgExec` transaction for efficiency.

The authorization model deliberately decouples the Cosmos `Signer` from the UEA `Owner`: any account may submit the message, and the cryptographic binding is verified **inside the UEA contract itself** via `executeUniversalTx`/`migrateUEA`, using a contract-tracked nonce and the owner's signature [3](#0-2) . The keeper simply forwards the raw payload/signature to the UEA via `CallUEAExecutePayload`/`CallUEAMigrateUEA` and propagates the `execErr` if the contract call fails [4](#0-3) [5](#0-4) , and `CallUEAMigrateUEA` invokes the UEA's `migrateUEA(payload, signature)` exactly as a normal EVM call [6](#0-5) .

Because `executeUniversalTx`/`migrateUEA` are ordinary public functions on a deployed EVM contract (not gated to only be callable via the `ue` module's `DerivedEVMCall`), any unprivileged attacker who observes a pending `MsgExecutePayload`/`MsgMigrateUEA` in the mempool can extract `(payload, verificationData/signature)` and submit a plain EVM transaction calling the UEA contract directly, consuming the owner's nonce before the Cosmos message lands. When the original `MsgExecutePayload`/`MsgMigrateUEA` is subsequently delivered, `CallUEAExecutePayload`/`CallUEAMigrateUEA` reverts because the signature/nonce has already been used, and the keeper propagates this as a hard error, causing the entire Cosmos transaction to fail [7](#0-6) .

If that `MsgExecutePayload`/`MsgMigrateUEA` was bundled with other, unrelated users' gasless messages inside a single `authz.MsgExec` (permitted per the gasless policy), the single front-run failure aborts the whole transaction atomically — exactly the Angstrom `PermitSubmitterHook` pattern, where anyone directly calling `permit()` consumes the nonce and forces the bundle containing that hook to revert, denying service to every other order/message batched alongside it.

### Impact Explanation
This is a denial-of-service vector reachable by any unprivileged attacker: no compromise of keys, validators, or admin access is required — only mempool visibility of a pending gasless `MsgExecutePayload`/`MsgMigrateUEA`. The impact is proportional to how much relayers batch these messages via `MsgExec`: batching multiple users' payload deliveries in one transaction (which the gasless whitelist explicitly supports) means one attacker-consumed signature can revert delivery for every other user in that same bundle, delaying or denying their intended UEA executions/migrations. It does not directly cause fund loss (fee deduction and EVM state are rolled back together per `ExecutePayloadV2`'s cache-context design [8](#0-7) ), but it is a reliable, unprivileged, no-cost griefing/DoS primitive against gasless batched delivery.

### Likelihood Explanation
Likelihood is high whenever relayers batch multiple gasless `MsgExecutePayload`/`MsgMigrateUEA` messages together (the exact use case the whitelist and `MsgExec` support were built for) since payload/signature data is public in the mempool and the UEA contract's `executeUniversalTx`/`migrateUEA` are unauthenticated as to caller identity — the attack costs only a small amount of gas.

### Recommendation
- Do not propagate a single failed `CallUEAExecutePayload`/`CallUEAMigrateUEA` as a hard error that aborts the entire enclosing Cosmos transaction when the message is delivered as part of a batch; treat "signature already consumed / payload already executed" as a benign no-op (idempotent success) rather than a failure, mirroring the Angstrom recommendation of wrapping the single-use call in a try/catch so one consumed permit does not sink the whole bundle.
- Alternatively/additionally, have the keeper pre-check the UEA's current nonce (or catch the specific "signature already used" revert reason) before/around the EVM call and short-circuit gracefully instead of surfacing a fatal error, so unrelated bundled messages in the same `MsgExec` are unaffected.

### Proof of Concept
1. UV/relayer submits a `MsgExec` containing `MsgExecutePayload(A)` for user A and `MsgExecutePayload(B)` for unrelated user B, both gasless per `IsGaslessTx`.
2. Attacker observes `MsgExecutePayload(A)`'s `payload` + `verificationData` in the mempool and submits a plain EVM transaction directly calling `UEA_A.executeUniversalTx(payload, verificationData)`, which succeeds and advances A's UEA nonce.
3. The relayer's `MsgExec` lands afterward; `CallUEAExecutePayload` for A now reverts ("nonce already used" / signature invalid), `ExecutePayload` returns `execErr` [7](#0-6) , and the entire Cosmos `MsgExec` transaction fails, so user B's otherwise-valid `MsgExecutePayload(B)` never executes in that block despite being unrelated to the attack.

```markdown
### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.

#### Where authorization actually lives

The cryptographic binding is enforced inside the UEA contract's `executeUniversalTx` (see [`UEA_EVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_EVM.sol#L145) and [`UEA_SVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_SVM.sol)):

1. The contract holds the owner's public key as **immutable bytes** set at UEA deployment via `initialize(_id, _factory)`. There is no code path that mutates this after init.
2. `executeUniversalTx(payload, signature)` verifies the `signature` (passed in as `MsgExecutePayload.VerificationData`) against this stored owner — ECDSA recovery for EVM-origin owners, the Ed25519 precompile (`0x00…00ca`) for SVM-origin owners.
3. The signed payload hash includes a contract-tracked `nonce` (monotonic per UEA) and optional `deadline`, providing replay and freshness protection.
4. If signature verification fails, the contract reverts. The revert propagates as `execErr` from `CallUEAExecutePayload`; the keeper returns the error from `ExecutePayload`; the entire Cosmos transaction (including any partial gas-fee deduction) rolls back atomically. **No state changes survive a failed signature check.**
```

```go
func (k Keeper) CallUEAMigrateUEA(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	migration_payload *types.MigrationPayload,
	signature []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiMigrationPayload, err := types.NewAbiMigrationPayload(migration_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		nil,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"migrateUEA",
		abiMigrationPayload,
		signature,
	)
}
```

```go
	// Step 2: Wrap EVM execution + fee deduction in a CacheContext so they
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr
	}
```
