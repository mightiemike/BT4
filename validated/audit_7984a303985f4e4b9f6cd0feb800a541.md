## Finding

### Title
Hardcoded 5% slippage tolerance in gas-refund and deposit-autoswap flows lets an unprivileged attacker sandwich UniversalCore swaps and steal value from users' inbound gas conversion and outbound gas refunds - (File: x/uexecutor/keeper/outbound.go, x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go)

### Summary
The external Pod report flags that a withdrawal path silently routes through a fee-charging pool exit with no user-supplied `maxFee`/slippage bound, letting the protocol impose an uncontrolled fee on the user. Push Chain has the same structural gap in its own internal AMM-swap flows: `applyGasRefund` (outbound gas refund), `CallPRC20DepositAutoSwap` (inbound gas-to-PC autoswap), and `gasAndPayloadDepositAutoSwap` all compute `minPCOut` as a **hardcoded** `quote * 95 / 100` from a live on-chain quote fetched moments before the swap executes, with no user-provided or governance-configurable maximum-slippage parameter.

### Finding Description
`applyGasRefund` in [1](#0-0)  fetches a spot quote via `getSwapQuoteForRefund`/`GetSwapQuote` and immediately derives `minPCOut = quote * 95 / 100`, then executes the swap through `CallUniversalCoreRefundUnusedGas`. The same pattern repeats for inbound gas conversion in `ExecuteInboundGas` [2](#0-1)  and in `gasAndPayloadDepositAutoSwap` [3](#0-2) . The underlying quote source is `GetSwapQuote`, which calls the Uniswap V3 `QuoterV2.quoteExactInputSingle` against a live, presumably publicly-tradable PRC20/WPC pool [4](#0-3) .

Because:
1. The quote is read and consumed for the swap within the same finalization flow (triggered deterministically once an ordinary user's inbound/outbound reaches vote quorum — not a privileged action),
2. `minPCOut` is a fixed 5% tolerance rather than a value the affected user (the gas-refund recipient or inbound sender) can set tighter, and
3. The pool being quoted is a standard AMM pool whose price any address can move by trading in the same or an adjacent block,

an unprivileged attacker can sandwich the swap: trade against the PRC20/WPC pool immediately before the block containing the finalizing vote tx to push the spot price down, let the module's swap execute at the now-degraded price (still within the 5% band), then trade back to restore the price and capture the difference. This extracts value that should have gone to the refund/recipient without needing any relayer, validator, or admin privilege — mirroring exactly the Pod bug class: a fee/slippage cost imposed on the user during "withdrawal" (here, gas refund/PC conversion) that the user has no ability to bound.

### Impact Explanation
This falls under "corruption of ... gas fee accounting, refund accounting ... " and "unauthorized ... refund ... of user or protocol-controlled funds" in the allowed-impact gate. The attacker can systematically skim up to ~5% of value from every inbound gas-to-PC swap and every outbound excess-gas refund routed through these code paths, at the expense of ordinary users' funds, purely by observing and front/back-running public transactions — no malicious validator or relayer assumption required.

### Likelihood Explanation
Every inbound `GAS`/`GAS_AND_PAYLOAD` transaction and every outbound with `gasFee > gasFeeUsed` (the common case) triggers one of these swaps, so the attack surface is hit on essentially every normal user cross-chain transaction. The 5% band is generous enough to make sandwiching profitable whenever the pool has realistic liquidity depth, and mempool/block visibility of the finalizing vote transaction is all that's needed to time the attack.

### Recommendation
Do not hardcode a fixed slippage percentage computed from a quote fetched in the same execution as the swap. Instead:
- Use a TWAP-based or otherwise manipulation-resistant price reference for `minPCOut`, or
- Persist the expected exchange rate at the time the inbound/outbound was created (before it could be front-run) and enforce it at execution, or
- Make the tolerance a protocol parameter that can be tightened, with a mechanism to abort/retry rather than accept whatever the spot pool offers at finalization time.

### Proof of Concept
1. Attacker monitors pending `MsgVoteInbound`/`MsgVoteOutbound` transactions that will reach quorum and trigger `ExecuteInboundGas` / `applyGasRefund`.
2. Immediately before that transaction is included, attacker submits a large swap against the same PRC20/WPC Uniswap V3 pool used by `GetSwapQuote`, moving the spot price down by close to 5%.
3. The quorum-finalizing transaction executes, `GetSwapQuote` returns the manipulated price, `minPCOut = quote*95/100` still passes, and `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes at the degraded rate.
4. Attacker submits a reverse swap to restore the pool price and pocket the difference, which was effectively taken from the inbound sender's UEA deposit or the outbound refund recipient.

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
