Based on my research, I found a strong structural analog in the mempool's capacity/eviction mechanism, which mirrors the report's core bug class: a single low-privileged actor can occupy a shared, global admission-control resource in a way that leaves no valid path for legitimately higher-priority (higher-fee) transactions from other users to be admitted, causing a network-wide denial of transaction confirmation until the attacker's transactions expire on their own.

### Title
Mempool becomes permanently saturated by non-gapped Sybil transactions, blocking higher-fee transactions from all other users - (File: crates/apollo_mempool/src/mempool.rs)

### Summary
The mempool's capacity-management logic only frees space by evicting accounts that have a **nonce gap** (`accounts_with_gap`). If an attacker fills the mempool to its byte capacity using transactions from many funded, non-gapped accounts (sequential/valid nonces), no evictable account exists, and `try_make_space` cannot free any room, regardless of how much fee a newly arriving, legitimate transaction is willing to pay.

### Finding Description
`try_make_space` only considers accounts present in `accounts_with_gap`, selected via `get_evictable_account`, which returns `None` when that set is empty: [1](#0-0) 

`handle_capacity_overflow` is the sole path used to make room for a brand-new transaction (different address) when the mempool is full: [2](#0-1) 

It only attempts eviction "if `!creating_gap`" — i.e., it never considers evicting an existing, non-gapped, low-fee transaction from another account just because the incoming transaction offers a higher fee. Fee-based replacement only applies to the *same account/nonce* via `validate_fee_escalation`, not across different accounts: [3](#0-2) 

`exceeds_capacity` is a simple byte-capacity check with no fee-priority consideration: [4](#0-3) 

As a result, if the pool is filled with capacity-worth of valid, well-ordered (non-gapped) transactions — which an attacker can produce cheaply from many low-value/self-funded accounts — the mempool has no mechanism to make room for subsequent, higher-fee transactions from unrelated honest users. They are all rejected with `MempoolError::MempoolFull`: [5](#0-4) 

This is structurally analogous to the reported bridge issue: a global, shared protective resource (there: the withdrawal queue; here: mempool capacity) can be forced into a saturated/active state by a single unprivileged actor's transactions, and once triggered, legitimate/unrelated users' operations are blocked with no override, until the attacker's occupying transactions eventually clear (TTL expiry, default `transaction_ttl` — 300s per deployment config, or by being included in blocks). [6](#0-5) 

### Impact Explanation
While the attacker's own transactions eventually need to be included or expire (bounding the attack duration to the TTL window), during that window honest users — even those willing to pay significantly higher fees — cannot get their transactions admitted into the mempool at all, so the network is effectively unable to confirm new transactions from those users. An attacker can continuously refresh their occupying transactions (before TTL expiry) to sustain the denial indefinitely, at a bounded resource cost (funding many low-cost accounts with sequential/valid nonces), unlike a "fair" fee-priority mempool where higher bids would displace lower-fee occupants.

### Likelihood Explanation
The attack only requires the capability of a normal, unprivileged transaction sender: control of multiple funded, non-gapped accounts able to submit valid transactions that fit within `capacity_in_bytes` (default 1 GiB per `mempool_config.static_config.capacity_in_bytes`). No special access to the gateway, sequencer internals, or p2p layer is needed — this is reachable purely through the normal `add_tx` transaction-submission path.

### Recommendation
Introduce fee-priority-aware eviction across different accounts when the mempool is full and no gapped/evictable low-value transactions exist — i.e., allow `handle_capacity_overflow` to evict the globally lowest-fee (or lowest-priority) non-gapped transaction(s) when a higher-fee, freshly-arriving transaction cannot otherwise be admitted, mirroring standard fee-market mempool designs (as is already done, but only within the *same* account, via `validate_fee_escalation`). Additionally, consider imposing a per-address or per-cluster cap on mempool byte-share to blunt Sybil-based saturation.

### Proof of Concept
1. Attacker deploys/funds N accounts such that the sum of their transaction sizes ≈ `mempool_config.static_config.capacity_in_bytes` (default 1 GiB).
2. Attacker submits one valid, sequential-nonce (non-gapped) transaction per account, filling the mempool to capacity. `accounts_with_gap` remains empty since none of these transactions create nonce gaps.
3. An honest user submits a transaction with a much higher tip/fee. `exceeds_capacity` returns `true`; `handle_capacity_overflow` calls `try_make_space`, which calls `get_evictable_account` — returns `None` since `accounts_with_gap.len() == 0` — so `try_make_space` returns `false` immediately.
4. The honest user's transaction is rejected with `MempoolError::MempoolFull`, irrespective of its fee, and this persists until attacker transactions are committed or expire via TTL, at which point the attacker can resubmit fresh occupying transactions to repeat the denial.

    fn add_tx_validations(
        &mut self,
        tx_reference: TransactionReference,
        tx: &InternalRpcTransaction,
        account_nonce: Nonce,
    ) -> MempoolResult<()> {
        self.validate_incoming_tx(tx_reference, account_nonce)?;
        let replaced_tx_reference = self.validate_fee_escalation(tx_reference)?;

        // The replaced transaction is still pooled, so its bytes still count toward
        // `size_in_bytes()`. Credit what its removal will free: a same-size bump nets to zero (no
        // overflow handling), and a larger replacement only needs room for the delta, consistent
        // with how a fresh next-nonce transaction is treated. The removal happens only after
        // capacity is confirmed below, so a rejected incoming transaction never strands the
        // account.
        let freed_bytes = replaced_tx_reference.map_or(0, |reference| {
            self.tx_pool
                .get_by_tx_hash(reference.tx_hash)
                .expect("Replacement target from pool must exist.")
                .total_bytes()
        });

        if self.exceeds_capacity(tx, freed_bytes) {
            self.handle_capacity_overflow(tx, account_nonce, freed_bytes)?;
        }

        // Capacity is confirmed: this is the final, infallible mutation before the incoming
        // transaction is inserted by the caller.
        if let Some(existing_tx_reference) = replaced_tx_reference {
            self.remove_replaced_tx(existing_tx_reference);
        }

        Ok(())
    }

    // Returns true if adding the given transaction would exceed the mempool capacity, after
    // crediting `freed_bytes` that an accompanying removal (e.g. a fee-escalation replacement)
    // will free. `freed_bytes` is 0 when there is no such removal.
    fn exceeds_capacity(&self, tx: &InternalRpcTransaction, freed_bytes: u64) -> bool {
        // The to-be-removed transaction is still counted in `size_in_bytes()` here, so subtract
        // what its removal frees. `saturating_sub` guards the (impossible) underflow defensively.
        (self.size_in_bytes() + tx.total_bytes()).saturating_sub(freed_bytes)
            > self.config.static_config.capacity_in_bytes
    }

    pub fn get_evictable_account(&self) -> Option<ContractAddress> {
        let len = self.accounts_with_gap.len();
        if len == 0 {
            return None;
        }
        let random_index = thread_rng().gen_range(0..len);
        self.accounts_with_gap.get_index(random_index).copied()
    }

    // Attempts to make space for a new transaction by evicting existing transactions.
    // Returns true if enough space was freed, false otherwise.
    pub fn try_make_space(&mut self, required_space: u64) -> bool {
        let mut total_space_freed = 0;
        let mut evicted_txs = Vec::new();

        while total_space_freed < required_space {
            let Some(address) = self.get_evictable_account() else {
                break;
            };

            let txs: Vec<_> = self.tx_pool.account_txs_sorted_by_nonce(address).copied().collect();
            for tx_ref in txs.iter().rev() {
                let tx = self
                    .tx_pool
                    .remove(tx_ref.tx_hash)
                    .expect("Transaction must exist in the pool.");
                total_space_freed += tx.total_bytes();
                evicted_txs.push(*tx_ref);
                metric_count_evicted_txs(1);
                self.decrement_stuck_txs_if_gap_account(address, 1);
                if total_space_freed >= required_space {
                    break;
                }
            }

            // Clean up if account is now empty.
            if !self.tx_pool.contains_account(address) {
                self.accounts_with_gap.swap_remove(&address);
            }
        }

        // Keep the queue consistent with the pool: the evicted txs were removed from the pool, so
        // drop their (now-orphaned) queue references too. In fee mode gap accounts are never
        // queued, so this is a no-op there; in Echonet/FIFO mode they are, and skipping this leaves
        // a dangling reference that panics the next `get_txs`.
        self.tx_queue.remove_txs(&evicted_txs);

        total_space_freed >= required_space

    fn handle_capacity_overflow(
        &mut self,
        tx: &InternalRpcTransaction,
        account_nonce: Nonce,
        freed_bytes: u64,
    ) -> Result<(), MempoolError> {
        let address = tx.contract_address();

        let account_has_gap = self.accounts_with_gap.contains(&address);
        let account_has_txs = self.tx_pool.contains_account(address);
        let closing_gap = tx.nonce() == account_nonce;
        let creating_gap = (account_has_gap || !account_has_txs) && !closing_gap;

        // Only the net growth must be evicted: an accompanying replacement removal frees
        // `freed_bytes` (0 when there is no replacement).
        let required_space = tx.total_bytes().saturating_sub(freed_bytes);
        if !creating_gap && self.try_make_space(required_space) {
            return Ok(());
        }

        Err(MempoolError::MempoolFull)
    }
