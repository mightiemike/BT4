### Title
Missing capability-origin check in `ShouldAllowMojoJsBindingsForFrame` grants full Mojo/MojoJS surface to any navigation-allowed PWC main frame - ([File: chrome/browser/chrome_content_browser_client.cc])

### Summary
The reported USSD bug is a classic "gate exists but is not actually enforced" access-control flaw: `burnRebalancer()` is designed to be balancer-only but has no modifier checking the caller. The Chromium codebase in this snapshot contains a structurally analogous flaw in the "Privileged WebContents" (PWC) / GEIC prototype code: `ChromeContentBrowserClient::ShouldAllowMojoJsBindingsForFrame` grants the extremely powerful MojoJS binding capability (which lets a renderer's JavaScript directly invoke `Mojo.bindInterface()` for arbitrary browser-exposed Mojo interfaces) to *any* outermost main frame belonging to a `pwc::PrivilegedWebContents`, without verifying that the committed origin is actually in the component's `capability_allowlist`.

### Finding Description
`PwcPolicyDelegate` defines a documented "two-tier trust model": `IsNavigationAllowed(origin)` decides which origins the PWC main frame may ever commit, while `IsCapabilityOrigin(origin)` decides the (structurally smaller) subset of navigable origins that may receive the elevated capability bridge [1](#0-0) .

However, the actual gate that turns on the most dangerous capability — MojoJS bindings, which expose the entire renderer-reachable Mojo interface surface via JavaScript — does not consult `IsCapabilityOrigin` at all:

```
bool ChromeContentBrowserClient::ShouldAllowMojoJsBindingsForFrame(
    content::RenderFrameHost& render_frame_host) {
  ...
  // TODO(crbug.com/539909218): Prototype shortcut. Enabling MojoJS for any PWC
  // exposes the entire Mojo interface surface rather than only GeicApi, and the
  // committed origin is not checked against the capability allowlist here.
  if (!render_frame_host.GetParentOrOuterDocument() && web_contents &&
      pwc::PrivilegedWebContents::FromWebContents(web_contents)) {
    return true;
  }
``` [2](#0-1) 

The comment in the source itself acknowledges the gap. The check only verifies that the frame is an outermost main frame of *some* `PrivilegedWebContents` — it says nothing about whether the frame's *committed origin* is in the component's `capability_allowlist`. Because `IsNavigationAllowed` and `IsCapabilityOrigin` are two independently-configurable allowlists (a component can navigate to a broader set of origins than it grants capability to, per the documented "two-tier trust model" comment), any origin that is merely *navigation-allowed* — but deliberately excluded from the *capability* allowlist by the component owner — still gets full MojoJS bindings once it becomes the primary main frame of a PWC.

This is reinforced by the same pattern appearing twice more in the sibling GEIC code, both carrying the identical caveat:

```
void GeicPwcManager::TabEntry::RenderFrameCreated(
    content::RenderFrameHost* render_frame_host) {
  // TODO(crbug.com/539909218): Prototype shortcut. This exposes the entire
  // Mojo surface rather than only GeicApi, and the committed origin is not
  // checked against the capability allowlist here.
  if (render_frame_host->IsInPrimaryMainFrame()) {
    render_frame_host->EnableMojoJsBindings(/*features=*/nullptr);
  }
}
``` [3](#0-2) 

```
void GeicPwcManager::TabEntry::ReadyToCommitNavigation(
    content::NavigationHandle* navigation_handle) {
  // TODO(crbug.com/539909218): Prototype shortcut. This exposes the entire
  // Mojo surface rather than only GeicApi, and the committed origin is not
  // checked against the capability allowlist here.
  if (navigation_handle->IsInPrimaryMainFrame() &&
      navigation_handle->GetRenderFrameHost()) {
    navigation_handle->GetRenderFrameHost()->EnableMojoJsBindings(
        /*features=*/nullptr);
  }
}
``` [4](#0-3) 

By contrast, the intended, narrower capability (`geic::mojom::GeicApi`) is correctly gated by `pwc::EnforceCapabilityGate`, which does perform the component/capability check and terminates the renderer on violation [5](#0-4) . The MojoJS-bindings path bypasses that same intended enforcement entirely — exactly like `burnRebalancer()` bypassing the intended `onlyBalancer` restriction: the "real" privileged capability has a correct guard elsewhere in the codebase, but a second, more powerful code path to reach nearly the same functionality (here, direct Mojo IPC access from JS) omits the check.

### Impact Explanation
MojoJS bindings let arbitrary page JavaScript call `Mojo.bindInterface('some.mojom.Interface', pipe)` and invoke any Mojo interface bound in that frame's `BinderMap`, as demonstrated by the repository's own PoC test harness that injects `MediaStreamDispatcherHost` via `Mojo.bindInterface` from an iframe when MojoJS is enabled [6](#0-5) . If a PWC's `navigation_allowlist` contains an origin outside the intended `capability_allowlist` (a configuration explicitly anticipated and supported by the two-tier design), that origin's committed main frame receives the same unrestricted MojoJS access as a fully-capability-blessed origin. This effectively turns a same-process, elevated-privilege renderer (already running with a distinct `content_feature_id`/process grouping, per `PwcComponentPolicy`) into one that can invoke the full browser-exposed Mojo interface surface reachable from a renderer, going well beyond the single `GeicApi`/`PrivilegedBridge` interfaces the design intends to expose — a serious SOP/privilege-boundary bypass within Chrome's own trusted-content model.

### Likelihood Explanation
This requires the `pwc::mojom::features::kPrivilegedWebContents` feature to be enabled and a component (GEIC or Glic) to configure a `navigation_allowlist` broader than its `capability_allowlist` — a scenario the code's own documentation calls out as the whole point of the "two-tier trust model." Given the explicit, still-open TODO/crbug reference (`crbug.com/539909218`) acknowledging this exact gap as a "prototype shortcut," the maintainers themselves recognize it as unresolved, not yet mitigated, security-relevant behavior tracked for follow-up work ("erikchen@ designs a scoped capability binding mechanism in follow-ups"). This is a real, currently-live gap in shipped-adjacent code, not a hypothetical.

### Recommendation
`ShouldAllowMojoJsBindingsForFrame` (and both `EnableMojoJsBindings` call sites in `GeicPwcManager::TabEntry`) should check the frame's actual committed origin against the component's `PwcComponentPolicy::IsCapabilityOrigin()` before granting MojoJS bindings, exactly mirroring the check already performed by `pwc::EnforceCapabilityGate` for `GeicApi`/`PrivilegedBridge`. Until the scoped capability-binding mechanism referenced in the TODO lands, MojoJS should not be blanket-enabled for every PWC main frame; it should be gated per-origin the same way the narrower capability interfaces already are.

### Proof of Concept
1. Enable `pwc::mojom::features::kPrivilegedWebContents` and configure a component (e.g. via `FixedPwcPolicyDelegate`) with `navigation_allowlist = {https://a.example, https://b.example}` but `capability_allowlist = {https://a.example}` only — a configuration explicitly supported by the `PwcPolicyDelegate` two-tier design [7](#0-6) .
2. Cause the PWC's primary main frame to navigate to `https://b.example` (navigation-allowed but not capability-allowed).
3. On `ReadyToCommitNavigation`/`RenderFrameCreated` for that frame, `EnableMojoJsBindings` is invoked unconditionally for any PWC main frame [8](#0-7) , and `ShouldAllowMojoJsBindingsForFrame` likewise returns `true` for any outermost PWC main frame regardless of origin [9](#0-8) .
4. From `https://b.example`'s script context, call `Mojo.bindInterface('<any registered interface>', pipe.handle0)` (same technique as the repo's own `multi_capture_iframe_browsertest.cc` PoC) to obtain a live remote to any Mojo interface registered in that frame's binder map — not just `GeicApi` — despite `https://b.example` never having been granted the capability bridge.

//
// Two-tier trust model: navigation is the set of origins the primary main
// frame may ever commit; capability is the subset of those origins that
// additionally receive the elevated capability bridge. A main frame
// committed to a navigation-only origin runs in the isolated process but is
// never handed capabilities.
class PwcPolicyDelegate {
 public:
  virtual ~PwcPolicyDelegate() = default;

  // True iff the primary main frame may commit `origin`.
  virtual bool IsNavigationAllowed(const url::Origin& origin) const = 0;

  // True iff a primary main frame committed to `origin` may receive the
  // elevated capability bridge.
  virtual bool IsCapabilityOrigin(const url::Origin& origin) const = 0;
};

// A PwcPolicyDelegate that answers from fixed origin lists. Suitable for
// tests and for components whose allowlists do not change at runtime.
class FixedPwcPolicyDelegate : public PwcPolicyDelegate {
 public:
  FixedPwcPolicyDelegate(std::vector<url::Origin> navigation_allowlist,
                         std::vector<url::Origin> capability_allowlist);
  ~FixedPwcPolicyDelegate() override;

  bool IsNavigationAllowed(const url::Origin& origin) const override;
  bool IsCapabilityOrigin(const url::Origin& origin) const override;

 private:
  const std::vector<url::Origin> navigation_allowlist_;
  const std::vector<url::Origin> capability_allowlist_;
};

      content::WebContents::FromRenderFrameHost(&render_frame_host);

```text
void BindGeicApi(content::RenderFrameHost* render_frame_host,
                 mojo::PendingReceiver<mojom::GeicApi> receiver) {
  // The shared gate enforces the full capability policy (and terminates the
  // renderer itself on a renderer-controllable violation); null simply means
  // do not bind.
  pwc::PrivilegedWebContents* privileged =
      pwc::EnforceCapabilityGate(render_frame_host);
  if (!privileged) {
    return;
  }

  // The gate is component-agnostic; GeicApi additionally requires the
  // component to be GEIC. A request from another component's frame is again a
  // compromised renderer.
  if (privileged->component() != pwc::PrivilegedComponent::kGeic) {
    bad_message::ReceivedBadMessage(render_frame_host->GetProcess(),
                                    bad_message::PWC_BRIDGE_UNQUALIFIED_FRAME);
    return;
  }

  if (!GeicHost::Get(privileged->unowned_user_data_host())) {
    // The frame qualifies, but the GEIC component has not attached its GeicHost
    // to this PrivilegedWebContents. That is a browser-side setup gap, not a
    // compromised renderer, so drop the request rather than terminating the
    // renderer.
    return;
  }
  GeicApiBinding::Create(render_frame_host, std::move(receiver));
}
