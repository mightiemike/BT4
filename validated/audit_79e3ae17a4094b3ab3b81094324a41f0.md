Confirmed: `handleFailedOutbound` at [1](#0-0)  re-mints the bridged funds back to the sender/revert recipient via `CallPRC20Deposit` when a REVERT vote is finalized, and `applyGasRefund` [2](#0-1)  also issues a gas refund on the failed path. If REVERT is voted incorrectly while the destination tx later actually lands, the sender receives both the re-minted funds on Push Chain *and* the successful transfer on the destination chain — a duplicate-payout scenario, contingent on the premise being correct.

The premise hinges on whether `CheckNonce`'s "finalized" nonce check is actually reorg-safe. It is not:### Title
`GetFinalizedNonce` queries "latest" not a reorg-safe block, letting `CheckNonce` vote outbound REVERT before `StandardConfirmations` is satisfied - ([File: universalClient/chains/evm/rpc_client.go], [File: universalClient/tss/txresolver/evm.go], [File: universalClient/tss/txflow/nonce.go])

### Summary
`resolveOutboundEVM`'s "tx found" path explicitly requires `confirmations >= r.chains.GetStandardConfirmations(chainID)` before making any terminal decision (success or revert) [3](#0-2) . But the "tx not found" path bypasses that guard entirely: it calls `txflow.CheckNonce`, which asks the chain for the "finalized" nonce and immediately votes REVERT if the signed nonce is behind it [4](#0-3) [5](#0-4) .

The "finalized" nonce is not actually queried at a reorg-safe finality checkpoint. `TxBuilder.GetNextNonce(useFinalized=true)` calls `rpcClient.GetFinalizedNonce(ctx, signerAddr, nil)` [6](#0-5) , and `GetFinalizedNonce` passes that `nil` block number straight into `client.NonceAt(ctx, address, blockNum)` [7](#0-6) . In go-ethereum's `ethclient`, a `nil` block number resolves to the **latest** block, not the chain's "finalized" tag (which requires the special `rpc.FinalizedBlockNumber` sentinel). So despite the name and comments ("finalized nonce", "chain finalized nonce", "already finalized on chain"), this code is reading the nonce at the chain head — a value that can move due to any recently-mined, not-yet-confirmed block, and can be undone by an ordinary reorg.

### Finding Description
On an ordinary, reorg-prone destination chain, a competing transaction consuming the same nonce slot (e.g., a resolver-driven re-broadcast that produces a different tx hash for the same nonce, or any other tx that lands at that nonce) can be mined in the very latest block. `resolveOutboundEVM`'s "not found" branch will then see:
- `VerifyBroadcastedTx` for the *original* tx hash returns `found=false` (only the competing tx occupies that nonce),
- `CheckNonce` queries `GetNextNonce(useFinalized=true)`, which is really just "latest" nonce, and sees it advanced past `signedNonce`,
- Verdict `NonceConsumed` is returned, and the resolver immediately votes REVERT via `voteOutboundFailureAndMarkReverted`, with **zero confirmation-depth requirement**, unlike the parallel "found" branch which enforces `StandardConfirmations`.

If that latest block is subsequently reorged out, and the transaction that consumed the nonce (or the original tx re-included) later lands successfully in the canonical chain, the on-chain outcome is "delivered", while Push Chain's `UniversalTx` has already recorded `Status_REVERTED` and executed `handleFailedOutbound`, which re-mints the bridged PRC20 amount back to the sender/revert recipient via `CallPRC20Deposit` [8](#0-7) , and also issues a gas refund via `applyGasRefund` [9](#0-8) . The sender ends up receiving the destination-chain transfer *and* the re-minted funds on Push Chain — duplicate value creation from what should be a single transfer.

This is not caused by a malicious validator, TSS signer, or relayer — it is a consequence of ordinary, honest destination-chain reorg activity interacting with a mislabeled/incorrect nonce query, reachable purely from a user's own withdrawal flow.

### Impact Explanation
This corrupts outbound-status accounting and can cause an unauthorized/duplicate re-mint of PRC20 or native assets (funds that were already delivered on the destination chain get re-created on Push Chain), which is squarely in the "unauthorized mint" / "corruption of refund accounting" / "corruption of canonical UniversalTx state" impact categories from the allowed-impact gate.

### Likelihood Explanation
Requires an ordinary reorg on the destination chain deep enough to remove a very-recently-mined block (0 confirmations) at exactly the moment the resolver polls, combined with a nonce state that, at that instant, looks consumed relative to `signedNonce`. This is inherently racy and self-limiting in the common case: if the *same* transaction is simply dropped and re-mined, the account nonce typically reverts with it, giving `NonceAvailable` (rewind-to-SIGNED) rather than `NonceConsumed`. The exploitable case specifically needs a *different* transaction to have (even momentarily) consumed the same nonce in an unconfirmed block that the polling cycle happens to observe before it's reorged away — e.g., during a resolver-driven re-broadcast/replace-nonce race, or any nonce-slot contention on the destination chain. It is a real code defect (finalized ≠ latest) but the end-to-end funds-duplication requires a fairly specific timing coincidence; the underlying bug (calling `NonceAt` with `nil` and treating it as "finalized") is unconditionally present and violates the invariant the "found" branch enforces, so likelihood is best characterized as low-to-moderate depending on target-chain reorg frequency and nonce contention, not purely theoretical.

### Recommendation
Fix `GetFinalizedNonce` to query the actual `finalized` (or at minimum a block that is `StandardConfirmations` deep) block tag instead of passing `nil` (which resolves to `latest`), e.g., use `client.HeaderByNumber(ctx, big.NewInt(rpc.FinalizedBlockNumber.Int64()))` to get the finalized block number and pass that to `NonceAt`, or otherwise compute a block number offset by `StandardConfirmations` from the tip and query the nonce there. Ensure `CheckNonce`'s REVERT decision is gated by the same confirmation-depth guarantee already enforced in the "tx found" branch of `resolveOutboundEVM`/`resolveFundMigrationEVM`.

### Proof of Concept
Not independently executable without live/simulated RPC access to an EVM node exposing both `latest` and `finalized` tags differently (e.g., a devnet with slow finality). Conceptually: 1) mine a competing tx at the TSS's next nonce in the latest (unconfirmed) block; 2) call `GetFinalizedNonce`/`GetNextNonce(useFinalized=true)` and observe it returns the same value as `PendingNonceAt`/latest, i.e., it advances immediately rather than staying pinned to a block `StandardConfirmations` deep; 3) drive `resolveOutboundEVM` with `VerifyBroadcastedTx` returning not-found for the original hash and this "finalized" nonce advanced — confirm it votes REVERT with 0 confirmations elapsed, contrasting with the `found=true` path's explicit `confirmations < StandardConfirmations` guard at [3](#0-2) .

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason

func CheckNonce(ctx context.Context, builder common.TxBuilder, signer string, signedNonce uint64) (NonceVerdict, uint64) {
	finalizedNonce, err := builder.GetNextNonce(ctx, signer, true)
	if err != nil {
		return NonceUnknown, 0
	}
	if signedNonce < finalizedNonce {
		return NonceConsumed, finalizedNonce
	}
	return NonceAvailable, finalizedNonce

// GetNextNonce returns the next nonce for the signer.
func (tb *TxBuilder) GetNextNonce(ctx context.Context, signerAddress string, useFinalized bool) (uint64, error) {
	if signerAddress == "" {
		return 0, fmt.Errorf("signerAddress is required")
	}
	signerAddr := ethcommon.HexToAddress(signerAddress)
	if useFinalized {
		return tb.rpcClient.GetFinalizedNonce(ctx, signerAddr, nil)
	}
	return tb.rpcClient.GetPendingNonce(ctx, signerAddr)
}

// GetFinalizedNonce returns the finalized nonce at a block.
func (rc *RPCClient) GetFinalizedNonce(ctx context.Context, address ethcommon.Address, blockNum *big.Int) (uint64, error) {
	var nonce uint64
	err := rc.executeWithFailover(ctx, "get_transaction_count_finalized", func(client *ethclient.Client) error {
		var innerErr error
		nonce, innerErr = client.NonceAt(ctx, address, blockNum)
		return innerErr
	})
	return nonce, err
}
