### Title
Auto-generated INBOUND_REVERT / RESCUE_FUNDS outbounds are never gated on `IsChainOutboundEnabled`, permanently stranding refunds when a chain has inbound enabled but outbound disabled - (File: x/uexecutor/keeper/create_outbound.go)

### Summary
Push Chain's `ChainConfig.Enabled` exposes two independent flags, `IsInboundEnabled` and `IsOutboundEnabled` [1](#0-0) , mirroring the `isBorrowPaused` / `isLiquidateBorrowPaused` split in the reported EvoqGovernance bug. Just as the external report shows a market can be deprecated (borrowing halted) while liquidation stays paused — trapping borrowers with no way to be liquidated — a Push Chain admin can leave `IsInboundEnabled = true` while setting `IsOutboundEnabled = false` for a source chain. Deposits keep flowing in, but any refund/rescue outbound that the protocol auto-generates for that same source chain (on failed pre-execution validation, expired ballots, or stuck-inbound rescue) is created without ever checking `IsChainOutboundEnabled`, so it sits `PENDING` forever and user funds are never returned.

### Finding Description
`BuildOutboundsFromReceipt` (used for normal contract-driven outbounds) explicitly enforces the outbound-enabled gate: [2](#0-1) 

However, the revert/rescue construction path, `attachOutboundsToUtx`, which is the single choke point used by both automatic inbound-revert creation (e.g. zero-amount or missing-token-config failures) and the admin `RevertStuckInbound`/rescue-funds flow, performs no such check before writing the outbound to `PendingOutbounds` and emitting the `OutboundCreatedEvent`: [3](#0-2) 

Integration tests confirm that a zero-amount (or otherwise failing) `FUNDS`/`GAS` inbound automatically creates an `INBOUND_REVERT` outbound whose `DestinationChain` is set back to the original `SourceChain`: [4](#0-3) 

and the admin `RevertStuckInbound` path builds the same kind of `INBOUND_REVERT` outbound with `DestinationChain: inbound.SourceChain` and `Status_PENDING`, again with no outbound-enabled check anywhere in the flow: [5](#0-4) 

Since a chain being fetched/watched by `universalClient` is itself gated on `Enabled` flags for TSS signing and relay [6](#0-5) , an outbound queued to a chain whose `IsOutboundEnabled` is `false` has no path to ever be signed and broadcast by TSS. The `PendingOutbound` entry and the `UniversalTx`'s `OutboundTx` remain `PENDING` indefinitely.

### Impact Explanation
This produces a permanent freezing of user funds: any ordinary user whose deposit (inbound) hits a failure condition (zero amount, missing token config, expired ballot, admin-initiated stuck-inbound revert, or a rescue-funds flow) on a chain configured with inbound enabled / outbound disabled has their refund silently and permanently stuck, with no mechanism in the reachable code to detect or recover it. This falls squarely within the in-scope impact "permanent freezing... of user or protocol-controlled funds" and is reachable purely from an unprivileged user's default deposit flow — the trigger is an ordinary, honestly-processed inbound failure, not any attacker action beyond normal transaction submission.

### Likelihood Explanation
The `Enabled` flags are independently settable per chain via governance/admin config updates [7](#0-6) , and operators have legitimate reasons to disable outbound while keeping inbound open (e.g., pausing withdrawals during an incident while still accepting bridge-in liquidity) — exactly the kind of "intentional flexibility" the original report's client cited for keeping the two pause flags independent. Any deposit that later needs to be reverted/rescued during that window is silently and irrecoverably stuck, so likelihood is high whenever this common operational configuration is used.

### Recommendation
Add an explicit `IsChainOutboundEnabled` check (or a dedicated "refund enabled" flag independent from ordinary outbound routing) inside `attachOutboundsToUtx` / before constructing `INBOUND_REVERT` and `RESCUE_FUNDS` outbounds, and either block the underlying inbound processing/rescue action with a clear error, or provide a distinct, always-available refund path that is not blocked by the general outbound-disabled flag, so that pausing outbound routing can never trap funds owed back to depositors on the same chain.

### Proof of Concept
1. Admin adds a `ChainConfig` for `eip155:X` with `Enabled: {IsInboundEnabled: true, IsOutboundEnabled: false}`.
2. A user submits a normal `FUNDS`/`GAS` inbound deposit that fails a pre-execution validation check (e.g., zero amount, as in `TestInboundGas` in `execute_inbound_gas_test.go`), or the inbound's ballot expires and gets recomputed/reverted via `RevertStuckInbound`.
3. `attachOutboundsToUtx` creates an `INBOUND_REVERT` outbound with `DestinationChain = eip155:X`, `OutboundStatus = PENDING`, and indexes it in `PendingOutbounds` — with no `IsChainOutboundEnabled` check performed anywhere in this path.
4. Because `eip155:X` has outbound disabled, `universalClient` never processes/signs this outbound via TSS; the refund remains `PENDING` forever, permanently freezing the user's deposited funds.

// IsChainInboundEnabled checks if inbound is enabled for a given chain
func (k Keeper) IsChainInboundEnabled(ctx context.Context, chain string) (bool, error) {
	config, err := k.GetChainConfig(ctx, chain)
	if err != nil {
		if errors.Is(err, collections.ErrNotFound) {
			// chain not found
			return false, nil
		}
		return false, err
	}
	if config.Enabled == nil {
		return false, nil
	}
	return config.Enabled.IsInboundEnabled, nil
}

func (k Keeper) attachOutboundsToUtx(
	ctx sdk.Context,
	utxId string,
	outbounds []*types.OutboundTx,
	revertMsg string, // revert msg if the outbound is for a inbound revert
) error {

	if len(outbounds) == 0 {
		return nil
	}
	return k.UpdateUniversalTx(ctx, utxId, func(utx *types.UniversalTx) error {

		for _, outbound := range outbounds {

			utx.OutboundTx = append(utx.OutboundTx, outbound)

			// Compute signature expiry deadline for the destination chain.
			var signingDeadline int64
			if chainCfg, err := k.uregistryKeeper.GetChainConfig(ctx, outbound.DestinationChain); err == nil {
				if chainCfg.TssSigningDeadline != nil && *chainCfg.TssSigningDeadline > 0 {
					signingDeadline = ctx.BlockTime().Unix() + int64(chainCfg.TssSigningDeadline.Seconds())
				}
			}

			// Write to pending outbounds index (inside UpdateUniversalTx closure for atomicity)
			if err := k.PendingOutbounds.Set(ctx, outbound.Id, types.PendingOutboundEntry{
				OutboundId:      outbound.Id,
				UniversalTxId:   utxId,
				CreatedAt:       ctx.BlockHeight(),
				SigningDeadline: signingDeadline,
			}); err != nil {
				return fmt.Errorf("failed to set pending outbound index for %s: %w", outbound.Id, err)
			}

			var pcTxHash string
			var logIndex string

			if outbound.PcTx != nil {
				pcTxHash = outbound.PcTx.TxHash
				logIndex = outbound.PcTx.LogIndex
			}

			evt, err := types.NewOutboundCreatedEvent(types.OutboundCreatedEvent{
				UniversalTxId:    utxId,
				TxID:             outbound.Id,
				DestinationChain: outbound.DestinationChain,
				Recipient:        outbound.Recipient,
				Amount:           outbound.Amount,
				AssetAddr:        outbound.ExternalAssetAddr,
				Sender:           outbound.Sender,
				Payload:          outbound.Payload,
				GasFee:           outbound.GasFee,
				GasLimit:         outbound.GasLimit,
				GasPrice:         outbound.GasPrice,
				GasToken:         outbound.GasToken,
				TxType:           outbound.TxType.String(),
				PcTxHash:         pcTxHash,
				LogIndex:         logIndex,
				RevertMsg:        revertMsg,
				SigningDeadline:  signingDeadline,
			})
			if err == nil {
				ctx.EventManager().EmitEvent(evt)
			}
		}

		return nil
	})

// determineChainAction determines what action to take for a chain config
func (c *Chains) determineChainAction(cfg *uregistrytypes.ChainConfig) chainAction {
	chainID := cfg.Chain

	// Check if chain is fully disabled (both flags off)
	bothDisabled := cfg.Enabled == nil ||
		(!cfg.Enabled.IsInboundEnabled && !cfg.Enabled.IsOutboundEnabled)

	c.chainsMu.RLock()
	_, exists := c.chains[chainID]
	existingConfig := c.chainConfigs[chainID]
	c.chainsMu.RUnlock()

	if bothDisabled {
		if exists {
			c.logger.Info().Str("chain", chainID).Msg("chain disabled, removing")
			return chainActionRemove
		}
		c.logger.Debug().Str("chain", chainID).Msg("chain disabled, skipping")
		return chainActionSkip
	}

	if !exists {
		return chainActionAdd
	}

	// Check if config changed (includes enabled flag changes)
	if existingConfig != nil && !configsEqual(existingConfig, cfg) {
		return chainActionUpdate
	}

	// No change
	return chainActionSkip
}
