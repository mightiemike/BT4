### Title
Stale intra-transaction interest-index cache causes incorrect bad-debt socialization in `liquidate` - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`market.clar`'s per-block index cache (`index-cache-`, populated by `accrue-and-cache`) is read again *after* a state-mutating vault call within the same `liquidate` invocation, without being refreshed, so a later computation in the same transaction uses an index value that no longer matches the vault's real state.

### Finding Description
`accrue-and-cache` is a memoized read: on cache hit for `{ timestamp: stacks-block-time, aid }` it returns the stored `{index, lindex}` without touching the vault again [1](#0-0) . In `liquidate`, this cache is populated early via `accrue-user-debts`/`accrue-user-collateral` and then consulted to compute `remaining-debt-to-repay` at line 1482, before any vault mutation [2](#0-1) . The function then executes `vault-system-repay`, a state-changing call into the debt asset's vault [3](#0-2) . Immediately after that mutation, the same cached (now potentially stale) borrow index for `debt-aid` is read again via `get-cached-indexes` to compute `other-debt-repayable`, which feeds into the `no-collateral-left` decision that determines whether bad debt gets socialized [4](#0-3) . Because `accrue-and-cache` never re-queries the vault once a cache entry exists for the block timestamp, the socialization decision is made against an index snapshot taken *before* the repay-triggered vault state change rather than the actual post-repay state — the classic "value bound → source moves → later use of the stale value" pattern.

### Impact Explanation
`no-collateral-left`/`other-debt-repayable` gates whether the borrower's leftover unsecured debt is written off (socialized to the pool) via `socialize-debt-asset` [5](#0-4) . A wrong (stale-index-derived) determination can cause bad debt to be incorrectly socialized (spreading unrecovered losses across lenders) or incorrectly skipped (leaving unbacked debt permanently stranded in the position with no matching collateral), degrading protocol accounting and lender-fund integrity — a temporary/permanent freezing-of-funds-class impact on other users' deposited liquidity.

### Likelihood Explanation
This triggers deterministically on ordinary partial liquidations that leave "other" collateral of the same debt asset, whenever the debt-asset's vault index would have changed as a side effect of `vault-system-repay` within the same transaction — no attacker coordination, multiple users, or oracle manipulation needed, only Clarity's normal single-transaction, single-block cache-hit evaluation order. It is a single-block, single-caller analog, consistent with scope.

### Recommendation
Force a fresh (non-cached) vault index read for `debt-aid` after any state-mutating vault call within the same function (`vault-system-repay`, `vault-system-borrow`, `collateral-remove`, etc.) before using it for further USD/scaled conversions, or invalidate/overwrite the `index-cache-` entry immediately after such mutating calls so subsequent reads in the same transaction reflect current vault state.

### Proof of Concept
1. Borrower has debt in `debt-aid` and collateral split across two collateral assets, one being `coll-aid` (target of this liquidation call) and residual balance in another asset ("other" collateral).
2. Liquidator calls `liquidate` with a `debt-amount` sized to leave partial `coll-remaining` for `coll-aid`, forcing the `remaining-debt-to-repay` branch to execute using the pre-repay cached index (line 1482-1484).
3. `vault-system-repay` executes and mutates the debt asset's vault state (line 1496).
4. The subsequent `let` block recomputes `other-debt-repayable` using `get-cached-indexes debt-aid` (line 1522), which still returns the pre-repay cached value from step 2's cache population rather than the vault's now-current index.
5. The mismatched index skews the token-to-scaled-debt conversion used in `other-debt-repayable`, which in turn flips the `no-collateral-left` boolean (line 1526-1532), causing bad-debt socialization to fire or be skipped incorrectly relative to the borrower's true post-repay state.
