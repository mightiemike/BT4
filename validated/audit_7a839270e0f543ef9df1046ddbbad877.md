No vulnerability found for this question.

**Analysis:** The exploit hypothesis requires a "parsing bug swapping adjacent variable-length keyless entries" in the `MultiKey`/`AnyPublicKey` deserialization path, but no such bug exists in the actual implementation.

- `multi_key::deserialize_multi_key` calls `bcs_stream::deserialize_vector(stream, |x| single_key::deserialize_any_public_key(x))` then reads `signatures_required`, preserving strict sequential order by construction. [1](#0-0) 
- `bcs_stream::deserialize_vector` is a straightforward sequential loop (`for (i in 0..len) { v.push_back(elem_deserializer(stream)); }`) that appends each deserialized element in encoded order with a single, monotonically-advancing cursor (`stream.cur`) — there is no code path that reorders, swaps, or otherwise permutes elements regardless of their variable byte-length (e.g., keyless entries). [2](#0-1) 
- `single_key::deserialize_any_public_key` reads a 1-byte scheme tag and then dispatches to the matching variant's deserializer (`ed25519`, `secp256k1`, `keyless::deserialize_public_key`, `federated_keyless::deserialize_public_key`), each of which consumes exactly its own encoded bytes from the shared cursor before returning control to the vector loop — variable-length keyless entries do not interact with or corrupt neighboring entries' positions. [3](#0-2) 
- `to_authentication_key` then BCS re-serializes the resulting `MultiKey` struct (which is a `(public_keys: vector<AnyPublicKey>, signatures_required: u8)` struct) and hashes it with the scheme ID; since BCS serialization of a struct/vector is itself deterministic and order-preserving, any permutation of `public_keys` would produce a different serialization and thus a different `authentication_key`/account address — it would not silently validate against the original address. [4](#0-3) 
- The framework's own test suite explicitly asserts round-trip fidelity (`bcs::to_bytes(&multi_key) == mk_bytes`) for exactly this scenario, including a test with variable-length keyless entries (`test_get_authentication_key`), confirming order and field values are preserved on deserialization. [5](#0-4) 
- Downstream signature binding (`MultiKeyAuthenticator::to_single_key_authenticators`) indexes into `self.public_keys.public_keys[idx]` using the same vector produced by this deterministic deserialization, so there is no additional indirection that could misbind a signature index to the wrong key once the vector itself is correctly ordered. [6](#0-5) 

No parsing-order defect exists in this code to support the described exploit; the deserialization is a simple, deterministic, byte-cursor-based sequential loop with no swap/permutation logic for any key type, including keyless.

    public fun deserialize_any_public_key(stream: &mut bcs_stream::BCSStream): AnyPublicKey {
        let scheme_id = bcs_stream::deserialize_u8(stream);
        let pk: AnyPublicKey;
        if (scheme_id == ED25519_PUBLIC_KEY_TYPE) {
            let public_key_bytes = bcs_stream::deserialize_vector(stream, |x| deserialize_u8(x));
            pk = AnyPublicKey::Ed25519{pk: ed25519::new_unvalidated_public_key_from_bytes(public_key_bytes)}
        } else if (scheme_id == SECP256K1_PUBLIC_KEY_TYPE) {
            let public_key_bytes = bcs_stream::deserialize_vector(stream, |x| deserialize_u8(x));
            pk = AnyPublicKey::Secp256k1Ecdsa{pk: secp256k1::ecdsa_raw_public_key_from_64_bytes(public_key_bytes)};
        } else if (scheme_id == WEB_AUTHN_PUBLIC_KEY_TYPE) {
            let public_key_bytes = bcs_stream::deserialize_vector(stream, |x| deserialize_u8(x));
            pk = AnyPublicKey::Secp256r1Ecdsa{pk: secp256r1::ecdsa_raw_public_key_from_64_bytes(public_key_bytes)};
        } else if (scheme_id == KEYLESS_PUBLIC_KEY_TYPE) {
            pk = AnyPublicKey::Keyless{pk: keyless::deserialize_public_key(stream)};
        } else if (scheme_id == FEDERATED_KEYLESS_PUBLIC_KEY_TYPE) {
            pk = AnyPublicKey::FederatedKeyless{pk: federated_keyless::deserialize_public_key(stream)}
        } else {
            abort error::invalid_argument(E_INVALID_PUBLIC_KEY_TYPE);
        };
        pk
    }
