### Title
Unbounded `PendingInbounds` scan on every inbound-ballot terminal transition enables gas-cost amplification DoS - ([File: x/uexecutor/keeper/ballot_hooks.go])

### Summary
`afterInboundBallotTerminal` performs a full linear `Walk` over the entire `PendingInbounds` collection every time *any* inbound ballot reaches a terminal state (PASSED/REJECTED/EXPIRED), searching for the entry whose variant matches the finalizing `ballotID`. This is the same structural pattern as the reported "unbounded loop" bug class: an attacker-inflatable, unbounded on-chain collection that is iterated in full on every routine state-transition operation, making that operation's cost grow linearly with total accumulated (unprivileged, unbounded) state.

### Finding Description
`x/uexecutor/keeper/inbound.go` `RecordInboundVote` [1](#0-0)  creates a new `PendingInboundEntry` in the `PendingInbounds` collections.Map [2](#0-1)  for every distinct `utx_key` (`sha256(source_chain:tx_hash:log_index)`) the first time a bonded universal validator votes on it. Because honest validators vote on *every* source-chain event they observe (this is their normal job, not a privileged/malicious action), an ordinary unprivileged user can inflate the size of `PendingInbounds` simply by generating many distinct low-value/spam deposit events on any supported source chain — each becomes its own entry that persists for up to `DefaultExpiryAfterBlocks` before a terminal transition clears it.

Every time one of these ballots reaches a terminal state, `x/uvalidator`'s `MarkBallotFinalized`/`MarkBallotExpired` fires the `BallotHooks.AfterBallotTerminal` callback [3](#0-2) , which for `INBOUND_TX` ballots calls `afterInboundBallotTerminal`. That function has no index from `ballotID` back to its owning `utx_key`/entry, so it must scan **the entire `PendingInbounds` map** with `Walk`, plus a nested loop over each entry's `Variants`, to find the matching one:

```go
err := h.k.PendingInbounds.Walk(ctx, nil, func(key string, e types.PendingInboundEntry) (bool, error) {
    for _, v := range e.Variants {
        if v.BallotId == ballotID {
            utxKey, entry, found = key, e, true
            return true, nil
        }
    }
    return false, nil
})
``` [4](#0-3) 

The code comment explicitly (and incorrectly, as an invariant guarantee) assumes the set stays small: *"the pending set is small and transient, and this hook only fires on terminal transitions"* [5](#0-4) . There is no cap, no per-source-chain rate limit, and no secondary index by `ballotID`, so this assumption is not enforced by any guard in the code.

This callback runs synchronously inside the message-processing path of every `MsgVoteInbound` transaction that finalizes or expires a ballot (`VoteInbound` → `VoteOnInboundBallot` → `uvalidatorKeeper.VoteOnBallot` → `CheckIfFinalizingVote` → `MarkBallotFinalized` → `fireBallotTerminalHook`) [6](#0-5) [7](#0-6) , as well as inside the batch `ExpireBallotsBeforeHeight` sweep [8](#0-7) , which can call `MarkBallotExpired` (and thus this same walk) once per expired ballot in a single invocation.

### Impact Explanation
As `PendingInbounds` grows, the gas cost of finalizing (or expiring) *any* inbound ballot — including ballots for completely unrelated, legitimate users' deposits — grows linearly with the total number of currently-pending entries. An unprivileged attacker who continuously seeds many cheap/low-value source-chain deposits across the expiry window can inflate this collection to a size where:
- Ordinary validator votes that trigger finalization become disproportionately expensive in gas, potentially causing votes to run out of gas or become uneconomical to submit, stalling finalization of legitimate inbound transfers (denial of service on the inbound execution path, reachable "without privileged control").
- The batch `ExpireBallotsBeforeHeight` operation (if `MarkBallotExpired` also traverses this hook, since inbound EXPIRE is a terminal status handled by the same code path) suffers compounding cost: N ballots expiring in one call each trigger an O(M) walk over the (also growing) `PendingInbounds` map, giving effectively O(N×M) work.

This does not directly steal funds, but it degrades availability of the universal-execution/finalization pipeline for all users — precisely the class of harm the original report flags ("future operations of the contract too expensive... impossible to make a transfer function call").

### Likelihood Explanation
Medium. The trigger requires no validator or admin privilege — only the ability to generate many distinct source-chain events that honest, correctly-functioning validators will observe and vote on (a normal, unprivileged action such as sending numerous small/dust transactions to a supported gateway). The cost to the attacker is bounded by external-chain gas fees, which on some supported low-fee chains could be inexpensive relative to the amplified cost imposed on Push Chain's finalization path. The severity is capped by the fact that entries eventually expire after `DefaultExpiryAfterBlocks`, and by how large validators' vote transaction gas limits are configured, but no code-level circuit breaker prevents accumulation, and the design comment's "small and transient" assumption is not enforced.

### Recommendation
- Add a secondary index keyed by `ballotID -> utx_key` (populated in `RecordInboundVote`, cleaned up alongside the `PendingInbounds` entry) so `afterInboundBallotTerminal` performs an O(1)/O(log N) lookup instead of a full collection scan.
- Alternatively/in addition, embed the `utx_key` inside the ballot ID's associated metadata passed through `AfterBallotTerminal` so the hook does not need to reverse-search state at all.
- Add a per-source-chain or global cap / rate limit on concurrently-pending `PendingInbounds` entries (or lower `DefaultExpiryAfterBlocks` for unconfirmed/low-value inbounds) to bound the worst-case size of the collection independent of the indexing fix.

### Proof of Concept
Conceptual (not directly executable without a live multi-validator devnet and an external testnet source chain):
1. An unprivileged actor submits a large number (N) of small/dust deposit transactions on a cheap supported source chain to the gateway contract, each with a unique `tx_hash`/`log_index`.
2. Honest universal validators observe each event and call `MsgVoteInbound`, each creating a new distinct `PendingInboundEntry` via `RecordInboundVote` (`x/uexecutor/keeper/inbound.go:27-46`).
3. Once `PendingInbounds` contains N entries, submit/observe a legitimate, unrelated inbound vote that reaches finalization threshold. Measure the gas consumed by `afterInboundBallotTerminal`'s `PendingInbounds.Walk` (`x/uexecutor/keeper/ballot_hooks.go:86-94`) as a function of N — it grows linearly, demonstrating the unbounded-loop cost amplification and confirming no index or cap exists to bound it.

func (k Keeper) MarkBallotFinalized(ctx context.Context, id string, status types.BallotStatus) error {
	if status != types.BallotStatus_BALLOT_STATUS_PASSED && status != types.BallotStatus_BALLOT_STATUS_REJECTED {
		return fmt.Errorf("invalid finalization status: %v", status)
	}

	ballot, err := k.Ballots.Get(ctx, id)
	if err != nil {
		return err
	}

	k.Logger().Debug("marking ballot as finalized",
		"ballot_id", id,
		"final_status", status.String(),
	)

	if err := k.ActiveBallotIDs.Remove(ctx, id); err != nil {
		return err
	}
	if err := k.FinalizedBallotIDs.Set(ctx, id); err != nil {
		return err
	}

	ballot.Status = status
	if err := k.Ballots.Set(ctx, id, ballot); err != nil {
		return err
	}

	k.fireBallotTerminalHook(ctx, ballot.Id, ballot.BallotType, status)
	return nil
}

// ExpireBallotsBeforeHeight checks active ballots and marks expired ones.
// It uses a two-phase approach: first collect IDs to expire, then mutate,
// to avoid modifying the ActiveBallotIDs collection during iteration.
func (k Keeper) ExpireBallotsBeforeHeight(ctx context.Context, currentHeight int64) error {
	iter, err := k.ActiveBallotIDs.Iterate(ctx, nil)
	if err != nil {
		return err
	}

	// Phase 1: collect IDs to expire
	var toExpire []string
	for ; iter.Valid(); iter.Next() {
		id, err := iter.Key()
		if err != nil {
			iter.Close()
			return err
		}

		ballot, err := k.Ballots.Get(ctx, id)
		if err != nil {
			iter.Close()
			return err
		}

		if ballot.BlockHeightExpiry <= currentHeight {
			toExpire = append(toExpire, id)
		}
	}

	// Close iterator explicitly before mutation phase to release the IAVL snapshot
	iter.Close()

	if len(toExpire) > 0 {
		k.Logger().Debug("expiring stale ballots", "count", len(toExpire), "current_height", currentHeight)
	}

	// Phase 2: expire collected ballots (safe — iterator is closed)
	for _, id := range toExpire {
		if err := k.MarkBallotExpired(ctx, id); err != nil {
			return err
		}
	}

	return nil
}

// CheckIfFinalizingVote inspects whether the just-cast vote pushes the ballot
// over its threshold and, if so, drives the finalization through
// MarkBallotFinalized — the single canonical write path for terminal status
// transitions, which applies CEI-style ordering on the secondary indexes.
func (k Keeper) CheckIfFinalizingVote(ctx context.Context, b types.Ballot) (types.Ballot, bool, error) {
	ballot, isFinalizing := b.IsFinalizingVote()
	if !isFinalizing {
		return b, false, nil
	}

	k.Logger().Debug("ballot reached finalization threshold",
		"ballot_id", ballot.Id,
		"ballot_status", ballot.Status.String(),
	)

	if err := k.MarkBallotFinalized(ctx, ballot.Id, ballot.Status); err != nil {
		return ballot, false, errors.Wrap(err, "failed updating finalized ballot")
	}

	k.Logger().Debug("ballot finalized",
		"ballot_id", ballot.Id,
		"ballot_status", ballot.Status.String(),
	)
	return ballot, true, nil
}

func (k Keeper) VoteOnInboundBallot(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	inbound types.Inbound,
) (isFinalized bool,
	isNew bool,
	err error) {
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return false, false, err
	}

	universalValidatorSet, err := k.uvalidatorKeeper.GetEligibleVoters(ctx)
	if err != nil {
		return false, false, err
	}

	// number of validators
	totalValidators := len(universalValidatorSet)

	// votesNeeded = ceil(2/3 * totalValidators)
	// >2/3 quorum similar to tendermint
	votesNeeded := (types.VotesThresholdNumerator*totalValidators)/types.VotesThresholdDenominator + 1

	k.Logger().Debug("voting on inbound ballot",
		"ballot_key", ballotKey,
		"validator", universalValidator.String(),
		"total_validators", totalValidators,
		"votes_needed", votesNeeded,
	)

	// Convert []sdk.ValAddress → []string
	universalValidatorSetStrs := make([]string, len(universalValidatorSet))
	for i, v := range universalValidatorSet {
		universalValidatorSetStrs[i] = v.IdentifyInfo.CoreValidatorAddress
	}

	// Step 2: Call VoteOnBallot for this inbound synthetic
	_, isFinalized, isNew, err = k.uvalidatorKeeper.VoteOnBallot(
		ctx,
		ballotKey,
		uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
		universalValidator.String(),
		uvalidatortypes.VoteResult_VOTE_RESULT_SUCCESS,
		universalValidatorSetStrs,
		int64(votesNeeded),
		int64(types.DefaultExpiryAfterBlocks),
	)
	if err != nil {
		return false, false, err
	}

	if isNew {
		k.Logger().Debug("inbound ballot created", "ballot_key", ballotKey)
	}
	if isFinalized {
		k.Logger().Info("inbound ballot finalized", "ballot_key", ballotKey, "source_chain", inbound.SourceChain)
	}

	return isFinalized, isNew, nil
}
