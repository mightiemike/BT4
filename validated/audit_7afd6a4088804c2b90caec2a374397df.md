### Title
Spot-price-only slippage check on PRC20→PC auto-swaps enables sandwich/frontrun extraction of bridged deposit value - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The `x/uexecutor` deposit-with-autoswap and gas-refund-with-autoswap flows compute their `minPCOut` slippage floor from an **instantaneous** Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote fetched in the same transaction, immediately before the swap itself executes. Because the reference price and the execution price are drawn from the same, unprotected pool state within the same atomic transaction, an attacker who can insert a swap transaction ahead of the module's transaction in the same block can move the pool price first — degrading the "fair" quote itself — and the fixed 5% buffer only protects against staleness/movement *after* the corrupted quote is taken, not against the manipulation that already occurred. This mirrors the reported bug class (Uniswap `PoolHelper.sol`/`LiquidityZap.sol`/`BalancerPoolHelper.sol` not validating real `amountOut` against manipulation), reimplemented natively in Push Chain's own registry/executor code rather than in the external DEX helper contracts.

### Finding Description
`GetSwapQuote` calls the live `QuoterV2.quoteExactInputSingle` for the current block/pool state [2](#0-1) . Immediately afterward, `minPCOut` is derived as `quote * 95 / 100` and passed straight into `CallPRC20DepositAutoSwap`, which performs the actual `depositPRC20WithAutoSwap` swap on the same pool [3](#0-2) . The identical pattern is used for `GAS_AND_PAYLOAD` inbounds in `gasAndPayloadDepositAutoSwap` [4](#0-3) , and for excess-gas refunds in `applyGasRefund`, which fetches a quote via `getSwapQuoteForRefund` and applies the same 95% floor before calling `CallUniversalCoreRefundUnusedGas` [5](#0-4) .

Because `MsgVoteInbound` executes the inbound synchronously — `VoteInbound` calls `k.ExecuteInbound(ctx, utx)` directly the moment the ballot finalizes [1](#0-0)  — the quote fetch and the swap execution occur back-to-back in the same block/transaction. Validator `MsgVoteInbound` transactions are ordinary, gasless-but-authz-wrapped transactions visible in the public mempool before being included in a block; the amount and token being swapped are derivable from the pending inbound. An attacker can therefore: (1) observe an approaching ballot finalization for a large `GAS`/`GAS_AND_PAYLOAD` deposit, (2) submit a higher-gas-price swap on the same Uniswap V3 pool ahead of the finalizing `MsgVoteInbound` in the target block to move the pool's spot price unfavorably for the upcoming prc20→WPC swap, (3) let the module's `GetSwapQuote` read this manipulated price and compute `minPCOut` as merely 95% of the already-degraded rate, and (4) reverse the position after the module's swap executes, capturing the price impact that was supposed to be delivered to the bridging user (or protocol) as PC/WPC.

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound deposit, and every outbound gas refund that opts for `withSwap=true`, routes user or protocol value through this atomically-manipulable price check. Since the check floor is derived from the manipulated spot price rather than any manipulation-resistant reference (e.g., a TWAP oracle or an off-chain/committed price bound), the 5% tolerance can be exploited to extract most of a large swap's economic value from ordinary bridging users, resulting in silent, permanent value loss on funds that are supposed to convert into native PC for the recipient's UEA. This falls within scope as loss of user/protocol-controlled funds arising from a corrupted accounting value (`minPCOut`) in the universal execution/gas-accounting path, reachable purely from ordinary deposit and mempool activity.

### Likelihood Explanation
Requires no privileged role: any external actor watching the public mempool for pending `MsgVoteInbound` transactions (and thus upcoming autoswap executions) and controlling sufficient capital/flash-loanable liquidity on the target Uniswap V3 pool can attempt this. Profitability scales with deposit size and pool depth, so it is most attractive against large deposits or thin PRC20↔WPC pools, but the flaw is structurally present on every autoswap and refund-with-swap call, making it a repeatable, not one-off, extraction vector.

### Recommendation
Do not derive the slippage floor from a spot quote taken in the same transaction as the swap. Use a manipulation-resistant reference price (e.g., a TWAP over a meaningful window from the same Uniswap V3 pool via `observe()`, or an external price oracle) to compute `minPCOut`, and/or bound the allowed deviation between the executed price and that independent reference rather than between the swap and its own just-fetched spot quote. Consider also capping per-block price impact or splitting very large deposits to limit attacker profitability.

### Proof of Concept
1. UV client broadcasts `MsgVoteInbound` votes for a large `GAS_AND_PAYLOAD` deposit of token `X`; the last vote needed to cross the 2/3 threshold is visible in the public mempool.
2. Attacker submits (with a higher gas price / earlier placement) a large `X → WPC` swap directly on the same Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetSwapQuote`, pushing the pool's spot price against subsequent `X → WPC` conversions.
3. The finalizing `MsgVoteInbound` executes in the same block: `GetSwapQuote` reads the now-manipulated spot price, `minPCOut = quote * 95 / 100` is computed off that bad price, and `CallPRC20DepositAutoSwap` executes the deposit swap at (or near) the manipulated rate — succeeding because it clears the (also-manipulated) 95% floor.
4. Attacker reverses the swap in the same or next block, extracting the price impact from the pool as profit, while the bridging user's UEA receives materially less PC/WPC than fair-market conversion would have produced.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
