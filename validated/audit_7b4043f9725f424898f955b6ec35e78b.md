### Title
`TokenConfig.Enabled` registry flag is defined but never enforced on any inbound/outbound money-moving path - (File: `x/uregistry/keeper/keeper.go`, `x/uexecutor/keeper/*`)

### Summary
The `uregistry` module models a per-token "kill switch": `TokenConfig.enabled` is documented as "Whether this token is enabled for minting/bridging" [1](#0-0) . Unlike `ChainConfig.Enabled` (`IsInboundEnabled`/`IsOutboundEnabled`), which is actively checked before every vote-inbound, payload execution, and outbound-build step [2](#0-1) [3](#0-2) , the token-level `Enabled` field is never read anywhere in the module's execution logic. This is the direct analog of the reported bug class: a deactivation flag exists in a registry to gate value-moving operations, but one execution surface (here: essentially *all* PRC20 mint/deposit/outbound/rescue flows) does not check it.

### Finding Description
`GetTokenConfig` / `GetTokenConfigByPRC20` are the only accessors used throughout `x/uexecutor` to resolve a token's PRC20 address and native representation before minting/depositing funds [4](#0-3) [5](#0-4) . Every call site that consumes the returned `TokenConfig` — `depositPRC20` (used by inbound funds/payload execution) [6](#0-5) , `BuildOutboundsFromReceipt` (outbound creation) [7](#0-6) , `buildRevertOutbound` (inbound-revert path) [8](#0-7) , and rescue-outbound handling [9](#0-8)  — only reads `NativeRepresentation`/`Address`/existence, never `tokenConfig.Enabled`. Only chain-level enablement (`IsChainInboundEnabled`/`IsChainOutboundEnabled`) is checked at the analogous points [10](#0-9) . A codebase-wide search for any read of the token's `Enabled` field outside of protobuf marshal/unmarshal boilerplate and its own setter (`AddTokenConfig`/`UpdateTokenConfig`, which merely persist it without semantic effect) [11](#0-10)  turns up nothing in `x/uexecutor` or `universalClient`.

### Impact Explanation
Push Chain's own documentation states the field exists specifically so an admin can disable a token "for minting/bridging" [12](#0-11) , presumably as an emergency circuit breaker (e.g., a compromised, depegged, or exploited external token). Because no execution path reads it, an ordinary unprivileged user can continue to trigger inbound deposits (PRC20 minting), CEA/UEA payload deposits, outbound withdrawals, revert-outbounds, and rescue-outbounds for a token the admin believes is disabled. This can result in unauthorized minting/movement of PRC20 balances for an asset that was intentionally frozen, defeating the intended safety control and potentially compounding losses from whatever incident triggered the disable action in the first place.

### Likelihood Explanation
High reachability from a purely unprivileged trigger: any user submitting a normal inbound deposit (`MsgVoteInbound` from honest validators observing a normal external-chain transfer) or normal outbound-triggering transaction exercises `depositPRC20`/`BuildOutboundsFromReceipt`, none of which consult `TokenConfig.Enabled`. No malicious validator/relayer/admin assumption is required — the gap is purely a missing check in code that already executes on every honest, ordinary transaction for that token. The only precondition is that an admin has previously flipped `Enabled=false` on a `TokenConfig` (an admin action, but the *exploitation* is fully unprivileged and requires no compromise).

### Recommendation
Add an explicit `tokenConfig.Enabled` check, mirroring the existing `IsChainInboundEnabled`/`IsChainOutboundEnabled` pattern, at every point a token is about to be minted/deposited/withdrawn:
- In `depositPRC20` (`x/uexecutor/keeper/handler.go`) before calling `CallPRC20Deposit`.
- In `BuildOutboundsFromReceipt` (`x/uexecutor/keeper/create_outbound.go`) alongside the existing outbound-enabled check.
- In `buildRevertOutbound` and rescue-outbound construction paths.
Reject with a clear error (analogous to `"inbound is disabled for chain %s"`) when the token is disabled, and ensure the resulting UniversalTx still records a FAILED PCTx/UTX for observability, consistent with the module's stated behavior of always creating a UTX on ballot finalization.

### Proof of Concept
1. Admin adds `ChainConfig` (inbound/outbound enabled) and `TokenConfig{Address: usdc, Enabled: true}` for `eip155:11155111` (as in `setupChainEnabledTest`) [13](#0-12) .
2. Admin later calls `MsgUpdateTokenConfig` with `Enabled: false` to disable the token after detecting an issue (e.g., compromised bridge asset). `UpdateTokenConfig` persists this with no other side effects [14](#0-13) .
3. A user still sends funds on the external chain and validators vote `MsgVoteInbound` for that asset. `VoteInbound` only checks `IsChainInboundEnabled`, not the token's `Enabled` flag [2](#0-1) .
4. Once quorum is reached, `ExecuteInboundFundsAndPayload` calls `depositPRC20`, which looks up `GetTokenConfig` and proceeds to `CallPRC20Deposit` regardless of `Enabled` [15](#0-14) .
5. Result: PRC20 tokens are minted to the recipient for an asset the admin intended to be frozen — identical in nature to the referenced report where a "deactivated" resource continues to be usable through an execution path that was never updated to check its state.

*Note: verification was limited to static grep/codebase-search of the indexed snippets; I could not execute the code to dynamically confirm no check exists elsewhere (e.g., in an ante handler or precompile not surfaced by search). If such a check exists outside the indexed files, this finding would not apply.*

```go
func (k Keeper) GetTokenConfigByPRC20(
	ctx context.Context,
	chain string,
	prc20Addr string,
) (types.TokenConfig, error) {

	if strings.TrimSpace(prc20Addr) == "" {
		return types.TokenConfig{}, fmt.Errorf("prc20 address is empty")
	}
	// Same canonical form as the index function, so any case variant hits the row.
	prc20Addr = canonicalPRC20(prc20Addr)

	// PRC20 addresses are globally unique by construction; MatchExact returns at most one.
	iter, err := k.TokenConfigs.Indexes.PRC20Index.MatchExact(ctx, prc20Addr)
	if err != nil {
		return types.TokenConfig{}, err
	}
	defer iter.Close()

	for ; iter.Valid(); iter.Next() {
		pk, err := iter.PrimaryKey()
		if err != nil {
			return types.TokenConfig{}, err
		}
		cfg, err := k.TokenConfigs.Get(ctx, pk)
		if err != nil {
			return types.TokenConfig{}, err
		}
		if cfg.Chain == chain {
			return cfg, nil
		}
	}

	return types.TokenConfig{}, collections.ErrNotFound
}
```

```go
func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}
```

```go
// UpdateTokenConfig updates an existing token configuration in the uregistry.
func (k Keeper) UpdateTokenConfig(ctx context.Context, tokenConfig *types.TokenConfig) error {
	storageKey := types.GetTokenConfigsStorageKey(tokenConfig.Chain, tokenConfig.Address)

	// Check if the token config exists
	if has, err := k.TokenConfigs.Has(ctx, storageKey); err != nil {
		return err
	} else if !has {
		return fmt.Errorf("token config for %s on chain %s does not exist", tokenConfig.Address, tokenConfig.Chain)
	}

	if err := k.TokenConfigs.Set(ctx, storageKey, *tokenConfig); err != nil {
		return err
	}
	k.Logger().Info("token config updated",
		"chain", tokenConfig.Chain,
		"token_address", tokenConfig.Address,
	)
	return nil
}
```
