## Finding

### Title
Nakamoto block identity (`block_hash`/`block_id`) omits `signer_signature`, letting a mutated/invalid signer-signature set poison the staging-DB slot for a valid block body - ([File: stackslib/src/chainstate/nakamoto/mod.rs])

### Summary
`NakamotoBlockHeader::block_hash()` is defined to be identical to `signer_signature_hash()` - both exclude the `signer_signature` field from the hash preimage. The Nakamoto staging-blocks DB keys and deduplicates stored blocks by `(consensus_hash, block_hash)`, explicitly treating "block hash" and "sighash" as the same identity for a given tenure/body. This is structurally the same malleability class as the Zcash NU5 issue: a field (`signer_signature`, analogous to `scriptSig`/authorizing data) can be swapped out by anyone relaying the block without altering the value used to key/identify the block, while a separate downstream check (`verify_signer_signatures`, analogous to `CheckBlock()`'s sigops check) validates that mutable field and can fail independently of the block's core commitment (`tx_merkle_root`, `state_index_root`, `miner_signature`, etc.).

### Finding Description
`block_hash()` and `block_id()` are computed as: [1](#0-0) 

which calls `signer_signature_hash_inner()`, the same function backing `signer_signature_hash()`: [2](#0-1) 

Both hashes cover `version, chain_length, burn_spent, consensus_hash, parent_block_id, tx_merkle_root, state_index_root, timestamp, miner_signature, pox_treatment, problematic_txs` - but explicitly **exclude `signer_signature`**.

The staging-blocks store keys and deduplicates entries on exactly `(consensus_hash, block_hash)`, with the code comment stating "the block hash and sighash are the same for Nakamoto blocks, so this is equivalent to storing a new block": [3](#0-2) 

Separately, `verify_signer_signatures` validates the (unhashed) `signer_signature` vector against the reward set - recovering a public key per signature, checking reward-set membership, enforcing strict ordering, and enforcing a minimum signing-weight threshold, returning `ChainstateError::InvalidStacksBlock` on any failure: [4](#0-3) 

Because `signer_signature` is not part of `block_hash()`/`block_id()`, an unprivileged network relay can take a legitimately-produced block and swap its `signer_signature` vector for garbage, a truncated/insufficient-weight subset, or out-of-order signatures, **without changing the block's hash or block_id**. This mutated copy is a different byte-for-byte serialization but is treated by the staging DB as "the same block" for identity/dedup purposes.

### Impact Explanation
This breaks the equality that "the value used to identify/dedupe a Nakamoto block equals the value that must be reproducible and equally validated by every node." If the mutated copy (invalid `signer_signature`) reaches a node's staging DB or is processed via `try_store_block_with_new_signer_sighash`/dedup logic first, the legitimate block with the correct, threshold-satisfying `signer_signature` shares the exact same `(consensus_hash, block_hash)` key. Depending on how the "already have this block_hash" and "already processed/rejected" bookkeeping interacts with `verify_signer_signatures` failures during full block acceptance, this is a minority-triggerable vector for a node to end up stuck believing the tenure's block is invalid/duplicate while the network's true signer-approved body for the same `block_id` cannot be substituted in - producing a temporary tip disagreement or block-processing stall for affected nodes, the same class of denial as the Zcash `bad-blk-sigops`/`duplicate-invalid` interaction. I was not able to fully trace, within the available tool budget, the exact call site that marks a staging row `processed`/`orphaned` on a `verify_signer_signatures` failure (i.e., whether that marking is permanent or can be superseded), so I cannot confirm whether recovery is possible via `replace_block`, which does exist for "replac[ing] an already-stored block with a newer copy with more signing power": [5](#0-4) 

The existence of `replace_block` suggests the authors anticipated a similar "same identity, different signature set" scenario and built a repair path, which may already substantially mitigate the poisoning severity relative to the Zcash case - but I could not verify from the code inspected whether `replace_block` is reachable once a block has been marked `processed=1`/`orphaned=1` after failing `verify_signer_signatures`.

### Likelihood Explanation
Any peer that receives and relays a Nakamoto block, or any single non-majority actor with network position, can perform this mutation - it requires no stake, no signing key, and no majority of signers. The precondition is purely a race: the mutated (invalid-signature) copy must be seen/processed before or in place of the legitimately-signed copy for the same `block_hash`.

### Recommendation
Confirm whether `try_store_block_with_new_signer_sighash`/dedup logic and the `verify_signer_signatures`-failure handling path allow a subsequently-received, correctly-signed block with the same `block_hash` to override a previously-stored bad-signature copy (via `replace_block` or equivalent) before it is marked `processed`/`orphaned`. If not, either (a) include `signer_signature` (or a threshold-independent commitment to it, such as a merkle root of participating signer pubkeys) in the value used to key/dedupe staging rows, or (b) ensure that a `verify_signer_signatures` failure never marks the `(consensus_hash, block_hash)` slot in a way that blocks a later, correctly-signed resubmission for the same hash.

### Proof of Concept
1. Observe a valid, fully-signed Nakamoto block `B` with `signer_signature` satisfying the weight threshold, and note `block_id = StacksBlockId::new(consensus_hash, block_hash())`.
2. Construct `B'` = `B` with `header.signer_signature` replaced by garbage/insufficient-weight/out-of-order signatures. Since `block_hash()`/`signer_signature_hash()` exclude `signer_signature`, `B'.header.block_hash() == B.header.block_hash()` and `B'.block_id() == B.block_id()`.
3. Relay `B'` to a victim node before `B` arrives. The staging DB accepts/records it keyed by `(consensus_hash, block_hash)` per `try_store_block_with_new_signer_sighash`/`has_nakamoto_block_with_block_hash`.
4. When the node attempts to append `B'`, `verify_signer_signatures` fails (insufficient weight / bad recovered pubkey / out-of-order), yielding `ChainstateError::InvalidStacksBlock`.
5. Determine (unresolved in this analysis due to tool-call limits) whether the node's bookkeeping then refuses to accept the legitimately-signed `B` for the same `block_hash`/`block_id`, reproducing the Zcash `bad-blk-sigops` → `duplicate-invalid` poisoning pattern.

    /// This includes all fields _except_ the stacker signature.
    fn signer_signature_hash_inner(&self) -> Result<Sha512Trunc256Sum, CodecError> {
        let mut hasher = Sha512_256::new();
        let fd = &mut hasher;
        write_next(fd, &self.version)?;
        write_next(fd, &self.chain_length)?;
        write_next(fd, &self.burn_spent)?;
        write_next(fd, &self.consensus_hash)?;
        write_next(fd, &self.parent_block_id)?;
        write_next(fd, &self.tx_merkle_root)?;
        write_next(fd, &self.state_index_root)?;
        write_next(fd, &self.timestamp)?;
        write_next(fd, &self.miner_signature)?;
        write_next(fd, &self.pox_treatment)?;
        if Self::version_includes_problematic_txs(self.version) {
            write_next(fd, &self.problematic_txs)?;
        }
        Ok(Sha512Trunc256Sum::from_hasher(hasher))
    }

    #[cfg_attr(test, mutants::skip)]
    pub fn verify_signer_signatures(
        &self,
        reward_set: &RewardSet,
        epoch_id: StacksEpochId,
    ) -> Result<u32, ChainstateError> {
        let message = self.signer_signature_hash();
        let Some(signers) = reward_set.signers() else {
            return Err(ChainstateError::InvalidStacksBlock(
                "No signers in the reward set".to_string(),
            ));
        };

        // if this is a shadow block, then its signing weight is as if every signer signed it, even
        // though the signature vector is undefined.
        if self.is_shadow_block() {
            return Ok(self.get_shadow_signer_weight(reward_set)?);
        }

        let mut total_weight_signed: u32 = 0;
        // `last_index` is used to prevent out-of-order signatures
        let mut last_index = None;
        // Before Epoch 4.0, signature order check contained a bug, so gate the
        // strict ordering behavior on the epoch.
        let strict_order = epoch_id.enforces_strict_signature_order();

        let total_weight = reward_set
            .total_signing_weight()
            .map_err(|_| ChainstateError::NoRegisteredSigners(0))?;

        // HashMap of <PublicKey, (Signer, Index)>
        let mut signers_by_pk: HashMap<_, _> = signers
            .iter()
            .enumerate()
            .map(|(i, signer)| (&signer.signing_key, (signer, i)))
            .collect();

        for signature in self.signer_signature.iter() {
            let public_key = Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s(
                message.bits(),
                signature,
            )
            .map_err(|_| {
                ChainstateError::InvalidStacksBlock(format!(
                    "Unable to recover public key from signature {}",
                    signature.to_hex()
                ))
            })?;

            let mut public_key_bytes = [0u8; 33];
            public_key_bytes.copy_from_slice(&public_key.to_bytes_compressed()[..]);

            let (signer, signer_index) = signers_by_pk.remove(&public_key_bytes).ok_or_else(|| {
                warn!(
                    "Found an invalid public key. Reward set has {} signers. Chain length {}. Signatures length {}",
                    signers.len(),
                    self.chain_length,
                    self.signer_signature.len(),
                );
                ChainstateError::InvalidStacksBlock(format!(
                    "Public key {} not found in the reward set",
                    public_key.to_hex()
                ))
            })?;

            // Enforce order of signatures
            if let Some(index) = last_index.as_ref() {
                if *index >= signer_index {
                    return Err(ChainstateError::InvalidStacksBlock(
                        "Signatures are out of order".to_string(),
                    ));
                }
                if strict_order {
                    last_index = Some(signer_index);
                }
            } else {
                last_index = Some(signer_index);
            }

            total_weight_signed = total_weight_signed
                .checked_add(signer.weight)
                .expect("FATAL: overflow while computing signer set threshold");
        }

        let threshold = Self::compute_voting_weight_threshold(total_weight)?;

        if total_weight_signed < threshold {
            return Err(ChainstateError::InvalidStacksBlock(format!(
                "Not enough signatures. Needed at least {} but got {} (out of {})",
                threshold, total_weight_signed, total_weight,
            )));
        }

        return Ok(total_weight_signed);
    }

    /// Do we have a block with the given signer sighash?
    /// NOTE: the block hash and sighash are the same for Nakamoto blocks
    fn has_nakamoto_block_with_block_hash(
        &self,
        consensus_hash: &ConsensusHash,
        block_hash: &BlockHeaderHash,
    ) -> Result<bool, ChainstateError> {
        let qry =
            "SELECT 1 FROM nakamoto_staging_blocks WHERE consensus_hash = ?1 AND block_hash = ?2";
        let args = rusqlite::params![consensus_hash, block_hash];
        let present: Option<u32> = query_row(self, qry, args)?;
        Ok(present.is_some())
    }

    /// Store a block into the staging DB if its sighash has never been seen before.
    /// NOTE: the block hash and sighash are the same for Nakamoto blocks, so this is equivalent to
    /// storing a new block.
    /// Return true if stored; false if not.
    /// NOTE: This should not be made public
    fn try_store_block_with_new_signer_sighash(
        &self,
        block: &NakamotoBlock,
        burn_attachable: bool,
        signing_weight: u32,
        obtain_method: NakamotoBlockObtainMethod,
    ) -> Result<bool, ChainstateError> {
        let block_hash = block.header.block_hash();
        if self.has_nakamoto_block_with_block_hash(&block.header.consensus_hash, &block_hash)? {
            return Ok(false);
        }
        self.store_block(block, burn_attachable, signing_weight, obtain_method)?;
        Ok(true)
    }

        &self,
        block: &NakamotoBlock,
        signing_weight: u32,
        obtain_method: NakamotoBlockObtainMethod,
    ) -> Result<(), ChainstateError> {
        self.execute("UPDATE nakamoto_staging_blocks SET data = ?1, signing_weight = ?2, obtain_method = ?3 WHERE consensus_hash = ?4 AND block_hash = ?5",

                        &block.serialize_to_vec(),
                        &signing_weight,
                        &obtain_method.to_string(),
                        &block.header.consensus_hash,
                        &block.header.block_hash(),
                    ])?;
        Ok(())
    }
