### Title
Unbounded prefix-scan + sort in `DelegatedResourceAccountIndexStore.getWithPrefix` allows attacker-inflated per-address index to cause disproportionate CPU cost on unauthenticated `getDelegatedResourceAccountIndex` RPC/HTTP/gRPC calls - ([File: chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java])

### Summary
`DelegatedResourceAccountIndexStore.getWithPrefix` performs two unbounded `prefixQuery` range scans and materializes/sorts the full result set with `Comparator.comparing(...::getTimestamp)` on every call to `getIndex`/`getV2Index`, with no pagination or entry cap [1](#0-0) . Because `DelegateResourceActuator.execute` writes a new `TO_PREFIX+receiver+sender` index entry for every distinct sender that delegates to a given receiver [2](#0-1) , an attacker who controls many distinct funded accounts can grow one address's index to tens of thousands of entries, after which the free, unauthenticated `Wallet.getDelegatedResourceAccountIndex` call [3](#0-2)  becomes expensive to serve.

### Finding Description
`getWithPrefix` runs `prefixQuery(key)` for `FROM_PREFIX`/`TO_PREFIX` (or V2 variants), copies all matched values into an `ArrayList`, and sorts by timestamp with no size limit [1](#0-0) . `prefixQuery` itself scans both the root DB and any open snapshot layers and merges results into a `HashMap` [4](#0-3) , so cost scales with the number of stored edges for that address, not with any query parameter the caller controls.

This method is reachable from a completely unauthenticated read path: `GetDelegatedResourceAccountIndexServlet` (HTTP), the JSON-RPC/gRPC equivalents, and `Wallet.getDelegatedResourceAccountIndex`/`getDelegatedResourceAccountIndexV2` all call straight into `getIndex`/`getV2Index` with only an address-format check, no ACL, no result-size limit [5](#0-4) [3](#0-2) .

To grow the index for a target address, an attacker needs distinct owner accounts each issuing a `DelegateResourceContract` to that address. `DelegateResourceActuator.validate()` only requires `delegateBalance >= 1 TRX` of available frozen V2 balance and a valid, existing receiver account that is not a contract [6](#0-5) [7](#0-6) ; `calcFee()` returns `0` [8](#0-7) , so the only real costs are the 1 TRX minimum frozen balance per sender account and ordinary transaction bandwidth. Each successful delegation writes one `TO_PREFIX+receiver+sender` entry via `delegatedResourceAccountIndexStore.delegateV2` [9](#0-8) , which is exactly the data structure iterated and sorted by `getWithPrefix`.

None of the existing protections (signature validation, address-format checks, actuator `validate()`, fork gates, bandwidth/energy metering) limit the *number of distinct edges* an address can accumulate, nor do they limit query-time work — metering applies to write-side transaction cost, not to the O(n log n) read-side cost imposed on every future caller.

### Impact Explanation
This is a DoS-via-RPC-API concern: once an address's delegation index is inflated, every subsequent unauthenticated `getDelegatedResourceAccountIndex`/`getDelegatedResourceAccountIndexV2` call (HTTP `/wallet/getdelegatedresourceaccountindex`, gRPC, JSON-RPC-backed paths) forces the full node to perform two prefix scans and two full sorts over the attacker-inflated edge set. A handful of concurrent callers against a heavily-populated address can multiply CPU consumption per request, degrading the node's ability to serve other JSON-RPC/HTTP/gRPC clients — consistent with the "DoS via RPC-API" impact class.

### Likelihood Explanation
The attack is technically unprivileged (no witness/SR/committee role, no leaked keys), but it is not cheap or instantaneous: to build 10k+ distinct edges against one address, the attacker needs 10k+ *distinct funded* accounts, each holding at least 1 TRX of frozen V2 balance, each broadcasting its own signed `DelegateResourceContract` transaction, consuming real bandwidth/chain throughput and taking many blocks to confirm (transactions cannot be batched into one sender because the index only grows with distinct `from` addresses). This requires meaningful upfront capital (~10k+ TRX plus account-creation/bandwidth costs) and sustained on-chain activity over time, which is a real but non-trivial precondition — it is not a "free" or instant attack. The read side itself is trivially repeatable and free once the state exists, and there is no pagination or per-address cap to prevent the state from growing arbitrarily large.

### Recommendation
- Add pagination/limit parameters (offset/limit) to `getWithPrefix`/`getIndex`/`getV2Index` and the corresponding RPC/HTTP/gRPC handlers so a single query cannot force scanning/sorting an unbounded number of entries.
- Alternatively/additionally, cap the number of distinct delegation index entries maintained per address (enforced in `DelegateResourceActuator.validate()`), rejecting further delegations once a configurable maximum is reached.
- Consider storing index entries pre-sorted (e.g., by using a sorted key encoding that embeds the timestamp) so no in-memory sort is needed at query time, reducing the marginal cost of large result sets.

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }

  private void delegateResource(byte[] ownerAddress, byte[] receiverAddress, boolean isBandwidth,
                                long balance, boolean lock, long lockPeriod) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicPropertiesStore = chainBaseManager.getDynamicPropertiesStore();
    DelegatedResourceStore delegatedResourceStore = chainBaseManager.getDelegatedResourceStore();
    DelegatedResourceAccountIndexStore delegatedResourceAccountIndexStore = chainBaseManager
        .getDelegatedResourceAccountIndexStore();

    // 1. unlock the expired delegate resource
    long now = chainBaseManager.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    delegatedResourceStore.unLockExpireResource(ownerAddress, receiverAddress, now);

    //modify DelegatedResourceStore
    long expireTime = 0;
    if (lock) {
      expireTime = now + lockPeriod * BLOCK_PRODUCED_INTERVAL;
    }
    byte[] key = DelegatedResourceCapsule.createDbKeyV2(ownerAddress, receiverAddress, lock);
    DelegatedResourceCapsule delegatedResourceCapsule = delegatedResourceStore.get(key);
    if (delegatedResourceCapsule == null) {
      delegatedResourceCapsule = new DelegatedResourceCapsule(ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
    }

    if (isBandwidth) {
      delegatedResourceCapsule.addFrozenBalanceForBandwidth(balance, expireTime);
    } else {
      delegatedResourceCapsule.addFrozenBalanceForEnergy(balance, expireTime);
    }
    delegatedResourceStore.put(key, delegatedResourceCapsule);

    //modify DelegatedResourceAccountIndexStore
    delegatedResourceAccountIndexStore.delegateV2(ownerAddress, receiverAddress,
        dynamicPropertiesStore.getLatestBlockHeaderTimestamp());

  public Map<WrappedByteArray, byte[]> prefixQuery(byte[] key) {
    Map<WrappedByteArray, byte[]> result = prefixQueryRoot(key);
    Map<WrappedByteArray, byte[]>  snapshot = prefixQuerySnapshot(key);
    result.putAll(snapshot);
    result.entrySet().removeIf(e -> e.getValue() == null);
    return result;
  }

  private Map<WrappedByteArray, byte[]> prefixQueryRoot(byte[] key) {
    Map<WrappedByteArray, byte[]> result = new HashMap<>();
    if (((SnapshotRoot) head.getRoot()).db.getClass() == LevelDB.class) {
      result = ((LevelDB) ((SnapshotRoot) head.getRoot()).db).getDb().prefixQuery(key);
    } else if (((SnapshotRoot) head.getRoot()).db.getClass() == RocksDB.class) {
      result = ((RocksDB) ((SnapshotRoot) head.getRoot()).db).getDb().prefixQuery(key);
    }
    return result;
  }
