### Title
Unbounded memory amplification via unbounded `strings.Split` on attacker-controlled `FieldMask` JSON string - (File: encoding/protojson/well_known_types.go)

### Summary
`protojson.Unmarshal` (the default ProtoJSON decoder) splits the entire user-supplied `FieldMask` JSON string on every comma via `strings.Split` before performing any length or path-validity check, allowing an attacker to force allocation of a large slice of string headers with a single crafted comma-heavy string.

### Finding Description
The JSON representation of the well-known `google.protobuf.FieldMask` type is a single string with paths separated by commas [1](#0-0) . When protojson decodes a message containing this well-known type, `unmarshalFieldMask` reads the whole JSON string token and immediately calls `strings.Split(str, ",")` on the entire, attacker-controlled contents, with no prior bound on the string length or number of separators: [2](#0-1) 

`strings.Split` allocates a single backing array holding one string header (16 bytes on 64-bit platforms) per delimiter-separated element. Because the split is performed unconditionally on the raw token before any per-path validation runs, a string consisting almost entirely of comma characters (e.g. `","` repeated N times) forces an eager allocation of an (N+1)-element `[]string` — an amplification of roughly 16x the size of the malicious substring — even though the very first loop iteration will immediately fail validation (`protoreflect.FullName("").IsValid()` returns false for the empty path produced between consecutive commas) and return an error: [3](#0-2) 

This mirrors the reported bug class exactly: an unbounded, untrusted string is split on a separator character before any validation gate, producing an allocation whose size scales with the number of separators in the input rather than with any bounded, pre-validated quantity — CWE-405 (Asymmetric Resource Consumption).

### Impact Explanation
Any unprivileged caller who can submit ProtoJSON containing a message with a `google.protobuf.FieldMask` field (a very common pattern for partial-update/`update_mask` parameters in JSON/gRPC-gateway style APIs) can force the server process to allocate memory proportional to the number of commas in the submitted string, well before any content validation occurs. Repeated or large requests can drive up memory/GC pressure and cause service degradation or crash (availability impact), consistent with the "S" and "A:H" components of the referenced advisory's CVSS vector.

### Likelihood Explanation
The `FieldMask` well-known type is part of the standard protobuf JSON mapping and is unmarshaled automatically by `protojson.Unmarshal` for any message referencing it — no custom resolver, malicious descriptor, or elevated privilege is required. Any endpoint that accepts protojson input containing a `FieldMask` field is exposed by default.

### Recommendation
Bound the size of the FieldMask string (or the number of comma-delimited segments) before splitting, or replace the eager `strings.Split` with an incremental/iterative parser (similar to the allocation-avoiding `rangeFields` helper already used elsewhere in the codebase for FieldMask path traversal [4](#0-3) ) that validates each path as it is scanned and aborts on the first invalid/empty segment without pre-allocating a full slice of all path elements.

### Proof of Concept
```go
package main

import (
	"fmt"
	"strings"

	"google.golang.org/protobuf/encoding/protojson"
	"google.golang.org/protobuf/types/known/fieldmaskpb"
)

func main() {
	// Craft a huge comma-only string; each comma forces one extra
	// 16-byte string-header allocation in strings.Split before any
	// path validation runs.
	n := 20_000_000
	payload := fmt.Sprintf(`{"paths":"%s"}`, strings.Repeat(",", n))

	var fm fieldmaskpb.FieldMask
	err := protojson.Unmarshal([]byte(payload), &fm)
	fmt.Println(err) // fails validation only *after* the ~320MB slice was allocated
}
```
Sending `payload` (roughly `n` bytes over the wire) causes `strings.Split` to allocate a `[]string` of `n+1` headers (~16 bytes each ≈ 16x the request size) before the loop rejects the first empty path.

// rangeFields is like strings.Split(path, "."), but avoids allocations by
// iterating over each field in place and calling a iterator function.
func rangeFields(path string, f func(field string) bool) bool {
	for {
		var field string
		if i := strings.IndexByte(path, '.'); i >= 0 {
			field, path = path[:i], path[i:]
		} else {
			field, path = path, ""
		}

		if !f(field) {
			return false
		}

		if len(path) == 0 {
			return true
		}
		path = strings.TrimPrefix(path, ".")
	}
}
