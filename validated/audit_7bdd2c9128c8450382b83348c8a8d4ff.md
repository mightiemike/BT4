### Title
Independent per-servlet rate limiting on `getpaginatedassetissuelist` allows attacker to multiply request budget across `/wallet/`, `/walletsolidity/`, `/walletpbft/` endpoints - ([File: framework/src/main/java/org/tron/core/services/http/GetPaginatedAssetIssueListServlet.java])

### Summary
`GetPaginatedAssetIssueListServlet`, `GetPaginatedAssetIssueListOnSolidityServlet`, and `GetPaginatedAssetIssueListOnPBFTServlet` are three distinct Spring `@Component` beans that each independently extend `RateLimiterServlet`, so each registers its own rate-limiter entry keyed by `getClass().getSimpleName()`. Because a default FullNode runs all three HTTP listeners simultaneously on separate ports, an attacker can call all three endpoints concurrently to obtain up to 3x the per-endpoint quota against the same underlying `AssetIssueStore.getAssetIssuesPaginated` sort-heavy logic.

### Finding Description
`RateLimiterServlet.addRateContainer()` looks up a per-servlet rate-limit config keyed on `getClass().getSimpleName()` and registers the resulting adapter into `container` under that same class name key: [1](#0-0) 

Because `GetPaginatedAssetIssueListOnSolidityServlet` and `GetPaginatedAssetIssueListOnPBFTServlet` are separate subclasses (and separate `@Component` beans) rather than reusing the base bean, `getClass().getSimpleName()` resolves to `"GetPaginatedAssetIssueListOnSolidityServlet"` and `"GetPaginatedAssetIssueListOnPBFTServlet"` respectively — distinct from `"GetPaginatedAssetIssueListServlet"`: [2](#0-1) [3](#0-2) 

Since the default `rate.limiter.http` list is empty and no explicit config entries name these servlet classes, each falls back to the global default (`DefaultBaseQqsAdapter`/`qps=1000`) as an independent bucket: [4](#0-3) 

All three underlying HTTP services are enabled by default on distinct ports — `fullNodeEnable`, `solidityEnable`, and `PBFTEnable` all default to `true` (ports 8090/8091/8092), and `HttpApiOnPBFTService`/`SolidityNodeHttpApiService` are wired up unconditionally on a FullNode deployment: [5](#0-4) [6](#0-5) [7](#0-6) 

Each of the three code paths ultimately reaches the same expensive `AssetIssueStore.getAssetIssuesPaginated`, which pulls the entire asset table and sorts it on every call regardless of `offset`/`limit`: [8](#0-7) 

Because each servlet class gets its own independent bucket rather than sharing a limiter keyed by logical endpoint, a client that would be throttled at, say, 1000 QPS on `/wallet/getpaginatedassetissuelist` can send another 1000 QPS to `/walletsolidity/getpaginatedassetissuelist` and another 1000 QPS to `/walletpbft/getpaginatedassetissuelist` from the same source, since `GlobalRateLimiter`'s IP/global check is the only shared control layer and the per-endpoint check runs first and independently for each class: [9](#0-8) 

### Impact Explanation
This amplifies a resource-consumption / DoS vector: instead of a single endpoint's configured limit bounding CPU spent in the O(n log n) sort of `getAssetIssuesPaginated`, an attacker distributing requests across the three wallet interfaces effectively triples the achievable request rate against that same expensive code path, increasing CPU/thread-pool pressure on the node. This maps to a DoS via RPC-API bounty class. It is not a full node crash by itself — it depends on the size of the underlying asset table and the configured global QPS ceilings, which still bound aggregate throughput (`global.qps = 50000`, `global.ip.qps = 10000`) — but per-endpoint throttling intended to bound this specific expensive call is bypassed for its stated purpose.

### Likelihood Explanation
No privileged access is required — an anonymous client can hit `/wallet/getpaginatedassetissuelist`, `/walletsolidity/getpaginatedassetissuelist`, and `/walletpbft/getpaginatedassetissuelist` concurrently on a default-configured FullNode where all three HTTP interfaces are enabled out of the box. The attacker pays no on-chain fee since these are read-only HTTP GET/POST calls, not transactions. However, exploitation is bounded by the still-present `GlobalRateLimiter` (global QPS and per-IP QPS ceilings), and operators can close the gap by explicitly configuring identical strict limits for all three servlet class names in `rate.limiter.http`, which the code supports today. This is a config/design gap rather than a broken enforcement mechanism.

### Recommendation
Key the per-endpoint rate limiter on a stable logical identifier shared by the base servlet and its Solidity/PBFT subclasses (e.g., use the declaring base class name or an explicit `@RateLimiterKey` annotation) instead of `getClass().getSimpleName()`, or route all three interface variants through a shared `IRateLimiter` instance in `RateLimiterContainer`. As an operational mitigation, document that operators should independently configure `GetPaginatedAssetIssueListServlet`, `GetPaginatedAssetIssueListOnSolidityServlet`, and `GetPaginatedAssetIssueListOnPBFTServlet` (and other analogous On-Solidity/On-PBFT wrapper servlets) with matching low limits in `rate.limiter.http` until code-level de-duplication lands.

  for i in $(seq 1 1000); do
    curl -s "http://TARGET:$port/$( [ $port -eq 8090 ] && echo wallet || ([ $port -eq 8091 ] && echo walletsolidity || echo walletpbft) )/getpaginatedassetissuelist?offset=0&limit=1" &
  done
done
wait

  @PostConstruct
  private void addRateContainer() {
    final String name = getClass().getSimpleName();
    RateLimiterInitialization.HttpRateLimiterItem item = Args.getInstance()
        .getRateLimiterInitialization().getHttpMap().get(name);

    String cName;
    String params;
    if (item == null) {
      cName = DEFAULT_ADAPTER_NAME;
      params = QpsStrategy.DEFAULT_QPS_PARAM;
    } else {
      cName = item.getStrategy();
      params = item.getParams();
    }

    try {
      container.add(KEY_PREFIX_HTTP, name, buildAdapter(cName, params, name));
    } catch (Exception e) {
      throw rateLimiterInitError(cName, params, name, e);
    }
  }

  @Override
  protected void service(HttpServletRequest req, HttpServletResponse resp)
      throws ServletException, IOException {

    RuntimeData runtimeData = new RuntimeData(req);
    IRateLimiter rateLimiter = container.get(KEY_PREFIX_HTTP, getClass().getSimpleName());

    // Check per-endpoint first to avoid consuming global IP/QPS quota for requests
    // that would be rejected by the per-endpoint limiter anyway. acquirePermit()
    // chooses blocking or non-blocking semantics based on rate.limiter.apiNonBlocking.
    boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
    boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);

    String contextPath = req.getContextPath();
    String url = Strings.isNullOrEmpty(req.getServletPath())
        ? MetricLabels.UNDEFINED : contextPath + req.getServletPath();
    // int64_as_string is honored only on GET requests (URL query). POST is intentionally
    // unsupported because reading the body here would consume request.getReader() and
    // break downstream servlets that read it themselves.
    if ("GET".equalsIgnoreCase(req.getMethod())) {
      JsonFormat.setInt64AsString(Util.getInt64AsString(req));
    }
    try {
      resp.setContentType("application/json; charset=utf-8");

      if (acquireResource) {
        Histogram.Timer requestTimer = Metrics.histogramStartTimer(
            MetricKeys.Histogram.HTTP_SERVICE_LATENCY, url);
        super.service(req, resp);
        Metrics.histogramObserve(requestTimer);
      } else {
        resp.getWriter()
            .println(Util.printErrorMsg(new IllegalAccessException("lack of computing resources")));
      }
    } catch (ServletException | IOException | BadMessageException e) {
      throw e;
    } catch (Exception unexpected) {
      logger.error("Http Api {}, Method:{}. Error：", url, req.getMethod(), unexpected);
    } finally {
      // CRITICAL: this clear pairs with the setInt64AsString call above. Removing it
      // will leak int64_as_string state across requests on reused Tomcat threads,
      // producing intermittent quoted/unquoted output that is very hard to debug.
      JsonFormat.clearInt64AsString();
      // Release whenever the per-endpoint permit was acquired (covers both the normal
      // completion path and the case where GlobalRateLimiter rejected the request).
      if (rateLimiter instanceof IPreemptibleRateLimiter && perEndpointAcquired) {
        ((IPreemptibleRateLimiter) rateLimiter).release();
      }

  private List<AssetIssueCapsule> getAssetIssuesPaginated(List<AssetIssueCapsule> assetIssueList,
      long offset, long limit) {
    if (limit < 0 || offset < 0) {
      return null;
    }

    if (assetIssueList.size() <= offset) {
      return null;
    }
    assetIssueList.sort((o1, o2) -> {
      if (o1.getName() != o2.getName()) {
        return o1.getName().toStringUtf8().compareTo(o2.getName().toStringUtf8());
      }
      return Long.compare(o1.getOrder(), o2.getOrder());
    });
    limit = limit > ASSET_ISSUE_COUNT_LIMIT_MAX ? ASSET_ISSUE_COUNT_LIMIT_MAX : limit;
    long end = offset + limit;
    end = end > assetIssueList.size() ? assetIssueList.size() : end;
    return assetIssueList.subList((int) offset, (int) end);
  }
