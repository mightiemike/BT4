### Title
Uninitialized `Factory` implementation at genesis lets an unprivileged attacker front-run `initialize()` and seize ownership of the UEA factory - (File: `x/uexecutor/keeper/genesis.go`)

### Summary
Push Chain's `x/uexecutor` module deploys the UEA (Universal Executor Account) factory as an upgradeable transparent proxy at genesis. Unlike the analogous `ProxyAdmin` contract, whose `Ownable.owner` storage slot is written directly during genesis, the factory logic/proxy is deployed with no owner set. Ownership must instead be established later by calling the ABI's `initialize(address initialOwner)` function, which — based on all evidence available in the indexed code — is only invoked from test setup (`test/utils/contracts_setup.go`), never from `InitGenesis`, an upgrade handler, or any other genesis/consensus-triggered path.

### Finding Description
`deployFactoryEA` (called from `InitGenesis` when `!data.Exported`) performs three steps: deploy the factory implementation, deploy the `ProxyAdmin`, and deploy the transparent proxy, wiring the EIP-1967 admin/implementation slots directly via `SetState`: [1](#0-0) 

Compare this to `deployProxyAdminContract`, which explicitly seeds the `Ownable.owner` slot of the `ProxyAdmin` contract: [2](#0-1) 

No equivalent write exists for the factory implementation's own `owner` variable (an OZ `Ownable`/`OwnableUpgradeable`-style state variable distinct from the EIP-1967 admin/impl slots). The factory ABI exposes a standard initializer: [3](#0-2) 

and `setUEAProxyImplementation` (used to point every future UEA proxy at an implementation) is presumably owner-gated: [4](#0-3) 

The only place in the indexed codebase that calls `initialize` on the factory is the integration-test helper, which explicitly checks the owner is unset right after genesis before calling `initialize`: [5](#0-4) 

No `InitGenesis`, `BeginBlocker`, or upgrade handler in `app/upgrades/**` was found calling `initialize` on the factory; `Keeper.InitGenesis` only calls `deployFactoryEA` and sets module params: [6](#0-5) 

Because the chain genesis state (including the factory bytecode and empty owner slot) is public before block 1 finalizes, and because any user can submit a normal EVM transaction, this is the classic "front-run the initializer" bug: whoever's transaction calling `initialize(attacker)` lands first becomes the permanent owner of the UEA factory, with no governance or admin check involved. This maps directly onto the report's bug class (an entity that controls upgrade/implementation wiring for user funds) but manifests here as an *unprivileged* race rather than a privileged-admin risk, because the honest deployer's own `initialize` call (if one exists at all in the deployment tooling) is not guaranteed to execute atomically with genesis.

### Impact Explanation
`setUEAProxyImplementation` controls the implementation contract used by every UEA (`UniversalAccountId`-derived per-user smart-contract wallet) that gets deployed via `DeployUEAV2`/`CallFactoryToDeployUEA`: [7](#0-6) 

If an attacker wins the initializer race and becomes factory owner, they can register a malicious implementation, `registerNewChain`/`registerUEA` mappings, or otherwise redirect UEA deployment so that every user's UEA (which custody user funds and execute cross-chain payloads on their behalf) runs attacker-controlled logic. This is unauthorized UEA execution and a path to draining or hijacking user-controlled funds routed through the universal execution flow — squarely in the "unauthorized UEA execution" / "unauthorized module-originated EVM execution" allowed-impact category, and triggered purely by an unprivileged transaction, not by admin/governance compromise.

### Likelihood Explanation
Likelihood is uncertain from the indexed code alone. Three important unknowns limit confidence:
1. It's possible (but not evidenced anywhere in the indexed code, docs, or upgrade handlers) that node/deployment tooling outside the repository's Go/test code calls `initialize()` synchronously as part of chain-launch automation before the network opens to public traffic, which would close the race window entirely.
2. It's possible the actual `FactoryImplRuntimeBytecode` contains an `initializer`/`_disableInitializers` guard, or a constructor-set owner, that isn't visible from ABI review alone — a search for `initializer`/`Initializable`/`_disableInitializers` across the repo returned no hits, but the bytecode itself is opaque without decompilation, which this index cannot perform.
3. The relative timing of genesis publication vs. the first block where transactions can land could not be conclusively verified.

Given these unknowns, this should be treated as a **must-verify** finding rather than a confirmed exploit. Due to index size limits, some file contents (e.g. the fully decompiled factory implementation logic, deployment scripts outside the indexed set, or a possible genesis-time `initialize` call issued via a script such as `setup-genesis-auto.sh`) may not be fully covered by this index — a Devin session with full repository and script access should confirm whether any deployment automation calls `initialize()` atomically with genesis before public block production begins.

### Recommendation
- Set the factory's owner storage slot directly during `deployFactoryEA` (the same way `deployProxyAdminContract` seeds the `ProxyAdmin`'s owner slot), rather than relying on a separate `initialize()` call that can be front-run.
- If an explicit `initialize()` call is required, invoke it directly from `InitGenesis` (or a dedicated `BeginBlock` at height 1) using a keeper-controlled address, guaranteeing it executes atomically with genesis before any external transaction can be included.
- Confirm the actual factory implementation bytecode has a proper `initializer` modifier/guard preventing re-initialization, and audit all `SYSTEM_CONTRACTS`/reserved-slot deployments in `x/uregistry/keeper/genesis.go` for the same class of "owner slot left unset, relies on post-genesis call" pattern.

### Proof of Concept
1. Observe genesis: `deployFactoryEA` deploys factory impl + proxy + admin, writing EIP-1967 admin/impl slots but never the factory's own `owner` storage variable.
2. As soon as the chain begins accepting transactions (block 1+), submit an EVM transaction calling `initialize(attackerAddress)` on `FACTORY_PROXY_ADDRESS_HEX` before the legitimate deployer's own initialization transaction is included.
3. If the attacker's transaction lands first, `owner()` on the factory now returns the attacker's address (as verified achievable via the exact same `CallEVM(..., "initialize", owner)` pattern used in `test/utils/contracts_setup.go`).
4. The attacker calls `setUEAProxyImplementation(maliciousImpl)`, `registerNewChain`, and `registerUEA` to redirect all subsequently deployed UEAs to attacker-controlled logic.
5. Any user whose UEA is deployed after this point executes the malicious implementation instead of the legitimate one, exposing their funds/payload execution to the attacker.

func deployFactoryProxy(ctx context.Context, evmKeeper types.EVMKeeper) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	proxyAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)
	proxyAdminOwner := common.HexToAddress(types.PROXY_ADMIN_ADDRESS_HEX)
	factoryImplAddress := common.HexToAddress(types.FACTORY_IMPL_ADDRESS_HEX)

	// Compute the code hash from the runtime bytecode
	codeHash := crypto.Keccak256(types.ProxyRuntimeBytecode)

	// Create the EVM account object
	evmAccount := statedb.Account{
		Nonce:    1,             // to prevent tx nonce=0 conflicts
		Balance:  new(uint256.Int), // zero balance by default
		CodeHash: codeHash,      // link to deployed code
	}

	// Set the EVM account with the factory proxy contract
	err := evmKeeper.SetAccount(sdkCtx, proxyAddress, evmAccount)
	if err != nil {
		panic("failed to set factory proxy contract account: " + err.Error())
	}

	// Store the runtime bytecode linked to the code hash
	evmKeeper.SetCode(sdkCtx, codeHash, types.ProxyRuntimeBytecode)

	// Update proxyAdmin Slot with the proxyAdmin owner address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_ADMIN_SLOT, common.LeftPadBytes(proxyAdminOwner.Bytes(), 32))

	// Update proxyImplementation Slot with the factory implementation address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_IMPLEMENTATION_SLOT, common.LeftPadBytes(factoryImplAddress.Bytes(), 32))
}

func setupFactoryContract(
	t *testing.T,
	app *app.ChainApp,
	ctx sdk.Context,
	factoryABI abi.ABI,
	opts AppSetupOptions,
	accounts TestAccounts,
) error {
	factoryAddr := opts.Addresses.FactoryAddr
	owner := common.BytesToAddress(accounts.DefaultAccount.GetAddress().Bytes())

	// Check initial factory owner
	ownerResult, err := app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after genesis: %s", common.BytesToAddress(ownerResult.Ret).Hex())

	// Initialize factory with owner
	_, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "initialize", owner)
	require.NoError(t, err)

	// Verify owner is set
	ownerResult, err = app.EVMKeeper.CallEVM(ctx, factoryABI, owner, factoryAddr, true, nil, "owner")
	require.NoError(t, err)
	t.Logf("Factory owner after initialization: %s", common.BytesToAddress(ownerResult.Ret).Hex())

// InitGenesis initializes the module's state from a genesis state.
func (k *Keeper) InitGenesis(ctx context.Context, data *types.GenesisState) error {

	if err := data.Params.ValidateBasic(); err != nil {
		return err
	}

	// Only deploy factory contracts on fresh genesis, not on import from export.
	// Re-deploying on import would overwrite existing EVM state or cause nonce collisions.
	if !data.Exported {
		deployFactoryEA(ctx, k.evmKeeper)
	}

	if err := k.Params.Set(ctx, data.Params); err != nil {
		return err
	}

package keeper

import (
	"context"

	sdk "github.com/cosmos/cosmos-sdk/types"
	evmtypes "github.com/cosmos/evm/x/vm/types"
	"github.com/ethereum/go-ethereum/common"
	"github.com/pushchain/push-chain-node/x/uexecutor/types"
)

// updateParams is for updating params collections of the module
func (k Keeper) DeployUEAV2(ctx context.Context, evmFrom common.Address, universalAccountId *types.UniversalAccountId) (*evmtypes.MsgEthereumTxResponse, error) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Debug("deploying UEA",
		"chain_namespace", universalAccountId.ChainNamespace,
		"chain_id", universalAccountId.ChainId,
		"owner", universalAccountId.Owner,
		"from", evmFrom.Hex(),
	)

	// EVM Call arguments
	factoryAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)

	// Use your keeper CallEVM directly
	receipt, err := k.CallFactoryToDeployUEA(
		sdkCtx,
		evmFrom,
		factoryAddress,
		universalAccountId,
	)
	if err != nil {
		return nil, err
	}

	k.Logger().Info("UEA deployed",
		"chain_namespace", universalAccountId.ChainNamespace,
		"chain_id", universalAccountId.ChainId,
		"owner", universalAccountId.Owner,
		"tx_hash", receipt.Hash,
		"gas_used", receipt.GasUsed,
	)

	return receipt, nil
}
