### Title
Attacker-controlled `Recipient` + `UniversalPayload.GasLimit` in a CEA inbound forces gas fees to be deducted from an unconsenting third-party contract's own balance - ([File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go], [File: x/uexecutor/keeper/execute_inbound_funds_and_payload.go], [File: x/uexecutor/keeper/fees.go])

### Summary
The zkSync finding lets an unprivileged actor force a doomed, gas-maximizing call whose cost is ultimately paid by a party that didn't choose to make that call. Push Chain has a structural analog in the `isCEA` inbound path: an attacker who merely emits a Gateway event on any supported source chain can name an **arbitrary existing Push Chain contract** as `Recipient`, attach an arbitrary `UniversalPayload.Data`/`GasLimit`, and have `x/uexecutor` invoke `executeUniversalTx` on that contract with the module account as the EVM `msg.sender`. Gas for this unsolicited call is then billed directly against **the recipient contract's own `upc` balance**, not the attacker's.

### Finding Description
In the CEA ("contract-execution-address") branch of inbound processing, `Recipient` is taken verbatim from the attacker-controlled source-chain event and is only checked to look like a hex address: [1](#0-0) 

Once quorum is reached, if the recipient resolves to a deployed non-UEA smart contract, the module calls `executeUniversalTx` on it with `amount`, `payload` (calldata), and `GasLimit` sourced from the same attacker-supplied `UniversalPayload`: [2](#0-1) 

The identical pattern exists in the GAS_AND_PAYLOAD variant: [3](#0-2) 

After the call returns, `DeductGasFeesFromReceipt` bills `receipt.GasUsed` against the **recipient's own `upc` account balance** (`ueaAddr` = the attacker-named `Recipient`), computed from `MaxFeePerGas`/`MaxPriorityFeePerGas`/base fee — all fields the attacker supplies in the payload: [4](#0-3) 

There is no check anywhere in `ValidateForExecution` bounding `GasLimit` to a sane ceiling, nor any requirement that the recipient contract has opted in to receiving CEA calls or to paying for them: [5](#0-4) 

The confirmed test suite explicitly demonstrates the mechanics: the recipient's `upc` balance decreases as a direct result of an inbound the recipient never authorized, and the payload's `Data`/`GasLimit` freely control what runs and how much gas it consumes: [6](#0-5) 

This mirrors the zkSync root cause precisely: an unprivileged party (the depositor on the source chain, functionally equivalent to the "operator" in the bug report) can craft a call whose gas cost is unavoidably billed to a party that isn't the one initiating/benefiting from the call, by choosing calldata that maximizes gas consumption (e.g., an expensive loop or a near-`GasLimit` revert) inside `executeUniversalTx`. The bootloader's `nearCallPanic` forced *all* gas of the operator's slot to burn; here the attacker forces the recipient to pay for however much gas the attacker's calldata consumes, up to the attacker-chosen `GasLimit`, entirely without recipient consent.

### Impact Explanation
An attacker can drain a target contract's native `upc` balance by repeatedly emitting cheap source-chain Gateway events naming that contract as `Recipient` with malicious/expensive calldata and a large `GasLimit`. Each such inbound: (1) costs the attacker only source-chain gas (which can be arbitrarily cheap on a testnet/L2, or amortized because it doesn't require signing anything on Push Chain — no `VerificationData`/signature check gates this path, unlike UEA execution which requires the owner's signature), and (2) deducts real `upc` from the victim contract for work the victim never requested. This is unauthorized/forced-fund-loss from the recipient's perspective and directly corrupts gas-fee accounting invariants ("gas fee accounting... must not misroute value" per the allowed-impact gate), reachable purely through ordinary/unprivileged deposit flows with honest validators and honest nodes.

### Likelihood Explanation
High reachability: any external-chain actor can call the Gateway's `addFunds`-style method with a `Recipient` and `UniversalPayload` of their choosing; there is no requirement that the recipient be a UEA or have opted in, only that it be "a deployed smart contract (not UEA)." The only friction is `ValidateForExecution`'s superficial address-format check and normal Universal Validator quorum on the *existence* of the source event — not on the wisdom of the calldata or gas limit. As long as the target contract holds any `upc` balance, this is directly exploitable.

### Recommendation
- Require explicit recipient opt-in for CEA calls (e.g., a registry flag or an interface check/allowlist) rather than allowing any deployed non-UEA contract to be silently invoked and billed.
- Cap `UniversalPayload.GasLimit` for CEA smart-contract executions to a protocol-defined maximum, and/or require the *depositor* (not the recipient) to pre-fund the gas cost, mirroring how UEA-authenticated flows require the account owner's own signed authorization before their balance is touched.
- Consider billing gas costs from a bonded/attacker-attributable source (e.g., escrowed from the deposited value) rather than debiting an arbitrary third party's existing `upc` balance for an unsolicited call.

### Proof of Concept
1. Deploy (or find) any non-UEA contract `V` on Push Chain that holds `upc` (e.g., from a legitimate unrelated inbound or self-funding).
2. On a configured source chain, call the Gateway with `TxType_FUNDS_AND_PAYLOAD`, `IsCEA=true`, `Recipient = V`, `Amount = 0` (or minimal), and `UniversalPayload.Data` set to calldata that triggers expensive computation in `V` (or reverts near `GasLimit`), with `GasLimit` set to a large value and `MaxFeePerGas`/`MaxPriorityFeePerGas` set high.
3. Once Universal Validators reach quorum on the observed event (per `test/integration/uexecutor/inbound_cea_smart_contract_test.go` flow), `x/uexecutor` calls `executeUniversalTx` on `V` and then `DeductGasFeesFromReceipt` debits `V`'s `upc` balance for the gas consumed — confirmed by the existing test `"gas fees deducted from smart contract recipient after executeUniversalTx"` at [6](#0-5) .
4. Repeat cheaply from the source chain to continually drain `V`'s `upc` balance without `V`'s consent.

Note: I was unable to fully inspect `CallExecuteUniversalTx`'s implementation in `x/uexecutor/keeper/evm.go` (its exact line range) within the available tool budget, so the precise `from`/module-sender wiring and any additional guardrails inside that specific helper could not be fully confirmed — a full Devin session with file access would be needed to verify there is no additional cap or opt-in check inside `CallExecuteUniversalTx` itself that mitigates this.

func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}

	t.Run("gas fees deducted from smart contract recipient after executeUniversalTx", func(t *testing.T) {
		chainApp, ctx, vals, inbound, coreVals, contractAddr := setupInboundCEASmartContractTest(t, 4)

		// Fund the smart contract with upc so fee deduction can succeed
		contractAccAddr := sdk.AccAddress(contractAddr.Bytes())
		fundCoins := sdk.NewCoins(sdk.NewInt64Coin("upc", 1_000_000_000))
		require.NoError(t, chainApp.BankKeeper.MintCoins(ctx, "mint", fundCoins))
		require.NoError(t, chainApp.BankKeeper.SendCoinsFromModuleToAccount(ctx, "mint", contractAccAddr, fundCoins))

		balanceBefore := chainApp.BankKeeper.GetBalance(ctx, contractAccAddr, "upc")

		// Reach quorum
		for i := 0; i < 3; i++ {
			valAddr, err := sdk.ValAddressFromBech32(coreVals[i].OperatorAddress)
			require.NoError(t, err)
			coreValAcc := sdk.AccAddress(valAddr).String()

			err = utils.ExecVoteInbound(t, ctx, chainApp, vals[i], coreValAcc, inbound)
			require.NoError(t, err)
		}

		// Verify executeUniversalTx PCTx has gas_used > 0
		utxKey := uexecutortypes.GetInboundUniversalTxKey(*inbound)
		utx, found, err := chainApp.UexecutorKeeper.GetUniversalTx(ctx, utxKey)
		require.NoError(t, err)
		require.True(t, found)
		require.GreaterOrEqual(t, len(utx.PcTx), 2, "should have deposit + executeUniversalTx PCTxs")

		callPcTx := utx.PcTx[1]
		require.Equal(t, "SUCCESS", callPcTx.Status)
		require.Greater(t, callPcTx.GasUsed, uint64(0), "executeUniversalTx should report gas used")

		// Verify upc balance decreased (gas was deducted)
		balanceAfter := chainApp.BankKeeper.GetBalance(ctx, contractAccAddr, "upc")
		require.True(t, balanceAfter.Amount.LT(balanceBefore.Amount),
			"smart contract upc balance should decrease after gas fee deduction (before=%s, after=%s)",
			balanceBefore.Amount, balanceAfter.Amount)
	})
