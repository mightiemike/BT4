### Title
Stale per-block liquidity/debt index cache in `market.clar` is not invalidated by vault `socialize-debt`, causing zToken collateral to be mispriced within the same block - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`v0-4-market.clar` caches each vault's `{index, lindex}` pair per block in the `index-cache` map, keyed only by `{timestamp: stacks-block-time, aid}`. Once cached for a given block, all subsequent accrual lookups for that asset in the same block return the cached value without re-querying the vault. However, the vault's `socialize-debt` function writes a new `lindex` directly to vault storage without going through `accrue`, and without any corresponding invalidation of the market's cache. Any market operation in the same block that reads accrual data after a `socialize-debt` call therefore keeps using the pre-socialization liquidity index, mispricing zToken collateral for the remainder of the block.

### Finding Description
`accrue-and-cache` in `market.clar` is a classic cache with a per-block key: [1](#0-0) 

On a cache HIT it returns the stored `{index, lindex}` with "1 read only", skipping any call into the vault. This value is bound the first time any market function accrues asset `aid` in the current `stacks-block-time`, and it is used by `accrue-collateral-asset` / `resolve-ztoken` to price zToken collateral for health checks and liquidations: [2](#0-1) [3](#0-2) 

The source of truth this cache mirrors is the vault's own `lindex` data var. That var is normally only updated inside `accrue()`: [4](#0-3) 

But `socialize-debt` (invoked by the market when bad debt must be written off) mutates `lindex` directly, bypassing `accrue()` entirely and with no notification to the market's `index-cache`: [5](#0-4) 

Sequence within a single block (same `stacks-block-time`, so the same `index-cache` key):
1. Any market entry point (deposit/borrow/repay/liquidation touching this asset) calls `accrue-and-cache(aid)`, which is a cache MISS, calls `vault-accrue`, and stores `{index, lindex}` in `index-cache` for `{timestamp: stacks-block-time, aid}`.
2. Later in the same block, a liquidation or bad-debt-handling flow calls `vault-socialize-debt(aid, amount)`, which writes a lower `lindex` directly into the vault (`v0-vault-stx.clar:944-984`) to reflect the loss, without touching `market.clar`'s `index-cache`.
3. Any further market operation in that same block (a different user's deposit, borrow, health check, or liquidation touching the same `aid`) calls `accrue-and-cache(aid)` again. Since the cache key `{timestamp, aid}` is unchanged, this is a cache HIT, and the market returns the pre-socialization `lindex` from step 1 instead of the vault's actual, lower, post-socialization `lindex`.
4. `resolve-ztoken` then values that zToken collateral using the stale, higher `lindex`, overstating collateral value in health/borrow/liquidation checks for the rest of the block.

This is possible under Clarity evaluation order because `index-cache` is a persistent map write (`map-set`) that survives across separate top-level transactions within the same block as long as `stacks-block-time` (the cache key) does not change, while the vault's `lindex` can be mutated by a code path (`socialize-debt`) that never consults or updates that map.

### Impact Explanation
Overstated `lindex` inflates the market value assigned to zToken collateral (`resolve-ztoken`, `mainnet/contracts/market/v0-4-market.clar:343-347`) in exactly the window right after bad debt has been socialized. This can let a borrower pass a health check and open/maintain debt against collateral that is actually worth less than the protocol believes, or block/mis-evaluate a legitimate liquidation of an account whose collateral value is computed from the stale cache. Because the mispricing directly affects the collateral valuation used to gate borrowing and liquidation, exploiting it can permit undercollateralized debt to be created, i.e. protocol insolvency risk.

### Likelihood Explanation
`socialize-debt` is a deliberate, reachable code path used whenever bad debt must be written off, and any transaction from any user touching the same asset later in the same block (which is common on a busy market) will hit the stale cache. No special privileges are required to trigger the read side — merely to be the "later" caller in the same block, which is easily achievable by front-running or simply happening to transact in the same block as the socialization event.

### Recommendation
Invalidate (or refresh) the `index-cache` entry for `aid` whenever `vault-socialize-debt` (or any other vault function that mutates `index`/`lindex` outside of `accrue`) is executed, or remove the block-scoped index cache and always read authoritative `index`/`lindex` from the vault after any state-mutating vault call in the same transaction/block.

### Proof of Concept
1. Block N, tx 1: User A deposits/borrows asset `aid`, triggering `accrue-and-cache(aid)` cache MISS; `index-cache[{timestamp: T, aid}]` is set to `{index: I0, lindex: L0}`.
2. Block N, tx 2: A liquidation on a different, insolvent position calls `vault-socialize-debt(aid, scaled-amount)`, which computes and writes `new-lindex = L1 < L0` directly to the vault's `lindex` var (`v0-vault-stx.clar:944-984`), with no update to `market.clar`'s `index-cache`.
3. Block N, tx 3: User B (or the same liquidator) opens a new position or health-checks an existing one holding the zToken for `aid`. `accrue-and-cache(aid)` is called again; since `stacks-block-time` is still `T`, it's a cache HIT and returns `{index: I0, lindex: L0}` (the pre-socialization value) instead of the vault's true `{I0, L1}`.
4. `resolve-ztoken` prices the collateral using `L0` instead of `L1`, overstating collateral value for the health check performed in tx 3, potentially letting an undercollateralized borrow succeed.

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
