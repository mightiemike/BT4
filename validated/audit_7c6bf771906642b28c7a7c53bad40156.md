### Title
`replace_class` syscall in the Starknet OS permits setting a contract's class hash to an undeclared class, without validation - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS implementation of the `replace_class` syscall writes an attacker-supplied `class_hash` into a contract's state entry without verifying that a class with that hash was ever declared, and the code contains an explicit TODO acknowledging the missing check.

### Finding Description
`execute_replace_class` in `syscall_impls.cairo` handles the `ReplaceClass` syscall, which any contract can invoke on itself during ordinary transaction execution (invoked from `execute_syscalls`/`execute_deprecated_syscalls` dispatch, e.g. lines 197-205 and 676-688 of the corresponding files). The function unconditionally takes `request.class_hash` from the syscall request and writes a new `StateEntry` with that class hash into `contract_state_changes`, with no existence/declaration check: [1](#0-0) 

The code itself flags this gap with an explicit developer TODO immediately before the unchecked write: [2](#0-1) 

The same unchecked pattern exists in the deprecated-syscall path used for Cairo 0 contracts: [3](#0-2) 

This is directly analogous to the reported bug class: a state-mutating operation (`setCollateralEscrowBeacon` in the original report) is performed without validating the input/authorization that is normally expected before accepting it. Here, instead of missing an `onlyOwner` check, the missing check is "the class hash must correspond to an actually-declared class" before it is committed as a contract's active class.

### Impact Explanation
Any account contract can invoke `replace_class` (via a normal `INVOKE` transaction) with an arbitrary, non-existent `class_hash`. Because the OS commits this class hash to `contract_state_changes` without verifying declaration, the contract's on-chain class pointer becomes permanently corrupted: subsequent calls into that contract will fail to resolve a compiled class, since no class was ever declared with that hash. This causes:
- Permanent bricking/freezing of the contract (denial of service on its own funds/functionality), since it can never execute again until (if ever) a class with that exact hash coincidentally gets declared.
- Potential divergence between the Starknet OS re-execution path (which accepts the write unconditionally) and any other execution engine (e.g., blockifier) if that engine enforces a stricter check on `replace_class`, which would produce differing state commitments/block hashes between re-execution and normal sequencer execution — an honest-node divergence.

### Likelihood Explanation
High likelihood: `replace_class` is a standard, un-gated Starknet syscall reachable from any contract's own code within a normal transaction; no special privilege, staking, or operator status is required. The vulnerable code path is hit on every `REPLACE_CLASS_SELECTOR` dispatch during OS execution/re-execution.

### Recommendation
Add a check in `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that the target `class_hash` corresponds to a declared class (compiled class hash present in `contract_class_changes` or the underlying state) before writing the new `StateEntry`, mirroring whatever check the blockifier's runtime `replace_class` implementation performs, to eliminate the possibility of committing an undeclared class hash and to keep OS re-execution semantics aligned with blockifier execution.

### Proof of Concept
1. Deploy any contract (e.g., a Cairo 0 or Cairo 1 account/test contract) with a `replace_class` syscall wrapper (such as `test_replace_class` in the test contracts referenced by `crates/starknet_os_flow_tests/src/tests.rs`).
2. Submit an `INVOKE` transaction calling that contract's `replace_class`/`test_replace_class` entry point with a `class_hash` value that has never been declared (e.g., a random felt).
3. Observe that `execute_replace_class` writes the new (bogus) class hash into `contract_state_changes` unconditionally — see the TODO at `syscall_impls.cairo:900-908` confirming no declaration check occurs.
4. Any subsequent call to the contract fails to resolve its class, permanently disabling the contract.

Note: I was not able to fully confirm within the available search budget whether the blockifier's Rust-side `replace_class` syscall implementation (`crates/blockifier/src/execution/syscalls/syscall_base.rs` / `hint_processor.rs`) performs a declared-class check that the OS lacks; if it does, this would additionally constitute an OS/blockifier consensus-divergence bug rather than only a griefing/DoS bug. This should be verified directly in a follow-up session with full file access.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
