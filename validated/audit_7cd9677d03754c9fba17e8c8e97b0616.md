### Title
Free, unbounded on-chain account creation via the gasless-tx allowlist bypasses the bonded-Universal-Validator requirement - (File: `app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator` grants free account initialization (no fee, no gas-price check, no signature-over-real-account-state) to *any* transaction whose message types are in the gasless allowlist, before the deeper application logic verifies that the signer is actually a bonded Universal Validator. This mirrors the Neptune Mutual pattern: a costly/privileged perk (fee exemption + account bootstrap) is granted based on a superficial condition (message type) that has no enforced relationship to the real eligibility requirement (`IsBondedUniversalValidator`), which is checked later and independently, deep inside the message handler.

### Finding Description
Push Chain's gasless-transaction machinery is meant only for "Universal Validators and UEA users" [1](#0-0) . `IsGaslessTx` determines eligibility purely from the message type URL, with no signer/identity check at all: it just checks that every message (including those nested in `authz.MsgExec`) is one of `MsgMigrateUEA`, `MsgExecutePayload`, `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`, `MsgVoteChainMeta` [2](#0-1) .

For the vote messages (`MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`), the documented authority is "bonded UV" and the actual `IsBondedUniversalValidator` / `IsTombstonedUniversalValidator` checks only run inside the respective `msgServer` handlers, e.g. `VoteInbound`, `VoteTssKeyProcess`, `VoteFundMigration` [3](#0-2) [4](#0-3) . Those checks execute **after** the ante-handler pipeline, i.e. after fee/gas gating has already decided the tx is free.

The ante pipeline itself makes decisions solely on message type, not on signer eligibility:
- `MinGasPriceDecorator` completely skips the minimum-fee check for any tx classified gasless by `IsGaslessTx` [5](#0-4) .
- `DeductFeeDecorator` skips fee deduction entirely for the same class of tx [6](#0-5) .
- `AccountInitDecorator` goes further: if the tx is gasless and the sole signer has no on-chain account yet, it verifies a signature over synthetic `account_number=0, sequence=0`, then unconditionally creates a brand-new account (`NewAccountWithAddress`, `SetSequence(1)`) and short-circuits the ante chain, all without any check that the signer is a registered/bonded validator [7](#0-6) .

Because the attacker fully controls the keypair they submit, they can trivially produce a valid signature over the synthetic sequence, satisfying `verifySignatureForNewAccount`. The account creation happens in the ante-handler execution context, which Cosmos SDK's `baseapp.runTx` commits independently of whether the subsequent message execution (`RunMsgs`) succeeds or fails. Consequently, even though the eventual `VoteInbound`/`VoteTssKeyProcess`/etc. call will fail with "universal validator ... is not bonded" once it reaches the deep bonded-check, the account creation performed by the ante decorator is not rolled back.

### Impact Explanation
An unprivileged external attacker — with no stake, no bond, no registration as a Universal Validator — can:
1. Generate an arbitrary keypair.
2. Submit a `MsgVoteInbound` (or any other allowlisted gasless message) with fabricated/garbage payload data, paying zero fee and no minimum gas price.
3. Have `AccountInitDecorator` permanently create a new on-chain account for that address at zero cost, before the "is a bonded UV" requirement is ever checked.
4. Repeat indefinitely with fresh keypairs (key generation is free and unlimited).

This is unbounded, fee-free growth of `x/auth` account state driven entirely by unprivileged users, and unbounded fee-free CPU/bandwidth consumption from mempool `CheckTx`/gossip processing of these transactions before they are ultimately rejected deep in the executor/TSS module logic. It directly parallels the reported bug class: a "requirement" (bonded UV status, analogous to NPM's minimum-stake requirement) that gates a privileged/valuable capability (gasless-tx fee exemption and account bootstrap, analogous to LP token issuance) is not actually enforced at the point where the valuable capability is granted — it is checked later, independently, and too late to prevent the resource cost from already being incurred.

### Likelihood Explanation
The trigger requires no privileged access, no colluding validators, and no external chain interaction — only the ability to generate a keypair and submit a transaction, which is available to any network participant. It is reachable purely through the default transaction submission path (`AnteHandler` -> gasless allowlist -> `AccountInitDecorator`), matching the "Admission and cryptographic path" scope explicitly called out in the task (gasless allowlisting / ante checks / first-use account initialization).

### Recommendation
Move (or duplicate) the `IsBondedUniversalValidator`/`IsTombstonedUniversalValidator` eligibility check into the ante pipeline (or into `AccountInitDecorator`/`IsGaslessTx` itself) so that fee exemption and free account creation are only granted to signers who are already provably bonded Universal Validators for the vote-type messages, or otherwise bound the resource cost (e.g., rate-limit new-account creation via gasless txs, or require a minimal bonded/stake precondition before account bootstrap). For `MsgExecutePayload`, which is intentionally "any signer" gasless by design (per `x/uexecutor/README.md`), consider whether unauthenticated free account creation should still be permitted, or gate it with a lightweight proof-of-eligibility / rate limit distinct from the vote-message case.

### Proof of Concept
1. Generate a new secp256k1/eth_secp256k1 keypair not previously used on chain (`newAcc`).
2. Construct a `MsgVoteInbound` with `Signer = newAcc` and an arbitrary/fabricated `Inbound` payload (any well-formed but bogus source-chain data).
3. Sign the transaction with `newAcc`'s key over `account_number=0, sequence=0` (as required by `AccountInitDecorator.verifySignatureForNewAccount`), with `fee = 0` and no gas price set.
4. Submit via `CheckTx`/broadcast. Observe:
   - `MinGasPriceDecorator` and `DeductFeeDecorator` both skip their checks because `IsGaslessTx` returns true for `MsgVoteInbound`.
   - `AccountInitDecorator` detects the account does not exist, verifies the self-signature, and creates the account on chain (`account_number` assigned, `sequence=1`) at zero cost — this state change is committed by `baseapp.runTx` even though...
   - the subsequent `VoteInbound` message execution fails with `"universal validator for signer ... is not bonded"` since `newAcc` was never registered via `MsgAddUniversalValidator`.
5. Repeat with a new keypair; a new on-chain account is created again for free. Repeat indefinitely to grow `x/auth` state and consume validator CheckTx/mempool resources at zero cost to the attacker.

Note: I was unable to inspect `app/ante/ante.go` and `app/ante/ante_cosmos.go` (tool access to those files failed in this session) to confirm the exact ordering of `AccountInitDecorator` relative to `SigVerificationDecorator`/`SetPubKeyDecorator` in the full chain, and I could not directly confirm from source that `baseapp.runTx` commits ante-handler-level state changes independently of message-execution failure (this is standard Cosmos SDK `baseapp` behavior but was not independently re-verified against this repo's `app.go`/`baseapp` wiring in this session). These points should be verified before treating the account-persistence claim as certain.

// IsGaslessTx checks if a transaction contains only allowed gasless message types
// Returns true if all messages in the transaction are in the allowed gasless message types
func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}
