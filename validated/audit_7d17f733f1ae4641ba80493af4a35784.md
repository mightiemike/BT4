## Analysis

I examined `universalClient/chains/svm/event_parser.go` and its caller `universalClient/chains/svm/event_listener.go`. [1](#0-0) 

The listener discovers candidate transactions via `GetSignaturesForAddress(gatewayAddr, ...)`, which returns **every** Solana transaction that merely references the gateway pubkey as an account — not only transactions that actually invoke the gateway program's instructions. It then iterates `tx.Meta.LogMessages` and calls `determineEventType` / `ParseEvent` against **each log line independently**, matching only on whether the line starts with `"Program data: "` and whether the first 8 decoded bytes equal a known discriminator: [2](#0-1) 

Crucially, there is no check that the matching `Program data:` line is bounded by a `Program <gatewayAddress> invoke [...] / success` pair — i.e., no verification that the log was actually emitted *by the gateway program itself* during its own CPI frame. Anchor/Solana event discriminators are deterministic hashes of a public event name (not a secret), so any attacker can compute the correct 8-byte prefix for `finalize_universal_tx`, `revert_universal_tx`, or `funds_rescued`.

`parseOutboundObservationEvent` then blindly decodes the remaining bytes as `sub_tx_id`, `universal_tx_id`, `gas_used`, etc., with zero cross-checks against any real on-chain vault/gateway state, and constructs a `store.Event` with `Status: store.StatusPending`: [3](#0-2) 

This event is persisted via `chainStore.InsertEventIfNotExists`, keyed by `signature:logIndex`, which is always unique for attacker-submitted transactions, so there is no dedup protection against volume: [4](#0-3) 

### Exploit path
An unprivileged attacker can:
1. Deploy their own trivial Solana program.
2. Submit a transaction that (a) references the real gateway pubkey as a (read-only) account — trivial and permissionless — and (b) invokes their own program, which calls `sol_log_data`/`emit!` to print a `Program data: <base64>` log whose first 8 bytes match a known discriminator (e.g. `finalize_universal_tx`) and whose remaining ≥89 bytes are attacker-chosen (arbitrary `sub_tx_id`, `universal_tx_id`, `gas_used`, etc.).
3. Repeat with new signatures indefinitely; each is picked up by `GetSignaturesForAddress`, parsed, and stored as a new pending `store.Event` of type Outbound.

This matches the premise of the question: authenticity of the observed log is verified only by discriminator content, not by binding the log to an actual instruction invocation of the real gateway program.

### Impact assessment
This is a genuine gap in provenance validation of SVM event logs. The confirmed, verifiable impact is **local resource/DB spam on the universalClient's event store and downstream finalization-worker load** — every attacker-submitted low-cost Solana transaction can inject an arbitrary number of fabricated pending outbound events. I could not verify within this file set whether these forged pending events ever reach a point where they could be voted into canonical chain state (that would require inspecting the finalization/voting keeper code in `x/`, which was not available in this pass) — if the chain-side keeper independently validates the `universal_tx_id`/`sub_tx_id` against real prior UniversalTx records before accepting a vote, the forged events would simply be rejected there and the impact is limited to wasted UV/local processing capacity (non-network-level DoS on the universalClient, not accepted protocol state corruption). Given the scope's explicit allowance for "denial of service only when it is not network-level and is reachable without privileged control," this qualifies as a valid, in-scope finding at the local processing/DoS level, while I cannot confirm fund loss or forged canonical chain state without further tracing into the finalization/voting keeper.

### Title
Unauthenticated SVM `Program data:` Log Injection Allows Spam of Pending Outbound Observation Events - (File: universalClient/chains/svm/event_parser.go)

### Summary
`parseOutboundObservationEvent` (invoked from `EventListener.processSignatureBatch`) accepts any log line beginning with `"Program data: "` whose first 8 bytes match a public, non-secret event discriminator, without verifying that the log was emitted by the actual gateway program's own instruction frame. Combined with `GetSignaturesForAddress` returning any transaction merely referencing the gateway pubkey, an attacker can submit permissionless Solana transactions from an arbitrary program to forge outbound observation logs with attacker-controlled `sub_tx_id`, `universal_tx_id`, and `gas_used` fields.

### Finding Description
- `determineEventType` (event_listener.go:398-423) and `parseOutboundObservationEvent` (event_parser.go:116-169) treat any 97+ byte base64 `Program data:` payload with a matching 8-byte discriminator as a legitimate gateway event.
- No check exists that the log line is nested within a `Program <gatewayAddress> invoke ... success` boundary in `tx.Meta.LogMessages`.
- `GetSignaturesForAddress(gatewayAddr, ...)` returns transactions that merely reference the account, not only ones invoking it.
- Discriminators used by Anchor-style event macros are deterministic and public, so they are trivially reproducible by an attacker's own program.

### Impact Explanation
An attacker can flood the universalClient's local event store (`store.Event` table) with fabricated pending Outbound events at will, at the cost of ordinary Solana transaction fees. This consumes finalization-worker processing capacity and DB storage. Whether this can escalate to acceptance of forged canonical chain state depends on validation logic in the outbound finalization/voting keeper (not reviewed here); absent that additional check, the confirmed impact is local resource exhaustion/non-network DoS on the universalClient rather than confirmed fund loss.

### Likelihood Explanation
High — requires only a standard, permissionless Solana transaction referencing the public gateway address and invoking an attacker-deployed program; no privileged access, validator collusion, or gateway-program interaction is needed.

### Recommendation
Bind log-to-program provenance explicitly: only accept `Program data:` lines that occur within the specific `Program <gatewayAddress> invoke [...]` / `success` bracket for the configured gateway program ID (parsing the surrounding invoke/success markers in `tx.Meta.LogMessages`), rather than scanning the whole transaction's log lines irrespective of which program emitted them. Additionally, cross-validate `sub_tx_id`/`universal_tx_id` against previously recorded UniversalTx state before treating an outbound observation as pending.

### Proof of Concept
1. Deploy a minimal Solana program that calls `sol_log_data` with a payload: `discriminator(8) || sub_tx_id(32) || universal_tx_id(32) || gas_fee(8) || gas_used(8, attacker value) || gas_to_refund(8) || ata_created(1)`, where `discriminator` equals the known 8-byte identifier for `finalize_universal_tx`.
2. Submit a transaction invoking this program while also listing the real gateway pubkey as a (read-only, non-signing) account.
3. Observe `GetSignaturesForAddress` returns this signature; `EventListener.processSignatureBatch` parses the forged log and calls `chainStore.InsertEventIfNotExists`, persisting a new pending Outbound `store.Event` with attacker-chosen `gas_used`/`txID`/`universalTxID`.
4. Repeat with fresh transactions to generate unbounded distinct `EventID`s (`signature:logIndex`), bypassing dedup.

func (el *EventListener) processSignatureBatch(
	ctx context.Context,
	batch []*solanarpc.TransactionSignature,
	fromSlot, toSlot uint64,
) (uint64, error) {
	var processed uint64
	for _, sig := range batch {
		if sig.Slot < fromSlot {
			continue
		}
		if sig.Slot > toSlot {
			continue
		}
		processed++

		// Get transaction details
		tx, err := el.rpcClient.GetTransaction(ctx, sig.Signature)
		if err != nil {
			el.logger.Error().
				Err(err).
				Str("signature", sig.Signature.String()).
				Msg("failed to get transaction")
			continue
		}

		// Process each log in the transaction
		if tx != nil && tx.Meta != nil && len(tx.Meta.LogMessages) > 0 {
			for logIndex, log := range tx.Meta.LogMessages {
				// Determine event type based on discriminator
				eventType := el.determineEventType(log)
				if eventType == "" {
					continue
				}

				// Parse gateway event from individual log

					// Insert event if it doesn't already exist

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

func parseOutboundObservationEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	// Minimum: 8 disc + 32 sub_tx_id + 32 universal_tx_id + 8 gas_fee + 8 gas_used
	// + 8 gas_to_refund + 1 ata_created = 97 bytes.
	if len(decoded) < 97 {
		logger.Warn().
			Int("data_len", len(decoded)).
			Msg("data too short for outboundObservation event; need at least 97 bytes")
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing outboundObservation event")

	// Skip discriminator (8 bytes)
	offset := 8

	// Extract txID (32 bytes)
	txID := "0x" + hex.EncodeToString(decoded[offset:offset+32])
	offset += 32

	// Extract universalTxID (32 bytes)
	universalTxID := "0x" + hex.EncodeToString(decoded[offset:offset+32])
	offset += 32

	// Skip gas_fee (prepaid budget, 8 bytes); the audited finalize event reports
	// gas_used separately and that's the value we want to surface as GasFeeUsed.
	offset += 8

	// Extract gas_used (8 bytes, u64 little-endian lamports) — actual gas consumed.
	gasUsed := binary.LittleEndian.Uint64(decoded[offset : offset+8])

	// Create OutboundEvent payload
	payload := common.OutboundEvent{
		TxID:          txID,
		UniversalTxID: universalTxID,
		GasFeeUsed:    fmt.Sprintf("%d", gasUsed),
	}
