### Title
`check_microblock_header_signer` / poison-microblock validation accepts a single miner signature malleated into two byte-distinct `MessageSignature`s as proof of equivocation - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`check_microblock_header_signer` (called from `handle_poison_microblock`) only checks that `check_recover_pubkey()` on `mblock_hdr_1` and `mblock_hdr_2` yields the same pubkey hash; it never checks that the two headers actually differ in signed content (e.g. `tx_merkle_root`), and `check_recover_pubkey` is backed by `recover_to_pubkey_without_validating_low_s`, which does not enforce low-S normalization. ECDSA signatures are trivially malleable (flip `S -> n-S`, flip the recovery-id byte) and still recover to the identical public key, as directly demonstrated by the existing `test_with_negated_s` unit test in `stacks-common/src/util/secp256k1/native.rs`.

### Finding Description
The intended equality for a valid poison report is:

`poison_report_valid == two_distinct_valid_signing_acts_by_the_miner_at_conflicting_content`

The actual validation chain is:
1. Mempool admission (`stackslib/src/chainstate/stacks/db/blocks.rs:6844-6861`) only requires `sequence`, `prev_block`, and `version` to match between the two headers, and that `check_recover_pubkey()` on each returns the same pubkey hash. It never requires the headers' signed content (`tx_merkle_root`) to differ. [1](#0-0) 
2. `check_microblock_header_signer` (`stackslib/src/chainstate/stacks/db/transactions.rs:686-713`), invoked from `handle_poison_microblock` (line 752), likewise only compares the two recovered pubkey hashes for equality - it performs no comparison of the header bodies themselves. [2](#0-1) [3](#0-2) 
3. `recover_to_pubkey_without_validating_low_s` deliberately skips the low-S malleability guard that the "safe" `recover_to_pubkey` enforces, explicitly documented as legacy ("You shouldn't use this in new code"). [4](#0-3) 
4. The property this enables - that negating `S` (and flipping the recovery id) on any existing signature yields a byte-different `MessageSignature` that recovers to the exact same public key over the exact same digest - is already proven by the repository's own test, `test_with_negated_s`. [5](#0-4) 

An attacker who merely observes one legitimately-broadcast, honestly-signed microblock header can compute its low-S/high-S malleated twin without any private key, then submit a `PoisonMicroblock` transaction with `mblock_header_1` = the real header and `mblock_header_2` = the malleated clone (identical `version`/`sequence`/`prev_block`/`tx_merkle_root`, different signature bytes only). This transaction passes every check described above and reaches `handle_poison_microblock`, which then punishes the pubkey-hash's associated miner as if they had signed two conflicting microblocks, even though only one signing act ever occurred and no genuine equivocation/fork took place.

The only other guard that legitimately detects miner equivocation, `validate_parent_microblock_stream`, is not on this path - it operates over an actual microblock stream and is unrelated to standalone `PoisonMicroblock` transactions submitted via `will_admit_mempool_tx`/`process_transaction`. [6](#0-5) 

### Impact Explanation
This allows an unprivileged attacker to falsely trigger a poison-microblock commission against an honest miner who never equivocated, diverting/forfeiting that miner's coinbase reward to the malicious reporter (or otherwise mis-signaling reward eligibility) without any real double-signing. This is a reward mis-payment bounded to a single commission event, not a chain split or root-hash divergence, matching the "High" impact bucket in the audit's rubric (poison/reward mis-payment).

### Likelihood Explanation
The attacker needs only to observe one broadcast, validly-signed microblock header from any miner (no BTC spend, no stake, no privileged role) and perform pure elliptic-curve arithmetic (negate `S`, flip recovery id) - a capability inherent to ECDSA and requiring no secret material. This is repeatable against any miner's signed microblock header at any time it becomes visible on the network, making it a low-cost, broadly repeatable attack limited only by the existence of `MINER_REWARD_MATURITY`-window pubkey-hash visibility checks in `handle_poison_microblock`.

### Recommendation
In `check_microblock_header_signer`, use the low-S-enforcing `check_recover_pubkey`/`recover_to_pubkey` path (not `recover_to_pubkey_without_validating_low_s`) so malleated duplicates of the same signature are rejected, and additionally require that the two headers differ in their signed content (e.g., differing `tx_merkle_root` or otherwise proving genuinely conflicting commitments) rather than relying solely on pubkey-hash equality.

### Proof of Concept
Rust integration test plan (to be run as a background Devin session, since this environment cannot execute code):
1. Generate a miner keypair and sign one `StacksMicroblockHeader` (fixed `version`/`sequence`/`prev_block`/`tx_merkle_root`) to get `header_1` with signature `sig_1`.
2. Derive `sig_2` via `sig_1.with_negated_s()` (or equivalent recovery-id-flip + `S -> n-S`), and construct `header_2` identical to `header_1` except for `signature = sig_2`.
3. Assert `header_1.check_recover_pubkey().unwrap() == header_2.check_recover_pubkey().unwrap()` (both sides of the equality: same pubkey hash from two byte-distinct sigs over one act).
4. Build and submit `TransactionPayload::PoisonMicroblock(header_1, header_2)` through `StacksChainState::process_transaction`, and assert it returns `Ok(..)` (i.e., `handle_poison_microblock` accepts it) despite no second, genuinely conflicting microblock ever having been produced by the miner - directly falsifying `poison_report_valid == two_distinct_valid_signing_acts_by_the_miner_at_conflicting_content`.

    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
