### Title
`ensure_match_transaction_info` skips state-checkpoint hash comparison, allowing replay-verify to accept a corrupted/divergent state root - ([File: types/src/transaction/mod.rs])

### Summary
`TransactionOutput::ensure_match_transaction_info` is the sole per-transaction integrity check used by the chunk executor's replay-verify path (`verify_execution` in `execution/executor/src/chunk_executor/mod.rs`) when replaying a backup/archive chunk against locally re-executed VM output. This function checks transaction status, gas used, write-set hash, and event root hash against the trusted `TransactionInfo`, but the code explicitly documents (and implements) that it does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`.

### Finding Description
`ensure_match_transaction_info` at [1](#0-0)  validates only status, gas, write-set hash, and event root hash. The trailing comment states the gap explicitly: [2](#0-1) 

This function is the only check performed in `ChunkExecutorInner::verify_execution`, which is the replay-verify entry point used when a chunk is loaded from a backup/restore stream and locally re-executed for comparison: [3](#0-2) 

The `TransactionInfo` objects fed into this comparison (`transaction_infos` parameter) originate from the backup archive and are only checked for accumulator-proof membership (that they were once part of some ledger with valid `LedgerInfo` signatures) — not that the locally recomputed Jellyfish Merkle root (`state_checkpoint_hash`) matches the archived one. Since `TransactionOutput` (the locally re-executed side) doesn't carry a `state_checkpoint_hash` at all (it's computed later by a separate `DoStateCheckpoint` stage operating on the whole batch, not per-transaction), the comparison function structurally cannot include it without further plumbing — hence the acknowledged TODO.

The result: verify-execution/replay-verify tooling (e.g., db-tool's `replay_on_archive`, and any state-sync/restore path using `VerifyExecutionMode::verify_all()`) will report **success** even though the state Merkle root produced by local re-execution differs from the state root that was actually committed and signed into the ledger's `TransactionInfo`. This directly defeats the stated purpose of "verify execution" for the state-authentication dimension of a `TransactionInfo` (the `state_checkpoint_hash` field is part of the accumulator-proven, hashed `TransactionInfo`, and is the primary binding of a version to its resulting state root).

### Impact Explanation
This breaks the "restore paths must preserve deterministic proof binding" and "hard-fork-only divergence during commit, replay, restore" integrity gates: a node using `verify_execution_mode: verify_all()` (for archival replay verification, chunk executor's execution-verification of untrusted backups, or the upcoming `COMPUTE_TRADING_NATIVE_STATE_ROOTS` feature/position-state trading root) can silently accept and commit a chunk whose recomputed state root diverges from the authenticated on-chain state root, without any error or alert. This is exactly the class of bug that "verify execution" exists to catch — a state-root divergence (whether from a non-deterministic VM bug, a state-merge bug, or a maliciously-tampered but syntactically-well-formed backup with correct write-set/event hashes but no way to alter state_checkpoint_hash consistency) goes undetected, and the corrupted-but-"verified" ledger continues to serve authenticated API responses (e.g., proofs derived from the diverged local state tree) as if they matched the canonical chain.

### Likelihood Explanation
This is not exploitable by an ordinary unprivileged transaction sender against a live consensus node's normal execution path (BlockExecutor's `DoStateCheckpoint`/`DoLedgerUpdate` still hash and compare full checkpoint outputs during live commit, per `do_ledger_update.rs`). The exposure is specifically in the chunk-executor replay-verify path used by db-tool/backup-verification/`verify_execution_mode::verify_all()`, which is triggered by whoever supplies the backup/replay chunk (an operator restoring from a possibly untrusted/third-party backup source, or replay-verify used as a "hard fork detector" across node versions). The bug is a documented, structural gap (not a hypothetical) confirmed by the code's own TODO comment referencing `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, indicating the Aptos team is aware this must be fixed before enabling that feature — i.e., they consider it currently unsafe/incomplete for that purpose.

### Recommendation
Thread the state-checkpoint hash(es) computed by `DoStateCheckpoint` (per-transaction `state_checkpoint_hashes`, `hot_state_checkpoint_hashes`, `position_state_checkpoint_hashes`, as already assembled in `DoLedgerUpdate::assemble_transaction_infos`) into `ensure_match_transaction_info` (or a sibling check called in `verify_execution`), and fail/alert when the locally recomputed checkpoint hash for a `Some(...)`-checkpoint version does not match the corresponding hash on the trusted `TransactionInfo` from the backup. This must be resolved before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS` as the comment states, and should also be applied unconditionally to protect existing replay-verify tooling.

### Proof of Concept
Structural/code-level PoC (repository-verifiable, no external exploit needed since this is a missing-check bug):
1. In `ChunkExecutorInner::verify_execution` [4](#0-3) , local execution output (`execution_output.to_commit.transaction_outputs`) is compared to archived `transaction_infos` solely via `ensure_match_transaction_info`.
2. `ensure_match_transaction_info` [5](#0-4)  never reads or compares `txn_info.state_checkpoint_hash()` (nor hot-state/position checkpoint hash fields present on `TransactionInfo` V1).
3. Construct (conceptually) a chunk where write set, events, gas, and status are identical to a genuine chunk, but the state resulting from applying that write set on top of a different (forked/corrupted) parent state tree yields a different Merkle root than the one recorded in the archived `TransactionInfo.state_checkpoint_hash`. `verify_execution` returns `Ok(end_version)` and the chunk is committed via `remove_and_apply` without any error, because no code path compares the checkpoint hash.
4. This demonstrates the exact corrupted value (the state checkpoint/Merkle root) that fails to be validated during the restore/replay-verify flow, consistent with the code's own acknowledged TODO.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())

    fn verify_execution(
        &self,
        transactions: &[Transaction],
        persisted_aux_info: &[PersistedAuxiliaryInfo],
        transaction_infos: &[TransactionInfo],
        write_sets: &[WriteSet],
        event_vecs: &[Vec<ContractEvent>],
        begin_version: Version,
        end_version: Version,
        verify_execution_mode: &VerifyExecutionMode,
    ) -> Result<Version> {
        // Execute transactions.
        let parent_state = self.commit_queue.lock().latest_state().clone();
        let state_view = self.state_view(parent_state.latest())?;
        let txns = transactions
            .iter()
            .take((end_version - begin_version) as usize)
            .cloned()
            .map(|t| t.into())
            .collect::<Vec<SignatureVerifiedTransaction>>();

        let auxiliary_info = persisted_aux_info
            .iter()
            .take((end_version - begin_version) as usize)
            .map(|persisted_aux_info| AuxiliaryInfo::new(*persisted_aux_info, None))
            .collect::<Vec<_>>();
        let onchain_config = chunk_onchain_config(&state_view)?;
        let execution_output = DoGetExecutionOutput::by_transaction_execution::<V>(
            &V::new(),
            txns.into(),
            auxiliary_info,
            &parent_state,
            state_view,
            onchain_config,
            TransactionSliceMetadata::chunk(begin_version, end_version),
        )?;
        // not `zip_eq`, deliberately
        for (version, txn_out, txn_info, write_set, events) in multizip((
            begin_version..end_version,
            &execution_output.to_commit.transaction_outputs,
            transaction_infos.iter(),
            write_sets.iter(),
            event_vecs.iter(),
        )) {
            if let Err(err) = txn_out.ensure_match_transaction_info(
                version,
                txn_info,
                Some(write_set),
                Some(events),
            ) {
                return if verify_execution_mode.is_lazy_quit() {
                    error!("(Not quitting right away.) {}", err);
                    verify_execution_mode.mark_seen_error();
                    Ok(version + 1)
                } else {
                    Err(err)
                };
            }
        }
        Ok(end_version)
