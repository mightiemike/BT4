### Title
`ActuatorFactory.getActuatorByContract` throws uncaught `NullPointerException` on unregistered `ContractType` instead of `ContractValidateException` - (`File: actuator/src/main/java/org/tron/core/actuator/ActuatorFactory.java`)

### Summary
`ActuatorFactory.getActuatorByContract` calls `TransactionFactory.getActuator(contract.getType())` and immediately invokes `clazz.newInstance()` without checking for `null`, whereas the parallel `ActuatorCreator.getActuatorByContract` explicitly null-checks the result and throws a `ContractValidateException`. For any `Contract.type` value not present in `TransactionFactory`'s `actuatorMap`, the `ActuatorFactory` path will NPE instead of failing gracefully.

### Finding Description
`TransactionFactory.getActuator(ContractType type)` is a simple `Map.get()` lookup that returns `null` for any `ContractType` that has not been registered via `TransactionFactory.register(...)` (registration happens indirectly through actuator subclasses being instantiated by `TransactionRegister.registerActuator()`) [1](#0-0) .

In `ActuatorFactory.getActuatorByContract`, the returned `clazz` is dereferenced unconditionally: [2](#0-1) 
If `clazz` is `null` (unmapped/reserved `ContractType`, e.g. an `UNRECOGNIZED` protobuf enum value or a numeric tag not backed by any registered `AbstractActuator`), `clazz.newInstance()` throws an uncaught `NullPointerException`. This exception is only caught for `IllegalAccessException`/`InstantiationException` in the caller `createActuator`: [3](#0-2) 
`NullPointerException` is a `RuntimeException`, not caught by this `catch (IllegalAccessException | InstantiationException e)` block, so it propagates uncaught.

By contrast, `ActuatorCreator.getActuatorByContract` performs the same lookup but explicitly checks for `null` and raises a checked `ContractValidateException`, which is caught by the generic `catch (Exception e)` in its caller and re-thrown as a `ContractValidateException`: [4](#0-3) 

### Impact Explanation
Any code path that still invokes `ActuatorFactory.createActuator` (it is referenced from `framework/src/main/java/org/tron/core/Wallet.java`) with a `TransactionCapsule` containing a `Contract` whose `type` is not registered in `TransactionFactory` will crash with an uncaught `NullPointerException` instead of a controlled validation failure. Depending on where this is invoked in the call stack (e.g., a gRPC/HTTP handler thread), this results in denial-of-service for that request path, or worse, an unhandled exception bubbling up in a thread not designed to recover, versus the safe `ContractValidateException` behavior in the `ActuatorCreator` path used by the main VM execution flow (`RuntimeImpl.execute`) [5](#0-4) .

### Likelihood Explanation
An attacker only needs to construct a serialized `Transaction` with a `Contract.type` set to an enum value not backed by any registered actuator (e.g. a reserved/future `ContractType` number, or `UNRECOGNIZED`). No privileges are required beyond normal transaction submission. The precondition is that the vulnerable `ActuatorFactory.createActuator`/`getActuatorByContract` path is reachable from an externally-triggerable entrypoint; I confirmed `ActuatorFactory` is referenced in `Wallet.java` but was not able to fully trace, within the available tool budget, the exact method in `Wallet.java` and confirm whether it sits on the `broadcastTransaction` gRPC/HTTP flow specifically (as opposed to an estimate/simulate-only utility method). This should be verified further before treating impact as certain on the main broadcast path.

### Recommendation
Add the same null-check used in `ActuatorCreator.getActuatorByContract` to `ActuatorFactory.getActuatorByContract`: if `TransactionFactory.getActuator(contract.getType())` returns `null`, throw a checked exception (or otherwise skip/reject the contract) instead of calling `newInstance()` on a `null` `Class` reference. Ideally, unify both code paths so there is a single source of truth for actuator instantiation and error handling, eliminating the divergence between `ActuatorFactory` and `ActuatorCreator`.

  private Actuator getActuatorByContract(Contract contract,
      TransactionCapsule tx)
      throws IllegalAccessException, InstantiationException, ContractValidateException {
    Class<? extends Actuator> clazz = TransactionFactory.getActuator(contract.getType());
    if (clazz == null) {
      throw new ContractValidateException("not exist contract " + contract);
    }
    AbstractActuator abstractActuator = (AbstractActuator) clazz.newInstance();
    abstractActuator.setChainBaseManager(chainBaseManager).setContract(contract)
        .setForkUtils(forkController).setTx(tx);
    return abstractActuator;
  }
