### Title
Unbounded recursion when hashing declared Cairo0 class JSON causes stack-overflow DoS - (File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs)

### Summary
A DECLARE V0/V1 transaction lets an unprivileged sender submit an arbitrary Cairo0 `program` object. This raw JSON eventually reaches `compute_cairo_hinted_class_hash` / `compute_deprecated_class_hash`, which round-trip the program through `serde_json::Value`, a custom `sort_json_value` recursive sorter, and `CairoContractDefinition` (holding several `serde_json::Value` fields), all without any recursion-depth or nesting-depth limit.

### Finding Description
`CairoContractDefinition` in [1](#0-0)  declares `abi: serde_json::Value` and other unconstrained fields, and `CairoProgram` similarly holds `identifiers: serde_json::Value`, `hints: BTreeMap<u64, Vec<serde_json::Value>>`, `reference_manager: serde_json::Value`, and `attributes` entries with `accessible_scopes`/`flow_tracking_data` as `serde_json::Value` [2](#0-1) . `compute_cairo_hinted_class_hash` first serializes the class to a `serde_json::Value`, recursively sorts every nested object with `sort_json_value` (which recurses without any depth bound), then deserializes it back into `CairoContractDefinition` via `serde_json::from_slice` [3](#0-2) . Both `serde_json`'s own recursive-descent value parser and the custom `sort_json_value` function recurse once per nesting level of attacker-controlled JSON, with no maximum-depth check, exactly the bug class described in CVE-2025-5302 (JSONReader uncontrolled recursion). `compute_deprecated_class_hash` performs an equivalent round trip [4](#0-3) .

These functions are invoked from the Starknet OS hint implementation that loads a `DeprecatedCompiledClass` into VM memory during transaction (re-)execution — `compute_cairo_hinted_class_hash(self)` is called directly inside `LoadCairoObject for ContractClass::load_into` [5](#0-4) , which is on the path that computes/validates the class hash preimage for a submitted DECLARE V0/V1 Cairo0 class, i.e. reachable purely from a transaction sender declaring a crafted, deeply nested `abi`/`hints`/`identifiers` JSON structure (e.g., thousands of nested arrays/objects).

### Impact Explanation
Rust's default thread stack size is limited (commonly 2–8MB), and unbounded JSON recursion (both in `serde_json`'s parser/`Value` drop and in `sort_json_value`) can exhaust the stack, aborting the process with SIGSEGV rather than returning a catchable error (stack overflows in Rust are not `panic`-catchable). If this code path executes during Starknet OS re-execution/class-hash verification of a DECLARE transaction, a single malicious but syntactically valid Cairo0 class declaration can crash the sequencer node process, causing denial of service and preventing the network from confirming new transactions during the crash/restart window — satisfying the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Likelihood is High for any unprivileged party able to submit a Cairo0 (V0/V1) DECLARE transaction with a crafted `program.abi`/`program.hints`/`program.identifiers`/`program.reference_manager` payload containing deep nesting. No special privileges, prior state, or coordination are required — a single transaction suffices, and JSON nesting depth needed to exhaust a multi-MB stack is well within typical request-body size limits.

### Recommendation
- Enforce a maximum JSON nesting depth check before/while deserializing user-submitted contract class JSON (both at the gateway ingress for declare transactions, and defensively before calling `compute_cairo_hinted_class_hash`/`compute_deprecated_class_hash`), rejecting classes whose `abi`, `hints`, `identifiers`, `reference_manager`, or `attributes` values exceed a safe depth (e.g., mirroring the JSONReader fix's depth cap).
- Replace the naive recursive `sort_json_value` with an iterative (stack-based) implementation, or bound its recursion depth explicitly.
- Consider running class-hash computation for externally supplied classes on a dedicated thread with a guarded/limited stack size and depth pre-check, so a stack overflow surfaces as a controlled error instead of crashing the process.

### Proof of Concept
1. Craft a DECLARE V0/V1 transaction whose Cairo0 `contract_class.program` field contains a deeply nested JSON structure in `abi` (or `identifiers`/`hints`/`reference_manager`), e.g. `{"abi": {"a":{"a":{"a": ... }}}}` nested tens of thousands of levels deep, staying under the request body size limit by using minimal repeated keys.
2. Submit the transaction so it reaches Starknet OS class-hash computation (`compute_deprecated_class_hash` → `compute_cairo_hinted_class_hash`), triggering `serde_json::to_value` / `sort_json_value` / `serde_json::from_slice::<CairoContractDefinition>` on the nested structure.
3. Observe the sequencer/OS process crash with a stack overflow (SIGSEGV) rather than returning a `HintedClassHashError`, denying service to the node processing the transaction.

Note: I could not fully trace the exact call path from the HTTP gateway's DECLARE V0/V1 acceptance through to block building/OS re-execution invocation of `compute_deprecated_class_hash` within the indexed portion of the codebase (index size limits may have excluded some intermediate files); a Devin session with full repo access would be needed to confirm the precise trigger point in the live transaction-processing pipeline versus only being reachable during offline OS proving.

pub fn compute_cairo_hinted_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    // Serialize to Value, sort all objects by keys for deterministic output, then to bytes.
    // The sorting is necessary because serde_json with `preserve_order` feature enabled
    // maintains insertion order instead of sorting keys.
    // TODO(Meshi): Compute hinted hashes when loading serialized contracts from storage, before
    // deserializing, to avoid back-and-forth serde.
    let contract_value = serde_json::to_value(contract_class)?;
    let sorted_contract_value = sort_json_value(contract_value);
    let contract_definition_vec = serde_json::to_vec(&sorted_contract_value)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;
