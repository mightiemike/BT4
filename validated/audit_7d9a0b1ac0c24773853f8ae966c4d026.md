### Title
Missing zero-address check on inbound `Recipient` allows attacker to permanently burn bridged PRC20 funds - (File: x/uexecutor/types/inbound.go)

### Summary
`Inbound.ValidateForExecution` accepts any syntactically valid hex address as `Recipient` for `FUNDS`/`GAS` inbounds, including the EVM zero address, and `depositPRC20`/`CallPRC20Deposit` mints PRC20 tokens straight to that address with no null-address guard, unlike the escrow/Airdrop pattern from the external report.

### Finding Description
`ValidateForExecution` requires `Recipient` to be non-empty and to pass `utils.IsValidAddress(p.Recipient, utils.HEX)`, which only wraps `common.IsHexAddress` — a purely syntactic check that returns `true` for `0x0000000000000000000000000000000000000000`. [2](#0-1) [3](#0-2) 

The `Recipient` field itself is derived verbatim from an attacker-controlled, indexed topic in the source-chain gateway event (`log.Topics[2]`), with no on-chain filtering by the universal client before it is submitted as part of the vote payload: [1](#0-0) 

`Canonicalize()` normalizes the recipient string but does not reject the zero address either — it only trims/lower-cases via `LenientCanonicalizeEVMAddress`: [4](#0-3) 

Once quorum is reached, `ExecuteInboundFunds` calls `depositPRC20` with `common.HexToAddress(inbound.Recipient)` verbatim, which in turn calls `CallPRC20Deposit`, minting the bridged PRC20 amount to whatever address was supplied — including the zero address: [5](#0-4) [6](#0-5) [7](#0-6) 

Since this is treated as a successful deposit (the PRC20 mint call itself does not fail on address zero), no `INBOUND_REVERT` outbound is created — the funds are simply minted to an address nobody controls, mirroring the exact "no null-address check" bug class from the external report (`setEscrowContractAddress` / `Airdrop` constructor), but here the impact is direct fund loss rather than a broken pointer.

### Impact Explanation
An unprivileged external user who deposits real value into the source-chain gateway (e.g. calling `addFunds`/`sendFunds` with `recipient = 0x000...000`) causes honest Universal Validators to observe, vote, and finalize an inbound with a valid-looking zero-address recipient. The protocol then mints the corresponding PRC20 tokens to the zero address on Push Chain — a permanent, protocol-enforced loss of the user's own bridged funds (and, since PRC20 total supply increases, an unauthorized/unreachable mint from the perspective of any legitimate holder). This matches the "permanent loss" / "unauthorized mint" impact categories in scope. It is a self-inflicted loss for the attacker/depositor in the base case, but the same code path applies to `RevertInstructions.FundRecipient` and outbound revert/refund flows (`buildRevertOutbound`, `handleFailedOutbound`, `applyGasRefund`), all of which also just check for an *empty* string, not the zero address, before minting/refunding — meaning a griefer could also craft an inbound whose failure path forces a refund to the zero address (via `FundRecipient` or fallback to `Sender`, both of which come from attacker-controlled source-chain data with only "non-empty" validation), destroying the refund that should have gone back to the honest original depositor. [8](#0-7) [9](#0-8) 

### Likelihood Explanation
High likelihood of triggerability (any user can set `recipient=0x0` in a normal gateway deposit call with no special privileges), but the primary and clearest impact (self-burn of one's own deposit) has limited attacker incentive. It becomes materially more concerning combined with the `RevertInstructions.FundRecipient` / `Sender` refund fallback paths, where a malicious or buggy relayer/source-chain contract integration could cause legitimate depositors' refunds to be misdirected to the zero address, permanently freezing user funds that should have been recoverable.

### Recommendation
Add an explicit zero-address rejection (matching the recommendation in the external report) in the following places:
- `Inbound.ValidateForExecution` for `Recipient` on `FUNDS`/`GAS`/CEA payload paths (reject `EvmZeroAddress`, not just empty string).
- `RevertInstructions.FundRecipient` validation (both inbound canonicalization/validation and outbound `handleFailedOutbound`/`applyGasRefund`), falling back to `Sender` (or failing outright) when `FundRecipient` resolves to the zero address.
- `depositPRC20`/`CallPRC20Deposit` as defense-in-depth, refusing to mint to `common.Address{}`.

### Proof of Concept
1. On a configured source chain, call the gateway's `addFunds`/`sendFunds` method depositing a whitelisted token, setting the `recipient` indexed parameter to `0x0000000000000000000000000000000000000000`.
2. The universal client's `parseUniversalTxEvent` parses this directly into `Inbound.Recipient` with no filtering. [1](#0-0) 
3. Universal Validators vote `MsgVoteInbound` for this event; `ValidateForExecution` passes because `utils.IsValidAddress("0x0...0", HEX)` returns `true`. [2](#0-1) 
4. Upon quorum, `ExecuteInboundFunds` → `depositPRC20` → `CallPRC20Deposit` mints the bridged amount to the zero address; the PCTx is recorded as `SUCCESS`, so no revert/refund outbound is created and the funds are unrecoverable. [10](#0-9)

func (p *Inbound) Canonicalize() {
	p.SourceChain = strings.TrimSpace(p.SourceChain)
	p.TxHash = utils.LenientCanonicalizeTxHash(p.SourceChain, p.TxHash)
	p.Sender = utils.LenientCanonicalizeAddress(p.SourceChain, p.Sender)
	p.AssetAddr = utils.LenientCanonicalizeAddress(p.SourceChain, p.AssetAddr)
	// Recipient lives on Push Chain (EVM) regardless of source chain.
	p.Recipient = utils.LenientCanonicalizeEVMAddress(p.Recipient)
	p.LogIndex = strings.TrimSpace(p.LogIndex)
	p.Amount = strings.TrimSpace(p.Amount)
	p.RawPayload = utils.CanonicalizeHexBlob(p.RawPayload)
	p.VerificationData = utils.CanonicalizeHexBlob(p.VerificationData)
	if p.RevertInstructions != nil {
		// Refunds return to the source chain.
		p.RevertInstructions.FundRecipient = utils.LenientCanonicalizeAddress(p.SourceChain, p.RevertInstructions.FundRecipient)
	}
}

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

func (k Keeper) CallPRC20Deposit(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // sender: module account
		handlerAddr,        // destination
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20Token",
		prc20Address,
		amount,
		to,
	)
}
