### Title
Unbounded full-table `PendingInbounds` scan on every inbound ballot finalization enables validator-vote-processing DoS - (File: x/uexecutor/keeper/ballot_hooks.go)

### Summary
This is the closest scoped analog to the Moloch `_ragequit` "unbounded loop over a whitelist grows with usage until the transaction can no longer fit in a block" bug class. Instead of an unbounded token whitelist, Push Chain's `x/uexecutor` keeper performs an unbounded `Walk` over the entire `PendingInbounds` collection every single time *any* inbound ballot reaches a terminal state (PASSED/REJECTED/EXPIRED), in order to locate the entry that owns that ballot ID.

### Finding Description
`AfterBallotTerminal` → `afterInboundBallotTerminal` in [1](#0-0)  scans the full `PendingInbounds` collection with `h.k.PendingInbounds.Walk(ctx, nil, ...)` on every terminal ballot transition, because "Ballot IDs are one-way canonical digests (not reversible)" and there is no secondary index from `ballotID -> utxKey`. The comment explicitly assumes "the pending set is small and transient" [2](#0-1) , but nothing in the code enforces that assumption.

`PendingInbounds` entries are created from ordinary, unprivileged, user-reachable input: any external-chain deposit/tx that a UV observes and votes on creates (or appends a variant to) a `PendingInboundEntry`, keyed by `utx_key = sha256(source_chain:tx_hash:log_index)`, as described in [3](#0-2) . `VoteInbound` (invoked per-vote in [4](#0-3) ) calls `RecordInboundVote` and `VoteOnInboundBallot`, which internally drives `x/uvalidator`'s generic ballot machine (`CheckIfFinalizingVote` → `MarkBallotFinalized` → `fireBallotTerminalHook`, see [5](#0-4) ). Each finalization fires the `PendingInbounds.Walk` above.

An unprivileged attacker who controls source-chain activity (e.g., submits a large volume of distinct low-value deposits/transactions on any supported external chain) can grow the `PendingInbounds` set arbitrarily large before entries clear, because clearing an entry itself requires the same O(n) walk to succeed. As the set grows, the per-finalization cost of `afterInboundBallotTerminal` grows linearly with the total number of outstanding pending inbounds, not with the attacker's own entry — directly mirroring the Moloch pattern where the cost of an unrelated, necessary operation (`_ragequit`) scales with the size of an attacker-influenced global list (whitelisted tokens).

### Impact Explanation
Because `VoteInbound` messages are processed as ordinary state-transitions by every UV for every deposit, and the hook fires synchronously inside that same message handling, an attacker who inflates `PendingInbounds` degrades or can eventually block inbound ballot finalization chain-wide once the walk cost exceeds available per-tx/per-block gas or execution budget. Since finalization is the only path that removes entries from `PendingInbounds` (via the very code path being slowed down), this can become self-reinforcing: slower finalization keeps more entries pending, which further slows finalization. Legitimate users' deposits observed by honest, non-malicious validators would fail to progress to `UniversalTx` creation, i.e., a DoS on the universal execution path reachable purely through ordinary deposit activity, without any privileged or malicious-validator assumption.

### Likelihood Explanation
The trigger requires no privileged access — only the ability to originate many distinct inbound events on a supported external chain (small deposits are cheap to generate on most low-fee external chains). Whether this reaches full transaction failure depends on the currently unverified block/tx gas budget for UV-submitted vote messages (potentially gasless per [6](#0-5) -style modules) and on how quickly UVs can process/finalize votes relative to the attacker's inbound generation rate — I was not able to fully verify the exact gas-metering behavior for `MsgVoteInbound` (whether it uses an infinite gas meter or is bounded like a normal message) before running out of iterations, so the precise threshold for practical DoS is unconfirmed.

### Recommendation
Maintain a direct `ballotID -> utxKey` secondary index (a `Map[string]string` or similar collection) updated whenever a variant/ballot is added to `PendingInbounds`, so `afterInboundBallotTerminal` can do an O(1) lookup instead of a full-table `Walk`. Alternatively, cap the maximum number of concurrently pending `PendingInbounds` entries (analogous to Moloch's `MAX_TOKEN_WHITELIST_COUNT`) and/or bound per-source-chain pending entries, rejecting or rate-limiting new inbound votes once the cap is reached.

### Proof of Concept
Conceptual, not executed (requires a running devnet):
1. Attacker sends N distinct low-value transactions to the monitored gateway on a supported source chain (e.g., Ethereum Sepolia), each with a unique `tx_hash`/`log_index`, generating N unique `PendingInboundEntry` records.
2. UVs vote on each inbound in `VoteInbound`, growing `PendingInbounds` before ballots finalize.
3. Measure the wall-clock/gas cost of `afterInboundBallotTerminal`'s `PendingInbounds.Walk` as N increases; demonstrate that the per-finalization cost scales linearly with N, and that at sufficiently large N (bounded only by attacker's ability to generate cheap external-chain transactions within the ballot expiry window) normal inbound finalization for other users' deposits is measurably degraded or halted.

func (h BallotHooks) afterInboundBallotTerminal(
	ctx context.Context,
	ballotID string,
	status uvalidatortypes.BallotStatus,
) error {
	// Ballot IDs are one-way canonical digests (not reversible), so locate
	// the owning audit-trail entry by scanning PendingInbounds for the
	// variant carrying this ballot ID. The pending set is small and
	// transient, and this hook only fires on terminal transitions.
	var (
		utxKey string
		entry  types.PendingInboundEntry
		found  bool
	)
	err := h.k.PendingInbounds.Walk(ctx, nil, func(key string, e types.PendingInboundEntry) (bool, error) {
		for _, v := range e.Variants {
			if v.BallotId == ballotID {
				utxKey, entry, found = key, e, true
				return true, nil
			}
		}
		return false, nil
	})
	if err != nil {
		return err
	}

### `PendingInbounds`

- **Created** by the FIRST validator vote on a given inbound (`RecordInboundVote`
  inside `VoteInbound`). The chain learns about the source-chain event from
  validator observations.
- **Keyed** by `utx_key = sha256(source_chain:tx_hash:log_index)`.
- **Variant-aware:** when validators marshal slightly different `Inbound` bytes
  for the same logical event (different decoded fields, formatting, etc.), each
  unique payload becomes its own `InboundVariant` inside the entry, with its
  own `ballot_id`, `voters[]`, and `terminal_status`.
- **Removed** when ALL related ballot variants reach a terminal state. If any
  variant ended `PASSED`, the existing post-finalization path in `VoteInbound`
  produced a `UniversalTx`. If ALL variants ended `EXPIRED`/`REJECTED`, the
  full per-variant audit trail is moved to `ExpiredInbounds` for the future
  escape-hatch refund flow.
- The cleanup-on-terminal logic lives in `keeper/ballot_hooks.go` (the
  `BallotHooks` impl wired into `x/uvalidator`).

func (k Keeper) VoteInbound(ctx context.Context, universalValidator sdk.ValAddress, inbound types.Inbound) error {
	// Canonicalize first so every derived key + the stored inbound use one
	// representation per logical event.
	inbound.Canonicalize()

	k.Logger().Info("vote inbound received",
		"validator", universalValidator.String(),
		"source_chain", inbound.SourceChain,
		"tx_hash", inbound.TxHash,
		"tx_type", inbound.TxType.String(),
		"sender", inbound.Sender,
	)

	// Check inbound enabled before any state changes
	enabled, err := k.uregistryKeeper.IsChainInboundEnabled(ctx, inbound.SourceChain)
	if err != nil {
		return errors.Wrap(err, "failed to check inbound enabled")
	}
	if !enabled {
		k.Logger().Warn("vote inbound rejected: chain inbound disabled", "source_chain", inbound.SourceChain)
		return fmt.Errorf("inbound is disabled for chain %s", inbound.SourceChain)
	}

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Step 1: Derive UTX key from the original inbound data (source_chain:tx_hash:log_index)
	universalTxKey := types.GetInboundUniversalTxKey(inbound)
	found, err := k.HasUniversalTx(ctx, universalTxKey)
	if err != nil {
		return errors.Wrap(err, "failed to check UniversalTx")
	}
	if found {
		k.Logger().Warn("vote inbound rejected: utx already exists", "utx_key", universalTxKey)
		return fmt.Errorf("universal tx with key %s already exists", universalTxKey)
	}

	// use a temporary context to not commit any ballot state change in case of error
	tmpCtx, commit := sdkCtx.CacheContext()

	// Step 2: Record this validator's vote in the per-utx PendingInbounds entry
	// (variant-aware audit trail). Each unique Inbound payload becomes its own
	// variant; multiple variants per utx_key indicate validator divergence.
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return errors.Wrap(err, "failed to derive inbound ballot key")
	}
	if err := k.RecordInboundVote(tmpCtx, inbound, universalValidator.String(), ballotKey); err != nil {
		return err
	}

// MarkBallotFinalized moves a ballot from active to finalized (PASSED or REJECTED).
// Side-effect ordering matches MarkBallotExpired: secondary indexes are
// updated before the canonical ballot record is rewritten with its final status.
//
// Fires the BallotHooks terminal callback (if registered) AFTER all writes
// have committed. Hook errors are logged but do NOT block the terminal
// transition.
func (k Keeper) MarkBallotFinalized(ctx context.Context, id string, status types.BallotStatus) error {
	if status != types.BallotStatus_BALLOT_STATUS_PASSED && status != types.BallotStatus_BALLOT_STATUS_REJECTED {
		return fmt.Errorf("invalid finalization status: %v", status)
	}

	ballot, err := k.Ballots.Get(ctx, id)
	if err != nil {
		return err
	}

	k.Logger().Debug("marking ballot as finalized",
		"ballot_id", id,
		"final_status", status.String(),
	)

	if err := k.ActiveBallotIDs.Remove(ctx, id); err != nil {
		return err
	}
	if err := k.FinalizedBallotIDs.Set(ctx, id); err != nil {
		return err
	}

	ballot.Status = status
	if err := k.Ballots.Set(ctx, id, ballot); err != nil {
		return err
	}

	k.fireBallotTerminalHook(ctx, ballot.Id, ballot.BallotType, status)
	return nil
}

// fireBallotTerminalHook invokes the registered BallotHooks (if any) and
// log-swallows any error. Terminal transitions must never be blocked by
// secondary-index side-effect failure.
func (k Keeper) fireBallotTerminalHook(
	ctx context.Context,
	ballotID string,
	ballotType types.BallotObservationType,
	status types.BallotStatus,
) {
	if k.ballotHooks == nil {
		return
	}
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	if err := k.ballotHooks.AfterBallotTerminal(sdkCtx, ballotID, ballotType, status); err != nil {
		k.Logger().Warn("ballot terminal hook returned error",
			"ballot_id", ballotID,
			"ballot_type", ballotType.String(),
			"status", status.String(),
			"err", err.Error(),
		)
	}
}
