### Title
Fee transfer to the sequencer can be treated as succeeded even when the ERC20 transfer entry point internally fails - (File: `crates/blockifier/src/transaction/account_transaction.rs`)

### Summary
`AccountTransaction::execute_fee_transfer` invokes the fee-token `transfer` entry point with the plain `CallEntryPoint::execute` API instead of `CallEntryPoint::non_reverting_execute`, and does not inspect the returned `CallInfo.execution.failed` flag before treating the fee transfer as successful.

### Finding Description
`execute_fee_transfer` builds a `CallEntryPoint` for the ERC20 `transfer` selector to the sequencer address and calls: [1](#0-0) 

It uses `.execute(...)`, whose only error path is a hard `EntryPointExecutionError` (VM/storage/class errors, out-of-recursion, etc.): [2](#0-1) 

Contrast this with the dedicated `non_reverting_execute` wrapper that exists specifically to catch the case where a call executes without a hard VM error but internally panics/fails (`call_info.execution.failed == true`), and explicitly converts that into an `Err(EntryPointExecutionError::ExecutionFailed)`: [3](#0-2) 

`non_reverting_execute` is used elsewhere for validate-style calls where an unchecked internal failure must not be silently accepted (`transactions.rs`, `deprecated_syscalls/hint_processor.rs`). The fee-transfer path, however, uses the plain `.execute(...)` and immediately wraps the `Result` into `Ok(CallInfo)` for `handle_fee`: [4](#0-3) 

Nowhere downstream (`handle_fee`, `TransactionReceipt::from_account_tx`, `PostExecutionReport`, `complete_fee_transfer_flow`) checks `fee_transfer_call_info.execution.failed`; the code base's own `CallInfo.execution.failed` semantics — demonstrated repeatedly in tests such as `test_call_contract_that_panics` — show that a callee can return `Ok(CallInfo{ execution: CallExecution{ failed: true, .. }, ..})` while the caller still completes normally unless it explicitly checks `failed` (as `non_reverting_execute` does) or reverts via the `execute_inner_call` syscall path: [5](#0-4) [6](#0-5) 

Because the fee-transfer call is a top-level `CallEntryPoint::execute` (not routed through the inner-call syscall machinery that reverts on `failed`, and not wrapped with `non_reverting_execute`), an internal panic/failure inside the fee token's `transfer` (e.g. a Cairo1 fee-token implementation that panics/returns a failure result instead of hard-erroring) is not detected. The transaction proceeds to commit: nonce is incremented, execution state is committed, and the transaction is reported as accepted with a `fee_transfer_call_info` that actually represents a failed transfer.

This mirrors the referenced report's root cause exactly: a treasury/fee-recipient transfer's return/failure status is not validated, so the caller's bookkeeping (nonce bump, state commit, reported "accepted" transaction) proceeds as if the transfer succeeded.

### Impact Explanation
If accounting proceeds despite a failed fee transfer, the sequencer's fee balance is not actually credited even though the block/state diff and receipt record the transaction as accepted and fee-paid — an accounting discrepancy that misrepresents collected fees (potential loss of fee revenue / incorrect state commitment believed to reflect a paid fee). Because the currently deployed Starknet fee token (Cairo0 ERC20) always asserts sufficient balance and reverts hard on insufficient funds (propagating as a VM-level error caught by the outer `.map_err`), this specific class is not exploitable against the current canonical fee-token class. However, the sequencer code itself does not enforce the invariant at the `execute_fee_transfer` call site — it silently relies on the current fee-token implementation always hard-erroring instead of panicking gracefully with `failed=true`. This is a latent defect: any future/whitelisted fee-token class (including Cairo1, or an update to the deployed class) that panics through a caught path instead of raising a `VmException`/state-read error would let a transaction with a failed fee transfer be committed as accepted.

### Likelihood Explanation
Reachable by any unprivileged account sending a normal transaction — no special privileges required to reach `execute_fee_transfer`; it runs unconditionally for every fee-charging transaction. Exploitability is currently gated on the fee-token contract's own behavior (whether a failure manifests as `execution.failed=true` in `CallInfo` versus a hard `EntryPointExecutionError`), which the current bundled Cairo0 ERC20 fee token avoids by asserting balance sufficiency. Likelihood is therefore Low-to-Medium: it requires a fee token class whose failure mode is a caught panic rather than a hard error, which is plausible for Cairo1 fee-token implementations but not confirmed for the currently deployed fee token.

### Recommendation
In `execute_fee_transfer` (`crates/blockifier/src/transaction/account_transaction.rs`), replace `fee_transfer_call.execute(...)` with `fee_transfer_call.non_reverting_execute(...)`, matching the pattern already used for `__validate__`/deploy calls, so that any `CallInfo.execution.failed == true` result is converted into an `EntryPointExecutionError` and the transaction is reverted (or the whole tx execution aborted) rather than committed as if the fee transfer succeeded.

### Proof of Concept
Not applicable as a live exploit against current mainnet state: reproduction would require deploying/whitelisting a fee-token class whose `transfer` implementation fails via a Cairo1 panic (returned as `CallInfo.execution.failed = true`) rather than a hard VM error, then observing that `AccountTransaction::execute_fee_transfer` returns `Ok(CallInfo{failed: true})`, `handle_fee` treats it as `Some(fee_transfer_call_info)`, and the transaction is committed/accepted (nonce incremented, receipt fee recorded) despite the sequencer's fee balance never actually increasing — analogous to the cited `test_call_contract_that_panics` test demonstrating that `execute()` returns `Ok` with `execution.failed = true` for a panicking inner call. impl CallEntryPoint {
    pub fn execute(
        mut self,
        state: &mut dyn State,
        context: &mut EntryPointExecutionContext,
        remaining_gas: &mut u64,
    ) -> EntryPointExecutionResult<CallInfo> {
        let tx_context = &context.tx_context;
        let strip_vm_frames = context.versioned_constants().strip_vm_frames_in_sierra_gas;
        let mut decrement_when_dropped = RecursionDepthGuard::new(
            context.current_recursion_depth.clone(),
            context.versioned_constants().max_recursion_depth,
        );
        decrement_when_dropped
            .try_increment_and_check_depth()
            .map_err(|e| e.annotated(TrackedResource::CairoSteps, strip_vm_frames))?;

        // Validate contract is deployed.
        let storage_class_hash = state.get_class_hash_at(self.storage_address).map_err(|e| {
            EntryPointExecutionError::from(e)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames)
        })?;
        if storage_class_hash == ClassHash::default() {
            return Err(EntryPointExecutionError::from(
                PreExecutionError::UninitializedStorageAddress(self.storage_address),
            )
            .annotated(TrackedResource::CairoSteps, strip_vm_frames));
        }

        let class_hash = match self.class_hash {
            Some(class_hash) => class_hash,
            None => storage_class_hash, // If not given, take the storage contract class hash.
        };
        // Hack to prevent version 0 attack on argent accounts.
        if tx_context.tx_info.version() == TransactionVersion::ZERO
            && class_hash
                == ClassHash(
                    Felt::from_hex(FAULTY_CLASS_HASH).expect("A class hash must be a felt."),
                )
        {
            return Err(EntryPointExecutionError::from(PreExecutionError::FraudAttempt)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames));
        }
        // Add class hash to the call, that will appear in the output (call info).
        self.class_hash = Some(class_hash);
        let compiled_class = state.get_compiled_class(class_hash).map_err(|e| {
            EntryPointExecutionError::from(e)
                .annotated(TrackedResource::CairoSteps, strip_vm_frames)
        })?;

        context.revert_infos.0.push(EntryPointRevertInfo::new(
            self.storage_address,
            storage_class_hash,
            context.n_emitted_events,
            context.n_sent_messages_to_l1,
        ));

        // This is the last operation of this function.
        execute_entry_point_call_wrapper(
            self.into_executable(class_hash),
            compiled_class,
            state,
            context,
            remaining_gas,
        )
    }

    /// Similar to `execute`, but returns an error if the outer call is reverted.
    pub fn non_reverting_execute(
        self,
        state: &mut dyn State,
        context: &mut EntryPointExecutionContext,
        remaining_gas: &mut u64,
    ) -> EntryPointExecutionResult<CallInfo> {
        let execution_result = self.execute(state, context, remaining_gas);
        if let Ok(call_info) = &execution_result {
            // Update revert gas tracking (for completeness - value will not be used unless the tx
            // is reverted).
            context.sierra_gas_revert_tracker.update_with_next_remaining_gas(
                call_info.tracked_resource,
                GasAmount(*remaining_gas),
            );
            // If the execution of the outer call failed, revert the transction.
            if call_info.execution.failed {
                return Err(EntryPointExecutionError::ExecutionFailed {
                    error_trace: extract_trailing_cairo1_revert_trace(
                        call_info,
                        Cairo1RevertHeader::Execution,
                    ),
                }
                .annotated(
                    call_info.tracked_resource,
                    context.versioned_constants().strip_vm_frames_in_sierra_gas,
                ));
            }
        }

        execution_result
    }

    pub fn execute_inner_call(
        &mut self,
        call: CallEntryPoint,
        remaining_gas: &mut u64,
    ) -> SyscallResult<Vec<Felt>> {
        let revert_idx = self.context.revert_infos.0.len();

        let call_info = call.execute(self.state, self.context, remaining_gas)?;

        let mut raw_retdata = call_info.execution.retdata.0.clone();
        let call_failed = call_info.execution.failed;
        self.inner_calls.push(call_info);
        if call_failed {
            self.context.revert(revert_idx, self.state)?;

            // Delete events and l2_to_l1_messages from the reverted call.
            let reverted_call = &mut self.inner_calls.last_mut().unwrap();
            let mut stack: Vec<&mut CallInfo> = vec![reverted_call];
            while let Some(call_info) = stack.pop() {
                call_info.execution.events.clear();
                call_info.execution.l2_to_l1_messages.clear();
                // Add inner calls that did not fail to the stack.
                // The events and l2_to_l1_messages of the failed calls were already cleared.
                stack.extend(
                    call_info
                        .inner_calls
                        .iter_mut()
                        .filter(|call_info| !call_info.execution.failed),
                );
            }

            raw_retdata.push(ENTRYPOINT_FAILED_ERROR_FELT);
            return Err(SyscallExecutionError::Revert { error_data: raw_retdata });
        }

        Ok(raw_retdata)
    }
