### Title
Alpenglow reward-points division truncates rewards to zero while `credits_observed` is unconditionally advanced, permanently losing inflation rewards for small delegators - ([File: runtime/src/inflation_rewards/points.rs])

### Summary
`calculate_alpenglow_points()` computes a stake's earned reward points for an epoch as `earned_credits * stake_amount / total_stake`, a single integer division performed once per epoch. `calc_earned_credits()`, which is invoked before this division, unconditionally advances `new_credits_observed` to `final_epoch_credits` regardless of whether the subsequent division truncates the reward to zero. This is structurally identical to the reported LoopFi `RewardManager._updateRewardIndex()` bug: an accumulator that represents "what has been paid/observed" (`credits_observed`, analogous to `lastBalance`) is advanced even when the reward index (`ag_points`) fails to advance because of division rounding, permanently forfeiting the reward for that period.

### Finding Description
In `calc_earned_credits()`, the function computes `earned_credits` and then always does: [1](#0-0) 

`calculate_alpenglow_points()` then divides the just-earned credits by `total_stake` in a single step, which floors to zero whenever `earned_credits * stake_amount < total_stake`: [2](#0-1) 

Crucially, this division happens on a per-epoch basis directly inside the points calculation (unlike the Tower path in `tower_epoch_credits_iter`, which accumulates raw `stake_amount * earned_credits` products across all unredeemed epochs and only divides once, at final redemption, by `point_value.points`): [3](#0-2) 

Back in `calculate_stake_rewards()`, when `ag_points == 0`, the code explicitly still advances `credits_observed` to the new value even though zero reward was paid: [4](#0-3) 

Because `credits_observed` is moved forward to `final_epoch_credits` for the already-processed epoch, the fractional (truncated) reward for that epoch can never be recovered in a later epoch — there's no mechanism to carry over the undistributed remainder, unlike Tower's deferred-division design which naturally accumulates fractional points across epochs until a single final division.

### Impact Explanation
Any staker whose `stake_amount` is small relative to a validator's `total_stake` (a very common situation for popular validators with concentrated total delegated stake) can have `earned_credits * stake_amount / total_stake` floor to zero on every single epoch under the full Alpenglow reward path. Since `credits_observed` still advances, that staker permanently loses 100% of the inflation reward they were nominally due for that epoch, with no way to "catch up" in a future epoch. This is a genuine, consensus-deterministic loss of lamports owed to legitimate stakers (not a rounding of at most 1 lamport as intended elsewhere in the code, e.g., the explicit Tower "cancel rewarding to avoid unfair one-sided split" comment) — it is a systematic, cumulative loss over the account's staking lifetime.

### Likelihood Explanation
This triggers under ordinary, unprivileged conditions — no malicious transaction or actor is required. Any validator with a large total delegated stake and any delegator with a comparatively small stake will hit this rounding-to-zero path every epoch once Alpenglow reward calculation (`AlpenglowEpochType::Alpenglow`) is active, since `calculate_alpenglow_points` is on the normal reward-calculation path used for every stake account (`calculate_stake_points_and_credits` → `calculate_alpenglow_points`, called from `calculate_reward_points_partitioned`/`calculate_stake_rewards_and_commissions` during ordinary epoch-boundary reward computation). This is inherent to the current implementation, not a rare edge case.

### Recommendation
Defer the division by `total_stake` to the final reward-redemption step, mirroring the Tower design: accumulate `earned_credits * stake_amount` as raw (undivided) points in `ag_points`, and only perform a single division (by an appropriately scaled total-points value) when calculating the actual lamport payout in `calculate_stake_rewards()`. Alternatively, if `earned_points` rounds to zero, do not advance `credits_observed` past `initial_epoch_credits` for the un-rewarded portion, so that the fractional credit can accumulate and be redeemed in a subsequent epoch instead of being silently discarded.

### Proof of Concept
1. Validator V has `total_stake` (across all its delegators) of 1,000,000 SOL = 10^15 lamports (`reward_epoch_delegated_stakes.delegated_stakes[V] = 10^15`).
2. Delegator D stakes 1 SOL = 10^9 lamports to V (`stake_amount = 10^9`).
3. In a given epoch, V earns `earned_credits = 100` (typical order of magnitude for per-epoch vote credits).
4. `calculate_alpenglow_points` computes `earned_points = 100 * 10^9 / 10^15 = 10^11 / 10^15 = 0` (floor division) — see `runtime/src/inflation_rewards/points.rs:300`.
5. Meanwhile `calc_earned_credits` (called just before, at `points.rs:158-181`) has already set `new_credits_observed = final_epoch_credits` for D's stake account.
6. `calculate_stake_rewards` in `runtime/src/inflation_rewards/mod.rs:287-294` sees `ag_points == 0`, calls `skip_reward(SkippedReason::ZeroPoints)`, which (since `advance_credits_for_skipped_reward` is true — non-Tower epoch, stake is effective, and `new_credits_observed != stake.credits_observed`) returns `Some(skipped_reward())`, committing `new_credits_observed` while paying `staker_rewards = 0`.
7. This repeats identically every epoch as long as D's stake share of V's total stake stays below the rounding threshold, so D receives zero inflation rewards indefinitely despite legitimately earning a nonzero (fractional) share each epoch.
