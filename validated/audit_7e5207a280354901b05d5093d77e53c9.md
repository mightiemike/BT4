### Title
Missing declared-class validation in Starknet OS `execute_replace_class` causes divergence from Blockifier's `ReplaceClass` syscall semantics - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
Analogous to CVE-2022-48425, where the Linux NTFS3 log replayer processed inode records without validating MFT flags before acting on them (leading to type-confused `kfree`), the Starknet OS's Cairo implementation of the `ReplaceClass` syscall applies a class-hash state update **without first validating that the class hash is actually declared**, unlike the corresponding Rust Blockifier implementation, which performs this check.

### Finding Description
In the Rust blockifier, `replace_class` explicitly validates that the target class hash is declared (and is a Cairo 1/V1 class) before mutating state: [1](#0-0) 

The deprecated-syscall variant likewise enforces this by reading the compiled class before setting it: [2](#0-1) 

However, the Starknet OS's native Cairo re-implementation of the same syscall (`execute_replace_class`), used during Starknet OS (SNOS) re-execution/proving, contains an explicit `TODO` acknowledging the missing check, and proceeds to update `contract_state_changes` and the revert log with the unvalidated `class_hash` unconditionally: [3](#0-2) 

The same missing check exists in the deprecated-syscall Cairo path (`deprecated_execute_syscalls.cairo`): [4](#0-3) 

Both are wired into the OS's syscall dispatch as the canonical Cairo semantics for `ReplaceClass`: [5](#0-4) 

Since SNOS is meant to re-execute the same transactions as the Blockifier and produce a matching state diff/output for proof generation, this creates a semantic divergence: a Blockifier execution of a transaction calling `replace_class` with an undeclared class hash would **revert** (raising `UndeclaredClassHash`/`is not declared`, as verified by tests), whereas the OS's own Cairo logic would **accept it unconditionally** and commit a `StateEntry` with an undeclared/unvalidated class hash into `contract_state_changes`, propagating into the OS's computed state diff and, ultimately, the state commitment.

### Impact Explanation
If the OS Cairo logic diverges from the Blockifier's actual enforcement, honest-node re-execution consistency is broken for any transaction whose class hash is not correctly validated in the OS path. This can result in the OS accepting a state transition (a contract's class hash pointing to an undeclared/invalid class) that the sequencer's actual Blockifier execution would have rejected, producing either: (a) an OS-computed state diff/commitment that does not match the sequencer's true execution result (honest-node divergence / wrong committed root), or (b) a contract left pointing at a class hash that was never actually declared, which is a form of unauthorized/incorrect account/contract state — a Blockifier-level invariant ("cannot use an undeclared class") that the network relies on for correctness of subsequent calls, hashing, and fee/resource accounting against that contract.

### Likelihood Explanation
The `ReplaceClass` syscall is directly reachable by any unprivileged contract during normal `__execute__`/entry-point execution — no special privilege is required, only a deployed contract invoking `replace_class_syscall` with an arbitrary (including undeclared) class hash. The bug is only present in the OS's Cairo re-execution path (used in proving / SNOS), not in the Blockifier's primary execution path that actually decides transaction success/failure for the sequencer's real state, so the practical trigger condition depends on whether/how the OS path independently re-validates and whether its output is authoritative for committed state (this repo's SNOS role in that pipeline). The explicit `TODO(Yoni, 1/1/2026)` comment confirms this is a known, currently-unaddressed gap rather than a designed behavior.

### Recommendation
Add an explicit declared-class check in the OS's Cairo `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) mirroring the Blockifier's Rust check — i.e., look up the class definition for `class_hash` via the appropriate state/class hint and assert it exists (and, per the V1-only Cairo1 restriction enforced by `syscall_base.rs`, that it is not a V0/Cairo0 class) before permitting the `StateEntry.class_hash` mutation. This keeps OS semantics in lockstep with Blockifier's `SyscallExecutionError`/`StateError::UndeclaredClassHash`/`ForbiddenClassReplacement` enforcement.

### Proof of Concept
1. Deploy a contract (Cairo1) that exposes a function invoking `replace_class_syscall(class_hash)` where `class_hash` is a value with no corresponding declared class in state (e.g. `felt!(1234)`).
2. In the Blockifier execution path, this transaction reverts with an `is not declared` error, as confirmed by the existing test: [6](#0-5) 
3. In the OS's Cairo re-execution of the identical transaction (`execute_replace_class` in `syscall_impls.cairo`), no equivalent check exists — the `TODO` comment on line 902 and the code that follows unconditionally writes the new (unvalidated) `class_hash` into `contract_state_changes`, producing a state diff entry that the real Blockifier execution never would have produced.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
