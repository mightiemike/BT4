## Finding: Gas fee truncation to zero in `CalculateGasCost` — `x/uexecutor/keeper/fees.go`

### Title
Universal payload execution gas fees can be silently rounded to zero via base-fee truncation - (File: `x/uexecutor/keeper/fees.go`)

### Summary
The external report's bug class — fee computation rounding down to zero via integer division — has a direct analog in the gas-fee accounting used for UEA-originated (`DerivedEVMCall`) universal payload execution. `CalculateGasCost` truncates the dynamic EIP-1559-style `baseFee` to a whole `upc` unit *before* multiplying by `gasUsed`, instead of performing the multiplication at full precision and rounding only the final result.

### Finding Description
`CalculateGasCost` receives `baseFee` as an `sdkmath.LegacyDec` (18-decimal fixed point) straight from the feemarket module: [1](#0-0) 

It immediately does:
```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
```
This is integer division that truncates any fractional part of `baseFee` (i.e., any base fee below 1 whole `upc`) down to `0`, based on the code's own (incorrect) assumption that "the base fee is always a whole number of upc -- no fractional upc exists." [2](#0-1)  That assumption does not hold for a dynamic EIP-1559-style base fee, which decays automatically toward zero whenever blocks run below their gas target — a routine, unprivileged, non-adversarial network condition.

Once `effectiveGasPrice` becomes `0`, `gasCost := effectiveGasPrice * gasUsed` is `0` regardless of how much gas was actually consumed: [3](#0-2) 

The caller, `DeductGasFeesFromReceipt`, then short-circuits and skips fee deduction entirely whenever `gasCost.Sign() <= 0`: [4](#0-3) 

So the EVM execution that consumed `receipt.GasUsed` gas (up to the payload's `GasLimit`) is never charged, and `DeductAndBurnFees` — the only place that actually moves/burns `upc` from the recipient — is never invoked. [5](#0-4) 

### Impact Explanation
This corrupts the protocol's gas-fee accounting invariant: fee should scale with `gasUsed × effective price`, but the truncation collapses it to `0` whenever the feemarket's base fee is below 1 whole `upc`. Any unprivileged user submitting inbound `FUNDS_AND_PAYLOAD`/`PAYLOAD` transactions that trigger module-originated `DerivedEVMCall` execution of a `UniversalPayload` gets that EVM computation for free, at the expense of the validators who must still execute it. This matches the "gas fee accounting" corruption item in the allowed-impact list.

### Likelihood Explanation
Base fee decay below 1 `upc` is not an attacker-controlled edge case requiring 49-token-style precision targeting — it is the expected steady-state outcome of an EIP-1559 fee market during any period of below-target block utilization, which is common on a young or low-traffic chain. No minimum-fee floor guards the truncation before it happens.

### Recommendation
Compute the gas cost using the full-precision `LegacyDec` (e.g., `baseFee.MulInt64(int64(gasUsed))`) and only round (preferably `Ceil()`, rounding up) at the very end when converting to an integer `upc` amount, rather than truncating `baseFee` to a whole unit before multiplying. Alternatively, enforce a minimum non-zero gas-fee floor so that any non-zero `gasUsed` always results in a strictly positive fee.

### Proof of Concept
1. Let network conditions (ordinary low block utilization) drive the feemarket's dynamic base fee to, e.g., `0.3` `upc` (Dec-encoded as `300000000000000000`).
2. An attacker submits any inbound `FUNDS_AND_PAYLOAD` causing `CallExecuteUniversalTx` to run a `UniversalPayload` through the user's UEA that consumes 500,000 gas.
3. `CalculateGasCost`: `baseFeeBig.Div(300000000000000000, 1e18) == 0` → `effectiveGasPrice = 0` → `gasCost = 0 * 500000 = 0`.
4. `DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns `nil` without ever calling `DeductAndBurnFees`.
5. The attacker repeats this for arbitrarily gas-heavy payloads for as long as base fee stays below 1 `upc`, consuming validator compute resources for free.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
