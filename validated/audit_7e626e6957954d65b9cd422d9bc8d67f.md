### Title
Unbounded memory allocation in `starknet_estimateFee`/`simulateTransactions` RPC when decompressing a user-supplied Declare V1 program - ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
`starknet_simulateTransactions`, `starknet_estimateFee` (and related trace/simulation RPC methods) accept a `BroadcastedDeclareTransaction::V1`, whose `DeprecatedContractClass.program` field is a base64+gzip‑compressed string supplied entirely by the caller. Converting it into an executable transaction calls `user_deprecated_contract_class_to_sn_api`, which calls `decompress_program`. That function gzip‑decompresses the attacker‑controlled bytes into an unbounded `Vec<u8>` with no cap on the decompressed size, unlike every other decompression path in the codebase.

### Finding Description
`decompress_program` reads the base64 payload, wraps it in a `flate2::bufread::GzDecoder`, and calls `decoder.read_to_end(&mut decompressed)` with no size limit: [1](#0-0) 

This is reached from `TryFrom<BroadcastedDeclareTransaction> for ExecutableTransactionInput`, which for `BroadcastedDeclareV1Transaction` calls `user_deprecated_contract_class_to_sn_api(contract_class)` — a fully user-supplied `DeprecatedContractClass` (no state/storage lookup involved): [2](#0-1) [3](#0-2) 

This `TryFrom` is invoked by `simulate_transactions` (and other simulate/estimate-fee RPC handlers) directly on caller-supplied `Vec<BroadcastedTransaction>`: [4](#0-3) 

The request body itself is capped at 10 MB (`SERVER_MAX_BODY_SIZE`), but that limits the *compressed* payload, not the *decompressed* output — gzip permits extreme compression ratios (a `SERVER_MAX_BODY_SIZE`-sized adversarial gzip stream can decompress to gigabytes). The `// TODO(dan): add time and size limits.` comment on `decompress_program` confirms the limit is intentionally missing.

This is the same bug class as CVE-2026-85201: an untrusted length/size declaration controlling an allocation with no bound, leading to unbounded memory growth and process abort/OOM. Every other decompression path in this codebase enforces a limit — e.g. `decode_and_decompress_with_size_limit` used for Sierra program compression: [5](#0-4) 
and the p2p `ProtoCodec` length-delimited decoder: [6](#0-5) 
`decompress_program` is the one outlier lacking such a bound.

### Impact Explanation
A single unauthenticated JSON-RPC caller can submit a `simulateTransactions`/`estimateFee` request containing a `BroadcastedDeclareTransaction::V1` with a small, highly-compressed `program` field. Decompression allocates memory proportional to the *decompressed* size (unbounded, limited only by available system memory), which can exhaust the RPC/full-node process's memory and crash it (OOM kill), denying RPC/execution service. This matches the CVE's "loss of orchestration/service" impact class, translated here to denial of the node's RPC execution service. This is a resource-based DoS on the RPC node process, not corruption of consensus-critical state.

### Likelihood Explanation
High: the entry point is a standard, publicly exposed JSON-RPC method (`starknet_simulateTransactions`/`starknet_estimateFee`) that any RPC client can call without needing to submit an actual on-chain transaction, get it included, or pass any prior validation. Constructing a gzip bomb is trivial and no authentication or special privilege is required.

### Recommendation
Apply a size-limited decompression to `decompress_program`, mirroring `decompress_with_size_limit` in `starknet_api::compression_utils` (e.g. use `.take(max_size + 1)` on the reader and reject if the result exceeds the limit), using a bound consistent with the maximum program size otherwise enforced for contracts (e.g. `max_contract_bytecode_size`/`DEFAULT_MAX_SIERRA_PROGRAM_SIZE`-equivalent for deprecated programs).

### Proof of Concept
1. Craft a gzip stream that decompresses to several GB but is small enough (e.g. a few hundred KB) to fit under `SERVER_MAX_BODY_SIZE` (10 MB) — e.g. a highly repetitive byte pattern compresses at ratios well over 1000:1 with gzip.
2. Base64-encode it and place it as `contract_class.program` in a `BroadcastedDeclareTransaction::V1` object.
3. Send this as the `transactions` parameter to `starknet_V0_8_simulateTransactions` (or `starknet_estimateFee`) against a target RPC node.
4. `user_deprecated_contract_class_to_sn_api` → `decompress_program` decompresses the payload fully into memory before any size check, causing large allocation and potential OOM/crash of the RPC node process.

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
