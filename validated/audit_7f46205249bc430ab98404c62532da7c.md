### Title
Fee-on-transfer / deflationary source-chain tokens cause unbacked PRC20 minting via unchecked event `amount` in inbound observation - ([File: universalClient/chains/evm/event_parser.go](universalClient/chains/evm/event_parser.go), [File: x/uexecutor/keeper/handler.go](x/uexecutor/keeper/handler.go))

### Summary
Push Chain's inbound bridging pipeline treats the `amount` field emitted in a source-chain gateway's `sendFunds`/`addFunds` event log as ground truth for how many tokens the vault actually custodies, and then mints that exact amount of PRC20 1:1 on Push Chain. Nowhere in the observation, voting, or execution path is this event-emitted amount reconciled against the vault contract's actual token balance delta. If a registered `TokenConfig` (`x/uregistry`) points at a fee-on-transfer, deflationary, or rebasing ERC20, an ordinary unprivileged user depositing that token causes the vault to receive less than the logged `amount`, while Push Chain still mints the full logged amount as PRC20, permanently breaking the 1:1 backing invariant between locked collateral and minted synthetic supply.

### Finding Description
The EVM event listener/parser reads the gateway `sendFunds` event and extracts the bridged `amount` directly from event log data, with no cross-check against the vault's token balance: [1](#0-0) 

This parsed `Amount` is placed unmodified into the `UniversalTx`/`Inbound` struct that Universal Validators vote on: [2](#0-1) 

Once 2/3+ validators vote the same observation (including the same `Amount`), `VoteInbound` finalizes the ballot and the executor mints PRC20 using that exact value, without ever querying the vault contract's actual token balance/delta: [3](#0-2) [4](#0-3) 

The `TokenConfig` (`x/uregistry`) that gates which ERC20s can be bridged has no field or validation excluding fee-on-transfer/deflationary/rebasing tokens — `ValidateBasic` only checks chain, address, decimals, and `NativeRepresentation` format: [5](#0-4) 

Because honest Universal Validators are simply relaying what the gateway contract emitted in its event (they are not being dishonest — the flaw is that the emitted `amount` is never validated against actual vault custody), an ordinary unprivileged user who deposits a fee-on-transfer token registered as a supported asset can cause PRC20 to be minted 1:1 against the *gross* (pre-fee) amount while the vault only receives the *net* (post-fee) amount. This directly corrupts PRC20 accounting — an "unauthorized mint" relative to actual backing, and a "corruption of PRC20 ... accounting" as defined in the allowed-impact gate — reachable purely through ordinary user deposit and default transaction submission paths, with all validators and nodes behaving honestly.

### Impact Explanation
Each deposit of a fee-on-transfer, deflationary, or rebasing token mints more PRC20 than the vault actually custodies. Over repeated deposits, PRC20 total supply diverges further from the vault's real balance, so redemptions/outbounds against that PRC20 eventually cannot be honored for all holders — a system-wide insolvency of that token's backing, consistent with the "corruption of PRC20 ... accounting" and "unauthorized mint" impact categories in scope. This is not limited to a single user; it degrades the shared backing pool that all holders of that PRC20 rely on.

### Likelihood Explanation
Likelihood depends on whether governance/admin registers a fee-on-transfer, deflationary, or rebasing token via `TokenConfig`. `ValidateBasic` for `TokenConfig` performs no check to exclude such tokens, so nothing in the scoped code prevents this from happening, and once such a token is registered, exploitation requires only an ordinary, unprivileged deposit — no relayer, validator, or admin misbehavior needed at trigger time.

### Recommendation
- Have the EVM/SVM event listener/tx builder query the vault's token balance immediately before and after the observed deposit transaction (or use `Transfer` event `value` reconciled with vault balance delta) and use the actual received delta as `Inbound.Amount`, rather than trusting the gateway-emitted `amount` word verbatim.
- Alternatively/additionally, add an explicit fee-on-transfer/rebasing exclusion check to `TokenConfig.ValidateBasic` (or an off-chain vetting step before `AddTokenConfig`) and document it as a requirement for token onboarding.
- Consider adding a periodic reconciliation check between total PRC20 supply for a given token and the vault's actual custodied balance on the source chain, alerting/halting inbound processing on mismatch.

### Proof of Concept
1. Governance registers a `TokenConfig` for a hypothetical fee-on-transfer ERC20 (e.g. a USDT-style token with a fee switch turned on) via `AddTokenConfig`, backed by `NativeRepresentation.ContractAddress` pointing to a PRC20.
2. An unprivileged user calls the source-chain gateway's `sendFunds`/`addFunds` with `amount = 1,000,000`. The token contract charges a 0.5% fee, so the vault actually receives `995,000` tokens, while the gateway's `sendFunds` event still logs `amount = 1,000,000` (the caller-specified `amount`, not the balance delta).
3. `parseUniversalTxEvent` in `universalClient/chains/evm/event_parser.go` extracts `Amount = "1000000"` verbatim from event log Word 1.
4. Universal Validators, observing the same event, vote `MsgVoteInbound` with `Amount = "1000000"`; quorum is reached honestly.
5. `ExecuteInboundFunds` → `depositPRC20` → `CallPRC20Deposit` mints `1,000,000` PRC20 to the recipient, while the vault only holds `995,000` of the underlying token — a `5,000`-token shortfall in backing that persists permanently and compounds with every subsequent deposit of that token.

// processInboundEvent processes an inbound event by voting on it and confirming it
func (ep *EventProcessor) processInboundEvent(ctx context.Context, event *store.Event) error {
	ep.logger.Debug().
		Str("event_id", event.EventID).
		Msg("processing inbound event")

	// Extract inbound data from event
	inbound, err := ep.constructInbound(event)
	if err != nil {
		return fmt.Errorf("failed to construct inbound: %w", err)
	}

	// Execute vote on blockchain
	voteTxHash, err := ep.signer.VoteInbound(ctx, inbound)
	if err != nil {
		ep.logger.Error().
			Str("event_id", event.EventID).
			Err(err).
			Msg("failed to vote on event - keeping status for retry")
		return err
	}

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

// Calls Handler Contract to deposit prc20 tokens
func (k Keeper) CallPRC20Deposit(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // sender: module account
		handlerAddr,        // destination
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20Token",
		prc20Address,
		amount,
		to,
	)
}

// ValidateBasic performs sanity checks on the TokenConfig
func (p TokenConfig) ValidateBasic() error {
	if strings.TrimSpace(p.Chain) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "chain cannot be empty")
	}

	if strings.TrimSpace(p.Address) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "token contract address cannot be empty")
	}

	// Enforce a parseable address for the chain's namespace (e.g. 20-byte hex
	// for eip155, base58 for solana) so every registration lands on the
	// canonical storage key.
	if _, err := utils.CanonicalizeAddressByNamespace(p.Chain, p.Address); err != nil {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid token address for chain %s: %s", p.Chain, err)
	}

	if strings.TrimSpace(p.Name) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "token name cannot be empty")
	}

	if strings.TrimSpace(p.Symbol) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "token symbol cannot be empty")
	}

	if p.Decimals == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "decimals must be greater than zero")
	}

	// Validate token_type is within known enum range
	if _, ok := TokenType_name[int32(p.TokenType)]; !ok {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid token_type: %v", p.TokenType)
	}

	if strings.TrimSpace(p.LiquidityCap) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "liquidity_cap cannot be empty")
	}

	if p.NativeRepresentation == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "native_representation is required")
	}
	if err := p.NativeRepresentation.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid native representation")
	}

	return nil
}
