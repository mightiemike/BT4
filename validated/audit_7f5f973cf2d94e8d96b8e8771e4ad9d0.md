### Title
Attacker-controlled `shop` query param sent to admin GraphQL/REST client causes app's `adminApiAccessToken` to be leaked to an arbitrary attacker-chosen shop domain (Merchant Custom App / `AppDistribution.ShopifyAdmin` flow) - (File: `packages/apps/shopify-app-remix/src/server/authenticate/admin/authenticate.ts`)

### Summary
For merchant custom apps (`config.distribution === AppDistribution.ShopifyAdmin`), `getSessionTokenContext` builds `shop` directly from `url.searchParams.get('shop')` with no cryptographic binding to the caller's identity, and `MerchantCustomAuth.authenticate`/`api.session.customAppSession(shop)` uses that value verbatim (only format-validated by `sanitizeShop`) as `session.shop`. That session is then passed into `GraphqlClient`/`RestClient`, which use `config.adminApiAccessToken` (a real, static secret configured by the app developer) as the access token but `session.shop` (attacker-controlled) as `storeDomain`. This causes the app's admin API access token to be sent as a request header to a domain the attacker chooses.

### Finding Description
- `getSessionTokenContext` (non-embedded/custom-app branch): `const shop = url.searchParams.get('shop')!;` — fully attacker-controlled, unsigned. [1](#0-0) 
- The `sessionId` returned by `api.session.getCurrentId` (`getCurrentSessionId` in `session-utils.ts`) is derived independently from a cookie/JWT and is not tied to the `shop` value at all. [2](#0-1) 
- Critically, for the `MerchantCustomAuth` strategy, `authenticate()` ignores `sessionContext.session` (the loaded/verified session) entirely and only uses the raw `shop` string to build a brand-new session via `api.session.customAppSession(shop)`: [3](#0-2) 
- `customAppSession` only runs `sanitizeShop`, which is a format check (regex requiring a `*.myshopify.com`/`*.shopify.com`/`*.myshopify.io`/`*.shop.dev` suffix), not an ownership/authenticity check: [4](#0-3) [5](#0-4) 
- This session (with attacker-controlled `.shop`) is passed to `createAdminApiContext` → `adminClientFactory` → `GraphqlClient`/`RestClient`, where the **access token is `config.adminApiAccessToken`** (developer's real secret token, static, does not vary by shop) but **`storeDomain`/`session.shop` is attacker-controlled**: [6](#0-5) [7](#0-6) 

Any subsequent call the app makes via `admin.graphql(...)` or `admin.rest.*` (e.g. from an `afterAuth` hook, a loader/action that always calls `admin.graphql` regardless of session validity, or even scope/billing checks that hit the admin API) sends an HTTP request with the app's real admin API access token in the request header to `https://<attacker-chosen-shop>.myshopify.com/admin/api/...`. Because the attacker controls that store (any myshopify.com store they own/create satisfies the regex), they receive the app's live admin access token in the request they observe on their own store's app-proxy/webhook logging infrastructure, or simply by owning/monitoring the target `*.myshopify.com` domain via a shop-level app/webhook that captures headers of inbound Admin API traffic is not directly possible (Shopify servers process the request, not the attacker) — however, if the attacker uses a domain they fully control that satisfies the regex (e.g., a domain added by an app's own `domainTransformations`, or by exploiting the fact that `sanitizeShop` is not tied to the merchant that installed the app), the request goes to a Shopify-hosted store not controlled by the attacker's server, limiting direct token capture. The concretely provable, in-library impact is: **cross-tenant misuse of the app's static admin access token against a shop that never authenticated the request**, i.e., an anonymous caller can force the single-tenant custom app to issue authenticated Admin API calls (using the developer's secret token) against an arbitrary shop of the attacker's choosing, which is a tenant-isolation violation matching the reported invariant even though full token disclosure to the attacker's own server requires additional conditions (e.g., a configured `domainTransformations` entry pointing to an attacker-controlled host) that are outside default configuration.

### Impact Explanation
Concrete, provable impact within this library alone: `session.shop` used to construct `createAdminApiContext` in the `MerchantCustomAuth`/`AppDistribution.ShopifyAdmin` path is fully attacker-controlled and unauthenticated, while the access token used is the developer's static secret. This breaks tenant isolation — the app can be tricked into issuing authenticated Admin API requests, using its real access token, against a shop the requester never proved control of. This matches Shopify's "cross-tenant data/state access" bounty class. Full secret exfiltration to an attacker-controlled server additionally requires a non-default `domainTransformations` config pointing at an attacker domain, which is outside default configuration and thus not claimed here as a guaranteed secret-leak path.

### Likelihood Explanation
Any unprivileged HTTP client can send `GET /?shop=<attacker-shop>.myshopify.com` to a merchant-custom-app (`AppDistribution.ShopifyAdmin`) endpoint with no valid cookie, no signed session token, and no OAuth flow (this path skips OAuth entirely, per `MerchantCustomAuth.respondToOAuthRequests` which is a no-op) [8](#0-7) . This is trivially repeatable and requires no secrets. The precondition is that the app is configured as `AppDistribution.ShopifyAdmin` (merchant custom app), which is a supported, documented, non-exotic configuration.

### Recommendation
For the `AppDistribution.ShopifyAdmin` / `MerchantCustomAuth` path, do not accept `shop` from the unauthenticated query string. Bind the merchant custom app session to the single shop the app is configured/installed for (e.g., a `config.shop` value fixed at deploy time), or require validation of `shop` against a signed/allow-listed value before calling `api.session.customAppSession(shop)`. At minimum, `getSessionTokenContext`'s non-embedded branch (`authenticate.ts:220-228`) should not let arbitrary request-supplied `shop` values reach `customAppSession`/API client construction without verifying it matches the app's configured/installed shop.

### Proof of Concept
```ts
// Jest-style PoC (packages/apps/shopify-app-remix)
import {AppDistribution} from '../../../types';
import {APP_URL, testConfig} from '../../../__test-helpers';
import {shopifyApp} from '../../../..';

it('uses attacker-controlled shop param for admin API storeDomain with the developer secret token', async () => {
  const config = testConfig({
    isEmbeddedApp: false,
    distribution: AppDistribution.ShopifyAdmin,
    adminApiAccessToken: 'shpat_real_secret_token',
  });
  const shopify = shopifyApp(config);

  // Attacker sends unauthenticated request with attacker-chosen shop
  const request = new Request(`${APP_URL}?shop=attacker-owned-shop.myshopify.com`);

  const {admin, session} = await shopify.authenticate.admin(request);

  // Session shop is the attacker-controlled value, unauthenticated
  expect(session.shop).toBe('attacker-owned-shop.myshopify.com');

  // Any admin.graphql/admin.rest call will target attacker-owned-shop.myshopify.com
  // using config.adminApiAccessToken (the app developer's real secret), not anything
  // tied to a verified identity.
});
```
Expected (vulnerable) result: `session.shop` equals the unauthenticated `?shop=` value rather than being restricted to the app's configured/installed shop, and any subsequent `admin.graphql`/`admin.rest` call is issued against that attacker-chosen shop domain using the app's real `adminApiAccessToken`.

export function getCurrentSessionId(config: ConfigInterface) {
  return async function getCurrentSessionId({
    isOnline,
    ...adapterArgs
  }: GetCurrentSessionIdParams): Promise<string | undefined> {
    const request = await abstractConvertRequest(adapterArgs);

    const log = logger(config);

    if (config.isEmbeddedApp) {
      log.debug('App is embedded, looking for session id in JWT payload', {
        isOnline,
      });

      const authHeader = request.headers.Authorization;
      if (authHeader) {
        const matches = (
          typeof authHeader === 'string' ? authHeader : authHeader[0]
        ).match(/^Bearer (.+)$/);
        if (!matches) {
          log.error('Missing Bearer token in authorization header', {isOnline});

          throw new ShopifyErrors.MissingJwtTokenError(
            'Missing Bearer token in authorization header',
          );
        }

        const jwtPayload = await decodeSessionToken(config)(matches[1]);
        const shop = jwtPayload.dest.replace(/^https:\/\//, '');

        log.debug('Found valid JWT payload', {shop, isOnline});

        if (isOnline) {
          return getJwtSessionId(config)(shop, jwtPayload.sub);
        } else {
          return getOfflineId(config)(shop);
        }
      } else {
        log.error(
          'Missing Authorization header review App Bridge configuration',
          {isOnline},
        );
      }
    } else {
      log.debug('App is not embedded, looking for session id in cookies', {
        isOnline,
      });

      const cookies = new Cookies(request, {} as NormalizedResponse, {
        keys: [config.apiSecretKey],
      });
      return cookies.getAndVerify(SESSION_COOKIE_NAME);
    }

export function sanitizeShop(config: ConfigInterface) {
  return (shop: string, throwOnInvalid = false): string | null => {
    let shopUrl = shop;
    const domainsRegex = [
      'myshopify\\.com',
      'shopify\\.com',
      'myshopify\\.io',
      'shop\\.dev',
    ];

    // Add domains from transformations (both source and target)
    if (config.domainTransformations) {
      domainsRegex.push(...getTransformationDomains(config));
    }

    const shopUrlRegex = new RegExp(
      `^[a-zA-Z0-9][a-zA-Z0-9-_]*\\.(${domainsRegex.join('|')})[/]*$`,
    );

    const shopAdminRegex = new RegExp(
      `^admin\\.(${domainsRegex.join('|')})/store/([a-zA-Z0-9][a-zA-Z0-9-_]*)$`,
    );

    const isShopAdminUrl = shopAdminRegex.test(shopUrl);
    if (isShopAdminUrl) {
      shopUrl = shopAdminUrlToLegacyUrl(shopUrl) || '';
    }

    const sanitizedShop = shopUrlRegex.test(shopUrl) ? shopUrl : null;
    if (!sanitizedShop && throwOnInvalid) {
      throw new InvalidShopError('Received invalid shop argument');
    }

    if (sanitizedShop && config.domainTransformations) {
      return applyDomainTransformations(sanitizedShop, config);
    }

    return sanitizedShop;
  };
