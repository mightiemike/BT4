## Analysis

`determineEventType` in `universalClient/chains/svm/event_listener.go` classifies a Solana log purely by its literal text and the first 8 decoded bytes, with no binding to which program actually emitted it: [1](#0-0) 

The caller, `processSignatureBatch`, iterates over **all** `tx.Meta.LogMessages` for any transaction returned by `GetSignaturesForAddress(gatewayAddr, ...)`, and feeds every `"Program data: ..."` line into `determineEventType`/`ParseEvent` with no check that the line was emitted from inside the gateway program's own CPI invoke/success bracket: [2](#0-1) 

Solana's `getSignaturesForAddress` RPC returns any transaction where the address appears as *any* account key in the message — it does not require that the account's program was actually invoked. An unprivileged attacker can therefore build a transaction that:
1. References the real gateway program pubkey as an unused account (satisfying the signature-history filter), and
2. Invokes their own attacker-controlled program in the same transaction, which emits a hand-crafted `sol_log_data`/`msg!` line of the form `Program data: <base64>` whose first 8 bytes exactly match a known discriminator (e.g. for `send_funds`) — discriminators are fixed, off-chain configured values (from `uregistrytypes.GatewayMethods`), but they are **public**, not secret, so any attacker can reproduce them: [3](#0-2) 

Because `determineEventType` and the downstream `ParseEvent`/`parseSendFundsEvent`/`decodeUniversalTxEvent` never verify that the "Program data:" log line sits inside the gateway program's own invoke/success bracket, the attacker's forged log is parsed exactly like a genuine gateway event, with attacker-controlled `sender`, `recipient`, `token`, `amount`, `revert_recipient`, `tx_type`, and payload fields: [4](#0-3) [5](#0-4) 

Since the forged transaction is genuinely on-chain, every honest Universal Client independently observing the same slot will deterministically derive the same fabricated `store.Event` (same signature, same log index, same decoded bytes), meaning honest-validator convergence does **not** protect against this — all honest UVs would agree on the forged inbound/outbound event and could reach quorum on it. This falls squarely in the in-scope category of "forged ... inbound ... state accepted through user-reachable flows with honest validators and honest nodes," because the flaw is a missing authentication/binding step in scoped code (`universalClient/chains/svm/event_listener.go`), not a malicious-validator assumption.

I was not able to trace this event further into the `x/` voting/finalization modules in this session (out of tool budget), so I cannot fully confirm what happens after the forged event reaches ballot state — e.g., whether the base layer or subsequent modules perform any additional binding/replay checks before mutating PRC20 balances. That downstream verification is material to whether this results in actual unauthorized minting versus merely a spurious pending/failed ballot that later gets rejected.

### Title
Missing program-origin binding lets unprivileged attacker forge gateway `Program data:` logs to fabricate cross-chain events - (File: universalClient/chains/svm/event_listener.go)

### Summary
`determineEventType`/`processSignatureBatch` classify any `"Program data:"` log line in a transaction that merely *references* the gateway address as a genuine gateway event, without verifying the log was emitted from within the gateway program's own invoke/success bracket.

### Finding Description
`GetSignaturesForAddress` matches transactions where the gateway pubkey appears as any account key, not only transactions that invoke the gateway program. An attacker can add the gateway pubkey as an unused account in a transaction that also invokes an attacker-owned program emitting a spoofed `Program data:` log with a valid, publicly-known 8-byte discriminator. `determineEventType` (lines 398–422) and `ParseEvent`/`parseSendFundsEvent`/`decodeUniversalTxEvent` have no mechanism to confirm which program emitted a given log line, so the forged log is parsed identically to a genuine gateway-emitted event.

### Impact Explanation
If accepted downstream without further on-chain/economic verification, this could let an attacker fabricate inbound (`send_funds`) or outbound-observation events with arbitrary sender/recipient/token/amount fields, potentially causing unauthorized state to be proposed for voting/finalization — since all honest UVs deterministically observe the same on-chain forged log, honest-validator convergence does not prevent this. Full fund-loss confirmation requires tracing the `x/` voting/finalization path, which was not completed in this session.

### Likelihood Explanation
Requires only an unprivileged Solana wallet capable of submitting a standard transaction; the discriminators used are derived from public, non-secret identifiers, and no signature/authorization is required to add an unrelated pubkey to a transaction's account list.

### Recommendation
Track Solana's "Program X invoke [depth]" / "Program X success"/"failed" bracketing while iterating `tx.Meta.LogMessages`, and only accept `"Program data:"` lines that fall within the gateway program's own invoke bracket (matching program ID and depth) rather than scanning the flat log list irrespective of origin.

### Proof of Concept
1. Deploy a minimal attacker Solana program that calls `sol_log_data`/`msg!` to emit `Program data: <base64>` where the first 8 bytes equal a real gateway discriminator (e.g. `send_funds`) and the remaining bytes encode attacker-chosen sender/recipient/amount fields.
2. Submit one transaction whose instruction list includes: (a) a no-op/read-only reference to the gateway program's pubkey as an account key, and (b) an invocation of the attacker program from step 1.
3. Confirm the transaction shows up via `GetSignaturesForAddress(gatewayAddr, ...)` and that `processSignatureBatch`/`determineEventType` classify the attacker's forged log as `send_funds`, producing a `store.Event` with attacker-controlled fields, as validated against `parseSendFundsEvent`/`decodeUniversalTxEvent` output.

```go
// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
```

```go
func parseSendFundsEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	if len(decoded) < 8 {
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing sendFunds event")

	// Create store.Event
	event := &store.Event{
		EventID:           eventID,
		BlockHeight:       slot,
		Type:              store.EventTypeInbound, // Gateway events from external chains are INBOUND
		Status:            store.StatusPending,
		ExpiryBlockHeight: 0, // Will be set based on confirmation type if needed
	}

	// Parse event data from this log
	parseUniversalTxEvent(event, decoded, logIndex, chainID, logger)

	return event
```

```go
// decodeUniversalTxEvent decodes a TxWithFunds event
func decodeUniversalTxEvent(data []byte, logger zerolog.Logger) (*common.UniversalTx, error) {
	if len(data) < 120 {
		logger.Warn().
			Int("data_len", len(data)).
			Msg("data might be too short for complete TxWithFunds event")
	}

	offset := 8
	payload := &common.UniversalTx{}

	// Parse sender (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for sender")
	}
	sender := solana.PublicKey(data[offset : offset+32])
	// Convert sender to hex format
	senderHex, err := base58ToHex(sender.String())
	if err != nil {
		logger.Warn().Err(err).Msg("failed to convert sender to hex, using base58")
		payload.Sender = sender.String()
	} else {
		payload.Sender = senderHex
	}
	offset += 32

	// Parse recipient (20 bytes - byte20 format)
	if len(data) < offset+20 {
		return nil, fmt.Errorf("not enough data for recipient")
	}
	// Convert 20 bytes to hex string (0x + 40 hex chars)
	recipientBytes := data[offset : offset+20]
	payload.Recipient = "0x" + hex.EncodeToString(recipientBytes)
	offset += 20

	// Parse bridge_token (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for bridge_token")
	}
	bridgeToken := solana.PublicKey(data[offset : offset+32])
	payload.Token = bridgeToken.String()
	offset += 32

	// Parse bridge_amount (8 bytes)
	if len(data) < offset+8 {
		return nil, fmt.Errorf("not enough data for bridge_amount")
	}
	bridgeAmount := binary.LittleEndian.Uint64(data[offset : offset+8])
	payload.Amount = fmt.Sprintf("%d", bridgeAmount)
	offset += 8
```
