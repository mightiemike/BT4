## Title
Unbounded recursive segment-hash computation in compiled-class hashing can stack-overflow the sequencer's gateway/sierra-compiler process — ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs])

## Summary
The GHSA-qwrx-45xf-jjf7 pattern (a specially crafted, deeply nested query causing unbounded recursion and a stack overflow in a server process) has a structural analog in the Starknet sequencer's compiled-class hash computation. The function `bytecode_hash_node` recurses once per level of the CASM bytecode's `NestedIntList` segment tree with no depth limit, and it is invoked directly (outside the resource-limited compiler subprocess) whenever a declared class's compiled-class hash is computed.

## Finding Description
`bytecode_hash_node` walks the `NestedIntList`/`HashableNestedIntList` structure that describes how a compiled class's bytecode is segmented, recursing into every child node: [1](#0-0) 

This is called from `hash_inner`/`HashableCompiledClass::hash`, which is the single entry point used to compute a `CompiledClassHash` for a `CasmContractClass`: [2](#0-1) 

Two independent, unprivileged-reachable call sites invoke this recursive hash **outside of any sandboxed/resource-limited subprocess**:

1. **Sierra compiler service** — after the actual `cairo-lang` Sierra→CASM compiler binary runs (in a CPU/memory-limited subprocess), the resulting `CasmContractClass` (including its `bytecode_segment_lengths: NestedIntList`) is hashed in the *parent* process, with no sandboxing or stack-size adjustment: [3](#0-2) 
The subprocess itself is only bounded by CPU time / memory / bytecode-size limits: [4](#0-3) 

2. **Blockifier declare-transaction execution** — during Declare v3 execution (reachable from any transaction sender's declare transaction), `check_compile_class_hash_v2_declaration` re-invokes `casm.hash(&HashVersion::V2)` on the main execution path: [5](#0-4) [6](#0-5) 

The recursion depth is a direct function of the nesting depth of the `NestedIntList` segment tree, which is derived from the compiled contract's function/branch structure. Unlike Cairo-Native contract-call recursion — for which the sequencer explicitly pre-allocates large thread stacks sized to tolerate `MAX_POSSIBLE_SIERRA_GAS`-bounded recursion (see `crates/blockifier/src/blockifier/transaction_executor.rs:310-345` and `crates/blockifier/src/concurrency/worker_pool.rs:26-72`) — there is no analogous stack-size provisioning, gas metering, or explicit depth cap for `bytecode_hash_node`. A contract author can deliberately structure a contract (many small nested functions/branches) to maximize the segment-tree depth within the existing `max_bytecode_size` (80K felts) limit, producing a `NestedIntList` deep enough to exhaust the default thread stack when hashed.

## Impact Explanation
A successful stack overflow in:
- the Sierra-compiler component crashes that service process, denying compilation/declaration service (and, since `max_concurrent_declare_compilations` gates concurrent compilations, repeated crashes degrade or halt declare processing for the whole gateway fleet);
- the blockifier's declare execution path (batcher/sequencer block-building) crashes the executing thread/process during block building, which can halt block production — a network-availability impact (inability to confirm new transactions), which is the qualifying "no confirmation" impact class for this scan.

Because the trigger is a normal, otherwise-valid Declare transaction from any unprivileged account, this is reachable without special privileges.

## Likelihood Explanation
Any account can submit a Declare transaction for a contract whose Sierra source is engineered to compile into a CASM bytecode with a deeply nested segment structure, within existing size/compile-time/memory limits (which bound compiler CPU/memory but not the resulting tree's *depth*). No special access is required beyond the ability to declare a class and pay for the (bounded) compilation.

## Recommendation
- Impose an explicit maximum depth (and/or convert to an iterative/explicit-stack traversal) for `bytecode_hash_node` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs`, rejecting/erroring out on excessively deep `NestedIntList` structures rather than recursing unboundedly.
- Ensure the hash computation in `SierraCompiler::compile` (`crates/apollo_compile_to_casm/src/lib.rs`) runs with the same resource isolation/stack-size safeguards as the compiler subprocess itself, or move the hash computation into the sandboxed subprocess.
- Add a similar depth guard for the equivalent OS/Cairo-side `bytecode_hash_node` in `blake_compiled_class_hash.cairo`/`poseidon_compiled_class_hash.cairo` if it can be driven by an unbounded segment tree during Starknet OS re-execution.

## Proof of Concept
Conceptual PoC: 
1. Author a Cairo1 contract with N deeply nested function/branch scopes (e.g., recursively nested `if`/`match` chains or many small helper functions chained so the Sierra→CASM compiler's segment structure produces a `NestedIntList::Node` chain N levels deep), staying within `max_bytecode_size` (80K felts).
2. Submit a Declare v3 transaction for this class.
3. On the sequencer/gateway, `SierraCompiler::compile` successfully compiles the class (bounded CPU/memory), then calls `executable_class.hash(&HashVersion::V2)`, invoking `bytecode_hash_node` recursively N times on the un-sandboxed process thread, exhausting the stack and crashing the process before a stack-size mitigation (as used for Cairo-Native execution) is applied.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

/// Computes the compiled class hash for a given hashable class using the specified hash algorithm.
fn hash_inner<H, EH, NL>(hashable_class: &impl HashableCompiledClass<EH, NL>) -> CompiledClassHash
where
    H: StarkHash,
    EH: EntryPointHashable,
    NL: HashableNestedIntList,
{
    let external_funcs_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_external_entry_points());
    let l1_handlers_hash = entry_point_hash::<H, EH>(hashable_class.get_hashable_l1_entry_points());
    let constructors_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_constructor_entry_points());

    let bytecode_hash = bytecode_hash::<H, NL>(
        &hashable_class.get_bytecode(),
        &*hashable_class.get_bytecode_segment_lengths(),
    );

    // Compute total hash by hashing each component on top of the previous one.
    CompiledClassHash(H::hash_array(&[
        *COMPILED_CLASS_V1,
        external_funcs_hash,
        l1_handlers_hash,
        constructors_hash,
        bytecode_hash,
    ]))
}

pub fn compile_with_args(
    compiler_binary_path: &Path,
    contract_class: ContractClass,
    additional_args: &[&str],
    resource_limits: ResourceLimits,
) -> Result<Vec<u8>, CompilationUtilError> {
    // Create a temporary file to store the Sierra contract class.
    let serialized_contract_class = serde_json::to_string(&contract_class)?;

    let mut temp_file = NamedTempFile::new()?;
    temp_file.write_all(serialized_contract_class.as_bytes())?;
    let temp_file_path = temp_file.path().to_str().ok_or(CompilationUtilError::UnexpectedError(
        "Failed to get temporary file path".to_owned(),
    ))?;

    // Set the parameters for the compile process.
    let mut command = Command::new(compiler_binary_path.as_os_str());
    command.arg(temp_file_path).args(additional_args);

    // Apply the resource limits to the command.
    resource_limits.apply(&mut command);

    // Run the compile process.
    let compile_output = command.output()?;

    if !compile_output.status.success() {
        let stderr_output = String::from_utf8(compile_output.stderr)
            .unwrap_or_else(|_| "Failed to decode stderr output".to_string());

        let error_message = format_compiler_error(&stderr_output, &compile_output.status);
        return Err(CompilationUtilError::CompilationError(error_message));
    }
    Ok(compile_output.stdout)
}

    /// Verifies that the compiled class hash field in the declare tx,
    /// is compiled_class_hash_v2 of the compiled contract.
    pub fn check_compile_class_hash_v2_declaration(&self) -> Result<(), StarknetApiError> {
        let compiled_class = &self.class_info.contract_class;
        let compiled_class_hash_v2 = match &compiled_class {
            ContractClass::V0(_) => return Ok(()),
            ContractClass::V1((casm, _)) => casm.hash(&HashVersion::V2),
        };
        let compiled_class_hash = self.compiled_class_hash();
        if compiled_class_hash_v2 != compiled_class_hash {
            let err_var = CasmHashMismatch {
                hash: self.class_hash(),
                actual: compiled_class_hash,
                expected: compiled_class_hash_v2,
            };
            return Err(StarknetApiError::DeclareTransactionCasmHashMissMatch(Box::new(err_var)));
        }
        Ok(())
    }
