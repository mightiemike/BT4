### Title
Outbound observation ballots can permanently deadlock a `UniversalTx` when honest validators' observations diverge, with no runtime recovery path — ([File: x/uexecutor/keeper/msg_vote_outbound.go])

### Summary
The `GetOutboundBallotKey` digest ( [1](#0-0) ) folds `GasFeeUsed`, `ErrorMsg`, and `BlockHeight` — none of which are normalized beyond whitespace trimming — into the ballot identity for outbound observation. If validators legitimately observe slightly different values for these fields (which are inherently non-deterministic across independently-polled RPC nodes, e.g. gas-used accounting quirks, differing revert-reason strings, or timing-dependent block height at time of observation), votes fracture across multiple distinct ballots, none of which can reach the 2/3 threshold, mirroring the LongShort `_updateSystemStateInternal`/`marketUpdateIndex` bug where a state-progression counter only advances given an external condition (price change) that may never occur.

### Finding Description
`VoteOutbound` derives the ballot key from the full `OutboundObservation` payload, including free-form/observability-sensitive fields: [2](#0-1) 
Only `TxHash` is canonicalized; `GasFeeUsed` and `ErrorMsg` are merely trimmed, and `BlockHeight` is taken verbatim. `GetOutboundBallotKey` then hashes `Success`, `BlockHeight`, `TxHash`, `GasFeeUsed`, and `ErrorMsg` together: [3](#0-2) 

Every distinct combination of these fields produces its own ballot with its own vote tally (`RecordOutboundVote`), so if UVs (using different RPC providers) observe slightly different `GasFeeUsed`/`ErrorMsg`/`BlockHeight` values for the same real-world destination-chain transaction, the votes for the "same" logical event get split across N different ballot IDs. None of these ballots may ever independently reach `votesNeeded = 2/3+1`, even though the aggregate agreement (that the tx succeeded/failed) is unanimous.

Unlike inbound ballots, `PendingOutbounds` is explicitly documented as never removed on ballot expiry: [4](#0-3) 
And `x/uvalidator` provides `RecomputeBallotQuorum`/`MsgRevertStuckInbound` as escape hatches for inbound ballots only, per `RecomputeBallotQuorum`'s doc-comment and the `RevertStuckInbound` integration test: [5](#0-4) [6](#0-5) 
No equivalent message exists for outbound ballots. The only remediation found in the repository is a one-time **chain-upgrade** handler, `purge-expired-outbounds`, which walks `PendingOutbounds` and deletes any of a hardcoded set of guessed expired ballot variants so validators can re-vote from scratch: [7](#0-6) 
The existence of this dedicated upgrade is direct evidence that this exact "stuck outbound ballot" class of issue previously manifested in production and required a governance-approved binary upgrade to resolve — there is no runtime, per-outbound admin message analogous to `MsgRecomputeBallotQuorum`/`MsgRevertStuckInbound` for outbound ballots.

### Impact Explanation
When an outbound ballot never reaches quorum on any single variant, the associated `OutboundTx` never transitions out of `Status_PENDING` (`VoteOutbound` only advances state on `isFinalized`, see step 4/5 at [8](#0-7) ). Consequently:
- `FinalizeOutbound` (refund-on-failure / success completion) never runs.
- The `UniversalTx` itself remains permanently unresolved — funds already routed for that outbound are neither confirmed delivered nor refunded, exactly the "no safe automatic resolution" state the README calls out.
- Because `PendingOutbounds` is intentionally never cleaned up on ballot expiry, this is a durable, on-chain freeze of protocol/user funds requiring a chain binary upgrade to unstick (as demonstrated by `purge-expired-outbounds`), not a normal governance parameter change.

This matches the in-scope impact categories "permanent freezing... of user or protocol-controlled funds" and "denial of service... reachable without privileged control," since the trigger only requires an ordinary cross-chain transaction whose destination-side execution characteristics (gas usage/error text/observation timing) are inherently variable across independent RPC observers — no malicious validator collusion is required.

### Likelihood Explanation
Moderate. This does not require an attacker to compromise or coordinate with validators; it only requires that the destination-chain transaction's observable characteristics are not perfectly reproducible across independently polled nodes — a realistic condition (e.g. destination-chain reverts with dynamic messages, RPC gas-accounting differences, or timing-sensitive block height capture). The team's own remediation (a purge upgrade) is strong direct evidence this has already occurred operationally, elevating likelihood above speculative.

### Recommendation
- Canonicalize `GasFeeUsed` (e.g., parse/round to a canonical integer representation) and drop or bucket free-form `ErrorMsg` text (or hash only a canonical error code) out of the ballot-key digest so genuine RPC/timing variance does not fragment consensus on the same real-world outcome.
- Add a runtime, admin-gated (or automatic, time-based) escape hatch for outbound ballots analogous to `RecomputeBallotQuorum`/`RevertStuckInbound`, so a stuck outbound ballot can be forcibly recomputed/re-voted without requiring a full chain software upgrade.
- Consider tallying "logical" agreement (e.g., success/failure + canonical amount) independently from side-channel observation metadata (gas used, error text) so quorum on the execution outcome isn't blocked by disagreement on non-consensus-critical metadata.

### Proof of Concept
Conceptual (cannot be executed without live validator infrastructure, so this is a structural trace rather than a runnable exploit):
1. An outbound `OutboundTx` is created for a UTX (e.g., a refund or a cross-chain call), and 4 UVs are eligible voters (quorum threshold = 3).
2. UV1 polls the destination-chain RPC node A: observes `Success=false, ErrorMsg="execution reverted: STF", GasFeeUsed="21042"`.
3. UV2 polls RPC node B (different provider, same tx): observes `Success=false, ErrorMsg="execution reverted", GasFeeUsed="21044"` (differing revert string/gas accounting — a common real-world RPC divergence, not malicious).
4. UV3 and UV4 similarly diverge slightly.
5. Each unique `(Success, BlockHeight, TxHash, GasFeeUsed, ErrorMsg)` tuple hashes to a distinct ballot via `GetOutboundBallotKey` ( [3](#0-2) ), so none of the 4 votes land on the same ballot; no ballot reaches the 3-vote threshold.
6. All ballots eventually expire (`BlockHeightExpiry`), but `PendingOutbounds.Remove` is only called inside the `isFinalized` branch of `VoteOutbound` ( [9](#0-8) ), which never executes — the outbound remains `Status_PENDING` forever, and the `UniversalTx` never finalizes.
7. The only demonstrated remediation path in the codebase is the `purge-expired-outbounds` chain upgrade ( [10](#0-9) ), confirming there is no runtime fix.

// GetOutboundBallotKey: versioned canonical digest over all observation fields
// (all consensus-critical — gas_fee_used drives the refund, error_msg must be
// agreed so no voter can inject unconsensused text). Caller canonicalizes
// tx_hash for the destination chain at vote ingress.
func GetOutboundBallotKey(
	utxId string,
	outboundIndex string,
	observedTx OutboundObservation,
) (string, error) {
	return hashFields(
		OutboundBallotDomain,
		utxId,
		outboundIndex,
		fmt.Sprintf("%t", observedTx.Success),
		fmt.Sprintf("%d", observedTx.BlockHeight),
		observedTx.TxHash,
		observedTx.GasFeeUsed,
		observedTx.ErrorMsg,
	), nil
}

// deleteExpiredOutboundBallots iterates all pending outbounds, finds their expired
// ballots, and deletes them. This allows validators to re-vote on the outbounds,
// creating fresh ballots with the current validator set and large expiry.
func deleteExpiredOutboundBallots(ctx sdk.Context, ak *upgrades.AppKeepers) (deleted, skipped, errCount int) {
	logger := ctx.Logger()

	if ak == nil || ak.UExecutorKeeper == nil || ak.UValidatorKeeper == nil {
		logger.Error("purge-expired-outbounds: keeper is nil, skipping")
		return 0, 0, 1
	}

	ek := ak.UExecutorKeeper
	vk := ak.UValidatorKeeper

	// Phase 1: collect all pending outbound entries (avoid mutating during iteration)
	type pendingItem struct {
		outboundId    string
		universalTxId string
	}
	var items []pendingItem

	err := ek.PendingOutbounds.Walk(ctx, nil, func(key string, entry types.PendingOutboundEntry) (bool, error) {
		items = append(items, pendingItem{
			outboundId:    entry.OutboundId,
			universalTxId: entry.UniversalTxId,
		})
		return false, nil
	})
	if err != nil {
		logger.Error("purge-expired-outbounds: failed to walk pending outbounds", "error", err)
		return 0, 0, 1
	}

	logger.Info("purge-expired-outbounds: found pending outbounds", "count", len(items))

	// Phase 2: for each pending outbound, find and delete expired ballots
	for _, item := range items {
		if item.outboundId == "" || item.universalTxId == "" {
			logger.Error("purge-expired-outbounds: skipping entry with empty ID",
				"outbound_id", item.outboundId,
				"utx_id", item.universalTxId,
			)
			errCount++
			continue
		}

		ballotKey, found := findExpiredBallot(ctx, vk, item.universalTxId, item.outboundId)
		if !found {
			logger.Debug("purge-expired-outbounds: no expired ballot found, skipping",
				"outbound_id", item.outboundId,
			)
			skipped++
			continue
		}

		if err := vk.DeleteBallot(ctx, ballotKey); err != nil {
			logger.Error("purge-expired-outbounds: failed to delete ballot",
				"ballot_key", ballotKey,
				"outbound_id", item.outboundId,
				"error", err,
			)
			errCount++
			continue
		}

		deleted++
		logger.Info("purge-expired-outbounds: deleted expired ballot",
			"ballot_key", ballotKey,
			"outbound_id", item.outboundId,
			"utx_id", item.universalTxId,
		)
	}

	return deleted, skipped, errCount
}

// findExpiredBallot tries common observation variants to locate the expired ballot
// for a given outbound. Returns the ballot key and true if found, or ("", false).
func findExpiredBallot(ctx sdk.Context, vk *uvalidatorkeeper.Keeper, utxId, outboundId string) (string, bool) {
	observations := []types.OutboundObservation{
		{Success: false, ErrorMsg: "event expired before TSS could start", GasFeeUsed: "0"},
		{Success: false, ErrorMsg: "event expired before TSS could start"},
		{Success: false},
		{Success: true},
		{Success: false, GasFeeUsed: "0"},
	}

	for _, obs := range observations {
		ballotKey, err := types.GetOutboundBallotKey(utxId, outboundId, obs)
		if err != nil {
			continue
		}

		ballot, err := vk.Ballots.Get(ctx, ballotKey)
		if err != nil {
			continue
		}

		if ballot.Status == uvalidatortypes.BallotStatus_BALLOT_STATUS_EXPIRED {
			return ballotKey, true
		}
	}

	return "", false
}
