### Title
Starknet OS `execute_replace_class` Syscall Handler Skips Declared-Class Validation, Diverging From Blockifier and Corrupting the Committed State Root - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall accepts any `class_hash` supplied by a contract and writes it directly into `contract_state_changes` without ever checking that the class hash corresponds to a declared contract class. The Rust blockifier — which executes the same transaction during sequencing — explicitly performs this check and rejects undeclared class hashes. This mirrors the reported bug class ("unvalidated address used to set state/permissions"): here the unvalidated value is a `class_hash` accepted by the OS and committed into the post-block state, rather than a renderer address accepted by a token manager.

### Finding Description
In the Cairo1 syscall handler, `execute_replace_class` reads the `class_hash` from the syscall request and immediately builds a new `StateEntry` with it, updating `contract_state_changes`, with only a `TODO` acknowledging the missing check: [1](#0-0) 

The same omission exists in the legacy Cairo0 handler `execute_replace_class` in `deprecated_execute_syscalls.cairo`, which likewise sets the new class hash into state without any declared-class check: [2](#0-1) 

By contrast, the Rust blockifier's `replace_class` syscall handler, which performs the actual state-transition during block building/execution, explicitly validates the class is declared before mutating state: [3](#0-2) 

This is confirmed by blockifier's own tests, which assert that replacing with an undeclared class hash fails with an `"is not declared"` error: [4](#0-3) [5](#0-4) 

Because the Starknet OS re-execution path (used for proving/verifying blocks, e.g. in `starknet_os_flow_tests`) is expected to compute an identical state diff and root to blockifier's, the missing validation in the Cairo `execute_replace_class` means the OS will happily accept an undeclared (or malicious/arbitrary) `class_hash` that blockifier would reject.

### Impact Explanation
This constitutes a correctness divergence between the OS and the sequencer's blockifier: for the same transaction, blockifier rejects an undeclared class hash (transaction reverts), while the OS unconditionally applies the class hash update to `contract_state_changes`. Since `contract_state_changes` feeds directly into the state diff used to build the new state commitment (Patricia tree updates) and, ultimately, the block hash, this can produce a wrong committed state root / honest-node divergence between the sequencer's execution result and the OS's (proof) re-execution result — matching the "wrong committed root" and "honest-node divergence" criteria. It can also let a contract set its own class hash to an arbitrary (non-existent) class hash inside the OS's view of state, breaking subsequent state reads/proofs.

### Likelihood Explanation
Any deployed contract can invoke the `replace_class` syscall directly (Cairo0 `replace_class` builtin or Cairo1 `replace_class_syscall`) with an attacker-chosen class hash; no special privileges are required — it is reachable from any transaction execution path that reaches this contract's own class-replacement logic, i.e., an unprivileged transaction sender's contract can trigger the divergence.

### Recommendation
Add the missing "class is declared" check in both `execute_replace_class` implementations (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) before writing the new `StateEntry`, mirroring the blockifier's `get_compiled_class` check, so that the OS's accepted state transitions are always consistent with blockifier's.

### Proof of Concept
1. A contract not previously declaring any class calls `replace_class_syscall(undeclared_class_hash)` (Cairo1) or `replace_class(class_hash=undeclared_class_hash)` (Cairo0).
2. In blockifier execution (sequencer), `hint_processor.rs::replace_class` calls `state.get_compiled_class(request.class_hash)` which fails, and the transaction reverts (as shown in the existing test `undeclared_class_hash`/`deprecated_syscalls_test.rs::test_replace_class`).
3. In the Starknet OS re-execution of the same transaction, `execute_replace_class` in `syscall_impls.cairo` (or `deprecated_execute_syscalls.cairo`) performs no such check, and unconditionally writes the undeclared class hash into `contract_state_changes`, producing a different state diff/root than the one blockifier committed.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
