**Analysis:** `Account::get_account_resource` derives a deterministic `StateKey` from the attacker-controlled `address` via `StateKey::resource_typed::<AccountResource>(self.address.inner())`, but the version used to fetch state is always `self.ledger_version`, which is set once at `Account` construction and passed unmodified to `self.context.get_state_value_poem(&state_key, self.ledger_version, &self.latest_ledger_info)`. [1](#0-0) 

The address only affects which `StateKey` is looked up, not which version is queried — there is no code path where attacker-controlled `address` input can alter `self.ledger_version` or otherwise decouple the state fetch from the ledger version bound at `Account::new`. The same `self.ledger_version` value is consistently threaded through all state-fetching calls in this file, including `balance()`'s `get_state_value_poem` calls and `find_resource()`'s `self.context.state_view(Some(self.ledger_version))`. Based on the visible call sites, there is no attacker-controlled input that can cause a version/address mismatch in the returned `AccountResource` bytes.
