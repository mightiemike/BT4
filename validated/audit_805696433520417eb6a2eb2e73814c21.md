### Title
Unrecoverable Panic on Nil Class-Manager Assumption in Gateway State Reader - (File: crates/apollo_gateway/src/sync_state_reader.rs)

### Summary
`SyncStateReader::get_contract_class_from_client` assumes that any class hash reported as "declared" by the state-sync service must also be present in the class manager. When that invariant is violated, the code executes an unconditional `panic!`, crashing the gateway process that is servicing ordinary user transactions — the same bug class as the free5GC AUSF advisory (an unchecked assumption that a lookup always succeeds, leading to a runtime panic reachable from processing an untrusted request).

### Finding Description
`SyncStateReader::get_contract_class_from_client` first checks `is_class_declared_at` against the state-sync client, and if that returns `true`, unconditionally unwraps the class-manager lookup with a `panic!` fallback instead of an error: [1](#0-0) 

```rust
fn get_contract_class_from_client(&self, class_hash: ClassHash) -> StateResult<ContractClass> {
    let is_class_declared = ...is_class_declared_at(...)?;
    if !is_class_declared {
        return Err(StateError::UndeclaredClassHash(class_hash));
    }
    let contract_class = ...get_executable(class_hash)...
        .unwrap_or_else(|| {
            panic!(
                "Class with hash {class_hash:?} doesn't appear in class manager even though \
                 it was declared"
            )
        });
    Ok(contract_class)
}
```

This function is invoked through `StateReader::get_compiled_class` on the code path the gateway uses to build a state view for stateful transaction validation (`SyncStateReaderFactory` → `SyncStateReader`, wired in `create_gateway`). The team's own test explicitly documents this as a `should_panic` case rather than an error path: [2](#0-1) 

The panic fires whenever the two backing services (state-sync, tracking chain state/declarations, and class-manager, tracking compiled class bodies) disagree about a class hash's availability — e.g., the class-manager's cache/storage is behind, pruned, or has not yet synced the class body for a hash that state-sync already marks declared at the requested block. Because `is_class_declared_at`/`get_executable` are two independent RPC/state calls with no atomicity guarantee between them, this divergence is a realistic operational condition (not merely a hypothetical), and it can be triggered by any ordinary transaction that references (invokes, or re-declares) the affected class hash — i.e., by an unprivileged transaction sender's normal `add_tx` submission that requires reading that class through the gateway's state reader.

This mirrors CWE-476 "Improper Null Check" in the reported free5GC advisory: an internal invariant ("if declared, then present") is asserted by an unconditional unwrap/panic instead of being defensively handled and surfaced as an error, and the code path is reachable by external, unprivileged input.

### Impact Explanation
A hit on this code path causes the gateway component to panic while handling a legitimate transaction submission. Depending on runtime supervision, this can crash the gateway worker/process, causing a denial of service for transaction submission across the affected node — i.e., "a network unable to confirm new transactions" if it occurs on enough sequencer/gateway replicas, or at minimum sustained availability loss for the affected node. This directly matches the class-of-impact called for by the assignment (concrete, node-crashing DoS from processing a single, otherwise-valid user transaction), and violates the repository's own explicit coding rule to "Never panic on data reachable from requests" (`.claude/rules/code-style.md`).

### Likelihood Explanation
The trigger does not require a malicious payload — it only requires querying/invoking any contract class whose declaration has propagated to state-sync but whose executable body has not yet (or no longer) propagated to the class manager on that node (e.g., during class-manager restart, cache eviction, or replication lag). Any account or transaction referencing that class hash — declare, deploy, or invoke — routes through `get_compiled_class` → `get_contract_class_from_client` and hits the panic. This makes the condition plausible during normal node operation/rollout, and it is reachable purely by submitting an ordinary transaction, satisfying the "single submitted transaction" reachability requirement.

### Recommendation
Replace the `panic!` in `get_contract_class_from_client` with a proper `StateResult` error (e.g., `StateError::StateReadError` or a dedicated `ClassManagerInconsistency` variant) that gets propagated back as a transaction validation/execution error, consistent with how `UndeclaredClassHash` is already handled a few lines above. Additionally, consider adding a bounded retry/backoff before treating the class-manager miss as a hard error, to tolerate short-lived propagation lag between state-sync and the class manager.

### Proof of Concept
1. Run a gateway node where the state-sync client is ahead of (or has diverged from) the local class-manager's known classes for a given `class_hash` (achievable via normal operational conditions such as class-manager cache eviction/restart while state-sync retains the "declared" record).
2. Submit any ordinary transaction that causes the gateway's stateful validation to read the compiled class for that `class_hash` (e.g., an `invoke` transaction against a contract with that class, or a `declare` reusing the hash).
3. `SyncStateReader::get_contract_class_from_client` calls `is_class_declared_at` (returns `true`) then `get_executable` (returns `None`), hitting the `unwrap_or_else(|| panic!(...))` branch, crashing the gateway's handling thread/process — confirmed to be reproducible by the repository's own `#[should_panic]` regression test: [2](#0-1)

    fn get_contract_class_from_client(&self, class_hash: ClassHash) -> StateResult<ContractClass> {
        let is_class_declared = self
            .runtime
            .block_on(self.state_sync_client.is_class_declared_at(self.block_number, class_hash))
            .map_err(|e| StateError::StateReadError(e.to_string()))?;

        if !is_class_declared {
            return Err(StateError::UndeclaredClassHash(class_hash));
        }

        let contract_class = self
            .runtime
            .block_on(self.class_manager_client.get_executable(class_hash))
            .map_err(|e| StateError::StateReadError(e.to_string()))?
