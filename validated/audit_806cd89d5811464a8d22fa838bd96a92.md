## Analysis

The reported CVE describes unbounded recursion in processing nested/segmented structures derived from an externally-supplied artifact (a channel program), which can be crafted to defeat a global "flat" limit by nesting sub-structures, leading to uncontrolled recursion depth and a crash (kernel: stack exhaustion). The sequencer contains a directly analogous pattern in its handling of `NestedIntList` bytecode-segment structures that are derived from the CASM compiled from an attacker-submitted Sierra program.

### Title
Unbounded recursion depth in CASM bytecode-segment processing enables sequencer crash during class declaration and OS re-execution - (File: `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`, `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
The Sierra→CASM compiler produces a `bytecode_segment_lengths: NestedIntList` tree describing how a contract's CASM bytecode is split into (possibly nested) segments. Several sequencer code paths recursively walk this tree with **no explicit recursion-depth limit**, only a total bytecode-size limit. An attacker who declares a class can shape the Sierra program (nested branches/functions) to make the compiler emit a deeply nested `NestedIntList`, which then drives unbounded native-stack recursion in these functions on every honest node.

### Finding Description
The vulnerable recursive functions are:
- `bytecode_hash_node` / the walk in `bytecode_hash` in [1](#0-0)  — recurses once per nesting level of the segment tree while computing the compiled-class hash (V2/Poseidon or Blake hash), with no depth check, only an `assert_eq!` on total consumed length.
- `create_bytecode_segment_structure_inner` and `BytecodeSegmentNode::hash` in [2](#0-1)  and [3](#0-2)  — used by the Starknet OS hint processor to build/hash the bytecode segment structure for every Cairo1 class touched by a block, invoked from [4](#0-3) .

Notably, a sibling code path in the blockifier explicitly caps this same kind of recursion: `NestedFeltCounts::new_inner` asserts `segmentation_depth <= 1, "Only supported for segmentation depth at most 1."` ( [5](#0-4) ), showing the developers were aware unbounded nesting is possible/unsafe — yet the hash-computation and OS-hint paths above impose no such bound. Only `max_bytecode_size` (default `80 * 1024` felts, [6](#0-5) ) and `max_cpu_time`/`max_memory_usage` bound the *compiler subprocess*; nothing bounds the **depth** of the segment tree that the compiler is permitted to emit for a crafted Sierra program, nor is depth re-validated when the resulting `CasmContractClass` is later consumed by the hash and OS-hint code that runs in-process (not sandboxed).

This mirrors the CVE class exactly: recursive processing of an externally influenced, segmented structure is bounded only by an unrelated aggregate limit (total CCW count / total bytecode size), not by nesting depth, so a determined submitter can construct an input that is small in aggregate but deep in structure, defeating the aggregate bound and driving native-stack recursion far beyond what the size limit was meant to constrain.

### Impact Explanation
If a submitted Sierra program can coerce the compiler into emitting a segment tree deep enough to exhaust the native stack, every honest sequencer/full node that (a) computes the class hash during `DECLARE` validation/execution, or (b) re-executes the block through the Starknet OS (which all honest nodes must do to agree on state) will recurse to the same depth and crash (stack overflow / process abort) deterministically. Because this is a deterministic function of transaction data, it reproduces on every node processing that class, which is a network-wide denial of service — nodes crash instead of confirming/re-executing the block, i.e. "a network unable to confirm new transactions."

### Likelihood Explanation
Reaching this requires only a normal, unprivileged `DECLARE` transaction with a specially structured Sierra program; no special network position or privileged role is needed. The compiler bounds total size but not tree depth, and the recursive Rust functions that consume the resulting structure (`bytecode_hash_node`, `create_bytecode_segment_structure_inner`, `BytecodeSegmentNode::hash`) have no depth guard, unlike the analogous `NestedFeltCounts::new_inner` path which explicitly asserts depth ≤ 1. The exact achievable depth depends on undocumented behavior of the external `cairo-lang` Sierra→CASM compiler's segmentation heuristic (which segments by function/branch boundaries), so exploitability should be confirmed empirically by crafting a Sierra program with many nested control-flow constructs and observing the emitted `bytecode_segment_lengths` nesting depth.

### Recommendation
- Impose and enforce an explicit maximum recursion/nesting depth for `NestedIntList` wherever it is consumed (compiled-class hashing in `starknet_api`, and the Starknet OS hint utilities), rejecting classes whose segment structure exceeds the bound — analogous to the depth guard already present in `NestedFeltCounts::new_inner`.
- Validate this depth bound at declaration time (before the class hash is trusted/stored), not only after compilation succeeds.
- Convert the recursive tree-walk implementations to iterative (explicit stack/work-queue) algorithms so that even legitimately deep-but-valid structures cannot cause native stack exhaustion.

### Proof of Concept
Not executable from static analysis alone; would require using the actual `cairo-lang` Sierra→CASM compiler to craft a Sierra program with many nested control-flow branches/functions (e.g., deeply nested `match`/`if` chains) that stays under `max_bytecode_size` (80 KiB felts) but drives the compiler's segmentation into a deeply nested `NestedIntList`, then confirm that `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs`) or `create_bytecode_segment_structure_inner` (`crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`) recurse to a stack-exhausting depth when processing the resulting `CasmContractClass`.

fn bytecode_hash<H, NL>(bytecode: &[Felt], bytecode_segment_lengths: &NL) -> Felt
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    let mut bytecode_iter = bytecode.iter().copied();
    let (len, bytecode_hash) =
        bytecode_hash_node::<H, NL>(&mut bytecode_iter, bytecode_segment_lengths);
    assert_eq!(len, bytecode.len());
    bytecode_hash
}

/// Computes the hash of a bytecode segment. See the documentation of `bytecode_hash_node` in
/// the Starknet OS.
/// Returns the length of the processed segment and its hash.
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

impl BytecodeSegmentNode {
    pub(crate) fn hash<H: HashFunction>(&self) -> StarkHash {
        match self {
            BytecodeSegmentNode::Leaf(leaf) => H::hash_array(&leaf.data),
            BytecodeSegmentNode::InnerNode(inner_node) => {
                let flatten_input: Vec<_> = inner_node
                    .segments
                    .iter()
                    .flat_map(|segment| [Felt::from(segment.length), segment.node.hash::<H>()])
                    .collect();
                H::hash_array(&flatten_input) + Felt::ONE
            }
        }
    }

    pub(crate) fn is_leaf(&self) -> bool {
        match self {
            BytecodeSegmentNode::Leaf(_) => true,
            BytecodeSegmentNode::InnerNode(_) => false,
        }
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
