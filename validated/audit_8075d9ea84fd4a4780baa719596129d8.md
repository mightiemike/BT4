### Title
Missing zero-address / format validation on `Inbound.RevertInstructions.FundRecipient` allows permanent loss of bridged funds during revert/refund minting - (File: x/uexecutor/types/inbound.go)

### Summary
`Inbound.ValidateForExecution()` in [1](#0-0)  rigorously validates `p.Recipient` (non-empty, valid hex) for `FUNDS`, `GAS`, and CEA payload paths, but never validates `p.RevertInstructions.FundRecipient` — the address that receives bridged funds whenever an inbound fails, is reverted, or is rescued. `Canonicalize()` only trims/rewrites the field leniently and explicitly does not reject malformed values [2](#0-1) . This mirrors the Surge `Factory.sol` bug class: one address field (`Recipient`) is gated against zero/invalid values, but a semantically equivalent field controlling fund destination (`FundRecipient`) has no such gate, so attacker-supplied data can route value to `address(0)`.

### Finding Description
`RevertInstructions.FundRecipient` is a user-controlled field (set by whoever emits the source-chain deposit event that the Push Chain gateway relays as an `Inbound`, e.g. an `addFunds` call). It flows unchecked into every fund-recovery path:

- `buildRevertOutbound` uses it directly as the outbound `Recipient` for `INBOUND_REVERT` [3](#0-2) .
- `handleFailedOutbound` uses it as the mint target when re-minting bridged PRC20 tokens back after a failed outbound: `k.CallPRC20Deposit(ctx, ..., common.HexToAddress(recipient), amount)` [4](#0-3) .
- `AttachRescueOutboundFromReceipt` uses it as the rescue-fund recipient [5](#0-4) .

None of these call sites, nor `Inbound.ValidateBasic()`/`ValidateForExecution()`, verify that `FundRecipient` is a non-zero, well-formed address — in contrast to `p.Recipient`, which is explicitly checked with `utils.IsValidAddress(p.Recipient, utils.HEX)` and rejected if empty [6](#0-5) . Because `common.HexToAddress` on a malformed/short/garbage hex string silently degrades to a zero-padded (often all-zero) `common.Address`, and the literal zero address `0x000...0` is itself "valid hex," an attacker-supplied `FundRecipient` can deterministically cause `CallPRC20Deposit`/`CallPRC20Deposit`-style re-mints to target `address(0)`, permanently burning the bridged PRC20 tokens that were supposed to be refunded.

### Impact Explanation
Any inbound whose deposit fails post-quorum (swap failure, missing token config, gas issues, etc.) or is force-reverted/rescued triggers a re-mint of the bridged amount to `FundRecipient`. If that field is unvalidated garbage or the zero address, the protocol mints PRC20 tokens to `address(0)` instead of refunding the depositor — a permanent, unrecoverable loss of user funds, matching the "permanent loss of user or protocol-controlled funds" allowed impact.

### Likelihood Explanation
`FundRecipient` is populated purely from attacker/user-supplied source-chain event data with no privileged actor involved; the vote/finalization path treats it as trusted because `ValidateBasic`/`ValidateForExecution` never touch it, and `Canonicalize()` is explicitly "lenient... never rejected". Any inbound that later fails (a condition regularly reachable via ordinary swap/config failures, not requiring validator collusion) will exercise this unguarded field. The main uncertainty is the exact byte-level behavior of `common.HexToAddress`/`LenientCanonicalizeAddress` on malformed input in this codebase — I could not fully inspect `utils/address.go` / `utils/canonical.go` in the time available to confirm the precise degenerate output, but the zero-address case (`FundRecipient = "0x0000000000000000000000000000000000000000"`, which is syntactically valid) is unambiguously unguarded regardless of that behavior.

### Recommendation
Add explicit validation for `RevertInstructions.FundRecipient` wherever it is accepted (in `ValidateForExecution`, mirroring the `Recipient` checks) rejecting empty, non-hex, and the zero address (`EvmZeroAddress`), and re-validate/fallback to `Sender` at each consumption site (`buildRevertOutbound`, `handleFailedOutbound`, `AttachRescueOutboundFromReceipt`) before calling `CallPRC20Deposit`.

### Proof of Concept
1. An unprivileged user triggers a `FUNDS`/`GAS`/`FUNDS_AND_PAYLOAD` inbound deposit whose source-chain event sets `RevertInstructions.FundRecipient = "0x0000000000000000000000000000000000000000"` (or any malformed string).
2. Validators vote and finalize the ballot; `ValidateBasic`/`ValidateForExecution` pass because neither checks `FundRecipient` [7](#0-6) .
3. Execution subsequently fails (e.g., autoswap failure, as already exercised in `TestInboundGas`'s "swap failure creates INBOUND_REVERT outbound" test) [8](#0-7) , or the outbound is later observed as failed.
4. `buildRevertOutbound`/`handleFailedOutbound` sets `recipient = FundRecipient` (the zero address) and calls `CallPRC20Deposit(ctx, prc20Address, common.HexToAddress(recipient), amount)` [9](#0-8) , minting the user's bridged tokens to `address(0)` — permanently destroying them instead of refunding the user.

// Canonicalize normalizes encoding-variant fields in place (per source-chain
// namespace) so the same event from any observer is byte-identical across
// ballot keys, UTX keys and registry lookups. Lenient (unparseable values are
// kept trimmed, never rejected) because the vote path must always record a
// UTX — execution-level validation rejects malformed inbounds later.
func (p *Inbound) Canonicalize() {
	p.SourceChain = strings.TrimSpace(p.SourceChain)
	p.TxHash = utils.LenientCanonicalizeTxHash(p.SourceChain, p.TxHash)
	p.Sender = utils.LenientCanonicalizeAddress(p.SourceChain, p.Sender)
	p.AssetAddr = utils.LenientCanonicalizeAddress(p.SourceChain, p.AssetAddr)
	// Recipient lives on Push Chain (EVM) regardless of source chain.
	p.Recipient = utils.LenientCanonicalizeEVMAddress(p.Recipient)
	p.LogIndex = strings.TrimSpace(p.LogIndex)
	p.Amount = strings.TrimSpace(p.Amount)
	p.RawPayload = utils.CanonicalizeHexBlob(p.RawPayload)
	p.VerificationData = utils.CanonicalizeHexBlob(p.VerificationData)
	if p.RevertInstructions != nil {
		// Refunds return to the source chain.
		p.RevertInstructions.FundRecipient = utils.LenientCanonicalizeAddress(p.SourceChain, p.RevertInstructions.FundRecipient)
	}
}

func (p Inbound) ValidateBasic() error {
	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)
	if chain == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}
	if !strings.Contains(chain, ":") {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain must be in CAIP-2 format <namespace>:<reference>")
	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")
	}

	// Validate sender — needed for revert recipient fallback
	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	// Validate log_index — needed for UTX key
	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}

	// Validate tx_type enum — needed to route execution
	if _, ok := TxType_name[int32(p.TxType)]; !ok || p.TxType == TxType_UNSPECIFIED_TX {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid tx_type: %v", p.TxType)
	}

	return nil
}

// ValidateForExecution checks fields that are required for actual execution of the inbound.
// Called after ballot finalization, before ExecuteInbound. Failures here produce a failed
// PCTx and (for non-isCEA) a revert outbound, rather than dropping the vote.
func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}
