### Title
Unguarded subtraction in `accrue()`'s treasury-fee calculation can underflow and permanently revert every deposit/redeem/transfer/borrow/repay call - (File: `mainnet/contracts/vault/v0-vault-usdc.clar` and identical `v0-vault-*` vault contracts)

### Summary
`accrue()` — which runs unconditionally at the top of `deposit`, `redeem`, `transfer`, `system-borrow`, `system-repay`, and `flashloan` — computes a treasury fee (`treasury-lp`) using an unguarded subtraction `(- (total-assets-preview) reserve-inc)`. If `reserve-inc` ever reaches or exceeds `total-assets-preview`, Clarity's uint subtraction aborts the transaction. Because every state-changing entry point re-invokes `accrue()`, once this condition is reached it recurs on every future call (interest keeps accruing, so `reserve-inc` stays non-zero), permanently freezing all funds in the vault with no way to deposit, redeem, or transfer.

### Finding Description
`accrue()` computes, on every call (when not paused):

```
(debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
(reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
(treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0))
``` [1](#0-0) 

The divisor `(- (total-assets-preview) reserve-inc)` is only guarded by `(> reserve-inc u0)`, which checks that a fee exists, not that `total-assets-preview` is large enough to subtract `reserve-inc` from. There is no `asserts!`, `min`, or clamping to prevent `reserve-inc` from exceeding `total-assets-preview`.

`total-assets-preview` is `current-assets + interest`, where `current-assets` is the raw `assets` data-var [2](#0-1) . That `assets` variable can be driven down — including to `u0` — by `socialize-debt`, which is a normal (non-DAO, authorized-caller) operational function used to write off bad debt:

```
(var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
``` [3](#0-2) 

`socialize-debt` reduces `assets` and `total-borrowed`/`principal-scaled` proportionally but does not touch `fee-reserve` or guarantee the subsequent per-block `debt-delta`/`reserve-inc` will stay smaller than the (now much smaller) `total-assets-preview`. Once outstanding scaled principal remains after a socialize-debt write-down and idle/AUM `assets` has been reduced near zero, later blocks' interest accrual again produces `reserve-inc > 0` while `total-assets-preview` can be at or below `reserve-inc` (this margin can be exactly zero or negative due to the rounding mismatch between `mul-div-up` used for `calc-cumulative-debt`/`debt-preview` and `mul-div-down` used for the local `new-debt`/`old-debt` computation in `accrue`, especially as `fee-reserve` approaches `BPS`). At that point `(- (total-assets-preview) reserve-inc)` underflows a `uint` and the whole `accrue()` call — and therefore the wrapping `deposit`/`redeem`/`transfer`/`system-borrow`/`system-repay`/`flashloan` — reverts.

`accrue()` is called unconditionally at the start of every one of these functions via `(u (try! (accrue)))`, as seen in `deposit`/`redeem`/`transfer` [4](#0-3)  and in `system-borrow`/`system-repay`/`flashloan` [5](#0-4) . There is no separate path to move funds that bypasses `accrue()`. Once the underflow condition is reached, since block time keeps advancing and generates further `debt-delta`/`reserve-inc > 0` on the next call, the failure is self-perpetuating: every subsequent call to any of these entry points reverts identically. This is structurally the same class as the reported bug — an unconditionally-invoked accrual/reward-claim step containing an unguarded arithmetic operation that can revert, permanently locking funds because it sits on the only path in/out of the vault.

The same `accrue()` pattern with the same unguarded subtraction is present identically in the other vault contracts (`v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-stx.clar`, `v0-vault-usdh.clar`), as shown by the earlier grep match count of the same `treasury-lp`/`reserve-inc` block in all six vault files.

### Impact Explanation
If triggered, every `deposit`, `redeem`, `transfer`, `system-borrow`, `system-repay`, and `flashloan` call on the affected vault reverts permanently (no admin bypass exists for `accrue()` other than the DAO pause flag, which only suppresses the *update* logic path but still requires normal governance action, not a code-level fix). This freezes all user principal and unclaimed yield already deposited in that vault indefinitely — a permanent freezing of funds.

### Likelihood Explanation
The trigger requires `socialize-debt` to substantially reduce `assets` while debt remains outstanding, combined with `fee-reserve` being large enough (or accrual timing tight enough) that per-block `reserve-inc` meets or exceeds the shrunken `total-assets-preview`. `socialize-debt` is a legitimate, reachable protocol mechanism (bad-debt write-off after undercollateralized liquidation shortfalls), not a DAO-compromise scenario, so the precondition is within normal operational scope. The exact numeric trigger is condition-dependent (requires the fee-reserve/asset-write-down ratio to align), making this a real but non-trivial-to-hit edge case; the root cause (missing guard before the subtraction) is unconditionally present in the code regardless of whether it has yet been observed on mainnet.

### Recommendation
Clamp `reserve-inc` (or the divisor) so the subtraction cannot underflow, e.g.:
```
(safe-reserve-inc (min reserve-inc (total-assets-preview)))
(treasury-lp (if (and (> reserve-inc u0) (> (total-assets-preview) reserve-inc))
                (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc))
                u0))
```
This makes `accrue()` degrade gracefully (skip minting treasury shares for that block) instead of aborting the transaction, preserving availability of `deposit`/`redeem`/`transfer`/`system-borrow`/`system-repay`/`flashloan` under all asset/debt states, including after large `socialize-debt` write-downs.

### Proof of Concept
1. Vault has outstanding debt (`scaled-principal > 0`, `total-borrowed > 0`) and `fee-reserve` set to a materially high value.
2. Market/authorized caller invokes `socialize-debt` with a `scaled-amount` that leaves some `scaled-principal` outstanding but drives `assets` down to `u0` (or near it) via `(var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))` [6](#0-5) .
3. Time advances; a user calls `deposit`, which begins with `(u (try! (accrue)))` [7](#0-6) .
4. Inside `accrue()`, `debt-delta`/`reserve-inc` are computed from the remaining `scaled-principal`'s index growth, while `total-assets-preview` reflects the now-near-zero `assets` plus interest [2](#0-1) .
5. `(- (total-assets-preview) reserve-inc)` underflows, aborting the `deposit` transaction.
6. Every later call to `deposit`, `redeem`, `transfer`, `system-borrow`, `system-repay`, or `flashloan` on this vault repeats steps 3-5 and reverts identically, permanently freezing all funds already held by the vault.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
