### Title
Unbounded native recursion over attacker-controlled `bytecode_segment_lengths` in compiled-class hashing/re-execution causes stack-overflow DoS - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
The Sierra→CASM compilation pipeline produces a `bytecode_segment_lengths` field (`NestedIntList`) whose nesting depth is derived from the structure of an attacker-submitted Sierra program. This nested structure is subsequently walked with ordinary (non-tail) native Rust recursion — with no depth limit — in at least three independent code paths that every honest node must execute to validate a `Declare` transaction or re-execute/prove a block. A pathologically deep segment structure can exhaust the default OS thread stack and crash the process, analogous to the uncontrolled-recursion crash described in CVE-2019-9143.

### Finding Description
`bytecode_hash_node` recurses once per nesting level of the segment tree with no depth check: [1](#0-0) 

This function is invoked by `HashableCompiledClass::hash`, which is the routine used to (re)compute a declared class's `compiled_class_hash` — a computation every gateway/full node performs itself to validate the value supplied by the transaction sender: [2](#0-1) 

The same unbounded pattern exists in the Starknet OS bytecode-segment-structure builder and hasher, used during OS re-execution/proving of the block: [3](#0-2) [4](#0-3) 

And again in the blockifier's post-execution segment-visitation accounting used for gas/segment tracking after any invocation of the class's entry point: [5](#0-4) 

The `bytecode_segment_lengths` value originates from the CASM produced by the Sierra-to-CASM compiler subprocess and is deserialized as-is: [6](#0-5) 

Its nesting depth tracks the compiled program's statement/branch structure, which an attacker fully controls by crafting the submitted Sierra program (an unprivileged contract declarer's input). Unlike Cairo0 "recursion" (which is checked in `RecursionDepthGuard`) or the deliberately-provisioned oversized-stack threads used for Cairo-Native contract-call execution, none of the above three recursive walkers run on a guarded/enlarged stack, and none enforce a maximum nesting depth: [7](#0-6) [8](#0-7) 

Notably, the codebase is already aware that deep nesting of this exact `NestedIntList` structure is dangerous — a sibling structure (`NestedFeltCounts`) explicitly asserts a depth bound of 1 — but that safeguard is not applied to the hashing/segment-visitation paths described above: [9](#0-8) 

### Impact Explanation
An attacker who declares a class whose compiled bytecode segment structure is crafted (via the Sierra program's control-flow/branch structure) to be deeply nested can exhaust the native call stack of any node executing `bytecode_hash_node` (gateway/full-node compiled-class-hash validation on `Declare`), `create_bytecode_segment_structure_inner`/`BytecodeSegmentNode::hash` (OS re-execution/proving), or `get_visited_segments` (post-execution accounting on every subsequent call into the class). A stack overflow in a Rust process typically manifests as an immediate process abort (SIGSEGV), crashing the gateway, sequencer, or prover process. Because compiled-class-hash validation is re-derived independently by every honest node that processes the `Declare` transaction, and OS re-execution is performed by every node/prover that replays the block, this can produce a synchronized crash across honest nodes — a network-wide denial of service / inability to confirm new transactions, satisfying the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Reachable directly from a single, unprivileged `Declare` (or L1-triggered class declaration) transaction — no operator/proposer/prover privilege required. The only constraint is producing a Sierra program whose compiled bytecode nesting depth is large enough to overflow the default thread stack, which is plausible for a program with many nested branches/functions well within existing bytecode-size and libfunc-list limits enforced by the compiler subprocess (those limits bound bytecode size/CPU/memory of the compiler, not the resulting `bytecode_segment_lengths` nesting depth).

### Recommendation
- Convert `bytecode_hash_node`, `create_bytecode_segment_structure_inner`, `BytecodeSegmentNode::hash`, and `get_visited_segments` to iterative (explicit-stack) implementations, or enforce and reject a maximum nesting depth for `bytecode_segment_lengths` immediately after Sierra-to-CASM compilation (mirroring the `segmentation_depth <= 1` style guard already used for `NestedFeltCounts`).
- Alternatively/additionally, run compiled-class-hash validation and OS bytecode-segment processing on a stack-size-guarded thread, the same way Cairo-Native contract execution already is.

### Proof of Concept
1. Craft a Sierra program whose control-flow structure compiles into a CASM bytecode with a `bytecode_segment_lengths: NestedIntList` containing tens of thousands of nested `Node` levels (e.g., via deeply chained/inlined function or branch structures), while staying within `max_bytecode_size`/allowed-libfuncs constraints enforced by `SierraToCasmCompiler::compile` (`crates/apollo_compile_to_casm/src/compiler.rs:30-55`).
2. Submit this class via a `Declare` transaction to the gateway.
3. When the gateway/full node computes `compiled_class_hash` via `HashableCompiledClass::hash` → `bytecode_hash::<H, NL>` → `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs:111-132`), the deep recursion exhausts the default thread stack, crashing the validating process before/while processing the transaction; the same class, if it enters state, later crashes OS re-execution (`create_bytecode_segment_structure_inner`) and post-execution segment accounting (`get_visited_segments`) on every node that replays or re-executes the block.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

fn get_visited_segments(
    segment_lengths: &NestedFeltCounts,
    visited_pcs: &mut Vec<usize>,
    bytecode_offset: &mut usize,
) -> Result<Vec<usize>, TransactionExecutionError> {
    let mut res = Vec::new();

    match segment_lengths {
        NestedFeltCounts::Leaf(length, _) => {
            let segment = *bytecode_offset..*bytecode_offset + length;
            if visited_pcs.last().is_some_and(|pc| segment.contains(pc)) {
                res.push(segment.start);
            }

            while visited_pcs.last().is_some_and(|pc| segment.contains(pc)) {
                visited_pcs.pop();
            }
            *bytecode_offset += length;
        }
        NestedFeltCounts::Node(segments) => {
            for segment in segments {
                let segment_start = *bytecode_offset;
                let next_visited_pc = visited_pcs.last().copied();

                let visited_inner_segments =
                    get_visited_segments(segment, visited_pcs, bytecode_offset)?;

                if next_visited_pc.is_some_and(|pc| pc != segment_start)
                    && !visited_inner_segments.is_empty()
                {
                    return Err(TransactionExecutionError::InvalidSegmentStructure(
                        next_visited_pc.unwrap(),
                        segment_start,
                    ));
                }

                res.extend(visited_inner_segments);
            }
        }
    }
    Ok(res)
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}

// Implementing the Drop trait to decrement the recursion depth when the guard goes out of scope.
impl Drop for RecursionDepthGuard {
    fn drop(&mut self) {
        *self.current_depth.borrow_mut() -= 1;
    }
}
