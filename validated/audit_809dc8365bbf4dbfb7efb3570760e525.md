The pattern described in the report (unbounded recursion consuming unlimited resources when traversing deeply nested/linked structures) is exactly what protobuf-go already defends against on every decode path. Each recursive unmarshal function decrements a bounded counter and errors out once exceeded, rather than recursing without limit:

- Binary unmarshal: `internal/impl/decode.go` `unmarshalPointer` checks `opts.depth--` against zero before recursing into nested messages, and the top-level `proto.UnmarshalOptions.unmarshal` seeds `RecursionLimit` from `protowire.DefaultRecursionLimit` when unset. [1](#0-0) [2](#0-1) 

- Slow-path binary unmarshal (`proto/decode.go`) applies the same check for maps/messages. [3](#0-2) 

- ProtoJSON decoding (`encoding/protojson/decode.go`) decrements `RecursionLimit` on every `unmarshalMessage` call and returns `"exceeded max recursion depth"` once it's exhausted. [4](#0-3) 

- ProtoText decoding (`encoding/prototext/decode.go`) applies the same guard in `unmarshalMessage`, `unmarshalMap`, `skipValue`, and `skipMessageValue`, covering both known and discarded/unknown nested fields. [5](#0-4) [6](#0-5) 

- Even the low-level wire skipping in `protowire.ConsumeFieldValue` (used for skipping unknown group fields) tracks a `depth` parameter and returns an error code rather than recursing unbounded. [7](#0-6) 

- Map value decoding in the table-driven codec (`internal/impl/codec_map.go`) and validation path (`internal/impl/validate.go`) both thread the same depth/`RecursionLimit` state through. [8](#0-7) [9](#0-8) 

Extensive tests exist confirming that exceeding these limits with deeply nested payloads (including maps and lists) correctly errors out with "exceeded max/maximum recursion depth" rather than consuming unbounded gas/CPU. [10](#0-9) [11](#0-10) 

Since every decode entry point (binary, JSON, text) on the untrusted-input path already enforces a bounded, default recursion limit (`protowire.DefaultRecursionLimit`) and returns a controlled error rather than recursing indefinitely, there is no reachable unprivileged path where an attacker-controlled message depth can cause unbounded resource consumption analogous to the Hats Protocol recursive-function-call issue.
