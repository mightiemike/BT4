Based on the investigation, the closest native analog to the SecuritizeVault bug is a slippage-protection pattern that reuses a self-referential, manipulable on-chain quote as its own protection floor, rather than a bug where a *fixed* redemption balance is misrouted.

### Title
Auto-swap `minPCOut` derived from a same-transaction spot quote provides no real slippage protection, letting an unprivileged attacker sandwich GAS-topup and gas-refund swaps for value loss - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
Three PRC20→PC auto-swap paths (gas top-up inbound, gas-and-payload inbound, and excess-gas outbound refund) compute a "safety" floor `minPCOut` by taking 95% of a spot quote fetched from the Uniswap V3 `QuoterV2` contract immediately before executing the swap in the same keeper call. Because the quote itself is read from the live AMM pool state at execution time, an attacker who moves the pool price beforehand causes the quote — and therefore `minPCOut` — to already reflect the manipulated price. The 5% band offers no protection against a price that has already been pushed away from fair value, enabling a classic sandwich extraction at the expense of the user's converted funds. This mirrors the external report's core defect: an output amount is computed from a rate that can diverge from the "fair"/expected value at the moment of use, and the mismatch causes end users to receive less than they should.

### Finding Description
The three call sites share the same anti-pattern: [1](#0-0) [2](#0-1) [3](#0-2) 

In each, `GetSwapQuote` performs a static (`commit=false`) call to `QuoterV2.quoteExactInputSingle` right before the real swap is executed via `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`: [4](#0-3) 

`minPCOut` is then derived purely as `quote * 95 / 100` — a percentage of the just-read spot price, not an independent floor derived from a time-weighted price, an oracle, or a user-specified slippage tolerance. Since inbound votes (and their consequent auto-swaps) are triggered by ordinary user transactions that reach quorum in a predictable block window, an unprivileged actor can:
1. Submit a large swap on the same PRC20/WPC Uniswap V3 pool immediately before the inbound quorum-triggering vote lands (or within the same block, depending on mempool/vote timing), pushing the pool price against the pending swap.
2. Let the module's `GetSwapQuote` read this already-manipulated price and compute `minPCOut` from it — the check is self-referential and will always be satisfied because it is 95% of the manipulated number itself, not of the pre-manipulation fair value.
3. Let the module's swap execute at the bad price, and then reverse the manipulating trade, capturing the price impact as profit.

The result is a token-accounting corruption in `CallPRC20DepositAutoSwap`'s output: the recipient's UEA receives materially less native PC than a swap at fair market price would have produced, even though the on-chain check reports success. This is functionally the same defect class as the SecuritizeVault report — an amount that should reflect an actual/expected external exchange rate is instead vulnerable to being computed post/at the moment of a manipulable external state read, producing an inconsistent (here: attacker-favorable, victim-unfavorable) amount without reverting.

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound (a normal user gas-abstraction top-up) and every outbound excess-gas refund routes PRC20→PC value through this swap. A sandwich against the pool directly reduces the PC amount minted to the user's UEA or refunded to the sender, i.e., a real, quantifiable value loss for ordinary unprivileged users with no validator or admin misbehavior required. Because this is systemic to every gas-related inbound/refund rather than a one-off edge case, the aggregate value extraction over the pool's lifetime can be material.

### Likelihood Explanation
Likelihood is high in relative terms because: (a) the trigger requires no special privilege — any account can trade against the Uniswap V3 pool used for `defaultFeeTier`/quoting; (b) inbound vote finalization timing (when 2/3 quorum of UVs vote) is externally observable, giving an attacker a window to time the sandwich; (c) the 5%-of-spot-quote formula is a very generous slippage tolerance to sandwich within. The mitigating factor is that profitability scales with pool liquidity/depth and the size of the swapped amount, so very deep pools reduce (but do not eliminate) the exploitable margin.

### Recommendation
Do not derive `minPCOut` from a spot quote fetched in the same call path as the swap execution. Instead:
- Use a time-weighted average price (TWAP) from the Uniswap V3 pool (or an independent price oracle) to compute the expected output, and apply the slippage tolerance to that TWAP-derived value.
- Alternatively, allow the original inbound/outbound event to carry a user- or protocol-configured `minPCOut`/slippage bound established at the time the source-chain event was observed (before it could be influenced by same-block trading), rather than recomputing it from live pool state at execution time.
- Consider adding pool-depth or price-impact circuit breakers so a single swap cannot exceed a bounded percentage of pool liquidity.

### Proof of Concept
1. Identify the Uniswap V3 pool address returned by `GetUniversalCoreQuoterAddress`/`GetDefaultFeeTierForToken` for the PRC20 token being gas-abstracted (e.g. PRC20 USDC / WPC pool).
2. Attacker submits a large swap on that pool (front-run leg) shifting the price unfavorably for a PRC20→WPC conversion.
3. Attacker's known target inbound (a normal user's `GAS` or `GAS_AND_PAYLOAD` deposit) reaches UV quorum and is executed by `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, calling `GetSwapQuote` which now returns the manipulated (lower) rate, and `minPCOut = quote*95/100` is computed from that already-bad number.
4. `CallPRC20DepositAutoSwap` executes at the manipulated price, and the check `minPCOut` is trivially satisfied since it was derived from the same manipulated price — the transaction does not revert.
5. Attacker submits the back-run leg, restoring the pool price and collecting the price-impact profit; the victim's UEA has received less PC than a fair-value swap would have provided.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
