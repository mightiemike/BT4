### Title
`handle_poison_microblock` accepts cross-tenure key-reuse as equivocation proof due to missing `sequence`/`prev_block` context check - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`)

### Summary
`check_microblock_header_signer` (lines 686-713) only verifies that `mblock_header_1` and `mblock_header_2` recover to the same public-key hash; it never checks that the two headers belong to the same microblock stream (same `sequence`, same `prev_block`/parent anchor). `handle_poison_microblock` (lines 722-883) then resolves the slashing target purely from the pubkey hash via `get_microblock_pubkey_hash_height`, with no re-validation of the headers' tenure context before recording/paying out the report.

### Finding Description
The invariant a valid poison report must satisfy is: `h1` and `h2` are two *distinct* microblocks occupying the *same slot* of the *same* stream — i.e. `h1.sequence == h2.sequence` and both chain from the same parent anchored block (`h1.prev_block == h2.prev_block`, or equivalently both belong to the microblock fork rooted at the same tenure). The code as written only checks pubkey-hash equality: [1](#0-0) 

`handle_poison_microblock` then takes `pubkh` and looks up a single height record for it via `get_microblock_pubkey_hash_height`, and uses `mblock_header_1.sequence` alone (never cross-checked against `mblock_header_2.sequence`, nor against `prev_block` on either header) to decide whether to (over)write the poison report and who the "reporter" of record becomes: [2](#0-1) 

Because the lookup and the report are keyed only by `pubkh`, and `pubkh` is not guaranteed unique per tenure/anchored block, a reused key `K` from two disjoint, honest microblock streams (heights H1 and H2, different `prev_block`/parent anchors, no real conflicting sequence overlap) will still pass `check_microblock_header_signer` since both headers recover to `K`. Nothing in `handle_poison_microblock` forces `h1.sequence == h2.sequence` or `h1.prev_block == h2.prev_block`; the function proceeds straight to slashing/reward logic against whichever block height is currently associated with `pubkh` in the database.

### Impact Explanation
If this path is reachable with a genuinely reused (but never-conflicting) key, an honest miner is wrongfully slashed and a false reporter can claim the coinbase — a reward theft (block-reward mis-payment) affecting the honest miner's tenure and the reporter's principal, matching the "reward mis-payment/loss" impact category. This does not, by itself, cause a chain split or fork, since it only affects Clarity-level bookkeeping of poison reports/coinbase slashing, not block-validity consensus.

### Likelihood Explanation
Exploitability depends entirely on whether the underlying data model (`get_microblock_pubkey_hash_height` / its insertion side in `clarity_db.rs` and `stackslib/src/chainstate/stacks/db/mod.rs`) enforces global uniqueness of a microblock pubkey hash across all tenures/blocks, or ties the stored height strictly to the specific block that declared it. I was not able to fully trace the insertion side (`set`/`register` logic for this height mapping) within the available iterations, so I cannot confirm with certainty whether two independent, honest, non-overlapping tenures can actually both legally register the same `pubkh` in the live chainstate such that this ambiguity is reachable in practice. The code-level omission of a `sequence`/`prev_block` equality check inside `check_microblock_header_signer`/`handle_poison_microblock` is directly confirmed; whether it is exploitable end-to-end hinges on the (unverified) uniqueness semantics of the pubkey-hash-to-height registration.

### Recommendation
In `check_microblock_header_signer`/`handle_poison_microblock`, in addition to verifying `pkh1 == pkh2`, require `mblock_header_1.sequence == mblock_header_2.sequence` and `mblock_header_1.prev_block == mblock_header_2.prev_block` (or equivalently, both headers must chain to the same registered microblock parent for the same anchored-block context) before accepting the pair as proof of equivocation.

    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
