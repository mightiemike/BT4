### Title
Signed cookie verification never checks the `expires` timestamp, allowing stale OAuth state/session cookies to remain valid indefinitely - (File: `packages/apps/shopify-api/runtime/http/cookies.ts`)

### Summary
The custom `Cookies` implementation used for the OAuth CSRF-protection nonce (`STATE_COOKIE_NAME`) and the non-embedded session cookie (`SESSION_COOKIE_NAME`) sets an `expires` value when signing a cookie, but the verification path (`getAndVerify` / `isSignedCookieValid`) only checks the HMAC signature over the cookie *value* — it never reads or compares the stored `expires` timestamp against the current time. This is the same root cause as the reported oracle bug class: a freshness/staleness attribute is set at creation time but is never enforced at validation time, so once a value is signed it is treated as valid forever regardless of the age of the data.

### Finding Description
`Cookies.setAndSign` stores an `expires` field alongside the cookie value/signature: [1](#0-0) 

That `expires` field is only ever used when serializing the `Set-Cookie` header for the client: [2](#0-1) 

But when a cookie is read back and verified, `getAndVerify` -> `isSignedCookieValid` recomputes the HMAC over the value and keys and compares signatures only — the `receivedCookieJar[name].expires` value (which is parsed and available, see `Cookies.parseCookies` at lines 101-108) is never consulted: [3](#0-2) 

This library's own OAuth flow relies exclusively on this mechanism to bound the lifetime of the CSRF state nonce: it signs the nonce with a 60-second expiry and expects that expiry to be enforced: [4](#0-3) 

and later reads it back purely via `getAndVerify`, with no additional freshness check performed in `oauth.ts`: [5](#0-4) 

The same unchecked-expiry `getAndVerify` call is also used to resolve the current session id for non-embedded apps: [6](#0-5) 

Because the signature is computed only over the cookie value (not the `expires` timestamp), a previously-valid signed cookie value remains cryptographically indistinguishable from a fresh one after its intended expiration — the library places 100% of the staleness enforcement burden on the browser honoring the `Set-Cookie: expires=...` attribute, exactly as the analog bug relies on Chainlink's `latestRoundData` freshness without protocol-side enforcement.

### Impact Explanation
If a previously-issued signed `shopify_oauth_state` cookie (or `shopify_app_session` cookie) is replayed to the server after its intended 60-second/expiration window — via a caching proxy, browser extension, misconfigured client, non-browser HTTP client, or any mechanism that doesn't strictly purge expired cookies — the library will treat it as fully valid. For the OAuth flow this extends the effective window during which a fixated/stolen state nonce can be used to complete a CSRF-driven OAuth callback, undermining the intended defense-in-depth of a short-lived nonce. For the session cookie, it means a session identifier cookie that should have already expired continues to resolve to a session id.

### Likelihood Explanation
Exploitation requires an attacker to have (or coerce a victim's client into replaying) a cookie value/signature pair issued earlier — no secret key compromise or privileged access is required, and this is purely a request-authentication/cookie-handling logic gap. The precondition (an intermediary or client that resends an "expired" cookie past its lifetime) is a known-realistic class of CSRF/cookie-replay scenario, though it depends on the cookie not being purged by a standards-compliant browser, moderating overall likelihood.

### Recommendation
Store and verify the `expires` (or an explicit `iat`/timestamp) value as part of the signed payload (e.g., include it in the data covered by `createCookieSignature`), and in `isSignedCookieValid`/`getAndVerify`, explicitly reject the cookie if `Date.now()` is past the stored expiration, mirroring the recommended `chainlinkStaleLimit` check pattern (compare current time against `expires` before trusting the signature).

### Proof of Concept
1. Call `shopify.auth.begin(...)`, capturing the `Set-Cookie: shopify_oauth_state=<nonce>; shopify_oauth_state.sig=<sig>; expires=<+60s>`.
2. Wait beyond the 60-second window (or simply construct a request replaying the captured `Cookie` header verbatim without waiting, since nothing time-bounds it server-side).
3. Send `shopify.auth.callback(...)` with the same `Cookie` header and a matching `state` query parameter/HMAC.
4. Observe `cookies.getAndVerify(STATE_COOKIE_NAME)` in `oauth.ts` returns the nonce value successfully and OAuth completes, despite the cookie being past its intended `expires` time — confirming no staleness check occurs in `Cookies.isSignedCookieValid`.

  static encodeCookie(data: CookieData): string {
    let result = '';
    result += `${data.name}=${data.value};`;
    result += Object.entries(data)
      .filter(([key]) => !['name', 'value', 'expires'].includes(key))
      .map(([key, value]) => `${key}=${value}`)
      .join('; ');
    if (data.expires) {
      result += ';';
      result += `expires=${data.expires.toUTCString()}`;
    }
    return result;
  }

    const value = this.get(name);
    if (!value) return undefined;

  private get canSign() {
    return this.keys?.length > 0;
  }

  set(name: string, value: string, opts: Partial<CookieData> = {}): void {
    this.outgoingCookieJar[name] = {
      ...opts,
      name,
      value,
    };
    this.updateHeader();
  }

  async setAndSign(
    name: string,
    value: string,
    opts: Partial<CookieData> = {},
  ): Promise<void> {
    if (!this.canSign) {
      throw Error('No keys provided for signing.');
    }
    this.set(name, value, opts);
    const sigName = `${name}.sig`;
    const signature = await createCookieSignature(this.keys[0], value);
    this.set(sigName, signature, opts);
    this.updateHeader();
  }

  async isSignedCookieValid(cookieName: string): Promise<boolean> {
    const signedCookieName = `${cookieName}.sig`;
    if (
      !this.cookieExists(cookieName) ||
      !this.cookieExists(signedCookieName)
    ) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }
    const cookieValue = this.get(cookieName);
    const signature = this.get(signedCookieName);

    if (!cookieValue || !signature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    const allCheckSignatures = await Promise.all(
      this.keys.map((key) => createCookieSignature(key, cookieValue)),
    );

    const validSignature = allCheckSignatures.some((checkSignature) =>
      safelyCompareSignatures(checkSignature, signature),
    );

    if (!validSignature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    return true;
  }
