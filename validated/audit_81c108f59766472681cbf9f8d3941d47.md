### Title
Wallet-Contract `has_in_flight_tx` lock can be permanently stuck with no recovery mechanism, freezing all future transactions - ([File: runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs])

### Summary
The eth-wallet-contract enforces a single-in-flight-transaction invariant via the `has_in_flight_tx` boolean, which is only ever cleared inside the terminal callbacks (`rlp_execute_callback`, `address_check_callback`, `nep_141_storage_balance_callback`, `ban_relayer`). There is no owner-callable, unprivileged, or protocol-level mechanism analogous to a "delegate" that can force-clear this flag if the resolving callback itself fails to complete. If the terminal callback panics (e.g. runs out of its fixed, small static gas budget) after `has_in_flight_tx` was already set to `true` by the initiating call, the state change resetting the flag is rolled back and never persists, permanently locking the wallet out of processing any future `rlp_execute` calls.

### Finding Description
`rlp_execute` sets `self.has_in_flight_tx = true` before returning a `Promise` [1](#0-0) . The invariant comment states this flag must be `true` while a promise is outstanding and `false` otherwise [2](#0-1) , but the only place that resets it back to `false` is inside the eventual callback (`rlp_execute_callback`, `address_check_callback`, `nep_141_storage_balance_callback`, or `ban_relayer`), and only if that callback function completes successfully without panicking.

The default execution path allocates a fixed, hard-coded gas budget for the terminal callback regardless of how large the called contract's return value is: [3](#0-2) 

`rlp_execute_callback` reads the promise result and copies it into the `ExecuteResponse.success_value`: [4](#0-3) 

The `target` account being called is chosen by the relayer (constrained only to match the "to" address encoded in the user-signed Ethereum transaction) [5](#0-4) , meaning any FunctionCall target the wallet owner signs a transaction for can return an arbitrarily large success value up to the protocol maximum. Because `RLP_EXECUTE_CALLBACK_GAS` is a fixed constant (5 Tgas) unrelated to the size of the returned payload [6](#0-5) , a large enough return value can exhaust this budget while `rlp_execute_callback` is deserializing/copying `env::promise_result(0)`, causing the callback receipt itself to fail with "Exceeded the prepaid gas." Because NEAR only persists state changes from a function call that completes without panicking, the `self.has_in_flight_tx = false` write at the top of the callback (line 280) is discarded along with the rest of that call's state diff, leaving `has_in_flight_tx` permanently `true`.

Unlike the connext `delegate` mechanism intended to let a trusted party force through or fix a stuck cross-chain transfer, the wallet contract exposes no such escape hatch: `rlp_execute` unconditionally rejects any call while `has_in_flight_tx == true` [7](#0-6) , and the reset-capable methods are all `#[private]`, callable only via a chained promise from the contract itself — there is no publicly reachable, unprivileged way to unstick the flag once this happens. This mirrors the audited bug class: the presence of a "delegate"/recovery mechanism is not enforced, so failure at the wrong step permanently locks funds.

### Impact Explanation
If triggered, the account permanently loses the ability to process any further Ethereum-emulated transaction through this wallet contract, effectively freezing the funds and access controlled by this contract, since the only entry point (`rlp_execute`) will always short-circuit on the stuck flag. This matches the "permanently frozen funds" acceptance criterion.

### Likelihood Explanation
Reaching this state requires the wallet owner (via their signed Ethereum-style transaction, which any relayer can submit under the NEAR wallet contract's meta-transaction-like flow) to target a contract that returns (or can be made to return) a payload large enough to exceed the fixed 5 Tgas callback budget. This is plausible when interacting with any large-response contract (or an adversarial/compromised one), and requires no validator/network-level compromise — only a normal transaction submission through the documented `rlp_execute` flow.

### Recommendation
Scale the static gas reserved for `rlp_execute_callback` (and the other terminal callbacks) based on a worst-case/maximum return value size, or bound/truncate the copied return value inside the callback before further processing. Additionally, consider adding a permissionless or time-boxed recovery function (analogous to enforcing a "delegate") that can clear `has_in_flight_tx` if the outstanding promise chain has definitively resolved but the callback failed to commit, preventing indefinite denial of service on the account.

### Proof of Concept
1. Deploy the wallet contract for an eth-implicit account and register a relayer, as in the existing integration tests (`runtime/near-wallet-contract/implementation/wallet-contract/src/tests/sanity.rs`).
2. Sign an Ethereum-style transaction (via the wallet's private key) whose `target` is a contract method that returns a very large value (up to the protocol's maximum allowed function-call return size).
3. Submit via `rlp_execute` with sufficient outer gas so that `has_in_flight_tx` is set to `true` and the inner action promise succeeds.
4. Observe that `rlp_execute_callback`, running with the fixed `RLP_EXECUTE_CALLBACK_GAS` budget, fails with "Exceeded the prepaid gas" while copying the oversized `promise_result`.
5. Call `rlp_execute` again with any valid transaction and observe it is permanently rejected with "transaction already in progress" — confirming `has_in_flight_tx` never resets, since compare to the existing `test_insufficient_gas` test that only demonstrates recoverability when the *outer* call runs out of gas *before* the flag is set [8](#0-7) , not the case where the terminal callback itself fails after the flag is already `true`.

    pub fn rlp_execute_callback(
        &mut self,
        caller_deposit: Option<CallerDeposit>,
    ) -> ExecuteResponse {
        self.has_in_flight_tx = false;
        let n = env::promise_results_count();

        if n == 0 {
            // `rlp_execute_callback` is called directly in the case of an emulated self-transfer.
            return ExecuteResponse { success: true, success_value: None, error: None };
        } else if n > 1 {
            return ExecuteResponse {
                success: false,
                success_value: None,
                error: Some(format!(
                    "Invariant violation: this callback comes after a single promise. n={n}"
                )),
            };
        }

        match env::promise_result(0) {
            PromiseResult::Failed => {
                // The cross-contract call failed, refund the caller if needed
                if let Some(CallerDeposit { account_id, yocto_near }) = caller_deposit {
                    let refund_promise = env::promise_batch_create(&account_id);
                    env::promise_batch_action_transfer(
                        refund_promise,
                        NearToken::from_yoctonear(yocto_near.into()),
                    );
                }

                ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Failed Near promise".into()),
                }
            }
            PromiseResult::Successful(value) => {
                ExecuteResponse { success: true, success_value: Some(value), error: None }
            }
        }
    }

fn validate_tx_relayer_data<'a>(
    tx: &NormalizedEthTransaction,
    target: &'a AccountId,
    context: &ExecutionContext,
    expected_nonce: u64,
) -> Result<TargetKind<'a>, Error> {
    if tx.address.raw() != context.current_address {
        return Err(Error::Relayer(RelayerError::InvalidSender));
    }

    if tx.chain_id != Some(CHAIN_ID) {
        return Err(Error::Relayer(RelayerError::InvalidChainId));
    }

    let to = tx.to.ok_or(Error::User(UserError::EvmDeployDisallowed))?.raw();

    let target_kind = parse_target(target, context.current_address);

    // valid targets satisfy `to == target` or `to == hash(target)`
    let is_valid_target = match target_kind {
        TargetKind::CurrentAccount if to == context.current_address => {
            target == &context.current_account_id
        }
        TargetKind::EthImplicit(address) if to == address => {
            target.as_str()
                == format!("0x{}{}", hex::encode(address), context.current_account_suffix())
        }
        _ => to == account_id_to_address(target),
    };

    if !is_valid_target {
        return Err(Error::Relayer(RelayerError::InvalidTarget));
    }

    let nonce = if tx.nonce <= U64_MAX {
        tx.nonce.low_u64()
    } else {
        return Err(Error::Relayer(RelayerError::InvalidNonce));
    };
    if nonce != expected_nonce {
        return Err(Error::Relayer(RelayerError::InvalidNonce));
    }

    // Relayers must attach at least as much gas as the user requested.
    let gas_limit = if tx.gas_limit < U64_MAX { tx.gas_limit.as_u64() } else { u64::MAX };
    if env::prepaid_gas().as_gas() < gas_limit.saturating_mul(GAS_MULTIPLIER) {
        return Err(Error::Relayer(RelayerError::InsufficientGas));
    }

    Ok(target_kind)
}

#[tokio::test]
async fn test_insufficient_gas() -> anyhow::Result<()> {
    let TestContext { worker, wallet_contract, wallet_sk, .. } = TestContext::new().await?;

    // If not enough gas is attached to the `rlp_execute` call then the action fails.
    let target = "some.account.near".to_string();
    let action = Action::FunctionCall {
        receiver_id: target.clone(),
        method_name: "greet".into(),
        args: br#"{"name": "Aurora"}"#.to_vec(),
        gas: 5_000_000_000_000,
        yocto_near: 0,
    };
    let signed_transaction = utils::create_signed_transaction(
        0,
        &target.parse().unwrap(),
        Wei::zero(),
        action,
        &wallet_sk,
    );

    let error = wallet_contract
        .inner
        .call(crate::tests::RLP_EXECUTE)
        .args_json(serde_json::json!({
            "target": target,
            "tx_bytes_b64": codec::encode_b64(&codec::rlp_encode(&signed_transaction))
        }))
        .gas(near_gas::NearGas::from_tgas(7))
        .transact()
        .await
        .unwrap()
        .raw_bytes()
        .unwrap_err();

    assert!(
        error.to_string().contains("Exceeded the prepaid gas."),
        "Error should be that there was not enough gas"
    );

    // But the contract is still usable afterwards.
    utils::deploy_and_call_hello(&worker, &wallet_contract, &wallet_sk, 0).await?;

    Ok(())
}
