### Title
Unauthenticated JSON-RPC endpoint accepts unbounded JSON nesting, enabling pre-authentication stack-overflow denial of service - ([File: chain/jsonrpc/src/lib.rs])

### Summary
The JSON-RPC server's HTTP handler `rpc_handler` deserializes every request body directly into the `Message` enum via axum's `Json<Message>` extractor (`serde_json::from_slice` under the hood) before any account, signature, or nonce validation takes place. `Message` is `#[serde(untagged)]` and its `Request` variant carries `params: serde_json::Value`, an arbitrary, unbounded JSON tree. Neither `serde_json` nor the surrounding code enforces any recursion/nesting depth limit on this parse step, matching the "unbounded type nesting" root cause described in the Apache Qpid Proton-J advisory (CVE-2026-66274).

### Finding Description
`create_jsonrpc_app()` registers the main POST route which is served by `rpc_handler`: [1](#0-0) 
The handler takes `Json(request): Json<Message>` as an axum extractor argument, meaning the JSON body is parsed into the `Message` type before `rpc_handler`'s body even runs — i.e., before `handler.process()`, before method dispatch, and before any transaction/account-key validation.

`Message` is defined as an untagged enum whose `Request` variant contains a raw `serde_json::Value` for `params`: [2](#0-1) [3](#0-2) 

Because `Message` is `#[serde(untagged)]`, serde must buffer the input into an internal `Content` representation to try each variant, and `serde_json::Value`'s own `Deserialize` implementation is inherently recursive over nested JSON arrays/objects — there is no depth counter or bail-out. Sending a body such as `[[[[[...]]]]]` nested tens of thousands of levels deep requires only a very small payload (well under the documented 10MB body-size limit noted in `chain/jsonrpc/RPC_ARCHITECTURE.md`), because nesting depth, not payload size, drives stack consumption. Each level of array/object nesting adds a stack frame to the recursive descent parser and to serde's `Content` deserialization; sufficiently deep nesting exhausts the worker thread's stack and aborts the process with a `SIGSEGV`/stack-overflow before the request reaches `JsonRpcHandler::process`, `process_request_internal`, or any per-method authentication/validation logic (`Params::parse`, `send_tx_commit`, etc.).

No mitigation (nesting-depth cap, custom `Deserializer` wrapping, or a bounded recursive-descent parser) is present anywhere in `chain/jsonrpc`, `chain/jsonrpc-primitives`, or the axum route configuration.

### Impact Explanation
The JSON-RPC HTTP endpoint (default port 3030) is the primary, unauthenticated public interface nearcore exposes to "any RPC caller" per the scan's reachability criteria. A stack overflow triggers an unrecoverable process abort in Rust (there is no way to catch a stack overflow), crashing the entire node process — including validator nodes that also run the RPC server, or any node depending on this pathway for transaction submission and view calls. This is a transaction/request-triggered halt of the affected process, satisfying the "transaction-triggered halt" acceptance criterion. If exploited against a majority of validators' RPC front-ends simultaneously (a single crafted HTTP request replayed against every public RPC endpoint), it can produce a coordinated denial of service across the network's client access layer.

### Likelihood Explanation
Likelihood is high: the attack requires a single unauthenticated HTTP POST request with no signed transaction, no valid nonce, and no funds — just a deeply nested JSON body. No special network position, validator status, or credentials are needed, matching the "pre-authentication" characterization of the referenced CVE class.

### Recommendation
Enforce a maximum JSON nesting depth before/while deserializing untrusted RPC bodies — e.g., wrap the incoming bytes with a depth-limited `serde_json::Deserializer` (via `serde_stacker`-style stack growth guarding, or a custom pre-pass that rejects inputs exceeding a fixed nesting bound, e.g. 128) prior to constructing `Message`/`Value`. Apply the same guard to any other externally reachable `serde_json::Value`/untagged-enum parse sites (e.g., `Params::parse` in `chain/jsonrpc/src/api/mod.rs`, and the JSON-RPC client's response parsing).

### Proof of Concept
```
python3 -c "
import socket
depth = 200000
body = b'{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"status\",\"params\":' + b'[' * depth + b']' * depth + b'}'
s = socket.create_connection(('127.0.0.1', 3030))
req = b'POST / HTTP/1.1\r\nHost: x\r\nContent-Type: application/json\r\nContent-Length: %d\r\n\r\n' % len(body) + body
s.sendall(req)
print(s.recv(4096))
"
```
Sending this request (well under the 10MB body limit) to a stock nearcore JSON-RPC endpoint causes the worker thread to overflow its stack while `axum::Json<Message>` deserializes `params`, aborting the process before `JsonRpcHandler::process` is ever invoked.
