## Finding: Unauthorized gas-fee drain of a victim's UEA via failed-signature `MsgExecutePayload`

### Title
`ExecutePayload` deducts and burns gas fees from a victim's UEA even when payload execution fails signature verification, allowing an unprivileged attacker to drain victim UEA balances for free - ([File: x/uexecutor/keeper/msg_execute_payload.go])

### Summary
This is the same bug class as the report: `Gauge.depositFor()` moved funds out of an account other than the one that authorized/paid for the action. In Push Chain's `x/uexecutor` module, `Keeper.ExecutePayload` (the handler backing the gasless, permissionless `MsgExecutePayload` message) deducts real EVM gas fees from the target UEA's balance **before** checking whether the payload execution actually succeeded, and does so without any cache/rollback wrapper. An attacker can submit a gasless `MsgExecutePayload` naming any victim's `UniversalAccountId` with a garbage `VerificationData`, causing the on-chain signature check inside the UEA to revert — yet the victim's UEA still pays the real gas cost consumed up to that revert.

### Finding Description
`MsgExecutePayload` is in the gasless whitelist [1](#0-0) , so the attacker (the Cosmos `Signer`) pays nothing to submit it, and by design `Signer != UniversalAccountId.Owner` is intentionally allowed so third parties can relay pre-authorized payloads [2](#0-1) .

The keeper method invoked from the message server is `Keeper.ExecutePayload`: [3](#0-2) 

Inside it, the EVM call to the UEA's `executeUniversalTx` runs directly against `sdkCtx` (no `CacheContext`), and then gas fees are deducted **unconditionally**, before the `execErr` from that call is even inspected: [4](#0-3) 

`DeductGasFeesFromReceipt` only skips deduction if `receipt == nil || receipt.GasUsed == 0`; it does not check whether the underlying call reverted: [5](#0-4) 

It then unconditionally transfers-and-burns real UPC from the **target UEA's balance** (`recipient`, derived from the attacker-supplied `universalAccountId`, not from the message `Signer`): [6](#0-5) [7](#0-6) 

Note the contrast with the sibling method `ExecutePayloadV2` (used only in the inbound-processing path), which correctly wraps the EVM call and fee deduction in a `CacheContext` and only commits (`writeCache()`) when **both** succeed, discarding fee deduction if `execErr != nil`: [8](#0-7) 

The `MsgExecutePayload`-facing `ExecutePayload` function lacks this safety wrapper. Because the on-chain signature check lives entirely inside the UEA contract (ECDSA recovery / Ed25519 precompile) as documented, the Cosmos layer intentionally does not pre-validate authorization [9](#0-8)  — meaning an attacker's call with an invalid signature always reaches the EVM, consumes real gas up to the revert point, and that gas cost then gets billed to the victim's UEA via `DeductGasFeesFromReceipt` regardless of the revert.

### Impact Explanation
An unprivileged attacker who knows (or enumerates) any victim's `UniversalAccountId` can:
1. Submit a gasless `MsgExecutePayload` with that victim's `UniversalAccountId`, an arbitrary `UniversalPayload` (with a large `GasLimit`/`MaxFeePerGas` to maximize consumed gas before the signature check reverts), and any garbage `VerificationData`.
2. Pay zero Cosmos fees (message is gasless).
3. Cause the victim's UEA to be billed and have its native UPC balance burned for gas consumed by an EVM call the victim never authorized.
4. Repeat this arbitrarily to drain the victim's UEA balance entirely, at no cost to the attacker.

This is an unauthorized burn of user-controlled funds by an unprivileged, non-consenting attacker, matching the in-scope impact "unauthorized burn ... of user or protocol-controlled funds," and directly analogous to `depositFor()` pulling funds from the wrong account.

### Likelihood Explanation
High. No privileged role, validator collusion, or key compromise is required — any external account can submit `MsgExecutePayload` naming any `UniversalAccountId` since the module deliberately does not require `Signer == Owner`. The only requirement is that the victim's UEA holds a UPC balance (which it must, to receive PRC20/native deposits at all) and is deployed (or auto-deployed via the pre-funded-address path in the same function [10](#0-9) ).

### Recommendation
Wrap the EVM execution and fee deduction in `Keeper.ExecutePayload` (msg_execute_payload.go) in a `CacheContext`, mirroring `ExecutePayloadV2`, so that gas-fee deduction is only committed together with a successful `execErr == nil` execution. Alternatively, if fee billing on revert is intentionally desired to prevent free spam, bill the message `Signer`/relayer rather than the target UEA `Owner` for reverted/unauthorized attempts, since the relayer — not the UEA owner — initiated the unauthenticated call.

### Proof of Concept
1. Victim deploys/funds a UEA for `UniversalAccountId{chainNamespace, chainId, Owner: victimAddr}` with some UPC balance (required for it to receive deposits).
2. Attacker (any account, no funds needed beyond dust to exist) submits `MsgExecutePayload{Signer: attacker, UniversalAccountId: victim's id, UniversalPayload: {To: attackerAddr, GasLimit: large, ...}, VerificationData: "0xdeadbeef"}` — a gasless message per `app/txpolicy/gasless.go`.
3. `msgServer.ExecutePayload` → `Keeper.ExecutePayload` resolves the victim's UEA address, calls `CallUEAExecutePayload`, which reverts inside the UEA contract's signature check (`executeUniversalTx`), but returns a receipt with `GasUsed > 0`.
4. `DeductGasFeesFromReceipt` runs unconditionally on `sdkCtx` and burns real UPC from the victim's UEA balance for that reverted call.
5. `execErr != nil` is only checked afterward, so the Cosmos message returns an error to the attacker, but the victim's on-chain state (UEA balance) has already permanently changed.
6. Repeating step 2 drains the victim UEA's balance over multiple calls, entirely at the attacker's discretion and at zero cost to the attacker.

```markdown
### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```

**File:** x/uexecutor/README.md (L222-227)
```markdown
The cryptographic binding is enforced inside the UEA contract's `executeUniversalTx` (see [`UEA_EVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_EVM.sol#L145) and [`UEA_SVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_SVM.sol)):

1. The contract holds the owner's public key as **immutable bytes** set at UEA deployment via `initialize(_id, _factory)`. There is no code path that mutates this after init.
2. `executeUniversalTx(payload, signature)` verifies the `signature` (passed in as `MsgExecutePayload.VerificationData`) against this stored owner — ECDSA recovery for EVM-origin owners, the Ed25519 precompile (`0x00…00ca`) for SVM-origin owners.
3. The signed payload hash includes a contract-tracked `nonce` (monotonic per UEA) and optional `deadline`, providing replay and freshness protection.
4. If signature verification fails, the contract reverts. The revert propagates as `execErr` from `CallUEAExecutePayload`; the keeper returns the error from `ExecutePayload`; the entire Cosmos transaction (including any partial gas-fee deduction) rolls back atomically. **No state changes survive a failed signature check.**
```

```go
// ExecutePayload handles universal payload execution on the UEA.
func (ms msgServer) ExecutePayload(ctx context.Context, msg *types.MsgExecutePayload) (*types.MsgExecutePayloadResponse, error) {
	_, evmFromAddress, err := utils.GetAddressPair(msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to parse signer address")
	}

	err = ms.k.ExecutePayload(ctx, evmFromAddress, msg.UniversalAccountId, msg.UniversalPayload, msg.VerificationData)
	if err != nil {
		return nil, err
	}

	return &types.MsgExecutePayloadResponse{}, nil
}
```

```go
func (k Keeper) DeductAndBurnFees(ctx context.Context, from sdk.AccAddress, gasCost *big.Int) error {
	amt := sdkmath.NewIntFromBigInt(gasCost)
	coin := sdk.NewCoin(pchaintypes.BaseDenom, amt)

	k.Logger().Debug("deducting and burning fees",
		"from", from.String(),
		"gas_cost", gasCost.String(),
		"denom", pchaintypes.BaseDenom,
	)

	err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, from, types.ModuleName, sdk.NewCoins(coin))
	if err != nil {
		return err
	}

	return k.bankKeeper.BurnCoins(ctx, types.ModuleName, sdk.NewCoins(coin))
}
```

```go
	// Step 2: Wrap EVM execution + fee deduction in a CacheContext so they
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr
	}

	// Both succeeded — commit EVM state and fee deduction together.
	writeCache()
```
