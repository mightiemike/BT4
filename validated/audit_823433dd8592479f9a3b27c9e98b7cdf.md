## Analysis

The external report describes Endaoment's `finalizeGrant` bug: `fee = grant.value/100` truncates to `0` under Solidity integer division when `grant.value < 100`, silently zeroing out a value meant to protect/compensate a party.

Push Chain's node code contains a structurally identical integer-truncation-to-zero pattern, but in a security-critical slippage-protection value rather than a fee, with a fund-loss impact rather than a missed-fee impact.

### Title
Slippage protection (`minPCOut`) truncates to zero on small swap quotes, nullifying sandwich-attack protection during gas-refund and gasless deposit auto-swaps - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
Every path in `x/uexecutor` that swaps a PRC20 gas token back into native PC computes its slippage floor with plain integer division:
```go
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
``` [1](#0-0) [2](#0-1) [3](#0-2) 

Solidity/Go integer division rounds down, so whenever `quote < 2` (i.e. the Uniswap V3 `quoteExactInputSingle` estimate for the swapped amount is 0 or 1 wei of PC — a routine occurrence for the small excess-gas amounts refunded through `applyGasRefund`, e.g. `refundAmount` values of tens/hundreds of wei as seen in the test fixtures), `minPCOut` truncates to `0`. This is the exact analog of `fee = grant.value/100` truncating to `0` for `grant.value < 100`.

### Finding Description
`applyGasRefund` (called from `handleSuccessfulOutbound`/`handleFailedOutbound` on every OBSERVED outbound vote) computes a Uniswap quote for the excess gas amount and derives a 5%-slippage floor via `quote*95/100`, then passes it to `CallUniversalCoreRefundUnusedGas` which performs the actual on-chain swap with `withSwap=true`. [4](#0-3) 

The same pattern is used for gasless inbound deposits that get auto-swapped through `depositPRC20WithAutoSwap` in `ExecuteInboundGas` and `gasAndPayloadDepositAutoSwap`. [5](#0-4) [6](#0-5) 

Because `minPCOut` is derived purely from `quote` via truncating division, any refund/auto-swap whose quoted output is below `100/95 ≈ 1.05` PC-wei (i.e. `quote` is 0 or 1) results in `minPCOut = 0`. When `minPCOut = 0` is passed on to the Uniswap-V3-style swap in `UniversalCore`/handler contracts, the swap executes with **no minimum-output constraint at all** — the AMM will accept any price, including one an unprivileged actor has manipulated immediately beforehand by trading against the same pool (classic sandwich attack). Since these swaps are triggered deterministically as part of ordinary, unprivileged user flows (an inbound deposit, or excess gas being refunded after a normal outbound), an external actor needs no special privilege to front-run/back-run the pool and extract the swap's value, permanently draining PC (or PRC20) value that should have gone to the refund recipient or the depositor.

### Impact Explanation
This falls squarely in scope: "corruption of ... gas fee accounting, refund accounting ... draining ... of user or protocol-controlled funds" reachable "from ordinary user deposits ... or default transaction submission paths alone," with an unprivileged external attacker (no malicious validator/relayer/TSS assumption needed — only the ability to trade against the same on-chain pool). The loss is real value transferred out of the protocol/user's control with no recourse (the swap already succeeded on-chain by the time `minPCOut=0` is discovered to have offered no protection).

### Likelihood Explanation
The trigger condition (`quote < 2`) is not an edge case reserved for pathological inputs — it is the *expected* regime for excess-gas refunds, which are typically small residual amounts (the integration tests use refund amounts like `61`, `110` wei of gas token). Any gas token with a low PC-denominated unit price, or any small residual/dust refund, will commonly produce `quote` values of 0 or 1, making `minPCOut = 0` a routine, not rare, occurrence.

### Recommendation
- Enforce a floor on `minPCOut` so it is never allowed to be zero when `quote > 0` (e.g. round up, or reject/skip the swap-with-slippage path and fall back to the no-swap direct-deposit path already implemented in `applyGasRefund` when `quote` is too small to derive a meaningful floor).
- Consider using ceiling division (`(quote*95 + 99) / 100`) or a fixed minimum absolute slippage bound rather than a purely proportional one, since proportional slippage becomes meaningless at small absolute values.
- Add explicit unit tests asserting `minPCOut` is never `0` for `quote > 0`, mirroring the existing `TestUniversalCoreABI_GetOutboundTxGasAndFees_Has6Outputs`-style regression coverage already present in `x/uexecutor/keeper/gas_fee_test.go`.

### Proof of Concept
1. An unprivileged user triggers a gasless inbound deposit of a low-value PRC20 gas token, or a normal outbound whose observed `gasFeeUsed` leaves a small excess (e.g. `gasFee=111`, `gasFeeUsed=110` → `refundAmount=1`).
2. `GetSwapQuote`/`getSwapQuoteForRefund` returns `quote=1` (1 wei of PC) for this tiny input amount.
3. `minPCOut = 1*95/100 = 0` (integer truncation).
4. An attacker who has visibility into the pending swap (or who has permanently skewed the low-liquidity pool being used, since this is the only pool for that gas token) executes trades against the pool to move price unfavorably immediately before the module's `DerivedEVMCall("refundUnusedGas", ..., withSwap=true, minPCOut=0)` executes.
5. The swap executes and reports success (`refundPcTx.Status = "SUCCESS"`) even though the recipient received far less PC than the fair-value quote, with the difference captured by the attacker — with no error, no revert, and no on-chain trace that slippage protection was silently disabled.

```go
// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
