Found a concrete, unprivileged-triggerable analog: the excess-gas refund calculation in `x/uexecutor/keeper/outbound.go` is silently skipped (with no error, no log, no fallback accounting) whenever the outbound's `GasFee`/`GasToken` fields end up unset, which is a normal/attacker-reachable outcome for `INBOUND_REVERT` outbounds built by `buildRevertOutbound`.

### Title
Silent skip of excess-gas-fee refund calculation leaves user gas overpayment permanently unrecovered on revert outbounds - (File: x/uexecutor/keeper/outbound.go, x/uexecutor/keeper/build_revert_outbound.go)

### Summary
`applyGasRefund` (the function responsible for calculating and returning any excess gas fee charged to a user, `gasFee - gasFeeUsed`) silently returns without performing any refund, error, or record whenever `outbound.GasFee`, `outbound.GasToken`, or the validator-reported `obs.GasFeeUsed` is empty: [1](#0-0) 

For `INBOUND_REVERT` outbounds, these gas fields are populated by `buildRevertOutbound`, which fetches them from `UniversalCore.getOutboundTxGasAndFees` — but on *any* failure of that lookup (token config missing/misconfigured, EVM call error, unpack error), the function logs a warning and returns the outbound **with the gas fields left empty**, rather than aborting or retrying: [2](#0-1) 

### Finding Description
The protocol's documented/expected behavior (mirrored by the explicit test suite in `test/integration/uexecutor/gas_fee_refund_test.go`) is: whenever `gasFee > gasFeeUsed`, the excess must be refunded via `CallUniversalCoreRefundUnusedGas`, and `PcRefundExecution` must be recorded — this is asserted even for the failed/reverted-outbound path: [3](#0-2) 

However, the "calculation" (excess = gasFee − gasFeeUsed) is gated entirely on `outbound.GasFee != ""` and `outbound.GasToken != ""`. For non-revert outbounds these fields come from a `UniversalTxOutboundEvent` emitted by the gateway contract during normal execution, so they are essentially always populated. But for `INBOUND_REVERT` outbounds (constructed off-chain by `buildRevertOutbound`, not sourced from an event), the gas fields depend on a live `CallEVM` to `getOutboundTxGasAndFees`. If that call, the token-config lookup, or the ABI unpack fails for any reason (e.g., a token whose `TokenConfig.NativeRepresentation` is missing/misconfigured, or a chain whose gas-price oracle hasn't been set yet — both are attacker/user-influenceable indirectly through which chains/tokens are used for inbound transfers that later need to revert), the function does not fail the outbound creation; it just returns the outbound with `GasFee == ""`.

Once that INBOUND_REVERT outbound is later voted OBSERVED/REVERTED by validators, `handleFailedOutbound` calls `applyGasRefund`, which immediately returns on the empty `GasFee` check — no refund is attempted, no error surfaces, and `PcRefundExecution` is never set: [4](#0-3) 

The gas fee that was already deducted/consumed from the user's inbound funds (baked into the gasFee amount reserved when the outbound was created) is thus never calculated or returned to the user — the exact "documented calculation not implemented in the reachable code path" pattern from the external report, translated to Push Chain's gas-accounting invariant instead of NFT-staking rewards.

### Impact Explanation
This results in **permanent loss of user-controlled funds**: the excess gas fee that should be refunded per the protocol's own invariant (validated by the project's own `TestGasFeeRefund` suite) is silently dropped with no accounting trail, no error, and no retry path once the outbound reaches a terminal `REVERTED` state. Because `PcRefundExecution` stays `nil` and no `RefundSwapError` is set, there is also no operational signal that a refund was skipped versus attempted-and-failed, making this a silent accounting gap rather than a visibly-failed operation that could be retried/monitored.

### Likelihood Explanation
Reachable via ordinary, unprivileged user action: a user submits an inbound with a token whose `TokenConfig` is missing `NativeRepresentation` or otherwise fails the gas lookup, and the inbound later needs to be reverted (a normal outcome of failed/rejected inbound execution). The condition depends on registry state, but does not require any privileged actor — it can occur from configuration gaps that are common in newly onboarded chains/tokens, or race conditions between token onboarding and traffic. No malicious validator/relayer/admin action is required to trigger the loss; only the ordinary revert path plus a lookup failure that the code already tolerates by design ("proceeding without gas fields").

### Recommendation
`buildRevertOutbound` should not silently proceed when gas-fee lookup fails; either abort outbound creation (surfacing an error that the caller must handle, e.g. via `AbortOutbound`) or fall back to a deterministic, safe estimate rather than leaving fields empty. Separately, `applyGasRefund` should distinguish "nothing to refund" (fields legitimately absent because no excess exists) from "unable to determine refund amount" (fields missing due to upstream failure), and in the latter case record a `PcRefundExecution` with a `FAILED`/`ERROR` status and populate `RefundSwapError`, so the gap is at minimum auditable and retryable rather than silently dropped.

### Proof of Concept
1. Register a source chain/token combination where `TokenConfig.NativeRepresentation` is unset, or where `UniversalCore.getOutboundTxGasAndFees` reverts for the configured PRC20 (e.g., gas-price oracle not yet set for that chain).
2. Submit an inbound from that chain/token that fails execution (e.g., invalid payload) so that `buildRevertOutbound` is invoked to create an `INBOUND_REVERT` outbound.
3. Observe (via `k.Logger().Warn("failed to fetch gas fee info for revert outbound...")`) that the outbound is created with `GasFee == ""`.
4. Have validators vote the outbound OBSERVED/FAILED with a non-trivial `gasFeeUsed` reported from the destination chain.
5. Confirm via `GetUniversalTx` that `outbound.PcRefundExecution` is `nil` and `RefundSwapError` is empty — no refund was computed or attempted, and the excess gas fee is permanently unaccounted for.

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}

	outbound.OutboundStatus = types.Status_REVERTED
	k.Logger().Info("outbound reverted",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)

	// Refund excess gas regardless of tx type — gas was consumed on the external
	// chain whether the execution succeeded or failed.
	k.applyGasRefund(ctx, &outbound, obs)

	return k.UpdateOutbound(ctx, utxId, outbound)
}

func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}
