### Title
Cairo0 (deprecated) declared classes bypass the reverted-class staleness check in `StateReaderAndContractManager` — ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
`native_blockifier`'s `py_block_executor.revert_block` explicitly clears the process-global class cache when reverting a block, with the comment "Clear global class cache, to properly revert classes declared in the reverted block." [1](#0-0)  This shows the sequencer relies on `is_declared` re-validation (rather than always clearing the cache in every revert path) as the correctness mechanism for stale-cache reads, and indeed `get_compiled_from_class_manager` re-validates non-V0 classes against `is_declared` before serving them from the global cache — but V0 (Cairo0/deprecated) classes are explicitly exempted from this check. [2](#0-1) 

### Finding Description
`get_compiled_from_class_manager` looks up `class_hash` in the process-wide `ContractClassManager`/`GlobalContractCache` (an LRU cache shared across the process, not per-block or per-state): [2](#0-1) 

```rust
if let Some(runnable_class) = self.contract_class_manager.get_runnable(...) {
    match &runnable_class {
        RunnableCompiledClass::V0(_) => {}
        _ => {
            // ... verify it is declared, since existence in the cache does not guarantee that
            // (it might contain a declared class from a reverted block, for example).
            if !self.state_reader.is_declared(class_hash)? {
                return Err(StateError::UndeclaredClassHash(class_hash));
            }
        }
    }
    ...
    return Ok(runnable_class);
}
```

For Cairo1 classes, the code correctly re-checks `is_declared` against the *current* state reader before trusting a cache hit — because a class hash could be cached from a block that was later reverted. For Cairo0 (`RunnableCompiledClass::V0`) classes, this check is skipped entirely (`RunnableCompiledClass::V0(_) => {}`).

The `is_declared` trait method is explicitly documented and implemented to only track Cairo1 declarations — "Cairo 0 classes always return `false`" [3](#0-2)  — and concrete implementations confirm this, e.g. `DictStateReader::is_declared` returns `false` for any `V0` entry [4](#0-3) , and `ApolloReader::is_declared` only consults the Cairo1 "class definition block number" table [5](#0-4) . Because `is_declared` can never validate Cairo0 classes, the code path deliberately avoids calling it for V0 and instead trusts the cache unconditionally.

This means: once a Cairo0 class has ever been declared and cached in the process-global `ContractClassManager`, no subsequent state-consistency check re-verifies that it is still declared in the *current* canonical state before it is served for execution. Storage-level revert of a declare transaction (`apollo_storage::state::revert_state_diff` deletes rows from `deprecated_declared_classes_table`) [6](#0-5)  does not, by itself, purge the class from the blockifier's in-process cache — only an explicit, separate `contract_class_manager.clear()` call (only wired into the legacy `native_blockifier::py_block_executor::revert_block` path) does that [1](#0-0) . In the current Rust-native `apollo_batcher`/`apollo_reverts` revert flow (`revert_blocks_and_eternal_pending`, `Batcher::revert_block`), there is no equivalent call visible that clears the blockifier's global `ContractClassManager` cache before/after reverting storage [7](#0-6) [8](#0-7) .

### Impact Explanation
If a Cairo0 class hash is declared and executed (populating the process-global cache), and the containing block is subsequently reverted (e.g., consensus rollback / reorg / `revert_block` request) without the blockifier's `ContractClassManager` being cleared, the class remains servable from cache. Any later, unprivileged transaction (deploy/invoke) referencing that same class hash will succeed in executing against a class hash that is *not declared* in the current canonical state, whereas an honest node without the warm cache (or one whose cache was correctly cleared) would return `StateError::UndeclaredClassHash` and reject/revert the transaction. This produces honest-node divergence in transaction acceptance/execution outcome and resulting state root/receipts for the same block — a consensus-critical bug affecting agreement on state commitments.

### Likelihood Explanation
Reachable purely by an unprivileged sequence of transactions: (1) declare a Cairo0 class, causing it to be cached in the process-global `ContractClassManager`; (2) have that block subsequently reverted (an operational/consensus event, not attacker-controlled, but common in this system given `apollo_reverts`/`RevertBlockInput` support and integration tests exercising this flow) [9](#0-8) ; (3) submit an unprivileged invoke/deploy transaction using the same class hash. The precondition of a block revert makes this conditional rather than always-reachable from a single transaction in isolation, so likelihood depends on revert frequency in the deployment (which the codebase explicitly supports and tests). I was not able to fully verify, within the available index, whether every current revert code path (batcher/committer/state-sync) definitely omits a `ContractClassManager::clear()` call — only the legacy `native_blockifier::py_block_executor::revert_block` path was confirmed to include it. This is a gap that should be checked directly in the repository (e.g., via a Devin session) before treating likelihood as certain.

### Recommendation
Apply the same reverted-cache staleness check used for Cairo1 classes to Cairo0 classes: extend `is_declared` (or a parallel mechanism) to also validate current declaration status of Cairo0/deprecated classes, and re-check it before trusting a V0 cache hit in `get_compiled_from_class_manager`. Alternatively/additionally, ensure every revert code path (not just the legacy `native_blockifier` one) unconditionally clears the process-global `ContractClassManager` cache before resuming execution.

### Proof of Concept
Conceptual reproduction (not fully verified end-to-end within index limits):
1. Submit a Declare transaction for a Cairo0 class `C` with hash `H`, and execute a transaction referencing `H` so it becomes cached in `ContractClassManager` via `get_compiled_from_class_manager`.
2. Trigger a block revert of the block containing the declare (e.g., via `RevertBlockInput`/`apollo_reverts`) without the blockifier's `ContractClassManager` being cleared.
3. Submit an unprivileged deploy/invoke transaction referencing class hash `H` again. Because `RunnableCompiledClass::V0(_) => {}` skips `is_declared` validation, execution proceeds and returns success on this node, while a node whose cache was cold/cleared correctly returns `StateError::UndeclaredClassHash`, causing a divergence in transaction/block outcome. // This function will panic if the storage reader fails to revert.
pub fn revert_block(storage_writer: &mut StorageWriter, target_block_marker: BlockNumber) {
    let txn = storage_writer
        .begin_rw_txn()
        .unwrap()
        .revert_header(target_block_marker)
        .unwrap()
        .0
        .revert_body(target_block_marker)
        .unwrap()
        .0
        .revert_state_diff(target_block_marker)
        .unwrap()
        .0
        .try_revert_class_manager_marker(target_block_marker)
        .unwrap()
        .try_revert_base_layer_marker(target_block_marker)
        .unwrap()
        .revert_partial_block_hash_components(&target_block_marker)
        .unwrap()
        .revert_block_hash(&target_block_marker)
        .unwrap()
        .revert_global_root(&target_block_marker)
        .unwrap();

    #[cfg(feature = "os_input")]
    let txn = txn.revert_accessed_keys(target_block_marker).unwrap();

    txn.commit().unwrap();
}

    // This function will panic if there is a storage failure to revert the block.
    pub async fn revert_block(&mut self, input: RevertBlockInput) -> BatcherResult<()> {
        info!("Reverting block at height {}.", input.height);
        let height = self.get_height_from_storage()?.prev().ok_or(
            BatcherError::StorageHeightMarkerMismatch {
                marker_height: BlockNumber(0),
                requested_height: input.height,
            },
        )?;

        if height != input.height {
            return Err(BatcherError::StorageHeightMarkerMismatch {
                marker_height: height.unchecked_next(),
                requested_height: input.height,
            });
        }

        if let Some(height) = self.active_height {
            info!("Aborting all work on height {} due to a revert request.", height);
            self.abort_active_height().await;
        }

        // Wait for the revert commitment to be completed before reverting the storage.
        self.revert_commitment(height).await;

        self.storage_writer.revert_block(height);
        BUILDING_HEIGHT.decrement(1);
        GLOBAL_ROOT_HEIGHT.decrement(1);
        REVERTED_BLOCKS.increment(1);
        Ok(())
    }
