### Title
`socialize-debt` writes down `lindex`/`principal-scaled` using stale `index`/`lindex` because it never calls `accrue` first - (File: `mainnet/contracts/vault/v0-vault-stx.clar`)

### Summary
Every state-mutating vault entrypoint (`deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan`) calls `(try! (accrue))` first so that `index`/`lindex`/`last-update` are brought current before the operation reads and writes them. `socialize-debt` is the one mutator that skips this step: it reads `index`/`lindex` directly via `var-get` and immediately uses those possibly-stale values to compute a debt write-down and a new `lindex`, then persists them - permanently discarding whatever interest should have accrued between `last-update` and the socialize-debt call.

### Finding Description
In `v0-vault-stx.clar` (and the identical `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`), `accrue` is the function responsible for advancing `index`, `lindex`, and `last-update` based on elapsed time and the current interest rate: [1](#0-0) 

All other public mutators bind `(u (try! (accrue)))` as the very first `let` binding before touching `index`/`lindex`/`principal-scaled`/`assets`, e.g. `system-borrow`: [2](#0-1) 

and `system-repay`: [3](#0-2) 

`socialize-debt`, however, reads `index` and `lindex` straight from storage with no preceding `accrue` call, then immediately overwrites `lindex`, `principal-scaled`, `total-borrowed`, and `assets`: [4](#0-3) 

`idx` (the cached `index`) and `current-lindex` (the cached `lindex`) are the "source" values that `accrue` would normally update based on `stacks-block-time - last-update`. Because `accrue` is never invoked here, `debt-reduction = scaled_amount * idx / INDEX-PRECISION` and `new-lindex = current-lindex * (old-total-assets - debt-reduction) / old-total-assets` are both computed on top of a stale index/lindex that does not reflect interest accrued since the last `accrue` call (which can be an arbitrary amount of elapsed blocks/time, since `accrue` is only triggered lazily by user activity). Once `var-set lindex new-lindex` executes, the pre-write-down interest that should have compounded into `lindex` between `last-update` and the current block is permanently lost — the next `accrue` call computes `next-liquidity-index` starting from this already-truncated `lindex`, using only the time delta from `last-update` (which `socialize-debt` also never advances), so that interval's yield is neither credited to depositors before the loss is applied nor recovered afterward. This is the direct analog of the Blend bug class: a value (`non_queued_tokens`/index) that must be refreshed via an "update" step before being consumed by a state-changing function is instead consumed pre-update, corrupting the accounting used by every subsequent participant.

### Impact Explanation
`lindex` is the compounding factor lenders' shares are valued against via `total-assets`/`convert-to-assets`. Silently dropping an interval of accrued interest before applying a socialize-debt write-down permanently and irreversibly understates the yield lenders were owed for that period — this is a permanent freezing (loss) of unclaimed yield for all depositors in the affected vault, matching the in-scope High-impact class "permanent freezing of unclaimed yield." It also skews `total-borrowed`/`assets`/`principal-scaled` bookkeeping relative to what an accrue-then-socialize sequence would have produced, since `debt-reduction` and `principal-reduction` are computed off a stale `idx`.

### Likelihood Explanation
`socialize-debt` is gated by `check-caller-auth`, so it is only callable by an authorized/privileged caller (e.g. the market contract during a bad-debt socialization flow) — this makes the bug trigger on every normal invocation of the intended feature, not just an attacker-crafted edge case: any time `socialize-debt` fires after time has elapsed since the last `accrue`-triggering user action (deposit/redeem/borrow/repay), the stale-index write-down occurs. Given vaults are not accrued every block, and socialize-debt can be called independently of any user transaction that would trigger `accrue`, this is highly likely to occur in normal operation whenever bad debt is socialized.

### Recommendation
Add `(u (try! (accrue)))` as the first binding in `socialize-debt`, mirroring `deposit`/`redeem`/`system-borrow`/`system-repay`, so `index`/`lindex`/`last-update` are brought current before computing `debt-reduction`, `principal-reduction`, and `new-lindex`.

### Proof of Concept
1. At `t0`, `accrue` runs (via any deposit/borrow), setting `index = I0`, `lindex = L0`, `last-update = t0`.
2. Time passes; interest continues to accrue conceptually (the interest rate is non-zero and utilization > 0), but no user calls a mutator that triggers `accrue` — `index`/`lindex` remain stuck at `I0`/`L0` in storage even though `next-index()`/`next-liquidity-index()` would compute higher values if invoked.
3. At `t1 >> t0`, the authorized caller invokes `socialize-debt(scaled-amount)` directly (e.g., market contract during bad-debt cleanup).
4. Inside `socialize-debt`, `idx = I0` and `current-lindex = L0` are read (stale), `debt-reduction` and `new-lindex` are computed from these stale values, and `(var-set lindex new-lindex)` is executed — `last-update` is never advanced.
5. All interest that would have compounded into `lindex` between `t0` and `t1` is now unrecoverable: the next `accrue` call (at some `t2`) computes `next-liquidity-index` from `new-lindex` and a time delta of `t2 - t0` (since `last-update` was never bumped by `socialize-debt`), applying the full historical rate on top of an already-reduced base, permanently understating what lenders should have received for the `[t0, t1]` interval versus a version of the flow where `accrue` ran immediately before the write-down at `t1`.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })

          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))

                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))

    (print {
      action: "socialize-debt",
      caller: contract-caller,
      data: {
        scaled-amount: scaled-amount,
        debt-reduction: debt-reduction,
        principal-reduction: principal-reduction,
        old-lindex: current-lindex,
        new-lindex: new-lindex,
        old-total-assets: old-total-assets,
        principal-scaled: (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0),
        total-borrowed: (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0),
        index: idx
      }
    })

    (ok true)))
