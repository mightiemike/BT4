### Title
`shopify.utils.validateHmac` throws an unhandled `SafeCompareError` DoS when the admin-signator query contains an array-valued `hmac`/`timestamp`/`shop` parameter - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
`shopify.utils.validateHmac()` is a public, documented API meant to validate unauthenticated/anonymous OAuth-callback requests (`const isValid = await shopify.utils.validateHmac(req.query)`). Its internal `normalizeQuery` function only enforces "must be single-valued, not an array" for the `appProxy` signator; for the default `admin` signator it performs **no type/shape check at all** on plain (non-`URLSearchParams`) query objects before comparing the `hmac` value with `safeCompare`, which throws if the two operands are not of matching JS types.

### Finding Description
In `hmac-validator.ts`, `normalizeQuery` explicitly guards against array-valued query parameters only for `appProxy`: [1](#0-0) 

For the `admin` signator branch, a plain object query (e.g. `req.query` as parsed by Express/`qs`, where repeated query-string keys become an array) is returned unmodified — no check equivalent to `APP_PROXY_SINGLE_VALUE_PARAMS` exists for admin queries.

`validateHmac` then only checks truthiness of `normalizedQuery.hmac` before comparing: [2](#0-1) 

A non-empty array is truthy, so `!normalizedQuery.hmac` does not catch an array. The value is then passed, via a bare `as string` type-assertion (no runtime check), into `safeCompare`: [3](#0-2) 

`safeCompare` requires `typeof strA === typeof strB`; comparing an `object` (array) to a `string` local HMAC throws `ShopifyErrors.SafeCompareError` instead of returning `false`. This is exactly analogous to the reference bug class: code assumes a value/return conforms to an expected primitive type without verifying it at runtime, and an unexpected-but-plausible input (an attacker-supplied duplicated query parameter, analogous to a non-conforming `approve` return value) causes the call to revert/throw instead of failing gracefully, breaking a core authentication code path.

The documented usage pattern explicitly recommends passing `req.query` straight into this function for OAuth requests: [4](#0-3) 

Many HTTP frameworks (Express with the default `qs` query parser, etc.) turn a duplicated query key like `?hmac=aaa&hmac=bbb&shop=...&timestamp=...&code=...` into `req.query.hmac = ['aaa','bbb']`. An anonymous attacker hitting the app's OAuth callback route (or any custom route that follows the documented pattern of calling `shopify.utils.validateHmac(req.query)`) with such a duplicated parameter causes an uncaught `SafeCompareError` to be thrown inside the (async) validation call.

### Impact Explanation
The library's own tests confirm the appProxy path deliberately rejects duplicated `hmac`/`shop`/`signature`/`timestamp` parameters to prevent exactly this kind of ambiguity/hardening issue (see the "App Proxy HMAC hardening" test suite and the CHANGELOG entry "Harden app proxy authentication by rejecting repeated security parameters" - [5](#0-4) ), but the equivalent hardening was never applied to the `admin` signator branch used for the standard OAuth callback flow. Because the thrown error is not caught by `validateHmac`/`generateLocalHmac`, and because the documented call site is a bare `await` with no surrounding try/catch shown in the docs, any app that implements custom OAuth-callback handling exactly as documented is subject to an unhandled promise rejection triggered by an unauthenticated, single crafted request — a Denial of Service of the authentication handler (the callback route either 500s uncontrollably or, in frameworks without automatic async-error handling, hangs/crashes the request pipeline).

### Likelihood Explanation
Likelihood is high for any consumer following the documented pattern: no authentication or prior session is needed, only the ability to send a GET/POST request to the app's public OAuth callback endpoint with a duplicated `hmac`, `shop`, `code`, or `timestamp` query parameter, which is trivial for anonymous internet traffic. The library's built-in `oauth.ts` `callback()` function itself is not vulnerable (it builds `authQuery` via `Object.fromEntries(new URL(...).searchParams.entries())`, which naturally collapses duplicate keys to the last value, so arrays never appear there), but the publicly exposed and documented `shopify.utils.validateHmac` helper is directly vulnerable when fed a framework's raw `req.query` object, which is the exact usage shown in the official docs.

### Recommendation
Apply the same single-value enforcement used for `appProxy` (`APP_PROXY_SINGLE_VALUE_PARAMS`) to the `admin` signator branch in `normalizeQuery`, explicitly rejecting array values for `hmac`, `shop`, `state`, `timestamp`, and `code` before any comparison is attempted, and have `validateHmac`/`safeCompare` return `false` (or throw a well-documented, catchable `InvalidHmacError`) rather than allow an uncaught `SafeCompareError` to propagate out of a function whose contract is `Promise<boolean>`.

### Proof of Concept
```ts
import {shopifyApi} from '@shopify/shopify-api';

const shopify = shopifyApi({ /* ...config... */ });

// Simulates req.query from an Express app using the default `qs` parser
// when the attacker sends: /auth/callback?hmac=aaa&hmac=bbb&shop=test.myshopify.com&timestamp=...&code=...
const maliciousQuery = {
  shop: 'test.myshopify.com',
  timestamp: String(Math.trunc(Date.now() / 1000)),
  code: 'whatever',
  hmac: ['aaa', 'bbb'], // duplicated hmac param parsed as array
};

// Per the documented usage: const isValid = await shopify.utils.validateHmac(req.query);
await shopify.utils.validateHmac(maliciousQuery);
// => throws ShopifyErrors.SafeCompareError("Mismatched data types provided: object and string")
// instead of resolving to `false`, causing an unhandled rejection in any route handler
// that does not explicitly try/catch this documented call.
```

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

export const safeCompare: SafeCompare = (strA, strB) => {
  if (typeof strA === typeof strB) {
    const enc = new TextEncoder();
    const buffA = enc.encode(JSON.stringify(strA));
    const buffB = enc.encode(JSON.stringify(strB));

    if (buffA.length === buffB.length) {
      return timingSafeEqual(buffA, buffB);
    }
  } else {
    throw new ShopifyErrors.SafeCompareError(
      `Mismatched data types provided: ${typeof strA} and ${typeof strB}`,
    );
  }
  return false;
};

# shopify.utils.validateHmac

Shopify requests include an `hmac` query argument (or, in the case of app proxy requests, a `signature` query argument). This method validates those requests to ensure that the `hmac` value was signed by Shopify and not spoofed.

## Example

For OAuth requests:

```ts
const isValid = await shopify.utils.validateHmac(req.query);
```

For App Proxy requests:

```ts
const isValid = await shopify.utils.validateHmac(req.query, {
  signator: 'appProxy',
});
```
