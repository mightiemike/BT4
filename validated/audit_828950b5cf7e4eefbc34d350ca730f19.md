### Title
Race Condition in `FsClassStorage::set_class` File Persistence Allows Concurrent Declare Compilation to Corrupt/Erase Committed Class Files - (File: `crates/apollo_class_manager/src/class_storage.rs`)

### Summary
`FsClassStorage::set_class` and its helper `rename_to_persistent_dir` implement a check-then-act ("TOCTOU") pattern over the filesystem that is not safe against concurrent invocations for the same `class_id`. Two concurrent `declare` transactions for the same (or colliding) class can race through `contains_class` → `write_class_atomically` → `rename_to_persistent_dir`, where the recovery logic explicitly performs `remove_dir_all` on an already-persisted class directory before renaming its own temp directory into place. A reader (`get_executable`/`get_sierra`) that observes the "exists" marker (`get_executable_class_hash_v2`) written by one writer can attempt to read the corresponding files while another concurrent writer has just deleted them, producing a spurious `ClassNotFound` error mid-flight.

### Finding Description
`FsClassStorage::set_class` [1](#0-0)  first checks `contains_class(class_id)` and, if absent, calls `write_class_atomically` followed by `mark_class_id_as_existent` (which writes the durable "exists" marker into `ClassHashStorage`) [2](#0-1) .

The critical race is in `rename_to_persistent_dir`: [3](#0-2) 
This function is documented as a crash-recovery mechanism ("Recovers from a previous partial write... an existing directory holds the same class; removing it lets the rename proceed"), but it is invoked on every `set_class` call, not only during recovery. If two `set_class` calls for the same `class_id` race (e.g., because both callers observed `contains_class == false` before either committed), the second writer's `rename_to_persistent_dir` will `remove_dir_all` the first writer's just-persisted directory and then rename its own temp directory in. Between the `remove_dir_all` and the subsequent `rename`, a concurrent reader that already saw the marker set by the first writer (in `get_executable`/`get_sierra`, which check `contains_class`/`get_executable_class_hash_v2` before opening the file) can hit a missing file and surface `FsClassStorageError::ClassNotFound`, exactly as demonstrated by the existing unit test for the "marker exists without files" scenario [4](#0-3) .

This is reachable by an ordinary transaction sender: the gateway explicitly permits up to `max_concurrent_declare_compilations` declares to compile in parallel [5](#0-4) , and `ClassManager::add_class` performs the same "check cache miss → compile → `set_class`" sequence for every declare [6](#0-5) . An attacker (or two independent users) submitting the same class (or two classes that hash-collide into the same class-directory bucket during the same time window) as separate `declare` transactions can trigger genuinely concurrent `add_class`/`set_class` calls on the class-manager component. Additionally, `add_class_and_executable_unsafe` (used by state sync) calls the identical `set_class` path [7](#0-6) , so a declare racing against a state-sync-driven write for the same class is also possible.

Whether this is exploitable depends on whether the class-manager component is deployed behind a `ConcurrentLocalComponentServer`, which explicitly clones the component and processes requests with real parallelism up to `max_concurrency` [8](#0-7) ; if so there is no serialization guarantee protecting `FsClassStorage`'s check-then-act sequence across concurrent request handlers.

### Impact Explanation
A reader hitting a transient `ClassNotFound` mid-execution (e.g., while the blockifier/Starknet OS fetches a class for execution or re-execution) can cause execution failures that differ from a node that read a moment earlier or later, i.e., a source of honest-node execution/timing divergence around class reads. In the worst case this manifests as sporadic transaction/block-building failures for declare-adjacent flows, which is a network-liveness/availability concern for the affected node rather than a guaranteed cross-node state fork, since the underlying bytes written by both racing writers for the *same* `class_id` are identical (class_id is content-derived), so no permanently incorrect content is ever committed — only a transient read failure window.

### Likelihood Explanation
Requires two or more concurrent declares (or a declare racing a state-sync write) for the same class hash to actually overlap within the narrow window between one writer's `rename_to_persistent_dir` remove/rename sequence and a reader's subsequent file open. This is a race window measured in filesystem I/O time, and requires the class-manager component to actually run with concurrency `> 1` for the race to occur at all — a fact I could not fully confirm from the available deployment/config code, so likelihood is assessed as **Medium** pending confirmation of concurrent component deployment (`max_concurrency` for the class-manager service).

### Recommendation
Make `set_class` idempotent and free of destructive TOCTOU behavior: only remove/replace an existing persistent directory in an explicit, separately-invoked recovery/repair path (not on every write), or use content-hash-verification instead of blind `remove_dir_all` before overwriting. Alternatively, serialize `set_class` per-`class_id` (e.g., per-class lock) so concurrent writers for the same class short-circuit safely once the marker is observed, and ensure readers treat "marker present but files transiently missing" as a retryable condition rather than a hard error.

### Proof of Concept
1. Deploy the class-manager component with `max_concurrency > 1` (`ConcurrentLocalComponentServer`).
2. Submit two `declare` transactions carrying the identical Sierra class (same `class_hash`) concurrently, or a declare concurrent with a state-sync `add_class_and_executable_unsafe` call for the same class.
3. Both requests pass `contains_class(class_id) == false` before either commits.
4. Writer A completes `rename_to_persistent_dir`, then `mark_class_id_as_existent`.
5. A concurrent reader (`get_executable`) observes the marker and attempts to read the file.
6. Writer B's `rename_to_persistent_dir` sees `persistent_dir.exists() == true`, calls `remove_dir_all`, briefly leaving the directory empty/missing before its own `rename` completes.
7. If the reader's file-open lands in this window, `FsClassStorageError::ClassNotFound` is returned, matching the exact error path already covered by `cached_storage_cairo1_marker_only_returns_error` [4](#0-3) .

**Note on confidence**: I was unable to confirm within the indexed code whether the production class-manager deployment actually runs under `ConcurrentLocalComponentServer` with `max_concurrency > 1` (vs. the single-threaded `LocalComponentServer`, which would serialize all `add_class`/`set_class` calls and eliminate this race). This is the key open question determining real-world exploitability; a Devin session with full repo/config access would be needed to confirm the class-manager's server configuration.

    /// Atomically moves the staged class directory `tmp_dir` into its content-addressed persistent
    /// directory.
    ///
    /// Recovers from a previous partial write: a crash between this rename and committing the
    /// existence marker (see `FsClassStorage::set_class`) can leave an orphaned, non-empty
    /// persistent directory. `std::fs::rename` refuses to replace a non-empty directory and fails
    /// with `ENOTEMPTY`, which permanently wedges sync on the class. Callers reach this only when
    /// the existence marker is absent, and the directory is named by the class hash, so an existing
    /// directory holds the same class; removing it lets the rename proceed and the marker get
    /// written, restoring filesystem/marker consistency.
    fn rename_to_persistent_dir(
        &self,
        tmp_dir: PathBuf,
        class_id: ClassId,
    ) -> FsClassStorageResult<()> {
        let persistent_dir = self.get_persistent_dir_with_create(class_id)?;
        if persistent_dir.exists() {
            warn!("Recovering orphaned class dir from a prior partial write: {persistent_dir:?}");
            std::fs::remove_dir_all(&persistent_dir)?;
        }
        std::fs::rename(tmp_dir, persistent_dir)?;

        Ok(())
    }

    pub async fn add_class(&mut self, class: RawClass) -> ClassManagerResult<ClassHashes> {
        let sierra_class = SierraContractClass::try_from(&class)?;
        let class_hash = sierra_class.calculate_class_hash();
        if let Ok(Some(executable_class_hash_v2)) =
            self.classes.get_executable_class_hash_v2(class_hash)
        {
            // Class already exists.
            return Ok(ClassHashes { class_hash, executable_class_hash_v2 });
        }

        let compilation_start_time = Instant::now();
        let (raw_executable_class, executable_class_hash_v2) =
            self.compiler.compile(class.clone()).await.map_err(|err| match err {
                SierraCompilerClientError::SierraCompilerError(error) => {
                    ClassManagerError::SierraCompiler { class_hash, error }
                }
                SierraCompilerClientError::ClientError(error) => {
                    ClassManagerError::Client(error.to_string())
                }
            })?;
        debug!(
            %class_hash,
            compiled_class_hash = %executable_class_hash_v2,
            compilation_elapsed_ms = compilation_start_time.elapsed().as_millis(),
            class_size_bytes =
                class.size().map_or("Failed to get class size".to_owned(), |size| size.to_string()),
            casm_size_bytes =
                raw_executable_class.size().map_or("Failed to get casm size".to_owned(), |size| size.to_string()),
            "Finished compiling class."
        );

        self.validate_class_length(&raw_executable_class)?;
        Self::validate_class_version(&sierra_class)?;
        self.classes.set_class(
            class_hash,
            class,
            executable_class_hash_v2,
            raw_executable_class,
        )?;

        let class_hashes = ClassHashes { class_hash, executable_class_hash_v2 };
        Ok(class_hashes)
    }

/// The `ConcurrentLocalComponentServer` adds a concurrency wrapper to the `LocalComponentServer`,
/// allowing concurrent processing of requests.
pub struct ConcurrentLocalComponentServer<Component, Request, Response>
where
    Request: Send,
    Response: Send,
{
    local_component_server: LocalComponentServer<Component, Request, Response>,
    max_concurrency: usize,
}

impl<Component, Request, Response> ConcurrentLocalComponentServer<Component, Request, Response>
where
    Component: ComponentRequestHandler<Request, Response> + Clone + Send + 'static,
    Request: Send + Debug + PrioritizedRequest + LabeledRequest + 'static,
    Response: Send + Debug + 'static,
{
    pub fn new(
        component: Component,
        config: &LocalServerConfig,
        rx: Receiver<RequestWrapper<Request, Response>>,
        metrics: &'static LocalServerMetrics,
    ) -> Self {
        let local_component_server = LocalComponentServer::new(component, config, rx, metrics);
        Self { local_component_server, max_concurrency: config.max_concurrency }
    }

    async fn await_requests(&mut self) {
        self.local_component_server.await_requests().await;
    }

    async fn process_requests(&mut self) {
        let component_name = short_type_name::<Component>();
        info!(
            "Starting to process requests in the component {component_name} concurrent local \
             server",
        );

        let RequestProcessingMembers {
            component,
            mut high_rx,
            mut normal_rx,
            metrics,
            processing_time_warning_threshold_ms,
        } = self.local_component_server.get_processing_inner_members();

        let task_limiter = Arc::new(Semaphore::new(self.max_concurrency));

        tokio::spawn(async move {
            loop {
                // TODO(Tsabary): add a test for the queueing time metric.
                let (request, tx, request_id) = get_next_request_for_processing(
                    &mut high_rx,
                    &mut normal_rx,
                    &component_name,
                    metrics,
                )
                .await;

                // Acquire a permit to run the task.
                let permit = task_limiter.clone().acquire_owned().await.unwrap();

                // Clone the component for concurrent request processing.
                let mut cloned_component = component.clone();
                tokio::spawn(async move {
                    process_request(
                        &mut cloned_component,
                        request,
                        request_id,
                        tx,
                        metrics,
                        processing_time_warning_threshold_ms,
                    )
                    .await;
                    // Drop the permit to allow more tasks to be created.
                    drop(permit);
                });
            }
        });
    }
}
