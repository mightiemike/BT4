### Title
Accrue-pause pass-through lets debt-index snapshot go stale while borrow/repay/redeem continue, permanently dropping the DAO's reserve-fee share for the paused interval - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Every vault contract's `accrue` function checks `pause-states.accrue` and, when true, returns the *current* `{index, lindex}` without recomputing anything and without reverting — a pass-through pause instead of a hard stop. All state-changing entry points (`system-borrow`, `system-repay`, `deposit`, `redeem`, `flashloan`) call `(try! (accrue))` and then unconditionally proceed to mutate `principal-scaled`, `total-borrowed`, and `assets` using the (possibly stale) `index`/`lindex`, and `last-update` is only advanced inside the non-paused branch.

### Finding Description
`accrue` in `mainnet/contracts/vault/v0-vault-stx.clar` (and every other vault: `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`, `v0-vault-usdc.clar`) is structured as: [1](#0-0) 

```clarity
(define-public (accrue)
  (let ((states (var-get pause-states)) (idx (var-get index)) (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index)) (nliq (next-liquidity-index)) ...
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            ...
            (if (> treasury-lp u0) (try! (ft-mint? zft treasury-lp .dao-treasury)) false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq))) (var-set last-update stacks-block-time) false)
            (ok { index: next, lindex: nliq })))))
```

`next-index`/`next-liquidity-index` derive the multiplier from `(- stacks-block-time (var-get last-update))`, and `last-update` is only bumped in the un-paused branch: [2](#0-1) 

`system-borrow` and `system-repay` call `accrue` first, then immediately act on `index`/`principal-scaled`/`total-borrowed` regardless of whether real accrual happened: [3](#0-2) [4](#0-3) 

Because `accrue` never reverts when `pause-states.accrue` is true, `deposit`/`redeem`/`system-borrow`/`system-repay` continue to execute (mint/burn shares, move underlying) as if nothing is wrong, treating a "paused" state identically to a successful accrual. The reserve-fee mint to `.dao-treasury` (`treasury-lp`) only happens on the branch that actually recomputes `next`/`nliq`; while `accrue` is paused, that mint path is skipped entirely for every block that elapses. When the pause is later lifted, the very next call recomputes `next-index` using `(- stacks-block-time last-update)`, where `last-update` still holds the pre-pause timestamp. This makes the accrual jump discontinuously to reflect the *entire* elapsed interval (pre-pause + paused + post-pause) in a single step, and the fee split (`reserve-inc`/`treasury-lp`) computed off that jump is a function of `total-supply` and `total-assets-preview` **at the moment of the first post-pause transaction**, not distributed per-block as designed. This lets whoever triggers that first post-pause `deposit`/`redeem`/`system-borrow` transaction manipulate `total-supply`/`total-assets-preview` (e.g., via a large deposit or redeem in the same call, since deposit/redeem also invoke `accrue` first) immediately before the catch-up accrual fires, skewing `treasury-lp = mul-div-down(reserve-inc, total-supply, total-assets-preview - reserve-inc)` and reducing the DAO treasury's minted share versus what it would have received had accrual (and its per-block reserve mint) run normally throughout the pause window.

### Impact Explanation
This is a single-transaction, single-block manipulation: an actor calls `deposit` or `redeem` on the vault as soon as (or in the same block as) an accrual-pause is lifted, altering `total-supply`/`total-assets-preview` immediately before the catch-up `treasury-lp` mint is computed inside that same `accrue` invocation, permanently reducing the protocol reserve's (DAO treasury's) share of interest for the entire paused interval. That is a permanent loss of unclaimed yield/royalties for the protocol treasury — High impact per the listed categories.

### Likelihood Explanation
Requires an accrue-pause/unpause cycle (a normal operational/emergency lever already present in the contract) plus a single well-timed transaction from any user right after unpause; no privileged access or DAO compromise is needed to trigger the skew, only to toggle the pause (which is a routine DAO operation already built into the contract, not a compromise).

### Recommendation
Do not let `accrue` silently pass through when paused: either (a) revert every state-mutating caller (`deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan`) when `pause-states.accrue` is true instead of proceeding on the stale snapshot, or (b) still advance `last-update` to `stacks-block-time` while paused (freezing the index at pause time rather than deferring the whole interval's growth to be applied in one lump, manipulable step) so that no interest — and no fee share — is retroactively computed over a window that can be front-run.

### Proof of Concept
1. DAO calls `set-pause-liquidation`-style toggle (or the vault-level pause setter) to set `pause-states.accrue = true` on `vault-stx`.
2. Time passes across N blocks; `last-update` is never advanced because the paused branch of `accrue` (line 838-843) always short-circuits before reaching the `var-set last-update` line.
3. DAO unpauses `accrue` (`pause-states.accrue = false`).
4. In the very next block, an attacker calls `deposit` with a large amount right as unpause takes effect; `deposit` internally calls `(try! (accrue))`, which now computes `next-index`/`next-liquidity-index` off the full multi-block time delta and computes `reserve-inc`/`treasury-lp` using `total-supply`/`total-assets-preview` values that already reflect the attacker's own just-added deposit, skewing the treasury's minted share downward for interest that accrued over the entire paused window.
5. `dao-treasury` receives a smaller `zft` mint than it would have received had per-block accrual (and its reserve mint) executed normally throughout the paused interval — the difference is permanently lost.
