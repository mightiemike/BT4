### Title
Residual TRX in `TRANSACTION_FEE_POOL` can become permanently stranded due to integer-division rounding, with no recovery mechanism - (File: framework/src/main/java/org/tron/core/db/Manager.java)

### Summary
The `TRANSACTION_FEE_POOL` accounting mechanism in java-tron accumulates real, user-paid transaction fees and distributes them to block-producing witnesses over a fixed period using integer floor-division. Because the payout amount is computed as `floorDiv(pool, PERIOD)` each block, once the pool balance falls below `TRANSACTION_FEE_POOL_PERIOD`, the computed payout becomes `0` and the remaining balance is never distributed again unless new fees happen to top up the pool. There is no sweep/reclaim function for this residual balance, mirroring the reported `BribeRewarder` class of bug: real funds set aside for reward distribution become permanently unutilized/stranded because of rounding, with no recovery path.

### Finding Description
User transaction fees are deposited into a shared reward pool via `DynamicPropertiesStore.addTransactionFeePool()`, called from the resource-consumption path (e.g. `ResourceProcessor.consumeFeeForBandwidth`), which is reachable by any ordinary broadcast transaction that consumes bandwidth fees: [1](#0-0) 

The pool balance is stored/read through simple getters/setters with no overflow or "remainder" tracking beyond the raw long value: [2](#0-1) 

Each block, `Manager.payReward()` distributes a fraction of the pool to the block's witness using floor division by a fixed period constant, then persists the pool minus that (rounded-down) payout: [3](#0-2) 

Because `floorDiv(pool, TRANSACTION_FEE_POOL_PERIOD)` truncates toward zero, once `pool < TRANSACTION_FEE_POOL_PERIOD` the payout is `0` every subsequent block. The remaining balance sits in the `TRANSACTION_FEE_POOL` dynamic property forever — it is never paid to any witness, never refunded to fee payers, and there is no actuator, admin function, or sweep mechanism anywhere in the codebase to withdraw or reclaim it (searches for `addTransactionFeePool` show it is only ever incremented, and the pool is only ever decremented by the rounded-down per-block payout in `payReward`). This is structurally identical to the reported issue: funds set aside for reward distribution get "stuck" purely due to integer-division rounding, and the protocol provides no way to sweep the residue.

### Impact Explanation
This causes a slow, permanent loss/lock of real TRX collected as transaction fees from ordinary users. Although any single rounding remainder is small, it accumulates across the network's entire lifetime of fee collection and is never reclaimable by anyone (not burned, not distributed, not withdrawable) — a genuine, unprivileged, protocol-level accounting leak reachable purely through everyday transaction fee payments (no special privilege required to trigger fee accrual). It differs from the intended design that all collected fees should eventually reach witnesses as rewards.

### Likelihood Explanation
High likelihood of continuously triggering: every ordinary transaction that pays a bandwidth fee funds the pool via `consumeFeeForBandwidth`, and every block invokes `payReward`, which performs the floor-division payout. Whenever the pool balance is small relative to `TRANSACTION_FEE_POOL_PERIOD` (e.g., during low network activity, right after a network's genesis, or any period without sufficient fee inflow), the rounding-to-zero condition is trivially reached and persists indefinitely with no external actor needed.

### Recommendation
- Track and carry forward rounding remainders instead of discarding them (e.g., compute `payout = pool / PERIOD`, but only subtract `payout`, and once `pool` stays below `PERIOD` for an extended time, either distribute the whole remaining balance in one go, or accumulate the "carry" precisely so it converges to zero).
- Alternatively, add explicit handling so that when `pool > 0 && pool < PERIOD`, the entire remaining balance is paid out (e.g., using a ceiling-based or "flush on threshold" strategy) rather than always flooring to zero.
- Add invariant tests verifying that, given no further fee inflow, the `TRANSACTION_FEE_POOL` balance eventually reaches exactly zero rather than converging to a nonzero fixed remainder.

### Proof of Concept
1. Set `supportTransactionFeePool()` to true and let `TRANSACTION_FEE_POOL_PERIOD` be its configured constant value (see `common/src/main/java/org/tron/core/Constant.java`).
2. Cause `TRANSACTION_FEE_POOL` to reach a value `V` such that `0 < V < TRANSACTION_FEE_POOL_PERIOD` (achievable naturally after a period of low fee inflow, or by directly funding it via ordinary fee-paying transactions until inflow stops).
3. Observe that in `Manager.payReward()`, `floorDiv(V, TRANSACTION_FEE_POOL_PERIOD)` evaluates to `0` every block: [4](#0-3) 
4. `saveTransactionFeePool(getTransactionFeePool() - transactionFeeReward)` re-saves the same value `V` (since `transactionFeeReward == 0`), so the pool never decreases and is never distributed to any witness, and no function in the codebase exists to withdraw or reclaim `V`.

  protected boolean consumeFeeForBandwidth(AccountCapsule accountCapsule, long fee) {
    try {
      long latestOperationTime = dynamicPropertiesStore.getLatestBlockHeaderTimestamp();
      accountCapsule.setLatestOperationTime(latestOperationTime);
      Commons.adjustBalance(accountStore, accountCapsule, -fee,
          this.disableJavaLangMath());
      if (dynamicPropertiesStore.supportTransactionFeePool()) {
        dynamicPropertiesStore.addTransactionFeePool(fee);
      } else if (dynamicPropertiesStore.supportBlackHoleOptimization()) {
        dynamicPropertiesStore.burnTrx(fee);
      } else {
        Commons.adjustBalance(accountStore, accountStore.getBlackhole().createDbKey(), +fee,
            this.disableJavaLangMath());
      }

      return true;
    } catch (BalanceInsufficientException e) {
      return false;
    }
  }

  public void addTransactionFeePool(long amount) {
    if (amount <= 0) {
      return;
    }
    amount += getTransactionFeePool();
    saveTransactionFeePool(amount);
  }

  public void saveTransactionFeePool(long value) {
    this.put(TRANSACTION_FEE_POOL,
        new BytesCapsule(ByteArray.fromLong(value)));
  }

  public long getTransactionFeePool() {
    return Optional.ofNullable(getUnchecked(TRANSACTION_FEE_POOL))
        .map(BytesCapsule::getData)
        .map(ByteArray::toLong)
        .orElseThrow(
            () -> new IllegalArgumentException("not found TRANSACTION_FEE_POOL"));
  }

  private void payReward(BlockCapsule block) {
    WitnessCapsule witnessCapsule =
        chainBaseManager.getWitnessStore().getUnchecked(block.getInstance().getBlockHeader()
            .getRawData().getWitnessAddress().toByteArray());
    if (getDynamicPropertiesStore().allowChangeDelegation()) {
      mortgageService.payBlockReward(witnessCapsule.getAddress().toByteArray(),
          getDynamicPropertiesStore().getWitnessPayPerBlock());
      mortgageService.payStandbyWitness();

      if (chainBaseManager.getDynamicPropertiesStore().supportTransactionFeePool()) {
        long transactionFeeReward = floorDiv(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool(),
                Constant.TRANSACTION_FEE_POOL_PERIOD,
            chainBaseManager.getDynamicPropertiesStore().disableJavaLangMath());
        mortgageService.payTransactionFeeReward(witnessCapsule.getAddress().toByteArray(),
            transactionFeeReward);
        chainBaseManager.getDynamicPropertiesStore().saveTransactionFeePool(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool()
                - transactionFeeReward);
      }
    } else {
      byte[] witness = block.getWitnessAddress().toByteArray();
      AccountCapsule account = getAccountStore().get(witness);
      account.setAllowance(account.getAllowance()
          + chainBaseManager.getDynamicPropertiesStore().getWitnessPayPerBlock());

      if (chainBaseManager.getDynamicPropertiesStore().supportTransactionFeePool()) {
        long transactionFeeReward = floorDiv(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool(),
                Constant.TRANSACTION_FEE_POOL_PERIOD,
            chainBaseManager.getDynamicPropertiesStore().disableJavaLangMath());
        account.setAllowance(account.getAllowance() + transactionFeeReward);
        chainBaseManager.getDynamicPropertiesStore().saveTransactionFeePool(
            chainBaseManager.getDynamicPropertiesStore().getTransactionFeePool()
                - transactionFeeReward);
      }

      getAccountStore().put(account.createDbKey(), account);
    }
  }
