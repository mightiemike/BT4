This confirms the concrete Push Chain analog: the gas-abstraction swap path (`ExecuteInboundGas`, `ExecuteInboundGasAndPayload`, `applyGasRefund`) derives `minPCOut` from a **live spot-price read of a single on-chain Uniswap V3 `QuoterV2` pool** (`GetSwapQuote` in [1](#0-0) ), then immediately executes the swap in the same transaction with only a fixed 5% slippage bound ( [2](#0-1) ). This is the same bug class as the Curve report — a price value is trusted for economic accounting without any oracle-quality control (whitelist, TWAP, deviation checks, multi-source aggregation) — except here it's a spot-price AMM read instead of a user-deployed oracle contract.

### Title
Gas-abstraction and gas-refund swaps trust an unguarded single-block spot-price quote from the internal QuoterV2 pool, allowing flash-loan/sandwich price manipulation to drain WPC/PRC20 value - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
`GetSwapQuote` reads `QuoterV2.quoteExactInputSingle` on the module's own AMM pool for the PRC20/WPC pair, and the caller applies a flat 5% slippage tolerance (`minPCOut = quote * 95/100`) before immediately calling `depositPRC20WithAutoSwap` in the same execution flow [3](#0-2) . This pattern is reused for `GAS_AND_PAYLOAD` inbounds ( [4](#0-3) ) and for excess-gas refunds on outbound completion ( [5](#0-4) ). None of these paths use a time-weighted average price, a deviation check against a second source, or any oracle-quality gate — they take whatever price the pool reports at the moment of the call.

### Finding Description
An unprivileged user fully controls the trigger and timing of these swaps: submitting a `TxType_GAS` or `TxType_GAS_AND_PAYLOAD` inbound (via the gateway on any supported external chain) causes Universal Validators to vote it in, and once quorum is reached, `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` runs `GetSwapQuote` → `CallPRC20DepositAutoSwap` deterministically inside the same Push Chain block that finalizes the ballot [6](#0-5) . Because Push Chain is an EVM-compatible chain, an attacker can compose, within a single block or adjacent blocks:
1. A large swap against the same QuoterV2 pool to push the PRC20/WPC spot price to an extreme.
2. Their crosschain gas-abstraction inbound, whose `minPCOut` is computed from that manipulated spot price with only 5% slippage protection.
3. A reversing trade to restore the pool price and capture the extracted WPC/PC value.

This is structurally identical to the reported bug class: a price-determining component (there, a user-supplied oracle contract; here, a single-block AMM spot quote) is trusted for fund-moving decisions without a whitelist, staleness/deviation check, or manipulation resistance (TWAP). The `x/uregistry` chain/token config whitelist (admin-gated `MsgAddTokenConfig`/`MsgAddChainConfig`, see [7](#0-6) ) and the `ChainMeta` gas-price oracle (validator-vote median aggregation, see [8](#0-7) ) both show the project's own pattern for guarding against exactly this class of manipulation — but the swap-quote path bypasses both mechanisms entirely.

### Impact Explanation
A successful manipulation lets the attacker receive more PRC20/PC value out of the autoswap or gas refund than their deposited collateral is actually worth, at the expense of the module account's / protocol's liquidity (the `UNIVERSAL_CORE` handler and its pools), i.e. unauthorized value extraction / drain of protocol-controlled funds through the mint/deposit + autoswap flow — squarely in the "stealing/draining ... protocol-controlled funds" allowed-impact category. Because the deposit and swap execute atomically as part of already-finalized, honest-validator-approved inbound processing, no privileged actor or malicious validator/relayer is required.

### Likelihood Explanation
Likelihood depends on the actual liquidity depth of the QuoterV2 pool(s) backing PRC20/WPC pairs at the time of exploitation; a thin pool makes single-block manipulation of spot price by 5%+ inexpensive. Given Push Chain is EVM-based, standard flash-loan/sandwich techniques used against thin AMM pools apply directly, and the trigger (submitting a gas-abstraction inbound) is fully permissionless and requires no elevated privilege.

### Recommendation
Do not rely solely on a single-block QuoterV2 spot quote for `minPCOut`. Use a manipulation-resistant price source (TWAP over a sufficient window, or cross-checked against `ChainMeta`-style validator-aggregated pricing), enforce a maximum allowed deviation from a reference/oracle price before executing the swap, and/or cap per-block swap volume for the auto-swap path so a single inbound cannot move the pool materially within the same block it is priced.

### Proof of Concept
1. Attacker identifies a PRC20/WPC QuoterV2 pool with limited depth used by `GetUniversalCoreQuoterAddress`/`GetSwapQuote`.
2. Attacker (via a flash loan or pre-funded EOA) executes a large swap against that pool on Push Chain's DEX to skew the spot price of PRC20 relative to WPC.
3. In the same block, attacker submits (or has already pending) a `TxType_GAS` or `TxType_GAS_AND_PAYLOAD` inbound whose `AssetAddr` maps to the manipulated PRC20; once UV quorum votes it in, `ExecuteInboundGas` calls `GetSwapQuote` against the now-skewed pool and computes `minPCOut` from that skewed quote [9](#0-8) .
4. `CallPRC20DepositAutoSwap` executes the deposit-and-swap using the manipulated `minPCOut`, letting the attacker's UEA receive an inflated amount of WPC/PC relative to the true fair value of the deposited PRC20.
5. Attacker reverses the initial swap to restore the pool price, pocketing the difference extracted from protocol liquidity.

func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,

	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
