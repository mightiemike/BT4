## Finding: Starknet OS `replace_class` syscall implementation omits declared-class and Cairo version checks that Blockifier enforces

### Title
Starknet OS `execute_replace_class` skips declared-class and Cairo-version validation performed by Blockifier, causing state/commitment divergence - (`File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The gfs2 CVE is a "flag flip without reconciling downstream state" bug class: a flag changes what representation is valid, but the code path doesn't enforce/validate consistency, so two representations get mixed. In this sequencer, the Starknet OS's Cairo implementation of the `replace_class` syscall omits validation checks that the Rust Blockifier execution engine enforces, so the two "representations" of block execution (Blockifier's transaction execution vs. the OS's independent re-execution used for proving/verification) can diverge for the exact same transaction.

### Finding Description
In Blockifier, `replace_class` is guarded by two checks before writing the new class hash to state: [1](#0-0) 
1. The target class must be declared (`self.state.get_compiled_class(class_hash)?` fails with `UndeclaredClassHash` otherwise).
2. The target class must be Cairo1 (`is_cairo1(&compiled_class)`), otherwise it errors with `ForbiddenClassReplacement`/"Cannot replace V1 class hash with V0 class hash", confirmed by the test: [2](#0-1) 

In contrast, the Starknet OS's Cairo implementation of the same syscall (`execute_replace_class` in `syscall_impls.cairo`, used for the OS's independent re-execution of the block, e.g., for proving) writes the new class hash to `contract_state_changes` unconditionally, with an explicit TODO acknowledging the missing check: [3](#0-2) 

Specifically, line 902's `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` shows that neither the "class must be declared" check nor the "class must be Cairo1 (cannot downgrade to V0)" check exists in the OS's syscall handling, unlike the equivalent Blockifier code path.

### Impact Explanation
Because the Starknet OS is the component that independently re-executes transactions to compute/verify the state commitment and block hash (see `state_update`/`squash_state_changes_and_maybe_allocate_aliases` in `state.cairo`, which consumes `contract_state_changes` produced by syscall execution), a discrepancy between what Blockifier accepts/rejects and what the OS accepts/rejects for the same transaction directly translates into a state root / commitment divergence: [4](#0-3) 

If a transaction calls `replace_class` with an undeclared class hash (or a Cairo0 class hash from a Cairo1 contract), Blockifier will reject/revert the transaction with `UndeclaredClassHash`/`ForbiddenClassReplacement`, while the OS's re-execution would accept it and commit the new (potentially undeclared/invalid) class hash into the contract state tree. This is a wrong-committed-root / honest-node-divergence class bug: the block actually built and agreed upon by the sequencer (via Blockifier) cannot be correctly re-derived/verified by the Starknet OS, breaking the soundness of OS-based re-execution and proof generation for that block, and potentially allowing state corruption where a contract's class hash points to an undeclared/incompatible class.

### Likelihood Explanation
This is trivially reachable by any account or contract deployer: a Cairo1 contract simply invokes the `replace_class` syscall with an arbitrary (undeclared, or Cairo0) class hash as calldata. No special privileges, staking, or operator/prover collusion needed — it's a single, ordinary transaction from any account.

### Recommendation
Add the same two validations to `execute_replace_class` in `syscall_impls.cairo` that exist in `syscall_base.rs::replace_class`:
1. Verify the target `class_hash` corresponds to a declared class (fail/abort the syscall otherwise, matching Blockifier's `UndeclaredClassHash` error).
2. Verify the target class is Cairo1 (reject replacement with a Cairo0 class hash, matching Blockifier's `ForbiddenClassReplacement`).

This keeps the OS's re-execution semantics in lockstep with Blockifier's, removing the possibility of commitment/state divergence for `replace_class` calls.

### Proof of Concept
1. Deploy a Cairo1 contract exposing an entry point that calls the `replace_class` syscall with a class hash that has never been declared (or with a valid, but Cairo0, class hash).
2. Submit an `invoke` transaction calling that entry point.
3. In Blockifier (used by the batcher to build the block), the syscall handler `replace_class` in `crates/blockifier/src/execution/syscalls/syscall_base.rs` calls `state.get_compiled_class(class_hash)` which fails for an undeclared hash (or `is_cairo1` check fails for Cairo0), causing the transaction to revert.
4. When the Starknet OS independently re-executes the same transaction (e.g., to build state commitments/proofs) via `execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`, no such check is performed — the OS unconditionally records the new (undeclared/Cairo0) class hash into `contract_state_changes`, which flows into `state_update`/`compute_contract_state_commitment` in `state.cairo`.
5. The state diff/commitment computed by the OS for this transaction differs from the one actually produced (and accepted) during block building by Blockifier, demonstrating the divergence.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,

    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
