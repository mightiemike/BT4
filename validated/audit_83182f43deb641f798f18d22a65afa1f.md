### Title
Admin OAuth HMAC validation lacks the repeated-parameter protection present in App Proxy validation, causing unhandled `SafeCompareError` (DoS) or HMAC-canonicalization mismatch - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
The reported bug class is a pricing-calculation inconsistency between two structurally parallel code paths (`register` vs `renew`) where one path applies a security-relevant protection (discount handling) that the other omits. The closest unprivileged analog in `shopify-app-js` is in `normalizeQuery()`/`validateHmac()` in `packages/apps/shopify-api/lib/utils/hmac-validator.ts`: the `appProxy` signator path explicitly rejects repeated/duplicated security query parameters (`hmac`, `shop`, `signature`, `timestamp`), while the `admin` signator path — used for OAuth begin/callback and exposed directly as `shopify.utils.validateHmac()` — has no equivalent protection.

### Finding Description
`normalizeQuery()` only enforces the `APP_PROXY_SINGLE_VALUE_PARAMS` uniqueness check when `signator === 'appProxy'`: [1](#0-0) 

For a plain object query (not `URLSearchParams`), the appProxy branch throws if `hmac`/`shop`/`signature`/`timestamp` is an array (duplicated), but the `admin` branch performs no such check at all — the query is returned unchanged: [2](#0-1) 

This is directly analogous to the Beranames bug: two call sites of essentially the same validation routine (`register`/`whitelistRegister` vs `renew`; here, `appProxy` vs `admin` signator) apply different levels of rigor to the same kind of input, where one path was hardened (per the CHANGELOG entry "Harden app proxy authentication by rejecting repeated security parameters") and the other was not: [3](#0-2) 

`shopify.utils.validateHmac()` is a public utility documented for direct use by app developers processing OAuth-style requests via `req.query`: [4](#0-3) 

In Node/Express, a duplicated query parameter (e.g., `?hmac=a&hmac=b`) is commonly parsed into an array by the query-string parser. Since the `admin` branch of `normalizeQuery` does not reject arrays, `normalizedQuery.hmac` can end up as an array while `localHmac` (computed in `generateLocalHmac`) is always a string: [5](#0-4) 

The final comparison calls `safeCompare(hmac as string, localHmac)`, where `hmac` is really an array object and `localHmac` a string. `safeCompare` explicitly throws `SafeCompareError` when `typeof strA !== typeof strB`, rather than returning `false`: [6](#0-5) 

Unlike the `appProxy` path, which wraps `validateHmac` calls in a `try/catch` and returns a controlled 400 response: [7](#0-6) 

the `admin`/OAuth callback path (`validQuery` in `oauth.ts`) calls `validateHmac(config)(query)` with no try/catch around that specific call: [8](#0-7) 

So a raw/uncaught `SafeCompareError` can propagate out of `shopify.utils.validateHmac()` (and out of `shopify.auth.callback()` if the surrounding wrapper does not intercept `ShopifyError` subtypes generically) for a single anonymous, unauthenticated HTTP request that merely repeats a query parameter — a scenario the audited report class ("existing rigor applied inconsistently across otherwise-parallel code paths") is meant to catch.

### Impact Explanation
The impact is availability-related rather than confidentiality/integrity: an anonymous attacker sending a single crafted HTTP request with a duplicated `hmac`/`shop`/`timestamp` query parameter to an OAuth begin/callback endpoint (or any handler that calls `shopify.utils.validateHmac(req.query)` directly, as documented) can trigger an uncaught `SafeCompareError` inside the authentication/validation path instead of a graceful `false`/400 rejection. Depending on how the surrounding framework/handler processes rejected promises, this can produce unhandled exceptions in the auth handler (a DoS-class effect on that handler), which is one of the accepted analog outcomes for this bug class.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a query-string parser that turns duplicate keys into arrays (default for Express/`qs`), and (b) a caller using the `admin` signator path (default) without its own defensive try/catch — which is exactly how `shopify.utils.validateHmac()` is documented to be used directly by app developers, and how the low-level OAuth `callback()`/`validQuery()` invokes it without a local try/catch. No secrets, privileged access, or MITM position are needed — a single unauthenticated request with a duplicated query parameter is sufficient to reach the vulnerable code path.

### Recommendation
Apply the same repeated-parameter rejection used for the `appProxy` signator to the `admin` signator inside `normalizeQuery()` (both for the `URLSearchParams` branch and the plain-object/array branch), so that duplicated `hmac`, `shop`, `state`, and `timestamp` parameters are rejected uniformly regardless of signator type, consistent with how the `appProxy` path was hardened in the referenced CHANGELOG fix. Additionally, ensure `validateHmac`'s type-mismatch failure path in `safeCompare` is caught and normalized to `false`/a controlled rejection wherever `validateHmac` is invoked (including the OAuth `callback()`/`validQuery()` path), rather than allowing a raw `SafeCompareError` to propagate.

### Proof of Concept
Conceptual PoC (mirrors the appProxy repeated-parameter tests already in the suite, but for the unprotected `admin` signator): [9](#0-8) 
1. Send `GET /auth/callback?shop=test-shop.myshopify.io&state=<validNonce>&timestamp=<ts>&code=<code>&hmac=<validHmac>&hmac=injected` (or call `shopify.utils.validateHmac(req.query)` directly with an Express-parsed `req.query` where `hmac` is `['validHmac','injected']`).
2. In `normalizeQuery()` (admin branch), no array/uniqueness check is performed, so `normalizedQuery.hmac` remains the array `['validHmac','injected']`. [2](#0-1) 
3. `validateHmac` proceeds to `safeCompare(hmac as string, localHmac)` with `hmac` actually being an array and `localHmac` a string, causing `typeof strA !== typeof strB` and throwing `SafeCompareError` instead of returning `false`. [6](#0-5) 

**Uncertainty note:** I was not able to fully verify, within the indexed code, how every downstream consumer (e.g., `shopify-app-express`'s OAuth begin/callback routes) wraps `shopify.auth.callback()`/`validQuery()` calls in try/catch, so I cannot confirm with certainty whether the `SafeCompareError` always surfaces as an unhandled exception versus being caught generically as a `ShopifyError` somewhere higher up the stack in every adapter package. A Devin session with full repository access would be needed to trace every call site and confirm the exact blast radius (unhandled promise rejection vs. generic 500 handling) in each framework adapter (`shopify-app-express`, `shopify-app-remix`, `shopify-app-react-router`).

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}

# shopify.utils.validateHmac

Shopify requests include an `hmac` query argument (or, in the case of app proxy requests, a `signature` query argument). This method validates those requests to ensure that the `hmac` value was signed by Shopify and not spoofed.

## Example

For OAuth requests:

```ts
const isValid = await shopify.utils.validateHmac(req.query);
```

For App Proxy requests:

```ts
const isValid = await shopify.utils.validateHmac(req.query, {
  signator: 'appProxy',
});

export const safeCompare: SafeCompare = (strA, strB) => {
  if (typeof strA === typeof strB) {
    const enc = new TextEncoder();
    const buffA = enc.encode(JSON.stringify(strA));
    const buffB = enc.encode(JSON.stringify(strB));

    if (buffA.length === buffB.length) {
      return timingSafeEqual(buffA, buffB);
    }
  } else {
    throw new ShopifyErrors.SafeCompareError(
      `Mismatched data types provided: ${typeof strA} and ${typeof strB}`,
    );
  }
  return false;
};

async function validateAppProxyHmac(
  params: BasicParams,
  url: URL,
): Promise<boolean> {
  const {api, logger} = params;

  try {
    let searchParams = new URLSearchParams(url.search);
    if (!searchParams.get('index')) {
      searchParams.delete('index');
    }

    let isValid = await api.utils.validateHmac(searchParams, {
      signator: 'appProxy',
    });

    if (!isValid) {
      const cleanPath = url.pathname
        .replace(/^\//, '')
        .replace(/\/$/, '')
        .replaceAll('/', '.');
      const data = `routes%2F${cleanPath}`;

      searchParams = new URLSearchParams(
        `?_data=${data}&${searchParams.toString().replace(/^\?/, '')}`,
      );

      isValid = await api.utils.validateHmac(searchParams, {
        signator: 'appProxy',
      });

      if (!isValid) {
        const searchParams = new URLSearchParams(
          `?_data=${data}._index&${url.search.replace(/^\?/, '')}`,
        );

        isValid = await api.utils.validateHmac(searchParams, {
          signator: 'appProxy',
        });
      }
    }

    return isValid;
  } catch (error) {
    const shop = url.searchParams.get('shop')!;
    logger.info(error.message, {shop});
    throw new Response(undefined, {status: 400, statusText: 'Bad Request'});
  }
}
