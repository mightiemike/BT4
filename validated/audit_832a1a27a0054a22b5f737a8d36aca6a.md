### Title
`accept_new_txs` transaction-intake kill switch is enforced only in the HTTP server, not in the Gateway component itself — ([File: crates/apollo_gateway/src/gateway.rs])

### Summary
The sequencer exposes an operational kill switch, `HttpServerDynamicConfig.accept_new_txs`, that operators use to stop the node from accepting new transactions (e.g., during an incident, maintenance, or spam attack). This control is checked exclusively in the HTTP server request handlers [1](#0-0) [2](#0-1) . The actual transaction-intake logic, `GenericGateway::add_tx` / `add_tx_inner`, never checks this flag [3](#0-2) . This mirrors the reported baserCMS bug class exactly: an acceptance/business-logic gate enforced in the "front-end" flow but missing from an alternate entry point into the same underlying accept function.

### Finding Description
`accept_new_txs` is a dynamic config field pushed to the HTTP server and consulted only by the two axum handlers `add_rpc_tx` and `add_tx`, via `check_new_transactions_are_allowed` [1](#0-0) [4](#0-3) [2](#0-1) . On success these handlers forward the transaction to `Gateway` via `GatewayClient::add_tx` [5](#0-4) .

However, `Gateway`/`GenericGateway::add_tx` — the component that actually performs stateless/stateful validation and forwards the transaction to the mempool — contains no reference to `accept_new_txs` at all [3](#0-2) . The gateway is reachable through multiple paths that do not go through the HTTP server:

1. **Remote Gateway component endpoint**: in distributed deployments the Gateway component itself listens on its own network port via `RemoteGatewayServer`/`RemoteComponentServer` while `http_server` is `Disabled` on that node [6](#0-5) . Any caller that can reach `GatewayRequest::AddTransaction` over this remote server bypasses the HTTP server's gate entirely, because the request handler goes straight into `Gateway::add_tx` [7](#0-6) .
2. **P2P-propagated transactions**: transactions received from other sequencers over the mempool P2P network are fed back into the local `Gateway::add_tx` with `p2p_message_metadata` set (per the documented submission flow, "Runner->>GW_B: add_tx(GatewayInput)") [8](#0-7) , again never touching the HTTP server's `accept_new_txs` check.

In both cases, the operator's decision to stop accepting new transactions (set via the HTTP server's dynamic config) has no effect: the gateway will still run stateless/stateful validation and enqueue the transaction into the mempool, from where it proceeds to normal block-building.

### Impact Explanation
This is a business-logic/access-control bypass (CWE-285), analogous to the baserCMS finding: an administrative "stop accepting submissions" control that is bypassable via an alternate entry point into the same accept function. In a running sequencer, this means:
- During an announced spam attack, DoS incident, or planned maintenance window, an operator disabling ingestion via `accept_new_txs` cannot actually halt the flow of new transactions if the Gateway is reachable directly (distributed topology) or via P2P re-propagation from a peer sequencer.
- This does not itself corrupt state or steal funds, but it defeats an operational safety control intended to protect the mempool/gateway from overload or abuse, undermining the node's ability to reliably manage/confirm transactions during the exact scenarios the flag exists to mitigate.

### Likelihood Explanation
Likelihood is high in any distributed/hybrid deployment topology where the Gateway component's remote server is enabled independently of the HTTP server, which is a shipped deployment configuration in this repo [6](#0-5) . No special privileges are needed beyond being able to reach the gateway's remote endpoint or being a P2P peer submitting transactions that get re-gossiped — both are within reach of an ordinary, unprivileged transaction sender/peer as scoped by this review.

### Recommendation
Move the `accept_new_txs` check (or an equivalent dynamic-config gate) into `GenericGateway::add_tx`/`add_tx_inner` itself (or into the shared `GatewayRequest::AddTransaction` handler in `crates/apollo_gateway/src/communication.rs`) so it is enforced regardless of whether the request originates from the HTTP server, a remote Gateway RPC call, or P2P propagation. The HTTP server's own check can remain as a fast-path rejection, but the authoritative check belongs in the Gateway component.

### Proof of Concept
1. Deploy the Gateway component in a distributed topology per `crates/apollo_deployments/resources/services/distributed/gateway.json`, with the Gateway's `remote_server_config` bound to `0.0.0.0` and `http_server` disabled.
2. Have the node operator set `accept_new_txs = false` via the HTTP server's dynamic config (on whichever node hosts the HTTP server).
3. Send a `GatewayRequest::AddTransaction` directly to the Gateway's remote server port (bypassing the HTTP server entirely).
4. Observe that `Gateway::add_tx` → `add_tx_inner` proceeds with stateless/stateful validation and forwards the transaction to the mempool [9](#0-8) , with no check of `accept_new_txs`, confirming the transaction is accepted despite the operator's intent to halt intake.

async fn add_tx_inner(
    app_state: AppState,
    headers: HeaderMap,
    tx: RpcTransaction,
) -> HttpServerResult<Json<GatewayOutput>> {
    debug!("Received transaction: {tx:?}");
    let gateway_input: GatewayInput = GatewayInput { rpc_tx: tx, message_metadata: None };
    // Wrap the gateway client interaction with a tokio::spawn as it is NOT cancel-safe.
    // Even if the current task is cancelled, e.g., when a request is dropped while still being
    // processed, the inner task will continue to run.
    let region = headers
        .get(CLIENT_REGION_HEADER)
        .and_then(|region| region.to_str().ok())
        .unwrap_or("N/A")
        .to_string();
    let add_tx_result = tokio::spawn(
        async move {
            let add_tx_result = app_state.gateway_client.add_tx(gateway_input).await.map_err(|e| {
                debug!("Error while adding transaction: {}", e);
                HttpServerError::from(Box::new(e))
            });
            record_added_transactions(&add_tx_result, &region);
            add_tx_result
        }
        .instrument(tracing::Span::current()),
    )
    .await
    .expect("Should be able to get add_tx result");

    Ok(Json(add_tx_result?))
}

    pub async fn add_tx(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        debug!("Processing tx: {:?}", &tx);
        let tx_signature = tx.signature().clone();
        let is_p2p = p2p_message_metadata.is_some();

        let start_time = std::time::Instant::now();
        let ret = self.add_tx_inner(tx, p2p_message_metadata).await;
        let elapsed = start_time.elapsed().as_secs_f64();

        debug!(
            "Processed tx with signature: {:?}. duration: {elapsed} sec, ret: {ret:?}, is_p2p: \
             {is_p2p}",
            &tx_signature,
        );

        ret
    }

    async fn add_tx_inner(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        let mut metric_counters = GatewayMetricHandle::new(&tx, &p2p_message_metadata);
        metric_counters.count_transaction_received();
        if let RpcTransaction::Invoke(RpcInvokeTransaction::V3(ref inv)) = tx {
            if !inv.proof_facts.is_empty() {
                metric_counters.count_private_transaction_received();
            }
        }
        let is_p2p = p2p_message_metadata.is_some();

        if let RpcTransaction::Declare(ref declare_tx) = tx {
            if let Err(e) = self.check_declare_permissions(declare_tx) {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        }

        // Perform stateless validations.
        self.stateless_tx_validator.validate(&tx)?;

        let tx_signature = tx.signature().clone();

        // Declare conversions overload the compiler component's CPU and memory. Reject declares if
        // there are too many declares compiling in parallel. The permit is held only across
        // compilation and released before stateful validation.
        let compilation_permit = if matches!(tx, RpcTransaction::Declare(_)) {
            Some(self.declare_compilation_semaphore.try_acquire().map_err(|_| {
                let error = StarknetError::too_many_concurrent_declare_compilations();
                metric_counters.record_add_tx_failure(&error);
                error
            })?)
        } else {
            None
        };

        let (internal_tx, executable_tx, proof_data) =
            self.convert_rpc_tx_to_internal_and_executable_txs(tx, &tx_signature).await?;
        drop(compilation_permit);

        let mut stateful_transaction_validator = self
            .stateful_tx_validator_factory
            .instantiate_validator(self.config.dynamic_config.native_classes_whitelist.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let nonce = stateful_transaction_validator
            .extract_state_nonce_and_run_validations(&executable_tx, self.mempool_client.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let proof_archive_handle = self
            .store_proof_and_spawn_archiving(proof_data, internal_tx.tx_hash, is_p2p)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let gateway_output = create_gateway_output(&internal_tx);

        let add_tx_args = AddTransactionArgsWrapper {
            args: AddTransactionArgs::new(internal_tx, nonce),
            p2p_message_metadata,
        };

        // Await as late as possible for proof archiving before sending the transaction to the
        // mempool.
        Self::await_proof_archiving(proof_archive_handle)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let mempool_client_result = self.mempool_client.add_tx(add_tx_args).await;
        match mempool_client_result_to_deprecated_gw_result(&tx_signature, mempool_client_result) {
            Ok(()) => {}
            Err(e) => {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        };

        metric_counters.transaction_sent_to_mempool();

        Ok(gateway_output)
    }

impl ComponentRequestHandler<GatewayRequest, GatewayResponse> for Gateway {
    async fn handle_request(&mut self, request: GatewayRequest) -> GatewayResponse {
        match request {
            GatewayRequest::AddTransaction(gateway_input) => {
                let p2p_message_metadata = gateway_input.message_metadata.clone();

                            source,
                            p2p_message_metadata,
                        }),
                )
            }
        }
    }
