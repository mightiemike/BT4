## Title
Missing "class is declared" check in Starknet OS `replace_class` syscall allows execution divergence from Blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall implementation inside the Starknet OS Cairo program (used for re-execution / proving) unconditionally rewrites a contract's class hash without verifying that the target `class_hash` corresponds to a declared class, while the equivalent Blockifier (VM sequencer execution) implementation explicitly performs this check before mutating state.

### Finding Description
In the Blockifier's deprecated syscall hint processor, `replace_class` reads the compiled class before updating storage, which fails if the class was never declared: [1](#0-0) 

The Starknet OS Cairo implementation of the same syscall (`execute_replace_class` in `syscall_impls.cairo`), which is executed during OS re-execution / proving of the block, performs the state-entry rewrite directly and only contains a TODO acknowledging the missing check: [2](#0-1) 

The deprecated (Cairo0) OS syscall path has the identical gap: [3](#0-2) 

Additionally, the `SnosHintProcessor`'s Rust-side `replace_class` hint handler (used to drive the Cairo execution of the OS program during re-execution) is a complete no-op that returns `Ok(ReplaceClassResponse {})` without validating anything: [4](#0-3) 

Any contract can invoke the `replace_class` syscall on itself (`REPLACE_CLASS_SELECTOR` is reachable from ordinary contract execution, see the dispatch in `execute_syscalls.cairo`): [5](#0-4) 

Because Blockifier (the sequencer's execution engine that actually determines what is accepted into a block) rejects `replace_class(class_hash)` calls where `class_hash` is not declared, but the Starknet OS (used to independently re-execute and prove the same block, generating the committed state root / block hash for L1) does not perform this check, there exists a semantic divergence between the two execution engines for otherwise-identical inputs.

### Impact Explanation
If the OS execution can be driven to accept a transaction/call sequence that the Blockifier would reject (or vice-versa) due to this asymmetric check, the OS's computed state diff and resulting Patricia root / block hash could differ from what the sequencer/Blockifier committed. This is exactly the class of bug the rules classify as high-impact: "honest-node divergence" or "wrong committed root or block hash." Since the OS is the ultimate source of truth used for proving state transitions to L1, any divergence between it and the sequencer's execution results undermines the integrity of state commitment — potentially permitting either invalid state to be proven valid, or valid blocks to fail proving, depending on which execution path is authoritative for a given deployment configuration.

### Likelihood Explanation
Reachability is trivial: `replace_class` is a syscall available to any deployed contract with no special privilege, so any unprivileged transaction sender can trigger a contract to call it with an arbitrary (potentially undeclared) `class_hash`. Whether this leads to an actual state divergence depends on how the OS's replay pipeline is fed its "expected" call data (hints) versus how Blockifier validates it live; based on the code reviewed, the check discrepancy is real and explicitly flagged by the authors' own TODO comment, but I could not fully verify from the available index whether an out-of-band validation exists elsewhere in the OS pipeline (e.g., at hint-population time) that would prevent an actually-undeclared class hash from reaching `execute_replace_class` during re-execution. This uncertainty should be resolved by tracing the hint-population code path (`GetContractAddressStateEntry`) and the OS's overall commitment-of-declared-classes invariant before treating this as fully proven root-divergence risk.

### Recommendation
Add an explicit assertion in `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that the given `class_hash` exists in `contract_class_changes` (i.e., has been declared), mirroring the check performed in Blockifier's `hint_processor.rs::replace_class`. This closes the TODO and removes the semantic gap between the two execution engines that could otherwise cause divergent state commitments.

### Proof of Concept
1. Deploy a contract `A` that calls `replace_class_syscall(undeclared_class_hash)` where `undeclared_class_hash` corresponds to no declared class in the current state.
2. Submit this via Blockifier (sequencer execution): the transaction reverts/fails because `get_compiled_class(class_hash)` errors (`crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:800-801`).
3. Feed the identical block/transaction trace into the Starknet OS re-execution path: `execute_replace_class` in `syscall_impls.cairo` (lines 881-920) performs the `dict_update` unconditionally, with no check that `class_hash` was declared — the state entry is rewritten regardless.
4. Compare the state diffs / resulting commitment produced by each path for this transaction to confirm divergence in observed behavior (accept vs. reject), which is a direct violation of the invariant that OS re-execution must match sequencer execution for a valid block.

        request: ReplaceClassRequest,
        _vm: &mut VirtualMachine,
        syscall_handler: &mut Self,
    ) -> DeprecatedSyscallResult<ReplaceClassResponse> {
        // Ensure the class is declared (by reading it).
        syscall_handler.state.get_compiled_class(request.class_hash)?;
        syscall_handler
            .state
            .set_class_hash_at(syscall_handler.storage_address, request.class_hash)?;

        Ok(ReplaceClassResponse {})

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
