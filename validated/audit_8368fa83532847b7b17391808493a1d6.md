### Title
Missing `Response.Validate()` check in `webapi/target.Execute()` allows inconsistent gateway payloads (ExecutionError + populated body) to be returned as valid workflow output - ([File: core/capabilities/webapi/target/target.go])

### Summary
`Capability.Execute()` in `core/capabilities/webapi/target/target.go` unmarshals the gateway's `ghcapabilities.Response` and directly forwards `StatusCode`/`Headers`/`Body` into the workflow's `CapabilityResponse.Value` without ever calling `ghcapabilities.Response.Validate()` or checking `ExecutionError`. The sibling code path `FetcherService.Fetch()` in `core/services/workflows/syncer/v2/fetcher.go` explicitly calls `payload.Validate()` and checks `payload.ExecutionError`/`StatusCode` range before returning data, demonstrating that this is a known, guarded-against invariant that was simply omitted here.

### Finding Description
`Execute()` performs the following (`core/capabilities/webapi/target/target.go:149-171`):
```go
resp, err := c.connectorHandler.HandleSingleNodeRequest(ctx, messageID, payload)
...
var payload ghcapabilities.Response
err = json.Unmarshal(resp.Body.Payload, &payload)
...
values, err := values.NewMap(map[string]any{
    "statusCode": payload.StatusCode,
    "headers":    payload.Headers,
    "body":       payload.Body,
})
```
There is no call to `payload.Validate()` (defined in `core/services/gateway/handlers/capabilities/webapi.go:26-42`) and no branch on `payload.ExecutionError`/`payload.ErrorMessage`. `Validate()` exists specifically to catch cases where `ExecutionError=true` but `StatusCode`/`Headers`/`Body` are also populated (an internally inconsistent state), or where `StatusCode` is outside the valid HTTP range.

The `Response` originates from the Gateway (`sendHTTPMessageToClient` / `createHTTPRequestCallback` in `core/services/gateway/handlers/capabilities/handler.go` and `.../v2/http_handler.go`), which relays the actual HTTP response from an external endpoint chosen by the workflow's `TargetPayload.Url`. Because a workflow author (or in a compromised/misbehaving relay/proxy scenario, the external HTTP server itself) controls the URL being queried, the response fields (status code, headers, body) reflect externally-supplied content that is combined with the Gateway's own `ExecutionError` flag. A crafted or buggy `Response` payload (e.g., `ExecutionError=true, ErrorMessage="failed", StatusCode=200, Body="fake success"`) is unmarshaled as-is and forwarded to `CapabilityResponse.Value` with no consistency check, so a downstream OCR/workflow report could be built from misleading values without any indication that the request actually failed.

By contrast, `FetcherService.Fetch()` (`core/services/workflows/syncer/v2/fetcher.go:145-167`) validates the raw gateway message (`resp.Validate()`), validates the decoded payload (`payload.Validate()`), rejects `ExecutionError` cases, and range-checks `StatusCode` before returning body bytes — the exact set of checks missing in `target.go`.

### Impact Explanation
This can cause misreporting of downstream workflow execution results: a target capability invocation that actually failed (transport-level error) could be represented to the workflow/consensus layer as a successful HTTP response with attacker/externally-influenced status/body content, since no validation gate exists to reject or flag the inconsistency. This falls under data-tampering/misreporting of workflow execution output rather than a direct fund-loss or RCE bug, but it undermines the integrity guarantee that `ExecutionError` is supposed to provide.

### Likelihood Explanation
The code path is reached on every `web-api-target@1.0.0` capability execution with `SingleNode` delivery mode (the default), which is a normal, non-privileged workflow operation. The precondition is only that the gateway-relayed `Response` payload be internally inconsistent — which can occur due to a bug in the Gateway/relay path, a misbehaving or compromised intermediary, or malformed responses from the target external endpoint feeding into the Gateway's error-handling branch — not because of any special attacker privilege. Given the pattern is unguarded in this file while explicitly guarded in the parallel `fetcher.go` code, the likelihood of the omission being exercised in practice is moderate.

### Recommendation
In `core/capabilities/webapi/target/target.go`, after `json.Unmarshal(resp.Body.Payload, &payload)`, call `payload.Validate()` and return an error if it fails; additionally branch on `payload.ExecutionError` to return `payload.ErrorMessage` as an error instead of populating `statusCode`/`headers`/`body`, mirroring the logic already implemented in `core/services/workflows/syncer/v2/fetcher.go:145-167`.

type Response struct {
	ExecutionError bool              `json:"executionError"`         // true if there were non-HTTP errors. false if HTTP request was sent regardless of status (2xx, 4xx, 5xx)
	ErrorMessage   string            `json:"errorMessage,omitempty"` // error message in case of failure
	StatusCode     int               `json:"statusCode,omitempty"`   // HTTP status code
	Headers        map[string]string `json:"headers,omitempty"`      // HTTP headers
	Body           []byte            `json:"body,omitempty"`         // HTTP response body
}

// Validate ensures the Response struct is consistent.
func (r Response) Validate() error {
	if r.ExecutionError {
		if r.ErrorMessage == "" {
			return errors.New("executionError is true but errorMessage is empty")
		}
		if r.StatusCode != 0 || len(r.Headers) > 0 || len(r.Body) > 0 {
			return errors.New("executionError is true but response details (statusCode, headers, body) are populated")
		}
		return nil
	}

	if r.StatusCode < 100 || r.StatusCode > 599 {
		return errors.New("statusCode must be a valid HTTP status code (100-599)")
	}

	return nil
}

// sendHTTPMessageToClient is an outgoing message from the gateway to external endpoints
// returns message to be sent back to the capability node
func (h *handler) sendHTTPMessageToClient(ctx context.Context, req network.HTTPRequest, msg *api.Message) (*api.Message, error) {
	var payload Response
	resp, err := h.httpClient.Send(ctx, req)
	if err != nil {
		return nil, err
	}
	payload = Response{
		ExecutionError: false,
		StatusCode:     resp.StatusCode,
		Headers:        resp.Headers,
		Body:           resp.Body,
	}
	payloadBytes, err := json.Marshal(payload)
	if err != nil {
		return nil, err
	}

	return &api.Message{
		Body: api.MessageBody{
			MessageId: msg.Body.MessageId,
			Method:    msg.Body.Method,
			DonId:     msg.Body.DonId,
			Payload:   payloadBytes,
		},
	}, nil
}
