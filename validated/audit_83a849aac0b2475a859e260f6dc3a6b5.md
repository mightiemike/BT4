## Title
Spot-price sandwich in the inbound gas-abstraction auto-swap allows theft of bridged user deposits - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The Ichi-vault report describes a class of bug where a critical value (vault shares owed to a depositor) is derived from an on-chain spot price with only a same-block sanity check, letting an MEV actor manipulate that spot price and steal the deposit. Push Chain's inbound gas-abstraction flow reproduces the same pattern: it fetches a Uniswap-V3-style spot quote and uses that *same* manipulated quote to compute its own slippage bound, then immediately executes the swap against the live pool.

### Finding Description
When a `GAS`/`GAS_AND_PAYLOAD` inbound is finalized, `ExecuteInboundGas` swaps the user's bridged PRC20 for PC on-chain to fund their new UEA [1](#0-0) . The protection logic is:

1. `GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96 = 0`, i.e. a pure current-spot-price quote, no TWAP [2](#0-1) .
2. That same spot quote is then used to derive `minPCOut = quote * 95 / 100` — a 5% band around itself, not around any independent/TWAP reference [3](#0-2) .
3. `CallPRC20DepositAutoSwap` then executes the real swap against the same pool in the same keeper call/block [4](#0-3) , [5](#0-4) .

Because the "reference" price and the "execution" price are read from the identical, attacker-manipulable pool state within the same block, the 5% check provides no real protection — an attacker only needs to push the pool price down before this call executes and restore it after, extracting essentially the full deposit value beyond the 5% floor. This is the same root cause as the Ichi report: a same-block/spot check that is trivially satisfied because both the "before" and "after" prices are attacker-controlled in that block. The identical pattern is reused for outbound gas refunds via `getSwapQuoteForRefund` / `applyGasRefund`, which also feeds a freshly-fetched spot quote into its own 95% floor before calling `CallUniversalCoreRefundUnusedGas` [6](#0-5) .

Any unprivileged user can permissionlessly swap against the PRC20/WPC pool on Push Chain's own EVM, so no validator or relayer collusion is required — only ordinary block-level MEV sandwiching around the block in which a UV's finalizing `MsgVoteInbound` (which triggers `ExecuteInboundGas`) lands.

### Impact Explanation
A depositor bridging funds for gas top-up can have the majority of their deposit's value siphoned by an MEV actor sandwiching the pool around the block that finalizes their inbound, since the swap's slippage protection is computed from the very price the attacker controls. This is a direct loss of user-deposited funds, falling squarely under "stealing, draining ... of user or protocol-controlled funds" and "corruption of ... refund accounting" in the allowed-impact list.

### Likelihood Explanation
Likelihood is higher than the original Ichi report's variant: that report required an attacker to fully control two consecutive blocks (multi-block MEV); here a single-block sandwich (a very common, well-tooled MEV pattern) around the ordinary transaction that finalizes an inbound vote is sufficient, since the quote and the swap happen in the same block/state. No privileged role (validator, relayer, TSS participant) is required — the attacker only needs capital to move the pool and observe the mempool for the finalizing `MsgVoteInbound`.

### Recommendation
Do not derive the slippage floor from the same spot quote that is about to be executed against. Compare the spot quote to an independent reference (e.g., a TWAP over a window, or an oracle price for the token pair) and reject/defer the swap if the spot price deviates from that independent reference by more than an allowed delta, regardless of what block the deviation occurred in — mirroring the recommendation in the source report ("check spot and twap price ... within an allowed delta regardless of when price was last updated"). Alternatively, route these swaps through a mechanism resistant to same-block manipulation (e.g., commit-reveal, or execution price bounded by a governance/registry-set reference price rather than a live pool quote).

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` in the mempool that will cross the vote threshold and trigger `ExecuteInboundGas` for a victim's bridged deposit.
2. In the block containing that finalizing vote, attacker front-runs with a large swap on the PRC20/WPC pool, driving the PRC20 price down.
3. The finalizing tx executes `GetSwapQuote` (spot, no TWAP) against the now-depressed price, computes `minPCOut = quote*95/100` off that depressed quote, and executes `CallPRC20DepositAutoSwap` — the victim's PRC20 is swapped for PC at the manipulated price.
4. Attacker back-runs to restore the pool price and pockets the PC that would otherwise have gone to the victim's UEA, beyond the (self-referential) 5% band.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
