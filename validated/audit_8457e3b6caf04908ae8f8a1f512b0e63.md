### Title
`handle_poison_microblock` accepts two identical (non-forked) microblock headers as proof of double-signing, allowing an attacker to slash an honest miner's coinbase without any actual fork - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`StacksChainState::handle_poison_microblock` only verifies that `mblock_header_1` and `mblock_header_2` recover to the *same signer public-key hash* via `check_microblock_header_signer`, but never verifies that the two headers actually diverge (i.e., represent two different microblocks published at the same sequence number by that signer). An attacker can copy a single legitimately-published, honestly-signed microblock header and submit it twice as `mblock_header_1`/`mblock_header_2`, trivially satisfying `pkh1 == pkh2`, and get a poison report inserted against an honest miner who never double-signed anything.

### Finding Description
The claimed equality is: `punished == true_only_if_headers_differ_at_same_sequence`. The code only implements `pkh1 == pkh2` [1](#0-0) , which is trivially true whenever `mblock_header_1` and `mblock_header_2` are byte-identical (the same signed header submitted twice) — no signature forgery is needed, the attacker simply reuses a header they can observe on the wire.

`handle_poison_microblock` then proceeds straight from this signer-equality check to load the historical height at which that pubkeyhash was registered, checks the maturity window, and unconditionally records a poison report using `mblock_header_1.sequence` as the "fork point," with no check anywhere that:
- `mblock_header_1.sequence == mblock_header_2.sequence`, or
- the two headers actually have different content/hash (i.e., that a real fork occurred). [2](#0-1) 

Because `check_microblock_header_signer`'s docstring literally states its only job is "were both headers signed by the same key" [3](#0-2) , and `handle_poison_microblock` treats that as sufficient proof of a double-sign, an attacker can:
1. Observe any honestly-published, valid microblock header `H` from a miner (its `microblock_pubkey_hash` is registered in that miner's block, satisfying the "seen before" and maturity-window checks at lines 754-803).
2. Submit a `PoisonMicroblock` transaction with `mblock_header_1 = H` and `mblock_header_2 = H` (identical copies).
3. `check_microblock_header_signer` recovers the same real pubkeyhash from both (since they're the same bytes) and returns `Ok(pkh)` — no divergence check fails.
4. `handle_poison_microblock` inserts a poison report at the honest miner's `mblock_pubk_height`, crediting the attacker as reporter, with zero evidence of an actual fork.

### Impact Explanation
This inserts a bogus poison-microblock record against an honest miner's legitimately-used microblock public key, which is the mechanism used elsewhere in the codebase to zero out/redirect that miner's coinbase reward upon maturation. This is a reward-loss/reward-theft class of impact: an honest miner's coinbase can be destroyed and the falsely-reporting attacker credited as the "commission" recipient, purely by replaying a public, legitimately-signed header — no double-signing, no majority stake, and no privileged role required.

### Likelihood Explanation
The only precondition is that the attacker can observe one honestly-published microblock header whose pubkeyhash is registered and within the `MINER_REWARD_MATURITY` window — both of which are normal, expected, low-cost conditions for any participant watching the chain (a single miner slot or even a plain observer submitting a transaction). No BTC spend beyond a normal transaction fee is required, and the attack is trivially repeatable against any miner's microblock stream within the maturity window.

### Recommendation
In `handle_poison_microblock` (and/or `check_microblock_header_signer`), require that the two headers are genuinely conflicting evidence of a fork before accepting them as proof of a double-sign: enforce `mblock_header_1.sequence == mblock_header_2.sequence` and that the headers are not identical (e.g., differ in `block_hash()`/signature payload), in addition to the existing signer pubkeyhash-equality check. Reject the transaction as invalid if the headers are byte-identical or if their sequence numbers differ.

### Proof of Concept
Rust integration test outline:
1. Set up a chainstate/Clarity test harness (as used in `stackslib/src/chainstate/stacks/tests/block_construction.rs`, which already exercises `PoisonMicroblock`).
2. Have an honest miner key sign one real `StacksMicroblockHeader` `H` at sequence `N`, and mine a block that registers `H`'s `microblock_pubkey_hash`.
3. Advance the chain within `MINER_REWARD_MATURITY` blocks.
4. Craft a `PoisonMicroblock` transaction from an unrelated attacker principal with `mblock_header_1 = H.clone()` and `mblock_header_2 = H.clone()` (byte-identical).
5. Call `StacksChainState::handle_poison_microblock` (or process the transaction end-to-end via `process_transaction_payload`).
6. Assert on both sides of the equality:
   - Expected (safe) side: the call should return `Err(Error::InvalidStacksTransaction(..))` because `mblock_header_1 == mblock_header_2` (no real fork).
   - Observed (vulnerable) side: the call instead returns `Ok(Value::Tuple(..))` and `env.global_context.database.get_microblock_poison_report(mblock_pubk_height)` now contains a report crediting the attacker at `H`'s sequence, despite no fork having occurred — demonstrating the honest miner's coinbase at that height is now flagged for punishment.

    /// Given two microblock headers, were they signed by the same key?
    /// Return the pubkey hash if so; return Err otherwise
    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
