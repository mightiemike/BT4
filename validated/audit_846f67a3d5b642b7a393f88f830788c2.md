## Analysis

`ExecuteInboundGas` computes the slippage-protection bound purely from a live on-chain AMM read: [1](#0-0) 

The quote itself comes from a direct `QuoterV2.quoteExactInputSingle` static call against the current pool reserves — a spot price, not a TWAP or any oracle-anchored value: [2](#0-1) 

That `minPCOut` is then handed straight into the real, committed swap executed by the module: [3](#0-2) 

Note the token must pass `uregistryKeeper.GetTokenConfig` (i.e. be a governance-registered asset) before this path is reached: [4](#0-3)  — so a *fully unregistered* token cannot enter this flow. However, this does not remove the underlying flaw: any registered PRC20/WPC pool with genuinely thin liquidity (a normal, expected market condition, not an attacker privilege) is subject to spot-price manipulation because the code has no oracle-independent sanity bound.

### Title
Slippage protection (`minPCOut`) for gas-abstraction auto-swap relies solely on manipulable on-chain spot quote - (File: `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
`ExecuteInboundGas` derives `minPCOut` as 95% of a single, same-block `QuoterV2.quoteExactInputSingle` spot read of the PRC20/WPC pool, then immediately executes the real swap using that same pool state. Since the quote and the executed swap both read the identical, attacker-influenceable AMM reserves, an unprivileged actor who can move the pool price before the inbound is finalized (trivial for a low-liquidity pool) can bias the executed swap price in either direction, extracting value from pool liquidity or corrupting the native PC amount credited to the UEA.

### Finding Description
1. An unprivileged user deposits a registered, low-liquidity gas token cross-chain, which becomes a `TxType_GAS` inbound.
2. When the inbound is finalized (honest validators, no privileged assumption needed), `ExecuteInboundGas` fetches `quoterAddr`, `wpcAddr`, `fee` and calls `GetSwapQuote` [5](#0-4) .
3. `GetSwapQuote` reads the AMM's *current* reserves via a static call, with no TWAP, external price feed, or bound check [6](#0-5) .
4. `minPCOut` is computed as a flat 95% of that instantaneous quote and passed to `CallPRC20DepositAutoSwap`, which performs the real, committed swap against the same pool [7](#0-6) .
5. Because the "protection" band and the actual execution price both derive from the same manipulable reserves, an attacker who trades against the pool immediately before the module's swap executes (cheap for low-liquidity pools) can shift the effective execution price. This lets the attacker extract WPC/PC from pool liquidity through the module's forced swap, and/or cause the credited PC amount for the UEA to reflect a manipulated rather than fair price — an accounting corruption of the native PC balance credited to the UEA, funded by draining AMM liquidity.

### Impact Explanation
This falls under "corruption of PRC20 or native asset accounting" and potential "draining ... of protocol-controlled funds" (pool liquidity) in the Allowed Impact Gate. The attacker doesn't need any privileged role — only ordinary deposit + the ability to submit ordinary EVM swap transactions against the same pool used by the quoter, which is a ordinary user action.

### Likelihood Explanation
Feasibility depends on (a) an admin having registered a token/pool with genuinely thin liquidity — a normal, expected operational state rather than an attacker privilege, and (b) the attacker being able to time their own swap in the same block/near the inbound's finalization block. Push Chain's inbound finalization timing is not fully attacker-controlled (it depends on ballot convergence across honest UVs), which reduces — but does not eliminate — reliability of precise sandwich timing; an attacker could instead maintain a manipulated price over a short window to catch the execution block, at the cost of holding capital/paying fees, which is economically rational for cheap-to-manipulate low-liquidity pools.

### Recommendation
Do not use a bare percentage-of-spot-quote as the sole slippage bound. Cross-check the quoter's spot price against a TWAP (Uniswap V3 pools support `observe`/oracle cardinality) or an independent price reference, and/or clamp the acceptable execution price to a sanity band derived from a longer time window, rejecting/deferring the swap if spot and TWAP diverge beyond a safe threshold, rather than deriving `minPCOut` purely from the same instantaneous read used for execution.

### Proof of Concept
Conceptual reproduction (would need a Devin session with EVM/pool access to fully simulate):
1. Register (via governance, as normal operations) a PRC20/WPC Uniswap V3 pool with low liquidity.
2. As an attacker, submit an EVM swap transaction that shifts the pool's PRC20/WPC price shortly before a `TxType_GAS` inbound (for a deposit of that PRC20 token) is finalized.
3. Observe that `GetSwapQuote` at execute_inbound_gas.go:135 returns the manipulated price, `minPCOut` is derived from it (line 144-145), and `CallPRC20DepositAutoSwap` executes against the still-manipulated pool, yielding a PC credit to the UEA and/or pool extraction that diverges materially from the pre-manipulation fair price.
4. Attacker reverses their manipulating trade to realize profit, net of the module's swap effect on the pool.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
