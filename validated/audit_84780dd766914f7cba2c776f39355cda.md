### Title
Attacker-manipulable UniswapV3 spot quote lets a sandwicher extract value from gas-abstraction auto-swaps within the fixed 5% slippage band - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The GAS / GAS_AND_PAYLOAD inbound-execution path and the outbound gas-refund path both source pricing from a live on-chain UniswapV3 `QuoterV2.quoteExactInputSingle` spot quote and then execute the swap immediately in the same call with only a flat 5% slippage tolerance (`minPCOut = quote * 95 / 100`). This is the exact bug class from the external report: a trusted "spot price" read from an AMM pool that an unprivileged attacker can skew (via flash/atomic trades against the same pool) just before the protected module consumes it, extracting value up to the size of the tolerance band — analogous to sandwiching SpotHedgeBaseMaker trades up to the price-band cap.

### Finding Description
`ExecuteInboundGas` ( [1](#0-0) ) fetches `fee` via `GetDefaultFeeTierForToken` and a spot `quote` via `GetSwapQuote` (which calls `QuoterV2.quoteExactInputSingle`, [2](#0-1) ), computes `minPCOut = quote * 95 / 100`, and then immediately calls `CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap` on `UniversalCore` ( [3](#0-2) ). The same quote→swap pattern with the identical 95% floor is used for excess-gas refunds in `applyGasRefund`/`getSwapQuoteForRefund` ( [4](#0-3) ), and for `gasAndPayloadDepositAutoSwap` used by the GAS_AND_PAYLOAD path ( [5](#0-4) ).

There is no oracle sanity check, no TWAP, and no comparison against `ChainMeta`/external price data anywhere in this path — the quote and the swap both read the *same* pool's *current* reserves. This mirrors the SpotHedgeBaseMaker root cause: the protocol treats the AMM's instantaneous price as ground truth and only bounds the discrepancy with a static tolerance band (here 5%, there the "price band"), rather than validating the price against an independent source.

Any account can move the `prc20:WPC` UniswapV3 pool's price on Push Chain's own EVM (this is a permissionless pool that the module trades against, deployed as part of the universal system contracts referenced in `x/uregistry`). Because `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`/`applyGasRefund` run synchronously as part of the message handler that finalizes the triggering `MsgVoteInbound`/`MsgVoteOutbound` (i.e., inside the same block, and the swap step happens without any cross-block delay or commit/reveal), an attacker who observes a pending quorum-finalizing vote in the mempool can:
1. Submit an EVM transaction that skews the `prc20/WPC` pool price downward (buy WPC / sell prc20, or vice versa depending on swap direction) just ahead of the finalizing vote transaction in the same or an adjacent block.
2. Let the module's auto-swap execute at the skewed price, degraded only by the fixed 5% floor — pushing real value out of the amount the depositor/recipient actually receives (or out of the refunded gas amount) into the pool.
3. Reverse the skew afterward, capturing the value difference risk-free, just as in the SpotHedgeBaseMaker sandwich.

The impact differs from the perp example in mechanism (a bridging/gas-abstraction auto-swap of protocol/user-owned funds instead of a maker/taker perpetual position) but shares the identical trigger: an unprivileged actor manipulating a public AMM pool that a privileged, protocol-controlled flow trusts with only a fixed tolerance, executed atomically with no external price cross-check.

### Impact Explanation
The victim is either the bridging user (whose bridged funds get auto-swapped into gas token at a manipulated rate, reducing what lands in their UEA) or the protocol's own held gas-fee funds (the `applyGasRefund` swap, where excess gas fees collected on the destination chain are swapped back to native PC and refunded — the module effectively worsens the exchange rate for the refund recipient, and the difference is captured by the pool/attacker). This is a fund-value-loss issue reachable purely by an unprivileged external actor manipulating a public AMM pool prior to a deterministic, keeper-triggered swap — squarely in the "corruption of ... gas fee accounting, refund accounting ... asset accounting" allowed-impact category.

### Likelihood Explanation
Medium. The attack requires:
- Enough capital to move the specific `prc20:WPC` pool by close to the 5% band (analogous to the sponsor's own conclusion in the referenced report that widening/loosening the tolerance is what makes the attack profitable).
- Timing the skew so it's still in effect when the module's swap executes, which depends on mempool visibility of the finalizing vote and block-inclusion ordering (attacker isn't a block proposer, so true same-block atomicity isn't guaranteed, but liquidity-light pools and multi-block windows before reversal are enough, per the original report's own back-and-forth on feasibility).
- Pool liquidity being thin enough for the 5%-bound skew to be economically worthwhile net of DEX fees — the same economic caveat that led the original Sherlock issue to be judged Medium rather than High/Critical after extensive escalation debate.

Given these caveats mirror almost exactly the debated real-world report (ultimately ruled valid Medium), the same severity judgment applies here.

### Recommendation
- Do not rely solely on the pool's own instantaneous `quoteExactInputSingle` result as both the reference price and the execution price. Cross-check the quote against `x/uexecutor`'s `ChainMetas`/oracle price (or a TWAP from the same pool) before accepting `minPCOut`.
- Tighten and/or make the slippage tolerance a `uregistry`/governance-configurable, per-token parameter rather than a hardcoded 5%, and consider using a TWAP-based quote instead of `quoteExactInputSingle`'s spot price for `GetSwapQuote`/`getSwapQuoteForRefund`.
- Consider deferring/rate-limiting auto-swaps or batching them so a single-block/mempool-visible sandwich can't reliably target a specific finalizing vote.

### Proof of Concept
Conceptual PoC (mirrors the external report's structure):
1. Attacker observes 2-of-3 (or quorum -1) `MsgVoteInbound` votes already recorded for a pending GAS/GAS_AND_PAYLOAD inbound (visible via `PendingInbounds` queries or mempool).
2. Attacker submits an EVM swap against the `prc20:WPC` UniswapV3 pool that Push Chain's `UniversalCore` uses (fetched via `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`), skewing the pool price down by close to (but within) the 5% tolerance that `ExecuteInboundGas` will apply.
3. The final quorum vote lands, triggering `ExecuteInboundGas` → `GetSwapQuote` (reads the now-skewed pool) → `minPCOut = quote*95/100` → `CallPRC20DepositAutoSwap` executes at the bad rate against `UniversalCore`.
4. Attacker reverses their swap, restoring the pool and pocketing the value difference, exactly as `IllIllI000`'s `testSandwich` PoC demonstrated for SpotHedgeBaseMaker.

Note: I could not directly execute or verify this against the actual `UniversalCore.sol` contract or the deployed UniswapV3 pool parameters (liquidity depth, actual fee tier) since those live in the EVM/system-contract bytecode outside what the indexed Go code exposes; a full working PoC (Foundry-style, as in the source report) would need to be built against the actual `UniversalCore` and pool contracts to confirm concrete profitability given real liquidity and fee-tier constants.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// handleSuccessfulOutbound refunds unused gas fee when gasFee > gasFeeUsed.
func (k Keeper) handleSuccessfulOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {

		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)
	k.applyGasRefund(ctx, &outbound, obs)
	return k.UpdateOutbound(ctx, utxId, outbound)
}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}

// getSwapQuoteForRefund fetches a Uniswap quote for the gas token refund swap.
func (k Keeper) getSwapQuoteForRefund(ctx sdk.Context, gasToken common.Address, fee *big.Int, amount *big.Int) (*big.Int, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(ctx)
	if err != nil {
		return nil, err
	}
	wpcAddr, err := k.GetUniversalCoreWPCAddress(ctx)
	if err != nil {
		return nil, err
	}
	return k.GetSwapQuote(ctx, quoterAddr, gasToken, wpcAddr, fee, amount)
