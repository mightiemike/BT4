### Title
Uncaught `SafeCompareError` thrown from `safeCompare()` causes unhandled exception (DoS) in `validateHmac()` when the `hmac` query parameter is supplied as an array - ([File: packages/apps/shopify-api/lib/auth/oauth/safe-compare.ts])

### Summary
`validateHmac()` is the core HMAC-based request-authentication routine used by `shopify-app-js` to verify Shopify-signed query strings (OAuth callbacks, custom-route/webhook verification via `shopify.utils.validateHmac`). For the default `admin` signator, the query-normalization step does not guard against `hmac` being supplied as an array, unlike the `appProxy` signator which explicitly rejects duplicated/array security parameters. This missing check allows a crafted request to reach `safeCompare()` with mismatched types, which throws an unhandled `SafeCompareError` instead of returning `false`, mirroring the "revert instead of graceful failure on an edge-case input" root cause from the referenced report.

### Finding Description
`normalizeQuery()` only enforces the "must not appear more than once" protection for the security parameters (`hmac`, `shop`, `signature`, `timestamp`) when `signator === 'appProxy'`: [1](#0-0) 

For the `admin` signator (the default), a plain-object query (i.e., not a `URLSearchParams` instance, which is exactly the shape of `req.query` in Express/qs-based routers when a param is repeated, e.g. `?hmac[]=a&hmac[]=b`) passes through untouched, so `normalizedQuery.hmac` can end up as an array: [2](#0-1) 

The falsy check `!normalizedQuery.hmac` does not catch this since an array is truthy, so execution proceeds to compute the locally derived HMAC and calls `safeCompare(hmac as string, localHmac)`: [3](#0-2) 

`safeCompare()` requires both operands to have the *same* JavaScript `typeof`; if they don't, it throws `SafeCompareError` rather than returning `false`: [4](#0-3) 

Since `hmac` is `typeof 'object'` (an array) and `localHmac` (the computed HMAC) is always `typeof 'string'`, the type-equality check fails and the function throws instead of returning a boolean `false` verdict. This is directly analogous to the Ammplify bug: an unhandled edge-case input (a zero-amount transfer there; a type-mismatched HMAC parameter here) causes the function to abort via an exception rather than resolving cleanly, propagating a DoS to any caller/route that expects `validateHmac` to always resolve to `true`/`false`.

Notably, the `appProxy` signator was already hardened against exactly this class of issue (per the project's own changelog: "Harden app proxy authentication by rejecting repeated security parameters..."), but the `admin` signator path was left unprotected, which is the residual analog of the fixed bug class.

### Impact Explanation
Any route or custom handler in an app built on `shopify-app-js` that calls the public `shopify.utils.validateHmac(query)` (default `admin` signator) with a raw framework-parsed query object is exposed to an unhandled exception when an anonymous caller supplies a duplicated `hmac` (or other admin-signed) parameter that a query parser (e.g., Express + `qs`) turns into an array. If the calling code does not wrap this call in a try/catch (the API is documented to return a `boolean`, not to throw on malformed input types), the resulting uncaught exception can crash the request handler / process for that route, denying legitimate HMAC-authenticated requests until the process is restarted — a DoS of the request-authentication handler.

### Likelihood Explanation
The attack requires no privileges — any anonymous HTTP client can send a crafted query string with a duplicated `hmac` parameter to any endpoint that performs admin-style HMAC validation via this shared utility. The only precondition is that the calling framework parses repeated query keys into arrays (a common default, e.g. Express with `qs`), which is standard for many app-proxy/OAuth-adjacent custom routes built on top of `shopify-app-js`.

### Recommendation
Apply the same duplicate/array-parameter guard used for the `appProxy` signator to the `admin` signator path in `normalizeQuery()` (i.e., reject arrays for `hmac`, `shop`, `timestamp` regardless of signator), and/or make `safeCompare()` return `false` instead of throwing when operand types differ, so `validateHmac()` always resolves to a boolean and never throws on malformed/attacker-controlled input.

### Proof of Concept
1. Stand up any route that calls `shopify.utils.validateHmac(req.query)` with default options (`signator: 'admin'`), using an Express-style router where duplicate query keys are parsed into arrays.
2. Send: `GET /route?hmac[]=aaa&hmac[]=bbb&shop=example.myshopify.com&timestamp=<validTimestamp>`.
3. `normalizeQuery()` passes `hmac` through unchanged as `['aaa', 'bbb']` (typeof `object`).
4. `validateHmac()` reaches `safeCompare(hmac as string, localHmac)` with `typeof hmac === 'object'` and `typeof localHmac === 'string'`, which throws `SafeCompareError` instead of returning `false`, per [4](#0-3) .

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

      throw new ShopifyErrors.InvalidHmacError(

      );

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

export const safeCompare: SafeCompare = (strA, strB) => {
  if (typeof strA === typeof strB) {
    const enc = new TextEncoder();
    const buffA = enc.encode(JSON.stringify(strA));
    const buffB = enc.encode(JSON.stringify(strB));

    if (buffA.length === buffB.length) {
      return timingSafeEqual(buffA, buffB);
    }
  } else {
    throw new ShopifyErrors.SafeCompareError(
      `Mismatched data types provided: ${typeof strA} and ${typeof strB}`,
    );
  }
  return false;
};
