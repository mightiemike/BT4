### Title
Starknet OS `execute_replace_class` accepts an undeclared/uninitialized class hash while Blockifier rejects it - honest-node state divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `replace_class` syscall handler in the Blockifier (Rust) execution path validates that the target `class_hash` is a declared class before mutating a contract's class hash. The equivalent logic in the Starknet OS Cairo program, which independently re-derives/re-executes state transitions for proof generation, is missing that check — with an explicit TODO marking the gap. This mirrors the reported bug class: a downstream/duplicate code path treats data as valid ("source of truth") without validating that the referenced entity was properly declared/initialized, exactly as `getAddresses()`/`getDAOVersions()` returned data for undeclared/zero-address DAO tokens.

### Finding Description
In the Blockifier's syscall implementation, `replace_class` explicitly ensures the class is declared by reading it before mutating state: [1](#0-0) 

This is validated by tests that assert an "is not declared" error for undeclared class hashes: [2](#0-1) 

In contrast, the Starknet OS's Cairo re-implementation of the same syscall (`execute_replace_class`, used both in the deprecated and current syscall dispatch tables) performs the state-entry class-hash mutation directly via `dict_update`, with an explicit acknowledgement that the declared-class check is not implemented: [3](#0-2) 

The same unguarded pattern exists in the deprecated syscalls variant: [4](#0-3) 

Both dispatch entry points route directly into this unguarded function for any `replace_class` syscall found in the transaction trace: [5](#0-4) 

The OS is the component responsible for independently re-executing every transaction to derive (and prove) the resulting state commitment; it is not supposed to blindly trust the Blockifier's bookkeeping. Because the OS's `execute_replace_class` does not verify `contract_class_changes` (the dict tracking declared classes) for the given `class_hash`, the OS will silently accept a state transition that sets a contract's class hash to a value that was never declared — a value that Blockifier's native execution path would have rejected with `StateError::UndeclaredClassHash`.

### Impact Explanation
The Starknet OS is the ultimate arbiter of state-transition correctness for proof generation, comparable to `getAddresses()`/`getDAOVersions()` being treated as the "source of truth" for downstream logic in the reported bug. If any code path (e.g., a future non-Blockifier prover/re-execution client, a different sequencer implementation processing the same trace, or a bug/omission elsewhere in Blockifier that fails to filter this before it reaches the OS) supplies a `replace_class` syscall referencing an undeclared class hash, the OS will compute a different, unchecked resulting state (accepting the class-hash overwrite) than what the protocol intends. This creates:
- A wrong committed root/class-hash-at-address for that contract if the OS silently accepts an invalid replace_class.
- Honest-node divergence: any node/verifier relying on the OS's Cairo logic as the canonical definition of valid state transitions would disagree with a node whose native execution enforces the "declared class" invariant (Blockifier), since the two implementations of the identical syscall enforce different invariants.

The TODO comment ("Check that there is a declared contract class with the given hash") confirms the check is a known, currently-missing invariant in the OS reference implementation, i.e., not merely benign or unreachable dead code but an acknowledged incompleteness in a protocol-critical, dual-implemented (Rust + Cairo) code path.

### Likelihood Explanation
Under the current architecture, Blockifier's own execution filters out `replace_class` calls to undeclared classes before they can reach the OS as part of a "successful" transaction trace, so in the ordinary sequencer flow this divergence is not directly triggerable by an external actor through the standard block-building path alone. However, the OS is designed to be a strict, self-contained verifier of the state transition; the missing check is a structural weakness in that role, and the codebase itself flags it as an outstanding TODO rather than an intentional invariant. The likelihood of exploitation depends on whether any code path (bug, alternate builder, malicious sequencer producing a corrupted trace that the OS is expected to catch) can present a `replace_class` syscall to the OS with an undeclared class hash without pre-filtering by Blockifier — a scenario the OS is explicitly supposed to guard against as an independent verifier.

### Recommendation
Add a declared-class check inside `execute_replace_class` (both syscall_impls.cairo and deprecated_execute_syscalls.cairo) analogous to Blockifier's `get_compiled_class` check — e.g., assert that `class_hash` exists in `contract_class_changes` (or the equivalent declared-classes dict) before performing the `dict_update` on `contract_state_changes`, matching the TODO already present in the code.

### Proof of Concept
1. Construct (or have the OS process) a transaction trace containing a `REPLACE_CLASS_SELECTOR` syscall with a `class_hash` that was never declared in the block (not present in `contract_class_changes`).
2. Feed this trace directly into the OS's `execute_syscalls` / `execute_deprecated_syscalls` dispatch, which routes to `execute_replace_class`. [6](#0-5) 
3. Observe that the OS updates `contract_state_changes` with the new (undeclared) class hash without any assertion failure, whereas the equivalent Rust Blockifier path (`hint_processor.rs::replace_class`) would have returned `StateError::UndeclaredClassHash` and aborted the syscall. [7](#0-6) 
4. This demonstrates the two implementations of the same protocol operation enforce different invariants, confirming the divergence risk described above.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
