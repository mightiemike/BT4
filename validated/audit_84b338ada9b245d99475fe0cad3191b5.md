### Title
Energy CPU-time penalty tracked in `ReceiptCapsule.energyPenaltyTotal` is never merged into billed usage in `payEnergyBill` - ([File: chainbase/src/main/java/org/tron/core/capsule/ReceiptCapsule.java])

### Summary
`TransactionTrace.exec()` records VM energy usage and CPU-time penalty as two separate receipt fields (`energyUsageTotal` via `setBill`, `energyPenaltyTotal` via `setPenalty`), but `ReceiptCapsule.payEnergyBill()` only reads `receipt.getEnergyUsageTotal()` when computing what to charge the account. `getEnergyPenaltyTotal()` is never consulted anywhere inside the billing path, so any non-zero penalty value is stored in the persisted `ResourceReceipt` but has no effect on the amount of energy actually deducted or the SUN fee charged.

### Finding Description
`TransactionTrace.exec()` sets the two fields independently after VM execution: [1](#0-0) 

`setBill`/`setPenalty` write to two distinct protobuf fields on the receipt with no merging logic: [2](#0-1) 

`TransactionTrace.finalization()` → `pay()` → `receipt.payEnergyBill(...)` is the only call site that actually debits energy/fee: [3](#0-2) 

`ReceiptCapsule.payEnergyBill()` and its private overload compute `originUsage`/`callerUsage` and the energy fee exclusively from `receipt.getEnergyUsageTotal()`; `getEnergyPenaltyTotal()` is defined as a getter/setter pair but is never referenced inside `payEnergyBill` or its helpers: [4](#0-3) [5](#0-4) 

Since the billing logic (`payEnergyBill`) and the deduction routine (private `payEnergyBill(...)`, lines 260-318) only ever key off `getEnergyUsageTotal()`, `energyPenaltyTotal` is effectively a write-only, unbilled field once it reaches `ReceiptCapsule`.

### Impact Explanation
If `energyPenaltyTotal` is meant to represent additional chargeable cost (e.g., a CPU-time-based penalty multiplier for particular opcodes), any such penalty is silently dropped from the actual account debit performed by `payEnergyBill`. The caller/origin account would only ever be charged for `energyUsageTotal`, so a contract execution that legitimately incurs a penalty would cost strictly less than intended — an underpriced-work / fee-bypass condition against the protocol's own accounting invariant that "all incurred energy cost is billed exactly once."

### Likelihood Explanation
I was not able to fully trace, within the available tool budget, the exact site in the TVM (`VM.java` / `Program.java` / `EnergyCost.java`) where `ProgramResult.setEnergyPenaltyTotal` is populated, nor confirm whether the underlying "penalty" energy is already spent through the ordinary `spendEnergy` bookkeeping (in which case it would already be folded into `getEnergyUsed()`/`energyUsageTotal`, making `energyPenaltyTotal` a purely informational/reporting field with no separate billing obligation). Grep of `Program.java` for `energyPenalty` returned zero matches, so the penalty is computed elsewhere and only surfaced via `ProgramResult.getEnergyPenaltyTotal()`. Whether this is a genuine double-tracked-but-unbilled cost, or a deliberate informational metric exposed via `Wallet.java`/transaction info queries, could not be conclusively determined from the code paths inspected. This uncertainty affects whether the finding constitutes an actual fee bypass versus a display-only field.

### Recommendation
Given the ambiguity, the concrete, verifiable code issue is that `ReceiptCapsule.payEnergyBill` never reads `getEnergyPenaltyTotal()`. If the penalty is intended to be billable, `payEnergyBill` should add `receipt.getEnergyPenaltyTotal()` to the usage used for both the origin/caller split and the final `useEnergy`/`energyFee` computation (e.g., billing `energyUsageTotal + energyPenaltyTotal` instead of `energyUsageTotal` alone). If the penalty is purely informational (already spent via normal `spendEnergy` accounting upstream), this should be explicitly documented/commented in `ReceiptCapsule` and `TransactionTrace` to prevent future confusion, and ideally covered by a regression test asserting the intended relationship between `energyUsageTotal`, `energyPenaltyTotal`, and the fee ultimately charged.

### Proof of Concept
```java
// Unit test sketch for ReceiptCapsule (or TransactionTrace) accounting invariant
@Test
public void testPenaltyIsBilled() throws Exception {
  ReceiptCapsule receipt = new ReceiptCapsule(Sha256Hash.ZERO_HASH);
  receipt.setEnergyUsageTotal(1000L);      // normal usage
  receipt.setEnergyPenaltyTotal(500L);     // CPU-time penalty

  // simulate account with just enough frozen/free energy to cover usage but not usage+penalty
  AccountCapsule caller = ...; // set up with energy left == 1000
  long balanceBefore = caller.getBalance();

  receipt.payEnergyBill(dynamicPropertiesStore, accountStore, forkController,
      /* origin */ null, caller, 0, 0, energyProcessor, now);

  // Expectation under correct accounting: usage billed should reflect
  // energyUsageTotal + energyPenaltyTotal (1500), causing an energy-fee charge
  // for the 500 excess (since account only had 1000 energy available).
  assertEquals(1500L, receipt.getEnergyUsage() /* or usage actually deducted */);
  assertTrue(receipt.getEnergyFee() > 0);

  // Actual observed behavior (bug): receipt.getEnergyUsage() == 1000,
  // receipt.getEnergyFee() == 0, and caller.getBalance() == balanceBefore,
  // i.e. the 500 penalty is never billed.
}
```
Run this against the current `ReceiptCapsule.payEnergyBill` implementation to confirm the penalty amount has no effect on `energyFee`/`useEnergy`, demonstrating the omission described above. Note: full confirmation of exploitability requires also verifying (in `VM.java`/`Program.java`) whether `energyPenaltyTotal` is additionally spent through the normal `spendEnergy` path during execution — this was not established within the current investigation and should be checked before treating this as a confirmed fee-bypass rather than a reporting-only field.

        boolean disableJavaLangMath = dynamicPropertiesStore.disableJavaLangMath();
        percent = max(Constant.ONE_HUNDRED - contractCapsule.getConsumeUserResourcePercent(
            disableJavaLangMath), 0, disableJavaLangMath);
        percent = min(percent, Constant.ONE_HUNDRED,
            disableJavaLangMath);
        originEnergyLimit = contractCapsule.getOriginEnergyLimit();
        break;
      default:
        return;
    }

    // originAccount Percent = 30%
    AccountCapsule origin = accountStore.get(originAccount);
    AccountCapsule caller = accountStore.get(callerAccount);
    if (dynamicPropertiesStore.supportUnfreezeDelay()

      // just fo caller is not origin, we set the related field for origin account
      if (origin != null && !caller.getAddress().equals(origin.getAddress())) {
        resetAccountUsage(origin,

            receipt.getOriginEnergyWindowSize(),
            receipt.getOriginEnergyMergedUsage(),
            receipt.getOriginEnergyMergedWindowSize(),
            receipt.getOriginEnergyWindowSizeV2());

  public void payEnergyBill(DynamicPropertiesStore dynamicPropertiesStore,
      AccountStore accountStore, ForkController forkController, AccountCapsule origin,
      AccountCapsule caller,
      long percent, long originEnergyLimit, EnergyProcessor energyProcessor, long now)
      throws BalanceInsufficientException {

    // Reset origin energy usage here! Because after stake 2.0, this field are reused for
    // recording pre-merge frozen energy for origin account. If total energy usage is zero, this
    // field will be a dirty record.
    this.setOriginEnergyUsage(0);

    if (receipt.getEnergyUsageTotal() <= 0) {
      return;
    }

    if (Objects.isNull(origin) && dynamicPropertiesStore.getAllowTvmConstantinople() == 1) {
      payEnergyBill(dynamicPropertiesStore, accountStore, forkController, caller,
          receipt.getEnergyUsageTotal(), receipt.getResult(), energyProcessor, now);
      return;
    }
    boolean disableJavaLangMath = dynamicPropertiesStore.disableJavaLangMath();

    if ((!Objects.isNull(origin)) && caller.getAddress().equals(origin.getAddress())) {
      payEnergyBill(dynamicPropertiesStore, accountStore, forkController, caller,
          receipt.getEnergyUsageTotal(), receipt.getResult(), energyProcessor, now);
    } else {
      long originUsage = multiplyExact(receipt.getEnergyUsageTotal(), percent, disableJavaLangMath)
          / 100;
      originUsage = getOriginUsage(dynamicPropertiesStore, origin, originEnergyLimit,
          energyProcessor,
          originUsage);

      long callerUsage = receipt.getEnergyUsageTotal() - originUsage;
      energyProcessor.useEnergy(origin, originUsage, now);
      this.setOriginEnergyUsage(originUsage);
      payEnergyBill(dynamicPropertiesStore, accountStore, forkController,
          caller, callerUsage, receipt.getResult(), energyProcessor, now);
    }
  }
