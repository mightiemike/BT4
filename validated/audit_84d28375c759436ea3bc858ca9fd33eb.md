### Title
Sandwich-attackable AutoSwap slippage bound lets an unprivileged trader extract inbound-deposit and gas-refund value from protocol-executed Uniswap V3 swaps - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/outbound.go)

### Summary
Push Chain's node code executes real Uniswap V3 swaps on behalf of users/protocol in two places: `CallPRC20DepositAutoSwap` (inbound `GAS_AND_PAYLOAD` deposits, called from `execute_inbound_gas*.go`) and `applyGasRefund` → `CallUniversalCoreRefundUnusedGas` (outbound gas refunds, `x/uexecutor/keeper/outbound.go:213-234`). Both derive their slippage protection (`minPCOut`/`minOut`) from a `GetSwapQuote` view call fetched inside the same handler, using a fixed 5% tolerance [1](#0-0) . Because these are Cosmos SDK messages (`MsgVoteInbound`/`MsgVoteOutbound`) whose execution order and inclusion an unprivileged user can observe and front-run/back-run in the mempool, an attacker can pre-move the on-chain Uniswap pool price used by `GetSwapQuote`/`CallEVM` swap execution (`x/uexecutor/keeper/evm.go:502-538`), forcing the protocol-executed swap to land at the worse end of the 5% band, then reverse the trade afterward — a sandwich attack structurally identical to the Malt "stabilize" sandwich in the reference report: the honest/automatic protocol action (swap-for-refund or swap-for-deposit) is executed at a price the attacker has manipulated just before it, and reversed just after, extracting value that should have accrued to the user/protocol.

### Finding Description
- `GetSwapQuote` performs a `CallEVM` (non-commit) `quoteExactInputSingle` against the live Uniswap V3 pool state at the time of the enclosing keeper call [2](#0-1) .
- The result is used unmodified to derive a `minPCOut` bound at 95% of the quote (`applyGasRefund`) or passed by the caller (`CallPRC20DepositAutoSwap`) [3](#0-2) .
- The actual swap execution (`depositPRC20WithAutoSwap` / `refundUnusedGas` with `withSwap=true`) happens via `DerivedEVMCall` in the same or a later transaction that is committed to the chain through validator votes (`MsgVoteOutbound`, `MsgVoteInbound`) — both are ordinary, unprivileged-observable transactions whose fee-market gasless/priority path is documented as reachable by any relayer/validator submitting the vote [4](#0-3) .
- Because the 5% band is fixed and derived from a spot quote rather than a TWAP or a caller-supplied minimum reflecting real market conditions, an attacker who can influence pool price around the block in which the vote transaction executes (buy pressure before, sell after) can force the protocol's swap to execute near the boundary of that 5% band, extracting the difference between fair price and the executed price — the same "sandwich the protocol's own on-chain price-moving action" pattern as the Malt `stabilize()` bug.
- This differs from the classic MEV/AMM slippage risk borne by an ordinary end user because the swapped funds are **protocol/user-owed refund or deposit value** (`gasFee - gasFeeUsed` excess, or bridged deposit auto-swap proceeds), i.e., value that would otherwise fully accrue to the refund recipient/depositor is partially captured by the sandwicher.

### Impact Explanation
Funds affected are the outbound gas-fee refund (`applyGasRefund`) and inbound auto-swap deposit proceeds (`CallPRC20DepositAutoSwap`) — both are user/protocol-owed value flowing through `UniversalCore`'s Uniswap V3 integration. A sandwich attacker can skim up to the full 5% slippage allowance from each such swap, systematically extracting value from every gas refund and PRC20 auto-swap deposit that is large enough to matter, at the expense of the intended recipient. This matches the "Allowed Impact Gate" category of corruption of PRC20/native asset accounting, gas/refund accounting reachable via honest validators processing ordinary inbound/outbound votes.

### Likelihood Explanation
Medium. It requires the attacker to (a) identify pending `MsgVoteOutbound`/`MsgVoteInbound` transactions in the mempool that will trigger a refund/auto-swap, and (b) have enough capital/liquidity access to move the specific Uniswap V3 pool price within the block window and reverse it profitably net of gas and slippage. This is comparable in structure and difficulty to the original Malt finding (Medium severity, sandwich requiring flash-loan-level capital), and Push Chain's fixed 5%/no-TWAP design makes the attack surface concretely present rather than merely theoretical, but it depends on transaction visibility and per-pool liquidity depth, which is not verified in this repo (values like pool depth, mempool privacy, and block-builder behavior are chain/infra parameters outside this codebase).

### Recommendation
- Replace the fixed 5%-off-spot-quote slippage bound with a much tighter, TWAP-based, or governance-configurable bound, and/or compute the quote as close as possible (same EVM state) to swap execution rather than allowing it to be set well ahead of commit.
- Consider bounding refund/auto-swap size to reduce sandwich profitability, or route large refunds through a batched/delayed mechanism resistant to per-transaction MEV.
- Emit and monitor for outsized deviation between `GetSwapQuote` estimate and actual `amountOut` realized by the swap, aborting/falling back to the no-swap path (already implemented as `Step 2` in `applyGasRefund`) when deviation exceeds a safety threshold.

### Proof of Concept
1. Attacker monitors the mempool/recently-voted `MsgVoteOutbound` messages for an outbound with a large `GasFee - GasFeeUsed` excess, which will trigger `applyGasRefund` → `CallUniversalCoreRefundUnusedGas(withSwap=true)` [5](#0-4) .
2. Before the finalizing vote lands, attacker submits a large swap on the relevant `gasToken/WPC` Uniswap V3 pool to push the price so that a subsequent `prc20 → wpc` swap yields less PC than fair value, but still within the 5% tolerance computed from the (now-skewed) `GetSwapQuote` [2](#0-1) .
3. The protocol's `refundUnusedGas`/auto-swap executes at the skewed price, and the recipient receives ~5% less PC than fair value; the attacker reverses their swap immediately after, capturing the difference as profit — mirroring the Malt `stabilize()` sandwich pattern from the source report.

Note: this analysis is based on static code review; I could not confirm (without a running testnet/mempool) the actual transaction-ordering guarantees, pool liquidity depth, or whether existing infra-level MEV protections (e.g., private mempools, proposer-controlled ordering) already mitigate this in production. If those mitigations exist at the infra layer, this finding's practical likelihood would be reduced accordingly.

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
