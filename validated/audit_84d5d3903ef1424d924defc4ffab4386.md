### Title
OAuth state cookie signature verification does not enforce the cookie's own expiration invariant server-side, extending the OAuth CSRF replay window ([File: packages/apps/shopify-api/runtime/http/cookies.ts])

### Summary
The reported bug class is about a validator-count invariant (`stoppedValidatorCounts[i]` must be monotonic/bounded) being trusted and stored without being enforced on-chain before use, allowing manipulation. The closest reachable analog in `shopify-app-js` is in the cookie-signing/verification primitive used to protect the OAuth `state` nonce: the signature-verification invariant "a signed value is only valid before its declared expiration" is never actually checked server-side, so a stale-but-still-signed cookie remains accepted indefinitely.

### Finding Description
When beginning OAuth, the library signs and stores the CSRF `state` nonce in a cookie with a declared expiration of 60 seconds: [1](#0-0) 

That `expires` value is only ever encoded into the outgoing `Set-Cookie` header attribute via `Cookies.encodeCookie`, and is purely advisory metadata for the browser: [2](#0-1) 

On the verification side, `getAndVerify`/`isSignedCookieValid` only recompute and compare the HMAC signature of the raw cookie *value* — the `expires` timestamp is never part of the signed payload (`createCookieSignature` only signs `value`, not `value + expiry`), and no expiry/staleness check is performed at verification time: [3](#0-2) 

This is used directly in the OAuth callback to accept the `state` cookie without any freshness check: [4](#0-3) 

Contrast this with the JWT session-token path, where expiration (`exp`/`nbf`) is embedded in the signed payload and is enforced by the JWT library itself at verification time with an explicit clock tolerance: [5](#0-4) 

So while session tokens correctly enforce the "not-expired" invariant as part of cryptographic verification, the OAuth state cookie's intended 60-second liveness window is an invariant that exists only in comments/intent (`expires: new Date(Date.now() + 60000)`) and browser-side cleanup, and is not enforced by the server that actually trusts the signature.

### Impact Explanation
Because the expiry is not bound into the signed payload nor checked at `getAndVerify` time, any previously-issued, validly-signed `shopify_app_state` cookie/signature pair remains cryptographically "valid" to the server forever (or at least well beyond the intended 60-second CSRF window), as long as the value/signature pair is presented again with a matching `state` query parameter and a valid Shopify HMAC on the callback query. This weakens the intended defense-in-depth of a short-lived OAuth nonce: the nonce's protective value is meant to be time-bound, but the invariant is silently unenforced, so any mechanism that causes an old signed cookie to be re-sent (e.g., non-browser HTTP clients, cookie jars that don't purge on schedule, replay via saved requests) extends the window in which a CSRF-style OAuth completion could succeed.

### Likelihood Explanation
Exploiting this specifically requires an attacker to be able to replay a previously valid `shopify_app_state` + `shopify_app_state.sig` cookie pair alongside a request that also satisfies the Shopify-signed HMAC and matching `state` — the same value/signature the legitimate flow would have used within its original 60-second window. This is a genuine missing invariant enforcement in the underlying trust primitive rather than a directly self-contained unauthenticated exploit, so likelihood is moderate: it primarily matters for non-browser callers or any flow where cookies are retained/reused past their intended lifetime, since the expiry is never actually validated by the verifying code.

### Recommendation
Bind the expiration into the signed payload (e.g., sign `value + expiresAtTimestamp`) and reject in `isSignedCookieValid`/`getAndVerify` if `Date.now()` is past that embedded timestamp, mirroring how `decodeSessionToken` enforces `exp`/`nbf` as part of JWT verification rather than relying solely on the `Set-Cookie` `expires` attribute that only the browser is expected to honor.

### Proof of Concept
1. Call `shopify.auth.begin(...)`, capturing the `Set-Cookie` response containing `shopify_app_state=<state>` and `shopify_app_state.sig=<signature>`.
2. Wait more than 60 seconds (past the intended `expires` window) — the cookie is logically supposed to be dead.
3. Replay the exact same `Cookie: shopify_app_state=<state>; shopify_app_state.sig=<signature>` header directly (bypassing browser cookie expiry) against `shopify.auth.callback(...)` with a query string containing `state=<state>` and a currently-valid Shopify HMAC/timestamp.
4. Observe that `cookies.getAndVerify(STATE_COOKIE_NAME)` in [6](#0-5)  succeeds because only the signature is checked, not the elapsed time, confirming the expiry invariant is unenforced server-side.

  static encodeCookie(data: CookieData): string {
    let result = '';
    result += `${data.name}=${data.value};`;
    result += Object.entries(data)
      .filter(([key]) => !['name', 'value', 'expires'].includes(key))
      .map(([key, value]) => `${key}=${value}`)
      .join('; ');
    if (data.expires) {
      result += ';';
      result += `expires=${data.expires.toUTCString()}`;
    }
    return result;
  }

  private get canSign() {
    return this.keys?.length > 0;
  }

  set(name: string, value: string, opts: Partial<CookieData> = {}): void {
    this.outgoingCookieJar[name] = {
      ...opts,
      name,
      value,
    };
    this.updateHeader();
  }

  async setAndSign(
    name: string,
    value: string,
    opts: Partial<CookieData> = {},
  ): Promise<void> {
    if (!this.canSign) {
      throw Error('No keys provided for signing.');
    }
    this.set(name, value, opts);
    const sigName = `${name}.sig`;
    const signature = await createCookieSignature(this.keys[0], value);
    this.set(sigName, signature, opts);
    this.updateHeader();
  }

  async isSignedCookieValid(cookieName: string): Promise<boolean> {
    const signedCookieName = `${cookieName}.sig`;
    if (
      !this.cookieExists(cookieName) ||
      !this.cookieExists(signedCookieName)
    ) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }
    const cookieValue = this.get(cookieName);
    const signature = this.get(signedCookieName);

    if (!cookieValue || !signature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    const allCheckSignatures = await Promise.all(
      this.keys.map((key) => createCookieSignature(key, cookieValue)),
    );

    const validSignature = allCheckSignatures.some((checkSignature) =>
      safelyCompareSignatures(checkSignature, signature),
    );

    if (!validSignature) {
      this.deleteInvalidCookies(cookieName, signedCookieName);
      return false;
    }

    return true;
  }
