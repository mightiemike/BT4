### Title
Instantaneous, flash-manipulable `TotalNetWeight`/`TotalEnergyWeight` used for per-account resource-limit accounting - ([File: chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java])

### Summary
Beanstalk's Gauge Point bug arises because a distribution ratio for a shared resource is computed from an instantaneous, single-block-manipulable total value instead of a time-weighted average. java-tron has an analogous pattern: `DynamicPropertiesStore.getTotalNetWeight()` / `getTotalEnergyWeight()` are global, instantaneously mutable accumulators that are read live to compute every account's proportional bandwidth/energy limit, and they can be inflated and deflated within the same block via unrestricted `FreezeBalanceV2`/`UnfreezeBalanceV2` transactions from any account.

### Finding Description
`FreezeBalanceV2Processor.execute` and `FreezeBalanceV2Actuator` increase `TotalNetWeight`/`TotalEnergyWeight` immediately when a user freezes TRX [1](#0-0) . `UnfreezeBalanceV2Actuator.validate` performs no minimum holding-period / lock-time check before allowing the frozen balance to be unfrozen again — it only checks that sufficient frozen balance exists and that the unfreezing-times limit (`UNFREEZE_MAX_TIMES`) is not exceeded [2](#0-1) . `UnfreezeBalanceV2Actuator.execute` then immediately decreases `TotalNetWeight`/`TotalEnergyWeight` back down via `updateTotalResourceWeight` [3](#0-2) [4](#0-3) .

This global total is read live and directly determines every other account's proportional bandwidth/energy limit for that instant: `calculateGlobalNetLimit`/`calculateGlobalNetLimitV2` compute `netWeight * (totalNetLimit / totalNetWeight)` [5](#0-4) , and the analogous energy computation exists for `TotalEnergyWeight`. Because this ratio is recomputed on every transaction (not fixed for an epoch like Beanstalk's per-Season Gauge Points), the exposure window for exploitation is limited to the time between the flash freeze and the flash unfreeze (potentially within the same block via multiple transactions, since no lock period is enforced), rather than persisting for a full "Season"-equivalent cycle.

### Impact Explanation
An attacker can broadcast a large `FreezeBalanceV2Contract` (BANDWIDTH or ENERGY) transaction, momentarily and massively inflating `TotalNetWeight`/`TotalEnergyWeight`, and then immediately broadcast an `UnfreezeBalanceV2Contract` to reverse it, since no minimum freeze duration is enforced before unfreezing is permitted. During the window in which the weight is inflated, every other account's computed `netLimit`/`energyLimit` (`frozenBalance/TRX_PRECISION * totalLimit/totalWeight`) is depressed, which can push honest accounts' available free resource below what is needed for their pending transactions, causing spurious `AccountResourceInsufficientException` / bandwidth-fee charges for transactions submitted in the same window. This is a resource-accounting/DoS-style griefing vector rather than a fund-theft vector — comparable in class, though narrower in duration, to the reported Beanstalk issue (the report itself notes the underlying incentive/attack surface is low-severity).

### Likelihood Explanation
Likelihood is low-to-moderate: the attacker must temporarily lock (not spend) a very large amount of TRX to meaningfully move `TotalNetWeight`/`TotalEnergyWeight` (which scale with the entire network's frozen stake), and the manipulation window is only as long as it takes to include both the freeze and unfreeze transactions, unlike Beanstalk's full-Season exposure. There is also no economic incentive beyond griefing, since resource weight changes net to zero after the unfreeze completes.

### Recommendation
Compute `TotalNetWeight`/`TotalEnergyWeight` contributions using a time-weighted or block-height-gated snapshot (e.g., require frozen balance to exist for a minimum number of blocks before it counts toward global weight, or use the weight value from the start of the block/window rather than the live value) instead of applying flash freeze/unfreeze deltas instantaneously to the value used for the current-block resource-limit ratio calculation.

### Proof of Concept
1. Attacker account A holds enough TRX to noticeably move `TotalNetWeight` relative to current network total.
2. A broadcasts `FreezeBalanceV2Contract` (resource=BANDWIDTH) with a large `frozen_balance`; this immediately calls `repo.addTotalNetWeight(newNetWeight - oldNetWeight)` [6](#0-5) , inflating `TotalNetWeight`.
3. While inflated, any other account B's `calculateGlobalNetLimit` result is proportionally reduced, since `totalNetWeight` is the divisor [7](#0-6) ; B's transaction may fail bandwidth checks it would otherwise pass.
4. A then broadcasts `UnfreezeBalanceV2Contract` for the same amount — `UnfreezeBalanceV2Actuator.validate` does not require any elapsed lock time [8](#0-7)  — restoring `TotalNetWeight` to its prior value and recovering A's TRX (subject only to the normal unfreeze withdrawal delay for the actual balance return, not for the weight change).

Note: I was unable to fully verify within the available exploration whether transaction ordering/block-packing constraints (e.g., mempool ordering, gas/bandwidth cost of the freeze/unfreeze transactions themselves) would meaningfully limit an attacker's ability to guarantee both transactions land in the same block or in immediate succession before a victim's transaction is processed; this would need dynamic/testnet verification to establish concrete exploitability and quantify real-world impact magnitude.

  public void updateTotalResourceWeight(AccountCapsule accountCapsule,
                                        Common.ResourceCode freezeType,
                                        long unfreezeBalance,
                                        Repository repo) {
    switch (freezeType) {
      case BANDWIDTH:
        long oldNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForBandwidthV2(-unfreezeBalance);
        long newNetWeight = accountCapsule.getFrozenV2BalanceWithDelegated(BANDWIDTH) / TRX_PRECISION;
        repo.addTotalNetWeight(newNetWeight - oldNetWeight);
        break;
      case ENERGY:
        long oldEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        accountCapsule.addFrozenBalanceForEnergyV2(-unfreezeBalance);
        long newEnergyWeight = accountCapsule.getFrozenV2BalanceWithDelegated(ENERGY) / TRX_PRECISION;
        repo.addTotalEnergyWeight(newEnergyWeight - oldEnergyWeight);
        break;
      case TRON_POWER:
        long oldTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        accountCapsule.addFrozenForTronPowerV2(-unfreezeBalance);
        long newTPWeight = accountCapsule.getTronPowerFrozenV2Balance() / TRX_PRECISION;
        repo.addTotalTronPowerWeight(newTPWeight - oldTPWeight);
        break;
      default:
        //this should never happen
        break;
    }
  }

  public long calculateGlobalNetLimit(AccountCapsule accountCapsule) {
    long frozeBalance = accountCapsule.getAllFrozenBalanceForBandwidth();
    if (dynamicPropertiesStore.supportUnfreezeDelay()) {
      return calculateGlobalNetLimitV2(frozeBalance);
    }
    if (frozeBalance < TRX_PRECISION) {
      return 0;
    }
    long totalNetLimit = chainBaseManager.getDynamicPropertiesStore().getTotalNetLimit();
    long totalNetWeight = chainBaseManager.getDynamicPropertiesStore().getTotalNetWeight();
    if (dynamicPropertiesStore.allowNewReward() && totalNetWeight <= 0) {
      return 0;
    }
    if (totalNetWeight == 0) {
      return 0;
    }
    if (hardenCalculation()) {
      return calculateGlobalLimitV1(frozeBalance, totalNetLimit, totalNetWeight);
    }
    long netWeight = frozeBalance / TRX_PRECISION;
    return (long) (netWeight * ((double) totalNetLimit / totalNetWeight));
  }

  public long calculateGlobalNetLimitV2(long frozeBalance) {
    long totalNetLimit = dynamicPropertiesStore.getTotalNetLimit();
    long totalNetWeight = dynamicPropertiesStore.getTotalNetWeight();
    if (totalNetWeight == 0) {
      return 0;
    }
    if (hardenCalculation()) {
      return calculateGlobalLimitV2(frozeBalance, totalNetLimit, totalNetWeight);
    }
    double netWeight = (double) frozeBalance / TRX_PRECISION;
    return (long) (netWeight * ((double) totalNetLimit / totalNetWeight));
  }
