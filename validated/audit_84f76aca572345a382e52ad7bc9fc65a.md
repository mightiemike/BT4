### Title
Unbounded WebAuthn credential enrollment per account leads to login-latency DoS via `web_authns` table growth - ([File: core/sessions/webauthn.go])

### Summary
`BeginWebAuthnRegistration`/`FinishWebAuthnRegistration` and the `AddCredentialToUser` helper impose no limit on how many WebAuthn credentials a single authenticated user can register. Since `CreateSession` calls `GetUserWebAuthn` to load *all* rows for that email on every login attempt, an authenticated low-privilege user can inflate their own `web_authns` row count arbitrarily, degrading their own login latency and growing the table without bound.

### Finding Description
The registration flow is: `WebAuthnController.BeginRegistration` → `sessions.WebAuthnSessionStore.BeginWebAuthnRegistration` [1](#0-0)  and `WebAuthnController.FinishRegistration` → `FinishWebAuthnRegistration` → `sessions.AddCredentialToUser` → `orm.SaveWebAuthn`, which is a plain `INSERT INTO web_authns` with no per-user row cap or uniqueness constraint beyond the exclude-list hint sent to the client [2](#0-1) [3](#0-2) [4](#0-3) .

`CredentialExcludeList` (built from `duoWebAuthUserFromUser(user, uwas)`) is only advisory browser-side UX to avoid re-registering the *same* physical authenticator; it does not prevent registering additional distinct (including synthetic/virtual) authenticators, and it is not a server-side authorization/cap check [5](#0-4) .

Every login of that account subsequently calls `GetUserWebAuthn`, which does `SELECT ... FROM web_authns WHERE LOWER(email) = $1` with no `LIMIT`, loading the full credential set into memory and iterating it during `FinishWebAuthnLogin`/`BeginWebAuthnLogin` verification [6](#0-5) [7](#0-6) . `SessionsController.Create` also calls `GetUserWebAuthn` up front on every login attempt to decide whether to route through the WebAuthn flow, so the query executes even before password comparison completes in that branch order [8](#0-7) .

Neither `BeginWebAuthnRegistration`, `FinishWebAuthnRegistration`, nor `AddCredentialToUser` enforce a maximum credential count, and no rate limit specific to registration exists beyond the generic global API rate limiter applied to all routes.

### Impact Explanation
The impact is scoped to the attacker's own account: an authenticated user can bloat `web_authns` rows tied to their own email, increasing the cost (query size, JSON unmarshal work, verification loop) of every future `CreateSession` call for that account, degrading their own login latency, and consuming DB storage. This does not directly cross into other users' sessions/accounts because `GetUserWebAuthn` filters by `email`, so other accounts' `CreateSession` calls are not slowed by this account's row count. At very large enrollment volumes this also creates general DB table bloat (index/table growth) that could contribute to broader resource pressure, but that is a secondary/indirect effect and not demonstrated to cause node-wide auth outage on its own.

### Likelihood Explanation
Feasible for any authenticated low-privilege user with valid credentials: the flow only requires repeatedly calling the registration begin/finish endpoints with distinct virtual authenticator responses (no distinct hardware is strictly required if the WebAuthn origin/attestation checks can be satisfied by a software authenticator in a test/PoC harness). It is fully repeatable and requires no special privilege beyond a normal login session.

### Recommendation
Enforce a maximum number of enrolled WebAuthn credentials per user (e.g., reject `FinishWebAuthnRegistration`/`AddCredentialToUser` once a configurable cap, such as 5–10, is reached) and add a `LIMIT`/count check in `GetUserWebAuthn` or a dedicated `CountUserWebAuthn` query before insert. Additionally, apply a stricter per-user rate limit on the `/webauthn/begin` and `/webauthn/finish` endpoints beyond the generic API rate limiter.

### Proof of Concept
Integration test plan:
1. Create a test user via `cltest.MustRandomUser` and log in to obtain an authenticated session.
2. In a loop (e.g., N=1000+), call `sessions.AddCredentialToUser` (or drive the full `BeginWebAuthnRegistration`/`FinishWebAuthnRegistration` HTTP flow with a software/virtual authenticator) with distinct `webauthn.Credential.ID` values for the same user email, as in the existing `TestORM_WebAuthn` test pattern [9](#0-8) .
3. Assert `orm.GetUserWebAuthn` returns N rows with no rejection at any point (no cap enforced).
4. Measure `orm.CreateSession` wall-clock latency before and after the bulk insert for that user; assert latency growth correlates with row count, demonstrating the missing cap and its DoS effect on the account's login path.

	if err != nil {
		w.App.GetLogger().Errorf("failed to obtain current user MFA tokens: error in GetUserWebAuthn: %s", err)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("unable to register key"))
		return
	}

	webAuthnConfig := w.App.GetWebAuthnConfiguration()

	credential, err := w.inProgressRegistrationsStore.FinishWebAuthnRegistration(*user, uwas, c.Request, webAuthnConfig)
	if err != nil {
		w.App.GetLogger().Errorf("error in FinishWebAuthnRegistration: %s", err)

		return
	}

		w.App.GetLogger().Errorf("Could not save WebAuthn credential to DB for user: %s", user.Email)
		jsonAPIError(c, http.StatusInternalServerError, errors.New("internal Server Error"))
		return
	}

func AddCredentialToUser(ctx context.Context, ap AuthenticationProvider, email string, credential *webauthn.Credential) error {
	credj, err := json.Marshal(credential)
	if err != nil {
		return err
	}

	token := WebAuthn{
		Email:         email,
		PublicKeyData: sqlxTypes.JSONText(credj),
	}
	return ap.SaveWebAuthn(ctx, &token)
}

// GetUserWebAuthn will return a list of structures representing all enrolled WebAuthn
// tokens for the user. This list must be used when logging in (for obvious reasons) but
// must also be used for registration to prevent the user from enrolling the same hardware
// token multiple times.
func (o *orm) GetUserWebAuthn(ctx context.Context, email string) ([]sessions.WebAuthn, error) {
	var uwas []sessions.WebAuthn
	err := o.ds.SelectContext(ctx, &uwas, "SELECT email, public_key_data FROM web_authns WHERE LOWER(email) = $1", strings.ToLower(email))
	if err != nil {
		return uwas, err
	}
	// In the event of not found, there is no MFA on this account and it is not an error
	// so this returns either an empty list or list of WebAuthn rows
	return uwas, nil
}
