## Title
Cairo 0 contract classes bypass declaration re-verification in `ContractClassManager`, allowing stale/undeclared classes to be executed — ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` caches compiled classes in a long-lived, process-global `ContractClassManager` cache (`RawClassCache`). When a cache hit occurs, the code re-verifies declaration status via `state_reader.is_declared()` **only for Cairo1 classes**; Cairo0 (`RunnableCompiledClass::V0`) cache hits are returned unconditionally with no re-check. Because `is_declared` is explicitly documented to always return `false` for Cairo0 classes, there is no mechanism to detect that a previously-cached Cairo0 class is no longer declared in the current canonical state (e.g., after its declaring block was reverted). This mirrors the Rancher bug class: a permission/authorization artifact (“this class is usable”) is cached, and the cleanup/revocation path (state revert removing the class from `deprecated_declared_classes`/`DeprecatedDeclaredClassesTable`) does not propagate to the derived authorization cache, so stale access persists.

### Finding Description
- `get_compiled_from_class_manager` in [1](#0-0)  checks the class cache first; for `RunnableCompiledClass::V0(_)` it takes the empty match arm (`{}`) and returns the cached class as-is, while for any other variant it calls `self.state_reader.is_declared(class_hash)` and errors out if the class is no longer declared, explicitly noting: *"since existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)."*
- The `FetchCompiledClasses::is_declared` contract itself states: *"Returns whether the given class hash corresponds to a declared Cairo 1 class. Cairo 0 classes always return `false`"* [2](#0-1) , which is why the V0 branch cannot use the same re-verification: doing so would always report Cairo0 classes as undeclared.
- Storage-level revert logic confirms that a Cairo0 declaration is a genuine, revertible, block-scoped authorization fact: `delete_deprecated_declared_classes` removes the class from the `DeprecatedDeclaredClassesTable` when the block that declared it is reverted [3](#0-2) , and the dedicated tests `declare_revert_declare_scenario` / `declare_revert_declare_without_classes_scenario` verify that after `revert_state_diff`, a Cairo0 class is no longer declared at that state [4](#0-3) .
- However, `ContractClassManager`'s in-memory `RawClassCache` (`class_cache`) is a long-lived structure (`GlobalContractCache`, backed by an LRU `SizedCache`) that is populated by `set_and_compile` and is **not** invalidated by `revert_block`. `revert_block` in `apollo_reverts` only touches the persistent storage tables (`revert_header`, `revert_body`, `revert_state_diff`, etc.) [5](#0-4)  and never calls `contract_class_manager.clear()` (the only observed callers of `.clear()` are `native_class_manager.rs`, `contract_class_manager.rs` themselves and `py_block_executor.rs`, none of which are wired into the revert path).
- Consequently, a node that has previously cached a Cairo0 class (via a prior `execute_declare_transaction`/`get_compiled_class` call while the class was declared in a block that is later reverted, e.g. due to a reorg) will continue to serve that stale, now-undeclared class from cache indefinitely, because the V0 branch performs no re-authorization check — unlike the explicit protection built in for Cairo1.

### Impact Explanation
This produces exactly the honest-node divergence pattern the scope calls out: a node with a cold cache queries `state_reader.get_compiled_classes()` for the class hash, finds it absent from `DeprecatedDeclaredClassesTable`, and correctly raises `StateError::UndeclaredClassHash` — causing a transaction that references that class hash (deploy/invoke/declare) to fail. A node with a warm cache (which previously served the class before the revert) returns the stale compiled class successfully and executes the transaction. Two honest nodes therefore reach different execution results / different resulting state (execution success vs. rejection, differing state diffs and state roots) for the same block, which can prevent consensus on the block's state commitment or allow execution of logic that should be treated as calling to a non-existent/undeclared class — an authorization bypass analogous to the orphaned-role-binding issue, where the enforcement point (`is_declared` re-check) is present for one code path (Cairo1) but missing for another (Cairo0).

### Likelihood Explanation
Likelihood depends on a preceding chain reorg/revert of a block that declared a Cairo0 class, combined with that class hash having been accessed (and thus cached) by the node beforehand. Reorgs of Starknet's sequencer occur in defined circumstances (e.g., L1 reorg propagation or explicit `RevertConfig`), and Cairo0 classes, while legacy, are still supported and can still be declared/used in constructor/deploy/invoke calls that a single external transaction submitter fully controls (choosing to reference a specific class hash). No malicious operator/proposer action beyond a normal transaction referencing the class hash is required to trigger the divergent execution outcome once the environmental precondition (revert + stale cache) exists.

### Recommendation
Apply the same re-verification defense used for Cairo1 classes to Cairo0 classes: extend `FetchCompiledClasses::is_declared` (or introduce an equivalent check backed by `DeprecatedDeclaredClassesTable`/`get_deprecated_class_definition_block_number`) so V0 cache hits are also validated against current canonical state before being returned, or alternatively invalidate/clear the relevant `ContractClassManager` cache entries as part of the storage revert path (`revert_block` / `revert_state_diff`) so that reverted class declarations cannot be served from any cache layer.

### Proof of Concept
1. Node A executes block N containing `execute_declare_transaction` (or a deploy referencing class hash `CH`) for a Cairo0 class `CH`; `get_compiled_class(CH)` is called, populating `ContractClassManager`'s cache via `set_and_compile` [6](#0-5) .
2. Block N is reverted (e.g., via `RevertConfig`/`revert_blocks_and_eternal_pending` → `revert_block`), which deletes `CH` from `DeprecatedDeclaredClassesTable` as shown by `delete_deprecated_declared_classes` [3](#0-2) , but does not touch `ContractClassManager`'s in-memory cache.
3. A new block N (or later) contains a transaction that again references `CH` without re-declaring it.
4. On Node A (warm cache): `get_compiled_from_class_manager` hits the cache, matches `RunnableCompiledClass::V0(_) => {}`, skips any declared-check, and returns the stale class — transaction executes successfully.
5. On Node B (cold cache, e.g., freshly synced): `get_compiled_from_class_manager` misses the cache, calls `state_reader.get_compiled_classes(CH)`, which fails to find `CH` in `DeprecatedDeclaredClassesTable` and returns `StateError::UndeclaredClassHash` — transaction fails.
6. Node A and Node B compute different state diffs/roots for the same block, demonstrating consensus-breaking divergence.

    fn get_compiled_from_class_manager(

        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}

fn delete_deprecated_declared_classes<'env>(
    txn: &'env DbTransaction<'env, RW>,
    block_number: BlockNumber,
    thin_state_diff: &ThinStateDiff,
    deprecated_declared_classes_table: &'env DeprecatedDeclaredClassesTable<'env>,
    file_handlers: &FileHandlers<RW>,
) -> StorageResult<IndexMap<ClassHash, DeprecatedContractClass>> {
    // Class hashes of the contracts that were deployed in this block.
    let deployed_contracts_class_hashes = thin_state_diff.deployed_contracts.values();

    // Merge the class hashes from the state diff and from the deployed contracts into a single
    // unique set.
    let class_hashes: HashSet<&ClassHash> = thin_state_diff
        .deprecated_declared_classes
        .iter()
        .chain(deployed_contracts_class_hashes)
        .collect();

    let mut deleted_data = IndexMap::new();
    for class_hash in class_hashes {
        // If the class is not in the deprecated classes table, it means that either we didn't
        // download it yet or the hash is of a deployed contract of a new class type. We've decided
        // to avoid deleting these classes because they're from at most 0.11.
        if let Some(IndexedDeprecatedContractClass {
            block_number: declared_block_number,
            location_in_file,
        }) = deprecated_declared_classes_table.get(txn, class_hash)?
        {
            // If the class was declared in a different block then we should'nt delete it.
            if block_number == declared_block_number {
                deleted_data.insert(
                    *class_hash,
                    file_handlers.get_deprecated_contract_class_unchecked(location_in_file)?,
                );
                deprecated_declared_classes_table.delete(txn, class_hash)?;
            }
        }
    }

    Ok(deleted_data)
}
