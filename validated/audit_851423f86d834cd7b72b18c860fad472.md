### Title
Starknet OS `execute_replace_class` accepts an undeclared/invalid class hash, diverging from Blockifier's authorization check - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall writes an arbitrary attacker-supplied `class_hash` into a contract's state entry without verifying that the class hash corresponds to a declared, Cairo1 contract class. The blockifier (Rust) execution engine, which is supposed to be semantically equivalent to the OS re-execution, does enforce this check. This is the same bug class as the referenced CVE: a component fails to verify that a resource being "linked" (here, a contract address being linked to a class hash) is one the caller is actually authorized/entitled to reference, permitting an unauthorized/invalid binding.

### Finding Description
`execute_replace_class` in `syscall_impls.cairo` reads the requested `class_hash` from the syscall request and directly updates the contract's `StateEntry` with it, with only an explicit `TODO` marking the missing validation: [1](#0-0) 

No check exists here (nor in the deprecated Cairo0 syscall path, `execute_replace_class` in `deprecated_execute_syscalls.cairo`) that the class hash is declared or that it is a Cairo1 class: [2](#0-1) 

By contrast, the blockifier's Rust implementation of the same syscall (`SyscallHandlerBase::replace_class`) explicitly reads the compiled class (which fails with `UndeclaredClassHash` if not declared) and rejects non-Cairo1 classes: [3](#0-2) 

This exact authorization gap is also demonstrated by blockifier's own tests, which assert that replacing to an undeclared class hash must fail with "is not declared": [4](#0-3) 

The Starknet OS (the Cairo program used to independently re-execute a block's transactions and produce the state diff / STARK proof consumed for state commitment) is meant to enforce identical semantics to blockifier so that the committed state and proof faithfully reflect the protocol's execution rules. Since the OS's `execute_replace_class` omits the "is declared" / "is Cairo1" check that blockifier enforces, any contract invoked by an ordinary, unprivileged transaction can issue a `replace_class` syscall with a `class_hash` that was never declared (or that is a Cairo0/deprecated class hash), and the OS accepts it, updating `contract_state_changes` to point the calling contract's class hash at a nonexistent/invalid class.

### Impact Explanation
This is reachable purely by an ordinary invoke transaction calling any contract that issues a `replace_class` syscall (a standard, permissionless account/contract capability) — no special privilege, staking, or operator role is required. The impact is state corruption of the calling contract:
- The contract's `class_hash` state entry is set to a class hash that has no corresponding compiled class, so any subsequent call into that contract (via any node/execution engine that trusts this class hash, e.g. `get_class_hash_at`) fails to resolve the compiled class, effectively **permanently bricking/freezing the contract** (and any funds/logic locked behind it) — a "permanent freezing of funds" outcome per the validation criteria.
- Because the OS's execution rules are laxer than blockifier's here, this creates a **honest-node/OS divergence**: blockifier (used by the sequencer to build/execute the block) enforces the "is declared" + "is Cairo1" invariant, while the OS re-execution that ultimately produces the proven state diff and commitment does not. Any code path or component that relies on the OS's Cairo semantics as the canonical definition of correct execution (rather than blockifier's Rust mirror) can end up committing/proving a state transition that blockifier itself would have rejected, i.e., a state root that does not match what the documented protocol rules (as enforced in blockifier) would produce.

### Likelihood Explanation
High likelihood of reachability: `replace_class` is a standard, unauthenticated syscall available to any deployed contract; a single low-privileged invoke transaction calling into a contract with a `replace_class` call (or any account/dummy contract executing it on the caller's behalf) triggers this code path in the OS. No special conditions, timing, or privileged roles are needed — only that the OS (rather than blockifier) is the component performing the check in the given execution context.

### Recommendation
Add, in `execute_replace_class` (both the current `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo`), an explicit check — mirroring blockifier's `SyscallHandlerBase::replace_class` — that:
1. The target `class_hash` corresponds to a declared contract class (reject with the same class of error blockifier uses, e.g. "not declared"), and
2. The declared class is Cairo1 (reject Cairo0/deprecated class hashes), 
before writing the new `StateEntry` into `contract_state_changes`, so OS semantics remain consistent with blockifier's authorization rules and cannot diverge from the on-chain execution invariants.

### Proof of Concept
1. Declare no class with hash `X` (i.e., `X` is not present in `contract_class_changes` / declared classes for the block).
2. Submit a normal, low-privileged Invoke transaction whose target contract's entry point calls `replace_class(class_hash=X)` (e.g., the `test_replace_class` external function present in test fixtures: [5](#0-4) ).
3. In blockifier's Rust execution path, this call fails with `UndeclaredClassHash`/"is not declared" (as demonstrated in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
4. In the Starknet OS Cairo re-execution path (`execute_replace_class` in `syscall_impls.cairo`), the same call succeeds unconditionally and updates `contract_state_changes` for the calling contract to class hash `X`, with no corresponding validation — demonstrating the divergence and the resulting corrupted/unresolvable contract state.

```rust
    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
```
