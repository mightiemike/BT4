## Title
Unauthenticated PBFT commit messages with an empty signature list bypass quorum validation and permanently poison `PbftSignDataStore`, blocking legitimate finality proofs - (File: `framework/src/main/java/org/tron/core/net/messagehandler/PbftDataSyncHandler.java`)

### Summary
`PbftDataSyncHandler.validPbftSign()` only performs quorum-signature verification when the supplied `srSignList` is non-empty; if a peer sends a `PbftCommitMessage` with an **empty** signature list, the method falls through to `return true` unconditionally, treating an entirely unverified commit as valid. Combined with the "write-once" guard in `processPBFTCommitMessage()` (`pbftSignDataStore.getBlockSignData(...) == null` / `getSrSignData(...) == null`), any unauthenticated peer can pre-fill the PBFT sign-data slot for an arbitrary future block number or maintenance epoch with garbage data, permanently preventing the real, quorum-signed PBFT commit proof for that slot from ever being stored — the same "poison a monotonic/first-write guard with unvalidated attacker data" bug class as the reported `proveWorldStateCannon()` issue.

### Finding Description
`processMessage()` caches any incoming `PbftCommitMessage` from any peer with **no validation whatsoever** other than protobuf parsing: [1](#0-0) 

When the local node later reaches the corresponding block, `processPBFTCommitData()` pulls the cached message (keyed by block number / `raw.getViewN()`) and hands it to `processPBFTCommitMessage()`: [2](#0-1) 

`processPBFTCommitMessage()` gates the store write on `validPbftSign()`, then writes only if the slot is currently empty: [3](#0-2) 

The root cause is in `validPbftSign()`: the quorum check (signature-count threshold, per-signer address recovery/validation against the active SR set) is entirely wrapped inside `if (srSignList.size() != 0) { ... }`. If the list is empty, none of that logic runs and the function returns `true` by default: [4](#0-3) 

This mirrors the reported bug exactly: in `proveWorldStateCannon()`, a partially-validated input (`rlpEncodedBlockData`) is not checked against the actually-verified state, allowing an attacker to write an arbitrary value into a slot governed by a `blockNumber` monotonic guard, permanently blocking legitimate future writes. Here, an attacker-crafted `PbftCommitMessage` with an empty `dataSignList` is accepted as "valid" by `validPbftSign()` without any quorum check, and `PbftSignDataStore.putBlockSignData()` / `putSrSignData()` is a write-once-per-key store (`getBlockSignData(...) == null` guard) with no ability to overwrite a poisoned entry: [5](#0-4) 

Once poisoned, the legitimate, quorum-signed `PbftCommitMessage` sent later by real SRs for the same block/epoch will be silently dropped, because the `== null` check will always be false from that point forward.

### Impact Explanation
An unauthenticated remote peer can permanently corrupt the PBFT finality/commit-proof record for any block number or maintenance epoch of their choosing, before the legitimate quorum-signed message arrives, by simply sending a `PbftCommitMessage` with an empty signature list. This:
- Poisons `PbftSignDataStore`, which backs `getBlockPbftCommitData()` / `getSRLPbftCommitData()` — consumed by peer-to-peer PBFT commit propagation (`sendPbftCommitMessage` in `FetchInvDataMsgHandler`) and by finality/solidity confirmation logic.
- Causes divergence between nodes: nodes hit by the fake commit data before the real one will forever serve/gossip an unsigned, attacker-supplied "commit" for that block/epoch, while unaffected nodes hold the correct quorum-signed proof — an invalid-state/divergence condition in the PBFT finality subsystem.
- Cannot be healed later since the store never overwrites an existing entry, so the effect is permanent for each poisoned key, and an attacker can repeat this for many block numbers/epochs to broadly disrupt PBFT-based finality reporting.

### Likelihood Explanation
High. Reaching `processMessage()` only requires establishing a P2P connection and sending a single, cheap message; no authentication, stake, or SR privilege is required, and `allowPBFT()` merely needs to be enabled network-wide (a normal production configuration). Racing the real quorum message is straightforward since the attacker's message can be sent proactively for any future block/epoch, well before real SRs reach PBFT consensus on it.

### Recommendation
Remove the early bypass in `validPbftSign()` — quorum verification (signature count, signer-address checks) must always be performed regardless of whether `srSignList` is empty; an empty list should be treated as automatically invalid (`return false`) rather than defaulting to `true`. Additionally, consider hardening `PbftSignDataStore` writes to only accept the first entry that has passed full signature verification, and audit for any other paths where `size() == 0` is used to shortcut validation.

### Proof of Concept
1. Attacker connects as a peer to a full node with `allowPBFT()` enabled.
2. Attacker sends a `PbftCommitMessage` for `DataType.BLOCK` (or `SRL`) with `raw.getViewN()` set to a future block number `N` and an empty `dataSignList`.
3. `processMessage()` caches it unconditionally: `pbftCommitMessageCache.put(raw.getViewN(), pbftCommitMessage)`.
4. When the victim node later processes block `N`, `processPBFTCommitData(block)` retrieves the cached message and calls `processPBFTCommitMessage()`.
5. `validPbftSign(raw, emptySignList, currentSrList)` returns `true` immediately (the `if (srSignList.size() != 0)` block is skipped).
6. Because `pbftSignDataStore.getBlockSignData(N) == null`, the attacker's unsigned data is stored as the "commit" for block `N`.
7. When the real SRs later broadcast the legitimate quorum-signed PBFT commit for block `N`, `pbftSignDataStore.getBlockSignData(N) == null` is now false, so the real proof is dropped — the poisoned data on this node is permanent.

  public void processPBFTCommitData(BlockCapsule block) {
    try {
      if (!chainBaseManager.getDynamicPropertiesStore().allowPBFT()) {
        return;
      }
      long epoch = 0;
      PbftCommitMessage pbftCommitMessage = pbftCommitMessageCache.getIfPresent(block.getNum());
      pbftCommitMessageCache.invalidate(block.getNum());
      long maintenanceTimeInterval = chainBaseManager.getDynamicPropertiesStore()
          .getMaintenanceTimeInterval();
      if (pbftCommitMessage == null) {
        long round = block.getTimeStamp() / maintenanceTimeInterval;
        epoch = (round + 1) * maintenanceTimeInterval;
      } else {
        processPBFTCommitMessage(pbftCommitMessage);
        Raw raw = Raw.parseFrom(pbftCommitMessage.getPBFTCommitResult().getData());
        epoch = raw.getEpoch();
      }
      pbftCommitMessage = pbftCommitMessageCache.getIfPresent(epoch);
      pbftCommitMessageCache.invalidate(epoch);
      if (pbftCommitMessage != null) {
        processPBFTCommitMessage(pbftCommitMessage);
      }
    } catch (Exception e) {
      logger.error("", e);
    }
  }

  private void processPBFTCommitMessage(PbftCommitMessage pbftCommitMessage) {
    try {
      PbftSignDataStore pbftSignDataStore = chainBaseManager.getPbftSignDataStore();
      Raw raw = Raw.parseFrom(pbftCommitMessage.getPBFTCommitResult().getData());
      if (!validPbftSign(raw, pbftCommitMessage.getPBFTCommitResult().getSignatureList(),
          chainBaseManager.getWitnesses())) {
        return;
      }
      if (raw.getDataType() == DataType.BLOCK
          && pbftSignDataStore.getBlockSignData(raw.getViewN()) == null) {
        pbftSignDataStore.putBlockSignData(raw.getViewN(), pbftCommitMessage.getPbftSignCapsule());
        logger.info("Save the block {} pbft commit data", raw.getViewN());
      } else if (raw.getDataType() == DataType.SRL
          && pbftSignDataStore.getSrSignData(raw.getEpoch()) == null) {
        pbftSignDataStore.putSrSignData(raw.getEpoch(), pbftCommitMessage.getPbftSignCapsule());
        logger.info("Save the srl {} pbft commit data", raw.getEpoch());
      }
    } catch (InvalidProtocolBufferException e) {
      logger.error("", e);
    }
  }

  private boolean validPbftSign(Raw raw, List<ByteString> srSignList,
      List<ByteString> currentSrList) {
    //valid sr list
    if (srSignList.size() != 0) {
      Set<ByteString> srSignSet = new ConcurrentSet();
      srSignSet.addAll(srSignList);
      if (srSignSet.size() < Param.getInstance().getAgreeNodeCount()) {
        logger.error("sr sign count {} < sr count * 2/3 + 1 == {}", srSignSet.size(),
            Param.getInstance().getAgreeNodeCount());
        return false;
      }
      byte[] dataHash = Sha256Hash.hash(true, raw.toByteArray());
      Set<ByteString> srSet = Sets.newHashSet(currentSrList);
      List<Future<Boolean>> futureList = new ArrayList<>();
      for (ByteString sign : srSignList) {
        futureList.add(executorService.submit(
            new ValidPbftSignTask(raw.getViewN(), srSignSet, dataHash, srSet, sign)));
      }
      for (Future<Boolean> future : futureList) {
        try {
          if (!future.get()) {
            return false;
          }
        } catch (Exception e) {
          logger.error("", e);
        }
      }
      if (srSignSet.size() != 0) {
        return false;
      }
    }
    return true;
  }
