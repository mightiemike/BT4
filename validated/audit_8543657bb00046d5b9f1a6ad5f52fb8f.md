### Title
Sandwich-attack drainable PRC20→PC swaps in gas-abstraction deposit/refund flows due to spot-quote-based slippage bound - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The `uexecutor` module performs on-chain Uniswap-style swaps (PRC20 → WPC/native PC) as part of gas-abstraction deposits and gas-refund flows. The slippage floor (`minPCOut`) used to protect these module-originated swaps is computed from a spot quote (`GetSwapQuote`) fetched *at the moment the finalizing transaction executes*, not from any price reference set before the triggering event became publicly visible. Because the triggering event (the quorum-crossing `MsgVoteInbound`, or an outbound observation) is visible in the mempool before it lands on-chain, an unprivileged attacker can front-run it to manipulate the AMM pool price, causing the module's own quote-then-swap sequence to compute `minPCOut` off an already-manipulated price, and then back-run to capture the difference — a classic sandwich attack extracting value from user/protocol-owned PRC20 being auto-swapped.

### Finding Description
`GetSwapQuote` [1](#0-0)  queries `QuoterV2.quoteExactInputSingle` for the current expected output, and the caller then derives `minPCOut` as `quote * 95 / 100` (a flat 5% tolerance) immediately before executing the real swap via `CallPRC20DepositAutoSwap` / `DerivedEVMCall`: [2](#0-1) 

The same pattern is repeated for the `GAS_AND_PAYLOAD` deposit-autoswap path: [3](#0-2) 

and for the gas-refund swap in outbound processing: [4](#0-3) 

The critical issue is *when* this quote+swap sequence runs. `ExecuteInboundGas` is dispatched synchronously from `VoteInbound` the moment the inbound ballot reaches quorum: [5](#0-4) 

The quorum-crossing `MsgVoteInbound` (typically the 3rd validator's vote out of 4, or `⌈2/3⌉+1` in general) is an ordinary, unprivileged, publicly broadcast Cosmos transaction sitting in the mempool before it is included in a block. Any observer can see it coming and know that a PRC20→WPC swap of a known `amount` (the inbound deposit amount) is about to occon-chain. Because `minPCOut` is derived from the pool's *current* state at execution time rather than from a price committed to before the triggering event was broadcast (e.g., a TWAP oracle or a price snapshot taken when the inbound was first observed off-chain), the 5% band only bounds slippage caused by the module's own trade — it does nothing to prevent the attacker from moving the pool price by more than 5% via a front-run swap immediately before the finalizing vote lands, then reversing that trade after the module's swap executes at the manipulated rate. The identical structural issue exists for `applyGasRefund`'s refund-swap and the `GAS_AND_PAYLOAD` autoswap.

This is the same bug class as the SynthChef `reinvest` report: the fix ("add a minimum return check") is present here in form, but the reference price used to compute that minimum is itself attacker-influenceable at the exact block where it matters, rendering the protection largely cosmetic against a determined MEV actor.

### Impact Explanation
An attacker can extract value from every gas-abstraction deposit or gas refund that routes through `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas(withSwap=true)`, reducing the amount of native PC ultimately credited to the user's UEA (for gas-abstraction deposits) or refunded to the sender (for gas refunds). This is unauthorized value extraction from user/protocol-controlled funds passing through the module's own on-chain trades, reachable purely by an unprivileged actor watching the public mempool — no validator, relayer, or TSS compromise is required.

### Likelihood Explanation
High for any external chain/token pair where the underlying WPC/PRC20 Uniswap-style pool has shallow liquidity relative to the deposit size, since a 5% price move is often cheap to engineer with a temporary swap. The trigger event (`MsgVoteInbound` crossing quorum, or the observation crossing quorum for outbound refunds) is deterministic and publicly visible before inclusion, and Push Chain's block production model does not shield it from front-running by ordinary users.

### Recommendation
Do not use a spot quote taken at execution time as the sole reference for `minPCOut`. Instead:
- Use a time-weighted average price (TWAP) from the AMM, or a governance/registry-configured reference price, when computing `minPCOut`, rather than `GetSwapQuote`'s instantaneous result.
- Alternatively, cap the acceptable deviation between the reference price used at inbound-observation time (before the triggering vote is broadcast) and the price at execution time, and revert (fall back to no-swap deposit) if that deviation exceeds a safe bound rather than always proceeding with a fixed 5% band computed from the manipulated spot price.
- Consider routing these swaps through a private/soft-commit mechanism or applying MEV-resistant execution (e.g., aggregated batch execution) so the triggering vote does not reveal an exact, exploitable trade size and direction ahead of execution.

### Proof of Concept
1. Attacker monitors the mempool for `MsgVoteInbound` transactions on Push Chain that will cross the 2/3 quorum threshold for a `TxType_GAS` or `TxType_GAS_AND_PAYLOAD` inbound with a known `Amount` and `AssetAddr` (visible in the plaintext message).
2. Just before this transaction is included, attacker submits a large swap in the same PRC20/WPC Uniswap pool (`quoterAddr`/`wpcAddr` are fixed, registry-known addresses obtained via `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`) to move the price against the upcoming module-originated swap direction, with higher gas/priority to land first.
3. The quorum-crossing `MsgVoteInbound` lands and finalizes the ballot; `ExecuteInboundGas` runs synchronously, calling `GetSwapQuote` (now reflecting the manipulated pool state) and computing `minPCOut = quote*95/100` off that manipulated price, then executing `CallPRC20DepositAutoSwap` at the bad rate.
4. Attacker submits a back-run transaction reversing the initial swap, capturing the price difference, funded by the reduced PC amount the user's UEA received relative to fair value.
5. Repeat for `applyGasRefund`'s gas-token→PC swap on any outbound observation crossing quorum.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```
