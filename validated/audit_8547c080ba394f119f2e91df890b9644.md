## Finding

The SVM event pipeline classifies and parses events purely by scanning `tx.Meta.LogMessages` for `"Program data: "` prefixed lines and matching the first 8 bytes against a discriminator table — it never verifies that the log line was emitted from *within* the gateway program's own `invoke ... success` frame.

### Finding Description

`EventListener.processSignatureBatch` fetches candidate signatures via `GetSignaturesForAddress(gatewayAddr, ...)`, which returns any transaction that merely references the gateway address as an account key — not only transactions where the gateway program is actually invoked. [1](#0-0) 

For every returned transaction, it iterates *all* log lines in `tx.Meta.LogMessages` and calls `determineEventType(log)`, which only checks that the line starts with `"Program data: "` and that the base64-decoded payload's first 8 bytes match a known event discriminator — with no linkage to the specific `Program <id> invoke [...] / success` bracket that Solana runtimes emit around each program's execution: [2](#0-1) [3](#0-2) 

Matching lines are then handed to `ParseEvent` → `parseSendFundsEvent` → `parseUniversalTxEvent`/`decodeUniversalTxEvent`, which trusts the decoded bytes wholesale to build sender, recipient, token, amount, raw payload, revert-recipient, tx-type, and `FromCEA` fields, and stores the result as a `store.EventTypeInbound` `StatusPending` event: [4](#0-3) [5](#0-4) 

Because Solana log output within a single transaction is a flat, program-attribution-free stream of strings (only bracketed by `"Program <id> invoke [depth]"` / `"Program <id> success"` markers that this code never inspects), any account — including an attacker-deployed program — invoked in the *same transaction* can emit an arbitrary `sol_log_data("Program data: <base64>")` line with a discriminator that collides with `send_funds`, `finalize_universal_tx`, `revert_universal_tx`, or `funds_rescued`. The attacker only needs the transaction to reference the real gateway address as one of its account keys (e.g., a harmless read-only, non-signer inclusion) so that `GetSignaturesForAddress` surfaces it; no real gateway instruction, and no real fund movement, needs to occur.

Because this event-derived data is what the universal-client observer produces as its local candidate observation (and, per the code shown, all honest nodes run identical parsing logic against the same public log stream), this is not a "malicious validator" issue — it is a client-side authentication gap: the observation itself can be forged by an ordinary, unprivileged transaction submitter, and every honest node parsing the same public chain data would independently derive the same forged event and could converge on it.

### Impact Explanation

An attacker can synthesize a fabricated `send_funds` inbound event with completely attacker-chosen sender, recipient, bridge token, amount, payload, revert recipient, and `tx_type`/`FromCEA` flags, without transferring any real funds through the actual gateway program. If this forged event is accepted into the inbound-voting/finalization pipeline as legitimate, it could lead to unauthorized mint/release of PRC20 or native assets on Push Chain (or a spoofed outbound/finalize/refund/rescue observation on the destination side), which matches the in-scope impact of "forged...inbound...state accepted through user-reachable flows with honest validators and honest nodes" and "unauthorized mint... of value."

### Likelihood Explanation

Exploitability depends on whether downstream ballot/finalization logic (outside the files reviewed here) re-derives or independently cross-checks that the event genuinely originated from within the gateway program's own invocation frame (e.g., by walking `tx.Meta.InnerInstructions`/instruction call stack, or re-simulating/re-deriving the event strictly from the gateway's own instruction data rather than trusting arbitrary log lines). I could not verify that from the code inspected; if no such re-validation exists anywhere in the pipeline, likelihood is high since it only requires deploying a trivial program and submitting one transaction. If a stronger validation layer exists elsewhere (not found in the reviewed files), this specific parser-level gap could still be a defense-in-depth issue but not independently exploitable.

### Recommendation

When scanning `tx.Meta.LogMessages`, track program invocation depth/bracketing (`Program <id> invoke [depth]` ... `Program <id> success`) and only accept `"Program data: "` lines emitted while the current program-invocation context equals the configured gateway program ID, rather than pattern/discriminator-matching on the flat log stream. Alternatively, validate the event against `tx.Meta.InnerInstructions` to confirm the instruction was actually executed by the gateway program ID with matching accounts.

### Proof of Concept

1. Deploy an attacker-controlled Solana program `Evil`.
2. Build a transaction whose account list includes the real gateway program address (e.g., as a harmless read-only account) so it passes `GetSignaturesForAddress(gatewayAddr, ...)`, and that invokes `Evil`.
3. Inside `Evil`, call `sol_log_data` with bytes: `send_funds` discriminator (8 bytes) + attacker-chosen sender (32 bytes) + attacker-chosen recipient (20 bytes) + arbitrary token pubkey (32 bytes) + attacker-chosen amount (8 bytes LE) + payload length/bytes + revert-recipient pubkey + tx_type + sig-length/bytes + fromCEA byte.
4. Submit the transaction as an ordinary unprivileged user (no real funds move through the gateway).
5. The universal client's `EventListener.processSignatureBatch` picks up the transaction, `determineEventType` matches the discriminator, and `parseSendFundsEvent`/`decodeUniversalTxEvent` produce a fully attacker-controlled `store.EventTypeInbound` event, which is inserted via `chainStore.InsertEventIfNotExists` for downstream inbound processing.

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

// parseSendFundsEvent parses a sendFunds event as UniversalTx
func parseSendFundsEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	if len(decoded) < 8 {
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing sendFunds event")

	// Create store.Event
	event := &store.Event{
		EventID:           eventID,
		BlockHeight:       slot,
		Type:              store.EventTypeInbound, // Gateway events from external chains are INBOUND
		Status:            store.StatusPending,
		ExpiryBlockHeight: 0, // Will be set based on confirmation type if needed
	}

	// Parse event data from this log
	parseUniversalTxEvent(event, decoded, logIndex, chainID, logger)

	return event

// decodeUniversalTxEvent decodes a TxWithFunds event
func decodeUniversalTxEvent(data []byte, logger zerolog.Logger) (*common.UniversalTx, error) {
	if len(data) < 120 {
		logger.Warn().
			Int("data_len", len(data)).
			Msg("data might be too short for complete TxWithFunds event")
	}

	offset := 8
	payload := &common.UniversalTx{}

	// Parse sender (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for sender")
	}
	sender := solana.PublicKey(data[offset : offset+32])
	// Convert sender to hex format
	senderHex, err := base58ToHex(sender.String())
	if err != nil {
		logger.Warn().Err(err).Msg("failed to convert sender to hex, using base58")
		payload.Sender = sender.String()
	} else {
		payload.Sender = senderHex
	}
	offset += 32

	// Parse recipient (20 bytes - byte20 format)
	if len(data) < offset+20 {
		return nil, fmt.Errorf("not enough data for recipient")
	}
	// Convert 20 bytes to hex string (0x + 40 hex chars)
	recipientBytes := data[offset : offset+20]
	payload.Recipient = "0x" + hex.EncodeToString(recipientBytes)
	offset += 20

	// Parse bridge_token (32 bytes)
	if len(data) < offset+32 {
		return nil, fmt.Errorf("not enough data for bridge_token")
	}
	bridgeToken := solana.PublicKey(data[offset : offset+32])
	payload.Token = bridgeToken.String()
	offset += 32

	// Parse bridge_amount (8 bytes)
	if len(data) < offset+8 {
		return nil, fmt.Errorf("not enough data for bridge_amount")
	}
	bridgeAmount := binary.LittleEndian.Uint64(data[offset : offset+8])
	payload.Amount = fmt.Sprintf("%d", bridgeAmount)
	offset += 8

	// Parse data field length (4 bytes)
	if len(data) < offset+4 {
		logger.Warn().Msg("not enough data for data field length")
		return payload, nil
	}
	dataLen := binary.LittleEndian.Uint32(data[offset : offset+4])
	offset += 4

	// Parse data field
	if len(data) < offset+int(dataLen) {
		logger.Warn().
			Uint32("expected_len", dataLen).
			Int("available", len(data)-offset).
			Msg("not enough data for data field")
		return payload, nil
	}
	if dataLen > 0 {
		dataField := data[offset : offset+int(dataLen)]
		payload.RawPayload = "0x" + hex.EncodeToString(dataField)
		offset += int(dataLen)
	}

	// Parse revert_recipient (Pubkey)
	if len(data) < offset+32 {
		logger.Warn().Msg("not enough data for revert recipient")
		return payload, nil
	}
	revertRecipient := solana.PublicKey(data[offset : offset+32])
	payload.RevertFundRecipient = revertRecipient.String()
	offset += 32
