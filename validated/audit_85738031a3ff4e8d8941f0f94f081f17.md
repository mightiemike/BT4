### Title
Unbounded gzip decompression of a user-submitted Declare-v1 `program` field causes out-of-memory / node crash - (File: crates/apollo_rpc/src/v0_8/api/mod.rs)

### Summary
The Nervos CKB advisory describes a decompression bomb: a peer can send a small compressed payload whose decompressed size is unbounded, forcing the node to allocate an arbitrarily large buffer and exhaust memory. The Starknet sequencer contains an analogous unbounded-decompression sink reachable directly from an unprivileged JSON-RPC caller, in `decompress_program` in `crates/apollo_rpc/src/v0_8/api/mod.rs`.

### Finding Description
`decompress_program` decodes a base64 string and gzip-decompresses it into an in-memory `Vec<u8>` with no size limit whatsoever: [1](#0-0) 

The `// TODO(dan): add time and size limits.` comment confirms the limit is missing by design/oversight. This function is invoked by `user_deprecated_contract_class_to_sn_api`, which converts a user-supplied `BroadcastedDeclareV1Transaction.contract_class.compressed_program` (a base64 gzip blob fully controlled by the caller) into an executable `ContractClass`: [2](#0-1) 

This conversion is reached through `TryFrom<BroadcastedDeclareTransaction> for ExecutableTransactionInput`, specifically the `V1` branch, which any RPC caller can trigger by submitting a `BroadcastedDeclareV1Transaction` to execution-simulation endpoints (e.g. `estimate_fee`, `simulate_transactions`, `call`): [3](#0-2) 

Elsewhere in the codebase, the equivalent decompression helper is properly bounded — `decode_and_decompress_with_size_limit` in `starknet_api::compression_utils` caps the read via `.take(max_size + 1)` before allocating, and callers such as `DeprecatedGatewaySierraContractClass::convert_to_sierra_contract_class` and the Cairo0 protobuf conversion pass an explicit `max_size`: [4](#0-3) [5](#0-4) 

`decompress_program` in `apollo_rpc` was never updated to use this bounded pattern, leaving one code path unprotected against the exact bug class described in the report: small compressed input, unbounded decompressed output, unconditional memory allocation before any size check.

### Impact Explanation
A single unprivileged JSON-RPC request containing a crafted Declare-v1 transaction with a gzip bomb (e.g., a few KB compressed expanding to gigabytes) causes the node to allocate an unbounded buffer in `decoder.read_to_end(&mut decompressed, ...)`. On resource-constrained nodes this can exhaust memory and crash the process (OOM-killed), causing that node to stop confirming/serving RPC requests — a denial-of-service against the node's execution/estimate-fee/simulate RPC surface reachable by any external caller, without needing to broadcast or pay for an actual transaction.

### Likelihood Explanation
The path is trivially reachable: no authentication, no fee payment, and no prior on-chain state is required — a single crafted RPC call to `estimate_fee`, `simulate_transactions`, or `call` with a `BroadcastedDeclareV1Transaction` triggers `decompress_program` directly on attacker-controlled bytes. The absence of any size limit (confirmed by the `TODO` comment) and comparison with the properly bounded counterpart elsewhere in the codebase make this straightforward to exploit.

### Recommendation
Replace the unbounded `GzDecoder::read_to_end` in `decompress_program` (`crates/apollo_rpc/src/v0_8/api/mod.rs`) with a bounded read using the same pattern as `starknet_api::compression_utils::decode_and_decompress_with_size_limit` — e.g. wrap the decoder with `.take(max_size + 1)` and reject with an error if the decompressed length exceeds a configured maximum (consistent with `MAX_CAIRO0_PROGRAM_SIZE` / `DEFAULT_MAX_SIERRA_PROGRAM_SIZE` used elsewhere).

### Proof of Concept
1. Craft a small gzip payload that decompresses to a very large buffer (a classic zip/gzip bomb, e.g. compress several GB of repeated zero bytes to a few KB).
2. Base64-encode it and place it as `contract_class.program` in a `BroadcastedDeclareV1Transaction`.
3. Send it to the node's `starknet_estimateFee` or `starknet_simulateTransactions` RPC endpoint.
4. `user_deprecated_contract_class_to_sn_api` → `decompress_program` (`crates/apollo_rpc/src/v0_8/api/mod.rs:671-682`) decompresses the payload with no size bound, allocating memory proportional to the attacker-chosen decompressed size, leading to excessive memory usage / OOM on the node.

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
