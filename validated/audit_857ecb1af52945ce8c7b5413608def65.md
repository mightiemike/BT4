### Title
Length-prefix truncation in lazy field indexer causes protobuf-go message field boundary desync - ([File: internal/protolazy/lazy.go])

### Summary
`buildIndex()` in `internal/protolazy/lazy.go` and its helper `BufferReader.DecodeVarint32()` in `internal/protolazy/bufferreader.go` decode the length prefix of `BytesType` (length-delimited) fields into a **32-bit** integer, even though the routine accepts a 5-byte varint that can encode up to 35 bits of value. Because the accumulator is a `uint32`, the final byte's contribution is shifted left by 28 using fixed-width 32-bit arithmetic, silently discarding bits 32-34 instead of raising an overflow error. This produces a field length that is smaller than the length actually encoded on the wire, causing the lazy-field indexer to stop consuming the field early and reinterpret the remaining bytes of that field's payload as unrelated tag/field data for the rest of the message — the same class of bug as the kernel's `clen` truncation that made `sip_help_tcp()` misjudge the SIP message boundary and reparse trailing payload as a new message.

### Finding Description
`BufferReader.DecodeVarint32()` [1](#0-0)  takes the fast path whenever `len(buf)-i >= 5`, manually unrolling up to 5 varint bytes into a `uint32 x`:
```
x |= (v & 127) << 28
```
Because `x` is `uint32`, this shift/OR keeps only bits 0-31 of the true value; if the 5th byte has bits 4-6 set (values ≥ 0x10), the contribution to bits 32-34 of the correctly-decoded 64-bit value is silently dropped rather than triggering `errOverflow`. This differs from the safe generic decoder `protowire.ConsumeVarint`, which operates on `uint64` throughout [2](#0-1) .

This exact vulnerable routine is invoked directly in `buildIndex()`, the function that scans a message's bytes to build the lazy field index used for on-demand field materialization:
```go
case protowire.BytesType:
    var n uint32
    n, err = r.DecodeVarint32()
    if err == nil {
        err = r.Skip(int(n))
    }
``` [3](#0-2) 

`buildIndex` is called from `FindFieldInProto`, which is invoked whenever a lazily-decoded message field is first read via a generated getter (`mi.lazyUnmarshal`) [4](#0-3) [5](#0-4) . Lazy decoding is **enabled by default**: `enableLazy` defaults to `1` unless the process sets `GOPROTODEBUG=nolazy` [6](#0-5) , and `unmarshalPointer` routes any message with a lazy-eligible offset through `unmarshalPointerLazy` on a normal `proto.Unmarshal` call with the default (`protoregistry.GlobalTypes`) resolver [7](#0-6) .

Because the truncated length (`n`) is smaller than what a correct 64-bit decode would have produced, `buildIndex` stops "skipping" the current field's payload early. The bytes that were actually part of that field's payload are then parsed as if they were the start of a brand-new tag/field, producing spurious `IndexEntry` records with attacker-influenced `FieldNum`, `Start`, and `End` offsets [8](#0-7) . When a legitimate field number later happens to match one of these fabricated entries, `FindFieldInProto`/`lookupField` will hand back a byte range that does not correspond to the field's true wire-format boundary [9](#0-8) , and `mi.unmarshalField` will decode that mis-sliced range as the field's declared Go type [5](#0-4) .

### Impact Explanation
An attacker who controls the bytes passed to a standard `proto.Unmarshal` call (the default binary parser, trusted schema, no custom resolver) can craft a 5-byte length varint whose low-order 32 bits decode to an attacker-chosen small value while the true (uint64) value is larger. This desynchronizes the lazy-field index from the true wire structure, so bytes intended for one field are attributed to a different (or fabricated) field number/offset. Depending on which fields collide, this can cause a getter to return values derived from bytes that were never intended for that field — an integrity/data-confusion issue that undermines the invariant that decoded field values correspond to their wire-encoded bytes. It does not require attacker network privilege, a malicious peer identity, or a custom descriptor — only attacker-controlled serialized bytes reaching `proto.Unmarshal`, which is the standard trust boundary protobuf-go is meant to defend at the wire-parsing layer.

### Likelihood Explanation
Lazy decoding is on by default for any message type with lazy-eligible (message-typed) fields, so this code path is exercised on ordinary `proto.Unmarshal` + later field-access usage without any special configuration. The only precondition is that the message contains at least one `BytesType`-encoded field whose length varint spans exactly 5 bytes with the top bits of the 5th byte set — an easily crafted, valid-looking wire payload.

### Recommendation
Change `BufferReader.DecodeVarint32` (and the inlined copy in `buildIndex`) to decode into a `uint64` accumulator (as `protowire.ConsumeVarint`/`DecodeVarint` already do) and only convert/validate against `uint32`/`int` bounds after the full 64-bit value is known, returning an overflow/error when the value exceeds what can be safely represented as a byte count for the remaining buffer, rather than silently truncating.

### Proof of Concept
```go
package main

import (
    "fmt"
    "google.golang.org/protobuf/internal/protolazy"
)

func main() {
    // 5-byte varint whose low 32 bits decode to a small value,
    // but whose true 64-bit value has bit 32 set (byte4 = 0x10).
    buf := []byte{0xFF, 0xFF, 0xFF, 0xFF, 0x10}
    r := protolazy.NewBufferReader(buf)
    n, err := r.DecodeVarint32()
    fmt.Printf("DecodeVarint32 -> n=%d err=%v\n", n, err)
    // n = 0x0FFFFFFF (268435455)

    r2 := protolazy.NewBufferReader(buf)
    v, err2 := r2.DecodeVarint()
    fmt.Printf("DecodeVarint (correct 64-bit) -> v=%d err=%v\n", v, err2)
    // v = 0x10FFFFFFF (4562027519) -- the true encoded value
}
```
Embedding such a 5-byte length prefix ahead of a `BytesType` field payload in a message that is lazily decoded will cause `buildIndex` to believe the field ends `2^32` bytes earlier than intended, causing the remainder of that field's payload to be reparsed as unrelated tag/field data in the lazy index — demonstrating the same length-truncation-driven message-boundary desync described in the reported kernel CVE.

func (b *BufferReader) DecodeVarint32() (x uint32, err error) {
	i := b.Pos
	buf := b.Buf

	if i >= len(buf) {
		return 0, io.ErrUnexpectedEOF
	} else if buf[i] < 0x80 {
		b.Pos++
		return uint32(buf[i]), nil
	} else if len(buf)-i < 5 {
		v, err := b.DecodeVarintSlow()
		return uint32(v), err
	}

	var v uint32
	// we already checked the first byte
	x = uint32(buf[i]) & 127
	i++

	v = uint32(buf[i])
	i++
	x |= (v & 127) << 7
	if v < 128 {
		goto done
	}

	v = uint32(buf[i])
	i++
	x |= (v & 127) << 14
	if v < 128 {
		goto done
	}

	if v < 128 {
		goto done
	}

	v = uint32(buf[i])
	i++
	x |= (v & 127) << 28
	if v < 128 {
		goto done
	}

	return 0, errOverflow

	return

// FindFieldInProto looks for field fieldNum in lazyUnmarshalInfo information
// (including protobuf), returns startOffset/endOffset/found.
func (lazy *XXX_lazyUnmarshalInfo) FindFieldInProto(fieldNum uint32) (start, end uint32, found, multipleContiguous bool, multipleEntries []IndexEntry) {
	if lazy.Protobuf == nil {
		// There is no backing protobuf for this message -- it was made from a builder
		return 0, 0, false, false, nil
	}
	index := atomicLoadIndex(&lazy.index)
	if index == nil {
		r, err := buildIndex(lazy.Protobuf)
		if err != nil {
			panic(fmt.Sprintf("findFieldInfo: error building index when looking for field %d: %v", fieldNum, err))
		}
		// lazy.index is a pointer to the slice returned by BuildIndex
		index = &r
		atomicStoreIndex(&lazy.index, index)
	}
	return lookupField(index, fieldNum)
}

func lookupField(indexp *[]IndexEntry, fieldNum uint32) (start, end uint32, found bool, multipleContiguous bool, multipleEntries []IndexEntry) {
	// The pointer indexp to the index was already loaded atomically.
	// The slice is uniquely associated with the pointer, so it doesn't
	// need to be loaded atomically.
	index := *indexp
	for i, entry := range index {
		if fieldNum == entry.FieldNum {
			if i < len(index)-1 && entry.FieldNum == index[i+1].FieldNum {
				// Handle the uncommon case where there are
				// repeated entries for the same field which
				// are not contiguous in the protobuf.
				multiple := make([]IndexEntry, 1, 2)
				multiple[0] = IndexEntry{fieldNum, entry.Start, entry.End, entry.MultipleContiguous}
				i++
				for i < len(index) && index[i].FieldNum == fieldNum {
					multiple = append(multiple, IndexEntry{fieldNum, index[i].Start, index[i].End, index[i].MultipleContiguous})
					i++
				}
				return 0, 0, false, false, multiple

			}
			return entry.Start, entry.End, true, entry.MultipleContiguous, nil
		}
		if fieldNum < entry.FieldNum {
			return 0, 0, false, false, nil
		}
	}
	return 0, 0, false, false, nil

func (mi *MessageInfo) lazyUnmarshal(p pointer, num protoreflect.FieldNumber) {
	var f *coderFieldInfo
	if int(num) < len(mi.denseCoderFields) {
		f = mi.denseCoderFields[num]
	} else {
		f = mi.coderFields[num]
	}
	if f == nil {
		panic(fmt.Sprintf("lazyUnmarshal: field info for %v.%v", mi.Desc.FullName(), num))
	}
	lazy := *p.Apply(mi.lazyOffset).LazyInfoPtr()
	start, end, found, _, multipleEntries := lazy.FindFieldInProto(uint32(num))
	if !found && multipleEntries == nil {
		panic(fmt.Sprintf("lazyUnmarshal: can't find field data for %v.%v", mi.Desc.FullName(), num))
	}
	// The actual pointer in the message can not be set until the whole struct is filled in, otherwise we will have races.
	// Create another pointer and set it atomically, if we won the race and the pointer in the original message is still nil.
	fp := pointerOfValue(reflect.New(f.ft))
	if multipleEntries != nil {
		for _, entry := range multipleEntries {
			mi.unmarshalField(lazy.Buffer()[entry.Start:entry.End], fp, f, lazy, lazy.UnmarshalFlags())
		}
	} else {
		mi.unmarshalField(lazy.Buffer()[start:end], fp, f, lazy, lazy.UnmarshalFlags())
	}
	p.Apply(f.offset).AtomicSetPointerIfNil(fp.Elem())
}

func (mi *MessageInfo) unmarshalPointer(b []byte, p pointer, groupTag protowire.Number, opts unmarshalOptions) (out unmarshalOutput, err error) {
	mi.init()
	if opts.depth--; opts.depth < 0 {
		return out, errRecursionDepth
	}
	if flags.ProtoLegacy && mi.isMessageSet {
		return unmarshalMessageSet(mi, b, p, opts)
	}

	lazyDecoding := LazyEnabled() // default
	if opts.NoLazyDecoding() {
		lazyDecoding = false // explicitly disabled
	}
	if mi.lazyOffset.IsValid() && lazyDecoding {
		return mi.unmarshalPointerLazy(b, p, groupTag, opts)
	}
	return mi.unmarshalPointerEager(b, p, groupTag, opts)
}
