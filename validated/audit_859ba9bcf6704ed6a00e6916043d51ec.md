### Title
Health check silently excludes debt/collateral value of DAO-disabled assets, letting borrowers bypass `is-healthy` and strand real debt uncollateralized - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`collateral-remove` (and other health-gated flows) determines whether a user "has debt" using an **unfiltered** debt lookup, but then values that debt using a **filtered, enabled-assets-only** list. When the DAO disables an asset for debt via `v0-assets.disable`, the existence check still sees the debt (correctly), but the USD valuation fold that feeds `is-healthy` silently skips it, understating `debt-value`. This is the exact bug class from the referenced report: an aggregate existence/count check succeeds while the enumeration used for the real computation drops the disabled item.

### Finding Description
1. `collateral-remove` fetches `position` via `get-position`, then computes `has-debt` from it: [1](#0-0) 

2. The market-level `get-position` wrapper passes the currently **enabled bitmap** into `v0-market-vault.get-position`: [2](#0-1) 

3. Inside `v0-market-vault.get-position`, the **collateral** list is filtered by that enabled-mask, but the **debt** list is looked up with `MAX-U128`, i.e. debt is *not* filtered by asset enable/disable status — `has-debt` will correctly stay `true` even for a disabled debt asset: [3](#0-2) 

4. Once inside the "HAS DEBT" branch, `collateral-remove` builds `assets` via `get-assets`, which intersects the user's mask with the **currently enabled** bitmap - a disabled debt asset is dropped from this list: [4](#0-3) 

5. `get-notional-evaluation` computes `debt-total`/`collateral-total` by **folding over `assets`** (the enabled-only list), using the user's `clist`/`dlist` only as accumulator state to match against: [5](#0-4) 

Because the fold iterates over `assets` (not over `dlist`), any `dlist` entry whose asset-id is absent from `assets` (i.e. disabled) is structurally never visited, so it never contributes to `debt-total`.

6. `collateral-remove` then asserts health using this understated `debt-value`: [6](#0-5) 

7. `v0-assets.disable` is a normal, legitimate DAO action (asset deprecation), not a compromise, and does not force repayment of existing debt in that asset: [7](#0-6) 

### Impact Explanation
A borrower with debt in an asset that the DAO later disables (for debt) keeps `has-debt = true` (existence check passes, matching the original M-10 pattern), but `debt-value` used by `is-healthy` no longer includes that debt's USD value. The health check consequently overstates free capacity, letting the user withdraw collateral (or add new collateral/borrow more against the false headroom) while their real, disabled-asset debt remains unpaid and effectively invisible to solvency checks. This strands unbacked debt on the protocol's books — protocol insolvency / undercollateralized positions that cannot be correctly liquidated at their true health ratio, which is a Critical-class impact (protocol insolvency / permanent freezing/loss of lenders' funds).

### Likelihood Explanation
Requires the DAO to disable an asset for debt while borrowers still hold open debt in it — a realistic operational scenario when deprecating/migrating an asset, not requiring a DAO compromise. Once that state exists, any single call to `collateral-remove` (or `borrow`, which follows the same `get-assets`/`get-notional-evaluation` pattern) by the affected borrower exploits the mismatch in one transaction.

### Recommendation
Value debt (and collateral) using the user's actual mask, not the enabled-only intersection — e.g. resolve prices for disabled-but-held assets on demand (as already done for disabled collateral in `collateral-remove`'s `else` branch and in `process-collateral-asset`'s liquidation fallback) so `debt-value`/`collateral-value` used in `is-healthy` always reflects true outstanding debt, regardless of the asset's current enabled status.

### Proof of Concept
1. User borrows asset `X` (debt-enabled), creating real scaled debt in `v0-market-vault`.
2. DAO calls `v0-assets.disable(X, collateral=false)` to retire `X` as a debt asset; existing debt is untouched.
3. User calls `collateral-remove` on a different, still-enabled collateral asset `Y`:
   - `has-debt` = true (debt lookup uses `MAX-U128`, sees `X`'s debt).
   - `assets = get-assets(position-mask)` excludes `X` (disabled).
   - `get-notional-evaluation` folds over `assets`, never valuing `X`'s debt → `debt-value` omits `X`.
   - `is-healthy collateral-value debt-value current-ltvb` passes using the understated `debt-value`.
4. User withdraws collateral `Y` up to the (falsely) healthy capacity, leaving the position with insufficient real collateral to cover total real debt (`X` + others). [8](#0-7)

(define-public (collateral-remove (ft <ft-trait>) (amount uint) (receiver (optional principal)) (price-feeds (optional (list 3 (buff 8192)))))
  (let ((ft-address (contract-of ft))
        (asset (try! (get-asset ft-address)))
        (asset-id (get id asset))
        (account contract-caller)
        (collateral-receiver (match receiver recv recv contract-caller))
        (position (try! (get-position account)))
        (has-debt (> (len (get debt position)) u0)))

    (asserts! (> amount u0) ERR-AMOUNT-ZERO)

    (if has-debt
        ;; HAS DEBT: Full flow with price resolution and health checks
        (let ((is-collateral-enabled (get collateral asset))
              (feeds-check (try! (write-feeds price-feeds)))
              (position-mask (get mask position))
              (pos-full (if is-collateral-enabled position (try! (get-full-position account))))
              (u-debt (accrue-user-debts (get debt pos-full)))
              (u-coll (accrue-user-collateral (get collateral pos-full)))
              (assets (get-assets position-mask))
              (curr-coll-aid (find-collateral-amount (get collateral position) asset-id))
              (removing-all (is-eq amount curr-coll-aid))
              (current-group (try! (get-egroup position-mask)))
              (current-ltvb (buff-to-uint-be (get LTV-BORROW current-group)))
              (notional-valued-assets (get-notional-evaluation { position: position, assets: assets }))
              (collateral-value (get collateral notional-valued-assets))
              (debt-value (get debt notional-valued-assets))
              (removed-asset-value (find-and-resolve-asset-value assets asset-id amount true)))

          (asserts! (is-healthy collateral-value debt-value current-ltvb) ERR-UNHEALTHY)
          (asserts!
            (if is-collateral-enabled
                (let ((t (asserts! (>= collateral-value removed-asset-value) ERR-INSUFFICIENT-COLLATERAL))
                      (post-removal-collateral-value (- collateral-value removed-asset-value)))
                  (if removing-all
                      (let ((future-mask (bit-and position-mask (bit-not (pow u2 asset-id)))))
                        (try! (is-healthy-with-mask post-removal-collateral-value debt-value future-mask)))
                      (is-healthy post-removal-collateral-value debt-value current-ltvb)))
                (let ((oracle-data (get oracle asset))
                      (price (unwrap! (price-resolve oracle-data) ERR-DISABLED-COLLATERAL-PRICE-FAILED))
                      (decimals (get decimals asset))
                      (user-amount (find-collateral-amount (get collateral pos-full) asset-id))
                      (disabled-notional (normalize (* user-amount price) decimals false))
                      (removal-notional (normalize (* amount price) decimals true))
                      (total-collateral-value (+ collateral-value disabled-notional)))
                  (asserts! (>= total-collateral-value removal-notional) ERR-INSUFFICIENT-COLLATERAL)
                  (is-healthy (- total-collateral-value removal-notional) debt-value current-ltvb)))
            ERR-UNHEALTHY)

          (let ((result (try! (contract-call? .v0-market-vault collateral-remove account amount ft asset-id collateral-receiver))))
            (print { action: "collateral-remove", caller: contract-caller,
                     data: { account: account, receiver: collateral-receiver, asset-id: asset-id,
                             asset-addr: ft-address, amount: amount, updated-collateral-amount: result,
                             position-collateral-usd: collateral-value, position-debt-usd: debt-value }})
            (ok result)))
