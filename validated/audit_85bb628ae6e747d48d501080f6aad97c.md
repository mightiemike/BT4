### Title
Starknet OS `execute_replace_class` omits the declared-class check that Blockifier enforces, allowing OS re-execution to accept `replace_class` to an undeclared class hash - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The GeoLens report's root cause pattern is "authorize/validate on one referenced entity while a second, related entity that the request pulls in is never re-validated." In this sequencer, the `replace_class` syscall exhibits an analogous asymmetric-validation gap between the two independent implementations of the same syscall: Blockifier's execution-time implementation and the Starknet OS's (SNOS) Cairo implementation used for re-execution/proving.

### Finding Description
Blockifier's `replace_class` syscall handler explicitly re-authorizes the class hash the caller supplies before mutating the contract's class pointer: [1](#0-0) 
It calls `self.state.get_compiled_class(class_hash)?` — i.e. it verifies the referenced class actually exists/was declared — and rejects non-Cairo1 classes, before calling `set_class_hash_at`.

The Starknet OS's own Cairo implementation of the same syscall, `execute_replace_class` in `syscall_impls.cairo`, performs the state mutation directly from the caller-supplied `class_hash` without any equivalent check: [2](#0-1) 
Notably the code contains an explicit acknowledgement of the gap: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` immediately before the state entry is overwritten with the unvalidated `class_hash`. The deprecated Cairo0 syscall path (`execute_replace_class` in `deprecated_execute_syscalls.cairo`) has the identical omission: [3](#0-2) 

This means the OS's independent Cairo-VM re-execution of a contract's `replace_class` call does not itself re-derive/re-check that the requested class hash was declared — it is the *only* place in the two independent implementations where this authorization step is missing, exactly mirroring the GeoLens pattern of "authorize the primary resource, but not the secondarily-referenced one" (here, the referenced class hash instead of a referenced dataset).

### Impact Explanation
Blockifier (used for actual block building/execution) enforces the declared-class check and reverts a transaction that tries to `replace_class` to an undeclared class hash (`StateError::UndeclaredClassHash`), confirmed by the dedicated test: [4](#0-3) 
Because the Starknet OS is the component that re-executes the same transactions from scratch (via the real Cairo VM, not by trusting Blockifier's decision) to compute/verify the block's state commitment and to produce the STARK execution trace, a control-flow path that omits this check is a genuine soundness gap in the OS's own state-transition function: the OS's Cairo implementation, taken on its own, does not enforce that `replace_class` targets a declared class, so a class-hash/state-entry corruption that Blockifier would reject is not independently rejected by the OS's syscall implementation. This directly touches the class stated in scope ("Starknet OS re-execution", "state reads and aliasing", "syscalls") and the class of harm allowed ("wrong committed root", "honest-node divergence") because the state root the OS computes for `contract_state_changes` after `execute_replace_class` is accepted unconditionally on the caller-supplied class hash, rather than an authorized/declared one.

### Likelihood Explanation
Under normal, honest sequencer operation, Blockifier's check happens first, and the OS is fed the same accepted call tree Blockifier already produced, so this gap is typically not reachable by an honest, single, ordinary transaction in the currently deployed pipeline — it requires the OS's syscall dispatch to be exercised directly for an execution path that Blockifier itself would have rejected. This is acknowledged as unresolved/unimplemented in the code itself (the TODO comment dated 1/1/2026), which indicates the developers are aware of the gap and it has not yet been fixed, but I could not fully verify from the available code within this session whether any currently-reachable single-transaction path (e.g., differing behavior between the deprecated and non-deprecated syscall dispatch, or a corner case in how `contract_state_changes` entries are seeded for a not-yet-touched contract) allows a caller to reach `execute_replace_class` in the OS without Blockifier having already vetted the class hash. Given the explicit developer TODO, I assess this as a real but not fully proven-exploitable gap from the material inspected.

### Recommendation
Add the same "declared class" existence/version check in the OS's Cairo `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` variant) that Blockifier performs in `syscall_base.rs::replace_class` (`get_compiled_class` + Cairo1-only check), so the OS's independent re-execution enforces the same authorization/validation as Blockifier and cannot silently accept a `replace_class` to an undeclared or wrong-version class hash.

### Proof of Concept
Not independently reproducible from static inspection within this session — reproducing it would require constructing an OS/prover-level test that invokes `execute_replace_class` (or the deprecated equivalent) with a class hash that was never declared in `contract_class_changes`/global declared-class set, and observing whether the SNOS Cairo VM re-execution completes and produces a state diff/output despite the missing check, in contrast to Blockifier's `syscall_tests/replace_class.rs::undeclared_class_hash` test which confirms Blockifier itself rejects this input.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
