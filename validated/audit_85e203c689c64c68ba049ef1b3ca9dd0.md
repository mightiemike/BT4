### Title
Unbounded per-UTX `OutboundTx` linear scan lets an attacker's own payload permanently DoS voting/finalization of its own outbounds - (File: `x/uexecutor/keeper/msg_vote_outbound.go`, `x/uexecutor/keeper/create_outbound.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The reported bug class (unbounded linear scan whose length is attacker/system-influenced, run inline in a hot transaction path, causing guaranteed out-of-gas reverts) has a direct analog in `x/uexecutor`. `BuildOutboundsFromReceipt` builds one `OutboundTx` entry per matching EVM log emitted during a single inbound/payload execution, and `attachOutboundsToUtx` appends all of them, unbounded, to the same `UniversalTx.OutboundTx` slice. Every subsequent `MsgVoteOutbound` for any of these outbounds must load the whole `UniversalTx`, deserialize the entire `OutboundTx` slice, and linearly scan it (`for _, ob := range utx.OutboundTx`) to find the matching outbound by ID, then re-marshal and persist the whole record again on every vote.

### Finding Description
`BuildOutboundsFromReceipt` iterates every log in the EVM receipt produced by executing a user's payload (or an inbound's `PAYLOAD`/`FUNDS_AND_PAYLOAD` execution) and creates an `OutboundTx` for every `UniversalTxOutboundEvent` emitted by `UniversalGatewayPC`: [1](#0-0) 

There is no cap on the number of outbound events processed here, and `attachOutboundsToUtx` appends all of them to the single UTX's `OutboundTx` slice without any size limit: [2](#0-1) 

Because `MsgExecutePayload` lets any unprivileged submitter deliver a UEA-authorized payload that can call arbitrary EVM contracts (including the attacker's own helper contract that repeatedly calls the gateway's withdraw/outbound function within one EVM call), a single Push Chain transaction can generate a large number of `UniversalTxOutboundEvent` logs, all attached to the same `UniversalTx.Id`. The size of this array is bounded only by the EVM gas limit of a single Cosmos transaction — attacker-controlled, not admin-controlled.

Every subsequent vote on any one of these outbounds must resolve the outbound by scanning the entire slice: [3](#0-2) 

and any later status update repeats the same O(n) scan-and-rewrite pattern: [4](#0-3) 

There is no secondary index that maps `outboundId -> position within UTX.OutboundTx`; `PendingOutbounds` only maps `outboundId -> UniversalTxId`, so the O(1) index still requires an O(n) walk of the parent UTX's slice to locate/update the specific entry. `UniversalTx.ValidateBasic` places no upper bound on `len(OutboundTx)`: [5](#0-4) 

### Impact Explanation
Exactly like the `recordMintBestAvailableTier` case, the cost of finalizing an individual state transition (here, `MsgVoteOutbound`) grows linearly with an attacker-controllable collection size, and both the read (`UniversalTx.Get`) and write (`UpdateUniversalTx`) paths must marshal/unmarshal and rewrite the *entire* growing slice on every single vote. If an attacker inflates a UTX's `OutboundTx` slice large enough, gas/computation cost for each `MsgVoteOutbound` targeting that UTX can exceed practical transaction/block gas limits, making it impossible for Universal Validators to ever vote those outbounds to a terminal (`OBSERVED`/`REVERTED`) state. Per the module's own documented lifecycle, `PendingOutbounds` entries are *not* auto-cleaned on expiry specifically because "the user's funds are already in flight" and "auto-refund risks double-pay" — meaning outbounds that can never be voted to completion leave any externally-sent (or externally-pending) funds permanently stuck, and their `PendingOutbounds` audit-trail state permanently unresolved. This is unauthorized denial of legitimate state transitions reachable purely by an unprivileged user's own gasless `MsgExecutePayload`, with no privileged or malicious-validator assumption required.

### Likelihood Explanation
`MsgExecutePayload` is explicitly gasless and open to any signer delivering an owner-authorized payload, and the UEA can call arbitrary EVM contracts. An attacker only needs to author a UEA-owned contract that calls the gateway's outbound/withdraw entry point many times in a single call (bounded only by the EVM gas limit configured for the chain, which can be large), producing many `UniversalTxOutboundEvent` logs in one receipt. This does not require any validator collusion, admin privilege, or protocol misconfiguration — it is directly reachable through the documented normal inbound/payload execution flow.

### Recommendation
Bound the number of outbounds a single receipt/UTX may accumulate (reject or split further outbound creation past a sane per-UTX cap), and/or replace the linear `for _, ob := range utx.OutboundTx` lookups with a proper keyed index (e.g., store each `OutboundTx` under its own collection key, keyed by `outboundId`, rather than as an unbounded slice inside `UniversalTx`) so that vote/update cost is O(1) regardless of how many outbounds a UTX accumulates.

### Proof of Concept
1. Attacker deploys an EVM helper contract `Amplifier` whose function loops N times calling `UniversalGatewayPC`'s withdraw/outbound entry point (each call emits a `UniversalTxOutboundEvent`).
2. Attacker submits `MsgExecutePayload` (gasless, any signer) whose payload, executed through their own UEA, calls `Amplifier`, generating N outbound events in a single receipt, all funneled through [1](#0-0)  into `BuildOutboundsFromReceipt`, then appended via [2](#0-1)  to one `UniversalTx.OutboundTx` slice of length N.
3. Once N is large enough that a single `UniversalTx.Get` + full-slice scan + `UniversalTx.Set` inside `MsgVoteOutbound` ( [3](#0-2) ) exceeds the practical transaction gas budget, Universal Validators can never successfully vote any of the N outbounds to a terminal state, permanently stalling that UTX's outbound lifecycle.

func (k Keeper) UpdateOutbound(ctx context.Context, utxId string, outbound types.OutboundTx) error {
	k.Logger().Debug("updating outbound state",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"status", outbound.OutboundStatus.String(),
	)
	return k.UpdateUniversalTx(ctx, utxId, func(utx *types.UniversalTx) error {
		if utx.OutboundTx == nil {
			return fmt.Errorf("outbound tx list is not initialized for utx %s", utxId)
		}

		updated := false
		for i, ob := range utx.OutboundTx {
			if ob.Id == outbound.Id {
				utx.OutboundTx[i] = &outbound
				updated = true
				break
			}
		}

		if !updated {
			return fmt.Errorf(
				"outbound with id %s not found in utx %s",
				outbound.Id,
				utxId,
			)
		}

		return nil
	})
}
