## Analysis

The CVE describes a cryptographic randomness-generation flaw that lets an attacker desynchronize/break a protocol that depends on shared, reproducible secret material. The closest reachable analog in this codebase is in the Starknet OS (SNOS) hint that derives DA-encryption keys for the "encrypted state diff" (committee DA) feature.

### Title
Non-deterministic randomness in SNOS state-diff-encryption key derivation breaks OS re-execution determinism - ([File: crates/starknet_os/src/hints/hint_implementation/output.rs])

### Summary
The hint `calculate_keys_using_sha256_hash` (invoked from Cairo as `GenerateKeysUsingSha256Hash`) derives the symmetric key and per-committee-member Starknet private keys used to encrypt the DA state-diff output by seeding a SHA-256 hash with true OS randomness (`OsRng.fill_bytes`), not with any value that is fixed and reproducible from the block/transaction data. [1](#0-0) 

### Finding Description
`encrypt_state_diff` in the Cairo OS program declares `symmetric_key` and `sn_private_keys` as hint-provided (non-deterministic) `local` variables and fills them via the `GenerateKeysUsingSha256Hash` hint: [2](#0-1) 

The Rust hint implementation generates 32 bytes from `OsRng` (a true, non-reproducible entropy source) and mixes them into a SHA-256 seed that is then used, via domain-separated hashing, to derive both the symmetric key and every committee member's Starknet private key: [3](#0-2) 

Because the seed is dominated by `OsRng` output (the compressed state diff bytes are only mixed in afterward "for extra defense," not as the sole source), two independent executions of the OS program over the *same block* will derive **different** symmetric/private keys, and therefore produce a **different ciphertext** for the encrypted DA/state-diff segment (`encrypt_state_diff` → `process_data_availability` → `serialize_data_availability`), which is written into the OS's program output: [4](#0-3) 

The Starknet OS is designed to be independently re-executable/verifiable — this is explicitly a supported flow in this repository (see `blockifier_reexecution`, which recomputes block commitments and compares them against the on-chain header): [5](#0-4) 

Any party that re-runs SNOS for the same block (a prover producing a proof for an already-published block, or a full node/validator performing OS re-execution to independently confirm the block) will, whenever committee-DA encryption is enabled (`n_keys > 0`), derive different keys and hence a different encrypted DA payload/output than the one originally committed. This is the direct analog of "insufficiently random" cryptographic key generation causing loss of protocol integrity: here, true (rather than deterministically-derivable) randomness is used exactly where the protocol requires bit-for-bit reproducibility across independent honest executions.

### Impact Explanation
This breaks the fundamental soundness property of the OS: the same block input must always yield the same program output so it can be proven and independently verified. If randomness leaks into the committed output:
- Independent re-execution/verification of a block's encrypted DA segment (SNOS re-execution, mentioned explicitly as an in-scope path) will diverge from the originally published output every single time the feature is exercised, causing honest-node divergence on the computed OS output/commitment.
- A prover cannot reproducibly regenerate the exact program output that matches an already-published block, which can block fact/proof verification for that block, i.e., inability to confirm new transactions/blocks that use committee DA.

### Likelihood Explanation
This is deterministic and always triggered — it is not a probabilistic weakness but a certain divergence — every time the `n_keys > 0` (committee DA / encrypted-state-diff) branch is exercised and the OS is executed more than once for the same block (which is inherent to the prove/re-execute/verify model). No attacker action beyond causing (or the system naturally producing) blocks that use the encrypted-DA feature is required.

### Recommendation
Replace `OsRng`-derived entropy in `calculate_keys_using_sha256_hash` with a value deterministically derived from data intrinsic to the block/state transition being proven (e.g., derive the seed solely and exclusively from the compressed state diff, block hash, and/or state root, with proper domain separation), so that every honest re-execution of the same block deterministically reproduces the same symmetric key and private keys.

### Proof of Concept
1. Execute SNOS once over a block that has `n_keys > 0` (committee DA enabled); the `GenerateKeysUsingSha256Hash` hint calls `OsRng.fill_bytes` and derives `symmetric_key_A` / `sn_private_keys_A`, producing ciphertext `C_A` written into the OS output and (eventually) committed as part of the block's DA/output.
2. Re-execute SNOS a second time over the exact same block inputs (e.g., during independent OS re-execution/verification, or when a different prover instance generates the proof for that block).
3. Because step 1's seed byte source (`OsRng`) is not reproducible, `calculate_keys_using_sha256_hash` derives `symmetric_key_B ≠ symmetric_key_A`, yielding ciphertext `C_B ≠ C_A`.
4. The two "honest" executions of the same block now disagree on the OS output, demonstrating non-determinism/honest-node divergence in a consensus-relevant computation. [1](#0-0)

pub(crate) fn calculate_keys_using_sha256_hash(mut ctx: HintContext<'_>) -> OsHintResult {
    // Generate a cryptographically secure random seed.
    let mut random_bytes = [0u8; 32];
    OsRng.fill_bytes(&mut random_bytes);

    let mut hasher = Sha256::new();
    hasher.update(random_bytes);

    // In addition, hash the compressed state diff for extra defense against potential attacks on
    // randomness source.
    let compressed_start = ctx.get_ptr(Ids::CompressedStart)?;
    let compressed_end = ctx.get_ptr(Ids::CompressedEnd)?;
    let array_size = (compressed_end - compressed_start)?;
    for i in 0..array_size {
        let felt = ctx.vm.get_integer((compressed_start + i)?)?;
        hasher.update(felt.to_bytes_be());
    }
    let random_key_seed = hasher.finalize().to_vec();

    const SYM_LABEL: &[u8] = b"SYM"; // domain separation: symmetric key
    const PRIV_LABEL: &[u8] = b"PRIV"; // domain separation: private keys

    // Derive the symmetric key (full 32 bytes):
    let symmetric_key = {
        let hash = Sha256::new().chain_update(&random_key_seed).chain_update(SYM_LABEL).finalize();
        Felt::from_bytes_be(&hash.into())
    };
    ctx.insert_value(Ids::SymmetricKey, symmetric_key)?;

    // Private keys: derive with a counter and truncate to 31 bytes (248 bits)
    // to ensure result is < 2^248 < EC group order < PRIME. This is required for
    // the Diffie-Hellman elliptic curve.

    let mut priv_counter: u8 = 0;
    let mut next_private_key = || -> MaybeRelocatable {
        let hash = Sha256::new()
            .chain_update(&random_key_seed)
            .chain_update(PRIV_LABEL)
            .chain_update([priv_counter])
            .finalize();
        priv_counter += 1;

        // Use only first 31 bytes to ensure < 2^248.
        let mut key_bytes = [0u8; 32];
        key_bytes[1..].copy_from_slice(&hash[..31]);
        MaybeRelocatable::from(Felt::from_bytes_be(&key_bytes))
    };

    let n_keys = ctx.get_integer(Ids::NKeys)?;
    let num_private_keys = felt_to_usize(&n_keys)?;
    let private_keys: Vec<MaybeRelocatable> =
        (0..num_private_keys).map(|_| next_private_key()).collect();
    let private_keys_start = ctx.vm.gen_arg(&private_keys)?;

    ctx.insert_value(Ids::SnPrivateKeys, private_keys_start)?;

// Returns the final data-availability to output.
func process_data_availability{range_check_ptr, ec_op_ptr: EcOpBuiltin*}(
    state_updates_start: felt*,
    state_updates_end: felt*,
    compress_state_updates: felt,
    n_keys: felt,
    public_keys: felt*,
) -> (da_start: felt*, da_end: felt*) {
    if (compress_state_updates == 0) {
        return (da_start=state_updates_start, da_end=state_updates_end);
    }

    alloc_locals;

    // Compress the state updates.
    local compressed_start: felt*;
    %{ SetCompressedStart %}
    let compressed_dst = compressed_start;
    with compressed_dst {
        compress(data_start=state_updates_start, data_end=state_updates_end);
    }

    if (n_keys == 0) {
        // No public keys - skip the state updates encryption.
        return (da_start=compressed_start, da_end=compressed_dst);
    }

    // Encrypt the compressed state updates.
    let (encrypted_start, encrypted_end) = encrypt_state_diff(
        compressed_start=compressed_start,
        compressed_end=compressed_dst,
        n_keys=n_keys,
        public_keys=public_keys,
    );

    return (da_start=encrypted_start, da_end=encrypted_end);
}

/// Note: Blocks before v0.14.0 may include deprecated (Cairo 0) declared classes which are not
/// represented in [`CommitmentStateDiff`]; those blocks skip hash comparison below.
pub async fn compare_block_hash(
    txs_hashing_data: Vec<TransactionHashingData>,
    actual_state_diff: CommitmentStateDiff,
    block_header: &BlockHeader,
    block_number: BlockNumber,
) -> ReexecutionResult<bool> {
    let starknet_version: StarknetVersion = block_header.starknet_version.clone().try_into()?;

    let min_version: StarknetVersion =
        MIN_VERSION_FOR_BLOCK_HASH_COMPARISON.try_into().expect("Invalid min version constant.");
    if starknet_version < min_version {
        tracing::debug!(
            "Block {block_number}: skipping block hash comparison (version {} < {}).",
            block_header.starknet_version,
            MIN_VERSION_FOR_BLOCK_HASH_COMPARISON
        );
        return Ok(true);
    }

    let (commitments, _measurements) = calculate_block_commitments(
        &txs_hashing_data,
        actual_state_diff.into(),
        block_header.l1_da_mode,
        &starknet_version,
    )
    .await;

    let block_info: BlockInfo = block_header.clone().try_into()?;
    let partial_block_hash_components = PartialBlockHashComponents::new(&block_info, commitments);

    let computed_hash = calculate_block_hash(
        &partial_block_hash_components,
        block_header.new_root,
        block_header.parent_hash,
    )?;

    if computed_hash == block_header.block_hash {
        Ok(true)
    } else {
        tracing::warn!(
            "Block hash mismatch for block {block_number}.\n  expected: {}\n  actual:   {}",
            block_header.block_hash,
            computed_hash,
        );
        Ok(false)
    }
}
