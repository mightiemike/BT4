### Title
Autoswap and gas-refund paths use unprotected spot AMM quotes as their own slippage floor, enabling sandwich-style value extraction from Push Chain's WPC pool — (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`)

### Summary
`ExecuteInboundGas` (and the analogous `refundUnusedGas` gas-refund path) computes the minimum acceptable swap output (`minPCOut`) directly from `GetSwapQuote`, a live, single-block spot price read from the UniswapV3 `QuoterV2.quoteExactInputSingle` on the PRC20/WPC pool. This is the same anti-pattern as the reported `balanceOfy3CRVinWant()` bug: a critical accounting value (minimum acceptable output) is derived from an on-chain balance/price that an unprivileged attacker can manipulate in the same block, and the code never validates the quote against a manipulation-resistant reference (e.g., TWAP or external price bound).

### Finding Description
When an inbound `GAS`/`GAS_AND_PAYLOAD` tx is executed, `k.ExecuteInboundGas` fetches a swap quote and uses it as its own protection bound: [1](#0-0) 

`GetSwapQuote` performs a non-committing call to `QuoterV2.quoteExactInputSingle`, which simulates a swap against the pool's *current* reserves/sqrtPrice — a spot price with no TWAP or staleness protection: [2](#0-1) 

The resulting `minPCOut = quote * 95 / 100` is then passed into `CallPRC20DepositAutoSwap`, which performs the actual on-chain swap in the very same call: [3](#0-2) 

Because the quote and the executed swap both read the *same* pool state at essentially the same instant, the 5% band only bounds intra-call execution noise — it provides zero protection against the pool price having been pushed away from its fair value immediately beforehand by an attacker's own transaction(s) in the same block. The identical pattern (spot-quote-derived `minPCOut` immediately consumed by a real swap) recurs in the gas-refund path: [4](#0-3) 

This is architecturally the same defect as the reported `balanceOfy3CRVinWant()` issue: a manipulable, unauthenticated on-chain value (spot balance/price) is consumed directly into value-moving logic without any check for manipulation, and the "safety" check (slippage / return-value validation) is computed from the same manipulable source it's supposed to protect against.

### Impact Explanation
An unprivileged actor who can influence transaction ordering in the block where their own inbound (or a queued gas refund) executes can:
1. Swap a large amount into (or out of) the PRC20/WPC pool to skew the spot price in the direction that benefits their upcoming autoswap/refund.
2. Let the skewed quote be read by `GetSwapQuote`, producing a `minPCOut` consistent with the manipulated price.
3. Have their crosschain deposit/refund swapped through the same distorted pool, extracting more WPC than the fair pre-manipulation exchange rate would provide.
4. Reverse their manipulating trade in the same or an adjacent transaction, netting a profit funded by the pool's liquidity providers (which may include protocol-owned liquidity), i.e., an unauthorized transfer of value out of PRC20/native asset accounting — falling under "corruption of PRC20 or native asset accounting" and "unauthorized module-originated EVM execution" impact categories.

Because `ExecuteInboundGas`/refund execution is deterministic and driven purely by validator vote finalization (not by any price-oracle input the attacker must corrupt through consensus), this is reachable through ordinary user deposit/refund flows alone, without any privileged or malicious-validator assumption — validators are honestly reporting the inbound; the manipulation happens entirely in the destination-chain (Push Chain) EVM state that the swap reads.

### Likelihood Explanation
Feasibility depends on: (a) the depth/liquidity of the specific PRC20/WPC pool and fee tier selected via `GetDefaultFeeTierForToken`, and (b) the attacker's ability to time or bundle a manipulating swap immediately before their inbound's autoswap executes within the same block (a standard MEV/sandwich technique, not requiring an actual flash-loan primitive on Push Chain — just enough capital or a thin pool). Newly listed or low-liquidity PRC20/WPC pools are especially exploitable. I was not able to fully verify from the indexed code whether `ExecuteInboundGas` executes synchronously inside the same block/transaction as the finalizing `MsgVoteInbound` (the call site in `execute_inbound.go` was not returned by search), which is material to precisely bounding the attacker's timing window — this should be confirmed with full repository access.

### Recommendation
- Replace or supplement the spot `quoteExactInputSingle` read with a manipulation-resistant reference price (TWAP over multiple blocks, or an external chain-meta price feed already used elsewhere in the module) before computing `minPCOut`.
- Do not derive the slippage floor exclusively from a value read in the same call as the swap it bounds; bound it against a price observed at least one block prior, or enforce a maximum allowed deviation from a longer-window average.
- Apply the same fix to `CallUniversalCoreRefundUnusedGas`'s `withSwap` path, which has the identical spot-quote-as-own-floor structure.
- Consider capping single-swap size relative to pool depth/liquidity caps already tracked in `x/uregistry` `TokenConfigs`.

### Proof of Concept
Conceptual (cannot be fully validated without live pool/contract bytecode access):
1. Attacker holds (or briefly acquires) enough capital to swap a large amount through the PRC20/WPC pool at the configured `defaultFeeTier`, pushing the pool price so that 1 PRC20 quotes for more WPC than the fair rate.
2. In the same block, attacker's cross-chain deposit (already pending finalization from prior honest UV votes) reaches its vote threshold, triggering `ExecuteInboundGas` → `GetSwapQuote` (reads the now-skewed price) → `minPCOut` computed from that skewed quote → `CallPRC20DepositAutoSwap` executes at the skewed price, minting the attacker more WPC-equivalent value than the deposited PRC20 is fairly worth.
3. Attacker reverses the initial manipulating swap, restoring the pool price and recovering most of the capital used to manipulate it, net profit equal to the value extracted from the pool during step 2, funded by other liquidity providers/the protocol. [5](#0-4)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)

// CallUniversalCoreRefundUnusedGas calls refundUnusedGas on UniversalCore to return excess gas fee
// to the recipient. withSwap=true swaps the gas token back to PC; withSwap=false deposits PRC20 directly.
func (k Keeper) CallUniversalCoreRefundUnusedGas(
	ctx sdk.Context,
	gasToken common.Address,
	amount *big.Int,
	recipient common.Address,
	withSwap bool,
	fee *big.Int,
	minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	// fee is uint24 in Solidity — pass as *big.Int (go-ethereum ABI packs non-standard widths as *big.Int)
	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress,
		handlerAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"refundUnusedGas",
		gasToken,
		amount,
		recipient,
		withSwap,
		fee,
		minPCOut,
	)
}
