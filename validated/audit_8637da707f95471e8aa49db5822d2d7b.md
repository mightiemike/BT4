### Title
Costless Unbounded Account-State Growth via `AccountInitDecorator` Short-Circuit on Gasless Transactions - (File: `app/ante/account_init_decorator.go`)

### Summary
The external report's bug class is "a privileged actor bypassing an accounting/allowance check by chaining two individually-allowed operations." The reachable native analog on Push Chain is in the **gasless admission path**: `AccountInitDecorator` lets *any* unprivileged external address create a brand-new on-chain account for free by submitting a gasless-allowlisted message type, but the decorator returns success and **terminates the ante chain before the wrapped message is ever executed**. Combined with the gasless fee/gas-price exemptions, this lets an attacker generate unlimited throwaway keypairs off-chain and permanently grow chain state (`x/auth` accounts) at zero fee cost — a state-bloat DoS that requires no validator, admin, or TSS privilege.

### Finding Description
`AccountInitDecorator.AnteHandle` is wired into the Cosmos ante chain in `app/ante/ante_cosmos.go` right after `NewDeductFeeDecorator` and `MinGasPriceDecorator`, both of which skip their checks entirely for gasless transactions per `app/txpolicy/gasless.go`'s allowlist (`MsgExecutePayload`, `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`, `MsgMigrateUEA`). [1](#0-0) 

For a gasless tx whose signer has no on-chain account yet, `AccountInitDecorator` verifies the signature against `account_number=0, sequence=0` (which any freshly generated keypair trivially satisfies against itself), creates the account, and returns: [2](#0-1) 

Note line 74: `return ctx, nil` — the decorator does **not** call `next(ctx, tx, simulate)`. This means:
1. The wrapped message (`MsgExecutePayload`, `MsgVoteInbound`, etc.) is never routed to its handler on the account's first gasless tx — no message-level validation (signature/payload checks in `ExecutePayload`, bonded-validator checks in `VoteInbound`, etc.) ever runs.
2. The ante chain reports success (`nil` error) regardless of whether the wrapped message content is well-formed.
3. Because `IsGaslessTx` only inspects message *type URLs*, not content, the message payload can be arbitrary garbage — an attacker only needs a syntactically valid `sdk.Tx` whose sole message is one of the allowlisted types.

`IsGaslessTx` gates purely on type, with no bonded/authorized-signer requirement enforced before this decorator runs: [3](#0-2) 

Since `MsgExecutePayload` is explicitly documented as submittable by "any account" and is gasless: [4](#0-3) 

an unprivileged attacker can:
- Generate an arbitrary number of fresh keypairs offline (free).
- Craft one `MsgExecutePayload` (or any other allowlisted type) per keypair, sign it with `account_number=0, sequence=0`.
- Broadcast each — no fee is deducted (`DeductFeeDecorator` skips), no minimum gas price applies (`MinGasPriceDecorator` skips), and the underlying message is never checked for validity since the ante chain short-circuits.
- Each accepted tx permanently commits a new `BaseAccount` to `x/auth` state.

This is a "first-use account initialization" bug in the exact area called out by the scope ("gasless allowlisting, authz wrapping, ante checks, first-use account initialization ... must not turn attacker input into accepted authorization") — attacker-controlled junk input is turned into an "accepted" (successful) transaction outcome purely to mint state, without ever passing through real message authorization.

### Impact Explanation
This is a costless, unbounded state-growth / resource-exhaustion vector reachable by any unprivileged external actor with no dependency on malicious validators, admins, or TSS participants — matching the allowed "denial of service ... not network-level and reachable without privileged control" impact category. Each malicious tx:
- Consumes block space and signature-verification CPU on every full node.
- Permanently increases the `x/auth` account-count/state size with zero cost to the attacker (no fee, no minimum gas price).
- Never executes the wrapped message, so it also silently defeats the documented UX purpose of the decorator ("lets a freshly-keygen'd Universal Validator hot key vote on its very first tx") — a legitimate new UV's very first `MsgVoteInbound` is a no-op rather than a recorded vote, requiring a second (now-funded-account) submission to actually register.

### Likelihood Explanation
High. No privileged capability is required — only a locally generated keypair and the ability to broadcast a signed Cosmos tx, both trivially available to any external user. The condition (`!aid.ak.HasAccount(ctx, newAccAddr)`) is met for every never-used address, which is unlimited in supply.

### Recommendation
`AccountInitDecorator` should call `next(ctx, tx, simulate)` after creating the account instead of short-circuiting with `return ctx, nil`, so the wrapped message is still validated/executed by the rest of the ante chain and message handlers on the same transaction. Separately, consider rate-limiting or requiring proof-of-work/minimum-deposit for account creation via the gasless path, since account creation itself has a real, non-zero state cost that is currently fully subsidized for anonymous first-time signers regardless of message validity.

### Proof of Concept
1. Generate a fresh secp256k1/ed25519 keypair `K` off-chain (address `A`, never seen on-chain).
2. Build a `sdk.Tx` with a single message of an allowlisted gasless type (e.g., `MsgExecutePayload` with arbitrary/garbage `UniversalAccountId`/`UniversalPayload` fields — content is irrelevant), fee = `0upc`, `account_number=0`, `sequence=0`, signed by `K`.
3. Broadcast the tx. `MinGasPriceDecorator` and `DeductFeeDecorator` both skip (gasless allowlist match). `AccountInitDecorator` verifies the self-consistent 0/0 signature (trivially valid), creates account `A` with `sequence=1`, and returns `ctx, nil` — the tx is accepted with no error and `MsgExecutePayload` is never actually processed.
4. Repeat steps 1–3 with a new keypair each time. Each iteration permanently adds one account to on-chain state at zero fee cost, with no bound on repetition.

```go
// IsGaslessTx checks if a transaction contains only allowed gasless message types
// Returns true if all messages in the transaction are in the allowed gasless message types
func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
```

```markdown
### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```
