### Title
Stale Signer-Set Linked-List Membership Causes Reward/Weight Mis-Calculation When a Removed Signer's Delegated Stake Is Re-Grown via Protocol Bonds - (File: `stackslib/src/chainstate/stacks/boot/pox-5.clar`)

### Summary

### Finding Description
In `pox-5.clar`, per-cycle signer membership for the reward set is tracked with an explicit linked list (`signer-set-ll-for-cycle`, `signer-set-ll-first-for-cycle`, `signer-set-ll-last-for-cycle`) [1](#0-0) . A signer enters this list only when the *STX-only staking* path (`add-staker-to-signer-for-cycle`) observes that `get-amount-delegated-for-signer` crosses `SIGNER_SET_MIN_USTX` from below, at which point `add-signer-to-set-for-cycle` links it in [2](#0-1) . It leaves the list only via `remove-staker-from-signer-for-cycle`, called when the same delegated total drops back below the threshold, which unlinks the node with `remove-staker-from-set-for-cycle` [3](#0-2) [4](#0-3) .

`get-amount-delegated-for-signer` is documented (and used) as the sum of STX-only staking *and* protocol-bond delegation to a signer — comments at both call sites state "the total uSTX delegated (through protocol bonds and STX-only staking)" [5](#0-4) [6](#0-5) . However, the protocol-bond accounting functions, `add-staker-to-bond-for-cycle` and `remove-staker-from-bond-for-cycle`, only mutate `total-shares-staked-for-cycle`, `signer-shares-staked-for-cycle`, and `staker-shares-staked-for-cycle` for the bond-index bucket. They never call `add-signer-to-set-for-cycle` / `remove-staker-from-set-for-cycle`, never touch `signer-delegated-per-cycle`, and never check `SIGNER_SET_MIN_USTX` [7](#0-6) .

This reproduces exactly the reported bug class: a linked-list membership check (`recalculateMinMaintCredit`/here, the STX-only threshold-crossing logic) removes an entity from the list, and a *different* mutation path (extending the key’s lock/increasing bond stake) that legitimately changes the entity's effective weight fails to re-insert it into the list. The list is what downstream reward/weight computations iterate.

Downstream, the reward set/signer weight is produced by walking only the linked list: `StakeEntryIteratorPox5` traverses `signer-set-ll-for-cycle` via `get-signer-set-next-item-for-cycle` [8](#0-7) , feeding `pox_5_make_signer_set`/`pox_5_compute_and_update_signers`, which computes signer weights and writes them into the `.signers` boot contract used by the network's Nakamoto signer set [9](#0-8) .

### Impact Explanation
If a signer's STX-only delegated stake drops the signer out of the linked list (delegated < `SIGNER_SET_MIN_USTX`), and a staker subsequently registers or increases a **protocol bond** for that same signer such that the true combined delegated amount (STX + bond) would cross back over `SIGNER_SET_MIN_USTX`, the bond path never re-links the signer. The signer therefore stays excluded from `pox_5_stake_entries`/`StakeEntryIteratorPox5`, so it is dropped from the computed `signer_set` written by `update_signers` into the `.signers` contract, and from `total-shares-staked-for-cycle`. This is a "weight below threshold / signer excluded despite qualifying stake" equality break: the on-chain accounting says the signer is delegated enough uSTX, but the consensus-relevant signer weight used for stackerdb slot assignment and reward distribution treats it as absent, denying it its earned share of block rewards for that cycle (reward mis-payment bounded to the affected signer's/staker's share). This matches the High-severity category "signer weight below threshold or from the wrong set" / "reward mis-payment bounded to fees/stake."

### Likelihood Explanation
Triggerable by any two unprivileged, minority stakers: (1) a staker whose STX-only stake for a signer drops below `SIGNER_SET_MIN_USTX` (removing the signer from the list), followed by (2) any staker (the same or different) registering/increasing a protocol bond for that same signer. Both `register-for-bond` and `update-bond-registration` route through `add-staker-to-bond-for-cycle`, an already-exposed, permissionless entry point. No majority coordination or privileged role is required.

### Recommendation
In `add-staker-to-bond-for-cycle` (and `remove-staker-from-bond-for-cycle`), recompute the signer's combined delegated total via `get-amount-delegated-for-signer` after the bond-share update and perform the same threshold-crossing check used in `add-staker-to-signer-for-cycle`/`remove-staker-from-signer-for-cycle` — calling `add-signer-to-set-for-cycle`/`remove-staker-from-set-for-cycle` and updating `total-shares-staked-for-cycle` accordingly whenever bond-driven changes cross `SIGNER_SET_MIN_USTX`.

### Proof of Concept
1. Signer S has only STX-only delegated stake ≥ `SIGNER_SET_MIN_USTX` for cycle N; S is linked into `signer-set-ll-for-cycle` for N.
2. The staker fully unstakes/updates away, calling the path that resolves to `remove-staker-from-signer-for-cycle`; since `new-delegated < SIGNER_SET_MIN_USTX`, `remove-staker-from-set-for-cycle` unlinks S from the cycle-N list [10](#0-9) .
3. Another (or the same) staker calls `register-for-bond`/`update-bond-registration` designating signer S, adding enough sats such that S's combined bond+STX delegated total for cycle N would again exceed `SIGNER_SET_MIN_USTX`. This flows into `add-staker-to-bond-for-cycle`, which updates only bond-bucket maps and never checks the threshold or calls `add-signer-to-set-for-cycle` [11](#0-10) .
4. At the reward-set computation boundary for cycle N, `pox_5_compute_and_update_signers` walks `signer-set-ll-for-cycle` via `StakeEntryIteratorPox5`; S is absent from the traversal despite having qualifying delegated stake, so S is omitted from the `.signers` contract write and from `total-shares-staked-for-cycle`, losing its rightful reward share for cycle N.

impl<'a, 'b, 'c> StakeEntryIteratorPox5<'a, 'b, 'c> {
    fn fallible_next(&mut self) -> Result<Option<RawPox5Entry>, PoxEntryParsingError> {
        let Some(cur_signer) = self.current_signer.take() else {
            return Ok(None);
        };

        let lookup_signer = SymbolicExpression::atom_value(Value::Principal(cur_signer.clone()));

        // Advance the linked list before any per-entry lookups: a malformed
        // entry skips this iteration but must not stall the iterator.
        let next_signer = self
            .clarity
            .eval_method_read_only(
                &self.pox_contract,
                "get-signer-set-next-item-for-cycle",
                &[lookup_signer.clone(), self.reward_cycle_clar.clone()],
            )
            .map_err(|e| PoxEntryParsingError::Abort(e.to_string()))?
            .expect_optional()
            .map_err(|_| {
                PoxEntryParsingError::Abort(
                    "get-signer-set-next-item-for-cycle did not return optional".into(),
                )
            })?
            .map(|entry| entry.expect_principal())
            .transpose()
            .map_err(|_| {
                PoxEntryParsingError::Abort(
                    "get-signer-set-next-item-for-cycle did not return principal".into(),
                )
            })?;
        self.current_signer = next_signer;
