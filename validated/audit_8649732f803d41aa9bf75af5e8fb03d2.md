**Rationale:**

`DeltaOp`/`DeltaChangeSet` is a purely in-memory, execution-time construct used only within a single block's speculative execution (Block-STM) to accumulate aggregator updates before they are materialized into concrete `WriteOp`s. There is no restore, state-sync, or storage-replay path that ever operates on `DeltaOp` entries.

Specifically:
- Deltas are merged only during live block execution via `DeltaOp::merge_with_previous_delta`/`merge_with_next_delta` (chunking here refers to speculative execution ordering within Block-STM, not to storage/restore chunking) and are converted into a final `u128` value or `WriteOp` before the transaction output leaves the VM. [1](#0-0) 
- At commit/materialization time (both in the parallel `apply_output_sequential` path and in the general executor), aggregator/delayed-field changes are resolved to concrete values and written as `AggregatorChangeV1::Write`/`MaterializedDelta`/`WriteWithDelayedFields`, i.e. plain `WriteOp`s — no `DeltaOp` survives past this point. [2](#0-1) 
- Chunk execution and state-sync (`ChunkExecutor`, `StorageSynchronizer`) only ever consume `TransactionOutputListWithProofV2`/`TransactionListWithProofV2`, which contain already-materialized `WriteSet`s, transaction infos, and events — never `DeltaOp`/`DeltaChangeSet`. [3](#0-2) 
- Storage's `restore_utils::save_transactions` path persists the already-materialized `WriteSet`s and transaction infos exactly as they were committed, with no delta-merge or replay logic involved. [4](#0-3) 
- A targeted search of `storage/**` for `DeltaChangeSet`/`DeltaOp` returned zero matches, confirming these types never cross into the storage/restore layer. 

Because chunking/grouping only applies to how blocks of already-resolved `TransactionOutput`s (or raw transactions to be re-executed identically by the VM) are batched for restore/state-sync, there is no code path where "replaying `DeltaOp` entries in a different chunking/order" is even possible — the deltas simply do not exist by the time any restore or sync logic runs. The premised exploit scenario does not correspond to an actual code path in this codebase.
