Based on my investigation, I found a viable analog to CVE-2019-9070's "unbounded recursion over attacker-influenced structured data" bug class in the sequencer's compiled-class-hash computation path.

### Title
Unbounded recursion in `bytecode_hash_node` over attacker-influenced segment tree can crash the sequencer/gateway process (stack overflow) - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs])

### Summary
`bytecode_hash_node` recursively walks a `NestedIntList` (`bytecode_segment_lengths`) that describes how a declared class's CASM bytecode is partitioned into a segment tree, recursing once per nesting level with no depth bound and no iterative fallback.

### Finding Description
`bytecode_hash_node` recurses into `node.iter_children()` for every internal node of the segment tree, with no depth limit: [1](#0-0) 

This is invoked from `HashableCompiledClass::hash` / `hash_inner`, which is called directly in the sequencer's own process — not inside the resource-limited, sandboxed compilation subprocess used for the actual Sierra→CASM compile step: [2](#0-1) 

and again during declare-transaction construction: [3](#0-2) 

The `bytecode_segment_lengths` field comes from `CasmContractClass::from_contract_class` (an external `cairo-lang-starknet-classes` dependency) and reflects the segmentation of the compiled bytecode into functions/branches, as documented in the corresponding Cairo OS hint: [4](#0-3) 

The Sierra→CASM compilation step itself runs in an isolated, resource-limited subprocess (CPU time, memory, file size limits, but notably **no stack-size limit**), so a crash there is contained: [5](#0-4) [6](#0-5) 

However, the subsequent hash computation (`executable_class.hash(&HashVersion::V2)`, and the `check_compile_class_hash_v2_declaration` re-hash) runs in-process on the returned `CasmContractClass`, with no process isolation and no depth check on the segment tree before recursing.

### Impact Explanation
If a contract declarer can craft Sierra source code (e.g., deeply nested sequential branching/functions within the `max_bytecode_size` limit of 80KB felts) that causes the compiler to emit a segment tree many levels deep, `bytecode_hash_node`'s unbounded recursion could exhaust the native call stack and crash the gateway/sequencer process handling that declare transaction (and any node re-validating it, e.g. via `check_compile_class_hash_v2_declaration` at block-building or re-execution time). Since this path is reachable from a single unprivileged declare transaction and executes in the main, non-sandboxed process, a crash here is a denial-of-service on transaction processing (a node unable to confirm new transactions while repeatedly crashing on the malicious class), which is honest-node-affecting and not merely resource exhaustion of a subprocess.

### Likelihood Explanation
Exploitability hinges on whether the external `cairo-lang-starknet-classes` bytecode segmentation algorithm can actually be driven to produce a deep/unbalanced tree (proportional to source nesting) rather than a shallow, bounded one — this repo only consumes the produced `NestedIntList`, it does not control its generation. This constrains confidence to medium: the recursive consumer (`bytecode_hash_node`) is unambiguously unbounded and unguarded, but confirming the achievable tree depth requires inspecting the `cairo-lang-starknet-classes` segmentation logic, which is outside this repository's index.

### Recommendation
Convert `bytecode_hash_node` (and its sibling recursive helpers, e.g. `hash_entry_points_inner`/Cairo OS equivalents) to an explicit iterative/worklist algorithm, or enforce and validate a hard maximum nesting depth on `bytecode_segment_lengths` before hashing, rejecting classes whose segment tree exceeds a safe bound.

### Proof of Concept
Not constructible from this repository alone: reproducing the crash requires crafting a Sierra program compiled by the external `cairo-lang-starknet-classes` crate into a `CasmContractClass` with a sufficiently deep `bytecode_segment_lengths` tree, then calling `HashableCompiledClass::hash` on it as done in `apollo_compile_to_casm/src/lib.rs:69` or `executable_transaction.rs:232`.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

    /// Verifies that the compiled class hash field in the declare tx,
    /// is compiled_class_hash_v2 of the compiled contract.
    pub fn check_compile_class_hash_v2_declaration(&self) -> Result<(), StarknetApiError> {
        let compiled_class = &self.class_info.contract_class;
        let compiled_class_hash_v2 = match &compiled_class {
            ContractClass::V0(_) => return Ok(()),
            ContractClass::V1((casm, _)) => casm.hash(&HashVersion::V2),
        };
        let compiled_class_hash = self.compiled_class_hash();
        if compiled_class_hash_v2 != compiled_class_hash {
            let err_var = CasmHashMismatch {
                hash: self.class_hash(),
                actual: compiled_class_hash,
                expected: compiled_class_hash_v2,
            };
            return Err(StarknetApiError::DeclareTransactionCasmHashMissMatch(Box::new(err_var)));
        }
        Ok(())
    }

// Returns the hash of the contract class bytecode according to its segments.
//
// The hash is computed according to a segment tree. Each segment may be either a leaf or divided
// into smaller segments (internal node).
// For example, the bytecode may be divided into functions and each function can be divided
// according to its branches.
//
// The hash of a leaf is the Poseidon hash the data.
// The hash of an internal node is `1 + poseidon(len0, hash0, len1, hash1, ...)` where
// len0 is the total length of the first segment, hash0 is the hash of the first segment, and so on.
//
// For each segment, the *prover* can choose whether to load or skip the segment.
// When full_contract is TRUE, all segments are loaded regardless of their usage.
//
// * Loaded segment:
//   For leaves, the data will be fully loaded into memory.
//   For internal nodes, the prover can choose to load/skip each of the children separately.
//
// * Skipped segment:
//   The inner structure of that segment is ignored.
//   The only guarantee is that the first field element is enforced to be -1.
//   The rest of the field elements are unconstrained.
//   The fact that a skipped segment is guaranteed to begin with -1 implies that the execution of
//   the program cannot visit the start of the segment, as -1 is not a valid Cairo opcode.
//
// In the example above of division according to functions and branches, a function may be skipped
// entirely or partially.
// As long as one function does not jump into the middle of another function and as long as there
// are no jumps into the middle of a branch segment, the loading process described above will be
// sound.
