### Title
Slippage-protected PRC20↔WPC auto-swaps use a manipulable spot-price quote as their own protection bound, enabling sandwich extraction of user deposit/refund value - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`ExecuteInboundGas` (gasless inbound gas-abstraction swap) and `applyGasRefund` (outbound gas refund swap) both derive their slippage-protection bound (`minPCOut`) from `GetSwapQuote`, which calls Uniswap V3 `QuoterV2.quoteExactInputSingle` against the pool's current spot price. Because the bound is computed from the same manipulable spot price that the swap itself executes against, it provides no real protection against price manipulation that occurred before (or is co-located with) the module's swap call — exactly the "spot price used as the amount oracle" defect described in the external OmoOracle report, just applied to Push Chain's native PRC20→WPC auto-swap paths instead of a Uniswap V3 LP-position valuation.

### Finding Description
`GetSwapQuote` in [1](#0-0)  fetches an instantaneous quote from the pool's live state (`sqrtPriceLimitX96 = 0`, no TWAP), reflecting whatever the current spot price is at call time.

Two production, unprivileged-user-reachable flows consume this quote as their sole price-manipulation defense:

1. `ExecuteInboundGas` (gas-abstraction swap for gasless inbound deposits) fetches the quote and immediately computes `minPCOut = quote * 95 / 100` before executing the real swap via `CallPRC20DepositAutoSwap`: [2](#0-1) 

2. `applyGasRefund` (outbound gas-refund swap, gasToken → PC native) does the same pattern via `getSwapQuoteForRefund` and `CallUniversalCoreRefundUnusedGas`: [3](#0-2) 

In both cases, the 5% band only bounds the difference between the quote call and the swap call within the *same* keeper execution — it does nothing to protect against the pool price having already been pushed away from fair value by an attacker prior to (or via front-running the ordering of) that block/transaction. Since these are standard, permissionless Uniswap V3 pools deployed for PRC20/WPC pairs (referenced via `GetUniversalCoreQuoterAddress`, `GetUniversalCoreWPCAddress`, `GetDefaultFeeTierForToken` in `UniversalCore`), any unprivileged actor can submit ordinary swap transactions against the same pool to move `sqrtPriceX96` before the module-triggered inbound/outbound swap executes, especially for thin-liquidity, newly-registered PRC20 tokens.

This is the direct native analog of the reported `OmoOracle.getLiquidityAmounts()` issue: an internal amount/price computation trusts a live, unauthenticated, manipulable spot price and treats it as ground truth for a downstream fund-moving operation, rather than using a TWAP or an external reference price.

### Impact Explanation
An attacker can manipulate the spot price of a PRC20/WPC pool immediately around the time a user's inbound gas deposit is processed (gasless admission path) or an outbound gas refund is executed, causing the protocol to auto-swap the user's/protocol's PRC20 into WPC at an off-fair price. The 5% slippage bound is self-referential (derived from the same manipulated price) and does not defend against pre-manipulation, so actual value extracted can exceed the nominal 5% tolerance up to the depth of price manipulation the attacker can achieve within pool liquidity constraints. This results in unauthorized loss of user/protocol-controlled funds (fewer WPC/PC credited than fair value) flowing to the attacker who reverses their manipulating trade afterward, which falls squarely within the "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" and "unauthorized … release … of user or protocol-controlled funds" impact categories.

### Likelihood Explanation
Likelihood is elevated for freshly onboarded or low-liquidity PRC20/WPC pools where moving the spot price materially is cheap. The attack requires no privileged role — any external account can submit ordinary swap transactions on the public pool; the vulnerable code paths (`ExecuteInboundGas`, `applyGasRefund`) trigger automatically as part of normal inbound/outbound processing with no additional authorization needed.

### Recommendation
Do not derive the slippage-protection bound purely from the instantaneous `QuoterV2.quoteExactInputSingle` result. Use a Uniswap V3 TWAP (e.g., `observe()` over a meaningful window) or an external reference price to compute `minPCOut`, and/or cap per-swap notional relative to pool liquidity/TVL, and consider widening the effective protection by comparing quote-derived and TWAP-derived prices and rejecting/deferring execution when they diverge beyond a safe threshold.

### Proof of Concept
1. Attacker identifies a PRC20/WPC Uniswap V3 pool used by `UniversalCore` for a given token (thin liquidity).
2. Attacker submits a large swap pushing the pool's `sqrtPriceX96` so PRC20 appears cheap relative to WPC.
3. A user's inbound gas-abstraction deposit for that PRC20 is processed by `ExecuteInboundGas`; `GetSwapQuote` returns a quote based on the manipulated price, and `minPCOut = quote*95/100` is computed from that same bad price.
4. `CallPRC20DepositAutoSwap` executes the swap at (or near) the manipulated price, crediting the user's UEA with far less WPC than fair value.
5. Attacker reverses their initial swap, extracting the price difference as profit, net of their own trading costs — repeatable per inbound/outbound gas-swap event on the targeted pool.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
