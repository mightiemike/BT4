### Title
Unbounded, attacker-supplied `UniversalPayload.GasLimit` is passed directly to `DerivedEVMCall` with no ceiling check - ([File: x/uexecutor/keeper/evm.go])

### Summary
`UniversalPayload.GasLimit` is a user-controlled string field that any unprivileged signer sets when submitting `MsgExecutePayload` (or that a Universal Validator relays from an observed `Inbound`). It is validated only for being a non-negative uint256 string and is then parsed into a `*big.Int` and forwarded verbatim as the explicit EVM `gasLimit` to `DerivedEVMCall`, with no upper bound, no comparison against the chain's configured block gas limit, and no cap relative to a sane per-tx maximum.

### Finding Description
`UniversalPayload.ValidateBasic()` only checks that `GasLimit` parses as a non-negative big integer: [1](#0-0) 

That unbounded value is later parsed again and passed straight through as the EVM call's gas limit in `CallUEAExecutePayload`: [2](#0-1) 

This is invoked from both the direct-submission path (`ExecutePayload`, reachable by any signer via `MsgExecutePayload`) and the inbound-voting path (`ExecutePayloadV2`, reachable via honestly-finalized `VoteInbound`/`VoteOutbound` ballots whose `UniversalPayload` originates from attacker-controlled source-chain calldata): [3](#0-2) [4](#0-3) 

There is no code anywhere in the scanned modules (`x/uexecutor`, ante handlers) that clamps `GasLimit` to the Cosmos SDK block gas limit or any other sane maximum before it reaches `DerivedEVMCall`. This mirrors the reported bug class exactly: a parameter that materially controls execution economics/behavior (here, the actual gas budget handed to a real, receipt-producing EVM transaction) is user-settable to any value with no logical bound — analogous to `changeOriginationFeeRate`/`changeMaxNumberOfCycles` lacking limits in the original report.

### Impact Explanation
An unprivileged user can submit `MsgExecutePayload` (or supply an `Inbound.UniversalPayload` that gets relayed through honest UV voting) with an astronomically large `GasLimit` (e.g., far exceeding `MaxUint64` or the chain's configured block gas limit). Depending on how the forked EVM's `DerivedEVMCall`/message construction handles this value (this logic lives in the external `github.com/pushchain/evm` fork, not directly available in this index), this could:
- cause the derived EVM message's gas limit to be truncated/overflow when converted from `*big.Int` to the message's `uint64` gas field, potentially desynchronizing the on-chain gas accounting from what `DeductGasFeesFromReceipt` bills, or
- allow a single `MsgExecutePayload`/relayed payload to claim (or attempt to consume) gas far beyond the block's gas limit, which is a denial-of-service risk against block production/finalization if the underlying EVM execution path does not itself clamp the value before scheduling execution.

Because the actual conversion/clamping logic sits in the external EVM fork dependency, I cannot fully confirm from this repository's code whether a hard revert, a panic, or an overflow-based gas-accounting bypass would result — this is the primary uncertainty in this finding.

### Likelihood Explanation
The trigger is a single-message, no-cost action: any account can submit `MsgExecutePayload` with a crafted `GasLimit` value, or any attacker on a source chain can construct an inbound payload with the same field, which is later voted through and executed by honest Universal Validators without further bound-checking. No privileged role is required to reach `CallUEAExecutePayload`.

### Recommendation
Add an explicit upper-bound check on `UniversalPayload.GasLimit` in `ValidateBasic()` (and/or immediately before `DerivedEVMCall` in `CallUEAExecutePayload`), rejecting any value greater than the chain's configured block gas limit (or a fixed protocol-level maximum comfortably below it, consistent with `MaxUint64` safety), returning an error rather than forwarding the raw value to the EVM keeper.

### Proof of Concept
1. Construct a `MsgExecutePayload` (or `Inbound.UniversalPayload`) with `GasLimit` set to a value such as `"115792089237316195423570985008687907853269984665640564039457584007913129639935"` (max uint256) or any value well beyond the chain's block gas limit.
2. `UniversalPayload.ValidateBasic()` accepts it because it only checks "valid non-negative uint256" — see `x/uexecutor/types/universal_payload.go:41-58`.
3. The payload flows into `ExecutePayload`/`ExecutePayloadV2` → `CallUEAExecutePayload`, which parses this string into a `*big.Int` and passes it unmodified as `gasLimit` to `k.evmKeeper.DerivedEVMCall(...)` — see `x/uexecutor/keeper/evm.go:172-192`.
4. Observe (in a full environment with the `pushchain/evm` fork) whether this call panics, truncates gas accounting, or attempts to reserve gas beyond the block gas limit — this final EVM-fork-side behavior could not be verified from the indexed repository content alone.

// CallUEAExecutePayload executes a universal payload through UEA
func (k Keeper) CallUEAExecutePayload(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	universal_payload *types.UniversalPayload,
	verificationData []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiUniversalPayload, err := types.NewAbiUniversalPayload(universal_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	gasLimit := new(big.Int)
	gasLimit, ok := gasLimit.SetString(universal_payload.GasLimit, 10)
	if !ok {
		return nil, fmt.Errorf("invalid gas limit: %s", universal_payload.GasLimit)
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		gasLimit,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"executeUniversalTx",
		abiUniversalPayload,
		verificationData,
	)
}

package keeper

import (
	"context"
	"fmt"

	"cosmossdk.io/errors"
	sdk "github.com/cosmos/cosmos-sdk/types"
	vmtypes "github.com/cosmos/evm/x/vm/types"
	"github.com/ethereum/go-ethereum/common"
	"github.com/pushchain/push-chain-node/utils"
	"github.com/pushchain/push-chain-node/x/uexecutor/types"
)

// ExecutePayloadV2 executes a universal payload through a UEA.
// The caller is responsible for resolving and validating ueaAddr before calling this function.
func (k Keeper) ExecutePayloadV2(ctx context.Context, evmFrom common.Address, ueaAddr common.Address, universalPayload *types.UniversalPayload, verificationData string) (*vmtypes.MsgEthereumTxResponse, error) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Debug("execute payload v2",
		"uea", ueaAddr.Hex(),
		"from", evmFrom.Hex(),
	)

	// Step 1: Validate payload and verificationData early (fast-fail before EVM work)
	if _, err := types.NewAbiUniversalPayload(universalPayload); err != nil {
		return nil, errors.Wrapf(err, "invalid universal payload")
	}

	verificationDataVal, err := utils.HexToBytes(verificationData)
	if err != nil {
		return nil, errors.Wrapf(err, "invalid verificationData format")
	}

	// Step 2: Wrap EVM execution + fee deduction in a CacheContext so they
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr
	}

	// Both succeeded — commit EVM state and fee deduction together.
	writeCache()

	k.Logger().Debug("payload executed via UEA",
		"uea", ueaAddr.Hex(),
		"tx_hash", receipt.Hash,
		"gas_used", receipt.GasUsed,
	)

	return receipt, nil
}
