### Title
Panic-inducing NULL/type-confusion in `ContractClass::bytecode_length` on attacker-controlled `program.data` - ([File: crates/starknet_api/src/deprecated_contract_class.rs])

### Summary
`starknet_api::deprecated_contract_class::ContractClass::bytecode_length()` unwraps the JSON `program.data` field with `.expect("The program data must be an array.")` without validating its type beforehand. Because `Program.data` is deserialized as a raw, unconstrained `serde_json::Value`, an attacker-supplied deprecated (Cairo 0) contract class whose `program.data` is not a JSON array (e.g. `null`, a number, or a string) causes an unrecoverable Rust panic instead of a graceful validation error — directly analogous to the PVFS dissector's NULL-pointer crash on a malformed field in CVE-2018-19624.

### Finding Description
`Program` (deprecated contract class format) stores most fields as loosely-typed `serde_json::Value`: [1](#0-0) 

`bytecode_length()` assumes `program.data` is a JSON array and calls `.as_array().expect(...)` unconditionally. There is no upstream schema check that forces `data` to be an array — `serde_json::Value` deserialization succeeds for any JSON value type.

This function is reached through `ClassInfo::bytecode_length()`/`code_size()`: [2](#0-1) 

`code_size()`/`bytecode_length()` are used in the blockifier's resource/fee accounting for Declare transactions (e.g. `crates/blockifier/src/fee/receipt.rs`, `crates/blockifier/src/transaction/account_transaction.rs`), which runs whenever a Declare V0/V1 (deprecated) transaction is executed, validated, or fee-estimated.

The attacker-reachable entry point is the JSON-RPC execution surface for deprecated declare transactions, which accepts a raw, user-provided contract class: [3](#0-2) 

and is converted into an executable transaction that flows into `ClassInfo::new(...)` / execution: [4](#0-3) 

Because `program.data` is never type-checked as an array before `bytecode_length()` is invoked, any unauthenticated RPC caller can submit a `starknet_call`, `starknet_estimateFee`, or `starknet_simulateTransactions` request containing a `DECLARE` V0/V1 transaction whose `contract_class.program.data` is a non-array JSON value, triggering the `.expect()` panic.

### Impact Explanation
A Rust `panic!` triggered from a single, unauthenticated JSON-RPC request crashes the async task/thread handling the request; in the worst case (consolidated deployment where the RPC/execution component shares a process with the sequencer's gateway/batcher), this can abort the node process, halting its ability to accept or confirm new transactions until restarted — this satisfies the "network unable to confirm new transactions" impact bar even though it is limited to affected node instances. This is a classic unauthenticated DoS-by-malformed-input bug, the same bug class as the referenced Wireshark CVE (parser crash on malformed/attacker-controlled field due to an unchecked type/nullability assumption).

### Likelihood Explanation
High. The only requirement is a single, unauthenticated JSON-RPC call (`starknet_call`, `starknet_estimateFee`, or `starknet_simulateTransactions`) with a `DECLARE` V0/V1 payload where `contract_class.program.data` is not an array. No special privileges, prior state, or network position are required — any caller of the public RPC endpoint can trigger it deterministically.

### Recommendation
- Validate that `program.data` (and any other `serde_json::Value` fields relied upon by `bytecode_length()`/related length computations) is a JSON array during deserialization or immediately upon receiving the deprecated contract class, returning a structured `StarknetApiError` instead of panicking.
- Replace the `.expect("The program data must be an array.")` call with a fallible check (`ok_or(StarknetApiError::...)`) and propagate the error through `ClassInfo::bytecode_length()`/`code_size()` and their callers.
- Add fuzz/unit tests submitting malformed deprecated contract classes (`program.data` as null/number/string/object) through the RPC execution entry points to confirm graceful rejection instead of a panic.

### Proof of Concept
1. Send a JSON-RPC `starknet_estimateFee` (or `starknet_call`/`starknet_simulateTransactions`) request containing a `DECLARE` transaction of the deprecated `BroadcastedDeclareV1Transaction` shape:
```json
{
  "type": "DECLARE",
  "contract_class": {
    "abi": [],
    "program": {
      "data": null,
      "...": "other Program fields with valid/placeholder JSON values"
    },
    "entry_points_by_type": {}
  },
  "sender_address": "0x1",
  "nonce": "0x0",
  "max_fee": "0x0",
  "version": "0x1",
  "signature": []
}
```
2. The node deserializes the class into `starknet_api::deprecated_contract_class::ContractClass` successfully (since `data` is an unconstrained `serde_json::Value`).
3. During execution/fee estimation, `ClassInfo::code_size()`/`bytecode_length()` invokes `self.program.data.as_array().expect(...)`, which panics because `data` is `Value::Null`, crashing the handling task/process.

impl ClassInfo {
    pub fn bytecode_length(&self) -> usize {
        match &self.contract_class {
            ContractClass::V0(contract_class) => contract_class.bytecode_length(),
            ContractClass::V1((contract_class, _sierra_version)) => contract_class.bytecode.len(),
        }
    }

    pub fn contract_class(&self) -> ContractClass {
        self.contract_class.clone()
    }

    pub fn sierra_program_length(&self) -> usize {
        self.sierra_program_length
    }

    pub fn abi_length(&self) -> usize {
        self.abi_length
    }

    pub fn code_size(&self) -> usize {
        (self.bytecode_length() + self.sierra_program_length())
            // We assume each felt is a word.
            * FELT_WIDTH
            + self.abi_length()
    }
