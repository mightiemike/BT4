### Title
Unauthenticated `/v2/resume/:runID` Endpoint Leaks Raw Database/Internal Error Details to Unauthenticated Callers - (File: core/web/pipeline_runs_controller.go)

### Summary
The `PATCH /v2/resume/:runID` route is mounted on an unauthenticated route group (`unauthedv2`) with no session/token/EI middleware, and its handler, `PipelineRunsController.Resume`, forwards raw error strings from `app.ResumeJobV2` (and JSON decoding/UUID parsing errors) directly into the client-facing JSON body via `jsonAPIError`. This is the same bug class as the reported MongoDB verbose-error disclosure — internal error messages (SQL/pgx details, task run state errors) are exposed unfiltered to unprivileged, unauthenticated callers — except here the endpoint is also completely unauthenticated, which is a stronger trust-boundary violation than the original finding.

### Finding Description
`v2Routes` explicitly creates a route group `unauthedv2 := r.Group("/v2")` with no auth middleware, and registers `unauthedv2.PATCH("/resume/:runID", prc.Resume)`: [2](#0-1) 

`PipelineRunsController.Resume` parses the `runID` path parameter as a UUID, decodes a JSON body into `pipeline.ResumeRequest`, and calls `prc.App.ResumeJobV2`. Any error at any of these steps — malformed UUID, malformed JSON body, or internal error from `ResumeJobV2` — is passed straight to `jsonAPIError`, which serializes `err.Error()` into the JSON response body: [3](#0-2) 

`jsonAPIError` unconditionally calls `err.Error()` and returns it in the response unless the error is already a `*models.JSONAPIErrors`: [4](#0-3) 

`ResumeJobV2` delegates to `pipelineRunner.ResumeRun`: [5](#0-4) 

which wraps ORM-level errors such as `"failed to update task run result: %w"`: [6](#0-5) 

Underlying ORM operations (e.g. `StoreRun`) wrap raw SQL/pgx driver errors with query-specific context strings like `"failed to update pipeline run %d: %w"`: [7](#0-6) 

Because the route requires no authentication, any unauthenticated network client that can reach the node's HTTP API can trigger these code paths (e.g., by supplying a valid-looking UUID for `runID` that hits edge-case DB errors, or malformed JSON bodies) and receive verbatim database/internal error text.

### Impact Explanation
- **Trust boundary violation**: unlike the report's original finding (an authenticated-but-verbose endpoint), this Chainlink route requires **zero authentication**, so the raw error disclosure is reachable by any network-adjacent unprivileged actor.
- **Database/internal fingerprinting**: error messages reveal SQL/pgx driver details, internal query structure (e.g., `pipeline_runs`, `pipeline_task_runs` table/column names), and internal function names (`failed to update task run result`, `failed to select pipeline run %d`), mirroring the MongoDB BSON/field-name disclosure in the original report.
- **Attack surface expansion**: the leaked internal messages help an attacker map the pipeline/task-run persistence model and craft further targeted requests against the resume/webhook-callback subsystem, which is a security-sensitive workflow-ingestion trust boundary (this is the endpoint external adapters/bridges use to resume suspended pipeline runs with task results).
- No direct RCE/secret disclosure was found, so this is assessed as an information-disclosure issue analogous to the Medium-severity report, not a critical compromise.

### Likelihood Explanation
High reachability: the endpoint is unauthenticated by design (intended for external adapter callbacks) and reachable directly over HTTP without any credentials, so triggering malformed input (bad UUID, malformed JSON, or non-existent/invalid `runID`) requires no privilege at all — likelihood is higher than the original report's authenticated-adjacent scenario.

### Recommendation
- Sanitize errors before returning them via `jsonAPIError` on unauthenticated routes: return generic messages (e.g., "invalid request" / "internal error") to the client and log full error details (including wrapped SQL/pgx errors) server-side only.
- Specifically audit `PipelineRunsController.Resume` and any other handler reachable from `unauthedv2` for direct `err.Error()` propagation, and route their errors through a centralized error-sanitizing layer instead of `jsonAPIError`'s default passthrough behavior in `core/web/helpers.go`.
- Consider requiring some form of shared-secret/HMAC validation for the resume callback (many bridge/EA integrations already support signed callbacks) in addition to sanitizing error output.

### Proof of Concept
1. As an unauthenticated client, send a malformed request to the always-public route:
   `PATCH /v2/resume/<valid-uuid-but-nonexistent-runID>` with an invalid JSON body, e.g. `{"error": {`.
2. `PipelineRunsController.Resume` fails JSON decoding and returns `jsonAPIError(c, http.StatusUnprocessableEntity, err)` where `err` wraps `"failed to unmarshal JSON body: ..."` verbatim from the decoder.
3. Alternatively, submit a syntactically valid `ResumeRequest` body referencing a `runID` that causes `ResumeJobV2` → `ResumeRun` → ORM `UpdateTaskRunResult`/`StoreRun` to fail (e.g., concurrent state conflicts), producing a response body containing wrapped ORM error text such as `"failed to update task run result: ..."` or `"failed to update pipeline run %d: ..."`, all without any authentication header or cookie.

Note: I was not able to inspect `pipeline.ResumeRequest.ToResult()` or `UpdateTaskRunResult`'s exact SQL error text in this pass due to index scope limits — a Devin session with full repo access could confirm the exact error strings returned end-to-end.

```go
func (prc *PipelineRunsController) Resume(c *gin.Context) {
	taskID, err := uuid.Parse(c.Param("runID"))
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	rr := pipeline.ResumeRequest{}
	decoder := json.NewDecoder(c.Request.Body)
	err = errors.Wrap(decoder.Decode(&rr), "failed to unmarshal JSON body")
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}
	result, err := rr.ToResult()
	if err != nil {
		jsonAPIError(c, http.StatusUnprocessableEntity, err)
		return
	}

	if err := prc.App.ResumeJobV2(c.Request.Context(), taskID, result); err != nil {
		jsonAPIError(c, http.StatusInternalServerError, err)
		return
	}

	prc.App.GetAuditLogger().Audit(audit.UnauthedRunResumed, map[string]any{"runID": c.Param("runID")})
	c.Status(http.StatusOK)
```

```go
func jsonAPIError(c *gin.Context, statusCode int, err error) {
	_ = c.Error(err).SetType(gin.ErrorTypePublic)
	var jsonErr *models.JSONAPIErrors
	if errors.As(err, &jsonErr) {
		c.JSON(statusCode, jsonErr)
		return
	}
	c.JSON(statusCode, models.NewJSONAPIErrorsWith(err.Error()))
}
```
