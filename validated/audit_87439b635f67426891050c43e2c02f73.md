## Verdict

I found a locally-confirmed, self-documented integrity gap, but I want to be precise about scope before calling it a "vulnerability": the gap is explicitly acknowledged by an in-code `TODO` as intentionally deferred pending a feature flag (`COMPUTE_TRADING_NATIVE_STATE_ROOTS`). That weakens the "unprivileged root cause / exploitable now" bar somewhat, but the mechanism itself is real, local, and matches the required impact class (replay/verification accepting a wrong committed state root as valid). I'll report it since it's a concrete, provable gap in a proof-binding invariant used by production tooling.

### Title
Replay/execution-output verification silently ignores state-checkpoint root hashes, allowing a divergent committed state root to pass as verified - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the function used by replay/verification tooling (`storage/db-tool/src/replay_on_archive.rs`, `storage/db-tool/src/replay_verify.rs`, `aptos-move/cli/src/commands.rs`, `aptos-move/aptos-debugger`, and `execution/executor/src/chunk_executor/mod.rs`) to assert that a freshly re-executed `TransactionOutput` matches the authenticated `TransactionInfo` recorded on-chain/in backup. It checks status, gas, write-set hash, and event root hash, but it never compares `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` from `TransactionInfo` against the locally computed state-checkpoint root. [1](#0-0) 

### Finding Description
`TransactionInfoV0`/`V1` carry `state_checkpoint_hash` (and, for V1, `hot_state_checkpoint_hash` / `position_state_checkpoint_hash`), which are the authenticated Sparse-Merkle-Tree roots of world state at checkpoints, hashed into the accumulator leaf via `TransactionInfo::hash()`. [2](#0-1) [3](#0-2) 

`ensure_match_transaction_info` is the comparator used to validate that a locally re-executed transaction (via `AptosVMBlockExecutor`) matches the historically committed `TransactionInfo` pulled from backup/archive. It validates `status`, `gas_used`, `write_set` hash (`state_change_hash`), and `event_root_hash`, but explicitly and knowingly skips the state-checkpoint-related hashes, as documented directly above the `Ok(())` return: [4](#0-3) 

This function is called by the db-tool `replay_on_archive` verifier, which drives mainnet/testnet replay-verify jobs (see `testsuite/replay-verify/main.py` invoking `aptos-debugger aptos-db replay-on-archive`), by `replay_verify.rs`, and by the CLI's transaction-replay command: [5](#0-4) [6](#0-5) 

Because the state-checkpoint hash is not checked, if a local re-execution produces a state root that diverges from the one authenticated by the original `TransactionInfo` (e.g., due to a nondeterminism bug, a storage-layer bug in Jellyfish Merkle Tree construction, or a hard-fork-relevant divergence in "trading-native"/hot-state root computation), replay-verify tooling will still report success as long as write-set bytes, events, gas, and status match. This decouples the verified proof invariant ("the committed state root reflects the correct VM result") from what the tooling actually checks.

### Impact Explanation
This breaks the "Committed state that differs from the correct VM result" and "Hard-fork-only divergence during commit, replay" invariants called out in the state-integrity gate: a state root that diverges from the true VM/state-checkpoint result at replay time is accepted as "verified" by the exact tool (`replay-on-archive`, run at scale in `testsuite/replay-verify/main.py`) that exists specifically to catch such divergence before/after hard forks. A silent pass here means real state-root corruption bugs (including ones affecting hot-state/`position_state_checkpoint_hash`, which per the comment is tied to the not-yet-enabled `COMPUTE_TRADING_NATIVE_STATE_ROOTS` feature) could go undetected by the primary safety-net tool.

### Likelihood Explanation
The gap is deterministic and always present in this comparator — it isn't triggered by an attacker input but by any actual state-root computation divergence between the archived data and re-execution. Likelihood of the underlying divergence occurring depends on other bugs (e.g., a hot-state or Merkle computation bug), so this finding is a "detection blind spot," not by itself a state-corruption primitive. The code's own TODO acknowledges the gap is intentional/deferred until `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled, which somewhat reduces confidence that this is unintentionally exploitable today versus a known, tracked limitation.

### Recommendation
Extend `ensure_match_transaction_info` to also compare locally computed `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present/applicable) against the corresponding fields on `txn_info`, gating this on whatever local state-checkpoint computation the caller can provide, before relying on `replay_on_archive`/`replay-verify` as an authoritative state-root integrity check.

### Proof of Concept
Not independently exploitable as a standalone attack; the "PoC" is code-level: run `storage/db-tool/src/replay_on_archive.rs`'s `execute_and_verify` path (which calls `ensure_match_transaction_info`) against a transaction whose backup-recorded `state_checkpoint_hash` differs from the locally recomputed post-execution SMT root, but whose write-set bytes, events, gas, and status happen to match — `ensure_match_transaction_info` returns `Ok(())` and the verifier reports success despite the state-root mismatch, since no assertion in that function ever touches `txn_info.state_checkpoint_hash()`/`hot_state_checkpoint_hash()`/`position_state_checkpoint_hash()`.     pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    // Execute the verify one valid range
    pub fn verify(&self, start: Version, limit: u64) -> Result<Vec<Error>> {
        let mut total_failed_txns = Vec::with_capacity(limit as usize);
        let txn_iter = self
            .backup_handler
            .get_transaction_iter(start, limit as usize)?;
        let mut cur_txns = Vec::with_capacity(limit as usize);
        let mut cur_persisted_aux_info = Vec::with_capacity(limit as usize);
        let mut expected_events = Vec::with_capacity(limit as usize);
        let mut expected_writesets = Vec::with_capacity(limit as usize);
        let mut expected_txn_infos = Vec::with_capacity(limit as usize);
        let mut chunk_start_version = start;
        let executor = AptosVMBlockExecutor::new();
        for item in txn_iter {
            // timeout check
            if let Some(duration) = self.timeout_secs {
                if self.replay_stat.get_elapsed_secs() >= duration {
                    bail!(
                        "Verify timeout: {}s elapsed. Deadline: {}s. Failed txns count: {}",
                        self.replay_stat.get_elapsed_secs(),
                        duration,
                        total_failed_txns.len(),
                    );
                }
            }

            let (
                input_txn,
                persisted_aux_info,
                expected_txn_info,
                expected_event,
                expected_writeset,
            ) = item?;
            let is_epoch_ending = expected_event.iter().any(ContractEvent::is_new_epoch_event);
            cur_txns.push(input_txn);
            cur_persisted_aux_info.push(persisted_aux_info);
            expected_txn_infos.push(expected_txn_info);
            expected_events.push(expected_event);
            expected_writesets.push(expected_writeset);
            if is_epoch_ending || cur_txns.len() >= self.chunk_size {
                let cnt = cur_txns.len();
                while !cur_txns.is_empty() {
                    // verify results
                    let failed_txn_opt = self.execute_and_verify(
                        &executor,
                        &mut chunk_start_version,
                        &mut cur_txns,
                        &mut cur_persisted_aux_info,
                        &mut expected_txn_infos,
                        &mut expected_events,
                        &mut expected_writesets,
                    )?;
                    // collect failed transactions
                    total_failed_txns.extend(failed_txn_opt);
                }
                self.replay_stat.update_cnt(cnt as u64);
                self.replay_stat.print_tps();
            }
        }
        // verify results
        let fail_txns = self.execute_and_verify(
            &executor,
            &mut chunk_start_version,
            &mut cur_txns,
            &mut cur_persisted_aux_info,
            &mut expected_txn_infos,
            &mut expected_events,
            &mut expected_writesets,
        )?;
        total_failed_txns.extend(fail_txns);
        Ok(total_failed_txns)
    }
