### Title
Market index-cache is not invalidated when `socialize-debt` writes down a vault's liquidity index within the same block - (File: `local-testing/contracts/market/market.clar`, `mainnet/contracts/vault/v0-vault-sbtc.clar`)

### Summary
`market.clar` caches each vault's `{index, lindex}` per `stacks-block-time` via `accrue-and-cache` to avoid repeated cross-contract calls to the vaults within the same block. This cache is populated only through the vault's `accrue` path. However, `socialize-debt` in the vault contracts mutates `lindex` directly (bad-debt write-down), bypassing `accrue` entirely and never touching the market's cache. If `socialize-debt` executes in the same block/timestamp in which the market already cached that vault's pre-write-down `lindex`, every subsequent market operation in that block (collateral valuation, health checks, borrow/collateral-add for zToken collateral tied to that vault) keeps using the stale, higher `lindex` instead of the freshly written-down value.

### Finding Description
`accrue-and-cache` in `market.clar` keys its cache strictly by `{timestamp: stacks-block-time, aid}` and treats a cache hit as authoritative for the rest of the block: [1](#0-0) 

This cache is documented as being safe because "the cache is automatically invalidated each block" and there are supposedly "no stale data risks", an assumption that only holds if the vault's `index`/`lindex` state can only change through the `accrue` code path that the cache wraps: [2](#0-1) 

That assumption is false. `socialize-debt`, exposed on every vault contract (e.g. `v0-vault-sbtc.clar`), directly recomputes and `var-set`s `lindex` to write down a proportional loss, completely independent of `accrue`/the market's cache, and with no call back into `market.clar` to invalidate `index-cache-`: [3](#0-2) 

Sequence within a single block (same `stacks-block-time`):
1. A user (or any market operation) touches zToken collateral backed by a given vault (e.g. `zsBTC`), causing `market.clar`'s `accrue-and-cache` to call `vault-accrue`, cache the current (pre-loss) `{index, lindex}` for that vault at the current timestamp.
2. The authorized caller invokes `socialize-debt` directly on the vault, writing `lindex` down to reflect a real loss in vault assets, without ever going through `market.clar`.
3. Within the remainder of the same block, any user performs `collateral-add`, `borrow`, or `collateral-remove` on zToken collateral from that vault. `accrue-and-cache` returns the stale cache entry from step 1 (cache HIT) instead of the post-write-down `lindex`.
4. `get-asset-value`/notional evaluation for that zToken collateral is computed against the stale, inflated `lindex`, overvaluing the user's collateral relative to its true (written-down) worth.

This is a textbook "cached value not invalidated when its source moves" bug: the value bound is the vault's `{index, lindex}` cached in `market.clar`'s `index-cache-` map; the event that invalidates the real source is `socialize-debt`'s direct `var-set lindex`; the later use is any zToken collateral valuation/health check performed later in the same block that reads the stale cache entry.

### Impact Explanation
Users holding zToken collateral from a vault that underwent `socialize-debt` in the same block can, for the remainder of that block, borrow against or maintain positions based on an overvalued collateral figure that does not reflect the just-recognized loss. This lets a position pass health checks (`is-healthy`/`is-healthy-with-mask`) that would otherwise fail, allowing extraction of debt beyond the real backing of the collateral — a path to protocol insolvency once the true, lower `lindex` is reflected at the next block/cache miss.

### Likelihood Explanation
Requires `socialize-debt` (a legitimate, non-DAO-governance-compromising bad-debt handling operation performed by an authorized system role) to execute in the same block in which the market has already cached that vault's index, and for a user (or the same actor) to perform a market operation on affected zToken collateral before the block ends. This is a realistic single-block interleaving, not requiring DAO compromise, oracle manipulation, or a flashloan mechanic — it only requires timing the loss-socialization and the market operation into the same block.

### Recommendation
Have `socialize-debt` invalidate (or update) `market.clar`'s `index-cache-` entry for the affected vault/timestamp when it writes down `lindex`, or have the market re-derive/never trust a cached `lindex` across a `socialize-debt` event (e.g., by having the vault emit and the market read a monotonically-increasing "generation" counter alongside the timestamp key, invalidated on any out-of-band state mutation such as `socialize-debt`).

### Proof of Concept
1. In block N, Alice performs any market operation (e.g. `collateral-add`) using `zsBTC` collateral backed by `v0-vault-sbtc`, causing `market.clar` to cache `{index, lindex}` for `v0-vault-sbtc` at timestamp N via `accrue-and-cache` (`local-testing/contracts/market/market.clar:253-265`).
2. Still in block N, the authorized caller invokes `v0-vault-sbtc.socialize-debt` to write down `lindex` after a bad-debt event (`mainnet/contracts/vault/v0-vault-sbtc.clar:942-964`), reducing the true value of `zsBTC` shares.
3. Still in block N, Bob (or Alice) calls `market.clar` `borrow` or `collateral-add` using `zsBTC` collateral. `accrue-and-cache` hits the stale cache from step 1 and returns the pre-write-down `lindex`, so the position's collateral is valued higher than its real, post-loss worth, allowing the health check to pass when it should not.
4. In block N+1, the cache key rolls over to the new timestamp, `vault-accrue` is called fresh, and the true written-down `lindex` is finally reflected — by which point Bob's over-collateralized-looking borrow has already been executed against understated risk.

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
```

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
```
