### Title
Unbounded `min_gas_price_percentage` config allows misconfiguration to permanently block all transaction admission - (File: crates/apollo_gateway_config/src/config.rs)

### Summary
`StatefulTransactionValidatorConfig::min_gas_price_percentage` is a `u8` used to compute a mandatory gas-price threshold that every incoming transaction must clear in the gateway's stateful validation path. Unlike its sibling field `fee_escalation_percentage` in `MempoolStaticConfig` (which is bounded with `#[validate(range(min = 1, max = 100))]`), `min_gas_price_percentage` has no `#[validate(...)]` bound at all, so `config_validate()` accepts any value from 0 to 255. An operator misconfiguration (e.g. setting the percentage above 100, or to an unreachable value) makes the derived threshold exceed any gas price a real transaction/L2 base price could reach, causing every submitted transaction to fail gateway validation with `GAS_PRICE_TOO_LOW` — the same "misconfiguration silently blocks all new admissions" bug class described in the external report.

### Finding Description
`StatefulTransactionValidatorConfig` is declared with `#[derive(... Validate ...)]` but none of its fields, including `min_gas_price_percentage`, carry field-level `#[validate(range(...))]` attributes: [1](#0-0) 

This field is consumed in `validate_tx_l2_gas_price_within_threshold`, which is invoked as part of stateful validation for every incoming transaction with `AllResources` bounds: [2](#0-1) 

The threshold is computed as `(min_gas_price_percentage / 100) * previous_block_l2_gas_price`. If the transaction's `max_price_per_unit` for L2 gas is below this threshold, the gateway rejects it with `GAS_PRICE_TOO_LOW`, regardless of how the transaction is otherwise valid.

Because the field is an unbounded `u8` (0–255) with no cross-check against 100 or against the block's dynamic gas-price adjustment bounds, an operator setting the value too high (deliberately or by typo/misconfiguration, e.g. `250` instead of a fraction like `80`) creates a threshold that is a multiple of the current price. Since the network's own dynamic gas price adjustment is bounded per block (`gas_price_max_change_denominator` in versioned constants limits how much the price can move each block), the required jump may never be reachable in practice, meaning the threshold check fails for every transaction indefinitely. This exactly mirrors the reported bug class: a configurable value combined into a hard requirement, where an accidental configuration choice makes the requirement permanently unsatisfiable, and the gate (bidding in the original report; transaction admission here) is closed for all future traffic.

By contrast, the codebase demonstrates the correct pattern is well known internally: `MempoolStaticConfig::fee_escalation_percentage` bounds itself to `[1, 100]` [3](#0-2) 
and is unit-tested for out-of-range rejection [4](#0-3) ,
while `min_gas_price_percentage` has no equivalent protection.

### Impact Explanation
If `min_gas_price_percentage` is misconfigured to a value that produces an unreachable threshold (e.g. > 100 combined with the bounded per-block gas price growth), the gateway's stateful validator rejects every V3 transaction with `AllResources` bounds submitted by any unprivileged sender. This halts admission of new transactions network-wide — matching the "network unable to confirm new transactions" impact criterion — until an operator manually reverts the configuration. This is a availability-critical, network-wide denial that a single misconfigured deploy (not a malicious actor) can trigger, exactly as in the original report where a configuration choice silently and permanently blocked all new auctions/bids.

### Likelihood Explanation
Likelihood is Medium: it requires an operator misconfiguration rather than exploitation by an unprivileged actor, but the root cause is a missing validation guard that should exist (as it does for the analogous `fee_escalation_percentage` field), making an accidental incorrect value plausible during config rollout/tuning of gas-price thresholds — precisely the scenario the original report flags as having actually occurred in production.

### Recommendation
Add a `#[validate(range(min = 1, max = 100))]` (or similar) constraint to `min_gas_price_percentage`, and/or add a cross-field sanity validation function (similar to `validate_all_rate_bounds_config` in `apollo_l1_gas_price_config`) that rejects configurations where the percentage, combined with the maximum per-block gas price change rate, could make the threshold unreachable within a bounded number of blocks. Additionally, add a unit test analogous to `zero_fee_escalation_percentage_fails_validation` that asserts out-of-range `min_gas_price_percentage` values fail config validation.

### Proof of Concept
1. Deploy the gateway with `stateful_tx_validator_config.min_gas_price_percentage` set to `200` (or any value that yields a threshold above the maximum price the dynamic gas-price mechanism can produce given its bounded per-block change rate).
2. Config validation (`config_validate`) passes because no range constraint exists on this field.
3. Any account submits a valid V3 invoke transaction with `AllResources` bounds and a reasonable `max_price_per_unit` for L2 gas.
4. `validate_tx_l2_gas_price_within_threshold` computes `threshold = 200% * previous_block_l2_gas_price`, which the submitted (and any realistic) `tx_l2_gas_price` cannot meet.
5. The gateway returns `StarknetErrorCode.GAS_PRICE_TOO_LOW` for every transaction, and this repeats for every subsequent transaction from every sender since price cannot catch up to the threshold within the bounded per-block adjustment, freezing new transaction admission network-wide.

pub struct StatefulTransactionValidatorConfig {
    // If true, ensures the max L2 gas price exceeds (a configurable percentage of) the base gas
    // price of the previous block.
    pub validate_resource_bounds: bool,
    pub max_allowed_nonce_gap: u32,
    pub reject_future_declare_txs: bool,
    pub max_nonce_for_validation_skip: Nonce,
    pub versioned_constants_overrides: Option<VersionedConstantsOverrides>,
    // Minimum gas price as percentage of threshold to accept transactions.
    pub min_gas_price_percentage: u8, // E.g., 80 to require 80% of threshold.
}

impl Default for StatefulTransactionValidatorConfig {
    fn default() -> Self {
        StatefulTransactionValidatorConfig {
            validate_resource_bounds: true,
            max_allowed_nonce_gap: 200,
            reject_future_declare_txs: true,
            max_nonce_for_validation_skip: Nonce(Felt::ONE),
            min_gas_price_percentage: 100,
            versioned_constants_overrides: None,
        }
    }
}

    // TODO(Arni): Consider running this validation for all gas prices.
    fn validate_tx_l2_gas_price_within_threshold(
        &self,
        tx_resource_bounds: ValidResourceBounds,
        previous_block_l2_gas_price: NonzeroGasPrice,
    ) -> StatefulTransactionValidatorResult<()> {
        match tx_resource_bounds {
            ValidResourceBounds::AllResources(tx_resource_bounds) => {
                let tx_l2_gas_price = tx_resource_bounds.l2_gas.max_price_per_unit;
                let gas_price_threshold_multiplier =
                    Ratio::new(self.config.min_gas_price_percentage.into(), 100_u128);
                let threshold = (gas_price_threshold_multiplier
                    * previous_block_l2_gas_price.get().0)
                    .to_integer();
                if tx_l2_gas_price.0 < threshold {
                    return Err(StarknetError {
                        // We didn't have this kind of an error.
                        code: StarknetErrorCode::UnknownErrorCode(
                            "StarknetErrorCode.GAS_PRICE_TOO_LOW".to_string(),
                        ),
                        message: format!(
                            "Transaction L2 gas price {tx_l2_gas_price} is below the required \
                             threshold {threshold}.",
                        ),
                    });
                }
            }
            ValidResourceBounds::L1Gas(_) => {
                // No validation required for legacy transactions.
            }
        }
        Ok(())
    }
