### Title
Missing declared-class validation in Starknet OS `execute_replace_class` allows blockifier/OS state divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The `replace_class` syscall implementation in the Starknet OS Cairo program does not verify that the supplied `class_hash` corresponds to a declared class before writing it into `contract_state_changes`, whereas the Rust Blockifier's implementation of the same syscall does perform this check. An unprivileged contract can invoke `replace_class_syscall` with an arbitrary, undeclared class hash; the Blockifier execution path (used by the sequencer to build/validate blocks) rejects it, while the OS re-execution path (used to generate the state diff that is committed/proven) accepts it unconditionally, producing divergent state.

### Finding Description
In `crates/blockifier/src/execution/syscalls/syscall_base.rs` the Rust `replace_class` implementation explicitly requires the class to be declared and of the correct version before allowing the class hash write: [1](#0-0) 

The same guarantee is exercised for the deprecated syscall path: [2](#0-1) 

However, the Starknet OS Cairo implementation of the identical syscall (`execute_replace_class` in `syscall_impls.cairo`, used for Cairo1 contracts) performs no such validation — it directly reads the caller-controlled `class_hash` from the syscall request and unconditionally updates `contract_state_changes`, with an explicit TODO acknowledging the gap: [3](#0-2) 

The deprecated (Cairo0) OS syscall handler `execute_replace_class` in `deprecated_execute_syscalls.cairo` has the identical omission — it also unconditionally performs the `dict_update` without checking that `class_hash` is declared: [4](#0-3) 

By contrast, Blockifier's own regression tests confirm that calling `replace_class` with an undeclared class hash is explicitly rejected ("is not declared") in the reference execution engine: [5](#0-4) 

This mirrors the report's bug class: an unprivileged caller supplies an unvalidated "pool"/class-hash-like input to a code path (`prepare`/`replace_class`) that trusts it and stores it for later use, while a parallel code path (`liquidate`/OS re-execution) consumes that unvalidated, cached value to make consequential decisions — here, the committed state diff.

### Impact Explanation
Any contract can call `replace_class_syscall(arbitrary_undeclared_class_hash)`. When the transaction is executed by the Blockifier (which the sequencer/batcher/gateway use to build blocks, run the mempool simulation, and the committer relies on for the state diff), the call is rejected: no class-hash write occurs and, depending on how the caller handles the syscall error, the inner call reverts. When the same transaction block is re-executed by the Starknet OS (used for zk-proving and for OS-based re-execution/verification, e.g. Echonet re-execution testing and the transaction prover), the OS unconditionally accepts the undeclared class hash and records a `contract_state_changes` update replacing the contract's class hash.

This produces a genuine divergence between the sequencer's committed state (built via Blockifier) and the state the OS would compute/prove for the same block, i.e., an honest-node divergence and a state root/class-hash mismatch for that contract address. Since the OS's output underlies the STARK proof of block validity, this is a state-commitment-level correctness bug — a High-severity issue affecting the account whose contract makes the call and the integrity of the proven state.

### Likelihood Explanation
This is trivially reachable: any contract deployer can add a single Cairo1 (or Cairo0) function that calls `replace_class_syscall` with a hardcoded arbitrary felt (no need to actually deploy or control a "malicious pool" contract as in the analog report — just an undeclared class hash constant). Invoking that function via one ordinary `INVOKE` transaction is sufficient to trigger the divergence; no special privileges, staking, or operator cooperation are required.

### Recommendation
Add the same "class must be declared" check to the Starknet OS Cairo `execute_replace_class` implementations (both the Cairo1 path in `syscall_impls.cairo` and the deprecated Cairo0 path in `deprecated_execute_syscalls.cairo`) that already exists in the Rust Blockifier (`syscall_base.rs::replace_class`), i.e., verify `class_hash` is present in `contract_class_changes`/declared-class state before performing the `dict_update`, and reject/revert otherwise, exactly matching Blockifier's `get_compiled_class` + `is_cairo1` semantics. This closes the TODO already flagged in the code.

### Proof of Concept
1. Deploy a Cairo1 contract with an external function:
```cairo
#[external(v0)]
fn trigger(self: @ContractState) {
    // 0xdead is never declared on-chain
    starknet::replace_class_syscall(0xdead.try_into().unwrap()).unwrap_syscall();
}
```
2. Send a single `INVOKE` transaction calling `trigger()`.
3. Under the Blockifier (sequencer execution/simulation), the syscall fails with `UndeclaredClassHash`/"is not declared", matching the behavior shown in the existing test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`.
4. Under Starknet OS re-execution (`execute_replace_class` in `syscall_impls.cairo`), no such check exists; the OS records a `contract_state_changes` `dict_update` unconditionally, setting the contract's class hash to `0xdead` in the OS-computed state diff.
5. Comparing the state diff/committed root produced by the Blockifier-based sequencer versus the OS-based re-execution for this block reveals a divergence on the calling contract's class hash — confirming the state-commitment mismatch.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];
