Interesting comment found: in `types/src/transaction/mod.rs`, `ensure_match_transaction_info` explicitly notes it does not validate the `position_state_checkpoint_hash` (or hot-state checkpoint hash), which is a real, code-documented integrity gap for replay-verify tooling.## Title
`ensure_match_transaction_info` skips validating `position_state_checkpoint_hash` (and hot-state checkpoint hash), letting replay/verify tooling accept a `TransactionOutput` whose native-position state root diverges from the authenticated `TransactionInfo` - (File: types/src/transaction/mod.rs)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the integrity check used by chunk-executor verification and replay-verify tooling to confirm a computed `TransactionOutput` matches the on-chain `TransactionInfo` for a version. It checks status, gas used, write-set hash (`state_change_hash`), and event root hash, but it explicitly and knowingly does **not** check `state_checkpoint_hash`/`hot_state_checkpoint_hash`, and in particular does not check `position_state_checkpoint_hash` at all, even though the code comment flags this as a known gap ahead of enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`.

### Finding Description
`ensure_match_transaction_info` in [1](#0-0)  validates only:
- `status` vs `txn_info.status()`
- `gas_used` vs `txn_info.gas_used()`
- `write_set_hash` vs `txn_info.state_change_hash()`
- `event_root_hash` vs `txn_info.event_root_hash()`

The comment directly preceding `Ok(())` states: "this comparator ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`), so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution. Validate the checkpoint hashes here before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`." [2](#0-1) 

This is used by `execution/executor/src/chunk_executor/mod.rs` (chunk verification path) and by debugger/replay tooling (`aptos-move/aptos-debugger/src/aptos_debugger.rs`, `aptos-move/cli/src/commands.rs`) as one of the authenticity checks between locally-recomputed `TransactionOutput`s and trusted `TransactionInfo` records fetched from a peer/archive. `TransactionInfoV1` carries `position_state_checkpoint_hash` as a first-class field alongside `state_checkpoint_hash`/`hot_state_checkpoint_hash` [3](#0-2) , and the native-position state root is computed and cross-checked elsewhere in the normal execution path (`DoStateCheckpoint::compute_position_checkpoint` / `get_state_checkpoint_hashes`, which does `ensure!` against known hashes) [4](#0-3) . However, `ensure_match_transaction_info` is a *separate*, independent verification code path (used for replay/verify, not the main executor commit path), and it silently skips this field.

### Impact Explanation
This is state-integrity relevant because if `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (native-position/"trading native" state feature) is enabled and a bug or a divergent execution produces a wrong `position_state_checkpoint_hash`, tools relying on `ensure_match_transaction_info` (replay-verify, debugger cross-checks) will report success even though the locally computed native-position Merkle root diverges from the authenticated on-chain value. That defeats the purpose of replay verification as an integrity backstop for the position/trading-native state tree, potentially masking a consensus-breaking bug or corrupted position state during audits/replay rather than catching it. It does not by itself corrupt the main committed ledger state (the primary commit path's `DoStateCheckpoint` does perform the `ensure!` check against known hashes), so the severity is bounded to detection/verification tooling rather than direct on-chain state corruption.

### Likelihood Explanation
The gap is explicit and acknowledged in the code's own TODO comment, confirming it is a real, currently-existing omission rather than speculation. However, exploitability requires `COMPUTE_TRADING_NATIVE_STATE_ROOTS` to be enabled (this is a newer, feature-gated "trading native"/position-state subsystem) and requires a scenario where `TransactionOutput` is independently reconstructed and compared via this specific function (replay-verify / debugger paths) rather than the main executor commit pipeline, which has its own independent checkpoint-hash validation. This limits likelihood to replay/audit-time detection failures rather than a directly exploitable mainnet consensus divergence.

### Recommendation
Extend `ensure_match_transaction_info` to also compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present on the `TransactionInfo` variant) against the locally computed values, consistent with the checks already performed by `DoStateCheckpoint::get_state_checkpoint_hashes` in the primary execution path, before/when enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS` in production.

### Proof of Concept
Not directly exploitable as an on-chain state-corruption PoC; the issue is a missing-check in a verification helper. Conceptual PoC: run `db-tool replay-on-archive` (or equivalent debugger tool using `ensure_match_transaction_info`) against a version whose locally recomputed native-position state root differs from the archived `TransactionInfo.position_state_checkpoint_hash` (e.g., due to a bug in `compute_position_checkpoint`); the tool will report the replay as matching/successful because this field is never compared, whereas the main executor's own `ensure!` (which is a separate, independent code path invoked only during forward execution, not during this replay comparison) would have caught the divergence had it been exercised.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
