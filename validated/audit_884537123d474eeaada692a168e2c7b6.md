### Title
Spot-price-only Uniswap V3 quote used for `minPCOut` slippage protection enables sandwich manipulation of auto-swap deposits and gas refunds - (File: x/uexecutor/keeper/evm.go)

### Summary
The external report flags a fee-timing vulnerability where a value used for accounting is read at a single, manipulable point in time instead of averaged over an interval. Push Chain's PRC20 auto-swap flow has the same class of bug: `GetSwapQuote` reads a single spot quote from the on-chain Uniswap V3 `QuoterV2` immediately before executing a real swap, with no TWAP or interval-based reference price, so the "protection" derived from it (`minPCOut = quote * 95%`) protects against nothing but a manipulated version of itself.

### Finding Description
`Keeper.GetSwapQuote` ( [1](#0-0) ) performs a single `CallEVM` (non-commit) call to `QuoterV2.quoteExactInputSingle`, returning the current spot-price-derived output amount for the pool. This is consumed immediately in `ExecuteInboundGas`: [2](#0-1) 

and in `gasAndPayloadDepositAutoSwap` for `GAS_AND_PAYLOAD` inbound routes: [3](#0-2) 

as well as in the gas-refund path `applyGasRefund` used on successful outbound finalization: [4](#0-3) 

In every case, `minPCOut` is computed as `quote * 95 / 100` — a 5% band around the *current* pool state, not a time-weighted or otherwise attack-resistant reference price. Because the quote read (`CallEVM`, commit=false) and the swap execution (`DerivedEVMCall`, commit=true) both operate against Push Chain's own live AMM state, an unprivileged actor who can move the pool price with an ordinary swap transaction earlier in the same block (or in a preceding block, since inbound finalization is driven by validator votes reaching quorum and is not synchronized to price freshness) can force the module to compute `minPCOut` off a manipulated price. The module then executes the deposit-with-swap (or gas refund) at that manipulated price, and the attacker reverses their price-moving trade afterward, capturing the difference at the expense of the depositing user or the protocol's refund recipient. The upgrade log confirms this quote mechanism is a recent, deliberate design choice ( [5](#0-4) ), replacing an even weaker "0-slippage" call, but it still relies purely on a spot quote.

### Impact Explanation
A successful sandwich against `GetSwapQuote` lets an unprivileged attacker extract value from ordinary users' GAS/GAS_AND_PAYLOAD inbound deposits (users receive fewer native PC tokens than fair value for their bridged gas token) and from gas-fee-refund swaps (`refundUnusedGas` withSwap path), directly corrupting native/PRC20 asset accounting and draining protocol- or user-controlled funds — matching the in-scope impact "corruption of PRC20 or native asset accounting ... revert destination ... refund accounting" and "draining ... of user or protocol-controlled funds."

### Likelihood Explanation
Reachable by an ordinary unprivileged user: no validator, TSS, or admin privilege is required — only the ability to submit swap transactions against the Uniswap V3 pool that Push Chain's `UniversalCore` contract queries, and to trigger (or wait for) an inbound/outbound finalization that invokes the auto-swap or refund path. Feasibility scales with the manipulability of the specific pool's liquidity depth, which is plausible for lower-liquidity PRC20/gas-token pools especially early after listing.

### Recommendation
Do not derive `minPCOut` solely from a same-instant `quoteExactInputSingle` call. Use a TWAP-based reference price (e.g., Uniswap V3 pool `observe`/oracle cardinality) or an independently-sourced, validator-attested price feed to bound acceptable slippage, and/or clamp the acceptable deviation between the spot quote and a longer-window reference before accepting `minPCOut`.

### Proof of Concept
1. Attacker identifies a thin-liquidity PRC20↔WPC pool configured as `defaultFeeTier` for a supported gas token.
2. Attacker submits a large swap to push the pool's spot price sharply against the token being deposited.
3. A GAS or GAS_AND_PAYLOAD inbound (from any user) reaches quorum and triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, which calls `GetSwapQuote` ( [1](#0-0) ) against the manipulated pool, then immediately calls `CallPRC20DepositAutoSwap` with `minPCOut` computed from that bad quote.
4. The depositing user receives PC at the manipulated exchange rate.
5. Attacker reverses the initial swap, restoring the pool price and pocketing the spread.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
