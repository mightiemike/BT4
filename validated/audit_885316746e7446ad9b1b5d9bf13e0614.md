### Title
Undocumented, still-live `MsgMigrateUEA` message creates a second, independently-authorized path to migrate a UEA — overlapping authorizers for the same privileged state transition - ([File: x/uexecutor/keeper/msg_migrate_uea.go])

### Summary
The external GMX report flagged that two independently-maintained "authorizer" surfaces (`GMXV1Authorization`/`GMXV2Authorization` vs. `ERC20ApproveAuthorization`/`ERC20TransferAuthorization`) exposed the *same* privileged operation through *different* validation logic, letting a caller pick the weaker path and reach an inconsistent approval state. Push Chain has a structural analog: `x/uexecutor` exposes two independent Cosmos-layer message paths that can both perform a UEA implementation migration — `MsgMigrateUEA` (a message the module's own README says "has been removed") and `MsgExecutePayload` (the documented, currently-supported path). Both are wired end-to-end, both are gasless, and each drives a *different* EVM entry point on the UEA contract with its own payload/nonce shape.

### Finding Description
`x/uexecutor/README.md` states explicitly:

> "UEA migration is now part of payload execution. There used to be a separate `MsgMigrateUEA` message; that path has been removed. UEAs are upgraded by submitting a normal `MsgExecutePayload`... The Cosmos layer no longer has a dedicated migration message." [1](#0-0) 

This is contradicted by the live code: `MsgMigrateUEA` is still fully defined in proto, registered on the `MsgServer`, and has a complete, callable keeper implementation: [2](#0-1) [3](#0-2) 

`MsgMigrateUEA` is also still present in the gasless-message allowlist that the AnteHandler consults, so an unprivileged attacker can submit it for free, with no Cosmos fee: [4](#0-3) 

The `MigrateUEA` keeper flow is a *second, independent* authorization surface for the same privileged effect ("change what a UEA points to / upgrade its implementation") that `MsgExecutePayload` is documented as the sole owner of:
- `MsgExecutePayload` resolves the UEA and calls `executeUniversalTx(payload, verificationData)`, whose signature/nonce/deadline are all embedded in the generic `UniversalPayload` and checked by the UEA contract's general nonce counter. [5](#0-4) 
- `MsgMigrateUEA` instead resolves the UEA and calls a distinct EVM entry point (`CallUEAMigrateUEA`) using a completely separate payload shape — `MigrationPayload{Migration, Nonce, Deadline}` plus a raw `Signature` string — that is validated and its own nonce/deadline tracked independently of the `executeUniversalTx` nonce path. [6](#0-5) [7](#0-6) 

This mirrors the GMX pattern precisely: two authorizers ("`MsgExecutePayload`→UEA generic nonce" and "`MsgMigrateUEA`→UEA migration-specific nonce/deadline") both claim jurisdiction over the same privileged action (UEA migration), each with its own independent state-tracking and independent validation rules, contrary to the "only one authorizer should own a selector" principle recommended in the referenced report. Because the maintainers' own documentation asserts this second path was retired, it is very likely to have received substantially less audit/test scrutiny and less monitoring on the ops side (e.g., alerting/anomaly detection built around `MsgExecutePayload` usage patterns) than the documented path, while still being reachable, gasless, and callable by any unprivileged account for any `UniversalAccountId`.

### Impact Explanation
If the UEA contract's `migrate` entry point (invoked via `CallUEAMigrateUEA`) tracks replay protection independently from the `executeUniversalTx` nonce, an attacker gains a second window to attempt privileged migration calls against a target UEA using stale or differently-scoped state (e.g., a `migrate`-specific nonce that lags behind or is unaware of nonce advancement on the `executeUniversalTx` side, or vice versa). Since UEA migration changes the implementation/logic a user's Universal Account executes, a successful desynchronization or a race between the two paths could let an attacker with a previously-valid-but-stale migration authorization push a UEA to an unintended implementation after the "current" path had already advanced state — a form of unauthorized/duplicated module-originated EVM execution and an unauthorized state transition in the universal execution flow, matching the in-scope impact category directly.

### Likelihood Explanation
Reaching this code path requires no privilege: any account can submit `MsgMigrateUEA` (it is gasless and open to "any user," identical to `MsgExecutePayload`'s authorization model). The likelihood of a *concrete* fund-affecting outcome depends on details of the UEA contract's nonce/replay design for `migrate` vs. `executeUniversalTx`, which lives in the separate `push-chain-core-contracts` repository and was **not fully verifiable from the indexed code available here** — I could not confirm whether the two entry points share a single monotonic nonce or track separate counters. What is fully confirmed and reproducible from this repository alone is the structural bug: a documented-as-removed, independently-validated authorization surface for a privileged action remains live, wired, and gasless-reachable, which is the exact "overlap of authorizers over one privileged function" class flagged in the source report, regardless of the precise contract-side consequence.

### Recommendation
1. Reconcile documentation and code: either fully remove `MsgMigrateUEA` (proto, msg server, keeper, gasless allowlist) as the README claims, or update the README to accurately describe it as still-active and give it the same authorization scrutiny as `MsgExecutePayload`.
2. If `MsgMigrateUEA` is to be kept, ensure the UEA contract enforces a single shared nonce/replay-protection surface for *all* code paths that can mutate its implementation (`executeUniversalTx`-driven migration calls and `migrateUEA` calls), so that a signature/nonce validated as stale on one path cannot be replayed successfully via the other.
3. Add a regression test asserting that once a UEA's implementation-affecting nonce advances via one path, the same/older nonce is rejected via the other path.
4. Audit `push-chain-core-contracts`' UEA contract migration logic specifically for this two-entry-point nonce consistency, since that is where the ultimate authorization decision (per the module's own README) is asserted to live.

Not independently reproducible from this repository alone, because the decisive check (whether `migrateUEA`'s nonce/deadline validation on the UEA contract is shared with or isolated from `executeUniversalTx`'s nonce) lives in the external `push-chain-core-contracts` Solidity source, which is out of scope/not indexed here. The reproducible module-layer PoC is:

2. Submit `MsgMigrateUEA{Signer: attacker, UniversalAccountId: victimUEA, MigrationPayload, Signature}` for free (no fee required) via the ante pipeline, exercising a path the module's own documentation states is retired. [2](#0-1)

Compare its independent payload/nonce shape (`MigrationPayload.Nonce`/`Deadline`) against the nonce embedded in `UniversalPayload` used by `MsgExecutePayload`, confirming two structurally distinct authorization/replay schemes exist for what the documentation calls a single, unified migration mechanism. func (k Keeper) MigrateUEA(ctx context.Context, evmFrom common.Address, universalAccountId *types.UniversalAccountId, migrationPayload *types.MigrationPayload, signature string) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Get Caip2Identifier for the universal account
	caip2Identifier := universalAccountId.GetCAIP2()

	k.Logger().Info("migrate UEA",
		"from", evmFrom.Hex(),
		"chain", caip2Identifier,
		"owner", universalAccountId.Owner,
	)

	// Step 1: Parse and validate payload and signature
	_, err := types.NewAbiMigrationPayload(migrationPayload)
	if err != nil {
		return errors.Wrapf(err, "invalid migration payload")
	}

	// add signature verification
	signatureVal, err := utils.HexToBytes(signature)
	if err != nil {
		return errors.Wrapf(err, "invalid signature format")
	}

	chainConfig, err := k.uregistryKeeper.GetChainConfig(sdkCtx, caip2Identifier)
	if err != nil {
		return errors.Wrapf(err, "failed to get chain config for chain %s", caip2Identifier)
	}

	// TODO: Decide later if migration should be disabled if inbound is disabled
	if !chainConfig.Enabled.IsInboundEnabled {
		k.Logger().Warn("migrate UEA rejected: chain not enabled", "chain", caip2Identifier)
		return fmt.Errorf("chain %s is not enabled", caip2Identifier)
	}

	factoryAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)

	// Step 2: Compute smart account address
	// Calling factory contract to compute the UEA address
	ueaAddr, isDeployed, err := k.CallFactoryToGetUEAAddressForOrigin(sdkCtx, evmFrom, factoryAddress, universalAccountId)
	if err != nil {
		return err
	}

	if !isDeployed {
		k.Logger().Warn("migrate UEA rejected: UEA not deployed", "chain", caip2Identifier, "owner", universalAccountId.Owner)
		return fmt.Errorf("UEA is not deployed")
	}

	k.Logger().Debug("migrating UEA",
		"uea", ueaAddr.Hex(),
		"chain", caip2Identifier,
		"from", evmFrom.Hex(),
	)

	// Step 3: Migrate UEA through UEA
	receipt, err := k.CallUEAMigrateUEA(sdkCtx, evmFrom, ueaAddr, migrationPayload, signatureVal)
	if err != nil {
		return err
	}

	k.Logger().Info("UEA migrated",
		"chain", caip2Identifier,
		"uea", ueaAddr.Hex(),
		"tx_hash", receipt.Hash,
		"gas_used", receipt.GasUsed,
	)

	return nil
}

// CallUEAExecutePayload executes a universal payload through UEA
func (k Keeper) CallUEAExecutePayload(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	universal_payload *types.UniversalPayload,
	verificationData []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiUniversalPayload, err := types.NewAbiUniversalPayload(universal_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	gasLimit := new(big.Int)
	gasLimit, ok := gasLimit.SetString(universal_payload.GasLimit, 10)
	if !ok {
		return nil, fmt.Errorf("invalid gas limit: %s", universal_payload.GasLimit)
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		gasLimit,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"executeUniversalTx",
		abiUniversalPayload,
		verificationData,
	)
}

// ValidateBasic does the sanity check on the UniversalPayload fields.
func (p MigrationPayload) ValidateBasic() error {
	// Validate 'migration' address
	if strings.TrimSpace(p.Migration) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "migration address cannot be empty")
	}
	if !utils.IsValidAddress(p.Migration, utils.HEX) {
		return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid migration contract address format: %s", p.Migration)
	}

	// Validate all numeric string fields as uint256
	uintFields := map[string]string{
		"nonce":    p.Nonce,
		"deadline": p.Deadline,
	}

	for fieldName, value := range uintFields {
		if value != "" {
			bi, ok := new(big.Int).SetString(value, 10)
			if !ok || bi.Sign() < 0 {
				return errors.Wrapf(sdkerrors.ErrInvalidRequest, "%s must be a valid unsigned integer", fieldName)
			}
		}
	}

	return nil
}
