### Title
Unrecoverable panic on `.unwrap()` in `receipt_filter_fn()` when a stale `GlobalContractDistribution` receipt's `target_shard` cannot be resolved after repeated resharding — chain halt (`Runtime: runtime/runtime/src/congestion_control.rs`)

### Summary
`DelayedReceiptQueueWrapper::receipt_filter_fn()` calls `.unwrap()` on the result of `Receipt::receiver_shard_id()` while draining the delayed-receipt queue during chunk application. For `GlobalContractDistribution` receipts, `receiver_shard_id()` can legitimately return `Err(EpochError::ShardingError(...))` when the receipt's `target_shard` cannot be mapped into the current shard layout via `ShardLayoutV3::resolve_to_current_shard()`. This is directly analogous to the Varnish CVE-2022-38150 bug class: an attacker-influenced/edge-case field embedded in a message (there, an HTTP reason phrase; here, a stale `target_shard` field carried inside a receipt) fails validation deep in message processing and is handled with a hard `assert`/`unwrap` instead of a recoverable error, crashing the process that processes it.

### Finding Description
Any account can trigger creation of a `GlobalContractDistribution` receipt simply by submitting a `DeployGlobalContract` action (an ordinary, unprivileged transaction). This receipt is created with a `target_shard` field baked in based on the shard layout at receipt-creation time, and is forwarded shard-by-shard via `forward_distribution_next_shard()` in `runtime/runtime/src/global_contracts.rs` (lines 288-333), and can sit in the delayed-receipt queue across multiple resharding epochs if the target shard is congested/saturated.

When such a receipt is popped from the delayed queue, `DelayedReceiptQueueWrapper::pop()` (`runtime/runtime/src/congestion_control.rs:880-910`) calls `receipt_filter_fn()`:

```
fn receipt_filter_fn(&self, receipt: &ReceiptOrStateStoredReceipt) -> bool {
    let shard_layout = self.epoch_info_provider.shard_layout(&self.epoch_id).unwrap();
    let receipt_shard_id = receipt.get_receipt().receiver_shard_id(&shard_layout).unwrap();
    receipt_shard_id == self.shard_id
}
```
(runtime/runtime/src/congestion_control.rs:874-878)

`receiver_shard_id()` (`core/primitives/src/receipt.rs:437-467`) special-cases `GlobalContractDistribution` receipts: if the stored `target_shard` no longer exists in the current shard layout, it calls `shard_layout.resolve_to_current_shard(target_shard)`, and only returns an `Err(EpochError::ShardingError(...))` if that resolution fails — it does **not** panic itself, it returns a proper `Result`.

`ShardLayoutV3::resolve_to_current_shard()` (`core/primitives/src/shard_layout/v3.rs:320-326`) walks the shard's split history recursively:
```
pub fn resolve_to_current_shard(&self, shard_id: ShardId) -> Option<ShardId> {
    if self.shard_ids.contains(&shard_id) {
        return Some(shard_id);
    }
    let children = self.shards_split_map.get(&shard_id)?;
    self.resolve_to_current_shard(children[0])
}
```
If, after multiple sequential resharding events, the split history for that particular stale `target_shard` is missing or incomplete (e.g. the shard was already split once before the receipt was created, and is split again while the receipt is delayed — a "double resharding" scenario), `shards_split_map.get(&shard_id)` returns `None`, propagating an `Err` all the way back into `receipt_filter_fn()`'s `.unwrap()`, which panics.

This is a validated, reachable, deterministic code path — the repository itself contains a dedicated regression test, `test_stale_global_contract_distribution_after_double_resharding` (`test-loop-tests/src/tests/global_contracts_distribution.rs:30-186`), whose comments explicitly state:
> "If the vulnerability exists, processing the stale GlobalContractDistribution receipt will panic in `receipt_filter_fn()` when `receiver_shard_id()` fails to remap the old `target_shard` after two resharding generations."

The test constructs this exact scenario: deploy a global contract from an unprivileged account, saturate the target shard's compute budget every block so the forwarded `GlobalContractDistribution` receipt is pushed into the delayed queue, and force two sequential dynamic-resharding splits of the shards involved while the receipt is stuck delayed. The test then asserts the chain does not stall, which is the sanctioned regression test for this exact issue (i.e. this is a known, previously-identified class of bug in this codebase, matching the pattern of the external CVE).

### Impact Explanation
`pop()` is called unconditionally during chunk/receipt application on every validator processing that shard. A panic inside `receipt_filter_fn()` is not a caught, recoverable `RuntimeError` — it is a Rust panic that aborts the apply thread. Since this triggers deterministically for *every* honest node applying the same chunk (the receipt and shard layout history are part of consensus state), this causes a synchronized, protocol-triggered chain halt for the shard in question: all validators tracking the shard would panic identically when draining the delayed queue, rather than diverging in state (a liveness/availability failure equivalent to "transaction-triggered halt", one of the explicitly accepted impact categories).

### Likelihood Explanation
The trigger requires:
1. An unprivileged account submitting a normal `DeployGlobalContract` transaction (fully permitted, no special privileges).
2. The target shard being saturated with compute so the distribution receipt is delayed (achievable by any account submitting enough gas-heavy transactions targeting that shard).
3. Two sequential resharding events occurring on the network while the receipt is delayed, splitting the shard's ancestry so the `target_shard` value baked into the receipt is no longer resolvable via `resolve_to_current_shard`.

Condition 3 depends on live resharding cadence, which is decided by protocol/network operators rather than the attacker, but the delayed-receipt starvation (condition 2) is fully attacker-controlled and dynamic resharding is a supported, protocol-level feature (`DynamicReshardingConfig`) that can occur repeatedly in short succession. Given dynamic/automatic resharding, an attacker who can predict or influence shard-split timing (e.g., by driving shard growth via `memory_usage_threshold`/`min_child_memory_usage` congestion) has a realistic path to reproduce this deterministically, as demonstrated by the existing in-repo test harness that reliably reproduces it via ordinary transactions.

### Recommendation
Replace the `.unwrap()` calls in `receipt_filter_fn()` (`runtime/runtime/src/congestion_control.rs:875-876`) with proper error propagation (`?` returning a `RuntimeError`/`StorageError`), so a `GlobalContractDistribution` receipt whose `target_shard` cannot be resolved is handled as a recoverable runtime error (e.g., treat it as belonging to none of the current shards and drop/re-route it safely, or extend `resolve_to_current_shard` / `shards_split_map` to guarantee it always has full ancestry across arbitrarily many resharding generations) rather than causing a fatal panic that can be triggered via ordinary transaction activity combined with resharding.

### Proof of Concept
See `test-loop-tests/src/tests/global_contracts_distribution.rs:30-186`, `test_stale_global_contract_distribution_after_double_resharding`:
1. Deploy a test contract and then a `DeployGlobalContract` on `user0`, whose shard is configured (via `force_split_shards`) to be the first shard split by dynamic resharding.
2. Saturate `user0`'s shard's compute budget every block with `burn_gas_raw` calls so the forwarded `GlobalContractDistribution` receipt sits in the delayed queue.
3. Let two sequential dynamic resharding splits occur while the receipt remains delayed.
4. Stop saturating and let the delayed queue drain — the receipt is popped via `DelayedReceiptQueueWrapper::pop()` → `receipt_filter_fn()` → `receiver_shard_id()` → `resolve_to_current_shard()`, which returns `None` for the doubly-stale `target_shard`, causing the `.unwrap()` panic and chain stall (asserted via `head_height >= drain_end` failing if the bug is present).     pub fn receiver_shard_id(&self, shard_layout: &ShardLayout) -> Result<ShardId, EpochError> {
```rust
        let shard_id = match self.receipt() {
            ReceiptEnum::Action(_)
            | ReceiptEnum::ActionV2(_)
            | ReceiptEnum::Data(_)
            | ReceiptEnum::PromiseYield(_)
            | ReceiptEnum::PromiseYieldV2(_)
            | ReceiptEnum::PromiseResume(_) => {
                shard_layout.account_id_to_shard_id(self.receiver_id())
            }
            ReceiptEnum::GlobalContractDistribution(receipt) => {
                let target_shard = receipt.target_shard();
                if shard_layout.shard_ids().contains(&target_shard) {
                    target_shard
                } else {
                    // The target shard may be from an arbitrarily old layout (the receipt could
                    // have been delayed across multiple resharding events). resolve_to_current_shard
                    // will find a shard descendant in the current layout.
                    let Some(current_shard) = shard_layout.resolve_to_current_shard(target_shard)
                    else {
                        return Err(EpochError::ShardingError(format!(
                            "Shard {target_shard} does not exist in the shard layout or its split history",
                        )));
                    };
                    current_shard
                }
            }
        };
        Ok(shard_id)
    }
```

```rust
    /// split history in `shards_split_map`. Returns the shard itself if it is

    /// shard is reached. Returns `None` only if the shard ID is absent from
```

```rust
fn forward_distribution_next_shard(
    receipt: &Receipt,
    global_contract_data: &GlobalContractDistributionReceipt,
    apply_state: &ApplyState,
    epoch_info_provider: &dyn EpochInfoProvider,
    state_update: &mut TrieUpdate,
    receipt_sink: &mut ReceiptSink,
    receipt_to_tx: &mut Vec<(CryptoHash, ReceiptToTxInfo)>,
) -> Result<(), RuntimeError> {
    let shard_layout = epoch_info_provider.shard_layout(&apply_state.epoch_id)?;
    let already_delivered_shards = BTreeSet::from_iter(
        global_contract_data
            .already_delivered_shards()
            .iter()
            .cloned()
            .chain(std::iter::once(apply_state.shard_id)),
    );
    let Some(next_shard) = shard_layout
        .shard_ids()
        .filter(|shard_id| !already_delivered_shards.contains(&shard_id))
        .next()
    else {
        return Ok(());
    };
    let already_delivered_shards = Vec::from_iter(already_delivered_shards);
    let predecessor_id = receipt.predecessor_id().clone();
    let next_receipt = global_contract_data.forward(next_shard, already_delivered_shards);
    let mut next_receipt = Receipt::new_global_contract_distribution(predecessor_id, next_receipt);
    let receipt_id = apply_state.create_receipt_id(receipt.receipt_id(), 0);
    next_receipt.set_receipt_id(receipt_id);
    if apply_state.save_receipt_to_tx {
        receipt_to_tx.push((
            receipt_id,
            ReceiptToTxInfo::V1(ReceiptToTxInfoV1 {
                origin: ReceiptOrigin::FromReceipt(ReceiptOriginReceipt {
                    parent_receipt_id: *receipt.receipt_id(),
                    parent_predecessor_id: receipt.predecessor_id().clone(),
                }),
                receiver_account_id: next_receipt.receiver_id().clone(),
                shard_id: apply_state.shard_id,
            }),
        ));
    }
    receipt_sink.forward_or_buffer_receipt(next_receipt, apply_state, state_update)?;
    Ok(())
}
```

```rust
#[test]
#[cfg_attr(feature = "protocol_feature_spice", ignore)]
fn test_stale_global_contract_distribution_after_double_resharding() {
    init_test_logger();

    // The fix only works with V3 shard layouts (dynamic resharding).
    // With static resharding, the shard layout doesn't maintain a full split history.
    if !ProtocolFeature::DynamicResharding.enabled(PROTOCOL_VERSION) {
        return;
    }

    let epoch_length: BlockHeightDelta = 10;
    let base_boundary_accounts = create_account_ids(["user2", "user3"]).to_vec();
    let base_shard_layout = ShardLayout::multi_shard_custom(base_boundary_accounts, 3);
    let deploy_user: AccountId = create_account_id("user0");
    let users = create_account_ids(["user0", "user1", "user2", "user3", "user4", "user5"]).to_vec();
    let validators_spec = create_validators_spec(1, 0);
    let clients = validators_spec_clients(&validators_spec);
    let chunk_producer = clients[0].clone();
    let gas_limit = Gas::from_teragas(300);
    let base_pv = PROTOCOL_VERSION - 1;

    // Configure dynamic resharding to force-split two shards sequentially.
    // The first split targets the shard containing deploy_user (user0), so the
    // GlobalContractDistribution receipt becomes stale after two layout transitions.
    let first_split_shard = base_shard_layout.account_id_to_shard_id(&deploy_user);
    let second_split_shard = base_shard_layout.account_id_to_shard_id(&create_account_id("user4"));
    assert_ne!(first_split_shard, second_split_shard);

    let dynamic_config = DynamicReshardingConfig {
        memory_usage_threshold: u64::MAX,
        min_child_memory_usage: u64::MAX,
        max_number_of_shards: 100,
        min_epochs_between_resharding: 1.try_into().unwrap(),
        force_split_shards: vec![first_split_shard, second_split_shard],
        block_split_shards: vec![],
    };

    let genesis = TestLoopBuilder::new_genesis_builder()
        .protocol_version(base_pv)
        .validators_spec(validators_spec)
        .shard_layout(base_shard_layout.clone())
        .epoch_length(epoch_length)
        .gas_limit(gas_limit)
        .add_user_accounts_simple(&users, Balance::from_near(1_000_000))
        .build();
    let base_epoch_config = TestEpochConfigBuilder::from_genesis(&genesis).build();

    let mut dynamic_epoch_config = base_epoch_config.clone();
    dynamic_epoch_config.shard_layout_config =
        ShardLayoutConfig::Dynamic { dynamic_resharding_config: dynamic_config };

    let epoch_config_store = EpochConfigStore::test(BTreeMap::from([
        (base_pv, Arc::new(base_epoch_config)),
        (base_pv + 1, Arc::new(dynamic_epoch_config)),
    ]));

    let mut env = TestLoopBuilder::new()
        .genesis(genesis)
        .clients(clients)
        .epoch_config_store(epoch_config_store)
        .gc_num_epochs_to_keep(5)
        .build();

    // Step 1: Deploy the test contract on user0's account so we can call burn_gas_raw.
    {
        let node = env.node_for_account(&chunk_producer);
        let tx = node.tx_deploy_test_contract(&deploy_user);
        node.submit_tx(tx);
    }
    env.runner_for_account(&chunk_producer).run_for_number_of_blocks(2);

    // Step 2: Deploy a global contract from user0. This creates a
    // GlobalContractDistribution receipt with target_shard = user0's shard (S_A),
    // which is the shard that will be split in the first resharding.
    {
        let node = env.node_for_account(&chunk_producer);
        let code = ContractCode::new(near_test_contracts::rs_contract().to_vec(), None);
        let tx = node.tx_deploy_global_contract(
            &deploy_user,
            code.code().to_vec(),
            GlobalContractDeployMode::CodeHash,
        );
        node.submit_tx(tx);
    }

    // Step 3: Saturate compute on user0's shard every block so that the
    // GlobalContractDistribution receipt (arriving as incoming) gets pushed to
    // the delayed queue and stays there through both resharding events.
    //
    // Each burn_gas_raw call burns slightly more than half the gas limit, so
    // two local receipts exhaust the chunk's compute budget. We submit 3 per
    // block to ensure at least 2 are processed as local receipts.
    let gas_to_burn = gas_limit.checked_div(2).unwrap().checked_add(Gas::from_gas(1)).unwrap();
    let initial_num_shards = base_shard_layout.num_shards();
    let target_num_shards = initial_num_shards + 2; // after two splits

    let start_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };

    // Keep saturating until both resharding events complete. Dynamic resharding has a
    // 2-epoch proposal-to-activation pipeline, so we need enough epochs for both splits.
    let max_saturation_height = start_height + epoch_length * 12;
    let mut both_splits_done = false;
    for target_height in (start_height + 1)..=max_saturation_height {
        // Submit 3 heavy transactions to saturate this block's compute budget.
        {
            let node = env.node_for_account(&chunk_producer);
            for _ in 0..3 {
                let tx = node.tx_call(
                    &deploy_user,
                    &deploy_user,
                    "burn_gas_raw",
                    gas_to_burn.as_gas().to_le_bytes().to_vec(),
                    Balance::ZERO,
                    gas_limit,
                );
                node.submit_tx(tx);
            }
        }
        env.runner_for_account(&chunk_producer).run_until_head_height(target_height);

        // Check if both resharding events have completed.
        let node = env.node_for_account(&chunk_producer);
        let epoch_id = node.client().chain.chain_store().head().unwrap().epoch_id;
        let current_layout = node.client().epoch_manager.get_shard_layout(&epoch_id).unwrap();
        if current_layout.num_shards() >= target_num_shards {
            both_splits_done = true;
            break;
        }
    }
    assert!(both_splits_done, "both shard splits did not complete within the allotted blocks");

    // Step 4: Stop saturating. Let the delayed queue drain.
    // If the vulnerability exists, processing the stale GlobalContractDistribution
    // receipt will panic in receipt_filter_fn() when receiver_shard_id() fails
    // to remap the old target_shard after two resharding generations.
    let current_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };
    let drain_end = current_height + epoch_length * 2;
    env.runner_for_account(&chunk_producer).run_until_head_height(drain_end);

    let head_height = {
        let node = env.node_for_account(&chunk_producer);
        node.client().chain.chain_store().head().unwrap().height
    };
    assert!(
        head_height >= drain_end,
        "chain stalled at height {}; expected >= {} (likely panicked processing stale receipt)",
        head_height,
        drain_end
    );
}
```
