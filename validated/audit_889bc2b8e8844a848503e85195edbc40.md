### Title
Deposit auto-swap and gas-refund swap use manipulable spot-price quotes with only a hardcoded 5% tolerance, no user-controlled slippage bound - ([File: x/uexecutor/keeper/evm.go], [File: x/uexecutor/keeper/execute_inbound_gas.go], [File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go], [File: x/uexecutor/keeper/outbound.go])

### Summary
The Hifi report's core defect — liquidity/swap operations that lack sufficient slippage protection because the affected party cannot bound the acceptable price impact — has a direct analog in Push Chain's gas-abstraction auto-swap flow. `GetSwapQuote` fetches a single-block spot quote from a Uniswap V3 `QuoterV2` contract, and the protocol unilaterally applies a fixed 5% tolerance (`minPCOut = quote * 95 / 100`) with no way for the depositing user (or the gas-refund recipient) to specify their own maximum slippage.

### Finding Description
`k.GetSwapQuote` at [1](#0-0)  calls `QuoterV2.quoteExactInputSingle` to obtain the current spot-price-derived output amount for a `prc20 → wpc` swap. This is an instantaneous AMM price read, not a TWAP or otherwise manipulation-resistant oracle. Every caller of this quote hardcodes the same fixed 5% band:

- `ExecuteInboundGas` (GAS route): [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD route): [3](#0-2) 
- `applyGasRefund` (outbound excess-gas refund swap): [4](#0-3) 

In all three, `minPCOut` is computed by the protocol itself from a freshly-fetched spot quote and passed to `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, which execute the actual on-chain swap via `DerivedEVMCall` at [5](#0-4)  and [6](#0-5) . The depositing user (who only submits a transaction on the *source* chain and has no influence over the Push-chain-side transaction ordering) has zero visibility or control over this bound — it is a fixed, protocol-wide 5%, derived from a price that any unprivileged actor can move by trading against the same Uniswap V3 pool referenced by `quoterAddr`/`fee` immediately before the vote-finalization transaction that triggers the swap lands.

This mirrors exactly the Hifi defect class: the party whose funds are at risk (LPs in Hifi; bridging users / refund recipients in Push Chain) cannot express their own acceptable price bound, and the fallback protection (front-end checks in Hifi; a fixed on-chain percentage in Push Chain) is insufficient against an attacker who can manipulate the reference price used to compute the bound itself.

### Impact Explanation
An unprivileged attacker who holds (or flash-borrows) the pooled assets can move the spot price of the `prc20`/`WPC` Uniswap V3 pool just before a `MsgVoteInbound` (or the outbound-vote-triggered refund) finalizes and consumes the `GetSwapQuote` result, then reverse the trade afterward. Because `minPCOut` is derived from that manipulated quote (not a manipulation-resistant TWAP) and the tolerance is a fixed 5%, the attacker can systematically extract up to ~5% of the value of every gas-abstraction deposit or refund swap that is auto-executed by the `uexecutor` module, directly corrupting the PC amount credited to bridging users' UEAs and the gas-fee refund amounts sent to legitimate senders — a direct loss of protocol/user-controlled funds reachable purely through ordinary deposit and swap transactions.

### Likelihood Explanation
Medium-to-high: this requires no privileged access, no relayer/validator compromise, and no cross-chain trust assumption — only the ability to submit ordinary swap transactions against the same on-chain AMM pool that Push Chain queries for pricing, timed around the (predictable, non-adversarial) processing of a pending inbound/outbound vote finalization. The attack is bounded per-transaction by the fixed 5% ceiling, so it is a repeatable value-extraction pattern rather than a one-shot drain, but is inherent in every GAS/GAS_AND_PAYLOAD inbound and every outbound gas refund.

### Recommendation
Do not derive `minPCOut` solely from an instantaneous `QuoterV2` spot call. Use a manipulation-resistant reference (e.g., TWAP over a meaningful window, or a governance/oracle-set reference price) to bound acceptable slippage, and/or make the tolerance itself configurable per token/route rather than a single hardcoded 5% constant shared by `execute_inbound_gas.go`, `execute_inbound_gas_and_payload.go`, and `outbound.go`.

### Proof of Concept
1. Attacker identifies the `prc20`/`WPC` Uniswap V3 pool referenced via `GetUniversalCoreQuoterAddress`/`GetDefaultFeeTierForToken` for a given bridged asset.
2. Attacker submits a large swap on that pool to push the spot price so that `quoteExactInputSingle` (called from `GetSwapQuote`, [7](#0-6) ) returns an artificially low `amountOut`.
3. A pending `Inbound` gas deposit is processed in the same window; `minPCOut = quote*95/100` is computed off the manipulated quote ( [8](#0-7) ) and `CallPRC20DepositAutoSwap` executes the swap, crediting the victim's UEA with fewer PC tokens than fair value.
4. Attacker reverses the initial trade, capturing the difference; repeat for each observed pending inbound/outbound refund.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
