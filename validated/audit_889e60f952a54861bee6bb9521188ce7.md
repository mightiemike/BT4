### Title
Unbounded free account creation via gasless-tx AccountInitDecorator enables state-storage exhaustion - (File: app/ante/account_init_decorator.go)

### Summary
The NEAR report describes a case where a state mutation (adding an owner to `tokens_per_owner`) creates permanent on-chain storage without the responsible party being charged for that storage cost, letting an attacker grow state for free. The Push Chain analog is `AccountInitDecorator`, which creates and persists a brand-new Cosmos `BaseAccount` for *any* signer of a gasless-whitelisted message, with **zero fee, zero bond requirement, and no check that the underlying message will even succeed**. An unprivileged attacker with unlimited fresh keypairs can force unbounded, permanently-committed account creation at no cost.

### Finding Description
`app/ante/ante_cosmos.go` wires `NewAccountInitDecorator` into the ante chain before `SetPubKeyDecorator`/signature verification/sequence increment: [1](#0-0) 

`AccountInitDecorator.AnteHandle` only requires the tx to be a `IsGaslessTx` (whitelist includes `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgExecutePayload`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration` — see `app/txpolicy/gasless.go`): [2](#0-1) 

If the single signer has no on-chain account, the decorator verifies a signature against a hardcoded `account_number=0, sequence=0`, then unconditionally creates and persists the account, short-circuiting the rest of the ante chain (`return ctx, nil` instead of `next(...)`): [3](#0-2) 

Crucially, this authorization check is purely cryptographic (does the attacker control the private key for a self-chosen new address) — it does **not** check whether the signer is actually a bonded Universal Validator. That check (`IsBondedUniversalValidator`/`IsTombstonedUniversalValidator`) only happens later, inside the message handler in `x/uexecutor/keeper/msg_server.go`, well after account creation has already been committed to state as part of the ante-handler's cache-context write, which is applied independently of whether the subsequent `runMsgs` phase succeeds or fails.

Since an attacker can generate an arbitrary number of fresh Ed25519/secp256k1 keypairs, sign a trivially cheap gasless message (e.g. `MsgVoteInbound` or `MsgVoteOutbound` with bogus content) for each one, and submit it, each such transaction:
1. Costs nothing (`DeductFeeDecorator` skips fee deduction for gasless txs, `MinGasPriceDecorator` skips the min-fee check).
2. Requires no stake, bond, or validator status.
3. Permanently creates one new `BaseAccount` entry in the auth module's state store, even though the wrapped message will fail downstream (not a bonded UV) and gets reverted separately from the ante-handler's committed state.

This mirrors the NEAR bug precisely: a storage-growing operation (`tokens_per_owner` insert / here, `SetAccount`) is performed with no fee attribution to the party causing the growth, enabling unbounded state bloat at zero cost to the attacker.

### Impact Explanation
This falls under the allowed "denial of service ... not network-level and reachable without privileged control" impact. An attacker can flood the chain with cheap, fee-free transactions that each permanently grow the auth store by one account record, with no bond or balance requirement. At scale this inflates the IAVL/state-store size indefinitely, increasing disk usage, sync time, and snapshot size for every full node and validator — a state-bloat DoS vector distinct from ordinary mempool spam, since normal transactions require paying gas/fees that make spam economically self-limiting; this path removes that limiter entirely for account creation.

### Likelihood Explanation
High. No special access is required — only the ability to submit ordinary transactions to the gasless-whitelisted message types with self-generated keys, which is exactly the intended entry point for gasless UV/UEA transactions. The only throttle is per-block gas/tx-size limits enforced by `ConsumeGasForTxSizeDecorator`/mempool, but that limits per-block throughput, not the cumulative cost to the attacker (which remains zero).

### Recommendation
Require the `AccountInitDecorator` to validate that the new account is *authorized* to exist for free (e.g., is a currently bonded Universal Validator hot key, or the sender of a message that itself proves value/stake) before creating and persisting the account, or impose a minimal bonded/collateral requirement / rate limit on new-account creation via this path — analogous to requiring NFT minters to sponsor storage costs in the NEAR fix. Alternatively, defer account persistence until the wrapped message itself is confirmed to be authorized (e.g., validate `IsBondedUniversalValidator` for the relevant vote messages inside the decorator before calling `SetAccount`).

### Proof of Concept
1. Generate N distinct keypairs, none registered as bonded UVs and none funded.
2. For each keypair, build a `MsgVoteInbound` (or any gasless-whitelisted message) transaction signed with `account_number=0, sequence=0`.
3. Submit each tx to the mempool; each passes `AccountInitDecorator` (valid self-signature, gasless whitelist match), creating and committing a new `BaseAccount` in the auth store — before `msg_server.go`'s `IsBondedUniversalValidator` check ever runs and rejects the wrapped vote.
4. Repeat indefinitely; auth-store size grows linearly with attacker-submitted (free) transactions, with no fee, bond, or balance ever charged. [4](#0-3)

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
