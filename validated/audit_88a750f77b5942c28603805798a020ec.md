### Title
Process-crashing `panic()` on malformed lazy extension-field bytes during deferred decode - ([File: internal/impl/codec_extension.go])

### Summary
`protobuf-go` defers ("lazily") decoding of extension field values until they are actually accessed. The eager wire-format validation that the rest of the library performs (returning `errUnknown`/`errDecode` on invalid varints, tags, or field values) is skipped for lazy extensions at unmarshal time. Instead, the raw bytes are copied verbatim and validated only later, inside `lazyInit()`. If those deferred bytes are malformed, `lazyInit()` calls Go's `panic()` (the Go analog of libpcap's `abort()`) instead of returning an error, which crashes the process unless the caller happens to run in a goroutine protected by `recover()`.

### Finding Description
When `proto.Unmarshal` (binary wire format) processes a message containing an extension field, the eager decode path in `internal/impl/decode.go` hands the field bytes to `MessageInfo.unmarshalExtension`, which — when the extension can be lazily stored — copies the raw, **unvalidated** tag+bytes into `ExtensionField.lazy.b` via `appendLazyBytes` [1](#0-0) . No tag/wiretype/varint validation happens at this point; validation is postponed.

The deferred, real decode happens later, in `ExtensionField.lazyInit()`, triggered the first time the field's value is read (e.g. via `proto.GetExtension`, which calls `ExtensionField.Value()`) [2](#0-1) . Inside `lazyInit()`, the buffered bytes are re-parsed manually: [3](#0-2) 

Two invariant-violation checks in this loop use `panic()` instead of returning an error to the caller:
- `panic(errors.New("bad tag in lazy extension decoding"))` when the varint tag fails to parse.
- `panic(errors.New("decode failure in lazy extension decoding: %v", err))` when the field's `unmarshal` function reports an error (e.g., wrong wire type, truncated length-prefixed value, invalid UTF-8, malformed submessage, etc.).

This is the exact analog of the libpcap bug: a parser that encounters a structurally-invalid unit of input (there: BPF opcode; here: a tag/value in an extension's deferred byte buffer) calls an unrecoverable abort primitive rather than surfacing a normal error, even though the equivalent eager decode paths elsewhere in the codebase (`internal/impl/decode.go`, `internal/impl/lazy.go`, `proto/decode.go`) consistently return `errDecode`/`errUnknown` for the same classes of malformed input [4](#0-3) .

### Impact Explanation
Any process that unmarshals a `proto.Message` containing extension fields from untrusted/attacker-controlled binary wire data, and later reads an extension value (a completely ordinary, expected usage pattern via `proto.GetExtension`), can be crashed by a single malformed message. This is a process-wide denial of service: `panic()` in Go, unless caught by an explicit `recover()` at the call site (which application code parsing protobufs generally does not install around every `GetExtension` call), terminates the entire process/goroutine tree unwound to `main`, taking down all in-flight requests — matching the CVSS `A:H` characteristic of the reported analog.

### Likelihood Explanation
The trigger requires only: (1) a message type with at least one extension field, (2) the sending of a wire-format message where that extension's byte range is malformed (bad tag varint, wrong wire type for the extension's kind, truncated length-prefix, etc.), and (3) the receiver reading that extension's value at any later point via reflection/`proto.GetExtension`. Extensions are a standard, first-class, documented protobuf feature and lazy decoding of extensions is a default optimization (subject to `LazyEnabled()`/depends on build defaults), not an opt-in advanced feature requiring a custom resolver or attacker-controlled descriptor. No privileged caller or malicious peer/node capability beyond "attacker controls the wire bytes fed to `Unmarshal`" is required.

### Recommendation
In `internal/impl/codec_extension.go`, `lazyInit()` should propagate decode failures as errors instead of `panic()`. Since `ExtensionField.Value()` has no error return today, this requires either: (a) storing the decode error on `lazyExtensionValue` and having `Value()`/callers check for and surface it (with a safe fallback value), or (b) validating extension bytes eagerly (as `skipField`/`ValidationStatus` does for lazy message fields in `internal/impl/lazy.go`) before allowing them to be stored lazily, falling back to eager unmarshal (and a normal `Unmarshal` error) when validation fails.

func (f *ExtensionField) appendLazyBytes(xt protoreflect.ExtensionType, xi *extensionFieldInfo, num protowire.Number, wtyp protowire.Type, b []byte) {
	if f.lazy == nil {
		f.lazy = &lazyExtensionValue{xi: xi}
	}
	f.typ = xt
	f.lazy.xi = xi
	f.lazy.b = protowire.AppendTag(f.lazy.b, num, wtyp)
	f.lazy.b = append(f.lazy.b, b...)
}

func (f *ExtensionField) lazyInit() {
	f.lazy.mu.Lock()
	defer f.lazy.mu.Unlock()
	if atomic.LoadUint32(&f.lazy.atomicOnce) == 1 {
		return
	}
	if f.lazy.xi != nil {
		b := f.lazy.b
		val := f.typ.New()
		for len(b) > 0 {
			var tag uint64
			if b[0] < 0x80 {
				tag = uint64(b[0])
				b = b[1:]
			} else if len(b) >= 2 && b[1] < 128 {
				tag = uint64(b[0]&0x7f) + uint64(b[1])<<7
				b = b[2:]
			} else {
				var n int
				tag, n = protowire.ConsumeVarint(b)
				if n < 0 {
					panic(errors.New("bad tag in lazy extension decoding"))
				}
				b = b[n:]
			}
			num := protowire.Number(tag >> 3)
			wtyp := protowire.Type(tag & 7)
			var out unmarshalOutput
			var err error
			val, out, err = f.lazy.xi.funcs.unmarshal(b, val, num, wtyp, lazyUnmarshalOptions)
			if err != nil {
				panic(errors.New("decode failure in lazy extension decoding: %v", err))
			}
			b = b[out.n:]
		}
		f.lazy.value = val
	} else {
		panic("No support for lazy fns for ExtensionField")
	}
	f.lazy.xi = nil
	f.lazy.b = nil
	atomic.StoreUint32(&f.lazy.atomicOnce, 1)
}
