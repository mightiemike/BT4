### Title
Committee-controlled `MARKET_CANCEL_FEE` can permanently trap user funds in the TRC10 Market by pricing cancellation out of reach - ([File: actuator/src/main/java/org/tron/core/actuator/MarketCancelOrderActuator.java])

### Summary
The on-chain TRC10 order-book market (`MarketSellAssetActuator` / `MarketCancelOrderActuator`) lets any unprivileged account lock TRC10 (or TRX) balance into a resting order that is only released when the order is matched or explicitly cancelled. Cancellation requires paying a flat `MARKET_CANCEL_FEE`, a parameter that the committee (super-representative governance, analogous to Aloe's "governor") can set anywhere in `[0, 10_000_000_000]` sun (up to 10,000 TRX) via a proposal. If the fee is raised above what an order owner currently holds in TRX, `MarketCancelOrderActuator.validate()` unconditionally rejects the cancel transaction, leaving the tokens locked in the order with no other exit path for an illiquid/unmatched pair.

### Finding Description
`MarketCancelOrderActuator.calcFee()` returns `dynamicStore.getMarketCancelFee()` [1](#0-0)  and `validate()` hard-fails the cancellation if the owner's TRX balance is below that fee:

```
long fee = calcFee();
if (ownerAccount.getBalance() < fee) {
  throw new ContractValidateException("No enough balance !");
}
``` [2](#0-1) 

There is no alternate, fee-free withdrawal path for the sell-side tokens locked in `MarketOrderCapsule`/`MarketAccountStore` other than this cancel actuator or a matching counter-order (which may never arrive for an illiquid pair). `MARKET_CANCEL_FEE` is set purely by committee proposal via `ProposalService.process` (`case MARKET_CANCEL_FEE: manager.getDynamicPropertiesStore().saveMarketCancelFee(entry.getValue())`) with the only bound being the range check in `ProposalUtil.validator`:

```
case MARKET_CANCEL_FEE: {
  ...
  if (value < 0 || value > 10_000_000_000L) {
    throw new ContractValidateException(
        "Bad MARKET_CANCEL_FEE parameter value, valid range is [0,10_000_000_000L]");
  }
  break;
}
``` [3](#0-2) 

This is structurally identical to the Aloe bug: a governance/committee-controlled economic parameter (interest rate in Aloe, cancel fee in java-tron) is not bounded relative to the actual funds it gates, so the "restricted" governing party can, without ever touching user funds directly, make it economically or literally impossible for ordinary users to reclaim assets they have committed to the protocol. Order placement (`MarketSellAssetActuator`) does not require the owner to reserve the future cancel fee, so a user with just enough TRX to place an order can later be priced out of cancelling it if the committee raises the fee afterward.

### Impact Explanation
Any TRC10 token balance (or TRX) placed into a resting market order becomes unrecoverable for accounts whose TRX balance is below the current `MARKET_CANCEL_FEE`, since `MarketCancelOrderActuator` is the only actuator that returns locked order funds outside of a match. Because the fee can be pushed up to 10,000 TRX by committee proposal at any time — independent of the order owner's balance at the time of order placement — this can strand funds indefinitely for affected accounts, matching the "prevent withdrawals" impact class from the Aloe report.

### Likelihood Explanation
This requires the committee/governance process to pass a `MARKET_CANCEL_FEE` proposal (subject to normal on-chain super-representative approval, comparable to Aloe's governor whose actions are timelocked but not otherwise restricted from harmful parameter choices). Given the parameter is explicitly designed to be adjustable within a wide range and no minimum-balance reservation exists at order-placement time, an adversarial or careless governance change is sufficient to trigger the impact without any additional preconditions.

### Recommendation
Bound `MARKET_CANCEL_FEE` (and similar fee/parameter changes) so it cannot exceed funds needed for users to exit positions they already committed to, e.g., by charging the fee from the returned proceeds/locked balance of the specific order being cancelled rather than requiring a separate available TRX balance, or by grandfathering existing orders against the fee in effect at creation time.
