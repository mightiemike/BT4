### Title
Reference (`==`) comparison instead of `ByteString.equals` in `useAssetAccountNet` breaks TRC10 issuer self-exemption path - (File: `chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java`)

### Summary
`BandwidthProcessor.useAssetAccountNet` checks whether the caller is the asset issuer using `assetIssueCapsule.getOwnerAddress() == accountCapsule.getAddress()`, a Java object-identity comparison rather than a content comparison. Because these `ByteString` values are decoded from two independently loaded protobuf messages (`AssetIssueContract`/`AssetIssueContractV2` and `Account`), they are never the same object instance even when they hold identical address bytes, so the intended "owner-exempt" branch is unreachable and every TRC10 transfer — including issuer self-transfers — falls through to the shared public/free-asset-net accounting path.

### Finding Description
In `useAssetAccountNet` (chainbase/src/main/java/org/tron/core/db/BandwidthProcessor.java:290-430), when a `TransferAssetContract` is processed, the code retrieves the `AssetIssueCapsule` for the asset and attempts to detect whether the transaction's owner account is the asset's issuer: [1](#0-0) 

`assetIssueCapsule.getOwnerAddress()` returns the `ByteString` stored in the deserialized `AssetIssueContract`/`AssetIssueContractV2` protobuf object (loaded from `AssetIssueStore`/`AssetIssueV2Store`), while `accountCapsule.getAddress()` returns the `ByteString` stored in the deserialized `Account` protobuf object (loaded from `AccountStore`). These are two entirely separate protobuf message instances constructed from different store lookups, each holding an independently allocated `ByteString` object; `==` compares object references, not byte content. Consequently, this condition can never evaluate to `true` in a real code path, even when the issuer transfers their own token to themselves, because `getOwnerAddress()` and `getAddress()` will never return the identical `ByteString` instance.

As a result, the intended fast/exempt path (`useAccountNet(accountCapsule, bytes, now)` at line 314) is dead code for real transactions, and issuer self-transfers instead fall through to the shared accounting logic starting at line 317, which consumes `publicFreeAssetNetLimit` and `freeAssetNetLimit` — resources intended for third-party asset holders — and also debits net usage from the (in this case identical) issuer account via `issuerAccountCapsule` bandwidth accounting at lines 355-386.

No existing check in `TransactionCapsule.validateSignature`, actuator `validate()`, or `ForkController` mitigates this, since it is purely an internal bandwidth-accounting logic defect, not an authorization bypass.

### Impact Explanation
This is an accounting/resource-allocation defect rather than a fund-theft or authorization bypass: it causes the shared `publicFreeAssetNetLimit`/`freeAssetNetLimit` bandwidth pools — meant for third-party TRC10 holders transacting the asset — to be depleted faster by issuer self-transfers than intended, and issuer transfers of their own asset are billed through the general bandwidth/fee mechanisms instead of being exempted. This falls into the "asset/accounting corruption" impact class: it degrades the intended resource allocation model for TRC10 assets but does not directly create, destroy, or steal value, and does not corrupt consensus state (all nodes compute the same, deterministically wrong, result, so no fork/divergence occurs).

### Likelihood Explanation
The precondition is trivial and requires no privilege: any account that issues a TRC10 token and subsequently broadcasts a `TransferAssetContract` for that same token (to itself or elsewhere) will hit this code path on every single transfer, on every node, deterministically. This is not a one-off edge case — it is the default behavior of the code today, 100% reproducible with a standard issue + transfer transaction sequence.

### Recommendation
Replace the identity comparison with a content-based comparison, e.g. `assetIssueCapsule.getOwnerAddress().equals(accountCapsule.getAddress())`, matching the pattern used elsewhere in the codebase (e.g., actuators compare owner addresses via `.equals()`/`Arrays.equals(byte[])`). Ensure a regression test exercises an issuer self-transfer to confirm the `useAccountNet` branch is taken.
