**Analysis:**

The recursion depth of `sig_to_ty` in `third_party/move/move-binary-format/src/constant.rs` is bounded by the depth of the `SignatureToken::Vector` nesting in `Constant::type_`, and this depth is enforced independently by `LimitsVerifier::verify_type_node` in `third_party/move/move-bytecode-verifier/src/limits.rs`, which walks every constant's `type_` via `preorder_traversal_with_depth()` and rejects it with `StatusCode::TOO_MANY_TYPE_NODES` if `depth > config.max_type_depth` or if the weighted `type_size` exceeds `config.max_type_nodes`. [1](#0-0) [2](#0-1) 

This limits check runs as part of module verification during publishing/loading, strictly before any constant is deserialized in `constants.rs::verify_constant_data` (which calls `Constant::deserialize_constant`) and before the module can be used in transaction execution. [3](#0-2) 

Because `max_type_depth`/`max_type_nodes` are enforced deterministically and independently of "input shape" tricks (the traversal itself is what's bounded, not just raw serialized size), an attacker cannot craft a constant pool whose nested-vector `SignatureToken` shape passes verification yet causes unbounded or highly divergent recursive cost in `sig_to_ty`. Any module exceeding these limits is rejected atomically at verification time with `VMResult::Err`, before any VM session or write-set state exists for that transaction — there is no partially-mutated in-memory session to hand off to the executor. `Constant::deserialize_constant`/`serialize_constant` are also pure, non-mutating functions with no side effects on shared VM/session state. [4](#0-3) 

Since the depth/size limits are enforced deterministically by the protocol-configured `VerifierConfig` (same for all validators) prior to any state mutation, there is no path by which unprivileged input causes resource usage disproportionate to a bounded, verifier-enforced structure, nor any path to a partially-committed or inconsistent write set reaching the executor. This does not meet the state-integrity/proof-corruption bar required by the review scope.

        Ok(())
