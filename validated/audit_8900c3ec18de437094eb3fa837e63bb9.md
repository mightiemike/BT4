## Title
Signer global-state agreement/disagreement thresholds use floor division while the canonical on-chain block-approval threshold uses ceiling division, letting a sub-70%/over-30% minority flip the signer network's off-chain consensus view - ([File: libsigner/src/v0/signer_state.rs])

### Summary
The Nakamoto protocol defines a single canonical "70% of signer weight" supermajority constant, `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7`. The on-chain/consensus-critical computation of this threshold, `NakamotoBlockHeader::compute_voting_weight_threshold`, correctly rounds *up* (ceiling) so that the required weight is always `>= 70%` of total weight. [1](#0-0) 

However, the signer-side `GlobalStateEvaluator::reached_agreement` / `reached_disagreement`, which every signer uses to decide the off-chain "global state" (current miner, burn view, protocol version, tx-replay set), instead uses plain floor division of the *same* constant, with no rounding-up: [2](#0-1) 

### Finding Description
Both formulas are meant to express the identical rule "vote_weight must be at least 70% of total_weight" (and, for disagreement, "more than 30%"), but they compute it differently:

- Canonical (chain-validated) threshold: `ceil(total_weight * 7 / 10)`.
- Signer off-chain threshold: `floor(total_weight * 7 / 10)`.

For any `total_weight` where `total_weight * 7` is not a multiple of 10, the floor-based formula in `reached_agreement` accepts strictly less absolute weight than the ceiling-based formula requires for an actually valid, chain-verifiable block (`verify_signer_signatures` calls `compute_voting_weight_threshold` and rejects if `total_weight_signed < threshold`). [3](#0-2) 

Because `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` gate purely off-chain signer coordination decisions — determining the agreed current miner/tenure, agreed burn view, agreed protocol version, and the agreed tx-replay set — a coalition whose combined weight sits in the gap between the floor-threshold and the true ceiling-threshold can force the signer network to "reach agreement" on a state view (e.g. a specific miner/tenure, a stale/forked burn view, or a truncated tx-replay set) that does **not** actually satisfy the real 70% supermajority rule used to validate blocks on-chain. This same threshold is also used to decide when to mark a miner as invalid due to reorg-rejection (`reached_disagreement` on `ReorgNotAllowed` weight) in `stacks-signer/src/v0/signer.rs`, meaning the discrepancy directly affects miner-invalidation and pre-commit/rejection consensus in the signer set. [4](#0-3) [5](#0-4) 

This is the same bug class as the reported `decimalOffset` issue: a protective threshold/scaling calculation that is supposed to guarantee a fixed percentage guarantee but is implemented inconsistently/imprecisely across two code paths, silently weakening the guarantee for certain (attacker-selectable) input values — here, `total_weight` values chosen so `total_weight * 7 mod 10 != 0`.

### Impact Explanation
This is a minority-triggerable divergence in signer weight thresholding: for specific weight totals, less than the canonical 70% weight is sufficient to make the off-chain `GlobalStateEvaluator` "agree" on a global state (miner/tenure/burn view/replay set) that would not clear the true, chain-enforced threshold. This can cause signers to diverge from what the actual chain-verifiable consensus requires, producing tip disagreement / incorrect miner invalidation decisions bounded to the off-chain signer coordination layer (not a direct chain split of on-chain consensus, since block acceptance itself still goes through `compute_voting_weight_threshold`). This matches the "High: minority-triggerable... static-validation divergence... temporary tip disagreement" impact tier.

### Likelihood Explanation
The discrepancy triggers deterministically whenever `total_weight * 7 % 10 != 0` (true for the majority of possible weight totals, e.g. `total_weight = 511` differs by exactly 1 unit of weight, as shown by the existing test `test_compute_voting_weight_threshold`). No majority collusion is required — a minority holding weight equal to the floor value but below the true ceiling value can already satisfy `reached_agreement`. [6](#0-5) 

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use the same ceiling-rounded formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (or call that function directly) so both code paths enforce an identical, consistently-rounded 70% supermajority / 30% blocking-minority threshold.

### Proof of Concept
1. Set `total_weight = 511` for a `GlobalStateEvaluator`.
2. The canonical/chain threshold is `compute_voting_weight_threshold(511) == 358` (ceiling), per the existing test. [6](#0-5) 
3. `reached_agreement(357)` computes `357 >= (511*7)/10 = 357` → `true`, i.e., the signer set can be considered to have "reached agreement" with only 357/511 ≈ 69.86% weight, one unit of weight short of what `compute_voting_weight_threshold`/`verify_signer_signatures` would actually require for a block to be accepted. [7](#0-6) 
4. This "agreed" global state (miner view, burn view, or tx-replay set) is then propagated and acted on by signers via `determine_global_state`/`capitulate_viewpoint`, even though it doesn't meet the real on-chain approval bar. [8](#0-7)

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

                continue;
            };
            let (burn_block, burn_block_height) = update.content.burn_block_view();
            let current_miner = update.content.current_miner();
            let tx_replay_set = update.content.tx_replay_set();

            let state_machine = SignerStateMachine {
                burn_block: burn_block.clone(),
                burn_block_height,
                current_miner: current_miner.clone().into(),
                active_signer_protocol_version,
                // We need to calculate the threshold for the tx_replay_set separately
                tx_replay_set: ReplayTransactionSet::none(),
            };
            let key = SignerStateMachineKey(state_machine.clone());
            let entry = state_views.entry(key).or_insert_with(|| 0);
            *entry += weight;

                found_state_view = Some(state_machine);

                found_replay_set = Some(tx_replay_set);

                break;
            }

    /// Check if the supplied vote weight crosses the global agreement threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_agreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }

    /// Check if the supplied vote weight crosses the blocking minority threshold.
    /// Returns true if it has, false otherwise.
    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {
        u64::from(vote_weight)
            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)
                / 10
    }
