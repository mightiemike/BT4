### Title
Starknet OS `execute_replace_class` fails to verify the target class is declared before rewriting contract state, diverging from blockifier's checked implementation - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
This maps to the same bug class as the reported `UpdateManager` issue: an update/replace operation is performed against a target without first validating that the target is in a legitimate, usable state — here, the Starknet OS's Cairo implementation of the `replace_class` syscall updates a contract's `class_hash` in `contract_state_changes` without checking that the new class hash was actually declared, unlike the Rust blockifier which enforces this check before mutating state.

### Finding Description
In `blockifier`, the `replace_class` syscall handler explicitly requires the class to be declared before allowing the contract's class hash to change: [1](#0-0) 
This same check-then-set order is what blockifier relies on for the VM/Native syscall implementation as well, and is exercised by unit tests expecting `"is not declared"` errors for undeclared class hashes. [2](#0-1) 

However, the Starknet OS (Cairo re-execution program used to build the proof and re-derive the state root/commitment) implements `execute_replace_class` without this validation. The code contains an explicit TODO acknowledging the missing check, and proceeds directly to `dict_update` on `contract_state_changes` with the attacker-supplied `class_hash`: [3](#0-2) 
The deprecated syscall variant in the OS has the identical gap: [4](#0-3) 

This is precisely analogous to the reported bug class: the "update" path (here, `replace_class`, which updates which contract class governs an already-deployed contract) omits the exact reference/validity check that a parallel/authoritative implementation (blockifier) performs, resulting in the operation succeeding against an invalid target (an undeclared class) where it should be rejected.

### Impact Explanation
Since the Starknet OS is the trusted, canonical execution used to (re-)derive the state commitment and is meant to match blockifier's execution semantics exactly (any divergence between the two is a soundness/consistency bug for the proving system), an unprivileged L2 account can invoke `replace_class_syscall(undeclared_class_hash)`. If reached with an undeclared class hash, the OS would accept the state transition (writing the undeclared class hash into `contract_state_changes`) at a point where blockifier's sequencer-side execution would reject the transaction with `UndeclaredClassHash`. This produces a state-transition/output mismatch between the blockifier-computed block (source of truth for the sequencer/network) and what the OS accepts as valid during proof generation/re-execution — a form of honest-node/verifier divergence and wrong computed state commitment for that contract (its class hash entry would not correspond to a real, retrievable compiled class), which can subsequently cause execution failures for any call into that "replaced" contract (denial of service on that contract) or corruption of the on-chain state root as computed by the OS versus the sequencer.

### Likelihood Explanation
Reachability is straightforward and requires no privilege: any deployed contract that invokes `replace_class_syscall` (a standard, permissionless Starknet syscall available to any Cairo 1 contract) with an attacker-chosen, undeclared class hash reaches this code path. The comment `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` confirms this is a known, currently-unaddressed gap rather than a defense-in-depth omission, making it directly and reliably triggerable by any contract on the network that calls `replace_class_syscall`.

### Recommendation
Add a check in the Cairo OS's `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that verifies the given `class_hash` corresponds to a declared contract class (mirroring blockifier's `get_compiled_class`/`is_declared` check) before performing the `dict_update` that rewrites `contract_state_changes`. This should be done prior to constructing/committing the `new_state_entry`, ensuring the OS's acceptance criteria for `replace_class` exactly matches blockifier's, eliminating any possibility of divergence between sequencer execution and OS re-execution/proof generation for this syscall.

### Proof of Concept
1. Deploy a Cairo 1 contract exposing a function that calls `replace_class_syscall(class_hash)` with an attacker-controlled `class_hash` parameter (e.g., the `test_replace_class` pattern shown in test fixtures).
2. Invoke that function with a `class_hash` value that has never been declared on the network.
3. In blockifier (sequencer execution), the call fails with `UndeclaredClassHash`/"is not declared" as shown in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs` and `crates/blockifier/src/execution/deprecated_syscalls/deprecated_syscalls_test.rs`.
4. In the Starknet OS Cairo implementation (`execute_replace_class` in `syscall_impls.cairo` / `deprecated_execute_syscalls.cairo`), the same call path performs no declared-class check and would (if the hint/hypothesis path for this transaction were replayed with acceptance) update `contract_state_changes` with the undeclared class hash, demonstrating the missing validation relative to blockifier's enforced check.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
