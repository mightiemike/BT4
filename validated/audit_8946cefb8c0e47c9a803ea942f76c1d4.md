### Title
Validator Proposals from Failed Action Receipts Persist After State Rollback, Breaking the Staking Invariant at Epoch Boundary - (File: `runtime/runtime/src/lib.rs`)

### Summary

In `apply_action_receipt`, validator proposals accumulated during action execution are appended to the chunk-level `validator_proposals` vector **before** the receipt's success/failure is checked. When a receipt fails, the trie state is rolled back (undoing any locked-balance changes from a `Stake` action), but the validator proposal is already in the outer vector and is never removed. At epoch boundary, `update_validator_accounts` computes `max_of_stakes` from those proposals and enforces the invariant `account.locked() >= max_of_stakes`. Because the state was rolled back, `account.locked()` is lower than the proposal value, triggering a FATAL `StorageInconsistentState` error that causes the epoch-boundary block to be rejected by every honest node, halting the chain.

### Finding Description

`apply_action_receipt` in `runtime/runtime/src/lib.rs` executes each action in a receipt sequentially. If any action fails, the loop breaks and the trie state is rolled back. However, the validator proposals collected in `result.validator_proposals` are moved into the chunk-level vector at line 943, two lines **before** the commit/rollback branch at line 946:

```rust
// Moving validator proposals          ← line 942-943
validator_proposals.append(&mut result.validator_proposals);

// Committing or rolling back state.   ← line 945-955
match &result.result {
    Ok(_) => { state_update.commit(...); }
    Err(_) => { state_update.rollback(); }   // ← state reverted, but proposal already moved
};
``` [1](#0-0) 

`action_stake` in `runtime/runtime/src/actions.rs` always pushes a `ValidatorStake` proposal into `result.validator_proposals` when the stake action itself succeeds, regardless of what later actions in the same receipt do:

```rust
result.validator_proposals.push(ValidatorStake::new(
    account_id.clone(),
    stake.public_key.clone(),
    stake.stake,
));
if stake.stake > account.locked() {
    account.set_amount(new_balance);
    account.set_locked(stake.stake);
}
``` [2](#0-1) 

When the receipt fails and the trie is rolled back, `account.locked()` reverts to its pre-action value, but the proposal carrying the new (higher) stake value is already committed to the chunk's `validator_proposals`. At epoch boundary, `update_validator_accounts` enforces:

```rust
if account.locked() < *max_of_stakes {
    return Err(StorageError::StorageInconsistentState(format!(
        "FATAL: staking invariant does not hold. \
         Account stake {} is less than maximum of stakes {} in the past three epochs",
        account.locked(), max_of_stakes)).into());
}
``` [3](#0-2) 

Because `max_of_stakes` is derived from the spurious proposal and `account.locked()` was rolled back, the invariant is violated and the epoch-boundary block is rejected.

The `docs/RuntimeSpec/ApplyingChunk.md` confirms that duplicate proposals are deduplicated by keeping only the last one per account, but there is no filtering of proposals from failed receipts.



### Impact Explanation

An unprivileged user with any positive NEAR balance can craft a multi-action transaction:

1. `Stake(Y)` — succeeds, locks `Y` tokens, pushes proposal `(account_id, Y)` into `result.validator_proposals`, and modifies `account.locked` in the staging trie.
2. `DeleteKey(<nonexistent_key>)` — fails with `DeleteKeyDoesNotExist`.

The receipt fails; the trie rolls back `account.locked` to its original value. The proposal `(account_id, Y)` is already in the chunk's `validator_proposals`. At the next epoch boundary, `update_validator_accounts` sees `max_of_stakes = Y` but `account.locked() < Y`, returns a `StorageInconsistentState` FATAL error, and the epoch-boundary block is rejected by all honest nodes. No further blocks can be produced: **chain halt**.

The staking invariant documented in `docs/ChainSpec/EpochAndStaking/Staking.md` states that `locked` is always equal to the maximum of the last three stakes and the highest proposal in the current epoch. The spurious proposal breaks this invariant. [4](#0-3) 

### Likelihood Explanation

Any account holder can trigger this with a single transaction. No validator role, no privileged access, and no special contract is required. The only prerequisite is having enough NEAR to cover the stake amount and transaction fees. The attack is deterministic and reproducible.

### Recommendation

Move the `validator_proposals.append` call inside the success branch of the commit/rollback match, so proposals from failed receipts are discarded along with the rolled-back state:

```rust
match &result.result {
    Ok(_) => {
        validator_proposals.append(&mut result.validator_proposals);
        state_update.commit(StateChangeCause::ReceiptProcessing {
            receipt_hash: receipt.get_hash(),
        });
    }
    Err(_) => {
        // result.validator_proposals is dropped here; state is rolled back.
        state_update.rollback();
    }
};
``` [1](#0-0)

     max_of_stakes for alice = 50 NEAR  (from the spurious proposal)

10. The epoch-boundary block is rejected by all honest nodes → chain halt.

    fn update_validator_accounts(
        &self,
        state_update: &mut TrieUpdate,
        validator_accounts_update: &ValidatorAccountsUpdate,
    ) -> Result<(), RuntimeError> {
        for (account_id, max_of_stakes) in &validator_accounts_update.stake_info {
            if let Some(mut account) = get_account(state_update, account_id)? {
                if let Some(reward) = validator_accounts_update.validator_rewards.get(account_id) {
                    tracing::debug!(target: "runtime", %account_id, %reward, locked = %account.locked(), "account adding reward to stake");
                    account.set_locked(account.locked().checked_add(*reward).ok_or_else(|| {
                        RuntimeError::UnexpectedIntegerOverflow("update_validator_accounts".into())
                    })?);
                }

                tracing::debug!(target: "runtime",
                       %account_id, locked = %account.locked(), %max_of_stakes,
                       "account stake and max of stakes"
                );
                if account.locked() < *max_of_stakes {
                    return Err(StorageError::StorageInconsistentState(format!(
                        "FATAL: staking invariant does not hold. \
                         Account stake {} is less than maximum of stakes {} in the past three epochs",
                        account.locked(),
                        max_of_stakes)).into());
                }
                let last_proposal = *validator_accounts_update
                    .last_proposals
                    .get(account_id)
                    .unwrap_or(&Balance::ZERO);
                let return_stake = account
                    .locked()
                    .checked_sub(max(*max_of_stakes, last_proposal))
                    .ok_or_else(|| {
                        RuntimeError::UnexpectedIntegerOverflow(
                            "update_validator_accounts - return stake".into(),
                        )
                    })?;
                tracing::debug!(target: "runtime", %account_id, %return_stake, "account return stake");
                account.set_locked(account.locked().checked_sub(return_stake).ok_or_else(
                    || {
                        RuntimeError::UnexpectedIntegerOverflow(
                            "update_validator_accounts - set_locked".into(),
                        )
                    },
                )?);
                account.set_amount(account.amount().checked_add(return_stake).ok_or_else(
                    || {
                        RuntimeError::UnexpectedIntegerOverflow(
                            "update_validator_accounts - set_amount".into(),
                        )
                    },
                )?);

                set_account(state_update, account_id.clone(), &account);
            } else if *max_of_stakes > Balance::ZERO {
                // if max_of_stakes > 0, it means that the account must have locked balance
                // and therefore must exist
                return Err(StorageError::StorageInconsistentState(format!(
                    "Account {} with max of stakes {} is not found",
                    account_id, max_of_stakes
                ))
                .into());
            }
        }

```rust
pub(crate) fn action_stake(
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    stake: &StakeAction,
    last_block_hash: &CryptoHash,
    epoch_info_provider: &dyn EpochInfoProvider,
) -> Result<(), RuntimeError> {
    let increment = stake.stake.saturating_sub(account.locked());

    if let Some(new_balance) = account.amount().checked_sub(increment) {
        if account.locked().is_zero() && stake.stake.is_zero() {
            // if the account hasn't staked, it cannot unstake
            result.result =
                Err(ActionErrorKind::TriesToUnstake { account_id: account_id.clone() }.into());
            return Ok(());
        }

        if stake.stake > Balance::ZERO {
            let minimum_stake = epoch_info_provider.minimum_stake(last_block_hash)?;
            if stake.stake < minimum_stake {
                result.result = Err(ActionErrorKind::InsufficientStake {
                    account_id: account_id.clone(),
                    stake: stake.stake,
                    minimum_stake,
                }
                .into());
                return Ok(());
            }
        }

        result.validator_proposals.push(ValidatorStake::new(
            account_id.clone(),
            stake.public_key.clone(),
            stake.stake,
        ));
        if stake.stake > account.locked() {
            // We've checked above `account.amount >= increment`
            account.set_amount(new_balance);
            account.set_locked(stake.stake);
        }
    } else {
        result.result = Err(ActionErrorKind::TriesToStake {
            account_id: account_id.clone(),
            stake: stake.stake,
            locked: account.locked(),
            balance: account.amount(),
        }
        .into());
    }
    Ok(())
}
