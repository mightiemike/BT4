Based on my investigation, I found a genuine analog to the Astaria bug pattern in Push Chain's `applyGasRefund` function.

### Title
Gas refund and fund-revert to `address(0)` when `outbound.Sender` is unset and no `RevertInstructions.FundRecipient` is provided - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
The Astaria bug pattern is: when the entity that should receive a payment (the "liquidator") is unset, it defaults to `address(0)`, and the code sends funds there anyway without checking. The Push Chain analog exists in `applyGasRefund` and `handleFailedOutbound` in [1](#0-0) , where `refundRecipient`/`recipient` fall back to `outbound.Sender`, and if that is empty, `common.HexToAddress("")` silently resolves to `address(0)` with no guard before the on-chain refund/mint call is made.

### Finding Description
`applyGasRefund` computes the refund recipient as: [2](#0-1) 

and `handleFailedOutbound` computes the re-mint recipient the same way: [3](#0-2) 

In both cases, if `outbound.RevertInstructions` is nil (or `FundRecipient` is empty) **and** `outbound.Sender` is itself an empty string, `common.HexToAddress("")` evaluates to the zero address, and the code proceeds unconditionally to call `k.CallUniversalCoreRefundUnusedGas(...)` or `k.CallPRC20Deposit(...)` with that zero address — exactly mirroring the Astaria pattern where an unset `liquidator` defaults to `address(0)` and the fee is paid there with no check.

`outbound.Sender` is populated from `event.Sender`, decoded from the `UniversalTxOutbound` EVM log topic emitted by the `UniversalGatewayPC` contract when a user's payload calls `withdraw`/`withdrawAndExecute`: [4](#0-3)  and [5](#0-4) . This value is derived from an indexed EVM topic (`log.Topics[2]`) rather than validated user input, and none of `applyGasRefund`, `handleFailedOutbound`, or `BuildOutboundsFromReceipt` reject an all-zero/empty sender before it is persisted onto `outbound.Sender` and later used as the fallback refund/revert destination.

### Impact Explanation
If an outbound record ever ends up with both an empty `Sender` and no `RevertInstructions.FundRecipient`, the module will:
- mint back bridged PRC20 funds to `address(0)` in `handleFailedOutbound` (permanent loss of user funds), or
- send the excess gas-fee refund (`refundUnusedGas` call) to `address(0)` in `applyGasRefund` (permanent loss of gas refund).

Both are within the "permanent loss of user or protocol-controlled funds" impact category for this scope.

### Likelihood Explanation
I could **not conclusively verify** a concrete unprivileged path that produces `outbound.Sender == ""` for `FUNDS`/`GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` outbound types — in the code paths I inspected (`BuildOutboundsFromReceipt`), `event.Sender` is always decoded from an EVM topic via `common.HexToAddress(...).Hex()`, which never produces an empty string (it would produce `"0x0000...0000"` for a literal zero topic, not `""`). The `common.HexToAddress("")` collapse-to-zero-address risk is real and unguarded, but whether the zero-address topic value itself (rather than an empty string) can be attacker-supplied through the Solidity gateway's `withdraw`/`withdrawAndExecute` functions is outside what I could confirm from the Go-side code alone — that would require inspecting the Solidity contract source (not in the indexed scope) to see if `sender` in the emitted event is bound to `msg.sender`/`tx.origin` or is a caller-supplied parameter that could be set to `address(0)` deliberately.

Given this uncertainty about whether the zero/empty sender is actually reachable by an unprivileged external attacker under honest-validator conditions, and that no other guard rejects a zero address before the fund-moving calls, I present this as a plausible but **not fully confirmed** analog.

### Recommendation
Before calling `CallPRC20Deposit` (revert re-mint) or `CallUniversalCoreRefundUnusedGas` (gas refund) in [6](#0-5) , explicitly check that the resolved recipient address is not `common.Address{}` (the zero address) and abort/mark the outbound as `ABORTED` for manual intervention if so — mirroring the Astaria fix of validating the payout target is non-zero before transferring funds.

### Proof of Concept
Not constructed — reaching this state requires confirming (from the Solidity `UniversalGatewayPC` contract, not available in this index) whether the `sender` topic of the `UniversalTxOutbound` event can be forced to the zero address by an ordinary user-supplied payload, which I was unable to verify with the tools available. A Devin session with full repository/contract access would be needed to trace the Solidity emission path and build a concrete PoC.

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}

	outbound.OutboundStatus = types.Status_REVERTED
	k.Logger().Info("outbound reverted",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)

	// Refund excess gas regardless of tx type — gas was consumed on the external
	// chain whether the execution succeeded or failed.
	k.applyGasRefund(ctx, &outbound, obs)

	return k.UpdateOutbound(ctx, utxId, outbound)
}

// handleSuccessfulOutbound refunds unused gas fee when gasFee > gasFeeUsed.
func (k Keeper) handleSuccessfulOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	k.Logger().Info("outbound completed successfully",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)
	k.applyGasRefund(ctx, &outbound, obs)
	return k.UpdateOutbound(ctx, utxId, outbound)
}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
