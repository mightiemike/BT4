### Title
Gateway's `accept_new_txs` pause flag is not enforced on the P2P transaction-ingestion path - ([File: crates/apollo_gateway/src/gateway.rs])

### Summary
The `accept_new_txs` dynamic-config flag is meant to let an operator pause transaction ingestion on a node, but this "pause" is enforced only at the HTTP server layer, not inside the `Gateway`/`GenericGateway` component itself. Transactions that arrive via the P2P broadcast path (`MempoolP2pRunner`) call `gateway_client.add_tx` directly, bypassing the HTTP-layer gate entirely, so the node's mempool state keeps changing even while it is supposed to be "paused" - mirroring the `NibblVault.updateTWAV` bug where a state-mutating entry point was reachable while the system was nominally paused because the pause modifier was applied to only one caller and not the underlying function.

### Finding Description
`accept_new_txs` is checked in the two axum handlers `add_rpc_tx` and `add_tx` in `crates/apollo_http_server/src/http_server.rs`: [1](#0-0) [2](#0-1) 

This is the only place `check_new_transactions_are_allowed` is invoked in the entire codebase. The actual state-mutating logic lives in `GenericGateway::add_tx` / `add_tx_inner`, which validates the transaction and forwards it to the mempool (`self.mempool_client.add_tx(add_tx_args)`), with no `accept_new_txs` (or any pause) check at all: [3](#0-2) 

The `MempoolP2pRunner` calls this same `gateway_client.add_tx` directly whenever it receives a transaction batch from the network - a path that never goes through the HTTP server and thus never checks `accept_new_txs`: [4](#0-3) 

So the "pause" only blocks the local HTTP submission endpoint. Any transaction submitted to (or accepted by) another honest node still propagates over the mempool-p2p gossip network to this node, where it is validated and inserted into the mempool via `Mempool::add_tx`, mutating mempool state (`tx_pool`, `tx_queue`, account nonce tracking) exactly as the `updateTWAV` bug mutated system state (TWAV, buyout status) despite `Pause` mode being active.

### Impact Explanation
When an operator sets `accept_new_txs = false` (e.g., during an incident, upgrade, or intentional halt of new-transaction admission), the intention is that the node's mempool/gateway state should stop changing from new transactions. Because the check is bypassed for the P2P ingestion path, the mempool keeps accepting and reordering transactions, consuming capacity, updating nonce tracking, and potentially proposing/broadcasting these transactions further - defeating the purpose of the pause. This can interfere with incident mitigation or maintenance procedures that rely on `accept_new_txs=false` to freeze mempool state, and could let mempool capacity fill up or account nonce state advance in ways the operator explicitly intended to prevent.

### Likelihood Explanation
Any regular, unprivileged transaction submitted to another sequencer/gateway on the network will be gossiped via the mempool P2P protocol to every peer, including one with `accept_new_txs` set to `false`. No special/malicious behavior is required from any peer - this is simply the normal transaction-propagation path — so the bypass is reliably triggered any time the network continues to carry traffic while one node is "paused."

### Recommendation
Enforce the `accept_new_txs` (or equivalent pause) check inside `GenericGateway::add_tx`/`add_tx_inner` itself (or in `Mempool::add_tx`), so that both the HTTP path and the P2P path are gated by the same dynamic config, rather than relying on the HTTP server to be the sole enforcement point.

### Proof of Concept
1. Set node A's `http_server_config.dynamic_config.accept_new_txs` to `false` (confirmed via `/gateway/is_ready` returning `503`).
2. Submit a valid transaction to node B (with `accept_new_txs = true`); node B's gateway forwards it to its mempool and propagator, which broadcasts it over the mempool-p2p topic.
3. Node A's `MempoolP2pRunner` receives the broadcast in its `broadcasted_topic_server.next()` branch and calls `self.gateway_client.add_tx(...)` directly (`crates/apollo_mempool_p2p/src/runner/mod.rs:104-128`), with no reference to `accept_new_txs`.
4. Node A's `GenericGateway::add_tx_inner` validates and forwards the transaction to its own mempool (`crates/apollo_gateway/src/gateway.rs:191-298`), mutating node A's mempool state even though `accept_new_txs=false` on node A.

        tx: RpcTransaction,

        let is_p2p = p2p_message_metadata.is_some();

        let start_time = std::time::Instant::now();

    async fn add_tx_inner(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        let mut metric_counters = GatewayMetricHandle::new(&tx, &p2p_message_metadata);
        metric_counters.count_transaction_received();
        if let RpcTransaction::Invoke(RpcInvokeTransaction::V3(ref inv)) = tx {
            if !inv.proof_facts.is_empty() {
                metric_counters.count_private_transaction_received();
            }
        }
        let is_p2p = p2p_message_metadata.is_some();

        if let RpcTransaction::Declare(ref declare_tx) = tx {
            if let Err(e) = self.check_declare_permissions(declare_tx) {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        }

        // Perform stateless validations.
        self.stateless_tx_validator.validate(&tx)?;

        let tx_signature = tx.signature().clone();

        // Declare conversions overload the compiler component's CPU and memory. Reject declares if
        // there are too many declares compiling in parallel. The permit is held only across
        // compilation and released before stateful validation.
        let compilation_permit = if matches!(tx, RpcTransaction::Declare(_)) {
            Some(self.declare_compilation_semaphore.try_acquire().map_err(|_| {
                let error = StarknetError::too_many_concurrent_declare_compilations();
                metric_counters.record_add_tx_failure(&error);
                error
            })?)
        } else {
            None
        };

        let (internal_tx, executable_tx, proof_data) =
            self.convert_rpc_tx_to_internal_and_executable_txs(tx, &tx_signature).await?;
        drop(compilation_permit);

        let mut stateful_transaction_validator = self
            .stateful_tx_validator_factory
            .instantiate_validator(self.config.dynamic_config.native_classes_whitelist.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let nonce = stateful_transaction_validator
            .extract_state_nonce_and_run_validations(&executable_tx, self.mempool_client.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let proof_archive_handle = self
            .store_proof_and_spawn_archiving(proof_data, internal_tx.tx_hash, is_p2p)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let gateway_output = create_gateway_output(&internal_tx);

        let add_tx_args = AddTransactionArgsWrapper {
            args: AddTransactionArgs::new(internal_tx, nonce),
            p2p_message_metadata,
        };

        // Await as late as possible for proof archiving before sending the transaction to the
        // mempool.
        Self::await_proof_archiving(proof_archive_handle)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let mempool_client_result = self.mempool_client.add_tx(add_tx_args).await;
        match mempool_client_result_to_deprecated_gw_result(&tx_signature, mempool_client_result) {
            Ok(()) => {}
            Err(e) => {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        };

        metric_counters.transaction_sent_to_mempool();

        Ok(gateway_output)
    }
