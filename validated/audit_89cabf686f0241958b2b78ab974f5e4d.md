### Title
Session authentication cookie persisted in plaintext on local disk with no encryption - (File: core/cmd/shell.go)

### Summary
The chainlink CLI's `DiskCookieStore` persists the node's session authentication cookie to a local file in cleartext, protected only by OS file permission bits (`0600`) rather than any cryptographic protection. This mirrors the HAL-04 analog: a sensitive authentication credential (there, a PIN in iOS Keychain; here, a session cookie granting authenticated API access to the Chainlink node) is stored in raw, unencrypted form, relying solely on the storage medium's access-control layer instead of encryption/hashing of the secret itself.

### Finding Description
`SessionCookieAuthenticator.Authenticate` obtains a session cookie from the node's `/sessions` endpoint and calls `t.store.Save(sc)` to persist it [1](#0-0) . The default production `CookieStore` implementation is `DiskCookieStore`, whose `Save` method writes the raw `cookie.String()` value directly to a file with `os.WriteFile(d.cookiePath(), []byte(cookie.String()), 0o600)` [2](#0-1) . `Retrieve` reads that same plaintext file back to reconstruct the authenticated session [3](#0-2) . The cookie path lives under the user's cache directory (`UserCacheDir()/chainlink/cookies/cookie`) [4](#0-3) , and this store is wired in as the default `CookieAuthenticator` for every CLI invocation in `app.Before` [5](#0-4) .

Similar to the underlying `securecookie` signing key used to authenticate the node's session cookies, which is likewise written to disk as a base64 string with only file-mode (`0600`) protection and no additional encryption-at-rest, via `FilePersistedSecretGenerator.Generate` [6](#0-5) .

In both cases, the sole protection for a bearer credential capable of granting authenticated node API access is the operating system's file permission bits — there is no hashing, envelope encryption, or OS keychain/secure-enclave-equivalent protection of the value itself. This is directly analogous to the HAL-04 finding: a sensitive credential stored in cleartext, protected only by the accessibility/permission attribute of the storage mechanism (Keychain accessibility level there; Unix file mode here) rather than by cryptographic means.

### Impact Explanation
If the cookie file (or the `secret` signing-key file) is exposed through any channel that bypasses or outlives the OS permission model — for example, unencrypted backups, disk images, misconfigured shared home directories, container volume snapshots, or a separate local process/service running with the same or elevated privileges that reads arbitrary files — an attacker can directly read the plaintext session cookie and immediately impersonate the authenticated admin user against the Chainlink node's HTTP API, without needing to know the underlying password. Compromise of the `secret` file additionally allows forging valid session cookies outright, since it is the HMAC/encryption key for `gorilla/securecookie`.

### Likelihood Explanation
Exploitation requires an attacker to obtain read access to the local filesystem location of the cookie/secret file (e.g., via backup exposure, misconfigured permissions in a different subsystem, or a co-located compromised process). This is a lower-likelihood, defense-in-depth-relevant path since normal OS access controls (`0600`) block same-machine, different-user access under correct configuration; but there is no protection against any process/context that has the running user's file access, which is exactly the class of exposure the plaintext-PIN report flags for the Keychain scenario.

### Recommendation
Encrypt the persisted session cookie (and the `secret` signing key) at rest using a key derived from something not stored alongside the file (e.g., OS keyring/secret-service integration, or a passphrase-derived key), rather than relying solely on filesystem permission bits. At minimum, treat these files with the same rigor recommended in the original report: avoid ever writing the raw bearer credential to disk unprotected, and if it must be cached, store a value that cannot be replayed if merely read (e.g., an encrypted blob unlockable only in the context of the authenticated CLI invocation).

### Proof of Concept
1. Run `chainlink admin login` (or any CLI command that triggers `SessionCookieAuthenticator.Authenticate`) to establish a session; observe the plaintext session cookie written to `$(go env GOPATH)/../Caches/chainlink/cookies/cookie` (or platform equivalent) via `DiskCookieStore.Save` [7](#0-6) .
2. `cat` the file to confirm the full raw `Set-Cookie` value (session ID) is stored unencrypted.
3. Copy this file to another context with read access to the user's cache directory (e.g., a backup, a shared volume, or another local process running as the same user) and use the cookie value directly in an HTTP request to the node's API to authenticate as the admin user, without ever knowing their password.

// Authenticate retrieves a session ID via a cookie and saves it to disk.
func (t *SessionCookieAuthenticator) Authenticate(ctx context.Context, sessionRequest sessions.SessionRequest) (*http.Cookie, error) {
	b := new(bytes.Buffer)
	err := json.NewEncoder(b).Encode(sessionRequest)
	if err != nil {
		return nil, err
	}
	url := t.config.RemoteNodeURL.String() + "/sessions"
	req, err := http.NewRequestWithContext(ctx, "POST", url, b)
	if err != nil {
		return nil, err
	}
	req.Header.Set("Content-Type", "application/json")

	client := newHttpClient(t.lggr, t.config.InsecureSkipVerify)
	resp, err := client.Do(req)
	if err != nil {
		return nil, err
	}
	defer t.lggr.ErrorIfFn(resp.Body.Close, "Error closing Authenticate response body")

	_, err = parseResponse(resp)
	if err != nil {
		return nil, err
	}

	cookies := resp.Cookies()
	if len(cookies) == 0 {
		return nil, errors.New("did not receive cookie with session id")
	}
	sc := web.FindSessionCookie(cookies)
	return sc, t.store.Save(sc)
}

// Retrieve returns any Saved cookies.
func (d DiskCookieStore) Retrieve() (*http.Cookie, error) {
	b, err := os.ReadFile(d.cookiePath())
	if err != nil {
		if os.IsNotExist(err) {
			return nil, nil
		}
		return nil, stderrors.Join(errors.New("unable to retrieve credentials, you must first login through the CLI"), err)
	}
	header := http.Header{}
	header.Add("Cookie", string(b))
	request := http.Request{Header: header}
	cookies := request.Cookies()
	if len(cookies) == 0 {
		return nil, errors.New("Cookie not in file, you must first login through the CLI")
	}
	return request.Cookies()[0], nil
}

type FilePersistedSecretGenerator struct{}

func (f FilePersistedSecretGenerator) Generate(rootDir string) ([]byte, error) {
	sessionPath := filepath.Join(rootDir, "secret")
	if exists, err := utils.FileExists(sessionPath); err != nil {
		return nil, err
	} else if exists {
		data, err := os.ReadFile(sessionPath)
		if err != nil {
			return data, err
		}
		return base64.StdEncoding.DecodeString(string(data))
	}
	key := securecookie.GenerateRandomKey(32)
	str := base64.StdEncoding.EncodeToString(key)
	err := utils.WriteFileWithMaxPerms(sessionPath, []byte(str), readWritePerms)
	return key, err
}
