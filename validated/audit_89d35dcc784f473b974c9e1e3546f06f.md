### Title
Free, unbounded, permanent account-state creation via `AccountInitDecorator` bypasses all storage/fee accounting - (File: `app/ante/account_init_decorator.go`)

### Summary
The external report describes `internal_register_account` creating new user accounts without charging for the storage they consume, eventually causing chain-wide account-creation exhaustion. Push Chain's native analog is `AccountInitDecorator.AnteHandle`, which creates a brand-new on-chain `BaseAccount` for *any* signer on a "gasless" transaction, with zero gas, zero fee, and zero storage cost, as long as the attacker can produce a syntactically valid signature over `account_number=0, sequence=0`. [1](#0-0) 

### Finding Description
`IsGaslessTx` whitelists specific message types (`MsgExecutePayload`, `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`, `MsgMigrateUEA`), intended for UEA users and Universal Validators who shouldn't need to pre-fund gas. [2](#0-1) 

Any transaction wrapping one of these message types is completely exempt from `MinGasPriceDecorator` and `DeductFeeDecorator` checks. [3](#0-2) 

In the ante chain, `AccountInitDecorator` runs before signature/sequence decorators. For a gasless tx whose single signer has no existing account, it only requires a valid signature over a fixed, attacker-known `SignerData{AccountNumber:0, Sequence:0}` — trivially producible offline for any freshly generated keypair with no cost — and then unconditionally calls `NewAccountWithAddress` + `SetAccount`, permanently persisting a new account record in state: [1](#0-0) 

Critically, this side effect is applied directly to the block-execution context, not a cache context. Even if the underlying wrapped message (e.g. `MsgVoteInbound`) subsequently fails authorization checks in its message handler — for example because the attacker is not a registered Universal Validator — that failure only reverts the message-handling cache context; it does **not** undo the account creation already committed by the ante handler. This is the same class of defect as `internal_register_account`: state that must be paid for (an account record occupying permanent chain storage) is created without any storage staking, fee, or bound. [4](#0-3) 

An unprivileged external attacker only needs to:
1. Generate an arbitrary keypair (free, offline).
2. Craft a tx wrapping any whitelisted message type (e.g. `MsgVoteInbound` with junk data) signed against `account_number=0, sequence=0`.
3. Broadcast it.

Each such tx is accepted by `AccountInitDecorator`, which creates and persists a new account, entirely bypassing `MinGasPriceDecorator` and `DeductFeeDecorator` (both skip when `IsGaslessTx` is true). [5](#0-4) 

This can be repeated indefinitely with new keypairs, at effectively zero cost to the attacker (no token balance required, no fee, no gas billed), each time growing chain state permanently.

### Impact Explanation
This is unauthorized, unbounded, fee-free growth of canonical on-chain state (account records) triggered purely by an unprivileged external attacker, matching the "in scope" DoS category ("not network-level and reachable without privileged control"). Over time this inflates the account store, increases IAVL tree size, state sync payloads, and snapshot/export costs for every full node and validator, degrading node performance and potentially exhausting disk/memory resources network-wide — mirroring exactly the original bug's outcome ("eventually users will not be able to create new accounts" / chain becomes unusable) but scoped to Push Chain's own gasless account-bootstrapping path rather than a generic account module.

### Likelihood Explanation
High. No privileged role, token balance, or validator status is required. The attacker only needs to craft a valid signature against a fixed, publicly known `(account_number=0, sequence=0, chain_id)` tuple for a self-chosen keypair — a purely local, free, and automatable operation. The whitelisted message types (e.g. `MsgVoteInbound`) do not need to be semantically valid or pass downstream authorization to trigger the account-creation side effect, since that side effect is committed by the ante handler before the message is ever routed to its handler.

### Recommendation
- Charge a minimal, non-gasless storage fee (or require a small bonded/escrowed amount) for account creation performed by `AccountInitDecorator`, even on otherwise-gasless transactions.
- Alternatively, gate account creation on the underlying message's authorization succeeding first (e.g., only create the account within the same atomic context as successful message execution, so a failed authorization check reverts the account creation too), and/or restrict eligibility to addresses that can be independently verified as legitimate UEA/UV identities before persisting new state.
- Consider rate-limiting or capping the number of ante-handler-driven account creations per block/proposer to bound worst-case state growth.

### Proof of Concept
1. Generate a new secp256k1/ed25519 keypair `K` offline (free).
2. Construct a `MsgVoteInbound` (or any other gasless-whitelisted message) with arbitrary/junk field values, signed by `K` using `SIGN_MODE_DIRECT`/`LEGACY_AMINO`, with `SignerData{Address: addr(K), ChainID: <chain-id>, AccountNumber: 0, Sequence: 0}` per `verifySignatureForNewAccount`. [6](#0-5) 
3. Broadcast the tx. `IsGaslessTx` returns true, so `MinGasPriceDecorator` and `DeductFeeDecorator` are skipped. [3](#0-2) 
4. `AccountInitDecorator` sees `HasAccount(addr(K)) == false`, verifies the crafted signature succeeds (trivial since attacker controls both key and target signer data), then calls `NewAccountWithAddress`/`SetAccount`, persisting the account and returning `(ctx, nil)`. [7](#0-6) 
5. The wrapped `MsgVoteInbound` is subsequently routed to its handler and rejected (attacker is not a registered Universal Validator), but the account created in step 4 remains persisted in state.
6. Repeat with a fresh keypair `K'`, `K''`, ... indefinitely — each iteration costs nothing and adds one permanent account record to chain state.

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}

func (mpd MinGasPriceDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (newCtx sdk.Context, err error) {
	feeTx, ok := tx.(sdk.FeeTx)
	if !ok {
		return ctx, errorsmod.Wrapf(errortypes.ErrInvalidType, "invalid transaction type %T, expected sdk.FeeTx", tx)
	}

	minGasPrice := mpd.feemarketKeeper.GetParams(ctx).MinGasPrice

	feeCoins := feeTx.GetFee()
	evmDenom := evmtypes.GetEVMCoinDenom()

	// only allow user to pass in aevmos and stake native token as transaction fees
	// allow use stake native tokens for fees is just for unit tests to pass
	//
	// TODO: is the handling of stake necessary here? Why not adjust the tests to contain the correct denom?
	validFees := len(feeCoins) == 0 || (len(feeCoins) == 1 && slices.Contains([]string{evmDenom, sdk.DefaultBondDenom}, feeCoins.GetDenomByIndex(0)))
	if !validFees && !simulate {
		return ctx, fmt.Errorf("expected only native token %s for fee, but got %s", evmDenom, feeCoins.String())
	}

	// Short-circuit if min gas price is 0 or if simulating
	if minGasPrice.IsZero() || simulate {
		return next(ctx, tx, simulate)
	}
