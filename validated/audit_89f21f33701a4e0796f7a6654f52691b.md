### Title
Per-endpoint permit leak when GlobalRateLimiter.acquirePermit throws before try/finally is entered - ([File: RateLimiterServlet.java])

### Summary
In `RateLimiterServlet.service`, the calls to acquire both the per-endpoint permit and the global permit happen *before* the `try` block that contains the release logic in `finally`. If `GlobalRateLimiter.acquirePermit(runtimeData)` throws an unchecked exception after the per-endpoint permit has already been acquired, the exception propagates out of `service()` without ever reaching the `finally` block, so the per-endpoint `IPreemptibleRateLimiter.release()` call is never made and the permit is permanently leaked.

### Finding Description
The relevant code is: [1](#0-0) 

Specifically:
- Line 107: `RuntimeData runtimeData = new RuntimeData(req);`
- Line 113: `boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);`
- Line 114: `boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);`
- Line 125: `try {` — the `try` block, and therefore the `finally` block at line 141 that performs `((IPreemptibleRateLimiter) rateLimiter).release();`, only starts **after** lines 107–114 have already executed.

This means the acquisition of both permits (lines 113–114) is entirely outside the `try/finally` protection. If `rateLimiter.acquirePermit(runtimeData)` (line 113) succeeds and sets `perEndpointAcquired = true`, but the subsequent `GlobalRateLimiter.acquirePermit(runtimeData)` call (line 114) throws an unchecked exception (e.g., `NullPointerException`, `IllegalArgumentException` from Guava's `RateLimiter`, or any exception derived from malformed `RuntimeData` state built from attacker-controlled headers such as `X-Forwarded-For` or `remoteAddr`), the exception unwinds the stack immediately. Since the `try` block hasn't been entered yet, the `finally` block at lines 141–151 — which contains the only release call for `IPreemptibleRateLimiter` — never executes.

`GlobalRateLimiter.acquirePermit` internally calls `loadIpLimiter(ip)` which uses a Guava `Cache.get()` with a loader `() -> RateLimiter.create(IP_QPS)`; while the current code wraps this specific call in a try/catch, any other unchecked exception thrown out of `tryAcquire`/`acquire` (for example if `RuntimeData.getRemoteAddr()` throws, or future refactors introduce an exception path) is not protected because the `perEndpointAcquired`/`acquireResource` evaluation itself sits outside the servlet's try/finally. [2](#0-1) 

The `GlobalPreemptibleAdapter`'s underlying `GlobalPreemptibleStrategy` uses a bounded `Semaphore` for the per-endpoint permit: [3](#0-2) 
Each leaked acquisition permanently reduces the semaphore's available permits (bounded by `STRATEGY_PARAM_PERMIT`), and repeated triggering of this path would eventually exhaust the semaphore for that endpoint (e.g., `/wallet/getrcm`), denying service to all future callers of that same rate limiter instance.

### Impact Explanation
Any endpoint configured with a `GlobalPreemptibleAdapter` (semaphore-backed `IPreemptibleRateLimiter`) is vulnerable to permanent permit exhaustion if this narrow exception window is exercised repeatedly. Because `GlobalPreemptibleAdapter`/`GlobalPreemptibleStrategy` instances are shared per rate-limiter key (potentially shared across configured servlets sharing the same adapter class/params), a sustained attack could deny service to legitimate callers of `/wallet/getrcm` and any other endpoint pointed at the same limiter instance, until process restart.

### Likelihood Explanation
The exploit requires finding an actual unchecked-exception trigger inside `GlobalRateLimiter.acquirePermit` (or a future/less-defensive code path) that fires only after the per-endpoint semaphore has been successfully acquired. In the current code, `loadIpLimiter` catches its own exceptions defensively, and `RuntimeData.getRemoteAddr()` was not found to throw for attacker-supplied header values in the reviewed code — I could not confirm a concrete, currently-reachable unchecked-exception trigger from crafted headers within `RuntimeData` or `GlobalRateLimiter` as written today. The structural bug (try/finally starting after both acquisitions) is real and independently verifiable by code inspection, but a full proof-of-concept requires identifying or injecting a code path that throws between lines 113 and 125 — this is best validated with a unit test that mocks `GlobalRateLimiter.acquirePermit` to throw, rather than relying on organically malformed headers.

### Recommendation
Move the permit-acquisition calls inside the `try` block (or restructure so that the per-endpoint acquisition and its corresponding release are always paired within the same try/finally scope), e.g.:
```java
RuntimeData runtimeData = new RuntimeData(req);
IRateLimiter rateLimiter = container.get(KEY_PREFIX_HTTP, getClass().getSimpleName());
boolean perEndpointAcquired = false;
try {
  perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
  boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);
  ...
} finally {
  if (rateLimiter instanceof IPreemptibleRateLimiter && perEndpointAcquired) {
    ((IPreemptibleRateLimiter) rateLimiter).release();
  }
}
```
This guarantees the release always executes regardless of where an exception occurs after the per-endpoint permit was obtained.

### Proof of Concept
```java
@Test
public void testPermitLeakedWhenGlobalAcquireThrowsAfterPerEndpointAcquired() throws Exception {
  IPreemptibleRateLimiter perEndpoint = Mockito.mock(IPreemptibleRateLimiter.class);
  when(perEndpoint.acquirePermit(any(RuntimeData.class))).thenReturn(true);
  container.add(KEY_HTTP, "TestServlet", perEndpoint);

  try (MockedStatic<GlobalRateLimiter> globalMock = mockStatic(GlobalRateLimiter.class)) {
    // Simulate an unchecked exception thrown mid-evaluation (e.g. malformed RuntimeData)
    globalMock.when(() -> GlobalRateLimiter.acquirePermit(any()))
        .thenThrow(new RuntimeException("simulated malformed RuntimeData failure"));

    assertThrows(RuntimeException.class, () -> servlet.service(request, response));

    // BUG: release() is never called because the exception occurs before try/finally
    verify(perEndpoint, never()).release();
  }
}
```
Expected (secure) behavior: `release()` should be invoked exactly once even when `GlobalRateLimiter.acquirePermit` throws, restoring the semaphore to baseline. Current behavior: `release()` is never called, demonstrating the leak.

  private Semaphore sp;

  public GlobalPreemptibleStrategy(String paramString) {
    super(paramString);
    sp = new Semaphore((Integer) mapParams.get(STRATEGY_PARAM_PERMIT).value);
  }

  // define the default strategy params.
  @Override
  protected Map<String, ParamItem> defaultParam() {
    Map<String, ParamItem> map = new HashMap<>();
    map.put(STRATEGY_PARAM_PERMIT, new ParamItem(Integer.class, DEFAULT_PERMIT_NUM));
    return map;
  }

  // Non-blocking: immediately rejects if no permit is available. Used when the
  // apiNonBlocking switch is on, to shed overload instead of tying up Netty IO /
  // gRPC executor threads while waiting for a permit.
  public boolean tryAcquire() {
    return sp.tryAcquire();
  }

  public boolean acquire() {
    try {
      return sp.tryAcquire(DEFAULT_ACQUIRE_TIMEOUT, TimeUnit.SECONDS);
    } catch (InterruptedException e) {
      // Restore the interrupt flag and reject — caller must not release a permit
      // it never acquired.
      logger.error("acquire permit with error: {}", e.getMessage());
      Thread.currentThread().interrupt();
      return false;
    }
  }

  public void release() {
    sp.release();
  }
