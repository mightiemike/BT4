### Title
Fixed 5% slippage tolerance on module-driven gas-abstraction auto-swap enables sandwich-style value extraction against PRC20/WPC accounting - ([File: x/uexecutor/keeper/execute_inbound_gas.go], [File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go], [File: x/uexecutor/keeper/outbound.go], [File: x/uexecutor/keeper/evm.go])

### Summary
The external report describes a role (`UNWIND_ROLE`) that can repeatedly exploit a fixed, protocol-set slippage tolerance (`allowedUnwindSlippagePercent`) against a price reference to extract value from an external market. Push Chain's `uexecutor` module has a structurally identical pattern: every gas-abstraction and gas-refund auto-swap uses a *fixed* 5% slippage band computed from a single spot quote fetched from an on-chain Uniswap V3 `QuoterV2` immediately before executing the real swap, with no price-impact cap (`SqrtPriceLimitX96 = 0`) and no TWAP/oracle cross-check.

### Finding Description
Three code paths compute `minPCOut` the same way and then commit the swap in the same call:

- `ExecuteInboundGas` (GAS inbound route): fetches a quote via `GetSwapQuote` and hard-codes `minPCOut = quote * 95 / 100` before calling `CallPRC20DepositAutoSwap`. [1](#0-0) 

- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound route): identical pattern. [2](#0-1) 

- `applyGasRefund` (outbound unused-gas refund path, triggered on `MsgVoteOutbound` finalization): fetches a fresh quote via `getSwapQuoteForRefund` and applies the same `quote * 95 / 100` band before calling `CallUniversalCoreRefundUnusedGas` with `withSwap=true`. [3](#0-2) 

The underlying quote mechanism, `GetSwapQuote`, calls `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96: big.NewInt(0)` — i.e., no price-limit protection is passed to the quoter, and the same spot price is trusted for the executed swap: [4](#0-3) 

`CallPRC20DepositAutoSwap` and `CallUniversalCoreRefundUnusedGas` then execute the real swap through `UniversalCore.depositPRC20WithAutoSwap` / `refundUnusedGas` against the same live, permissionless PRC20/WPC Uniswap V3 pool used for the quote: [5](#0-4) [6](#0-5) 

Because the pool is a standard, permissionlessly-tradable Uniswap V3 pool (the ABI includes `uniswapV3Quoter`, `WPC`, `defaultFeeTier`) and 5% is a fixed, protocol-wide constant rather than a value derived from a manipulation-resistant reference price (e.g., TWAP), any unprivileged trader who can influence the pool's instantaneous price at the moment `GetSwapQuote`/swap execute — analogous to how the `UNWIND_ROLE` exploited `allowedUnwindSlippagePercent` against an external market price — can bias the module's auto-swap outcome and capture the spread, up to the 5% band, on every gas-abstraction deposit or gas-fee refund that flows through these routes.

### Impact Explanation
This corrupts PRC20/native asset accounting: the module mints/deposits PRC20 and swaps it for WPC (or vice versa for refunds) using module-owned funds, and a manipulated quote lets an outside trader repeatedly skim up to 5% of each such swap's notional value from protocol-controlled liquidity — draining value across many inbound/outbound events over time, matching the "repeated slippage arbitrage" impact class (unauthorized drain of protocol-controlled funds via allowed-tolerance abuse).

### Likelihood Explanation
Likelihood is **uncertain and could not be fully confirmed** with available tooling. The exploit requires an unprivileged trader to move the PRC20/WPC pool price immediately before the module's internal `GetSwapQuote` → swap sequence executes, and for that sequencing to be attacker-influenceable (e.g., via transaction ordering/mempool front-running relative to the `MsgVoteInbound`/`MsgVoteOutbound` transaction that triggers `ExecuteInboundGas`/`applyGasRefund`). I was not able to inspect `x/uexecutor/keeper/msg_vote_inbound.go` or `ballot_hooks.go` before running out of tool calls, so I cannot confirm whether ballot finalization and the auto-swap execute purely synchronously within a single validator-submitted transaction (which would still allow front-running by an unprivileged trader submitting an ordinary swap transaction in the same block) or whether additional protections exist elsewhere. The quote-then-swap step itself is atomic (single message handler, `commit=false` quote followed immediately by `commit=true` swap), so the only manipulation vector is the pool's price state going into that handler, not interleaving within it.

### Recommendation
- Replace the fixed 5% band with a slippage bound derived from a manipulation-resistant reference (TWAP over multiple blocks, or a bounded max deviation from a recent moving average), not a single spot quote from the same block used to execute the trade.
- Pass a non-zero `SqrtPriceLimitX96` or otherwise cap allowable price impact per trade in `GetSwapQuote`.
- Consider splitting large gas-abstraction/refund swaps or routing through a protected internal price source instead of a public AMM pool that any address can trade against just before protocol-triggered swaps execute.

### Proof of Concept
Conceptual PoC (mirrors the external report's structure; not independently executed against this repo):
1. Attacker observes a pending `MsgVoteInbound` (GAS or GAS_AND_PAYLOAD route) about to reach the 2/3 threshold, which will trigger `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap`.
2. Attacker submits a large swap against the PRC20/WPC Uniswap V3 pool with a higher gas price so it lands immediately before the finalizing vote transaction in the same block, moving the spot price used by `GetSwapQuote`.
3. The module's `depositPRC20WithAutoSwap` executes against the skewed price, bounded only by the fixed 5% `minPCOut` floor, letting the attacker capture the difference by reversing their initial trade afterward.
4. Repeat across successive inbound/outbound gas-refund events to accumulate profit — the analog to repeatedly calling `unwind` in the original report. [7](#0-6) [8](#0-7)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// CallUniversalCoreRefundUnusedGas calls refundUnusedGas on UniversalCore to return excess gas fee
// to the recipient. withSwap=true swaps the gas token back to PC; withSwap=false deposits PRC20 directly.
func (k Keeper) CallUniversalCoreRefundUnusedGas(
	ctx sdk.Context,
	gasToken common.Address,
	amount *big.Int,
	recipient common.Address,
	withSwap bool,
	fee *big.Int,
	minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	// fee is uint24 in Solidity — pass as *big.Int (go-ethereum ABI packs non-standard widths as *big.Int)
	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress,
		handlerAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"refundUnusedGas",
		gasToken,
		amount,
		recipient,
		withSwap,
		fee,
		minPCOut,
	)
}
