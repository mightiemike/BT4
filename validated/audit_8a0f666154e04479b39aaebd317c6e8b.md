### Title
Unbounded recursion when hashing/traversing attacker-controlled `bytecode_segment_lengths` (`NestedIntList`) can stack-overflow the sequencer - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs])

### Summary
The compiled-class hash computation and the Starknet-OS bytecode segment traversal both process the `bytecode_segment_lengths: Option<NestedIntList>` field of a `CasmContractClass` with unbounded, non-tail recursion. This field is a recursive `Leaf`/`Node(Vec<NestedIntList>)` tree produced by the Sierra→CASM compiler from the *shape* of the declared Sierra program (branch/function segmentation). A contract declarer fully controls the Sierra program submitted in a `DECLARE` transaction, and therefore has significant influence over the depth/shape of the resulting segment tree that the sequencer subsequently walks recursively multiple times (during compilation/hashing, execution, and OS re-execution), with no explicit depth cap on this particular recursion — analogous to SnakeYAML's unguarded recursive-descent parsing of attacker-supplied nested YAML causing a native stack overflow (CVE-2022-41854).

### Finding Description
`CasmContractClass::hash()` computes the compiled class hash by calling `bytecode_hash` → `bytecode_hash_node`, which recurses once per nesting level of `bytecode_segment_lengths`: [1](#0-0) 

This is invoked directly from the Sierra compiler pipeline right after a class is compiled (i.e., on every accepted `DECLARE`): [2](#0-1) 

The same recursive-tree structure is also walked without depth limiting in the Starknet OS hint implementation used during (re-)execution/proving: [3](#0-2) 

and it is stored/retrieved via a recursive `StorageSerde`/serde implementation (`NestedIntList` derives recursive `Serialize`/`Deserialize`), which will itself recurse to the same depth whenever the class is (de)serialized (e.g. `CasmContractClass::deserialize_from` in `apollo_storage`): [4](#0-3) 

None of these functions impose an explicit maximum recursion depth for this particular tree, unlike the contract call recursion, which is explicitly bounded by `RecursionDepthGuard`/`max_recursion_depth`: [5](#0-4) 

Only the blockifier's `NestedFeltCounts::new_inner` (used for gas/visited-PC accounting) enforces `segmentation_depth <= 1` and would `assert!`/panic if violated: [6](#0-5) 

— but the class-hash computation path (`bytecode_hash_node`) and the OS hint path (`create_bytecode_segment_structure_inner`) have no such restriction, and process the tree exactly as emitted by the compiler for whatever depth the Sierra program's control-flow/segmentation produces. The `max_bytecode_size` config bound (`DEFAULT_MAX_BYTECODE_SIZE = 80 * 1024`) only limits the *total number of felts* in the bytecode, not the *nesting depth* of the segment tree; a program can be crafted so that segmentation is heavily degenerate (deeply chained single-child `Node`s) rather than balanced, producing a very deep tree relative to the felt budget.

### Impact Explanation
If a maliciously crafted Sierra program produces a `bytecode_segment_lengths` tree deep enough to exceed the sequencer process's stack, the recursive traversal in `bytecode_hash_node` (called on every `DECLARE`, and again by every full node re-executing the block/verifying `check_compile_class_hash_v2_declaration`), in `create_bytecode_segment_structure_inner` (called by the Starknet OS during (re-)execution/proving), and in the recursive `(de)serialize` of `NestedIntList` in storage, will overflow the native stack and crash the process (SIGSEGV/abort). Because this class-hash computation and CASM (de)serialization must be performed identically by every sequencer/full node/prover processing the same declared class, this can cause honest-node divergence (some nodes crash while trying to validate the class, halting progress) or a network-wide inability to process blocks containing the malicious declaration — a Medium/High severity denial-of-service, consistent with the CWE-121/CWE-787 stack-overflow class in the reported SnakeYAML advisory.

### Likelihood Explanation
Reachable directly from an unprivileged contract declarer: only requires submitting a `DECLARE` transaction whose Sierra program compiles (within the resource-limited Sierra-to-CASM compiler subprocess) to a `CasmContractClass` with a deeply/degenerately nested `bytecode_segment_lengths`. No special privileges, cooperating validators, or network positioning are required — a single crafted transaction submitted by any account is sufficient to trigger the vulnerable recursive code paths on every node that later hashes, stores, or re-executes the class.

### Recommendation
Impose an explicit maximum nesting-depth check on `NestedIntList`/`bytecode_segment_lengths`, enforced immediately after Sierra→CASM compilation (before it is hashed, stored, or handed to the OS hint processor), analogous to the existing `RecursionDepthGuard`/`max_recursion_depth` mechanism for contract calls. Alternatively/complementarily, convert `bytecode_hash_node`, `create_bytecode_segment_structure_inner`, and the `NestedIntList` (de)serialization to iterative, explicit-stack (heap-allocated worklist) implementations so that depth is bounded only by available heap memory rather than the native call stack, and reject classes whose segment tree exceeds a sane depth bound during declare-time validation.

### Proof of Concept
Conceptual PoC (exact Sierra source needed to produce a maximally-degenerate segment tree could not be fully verified from the indexed code, since the segmentation algorithm itself lives in the external `cairo-lang-starknet-classes` compiler, not in this repository):
1. Author a Cairo 1 contract whose Sierra program is structured so that the compiler's bytecode segmentation produces a deeply chained (near-linear) nesting of functions/branches (e.g., many single-branch nested `match`/function calls) rather than a flat/balanced structure, up to the `max_bytecode_size` felt budget (default `80 * 1024`).
2. Submit this contract as a `DECLARE` transaction; the sequencer's `SierraCompiler::compile` (`crates/apollo_compile_to_casm/src/lib.rs`) will compile it and immediately call `.hash(&HashVersion::V2)`, which recurses via `bytecode_hash_node` once per nesting level of the resulting `bytecode_segment_lengths`.
3. If nesting depth is sufficient to exceed the thread's stack size, the compiler/sequencer process crashes during hashing; any full node/prover later re-executing this declared class hits the same unbounded recursion in `create_bytecode_segment_structure_inner`.

This should be validated on an actual running sequencer/testnet with a real compiled degenerate Sierra program to confirm the concrete depth needed to overflow the stack, since the exact segmentation behavior of the external Sierra compiler for adversarial inputs is outside what could be confirmed purely from this repository's indexed source.

/// Computes the hash of a bytecode segment. See the documentation of `bytecode_hash_node` in
/// the Starknet OS.
/// Returns the length of the processed segment and its hash.
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

/// Helper function for `create_bytecode_segment_structure`.
/// Returns the bytecode segment structure and the total length of the processed segment.
pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}

    /// Recursively builds the nested structure and returns it with the number of items consumed.
    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
    }
