### Title
State-diff encryption symmetric key is derived deterministically from public data, breaking the confidentiality guarantee of encrypted state-diff DA output - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/encrypt.cairo`)

### Summary
The comment header of `encrypt.cairo` states: *"An hint generates a `symmetric_key` and `sn_private_keys` by hashing the compressed state diff"* [1](#0-0) . The `GenerateKeysUsingSha256Hash` hint (invoked from `encrypt_state_diff`) produces the `symmetric_key` used to mask the entire compressed state diff via `ciphertext[i] = plaintext[i] + BLAKE2s(symmetric_key, i)` [2](#0-1) . This is analogous to the reported PasswordStore bug: data is assumed confidential ("encrypted", visible only to committee members who hold private keys) but the mechanism securing that confidentiality is derived from data that is not actually secret.

### Finding Description
Confidentiality of the encrypted DA output depends entirely on `symmetric_key` being unpredictable to non-committee observers. The Cairo comment documents that this key is generated by hashing the *compressed state diff itself* — i.e., the very plaintext being encrypted — rather than from a source of independent randomness (e.g., a random nonce, block hash, or committee-only secret) [3](#0-2) . The masking scheme itself is a simple field-addition stream cipher (`ciphertext = plaintext + hash(key, index)`), explicitly noted as providing "confidentiality only" and relying on the mask being unknown to attackers [4](#0-3) , and the Rust-side reference implementation in `encrypt_state_diff`/`calc_blake_hash` mirrors this exact per-index additive masking [5](#0-4) .

Because the symmetric key is a hash of the plaintext state diff, and the state diff is fully determined by the block's transactions (which are executed deterministically by every node re-executing the OS, per `starknet_os` re-execution), any node capable of computing the state diff independently (which is required to verify correctness of the block in the first place) can recompute the identical `symmetric_key` without needing any committee private key, `ec_mul`/ECDH shared secret, or the encrypted-symmetric-key entries in the output (`output_encrypted_symmetric_key`) at all [6](#0-5) . This defeats the entire purpose of the Diffie-Hellman key wrapping scheme designed to restrict decryption to committee members holding `sn_private_keys` — the "privacy" of the state diff is illusory since the key material used to compute it is derivable by anyone who can compute the state diff, and the OS's re-execution/verification path guarantees exactly that capability to all full nodes, not just the committee.

### Impact Explanation
This breaks the confidentiality guarantee that the encrypted-state-diff DA feature (`use_kzg_da` with committee `private_keys`) is meant to provide: pre-confirmation, privileged committee-only visibility into the state diff. Any full node/verifier of the Starknet OS output — which by design must re-derive the state diff to validate the block — can trivially reconstruct the "secret" symmetric key and decrypt the DA blob ahead of, or without, committee involvement, exposing the intended-to-be-private state diff to unauthorized parties. This is a confidentiality break analogous to the PasswordStore issue (data assumed private is publicly derivable), though the concrete monetary/consensus impact depends on how downstream consumers rely on this encryption for privileged-disclosure timing guarantees.

### Likelihood Explanation
Reaching this path only requires normal block production/state-diff generation with encrypted DA and committee private keys configured (`n_keys > 0`), i.e., the standard `encrypt_state_diff` code path invoked as part of OS execution for any block whose transactions produce a state diff — no privileged access or malicious operator behavior is needed to trigger the flawed key derivation; the vulnerability is inherent to the always-executed key-generation logic itself.

### Recommendation
Derive `symmetric_key` from a source of independent, unpredictable randomness that is not equal to (or trivially derivable from) the plaintext being encrypted — e.g., a fresh random value combined with a domain separator and possibly the block/committee context, sampled outside of any function of the compressed state diff — and ensure `sn_private_keys` are likewise generated independently of the plaintext. Document and test that no observer who can only compute the state diff (i.e., every honest full node) can derive `symmetric_key` without a committee private key.

### Proof of Concept
Conceptual PoC (cannot be fully executed without running the OS test harness, but the code paths are cited above):
1. Configure a block with encrypted state-diff DA and `n_keys >= 1` committee public keys, as done in `crates/starknet_os/src/hints/hint_implementation/state_diff_encryption/state_diff_encryption_test.rs`.
2. As an unprivileged full node, execute the block's transactions locally to compute the same `compressed_start`/`compressed_end` state diff that the sequencer would produce (this is required for any node to verify OS output/re-execute per the Starknet OS re-execution model).
3. Reproduce the `GenerateKeysUsingSha256Hash` derivation (hash of the compressed state diff, per the documented comment) to recompute `symmetric_key` — matching what `encrypt_state_diff` in `encrypt.cairo` line 45-74 would have generated — without possessing any `sn_private_keys`.
4. Use the recomputed `symmetric_key` with `decrypt_state_diff`/`decrypt_iter` from `crates/starknet_os/src/hints/hint_implementation/state_diff_encryption/utils.rs` lines 98-130 to decrypt the published encrypted DA blob, bypassing the committee-only access control entirely.

// Encrypt the same symmetric_key for many recipients.
// Step-by-step for each recipient:
// 1) Recover the full public point (x, y) from the given x.
// 2) Compute a shared secret point = our private key * recipient public point (Diffie–Hellman).
// 3) Hash the x-coordinate of the shared point to get a mask.
// 4) encrypted symmetric key = symmetric_key + hash(shared_secret.x)`.
func output_encrypted_symmetric_key{
    range_check_ptr, ec_op_ptr: EcOpBuiltin*, output_pointer: felt*
}(n_keys: felt, public_keys: felt*, sn_private_keys: felt*, symmetric_key: felt) {
    if (n_keys == 0) {
        return ();
    }

    alloc_locals;

    // Using recover_y(x) is safe because on short-Weierstrass curves (x, y) and (x, -y) share the same x.
    // Scalar multiplication depends only on x(Q), so we can reconstruct y later without ambiguity.
    let (public_key) = recover_y(public_keys[0]);

    let (__fp__, _) = get_fp_and_pc();
    let (local shared_secret) = ec_mul(m=sn_private_keys[0], p=public_key);
    let (hash) = calc_blake_hash_single(item=shared_secret.x);

    assert output_pointer[0] = symmetric_key + hash;
    let output_pointer = &output_pointer[1];

    return output_encrypted_symmetric_key(
        n_keys=n_keys - 1,
        public_keys=&public_keys[1],
        sn_private_keys=&sn_private_keys[1],
        symmetric_key=symmetric_key,
    );
}

#[allow(dead_code)]
pub fn encrypt_state_diff(symmetric_key: Felt, state_diff: &[Felt]) -> Vec<Felt> {
    // Encrypt the state_diff using the symmetric key.
    let encrypted_state_diff = state_diff
        .iter()
        .enumerate()
        .map(|(i, felt)| felt + calc_blake_hash(&[symmetric_key, Felt::from(i)]))
        .collect();
    encrypted_state_diff
}
