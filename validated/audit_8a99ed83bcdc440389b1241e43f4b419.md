### Title
Unbounded recursive JSON traversal on attacker-controlled deprecated (Cairo0) class `Program` fields causes StackOverflow DoS during class-hash computation - ([File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs])

### Summary
`starknet_api::deprecated_contract_class::Program` stores several fields — `attributes`, `builtins`, `compiler_version`, `data`, `debug_info`, `hints`, `identifiers`, `main_scope`, `prime`, `reference_manager` — as untyped `serde_json::Value` [1](#0-0) . These are populated directly by `serde_json`'s recursive `Value` deserializer when a Cairo0 (`DECLARE` v0/v1) contract class is parsed from an incoming transaction, with no nesting-depth limit enforced anywhere in the gateway's stateless validation path. When the hinted class hash is later computed for OS re-execution, `compute_cairo_hinted_class_hash` re-serializes the whole `ContractClass` to a `serde_json::Value` and calls `sort_json_value`, a hand-written function that recurses once per nested JSON object/array level with no depth bound, before re-parsing it into `CairoContractDefinition` (whose `abi`, `identifiers`, `hints`, `reference_manager` fields are again raw `serde_json::Value`) [2](#0-1) [3](#0-2) . A declarer/transaction sender can submit a deeply nested `program.identifiers` / `program.reference_manager` / `abi` JSON blob (syntactically tiny but arbitrarily deep) inside a Cairo0 declare transaction; both the initial `serde_json` deserialization of the `Value` fields and the subsequent `sort_json_value` recursive walk grow the call stack linearly with nesting depth, matching exactly the HAPI-FHIR `readArray()`/`readObject()` unbounded-recursion bug class.

### Finding Description
`ContractClass::program: Program` is deserialized straight from user/transaction-supplied JSON with no `deny_unknown_fields`/depth restriction; several of its members are declared as plain `serde_json::Value`, meaning `serde_json`'s standard (recursive-descent) `Value` deserializer will happily parse an arbitrarily deep array/object nest, recursing once per level [1](#0-0) . Neither the gateway's `StatelessTransactionValidator` (which only checks calldata length, signature length, resource bounds, Sierra bytecode size, and Sierra-specific contract-class-object byte-size — none of which apply to Cairo0 `program` sub-structure depth) nor any other layer bounds the *nesting depth* of this JSON, only its serialized byte size in the Sierra path [4](#0-3) . A byte-size cap does not prevent deep nesting because a document like `[[[[[...]]]]]` can reach thousands of nesting levels while remaining only a few KB.

Once the class reaches Starknet OS re-execution / deprecated class-hash computation, `compute_deprecated_class_hash` calls `compute_cairo_hinted_class_hash`, which performs `serde_json::to_value(contract_class)` followed by the explicitly recursive `sort_json_value` (one stack frame per Object/Array nesting level, unbounded) and then `serde_json::from_slice::<CairoContractDefinition>` — parsing the same deeply-nested `abi`/`identifiers`/`hints`/`reference_manager` `Value` fields all over again [3](#0-2) . This is invoked from `compute_deprecated_class_hash`, which is used by the Starknet OS hint implementation for deprecated compiled classes during (re-)execution of declare transactions [5](#0-4) .

Each of the two recursive passes (serde_json's internal `Value` parser and the hand-rolled `sort_json_value`) adds stack frames proportional to input nesting depth, with no maximum depth check, directly analogous to HAPI FHIR's unbounded `readArray()`/`readObject()` recursion (CVE-2026-62295).

### Impact Explanation
A stack overflow in a worker thread executing class-hash computation/re-execution will abort that thread via `StackOverflowError`/process abort in Rust (`SIGSEGV`/`abort`), which is not catchable via `Result`/`panic::catch_unwind` in the general case (stack overflows abort the whole process in Rust, unlike catchable panics). If this crashes the Starknet OS re-execution process or a sequencer worker that is validating/re-executing declare transactions, it can crash or destabilize the whole node process, producing a denial-of-service condition — the sequencer becomes unable to process transactions (network unable to confirm new transactions), satisfying the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Reachable trivially by any unprivileged party submitting a Cairo0 `DECLARE` transaction (`sender_address` need only pass basic address validation) with a maliciously deep `program.identifiers`/`program.reference_manager`/`abi` JSON structure. No special privileges, staking, or node compromise are required — only crafting a valid-looking (but deeply nested) JSON class body, which passes byte-size checks in `validate_class_length`/`validate_declare_tx` (those apply to the Sierra `ContractClass`, not deprecated Cairo0 `Program`, and even where a byte-size cap exists, it does not bound nesting depth).

### Recommendation
- Enforce an explicit maximum JSON nesting depth check on the raw request body before deserialization of `deprecated_contract_class::Program`/`ContractClassAbiEntry`/`CairoContractDefinition` (e.g., pre-scan brace/bracket nesting depth, or use a depth-limited JSON reader).
- Replace the hand-rolled recursive `sort_json_value` in `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs` with an iterative (explicit stack/queue based) implementation that enforces/rejects beyond a bounded depth.
- Reject Cairo0 declare transactions whose `program` JSON sub-fields exceed a configured maximum nesting depth during stateless gateway validation, mirroring the existing `max_contract_bytecode_size`/`max_contract_class_object_size` checks.

### Proof of Concept
1. Craft a Cairo0 `DECLARE` (v0/v1) transaction whose `contract_class.program.identifiers` (or `reference_manager`, or `abi`) field is a deeply nested JSON array, e.g. `[[[[[[[[[[ ... ]]]]]]]]]]` nested to ~50,000+ levels (a few hundred KB, well under typical byte-size limits).
2. Submit the transaction to the gateway; it passes `StatelessTransactionValidator` (which does not check Cairo0 `Program` nesting depth) and is accepted for further processing/eventual OS re-execution.
3. During class-hash computation (`compute_deprecated_class_hash` → `compute_cairo_hinted_class_hash`), both `serde_json`'s `Value` deserialization and `sort_json_value`'s recursive walk consume stack proportional to nesting depth, causing the process to hit its stack limit and abort/crash.

Note: I was not able to execute this PoC in a sandboxed environment (no code execution tools available in this session); the depth-to-crash threshold and exact crash behavior (abort vs. `SIGSEGV`) would need to be confirmed empirically by a Devin session with code execution access.

/// Recursively sorts all JSON objects by their keys.
/// This ensures deterministic serialization regardless of the `preserve_order` feature in
/// serde_json.
fn sort_json_value(value: serde_json::Value) -> serde_json::Value {
    match value {
        serde_json::Value::Object(map) => {
            let sorted: BTreeMap<String, serde_json::Value> =
                map.into_iter().map(|(k, v)| (k, sort_json_value(v))).collect();
            serde_json::Value::Object(sorted.into_iter().collect())
        }
        serde_json::Value::Array(arr) => {
            serde_json::Value::Array(arr.into_iter().map(sort_json_value).collect())
        }
        other => other,
    }
}

    fn validate_sierra_version(
        &self,
        sierra_program: &[Felt],
    ) -> StatelessTransactionValidatorResult<()> {
        // Any patch version is valid. (i.e. when check version for upper bound, we ignore the Z
        // part in a version X.Y.Z).
        let mut max_sierra_version = self.config.max_sierra_version;
        max_sierra_version.0.patch = usize::MAX;

        let sierra_version = VersionId::from_sierra_program(sierra_program)?;
        if self.config.min_sierra_version <= sierra_version && sierra_version <= max_sierra_version
        {
            return Ok(());
        }

        Err(StatelessTransactionValidatorError::UnsupportedSierraVersion {
            version: sierra_version,
            min_version: self.config.min_sierra_version,
            max_version: self.config.max_sierra_version,
        })
    }

    fn validate_class_length(
        &self,
        contract_class: &starknet_api::state::SierraContractClass,

pub fn compute_deprecated_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    let hinted_class_hash = compute_cairo_hinted_class_hash(contract_class)?;
    let contract_definition_vec = serde_json::to_vec(contract_class)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let FlatEntryPointFelts { external, l1_handler, constructor } =
        get_flat_entry_point_felts(&contract_definition.entry_points_by_type);
    let builtins = ascii_strs_as_felts(&contract_definition.program.builtins);
    let bytecode = hex_strs_as_felts(&contract_definition.program.data);

    let mut hash_state = HashState::<Pedersen>::new();
    hash_state.update_single(&DEPRECATED_COMPILED_CLASS_VERSION);
    hash_state.update_with_hashchain(&external);
    hash_state.update_with_hashchain(&l1_handler);
    hash_state.update_with_hashchain(&constructor);
    hash_state.update_with_hashchain(&builtins);
    hash_state.update_single(&hinted_class_hash);
    hash_state.update_with_hashchain(&bytecode);
    Ok(hash_state.finalize())
