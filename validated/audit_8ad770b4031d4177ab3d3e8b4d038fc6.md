This confirms the vulnerability described. Key evidence:

- `FindUserByAPIToken` in `core/sessions/ldapauth/ldap.go:205-236` reads the role directly from the `ldap_user_api_tokens` table and validates only expiration (`created_at + UserAPITokenDuration >= now()`), with no live upstream re-check — comment explicitly states "no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server via the UpstreamSyncInterval config and reaper.go sync implementation" [1](#0-0) .
- `AuthenticateByToken` in `core/web/auth/auth.go:78-111` grants a session purely based on this returned role, feeding directly into `RequiresAdminRole` in `core/web/auth/auth.go:239-255` which checks only `user.Role != clsessions.UserRoleAdmin`.
- `Work()` purges stale tokens by age (`deleteStaleAPITokens`, using `UserAPITokenDuration`) unconditionally at the top, but the group-membership re-verification/role-downgrade transaction only runs after the rate-limit gate and after all four `ldapGroupMembersListToUser` calls succeed; any error triggers an early `return` before `validateUsersActive` and the role-sync transaction [2](#0-1) .
- The actual role downgrade only happens inside the transaction's `CASE WHEN` update against `ldap_user_api_tokens` [3](#0-2) .

This validates the reasoning: a token retains its originally-issued role until either (a) the full sync pipeline completes successfully and re-derives a lower role, or (b) `UserAPITokenDuration` elapses and `deleteStaleAPITokens`/`FindUserByAPIToken`'s inline expiry check removes it — whichever is not gated on live re-verification of privilege.

### Title
Stale-role API token privilege retention after LDAP group demotion when sync errors or rate-limit gate blocks re-sync - ([File: core/sessions/ldapauth/sync.go])

### Summary
`LDAPServerStateSyncer.Work` purges expired tokens purely by age via `deleteStaleAPITokens` (gated by `UserAPITokenDuration`), completely decoupled from the group-membership re-verification pipeline that actually downgrades a token's cached role. If `ldapGroupMembersListToUser` errors on any group query, or the `UpstreamSyncRateLimit` window hasn't elapsed, `Work` returns before reaching the role-downgrade transaction, leaving a previously-admin token's `user_role` unchanged in `ldap_user_api_tokens` for up to the full `UserAPITokenDuration` (default `240h`).

### Finding Description
`FindUserByAPIToken` trusts the cached `user_role` column in `ldap_user_api_tokens` and only checks token age against `UserAPITokenDuration`, explicitly relying on the background sync to keep the role current rather than re-querying LDAP per request [4](#0-3) . That role feeds `AuthenticateByToken` and downstream `RequiresAdminRole`/`RequiresEditRole` checks in `core/web/auth/auth.go`, so a stale "admin" cached row grants real admin API access [5](#0-4) .

The only mechanism updating this cached role is the transaction inside `Work()` at the end of the sync pipeline (`sync.go:189-279`), which is reached only if: (1) the `UpstreamSyncRateLimit` window has elapsed (`sync.go:107-114`), and (2) all four `ldapGroupMembersListToUser` calls for Admin/Edit/Run/Read groups succeed (`sync.go:134-156`). Any LDAP query error (network blip, timeout, malformed response, transient LDAP server issue) on any of these calls causes an early `return` — the function exits having already run `deleteStaleAPITokens` (age-based purge only) but never having re-derived or written a downgraded role. Meanwhile `deleteStaleAPITokens` at `sync.go:100-104` runs unconditionally on every `Work()` invocation, but only removes tokens older than `UserAPITokenDuration` — it does not know about, or act on, role demotions.

Consequently, a user demoted from the Admin LDAP group upstream, but who already holds a valid, unexpired API token issued while they were Admin, keeps full Admin API privileges as long as the downgrade transaction never successfully runs — which can persist for the entire `UserAPITokenDuration` window if group queries keep failing or the rate limit keeps deferring re-sync, and errors are only logged (`l.lggr.Error`) without any fail-closed action such as suspending existing tokens.

### Impact Explanation
A demoted user (previously legitimately an Admin) retains full administrative API access — including issuing jobs, managing bridges, mutating node configuration — via their old API token for up to `UserAPITokenDuration` (default 10 days) after losing upstream Admin group membership, purely because the sync's error-handling/rate-limiting is not fail-closed for privilege downgrade. This is a privilege-escalation / stale-authorization issue with direct unauthorized privileged API access impact.

### Likelihood Explanation
Requires: (1) `UserApiTokenEnabled` on, (2) a user previously granted Admin who was issued an API token, (3) later removed from the Admin group upstream, and (4) the sync's group-query step failing or being rate-limited at the time of demotion or repeatedly thereafter. LDAP query failures (timeouts, transient connectivity issues) and the default 2-minute `UpstreamSyncRateLimit`/`0s` `UpstreamSyncInterval` (meaning background sync may not even run unless triggered) make this a realistic operational condition rather than a contrived edge case, especially in environments with occasional LDAP connectivity flakiness.

### Recommendation
Decouple the "safety" purge from age-only logic: on any error in the upstream group-membership fetch (`ldapGroupMembersListToUser`) or `validateUsersActive`, fail closed by either (a) not extending trust in existing cached roles — e.g., temporarily suspend/invalidate existing `ldap_user_api_tokens`/`ldap_sessions` entries until a successful re-sync occurs, or (b) shrinking the effective trust window for cached elevated roles independent of `UserAPITokenDuration`, and (c) ensure `deleteStaleAPITokens`/role-verification is not solely time-based for privilege-bearing rows — periodic mandatory re-verification (or a much shorter TTL for Admin-role cached tokens) should be enforced even when the rate limit gate blocks a full sync.

// FindUserByAPIToken retrieves a possible stored user and role from the ldap_user_api_tokens table store
func (l *ldapAuthenticator) FindUserByAPIToken(ctx context.Context, apiToken string) (sessions.User, error) {
	if !l.config.UserApiTokenEnabled() {
		return sessions.User{}, errors.New("API token is not enabled ")
	}

	// Query the ldap user API token table for given token, user role and email are cached so
	// no further upstream LDAP query is performed, sessions and tokens are synced against the upstream server
	// via the UpstreamSyncInterval config and reaper.go sync implementation
	var foundUserToken struct {
		UserEmail string
		UserRole  sessions.UserRole
		Valid     bool
	}
	err := l.ds.GetContext(ctx, &foundUserToken,
		"SELECT user_email, user_role, created_at + $2 >= now() as valid FROM ldap_user_api_tokens WHERE token_key = $1",
		apiToken, l.config.UserAPITokenDuration().Duration(),
	)
	if err != nil {
		return sessions.User{}, err
	}
	if !foundUserToken.Valid { // API Token expired, purge
		if _, execErr := l.ds.ExecContext(ctx, "DELETE FROM ldap_user_api_tokens WHERE token_key = $1", apiToken); execErr != nil {
			l.lggr.Errorf("error purging stale ldap API token session: %v", execErr)
		}
		return sessions.User{}, sessions.ErrUserSessionExpired
	}

	return sessions.User{
		Email: foundUserToken.UserEmail,
		Role:  foundUserToken.UserRole,
	}, nil
}

	// Purge expired ldap_sessions and ldap_user_api_tokens
	recordCreationStaleThreshold := l.config.SessionTimeout().Before(time.Now())
	err := l.deleteStaleSessions(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire local LDAP sessions: ", err)
	}
	recordCreationStaleThreshold = l.config.UserAPITokenDuration().Before(time.Now())
	err = l.deleteStaleAPITokens(ctx, recordCreationStaleThreshold)
	if err != nil {
		l.lggr.Error("unable to expire user API tokens: ", err)
	}

	// Optional rate limiting check to limit the amount of upstream LDAP server queries performed
	if !l.config.UpstreamSyncRateLimit().IsInstant() {
		if !time.Now().After(l.nextSyncTime) {
			return
		}

		// Enough time has elapsed to sync again, store the time for when next sync is allowed and begin sync
		l.nextSyncTime = time.Now().Add(l.config.UpstreamSyncRateLimit().Duration())
	}

	l.lggr.Info("Begin Upstream LDAP provider state sync after checking time against config UpstreamSyncInterval and UpstreamSyncRateLimit")

	// For each defined role/group, query for the list of group members to gather the full list of possible users

func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {

			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
}
