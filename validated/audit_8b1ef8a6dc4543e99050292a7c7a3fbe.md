### Title
Unauthenticated exposure of LOOP-plugin pprof/metrics proxy endpoints - ([File: core/web/router.go])

### Summary
`loopRoutes` is mounted directly on the top-level `api` group in `NewRouter` with no authentication middleware, unlike every other sensitive route group (`debugRoutes`, `v2Routes`, `metricRoutes`). This makes `/discovery`, `/plugins/:name/metrics`, `GET /plugins/:name/debug/pprof/*profile`, and `POST /plugins/:name/debug/pprof/symbol` reachable by any unauthenticated network client that can reach the node's web server.

### Finding Description
In `core/web/router.go`, `NewRouter` builds `api := engine.Group("/", rateLimiter(...), sessions.Sessions(...))` and then calls route registrars on it: [1](#0-0) 
`debugRoutes` wraps its own group with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`: [2](#0-1) 
`metricRoutes` (the node's own `/debug/pprof/*`) is only invoked from inside `authv2`, which requires token/session auth: [3](#0-2) 
But `loopRoutes` registers its handlers directly on `api` with no `auth.Authenticate` wrapper at all: [4](#0-3) 
As a result, `LoopRegistryServer.discoveryHandler`, `pluginMetricHandler`, `pluginPPROFHandler`, and `pluginPPROFPOSTSymbolHandler` in `core/web/loop_registry.go` are reachable by any unauthenticated client that can send HTTP requests to the node: [5](#0-4) [6](#0-5) 
These handlers proxy the request straight through to the internal LOOP plugin's pprof/metrics HTTP server (`l.loopHostName:p.EnvCfg.PrometheusPort`) and return the raw response body to the caller, including CPU/heap/goroutine/trace profiles that can contain sensitive in-memory data (addresses, potentially secret material handled by the plugin, internal state). The `seconds` query parameter is also forwarded unbounded to the profile/trace proxy, which can be used to hold connections/resources for extended periods (a lightweight DoS/resource-exhaustion vector), and this is all achievable without any credentials.

### Impact Explanation
An unprivileged, unauthenticated attacker with network access to the Chainlink node's HTTP API can enumerate registered LOOP plugins via `/discovery`, and pull `pprof` CPU/heap/goroutine/trace dumps and Prometheus metrics from any registered plugin (`/plugins/:name/debug/pprof/*`, `/plugins/:name/metrics`) with no login, API token, or role check. This is an information-disclosure vulnerability (memory/goroutine/internal-topology leakage) and a minor availability risk via unbounded profile duration, in violation of the same-server authentication model applied to every other sensitive/debug route (`/debug/vars`, `/v2/*` debug/pprof routes).

### Likelihood Explanation
High feasibility and fully repeatable: the attacker only needs network reachability to the node's configured web server port (the same port serving `/v2/*` and the operator UI) and knowledge/enumeration of a plugin name (obtainable for free via the unauthenticated `/discovery` endpoint, which lists plugin names in `LabelMetaPluginName`). No preconditions beyond "LOOP plugin mode is enabled and at least one plugin is registered," which is a standard deployment configuration for OCR2/CCIP LOOP plugins.

### Recommendation
Wrap `loopRoutes` registration with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware (and appropriate role check, e.g. `auth.RequiresAdminRole` or `RequiresEditRole`, since this exposes operational/debug data) used for `debugRoutes` and the `authv2` `metricRoutes`, instead of registering it unauthenticated on `api`. At minimum, gate the pprof/metric proxy handlers behind the same session/token authentication check performed elsewhere.

### Proof of Concept
Integration test (extending `core/web/loop_registry_test.go`):
1. Start an `app` with a registered LOOP plugin (as in `TestLoopRegistry`).
2. Instead of using `app.NewHTTPClient(nil)` (which is an authenticated test client), issue raw `http.Get` requests directly to the running node's HTTP address for:
   - `GET /discovery`
   - `GET /plugins/mockLoopImpl/metrics`
   - `GET /plugins/mockLoopImpl/debug/pprof/heap`
   - `POST /plugins/mockLoopImpl/debug/pprof/symbol`
   with **no session cookie and no `X-API-KEY`/`X-API-SECRET` headers**.
3. Assert that all four requests return `200 OK` with plugin data in the body, proving no authentication is enforced — contrast this with an equivalent raw (unauthenticated) request to `/v2/build_info` or `/debug/vars`, which should return `401 Unauthorized`, demonstrating the routing inconsistency.

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
```
