## Title
Deterministic (and Universal) accounts backed by an `AccountId`-mode global contract are not actually immutable, letting the global contract owner rewrite their code after funds are deposited - ([File: runtime/runtime/src/global_contracts.rs])

### Summary
`DeterministicStateInitAction` and `UniversalStateInitAction` let a `GlobalContractIdentifier::AccountId(owner)` be used as the "fixed code" for a deterministic/universal account. Docs explicitly promise that deterministic accounts "have a fixed code and fixed initial state associated with it" [1](#0-0) , and the account ID is derived deterministically from the `DeterministicAccountStateInit` (which only embeds the `GlobalContractIdentifier`, not a code hash, when `AccountId` mode is used) [2](#0-1) . However, when `AccountId` mode is chosen, the "fixed code" is a live pointer: the referenced account's owner can redeploy new code at any time via `DeployGlobalContractAction{deploy_mode: AccountId}`, and every account that resolved to that identifier (including already-funded deterministic/universal accounts) immediately starts executing the new code, exactly analogous to a price-oracle owner swapping the oracle right before a trade executes.

### Finding Description
`GlobalContractDeployMode::AccountId` is documented as: "Contract is deployed under the owner account id. Users will be able to reference it by that account id. This allows the owner to update the contract for all its users." [3](#0-2) 

`action_use_global_contract`/`use_global_contract` sets `AccountContract::GlobalByAccount(id)` on the referencing account rather than pinning a code hash [4](#0-3) . Resolution to actual bytecode happens dynamically at call time via `RuntimeContractIdentifier::resolve`, using whatever the global-contract account currently has deployed [5](#0-4) .

This same `use_global_contract` path is invoked when installing the code for a `DeterministicStateInitAction` (`deploy_deterministic_account` → `use_global_contract`) and a `UniversalStateInitAction` (`install_universal_account` → `use_global_contract`) whenever `code: GlobalContractIdentifier::AccountId(...)` is supplied [6](#0-5) . Validation (`validate_deterministic_state_init`) only checks that the identifier is well-formed and that the receiver ID matches the derived deterministic ID; it places no restriction that only immutable `CodeHash`-mode identifiers may be used for a "fixed code" account [7](#0-6) .

Consequently:
- A deterministic/universal account's *code* is only fixed if `CodeHash` mode is used. With `AccountId` mode it is fully mutable by a third party (the global-contract owner), even though the account ID itself was derived and verified against the *identifier* (not the code bytes).
- A user can inspect the current code of the referenced global-contract account, verify it is trustworthy, and deposit funds into (or interact with) the deterministic/universal account relying on that code. The global-contract owner can then front-run or simply wait and redeploy malicious code via `DeployGlobalContractAction{AccountId}` — a normal, unprivileged transaction reachable by anyone who deployed that global contract — and the very next `FunctionCall` receipt to any account using that identifier executes the new, attacker-controlled logic against the account's balance and storage.
- This exactly mirrors the reported bug class: a privileged party can swap out a referenced resource ("oracle"/contract code) at any time, right before a victim's transaction executes, causing the victim to lose funds to logic they never approved.

### Impact Explanation
Any deterministic or universal account (`0s...`/`0u...`) created with `code: GlobalContractIdentifier::AccountId(owner)` can have its entire behavior silently rewritten post-hoc by `owner`. Since these accounts can hold NEAR balance and arbitrary contract storage, a malicious or compromised global-contract owner can drain funds or corrupt state of every account referencing that identifier by deploying new code — a concrete unauthorized value movement reachable purely through ordinary, unprivileged `DeployGlobalContract`/`FunctionCall` transactions, contradicting the "fixed code" invariant that deterministic accounts are supposed to guarantee.

### Likelihood Explanation
No special privileges are required beyond being the account that originally deployed the `AccountId`-mode global contract. Any application relying on `AccountId` mode for a deterministic/universal account (e.g., to allow future upgrades) is exposed. Because deployment and use of global contracts by account id is a documented, supported feature, this is easy to reach: deploy a benign-looking contract, wait for users to fund derived deterministic/universal accounts against it, then redeploy malicious code.

### Recommendation
- For any account whose identity/security model depends on "fixed code" (deterministic and universal accounts), require `GlobalContractIdentifier::CodeHash` and reject `AccountId` mode in `validate_deterministic_state_init` / `UniversalStateInit` validation, or clearly document and gate `AccountId` mode behind an explicit user acknowledgment.
- Alternatively, snapshot/pin the code hash of the referenced `AccountId` contract at state-init time so later redeployments by the owner do not retroactively change already-initialized accounts.

### Proof of Concept
1. Owner deploys global contract `benign.near` (`GlobalContractDeployMode::AccountId`) containing legitimate logic [8](#0-7) .
2. A user submits `DeterministicStateInitAction`/`UniversalStateInitAction` with `code = GlobalContractIdentifier::AccountId(benign.near)`, deriving account `0s...`/`0u...`, and deposits funds into it [9](#0-8) .
3. `benign.near` owner submits a new `DeployGlobalContractAction{AccountId}` with malicious code (e.g., a "withdraw all to attacker" method) — an ordinary transaction from an unprivileged signer.
4. Any subsequent `FunctionCall` receipt to the `0s.../0u...` account resolves to the new malicious code via `RuntimeContractIdentifier::resolve` [10](#0-9)  and drains the account's funds, despite the account's ID having been derived and trusted based on the original, benign reference.

pub(crate) fn action_deploy_global_contract(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    apply_state: &ApplyState,
    deploy_contract: &DeployGlobalContractAction,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let _span = tracing::debug_span!(target: "runtime", "action_deploy_global_contract").entered();

    let storage_cost = apply_state
        .config
        .fees
        .storage_usage_config
        .global_contract_storage_amount_per_byte
        .saturating_mul(deploy_contract.code.len() as u128);
    let Some(updated_balance) = account.amount().checked_sub(storage_cost) else {
        result.result = Err(ActionErrorKind::LackBalanceForState {
            account_id: account_id.clone(),
            amount: storage_cost,
        }
        .into());
        return Ok(());
    };
    result.tokens_burnt =
        result.tokens_burnt.checked_add(storage_cost).ok_or(IntegerOverflowError)?;
    account.set_amount(updated_balance);

    initiate_distribution(
        state_update,
        account_id.clone(),
        deploy_contract.code.clone(),
        &deploy_contract.deploy_mode,
        apply_state.shard_id,
        result,
    )?;

    Ok(())
}

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };

pub(crate) fn action_universal_state_init(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    maybe_account: &mut Option<Account>,
    account_id: &AccountId,
    receipt: &Receipt,
    action: &UniversalStateInitAction,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let fees = &apply_state.config.fees;
    let storage_usage_config = &fees.storage_usage_config;

    // The account may already exist without its state: a transfer to a `0u` id
    // creates an uninitialized account. Install on the first state init and skip
    // straight to the deposit handling on a repeat, without touching the state
    // already there.
    //
    // A half-installed account can never be observed here: a failed action
    // rolls the whole state update back (see `runtime::apply_action_receipt`),
    // so an initialized account always means a completed install.
    let account = match maybe_account {
        Some(account) => account,
        // Create without changing actor_id, so a same-receipt follow-up can't hijack the account.
        None => maybe_account.insert(Account::new_uninitialized(
            Balance::ZERO,
            storage_usage_config.num_bytes_account,
            initial_nonce_value(apply_state.block_height),
        )),
    };

    if !account.is_initialized() {
        // The action carries the bytes the producer serialized; installing the
        // state needs them decoded. Every receipt is validated before its actions
        // run and validation rejects a state init that does not decode, so this
        // only fires if that invariant has been broken. Failing the action rather
        // than the chunk keeps a hypothetical gap in that coverage from becoming a
        // halt, since the payload comes from outside.
        let Ok(state_init) = UniversalStateInit::from_raw(&action.state_init) else {
            result.result = Err(ActionErrorKind::MalformedUniversalStateInit.into());
            return Ok(());
        };
        // Installed keys must start above the nonce the bootstrap consumed, or those
        // same bytes replay through the access-key path. It's practically impossible
        // for `consumed_nonce` to be bigger than `initial_nonce_value(apply_state.block_height)`,
        // but let's keep the check for the sake of complete safety.
        let consumed_nonce = account.bootstrap_nonce().unwrap_or(0);
        let access_key_nonce = max(initial_nonce_value(apply_state.block_height), consumed_nonce);
        account.initialize().or_inconsistent_state(account_id)?;
        install_universal_account(
            state_update,
            account,
            account_id,
            &state_init,
            result,
            fees,
            access_key_nonce,
        )?;
        if result.result.is_err() {
            return Ok(());
        }
    }

    settle_state_init_deposit(
        account,
        action.deposit,
        account_id,
        receipt,
        &apply_state.config,
        result,
    )
