### Title
Unchecked `Option` on `AotContractExecutor::from_path` Causes Panic in Sierra-to-Native Compilation - ([File: crates/apollo_compile_to_native/src/compiler.rs])

### Summary
`SierraToNativeCompiler::compile` calls `AotContractExecutor::from_path(...)`, which returns `Result<Option<AotContractExecutor>, ...>`. The code checks the `Result` via `.map_err(...)?` but then blindly calls `.unwrap()` on the inner `Option`, exactly the "unchecked return value" pattern described in the libtiff report (the caller inspects only one layer of the fallible/optional return and dereferences the other unconditionally). If the subprocess-based native compiler reports success (`compile_with_args` sees exit status 0) but the resulting artifact file cannot be reconstituted into an executor (missing/incompatible/empty output), `from_path` yields `Ok(None)`, and the subsequent `.unwrap()` panics.

### Finding Description [1](#0-0) 

`compile_with_args` only validates the subprocess exit status; it does not validate that the declared output artifact is well-formed: [2](#0-1) 

`SierraToNativeCompiler::compile` is invoked from `process_compilation_request` in the native class manager, which is on the path triggered whenever an account declares a Cairo 1 class and native compilation is enabled (`CairoNativeMode::WaitOnCompilation` or `LazyCompilation`): [3](#0-2) [4](#0-3) 

Crucially, the wrapping code only guards against an `Err` result from `compiler.compile(...)` (`compilation_result` match on `Ok`/`Err`, and `.unwrap_or(())` on the outer `Result<(), CompilationUtilError>`). None of this protects against a **panic** raised inside `compile()` itself — `unwrap_or` only converts `Err` to a default value, it does not catch unwinding panics. So the `.unwrap()` panic inside `compile()` is not contained by any of the call sites (`set_and_compile`, `run_compilation_worker`).

### Impact Explanation
- In `CairoNativeMode::WaitOnCompilation`, `compile()` is invoked synchronously from `set_and_compile`, which is called directly from the block-building/execution path when a class is declared. A panic here propagates up through transaction/class processing, crashing the thread (or the whole process, if compiled with `panic = "abort"`, common in production Rust services) handling that block.
- In `CairoNativeMode::LazyCompilation`, the panic occurs in the dedicated compilation worker thread (`run_compilation_worker`); if the runtime is configured with `panic = "abort"`, the entire sequencer process aborts. Even under `panic = "unwind"`, the worker thread dies permanently (no restart logic), silently disabling all future native compilation for the node, which can create state/consensus behavior divergence between nodes that have Cairo Native enabled and those that don't process such Declares.
- Because this is reachable from a single, unprivileged `Declare` transaction (an attacker only needs to submit a Sierra class that reproducibly makes the external `cairo-native` compiler binary "succeed" while writing an unusable/empty output artifact), this can be used to deny service — a network unable to confirm new transactions on affected sequencer processes, satisfying the "Medium" severity bar for this class of bug.

### Likelihood Explanation
Likelihood depends on whether cairo_native compilation is enabled in the deployment (feature/mode gated), and on being able to craft a Sierra program that makes the external native-compiler subprocess return a successful exit status while failing to produce a loadable artifact at the output path (e.g., truncated output due to a resource limit boundary condition, or an artifact format the loader rejects). This requires investigation of the `cairo_native` crate's `from_path`/build behavior to construct a concrete trigger, which could not be fully verified in this codebase (external dependency). Given the code is only reachable when `cairo_native` mode is active, likelihood is assessed as **moderate** rather than trivial.

### Recommendation
Replace the `.unwrap()` with proper error propagation:
```rust
AotContractExecutor::from_path(output_file.path())
    .map_err(|e| CompilationUtilError::CompilationError(e.to_string()))?
    .ok_or_else(|| CompilationUtilError::CompilationError(
        "Native compiler reported success but produced no loadable artifact".to_string(),
    ))
```
This converts the `None` case into a normal `Err(CompilationUtilError)`, which is already handled gracefully by `process_compilation_request` (falls back to CASM execution via `CachedCairoNative::CompilationFailed`) instead of panicking/aborting the process.

### Proof of Concept
Not independently reproducible without access to the `cairo_native` compiler binary's exact failure modes for `from_path`; the vulnerability is proven structurally by code inspection:
1. `SierraCompiler`/`NativeClassManager` accepts an unprivileged `Declare` transaction's Sierra class.
2. `SierraToNativeCompiler::compile` runs the external native compiler subprocess (`compile_with_args`), which only checks exit status, not artifact validity.
3. `AotContractExecutor::from_path(...)` is called on the declared output path; if it returns `Ok(None)` (a documented possible outcome of the `Option`-returning API), the subsequent unconditional `.unwrap()` on line 60 panics, crashing the compilation worker thread or the block-processing thread depending on `CairoNativeMode`.

```rust
fn process_compilation_request(
    class_cache: RawClassCache,
    compiler: Arc<SierraToNativeCompiler>,
    compilation_request: CompilationRequest,
    panic_on_compilation_failure: bool,
) -> Result<(), CompilationUtilError> {
    let (class_hash, sierra, casm) = compilation_request;
    if let Some(CompiledClasses::V1Native(_)) = class_cache.get(&class_hash) {
        // The contract class is already compiled to native - skip the compilation.
        return Ok(());
    }
    let sierra_for_compilation = into_contract_class_for_compilation(sierra.as_ref());
    let start = Instant::now();
    let compilation_result = compiler.compile(sierra_for_compilation);
    let duration = start.elapsed();
    log::info!(
        "Compiling to native contract with class hash: {:#066x}. Duration: {:.3} seconds",
        class_hash.0,
        duration.as_secs_f32()
    );
    match compilation_result {
        Ok(executor) => {
            let native_compiled_class = NativeCompiledClassV1::new(executor, casm);
            class_cache.set(
                class_hash,
                CompiledClasses::V1Native(CachedCairoNative::Compiled(native_compiled_class)),
            );
            log::info!("Compilation succeeded");
            Ok(())
        }
        Err(err) => {
            class_cache.set(
                class_hash,
                CompiledClasses::V1Native(CachedCairoNative::CompilationFailed(casm)),
            );
            log::error!(
                "Error compiling contract class with class hash: {:#066x}: {err}",
                class_hash.0
            );
            NATIVE_COMPILATION_ERROR.increment(1);
            if panic_on_compilation_failure {
                panic!("Compilation of class hash: {:#066x} failed", class_hash.0);
            }
            Err(err)
        }
    }
}
```
