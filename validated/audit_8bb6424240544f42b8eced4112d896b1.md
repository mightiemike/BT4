### Title
Unchecked fee-transfer call result in `execute_fee_transfer` diverges from Starknet OS's `charge_fee`, which asserts fee-transfer never reverts - ([File: crates/blockifier/src/transaction/account_transaction.rs])

### Summary
`AccountTransaction::execute_fee_transfer` (and its concurrency variant) invokes the ERC20 `transfer` entry point via `CallEntryPoint::execute` but never inspects the returned `CallInfo.execution.failed` flag. If the fee-transfer call reverts internally, the sequencer still treats the transaction as successfully fee-charged and includes it in the block, whereas the Starknet OS's equivalent `charge_fee` routine hard-asserts that the same call must not revert.

### Finding Description
`execute_fee_transfer` builds a `CallEntryPoint` for the `transfer` selector on the fee token and calls the plain `.execute(...)`, propagating only VM/state errors via `?`: [1](#0-0) 

Crucially, `CallEntryPoint::execute` goes through `execute_entry_point_call_wrapper`, which — when reverts are enabled (the default in all shipped `blockifier_versioned_constants_*.json` configs) — returns `Ok(call_info)` even when `call_info.execution.failed == true`; it only turns a failure into an `Err` when `enable_reverts` is false: [2](#0-1) 

There is a dedicated helper, `CallEntryPoint::non_reverting_execute`, that explicitly checks `call_info.execution.failed` and converts a failed/reverted inner call into an `Err(EntryPointExecutionError::ExecutionFailed)`: [3](#0-2) 

`execute_fee_transfer` does **not** use `non_reverting_execute` — it uses the plain `execute`, so a reverted/failed fee-transfer call silently becomes a "successful" `Ok(CallInfo)` with `execution.failed = true`, and `handle_fee` returns `Some(fee_transfer_call_info)` as if everything succeeded: [4](#0-3) 

This directly mirrors the external analog's root cause: an external/low-level call result whose "success" is never checked, so failure is silently swallowed and normal flow continues.

Contrast this with the Starknet OS Cairo implementation of `charge_fee`, which performs the equivalent ERC20 transfer call through `non_reverting_select_execute_entry_point_func`, a function whose name and implementation explicitly `assert is_reverted = 0` — i.e., the OS treats a reverted fee transfer as a fatal, unrecoverable condition: [5](#0-4) [6](#0-5) 

So the Rust sequencer path silently accepts a reverted fee-transfer as "handled," while the Cairo OS path (used to prove the very same block) hard-fails if that same call reverts. This is a genuine root-cause split between two components in the sequencer stack that are supposed to compute the same result.

### Impact Explanation
If a fee-transfer entry point call fails/reverts for a transaction the sequencer includes in a block (e.g., an ERC20 fee-token implementation that reverts under some edge condition, or any state condition that causes the transfer to panic), the blockifier will:
- Record a `fee_transfer_call_info` with `execution.failed = true` as part of a "successfully executed and committed" transaction, and
- Commit the associated state changes/block as valid.

When the Starknet OS later re-executes the same block to build the proof, its `charge_fee` will hit `assert is_reverted = 0` and abort, since the OS treats an unsuccessful fee transfer as an unrecoverable condition. This produces honest-node/prover divergence: a block accepted and committed by the sequencer that cannot be proven by the OS, which blocks state finalization/L1 confirmation for that block — a "network unable to confirm new transactions" scenario, and it undermines the invariant (enforced by the OS but not by the blockifier) that every transaction's actual fee is always successfully collected.

### Likelihood Explanation
The check gap is deterministic and always present (fee-transfer failure is never checked whenever `enable_reverts` is on, which is the versioned-constants default for all supported protocol versions in this repo). Triggering it requires a scenario in which the fee-token `transfer` call itself reverts (as opposed to a normal insufficient-balance validation that is expected to be pre-checked elsewhere) — for example a fee token whose `transfer` implementation can panic on some input, or a race/edge case around balance state during concurrent execution. The bug class does not require any privileged actor: it is reachable purely via ordinary transaction execution paths that any submitted transaction goes through, satisfying the "unprivileged transaction sender" reachability requirement.

### Recommendation
In `execute_fee_transfer` (and `concurrency_execute_fee_transfer`), use `CallEntryPoint::non_reverting_execute` instead of `execute`, mirroring the Starknet OS's `non_reverting_select_execute_entry_point_func` behavior, so that a reverted/failed fee-transfer call is converted into a hard `TransactionFeeError` and the transaction is rejected/reverted by the blockifier consistently with what the OS will enforce during proving.

### Proof of Concept
1. Craft or use a fee-token contract class whose `transfer` entry point can `panic`/revert under some caller-reachable condition (e.g., a custom fee token deployed via a declare+deploy flow, if the chain configuration allows a non-default fee token, or exploit an edge case in the existing ERC20 contract that causes an assertion failure during transfer, such as manipulated allowance/balance state from a prior call in the same transaction).
2. Submit an invoke transaction whose execution leaves the sender's fee-token balance/state such that the final `transfer(sequencer, actual_fee)` call made by `execute_fee_transfer` reverts.
3. Observe that `AccountTransaction::execute_raw` -> `handle_fee` -> `execute_fee_transfer` returns `Ok(CallInfo{ execution: CallExecution { failed: true, .. }, .. })` and the transaction is still included as "accepted" in `TransactionExecutionInfo` (see `execute_raw`), with the block subsequently built/committed: [7](#0-6) 

4. Feed the same block to the Starknet OS program for proving; observe the `assert is_reverted = 0` in `non_reverting_select_execute_entry_point_func` fail during `charge_fee`, aborting OS execution/proof generation for a block the sequencer already committed.

    fn execute_fee_transfer(
        state: &mut dyn State,
        tx_context: Arc<TransactionContext>,
        actual_fee: Fee,
    ) -> TransactionExecutionResult<CallInfo> {
        // The least significant 128 bits of the amount transferred.
        let lsb_amount = Felt::from(actual_fee.0);
        // The most significant 128 bits of the amount transferred.
        let msb_amount = Felt::ZERO;

        let TransactionContext { block_context, tx_info } = tx_context.as_ref();
        let storage_address = tx_context.fee_token_address();
        // The fee contains the cost of running this transfer, and the token contract is
        // well known to the sequencer, so there is no need to limit its run.
        let mut remaining_gas_for_fee_transfer =
            block_context.versioned_constants.os_constants.gas_costs.base.default_initial_gas_cost;
        let fee_transfer_call = CallEntryPoint {
            class_hash: None,
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector_from_name(constants::TRANSFER_ENTRY_POINT_NAME),
            calldata: calldata![
                *block_context.block_info.sequencer_address.0.key(), // Recipient.
                lsb_amount,
                msb_amount
            ],
            storage_address,
            caller_address: tx_info.sender_address(),
            call_type: CallType::Call,

            initial_gas: remaining_gas_for_fee_transfer,
        };
        let mut context = EntryPointExecutionContext::new_invoke(
            tx_context,
            true,
            SierraGasRevertTracker::new(GasAmount(remaining_gas_for_fee_transfer)),
        );

        Ok(fee_transfer_call
            .execute(state, &mut context, &mut remaining_gas_for_fee_transfer)
            .map_err(|error| Box::new(TransactionFeeError::ExecuteFeeTransferError(error)))?)
    }

    /// Similar to `execute`, but returns an error if the outer call is reverted.
    pub fn non_reverting_execute(
        self,
        state: &mut dyn State,
        context: &mut EntryPointExecutionContext,
        remaining_gas: &mut u64,
    ) -> EntryPointExecutionResult<CallInfo> {
        let execution_result = self.execute(state, context, remaining_gas);
        if let Ok(call_info) = &execution_result {
            // Update revert gas tracking (for completeness - value will not be used unless the tx
            // is reverted).
            context.sierra_gas_revert_tracker.update_with_next_remaining_gas(
                call_info.tracked_resource,
                GasAmount(*remaining_gas),
            );
            // If the execution of the outer call failed, revert the transction.
            if call_info.execution.failed {
                return Err(EntryPointExecutionError::ExecutionFailed {
                    error_trace: extract_trailing_cairo1_revert_trace(
                        call_info,
                        Cairo1RevertHeader::Execution,
                    ),
                }
                .annotated(
                    call_info.tracked_resource,
                    context.versioned_constants().strip_vm_frames_in_sierra_gas,
                ));
            }
        }

        execution_result
    }

// Charges a fee from the user.
// If max_fee is not 0, validates that the selector matches the entry point of an account contract
// and executes an ERC20 transfer on the behalf of that account contract.
//
// Arguments:
// block_context - a global context that is fixed throughout the block.
// tx_execution_context - The execution context of the transaction that pays the fee.
func charge_fee{
    range_check_ptr,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, tx_execution_context: ExecutionContext*) {
    alloc_locals;

    local tx_info: TxInfo* = tx_execution_context.execution_info.tx_info;
    let max_fee = compute_max_possible_fee(tx_info=tx_info);

    if (max_fee == 0) {
        return ();
    }

    local low_actual_fee;
    %{ LoadActualFee %}
    local calldata: TransferCallData = TransferCallData(
        recipient=block_context.block_info_for_execute.sequencer_address,
        amount=Uint256(low=low_actual_fee, high=0),
    );

    // Verify that the charged amount is not larger than the transaction's max_fee field.
    assert_nn_le(calldata.amount.low, max_fee);

    // TODO(ilya, 01/01/2026): Consider caching the fee_token_class_hash.
    local fee_token_address = block_context.os_global_context.starknet_os_config.fee_token_address;
    let (fee_state_entry: StateEntry*) = dict_read{dict_ptr=contract_state_changes}(
        key=fee_token_address
    );
    let (__fp__, _) = get_fp_and_pc();
    // Use block_info directly from block_context, so that charge_fee will always run in
    // execute-mode rather than validate-mode.
    local execution_context: ExecutionContext = ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=fee_state_entry.class_hash,
        calldata_size=TransferCallData.SIZE,
        calldata=&calldata,
        execution_info=new ExecutionInfo(
            block_info=block_context.block_info_for_execute,
            tx_info=tx_info,
            caller_address=tx_info.account_contract_address,
            contract_address=fee_token_address,
            selector=TRANSFER_ENTRY_POINT_SELECTOR,
        ),
        deprecated_tx_info=tx_execution_context.deprecated_tx_info,
    );

    let remaining_gas = DEFAULT_INITIAL_GAS_COST;
    non_reverting_select_execute_entry_point_func{remaining_gas=remaining_gas}(
        block_context=block_context, execution_context=&execution_context
    );
    return ();
}
