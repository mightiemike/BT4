Replay-verification / debugger replay accepts execution results with a diverging position-state root — `ensure_match_transaction_info` skips checkpoint-hash validation - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the function used by chunk-executor replay/verification, the aptos-debugger, and the CLI replay tooling to authenticate a locally re-executed `TransactionOutput` against the persisted, ledger-info-anchored `TransactionInfo`. The function checks status, gas, write-set hash, and event root hash, but — per its own inline TODO — deliberately omits comparing `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` from `TransactionInfo`. This is the direct structural analog of the `Ownable.onTransferOwnership` bug: a value that is supposed to gate acceptance (here, checkpoint-root equality) is computed/available but never checked before the caller treats replay as "matched."

### Finding Description
`ensure_match_transaction_info` at [1](#0-0)  validates only status, gas, write-set hash, and event-root hash, then returns `Ok(())` unconditionally, with an explicit acknowledgment that checkpoint hashes (state, hot-state, and `position_state_checkpoint_hash`) are not compared: [2](#0-1) 

This function is the sole comparator used by `ChunkExecutorInner::verify_execution`, the replay-verify code path that re-executes historical/backup transactions and is supposed to detect divergence from the authenticated, ledger-info-signed `TransactionInfo` (which itself is bound to the transaction accumulator root and thus to consensus/mainnet state): [3](#0-2) 

The `TransactionInfo::V1` variant carries a `position_state_checkpoint_hash` field specifically to authenticate the "trading-native" position-state root: [4](#0-3) 

and this root is computed independently during normal block commit via `DoStateCheckpoint::compute_position_checkpoint`, gated by the `compute_trading_native_state_roots` flag: [5](#0-4) 

The same `ensure_match_transaction_info` function is also invoked by the aptos-debugger and CLI replay tooling (`aptos-move/aptos-debugger/src/aptos_debugger.rs`, `aptos-move/cli/src/commands.rs`), meaning any user- or operator-facing "replay and verify" workflow reports a positive (matched) result even when the position-state checkpoint hash — an authenticated, proof-bearing commitment — diverges between the locally recomputed state and the value embedded in the trusted `TransactionInfo`.

### Impact Explanation
This breaks the "authenticated API/state-view output bound to the wrong version/root" and "hard-fork-only divergence during commit/replay/restore/proof verification" invariants called out in the task: a divergence in the position-state Merkle root (or state/hot-state checkpoint root, though those two are also independently checked by `do_state_checkpoint.rs` during live commit) between two nodes, or between backup-restored data and live re-execution, is not caught by the one function whose entire purpose is to catch exactly this kind of mismatch. Replay-verify tooling (`db-tool replay-on-archive`, debugger commands) can report a clean/successful verification even though the authenticated ledger-bound checkpoint hash for position state doesn't match what was locally computed — silently masking a consensus/state divergence bug (e.g., a hard fork in the trading-native/position-state subsystem) instead of flagging it. This directly matches the "Hard-fork-only divergence during commit, replay, restore, or proof verification" impact class in scope.

Note: this gap is currently latent/limited in blast radius, because `compute_trading_native_state_roots` is an as-yet-unreleased/gated feature (per the code's own comment: "Validate the checkpoint hashes here before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`"), and normal block-commit-time verification (`do_state_checkpoint.rs`) does perform state/hot-state checkpoint comparisons independently of this function. So today the impact is confined to the replay/debugger verification tools not catching position-state divergence, not to consensus itself accepting a bad root at commit time.

### Likelihood Explanation
Likelihood is low-to-moderate today because the affected feature (`COMPUTE_TRADING_NATIVE_STATE_ROOTS`) is not yet enabled by default, and the gap is explicitly documented as a known TODO rather than silently introduced. It is not unprivileged/mainnet-exploitable at the current time; it becomes a real integrity gap only once the trading-native/position-state feature is turned on, at which point replay-verify tooling silently loses coverage over a proof-bearing root.

### Recommendation
Extend `ensure_match_transaction_info` to compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` from `txn_info` against locally computed values (the function signature already receives enough context to be extended, or callers should pass these in), and do so before `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/hot-state checkpoint features are enabled by default, per the existing TODO.

### Proof of Concept
Not exploitable as a standalone PoC without triggering an actual position-state root divergence (e.g., a bug in position-state computation or a malicious backup snapshot with a mismatched position tree). Conceptually: construct or obtain a `TransactionInfo` (V1) whose `position_state_checkpoint_hash` does not match the position-state root that would be recomputed by local re-execution of the corresponding `WriteSet`/transaction, then run it through `ChunkExecutorInner::verify_execution` (or the debugger/CLI replay command) — `ensure_match_transaction_info` will return `Ok(())` because it never inspects `position_state_checkpoint_hash`, `state_checkpoint_hash`, or `hot_state_checkpoint_hash`, in contrast to it correctly rejecting mismatches in status, gas, write-set hash, or event root hash.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
