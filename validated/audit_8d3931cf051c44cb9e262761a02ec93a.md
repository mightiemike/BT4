I found a valid Push Chain analog. The core pattern from the Lybra report — an unprivileged actor monitoring the mempool for a pending state-changing transaction and timing their own action to piggyback on it and extract value that a slippage/safety check was supposed to protect — maps onto Push Chain's `GAS`/`GAS_AND_PAYLOAD` inbound auto-swap path, where the swap quote and the swap execution are **not atomic with quote validity binding to price at commit time in a way that resists sandwiching**, and the 5% slippage tolerance is fixed/generous and attacker-predictable.

### Title
Predictable, oversized (5%) slippage tolerance on module-driven PRC20→WPC auto-swap lets an unprivileged actor sandwich gas-abstraction deposits to extract user value - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/evm.go`)

### Summary
When Push Chain executes a `GAS` or `GAS_AND_PAYLOAD` inbound, the `uexecutor` module fetches a Uniswap-style quote via `GetSwapQuote` and then immediately performs the swap via `CallPRC20DepositAutoSwap`, bounding acceptable output with `minPCOut = quote * 95 / 100` — a hardcoded 5% slippage tolerance computed in the same block the inbound is executed [1](#0-0) . This mirrors the report's core bug class: a value-extraction window that is supposed to be protected by an economic parameter (financial-stability ratio in the original report; slippage bound here) can be fully anticipated and exploited by anyone watching pending state, because the parameter is generous, fixed, and computed adjacent to — not atomically isolated from — the manipulable price source.

### Finding Description
The inbound execution flow (`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`) is fully deterministic and driven by validator votes reaching the 2/3 threshold: once the last required `MsgVoteInbound` is submitted, execution occurs synchronously inside the same message handler [2](#0-1) . The `quote` used to compute `minPCOut` is read live from `QuoterV2.quoteExactInputSingle` against the on-chain Uniswap pool state at that moment [3](#0-2) , and the actual swap executes moments later in the same transaction context via `CallPRC20DepositAutoSwap` [4](#0-3) .

Because `MsgVoteInbound` transactions are gasless and broadcast by every Universal Validator (whitelisted in `IsGaslessTx`) [5](#0-4) , the pending vote that will trigger execution — and the resulting swap of a known PRC20 amount for WPC — is visible in the mempool before it lands. An unprivileged actor (anyone with a funded EVM account on Push Chain, not a UV) can observe the pending inbound-completing vote, predict that a swap of `inbound.Amount` of a specific PRC20 against WPC is about to execute with a **5% slippage tolerance** (`minPCOut = quote*95/100`, identical formula in both `execute_inbound_gas.go:142-145` and `execute_inbound_gas_and_payload.go:374-376`), and sandwich it: push the pool price down before the module's swap executes (extracting up to the full 5% band as MEV) and revert the price afterward, or simply front-run/back-run for arbitrage profit. The victim depositor's synthetic PC output is systematically reduced toward the worst-case bound the module will still accept, with the difference captured by the attacker — a direct value-drain of protocol/user-controlled funds during a canonical UniversalTx state transition (`FUNDS`/`GAS`/`GAS_AND_PAYLOAD` deposit-with-autoswap), not merely a slippage inconvenience.

This is architecturally analogous to the reported Lybra bug: both cases have (1) a public mempool signal revealing an imminent beneficial/state-changing transaction, (2) a fixed tolerance/ratio meant to bound acceptable outcomes, and (3) no randomization, commit-reveal, or TWAP-based defense, allowing the tolerance itself to be treated as the attacker's guaranteed extractable profit ceiling rather than a safety margin.

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound that routes through the auto-swap path is exposed. Since inbound amounts and asset addresses are visible in `Inbound.amount`/`Inbound.asset_addr` on the finalizing `MsgVoteInbound`, and the destination pool (`UniversalCore`'s configured Uniswap pool for that PRC20/WPC pair) is public and thinly liquid relative to individual deposits, an attacker can reliably extract value up to the 5% band on every such deposit, corrupting the intended net PC balance credited to the user's UEA (a canonical UniversalTx state value) without ever touching a UV key or governance path — squarely an unprivileged, user-reachable impact on protocol/user-controlled fund accounting.

### Likelihood Explanation
High. `MsgVoteInbound` transactions are visible pre-confirmation, the swap parameters are deterministic from the inbound's `amount`/`asset_addr`, the slippage formula is fixed and public in source, and sandwiching against an on-chain DEX quote is a well-known, cheap, automatable MEV pattern requiring no privileged role — matching the "likely to be exploited by many actors" characterization in the original report.

### Recommendation
- Replace the fixed 5% `minPCOut` heuristic with a tighter, dynamically-computed bound derived from a manipulation-resistant price source (e.g., TWAP over multiple blocks) rather than a single spot `quoteExactInputSingle` call taken immediately before the swap.
- Consider batching/aggregating auto-swaps or routing through a private/relayed execution path so pending swap parameters are not fully predictable from the public mempool.
- Add a configurable, generally much smaller slippage parameter (governance-tunable) and monitor realized-vs-quoted output to detect systematic sandwich extraction.
- Evaluate whether `CallPRC20DepositAutoSwap`'s deadline (`big.NewInt(0)`, i.e., "use contract default") combined with the wide slippage band should be tightened together, since a permissive deadline further widens the attacker's window.

### Proof of Concept
1. Attacker monitors the Push Chain mempool/gasless-tx stream for `MsgVoteInbound` messages of `TxType_GAS` or `TxType_GAS_AND_PAYLOAD` that will supply the final vote needed to cross the 2/3 threshold (visible because the ballot's current vote count and threshold are queryable, and vote messages carry the full `Inbound` payload including `amount` and `asset_addr`).
2. Knowing `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap` will fetch a fresh quote and execute `depositPRC20WithAutoSwap` with `minPCOut = quote*95/100` immediately upon finalization [6](#0-5) , the attacker submits a large sell of the same PRC20 into the WPC pool just before the finalizing vote lands, depressing price.
3. The finalizing `MsgVoteInbound` executes; the module's swap receives an output near the depressed `minPCOut` floor, crediting the victim's UEA with less PC than the pre-manipulation quote implied.
4. The attacker submits a reverse trade immediately after, restoring the pool price and realizing the price-impact difference as profit, extracted from the value that should have accrued to the depositing user's UEA balance.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// IsGaslessTx checks if a transaction contains only allowed gasless message types
// Returns true if all messages in the transaction are in the allowed gasless message types
func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
