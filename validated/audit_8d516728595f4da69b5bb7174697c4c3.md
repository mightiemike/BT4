## Analysis: Sandwichable spot-price quote in gas-abstraction PRC20 auto-swap

The external report's core issue — swaps executed without genuine slippage protection, letting an attacker manipulate the price right before execution — has a concrete analog in Push Chain's gas-abstraction swap path used for `GAS` and `GAS_AND_PAYLOAD` inbound routes.

### Title
Hardcoded 5% slippage computed from a manipulable spot-price quote enables sandwich attacks on gas-abstraction deposit auto-swaps - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
For `GAS` and `GAS_AND_PAYLOAD` inbound routes, and for refunding unused relayer gas on outbound completion, the executor keeper deposits a PRC20 and auto-swaps it into native PC via a Uniswap V3-style pool. The "slippage protection" is computed as `minPCOut = quote * 95 / 100` where `quote` comes from `GetSwapQuote`, which calls `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96 = 0` against the pool's live spot price at the exact block the swap executes [1](#0-0) . Because the quote is derived from the pool's instantaneous state rather than a TWAP or a genuinely user-committed minimum, an attacker who can get a transaction included immediately before the swap in the same block can move the pool price, causing `minPCOut` itself to be computed from an already-degraded price.

### Finding Description
`ExecuteInboundGas` fetches a swap quote and computes `minPCOut` right before calling `CallPRC20DepositAutoSwap`, all within the same keeper call that finalizes inbound-vote execution: [2](#0-1) 

The same pattern is repeated for `GAS_AND_PAYLOAD` in `gasAndPayloadDepositAutoSwap` [3](#0-2)  and for excess-gas refunds in `applyGasRefund` [4](#0-3) .

`GetSwapQuote` performs a read-only `CallEVM` to `QuoterV2.quoteExactInputSingle`, which simulates the swap against the pool's *current* reserves/price at call time — it is not a TWAP oracle and has no protection against transient price manipulation: [5](#0-4) . `CallPRC20DepositAutoSwap` also passes `deadline = 0` ("contract uses its default"), removing any staleness protection as well: [6](#0-5) .

The upgrade notes confirm this design was deliberately introduced to replace a prior 0-slippage call, explicitly citing the same bug class as the external report: [7](#0-6) .

Because vote finalization (`MsgVoteInbound` reaching quorum) is a normal, unprivileged, publicly observable transaction, an unprivileged attacker can:
1. Watch the mempool/chain for the inbound vote transaction that will trigger `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` for a large deposit amount.
2. Submit (with higher priority/gas) a swap against the same PRC20/WPC Uniswap V3 pool immediately before that vote lands in the block, pushing the spot price down.
3. The module's `GetSwapQuote` call then returns a quote computed from the now-manipulated price; `minPCOut = quote * 0.95` is only a 5% band around this already-bad price, not around the pre-manipulation fair price.
4. `CallPRC20DepositAutoSwap` executes at (or above) `minPCOut`, so the deposited PRC20 is swapped for far less PC than fair value, and the difference accrues to the attacker's LP/arbitrage position, which the attacker then unwinds (backrun) to realize the profit.

This directly maps the external report's "attacker manipulates price around the victim's on-chain trade because the victim's slippage bound is derived from — rather than independent of — the manipulable price" pattern onto a protocol-initiated (not user-initiated) swap. Unlike a typical DEX front-end where the user could set their own `minPCOut` off-chain, here the "user" (the inbound depositor from the external chain) has no way to specify a real minimum: the value is entirely computed on-chain, atomically, from a spot price the attacker directly controls.

### Impact Explanation
An unprivileged attacker can extract value from every gas-abstraction deposit auto-swap (and from unused-gas refund swaps) beyond the nominal 5% tolerance by manipulating the underlying pool's spot price in the same block, directly reducing the PC amount credited to depositors/UEAs and effectively draining value from users going through the `GAS`/`GAS_AND_PAYLOAD` inbound routes or from refund recipients. This corrupts PRC20/native asset accounting and gas-refund accounting invariants (Registry and accounting path) and constitutes unauthorized value extraction from ordinary user deposit flows (Universal execution path), matching the "corruption of ... gas fee accounting, refund accounting" and "stealing ... funds" allowed-impact categories.

### Likelihood Explanation
Likelihood depends on the liquidity depth of the specific PRC20/WPC pool and the attacker's capital, but the trigger conditions (observing a pending `MsgVoteInbound` and front-running it in the same block) are fully within reach of an ordinary, unprivileged actor and require no validator, relayer, or admin collusion. Shallow-liquidity PRC20 pools (newly listed tokens) would be especially exposed, and the impact scales with deposit size.

### Recommendation
Do not derive `minPCOut` solely from a spot-price quote fetched immediately before the swap. Consider: (1) using a time-weighted average price (TWAP) oracle observed over a window prior to the triggering event rather than the instantaneous `quoteExactInputSingle` result; (2) widening protections with circuit breakers/maximum price-impact checks independent of the just-fetched quote; (3) setting a real deadline instead of `0`; (4) capping per-block swap size or requiring the swap amount to be below a fraction of pool liquidity to bound worst-case manipulation.

### Proof of Concept
1. Attacker identifies a pending large `GAS`/`GAS_AND_PAYLOAD` inbound whose vote is one confirmation from quorum (publicly observable, e.g., via `QueryUniversalTx`/mempool).
2. Attacker submits a large swap PRC20↔WPC on the pool referenced by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress` with a higher gas price, ensuring it lands in the block immediately before the finalizing `MsgVoteInbound`.
3. When the final vote lands, `ExecuteInboundGas` → `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) computes `quote` from the now-manipulated pool state; `minPCOut = quote*95/100` (`x/uexecutor/keeper/execute_inbound_gas.go:142-146`).
4. `CallPRC20DepositAutoSwap` executes and succeeds even though the depositor receives materially less PC than the pre-manipulation fair value.
5. Attacker reverses their initial swap in a following transaction, capturing the price difference as profit, financed by the reduced value delivered to the depositor/UEA.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
