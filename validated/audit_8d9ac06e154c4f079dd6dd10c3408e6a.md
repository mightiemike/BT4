### Title
`FreezeBalanceV2Processor`/`UnfreezeBalanceV2Processor` bypass the `supportUnfreezeDelay` governance gate that transaction-level actuators enforce - (File: `actuator/src/main/java/org/tron/core/vm/nativecontract/FreezeBalanceV2Processor.java`, `actuator/src/main/java/org/tron/core/vm/nativecontract/UnfreezeBalanceV2Processor.java`)

### Summary
`FreezeBalanceV2Contract`/`UnfreezeBalanceV2Contract` transactions, when submitted through the normal actuator pipeline, are only permitted once the committee enables the FreezeV2 feature via `supportUnfreezeDelay()`. However, the same freeze/unfreeze logic is also reachable from TVM smart contracts via the `freezeBalanceV2`/`unfreezeBalanceV2` opcodes, which delegate to `FreezeBalanceV2Processor`/`UnfreezeBalanceV2Processor`. These processors never check `supportUnfreezeDelay()`, so a smart contract can perform FreezeV2/UnfreezeV2 state mutations even when the committee has not enabled the feature — mirroring the `PSM._redeem()` pattern where an internal path bypasses checks enforced only at the "normal" entry point.

### Finding Description
`FreezeBalanceV2Actuator.validate()` explicitly gates the feature: [1](#0-0) 

`UnfreezeBalanceV2Actuator.validate()` enforces the analogous check: [2](#0-1) 

These are the only entry points a normal user has to freeze/unfreeze v2 balances via ordinary transactions, and both require `dynamicStore.supportUnfreezeDelay()` to be `true` (a chain parameter that must be activated by committee proposal) before any state change occurs.

However, `Program.freezeBalanceV2()` and `Program.unfreezeBalanceV2()` — invoked by the TVM `freezeBalanceV2`/`unfreezeBalanceV2` opcodes from within a smart contract — call `FreezeBalanceV2Processor`/`UnfreezeBalanceV2Processor` directly: [3](#0-2) [4](#0-3) 

`FreezeBalanceV2Processor.validate()` checks address validity, account existence, and frozen-balance bounds, but never checks `supportUnfreezeDelay()`: [5](#0-4) 

`UnfreezeBalanceV2Processor.validate()` similarly omits the check while validating unfreezing counts and frozen balances: [6](#0-5) 

This is structurally identical to the reported bug class: a shared internal execution routine (`PSM._redeem()` / `FreezeBalanceV2Processor`+`UnfreezeBalanceV2Processor`) is reachable from multiple entry points, but the governance/feature-gate check (`yzUSD` pause+redeem-restriction / `supportUnfreezeDelay`) is enforced only at one entry point (`PSM.redeem()`+`yzUSD.maxRedeem()` / the user-facing `*Actuator.validate()`), not inside the shared logic itself.

### Impact Explanation
If a smart contract invokes the `freezeBalanceV2`/`unfreezeBalanceV2` opcodes before the committee activates `supportUnfreezeDelay`, it can mutate `FrozenV2`/`UnfrozenV2` account state, total resource weights (`addTotalNetWeight`/`addTotalEnergyWeight`/`addTotalTronPowerWeight`), and votes — state transitions that the network intentionally disallows until the FreezeV2 feature is turned on. This can desynchronize on-chain resource accounting from the expected feature-gated behavior and create inconsistent frozen-balance/vote state relative to what the rest of the protocol (e.g. `BandwidthProcessor`, `EnergyProcessor`, vote tallying) assumes is only possible post-activation. Since the actuator and processor share the same underlying account fields, this is a state/accounting integrity concern rather than a purely cosmetic one.

### Likelihood Explanation
Exploitability depends on TVM opcode availability: these opcodes are further gated by `VMConfig.allowTvmFreezeV2()`, a separate hard-fork/opcode-activation flag. If that flag is enabled network-wide (opcode compiled in) while `supportUnfreezeDelay` (the FreezeV2 feature parameter) has not yet been separately voted on by the committee, any contract can trigger this bypass with no special privileges — making likelihood dependent on the exact rollout sequencing of these two independently-controlled flags, which I was not able to fully confirm from the available code (i.e., whether in practice `allowTvmFreezeV2` and `supportUnfreezeDelay` are always toggled together at genesis/hard-fork or can diverge in timing).

### Recommendation
Add an explicit `dynamicStore.supportUnfreezeDelay()` check inside `FreezeBalanceV2Processor.validate()` and `UnfreezeBalanceV2Processor.validate()` (and any other native-contract processor reachable from TVM) so the governance gate is enforced consistently regardless of entry point, matching the checks already present in `FreezeBalanceV2Actuator`/`UnfreezeBalanceV2Actuator`.

### Proof of Concept
1. Deploy chain/testnet configuration where `VMConfig.allowTvmFreezeV2()` is enabled (opcode active) but the dynamic property backing `supportUnfreezeDelay()` has not yet been set to enable the feature.
2. Deploy a smart contract that calls the `freezeBalanceV2`/`unfreezeBalanceV2` TVM opcodes (reaching `Program.freezeBalanceV2()`/`Program.unfreezeBalanceV2()`).
3. Submit a normal `FreezeBalanceV2Contract`/`UnfreezeBalanceV2Contract` transaction directly — observe it is rejected with `"Not support FreezeV2 transaction, need to be opened by the committee"` from `FreezeBalanceV2Actuator.validate()`.
4. Trigger the same operation via the smart contract opcode path — observe it succeeds and mutates account frozen/unfrozen state and total resource weights despite the feature not being enabled at the transaction-actuator level, confirming the bypass.

  public boolean freezeBalanceV2(DataWord frozenBalance, DataWord resourceType) {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, owner,
        frozenBalance.longValue(), null,
        "freezeBalanceV2For" + convertResourceToString(resourceType), nonce, null);

    try {
      FreezeBalanceV2Param param = new FreezeBalanceV2Param();
      param.setOwnerAddress(owner);
      param.setResourceType(parseResourceCodeV2(resourceType));
      param.setFrozenBalance(frozenBalance.sValue().longValueExact());

      FreezeBalanceV2Processor processor = new FreezeBalanceV2Processor();
      processor.validate(param, repository);
      processor.execute(param, repository);
      repository.commit();
      return true;
    } catch (ContractValidateException e) {
      logger.warn("TVM FreezeBalanceV2: validate failure. Reason: {}", e.getMessage());
    } catch (ArithmeticException e) {
      logger.warn("TVM FreezeBalanceV2: frozenBalance out of long range.");
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return false;
  }

  public void validate(FreezeBalanceV2Param param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    byte[] ownerAddress = param.getOwnerAddress();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid address");
    }
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    if (ownerCapsule == null) {
      String readableOwnerAddress = StringUtil.createReadableString(ownerAddress);
      throw new ContractValidateException(
          ACCOUNT_EXCEPTION_STR + readableOwnerAddress + "] does not exist");
    }
    long frozenBalance = param.getFrozenBalance();
    if (frozenBalance <= 0) {
      throw new ContractValidateException("FrozenBalance must be positive");
    } else if (frozenBalance < TRX_PRECISION) {
      throw new ContractValidateException("FrozenBalance must be greater than or equal to 1 TRX");
    } else if (frozenBalance > ownerCapsule.getBalance()) {
      throw new ContractValidateException(
          "FrozenBalance must be less than or equal to accountBalance");
    }

    // validate arg @resourceType
    switch (param.getResourceType()) {
      case BANDWIDTH:
      case ENERGY:
        break;
      case TRON_POWER:
        if (!repo.getDynamicPropertiesStore().supportAllowNewResourceModel()) {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
        break;
      default:
        if (repo.getDynamicPropertiesStore().supportAllowNewResourceModel()) {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY、TRON_POWER]");
        } else {
          throw new ContractValidateException(
              "Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
    }
  }

  public void validate(UnfreezeBalanceV2Param param, Repository repo)
      throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    byte[] ownerAddress = param.getOwnerAddress();
    DynamicPropertiesStore dynamicStore = repo.getDynamicPropertiesStore();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid address");
    }
    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    if (accountCapsule == null) {
      String readableOwnerAddress = StringUtil.createReadableString(ownerAddress);
      throw new ContractValidateException(
          ACCOUNT_EXCEPTION_STR + readableOwnerAddress + "] does not exist");
    }
    long now = dynamicStore.getLatestBlockHeaderTimestamp();
    int unfreezingCount = accountCapsule.getUnfreezingV2Count(now);
    if (UnfreezeBalanceV2Actuator.getUNFREEZE_MAX_TIMES() <= unfreezingCount) {
      throw new ContractValidateException("Invalid unfreeze operation, unfreezing times is over limit");
    }
    switch (param.getResourceType()) {
      case BANDWIDTH:
        // validate frozen balance
        if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.BANDWIDTH)) {
          throw new ContractValidateException("no frozenBalance(BANDWIDTH)");
        }
        break;
      case ENERGY:
        // validate frozen balance
        if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.ENERGY)) {
          throw new ContractValidateException("no frozenBalance(ENERGY)");
        }
        break;
      case TRON_POWER:
        if (dynamicStore.supportAllowNewResourceModel()) {
          if (!this.checkExistFrozenBalance(accountCapsule, Common.ResourceCode.TRON_POWER)) {
            throw new ContractValidateException("no frozenBalance(TRON_POWER)");
          }
        } else {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
        break;
      default:
        if (dynamicStore.supportAllowNewResourceModel()) {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY、TRON_POWER]");
        } else {
          throw new ContractValidateException("Unknown ResourceCode, valid ResourceCode[BANDWIDTH、ENERGY]");
        }
    }

    if (!checkUnfreezeBalance(accountCapsule, param.getUnfreezeBalance(), param.getResourceType())) {
      throw new ContractValidateException(
          "Invalid unfreeze_balance, [" + param.getUnfreezeBalance() + "] is invalid");
    }
  }
