### Title
Stale Global Contract-Class Cache Skips Re-Declaration Check for Cairo0 Classes, Allowing Execution of Undeclared/Reverted Classes - ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` serves compiled classes from a process-wide, cross-block LRU cache (`ContractClassManager`/`GlobalContractCache`) rather than re-checking the authoritative state on every access — mirroring the reported bug class where cached/embedded data is trusted without re-validating current backing state. For Cairo1 classes the code explicitly re-validates against the state reader before trusting the cache hit, but for Cairo0 (`RunnableCompiledClass::V0`) classes this re-validation is skipped entirely.

### Finding Description
`get_compiled_from_class_manager` looks up `class_hash` in the shared `contract_class_manager` cache: [1](#0-0) 

For any non-V0 (Cairo1) cached class, the code re-fetches authoritative declaration status via `self.state_reader.is_declared(class_hash)` and rejects the class with `StateError::UndeclaredClassHash` if the state no longer considers it declared — explicitly citing the scenario "it might contain a declared class from a reverted block." For `RunnableCompiledClass::V0(_)` (Cairo0 classes), this branch is a no-op (`{}`), so a cache hit is trusted unconditionally and returned without ever asking the state reader whether the class is currently declared.

The `contract_class_manager`'s underlying `GlobalContractCache` is a long-lived, `Arc<Mutex<..>>`-backed LRU cache shared across the entire sequencer process and across all blocks (see `crates/starknet_api/src/class_cache.rs` and `crates/blockifier/src/state/native_class_manager.rs`), not scoped to a single block's `CachedState`. This is analogous to the JWT report's core defect: data that was valid at caching time (the compiled class object) is handed back to callers as ground truth without re-checking the current, authoritative record (declared-classes state) — exactly as the JWT `CheckToken` trusted `claims.Account` without re-fetching from the DB. [2](#0-1) 

### Impact Explanation
If a Cairo0 class hash is ever cached (e.g., via a successful `get_compiled_class` lookup during speculative/validate execution, a reverted block, or execution of a transaction whose containing block is later reorganized/not included), any subsequent transaction referencing that class hash — even in a later block where the class was never actually declared in the canonical state, or where the declaring block was reverted — will have its class execution logic served from the stale cache instead of being rejected with `UndeclaredClassHash`. This can let an unprivileged transaction sender invoke functionality of a supposedly-undeclared Cairo0 class, causing execution using code the current state does not recognize as declared. Depending on how deploy/class-hash validation elsewhere composes with this gap, this can lead to accepting transactions the honest state should reject, risking node/state divergence (a node that never populated its cache for that hash would legitimately raise `UndeclaredClassHash`, while a node that had it cached would proceed) — i.e., honest-node execution divergence for the same block, which is exactly the class of impact this scan is meant to flag (wrong committed state / honest-node divergence).

### Likelihood Explanation
Reachability requires only that a Cairo0 class hash was cached at some point (a normal side effect of validation, reverted blocks, or view calls sharing the same class cache per `StorageViewStateReaderFactory`) and that its declared status subsequently changes or was never truly finalized in canonical state — both realistic operational conditions in a sequencer that reverts/re-executes blocks and shares this cache across view calls and block production. No special privilege is needed: any account/contract deployer or transaction sender referencing a previously-cached Cairo0 class hash can trigger the code path.

### Recommendation
Apply the same re-validation the Cairo1 branch already performs to Cairo0 classes: extend `FetchCompiledClasses::is_declared` (or add an equivalent check) so Cairo0 declaration status can also be authoritatively re-verified on cache hits, and remove the empty `RunnableCompiledClass::V0(_) => {}` no-op branch in `get_compiled_from_class_manager`, replacing it with a genuine re-check against `self.state_reader` before trusting the cached class.

### Proof of Concept
Not independently reproducible from static analysis alone — this requires exercising a scenario where a Cairo0 class becomes cached via `set_and_compile`/`get_runnable` in `contract_class_manager` and its containing declaring block is later reverted or otherwise removed from canonical state, then issuing a transaction referencing that class hash to observe that `get_compiled_from_class_manager` returns the stale cached class instead of `StateError::UndeclaredClassHash`. I was unable to fully confirm from the index whether `apollo_state_reader/src/apollo_state.rs`'s `is_declared` implementation treats Cairo0 differently in a way that closes this gap elsewhere in the pipeline (the file's `is_declared` body content was not available in my search results) — a Devin session with full repository access should trace `apollo_state.rs::is_declared` and the block-revert/class-manager lifecycle to confirm whether any other layer already guards against this before treating this as fully exploitable in production.

    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }

#[derive(Clone, Debug)]
pub struct GlobalContractCache<T: Clone>(pub Arc<Mutex<ContractLRUCache<T>>>);

impl<T: Clone> GlobalContractCache<T> {
    /// Locks the cache for atomic access. Although conceptually shared, writing to this cache is
    /// only possible for one writer at a time.
    pub fn lock(&self) -> LockedClassCache<'_, T> {
        self.0.lock().expect("Global contract cache is poisoned.")
    }

    pub fn get(&self, class_hash: &ClassHash) -> Option<T> {
        self.lock().cache_get(class_hash).cloned()
    }

    pub fn set(&self, class_hash: ClassHash, contract_class: T) {
        self.lock().cache_set(class_hash, contract_class);
    }

    pub fn clear(&mut self) {
        self.lock().cache_clear();
    }

    pub fn new(cache_size: usize) -> Self {
        Self(Arc::new(Mutex::new(ContractLRUCache::<T>::with_size(cache_size))))
    }
