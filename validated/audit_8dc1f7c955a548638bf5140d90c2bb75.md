### Title
Unbounded permanent disk consumption via unauthenticated Sierra class writes in Gateway declare flow before fee/signature validation - (File: crates/apollo_transaction_converter/src/transaction_converter.rs)

### Summary
The Gateway permanently persists a declared Sierra class (compiled to CASM and written to disk via `FsClassStorage`) *before* the declare transaction is stateful-validated (signature, nonce, balance/fee). Any sender can submit a stream of syntactically-valid but stateful-invalid (or never-mempool-admitted) declare transactions, each carrying a unique Sierra program, and force the node to compile and durably write each one to disk. There is no mechanism found in the Class Manager storage layer to delete or garbage-collect classes that were written but whose owning declare transaction never got committed to a block. This mirrors GHSA-h737-q6g6-8wr6 (Glance): a resource-creating request is admitted and durably persisted before the higher-level entity (image upload / declare tx) is guaranteed to complete or be authorized, and the created resource is never reclaimed if that entity is abandoned/rejected — leading to disk-consumption DoS.

### Finding Description
The transaction submission flow (see `docs/diagrams/02-tx-submission-flow.md`) shows that `GW->>CM: add_class(SierraContractClass)` happens immediately after stateless (format-only) validation, and *before* the stateful validation stage that checks nonce/balance/signature.

Concretely, in `apollo_gateway::gateway::GenericGateway::add_tx_inner` (`crates/apollo_gateway/src/gateway.rs:214-266`):
1. `self.stateless_tx_validator.validate(&tx)` — checks only format/resource-bounds/size, not signature or balance. [1](#0-0) 
2. `self.convert_rpc_tx_to_internal_and_executable_txs(tx, ...)` is called, which internally calls `TransactionConverter::convert_rpc_tx_to_internal`, which for `RpcTransaction::Declare` unconditionally calls `self.class_manager_client.add_class(tx.contract_class).await?` — compiling Sierra→CASM and writing it to persistent storage. [2](#0-1) 
3. Only *after* this conversion (and thus after the class is already durably persisted) does `stateful_transaction_validator.extract_state_nonce_and_run_validations(...)` run, which is where signature validity, account nonce, and balance/fee are actually checked. [3](#0-2) 

`ClassManager::add_class` (`crates/apollo_class_manager/src/class_manager.rs:70-113`) computes the class hash, compiles it, and calls `self.classes.set_class(...)`, which for a new class writes it to disk unconditionally. [4](#0-3) 

The actual disk write is `FsClassStorage::set_class` → `write_class_atomically` → `rename_to_persistent_dir`, which places the Sierra + CASM files into a permanent, content-addressed directory on disk (`crates/apollo_class_manager/src/class_storage.rs:451-522`). [5](#0-4) 

No deletion, expiry, or garbage-collection path for classes exists in the `apollo_class_manager` crate (a `grep` for delete/remove/expire/gc/ttl/cleanup in that crate returned no matches). Once written, a class's files remain on disk forever regardless of whether:
- The declare tx subsequently fails stateful validation (bad signature, insufficient balance, wrong nonce) and is never admitted to the mempool,
- The tx is admitted but later evicted from the mempool (capacity eviction, TTL expiry, fee-escalation replacement) and never included in a block,
- The tx is a `p2p` gossiped-but-fabricated declare that similarly triggers `add_class` on every receiving node (`apollo_p2p_sync` and mempool p2p also call `class_manager_client.add_class`).

Because each unique Sierra program produces a unique `ClassHash` (content-addressed), an attacker can trivially generate unlimited distinct classes (e.g. by varying trailing/no-op felts in the Sierra bytecode) and have each one durably written to disk with **zero cost**, since fee/balance is checked only after the write, and a failed/rejected declare costs the attacker nothing (no fee is charged unless the tx is actually included and executed).

The gateway does bound *concurrent* compilations (`declare_compilation_semaphore`, default 40) and per-tx class size (`stateless_tx_validator.validate_class_length`), which throttles throughput but does not prevent unbounded, permanent accumulation over time — analogous to how the Glance bug didn't require unlimited concurrency, just repeated create+abandon cycles to keep growing disk usage.

### Impact Explanation
This is a High-severity denial-of-service: sustained, low-cost submission of declare transactions that never get committed can permanently fill the sequencer's/class-manager's disk (and, via P2P propagation and central sync `add_class` calls on peers/nodes syncing declares, potentially disks of other nodes running a Class Manager). Once disk space is exhausted, the node can no longer accept new declares (and potentially any transaction/service that shares that filesystem, e.g. mempool/storage), leading to a Starknet node/service becoming unable to confirm new transactions — matching the "network unable to confirm new transactions" acceptance criterion. This is reachable directly by any unprivileged transaction sender/declarer without needing to control fees, signatures, or block inclusion.

### Likelihood Explanation
High likelihood: the attack requires only crafting distinct valid-format Sierra programs (passing `stateless_tx_validator.validate_declare_tx` — sierra version, entry-point ordering, length limits) and submitting them via the public gateway `add_transaction` RPC. No valid account, signature, or balance is required to trigger the disk write, since those checks happen downstream of `add_class`. The 40-concurrent-compilation cap only throttles compilation rate, not the number of already-committed writes to disk; an attacker with modest bandwidth can sustain writes indefinitely.

### Recommendation
- Defer `class_manager_client.add_class` (the actual compile-and-persist step) until after stateful validation (signature, nonce, fee/balance) has succeeded for the declare transaction, or make the persisted write reversible/garbage-collectible on validation failure or mempool eviction/expiry.
- Alternatively, use a separate short-lived staging area for classes pending mempool admission, and only promote to permanent `FsClassStorage` once the declare transaction is confirmed committed in a block (or at least admitted and not evicted after some grace period), with a reaper that deletes staged classes whose owning tx never reaches this state.
- Add disk-usage/backpressure limits (quota) to `FsClassStorage`/`ClassManager` independent of per-request checks, and metrics/alerts on persisted-but-uncommitted class counts.
- Require proof of fee-payment capability (e.g., a lightweight balance/nonce pre-check) before compiling/persisting the class, not merely stateless format validation.

### Proof of Concept
1. Generate N syntactically valid Sierra `ContractClass` payloads, each differing minimally (e.g., appended distinct no-op felt) so each has a unique `ClassHash`, sized near the maximum permitted class length.
2. For each payload, submit an RPC `Declare` V3 transaction to the gateway's `add_transaction` endpoint with an arbitrary/fabricated signature and a sender address for a non-existent or under-funded account (only format-level `StatelessTransactionValidator::validate` needs to pass — no valid signature or balance is required at this stage; see `crates/apollo_gateway/src/gateway.rs:235-254` and `crates/apollo_transaction_converter/src/transaction_converter.rs:347-360`).
3. Observe that `ClassManager::add_class` compiles and persists the Sierra+CASM to `FsClassStorage` under a permanent, content-addressed directory (`crates/apollo_class_manager/src/class_storage.rs:451-522`) even though the subsequent stateful validation step (run seconds later, `crates/apollo_gateway/src/gateway.rs:263-266`) rejects the transaction for bad signature/insufficient balance and it is never sent to (or evicted from) the mempool.
4. Repeat at the rate allowed by `max_concurrent_declare_compilations` (default 40 concurrent) indefinitely; disk usage under the class-manager persistent root grows monotonically with no corresponding cleanup mechanism, since no delete/expire/gc code path exists in `apollo_class_manager`.

    #[instrument(skip(self, class), ret, err)]
    pub async fn add_class(&mut self, class: RawClass) -> ClassManagerResult<ClassHashes> {
        let sierra_class = SierraContractClass::try_from(&class)?;
        let class_hash = sierra_class.calculate_class_hash();
        if let Ok(Some(executable_class_hash_v2)) =
            self.classes.get_executable_class_hash_v2(class_hash)
        {
            // Class already exists.
            return Ok(ClassHashes { class_hash, executable_class_hash_v2 });
        }

        let compilation_start_time = Instant::now();
        let (raw_executable_class, executable_class_hash_v2) =
            self.compiler.compile(class.clone()).await.map_err(|err| match err {
                SierraCompilerClientError::SierraCompilerError(error) => {
                    ClassManagerError::SierraCompiler { class_hash, error }
                }
                SierraCompilerClientError::ClientError(error) => {
                    ClassManagerError::Client(error.to_string())
                }
            })?;
        debug!(
            %class_hash,
            compiled_class_hash = %executable_class_hash_v2,
            compilation_elapsed_ms = compilation_start_time.elapsed().as_millis(),
            class_size_bytes =
                class.size().map_or("Failed to get class size".to_owned(), |size| size.to_string()),
            casm_size_bytes =
                raw_executable_class.size().map_or("Failed to get casm size".to_owned(), |size| size.to_string()),
            "Finished compiling class."
        );

        self.validate_class_length(&raw_executable_class)?;
        Self::validate_class_version(&sierra_class)?;
        self.classes.set_class(
            class_hash,
            class,
            executable_class_hash_v2,
            raw_executable_class,
        )?;

        let class_hashes = ClassHashes { class_hash, executable_class_hash_v2 };
        Ok(class_hashes)
    }

impl ClassStorage for FsClassStorage {
    type Error = FsClassStorageError;

    #[instrument(skip(self, class, executable_class), level = "debug", ret, err)]
    fn set_class(
        &mut self,
        class_id: ClassId,
        class: RawClass,
        executable_class_hash_v2: ExecutableClassHash,
        executable_class: RawExecutableClass,
    ) -> Result<(), Self::Error> {
        if self.contains_class(class_id)? {
            return Ok(());
        }

        self.write_class_atomically(class_id, class, executable_class)?;
        self.mark_class_id_as_existent(class_id, executable_class_hash_v2)?;

        Ok(())
    }
