### Title
Unbounded growth of `activeRequests` map in Vault gateway handler enables memory-exhaustion DoS - (File: core/services/gateway/handlers/vault/handler.go)

### Summary
The Vault gateway `handler` maintains an `activeRequests map[string]*activeRequest` that is populated on every incoming user JSON-RPC request via `newActiveRequest`, keyed by the caller-supplied `req.ID` [1](#0-0) . Unlike the generic `RequestCache` implementation elsewhere in the gateway package, which explicitly enforces a `maxCacheSize` and rejects new entries once the cache is full [2](#0-1) , `newActiveRequest` in the Vault handler performs no size/capacity check before inserting into `h.activeRequests` — it only checks for ID collision [3](#0-2) . The same unbounded pattern exists in the confidential-relay handler's `newActiveRequest`/`activeRequests` map [4](#0-3) .

### Finding Description
This mirrors the reported bug class: a permissionless, externally reachable entry point inserts into a collection with no upper bound, and the only mitigation is a periodic reaper (`removeExpiredRequests`) that walks the entire map and removes entries older than `requestTimeout` [5](#0-4) . Just as `TwapOracle.update` iterates every registered pair with no way to bound or prune the set proactively, `removeExpiredRequests` must iterate the full `activeRequests` map every sweep, and the map's size is controlled entirely by the volume of unauthenticated/attacker-controlled inbound requests rather than by any configured cap. Any unprivileged caller reaching the Vault gateway handler (`HandleJSONRPCUserMessage` → `newActiveRequest`) can create new entries with unique `req.ID` values faster than the timeout-based reaper removes them, growing the map without bound between reap cycles.

### Impact Explanation
Sustained flooding can grow `activeRequests` to arbitrary size, consuming node memory and increasing the cost of every `removeExpiredRequests` sweep and every `HandleNodeMessage` lookup, degrading or ultimately disrupting the gateway's ability to process legitimate Vault requests (a DoS on the Vault capability's request-routing path). This does not, by itself, corrupt vault data or bypass authorization, but it can impair availability of the vault handler component and, transitively, node/gateway responsiveness.

### Likelihood Explanation
Reaching `newActiveRequest` requires only submitting JSON-RPC requests to the gateway's Vault handler with unique `ID` values; there is no indication that request admission is capacity-gated before insertion, only rate limiting elsewhere in the pipeline (`nodeRateLimiter` governs node-originated messages, not the initial user request volume tied to `activeRequests` growth) [6](#0-5) . This makes the condition reachable by any unprivileged/unauthenticated client able to reach the gateway endpoint, similar to how `TwapOracle.registerPair` (though owner-only there) let unbounded state accumulate; here the growth vector is even more directly attacker-controlled since it's driven by public request volume rather than an owner action.

### Recommendation
Add an explicit maximum size for `h.activeRequests` (mirroring `requestCache.maxCacheSize` in `core/services/gateway/handlers/common/requestcache.go`) and reject/backpressure new requests once the limit is reached, rather than relying solely on time-based expiry. Apply the same fix to the analogous `activeRequests` map in `core/services/gateway/handlers/confidentialrelay/handler.go`.

### Proof of Concept
1. An external, unauthenticated client sends a rapid stream of JSON-RPC requests to the Vault gateway handler's user-facing endpoint, each with a distinct `req.ID`.
2. Each call reaches `HandleJSONRPCUserMessage` → `newActiveRequest`, which only checks for ID collision before unconditionally inserting into `h.activeRequests` (`core/services/gateway/handlers/vault/handler.go:466-481`) — no capacity limit exists comparable to `requestCache.maxCacheSize` (`core/services/gateway/handlers/common/requestcache.go:46-66`).
3. Because entries are only removed by the timer-driven `removeExpiredRequests` sweep (`core/services/gateway/handlers/vault/handler.go:369-393`), a request rate exceeding the reap rate causes `activeRequests` to grow without bound, consuming increasing memory and CPU on each reap/lookup cycle until the gateway's Vault handler becomes unresponsive or the process is starved of resources.

// removeExpiredRequests removes expired requests from the pending requests map
func (h *handler) removeExpiredRequests(ctx context.Context) {
	h.mu.RLock()
	var expiredRequests []*activeRequest
	now := h.clock.Now()
	for _, userRequest := range h.activeRequests {
		if now.Sub(userRequest.createdAt) > h.requestTimeout {
			expiredRequests = append(expiredRequests, userRequest)
		}
	}
	h.mu.RUnlock()

	for _, er := range expiredRequests {
		responses := er.copiedResponses()
		var nodeResponses strings.Builder
		for nodeKey, nodeResponse := range responses {
			_, _ = fmt.Fprintf(&nodeResponses, "%s ---::: %v               ", nodeKey, nodeResponse)
		}
		nodeResponsesStr := nodeResponses.String()
		err := h.sendResponse(ctx, er, h.errorResponse(er.req, api.RequestTimeoutError, errors.New("request expired without getting quorum of responses from nodes. Available responses: "+nodeResponsesStr), []byte(nodeResponsesStr)))
		if err != nil {
			h.lggr.Errorw("error sending response to user", "requestID", er.req.ID, "error", err)
		}
	}
}

func (h *handler) newActiveRequest(req jsonrpc.Request[json.RawMessage], callback gwhandlers.Callback) (*activeRequest, error) {
	h.mu.Lock()
	defer h.mu.Unlock()
	if h.activeRequests[req.ID] != nil {
		h.lggr.Errorw("request id already exists", "requestID", req.ID)
		return nil, errors.New("request ID already exists: " + req.ID)
	}
	ar := &activeRequest{
		Callback:  callback,
		req:       req,
		createdAt: h.clock.Now(),
		responses: map[string]*jsonrpc.Response[json.RawMessage]{},
	}
	h.activeRequests[req.ID] = ar
	return ar, nil
}

	if request == nil {
		return errors.New("request is nil")
	}
	if responseData == nil {
		return errors.New("responseData is nil")
	}
	key := globalId{request.Body.Sender, request.Body.MessageId}
	c.mu.Lock()
	defer c.mu.Unlock()
	_, ok := c.cache[key]
	if ok {
		return errors.New("request already exists")
	}
	if len(c.cache) >= int(c.maxCacheSize) {
		return errors.New("request cache is full")
