### Title
Missing class-declaration validation in the Starknet OS `replace_class` syscall implementation causes execution-engine divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The external report's root cause is a security-sensitive parameter (`gauge`) that is accepted and persisted without verifying it references a legitimate, pre-registered entity. The equivalent pattern exists in the sequencer: the Cairo `execute_replace_class` function that implements the `replace_class` syscall inside the Starknet OS program writes an attacker-supplied `class_hash` into `contract_state_changes` without checking that a compiled class was ever declared for that hash — a check that the Rust `blockifier` execution engine does perform.

### Finding Description
The `replace_class` syscall lets any contract change its own class hash. In `blockifier`'s native execution engine, this is properly guarded: [1](#0-0) 

This enforces both that the class hash is declared and that it is a Cairo 1 class before allowing the replacement.

The Starknet OS Cairo implementation of the very same syscall — used for transaction re-execution/verification and STARK proof generation of the block — does not replicate this validation. The code contains an explicit, unresolved acknowledgment of the gap: [2](#0-1) 

The `class_hash` from the syscall request is written directly into `new_state_entry` and committed via `dict_update` on `contract_state_changes` with no assertion that a corresponding compiled class exists (no check equivalent to `is_cairo1(&compiled_class)` or `get_compiled_class` either). The deprecated (Cairo 0) syscall path exhibits the identical gap: [3](#0-2) 

This is exactly the "unverified privileged reference" bug class from the report: the `gauge`/`class_hash`-like parameter fully controls a state mutation but is never checked against the set of legitimately registered values (declared classes) before being trusted.

### Impact Explanation
`blockifier` and the Starknet OS Cairo program are required to compute bit-identical state transitions for a given transaction — `blockifier` builds/executes the block, and the OS independently re-derives/verifies the same execution to produce the proof that anchors the committed state root. Because the OS's `replace_class` handler omits the declared-class check that `blockifier` enforces, the two execution paths encode different acceptance criteria for the same syscall. Any circumstance where the OS is relied upon as the authoritative execution/validity engine (re-execution, proof generation, or future OS-native execution) for a transaction invoking `replace_class` with an undeclared or non-Cairo1 class hash will silently accept it, whereas `blockifier` would reject the transaction. This is a concrete honest-node/implementation divergence for the same code path (`crates/blockifier/src/execution/syscalls/syscall_base.rs::replace_class` vs. `execute_replace_class` in `syscall_impls.cairo`), which can result in inconsistent committed contract class hashes and blocks that cannot be soundly proven.

### Likelihood Explanation
The gap is triggered by nothing more than a single unprivileged contract invoking the standard `replace_class` syscall with a crafted `class_hash` (e.g., a hash that is undeclared or a Cairo 0 class hash) — no special privileges are required. The gap is explicitly marked with a `TODO` in the shipped source, confirming the check is currently absent rather than intentionally omitted for a proven-safe reason.

### Recommendation
Add the same validation performed by `blockifier`'s `syscall_base.rs::replace_class` (declared-class existence and Cairo1-only enforcement) to the Cairo implementation `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, using the `contract_class_changes` dictionary (or equivalent declared-class-hash-to-compiled-class-hash Patricia data) to assert the class hash was previously declared before permitting the state update.

### Proof of Concept
1. An unprivileged account deploys/uses a contract that calls the `replace_class` syscall (Cairo 1) with an arbitrary `class_hash` that has never been declared (or is a Cairo 0 class hash).
2. Under `blockifier`, this transaction is rejected because `replace_class` in `crates/blockifier/src/execution/syscalls/syscall_base.rs` calls `self.state.get_compiled_class(class_hash)` and additionally checks `is_cairo1`.
3. Under the Starknet OS Cairo implementation (`execute_replace_class` in `syscall_impls.cairo`), the identical syscall request is processed with no equivalent check — `class_hash` is written straight into `contract_state_changes` — demonstrating the two "reference implementations" of the sequencer disagree on whether this transaction is valid.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
