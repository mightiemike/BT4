### Title
Blocked/revoked ToS senders remain authorized in the Functions Gateway allowlist due to stale in-memory state - (File: core/services/gateway/handlers/functions/allowlist/allowlist.go)

### Summary
The Functions Gateway `OnchainAllowlist` maintains an in-memory `allowlist` map (`atomic.Pointer[map[common.Address]struct{}]`) that is consulted by `Allow(address)` to authorize incoming Functions requests [1](#0-0) . When the Terms-of-Service allowlist contract reports addresses that have been *blocked* (revoked), `syncBlockedSenders` only deletes them from the persistent ORM table but never removes them from the live in-memory map used for the actual authorization check, mirroring the reported bug class where exclusion additions fail to update the dependent state used for the enforcement decision.

### Finding Description
`updateFromContractV1` performs two independent updates per cycle: it grows the in-memory allowlist via `updateAllowedSendersInBatches` (which seeds `currentAllowedSenderList` from the *current in-memory* map and only ever adds newly allowed addresses) [2](#0-1) [3](#0-2) , and it calls `syncBlockedSenders` to reconcile blocked senders [4](#0-3) .

`syncBlockedSenders` fetches the blocked-sender list from the on-chain `TermsOfServiceAllowList` contract and calls `a.orm.DeleteAllowedSenders(ctx, blockedSendersBatch)`, which only issues a SQL `DELETE` against the `functions_allowlist` table [5](#0-4) [6](#0-5) . It never touches `a.allowlist` (the atomic in-memory pointer). Because `updateAllowedSendersInBatches` always starts from the existing in-memory snapshot and only adds to it, a previously-allowed address that has since been added to the on-chain blocklist stays permanently present in `a.allowlist` across update cycles — it is deleted from storage but not from the structure that `Allow()` actually checks:

```go
func (a *onchainAllowlist) Allow(address common.Address) bool {
    allowlist := *a.allowlist.Load()
    _, ok := allowlist[address]
    return ok
}
``` [1](#0-0) 

The in-memory map is only rebuilt from the (now-correct) ORM state at node startup, via `loadStoredAllowedSenderList` → `a.update(...)`, which replaces the map wholesale [7](#0-6) . Between restarts, revocation has no effect on the live gateway node.

This is the direct analog of the reported bug: an "exclusion" event (blocking a sender / adding to `isExcludedAddress` in the original report) fails to update the dependent state (`totalLiquidity` there, `allowlist` here) that the authorization/decision function (`getMaxCommunityLpPositon()` there, `Allow()` here) relies on, leading the enforcement function to keep granting privileges to an entity that should have been cut off.

### Impact Explanation
`allowlist.Allow()` gates access to the Functions Gateway on a per-DON basis — see `functionsHandler` which wires `fallow.OnchainAllowlist` into request processing and returns `ErrNotAllowlisted` for denied senders [8](#0-7) [9](#0-8) . If a subscriber's ToS acceptance is revoked/blocked on-chain (e.g., due to abuse, fraud, or compliance action), the gateway node continues to accept and route their Functions requests until the process restarts, because the periodic in-memory refresh path never subtracts newly blocked senders. This is an authorization-bypass/stale-permission issue directly affecting who can submit requests into the DON's off-chain workflow.

### Likelihood Explanation
This triggers deterministically whenever `UpdateFrequencySec` periodic updates are enabled (the common production configuration) and the batch-processing code path is used (contract version ≥ `v1.1.0`, `tosContractMinBatchProcessingVersion`) [4](#0-3) . Any address added to the on-chain blocklist after the gateway node has already cached it as allowed will remain effectively allowed for the lifetime of the running process — no attacker action beyond having been previously allowlisted and later blocked is required.

### Recommendation
In `syncBlockedSenders` (or its caller `updateFromContractV1`), after fetching each `blockedSendersBatch`, also remove those addresses from the in-memory `a.allowlist` snapshot (e.g., load the current map, delete the blocked addresses, and atomically store the updated map) rather than only calling `a.orm.DeleteAllowedSenders`. Alternatively, rebuild `a.allowlist` from the ORM's authoritative state after every sync cycle instead of only at `Start()`.

### Proof of Concept
1. Configure `OnchainAllowlist` with `UpdateFrequencySec` > 0 and a ToS contract version ≥ `v1.1.0` so the batch path (`updateAllowedSendersInBatches` + `syncBlockedSenders`) is used.
2. Address `0xA` is present in the on-chain allowlist; a periodic update cycle runs, adding `0xA` to `a.allowlist` via `updateAllowedSendersBatch` [3](#0-2) .
3. Contract owner blocks `0xA` (adds it to the contract's blocked-senders list).
4. Next periodic update: `syncBlockedSenders` fetches `0xA` in `blockedSendersBatch` and calls `orm.DeleteAllowedSenders(ctx, [0xA])`, removing the DB row, but `a.allowlist` in memory still contains `0xA` since `updateAllowedSendersInBatches` seeded from the stale in-memory map and never subtracts blocked addresses [5](#0-4) .
5. `functionsHandler` continues to call `allowlist.Allow(0xA)`, which returns `true`, allowing the blocked sender's requests to keep being processed, until the gateway node restarts and `loadStoredAllowedSenderList` rebuilds the map from the now-correct ORM state.

// syncBlockedSenders fetches the list of blocked addresses from the contract in batches
// and removes the addresses from the functions_allowlist table if present
func (a *onchainAllowlist) syncBlockedSenders(ctx context.Context, tosContract *functions_allow_list.TermsOfServiceAllowList, blockNum *big.Int) error {
	count, err := tosContract.GetBlockedSendersCount(&bind.CallOpts{
		Pending:     false,
		BlockNumber: blockNum,
		Context:     ctx,
	})
	if err != nil {
		return errors.Wrap(err, "unexpected error during functions_allow_list.GetBlockedSendersCount")
	}

	throttleTicker := time.NewTicker(time.Duration(a.config.FetchingDelayInRangeSec) * time.Second)
	for idxStart := uint64(0); idxStart < count; idxStart += uint64(a.config.OnchainAllowlistBatchSize) {
		<-throttleTicker.C

		idxEnd := idxStart + uint64(a.config.OnchainAllowlistBatchSize)
		if idxEnd >= count {
			idxEnd = count - 1
		}

		blockedSendersBatch, err := tosContract.GetBlockedSendersInRange(&bind.CallOpts{
			Pending:     false,
			BlockNumber: blockNum,
			Context:     ctx,
		}, idxStart, idxEnd)
		if err != nil {
			return errors.Wrap(err, "error calling GetAllowedSendersInRange")
		}

		err = a.orm.DeleteAllowedSenders(ctx, blockedSendersBatch)
		if err != nil {
			a.lggr.Errorf("failed to delete blocked address from allowed list in storage: %v", err)
		}
	}

func (a *onchainAllowlist) update(addrList []common.Address) {
	newAllowlist := make(map[common.Address]struct{})
	for _, addr := range addrList {
		newAllowlist[addr] = struct{}{}
	}
	a.allowlist.Store(&newAllowlist)
	a.lggr.Infow("allowlist updated successfully", "len", len(addrList))
}

func (a *onchainAllowlist) loadStoredAllowedSenderList(ctx context.Context) {
	allowedList := make([]common.Address, 0)
	offset := uint(0)
	for {
		asBatch, err := a.orm.GetAllowedSenders(ctx, offset, a.config.StoredAllowlistBatchSize)
		if err != nil {
			a.lggr.Errorf("failed to get stored allowed senders: %v", err)
			break
		}

		allowedList = append(allowedList, asBatch...)

		if len(asBatch) < int(a.config.StoredAllowlistBatchSize) {
			break
		}
		offset += a.config.StoredAllowlistBatchSize
	}

	a.update(allowedList)
}

// DeleteAllowedSenders is used to remove blocked senders from the functions_allowlist table.
// This is achieved by specifying a list of blockedSenders to remove.
func (o *orm) DeleteAllowedSenders(ctx context.Context, blockedSenders []common.Address) error {
	var valuesPlaceholder []string
	for i := 1; i <= len(blockedSenders); i++ {
		valuesPlaceholder = append(valuesPlaceholder, fmt.Sprintf("$%d", i+1))
	}

	stmt := fmt.Sprintf(`
		DELETE FROM %s
		WHERE router_contract_address = $1
		AND allowed_address IN (%s);`, tableName, strings.Join(valuesPlaceholder, ", "))

	args := []any{o.routerContractAddress}
	for _, bs := range blockedSenders {
		args = append(args, bs)
	}

	res, err := o.ds.ExecContext(ctx, stmt, args...)
	if err != nil {
		return err
	}

	rowsAffected, err := res.RowsAffected()
	if err != nil {
		return err
	}

	o.lggr.Debugf("Successfully removed blocked senders from the allowed list: %v for routerContractAddress: %s. rowsAffected: %d", blockedSenders, o.routerContractAddress, rowsAffected)

	return nil
}
