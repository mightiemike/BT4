### Title
Unvalidated `new_seed` in `LeaderBlockCommitOp` lets a minority miner arbitrarily bias the next sortition's VRF-mix index - ([File: stackslib/src/chainstate/burn/sortition.rs])

### Summary
`BlockSnapshot::get_last_vrf_seed` and `BlockSnapshot::select_winning_block` in `stackslib/src/chainstate/burn/sortition.rs` pull `new_seed` straight from the winning `LeaderBlockCommitOp` without verifying it is the hash of a genuine VRF proof. Because `LeaderBlockCommitOp::check` (in `leader_block_commit.rs`) never validates `new_seed` against any VRF proof, a minority miner who wins sortition N can submit an arbitrary 32-byte `new_seed`, forfeiting only their own tenure's coinbase, and thereby fully control the seed that biases sortition N+1's `sortition_hash.mix_VRF_seed(VRF_seed)` sampling.

### Finding Description
The claimed equality is: `SORTITION winner at height N+1 == index derived from sortition_hash mixed with a VRF-derived, non-grindable seed from the height-N winner`.

Trace:
- `BlockSnapshot::get_last_vrf_seed` (sortition.rs:155-179) reads `new_seed` directly off the on-chain winning block-commit with no validity check: [1](#0-0) 
- `select_winning_block` feeds this raw `new_seed` into `sample_burn_distribution`, which computes `sortition_hash.mix_VRF_seed(VRF_seed).to_uint256()` to pick the winner index: [2](#0-1) 
- The function's own doc comment concedes the seed is not guaranteed to derive from a valid VRF proof: [3](#0-2) 
- `LeaderBlockCommitOp::check` (leader_block_commit.rs:1290-1372) validates burn amount, PoX outputs, epoch marker, and missed-block modulus — but never checks `new_seed` against any VRF proof: [4](#0-3) 
- The only place `new_seed` is checked against a real VRF proof is `NakamotoChainState::validate_vrf_seed` / `check_normal_coinbase_tx`, but these run only when a *Stacks block* for that tenure is later validated, and they check that the *current* block's own `new_seed` matches its *parent's* proof — they never gate whether the burnchain-level sortition (which happens immediately when the burn block is processed, independent of whether a Stacks block is ever produced) can use a bogus seed: [5](#0-4) 

Exploit flow: the attacker wins sortition N via the normal burn-weighted lottery (achievable with any nonzero minority stake, probabilistically). Their `LeaderBlockCommitOp` for that win carries a `new_seed` of their choosing (not derived from any VRF proof). `select_winning_block`/`get_last_vrf_seed` unconditionally record this value as the winning commit's seed regardless of whether the attacker (or anyone) ever produces a valid Stacks block for tenure N — the burn-layer bookkeeping (`BlockSnapshot`, `winning_block_txid`) is entirely decoupled from Stacks-block validation. At height N+1, every node computes the same `sortition_hash.mix_VRF_seed(attacker_chosen_seed)`, so the attacker (who forfeits only their own tenure-N coinbase, since no valid block can ever be produced referencing a fabricated seed) gets free, non-grindable-in-name-only control over the randomness that selects the N+1 winner among the burn-weighted candidates.

Existing guards (`validate_vrf_seed`, `check_normal_coinbase_tx`, `common_validate_against_burnchain`) only protect the *Stacks-block* layer's internal consistency (a tenure's block must match its own commit's `new_seed`↔proof relationship); none of them prevent the *burnchain sortition* layer from consuming an unvalidated seed when picking the next winner.

### Impact Explanation
All honest nodes still agree deterministically on the N+1 winner (no chain split, no MARF divergence, no reward double-payment) because every node reads the same on-chain `new_seed` byte string. The impact is a fairness/bias break in the sortition RNG: a minority miner can, at the one-time cost of forfeiting their own tenure-N coinbase, choose the seed value that determines which candidate wins tenure N+1, undermining the "VRF-derived, non-grindable seed" guarantee that sortition selection is meant to rely on. This matches the High-severity category of "a minority-triggerable sortition/VRF divergence" rather than Critical, since no chain split, invalid-block-acceptance, or double-payment results — nodes remain in consensus, but the randomness itself is attacker-influenced.

### Likelihood Explanation
Preconditions: attacker needs only to win a single sortition round (any nonzero burn stake gives nonzero probability, no majority required), and to be willing to sacrifice that round's coinbase reward (since a block can never be validly produced against a fabricated `new_seed`). The cost is bounded (one coinbase reward), and the attack is repeatable every time the attacker wins a round. This is feasible for any minority miner and does not require any privileged role, Sybil, or majority stake — it fits the specified unprivileged-minority threat model.

### Recommendation
Reject `LeaderBlockCommitOp`s (or at minimum flag the resulting sortition as ineligible to seed future randomness) whose `new_seed` cannot later be proven to derive from a valid VRF proof over the correct sortition hash — e.g., require the burn-layer sortition acceptance to be provisional until the corresponding Stacks block/VRF proof is confirmed, or fall back deterministically to a previous validated seed (rather than an unvalidated one) when the winning commit's tenure never produces a validly-proved block within the maturation window.

### Proof of Concept
Rust integration test plan (two-node/two-fork harness or single-node `SortitionHandleTx` harness akin to `stackslib/src/chainstate/burn/sortition.rs` unit tests):
1. Build a sortition history where miner A wins block N with `LeaderBlockCommitOp.new_seed = VRFSeed([0xAA; 32])` (not derived from any VRF proof).
2. Assert `BlockSnapshot::get_last_vrf_seed(&mut sort_tx, &header_N1) == VRFSeed([0xAA; 32])` — i.e., the fabricated seed is accepted unconditionally.
3. Submit two candidate `LeaderBlockCommitOp`s at height N+1 with equal burn amounts from miner A and miner B; compute `sample_burn_distribution` for two different attacker-chosen `new_seed` values from step 1 and show the winner index flips deterministically to favor whichever seed the attacker picked (`assert_ne!` on `win_idx` across seed choices), demonstrating non-uniform, attacker-controlled winner distribution.
4. Confirm no valid `NakamotoBlock` can ever be constructed for tenure N (i.e., `validate_vrf_seed` fails for any real VRF proof against `VRFSeed([0xAA;32])`), proving the attacker's only cost is the forfeited coinbase, while the sortition-layer bias at N+1 still takes effect.

    /// Given the weighted burns, VRF seed of the last winner, and sortition hash, pick the next
    /// winner.  Return the index into the distribution *if there is a sample to take*.
    fn sample_burn_distribution(
        dist: &[BurnSamplePoint],
        VRF_seed: &VRFSeed,
        sortition_hash: &SortitionHash,
    ) -> Option<usize> {
        if dist.is_empty() {
            // no winners
            return None;
        }
        if dist.len() == 1 {
            // only one winner
            return Some(0);
        }

        let index = sortition_hash.mix_VRF_seed(VRF_seed).to_uint256();
        for (i, dist_elem) in dist.iter().enumerate() {
            if (dist_elem.range_start <= index) && (index < dist_elem.range_end) {
                debug!(
                    "Sampled {}: i = {}, sortition index = {}",
                    dist_elem.candidate.block_header_hash, i, &index
                );
                return Some(i);
            }
        }

        // should never happen
        panic!("FATAL ERROR: unable to map {} to a range", index);
    }

    /// Returns Ok() and a vector of PoxAddresses which were punished by this op
    pub fn check(
        &mut self,
        burnchain: &Burnchain,
        tx: &mut SortitionHandleTx,
        reward_set_info: Option<&RewardSetInfo>,
    ) -> Result<(), op_error> {
        /////////////////////////////////////////////////////////////////////////////////////
        // There must be a burn
        /////////////////////////////////////////////////////////////////////////////////////

        let apparent_sender_repr = format!("{}", &self.apparent_sender);

        if self.burn_fee == 0 {
            warn!("Invalid block commit: no burn amount";
                  "apparent_sender" => %apparent_sender_repr
            );
            return Err(op_error::BlockCommitBadInput);
        }
        let epoch = SortitionDB::get_stacks_epoch(tx, self.block_height)?.unwrap_or_else(|| {
            panic!(
                "FATAL: impossible block height: no epoch defined for {}",
                self.block_height
            )
        });

        let intended_modulus = (self.burn_block_mined_at() + 1) % BURN_BLOCK_MINED_AT_MODULUS;
        let actual_modulus = self.block_height % BURN_BLOCK_MINED_AT_MODULUS;
        if actual_modulus != intended_modulus {
            // This transaction "missed" its target burn block, the transaction
            //  is not valid, but we should allow this UTXO to "chain" to valid
            //  UTXOs to allow the miner windowing to work in the face of missed
            //  blocks.
            let miss_distance = if actual_modulus > intended_modulus {
                actual_modulus - intended_modulus
            } else {
                BURN_BLOCK_MINED_AT_MODULUS + actual_modulus - intended_modulus
            };
            warn!("Invalid block commit: missed target block";
                  "intended_modulus" => intended_modulus,
                  "actual_modulus" => actual_modulus,
                  "miss_distance" => miss_distance,
                  "block_height" => self.block_height,
                  "apparent_sender" => %apparent_sender_repr
            );
            let intended_sortition =
                self.check_intended_sortition(epoch.epoch_id, burnchain, tx, miss_distance)?;
            let missed_data = MissedBlockCommit {
                input: self.input.clone(),
                txid: self.txid.clone(),
                intended_sortition,
            };

            return Err(op_error::MissedBlockCommit(missed_data));
        }

        let punished = if burnchain
            .pox_constants
            .is_after_pox_sunset_end(self.block_height, epoch.epoch_id)
        {
            // sunset has begun and we're not in epoch 2.1 or later, so apply sunset check
            self.check_after_pox_sunset().inspect_err(|e| {
                warn!("Invalid block-commit: bad PoX after sunset: {e:?}";
                          "apparent_sender" => %apparent_sender_repr);
            })?;
            vec![]
        } else {
            // either in epoch 2.1, or the PoX sunset hasn't completed yet
            self.check_pox(epoch.epoch_id, burnchain, tx, reward_set_info)
                .inspect_err(|e| {
                    warn!("Invalid block-commit: bad PoX: {e:?}";
                          "apparent_sender" => %apparent_sender_repr);
                })?
        };

        self.check_common(epoch.epoch_id, tx)?;

        if reward_set_info.is_some_and(|r| r.allow_nakamoto_punishment()) {
            self.treatment = punished;
        }

        // good to go!
        Ok(())
    }

    /// Verify that the VRF seed of this block's block-commit is the hash of the parent tenure's
    /// VRF seed.
    pub fn validate_vrf_seed<SDBI: StacksDBIndexed>(
        &self,
        sortdb_conn: &Connection,
        chainstate_conn: &mut SDBI,
        block_commit: &LeaderBlockCommitOp,
    ) -> Result<(), ChainstateError> {
        // the block-commit from the miner who created this coinbase must have a VRF seed that
        // is the hash of the parent tenure's VRF proof.
        // Do the query relative to the parent block ID, since this block may not be processed yet.
        let parent_vrf_proof = NakamotoChainState::get_parent_vrf_proof(
            chainstate_conn,
            &self.header.parent_block_id,
            sortdb_conn,
            &self.header.consensus_hash,
            &block_commit.txid,
        )?;
        if !block_commit.new_seed.is_from_proof(&parent_vrf_proof) {
            warn!("Invalid Nakamoto block-commit: seed does not match parent VRF proof";
                  "consensus_hash" => %self.header.consensus_hash,
                  "stacks_block_hash" => %self.header.block_hash(),
                  "stacks_block_id" => %self.block_id(),
                  "parent_block_id" => %self.header.parent_block_id,
                  "commit_seed" => %block_commit.new_seed,
                  "proof_seed" => %VRFSeed::from_proof(&parent_vrf_proof),
                  "parent_vrf_proof" => %parent_vrf_proof.to_hex(),
                  "block_commit" => format!("{:?}", &block_commit)
            );
            return Err(ChainstateError::InvalidStacksBlock(
                "Invalid Nakamoto block: bad VRF proof".into(),
            ));
        }
        Ok(())
    }
