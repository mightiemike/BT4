## Finding

### Title
Fee-market base fee fractional precision discarded before multiplication in gas cost calculation - (File: x/uexecutor/keeper/fees.go)

### Summary
`CalculateGasCost` in `x/uexecutor/keeper/fees.go` unwraps the fee-market's `LegacyDec` base fee into a whole-`upc` integer by dividing by `1e18` *before* multiplying by `gasUsed`, instead of multiplying the exact `Dec` price by `gasUsed` and truncating only the final total. This is the same "division in the middle of the calculation" pattern as the referenced report, and it silently discards the fractional-`upc` component of the per-gas price on every gas-fee burn. [1](#0-0) 

### Finding Description
`CalculateGasCost` takes the current EIP-1559 `baseFee` (a `sdkmath.LegacyDec`) from the fee-market keeper and computes the gas cost paid by the recipient's smart account for a `DerivedEVMCall`:

```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
...
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)
``` [2](#0-1) 

The code comment asserts that "the base fee is always a whole number of upc -- no fractional upc exists," and therefore the `Div(1e18)` step is claimed to be a lossless unwrap of the `LegacyDec` encoding. That assumption is only true if `baseFee` never carries a fractional-`upc` component. In practice `baseFee` is a *price* (upc per unit of gas), not a token balance, and Cosmos EVM's fee-market module adjusts it every block using an EIP-1559-style elastic formula (`baseFee ± baseFee*gasUsedDelta/gasTarget/changeDenominator`). Such Dec arithmetic routinely produces a base fee with a non-zero fractional component (e.g. `1000000000.734521...` upc/gas) under ordinary network load, since nothing in the fee-market's update logic rounds the result to a whole `upc`.

Because `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` performs integer division on the internal Dec representation *before* the multiplication by `gasUsed`, any fractional-`upc` part of the per-gas price is truncated to zero up front. The subsequent multiplication by `gasUsed` then propagates this already-truncated, artificially-lowered price, rather than the mathematically correct `floor(baseFee_exact * gasUsed)`.

This function feeds directly into `DeductGasFeesFromReceipt`, which burns the computed `gasCost` from the sender's account for every module-originated EVM execution (`DerivedEVMCall`) triggered by ordinary universal-payload transactions: [3](#0-2) 

### Impact Explanation
Every universal-payload execution that consumes gas is subject to this truncated-before-multiplied computation. Any time the network's dynamically-adjusted base fee (a `LegacyDec`) carries a fractional-`upc` component — which is the normal case for an elastic base fee, not an edge case — the protocol burns strictly less than the mathematically correct `baseFee * gasUsed` from the executing account. The loss scales with `gasUsed`: for payload executions consuming hundreds of thousands of gas units, the undercharge from a fractional price component approaching 1 `upc` can reach hundreds of thousands of `upc` per transaction. This is a systemic, per-transaction gas-fee-accounting corruption (protocol under-burns fees) reachable purely by ordinary users submitting universal payloads through the standard flow — no privileged actor is required.

### Likelihood Explanation
This triggers automatically whenever the fee-market's base fee has a non-integer `upc` component, which is the ordinary steady-state behavior of an elastic EIP-1559-style base fee once network gas usage deviates from the target in any block. It requires no attacker action beyond normal transaction submission, making it a near-certain, continuously-occurring leak rather than a rare edge case (mirroring the "1%-7.5% lost fees in normal usage" pattern from the reference report).

### Recommendation
Perform the multiplication before any division/truncation: multiply the exact `LegacyDec` base fee by `gasUsed` first (e.g. `baseFee.MulInt64(int64(gasUsed))`), then truncate/round to a whole `upc` integer exactly once at the end, mirroring the correct pattern already used in `app/cosmos/min_gas_price.go` (`gp.Amount.Mul(gasLimit).Ceil().RoundInt()`). Remove the premature `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` step and the associated "always a whole number of upc" assumption from `CalculateGasCost`.

### Proof of Concept
1. Fee-market base fee elastic adjustment produces `baseFee = 1_000_000_000.734521 upc` (a `LegacyDec`) after a block of above-target gas usage — normal operation, no privileged action.
2. A user submits a universal payload whose `DerivedEVMCall` consumes `gasUsed = 500_000`.
3. `CalculateGasCost` computes `baseFeeBig := baseFee.BigInt()` (`= 1_000_000_000734521000000000000000000` internally, exact), then `baseFeeBig.Div(baseFeeBig, 1e18)` truncates it to `1_000_000_000` upc, discarding the `0.734521` fractional-upc price component.
4. `gasCost = 1_000_000_000 * 500_000 = 500_000_000_000_000 upc` is burned via `DeductAndBurnFees`, instead of the mathematically correct `floor(1_000_000_000.734521 * 500_000) = 500_000_367_260 ...` (undercharge of ~367,260 `upc` on this single transaction, scaling with `gasUsed` and the fractional remainder of `baseFee`). func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}
