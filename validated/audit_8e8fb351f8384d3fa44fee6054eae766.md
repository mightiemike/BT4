### Title
`TransactionOutput::ensure_match_transaction_info` omits verification of `position_state_checkpoint_hash`, allowing accepted `TransactionInfo` to commit an unauthenticated native-position state root - (File: types/src/transaction/mod.rs)

### Summary
The Nomic report's root cause was that a commitment field (destination) was not bound/verified against the actual, distinguishing context, letting an attacker substitute a different value that got silently accepted. The Aptos analog: `TransactionInfoV1` carries a new `position_state_checkpoint_hash` field, which is meant to be a consensus-verified commitment to the native-position Jellyfish Merkle Tree root [1](#0-0) . But the function that is supposed to cross-check `TransactionOutput` against `TransactionInfo` before it is treated as authenticated (`ensure_match_transaction_info`) validates status, gas, write-set hash, and event root hash, yet explicitly skips `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` [2](#0-1) .

### Finding Description
`position_state_checkpoint_hash` is designed to be a committed root of the native-position state tree, gated by the `COMPUTE_TRADING_NATIVE_STATE_ROOTS` feature [3](#0-2) . It is produced during execution (`DoStateCheckpoint`/`DoLedgerUpdate`) and threaded into `TransactionInfoV1` [4](#0-3) , and separately used by state-sync's bootstrapper as the trusted root to which the native-position `StateValueSyncer` snapshot is verified against [5](#0-4) .

The function `ensure_match_transaction_info` is the place in the codebase whose entire purpose is to assert that a `TransactionOutput` (the executed result) is consistent with a `TransactionInfo` (the object that gets hashed into the transaction accumulator and cryptographically committed by validator signatures / proofs). It checks `status`, `gas_used`, `write_set` hash, and `event_root_hash`, but the code comment openly documents that the checkpoint hashes — including `position_state_checkpoint_hash` — are not compared [6](#0-5) . This means any caller that relies on this function as its sole cross-check between locally computed output and an authenticated `TransactionInfo` will accept a `TransactionInfo` whose `position_state_checkpoint_hash` does not correspond to the locally executed position state, without detecting the mismatch.

### Impact Explanation
If any replay/verification tool (e.g. `db-tool`'s `replay_on_archive`, mentioned directly in the comment) or a component that uses `ensure_match_transaction_info` as its correctness oracle relies on it to detect divergence between local re-execution and the ledger-committed `TransactionInfo`, a divergent/corrupted native-position root would go undetected — the tool would report a "successful replay" even though the authenticated position state root diverges from local execution, per the comment itself [7](#0-6) . This is precisely the "hard-fork-only divergence during commit/replay/restore" class in the state-integrity gate — a state root that is supposed to be validated against the proof/commit path is silently accepted as correct even when wrong.

### Likelihood Explanation
Low-to-moderate: `COMPUTE_TRADING_NATIVE_STATE_ROOTS` and `TRANSACTION_INFO_V1` are still being rolled out (feature flags default off) [8](#0-7) , and the code comment shows the team is aware and is treating this as a pre-launch TODO rather than a shipped bypass. The exact severity depends on whether `ensure_match_transaction_info` is invoked in a security-critical path (e.g. state-sync verification, executor validation) where a mismatch must be caught before that feature is enabled on mainnet — I could not find, within the indexed code, all call sites of `ensure_match_transaction_info` to confirm whether any currently-mainnet-active path depends on it for position-root validation. This should be verified by grepping all callers before treating this as exploitable on current mainnet configuration.

### Recommendation
- Before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, extend `ensure_match_transaction_info` to also assert `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` match locally computed values whenever they are `Some` in the `TransactionInfo`, mirroring the existing `write_set_hash`/`event_root_hash` checks.
- Audit every caller of `ensure_match_transaction_info` to confirm whether any of them (e.g., replay-verify tooling, state-sync, executor commit validation) currently depend on it to catch state-root divergence, and gate feature rollout on this fix landing first.

### Proof of Concept
Conceptual (no exploitable path against current mainnet since the feature is gated off): once `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled, construct a `TransactionOutput` whose actual native-position write set produces position-tree root `R_actual`, but supply/accept a `TransactionInfoV1` carrying `position_state_checkpoint_hash = R_forged` (any other valid-looking hash). Calling `output.ensure_match_transaction_info(version, &forged_info, None, None)` returns `Ok(())` despite the mismatch, because the check for `position_state_checkpoint_hash` is absent from the function body [6](#0-5) .

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    /// The expected snapshot root for the given kind at the target version, read
    /// from the target transaction info: main state's state checkpoint hash, or
    /// the committed position state root (guaranteed present once the position
    /// stage runs, per `snapshot_kind_applies_to_target`). All kinds share the
    /// target version, so this is taken from the target output, not a storage read.
    fn expected_snapshot_root(&mut self, kind: StateKind) -> Result<HashValue, Error> {
        let transaction_output_to_sync = self.get_transaction_output_to_sync()?;
        let target_transaction_info = transaction_output_to_sync
            .get_output_list_with_proof()
            .proof
            .transaction_infos
            .first()
            .ok_or_else(|| {
                Error::UnexpectedError("Target transaction info does not exist!".into())
            })?;
        match kind {
            StateKind::MainState => target_transaction_info
                .ensure_state_checkpoint_hash()
                .map_err(|error| {
                    Error::UnexpectedError(format!(
                        "State checkpoint must exist! Error: {:?}",
                        error
                    ))
                }),
            StateKind::Position => target_transaction_info
                .position_state_checkpoint_hash()
                .ok_or_else(|| Error::UnexpectedError("Missing position state root!".into())),
        }
    }
