### Title
Auto-swap slippage protection derived from a manipulable spot quote enables sandwich attacks on module-originated PRC20→PC swaps - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
The Hypervisor report shows that letting `pool.swap`/`pool.mint`/`pool.burn` execute without a caller-committed minimum-output bound lets a front-runner manipulate the AMM price around the victim's call. Push Chain re-implements the exact primitive natively: `x/uexecutor` fetches a Uniswap V3 `QuoterV2` spot quote and derives a 5% slippage floor (`minPCOut = quote * 95 / 100`) from that same spot price, immediately before executing a module-originated swap (`depositPRC20WithAutoSwap` / `refundUnusedGas`). Because the "protection" bound is derived from the very same manipulable AMM state it is meant to protect against, an attacker who moves the pool price immediately before the module's swap executes (and reverses it afterward) can extract value from every gas-abstraction deposit or gas-refund swap that Push Chain performs on users' behalf.

### Finding Description
For `GAS` and `GAS_AND_PAYLOAD` inbound routes, `ExecuteInboundGas` / `ExecuteInboundGasAndPayload` compute the swap floor like this: [1](#0-0) 

`GetSwapQuote` performs a live, non-committing call to `QuoterV2.quoteExactInputSingle` against the current pool state: [2](#0-1) 

Immediately after, `CallPRC20DepositAutoSwap` executes the real swap through `UniversalCore.depositPRC20WithAutoSwap`, passing `minPCOut` derived from that same spot quote and `deadline = 0` (module lets the handler contract fall back to its own default deadline, i.e. no caller-enforced staleness bound): [3](#0-2) 

The identical pattern is used for the excess-gas refund swap on outbound finalization: [4](#0-3) [5](#0-4) 

In every case, the "slippage protection" is 5% *relative to the pool's price at the instant the module reads it* — not relative to a price the end user committed to, an oracle, or a TWAP. This is the same structural flaw the Hypervisor report flags: bounding a swap only by a percentage of its own just-read spot price does not stop sandwiching, because the attacker can shift the spot price down right before the module's `GetSwapQuote`/`depositPRC20WithAutoSwap` pair executes (buy/sell into the WPC/PRC20 pool), causing the quote itself — and therefore the 95% floor — to already reflect the manipulated, depressed price. The module's swap then clears at that manipulated rate, and the attacker reverses their pool position afterward (back-run) to capture the spread. Because `depositPRC20WithAutoSwap` and `refundUnusedGas` are invoked automatically by the protocol whenever a user submits any `GAS`/`GAS_AND_PAYLOAD` inbound or accrues an outbound gas refund, an unprivileged attacker only needs to be able to observe (or trigger, since they control their own inbound's timing) the block in which the module's derived swap will execute and place manipulation trades around it — no privileged role or validator collusion is required, since it only requires ordinary swap transactions the attacker submits themselves.

### Impact Explanation
Every gas-abstraction deposit auto-swap and every gas-refund swap the protocol performs on a user's behalf is exposed to value extraction proportional to pool depth and the manipulation window, up to the full 5% band on each occurrence (and potentially more since the reference price itself, not just the executed price, is what's being manipulated — the 5% is not measured from an unbiased baseline). Because this runs unconditionally for the `GAS`/`GAS_AND_PAYLOAD` and outbound-refund flows on every UEA deposit, it can be triggered repeatedly against arbitrary victims' inbound/outbound flows to siphon protocol/user-controlled PRC20↔PC swap value, i.e. unauthorized draining of user/protocol funds through a module-originated EVM execution path with a broken invariant (the swap's "minimum acceptable output" is not tied to anything but the pool it's fed from).

### Likelihood Explanation
Likelihood is moderate: exploitation requires MEV-style capability (mempool visibility of the block a validator-vote-driven inbound/outbound execution will land in, or the attacker's own inbound submission timing) and enough capital/pool depth knowledge to move price within the 5% band profitably, but no privileged role, key compromise, or malicious validator/relayer assumption is needed — an ordinary external user triggering their own `GAS`/`GAS_AND_PAYLOAD` inbound, combined with public DEX trades around the block that finalizes it, is sufficient.

### Recommendation
Do not derive the slippage floor from a spot quote read moments before the swap executes. Bind `minPCOut` to a price the depositor/relayer already agreed to (e.g. carried in the inbound payload and validated by quorum) or to a manipulation-resistant reference (TWAP over a meaningful window, or an off-chain-attested price validated by Universal Validators), and enforce a short, non-zero `deadline` (rather than `deadline = 0`) so the executed price cannot drift arbitrarily from the committed reference. This mirrors the Hypervisor fix's intent — an `amountMin` that reflects the user's actual expectation, not a value re-derived from the same pool being swapped against.

### Proof of Concept
1. Attacker submits (or waits for) a `GAS`/`GAS_AND_PAYLOAD` inbound (their own, or any user's) whose PRC20→PC autoswap will be executed by `x/uexecutor` once validator votes reach quorum.
2. Attacker monitors the mempool/validator-vote flow for the block in which `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` will run `GetSwapQuote` + `CallPRC20DepositAutoSwap`.
3. In the same block, immediately before that execution, attacker submits a large swap against the WPC/PRC20 pool that depresses the PRC20→WPC price.
4. The module's `GetSwapQuote` call (x/uexecutor/keeper/evm.go:502-538) reads this manipulated price; `minPCOut` (95% of that manipulated quote) is computed and passed to `depositPRC20WithAutoSwap` with `deadline=0`.
5. The module's swap executes at the manipulated, depressed rate — within the "protected" 5% band, which is meaningless since the band itself moved with the manipulation.
6. Attacker immediately reverses their pool position (back-run) in the same or next block, restoring the price and pocketing the spread extracted from the module's swap. [6](#0-5)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// getSwapQuoteForRefund fetches a Uniswap quote for the gas token refund swap.
func (k Keeper) getSwapQuoteForRefund(ctx sdk.Context, gasToken common.Address, fee *big.Int, amount *big.Int) (*big.Int, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(ctx)
	if err != nil {
		return nil, err
	}
	wpcAddr, err := k.GetUniversalCoreWPCAddress(ctx)
	if err != nil {
		return nil, err
	}
	return k.GetSwapQuote(ctx, quoterAddr, gasToken, wpcAddr, fee, amount)
}
