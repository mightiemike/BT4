### Title
Webhook HMAC does not bind shop domain/topic, enabling cross-tenant webhook signature replay - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
The webhook authentication path verifies only that `HMAC(apiSecretKey, rawBody)` matches the `X-Shopify-Hmac-Sha256` header. The `X-Shopify-Shop-Domain` and `X-Shopify-Topic` headers that determine which merchant's offline session is loaded and which app-registered handler is invoked are never included in the signed material, so any request with a previously-observed valid `(rawBody, hmac)` pair can be replayed with attacker-chosen domain/topic headers and will pass validation.

### Finding Description
`validateHmacFromRequestFactory` computes `validHmac = validateHmacString(config, rawBody, hmac, HashFormat.Base64)`, i.e. the local HMAC is derived solely from `rawBody` and the app-wide `apiSecretKey` [5](#0-4) . Once this check passes, `checkWebhookHeaders` simply reads `domain`, `topic`, `webhookId`, and `apiVersion` from the (unauthenticated) headers and returns them as trusted fields without any relation to the HMAC computation [6](#0-5) . Because `apiSecretKey` is a single per-app secret shared across every shop that installs the app (not a per-shop secret), any actor who can trigger one legitimate webhook delivery to their own store obtains a valid `(rawBody, hmac)` pair signed with that same secret. That pair can then be POSTed again to the app's webhook endpoint with a forged `X-Shopify-Shop-Domain` (and/or `X-Shopify-Topic`) header pointing at a different, victim shop, and the HMAC check will still succeed since the header values are not part of the signed data.

Downstream, `webhookCheck.domain` is passed unmodified into `ensureValidOfflineSession(params, check.domain)` to load and attach the victim shop's offline `Session`/access token to the request context, and `webhookCheck.topic` selects which registered handler callback runs against attacker-controlled `rawBody` [3](#0-2) , [4](#0-3) . This is the same bug class described in the reference report: an authenticity check (`isValidSignature`/HMAC) that does not bind the full context (chain/domain equivalent) of the signed data, permitting reuse of a legitimately-produced signature against a different target context.

### Impact Explanation
An attacker who controls or can trigger webhook-eligible events on their own installed store (e.g. creating an order, updating a product, or receiving `APP_UNINSTALLED`) can capture a genuine `(rawBody, hmac)` pair and replay it against the shared webhook endpoint while spoofing `X-Shopify-Shop-Domain` for an arbitrary other shop that has installed the same app. Depending on which handlers are registered, this can cause the app to: load and act with another merchant's offline access token (`ensureValidOfflineSession`), execute business logic (e.g. `APP_UNINSTALLED` cleanup, data deletion, order processing) attributed to a shop the attacker does not control, and process attacker-influenced body content under a victim's session context — a cross-tenant integrity/authorization violation.

### Likelihood Explanation
This is reachable by any unauthenticated party that can obtain one valid webhook delivery from Shopify to any shop installed on the target app (including their own store), which is trivial to obtain (installing the app on a free/dev store and triggering an event). No secret leakage or privileged access is required beyond normal merchant-level interaction with the app.

### Recommendation
Bind the authoritative request context into the HMAC input (or otherwise cryptographically verify it), e.g. compute the HMAC over `rawBody` concatenated with `X-Shopify-Shop-Domain`, `X-Shopify-Topic`, and `X-Shopify-Webhook-Id`, or use `X-Shopify-Webhook-Id` uniqueness plus per-shop session validation to reject cross-tenant mismatches before dispatching to handlers/session lookup. At minimum, cross-check that the resolved `domain` corresponds to a shop with an active session state consistent with how/when the webhook subscription was registered, and reject replays of a `webhookId` already processed.

### Proof of Concept
1. Install the target app on attacker-controlled shop `attacker.myshopify.com`; trigger an event whose webhook is subscribed (e.g. update a product), capturing the raw POST body `B` and its `X-Shopify-Hmac-Sha256: H` header from the delivered webhook.
2. Send a new POST to the app's webhook endpoint with the same body `B` and header `H`, but set `X-Shopify-Shop-Domain: victim.myshopify.com` (and `X-Shopify-Topic` if desired for a different handler).
3. `validateHmacFromRequestFactory` recomputes `HMAC(apiSecretKey, B)`, matches `H`, and returns `valid: true` [7](#0-6) ; `checkWebhooksHeaders` reports `domain: 'victim.myshopify.com'` without further verification [8](#0-7) .
4. The app framework calls `ensureValidOfflineSession(params, 'victim.myshopify.com')` and dispatches the registered handler for the (possibly attacker-chosen) topic with body `B`, executing app logic in the victim shop's session context.

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };
}

function checkWebhooksHeaders(

  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);

    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };

  const name = getHeader(headers, headerNames.name);
  if (name) fields.name = name;

  const triggeredAt = getHeader(headers, headerNames.triggeredAt);
  if (triggeredAt) fields.triggeredAt = triggeredAt;

  const eventId = getHeader(headers, headerNames.eventId);
  if (eventId) fields.eventId = eventId;

  return {valid: true, ...fields};
