### Title
Truncated Per-Voter Reward Distribution Causes Unrecoverable Dust Accumulation in Vote-Reward Pool - (File: chainbase/src/main/java/org/tron/core/service/MortgageService.java)

### Summary
The vote-reward payout in `MortgageService` proportionally splits a witness's per-cycle reward pool (`DelegationStore.addReward`) among voters using integer/BigInteger division that truncates the result for each voter. The sum of the truncated per-voter distributions can be strictly less than the total reward credited to the pool for that witness/cycle, and the shortfall is never tracked, redistributed, or reclaimable by any account — it is permanently and silently lost, analogous to the `TwabRewards` "dust that cannot be claimed" finding, but here there is no admin/skim mechanism at all.

### Finding Description
`payReward` credits a witness's cycle reward pool via `delegationStore.addReward(cycle, witnessAddress, value)` [1](#0-0) . When a voter withdraws, `computeReward` divides that pool amount among voters proportionally to their vote share, using either the old floating point path:
```
double voteRate = (double) userVote / totalVote;
reward += voteRate * totalReward;
``` [2](#0-1) 
or the new VI-based path that truncates via integer `BigInteger` division:
```
reward += deltaVi.multiply(BigInteger.valueOf(userVote))
    .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
``` [3](#0-2) 

Both paths independently round the reward down (floor) for each individual voter. `DelegationStore.getReward`/`addReward` simply store a running total per (cycle, witness) key and are never decremented by the amounts actually paid out — there is no accounting reconciliation step that tracks the difference between what was allocated to the pool and what was actually distributed to voters [4](#0-3) . The identical truncation pattern is duplicated in the TVM-reachable `VoteRewardUtil.computeReward` used by `WithdrawRewardProcessor`/`Program.withdrawReward`, meaning this is reachable both via the standard `WithdrawBalanceContract` broadcast transaction path and via the `withdrawReward` TVM native contract callable from any smart contract [5](#0-4) [6](#0-5) .

Unlike the `TwabRewards` case (ERC20 tokens deposited up front and stuck in the contract), the java-tron reward pool is not a pre-funded balance but an accounting ledger updated at block-reward time; nonetheless the effect is the same in spirit: any residual reward amount lost to floor-rounding across all voters for a witness/cycle is never made available to any account (voter, witness, or admin) — it is simply never paid, with no mechanism to sweep, re-aggregate, or reclaim it.

### Impact Explanation
This is a low-severity accounting/economic-inefficiency issue rather than a fund-theft or consensus-safety bug: no unrecoverable existing user balance is locked (the reward pool is credited via inflation-style issuance at block-reward time, not by depositing pre-existing user funds), and per-voter/per-cycle rounding losses are individually tiny (sub-unit of the smallest divisible token amount, bounded by number of distinct voters per witness per cycle). Over long periods and many witnesses/cycles, these losses accumulate into a permanent, unrecoverable shortfall against the nominally "allocated" reward pool, but it does not directly cause consensus divergence (all full nodes execute the same deterministic truncation) nor grant any party unauthorized funds.

### Likelihood Explanation
The truncation occurs on essentially every reward withdrawal that has more than one voter with non-evenly-divisible vote shares, making the dust-accrual condition highly likely to occur continuously in normal network operation; however, exploitation for direct profit is not possible, and the amounts involved per instance are negligible.

### Recommendation
Consider tracking cumulative rounding remainders per (cycle, witness) so a small residual amount is either carried forward into the next cycle's pool for the same witness, or made available for periodic sweep/reclamation (e.g., credited back to the transaction-fee pool or the burn/blackhole account) rather than being silently discarded, mirroring the recommended-mitigation pattern from the referenced report (periodic admin/protocol-level skim of inactive dust rather than allowing indefinite unclaimable accrual).

### Proof of Concept
Not applicable in the traditional PoC sense — the truncation is deterministic arithmetic reachable by any voter calling `WithdrawBalanceContract` (`WithdrawBalanceActuator.execute` → `MortgageService.withdrawReward` → `computeReward`) [7](#0-6) , or any smart contract invoking the `withdrawReward` TVM opcode path [8](#0-7) . Each such call, for witnesses with multiple voters whose vote-share division is not exact, produces a per-voter reward strictly less than the mathematically proportional share, and the aggregate difference across all voters for that witness/cycle is never subsequently accounted for or reclaimed anywhere in `DelegationStore` or `MortgageService`.

  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }

  private static long computeReward(long beginCycle, long endCycle,
                                    AccountCapsule accountCapsule, Repository repository) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    for (Protocol.Vote vote : accountCapsule.getVotesList()) {
      byte[] srAddress = vote.getVoteAddress().toByteArray();
      BigInteger beginVi = repository.getDelegationStore().getWitnessVi(beginCycle - 1, srAddress);
      BigInteger endVi = repository.getDelegationStore().getWitnessVi(endCycle - 1, srAddress);
      BigInteger deltaVi = endVi.subtract(beginVi);
      if (deltaVi.signum() <= 0) {
        continue;
      }
      long userVote = vote.getVoteCount();
      reward += deltaVi.multiply(BigInteger.valueOf(userVote))
          .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
    }
    return reward;
  }

  public long execute(WithdrawRewardParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getOwnerAddress();

    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    long oldBalance = accountCapsule.getBalance();
    long allowance = accountCapsule.getAllowance();
    long newBalance = 0;

    try {
      newBalance = LongMath.checkedAdd(oldBalance, allowance);
    } catch (ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractExeException(e.getMessage());
    }

    // If no allowance, do nothing and just return zero.
    if (allowance <= 0) {
      return 0;
    }

    accountCapsule.setInstance(accountCapsule.getInstance().toBuilder()
        .setBalance(newBalance)
        .setAllowance(0L)
        .setLatestWithdrawTime(param.getNowInMs())
        .build());

    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
    return allowance;
  }

  public long withdrawReward() {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, owner, 0, null,
        "withdrawReward", nonce, null);

    WithdrawRewardParam param = new WithdrawRewardParam();
    param.setOwnerAddress(owner);
    param.setNowInMs(getTimestamp().longValue() * 1000);
    try {
      WithdrawRewardProcessor processor = new WithdrawRewardProcessor();
      processor.validate(param, repository);
      long allowance = processor.execute(param, repository);
      repository.commit();
      if (internalTx != null) {
        internalTx.setValue(allowance);

      return allowance;

      logger.warn("TVM WithdrawReward: validate failure. Reason: {}", e.getMessage());
    } catch (ContractExeException e) {
      logger.warn("TVM WithdrawReward: execute failure. Reason: {}", e.getMessage());
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return 0;
