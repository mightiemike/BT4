### Title
Batch-prover JSON-RPC methods that mutate proving state and submit DA transactions have no access control - (File: `crates/common/src/rpc/auth.rs`, `crates/batch-prover/src/rpc.rs`)

### Summary
The Auth middleware that gates the node's JSON-RPC surface only protects three method names (`backup_create`, `backup_validate`, `backup_info`); every other method, including the batch-prover's state-mutating RPCs, is dispatched to any caller with network access, with no whitelist/role check analogous to the modifier the external report recommends for `flexGovernanceAdapater`.

### Finding Description
`Auth::call` only requires an API key for `PROTECTED_METHODS`: [1](#0-0) 
Any method not in that 3-entry list, including `batchProver_setCommitments`, `batchProver_prove`, `batchProver_submitFakeProof`, `batchProver_pauseProving`, and `batchProver_createCircuitInput`, is forwarded unauthenticated: [2](#0-1) 

- `setCommitments` overwrites the prover's ledger view of sequencer commitments ("overrides the commitment already if exists, so use with caution").
- `submitFakeProof` builds a `FakeReceipt`/`InnerReceipt::Fake` from ledger-derived state roots and submits it as a `DaTxRequest::ZKProof` transaction to the DA layer under the batch prover's own signing identity: [3](#0-2) [4](#0-3) 
- `pauseProving` and `prove` control the internal `ProverRequest` channel that starts/stops the real proving loop: [5](#0-4) 

This is the same class of bug as the report: functions meant to be invoked only by a trusted operator/service accept calls from anyone able to reach the RPC endpoint, because no modifier/whitelist check restricts callers before mutating authoritative proving/commitment state or emitting a DA transaction under the prover's identity.

### Impact Explanation
An unauthenticated caller can overwrite the batch prover's tracked commitment set (`setCommitments`), halt real proving (`pauseProving`), or force a DA submission of a proof object (`submitFakeProof`) under the batch prover's DA key/identity without the operator's consent. Whether the fake receipt is ultimately accepted as a valid state transition downstream depends on the zkVM verifier configuration used by full nodes and the light-client circuit at the time (`code_commitments_by_spec`/receipt verification path), which I could not fully trace in this session; I could not confirm from the indexed code whether production risc0 verification rejects `InnerReceipt::Fake` in all deployed configurations. Independent of that uncertainty, the ability for any unauthenticated party to mutate the prover's commitment bookkeeping and pause/resume its core proving loop is itself a state-mutating, unauthenticated RPC call, matching the "High - unauthenticated JSON-RPC call that mutates node state or bypasses `Auth`" bucket.

### Likelihood Explanation
High if the batch-prover RPC port is reachable by the same network population that can reach other JSON-RPC endpoints, since no credential, signature, or IP allow-list is required — only network reachability, exactly like the unprotected `flexGovernanceAdapater` functions in the reference report.

### Recommendation
Extend the `PROTECTED_METHODS` allow-list (or introduce a dedicated operator-only auth layer) to cover all state-mutating batch-prover (and sequencer `citrea_haltCommitments`/`citrea_resumeCommitments`) RPC methods, requiring the same API-key/whitelist check used for `backup_*` methods before `setCommitments`, `prove`, `submitFakeProof`, `pauseProving`, and `createCircuitInput` are dispatched.

### Proof of Concept
1. Start a batch-prover node with its JSON-RPC port reachable.
2. Without any API key, call `batchProver_submitFakeProof(index_start, index_end)` or `batchProver_setCommitments([...])` directly via `jsonrpsee` client, as done in the test harness: [6](#0-5) 
3. Observe the call succeeds and mutates prover state / submits a DA transaction, with no authentication check performed, because the method name is absent from `PROTECTED_METHODS`.

    async fn submit_fake_proof(
        &self,
        index_start: u32,
        index_end: u32,
    ) -> RpcResult<BatchProofResponse> {
        info!(
            "Submitting fake proof for commitment index range [{},{}]",
            index_start, index_end
        );

        let ledger_db = &self.context.ledger_db;

        if index_start > index_end {
            return Err(internal_rpc_error("Invalid index range"));
        }
        // don't allow first commitment index to be called through this rpc as it requires extra handling
        if index_start <= 1 {
            return Err(internal_rpc_error(
                "submitFakeProof rpc supports only index_start > 1",
            ));
        }

        let previous_commitment = ledger_db
            .get_commitment_by_index(index_start - 1)
            .map_err(internal_rpc_error)?
            .ok_or_else(|| internal_rpc_error("Missing previous commitment index"))?;

        let commitments = ledger_db
            .get_commitment_by_range(index_start..=index_end)
            .map_err(internal_rpc_error)?;
        if commitments.len() as u32 != index_end - index_start + 1 {
            return Err(internal_rpc_error(
                "Missing some commitment indices from the range",
            ));
        }

        let last_commitment = commitments.last().expect("Already ensured");
        let last_l2_block = ledger_db
            .get_l2_block_by_number(&L2BlockNumber(last_commitment.l2_end_block_number))
            .map_err(internal_rpc_error)?
            .ok_or_else(|| internal_rpc_error("Not synced up to latest L2 block yet"))?;

        let initial_state_root = ledger_db
            .get_l2_state_root(previous_commitment.l2_end_block_number)
            .map_err(internal_rpc_error)?
            .expect("Initial L2 state root must exist");

        let mut start_l2_height = previous_commitment.l2_end_block_number + 1;
        let mut sequencer_commitment_hashes = Vec::with_capacity(commitments.len());
        let mut state_roots = Vec::with_capacity(commitments.len() + 1);
        state_roots.push(initial_state_root);

        let mut cumulative_state_diff = CumulativeStateDiff::new();
        for commitment in commitments.iter() {
            let end_l2_height = commitment.l2_end_block_number;

            for l2_height in start_l2_height..=end_l2_height {
                let state_diff = ledger_db
                    .get_l2_state_diff(L2BlockNumber(l2_height))
                    .map_err(internal_rpc_error)?
                    .expect("L2 state diff must exist");
                cumulative_state_diff.extend(state_diff);
            }

            sequencer_commitment_hashes.push(commitment.serialize_and_calculate_sha_256());

            let end_state_root = ledger_db
                .get_l2_state_root(end_l2_height)
                .map_err(internal_rpc_error)?
                .expect("L2 state root must exist");
            state_roots.push(end_state_root);

            start_l2_height = end_l2_height + 1;
        }
