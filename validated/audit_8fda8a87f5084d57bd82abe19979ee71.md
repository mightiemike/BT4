Confirmed: the blockifier's native/VM execution path enforces two checks in `replace_class` that the Starknet OS Cairo re-execution path does not enforce at all.

### Title
Missing declared-class validation in OS `execute_replace_class` causes state divergence between blockifier execution and OS re-execution - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The blockifier's Rust implementation of the `replace_class` syscall requires the target class hash to be declared and of Cairo1 type before mutating a contract's class hash. The Starknet OS Cairo implementation of the same syscall, `execute_replace_class`, performs neither check — it is an explicitly acknowledged TODO in the code.

### Finding Description
In `crates/blockifier/src/execution/syscalls/syscall_base.rs`, `replace_class` is guarded: [1](#0-0) 
It calls `self.state.get_compiled_class(class_hash)?` to ensure the class is declared, rejects non-Cairo1 classes with `ForbiddenClassReplacement`, and only then calls `set_class_hash_at`.

In contrast, the Starknet OS's Cairo implementation of the same syscall, `execute_replace_class` in `syscall_impls.cairo`, unconditionally writes the requested `class_hash` into the contract's state entry with no check that the class was ever declared, and no check on its Cairo version: [2](#0-1) 
Note the explicit `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment at line 902 confirming the check is known to be missing. The deprecated syscall variant `execute_replace_class` in `deprecated_execute_syscalls.cairo` has the identical gap: [3](#0-2) 

The blockifier is used by the sequencer to execute transactions when building blocks (determining what is accepted/rejected and what the resulting state is), while the Starknet OS Cairo program is used to re-execute the same block for proving/state-commitment purposes. Since the two implementations enforce different constraints on the same syscall, a contract that legitimately calls `replace_class_syscall` with an undeclared (or Cairo0) class hash will be **rejected by the blockifier** (transaction reverts, `ForbiddenClassReplacement`/`StateError` raised, so the block builder never commits this state change) but the **OS accepts it unconditionally** if it ever needs to re-execute or verify such a call reconstructed from any other execution path (e.g. via a different state-reading path, an override, or future change that relaxes the blockifier-side check while the OS remains permissive, or vice versa if the OS's un-declared write ever gets included in a state diff it re-derives). More concretely, this is a source of consensus-critical logic drift: the syscall's semantics (validity of `ReplaceClass`) are duplicated in two independently-maintained code paths (Rust blockifier vs. Cairo OS program), and they currently disagree on what constitutes a valid class replacement. Any divergence in accepted/rejected syscall semantics between the block-building engine and the block re-execution/proving engine is a state-root/commitment correctness bug class, because the OS's re-execution — which underlies the STARK proof of the block and the Starknet OS's own state root computation — must exactly match what the sequencer actually committed.

### Impact Explanation
If the OS ever performs a replace_class write that the blockifier would have rejected (or accepts a broader set of class hashes, including undeclared/non-existent ones), the state root computed by the Starknet OS during proving will not match the state actually committed by the sequencer/blockifier during block building. This is exactly the "wrong committed root / honest-node divergence" failure class: the network could produce a proof or committed state that diverges from the sequencer's blockifier-derived state, undermining the guarantee that OS re-execution faithfully reproduces sequencer execution. It is also a correctness gap that could let a contract's class hash be replaced with an undeclared class hash during OS-side execution/verification, silently breaking invariants that class hashes always refer to declared classes.

### Likelihood Explanation
Every Cairo1 contract that includes a `replace_class_syscall` call reaches this code path, using only a normal transaction from an unprivileged sender — no special privileges are required to trigger `ReplaceClass`. The divergence is deterministic and reachable through the standard syscall execution flow (`execute_syscalls.cairo` selects `execute_replace_class` for `REPLACE_CLASS_SELECTOR`), rather than requiring an unusual internal state; the only remaining uncertainty is exactly which real-world call sequence exercises the OS-side under-checking versus the blockifier's rejection in the current implementation, since I could not trace every state-reader override that might normally cause the OS-side read of `GetContractAddressStateEntry` to also fail for undeclared classes (this hint-side behavior was not fully explorable in the given time).

### Recommendation
Add the equivalent declared-class (and Cairo1-only) check to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring `syscall_base.rs::replace_class`'s `get_compiled_class` + `is_cairo1` checks, so that the OS's semantics for `ReplaceClass` are provably identical to the blockifier's.

### Proof of Concept
1. A Cairo1 contract calls `replace_class_syscall(undeclared_or_cairo0_class_hash)`.
2. Under the blockifier (`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`), this call fails with `StateError` (class not found) or `ForbiddenClassReplacement` — the transaction reverts and the contract's class hash is unchanged in the committed block.
3. Under the Starknet OS Cairo re-execution (`syscall_impls.cairo:881-920` / `deprecated_execute_syscalls.cairo:307-329`), the same syscall unconditionally overwrites the contract's `class_hash` in `contract_state_changes` with no declared-class or version check.
4. Because the two independently implemented enforcement paths for the identical syscall diverge, any code path that relies on the OS's permissiveness (or any future maintenance change to either side without updating the other) can produce a state/root mismatch between the block actually committed by the sequencer and the state re-derived by the Starknet OS for proving.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
