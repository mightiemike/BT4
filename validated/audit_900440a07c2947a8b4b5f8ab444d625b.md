## Valid Analog Found

### Title
Permanent `rlp_execute` lockout of ETH-implicit accounts via un-recoverable `has_in_flight_tx` flag - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
`WalletContract` (the NEAR Wallet Contract deployed on every ETH-implicit account) guards re-entrancy with a single boolean, `has_in_flight_tx`, that is set to `true` before scheduling any outbound promise and is only reset to `false` at the very start of the corresponding private callback. If a scheduled callback (`address_check_callback`, `nep_141_storage_balance_callback`, or `rlp_execute_callback`) ever fails to complete successfully as a whole (e.g. it panics mid-execution, including from an out-of-gas condition while scheduling the next chained promise), the entire state mutation of that callback — including the `has_in_flight_tx = false` reset — is rolled back by the runtime, while the previously-committed `true` value remains on chain forever. Because `rlp_execute` immediately rejects any call while `has_in_flight_tx` is `true`, and because no other public/administrative method exists to clear the flag, the account becomes permanently unusable: it can never again process a transfer, function call, key management action, or any other operation, freezing any funds held by that account forever.

### Finding Description
The contract stores `has_in_flight_tx` as its only re-entrancy guard [1](#0-0) . `rlp_execute` refuses to run while the flag is `true`, and only sets it after successfully constructing an outbound `Promise` [2](#0-1) . Multi-hop flows (`EOABaseTokenTransfer` with address check, `ERC20Transfer`) chain a second promise via `address_check_callback` / `nep_141_storage_balance_callback`, which unconditionally reset the flag to `false` as their first statement and only re-set it to `true` after successfully scheduling the next promise in the chain [3](#0-2)  and [4](#0-3) . The gas budget for each hop is derived from attacker/relayer-supplied `action.gas()` plus a small fixed margin (`ADDRESS_CHECK_CALLBACK_GAS`, `NEP_141_STORAGE_BALANCE_CALLBACK_GAS`) [5](#0-4) , with no protocol-level or contract-level upper/lower bound validation ensuring that margin is always sufficient for the callback's own execution cost (JSON (de)serialization, string formatting, nested promise construction). Since NEAR reverts *all* state writes of a call that panics, any panic inside these callback functions — including a legitimate `ExceededPrepaidGas` failure — discards the `has_in_flight_tx = false` write while the previously committed `true` persists in trie state. There is no timeout, watchdog, or reset entry point: `rlp_execute` is the only externally reachable method and it is gated by the very flag that got stuck.

This is the direct analog of the reported bug class: just as `NFTLootbox::createLootbox` lacks bounds on `_duration`/`_priceForPlay` that can leave NFTs stuck forever, the Wallet Contract lacks any bound/validation/fallback ensuring the `has_in_flight_tx` guard can always be cleared, which can leave the entire account (and its funds) stuck forever with no possible input validation fix, misconfiguration, or gas-estimation edge case.

### Impact Explanation
High — a permanently stuck `has_in_flight_tx` flag makes the affected ETH-implicit account completely and irrecoverably inoperable. Since ETH-implicit accounts cannot have a full access key added, cannot be deleted, and can only be operated through `rlp_execute` [6](#0-5) , any NEAR tokens, NEP-141 tokens, or contract permissions held by that account become permanently frozen, matching the report's "NFTs stuck in the contract forever" impact class exactly.

### Likelihood Explanation
Low-to-medium — requires a callback to panic (e.g. an underestimated gas margin for large/complex action payloads, or any other unhandled panic path) after `has_in_flight_tx` was already committed as `true` by a prior successful call. This does not require a malicious validator or network-layer actor; it is reachable purely from a signer/relayer submitting a crafted (but validly signed) Ethereum-emulation transaction through `rlp_execute`, consistent with the "unprivileged transaction signer" reachability requirement.

### Recommendation
Add an explicit, generously-bounded gas reservation check before scheduling any chained promise inside `address_check_callback` / `nep_141_storage_balance_callback` / `rlp_execute` so that insufficient-gas conditions are detected and handled gracefully (returning a failure `ExecuteResponse` while still clearing `has_in_flight_tx`) rather than causing a panic that reverts the flag reset. Additionally, consider adding a stateless, permissionless "unstick" mechanism (e.g., a `#[private]` catch-all cleanup callback with a `#[near_bindgen] #[handle_result]`/`ext_contract` that always executes regardless of upstream failure, or an owner/relayer-independent timeout-based recovery function) so that `has_in_flight_tx` can never remain `true` indefinitely.

### Proof of Concept
1. A relayer submits an `rlp_execute` call carrying an emulated `ERC20Transfer` (or `EOABaseTokenTransfer` with `address_check`) whose downstream `action` (FunctionCall args / method_names) is large enough, or whose nested promise chain gas is tight enough, that the fixed margin (`NEP_141_STORAGE_BALANCE_CALLBACK_GAS` / `ADDRESS_CHECK_CALLBACK_GAS`, only 5–10 Tgas) is insufficient to cover the callback's own WASM execution cost on top of the forwarded `action.gas()`.
2. `rlp_execute` succeeds, persisting `has_in_flight_tx = true` [7](#0-6) .
3. The scheduled second-hop callback (`nep_141_storage_balance_callback` or `address_check_callback`) begins execution, sets `self.has_in_flight_tx = false` in-memory, then panics (e.g. `ExceededPrepaidGas`) while constructing/attaching the next chained promise.
4. Because the callback call fails, none of its state writes — including the `has_in_flight_tx = false` reset — are committed; the on-chain value remains `true`.
5. Every subsequent call to `rlp_execute` for that account immediately short-circuits with "transaction already in progress" [8](#0-7)  forever, with no method available to clear the flag, permanently freezing the account and any funds/tokens it holds.

    #[private]
    pub fn address_check_callback(
        &mut self,
        target: AccountId,
        action: near_action::Action,
        caller_deposit: Option<CallerDeposit>,
    ) -> PromiseOrValue<ExecuteResponse> {
        self.has_in_flight_tx = false;
        let maybe_account_id: Option<AccountId> = match env::promise_result(0) {
            PromiseResult::Failed => {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Call to Address Registrar contract failed".into()),
                });
            }
            PromiseResult::Successful(value) => match serde_json::from_slice(&value) {
                Ok(x) => x,
                Err(_) => {
                    return PromiseOrValue::Value(ExecuteResponse {
                        success: false,
                        success_value: None,
                        error: Some("Unexpected response from account registrar".into()),
                    });
                }
            },
        };
        let current_account_id = env::current_account_id();
        let promise = if maybe_account_id.is_some() {
            // We intentionally do not increment the nonce in this case because the
            // error is caused by a faulty relayer, not the user. An honest relayer
            // may still be able to successfully send the user's intended transaction.
            if env::signer_account_id() == current_account_id {
                create_ban_relayer_promise(current_account_id)
            } else {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Invalid target: target is address corresponding to existing named account_id".into()),
                });
            }
        } else {
            // We must increment the nonce at this point to prevent replay of the transaction.
            // Recall that the nonce was not incremented in `inner_rlp_execute` in the case that
            // the registrar contract was called (i.e. in the case we end up inside this callback).
            self.nonce = self.nonce.saturating_add(1);
            let ext =
                WalletContract::ext(current_account_id).with_static_gas(RLP_EXECUTE_CALLBACK_GAS);
            match action_to_promise(target, action)
                .map(|p| p.then(ext.rlp_execute_callback(caller_deposit)))
            {
                Ok(p) => p,
                Err(e) => {
                    return PromiseOrValue::Value(e.into());
                }
            }
        };
        self.has_in_flight_tx = true;
        PromiseOrValue::Promise(promise)
    }

    #[private]
    pub fn nep_141_storage_balance_callback(
        &mut self,
        token_id: AccountId,
        receiver_id: AccountId,
        action: near_action::Action,
        caller_deposit: Option<CallerDeposit>,
    ) -> PromiseOrValue<ExecuteResponse> {
        self.has_in_flight_tx = false;
        let maybe_storage_balance: Option<StorageBalance> = match env::promise_result(0) {
            PromiseResult::Failed => {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some(format!("Call to NEP-141 {token_id}::storage_balance_of failed")),
                });
            }
            PromiseResult::Successful(value) => match serde_json::from_slice(&value) {
                Ok(x) => x,
                Err(_) => {
                    return PromiseOrValue::Value(ExecuteResponse {
                        success: false,
                        success_value: None,
                        error: Some("Unexpected response from NEP-141 storage_balance_of".into()),
                    });
                }
            },
        };
        let current_account_id = env::current_account_id();
        let ext = WalletContract::ext(current_account_id).with_static_gas(RLP_EXECUTE_CALLBACK_GAS);
        let promise = match maybe_storage_balance {
            Some(_) => {
                // receiver_id is registered so we can send the transfer
                // without additional actions. Note: in the standard NEP-141
                // implementation it is impossible to have `Some` storage balance,
                // but have it be insufficient to transact.
                match action_to_promise(token_id, action)
                    .map(|p| p.then(ext.rlp_execute_callback(caller_deposit)))
                {
                    Ok(p) => p,
                    Err(e) => {
                        return PromiseOrValue::Value(e.into());
                    }
                }
            }
            None => {
                // receiver_id is not registered so we must call `storage_deposit` first.
                let storage_deposit_args =
                    format!(r#"{{"account_id": "{receiver_id}"}}"#).into_bytes();
                let transfer_function_call = match action {
                    near_action::Action::FunctionCall(x) => x,
                    _ => {
                        return PromiseOrValue::Value(ExecuteResponse {
                            success: false,
                            success_value: None,
                            error: Some(
                                "Expected function call action to perform NEP-141 transfer".into(),
                            ),
                        });
                    }
                };
                Promise::new(token_id)
                    .function_call(
                        "storage_deposit".into(),
                        storage_deposit_args,
                        NEP_141_STORAGE_DEPOSIT_AMOUNT,
                        NEP_141_STORAGE_DEPOSIT_GAS,
                    )
                    .function_call(
                        transfer_function_call.method_name,
                        transfer_function_call.args,
                        transfer_function_call.deposit,
                        transfer_function_call.gas,
                    )
                    .then(ext.rlp_execute_callback(caller_deposit))
            }
        };
        self.has_in_flight_tx = true;
        PromiseOrValue::Promise(promise)
    }
