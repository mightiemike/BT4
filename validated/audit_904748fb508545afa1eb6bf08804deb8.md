This maps directly onto a concrete Push Chain analog: the "same-block self-referential quote" pattern used for the auto-swap deposit and gas-refund swap, which provides no real slippage protection since the reference price and the executed trade come from the exact same AMM pool in the same atomic operation.

## Title
Self-referential AMM quote used as slippage bound lets attackers sandwich `depositPRC20WithAutoSwap` / `refundUnusedGas` swaps in `uexecutor` - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`)

## Summary
`GetSwapQuote` reads the *current* spot price from the same Uniswap V3 `QuoterV2`/pool that the module immediately trades against, and derives `minPCOut` as `quote * 95 / 100` [1](#0-0) . This "slippage protection" is self-referential: it bounds the swap relative to the pool's own manipulable current state rather than an external/TWAP reference, so an attacker who moves the pool price immediately before the module's swap executes gets a quote and a `minPCOut` that already reflect the manipulated price, defeating the protection entirely — the same fundamental flaw as the original report's hardcoded-zero minimum-out, just with a cosmetic 5% guard that tracks the manipulated price instead of a real market price.

## Finding Description
The quote-then-swap sequence is used in two places:

1. **Inbound GAS / GAS_AND_PAYLOAD auto-swap** — when processing a user's inbound deposit, the keeper fetches a quote and immediately executes `depositPRC20WithAutoSwap` using `minPCOut` derived from that same quote: [2](#0-1) 

2. **Outbound gas-fee refund** — `applyGasRefund` fetches a swap quote for the excess gas token and immediately calls `CallUniversalCoreRefundUnusedGas` using the same 5%-off-quote pattern: [3](#0-2) 

Both paths call `GetSwapQuote`, which invokes `quoteExactInputSingle` with `SqrtPriceLimitX96: big.NewInt(0)` (no price-limit protection) against the live pool state, in the same keeper invocation that then executes the real swap against that same pool: [4](#0-3) . There is no TWAP, no oracle cross-check, and no reference to a price recorded before the transaction was broadcast — the "protection" is computed from, and compared against, the exact same manipulable state used for the trade.

These swaps execute as part of ordinary `MsgVoteInbound` / `MsgVoteOutbound` message processing, which (unlike the original report's Gelato-keeper-only paths) are broadcast through Push Chain's normal public mempool by any validator/relayer submitting votes for user-initiated inbound/outbound events. An unprivileged actor observing the mempool can front-run the vote transaction (or the block containing it) with a trade that moves the WPC/PRC20 pool price, causing the module's own quote-and-swap to execute against the manipulated price and back-run to restore it and capture the difference — a classic sandwich, but structurally guaranteed to succeed because the slippage bound is derived from the very state being manipulated.

## Impact Explanation
This directly corrupts PRC20/native asset accounting for ordinary users: victims performing GAS/GAS_AND_PAYLOAD inbound deposits receive less PC/PRC20 than the honest market rate, and outbound gas-fee refunds return less than the true excess gas amount, with the difference extracted by the attacker. This is unauthorized value drain from user/protocol-controlled funds reachable purely through default inbound/outbound transaction submission — squarely in-scope under "corruption of PRC20 or native asset accounting ... must not misroute value."

## Likelihood Explanation
Reachable by any unprivileged actor with mempool visibility and capital to trade the WPC/target-PRC20 pool; no validator or admin collusion is required. The trigger conditions (a user deposit/withdrawal routed through the auto-swap or refund path) occur in normal operation, and the fixed 5% band is a wide, predictable target for sandwiching, especially on lower-liquidity PRC20 pairs.

## Recommendation
Do not derive the slippage floor from a quote fetched immediately before the trade against the same pool. Use a TWAP-based reference price (or an external price oracle) for `minPCOut`, allow the amount to be configured by the requesting flow rather than hardcoded to a fixed percentage of the manipulable spot quote, and/or set a non-zero `sqrtPriceLimitX96` bound derived from a trusted reference price so a single-block manipulation cannot pass the check.

## Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` (or the vote reaching quorum) for a GAS/GAS_AND_PAYLOAD inbound in the public mempool.
2. Attacker submits a large trade against the WPC/PRC20 Uniswap V3 pool used by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`, pushing the price against the direction of the module's upcoming swap, ordered before the vote transaction in the block.
3. The vote transaction executes `ExecuteInboundGas` → `GetSwapQuote` (reads the now-manipulated price) → `minPCOut = quote*95/100` → `CallPRC20DepositAutoSwap`, which executes at the manipulated price and satisfies `minPCOut` trivially since both are derived from the same distorted state [5](#0-4) .
4. Attacker submits a reverse trade immediately after, restoring the pool price and pocketing the value difference at the expense of the depositor (or, in the refund case, the gas-fee-refund recipient).

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
