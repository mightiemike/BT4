### Title
`accrue` pause silently no-ops while `deposit`/`redeem`/`system-borrow`/`system-repay` continue to mutate state against a stale index — (File: `mainnet/contracts/vault/v0-vault-usdc.clar`, and mirrored in every other v0 vault)

### Summary
Each Zest vault (`v0-vault-usdc.clar`, `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`) exposes a DAO-settable `pause-states` map with an `accrue` flag. When `accrue` is set to `true`, the public `accrue` function becomes a pure pass-through that returns the *current* `index`/`lindex` without recomputing or persisting them, instead of reverting. However, the flag only guards `accrue` itself — every state-changing entrypoint that depends on an up-to-date exchange rate (`deposit`, `redeem`, `system-borrow`, `system-repay`) still calls `accrue` and proceeds normally regardless of the outcome, converting shares/assets using whatever `index`/`lindex` happen to be in storage.

### Finding Description
`accrue` is defined identically in all vaults: [1](#0-0) 

```
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ...
```

When `accrue` is paused, `next-index`/`next-liquidity-index` are never computed and `index`/`lindex`/`last-update` are never persisted — interest that has economically accrued between the last update and now is simply dropped for as long as the pause is active. This is the "clock advanced only on change" / "pause that passes through instead of reverting" analog: the value that should be invalidated (the stale index representing the exchange rate) is not recomputed, yet the guard that should stop callers from relying on it does not exist.

Every value-moving entrypoint still runs `(u (try! (accrue)))` and continues unconditionally on the `ok` result — it never checks whether accrual actually happened: [2](#0-1) 

```
(define-public (redeem (amount uint) (min-out uint) (recipient principal))
  (let (
    (states (var-get pause-states))
    (u (try! (accrue)))
    ...
    (inkind (convert-to-assets-preview amount)))
  (asserts! (>= current-assets inkind) ERR-INSUFFICIENT-ASSETS)
  (asserts! (not (get redeem states)) ERR-PAUSED)
  ...
  (try! (ft-burn? zft amount account))
  (try! (send-underlying inkind recipient))
  ...
```

`system-borrow` and `system-repay` follow the same pattern: they call `accrue` (a no-op while paused), then still mutate `principal-scaled`/`total-borrowed` using the stale `index`: [3](#0-2) 

Only `deposit`, `redeem`, `borrow`, `repay`, and `flashloan` have their own dedicated pause flags checked with `asserts!`. There is no flag that blocks `deposit`/`redeem`/`system-borrow`/`system-repay` specifically when `accrue` is paused, nor is there any check inside those functions that `accrue` actually advanced the index before trusting `convert-to-assets-preview`/`convert-to-shares-preview` (which are built on `index`/`lindex`). This mirrors the HydraDX bug class precisely: a security parameter (`Tradability` state / here `pause-states.accrue`) is used to disable the mechanism that keeps a price/rate honest (`ensure_price` / here the index update), while the operations that depend on that rate (`remove_liquidity`/`add_liquidity` / here `deposit`/`redeem`/`system-borrow`/`system-repay`) are left fully enabled and execute against the now-frozen value.

### Impact Explanation
While `accrue` is paused:
- Borrowers keep taking on debt via `system-borrow`/being repaid via `system-repay`, and depositors/redeemers keep minting/burning zTokens, all priced off a `index`/`lindex` pair that is frozen at the value from the moment the pause began.
- Interest that continues to accrue economically during the pause window is never materialized into `index`/`lindex`, so it is permanently skipped rather than merely delayed for redemptions/mint conversions executed during the pause — any LP who deposits or redeems while `accrue` is paused transacts at a stale, incorrect exchange rate rather than the fair one, diluting or shortchanging other zToken holders' claim on accrued yield.
- This lands on the in-scope impact class of theft/loss of unclaimed yield for LPs, and, since the true backing/exchange-rate relationship between shares and assets is broken for the duration of the pause, it also creates a temporary freezing of the correct redemption value of funds until an unpause allows accrual to "catch up" (if at all, since the intervening yield delta was never recorded).

### Likelihood Explanation
`pause-states` is settable by the DAO/authorized admin, exactly as `set_asset_tradable_state` was authority-gated in the original finding — the judge in the original report still rated this Medium severity because such an "intended" edge case can still be triggered accidentally or exploited around a known pause window (e.g., pausing `accrue` briefly for maintenance while forgetting `deposit`/`redeem` remain open), and any user (not just the admin) can call `deposit`/`redeem`/trigger `system-borrow`/`system-repay` during that window without any special permission.

### Recommendation
Gate `deposit`, `redeem`, `system-borrow`, and `system-repay` on the same `accrue` pause flag (or have them revert if `accrue` did not actually update `index`/`lindex` when it should have), so that no state-changing, rate-dependent operation can execute while the source of truth for the exchange rate is frozen.

### Proof of Concept
1. DAO/admin sets `pause-states.accrue = true` on `v0-vault-usdc` (a legitimate action per its own design, no compromise required).
2. Time passes; debt interest that should raise `index`/`lindex` is never applied because `accrue` short-circuits to `(ok { index: idx, lindex: lidx })`. [4](#0-3) 
3. A user calls `redeem`, which still calls `accrue` (no-op) and then computes `inkind` via `convert-to-assets-preview`, burning shares and sending underlying at the stale, incorrect rate instead of reverting. [2](#0-1) 
4. Simultaneously, `system-borrow`/`system-repay` keep mutating `principal-scaled`/`total-borrowed` against the same stale `index`, so the yield differential accrued during the pause is permanently lost from the accounting rather than caught up later. [3](#0-2)
