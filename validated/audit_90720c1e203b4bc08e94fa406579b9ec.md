### Title
Zero-valued gas conversion rate in `balanceStore.convertToBalance` silently zeroes out billing deductions instead of failing open into metering mode - (`core/services/workflows/metering/balance_store.go`)

### Summary
`balanceStore.convertToBalance`, used by `ByResource` to deduct credits for a capability's resource usage, has a special case for gas spend types: if the configured conversion rate for that gas resource is `0`, the function returns `decimal.Zero` with **no error**, instead of surfacing an error that would trigger the metering module's fail-safe ("metering mode"). This mirrors the ZcToken bug class where a rate that is legitimately `0` (e.g., because it hasn't been populated yet, or a chain/resource is genuinely unpriced) is used directly in a financial computation without distinguishing "unset/invalid" from "intentionally free," resulting in a silent zero result that understates the actual cost owed.

### Finding Description
`convertToBalance` looks up the conversion rate for a resource type and, for gas spend types, explicitly short-circuits to zero when the rate is zero: [1](#0-0) 

This differs from the "resource not found" path, which returns `ErrResourceTypeNotFound` and is treated by callers as a signal to `switchToMeteringMode`, a deliberate fail-open safety mechanism: [2](#0-1) 

In `ByResource`, the deduction from the local credit balance is computed via `ConvertToBalance`. If the gas rate happens to be `0` (whether because the billing service has not yet populated a rate for that particular chain selector, returns a default/placeholder `"0"`, or any other reason the rate is unset), `ConvertToBalance` returns `(0, nil)` — no error — so `step.Deduction` is `0` and `r.balance.Minus(0)` leaves the balance untouched, even though the capability actually consumed gas-priced resources. Unlike the `ErrResourceTypeNotFound` case, this path does **not** trigger `switchToMeteringMode`, so the report proceeds in normal accounting mode believing the capability call was properly billed.

This is confirmed as expected/tested behavior for the "gas rate = 0" case in the settle path as well, where a `GasTokensPerCredit` entry of `"0"` is documented to "convert to 0 credits": [3](#0-2) 

The root cause is structurally identical to the ZcToken bug: a stored/derived rate value that can be `0` for two different reasons (legitimately free vs. not-yet-populated/misconfigured) is consumed directly in a monetary calculation without any explicit check or fallback, so downstream code cannot distinguish "intentionally free" from "erroneously zero," and the result is a silent zero-cost outcome rather than a safe failure.

### Impact Explanation
If a gas-denominated resource type's conversion rate is ever `0` for reasons other than an intentional "this chain/action is free" policy (e.g., a new chain selector not yet populated in `GasTokensPerCredit`, a billing-service response omission, or a data error), workflow executions that consume that gas-priced resource will not have their local credit balance debited at all for that spend, and the metering system will not switch into its safety "metering mode." This constitutes billing/metering data tampering: capability usage that should cost credits is unmetered, allowing a workflow owner to consume gas-priced capability resources without being charged, undermining the accounting integrity that `Report`/`balanceStore` are meant to guarantee.

### Likelihood Explanation
Reachable by any unprivileged workflow owner simply by invoking a capability with a `GAS.<chainSelector>` spend type for a chain whose rate happens to resolve to `0` in the billing service's rate card response — no special privileges are required, only that the billing service returns (or fails to return) a non-zero gas rate for that resource. Because the code path explicitly special-cases "rate is zero → return zero, no error" rather than treating it the same as "resource not found," the safety net (`switchToMeteringMode`) that exists for the analogous missing-rate case does not activate here.

### Recommendation
Do not silently return `0`/`nil` from `convertToBalance` (and the equivalent gas branch of `convertFromBalance`) when the gas conversion rate is zero. Instead, either:
- Treat a `0` gas rate the same as an unset/not-found rate — return an error so callers can invoke `switchToMeteringMode` and fail open safely, or
- Introduce an explicit, distinguishable "rate intentionally free" signal from the billing service (separate from the numeric value `0`) so `balanceStore` can differentiate an intentionally-free resource from a missing/invalid one, analogous to the recommended `getMaturityRate`-style fallback in the original finding.

### Proof of Concept
1. Billing service responds to `GetWorkflowExecutionRates` with `GasTokensPerCredit` containing `{"<chainSelector>": "0"}` for a given chain (e.g., a newly supported chain not yet priced, as exercised by the existing test `successfully settles zero value rate` / `GasTokensPerCredit: map[uint64]string{5009297550715157269: "0"}`).
2. A workflow capability step spends resource type `GAS.<chainSelector>` and calls `ByResource(spendType, capabilityID, amount)` with a nonzero `amount`.
3. `balanceStore.convertToBalance` hits the `isGasSpendType` branch, sees `rate.IsZero()`, and returns `(decimal.Zero, nil)`.
4. `ByResource` sets `step.Deduction = 0` and calls `r.balance.Minus(0)`, leaving the credit balance unchanged; `switchToMeteringMode` is never invoked because no error was returned.
5. The workflow's metering report shows zero cost for actual gas-priced capability usage, and the billing/metering system silently under-bills the execution instead of failing open into its documented safety mode.

func (bs *balanceStore) convertToBalance(fromResourceType string, amount decimal.Decimal) (decimal.Decimal, error) {
	rate, ok := bs.conversions[fromResourceType]
	if !ok {
		return amount, ErrResourceTypeNotFound
	}

	// Special case for gas as gas token conversions are provided in amount per credit.
	// Other rates are provided as the inverse.
	if isGasSpendType(fromResourceType) {
		if rate.IsZero() {
			return decimal.Zero, nil
		}

		return amount.Div(rate).Round(defaultDecimalPrecision), nil
	}

	return amount.Mul(rate), nil
}

func ByResource(
	spendType, capabilityID string,
	amount decimal.Decimal,
) func(string, *Report) ([]capabilities.SpendLimit, error) {
	return func(ref string, r *Report) ([]capabilities.SpendLimit, error) {
		step := ReportStep{
			CapabilityID:     capabilityID,
			Deduction:        decimal.Zero,
			AggregatedSpends: make(map[string]AggregatedStepDetail),
		}

		defer func() {
			r.steps[ref] = step
		}()

		bal, err := r.balance.ConvertToBalance(spendType, amount)
		if err != nil {
			// Fail open, continue optimistically
			r.switchToMeteringMode(fmt.Errorf("failed to convert to balance [%s]: %w", spendType, err))
		}

		step.Deduction = bal

		// if in metering mode, exit early without modifying local balance
		if r.meteringMode {
			return []capabilities.SpendLimit{}, nil
		}

		return []capabilities.SpendLimit{}, r.balance.Minus(bal)
	}
}
