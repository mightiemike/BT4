### Title
Unvalidated `RevertInstructions.FundRecipient = address(0)` permanently bricks the outbound fund-recovery path into `ABORTED` - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
Push Chain's outbound-failure recovery mechanism (`handleFailedOutbound`) re-mints bridged PRC20 tokens back to a "revert recipient" whenever an outbound broadcast to a destination chain fails. That recipient is taken verbatim, with no non-zero/format validation, from attacker-controlled data (`RevertInstructions.FundRecipient`), which originates either from the on-chain `UniversalTxOutboundEventSig` event emitted by `UniversalGatewayPC` (`event.RevertRecipient`) or from the inbound's `revert_instructions` field supplied by the source-chain sender. If this value is `address(0)`, the compensating `depositPRC20Token` mint call is guaranteed to revert (standard ERC20/OZ-style `_mint`/`_transfer` reject `address(0)`), which forces the keeper into `AbortOutbound`, permanently marking the outbound `ABORTED` with no further automatic processing. This is the same root cause as the referenced Yield `Witch.sol` H-01 finding: an unchecked, attacker-settable "payout to" address of `0x0` that deterministically breaks the protocol's own safety/recovery call.

### Finding Description
`BuildOutboundsFromReceipt` copies the on-chain event's revert recipient with no validation: [1](#0-0) 

`buildRevertOutbound` (used for inbound-side reverts) similarly takes `inbound.RevertInstructions.FundRecipient` unchecked: [2](#0-1) 

When an outbound observation comes back as failed, `handleFailedOutbound` resolves the recipient the same unchecked way and calls `CallPRC20Deposit` (which ultimately calls `depositPRC20Token` → PRC20 `mint`/`transfer`) to compensate the user: [3](#0-2) 

If the mint call reverts (as it will for `address(0)` on a standard OZ-style token implementation), the code does not retry or fall back to a safe default (e.g., `outbound.Sender`) — it immediately calls `AbortOutbound`, which sets `Status_ABORTED` and removes the entry from `PendingOutbounds`, ending all further automated processing: [4](#0-3) 

Per the module's own documentation, `ABORTED` explicitly means "finalization or revert attachment failed and requires manual intervention": [5](#0-4) 

The same unchecked fallback logic recurs in `applyGasRefund` (gas-refund recipient) and in `AttachRescueOutboundFromReceipt` (rescue recipient), both of which also read `outbound.RevertInstructions.FundRecipient`/`originalUtx.InboundTx.RevertInstructions.FundRecipient` without ever checking for the zero address: [6](#0-5) [7](#0-6) 

Nowhere in the `Inbound`/`OutboundTx` validation pipeline (`ValidateBasic`/`ValidateForExecution`, seen exercised in `x/uexecutor/types/inbound_test.go`) is `RevertInstructions.FundRecipient` checked for being non-zero or a well-formed non-null address — the pipeline only validates `Recipient`, not `RevertInstructions.FundRecipient`.

### Impact Explanation
Once the compensating mint reverts and `AbortOutbound` fires, the bridged principal for that outbound is permanently unrecoverable through the normal protocol flow: no re-mint happened, the outbound is removed from `PendingOutbounds`, and the UTX is left in a terminal `ABORTED` state requiring privileged/manual off-chain intervention that is not guaranteed by any deterministic on-chain path. This is a direct match to the required "permanent freezing / permanent loss of ... user or protocol-controlled funds" impact, and it is the same class of bug as the seed report: a single attacker-controlled address field that is never checked against `address(0)`, which the protocol's own compensating-payout logic then chokes on, turning a normally-recoverable failure into a permanently stuck state.

### Likelihood Explanation
Reachability requires only that an ordinary, unprivileged user set `RevertInstructions.FundRecipient` (or the on-chain `revertRecipient` parameter passed to the `UniversalGatewayPC` withdraw call) to `address(0)` and that the corresponding outbound subsequently observes as failed (a condition attacker cannot fully control but which occurs routinely for outbound failures — insufficient destination-chain gas, reverting calldata, etc., all of which are also attacker-influenceable for their own outbound). No validator collusion, admin action, or privileged access is needed to set the field; only the failure trigger requires a genuine destination-chain failure, which is a normal and expected occurrence in the outbound lifecycle that the protocol explicitly handles (`handleFailedOutbound`) — meaning the vulnerable path is a mainline, frequently-exercised path, not an edge case.

### Recommendation
Add an explicit validation step — in `Inbound.ValidateForExecution`/`OutboundTx` construction, and defensively again at the point of use in `handleFailedOutbound`, `applyGasRefund`, `buildRevertOutbound`, and `AttachRescueOutboundFromReceipt` — rejecting `RevertInstructions.FundRecipient == address(0)` (and any other degenerate/non-hex value), and falling back deterministically to `outbound.Sender`/`inbound.Sender` whenever the supplied fund recipient fails this check, rather than propagating an attacker-supplied zero address into the compensating mint/refund call.

### Proof of Concept
1. A user submits a withdraw/outbound-triggering payload on Push Chain (or a source-chain deposit event with `revert_instructions`) that sets `revertRecipient` / `RevertInstructions.FundRecipient = 0x0000000000000000000000000000000000000000`.
2. `BuildOutboundsFromReceipt` (or `buildRevertOutbound`) stores this unchecked value on the resulting `OutboundTx.RevertInstructions.FundRecipient`.
3. Universal Validators later vote the outbound as failed via `MsgVoteOutbound` (a legitimate, expected occurrence for destination-chain execution failures).
4. `FinalizeOutbound` → `handleFailedOutbound` resolves `recipient = outbound.RevertInstructions.FundRecipient = 0x0` and calls `CallPRC20Deposit(ctx, prc20, 0x0, amount)`.
5. The PRC20 contract's mint/transfer to `address(0)` reverts; `err != nil` in `handleFailedOutbound`.
6. `AbortOutbound` is invoked, setting `Status_ABORTED` permanently and removing the entry from `PendingOutbounds` — the bridged funds are never re-minted and no further automated recovery occurs.

func (k Keeper) AbortOutbound(ctx context.Context, utxId string, outbound types.OutboundTx, reason string) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	outbound.OutboundStatus = types.Status_ABORTED
	outbound.AbortReason = reason

	if err := k.UpdateOutbound(ctx, utxId, outbound); err != nil {
		return err
	}

	// Defensively remove from pending index (may already be removed by caller)
	_ = k.PendingOutbounds.Remove(ctx, outbound.Id)

	// Emit event for monitoring/alerting
	sdkCtx.EventManager().EmitEvent(sdk.NewEvent(
		"outbound_aborted",
		sdk.NewAttribute("utx_id", utxId),
		sdk.NewAttribute("outbound_id", outbound.Id),
		sdk.NewAttribute("abort_reason", reason),
	))

	return nil
}

func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
