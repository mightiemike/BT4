### Title
Disabled `TokenConfig.Enabled` flag is never enforced before minting PRC20 on inbound deposits - (File: x/uexecutor/keeper/handler.go)

### Summary
`x/uregistry`'s `TokenConfig` has an `Enabled` field intended to gate whether a token is currently whitelisted for minting/bridging [1](#0-0) . However, the crosschain deposit path in `x/uexecutor` never reads or checks this field before minting the corresponding PRC20 to a recipient — it only checks that a `NativeRepresentation` exists.

### Finding Description
The core minting helper `depositPRC20` in `x/uexecutor/keeper/handler.go` looks up the `TokenConfig` for `(sourceChain, assetAddr)` via `k.uregistryKeeper.GetTokenConfig`, and the only validation performed is that `tokenConfig.NativeRepresentation != nil`: [2](#0-1) 

The `Enabled` bool on `TokenConfig` — the field admins use to disable a token whitelisting after registration (e.g. via `MsgUpdateTokenConfig`) — is never read anywhere in this path. This mirrors the Sentiment bug class exactly: an operation (`CallPRC20Deposit` → mints PRC20) proceeds for an arbitrary/disabled token as long as *some* registry entry with an oracle/native-representation exists, with no check against the "is this token currently allowed" flag.

`depositPRC20` is invoked from every inbound execution path that credits funds:
- `x/uexecutor/keeper/execute_inbound_funds_and_payload.go` [3](#0-2) 
- `x/uexecutor/keeper/execute_inbound_gas.go`
- `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`

None of these call sites, nor `Inbound.ValidateForExecution()` [4](#0-3) , nor the ballot/vote-tally path, check `TokenConfig.Enabled` for the asset being deposited. Grepping the entire `x/uexecutor` package for `.Enabled` usage only turns up `ChainConfig.Enabled.IsInboundEnabled` checks (chain-level), never a token-level enabled check.

Since `GetTokenConfig` is a straight `(chain, address)` map lookup with no filter, once an admin has ever registered a `TokenConfig` row with a `NativeRepresentation.ContractAddress` for a given `(chain, address)`, that row remains fully usable for minting regardless of whether `Enabled` is later flipped to `false`.

### Impact Explanation
This breaks the intended "admin can pause/disable a token" invariant. If an admin sets `Enabled=false` on a token (e.g. because the source-chain token contract is discovered to be compromised, exploitable, or has liquidity/oracle issues — the exact scenario described in the Sentiment report), an unprivileged user can still send a real deposit of that token to the external gateway and have honest Universal Validators observe and vote the inbound (this is the ordinary, honest deposit flow — no validator collusion required). `ExecuteInboundFundsAndPayload`/`ExecuteInboundGas`/`ExecuteInboundGasAndPayload` will still call `depositPRC20`, which will happily mint the corresponding PRC20 to the recipient's UEA. This is unauthorized minting of a token the protocol explicitly intended to be un-whitelisted, corrupting PRC20 accounting/token mapping and potentially allowing the attacker to use the disabled token as spendable/tradeable collateral inside Push Chain even though the admin tried to shut it off.

### Likelihood Explanation
High reachability, low complexity: any user can trigger this by simply depositing the disabled token's underlying asset to the already-configured external gateway. No privileged actor, no validator misbehavior, and no additional preconditions beyond the token having been registered (and later disabled) in `uregistry`. The only gate — `Enabled` — is silently ignored in the exact code path that performs the mint.

### Recommendation
Enforce `TokenConfig.Enabled` at the point of minting/crediting, not just at admin-config time. In `x/uexecutor/keeper/handler.go`'s `depositPRC20`, after resolving `tokenConfig`, reject (fail the PCTx / route to revert-fund handling) if `!tokenConfig.Enabled`, mirroring the recommended fix pattern from the referenced report:

```go
tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
if err != nil {
    return nil, err
}
if !tokenConfig.Enabled {
    return nil, fmt.Errorf("token %s:%s is not enabled for minting", sourceChain, assetAddr)
}
```
Apply the same check consistently across all deposit/auto-swap call sites (`CallPRC20Deposit`, `CallPRC20DepositAutoSwap`) and consider validating it earlier, in `Inbound.ValidateForExecution`, so disabled-token inbounds fail fast and route through the existing revert/refund flow instead of silently minting.

### Proof of Concept
1. Admin registers `TokenConfig{Chain: "eip155:11155111", Address: "0xTOKEN", Enabled: true, NativeRepresentation: {ContractAddress: "0xPRC20TOKEN"}}` via `MsgAddTokenConfig`.
2. Later, admin discovers a vulnerability/manipulation risk in `0xTOKEN` and disables it via `MsgUpdateTokenConfig` setting `Enabled: false` (but the row, including `NativeRepresentation`, is not removed — `MsgRemoveTokenConfig` is a separate, unused action).
3. An attacker deposits `0xTOKEN` into the already-configured gateway contract on `eip155:11155111`.
4. Honest Universal Validators observe the real on-chain event and vote `MsgVoteInbound` with `AssetAddr = "0xTOKEN"`, `TxType = FUNDS` (or `FUNDS_AND_PAYLOAD`).
5. Ballot finalizes; `ExecuteInboundFundsAndPayload` (or the FUNDS variant) calls `k.depositPRC20(ctx, "eip155:11155111", "0xTOKEN", recipientUEA, amount)`.
6. `depositPRC20` finds the `TokenConfig`, sees `NativeRepresentation != nil`, and calls `CallPRC20Deposit`, minting `0xPRC20TOKEN` to the recipient — despite `Enabled == false`.

Note: I was unable to trace every downstream consumer of the minted PRC20 (e.g., how the UEA/DeFi contracts on Push Chain price or restrict this PRC20 once minted) since that logic lives in the Solidity system contracts, not in the indexed Go codebase; the confirmed root cause is the missing `Enabled` check in `x/uexecutor/keeper/handler.go`, which is sufficient on its own to break the token-whitelisting invariant regardless of downstream usage.

func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}

// ValidateForExecution checks fields that are required for actual execution of the inbound.
// Called after ballot finalization, before ExecuteInbound. Failures here produce a failed
// PCTx and (for non-isCEA) a revert outbound, rather than dropping the vote.
func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}
