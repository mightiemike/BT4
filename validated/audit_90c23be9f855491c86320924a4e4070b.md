### Title
Signer-boot reward-per-token snapshot advances for a cycle a signer never earned in, letting a below-threshold signer's staker collect phantom STX-only rewards - (File: stackslib/src/chainstate/stacks/boot/pox-5.clar)

### Summary
`pox-5.clar` implements a lazily-accrued, Compound/Aave-style "rewards-per-token" accrual model for both bond rewards and STX-only staking rewards, exactly the accrual pattern the external report (Wild Credit M-04) flags as bug-prone: a shared, monotonically-increasing "rewards-per-token" accumulator is advanced on individual, unprivileged calls, and later reads are diffed against a per-staker "paid" snapshot to compute what is owed. When the accumulator is advanced by a code path that is not gated on the signer actually having been a contributing member of the sub-ledger being updated, a staker who never contributed to that sub-ledger during that cycle can still walk away with rewards for it — the exact "reward paid ... to the wrong party" analog called out in the rules.

### Finding Description
`add-staker-to-signer-for-cycle` (stackslib/src/chainstate/stacks/boot/pox-5.clar:1663-1710) calls `settle-rewards` for the signer/cycle pair before mutating any staked-amount state, and conditionally calls `settle-staker-rewards` for the staker only if `prev-staker-shares > 0`. [1](#0-0) 

Separately, `calculate-bond-rewards`/the distribution logic (stackslib/src/chainstate/stacks/boot/pox-5.clar:2161-2220) advances the global `rewards-per-token-for-cycle` map keyed by `{reward-cycle, bond-index}` using `cycle-staked-ustx = get-total-shares-staked-for-cycle`, unconditionally accumulating `accrued-rewards-per-ustx` into the cumulative rate regardless of which specific signer's shares happened to be non-zero at settlement time. [2](#0-1) 

This is the direct Stacks analog of the reported bug class: total/global accrual state (`rewards-per-token-for-cycle`) is updated by a code path invoked incidentally (a bond claim, `claimRewards`), on a signer whose STX-only shares are zero for that cycle, which — per the repo's own regression test — corrupts `signer-rewards-per-token-for-cycle` for that signer/cycle, advancing the snapshot past a window the signer never participated in: [3](#0-2) 

The setup: signer1 is below `SIGNER_SET_MIN_USTX` for cycle 1 via STX-only staking (bob's bond ustx + alice's STX-only stake together still fall short of the threshold), so `isSignerInCycle(signer1, 1)` is `false` and `getSignerSharesStakedForCycle(signer1, 1, none)` is `0`. [4](#0-3) 

Because signer2 independently crosses the threshold, the *global* STX-only rewards-per-token for cycle 1 advances past zero when rewards are calculated. [5](#0-4) 

Triggering `claimRewards` on bob's bond then runs `settle-rewards` on signer1's STX-only cycle-1 ledger with `shares = 0`, and the test's own comment states this "corrupts signer-rewards-per-token-for-cycle" — after which alice (who staked STX-only to signer1, a signer that was never in the cycle-1 reward set) becomes owed non-zero rewards for a period her signer did not participate in. [3](#0-2) 

### Impact Explanation
This breaks the equality "a staker's accrued STX-only reward == sum of rewards actually earned by the signer they staked to, for the cycles that signer was in the active reward set." Any unprivileged party can trigger this by (1) staking through a signer intentionally kept below the delegation threshold, and (2) causing any bond claim to run on that same signer/cycle pair while a different, above-threshold signer advances the global rate. The result is reward mis-payment: value is diverted from the sBTC/STX reward pool (funded by depositors/reward payers) to a staker who is not entitled to any cycle-1 STX-only reward, without requiring node-operator/majority collusion — matching the rules' "reward paid ... to the wrong party" and "poison or reward mis-payment bounded to fees" categories (High).

### Likelihood Explanation
Minority-triggerable and unprivileged: a single staker (bob) registering a tiny bond, a second STX-only staker (alice) staking just under the delegation threshold to the same signer, and a third, unrelated signer (signer2) independently crossing the threshold are sufficient; no majority of signers, no admin key, and no economic assumption beyond ordinary staking/reward flows are needed. The existing repo test explicitly reproduces the corrupted state end-to-end, indicating this is not a theoretical concern but a reachable, deterministic sequence of unprivileged public-entry-point calls (`stake`, `registerForBond`, `calculateRewards`, `claimRewards`).

### Recommendation
Gate `settle-rewards`/the rewards-per-token accrual advance for a signer/cycle so it cannot be invoked (or cannot mutate that signer's `signer-rewards-per-token-for-cycle` snapshot) unless the signer was actually a member of that cycle's active reward set (`isSignerInCycle`) for the ledger being settled (bond vs. STX-only). Equivalently, snapshot/checkpoint a staker's "paid" rate only against the rate that existed while their signer was actually contributing shares, rather than allowing any incidental call (e.g., an unrelated bond claim) to fast-forward the snapshot baseline for a zero-share signer.

### Proof of Concept
See the repo's own regression test, which demonstrates the exact corrupted-state sequence: `contrib/core-contract-tests/tests/pox-5/pox-5.test.ts:6064-6157` (`below-threshold signer leaks phantom stx-only rewards via bond co-claim`) — it sets up a below-threshold signer1, advances the global STX-only rate via an unrelated above-threshold signer2, triggers `settle-rewards` on signer1's zero-share cycle-1 STX-only ledger via `claimRewards`, and asserts (documenting the unfixed-code failure) that alice must not, but currently can, become owed STX-only rewards for a cycle her signer never earned in. [6](#0-5)

test('below-threshold signer leaks phantom stx-only rewards via bond co-claim', () => {
  const signer1 = testSigner.identifier;
  const signer2 = deployTestSigner('phantom-bond-signer-2').identifier;
  const bobSbtc = 400_000n;
  const targetRate = 1200n;

  registerSigner();

  // Bond 0 with bob as the lone participant on signer1. The minimum ustx
  // that backs his sats lockup is tiny -- well under SIGNER_SET_MIN_USTX --
  // so signer1's only chance of crossing the threshold is via STX-only
  // stakers.
  txOk(
    pox5.setupBond({
      bondIndex: 0n,
      targetRate,
      stxValueRatio: 10n,
      minUstxRatio: 100n,
      earlyUnlockBytes: new Uint8Array(),
      allowlist: [{ maxSats: bobSbtc, staker: bob }],
    }),
    deployer,
  );
  const bobBondUstx = rov(pox5.minUstxForSatsAmount(bobSbtc, 10n, 100n));
  txOk(
    pox5.registerForBond({
      bondIndex: 0n,
      signerManager: signer1,
      amountUstx: bobBondUstx,
      btcLockup: err(bobSbtc),
      signerCalldata: null,
    }),
    bob,
  );

  // Alice stakes STX-only to signer1, sized to leave signer1 below the
  // threshold even once bob's bond ustx is added in.
  const aliceStake = stxToUStx(40_000);
  expect(aliceStake + bobBondUstx).toBeLessThan(
    pox5.constants.SIGNER_SET_MIN_USTX,
  );
  txOk(
    pox5.stake({
      signerManager: signer1,
      amountUstx: aliceStake,
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    alice,
  );

  // signer2 carries an independently-above-threshold STX-only staker so the
  // global STX-only rewards-per-token for cycle 1 advances. Without this
  // there are no STX rewards distributed and the snapshot bug is masked
  // behind a zero global.
  txOk(
    pox5.stake({
      signerManager: signer2,
      amountUstx: stxToUStx(60_000),
      numCycles: 2n,
      startBurnHt: simnet.burnBlockHeight,
      signerCalldata: null,
    }),
    charlie,
  );

  expect(isSignerInCycle({ signer: signer1, cycle: 1n })).toBe(false);
  expect(isSignerInCycle({ signer: signer2, cycle: 1n })).toBe(true);
  expect(rov(pox5.getSignerSharesStakedForCycle(signer1, 1n, null))).toBe(0n);

  // Fund rewards: enough for bob's bond to fully pay out, with surplus
  // flowing through the STX waterfall so the global STX-only rpt advances.
  sbtcTransfer(1000n, deployer, pox5.identifier);
  mineUntil(rov(pox5.rewardCycleToBurnHeight(1n)) + HALF_CYCLE_LENGTH);
  txOk(pox5.calculateRewards([0n]), deployer);

  // Sanity: signer1 has earned nothing STX-only for cycle 1 and alice
  // sees no earnings yet.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);

  // Trigger the bond claim. settle-rewards runs on signer1's STX-only
  // cycle 1 with shares=0 and corrupts signer-rewards-per-token-for-cycle.
  txOk(testSigner.claimRewards([0n], 1n), deployer);

  // signer1's STX-only earnings remain 0 -- it never contributed.
  expect(rov(pox5.getEarned(signer1, 1n, null))).toBe(0n);

  // Witnessing assertion: alice must not be owed STX-only rewards for a
  // cycle where her signer was not a member. Fails on the unfixed code
  // because the snapshot was advanced past a window signer1 didn't earn in.
  expect(rov(testSigner.getEarnedStakerRewards(alice, 1n, null))).toBe(0n);
});
