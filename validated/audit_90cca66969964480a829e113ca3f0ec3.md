The reported issue (`jose2go`) is a decompression-bomb DoS: the JWE decoder inflates a DEFLATE-compressed token body without limiting the output size, so a small compressed input can expand to unbounded memory. To find an analog in `protobuf-go`, I looked for any place where untrusted request bytes are passed through a general-purpose decompressor (gzip/zlib/deflate) as part of parsing.

The only `gzip`/`compress` usage found is unrelated to any unprivileged request path: it decompresses the compile-time-embedded `FileDescriptorProto` bytes generated by `protoc-gen-go` (e.g. `internal/impl/legacy_file.go`'s `legacyLoadFileDesc`, `internal/protolegacy/proto.go`'s `RegisterFile`, and the `Export.CompressGZIP` used purely to produce the embedded `rawDescGZIP` blobs). These operate on bytes baked into the generated `.pb.go` files at build time, not on data sent by an unprivileged remote peer. [1](#0-0) [2](#0-1) [3](#0-2) 

Protobuf-go's actual message decoders — binary (`proto/decode.go`, `internal/impl/decode.go`), `protojson` (`encoding/protojson/decode.go`), and `prototext` (`encoding/prototext/decode.go`) — do not perform any generic decompression of attacker-controlled bytes at all; wire-format "bytes" fields are simply consumed as raw length-prefixed byte slices, with no inflate/deflate stage. The relevant DoS control in these paths is a bounded recursion-depth limit (`o.RecursionLimit`/`opts.depth`, default `protowire.DefaultRecursionLimit`), which guards against message nesting, not compression ratio. [4](#0-3) [5](#0-4) [6](#0-5) 

Since no code path in `protobuf-go` decompresses attacker-supplied bytes with a general-purpose compressor lacking an output-size cap, the "decompression/compression-ratio bomb" bug class from the `jose2go` advisory has no reachable analog here — it does not apply to a Go serialization library that never performs decompression on untrusted input.

func (Export) CompressGZIP(in []byte) (out []byte) {
	// RFC 1952, section 2.3.1.
	var gzipHeader = [10]byte{0x1f, 0x8b, 0x08, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, 0xff}

	// RFC 1951, section 3.2.4.
	var blockHeader [5]byte
	const maxBlockSize = math.MaxUint16
	numBlocks := 1 + len(in)/maxBlockSize

	// RFC 1952, section 2.3.1.
	var gzipFooter [8]byte
	binary.LittleEndian.PutUint32(gzipFooter[0:4], crc32.ChecksumIEEE(in))
	binary.LittleEndian.PutUint32(gzipFooter[4:8], uint32(len(in)))

	// Encode the input without compression using raw DEFLATE blocks.
	out = make([]byte, 0, len(gzipHeader)+len(blockHeader)*numBlocks+len(in)+len(gzipFooter))
