Confirmed: the app-proxy authentication path (`validateAppProxyHmac` in `shopify-app-remix`/`shopify-app-react-router`) calls `validateHmac` with a raw `URLSearchParams` object built directly from the incoming request's query string, which is exactly the code path that hits the vulnerable string-concatenation logic in `normalizeQuery`.

### Title
CPU-bound DoS via quadratic string concatenation on duplicate query parameters in `normalizeQuery` - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
`normalizeQuery` collapses duplicate query-string keys from a `URLSearchParams` instance by repeatedly doing `normalizedQuery[key] = \`${existingValue},${value}\``, which is O(n) per duplicate and O(n²) total for n duplicates of the same key. An attacker can send an app-proxy request (or any endpoint that funnels a raw `URLSearchParams` object into `validateHmac`) with tens of thousands of duplicate keys (e.g., `foo=x` repeated 20,000 times) to force large CPU work in the authentication handler before the HMAC comparison ever runs.

### Finding Description
`validateHmac` (`packages/apps/shopify-api/lib/utils/hmac-validator.ts:84-116`) calls `normalizeQuery(query, signator)` before any HMAC/signature check occurs. [1](#0-0) 

When `query` is a `URLSearchParams` instance, `normalizeQuery` iterates every entry; for repeated keys it concatenates the new value onto the growing `existingValue` string via `normalizedQuery[key] = \`${existingValue},${value}\``. Because string concatenation creates a new string of length proportional to the current accumulated length, n repeats of the same key cost O(n²) time/memory, not O(n). This work happens unconditionally before the (soon-to-fail) `safeCompare(hmac, localHmac)` at the end of `validateHmac`, so an attacker does not need a valid HMAC to trigger it — they just need to reach the handler with a garbage `hmac`/`signature` value.

The app-proxy authentication entry point in `shopify-app-remix`/`shopify-app-react-router` constructs the `URLSearchParams` directly from the raw request URL and passes it straight into `api.utils.validateHmac(searchParams, {signator: 'appProxy'})`, without any bound on parameter count or key repetition: [2](#0-1) 

This is invoked on every unauthenticated app-proxy request before any signature is verified, and it is retried up to 3 times on failure (each retry re-parses and re-normalizes a `URLSearchParams` object), compounding the cost. [3](#0-2) 

Note: the OAuth callback path (`packages/apps/shopify-api/lib/auth/oauth/oauth.ts:178`) is NOT vulnerable, because it converts the `URLSearchParams` to a plain object via `Object.fromEntries(query.entries())` before calling `validateHmac`, which silently drops duplicates (keeps only the last value per key) and thus never reaches the `URLSearchParams` branch of `normalizeQuery`. [4](#0-3) 

There is no upper bound anywhere on the number of query parameters or on the length of an individual key's accumulated value before this concatenation loop runs, and no early-exit check for parameter count exists in `validateHmac`, `normalizeQuery`, or the app-proxy handler.

### Impact Explanation
This enables a CPU-bound denial-of-service against the app-proxy authentication handler: a single crafted request with a large number of duplicate keys can cause quadratic-time string building (and corresponding memory churn) in the request-handling thread, before the cryptographic check even executes. Repeated concurrent requests of this shape can degrade or exhaust server resources for the app, affecting availability for all users of that app. This maps to Shopify's "Denial of Service in an authentication/validation handler" bounty impact class — algorithmic-complexity DoS reachable pre-authentication.

### Likelihood Explanation
No privileged access or secret is required — an anonymous client can send a crafted app-proxy request with a bogus `hmac`/`signature` and thousands of duplicate query keys. This is fully within a normal unprivileged HTTP client's capability, is trivially repeatable, and is amplified by the up-to-3x retry logic in `validateAppProxyHmac`.

### Recommendation
- In `normalizeQuery`, avoid repeated string concatenation growth; use an array/list accumulator per key (`normalizedQuery[key].push(value)`) and join once at the end, or track and enforce a maximum number of values per key / total query parameters, rejecting (fast-failing) requests that exceed a sane limit before doing any normalization work.
- Add an explicit cap on the total number of query parameters (and/or total query-string length) accepted by `validateHmac`/`validateAppProxyHmac`, rejecting oversized requests immediately (O(1) check) prior to any parsing or normalization.
- Consider applying a request-size limit (e.g., max URL/query length) at the HTTP layer for app-proxy and OAuth callback endpoints.

```ts
import {URLSearchParams} from 'url';
import {testConfig} from '../../__tests__/test-config';
import {shopifyApi} from '../..';

test('validateHmac scales quadratically with duplicate query keys (DoS)', async () => {
  const shopify = shopifyApi(testConfig({apiSecretKey: 'secret'}));

  const build = (n: number) => {
    const params = new URLSearchParams();
    for (let i = 0; i < n; i++) {
      params.append('foo', 'x'.repeat(50)); // duplicate key, growing concat target
    }
    params.append('signature', 'garbage'); // forces full normalization before failing compare
    params.append('timestamp', String(Math.trunc(Date.now() / 1000)));
    params.append('shop', 'test.myshopify.com');
    return params;
  };

  const time = async (n: number) => {
    const params = build(n);
    const start = performance.now();
    await shopify.utils.validateHmac(params, {signator: 'appProxy'}).catch(() => false);
    return performance.now() - start;
  };

  const t1 = await time(5000);
  const t2 = await time(20000); // 4x input size

  // Linear scaling would expect ~4x; quadratic concatenation causes >>4x (e.g. >10x)
  expect(t2 / t1).toBeLessThan(6); // fails against current implementation
});
```

```typescript
function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}
```
