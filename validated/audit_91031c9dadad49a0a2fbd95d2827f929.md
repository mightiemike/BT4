### Title
Anonymous `shopify.utils.validateHmac` calls with duplicate `hmac`/query-array values can throw an uncaught `SafeCompareError` instead of returning `false` - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
`shopify.utils.validateHmac` (`signator: 'admin'`) is the documented entry point apps use to validate unauthenticated, Shopify-originated requests such as the initial embedded-app load (`?hmac=...&shop=...&host=...&timestamp=...`) and OAuth callback query strings, using `req.query` directly as input. [1](#0-0) 

### Finding Description
`normalizeQuery` only guards against array-valued security parameters (`hmac`, `shop`, `signature`, `timestamp`) when the `signator` is `'appProxy'`, and only when the input is a `URLSearchParams` instance; for the `'admin'` signator, or for a plain object query (e.g. `req.query` from Express/Connect-style frameworks using `qs`, which turns repeated query keys like `?hmac=a&hmac=b` into an array), the function performs no validation at all and returns the object unchanged. [2](#0-1) 

`validateHmac` then only checks truthiness of `normalizedQuery.hmac` (an array is truthy) and passes it straight to `safeCompare(hmac as string, localHmac)`. [3](#0-2) 

`safeCompare` requires `typeof strA === typeof strB`; if `hmac` is an array (`typeof === 'object'`) while `localHmac` is always a `string`, it throws `SafeCompareError` instead of returning `false`. [4](#0-3) 

This is analogous in bug-class to the reported Nimbus issue (malformed/attacker-controlled input reaching a validation routine that is not defensively coded for all shapes of that input, causing an unhandled exception instead of a graceful rejection) — here the "malformed attestation" analog is a malformed/duplicated HMAC query parameter reaching an authentication-validation function.

### Impact Explanation
If a consuming app calls `shopify.utils.validateHmac(req.query)` without wrapping the call in a try/catch for `SafeCompareError` specifically (only `InvalidHmacError` is documented/expected as the failure mode), an anonymous request with a duplicated `hmac` (or `shop`/`timestamp`) query parameter can throw an uncaught exception in the request path used for the initial unauthenticated app load or OAuth-adjacent validation. Depending on the app's error handling and runtime (e.g., no global unhandled-rejection/exception handler), this can crash the request or, in worse-configured Node servers, take down the process — a remote DoS triggerable by an anonymous single request, without any secret knowledge.

### Likelihood Explanation
Whether this is actually exploitable depends entirely on how the consuming app's web framework parses `req.query` (many frameworks like Express with the default `qs` parser do produce arrays for repeated keys) and whether the app's route/error-handling middleware happens to catch generic errors. Within the shopify-api library itself I could not find a call site that passes attacker-controlled arrays into the `admin` signator path — the library's own OAuth callback (`oauth.ts`) explicitly deduplicates via `Object.fromEntries(query.entries())` before calling `validateHmac`, so the library's built-in flows are not directly vulnerable. The exposure exists only for apps that follow the documented pattern of calling `shopify.utils.validateHmac(req.query)` directly with a non-deduplicating query parser. I could not verify within the available index which downstream packages (if any) call `validateHmac` this way in production code paths, so likelihood is uncertain and moderate at best.

### Recommendation
Harden `normalizeQuery`/`validateHmac` for the `'admin'` signator to also reject (or safely coerce) array-valued security parameters (`hmac`, `shop`, `timestamp`) the same way it already does for `'appProxy'`, converting the failure into the documented `InvalidHmacError` (or a `false` return) rather than allowing an uncaught `SafeCompareError` to propagate. Additionally, `safeCompare` could be made to return `false` on type mismatch (or the mismatch could be normalized before comparison) rather than throwing, so misuse from arbitrary caller-supplied `req.query` shapes cannot escape as an unhandled exception.

### Proof of Concept
```ts
import {shopifyApi} from '@shopify/shopify-api';

const shopify = shopifyApi(/* config */);

// Simulates req.query from a framework that parses repeated keys as arrays

const maliciousQuery = {
  shop: 'test.myshopify.com',
  timestamp: '123',

await shopify.utils.validateHmac(maliciousQuery as any);

# shopify.utils.validateHmac

Shopify requests include an `hmac` query argument (or, in the case of app proxy requests, a `signature` query argument). This method validates those requests to ensure that the `hmac` value was signed by Shopify and not spoofed.

## Example

For OAuth requests:

```ts
const isValid = await shopify.utils.validateHmac(req.query);
```

For App Proxy requests:

```ts
const isValid = await shopify.utils.validateHmac(req.query, {
  signator: 'appProxy',
});
```

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}

export const safeCompare: SafeCompare = (strA, strB) => {
  if (typeof strA === typeof strB) {
    const enc = new TextEncoder();
    const buffA = enc.encode(JSON.stringify(strA));
    const buffB = enc.encode(JSON.stringify(strB));

    if (buffA.length === buffB.length) {
      return timingSafeEqual(buffA, buffB);
    }
  } else {
    throw new ShopifyErrors.SafeCompareError(
      `Mismatched data types provided: ${typeof strA} and ${typeof strB}`,
    );
  }
  return false;
};
