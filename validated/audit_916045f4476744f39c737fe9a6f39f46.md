Confirmed: `HandleOffchainRequest` in `core/services/functions/listener.go` validates address formats and timestamp only, and never checks `request.SubscriptionId` against on-chain ownership by `subscriptionOwner`/`senderAddr` before calling `l.handleRequest(ctx, requestId, request.SubscriptionId, subscriptionOwner, ...)`, which forwards `SubscriptionId` unchecked to `eaClient.RunComputation`.### Title
Offchain heartbeat requests forward attacker-chosen `SubscriptionId` to the External Adapter without on-chain ownership verification - ([File: core/services/functions/listener.go])

### Summary
`functionsConnectorHandler.handleHeartbeat` validates that `RequestInitiator` and `SubscriptionOwner` in the attacker-supplied `OffchainRequest` match the gateway-authenticated sender address, but never validates that the attacker-chosen `SubscriptionId` is actually owned on-chain by that sender. This unvalidated `SubscriptionId` is propagated through `handleOffchainRequest` → `FunctionsListener.HandleOffchainRequest` → `handleRequest` → `ExternalAdapterClient.RunComputation`, misrepresenting the billing/authorization context sent to the EA.

### Finding Description
In `core/services/functions/connector_handler.go`, `handleHeartbeat` (lines 240-262) checks: [1](#0-0) 
only that `RequestInitiator` and `SubscriptionOwner` bytes equal `fromAddr`. No check exists anywhere in this function, nor in `handleOffchainRequest`, that ties `request.SubscriptionId` (an arbitrary attacker-supplied `uint64`) to an actual on-chain subscription owned by `fromAddr`.

The request then flows to `FunctionsListener.HandleOffchainRequest` in `core/services/functions/listener.go`: [2](#0-1) 
This function validates address length and timestamp freshness only — it never queries `OnchainSubscriptions` to confirm `request.SubscriptionId` belongs to `subscriptionOwner`. It calls `l.handleRequest(ctx, requestId, request.SubscriptionId, subscriptionOwner, RequestFlags{}, &request.Data)` directly using the unverified `SubscriptionId`.

`handleRequest` in the same file forwards this identifier straight to the external adapter: [3](#0-2) 
`eaClient.RunComputation(ctx, requestIDStr, l.job.Name.ValueOrZero(), subscriptionOwner.Hex(), subscriptionId, flags, nodeProvidedSecrets, requestData)` — and `RunComputation` places `subscriptionOwner`/`subscriptionId` verbatim into the JSON `requestPayload` sent to the EA: [4](#0-3) 

The `OnchainSubscriptions` component that does perform ownership tracking (`core/services/gateway/handlers/functions/subscriptions/user_subscriptions.go`) is wired into the `handleSecretsSet`/`MethodSecretsList` balance-check path in `connector_handler.go` but is not consulted at all in `handleHeartbeat`, confirming the gap is a missing check rather than a bypass of an existing one.

### Impact Explanation
Because the EA trusts the `subscriptionId`/`subscriptionOwner` pair passed by the node as the billing/authorization context (per the `RunComputation` interface's stated purpose), an attacker who is any allow-listed gateway user can submit heartbeat requests using their own address as `SubscriptionOwner`/`RequestInitiator` (satisfying the checks) but supply any other subscription's real `SubscriptionId`. If the EA keys quota/rate-limit decisions primarily off `subscriptionId`, this lets the attacker consume or influence another subscription's quota allocation, i.e., a rate-limit/billing-authorization bypass at the EA layer.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs to be an allow-listed heartbeat-capable gateway user (`h.allowedHeartbeatInitiators`) — no special privilege, no key compromise. The exploit is fully repeatable since it's a straightforward JSON payload manipulation of the `OffchainRequest.SubscriptionId` field, which is never validated against on-chain state.

### Recommendation
In `handleHeartbeat` (or in `FunctionsListener.HandleOffchainRequest`), validate that `request.SubscriptionId` is actually owned by `fromAddr`/`subscriptionOwner` using the existing `OnchainSubscriptions`/subscriptions ORM (as already done for balance checks in `handleSecretsSet`) before proceeding to `handleOffchainRequest`/`RunComputation`. Reject the request if no such on-chain subscription-to-owner relationship exists.

### Proof of Concept
Unit test in `core/services/functions/listener_test.go` style, extending `TestFunctionsListener_HandleOffchainRequest_Success`:
1. Construct an `OffchainRequest` with `RequestInitiator = attacker.Bytes()`, `SubscriptionOwner = attacker.Bytes()` (passes existing checks), but `SubscriptionId = victimSubscriptionId` (a real ID not owned by `attacker`).
2. Call `uni.service.HandleOffchainRequest(ctx, request)`.
3. Assert that `eaClient.RunComputation` is still invoked with `subscriptionId = victimSubscriptionId` and `subscriptionOwner = attacker.Hex()` despite no on-chain relationship between `attacker` and `victimSubscriptionId` — demonstrating the missing ownership check (currently the test suite only exercises address-format/timestamp validation in `TestFunctionsListener_HandleOffchainRequest_Invalid`, never subscription-ownership validation).

func (l *functionsListener) HandleOffchainRequest(ctx context.Context, request *OffchainRequest) error {
	if request == nil {
		return errors.New("HandleOffchainRequest: received nil request")
	}
	if len(request.RequestId) != RequestIDLength {
		return fmt.Errorf("HandleOffchainRequest: invalid request ID length %d", len(request.RequestId))
	}
	if len(request.SubscriptionOwner) != common.AddressLength || len(request.RequestInitiator) != common.AddressLength {
		return errors.New("HandleOffchainRequest: SubscriptionOwner and RequestInitiator must be set to valid addresses")
	}
	if request.Timestamp < uint64(time.Now().Unix()-int64(l.pluginConfig.RequestTimeoutSec)) {
		return errors.New("HandleOffchainRequest: request timestamp is too old")
	}

	var requestId RequestID
	copy(requestId[:], request.RequestId[:32])
	subscriptionOwner := common.BytesToAddress(request.SubscriptionOwner)
	senderAddr := common.BytesToAddress(request.RequestInitiator)
	emptyTxHash := common.Hash{}
	zeroCallbackGasLimit := uint32(0)
	newReq := &Request{
		RequestID:        requestId,
		RequestTxHash:    &emptyTxHash,
		ReceivedAt:       time.Now(),
		Flags:            []byte{},
		CallbackGasLimit: &zeroCallbackGasLimit,
		// use sender address in place of coordinator contract to keep batches uniform
		CoordinatorContractAddress: &senderAddr,
		OnchainMetadata:            []byte(OffchainRequestMarker),
	}
	if err := l.pluginORM.CreateRequest(ctx, newReq); err != nil {
		if errors.Is(err, ErrDuplicateRequestID) {
			l.logger.Warnw("HandleOffchainRequest: received duplicate request ID", "requestID", formatRequestId(requestId), "err", err)
		} else {
			l.logger.Errorw("HandleOffchainRequest: failed to create a DB entry for new request", "requestID", formatRequestId(requestId), "err", err)
		}
		return err
	}
	return l.handleRequest(ctx, requestId, request.SubscriptionId, subscriptionOwner, RequestFlags{}, &request.Data)
}
