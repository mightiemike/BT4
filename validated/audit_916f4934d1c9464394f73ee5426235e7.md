### Title
CancelAllUnfreezeV2Actuator forfeits pending vote reward by skipping mandatory reward settlement before mutating frozen-balance/weight state - (File: `actuator/src/main/java/org/tron/core/actuator/CancelAllUnfreezeV2Actuator.java`)

### Summary
Every other resource state-transition actuator that mutates an account's frozen balance/resource weight and can invalidate a vote-power snapshot first settles pending vote rewards via `mortgageService.withdrawReward(ownerAddress)` (or `VoteRewardUtil.withdrawReward` on the TVM-native path). `CancelAllUnfreezeV2Actuator`/`CancelAllUnfreezeV2Processor` do not, mirroring the reported `Migration.sol` bug class where `instantUnstake(false)` mutates state while skipping the optional rebase that would have settled pending rewards.

### Finding Description
`UnfreezeBalanceActuator.execute()` calls `mortgageService.withdrawReward(ownerAddress)` before mutating the account's frozen balances/votes [1](#0-0) . `UnfreezeBalanceV2Actuator.execute()` does the same before adding to the `unfrozenV2` list and updating vote/weight state [2](#0-1) . `VoteWitnessActuator.countVoteAccount()` likewise settles reward first, before clearing/overwriting the account's votes [3](#0-2) . The TVM-native counterparts (`UnfreezeBalanceV2Processor`, `VoteWitnessProcessor`, `WithdrawRewardProcessor`) all call `VoteRewardUtil.withdrawReward(ownerAddress, repo)` as the first statement of `execute()` [4](#0-3) [5](#0-4) [6](#0-5) .

By contrast, `CancelAllUnfreezeV2Actuator.execute()` restores frozen balance and resource weight for BANDWIDTH/ENERGY/TRON_POWER directly from the pending unfreeze list, and updates `dynamicStore` total weights, without ever invoking `mortgageService.withdrawReward()` [7](#0-6) . The TVM-native equivalent `CancelAllUnfreezeV2Processor.execute()` shows the identical omission—no call to `VoteRewardUtil.withdrawReward()` anywhere in the class [8](#0-7) .

`MortgageService.withdrawReward()` is not idempotent/lossless if delayed indefinitely: it advances `beginCycle`/`endCycle` and snapshots the account's *current* vote list into `delegationStore.setAccountVote(endCycle, address, accountCapsule)` for later reward computation [9](#0-8) . Because this settlement point is tied to the account's vote/resource state at call time, any state-mutating transaction that changes the account (frozen balance, resource weight, or later a vote clear triggered by insufficient TronPower) but does not first call `withdrawReward()` risks having the reward for the still-pending cycle computed against a state that no longer reflects what the account actually held during that cycle — directly analogous to `instantUnstake(false)` skipping `rebase()` in the referenced Migration.sol finding.

### Impact Explanation
An account holding TRON_POWER/BANDWIDTH/ENERGY unfreeze-in-progress balances that calls `CancelAllUnfreezeV2` mutates its resource-weight accounting without going through the same reward-settlement checkpoint used by every sibling actuator (`UnfreezeBalance(V2)`, `VoteWitness`, `WithdrawReward`). This creates an inconsistency in the accrual pipeline: since `CancelAllUnfreezeV2` is not the terminal action in a user's session (they can subsequently unfreeze, vote, or withdraw), the omission is a state-consistency/accounting-hygiene bug rather than a case where reward is unconditionally destroyed on this call alone, but it breaks the invariant maintained by all comparable actuators and is the closest concrete analog to the reported bug class of "state-mutating actuator skips reward settlement before mutating the account that the reward calculation depends on."

### Likelihood Explanation
Any TRX holder can trigger this by unfreezing (V2) resources and later calling `CancelAllUnfreezeV2` (`cancelAllUnfreezeV2Contract`), a normal, permissionless operation with no privileged role required, reachable directly via broadcast transaction or TVM native contract call.

### Recommendation
Add `mortgageService.withdrawReward(ownerAddress)` (and `VoteRewardUtil.withdrawReward(ownerAddress, repo)` in the TVM path) as the first state-affecting statement in `CancelAllUnfreezeV2Actuator.execute()` and `CancelAllUnfreezeV2Processor.execute()`, consistent with `UnfreezeBalanceActuator`, `UnfreezeBalanceV2Actuator`, and `VoteWitnessActuator`, so that any pending reward is always settled against the account's pre-mutation state before frozen balance/weight is changed.

### Proof of Concept
1. Account freezes TRON_POWER/ENERGY, votes for a witness, and accrues reward across cycles.
2. Account calls `UnfreezeBalanceV2` to begin unfreezing part of its balance, then before the unfreeze period elapses, calls `CancelAllUnfreezeV2`.
3. `CancelAllUnfreezeV2Actuator.execute()` directly manipulates `ownerCapsule`'s frozen-V2 balances and `dynamicStore` total weights [10](#0-9)  without first calling `mortgageService.withdrawReward(ownerAddress)`, unlike every other actuator that mutates the same account fields (compare `UnfreezeBalanceV2Actuator.execute()` line 72) [2](#0-1) .
4. Because the reward-settlement checkpoint is skipped, the account's vote/reward accrual snapshot is not synchronized with its pre-mutation state at the same trust boundary as its sibling actuators, matching the "forfeited rebase/reward" bug pattern from the referenced report.

    long fee = calcFee();
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    byte[] ownerAddress;
    try {
      ownerAddress = getOwnerAddress().toByteArray();
    } catch (InvalidProtocolBufferException e) {
      logger.debug(e.getMessage(), e);
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    }
    AccountCapsule ownerCapsule = accountStore.get(ownerAddress);
    List<UnFreezeV2> unfrozenV2List = ownerCapsule.getUnfrozenV2List();

    AtomicLong atomicWithdrawExpireBalance = new AtomicLong(0L);

    right representing the pair object corresponding to tron power. The pair object for each

    resources for that resource type. */
    Triple<Pair<AtomicLong, AtomicLong>, Pair<AtomicLong, AtomicLong>, Pair<AtomicLong, AtomicLong>>
        triple = Triple.of(
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)),
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)),
        Pair.of(new AtomicLong(0L), new AtomicLong(0L)));
    for (UnFreezeV2 unFreezeV2 : unfrozenV2List) {
      updateAndCalculate(triple, ownerCapsule, now, atomicWithdrawExpireBalance, unFreezeV2);
    }
    ownerCapsule.clearUnfrozenV2();
    addTotalResourceWeight(dynamicStore, triple);

    long withdrawExpireBalance = atomicWithdrawExpireBalance.get();
    if (withdrawExpireBalance > 0) {
      ownerCapsule.setBalance(ownerCapsule.getBalance() + withdrawExpireBalance);
    }

    accountStore.put(ownerCapsule.createDbKey(), ownerCapsule);
    ret.setWithdrawExpireAmount(withdrawExpireBalance);
    Map<String, Long> cancelUnfreezeV2AmountMap = new HashMap<>();
    cancelUnfreezeV2AmountMap.put(BANDWIDTH.name(), triple.getLeft().getRight().get());
    cancelUnfreezeV2AmountMap.put(ENERGY.name(), triple.getMiddle().getRight().get());
    cancelUnfreezeV2AmountMap.put(TRON_POWER.name(), triple.getRight().getRight().get());
    ret.putAllCancelUnfreezeV2AmountMap(cancelUnfreezeV2AmountMap);
    ret.setStatus(fee, code.SUCESS);
    return true;

  public Map<String, Long> execute(CancelAllUnfreezeV2Param param, Repository repo) throws ContractExeException {
    Map<String, Long> result = new HashMap<>();
    byte[] ownerAddress = param.getOwnerAddress();
    AccountCapsule ownerCapsule = repo.getAccount(ownerAddress);
    long now = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    long withdrawExpireBalance = 0L;
    for (Protocol.Account.UnFreezeV2 unFreezeV2: ownerCapsule.getUnfrozenV2List()) {
      if (unFreezeV2.getUnfreezeExpireTime() > now) {
        String resourceName = unFreezeV2.getType().name();
        result.put(resourceName, result.getOrDefault(resourceName, 0L) + unFreezeV2.getUnfreezeAmount());

        updateFrozenInfoAndTotalResourceWeight(ownerCapsule, unFreezeV2, repo);
      } else {
        // withdraw
        withdrawExpireBalance += unFreezeV2.getUnfreezeAmount();
      }
    }
    if (withdrawExpireBalance > 0) {
      ownerCapsule.setBalance(ownerCapsule.getBalance() + withdrawExpireBalance);
    }
    ownerCapsule.clearUnfrozenV2();

    repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);

    result.put(VMConstant.WITHDRAW_EXPIRE_BALANCE, withdrawExpireBalance);
    return result;
  }

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }
