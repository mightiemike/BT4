### Title
Null-miner ATC divergence forces spurious sortition-winner rejection when the windowed median burn is zero - (File: stackslib/src/chainstate/burn/sortition.rs)

### Summary
`BlockSnapshot::get_miner_commit_carryover` short-circuits to `(AtcRational::zero(), true)` whenever `windowed_median_burns == 0` [1](#0-0) , which then feeds into `null_miner_probability` to compute a null-miner win probability, and that probability is combined with the VRF-derived sortition index in `null_miner_wins` to potentially override (reject) the actual burn-weighted winner [2](#0-1) . This mirrors the PartyDAO bug class: a special-cased "zero" branch substitutes a default outcome (null-miner defeats winner) that does not correspond to the actual burn-weight function, and an unprivileged miner can trigger the zero-median condition by controlling their own recent commit history.

### Finding Description
The burn-weighted sortition is supposed to pick the winning block-commit strictly as a function of the relative burn amounts in `state_transition.burn_dist`, via `sample_burn_distribution`, which maps a VRF-derived index into the burn-weighted ranges [3](#0-2) .

In Nakamoto epochs (`>= StacksEpochId::Epoch30`), after `select_winning_block` already determined the burn-weighted winner, `get_miner_commit_carryover` is called to compute the "assumed total commit" (ATC) ratio between this block's total burn and the historical windowed-median burn [4](#0-3) . The function is defined as `ATC = min(1, total-block-spend / median-windowed-total-block-spend)`. When the median is `0`, instead of treating this as an undefined/1.0 case (there is no historical baseline to compare against, so nothing indicates underpayment), the function forces `null_active = true` with `atc = 0`, i.e. treats the winner as having committed *0% of an assumed baseline*. That is then fed to `null_miner_probability(atc)` which, for `atc = 0`, computes a probability at or near the maximum of the logistic curve (up to the null miner's overwhelming ~default win chance) [5](#0-4) . `null_miner_wins` then samples this probability distribution against the VRF seed, and if the null miner range is hit, the previously-computed burn-weighted winner is discarded via `reject_winner_reason` [6](#0-5) .

The windowed median can be trivially forced to zero by an unprivileged, minority miner: `windowed_median_burns` (and `windowed_block_commits`) are derived from `MissedBlockCommit`/`LeaderBlockCommitOp` history over the `MINING_COMMITMENT_WINDOW` (6 blocks) [7](#0-6) , and the median-of-burns computation treats an absent commit slot as burn amount `1` (a floor value used "to give a miner a small chance of winning") rather than the miner's true recent spend [8](#0-7) . A miner (or any account that becomes the recorded "apparent sender" for a commit lineage) that has recently missed commits in more than half its window will have a computed `median_burn` of `1` or effectively very low, and if that value collapses to `0` for the *windowed* median used by `get_miner_commit_carryover`, the null-miner mechanism is unconditionally activated for that block's winner regardless of the amount actually burned in the winning commit.

This breaks the equality that "the winner selected purely by burn-weighted VRF sampling in `select_winning_block`/`sample_burn_distribution` is the sortition winner." Instead, a winner that legitimately won the burn-weighted lottery can be spuriously defeated by the null miner because of a degenerate zero-median condition that a minority participant's own commit history can produce, not because of anything wrong with the winning commit's actual burn amount.

### Impact Explanation
If different nodes/miners compute `windowed_median_burns` differently due to differing views of recent missed-commit history (e.g., across a burnchain fork, or because one node has a different windowed history for a given `apparent_sender`), one node could evaluate `windowed_median_burns == 0` while another computes a nonzero value, causing divergent `null_active`/ATC values and hence divergent `null_miner_wins` outcomes for the same burn block — i.e., temporary tip disagreement/consensus divergence on which block is the sortition winner (High, per the "minority-triggerable sortition/VRF/static-validation divergence" category). If consistently triggered network-wide (all nodes compute the same zero median from the shared burnchain history), it deterministically causes a valid, burn-weighted winning block-commit to be network-wide rejected in favor of "no sortition," which denies that miner their block reward for a block they legitimately won by burn amount — a bounded reward/tenure-assignment loss.

### Likelihood Explanation
Triggering requires only that a miner's own recent commit history (which they fully control, being unprivileged) produces a windowed-median burn of exactly zero — e.g., by missing enough commits in their commitment window so that `median_burn` (computed via `cmp::min(median_burn, most_recent_burn)` over a window where absent slots use the floor value `1`) is driven down. Given the floor is `1` rather than `0`, hitting an exact zero windowed median requires specific commit-history conditions (e.g., an all-missed window or specific missed-commit configurations at the sortition DB level, since `windowed_median_burns()` may be computed independently of the per-candidate floor-of-`1` used in `make_min_median_distribution`). This makes the likelihood non-trivial to hit exactly but plausible over many blocks/miners, especially in low-participation reward cycles or prepare-phase windows where `windowed_block_commits.len()` is small.

### Recommendation
When `windowed_median_burns == 0`, do not force `null_active = true` with `atc = 0`. Instead, either (a) treat a zero/undefined historical baseline as ATC = 1.0 (no null-miner activation) until a real baseline exists, mirroring how `block_burn_total >= windowed_median_burns` already clamps to 1.0, or (b) require a minimum number of nonzero historical samples before enabling the null-miner mechanism at all, so a single miner's own missed-commit history cannot unilaterally force a burn-weighted winner's rejection.

### Proof of Concept
1. A miner deliberately or incidentally misses commits over its `MINING_COMMITMENT_WINDOW`, so that the sortition DB's per-height missed-commit and block-commit history for that miner's `windowed_block_commits`/`windowed_missed_commits` yields `windowed_median_burns() == Some(0)` for the block being evaluated (see `BurnchainStateTransition::windowed_median_burns` consumed at `get_miner_commit_carryover` call site) [9](#0-8) .
2. On the next block, this same miner submits a legitimate, well-funded `LeaderBlockCommitOp` that wins the burn-weighted sortition via `select_winning_block`.
3. `get_miner_commit_carryover(Some(nonzero_total), Some(0))` returns `(AtcRational::zero(), true)` [1](#0-0) .
4. `null_miner_wins` is invoked with `atc = 0`, giving the null miner a large (near-maximal) win probability from `null_miner_probability`/`null_miner_logistic` [5](#0-4) .
5. Depending on the VRF-derived sortition index, the null miner may win, causing `reject_winner_reason` to be set and the legitimately burn-weighted winner to be discarded for that block — even though nothing was actually wrong with the amount that miner burned in the winning commit [6](#0-5) .

    /// Determine the miner's assumed total commit carryover.
    ///
    ///                              total-block-spend
    /// This is ATC = min(1, ----------------------------------- )
    ///                       median-windowed-total-block-spend
    ///
    /// Now, this value is 1.0 in the "happy path" case where miners commit the same BTC in this
    /// block as they had done so over the majority of the windowed burnchain blocks.
    ///
    /// It's also 1.0 if miners spend _more_ than this median.
    ///
    /// It's between 0.0 and 1.0 only if miners spend _less_ than this median.  At this point, it's
    /// possible that the "null miner" can win sortition, and the probability of that null miner
    /// winning is a function of (1.0 - ATC).
    ///
    /// Returns the ATC value, and whether or not it decreased.  If the ATC decreased, then we must
    /// invoke the null miner.
    fn get_miner_commit_carryover(
        total_burns: Option<u64>,
        windowed_median_burns: Option<u64>,
    ) -> (AtcRational, bool) {
        let Some(block_burn_total) = total_burns else {
            // overflow
            return (AtcRational::zero(), false);
        };

        let Some(windowed_median_burns) = windowed_median_burns else {
            // overflow
            return (AtcRational::zero(), false);
        };

        if windowed_median_burns == 0 {
            // no carried commit, so null miner wins by default.
            return (AtcRational::zero(), true);
        }

        if block_burn_total >= windowed_median_burns {
            // clamp to 1.0, and ATC increased
            return (AtcRational::one(), false);
        }

        (
            AtcRational::frac(block_burn_total, windowed_median_burns),
            true,
        )
    }

    pub(crate) fn null_miner_probability(atc: AtcRational) -> AtcRational {
        // compute min(1.0, (1.0 - atc) + (atc * adv))
        let adv = Self::null_miner_logistic(atc);
        let Some(one_minus_atc) = AtcRational::one().sub(&atc) else {
            // somehow, ATC > 1.0, then miners spent more than they did in the last sortition.
            // So, the null miner loses.
            warn!("ATC > 1.0 ({})", &atc.to_hex());
            return AtcRational::zero();
        };

        let Some(atc_prod_adv) = atc.mul(&adv) else {
            // if this is somehow too big (impossible), it would otherwise imply that the null
            // miner advantage is overwhelming
            warn!("ATC * ADV == INF ({} * {})", &atc.to_hex(), &adv.to_hex());
            return AtcRational::one();
        };

        let Some(sum) = one_minus_atc.add(&atc_prod_adv) else {
            // if this is somehow too big (impossible), it would otherwise imply that the null
            // miner advantage is overwhelming
            warn!(
                "(1.0 - ATC) + (ATC * ADV) == INF ({} * {})",
                &one_minus_atc.to_hex(),
                &atc_prod_adv.to_hex()
            );
            return AtcRational::one();
        };
        sum.min(&AtcRational::one())
    }

    fn null_miner_wins(
        sort_tx: &mut SortitionHandleTx,
        block_header: &BurnchainBlockHeader,

            // * range_start
            // * range_end
            // * candidate

        let Some(win_idx) =
            BlockSnapshot::sample_burn_distribution(&burn_dist, &vrf_seed, sortition_hash)
        else {
            // miner wins by default if there's no winner index
            return Ok(false);
        };

        test_debug!("win_idx = {}", win_idx);

        // null miner is index 0
        Ok(win_idx == 0)

impl MinerStats {
    /// Find the burn distribution for a single sortition's block-commits and missed-commits
    fn get_burn_distribution<SH: SortitionHandle>(
        sort_handle: &mut SH,
        burnchain: &Burnchain,
        burn_block_height: u64,
        block_commits: Vec<LeaderBlockCommitOp>,
        missed_commits: Vec<MissedBlockCommit>,
    ) -> Result<Vec<BurnSamplePoint>, BurnchainError> {
        // assemble the commit windows
        let mut windowed_block_commits = vec![block_commits];
        let mut windowed_missed_commits = vec![];

        if !burnchain.is_in_prepare_phase(burn_block_height) {
            // PoX reward-phase is active!
            // build a map of intended sortition -> missed commit for the missed commits
            //   discovered in this block.
            let mut missed_commits_map: HashMap<_, Vec<_>> = HashMap::new();
            for missed in missed_commits.iter() {
                if let Some(commits_at_sortition) =
                    missed_commits_map.get_mut(&missed.intended_sortition)
                {
                    commits_at_sortition.push(missed);
                } else {
                    missed_commits_map.insert(missed.intended_sortition.clone(), vec![missed]);
                }
            }

            for blocks_back in 0..(MINING_COMMITMENT_WINDOW - 1) {
                if burn_block_height.saturating_sub(1) < (blocks_back as u64) {
                    debug!("Mining commitment window shortened because block height is less than window size";
                           "block_height" => %burn_block_height.saturating_sub(1),
                           "window_size" => %MINING_COMMITMENT_WINDOW);
                    break;
                }
                let block_height = (burn_block_height.saturating_sub(1)) - (blocks_back as u64);
                let sortition_id = match sort_handle.get_block_snapshot_by_height(block_height)? {
                    Some(sn) => sn.sortition_id,
                    None => break,
                };
                windowed_block_commits.push(SortitionDB::get_block_commits_by_block(
                    sort_handle.sqlite(),
                    &sortition_id,
                )?);
                let mut missed_commits_at_height = SortitionDB::get_missed_commits_by_intended(
                    sort_handle.sqlite(),
                    &sortition_id,
                )?;
                if let Some(missed_commit_in_block) = missed_commits_map.remove(&sortition_id) {
                    missed_commits_at_height.extend(missed_commit_in_block.into_iter().cloned());
                }

                windowed_missed_commits.push(missed_commits_at_height);
            }
        } else {
            // PoX reward-phase is not active
            debug!(
                "Block {burn_block_height} is in a prepare phase or post-PoX sunset, so no windowing will take place"
            );

            assert_eq!(windowed_block_commits.len(), 1);
            assert!(windowed_missed_commits.is_empty());
        }
