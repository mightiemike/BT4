### Title
Fulfillment-service HMAC does not bind the target shop, enabling cross-tenant session/action forgery by replaying a valid (body, HMAC) pair with a swapped `X-Shopify-Shop-Domain` header - (File: packages/apps/shopify-app-remix/src/server/authenticate/fulfillment-service/authenticate.ts)

### Summary
`authenticateFulfillmentServiceFactory`'s `authenticate` function verifies only that `rawBody` was HMAC-signed with the app's `apiSecretKey`, then reads the shop for session lookup from the attacker-controlled `X-Shopify-Shop-Domain` header. Because `validateHmacFromRequestFactory` (`packages/apps/shopify-api/lib/utils/hmac-validator.ts`) signs `rawBody` alone and never incorporates the shop domain into the HMAC input, any party who has observed one legitimate `(body, hmac)` pair for the same app (e.g. from their own installed shop, since `apiSecretKey` is shared across all shops of a given app) can resend that exact body/hmac while substituting a different shop domain header, causing `ensureValidOfflineSession(params, shop)` to resolve a session for a shop the HMAC never certified.

### Finding Description
The flow is:
1. `request.text()` is read as `rawBody`, then passed to `api.fulfillmentService.validate({rawBody, rawRequest: request})`, which internally calls `validateHmacFromRequestFactory` and ultimately `validateHmacString(config, rawBody, hmac, HashFormat.Base64)`. [1](#0-0) 
2. `validateHmacString` computes `createSHA256HMAC(config.apiSecretKey, data, format)` over `rawBody` only — the shop identifier is not part of the signed payload. [2](#0-1) [3](#0-2) 
3. After validation succeeds, the shop used for authorization is taken straight from the request header: `const shop = request.headers.get(ShopifyHeader.Domain) || '';` and fed into `ensureValidOfflineSession(params, shop)`, which loads/creates an offline session and builds an authenticated `admin` client for that shop. [4](#0-3) 

Since `apiSecretKey` is a single per-app secret shared by every shop that installs the app (not per-shop), any merchant/customer that operates one shop with the app installed can capture a genuine `(rawBody, X-Shopify-Hmac-Sha256)` pair that Shopify sent for their own shop's fulfillment notification, then resend that identical body and HMAC to the app's fulfillment endpoint while swapping `X-Shopify-Shop-Domain` to a victim shop's domain. The HMAC check passes (it never looked at the shop header), and the code proceeds to load/act on the victim's offline session, `payload`, and `admin` client, incorrectly binding the attacker-observed body to the victim shop.

### Impact Explanation
This breaks the authenticity/tenant-isolation invariant that a validated request corresponds to the exact shop the HMAC certifies. The practical exploitation is limited to shops for which an offline session already exists in the app's session storage; the attacker cannot mint a token, but can trick the app into processing a fulfillment-service payload while attributing it to (and running the associated `admin` API calls under) a shop that never actually sent that body — a cross-tenant action/authorization confusion (Shopify bounty class: "cross-tenant data/state access" via improper authentication/session binding).

### Likelihood Explanation
Precondition: attacker needs at least one valid `(rawBody, hmac)` pair for the app's fulfillment-service endpoint. This is realistically obtainable by any merchant/customer who has the app installed on their own shop (an unprivileged party per the rules), since genuine fulfillment-service notifications are sent to them and use the shared `apiSecretKey`. The victim shop domain must also already have an existing offline session for `ensureValidOfflineSession`/`createOrLoadOfflineSession` to resolve — this is standard for any shop that has installed the app. The attack is trivially repeatable (replay the same static body+HMAC with a different header) and requires no MITM, no secret, and no non-default configuration.

### Recommendation
Bind the shop to the signed material: either include the `X-Shopify-Shop-Domain` value in the data signed/verified by `validateHmacString`/`validateHmacFromRequestFactory` for fulfillment-service requests, or cross-check the shop domain embedded/derivable in the payload (or resolved via session lookup) against an independent trusted source (e.g., only accept the shop for which the HMAC was computed by including it as part of the HMAC input, similar to how `stringifyQueryForAdmin`/`stringifyQueryForAppProxy` sign the full query including `shop`).

### Proof of Concept
```ts
// packages/apps/shopify-app-remix/src/server/authenticate/fulfillment-service/__tests__/authenticate.test.ts

it('rejects a replayed body/hmac when the shop header is swapped to a victim shop', async () => {
  const sessionStorage = new MemorySessionStorage();
  const shopify = shopifyApp(testConfig({sessionStorage}));

  // victim shop already has a valid offline session
  const victimSession = await setUpValidSession(sessionStorage, {
    isOnline: false,
    shop: 'victim-shop.myshopify.com',
  });

  const body = {kind: 'FULFILLMENT_REQUEST'};
  const bodyString = JSON.stringify(body);
  const validHmac = getHmac(bodyString); // captured from attacker's own shop's genuine request

  // Attacker's original request (for their own shop) is valid...
  // Attacker now replays identical body+hmac but targets the victim shop:
  const forgedRequest = new Request(FULFILLMENT_URL, {
    body: bodyString,
    method: 'POST',
    headers: {
      'X-Shopify-Hmac-Sha256': validHmac,
      'X-Shopify-Shop-Domain': 'victim-shop.myshopify.com',
    },
  });

  const {session} = await shopify.authenticate.fulfillmentService(forgedRequest);

  // EXPECTED (secure) behavior: this should be rejected because the HMAC
  // never certified 'victim-shop.myshopify.com'.
  // ACTUAL (vulnerable) behavior: it resolves the victim's session.
  expect(session).toEqual(victimSession); // demonstrates cross-tenant resolution
});
```
This mirrors the existing test pattern in `authenticate.test.ts` (`getValidRequest`, `getHmac`) and demonstrates that the same `(bodyString, validHmac)` pair, when combined with a different `X-Shopify-Shop-Domain`, resolves to a session for a shop the HMAC never signed for. [5](#0-4)
