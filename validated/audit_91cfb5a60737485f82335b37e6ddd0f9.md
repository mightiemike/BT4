## Title
Attacker can sandwich the module's own atomic Uniswap V3 quote-then-swap during gas-abstraction inbound execution, extracting value via slippage - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The GAS / GAS_AND_PAYLOAD inbound path and the outbound gas-refund path both convert a PRC20 gas token into native PC by fetching a live spot-price quote from a Uniswap V3 `QuoterV2` and immediately executing the swap with only a fixed 5% slippage tolerance and no TWAP or price-sanity check. Because the quote fetch and the swap are two sequential EVM calls issued by the module in the same block (triggered synchronously by the threshold-crossing `MsgVoteInbound`/`MsgVoteOutbound` transaction), an unprivileged attacker who observes the pending vote transaction in the mempool can sandwich it with ordinary swap transactions against the same pool — manipulating the spot price immediately before the module's quote/swap and reverting it immediately after — extracting value up to the 5% slippage band from every gas-abstraction deposit or refund.

### Finding Description
`ExecuteInboundGas` (and the analogous `ExecuteInboundGasAndPayload` / `gasAndPayloadDepositAutoSwap`) computes the amount of native PC to credit a user for their bridged gas token by:
1. `k.GetDefaultFeeTierForToken` / `k.GetSwapQuote` — a `commit=false` `CallEVM` to `QuoterV2.quoteExactInputSingle`, returning the *current spot price* of the PRC20/WPC pool [1](#0-0) .
2. Immediately computing `minPCOut = quote * 95 / 100` (flat 5% slippage, no TWAP or oracle cross-check) and calling `CallPRC20DepositAutoSwap`, which performs the real swap on-chain [2](#0-1) .

The same pattern occurs on the refund side: `applyGasRefund` fetches a fee tier and swap quote and then calls `CallUniversalCoreRefundUnusedGas` with `minPCOut` derived from the same just-fetched spot quote [3](#0-2) .

Both the quote fetch and the swap execution are triggered synchronously inside a single Cosmos transaction — the vote transaction that crosses the 2/3+ threshold calls `k.VoteInbound` → `k.ExecuteInbound` → `ExecuteInboundGas` in one atomic call chain [4](#0-3) . `MsgVoteInbound` from Universal Validators is a normal, publicly broadcast, gasless message wrapped in `MsgExec` [5](#0-4) , so the transaction that will trigger the module's swap is visible in the mempool before it lands in a block, exactly like the ordinary user transactions the report's PoC relies on.

An unprivileged attacker can therefore:
1. Watch the mempool for the UV vote transaction that will push an inbound ballot over threshold (2/3+ votes), knowing this triggers an in-block Uniswap V3 spot-price quote + swap against the PRC20/WPC pool.
2. Submit a front-running swap in the same block that pushes the pool's spot price against the module (within the 5% band the module tolerates), inflating or deflating the quote the module will read.
3. Let the vote transaction land, causing the module to swap at the manipulated price — the user is credited with up to 5% less PC than the fair price, or the refund/deposit swap consumes more of the pool's WPC/PRC20 liquidity than it should.
4. Submit a back-running swap to restore the pool price and capture the extracted value, net of trading fees.

This is the same bug class as the audited report — using a legitimate, permissionless-to-observe pricing mechanism with a static (non-TWAP) tolerance band to arbitrage a deposit/swap that a protocol executes at a predictable moment — except here the "victim" price source is the protocol's own AMM quoter rather than Chainlink, and the "deposit/withdraw" is the module's own atomic quote-then-swap flow rather than a user LP position.

### Impact Explanation
Each exploited inbound/outbound gas-abstraction event lets the attacker extract up to ~5% of the swapped notional from the protocol-managed PRC20/WPC liquidity pool or from the amount actually credited to the depositor/refund recipient, corrupting PRC20/native accounting for that UniversalTx. This is repeatable on every GAS, GAS_AND_PAYLOAD inbound and every successful outbound refund, so the aggregate drain scales with gas-abstraction volume. It requires no validator or TSS compromise — only public mempool observation and ordinary swap transactions.

### Likelihood Explanation
Medium. It requires the attacker to win/insert transactions immediately before and after a specific vote transaction in the same block (normal MEV/front-running conditions, not validator collusion), and the pool must have thin-enough liquidity that a swap within the 5% band is profitable net of gas/fees. Both conditions are commonly satisfiable for newly listed or low-liquidity PRC20/WPC pools.

### Recommendation
Do not derive `minPCOut` from a spot-price quote fetched moments before the swap. Use a manipulation-resistant reference price (e.g., a TWAP over multiple blocks, or the `ChainMeta`/oracle-reported external price) to bound the acceptable swap output, and/or tighten the slippage tolerance and add a maximum price-impact check against pool liquidity before executing `depositPRC20WithAutoSwap` / `refundUnusedGas`.

### Proof of Concept
1. Attacker monitors the mempool for a `MsgVoteInbound` (wrapped in `MsgExec`) that will be the threshold-crossing vote for a `GAS` or `GAS_AND_PAYLOAD` inbound targeting a known PRC20/WPC Uniswap V3 pool.
2. Attacker submits (with sufficient priority fee) a swap tx immediately before it in the same block that shifts the pool's spot price up to the edge of the module's 5% tolerance.
3. The vote tx lands, triggering `ExecuteInboundGas` → `GetSwapQuote` (reads the manipulated spot price) → `CallPRC20DepositAutoSwap` with `minPCOut` computed from that manipulated quote [6](#0-5) .
4. Attacker submits a back-running swap to restore the pool price, net of fees pocketing the value that should have gone to the deposit recipient or remained in the protocol's pool position.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
