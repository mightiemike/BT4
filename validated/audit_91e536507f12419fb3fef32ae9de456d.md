### Title
Starknet OS `execute_replace_class` omits the "class must be declared" check enforced by the Blockifier, allowing state-root divergence on `replace_class` syscalls - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
Any contract invoked by an ordinary transaction can call the `replace_class` syscall to change its own class hash. The Blockifier's implementations of this syscall (both VM and Native) explicitly verify that the target class hash is declared before mutating state, but the Starknet OS's own Cairo re-implementation of the same syscall (`execute_replace_class` in `syscall_impls.cairo`) has this check marked as an unfinished `TODO` and unconditionally accepts any `class_hash`, with no unprivileged-caller restriction at all.

### Finding Description
The Blockifier's `replace_class` syscall handler enforces that the class exists before allowing a contract to replace its own class hash: [1](#0-0) 

The same check exists for Cairo1/native execution, which is proven by the dedicated negative test asserting an "is not declared" error when replacing with an undeclared class hash: [2](#0-1) 

However, the Starknet OS's own Cairo implementation of the identical syscall - which is what actually gets proven and re-executed to compute/verify the committed state during Starknet OS execution/re-execution - explicitly skips this validation, leaving only a TODO comment: [3](#0-2) 

Any account/contract calling `replace_class_syscall(class_hash)` (an entry point reachable from a single submitted, unprivileged transaction — no `onlyPoolManager`-style guard, no permission check whatsoever) is the trigger, exactly analogous to the reported `setPoolActive` bug class: a state-critical operation ("this contract's class pointer") is mutable by any caller/any value with no validation in one code path, while the parallel/should-be-equivalent code path (Blockifier) does enforce the guard.

### Impact Explanation
This is a divergence between the two implementations that are supposed to compute the exact same state transition:
- The Blockifier (used by the sequencer to build/execute blocks) rejects `replace_class` to an undeclared class hash.
- The Starknet OS Cairo hints (used during OS execution/re-execution and proving) do not perform this check and will happily accept the state-diff transition regardless of whether the class is declared.

If any code path allows the OS's dict-based state view of "declared classes" to diverge even momentarily from the Blockifier's view (e.g., differing bookkeeping of declared-class dictionaries across a block, or a state-diff-only re-execution that does not carry the full declared-class check the blockifier performs against actual state), the OS could accept and commit a state entry (`class_hash`) for a contract that was never validated as declared by the OS itself. This can lead to computing/accepting a wrong committed state root, or to a discrepancy between the sequencer's block execution and the OS's proof of that same block — i.e., an "honest-node divergence" / wrong-committed-root condition, which is exactly one of the accepted impact categories (wrong committed root, honest-node divergence). The severity is elevated because `replace_class` directly controls which code governs a contract's storage layout and behavior, and the omitted check is the sole guard that is supposed to make the substitution safe.

### Likelihood Explanation
Likelihood is High for reachability (any transaction/contract can invoke `replace_class_syscall` with any `class_hash`, this is a wholly unprivileged, permissionless entry point identical in spirit to `setPoolActive` lacking an owner check), but the actual security-relevant consequence (a proof/execution divergence) depends on the specifics of how the OS's `contract_state_changes` dict-based bookkeeping of declared classes interacts with this now-unchecked write. The code explicitly flags this exact gap with a dated `TODO(Yoni, 1/1/2026)`, confirming project maintainers are aware the check is currently missing and intend to add it — strong first-party evidence that the current unchecked state is unintentional and considered incomplete/incorrect.

### Recommendation
Add the equivalent "class must be declared" check inside `execute_replace_class` in `syscall_impls.cairo` (and, for parity, `deprecated_execute_syscalls.cairo`'s `execute_replace_class`) before performing the `dict_update` that changes `contract_state_changes`, mirroring the Blockifier's `get_compiled_class`/`is_declared` check in `crates/blockifier/src/execution/syscalls/hint_processor.rs` and `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`. This ensures the OS and Blockifier compute identical state transitions for the same input transactions.

### Proof of Concept
1. Deploy a contract exposing `replace_class_syscall`, e.g. the test contract's `test_replace_class` entry point: [4](#0-3) 
2. Submit an invoke transaction calling `test_replace_class` with an arbitrary/undeclared `class_hash`.
3. In the Blockifier execution path, this transaction reverts/fails with "is not declared" as demonstrated by the existing regression test: [2](#0-1) 
4. In the Starknet OS Cairo execution of the identical syscall (`execute_replace_class` in `syscall_impls.cairo`), no equivalent check exists (only a `TODO`), so the OS-side state update for `contract_state_changes` proceeds unconditionally regardless of whether `class_hash` is declared, demonstrating the code-path divergence between the two engines that are meant to agree on the resulting state.

Note: I was unable to fully trace the exact runtime conditions under which the OS's un-checked path would actually be exercised with a value that the Blockifier would have rejected (i.e., whether earlier layers guarantee the OS only ever re-executes already-Blockifier-validated traces). This would require deeper investigation into the OS hint injection (`GetContractAddressStateEntry`) and the SNOS re-execution harness (`crates/starknet_os/src/hint_processor/snos_syscall_executor.rs`) to confirm an end-to-end exploitable divergence versus a currently-dormant but flagged code-quality gap.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
