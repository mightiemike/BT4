### Title
Missing Early Return in `validate_delegate_action_key` Allows Nonce Consumption on Rejected DelegateAction — (File: runtime/runtime/src/actions.rs)

### Summary

In `validate_delegate_action_key`, before `ProtocolFeature::FixDelegateActionDepositWithFunctionCallError` (protocol version 85), a missing `return` after setting `result.result = Err(DepositWithFunctionCall)` allows execution to fall through to the `receiver_id` and `method_name` checks. When those checks pass (receiver matches, method_names is empty or matches), execution reaches the nonce-commit block at lines 685–699 and writes the advanced nonce to `state_update` — even though `result.result` is already `Err`. The caller (`apply_delegate_action`) then sees `result.result.is_err()` and aborts receipt creation, but the nonce write has already been staged in the trie update and is committed with the chunk.

### Finding Description

`validate_delegate_action_key` in `runtime/runtime/src/actions.rs` validates the access key used to sign a `DelegateAction`. For a `FunctionCall`-permission key, the function checks three constraints in sequence: `deposit == 0`, `receiver_id` match, and `method_name` match.

Before the fix, the `deposit > 0` branch sets `result.result` to `Err(DepositWithFunctionCall)` but does **not** return:

```rust
if function_call.deposit > Balance::ZERO {
    result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
        InvalidAccessKeyError::DepositWithFunctionCall,
    ).into());
    // ← no early return before FixDelegateActionDepositWithFunctionCallError
}
if delegate_action.receiver_id() != &function_call_permission.receiver_id {
    result.result = Err(...ReceiverMismatch...);
    return Ok(());
}
// method_name check …
// Falls through to:
match nonce_update {
    DelegateNonceUpdate::AccessKey => {
        access_key.nonce = delegate_nonce.nonce();
        set_access_key(state_update, sender_id.clone(), public_key.clone(), &access_key);
    }
    …
}
```

When `deposit > 0`, `receiver_id` matches the key's `receiver_id`, and `method_names` is empty (any method allowed) or the method name matches, all three downstream checks pass silently. The nonce is written to `state_update` at lines 685–699. `validate_delegate_action_key` returns `Ok(())`. Back in `apply_delegate_action`, the guard `if result.result.is_err() { return Ok(()); }` fires and no receipt is emitted — but the nonce write is already staged and is committed with the rest of the chunk's trie update.

The secondary effect (documented in the test `test_delegate_deposit_with_function_call_reports_receiver_mismatch_before_fix`) is that when `receiver_id` does **not** match, the `ReceiverMismatch` branch overwrites `result.result`, masking the true `DepositWithFunctionCall` error and returning the wrong error code to the user. ### Impact Explanation

**Nonce consumed without action execution.** The sender's `FunctionCall`-key nonce is advanced in committed trie state even though the `DelegateAction` is rejected. Any subsequent meta-transaction signed with the same nonce will be rejected as `DelegateActionInvalidNonce`. A malicious or buggy relayer can therefore burn one nonce slot per submission without the sender's intended action ever executing, constituting transaction manipulation reachable from ordinary user-submitted meta-transactions.

**Wrong error code.** When `receiver_id` does not match, `ReceiverMismatch` overwrites `DepositWithFunctionCall`, breaking any client logic that branches on the error kind. [4](#0-3) 

### Likelihood Explanation

The trigger requires:
1. The sender holds a `FunctionCall`-permission access key (common for dApp integrations).
2. The sender signs a `DelegateAction` with `deposit > 0` targeting the key's permitted `receiver_id` and a permitted method name (or empty `method_names`).
3. A relayer submits the action on a node running protocol version < 85.

Condition 2 is plausible: a user or SDK may attempt to attach a yoctoNEAR deposit via a meta-transaction without knowing that `FunctionCall` keys prohibit deposits. The relayer pays gas but gains the ability to consume the sender's nonce at will for any such signed payload it holds. [5](#0-4) 

### Recommendation

The fix — adding `return Ok(());` immediately after setting `result.result = Err(DepositWithFunctionCall)` — is already gated behind `ProtocolFeature::FixDelegateActionDepositWithFunctionCallError` (protocol version 85):

```rust
if ProtocolFeature::FixDelegateActionDepositWithFunctionCallError
    .enabled(apply_state.current_protocol_version)
{
    return Ok(());
}
```

Once all nodes have upgraded past version 85, the legacy fall-through path and its protocol-version guard should be removed entirely to eliminate the dead code and the risk of future regressions. Additionally, the nonce-update block should be restructured so that it is unreachable when `result.result` is already `Err`, making the invariant structurally enforced rather than relying on every error branch remembering to `return`. [6](#0-5) 

### Proof of Concept

The existing test `deposit_with_function_call_and_receiver_mismatch` in `runtime/runtime/src/actions.rs` demonstrates the error-overwrite half of the bug. To demonstrate nonce consumption, extend it so that `receiver_id` in the access key matches the delegate action's `receiver_id` and `method_names` is empty, then run `validate_delegate_action_key` at a protocol version below 85 and inspect the `state_update` for the advanced nonce:

```rust
// access key: receiver_id = "token.test.near", method_names = []
// delegate action: receiver_id = "token.test.near", deposit = 1 yoctoNEAR, method = "ft_transfer"
// protocol_version < FixDelegateActionDepositWithFunctionCallError

let mut result = ActionResult::default();
validate_delegate_action_key(&mut state_update, &apply_state, (&delegate_action).into(), &mut result)
    .expect("no RuntimeError");

// result.result is Err(DepositWithFunctionCall) — action is rejected
assert!(result.result.is_err());

// But the nonce was written to state_update before the function returned:
let stored_nonce = get_access_key(&state_update, &sender_id, &public_key)
    .unwrap().unwrap().nonce;
assert_eq!(stored_nonce, delegate_action.nonce); // nonce consumed despite rejection
``` [7](#0-6) [8](#0-7)

pub(crate) fn apply_delegate_action(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    action_receipt: &VersionedActionReceipt,
    sender_id: &AccountId,
    signed_delegate_action: VersionedSignedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    if !signed_delegate_action.verify() {
        result.result = Err(ActionErrorKind::DelegateActionInvalidSignature.into());
        return Ok(());
    }
    let delegate_action = signed_delegate_action.delegate_action();
    if apply_state.block_height > delegate_action.max_block_height() {
        result.result = Err(ActionErrorKind::DelegateActionExpired.into());
        return Ok(());
    }
    if delegate_action.sender_id().as_str() != sender_id.as_str() {
        result.result = Err(ActionErrorKind::DelegateActionSenderDoesNotMatchTxReceiver {
            sender_id: delegate_action.sender_id().clone(),
            receiver_id: sender_id.clone(),
        }
        .into());
        return Ok(());
    }

    validate_delegate_action_key(state_update, apply_state, delegate_action, result)?;
    if result.result.is_err() {
        // Validation failed. Need to return Ok() because this is not a runtime error.
        // "result.result" will be return to the User as the action execution result.
        return Ok(());
    }

    fn deposit_with_function_call_and_receiver_mismatch(
        protocol_version: ProtocolVersion,
    ) -> ActionResult {
        let (_, signed_delegate_action) = create_delegate_action_receipt();
        let sender_id = signed_delegate_action.delegate_action.sender_id.clone();
        let sender_pub_key = signed_delegate_action.delegate_action.public_key.clone();

        let initial_nonce: u64 = 19_000_000;
        let access_key = AccessKey {
            nonce: initial_nonce,
            permission: AccessKeyPermission::FunctionCall(FunctionCallPermission {
                allowance: None,
                // Use a different receiver than the delegate action to trigger
                // ReceiverMismatch after DepositWithFunctionCall.
                receiver_id: "other.test.near".to_string(),
                method_names: Vec::new(),
            }),
        };

        let mut apply_state =
            create_apply_state(signed_delegate_action.delegate_action.max_block_height);
        apply_state.current_protocol_version = protocol_version;
        let mut state_update = setup_account(&sender_id, &sender_pub_key, &access_key);

        let mut delegate_action = signed_delegate_action.delegate_action;
        delegate_action.nonce = initial_nonce + 1;
        delegate_action.actions =
            vec![non_delegate_action(Action::FunctionCall(Box::new(FunctionCallAction {
                args: Vec::new(),
                deposit: Balance::from_yoctonear(1),
                gas: Gas::from_gas(300),
                method_name: "any_method".parse().unwrap(),

        let mut result = ActionResult::default();
        validate_delegate_action_key(
            &mut state_update,
            &apply_state,
            (&delegate_action).into(),
            &mut result,
        )
        .expect("validate_delegate_action_key must not return a RuntimeError");

        result
    }
