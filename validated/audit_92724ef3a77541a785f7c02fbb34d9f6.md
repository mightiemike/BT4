## Analysis

The op-geth bug's core invariant — "a sponsor's balance must be validated against the *cumulative* cost of all transactions it is expected to cover, not against each transaction individually" — maps onto Push Chain's gasless `MsgExecutePayload` flow, where the UEA (not the Cosmos tx signer) is billed for EVM gas *after* execution.

### Title
Unbounded admission of gasless `MsgExecutePayload` transactions against an underfunded UEA enables mempool/block resource-exhaustion DoS - (File: `app/ante/fee.go`, `app/txpolicy/gasless.go`, `x/uexecutor/keeper/execute_payload.go`)

### Summary
`MsgExecutePayload` is a gasless message type [1](#0-0) , so the Cosmos ante pipeline skips fee checking (`DeductFeeDecorator`) and the min-gas-price check entirely for it, and `AccountInitDecorator` will even create a brand-new zero-balance signer account on the fly to admit it [2](#0-1) [3](#0-2) . The actual gas cost of the payload is billed post-hoc against the *target UEA's* balance via `DeductGasFeesFromReceipt`, invoked only during full message execution inside `ExecutePayloadV2`/`ExecutePayload` [4](#0-3) [5](#0-4) . Because the Cosmos-layer authorization model deliberately allows `Signer != Owner` for any relayer to submit a pre-signed payload on behalf of a UEA [6](#0-5) , nothing at admission time checks whether the target UEA's real on-chain balance can cover even one of the pending payloads, let alone the sum of several concurrently-submitted ones.

### Finding Description
For a normal fee-paying Cosmos tx, `DeductFeeDecorator.checkDeductFee` verifies the sender has enough balance to pay fees at admission (`CheckTx`) time, and account sequence numbers naturally serialize submissions from one signer. `MsgExecutePayload` breaks both safeguards simultaneously:

1. It is exempt from `DeductFeeDecorator`'s balance check [2](#0-1) .
2. Any number of distinct, freshly created throwaway signer accounts can submit it — `AccountInitDecorator` auto-provisions a new account for each first-time gasless signer, requiring only a self-consistent signature (not the UEA owner's) [7](#0-6) , so sequence numbers never collide across submissions.
3. The only balance check that matters — whether the *target UEA* can actually pay for the EVM gas the payload will consume — happens inside `ExecutePayloadV2`/`ExecutePayload`, i.e., only during full message execution in `DeliverTx`, via `DeductGasFeesFromReceipt` [8](#0-7) , never at `CheckTx`/mempool admission.

This is precisely the op-geth pattern: many transactions that individually "look valid" (correct signatures, in-whitelist message type, gasless so no fee-balance requirement) are all admitted, but the balance that actually has to cover them (the UEA's) is never checked cumulatively — or even singularly — before admission. A UEA owner (or an attacker in possession of several pre-signed, future-dated payloads for one UEA, since `VerificationData` payloads are visible on submission and can be resubmitted/rebroadcast by anyone since `Signer` is unconstrained) can have N `MsgExecutePayload` transactions admitted into the mempool/block for free even though the UEA only has funds to cover one of them. Each of the N-1 remaining transactions still runs a real `CallUEAExecutePayload` EVM execution attempt during `DeliverTx` before failing at the post-hoc fee-deduction step, consuming validator CPU/EVM execution time and block space at zero cost to the submitter.

### Impact Explanation
This is an unprivileged, non-network-level denial-of-service vector reachable through the default `MsgExecutePayload` gasless submission path: attackers can force honest validators to repeatedly execute (and discard, via the `CacheContext` rollback) full EVM calls for free, at no cost to themselves, using an unlimited number of freshly auto-provisioned signer accounts. This degrades block processing throughput and can be used to crowd out legitimate gasless traffic (UV votes, TSS votes) that share the same gasless admission surface.

### Likelihood Explanation
High. No special privileges, no validator/relayer/TSS compromise, and no external chain compromise are required — an ordinary user can generate arbitrary key pairs (free), assemble `MsgExecutePayload` envelopes (whitelisted, fee-exempt), and repeatedly submit them against any UEA whose real balance is known to be low or zero, since the Cosmos-layer authorization model explicitly permits `Signer != Owner`.

### Recommendation
Before admitting or executing a gasless `MsgExecutePayload`, verify the target UEA's current native balance is sufficient to cover the payload's declared `MaxFeePerGas * GasLimit` (or a conservative estimate) — analogous to the op-geth fix that checks the sponsor's balance against the cumulative committed cost, not per-transaction in isolation. Consider adding a per-UEA or per-signer rate limit/quota for gasless message admission (mempool-level) to bound the amount of free EVM execution attempts a single, unprivileged actor can trigger.

### Proof of Concept
1. Deploy/derive a UEA with near-zero native `upc` balance.
2. Have the UEA owner sign several `UniversalPayload`s (different nonces, future deadlines) authorizing distinct calls with high `gasLimit`.
3. Using N distinct freshly generated Cosmos keypairs (each auto-provisioned for free by `AccountInitDecorator`), submit N `MsgExecutePayload` transactions relaying those payloads.
4. Observe all N pass `CheckTx`/ante admission with zero balance or fee requirement.
5. Observe that during block execution, the first succeeds; each subsequent transaction executes a full `CallUEAExecutePayload` EVM call (consuming real computation) before failing at `DeductGasFeesFromReceipt` with "insufficient gas," per the fix message referenced at [9](#0-8) , with the submitter paying nothing throughout.

### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.

// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
