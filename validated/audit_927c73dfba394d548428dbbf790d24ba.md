### Title
Uncaught `URL` parse exception in `sanitizeHost` on malformed base64 `host` param crashes unauthenticated request handling - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost` validates the `host` query parameter only with a loose base64 character-set regex before decoding it and passing the raw decoded string into `new URL()` with no `try/catch`. An anonymous attacker can supply a `host` value that is syntactically valid base64 but decodes into a string that makes `new URL()` throw (e.g. a decoded value containing multiple colons, which breaks WHATWG host:port parsing), causing an unhandled `TypeError` inside `sanitizeHost`, reached before any session lookup or authentication check.

### Finding Description
`sanitizeHost` in `packages/apps/shopify-api/lib/utils/shop-validator.ts` first checks `base64regex.test(host)` [1](#0-0) , which only verifies the character set (`[0-9a-zA-Z+/]+={0,2}`), not that the decoded content forms a well-formed hostname. It then calls `decodeHost(sanitizedHost)`, which is a thin wrapper over `atob` [2](#0-1) , and immediately feeds the result into `new URL(\`https://${decodeHost(sanitizedHost)}\`)` with no surrounding `try/catch`. If the decoded string is something like `::::` (base64: `Ojo6Og==`, which passes `base64regex`), the WHATWG URL host/port parser fails (ambiguous/invalid host:port split) and `new URL()` throws a `TypeError`, which propagates synchronously out of `sanitizeHost`.

This function is called directly from unauthenticated pre-session code paths, e.g. `validateShopAndHostParams` in both `shopify-app-remix` and `shopify-app-react-router` [3](#0-2) [4](#0-3) , and from `redirectToAuth`/`clientSideRedirect` in `shopify-app-express` [5](#0-4) . None of these call sites wrap the `sanitizeHost` call in a `try/catch`, and the existing test suite for `sanitizeHost` only exercises inputs that fail the base64 regex or fail the domain-suffix regex — it never exercises a base64-valid-but-URL-unparseable payload [6](#0-5) .

### Impact Explanation
This is reachable pre-authentication (before shop/session validation completes) and results in an unhandled exception thrown synchronously from a utility function with no defensive error handling in the library. However, downstream frameworks typically convert uncaught synchronous errors in a single request/loader into an HTTP 500 response (Express's default error handler for sync throws in route handlers; Remix/React Router's error boundary mechanism for loader throws) rather than crashing the whole server process. So the concrete, verifiable impact is a per-request 500 error / unhandled-exception path for that single request, not a demonstrated persistent server crash or resource-exhaustion DoS. This is a robustness/input-validation defect rather than a compromise of session, HMAC, OAuth, or cross-tenant data.

### Likelihood Explanation
Trivially reachable: any anonymous request to an embedded-app login/auth route with a crafted `host=Ojo6Og==` (or similar) query parameter triggers the throw, with no authentication, secret, or non-default configuration required.

### Recommendation
Wrap the `new URL()` call in `sanitizeHost` in a `try/catch`, treating any parse failure the same as a regex mismatch (`sanitizedHost = null`), and add a regression test covering base64-valid inputs that decode to strings which are not parseable as a URL authority (e.g. `Buffer.from('::::').toString('base64')`).

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/utils/__tests__/shop-validator.test.ts
test('does not throw for base64-valid host that fails URL parsing', () => {
  const shopify = shopifyApi(testConfig());
  const malformedHost = Buffer.from('::::').toString('base64'); // "Ojo6Og=="

  expect(() => shopify.utils.sanitizeHost(malformedHost)).not.toThrow();
  expect(shopify.utils.sanitizeHost(malformedHost)).toBe(null);
});
```
Expected today: the test fails because `sanitizeHost` throws `TypeError: Invalid URL` instead of returning `null`.

Equivalent HTTP PoC against an embedded Remix/React Router app:
```
GET /auth?shop=x.myshopify.com&host=Ojo6Og==
```
This reaches `validateShopAndHostParams` → `api.utils.sanitizeHost('Ojo6Og==')` → throws before `shop`/`host` validation completes or any session lookup occurs.
