## Analog Vulnerability Found

### Title
Pause/halt mechanism (`accept_new_txs`) is bypassed for transactions received via P2P propagation - ([File: crates/apollo_mempool_p2p/src/runner/mod.rs])

### Summary
The sequencer exposes an operator-controlled "pause" flag, `accept_new_txs`, meant to stop the node from admitting new transactions (analogous to the vault's paused state in the external report). However, this flag is only enforced at the HTTP server layer. Transactions arriving via the Mempool P2P gossip network are forwarded directly to the `Gateway`'s `add_tx`, completely bypassing the `accept_new_txs` check, so a "paused" node still validates, admits to its mempool, and can include transactions it was explicitly told to stop accepting.

### Finding Description
The pause check `check_new_transactions_are_allowed(accept_new_txs)` is invoked only inside the HTTP server's `add_rpc_tx` and `add_tx` handlers before the request reaches the gateway: [1](#0-0) [2](#0-1) 

The `Gateway`/`GenericGateway::add_tx` and `add_tx_inner` functions, which perform stateless/stateful validation and forward the transaction to the mempool, contain no reference to `accept_new_txs` at all: [3](#0-2) [4](#0-3) 

Meanwhile, `MempoolP2pRunner` receives transaction batches broadcast by peers over gossipsub and calls `gateway_client.add_tx(...)` directly — a separate code path from the HTTP server that never passes through `check_new_transactions_are_allowed`: [5](#0-4) 

Because `accept_new_txs` is a dynamic config value polled only by the HTTP server (`dynamic_config_poll`) and consulted solely in its handlers, it has zero effect on the gossip-sourced transaction path: [6](#0-5) 

### Impact Explanation
`accept_new_txs` is the node operator's mechanism to halt intake of new transactions (e.g., during maintenance, an incident, or a security freeze). Just as the reported vault's pause was expected to universally stop position-affecting operations yet `liquidatePosition` slipped through, here a node configured with `accept_new_txs = false` will still validate and admit transactions that arrive via P2P propagation from other network peers, and those transactions can proceed to the mempool and be included in blocks. This defeats the operator's intent to fully halt transaction processing, and since the same `Gateway::add_tx_inner` path is used, admitted transactions are treated identically to normally-submitted ones — they can still be batched, proposed, and committed to the chain, i.e., the "pause" provides no real guarantee against unwanted transaction inclusion.

### Likelihood Explanation
Any unprivileged transaction sender who submits a transaction to a different (non-paused) node in the network will have it propagate via gossipsub to the "paused" node, where `MempoolP2pRunner` will forward it straight to `Gateway::add_tx`, with no dependency on malicious/privileged actors — a normal user transaction submitted elsewhere in the network is sufficient to reach and bypass the paused node's gate.

### Recommendation
Enforce `accept_new_txs` (or an equivalent guard) inside `Gateway`/`GenericGateway::add_tx_inner` itself (or check it in `MempoolP2pRunner` before forwarding to the gateway client), so the pause applies uniformly regardless of transaction origin (HTTP or P2P).

### Proof of Concept
1. Operator sets node A's dynamic config `accept_new_txs = false` via the config manager, intending to halt all new transaction intake on node A.
2. A user submits a transaction to node B (`accept_new_txs = true`), which validates it and forwards it to node B's mempool/P2P propagator.
3. Node B's `MempoolP2pPropagatorClient` broadcasts the transaction batch over gossipsub.
4. Node A's `MempoolP2pRunner::start` loop receives the broadcasted batch in the `broadcasted_topic_server.next()` branch and calls `gateway_client.add_tx(GatewayInput { rpc_tx, message_metadata })` directly (`crates/apollo_mempool_p2p/src/runner/mod.rs:104-128`) — no call to `check_new_transactions_are_allowed` occurs anywhere in this path.
5. Node A's `Gateway::add_tx_inner` validates and forwards the transaction to node A's own mempool, despite `accept_new_txs = false`, demonstrating that the pause has no effect on P2P-sourced transactions.

    async fn add_tx_inner(
        &self,
        tx: RpcTransaction,
        p2p_message_metadata: Option<BroadcastedMessageMetadata>,
    ) -> GatewayResult<GatewayOutput> {
        let mut metric_counters = GatewayMetricHandle::new(&tx, &p2p_message_metadata);
        metric_counters.count_transaction_received();
        if let RpcTransaction::Invoke(RpcInvokeTransaction::V3(ref inv)) = tx {
            if !inv.proof_facts.is_empty() {
                metric_counters.count_private_transaction_received();
            }
        }
        let is_p2p = p2p_message_metadata.is_some();

        if let RpcTransaction::Declare(ref declare_tx) = tx {
            if let Err(e) = self.check_declare_permissions(declare_tx) {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        }

        // Perform stateless validations.
        self.stateless_tx_validator.validate(&tx)?;

        let tx_signature = tx.signature().clone();

        // Declare conversions overload the compiler component's CPU and memory. Reject declares if
        // there are too many declares compiling in parallel. The permit is held only across
        // compilation and released before stateful validation.
        let compilation_permit = if matches!(tx, RpcTransaction::Declare(_)) {
            Some(self.declare_compilation_semaphore.try_acquire().map_err(|_| {
                let error = StarknetError::too_many_concurrent_declare_compilations();
                metric_counters.record_add_tx_failure(&error);
                error
            })?)
        } else {
            None
        };

        let (internal_tx, executable_tx, proof_data) =
            self.convert_rpc_tx_to_internal_and_executable_txs(tx, &tx_signature).await?;
        drop(compilation_permit);

        let mut stateful_transaction_validator = self
            .stateful_tx_validator_factory
            .instantiate_validator(self.config.dynamic_config.native_classes_whitelist.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let nonce = stateful_transaction_validator
            .extract_state_nonce_and_run_validations(&executable_tx, self.mempool_client.clone())
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let proof_archive_handle = self
            .store_proof_and_spawn_archiving(proof_data, internal_tx.tx_hash, is_p2p)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let gateway_output = create_gateway_output(&internal_tx);

        let add_tx_args = AddTransactionArgsWrapper {
            args: AddTransactionArgs::new(internal_tx, nonce),
            p2p_message_metadata,
        };

        // Await as late as possible for proof archiving before sending the transaction to the
        // mempool.
        Self::await_proof_archiving(proof_archive_handle)
            .await
            .inspect_err(|e| metric_counters.record_add_tx_failure(e))?;

        let mempool_client_result = self.mempool_client.add_tx(add_tx_args).await;
        match mempool_client_result_to_deprecated_gw_result(&tx_signature, mempool_client_result) {
            Ok(()) => {}
            Err(e) => {
                metric_counters.record_add_tx_failure(&e);
                return Err(e);
            }
        };

        metric_counters.transaction_sent_to_mempool();

        Ok(gateway_output)
    }
