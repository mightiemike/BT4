### Title
Unbounded O(n) `PendingInbounds.Walk` in inbound ballot terminal hook enables gas-exhaustion DoS on inbound finalization - ([File: x/uexecutor/keeper/ballot_hooks.go])

### Summary
`afterInboundBallotTerminal` (invoked via `AfterBallotTerminal` on every terminal transition of an `INBOUND_TX` ballot) performs a full, unbounded scan of the entire `PendingInbounds` collection to locate the entry owning a given `ballotID`, exactly analogous to the PolicyBook.sol `_updateWithdrawalQueue` bug: an in-protocol "queue" (here, the `PendingInbounds` map) is walked to completion on every processing call, with no batching, pagination, or per-call cap.

### Finding Description
`x/uexecutor/keeper/ballot_hooks.go` comments explicitly assume "the pending set is small and transient" [1](#0-0) , but nothing enforces that assumption. Every ordinary user crosschain deposit creates a `PendingInbounds` entry the moment the first UV votes on the observation [2](#0-1) , and the entry is only removed once the corresponding ballot reaches a terminal state (`PASSED`/`REJECTED`/`EXPIRED`) for ALL variants [3](#0-2) .

Because inbound observation is driven purely by external-chain deposit events that any unprivileged user can generate (simply by sending many small crosschain transfers through the gateway), the `PendingInbounds` map size is attacker-influenced and unbounded — there is no queue depth cap or rate limit on how many entries can be outstanding simultaneously (e.g. while waiting for confirmation delay, or while ballots slowly accumulate votes).

On every single ballot terminal transition (`MarkBallotFinalized` or `MarkBallotExpired` in `x/uvalidator/keeper/ballot.go`) the hook `fireBallotTerminalHook` synchronously calls `AfterBallotTerminal` → `afterInboundBallotTerminal`, which does a full `Walk` over `PendingInbounds`, inspecting every entry's `Variants` slice, until it finds the one containing the matching `ballotID`:
```go
err := h.k.PendingInbounds.Walk(ctx, nil, func(key string, e types.PendingInboundEntry) (bool, error) {
    for _, v := range e.Variants {
        if v.BallotId == ballotID {
            utxKey, entry, found = key, e, true
            return true, nil
        }
    }
    return false, nil
})
``` [4](#0-3) 

This walk is O(n) in the number of currently-pending inbounds, and it fires **once per terminal vote** (`VoteInbound` → `CheckIfFinalizingVote` → `MarkBallotFinalized`/`MarkBallotExpired` → `fireBallotTerminalHook`) [5](#0-4) [6](#0-5) . Additionally, `CreateBallot` calls `ExpireBallotsBeforeHeight`, which can mark and terminate multiple stale ballots in a single call, each one separately triggering another full `PendingInbounds` walk within the same transaction [7](#0-6) .

An attacker who drives up the number of concurrent, slow-to-finalize (or never-finalizing) inbound entries — e.g. by submitting many crosschain deposits with distinct nonces/log indexes that only receive partial validator agreement, keeping ballots pending near their expiry window — inflates `PendingInbounds` size. Every subsequent legitimate `MsgVoteInbound` (gasless, from honest UVs) that reaches a terminal transition then pays for a full walk over that inflated set, multiplying gas cost linearly with queue size. Because `MsgVoteInbound` is gasless (fee-exempt but not gas-metering-exempt), this raises the risk that vote transactions from honest UVs run out of gas mid-block and fail, stalling inbound finalization for the whole set of in-flight users, or as the queue grows further, forces node operators to raise gas limits indefinitely — a state-growth-driven DoS reachable purely from ordinary/attacker-driven deposit volume, without any privileged actor.

### Impact Explanation
This is a scoped, non-privileged denial-of-service vector on the universal execution path: normal user deposit volume grows `PendingInbounds` without bound, and the linear-scan hook that fires on every inbound ballot finalize/expire event turns O(1) per-vote processing into O(n). At scale this can stall or fail honest UV `MsgVoteInbound` transactions, delaying or blocking finalization of legitimate crosschain deposits network-wide — a material, non-network-level DoS in the inbound voting/finalization flow that is explicitly in scope ("denial of service only when it is not network-level and is reachable without privileged control").

### Likelihood Explanation
Likelihood is moderate: it requires sustained volume of concurrent pending inbounds (achievable by any user submitting many source-chain transactions, or by inducing validator disagreement to keep ballot variants pending near expiry), but no privileged access, no validator collusion, and no protocol bypass are needed — only ordinary deposit transactions repeated at scale.

### Recommendation
Store an explicit reverse index from `ballotID -> utxKey` (populated in `RecordInboundVote` alongside the variant append) so `afterInboundBallotTerminal` can do an O(1) lookup instead of a full collection walk. Alternatively, bound `PendingInbounds` size (reject/backpressure new inbound votes once a cap is reached) or process the terminal-hook lookup incrementally/paginated per call, mirroring the PolicyBook.sol fix of processing a limited number of queue items per invocation rather than scanning to completion every time.

### Proof of Concept
Conceptual (not executed, since this requires runtime/gas measurement not available via static review):
1. Submit N distinct crosschain deposit inbound events (distinct `tx_hash`/`log_index`) from a controlled source-chain account, each observed and voted by only a subset of UVs so their ballots remain `PENDING` near/at expiry, inflating `PendingInbounds` to size N.
2. Submit/await a normal `MsgVoteInbound` for any other in-flight inbound that reaches quorum (PASSED) or expires.
3. Measure gas consumed by `afterInboundBallotTerminal`'s `PendingInbounds.Walk` as a function of N — demonstrate it scales linearly and can be driven to exceed a UV's default gas limit for `MsgVoteInbound`, causing that (and subsequent) terminal votes to fail with out-of-gas.

Note: I was unable to execute this PoC or find any existing gas-benchmark/test asserting a bound on `PendingInbounds` size in the indexed code; if further certainty is needed a Devin session with full repo/build access should add a load test measuring `afterInboundBallotTerminal` gas cost at increasing `PendingInbounds` sizes.

func (k Keeper) MarkBallotFinalized(ctx context.Context, id string, status types.BallotStatus) error {
	if status != types.BallotStatus_BALLOT_STATUS_PASSED && status != types.BallotStatus_BALLOT_STATUS_REJECTED {
		return fmt.Errorf("invalid finalization status: %v", status)
	}

	ballot, err := k.Ballots.Get(ctx, id)
	if err != nil {
		return err
	}

	k.Logger().Debug("marking ballot as finalized",
		"ballot_id", id,
		"final_status", status.String(),
	)

	if err := k.ActiveBallotIDs.Remove(ctx, id); err != nil {
		return err
	}
	if err := k.FinalizedBallotIDs.Set(ctx, id); err != nil {
		return err
	}

	ballot.Status = status
	if err := k.Ballots.Set(ctx, id, ballot); err != nil {
		return err
	}

	k.fireBallotTerminalHook(ctx, ballot.Id, ballot.BallotType, status)
	return nil
}

// ExpireBallotsBeforeHeight checks active ballots and marks expired ones.
// It uses a two-phase approach: first collect IDs to expire, then mutate,
// to avoid modifying the ActiveBallotIDs collection during iteration.
func (k Keeper) ExpireBallotsBeforeHeight(ctx context.Context, currentHeight int64) error {
	iter, err := k.ActiveBallotIDs.Iterate(ctx, nil)
	if err != nil {
		return err
	}

	// Phase 1: collect IDs to expire
	var toExpire []string
	for ; iter.Valid(); iter.Next() {
		id, err := iter.Key()
		if err != nil {
			iter.Close()
			return err
		}

		ballot, err := k.Ballots.Get(ctx, id)
		if err != nil {
			iter.Close()
			return err
		}

		if ballot.BlockHeightExpiry <= currentHeight {
			toExpire = append(toExpire, id)
		}
	}

	// Close iterator explicitly before mutation phase to release the IAVL snapshot
	iter.Close()

	if len(toExpire) > 0 {
		k.Logger().Debug("expiring stale ballots", "count", len(toExpire), "current_height", currentHeight)
	}

	// Phase 2: expire collected ballots (safe — iterator is closed)
	for _, id := range toExpire {
		if err := k.MarkBallotExpired(ctx, id); err != nil {
			return err
		}
	}

	return nil
}

// CheckIfFinalizingVote inspects whether the just-cast vote pushes the ballot
// over its threshold and, if so, drives the finalization through
// MarkBallotFinalized — the single canonical write path for terminal status
// transitions, which applies CEI-style ordering on the secondary indexes.
func (k Keeper) CheckIfFinalizingVote(ctx context.Context, b types.Ballot) (types.Ballot, bool, error) {
	ballot, isFinalizing := b.IsFinalizingVote()
	if !isFinalizing {
		return b, false, nil
	}

	k.Logger().Debug("ballot reached finalization threshold",
		"ballot_id", ballot.Id,
		"ballot_status", ballot.Status.String(),
	)

	if err := k.MarkBallotFinalized(ctx, ballot.Id, ballot.Status); err != nil {
		return ballot, false, errors.Wrap(err, "failed updating finalized ballot")
	}

	k.Logger().Debug("ballot finalized",
		"ballot_id", ballot.Id,
		"ballot_status", ballot.Status.String(),
	)
	return ballot, true, nil
}
