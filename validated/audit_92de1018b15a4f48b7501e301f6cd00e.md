### Title
Signer-weight apportionment lets a single staker mint extra voting weight by splitting stake across multiple signer keys - (File: stackslib/src/chainstate/nakamoto/signer_set.rs)

### Summary
`NakamotoSigners::pox_5_make_signer_set` computes each Nakamoto reward-cycle signer's block-approval weight with a largest-remainder ("Hare quota") apportionment: a `threshold = ceil(total_locked / reward_slots)` is computed, each key gets `floor(stacked/threshold)` base weight, and any `leftover = reward_slots - base` slots are handed out one-per-key to the keys with the largest fractional remainder [2](#0-1) . Because stake is aggregated strictly per `signer_key` before this apportionment runs [3](#0-2) , and every `stack-stx`/`delegate-stx` position independently chooses its own `signer_key`, a single economic actor who splits an unchanged total of locked uSTX across `k` distinct signer keys is treated as `k` separate apportionment participants, each eligible for its own largest-remainder bonus, instead of one participant capped at `+1` bonus slot as the per-key invariant assumes [4](#0-3) . This exactly mirrors the analog bug class: an unprivileged party inflates its *counted* share (here, apportionment participants) relative to its real economic contribution, without needing majority stake, breaking the intended equality "signer weight ∝ staked uSTX per economic entity."

### Finding Description
The comment above the function explicitly frames the algorithm as apportioning `reward_slots` "across signers in proportion to stake" [5](#0-4) , and the test suite encodes this as an invariant: each *signer_key's* final weight lies in `{floor(stacked/threshold), floor(stacked/threshold)+1}` [4](#0-3) . That invariant is only true per-key, not per-economic-owner. `weight_zero_entries_are_filtered` and `equal_stakes_exceeding_reward_slots_are_not_all_zeroed` demonstrate that keys with stake far below `threshold` (floor = 0) can still win a full weight-1 "leftover" slot purely by ranking near the top of the remainder ordering (remainder = full stake when stake < threshold) [6](#0-5) . Consequently, an actor who fragments a total stake `S` into `k` keys each just under `threshold` captures up to `min(k, leftover)` bonus slots — each worth a full weight unit — whereas the *same total stake S* registered under a single key can win at most one bonus slot on top of its base `floor(S/threshold)`. Two stakers locking identical uSTX end up with materially different signing weight solely because one split identities, which the signer set feeds directly into `NakamotoBlockHeader::verify_signer_signatures`/`compute_voting_weight_threshold`, i.e. into the 70%-weight quorum that decides whether a Nakamoto block is accepted [7](#0-6) , and into the signers-voting aggregate-key threshold contract, which weights votes "by the amount of reward slots that the signer controls" [8](#0-7) .

### Impact Explanation
This breaks the equality "signer approval weight is proportional to bonded/staked uSTX," which underlies both Nakamoto block-approval quorum and the `.signers-voting` aggregate-key threshold. A minority staker (well under the honest per-slot threshold) can, by unprivileged registration choices alone (choosing new `signer_key`s for separate stacking calls), acquire disproportionately more voting weight than an equally-funded non-splitting staker, up to the size of the leftover pool (bounded by `reward_slots`, which is on the order of the total number of reward slots in a cycle). This is a genuine reward/weight mis-apportionment bounded to signing/voting weight (not block-reward theft or a chain split by itself), matching the "High" bucket: a minority-triggerable divergence between intended (stake-proportional) and actual signer weight, capable of shifting who can push a block or aggregate-key vote past the 70% threshold.

### Likelihood Explanation
No node-operator, admin, or third-party key is required: any principal that can already call `stack-stx`/`delegate-stx` multiple times with different `signer-key` arguments (an ordinary, permissionless PoX-5 operation) can trigger this at every reward-cycle boundary. It requires no majority of network stake, only enough capital to reach the reward-slot dust threshold multiple times, so it is squarely a minority/unprivileged trigger.

### Recommendation
Aggregate stake by the underlying staking principal/owner (or otherwise bind the apportionment unit to one identity per economic contributor) before running the largest-remainder round, or cap the number of leftover-round bonus slots a single principal's set of registered keys may win, so that fragmenting stake across many `signer_key`s cannot yield more aggregate weight than registering the same total stake under one key would.

### Proof of Concept
1. Let `reward_slots = R` and `threshold = ceil(total_locked / R)`.
2. Staker A locks `S = threshold - 1` uSTX under a single `signer_key`; base weight `= floor(S/threshold) = 0`, and A wins at most 1 leftover slot (if remainder is high enough), for a maximum of weight `1`.
3. Staker B locks the same total `S` split as `k` separate `stack-stx` calls, each for `S/k < threshold` uSTX, each under a fresh, distinct `signer_key`. Each fragment has base weight `0` and remainder `= S/k`. If `k <= leftover` and B's fragments' remainders outrank other participants' remainders (easy when other stake is a multiple of `threshold`, i.e., remainder 0), all `k` fragments win a leftover slot, giving B aggregate weight `k`, i.e., `k` times what A achieved with identical total stake — directly reproducible against `NakamotoSigners::pox_5_make_signer_set` [9](#0-8)  using the same harness as the existing `weight_zero_entries_are_filtered`/`equal_stakes_exceeding_reward_slots_are_not_all_zeroed` unit tests [10](#0-9) .

    pub(crate) fn pox_5_make_signer_set<I>(
        entries: &mut I,
        pox_constants: &PoxConstants,
    ) -> Result<Pox5SignerSetOutput, ChainstateError>
    where
        I: Iterator<Item = Result<RawPox5Entry, PoxEntryParsingError>>,
    {
        let mut signer_set = HashMap::new();
        let mut total_ustx_locked = 0u128;
        for entry_res in entries {
            let entry = match entry_res {
                Ok(x) => x,
                Err(PoxEntryParsingError::Skip(err_str)) => {
                    warn!(
                        "Error while iterating PoX-5 entries, impacting a single entry. Dropping entry from signer set";
                        "error" => err_str
                    );
                    continue;
                }
                Err(PoxEntryParsingError::Abort(err_str)) => {
                    error!(
                        "Abort-triggering error while iterating PoX-5 entries";
                        "error" => err_str
                    );
                    return Err(ChainstateError::PoxNoRewardCycle);
                }
            };

            total_ustx_locked += entry.amount_ustx;

            signer_set
                .entry(entry.signer_key)
                .and_modify(|existing_entry| *existing_entry += entry.amount_ustx)
                .or_insert_with(|| entry.amount_ustx);
        }

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
        let reward_slots = u128::from(pox_constants.reward_slots());
        let threshold = std::cmp::max(1, total_ustx_locked.div_ceil(reward_slots));

        struct Apportionment {
            signing_key: [u8; SIGNERS_PK_LEN],
            stacked_amt: u128,
            weight: u128,
            remainder: u128,
        }

        let mut apportioned: Vec<Apportionment> = signer_set
            .into_iter()
            .map(|(signing_key, stacked_amt)| Apportionment {
                signing_key,
                stacked_amt,
                weight: stacked_amt / threshold,
                remainder: stacked_amt % threshold,
            })
            .collect();

        // Guaranteed `<= reward_slots` by the ceil quota, so leftover does not underflow.
        let assigned: u128 = apportioned.iter().map(|entry| entry.weight).sum();
        let mut leftover = reward_slots.saturating_sub(assigned);

        if leftover > 0 {
            // Largest fractional remainder wins the next slot; ties broken by signing_key
            // ascending so the apportionment is deterministic (and matches the final sort).
            apportioned.sort_by(|a, b| {
                b.remainder
                    .cmp(&a.remainder)
                    .then_with(|| a.signing_key.cmp(&b.signing_key))
            });
            for entry in apportioned.iter_mut() {
                if leftover == 0 {
                    break;
                }
                entry.weight += 1;
                leftover -= 1;
            }
        }

fn weight_zero_entries_are_filtered() {
    // reward_slots == 4. Four big signers with equal stake consume all four
    // leftover slots (their remainders are larger than the dust signer's), so

        signer_key: dust,
        amount_ustx: 1,

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );
}
