Based on my investigation, I found a genuine analog to the referrer-validation bug in the Universal Validator voting path: the eligibility check used across all gasless voting message handlers (`MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteFundMigration`) verifies that a signer's underlying core validator is *bonded* and *not tombstoned*, but never verifies that the corresponding Universal Validator has completed onboarding (i.e., is in `UV_STATUS_ACTIVE`). This mirrors the referral bug's pattern: checking a *relationship* (authority match) while skipping the *prerequisite completion* check (paid fee / created code).

### Title
Universal Validator vote admission does not require ACTIVE lifecycle status, allowing PENDING_JOIN validators' votes to be admitted - (File: x/uvalidator/keeper/voting.go)

### Summary
`IsBondedUniversalValidator`, used as the sole eligibility gate in `VoteInbound`, `VoteOutbound`, `VoteChainMeta`, and `VoteFundMigration`, only checks (1) the validator is present in `UniversalValidatorSet` and (2) the underlying core validator is bonded in the staking module. It never inspects `LifecycleInfo.CurrentStatus`, so a validator freshly registered via `AddUniversalValidator` — which explicitly starts in `UVStatus_UV_STATUS_PENDING_JOIN` — passes this gate as long as its core validator is bonded.

### Finding Description
`AddUniversalValidator` always creates new registrations with `initialStatus := types.UVStatus_UV_STATUS_PENDING_JOIN` [1](#0-0) . The intended lifecycle model treats `PENDING_JOIN` as a distinct, non-participating state from `UV_STATUS_ACTIVE`, and other code explicitly checks for `ACTIVE` before treating a validator as an authorized participant (e.g., `IsActiveUniversalValidator`) [2](#0-1) .

However, the admission check actually used for casting votes on the gasless message paths is `IsBondedUniversalValidator`, which only checks set-membership and core-validator bonded status — it does not read or check `LifecycleInfo.CurrentStatus` at all: [3](#0-2) 

This function is invoked as the gate in every voting message handler:
- `VoteInbound` [4](#0-3) 
- `VoteOutbound` [5](#0-4) 
- `VoteChainMeta` [6](#0-5) 
- `VoteFundMigration` [7](#0-6) 

In none of these handlers is `LifecycleInfo.CurrentStatus == UV_STATUS_ACTIVE` checked prior to accepting and recording the vote.

**Important caveat / uncertainty:** I was not able to fully confirm, within the remaining tool budget, whether `GetEligibleVoters` (the function that supplies the `voters` list and `votesNeeded` threshold used to actually tally and finalize ballots in `k.uvalidatorKeeper.VoteOnBallot`, see `x/uexecutor/keeper/voting.go` lines 11-71) filters strictly to `ACTIVE` validators. If it does, a PENDING_JOIN validator's vote would still be *recorded* (accepted by the message-level gate) but excluded from the voter set used for quorum math in `AddVoteToBallot`/`Ballot.AddVote`, which could reject the vote at a deeper layer or simply make it inert. I could not verify the implementation of `Ballot.AddVote` in `x/uvalidator/types/ballot.go` to confirm whether it validates that the voting address is a member of the passed `voters` list before counting it, nor could I confirm `GetEligibleVoters`'s filtering criteria before running out of iterations.

Because of this unresolved dependency, I cannot assert with certainty that a PENDING_JOIN validator's vote is actually counted toward ballot finalization (only that the message-level admission control, unlike the referrer-fee-payment case, does not itself perform the prerequisite "has completed onboarding" check).

### Impact Explanation
If `GetEligibleVoters` does not itself filter out non-ACTIVE validators (or if any other call site uses `IsBondedUniversalValidator` as a standalone authorization gate without separately consulting `GetEligibleVoters`), a validator that is merely bonded but still `PENDING_JOIN` — i.e., has not completed the TSS key-join process — would be treated as authorized to vote on inbound/outbound/chain-meta/fund-migration ballots. This could allow premature or unauthorized influence over ballot finalization, UTX creation, or TSS fund migration voting before the validator has actually joined the active validator/TSS set, which is a corruption of honest-validator finalization invariants in the target scope. However, this requires confirmation of `GetEligibleVoters` behavior to determine if it is actually exploitable end-to-end.

### Likelihood Explanation
Likelihood is uncertain without confirming `GetEligibleVoters`. If it correctly filters to ACTIVE-only validators (which is the more likely design given `IsActiveUniversalValidator` exists elsewhere for that exact purpose), then this is a defense-in-depth gap rather than an exploitable bug — the vote would be accepted at the message-handler level but rendered ineffective at the ballot-tallying level. Given the uncertainty, I cannot confidently confirm this as a standalone exploitable vulnerability without further verification of `x/uvalidator/keeper/validator.go`'s `GetEligibleVoters` and `x/uvalidator/types/ballot.go`'s `AddVote`.

### Recommendation
Regardless of whether `GetEligibleVoters` provides a secondary filter, `IsBondedUniversalValidator` should be hardened to also check `LifecycleInfo.CurrentStatus == UVStatus_UV_STATUS_ACTIVE` (mirroring `IsActiveUniversalValidator`), so that message-level admission control and ballot-level quorum eligibility are consistently enforced at both layers, eliminating any dependency on the caller doing the right secondary check.

### Proof of Concept
Not constructed — this requires confirming `GetEligibleVoters`'s filtering logic and `Ballot.AddVote`'s voter-list validation, which I was unable to complete within the available tool budget. A Devin session with full repository access should verify:

2. Does `Ballot.AddVote` in `x/uvalidator/types/ballot.go` reject votes from addresses not in the passed `voters` slice?
3. If both checks are strict, this finding should be downgraded/rejected as non-exploitable; if either is missing, this is directly exploitable by any freshly self-registered (bonded) core validator calling `AddUniversalValidator` and then immediately submitting `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta`/`MsgVoteFundMigration` before reaching ACTIVE status.

// IsActiveUniversalValidator returns true if the given validator address is
// currently registered as an active universal validator.
func (k Keeper) IsActiveUniversalValidator(
	ctx context.Context,
	validatorOperatorAddr string,
) (bool, error) {
	valAddr, err := sdk.ValAddressFromBech32(validatorOperatorAddr)
	if err != nil {
		return false, err
	}

	exists, err := k.UniversalValidatorSet.Has(ctx, valAddr)
	if err != nil {
		return false, err
	}
	if !exists {
		return false, nil
	}

	uv, err := k.UniversalValidatorSet.Get(ctx, valAddr)
	if err != nil {
		return false, fmt.Errorf("failed to get universal validator: %w", err)
	}

	isActive := uv.LifecycleInfo.CurrentStatus == types.UVStatus_UV_STATUS_ACTIVE
	k.Logger().Debug("checked active universal validator status",
		"validator", validatorOperatorAddr,
		"is_active", isActive,
		"current_status", uv.LifecycleInfo.CurrentStatus.String(),
	)

	return isActive, nil
}

func (k Keeper) IsBondedUniversalValidator(ctx context.Context, universalValidator string) (bool, error) {
	k.Logger().Debug("checking bonded status of universal validator", "validator", universalValidator)

	accAddr, err := sdk.AccAddressFromBech32(universalValidator)
	if err != nil {
		return false, fmt.Errorf("invalid signer address: %w", err)
	}

	valAddr := sdk.ValAddress(accAddr)

	// Check if the universal validator is in the registered set
	exists, err := k.HasUniversalValidatorInSet(ctx, valAddr)
	if err != nil {
		return false, fmt.Errorf("failed to check universal validator set: %w", err)
	}
	if !exists {
		k.Logger().Debug("validator not found in universal validator set", "validator", universalValidator)
		return false, fmt.Errorf("validator %s not present in the registered universal validators set", valAddr.String())
	}

	// Ensure the universal validator exists in the staking module
	validator, err := k.StakingKeeper.GetValidator(ctx, valAddr)
	if err != nil {
		return false, fmt.Errorf("core validator not found: %w", err)
	}

	// Check that the validator is in bonded status
	if !validator.IsBonded() {
		k.Logger().Debug("universal validator is not bonded", "validator", universalValidator)
		return false, nil // exists but not bonded
	}

	k.Logger().Debug("universal validator is bonded", "validator", universalValidator)
	return true, nil
}
