### Title
Missing sanity-bound (circuit-breaker) checks on the HTTP exchange-rate oracle path used for L1→L2 fee conversion - (File: `crates/apollo_l1_gas_price/src/exchange_rate_oracle.rs`)

### Summary
The sequencer's default ETH→STRK / STRK→USD conversion rate source (`ExchangeRateOracleClient`, `eth_to_strk_oracle_source = "Http"` by default) parses and accepts any non-zero, correctly-decimalled price returned by the configured external HTTP API without checking it against the `rate_bounds_config` sanity bounds that the codebase already defines and enforces for the alternative Chainlink oracle path. This mirrors exactly the reported bug class: an external price feed's out-of-range/anomalous answer being consumed unchecked and propagated into fee/gas-price computation for every block.

### Finding Description
`resolve_query()` in `crates/apollo_l1_gas_price/src/exchange_rate_oracle.rs` (lines 171-219) only validates that the parsed price is non-zero and that `decimals == EXCHANGE_RATE_DECIMALS`: [1](#0-0) 

It never calls `check_rate_bounds`, unlike the Chainlink path, which explicitly guards every feed read with the exact same class of check the external report recommends: [2](#0-1) [3](#0-2) 

The comment in `rate_bounds.rs` even documents that these absolute bounds are "the only defense against a feed wired to the wrong asset or a plausible-but-poisoned answer," but this defense is applied only to the Chainlink client (`ChainlinkOracleClient::query_rate` in `crates/apollo_l1_gas_price/src/chainlink_oracle/mod.rs`), not to `ExchangeRateOracleClientTrait::fetch_rate` for `ExchangeRateOracleClient` (the default, `Http`-sourced) implementation: [4](#0-3) 

The rate produced by this unchecked path is consumed directly by the consensus orchestrator to derive L1 gas prices in FRI and, through `apply_fee_transformations`, is committed into `ConsensusBlockInfo` (`l1_gas_price_fri`, `l1_data_gas_price_fri`) for every proposed block: [5](#0-4) 

There is no downstream re-validation of the rate's magnitude before it is used to compute fees — the only mitigations at that layer are min/max clamps on the wei-denominated L1 gas price itself (`min_l1_gas_price_wei`/`max_l1_gas_price_wei`), not on the ETH↔STRK conversion rate that this oracle supplies, and those clamps operate on wei price, not on the exchange rate that also feeds fee-in-FRI computations elsewhere (e.g., `l2_gas_price`/dynamic gas price logic and STRK/USD rate usage).

### Impact Explanation
If the configured HTTP price API (a genuine external dependency, not an on-chain malicious actor) returns a corrupted, stale-but-differently-shaped, decimal-correct, non-zero price — due to a data provider bug, a compromised/hijacked upstream API, a flash-crash-driven extreme quote, or a misconfiguration — the sequencer will accept it unconditionally on the default `Http` oracle source. This rate feeds:
- the ETH→FRI conversion used to price L1 gas/data-gas for every block, and
- (via `strk_to_usd_oracle_client`) other rate-dependent computations.

An extreme rate can cause gas/fee prices committed into `ConsensusBlockInfo` to become drastically wrong (too high → transactions become unaffordable and the network effectively cannot confirm new transactions; too low → L1 costs are dramatically under-recovered, a funds-loss/mispricing condition for the network's fee economics). This falls squarely in the accepted impact categories: "a network unable to confirm new transactions" and mis-priced/wrong committed block info, reached purely through normal block-building using a configured, non-Chainlink price source — no privileged, malicious-operator, or p2p-based action is required.

### Likelihood Explanation
`Http` is the documented default (`eth_to_strk_oracle_source` and `strk_to_usd_oracle_source` both default to `"Http"` per `crates/apollo_l1_gas_price_config/src/config.rs` and `config_schema.json`), meaning most deployments rely on this unguarded path rather than the bounded Chainlink path. Any anomalous-but-well-formed price from the operator-configured external API (equivalent in spirit to Chainlink's `minAnswer`/`maxAnswer` clamp during a market dislocation) is sufficient to trigger the issue — no attacker action against the sequencer itself is needed, only a misbehaving upstream price source, which is a realistic and recurring operational condition for any price-feed-dependent system.

### Recommendation
Apply the same `check_rate_bounds(rate, bounds)` validation (already implemented in `crates/apollo_l1_gas_price/src/rate_bounds.rs` and used by the Chainlink path) to `resolve_query()`/`fetch_rate()` in `ExchangeRateOracleClient` (`exchange_rate_oracle.rs`), using the corresponding `RateBounds` from `AllRateBoundsConfig` (`eth_strk_bounds()`/`strk_usd_bounds()`) for whichever pair the client instance serves, so that both oracle sources enforce identical sanity bounds before a rate is cached or returned to callers. Additionally, consider implementing the TODO already present in `rate_bounds.rs` (anchoring bounds to the previous block's implied rate) to catch plausible-but-poisoned values that pass the wide absolute bounds.

### Proof of Concept
1. Deploy the sequencer with the default config (`eth_to_strk_oracle_source = "Http"`), pointed at an external price API.
2. That API (due to a bug, compromise, or genuine market flash event) returns a well-formed JSON body such as `{"price": "0x1", "decimals": 18}` — non-zero, correctly decimalled, but many orders of magnitude away from the true rate.
3. `resolve_query()` (`exchange_rate_oracle.rs:171-219`) accepts this value: it is non-zero and has the right `decimals`, so no error is raised and `metrics.record_success(rate)` is called.
4. `ExchangeRateOracleClient::fetch_rate` caches and returns this rate; `L1GasPriceProvider::eth_to_fri_rate` passes it through unmodified (`l1_gas_price_provider.rs:212-217`).
5. `get_l1_prices_in_fri_and_wei_and_conversion_rate` in `apollo_consensus_orchestrator/src/utils.rs` uses this corrupted rate to convert wei gas prices to FRI (`L1PricesInFri::convert_from_wei`), and the resulting (wildly wrong) `l1_gas_price_fri`/`l1_data_gas_price_fri` is embedded into the proposed block's `ConsensusBlockInfo`, affecting fee charging for every transaction in that block — with no bounds check anywhere in the path to reject it, unlike the equivalent Chainlink code path which would have rejected such a value via `check_rate_bounds`.

#[async_trait]
impl ExchangeRateOracleClientTrait for ExchangeRateOracleClient {
    /// The HTTP response must include the following fields:
    /// - `price`: a hexadecimal string representing the price.
    /// - `decimals`: a number equal to `EXCHANGE_RATE_DECIMALS`.
    #[instrument(skip(self))]
    async fn fetch_rate(
        &self,
        timestamp: u64,
    ) -> Result<ExchangeRate, ExchangeRateOracleClientError> {
        const NUMBER_OF_TIMESTAMPS_BACK: u64 = 1;
        let quantized_timestamp = (timestamp - self.config.lag_interval_seconds)
            .checked_div(self.config.lag_interval_seconds)
            .expect("lag_interval_seconds should be non-zero");

        let mut cache = self.cached_prices.lock().unwrap();

        if let Some(rate) = cache.get(&quantized_timestamp) {
            debug!("Cached conversion rate for timestamp {timestamp} is {rate}");
            return Ok(*rate);
        }

        // Check if there is a query already sent out for this timestamp, if not, start one.
        let mut queries = self.queries.lock().unwrap();
        let handle = queries
            .get_or_insert_mut(quantized_timestamp, || self.spawn_query(quantized_timestamp));
        // If the query is not finished, return an error.
        if !handle.is_finished() {
            debug!("Query not yet resolved: timestamp={timestamp}");
            // If the previous quantized timestamp is in the cache, use it.
            if let Some(rate) = cache.get(&(quantized_timestamp - NUMBER_OF_TIMESTAMPS_BACK)) {
                debug!(
                    "Query not yet resolved: timestamp={timestamp}, using previous rate {rate} \
                     from quantized timestamp={}",
                    (quantized_timestamp - NUMBER_OF_TIMESTAMPS_BACK)
                        * self.config.lag_interval_seconds
                );
                return Ok(*rate);
            }
            // If not, return a query not ready error.
            return Err(ExchangeRateOracleClientError::QueryNotReadyError(timestamp));
        }
        let result = handle.now_or_never().expect("Handle must be finished if we got here");
        let rate = match result {
            Ok(Ok(rate)) => rate,
            Ok(Err(e)) => {
                warn!("Query returned an error for timestamp {timestamp}: {e:?}");
                // Must remove failed query from the cache, to avoid re-polling it.
                queries.pop(&quantized_timestamp);
                return Err(e);
            }
            Err(e) => {
                warn!("Query failed to join handle for timestamp {timestamp}: {e:?}");
                self.metrics.record_error(ExchangeRateOracleErrorType::JoinError);
                // Must remove failed query from the cache, to avoid re-polling it.
                queries.pop(&quantized_timestamp);
                return Err(ExchangeRateOracleClientError::JoinError(e.to_string()));
            }
        };

        // Make sure to cache the result.
        cache.put(quantized_timestamp, rate);
        // We don't need to come back to this query since we have the result in cache.
        queries.pop(&quantized_timestamp);
        debug!("Caching conversion rate for timestamp {timestamp}, with rate {rate}");
        Ok(rate)
    }

/// Absolute bounds are the only defense against a feed wired to the wrong asset or a
/// plausible-but-poisoned answer: consensus checks that validators agree with each other, never
/// that the agreed value is sane, and every node reads the same chain state.
pub(crate) fn check_rate_bounds(
    rate: ExchangeRate,
    bounds: RateBounds,
) -> Result<(), ExchangeRateOracleClientError> {
    if rate < bounds.minimum_rate || rate > bounds.maximum_rate {
        return Err(ExchangeRateOracleClientError::RateOutOfBoundsError {
            pair: bounds.pair,
            rate,
            min_rate: bounds.minimum_rate,
            max_rate: bounds.maximum_rate,
        });
    }
    Ok(())
}
