## Analog Found: Rescue-funds outbound accepts an attacker-supplied PRC20 without binding it to the original inbound's locked asset

### Title
Rescue-funds outbound misroutes value by trusting the attacker-selectable `PRC20` from `RescueFundsOnSourceChain` instead of the original stuck asset - (File: `x/uexecutor/keeper/create_outbound.go`)

### Summary
This is the same bug class as the Connext `PortalFacet` report: an obligation denominated in one asset (the original stuck deposit) is allowed to be "settled"/released using caller-selected asset data instead of the asset that was actually debited/locked, because the settlement code never cross-checks token identity against the original transaction record.

### Finding Description
`AttachRescueOutboundFromReceipt` (`x/uexecutor/keeper/create_outbound.go:193-337`) processes a `RescueFundsOnSourceChain` event emitted by `UNIVERSAL_GATEWAY_PC`. The event carries an attacker/user-controlled `PRC20` field [1](#0-0) , decoded straight from the log topics with no cross-reference to the original inbound's asset [2](#0-1) .

The keeper looks up the original stuck `UniversalTx` purely by `universalTxId` and validates only *eligibility* (CEA deposit failed, or the auto-revert outbound reverted) [3](#0-2) . It then resolves the external asset address to attach to the new outbound from `event.PRC20` — the caller-supplied token — rather than from `originalUtx.InboundTx.AssetAddr`, the token that was actually locked on the source chain for that UTX:

```go
tokenCfg, err := k.uregistryKeeper.GetTokenConfigByPRC20(
    ctx,
    originalUtx.InboundTx.SourceChain,
    event.PRC20,
)
...
outbound := &types.OutboundTx{
    ...
    Amount:            originalUtx.InboundTx.Amount,   // original amount, original token's units
    ExternalAssetAddr: tokenCfg.Address,                // resolved from attacker-supplied PRC20
    Prc20AssetAddr:    event.PRC20,                     // attacker-supplied PRC20
    ...
}
``` [4](#0-3) 

`GetTokenConfigByPRC20` only verifies that `event.PRC20` is *some* registered token on the source chain — it does not verify it is the *same* PRC20 mapped to `originalUtx.InboundTx.AssetAddr` [5](#0-4) . Nowhere in `AttachRescueOutboundFromReceipt` is `event.PRC20` compared against the PRC20 that corresponds to `originalUtx.InboundTx.AssetAddr`.

The resulting `OutboundTx` is a `RESCUE_FUNDS`-typed outbound that goes through the normal `PendingOutbounds`/TSS signing flow just like any other outbound [6](#0-5) , meaning it will be signed and broadcast to the source chain to release `originalUtx.InboundTx.Amount` units of whatever token `tokenCfg.Address` maps to — a token identity chosen entirely by whoever called the gateway to emit the rescue event, not necessarily the token that is actually stuck for that `universalTxId`.

### Impact Explanation
If the amount recorded for the original UTX (denominated in units/decimals of the original locked asset, e.g. 1,000,000 = 1 USDC at 6 decimals) is attached to an unrelated token address chosen by the caller (e.g. a token with different decimals or market value), the resulting outbound instructs UVs/TSS to release that raw amount of the wrong asset on the source chain. This is functionally identical to the Connext bug: an obligation for asset A gets discharged using asset B's identity, letting an unprivileged caller misroute or over-extract value from the vault/gateway's asset pool, corrupting token-mapping/accounting invariants and enabling unauthorized release of protocol-controlled funds.

### Likelihood Explanation
The trigger is a normal, permissionless interaction: any user can drive an inbound to a state eligible for rescue (a CEA deposit that fails, or an inbound revert that reverted) and then call the rescue path on the source-chain gateway/vault specifying an arbitrary registered PRC20. No validator, admin, or TSS misbehavior is required — the missing check is purely in the Go keeper's post-processing of an on-chain event it already trusts for `universalTxId` eligibility but not for asset identity.

### Recommendation
In `AttachRescueOutboundFromReceipt`, before building the outbound, resolve the expected PRC20 from `originalUtx.InboundTx.SourceChain` + `originalUtx.InboundTx.AssetAddr` (the same lookup used in `buildRevertOutbound`, `x/uexecutor/keeper/build_revert_outbound.go:27-36`) and require `event.PRC20` to equal that value; reject the rescue event otherwise.

### Proof of Concept
1. Create/observe a CEA inbound for token A (e.g. USDC) whose deposit fails, producing a stuck `UniversalTx` with `Amount = "1000000"`, `AssetAddr = USDC_addr` (see `setupRescueFundsTest` for the exact harness) [7](#0-6) .
2. Craft (or trigger via the gateway contract) a `RescueFundsOnSourceChain` log referencing the same `universalTxId` but with `PRC20` set to a different registered token B's PRC20 address, as done in `buildRescueFundsLog` [8](#0-7) .
3. Call `AttachRescueOutboundFromReceipt` with that receipt; observe the resulting `RESCUE_FUNDS` outbound has `ExternalAssetAddr` mapped to token B while `Amount` remains the original token-A-denominated amount, with no error raised [4](#0-3) .

func DecodeRescueFundsOnSourceChainFromLog(log *evmtypes.Log) (*RescueFundsOnSourceChainEvent, error) {
	if len(log.Topics) < 4 {
		return nil, fmt.Errorf("RescueFundsOnSourceChain: need 4 topics, got %d", len(log.Topics))
	}
	if strings.ToLower(log.Topics[0]) != strings.ToLower(RescueFundsOnSourceChainEventSig) {
		return nil, fmt.Errorf("not a RescueFundsOnSourceChain event")
	}

	event := &RescueFundsOnSourceChainEvent{
		UniversalTxId: log.Topics[1], // bytes32 as 0x-prefixed hex
		PRC20:         common.HexToAddress(log.Topics[2]).Hex(),
		Sender:        common.HexToAddress(log.Topics[3]).Hex(),
	}

// TestGetTokenConfigByPRC20_LookupViaIndex covers the happy path: the
// IndexedMap auto-populates PRC20Index on every Set, so lookup returns the
// matching config in O(1) without scanning all of TokenConfigs.
func TestGetTokenConfigByPRC20_LookupViaIndex(t *testing.T) {
	ctx, k, _ := setupPRC20Keeper(t)

	cfgA := makeTokenCfg(tcChainA, "0xUSDC_eth", "0xPRC20_aaa")
	cfgB := makeTokenCfg(tcChainB, "0xUSDC_polygon", "0xPRC20_bbb")
	cfgC := makeTokenCfg(tcChainC, "USDCsvm", "0xPRC20_ccc")
	for _, cfg := range []types.TokenConfig{cfgA, cfgB, cfgC} {
		require.NoError(t, k.TokenConfigs.Set(ctx, types.GetTokenConfigsStorageKey(cfg.Chain, cfg.Address), cfg))
	}

	got, err := k.GetTokenConfigByPRC20(ctx, tcChainA, "0xPRC20_aaa")
	require.NoError(t, err)
	require.Equal(t, cfgA.Address, got.Address)

	got, err = k.GetTokenConfigByPRC20(ctx, tcChainB, "0xPRC20_bbb")
	require.NoError(t, err)
	require.Equal(t, cfgB.Address, got.Address)

	got, err = k.GetTokenConfigByPRC20(ctx, tcChainC, "0xPRC20_ccc")
	require.NoError(t, err)
	require.Equal(t, cfgC.Address, got.Address)
}

func buildRescueFundsLog(
	t *testing.T,
	utxId string, // UTX key (64-char hex, no 0x prefix)
	prc20Addr common.Address,
	senderAddr common.Address,
	chainNamespace string,
	gasFee, gasPrice, gasLimit *big.Int,
) *evmtypes.Log {
	t.Helper()

	stringType, _ := abi.NewType("string", "", nil)
	uint8Type, _ := abi.NewType("uint8", "", nil)
	uint256Type, _ := abi.NewType("uint256", "", nil)

	args := abi.Arguments{
		{Type: stringType},  // chainNamespace
		{Type: uint8Type},   // txType (RESCUE_FUNDS = 4)
		{Type: uint256Type}, // gasFee
		{Type: uint256Type}, // gasPrice
		{Type: uint256Type}, // gasLimit
	}
	data, err := args.Pack(chainNamespace, uint8(4), gasFee, gasPrice, gasLimit)
	require.NoError(t, err)

	// UTX ID is stored as a bytes32 topic: "0x" + the 64-char hex UTX key.
	utxIdTopic := "0x" + utxId

	gwPCAddr := utils.GetDefaultAddresses().UniversalGatewayPCAddr

	return &evmtypes.Log{
		Address: gwPCAddr.Hex(),
		Topics: []string{
			uexecutortypes.RescueFundsOnSourceChainEventSig,
			utxIdTopic,
			common.BytesToHash(prc20Addr.Bytes()).Hex(),  // indexed prc20
			common.BytesToHash(senderAddr.Bytes()).Hex(), // indexed sender
		},
		Data:    data,
		Removed: false,
	}
}

// setupRescueFundsTest creates a CEA inbound whose deposit will fail (asset address has
// no registered token config), drives it to quorum, and returns the UTX key of the failed UTX.
// The returned UTX has at least one FAILED PCTx and is ready for a rescue outbound.
func setupRescueFundsTest(
	t *testing.T,
	numVals int,
) (
	*app.ChainApp,
	sdk.Context,
	[]string, // universalVals
	string, // utxId of the failed CEA UTX
	[]stakingtypes.Validator,
) {
	t.Helper()

	// Reuse the CEA environment (validators, chain/token config, authz for inbound voting).
	chainApp, ctx, vals, _, coreVals, _ := setupInboundCEAPayloadTest(t, numVals)

	testAddress := utils.GetDefaultAddresses().DefaultTestAddr
	recipient := utils.GetDefaultAddresses().TargetAddr2
	// Use an asset address that has no registered token config — depositPRC20 will fail.
	unregisteredAsset := common.HexToAddress("0x000000000000000000000000000000000000DEAD")

	inbound := &uexecutortypes.Inbound{
		SourceChain: "eip155:11155111",
		TxHash:      "0xrescue01",
		Sender:      testAddress,
		Recipient:   recipient,
		Amount:      "1000000",
		AssetAddr:   unregisteredAsset.String(),
		LogIndex:    "1",
		TxType:      uexecutortypes.TxType_FUNDS_AND_PAYLOAD,
		UniversalPayload: &uexecutortypes.UniversalPayload{
			To:                   recipient,
			Value:                "1000000",
			Data:                 "0x",
			GasLimit:             "21000000",
			MaxFeePerGas:         "1000000000",
			MaxPriorityFeePerGas: "200000000",
			Nonce:                "1",
			Deadline:             "9999999999",
			VType:                uexecutortypes.VerificationType(1),
		},
		IsCEA: true,
		RevertInstructions: &uexecutortypes.RevertInstructions{
			FundRecipient: testAddress,
		},
	}

	for i := 0; i < 3; i++ {
		valAddr, err := sdk.ValAddressFromBech32(coreVals[i].OperatorAddress)
		require.NoError(t, err)
		coreValAcc := sdk.AccAddress(valAddr).String()
		err = utils.ExecVoteInbound(t, ctx, chainApp, vals[i], coreValAcc, inbound)
		require.NoError(t, err)
	}

	utxId := uexecutortypes.GetInboundUniversalTxKey(*inbound)
	utx, found, err := chainApp.UexecutorKeeper.GetUniversalTx(ctx, utxId)
	require.NoError(t, err)
	require.True(t, found, "UTX must exist after quorum")

	require.NotEmpty(t, utx.PcTx, "setup: at least one PCTx must exist")
	require.Equal(t, "FAILED", utx.PcTx[0].Status, "setup: deposit must fail for unregistered asset")

	return chainApp, ctx, vals, utxId, coreVals
}
