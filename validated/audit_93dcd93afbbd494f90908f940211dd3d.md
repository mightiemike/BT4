## Finding

### Title
Spot-price sandwich manipulation of the auto-swap quote defeats the 5% slippage guard, letting an attacker extract value from module-initiated PRC20→PC swaps - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The 1inch bug allowed a maker-controlled "getter" callback to return an inflated amount that got silently substituted into the fill computation, defeating the taker's `threshold` check and letting the maker take more of the taker's funds than intended. Push Chain's analog is the `GetSwapQuote` → `minPCOut` slippage-guard pattern used for every module-initiated PRC20→PC auto-swap (`GAS`, `GAS_AND_PAYLOAD`, and gas-refund flows). Instead of a maker-supplied callback, the "amount authority" here is the spot price of an on-chain Uniswap V3 pool, read via a single un-TWAP'd `quoteExactInputSingle` call and then bounded only by a flat, attacker-predictable 5% band. Because the quote and the swap execute in the same externally-observable/attacker-triggerable window, an unprivileged actor can manipulate the pool price immediately around the module's swap (a standard sandwich), forcing the swap to clear at a manipulated rate while the 5% guard — the chain's analog of 1inch's `thresholdAmount` check — does nothing to stop it, since the guard is computed *from* the very price the attacker just moved.

### Finding Description
`GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) performs a static, single-block call to the Uniswap V3 `QuoterV2.quoteExactInputSingle`: [1](#0-0) 

Every module-driven auto-swap path (`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, `applyGasRefund`/`getSwapQuoteForRefund`) then derives `minPCOut` purely from that just-fetched spot quote with a fixed 5% haircut and immediately submits the swap in the same keeper call: [2](#0-1) [3](#0-2) [4](#0-3) 

This mirrors the 1inch flaw structurally: a value that is supposed to represent "what the counterparty considers a fair/expected amount" is fetched from a source the attacker can influence, and then used both to compute the executed amount *and* to validate that execution — so the check can never fail no matter how adversarial the input is, exactly like 1inch's `actualMakingAmount * takingAmount < thresholdAmount * actualTakingAmount` check passing because both sides of the inequality were derived from the same manipulated getter output. Here, `minPCOut` is derived from the same spot price the attacker just moved, so a classic sandwich (push price down right before the module's swap, let the module's `depositPRC20WithAutoSwap` clear at the manipulated rate, then push the price back and capture the spread) passes the "slippage" check by construction, because the check's reference point is the manipulated price itself, not an independent/TWAP'd fair value.

Any unprivileged actor with capital can execute this: no relayer, validator, or admin privilege is required to move the price of the pool immediately around a `MsgVoteInbound`-triggered auto-swap (or the equivalent refund path in `applyGasRefund`), since inbound execution deterministically fires within the same block once quorum is reached, and the target pool address (`UniversalCore`'s configured Uniswap V3 quoter/pool) and fee tier are public on-chain values (`GetUniversalCoreQuoterAddress`, `GetDefaultFeeTierForToken`).

### Impact Explanation
This falls under "corruption of PRC20 or native asset accounting" and "draining... of user or protocol-controlled funds" in the allowed-impact gate: the module-initiated swap moves real PRC20/PC value (deposited user funds being converted to gas top-up, or gas-refund proceeds) through a pool whose price the attacker just manipulated, letting the attacker's sandwich extract value that should have accrued to the depositing user / protocol liquidity, while the module's own "safety" check (`minPCOut`) is powerless to detect it because it's built from the manipulated price.

### Likelihood Explanation
High for any chain with meaningful trading volume/available capital: sandwich attacks against un-TWAP'd spot quoters are a well-understood, mechanically simple DeFi pattern, and here the trigger condition (an inbound/outbound event reaching quorum, or the gas-refund path firing) is either attacker-controlled directly (the attacker submits their own inbound) or externally observable in the mempool before the finalizing vote lands.

### Recommendation
Do not derive the slippage bound from a spot quote fetched immediately before execution. Use a TWAP-based quote (or a price bound configured/attested by governance/oracle with staleness and deviation checks), and/or let the depositing user supply their own `minPCOut`/max-slippage tolerance up front (analogous to 1inch's taker-supplied `threshold`) rather than having the protocol compute both the executed amount and its own check from the same single-block price sample.

### Proof of Concept
1. Attacker identifies the `UniversalCore` Uniswap V3 pool address and fee tier used for a target PRC20 (`GetUniversalCoreQuoterAddress` / `GetDefaultFeeTierForToken`, both public on-chain reads).
2. Attacker submits a source-chain deposit (or waits for one of their own inbounds) that will trigger `ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap` on Push Chain.
3. Immediately before the finalizing `MsgVoteInbound` (the last vote that reaches quorum and triggers execution) lands, attacker submits a large swap against the same pool to move the spot price.
4. `GetSwapQuote` returns the manipulated price; `minPCOut = quote * 95/100` is computed from it; `CallPRC20DepositAutoSwap`/`refundUnusedGas` executes at the manipulated rate and passes the check trivially.
5. Attacker reverses their price-moving trade, capturing the spread extracted from the module's swap — all without any validator, relayer, or admin cooperation.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
