## Finding

### Title
`ensure_match_transaction_info` never validates `state_checkpoint_hash`, letting replay-verify tooling accept a divergent state root - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the sole correctness check used by replay/verify tooling (`storage/db-tool/src/replay_on_archive.rs`, `aptos-move/aptos-debugger/src/aptos_debugger.rs`, `aptos-move/cli/src/commands.rs`) to confirm that a locally re-executed transaction matches the authenticated `TransactionInfo` recorded in the transaction accumulator. It checks status, gas used, write-set hash, and event root hash, but it never checks `txn_info.state_checkpoint_hash()` (nor `hot_state_checkpoint_hash` / `position_state_checkpoint_hash` on `TransactionInfoV1`). A divergence in the post-execution state root — the very value the state-checkpoint hash is meant to authenticate — is silently ignored by this comparator.

### Finding Description
`ensure_match_transaction_info` at [1](#0-0)  compares four fields between the locally produced `TransactionOutput` and the archived `TransactionInfo`: status, gas_used, write_set hash (`state_change_hash`), and event root hash. It never reads or asserts on `txn_info.state_checkpoint_hash()`. The function even carries a TODO acknowledging that the newer trading-native checkpoint fields (`hot_state_checkpoint_hash`, `position_state_checkpoint_hash`) are skipped: [2](#0-1)  — but the comment is silent on the fact that the base `state_checkpoint_hash` field, present since `TransactionInfoV0`, is likewise never checked here at all.

This function is the terminal verification step of `storage/db-tool/src/replay_on_archive.rs`'s `execute_and_verify`, which re-executes archived transactions with `AptosVMBlockExecutor` and calls `ensure_match_transaction_info` against the expected `TransactionInfo` pulled from backup: [3](#0-2) . No other check in this path independently validates that the locally computed state-checkpoint (Jellyfish Merkle / sparse-merkle) root for the version matches the archived, ledger-committed `state_checkpoint_hash`.

### Impact Explanation
`state_checkpoint_hash` is the field in `TransactionInfo` that binds a version to its post-execution global state root, and `TransactionInfo` itself is the leaf hashed into the transaction accumulator that ledger infos commit to. Because the replay/verify comparator never checks it, a chunk of transactions can be replayed with correct write-set bytes, events, gas, and status, yet with a state-checkpoint root that has silently diverged from the authenticated chain history (e.g., due to a bug in state-checkpoint/state-summary computation, hot-state handling, or JMH restore logic elsewhere in the stack), and `replay_on_archive`/`aptos-debugger`/CLI replay commands would report success. This masks hard-fork-class state divergence exactly in the tooling whose job is to catch it, which falls squarely in the "authenticated response bound to wrong root" / "replay/restore divergence" impact category.

### Likelihood Explanation
This is not itself a trigger for state corruption — normal block execution's own commit path (`do_state_checkpoint.rs`, `do_ledger_update.rs`) independently computes and commits `state_checkpoint_hash` correctly, as seen in [4](#0-3)  and the checkpoint-hash reconciliation logic in [5](#0-4) . The gap is specifically in the offline replay/verification tooling's blind spot: it is not itself a live consensus/commit bug, but it removes a safety net that operators and auditors rely on to detect state-root divergence during replay-verify or forensic re-execution. Likelihood of the underlying divergence being introduced (e.g., a future regression in checkpoint computation, hot-state, or restore code) is speculative, but the missing check is a concrete, unconditional code defect independent of any feature flag.

### Recommendation
Extend `ensure_match_transaction_info` to compute the state-checkpoint hash for the replayed output (when available/applicable) and assert it equals `txn_info.state_checkpoint_hash()`, and similarly validate `hot_state_checkpoint_hash`/`position_state_checkpoint_hash` for `TransactionInfoV1` once the trading-native state roots are computed, per the existing TODO. Do not treat replay as verified until all checkpoint-hash fields of the archived `TransactionInfo` are checked against the locally recomputed roots.

### Proof of Concept
Not independently exploitable via a standalone PoC without a companion bug that causes state_checkpoint_hash to actually diverge (e.g. a bug in checkpoint/hot-state computation). Conceptually: run `replay_on_archive` (or `aptos-debugger`/CLI replay) over a version range where the locally executed write set, events, gas, and status match the archive but the recomputed state-checkpoint root differs (e.g., due to a hot-state or JMT restore bug) — `execute_and_verify` at [6](#0-5)  will report no error, since `ensure_match_transaction_info` never inspects `state_checkpoint_hash`.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn get_state_checkpoint_hashes(
        execution_output: &ExecutionOutput,
        known_state_checkpoints: Option<Vec<Option<HashValue>>>,
        computed_last_checkpoint_hash: HashValue,
        label: &str,
    ) -> Result<Vec<Option<HashValue>>> {
        let _timer = OTHER_TIMERS.timer_with(&[&format!("get_{label}_checkpoint_hashes")]);

        let num_txns = execution_output.to_commit.len();
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();

        if let Some(known) = known_state_checkpoints {
            ensure!(
                known.len() == num_txns,
                "Bad number of known {label} hashes. {} vs {}",
                known.len(),
                num_txns,
            );
            if let Some(idx) = last_checkpoint_index {
                ensure!(
                    known[idx] == Some(computed_last_checkpoint_hash),
                    "{label} root hash mismatch with known hashes passed in. {:?} vs {:?}",
                    known[idx],
                    Some(computed_last_checkpoint_hash),
                );
            }
            Ok(known)
        } else {
            if !execution_output.is_block {
                // We should enter this branch only in test.
                execution_output.to_commit.ensure_at_most_one_checkpoint()?;
            }

            let mut out = vec![None; num_txns];
            if let Some(index) = last_checkpoint_index {
                out[index] = Some(computed_last_checkpoint_hash);
            }
            Ok(out)
        }
    }
