### Title
Self-destructing a contract via TVM `SUICIDE`/`SUICIDE2` unconditionally deletes the account even when its TRC10 asset balances and voting rewards were not transferred out - ([File: actuator/src/main/java/org/tron/core/vm/program/Program.java])

### Summary
`Program.suicide()` and `Program.suicide2()` mark the self-destructing contract's account for deletion **unconditionally**, but the steps that move the account's remaining value (TRC10 token balances, unclaimed voting reward/allowance) to the inheritor/blackhole are each gated behind separate feature flags (`VMConfig.allowTvmTransferTrc10()`, `VMConfig.allowTvmVote()`). If any of these flags are not active, the corresponding value is left in the doomed account and is destroyed together with it when the account row is later removed from `AccountStore` — the same "burn-while-still-holding-collateral" defect described in the external report (burn triggered by one condition, `shortAmount==0`, without checking the other, `collateralAmount==0`).

### Finding Description
`Program.suicide()` performs cleanup in this order: [1](#0-0) 

1. If `owner == obtainer`, TRX balance is zeroed and, only `if (VMConfig.allowTvmTransferTrc10())`, TRX and all TRC10 token balances are moved to the blackhole address.
2. If `owner != obtainer`, `MUtil.transfer` moves TRX, and only `if (VMConfig.allowTvmTransferTrc10())` does `MUtil.transferAllToken` move the TRC10 balances to the obtainer.
3. Voting rewards/allowance are only reconciled via `withdrawRewardAndCancelVote(owner, ...)` when `VMConfig.allowTvmVote()` is true: [2](#0-1) [3](#0-2) 
4. Regardless of whether steps 1–3 ran, the method finishes with an unconditional `getResult().addDeleteAccount(this.getContractAddress())`: [4](#0-3) 

Because `AccountCapsule` stores TRC10 asset balances (`assetV2` map) and pending vote/allowance data inline on the account record, once the account is deleted from `AccountStore` any balance that was not moved out in the gated steps above is permanently lost — there is no check equivalent to "don't delete unless the remaining collateral/asset balance is zero," exactly mirroring the `ShortToken.adjustPosition()` defect where `position.shortAmount == 0` triggers `_burn(positionId)` without verifying `position.collateralAmount == 0`.

`suicide2()` has the analogous structure — TRC10/vote transfer are each individually flag-gated, but neither gate protects the underlying account state from being effectively orphaned of un-transferred value when the corresponding feature is not active on the network on which the contract is executing.

### Impact Explanation
Any account (attacker-controlled or victim) that self-destructs while still holding TRC10 token balances or an unclaimed voting reward, on a network/point-in-time where `allowTvmTransferTrc10` or `allowTvmVote` is not yet active (e.g., private chains, consortium chains, or a mainnet prior to the corresponding proposal being approved), permanently loses that value: the value is neither transferred to the inheritor nor retained by the deleted account, since the account row (and its embedded asset/vote/allowance fields) is removed from `AccountStore`. This is an unauthorized, irrecoverable loss of user assets triggered purely by a TVM opcode invocation.

### Likelihood Explanation
The path is reachable by any user who deploys a contract containing a `SELFDESTRUCT`/`SUICIDE` opcode and calls it via an ordinary broadcast transaction — no privileged role is required. The condition depends on the on-chain state of two independent, per-network governance flags (`ALLOW_TVM_TRANSFER_TRC10`, `ALLOW_TVM_VOTE`); on the current TRON mainnet these have long been enabled, but the code contains no defensive check tying account deletion to the absence of remaining transferable value, so the same unconditional-delete pattern reproduces the reported bug class on any deployment where these flags are not (yet) active.

### Recommendation
Make account deletion in `suicide()`/`suicide2()` conditional on all value having actually been relocated: verify (or force) that TRC10 asset balances and any unresolved vote/allowance state are empty/zero before calling `getResult().addDeleteAccount(...)`, or make the TRC10/vote transfer steps unconditional (not feature-flag gated) whenever the account is about to be deleted, so that self-destructing an account can never leave value stranded in a subsequently deleted account record.

### Proof of Concept
1. On a network/instance where `ALLOW_TVM_TRANSFER_TRC10` (and/or `ALLOW_TVM_VOTE`) is not activated, mint/acquire a TRC10 token balance to a contract account, or leave an unclaimed voting reward/allowance associated with it.
2. Broadcast a transaction that triggers the contract's `SUICIDE`/`SUICIDE2` opcode to any obtainer address.
3. Observe: `Program.suicide()` moves the TRX balance but skips the TRC10/vote transfer branches (flags disabled), then unconditionally calls `getResult().addDeleteAccount(this.getContractAddress())`.
4. After the block commits, query the account: `AccountStore.get(contractAddress)` returns `null` (deleted), while the previously held TRC10 balance/voting reward is nowhere credited to the obtainer or blackhole — permanently lost.

  public void suicide(DataWord obtainerAddress) {

    byte[] owner = getContextAddress();
    byte[] obtainer = obtainerAddress.toTronAddress();

    if (VMConfig.allowTvmVote()) {
      withdrawRewardAndCancelVote(owner, getContractState());
    }

    long balance = getContractState().getBalance(owner);

    if (logger.isDebugEnabled()) {
      logger.debug("Transfer to: [{}] heritage: [{}]",
          Hex.toHexString(obtainer),
          balance);
    }

    increaseNonce();

    InternalTransaction internalTx = addInternalTx(null, owner, obtainer, balance, null,
        "suicide", nonce, getContractState().getAccount(owner).getAssetMapV2());

    int ADDRESS_SIZE = VMUtils.getAddressSize();
    if (FastByteComparisons.compareTo(owner, 0, ADDRESS_SIZE, obtainer, 0, ADDRESS_SIZE) == 0) {
      // if owner == obtainer just zeroing account according to Yellow Paper
      getContractState().addBalance(owner, -balance);
      byte[] blackHoleAddress = getContractState().getBlackHoleAddress();
      if (VMConfig.allowTvmTransferTrc10()) {
        getContractState().addBalance(blackHoleAddress, balance);
        MUtil.transferAllToken(getContractState(), owner, blackHoleAddress);
      }
    } else {
      createAccountIfNotExist(getContractState(), obtainer);
      try {
        MUtil.transfer(getContractState(), owner, obtainer, balance);
        if (VMConfig.allowTvmTransferTrc10()) {
          MUtil.transferAllToken(getContractState(), owner, obtainer);
        }
      } catch (ContractValidateException e) {
        if (VMConfig.allowTvmConstantinople()) {
          throw new TransferException(
              "transfer all token or transfer all trx failed in suicide: %s", e.getMessage());
        }
        throw new BytecodeExecutionException("transfer failure");
      }
    }
    if (VMConfig.allowTvmFreeze()) {
      byte[] blackHoleAddress = getContractState().getBlackHoleAddress();
      if (FastByteComparisons.isEqual(owner, obtainer)) {
        transferDelegatedResourceToInheritor(owner, blackHoleAddress, getContractState());
      } else {
        transferDelegatedResourceToInheritor(owner, obtainer, getContractState());
      }
    }
    if (VMConfig.allowTvmFreezeV2()) {
      byte[] Inheritor =
          FastByteComparisons.isEqual(owner, obtainer)
              ? getContractState().getBlackHoleAddress()
              : obtainer;
      long expireUnfrozenBalance = transferFrozenV2BalanceToInheritor(owner, Inheritor, getContractState());
      if (expireUnfrozenBalance > 0 && internalTx != null) {
        internalTx.setValue(internalTx.getValue() + expireUnfrozenBalance);
      }
    }
    getResult().addDeleteAccount(this.getContractAddress());
  }

  private void withdrawRewardAndCancelVote(byte[] owner, Repository repo) {
    VoteRewardUtil.withdrawReward(owner, repo);

    AccountCapsule ownerCapsule = repo.getAccount(owner);
    if (!ownerCapsule.getVotesList().isEmpty()) {
      VotesCapsule votesCapsule = repo.getVotes(owner);
      if (votesCapsule == null) {
        votesCapsule = new VotesCapsule(ByteString.copyFrom(owner),
            ownerCapsule.getVotesList());
      } else {
        votesCapsule.clearNewVotes();
      }
      ownerCapsule.clearVotes();
      ownerCapsule.setOldTronPower(0);
      repo.updateVotes(owner, votesCapsule);
    }
    try {
      long balance = ownerCapsule.getBalance();
      long allowance = ownerCapsule.getAllowance();
      ownerCapsule.setInstance(ownerCapsule.getInstance().toBuilder()
          .setBalance(addExact(balance, allowance, VMConfig.disableJavaLangMath()))
          .setAllowance(0)
          .setLatestWithdrawTime(getTimestamp().longValue() * 1000)
          .build());
      repo.updateAccount(ownerCapsule.createDbKey(), ownerCapsule);

      throw new BytecodeExecutionException("Suicide: balance and allowance out of long range.");
