### Title
Unauthenticated "BOOTSTRAP" declare path allows any transaction sender to bypass account validation and fee enforcement — ([File: crates/starknet_api/src/executable_transaction.rs])

### Summary
The Starknet OS and blockifier contain a special-cased declare-transaction path, gated only by `sender_address == BOOTSTRAP_ADDRESS`, `nonce == 0`, and `charge_fee == false` / `max_possible_fee == 0` — all of which are attacker-controllable fields in a normal, permissionlessly-submitted `Declare` V3 transaction. There is no cryptographic or configuration-level access control tying this magic sender address to a trusted deployer/genesis process, so any unprivileged transaction sender can invoke this "no validation, no fee" declare flow at any point in the chain's life, not just at genesis.

### Finding Description
`DeclareTransaction::bootstrap_address()` returns a fixed, publicly-known `ContractAddress` derived from the ASCII string "BOOTSTRAP": [1](#0-0) 

`is_bootstrap_declare` treats any V3 declare transaction as a privileged bootstrap transaction purely based on attacker-suppliable fields (`sender_address`, `nonce`, and whether fee is charged): [2](#0-1) 

In the blockifier's transaction execution, if this condition is met, `__validate_declare__` is entirely skipped (no signature/account authentication is performed) and fee handling is skipped as well — the code jumps straight to `run_execute`: [3](#0-2) 

The Starknet OS Cairo implementation mirrors this: it checks `sender_address == 'BOOTSTRAP' and tx_info.nonce == 0 and tx_info.version == 3` and, if `max_possible_fee == 0` (attacker sets resource bounds to zero), commits the class hash directly via `dict_update`, skipping `__validate_declare__` and nonce increment entirely: [4](#0-3) 

At the gateway layer, the only declare-time authorization check is `is_authorized_declarer`, which — by default configuration (`authorized_declarer_accounts: None`) — allows **every** address, including the BOOTSTRAP address, to declare: [5](#0-4) [6](#0-5) 

No other check in the reviewed code (gateway, stateless/stateful validator, mempool) restricts the BOOTSTRAP sender address to a genesis-only, trusted-caller context. The comments in the code describe the mechanism as intended "to bootstrap a new system" and acknowledge unusual mempool-retention behavior, but this is a documentation/comment-level assumption, not an enforced access-control boundary — analogous to `diamondCut` lacking an owner check: a highly privileged state-mutating operation (declaring a class with zero fee and no signature verification) is reachable by any unprivileged caller who simply crafts a transaction with the known constant sender address.

### Impact Explanation
Any external, unprivileged account can submit a `Declare` V3 transaction with `sender_address = BOOTSTRAP_ADDRESS`, `nonce = 0`, and zero resource bounds. This transaction:
- Bypasses `__validate_declare__` signature/account verification entirely (no private key or account deployment needed for this address).
- Bypasses fee charging, letting the attacker force the sequencer/committer to perform Sierra→CASM compilation, class-hash verification, and state-diff writes for free.
- Because such a transaction has no fee and does not increment a nonce, it does not naturally exit the mempool the way normal transactions do; per the code's own inline documentation, a successful bootstrap declare is not reported to the mempool as included, so the mempool will re-propose it every block until it eventually fails (because the class is already declared) — creating a mechanism for repeated free compute consumption and resource-accounting bypass across blocks.
- This effectively provides an unauthorized, fee-free class declaration primitive available to any network participant post-genesis, undermining the fee market and validate-before-execute security invariant that every other declare path enforces.

This matches the required impact bar: unauthorized account action (declaring classes without authentication or payment) and resource-accounting bypass reachable from a single unprivileged submitted transaction.

### Likelihood Explanation
High. The BOOTSTRAP address is a fixed, publicly computable constant (`0x424f4f545354524150`), requiring no secret. All gating conditions (`sender_address`, `nonce == 0`, zero resource bounds) are directly attacker-controlled fields of a standard V3 declare transaction, and by default `authorized_declarer_accounts` is unset, so the gateway does not restrict who may use this address. No additional runtime check preventing reuse of this path after genesis was found in the gateway, stateless/stateful validators, or mempool logic examined.

### Recommendation
Restrict the bootstrap-declare code path so it can only execute a single time (e.g., only in the genesis block / block number 0), or require an explicit, cryptographically-verifiable authorization (e.g., signature check or restriction via `authorized_declarer_accounts` defaulting to reject the BOOTSTRAP address) before allowing a declare transaction from `BOOTSTRAP_ADDRESS` to skip validation and fee charging. Additionally, ensure the gateway explicitly rejects transactions using this synthetic sender address outside of genesis initialization, rather than relying on informal nonce/fee-based heuristics that are fully attacker-controllable.

### Proof of Concept
1. Attacker crafts a `DeclareTransaction::V3` with:
   - `sender_address = DeclareTransaction::bootstrap_address()` (`0x424f4f545354524150`)
   - `nonce = Nonce(Felt::ZERO)`
   - `resource_bounds` set so that `max_possible_fee == 0` (e.g., zero L1/L2/L1-data gas bounds), matching the pattern used in `generate_bootstrap_declare` / `create_cairo1_bootstrap_declare_tx` test helpers: [7](#0-6) 
2. Submits it via the gateway like any ordinary declare transaction (default config has no `authorized_declarer_accounts` restriction): [5](#0-4) 
3. In execution, `is_bootstrap_declare` evaluates true, so `__validate_declare__`/signature checks and fee charging are skipped, and the class is declared directly: [8](#0-7) 
4. The transaction succeeds without any signature, account deployment, or payment, and (per the code's own comments) is not properly removed from the mempool, causing it to be repeatedly reproposed in subsequent blocks until it errors out for redeclaring the same class hash.

/// Create a declare tx from the funded account. Optionally creates the tx as a bootstrap-declare.
pub(crate) fn create_declare_tx(
    feature_contract: FeatureContract,
    nonce_manager: &mut NonceManager,
    execution_contracts: &mut OsExecutionContracts,
    bootstrap: bool,
) -> AccountTransaction {
    let sender_address =
        if bootstrap { DeclareTransaction::bootstrap_address() } else { *FUNDED_ACCOUNT_ADDRESS };
    let nonce = if bootstrap { Nonce::default() } else { nonce_manager.next(sender_address) };
    let declare_args = match feature_contract.get_class() {
        ContractClass::V0(class) => {
            let class_hash = ClassHash(compute_deprecated_class_hash(&class).unwrap());
            execution_contracts.add_deprecated_contract(class_hash, class);
            declare_tx_args! {
                version: TransactionVersion::ONE,
                max_fee: if bootstrap { Fee::default() } else { Fee(1_000_000_000_000_000) },
                class_hash,
                sender_address,
                nonce,
            }
        }
        ContractClass::V1((casm, _sierra_version)) => {
            let sierra = feature_contract.get_sierra();
            let class_hash = sierra.calculate_class_hash();
            let compiled_class_hash = feature_contract.get_compiled_class_hash(&HashVersion::V2);
            execution_contracts.add_cairo1_contract(casm, &sierra);
            declare_tx_args! {
                sender_address,
                class_hash,
                compiled_class_hash,
                resource_bounds: if bootstrap {
                    ValidResourceBounds::create_for_testing_no_fee_enforcement()
                } else {
                    *NON_TRIVIAL_RESOURCE_BOUNDS
                },
                nonce,
            }
        }
    };
    let account_declare_tx = declare_tx(declare_args);
