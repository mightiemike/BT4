### Title
Failed/timed-out HTTP trigger requests permanently leak callback state, permanently blocking retries with the same request ID - ([File: core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go])

### Summary
`httpTriggerHandler.HandleUserTriggerRequest` registers a pending request in `h.callbacks` via `setupCallback` before broadcasting to DON members, but it never removes that entry when the broadcast ultimately fails (all retries exhausted / `MaxTriggerRequestDurationMs` reached). This is structurally the same bug class as the Fractional `Buyout.end()` finding: state written before an external/asynchronous operation is not cleaned up when that operation fails, permanently blocking any future action tied to the same identifier.

### Finding Description
`setupCallback` inserts a `savedCallback` into the `h.callbacks` map keyed by `req.ID` and rejects any subsequent request that reuses the same ID while an entry is still present: [1](#0-0) 

The only code path that removes an entry from `h.callbacks` is `cleanupCallback`, which is invoked from `HandleNodeTriggerResponse` **after a successful quorum response is aggregated and sent back to the user**: [2](#0-1) 

`HandleUserTriggerRequest` calls `setupCallback` and then hands off to `sendWithRetries`, returning whatever error `sendWithRetries` produces without ever calling `cleanupCallback`: [3](#0-2) 

`sendWithRetries` retries broadcasting to DON members until either all succeed, the callback is externally resolved (`doneCh`), or the overall `ctxWithTimeout` (bounded by `MaxTriggerRequestDurationMs`) expires — in the timeout case it simply returns an error: [4](#0-3) 

Because neither `sendWithRetries`'s error path nor `HandleUserTriggerRequest`'s propagation of that error calls `cleanupCallback`, the `h.callbacks[req.ID]` entry is never deleted and `doneCh` is never closed. Any later request reusing the same `req.ID` is rejected with `jsonrpc.ErrConflict` ("in-flight request ID") forever (until process restart), even though the original request has definitively failed and no response will ever arrive for it.

### Impact Explanation
This mirrors the reported bug class: a state entry created to track an in-progress action is never released on failure, permanently denying any new action that shares the same key. Here, once nodes are slow/unreachable long enough to exceed `MaxTriggerRequestDurationMs` (a condition reachable simply by transient DON connectivity issues, not requiring a malicious contract), the associated `requestID` is permanently unusable for that gateway instance's lifetime — a persistent denial of service for workflow executions keyed by that ID, and a memory leak of stale callback/aggregator state that accumulates over time.

### Likelihood Explanation
Any user-triggered HTTP workflow request that experiences a full-duration send failure (e.g., DON members unreachable, node send timeouts, or an attacker deliberately reusing a request ID that they know is currently pending/failing) will trigger this leak. No special privilege is required — this is reachable from the standard unauthenticated/low-privilege HTTP trigger ingestion path (`HandleJSONRPCUserMessage` → `HandleUserTriggerRequest`).

### Recommendation
Ensure `cleanupCallback(req.ID)` (or equivalent removal from `h.callbacks` and closing of `doneCh`) is called on every exit path of `HandleUserTriggerRequest` after `setupCallback` succeeds, including when `sendWithRetries` returns an error. Consider wrapping the post-`setupCallback` logic in a `defer` that removes the entry unless it was already cleaned up by a successful `HandleNodeTriggerResponse`, and returning a well-defined error to the caller that permits retry with the same or a new request ID.

### Proof of Concept
1. Client sends `MethodWorkflowExecute` with `id = "req-1"`.
2. `setupCallback` inserts `h.callbacks["req-1"]`.
3. All DON members become unreachable/slow such that `sendWithRetries` never reaches quorum before `ctxWithTimeout` (bounded by `MaxTriggerRequestDurationMs`) expires — see `core/services/gateway/handlers/capabilities/v2/http_trigger_handler.go:669-671`.
4. `HandleUserTriggerRequest` returns the timeout error without cleaning up `h.callbacks["req-1"]`.
5. Client retries with `id = "req-1"` — `setupCallback` rejects it permanently with `jsonrpc.ErrConflict`, even though nodes have since recovered and no earlier response will ever complete this ID.

func (h *httpTriggerHandler) setupCallback(ctx context.Context, requestID string, callback handlers.Callback, requestStartTime time.Time) (<-chan struct{}, error) {
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()

	if _, found := h.callbacks[requestID]; found {
		h.handleUserError(ctx, requestID, jsonrpc.ErrConflict, fmt.Sprintf("requestID: %s has already been used. Ensure the requestID is unique for each request.", requestID), callback)
		return nil, fmt.Errorf("in-flight request ID: %s", requestID)
	}

	// (N+F)//2 + 1 threshold where N = number of nodes, F = number of faulty nodes
	threshold := (len(h.donConfig.Members)+h.donConfig.F)/2 + 1
	agg, err := aggregation.NewIdenticalNodeResponseAggregator(threshold)
	if err != nil {
		return nil, errors.New("failed to create response aggregator: " + err.Error())
	}

	doneCh := make(chan struct{})
	h.callbacks[requestID] = savedCallback{
		Callback:           callback,
		requestStartTime:   requestStartTime,
		createdAt:          time.Now(),
		responseAggregator: agg,
		doneCh:             doneCh,
	}
	return doneCh, nil
}

// cleanupCallback removes a callback and signals sendWithRetries to stop.
// Must be called while holding callbacksMu lock.
func (h *httpTriggerHandler) cleanupCallback(requestID string) {
	saved, exists := h.callbacks[requestID]
	if !exists {
		return
	}
	close(saved.doneCh)
	delete(h.callbacks, requestID)
}

func (h *httpTriggerHandler) HandleNodeTriggerResponse(ctx context.Context, resp *jsonrpc.Response[json.RawMessage], nodeAddr string) error {
	h.lggr.Debugw("handling trigger response", "requestID", resp.ID, "nodeAddr", nodeAddr, "error", resp.Error, "result", resp.Result)
	h.callbacksMu.Lock()
	defer h.callbacksMu.Unlock()
	saved, exists := h.callbacks[resp.ID]
	if !exists {
		return errors.New("callback not found for request ID: " + resp.ID)
	}
	aggResp, err := saved.responseAggregator.CollectAndAggregate(resp, nodeAddr)
	if err != nil {
		return err
	}
	if aggResp == nil {
		h.lggr.Debugw("Not enough responses to aggregate", "requestID", resp.ID, "nodeAddress", nodeAddr)
		return nil
	}
	rawResp, err := json.Marshal(aggResp)
	if err != nil {
		return errors.New("failed to marshal response: " + err.Error())
	}

	err = saved.SendResponse(handlers.UserCallbackPayload{
		RawResponse: rawResp,
		ErrorCode:   api.NoError,
	})
	if err != nil {
		return err
	}

	// Only after successfully sending the response, clean up the callback
	h.cleanupCallback(resp.ID)
	latencyMs := time.Since(saved.requestStartTime).Milliseconds()
	h.metrics.RecordRequestHandlerLatency(ctx, latencyMs, h.lggr)
	h.metrics.IncrementRequestSuccess(ctx, h.lggr)
	return nil
}
