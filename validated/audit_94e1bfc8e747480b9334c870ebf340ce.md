## Analog Found

### Title
Missing declared-class check in Starknet OS `replace_class` syscall causes execution divergence from Blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall is implemented twice in this codebase: once in the Blockifier (Rust, used by the sequencer to build/execute blocks) and once in the Starknet OS (Cairo, used to re-execute the block and compute the committed state root/prove correctness). The Blockifier's implementation validates that the target `class_hash` is a declared class before allowing the replacement, but the Starknet OS's implementation of the same syscall skips this check entirely, exactly mirroring the ENS bug pattern where one code path (ETHRegistrarController → Base Registrar) bypassed the permission/state-consistency logic enforced by the other path (NameWrapper).

### Finding Description
The Blockifier's `replace_class` syscall handler explicitly reads the target class to ensure it is declared before updating the contract's class hash: [1](#0-0) 

The same guarantee is verified for the Cairo1 syscall path via `syscall_base.rs`/state layer, and is proven by the dedicated test that a `replace_class` call to an undeclared class hash fails with "is not declared": [2](#0-1) [3](#0-2) 

However, the Starknet OS's Cairo implementation of `execute_replace_class` (used for Cairo1 syscalls) has this check explicitly missing, flagged by an unresolved TODO: [4](#0-3) 

The deprecated (Cairo0) syscall path in the OS has the identical omission: [5](#0-4) 

Both OS functions read the current `StateEntry` via the `GetContractAddressStateEntry` hint and unconditionally write a `new_state_entry` with the caller-supplied `class_hash`, with no assertion that this class hash exists in `contract_class_changes` or the declared-class tree — unlike Blockifier, which raises `StateError::UndeclaredClassHash` and fails/reverts the call in this situation.

### Impact Explanation
The Starknet OS is the component that re-executes each transaction (via Cairo `starknet_os_program`) to compute the committed state/class commitment (Patricia tree roots) that is included in the block hash/proof, per the Cairo OS `state_update` pipeline (`state.cairo`). If a contract invokes `replace_class` with an undeclared class hash within a transaction:
- Blockifier treats this as an execution error, causing the call (and typically the whole transaction, or a REVERTED transaction if reverts are enabled) to fail, per the explicit check and matching test coverage.
- The Starknet OS silently accepts the same call as successful and commits the new (undeclared) class hash into `contract_state_changes`, producing a different final state and a different global state root than the one actually computed by the sequencer/Blockifier for the same transaction.

This is a Blockifier/OS execution divergence: the sequencer and OS disagree on whether the transaction succeeded/reverted and on the resulting state, which can lead to an incorrect committed state root / block hash relative to what the sequencer actually built, i.e., an honest-node divergence and potential wrong committed root.

### Likelihood Explanation
Reachable by any unprivileged contract simply invoking the `replace_class` syscall (deprecated or new) with an arbitrary, non-existent class hash — no special privileges are required, and the syscall is available to any executing contract. The bug is unconditional (no feature flag) in both the Cairo1 (`syscall_impls.cairo`) and Cairo0 (`deprecated_execute_syscalls.cairo`) syscall handlers within the Starknet OS program, and is explicitly acknowledged as outstanding via the `TODO(Yoni, 1/1/2026)` comment, confirming the check was never implemented on the OS side.

### Recommendation
Add the equivalent declared-class check in both `execute_replace_class` implementations in the Starknet OS Cairo program (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`), mirroring the Blockifier logic in `hint_processor.rs::replace_class`: before updating `contract_state_changes` with the new class hash, assert that `class_hash` exists in `contract_class_changes` (i.e., has been declared), and fail/revert the syscall consistently with Blockifier's behavior when it has not.

### Proof of Concept
1. Deploy a contract whose code invokes the `replace_class` syscall with an attacker-chosen, undeclared `class_hash` (e.g., `0xdeadbeef`), analogous to the test setup in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash`.
2. In Blockifier (actual sequencer execution), `hint_processor.rs::replace_class` calls `state.get_compiled_class(request.class_hash)?`, which returns `StateError::UndeclaredClassHash`, causing the call/transaction to fail or revert.
3. If the same syscall trace/inputs were re-executed by the Starknet OS's `execute_replace_class` (`syscall_impls.cairo` lines 881-919, or the deprecated variant), no such check exists — the OS would compute `new_state_entry` with the undeclared `class_hash` and commit it via `dict_update`, producing a state/class commitment that disagrees with what Blockifier actually would have produced for that transaction.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
