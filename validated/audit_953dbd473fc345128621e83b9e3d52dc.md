Confirmed: `MsgVoteInbound.GetSigners()` returns whatever `sdk.AccAddress` parses from the free-text `Signer` string field [1](#0-0) , and `AccountInitDecorator.verifySignatureForNewAccount` never checks that the signature's `PubKey` derives to that same address before creating the account and short-circuiting the ante chain [2](#0-1) .

### Title
Gasless first-use account initialization creates accounts without binding pubkey to signer address, enabling identity spoofing for bonded-UV vote messages - (File: `app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator` is inserted into the Cosmos ante chain specifically to let a brand-new signer submit a gasless tx (`MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`, `MsgExecutePayload`) before any account exists for it [3](#0-2) . It is documented and wired to run *before* `SetPubKeyDecorator` and `SigVerificationDecorator`, and explicitly bypasses the remainder of the ante chain on success [4](#0-3) . Its own signature check (`verifySignatureForNewAccount`) never verifies that the recovered `pubKey.Address()` equals the message's declared signer address (`newAccAddr`); it only checks that the signature cryptographically validates against `signerData{Address: newAccAddr, AccountNumber:0, Sequence:0, PubKey: <attacker's key>}` [5](#0-4) .

### Finding Description
For SIGN_MODE_DIRECT (the default signing mode), the actual bytes cryptographically signed are `SignDoc{body_bytes, auth_info_bytes, chain_id, account_number}` — this does not encode the bech32 "Address" string from `signerData` anywhere. The `Address` field passed into `authsigning.VerifySignature` in this decorator is therefore not an input that constrains the signature at all under Direct mode; it is only meaningful for `SIGN_MODE_LEGACY_AMINO_JSON`, and even that path is not cross-checked against the pubkey's derived address.

Because `msg.Signer` (the free-text bech32 field) is what `GetSigners()` returns for `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta`/`MsgVoteTssKeyProcess`/`MsgVoteFundMigration` [1](#0-0) , an attacker can:
1. Pick a target address `V` that is a bonded Universal Validator (or soon-to-be-bonded UV hot key) whose Cosmos account has never yet been created on-chain (`HasAccount(ctx, V) == false`) — a very likely condition for freshly onboarded UVs, since this decorator's entire purpose is to support "a freshly-keygen'd Universal Validator hot key vot[ing] on its very first tx" [3](#0-2) .
2. Craft a gasless `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta`/TSS vote message with `Signer = V`, and sign it with their own attacker-controlled Ed25519/secp256k1 keypair (not `V`'s).
3. Submit the tx. `IsGaslessTx` accepts it [6](#0-5) . `AccountInitDecorator.AnteHandle` sees `!HasAccount(ctx, V)`, calls `verifySignatureForNewAccount`, which succeeds because the signature is valid for the attacker's own key over the Direct sign bytes (address never checked) [7](#0-6) .
4. The decorator creates a `BaseAccount` at address `V` with `sequence=1` and returns `ctx, nil` — **skipping** `SetPubKeyDecorator`, `ValidateSigCountDecorator`, `SigGasConsumeDecorator`, and `SigVerificationDecorator` entirely for this tx [8](#0-7) [9](#0-8) .
5. Message execution proceeds with `Signer = V`. The vote-handling keeper code (`VoteInbound`/`VoteOnInboundBallot`, etc.) treats the vote as coming from validator `V` — i.e., the attacker has forged a valid, gasless, bonded-UV-attributed vote/ballot participation without ever holding `V`'s key.

This is the direct analog of the reported "wallet stays unlocked" flaw: an authorization/identity binding that should be freshly (re-)established per session is instead accepted on trust and persisted — here, the address↔pubkey binding for a brand-new account is never checked at the one point where it matters (first use), permanently seeding the address's identity in a state the attacker controls.

### Impact Explanation
This breaks the "honest-validator finalization path" invariant: an unprivileged attacker who never holds a bonded UV's private key can cast forged inbound/outbound/chain-meta ballot votes, or TSS key-process/fund-migration votes, attributed to that UV's address, provided the target UV's Cosmos account has not yet transacted. This can corrupt ballot finalization (wrong ballot outcome, premature/incorrect UTX creation, forged outbound observation, forged TSS key/migration votes) and is reachable purely via unprivileged, default transaction submission — squarely within "forged, replayed, mismatched... ballot, TSS, or migration state accepted through user-reachable flows with honest validators and honest nodes," and "unauthorized state transitions in universal execution flows."

### Likelihood Explanation
The bug is trivially reachable by anyone who can submit a Cosmos transaction. The only precondition is that the target address has no on-chain account yet — realistic for newly bonded UVs (this is the exact scenario the decorator was built to support) and for any address that has simply never transacted. No validator or node collusion, no privileged access, and no external chain dependency is required — only knowledge of a target's bech32 address.

### Recommendation
In `AccountInitDecorator.verifySignatureForNewAccount`, after recovering `sig.PubKey`, explicitly verify `sdk.AccAddress(pubKey.Address()).Equals(newAccAddr)` before accepting the signature and creating the account (matching the check that stock `SetPubKeyDecorator` performs in the normal ante path). Reject the tx if the derived address does not match the declared signer.

### Proof of Concept
1. Identify an address `V` for a bonded (or about-to-be-bonded) Universal Validator that has not yet submitted any transaction (`HasAccount(ctx, V) == false`).
2. As attacker, generate your own keypair `K_attacker`.
3. Build a `MsgVoteInbound{Signer: V, Inbound: <attacker-chosen fabricated inbound>}`.
4. Sign the tx with `K_attacker` using SIGN_MODE_DIRECT, `account_number=0`, `sequence=0`.
5. Broadcast. `IsGaslessTx` passes; `AccountInitDecorator` verifies the signature against `signerData{Address: V, ...}` — which succeeds because Direct-mode sign bytes never encode `Address`; account `V` gets created with `sequence=1`; ante short-circuits; the message executes with `Signer = V`, casting a forged UV vote.
6. Repeat for `MsgVoteOutbound`/`MsgVoteChainMeta`/`MsgVoteTssKeyProcess`/`MsgVoteFundMigration` to forge outbound observations or TSS process/migration votes attributed to `V`.

Note: I was not able to fully trace the bonded-UV authorization check inside `msg_server.go` (`IsBondedUniversalValidator`) within the available context to confirm whether it does any additional address-source validation beyond trusting `msg.Signer`; a Devin session with full repo access should verify this final link before remediation to ensure no additional gate exists that would block the forged vote after account creation.

func (aid AccountInitDecorator) verifySignatureForNewAccount(ctx sdk.Context, tx sdk.Tx, simulate bool) error {
	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	// stdSigs contains the sequence number, account number, and signatures.
	// When simulating, this would just be a 0-length slice.
	sigs, err := sigTx.GetSignaturesV2()
	if err != nil {
		return err
	}

	signers, err := sigTx.GetSigners()
	if err != nil {
		return err
	}

	// check that signer length and signature length are the same
	if len(sigs) != len(signers) {
		return errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "invalid number of signer;  expected: %d, got %d", len(signers), len(sigs))
	}

	newAccAddr := sdk.AccAddress(signers[0])
	for _, sig := range sigs {
		pubKey := sig.PubKey
		if pubKey == nil {
			return errorsmod.Wrap(sdkerrors.ErrInvalidPubKey, "pubkey is not provided in signature")
		}

		// retrieve signer data
		chainID := ctx.ChainID()
		var accSequence uint64 = 0
		var accNum uint64 = 0

		// no need to verify signatures on recheck tx
		if !simulate && !ctx.IsReCheckTx() && ctx.IsSigverifyTx() {
			anyPk, _ := codectypes.NewAnyWithValue(pubKey)

			signerData := txsigning.SignerData{
				Address:       newAccAddr.String(),
				ChainID:       chainID,
				AccountNumber: accNum,
				Sequence:      accSequence,
				PubKey: &anypb.Any{
					TypeUrl: anyPk.TypeUrl,
					Value:   anyPk.Value,
				},
			}
			adaptableTx, ok := tx.(authsigning.V2AdaptableTx)
			if !ok {
				return fmt.Errorf("expected tx to implement V2AdaptableTx, got %T", tx)
			}
			txData := adaptableTx.GetSigningTxData()
			ctx.Logger().Debug("account init decorator: verifying signature for new account",
				"address", newAccAddr.String(),
				"chain_id", chainID,
				"acc_num", accNum,
				"sequence", accSequence,
			)
			err = authsigning.VerifySignature(ctx, pubKey, signerData, sig.Data, aid.signModeHandler, txData)
			if err != nil {
				var errMsg string
				if OnlyLegacyAminoSigners(sig.Data) {
					// If all signers are using SIGN_MODE_LEGACY_AMINO, we rely on VerifySignature to check account sequence number,
					// and therefore communicate sequence number as a potential cause of error.
					errMsg = fmt.Sprintf("signature verification failed; please verify account number (%d), sequence (%d) and chain-id (%s)", accNum, accSequence, chainID)
				} else {
					errMsg = fmt.Sprintf("signature verification failed; please verify account number (%d) and chain-id (%s): (%s)", accNum, chainID, err.Error())
				}
				ctx.Logger().Debug("account init decorator: signature invalid for new account",
					"address", newAccAddr.String(),
					"chain_id", chainID,
				)
				return errorsmod.Wrap(sdkerrors.ErrUnauthorized, errMsg)

			}
		} else {
			ctx.Logger().Debug("account init decorator: skipping signature verification",
				"address", newAccAddr.String(),
				"simulate", simulate,
				"is_recheck_tx", ctx.IsReCheckTx(),
				"is_sigverify_tx", ctx.IsSigverifyTx(),
			)
		}
	}
	return nil
}

func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
