### Title
Missing declared-class validation in Starknet OS `execute_replace_class` causes state divergence from blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall does not verify that the target class hash is actually declared before writing it into the contract's state entry, while the Rust blockifier (the actual sequencer execution engine) enforces this check and reverts the transaction if the class is undeclared. This is the same bug class as the reported "missing allow-list validation before using a returned/attacker-controlled value to mutate state": an unchecked value (here, a class hash supplied via syscall calldata) is accepted and committed to state without confirming it satisfies the required precondition (declared class).

### Finding Description
In the blockifier, `replace_class` explicitly validates that the class is declared before mutating state: [1](#0-0) 

This is confirmed by tests that expect a hard failure ("is not declared", and "Cannot replace V1 class hash with V0 class hash") when the supplied class hash is not declared or of an incompatible version: [2](#0-1) 

However, the equivalent logic in the Starknet OS Cairo program (used by the sequencer/prover for state-transition re-execution and STARK proof generation) has no such check, and this gap is explicitly acknowledged by an open TODO in the source: [3](#0-2) 

The deprecated (Cairo0) syscall path in the OS has the identical omission — it updates `contract_state_changes` with the new class hash unconditionally, without ever reading/validating the declared class: [4](#0-3) 

Because the blockifier is the ground-truth execution engine that actually commits state during block building, and the Starknet OS is meant to re-execute the same transactions to prove that the state transition is valid, any function whose semantics differ between the two — as `replace_class` does here — can cause the OS's computed state (and thus its proof) to diverge from the state the sequencer actually committed on-chain.

### Impact Explanation
If a transaction invokes `replace_class` with a class hash that has never been declared:
- The blockifier will fail the syscall (an entrypoint/Cairo1 revert, with error "is not declared"), leaving the contract's class hash unchanged and only charging the reverted-tx fee.
- The Starknet OS, when re-executing the exact same transaction to compute the state commitment/proof, will not detect the missing declaration and will instead successfully update `contract_state_changes` to the undeclared class hash, marking the syscall (and therefore likely the whole transaction) as succeeding rather than reverting.

This produces an execution/state divergence between the actual sequencer-committed state (via blockifier) and the OS-computed state used to attest/prove the block, i.e. a wrong committed state root/proof for the block. Depending on how this divergence surfaces (SNOS proof rejection or acceptance of a state transition that does not match the sequencer's real state), this can either halt block finality (network unable to confirm new blocks) or allow commitment of an incorrect state root — both of which fall under the accepted high/medium impact categories (wrong committed root, honest-node divergence, network unable to confirm new transactions).

### Likelihood Explanation
The `replace_class` syscall is directly reachable by any contract (via Cairo1 `replace_class_syscall` or the deprecated Cairo0 `replace_class` syscall) from a single submitted, unprivileged transaction — no special privileges are required. Any account or contract can trigger it by simply passing an arbitrary/undeclared class hash as calldata, making the divergence trivially and deterministically reproducible on every node running the OS re-execution/proving path.

### Recommendation
Add an explicit declared-class check in the Starknet OS's `execute_replace_class` (both the Cairo1 path in `syscall_impls.cairo` and the deprecated Cairo0 path in `deprecated_execute_syscalls.cairo`) that mirrors the blockifier's behavior — i.e., look up the compiled class for `class_hash` (via the `contract_class_changes` dict / declared classes structure) and fail/revert the syscall the same way the blockifier does (including the V0/V1 compatibility check) when it is not declared, ensuring semantic parity between the OS and the blockifier for this syscall.

### Proof of Concept
1. Deploy a contract implementing `__execute__` that calls `replace_class_syscall(undeclared_class_hash)` with a `class_hash` that has never been declared on-chain.
2. Submit an invoke transaction targeting this entrypoint.
3. Observe: the blockifier reverts the transaction ("is not declared"), as shown by the existing test `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash`.
4. Feed the same transaction/block to the Starknet OS for re-execution (`execute_replace_class` in `syscall_impls.cairo`, currently missing the check per its own TODO comment) — it will proceed to update `contract_state_changes` for the contract with the undeclared class hash instead of reverting, producing a different resulting state/trace than the blockifier's actual execution.

        // Ensure the class is declared (by reading it).
        syscall_handler.state.get_compiled_class(request.class_hash)?;
        syscall_handler

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
