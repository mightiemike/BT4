### Title
Inconsistent rounding of the 70% signer-weight supermajority threshold between `GlobalStateEvaluator::reached_agreement` (floor) and `NakamotoBlockHeader::compute_voting_weight_threshold` (ceiling) lets a sub-quorum weight be treated as "global agreement" - (File: libsigner/src/v0/signer_state.rs)

### Summary
The signer set computes the 70% supermajority threshold in two different places using two different rounding rules for the same constant, `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`. The chain-validating threshold rounds up (ceiling), while the signer-local "global state" agreement threshold rounds down (floor). This mirrors the C4 finding's root cause: a fixed-point ratio (`weight * numerator / denominator`) that truncates instead of consistently rounding, so a value that should require a strictly higher weight to "count" is accepted with less.

### Finding Description
`NakamotoBlockHeader::compute_voting_weight_threshold` explicitly ceils the 70% threshold so that a fractional requirement is never under-counted: [1](#0-0) 

This is the threshold actually enforced when verifying that a Nakamoto block carries enough signer weight to be valid (`verify_signer_signatures`): [2](#0-1) 

By contrast, `GlobalStateEvaluator::reached_agreement` / `reached_disagreement`, which every signer uses to decide whether the signer set has reached consensus on the *current miner*, the *active signer protocol version*, the *burn view*, and the *tx replay set*, use a plain floor division of the same nominal 70%/30% split with no rounding-up correction: [3](#0-2) 

These functions gate `determine_latest_supported_signer_protocol_version`, `determine_global_burn_view`, and `determine_global_state` (which in turn produces the canonical `current_miner`/`tx_replay_set` a signer will capitulate to): [4](#0-3) 

and drive `LocalStateMachine::capitulate_viewpoint` / `capitulate_miner_view`, which decide when a signer switches its local view of the current miner and, transitively, which tenure it is willing to sign blocks for: [5](#0-4) 

Because `compute_voting_weight_threshold` ceils and `reached_agreement` floors, for the same `total_weight` there exist values of `total_weight` where the two functions disagree by exactly one weight unit (e.g., `total_weight = 13`, threshold constant `= 7`: ceiling threshold = `91/10 + 1 = 10`, floor threshold in `reached_agreement` = `91/10 = 9`). A coalition holding only 9/13 (≈69.2%, i.e. *below* the intended 70% supermajority and below what `compute_voting_weight_threshold` would require for an actual block-signature quorum) is nonetheless treated by `GlobalStateEvaluator::reached_agreement` as having reached "global agreement" on the current miner/tenure/tx-replay state.

### Impact Explanation
This is not identical to the original token-dust bug (no funds are directly at risk here), but it is the same rounding-mismatch bug class applied to the signer-weight-threshold analog explicitly called out in scope ("signer weight below threshold or from the wrong set"). The practical effect: a set of signers representing strictly less weight than the actual protocol-mandated supermajority (as enforced at block-validation time by `compute_voting_weight_threshold`) can cause the rest of the signer set's local state machines to "capitulate" to a new miner/tenure view or a new tx-replay-set/protocol-version before the true ceiling-rounded threshold is met. Since actual block acceptance is still gated by the stricter `compute_voting_weight_threshold` in `verify_signer_signatures`, this does not directly let an invalid block be accepted network-wide; the impact is bounded to **temporary tip/tenure-view disagreement among signers** — some signers may switch to treating a new tenure as canonical (and correspondingly stop signing the old one) a fraction of a weight-unit before the real quorum threshold is reached, which can stall block production or cause transient signature-collection splits across the signer set until true supermajority is reached. This matches the "temporary tip disagreement" High-impact category defined in scope.

### Likelihood Explanation
This requires no special privilege beyond being (or colluding as) a set of signers whose combined weight lands exactly on one of the total_weight values where `floor(total_weight * 7 / 10) < ceil(total_weight * 7 / 10)`, i.e., whenever `total_weight * 7 mod 10 != 0`. This is the common case for arbitrary signer weight distributions (only exact multiples of 10 in total weight avoid the discrepancy), so the divergence window is realistically reachable on most reward cycles without needing majority control — only enough signers to reach the lower (floor) bound, which can be a strict minority relative to the true intended supermajority.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement` and `reached_disagreement` use the same ceiling-rounding convention as `NakamotoBlockHeader::compute_voting_weight_threshold` (or better, have both call a single shared threshold-computation function) so that "global agreement" as observed by signers can never be satisfied by less weight than the chain-level quorum requires.

### Proof of Concept
Arithmetic proof (no live network needed, deterministic from the two functions' code):
1. Let `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7` (70%) and `total_weight = 13`.
2. `compute_voting_weight_threshold(13)`: `91 % 10 = 1 != 0` ⇒ `ceil = 1`; result = `91/10 + 1 = 10`. A block needs signature weight ≥ 10/13 to be valid per `stackslib/src/chainstate/nakamoto/mod.rs:1194-1207`.
3. `GlobalStateEvaluator::reached_agreement(9)` on the same `total_weight = 13`: `9 >= 13*7/10 = 91/10 = 9` (integer floor) ⇒ returns `true`, per `libsigner/src/v0/signer_state.rs:171-175`.
4. Therefore a coalition with exactly 9/13 signer weight (< the 10/13 actually required for block validity) is reported by `GlobalStateEvaluator` as having reached global agreement on `current_miner` / `tx_replay_set` / protocol version, even though that same weight would be rejected by `verify_signer_signatures`'s `compute_voting_weight_threshold` check for an actual block signature quorum.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Returns true if it has, false otherwise.

            >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)

    pub fn reached_disagreement(&self, vote_weight: u32) -> bool {

            > u64::from(self.total_weight).strict_mul(10 - NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD)

    #[allow(clippy::too_many_arguments)]

        &mut self,
        stacks_client: &StacksClient,
        signerdb: &mut SignerDb,
        eval: &mut GlobalStateEvaluator,

        self.update_protocol_version(stacks_client, eval, local_supported_signer_protocol_version);

            local_supported_signer_protocol_version,
            capitulate_miner_view_timeout,
            last_capitulate_miner_view,

            return;

        // This is a bit of an expensive call (due to call for node tip) so we don't want to do it if
        // the node is advancing with our participation.
        self.update_parent_tenure_last_block(
            stacks_client,
            signerdb,
            local_supported_signer_protocol_version,
            tenure_last_block_proposal_timeout,
        );
        let Ok(local_update) =
            self.try_into_update_message_with_version(local_supported_signer_protocol_version)
        else {

        let Some(new_miner) = self.capitulate_miner_view(
            stacks_client,
            eval,
            signerdb,
            &local_update,
            tenure_last_block_proposal_timeout,
        ) else {
            return;
        };

        let (burn_block, burn_block_height) = local_update.content.burn_block_view();
        let current_miner = local_update.content.current_miner();
        let tx_replay_set = local_update.content.tx_replay_set();

                burn_block: burn_block.clone(),
                burn_block_height,

                active_signer_protocol_version: local_update.active_signer_protocol_version,

                                SortitionMinerStatus::InvalidatedBeforeFirstBlock
                        }
                    }
                }
                StateMachineUpdateMinerState::NoValidMiner => (),

        }
