### Title
Off-chain CCIP execution gas estimator uses flat, untiered calldata cost, causing gas under-estimation for large messages - ([File: core/capabilities/ccip/ccipevm/gas_helpers.go])

### Summary
The chainlink node's CCIP execute-plugin gas estimator, `EstimateProvider.CalculateMessageMaxGas` in `core/capabilities/ccip/ccipevm/gas_helpers.go`, computes calldata gas using a single flat rate (`CalldataGasPerByteBase = 16`) regardless of message size. This mirrors exactly the bug class described in the external report: an on-chain/off-chain gas-accounting function that has not been updated to reflect that large calldata should be charged at a higher per-byte rate. The on-chain `FeeQuoter` contract that this same package feeds config for already implements a two-tier calldata cost model (`DestGasPerPayloadByteBase`/`DestGasPerPayloadByteHigh`/`DestGasPerPayloadByteThreshold`), but the node-side gas estimator used to size CCIP execution reports does not.

### Finding Description
`core/capabilities/ccip/ccipevm/gas_helpers.go` defines the constants used both to configure the on-chain `FeeQuoter` and to estimate off-chain the gas a message will need on execution: [1](#0-0) 

The on-chain `FeeQuoter` dest-chain config deliberately encodes a tiered calldata-cost model — a base rate below a byte threshold and a higher rate ("High") above it — as populated in the deployment/config code: [2](#0-1) 

However, the off-chain `CalculateMessageMaxGasWithError` function, which estimates the maximum gas a message will consume on the destination chain (used by the OCR execution plugin to decide gas limits/batching for execution reports), always multiplies the total message bytes by the flat `CalldataGasPerByteBase` rate, never applying the `CalldataGasPerByteHigh`/`CalldataGasPerByteThreshold` tiering that the on-chain fee/gas model uses: [3](#0-2) 

`CalculateMerkleTreeGas` has the same limitation — it also always uses `CalldataGasPerByteBase`: [4](#0-3) 

This is the same root-cause pattern as the reported Optimism issue: a gas-accounting formula for calldata that assumes a flat per-byte cost fails to reflect that, above a certain size, calldata should be charged more (in Optimism's case due to EIP-7623's floor cost; in CCIP's case, the protocol's own dest-chain fee/gas model explicitly defines a "High" tier for large payloads via `DestGasPerPayloadByteHigh`/`DestGasPerPayloadByteThreshold`). The off-chain estimator that decides whether/how a node will attempt to execute a message on the destination chain does not implement this tiering and therefore under-estimates the gas required for large-calldata messages.

### Impact Explanation
`CalculateMessageMaxGas` is exposed as the node's `ccipocr3.EstimateProvider` implementation (wired via `NewGasEstimateProvider`) and is consumed by the CCIP execution OCR plugin to size gas requirements/batches for `ExecutePluginReport`s before they are submitted on-chain via `OffRamp.ManuallyExecute`/automatic execution. If the off-chain estimate under-reports the true gas needed for a large-calldata message (because it never applies the higher per-byte rate that the on-chain fee model uses above the payload threshold), the plugin can pack messages into an execution report with insufficient gas headroom. This can cause the destination-chain execution transaction to run out of gas and fail (`EXECUTION_STATE_FAILURE`), leaving the message stuck and requiring manual re-execution — the same "message gets stuck due to insufficient allocated gas" failure mode described in the original report, applied to CCIP's L1<->L2-style cross-chain messaging.

### Likelihood Explanation
This triggers deterministically whenever a message's calldata size crosses the byte size at which the on-chain fee model would apply the higher per-byte rate (`CalldataGasPerByteThreshold = 3000` bytes, mirrored in the on-chain `DestGasPerPayloadByteThreshold`). Any user submitting a CCIP message with calldata larger than this threshold can reproduce the discrepancy between the off-chain estimate and the true on-chain-modeled gas requirement; no privileged or malicious node/operator behavior is required — an ordinary CCIP message sender can trigger it.

### Recommendation
Update `CalculateMessageMaxGasWithError` (and `CalculateMerkleTreeGas`) in `core/capabilities/ccip/ccipevm/gas_helpers.go` to apply the same tiered calldata-cost model used on-chain (`CalldataGasPerByteBase` below `CalldataGasPerByteThreshold`, `CalldataGasPerByteHigh` above it) so the off-chain gas estimate used for execution/batching decisions cannot under-estimate the true destination-chain gas requirement for large messages.

### Proof of Concept
1. Construct a CCIP message whose ABI-encoded size (`ConstantMessagePartBytes + bytesForMsgTokens(numTokens) + len(Data)`) exceeds `CalldataGasPerByteThreshold` (3000 bytes).
2. Call `EstimateProvider.CalculateMessageMaxGas` on this message; observe it charges `messageBytes * CalldataGasPerByteBase` (16 gas/byte) for the entire payload.
3. Compare against the gas the on-chain `FeeQuoter`/`OffRamp` execution path would actually require if it followed the same tiered model configured via `DestGasPerPayloadByteHigh`/`DestGasPerPayloadByteThreshold` (40 gas/byte above the threshold) — the off-chain estimate is lower than the true on-chain cost for the calldata beyond the threshold, demonstrating the under-estimation.

// CalculateMerkleTreeGas estimates the merkle tree gas based on number of requests
func (gp EstimateProvider) CalculateMerkleTreeGas(numRequests int) uint64 {
	if numRequests <= 0 {
		return 0
	}
	merkleProofBytes := (math.Ceil(math.Log2(float64(numRequests))))*32 + (1+2)*32 // only ever one outer root hash
	return uint64(merkleProofBytes * CalldataGasPerByteBase)
}

	if err != nil {
		return 0, fmt.Errorf("error decoding extra args: %w", err)

	if err != nil {
		return 0, fmt.Errorf("error parsing extra args map: %w", err)
	}

	for _, rampTokenAmount := range msg.TokenAmounts {
		decodedMap, err = gp.extraDataCodec.DecodeTokenAmountDestExecData(rampTokenAmount.DestExecData, msg.Header.SourceChainSelector)
		if err != nil {
			return 0, fmt.Errorf("failed to decode token dest gas overhead: %w", err)
		}

		tokenDestGasOverhead, err := extractDestGasAmountFromMap(decodedMap)

			return 0, fmt.Errorf("failed to extract dest gas amount from map: %w", err)
		}

	}

		bytesForMsgTokens(numTokens) +
		dataLength

	if messageBytes < 0 {
		return 0, errors.New("message bytes cannot be negative")
	}

	messageCallDataGas := uint64(messageBytes) * CalldataGasPerByteBase
