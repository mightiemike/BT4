## Analysis

The seed bug (median-of-two computed incorrectly in `SimplePriceFeedStrategy.sol`) maps to Push Chain's own median/price-aggregation logic in `x/uexecutor/keeper/chain_meta.go` and `x/uexecutor/keeper/gas_price.go`, which independently compute two different "median" values over the same `Prices` array using two different (and desynchronized) algorithms.

### Title
Stale `MedianIndex` causes `GasPrice`/`ChainMeta` queries to return a gas price that diverges from the actually-applied on-chain oracle value - (File: `x/uexecutor/keeper/chain_meta.go`, `x/uexecutor/keeper/gas_price.go`, `x/uexecutor/keeper/query_server.go`)

### Summary
`VoteChainMeta` computes the actual on-chain-applied gas price via `upperMedianUint64` over only the freshness-filtered vote set (`fresh`), but it separately stores `entry.MedianIndex = computeMedianIndex(entry.Prices)` computed over the **entire, unfiltered** `Prices` array, including stale votes. Any external client reading gas price via the gRPC query (`Querier.GasPrice`, `Querier.AllGasPrices`, `Querier.ChainMeta`) receives `Prices[MedianIndex]`, which can differ from the value that was actually written to the `UniversalCore` EVM oracle via `CallUniversalCoreSetChainMeta`.

### Finding Description
In `VoteChainMeta` (`x/uexecutor/keeper/chain_meta.go:110-177`), the function builds a `fresh` slice containing only votes whose `StoredAts` timestamp is within `chainMetaVoteStalenessSeconds`, then computes:
```go
medianPrice := upperMedianUint64(fresh, func(v voteSnapshot) uint64 { return v.price })
``` [1](#0-0) 
This `medianPrice` is what actually gets pushed on-chain via `CallUniversalCoreSetChainMeta`. [2](#0-1) 

However, the stored `entry.MedianIndex` field — which downstream queries use to pick a "median" from `entry.Prices` — is computed on the **full, unfiltered** `Prices` array, not the fresh subset:
```go
entry.MedianIndex = uint64(computeMedianIndex(entry.Prices))
``` [3](#0-2) 

`computeMedianIndex` in `gas_price.go` sorts all prices (stale or not) and returns the index of the upper-median element in the raw array: [4](#0-3) 

The gRPC `Querier.GasPrice`, `Querier.AllGasPrices`, and `Querier.ChainMeta` handlers return `Prices[MedianIndex]` directly (via `chainMetaToGasPrice`) without any staleness filtering: [5](#0-4) 

The integration test `TestVoteChainMetaIntegration/"stale votes excluded from median"` demonstrates the exact divergence: after a stale-vote round, the EVM-applied price is `900` (only the fresh vote), while `GetChainMeta` / `MedianIndex`-derived price would reflect a different, stale-influenced value: [6](#0-5) 

This is structurally the same class of defect as the Sherlock M-3 report: two independently-computed "median" results over the same data set diverge because one code path filters/handles edge cases the other does not, and consumers of the "cheap" computation get a wrong value.

### Impact Explanation
`universalClient/pushcore/pushCore.go`'s `Client.GetGasPrice` is a real consumer of this query path — it fetches `resp.GasPrice.MedianIndex` and indexes into `resp.GasPrice.Prices` to determine the gas price used for constructing/estimating outbound transactions: [7](#0-6) 
Because `MedianIndex` can point to a stale-vote-influenced value that is different from what was actually written to the `UniversalCore` on-chain oracle (`entry.LastAppliedChainHeight`/`medianPrice`), this corrupts gas fee accounting: `universalClient` may build/estimate transactions with the wrong gas price relative to the canonical on-chain gas price the protocol is actually using, which falls under "corruption of ... gas fee accounting ... chain config use" per the allowed-impact list.

### Likelihood Explanation
This divergence requires no malicious validator or attacker action at all — it occurs purely through ordinary operation whenever votes go stale asynchronously (e.g., a subset of validators re-vote before others, which is explicitly exercised and expected behavior per `chainMetaVoteStalenessSeconds`). Since it needs no privileged or malicious actor, it is squarely within scope, but the resulting impact is limited to off-chain query/estimation correctness rather than a direct fund-loss, unauthorized-mint, or consensus-divergence primitive; the `LastAppliedChainHeight`/on-chain oracle values themselves stay internally consistent, since only `entry.MedianIndex` (a "best-effort" field explicitly marked in the code comment as "used for storage/querying only") diverges. Because the on-chain oracle write path itself remains correct, and the divergence is confined to a documented "best-effort" convenience field, this does not rise to a material, directly-exploitable protocol invariant break.

### Recommendation
Recommend to Push Chain: compute `MedianIndex` (or better, store the actual `medianPrice`/`medianChainHeight` values directly) against the same `fresh` filtered set used for the on-chain oracle write, so that `GetChainMeta`/`GetGasPrice` query responses are always consistent with the value actually applied via `CallUniversalCoreSetChainMeta`. Alternatively, deprecate `MedianIndex`-based indexing entirely and expose the already-computed `medianPrice`/`medianChainHeight` scalars in the query response.

### Proof of Concept
Reproduced by the existing test `TestVoteChainMetaIntegration/"stale votes excluded from median"` at [6](#0-5) : 3 validators vote prices `100/300/200` at time T (on-chain applied median = `200`); after `301s`, only `val0` re-votes with price `900`; the EVM oracle correctly reflects `900` (only fresh vote used), but `stored.Prices`/`MedianIndex` reflect the full unfiltered array `[900,300,200]` (median index → `300`), which a client calling the `GasPrice`/`ChainMeta` gRPC query (and in turn `pushcore.Client.GetGasPrice`) would read instead of the actually-applied `900`.

// computeMedianIndex returns index of the median element
func computeMedianIndex(values []uint64) int {
	type idxVal struct {
		Idx int
		Val uint64
	}
	arr := make([]idxVal, len(values))
	for i, v := range values {
		arr[i] = idxVal{Idx: i, Val: v}
	}
	sort.SliceStable(arr, func(i, j int) bool { return arr[i].Val < arr[j].Val })
	return arr[len(arr)/2].Idx
}
```

// GetGasPrice retrieves the median gas price for a specific chain from the on-chain oracle.
func (c *Client) GetGasPrice(ctx context.Context, chainID string) (*big.Int, error) {
	if chainID == "" {
		return nil, errors.New("pushcore: chainID is required")
	}

	return retryWithRoundRobin(
		len(c.uexecutorClients),
		&c.rr,
		func(idx int) (*big.Int, error) {
			resp, err := c.uexecutorClients[idx].GasPrice(ctx, &uexecutortypes.QueryGasPriceRequest{
				ChainId: chainID,
			})
			if err != nil {
				return nil, err
			}
			if resp.GasPrice == nil {
				return nil, errors.New("pushcore: GasPrice response is nil")
			}

			if len(resp.GasPrice.Prices) == 0 {
				return nil, fmt.Errorf("pushcore: no gas prices available for chain %s", chainID)
			}

			medianIdx := resp.GasPrice.MedianIndex
			if medianIdx >= uint64(len(resp.GasPrice.Prices)) {
				medianIdx = 0
			}

			medianPrice := resp.GasPrice.Prices[medianIdx]
			return new(big.Int).SetUint64(medianPrice), nil
		},
		"GetGasPrice",
		c.logger,
	)
}
