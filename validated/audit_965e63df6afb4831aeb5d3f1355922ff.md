Based on the code I found, this reduces to a real (but historical, fork-gated) double-counting bug in `TransactionCapsule.checkWeight`.

### Title
Pre-VERSION_4_7_1 signature-dedup bypass in `TransactionCapsule.checkWeight` allows same-key weight double-counting via ECDSA signature malleability - (File: chainbase/src/main/java/org/tron/core/capsule/TransactionCapsule.java)

### Summary
`TransactionCapsule.checkWeight` deduplicates signatures by keying `addMap` on the raw base64-encoded signature string unless `ForkController.instance().pass(VERSION_4_7_1)` is true, in which case it keys on the recovered address instead. Because signature recovery (`ECKey.recoverPubBytesFromSignature`) does not reject non-canonical/high-S signatures, an attacker can produce two byte-distinct 65-byte signatures for the same private key that both recover to the same address, bypassing the "has signed twice" check pre-fork and causing `currentWeight` to be double-counted for a single key.

### Finding Description
In `checkWeight` [1](#0-0) , for each signature the code computes `base64 = getBase64FromByteString(sig)`, recovers `address` from it, and only switches the dedup key to `encode58Check(address)` when `ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)` is true. Before this fork passes, `addMap` is keyed on the raw signature bytes/string, so two different signature encodings that both recover to the same address are treated as distinct entries, each contributing `weight` to `currentWeight`.

`ECKey.recoverPubBytesFromSignature` [2](#0-1)  performs raw SEC1 recovery from `(r, s, recId)` without any low-S/canonical-S enforcement (canonicalization, via `toCanonicalised()`, is only applied by the *signer* in `doSign`/`sign` [3](#0-2) , not by the verifier/recovery path). This means an attacker with any valid signature `(r, s, recId)` can derive the classic ECDSA-malleable counterpart `(r, N-s, recId')` which recovers to the identical address but differs byte-for-byte, thus differs when base64-encoded.

This is reachable via the public entrypoints:
- `TransactionUtil.getTransactionSignWeight` (called from `GetTransactionSignWeightServlet.doPost` [4](#0-3)  and the gRPC `getTransactionSignWeight` [5](#0-4) ), which calls `TransactionCapsule.checkWeight` and directly compares the resulting `currentWeight` against `permission.getThreshold()` to set `ENOUGH_PERMISSION`/`NOT_ENOUGH_PERMISSION` [6](#0-5) .
- `Wallet.getTransactionApprovedList`, similarly calling `checkWeight` [7](#0-6) .

An unprivileged attacker supplying a crafted transaction with two such malleable signatures for a single key of weight `W/2` (permission threshold `W`) would, pre-fork, get `currentWeight = W` and `ENOUGH_PERMISSION`, even though only one distinct signer actually approved.

### Impact Explanation
If exploited while the fork is inactive, a co-signer or wallet querying `GetTransactionSignWeight`/`GetTransactionApprovedList` could be misled into believing a multi-sig transaction has reached its Active-permission threshold when only one real signer approved, potentially causing them to countersign or broadcast a transaction (moving TRX/TRC10/TRC20) without genuine multi-party consensus. Note this only affects the read-only *reporting* APIs (`checkWeight`'s misreport); actual on-chain execution consensus checks would need separate confirmation, though `Wallet.getTransactionApprovedList`/`getTransactionSignWeight` are the exact tools operators use to decide whether to co-sign/broadcast.

### Likelihood Explanation
This is entirely a **historical/fork-gated** condition: the vulnerable branch only executes when `ForkController.instance().pass(Parameter.ForkBlockVersionEnum.VERSION_4_7_1)` returns `false`. `VERSION_4_7_1` is fork block value 27 [8](#0-7) , an old fork that long ago activated and hard-forked (hardForkTime `1596780000000` = 2020-08-07) on the java-tron mainnet and public testnets that this codebase targets. On any currently-running network where this fork has already passed (which is the case for all live TRON networks derived from this codebase), the address-keyed dedup path is always taken and the double-count is impossible. The bug is only reachable pre-fork-activation, i.e., during a narrow historical window or on a freshly bootstrapped private/test chain where an operator has not yet enabled `VERSION_4_7_1` — not a condition an unprivileged attacker can force on an already-forked network.

### Recommendation
Since the fork-gated branch is dead code on any chain that has already activated `VERSION_4_7_1`, no fix is required for currently operating networks. For defense-in-depth (e.g. new private chains bootstrapped without this proposal activated), always dedup by recovered address unconditionally rather than gating on the fork, or additionally reject non-canonical (`s > HALF_CURVE_ORDER`) signatures in the recovery path.

```java
// Precondition: ForkController.instance().pass(VERSION_4_7_1) == false (fork not yet active)
@Test
public void testPreForkMalleableSignatureDoubleCounts() throws Exception {
  ECKey ecKey = new ECKey(Utils.getRandom());
  // set up account with an Active permission: threshold = 2, single key weight = 1
  Permission permission = Permission.newBuilder()
      .setType(PermissionType.Active).setThreshold(2)
      .addKeys(Key.newBuilder().setAddress(ByteString.copyFrom(ecKey.getAddress())).setWeight(1))
      .build();

  byte[] hash = ...; // transaction hash
  ECKey.ECDSASignature sig = ecKey.sign(hash);           // canonical (r, s, v)
  ECKey.ECDSASignature malleable = new ECKey.ECDSASignature(
      sig.r, ECKey.CURVE.getN().subtract(sig.s));        // (r, N-s)
  malleable.v = flippedRecId(sig.v);                     // recompute matching recId

  ByteString sigA = ByteString.copyFrom(toBase64Bytes(sig));
  ByteString sigB = ByteString.copyFrom(toBase64Bytes(malleable));
  // sigA != sigB as byte strings, but both recover to ecKey.getAddress()

  List<ByteString> approveList = new ArrayList<>();
  long currentWeight = TransactionCapsule.checkWeight(
      permission, Arrays.asList(sigA, sigB), hash, approveList);

  // Pre-fork: expect currentWeight == 2 (double-counted single key) -> ENOUGH_PERMISSION
  // Post-fork (VERSION_4_7_1 active): expect PermissionException "has signed twice!"
  assertEquals(2, currentWeight);
}
```
Expected assertion difference: pre-fork `checkWeight` returns `currentWeight == 2` (>= threshold, `ENOUGH_PERMISSION`) with `approveList` containing the same address twice; post-fork it throws `PermissionException` ("has signed twice!"), confirming the dedup-by-address fix already closes this gap once the fork passes.

```java
  @Nullable
  public static byte[] recoverPubBytesFromSignature(int recId,
      ECDSASignature sig, byte[] messageHash) {
    check(recId >= 0, "recId must be positive");
    check(sig.r.signum() >= 0, "r must be positive");
    check(sig.s.signum() >= 0, "s must be positive");
    check(messageHash != null, "messageHash must not be null");
    // 1.0 For j from 0 to h   (h == recId here and the loop is outside
    // this function)
    //   1.1 Let x = r + jn
    BigInteger n = CURVE.getN();  // Curve order.
    BigInteger i = BigInteger.valueOf((long) recId / 2);
    BigInteger x = sig.r.add(i.multiply(n));
    //   1.2. Convert the integer x to an octet string X of length mlen
    // using the conversion routine
    //        specified in Section 2.3.7, where mlen = ⌈(log2 p)/8⌉ or
    // mlen = ⌈m/8⌉.
    //   1.3. Convert the octet string (16 set binary digits)||X to an
    // elliptic curve point R using the
    //        conversion routine specified in Section 2.3.4. If this
    // conversion routine outputs “invalid”, then
    //        do another iteration of Step 1.
    //
    // More concisely, what these points mean is to use X as a compressed
    // public key.
    ECCurve.Fp curve = (ECCurve.Fp) CURVE.getCurve();
    BigInteger prime = curve.getQ();  // Bouncy Castle is not consistent
    // about the letter it uses for the prime.
    if (x.compareTo(prime) >= 0) {
      // Cannot have point co-ordinates larger than this as everything
      // takes place modulo Q.
      return null;
    }
    // Compressed allKeys require you to know an extra bit of data about the
    // y-coord as there are two possibilities.
    // So it's encoded in the recId.
    ECPoint R = decompressKey(x, (recId & 1) == 1);
    //   1.4. If nR != point at infinity, then do another iteration of
    // Step 1 (callers responsibility).
    if (!R.multiply(n).isInfinity()) {
      return null;
    }
    //   1.5. Compute e from M using Steps 2 and 3 of ECDSA signature
    // verification.
    BigInteger e = new BigInteger(1, messageHash);
    //   1.6. For k from 1 to 2 do the following.   (loop is outside this
    // function via iterating recId)
    //   1.6.1. Compute a candidate public key as:
    //               Q = mi(r) * (sR - eG)
    //
    // Where mi(x) is the modular multiplicative inverse. We transform
    // this into the following:
    //               Q = (mi(r) * s ** R) + (mi(r) * -e ** G)
    // Where -e is the modular additive inverse of e, that is z such that
    // z + e = 0 (mod n). In the above equation
    // ** is point multiplication and + is point addition (the EC group
    // operator).
    //
    // We can find the additive inverse by subtracting e from zero then
    // taking the mod. For example the additive
    // inverse of 3 modulo 11 is 8 because 3 + 8 mod 11 = 0, and -3 mod
    // 11 = 8.
    BigInteger eInv = BigInteger.ZERO.subtract(e).mod(n);
    BigInteger rInv = sig.r.modInverse(n);
    BigInteger srInv = rInv.multiply(sig.s).mod(n);
    BigInteger eInvrInv = rInv.multiply(eInv).mod(n);
    ECPoint.Fp q = (ECPoint.Fp) ECAlgorithms.sumOfTwoMultiplies(CURVE
        .getG(), eInvrInv, R, srInv);
    return q.getEncoded(/* compressed */ false);
  }
```

```java
  public ECDSASignature doSign(byte[] input) {
    if (input.length != 32) {
      throw new IllegalArgumentException("Expected 32 byte input to " +
          "ECDSA signature, not " + input.length);
    }
    // No decryption of private key required.
    if (privKey == null) {
      throw new MissingPrivateKeyException();
    }
    if (privKey instanceof BCECPrivateKey) {
      ECDSASigner signer = new ECDSASigner(new HMacDSAKCalculator(new
          SHA256Digest()));
      ECPrivateKeyParameters privKeyParams = new ECPrivateKeyParameters
          (((BCECPrivateKey) privKey).getD(), CURVE);
      signer.init(true, privKeyParams);
      BigInteger[] components = signer.generateSignature(input);
      return new ECDSASignature(components[0], components[1])
          .toCanonicalised();
    } else {
      throw new RuntimeException("ECKey signing error");
    }
  }

  /**
   * Takes the keccak hash (32 bytes) of data and returns the ECDSA signature
   *
   * @param messageHash -
   * @return -
   * @throws IllegalStateException if this ECKey does not have the private part.
   */
  public ECDSASignature sign(byte[] messageHash) {
    ECDSASignature sig = doSign(messageHash);
    // Now we have to work backwards to figure out the recId needed to
    // recover the signature.
    int recId = -1;
    byte[] thisKey = this.pub.getEncoded(/* compressed */ false);
    for (int i = 0; i < 4; i++) {
      byte[] k = ECKey.recoverPubBytesFromSignature(i, sig, messageHash);
      if (k != null && Arrays.equals(k, thisKey)) {
        recId = i;
        break;
      }
    }
    if (recId == -1) {
      throw new RuntimeException("Could not construct a recoverable key" +
          ". This should never happen.");
    }
    sig.v = (byte) (recId + 27);
    return sig;
  }
```
