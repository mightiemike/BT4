Replay-verify's `ensure_match_transaction_info()` does not check state-checkpoint hashes, letting state-root divergence pass verification silently - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info()` is the comparator used by replay/verify tooling to confirm that a locally re-executed transaction matches the historical, authenticated `TransactionInfo` for that version. It checks status, gas used, write-set hash (`state_change_hash`), and event root hash, but explicitly skips the `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` fields, per the author's own `TODO(trading-native)` comment. [1](#0-0) 

### Finding Description
`TransactionInfo` carries multiple root-hash fields that authenticate ledger state at a version: `state_change_hash` (write-set hash), `event_root_hash`, and — depending on `TransactionInfo::V1` — `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash`. These checkpoint hashes commit to the Jellyfish Merkle / hot-state / position-state roots produced by `DoStateCheckpoint`/`DoLedgerUpdate` at block boundaries. [2](#0-1) 

`ensure_match_transaction_info()` is the single function used to decide whether a re-executed `TransactionOutput` matches a trusted, on-chain `TransactionInfo`. It is invoked from:
- `execution/executor/src/chunk_executor/mod.rs`'s `verify_execution`, which is the core correctness gate for chunk replay (used by backup restore's replay-verify and by `db-tool`'s replay tooling), and
- `aptos-move/cli/src/commands.rs` and `aptos-move/aptos-debugger/src/aptos_debugger.rs`, used for CLI-driven transaction replay/debugging against on-chain state. [3](#0-2) [4](#0-3) 

The function checks:
1. execution status,
2. gas used,
3. write-set hash vs. `state_change_hash`,
4. event root hash,

then returns `Ok(())` without ever comparing the locally computed state-checkpoint/hot-state/position-state roots to the corresponding fields recorded in the authenticated `TransactionInfo`. [5](#0-4) 

Because the write set hash only covers the deltas applied by that specific transaction (and the event root only covers its events), neither of the two checked hashes commits to the *overall resulting state tree root* the way `state_checkpoint_hash` does. If execution diverges in a way that corrupts the resulting global state root without altering the individual transaction's write set/events/gas/status — e.g. a bug in `DoStateCheckpoint`'s Merkle update, a mishandled resource-group merge, a hot-state or position-state materialization bug, or a divergent order-independent aggregation across the block — that divergence is invisible to this comparator. Replay-verify (`storage/db-tool/src/replay_verify.rs` → `ReplayVerifyCoordinator` → `chunk_executor`'s `verify_execution`) would report success even though the authenticated state root does not match what local replay actually computed. [6](#0-5) [7](#0-6) 

This is a real, currently-shipped gap acknowledged directly in the code by the author (`TODO(trading-native): ... so replay-verify tooling (e.g. db-tool's replay_on_archive) can report a successful replay even when the authenticated position state root diverges from local execution`), not a hypothetical.

### Impact Explanation
Replay-verify and the CLI transaction-replay/debugger paths are the primary tools operators and auditors use to confirm that historical ledger data — restored from backups or fetched via full-node/API — actually reflects correct VM execution, and to detect storage/executor bugs or non-determinism ("hard forks") after the fact. Because the comparator silently ignores state-checkpoint, hot-state, and position-state roots, a state-root-corrupting bug in the executor or storage layer (independent of write-set/event content) would not be caught: `replay-verify` and the CLI replay comparison would both report success ("ReplayVerify coordinator succeeded") on data whose committed state root actually diverges from correct execution. This directly matches the in-scope impact "Hard-fork-only divergence during commit, replay, restore, or proof verification" and "Authenticated API or state-view output bound to the wrong version, object, or proof context" — an operator or auditor relying on replay-verify's PASS result would have false assurance about ledger correctness, and a genuine state divergence (e.g., from a subtle Merkle-tree bug elsewhere) could go undetected in production audits/backups.

### Likelihood Explanation
The gap is unconditional and always present in the current comparator — it doesn't depend on a feature flag or rare interleaving; every call to `ensure_match_transaction_info()` (in chunk replay verification, CLI replay, and debugger diff printing) skips these three fields. The trigger for actual harm requires a separate root-cause bug that corrupts the state/hot-state/position-state root while leaving per-transaction write-set/event hashes intact (e.g., a bug in cross-transaction state-checkpoint aggregation or hot-state materialization), which is plausible given the comment explicitly flags this as a known, live limitation tied to the upcoming `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/"trading-native" feature. Until that check is added, any latent state-checkpoint bug is systematically invisible to this verification path.

### Recommendation
Extend `ensure_match_transaction_info()` to compare the locally computed state-checkpoint hash (and, when present, `hot_state_checkpoint_hash`/`position_state_checkpoint_hash`) against the corresponding fields in `txn_info`, using the same `ensure!`-based hard failure pattern used for `state_change_hash` and `event_root_hash`, before any code path (replay-verify, CLI replay, debugger) is allowed to report success on TRANSACTION_INFO_V1 data. This should be done before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS` as the existing comment recommends, but the gap already exists for `state_checkpoint_hash` (V0) as well and should be fixed unconditionally.

### Proof of Concept
1. In `execution/executor/src/chunk_executor/mod.rs::verify_execution`, re-execute a chunk whose persisted `TransactionInfo` includes a `state_checkpoint_hash` produced from a corrupted/incorrect state root (simulating a hypothetical state-checkpoint bug) but with unchanged per-transaction write-set/events/gas/status.
2. Call `txn_out.ensure_match_transaction_info(version, txn_info, Some(write_set), Some(events))` as done at [8](#0-7)  — it returns `Ok(())` because only status/gas/write_set_hash/event_root_hash are compared, per [1](#0-0) .
3. `ReplayVerifyCoordinator::run()` completes without `ReplayError::TxnMismatch`, and `storage/db-tool/src/replay_verify.rs` prints "ReplayVerify coordinator succeeded" [9](#0-8)  despite the authenticated state root having diverged from local re-execution.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn assemble_transaction_infos(

        transaction_info_v1: bool,

        (0..to_commit.len())
            .into_par_iter()
            .with_min_len(optimal_min_len(to_commit.len(), 64))
            .map(|i| {
                let txn = &to_commit.transactions[i];
                let txn_output = &to_commit.transaction_outputs[i];
                let persisted_auxiliary_info = &to_commit.persisted_auxiliary_infos[i];
                // Use the auxiliary info hash directly from the persisted info

                    PersistedAuxiliaryInfo::V1 { .. } => {

                    },
                    PersistedAuxiliaryInfo::TimestampNotYetAssignedV1 { .. } => None,
                };
                let state_checkpoint_hash = state_checkpoint_hashes[i];
                let event_hashes = txn_output
                    .events()
                    .iter()
                    .map(CryptoHash::hash)
                    .collect::<Vec<_>>();
                let event_root_hash =
                    InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash();
                let write_set_hash = CryptoHash::hash(txn_output.write_set());
                let status = txn_output
                    .status()
                    .as_kept_status()
                    .expect("Already sorted.");
                let txn_info = if transaction_info_v1 {
                    TransactionInfo::builder_v1()
                        .transaction_hash(txn.committed_hash())
                        .state_change_hash(write_set_hash)
                        .event_root_hash(event_root_hash)
                        .maybe_state_checkpoint_hash(state_checkpoint_hash)
                        .maybe_hot_state_checkpoint_hash(
                            hot_state_checkpoint_hashes.and_then(|hot| hot[i]),
                        )
                        .gas_used(txn_output.gas_used())
                        .status(status)
                        .maybe_auxiliary_info_hash(auxiliary_info_hash)
                        .maybe_position_state_checkpoint_hash(
                            position_state_checkpoint_hashes.and_then(|p| p[i]),
                        )
                        .build()
                } else {
                    TransactionInfo::builder_v0()
                        .transaction_hash(txn.committed_hash())
                        .state_change_hash(write_set_hash)
                        .event_root_hash(event_root_hash)
                        .maybe_state_checkpoint_hash(state_checkpoint_hash)
                        .gas_used(txn_output.gas_used())
                        .status(status)
                        .maybe_auxiliary_info_hash(auxiliary_info_hash)
                        .build()
                };
                let txn_info_hash = txn_info.hash();
                (txn_info, txn_info_hash)
            })
            .unzip()
    }

    fn verify_execution(
        &self,
        transactions: &[Transaction],
        persisted_aux_info: &[PersistedAuxiliaryInfo],
        transaction_infos: &[TransactionInfo],
        write_sets: &[WriteSet],
        event_vecs: &[Vec<ContractEvent>],
        begin_version: Version,
        end_version: Version,
        verify_execution_mode: &VerifyExecutionMode,
    ) -> Result<Version> {
        // Execute transactions.
        let parent_state = self.commit_queue.lock().latest_state().clone();
        let state_view = self.state_view(parent_state.latest())?;
        let txns = transactions
            .iter()
            .take((end_version - begin_version) as usize)
            .cloned()
            .map(|t| t.into())
            .collect::<Vec<SignatureVerifiedTransaction>>();

        let auxiliary_info = persisted_aux_info
            .iter()
            .take((end_version - begin_version) as usize)
            .map(|persisted_aux_info| AuxiliaryInfo::new(*persisted_aux_info, None))
            .collect::<Vec<_>>();
        let onchain_config = chunk_onchain_config(&state_view)?;
        let execution_output = DoGetExecutionOutput::by_transaction_execution::<V>(
            &V::new(),
            txns.into(),
            auxiliary_info,
            &parent_state,
            state_view,
            onchain_config,
            TransactionSliceMetadata::chunk(begin_version, end_version),
        )?;
        // not `zip_eq`, deliberately
        for (version, txn_out, txn_info, write_set, events) in multizip((
            begin_version..end_version,
            &execution_output.to_commit.transaction_outputs,
            transaction_infos.iter(),
            write_sets.iter(),
            event_vecs.iter(),
        )) {
            if let Err(err) = txn_out.ensure_match_transaction_info(
                version,
                txn_info,
                Some(write_set),
                Some(events),
            ) {
                return if verify_execution_mode.is_lazy_quit() {
                    error!("(Not quitting right away.) {}", err);
                    verify_execution_mode.mark_seen_error();
                    Ok(version + 1)
                } else {
                    Err(err)
                };
            }
        }
        Ok(end_version)
    }
