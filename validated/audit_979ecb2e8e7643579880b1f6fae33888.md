### Title
Missing "class must be declared" check in Starknet OS `execute_replace_class` allows honest-node state divergence from the Blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Rust Blockifier's `replace_class` syscall handler explicitly requires the target class hash to be a declared class before updating a contract's class hash, but the Starknet OS's Cairo re-implementation of the same syscall (used for proof generation / OS re-execution) skips this check entirely, leaving a `TODO` in place of the validation.

### Finding Description
In the Blockifier (Rust), `replace_class` reads the compiled class before mutating state, which fails if the class hash was never declared: [1](#0-0) 

The Cairo1-native syscall handler forwards to the same base logic: [2](#0-1) 

However, the Starknet OS's own Cairo implementation of `execute_replace_class` (used during Starknet OS re-execution, which recomputes/attests the state transition for proving) contains an explicit `TODO` noting the missing declaration check, and unconditionally overwrites the contract's `class_hash` in `contract_state_changes` with the caller-supplied `class_hash`: [3](#0-2) 

The deprecated (Cairo0) OS syscall path has the same unguarded behavior: [4](#0-3) 

This is directly analogous to the reported bug class: a privileged/critical guard ("class must be declared") that exists in one code path (Blockifier) is missing in a parallel, reachable path (Starknet OS Cairo re-execution), which any account contract can invoke merely by calling `replace_class` with an arbitrary felt as `class_hash` — no special privilege is required, exactly like the unprotected `mintRebalancer`/`burnRebalancer` in the original report.

### Impact Explanation
Because the Blockifier rejects `replace_class` calls with undeclared class hashes (raising an "is not declared" error, as also verified in tests: `undeclared_class_hash`), but the Starknet OS accepts and applies them unconditionally, a transaction using this call pattern can succeed differently on the two computation paths: [5](#0-4) 

This causes a divergence between what the sequencer (Blockifier) actually executed/committed as the canonical block, and what the Starknet OS would recompute for that same block during proving/re-execution. The `class_hash` is part of the contract's leaf value in the state's Patricia commitment, so if the OS accepts an undeclared class hash that the Blockifier would have rejected, the OS-computed state commitment (used to attest the block for L1 proof settlement) diverges from the sequencer's actual, committed state root — an "honest-node divergence" / "wrong committed root" outcome per the impact criteria.

### Likelihood Explanation
Reachable by any account contract executing a normal transaction: any contract calling the `replace_class` syscall with an arbitrary (undeclared) felt as the class hash triggers this path in the Starknet OS re-execution, with no special permissions, deployer status, or privileged role required. The `TODO` comment in the source confirms this is a known, unaddressed gap rather than a hypothetical.

### Recommendation
Add the missing "class hash is declared" check in the Starknet OS's `execute_replace_class` (and the deprecated Cairo0 variant), mirroring the Blockifier's `syscall_handler.state.get_compiled_class(request.class_hash)?` check, before applying the new `class_hash` to `contract_state_changes`. This keeps the OS's semantics consistent with the Blockifier so that both computation paths reject the same invalid inputs.

### Proof of Concept
1. Deploy any Cairo1 contract that exposes a `test_replace_class`-like entry point calling the `replace_class` syscall with a caller-supplied `class_hash` argument (as in the existing test helper).
2. Submit an invoke transaction calling this entry point with an arbitrary/undeclared felt as `class_hash`.
3. In the Blockifier execution path, this call reverts/fails with "... is not declared" (see `undeclared_class_hash` test at `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
4. In the Starknet OS re-execution path (`syscall_impls.cairo:881-920` / `deprecated_execute_syscalls.cairo:307-329`), the same call is accepted and unconditionally writes the undeclared class hash into `contract_state_changes`, producing a different state entry (and therefore different Patricia leaf/commitment) than what the Blockifier committed.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
