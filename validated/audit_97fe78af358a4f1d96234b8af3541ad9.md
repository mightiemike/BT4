### Title
Starknet OS `replace_class` syscall omits declared-class validation, diverging from Blockifier's enforcement - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
Analogous to the OpenCTI GraphQL mutation that mutated/deleted an object without validating that the target was contextually related to the requested action, the Starknet OS's Cairo implementation of the `replace_class` syscall (used for Cairo1 contracts) and its deprecated equivalent (for Cairo0 contracts) update a contract's class hash without validating that the new class hash actually corresponds to a declared class. This is an explicit, acknowledged gap (`TODO(Yoni, 1/1/2026)`), while the Rust `blockifier` execution engine — which computes the same state transition during block building — does perform this validation and rejects the syscall with an "is not declared" error.

### Finding Description
The OS's `execute_replace_class` function directly overwrites the `class_hash` field of a contract's `StateEntry` using only the caller-supplied `class_hash`, with no check that this class hash has ever been declared: [1](#0-0) 

The comment at line 902 explicitly states the check is missing: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The same missing-check pattern exists in the deprecated (Cairo0) syscall path: [2](#0-1) 

By contrast, the Rust `blockifier` execution engine, which is what the sequencer actually uses to build and validate blocks (the source of truth for what state transition a transaction produces), explicitly performs a "class is declared" check before allowing `replace_class` to update state: [3](#0-2) 

This is confirmed by tests asserting the blockifier rejects replacement with an undeclared class hash with the error `"is not declared"`: [4](#0-3) [5](#0-4) 

The Starknet OS is a separate re-execution engine (a non-deterministic Cairo VM program) whose job is to independently execute the same contract bytecode and reproduce the block's state transition/commitment for proving purposes; the `starknet_os_flow_tests` framework exists specifically to verify OS output matches blockifier's ground truth. Since the OS's own Cairo syscall-handling logic for `replace_class` — not merely a replay of blockifier's precomputed results — omits the declared-class check, an honest contract that issues `replace_class_syscall(undeclared_class_hash)` can produce **different outcomes** in the two engines: the blockifier reverts the call (transaction fails, "is not declared"), while the OS's own execution would accept the class-hash overwrite unconditionally.

### Impact Explanation
This is a root-cause divergence between the two components that are both supposed to compute the canonical Starknet state transition:
- The Rust blockifier (used for mempool/block-building/RPC simulation) treats `replace_class(undeclared_hash)` as a reverting call.
- The Cairo Starknet OS (used to generate the STARK-provable execution and state commitment) accepts it and commits a `class_hash` for the contract that has no corresponding declared/compiled class.

This causes honest-node/component divergence in state computation for the same syscall input, and can result in a contract's class hash being unconditionally overwritten to an undeclared, non-existent class in the OS's committed state diff — which, if this path were exercised in production proving, would produce a wrong committed state root relative to what block-building's execution semantics guarantee, and would permanently render such a contract's code missing/broken (any subsequent call to the contract would fail against a class hash with no compiled class), a form of permanent bricking of the contract that is directly reachable by any account holder whose contract calls `replace_class_syscall` with an unchecked hash. Given the severity criteria (wrong committed root, honest-node divergence, unauthorized state modification), this qualifies as Medium/High depending on whether the divergence is provably reachable via the standard OS execution path used in consensus (this repo context does not let me confirm whether this OS Cairo program is currently the actively-used proving path in production versus still under active development given the "1/1/2026" TODO date, which introduces some uncertainty about current exploitability status).

### Likelihood Explanation
`replace_class_syscall` is a syscall available to any Cairo1/Cairo0 contract deployed by any user; no special privilege is required — any account or contract deployer can invoke it as part of an ordinary transaction. Triggering the divergence requires only calling `replace_class_syscall` with a class hash that has not been declared, which is a single, cheap, permissionless action. Because the TODO is explicit and un-remediated in the codebase, this indicates the check was consciously deferred rather than accidentally omitted, but it remains a live discrepancy between the two execution engines as of the current code state.

### Recommendation
Add the same "declared class" validation to the OS's `execute_replace_class` in both `syscall_impls.cairo` (Cairo1 path) and `deprecated_execute_syscalls.cairo` (Cairo0 path) that the blockifier already performs — i.e., before updating `contract_state_changes` with the new `class_hash`, assert (via a hint reading `contract_class_changes`/declared classes) that the target class hash has a corresponding declared/compiled class in the current state, and fail/revert consistently with the blockifier's `"is not declared"` semantics (including the Cairo0-vs-Cairo1 "cannot replace V1 with V0" rule enforced in `crates/blockifier/src/execution/syscalls/hint_processor.rs`). Extend `starknet_os_flow_tests` with a negative-flow scenario ("replace class to undeclared hash") to lock in identical behavior between blockifier and the OS.

### Proof of Concept
1. Deploy a Cairo1 contract that calls `replace_class_syscall(class_hash)` with an attacker-chosen, arbitrary `class_hash` that has never been declared on-chain.
2. In blockifier-based block building/simulation, this call reverts with `"... is not declared"` (see test at `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
3. In the Starknet OS's own Cairo re-execution of the identical syscall (`execute_replace_class` in `syscall_impls.cairo:881-920`), no declared-class check exists; the `StateEntry.class_hash` for the calling contract is unconditionally overwritten with the undeclared hash and recorded in `contract_state_changes`.
4. This constitutes a state-transition divergence between the two engines for the identical transaction/syscall input, and (if reached via the OS's production proving path) results in a committed state entry referencing a non-existent contract class, permanently bricking calls into that contract address. // Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
