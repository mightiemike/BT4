### Title
Gasless `MsgExecutePayload` allows unlimited free EVM re-execution when `DeductGasFeesFromReceipt` fails after `CallUEAExecutePayload` succeeds - (File: `x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`Keeper.ExecutePayload` (the non-cached, `MsgExecutePayload` path, as opposed to `ExecutePayloadV2`) executes the UEA payload directly against `sdkCtx` and only afterwards attempts fee deduction. If `DeductGasFeesFromReceipt` fails, the handler returns an error, which reverts the whole Cosmos tx (including the EVM state produced by `CallUEAExecutePayload`). Crucially, `MsgExecutePayload` is registered as a gasless message type in `app/txpolicy/gasless.go`, so the attacker pays no Cosmos-level tx fee for this resubmission, while the node still performs the full EVM execution cost of `CallUEAExecutePayload` before the fee-deduction failure is discovered.

### Finding Description [1](#0-0) 
runs `CallUEAExecutePayload` directly on `sdkCtx` (not a `CacheContext` as in `ExecutePayloadV2`, see [2](#0-1) 
), then calls [3](#0-2) 
to deduct fees from the UEA's balance. If the UEA balance is insufficient to cover `gasCost`, `DeductAndBurnFees` fails and the handler returns `"gas fee deduction failed: %w"`, causing the entire Cosmos tx to roll back.

`MsgExecutePayload` is explicitly listed as an allowed gasless message type: [4](#0-3) 
meaning the standard Cosmos SDK ante fee deduction is bypassed for this message. Since the tx is gasless, an attacker whose UEA is already deployed (a prerequisite reachable by any unprivileged user, per [5](#0-4) 
) can repeatedly submit payloads that succeed in `CallUEAExecutePayload` (real EVM computation, gas-metered) but then fail `DeductGasFeesFromReceipt` (e.g., by draining the UEA's PC balance to below the computed `gasCost`). Each resubmission forces the node to fully re-execute the EVM call before discovering the fee failure and rolling everything back — at zero Cosmos-level fee cost to the attacker.

### Impact Explanation
This constitutes a non-network-level, unprivileged-reachable denial-of-service vector: repeated free EVM execution work can be forced onto validating nodes without a per-account cost or throttle in the scoped gasless/ante logic reviewed. Over sustained resubmission, this degrades block-processing throughput and wastes validator EVM execution capacity, without producing any material fund loss but materially harming liveness/throughput, which fits the "denial of service only when it is not network-level and is reachable without privileged control" in-scope category.

### Likelihood Explanation
Likelihood is moderate: the attacker needs a deployed UEA (achievable through ordinary, unprivileged use — deploy then drain its balance), then can freely resubmit `MsgExecutePayload` transactions that are gasless per `app/txpolicy/gasless.go`. I was not able to fully verify, within the available tool budget, whether `app/ante/fee.go` or `app/ante/account_init_decorator.go` impose any additional per-account/gas-based throttle specifically on gasless `MsgExecutePayload` submissions (e.g., mempool-level minimum gas price still applies via `app/cosmos/min_gas_price.go`, and CheckTx/block gas limits bound the practical batch size per block, but I could not confirm any per-account rate limiting across blocks). This uncertainty should be resolved before treating severity as final.

### Recommendation
Mirror the `ExecutePayloadV2` cache-context pattern in the `ExecutePayload` (`MsgExecutePayload`) path so that fee-deduction failure is detected as cheaply as possible, and additionally consider excluding `MsgExecutePayload` from the gasless allow-list (or adding a minimum-fee/bond requirement or per-account throttling for gasless resubmission) so failed fee deduction cannot be repeated indefinitely at zero cost.

### Proof of Concept
1. Deploy a UEA via a legitimate `MsgExecutePayload`/`DeployUEAV2` call, funding it with just enough PC to cover one execution's `gasCost`.
2. Execute a payload that succeeds in `CallUEAExecutePayload`, consuming the UEA's balance to below the `gasCost` threshold for a subsequent call (or directly drain it via a transfer inside the payload).
3. Resubmit the same/similar payload as a gasless `MsgExecutePayload` transaction (no other messages in the tx, so `IsGaslessTx` returns true). Each time, `CallUEAExecutePayload` runs to completion (full EVM cost) and `DeductGasFeesFromReceipt` fails with "insufficient gas", rolling back the tx.
4. Repeat step 3 arbitrarily many times across blocks; assert (in a Go test) that the cumulative EVM gas/computation performed grows unboundedly while the attacker's on-chain fee payment remains zero, demonstrating unmetered resubmission cost imposed on the network.

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```
