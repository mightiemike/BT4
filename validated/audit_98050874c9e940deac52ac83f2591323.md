### Title
Missing class-hash validation in `replace_class` syscall handling within the Starknet OS Cairo program causes divergence from the sequencer's blockifier execution - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS's Cairo re-execution implementation of the `replace_class` syscall never verifies that the target `class_hash` is a declared class (nor that it is a Cairo1 class), unlike the sequencer's Rust `blockifier` implementation, which enforces both checks. This lets a contract, in the untrusted proving re-execution path, be "replaced" with an undeclared/zero/garbage class hash - the exact bug class of the referenced report ("can set a critical target field to an invalid/zero value without validation"), applied here to a contract's own class hash rather than a position recipient.

### Finding Description
Any Cairo1 contract can invoke the `replace_class_syscall` to change its own `class_hash`. In the sequencer's actual execution engine (`blockifier`), this is guarded: [1](#0-0) 

The handler explicitly reads the compiled class (which fails if it was never declared) and rejects Cairo0 classes with `ForbiddenClassReplacement`.

However, the Starknet OS's own Cairo implementation of the same syscall - used for re-executing (proving) the block - performs neither check. It reads the requested `class_hash` straight from the syscall request and unconditionally writes it into the contract's state entry: [2](#0-1) 

Note the explicit acknowledgment of the missing check in the code itself: [3](#0-2) 

The same unguarded pattern exists in the deprecated (Cairo0) syscall execution path: [4](#0-3) 

Because `blockifier` and the Starknet OS are supposed to compute *identical* state transitions for the same transaction (the OS re-executes the block to produce the validity proof committed on L1), any place where one implementation is stricter than the other is a correctness hazard: a transaction that `blockifier` reverts (due to `ForbiddenClassReplacement` or an undeclared-class error) is a transaction the OS would happily apply, producing a different post-state (and therefore a different state root/block hash) than what the sequencer actually committed.

### Impact Explanation
This is a state-transition-function divergence between the sequencer's execution engine and the Starknet OS's proving re-execution, directly analogous to the reported bug class (a mutation entry point that fails to validate its target before committing an unrecoverable change). Consequences include:
- A contract could be "replaced" to an undeclared/zero class hash inside the OS's version of the state, permanently bricking that contract (loss of ability to interact with it, i.e., permanent freezing of any funds/logic it holds) - matching the "stuck assets" impact of the original finding.
- More broadly, since the OS is the authoritative state-transition function for proof generation, any divergence from blockifier's semantics can produce a wrong committed state root/block hash relative to what the sequencer's execution actually enforced, i.e., an honest-node divergence between the execution layer and the proving layer.

### Likelihood Explanation
Reachable by any unprivileged Cairo1 contract call: invoking `replace_class_syscall` with an arbitrary (including zero/undeclared) `class_hash` is a normal, permissionless external call requiring no special privileges, only a standard invoke transaction targeting a contract that calls the syscall.

### Recommendation
Add the same validation present in `blockifier`'s `replace_class` (`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`) to the Cairo OS implementations in `syscall_impls.cairo::execute_replace_class` and `deprecated_execute_syscalls.cairo::execute_replace_class`: verify the requested `class_hash` corresponds to a declared class (and reject Cairo0 replacement targets for Cairo1 contracts) before committing the state update, removing the outstanding TODO and closing the semantic gap between the two execution engines.

### Proof of Concept
1. Deploy a Cairo1 contract exposing a function that calls `replace_class_syscall(class_hash)` with an attacker-supplied `class_hash` (e.g., `crates/blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo:513-516` shows the pattern already present in test fixtures: `syscalls::replace_class_syscall(class_hash).unwrap_syscall();`).
2. Invoke it with `class_hash = 0` (or any hash that was never declared).
3. In `blockifier`, `self.state.get_compiled_class(class_hash)` fails, causing the syscall (and typically the call) to error out - the transaction is rejected/reverted by the sequencer.
4. When the same transaction/calldata is re-executed by the Starknet OS Cairo program (`execute_replace_class` in `syscall_impls.cairo`), no equivalent check exists, so the state entry's `class_hash` is unconditionally overwritten with the attacker-supplied value, producing a different final state than the one the sequencer actually committed.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
