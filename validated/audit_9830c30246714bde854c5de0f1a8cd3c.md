## Analysis

The DYAD bug pattern — a "move everything back" function that special-cases one asset type and silently omits another, leaving that specific asset's holder either short (liquidator) or with un-recovered funds (liquidated position) — has a direct analog in `x/uexecutor`'s outbound-failure handling path.

### Title
Failed `GAS`-type outbounds never re-mint the burned PRC20/gas-token amount, permanently losing user funds - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
`handleFailedOutbound` re-mints the bridged PRC20 amount back to the sender only for `TxType_FUNDS`, `TxType_GAS_AND_PAYLOAD`, and `TxType_FUNDS_AND_PAYLOAD` outbounds. It does not do so for `TxType_GAS` outbounds, even though the `README` explicitly documents `GAS` outbound semantics as "Refund of unused gas back to a source chain" — i.e., a value-bearing outbound, not a no-op like `PAYLOAD`.

### Finding Description
`BuildOutboundsFromReceipt` (`x/uexecutor/keeper/create_outbound.go:69-91`) decodes every `UniversalTxOutbound` event uniformly and always populates `Amount`, `Prc20AssetAddr`, `GasFee`, etc., regardless of the decoded `TxType`. There is no branch that zeroes out `Amount`/`Prc20AssetAddr` for `TxType_GAS`. [1](#0-0) 

Per the module's own documentation, the `GAS` `TxType` on the outbound side means "Refund of unused gas back to a source chain" — a genuine value-transfer, not a pure signal. [2](#0-1) 

When Universal Validators (honestly) vote that this outbound's broadcast on the destination chain failed via `MsgVoteOutbound`, `FinalizeOutbound` routes to `handleFailedOutbound`: [3](#0-2) 

`handleFailedOutbound` re-mints (via `CallPRC20Deposit`) the bridged amount back to the revert recipient **only** if `outbound.TxType` is `FUNDS`, `GAS_AND_PAYLOAD`, or `FUNDS_AND_PAYLOAD`: [4](#0-3) 

`TxType_GAS` is excluded from this list. If a `GAS`-type outbound fails, the function skips straight to marking the outbound `REVERTED` and only attempts the unrelated excess-gas-fee refund (`applyGasRefund`, which is keyed on `GasFee`/`GasFeeUsed`, not `Amount`): [5](#0-4) 

This is structurally identical to the DYAD `VaultManagerV2::liquidate` bug: a function meant to "return all the value that was locked/burned" enumerates specific asset/type categories and omits one, silently dropping that category's value on the floor while marking the operation complete (`Status_REVERTED` / fully-liquidated, respectively).

By contrast, `RESCUE_FUNDS` is deliberately excluded from re-minting, and this is verified by an explicit test asserting "no PC-side revert (no funds locked on PC)" for that type, because rescue only fires after a deposit already failed (no PRC20 was ever minted/burned on PC for that flow). [6](#0-5) 

No equivalent test or code comment establishes that `TxType_GAS` outbounds carry zero `Amount`/no burned backing — the README explicitly states the opposite (it's a "refund" of value). I could not locate the Solidity-side `UniversalGatewayPC.withdraw`/burn logic (out of the indexed Go code) to conclusively confirm the exact on-chain burn semantics for `GAS` outbounds; this is a limitation of what I could verify from the indexed repository content. Based on the documented `TxType` semantics and the uniform `Amount`/`Prc20AssetAddr` population in `BuildOutboundsFromReceipt`, the omission of `TxType_GAS` from the re-mint condition appears to be the same class of oversight as the DYAD finding.

### Impact Explanation
If confirmed, a normal (unprivileged) user whose `GAS`-outbound (gas top-up refund to a source chain) fails to broadcast — a routine, non-malicious occurrence (e.g., destination-chain congestion, RPC failure, insufficient relayer gas) reachable purely through honest UV voting — would have the PRC20/native-gas-token amount underlying that outbound permanently burned/lost with no re-mint path, and the `UniversalTx` record would show `Status_REVERTED` with `PcRevertExecution == nil`, giving no on-chain accounting trail to recover the funds. This matches the "permanent loss ... of user ... funds" and "corruption of ... refund accounting" impact categories in scope.

### Likelihood Explanation
Triggering this requires only an ordinary `GAS`-type outbound (created from normal user gas-refund flow) and an honest-majority `MsgVoteOutbound` reporting failure — both are default, unprivileged, expected occurrences (destination-chain transient failures happen regularly), so likelihood is non-trivial whenever `GAS` outbounds are actually used in production with non-zero `Amount`.

### Recommendation
Extend the funds re-mint condition in `handleFailedOutbound` to also cover `types.TxType_GAS` (and re-audit whether any other `TxType` value carries burned/locked value on the outbound side but is excluded from this branch), so that every value-bearing `TxType` is re-minted back to the sender/fund-recipient on outbound failure, consistent with `FUNDS`/`GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` handling.

### Proof of Concept
Conceptual reproduction (cannot be fully executed without the on-chain gateway contract's exact burn semantics for `GAS`-type withdrawals, which sit outside the indexed Go code):
1. Trigger a user flow that creates a `GAS`-type outbound with non-zero `Amount`/`Prc20AssetAddr` via `BuildOutboundsFromReceipt` (decoded from a `UniversalTxOutbound` event with `tx_type = 0`).
2. Have the honest UV set vote `MsgVoteOutbound` with `success = false` for this outbound, reaching quorum.
3. Observe `FinalizeOutbound` → `handleFailedOutbound`: since `outbound.TxType == TxType_GAS`, the `CallPRC20Deposit` re-mint branch is skipped entirely.
4. Assert the outbound ends in `Status_REVERTED` with `PcRevertExecution == nil` and no PRC20 balance restored to `outbound.Sender`/`RevertInstructions.FundRecipient`, while the original amount was already burned/locked when the outbound was created — permanent loss. [7](#0-6)

func (k Keeper) FinalizeOutbound(ctx context.Context, utxId string, outbound types.OutboundTx) error {
	// If not observed yet, do nothing
	if outbound.OutboundStatus != types.Status_OBSERVED {
		return nil
	}

	obs := outbound.ObservedTx
	if obs == nil {
		return nil
	}

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Info("finalizing outbound",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"success", obs.Success,
		"dest_chain", outbound.DestinationChain,
		"tx_type", outbound.TxType.String(),
	)

	if !obs.Success {
		return k.handleFailedOutbound(sdkCtx, utxId, outbound, obs)
	}

	return k.handleSuccessfulOutbound(sdkCtx, utxId, outbound, obs)
}

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}
