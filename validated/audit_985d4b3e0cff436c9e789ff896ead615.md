Confirmed: there is no retry/rescue message handler for a failed `PcRefundExecution` — once `applyGasRefund` records `Status="FAILED"`, that outbound's excess gas fee is permanently stranded with no on-chain recovery path. [1](#0-0) 

### Title
Permanently unrecoverable excess-gas-fee refund on `applyGasRefund` failure - (File: x/uexecutor/keeper/outbound.go)

### Summary
`applyGasRefund` computes the excess gas fee owed back to a user (`gasFee - gasFeeUsed`) after an outbound is observed, and attempts to return it via two `CallUniversalCoreRefundUnusedGas` EVM calls (swap-refund, then no-swap fallback). If both calls fail, the function records `PcRefundExecution.Status = "FAILED"` and `RefundSwapError`, then simply returns — the excess amount is never reimbursed and there is no retry, queue, or rescue message to recover it later. This mirrors the M-8 report's pattern of a fee-loss value being recorded in state bookkeeping without any mechanism to actually pay it back to the party owed it.

### Finding Description
When an outbound is voted OBSERVED by Universal Validators, `handleSuccessfulOutbound`/`handleFailedOutbound` call `applyGasRefund` [2](#0-1) . The function computes `refundAmount := gasFee - gasFeeUsed` when `gasFee > gasFeeUsed` [3](#0-2) , and attempts to send that amount to the sender/fund_recipient first via a swap-back leg, then via a direct PRC20-deposit fallback [4](#0-3) . If both the swap call and the no-swap fallback (`CallUniversalCoreRefundUnusedGas`) fail, the code path only sets `refundPcTx.Status = "FAILED"` and `outbound.RefundSwapError`, and stores that on the outbound record before returning [5](#0-4) . There is no subsequent module message (e.g. a `MsgRetryRefund`), background job, or `PendingOutbounds`-style re-queue mechanism that revisits a `FAILED` `PcRefundExecution` and attempts the refund again — a grep across the module for retry/rescue message handlers for this state turns up nothing.

The no-swap fallback path passes `fee=0, minPCOut=0` to `refundUnusedGas`, which usually avoids the slippage-based revert that could break the swap leg, but the fallback can still fail for legitimate reasons scoped entirely to the destination gas token/PRC20 (e.g. minted supply/allowance edge cases in the PRC20 or handler contract, an intentionally malicious/broken PRC20 the sender routes through as the destination gas token, or any other EVM-level revert in `UniversalCore.refundUnusedGas`). Because `applyGasRefund` runs during ordinary `MsgVoteOutbound` finalization triggered by honest validators reporting on an unprivileged user's own outbound, the loss is reachable purely through normal usage/misconfiguration of the destination gas token by the transacting user — no privileged actor is required to trigger the failure branch.

### Impact Explanation
Once both refund legs fail, the excess gas fee entitled to the user is permanently lost: it is neither retried, nor queued, nor exposed through any other keeper/message path that could re-attempt delivery. This is a permanent loss of protocol-owed/user-owed funds with no recovery mechanism, matching the "permanent loss ... of user or protocol-controlled funds" allowed-impact category.

### Likelihood Explanation
`gasFee > gasFeeUsed` is the common case for outbound transactions (the gateway pre-allocates a gas budget that is rarely fully consumed), so `applyGasRefund` executes routinely. The failure branch only requires the destination gas token/PRC20 or `UniversalCore.refundUnusedGas` handler to revert on both the swap and no-swap paths for a given refund — plausible for edge-case token configurations, dust amounts, or any transient EVM-level revert — after which the loss is unconditional and irreversible for that outbound.

### Recommendation
Persist failed refund attempts (e.g., in a dedicated pending-refund collection keyed by outbound ID) instead of only recording a terminal `FAILED` status, and add either an automatic retry path (triggered on a later block or by a subsequent vote/message) or a permissioned-but-observable rescue message that lets the rightful recipient reclaim the still-owed excess gas fee, analogous to the existing `RESCUE_FUNDS` outbound flow already used for stuck deposits.

### Proof of Concept
1. A user submits an inbound/outbound flow (e.g. `FUNDS_AND_PAYLOAD`) that results in `outbound.GasFee` being set higher than what is actually consumed on the destination chain (the normal case, per `outbound.GasFee` vs `obs.GasFeeUsed` in `test/integration/uexecutor/gas_fee_refund_test.go`).
2. Universal Validators vote `MsgVoteOutbound` with `gas_fee_used < gas_fee`, triggering `applyGasRefund` [6](#0-5) .
3. The destination `GasToken`/PRC20 or `UniversalCore.refundUnusedGas` is configured/behaves such that both the swap-refund call and the no-swap fallback call revert (e.g. as exercised by the "swap fallback reason stored when swap refund fails" test case) [7](#0-6) .
4. `outbound.PcRefundExecution.Status` becomes `"FAILED"` and `outbound.RefundSwapError` is set [5](#0-4) ; the UTX is finalized in this state with no further code path anywhere in the module ever revisiting or retrying this refund, permanently stranding the excess gas fee owed to the user.

// handleSuccessfulOutbound refunds unused gas fee when gasFee > gasFeeUsed.
func (k Keeper) handleSuccessfulOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	k.Logger().Info("outbound completed successfully",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"dest_chain", outbound.DestinationChain,
	)
	k.applyGasRefund(ctx, &outbound, obs)
	return k.UpdateOutbound(ctx, utxId, outbound)
}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
