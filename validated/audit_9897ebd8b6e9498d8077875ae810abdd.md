### Title
Unbounded goroutine/HTTP-client spawning per on-chain OracleRequest allows resource-exhaustion DoS of Functions EA pipeline - ([File: core/services/functions/listener.go], [File: core/services/functions/external_adapter_client.go])

### Summary
`functionsListener.processOracleEventsV1` spawns one unbounded goroutine per `OracleRequest` log returned by `LatestEvents` with no concurrency cap, each of which eventually calls `externalAdapterClient.request`, which itself creates a brand-new `retryablehttp.NewClient()` (with its own `http.Transport`/connection pool) per request. An unprivileged caller who can submit many cheap `OracleRequest` events (via a self-funded Functions subscription) can drive the node to open unbounded concurrent goroutines and outbound HTTP connections to the bridge, degrading or stalling the EA/OCR pipeline.

### Finding Description
`processOracleEventsV1` polls `l.logPollerWrapper.LatestEvents(ctx)` on a ticker and, for every request returned, unconditionally does `l.shutdownWaitGroup.Add(1); go l.handleOracleRequestV1(&request)` with no batch size cap, no semaphore, and no per-subscription/global concurrency limit: [1](#0-0) 

`handleOracleRequestV1` runs `CreateRequest`, parses the CBOR payload, and calls `l.handleRequest(...)`, which ultimately calls `bridgeAccessor.NewExternalAdapterClient` and `eaClient.RunComputation`: [2](#0-1) 

Inside `externalAdapterClient.request`, every single call constructs a fresh `retryablehttp.NewClient()` (with its own default `RoundTripper`/connection pool, not shared or pooled across calls) configured with `RetryMax`/`RetryWaitMin`, then issues the HTTP POST: [3](#0-2) 

There is no rate limiter, request queue, or worker-pool bound anywhere in this on-chain-event-to-bridge path. The only `RateLimiter` config field in `PluginConfig` (`pluginConfig.RateLimiter`) is used exclusively for the optional off-chain Gateway connector path (`OnchainAllowlist`/`RateLimiter`/`OnchainSubscriptions` gating), not for the on-chain `OracleRequest` log-driven path: [4](#0-3)  and the config struct shows `RateLimiter` scoped only to gateway usage: [5](#0-4) 

Because subscription/gas cost is the only economic friction, and no node-side rate limiting or goroutine-pool bound exists, an attacker who can fund a Functions subscription with a small amount of LINK (no operator privilege) and submit many low-value requests to a deployed `FunctionsConsumer` can force the node to spawn goroutines and outbound HTTP connections proportional to attacker-controlled on-chain volume.

### Impact Explanation
This matches "Denial of service of specific node function(s)" impact: the EA client / OCR reporting pipeline for Functions requests can be stalled or degraded through goroutine/file-descriptor/connection exhaustion driven purely by untrusted on-chain input volume, with no per-tick/per-subscription bound in `processOracleEventsV1` or `externalAdapterClient.request`.

### Likelihood Explanation
Feasible and repeatable: the attacker needs no operator/admin privilege, only the ability to fund and call a public `FunctionsConsumer` request function (creating/funding a subscription costs gas + minimal LINK, but is otherwise unrestricted). Each request reliably triggers exactly one unbounded goroutine plus a dedicated HTTP client/connection in `externalAdapterClient.request`, so the attack scales linearly and repeatably with request volume; no existing check throttles it before goroutines/HTTP clients are created.

### Recommendation
- Bound concurrency in `processOracleEventsV1` (e.g., a fixed-size worker pool or semaphore limiting concurrent `handleOracleRequestV1` invocations per tick and in aggregate).
- Reuse a single shared, pre-configured `retryablehttp.Client`/`http.Client` (with bounded max idle/active connections) in `externalAdapterClient` instead of constructing `retryablehttp.NewClient()` per request.
- Add a per-subscription and/or global rate limiter (reusing the existing `ratelimit.RateLimiter` used for the gateway path) in front of `handleOracleRequestV1`/`handleRequest` for the on-chain `OracleRequest` path as well.
- Cap the number of requests processed per `LatestEvents` poll cycle and queue the excess instead of spawning unbounded goroutines immediately.

### Proof of Concept
Integration test plan (extending `core/services/functions/listener_test.go` patterns):
1. Build a `FunctionsListenerUniverse` as in `NewFunctionsListenerUniverse`.
2. Mock `logPollerWrapper.On("LatestEvents", ...)` to return several thousand synthetic `evmconfig.OracleRequest` entries with distinct `RequestId`s in a single call.
3. Mock `bridgeAccessor.NewExternalAdapterClient` and `eaClient.RunComputation` to block on a channel/slow response (simulating a slow bridge) to keep goroutines alive.
4. Start `uni.service` and record `runtime.NumGoroutine()` before/during the flood, and count concurrent invocations of `NewExternalAdapterClient`/`RunComputation` via the mock's call count.
5. Assert that goroutine count and concurrent adapter-client instantiations grow unbounded/linearly with the injected event count rather than being capped by a fixed worker limit — demonstrating the missing bound described in `processOracleEventsV1` and `externalAdapterClient.request`.

func (l *functionsListener) handleOracleRequestV1(request *evmconfig.OracleRequest) {
	defer l.shutdownWaitGroup.Done()
	l.logger.Infow("handleOracleRequestV1: oracle request v1 received", "requestID", formatRequestId(request.RequestId))
	ctx, cancel := l.getNewHandlerContext()
	defer cancel()

	callbackGasLimit := uint32(request.CallbackGasLimit)
	newReq := &Request{
		RequestID:                  request.RequestId,
		RequestTxHash:              &request.TxHash,
		ReceivedAt:                 time.Now(),
		Flags:                      request.Flags[:],
		CallbackGasLimit:           &callbackGasLimit,
		CoordinatorContractAddress: &request.CoordinatorContract,
		OnchainMetadata:            request.OnchainMetadata,
	}
	if err := l.pluginORM.CreateRequest(ctx, newReq); err != nil {
		if errors.Is(err, ErrDuplicateRequestID) {
			l.logger.Warnw("handleOracleRequestV1: received a log with duplicate request ID", "requestID", formatRequestId(request.RequestId), "err", err)
		} else {
			l.logger.Errorw("handleOracleRequestV1: failed to create a DB entry for new request", "requestID", formatRequestId(request.RequestId), "err", err)
		}
		return
	}

	promRequestReceived.WithLabelValues(l.contractAddressHex).Inc()
	promRequestDataSize.WithLabelValues(l.contractAddressHex).Observe(float64(len(request.Data)))
	requestData, err := l.parseCBOR(request.RequestId, request.Data, l.getMaxCBORsize(request.Flags))
	if err != nil {
		l.setError(ctx, request.RequestId, USER_ERROR, []byte(err.Error()))
		return
	}
	err = l.handleRequest(ctx, request.RequestId, request.SubscriptionId, request.SubscriptionOwner, request.Flags, requestData)
	if err != nil {
		l.logger.Errorw("handleOracleRequestV1: error in handleRequest()", "requestID", formatRequestId(request.RequestId), "err", err)
	}
}
