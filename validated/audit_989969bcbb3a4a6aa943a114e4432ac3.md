### Title
Webhook HMAC covers only the request body, letting a single merchant forge the `X-Shopify-Shop-Domain`/topic headers to impersonate another shop's webhook - ([File: packages/apps/shopify-api/lib/webhooks/validate.ts])

### Summary
Webhook validation in `shopify-api` computes and checks the HMAC exclusively over `rawBody`, and separately/independently reads `domain`, `topic`, `webhookId`, and `apiVersion` straight from unauthenticated request headers with no cryptographic binding between them and the signature.

### Finding Description
`validateHmacFromRequestFactory` in `packages/apps/shopify-api/lib/utils/hmac-validator.ts` validates a webhook purely by comparing the `X-Shopify-Hmac-Sha256` header against `HMAC(apiSecretKey, rawBody)`: [1](#0-0) 

`validateFactory` in `packages/apps/shopify-api/lib/webhooks/validate.ts` then, once that body-only HMAC succeeds, pulls `domain`, `topic`, `apiVersion`, `webhookId` from headers with `checkWebhooksHeaders`/`getRequiredHeader`, without any HMAC coverage of those fields: [2](#0-1) [3](#0-2) 

Downstream, `authenticateWebhookFactory` (Remix/React-Router adapters) trusts `check.domain` at face value to load the offline session and build an authenticated admin client for that shop: [4](#0-3) 

`ensureValidOfflineSession` looks up/creates the session purely by the `shop` string it is given — there is no secondary check that this shop is the one that actually produced the signed body: [5](#0-4) 

Because `apiSecretKey` is shared by the app across every installing shop, any single merchant who has installed the app can capture one legitimate `(rawBody, hmac)` pair delivered to their own store's webhook and replay it to the app's shared `/webhooks` endpoint while freely rewriting `X-Shopify-Shop-Domain`, `X-Shopify-Topic`, and `X-Shopify-Webhook-Id` to name a different, victim shop. The HMAC still validates because it never covered those headers, so the app processes attacker-chosen data/topic combinations under a victim shop's identity/session.

### Impact Explanation
An attacker who is themselves an installed merchant (unprivileged relative to other tenants) can forge cross-tenant webhook deliveries for any other shop that has the same app installed, as long as they know/guess the victim's `myshopify.com` domain (which is generally public/guessable). Depending on which topic + registered handler is targeted, this enables: forced state changes on a victim's install (e.g., replaying a captured body while claiming topic `app/uninstalled` to trigger the app's uninstall cleanup/session teardown for the victim, a cross-tenant DoS), or feeding attacker-controlled payload data into handlers that act on `webhookCheck.domain`/`shop_domain` and the admin client scoped to the victim's access token, corrupting per-shop application state that isn't the attacker's own.

### Likelihood Explanation
Requires only (1) installing the app on one's own store to legitimately receive at least one real webhook, and (2) sending a crafted HTTP POST to the public webhook endpoint with rewritten headers — no secrets, no privileged role, and no session compromise are needed. This is a low-effort, unauthenticated-endpoint-facing attack path.

### Recommendation
Bind the trusted request metadata to the signature, or otherwise cross-validate it before acting: e.g., independently verify (via the Admin API or existing session storage) that the offline session for `check.domain` corresponds to a shop for which this specific `webhookId`/body was actually registered, reject topic/domain combinations that don't match what Shopify's delivery log would show for that HMAC, or maintain a per-shop nonce/webhook-id replay cache keyed to prevent cross-shop header substitution on an otherwise-valid signature.

### Proof of Concept
1. Install the target app on shop `attacker.myshopify.com`; wait for/trigger a webhook (e.g. `products/create`) and capture its raw POST body `B` and its `X-Shopify-Hmac-Sha256` header `H` (valid because `H = HMAC(apiSecretKey, B)`).
2. Send a new POST to the app's public `/webhooks` endpoint with body `B`, header `X-Shopify-Hmac-Sha256: H` (unchanged, still valid since HMAC covers only `B`), but `X-Shopify-Shop-Domain: victim.myshopify.com` and `X-Shopify-Topic: app/uninstalled` (or another topic with a registered handler).
3. `validateHmacFromRequestFactory` accepts the HMAC (matches body `B`); `checkWebhooksHeaders` accepts the forged `domain`/`topic` headers; `authenticateWebhookFactory` loads `victim.myshopify.com`'s offline session via `ensureValidOfflineSession` and invokes the registered handler as if the request genuinely originated from the victim shop. export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };
}

export function validateFactory(config: ConfigInterface) {

    rawBody,
    ...adapterArgs
  }: WebhookValidateParams): Promise<WebhookValidation> {
    const request: NormalizedRequest =
      await abstractConvertRequest(adapterArgs);

      return validHmacResult;
    }

function checkWebhooksHeaders(
  headers: Headers,
): WebhookValidationMissingHeaders | WebhookValidationValid {
  const headerNames = WEBHOOK_HEADER_NAMES[WebhookType.Webhooks];
  const missingHeaders: string[] = [];

  const hmac = getRequiredHeader(headers, headerNames.hmac, missingHeaders);
  const topic = getRequiredHeader(headers, headerNames.topic, missingHeaders);
  const domain = getRequiredHeader(headers, headerNames.domain, missingHeaders);
  const apiVersion = getRequiredHeader(
    headers,
    headerNames.apiVersion,
    missingHeaders,
  );
  const webhookId = getRequiredHeader(
    headers,
    headerNames.webhookId,
    missingHeaders,
  );

  if (missingHeaders.length) {
    return {
      valid: false,
      reason: WebhookValidationErrorReason.MissingHeaders,
      missingHeaders,
    };
  }

  const fields: WebhooksWebhookFields = {
    webhookType: WebhookType.Webhooks,
    hmac: hmac!,
    topic: topicForStorage(topic!),
    domain: domain!,
    apiVersion: apiVersion!,
    webhookId: webhookId!,
  };

  const name = getHeader(headers, headerNames.name);
  if (name) fields.name = name;

  const triggeredAt = getHeader(headers, headerNames.triggeredAt);
  if (triggeredAt) fields.triggeredAt = triggeredAt;

  const eventId = getHeader(headers, headerNames.eventId);
  if (eventId) fields.eventId = eventId;

  return {valid: true, ...fields};
}

import {createOrLoadOfflineSession} from './create-or-load-offline-session';
import {ensureOfflineTokenIsNotExpired} from './ensure-offline-token-is-not-expired';

export async function ensureValidOfflineSession(
  params: BasicParams,
  shop: string,
) {
  const session = await createOrLoadOfflineSession(params, shop);

  if (!session) return undefined;

  return ensureOfflineTokenIsNotExpired(session, params, shop);
}
