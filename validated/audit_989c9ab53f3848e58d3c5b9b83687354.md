## Analysis Result

### Title
Permanent EVM inbound-event ingestion freeze via unbounded FilterLogs failures with no adaptive chunking - (File: `universalClient/chains/evm/event_listener.go`)

### Summary
The external report describes the Gravity Bridge's `find_latest_valset` calling a raw `eth_getLogs`-style scan over a fixed block window that can permanently error out once RPC providers reject responses exceeding their size/result caps, with no fallback to shrink the window — freezing the bridge until a manual patch. Push Chain's universalClient contains the direct architectural analog: the EVM `EventListener` scans gateway/vault logs in fixed-size chunks with no adaptive retry when the underlying `FilterLogs` call fails due to provider-side result/size limits, and it never advances its cursor on error, so a single failing chunk repeats forever.

### Finding Description
`EventListener.processBlockRange` chunks the from/to block window into fixed `maxBlockRange = 9000` slices [1](#0-0) , and each chunk is fetched via `RPCClient.FilterLogs`, which wraps a single `ethclient.FilterLogs` call with round-robin failover across configured RPC endpoints but performs no query-size adaptation [2](#0-1) [3](#0-2) .

If the gateway+vault log query for a given 9000-block window returns a response that trips an RPC provider's result-count or payload-size limit (e.g. "query returned more than N results" or byte-size caps enforced by many production JSON-RPC providers), `FilterLogs` returns an error on every configured endpoint (since all endpoints see the same over-limit query), `processBlockChunk` propagates the error [4](#0-3) , and `processBlockRange`/`processNewBlocks` abort without ever calling `updateLastProcessedBlock` or advancing `currentBlock` [5](#0-4) . Since `currentBlock` is a pointer captured once in the `listen` loop and only mutated on success, the exact same fixed 9000-block chunk gets resubmitted identically on every subsequent poll tick [6](#0-5) , producing the same over-limit error indefinitely — an unrecoverable loop, exactly the failure mode the external report warns about, but here there is no chunk-halving/backoff logic at all (the external report's own recommended mitigation).

Unlike the original Gravity Bridge case (validator-set updates require validator-level activity), here the trigger is directly reachable by an ordinary user: `EventTypeSendFunds`, `EventTypeExecuteUniversalTx`, `EventTypeRevertUniversalTx` (gateway) and `EventTypeFinalizeUniversalTx`, `EventTypeFundsRescued` (vault) topics are all emitted from unprivileged, user-initiated cross-chain transactions [7](#0-6) . An attacker can flood the gateway/vault contracts on the source chain with many low-value transactions inside a single 9000-block window to make the combined address+topic log query exceed a provider's per-call result/size ceiling.

### Impact Explanation
Once tripped, the affected EVM chain's `EventListener` never advances past the offending block range, permanently halting ingestion of all inbound bridging events (`SendFunds`, `ExecuteUniversalTx`, `RevertUniversalTx`, `FinalizeUniversalTx`, `FundsRescued`) for that chain. This is a durable denial of service against Push Chain's universal execution inbound pipeline — no new deposits/inbound observations reach ballot voting/finalization until an operator manually reconfigures `EventStartFrom` past the poisoned range, matching the "freezing the bridge" impact called out as in-scope (non-network-level DoS reachable without privileged control).

### Likelihood Explanation
Requires only unprivileged transaction submission volume sufficient to make one 9000-block filtered-log response exceed a provider's result/size limit — achievable with ordinary account funds and no validator, relayer, or admin privilege. Likelihood depends on the specific RPC provider's limits (varies by provider/tier), but the code path has zero defense-in-depth against it.

### Recommendation
On `FilterLogs` failure in `processBlockChunk`/`processBlockRange`, detect provider result/size-limit errors and progressively halve the chunk's block range (recursively), retrying until it succeeds or a floor is hit, then continue advancing the cursor rather than perpetually retrying the same unbounded chunk — mirroring the fix Althea implemented in response to the original report.

### Proof of Concept
1. Deploy/target a chain configured with the gateway/vault addresses used by `EventListener`.
2. From an unprivileged account, submit a high volume of `sendFunds`/`executeUniversalTx` calls to the gateway contract within a single ~9000 block window, sized so the combined log response for the listener's `FilterLogs` query (addresses = [gateway, vault], topics = configured event topics) exceeds the RPC provider's per-call result/size limit.
3. Observe `processBlockChunk` return an error every poll tick with `currentBlock` never advancing (via added logging or state inspection of `chainStore.GetChainHeight()`), demonstrating the listener is stuck on the same block range indefinitely.

// processNewBlocks processes new blocks since last processed block
func (el *EventListener) processNewBlocks(
	ctx context.Context,
	currentBlock *uint64,
	topics []ethcommon.Hash,
) error {
	// Get latest block
	latestBlock, err := el.rpcClient.GetLatestBlock(ctx)
	if err != nil {
		return fmt.Errorf("failed to get latest block: %w", err)
	}

	// Skip if no new blocks
	if *currentBlock >= latestBlock {
		return nil
	}

	// Process blocks in range
	if err := el.processBlockRange(ctx, *currentBlock, latestBlock, topics); err != nil {
		return fmt.Errorf("failed to process block range: %w", err)
	}

	// Update last processed block in database
	if err := el.updateLastProcessedBlock(latestBlock); err != nil {
		el.logger.Error().Err(err).Msg("failed to update last processed block")
		// Don't return error - continue processing
	}

	// Move to next block
	*currentBlock = latestBlock + 1
	return nil
}

// processBlockChunk processes a single chunk of blocks
func (el *EventListener) processBlockChunk(
	ctx context.Context,
	fromBlock, toBlock uint64,
	topics []ethcommon.Hash,
) error {
	// Build address filter: gateway + vault
	addresses := []ethcommon.Address{ethcommon.HexToAddress(el.gatewayAddress), ethcommon.HexToAddress(el.vaultAddress)}

	// Create filter query
	query := ethereum.FilterQuery{
		FromBlock: big.NewInt(int64(fromBlock)),
		ToBlock:   big.NewInt(int64(toBlock)),
		Addresses: addresses,
		Topics:    [][]ethcommon.Hash{topics},
	}

	// Get logs for this chunk
	logs, err := el.rpcClient.FilterLogs(ctx, query)
	if err != nil {
		return fmt.Errorf("failed to get logs: %w", err)
	}

// executeWithFailover executes a function with round-robin failover
func (rc *RPCClient) executeWithFailover(ctx context.Context, operation string, fn func(*ethclient.Client) error) error {
	rc.mu.RLock()
	clients := rc.clients
	rc.mu.RUnlock()

	if len(clients) == 0 {
		return fmt.Errorf("no RPC clients available for %s", operation)
	}

	maxAttempts := len(clients)
	// Snapshot start index once per call so concurrent callers can't share
	// counter advances and retry the same failing endpoint.
	startIndex := atomic.AddUint64(&rc.index, 1) - 1
	var lastErr error
	for attempt := 0; attempt < maxAttempts; attempt++ {
		if ctx != nil {
			select {
			case <-ctx.Done():
				return ctx.Err()
			default:
			}
		}

		client := clients[(startIndex+uint64(attempt))%uint64(len(clients))]

		if client == nil {
			continue
		}

		err := fn(client)
		if err == nil {
			return nil
		}
		lastErr = err

		rc.logger.Warn().
			Str("operation", operation).
			Int("attempt", attempt+1).
			Err(err).
			Msg("operation failed, trying next endpoint")
	}

	if lastErr != nil {
		return fmt.Errorf("operation %s failed after trying %d endpoints: %w", operation, maxAttempts, lastErr)
	}
	return fmt.Errorf("operation %s failed after trying %d endpoints", operation, maxAttempts)

// FilterLogs fetches logs matching the filter query
func (rc *RPCClient) FilterLogs(ctx context.Context, query ethereum.FilterQuery) ([]types.Log, error) {
	var logs []types.Log
	err := rc.executeWithFailover(ctx, "filter_logs", func(client *ethclient.Client) error {
		var innerErr error
		logs, innerErr = client.FilterLogs(ctx, query)
		return innerErr
	})
	return logs, err
}
