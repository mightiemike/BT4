### Title
`socialize-debt` computes loss write-down using a stale interest `index` because it never calls `accrue()` — (File: `mainnet/contracts/vault/v0-vault-usdc.clar`)

### Summary
Every state-mutating vault entry point that depends on the interest `index` (`deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan`) begins its `let` binding with `(u (try! (accrue)))` to roll the cached `index`/`lindex`/`last-update` vars forward before reading them. `socialize-debt` is the one exception: it reads `(var-get index)`, `(var-get lindex)`, `(var-get principal-scaled)`, and `(total-assets)` directly, with no preceding `accrue()` call, exactly the "cached value not invalidated when its source moves" pattern described in the external report (where `amountToken1PendingLPWithdrawal` was read without first calling `update()`).

### Finding Description
`total-assets` is defined as `current-assets + max(total-debt - total-borrowed, 0)`, where `total-debt = calc-cumulative-debt(principal-scaled, index)` [1](#0-0) . This `index` is only advanced inside `accrue()`, which every other lending/vault function calls first via `(u (try! (accrue)))` [2](#0-1) [3](#0-2) [4](#0-3) .

`socialize-debt`, however, reads the cached `index`, `lindex`, `principal-scaled`, and derives `old-total-assets` from `(total-assets)` — all without calling `accrue()` first: [5](#0-4) 

If `last-update` is older than the current block (i.e., interest has accrued but no one has called any of `deposit`/`redeem`/`borrow`/`repay`/`accrue` in that block), `index` is stale and understates `total-debt`, hence understates `old-total-assets` and `total-borrowed`. The write-down math then uses this stale base:
- `debt-reduction = mul-div-down(scaled-amount, idx, INDEX-PRECISION)` — computed off the stale `idx`.
- `new-lindex = mul-div-down(current-lindex, old-total-assets - debt-reduction, old-total-assets)` — computed off the stale `old-total-assets`.

Because `idx` is stale (too low), `debt-reduction` is calculated too small relative to the actual current cumulative debt being written off, and `old-total-assets` is likewise understated. The `lindex` (liquidity/share index) write-down ratio `(old-total-assets - debt-reduction) / old-total-assets` is therefore computed against numbers that do not reflect the true, currently-accrued state of the vault — the same "split-brain" accounting the external report flagged: one live/mutated quantity (`principal-scaled`, `total-borrowed`, direct var mutations) combined with a not-yet-refreshed cached quantity (`index`) in a single formula.

### Impact Explanation
`socialize-debt` is the bad-debt write-down mechanism that reduces `lindex` (which directly determines the redemption value of every zft share via `total-assets-preview`/`convert-to-assets-preview`) and reduces `principal-scaled`/`total-borrowed` for the whole vault. Using a stale `index` means the socialized loss is mis-apportioned against a `total-assets` base that hasn't captured pending accrued interest for the block. Depending on the direction of drift, this either:
- under-writes-down `lindex`, leaving redeemable share value overstated relative to real backing assets (protocol insolvency risk — some depositors can redeem more than the vault actually holds after the bad debt event), or
- distorts the relationship between `total-borrowed`/`principal-scaled` and the true accrued debt, corrupting subsequent `total-debt`/`interest-rate`/`utilization` calculations for all later callers in the same block.

This lands on **Critical** impact: protocol insolvency via incorrect share-value accounting after a debt socialization event.

### Likelihood Explanation
The condition only requires that `socialize-debt` be invoked in a block/transaction where no prior `accrue()`-triggering call (deposit/redeem/borrow/repay/accrue) has happened since the last update — i.e., whenever the caller (the market/liquidation orchestrator) invokes `socialize-debt` without first accruing interest. Since `socialize-debt` is a single, self-contained public function with no accrue step, this is trivially reachable on the very first call after any time gap, making it a realistic, likely-to-occur operational sequence rather than a contrived edge case.

### Recommendation
Add `(u (try! (accrue)))` as the first binding in `socialize-debt`'s `let`, mirroring every other state-mutating entry point (`deposit`, `redeem`, `system-borrow`, `system-repay`, `flashloan`), so that `index`, `lindex`, and `last-update` are rolled forward before `total-assets`/`total-debt` are read and used in the write-down math. Apply the same fix to the other vault contracts that share this pattern (`v0-vault-stx.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`, and the sBTC vault) since they all appear to replicate the same `socialize-debt` structure without an `accrue()` call.

### Proof of Concept
1. Vault has active debt (`principal-scaled > 0`) and `index` was last updated at block `T0` (`last-update = T0`).
2. No `deposit`/`redeem`/`borrow`/`repay`/`accrue` transaction occurs for several blocks, so real accrued interest is pending but `index` in storage is stale (still reflects `T0`).
3. The market/liquidation orchestrator calls `socialize-debt(scaled-amount)` directly at block `T1 > T0` to write off bad debt.
4. Inside `socialize-debt`, `idx = var-get index` (stale, from `T0`), `old-total-assets = (total-assets)` computed with the stale `idx` [6](#0-5) .
5. `debt-reduction` and `new-lindex` are computed from these stale values and committed via `var-set lindex new-lindex` and the other `var-set` calls [7](#0-6) .
6. Because the true (post-accrual) `total-debt`/`total-assets` at `T1` differ from the stale values used, the resulting `lindex` write-down ratio is wrong, permanently mispricing zft share redemption value relative to actual vault backing — this cannot be corrected retroactively since `lindex` has already been persisted with the wrong ratio.

```text
(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
```
