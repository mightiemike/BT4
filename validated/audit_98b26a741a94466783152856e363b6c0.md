### Title
`sanitizeHost` can throw an unhandled `TypeError`/`URIError` instead of `InvalidHostError` when the base64 `host` param decodes to a malformed URL string - (File: packages/apps/shopify-api/lib/utils/shop-validator.ts)

### Summary
`sanitizeHost` only checks that the raw `host` parameter is syntactically valid base64 with `base64regex`, but never validates the *decoded* content before passing it into `new URL()`. Since `decodeHost` is a thin wrapper around `atob`, an attacker can supply a base64 string that decodes to bytes (e.g. control characters, null bytes) that make `new URL('https://' + decoded)` throw a raw `TypeError`/`URIError` instead of returning `null`/throwing `InvalidHostError`.

### Finding Description
`sanitizeHost` validates the `host` query param as follows: [1](#0-0) 

`base64regex` (`/^[0-9a-zA-Z+/]+={0,2}$/`) only guarantees the *encoding* is valid base64 — it says nothing about what the decoded bytes look like. `decodeHost` simply calls `atob`: [2](#0-1) 

The result is fed directly into `new URL(\`https://${decodeHost(sanitizedHost)}\`)` at line 58 with **no try/catch**. WHATWG `URL` parsing throws a raw `TypeError` when the input contains forbidden host code points (e.g. control characters, spaces, or otherwise malformed authority/host segments) — this is not caught anywhere in `sanitizeHost`, so it propagates out of the function as an unhandled exception rather than being converted into the library's `InvalidHostError`.

This function is reachable directly from unauthenticated input: `host` is read straight from the query string with no other check in `getEmbeddedAppUrl`/`buildEmbeddedAppUrl` (`packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts`, calling `sanitizeHost(config)(host, true)` with no surrounding try/catch), and in the Remix helper `validateShopAndHostParams` (`packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-shop-and-host-params.ts`), which calls `api.utils.sanitizeHost(url.searchParams.get('host')!)` directly inside the admin authentication path with no try/catch around the call either — it only checks the return value, assuming `sanitizeHost` never throws anything but the documented `InvalidHostError` (and even that isn't caught there).

No existing check filters out decoded content before it reaches `new URL()`: `base64regex` only constrains encoding, and there is no post-decode sanitization (e.g. stripping non-printable/control characters or wrapping the `new URL()` call in try/catch).

### Impact Explanation
This is a **denial-of-service in an authentication/routing handler**: any anonymous client that can hit an embedded-app route or the OAuth/admin authentication entrypoint with a crafted `host` query parameter can trigger an unhandled exception inside the library's auth utility code. Depending on the host framework (Remix/Express/React Router adapters) this can crash the request handler with a raw, unclassified error (potentially an unhandled promise rejection in async contexts) instead of the expected, safely-handled `InvalidHostError` → 400-style response, violating the stated invariant that auth handlers never crash on malformed input. This matches Shopify's "DoS in an authentication handler" bounty impact class.

### Likelihood Explanation
Highly feasible and repeatable: the `host` param is fully attacker-controlled, requires no authentication, no secret, and no non-default configuration. The attacker only needs to base64-encode a string containing characters that make `new URL()` reject the resulting host (e.g. embedded control/null bytes), which passes `base64regex` trivially. This can be triggered on every request to any route that calls `sanitizeHost`/`buildEmbeddedAppUrl`/`validateShopAndHostParams` with such a value.

### Recommendation
Wrap the `new URL(...)` call in `sanitizeHost` in a `try/catch`, converting any thrown error into `null` (or `InvalidHostError` when `throwOnInvalid` is true), mirroring how `sanitizeShop` never throws unexpected errors. Additionally, validate/sanitize the decoded string (e.g., reject non-printable/control characters) before constructing the `URL`.
