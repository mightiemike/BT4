### Title
HTTP/2 Rapid Reset (CVE-2023-44487) DoS possible because `maxRstFramesPerWindow` protection is disabled by default - ([File: framework/src/main/java/org/tron/common/application/RpcService.java])

### Summary
`RpcService.initServerBuilder()` only calls `NettyServerBuilder.maxRstFramesPerWindow(...)` when both `parameter.getRpcMaxRstStream() > 0` and `parameter.getRpcSecondsPerWindow() > 0`. There is no default in `config.conf` setting these values, so by default they are `0`, and the RST_STREAM flood mitigation is never installed on the gRPC server.

### Finding Description
`RpcService.initServerBuilder()` builds the Netty-based gRPC server and conditionally applies the RST-frame rate limiter:
```java
if (parameter.getRpcMaxRstStream() > 0 && parameter.getRpcSecondsPerWindow() > 0) {
  serverBuilder.maxRstFramesPerWindow(
      parameter.getRpcMaxRstStream(), parameter.getRpcSecondsPerWindow());
}
``` [1](#0-0) 

Searching the repository's configuration files (`*.conf`) turns up no entries for `rpcMaxRstStream` or `rpcSecondsPerWindow`, meaning the operator-facing default configuration does not set them, so the underlying `CommonParameter` fields remain at their compiled-in default (`0`). With this condition false, `maxRstFramesPerWindow()` is never invoked on the `NettyServerBuilder`, leaving the gRPC Netty transport without the mitigation gRPC added specifically for the "HTTP/2 Rapid Reset" attack class (open a stream via HEADERS then immediately send RST_STREAM, repeated at very high rate to force the server to allocate and tear down stream state without ever completing a request/response cycle). An unauthenticated remote client can open a plain HTTP/2 connection to the node's gRPC port and hammer it with HEADERS+RST_STREAM pairs; because no per-connection/per-window cap on RST frames exists, the server has no built-in circuit breaker for this pattern, other than generic OS/network limits and the (independent) `RateLimiterInterceptor`/`RpcApiAccessInterceptor`, which operate at the gRPC-call level and are not designed to bound raw HTTP/2 stream churn.

### Impact Explanation
This matches TRON's "DoS via the RPC-API" impact class: excessive CPU/memory/connection-table consumption on the full node's gRPC service, potentially causing RPC unavailability or degraded node responsiveness for legitimate clients, without requiring any privileged role, signed transaction, or non-default configuration — it is exploitable purely by connecting to the exposed gRPC port with default settings.

### Likelihood Explanation
Precondition is simply the shipped default (`rpcMaxRstStream`/`rpcSecondsPerWindow` unset ⇒ 0/0), which is the out-of-the-box state per the absence of these keys in the config files. The attack requires only a raw HTTP/2 client capable of issuing HEADERS+RST_STREAM (widely available tooling, e.g., custom HTTP/2 clients or fuzzers), no funds, no authentication, and no special network position — just network reachability to the gRPC port (a default, non-privileged capability for anyone allowed to talk to the node's RPC).

### Recommendation
Set sane non-zero defaults for `rpcMaxRstStream`/`rpcSecondsPerWindow` in `CommonParameter`/`Args` (and document them in `config.conf`/`config.conf.example`) so `maxRstFramesPerWindow` is enabled out of the box, or unconditionally call `maxRstFramesPerWindow` with a safe built-in floor value in `RpcService.initServerBuilder()` regardless of configuration, only allowing operators to raise/lower the limits rather than disable them entirely.

  protected NettyServerBuilder initServerBuilder() {
    NettyServerBuilder serverBuilder = NettyServerBuilder.forPort(this.port);
    CommonParameter parameter = Args.getInstance();
    if (parameter.getRpcThreadNum() > 0) {
      this.executorService = ExecutorServiceManager.newFixedThreadPool(
          this.executorName, parameter.getRpcThreadNum());
      serverBuilder = serverBuilder.executor(this.executorService);
    }
    // Set configs from config.conf or default value
    serverBuilder
        .maxConcurrentCallsPerConnection(parameter.getMaxConcurrentCallsPerConnection())
        .flowControlWindow(parameter.getFlowControlWindow())
        .maxConnectionIdle(parameter.getMaxConnectionIdleInMillis(), TimeUnit.MILLISECONDS)
        .maxConnectionAge(parameter.getMaxConnectionAgeInMillis(), TimeUnit.MILLISECONDS)
        .maxInboundMessageSize(parameter.getMaxMessageSize())
        .maxHeaderListSize(parameter.getMaxHeaderListSize());
    if (parameter.getRpcMaxRstStream() > 0 && parameter.getRpcSecondsPerWindow() > 0) {
      serverBuilder.maxRstFramesPerWindow(
          parameter.getRpcMaxRstStream(), parameter.getRpcSecondsPerWindow());
    }

    if (parameter.isRpcReflectionServiceEnable()) {
      serverBuilder.addService(ProtoReflectionService.newInstance());
    }
    return serverBuilder;
  }
