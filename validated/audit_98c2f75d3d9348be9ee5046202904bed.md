### Title
Vault `accrue` pauses via silent pass-through instead of reverting, letting borrow/repay/withdraw proceed on stale liquidity indexes - ([File: mainnet/contracts/vault/v0-vault-usdc.clar])

### Summary
The vault's `accrue` function, when the `accrue` pause flag is set, does not revert - it returns the last-stored `index`/`lindex` unchanged ("PAUSED: Pass-through without reverting"). Every state-mutating vault entrypoint (`deposit`, `system-borrow`, `repay`, `flashloan`, etc.) calls `(try! (accrue))` first and then proceeds to mutate state and move funds using whatever indexes `accrue` returned, without any check that the returned indexes reflect current market conditions. Because `accrue` returning stale-but-`ok` values is indistinguishable from `accrue` returning fresh values, downstream logic silently continues to operate as if accrual is current.

### Finding Description
In `v0-vault-usdc.clar` (mirrored in `v0-vault-sbtc.clar`, `v0-vault-stx.clar`, `v0-vault-usdh.clar`, `v0-vault-ststx.clar`), `accrue` is defined as: [1](#0-0) 

```
(if (get accrue states)
    ;; PAUSED: Pass-through without reverting
    (ok { index: idx, lindex: lidx })
    ;; NOT PAUSED: Normal accrual logic
    ...)
```

Every mutating vault function binds `u` (the result of `(try! (accrue))`) and continues unconditionally: [2](#0-1) [3](#0-2) 

`system-borrow` reads `(var-get index)` (`idx`) right after `(try! (accrue))` and uses it to compute `scaled-amount`, mutates `principal-scaled`/`total-borrowed`, and sends underlying funds - all gated only by pause flags for `borrow` itself, liquidity, and debt-cap checks, with no re-validation that `idx` is fresh: [4](#0-3) 

Separately, `set-pause-states` documents the intended invariant for the `accrue` flag: pausing forces one final accrual to capture pending interest, and unpausing "jumps" `last-update` forward to skip the paused interval so no interest is retroactively charged for the paused window: [5](#0-4) 

The pass-through-on-pause pattern is the mechanism described by the rules as "a pause that passes through instead of reverting." Because `accrue` succeeds (`ok`) instead of reverting while `accrue` is paused, any function chained after it (`deposit`, `system-borrow`, `repay`, `flashloan`) has no way to distinguish "indexes are current" from "indexes are frozen because accrual is paused" - it simply proceeds with `idx`/`lidx` as if they were fresh. This is compounded by the market-level index cache: `accrue-and-cache` in `v0-4-market.clar` calls `vault-accrue` and caches whatever indexes come back (fresh or frozen) for the rest of the block, keyed only by `stacks-block-time`/`aid`, with no distinction for pause state: [6](#0-5) 

The market's health/notional calculations then use these cached indexes (fresh or frozen indiscriminately) to price ztoken collateral/debt for borrow, withdraw, and liquidation decisions: [7](#0-6) [8](#0-7) 

### Impact Explanation
While pausing `accrue` is a deliberate design choice for the vault's own interest-accrual bookkeeping, the pass-through means the frozen index/lindex values are silently fed into `system-borrow`/`repay`/`deposit` and into the market's ztoken price resolution (`resolve-ztoken`) and notional-value calculations used for collateral valuation, borrow capacity, and liquidation health checks. If `accrue` is paused while debt continues to be serviced (borrow/repay proceed because only their own `borrow`/`repay` flags gate them, not `accrue`), ztoken-denominated collateral and debt will be priced using a `lindex`/`index` that no longer reflects the true growth of the underlying position, causing borrow limits, collateral valuations, and liquidation thresholds to be computed against stale exchange rates. This can result in under-collateralized borrows being permitted or healthy positions being wrongly flagged, i.e., temporary freezing or mispricing of funds tied to ztoken positions during the paused-accrue window - falling under the "temporary freezing of funds" impact class.

### Likelihood Explanation
Likelihood is moderate: it requires the DAO/admin to pause `accrue` specifically (not `deposit`/`borrow`/`repay`) via `set-pause-states`, which is a legitimate operational action (e.g., during an incident response where accrual bookkeeping needs to be frozen but the market should otherwise stay operative). Because `borrow`, `repay`, and `deposit` are independently gated and do not check the `accrue` pause flag, any window where `accrue` is paused but other operations remain open reliably triggers the stale-index-pass-through path on every subsequent call within the same block/transaction sequence.

### Recommendation
When `accrue` is paused, either (a) have `accrue` return an explicit "stale" indicator (e.g., an additional flag in the response tuple) that callers such as `system-borrow`, `repay`, `deposit`, and the market's `price-resolve`/`resolve-ztoken` must check and reject on, or (b) have `set-pause-states` also force-pause `borrow`/`repay`/`deposit`/ztoken price resolution whenever `accrue` is paused, so stale indexes can never be consumed by state-mutating or price-determining logic.

### Proof of Concept
1. DAO calls `set-pause-states` on a vault (e.g., `v0-vault-usdc`) with `accrue: true` but `borrow: false`, `repay: false`, `deposit: false` - a legitimate partial pause.
2. A user calls `market` `borrow`/`collateral` operations that reference the corresponding ztoken asset; the market calls `accrue-and-cache`, which calls the vault's `accrue`.
3. `accrue` sees `(get accrue states)` is `true` and returns `(ok { index: idx, lindex: lidx })` unchanged, without reverting: [9](#0-8) 
4. The market caches these frozen indexes for the block and uses them in `resolve-ztoken`/notional valuation to compute the user's collateral/debt value and health factor: [7](#0-6) 
5. Simultaneously, `system-borrow`/`repay` on the vault itself proceed (since only `borrow`/`repay` flags gate them) using the same frozen `idx`, allowing debt to be added/removed at a stale exchange rate relative to the real, still-accruing debt.
6. Result: collateral/debt valuations and borrow/liquidation decisions in the market are computed against indexes that do not reflect actual accrued interest for the duration of the `accrue` pause, producing incorrect health-factor outcomes until `accrue` is unpaused and `last-update` is jumped forward.

(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))
  (begin
    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      ;; When pausing accrue, accrue first to capture pending interest
      (if (and (not was-paused) now-paused)
          (begin (try! (accrue)) false)
          false)
      ;; When unpausing accrue, jump last-update to now to skip paused period
      (if (and was-paused (not now-paused))
          (var-set last-update stacks-block-time)
          false)
      (var-set pause-states states)
      
      (print {
        action: "vault-set-pause-states",
        caller: tx-sender,
        data: {
          vault: UNDERLYING,
          states: states
        }
      })
      
      (ok true))))

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
