## Title
`ensure_match_transaction_info` / `execute_and_verify` replay comparators never validate `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`, letting a corrupted state root pass as a verified replay - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` — the comparator used by `aptos-move/cli`'s replay command and by `storage/db-tool/src/replay_on_archive.rs`'s archive verification — checks status, gas, write-set hash, and event-root hash against a trusted `TransactionInfo`, but explicitly skips comparing any of the `TransactionInfoV1` checkpoint hash fields (`state_checkpoint_hash`, `hot_state_checkpoint_hash`, `position_state_checkpoint_hash`). The code even contains a self-documenting `TODO(trading-native)` acknowledging the gap. [1](#0-0) 

### Finding Description
`ensure_match_transaction_info` computes and checks `write_set_hash` against `txn_info.state_change_hash()` and `event_root_hash` against `txn_info.event_root_hash()`, but never calls `txn_info.state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, or `position_state_checkpoint_hash()` for comparison. [2](#0-1) 

This function is the sole per-transaction correctness gate used by:
- `aptos move replay` for a fetched `(txn, txn_info, aux_info)` pair from an authenticated debugger source. [3](#0-2) [4](#0-3) 

Meanwhile `TransactionInfoV1` carries `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and the newly repurposed `position_state_checkpoint_hash` field as authenticated, accumulator-committed data. [5](#0-4) 

These fields are the periodic state-root commitments produced by `DoStateCheckpoint::run` / `get_state_checkpoint_hashes`, which is the actual mechanism binding a block's Sparse-Merkle/JMT (and now native-position) root to the committed `TransactionInfo`/accumulator leaf. [6](#0-5) 

Because `ensure_match_transaction_info` (and, by extension, the archive-replay tool `storage/db-tool/src/replay_on_archive.rs::verify`, which calls `execute_and_verify` per chunk using the same expected-txn-info comparison contract) never re-derives and compares these checkpoint hashes against locally-recomputed state roots, a divergence in the state tree (or native-position tree) computed by local re-execution versus what was originally committed will not be detected by this verification path. The write-set hash and event-root hash can match exactly (i.e., the transaction's individual output is byte-for-byte identical) while the *aggregated, periodic state root* silently diverges — this is precisely the class of bug the comment flags: the position state root (an authenticated, accumulator-bound commitment) can diverge from local execution without `replay-verify` catching it. [7](#0-6) 

This differs from the full `TransactionOutputListWithProof::verify` used by fast-sync/state-sync clients, which also never checks the state-checkpoint hash fields per-transaction (only write-set/event/gas/status/txn-hash, then anchors the accumulator via the ledger info), meaning the same blind spot potentially exists broadly, but the concrete, currently-reachable code that documents and exhibits it is the replay/debugger comparator. [8](#0-7) 

### Impact Explanation
`replay_on_archive` and `aptos move replay` are the primary tools operators and auditors use to assert "local re-execution reproduces the exact committed ledger state" — this is the standard hard-fork/regression detection mechanism. If the state-checkpoint (or position-state-checkpoint) root diverges due to a bug in checkpoint construction, storage commit ordering, or the native-position pipeline (`commit_native_position`'s dual code path that either takes `chunk.position_state_summary` from execution or independently recomputes it via `position_summary_at_commit` when absent — two potentially divergent code paths), the divergence would be masked as a "successful" replay/verify run. [9](#0-8) 

This is a proof-integrity/state-commitment gap: a wrong accumulator-bound state root could be treated as validated by tooling meant to catch exactly this class of corruption, undermining the ability to detect hard-fork-causing state divergence before it affects consensus-observing infrastructure and node operators relying on `db-tool` for integrity assurance.

### Likelihood Explanation
This is a real, currently-shipped gap (not hypothetical): the code contains an explicit acknowledgment (`TODO(trading-native): ... Validate the checkpoint hashes here before enabling COMPUTE_TRADING_NATIVE_STATE_ROOTS`), confirming maintainers are aware the comparator is incomplete for the position/hot-state trading-native migration. [10](#0-9) 
Because `COMPUTE_TRADING_NATIVE_STATE_ROOTS` and the `hot_state_root_in_txn_info` feature gate whether these fields are populated at all, the exposure window is any period between when these features are computed/enabled on mainnet and when this comparator is patched to check them — during which any state/hot-state/position-state root divergence bug elsewhere in the stack would go undetected by replay-verify tooling.

### Recommendation
Extend `TransactionOutput::ensure_match_transaction_info` (and the analogous list-proof `verify()` in `types/src/transaction/mod.rs:2941-3022`, plus `storage/db-tool/src/replay_on_archive.rs`) to recompute and compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` against locally-derived roots whenever `txn_info` is a `TransactionInfoV1` carrying `Some` values for these fields, before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS` on mainnet, exactly as the existing TODO comment prescribes.

### Proof of Concept
No dynamic PoC was run (index/tooling limits); the vulnerability is demonstrated statically:
1. `DoStateCheckpoint::run` computes `state_checkpoint_hashes` / `hot_state_checkpoint_hashes` / `position_state_checkpoint_hashes` as the authoritative state roots for committed transactions. [11](#0-10) 
2. These are embedded into `TransactionInfoV1` and committed to the transaction accumulator (i.e., authenticated). [5](#0-4) 
3. `TransactionOutput::ensure_match_transaction_info`, used by `aptos-move/cli/src/commands.rs` replay paths, never reads or compares these three fields, only write-set hash, event-root hash, gas, and status. [2](#0-1) 
Thus a hand-crafted `TransactionInfoV1` (or a real divergent local state tree) with an incorrect `state_checkpoint_hash`/`position_state_checkpoint_hash` but correct `write_set`/`events`/`gas`/`status` fields would pass `ensure_match_transaction_info` without error, confirming the comparator's proof-integrity gap purely from the code path (no VM execution required to prove the missing check exists).

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())

    /// This method will ensure:
    /// 1. All transaction infos exist on the given `ledger_info`.
    /// 2. If `first_transaction_output_version` is None, the transaction output list is empty.
    ///    Otherwise, the list starts at `first_transaction_output_version`.
    /// 3. Events, gas, write set, status in each transaction output match the expected event root hashes,
    ///    the gas used and the transaction execution status in the proof, respectively.
    /// 4. The transaction hashes match those of the transaction infos.
    pub fn verify(
        &self,
        ledger_info: &LedgerInfo,
        first_transaction_output_version: Option<Version>,
    ) -> Result<()> {
        // Verify the first transaction output versions match
        ensure!(
            self.get_first_output_version() == first_transaction_output_version,
            "First transaction and output version ({:?}) doesn't match given version ({:?}).",
            self.get_first_output_version(),
            first_transaction_output_version,
        );

        // Verify the lengths of the transactions and outputs match the transaction infos
        ensure!(
            self.proof.transaction_infos.len() == self.get_num_outputs(),
            "The number of TransactionInfo objects ({}) does not match the number of \
             transactions and outputs ({}).",
            self.proof.transaction_infos.len(),
            self.get_num_outputs(),
        );

        // Verify the events, write set, status, gas used and transaction hashes.
        self.transactions_and_outputs.par_iter().zip_eq(self.proof.transaction_infos.par_iter())
        .map(|((txn, txn_output), txn_info)| {
            // Check the events against the expected events root hash
            verify_events_against_root_hash(&txn_output.events, txn_info)?;

            // Verify the write set matches for both the transaction info and output
            let write_set_hash = CryptoHash::hash(&txn_output.write_set);
            ensure!(
                txn_info.state_change_hash() == write_set_hash,
                "The write set in transaction output does not match the transaction info \
                     in proof. Hash of write set in transaction output: {}. Write set hash in txn_info: {}.",
                write_set_hash,
                txn_info.state_change_hash(),
            );

            // Verify the gas matches for both the transaction info and output
            ensure!(
                txn_output.gas_used() == txn_info.gas_used(),
                "The gas used in transaction output does not match the transaction info \
                     in proof. Gas used in transaction output: {}. Gas used in txn_info: {}.",
                txn_output.gas_used(),
                txn_info.gas_used(),
            );

            // Verify the execution status matches for both the transaction info and output.
            ensure!(
                *txn_output.status() == TransactionStatus::Keep(txn_info.status().clone()),
                "The execution status of transaction output does not match the transaction \
                     info in proof. Status in transaction output: {:?}. Status in txn_info: {:?}.",
                txn_output.status(),
                txn_info.status(),
            );

            // Verify the transaction hashes match those of the transaction infos
            let txn_hash = txn.committed_hash();
            ensure!(
                txn_hash == txn_info.transaction_hash(),
                "The transaction hash does not match the hash in transaction info. \
                     Transaction hash: {:x}. Transaction hash in txn_info: {:x}.",
                txn_hash,
                txn_info.transaction_hash(),
            );
            Ok(())
        })
        .collect::<Result<Vec<_>>>()?;

        // Verify the transaction infos are proven by the ledger info.
        self.proof
            .verify(ledger_info, self.get_first_output_version())?;

        Ok(())
    }

    fn get_state_checkpoint_hashes(
        execution_output: &ExecutionOutput,
        known_state_checkpoints: Option<Vec<Option<HashValue>>>,
        computed_last_checkpoint_hash: HashValue,
        label: &str,
    ) -> Result<Vec<Option<HashValue>>> {
        let _timer = OTHER_TIMERS.timer_with(&[&format!("get_{label}_checkpoint_hashes")]);

        let num_txns = execution_output.to_commit.len();
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();

        if let Some(known) = known_state_checkpoints {
            ensure!(
                known.len() == num_txns,
                "Bad number of known {label} hashes. {} vs {}",
                known.len(),
                num_txns,
            );
            if let Some(idx) = last_checkpoint_index {
                ensure!(
                    known[idx] == Some(computed_last_checkpoint_hash),
                    "{label} root hash mismatch with known hashes passed in. {:?} vs {:?}",
                    known[idx],
                    Some(computed_last_checkpoint_hash),
                );
            }
            Ok(known)
        } else {
            if !execution_output.is_block {
                // We should enter this branch only in test.
                execution_output.to_commit.ensure_at_most_one_checkpoint()?;
            }

            let mut out = vec![None; num_txns];
            if let Some(index) = last_checkpoint_index {
                out[index] = Some(computed_last_checkpoint_hash);
            }
            Ok(out)
        }
    }

    // Execute the verify one valid range
    pub fn verify(&self, start: Version, limit: u64) -> Result<Vec<Error>> {
        let mut total_failed_txns = Vec::with_capacity(limit as usize);
        let txn_iter = self
            .backup_handler
            .get_transaction_iter(start, limit as usize)?;
        let mut cur_txns = Vec::with_capacity(limit as usize);
        let mut cur_persisted_aux_info = Vec::with_capacity(limit as usize);
        let mut expected_events = Vec::with_capacity(limit as usize);
        let mut expected_writesets = Vec::with_capacity(limit as usize);
        let mut expected_txn_infos = Vec::with_capacity(limit as usize);
        let mut chunk_start_version = start;
        let executor = AptosVMBlockExecutor::new();
        for item in txn_iter {
            // timeout check
            if let Some(duration) = self.timeout_secs {
                if self.replay_stat.get_elapsed_secs() >= duration {
                    bail!(
                        "Verify timeout: {}s elapsed. Deadline: {}s. Failed txns count: {}",
                        self.replay_stat.get_elapsed_secs(),
                        duration,
                        total_failed_txns.len(),
                    );
                }
            }

            let (
                input_txn,
                persisted_aux_info,
                expected_txn_info,
                expected_event,
                expected_writeset,
            ) = item?;
            let is_epoch_ending = expected_event.iter().any(ContractEvent::is_new_epoch_event);
            cur_txns.push(input_txn);
            cur_persisted_aux_info.push(persisted_aux_info);
            expected_txn_infos.push(expected_txn_info);
            expected_events.push(expected_event);
            expected_writesets.push(expected_writeset);
            if is_epoch_ending || cur_txns.len() >= self.chunk_size {
                let cnt = cur_txns.len();
                while !cur_txns.is_empty() {
                    // verify results
                    let failed_txn_opt = self.execute_and_verify(
                        &executor,
                        &mut chunk_start_version,
                        &mut cur_txns,
                        &mut cur_persisted_aux_info,
                        &mut expected_txn_infos,
                        &mut expected_events,
                        &mut expected_writesets,
                    )?;
                    // collect failed transactions
                    total_failed_txns.extend(failed_txn_opt);
                }
                self.replay_stat.update_cnt(cnt as u64);
                self.replay_stat.print_tps();
            }
        }
        // verify results
        let fail_txns = self.execute_and_verify(
            &executor,
            &mut chunk_start_version,
            &mut cur_txns,
            &mut cur_persisted_aux_info,
            &mut expected_txn_infos,
            &mut expected_events,
            &mut expected_writesets,
        )?;
        total_failed_txns.extend(fail_txns);
        Ok(total_failed_txns)
    }
