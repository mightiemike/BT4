### Title
Vault `accrue` pause silently returns stale index instead of reverting, letting borrowers escape interest and permanently reducing yield owed to LPs - (File: `mainnet/contracts/vault/v0-vault-usdc.clar`)

### Summary
Each Zest vault contract (`v0-vault-usdc.clar`, `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`) exposes an independent `accrue` pause flag inside `pause-states`. When `accrue` is paused, the `accrue` function does not revert - it silently passes through and returns the last cached `index`/`lindex` without recomputing interest and without advancing `last-update`. Because `borrow`/`repay` have their own separate pause flags, a borrower can still call `system-borrow`/`system-repay` while `accrue` is paused, permanently escaping the interest that should have accrued for that window - a real economic loss to LP/zToken holders.

### Finding Description
`accrue` explicitly implements a "pause pass-through" instead of a revert: [1](#0-0) 

```clarity
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ...
```

Note that `last-update` is only advanced when the index actually changes: [2](#0-1) 

This is exactly the "clock advanced only on change" / "pause that passes through instead of reverting" pattern: the *value bound* is the vault's `index`/`lindex`/`last-update` state, the *event that invalidates it* is real elapsed time (interest accruing) while `accrue` is paused, and the *later use* is `system-borrow`/`system-repay`, both of which call `(try! (accrue))` first and then act on `(var-get index)`/`total-debt`: [3](#0-2) [4](#0-3) 

Because `accrue`, `borrow`, and `repay` are tracked as **independent** boolean flags in `pause-states`: [5](#0-4) 

an admin/DAO action that pauses only `accrue` (e.g. during an oracle/index bug investigation) does not stop `borrow`/`repay`. Any user can then `repay` (or `borrow`) while `accrue` is paused: `system-repay` computes `interest-paid = capped-amount - principal-repaid` using the pre-pause `index`, so no interest for the paused period is ever charged. Once the position is fully repaid (`principal-scaled` reduced to `0`), that missed interest can never be retroactively collected from that user - it is permanently gone. When accrue is later resumed, `next-index()`/`next-liquidity-index()` recompute forward from the old `last-update` timestamp, but the accrued/lost interest owed by users who already exited during the pause is not recoverable, permanently reducing `lindex`/`assets` growth that should have gone to zToken (LP) holders.

### Impact Explanation
This causes permanent loss of yield owed to liquidity providers (zToken holders): interest that should have accrued on outstanding debt during any `accrue`-paused window is silently dropped rather than deferred, and any borrower who repays/exits during that window escapes it entirely. This falls under the "High" impact class: theft/permanent freezing of unclaimed yield for LPs, realized without requiring any privileged action beyond a routine, narrowly-scoped pause toggle.

### Likelihood Explanation
The trigger only requires the `accrue` pause flag to be set on a vault while `borrow`/`repay` remain active - a plausible narrow operational action (e.g., pausing accrual to prevent a suspected bad interest-rate update while still allowing normal borrow/repay flow to not disrupt users). No collusion, oracle manipulation, or DAO compromise is needed to exploit the window once it exists; any regular borrower can repay during that window to capture the missed interest.

### Recommendation
Either (a) have `accrue`'s pause path revert (`ERR-PAUSED`) instead of returning a stale, silently-passed-through value, or (b) make `borrow`/`repay`/`flashloan` also gated by the `accrue` pause flag so debt-affecting operations cannot proceed on stale interest state, or (c) track and enforce accrual of interest lazily/retroactively for the paused interval rather than dropping it.

### Proof of Concept
1. DAO/admin pauses only `accrue` on `v0-vault-usdc` (`pause-states.accrue = true`), leaving `borrow`/`repay` active.
2. A borrower with outstanding scaled debt calls `market.repay` for `v0-vault-usdc`, which routes to `system-repay`.
3. `system-repay` calls `(try! (accrue))`; because `accrue` is paused, it returns the old `{index, lindex}` without recomputing `next-index`/`next-liquidity-index` and without updating `last-update` (`mainnet/contracts/vault/v0-vault-usdc.clar:837-861`).
4. `total-debt`/`interest-paid` are computed from the stale `index`, so the borrower fully closes their position (`principal-scaled` reduced to `0`) paying none of the interest that accrued in real time during the pause window (`mainnet/contracts/vault/v0-vault-usdc.clar:900-940`).
5. Admin unpauses `accrue`. `next-index`/`next-liquidity-index` recompute forward only from the old `last-update`, but the interest owed by the borrower who already exited during the pause is unrecoverable - permanently reducing the yield realized by remaining zToken/LP holders.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-public (system-borrow (amount uint) (receiver principal))

      (states (var-get pause-states))
      (u (try! (accrue)))

      (available-assets (get-available-assets))
      (scaled-principal (var-get principal-scaled))
      (idx (var-get index))
      (debt (total-debt))
      (scaled-amount (mul-div-up amount INDEX-PRECISION idx))
      (updated-scaled-principal (+ scaled-principal scaled-amount)))

    (try! (check-caller-auth))
    (asserts! (not (get borrow states)) ERR-PAUSED)
    (asserts! (> amount u0) ERR-AMOUNT-ZERO)
    (asserts! (<= amount available-assets) ERR-INSUFFICIENT-VAULT-LIQUIDITY)

    (var-set principal-scaled updated-scaled-principal)
