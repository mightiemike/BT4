### Title
Unlimited fee-free UEA-mapped account creation via `AccountInitDecorator` on gasless message types — no rate limiting, no cost, unbounded chain-state growth ([File: app/ante/account_init_decorator.go])

### Summary
The external report flags a missing throttle on an authenticated-but-unlimited endpoint that lets an attacker cheaply flood a system with distinct submissions. The Push Chain analog is `AccountInitDecorator`, which lets any unprivileged actor create a brand-new on-chain `BaseAccount` for free, with zero fee, zero minimum-gas-price check, and no per-account/per-IP/per-block throttle, as long as the transaction only contains gasless-whitelisted messages and a validly signed (but otherwise arbitrary/self-controlled) new keypair.

### Finding Description
`app/txpolicy/gasless.go` defines a message whitelist (`MsgExecutePayload`, `MsgMigrateUEA`, `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`) used by `IsGaslessTx` to determine whether a transaction skips fee and min-gas-price checks: [1](#0-0) 

For gasless transactions, `app/ante/account_init_decorator.go`'s `AccountInitDecorator.AnteHandle` checks whether the signer's address already has an account on chain. If not, it verifies the signature against a synthetic `account_number=0, sequence=0` signer payload and, on success, unconditionally creates the account and short-circuits the rest of the ante chain (skipping `SetPubKeyDecorator`, `SigVerificationDecorator`, `IncrementSequenceDecorator`, and all fee logic): [2](#0-1) 

`MsgExecutePayload` is explicitly designed so that "the Cosmos signer... Any account may submit the message," independent of the `UniversalAccountId.Owner`, since the message is gasless: [3](#0-2) 

Combining these facts: an attacker can generate an unlimited number of fresh keypairs off-chain (free), and for each one submit a single, minimally-valid `MsgExecutePayload` (or any other gasless-whitelisted message) transaction signed by that new key. `DeductFeeDecorator` and `MinGasPriceDecorator` both check `IsGaslessTx` first and skip the fee/min-gas-price checks entirely: [4](#0-3) [5](#0-4) 

Because Cosmos SDK's `BaseApp.runTx` commits the AnteHandler's cache-multistore mutations before executing the message body, the account creation performed inside `AccountInitDecorator` is persisted regardless of whether the inner message (e.g., an `executePayload` call against a non-existent or invalid UEA) subsequently fails in the message server. This means the attacker does not even need the payload to be semantically valid — a syntactically well-formed, freshly-signed gasless message with a brand new signer address is sufficient to permanently create a `BaseAccount` entry in the `x/auth` KV store, at zero fee, with no rate limiting, no CAPTCHA-equivalent proof-of-work, and no per-block/per-sender cap analogous to what the referral-code report recommended.

None of the ante decorators upstream of `AccountInitDecorator` (`NewSetUpContextDecorator`, `NewConsumeGasForTxSizeDecorator`, wasm decorators, `CircuitBreakerDecorator`, etc.) impose an economic cost on the sender for gasless transactions, since fee deduction is explicitly bypassed.

### Impact Explanation
An unprivileged external attacker can flood Push Chain with an effectively unbounded number of new on-chain accounts for zero on-chain cost, causing unbounded, permanent growth of validator state (the `x/auth` account store) purely through ordinary, permissionless transaction submission — no malicious validator, relayer, or privileged actor is required. This is a state-safety/resource-exhaustion issue reachable by any user via the default transaction submission path, matching the "denial of service... reachable without privileged control" allowed-impact category, since the growth is persistent on-chain state, not merely network/mempool noise.

### Likelihood Explanation
High. The only prerequisites are the ability to generate arbitrary Ed25519/secp256k1 keypairs (free, off-chain) and broadcast transactions, both trivially available to any actor. The whitelist mechanism and short-circuit behavior are unconditional and require no special privileges, bonding, or existing on-chain reputation.

### Recommendation
- Require a minimal, non-gasless "bootstrap" cost (e.g., a fixed minimum fee or dust deposit) for first-time account creation even on gasless message types, or restrict the `AccountInitDecorator` fast-path to signer addresses that are cryptographically tied to a real, pre-existing off-chain identity (e.g., only allow it for `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta`/`MsgVoteTssKeyProcess`/`MsgVoteFundMigration` signers that are already registered bonded Universal Validators, checked before account creation).
- Add an explicit rate limit / cap on new-account creation per block or per external IP/signer cluster at the mempool or ante level for the gasless path.
- For `MsgExecutePayload`/`MsgMigrateUEA`, consider requiring that the `Signer` already have an existing account (reject first-use account bootstrap for messages that don't need it), since only the fixed set of validator-vote messages was the original motivating case for the free account-init flow ("lets a freshly-keygen'd Universal Validator hot key vote on its very first tx").

### Proof of Concept
1. Generate a fresh keypair `K_i` off-chain (no cost).
2. Construct a `MsgExecutePayload` (or any gasless-whitelisted message) with `Signer = addr(K_i)` and an arbitrary/garbage `UniversalAccountId`/payload — the inner content can be invalid since it isn't checked before account creation.
3. Sign it with `account_number=0, sequence=0` and broadcast.
4. `AccountInitDecorator` verifies the signature, creates `addr(K_i)` as a `BaseAccount` with `sequence=1`, and short-circuits the ante chain — no fee charged, no min-gas-price enforced.
5. Repeat steps 1–4 with a new keypair `K_{i+1}` indefinitely; each iteration persists a new account in chain state at zero cost and with no throttling mechanism in place.

```go
func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}
```

**File:** x/uexecutor/README.md (L213-218)
```markdown
`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```
