### Title
Self-Referential Spot-Price Quote Defeats Slippage Protection in PRC20 Autoswap (GAS/GAS_AND_PAYLOAD Inbounds) - (File: x/uexecutor/keeper/evm.go, execute_inbound_gas.go, execute_inbound_gas_and_payload.go)

### Summary
The reported bug's root cause is that a protocol-critical ratio (shares-per-underlying) is derived from a balance an attacker can directly manipulate in the same flow that also consumes it, defeating the invariant it's meant to protect. Push Chain's autoswap path for `GAS` / `GAS_AND_PAYLOAD` inbounds has the same structural flaw: the slippage bound (`minPCOut`) used to protect a protocol-forced swap is derived from the *same* instantaneous, attacker-influenceable AMM spot price that the swap itself executes against, with no TWAP or external reference price.

### Finding Description

and equivalently in `gasAndPayloadDepositAutoSwap`: [2](#0-1) 

`GetSwapQuote` calls Uniswap V3 `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96` set to zero (no bound) against the current pool state — a pure spot-price read, not a TWAP: [3](#0-2) 

`minPCOut` is then computed as 95% of that same spot quote, and the actual swap (`depositPRC20WithAutoSwap` on `UniversalCore`) is executed immediately after with that `minPCOut`: [4](#0-3) 

The identical pattern also protects gas refunds in `applyGasRefund`: [5](#0-4) 

Because both the quote and the bound derived from it come from the same manipulable pool state, an attacker who moves the PRC20/WPC pool price down (via ordinary, unprivileged swaps on the public Uniswap V3 pool) immediately before the module's inbound-triggered swap executes gets a self-consistent but economically wrong `minPCOut` — the "protection" simply tracks the manipulated price rather than bounding against it. This mirrors the reported bug's core defect: a ratio computed from state the attacker just perturbed is then used, unchecked against any external/anchor reference, to size value delivered to a third party (here, the depositing user, whose position is drained into the attacker's sandwich).

### Impact Explanation
An unprivileged attacker who sandwiches the module's forced autoswap (front-run the pool price down, let the module's deposit+swap execute against the depressed price bounded only by 95% of that same depressed price, then back-run to restore price) can extract value from every `GAS`/`GAS_AND_PAYLOAD` inbound and every gas refund that goes through the swap-back path. This is a real loss of user/protocol funds reachable purely by an ordinary account trading on the public AMM pool — no validator, relayer, or admin privilege required — matching the "stealing, draining ... of user or protocol-controlled funds" and "corruption of ... gas fee accounting, refund accounting" allowed-impact categories.

### Likelihood Explanation
Likelihood is moderate-to-high: exploiting it only requires the ability to submit ordinary EVM swap transactions on Push Chain around the block(s) in which the UV-driven inbound execution happens, since Cosmos SDK block proposers determine ordering and MEV-style sandwiching across adjacent blocks is a well-established technique against spot-price-derived slippage bounds. It also compounds with pool liquidity — thinner pools amplify the achievable price impact and thus attacker profit.

### Recommendation
Do not derive the slippage bound from the same instantaneous quote used to execute the trade. Use a time-weighted average price (TWAP) from the pool (or an independent oracle) as the reference price for computing `minPCOut`, and/or cap the allowed deviation between the spot quote and the TWAP before allowing the autoswap to proceed, reverting to the no-swap deposit path if deviation exceeds a safe threshold.

### Proof of Concept
1. Attacker observes an in-flight `GAS`/`GAS_AND_PAYLOAD` inbound about to be finalized by UV votes (inbound data is public/observable once votes start landing).
2. Attacker submits an ordinary Uniswap V3 swap that pushes the PRC20/WPC pool price down within the pool's normal trading mechanics (no special privilege).
3. When the module's inbound execution runs `GetSwapQuote` → `minPCOut = quote * 95/100` → `CallPRC20DepositAutoSwap`, the depressed spot price is used for both the quote and its own slippage bound, so the swap executes at the manipulated rate without reverting.
4. Attacker back-runs by swapping back, restoring the pool price and capturing the difference, at the expense of the PC amount that should have landed in the user's UEA from the inbound.

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,

		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

		return nil, err

	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
