### Title
Unchecked boolean return value of `reduceAssetAmountV2`/`addAssetAmountV2` in `ExchangeTransactionActuator.execute()` may cause silent asset accounting inconsistency - (File: actuator/src/main/java/org/tron/core/actuator/ExchangeTransactionActuator.java)

### Summary
`ExchangeTransactionActuator.execute()` calls `AccountCapsule.reduceAssetAmountV2()` and `AccountCapsule.addAssetAmountV2()` to debit/credit TRC10 asset balances during an on-chain exchange trade, but it never checks the boolean return value of either call, unlike the sibling `TransferAssetActuator`, which explicitly checks and throws `ContractExeException` on failure.

### Finding Description
In `ExchangeTransactionActuator.execute()`, the token debit/credit logic is: [1](#0-0) 

Both `reduceAssetAmountV2(...)` and `addAssetAmountV2(...)` return a `boolean` indicating success/failure of the balance mutation, but their results are discarded here. Compare this to `TransferAssetActuator.execute()`, which treats the exact same API as fallible and aborts the transaction if it fails: [2](#0-1) 

This is the same bug class as the external report: a state-mutating "transfer-like" call whose success/failure signal is silently ignored, allowing the actuator to proceed and emit a success result (and update the `ExchangeCapsule` pool balances, via `Commons.putExchangeCapsule`) even if the underlying asset debit/credit did not actually occur as expected.

### Impact Explanation
If `reduceAssetAmountV2` silently fails (returns `false`) while the surrounding code proceeds unconditionally, the trader's asset balance would not be deducted, yet the exchange's internal `ExchangeCapsule` liquidity-pool balances (`firstTokenBalance`/`secondTokenBalance`, updated via `exchangeCapsule.transaction(...)` inside `doValidate()`/`execute()`) and the trader's *credited* `anotherTokenID` balance are still updated and the transaction is marked `code.SUCESS`. This produces an accounting divergence between the on-chain TRC10 asset ledger and the exchange pool bookkeeping — effectively creating value inconsistency comparable to the cross-chain HTLC inconsistency in the original report, where one side of a value transfer completes while the paired side silently fails. Reachable directly from an anonymous broadcast `ExchangeTransactionContract` transaction, this could result in asset/accounting corruption in a system contract path.

### Likelihood Explanation
Exploitability depends on finding a state where `reduceAssetAmountV2`/`addAssetAmountV2` can return `false` despite passing `validate()` (e.g., TOCTOU/staleness between `doValidate()`'s `assetBalanceEnoughV2` check and `execute()`'s mutation, arithmetic edge cases inside `AccountCapsule` asset-map handling, or same-token-name migration edge cases referenced by the extensive `SameTokenName` test suite). I was not able to fully inspect the internal implementation of `AccountCapsule.reduceAssetAmountV2`/`addAssetAmountV2` (source not retrievable within the available context) to enumerate every concrete false-return condition, so the exact triggering scenario is not fully confirmed — this should be verified against `chainbase/src/main/java/org/tron/core/capsule/AccountCapsule.java`.

### Recommendation
Mirror the pattern already used in `TransferAssetActuator`: check the boolean return values of `reduceAssetAmountV2` and `addAssetAmountV2` in `ExchangeTransactionActuator.execute()`, and throw `ContractExeException` (aborting the transaction and preventing the `ExchangeCapsule` pool update / `SUCESS` status) if either call returns `false`.

### Proof of Concept
Not independently reproducible from the index alone (would require exercising `AccountCapsule.reduceAssetAmountV2`/`addAssetAmountV2` failure paths, e.g., via crafted `SameTokenName` transition state or asset-map overflow, then invoking `ExchangeTransactionActuator` with a matching `ExchangeTransactionContract`) — flagged based on direct code-pattern comparison against the already-fixed/guarded `TransferAssetActuator` in the same codebase.   @Override
  public boolean execute(Object object) throws ContractExeException {
    TransactionResultCapsule ret = (TransactionResultCapsule) object;
    if (Objects.isNull(ret)) {
      throw new RuntimeException(ActuatorConstant.TX_RESULT_NULL);
    }

    long fee = calcFee();
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    ExchangeStore exchangeStore = chainBaseManager.getExchangeStore();
    ExchangeV2Store exchangeV2Store = chainBaseManager.getExchangeV2Store();
    AssetIssueStore assetIssueStore = chainBaseManager.getAssetIssueStore();
    try {
      final ExchangeTransactionContract exchangeTransactionContract = this.any
          .unpack(ExchangeTransactionContract.class);
      AccountCapsule accountCapsule = accountStore
          .get(exchangeTransactionContract.getOwnerAddress().toByteArray());

      ExchangeCapsule exchangeCapsule = Commons
          .getExchangeStoreFinal(dynamicStore, exchangeStore, exchangeV2Store)
          .get(ByteArray.fromLong(exchangeTransactionContract.getExchangeId()));

      byte[] firstTokenID = exchangeCapsule.getFirstTokenId();
      byte[] secondTokenID = exchangeCapsule.getSecondTokenId();

      byte[] tokenID = exchangeTransactionContract.getTokenId().toByteArray();
      long tokenQuant = exchangeTransactionContract.getQuant();

      byte[] anotherTokenID;
      long anotherTokenQuant = exchangeCapsule.transaction(tokenID, tokenQuant,
          dynamicStore.allowStrictMath(), allowHarden());

      if (Arrays.equals(tokenID, firstTokenID)) {
        anotherTokenID = secondTokenID;
      } else {
        anotherTokenID = firstTokenID;
      }

      long newBalance = subtractExact(accountCapsule.getBalance(), calcFee());
      accountCapsule.setBalance(newBalance);

      if (Arrays.equals(tokenID, TRX_SYMBOL_BYTES)) {
        accountCapsule.setBalance(subtractExact(newBalance, tokenQuant));
      } else {
        accountCapsule.reduceAssetAmountV2(tokenID, tokenQuant, dynamicStore, assetIssueStore);
      }

      if (Arrays.equals(anotherTokenID, TRX_SYMBOL_BYTES)) {
        accountCapsule.setBalance(addExact(newBalance, anotherTokenQuant));
      } else {
        accountCapsule
            .addAssetAmountV2(anotherTokenID, anotherTokenQuant, dynamicStore, assetIssueStore);
      }

      accountStore.put(accountCapsule.createDbKey(), accountCapsule);

      Commons.putExchangeCapsule(exchangeCapsule, dynamicStore, exchangeStore, exchangeV2Store,
          assetIssueStore);

      ret.setExchangeReceivedAmount(anotherTokenQuant);
      ret.setStatus(fee, code.SUCESS);
    } catch (ItemNotFoundException | InvalidProtocolBufferException
        | ContractValidateException | ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    }
    return true;
  }
