## Analysis

The Clearpool `bid()` report is a classic "attacker can time a transaction relative to another party's transaction to steal value" bug — pure ordering/front-running risk with no cryptographic or authorization flaw, just an economically exploitable window around a state-changing operation whose outcome depends on transaction ordering.

The closest native analog in Push Chain is the on-chain Uniswap V3 auto-swap that `x/uexecutor` executes as a side effect of validator-vote finalization (inbound `GAS`/`GAS_AND_PAYLOAD` execution and outbound gas-refunds). This swap is quoted and executed with a fixed, small slippage tolerance inside the same keeper call, and its trigger (a validator vote crossing the ballot threshold) is visible in the public mempool before it lands — giving an ordinary, unprivileged trader on the same Push Chain EVM a sandwich/front-run window to skim value out of every such swap.

### Title
Sandwichable auto-swap slippage in module-driven GAS deposit/refund execution allows unprivileged value extraction from user funds - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
When `x/uexecutor` processes a `GAS`/`GAS_AND_PAYLOAD` inbound, or refunds excess outbound gas, it fetches a Uniswap V3 `QuoterV2` quote and immediately executes `depositPRC20WithAutoSwap` / `refundUnusedGas(withSwap=true)` with `minPCOut = quote * 95 / 100` — a fixed 5% slippage tolerance [1](#0-0) . Because the quote-then-swap sequence executes atomically as a side effect of a normal, mempool-visible `MsgVoteInbound`/`MsgVoteOutbound` transaction reaching quorum, any unprivileged trader on Push Chain's EVM can sandwich that transaction: push the pool price against the swap direction immediately before it lands, letting the module's swap execute at up to the full 5% worse rate, then reverse the price immediately after, pocketing the difference at the expense of the crosschain user's minted PC / refunded gas amount.

### Finding Description
The relevant code path is:

1. `GetSwapQuote` reads the current AMM price via `QuoterV2.quoteExactInputSingle` [2](#0-1) .
2. The keeper immediately computes `minPCOut = quote * 95 / 100` and calls `CallPRC20DepositAutoSwap`, which issues the real state-changing `depositPRC20WithAutoSwap` call via `DerivedEVMCall` [3](#0-2) .
3. The identical quote→95%→swap pattern is repeated for `GAS_AND_PAYLOAD` inbounds in `gasAndPayloadDepositAutoSwap` [4](#0-3) , and for outbound gas refunds in `applyGasRefund` (`CallUniversalCoreRefundUnusedGas` with `withSwap=true`) [5](#0-4) .

All three call sites are triggered synchronously inside the message handler for `MsgVoteInbound` / `MsgVoteOutbound` — i.e., the very Cosmos transaction submitted by the last Universal Validator whose vote crosses the 2/3 threshold. That transaction is an ordinary, gasless transaction visible in the mempool before inclusion (per `app/txpolicy/gasless.go` allowlist [6](#0-5) ), so an unprivileged attacker watching the mempool can:
- see the finalizing vote transaction before it lands,
- submit a large swap on the same Uniswap V3 pool (tokenIn=PRC20 gas token / tokenOut=WPC or vice versa) immediately before it to move the price against the module's upcoming swap,
- let the module's swap execute at the worse price (still within the fixed 5% band so it doesn't revert),
- reverse the price immediately after with a back-run trade, capturing the spread.

This is a direct ordering-dependent value-extraction bug, structurally identical to the reported `bid()` front-running issue: whoever can control transaction ordering around a price-sensitive operation captures value that should have gone to the legitimate party (here, the crosschain depositor/refund recipient) instead.

### Impact Explanation
Each `GAS`/`GAS_AND_PAYLOAD` inbound execution and each outbound-refund-with-swap is an opportunity for an unprivileged actor to skim up to ~5% of the swapped notional from the user's minted PC (or refunded PC), directly corrupting the native/PRC20 asset accounting for that crosschain transaction and reducing the amount of funds the legitimate recipient receives. This falls under "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" and effectively a partial, repeatable draining of user-controlled funds — it is systemic (applies to every gas-paying inbound and every gas-refunding outbound) rather than a one-off griefing.

### Likelihood Explanation
High feasibility for an economically motivated attacker: no privileged role is required, the triggering transaction (validator vote finalization) is visible pre-confirmation like any other mempool transaction, the pool and its price are public, and the 5% band is generous relative to typical DEX liquidity depth for these routes, making profitable sandwiching realistic whenever pool liquidity is not extremely deep relative to the swap size.

### Recommendation
Do not derive `minPCOut` from a quote fetched in the same transaction that also executes the swap when the triggering transaction's inclusion is attacker-observable in advance. Options: tighten and dynamically calibrate slippage to real-time pool depth, use a TWAP-based quote source that cannot be moved within a single block, add a same-block manipulation guard (e.g., compare pre/post swap price impact against a sanity bound and abort/queue on anomaly), or route these swaps through a private/aggregated execution path insulated from public mempool ordering.

### Proof of Concept
1. Attacker monitors the Push Chain mempool for a `MsgVoteInbound`/`MsgVoteOutbound` transaction that will push a pending `GAS`/`GAS_AND_PAYLOAD` inbound (or outbound refund) over its 2/3 threshold.
2. Immediately before it, attacker submits a swap on the same Uniswap V3 pool (prc20GasToken/WPC) sized to move the price against the module's upcoming `depositPRC20WithAutoSwap` / `refundUnusedGas(withSwap=true)` direction, staying within a range that still lets the module's swap clear `minPCOut = quote*95/100` [7](#0-6) .
3. The finalizing vote transaction lands, and the module's swap executes at the manipulated (still slippage-compliant) price, crediting the recipient's UEA with less PC than a fair-price swap would.
4. Attacker immediately submits a reverse trade to restore the pool price, realizing the price-impact spread as profit, funded by the reduced amount credited to the crosschain user.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
