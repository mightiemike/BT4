### Title
PrivilegedWebContents/GEiC MojoJS gate over-grants capability surface and bypasses origin allowlist - (`chrome/browser/geic/geic_pwc_manager.cc`, `chrome/browser/chrome_content_browser_client.cc`)

### Summary
The external report is about an over-privileged `DEPLOYER` role that can both increase balances (`depositLP`) and drain them (`withdraw`) because a single `onlyDAO()` modifier is shared by two principals and there is no `purgeDeployer()` to revoke the role. The closest Chromium analog is the GEiC/PrivilegedWebContents prototype, where the renderer is granted the entire MojoJS surface (`EnableMojoJsBindings`) without checking the committed origin against the capability allowlist, and where the privileged-process gate is coarse enough that any qualifying PWC main frame can request interfaces that may later hold powerful capabilities. The actual `BindGeicApi`/`BindPrivilegedBridge` binders do enforce a tiered capability gate, but the MojoJS-enablement path is wider than the binder gate and is explicitly marked as a prototype shortcut.

### Finding Description
In `chrome/browser/geic/geic_pwc_manager.cc`, `TabEntry::RenderFrameCreated` and `TabEntry::ReadyToCommitNavigation` call `render_frame_host->EnableMojoJsBindings(/*features=*/nullptr)` for any primary main frame of a GEiC `PrivilegedWebContents`, with comments stating:

> "Prototype shortcut. This exposes the entire Mojo surface rather than only GeicApi, and the committed origin is not checked against the capability allowlist here." [1](#0-0) 

The same over-granting is present in `ChromeContentBrowserClient::ShouldAllowMojoJsBindingsForFrame`, which returns `true` for any outermost main frame of a `PrivilegedWebContents` without origin verification:

> "TODO(crbug.com/539909218): Prototype shortcut. Enabling MojoJS for any PWC exposes the entire Mojo interface surface rather than only GeicApi, and the committed origin is not checked against the capability allowlist here." [2](#0-1) 

By contrast, the actual binder gate in `chrome/browser/pwc/pwc_api_binder.cc` checks `IsStructurallyQualified` (HTTPS URL, capability origin, no parent/outer document) and `IsLifecycleAndIsolationQualified` (primary main frame, origin-keyed process) before binding `PrivilegedBridge` or `GeicApi`. [3](#0-2) 

The gap is that MojoJS is enabled before the binder gate runs, so any renderer bug or confused-deputy issue that lets a PWC main frame request an interface other than `GeicApi`/`PrivilegedBridge` reaches the full broker surface. The `PopulateChromeFrameBinders` registration further narrows the privileged interfaces to `render_frame_host->GetProcess()->IsPrivileged()`, but that is process-level, not origin-level. [4](#0-3) 

### Impact Explanation
If a GEiC `PrivilegedWebContents` is navigated to an origin that is in the navigation allowlist but not the capability allowlist (or if a same-site cross-origin document inherits an HTTPS capability origin via `about:blank`/`srcdoc` before the structural gate can reject it), the renderer still has MojoJS enabled and can attempt to bind interfaces that are registered for privileged processes. The binder gate is supposed to reject such requests with `bad_message::ReceivedBadMessage`, but the MojoJS-enablement path is wider and creates a larger attack surface than necessary. This maps to the report's "DEPLOYER can call both `depositLP` and `withdraw`" pattern: a single coarse gate (`onlyDAO()` / `IsPrivileged() + EnableMojoJsBindings`) grants more capability than the fine-grained gate (`onlyDeployer()` / `IsCapabilityOrigin`), and there is no `purgeDeployer()` equivalent to revoke MojoJS once the frame navigates to a non-capability origin.

### Likelihood Explanation
Reachability requires:
1. A `PrivilegedWebContents` feature is enabled (Finch/command-line/enterprise policy).
2. The attacker can navigate the GEiC panel to an origin that passes navigation but not capability policy, or exploit a renderer bug to confuse the origin/process boundary.
3. The attacker can request a privileged Mojo interface before the binder gate rejects it.

The code comments explicitly call this a "prototype shortcut" and note the committed origin is not checked, so the vulnerability is acknowledged in source. However, the binder gate still terminates the renderer on structural violations, so a direct same-origin bypass would need to defeat the `IsStructurallyQualified` checks (HTTPS URL, capability origin, no inherited document).

### Recommendation
1. Scope `EnableMojoJsBindings` to only the capability allowlist origins, mirroring `IsCapabilityOrigin` in `pwc_component_policy.cc`, instead of enabling it for any PWC main frame. [5](#0-4) 
2. Add a `purgeMojoJsBindings` / `DisableMojoJsBindings` equivalent (or rely on document-scoped teardown) so that navigation to a non-capability origin revokes the MojoJS capability, analogous to the requested `purgeDeployer()`.
3. Replace the coarse `IsPrivileged()` process check in `PopulateChromeFrameBinders` with per-interface, per-origin capability checks at bind time, so that even if MojoJS is enabled, only `GeicApi` (or the explicitly allowed interface) is reachable from a GEiC frame.

### Proof of Concept
A conceptual PoC, derived from the existing browsertest pattern:

```cpp
// In a GEiC PrivilegedWebContents, navigate the primary main frame to an
// origin that is in the navigation allowlist but not the capability allowlist.
std::unique_ptr<pwc::PrivilegedWebContents> privileged =
    pwc::PrivilegedWebContents::Create(
        pwc::PrivilegedComponent::kGeic, profile,
        std::make_unique<pwc::FixedPwcPolicyDelegate>(
            /*navigation_allowlist=*/{url::Origin::Create(
                GURL("https://allowed.example.com"))},
            /*capability_allowlist=*/{}));  // no capability origins
content::WebContents* web_contents = privileged->web_contents();
content::NavigateToURL(
    web_contents, GURL("https://allowed.example.com/title1.html"));

// MojoJS is enabled for the primary main frame despite the empty capability
// allowlist, because geic_pwc_manager.cc and
// ChromeContentBrowserClient::ShouldAllowMojoJsBindingsForFrame do not check
// IsCapabilityOrigin.
content::RenderFrameHost* frame = web_contents->GetPrimaryMainFrame();
EXPECT_TRUE(frame->AreMojoJsBindingsEnabled());  // conceptual API

// The renderer can now attempt to bind interfaces registered for privileged
// processes. BindGeicApi will reject it via EnforceCapabilityGate, but the
// MojoJS surface is exposed wider than GeicApi, increasing attack surface.
```

The source comments and the mismatch between `EnableMojoJsBindings` and `IsCapabilityOrigin` are the root cause.

// Tier 1 of the capability gate -- static properties of the requesting
// document that a well-behaved renderer can never get wrong: it must belong
// to a PrivilegedWebContents, be an outermost main frame (never a subframe
// or a fenced frame), and have committed over HTTPS to a capability origin.
// The HTTPS-URL check (not just an HTTPS *origin*) is what rejects
// inheriting schemes -- about:blank/srcdoc, blob:, data:, filesystem: --
// whose document can carry an inherited capability origin while never
// actually loading the trusted resource. None of these can change for the
// lifetime of the document, so a violation cannot be an innocent race.
bool IsStructurallyQualified(content::RenderFrameHost* render_frame_host,
                             PrivilegedWebContents* privileged) {
  return privileged && !render_frame_host->GetParentOrOuterDocument() &&
         render_frame_host->GetLastCommittedURL().SchemeIs(url::kHttpsScheme) &&
         privileged->policy().IsCapabilityOrigin(
             render_frame_host->GetLastCommittedOrigin());
}

// Tier 2 of the capability gate -- conditions a well-behaved renderer cannot
// control or observe race-free:
// - The document must currently be the primary main frame. A legitimate
//   request can be in flight while the browser commits a cross-document
//   navigation that moves the requesting document out of the primary page
//   (pending deletion). (A privileged WebContents never hosts prerendered or
//   back-forward-cached pages, so pending deletion is the only such state.)
//   Checking IsInPrimaryMainFrame() rather than IsOutermostMainFrame() also
//   keeps the gate correct if the PWC is ever embedded.
// - The document must actually run in an origin-keyed process: in a merely
//   site-keyed privileged process, a same-site cross-origin subframe could
//   share the qualifying frame's process, so such a process must not hold
//   capabilities.
bool IsLifecycleAndIsolationQualified(
    content::RenderFrameHost* render_frame_host) {
  return render_frame_host->IsInPrimaryMainFrame() &&
         render_frame_host->GetSiteInstance()
             ->GetSecurityPrincipal()
             .IsOriginKeyed();
}

}  // namespace

bool IsCapabilityQualifiedFrame(content::RenderFrameHost* render_frame_host) {
  content::WebContents* web_contents =
      content::WebContents::FromRenderFrameHost(render_frame_host);
  PrivilegedWebContents* privileged =
      PrivilegedWebContents::FromWebContents(web_contents);
  return IsStructurallyQualified(render_frame_host, privileged) &&
         IsLifecycleAndIsolationQualified(render_frame_host);
}

PrivilegedWebContents* EnforceCapabilityGate(
    content::RenderFrameHost* render_frame_host) {
  content::WebContents* web_contents =
      content::WebContents::FromRenderFrameHost(render_frame_host);
  PrivilegedWebContents* privileged =
      PrivilegedWebContents::FromWebContents(web_contents);

  // Fail closed, in two tiers. A tier-1 (structural) violation is a
  // compromised renderer and terminates the process; a tier-2 failure is not
  // renderer-controllable, so the receiver is dropped without a kill.
  if (!IsStructurallyQualified(render_frame_host, privileged)) {
    bad_message::ReceivedBadMessage(render_frame_host->GetProcess(),
                                    bad_message::PWC_BRIDGE_UNQUALIFIED_FRAME);
    return nullptr;
  }

  if (!IsLifecycleAndIsolationQualified(render_frame_host)) {
    return nullptr;
  }

  return privileged;
}

bool PwcComponentPolicy::IsCapabilityOrigin(const url::Origin& origin) const {
  // Structural guardrail: capability is a refinement of navigation. A
  // delegate cannot grant capability to an origin the main frame could
  // never commit.
  return IsNavigationAllowed(origin) && delegate_->IsCapabilityOrigin(origin);
}
