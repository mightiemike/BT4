### Title
Gas-abstraction auto-swap slippage protection is computed from a manipulable spot quote in the same execution, enabling sandwich attacks on inbound deposits - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
The Curve report shows that computing a "minimum received" slippage bound from the same manipulable on-chain state that the trade itself will execute against provides no real protection, since an attacker can move that state immediately beforehand. Push Chain's GAS / GAS_AND_PAYLOAD inbound execution and the outbound gas-refund path reproduce this exact pattern: they fetch a spot quote from a public Uniswap V3 `QuoterV2` pool and apply a flat 5% discount as `minPCOut`, then immediately execute the swap in the very same call, with no TWAP or external price check.

### Finding Description
`ExecuteInboundGas` (GAS route), `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD route), and `applyGasRefund`/`getSwapQuoteForRefund` (outbound gas refund) all follow the identical pattern:

1. Call `k.GetSwapQuote` → `QuoterV2.quoteExactInputSingle` (a `commit=false` spot-price query against a live, publicly-tradeable Uniswap V3 pool). [1](#0-0) 
2. Compute `minPCOut = quote * 95 / 100` — a flat 5% discount off whatever the pool's spot state currently reports. [2](#0-1) 
3. Immediately execute `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` with that `minPCOut`, in the same keeper call — no delay, no independent price oracle. [3](#0-2) 

The same construction is repeated for GAS_AND_PAYLOAD inbounds and for the outbound excess-gas refund: [4](#0-3) [5](#0-4) 

Critically, execution is triggered synchronously by the vote that crosses quorum: `VoteInbound` calls `ExecuteInbound` → `ExecuteInboundGas` in the same message handling as soon as ballot finalization occurs, with no delay/commit-reveal between quote and execution. [6](#0-5) 

`MsgVoteInbound` from Universal Validators is gasless and broadcast publicly (mempool-visible before inclusion), so an attacker watching for the vote that will cross quorum can front-run it with a large swap against the same PRC20/WPC Uniswap V3 pool, pushing the pool's spot price. Because the quote is fetched *after* the attacker's manipulation lands and *before* the deposit-swap executes (both within the block-processing pipeline, with no TWAP/oracle protection — confirmed absent by searching the codebase for TWAP/price-deviation checks, which only appear in these same slippage-calculation call sites), the 5% band is computed relative to the attacker's already-degraded price rather than a fair reference price. The subsequent swap then executes at (or near) that same manipulated price and trivially satisfies `minPCOut`, after which the attacker back-runs to restore price and capture the extracted value. This is functionally identical to the reported bug class: a "minimum amount" auto-derived from the same spot state the trade executes against, which does not protect against a moved market and produces "the vault receiving fewer tokens... resulting in losses" — here, the depositing user's UEA receives materially less native PC than a fair swap would have produced, with value siphoned to the attacker.

### Impact Explanation
An unprivileged attacker who can trade against the public Uniswap V3 PRC20/WPC pool can degrade the amount of native PC credited to a victim's UEA on every GAS/GAS_AND_PAYLOAD inbound deposit and on outbound gas refunds, extracting value at the expense of ordinary depositing users. This corrupts gas-fee/PRC20 accounting for the auto-swap path and results in a real, repeatable loss of user funds — squarely in scope under "corruption of ... gas fee accounting ... token mapping" and unauthorized value transfer via a user-reachable flow with honest validators/nodes.

### Likelihood Explanation
The `MsgVoteInbound`/`MsgVoteOutbound` transactions that trigger execution are gasless and therefore visible in the mempool prior to inclusion, giving an attacker a reliable trigger to front-run. The Uniswap V3 pools used for gas-token↔WPC conversion are ordinary public pools that any user can trade against; no special privilege is required. The 5% discount is a fixed, generous band that a moderately liquid pool can be moved through with a single flash-loan-funded swap, making the attack economically straightforward whenever pool depth is not overwhelming relative to deposit sizes.

### Recommendation
Do not derive `minPCOut` solely from a spot quote fetched immediately before execution. Use a manipulation-resistant reference price (e.g., a TWAP over multiple blocks from the same V3 pool, or an external price oracle) to bound the acceptable slippage, and/or require quote freshness/deviation checks against a longer-window observation before accepting the swap. Alternatively, let node operators/governance configure a maximum acceptable price-impact check independent of the same-transaction spot quote, and consider capping single-block price impact for the pools used by `depositPRC20WithAutoSwap`/`refundUnusedGas`.

### Proof of Concept
1. Attacker monitors the mempool for `MsgVoteInbound` transactions on Push Chain that will bring a GAS or GAS_AND_PAYLOAD inbound to quorum (votes are gasless and public).
2. Immediately before that vote is included, the attacker submits a large swap against the PRC20↔WPC Uniswap V3 pool used by `GetSwapQuote`, pushing the pool's spot price so that `quoteExactInputSingle` returns a degraded `amountOut`.
3. The quorum-crossing vote lands; `ExecuteInboundGas` calls `GetSwapQuote` (now reflecting the manipulated price) and computes `minPCOut = quote * 95/100` off that degraded value. [7](#0-6) 
4. `CallPRC20DepositAutoSwap` executes the swap; because `minPCOut` was derived from the same manipulated price, the swap succeeds despite the depositor's UEA receiving far less native PC than under fair market conditions.
5. Attacker back-runs to unwind their position, capturing the price differential as profit at the depositing user's expense.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
