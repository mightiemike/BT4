### Title
Gas-abstraction swaps and gas refunds use manipulable spot Uniswap V3 quotes instead of a TWAP, letting an attacker skew module-executed swap output - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/outbound.go, x/uexecutor/keeper/evm.go)

### Summary
`ExecuteInboundGas` and `applyGasRefund` derive the `minPCOut` slippage bound for module-initiated PRC20↔PC swaps from `GetSwapQuote`, which calls Uniswap V3 `QuoterV2.quoteExactInputSingle` — a pure spot-price simulation against the *current* pool state, with no TWAP or reference-price sanity check anywhere in the call path.

### Finding Description
`ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:104-153`) computes a gas-abstraction swap for every inbound deposit: it fetches a quoter address and WPC address, calls `k.GetSwapQuote(...)`, derives `minPCOut = quote * 95 / 100`, and immediately executes `k.CallPRC20DepositAutoSwap(...)`, which performs a real on-chain swap via the `UniversalCore` handler contract (`x/uexecutor/keeper/evm.go:542-593`). The same pattern is repeated for gas refunds in `applyGasRefund` → `getSwapQuoteForRefund` → `GetSwapQuote` (`x/uexecutor/keeper/outbound.go:213-269`).

`GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) calls `quoteExactInputSingle` on Uniswap's `QuoterV2`, which simulates the swap against the pool's *current* reserves/tick — an instantaneous spot price, not a time-weighted average. [1](#0-0)  There is no TWAP (`observe()`), no external reference price, and no maximum-deviation check anywhere in this path (confirmed by searching for `TWAP`, `observe(`, `maxDeviation` across the repo, which returns no matches in the swap logic). [2](#0-1) 

Because the quote and the swap execute back-to-back within the same atomic keeper call, the 5% slippage bound is self-referential (it is always satisfied against whatever state the pool happens to be in at call time) rather than anchored to a fair/TWAP price. An unprivileged attacker can, in any prior block, execute an ordinary swap against the same gas-token/WPC Uniswap V3 pool used by `UniversalCore` to push the spot price to an extreme, then trigger their own inbound deposit (gas-abstraction path is reached by any user's inbound message with a PRC20 gas token) or wait for a refund event, so that the protocol's own auto-swap executes at the attacker-skewed rate. This lets the attacker extract value from the module-owned WPC/PRC20 liquidity, or forces users' gas-refund/gas-abstraction swaps to receive far less PC than fair value, corrupting gas fee/refund accounting. This directly parallels the external report's root cause: relying on manipulable AMM state (pool reserves / spot price) rather than a TWAP for a price-sensitive financial operation.

### Impact Explanation
This falls under "corruption of ... gas fee accounting, refund accounting" and "unauthorized module-originated EVM execution" in the allowed-impact gate, since the module performs a fund-moving swap (`depositPRC20WithAutoSwap`, `refundUnusedGas` with `withSwap=true`) whose exchange rate an unprivileged attacker can bias by manipulating the underlying pool beforehand. This can cause protocol-owned WPC/PC value to leak to the attacker, or cause honest users to receive degraded PC amounts (or, if skew exceeds 5%, cause the swap to revert and fall back to a raw PRC20 refund/failure path), all without any privileged actor involved. [3](#0-2) 

### Likelihood Explanation
Likelihood depends on the liquidity depth of the specific gas-token/WPC Uniswap V3 pools deployed by `UniversalCore`, which I could not fully inspect (pool creation/seeding logic and default fee tiers live in Solidity contracts referenced only via ABI calls, and were not available in the indexed code). If these pools are thin relative to attacker capital (plausible for newly-listed or low-liquidity gas tokens), the attack is straightforward and repeatable each time an inbound deposit or refund triggers an auto-swap.

### Recommendation
Anchor `GetSwapQuote` (or a parallel check) to a Uniswap V3 TWAP (`observe()`/`OracleLibrary`) over a meaningful window, and/or enforce a maximum allowed deviation between the spot quote and the TWAP before using it to compute `minPCOut`; reject or fall back to the no-swap path when deviation exceeds a safe threshold.

### Proof of Concept
Conceptual (Solidity/Go-level, not runnable against this repo's Go-only indexed sources):
1. Attacker holds a large balance of the gas token PRC20 paired with WPC in the `UniversalCore` Uniswap V3 pool.
2. Attacker swaps a large amount of PRC20 into WPC on that pool via a normal DEX transaction, pushing the pool's spot price so PRC20 appears cheap relative to WPC.
3. Attacker (or any user) submits an inbound deposit in the same gas token; `ExecuteInboundGas` calls `GetSwapQuote` against the now-skewed pool and computes `minPCOut` from that skewed price (`x/uexecutor/keeper/execute_inbound_gas.go:134-145`), then executes `CallPRC20DepositAutoSwap` at that same skewed rate.
4. The module ends up swapping the deposited PRC20 for a below-fair-value amount of PC, and the attacker can immediately reverse their initial swap to restore the pool and capture the value difference — analogous to the reserve-manipulation PoC in the original Salty.IO report, but applied to Push Chain's module-initiated auto-swap rather than an oracle read.

I was unable to inspect the Solidity `UniversalCore`/`depositPRC20WithAutoSwap`/pool-seeding contracts (only their ABI call sites are present in the Go-indexed code), so the exact pool liquidity parameters and whether any additional on-chain guard exists inside the Solidity contract itself could not be fully verified from this index; a full audit of those contracts would be needed to confirm exploitability at current liquidity levels.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
