## Analysis

The external report describes `TransmuterBuffer` calling `depositUnderlying` with `0` as `minimumAmountOut`, exposing depositors to unbounded slippage. Push Chain's equivalent flow already replaced an earlier 0-slippage call with a bounded one, but the bound itself is derived from a spot AMM quote rather than a manipulation-resistant price source, which reproduces the same underlying invariant break (insufficient slippage protection against an unprivileged, incentivized actor) in a different form.

### Title
Gas-abstraction auto-swap slippage bound derived from manipulable spot Uniswap V3 quote enables sandwich extraction of user funds - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
`ExecuteInboundGas` and `ExecuteInboundGasAndPayload` convert a user's bridged PRC20 gas asset into native PC by calling `GetSwapQuote` followed immediately by `CallPRC20DepositAutoSwap`, using `minPCOut = quote * 95 / 100` as the slippage floor [1](#0-0) . The quote itself comes from `QuoterV2.quoteExactInputSingle` called with `SqrtPriceLimitX96 = 0` against the pool's current (spot) reserves, not a TWAP [2](#0-1) . Because the quote and the swap happen back-to-back against the same live pool state, and because the triggering event (a validator's finalizing `MsgVoteInbound`, once quorum is reached) is visible in the public mempool before it lands on-chain, an unprivileged actor can sandwich the module's swap: push the pool price down immediately before the module's tx, let the module's autoswap execute at the manipulated price (which still satisfies the 95% floor since the floor itself was computed after manipulation would have already begun, or simply because 5% tolerance is wide enough to absorb a profitable sandwich), then restore price afterward, pocketing the difference. This is the same "0/low slippage protection on deposit" invariant break as the cited report, just bounded to ~5% instead of unbounded — and 5% is a large, static tolerance that is not tied to pool liquidity depth, trade size, or a manipulation-resistant price feed.

### Finding Description
The relevant call chain is:
1. `GetSwapQuote` reads the AMM's current-block price via `quoteExactInputSingle` (no TWAP, no price-impact cap) [2](#0-1) .
2. The keeper computes `minPCOut = quote * 95 / 100` and immediately calls `CallPRC20DepositAutoSwap` with that bound [3](#0-2) , and identically in the GAS_AND_PAYLOAD path via `gasAndPayloadDepositAutoSwap` [4](#0-3) .
3. The same pattern (quote → 5% floor → swap) is reused for excess-gas refunds in `applyGasRefund` [5](#0-4) .

Both the quote fetch and the swap execution occur inside the same keeper call with no intervening block, so this is effectively equivalent to a single atomic "quote-then-trade" operation performed on-chain against a spot price. Any pool whose price can be moved by an ordinary, unprivileged trader (a normal Uniswap V3 pool with public liquidity) is subject to classic sandwich extraction: an attacker who sees the finalizing vote transaction (or otherwise anticipates when `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` will run) can trade against the pool beforehand to shift the spot price down by close to 5%, let the module's autoswap execute at that shifted price (still passing the `minPCOut` check because the check itself is computed from the already-degraded price), and then trade back afterward to restore the pool and realize the extracted value. The upgrade note explicitly frames the prior state as "0-slippage" and the current state as "5% slippage," but neither TWAP usage nor liquidity-depth/trade-size-aware bounding was introduced [6](#0-5) .

### Impact Explanation
Every GAS or GAS_AND_PAYLOAD inbound that triggers an on-chain PRC20→PC swap converts user-owned bridged value; a successful sandwich extracts up to ~5% of the swapped amount per inbound, directly from user funds, to an unprivileged attacker. Unlike the original Alchemix report — where the acknowledged mitigation was "this is only keeper-triggered, low risk" — here the vulnerable path executes automatically for ordinary user gas-abstraction inbounds and gas refunds, so it is reachable purely from default user transaction submission (bridging any GAS-denominated inbound), not from a privileged keeper action. This matches the in-scope impact category of "stealing ... of user or protocol-controlled funds" via the universal execution flow.

### Likelihood Explanation
Exploitation requires only: (1) capital to move the target pool's spot price temporarily, and (2) visibility into when the module's autoswap will execute (achievable by watching for the finalizing `MsgVoteInbound`/`MsgVoteChainMeta`-driven quorum transaction in the mempool, or simply by monitoring the pool and racing any observed inbound activity). No validator, TSS, or admin compromise is required — this is standard MEV sandwiching against a spot-price-quoted AMM interaction, well understood and commonly automated by bots. The fixed 5% tolerance, applied uniformly regardless of trade size or pool depth, makes low-liquidity token pools especially easy to move within that band.

### Recommendation
- Derive `minPCOut` from a manipulation-resistant reference (e.g., a TWAP over several blocks, or a bounded price-impact check using pool liquidity depth) rather than a single spot `quoteExactInputSingle` call combined with a static percentage.
- Scale the slippage tolerance down for large trades relative to pool liquidity, or cap per-inbound swap size against available liquidity.
- Consider routing gas-abstraction swaps through a mechanism less exposed to atomic sandwiching (e.g., committing to the trade in one block and executing in a later block using an already-finalized price checkpoint), or use protected/private submission for the module's derived EVM calls where feasible.

### Proof of Concept
1. Attacker observes a `MsgVoteInbound` (or equivalent finalizing message) in the mempool that will bring an inbound to quorum and trigger `ExecuteInboundGas` for a PRC20 gas asset with a known Uniswap V3 pool of modest liquidity.
2. Attacker front-runs with a swap that pushes the PRC20/WPC pool price down by close to 5%.
3. The finalizing tx executes, calling `GetSwapQuote` (spot-based) then `CallPRC20DepositAutoSwap` with `minPCOut = quote * 95 / 100` computed from the now-degraded price [7](#0-6) ; the swap succeeds because the floor is derived from the manipulated quote itself.
4. Attacker back-runs, trading back through the pool to restore price, netting the value that would otherwise have gone to the bridging user's UEA deposit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
