### Title
Forced Gas-Abstraction PRC20→WPC Autoswap Uses Fixed 5% Slippage, Enabling Sandwich Theft of Bridged User Funds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The reported Basin bug is a sandwich attack that exploits an AMM operation performed on a user's behalf with no user-controlled slippage protection, letting an attacker extract value from a forced, price-dependent conversion. Push Chain's `x/uexecutor` module has a native analog: whenever a `GAS` or `GAS_AND_PAYLOAD` inbound is finalized, the node forces the bridged PRC20 token through a Uniswap-V3-style pool (`QuoterV2.quoteExactInputSingle` + `depositPRC20WithAutoSwap`) to obtain native WPC for gas, using a **protocol-hardcoded 5% slippage tolerance** that the user cannot configure. Because pending inbounds (amount, asset, tx type) are visible on-chain before ballot finalization, and the actual quote/swap execution happens atomically at finalization time, an unprivileged actor can sandwich this forced swap and capture up to the full 5% slippage margin from ordinary users' bridged funds.

### Finding Description
For every `TxType_GAS` and `TxType_GAS_AND_PAYLOAD` inbound, once 2/3+ validators vote and the ballot is finalized (`x/uexecutor/keeper/msg_vote_inbound.go`, step 8 → `ExecuteInbound`), execution flows into `ExecuteInboundGas` [1](#0-0)  and `gasAndPayloadDepositAutoSwap` [2](#0-1) .

Both paths perform the same pattern: fetch a swap quote from the Uniswap-style `QuoterV2` contract via `GetSwapQuote` [3](#0-2) , then compute `minPCOut` as a **fixed 95% of the just-fetched quote** — never a user-supplied slippage bound — and immediately execute the swap through `CallPRC20DepositAutoSwap` [4](#0-3) [5](#0-4) .

This mirrors the Basin bug's root cause exactly: the protocol performs a price-sensitive AMM operation on behalf of the user without letting the user set their own acceptable slippage, and the quote/execution round-trip is exploitable by anyone who can move the pool price around it. Here the exploitation window is even wider than in the original report:
- `Inbound` observations are recorded validator-by-validator and held in `PendingInbounds` until 2/3+ votes land [6](#0-5) , which is queryable on-chain (`AllPendingInbounds`), revealing the exact amount/asset/tx-type of an upcoming forced swap well before it executes.
- The swap only actually happens in the same transaction as the vote that reaches quorum (`VoteInbound` → `ExecuteInbound`), so an attacker watching the mempool for the quorum-completing `MsgVoteInbound` can submit front-run/back-run swap transactions against the same Uniswap pool in the same block, moving the pool price unfavorably for the victim before the forced quote is taken and reverting it afterward — a classic JIT sandwich — capturing the entire 5% tolerance as guaranteed profit regardless of the pool's actual depth/fee.
- Because `minPCOut` is derived from `quote` fetched in the very same call rather than from any caller/user input, there is no way for the bridging user to reduce their exposure (contrast with the Basin recommendation of "user-defined slippage controls").

### Impact Explanation
This directly results in draining of bridged user funds during ordinary, unprivileged cross-chain gas-abstraction deposits — squarely in scope ("stealing … draining … of user or protocol-controlled funds", reachable via "ordinary user deposits … or default transaction submission paths alone"). Every `GAS`/`GAS_AND_PAYLOAD` inbound that requires a PRC20→WPC conversion is affected, and the loss (up to ~5% of the swapped notional) is deterministic and repeatable per inbound, not a one-off. Given Push Chain's gas-abstraction is a core, frequently-used flow for all inbound cross-chain transactions needing native gas, the aggregate value at risk is significant.

### Likelihood Explanation
High. No privileged access is required — any external actor able to submit transactions and observe `PendingInbounds`/mempool contents can execute the sandwich. The attack does not depend on validator or relayer misbehavior; it only requires ordinary MEV capability (front-run/back-run around a same-block swap), which is realistic for a public chain with visible mempool and pending-inbound state. The vulnerability is deterministic since `minPCOut` is always exactly 95% of the on-execution quote, giving attackers a known, bounded, guaranteed extraction margin.

### Recommendation
- Do not hardcode a fixed 5% slippage tolerance computed from a quote fetched in the same call as execution; instead, let the swap quote be fetched with TWAP/oracle-resistant pricing, and/or expose slippage as a configurable, conservative governance parameter that can be tightened.
- Consider using a commit-reveal or delayed-execution scheme so the swap is not directly and predictably triggered by the observable quorum-completing vote transaction, reducing the attacker's ability to precisely time the sandwich.
- Where feasible, route required gas-conversion swaps through TWAP-based on-chain oracles rather than instantaneous pool quotes, or split large conversions to reduce price-impact-driven MEV extraction.
- Add integration tests measuring realized vs. quoted output under adversarial pool-price movement within the finalization block, and enforce a tighter/percentage-of-pool-depth-based bound rather than a flat 5%.

### Proof of Concept
1. A user submits a cross-chain deposit of native gas token requiring a `GAS` inbound with `AssetAddr` = some ERC20 requiring conversion via `depositPRC20WithAutoSwap`.
2. Validators begin voting; the pending inbound (amount, asset, tx type) becomes visible via `AllPendingInbounds` / mempool of `MsgVoteInbound` transactions before quorum is reached.
3. An attacker, seeing the quorum-completing `MsgVoteInbound` transaction about to land, submits (a) a large swap of the same PRC20→WPC pair on the underlying Uniswap-style pool immediately before it in the same block, moving the pool price unfavorably, and (b) a reverse swap immediately after.
4. When the quorum-completing vote executes, `ExecuteInboundGas` calls `GetSwapQuote` [3](#0-2)  against the now-manipulated pool, computes `minPCOut = quote * 95/100` [7](#0-6) , and executes the swap at the worse price — the victim receives close to the guaranteed floor instead of the fair-market amount.
5. The attacker's back-run trade restores the pool price and realizes the difference as profit, extracted from the user's bridged funds, with no interaction with any privileged role.

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
