Front-runnable PoisonMicroblock reporting lets an attacker steal another user's fork-detection commission - (File: stackslib/src/chainstate/stacks/db/transactions.rs)

### Summary
The Stacks `PoisonMicroblock` transaction handler determines who is entitled to the poison-microblock commission (a slice of the offending miner's coinbase) purely by comparing the reported fork sequence number against whatever is already recorded on-chain for that microblock public-key hash. Anyone can observe an honest reporter's pending `PoisonMicroblock` transaction in the mempool (it reveals the two conflicting microblock headers) and resubmit the same evidence with a higher fee to be mined first, claiming the reward the honest party discovered. This is a direct analog of the reported LendingPool `redeem` front-run: an unprivileged third party observes an in-flight beneficial transaction and races it with a copy of their own to seize the payout before the original sender.

### Finding Description
`process_poison_microblock` in [1](#0-0)  decides the poison-microblock reporter and rewarded sequence solely from `get_microblock_poison_report`/`insert_microblock_poison` state at the time each individual transaction executes:

- If no report exists yet for `mblock_pubk_height`, the first transaction to execute becomes the recorded reporter [2](#0-1) .
- If a report already exists, a later transaction only overwrites it if it reports a strictly lower `sequence` (a "better" fork point); otherwise it is dropped and the earlier reporter keeps the record [3](#0-2) .

Both the microblock headers proving the fork and the reporter identity are fully visible once the honest discoverer's `PoisonMicroblock` transaction is broadcast (it is a normal, unauthenticated-content transaction — anyone with the two conflicting microblock headers can construct an equivalent transaction from a different sending address). Because acceptance is decided purely by transaction ordering (equal-or-better sequence + first to be mined), an attacker who sees the honest reporter's pending transaction can copy the same `(mblock_header_1, mblock_header_2)` payload into their own transaction, pay a higher fee, and get it mined first — winning `insert_microblock_poison(mblock_pubk_height, attacker_principal, seq)` for themselves.

This mirrors the bug class in the external report precisely: a state-changing, reward-granting operation is gated by a check that depends only on the order transactions land on-chain, not on who actually "owns" the underlying claim (in the LendingPool case, liquidity/health factor; here, first-to-record reporter identity). An unprivileged minority actor (a single miner or a user paying a modest fee premium) can win the race without needing majority hash power, majority signer weight, or any special key.

### Impact Explanation
This breaks the equality "commission recipient == the party who first discovered/produced the fork evidence." The mispayment is bounded to the poison-microblock commission fraction of a single coinbase reward (`POISON_MICROBLOCK_COMMISSION_FRACTION`, see `calculate_miner_reward`/`poison_microblock_commission` in [4](#0-3)  and the payout applied via `find_mature_miner_rewards` [5](#0-4) ). This falls under the "High" impact bucket in the rules: a reward mis-payment bounded to fees/commission, achievable by an unprivileged minority actor, with no chain split or consensus-verdict divergence (both honest and malicious versions of the transaction are equally valid to every node — the outcome is deterministic given transaction order, so there is no fork; the loss is economic, to the honest reporter).

### Likelihood Explanation
Likelihood is moderate: it requires (a) an epoch-2.x style microblock fork to exist and be discovered by an honest party, (b) that party to submit a `PoisonMicroblock` transaction visible in the mempool before confirmation, and (c) an attacker monitoring the mempool to copy and outbid it. This is functionally identical in shape to standard MEV/front-running conditions already acknowledged as a risk class by the external report; it requires no special privilege, only mempool visibility and the ability to pay a marginally higher fee — exactly the "unprivileged, minority-triggerable" threshold the task calls for.

### Recommendation
Do not let the raw poison-microblock payload transferred in cleartext be trivially replayable by a third party. Options: require the report to commit to the sender's identity in a way that can't be copied (e.g., require a commit-reveal scheme, or bind the reward to the account that originally produced the microblock signature chain rather than the tx sender), or make the comparison additionally consider the original block-inclusion time/proposer so that a strictly later, merely fee-boosted duplicate cannot supersede an already-broadcast equivalent report. Documenting the front-run risk (as the external report recommends short-term) and advising reporters to use private relays/higher fees is a viable interim mitigation.

### Proof of Concept
1. Miner M produces a forked microblock stream signed under a given `mblock_pubkey_hash` (two microblocks at the same sequence, different content).
2. Honest user A observes the fork off-chain and broadcasts `PoisonMicroblock(mblock_header_1, mblock_header_2)` from principal A, with a normal fee.
3. Attacker B observes A's unconfirmed transaction in the mempool (payload has both headers, i.e., the entire proof), and immediately broadcasts an identical `PoisonMicroblock(mblock_header_1, mblock_header_2)` from principal B, with a higher fee.
4. Because block/microblock inclusion order is determined by fee/priority (not discovery order), B's transaction gets mined first. `get_microblock_poison_report` returns `None` when B's tx executes, so `insert_microblock_poison(mblock_pubk_height, B, seq)` is recorded per [2](#0-1) .
5. When A's transaction executes afterward with an equal (not strictly lower) sequence, it falls into the "someone else beat the sender to this report" branch and is dropped, per [6](#0-5) .
6. At maturity, `find_mature_miner_rewards` reads the poison report and pays the commission to B instead of A [5](#0-4) , confirming the reward-to-wrong-party outcome.

    /// user-burn-supporters.
    ///
    /// If poison_reporter_opt is not None, then the returned MinerReward will reward the _poison reporter_,
    /// not the miner, for reporting the microblock stream fork.
    fn calculate_miner_reward(
        mainnet: bool,
        parent_block_epoch: StacksEpochId,
        participant: &MinerPaymentSchedule,
        miner: &MinerPaymentSchedule,
        users: &[MinerPaymentSchedule],
        parent: &MinerPaymentSchedule,
        poison_reporter_opt: Option<&StacksAddress>,
    ) -> (MinerReward, MinerReward) {
        ////////////////////// coinbase reward total /////////////////////////////////
        let (this_burn_total, other_burn_total) = {
            if participant.miner {
                // we're calculating the miner's reward
                let mut total_user: u128 = 0;
                for user_support in users.iter() {
                    total_user = total_user
                        .checked_add(user_support.burnchain_commit_burn as u128)
                        .expect("FATAL: user support burn overflow");
                }
                (participant.burnchain_commit_burn as u128, total_user)
            } else {
                // we're calculating a user burn support's reward
                let mut this_user: u128 = 0;
                let mut total_other: u128 = miner.burnchain_commit_burn as u128;
                for user_support in users.iter() {
                    if user_support.address != participant.address {
                        total_other = total_other
                            .checked_add(user_support.burnchain_commit_burn as u128)
                            .expect("FATAL: user support burn overflow");
                    } else {
                        this_user = user_support.burnchain_commit_burn as u128;
                    }
                }
                (this_user, total_other)
            }
        };

        let burn_total = other_burn_total
            .checked_add(this_burn_total)
            .expect("FATAL: combined burns exceed u128");

        test_debug!(
            "{}: Coinbase reward = {} * ({}/{})",
            participant.address.to_string(),
            participant.coinbase,
            this_burn_total,
            burn_total
        );

        // in the case of shadow blocks, there will be zero burns.
        // the coinbase is still generated, but it's rendered unspendable
        let (this_burn_total, burn_total) = if burn_total == 0 {
            (1, 1)
        } else {
            (this_burn_total, burn_total)
        };

        // each participant gets a share of the coinbase proportional to the fraction it burned out
        // of all participants' burns.
        let coinbase_reward = participant
            .coinbase
            .checked_mul(this_burn_total)
            .expect("FATAL: STX coinbase reward overflow")
            / burn_total;

        // process poison -- someone can steal a fraction of the total coinbase if they can present
        // evidence that the miner forked the microblock stream.  The remainder of the coinbase is
        // destroyed if this happens.
        let (child_address, child_recipient, coinbase_reward, punished) =
            if let Some(reporter_address) = poison_reporter_opt {
                if participant.miner {
                    // the poison-reporter, not the miner, gets a (fraction of the) reward
                    debug!(
                        "{:?} will recieve poison-microblock commission {}",
                        &reporter_address.to_string(),
                        StacksChainState::poison_microblock_commission(coinbase_reward)
                    );

                        reporter_address.clone(),
                        reporter_address.to_account_principal(),

                        0,
                        false,
                    )
                }
            } else {
                // no poison microblock reported
                (
                    participant.address.clone(),
                    participant.recipient.clone(),
                    coinbase_reward,
                    false,
                )
            };
