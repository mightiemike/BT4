### Title
Accrue Pause Silently Passes Through Instead of Reverting, Allowing Interest-Free Borrow/Repay Windows That Permanently Freeze Lender Yield — (File: `mainnet/contracts/vault/v0-vault-sbtc.clar` and identical logic in `v0-vault-stx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`)

### Summary
`accrue()` in every mainnet vault contract checks the `accrue` flag in `pause-states` and, when set, returns the stale cached `{index, lindex}` pair with `(ok ...)` instead of reverting. Because `system-borrow`, `system-repay`, `deposit` and `redeem` each call `(try! (accrue))` unconditionally before checking their *own*, independent pause flag, all of these operations can continue to execute against a frozen interest index while the protocol operator believes accrual is halted. When accrual is later re-enabled, `set-pause-states` jumps `last-update` straight to `stacks-block-time`, permanently discarding all interest that should have accrued on the debt principal outstanding during the paused window.

### Finding Description
`accrue` is defined identically across all vaults, e.g. `v0-vault-sbtc.clar`: [1](#0-0) 

```clarity
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          ...
```

When `accrue` is paused, no `next-index`/`next-liquidity-index` is computed and `last-update` is not advanced — the function simply returns the last-known index unchanged and `(ok ...)`. It never signals `ERR-PAUSED`.

`system-borrow` (and equivalently `system-repay`, `deposit`, `redeem`) call `accrue` unconditionally first, then separately gate on their own flag: [2](#0-1) 

```clarity
(define-public (system-borrow (amount uint) (receiver principal))
  (let (
      (states (var-get pause-states))
      (u (try! (accrue)))
      ...
    (try! (check-caller-auth))
    (asserts! (not (get borrow states)) ERR-PAUSED)
    ...
    (var-set principal-scaled updated-scaled-principal)
    (var-set total-borrowed (+ (var-get total-borrowed) amount))
```

Because `accrue`'s pause flag is independent of `borrow`/`repay`/`deposit`/`redeem` flags, an operator can pause `accrue` alone (e.g., to freeze interest-rate movement while investigating an oracle or IR-model issue) while leaving borrow/repay/deposit/redeem active. During that window:
1. `principal-scaled` continues to change from borrows/repays using the *frozen* `idx`.
2. Real elapsed time (`stacks-block-time - last-update`) keeps growing, but is never applied to the index because `accrue` short-circuits and never updates `last-update`.
3. When `accrue` is unpaused via `set-pause-states`, the transition code jumps `last-update` directly to the current time: [3](#0-2) 

```clarity
(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))
  (begin
    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      (if (and (not was-paused) now-paused)
          (begin (try! (accrue)) false)
          false)
      (if (and was-paused (not now-paused))
          (var-set last-update stacks-block-time)
          false)
      (var-set pause-states states)
      ...
```

The `(var-set last-update stacks-block-time)` on unpause permanently discards the interest window that elapsed during the pause, for whatever principal was outstanding at that time (including principal added/removed *during* the pause via still-active borrow/repay). This is the "pause that passes through instead of reverting" pattern: instead of reverting borrow/repay operations that depend on a correctly-accruing index while that index is paused, the code lets them silently succeed against a stale value, and the un-pause logic then erases the entire missed accrual period rather than catching it up.

### Impact Explanation
Lenders (zToken holders) permanently lose the yield that should have accrued on the debt outstanding during the `accrue`-paused window — this is unclaimed-yield freezing/loss, which is explicitly an in-scope High-impact category ("permanent freezing of unclaimed yield"). Because `principal-scaled`/`total-borrowed` can keep changing via `system-borrow`/`system-repay` while `accrue` is paused (their gating flags are separate), the amount of principal exposed to this zero-interest window is not bounded to whatever it was at the moment of pausing — new borrows opened during the pause earn a completely free ride until unpause, and the reset of `last-update` on unpause makes this loss permanent rather than temporary.

### Likelihood Explanation
This requires only a single, ordinary operational action already supported by the contract's design: the DAO/authorized caller invoking `set-pause-states` with `accrue: true` while leaving `borrow`/`repay` unset (false). This is a legitimate, intended operational lever (e.g., "pause accrual to adjust IR curve"), not a compromise of the DAO — the DAO is exercising a documented, in-scope capability, so it is not excluded by the "DAO compromise" carve-out. Any borrow/repay/deposit/redeem transaction that occurs while `accrue` alone is paused reaches this code path deterministically within a single transaction/evaluation, satisfying the single-transaction analog requirement.

### Recommendation
Either (a) have `system-borrow`, `system-repay`, `deposit`, and `redeem` also revert when `accrue` itself is paused (since they all depend on an up-to-date index), or (b) make `accrue`'s pause branch not skip index math but instead defer only the reserve/treasury minting side-effects, while still catching up `last-update`/`index`/`lindex` to reflect true elapsed time so no interest is silently discarded. At minimum, on unpausing, apply the accrual retroactively for the paused interval instead of resetting `last-update` to `stacks-block-time` unconditionally.

### Proof of Concept
1. DAO calls `set-pause-states` on `v0-vault-sbtc` with `{..., accrue: true, borrow: false, repay: false, ...}` — `accrue` is now paused, `borrow`/`repay` remain active.
2. User A calls `borrow` (via market) → market calls `vault-accrue`/`system-borrow` → `accrue()` returns the stale `{index, lindex}` without reverting → `principal-scaled` increases at the current, frozen `idx`.
3. Time passes (many blocks); real interest that should compound on this new debt is never applied because `last-update` never advances while `accrue` is paused.
4. DAO calls `set-pause-states` again with `accrue: false` → `set-pause-states` executes `(var-set last-update stacks-block-time)`, wiping out the entire elapsed period's interest obligation for User A's debt and any other principal outstanding at that time.
5. Net effect: zToken holders receive no yield for that period on the debt that existed during the pause, and it can never be recovered, since `last-update` has already been advanced past that interval. [4](#0-3)
