## Finding

### Title
Unhandled fee-token `transfer()` revert in `charge_fee` can abort Starknet OS re-execution and halt block proving - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/transaction_impls.cairo])

### Summary
The reported bug class is DoS caused by unconditional reliance on an ERC20 `transfer()`/`transferFrom()` call that can revert (e.g. a paused token), breaking a core protocol flow. The sequencer's analog is the fee-charging flow: both the blockifier (Rust) and the Starknet OS (Cairo, used for re-execution/proving) unconditionally invoke the fee token's `transfer` entry point as part of processing every transaction, and the OS path is explicitly built to **not tolerate a revert** of that call.

### Finding Description
In the Starknet OS, `charge_fee` builds a `TransferCallData` and executes the fee token's `transfer` entry point via `non_reverting_select_execute_entry_point_func`: [1](#0-0) 

That helper is explicitly documented as not supporting reverts, and it hard-asserts that the inner call did not revert: [2](#0-1) 

`assert is_reverted = 0;` means that if the fee-token `transfer` call reverts for any reason (insufficient balance not otherwise caught, a token blocklist/pause condition, or any state divergence between the sequencer's Rust execution and the OS's Cairo re-execution using the `LoadActualFee` hint), the OS program itself fails to complete — it cannot merely "revert the transaction" like normal execution does. This is different from the blockifier (Rust) fee-transfer path, which wraps failures in a typed error and propagates them via `Result`: [3](#0-2) 

The Rust side's `PostExecutionReport` checks account balance sufficiency before calling `execute_fee_transfer` (see `test_revert_on_overdraft`), and normally guarantees the transfer succeeds: [4](#0-3) 

However, the fee token contract itself is external to the sequencer's control-flow guarantees; the sequencer can only check the on-chain balance/allowance state, not guarantee that the token's `transfer` logic won't add extra conditions (e.g. a blocklist, pause switch, or any other divergent behavior) that cause it to revert despite sufficient balance. If a transaction is admitted and included into a block by the sequencer under such a condition, the block becomes **unprovable**: the Starknet OS re-execution of that same block will hit the `assert is_reverted = 0` in `non_reverting_select_execute_entry_point_func` and fail entirely, rather than gracefully marking that one transaction as reverted.

### Impact Explanation
A single block containing such a transaction cannot be proven by the Starknet OS, since the assertion aborts OS execution for the whole block rather than only the offending transaction. This blocks that block (and potentially all subsequent ones dependent on state committed from it) from being confirmed/finalized on L1, i.e., a network unable to confirm new transactions/blocks — a materially more severe consequence than the original report's per-protocol repay/liquidation DoS, because it affects the sequencer's core commit/prove pipeline rather than a single dApp's function calls.

### Likelihood Explanation
Likelihood is constrained by the fact that the fee token address is a fixed, protocol-controlled contract (STRK/ETH bridge tokens), so an ordinary unprivileged sender cannot arbitrarily pause it. However, the same class of vulnerability (unconditional trust that an external ERC20 `transfer()` call succeeds, with no fallback/graceful-revert path) is embedded directly in the `charge_fee` code path that every transaction goes through, and the "non-reverting" design choice is exactly the anti-pattern flagged in the source report: a component that assumes a transfer call can never revert.

### Recommendation
Have `charge_fee` (and `non_reverting_select_execute_entry_point_func` usage for fee transfers) tolerate a reverted fee-transfer call gracefully, e.g., by treating it as a transaction-level revert (as `select_execute_entry_point_func` does elsewhere) instead of asserting `is_reverted = 0` unconditionally, so that a misbehaving/paused fee token cannot abort OS re-execution of an entire block.

### Proof of Concept
1. A transaction whose actual fee, sender balance, and allowance pass the blockifier's Rust-side `PostExecutionReport` checks is included by the sequencer in a block.
2. If the fee token's `transfer` implementation reverts under some condition not modeled by the blockifier's balance/allowance checks (e.g. blocklist, pause flag, reentrancy guard), the block is nonetheless built and gossiped.
3. When the Starknet OS re-executes the block to generate the proof, `charge_fee` calls `non_reverting_select_execute_entry_point_func`, which asserts `is_reverted = 0`; since the transfer reverted, this assertion fails and OS execution for the whole block aborts, preventing block proving/finalization. // If max_fee is not 0, validates that the selector matches the entry point of an account contract
// and executes an ERC20 transfer on the behalf of that account contract.

// Arguments:
// block_context - a global context that is fixed throughout the block.
// tx_execution_context - The execution context of the transaction that pays the fee.
func charge_fee{

    builtin_ptrs: BuiltinPointers*,

    alloc_locals;

    local tx_info: TxInfo* = tx_execution_context.execution_info.tx_info;

    local low_actual_fee;

    local calldata: TransferCallData = TransferCallData(

    // Verify that the charged amount is not larger than the transaction's max_fee field.

    );
    let (__fp__, _) = get_fp_and_pc();
    // Use block_info directly from block_context, so that charge_fee will always run in
    // execute-mode rather than validate-mode.

            contract_address=fee_token_address,
            selector=TRANSFER_ENTRY_POINT_SELECTOR,

        deprecated_tx_info=tx_execution_context.deprecated_tx_info,

    let remaining_gas = DEFAULT_INITIAL_GAS_COST;
    non_reverting_select_execute_entry_point_func{remaining_gas=remaining_gas}(
        block_context=block_context, execution_context=&execution_context

// Same as `select_execute_entry_point_func`, but does not support reverts and does
// not have an implicit 'revert_log' argument.
func non_reverting_select_execute_entry_point_func{
    range_check_ptr,
    remaining_gas: felt,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, execution_context: ExecutionContext*) -> (
    retdata_size: felt, retdata: felt*, is_deprecated: felt
) {
    let revert_log = init_revert_log();
    let (is_reverted, retdata_size, retdata, is_deprecated) = select_execute_entry_point_func{
        revert_log=revert_log
    }(block_context=block_context, execution_context=execution_context);
    assert is_reverted = 0;
    return (retdata_size, retdata, is_deprecated);
}

    fn execute_fee_transfer(
        state: &mut dyn State,
        tx_context: Arc<TransactionContext>,
        actual_fee: Fee,
    ) -> TransactionExecutionResult<CallInfo> {
        // The least significant 128 bits of the amount transferred.
        let lsb_amount = Felt::from(actual_fee.0);
        // The most significant 128 bits of the amount transferred.
        let msb_amount = Felt::ZERO;

        let TransactionContext { block_context, tx_info } = tx_context.as_ref();
        let storage_address = tx_context.fee_token_address();
        // The fee contains the cost of running this transfer, and the token contract is
        // well known to the sequencer, so there is no need to limit its run.
        let mut remaining_gas_for_fee_transfer =
            block_context.versioned_constants.os_constants.gas_costs.base.default_initial_gas_cost;
        let fee_transfer_call = CallEntryPoint {
            class_hash: None,
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector_from_name(constants::TRANSFER_ENTRY_POINT_NAME),
            calldata: calldata![
                *block_context.block_info.sequencer_address.0.key(), // Recipient.
                lsb_amount,
                msb_amount
            ],
            storage_address,
            caller_address: tx_info.sender_address(),
            call_type: CallType::Call,

            initial_gas: remaining_gas_for_fee_transfer,
        };
        let mut context = EntryPointExecutionContext::new_invoke(
            tx_context,
            true,
            SierraGasRevertTracker::new(GasAmount(remaining_gas_for_fee_transfer)),
        );

        Ok(fee_transfer_call
            .execute(state, &mut context, &mut remaining_gas_for_fee_transfer)
            .map_err(|error| Box::new(TransactionFeeError::ExecuteFeeTransferError(error)))?)
    }
