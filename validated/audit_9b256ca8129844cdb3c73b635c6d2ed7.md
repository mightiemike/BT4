### Title
Direct `MsgExecutePayload` path skips the CacheContext atomicity fix applied to `ExecutePayloadV2`, allowing free EVM execution when gas-fee deduction fails - (File: `x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`x/uexecutor` has two nearly-identical code paths that run a UEA payload and then bill the UEA for gas: `ExecutePayloadV2` (`x/uexecutor/keeper/execute_payload.go`) and `ExecutePayload` (`x/uexecutor/keeper/msg_execute_payload.go`). Only the former wraps the EVM call and `DeductGasFeesFromReceipt` in a `sdk.Context.CacheContext()` so a failed fee deduction discards the EVM state change. The latter — which is the one actually wired to the live, gasless, user-reachable `MsgExecutePayload` message — performs the EVM call directly on `sdkCtx` and only returns an error on fee-deduction failure, reproducing the exact "fixed one path, not its side effects elsewhere" pattern described in the source report.

### Finding Description
`x/uexecutor/keeper/execute_payload.go` (`ExecutePayloadV2`) explicitly documents a prior vulnerability class and its fix: [1](#0-0) 

The comment states plainly that without the `CacheContext` wrapper, "EVM state changes from `CallUEAExecutePayload` are discarded" only because of the cache — implying that *without* it, a failed fee deduction does **not** roll back the already-executed EVM call. This is the same class of bug used elsewhere in the repo, e.g. `x/uexecutor/keeper/execute_inbound_funds_and_payload.go` and `execute_inbound_gas_and_payload.go`, both of which independently apply the same `CacheContext` pattern with the comment "closes the free-execution gap when the recipient contract has no native UPC to cover gas." [2](#0-1) 

However, `x/uexecutor/keeper/msg_execute_payload.go`'s `ExecutePayload` — the function invoked directly by `msgServer.ExecutePayload` for the live, user-submitted `MsgExecutePayload` message — was never updated with this fix. It calls `CallUEAExecutePayload` on the raw `sdkCtx`, then attempts fee deduction, and only on failure returns an error, with no compensating cache/rollback of the already-applied EVM state: [3](#0-2) 

This is wired directly to the message handler: [4](#0-3) 

`MsgExecutePayload` is a gasless-whitelisted message type, reachable by any unprivileged account, and requires no Cosmos-level fee: [5](#0-4) 

Fee for the actual EVM work is billed separately, from the UEA's own native balance, via `DeductGasFeesFromReceipt`: [6](#0-5) 

### Impact Explanation
Because `ExecutePayload` (the live path) does not cache-wrap the EVM call + fee deduction the way `ExecutePayloadV2` does, an attacker holding, or targeting, a UEA with zero (or insufficient) native `upc` balance can submit a valid, signature-authenticated `MsgExecutePayload` whose EVM execution (`CallUEAExecutePayload` → `executeUniversalTx` on the UEA) commits to state even though `DeductGasFeesFromReceipt` subsequently fails for insufficient funds. If, as the sibling fixes strongly imply, `DerivedEVMCall`'s underlying commit is not automatically undone merely because the parent keeper function later returns an error, the payload's EVM side effects (arbitrary contract calls, token transfers, PRC20 movements, further outbound-triggering calls, etc., all funded by protocol/module gas) persist while the requester never pays for the gas consumed. This is unauthorized/unbilled UEA execution and gas-fee accounting corruption reachable by an ordinary unprivileged user with no attacker-controlled balance requirement, matching the in-scope impact "corruption of ... gas fee accounting ... or unauthorized UEA or CEA execution."

### Likelihood Explanation
High, if the underlying assumption behind the sibling fixes holds (that `DerivedEVMCall`/EVM StateDB commits are not implicitly undone by a Go-level error return from the enclosing keeper call). The pattern is trivially reachable: any account can submit `MsgExecutePayload` for a UEA with insufficient native balance, the message is gasless so it costs the attacker nothing to send repeatedly, and no privileged actor or validator misbehavior is required.

Caveat / uncertainty: I could not directly inspect the `pushchain/evm` fork's `DerivedEVMCall` implementation (it lives in an external repository pinned via `go.mod replace`, outside this indexed codebase), so I cannot with 100% certainty confirm that its `commit=true` state writes bypass normal Cosmos SDK tx-level rollback-on-error. However, the presence of near-identical `CacheContext` fixes in three separate call sites (`ExecutePayloadV2`, `execute_inbound_funds_and_payload.go`, `execute_inbound_gas_and_payload.go`), each with an explicit comment describing exactly this "free execution gap," is strong first-party evidence that the underlying commit does escape ordinary rollback and that the missing fourth site (`msg_execute_payload.go`) is a genuine oversight of the kind the report describes.

### Recommendation
Apply the same `CacheContext` pattern used in `ExecutePayloadV2` to `x/uexecutor/keeper/msg_execute_payload.go`'s `ExecutePayload`: wrap `CallUEAExecutePayload` and `DeductGasFeesFromReceipt` in a single `sdkCtx.CacheContext()`, only calling `writeCache()` when both the EVM call and fee deduction succeed, ensuring the UEA's EVM state mutation and the corresponding gas bill are atomic. Alternatively, refactor so the direct `MsgExecutePayload` message handler calls `ExecutePayloadV2` instead of maintaining a diverging, unpatched duplicate code path.

### Proof of Concept
1. Deploy or identify a UEA with `0` native `upc` balance (any freshly-created UEA before it's funded, or one drained to zero).
2. Craft a valid `UniversalPayload` + `verificationData` that the UEA's `executeUniversalTx` will accept (correct signature/nonce/deadline over the owner's key) and whose `Data` performs some state-mutating call (e.g., transferring PRC20 tokens the UEA holds, or calling into another contract).
3. Submit `MsgExecutePayload` with this payload as any `Signer` account (message is gasless, so no Cosmos fee is required from the attacker).
4. `ms.k.ExecutePayload` (`x/uexecutor/keeper/msg_execute_payload.go`) calls `CallUEAExecutePayload(sdkCtx, ...)` directly, executing the payload against live EVM state.
5. `DeductGasFeesFromReceipt` subsequently fails because the UEA has no `upc` balance to cover `gasCost`; `ExecutePayload` returns `"gas fee deduction failed: ..."`.
6. Query the EVM state (recipient balances, contract storage touched by the payload) to check whether the mutation from step 4 persisted despite the error in step 5 — if it persisted, unbilled/unauthorized EVM execution has occurred, confirming the vulnerability. (This final on-chain confirmation step requires actually running the node, which was not possible from static analysis alone.)

```go
	// Step 2: Wrap EVM execution + fee deduction in a CacheContext so they
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr
	}
```

```go
// ExecutePayload handles universal payload execution on the UEA.
func (ms msgServer) ExecutePayload(ctx context.Context, msg *types.MsgExecutePayload) (*types.MsgExecutePayloadResponse, error) {
	_, evmFromAddress, err := utils.GetAddressPair(msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to parse signer address")
	}

	err = ms.k.ExecutePayload(ctx, evmFromAddress, msg.UniversalAccountId, msg.UniversalPayload, msg.VerificationData)
	if err != nil {
		return nil, err
	}

	return &types.MsgExecutePayloadResponse{}, nil
}
```

```go
// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```
