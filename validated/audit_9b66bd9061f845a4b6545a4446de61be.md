### Title
Class-hash collision via unscoped regex-based text rewriting in deprecated (Cairo 0) `hinted_class_hash` computation - ([File: crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs])

### Summary
`add_backward_compatibility_space` in `crates/starknet_os/src/hints/class_hash/hinted_class_hash.rs` uses four naive, string-scoped regexes to rewrite the fully-serialized JSON of a deprecated (Cairo 0) contract class before hashing it into `hinted_class_hash`. Because the regexes match on raw substrings (`"cairo_type"` / `"value"` immediately followed by `: "…"`) anywhere in the entire serialized blob rather than on the actual AST location of the `reference_manager`/`attributes` type fields, an attacker-controlled Cairo 0 class definition can contain unrelated, fully declarer-controlled string content (e.g. `attributes[].value`, `identifiers`, `hints` entries, which are typed as `serde_json::Value`/`String` with no schema restriction) that incidentally matches these patterns. This is directly analogous to the reported Mail CVE: a single, overly permissive text match/substitution is applied to a serialized blob without being anchored to the true structural boundary, allowing crafted input to make the "decoded"/rewritten value diverge from what the reviewer (or, here, another computation of the same hash) would expect. [1](#0-0) 

### Finding Description
`compute_cairo_hinted_class_hash` serializes the entire `CairoContractDefinition` (including attacker-supplied `attributes`, `hints`, `identifiers`, `reference_manager` and other free-form `serde_json::Value` fields) to a single JSON string and, for classes without a `compiler_version` (i.e. old Cairo 0 classes), post-processes that whole string with `add_backward_compatibility_space` before hashing it with Keccak256: [2](#0-1) 

The rewriting regexes are unscoped — they operate on the raw text of the *entire* serialized document, not on a parsed/typed view of the `reference_manager` type-annotation fields they are meant to fix:

```rust
let cairo_regex = Regex::new(r#""cairo_type"\s*:\s*"\(([^"]*)\)""#).unwrap();
let value_regex = Regex::new(r#""value"\s*:\s*"(.*?)""#).unwrap();
``` [3](#0-2) 

Several struct fields that are fully attacker-controlled during a `Declare` of a deprecated class are serialized as generic JSON and can therefore contain arbitrary literal text, including strings that happen to match `"value": "(...)"` or `"cairo_type": "(...)"` without being an actual Cairo type annotation: [4](#0-3) 

Because the regex substitution is applied by pure text pattern-matching (not scoped by field path/AST position), a declarer can construct two different Cairo 0 programs whose *distinct* pre-image content (e.g., differing debug strings, hint metadata, or attribute values) get normalized by this transform into an *identical* post-processed byte string, or can cause a legitimate program's non-type-related string content to be mutated unexpectedly. Since `hinted_class_hash` is subsequently mixed, unmodified, directly into the on-chain `class_hash` computation: [5](#0-4) 

and this same routine is re-executed inside the Starknet OS when loading deprecated compiled-class facts for proving/re-execution: [6](#0-5) 

any place where this text-based transform behaves non-uniquely (collision) or diverges from any other place in the pipeline that independently derives/validates the same class hash produces a class-identity value (`class_hash`) that does not faithfully and uniquely represent the underlying bytecode/hints of the declared class — the same failure mode as the CVE, where a naive text transform crossed intended boundaries and produced a decoded value inconsistent with the raw input.

### Impact Explanation
`class_hash` is a core identity value: it is committed to state on `Declare`, is used to validate `DeployAccount`/`deploy` `contract_address` derivation, and is recomputed by the Starknet OS during re-execution as part of state-root/block-hash computation. If crafted attacker-controlled JSON content (fully reachable from an unprivileged `Declare` transaction of a deprecated class) can make this unscoped regex rewrite two distinct class definitions into the same hashed bytes, that is a `class_hash` collision — enabling a class whose real bytecode/hints differ from what a reviewer or another contract (e.g. one pinned to a specific `class_hash`) expects, which can be leveraged for unauthorized contract-identity substitution. At minimum, any divergence between the value computed here and any other computation path of the same logical hash (e.g. across a future refactor, or between the OS's own recomputation and a cached/committed value) produces a wrong committed class hash / state root, i.e., honest-node divergence.

### Likelihood Explanation
Reachable by any account able to submit a `Declare` transaction for a deprecated (Cairo 0) contract class — no special privilege required. The attacker fully controls the JSON content of `program.attributes[].value`, `program.hints` entries, and other generic `serde_json::Value` fields that get serialized into the very same text blob the regex operates on, making it straightforward to embed lookalike `"value": "(...)"` / `"cairo_type": "(...)"` substrings outside their intended structural context.

### Recommendation
Do not run `add_backward_compatibility_space` as an unscoped string transform over the entire serialized document. Instead, walk the typed `reference_manager`/type-annotation structures directly (or restrict the regex application strictly to the known `reference_manager.references[].value.cairo_type` paths using structured JSON traversal) so the transform can only ever touch the intended type-annotation strings and cannot be triggered by attacker-controlled content in unrelated fields (`attributes[].value`, `hints`, `identifiers`, etc.). Add fuzz/differential tests that submit adversarial attribute/hint content designed to spoof the regex markers and assert the resulting hash matches a reference (non-regex, structural) implementation.

### Proof of Concept
1. Construct a deprecated (Cairo 0) `ContractClass` JSON where `program.attributes` contains an `AttributeScope` whose `value` field is the literal string `"\": \"(a: felt)"` appended with a stray leading quote sequence, e.g. crafted so that after serialization the byte sequence directly preceding this attribute's own `"value": "..."` key looks like `"value": "(x: felt)"` for a *different*, unrelated attribute purpose (not a type annotation).
2. Call `compute_cairo_hinted_class_hash` on this crafted class and on a second, semantically different class engineered so both produce byte-identical output after `add_backward_compatibility_space` runs its global `replace_all` over the whole JSON text (e.g., by using different original spacing/content that the regex normalizes to the same rewritten substring).
3. Observe that `compute_deprecated_class_hash` (which folds `hinted_class_hash` into the final `class_hash`) returns the same `class_hash` for two distinct contract class definitions, demonstrating the collision, or that the same class's hash differs from a hash computed by scoping the transform correctly to `reference_manager` fields only — demonstrating the divergence root cause.

Note: full exploitation to a concrete state-root divergence would additionally require confirming whether any other component in this codebase (e.g. gateway/blockifier) independently recomputes this hash using different logic; that cross-component comparison could not be fully verified with the available search tools within this session, and is flagged as an open item for a background agent with full repository access to confirm.

pub fn compute_cairo_hinted_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    // Serialize to Value, sort all objects by keys for deterministic output, then to bytes.
    // The sorting is necessary because serde_json with `preserve_order` feature enabled
    // maintains insertion order instead of sorting keys.
    // TODO(Meshi): Compute hinted hashes when loading serialized contracts from storage, before
    // deserializing, to avoid back-and-forth serde.
    let contract_value = serde_json::to_value(contract_class)?;
    let sorted_contract_value = sort_json_value(contract_value);
    let contract_definition_vec = serde_json::to_vec(&sorted_contract_value)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let mut string_buffer = vec![];

    let mut ser = serde_json::Serializer::with_formatter(&mut string_buffer, PythonJsonFormatter);
    contract_definition.serialize(&mut ser)?;

    let mut raw_json_output = String::from_utf8(string_buffer)?;
    if contract_definition.program.compiler_version.is_none() {
        add_backward_compatibility_space(&mut raw_json_output);
    }

    let mut keccak_writer = KeccakWriter::default();
    keccak_writer
        .write_all(raw_json_output.as_bytes())
        .expect("writing to KeccakWriter never fails");

    let KeccakWriter(hash) = keccak_writer;
    Ok(truncated_keccak(<[u8; 32]>::from(hash.finalize())))
}

/// Adds space before the colon when formatting named tuple types.
/// This should be used for backward compatibility in the contract hash computation in versions
/// before 0.10.0.
/// For example, use "(a : felt)" instead of "(a: felt)".
pub fn add_backward_compatibility_space(input: &mut String) {
    let cairo_regex = Regex::new(r#""cairo_type"\s*:\s*"\(([^"]*)\)""#).unwrap();
    let value_regex = Regex::new(r#""value"\s*:\s*"(.*?)""#).unwrap();
    let paren_regex = Regex::new(r"\(([^()]+)\)").unwrap();
    let pair_regex = Regex::new(r"([^:\s,]+):\s*([^,\s)]+)").unwrap();

    // Fix cairo_type, which must be a single type (either a simple type or a tuple).
    *input = cairo_regex
        .replace_all(input, |caps: &regex::Captures<'_>| {
            let inner = &caps[1];
            let fixed = pair_regex.replace_all(inner, "$1 : $2");
            format!("\"cairo_type\": \"({fixed})\"")
        })
        .into_owned();

    // Fix only (key: value) pairs inside (...) in "value".
    *input = value_regex
        .replace_all(input, |caps: &regex::Captures<'_>| {
            let raw_value = &caps[1];
            let fixed = paren_regex
                .replace_all(raw_value, |paren_caps: &regex::Captures<'_>| {
                    let inner = &paren_caps[1];
                    let fixed_inner = pair_regex.replace_all(inner, "$1 : $2");
                    format!("({fixed_inner})")
                })
                .into_owned();
            format!("\"value\": \"{fixed}\"")
        })
        .into_owned();
}

pub fn compute_deprecated_class_hash(
    contract_class: &ContractClass,
) -> Result<Felt, HintedClassHashError> {
    let hinted_class_hash = compute_cairo_hinted_class_hash(contract_class)?;
    let contract_definition_vec = serde_json::to_vec(contract_class)?;
    let contract_definition: CairoContractDefinition<'_> =
        serde_json::from_slice(&contract_definition_vec)?;

    let FlatEntryPointFelts { external, l1_handler, constructor } =
        get_flat_entry_point_felts(&contract_definition.entry_points_by_type);
    let builtins = ascii_strs_as_felts(&contract_definition.program.builtins);
    let bytecode = hex_strs_as_felts(&contract_definition.program.data);

    let mut hash_state = HashState::<Pedersen>::new();
    hash_state.update_single(&DEPRECATED_COMPILED_CLASS_VERSION);
    hash_state.update_with_hashchain(&external);
    hash_state.update_with_hashchain(&l1_handler);
    hash_state.update_with_hashchain(&constructor);
    hash_state.update_with_hashchain(&builtins);
    hash_state.update_single(&hinted_class_hash);
    hash_state.update_with_hashchain(&bytecode);
    Ok(hash_state.finalize())
}
