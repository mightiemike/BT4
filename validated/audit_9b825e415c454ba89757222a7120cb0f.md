### Title
Flat gas charge for variable-length Ed25519 message verification breaks gas/CPU-time proportionality — (File: precompiles/usigverifier/usigverifier.go, query.go)

### Summary
`VerifyEd25519RawMessage`'s `RequiredGas` is a fixed 4000 regardless of `message` length, while the underlying `ed25519.Verify` call performs SHA-512 hashing whose CPU cost is linear in message size. An unprivileged caller can invoke this precompile repeatedly with large `message` payloads (from a looping contract that reuses already-allocated calldata/memory so it avoids repaying EVM memory-expansion costs) inside a single transaction, causing execution time to grow with `n * len(message)` while gas billed only grows with `n * 4000`.

### Impact Explanation
This falls under the in-scope "denial of service only when it is not network-level and is reachable without privileged control" category. Because gas does not track actual CPU work, an attacker can construct a transaction that consumes disproportionate validator CPU time relative to the gas paid, degrading block-processing throughput for honest validators executing that transaction. This is a liveness/performance concern rather than a fund-loss or consensus-safety issue, so its severity is bounded — no funds are stolen, no state is corrupted, and no consensus divergence occurs (all validators execute identically, so no fork risk), but honest block production/execution time is negatively impacted, which is the impact category explicitly permitted by the scope for non-network-level DoS.

### Likelihood Explanation
Reachable via ordinary unprivileged contract calls — no special privileges, validator, or off-chain component control needed. The realistic amplification is bounded in practice: EVM memory-expansion gas is quadratic, so allocating very large `message` buffers in the caller's memory is itself expensive (this naturally caps how large a message an attacker can cheaply reuse across a loop), and each CALL still costs base call overhead (~2600 gas) plus 4000 gas, limiting the number of iterations per block. So while the flaw is real, the achievable amplification factor is constrained by existing EVM cost mechanics for memory and call overhead, making this a moderate/likely-but-limited-impact issue rather than a severe one.

### Recommendation
Make `RequiredGas` for `verifyEd25519RawMessage` (and consider `verifyEd25519`, though its message is fixed at 32 bytes) scale with `len(message)`, e.g., `VerifyEd25519RawMessageGas + perByteGas*len(message)`, mirroring the linear-cost model used by other variable-length-input precompiles (SHA256/RIPEMD160) in go-ethereum, so gas charged is proportional to actual hashing work performed.

### Proof of Concept
A caller contract can:
1. Allocate a large `message` buffer once in memory (paying the one-time quadratic memory-expansion cost).
2. Loop `n` times, calling the precompile at `0xEC00...0001` with `verifyEd25519RawMessage(pubKey, message, signature)` reusing the same memory offset/size each iteration, paying only ~`(2600 CALL overhead + 4000 RequiredGas)` per iteration.
3. Total CPU cost across the transaction is `O(n * len(message))` SHA-512 work, while gas billed is `O(n * 4000)`, independent of `len(message)`.

This can be demonstrated with a Go benchmark directly invoking `Precompile.Run`/`RequiredGas` in a loop with large `message` byte slices under a fixed gas budget and measuring elapsed wall-clock time versus gas consumed, confirming the disproportion.

func (p Precompile) VerifyEd25519RawMessage(
	method *abi.Method,
	args []interface{},
) ([]byte, error) {

	pubKey, ok := args[0].([]byte)
	if !ok {
		return nil, fmt.Errorf("invalid pubKey type")
	}

	message, ok := args[1].([]byte)
	if !ok {
		return nil, fmt.Errorf("invalid message type")
	}

	signature, ok := args[2].([]byte)
	if !ok {
		return nil, fmt.Errorf("invalid signature type")
	}

	pubKeyBytes, err := getSolanaPubKeyFromAddress(pubKey)
	if err != nil {
		return nil, fmt.Errorf("failed to parse pubKey: %w", err)
	}

	if len(pubKeyBytes) != ed25519.PublicKeySize || len(signature) != ed25519.SignatureSize {
		return nil, fmt.Errorf("invalid params")
	}

	ok = ed25519.Verify(pubKeyBytes, message, signature)

	return method.Outputs.Pack(ok)
}
