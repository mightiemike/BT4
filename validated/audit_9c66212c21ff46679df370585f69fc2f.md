### Title
Unchecked/unguarded gas subtraction in `NativeSyscallHandler::pre_execute_syscall` can underflow — (File: `crates/blockifier/src/execution/native/syscall_handler.rs`)

### Summary
`pre_execute_syscall` computes `required_gas = total_gas_cost - self.gas_costs().base.syscall_base_gas_cost` as a plain `u64` subtraction, whereas the VM (non-native) syscall dispatcher performs the same computation but first asserts `syscall_gas_cost >= syscall_base_cost` before subtracting [3](#0-2) . The native path lacks this invariant check, mirroring the reported bug class: an unguarded subtraction that assumes an ordering invariant which is not locally enforced at the call site.

### Finding Description
`total_gas_cost` passed into `pre_execute_syscall` is derived per-syscall, e.g. for `deploy` and `meta_tx_v0` it is `base + linear_factor * calldata.len()` [4](#0-3) , and for fixed-cost syscalls it is `self.gas_costs().syscalls.X.base_syscall_cost()` [5](#0-4) . The invariant that every syscall's total cost is `>= syscall_base_gas_cost` is only enforced centrally when the versioned constants are constructed, via `base_gas = std::cmp::max(base_costs.syscall_base_gas_cost, base_gas)` [6](#0-5) . That `max()` clamp is applied to the syscall's *base* component, but it is not re-verified at the call site in the native handler the way the VM path does with its explicit `assert!`. If any code path constructs or overrides a `SyscallGasCost` (e.g. via `old_syscall_gas_cost_summary` deserializing raw JSON constants, or future versioned-constants updates) such that `total_gas_cost < syscall_base_gas_cost` for a given selector, the native handler's subtraction underflows silently (`u64` wraps in release builds, panics in debug builds), producing either: (a) a debug-build panic that crashes the sequencer node while processing an otherwise valid transaction (network unable to confirm new transactions / node divergence between debug and release builds), or (b) in release mode, a wrapped-around enormous `required_gas`, causing `*remaining_gas < required_gas` to spuriously trigger `OUT_OF_GAS_ERROR_FELT` for every subsequent syscall — silently reverting transactions that should have succeeded (identical class of "revert although it shouldn't" bug as the reported `getTokensNeededToAddEthValue` issue).

### Impact Explanation
Because Cairo Native execution is a first-class transaction execution path (`RunnableCairo1::Native`), this is reachable by any unprivileged transaction sender submitting a Cairo-1-Native class invocation. A wraparound (or panic) breaks either liveness (crash) or correctness (spurious out-of-gas reverts / honest-node divergence between native and VM execution of the same contract for the same syscall), which matches the "no vulnerability without concrete impact" bar via honest-node divergence and network-liveness risk.

### Likelihood Explanation
Today, with the current bundled versioned-constants JSON files, `new_syscall_gas_cost_summary`'s `max()` clamp keeps `base >= syscall_base_gas_cost` for every syscall, so the underflow is not currently triggerable with production constants. The bug is latent/defensive-in-depth-missing rather than immediately exploitable: it requires a future or alternate versioned-constants configuration (e.g. `old_syscall_gas_cost_summary`, used when `os_constants.syscall_gas_costs` is `Some(...)`, has no equivalent `max()` clamp) to produce a `total_gas_cost` below `syscall_base_gas_cost` for some syscall. Given the VM path was hardened with an explicit `assert!` (a recent-looking safety net, per the comment "Sanity check for preventing underflow"), the native path was apparently missed in that hardening pass, making this a real robustness gap rather than a purely theoretical one.

### Recommendation
Add the same defensive check used in `execute_syscall` to `NativeSyscallHandler::pre_execute_syscall`:
```rust
let base_cost = self.gas_costs().base.syscall_base_gas_cost;
assert!(total_gas_cost >= base_cost, "Syscall gas cost must be greater than base syscall gas cost");
let required_gas = total_gas_cost - base_cost;
```
or use `total_gas_cost.checked_sub(base_cost)` with an explicit error path, for parity between the native and VM syscall execution flows.

### Proof of Concept
Not independently reproducible against current mainnet versioned constants (the `max()` clamp in `new_syscall_gas_cost_summary` currently prevents `total_gas_cost < syscall_base_gas_cost`). A concrete PoC would require constructing a `VersionedConstants`/`GasCosts` value (e.g. via the legacy `old_syscall_gas_cost_summary` deserialization path, which has no equivalent clamp) where a syscall's `SyscallGasCost.base` is set below `syscall_base_gas_cost`, then invoking that syscall through a Cairo-Native contract; `pre_execute_syscall` would then underflow on `total_gas_cost - syscall_base_gas_cost`.
