### Title
`handle_poison_microblock` never checks `mblock_header_1.sequence == mblock_header_2.sequence`, allowing slashing of honest miners for normal, non-forking microblocks - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`StacksChainState::check_microblock_header_signer` (called from `handle_poison_microblock`) only verifies that the two supplied microblock headers were signed by the same key; it never checks that the headers occur at the same sequence number or otherwise represent an equivocation/fork. As a result, any two legitimately sequential microblocks from an honest miner's normal chain (e.g., sequence 5 and sequence 6) can be submitted as a "PoisonMicroblock" transaction and will be accepted and recorded via `insert_microblock_poison`.

### Finding Description
The claimed invariant "poison report recorded ⇔ two headers signed by the same key at the SAME sequence (equivocation)" is broken. The only validation performed before recording a report is in `check_microblock_header_signer` (transactions.rs:686-713), which recovers the public key from each header and compares `pkh1 != pkh2`: [1](#0-0) 

`handle_poison_microblock` (transactions.rs:722-883) calls this check at line 750-752 and, if it passes, proceeds directly to height/maturity checks and then unconditionally calls `insert_microblock_poison` using `mblock_header_1.sequence` as the reported sequence: [2](#0-1) [3](#0-2) 

Nowhere in this path is `mblock_header_1.sequence` compared to `mblock_header_2.sequence`, nor is it verified that the two headers actually diverge (different `prev_block`/content) at the same point in the stream. An attacker can therefore take two headers legitimately produced by an honest miner's own microblock stream — e.g., sequence 5 with `prev_block` pointing to microblock 4, and sequence 6 with `prev_block` pointing to microblock 5 — both signed by the same private key, and submit them as `mblock_header_1`/`mblock_header_2` in a `PoisonMicroblock` transaction. `check_microblock_header_signer` passes trivially (same key), the maturity check passes for a recently-produced key, and `insert_microblock_poison` records a slashable report at `mblock_header_1.sequence`, even though no fork or double-signing at the same sequence ever occurred.

### Impact Explanation
This allows an unprivileged attacker to trigger the on-chain poison-microblock commission/slashing machinery against a miner who never equivocated. Per the classification rules, "a poison or reward mis-payment bounded to fees" is a High severity finding (not Critical), since the loss is bounded to the punished miner's coinbase/commission rather than causing a chain split or double-payment of the full block reward across the network. The affected party is the honest miner whose microblock public key hash is punished; the attacker (any principal who observes two sequential microblock headers) gains the reporter's commission. This is repeatable against any miner whose microblock signing key is still within the `MINER_REWARD_MATURITY` window and produces at least two microblocks.

### Likelihood Explanation
No majority stake or privileged role is required — the attacker only needs to observe two microblock headers (both public data, gossiped as part of the miner's own honest microblock stream) and construct a `PoisonMicroblock` transaction. It requires the targeted key's microblock height to still be within `MINER_REWARD_MATURITY` blocks of the current height (checked at transactions.rs:783-802), which is routinely true for any actively-mining key. This is fully feasible with ordinary transaction-broadcast capability and no BTC/stake cost beyond a normal transaction fee.

### Recommendation
In `handle_poison_microblock` / `check_microblock_header_signer`, explicitly require `mblock_header_1.sequence == mblock_header_2.sequence` and that the two headers are distinct (different block hash / body) — i.e., verify a genuine equivocation at the same sequence number — before proceeding to `insert_microblock_poison`. Reject the transaction with `Error::InvalidStacksTransaction` otherwise.

### Proof of Concept
Rust integration test plan (e.g., in `stackslib/src/chainstate/stacks/db/transactions.rs` test module):
1. Generate a microblock signing keypair `k`.
2. Construct `mblock_header_1` with `sequence = 5`, `prev_block = hash(microblock_4)`, signed with `k`.
3. Construct `mblock_header_2` with `sequence = 6`, `prev_block = hash(microblock_5)` (i.e., `microblock_5` matches `mblock_header_1`'s resulting block), signed with `k` — representing normal, non-forking progression.
4. Assert as a precondition: `mblock_header_1.sequence != mblock_header_2.sequence` (5 != 6), confirming this is not an equivocation.
5. Build a `PoisonMicroblock` transaction using these two headers and call `StacksChainState::handle_poison_microblock` (or process the tx through `process_transaction_payload`) against a test chainstate where `pubkh` has a valid, unmatured `microblock_pubkey_hash_height`.
6. Assert the call currently returns `Ok(Value::Tuple(...))` and that `get_microblock_poison_report` now returns `Some((reporter, 5))` — demonstrating the honest miner is slashed despite no equal-sequence double-signature existing.
7. After applying the fix (adding the sequence-equality/distinctness check), re-run the same test and assert the transaction now returns `Err(Error::InvalidStacksTransaction(..))` and no poison report is recorded.

    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
