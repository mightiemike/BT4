Based on my research, there is a genuine analog to the CKB nondeterminism issue in this codebase: dual execution backends (Cairo Native vs Cairo VM/CASM) whose selection depends on **local, per-node, asynchronous cache state** rather than canonical chain state — and the codebase's own tests document that this class of divergence has occurred before.

### Title
Cairo Native vs CASM (Cairo VM) execution backend divergence causes non-deterministic transaction results across sequencer nodes - ([File: crates/blockifier/src/execution/execution_utils.rs])

### Summary
Each sequencer node independently and asynchronously decides whether to execute a given Cairo1 contract call using the AOT-compiled Cairo Native backend or the interpreted CASM (Cairo VM) backend, based on **local** configuration (`CairoNativeMode`, `NativeClassesWhitelist`) and the **timing** of background native compilation (`LazyCompilation`). This selection is not derived from canonical on-chain state, so different honest nodes can run the identical transaction through different execution engines. The codebase's own regression test comments confirm that Native and CASM execution have previously produced byte-different outputs (revert text) for the same Cairo1 program, and only that specific discrepancy has been patched — the general invariant is enforced only by best-effort tests, not by a runtime cross-check.

### Finding Description
The dispatch between backends happens in `execute_entry_point_call` in [1](#0-0) , which chooses native vs casm execution based on `context.tracked_resource_stack` and the `RunnableCompiledClass` variant currently cached for the class.

Which variant (`V1` casm vs `V1Native`) is cached is determined per-node by `NativeClassManager`/`ContractClassManager`:
- `CairoNativeMode` can be `Off`, `WaitOnCompilation`, or `LazyCompilation`, and is a **static, independently configurable per-node setting** [2](#0-1) .
- Under `LazyCompilation`, classes execute on CASM until an async background worker finishes native compilation, at which point later calls switch to Native [3](#0-2) , and compilation failures silently fall back to CASM (`CachedCairoNative::CompilationFailed`) unless `panic_on_compilation_failure` is set [4](#0-3) .
- `NativeClassesWhitelist` is also an independent per-node dynamic config value used directly in the batcher's block-building path (`preprocess_and_create_transaction_executor`) [5](#0-4) .

None of this timing/config state is part of consensus — it depends purely on each node's local process history, hardware speed of the async compiler thread, and static config file. This mirrors the CKB `load_cell_data_hash` bug class exactly: the underlying "correct" value (execution result) can be computed through two different code paths whose selection depends on non-canonical, per-node local state rather than deterministic protocol inputs.

Critically, this is not a purely theoretical concern: `crates/blockifier/src/execution/stack_trace_test.rs` contains an explicit regression test with a comment documenting a **real, previously-shipped divergence**: prior to a v0.14.3 patch, CASM execution emitted extra stack-trace lines (`Error at pc=0:443:` / `Error at pc=0:797:`) that Native execution never produced for the identical Cairo1 constructor revert [6](#0-5) . The invariant that Native and CASM outputs must match is otherwise enforced only by scattered unit tests, e.g. `test_builtin_counts_consistency` [7](#0-6) , not by any runtime cross-check or protocol-level constraint that would prevent a not-yet-discovered divergence from reaching production.

### Impact Explanation
If a submitted transaction's execution (revert message content included in the receipt, gas/resource consumption, builtin usage, or state writes) differs even slightly between the Native and CASM backends for some as-yet-undiscovered edge case (as has already happened once, per the codebase's own history), then:
- A sequencer proposing a block with `CairoNativeMode = LazyCompilation`/`WaitOnCompilation` may compute a state diff / receipt / gas usage that differs from what a validating node using CASM (because its native compiler hasn't finished, is disabled, or the class isn't in its whitelist) would compute for the same transaction.
- This causes wrong committed state root / block hash divergence between honest nodes, i.e., a network unable to reach consensus on the block — matching the "Critical" bar of honest-node divergence / inability to confirm new blocks, directly analogous to the CKB advisory's "nondeterministic tx-pool verification" impact.

### Likelihood Explanation
Any unprivileged actor can declare and invoke a Cairo1 contract (no privileged access required). Triggering an actual divergence requires finding an edge case where Native and CASM disagree — which the project's own test suite proves is possible (a real one shipped and had to be patched). Given the complexity of compiling Sierra to native machine code vs interpreting it in the Cairo VM (different code generation, different builtin/error-handling implementations), further undiscovered discrepancies (e.g., involving floating precision in future opcodes, panic formatting, gas metering rounding, builtin edge cases) are plausible, especially as `CairoNativeMode` moves toward broader production rollout (`LazyCompilation` is the crate's `#[cfg(feature = "cairo_native")]` default) [8](#0-7) .

### Recommendation
- Treat backend selection (Native vs CASM) as a pure performance optimization that must never be allowed to affect consensus-visible outputs; add a protocol-level/runtime safeguard (e.g., periodic canary re-execution comparing Native vs CASM outputs for the same call, or disabling Native for the block-building/validation path entirely until formally verified equivalent).
- Expand the invariant test suite (like `test_builtin_counts_consistency` and `test_revert_text_is_backend_invariant_for_sierra_gas`) to a fuzz/property-based test comparing Native and CASM outputs across a broad, randomly generated corpus of Cairo1 programs, not just hand-picked regression cases.
- Consider gating `CairoNativeMode` so that all nodes participating in consensus (proposers and validators) are required to run with byte-identical backend configuration for the same block height, removing the local/asynchronous nature of the choice from the hot path.

### Proof of Concept
A conceptual PoC (not executable from this analysis alone) would:
1. Declare a Cairo1 contract crafted to exercise an execution path where Cairo Native and Cairo VM(CASM) code generation differs (e.g., an edge case in panic/error formatting, gas accounting for a specific opcode/builtin sequence, or floating precision in a new builtin) — following the same class of bug already documented and fixed in `stack_trace_test.rs`.
2. Invoke the contract via a transaction.
3. Have one honest sequencer configured with `CairoNativeMode = LazyCompilation` (native already compiled and cached) execute/propose the block, while another honest validator with `CairoNativeMode = Off` (or whose native compilation hasn't completed) executes the same transaction via CASM.
4. Compare the resulting receipts/state diffs — a divergence (as previously observed for revert text) would cause the validator to reject a valid block or compute a different state root, causing honest-node divergence.

    /// Caches the compiled class.
    /// For Cairo 1 classes:
    /// * if Native mode is LazyCompilation, triggers async compilation to Native.
    /// * If Native mode is WaitOnCompilation, caches the Native variant immediately.
    pub fn set_and_compile(&self, class_hash: ClassHash, compiled_class: CompiledClasses) {
        match compiled_class {
            CompiledClasses::V0(_) => self.class_cache.set(class_hash, compiled_class),
            CompiledClasses::V1(compiled_class_v1, sierra_contract_class) => {
                if self.cairo_native_mode() == CairoNativeMode::WaitOnCompilation {
                    let compiler = self.compiler.as_ref().expect("Compiler not available.");
                    // After this point, the Native class should be cached and available through
                    // `get_runnable` access.
                    // Ignore compilation errors for now.
                    process_compilation_request(
                        self.class_cache.clone(),
                        compiler.clone(),
                        (class_hash, sierra_contract_class, compiled_class_v1),
                        self.cairo_native_run_config.panic_on_compilation_failure,
                    )
                    .unwrap_or(());
                    return;
                }

                // Cache the V1 class.
                self.class_cache.set(
                    class_hash,
                    CompiledClasses::V1(compiled_class_v1.clone(), sierra_contract_class.clone()),
                );

                if self.cairo_native_mode() == CairoNativeMode::LazyCompilation {
                    // Send a non-blocking compilation request.
                    // Ignore compilation errors for now.
                    self.send_compilation_request((
                        class_hash,
                        sierra_contract_class,
                        compiled_class_v1,
                    ))
                    .unwrap_or(());
                }
            }
            // TODO(Yoni): consider panic since this flow should not be reachable.
            CompiledClasses::V1Native(_) => self.class_cache.set(class_hash, compiled_class),
        }
    }

#[cfg(feature = "cairo_native")]
fn test_builtin_counts_consistency() {
    let test_contract_casm =
        FeatureContract::TestContract(CairoVersion::Cairo1(RunnableCairo1::Casm));
    let chain_info = &ChainInfo::create_for_testing();
    let mut casm_state = test_state(chain_info, BALANCE, &[(test_contract_casm, 1)]);

    let entry_point_call_casm = CallEntryPoint {
        entry_point_selector: selector_from_name("test_builtin_counts_consistency"),
        calldata: calldata![],
        ..trivial_external_entry_point_new(test_contract_casm)
    };

    let casm_call_info = entry_point_call_casm.execute_directly(&mut casm_state).unwrap();
    assert!(!casm_call_info.execution.failed, "CASM execution failed, {casm_call_info:?}");

    let expected_builtins = [
        BuiltinName::range_check,
        BuiltinName::pedersen,
        BuiltinName::poseidon,
        BuiltinName::keccak,
        BuiltinName::bitwise,
        BuiltinName::ec_op,
        BuiltinName::add_mod,
        BuiltinName::mul_mod,
        BuiltinName::range_check96,
    ];
    // Check that all builtins are covered by this test.
    for builtin in expected_builtins {
        assert!(
            casm_call_info.builtin_counters.get(&builtin.into()).copied().unwrap_or(0) > 0,
            "Builtin {builtin:?} was not called"
        );
    }

    let test_contract_native =
        FeatureContract::TestContract(CairoVersion::Cairo1(RunnableCairo1::Native));
    let mut native_state = test_state(chain_info, BALANCE, &[(test_contract_native, 1)]);

    let entry_point_call_native = CallEntryPoint {
        entry_point_selector: selector_from_name("test_builtin_counts_consistency"),
        calldata: calldata![],
        ..trivial_external_entry_point_new(test_contract_native)
    };

    let native_call_info = entry_point_call_native.execute_directly(&mut native_state).unwrap();
    assert!(!native_call_info.execution.failed, "Native execution failed");

    let casm_builtins = &casm_call_info.builtin_counters;
    let native_builtins = &native_call_info.builtin_counters;
    assert_eq!(
        casm_builtins, native_builtins,
        "Builtin usage should be identical between CASM and Native"
    );
}
