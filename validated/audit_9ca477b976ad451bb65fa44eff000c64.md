### Title
Blacklist-style PRC20 recipient permanently freezes bridged-back funds on failed outbound revert - (File: x/uexecutor/keeper/outbound.go)

### Summary
When an outbound fails on the destination chain, `handleFailedOutbound` re-mints the bridged PRC20 back to a revert recipient via `CallPRC20Deposit`. If that recipient is blacklisted by the PRC20's underlying token logic (e.g. a PRC20 wrapping a blacklist-capable asset like USDC), the deposit call reverts and the outbound is marked `ABORTED`, permanently freezing the user's principal pending manual/governance intervention, with no automatic retry path.

### Finding Description
`handleFailedOutbound` computes the revert recipient from `outbound.RevertInstructions.FundRecipient` (falling back to `outbound.Sender`) — both attacker/user-controlled fields set at inbound time — and calls `k.CallPRC20Deposit(ctx, ..., common.HexToAddress(recipient), amount)` to re-mint the bridged tokens back on Push Chain. [1](#0-0) 
If the deposit call errors (which happens if the underlying PRC20 contract enforces a blacklist and the recipient address is blacklisted), the code does not retry or route the funds elsewhere — it calls `AbortOutbound`, which sets `Status_ABORTED` and removes any pending index entry, requiring manual/governance resolution: [2](#0-1) 
The `x/uexecutor` README explicitly documents that stuck/aborted states are not auto-resolved: "there is no safe automatic resolution... resolution is governance-driven, not chain-driven." [3](#0-2) 
Separately, `applyGasRefund` (used for both successful and failed outbounds) sends any excess relayer gas fee back to `outbound.Sender` or `RevertInstructions.FundRecipient` via `CallUniversalCoreRefundUnusedGas`; if that call reverts, it is simply recorded as `PcRefundExecution.Status = "FAILED"` with no retry, permanently losing the excess-gas refund: [4](#0-3) 
Unlike the BendDAO analog, this does *not* block other users: `VoteOutbound` removes the entry from `PendingOutbounds` unconditionally *before* `FinalizeOutbound` runs, so a stuck/ABORTED outbound does not gate other outbounds or the TSS fund-migration pending check (`HasPendingOutboundsForChain`). [5](#0-4) 

### Impact Explanation
The impact is scoped to the specific UTX whose recipient is blacklisted: the bridged principal becomes permanently stuck in `ABORTED` state (no automated re-mint retry, no alternate recipient fallback) and the excess gas refund is permanently lost. This matches the in-scope "permanent freezing" / "permanent loss ... of user ... funds" impact category, but is a self-contained, single-transaction fund freeze rather than a network-wide DoS of other users' loans/auctions as in the original BendDAO finding — there is no cross-user blocking because `PendingOutbounds` is cleared before finalization runs.

### Likelihood Explanation
Requires a PRC20 whose native representation wraps or otherwise enforces blacklist-style transfer restrictions (e.g. a token config mapped to USDC or similar), and requires that either the original sender or the `RevertInstructions.FundRecipient` address supplied at inbound time later becomes blacklisted, or is deliberately set to an already-blacklisted/reverting address. Since `FundRecipient` is attacker/user-supplied at inbound submission time, an attacker can trivially set it to any known-blacklisted or reverting address to self-inflict (or grief) the freeze; likelihood of the underlying PRC20 supporting a blacklist depends on the specific token registered via `x/uregistry`.

### Recommendation
Wrap `CallPRC20Deposit` (in `handleFailedOutbound`) and `CallUniversalCoreRefundUnusedGas` (in `applyGasRefund`) reverts with a fallback path — e.g. retry against a rescue/escrow account, or expose an explicit admin/`RESCUE_FUNDS` recovery flow that doesn't require indefinite manual chain state — and clearly document that `ABORTED` outbounds require governance action, consistent with existing `RESCUE_FUNDS` tx type semantics already defined in the protocol. [6](#0-5) 

### Proof of Concept
1. Register (via `x/uregistry`, governance) a token whose PRC20 native representation forwards to/wraps an ERC20-like asset with blacklist semantics, or deploy a malicious PRC20-compatible contract that reverts transfers to a specific address.
2. Submit an inbound (`MsgVoteInbound`, `FUNDS` or `FUNDS_AND_PAYLOAD`) with `RevertInstructions.FundRecipient` set to an address that is blacklisted on that PRC20 (or will be blacklisted by the token issuer before the outbound resolves).
3. Trigger an outbound flow whose destination-chain execution fails (`MsgVoteOutbound` with `Success=false`) so `handleFailedOutbound` attempts `CallPRC20Deposit` to the blacklisted `FundRecipient`.
4. Observe `CallPRC20Deposit` revert, causing `AbortOutbound` to mark the outbound `Status_ABORTED` with no automated recovery — the bridged principal remains frozen pending manual/governance intervention. [7](#0-6)

// AbortOutbound marks an outbound as ABORTED with a reason.
// This signals that automatic processing has failed and manual intervention is needed.
func (k Keeper) AbortOutbound(ctx context.Context, utxId string, outbound types.OutboundTx, reason string) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	outbound.OutboundStatus = types.Status_ABORTED
	outbound.AbortReason = reason

	if err := k.UpdateOutbound(ctx, utxId, outbound); err != nil {
		return err
	}

	// Defensively remove from pending index (may already be removed by caller)
	_ = k.PendingOutbounds.Remove(ctx, outbound.Id)

	// Emit event for monitoring/alerting
	sdkCtx.EventManager().EmitEvent(sdk.NewEvent(
		"outbound_aborted",
		sdk.NewAttribute("utx_id", utxId),
		sdk.NewAttribute("outbound_id", outbound.Id),
		sdk.NewAttribute("abort_reason", reason),
	))

	return nil
}

func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
