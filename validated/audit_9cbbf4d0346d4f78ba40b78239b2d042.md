## Finding: Missing zero-address / sanity check on attacker-controlled `RevertInstructions.FundRecipient` in the inbound refund/revert path

### Title
Unvalidated `RevertInstructions.FundRecipient` allows a depositor to permanently burn their own bridged funds and gas refunds by targeting the zero address — ([File: x/uexecutor/keeper/build_revert_outbound.go])

### Summary
The external report's bug class ("constructor sets a critical address without a zero-address sanity check") has a direct analog in Push Chain's crosschain refund/revert flow. `RevertInstructions.FundRecipient` is a string supplied entirely by the depositor as part of the gateway event on the *source* chain — it flows through `Inbound.Canonicalize()` and `ValidateForExecution()` untouched, with no check that it isn't the zero address (or otherwise a burn/black-hole address), and is then used verbatim as the destination for reverted deposits and excess-gas refunds.

### Finding Description
`Inbound.RevertInstructions.FundRecipient` is populated from user-controlled calldata on the external chain (the depositor decides where refunds should go when they call the gateway). It is canonicalized but never validated: [1](#0-0) 

Neither `ValidateBasic()` nor `ValidateForExecution()` performs a non-zero-address check on `RevertInstructions.FundRecipient`: [2](#0-1) [3](#0-2) 

The unvalidated value is then used as the actual on-chain refund recipient in two places:
1. `buildRevertOutbound`, used whenever an inbound fails validation/execution and funds must be returned: [4](#0-3) 

2. `handleFailedOutbound` / `applyGasRefund`, used when an outbound fails on the destination chain and bridged tokens are re-minted, or excess gas is refunded: [5](#0-4) [6](#0-5) 

In all three call sites, the value is passed to `common.HexToAddress(...)` and used directly as a PRC20 mint destination or as an outbound `Recipient` broadcast back to the source chain, with no `address(0)` (or chain-specific null-address) guard — the exact class of defect the external report flags (unchecked critical address parameter).

### Impact Explanation
This falls under "unauthorized... permanent loss... permanent freezing... unauthorized refund of user or protocol-controlled funds" in the allowed impact gate. An unprivileged depositor who (accidentally or through a buggy/malicious integrating dApp) submits `revert_instructions.fund_recipient = 0x0000000000000000000000000000000000000000` (or any other unspendable address) with their deposit will, upon a validation failure, execution failure, or outbound revert, have their own bridged principal and/or excess gas refund routed by honest validators/honest nodes to that address — a state transition that is unrecoverable (PRC20 re-mint to `address(0)` reverts/burns depending on the token implementation; an outbound to the source chain with recipient `address(0)` permanently locks funds in the gateway/vault). Because honest validators/honest nodes execute this deterministically per protocol rules, this is not a privileged-actor or governance-abuse scenario — it is triggered purely by the depositor's own (or their integration's) unvalidated calldata, and it corrupts the canonical UniversalTx/outbound accounting by sending value to an address from which it can never be recovered.

### Likelihood Explanation
Any attacker (or careless integrator) controls the calldata of their own gateway deposit, including the encoded `revert_instructions`. Triggering a failure path (empty/invalid recipient for non-`isCEA` FUNDS, missing token config, failed autoswap on GAS inbound, or an OBSERVED-but-failed outbound) is straightforward and is exercised routinely in normal operation (see the existing revert/refund test suite), so the zero-address `fund_recipient` only needs to ride along with any one of these already-common failure conditions to be exploited.

### Recommendation
Add an explicit sanity check rejecting `RevertInstructions.FundRecipient` (and the `Inbound.Sender` fallback, defensively) when it canonicalizes to the chain's null/zero address, in `ValidateForExecution` (or `Canonicalize`) before the value is ever attached to a `UniversalTx`/`OutboundTx`. If detected, either reject the inbound outright (mirroring the empty-recipient FUNDS check already present) or fall back to a well-defined, auditable recovery destination instead of silently permitting the zero address.

### Proof of Concept
1. Depositor calls the gateway on an external EVM chain (e.g. `eip155:11155111`) with a `FUNDS` deposit and encodes `revert_instructions.fund_recipient = 0x0000000000000000000000000000000000000000`.
2. Universal Validators observe and vote the inbound via `MsgVoteInbound`; quorum is reached and the UTX is created; `Inbound.Canonicalize()` normalizes the zero-address string but does not reject it.
3. The deposit execution fails post-quorum (e.g. token config removed, or amount/token routing error) — `handleFailedInboundValidation` → `buildRevertOutbound` is invoked, setting `outbound.Recipient = "0x0000...0000"` (per `build_revert_outbound.go:11-14`) because `FundRecipient != ""`.
4. The `INBOUND_REVERT` outbound is signed by TSS and broadcast to the source chain with recipient `address(0)`, permanently burning the depositor's principal, exactly as demonstrated for the (non-zero) recipient case in `TestRevertStuckInbound_HappyPath_ExpiredBallot_CreatesRevertOutbound` — substitute the zero address for `revertRecipient` in that test to reproduce.

func (p Inbound) ValidateBasic() error {
	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)
	if chain == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}
	if !strings.Contains(chain, ":") {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain must be in CAIP-2 format <namespace>:<reference>")
	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")
	}

	// Validate sender — needed for revert recipient fallback
	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	// Validate log_index — needed for UTX key
	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}

	// Validate tx_type enum — needed to route execution
	if _, ok := TxType_name[int32(p.TxType)]; !ok || p.TxType == TxType_UNSPECIFIED_TX {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "invalid tx_type: %v", p.TxType)
	}

	return nil
}

// ValidateForExecution checks fields that are required for actual execution of the inbound.
// Called after ballot finalization, before ExecuteInbound. Failures here produce a failed
// PCTx and (for non-isCEA) a revert outbound, rather than dropping the vote.
func (p Inbound) ValidateForExecution() error {
	// Validate amount as uint256
	if strings.TrimSpace(p.Amount) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount cannot be empty")
	}
	bi, ok := new(big.Int).SetString(p.Amount, 10)
	if !ok || bi.Sign() < 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be a valid non-negative uint256")
	}
	// Only GAS_AND_PAYLOAD and FUNDS_AND_PAYLOAD allow zero amount (skip deposit, still execute payload)
	if bi.Sign() == 0 && p.TxType != TxType_GAS_AND_PAYLOAD && p.TxType != TxType_FUNDS_AND_PAYLOAD {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "amount must be positive for this tx type")
	}

	// Validate asset_addr
	if strings.TrimSpace(p.AssetAddr) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "asset_addr cannot be empty")
	}

	// isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD
	if p.IsCEA && p.TxType != TxType_FUNDS && p.TxType != TxType_FUNDS_AND_PAYLOAD && p.TxType != TxType_GAS_AND_PAYLOAD {
		return errors.Wrapf(sdkerrors.ErrInvalidRequest, "isCEA is only supported for FUNDS, FUNDS_AND_PAYLOAD, and GAS_AND_PAYLOAD tx types, got: %v", p.TxType)
	}

	// Validate fields required per tx_type
	switch p.TxType {
	case TxType_FUNDS_AND_PAYLOAD, TxType_GAS_AND_PAYLOAD:
		if p.UniversalPayload == nil {
			return errors.Wrap(sdkerrors.ErrInvalidRequest, "payload is required for payload tx types")
		}
		if p.IsCEA && strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty when isCEA is true")
		}
		if p.IsCEA && !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address when isCEA is true: %s", p.Recipient)
		}
		if err := p.UniversalPayload.ValidateBasic(); err != nil {
			return errors.Wrap(err, "invalid payload")
		}
	case TxType_FUNDS, TxType_GAS:
		if strings.TrimSpace(p.Recipient) == "" {
			return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be empty")
		}
		if !utils.IsValidAddress(p.Recipient, utils.HEX) {
			return errors.Wrapf(sdkerrors.ErrInvalidAddress, "invalid recipient address: %s", p.Recipient)
		}
	}

	return nil
}
