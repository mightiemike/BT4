### Title
Unauthenticated disclosure of internal plugin metrics and pprof data via `/plugins/:name/*` routes - ([File: core/web/router.go])

### Summary
`loopRoutes` registers `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly onto the `api` route group with no `auth.Authenticate` middleware, unlike sibling route groups (`debugRoutes`, authenticated `sessionRoutes` DELETE, `v2Routes`) which explicitly wrap themselves in a session-authenticated sub-group. The `api` group itself only applies rate limiting and cookie-session-store middleware — it never enforces that a valid session actually exists — so these three routes are reachable by any unauthenticated client.

### Finding Description
In `core/web/router.go`, the top-level `api` group is created with only rate limiting and `sessions.Sessions(...)` middleware: [1](#0-0) 
Note that `sessions.Sessions` only attaches a session store to the gin context for later retrieval; it performs no authentication check. Authentication is only actually enforced when a route/group explicitly wraps itself with `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`, as seen in `debugRoutes`: [2](#0-1) 
and in `sessionRoutes` for the `DELETE /sessions` endpoint: [3](#0-2) 

However, `loopRoutes` registers its handlers directly on the unauthenticated `api` group with no such wrapping: [4](#0-3) 

Correspondingly, `pluginMetricHandler` and `pluginPPROFHandler` in `core/web/loop_registry.go` perform no session/API-key check themselves — they only validate that the requested plugin name exists in the registry, then proxy the request to the plugin's internal Prometheus/pprof port and return the raw response body: [5](#0-4) [6](#0-5) 

Since neither the handler nor the route registration enforces authentication, and the enclosing `api` group provides no authentication guarantee (only session-store attachment), any unauthenticated network client that can reach the node's web server can invoke `GET /plugins/{name}/metrics` or `GET /plugins/{name}/debug/pprof/{profile}` and receive internal plugin runtime metrics and pprof profiling data intended only for node operators.

### Impact Explanation
This is unauthenticated disclosure of internal plugin runtime/profiling data (Prometheus metrics and Go pprof heap/goroutine/profile dumps), which can leak internal state, memory layout, function names, and operational details useful for reconnaissance or further attacks against the node — matching a "sensitive information disclosure without authentication" bounty impact class. It does not directly yield fund loss or transaction forgery, but it violates the core invariant that privileged introspection endpoints must require an authenticated session, and the disclosed pprof data (heap/goroutine dumps) can reveal internal application state that aids follow-on exploitation.

### Likelihood Explanation
Highly likely to be exploitable if this router code path reflects the deployed configuration: no operator privilege, leaked credentials, or social engineering is required — only network reachability to the node's web server port and knowledge/guessing of a registered plugin name (or use of `/discovery`, which is also unauthenticated, to enumerate plugin names and their metrics paths). The `/discovery` endpoint in `loopRoutes` further makes enumeration trivial since it lists all registered plugin names and their metrics paths without authentication: [7](#0-6) 

### Recommendation
Wrap `loopRoutes` (or at minimum the `/plugins/:name/metrics` and `/plugins/:name/debug/pprof/*` routes) in an authenticated sub-group using `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession)`, consistent with `debugRoutes`, e.g.:
```go
func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	authGroup := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	authGroup.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	authGroup.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	authGroup.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	authGroup.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}
```
If external Prometheus scraping without session cookies is a hard requirement, use a separate mechanism (e.g., a dedicated auth token, mTLS, or network-level restriction) rather than leaving the routes fully open.

### Proof of Concept
Integration test in `core/web/loop_registry_test.go` style, using an HTTP client without any session cookie/Authorization header:
```go

    // ...

    require.NoError(t, err)
    assert.Equal(t, http.StatusUnauthorized, resp.StatusCode, "expected 401 for unauthenticated metrics access")

    assert.Equal(t, http.StatusUnauthorized, resp2.StatusCode, "expected 401 for unauthenticated pprof access")
```

Running this against the current code will show a `200 OK` with plugin metrics/pprof body returned instead of `401`, confirming the authorization gap; existing test `TestLoopRegistry` at [8](#0-7)  already demonstrates that `client.Get(expectedLooppEndPoint)` (using `app.NewHTTPClient(nil)`, i.e., no authenticated session) succeeds with `200 OK`, which corroborates the missing auth enforcement.

```go
	w.Header().Set("Content-Type", "application/json")

	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	for _, registeredPlugin := range l.registry.List() {
```

```go
func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), "GET", pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```
