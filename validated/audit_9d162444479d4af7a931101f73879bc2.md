### Title
`WithdrawFromGasKey` Action Executable via Receipt (Delegate Action), Bypassing Transaction-Only Restriction and Pending-Queue Balance Tracking — (`core/primitives/src/action/mod.rs`, `runtime/runtime/src/action_validation.rs`)

### Summary

`WithdrawFromGasKey` is explicitly documented as a transaction-only action: no host function exists for it, and the comment in the source states it must never arrive via contract execution because the pending transaction queue must see every gas-key balance reduction. However, `validate_action_with_mode` imposes no such restriction when validating inner actions of a `Delegate`/`DelegateV2` action. An unprivileged user can therefore embed `WithdrawFromGasKey` inside a delegate action, causing the runtime to execute it through a receipt path that is invisible to the pending transaction queue.

### Finding Description

**Design invariant (documented in source):** [1](#0-0) 

The comment reads: *"This action must only be available via transactions, not via contract execution (there is no corresponding promise batch action host function)."*

The same invariant is restated in the VM imports file: [2](#0-1) 

*"Actions that reduce gas key balance must only be initiated via transactions, not by contracts. Otherwise, they will not be visible to the pending transaction queue."*

**Where the invariant is broken:**

`validate_action_with_mode` handles `WithdrawFromGasKey` with only a protocol-feature gate — it does not distinguish between a transaction context and a receipt context: [3](#0-2) [4](#0-3) 

`validate_delegate_action` calls `validate_actions_with_mode` on the inner actions of a `Delegate`/`DelegateV2` payload, passing the same `mode` parameter: [5](#0-4) 

Because `WithdrawFromGasKey` is not a delegate action (`Action::is_delegate()` returns `false` for it), it is a valid `NonDelegateAction` and passes inner-action validation without error.

**Execution path:**

When `apply_delegate_action` processes the delegate action, it spawns a new receipt addressed to `delegate_action.receiver_id` containing the inner `WithdrawFromGasKey` action: [6](#0-5) 

That receipt is then validated with `validate_receipt(..., NewReceipt)` — which again only checks the protocol feature — and executed via `action_withdraw_from_gas_key`, which reduces the gas key balance and credits the account: [7](#0-6) 

**Pending queue is never updated:**

The pending transaction queue only scans transactions for `WithdrawFromGasKey` actions: [8](#0-7) 

A withdrawal that arrives via a receipt is never recorded there, so the queue's view of the gas key balance diverges from the actual on-chain balance.

### Impact Explanation

**Confirmed impact (pending-queue invariant broken):** The pending transaction queue, which is used by the RPC to reject gas key transactions that would overdraw the gas key balance, does not see withdrawals that arrive via receipts. An account owner can therefore drain their gas key balance through a delegate-action receipt while the RPC still believes the balance is intact, causing subsequently submitted gas key transactions (accepted by the RPC) to fail at execution with `InsufficientGasKeyBalance`. This breaks the balance-tracking invariant documented in NEP-611.

**Potential additional impact (unconfirmed — depends on `check_actor_permissions`):** If `check_actor_permissions` (`runtime/runtime/src/actions.rs:776`) does not restrict `WithdrawFromGasKey` to `actor_id == account_id`, then any user could embed `WithdrawFromGasKey` in a delegate action addressed to a victim's account and drain that account's gas key balance into the account's `amount` field. This would constitute unauthorized balance manipulation / fund theft. This could not be confirmed without reading `check_actor_permissions` directly.

### Likelihood Explanation

The trigger requires only a valid access key on any account (to sign the delegate action) and knowledge of the target gas key's public key (which is public on-chain). No privileged access is needed. The `GasKeys` feature is active at protocol version 85 (stable on mainnet as of 2.13.0).

### Recommendation

Add an explicit check in `validate_action_with_mode` (or in `validate_delegate_action`) that rejects `WithdrawFromGasKey` when the validation mode is `NewReceipt` (i.e., when the action is being placed into a receipt rather than processed directly from a transaction). Concretely:

```rust
Action::WithdrawFromGasKey(_) => {
    require_protocol_feature(ProtocolFeature::GasKeys, "GasKeys", current_protocol_version)?;
    if mode == ValidateReceiptMode::NewReceipt {
        return Err(ActionsValidationError::UnsupportedProtocolFeature {
            protocol_feature: "WithdrawFromGasKey is not allowed in receipts".to_owned(),
            version: current_protocol_version,
        });
    }
    Ok(())
}
```

Alternatively, introduce a dedicated `ActionsValidationError::WithdrawFromGasKeyNotAllowedInReceipt` variant for clarity.

### Proof of Concept

1. Account `alice.near` owns a gas key with public key `GK` and balance `B`.
2. Alice constructs a `DelegateAction` with:
   - `sender_id = alice.near`
   - `receiver_id = alice.near`
   - inner actions: `[WithdrawFromGasKey { public_key: GK, amount: B }]`
   - signed with Alice's full-access key
3. Alice submits this as a meta-transaction via `broadcast_tx_async` (the relayer can be Alice herself).
4. The runtime validates the delegate action — `validate_action_with_mode` for `WithdrawFromGasKey` passes (only checks `GasKeys` feature).
5. `apply_delegate_action` spawns a receipt addressed to `alice.near` containing `WithdrawFromGasKey`.
6. The receipt executes: `action_withdraw_from_gas_key` reduces `GK.balance` from `B` to `0` and increases `alice.amount` by `B`.
7. The pending transaction queue was never notified of this withdrawal.
8. Any gas key transaction previously accepted by the RPC (based on the pre-withdrawal balance `B`) will now fail at execution with `InsufficientGasKeyBalance`, while the RPC continues to accept new gas key transactions up to the stale balance `B`. [9](#0-8) [10](#0-9)

```rust
fn validate_delegate_action(
    limit_config: &LimitConfig,
    delegate_action: VersionedDelegateActionRef<'_>,
    receiver: &AccountId,
    current_protocol_version: ProtocolVersion,
    mode: ValidateReceiptMode,
) -> Result<(), ActionsValidationError> {
    let actions = delegate_action.get_actions();
    let inner_receiver =
        if ProtocolFeature::FixDelegatedDeterministicStateInit.enabled(current_protocol_version) {
            // This is the correct receiver id to use for the check.
            delegate_action.receiver_id()

            // validation here, it will fail when it is checked as incoming receipt.

        };

        limit_config,
        &actions,
        inner_receiver,
        current_protocol_version,
        mode,
    )?;
    Ok(())
```

```rust
pub(crate) fn action_withdraw_from_gas_key(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &WithdrawFromGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    let Some(updated_balance) = gas_key_info.balance.checked_sub(action.amount) else {
        result.result = Err(ActionErrorKind::InsufficientGasKeyBalance {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
            balance: gas_key_info.balance,
            required: action.amount,
        }
        .into());
        return Ok(());
    };
    gas_key_info.balance = updated_balance;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);

    let new_account_balance = account.amount().checked_add(action.amount).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "Account balance integer overflow".to_string(),
        ))
    })?;
    account.set_amount(new_account_balance);
    Ok(())
```
