### Title
Missing reward settlement and vote/TronPower reconciliation in `DelegateResourceActuator` allows retention of unbacked voting rewards - (File: actuator/src/main/java/org/tron/core/actuator/DelegateResourceActuator.java)

### Summary
`DelegateResourceActuator` (and its TVM counterpart `DelegateResourceProcessor`) reduces an account's frozen balance that backs `TronPower` without first settling pending voting rewards and without recalculating/invalidating the account's existing votes, unlike every other stake-mutating actuator in the codebase.

### Finding Description
The reported bug class is: a balance-changing operation fails to call the reward-accounting hook (`onBalanceChange()` in Curves), letting stale/incorrect reward-accounting state persist and be exploited.

In java-tron, the analogous reward accounting hook is `MortgageService.withdrawReward()` / `VoteRewardUtil.withdrawReward()`, which snapshots an account's vote list and settles its per-cycle reward checkpoint (`beginCycle`/`endCycle`) whenever the account's stake or votes change. Every actuator that can affect an account's `TronPower` or votes calls this before mutating state:

- `VoteWitnessActuator.countVoteAccount()` calls `mortgageService.withdrawReward(ownerAddress)` before rewriting votes. [1](#0-0) 
- `UnfreezeBalanceV2Actuator.execute()` calls `mortgageService.withdrawReward(ownerAddress)` before reducing frozen balance, and additionally calls `updateVote()` to proportionally shrink the account's existing votes if `TronPower` becomes insufficient to back them. [2](#0-1) [3](#0-2) 
- `WithdrawBalanceActuator.execute()` also settles rewards first. [4](#0-3) 

By contrast, `DelegateResourceActuator.execute()` moves frozen `BANDWIDTH`/`ENERGY` balance from `FrozenV2Balance` into `DelegatedFrozenV2Balance` — reducing the amount of frozen balance the owner retains — but never calls `mortgageService.withdrawReward()` and never calls any `updateVote()`-equivalent to shrink/invalidate the owner's existing vote list: [5](#0-4) 

The same omission exists in the TVM-invoked `DelegateResourceProcessor.execute()`, which likewise mutates `FrozenV2Balance`/`DelegatedFrozenV2Balance` without any reward settlement or vote reconciliation step: [6](#0-5) 

Under the legacy (pre-Stake2.0-migration) resource model, frozen `BANDWIDTH`/`ENERGY` balance directly contributes to an account's `TronPower`, which is checked against the account's cast votes both at vote time (`VoteWitnessProcessor`/`VoteWitnessActuator`, `sum > tronPower`) and is expected to be re-checked/re-scaled whenever `TronPower` shrinks, as `UnfreezeBalanceV2Actuator.updateVote()` does: [7](#0-6) 

`DelegateResource` shrinks the same underlying frozen balance that backs `TronPower`, but performs none of this reconciliation. This means an account can: (1) freeze balance, (2) cast votes up to its full `TronPower`, then (3) delegate that same frozen balance away to another account (retaining it as `DelegatedFrozenV2Balance`, which still counts for the owner via `getFrozenV2BalanceWithDelegated()` used in some contexts, but is removed from `FrozenV2Balance` and, depending on model state, from the balance actually available to back votes) — without the vote list ever being shrunk or the reward checkpoint being settled at the point of change.

### Impact Explanation
This breaks the accounting invariant enforced everywhere else in the stake/reward subsystem (`votes <= TronPower`, and "reward settled on every stake-affecting event"). The consequence is state divergence between the votes an account is credited for reward purposes (`VoteRewardUtil.computeReward`, `MortgageService.computeReward`, both driven purely from the stored `votesList` snapshot) and the actual stake currently backing those votes. An account can continue accruing witness voting rewards proportional to votes it no longer has real `TronPower` to justify, since nothing forces re-validation or shrinkage of the vote list when `DelegateResource` is used to move stake elsewhere. This is a reward/accounting-integrity issue analogous to the reported bug class (accounting hooks skipped on a balance-changing operation), though it manifests as vote/stake divergence rather than a per-holder “offset reset to zero” exploit, because java-tron’s reward math is checkpoint-based (delta-VI over `beginCycle`/`endCycle`) rather than balance-multiplied-by-global-accumulator.

### Likelihood Explanation
Reachable by any unprivileged account holding frozen `BANDWIDTH`/`ENERGY` balance and votes: submit `DelegateResourceContract` (or call the TVM `delegateResource` precompile) after voting. No special privileges are required, and `DelegateResourceActuator`/`DelegateResourceProcessor` are ordinary user-facing actuators.

### Recommendation
In `DelegateResourceActuator.execute()` and `DelegateResourceProcessor.execute()`, before mutating `FrozenV2Balance`/`DelegatedFrozenV2Balance`:
1. Call `mortgageService.withdrawReward(ownerAddress)` (or `VoteRewardUtil.withdrawReward` in the TVM path) to settle any pending reward against the current vote snapshot.
2. Recompute the owner's effective `TronPower` after the delegation and, if it now falls below the sum of cast votes, proportionally shrink/invalidate the vote list the same way `UnfreezeBalanceV2Actuator.updateVote()` does.

### Proof of Concept
1. Account A freezes X TRX for `BANDWIDTH` (legacy resource model still active for A), gaining `TronPower` = X.
2. A votes for witness W using the full X `TronPower` via `VoteWitnessContract`.
3. A calls `DelegateResourceContract` to delegate the same X frozen balance to Account B for `BANDWIDTH`. `DelegateResourceActuator.execute()` reduces A's `FrozenV2Balance` by X and increases `DelegatedFrozenV2Balance` by X [8](#0-7) , without calling `withdrawReward()` or adjusting A's `votesList`.
4. At the next maintenance cycle, `MaintenanceManager`/`RewardViCalService` accumulate witness `Vi` based on total vote counts including A's unmodified vote for W [9](#0-8) .
5. A calls `WithdrawBalanceActuator`/`withdrawReward` and receives a reward computed from the unmodified vote count for W [10](#0-9) , despite no longer actually holding the frozen stake that justified those votes.

  private void accumulateWitnessVi(long cycle, byte[] address) {
    BigInteger preVi = getWitnessVi(cycle - 1, address);
    long voteCount = getWitnessVote(cycle, address);
    long reward = getReward(cycle, address);
    if (reward == 0 || voteCount == 0) { // Just forward pre vi
      if (!BigInteger.ZERO.equals(preVi)) { // Zero vi will not be record
        setWitnessVi(cycle, address, preVi);
      }
    } else { // Accumulate delta vi
      BigInteger deltaVi = BigInteger.valueOf(reward)
          .multiply(DECIMAL_OF_VI_REWARD)
          .divide(BigInteger.valueOf(voteCount));
      setWitnessVi(cycle, address, preVi.add(deltaVi));
    }
  }

  public void withdrawReward(byte[] address) {
    if (!dynamicPropertiesStore.allowChangeDelegation()) {
      return;
    }
    AccountCapsule accountCapsule = accountStore.get(address);
    long beginCycle = delegationStore.getBeginCycle(address);
    long endCycle = delegationStore.getEndCycle(address);
    long currentCycle = dynamicPropertiesStore.getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    //withdraw the latest cycle reward
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = delegationStore.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account);
        adjustAllowance(address, reward);
        reward = 0;
        logger.info("Latest cycle reward {}, {}.", beginCycle, account.getVotesList());
      }
      beginCycle += 1;
    }
    //
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      delegationStore.setBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule);
      adjustAllowance(address, reward);
    }
    delegationStore.setBeginCycle(address, endCycle);
    delegationStore.setEndCycle(address, endCycle + 1);
    delegationStore.setAccountVote(endCycle, address, accountCapsule);
    logger.info("Adjust {} allowance {}, now currentCycle {}, beginCycle {}, endCycle {}, "
            + "account vote {}.", Hex.toHexString(address), reward, currentCycle,
        beginCycle, endCycle, accountCapsule.getVotesList());
  }
