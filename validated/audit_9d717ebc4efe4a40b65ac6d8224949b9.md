### Title
Unsynchronized cross-thread reads of mmap-backed storage race with in-progress writes - (File: crates/apollo_storage/src/mmap_file/mod.rs)

### Summary
`FileHandler<V, RW>::append` writes serialized objects into a shared `MmapMut` while holding an `Arc<Mutex<MMapFile<V>>>` lock, but `FileHandler<V, Mode>::get` (used by every reader, including `RO` handles cloned and handed to other threads/tasks) dereferences a raw `*const u8` pointer (`memory_ptr`) directly, without ever acquiring that mutex. The two `unsafe impl Send`/`Sync` for `FileHandler` make it legal to freely share/clone these raw-pointer handles across threads with no compiler-enforced synchronization on the read path, mirroring the `cgc` `Ptr` issue where non-atomic, unsynchronized writes/reads of the same memory region across threads can create a data race.

### Finding Description
`open_file` creates one `MmapMut`, wraps it in `Arc<Mutex<MMapFile<V>>>`, and hands out two `FileHandler` instances (`RW` and `RO`) that both keep an independent raw pointer `memory_ptr = mmap.as_ptr()` into the same backing memory: [1](#0-0) 

The `unsafe impl Send`/`Sync` blanket-implementations allow these raw-pointer handles (and their clones) to be freely moved and shared across threads: [2](#0-1) 

The writer path locks the shared mutex before mutating the mmap bytes via `copy_from_slice`: [3](#0-2) 

The reader path, however, never touches the mutex — it dereferences `self.memory_ptr` directly with `std::slice::from_raw_parts` and deserializes whatever bytes are currently there: [4](#0-3) 

Because the writer's mutation is a plain (non-atomic) byte copy and the reader's access is not synchronized with the writer's lock (no acquire/release pairing at all on the read side), this is a textbook data race: concurrent, unsynchronized access to the same memory with at least one writer. This is directly analogous to the `cgc` advisory's issue #3 (`Ptr::write` performs non-atomic writes usable across threads, causing data races) and issue #1 (blanket unsafe `Send`/`Sync` enabling cross-thread sharing of a type that is not internally synchronized for reads).

### Impact Explanation
Any component that clones a `FileHandler<V, RO>` (e.g., readers serving storage queries used during blockifier execution, state reads, or Starknet OS re-execution) and reads a `LocationInFile` concurrently with an in-flight `append` risks observing a torn/partially-written value, or — under Rust's memory model — undefined behavior from the unsynchronized aliasing of `&mut` (writer, via `MmapMut`) and raw immutable reads (reader) to overlapping mapped memory. A torn read that still deserializes successfully (e.g., a partially written state diff, casm body, or block-body entry) can feed corrupted data into execution or commitment logic, producing an incorrect state root/block hash on some nodes while others compute correctly — i.e., honest-node divergence. This satisfies the "wrong committed root or block hash / honest-node divergence" impact bar.

### Likelihood Explanation
This mmap file abstraction backs core storage data written via `StorageWriter`/read via `StorageReader`, and reader handles are `Clone`-able and safely shareable across async tasks/threads per the `unsafe impl Send + Sync`. Given normal concurrent node operation (readers actively serving queries while sync/blockifier commits new data), overlapping read/append operations on the same underlying mmap are a realistic occurrence, not a contrived edge case, though actually observing a torn value depends on timing and CPU memory-ordering behavior, which is why this is rated medium rather than high/critical — similar to the CVSS AC:H rating in the referenced advisory.

### Recommendation
Have `FileHandler::get` acquire (at least a read guard on) the same `Mutex`/lock used by `append`, or replace the ad hoc raw-pointer sharing with a synchronization primitive that establishes a proper happens-before relationship between writers and readers (e.g., an `RwLock`, or an atomic "committed offset" watermark with `Acquire`/`Release` ordering that readers check before dereferencing memory beyond it). Remove or justify the blanket `unsafe impl Send`/`Sync` only once reads are properly synchronized with writes.

### Proof of Concept
1. Call `open_file` to obtain `(writer, reader)` for a `FileHandler<V, RW>`/`FileHandler<V, RO>` pair.
2. Clone `reader` into another thread.
3. In the writer thread, call `writer.append(&large_value)` repeatedly.
4. In the reader thread, concurrently call `reader.get(location)` for a `LocationInFile` whose byte range is currently being written by an in-flight `append` (no barrier synchronizes the two operations beyond incidental scheduling).
5. Because `get` never locks `mmap_file`, on architectures/compilers where store visibility to other cores is not guaranteed without an acquire operation, the reader can observe partially written bytes, corrupting deserialization — the same class of "non-atomic write across threads" issue described in the `cgc` advisory (GHSA-pwhf-7427-9vv2). [5](#0-4)

/// Open a memory mapped file, create it if it doesn't exist.
#[instrument(level = "debug", err)]
pub(crate) fn open_file<V: ValueSerde>(
    config: MmapFileConfig,
    path: PathBuf,
    offset: usize,
) -> MmapFileResult<(FileHandler<V, RW>, FileHandler<V, RO>)> {
    let file = OpenOptions::new().read(true).write(true).create(true).truncate(false).open(path)?;
    let size = file.metadata()?.len();
    let mmap = unsafe { MmapOptions::new().len(config.max_size).map_mut(&file)? };
    let mmap_ptr = mmap.as_ptr();
    let mmap_file = MMapFile {
        config,
        file,
        mmap,
        size: size.try_into().expect("size should fit in usize"),
        offset,
        should_flush: false,
        _value_type: PhantomData {},
    };
    let shared_mmap_file = Arc::new(Mutex::new(mmap_file));

    let mut write_file_handler: FileHandler<V, RW> = FileHandler {
        memory_ptr: mmap_ptr,
        mmap_file: shared_mmap_file.clone(),
        _mode: PhantomData,
    };
    write_file_handler.grow_file_if_needed(0);

    let read_file_handler: FileHandler<V, RO> =
        FileHandler { memory_ptr: mmap_ptr, mmap_file: shared_mmap_file, _mode: PhantomData };

    Ok((write_file_handler, read_file_handler))
}

/// A wrapper around `MMapFile` that provides both write and read interfaces.
#[derive(Debug)]
pub(crate) struct FileHandler<V: ValueSerde, Mode: TransactionKind> {
    memory_ptr: *const u8,
    mmap_file: Arc<Mutex<MMapFile<V>>>,
    _mode: PhantomData<Mode>,
}

// Manual impl so that V: Clone is not required.
impl<V: ValueSerde, Mode: TransactionKind> Clone for FileHandler<V, Mode> {
    fn clone(&self) -> Self {
        Self { memory_ptr: self.memory_ptr, mmap_file: self.mmap_file.clone(), _mode: PhantomData }
    }
}

unsafe impl<V: ValueSerde, Mode: TransactionKind> Send for FileHandler<V, Mode> {}
unsafe impl<V: ValueSerde, Mode: TransactionKind> Sync for FileHandler<V, Mode> {}

impl<V: ValueSerde> FileHandler<V, RW> {
    fn grow_file_if_needed(&mut self, offset: usize) {
        let mut mmap_file = self.mmap_file.lock().expect("Lock should not be poisoned");
        if mmap_file.size < offset + mmap_file.config.max_object_size {
            debug!(
                "Attempting to grow file. File size: {}, offset: {}, max_object_size: {}",
                mmap_file.size, offset, mmap_file.config.max_object_size
            );
            mmap_file.grow();
        }
    }
}

impl<V: ValueSerde + Debug> Writer<V> for FileHandler<V, RW> {
    fn append(&mut self, val: &V::Value) -> LocationInFile {
        trace!("Inserting object: {:?}", val);
        let serialized = V::serialize(val).expect("Should be able to serialize");
        let len = serialized.len();
        let offset;
        {
            let mut mmap_file = self.mmap_file.lock().expect("Lock should not be poisoned");
            offset = mmap_file.offset;
            trace!("Inserting object at offset: {}", offset);
            let mmap_slice = &mut mmap_file.mmap[offset..];
            mmap_slice[..len].copy_from_slice(&serialized);
            mmap_file
                .mmap
                .flush_async_range(offset, len)
                .expect("Failed to asynchronously flush the mmap after inserting");
            mmap_file.offset += len;
            mmap_file.should_flush = true;
        }
        let location = LocationInFile { offset, len };
        self.grow_file_if_needed(location.next_offset());
        location
    }

    fn flush(&self) {
        let mut mmap_file = self.mmap_file.lock().expect("Lock should not be poisoned");
        if mmap_file.should_flush {
            mmap_file.flush();
        }
    }
}

impl<V: ValueSerde, Mode: TransactionKind> Reader<V> for FileHandler<V, Mode> {
    /// Returns an object from the file.
    fn get(&self, location: LocationInFile) -> MmapFileResult<Option<V::Value>> {
        trace!("Reading object at location: {:?}", location);
        let mut bytes = unsafe {
            std::slice::from_raw_parts(
                self.memory_ptr.offset(location.offset.try_into()?),
                location.len,
            )
        };
        trace!("Deserializing object: {:?}", bytes);
        Ok(V::deserialize(&mut bytes))
    }
}
