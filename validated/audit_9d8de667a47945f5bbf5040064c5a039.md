### Title
Unchecked refund `Promise::transfer` result in `WalletContract::rlp_execute_callback` can permanently strand a caller's deposit - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
`rlp_execute_callback` refunds an external caller's attached deposit by firing a bare `env::promise_batch_action_transfer` when the inner cross-contract promise fails, but it never checks or chains on the outcome of that refund transfer, exactly mirroring the reported `CrabNetting::withdrawUSDC` pattern where a transfer's failure is not verified before the contract considers the fund-movement complete.

### Finding Description
`CallerDeposit` exists specifically to let the Wallet Contract "refund the caller's deposit if the cross-contract call fails" [1](#0-0) . When the inner promise the wallet dispatched on behalf of an external caller fails, `rlp_execute_callback` creates a fresh promise batch to `account_id` and appends a `Transfer` action to it, but does not attach a `.then()` callback and never inspects whether that refund promise itself succeeds: [2](#0-1) 

This is analogous to the reported bug: state/intent ("the caller has been refunded") is finalized without verifying the actual value-transfer outcome. On NEAR, a `Transfer` action from a contract-initiated receipt that fails is refunded by the protocol back to the *predecessor* of that failed receipt [3](#0-2) . The predecessor of the `refund_promise` batch is the Wallet Contract account itself (`current_account_id`), not the original external `account_id` that is owed the refund, per the documented refund semantics ("Deposit refunds ... sent as a refund to a `predecessor_id`") [4](#0-3) . So if this refund transfer itself fails (e.g., the target account no longer exists, or any other receiver-side failure at execution time), the deposit is not lost to burn, but it is misdirected: it returns to the Wallet Contract's own balance, not to the caller who supplied it. The Wallet Contract has no bookkeeping, no `.then()` callback, and no retry logic to detect or reconcile this case — the caller's `CallerDeposit` is simply dropped after the fire-and-forget `promise_batch_action_transfer` call, so the entitled caller can never claim it back through the contract's normal interface.

### Impact Explanation
An unprivileged external account that calls `rlp_execute`/`rlp_execute_from` on a deployed Wallet Contract instance with an attached deposit (the `CallerDeposit` path is only tracked "for external (non-self) callers" [5](#0-4) ) can permanently lose that deposit if the automatic refund-on-failure transfer itself fails at the protocol level. This is a concrete "permanently frozen funds" outcome reachable purely through a transaction/contract-call from an ordinary user or relayer — no validator or operator privilege required.

### Likelihood Explanation
The refund path is only exercised when the inner promise the wallet dispatches fails (a normal, reachable condition — e.g., relayer sends transaction to a wrong/faulty target, as already exercised by `test_caller_refunds`) [6](#0-5) . The refund transfer failing on top of that is a secondary, lower-probability event (e.g. target account deleted between the original call and the callback, or any transient receiver-side failure), but the code path performs zero validation or fallback, so whenever it does occur, fund loss is deterministic and unrecoverable through the contract's public interface.

### Recommendation
Chain the refund `Promise` with a `.then()` callback (similar to `rlp_execute_callback` itself) that inspects `env::promise_result` for the refund transfer. On failure, persist the pending refund obligation in contract state (e.g., a `pending_refunds: LookupMap<AccountId, Balance>`) and expose a method allowing the caller to retry claiming it, instead of relying on an unchecked, unattributed protocol-level balance refund that returns funds to the wrong account.

### Proof of Concept
1. An external account `Alice` calls `rlp_execute_from` on a Wallet Contract instance with a non-zero deposit, targeting a receiver.
2. `CallerDeposit::new` records `{account_id: Alice, yocto_near: N}` [5](#0-4) .
3. The inner cross-contract promise fails (e.g. receiver rejects/misbehaves).
4. `rlp_execute_callback` fires `env::promise_batch_action_transfer(refund_promise, N)` targeting `Alice`, with no `.then()` and no result check [7](#0-6) .
5. If that refund receipt fails execution (e.g. `Alice`'s account no longer exists at that time), the protocol-level deposit refund goes to the receipt's predecessor — the Wallet Contract account — not to `Alice` [3](#0-2) .
6. `Alice`'s `N` yoctoNEAR is now held by the Wallet Contract with no record and no way for `Alice` to reclaim it through the contract's interface.

/// A data type to keep track of the deposit given by an external caller.
/// This allows us to refund the caller's deposit if the cross-contract call fails.
#[derive(Debug, PartialEq, Eq, Clone, serde::Serialize, serde::Deserialize)]
pub struct CallerDeposit {
    pub account_id: AccountId,
    pub yocto_near: NonZeroU128,
}

impl CallerDeposit {
    pub fn new(context: &ExecutionContext) -> Option<Self> {
        // Only track for external (non-self) callers
        if context.current_account_id == context.predecessor_account_id {
            return None;
        }

        NonZeroU128::new(context.attached_deposit.as_yoctonear()).map(|yocto_near| Self {
            account_id: context.predecessor_account_id.clone(),
            yocto_near,
        })
    }
}

// An external caller gets its deposit back if the cross-contract call fails.
#[tokio::test]
async fn test_caller_refunds() -> anyhow::Result<()> {
    let TestContext { worker, wallet_contract, wallet_sk, address_registrar, .. } =
        TestContext::new().await?;

    let caller = worker.root_account()?;
    let deposit_amount = NearToken::from_near(3);
    let create_tx = |receiver_id: &AccountId, nonce: u64| {
        let method = "register";
        let args = br#"{"account_id": "birchmd.near"}"#;
        let action = Action::FunctionCall {
            receiver_id: receiver_id.to_string(),
            method_name: method.into(),
            args: args.to_vec(),
            gas: Gas::from_tgas(10).as_gas(),
            yocto_near: 0,
        };
        utils::create_signed_transaction(
            nonce,
            receiver_id,
            Wei::new_u128(deposit_amount.as_yoctonear() / (MAX_YOCTO_NEAR as u128)),
            action,
            &wallet_sk,
        )
    };

    // External caller gets a refund when the cross-contract call fails
    let pre_tx_account_balance = caller.view_account().await?.balance;
    let receiver_id: AccountId = "fake.near".parse()?;
    let result = wallet_contract
        .rlp_execute_from(
            &caller,
            receiver_id.as_str(),
            &create_tx(&receiver_id, 0),
            deposit_amount,
        )
        .await?;
    assert!(!result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            < deposit_amount.as_yoctonear()
    );
