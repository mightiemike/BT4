### Title
Cached deprecated (Cairo0) classes bypass the declared-class re-verification, allowing execution of undeclared/stale code - (File: crates/blockifier/src/state/state_reader_and_contract_manager.rs)

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` re-verifies via `is_declared` that a *cached* Cairo1 class is still actually declared in the current canonical state before returning it, explicitly because the global class cache can retain an entry belonging to a reverted/stale block. That same re-verification is skipped for cached Cairo0 (deprecated, `RunnableCompiledClass::V0`) classes, even though the caching layer and the stated risk (stale cache entries surviving a chain reorg/revert) apply identically to both class kinds.

### Finding Description
`get_compiled_from_class_manager` looks up `class_hash` in the shared `ContractClassManager` cache. When a hit occurs, the code branches on the runnable class variant: [1](#0-0) 

For any non-V0 (Cairo1) class, it calls `self.state_reader.is_declared(class_hash)` and returns `StateError::UndeclaredClassHash` if the check fails — the accompanying comment states this exists because "existence in the cache does not guarantee [declaration], it might contain a declared class from a reverted block, for example." For `RunnableCompiledClass::V0` (deprecated Cairo0 classes), this branch is `{}` — no re-verification is performed at all, and the cached class is returned unconditionally as long as the LRU cache entry exists.

The `FetchCompiledClasses` trait itself documents this asymmetry: `is_declared` is defined to always return `false` for Cairo0 classes, "Cairo 0 classes always return `false`," confirming that the trait/check was designed only around Cairo1 declarations and never extended to cover Cairo0. [2](#0-1) 

The unit tests make the intended vs. actual behavior explicit: for the Cairo1 "cached but verification failed after reorg" scenario, the test expects a hard `UndeclaredClassHash` error, whereas the analogous Cairo0 "cached" scenario expects zero declaration verification calls and always succeeds: [3](#0-2) 

The cache (`ContractClassManager` / `GlobalContractCache`) is a long-lived, in-process LRU keyed purely by `ClassHash`, shared across blocks/transactions and not automatically pruned when a specific class's declaration is reverted at the storage layer: [4](#0-3) 

The one place that defends against this at all is `native_blockifier`'s block-revert path, which unconditionally clears the *entire* cache on any block revert: [5](#0-4) 
This is a blunt, component-specific mitigation (full-cache invalidation) rather than a correctness guarantee inside `get_compiled_from_class_manager` itself, and it is not present as an invariant enforced by the state-reader/contract-manager abstraction used generally by `blockifier`'s `TransactionExecutor` (used by the batcher, gateway simulation, re-execution, and the virtual SNOS prover/executor paths). Any consumer of `StateReaderAndContractManager` that reaches a class-hash lookup while a Cairo0 class previously cached (e.g., from a transaction that ran against a pending/candidate block state that was later reverted, or a class hash that was declared and then reverted) remains cached and is returned without ever consulting current storage/state declaration status, unlike the Cairo1 path.

### Impact Explanation
If a Cairo0 (deprecated) class becomes cached under a state that is later reverted (e.g., speculative/optimistic execution, reorg, or any component using `StateReaderAndContractManager` without performing the same aggressive full-cache clear that `native_blockifier`'s `revert_block` does), subsequent transactions that reference that class hash will execute against the stale bytecode without any re-check that it is still declared in the canonical state. This can cause:
- Execution of a contract class that is not part of the actual, currently-committed state — a wrong state transition relative to what a node that correctly re-fetches from storage would produce.
- Divergence between two otherwise-honest sequencer/executor instances depending on whether their local class cache happens to still hold the stale Cairo0 entry, since the check that would force a fresh, correct lookup (`is_declared`) is present for Cairo1 but is compiled out entirely for Cairo0.
- Because this state divergence feeds into transaction execution results (state diffs, receipts) that are committed to the state and block hash, this maps to the "wrong committed root or block hash / honest-node divergence" impact category.

### Likelihood Explanation
The asymmetry is unconditional and code-level (not a rare race): any code path that (a) populates the cache with a Cairo0 class under one state view, and (b) later serves a `get_compiled_class` call for the same class hash under a state view where that class is no longer declared, hits this gap deterministically — there is no `is_declared` check to catch it, unlike for Cairo1. The mitigation that exists (`native_blockifier`'s full-cache clear on revert) is component-specific and coarse; other consumers of `StateReaderAndContractManager` (batcher's transaction executor, gateway simulation/execution, re-execution tooling, the virtual SNOS prover's block executor) do not exhibit the same explicit full-cache-clear-on-revert call in the reviewed code, so the guarantee is not uniformly enforced across all reachable execution paths.

### Recommendation
Apply the same declaration re-verification to cached `RunnableCompiledClass::V0` entries as is done for non-V0 variants — i.e., remove the `RunnableCompiledClass::V0(_) => {}` special case and instead verify (via a Cairo0-aware equivalent of `is_declared`, since the current trait doc says Cairo0 always returns `false`) that the class hash is still declared in the current state before returning a cached deprecated class. Alternatively, ensure every consumer of `StateReaderAndContractManager` invalidates or scopes the class cache identically to `native_blockifier::revert_block`, and add a regression test mirroring `cached_but_verification_failed_after_reorg_scenario` for the Cairo0 case.

### Proof of Concept
1. Use `StateReaderAndContractManager` with a `DictStateReader`/mock `FetchCompiledClasses` where a Cairo0 class hash `H` is declared and its compiled class is fetched and cached via `get_compiled_from_class_manager` (cache miss path, populates `ContractClassManager`).
2. Simulate a revert of the block that declared `H` at the storage layer (e.g., via `revert_state_diff`/`delete_deprecated_declared_classes`, as exercised in `declare_revert_declare_scenario`) — critically, without clearing `ContractClassManager`'s in-process cache (i.e., using a consumer other than `native_blockifier::revert_block`, which is the only place seen to clear it). [6](#0-5) 
3. Call `state_reader.get_compiled_class(H)` again. Because `H`'s runnable class is `RunnableCompiledClass::V0`, the code takes the empty `{}` branch and returns the cached class without calling `is_declared`, unlike the Cairo1 equivalent test `cached_but_verification_failed_after_reorg_scenario`, which asserts an `UndeclaredClassHash` error in this exact situation. [7](#0-6) 
4. The transaction executes successfully against a class that is no longer declared in canonical state, producing a state diff/receipt inconsistent with what correct re-verification (as Cairo1 receives) would have produced.

/// Thread-safe LRU cache for contract classes (Sierra or compiled Casm/Native), optimized for
/// inter-language sharing when `blockifier` compiles as a shared library.
#[derive(Clone, Debug)]
pub struct GlobalContractCache<T: Clone>(pub Arc<Mutex<ContractLRUCache<T>>>);

impl<T: Clone> GlobalContractCache<T> {
    /// Locks the cache for atomic access. Although conceptually shared, writing to this cache is
    /// only possible for one writer at a time.
    pub fn lock(&self) -> LockedClassCache<'_, T> {
        self.0.lock().expect("Global contract cache is poisoned.")
    }

    pub fn get(&self, class_hash: &ClassHash) -> Option<T> {
        self.lock().cache_get(class_hash).cloned()
    }

    pub fn set(&self, class_hash: ClassHash, contract_class: T) {
        self.lock().cache_set(class_hash, contract_class);
    }

    pub fn clear(&mut self) {
        self.lock().cache_clear();
    }

    pub fn new(cache_size: usize) -> Self {
        Self(Arc::new(Mutex::new(ContractLRUCache::<T>::with_size(cache_size))))
    }
