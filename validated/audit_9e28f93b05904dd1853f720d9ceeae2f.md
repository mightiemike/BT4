### Title
Permissionless `TransferToGasKey` Allows Any Third Party to Inflate Gas Key Balance Above Deletion Threshold, Preventing Key Deletion — (`runtime/runtime/src/actions.rs`)

---

### Summary

`Action::TransferToGasKey` carries no `actor_id == account_id` authorization guard in `check_actor_permissions`. Any unprivileged account can therefore send a `TransferToGasKey` receipt to a victim's account, inflating the victim's gas key `GasKeyInfo.balance` above `MAX_BALANCE_TO_BURN` (1 NEAR). Once the balance exceeds that threshold, `delete_gas_key` unconditionally returns `GasKeyBalanceTooHigh` and refuses to delete the key. An attacker who continuously re-inflates the balance after each victim withdrawal can sustain a denial-of-service against the victim's ability to delete or rotate their gas key.

---

### Finding Description

**Permissionless action dispatch**

`check_actor_permissions` in `runtime/runtime/src/actions.rs` enforces `actor_id == account_id` for sensitive actions (`Stake`, `AddKey`, `DeleteKey`, `WithdrawFromGasKey`, etc.), but explicitly places `TransferToGasKey` in the unrestricted arm alongside `Transfer` and `FunctionCall`:

```rust
Action::CreateAccount(_)
| Action::FunctionCall(_)
| Action::Transfer(_)
| Action::TransferToGasKey(_) => (),   // ← no actor check
``` [1](#0-0) 

This means any account can send a transaction (or a cross-contract call via `promise_batch_action_transfer_to_gas_key`) addressed to a victim's account with a `TransferToGasKey` action specifying the victim's gas key public key and any deposit amount.

**The deletion guard**

`delete_gas_key` in `runtime/runtime/src/access_keys.rs` refuses to delete a gas key whose balance exceeds `MAX_BALANCE_TO_BURN` (1 NEAR), to prevent accidentally burning a large prepaid pot:

```rust
if balance > MAX_BALANCE_TO_BURN {
    result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh { ... }.into());
    return Ok(());
}
``` [2](#0-1) 

**The combined invariant break**

`action_transfer_to_gas_key` simply does a `checked_add` on `GasKeyInfo.balance` with no caller check:

```rust
gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit)...;
set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
``` [3](#0-2) 

An attacker who sends `TransferToGasKey { deposit: 1_000_000_000_000_000_000_000_001 }` (just above 1 NEAR) to the victim's account pushes `GasKeyInfo.balance` above `MAX_BALANCE_TO_BURN`. The victim's subsequent `DeleteKey` call hits the guard and fails.

**Race condition against victim's mitigation**

The victim's only mitigation is to combine `WithdrawFromGasKey(known_balance)` and `DeleteKey` in the same transaction. However, `WithdrawFromGasKey` requires a specific amount; if the attacker inserts a `TransferToGasKey` transaction that executes in the same chunk but before the victim's transaction, the remaining balance after the victim's withdrawal equals the attacker's deposit. If that deposit exceeds `MAX_BALANCE_TO_BURN`, the `DeleteKey` in the same transaction still fails. The attacker only needs to spend gas fees (the deposited tokens are credited to the victim's gas key and can be withdrawn, but the attacker can re-inflate immediately after each withdrawal).

The host function `promise_batch_action_transfer_to_gas_key` makes this callable from any deployed contract, lowering the barrier further. [4](#0-3) 

---

### Impact Explanation

- **Balance manipulation**: An unauthorized third party directly mutates `GasKeyInfo.balance` on the victim's trie state.
- **Denial of service (non-network-level, hardfork-free fix)**: The victim cannot delete or rotate their gas key as long as the attacker keeps the balance above 1 NEAR. Key rotation is a security-critical operation; inability to delete a compromised key is a material harm.
- **Contract execution flow breakage**: The `DeleteKey` action execution path is broken for the victim's gas key by an externally injected state change.

---

### Likelihood Explanation

- Any unprivileged account can trigger this with a single transaction costing only gas fees plus a deposit > 1 NEAR (which the victim can withdraw, but the attacker can re-deposit).
- The attack is cheap to sustain: the attacker's net cost per round is only gas fees, since the deposited tokens are credited to the victim (not burned).
- The victim can eventually succeed if they can get their combined `WithdrawFromGasKey + DeleteKey` transaction included before the attacker's next `TransferToGasKey`, but this is a race the attacker can win repeatedly.
- The host function path (`promise_batch_action_transfer_to_gas_key`) allows any contract to automate the attack.

---

### Recommendation

Add `Action::TransferToGasKey(_)` to the `actor_id == account_id` enforcement arm in `check_actor_permissions`, restricting gas key funding to the key owner (or an explicitly authorized predecessor):

```rust
Action::DeployContract(_)
| Action::Stake(_)
| Action::AddKey(_)
| Action::DeleteKey(_)
| Action::DeployGlobalContract(_)
| Action::UseGlobalContract(_)
| Action::WithdrawFromGasKey(_)
| Action::TransferToGasKey(_) => {   // ← add here
    if actor_id != account_id {
        return Err(ActionErrorKind::ActorNoPermission { ... }.into());
    }
}
``` [5](#0-4) 

Alternatively, change `delete_gas_key` to burn up to `MAX_BALANCE_TO_BURN` and refund the remainder to the account, eliminating the hard block on deletion regardless of balance.

---

### Proof of Concept

```
1. Victim (alice.near) creates a gas key with public key GK and balance 0.
2. Attacker (eve.near) submits:
     SignedTransaction {
       signer_id: "eve.near",
       receiver_id: "alice.near",
       actions: [TransferToGasKey { public_key: GK, deposit: 2_000_000_000_000_000_000_000_000 }]
     }
   Cost to attacker: gas fees only (deposit credited to alice's gas key).
3. alice.near's GasKeyInfo.balance is now 2 NEAR > MAX_BALANCE_TO_BURN (1 NEAR).
4. Alice submits DeleteKey { public_key: GK }.
   → Runtime calls delete_gas_key → balance (2 NEAR) > MAX_BALANCE_TO_BURN → GasKeyBalanceTooHigh error.
5. Alice submits WithdrawFromGasKey { public_key: GK, amount: 2 NEAR } + DeleteKey in same tx.
   → Eve front-runs with TransferToGasKey { deposit: 1.1 NEAR }.
   → After Alice's withdrawal: remaining balance = 1.1 NEAR > MAX_BALANCE_TO_BURN.
   → DeleteKey fails again.
6. Eve repeats step 5 each time Alice attempts deletion, sustaining the DoS.
```

pub(crate) fn check_actor_permissions(
    action: &Action,
    account: &Option<Account>,
    actor_id: &AccountId,
    account_id: &AccountId,
) -> Result<(), ActionError> {
    match action {
        Action::DeployContract(_)
        | Action::Stake(_)
        | Action::AddKey(_)
        | Action::DeleteKey(_)
        | Action::DeployGlobalContract(_)
        | Action::UseGlobalContract(_)
        | Action::WithdrawFromGasKey(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
        }
        Action::DeleteAccount(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
            let account = account.as_ref().unwrap();
            if !account.locked().is_zero() {
                return Err(ActionErrorKind::DeleteAccountStaking {
                    account_id: account_id.clone(),
                }
                .into());
            }
        }
        Action::CreateAccount(_)
        | Action::FunctionCall(_)
        | Action::Transfer(_)
        | Action::TransferToGasKey(_) => (),
        Action::Delegate(_) | Action::DelegateV2(_) => (),
        Action::DeterministicStateInit(_) => (),
    };
    Ok(())

pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}
