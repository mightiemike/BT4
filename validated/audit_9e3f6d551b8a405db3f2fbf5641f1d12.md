### Title
Starknet OS `execute_replace_class` accepts undeclared class hashes without validation, causing state divergence from blockifier - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Starknet OS's implementation of the `replace_class` syscall writes a new `class_hash` into a contract's `StateEntry` without checking that the class hash corresponds to a declared contract class. The blockifier (the actual Rust execution engine used to build blocks) enforces this exact check before allowing the state write.

### Finding Description
In the Starknet OS Cairo program, `execute_replace_class` reads the requested `class_hash` from the syscall request and unconditionally overwrites the contract's `StateEntry.class_hash`, with an explicit TODO acknowledging the missing validation: [1](#0-0) 

The same gap exists in the deprecated (Cairo0) syscall path: [2](#0-1) 

In contrast, the blockifier's Rust implementation of the same syscall explicitly reads the compiled class (which fails with `StateError::UndeclaredClassHash` if the class was never declared) and additionally rejects replacing a Cairo1 contract with a Cairo0 class, before permitting the state write: [3](#0-2) 

The deprecated (Cairo0) syscall handler in the blockifier performs the equivalent check: [4](#0-3) 

Tests explicitly confirm the blockifier's behavior of rejecting undeclared class hashes with `"is not declared"`: [5](#0-4) [6](#0-5) 

This is directly analogous to the reported `Token.tokenURI()` bug: a state-affecting/state-reading operation is performed against an identifier (an NFT id in the original report; a class hash here) without verifying that the referenced entity actually exists ("has been minted"/"has been declared"), allowing the operation to proceed as if the reference were genuine.

### Impact Explanation
Since the Starknet OS is used to re-execute and verify blocks (generating the STARK proof of correct execution and the resulting state commitment), a missing existence check here means the OS's constraint system does not enforce that `replace_class` targets a declared class. A transaction that calls `replace_class` with an undeclared (or otherwise invalid, e.g. Cairo0-into-Cairo1) class hash would be rejected/reverted by the blockifier during actual block building (the honest execution path), but the OS's Cairo constraints do not force this rejection. This creates:
- A **wrong committed state root**: the OS could accept/prove a state transition (contract permanently pointing at a non-existent class) that the network's real execution semantics forbid.
- **Permanent freezing of funds**: any contract whose class hash is set to an undeclared class hash becomes permanently non-functional (no entry points can be resolved for a non-existent class), locking any tokens/assets held by that contract forever.
- **Honest-node divergence**: nodes relying on the OS-computed state for verification could diverge from the blockifier-computed canonical state, since one path rejects and the other silently accepts the same transaction semantics.

### Likelihood Explanation
The `replace_class` syscall is reachable by any account/contract with a single submitted transaction — no special privilege is required. The gap is explicitly flagged in the code via a `TODO(Yoni, 1/1/2026)` comment, confirming it is a known, currently-unaddressed omission in the Starknet OS rather than a theoretical concern.

### Recommendation
Add an explicit assertion in both `execute_replace_class` implementations (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that verifies the given `class_hash` is present in the declared-classes state (mirroring the blockifier's `get_compiled_class`/declared-class check), causing the syscall to fail/revert consistently with the blockifier's behavior when the class hash is undeclared (and, ideally, also enforcing the Cairo0/Cairo1 compatibility rule that the blockifier applies).

### Proof of Concept
1. A contract calls the `replace_class` syscall (or `library_call`-style abstraction leading to it) with an arbitrary, never-declared `class_hash` value.
2. In real network execution (blockifier), `syscall_base.rs::replace_class` calls `self.state.get_compiled_class(class_hash)` which returns `Err(StateError::UndeclaredClassHash(class_hash))`, causing the syscall/transaction to fail — no state change is committed for this class hash.
3. During Starknet OS re-execution/proving of the same transaction trace, `execute_replace_class` (`syscall_impls.cairo:881-920`) performs no such check and unconditionally updates `contract_state_changes` with the new (undeclared) class hash, producing a `StateEntry` update that the honest blockifier execution would never have produced.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
