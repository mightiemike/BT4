### Title
Self-Referential Slippage Protection in Auto-Swap Deposits and Gas Refunds Enables Sandwich-Style Value Extraction - (File: x/uexecutor/keeper/execute_inbound_gas.go)

### Summary
The `x/uexecutor` module's auto-swap paths (inbound gas top-up, inbound gas+payload, and outbound gas refund) derive their sole slippage protection (`minPCOut`) from the same untrusted, manipulable AMM quote (`quoteExactInputSingle`) that is fetched moments before the swap executes, with no TWAP or price-limit safeguard. This is the same *degenerate-ratio* bug class as the reported StakedUSH issue: a value the protocol trusts for a fairness computation (`shares = f(totalSupply, totalAssets)` there; `minPCOut = 0.95 * quote` here) can be pushed to a near-zero/degenerate value by an attacker manipulating one side of the ratio (a direct token transfer there; a pool-price move here) immediately before the protected operation executes, defeating the protection and causing value loss to the legitimate party.

### Finding Description
`GetSwapQuote` calls Uniswap-style `QuoterV2.quoteExactInputSingle` with `SqrtPriceLimitX96 = 0` (no price bound) to get the current spot-derived quote for converting a bridged PRC20 to WPC: [1](#0-0) 

That quote is then used, within the very same keeper call, to derive the *only* slippage guard for the actual swap: [2](#0-1) 

and identically in the gas+payload path: [3](#0-2) 

and in the outbound excess-gas refund path: [4](#0-3) 

Because the "reference price" and the "protection floor" come from the same manipulable pool state at nearly the same instant, an unprivileged attacker who can trade against the underlying WPC/PRC20 pool can:
1. Front-run the block containing the validator-triggered `MsgVoteInbound` (or the outbound-vote tx driving the refund) with a large swap that depresses the PRC20→WPC price in the pool.
2. Because `quote` is fetched fresh at execution time and is already depressed, `minPCOut = quote * 95 / 100` is also depressed — the "protection" simply re-affirms whatever manipulated price exists at execution time instead of bounding it against a fair/historical price.
3. The module's own auto-swap (`CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas` with `withSwap=true`) then executes at the manipulated price, converting the user's/protocol's bridged tokens into far less WPC than fair value.
4. The attacker back-runs to restore the pool price and pockets the extracted value, extracted directly from the user's deposited funds or the protocol's refund payout.

This mirrors the reported bug's root cause exactly: a fairness ratio computed from a value that is trivially manipulable by an outside actor immediately before the dependent operation consumes it, with no independent reference (e.g., TWAP, oracle, or a caller-supplied/pre-committed minimum) to anchor the protection.

### Impact Explanation
Successful exploitation drains value from legitimate inbound depositors (they receive far less PC than the fair-value auto-swap should have produced) or from the protocol's gas-refund payouts (excess gas refunded to users is siphoned via the same manipulated conversion). This falls within the allowed impact of "stealing ... of user or protocol-controlled funds" and "corruption of ... gas fee accounting, refund accounting ... PRC20 or native asset accounting" reachable through ordinary, unprivileged user interaction with the public AMM pool plus ordinary bridging/refund flows — no privileged access or malicious validator/relayer assumption is required.

### Likelihood Explanation
Likelihood depends on pool liquidity depth relative to the bridged amount and MEV/front-running capability, both realistic on a permissionless AMM pool with public mempool visibility of pending inbound votes/outbound observations. The fixed 5% slippage band computed off a zero-price-limit spot quote provides negligible real protection against a purpose-built sandwich, especially for thinly-liquid PRC20/gas-token pairs.

### Recommendation
Do not derive the slippage floor from the same instantaneous quote used to justify it. Use a TWAP-based reference price (or an admin/registry-configured expected exchange rate) to bound `minPCOut`, add a non-zero `SqrtPriceLimitX96` bound to `quoteExactInputSingle`/the underlying swap, and/or cap the maximum acceptable single-block price deviation before allowing the auto-swap or refund-swap path to proceed (falling back to the no-swap deposit/refund path otherwise).

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound` (or outbound-vote) that will trigger `ExecuteInboundGas` / `applyGasRefund` for a sizeable PRC20 amount.
2. Attacker submits a swap in the same or preceding block that pushes the PRC20/WPC pool price down significantly (bounded only by pool liquidity and gas cost).
3. The validator's tx executes: `GetSwapQuote` returns the manipulated low quote; `minPCOut = quote*95/100` is computed from that already-bad price; `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas(withSwap=true)` executes and succeeds since it easily clears the depressed `minPCOut`.
4. Attacker reverses their initial swap in a back-run transaction, capturing the price difference extracted from the bridged/refunded amount.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
