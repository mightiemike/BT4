### Title
Panic (`.unwrap()`) on `AotContractExecutor::from_path` after successful native compilation causes sequencer crash / halted block production - ([File: crates/apollo_compile_to_native/src/compiler.rs])

### Summary
`SierraToNativeCompiler::compile` invokes the external Cairo-Native compiler binary in a resource-limited subprocess, then loads the resulting shared object via `AotContractExecutor::from_path`. The result of that load is force-unwrapped with `.unwrap()` rather than being converted to a deterministic `CompilationUtilError`, so any load-time failure (e.g., missing/corrupt output artifact, dynamic-loader/resource failure after the subprocess reported success) panics the calling thread instead of returning an error. [1](#0-0) 

### Finding Description
`compile_with_args` only checks the subprocess exit status/stdout; it does not guarantee the on-disk artifact written to `output_file_path` is well-formed or fully loadable (e.g., truncated writes if the subprocess is killed at the boundary of its resource limits, disk/OS-level load failures, or a `None` return from `AotContractExecutor::from_path` if the artifact is malformed). The subsequent line:
```rust
Ok(AotContractExecutor::from_path(output_file.path())
    .map_err(|e| CompilationUtilError::CompilationError(e.to_string()))?
    .unwrap())
```
handles the `Err` variant properly (mapped into `CompilationUtilError::CompilationError`), but the `Option` returned inside the `Ok` variant is force-unwrapped, converting any "successfully compiled but load returned `None`" case into an unrecoverable panic. [2](#0-1) 

This function is the load path for native compilation of any Sierra-to-Native `declare`d class, and is called both synchronously (in `WaitOnCompilation` mode) and from the async compilation worker (in `LazyCompilation` mode) inside `NativeClassManager`. [3](#0-2) 
In `WaitOnCompilation` mode, `compiler.compile(...)` is called directly and unconditionally from `set_and_compile`, with no panic-suppression around it — the panic in `compiler.rs` would propagate straight out of a transaction-processing call, not through the guarded `panic_on_compilation_failure` path (which only wraps the compilation *error*, not the raw `.unwrap()` panic on load). [4](#0-3) 

This is the direct analog of the NEAR/nearcore bug class: successful compilation followed by a load step that can fail for reasons outside deterministic program validity (resource exhaustion, malformed intermediate artifact, disk/loader anomalies), and the implementation panics instead of surfacing a deterministic execution/compilation error.

### Impact Explanation
A panic on this path, reached during processing of an attacker-controlled `declare` transaction's Sierra class, crashes the executing thread. Depending on whether this runs in `WaitOnCompilation` (synchronous, in the gateway/batcher declare-validation or execution path) or in the background compilation worker thread, this can:
- Crash the gateway/batcher process handling declare validation, denying service to all subsequent transactions on that node (network unable to confirm new transactions from that node).
- If it occurs identically across all honest nodes processing the same declared class during block building/execution, it can cause simultaneous unavailability across the network — a liveness/DoS impact reachable purely from a submitted `declare` transaction, with no privileged access required.

This satisfies the "network unable to confirm new transactions" criterion for Medium/High severity, matching the reachable-by-unprivileged-declarer class explicitly listed in scope (Sierra-to-CASM/Native compilation).

### Likelihood Explanation
Likelihood depends on how reliably an attacker-crafted Sierra program (already passing the CASM-compilation gate) can force the Cairo-Native compiler subprocess to hit resource limits (`max_cpu_time`, `max_memory_usage`, `max_file_size`) or otherwise emit an artifact from which `AotContractExecutor::from_path` cannot construct an executor. Because `compile_with_args` already treats non-zero exit / SIGKILL as failures returned via `Err`, the only trigger for this specific `.unwrap()` panic is the narrower case where the subprocess exits successfully but the resulting file is not loadable by `from_path` (returns `Ok(None)` or similar). I could not verify from the available index whether `cairo_native::executor::AotContractExecutor::from_path`'s `Option` return is realistically reachable via a crafted contract (this is defined in the external `cairo_native` crate, outside this repo's indexed contents), so likelihood is uncertain and should be validated by a Devin session with access to the `cairo_native` dependency source and by fuzzing subprocess resource-limit edge cases.

### Recommendation
Replace the `.unwrap()` in `SierraToNativeCompiler::compile` with a proper `Err(CompilationUtilError::CompilationError(...))` when `AotContractExecutor::from_path` yields `Ok(None)`, mirroring the fix pattern in the referenced nearcore commit (treat loading failures after successful compilation as deterministic execution/compilation errors, not panics). Additionally, audit `run_compilation_worker`/`process_compilation_request` to ensure no other panics can escape from the compilation path regardless of `panic_on_compilation_failure` configuration, since that flag currently only governs deliberate panics on `CompilationUtilError`, not incidental `.unwrap()` panics inside `compile()`.

### Proof of Concept
1. Craft or observe a Sierra contract class whose Cairo-Native compilation subprocess exits successfully (exit code 0) but produces an artifact file that `cairo_native::executor::AotContractExecutor::from_path` cannot parse into `Some(executor)` (e.g., a partially-written `.so`/artifact due to it approaching `max_file_size`/`max_memory_usage` boundaries without being killed, or a version/ABI mismatch in the emitted object).
2. Submit this class via a `declare` transaction to a node configured with `cairo_native_mode = WaitOnCompilation` (as used in reexecution/testing configs) or let it flow through the `LazyCompilation` async worker.
3. Observe `SierraToNativeCompiler::compile` panic at the `.unwrap()` call in `crates/apollo_compile_to_native/src/compiler.rs:60`, crashing the calling thread/process instead of returning a `CompilationUtilError`. [1](#0-0)

    pub fn compile(
        &self,
        contract_class: ContractClass,
    ) -> Result<AotContractExecutor, CompilationUtilError> {
        let compiler_binary_path = &self.path_to_binary;

        let output_file = NamedTempFile::new()?;
        let output_file_path = output_file.path().to_str().ok_or(
            CompilationUtilError::UnexpectedError("Failed to get output file path".to_owned()),
        )?;
        let optimization_level = self.config.optimization_level.to_string();
        let additional_args = [output_file_path, "--opt-level", &optimization_level];
        let resource_limits = ResourceLimits::new(
            Some(self.config.max_cpu_time),
            self.config.max_file_size,
            Some(self.config.max_memory_usage),
        );
        let _stdout = compile_with_args(
            compiler_binary_path,
            contract_class,
            &additional_args,
            resource_limits,
        )?;

        Ok(AotContractExecutor::from_path(output_file.path())
            .map_err(|e| CompilationUtilError::CompilationError(e.to_string()))?
            .unwrap())
    }

/// Processes a compilation request and caches the result.
fn process_compilation_request(
    class_cache: RawClassCache,
    compiler: Arc<SierraToNativeCompiler>,
    compilation_request: CompilationRequest,
    panic_on_compilation_failure: bool,
) -> Result<(), CompilationUtilError> {
    let (class_hash, sierra, casm) = compilation_request;
    if let Some(CompiledClasses::V1Native(_)) = class_cache.get(&class_hash) {
        // The contract class is already compiled to native - skip the compilation.
        return Ok(());
    }
    let sierra_for_compilation = into_contract_class_for_compilation(sierra.as_ref());
    let start = Instant::now();
    let compilation_result = compiler.compile(sierra_for_compilation);
    let duration = start.elapsed();
    log::info!(
        "Compiling to native contract with class hash: {:#066x}. Duration: {:.3} seconds",
        class_hash.0,
        duration.as_secs_f32()
    );
    match compilation_result {
        Ok(executor) => {
            let native_compiled_class = NativeCompiledClassV1::new(executor, casm);
            class_cache.set(
                class_hash,
                CompiledClasses::V1Native(CachedCairoNative::Compiled(native_compiled_class)),
            );
            log::info!("Compilation succeeded");
            Ok(())
        }
