### Title
Unbounded recursion in JSON-RPC message parsing crashes the node process - (File: `chain/jsonrpc-primitives/src/message.rs`)

### Summary
The nearcore JSON-RPC server deserializes every incoming request body directly into a `serde_json::Value`-backed `Message` enum using `serde_json::de::from_slice`, with no bound on JSON nesting depth. `serde_json`'s `Value` deserializer, like the Peggy-generated TOML parser in the reported CVE, is a recursive-descent parser that recurses once per array/object nesting level with no depth limit. A single unauthenticated HTTP POST to the JSON-RPC endpoint containing a deeply nested JSON array can exhaust the Rust call stack.

### Finding Description
`from_slice`/`from_str` in `chain/jsonrpc-primitives/src/message.rs` parse the raw request bytes straight into the JSON-RPC `Message` enum: [1](#0-0) 

`Message` is `#[serde(untagged)]` over variants (`Request`, `Response`, `Notification`, `Batch`) whose `params`/`result` fields are typed as `serde_json::Value`: [2](#0-1) [3](#0-2) 

Per `RPC_ARCHITECTURE.md`, `rpc_handler()` deserializes the raw HTTP body into this `Message` type as the very first step of request processing, before any method dispatch or method-specific validation occurs: [4](#0-3) 

`serde_json::Value`'s deserializer is a recursive-descent parser: each `[` or `{` nesting level adds a stack frame, with no depth counter or limit — architecturally identical to the `peg$parsevalue`/`peg$parsearray` unbounded recursion described in the toml-node CVE. The only defense in the pipeline is a flat request body size limit (documented as 10MB), which bounds total bytes but not nesting depth: a payload of the form `"[[[[[...]]]]]"` can encode millions of nesting levels in a few megabytes (2 bytes per level), far exceeding the recursion depth needed to exhaust the default Rust thread stack (8MB, ~thousands of frames for `Value`'s recursive `deserialize` implementation).

### Impact Explanation
Unlike the JS case, where the analogous bug produces a catchable `RangeError` in a single request handler, a stack overflow in Rust triggers a guard-page fault that the language cannot catch — it aborts the entire process. Because the JSON-RPC server is a single process serving all RPC/view-call/transaction-submission traffic for the node, one unauthenticated malicious request kills the whole node (a full node/validator RPC endpoint halt), not just a worker thread. This matches the "transaction-triggered halt" acceptance criterion via the JSON-RPC caller path explicitly listed as in-scope.

### Likelihood Explanation
High. No authentication, staking, or balance is required — any RPC caller can reach `rpc_handler()` by POSTing to the node's public `/` JSON-RPC endpoint (default port 3030). The malicious payload is tiny (well under the 10MB body limit) and trivial to construct.

### Recommendation
Impose an explicit recursion/nesting-depth limit before or during JSON parsing of the RPC body — e.g. use a depth-limited JSON parser, pre-scan the byte stream to reject inputs whose bracket/brace nesting exceeds a safe bound (e.g. 128), or run the parse on a bounded worker with a recoverable stack-overflow guard (e.g. via `stacker`) so a crash is isolated rather than taking down the whole process.

### Proof of Concept
1. Start a nearcore node with the default JSON-RPC server enabled (port 3030).
2. Send: `POST http://<node>:3030/` with `Content-Type: application/json` and body `"[" * 2_000_000 + "]" * 2_000_000` (well under the 10MB limit).
3. `rpc_handler()` calls `Message::from_slice`/`serde_json::de::from_slice`, recursing once per `[`; the Rust call stack overflows before the size limit or any method-level validation is reached, aborting the node process.

Note: I could not directly inspect the exact axum body-size-limit middleware configuration value in `chain/jsonrpc/src/lib.rs` (only indirectly confirmed via `RPC_ARCHITECTURE.md`'s documented "10MB" default) — the index did not surface the specific `DefaultBodyLimit`/layer registration line. This does not affect the core finding, since even a much smaller nested payload (well under any reasonable body limit) is sufficient to overflow the stack.
