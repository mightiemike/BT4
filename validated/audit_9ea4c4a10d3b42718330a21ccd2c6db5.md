### Title
Permanent loss of user's excess gas refund when `refundUnusedGas` fails - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
`applyGasRefund` in `x/uexecutor/keeper/outbound.go` computes the excess gas fee (`gasFee - gasFeeUsed`) owed back to a user after an outbound executes, and calls `CallUniversalCoreRefundUnusedGas` (which invokes `refundUnusedGas` on the `UNIVERSAL_CORE` system contract via `DerivedEVMCall`) to pay it out. If both the swap-refund path and the no-swap fallback fail (e.g. `UniversalCore` lacks liquidity/balance for the gas token, similarly to the `RewardDistributor.sol` pattern where a contract can only pay out what it currently holds), the code simply records `Status: "FAILED"` on `outbound.PcRefundExecution` and returns — there is no bookkeeping of the owed `refundAmount` anywhere and no retry mechanism, so the user's entitled refund is permanently and silently lost.

### Finding Description
`applyGasRefund` computes `refundAmount := gasFee - gasFeeUsed` [1](#0-0)  and attempts delivery in two steps: first a swap-based refund via `CallUniversalCoreRefundUnusedGas(..., withSwap=true, ...)`, and on any failure, a fallback direct-deposit call with `withSwap=false` [2](#0-1) . If the fallback call also errors, the function only sets `refundPcTx.Status = "FAILED"` and `refundPcTx.ErrorMsg = err.Error()`, then stores this on `outbound.PcRefundExecution` and `outbound.RefundSwapError` before returning [3](#0-2) .

Crucially, `refundAmount` itself — the exact value the user is owed — is never persisted in any retryable ledger (no `PendingRefund` map or similar structure exists in the module; a grep across the repository found none). Once `UpdateOutbound` commits this `FAILED` status, the `OutboundTx` record for that UTX moves on with `OutboundStatus` already set to `OBSERVED`/`REVERTED` [4](#0-3) . There is no subsequent job, hook, or admin path anywhere in the codebase that re-attempts a failed `PcRefundExecution`; the excess funds owed to the user are functionally abandoned as soon as `refundUnusedGas` reverts for lack of funds/liquidity on the `UniversalCore` contract side.

This mirrors the `RewardDistributor.sol` bug class exactly: the paying contract/flow can only distribute what it currently holds/can execute successfully, and when it cannot, the amount is dropped rather than tracked for later distribution.

### Impact Explanation
This causes permanent loss of user-owned funds: the excess gas fee that Push Chain's own accounting (`gasFee - gasFeeUsed`) determines is owed back to the sender/recipient is never delivered and never recoverable, with no on-chain record of the specific unpaid amount beyond a free-text `ErrorMsg`. This falls under the explicitly in-scope impact "permanent loss ... of user or protocol-controlled funds" for the gas fee refund accounting path.

### Likelihood Explanation
Reachability requires no privileged actor — any legitimate outbound flow (triggered by ordinary user cross-chain transactions) can hit this condition whenever the `UniversalCore` contract cannot fulfil `refundUnusedGas` (e.g., insufficient PC/PRC20 liquidity for the swap-out, or the no-swap deposit likewise failing due to insufficient balance/allowance in the underlying PRC20). Since `applyGasRefund` runs for both successful and failed outbounds [5](#0-4) , this is a routine code path, not an edge case requiring an attacker to do anything unusual — it triggers purely from normal gas-fee variance on the destination chain combined with an underfunded `UniversalCore`.

### Recommendation
When both the swap and no-swap `refundUnusedGas` calls fail, persist the unpaid `refundAmount`, `gasToken`, and `recipientAddr` in a dedicated retryable state entry (e.g. a `PendingRefunds` collection analogous to `PendingOutbounds`/`PendingInbounds`), and expose a message or automated re-attempt path (triggered once `UniversalCore` is refunded/liquid again) to complete the payout. Additionally, document today's fire-and-forget behavior so integrators understand the current risk.

### Proof of Concept
1. Drive a normal outbound to completion so that `gasFee > gasFeeUsed` (as in `test/integration/uexecutor/gas_fee_refund_test.go`'s "refund execution recorded" case) [6](#0-5) .
2. Ensure the `UniversalCore` system contract has insufficient balance/liquidity of `gasToken` (or PC) to satisfy `refundUnusedGas` for both the swap path and the no-swap fallback (e.g. by not funding it, or draining it via other concurrent refunds).
3. Observe that `CallUniversalCoreRefundUnusedGas` returns an error for both attempts in `applyGasRefund` [7](#0-6) .
4. Confirm `outbound.PcRefundExecution.Status == "FAILED"` is committed via `UpdateOutbound`, and that no other module state records the `refundAmount` for later retry — the funds are permanently unrecoverable through any user- or validator-reachable flow.

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
