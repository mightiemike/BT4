### Title
`eth_estimateGas`/`eth_call`/`eth_createAccessList` execute against pruned L2 roots because the historical-block path bypasses `check_if_l2_block_pruned` - (File: `crates/evm/src/query.rs`)

### Summary
`Evm::get_balance`, `get_storage_at`, `get_transaction_count`, and `get_code` route through `set_state_to_end_of_evm_block_by_block_id`, which calls `check_if_l2_block_pruned` before rewinding the working set. `estimate_tx_expenses` (backing `eth_estimateGas`/`eth_estimateDiffSize`), `get_call_inner` (`eth_call`), `create_access_list_inner` (`eth_createAccessList`), `trace_block_transactions_by_number`, and the debug-trace-call path instead call `set_state_to_end_of_evm_block::<C>` directly, skipping that guard entirely. An attacker can therefore request `eth_estimateGas` at an explicit historical `block_number` that is already below the prune horizon; the query executes and its result — surfaced through `gas_limit_to_return(estimated)` and the `EstimatedTxExpenses`/`EstimatedDiffSize` values that carry `l1_fee`, `gas_with_l1_overhead`, and `gas_used` — reflects a JMT version whose nodes the node has already deleted (or reconstructs inconsistently), rather than being rejected like the sibling handlers are.

### Finding Description
The invariant under test is the equality: `root(query.block_number) == root(last_pruned_l2_height < block_number)`, i.e. "the root a query executes against" must equal "a root the node can still prove". `check_if_l2_block_pruned` (`crates/evm/src/query.rs:2081-2098`) is the only code in this file that enforces this by comparing `block_number` against `working_set.get_last_pruned_l2_height()` and returning `ProviderError::StateAtBlockPruned` when violated.

That check is wired into exactly one entry point, `set_state_to_end_of_evm_block_by_block_id` (`crates/evm/src/query.rs:2048-2078`), used only by `get_balance`, `get_storage_at`, `get_transaction_count`, and `get_code`.

`estimate_tx_expenses` (`crates/evm/src/query.rs:930-987`), `get_call_inner` (`crates/evm/src/query.rs:676-769`), `create_access_list_inner` (`crates/evm/src/query.rs:802-926`), `trace_block_transactions_by_number` (`crates/evm/src/query.rs:1500-1575`), and the `debug_traceCall`-style handler at `crates/evm/src/query.rs:1586-1684` all resolve an explicit `block_number` and then call `set_state_to_end_of_evm_block::<C>(block_num, working_set)` (`crates/evm/src/query.rs:2286-2294`, which just does `working_set.set_archival_version(block_number + 1)`) with no call to `check_if_l2_block_pruned` anywhere on that path.

Attacker flow:
1. Attacker (unprivileged) deploys/uses any contract that reads block/L1-derived state.
2. Node prunes state up to some `last_pruned_l2_height` (normal operation of `crates/storage-ops/src/pruning`).
3. Attacker calls `eth_estimateGas` (or `eth_call`, `eth_createAccessList`, `debug_traceCall`) with `blockNumber <= last_pruned_l2_height`, plus arbitrary `state_overrides`/`block_overrides` of their choosing.
4. `estimate_tx_expenses` sets the working set's archival version to the pruned height without ever consulting `get_last_pruned_l2_height`, then runs the simulation (`estimate_gas_with_env` → `inspect_with_citrea_handler`) and finally emits `gas_limit_to_return(estimated)` — a value computed from `EstimatedTxExpenses::gas_used`, `l1_fee`, `base_fee`, and `gas_with_l1_overhead`.
5. Because pruning has already deleted the superseded JMT nodes for that version, the node either serves whatever residual/incorrect leaf data remains reachable or the read returns a different result than the version that was actually committed and proved on-chain; the resulting `gas_used`/`l1_fee`/output value is derived from a root the node can no longer reconstruct or prove.

Existing guards do not stop this: `check_if_l2_block_pruned` exists but is not called on this path, and `BitcoinVerifier`, `Auth`, and JMT-witness checks are unrelated to this off-chain RPC read path — they guard L1 blob/consensus validation and authenticated write paths, not this native RPC query dispatch.

### Impact Explanation
This is a node-serving-unprovable-state bug: the node answers a public JSON-RPC query (`eth_estimateGas`/`eth_call`/`eth_createAccessList`/`debug_traceCall`) using state at a version whose Merkle nodes have been pruned, so the returned `gas_used`, `l1_fee`, `access_list`, `EstimatedDiffSize`, or call `Bytes` output can silently diverge from what the proved chain actually contains at that height. Bridges, exchanges, or Clementine operators relying on these RPC calls for fee/gas sizing or simulated call results at a historical block get answers the node cannot back with a provable root — matching the "High: an honest node persisting or serving state contradicting the proved chain" category. It is repeatable indefinitely: every pruned historical block number is a valid trigger, requires no special privilege, and costs only a single RPC call.

### Likelihood Explanation
No special preconditions beyond normal operation: a node running the standard pruning service (`crates/storage-ops/src/pruning`) will have `last_pruned_l2_height > 0` after running for any length of time, and this is common default node/prover config. The attacker only needs public RPC access and knowledge of an old block number (`eth_blockNumber` minus retention window is public knowledge). No Bitcoin fee, no cBTC, no privileged key is required. This is highly likely to be reachable on any production Citrea full node that prunes state and exposes `eth_estimateGas`/`eth_call`/`eth_createAccessList`/`debug_traceCall` to the public.

### Recommendation
Route `estimate_tx_expenses`, `get_call_inner`, `create_access_list_inner`, `trace_block_transactions_by_number`, and the debug-trace-call handler through the same `check_if_l2_block_pruned` guard used in `set_state_to_end_of_evm_block_by_block_id`, or centralize the pruning check inside `set_state_to_end_of_evm_block` itself so every caller inherits it automatically, returning `ProviderError::StateAtBlockPruned`/the equivalent RPC error instead of silently executing against a pruned version.

    /// Rewind working_set to the given block_id
    pub fn set_state_to_end_of_evm_block_by_block_id(
        &self,
        block_id: Option<BlockId>,
        working_set: &mut WorkingSet<C::Storage>,
        ledger_db: &crate::LedgerDB,
    ) -> Result<(), EthApiError> {
        let block_num = match block_id {
            // latest state
            None => {
                return Ok(());
            }
            Some(BlockId::Number(block_num)) => {
                match block_num {
                    // Working state here is already at the latest state, so no need to anything
                    BlockNumberOrTag::Latest | BlockNumberOrTag::Pending => {
                        return Ok(());
                    }
                    _ => {
                        let num = self.block_number_for_id(&block_num, working_set, ledger_db)?;
                        self.check_if_l2_block_pruned(num, working_set)?;
                        num
                    }
                }
            }
            Some(BlockId::Hash(block_hash)) => self
                .get_block_number_by_block_hash(block_hash.block_hash, working_set)
                .ok_or_else(|| EthApiError::UnknownBlockOrTxIndex)?,
        };
        set_state_to_end_of_evm_block::<C>(block_num, working_set);
        Ok(())
    }

    /// Returns `ProviderError::StateAtBlockPruned` if the state at the given block number is pruned
    fn check_if_l2_block_pruned(
        &self,
        block_number: u64,
        working_set: &mut WorkingSet<C::Storage>,
    ) -> Result<(), ProviderError> {
        if let Some(last_pruned_l2_height) = working_set
            .get_last_pruned_l2_height()
            .expect("Failed to get last pruned l2 height")
        {
            if block_number == 0 {
                // Genesis block is never pruned
                return Ok(());
            } else if block_number <= last_pruned_l2_height {
                return Err(ProviderError::StateAtBlockPruned(block_number));
            }
        }
        Ok(())
    }
