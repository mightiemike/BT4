### Title
Inaccurate `bootstrap_congestion_info` totals from `ShardsOutgoingReceiptBuffer::shards()` omitting stale shard-keyed buffers - ([File: runtime/runtime/src/congestion_control.rs])

### Summary
`bootstrap_congestion_info` recomputes a shard's `CongestionInfo` (its "collateral factor" analog — the aggregate `buffered_receipts_gas`/`receipt_bytes` totals that drive congestion-level and admission decisions) by iterating `ShardsOutgoingReceiptBuffer::shards()` and summing every buffer it finds [1](#0-0) . `shards()` returns exactly the key set of the persisted `BufferedReceiptIndices.shard_buffers` map [2](#0-1) , which is populated on demand whenever `to_shard(shard_id)` is first written to [3](#0-2) , and is never explicitly reconciled against the current epoch's live `ShardLayout`.

### Finding Description
The sherlock bug's root cause is a "total" that is derived by iterating a *mutable collection of tracked entities*, where entity removal is not reflected back into the aggregate, so the total silently drops the removed entity's contribution. The nearcore analog is structurally identical: `bootstrap_congestion_info` is the fallback recompute path used whenever `apply_state.congestion_info` has no entry for the local shard — e.g. genesis, a freshly enabled feature, or (per code comments elsewhere) shortly after resharding [4](#0-3) . It sums `buffered_receipts_gas` and `receipt_bytes` only over the shard IDs currently present as keys in `shard_buffers`, which is a stale key set from whichever previous shard layout wrote those buffers — not the authoritative source of truth (the trie itself, or the current/parent `ShardLayout`). Elsewhere in the codebase, the module explicitly acknowledges that after resharding a shard's outgoing buffer key can belong to a *parent* shard ID that "no longer exists," and separate code (`ReceiptSinkV2WithInfo::forward_from_buffer`, `generate_bandwidth_requests`) is specifically written to also walk `info.parent_shard_ids` in addition to `outgoing_buffers.shards()` to avoid missing that leftover data [5](#0-4) . `bootstrap_congestion_info`, however, has no such parent-shard awareness and only calls `outgoing_buffers.shards()` [6](#0-5) ; if this path is ever exercised for a shard where `shard_buffers` entries reflect a different/older shard set than what the trie's buffered-receipt trie keys actually contain (e.g., due to divergent bootstrapping order, an incompletely migrated buffer map across a resharding boundary, or any situation where the map's keys diverge from the buffers physically present), the resulting `CongestionInfo.buffered_receipts_gas`/`receipt_bytes` totals underestimate the true accumulated backlog — mirroring exactly the "removed collateral asset missing from total" pattern.

### Impact Explanation
An underestimated `CongestionInfo` from `bootstrap_congestion_info` directly weakens NEP-539 congestion control: `congestion_level` (max of incoming/outgoing/memory fractions) would read lower than actual [7](#0-6) , so `outgoing_gas_limit` would fail to red-light senders that should be throttled, and `shard_accepts_transactions` would keep admitting new transactions to a shard whose real backlog already exceeds the reject threshold [8](#0-7) . Because this bootstrapped value becomes the committed `ApplyResult.congestion_info` written into the chunk header and consumed by every other shard's forwarding decisions next block, a wrong bootstrap on one node (vs. a node that never needed to bootstrap, or that bootstrapped at a different, consistent point) risks disagreement in computed `CongestionInfo`, which is exactly the kind of divergence the protocol's own invariants (checked-add/sub, `sanity_check_hash`) are designed to catch — but only for overflow/instrumentation drift, not silently-low totals from an incomplete shard enumeration.

### Likelihood Explanation
This path is only taken when `apply_state.congestion_info` lacks an entry for the local shard [9](#0-8) , i.e. genesis/feature-activation/tooling contexts documented as "IO-intensive fallback" [10](#0-9) , so it is rare in normal chunk application. The likelihood hinges on whether `shard_buffers` keys can actually diverge from the live buffer set in a way that matters in practice; this is plausible but not proven from static code alone — it needs confirmation against how `BufferedReceiptIndices` is populated/migrated across the resharding boundary and genesis-populate tooling paths (`genesis-populate/src/lib.rs:340` also calls `bootstrap_congestion_info` directly).

### Recommendation
Make `bootstrap_congestion_info`'s buffer enumeration source-of-truth-safe: either enumerate buffers using the full set of shard IDs from the relevant `ShardLayout` (current + any known parent shards, matching the pattern already used in `ReceiptSinkV2WithInfo::forward_from_buffer`), or scan the trie's `BufferedReceipt` column directly instead of trusting `shard_buffers` map keys, so that no buffered receipt bytes/gas are silently dropped from the recomputed total regardless of how `BufferedReceiptIndices` was populated.

/// Iterate all columns in the trie holding unprocessed receipts and
/// computes the storage consumption as well as attached gas.
///
/// This is an IO intensive operation! Only do it to bootstrap the
/// `CongestionInfo`. In normal operation, this information is kept up
/// to date and passed from chunk to chunk through chunk header fields.
pub fn bootstrap_congestion_info(
    trie: &dyn near_store::TrieAccess,
    config: &RuntimeConfig,
    shard_id: ShardId,
) -> Result<CongestionInfo, StorageError> {
    let mut receipt_bytes: u64 = 0;
    let mut delayed_receipts_gas: u128 = 0;
    let mut buffered_receipts_gas: u128 = 0;

    let delayed_receipt_queue = &DelayedReceiptQueue::load(trie)?;
    for receipt_result in delayed_receipt_queue.iter(trie, true) {
        let receipt = receipt_result?;
        let gas =
            receipt_congestion_gas(&receipt, config).map_err(int_overflow_to_storage_err)?.as_gas();
        delayed_receipts_gas = safe_add_gas_to_u128(delayed_receipts_gas, Gas::from_gas(gas))
            .map_err(int_overflow_to_storage_err)?;

        let memory = receipt_size(&receipt).map_err(int_overflow_to_storage_err)? as u64;
        receipt_bytes = receipt_bytes.checked_add(memory).ok_or_else(overflow_storage_err)?;
    }

    let mut outgoing_buffers = ShardsOutgoingReceiptBuffer::load(trie)?;
    for shard in outgoing_buffers.shards() {
        for receipt_result in outgoing_buffers.to_shard(shard).iter(trie, true) {
            let receipt = receipt_result?;
            let gas = receipt_congestion_gas(&receipt, config)
                .map_err(int_overflow_to_storage_err)?
                .as_gas();
            buffered_receipts_gas = safe_add_gas_to_u128(buffered_receipts_gas, Gas::from_gas(gas))
                .map_err(int_overflow_to_storage_err)?;
            let memory = receipt_size(&receipt).map_err(int_overflow_to_storage_err)? as u64;
            receipt_bytes = receipt_bytes.checked_add(memory).ok_or_else(overflow_storage_err)?;
        }
    }

    Ok(CongestionInfo::V1(CongestionInfoV1 {
        delayed_receipts_gas: delayed_receipts_gas as u128,
        buffered_receipts_gas: buffered_receipts_gas as u128,
        receipt_bytes,
        // For the first chunk, set this to the own id.
        // This allows bootstrapping without knowing all other shards.
        // It is also irrelevant, since the bootstrapped value is only used at
        // the start of applying a chunk on this shard. Other shards will only
        // see and act on the first congestion info after that.
        allowed_shard: shard_id.into(),
    }))
}

impl ApplyState {
    fn own_congestion_info(&self, trie: &dyn TrieAccess) -> Result<CongestionInfo, RuntimeError> {
        if let Some(congestion_info) = self.congestion_info.get(&self.shard_id) {
            return Ok(congestion_info.congestion_info);
        }

        tracing::warn!(target: "runtime", "starting to bootstrap congestion info, this might take a while");
        let start = std::time::Instant::now();
        let result = bootstrap_congestion_info(trie, &self.config, self.shard_id);
        let time = start.elapsed();
        tracing::warn!(target: "runtime", ?time, "bootstrapping congestion info done");
        let computed = result?;
        Ok(computed)
    }
