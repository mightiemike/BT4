## Title
`ensure_match_transaction_info` skips state/hot-state/position checkpoint hash verification, allowing replay/restore tooling to accept a diverged state root as valid - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the authenticity check used by backup restore replay (`TransactionReplayer::verify_execution` in the chunk executor), `db-tool`'s `replay_on_archive`/`replay_verify`, and `aptos-debugger`/CLI transaction replay to confirm that locally re-executed transaction outputs match the `TransactionInfo` that was already authenticated against a trusted ledger-info/accumulator proof. The function validates `status`, `gas_used`, the write-set hash (`state_change_hash`), and the event root hash, but it explicitly does **not** validate `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` — the fields that actually commit the Sparse-Merkle/JMT (and now hot-state / native-position) root to the ledger accumulator.

### Finding Description
In [1](#0-0)  the comparator computes and checks:
- `status` vs `txn_info.status()`
- `gas_used` vs `txn_info.gas_used()`
- `write_set_hash` (hash of `self.write_set()`) vs `txn_info.state_change_hash()`
- `event_root_hash` vs `txn_info.event_root_hash()`

It then returns `Ok(())` without ever touching `txn_info.state_checkpoint_hash()`, `txn_info.hot_state_checkpoint_hash()`, or `txn_info.position_state_checkpoint_hash()`. The code contains its own acknowledgment of the gap:
```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
```
This function is called directly on raw VM-executed outputs (not outputs that have gone through `DoStateCheckpoint`) in the backup-restore replay path: [2](#0-1)  builds `execution_output` via `DoGetExecutionOutput::by_transaction_execution`, which produces per-transaction `TransactionOutput`s with a write set but no computed state-checkpoint root, and then compares each output to the backup-provided (and separately accumulator-verified) `TransactionInfo` purely through `ensure_match_transaction_info`. It is used identically by db-tool's `replay_on_archive` at [3](#0-2)  and by the CLI transaction replay path at [4](#0-3) .

By contrast, the *live* execution/commit path does validate checkpoint roots against known hashes taken from the (also-untrusted-until-here) `TransactionInfo`, via `DoStateCheckpoint::run` → `get_state_checkpoint_hashes`, invoked from `chunk_executor::update_ledger` ( [5](#0-4) ) and from `do_state_checkpoint.rs` ( [6](#0-5) ). However, the `verify_execution`/replay-verification code path used specifically to *validate a backup before/while restoring a node* does not route through `DoStateCheckpoint` at all — it relies solely on `ensure_match_transaction_info`, which is blind to the checkpoint roots.

### Impact Explanation
State-checkpoint hashes are the values that bind the entire world-state tree (and, with `TransactionInfoV1`/`HOT_STATE_ROOT_IN_TXN_INFO`/`COMPUTE_TRADING_NATIVE_STATE_ROOTS`, the hot-state and native-position trees) to the transaction accumulator that consensus and light clients rely on for authenticated proofs. A divergence there — from a storage bug, a JMT computation bug, a bad backup chunk, or a subtly corrupted state snapshot — changes what a node's durable state actually contains while all of gas/status/event/write-set-hash checks can still pass (write-set hash only covers the delta emitted by that one transaction, not the accumulated tree root). Because `verify_execution`/replay tooling is precisely the mechanism operators and infra rely on to confirm that replaying a backup (or verifying archived history) reproduces the authenticated chain state, silently skipping the checkpoint-hash comparison means a node can complete a "successful" replay/restore while holding a durable state that differs from the correct VM result recorded on-chain. This is a hard-fork-class divergence risk: a validator bootstrapped this way would compute different roots at the next reconfiguration/checkpoint boundary than honest peers, and `replay-verify`/backup-integrity tooling used to audit archived history would fail to detect real corruption.

### Likelihood Explanation
This is not a theoretical construction — the divergence path is explicitly flagged as unhandled by the code authors' own `TODO(trading-native)` comment, confirming both the intent and the current gap. It doesn't require an attacker with special privileges: it triggers whenever local re-execution during restore/replay produces a state tree whose root differs from what is recorded in the trusted `TransactionInfo`, while per-transaction write-set/event hashes still match (e.g., due to any bug or corruption affecting cross-version state accumulation, hot-state/position-tree computation, or a backup snapshot that was tampered with only at pre-checkpoint versions). Given `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/`HOT_STATE_ROOT_IN_TXN_INFO` are newly introduced features (feature flags 122/123) still being rolled out, and the comment says to fix this "before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`," the gap is currently live in code and reachable today through the ordinary backup-restore and replay-verify workflows.

### Recommendation
Extend `ensure_match_transaction_info` to recompute the local state/hot-state/position checkpoint hashes for checkpoint-bearing transactions (mirroring the logic in `DoStateCheckpoint::get_state_checkpoint_hashes`) and assert equality against `txn_info.state_checkpoint_hash()`, `txn_info.hot_state_checkpoint_hash()`, and `txn_info.position_state_checkpoint_hash()` when present, failing loudly on mismatch. Route the chunk-executor `verify_execution` replay path (and any other caller of `ensure_match_transaction_info`) through `DoStateCheckpoint::run` (or an equivalent lightweight state-tree accumulation) so the checkpoint roots are actually recomputed and compared before backup restore or replay-verify report success.

### Proof of Concept
1. Take a `TransactionInfoV1` history segment (or one produced under `COMPUTE_TRADING_NATIVE_STATE_ROOTS`) where the write-set of a given checkpoint transaction, its events, gas, and status are unmodified, but an earlier version's state write is altered/corrupted such that the resulting JMT/hot-state/position root at the checkpoint differs from the `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` fields recorded in the (accumulator-proof-verified) `TransactionInfo`.
2. Feed this corrupted history through `TransactionReplayer`'s restore path (or `db-tool replay-verify` / `replay_on_archive`), which calls `chunk_executor::verify_execution` → `TransactionOutput::ensure_match_transaction_info` per [7](#0-6) .
3. Because `ensure_match_transaction_info` ( [8](#0-7) ) never inspects the checkpoint-hash fields, the check returns `Ok(())` for every transaction, and the restore/replay reports success despite the durable state root diverging from the correct, on-chain-authenticated value.

I was unable to fully trace whether every downstream consumer of `verify_execution`'s success signal (e.g., all fast-sync/backup restore entry points) unconditionally trusts this check without an independent secondary root comparison elsewhere in the pipeline; confirming that would require deeper tracing of `TransactionReplayer::commit`/`commit_chunk_impl` in `execution/executor/src/chunk_executor/mod.rs`, which I could not fully retrieve within the available tool budget.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn verify_execution(
        &self,
        transactions: &[Transaction],
        persisted_aux_info: &[PersistedAuxiliaryInfo],
        transaction_infos: &[TransactionInfo],
        write_sets: &[WriteSet],
        event_vecs: &[Vec<ContractEvent>],
        begin_version: Version,
        end_version: Version,
        verify_execution_mode: &VerifyExecutionMode,
    ) -> Result<Version> {
        // Execute transactions.
        let parent_state = self.commit_queue.lock().latest_state().clone();
        let state_view = self.state_view(parent_state.latest())?;
        let txns = transactions
            .iter()
            .take((end_version - begin_version) as usize)
            .cloned()
            .map(|t| t.into())
            .collect::<Vec<SignatureVerifiedTransaction>>();

        let auxiliary_info = persisted_aux_info
            .iter()
            .take((end_version - begin_version) as usize)
            .map(|persisted_aux_info| AuxiliaryInfo::new(*persisted_aux_info, None))
            .collect::<Vec<_>>();
        let onchain_config = chunk_onchain_config(&state_view)?;
        let execution_output = DoGetExecutionOutput::by_transaction_execution::<V>(
            &V::new(),
            txns.into(),
            auxiliary_info,
            &parent_state,
            state_view,
            onchain_config,
            TransactionSliceMetadata::chunk(begin_version, end_version),
        )?;
        // not `zip_eq`, deliberately
        for (version, txn_out, txn_info, write_set, events) in multizip((
            begin_version..end_version,
            &execution_output.to_commit.transaction_outputs,
            transaction_infos.iter(),
            write_sets.iter(),
            event_vecs.iter(),
        )) {
            if let Err(err) = txn_out.ensure_match_transaction_info(
                version,
                txn_info,
                Some(write_set),
                Some(events),
            ) {
                return if verify_execution_mode.is_lazy_quit() {
                    error!("(Not quitting right away.) {}", err);
                    verify_execution_mode.mark_seen_error();
                    Ok(version + 1)
                } else {
                    Err(err)
                };
            }
        }
        Ok(end_version)
    }
