## Finding: `TransactionOutput::ensure_match_transaction_info` never validates state/position checkpoint roots, letting execution-divergence bugs pass silently through replay-verify and chunk-execution-verify tooling

### Title
Missing state-checkpoint-root comparison in `ensure_match_transaction_info` allows a divergent state root to pass replay/execution verification - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the function used by the chunk executor's "verify execution" path and by `db-tool replay-on-archive` to confirm that VM-recomputed execution matches the authenticated ledger (transaction info) fetched from a trusted backup/archive. It checks status, gas used, write-set hash, and event root hash, but it never compares the recomputed state Merkle root against `TransactionInfo::state_checkpoint_hash()` (nor the hot-state or position-state checkpoint hashes). A code author's own `TODO` comment in the function acknowledges this gap. Any bug that corrupts state-tree merklization (JMT root computation, hot-state root, or the newer native "position" state root) without altering the per-transaction write set will be invisible to this check, defeating the exact purpose of replay/execution verification: detecting silent consensus/state divergence.

### Finding Description
`ensure_match_transaction_info` is defined at: [1](#0-0) 

It compares status, gas used, the hash of the write set (`state_change_hash`), and the event root hash against the corresponding fields on `TransactionInfo`, but has no comparison against `txn_info.state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, or `position_state_checkpoint_hash()`. The function itself documents this: [2](#0-1) 

This function is the sole correctness gate in two production verification paths:

1. Chunk executor's "verify execution" mode (used by state-sync driven `VerifyExecutionMode::should_verify()` and by replay/backup verification tooling), which re-executes transactions with the VM and calls `ensure_match_transaction_info` to decide whether local execution matches the trusted, proof-verified `TransactionInfo` list before falling back to blindly applying the archived write sets: [3](#0-2) 

2. `db-tool replay-on-archive`, whose entire purpose is auditing historical execution against archived transaction infos for hard-fork/divergence detection: [4](#0-3) 

By contrast, the *only* code path that actually re-derives and checks the JMT/state-checkpoint root against a "known" value from `TransactionInfo` is `DoStateCheckpoint::get_state_checkpoint_hashes`, which is invoked from `update_ledger`/`DoStateCheckpoint::run` when committing a chunk that is built from the *archived write set itself* (not from the VM's freshly recomputed output): [5](#0-4) [6](#0-5) 

That means the "verify" step (VM re-execution vs. trusted ledger) and the "commit" step (apply archived write set + recompute+check its root) are decoupled: `verify_execution` never itself recomputes or checks the state root produced from *its own VM run*, and the value it does check (`state_change_hash`, i.e., hash of raw write ops) says nothing about the resulting Merkle root. A bug specifically in the state-tree merklization logic (e.g., JMT internal-node construction, hot-state, or the new native "position" state tree introduced alongside `compute_trading_native_state_roots`) that changes the produced root while leaving the transaction's own write set byte-identical will make `ensure_match_transaction_info` report success even though local execution's derived ledger state has silently diverged from the authenticated chain state.

### Impact Explanation
This breaks the state-commitment/proof-integrity invariant that "authenticated ... state-view output [must be] bound to the wrong version, object, or proof context" is detectable: the very tool designed to catch state-root divergence (hard-fork detection during replay/verify, and state-sync's execution-verification mode) is blind to divergence in the Merkle root itself. A node relying on `VerifyExecutionMode::should_verify()` (state-sync chunk executor) or `db-tool replay-on-archive` to detect a consensus-breaking bug in state merklization would falsely conclude execution is correct, masking a hard-fork-class divergence rather than surfacing it. Given the explicit scope item "Hard-fork-only divergence during commit, replay, restore, or proof verification," and "Wrong accumulator root ... accepted as valid," this qualifies as a High-severity proof-integrity gap: the verification mechanism itself accepts an incorrect root as valid.

### Likelihood Explanation
The gap is deterministic and always present — it is not conditional on adversarial input, it is a structural omission in the comparator used by every invocation of `ensure_match_transaction_info`. It is triggered whenever there exists *any* other bug (e.g., in JMT computation, hot-state promotion, or the new position-state tree) that alters the state checkpoint root without altering the write set bytes of the affected transactions — a realistic class of bug given the number of new state-summary code paths (hot state, position state) recently added alongside this comparator. The TODO comment in the code is a direct admission from the maintainers that this is a known, unresolved gap in exactly the safety-net feature meant to catch such divergence before it silently propagates into consensus-breaking behavior.

### Recommendation
Extend `ensure_match_transaction_info` (and its position-state-aware variant, if any) to additionally take and verify the recomputed `state_checkpoint_hash` / `hot_state_checkpoint_hash` / `position_state_checkpoint_hash` for checkpoint transactions against `TransactionInfo`'s corresponding fields, mirroring the check already performed in `DoStateCheckpoint::get_state_checkpoint_hashes`. Until fixed, `verify_execution` and `replay_on_archive` cannot be relied upon to detect state-root-only divergence bugs.

### Proof of Concept
Conceptual trace (no PoC harness executed, this is code-path analysis of local repository code):
1. Suppose a bug exists in JMT/hot-state/position-state root computation such that, for some sequence of writes, `LedgerStateSummary::update` (called from `DoStateCheckpoint::run`) yields root `R'` instead of the correct root `R`, while the actual write set bytes committed for that transaction are unaffected. [7](#0-6) 
2. Run `db-tool replay-on-archive` (or state-sync chunk-executor in `VerifyExecutionMode::should_verify()`), which re-executes the transaction via the VM and calls `ensure_match_transaction_info(version, txn_info, Some(write_set), Some(events))`. [8](#0-7) 
3. Because `ensure_match_transaction_info` never compares any checkpoint hash, and `write_set`/`events`/`gas_used`/`status` are unaffected by the state-root bug, the function returns `Ok(())`, i.e., "execution verified" — even though the locally-recomputed ledger root diverges from the archived/authenticated one. [1](#0-0) 
4. Result: a real state-root divergence (hard-fork-class bug) is silently swallowed by the tooling whose entire job is to surface it.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn verify_execution(
        &self,
        transactions: &[Transaction],
        persisted_aux_info: &[PersistedAuxiliaryInfo],
        transaction_infos: &[TransactionInfo],
        write_sets: &[WriteSet],
        event_vecs: &[Vec<ContractEvent>],
        begin_version: Version,
        end_version: Version,
        verify_execution_mode: &VerifyExecutionMode,
    ) -> Result<Version> {
        // Execute transactions.
        let parent_state = self.commit_queue.lock().latest_state().clone();
        let state_view = self.state_view(parent_state.latest())?;
        let txns = transactions
            .iter()
            .take((end_version - begin_version) as usize)
            .cloned()
            .map(|t| t.into())
            .collect::<Vec<SignatureVerifiedTransaction>>();

        let auxiliary_info = persisted_aux_info
            .iter()
            .take((end_version - begin_version) as usize)
            .map(|persisted_aux_info| AuxiliaryInfo::new(*persisted_aux_info, None))
            .collect::<Vec<_>>();
        let onchain_config = chunk_onchain_config(&state_view)?;
        let execution_output = DoGetExecutionOutput::by_transaction_execution::<V>(
            &V::new(),
            txns.into(),
            auxiliary_info,
            &parent_state,
            state_view,
            onchain_config,
            TransactionSliceMetadata::chunk(begin_version, end_version),
        )?;
        // not `zip_eq`, deliberately
        for (version, txn_out, txn_info, write_set, events) in multizip((
            begin_version..end_version,
            &execution_output.to_commit.transaction_outputs,
            transaction_infos.iter(),
            write_sets.iter(),
            event_vecs.iter(),
        )) {
            if let Err(err) = txn_out.ensure_match_transaction_info(
                version,
                txn_info,
                Some(write_set),
                Some(events),
            ) {
                return if verify_execution_mode.is_lazy_quit() {
                    error!("(Not quitting right away.) {}", err);
                    verify_execution_mode.mark_seen_error();
                    Ok(version + 1)
                } else {
                    Err(err)
                };
            }
        }
        Ok(end_version)
    }

    fn remove_and_apply(
        &self,
        transactions: &mut Vec<Transaction>,
        persisted_aux_info: &mut Vec<PersistedAuxiliaryInfo>,

                    events,

            transaction_infos: txn_infos,
        });

    }

    fn execute_and_verify(
        &self,
        executor: &AptosVMBlockExecutor,
        current_version: &mut Version,
        cur_txns: &mut Vec<Transaction>,
        cur_persisted_aux_info: &mut Vec<PersistedAuxiliaryInfo>,
        expected_txn_infos: &mut Vec<TransactionInfo>,
        expected_events: &mut Vec<Vec<ContractEvent>>,
        expected_writesets: &mut Vec<WriteSet>,
    ) -> Result<Option<Error>> {
        if cur_txns.is_empty() {
            return Ok(None);
        }
        let txns = cur_txns
            .iter()
            .map(|txn| SignatureVerifiedTransaction::from(txn.clone()))
            .collect::<Vec<_>>();
        let txns_provider = DefaultTxnProvider::new(
            txns,
            cur_persisted_aux_info
                .iter()
                .map(|info| AuxiliaryInfo::new(*info, None))
                .collect(),
        );
        let executed_outputs = executor
            .execute_block(
                &txns_provider,
                &self
                    .arc_db
                    .state_view_at_version(current_version.checked_sub(1))?,
                BlockExecutorConfigFromOnchain::new_no_block_limit(), // TODO(HotState): will need to incorporate some features.
                TransactionSliceMetadata::Chunk {
                    begin: *current_version,
                    end: *current_version + cur_txns.len() as u64,
                },
            )
            .map(BlockOutput::into_transaction_outputs_forced)?;
        assert_eq!(executed_outputs.len(), cur_txns.len());

        for idx in 0..cur_txns.len() {
            let version = *current_version;
            *current_version += 1;

            if let Err(err) = executed_outputs[idx].ensure_match_transaction_info(
                version,
                &expected_txn_infos[idx],
                Some(&expected_writesets[idx]),
                Some(&expected_events[idx]),
            ) {
                cur_txns.drain(0..idx + 1);
                cur_persisted_aux_info.drain(0..idx + 1);
                expected_txn_infos.drain(0..idx + 1);
                expected_events.drain(0..idx + 1);
                expected_writesets.drain(0..idx + 1);

                return Ok(Some(err));
            }
        }

        cur_txns.clear();
        cur_persisted_aux_info.clear();
        expected_txn_infos.clear();
        expected_events.clear();
        expected_writesets.clear();

        Ok(None)
    }
}

    fn get_state_checkpoint_hashes(
        execution_output: &ExecutionOutput,
        known_state_checkpoints: Option<Vec<Option<HashValue>>>,
        computed_last_checkpoint_hash: HashValue,
        label: &str,
    ) -> Result<Vec<Option<HashValue>>> {
        let _timer = OTHER_TIMERS.timer_with(&[&format!("get_{label}_checkpoint_hashes")]);

        let num_txns = execution_output.to_commit.len();
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();

        if let Some(known) = known_state_checkpoints {
            ensure!(
                known.len() == num_txns,
                "Bad number of known {label} hashes. {} vs {}",
                known.len(),
                num_txns,
            );
            if let Some(idx) = last_checkpoint_index {
                ensure!(
                    known[idx] == Some(computed_last_checkpoint_hash),
                    "{label} root hash mismatch with known hashes passed in. {:?} vs {:?}",
                    known[idx],
                    Some(computed_last_checkpoint_hash),
                );
            }
            Ok(known)
        } else {
            if !execution_output.is_block {
                // We should enter this branch only in test.
                execution_output.to_commit.ensure_at_most_one_checkpoint()?;
            }

            let mut out = vec![None; num_txns];
            if let Some(index) = last_checkpoint_index {
                out[index] = Some(computed_last_checkpoint_hash);
            }
            Ok(out)
        }
    }
