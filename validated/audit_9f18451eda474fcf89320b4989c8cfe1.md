## Finding

### Title
Uncontrolled recursion in Sierra bytecode-segment hashing/parsing enables stack-exhaustion DoS from a single Declare transaction - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`)

### Summary
The compiled-class-hash computation and the Starknet OS bytecode-segment-structure builder both recurse over the `bytecode_segment_lengths` (`NestedIntList`) tree that is embedded in a CASM contract class with no depth bound. This tree's nesting depth is derived from the attacker-supplied Sierra program's function/branch structure during Sierra→CASM compilation, and unlike every other recursive/entry-point-call path in this codebase (which is explicitly gas-metered, height-bounded to 251, or protected by a `RecursionDepthGuard`), these two functions have no depth limit and run in-process, outside of the sandboxed compiler subprocess.

### Finding Description
`bytecode_hash_node` recurses once per tree level of `bytecode_segment_lengths` with no depth check: [1](#0-0) 

This is invoked by `HashableCompiledClass::hash()`, which is called immediately after the Sierra-to-CASM compiler subprocess returns, in the gateway/class-manager's own process — i.e. outside of the CPU/memory-limited subprocess sandbox used for compilation itself: [2](#0-1) [3](#0-2) 

This compile path is triggered directly by any account submitting a Declare transaction, via `ClassManager::add_class` → `SharedSierraCompilerClient::compile`: [4](#0-3) 

The comment in `apollo_compile_to_casm_types`/`config.rs` explicitly confirms this ordering: compilation happens "before the transaction's signature and balance are verified," and only the concurrency of compilations (not the recursion depth of the subsequent hash computation) is bounded: [5](#0-4) 

A second, independently vulnerable instance of the same unbounded pattern exists in the Starknet OS hint that reconstructs the bytecode segment tree for every compiled class touched during block re-execution/proving: [6](#0-5) 

Notably, the blockifier's own analogous structure-walker (`NestedFeltCounts::new_inner`, used for gas estimation) explicitly *asserts* the segmentation depth cannot exceed 1, which is direct evidence that the team is aware nesting depth is not intrinsically bounded to a small constant and must be actively restricted where it matters for resource accounting — yet no equivalent restriction exists in the hash-computation or OS-hint recursion paths: [7](#0-6) 

By contrast, every other recursion-capable path reachable from a transaction is explicitly bounded: Cairo/Sierra execution recursion is capped via `RecursionDepthGuard`/`max_recursion_depth` and native-stack sizing keyed to `MAX_POSSIBLE_SIERRA_GAS`: [8](#0-7) [9](#0-8) 

and Patricia-tree recursion is bounded by the fixed tree height (251): [10](#0-9) 

The bytecode-segment tree has no such bound: its structure is produced by the external `cairo-lang-sierra-to-casm` compiler from the Sierra program's function/branch layout, which an attacker fully controls up to the `max_bytecode_size` limit (81920 felts by default): [11](#0-10) 

A Sierra program crafted to maximize segmentation nesting (e.g., deeply chained function calls each producing its own nested "used/unused" segment split) can therefore drive `bytecode_hash_node` and `create_bytecode_segment_structure_inner` to recurse to a depth on the order of thousands, which is sufficient to exhaust the native call stack of the process executing them.

### Impact Explanation
- In `apollo_compile_to_casm`/`apollo_class_manager`: the recursive `hash()` call runs in the gateway/class-manager process itself, not inside the resource-limited compiler subprocess. A stack overflow here aborts the process handling the Declare transaction, which is a network-wide-reachable DoS vector against every sequencer node's transaction-ingestion path (gateway/class-manager), fitting "a network unable to confirm new transactions."
- In `starknet_os`, the same unbounded recursion runs during block re-execution/proving for every compiled class encountered in a block, which can crash/hang the OS re-execution pipeline, threatening the ability to produce/verify committed blocks.

### Likelihood Explanation
Any account can submit a Declare transaction with an adversarially structured Sierra program (only requiring standard declare fees/resources) and does not need any privileged role, matching the "single submitted transaction ... declared class" reachability requirement. The exact required nesting depth depends on the segmentation algorithm internals of the external `cairo-lang-sierra-to-casm` compiler, which was not fully verified in this repository (dependency-only code) — this introduces uncertainty about whether the attacker can practically reach stack-exhausting depths within the `max_bytecode_size` budget, but the complete absence of any depth check in the sequencer's own recursive consumers (`bytecode_hash_node`, `create_bytecode_segment_structure_inner`) is a clear and provable gap relative to every other recursion path in this codebase.

### Recommendation
Add an explicit maximum recursion/nesting-depth check (mirroring the `segmentation_depth <= 1` assumption already encoded in `NestedFeltCounts::new_inner`) to `bytecode_hash_node` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs` and to `create_bytecode_segment_structure_inner` in `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`, rejecting/erroring out on classes whose `bytecode_segment_lengths` tree exceeds the expected depth, and/or convert these functions to explicit iterative (worklist-based) traversal, consistent with the iterative approach already used elsewhere in the Patricia-tree code (`fetch_patricia_paths_inner`, `fetch_nodes`).

### Proof of Concept
Not fully constructible without access to the `cairo-lang-sierra-to-casm` compiler's segmentation algorithm internals (external dependency) to confirm the maximum achievable nesting depth within `max_bytecode_size`; the finding is based on static code-path analysis showing the absence of any depth bound in the two recursive consumers described above, in contrast to every other recursive/entry-point path in the codebase which is explicitly depth- or gas-bounded.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

    /// Recursively builds the nested structure and returns it with the number of items consumed.
    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
    }

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}

                let right_index = left_index + NodeIndex::ROOT;
