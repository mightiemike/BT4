### Title
Unbounded `UniversalPayload.gas_limit` from attacker-controlled inbound payload lets a single cross-chain deposit force an unmetered, arbitrarily large EVM sub-call during block execution - ([File: x/uexecutor/types/universal_payload.go], [File: x/uexecutor/keeper/evm.go])

### Summary
The ZkEvmV2 report describes a `finalizeBlocks` entrypoint whose gas cost scales with attacker-influenced block content (transactions/logs) without any upper bound, risking gas requirements above the block gas limit and stalling finalization. In Push Chain, the closest reachable analog is `UniversalPayload.GasLimit` - a string field fully controlled by whoever emits the source-chain gateway event (an unprivileged cross-chain user) - which is parsed and passed unmodified as the *explicit* `gasLimit` argument to `DerivedEVMCall` when the payload is executed on Push Chain. Neither `UniversalPayload.ValidateBasic()` nor `Inbound.ValidateForExecution()` enforce any upper bound on this value.

### Finding Description
`UniversalPayload.ValidateBasic()` only checks that `gas_limit` parses as a non-negative uint256 string; there is no ceiling check: [1](#0-0) 

This unbounded value flows straight into `CallUEAExecutePayload`, which parses it into a `*big.Int` and forwards it as the explicit `gasLimit` parameter of `DerivedEVMCall` - the fork's primitive for issuing a real EVM transaction from module/derived code: [2](#0-1) 

`DerivedEVMCall`'s documented purpose is precisely to let a caller "Set an explicit `gasLimit`" that `CallEVM` does not support, and the docs mark it as "Critical for predictable receipts": [3](#0-2) 

This path is reachable in two ways by an unprivileged attacker with no validator/relayer trust required:
1. A source-chain gateway event of type `FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` is observed by honest Universal Validators and voted on via `MsgVoteInbound` (a gasless, whitelisted message type). Once ballot quorum is reached, the state machine deterministically calls `ExecuteInboundFundsAndPayload`/`ExecuteInboundGasAndPayload` → `ExecutePayloadV2` → `CallUEAExecutePayload` → `DerivedEVMCall`, using the attacker-supplied `GasLimit` verbatim. [4](#0-3) [5](#0-4) 
2. `MsgExecutePayload` is a directly user-submitted message that also carries `UniversalPayload` and follows the identical `ExecutePayload` → `CallUEAExecutePayload` chain. [6](#0-5) 

Because `MsgVoteInbound` is on the gasless allowlist, the outer Cosmos SDK tx (submitted by the honest UV) skips fee-based gas pricing entirely, and the *content* being executed (the attacker's payload gas limit) is decoupled from any fee the submitter is paying: [7](#0-6) 

`DerivedEVMCall`'s `gasLimit` is an independent, explicit ceiling for the *inner* EVM execution, separate from the ambient SDK gas meter that bounds the enclosing `MsgVoteInbound`/`MsgExecutePayload` transaction. Since no code in this repository clamps `UniversalPayload.GasLimit` to a sane maximum (e.g., the chain's block gas limit or a per-tx cap) before it is handed to `DerivedEVMCall`, an attacker can set it to an arbitrarily large uint256 value. Depending on how the underlying EVM fork's `DerivedEVMCall` meters this inner call against `ctx.GasMeter()` (that logic lives in the external `github.com/pushchain/evm` fork and is out of this repository's index, so it cannot be verified here), this creates the same risk class as the ZkEvmV2 report: computation whose cost is dictated by attacker-controlled input, with no upper bound enforced in-repo, executed deterministically as part of ordinary block processing (`VoteInbound`/`ExecutePayload`) reachable by any unprivileged cross-chain user.

### Impact Explanation
If the inner EVM call's gas accounting is not strictly bounded by (or is additive on top of) the ambient SDK gas meter for the enclosing message, a single crafted inbound event or `MsgExecutePayload` can force every honest validator processing that block to perform execution far beyond intended per-tx/per-block budgets. This can (a) degrade block-processing time chain-wide (non-network-level DoS reachable from an ordinary user payload), and (b) in the worst case, cause processing to exceed the practical block gas/time budget, risking finalization delays or divergence between nodes if the sub-call's gas accounting is not fully deterministic w.r.t. state size touched. This matches the "in scope" impact category: "denial of service...reachable without privileged control" and "consensus or state-machine divergence reachable from ordinary user deposits, payloads...alone."

### Likelihood Explanation
The trigger requires only an unprivileged user to emit a gateway event (or submit `MsgExecutePayload`) with an oversized `gas_limit` field - no validator/relayer collusion needed, and no privileged action. `ValidateBasic()` and `ValidateForExecution()` both fail to bound this field, so the malformed input reaches `DerivedEVMCall` unmodified. Whether this actually translates into an out-of-proportion gas/CPU cost depends on the (unverifiable from this repo) internal accounting of the external EVM fork's `DerivedEVMCall`, which is a meaningful source of uncertainty.

### Recommendation
- Enforce an explicit, chain-configured maximum on `UniversalPayload.GasLimit` (and similarly on `MigrationPayload`/any other user-supplied gas-limit-like fields) in `UniversalPayload.ValidateBasic()` and/or `Inbound.ValidateForExecution()`, capping it well below the Push Chain block gas limit.
- Verify (in the `pushchain/evm` fork, out of this repo's scope) that `DerivedEVMCall`'s `gasLimit` argument is metered against the ambient `ctx.GasMeter()` so that oversized limits cannot let a single call consume more resources than the enclosing SDK message's own gas budget allows.
- Add integration/benchmark tests that submit inbounds/`MsgExecutePayload` with maximal `gas_limit` values and measure wall-clock/gas cost of `VoteInbound`/`ExecutePayload` execution to confirm bounded worst-case cost per block.

### Proof of Concept
Not independently verifiable end-to-end from this repository alone because the actual gas-metering behavior of `DerivedEVMCall` lives in the external `github.com/pushchain/evm` fork, which is not indexed here. The reachable, verifiable part of the chain is:
1. Construct an `Inbound` of `TxType_FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` with `UniversalPayload.GasLimit` set to a very large uint256 string (e.g., `"115792089237316195423570985008687907853269984665640564039457584007913129639935"`), which passes `ValidateBasic()`/`ValidateForExecution()` unchanged: [8](#0-7) 
2. Have 2/3+1 validators vote via `MsgVoteInbound` to reach ballot quorum, triggering `ExecuteInboundFundsAndPayload`/`ExecuteInboundGasAndPayload` → `ExecutePayloadV2` → `CallUEAExecutePayload`, which parses and forwards the oversized `GasLimit` to `DerivedEVMCall` untouched: [9](#0-8) 
3. Observe (requires the external EVM fork, not available in this index) whether the resulting `DerivedEVMCall` execution consumes CPU/gas proportional to `GasLimit` independent of/beyond the enclosing tx's own `GasWanted`.

Given the inability to inspect the external fork's gas-metering implementation, this should be validated with a live/benchmark Devin session against the actual `pushchain/evm` binary before treating this as a confirmed, high-confidence DoS rather than a plausible but unverified analog.

func (k Keeper) CallUEAExecutePayload(
	ctx sdk.Context,
	from, ueaAddr common.Address,
	universal_payload *types.UniversalPayload,
	verificationData []byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	abi, err := types.ParseUeaABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UEA ABI")
	}

	abiUniversalPayload, err := types.NewAbiUniversalPayload(universal_payload)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to create universal payload")
	}

	gasLimit := new(big.Int)
	gasLimit, ok := gasLimit.SetString(universal_payload.GasLimit, 10)
	if !ok {
		return nil, fmt.Errorf("invalid gas limit: %s", universal_payload.GasLimit)
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		from,
		ueaAddr,
		big.NewInt(0),
		gasLimit,
		true,  // commit = true (real tx, not simulation)
		false, // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		false, // not a module sender
		nil,
		"executeUniversalTx",
		abiUniversalPayload,
		verificationData,
	)
}

func (k Keeper) ExecutePayload(ctx context.Context, evmFrom common.Address, universalAccountId *types.UniversalAccountId, universalPayload *types.UniversalPayload, verificationData string) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Get Caip2Identifier for the universal account
	caip2Identifier := universalAccountId.GetCAIP2()

	k.Logger().Info("execute payload",
		"from", evmFrom.Hex(),
		"chain", caip2Identifier,
		"owner", universalAccountId.Owner,
	)

	// Step 1: Validate payload and verificationData early (fast-fail before EVM work)
	if _, err := types.NewAbiUniversalPayload(universalPayload); err != nil {
		return errors.Wrapf(err, "invalid universal payload")
	}

	verificationDataVal, err := utils.HexToBytes(verificationData)
	if err != nil {
		return errors.Wrapf(err, "invalid verificationData format")
	}

	chainConfig, err := k.uregistryKeeper.GetChainConfig(sdkCtx, caip2Identifier)
	if err != nil {
		return errors.Wrapf(err, "failed to get chain config for chain %s", caip2Identifier)
	}

	if !chainConfig.Enabled.IsInboundEnabled {
		k.Logger().Warn("execute payload rejected: chain inbound disabled", "chain", caip2Identifier)
		return fmt.Errorf("inbound is disabled for chain %s", caip2Identifier)
	}

	factoryAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)

	// Step 2: Compute smart account address
	// Calling factory contract to compute the UEA address
	ueaAddr, isDeployed, err := k.CallFactoryToGetUEAAddressForOrigin(sdkCtx, evmFrom, factoryAddress, universalAccountId)
	if err != nil {
		return err
	}

	if !isDeployed {
		// only deploy if the UEA address has funds and not deployed yet
		ueaAccAddr := sdk.AccAddress(ueaAddr.Bytes())
		balance := k.bankKeeper.GetBalance(sdkCtx, ueaAccAddr, pchaintypes.BaseDenom)
		if balance.Amount.Sign() == 0 {
			k.Logger().Warn("execute payload rejected: UEA not deployed and has no balance",
				"chain", caip2Identifier,
				"owner", universalAccountId.Owner,
			)
			return fmt.Errorf("UEA is not deployed")
		}

		k.Logger().Info("auto-deploying UEA before execute (pre-funded address)",
			"uea", ueaAddr.Hex(),
			"balance", balance.Amount.String(),
			"chain", caip2Identifier,
			"owner", universalAccountId.Owner,
		)
		if _, err := k.DeployUEAV2(ctx, evmFrom, universalAccountId); err != nil {
			return errors.Wrapf(err, "failed to auto-deploy pre-funded UEA")
		}
	}

	k.Logger().Debug("executing payload via UEA",
		"uea", ueaAddr.Hex(),
		"chain", caip2Identifier,
		"from", evmFrom.Hex(),
	)

	// Step 3: Execute payload through UEA
	receipt, execErr := k.CallUEAExecutePayload(sdkCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 4: Deduct gas fees regardless of success/failure.
	// If deduction fails, return error so the entire Cosmos tx rolls back (including EVM state).
	if feeErr := k.DeductGasFeesFromReceipt(ctx, sdkCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		return fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		return execErr
	}

// IsGaslessTx checks if a transaction contains only allowed gasless message types
// Returns true if all messages in the transaction are in the allowed gasless message types
func IsGaslessTx(tx sdk.Tx) bool {
	var (
		// GaslessMsgTypes defines the message types that are allowed in gasless transactions
		GaslessMsgTypes = []string{
			sdk.MsgTypeURL(&uexecutortypes.MsgMigrateUEA{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgExecutePayload{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteInbound{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteOutbound{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteTssKeyProcess{}),
			sdk.MsgTypeURL(&utsstypes.MsgVoteFundMigration{}),
			sdk.MsgTypeURL(&uexecutortypes.MsgVoteChainMeta{}),
		}
	)

	msgs := tx.GetMsgs()
	if len(msgs) == 0 {
		return false
	}

	for _, msg := range msgs {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// Only gasless if ALL inner messages are allowed
			for _, innerMsg := range m.Msgs {
				if !slices.Contains(GaslessMsgTypes, innerMsg.TypeUrl) {
					return false
				}
			}
		default:
			if !slices.Contains(GaslessMsgTypes, sdk.MsgTypeURL(msg)) {
				return false
			}
		}
	}
	return true
}
