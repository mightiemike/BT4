## Finding: Self-Referential Uniswap Quote Provides No Sandwich Protection in GAS Auto-Swap Deposit Flow

### Title
Same-block self-referential slippage check in `ExecuteInboundGas`/`applyGasRefund` allows an attacker to sandwich the GAS deposit auto-swap and extract value from user deposits - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The Push Chain analog of the LamboWin `rebalance()` bug is the GAS-token auto-swap path. Instead of taking a flashloan and checking `profit > 0` against a stale reference, Push Chain fetches a Uniswap V3 `QuoterV2` quote and derives `minPCOut` from it (5% slippage) in the very same keeper call that then immediately executes the swap on the same pool [1](#0-0) . Because the "reference price" and the "executed price" are both read from the identical, attacker-manipulable pool state within one atomic transaction, the slippage guard provides no real protection against a classic sandwich: an unprivileged attacker can move the pool price with an ordinary swap placed just before the finalizing vote transaction, and the quote/swap pair that follows will self-consistently "pass" the check while executing at the manipulated price.

### Finding Description
`VoteInbound` finalizes the ballot and synchronously calls `ExecuteInbound` → `ExecuteInboundGas` inside the same `MsgVoteInbound` message handler that carries the quorum-forming vote [2](#0-1) . That final `MsgVoteInbound` (wrapped in `authz.MsgExec`) is an ordinary, mempool-visible transaction submitted by a universal validator [3](#0-2) , so an unprivileged attacker can see it before it lands and race to be included earlier in the same block.

Inside `ExecuteInboundGas`, the flow is:
1. `GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` for `prc20 → wpc` at the *current* pool state [4](#0-3) .
2. `minPCOut` is derived as `quote * 95 / 100` [5](#0-4) .
3. `CallPRC20DepositAutoSwap` immediately executes the real swap against the same pool with that `minPCOut` as the floor [6](#0-5) , [7](#0-6) .

Both the quote and the actual swap read the same on-chain pool state within the same block/transaction, so if the attacker has already pushed the pool price off-market via a front-run swap, the "5% slippage protection" is computed relative to the *already-manipulated* price rather than any fair/external reference. The check can never catch this because it is tautological: `minPCOut` is defined in terms of the very price the attacker just set. The identical pattern is reused for `GAS_AND_PAYLOAD` deposits (`gasAndPayloadDepositAutoSwap`) [8](#0-7)  and for the excess-gas refund swap in `applyGasRefund`, which similarly quotes and swaps atomically inside `handleSuccessfulOutbound` (triggered by the finalizing `MsgVoteOutbound`) [9](#0-8) .

This differs from the LamboWin report's DoS outcome (attacker inflates the ratio so the honest `profit > 0` check reverts) because here the reference and the executed trade are computed from the *same* manipulated state rather than from an independent invariant — so instead of causing a revert, it silently lets the deposit/refund execute at an attacker-favorable price, extracting value from the depositing user (or from the refund recipient) into the attacker's sandwich position.

### Impact Explanation
An unprivileged attacker who is capable of moving the price on the relevant PRC20/WPC Uniswap V3 pool (particularly plausible for low-liquidity or newly-listed gas tokens, since `GetDefaultFeeTierForToken` selects a single default fee tier pool with no minimum-liquidity floor enforced here) can extract value from every GAS inbound deposit and every excess-gas refund that uses the auto-swap path. Each occurrence corrupts the amount of PC native asset actually credited to the user's UEA (or refund recipient) relative to fair market value, i.e., unauthorized value extraction from user/protocol-controlled funds during a core, user-reachable, default transaction path (deposit of gas token via inbound bridging).

### Likelihood Explanation
Every GAS and GAS_AND_PAYLOAD inbound, and every outbound refund with excess gas, goes through this exact quote-then-swap-in-one-tx pattern. The triggering `MsgVoteInbound`/`MsgVoteOutbound` transactions are ordinary mempool transactions with predictable effects (deposit auto-swap execution) once quorum is about to be reached, making them straightforward, repeatable sandwich targets for any attacker capable of trading against the pool and observing the mempool — no privileged role (validator, TSS, admin) is required.

### Recommendation
Do not derive the slippage floor from a same-block, same-transaction on-chain quote against the exact pool being traded. Instead:
- Use a time-weighted average price (TWAP) oracle from the pool (or an external reference) that cannot be moved atomically within one block/transaction, and/or
- Enforce a maximum single-block price deviation check against a persisted reference price (e.g., last observed price from `ChainMeta`/registry) before allowing the auto-swap to proceed, reverting to the no-swap PRC20 deposit fallback if deviation exceeds a bound, and
- Consider requiring minimum pool liquidity/TVL checks for tokens eligible for the auto-swap path in `uregistry` token configuration.

### Proof of Concept
1. Attacker monitors the mempool for a `MsgVoteInbound` (wrapped in `authz.MsgExec`) that will push a `GAS` inbound to quorum, per `VoteOnInboundBallot`/`VoteInbound` [10](#0-9) .
2. Attacker submits a large swap on the PRC20/WPC Uniswap V3 pool used by `GetDefaultFeeTierForToken`/`GetSwapQuote`, with higher gas price, to land earlier in the same block, moving the pool price adversely for the upcoming deposit swap.
3. The validator's `MsgVoteInbound` finalizes in the same block; `ExecuteInboundGas` calls `GetSwapQuote` against the now-manipulated pool, computes `minPCOut = quote*95/100` from that manipulated price, then executes `CallPRC20DepositAutoSwap` against the same manipulated pool [1](#0-0) .
4. The check passes trivially (quote and executed price are self-consistent), but the user's UEA receives less WPC than fair value; the attacker closes out the sandwich in a following transaction, capturing the difference.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```

```go
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
```

```go
// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
```
