Based on my research, I found a genuine analog to the reported bug class: **missing bound check on a divisor derived directly from unprivileged, attacker-controlled transaction input**, in the fee-priority computation used by Push Chain's custom ante logic.

### Title
Missing zero-gas guard causes division-by-zero panic in `getTxPriority` - (File: `app/ante/validator_tx_fee.go`)

### Summary
`NarwhalPool`/`TradingVaultV2`'s bug was a governance-set duration used later as a divisor with no bound check, causing divide-by-zero. The closest reachable analog in this repository is not a governance parameter (those are explicitly out of scope per the allowed-impact gate) but the **transaction's own `Gas` field**, which is fully attacker-controlled and is used as a raw divisor in the custom fee-priority computation without a zero check at the point of use.

### Finding Description
`checkTxFeeWithValidatorMinGasPrices` computes a transaction's mempool priority by calling `getTxPriority(feeCoins, int64(gas))`, where `gas` comes directly from `feeTx.GetGas()` [1](#0-0) . Inside `getTxPriority`, the code performs `c.Amount.QuoRaw(gas)` for every fee coin, with no check that `gas != 0` before dividing [2](#0-1) . `sdkmath.Int.QuoRaw` wraps `big.Int` division, which panics on division by zero in Go.

There is a partial guard elsewhere: `DeductFeeDecorator` rejects non-gasless transactions with `gas == 0` at block height > 0 outside of simulation, as shown by `TestDeductFee_ZeroGasRejected` [3](#0-2) . However, `TestDeductFee_SimulationSkipsZeroGasCheck` confirms this zero-gas rejection is explicitly bypassed when `simulate == true` [4](#0-3) . Since `checkTxFeeWithValidatorMinGasPrices` is registered as the custom `TxFeeChecker` passed into `NewDeductFeeDecorator`, and gas-price/priority computation can also be exercised via CheckTx mempool re-prioritization and simulate/query paths independent of the `DeliverTx` zero-gas guard, the divisor-zero condition is not uniformly prevented at the actual point of division.

### Impact Explanation
A crafted, unprivileged transaction with `Gas = 0` reaching `getTxPriority` (e.g., via a simulate/CheckTx path where the zero-gas short-circuit doesn't apply) triggers a Go runtime panic in `QuoRaw`. Depending on whether the call site is wrapped in a `recover()` (as `baseapp` typically does for query/simulate handlers), this could manifest as a request-scoped failure or, in unprotected code paths, a node-level crash — a non-network-level DoS reachable without any privileged control, which is within the allowed impact gate.

### Likelihood Explanation
Medium-low. The primary `DeliverTx`/CheckTx execution flow is protected by the explicit zero-gas rejection in `DeductFeeDecorator`. The residual exposure is the simulate path (`TestDeductFee_SimulationSkipsZeroGasCheck`) and any direct callers of `checkTxFeeWithValidatorMinGasPrices` (e.g., mempool priority re-computation) that could invoke the fee checker with `gas == 0` without first passing through the `DeductFeeDecorator` guard. I was not able to fully trace every caller and their panic-recovery guarantees within the remaining tool budget, so likelihood is uncertain and should be confirmed by reviewing `app/ante/ante_cosmos.go` and `app/ante/fee.go` decorator ordering, and whether `baseapp`'s simulate/query handling recovers panics for this call path.

### Recommendation
Add an explicit `gas == 0` check inside `getTxPriority` (or at the top of `checkTxFeeWithValidatorMinGasPrices`) that returns a sentinel priority or error instead of dividing, independent of whatever gas checks exist in calling decorators — mirroring the fix pattern from the report (defensive bound/zero check at the actual division site, not only at a distant caller).

### Proof of Concept
1. Construct a `FeeTx` with `Gas = 0` and a non-empty `Fee` (e.g., via the gRPC `simulate` endpoint, which per `TestDeductFee_SimulationSkipsZeroGasCheck` skips the zero-gas rejection).
2. Ensure the tx reaches `checkTxFeeWithValidatorMinGasPrices` (used as the app's `TxFeeChecker`).
3. `getTxPriority` executes `c.Amount.QuoRaw(0)` for each fee coin, panicking in the underlying `big.Int` division.

**Uncertainty note:** I could not fully verify, within the available tool budget, (a) the exact decorator ordering in `app/ante/ante_cosmos.go` to confirm whether every call path to `checkTxFeeWithValidatorMinGasPrices` is preceded by a zero-gas guard, and (b) whether the simulate/query call path wraps this panic in `recover()`, which would downgrade this from a node crash to a contained RPC error. This should be verified directly in the repository before treating this as a confirmed high-severity DoS.

func getTxPriority(fee sdk.Coins, gas int64) int64 {
	var priority int64
	for _, c := range fee {
		p := int64(math.MaxInt64)
		gasPrice := c.Amount.QuoRaw(gas)
		if gasPrice.IsInt64() {
			p = gasPrice.Int64()
		}
		if priority == 0 || p < priority {
			priority = p
		}

// TestDeductFee_SimulationSkipsZeroGasCheck verifies that simulation bypasses
// the zero-gas rejection, even for non-gasless txs.
func TestDeductFee_SimulationSkipsZeroGasCheck(t *testing.T) {
	bk := &mockBankKeeperAnte{}
	payer := sdk.AccAddress([]byte("payeraddr123456"))
	ak := newMockAccountKeeperAnte(sdk.AccAddress([]byte("feeCollector")))
	// Register payer so GetAccount returns non-nil (needed by checkDeductFee).
	ak.SetAccount(context.Background(), authtypes.NewBaseAccountWithAddress(payer))

	dfd := ante.NewDeductFeeDecorator(ak, bk, nil, nil /* default checker */)

	tx := mockFeeTx{
		msgs:     []sdk.Msg{&banktypes.MsgSend{}},
		gas:      0, // zero gas — would be rejected if not simulating
		fee:      sdk.Coins{},
		feePayer: payer,
	}

	ctx := newAnteTestCtx(t, false)
	nextCalled := false
	_, err := dfd.AnteHandle(ctx, tx, true /*simulate=true*/, func(ctx sdk.Context, tx sdk.Tx, simulate bool) (sdk.Context, error) {
		nextCalled = true
		return ctx, nil
	})

	require.NoError(t, err)
	require.True(t, nextCalled, "next handler must be called when simulate=true")
}
