### Title
Denial of Service via Unbounded Recursion in Compiled-Class Bytecode-Segment Hashing/Reconstruction (Stack Overflow) - (File: crates/starknet_api/src/contract_class/compiled_class_hash.rs)

### Summary
The Sierra→CASM compiler in `apollo_compile_to_casm` runs in a resource-limited sandboxed subprocess, but the compiled class hash is then computed *in the main, non-sandboxed sequencer process* by recursively walking the `NestedIntList` bytecode-segment structure the compiler produced. A declarer who crafts a contract with sufficiently deep, nested control flow can cause the compiler to emit a deeply nested segment-length tree; hashing (and, on the OS side, re-building) that tree recurses without any depth bound, which in Rust cannot be caught and aborts the whole process — the same "unbounded recursion on attacker-controlled nested structure → stack overflow" bug class described in the Helm `strvals` advisory (CVE-2022-23524), except here the crash lands in an unsandboxed, security-critical component instead of a short-lived CLI.

### Finding Description
`SierraCompiler::compile` first compiles a submitted class in an isolated, `rlimit`-bounded child process: [1](#0-0) 

The parent process then immediately hashes the resulting `CasmContractClass` outside of any sandbox: [2](#0-1) 

`hash()` delegates to `hash_inner`, which calls `bytecode_hash`, which calls the fully recursive `bytecode_hash_node` over the compiler-generated `NestedIntList`/`HashableNestedIntList` segment tree, with no depth limit: [3](#0-2) [4](#0-3) 

The segment tree's shape is derived by the Cairo compiler from the contract's own control-flow nesting (functions divided into branch segments, branches divided further), so a declarer who writes Sierra code with sufficiently deep nested branching can force an arbitrarily deep `NestedIntList::Node(...)` chain while staying under the flat `max_bytecode_size` (80 KiB felts) limit — that limit bounds total leaf data, not tree depth.

The identical unbounded-recursion pattern also exists on the Starknet OS re-execution path, which is reachable whenever the block containing the declared class is (re-)executed/proven: [5](#0-4) [6](#0-5) 

Note that the codebase already recognizes this class of hazard elsewhere and explicitly limits nesting to depth 1 with an `assert!`, but that guard only protects the (currently unused, `#[allow(unused)]`) `NestedFeltCounts::new_inner` helper, not the actual hash-computation or OS-side reconstruction paths that run on every DECLARE and every block re-execution: [7](#0-6) 

### Impact Explanation
A stack overflow in Rust from unbounded recursion aborts the process (`SIGSEGV`/`SIGABRT`); it cannot be caught with `Result`/`panic::catch_unwind` in the general case for deep native recursion. Because `hash()`/`bytecode_hash_node` executes directly in the gateway/sequencer process (not the CPU/memory-limited compiler subprocess), a single malicious DECLARE transaction can crash the gateway or batcher process handling it, and the same malicious class, once included in a block, can crash any full node or prover performing Starknet OS re-execution when it walks `create_bytecode_segment_structure_inner`/`BytecodeSegmentNode::hash`. This is a network-wide availability impact — "a network unable to confirm new transactions" — satisfying the required Medium-severity DoS bar, mirroring the original Helm finding's impact on the process handling untrusted input.

### Likelihood Explanation
Reachable directly from an unprivileged class declarer: no special privileges, staking, or network position are required — just submitting a DECLARE transaction with a contract containing deliberately deep nested branching/control flow that the Sierra→CASM compiler will segment into a deeply nested `NestedIntList`. The bytecode-size cap (`DEFAULT_MAX_BYTECODE_SIZE = 80 * 1024` felts) constrains total leaf-segment data but not recursion depth, so an attacker can trade segment width for depth (many single-felt leaves under many single-child `Node`s) to maximize recursion depth within the size budget.

### Recommendation
- Impose an explicit maximum nesting depth (mirroring the depth-1 assertion already used in `NestedFeltCounts::new_inner`) when validating/consuming compiler-emitted `NestedIntList` structures, rejecting any class whose segment tree exceeds the bound, before calling `hash()`/`create_bytecode_segment_structure`.
- Alternatively/additionally, convert `bytecode_hash_node` and `create_bytecode_segment_structure_inner` to iterative (stack-based, depth-tracked) implementations that return an error instead of recursing unboundedly.
- Ensure the hash computation that currently runs unsandboxed in the main process after subprocess compilation also runs under equivalent isolation/resource limits, or run with a bounded-size, monitored stack (e.g., a dedicated thread with a fixed stack size and depth counter) so a stack overflow cannot take down the whole process.

### Proof of Concept
1. Author a Cairo1 contract whose Sierra code contains deeply nested conditional branches (e.g., programmatically generate `N` levels of nested `if`/`match` statements, where `N` is large, e.g. tens of thousands), keeping total bytecode length under `max_bytecode_size` (80 * 1024 felts) by keeping each branch segment minimal (1–2 felts).
2. Submit this contract via a DECLARE transaction to the gateway.
3. The Sierra→CASM compiler (sandboxed subprocess) segments the bytecode according to the nested branch structure, producing a `CasmContractClass` with a `bytecode_segment_lengths` field that is a `NestedIntList` with depth ≈ N.
4. `SierraCompiler::compile` (main process) calls `executable_class.hash(&HashVersion::V2)`, which recurses N levels deep in `bytecode_hash_node` — crashing the gateway/sequencer process with a stack overflow instead of returning an error.
5. If the class is ever included in a block, any node/prover performing Starknet OS re-execution hits the same unbounded recursion in `create_bytecode_segment_structure_inner`/`BytecodeSegmentNode::hash`, crashing that process as well.

/// Computes the hash of a bytecode segment. See the documentation of `bytecode_hash_node` in
/// the Starknet OS.
/// Returns the length of the processed segment and its hash.
fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

/// Computes the compiled class hash for a given hashable class using the specified hash algorithm.
fn hash_inner<H, EH, NL>(hashable_class: &impl HashableCompiledClass<EH, NL>) -> CompiledClassHash
where
    H: StarkHash,
    EH: EntryPointHashable,
    NL: HashableNestedIntList,
{
    let external_funcs_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_external_entry_points());
    let l1_handlers_hash = entry_point_hash::<H, EH>(hashable_class.get_hashable_l1_entry_points());
    let constructors_hash =
        entry_point_hash::<H, EH>(hashable_class.get_hashable_constructor_entry_points());

    let bytecode_hash = bytecode_hash::<H, NL>(
        &hashable_class.get_bytecode(),
        &*hashable_class.get_bytecode_segment_lengths(),
    );

    // Compute total hash by hashing each component on top of the previous one.
    CompiledClassHash(H::hash_array(&[
        *COMPILED_CLASS_V1,
        external_funcs_hash,
        l1_handlers_hash,
        constructors_hash,
        bytecode_hash,
    ]))
}

impl BytecodeSegmentNode {
    pub(crate) fn hash<H: HashFunction>(&self) -> StarkHash {
        match self {
            BytecodeSegmentNode::Leaf(leaf) => H::hash_array(&leaf.data),
            BytecodeSegmentNode::InnerNode(inner_node) => {
                let flatten_input: Vec<_> = inner_node
                    .segments
                    .iter()
                    .flat_map(|segment| [Felt::from(segment.length), segment.node.hash::<H>()])
                    .collect();
                H::hash_array(&flatten_input) + Felt::ONE
            }
        }
    }

/// Helper function for `create_bytecode_segment_structure`.
/// Returns the bytecode segment structure and the total length of the processed segment.
pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }

    /// Recursively builds the nested structure and returns it with the number of items consumed.
    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
    }
