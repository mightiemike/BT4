### Title
Unbounded, un-rate-limited `savedCallbacks` map in capabilities gateway handler allows DoS eviction of legitimate in-flight callbacks - ([File: core/services/gateway/handlers/capabilities/handler.go])

### Summary
`HandleLegacyUserMessage` in the WebAPI capabilities gateway handler inserts every incoming `MethodWebAPITrigger` request into `h.savedCallbacks` with no allowlist or per-sender rate limiting, explicitly marked by a `// TODO: apply allowlist and rate-limiting here` comment. Because pruning only runs on a fixed interval (`defaultCallbackPruneIntervalSec` = 30s) and evicts the oldest half of all saved callbacks once the map exceeds `MaxSavedCallbacks` (20000), an attacker who floods the gateway with distinct signed `web_api_trigger` messages between prune cycles can force eviction of legitimate, still-pending user callbacks.

### Finding Description
`gateway.ProcessRequest` routes any legacy request with a valid `DonId` and passing `msg.Validate()`/signature check to `handler.HandleLegacyUserMessage` [1](#0-0) . Inside `HandleLegacyUserMessage`, after basic payload/timestamp validation, the code explicitly skips allowlisting/rate-limiting: [2](#0-1) 

It then unconditionally stores the callback keyed by `msg.Body.MessageId` (attacker-controlled, unique per message) and fans the request out to all DON members: [3](#0-2) 

Contrast this with the sibling `functions` handler and `vault` handler, both of which perform allowlist and/or per-sender rate-limit checks (`h.allowlist.Allow`, `h.userRateLimiter.Allow`, or vault's `requestProcessor.ProcessRequest` authorization) before admitting a request into their pending-request stores [4](#0-3) . The capabilities handler has no equivalent gate — the only per-node rate limiter (`nodeRateLimiter`) applies to `handleWebAPIOutgoingMessage` (node → gateway direction), not to incoming user messages [5](#0-4) .

Eviction happens in `pruneCallbacks`, run only every `CallbackPruneIntervalSec` (default 30s): [6](#0-5) 

If the map exceeds `MaxSavedCallbacks` (20000) when the ticker fires, it sorts all entries by `createdAt` and deletes the oldest half — `entries[:len(entries)-maxSize/2]` — regardless of whether those callbacks belong to legitimate users still awaiting a response. An attacker who requires no privilege beyond being able to sign a message (any external user reaching the gateway's HTTP endpoint can construct a `web_api_trigger` legacy message) can insert far more than 20000 entries within a 30-second window, since insertion is essentially just an HTTP request plus JSON/signature construction with no per-sender throttling. This will evict legitimate victims' pending callbacks, whose `SendResponse` will never be called, causing their gateway requests to time out (silent DoS) with no auth bypass but a real availability impact.

### Impact Explanation
This is a Denial-of-Service against legitimate WebAPI-trigger gateway users: an unprivileged, unauthenticated (from the allowlist perspective) attacker can cause the gateway to silently drop/never respond to victims' in-flight capability trigger requests by out-registering their callbacks in the `savedCallbacks` map before the prune cycle runs. This matches a "protocol/service disruption via unbounded resource consumption without rate limiting" style bounty impact rather than fund loss or code execution, but it is a concrete availability/DoS bug in the gateway's capabilities handler.

### Likelihood Explanation
No special privilege is needed — only network access to the gateway HTTP endpoint and the ability to construct/sign JSON-RPC legacy messages of method `web_api_trigger`, which is explicitly called out in the code itself via the `// TODO: apply allowlist and rate-limiting here` comment, confirming this gap is known/unaddressed. The attack is repeatable every prune interval (30s by default) as long as the attacker can generate >20000 unique `MessageId`s and sustain the request rate, which is feasible for a scripted/fuzzing client with no rate limiting to slow it down on this path.

### Recommendation
Add per-sender rate limiting and/or an allowlist check (as already done in the `functions` and `vault` handlers) to `HandleLegacyUserMessage` before storing entries in `savedCallbacks`, and/or bound insertion by rejecting new callbacks once `MaxSavedCallbacks` is reached instead of only reactively evicting the oldest half on a timer, so that a burst cannot silently evict legitimate pending callbacks.

### Proof of Concept
Unit/load test plan for `core/services/gateway/handlers/capabilities/handler_test.go`:
1. Construct a `handler` with small `MaxSavedCallbacks` (e.g. 100) and `CallbackPruneIntervalSec` large enough that pruning does not run during the test.
2. Call `HandleLegacyUserMessage` with a legitimate user's signed `web_api_trigger` message; capture its callback/`MessageId`.
3. In a loop, rapidly call `HandleLegacyUserMessage` with >`MaxSavedCallbacks` distinct signed messages (varying `MessageId`, using freshly generated keys/signatures to simulate different unprivileged senders) — no rate limiter should block this given the code path skips it.
4. Manually invoke `pruneCallbacks()` (or wait for the ticker) and assert that the legitimate user's original `MessageId` is no longer present in `h.savedCallbacks`, i.e., its callback was evicted (`entries[:len(entries)-maxSize/2]`), and that no response was ever sent to it (`SendResponse` never called for the legitimate callback).
5. Expected (fixed) behavior: legitimate callback should survive eviction (e.g., via per-sender rate limiting rejecting the flood before insertion), and the test should assert the legitimate `MessageId` remains in `savedCallbacks` or receives its response.

	maxSize := h.config.MaxSavedCallbacks
	var evicted int
	if len(h.savedCallbacks) > maxSize {
		type entry struct {
			id        string
			createdAt time.Time
		}
		entries := make([]entry, 0, len(h.savedCallbacks))
		for id, cb := range h.savedCallbacks {
			entries = append(entries, entry{id, cb.createdAt})
		}
		sort.Slice(entries, func(i, j int) bool {

		})

			delete(h.savedCallbacks, e.id)

func (h *functionsHandler) HandleLegacyUserMessage(ctx context.Context, msg *api.Message, callback handlers.Callback) error {
	sender := common.HexToAddress(msg.Body.Sender)
	if h.allowlist != nil && !h.allowlist.Allow(sender) {
		h.lggr.Debugw("received a message from a non-allowlisted address", "sender", msg.Body.Sender)
		promHandlerError.WithLabelValues(h.donConfig.DonId, ErrNotAllowlisted.Error()).Inc()
		return ErrNotAllowlisted
	}
	if h.userRateLimiter != nil && !h.userRateLimiter.Allow(msg.Body.Sender) {
		h.lggr.Debugw("rate-limited", "sender", msg.Body.Sender)
		promHandlerError.WithLabelValues(h.donConfig.DonId, ErrRateLimited.Error()).Inc()
		return ErrRateLimited
	}
