### Title
`get_sorted_potential_ancient_slots` / `combine_ancient_slots_packed_internal` scan cost scales with distinct slot count, not account count or fees paid - ([File: accounts-db/src/accounts_db.rs], [File: accounts-db/src/ancient_append_vecs.rs])

### Summary
`AccountsDb::shrink_ancient_slots` calls `get_sorted_potential_ancient_slots`, which returns *every* storage slot older than `oldest_non_ancient_slot` from `self.storage.slots_less_than(...)` and sorts it, and then `combine_ancient_slots_packed_internal` re-scans that entire list via `calc_ancient_slot_info` on every invocation. If most of those slots are already "fully alive, tiny" storages, `filter_by_smallest_capacity` either does nothing (returns early when `total_storages <= max_ancient_slots`) or only combines a small, throughput-limited subset (`max_resulting_storages`, `low_threshold`) each pass, leaving the backlog to be fully re-scanned on the next pass. This makes per-pass CPU/I/O cost proportional to the number of distinct ancient slots the attacker has created, not to the number of accounts touched or fees paid.

### Finding Description
`shrink_ancient_slots` computes `oldest_non_ancient_slot` and calls `get_sorted_potential_ancient_slots`, which unconditionally collects and sorts *all* slots in `self.storage` below that boundary: [1](#0-0) 

`combine_ancient_slots_packed` then runs `combine_ancient_slots_packed_internal(sorted_slots, ...)`, which calls `calc_ancient_slot_info(sorted_slots, ...)` — an O(n) loop over the *entire* sorted-slot list every time it is invoked, doing a storage-map lookup and alive-bytes computation per slot regardless of whether that slot needs any work: [2](#0-1) [3](#0-2) 

`AncientSlotInfos::add` only drops a storage from `all_infos` entirely if it is already near `ideal_storage_size` (80% threshold); a tiny, fully-alive, single-account storage is neither `should_shrink` (nothing dead to reclaim) nor near ideal size, so it stays in `all_infos` and is re-processed on every pass: [4](#0-3) 

`filter_by_smallest_capacity` (called from `filter_ancient_slots` -> `collect_sort_filter_ancient_slots`) short-circuits and does no combining at all if `total_storages <= tuning.max_ancient_slots`, clearing `all_infos`/`shrink_indexes` for this pass without reducing the underlying storage-slot count: [5](#0-4) 

Even when `total_storages > max_ancient_slots`, `truncate_to_max_storages` limits how many storages get combined per pass via `max_resulting_storages` and `low_threshold` (`max_ancient_slots * 50 / 100`), so only a bounded fraction of the backlog is packed away each call: [6](#0-5) 

Net effect: an attacker who creates one minimal-lamport account per slot across many distinct slots (each slot requiring only one cheap transaction) accumulates many independent tiny ancient storages. None of the existing guards (zero-lamport pruning, ref-count checks, epoch-boundary gating) limit the *number of distinct slots* scanned by `get_sorted_potential_ancient_slots` / `calc_ancient_slot_info`; those functions always do O(slot-count) work per call, and the packing throughput per call is bounded independently of how many slots exist, so a growing backlog is re-scanned in full every time `shrink_ancient_slots` runs.

### Impact Explanation
This falls under the "disproportionate storage and CPU cost" background-cleanup category (ancient-packing CPU/I/O amplification), matching the scoped impact in the question. Each call to `shrink_ancient_slots` does O(number of distinct pre-ancient-boundary slots) work in `slots_less_than`, sorting, and `calc_ancient_slot_info`, regardless of how many accounts or how much fee revenue produced those slots. An attacker who spreads minimal-fee, minimal-lamport account writes thinly across many slots can grow this backlog roughly linearly with slot count while paying a fee only proportional to transaction count — and the per-pass scanning/sorting overhead is not itself gated by any per-account or per-fee cost, since fully-alive tiny storages are neither shrunk nor removed from consideration until the packer's bounded per-pass output quota catches up.

### Likelihood Explanation
Feasibility is constrained by real wall-clock slot production (one storage per rooted slot requires one leader slot to pass), so the attacker cannot create the backlog instantaneously; it accumulates over real time proportional to the number of distinct-slot transactions submitted. This is fully achievable by an unprivileged user submitting one cheap transaction per target slot across an extended period, entirely within the stated threat model (normal user paying for and controlling their own writes/timing). The condition is repeatable indefinitely as long as new small-storage slots are created faster than the bounded per-pass packing throughput (`max_resulting_storages`, `low_threshold`) can retire them, causing the re-scan cost of `get_sorted_potential_ancient_slots`/`calc_ancient_slot_info` to grow with accumulated slot count.

### Recommendation
Bound the per-pass scanning cost independently of accumulated slot count, e.g.: (1) cap the number of slots `get_sorted_potential_ancient_slots` returns per call (process the backlog in fixed-size batches rather than the full "slots_less_than" set), (2) track already-scanned-and-ideal-size slots in a persistent skip-set so they are not fully re-evaluated (`calc_ancient_slot_info`) on every pass, and (3) ensure `filter_by_smallest_capacity`'s early-return path (`total_storages <= max_ancient_slots`) still makes forward progress combining very small storages regardless of the `max_ancient_slots` target, so tiny single-account storages don't persist indefinitely as separate slots.

        db.store_for_tests((slot, [(&pubkey, &account)].as_slice()));
        db.add_root_and_flush_write_cache(slot);

    db.add_root(completed_slot);
    let oldest_non_ancient_slot = db.get_oldest_non_ancient_slot(&epoch_schedule);

    let (sorted_slots, select_us) =
        measure_us!(db.get_sorted_potential_ancient_slots(oldest_non_ancient_slot));
    assert_eq!(sorted_slots.len(), n, "backlog should equal attacker-created slot count");

        // early-return / throughput cap leaves most tiny storages unpacked, and the
        // O(n) rescan cost (select_us, calc_ancient_slot_info) repeats every pass.
        println!("remaining backlog: {}", remaining.len());

    fn truncate_to_max_storages(
        &mut self,
        tuning: &PackedAncientStorageTuning,
        stats: &ShrinkAncientStats,
    ) {
        // these indexes into 'all_infos' are useless once we truncate 'all_infos', so make sure they're cleared out to avoid any issues
        self.shrink_indexes.clear();
        let total_storages = self.all_infos.len();
        let mut cumulative_bytes = Saturating(0u64);
        let low_threshold = tuning.max_ancient_slots * 50 / 100;
        let mut bytes_from_must_shrink = 0;
        let mut bytes_from_smallest_storages = 0;
        let mut bytes_from_newest_storages = 0;
        for (i, info) in self.all_infos.iter().enumerate() {
            cumulative_bytes += info.alive_bytes;
            let ancient_storages_required =
                cumulative_bytes.0.div_ceil(tuning.ideal_storage_size.get()) as usize;
            let storages_remaining = total_storages - i - 1;

            // if the remaining uncombined storages and the # of resulting
            // combined ancient storages are less than the threshold, then
            // we've gone too far, so get rid of this entry and all after it.
            // Every storage after this one is larger than the ones we've chosen.
            // if we ever get to more than `max_resulting_storages` required ancient storages, that is enough to stop for now.
            // It will take a lot of time for the pack algorithm to create that many, and that is bad for system performance.
            // This should be a limit that only affects extreme testing environments.
            // We do not stop including entries until we have dealt with all the high slot #s. This allows the algorithm to continue
            // to make progress each time it is called. There are exceptions that can cause the pack to fail, such as accounts with multiple
            // refs.
            if !info.is_high_slot
                && (storages_remaining + ancient_storages_required < low_threshold
                    || ancient_storages_required as u64 > u64::from(tuning.max_resulting_storages))
            {
                self.all_infos.truncate(i);
                break;
            }
            if info.should_shrink {
                bytes_from_must_shrink += info.alive_bytes;
            } else if info.is_high_slot {
                bytes_from_newest_storages += info.alive_bytes;
            } else {
                bytes_from_smallest_storages += info.alive_bytes;
            }
        }

    fn calc_ancient_slot_info(
        &self,
        slots: Vec<Slot>,
        tuning: &PackedAncientStorageTuning,
    ) -> AncientSlotInfos {
        let len = slots.len();
        let mut infos = AncientSlotInfos {
            shrink_indexes: Vec::with_capacity(len),
            all_infos: Vec::with_capacity(len),
            ..AncientSlotInfos::default()
        };
        let mut randoms = 0;
        let max_slot = slots.iter().max().cloned().unwrap_or_default();
        // heuristic to include some # of newly eligible ancient slots so that the pack algorithm always makes progress
        let high_slot_boundary = max_slot.saturating_sub(HIGH_SLOT_OFFSET);
        let is_high_slot = |slot| slot >= high_slot_boundary;
        for slot in &slots {
            if let Some(storage) = self.storage.get_slot_storage_entry(*slot) {
                let is_candidate_for_shrink = self.is_candidate_for_shrink(&storage);
                let alive_bytes_after_shrink = self.alive_bytes_after_shrink(&storage) as u64;
                if infos.add(
                    *slot,
                    storage,
                    alive_bytes_after_shrink,
                    tuning.can_randomly_shrink,
                    tuning.ideal_storage_size,
                    is_high_slot(*slot),
                    is_candidate_for_shrink,
                ) {
                    randoms += 1;
                }
