### Title
Missing Upper Bound on Syscall Array-Size Before Allocation Causes Node DoS - ([File: crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs])

### Summary
`read_felt_array` reads a contract-controlled `array_size` Felt from Cairo VM memory and converts it directly to a `usize` allocation size, with no upper-bound / gas-based cap check before that size is used to build a Vec, mirroring the reported Elasticsearch bug class: a user-supplied count drives a large allocation before any existing safety limit is evaluated.

### Finding Description
`read_felt_array` reads the array length as a raw `Felt` from VM memory and converts it to `usize` with only an overflow check, not a magnitude/resource-based limit: [1](#0-0) 

The `array_size` value is decoded from memory the executing (attacker/deployer-controlled) contract populated as part of a deprecated syscall request (e.g. calldata/payload arrays for library-call, deploy, or send-message-to-L1 style requests) — it is not itself checked against the amount of data actually available before being handed to the array-reading routine, which then allocates a buffer sized by that value: [2](#0-1) 

The pattern is structurally identical to the reported CVE: a small, cheap request (just writing one large size felt into memory) causes the allocation size to be derived and used before the amount of real backing data, gas budget consumed, or any explicit cap is verified against that claimed size.

### Impact Explanation
If the length felt can be driven arbitrarily large (up to `usize::MAX`-range after the `try_from` conversion succeeds), the resulting allocation attempt can trigger an out-of-memory abort or an extremely expensive allocation/copy, crashing or stalling the sequencer node processing that transaction — a denial of service on that node, consistent with "Medium" severity DoS class described in the report (single node crash, not fund loss, but disrupts availability/liveness of block building for that node).

### Likelihood Explanation
Reachability requires only a normal contract invocation that exercises a deprecated syscall path using `read_felt_array` (e.g., building calldata/payload arrays for library-call/deploy/message syscalls) — no special privileges beyond submitting an ordinary transaction/contract call are needed, matching "an authenticated user... can submit one small... request" from the source report.

### Recommendation
Before allocating based on `array_size`, cap the value against a fixed maximum (or against the remaining bytes/felts actually available in the VM's memory segment) and return a syscall error rather than proceeding to allocate, analogous to the fix already applied in `CairoArray::try_from` in `crates/apollo_cairo_utils/src/lib.rs`, which validates a declared length against remaining data before calling `Vec::with_capacity`: [3](#0-2) 

### Proof of Concept
A contract executes a deprecated syscall whose request struct includes an array field parsed via `read_felt_array`; the contract writes a huge value (e.g. close to `usize::MAX`) as the declared `array_size` felt at the expected VM memory offset while providing an actual data segment far smaller than declared. The call into `read_felt_array` reads this size, converts it to `usize`, and passes it straight to the underlying range-reading allocation before any check that the segment actually contains that many elements, potentially aborting the process on allocation failure.

**Caveat:** I could not fully verify, within available search results, whether the underlying `felt_range_from_ptr`/VM range-read routine performs its own bound check prior to allocating (that logic may live inside the `cairo-vm` dependency rather than in this repository), so the exact allocation trigger point downstream of `read_felt_array` is not fully confirmed from the indexed code alone. [4](#0-3)

pub fn read_felt_array<TErr>(vm: &VirtualMachine, ptr: &mut Relocatable) -> Result<Vec<Felt>, TErr>
where
    TErr: From<StarknetApiError>
        + From<VirtualMachineError>
        + From<MemoryError>
        + From<MathError>
        + From<TryFromBigIntError<BigUint>>,
{
    let array_size = felt_from_ptr(vm, ptr)?;
    // An empty array's data pointer may be a felt-zero null (`cast(0, felt*)`) rather than a real
    // segment.
    if array_size == Felt::ZERO {
        *ptr = (*ptr + 1)?;
        return Ok(vec![]);
    }
    let array_data_start_ptr = vm.get_relocatable(*ptr)?;
    *ptr = (*ptr + 1)?;

    Ok(felt_range_from_ptr(vm, array_data_start_ptr, usize::try_from(array_size.to_biguint())?)?)
}
