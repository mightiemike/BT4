### Title
Gateway vault response aggregator accepts OCR-signed responses without binding them to the requesting request ID when `VaultSignedResponseRequestIDEnabled` is off (default) - ([File: core/services/gateway/handlers/vault/aggregator.go])

### Summary
The Buffer report describes `BufferRouter.resolveQueuedTrades` validating a signer's signature over a price but never checking that the *asset* in the signed payload matches the asset of the queued trade being resolved, so a validly-signed price for asset A can be used to fill an order for asset B. The Chainlink analog is in the vault gateway's response aggregation: `validateUsingSignatures` validates that a `SignedOCRResponse` carries a quorum of genuine DON signatures, but whether it also checks that the signed payload's `requestId` matches the JSON-RPC request currently being resolved is gated by the `VaultSignedResponseRequestIDEnabled` CRE setting — which defaults to disabled.

### Finding Description
`baseAggregator.Aggregate` decides how to validate an incoming vault DON response: [1](#0-0) 

When the `signedResponseRequestIDEnabled` gate is off (the default, per the dedicated regression test), `validateUsingSignatures` is called with `validateSignedPayloadRequestID = false` for **every** method, and the function returns success as soon as the OCR signature threshold is satisfied — the `SignedPayloadRequestID` check that ties the payload back to the specific `requestID` is entirely skipped: [2](#0-1) 

`vaulttypes.ValidateSignatures` only proves that the payload bytes were signed by a quorum of the vault DON's registered signers — it says nothing about which logical request that payload was produced for: [3](#0-2) 

The binding between a signed OCR payload and the specific request it answers is only enforced by the separate `SignedPayloadRequestID` extraction/comparison path, and only when the gate is enabled: [4](#0-3) 

Confirmed default-disabled state of the protective check: [5](#0-4) 

This is structurally identical to the BufferRouter flaw: a signature (of a price / of an OCR payload) is verified for authenticity, but the code omits verifying that the *signed content's identity field* (asset / requestId) matches the specific record being resolved (queued trade / active gateway request). With the gate off, the gateway will happily accept any correctly quorum-signed `SignedOCRResponse` for a supported method (`SecretsCreate`, `SecretsUpdate`, `SecretsDelete`, `SecretsList`) as the answer to the in-flight request, without checking that the payload's own `requestId` field corresponds to that request at all.

### Impact Explanation
If a stale, cached, or cross-request signed OCR response payload (e.g., a `ListSecretIdentifiersResponse` or `UpdateSecretsResponse` correctly signed by quorum for a *different* request/owner) is ever delivered to `HandleNodeMessage` for a different active request, the aggregator will accept it as authoritative for the current caller's request because payload/requestId binding is skipped entirely by default. This can result in a user receiving another request's (potentially another owner's) vault operation result, or a stale/replayed result being treated as fresh — a data-tampering / response-misattribution risk in the trust boundary between the gateway and its unprivileged HTTP/JSON-RPC clients, without requiring any malicious DON node (the signatures involved are genuine quorum signatures).

### Likelihood Explanation
Exploitability depends on the gateway or vault DON producing/caching a validly quorum-signed response whose payload `requestId` differs from the currently active gateway request (e.g., through response caching, retries, or concurrent request handling edge cases already acknowledged in the codebase, as seen in `sendVaultSignedOCRRequestToGateway`'s handling of timeouts and cached `publicKeyGet` responses). Because the protective `requestId` check is explicitly a CRE feature-gated addition (referenced by ticket `CRE-4875`) that is *off by default*, any code path that can cause a payload/requestID mismatch to reach the aggregator is currently unguarded in production configurations, whereas it is guarded when the gate is enabled. I was not able to fully trace, in the time available, a complete unprivileged-user proof-of-concept for the exact mechanism that causes payload/requestID divergence to reach `HandleNodeMessage` in practice (e.g., whether the public-key-get caching path or concurrent-request retry path can trigger it); this remains uncertain and would require further investigation into `handler.go`'s `HandleNodeMessage`/`activeRequests` routing logic.

### Recommendation
Make request-ID binding for signed OCR vault responses (`validateSignedPayloadRequestID = true`) unconditional rather than gated behind `VaultSignedResponseRequestIDEnabled`, mirroring the Buffer fix recommendation of always validating that signed content matches the specific record it is being applied to. At minimum, flip the default of `VaultSignedResponseRequestIDEnabled` to `true` and treat missing/mismatched `requestId` in the signed payload as a hard rejection rather than a tolerated fallback.

### Proof of Concept
Not independently reproduced end-to-end (would require crafting a scenario where `HandleNodeMessage` receives, for an active request, a genuinely quorum-signed `SignedOCRResponse` whose payload `requestId` corresponds to a different request/owner, then observing `baseAggregator.Aggregate` accept it). The existing test `TestAggregator_SignedResponseRequestIDMismatch` demonstrates the mismatch is only detected/rejected when the gate is explicitly enabled (`testAggregator(t, mcr, true)`), confirming that with the gate at its default `false` value the same mismatched payload would be accepted by `validateUsingSignatures`: [6](#0-5)

func (a *baseAggregator) Aggregate(ctx context.Context, l logger.Logger, requestID string, resps map[string]jsonrpc.Response[json.RawMessage], currResp *jsonrpc.Response[json.RawMessage]) (*jsonrpc.Response[json.RawMessage], error) {
	don, err := a.donForVaultCapability(ctx)
	if err != nil {
		return nil, fmt.Errorf("failed to get DON for vault capability: %w", err)
	}

	if a.signedResponseRequestIDEnabled(ctx, l) {
		if methodSupportsSignedOCRValidation(currResp.Method) {
			currResp, err = a.validateUsingSignatures(ctx, l, don.DON, don.Nodes, requestID, currResp, true)
			if err == nil {
				return currResp, nil
			}

			l.Debugw("failed to validate signatures, falling back to quorum aggregation", "error", err)
		}
	} else {
		currResp, err = a.validateUsingSignatures(ctx, l, don.DON, don.Nodes, requestID, currResp, false)
		if err == nil {
			return currResp, nil
		}

		l.Debugw("failed to validate signatures, falling back to quorum aggregation", "error", err)
	}

	currResp, err = a.validateUsingQuorum(don.DON, resps, l)
	if err != nil {
		return nil, fmt.Errorf("failed to validate using quorum: %w", err)
	}

	return currResp, nil
}

func (a *baseAggregator) validateUsingSignatures(ctx context.Context, l logger.Logger, don capabilities.DON, nodes []capabilities.Node, requestID string, resp *jsonrpc.Response[json.RawMessage], validateSignedPayloadRequestID bool) (*jsonrpc.Response[json.RawMessage], error) {
	if resp.Result == nil {
		if resp.Error != nil {
			return nil, errors.New("response has an error, cannot validate signatures. Error: " + resp.Error.Error())
		}
		return nil, errors.New("response result and error both are is nil: cannot validate signatures")
	}

	r := &vaulttypes.SignedOCRResponse{}
	err := a.unmarshal(bytes.NewReader(*resp.Result), r)
	if err != nil {
		return nil, err
	}

	signers := []common.Address{}
	for _, n := range nodes {
		signers = append(signers, common.BytesToAddress(n.Signer[0:20]))
	}

	err = vaulttypes.ValidateSignatures(r, signers, int(don.F+1))
	if err != nil {
		return nil, fmt.Errorf("failed to validate signatures: %w", err)
	}

	if !validateSignedPayloadRequestID {
		return resp, nil
	}

	payloadRequestID, err := vaultutils.SignedPayloadRequestID(resp.Method, r.Payload)
	if err != nil {
		l.Errorw("failed to read signed payload request id, discarding response", "requestID", requestID, "method", resp.Method, "error", err)
		a.recordSignedPayloadRequestIDMismatch(ctx)
		return nil, fmt.Errorf("%w: %w", errSignedPayloadRequestIDMismatch, err)
	}
	// Temporarily tolerate signed OCR reports from vault nodes that have not upgraded to
	// include requestId in the signed payload. Once all vault nodes are upgraded, the
	// gateway should start rejecting responses with a missing requestId.
	// https://smartcontract-it.atlassian.net/browse/CRE-4875
	if payloadRequestID != "" && payloadRequestID != requestID {
		logger.Sugared(l).Criticalw("signed payload request id mismatch, discarding response", "requestID", requestID, "signedPayloadRequestID", payloadRequestID, "method", resp.Method)
		a.recordSignedPayloadRequestIDMismatch(ctx)
		return nil, errSignedPayloadRequestIDMismatch
	}

	return resp, nil
}

func ValidateSignatures(resp *SignedOCRResponse, allowedSigners []common.Address, minRequired int) error {
	if len(resp.Context) < 64 {
		return fmt.Errorf("context too short: expected min 64 bytes, got %d bytes", len(resp.Context))
	}

	if len(resp.Signatures) < minRequired {
		return fmt.Errorf("not enough signatures: expected min %d, got %d", minRequired, len(resp.Signatures))
	}

	// The context contains:
	// 0:32 -> config digest
	// 32:64 -> epoch + round, namely:
	//   - 0:27 -> zero padding
	//   - 27:31 -> sequence number (big endian uint32)
	//   - 31:32 -> zero round value
	// 64:96 -> extra hash (not used by the vault plugin)
	cd, epochRound := resp.Context[:32], resp.Context[32:64]
	configDigest, err := ocr2types.BytesToConfigDigest(cd)
	if err != nil {
		return fmt.Errorf("invalid config digest in signature: %w", err)
	}

	epoch := binary.BigEndian.Uint32(epochRound[27:31])
	round := epochRound[31]

	fullHash := ocr2key.ReportToSigData(ocr2types.ReportContext{
		ReportTimestamp: ocr2types.ReportTimestamp{
			ConfigDigest: configDigest,
			Epoch:        epoch,
			Round:        round,
		},
	}, []byte(resp.Payload))

	validSigners := map[common.Address]bool{}
	for _, s := range resp.Signatures {
		signerPubkey, err := crypto.SigToPub(fullHash, s)
		if err != nil {
			return fmt.Errorf("invalid signature: %w", err)
		}
		signerAddr := crypto.PubkeyToAddress(*signerPubkey)

		for _, as := range allowedSigners {
			if as.Hex() == signerAddr.Hex() {
				validSigners[signerAddr] = true
				break
			}
		}

		if len(validSigners) >= minRequired {
			return nil
		}
	}

	return fmt.Errorf("only %d valid signatures, need at least %d", len(validSigners), minRequired)
}

// SignedPayloadRequestID extracts the requestId field from a vault OCR signed response payload.
func SignedPayloadRequestID(method string, payload json.RawMessage) (string, error) {
	if len(payload) == 0 {
		return "", errors.New("signed payload is empty")
	}

	unmarshal := protojson.UnmarshalOptions{DiscardUnknown: true}
	switch method {
	case vaulttypes.MethodSecretsCreate:
		resp := &vaultcommon.CreateSecretsResponse{}
		if err := unmarshal.Unmarshal(payload, resp); err != nil {
			return "", fmt.Errorf("failed to unmarshal signed create secrets payload: %w", err)
		}
		return resp.RequestId, nil
	case vaulttypes.MethodSecretsUpdate:
		resp := &vaultcommon.UpdateSecretsResponse{}
		if err := unmarshal.Unmarshal(payload, resp); err != nil {
			return "", fmt.Errorf("failed to unmarshal signed update secrets payload: %w", err)
		}
		return resp.RequestId, nil
	case vaulttypes.MethodSecretsDelete:
		resp := &vaultcommon.DeleteSecretsResponse{}
		if err := unmarshal.Unmarshal(payload, resp); err != nil {
			return "", fmt.Errorf("failed to unmarshal signed delete secrets payload: %w", err)
		}
		return resp.RequestId, nil
	case vaulttypes.MethodSecretsList:
		resp := &vaultcommon.ListSecretIdentifiersResponse{}
		if err := unmarshal.Unmarshal(payload, resp); err != nil {
			return "", fmt.Errorf("failed to unmarshal signed list secret identifiers payload: %w", err)
		}
		return resp.RequestId, nil
	default:
		return "", fmt.Errorf("unsupported method for signed payload request id validation: %s", method)
	}
}
