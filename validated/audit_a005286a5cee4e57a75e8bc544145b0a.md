### Title
Starknet OS `replace_class` syscall handler omits the "class must be declared" / Cairo1-only check enforced by the blockifier, causing OS/blockifier execution divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The reported Vvveb bug is a class of "authorization/validation bypass by trusting caller-controlled input without re-applying the check the rest of the system relies on." In the Starknet sequencer, the analogous pattern appears in the `replace_class` syscall: the Rust `blockifier` enforces that the target `class_hash` supplied by the calling contract is (a) actually declared and (b) a Cairo1 class before mutating contract state, but the Starknet OS Cairo re-implementation of the same syscall, used to prove/re-verify the block, skips this validation entirely (with an explicit `TODO` acknowledging the omission).

### Finding Description
Any contract can invoke the `replace_class` syscall with an attacker/caller-controlled `class_hash` taken directly from calldata (e.g. `test_contract.cairo`'s `test_replace_class`, or any custom contract). In the blockifier execution engine, `replace_class` is implemented in `crates/blockifier/src/execution/syscalls/syscall_base.rs`: [1](#0-0) 

This reads the compiled class (which fails if `class_hash` is not declared) and additionally rejects Cairo0 (V0) classes, before writing the new class hash into contract state.

The Starknet OS re-implements the same syscall in Cairo for the Cairo1 execution path in `syscall_impls.cairo`: [2](#0-1) 

Note line 902: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The function reads `class_hash` straight from the syscall request and unconditionally updates the `StateEntry` for `contract_address` via `dict_update`, with no declared-class check and no Cairo1-only check.

The Cairo0 (deprecated) syscall path exhibits the identical gap in `deprecated_execute_syscalls.cairo`: [3](#0-2) 

Here too, `execute_replace_class` blindly writes `class_hash` from the syscall request into the new `StateEntry` without verifying the class was declared.

### Impact Explanation
The Starknet OS is the Cairo program that re-executes every transaction in a block to generate the STARK proof of correctness, and is meant to be a faithful re-implementation of blockifier semantics; the resulting execution trace (and derived state commitments) must match what the blockifier (used by the sequencer/batcher to build the block) actually computed. Because the OS's `replace_class` implementation omits the declared-class and Cairo1-only checks that the blockifier enforces, a transaction that calls `replace_class` with an undeclared or V0 class hash:

- Reverts/fails in blockifier (`get_compiled_class` errors, or the Cairo1-only check trips `ForbiddenClassReplacement`), so the sequencer's real state diff for that call reflects a revert and no class-hash mutation, and
- Is accepted (or handled path-inconsistently) by the OS's Cairo implementation, which unconditionally performs the state mutation and revert-log entry regardless of whether the class is declared or which Cairo version it is.

This produces execution divergence between the blockifier (used to build/commit the block) and the OS (used to prove/verify the block): the OS can compute a different `contract_state_changes`/class hash outcome than the one actually committed, leading to a state root / block-hash mismatch between the trusted execution and its proof, i.e. an honest-node divergence and a corrupted committed root for that contract's class assignment. This is directly reachable by a single unprivileged transaction/contract call (any contract exposing a `replace_class` invocation with attacker-supplied calldata), matching the "unauthorized state mutation via unchecked caller-controlled ID" pattern in the source report.

### Likelihood Explanation
High reachability: `replace_class` is a standard syscall exposed to any Cairo1 contract; an attacker only needs to deploy or call a contract that forwards an arbitrary `class_hash` argument into the syscall (as already demonstrated by existing test contracts in the repo, e.g. `test_contract.cairo`'s `test_replace_class`/`test_forbidden_syscall_in_virtual_mode`). No special privilege, staking, or protocol role is required — a normal `INVOKE` transaction from any account suffices to trigger the divergent code path in the OS.

### Recommendation
Add the same validation to both OS syscall implementations that the blockifier performs before mutating `StateEntry.class_hash`:
1. In `syscall_impls.cairo::execute_replace_class`, verify (via `contract_class_changes` / declared-classes state) that `request.class_hash` corresponds to a declared, Cairo1 class before performing `dict_update`; fail/revert the syscall analogously to `SyscallExecutionError::ForbiddenClassReplacement` / "is not declared" errors in the blockifier if not.
2. Apply the equivalent check in `deprecated_execute_syscalls.cairo::execute_replace_class` for the Cairo0 execution path.
3. Add regression tests (OS flow tests) that call `replace_class` with an undeclared class hash and with a Cairo0 class hash, asserting the OS re-execution result (revert/failure) matches blockifier behavior bit-for-bit.

### Proof of Concept
1. Deploy a Cairo1 contract exposing a function that calls `replace_class_syscall(attacker_supplied_class_hash)` with `attacker_supplied_class_hash` set to a value that has never been declared (or belongs to a Cairo0/V0 class).
2. Submit an `INVOKE` transaction calling this function.
3. In blockifier (sequencer execution), the call reverts: `syscall_base.rs::replace_class` returns an error (`get_compiled_class` fails, or `ForbiddenClassReplacement` for V0 classes) — confirmed by existing tests in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs` (`undeclared_class_hash`, `cairo0_class_hash`).
4. When the Starknet OS re-executes the identical transaction/calldata for proof generation (`syscall_impls.cairo::execute_replace_class`, or the Cairo0 path in `deprecated_execute_syscalls.cairo`), no such check exists — the OS Cairo code unconditionally writes the new (invalid) `class_hash` into `contract_state_changes` and appends a `RevertLogEntry`, producing an execution result and state diff inconsistent with the actual blockifier-committed state.

Note: exhaustively confirming that no external check exists elsewhere in the OS pipeline (e.g., a later global "all touched classes must be declared" validation pass) was not fully possible with the available static search of `output.cairo`/`transaction_impls.cairo`; if such a global check exists, its exact code path should be inspected to see if it happens before or after this state mutation and whether it covers this specific case.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
