### Title
Unauthorized gas-fee draining of arbitrary on-chain contracts via zero-value CEA inbound `executeUniversalTx` calls - (File: x/uexecutor/keeper/execute_inbound_funds_and_payload.go)

### Summary
The CEA (contract-execution-address) inbound path lets an attacker designate *any* deployed, non-UEA smart contract on Push Chain as the `Recipient` of an inbound message and supply arbitrary `UniversalPayload.Data`. Unlike the UEA path (which requires the UEA contract to verify a signature bound to the payload before spending its owner's gas), the smart-contract branch has **no authorization check at all** — `CallExecuteUniversalTx` is called unconditionally for any deployed contract, and `DeductGasFeesFromReceipt` then burns native `upc` from that contract's own balance to pay for gas, regardless of whether the contract's owner ever consented to being called with that payload. This lets an attacker use a victim contract's own residual/native balance to pay for gas of calls the attacker fully controls — the same class of bug as the "residual allowance" report: an unprivileged party reaching into a balance/allowance that was never granted to them for this specific purpose.

### Finding Description
In `ExecuteInboundFundsAndPayload` (`x/uexecutor/keeper/execute_inbound_funds_and_payload.go`), when `utx.InboundTx.IsCEA` is true and `Recipient` resolves to a deployed contract that is *not* a UEA (`isUEA == false`, `codeHash != EmptyCodeHash`), `isSmartContract` is set to `true` [3](#0-2) . Crucially, unlike the UEA branch (`inboundAmount.Sign() > 0` gate for deposit, then `ExecutePayloadV2` which calls `CallUEAExecutePayload` with `verificationData` that the UEA contract cryptographically verifies), the smart-contract branch's `CallExecuteUniversalTx` invocation is unconditional and has **no amount gate and no signature check**:

```go
// isSmartContract path — always runs once entered, regardless of amount
contractReceipt, contractErr = k.CallExecuteUniversalTx(
    cacheCtx,
    ueaAddr,                         // attacker-chosen recipient contract
    utx.InboundTx.SourceChain,
    []byte(utx.InboundTx.Sender),    // attacker-chosen "sender" on source chain
    payload,                         // attacker-chosen raw calldata
    amount,
    prc20Addr,
    txId,
)
if contractErr == nil {
    feeErr = k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, contractReceipt, utx.InboundTx.UniversalPayload)
``` [4](#0-3) 

`CallExecuteUniversalTx` sends the call as the `uexecutor` module account (`isModuleSender=true`) directly into `recipientAddr.executeUniversalTx(sourceChain, ceaAddress, payload, amount, prc20AssetAddr, txId)` [5](#0-4) . There is no verification that the contract's deployer/owner authorized this specific `Sender`/`payload` combination — the UEA contract-level signature check documented in `x/uexecutor/README.md` (lines 220-237) only applies to the UEA branch, not this smart-contract branch.

`DeductGasFeesFromReceipt` then unconditionally burns `upc` from the recipient contract's own account balance to cover `receipt.GasUsed` [6](#0-5) , using `MaxFeePerGas`/`MaxPriorityFeePerGas`/`GasLimit` values taken from the attacker-supplied `UniversalPayload` embedded in the inbound (not from any owner-approved data).

Because the `IsCEA` path is populated straight from a source-chain event that a UV observes and votes on (honest validators simply relay what actually happened on the source chain), an attacker fully controls: (1) the `Recipient` (any deployed contract address on Push Chain, chosen without that contract owner's consent), (2) the raw `Data` executed via `executeUniversalTx`, and (3) `GasLimit`/`MaxFeePerGas` used for fee calculation — while the actual gas cost is paid out of the *recipient's* own upc balance, not the attacker's.

### Impact Explanation
Any account holding native `upc` on Push Chain that also happens to be (or ever becomes) a deployed contract address can have its balance drained via repeated attacker-triggered CEA inbounds that call arbitrary payloads against it and bill gas to it, with no consent, no minimum bridged amount required (deposit is gated on `amount>0` but the `executeUniversalTx` call/fee-burn is not), and no signature check. This is unauthorized burn of protocol-user funds reachable purely from an ordinary attacker-controlled source-chain transaction plus honest UV voting — matching the in-scope "unauthorized burn ... of user or protocol-controlled funds" and "unauthorized module-originated EVM execution" impact categories.

### Likelihood Explanation
Reaching this path requires only: (a) registering/triggering one qualifying CEA-style inbound event on a supported source chain (attacker fully controls the event's sender/payload/recipient fields within the gateway's encoding), and (b) 2/3+ honest UV votes simply relaying that genuine observation — no validator collusion or privileged access needed. The victim only needs to be any already-deployed contract on Push Chain holding `upc` for gas.

### Recommendation
Gate the smart-contract `executeUniversalTx` branch behind the same authorization discipline as the UEA branch: either (a) require the target contract to explicitly opt in / whitelist accepted callers for CEA-triggered `executeUniversalTx`, (b) require `inboundAmount.Sign() > 0` (or some minimum bridged value) before allowing arbitrary payload execution against a third-party contract, and/or (c) never charge gas fees to the recipient's own balance for CEA-triggered contract calls unless the recipient contract has explicitly funded/approved a "CEA relayer" allowance for that purpose, rather than debiting its full native balance unconditionally.

### Proof of Concept
1. Deploy (or identify) a contract `C` on Push Chain holding native `upc` for its own gas needs (e.g., a normal dApp contract, not a UEA).
2. On a registered source chain, submit a bridge event (via the gateway) with `TxType = FUNDS_AND_PAYLOAD`, `IsCEA = true`, `Recipient = C`, `Amount = 0` (or negligible), and `UniversalPayload.Data` set to any calldata the attacker wants `C` to execute, with `GasLimit`/`MaxFeePerGas` set high.
3. Honest UVs observe and vote the inbound to quorum via `MsgVoteInbound` — no special privilege needed since this is genuine relaying of the real source-chain event.
4. `ExecuteInboundFundsAndPayload` finalizes: `isUEA` is false, `codeHash != EmptyCodeHash` → `isSmartContract = true`; `CallExecuteUniversalTx` invokes `C.executeUniversalTx(...)` with attacker payload; `DeductGasFeesFromReceipt` burns `upc` from `C`'s account to cover the gas, with no signature or consent check from `C`'s owner.
5. Repeat cheaply (attacker only pays negligible source-chain fees) to drain `C`'s `upc` balance over multiple inbounds.

// CallExecuteUniversalTx calls executeUniversalTx on a smart-contract recipient.
// This is used for isCEA inbounds whose recipient is a deployed contract (not a UEA).
func (k Keeper) CallExecuteUniversalTx(
	ctx sdk.Context,
	recipientAddr common.Address,
	sourceChain string,
	ceaAddress []byte,
	payload []byte,
	amount *big.Int,
	prc20AssetAddr common.Address,
	txId [32]byte,
) (*evmtypes.MsgEthereumTxResponse, error) {
	recipientABI, err := types.ParseRecipientContractABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse recipient contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		recipientABI,
		ueModuleAccAddress,
		recipientAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"executeUniversalTx",
		sourceChain,
		ceaAddress,
		payload,
		amount,
		prc20AssetAddr,
		txId,
	)

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
