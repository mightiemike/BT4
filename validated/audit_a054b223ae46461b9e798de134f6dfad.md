## Title
Division before multiplication in bouncer's per-builtin proving-gas cost derivation amplifies rounding-down, allowing the bouncer to systematically undercount block proving-gas usage - (File: crates/blockifier/src/bouncer.rs)

### Summary
`BuiltinInstanceLimits::induced_gas_costs` derives a per-instance proving-gas cost for every Cairo builtin/opcode by performing an integer division (`proving_gas.0 / limit.get()`) *before* that per-unit cost is later multiplied by the actual number of instances a transaction used, exactly the "division before multiplication" pattern flagged in the referenced report.

### Finding Description
`induced_gas_costs` computes, for each builtin, `cost = floor(proving_gas / limit)`: [1](#0-0) 

This per-unit, already-floored cost (`BuiltinGasCosts`) is exposed via `BouncerConfig::builtin_gas_costs`: [2](#0-1) 

and is subsequently *multiplied* by the number of instances a submitted transaction actually consumed for each builtin (via `cairo_primitives_to_gas` inside `proving_gas_from_cairo_primitives_and_sierra_gas`, which is used when building `BouncerWeights` in `get_tx_weights`/`try_update`): [3](#0-2) 

Because the per-unit rate is truncated by integer division *before* it is multiplied by a (potentially large, single-transaction-controlled) instance count, the rounding-down error scales linearly with usage — precisely the amplification effect described in the external report (`(a/b)*b` vs `(a*b)/b`). For example, with `range_check` (default limit `66_666_666` per the default `BuiltinInstanceLimits`) and a `proving_gas` budget that is not an exact multiple of the limit, `derive()` truncates the per-unit cost downward; a transaction consuming a very large number of `range_check` instances (submitted directly via a contract call, reachable by any unprivileged transaction sender) will have its true proving-gas cost undercounted by `count * (true_rate - floored_rate)`, which can be a nontrivial fraction of the entire per-block proving-gas budget.

### Impact Explanation
The bouncer's accumulated `BouncerWeights.proving_gas` is the value checked against `BouncerConfig.block_max_capacity.proving_gas` to decide whether the block still has room for a transaction: [4](#0-3) [5](#0-4) 

If the per-builtin rate used for this accounting is systematically rounded down before being multiplied by usage, the sequencer can admit transactions/blocks whose *true* proving cost exceeds the intended `proving_gas` capacity while `try_update`/`verify_tx_weights_within_max_capacity` still reports the block as within capacity. This can lead to blocks being built that exceed the real prover's capacity budget, risking an inability to generate/verify proofs for produced blocks (i.e., a network unable to confirm new transactions in a timely, provable way), which matches the accepted "network unable to confirm new transactions" impact category.

### Likelihood Explanation
Reachability requires only a normal, unprivileged transaction that heavily uses one or more Cairo builtins (e.g., many `range_check`, `bitwise`, `poseidon` operations) — a pattern any external caller can trigger via ordinary contract execution. No special privileges are needed; the flaw is in production accounting code (`bouncer.rs`) that runs during block building for every transaction (`Bouncer::try_update`), making the amplified rounding error deterministic and reproducible given known default `BuiltinInstanceLimits` values (e.g., `range_check: 66_666_666`, `proving_gas` default `5_000_000_000`, `5_000_000_000 % 66_666_666 != 0`).

### Recommendation
Avoid computing and caching a pre-floored per-unit rate. Instead, defer the division until after multiplication by usage count, e.g., compute `(proving_gas.0 * count) / limit.get()` per builtin at usage-accounting time (or use exact rational arithmetic, similar to the `Ratio`-based approach already used elsewhere in `blockifier_versioned_constants.rs` for L1/L2 gas conversions), and/or round up (`ceil`) instead of down when deriving conservative per-unit costs used for capacity enforcement, so that accumulated weights never underestimate real proving-gas consumption.

### Proof of Concept
1. Configure (or use default) `BuiltinInstanceLimits { range_check: 66_666_666, .. }` and `BouncerConfig.block_max_capacity.proving_gas = 5_000_000_000` (the shipped default values): [6](#0-5) 
2. `induced_gas_costs` computes `range_check_cost = 5_000_000_000 / 66_666_666 = 75` (floor), whereas the exact rational rate is `75.0000045`.
3. Submit/execute a transaction (or several) that collectively use a very large number of `range_check` operations, e.g. `N = 66_666_666` (one full builtin-limit's worth). The bouncer accounts `N * 75 = 5_000_000_000 - N*epsilon` proving-gas (slightly less than intended), while the true intended consumption for exhausting one builtin's fair share of the budget is `proving_gas` exactly (5,000,000,000) plus similar shortfalls compound across multiple transactions and multiple builtins in the same block.
4. Over many transactions in a block (or many blocks), the cumulative shortfall (`N * limit-derived rounding error`) grows, letting the bouncer admit transactions whose aggregate real proving cost exceeds `block_max_capacity.proving_gas`, while `Bouncer::try_update`'s capacity check (`bouncer_config.has_room`) still reports room: [7](#0-6) 

Note: I was not able to fully trace every downstream consumer of `proving_gas` weights (e.g., exact prover input construction) within the available time/index limits, so the precise numeric magnitude of exploitable drift in a live network configuration should be validated with a live build/test run; the core rounding-direction defect in `induced_gas_costs` is confirmed directly from the source.

impl BuiltinInstanceLimits {
    /// Induces the per-instance proving-gas cost of each Cairo primitive from its per-block
    /// instance limit: `cost = floor(proving_gas / limit)`.
    pub fn induced_gas_costs(&self, proving_gas: GasAmount) -> BuiltinGasCosts {
        let derive = |limit: NonZeroU64| -> u64 { proving_gas.0 / limit.get() };
        BuiltinGasCosts {
            pedersen: derive(self.pedersen),
            range_check: derive(self.range_check),
            range_check96: derive(self.range_check96),
            poseidon: derive(self.poseidon),
            ecdsa: derive(self.ecdsa),
            ecop: derive(self.ecop),
            bitwise: derive(self.bitwise),
            keccak: derive(self.keccak),
            add_mod: derive(self.add_mod),
            mul_mod: derive(self.mul_mod),
            blake: derive(self.blake),
        }
    }

/// Calculates proving gas from builtin counters and Sierra gas.
fn proving_gas_from_cairo_primitives_and_sierra_gas(
    sierra_gas: GasAmount,
    cairo_primitives_counters: &CairoPrimitiveCounterMap,
    proving_builtin_gas_costs: &BuiltinGasCosts,
    sierra_builtin_gas_costs: &BuiltinGasCosts,
) -> GasAmount {
    let cairo_primitives_proving_gas =
        cairo_primitives_to_gas(cairo_primitives_counters, proving_builtin_gas_costs);
    let steps_proving_gas =
        sierra_gas_to_steps_gas(sierra_gas, cairo_primitives_counters, sierra_builtin_gas_costs);

    steps_proving_gas.checked_add_panic_on_overflow(cairo_primitives_proving_gas)
}
