### Title
Signer-side global-agreement threshold uses floor rounding while block-approval threshold uses ceiling rounding, allowing a sub-quorum weight to be treated as "agreed" - (File: libsigner/src/v0/signer_state.rs)

### Summary
`GlobalStateEvaluator::reached_agreement` (and its complement `reached_disagreement`) computes the 70% consensus threshold for the signer set's local state machine (current miner, burn view, tx-replay set, protocol version) using truncating integer division, while the analogous, consensus-critical threshold used to actually approve a Nakamoto block, `NakamotoBlockHeader::compute_voting_weight_threshold`, explicitly rounds the same 70% fraction *up* (ceiling). These two functions compute nominally the same "supermajority-of-weight" quantity from the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` constant but round it differently, so for many `total_weight` values the two thresholds differ by exactly one unit of weight.

### Finding Description
`compute_voting_weight_threshold` in [1](#0-0)  computes:
```
ceil = if (total_weight * threshold) % 10 == 0 { 0 } else { 1 };
(total_weight * threshold) / 10 + ceil
```
i.e. `ceil(total_weight * threshold / 10)`. This is the threshold used by `verify_signer_signatures` [2](#0-1)  to decide whether a Nakamoto block has enough signer weight to be valid.

`GlobalStateEvaluator::reached_agreement` in [3](#0-2)  computes:
```
u64::from(vote_weight) >= u64::from(self.total_weight).strict_mul(NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD) / 10
```
i.e. `floor(total_weight * threshold / 10)` — no ceiling correction. This function (and `reached_disagreement`, same file, lines 179-183) is what signers use to decide the "global state" (agreed current miner, agreed burn-block view, protocol version, tx-replay set) via `determine_global_state`, `determine_global_burn_view`, and `determine_latest_supported_signer_protocol_version` [4](#0-3) .

Both functions are meant to express the same "70% of signer weight" supermajority rule from the same `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD` constant, but whenever `total_weight * threshold` is not evenly divisible by 10, the two disagree by one unit of weight: the block-approval threshold rounds up (stricter), while the local/global state-agreement threshold rounds down (looser). For example, with `total_weight = 3` and `threshold = 7` (70%), `compute_voting_weight_threshold` yields `3` (ceil(2.1)=3) but `reached_agreement` accepts `vote_weight = 2` (floor(2.1)=2) as sufficient for "agreement."

This breaks the equality that both mechanisms are supposed to express the same supermajority-of-weight predicate. A set of signers whose combined weight is enough to satisfy `reached_agreement` but not `compute_voting_weight_threshold` can cause the signer network to believe it has reached global agreement on "who the current miner is" or "which burn view is canonical" without holding the weight actually required to co-sign (approve) a Nakamoto block under `verify_signer_signatures`.

### Impact Explanation
This is a minority-triggerable divergence (no majority/Sybil assumption needed — it only requires the natural distribution of signer weights, which can be adversarially engineered by an unprivileged party controlling stacked amounts to land on a "boundary" `total_weight` value). Because signer-side global-state agreement (miner selection, burn view) can be satisfied at a strictly lower weight than the weight actually required to sign a block, signers using the weaker `reached_agreement` threshold can commit to a "current miner"/tenure view that a subset controlling less than the true (ceiling) supermajority could never get co-signed into an actual valid Nakamoto block. This produces a temporary tip/state disagreement between signers (and versus nodes enforcing the stricter block-approval threshold), matching the "High — minority-triggerable signer weight below threshold... temporary tip disagreement" category in scope.

### Likelihood Explanation
The trigger condition (`total_weight * 7 mod 10 != 0`) occurs for the majority of possible `total_weight` values (any weight not a multiple of 10), so this is not a rare edge case — it is the common case for realistic signer-set weight totals. No privileged access or majority coalition is required; it is purely a function of the (attacker-influenceable via stacked-amount apportionment) total signer weight.

### Recommendation
Make `GlobalStateEvaluator::reached_agreement`/`reached_disagreement` use the same ceiling-rounding formula as `NakamotoBlockHeader::compute_voting_weight_threshold` (i.e., factor out a single shared threshold function and use it in both `stackslib` and `libsigner`), so that "reaching agreement" in the signer state machine can never be satisfied by less weight than would be required to actually approve a block.

### Proof of Concept
1. Construct a signer set with `total_weight = 3` (e.g., three signers each with weight 1), with `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD = 7` (70%).
2. Compute `NakamotoBlockHeader::compute_voting_weight_threshold(3)` → `(3*7)/10 + 1 = 2 + 1 = 3` (needs all 3 signers).
3. Compute `GlobalStateEvaluator::reached_agreement(2)` with `total_weight = 3` → `2 >= (3*7)/10 = 2` → `true` (only 2 of 3 signers needed).
4. Two signers (weight 2/3, below the 3/3 needed to actually co-sign a block per step 2) can drive the signer network's `determine_global_state`/`determine_global_burn_view` to "agree" on a miner/burn view that the third signer disputes, while no valid Nakamoto block can actually be produced and approved under the stricter block-level threshold — producing a state/tip disagreement among signers and between signers and full nodes.

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }

    /// Determine what the maximum signer protocol version that a majority of signers can support
    pub fn determine_latest_supported_signer_protocol_version(&self) -> Option<u64> {
        let mut protocol_versions = HashMap::new();
        for (address, update) in &self.address_updates {
            let Some(weight) = self.address_weights.get(address) else {
                continue;
            };
            let entry = protocol_versions
                .entry(update.local_supported_signer_protocol_version)
                .or_insert_with(|| 0);
            *entry += weight;
        }
        // find the highest version number supported by a threshold number of signers
        let mut protocol_versions: Vec<_> = protocol_versions.into_iter().collect();
        protocol_versions.sort_by_key(|(version, _)| *version);
        let mut total_weight_support: u32 = 0;
        for (version, weight_support) in protocol_versions.into_iter().rev() {
            total_weight_support += weight_support;
            if self.reached_agreement(total_weight_support) {
                return Some(version);
            }
        }
        None
    }

    /// Determine what the global burn view is if there is one
    pub fn determine_global_burn_view(&self) -> Option<(&ConsensusHash, u64)> {
