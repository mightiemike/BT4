### Title
Unauthenticated free class declaration via unrestricted `BOOTSTRAP` sender address in the declare transaction execution path - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/transaction_impls.cairo])

### Summary
The declare-transaction execution flow (both in the Starknet OS Cairo implementation and in the Rust blockifier) contains a special "bootstrap" path that skips `__validate_declare__`, nonce increment, and fee charging whenever a declare transaction's `sender_address` equals the constant `'BOOTSTRAP'`, `nonce == 0`, and `max_possible_fee == 0`. Unlike the Footium report — where a division-tier fee that was never configured let a club owner mint for free — here the exemption is granted purely by matching a well-known constant sender address and zero resource bounds, with no check that this is actually a genesis/bootstrap moment (e.g. no restriction to block 0 or to a specific authorized caller in the execution layer itself).

### Finding Description
In the OS declare handler, any declare transaction whose `sender_address == 'BOOTSTRAP'`, `nonce == 0`, `version == 3`, and `max_possible_fee == 0` (i.e., all resource bounds are zero) is fast-pathed: it skips `__validate_declare__`, nonce increment (`check_and_increment_nonce` is never called), and `charge_fee`, and directly writes the class hash into `contract_class_changes`. [1](#0-0) 

The Rust-side blockifier mirrors this: `AccountTransaction::execute_raw` checks `tx.is_bootstrap_declare(charge_fee)` and, if true, executes only the raw declare (registering the class) and returns a `TransactionExecutionInfo::default()` — no validation call info, no fee transfer, no nonce bump. [2](#0-1) 

`is_bootstrap_declare` and `bootstrap_address()` show the gating condition is only: fixed sender address constant `'BOOTSTRAP'`, `nonce == 0`, and `charge_fee == false` (i.e., zero resource bounds at the gateway/mempool layer determine `charge_fee`). [3](#0-2) 

Crucially, because `sender_address == 'BOOTSTRAP'` has no deployed account contract, `__validate_declare__` is never invoked for this path, so **no signature verification of any kind occurs**. This means any party — with no private key, no funds, and no special permission — can craft a `DeclareTransaction::V3` with `sender_address = bootstrap_address()`, `nonce = 0`, and `resource_bounds` set to all-zero (`ValidResourceBounds::create_for_testing_no_fee_enforcement()`/`new_unlimited_gas_no_fee_enforcement()`), and it will be treated by the execution layer as a valid, fee-free, signature-free class declaration for the given `class_hash`/`compiled_class_hash` pair, as long as that class hash has never been declared before (enforced only via `dict_update{...}(prev_value=0, ...)`).

The only other gate that exists is at the gateway layer: `check_declare_permissions` calls `self.config.is_authorized_declarer(&declare_v3_tx.sender_address)`. [4](#0-3) 
However, this is purely an *operator-configurable allowlist policy* at the gateway/mempool-entry boundary — it says nothing about whether the `BOOTSTRAP` address is excluded from that allowlist by default, and more importantly, the actual execution-layer enforcement (blockifier `execute_raw` and the OS Cairo code) has **no analogous restriction at all** — it does not check block number, does not check whether the chain has already progressed past genesis, and does not require any authorization beyond the sender-address/nonce/fee-bound pattern match. If a transaction bearing this pattern ever reaches execution (e.g., via a differently configured gateway, a permissioned relay, direct batcher/mempool injection in a hybrid deployment, or any gateway misconfiguration of `is_authorized_declarer`), it will be accepted as a legitimate free declaration by every honest node re-executing the block (including the Starknet OS re-execution), since the exemption logic is baked into the core execution/OS code, not merely the gateway.

### Impact Explanation
Any transaction that reaches execution matching the `BOOTSTRAP`/nonce-0/zero-fee pattern bypasses signature verification, fee charging, and nonce consumption entirely, permanently declaring an arbitrary class for free. Since the check is embedded in both the blockifier (`account_transaction.rs`) and the Starknet OS Cairo program (used for re-execution/proving), this is not a peripheral gateway bug: if such a transaction is admitted anywhere in the pipeline (mempool, batcher, or a differently configured gateway instance in a distributed/hybrid topology), it will be committed as valid state, and honest nodes replaying the OS will agree, permanently declaring the class hash without payment — an unauthorized privileged action ("declare for free") performed by an unprivileged sender, and a bypass of the fee/resource-accounting mechanism that is supposed to gate all declare transactions.

### Likelihood Explanation
The pattern-matching condition (`sender_address == 'BOOTSTRAP'`, `nonce == 0`, zero resource bounds) is a fixed, publicly known constant with no cryptographic protection at the execution layer. The only defense against arbitrary submission is the gateway-level `is_authorized_declarer` allowlist check, which is an external/operator configuration concern, not a protocol-level invariant enforced by the executor itself. Any deployment path that does not funnel every declare through that specific gateway check (e.g. a batcher/mempool P2P-received transaction, a different topology, or a future change to `check_declare_permissions`) would allow this bug to be triggered by any unprivileged party submitting a single transaction.

### Recommendation
Move the bootstrap-declare authorization enforcement into the execution layer itself (blockifier `account_transaction.rs` and the OS Cairo declare handler), rather than relying solely on the gateway's `is_authorized_declarer` policy check. Specifically: restrict the bootstrap-declare fast path to only be valid when the current block number is genesis (e.g., block 0), and/or require that this path can only be exercised once per class ever and only during an explicit, protocol-enforced bootstrap phase rather than being reachable indefinitely by pattern-matching a constant address. Ensure the OS re-execution logic in `transaction_impls.cairo` and the blockifier's `is_bootstrap_declare`/`execute_raw` share and enforce the same invariant so that no combination of gateway misconfiguration or alternate transaction-submission path can reach this fee-free declare path outside of genesis.

### Proof of Concept
1. Construct a `DeclareTransaction::V3` with:
   - `sender_address = DeclareTransaction::bootstrap_address()` (the constant `'BOOTSTRAP'` address)
   - `nonce = Nonce(Felt::ZERO)`
   - `resource_bounds = ValidResourceBounds::create_for_testing_no_fee_enforcement()` (all-zero bounds, `max_possible_fee == 0`)
   - Any valid `class_hash`/`compiled_class_hash` pair not previously declared, with an empty/default signature (no signing key needed since `__validate_declare__` is never called). [5](#0-4) 
2. Submit this transaction to any transaction-admission path that does not independently reject the `BOOTSTRAP` sender/zero-fee combination (bypassing or absent the gateway's `is_authorized_declarer` allowlist).
3. `AccountTransaction::execute_raw` detects `is_bootstrap_declare(charge_fee) == true`, skips validation, nonce increment, and fee charging, and directly registers the class. [6](#0-5) 
4. The class hash is now declared in state at zero cost and without any signature check, and the Starknet OS re-execution (used for proving/verification) will independently confirm this same free declaration via the identical `sender_address == 'BOOTSTRAP'` branch. [7](#0-6)

        // meet the following conditions.
        // This flow is used for the sequencer to bootstrap a new system.
        // Note: The absence of any account-related action leads to some unintuitive but expected
        // behavior:
        // - After the transaction is executed successfully, the batcher does not notify the mempool
        //   about its inclusion in a block. As a result, the transaction remains in the mempool.
        // - When the next block is produced, the mempool will propose the same transaction again.
        // - This time, execution will fail because the contract has already been declared.
        // - The transaction will then be marked as rejected, the mempool will be notified, and the

    // Returns whether the declare transaction is for bootstrapping.
    // In this case, no account-related actions should be made besides the declaration.
    pub fn is_bootstrap_declare(&self, charge_fee: bool) -> bool {
        if let crate::transaction::DeclareTransaction::V3(tx) = &self.tx {
            return tx.sender_address == Self::bootstrap_address()
                && tx.nonce == Nonce(Felt::ZERO)
                && !charge_fee;
        }
        false
    }

    /// Returns the address of the bootstrap contract.
    /// Declare transactions can be sent from this contract with no validation, fee or nonce
    /// change. This is used for starting a new Starknet system.
    pub fn bootstrap_address() -> ContractAddress {
        // A felt representation of the string 'BOOTSTRAP'.
        ContractAddress::from(0x424f4f545354524150_u128)
    }
