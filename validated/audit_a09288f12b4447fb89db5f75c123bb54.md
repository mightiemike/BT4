### Title
Out-of-bounds slice panic when building bytecode segment structure from unverified compiled-class data in Starknet OS re-execution - ([File: crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs])

### Summary
`create_bytecode_segment_structure_inner` slices the compiled-class bytecode array using offsets/lengths taken directly from the `bytecode_segment_lengths` field of a `CasmContractClass` supplied as Starknet OS input, before that data has been hash-verified against the committed class hash. A crafted mismatch between `bytecode_segment_lengths` and the actual `bytecode` length causes a Rust slice-index panic, crashing the OS/re-execution process — the same bug class as CVE‑2021‑3549 (a length field from an untrusted section record consumed for indexing without a prior bounds check, causing an out-of-bounds crash).

### Finding Description
`create_bytecode_segment_structure_inner` recurses over `NestedIntList` segment lengths and, for each `Leaf(length)`, computes `segment_end = bytecode_offset + length` and immediately does `bytecode[bytecode_offset..segment_end].to_vec()`: [1](#0-0) 

The consistency check that `total_len == bytecode.len()` is only performed in the *outer* `create_bytecode_segment_structure` function, **after** `create_bytecode_segment_structure_inner` has already returned: [2](#0-1) 

This means if any `Leaf(length)` (or nested combination of lengths) exceeds the remaining bytecode, the slice indexing operation panics with an out-of-range index *before* the sanity check ever executes, aborting the process rather than returning the intended `OsHintError::AssertionFailed`.

This function is invoked from `load_classes_and_create_bytecode_segment_structures`, which is triggered by the `LoadClassesAndBuildBytecodeSegmentStructures` hint: [3](#0-2) 

Critically, this hint runs inside `guess_compiled_class_facts`, which the Cairo source explicitly documents as loading classes from OS input **without validating their hashes** — hash validation is deferred to a later call, `validate_compiled_class_facts`: [4](#0-3) [5](#0-4) 

The Rust-side hash consistency check (`load_class`) also happens only after the bytecode segment structure has already been built: [6](#0-5) 

Thus a `CasmContractClass` entry supplied to the OS/re-execution engine with `bytecode_segment_lengths` inconsistent with its `bytecode` field crashes the process at the "guess" stage — well before the deferred hash check can reject it as invalid.

### Impact Explanation
The Starknet OS re-execution flow is on the critical path used to validate/re-execute blocks (e.g. by the Starknet Transaction Prover / SNOS runner). A panic here is an unrecoverable process abort (Rust panics on out-of-bounds slicing are not caught mid-execution unless wrapped explicitly), so a single malformed compiled class supplied as OS input halts the re-execution/proving pipeline for that block, matching the "network unable to confirm new transactions" impact criterion. Because the whole design intentionally defers hash verification (`guess` then `validate`), the code assumes malformed/adversarial compiled-class data must survive to the validation step gracefully — but the segment-structure builder violates that assumption by panicking first.

### Likelihood Explanation
The bug is deterministic and requires only a single declared/undeclared `CasmContractClass` whose `bytecode_segment_lengths` sums to a different value than `bytecode.len()` (or contains a `Leaf` length exceeding the remaining data) to be fed into `create_bytecode_segment_structure`/`_inner`. Since this data is explicitly documented as being consumed prior to hash validation ("guess ... without validating their hashes"), triggering the panic does not require bypassing any cryptographic check.

### Recommendation
In `create_bytecode_segment_structure_inner` (and its outer wrapper), validate that `bytecode_offset + length <= bytecode.len()` for every `Leaf` (and that cumulative offsets never exceed the bytecode length) before performing any slicing, returning `OsHintError::AssertionFailed` instead of indexing directly. Equivalently, move/duplicate the bounds check into the recursive helper so it fails gracefully at the first invalid segment rather than only checking the aggregate `total_len` after the fact.

### Proof of Concept
1. Construct a `CasmContractClass` (or the OS input structure feeding `hint_processor.compiled_classes`) whose `bytecode` has length `N`, but whose `bytecode_segment_lengths` is `NestedIntList::Leaf(N + 1)` (or a `Node` whose child leaf lengths sum beyond `N`).
2. Feed this class into the Starknet OS re-execution flow so that `load_classes_and_create_bytecode_segment_structures` is invoked (the `LoadClassesAndBuildBytecodeSegmentStructures` hint during `guess_compiled_class_facts`), prior to any hash check.
3. `create_bytecode_segment_structure_inner` computes `segment_end = 0 + (N+1)` and executes `bytecode[0..N+1]`, which panics with "range end index N+1 out of range for slice of length N", aborting the OS re-execution process instead of returning a controlled `OsHintError`.

/// Creates the bytecode segment structure from the given bytecode and bytecode segment lengths.
pub(crate) fn create_bytecode_segment_structure(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
) -> Result<BytecodeSegmentNode, OsHintError> {
    let (structure, total_len) =
        create_bytecode_segment_structure_inner(bytecode, bytecode_segment_lengths, 0);
    // Sanity checks.
    if total_len != bytecode.len() {
        return Err(OsHintError::AssertionFailed {
            message: format!(
                "Invalid length bytecode segment structure: {}. Bytecode length: {}.",
                total_len,
                bytecode.len()
            ),
        });
    }

    Ok(structure)
}

func validate_compiled_class_facts{poseidon_ptr: PoseidonBuiltin*, range_check_ptr}(
    n_compiled_class_facts, compiled_class_facts: CompiledClassFact*, builtin_costs: felt*

    if (n_compiled_class_facts == 0) {
        return ();
    }
    alloc_locals;

    let compiled_class_fact = &compiled_class_facts[0];
    let compiled_class = compiled_class_fact.compiled_class;

    validate_entry_points(
        n_entry_points=compiled_class.n_external_functions,
        entry_points=compiled_class.external_functions,
    );

        n_entry_points=compiled_class.n_l1_handlers, entry_points=compiled_class.l1_handlers
    );
    // Compiled classes are expected to end with a `ret` opcode followed by a pointer to the
    // builtin costs.
    assert compiled_class.bytecode_ptr[compiled_class.bytecode_length] = 0x208b7fff7fff7ffe;

        builtin_costs, felt

    %{ LoadClass %}
