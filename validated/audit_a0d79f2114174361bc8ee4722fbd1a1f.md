### Title
Empty PBFT signature list bypasses SR quorum verification in `validPbftSign` - ([File: framework/src/main/java/org/tron/core/net/messagehandler/PbftDataSyncHandler.java])

### Summary
`PbftDataSyncHandler.validPbftSign` only enforces the 2/3+1 SR signature threshold when `srSignList.size() != 0`; if the list is empty, the method skips all verification and falls through to `return true` [1](#0-0) . Any connected peer can send a `PbftCommitMessage` with an empty `signature` list in its `PBFTCommitResult`, and the handler will accept and persist it as if it were a fully SR-verified PBFT commit.

### Finding Description
The message flow is: `P2pEventHandlerImpl.onMessage` dispatches `PBFT_COMMIT_MSG` type messages to `pbftDataSyncHandler.processMessage` without any sender-privilege check [2](#0-1) . `processMessage` only checks `allowPBFT()` and then caches the message keyed by `raw.getViewN()` [3](#0-2) . Later, `processPBFTCommitData` (triggered on new blocks) retrieves the cached message and calls `processPBFTCommitMessage`, which calls `validPbftSign(raw, signatureList, witnesses)` [4](#0-3) .

In `validPbftSign`, the entire quorum-count check, per-signature ECDSA recovery/address matching, and the "consumed all signatures" check are all inside the `if (srSignList.size() != 0)` block. If the attacker sends an empty signature list, none of these checks execute, and the function falls through to `return true` unconditionally [1](#0-0) . The caller treats a `true` result as "signature valid" and stores the capsule into `PbftSignDataStore` via `putBlockSignData`/`putSrSignData` [5](#0-4) , with no distinction between "signatures verified" and "no signatures present."

No other guard in this path checks that the signature list is non-empty before treating the result as valid — the only precondition is `allowPBFT()==true`, which is a chain-wide feature flag, not a peer-privilege check.

### Impact Explanation
An unprivileged network peer can inject a forged/empty-signed PBFT commit for a block or SR list (`DataType.BLOCK` or `DataType.SRL`) that gets persisted in `PbftSignDataStore` as though it carries 2/3+1 real SR signatures. This is a genuine authentication/threshold-bypass bug: the "no unprivileged user can bypass multisig/signer threshold checks" invariant is violated for the empty-list case. Downstream consumers of `PbftSignDataStore` that rely on stored PBFT sign data being SR-quorum-verified would be trusting unverified data.

### Likelihood Explanation
Feasible and repeatable: any connected peer (no special role required) can construct a `PBFTCommitResult` with `signature=[]` and a validly-formed `Raw` payload, wrap it in a `PbftCommitMessage`, and send it once `allowPBFT()` is true on the target node (a normal, non-privileged runtime condition on PBFT-enabled chains/side-chains). The bug is a pure logic omission (missing empty-list rejection), not reliant on race conditions or timing.

### Recommendation
In `validPbftSign`, explicitly reject empty signature lists rather than treating them as trivially valid, e.g.:
```java
if (srSignList.isEmpty()) {
  logger.error("sr sign list is empty");
  return false;
}
```
before/instead of the `if (srSignList.size() != 0)` guard, so the quorum count and per-signature verification are unconditionally required.

  Assert.assertFalse("empty signature list must not be treated as valid quorum", result);

  private void processPBFTCommitMessage(PbftCommitMessage pbftCommitMessage) {
    try {
      PbftSignDataStore pbftSignDataStore = chainBaseManager.getPbftSignDataStore();
      Raw raw = Raw.parseFrom(pbftCommitMessage.getPBFTCommitResult().getData());
      if (!validPbftSign(raw, pbftCommitMessage.getPBFTCommitResult().getSignatureList(),

        pbftSignDataStore.putSrSignData(raw.getEpoch(), pbftCommitMessage.getPbftSignCapsule());

      }

  private boolean validPbftSign(Raw raw, List<ByteString> srSignList,
      List<ByteString> currentSrList) {
    //valid sr list
    if (srSignList.size() != 0) {
      Set<ByteString> srSignSet = new ConcurrentSet();
      srSignSet.addAll(srSignList);
      if (srSignSet.size() < Param.getInstance().getAgreeNodeCount()) {
        logger.error("sr sign count {} < sr count * 2/3 + 1 == {}", srSignSet.size(),
            Param.getInstance().getAgreeNodeCount());
        return false;
      }
      byte[] dataHash = Sha256Hash.hash(true, raw.toByteArray());
      Set<ByteString> srSet = Sets.newHashSet(currentSrList);
      List<Future<Boolean>> futureList = new ArrayList<>();
      for (ByteString sign : srSignList) {
        futureList.add(executorService.submit(
            new ValidPbftSignTask(raw.getViewN(), srSignSet, dataHash, srSet, sign)));
      }
      for (Future<Boolean> future : futureList) {
        try {
          if (!future.get()) {
            return false;
          }
        } catch (Exception e) {
          logger.error("", e);
        }
      }
      if (srSignSet.size() != 0) {
        return false;
      }
    }
    return true;
  }
