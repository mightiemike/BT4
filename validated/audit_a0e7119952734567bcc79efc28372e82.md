### Title
PoX-4 signer-set apportionment can floor every signer's weight to zero, emptying the Nakamoto signer set and collapsing the signature threshold to zero - (File: stackslib/src/chainstate/stacks/boot/mod.rs)

### Summary
`StacksChainState::make_signer_set` (still the active code path for PoX-4 reward cycles) allocates each signer's weight as `stacked_amt / threshold` and silently drops any signer whose weight floors to `0`. If enough small/distinct signer-keys stake below the per-slot threshold, *every* signer in the cycle can be dropped, yielding an empty signer set even though total participation is non-zero. This is the exact "floor-and-drop" bug class from the MuteBond report (`timeToTokens` truncating to 0 and DOS-ing `lockTo`), except here the resulting truncation doesn't merely revert a call — it removes the entire signer set for a reward cycle, which downstream collapses the Nakamoto block-signing weight threshold to `0`, allowing blocks to be accepted network-wide with zero signer signatures.

### Finding Description
`make_signer_set` computes, per signing key: [1](#0-0) 
`weight = stacked_amt / threshold`, and returns `None` (drops the entry) whenever `weight == 0`. This is called unconditionally from `make_reward_set`, which is the PoX-4 reward-set builder: [2](#0-1) 

This is invoked from `pox_4_compute_and_update_signers`, the currently-active signer-set computation path prior to PoX-5's Epoch 4.0 activation: [3](#0-2) 

Unlike the PoX-5 path, which was explicitly patched with a Hare/largest-remainder apportionment *specifically to fix this exact degenerate mode* (documented in-code: "when more than `reward_slots` distinct signers hold roughly equal stake, every base weight floors to 0, and without the leftover round the entire signer set could be dropped"), and which hard-aborts if the resulting signer set is empty: [4](#0-3) [5](#0-4) 

...the PoX-4 path has **no such guard**. It simply falls back to an empty `Vec` and continues: [6](#0-5) 

Because `make_signer_set` returns `Some(vec![])` (not `None`) whenever the input entries are non-empty but all filtered out, `reward_set.signers()` returns `Some(&[])` rather than `None`, so no upstream error path is triggered. This empty signer list is written directly into the `.signers` boot contract via `update_signers` (called with `has_participation = true` since real STX was locked, but iterating over an empty `signers` slice).

Downstream, `verify_signer_signatures` computes: [7](#0-6) [8](#0-7) 
With `total_weight == 0` for the cycle, `compute_voting_weight_threshold(0)` computes a threshold that is a function of `total_weight` (scaled by a fixed percentage); with `total_weight = 0` the resulting threshold is `0`. A block with **zero signer signatures** (`total_weight_signed = 0`) then satisfies `total_weight_signed >= threshold` and is accepted as validly signed by every node running this deterministic logic.

### Impact Explanation
This breaks the core equality that a Nakamoto block must carry enough signer weight to meet the BFT signing threshold. Because the empty-signer-set condition is deterministic and computed identically by every node from on-chain PoX-4 stacking state, this is not a "temporary tip disagreement" — every node in the network would independently derive the same broken (`0`) threshold and accept unsigned blocks for that reward cycle. This is a **Critical** severity issue: an invalid (unsigned) block would be accepted network-wide, effectively disabling signer-set enforcement for the affected reward cycle and allowing a single miner to produce blocks without any signer participation.

### Likelihood Explanation
Triggering requires only that a minority of low-stake stackers (each individually unprivileged, not requiring majority stake or hash power) register with enough **distinct `signer-key`s**, each holding an amount whose floor-division by the per-slot `threshold` yields `0`. Since PoX-4's `get_reward_threshold_and_participation`/`make_signer_set` scale the required per-slot amount to `liquid_ustx / reward_slots`, using many small/distinct signer keys (a naturally permitted, unprivileged action any stacker can take) is sufficient — exactly the scenario the PoX-5 code comments explicitly call out as the "old floor-and-drop scheme" that "stalls the chain" (or here, worse: drops the entire signature requirement rather than merely stalling).

### Recommendation
Port the PoX-5 fix back to the PoX-4 path: apply the same largest-remainder/Hare apportionment in `make_signer_set` (or an equivalent minimum-weight guarantee) so that no signer's weight can floor to `0` when it holds a fair share, and add an explicit hard-abort (mirroring `pox_5_compute_and_update_signers`'s `if signer_set.is_empty() { ... return Err(...) }`) in `pox_4_compute_and_update_signers` if the computed signer set is empty despite `participation > 0`, rather than silently writing an empty signer list to the `.signers` contract.

### Proof of Concept
1. During a PoX-4 reward cycle, have several distinct principals each `stack-stx` with unique `signer-key`s, each with an amount such that `amount / threshold == 0` (e.g., `threshold` computed from `liquid_ustx / reward_slots`, and each staker's amount below that threshold but the sum being consensus-recognized non-zero `participation`).
2. At the prepare-phase boundary, `pox_4_compute_and_update_signers` runs `make_signer_set`, and every entry is filtered out at [9](#0-8) 
resulting in `signer_set = Some(vec![])`, which is used unmodified since `participation > 0` bypasses the "no participation" fallback: [10](#0-9) 
3. `.signers` is set with an empty signer list and `total_signing_weight() == 0` for that cycle.
4. Any miner can now produce a Nakamoto block for that cycle with an empty `signer_signature` vector; `verify_signer_signatures` computes `threshold = compute_voting_weight_threshold(0)` and accepts `total_weight_signed (0) >= threshold`, so the unsigned block is accepted by every node.

        // Allocate `reward_slots` weight across signers in proportion to stake using the
        // a largest-remainder method:
        //
        // The threshold is `ceil(total / reward_slots)`.
        //
        // Flooring each signer's `stacked / threshold` assigns a base weight where the sum is `<= reward_slots`
        // (the ceil makes `total/threshold <= reward_slots`).
        //
        // This leaves some unassigned ("leftover") slots, which are handed out one-per-signer
        //  in descending fractional-remainder order (ties broken by pubkey-sort order).
        //
        // This avoids degenerate modes of the floor-and-drop scheme: when more than
        // `reward_slots` distinct signers hold roughly equal stake, every base weight floors to
        // 0, and without the leftover round the entire signer set could be dropped.
