### Title
Stale OIDC session role bypasses live authorization checks in GraphQL admin mutations - ([File: core/sessions/oidcauth/oidc.go])

### Summary
`AuthorizedUserWithSession` in the OIDC authenticator resolves a user's role solely from the `oidc_sessions.user_role` column cached at login time, never re-validating against the current source of truth (the identity provider's group claims, or the `users` table for local fallback logins). `AuthenticateGQL` places this stale role directly into `GQLSession.User.Role`, which `authenticateUserIsAdmin` and other role gates trust unconditionally, so a demoted user retains their old privilege level for the lifetime of `SessionTimeout`.

### Finding Description
On OIDC login (`handleTokenExchange`), the mapped role is computed once from ID token claims and persisted into `oidc_sessions.user_role`: [1](#0-0) . Every subsequent GraphQL request calls `AuthenticateGQL`, which calls `authenticator.AuthorizedUserWithSession(ctx, sessionID)` [2](#0-1) . For the OIDC provider, this function only re-reads `user_email, user_role, ... FROM oidc_sessions WHERE id = $1` — it never re-verifies the ID token, re-queries the IdP group claims, nor cross-checks the `users` table: [3](#0-2) . The resulting `clsessions.User{Role: foundSession.UserRole}` is placed into the GQL context via `WithGQLAuthenticatedSession`, and role gates such as `authenticateUserIsAdmin` trust `session.User.Role` directly with no additional verification: [4](#0-3) .

Critically, `oidcAuthenticator.UpdateRole` is explicitly unimplemented (`return clsessions.User{}, clsessions.ErrNotSupported`) [5](#0-4) , in contrast to the local auth ORM's `UpdateRole`, which purges the user's active sessions as part of a role change: `DELETE FROM sessions WHERE email = lower($1)` followed by the role update [6](#0-5) . This means for OIDC-configured nodes there is no in-app mechanism to demote a user's role and simultaneously invalidate their cached `oidc_sessions.user_role`; role changes are expected to occur via the upstream IdP's group membership, but the running session's cached role is not synchronized against that upstream state again until the session naturally expires (`SessionTimeout`) or is otherwise purged (e.g. `DeleteUserSession`, `ClearNonCurrentSessions`, or the periodic `reaper.go` sync — none of which run automatically upon a mid-session demotion at the IdP).

### Impact Explanation
An OIDC user who previously had Admin-level (or any elevated) group membership and an active session retains that Admin role in every GraphQL mutation gated by `authenticateUserIsAdmin`/`authenticateUserCanEdit` until `SessionTimeout` elapses, even after being removed from the Admin group at the identity provider. This is a privilege-persistence/authorization bypass: the invariant that authorization should reflect current role at time of action, not role cached at login, is violated. Concretely this allows continued execution of admin-only GraphQL mutations (job/spec management, bridge configuration, user management, etc.) by a principal that has already been revoked upstream.

### Likelihood Explanation
This requires only ordinary conditions found in typical OIDC-enabled Chainlink Node deployments: an attacker (or compromised/former-privileged account) had an active session prior to demotion, and demotion happens via IdP group changes rather than immediate local session invalidation (since `UpdateRole` is `ErrNotSupported` for OIDC). No credential theft, admin action, or code bypass is needed beyond simply continuing to use an already-established session cookie — this is fully within the "unprivileged/ordinary session replay" threat model and is deterministic/repeatable up to `SessionTimeout` (config `SessionTimeout` under OIDC config, no automatic re-sync on demotion).

### Recommendation
Do not treat `oidc_sessions.user_role` as an authoritative, long-lived cache. Options:
1. On each `AuthorizedUserWithSession` call, re-verify current role against the OIDC provider (e.g., periodic token refresh + claims re-check, or a short-lived cache with TTL much smaller than `SessionTimeout`).
2. Provide an explicit admin-facing "revoke sessions for user" action (e.g. calling `DeleteUserSession`/`ClearNonCurrentSessions`) that operators must invoke whenever a user's IdP group membership changes, and document this as a required step.
3. Reduce reliance on cached `user_role`: have the reaper/sync job (`core/sessions/oidcauth/reaper.go`) actively re-validate role against the IdP or against a webhook/SCIM push, purging or downgrading stale sessions promptly rather than only purging expired ones.

### Proof of Concept
Integration test (`core/sessions/oidcauth/oidc_test.go`):
1. Insert a user/OIDC session directly via `handleTokenExchange` flow (or `INSERT INTO oidc_sessions ... user_role = 'admin'`) simulating a completed OIDC login with Admin role, obtaining `sessionID`.
2. Call `oi.AuthorizedUserWithSession(ctx, sessionID)` and assert `Role == UserRoleAdmin`.
3. Simulate demotion: since `UpdateRole` is unsupported for OIDC, directly update `oidc_sessions.user_role` to `'view'` is not representative — instead simulate the real-world path by asserting that no code path exists that updates `oidc_sessions.user_role` when the equivalent `users`/IdP role changes, and that `AuthorizedUserWithSession` continues to return the originally cached `'admin'` role even though the underlying identity has been demoted at the IdP (mock provider claims change).
4. Replay `sessionID` through `AuthenticateGQL` → `authenticateUserIsAdmin(ctx)` on an admin-only mutation resolver and assert it currently **passes** (demonstrating the bug), where the expected/fixed behavior is that it should be **rejected** post-demotion.

func authenticateUserIsAdmin(ctx context.Context) error {
	session, ok := auth.GetGQLAuthenticatedSession(ctx)
	if !ok {
		return unauthorizedError{}
	}
	if session.User.Role != sessions.UserRoleAdmin {
		return RoleNotPermittedError{session.User.Role}
	}
	return nil
}

// UpdateRole overwrites role field of the user specified by email.
func (o *orm) UpdateRole(ctx context.Context, email, newRole string) (sessions.User, error) {
	var userToEdit sessions.User

	if newRole == "" {
		return userToEdit, pkgerrors.New("user role must be specified")
	}

	err := sqlutil.TransactDataSource(ctx, o.ds, nil, func(tx sqlutil.DataSource) error {
		// First, attempt to load specified user by email
		if err := tx.GetContext(ctx, &userToEdit, "SELECT * FROM users WHERE lower(email) = lower($1)", email); err != nil {
			return pkgerrors.New("no matching user for provided email")
		}

		// Patch validated role
		userRole, err := sessions.GetUserRole(newRole)
		if err != nil {
			return err
		}
		userToEdit.Role = userRole

		_, err = tx.ExecContext(ctx, "DELETE FROM sessions WHERE email = lower($1)", email)
		if err != nil {
			o.lggr.Errorw("Failed to purge user sessions for UpdateRole", "err", err)
			return pkgerrors.New("error updating API user")
		}

		sql := "UPDATE users SET role = $1, updated_at = now() WHERE lower(email) = lower($2) RETURNING *"
		if err := tx.GetContext(ctx, &userToEdit, sql, userToEdit.Role, email); err != nil {
			o.lggr.Errorw("Error updating API user", "err", err)
			return pkgerrors.New("error updating API user")
		}

		return nil
	})

	return userToEdit, err
}
