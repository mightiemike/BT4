### Title
Starknet OS `execute_replace_class` Skips Declared-Class Validation Performed by Blockifier, Causing State Divergence in OS Re-execution - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Cairo Starknet OS implementation of the `replace_class` syscall unconditionally writes the requested `class_hash` into the contract's state entry, without verifying that the class hash corresponds to a declared class. The blockifier (Rust execution engine that actually builds blocks) enforces this check and rejects the syscall (reverting the call) when the class is undeclared. This asymmetry between the two independent implementations of the same syscall can cause the OS's re-execution — used to prove/attest block correctness — to compute a different resulting state than the sequencer's blockifier actually committed to the block, an honest-node/prover divergence in contract-class state.

### Finding Description
`execute_replace_class` in the OS Cairo code contains an explicit TODO acknowledging the missing check: [1](#0-0) 

It directly builds a `new_state_entry` with the caller-supplied `class_hash` and commits it via `dict_update`, with no lookup against the OS's declared-class table. The deprecated syscall path in the OS has the identical gap: [2](#0-1) 

By contrast, the blockifier's (Rust) implementation of the same syscall — the code that a sequencer actually runs to build the block and compute the state diff — explicitly enforces declaration before allowing the replacement:
- Deprecated (Cairo0) syscall handler: `syscall_handler.state.get_compiled_class(request.class_hash)?` before `set_class_hash_at` [3](#0-2) 
- Cairo1 (non-deprecated) syscall base implementation is likewise validated, as confirmed by the accompanying blockifier tests that assert failure for undeclared class hashes: [4](#0-3) [5](#0-4) 

Because the blockifier is the component that actually decides transaction success/failure and produces the canonical state diff for the block, any transaction attempting `replace_class` with an undeclared class hash is reverted by the sequencer — its effects (including the class-hash update) are rolled back and never appear in the committed state diff. The Starknet OS, however, is expected to independently re-execute the same transactions from the same block inputs to reconstruct/attest the resulting state root (used in proof generation and state-root/block-hash validation). Since the OS's `execute_replace_class` omits the "is declared" check, if the OS's local view of declared classes ever fails to match the blockifier's view for a given class hash during re-execution (e.g. differing catch of an undeclared/removed class, or a divergent case not otherwise caught elsewhere in the OS pipeline before this point is reached), the OS would apply the class replacement unconditionally while the blockifier would have reverted it — producing a different final class-hash-to-contract mapping, and therefore a different committed state root/commitment between the two independently-implemented executors.

### Impact Explanation
A divergence between the blockifier (the block-building/execution reference) and the OS (the block/state re-execution and proving reference) over whether a `replace_class` syscall succeeds directly affects the committed contract state (`class_hash` at a contract address), which feeds into the state commitment/Patricia tree and ultimately the block's state root and block hash. This falls squarely into "wrong committed root or block hash" / "honest-node divergence" impact categories: the OS could attest to a state that the sequencer's actual (blockifier-computed) block does not contain, undermining the correctness guarantee that the OS proof is supposed to provide.

### Likelihood Explanation
The check is unconditional in the OS syscall path and reachable by any Cairo1 (and legacy Cairo0) contract that calls `replace_class_syscall`, a syscall available to an ordinary, unprivileged contract during transaction execution — the exact reachable path required (sequencer transaction execution / syscalls). The explicit `TODO(Yoni, 1/1/2026)` comment in production code confirms the gap is a known, currently-unaddressed omission rather than a hypothesized bug, raising confidence that this divergence is real and not compensated for elsewhere in the visible syscall implementation. I could not fully verify within the available index whether some other OS-level invariant (e.g., a class-declaration check performed earlier in the OS pipeline, such as while validating declared classes against the L2 state or during commitment computation) fully closes this gap before it manifests as a root divergence; this residual uncertainty should be validated by directly tracing the OS's overall class-declaration bookkeeping (`contract_state_changes`, declared-class Patricia tree updates) end to end.

### Recommendation
Add the missing declared-class validation to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring the blockifier's behavior (reading/looking up the class in the OS's own compiled-class/declared-class table and asserting or failing the syscall the same way the blockifier's `get_compiled_class` check does), so that OS re-execution and blockifier execution reach identical accept/reject outcomes for `replace_class` given the same declared-class state.

func execute_replace_class{contract_state_changes: DictAccess*, revert_log: RevertLogEntry*}(
    contract_address, syscall_ptr: ReplaceClass*
) {
    alloc_locals;
    let class_hash = syscall_ptr.class_hash;

    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
