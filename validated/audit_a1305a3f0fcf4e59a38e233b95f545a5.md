### Title
Missing "class must be declared" check in the Starknet OS `execute_replace_class` syscall causes execution divergence from the Rust Blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The ENS report shows that a security invariant (ownership must be validated consistently across all state sources that gate a privileged action) was enforced in one code path but not in a logically-equivalent second path, letting an attacker exploit the unchecked path to bypass the protection entirely. The analogous pattern exists in the Starknet sequencer between the two independent implementations of the `replace_class` syscall: the Rust Blockifier (used by the Gateway/Batcher to build and validate blocks) enforces that the target class hash must already be declared, while the Cairo Starknet OS program (used for re-execution/proving of the same transactions) does not.

### Finding Description
The `replace_class` syscall lets a contract change its own class hash to any given `class_hash`. This is a privileged, security-sensitive operation, so both engines that execute Starknet transactions must agree on when it succeeds or fails.

In the Rust Blockifier, the deprecated (Cairo0) syscall handler explicitly checks that the target class is declared before allowing the replacement, and fails otherwise: [1](#0-0) 

Tests confirm this behavior — invoking `replace_class` on an undeclared class hash yields an "is not declared" error and the state is left unchanged: [2](#0-1) [3](#0-2) 

In contrast, the Cairo Starknet OS program's implementation of the same syscall (`execute_replace_class`) contains an explicit TODO acknowledging that this check is missing, and unconditionally overwrites the contract's class hash in `contract_state_changes` regardless of whether `class_hash` was ever declared: [4](#0-3) 

The older deprecated-syscalls Cairo implementation (`execute_replace_class` in `deprecated_execute_syscalls.cairo`) has the exact same gap — it reads the state entry via the `GetContractAddressStateEntry` hint and updates `contract_state_changes` with the new `class_hash` with no declaration check at all: [5](#0-4) 

This mirrors the ENS bug class precisely: two logically-parallel state-transition engines (Registry vs Registrar in ENS; Blockifier vs Starknet OS here) are each responsible for validating the same operation, but only one of them enforces the safety check. An attacker who is aware of this gap can submit a transaction containing a `replace_class` syscall targeting an undeclared class hash from an unprivileged account contract they control.

### Impact Explanation
When the Batcher/Blockifier builds a block, a transaction invoking `replace_class(undeclared_class_hash)` will fail inside the syscall handler (the entry point call errors out), causing the transaction to be marked as reverted (only fee charged, no state change applied) — this is the state that gets committed to the block and agreed upon by consensus.

When the Starknet OS later re-executes the same block (used for Starknet OS re-execution / proof generation, an explicitly in-scope reachable path per the rules), the missing check means the syscall succeeds: the contract's class hash is unconditionally set to the undeclared value, and the transaction proceeds as if it succeeded rather than reverted. This produces a different state diff (and potentially different subsequent execution behavior, since the contract's declared entry points would be undefined/garbage) than what the Blockifier computed and what was already committed as the canonical block result.

This is a genuine root-cause divergence between the two execution engines that must agree bit-for-bit for the system to produce a valid Starknet OS proof of the committed block: the OS would compute a wrong committed state root/state diff relative to the block actually agreed upon by the sequencer's consensus, which is either (a) an honest-node/engine divergence that produces a wrong committed root, or (b) causes state-transition proof generation to fail for perfectly ordinary blocks containing a "replace_class-to-undeclared-hash" transaction, i.e., the network becomes unable to confirm/finalize new blocks through the proving pipeline. Both are explicitly accepted impact categories.

### Likelihood Explanation
Likelihood is high: `replace_class` is a standard, unprivileged syscall reachable by any account/contract via an ordinary Invoke transaction — no special privileges, staking, or operator access are required. The trigger condition (target class hash simply not declared) is trivial to construct and requires no race condition or timing dependency, unlike the more elaborate ENS PoC. The bug is also self-documented by the TODO comment in the OS source, confirming it is a known, currently-unmitigated gap rather than a hypothetical.

### Recommendation
Add the same "class must be declared" check to the Starknet OS `execute_replace_class` implementation(s) (`syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that the Rust Blockifier already performs — i.e., before writing the new `class_hash` into `contract_state_changes`, verify (via a hint or dict lookup against `contract_class_changes`) that the class hash has already been declared, and fail/revert the syscall analogously to the Blockifier's `get_compiled_class` check, ensuring both execution engines produce identical accept/reject decisions and identical state diffs for every transaction.

### Proof of Concept
1. Declare and deploy an account/test contract `A` (no special privileges needed) that exposes a function calling the `replace_class` syscall with an attacker-supplied `class_hash` parameter (as in the existing test helper `test_replace_class` used by `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
2. Submit an Invoke transaction from contract `A` calling `test_replace_class(felt!(1234))` where `1234` is a class hash that has never been declared on-chain.
3. Observe, per `undeclared_class_hash` test at [3](#0-2) , that the Blockifier rejects this with an "is not declared" error, so the block-builder reverts the transaction and the class hash of `A` is left unchanged in the committed state.
4. Re-execute the identical block through the Starknet OS pipeline (`crates/apollo_starknet_os_program/.../syscall_impls.cairo` `execute_replace_class`), where no such declaration check exists (per the TODO at line 902) — the OS will instead accept the syscall and overwrite `A`'s class hash to the undeclared value `1234` in `contract_state_changes`, producing a state diff/result that disagrees with what the Blockifier (and therefore the committed block) actually produced.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
