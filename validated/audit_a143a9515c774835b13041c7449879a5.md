### Title
`accrue`-pause pass-through freezes interest accrual while `system-borrow`/`system-repay`/liquidation continue to use the stale index - ([File: mainnet/contracts/vault/v0-vault-usdc.clar])

### Summary
When the vault's `accrue` pause flag is set, `accrue`, `next-index`, and `next-liquidity-index` all short-circuit and return the *current* (stale) `index`/`lindex` instead of computing what the index should be given elapsed time, and instead of reverting. Because `borrow`, `repay`, and `withdraw`-style pause flags are independent booleans from `accrue`, an admin can pause only `accrue` while leaving `borrow`/`repay` active, or `accrue` can remain paused for an extended window while other operations continue. During that window, debt stops accruing interest for depositors (LPs) while all debt/asset flows still execute normally against the unchanged index, permanently losing the yield that would have accrued for that interval once the pause is lifted (the elapsed time is not banked anywhere - `last-update` is only bumped when the index actually changes).

### Finding Description
`accrue` in `v0-vault-usdc.clar` (and the other `v0-vault-*.clar` reserve vaults) is written as: [1](#0-0) 

```clarity
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ...
```

`next-index` and `next-liquidity-index` implement the same pass-through: [2](#0-1) 

Both helper functions check `(get accrue states)` and, if paused, return the unmodified `idx`/`lidx` rather than an error - i.e. the pause is implemented as a silent pass-through instead of a revert, exactly matching the accepted analog class ("a pause that passes through instead of reverting").

The problem is that `accrue`'s pause flag is independent from `borrow`/`repay`/`redeem` flags in `pause-states`: [3](#0-2) 

`system-borrow` calls `accrue` first, then immediately uses the value of `index` returned by that call to compute `scaled-amount`: [4](#0-3) 

If `accrue` is paused (its own flag true) while `borrow`/`repay` are false, every `system-borrow`/`system-repay` invocation goes through the "PAUSED: Pass-through" branch, gets back the old `idx`, and proceeds to mint/burn scaled debt against that unchanged index — never reverting, never recording that real time (and real accrued interest) has passed. `last-update` is only advanced inside the non-paused branch of `accrue` when the index actually changes: [5](#0-4) 

so while `accrue` is paused, `last-update` never moves. The elapsed real time during the pause is simply discarded — it is not "banked" to be applied once unpaused; once unpaused, `next-index` again measures `time-delta` from the (stale) `last-update`, but any interest owed strictly for the paused interval that already had debt outstanding and was serviced by pass-through borrows/repays during that interval is permanently lost, because those interactions happened at the old index and were never re-priced.

### Impact Explanation
Depositors (LPs) in the affected vault permanently lose the interest that should have accrued on outstanding debt for the duration that `accrue` is paused but other operations (`borrow`/`repay`) remain enabled. This is a loss of unclaimed yield to liquidity providers, matching the in-scope High impact class ("theft of unclaimed yield ... or permanent freezing of unclaimed yield"). It is not a DAO-misconfiguration or accidental registry issue — it is a property of how `accrue`'s pass-through branch interacts with the separately-gated `borrow`/`repay` flags and the `last-update` bookkeeping, i.e. a code-logic issue rather than a deliberate design decision to disable a feature outright.

### Likelihood Explanation
The `pause-states` tuple is DAO/admin controlled, and per the scope rules DAO-controlled configuration is intended design; however, the underlying code defect — a pause implemented as silent pass-through rather than revert, combined with independent pause flags — creates a real risk any time `accrue` is paused for legitimate operational reasons (e.g., during an interest-rate model migration or emergency response) without also pausing `borrow`/`repay`. Given six near-identical vault contracts (`v0-vault-stx`, `v0-vault-sbtc`, `v0-vault-ststx`, `v0-vault-usdc`, `v0-vault-usdh`, `v0-vault-ststxbtc`) all share this exact pattern, the likelihood of this occurring in at least one vault during the system's operational lifetime is non-trivial.

### Recommendation
Either (a) make `accrue` revert (rather than pass through) when paused, and make `system-borrow`/`system-repay`/`liquidate` paths that call `accrue` fail closed when accrual is paused, or (b) couple the `accrue` pause with `borrow`/`repay` pauses so that pausing `accrue` automatically disables `borrow`/`repay` for that vault, preventing new debt operations from being priced against a frozen index while real time elapses.

### Proof of Concept
1. Admin pauses only `accrue` on `v0-vault-usdc` via `pause-states` (`accrue: true`, `borrow`/`repay` left `false`). [3](#0-2) 
2. Time passes (e.g., a period long enough that `interest-rate` × `time-delta` would normally produce a meaningful index increase).
3. A borrower calls `market.borrow`, which internally calls `vault-system-borrow` → `system-borrow`, which calls `accrue`. [4](#0-3) 
4. `accrue` detects `(get accrue states)` is true and returns the stale `{index: idx, lindex: lidx}` without reverting and without updating `last-update`. [6](#0-5) 
5. `system-borrow` computes `scaled-amount` using this stale `idx`, records new scaled debt, and completes successfully — as if no time (and hence no interest) had passed, even though real time did pass and other debt outstanding during that window is also being serviced (via `repay`) at the same stale index.
6. When `accrue` is later unpaused, `next-index` only accrues interest going forward from the (never-updated) `last-update` for genuinely new elapsed time; the interest that should have accumulated on debt actively borrowed/repaid during the paused window is never captured, permanently reducing yield paid to LPs for that interval. [7](#0-6) 

**Note:** I was unable to find an explicit permissions/authorization check gating who can flip individual `pause-states` fields (e.g., separately pausing `accrue` without `borrow`/`repay`) within the indexed content; if such a function enforces that `accrue` pause always also pauses `borrow`/`repay`, this finding would be mitigated. Given the size limits on the codebase index, you may want to start a Devin session to fully confirm the admin-facing pause-setter function's behavior across all six vaults.
