### Title
Unchecked-length panic in Solana CCIP `DecodeDestExecDataToMap` on attacker-controlled dest-exec data - (File: core/capabilities/ccip/ccipsolana/extradatacodec.go)

### Summary
`ExtraDataDecoder.DecodeDestExecDataToMap` in the Solana CCIP extra-data codec reads a `uint32` from the raw `destExecData` bytes without checking that the slice is at least 4 bytes long, unlike every other decode path in the same file and its EVM counterpart, which explicitly guard with `len(...) < 4`.

### Finding Description
`DecodeDestExecDataToMap` is implemented as: [1](#0-0) 

This directly calls `binary.BigEndian.Uint32(destExecData)`, which internally does `_ = b[3]` — an unchecked slice index. If `destExecData` has fewer than 4 bytes, this panics with `index out of range`. This is the same root-cause pattern as the ZetaChain report: the caller assumes the input is "at least 4 bytes long" and slices it without validation.

By contrast, the sibling function `DecodeExtraArgsToMap` in the same file explicitly guards against this: [2](#0-1) 

And the EVM equivalent (`ccipevm.ExtraDataDecoder.DecodeDestExecDataToMap`) safely delegates to `abiDecodeUint32`, which uses ABI unpacking (returns an error rather than panicking) instead of a raw byte-slice index: [3](#0-2) 

`destExecData` originates from cross-chain message data (dest-exec/token-transfer extra data) that is decoded when translating CCIP message fields into a chain-agnostic representation — i.e., data that ultimately traces back to values placed on-chain by a message sender on the source chain, an unprivileged trust boundary consistent with the "bridge/external-adapter abuse" category in scope.

### Impact Explanation
If this decode path is invoked from a message-processing / observation-building pipeline (e.g., converting a CCIP message for reporting, plugin observation building, or UI/API surfaces that describe pending messages) with attacker-influenced dest-exec data shorter than 4 bytes, it will panic. Depending on where in the call stack this executes:
- If it runs inside a goroutine or service loop without a `recover()` wrapper, the panic could crash the node process handling that message, denying availability for that CCIP lane.
- If it happens during OCR observation generation for message execution/reporting, it could repeatedly disrupt an oracle node's report generation for the affected message, analogous to the CCTX-stuck effect described in the source report (a specific message can never be successfully translated/observed, blocking downstream state).

I could not fully trace every call site of `DecodeDestExecDataToMap` within the given search budget to confirm whether all invocations are wrapped in a panic-recovery boundary; this should be verified by a maintainer/Devin session to determine exact reachability and blast radius.

### Likelihood Explanation
Likelihood is moderate: the attacker needs to control or influence `destExecData` bytes (e.g., a malformed/short token-transfer extra data blob within a CCIP message) and get it routed to this specific Solana decode path with fewer than 4 bytes. Given CCIP message construction is user/attacker-influenced on the source chain side and this data crosses a trust boundary into node-side decoding, exploitation appears feasible without special privileges, similar in spirit to the ZetaChain PoC using a short/empty payload to a precompile.

### Recommendation
Add the same length guard used elsewhere in this file and in the EVM codec:
```go
func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
	if len(destExecData) < 4 {
		return nil, fmt.Errorf("dest exec data too short: %d, should be at least 4", len(destExecData))
	}
	return map[string]any{
		svmDestExecDataKey: binary.BigEndian.Uint32(destExecData),
	}, nil
}
```
Additionally, audit other call sites that slice untrusted CCIP payload bytes without an explicit length check to ensure consistent defensive validation, and confirm whether callers of this function are protected by panic-recovery so a malformed message cannot crash the process.

### Proof of Concept

func (d ExtraDataDecoder) DecodeDestExecDataToMap(destExecData cciptypes.Bytes) (map[string]any, error) {
	destGasAmount, err := abiDecodeUint32(destExecData)
	if err != nil {
		return nil, fmt.Errorf("decode dest gas amount: %w", err)
	}

	return map[string]any{
		evmDestExecDataKey: destGasAmount,
	}, nil
}
