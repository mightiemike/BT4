### Title
Missing declared-class validation in Starknet OS `execute_replace_class` allows honest-node state divergence from Blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Blockifier's `replace_class` syscall implementation strictly validates that the target `class_hash` is declared (and is Cairo1) before permitting a contract to change its own class hash. The Starknet OS's Cairo implementation of the same syscall (`execute_replace_class`) performs no such validation — the check is stubbed out with a `TODO`. This creates a state-transition rule mismatch between the two execution engines that are supposed to produce identical results (Blockifier during block building, and the OS during proof generation/re-execution), analogous in root cause to the ZITADEL advisory's class of bug: a state-mutating operation reachable by an unprivileged caller that lacks the validation the rest of the system assumes is enforced.

### Finding Description
Blockifier enforces, in `syscall_base.rs`, that `replace_class` only succeeds if the class is declared and Cairo1: [1](#0-0) 

The deprecated (Cairo0) syscall handler enforces the same via `get_compiled_class`: [2](#0-1) 

These checks are proven correct by existing tests, which assert that replacing with an undeclared class hash fails with "is not declared": [3](#0-2) [4](#0-3) 

However, the Starknet OS's own Cairo implementation of `execute_replace_class` (used for `RunnableCairo1` execution in the OS) contains an explicit TODO stating the check is missing, and simply updates `contract_state_changes` with the requested `class_hash` unconditionally: [5](#0-4) 

The deprecated (Cairo0) OS syscall path has the identical gap — no declared-class check before the `dict_update`: [6](#0-5) 

This is a root-cause parallel to the ZITADEL IDOR bug class: a caller-reachable state-mutating operation (here, `replace_class`, invoked by any contract during its own execution) that the "trusted" path (Blockifier) gates with a permission/validity check, while an equally-authoritative alternate path (the Starknet OS, which independently re-derives/re-verifies the same state transition for proving) omits that check entirely — a classic "authorization enforced in one code path but not the other" defect.

### Impact Explanation
The Starknet OS is the component that re-executes transactions to produce the proven state transition and, ultimately, the committed state root and block hash. If the OS's `execute_replace_class` accepts a `class_hash` that Blockifier would have rejected (undeclared, or a V0 hash where V1 is required), any bug, malicious hint injection, or divergent code path that causes the OS's syscall trace to contain such a value would let the OS compute and prove a state transition that Blockifier itself would never have produced (Blockifier would abort the transaction with a declared-class error, while the OS accepts it silently). This breaks the fundamental invariant that OS re-execution must exactly match Blockifier's semantics for the same transaction, and it is precisely the kind of state-model divergence (CWE-639-style "insufficient verification of caller-supplied identifier before privileged state mutation") that leads to wrong committed state roots / honest-node divergence if the two engines ever disagree on syscall trace validity.

### Likelihood Explanation
The likelihood of this being triggered "for free" in a fully consistent Blockifier→OS pipeline is limited, because Blockifier's own gate normally prevents an invalid `class_hash` from ever appearing in a legitimate, blockifier-approved transaction trace that gets handed to the OS. However, this is still a genuine correctness gap, not merely defense-in-depth: the OS is designed to be a self-contained, independently verifiable re-implementation of Starknet execution rules, and the explicit `TODO(Yoni, 1/1/2026)` confirms the developers recognize the check as required and currently absent. Any place where OS input construction, hint generation, or an alternate/relaxed re-execution flow (e.g., for testing, virtual OS execution, or future code paths that bypass Blockifier's gate) can supply a class hash without going through Blockifier's `replace_class` check would immediately be exploitable by a single account contract invoking `replace_class_syscall` with an arbitrary undeclared class hash.

### Recommendation
Add the same class-declaration (and Cairo1-type) validation performed in Blockifier's `syscall_base.rs::replace_class` to both OS implementations (`syscall_impls.cairo::execute_replace_class` and `deprecated_execute_syscalls.cairo::execute_replace_class`) before applying the `contract_state_changes` update. This closes the outstanding TODO and restores parity between the OS's independent state-transition validation and Blockifier's enforced rules.

### Proof of Concept
Not independently executable from the indexed context alone — the currently observable divergence is a code-level parity gap (confirmed via the tracked `TODO(Yoni, 1/1/2026)`), not a demonstrated live exploit trace. Exploitation would require identifying/constructing an OS input path where a `replace_class` syscall record with an undeclared `class_hash` reaches `execute_replace_class` without having first passed Blockifier's `get_compiled_class` gate (e.g., via a divergent hint-generation or alternate re-execution entry point not shown in the indexed snippets). A background engineering session with full repository/test access would be needed to determine whether such an input-construction path currently exists in the OS runner/hint-processor pipeline.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
