## Analysis Summary

The External Report describes a scheme where a time-lagged, publicly-predictable price/PnL value that gets applied later (at the end of an epoch) can be front-run by an attacker who deposits/withdraws before the lag resolves, extracting value at the expense of other users.

The closest reachable analog in Push Chain's scoped code is the **gas-abstraction auto-swap performed during inbound execution** in `x/uexecutor/keeper/execute_inbound_gas.go`, which quotes a Uniswap V3 pool price and then executes the swap with only a fixed 5% slippage tolerance — inside a transaction (`MsgVoteInbound`, the ballot-finalizing vote) that is visible in the public mempool before it lands on-chain, giving an ordinary unprivileged user the ability to sandwich it.

### Title
Sandwichable gas-abstraction auto-swap with fixed 5% slippage tolerance during inbound execution - (File: x/uexecutor/keeper/execute_inbound_gas.go)

### Summary
When an inbound deposit requires gas abstraction, `ExecuteInboundGas` fetches a swap quote from the on-chain Uniswap V3 `QuoterV2` and then immediately performs the swap via `CallPRC20DepositAutoSwap`, bounding slippage to a hardcoded 5%. Because this logic executes as part of the finalizing `MsgVoteInbound` transaction — an ordinary, mempool-visible Cosmos transaction, not a validator-only internal event — any unprivileged actor watching the mempool can front-run/sandwich it, manipulating the WPC/PRC20 pool price within the 5% band to extract value from the depositor's swap, mirroring the "act on a soon-to-be-applied value before it lands" front-running pattern in the source report.

### Finding Description
`ExecuteInboundGas` ( [1](#0-0) ) performs:
1. `GetSwapQuote` — a read-only `CallEVM` (`commit=false`) call to `QuoterV2.quoteExactInputSingle`, returning the *current* pool-implied output amount ( [2](#0-1) ).
2. A hardcoded 5% slippage bound: `minPCOut := quote * 95 / 100` ( [3](#0-2) ).
3. `CallPRC20DepositAutoSwap`, which commits the real swap via `DerivedEVMCall` ( [4](#0-3) ).

This entire quote→execute sequence happens synchronously inside the same keeper call, triggered from the last vote that finalizes an inbound ballot (`MsgVoteInbound`). Because Cosmos SDK transactions (including `MsgVoteInbound`) sit in the public mempool before block inclusion, and validator identities/ballot state are queryable, an attacker can observe an about-to-finalize inbound requiring auto-swap and, within the same block, submit a large swap against the underlying WPC/PRC20 pool immediately before the finalizing vote transaction, then reverse it immediately after (classic sandwich). The 5% band is the *only* protection and is fixed regardless of pool depth/inbound size, so on any pool with limited liquidity relative to the deposit size, the attacker can move price by close to (or up to) 5% and pocket the difference, at the depositor's expense, while the deposit itself still "succeeds" (satisfies `minPCOut`).

This mirrors the report's core defect class: a value (swap quote / effective exchange rate) is computed at one point but only takes economic effect later at execution, and the gap is exploitable by anyone who can observe and act ahead of the finalizing state transition — no privileged validator/relayer/TSS behavior is required, only an ordinary user submitting ordinary swap transactions against the same AMM pool the protocol itself trades against.

### Impact Explanation
An unprivileged attacker can extract value from ordinary depositors' gas-abstraction auto-swaps by sandwiching the finalizing `MsgVoteInbound` transaction, degrading the PC amount credited to the user's UEA within the 5% tolerance band. This is a direct value-extraction/fund-drain vector against user-controlled deposits routed through the protocol's own on-chain swap path, fitting the in-scope "draining ... of user or protocol-controlled funds" and "corruption of ... native asset accounting" categories. Severity is bounded by the 5% slippage cap and pool depth, making it Medium impact rather than critical.

### Likelihood Explanation
Likelihood is Medium: it requires the attacker to (a) monitor the mempool/ballot state for inbound events large enough to matter, (b) have capital and access to the specific WPC/PRC20 pool, and (c) successfully order transactions around the finalizing vote in the same block (subject to normal MEV/ordering constraints on the chain). No validator, TSS, or admin privilege is needed — this is reachable purely from default deposit flows and ordinary swap transactions.

### Recommendation
- Do not derive `minPCOut` from a quote fetched moments before commit inside the same keeper flow; instead let depositors/relayers specify an acceptable minimum output as part of the inbound payload (bound to what was expected off-chain), or use a TWAP-based quote from the pool rather than the instantaneous `quoteExactInputSingle` spot quote.
- Consider tightening slippage tolerance dynamically based on trade size relative to pool liquidity, or routing gas-abstraction swaps through a mechanism resistant to same-block manipulation (e.g., commit-reveal, batched execution, or protocol-owned liquidity with fixed pricing for small amounts).
- Evaluate applying the swap at a price checkpointed prior to ballot finalization rather than at execution time, analogous to the report's recommendation of using a minimum of end-of-period and request-time pricing.

### Proof of Concept
1. An inbound requiring gas abstraction (non-gas-token PRC20 deposit) reaches quorum votes; the final `MsgVoteInbound` sits in the mempool.
2. Attacker observes this pending transaction (and the source chain amount / token, which is visible in `Inbound.Amount`/`AssetAddr`) and estimates the resulting `GetSwapQuote` output.
3. Attacker submits a large swap in the same WPC/PRC20 Uniswap V3 pool immediately before the finalizing vote transaction lands (front-run leg), shifting the spot price such that `GetSwapQuote` in `ExecuteInboundGas` ( [5](#0-4) ) returns a degraded quote, still within 5% so `minPCOut` is still satisfied.
4. `CallPRC20DepositAutoSwap` executes at the manipulated price, crediting the victim's UEA with up to 5% less PC than fair value.
5. Attacker submits a back-run swap reversing their position, capturing the price differential as profit, extracted from the victim depositor.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
