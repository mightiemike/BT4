### Title
Unmetered gasless `MsgMigrateUEA` allows fee-free spam of EVM execution - (File: `x/uexecutor/keeper/msg_migrate_uea.go`, `app/txpolicy/gasless.go`)

### Summary
`MsgMigrateUEA` is registered as a gasless message type (no Cosmos tx fee required) in `app/txpolicy/gasless.go` line 18, mirroring `MsgExecutePayload`. However, while `ExecutePayload` (`x/uexecutor/keeper/msg_execute_payload.go` lines 89-93) unconditionally deducts EVM gas cost from the target UEA via `DeductGasFeesFromReceipt` after every EVM call, `MigrateUEA` (`x/uexecutor/keeper/msg_migrate_uea.go` lines 70-83) performs `CallUEAMigrateUEA` and returns without any equivalent fee deduction call. [1](#0-0) 

### Finding Description
`MsgMigrateUEA.Signer` can be any account (contract-only binding model, same as `MsgExecutePayload` per the README): the signer pays no Cosmos fee since the message is in the gasless allowlist [2](#0-1) , and the module deliberately does not require `Signer == EVM(Owner)` [3](#0-2) . `MigrateUEA` still executes real EVM computation (`CallUEAMigrateUEA`, an actual `DerivedEVMCall`-style call into the UEA contract) for any syntactically valid `UniversalAccountId` + `MigrationPayload`, gated only by chain-enabled and UEA-deployed checks — no signature or ownership check happens at the Cosmos layer, and none of the resulting EVM gas is billed to anyone. [4](#0-3) 

Compare this to `ExecutePayload`, where gas is deducted from the target UEA "regardless of success/failure" specifically to prevent unmetered EVM execution: [5](#0-4) 

This is the closest scoped analog to the `RequestBandPrice` report's root cause ("any entity can potentially trigger the [privileged] request... leading to... spamming the oracle with unnecessary requests"): an unprivileged, unauthenticated (at the Cosmos layer) caller can trigger real work (`CallUEAMigrateUEA`, an EVM state-transition call) for free, repeatedly, against any deployed UEA, with the invalid-signature case reverting only inside the EVM call after gas/compute has already been spent, and with no fee ever charged to the attacker or the UEA.

### Impact Explanation
This does not directly drain funds since the EVM contract itself still reverts on bad `VerificationData`/`Signature` before mutating UEA state (per the README's contract-only-binding safety argument). But it breaks the "gasless admission" invariant asked about in scope: gasless messages are meant to be economically bounded by billing the UEA for the gas they consume, and `MigrateUEA` is the one gasless, state-mutating message that has no such billing path at all, unlike its sibling `ExecutePayload`. An unprivileged attacker can submit unlimited `MsgMigrateUEA` transactions (free of Cosmos fees) against arbitrary deployed UEAs, each one causing a real EVM call to execute, with zero cost to the attacker and zero recovery of validator compute cost — a free computational-resource-exhaustion vector reachable from ordinary user transaction submission alone.

### Likelihood Explanation
High reachability: `MsgMigrateUEA` is a standard user-submittable message, requires no bonded/privileged role, and is explicitly gasless. It's likely to trigger under default configuration since only a deployed UEA + `IsInboundEnabled` chain config is required — both attacker-controllable/discoverable preconditions.

### Recommendation
Add the same `DeductGasFeesFromReceipt` (or an equivalent metering step) call to `MigrateUEA` after `CallUEAMigrateUEA` returns, mirroring `ExecutePayload`'s fee-deduction step, so that gas consumed by migration attempts (successful or reverted) is always billed to the target UEA. Alternatively, if `MsgMigrateUEA` is truly deprecated per the README's claim that "the Cosmos layer no longer has a dedicated migration message," it should be removed from both the gasless allowlist and the module's registered message set, since its continued presence contradicts the documented design and leaves an unmetered code path live.

### Proof of Concept
1. Attacker identifies any deployed UEA (`UniversalAccountId`) on a chain with `IsInboundEnabled = true`.
2. Attacker crafts a `MsgMigrateUEA` with an arbitrary/garbage `MigrationPayload` and `Signature` (does not need to be valid — the EVM contract will revert the signature check, but only after the call executes).
3. Attacker submits the message from any account; because `MsgMigrateUEA` is in `GaslessMsgTypes`, no Cosmos tx fee is charged.
4. `msgServer.MigrateUEA` → `Keeper.MigrateUEA` runs `CallUEAMigrateUEA`, consuming real EVM gas/compute, then returns without ever calling `DeductGasFeesFromReceipt`.
5. Attacker repeats indefinitely at zero cost, generating unbounded free EVM execution load on validators/full nodes. [6](#0-5) [5](#0-4) [7](#0-6)

```go
func (k Keeper) MigrateUEA(ctx context.Context, evmFrom common.Address, universalAccountId *types.UniversalAccountId, migrationPayload *types.MigrationPayload, signature string) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Get Caip2Identifier for the universal account
	caip2Identifier := universalAccountId.GetCAIP2()

	k.Logger().Info("migrate UEA",
		"from", evmFrom.Hex(),
		"chain", caip2Identifier,
		"owner", universalAccountId.Owner,
	)

	// Step 1: Parse and validate payload and signature
	_, err := types.NewAbiMigrationPayload(migrationPayload)
	if err != nil {
		return errors.Wrapf(err, "invalid migration payload")
	}

	// add signature verification
	signatureVal, err := utils.HexToBytes(signature)
	if err != nil {
		return errors.Wrapf(err, "invalid signature format")
	}

	chainConfig, err := k.uregistryKeeper.GetChainConfig(sdkCtx, caip2Identifier)
	if err != nil {
		return errors.Wrapf(err, "failed to get chain config for chain %s", caip2Identifier)
	}

	// TODO: Decide later if migration should be disabled if inbound is disabled
	if !chainConfig.Enabled.IsInboundEnabled {
		k.Logger().Warn("migrate UEA rejected: chain not enabled", "chain", caip2Identifier)
		return fmt.Errorf("chain %s is not enabled", caip2Identifier)
	}

	factoryAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)

	// Step 2: Compute smart account address
	// Calling factory contract to compute the UEA address
	ueaAddr, isDeployed, err := k.CallFactoryToGetUEAAddressForOrigin(sdkCtx, evmFrom, factoryAddress, universalAccountId)
	if err != nil {
		return err
	}

	if !isDeployed {
		k.Logger().Warn("migrate UEA rejected: UEA not deployed", "chain", caip2Identifier, "owner", universalAccountId.Owner)
		return fmt.Errorf("UEA is not deployed")
	}

	k.Logger().Debug("migrating UEA",
		"uea", ueaAddr.Hex(),
		"chain", caip2Identifier,
		"from", evmFrom.Hex(),
	)

	// Step 3: Migrate UEA through UEA
	receipt, err := k.CallUEAMigrateUEA(sdkCtx, evmFrom, ueaAddr, migrationPayload, signatureVal)
	if err != nil {
		return err
	}

	k.Logger().Info("UEA migrated",
		"chain", caip2Identifier,
		"uea", ueaAddr.Hex(),
		"tx_hash", receipt.Hash,
		"gas_used", receipt.GasUsed,
	)

	return nil
}
```

```markdown
### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```
