## Analog Vulnerability Found

### Title
Fixed 5% Slippage Tolerance on Protocol-Executed Autoswaps Enables Sandwich Attacks Against Bridged Deposits and Gas Refunds - (File: x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go, x/uexecutor/keeper/evm.go)

### Summary
The external report describes a UniswapV3 liquidity-locking flow that removes and redeposits a position without slippage protection, letting an attacker sandwich the redeposit for profit. Push Chain's analog is the module-driven PRC20→WPC autoswap that runs whenever a `GAS` or `GAS_AND_PAYLOAD` inbound is executed, and whenever excess gas is refunded on outbound completion. In both cases the module fetches a spot quote from the on-chain Uniswap V3 `QuoterV2` and applies a **hardcoded 5% slippage tolerance** computed from that just-fetched (attacker-manipulable) spot price, then immediately executes the swap. There is no protection against the pool price having been moved by an ordinary, unprivileged transaction ordered immediately before the module's swap in the same block.

### Finding Description
Both autoswap call sites compute `minPCOut` the same way: [1](#0-0) [2](#0-1) 

The quote is obtained via `GetSwapQuote`, which calls `QuoterV2.quoteExactInputSingle` against the live pool state at the moment of execution: [3](#0-2) 

The swap is then executed via `CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap` on the `UniversalCore` handler, using the just-computed `minPCOut` as the sole downside protection, with `deadline = 0`: [4](#0-3) 

The same fixed 5% pattern is reused for the gas-refund swap path (`gasToken → PC` on outbound completion): [5](#0-4) 

Because the quote is fetched and the swap executed inside a single Cosmos SDK message handler (`VoteInbound` reaching quorum, or `VoteOutbound` finalization), there is no reentrancy window *between* the quote call and the swap call. However, both calls execute against whatever pool state exists when the enclosing transaction is processed in the block — state that any ordinary, unprivileged user can manipulate via their own transactions ordered earlier in the same block (front-run) and restore afterward (back-run), exactly as in the original UniswapV3 report where liquidity redistribution around a locking event was sandwiched. Since inbound/outbound observations and pending ballots are public on-chain data, an attacker can predict when a quorum-triggering vote (and therefore the autoswap) will land and time the sandwich accordingly. The 5% tolerance is a protocol-fixed constant, not something the depositor can tighten — it is effectively an MEV budget available to whoever front-runs the swap.

### Impact Explanation
Every `GAS` / `GAS_AND_PAYLOAD` inbound deposit and every outbound gas refund that goes through the autoswap path can have up to 5% of its swapped value extracted by an unprivileged attacker sandwiching the module's swap within the block. This is a direct, repeatable value leakage from user/protocol-controlled PRC20↔WPC funds routed through `UniversalCore`'s Uniswap V3 pool, falling under "corruption of ... gas fee accounting, refund accounting ... PRC20 or native asset accounting" and unauthorized drain of user funds in the allowed impact gate. The loss scales with deposit/refund size and pool liquidity depth, and is systematic (triggerable on essentially every qualifying inbound/outbound), not a one-off edge case.

### Likelihood Explanation
High. No privileged access is required — sandwiching a known AMM pool around a predictable transaction is a standard, automatable MEV strategy, and the trigger conditions (any `GAS`/`GAS_AND_PAYLOAD` inbound, or any outbound gas refund) occur routinely as part of normal user activity. The only requirement is sufficient capital to move the pool price within the 5% band and back, which is generally cheap relative to bridged amounts on a lower-liquidity WPC/PRC20 pool.

### Recommendation
- Do not rely solely on a spot quote fetched at execution time for slippage protection; anchor `minPCOut` to a manipulation-resistant reference (e.g., a TWAP-based quote from the pool, or an oracle-checked bound) in addition to/instead of the raw `quoteExactInputSingle` spot quote.
- Tighten and/or make the slippage tolerance protocol-governed and monitorable rather than a silently hardcoded 5% magic number, and consider capping the absolute value extractable per swap.
- Consider splitting large autoswaps or routing through pools with sufficient depth/guardrails, and add commit-reveal or batching so individual swap targets aren't trivially predictable/sandwichable from public UV ballot state.
- Set a real `deadline` rather than `0` where feasible.

### Proof of Concept
1. Attacker observes a pending `MsgVoteInbound`/`MsgVoteOutbound` (or their aggregate ballot) that is one vote away from quorum for a `GAS` or `GAS_AND_PAYLOAD` inbound, or a completing outbound eligible for a gas refund — all of this is public on-chain state.
2. Attacker submits a transaction ordered immediately before the quorum-finalizing vote transaction in the same block, performing a large PRC20→WPC (or WPC→PRC20) swap on the relevant Uniswap V3 pool to move the spot price.
3. The quorum-finalizing transaction executes `GetSwapQuote` against the now-manipulated pool, computes `minPCOut = quote * 95/100`, and executes `depositPRC20WithAutoSwap`/`refundUnusedGas` at the manipulated price — the victim (protocol/bridging user) receives up to 5% less WPC/PC than the true pre-manipulation price would have given.
4. Attacker submits a follow-up transaction later in the same block reversing their initial swap, capturing the price difference as profit, net of pool fees and their own price impact.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
