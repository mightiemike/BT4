### Title
Missing method-whitelist check in `HandleJSONRPCUserMessage` allows unauthorized methods to be fanned out to all DON nodes before rejection - ([File: core/services/gateway/handlers/confidentialrelay/handler.go])

### Summary
`handler.HandleJSONRPCUserMessage` (`core/services/gateway/handlers/confidentialrelay/handler.go:349-366`) only validates `req.ID`; it never checks `req.Method` against the whitelist returned by `Methods()` (`MethodSecretsGet`, `MethodCapabilityExec`) before creating an `activeRequest` and calling `fanOutToNodes`, which sends the raw request to every DON member. The method is only checked later, in `bundler.Bundle`, which returns `errUnknownMethod` for any other method (`bundler.go:118-163`).

### Finding Description
`HandleJSONRPCUserMessage` builds an `activeRequest` via `newActiveRequest` and immediately calls `h.fanOutToNodes(ctx, l, ar)`, which iterates `h.donConfig.Members` and calls `h.don.SendToNode(sendCtx, node.Address, &ar.req)` for every member [1](#0-0) . No method whitelist check occurs anywhere in this path [2](#0-1) . The unsupported-method rejection only happens once a node response arrives and `HandleNodeMessage` calls `h.bundler.Bundle`, which returns `errUnknownMethod` in its `default` case [3](#0-2) .

Whether this handler is actually reachable for an attacker-chosen arbitrary method depends on the outer dispatcher, `multiHandler.getHandler` (`core/services/gateway/multihandler.go:80-96`). Normally, `NewMultiHandler` builds a `methodToHandler` map from each registered handler's `Methods()` and routes strictly by method, rejecting unknown methods with `"no handler found for method"` before ever reaching `confidentialrelay.HandleJSONRPCUserMessage` [4](#0-3) [5](#0-4) . However, `getHandler` contains a special-case bypass: if only a single handler type is registered for that DON, it returns that handler directly without any method-map lookup, meaning arbitrary `req.Method` values reach the handler regardless of whitelist [6](#0-5) .

I was unable to fully confirm from the code I retrieved whether production DON configurations ever register the confidential-relay handler as the sole handler for a given gateway/DON (this depends on deployment config, which is outside the indexed code I could inspect in this session). If it is the sole handler for that DON — which is a plausible and common single-purpose-handler deployment — the single-handler bypass in `multiHandler.getHandler` combined with the missing whitelist check in `confidentialrelay.HandleJSONRPCUserMessage` allows any unauthenticated caller to submit a request with an arbitrary `req.Method` and have it fanned out to every DON member before being rejected only at bundling time.

### Impact Explanation
Each junk request with an invalid method is fully fanned out to all DON members over the websocket transport (`don.SendToNode`) and only fails later in `bundler.Bundle`. This wastes: (1) per-request DON node bandwidth for every member on every submitted request, (2) node processing since each node must still respond to and the gateway must still process `HandleNodeMessage`, which itself consumes both `perNodeRateLimiters` and `globalNodeRateLimiter` budget on the response path per node per junk request [7](#0-6) . Because the fan-out cost is paid before the `errUnknownMethod` rejection, this is an amplification vector: one cheap unauthenticated request produces N (DON member count) sends and N rate-limited response-processing cycles, none of which perform useful work.

### Likelihood Explanation
The precondition is that the deployed multi-handler configuration for the relevant DON registers only the confidential-relay handler (the single-handler bypass path in `multiHandler.getHandler`). If multiple handler types are registered for the DON, `methodToHandler` lookup rejects unknown methods immediately and this handler is never reached, defeating the attack. Whether real deployments run confidential-relay as the sole handler on a given DON/gateway instance could not be confirmed from the code retrieved in this session — this is a configuration-dependent precondition, not something enforced or guaranteed by the code itself. If the precondition holds, the attack is trivially repeatable (an unauthenticated caller can submit unlimited requests with any junk method).

### Recommendation
Add an explicit method-whitelist check at the top of `HandleJSONRPCUserMessage` before creating the `activeRequest` or fanning out, e.g., reject any `req.Method` not in `MethodSecretsGet`/`MethodCapabilityExec` with `api.UnsupportedMethodError` immediately. Additionally, fix `multiHandler.getHandler`'s single-handler bypass so it still validates `req.Method` against that handler's `Methods()` list rather than unconditionally forwarding any method when only one handler type is registered.

### Proof of Concept
Unit test in `core/services/gateway/handlers/confidentialrelay/handler_test.go`:
1. Construct a `handler` via `NewHandler` with a mock `gwhandlers.DON` that records `SendToNode` calls.
2. Call `h.HandleJSONRPCUserMessage(ctx, jsonrpc.Request[json.RawMessage]{ID: "req-1", Method: "not.a.real.method"}, callback)`.
3. Assert: (a) the call does not return an error indicating unsupported method immediately, (b) `SendToNode` was invoked once per DON member (fan-out occurred), demonstrating the request was forwarded before rejection.
4. Follow with simulated `HandleNodeMessage` responses and assert the eventual error surfaced to the callback originates from `bundler.Bundle`'s `errUnknownMethod`, confirming rejection only happens post-fan-out.

For the multi-handler bypass, add a test in `core/services/gateway/gateway_test.go` / `multihandler_test.go` constructing a `multiHandler` with a single registered handler type and asserting that `HandleJSONRPCUserMessage` with a method not in that handler's `Methods()` is still routed to it (demonstrating the bypass) rather than rejected with `"no handler found for method"`.

	if err != nil {
		return err
	}

}

		return fmt.Errorf("received message from unexpected node %s", nodeAddr)
	}
	if !nodeRateLimiter.Allow(ctx) {
		l.Debugw("node is rate limited", "nodeAddr", nodeAddr)
		return nil
	}
	if !h.globalNodeRateLimiter.Allow(ctx) {
		l.Debug("global relay rate limit exceeded")
		return nil
	}

func (h *handler) fanOutToNodes(ctx context.Context, l logger.Logger, ar *activeRequest) error {
	var (
		group      errgroup.Group
		nodeErrors atomic.Uint32
	)

	// Each send is bounded independently. A node whose websocket accepts no writes blocks
	// until its context is cancelled, and because the caller only reads the response callback
	// after this function returns, an unbounded send would hold the request open until the
	// client gives up, discarding a bundle that already reached quorum.
	sendCtx, cancel := context.WithTimeout(ctx, h.nodeSendTimeout)
	defer cancel()

	for _, node := range h.donConfig.Members {
		group.Go(func() error {
			err := h.don.SendToNode(sendCtx, node.Address, &ar.req)
			if err != nil {
				nodeErrors.Add(1)
				l.Errorw("error sending request to node", "node", node.Address, "error", err)
			}
			return nil
		})
	}

	_ = group.Wait()

func (b *bundler) Bundle(req jsonrpc.Request[json.RawMessage], resps map[string]jsonrpc.Response[json.RawMessage], l logger.Logger) (*BundleSummary, error) {
	summary := newBundleSummary(len(resps))

	switch req.Method {
	case relaytypes.MethodSecretsGet:
		out := make([]relaytypes.SignedSecretsResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedSecretsResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable secrets response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedSecretsResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode secrets response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	case relaytypes.MethodCapabilityExec:
		out := make([]relaytypes.SignedCapabilityResponseResult, 0, len(resps))
		for nodeAddr, r := range resps {
			if r.Error != nil || r.Result == nil {
				summary.addError(nodeAddr, r.Error)
				continue
			}
			var signed relaytypes.SignedCapabilityResponseResult
			if err := json.Unmarshal(*r.Result, &signed); err != nil {
				summary.addUndecodable()
				l.Warnw("skipping undecodable capability response from node", "nodeAddr", nodeAddr, "error", err)
				continue
			}
			out = append(out, signed)
		}
		encoded, err := json.Marshal(relaytypes.SignedCapabilityResponseBundle{Responses: out})
		if err != nil {
			return nil, fmt.Errorf("failed to encode capability response bundle: %w", err)
		}
		summary.setSignedResponse(wrapBundle(req, encoded), len(out))
		return summary, nil
	default:
		return nil, fmt.Errorf("%w: %q", errUnknownMethod, req.Method)
	}

// NewMultiHandlerSharded creates a multiHandler with sharded DON support.
func NewMultiHandler(handlerFactory HandlerFactory, hdlrs []config.Handler, shardedDONs []config.ShardedDONConfig, shardsConnMgrs [][]handlers.DON) (handlers.Handler, error) {
	methodToHandler := map[string]handlers.Handler{}
	typeToHandler := map[string]handlers.Handler{}
	for _, h := range hdlrs {
		hdlr, err := handlerFactory.NewHandler(h.Name, h.Config, shardedDONs, shardsConnMgrs)
		if err != nil {
			return nil, fmt.Errorf("failed to create handler %s: %w", h.Name, err)
		}

		typeToHandler[h.Name] = hdlr

		for _, method := range hdlr.Methods() {
			if _, exists := methodToHandler[method]; exists {
				return nil, fmt.Errorf("duplicate handler for method %s: methods must be globally unique across handlers", method)
			}

			methodToHandler[method] = hdlr
		}
	}

	return &multiHandler{
		methodToHandler: methodToHandler,
		typeToHandler:   typeToHandler,
	}, nil
}
