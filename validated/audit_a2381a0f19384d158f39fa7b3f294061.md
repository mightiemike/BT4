### Title
`min_gas_price` can be set greater than `max_gas_price` in genesis config, causing a panic-based chain halt on gas price computation - ([File: core/primitives/src/block.rs])

### Summary
`GenesisConfig::min_gas_price` and `GenesisConfig::max_gas_price` are set once by whoever assembles the genesis (analogous to a constructor-set parameter), but `validate_genesis` never checks that `min_gas_price <= max_gas_price`, unlike other paired thresholds it does validate (e.g. `online_min_threshold`/`online_max_threshold`, `gas_price_adjustment_rate < 1`). If `min_gas_price` is configured above `max_gas_price`, the derived `BlockEconomicsConfig::max_gas_price()` can end up smaller than `min_gas_price()`, and the subsequent `.clamp(min, max)` call in gas price calculation is invoked with an inverted range.

### Finding Description
`GenesisConfig` declares `min_gas_price` and `max_gas_price` as independent fields with no cross-field relationship enforced: [1](#0-0) 

`validate_genesis`/`GenesisValidator::validate_processed_records` performs several "threshold-pair" sanity checks (min < max for online thresholds, adjustment rate < 1, epoch_length > 0), but there is no equivalent check comparing `min_gas_price` to `max_gas_price`: [2](#0-1) 

These values flow directly into `ChainGenesis` and then into `BlockEconomicsConfig`: [3](#0-2) [4](#0-3) 

`BlockEconomicsConfig::max_gas_price()` computes `min(genesis_max_gas_price, min_gas_price() * 20)`. If `genesis_min_gas_price > genesis_max_gas_price`, the effective `max_gas_price()` returned can be smaller than `min_gas_price()` — because `genesis_max_gas_price` itself is already below `min_gas_price()`, and `min()` only ever lowers the returned value further, never raises it back above `min_gas_price()`.

This inverted `[min, max]` pair is then passed into `compute_next_gas_price_checked`, which clamps the computed price: [5](#0-4) 

The `.clamp(min, max)` call (via the underlying `U256`/`Ord`-based clamp) requires `min <= max`; when that invariant is violated the operation panics rather than silently returning a nonsensical value. This function is called for essentially every produced/validated block (both by `Block::verify_gas_price_checked` and block production logic), so once genesis with `min_gas_price > max_gas_price` is used, the very first block whose chunk actually spends gas (`gas_limit != Gas::ZERO`) triggers the panic in every node processing it.

### Impact Explanation
This is a chain-halting misconfiguration: a genesis with `min_gas_price > max_gas_price` passes `validate_genesis` successfully, but as soon as a chunk with nonzero gas usage is included, all honest nodes computing/verifying the next gas price panic deterministically on the same clamp call, network-wide, since the buggy inverted range is derived identically by every node from the same genesis data. This matches the "transaction-triggered halt" class: the panic is triggered as soon as any transaction/receipt causes a chunk with `gas_limit != Gas::ZERO` to be processed, which is the normal case for any network activity.

### Likelihood Explanation
This requires whoever assembles the genesis (chain deployer/operator, e.g. for a new testnet/localnet or a custom chain spec) to set `min_gas_price` above `max_gas_price` — an easy mistake since nothing in `validate_genesis` rejects it, unlike the analogous `online_min_threshold`/`online_max_threshold` pair which *is* checked. Given `max_gas_price` defaults to a small constant (`MAX_GAS_PRICE = 10 millinear`) while `min_gas_price` is a required, unconstrained field, misconfigured or copy-pasted genesis files (e.g., custom localnet/devnet setups) are plausible.

### Recommendation
Add a genesis semantics check in `GenesisValidator::validate_processed_records` (mirroring the existing `online_max_threshold <= online_min_threshold` check) that rejects genesis configs where `min_gas_price > max_gas_price`, e.g.:
```rust
if self.genesis_config.min_gas_price > self.genesis_config.max_gas_price {
    let error_message = format!(
        "min_gas_price {} is greater than max_gas_price {}",
        self.genesis_config.min_gas_price, self.genesis_config.max_gas_price
    );
    self.validation_errors.push_genesis_semantics_error(error_message)
}
```
Additionally, consider hardening `BlockEconomicsConfig::max_gas_price()`/`compute_next_gas_price_checked` to return an error (or clamp defensively with `max(min_gas_price, ...)`) instead of panicking, so a single misconfigured field cannot crash the whole network.

### Proof of Concept
1. Construct a `GenesisConfig` with `min_gas_price = Balance::from_yoctonear(X)` and `max_gas_price = Balance::from_yoctonear(Y)` where `Y < X` (e.g., `min_gas_price = 10^12`, `max_gas_price = 10^6`, well within `MAX_GAS_MULTIPLIER = 20` bound check that doesn't exist).
2. Run `validate_genesis(&genesis)` — it returns `Ok(())` because no check compares these two fields (`core/chain-configs/src/genesis_validate.rs:178-229`).
3. Start the chain; on the first block with `gas_limit != Gas::ZERO` chunk, `Block::compute_next_gas_price_checked` (or `verify_gas_price_checked`) is invoked with `min_gas_price > max_gas_price` (`core/primitives/src/block.rs:455-492`), causing the `.clamp(min, max)` call to panic, crashing every node that processes/verifies that block.

/// Block economics config taken from genesis config
pub struct BlockEconomicsConfig {
    gas_price_adjustment_rate: Rational32,
    genesis_min_gas_price: Balance,
    genesis_max_gas_price: Balance,
    genesis_protocol_version: ProtocolVersion,
}

impl BlockEconomicsConfig {
    /// Set max gas price to be this multiplier * min_gas_price
    const MAX_GAS_MULTIPLIER: u128 = 20;
    /// Compute min gas price according to protocol version and genesis protocol version.
    ///
    /// This returns the effective minimum gas price for a block with the given
    /// protocol version. The base value is defined in genesis.config but has
    /// been overwritten at specific protocol versions. Chains with a genesis
    /// version higher than those changes are not overwritten and will instead
    /// respect the value defined in genesis.
    pub fn min_gas_price(&self) -> Balance {
        if self.genesis_protocol_version == PROD_GENESIS_PROTOCOL_VERSION {
            MIN_GAS_PRICE_NEP_92_FIX
        } else {
            self.genesis_min_gas_price
        }
    }

    pub fn max_gas_price(&self) -> Balance {
        std::cmp::min(
            self.genesis_max_gas_price,
            self.min_gas_price().checked_mul(Self::MAX_GAS_MULTIPLIER).unwrap(),
        )
    }

    pub fn gas_price_adjustment_rate(&self) -> Rational32 {
        self.gas_price_adjustment_rate
    }
}

    pub fn compute_next_gas_price_checked(
        gas_price: Balance,
        gas_used: Gas,
        gas_limit: Gas,
        gas_price_adjustment_rate: Rational32,
        min_gas_price: Balance,
        max_gas_price: Balance,
    ) -> Option<Balance> {
        // If block was skipped, the price does not change.
        if gas_limit == Gas::ZERO {
            return Some(gas_price);
        }

        let gas_used = u128::from(gas_used.as_gas());
        let gas_limit = u128::from(gas_limit.as_gas());
        let adjustment_rate_numer = *gas_price_adjustment_rate.numer() as u128;
        let adjustment_rate_denom = *gas_price_adjustment_rate.denom() as u128;

        // This number can never be negative as long as gas_used <= gas_limit and
        // adjustment_rate_numer <= adjustment_rate_denom.
        let numerator = 2u128
            .checked_mul(adjustment_rate_denom)?
            .checked_mul(gas_limit)?
            .checked_add(2u128.checked_mul(adjustment_rate_numer)?.checked_mul(gas_used)?)?
            .checked_sub(adjustment_rate_numer.checked_mul(gas_limit)?)?;
        let denominator = 2u128.checked_mul(adjustment_rate_denom)?.checked_mul(gas_limit)?;
        let next_gas_price =
            U256::from(gas_price.as_yoctonear()) * U256::from(numerator) / U256::from(denominator);

        Some(Balance::from_yoctonear(
            next_gas_price
                .clamp(
                    U256::from(min_gas_price.as_yoctonear()),
                    U256::from(max_gas_price.as_yoctonear()),
                )
                .as_u128(),
        ))
    }
