### Title
Non-injective canonicalization in `stringifyQueryForAppProxy` allows signature reuse across different app-proxy query parameter sets - ([File: packages/apps/shopify-api/lib/utils/hmac-validator.ts])

### Summary
`stringifyQueryForAppProxy` concatenates sorted `key=value` pairs with no separator and no escaping, so different `(key, value)` dictionaries can serialize to the identical byte string that is fed into `createSHA256HMAC`. This is unlike `stringifyQueryForAdmin`, which uses `URLSearchParams`/`ProcessedQuery` and therefore always inserts `&` and percent-encodes reserved characters, making that path injective.

### Finding Description
`stringifyQueryForAppProxy` in [1](#0-0)  builds the canonical string by simple template concatenation (`` `${acc}${key}=${value}` ``) with no delimiter between successive `key=value` pairs and no encoding of `=` characters that may appear inside a value. Because sorting is lexicographic over keys only, two different query objects can produce the same concatenated string when a byte sequence can be split at a different key/value boundary, e.g.:

- QueryA = `{a: '1', ab: '2'}` → sorted keys `a, ab` → `"a=1" + "ab=2"` = `"a=1ab=2"`
- QueryB = `{a: '1a', b: '2'}` → sorted keys `a, b` → `"a=1a" + "b=2"` = `"a=1ab=2"`

Both serialize to the identical string `"a=1ab=2"`, so `createSHA256HMAC(secret, "a=1ab=2", ...)` is identical for both, meaning `generateLocalHmac(config)(QueryA, 'appProxy')` equals `generateLocalHmac(config)(QueryB, 'appProxy')` in [2](#0-1) . `validateHmac` in [3](#0-2)  only performs `safeCompare(hmac, localHmac)` on this ambiguous string, so it cannot distinguish the two distinct parameter dictionaries. Contrast with `stringifyQueryForAdmin` at [4](#0-3) , which delegates to `ProcessedQuery`/`URLSearchParams` (`&`-joined, percent-encoded) in [5](#0-4) , so that path is not subject to the same boundary-shifting collision.

Note this concatenation format matches Shopify's own documented app-proxy signing algorithm (unescaped, delimiter-less, sorted key/value concatenation), so the library must reproduce it exactly to validate signatures issued by Shopify's servers. The ambiguity is therefore inherent to the app-proxy signing scheme this library must interoperate with, not an implementation choice that can be changed without breaking compatibility with genuinely signed Shopify requests.

### Impact Explanation
An attacker who can get Shopify to sign one query (by simply visiting their own app-proxy URL with attacker-chosen query parameters, which Shopify's servers sign and forward) could in principle capture a `signature` value and replay it against a different, colliding query dictionary, causing `validateHmac` to accept parameters that were never actually signed by Shopify for that meaning. This falls into a signature/parameter-substitution class, but the practical value depends entirely on the crafted collision producing param names/values with divergent semantics inside the target app.

### Likelihood Explanation
Constructing the collision itself is trivial and demonstrated above via pure string math on the library function. However, actually weaponizing it against a live app requires: (1) the app-proxy request to reach the target app directly with attacker-supplied headers bypassing Shopify's normal forwarding (or the attacker being able to relay a captured signed request), and (2) the app to treat the substituted parameter as security- or logic-relevant. Because this concatenation format is mandated by Shopify's own app-proxy signing protocol (not a deviation introduced by this library), fixing it here alone (e.g., adding delimiters/escaping) would break verification of legitimately-signed Shopify requests, since local computation would then diverge from Shopify's server-side HMAC.

### Recommendation
None achievable purely within this library without breaking interoperability with Shopify's app-proxy HMAC scheme; any change to add delimiters/escaping to `stringifyQueryForAppProxy` would cause legitimate Shopify-signed requests to fail validation. Downstream app developers should avoid using ambiguous/overlapping parameter names in app-proxy-sensitive logic and treat single-value app-proxy parameters (already partially enforced by `APP_PROXY_SINGLE_VALUE_PARAMS`) as the only trusted fields.

```ts
import {generateLocalHmac} from '../hmac-validator';
import {testConfig} from '../../__tests__/test-config'; // representative config helper

test('stringifyQueryForAppProxy canonicalization collision', async () => {
  const config = testConfig();
  const localHmac = generateLocalHmac(config);

  const queryA = {a: '1', ab: '2'};
  const queryB = {a: '1a', b: '2'};

  const hmacA = await localHmac(queryA, 'appProxy');
  const hmacB = await localHmac(queryB, 'appProxy');

  expect(hmacA).toBe(hmacB); // both concatenate to "a=1ab=2"
});
```
Expected: assertion passes, confirming `generateLocalHmac` produces identical HMACs for two distinct query dictionaries when using the `appProxy` signator, demonstrating the canonicalization is not injective.

```typescript
function stringifyQueryForAdmin(query: AuthQuery): string {
  const processedQuery = new ProcessedQuery();
  Object.keys(query)
    .sort((val1, val2) => val1.localeCompare(val2))
    .forEach((key: string) => processedQuery.put(key, query[key]));

  return processedQuery.stringify(true);
}
```

```typescript
function stringifyQueryForAppProxy(query: AuthQuery): string {
  return Object.entries(query)
    .sort(([val1], [val2]) => val1.localeCompare(val2))
    .reduce((acc, [key, value]) => {
      return `${acc}${key}=${Array.isArray(value) ? value.join(',') : value}`;
    }, '');
}
```

```typescript
export function generateLocalHmac(config: ConfigInterface) {
  return async (
    params: AuthQuery,
    signator: HMACSignator = 'admin',
  ): Promise<string> => {
    const {hmac: _hmac, signature: _signature, ...query} = params;

    const queryString =
      signator === 'admin'
        ? stringifyQueryForAdmin(query)
        : stringifyQueryForAppProxy(query);

    return createSHA256HMAC(config.apiSecretKey, queryString, HashFormat.Hex);
  };
}
```

```typescript
export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}
```
