### Title
Self-referential minPCOut slippage bound derived from a manipulable spot-price Uniswap quote allows sandwich extraction on inbound gas swaps and gas refunds - (File: x/uexecutor/keeper/evm.go, execute_inbound_gas.go, execute_inbound_gas_and_payload.go, outbound.go)

### Summary
Push Chain's own README explicitly documents this exact bug class as previously identified and "fixed" by adding a 5% `minPCOut` slippage bound derived from `QuoterV2.quoteExactInputSingle` [4](#0-3) . However, the fix computes the *reference* quote from the same manipulable spot price that the swap itself will execute against, in the same call path, rather than from an external, attacker-independent price source (e.g., a TWAP or a caller/governance-supplied bound). This mirrors the root cause underlying the original Vultisig `ILOPool::claim` report: value-bearing burn/swap operations execute against on-chain AMM state that an unprivileged actor can move immediately beforehand, and the "protection" is computed from that same influenced state, so it bounds only intra-call rounding/impact, not price manipulation.

### Finding Description
Three module-originated swap paths compute their slippage floor identically:

1. `ExecuteInboundGas` (GAS inbound funding path) — fetches `quote := GetSwapQuote(...)`, sets `minPCOut = quote * 95/100`, then immediately calls `CallPRC20DepositAutoSwap` with that bound [2](#0-1) .
2. `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound path) — identical pattern [5](#0-4) .
3. `applyGasRefund` (outbound gas-refund path, triggered on `MsgVoteOutbound` finalization) — identical pattern via `getSwapQuoteForRefund` [6](#0-5) .

`GetSwapQuote` itself is a static call to `QuoterV2.quoteExactInputSingle`, i.e., it reads the *current* spot state of the Uniswap V3 pool at execution time [1](#0-0) . There is no TWAP, no governance-configured maximum price deviation, and no independently sourced reference price — the "slippage protection" is 95% of whatever price the pool reports *at the instant the module reads it*, inside the very same transaction that then executes the swap against that same pool.

All three call sites are triggered by unprivileged, user-reachable flows:
- GAS / GAS_AND_PAYLOAD inbound execution is triggered once `MsgVoteInbound` from Universal Validators reaches quorum for an inbound that any external user can create by depositing on a source chain — the *timing* of quorum (and thus of the swap) is attacker-influenceable by choosing when/whether to trigger the deposit and by the public mempool visibility of the finalizing vote transaction.
- `applyGasRefund` fires inside `MsgVoteOutbound` finalization, another publicly-visible, quorum-triggered transaction.

Because Push Chain (or any market participant) can, in a preceding block or via front-running the finalizing vote transaction, execute a large swap against the same PRC20/WPC Uniswap V3 pool to move its spot price, the subsequently read `quote` will reflect the manipulated price. The 95% bound only guards against further in-block price movement after the quote is read — it does not protect against the reference price itself already being manipulated. An attacker can:
1. Swap into the pool to depress `prc20 → wpc` price.
2. Wait for (or induce) the inbound-execution or outbound-refund swap to execute at that depressed price, still passing its own 95%-of-manipulated-quote check.
3. Reverse the initial swap, capturing the value the module lost by swapping PRC20 for less PC than fair value.

The net effect is the recipient (or refund recipient) of the auto-swap receives less PC than they should, and the difference is extracted by the attacker via the sandwich, functionally identical in mechanism to the cited Vultisig report despite the presence of a slippage parameter — the parameter is derived from, not independent of, the manipulable price.

### Impact Explanation
This corrupts PC/PRC20 refund and deposit accounting on the universal execution path: gas-refund recipients (`applyGasRefund`) and inbound gas-funding recipients (`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`) receive less native PC than the fair-value swap would have produced, while an unprivileged attacker profits the difference through arbitrage against the same pool. This falls under "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting" in the allowed impact set, reachable purely from ordinary user deposit/outbound flows with honest validators — no privileged or malicious-validator assumption is required.

### Likelihood Explanation
Requires the attacker to have capital to move the specific PRC20/WPC pool's price and to time a swap around the public, quorum-triggering vote transaction (front-runnable since votes are ordinary mempool transactions). Feasibility scales inversely with the pool's liquidity depth; for low-liquidity PRC20 gas-token pools this is a realistic MEV/sandwich opportunity. Likelihood is Medium, consistent with the original C4 judge's Medium-risk determination for the analogous Vultisig finding.

### Recommendation
Do not derive `minPCOut` solely from a spot-price quote fetched in the same transaction as the swap. Use a manipulation-resistant reference price (e.g., a time-weighted average price over multiple blocks, or a price bound anchored to the chain-meta/gas-price oracle already maintained by `x/uexecutor`) to compute the slippage floor, and/or widen protections with a maximum allowed deviation from that independent reference rather than a fixed percentage of the just-read spot quote.

### Proof of Concept
1. Attacker identifies a PRC20 gas-token/WPC Uniswap V3 pool used by `CallPRC20DepositAutoSwap`/`refundUnusedGas` with modest liquidity.
2. Attacker submits a large `prc20 → wpc` swap to depress the pool's spot price.
3. Attacker observes (or waits for) a pending `MsgVoteOutbound` (or the last vote reaching quorum for `MsgVoteInbound` GAS type) in the mempool that will trigger `applyGasRefund` / `ExecuteInboundGas`.
4. The finalizing vote transaction executes: `GetDefaultFeeTierForToken` → `getSwapQuoteForRefund`/`GetSwapQuote` reads the now-depressed price, computes `minPCOut = quote*95/100` from that already-manipulated `quote`, and `CallUniversalCoreRefundUnusedGas`/`CallPRC20DepositAutoSwap` executes the swap, satisfying its own manipulated bound.
5. Attacker reverses the initial swap, extracting the value difference; the refund/deposit recipient permanently receives less PC than fair value would have produced.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
```
