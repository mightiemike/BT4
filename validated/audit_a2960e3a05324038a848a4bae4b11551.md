### Title
Misnamed `isSafe` redirect validator does not restrict redirect target to the app's domain, enabling open redirect via unauthenticated `exitIframe` request - (File: `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-redirect-url.ts` / `packages/apps/shopify-app-react-router/src/server/authenticate/admin/helpers/validate-redirect-url.ts`)

### Summary
The `sanitizeRedirectUrl`/`isSafe` helper is named as if it enforces that redirect targets stay within the app's own domain, but it never checks the resulting URL's hostname against `config.appUrl`. It only rejects `file:` URIs, whitespace, protocol-relative/backslash tricks in the pathname, and non-`http(s)` protocols. Any fully-qualified `https://` URL is accepted as "safe," which is functionally analogous to the `_safeTransferFrom` finding: a function whose name promises a security guarantee it does not actually provide.

### Finding Description
`isSafe()` builds `new URL(redirectUrl, domain)` and only validates:
- absence of `///` (file URI) and whitespace,
- absence of `//` or `\\` in `url.pathname`,
- `url.protocol` is `http:`/`https:`,
- optionally requires `https:` when `requireSSL` is true (default). [1](#0-0) 

Crucially, it never compares `url.hostname`/`url.origin` to the `domain` argument (`config.appUrl`). When `redirectUrl` is already an absolute URL (e.g. `https://evil.example.com/phish`), `new URL(redirectUrl, domain)` simply parses it as `https://evil.example.com/phish`, `url.pathname` is `/phish` (no double slash), the protocol is `https:`, so `isSafe` returns `true` and `sanitizeRedirectUrl` returns that external URL unchanged: [2](#0-1) 

This helper is used by `renderAppBridge` to build the exit-iframe redirect script: [3](#0-2) 

The destination comes straight from the attacker-controlled `exitIframe` query parameter, extracted in `respondToExitIframeRequest`, which runs unconditionally for any request that hits `authenticate.admin()` on the app's exit-iframe path — before shop/host validation or session authentication: [4](#0-3) [5](#0-4) 

The identical pattern exists in the `shopify-app-remix` package: [6](#0-5)  and its own `validate-redirect-url.ts`/`render-app-bridge.ts` copies.

### Impact Explanation
An anonymous attacker can craft a link to any app's exit-iframe endpoint (e.g. `https://merchant-app.example.com/auth/exitframe?exitIframe=https://evil.example.com`) and have the app render a script performing `window.open("https://evil.example.com", "_top")` (top-level navigation out of the Shopify admin iframe). Since this is served from the legitimate app domain and reached during the normal embedded-app bounce/exit-iframe flow (which merchants are conditioned to trust), it enables convincing phishing/open-redirect attacks against merchants using the app — e.g., redirecting a merchant mid-OAuth/session-token flow to an attacker-controlled page that mimics Shopify login to harvest credentials or session tokens.

### Likelihood Explanation
High: the exit-iframe path check happens unconditionally at the very top of `authenticateAdmin`, before any shop/host validation or session-token check, so it is reachable by a single unauthenticated HTTP GET with a crafted `exitIframe` query parameter — no privileged access, secrets, or MITM required.

### Recommendation
Fix `isSafe()` (in both `shopify-app-remix` and `shopify-app-react-router`) to also validate that the parsed URL's origin/hostname equals (or is a subpath of) the `domain` parameter (`config.appUrl`) when the input is an absolute URL, rejecting any cross-origin destination unless explicitly allow-listed. This restores the guarantee the function name implies.

### Proof of Concept
1. Deploy an embedded app using `shopify-app-remix` or `shopify-app-react-router` with `exitIframePath` configured (e.g. `/auth/exitframe`).
2. As an anonymous browser, visit:
   `https://<app-domain>/auth/exitframe?exitIframe=https://evil.example.com/phish`
3. The server responds 200 with the App Bridge HTML containing:
   `<script>window.open("https://evil.example.com/phish", "_top")</script>`
4. The browser (or Shopify admin iframe host) performs a top-level navigation to `https://evil.example.com/phish`, confirming `isSafe`/`sanitizeRedirectUrl` accepted an off-domain URL as "safe."

```typescript
function isSafe(
  domain: string,
  redirectUrl: unknown,
  requireSSL: boolean | undefined = true,
): redirectUrl is string {
  if (typeof redirectUrl !== 'string') {
    return false;
  }

  if (
    FILE_URI_MATCH.test(redirectUrl) ||
    WHITESPACE_CHARACTER.test(redirectUrl)
  ) {
    return false;
  }

  let url: URL;

  try {
    url = new URL(redirectUrl, domain);
  } catch (_error) {
    return false;
  }

  if (INVALID_RELATIVE_URL.test(url.pathname)) {
    return false;
  }

  if (!VALID_PROTOCOLS.includes(url.protocol)) {
    return false;
  }

  if (requireSSL && url.protocol !== 'https:') {
    return false;
  }

  return true;
}
```

```typescript
export function sanitizeRedirectUrl<OptionsArg extends Options>(
  domain: string,
  redirectUrl: unknown,
  options: OptionsArg = {} as OptionsArg,
): SanitizedRedirectUrl<OptionsArg> {
  if (isSafe(domain, redirectUrl, options.requireSSL)) {
    return new URL(redirectUrl, domain) as SanitizedRedirectUrl<OptionsArg>;
  } else if (options.throwOnInvalid === false) {
    return undefined as SanitizedRedirectUrl<OptionsArg>;
  } else {
    throw new ShopifyError('Invalid URL. Refusing to redirect');
  }
}
```
