## Finding: Integer-division truncation zeroes out the swap slippage floor for small gas-abstraction deposits

### Title
Integer division `quote * 95 / 100` truncates `minPCOut` to (near-)zero for small deposits, defeating the swap slippage protection - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The H-8 bug class is "an integer division whose numerator is scaled by a small percentage factor rounds a legitimate, non-zero protective value down to zero, silently disabling the invariant the division was meant to enforce." Push Chain's gas-abstraction auto-swap path reproduces exactly this pattern: `minPCOut := quote * 95 / 100` is meant to bound the acceptable DEX slippage to 5%, but for attacker-controlled small deposit amounts the truncating integer division collapses `minPCOut` toward `0`, removing the slippage floor entirely.

### Finding Description
Every code path that performs the PRC20→PC auto-swap for gas top-ups computes the DEX minimum-output guard the same way: [1](#0-0) [2](#0-1) [3](#0-2) 

```go
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
```

`quote` comes from `GetSwapQuote`, which is a live on-chain Uniswap-style quote for `amount` (the user-supplied, attacker-controlled `inbound.Amount`, or the excess-gas `refundAmount` computed from validator-reported `gasFeeUsed`). Because `Div` is integer (truncating) division, whenever `quote * 95 < 100` (i.e. `quote` is `0` or a very small integer — trivially reachable since dust-sized `Amount` values are user-controlled and unvalidated for a minimum), `minPCOut` truncates to `0`. Even for slightly larger but still small `quote` values, the truncation systematically under-protects (e.g. `quote=19` → intended min `18.05` → actual `18`, `quote=1` → intended `0.95` → actual `0`), the closer `quote` is to zero the larger the *relative* slippage tolerance becomes.

This value is passed straight into `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, which execute `UniversalCore.depositPRC20WithAutoSwap(...)` / `refundUnusedGas(..., minPCOut)` via a module-originated `DerivedEVMCall`: [4](#0-3) 

`minPCOut=0` (or near-zero) means the Uniswap-style swap inside `UniversalCore` accepts virtually any output amount — the on-chain slippage check the contract relies on is neutralized for exactly the deposits it should protect (small ones), and an attacker who can also influence the underlying pool's spot price (sandwiching the module-originated swap tx, which is deterministically ordered/known ahead of inclusion) can extract nearly the entire swapped value from the deposit or refund.

### Impact Explanation
An unprivileged attacker submitting an ordinary `GAS` or `GAS_AND_PAYLOAD` inbound with a small `Amount` (fully attacker-controlled, no minimum-amount validation gate before the quote/slippage computation) causes the protocol's own slippage protection to silently disappear for that deposit's auto-swap. Combined with sandwich/MEV activity around the pool the module swaps against, this allows draining of the swapped value that should have gone to the recipient/gas top-up, i.e. loss of user/protocol funds during a core universal-execution flow (`ExecuteInboundGas` / `ExecuteInboundGasAndPayload` / `applyGasRefund`), which is squarely in the "PRC20/native asset accounting" and "universal execution flow" impact categories.

### Likelihood Explanation
High reachability: any external user can trigger `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` by initiating a normal cross-chain deposit with a small token amount — no privileged role, honest-validator collusion, or unusual configuration is required. The truncation is deterministic arithmetic, not a probabilistic edge case.

### Recommendation
Round the slippage floor up (ceiling division) rather than down, and/or enforce a floor that scales with `amount`/`quote` precision (e.g. compute `minPCOut = (quote*95 + 99) / 100`, and additionally reject/round using higher internal precision before scaling by the fee/BPS factor) so that `minPCOut` never truncates below the intended 5%-bounded value, mirroring the `BASE_SCALE` fix recommended for the original Vault issue.

### Proof of Concept
1. Attacker sends an inbound (`TxType_GAS` or `GAS_AND_PAYLOAD`) with `Amount` small enough that `GetSwapQuote` returns `quote` such that `quote*95 < 100` (e.g. `quote = 1`).
2. `ExecuteInboundGas` computes `minPCOut = 1*95/100 = 0`.
3. `CallPRC20DepositAutoSwap(..., minPCOut=0)` is executed on-chain; the DEX swap accepts any non-negative output.
4. An observer sandwiches the module-originated swap transaction (predictable calldata/ordering), extracting the swap output before the recipient receives it, resulting in near-total loss of the deposit's swap value with no revert or error recorded (the PCTx is marked `SUCCESS`).
