### Title
Microblock pubkey-hash height lookup is last-write-wins, letting a miner launder a genuine equivocation to a different (cheaper) tenure's coinbase - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`)

### Summary
`handle_poison_microblock` resolves the tenure height to punish solely via `get_microblock_pubkey_hash_height`, which is backed by a Clarity key keyed only on `pubkey_hash` (`make_microblock_pubkey_height_key`), not on `(pubkey_hash, height)`. Because `insert_microblock_pubkey_hash` overwrites this single-valued mapping every time the same microblock signing key is stamped at a new tenure, a miner who reuses one microblock private key across two of their own tenures h1 < h2 can cause a valid double-sign report for h1's real equivocation to be recorded against h2 instead, sparing h1's (potentially larger) coinbase from forfeiture and misdirecting h2's coinbase to the reporter.

### Finding Description
The broken equality: "reward forfeited == coinbase of the tenure at which the reported miner actually double-signed microblocks" is not preserved. Instead, the actual equality enforced by the code is "reward forfeited == coinbase of whichever tenure most recently wrote `pubkey_hash -> height` in the Clarity KV store", per `get_microblock_pubkey_hash_height` [1](#0-0) .

Root cause: `ClarityDatabase::make_microblock_pubkey_height_key` (and thus `get_microblock_pubkey_hash_height`) is keyed purely by `pubkey_hash`, so there is only one height value stored per pubkey hash at any time; a later `insert_microblock_pubkey_hash` call for the same pubkey hash at a different height silently overwrites the earlier mapping. `handle_poison_microblock` uses this single lookup to determine which height's poison report/coinbase to touch, then `get_microblock_poison_report`/`insert_microblock_poison` and downstream `find_mature_miner_rewards` (`StacksChainState::get_poison_microblock_report(clarity_tx, reward_height)`) key the punishment strictly on that resolved height [2](#0-1) , and `calculate_miner_reward` forfeits the coinbase belonging to whichever height is passed in [3](#0-2) .

Attacker input/exploit flow: a single miner (no majority stake required — just any miner able to win two leader-election slots over time) mines tenure h1 and deliberately double-signs a microblock fork there (the real, valuable offense — e.g. a high-fee tenure), then later mines tenure h2 with a low-value/near-empty tenure and re-uses the same microblock signing key so that `insert_microblock_pubkey_hash(h2, pubkh)` overwrites the h1 mapping. When any reporter (the attacker themself, or an unwitting third party who did observe h1's fork) submits a legitimate `PoisonMicroblock` transaction proving h1's equivocation, `get_microblock_pubkey_hash_height(&pubkh)` returns h2 (the last write), so the poison report and eventual coinbase forfeiture land on h2's schedule instead of h1's. h1's genuine offense goes unpunished and its (larger) coinbase matures normally to the miner; h2's coinbase — which committed no offense — is the one forfeited to the reporter.

None of the listed guards (`check_tenure_tx`, `verify_signer_signatures`, `validate_vrf_seed`, `validate_*_static`, `common_validate_against_burnchain`, MARF hashing, maturation-window checks) inspect whether a microblock pubkey hash was already associated with an earlier height before overwriting it; nothing in `insert_microblock_pubkey_hash` enforces key uniqueness across tenures.

### Impact Explanation
This is a block-reward mis-payment/loss: the coinbase that should be forfeited (the genuinely offending tenure's) is paid in full to the miner, while an innocent tenure's coinbase (potentially belonging to the same or, in principle, a different scheduled reward entry) is instead forfeited to the reporter. A miner can specifically choose which of two of their own tenures absorbs the penalty, effectively laundering punishment away from a high-value coinbase onto a low-value one they are willing to sacrifice — a direct, repeatable reward-theft/evasion path scoped to Critical per the "block-reward theft/double-payment/loss" category.

### Likelihood Explanation
Preconditions are within reach of a single unprivileged miner: they need only (a) win two separate tenures over time (ordinary mining participation, no majority stake), (b) reuse the exact same microblock private key across those two tenures — which nothing in `insert_microblock_pubkey_hash`/`make_microblock_pubkey_height_key` prevents — and (c) actually double-sign microblocks in the tenure they intend to protect. No coordination with, or compromise of, any other party's keys is required, satisfying the "unprivileged, single miner slot" attacker model. The behavior is deterministic and fully repeatable each time the same miner reuses a key across tenures.

### Recommendation
Key the microblock-pubkey-hash-to-height mapping (and the poison lookup) by `(pubkey_hash, height)` or otherwise refuse to overwrite an existing `pubkey_hash -> height` mapping in `insert_microblock_pubkey_hash`/`make_microblock_pubkey_height_key`, so `get_microblock_pubkey_hash_height` can return (or reject ambiguity across) all heights that ever used a given pubkey hash rather than only the most recent one. Alternatively, reject microblock-pubkey-hash reuse across tenures outright during block validation.

### Proof of Concept
Rust integration test (two-tenure harness similar to `stackslib/src/chainstate/stacks/tests/block_construction.rs`):
1. Tenure h1: miner commits block with `microblock_pubkey_hash = pubkh` (from `privk`), builds two conflicting microblocks at sequence `seq1` signed with `privk` (genuine equivocation). Do not submit poison tx yet.
2. Tenure h2 (h2 > h1): same miner commits a new block reusing the same `microblock_pubkey_hash = pubkh`; no equivocation occurs in h2's stream.
3. After h2 is mined, submit a `PoisonMicroblock` tx referencing h1's two conflicting microblock headers.
4. Assert `StacksChainState::get_poison_microblock_report(clarity_tx, h1) == None` (h1's real offense unrecorded) and `StacksChainState::get_poison_microblock_report(clarity_tx, h2) == Some((reporter, seq1))` (misattributed to h2), demonstrating the equality `reward_height_of_poison_record == height_of_actual_offense` is violated.
5. Advance chain past `MINER_REWARD_MATURITY` for both h1 and h2, and assert via `find_mature_miner_rewards`/`get_matured_miner_payment` that h1's miner reward (coinbase) is paid in full to the miner, while h2's coinbase is redirected to the reporter — confirming reward mis-payment to the wrong tenure.

    /// Find the latest miner reward to mature, assuming that there are mature rewards.
    /// Returns a list of payments to make to each address -- miners and user-support burners -- as
    /// well as an info struct about where the rewards took place on the chain.
    pub fn find_mature_miner_rewards(
        clarity_tx: &mut ClarityTx,
        sortdb_conn: &Connection,
        tip_stacks_height: u64,
        mut latest_matured_miners: Vec<MinerPaymentSchedule>,
        parent_miner: MinerPaymentSchedule,
    ) -> Result<Option<(MinerReward, Vec<MinerReward>, MinerReward, MinerRewardInfo)>, Error> {
        let mainnet = clarity_tx.config.mainnet;
        if tip_stacks_height <= MINER_REWARD_MATURITY {
            // no mature rewards exist
            return Ok(None);
        }

        let reward_height = tip_stacks_height - MINER_REWARD_MATURITY;

        let latest_matured_miners_head = latest_matured_miners
            .first()
            .expect("latest_matured_miners should not be empty");
        assert!(latest_matured_miners_head.vtxindex == 0);
        assert!(latest_matured_miners_head.miner);

        let users = latest_matured_miners.split_off(1);
        let miner = latest_matured_miners
            .pop()
            .expect("BUG: no matured miners despite prior check");

        let reward_info = MinerRewardInfo {
            from_stacks_block_hash: miner.block_hash.clone(),
            from_block_consensus_hash: miner.consensus_hash.clone(),
            from_parent_stacks_block_hash: parent_miner.block_hash.clone(),
            from_parent_block_consensus_hash: parent_miner.consensus_hash.clone(),
        };

        // what epoch was the parent miner's block evaluated in?
        let parent_evaluated_snapshot =
            SortitionDB::get_block_snapshot_consensus(sortdb_conn, &parent_miner.consensus_hash)?
                .expect("FATAL: no snapshot for evaluated block");

        let parent_evaluated_epoch =
            SortitionDB::get_stacks_epoch(sortdb_conn, parent_evaluated_snapshot.block_height)?
                .expect("FATAL: no epoch for evaluated block");

        // was this block penalized for mining a forked microblock stream?
        // If so, find the principal that detected the poison, and reward them instead.
        let poison_recipient_opt =
            StacksChainState::get_poison_microblock_report(clarity_tx, reward_height)?
                .map(|(reporter, _)| reporter);

        if let Some(ref _poison_reporter) = poison_recipient_opt.as_ref() {
            test_debug!(
                "Poison-microblock reporter {} at height {}",
                &_poison_reporter.to_string(),
                reward_height
            );
        } else {
            test_debug!("No poison-microblock report at height {}", reward_height);
        }

        // calculate miner reward
        let (parent_miner_reward, miner_reward) = StacksChainState::calculate_miner_reward(
            mainnet,
            parent_evaluated_epoch.epoch_id,
            &miner,
            &miner,
            &users,
            &parent_miner,
            poison_recipient_opt.as_ref(),
        );
