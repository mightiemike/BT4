### Title
Gas fee accounting bypass via base-fee truncation to zero in `CalculateGasCost` — free UEA/CEA payload execution when actual base fee is below 1 upc-per-gas unit ([File: x/uexecutor/keeper/fees.go])

### Summary
`CalculateGasCost` (called from `DeductGasFeesFromReceipt`, which gates fee billing for every UEA/CEA payload execution path — `ExecutePayloadV2`, `ExecuteInboundFundsAndPayload`, `ExecuteInboundGasAndPayload`, `ExecutePayload`) truncates the on-chain `baseFee` via integer division by `1e18` before using it as the effective gas price. If the truncated value is `0`, `gasCost` becomes `0` and `DeductGasFeesFromReceipt` explicitly treats that as "nothing to bill" (`gasCost.Sign() <= 0 { return nil }`), skipping fee collection entirely even though real EVM gas (`receipt.GasUsed`) was consumed. This mirrors the M-13 pattern: a derived ratio/quantity that legitimately should reflect real economic activity collapses to zero under an edge condition, and the zero value is then trusted to mean "no cost," which favors the executing party.

### Finding Description
`x/uexecutor/keeper/fees.go`:

```go

    baseFee sdkmath.LegacyDec,
    maxFeePerGas *big.Int,
    maxPriorityFeePerGas *big.Int,
    gasUsed uint64,

    baseFeeBig := baseFee.BigInt()
    baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
    ...
    effectiveGasPrice := new(big.Int).Set(baseFeeBig)
    gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

``` [1](#0-0) 

`baseFee.BigInt()` returns the raw internal `LegacyDec` representation, which is already scaled by `1e18` for its own fixed-point decimal precision — this is a separate scale from any "upc has 18 decimals" assumption. The code assumes the two `1e18` factors coincide (i.e., that the fee-market's base fee value, once expressed as an integer count of `upc`, is always ≥ 1). If the network's actual base fee (in wei-equivalent units) is set below `1e18` at the raw-Dec level — which corresponds to an extremely low but non-zero fee-market base fee, achievable during low-congestion periods, at genesis, right after a base-fee-lowering adjustment, or via legitimate feemarket mechanics driving the fee down toward its floor — the integer division silently truncates `baseFeeBig` to `0`.

That zero then flows into `effectiveGasPrice = 0`, so `gasCost = effectiveGasPrice * gasUsed = 0`. `DeductGasFeesFromReceipt` treats `gasCost.Sign() <= 0` as a legitimate "no fee owed" case and returns `nil` without ever calling `DeductAndBurnFees`:

This function gates every payload-execution accounting path that spends real EVM gas on behalf of a UEA/CEA — `ExecutePayloadV2` (direct universal-payload execution), `ExecuteInboundFundsAndPayload`, `ExecuteInboundGasAndPayload` (smart-contract/isCEA branch), and `ExecutePayload` via `MsgExecutePayload`: [3](#0-2) [4](#0-3) [5](#0-4) 

An unprivileged attacker who submits a `UniversalPayload` for execution when the chain's `baseFee` happens to sit under the truncation threshold gets their `executeUniversalTx`/`ExecuteUEAPayload` EVM call fully executed — consuming real network gas, storage writes, and validator compute — while paying `0 upc` in gas fees. This is a direct "corruption of gas fee accounting" reachable purely from ordinary user payload submission (in-scope impact category), with no privileged assumption required; it only depends on network-observable base-fee state.

### Impact Explanation
Every legitimate payload execution is supposed to bill the executing account for `gasUsed * effectiveGasPrice`. When the truncation collapses this to zero, the protocol loses gas-fee revenue on that execution while still paying the real infrastructure/validator cost of running the EVM call, and the recipient/executor gets unlimited free execution during any block where truncation applies. Since `baseFee` is a chain-wide value (not attacker-controlled directly, but externally observable and something an attacker can simply wait for or that can occur transiently under normal feemarket dynamics), this is systematically exploitable by any user who monitors the current base fee and times payload submissions accordingly — a repeatable, low-effort "free execution" primitive. This matches the "corruption of gas fee accounting" and "unauthorized module-originated EVM execution without paying for it" impact categories explicitly listed as in-scope.

### Likelihood Explanation
Likelihood depends on how low the feemarket's `baseFee` can realistically go under the deployed `x/feemarket` parameters (min base fee, elasticity, adjustment rate). Push Chain's own tests hard-code `baseFee = 1_000_000_000_000_000_000` (`1e18`, i.e., non-truncating) in the test harness, which shows the team engineers around a "safe" magnitude and never exercises the low-base-fee boundary in tests: [6](#0-5) 
I could not verify from the available index what the production `MinGasPrice`/base-fee floor parameter is configured to in mainnet genesis, nor whether the feemarket's minimum base fee is bounded well above `1e18` at all times (which would make this unreachable in practice). This is the key uncertainty: if the protocol enforces a feemarket-level minimum base fee that always exceeds `1e18` in its internal Dec representation, this specific truncation path is unreachable; if the floor can go below that (e.g., during a fee-market misconfiguration, aggressive minimum-price reduction via governance, or an initial/degenerate genesis state), the bug is trivially and repeatably triggerable by any user.

### Recommendation
- Do not silently treat a computed `gasCost == 0` as "no fee owed" when `receipt.GasUsed > 0` and `baseFee` is nonzero at its native (un-truncated) precision. Perform the gas-cost multiplication in the Dec's native fixed-point representation (or use `sdkmath.LegacyDec` multiplication) and round up (ceil) when converting to the integer `upc` amount, instead of truncating `baseFee` down to an integer number of `upc` before multiplying.
- Add an explicit guard/error (not a silent `return nil`) when the computed effective gas price is `0` despite `baseFee.IsPositive()`, since that indicates a rounding/precision bug rather than a legitimate free transaction.
- Add unit tests for `CalculateGasCost` with `baseFee` values below `1e18` (in the Dec's internal representation) to confirm fees are still correctly charged (proportionally) rather than truncated to zero.

### Proof of Concept
1. Set (or wait for) the feemarket's `baseFee` such that `baseFee.BigInt()` (the raw `LegacyDec` big.Int, itself `1e18`-scaled) is less than `1e18`, e.g. `baseFee = sdkmath.LegacyNewDecFromBigInt(big.NewInt(5e17))` (equivalent to `0.5` upc-per-gas in the intended semantics).
2. Submit a `MsgExecutePayload` (or trigger a `FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` inbound with `IsCEA=true`) whose `UniversalPayload` executes non-trivial EVM logic (e.g., `SSTORE`) with `MaxFeePerGas` set high enough to pass the `maxFeePerGas.Cmp(baseFeeBig) < 0` check (note `baseFeeBig` is already truncated to `0` at that comparison point, so any non-negative `maxFeePerGas` passes).
3. Observe in `CalculateGasCost`: `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` yields `0`; `effectiveGasPrice = 0`; `gasCost = 0 * gasUsed = 0`.
4. In `DeductGasFeesFromReceipt`, `gasCost.Sign() <= 0` is true, so the function returns `nil` without calling `DeductAndBurnFees` — the recipient's `upc` balance is unchanged despite `receipt.GasUsed > 0`, confirmed by comparing pre/post balances (analogous to the existing rollback test at `test/integration/uexecutor/inbound_cea_smart_contract_test.go:373-472`, but here the payload succeeds and fees are still skipped because `gasCost == 0`, not because of insufficient balance).

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}
