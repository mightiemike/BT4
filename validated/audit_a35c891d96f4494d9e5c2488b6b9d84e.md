## Analysis

The C4 bug is about a single owner-controlled *mutable pointer* (`liquidityPool`) that in-flight user funds implicitly depend on: once users deposit against the old pointer value, an owner call that repoints it — with no migration path — breaks their ability to withdraw, though the loss is only temporary/recoverable (severity downgraded to Medium) because the old value can be reinstated.

The closest reachable analog in `nearcore` is the **`GlobalContractDeployMode::AccountId`** mechanism for global contracts.

### Title
Global contract redeploy under `AccountId` mode instantly and unilaterally repoints code for all referencing accounts with no migration guard - (File: `runtime/runtime/src/global_contracts.rs`)

### Summary
`DeployGlobalContractAction` with `GlobalContractDeployMode::AccountId` lets the deploying account redeploy new WASM code under its own `AccountId` identifier at any time. Every account that previously bound itself to that identifier via `UseGlobalContractAction`/`AccountContract::GlobalByAccount` automatically starts executing the new code the next time it is called — there is no versioning pin, consent mechanism, or migration path for the "consumer" accounts, mirroring the C4 finding's mutable, unguarded `liquidityPool` pointer.

### Finding Description
`GlobalContractDeployMode` explicitly documents this behavior: `CodeHash` mode is immutable, but `AccountId` mode "allows the owner to update the contract for all its users" [1](#0-0) . `action_deploy_global_contract` performs this redeploy as a normal action with no restriction beyond storage-cost accounting, and dispatches a distribution receipt that overwrites the code stored at `TrieKey::GlobalContractCode { identifier: AccountId(...) }` on every shard [2](#0-1) . Consuming accounts reference this identifier indirectly through `AccountContract::GlobalByAccount(id)`, set once via `use_global_contract` and never re-validated against a specific code version afterward [3](#0-2) ; `apply_distribution_current_shard` simply overwrites the trie entry for that identifier when a fresher nonce arrives [4](#0-3) . Because the referencing account's own per-account contract storage (`TrieKey::ContractData`) is left untouched by a redeploy, any application-level ledger the *old* code maintained there (e.g., internal balances, escrowed deposits, allowances) can become undecodable or semantically reinterpreted by the *new* code, with no built-in migration step — precisely the "changing a pointer that already-committed funds depend on, without a migration mechanism" defect pattern from the report. As in the original, the damage is not necessarily permanent: the owner can redeploy the old, compatible code again to restore access, matching the same "acknowledged/downgraded to Medium" reasoning in the source report.

### Impact Explanation
If a global contract deployed in `AccountId` mode is used by other accounts to manage user funds/token balances tracked in per-account contract storage, an unmonitored or malicious redeploy by the owning account can instantly and globally break every consuming account's ability to correctly execute withdrawal/accounting logic, effectively freezing user-held value inside those accounts until a compatible version is redeployed. This is a real risk unique to `nearcore`'s global-contract feature, reachable purely through ordinary `DeployGlobalContractAction`/`UseGlobalContractAction` transactions, with no additional privilege beyond being the deploying account.

### Likelihood Explanation
The likelihood is moderate: `AccountId` mode is explicitly marketed as mutable/upgradable (the alternative `CodeHash` mode is provided specifically for immutability), so any application built on `AccountId`-mode global contracts inherits this risk by design; existing tests only validate that redeploys successfully propagate new logic to consumers, not that consumers are protected from incompatible upgrades [5](#0-4) .

### Recommendation
For applications relying on `GlobalContractDeployMode::AccountId`, provide/require an explicit versioning and migration mechanism (e.g., binding consumer accounts to a specific code hash/nonce rather than a mutable `AccountId`, or requiring a compatibility check before overwriting), and document prominently that `AccountId`-mode global contracts carry the same "no migration, owner can break consumers" risk class as centrally-pointed liquidity pools.

### Proof of Concept
1. Account `A` deploys contract `V1` via `DeployGlobalContractAction{ deploy_mode: AccountId }` [6](#0-5) .
2. Accounts `B`, `C` call `UseGlobalContractAction{ contract_identifier: AccountId(A) }`, binding their `AccountContract` to `GlobalByAccount(A)` and building up application state in their own `ContractData` trie entries [3](#0-2) .
3. Account `A` redeploys incompatible code `V2` under the same `AccountId` mode; the distribution receipt overwrites the shared code for identifier `AccountId(A)` on all shards [4](#0-3) .
4. `B` and `C` now execute `V2` against their pre-existing `V1`-formatted storage; if `V2`'s deserialization/logic is incompatible, their funds/ledger entries tracked in that storage become inaccessible through the contract's public methods until `A` redeploys `V1` again — mirroring the reported "temporary but real fund-freeze" outcome.

pub(crate) fn action_deploy_global_contract(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    apply_state: &ApplyState,
    deploy_contract: &DeployGlobalContractAction,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let _span = tracing::debug_span!(target: "runtime", "action_deploy_global_contract").entered();

    let storage_cost = apply_state
        .config
        .fees
        .storage_usage_config
        .global_contract_storage_amount_per_byte
        .saturating_mul(deploy_contract.code.len() as u128);
    let Some(updated_balance) = account.amount().checked_sub(storage_cost) else {
        result.result = Err(ActionErrorKind::LackBalanceForState {
            account_id: account_id.clone(),
            amount: storage_cost,
        }
        .into());
        return Ok(());
    };
    result.tokens_burnt =
        result.tokens_burnt.checked_add(storage_cost).ok_or(IntegerOverflowError)?;
    account.set_amount(updated_balance);

    initiate_distribution(
        state_update,
        account_id.clone(),
        deploy_contract.code.clone(),
        &deploy_contract.deploy_mode,
        apply_state.shard_id,
        result,
    )?;

    Ok(())
}

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };
    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract);
    Ok(())
}

fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())
}

fn apply_distribution_current_shard(
    receipt: &Receipt,
    global_contract_data: &GlobalContractDistributionReceipt,
    apply_state: &ApplyState,
    state_update: &mut TrieUpdate,
) -> Result<Compute, RuntimeError> {
    let identifier = match &global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => GlobalContractCodeIdentifier::CodeHash(*hash),
        GlobalContractIdentifier::AccountId(account_id) => {
            GlobalContractCodeIdentifier::AccountId(account_id.clone())
        }
    };

    let is_nonce_fresh = check_and_update_nonce(global_contract_data, &identifier, state_update)?;
    if !is_nonce_fresh {
        return Ok(0);
    }

    let config = apply_state.config.wasm_config.clone();
    let trie_key = TrieKey::GlobalContractCode { identifier };
    let code_len = global_contract_data.code().len() as u64;
    state_update.set(trie_key, global_contract_data.code().to_vec());
    state_update.commit(StateChangeCause::ReceiptProcessing { receipt_hash: receipt.get_hash() });
    let code_hash = match global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => Some(*hash),
        GlobalContractIdentifier::AccountId(_) => None,
    };
    precompile_contract_with_warming(
        &ContractCode::new(global_contract_data.code().to_vec(), code_hash),
        config,
        apply_state.next_wasm_config.clone(),
        apply_state.cache.as_deref(),
    );
    near_vm_runner::report_metrics(apply_state.shard_id, "global_contract");
    let fees = &apply_state.config.fees;
    let per_byte_total = fees
        .deploy_global_contract_execution_per_byte
        .checked_mul(code_len)
        .ok_or(IntegerOverflowError)?;
    let compute = fees
        .deploy_global_contract_execution_base
        .checked_add(per_byte_total)
        .ok_or(IntegerOverflowError)?;
    Ok(compute)
}
