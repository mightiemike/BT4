## Analysis

The Illuminate bug is: a fee amount is computed and deducted, but never written into a persistent, reclaimable ledger entry (`fees[u]`), so once the "happy path" transfer step fails or is skipped, the value is effectively stranded with no fallback accounting to recover it later.

The closest scoped analog in this repo is in the excess-gas-refund flow of `x/uexecutor/keeper/outbound.go`, specifically `applyGasRefund`.

### Finding

`applyGasRefund` computes the excess gas amount (`gasFee - gasFeeUsed`) held by `UniversalCore` after an outbound completes, and tries to pay it to `refundRecipient` — which defaults to `outbound.Sender`, or (attacker-controlled) `outbound.RevertInstructions.FundRecipient` if set: [1](#0-0) 

It first tries a swap-based refund, and on failure falls back to a direct PRC20 deposit: [2](#0-1) 

If **both** attempts fail (e.g. `CallUniversalCoreRefundUnusedGas` reverts because the recipient is a contract that reverts on receiving the PRC20, or is otherwise incompatible), the code simply records:

```go
refundPcTx.Status = "FAILED"
refundPcTx.ErrorMsg = err.Error()
...
outbound.PcRefundExecution = refundPcTx
outbound.RefundSwapError = swapFallbackReason
``` [3](#0-2) 

`applyGasRefund` is invoked exactly once per outbound, from `handleSuccessfulOutbound` and `handleFailedOutbound`, both of which are one-shot terminal handlers reached only when `FinalizeOutbound` observes `Status_OBSERVED`: [4](#0-3) [5](#0-4) 

There is no `fees[u]`-style persistent ledger for unclaimed refunds and no retry mechanism anywhere in the codebase — searches for `RetryRefund`, `FeePool`, and similar patterns return nothing beyond this single attempt path. Once `refundPcTx.Status = "FAILED"` is written, the excess-gas amount that already exists as balance inside `UniversalCore` is never revisited by any subsequent keeper logic; it is only visible as an error string (`RefundSwapError`) on a terminal outbound record.

Because `outbound.Sender`/`RevertInstructions.FundRecipient` originate from attacker-influenced inbound/outbound data (the source-chain sender or an explicit fund-recipient field the payload creator can set), an attacker can deliberately choose a `refundRecipient` that reverts on token receipt (e.g., a Push-chain contract address with no fallback compatible with the PRC20's `transfer`/hook semantics), guaranteeing both the swap and no-swap refund attempts fail. This permanently stalls this specific excess-gas amount inside `UniversalCore` with no code path to reclaim it — an unprivileged, attacker-triggerable, permanent-loss condition, matching the structural root cause of the Illuminate finding (fee value computed but never captured in a durable, reclaimable accounting record).

### Caveats
- This causes loss of the **excess gas refund amount only** (bounded by `gasFee - gasFeeUsed`), not the full bridged principal — the bridged funds revert path (`CallPRC20Deposit`) is separate and, on failure, correctly falls back to `AbortOutbound` for manual intervention, unlike the refund path.
- Whether this rises to "material impact" depends on typical excess-gas magnitudes vs. bridged amounts; it is a real but narrower-value permanent-freezing bug than a full fund-drain. [6](#0-5)

func (k Keeper) FinalizeOutbound(ctx context.Context, utxId string, outbound types.OutboundTx) error {
	// If not observed yet, do nothing
	if outbound.OutboundStatus != types.Status_OBSERVED {
		return nil
	}

	obs := outbound.ObservedTx
	if obs == nil {
		return nil
	}

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Info("finalizing outbound",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"success", obs.Success,
		"dest_chain", outbound.DestinationChain,
		"tx_type", outbound.TxType.String(),
	)

	if !obs.Success {
		return k.handleFailedOutbound(sdkCtx, utxId, outbound, obs)
	}

	return k.handleSuccessfulOutbound(sdkCtx, utxId, outbound, obs)
}

	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
