### Title
PoisonMicroblock proof accepts an ECDSA-malleable "twin" signature of the *same* message as proof of miner double-signing - (`stackslib/src/chainstate/stacks/db/transactions.rs`)

### Summary
`check_microblock_header_signer` and `StacksMicroblockHeader::check_recover_pubkey` recover the signer's `Hash160` using `recover_to_pubkey_without_validating_low_s`, which accepts both the canonical low-S signature and its high-S malleable twin `(r, n-s)` for the exact same message digest. Because the digest is computed from the header with signature stripped (`version`, `sequence`, `prev_block`, `tx_merkle_root` only), an attacker who has ever seen one broadcast microblock header+signature from a miner can derive a second, syntactically distinct `StacksMicroblockHeader` (same content, mutated signature bytes) that recovers to the identical `pubkh`, and submit it as `PoisonMicroblock(h1, h2)`.

### Finding Description
The equality the protocol is supposed to enforce is: *"poison report accepted" == "miner produced two distinct, actually broadcast microblocks at the same sequence"*. The actual code only checks a weaker equality: *`check_recover_pubkey(h1) == check_recover_pubkey(h2)` AND `h1.sequence == h2.sequence` AND `h1.prev_block == h2.prev_block` AND `h1.version == h2.version` AND `h1 != h2` (bytewise)*.

- `StacksMicroblockHeader::check_recover_pubkey` (`stacks-codec/src/transaction.rs:2598-2616`) serializes the header with the signature zeroed out to build the digest, then calls `StacksPublicKey::recover_to_pubkey_without_validating_low_s` [1](#0-0) . This recovery function explicitly skips the low-S canonicalization check [2](#0-1) , so both `(r, s)` and its ECDSA-malleable twin `(r, n-s)` (with the complementary recovery id) recover to the same public key for the same digest.
- `check_microblock_header_signer` (`stackslib/src/chainstate/stacks/db/transactions.rs:686-713`) only compares the two recovered `pkh`s; it never inspects `tx_merkle_root` or otherwise confirms the headers encode genuinely different message content [3](#0-2) .
- The mempool admission check (`stackslib/src/chainstate/stacks/db/blocks.rs:6844-6867`) requires `sequence`, `prev_block`, and `version` to be *equal* between the two headers (which is trivially true for the malleable twin, since these fields are untouched) and requires `pkh1 == pkh2`; it never requires `tx_merkle_root` to differ [4](#0-3) .
- The only defense found at the codec layer is a bytewise-equality guard rejecting a payload where the two headers are byte-for-byte identical ("microblock headers match") and a guard requiring `sequence`/`prev_block` to be consistent ("do not identify a fork") [5](#0-4) . Neither guard requires the *message content* (`tx_merkle_root`) to differ, so a header that differs *only* in its (malleable) signature bytes passes both checks.
- `handle_poison_microblock` (`stackslib/src/chainstate/stacks/db/transactions.rs:722-857`) trusts `check_microblock_header_signer`'s result and proceeds directly to recording a poison report / commission entitlement for the reporter against the miner's coinbase at the pubkey's associated block height, provided that height is still within `MINER_REWARD_MATURITY` [6](#0-5) .

Exploit flow: attacker observes any one broadcast, signed `StacksMicroblockHeader` `h1` from a miner (public data). Since the signed digest only covers `version/sequence/prev_block/tx_merkle_root`, the attacker computes the malleable twin signature `sig' = (r, n-s, recovery_id')` for that same digest and builds `h2 = h1` with `signature = sig'`. `h1 != h2` (raw bytes differ due to the signature), but `check_recover_pubkey(h1) == check_recover_pubkey(h2)`, and `sequence/prev_block/version` are identical by construction. Submitting `PoisonMicroblock(h1, h2)` passes mempool admission, codec validation, and `handle_poison_microblock`, even though the miner never signed two distinct microblocks.

### Impact Explanation
This breaks the fundamental slashing invariant that a `PoisonMicroblock` proof implies the target actually equivocated (signed two different microblocks at the same sequence). An attacker can fabricate a false-positive poison report against any miner whose microblock pubkey-hash is still within its `MINER_REWARD_MATURITY` window, causing the honest miner's coinbase commission to be diverted to the attacker/reporter. This is block-reward theft/mis-payment triggered by an unprivileged, non-colluding party using only public broadcast data, matching the Critical reward-theft category.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only one publicly broadcast, validly signed `StacksMicroblockHeader` from the target miner (obtainable from any node that relayed it) and standard offline ECDSA signature-malleability arithmetic (no private key, no majority stake, no node compromise). The attack costs only the fee for submitting a `PoisonMicroblock` transaction and is repeatable against any miner/microblock signature the attacker can observe while its pubkey-hash height has not matured out.

### Recommendation
Enforce canonical (low-S) signature verification when recovering public keys for poison-microblock purposes — i.e., use the `verify_low_s = true` path (`recover_to_pubkey_possibly_with_low_s_verification`) instead of `recover_to_pubkey_without_validating_low_s` in `StacksMicroblockHeader::check_recover_pubkey`/`check_microblock_header_signer`, and additionally require that the two headers differ in actual signed content (e.g., `tx_merkle_root`), not merely in signature bytes, before accepting a `PoisonMicroblock` payload at the codec/mempool/`handle_poison_microblock` layers.

### Proof of Concept
Rust integration test plan (e.g., in `stackslib/src/chainstate/stacks/db/transactions.rs` test module):
1. Generate a `StacksPrivateKey`/`StacksPublicKey` pair, compute `pubkh`, and insert it via `StacksChainState::insert_microblock_pubkey_hash` at some height, as in `process_poison_microblock` tests.
2. Build a single legitimately signed `StacksMicroblockHeader h1` with `sign(&privk)` (this is the "one broadcast microblock" the attacker observes).
3. Recover `h1.signature`'s `(r, s, v)` via `to_secp256k1_recoverable`; compute the malleable twin `s' = n - s` and flipped recovery id `v' = v ^ 1`; construct `sig'` and build `h2 = h1.clone()` with `signature = sig'` (leaving `version/sequence/prev_block/tx_merkle_root` untouched).
4. Assert `h1 != h2` (raw struct inequality) while `h1.check_recover_pubkey().unwrap() == h2.check_recover_pubkey().unwrap() == pubkh`.
5. Build and sign a `TransactionPayload::PoisonMicroblock(h1.clone(), h2.clone())` transaction from an unrelated reporter key, and run it through `StacksChainState::process_transaction`.
6. Assert on both sides of the equality: the *broken* side is `handle_poison_microblock` returning `Ok(..)` and `get_poison_microblock_report` recording a slash/commission entry against the miner despite the miner having produced only one microblock; the *correct* side (post-fix) should be `Err(Error::InvalidStacksTransaction(...))` due to failed low-S verification and/or absence of content divergence.

    pub fn check_recover_pubkey(&self) -> Result<Hash160, AuthError> {
        let mut bytes = vec![];
        self.serialize(&mut bytes, true)
            .expect("BUG: failed to serialize to a vec");
        let digest = Sha512Trunc256Sum::from_data(&bytes[..]);

        let mut pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            digest.as_bytes(),
            &self.signature,
        )
        .map_err(|_ve| {
            AuthError::VerifyingError(
                "Failed to verify signature: failed to recover public key".to_string(),
            )
        })?;

        pubk.set_compressed(true);
        Ok(Hash160::from_node_public_key(&pubk))
    }

    fn recover_to_pubkey_possibly_with_low_s_verification(
        msg: &[u8],
        sig: &MessageSignature,
        verify_low_s: bool,
    ) -> Result<Secp256k1PublicKey, &'static str> {
        _secp256k1.with(|ctx| {
            let msg = LibSecp256k1Message::from_slice(msg).map_err(|_e| {
                "Invalid message: failed to decode data hash: must be a 32-byte hash"
            })?;

            let secp256k1_sig = sig
                .to_secp256k1_recoverable()
                .ok_or("Invalid signature: failed to decode recoverable signature")?;

            if verify_low_s {
                let secp256k1_sig_standard = secp256k1_sig.to_standard();
                let mut secp256k1_sig_low_s = secp256k1_sig_standard;
                secp256k1_sig_low_s.normalize_s();
                if secp256k1_sig_low_s != secp256k1_sig_standard {
                    return Err("Invalid signature: high-S");
                }
            }

            let recovered_pubkey = ctx
                .recover_ecdsa(&msg, &secp256k1_sig)
                .map_err(|_e| "Invalid signature: failed to recover public key")?;

            Ok(Secp256k1PublicKey {
                key: recovered_pubkey,
                compressed: true,
            })
        })

    fn check_microblock_header_signer(
        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
