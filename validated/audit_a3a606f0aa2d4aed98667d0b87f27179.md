### Title
Non-atomic check-then-act race in JWT replay cache allows single-use token to authorize two concurrent workflow executions - ([File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go])

### Summary
`WorkflowMetadataHandler.Authorize` checks `jwtCache.isReplay(claims.ID)` and later calls `jwtCache.recordUsage(claims.ID)` as two separate, independently-locked operations rather than a single atomic check-and-set. Two goroutines racing through `httpTriggerHandler.authorizeRequest` with the same JWT can both pass `isReplay` before either calls `recordUsage`, both being treated as valid single-use authorizations for the same signed request.

### Finding Description
`Authorize` in `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go` performs: [1](#0-0) 

The replay guard itself is implemented as two independently-locked methods: [2](#0-1) 

`isReplay` takes an `RLock`, reads, and releases the lock; `recordUsage` is only invoked later, after the workflow-ID lookup and signer-authorization checks pass, and takes its own separate `Lock`. There is no single critical section covering "check jti unseen" + "mark jti seen" for a given `Authorize` call. This is invoked from `httpTriggerHandler.authorizeRequest`, which is reachable from `HandleUserTriggerRequest` on every incoming `workflow.execute` HTTP trigger request: [3](#0-2) 

If two goroutines call `Authorize` with the same token concurrently (e.g., two near-simultaneous HTTP requests carrying the identical JWT, replayed by an unprivileged attacker who captured/observed it, or duplicated by a retrying/misbehaving client), both can execute `isReplay(claims.ID)` before either executes `recordUsage(claims.ID)`, since these calls do not share a lock and there is significant intervening work (workflow-ID map lookup, signer-in-allowlist check) between them. Both calls will observe `exists == false`, both will pass the signer-authorization check, and both will subsequently call `recordUsage`, meaning both `Authorize` calls succeed and return a valid `*gateway.AuthorizedKey`. This directly contradicts the single-use invariant that the same code documents and tests for sequential (non-concurrent) replay: [4](#0-3) 

That test only proves sequential replay is blocked; it does not exercise concurrent racing calls, so the TOCTOU gap is not covered. This contrasts with the sibling `vault` package's `RequestReplayGuard.CheckAndRecord`, which correctly performs the check-and-record under a single mutex acquisition: [5](#0-4) 

and which has an explicit concurrency test proving exactly one of N concurrent identical requests succeeds: [6](#0-5) 

`jwtReplayCache` lacks an equivalent atomic primitive.

### Impact Explanation
A single valid, signed JWT for a workflow-execute request can be used to trigger duplicate execution of the same workflow trigger by racing two concurrent requests before the first's `recordUsage` call commits. This matches the described "unauthorized duplicate workflow execution using a single authorized signature" — an integrity/replay-protection bypass on the gateway's HTTP trigger authorization path, potentially causing duplicate on-chain/workflow side effects (double execution of workflow logic triggered by capability nodes) despite the signer only having authorized one such execution via one JWT (`jti`).

### Likelihood Explanation
The attacker needs no special privilege beyond possessing (or replaying/duplicating) one previously-issued, still-valid JWT — e.g., an unprivileged network attacker capable of duplicating an in-flight HTTP request (common with retrying clients/proxies, or intentional double-send by an attacker who intercepts/observes the token before its holder submits it). The race window (between `isReplay` and `recordUsage`, spanning a map lookup and an authorization check) is small but real, and is fully attacker-triggerable by firing two requests back-to-back; no timing manipulation of the server is required, only ordinary network-level concurrency. This is a genuine, reproducible TOCTOU bug rather than a purely theoretical one.

### Recommendation
Make the JWT replay check-and-record atomic: add a single method (e.g., `checkAndRecord(jti string) bool`) on `jwtReplayCache` that takes a single `Lock()`, checks `cache[jti]` existence, and if absent inserts it, returning whether the jti was newly recorded, all inside one critical section. Call this atomic method from `Authorize` instead of separate `isReplay` + `recordUsage` calls (moving the atomic reservation earlier, before or fused with the authorization checks, so the jti is claimed exactly once regardless of interleaving). Alternatively, add a per-workflow or global mutex serializing `Authorize` calls sharing the same `jti`.

### Proof of Concept
Add a concurrency test in `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler_test.go` modeled on `vault`'s `TestRequestReplayGuard_ConcurrentAccess`:

1. Set up a `WorkflowMetadataHandler` with one authorized signer/workflow (as in `TestWorkflowMetadataHandler_Authorize`).
2. Create one signed JWT (`utils.CreateRequestJWT` + `SignedString`) for a fixed request.
3. Launch N (e.g., 50) goroutines that all call `handler.Authorize(workflowID, tokenString, req)` concurrently with the same token, and add a small `sync.WaitGroup`/barrier to maximize simultaneous entry.
4. Collect results; assert that `sum(success) == 1` and `sum(errors containing "already been used") == N-1`.
5. Expected today: due to the non-atomic `isReplay`/`recordUsage` gap, the test will intermittently show `sum(success) > 1`, demonstrating the double-spend; after the fix (atomic check-and-set), exactly one success is guaranteed under `go test -race -count=100`.

func (h *WorkflowMetadataHandler) Authorize(workflowID string, token string, req *jsonrpc.Request[json.RawMessage]) (*gateway.AuthorizedKey, error) {
	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

func (g *RequestReplayGuard) CheckAndRecord(digest string, expiresAtUnix int64) error {
	g.mu.Lock()
	defer g.mu.Unlock()

	g.clearExpiredLocked()

	if _, exists := g.seen[digest]; exists {
		return ErrRequestAlreadySeen
	}

	g.seen[digest] = expiresAtUnix
	return nil
}

func TestRequestReplayGuard_ConcurrentAccess(t *testing.T) {
	guard := NewRequestReplayGuard()
	futureExpiry := time.Now().UTC().Unix() + 100

	const goroutines = 100
	results := make([]error, goroutines)
	var wg sync.WaitGroup
	wg.Add(goroutines)

	for i := range goroutines {
		go func(idx int) {
			defer wg.Done()
			results[idx] = guard.CheckAndRecord("same-digest", futureExpiry)
		}(i)
	}
	wg.Wait()

	successCount := 0
	duplicateCount := 0
	for _, err := range results {
		if err == nil {
			successCount++
		} else {
			require.ErrorIs(t, err, ErrRequestAlreadySeen)
			duplicateCount++
		}
	}

	assert.Equal(t, 1, successCount, "exactly one goroutine should succeed")
	assert.Equal(t, goroutines-1, duplicateCount, "all others should be rejected as duplicates")
}
