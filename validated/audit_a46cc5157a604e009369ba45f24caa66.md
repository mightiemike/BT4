### Title
Spot-price Uniswap V3 quote used as slippage guard for automatic PRC20→WPC deposit swaps enables sandwich extraction on gas-abstraction inbounds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The external report describes an LP-pricing oracle that trusts manipulable spot reserves with no TWAP protection. Push Chain's universal-execution GAS / GAS_AND_PAYLOAD inbound flow, and the outbound gas-refund flow, contain the same class of bug: `GetSwapQuote` fetches a **spot** quote from the on-chain Uniswap V3 `QuoterV2.quoteExactInputSingle` immediately before executing the actual swap, and derives the only slippage protection (`minPCOut = quote * 95/100`) from that same manipulable spot value, in the same block/transaction as the swap itself.

### Finding Description
`Keeper.GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` against the current pool state (a normal Uniswap V3 pool, not a TWAP oracle): [1](#0-0) 

This quote is used directly to compute `minPCOut` with a flat 5% haircut, then passed straight into the actual swap call in all three call sites:

- Gas-only inbound: `x/uexecutor/keeper/execute_inbound_gas.go` lines 104-153, where `GetSwapQuote` is called and `minPCOut` is derived, then `CallPRC20DepositAutoSwap` executes the swap in the same keeper call. [2](#0-1) 
- Gas+payload inbound: `gasAndPayloadDepositAutoSwap` in `execute_inbound_gas_and_payload.go`. [3](#0-2) 
- Outbound excess-gas refund: `applyGasRefund` / `getSwapQuoteForRefund` in `outbound.go`. [4](#0-3) 

In all three, the "protection" (`minPCOut`) is computed from the exact same spot price that the swap will execute against, at the exact same block height, with no TWAP, no external price reference, and no check that the spot price is itself undistorted. This is architecturally identical to the reported `BondSteerOracle._currentPrice` flaw: using instantaneous reserve-derived price both to price the asset and to bound the resulting execution, which an attacker can move immediately beforehand.

Because the underlying WPC/PRC20 Uniswap V3 pool lives on Push Chain's own EVM state, any unprivileged user can submit an ordinary EVM transaction that swaps a large amount against that pool to shift its spot price, then rely on the deterministic execution of a pending inbound (finalized once 2/3 of universal validators have voted, and executed automatically as part of processing that finalizing vote transaction in a block) to be included after their manipulating transaction, and finally reverse the manipulation in a subsequent transaction in the same block — the classic sandwich pattern. Because `minPCOut` is derived from the manipulated price itself rather than an independent, time-resistant reference price, it does not actually protect the swap from a moved price; it only protects against the "unaffected" execution deviating from the poisoned quote.

### Impact Explanation
An attacker who is themselves the depositor (or who colludes with/observes a pending deposit) can:
1. Move the pool price to inflate the PRC20→WPC exchange rate immediately before their own gas-abstraction deposit inbound is finalized and auto-swapped.
2. Let the swap execute against the inflated price, extracting more WPC/PC than the deposit is genuinely worth, at the expense of the pool's liquidity (protocol-owned or third-party LPs).
3. Reverse their manipulating trade afterward to realize the arbitrage profit.

This is an unprivileged-attacker-reachable drain of protocol/pool-controlled funds through the universal execution path (`x/uexecutor` deposit-auto-swap and gas-refund paths), matching the in-scope impact "stealing... draining... unauthorized release... of user or protocol-controlled funds" and "corruption of PRC20 or native asset accounting... revert destination... token mapping." The same mechanism can degrade honest users' received amounts (value extraction against the depositor) if the manipulation instead depresses price while still passing the 5% slippage band.

### Likelihood Explanation
Likelihood depends on: (a) the manipulator's ability to reliably land a manipulating transaction immediately before the ballot-finalizing transaction that triggers the auto-swap within the same block (mempool-visibility/gas-priority dependent, similar to ordinary MEV sandwiching, not requiring any validator/relayer privilege), and (b) sufficient pool depth/fee-tier liquidity for the manipulation cost to be less than the extracted value. Both are plausible on a young chain with limited PRC20/WPC pool liquidity, and this pattern is a well-known, systematically exploitable MEV vector rather than a theoretical one — it does not require a compromised or malicious validator, only an ordinary user submitting ordinary transactions.

### Recommendation
Do not derive the swap's minimum-output bound from the same call that is about to execute against the pool. Use a manipulation-resistant reference price instead:
- Use Uniswap V3's TWAP (`observe`) over a sufficiently long window instead of the instantaneous `quoteExactInputSingle` spot quote, and/or
- Enforce a maximum allowed deviation between the spot price and the TWAP before allowing the auto-swap to proceed (revert/fallback to non-swap deposit if deviation exceeds a threshold), and/or
- Add a per-block/tx sandwich resistance mechanism, such as basing `minPCOut` on a slower-moving oracle (chain-meta style aggregated price) rather than the pool being swapped against, similar in spirit to the recommended `2*sqrt(p0*p1)*sqrt(k)/L` TWAP-based fix in the original report.

### Proof of Concept
Not independently executable from static analysis (no local devnet/tooling access in this environment). The reachable code path is:
1. `GetSwapQuote` → `QuoterV2.quoteExactInputSingle(prc20, wpc, amount, fee, 0)` returns a value computed off the pool's *current* reserves/sqrtPriceX96 [1](#0-0) .
2. `minPCOut := quote * 95 / 100` is computed directly from that value [5](#0-4) .
3. `CallPRC20DepositAutoSwap(..., minPCOut)` executes the swap against the (still) manipulated pool in the same block, with no TWAP cross-check.

To confirmed exploit this, a background Devin session with access to a local devnet (`e2e-tests` setup) would be needed to: deploy/seed the WPC/PRC20 Uniswap V3 pool with realistic liquidity, submit a large swap to shift the spot price, trigger a pending gas-abstraction inbound to finalize in the same block immediately after, and measure the resulting `amountOut` vs. a fair-market baseline, then reverse the manipulating trade and compute net attacker profit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)

// getSwapQuoteForRefund fetches a Uniswap quote for the gas token refund swap.
func (k Keeper) getSwapQuoteForRefund(ctx sdk.Context, gasToken common.Address, fee *big.Int, amount *big.Int) (*big.Int, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(ctx)
	if err != nil {
		return nil, err
	}
	wpcAddr, err := k.GetUniversalCoreWPCAddress(ctx)
	if err != nil {
		return nil, err
	}
	return k.GetSwapQuote(ctx, quoterAddr, gasToken, wpcAddr, fee, amount)
}
