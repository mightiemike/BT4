**Reasoning:** `APTOS_TRANSACTION_VALIDATION` is a `Lazy` static built entirely from compile-time Rust constants — `module_addr: CORE_CODE_ADDRESS` and `module_name: Identifier::new("transaction_validation")` — not from any on-chain, governance-configurable, or user-supplied value. [1](#0-0) 

The `module_id()`, `is_account_module_abort`, and `is_transaction_limits_module_abort` helpers compare `AbortLocation` against this hardcoded `ModuleId`, with `is_account_module_abort` even including a literal fallback (`CORE_CODE_ADDRESS`/`"transaction_validation"`) independent of the struct fields. [2](#0-1) 

There is no code path by which an unprivileged transaction, package publish, API call, view function, bytecode, or proof input can alter `module_addr`/`module_name` at runtime — changing them would require editing and recompiling the validator binary itself, which is a node-software/hard-fork change under operator control, explicitly out of scope ("depends on trusted operator mistakes alone"). Since no reachable input path exists from the required entry points (transaction/package/API/view/bytecode/proof) to a divergence in this constant, the premise of the question — nodes "caching" different values due to a chain upgrade triggered by ordinary transactions — does not correspond to any actual code behavior in this file.

impl TransactionValidation {
    pub fn module_id(&self) -> ModuleId {
        ModuleId::new(self.module_addr, self.module_name.clone())
    }

    pub fn is_account_module_abort(&self, location: &AbortLocation) -> bool {
        location == &AbortLocation::Module(self.module_id())
            || location
                == &AbortLocation::Module(ModuleId::new(
                    CORE_CODE_ADDRESS,
                    ident_str!("transaction_validation").to_owned(),
                ))
    }

    pub fn is_transaction_limits_module_abort(&self, location: &AbortLocation) -> bool {
        location
            == &AbortLocation::Module(ModuleId::new(
                CORE_CODE_ADDRESS,
                ident_str!("transaction_limits").to_owned(),
            ))
    }
}
