## Analog Found

### Title
Stale Cache Bypasses Class-Declaration Validation for Cairo 0 Classes After Block Revert - (File: `crates/blockifier/src/state/state_reader_and_contract_manager.rs`)

### Summary
The ORY Oathkeeper bug (CVE-2021-32701) stems from a cache lookup that validates only one attribute of a cached decision (token expiry) while silently skipping validation of another attribute required for correctness (scope), letting a previously-authorized-for-X token be treated as authorized-for-Y. The sequencer's contract-class cache exhibits the same bug class: on a cache hit it validates "is this class still declared" only for Cairo 1 (Sierra) classes, and unconditionally skips that check for Cairo 0 (deprecated) classes, relying on an out-of-band cache-clear that is not actually performed by the production revert path.

### Finding Description
`get_compiled_from_class_manager` in [1](#0-0)  reads the process-global `contract_class_manager` cache for a `class_hash`. When the cache hit is a Cairo 1 class it re-validates against `state_reader.is_declared(class_hash)`, explicitly to defend against the case "it might contain a declared class from a reverted block" [2](#0-1) . For `RunnableCompiledClass::V0(_)` (Cairo 0 / deprecated classes) this branch is empty — no re-validation is performed at all.

This asymmetry is not accidental: `FetchCompiledClasses::is_declared` is documented to always return `false` for Cairo 0 classes [3](#0-2) , so it cannot be used to validate V0 classes — the design instead depends on the global class cache being invalidated whenever a block (and its declarations) is reverted.

That invalidation, however, is only performed in the legacy Python-bindings path: `native_blockifier`'s `revert_block` explicitly calls `self.contract_class_manager.clear()` with the comment "Clear global class cache, to properly revert classes declared in the reverted block" [4](#0-3) . Searching the production Rust node's revert paths (`apollo_batcher`, `apollo_committer`, `apollo_reverts`) shows only storage-level reverts (`revert_header`, `revert_body`, `revert_state_diff`, `revert_block_hash`, etc.) [5](#0-4)  — none of them touch the `blockifier`/`ContractClassManager` global class cache (`GlobalContractCache`) that backs `get_compiled_from_class_manager`. The cache implementation itself has no revert/invalidate hook beyond `clear()` [6](#0-5) .

Consequently, once a Cairo 0 class has been declared and cached (e.g., during normal block execution, or via a batcher-proposed block that is later reverted before commit), the cache entry survives a state revert. Because the V0 branch performs no `is_declared`-style re-check, `get_compiled_from_class_manager` will keep returning the cached, no-longer-declared Cairo 0 class to any subsequent transaction that references that class hash, entirely bypassing the "class must be currently declared" invariant.

The project's own test suite even documents the asymmetric handling: `cairo_1_cached_scenario`/`cached_but_verification_failed_after_reorg_scenario` exercise the Cairo 1 re-validation-after-reorg path, while `cairo_0_cached_scenario` explicitly expects no `is_declared` call and no failure at all [7](#0-6)  — confirming there is no reorg/revert protection for Cairo 0 classes.

### Impact Explanation
A sequencer node whose in-memory `ContractClassManager` cache still holds a Cairo 0 class from a state that has since been reverted (state_diff/declared-classes rolled back at the storage layer, but the blockifier-level global class cache untouched) will continue to execute transactions against that undeclared class. This causes:
- Honest-node divergence: nodes that have the stale cache entry execute calls against the class successfully, while nodes without it (fresh cache, or one that started after the revert) correctly reject the same transaction as referencing an undeclared class hash — producing different state transitions/committed roots for the same block.
- Unauthorized contract behavior: a contract address whose class was supposed to be reverted (undeclared) can still be invoked as if declared, effectively resurrecting logic that governance/consensus rejected via the revert.

This matches the required impact classes: wrong committed root / honest-node divergence.

### Likelihood Explanation
Requires a preceding block revert (a legitimate, non-malicious-operator event handled by the batcher/committer/reverts crates for chain-reorg or block-rejection scenarios) followed by an ordinary, unprivileged transaction (invoke/declare/deploy) referencing the previously-cached Cairo 0 class hash — no special privilege beyond submitting a normal transaction is needed to trigger execution against the stale class. The only uncertain variable is exactly which memory-resident caches get cleared in which revert code paths across the various node runtime configurations (batcher-only, full node, sequencer w/ consensus) — this could not be fully confirmed from the indexed code (no `contract_class_manager.clear()` call was found anywhere in the non-`native_blockifier`/non-`blockifier`-internal crates), which is a meaningful signal but not a complete proof for every deployment configuration.

### Recommendation
- Apply the same "verify still declared" pattern used for Cairo 1 classes to Cairo 0 classes on every cache hit in `get_compiled_from_class_manager`, using a Cairo-0-aware declaration check (e.g., extend `FetchCompiledClasses::is_declared` or add a dedicated `is_deprecated_declared` that also reads the deprecated-declared-classes table), or
- Ensure every revert code path (batcher/committer/consensus revert, not just `native_blockifier`) explicitly clears/invalidates the `ContractClassManager` global class cache, mirroring `py_block_executor::revert_block`'s `contract_class_manager.clear()`.

### Proof of Concept
1. Node declares and caches a Cairo 0 (deprecated) class `C` at class hash `H` (populates `contract_class_manager`'s `class_cache` via `set_and_compile` in `get_compiled_from_class_manager`, see [8](#0-7) ).
2. The block containing that declaration is reverted through the production revert flow (`apollo_reverts::revert_block` / batcher/committer revert), which rolls back storage-level declared-classes tables [5](#0-4)  but does not clear the in-memory `ContractClassManager` cache.
3. An unprivileged user submits a normal transaction (e.g. `invoke`) targeting a contract at address `H`/whose class hash is `H`.
4. `get_compiled_from_class_manager` finds `H` in cache as `RunnableCompiledClass::V0`, takes the empty match arm, performs no declaration re-check, and returns the class as runnable [9](#0-8)  — executing code for a class the chain state says is undeclared, while a node without the cached entry would return `StateError::UndeclaredClassHash` and reject the transaction.

    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }

use std::sync::{Arc, Mutex, MutexGuard};

use cached::{Cached, SizedCache};

use crate::core::ClassHash;

type ContractLRUCache<T> = SizedCache<ClassHash, T>;
type LockedClassCache<'a, T> = MutexGuard<'a, ContractLRUCache<T>>;

// TODO(Yoni, 1/2/2025): consider defining CachedStateReader.
/// Thread-safe LRU cache for contract classes (Sierra or compiled Casm/Native), optimized for
/// inter-language sharing when `blockifier` compiles as a shared library.
#[derive(Clone, Debug)]
pub struct GlobalContractCache<T: Clone>(pub Arc<Mutex<ContractLRUCache<T>>>);

impl<T: Clone> GlobalContractCache<T> {
    /// Locks the cache for atomic access. Although conceptually shared, writing to this cache is
    /// only possible for one writer at a time.
    pub fn lock(&self) -> LockedClassCache<'_, T> {
        self.0.lock().expect("Global contract cache is poisoned.")
    }

    pub fn get(&self, class_hash: &ClassHash) -> Option<T> {
        self.lock().cache_get(class_hash).cloned()
    }

    pub fn set(&self, class_hash: ClassHash, contract_class: T) {
        self.lock().cache_set(class_hash, contract_class);
    }

    pub fn clear(&mut self) {
        self.lock().cache_clear();
    }

    pub fn new(cache_size: usize) -> Self {
        Self(Arc::new(Mutex::new(ContractLRUCache::<T>::with_size(cache_size))))
    }
}
