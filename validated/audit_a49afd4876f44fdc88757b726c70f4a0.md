### Title
External GCS Proof-Archive Write Failure Blocks Otherwise-Valid Private Transaction Submission - (File: `crates/apollo_gateway/src/gateway.rs`)

### Summary
The bug class described in the external report is: a core, security-critical operation (`swap`) is made to hard-depend on the success of an auxiliary, non-essential external call (`AlgebraVirtualPool`), so that when the auxiliary call fails, the primary operation fails too, even though the auxiliary call has nothing to do with the correctness of the primary operation. The reachable analog in this sequencer is in the Gateway's transaction-admission path: for "client-side proving" (private) transactions, `add_tx_inner` synchronously waits on an auxiliary GCS archive write (`proof_archive_writer`) and rejects the transaction — refusing to forward it to the mempool — if that write fails or times out, even though the write is a best-effort archival copy that is not required to validate or execute the transaction.

### Finding Description
In `add_tx_inner`, after stateful validation succeeds, the gateway calls `store_proof_and_spawn_archiving`, which spawns a GCS upload (`proof_archive_writer.set_proof`) in parallel with the mandatory `store_proof_in_proof_manager` call [1](#0-0) . Before the transaction is forwarded to the mempool, the gateway calls `await_proof_archiving`, which blocks on the spawned GCS task and propagates any failure, panic, or timeout as an error, aborting `add_tx_inner` before `mempool_client.add_tx` is ever called [2](#0-1) .

`await_proof_archiving` treats a GCS write error, task panic, or timeout identically to a fatal validation failure — it returns `Err(...)`, and the caller (`add_tx_inner`) short-circuits and never reaches `self.mempool_client.add_tx(...)` [3](#0-2) . The GCS archive (`GcsProofArchiveWriter::set_proof`) is a separate storage backend from the "proof manager" that is actually required for verification; a GCS outage, misconfiguration, or elevated latency (beyond `PROOF_ARCHIVE_WRITE_TIMEOUT`) is sufficient to trigger this failure path, exactly like the AlgebraVirtualPool contract failing and blocking swaps [4](#0-3) .

This is confirmed by the existing unit test, which shows that a GCS archive failure alone (with the proof-manager store succeeding) causes the entire transaction to be rejected and never sent to the mempool: [5](#0-4) . The test scaffolding elsewhere also explicitly documents this coupling: "When archive fails the gateway must not forward the tx to the mempool" [6](#0-5) .

### Impact Explanation
Any unprivileged sender submitting a client-side-proving ("private") transaction with non-empty `proof_facts` is subject to this dependency. If the GCS archive backend (an external, non-consensus-critical service) is unavailable, rate-limiting, or slow beyond the hard timeout, all such otherwise-valid transactions are rejected at the gateway and cannot enter the mempool — the network becomes unable to confirm these new transactions, even though nothing about the transaction's validity or the state it touches is impaired. This mirrors the reported bug class: an auxiliary/optional external write, unrelated to the correctness of the primary operation, gates the primary operation and can cause a persistent denial of service for a class of transactions until the auxiliary service is restored.

### Likelihood Explanation
The path is trivially reachable by any external, unprivileged caller who submits an invoke transaction using client-side proving (non-empty `proof_facts`); no special privileges are required. The trigger condition (GCS backend errors, quota exhaustion, network partition, or elevated latency crossing `PROOF_ARCHIVE_WRITE_TIMEOUT`) is a realistic operational failure mode for any external cloud storage dependency, making this more of an availability/liveness concern than a rare edge case.

### Recommendation
Short term: do not fail `add_tx` when the GCS archive write fails or times out — log/alert (as is already done via `GATEWAY_PROOF_ARCHIVE_WRITE_FAILURE`) but still forward the transaction to the mempool, since the proof itself is already durably stored via the mandatory `store_proof_in_proof_manager` call. Long term, decouple archival entirely from the tx-admission critical path (e.g., use a best-effort background job / retry queue for GCS writes, and only treat the proof-manager store as blocking), so the sequencer's availability does not depend on an auxiliary storage backend's uptime.

### Proof of Concept
1. Submit an `RpcTransaction::Invoke` with non-empty `proof_facts` (`invoke_args_with_client_side_proving`) to the gateway.
2. Ensure `store_proof_in_proof_manager` succeeds (the mandatory proof store).
3. Simulate a GCS failure (as in `test_add_tx_fails_when_proof_archive_write_fails`) so `proof_archive_writer.set_proof` returns `Err(ProofArchiveError::WriteError(...))`.
4. Observe that `await_proof_archiving` returns an internal error and `add_tx_inner` returns before calling `mempool_client.add_tx`, per [5](#0-4) ; the transaction is never admitted to the mempool despite being fully valid and its proof already durably stored in the proof manager.

        &self,
        proof_data: Option<(ProofFacts, Proof)>,
        tx_hash: TransactionHash,
        is_p2p: bool,
    ) -> GatewayResult<ProofArchiveHandle> {
        let Some((proof_facts, proof)) = proof_data else {
            return Ok(None);
        };

        // Spawn the GCS archive write before the proof-manager store so the two run in parallel
        // — the proof-manager store is the dominant latency and there's no point serializing them.
        let archive_handle = if is_p2p {
            // Skip the GCS archive write for transactions received via P2P to avoid double writes.
            None

            let archive_proof_facts = proof_facts.clone();
            let archive_proof = proof.clone();

                let proof_facts_hash = archive_proof_facts.hash();
                let proof_archive_writer_start = Instant::now();
                let result =
                    proof_archive_writer.set_proof(archive_proof_facts, archive_proof).await;

                info!(
                    "Proof archive writer took: {proof_archive_writer_duration:?} for tx hash: \
                     {tx_hash:?}"
                );

            }))

    /// Awaits the spawned GCS archive task with a hard timeout.
    async fn await_proof_archiving(proof_archive_handle: ProofArchiveHandle) -> GatewayResult<()> {
        let Some((handle, tx_hash)) = proof_archive_handle else {
            return Ok(());
        };

        let abort_handle = handle.abort_handle();
        match timeout(PROOF_ARCHIVE_WRITE_TIMEOUT, handle).await {
            Ok(Ok((proof_facts_hash, Ok(())))) => {
                info!(
                    "Proof archived successfully. proof_facts_hash: {proof_facts_hash:?}, \
                     tx_hash: {tx_hash:?}"
                );
                Ok(())
            }
            Ok(Ok((proof_facts_hash, Err(e)))) => {
                GATEWAY_PROOF_ARCHIVE_WRITE_FAILURE.increment(1);
                Err(StarknetError::internal_with_logging(
                    &format!(
                        "Failed to archive proof to GCS. proof_facts_hash: {proof_facts_hash:?}, \
                         tx_hash: {tx_hash:?}"
                    ),
                    e,
                ))
            }
            Ok(Err(e)) => {
                GATEWAY_PROOF_ARCHIVE_WRITE_FAILURE.increment(1);
                Err(StarknetError::internal_with_logging(
                    &format!("Proof archive writer task panicked. tx_hash: {tx_hash:?}"),
                    e,
                ))
            }
            Err(elapsed) => {
                abort_handle.abort();
                GATEWAY_PROOF_ARCHIVE_WRITE_FAILURE.increment(1);
                Err(StarknetError::internal_with_logging(
                    &format!(
                        "Proof archive writer timed out after {PROOF_ARCHIVE_WRITE_TIMEOUT:?}. \
                         tx_hash: {tx_hash:?}"
                    ),
                    elapsed,
                ))
            }
        }
    }

    // TODO(Einat): Add retry mechanism.
    async fn set_proof(
        &self,
        proof_facts: ProofFacts,
        proof: Proof,
    ) -> Result<(), ProofArchiveError> {
        let client = self.client.get().expect("GCS client not connected. Call connect() first.");
        let facts_hash = proof_facts.hash();
        let proof_bytes: Vec<u8> = proof.0.iter().flat_map(|&val| val.to_be_bytes()).collect();
        let object_name = format!("proofs/{}", facts_hash);

        let result = client
            .upload_object(
                &UploadObjectRequest {
                    bucket: self.config.bucket_name.clone(),
                    // Only write if the object does not already exist.
                    if_generation_match: Some(0),
                    ..Default::default()
                },
                proof_bytes,
                &UploadType::Simple(Media::new(object_name)),
            )
            .await;

        match result {
            Ok(_) => Ok(()),
            Err(GcsError::Response(ref err)) if err.code == GCS_ERROR_CODE_PRECONDITION_FAILED => {
                // Precondition failed: object already exists. This is expected if the proof already
                // exists in the archive.
                Ok(())
            }
            Err(e) => Err(ProofArchiveError::WriteError(format!("Failed to upload to GCS: {}", e))),
        }
    }
}
