CVE-2019-11046 is a PHP bcmath extension bug where a locale-aware, OS-level "is this string numeric" check reads past the end of an allocated buffer when the string contains non-ASCII digit characters that some C library locales still classify as numeric. That bug class requires a locale-dependent, C-level numeric-string scanner reading beyond a fixed-size allocation.

protobuf-go's numeric parsing has no comparable mechanism:

- All JSON number tokens are first validated byte-by-byte against a strict ASCII grammar (`-`, `0-9`, `.`, `e`/`E`, `+`/`-`) in `parseNumber` and `parseNumberParts` before any conversion is attempted. [1](#0-0) 
- Actual numeric conversion is done exclusively via Go's standard `strconv.ParseInt`/`ParseUint`/`ParseFloat`, which are pure Go implementations operating on Go string/byte slices with bounds-checked indexing — not OS/locale-dependent C functions, and not vulnerable to reading beyond the slice. [2](#0-1) 
- Numeric strings passed via ProtoJSON (e.g., `"1234"` for an int64 field) go through `unmarshalInt`/`unmarshalUint`/`unmarshalFloat`, which re-tokenize the trimmed string through the same strict JSON number grammar and reject anything with extra/non-ASCII content (explicitly tested with inputs like `"12谷歌34"`). [3](#0-2) [4](#0-3) 
- Text-format numeric parsing (`internal/encoding/text/decode_token.go`) likewise uses `strconv.ParseInt`/`ParseFloat` on Go strings, not locale-aware C numeric detection. [5](#0-4) 

There is no locale-dependent, OS-level numeric-string classification anywhere in this codebase, no buffer over-read risk, and no analogous unsafe-memory or confidentiality-impacting sink. This is a PHP-runtime-specific bug class that doesn't map onto Go's `strconv` or protobuf-go's pre-validated number parsing.

func parseNumber(input []byte) (int, bool) {
	var n int

	s := input
	if len(s) == 0 {
		return 0, false
	}

	// Optional -
	if s[0] == '-' {
		s = s[1:]
		n++
		if len(s) == 0 {
			return 0, false
		}
	}

	// Digits
	switch {
	case s[0] == '0':
		s = s[1:]
		n++

	case '1' <= s[0] && s[0] <= '9':
		s = s[1:]
		n++
		for len(s) > 0 && '0' <= s[0] && s[0] <= '9' {
			s = s[1:]
			n++
		}

	default:
		return 0, false
	}

func unmarshalInt(tok json.Token, bitSize int) (protoreflect.Value, bool) {
	switch tok.Kind() {
	case json.Number:
		return getInt(tok, bitSize)

	case json.String:
		// Decode number from string.
		s := strings.TrimSpace(tok.ParsedString())
		if len(s) != len(tok.ParsedString()) {
			return protoreflect.Value{}, false
		}
		dec := json.NewDecoder([]byte(s))
		tok, err := dec.Read()
		if err != nil {
			return protoreflect.Value{}, false
		}
		// Ensure there is no non-number content in this string.
		if next, err := dec.Read(); err != nil || next.Kind() != json.EOF {
			return protoreflect.Value{}, false
		}
		return getInt(tok, bitSize)
	}
	return protoreflect.Value{}, false
}
