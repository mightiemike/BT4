### Title
Committed and Rejected L1 handler transaction records are never purged from `TransactionManager`, causing unbounded memory growth reachable by any L1 message sender - (File: crates/apollo_l1_events/src/transaction_manager.rs)

### Summary
`TransactionManager::records` retains an entry for every L1→L2 message ever scraped. Unlike the `Consumed` and `CancellationFinalizedOnL1` states, which are actively pruned (`clear_old_tx_from_consumed_queue`, `finalize_cancellation`), transactions that reach `TransactionState::Committed` or `TransactionState::Rejected` are never removed from `records`. Since anyone can trigger an L1→L2 message by calling the Starknet core contract on L1 (an "L1 message sender" in scope), a malicious actor can cheaply and repeatedly send L1 handler messages that get committed to L2, permanently growing the sequencer's in-memory `records` map with no eviction path — directly analogous to the reported `WithdrawRequests` array that grows forever because entries are never removed after being "claimed" (here: committed).

### Finding Description
`TransactionManager::records: Records` (an `IndexMap<TransactionHash, TransactionRecord>`) is the canonical store for every L1 handler transaction known to the provider [1](#0-0) .

Records are only removed from this map in two places:
1. `finalize_cancellation`, when an L1 cancellation is finalized [2](#0-1) .
2. `clear_old_tx_from_consumed_queue`, which purges `Consumed` transactions once `l1_handler_consumption_timelock_seconds` elapses, invoked from `consume_tx` [3](#0-2) .

However, transactions that transition to `TransactionState::Committed` via `commit_txs`/`mark_committed`, or to `TransactionState::Rejected` via `mark_rejected`, have no corresponding cleanup path anywhere in the file [4](#0-3) [5](#0-4) . The struct's own doc comment for `records` even acknowledges only cancellation/consumption as removal triggers: "keeps transactions until they can be safely removed, like when they are consumed on L1, or fully cancelled on L1" [6](#0-5) . Committed transactions are explicitly excluded from consideration ("Committing overrides cancellations" causes `update_time_based_state` to skip further transitions) [7](#0-6) , and there is no retention-window config (unlike the mempool's `committed_nonce_retention_block_count`) governing committed L1-handler records.

Since L1→L2 messages are user-controlled (any L1 account can call the messaging contract), and each accepted message eventually becomes `Committed` after inclusion in an L2 block via `commit_txs`, an attacker can continually send low-value L1 handler messages that get committed and permanently occupy memory in every sequencer node's `L1EventsProvider`/`TransactionManager`, with no bound or expiry — this is the same bug class as the reported issue: an append-only collection that is populated by repeated user calls and never shrinks even after the corresponding request has been fully "claimed"/finalized.

### Impact Explanation
Unbounded growth of `records` (and its `TransactionRecord` payloads, which include full `L1HandlerTransaction` calldata) leads to continuously increasing memory consumption on every sequencer node running the `apollo_l1_events` component. Over time this can exhaust node memory, causing crashes or severe performance degradation of the L1 events provider, which is on the critical path for block proposal/validation of L1 handler transactions (`get_txs`, `validate_tx`). A sustained OOM or crash of this component across the network could disrupt the sequencer's ability to process new L1 handler transactions and, by extension, degrade block production — a network-level denial-of-service condition, satisfying the "network unable to confirm new transactions" acceptance criterion.

### Likelihood Explanation
Likelihood is high in terms of reachability (any L1 account can call the Starknet core contract's message-sending function to create an L1 handler transaction cheaply and repeatedly), but the practical cost is bounded by L1 gas fees for each message, and actual OOM would require sustained, high-volume spam over a long period. This makes it a real but resource/cost-gated growth issue rather than an instantaneous DoS.

### Recommendation
Introduce a retention policy for `Committed` (and `Rejected`) transaction records analogous to the consumption timelock cleanup already in place: track committed/rejected transactions in a time- or block-height-indexed queue and prune them from `records` once they are old enough that they can no longer be referenced (e.g., past the point where L1 reorg/double-inclusion checks are relevant), mirroring the `consumed_queue` + `clear_old_tx_from_consumed_queue` pattern used for `Consumed` transactions.

### Proof of Concept
1. An attacker calls the L1 Starknet core contract's `sendMessageToL2` (or equivalent) repeatedly, generating many distinct L1 handler transactions with minimal calldata/fee.
2. The L1 events scraper picks these up and calls `L1EventsProvider::add_events` → `TransactionManager::add_tx`, creating a `TransactionRecord` for each in `records` [8](#0-7) .
3. Each transaction eventually gets proposed/validated (`get_txs`/`validate_tx`) and included in a block; on commit, `commit_txs` calls `mark_committed`, transitioning the record to `TransactionState::Committed` [4](#0-3) .
4. No code path ever removes a `Committed` record from `self.records`; repeating steps 1–3 indefinitely grows `records` without bound, confirmed by the snapshot logic which explicitly enumerates `Committed` entries as retained forever (`snapshot.committed.push(tx_hash)`) with no corresponding pruning routine [9](#0-8) .

    pub fn add_tx(
        &mut self,
        tx: L1HandlerTransaction,
        block_timestamp: BlockTimestamp,
        scrape_timestamp: UnixTimestamp,
    ) {
        let tx_hash = tx.tx_hash;
        // If exists, return false and do nothing. If not, create the record as a HashOnly payload.
        let is_new_record = self.create_record_if_not_exist(tx_hash);
        // Replace a HashOnly payload with a Full payload. Do not update a Full payload.
        // A hash only payload can come from catching up from state sync, and then updated by
        // add_events from the scraper. However, if we get the same full tx twice (from the scraper)
        // it could indicate a double-scrape, and may cause the tx to be re-added to the proposable
        // index.
        self.with_record(tx_hash, move |record| match &record.tx {
            TransactionPayload::HashOnly(_) => {
                if !is_new_record {
                    info!(
                        "Transaction {tx_hash} already exists as a HashOnly payload. It was \
                         probably gotten via state sync component, and is now updated with a Full \
                         payload."
                    );
                }
                record.tx.set(tx, block_timestamp, scrape_timestamp);
                // Counts the HashOnly -> Full transition, regardless of whether the HashOnly
                // was just created here or pre-existed from state sync.
                L1_MESSAGE_SCRAPER_L1_HANDLER_TX_COUNT.increment(1);
            }
            TransactionPayload::Full { tx: _, created_at_block_timestamp: _, scrape_timestamp } => {
                warn!(
                    "Transaction {tx_hash} already exists as a Full payload, scraped at \
                     {scrape_timestamp}. This could indicate a double scrape. Ignoring the new \
                     transaction."
                );
            }
        });
    }

    pub fn finalize_cancellation(&mut self, tx_hash: TransactionHash) {
        let Some(record) = self.records.get(&tx_hash) else {
            info!(
                "Attempted to finalize cancellation for non-existent transaction: {tx_hash}. This \
                 can happen if the transaction was too old to be scraped (e.g. it was created \
                 before we started scraping)."
            );
            return;
        };

        // Regardless of the state of the tx in the record, if we get the cancellation event from
        // the L1 contract, we delete this tx from the records and from the proposable index, even
        // if it was Pending and ready to be proposed (which is not supposed to happen, hence the
        // warning).
        if record.state != TransactionState::CancellationStartedOnL2 {
            warn!(
                "Attempted to finalize cancellation for transaction {tx_hash} that is not in the \
                 cancellation started on L2 state, but in the {:?} state.",
                record.state
            );
        }
        // This will also call maintain_indices to remove the tx from the proposable index.
        self.with_record(tx_hash, |r| r.mark_cancellation_finalized_on_l1());
        self.records.remove(&tx_hash);
    }

    pub fn consume_tx(
        &mut self,
        tx_hash: TransactionHash,
        consumed_at: BlockTimestamp,
        unix_now: u64,
    ) -> Result<(), BlockTimestamp> {
        self.clear_old_tx_from_consumed_queue(unix_now);

        let Some(record) = self.records.get(&tx_hash) else {
            debug!(
                "Attempted to consume an unknown transaction: {tx_hash}. This can happen if the \
                 transaction was too old to be scraped (e.g. it was created before we started \
                 scraping)."
            );
            return Ok(());
        };

        // Double consumption is a bug.
        if let Some(previously_consumed_at) = record.get_consumed_at_timestamp() {
            return Err(previously_consumed_at);
        }

        // Mark the transaction as consumed.
        self.with_record(tx_hash, |record| record.mark_consumed(consumed_at));
        Ok(())
    }

    pub fn clear_old_tx_from_consumed_queue(&mut self, unix_now: u64) {
        let cutoff =
            unix_now.saturating_sub(self.config.l1_handler_consumption_timelock_seconds.as_secs());
        let still_timelocked = self.consumed_queue.split_off(&BlockTimestamp(cutoff));
        let passed_timelock = std::mem::replace(&mut self.consumed_queue, still_timelocked);
        for tx_hashes in passed_timelock.values() {
            for tx_hash in tx_hashes {
                self.records.remove(tx_hash);
            }
        }
    }

    pub(crate) fn snapshot(&self) -> TransactionManagerSnapshot {
        let mut snapshot = TransactionManagerSnapshot::default();

        for (&tx_hash, record) in self.records.iter() {
            match record.state {
                TransactionState::Rejected => {
                    snapshot.rejected.push(tx_hash);
                    if self.is_staged(tx_hash) {
                        snapshot.rejected_staged.push(tx_hash);
                    }
                }
                TransactionState::Committed => {
                    snapshot.committed.push(tx_hash);
                }
                TransactionState::Pending => {
                    snapshot.uncommitted.push(tx_hash);
                    if self.is_staged(tx_hash) {
                        snapshot.uncommitted_staged.push(tx_hash);
                    }
                }
                TransactionState::CancellationStartedOnL2 => {
                    snapshot.cancellation_started_on_l2.push(tx_hash);
                }
                TransactionState::CancelledOnL2 => {
                    snapshot.cancelled_on_l2.push(tx_hash);
                }
                // This should never happen, fully cancelled txs are removed from the transaction
                // manager.
                TransactionState::CancellationFinalizedOnL1 => {
                    panic!(
                        "This should never happen, fully cancelled txs are removed from the \
                         transaction manager."
                    );
                }
                TransactionState::Consumed => {
                    snapshot.consumed.push(tx_hash);
                }
            }
        }
        snapshot.proposable_index = self.proposable_index.clone();
        snapshot
    }

    pub fn mark_committed(&mut self) {
        // Can't return error because committing only part of a block leaves the provider in an
        // undetermined state.
        assert!(
            !self.committed,
            "L1 handler transaction {} committed twice, this may lead to l2 reorgs,",
            self.tx.tx_hash()
        );
        self.state = TransactionState::Committed;
        self.committed = true;
    }

    // Note: double reject not currently checked.
    pub fn mark_rejected(&mut self) {
        // Pedantic, this is unlikely to happen.
        assert!(
            !self.committed,
            "Attempted to reject a committed transaction {}",
            self.tx.tx_hash()
        );
        self.state = TransactionState::Rejected;
        self.rejected = true;
    }

    pub fn update_time_based_state(&mut self, unix_now: u64, policy: TransactionRecordPolicy) {
        if let Some(requested_at) = self.cancellation_requested_at {
            if self.committed {
                return; // Committing overrides cancellations.
            }

            let cancellation_timelock = &policy.cancellation_timelock.as_secs();
            let is_cancellation_timelock_passed =
                unix_now >= *requested_at.saturating_add(cancellation_timelock);

            if is_cancellation_timelock_passed {
                self.state = TransactionState::CancelledOnL2;
            }
        }
    }
