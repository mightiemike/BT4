## Analysis

The reported bug class — an attacker replaying/front-running a permit-style signature to force a victim's protected call to revert while still incurring cost — has a direct, and more severe, analog in Push Chain's `MsgExecutePayload` gasless-execution path.

### Root cause

`x/uexecutor/keeper/msg_execute_payload.go:ExecutePayload` executes the UEA call and then **unconditionally** deducts gas fees from the UEA regardless of whether the EVM call succeeded or reverted: [1](#0-0) 

`DeductGasFeesFromReceipt` only skips billing when the receipt is `nil` or `GasUsed == 0` — it does not check EVM execution status: [2](#0-1) 

The UEA contract enforces replay protection via a monotonic, contract-tracked `nonce` bound into the signed payload hash (per `x/uexecutor/README.md`): [3](#0-2) 

Because `MsgExecutePayload` deliberately does **not** bind `Signer == EVM(Owner)` — "any account may submit the message" — and it is on the gasless whitelist (free to submit, no Cosmos fee): [4](#0-3) [5](#0-4) 

### Attack

Any previously-broadcast or on-chain `MsgExecutePayload` exposes its `UniversalAccountId` + `UniversalPayload` + `VerificationData` in plaintext (mempool gossip or immutable tx history). An attacker can:
1. Extract any such already-consumed (or about-to-be-consumed) signed payload for a victim UEA.
2. Resubmit it verbatim as a new `MsgExecutePayload` with their own `Signer`, at zero cost (gasless).
3. Inside `CallUEAExecutePayload`, the UEA contract rejects the replay because its on-chain nonce has already advanced — the call reverts with nonzero `GasUsed`.
4. `ExecutePayload` still calls `DeductGasFeesFromReceipt`, which burns real UPC from the **victim UEA's balance** for this reverted, functionally useless call.
5. This is repeatable indefinitely — every resubmission costs the attacker nothing but drains the victim's UPC balance on every attempt (as long as balance remains and the fee can be paid).

This is worse than the cited report's DoS: the original protocol design in `push-chain-node` explicitly bills the sender by receipt regardless of success ("Step 4: Deduct gas fees regardless of success/failure"), turning a replay-rejection revert into a real, unauthorized, repeatable fund drain rather than a mere denial of service.

### Title
Unprivileged replay of any historical/mempool `MsgExecutePayload` drains victim UEA gas balance via unconditional fee deduction on revert - (File: `x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`ExecutePayload` bills the target UEA for gas usage from `CallUEAExecutePayload` even when the EVM call reverts (e.g., due to nonce reuse from a replayed signed payload). Since `MsgExecutePayload` allows any `Signer` to submit any owner's previously-observed `VerificationData`+`UniversalPayload` at zero cost (gasless whitelist, `Signer != Owner` by design), an attacker can repeatedly resubmit an already-consumed signed payload to force reverted executions that still burn the victim UEA's UPC balance.

### Finding Description
`ExecutePayload` (`x/uexecutor/keeper/msg_execute_payload.go:86-97`) calls `CallUEAExecutePayload`, capturing `execErr` and `receipt`, then calls `DeductGasFeesFromReceipt` before checking `execErr`. `DeductGasFeesFromReceipt` (`x/uexecutor/keeper/fees.go:97-148`) only no-ops when `receipt == nil || receipt.GasUsed == 0`; any receipt with nonzero `GasUsed` — including a reverted call — is billed via `DeductAndBurnFees`, which burns real UPC from the recipient (UEA) balance. The UEA contract's nonce+deadline replay protection means that once a `verificationData`/payload pair has been consumed (either legitimately or via front-run), any later resubmission of the identical bytes is guaranteed to revert inside `executeUniversalTx`, yet still consume nonzero gas before hitting the nonce check, and still gets billed to the victim.

Because `MsgExecutePayload` is on the gasless whitelist and does not require `Signer == EVM(Owner)`, the attacker's resubmission costs them nothing on the Cosmos side, while the victim UEA is billed real UPC each time.

### Impact Explanation
Medium-High. An unprivileged attacker can repeatedly and indefinitely drain a victim's UEA UPC balance (used for gas billing on universal payload execution) by replaying any signed payload that is publicly visible once broadcast/mined, at zero cost to themselves. This is an unauthorized value transfer/burn from user-controlled funds triggered purely by unprivileged external input — falls squarely within the "unauthorized ... module-originated EVM execution" / "corruption of ... gas fee accounting" impact categories.

### Likelihood Explanation
Medium. Requires the attacker to observe a `MsgExecutePayload`'s `VerificationData` + `UniversalPayload` (available in mempool before inclusion, or trivially from on-chain history after inclusion) and resubmit it. No special privileges, keys, or validator collusion needed — it is a plain unprivileged resubmission of already-public data.

### Recommendation
In `ExecutePayload` / `ExecutePayloadV2`, skip (or reduce) gas-fee deduction when `execErr` indicates the EVM call reverted due to signature/nonce/deadline rejection inside the UEA contract (i.e., distinguish "payload never authenticated/executed" reverts from partial execution failures), similar to how the codebase already treats fee-deduction failure as fully rolling back state. At minimum, cap or waive billing for calls that revert before any meaningful state mutation, and/or require that `VerificationData`+payload nonce be checked against the UEA's current on-chain nonce before invoking the costly `DerivedEVMCall`, so a known-stale/replayed nonce is rejected cheaply pre-execution rather than always incurring EVM gas that gets billed to the victim.

### Proof of Concept
1. Owner submits `MsgExecutePayload` (payload nonce `N`, valid `VerificationData`) via a relayer; it succeeds, advancing the UEA's on-chain nonce to `N+1`.
2. Attacker observes this transaction on-chain (or in mempool before inclusion) and extracts `UniversalAccountId`, `UniversalPayload` (nonce `N`), and `VerificationData`.
3. Attacker submits a new `MsgExecutePayload` with their own `Signer`, reusing the identical `UniversalAccountId`/`UniversalPayload`/`VerificationData`.
4. `ExecutePayload` → `CallUEAExecutePayload` → the UEA contract reverts (`invalid nonce`), but returns a receipt with `GasUsed > 0`.
5. `DeductGasFeesFromReceipt` runs unconditionally per `x/uexecutor/keeper/msg_execute_payload.go:91`, burning UPC from the UEA balance.
6. Attacker repeats step 3–5 indefinitely (free, gasless tx) until the victim UEA's UPC balance is exhausted.

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```

**File:** x/uexecutor/README.md (L213-218)
```markdown
`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```

**File:** x/uexecutor/README.md (L222-227)
```markdown
The cryptographic binding is enforced inside the UEA contract's `executeUniversalTx` (see [`UEA_EVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_EVM.sol#L145) and [`UEA_SVM.sol`](https://github.com/pushchain/push-chain-core-contracts/blob/86e20e2d26819e7cc885549f08c66895221dfab0/src/uea/UEA_SVM.sol)):

1. The contract holds the owner's public key as **immutable bytes** set at UEA deployment via `initialize(_id, _factory)`. There is no code path that mutates this after init.
2. `executeUniversalTx(payload, signature)` verifies the `signature` (passed in as `MsgExecutePayload.VerificationData`) against this stored owner — ECDSA recovery for EVM-origin owners, the Ed25519 precompile (`0x00…00ca`) for SVM-origin owners.
3. The signed payload hash includes a contract-tracked `nonce` (monotonic per UEA) and optional `deadline`, providing replay and freshness protection.
4. If signature verification fails, the contract reverts. The revert propagates as `execErr` from `CallUEAExecutePayload`; the keeper returns the error from `ExecutePayload`; the entire Cosmos transaction (including any partial gas-fee deduction) rolls back atomically. **No state changes survive a failed signature check.**
```
