## Analysis

The M-8 pattern (attacker fills a bounded/costly resource for free, degrading availability for legitimate users) has a direct analog in Push Chain's gasless transaction admission path, specifically the `AccountInitDecorator`.

### Finding

**Title:** Unbounded free BaseAccount creation via gasless-tx first-use account initialization — state-bloat DoS - (File: `app/ante/account_init_decorator.go`)

**Summary**

`AccountInitDecorator.AnteHandle` [1](#0-0)  is wired into the Cosmos ante chain and triggers on *any* gasless transaction (the gasless whitelist includes `MsgExecutePayload`, which "any account may submit" per the module README) [2](#0-1) . For a signer with no existing on-chain account, it verifies a signature over a fixed `account_number=0, sequence=0` payload and then unconditionally creates and persists a `BaseAccount`: [3](#0-2) 

Critically, on success it `return ctx, nil` — it does **not** call `next(ctx, tx, simulate)`. The rest of the ante chain (pubkey/signature-count/increment-sequence decorators) and the message handler are never reached. This means the underlying message content (e.g., an intentionally malformed `MsgExecutePayload` or `MsgVoteInbound` that would fail message-level validation) never has to succeed, or even be evaluated, for the account to be created and the transaction to be accepted as valid.

Both `MinGasPriceDecorator` and `DeductFeeDecorator` explicitly skip their checks for gasless transactions [4](#0-3) [5](#0-4) , and this decorator runs *before* signature-count/pubkey/sig-verification decorators in the chain: [6](#0-5) .

**Impact**

An unprivileged external attacker can, at zero monetary cost:
1. Generate an arbitrary new keypair.
2. Sign a minimal gasless-whitelisted message (`MsgExecutePayload` is the easiest, since "any account may submit" it) with `account_number=0, sequence=0`.
3. Submit it — this creates a permanent `BaseAccount` entry in state, consuming no coin, and the tx is accepted without ever reaching message-level validation.
4. Repeat indefinitely with fresh keypairs.

This grows the account/auth state store without bound and at zero cost, analogous to M-8's free order-queue filling — it is an unprivileged, non-network-level state-bloat/DoS vector reachable via ordinary transaction submission, not requiring any privileged, validator, or peer role.

**Likelihood**

High — the only "cost" is generating a keypair and a valid signature locally, both computationally trivial and free; no minimum balance or fee is required because the transaction is gasless and this decorator runs ahead of fee/gas-price checks.

**Recommendation**

Consider bounding or de-incentivizing this path: e.g., require a minimum non-zero fee/deposit for first-use account creation regardless of gaslessness, rate-limit new-account creation per block/IP at the mempool layer, or require the inner message to itself pass `ValidateBasic`/authorization checks (e.g., bonded-UV or valid-UEA-owner checks) before persisting the new account, rather than short-circuiting the ante chain immediately after signature verification.

**Note:** this write-up should be validated further (e.g., against `NewConsumeGasForTxSizeDecorator`'s effect on mempool inclusion, and whether CometBFT/mempool-level per-account tx limits mitigate the practical rate of exploitation) since the index does not give full visibility into all runtime mempool constraints; a Devin session with full repo/build access would be needed to confirm exploitability end-to-end and measure the real growth rate.

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}
