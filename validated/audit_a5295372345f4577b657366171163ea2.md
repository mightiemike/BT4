### Title
PoisonMicroblock proof accepts a signature-malleability variant of a single microblock header as proof of equivocation, allowing an honest miner to be slashed - ([File: stackslib/src/chainstate/stacks/db/transactions.rs], [File: stacks-codec/src/transaction.rs])

### Summary
`TransactionPayload::PoisonMicroblock::consensus_deserialize` only checks that the two headers are not byte-identical and that they share `sequence` or `prev_block`; it never requires their `tx_merkle_root` to differ. `check_microblock_header_signer` recovers each header's signer via `StacksPublicKey::recover_to_pubkey_without_validating_low_s`, which does not enforce low-S normalization. Since ECDSA signatures are malleable (given a valid `(r, s)` for a message, `(r, n-s)` with a flipped recovery id is also valid for the *same* message under the *same* key, without knowledge of the private key), an attacker can take one already-published, valid `StacksMicroblockHeader` and mechanically derive a second header object that is byte-different (different `signature` field) but semantically identical (same `version`, `sequence`, `prev_block`, `tx_merkle_root`), and submit both as a `PoisonMicroblock` transaction.

### Finding Description
The broken equality is: **"two distinct serialized `StacksMicroblockHeader`s ⇒ two distinct signed messages by the miner (genuine equivocation)."** The code only enforces byte-inequality of the full struct (`h1 == h2` check) plus a same-`sequence`-or-same-`prev_block` fork-shape check: [1](#0-0) 

It never compares `tx_merkle_root`, and it never checks that the two `signature` fields correspond to genuinely different signing operations rather than two valid encodings of one ECDSA signature (canonical low-S vs. malleable high-S with flipped recovery id).

Downstream, `check_microblock_header_signer` recovers each header's public key hash via `recover_to_pubkey_without_validating_low_s` (i.e. `verify_low_s = false`), so a high-S signature is accepted for recovery purposes in this specific poison-verification path: [2](#0-1) [3](#0-2) [4](#0-3) 

Exploit flow: attacker observes a single legitimately signed microblock header `H = (version, sequence, prev_block, tx_merkle_root, sig)` broadcast by an honest miner. Without any private key, attacker computes the malleable variant `sig' = (r, n-s, recid')` — a publicly known transform requiring only curve order `n` — producing `H' = (version, sequence, prev_block, tx_merkle_root, sig')` with `H != H'` (signature bytes differ) but both recover to the same pubkey hash. Attacker submits `PoisonMicroblock(H, H')`. `consensus_deserialize` accepts it (`h1 != h2`, `sequence == sequence`, `prev_block == prev_block`). `handle_poison_microblock` calls `check_microblock_header_signer`, which recovers `pkh1 == pkh2` (both recover to the honest miner's key since the transform preserves recoverability), and proceeds to record a poison report and slash the miner's microblock public key hash, crediting the attacker/reporter: [5](#0-4) [6](#0-5) 

The existing guard `PoisonMicroblocksDoNotConflict` in mempool admission (`will_admit_mempool_tx`) checks `sequence`, `prev_block`, `version`, and that `pkh1 == pkh2` — it likewise never checks `tx_merkle_root` inequality, so it does not stop this construction either: [7](#0-6) 

### Impact Explanation
An unprivileged attacker (no signer/majority stake, no miner key) can cause an honest miner's microblock public-key hash to be permanently marked "poisoned," diverting the associated block-reward commission to the attacker/reporter and denying it to the legitimate miner — without any actual equivocation having occurred. This is a reward mis-payment triggerable by a single minority participant who merely observes one public, already-broadcast microblock header; it is repeatable against any miner whose signed microblock header becomes publicly visible. This matches the **High** severity bucket ("a poison or reward mis-payment bounded to fees, temporary tip disagreement").

### Likelihood Explanation
Preconditions: attacker needs to observe exactly one validly signed `StacksMicroblockHeader` from a target miner (trivially available from the P2P network) and the pubkey-hash must still be within `MINER_REWARD_MATURITY` of current height. No BTC spend, no stake, no privileged role, and no cryptographic secret is required — only the well-known ECDSA `s → n-s` malleability transform. This is fully attacker-controlled and deterministic, and can be repeated against every miner's every microblock header that the attacker sees.

### Recommendation
1. In `TransactionPayload::PoisonMicroblock::consensus_deserialize`, require `h1.tx_merkle_root != h2.tx_merkle_root` (or otherwise require the pre-signature message content to differ) in addition to the existing byte-inequality and fork-shape checks, so structurally-identical-content headers with only malleable-signature differences are rejected.
2. In `check_microblock_header_signer` (and/or `StacksMicroblockHeader::check_recover_pubkey` when used for poison verification), enforce low-S normalization (use `recover_to_pubkey`/enforce canonical `s`) so that a malleable high-S counterpart of an existing low-S signature cannot independently validate as a distinct "signed" header.

### Proof of Concept
Rust integration test plan (place near `process_poison_microblock_*` tests in `stackslib/src/chainstate/stacks/db/transactions.rs`):
1. Generate a miner keypair `privk`/`pubkh`; sign a `StacksMicroblockHeader` `h1` with fixed `sequence`, `prev_block`, `tx_merkle_root` via `h1.sign(&privk)`.
2. Programmatically derive `h2` = `h1` but with `signature` replaced by the malleable transform: parse `h1.signature` into `(r, s, recid)`, compute `s' = n - s`, `recid' = 1 - (recid & 1)` (preserving the high bit for x-overflow if present), and set `h2.signature = (r, s', recid')`. Assert `h1 != h2` and `h1.tx_merkle_root == h2.tx_merkle_root`.
3. Assert `TransactionPayload::consensus_deserialize` on `(h1, h2)` **succeeds** today (demonstrating the current gap), i.e. does not raise "microblock headers match" or "do not identify a fork".
4. Call `StacksChainState::check_microblock_header_signer(&h1, &h2)` (or drive it through `handle_poison_microblock`/`process_transaction`) and assert it currently returns `Ok(pubkh)` — i.e., the poison report is accepted and the miner is slashed.
5. After applying the recommended fix (require `tx_merkle_root` inequality and/or low-S enforcement in `check_recover_pubkey` for poison verification), re-run steps 3–4 and assert the transaction/report is now **rejected** with an error such as "microblock headers do not identify distinct content" or a low-S verification failure, while a genuine equivocation pair (different `tx_merkle_root` or `prev_block`, independently signed) still succeeds.

        let mut bytes = vec![];

        let digest = Sha512Trunc256Sum::from_data(&bytes[..]);

        let mut pubk = StacksPublicKey::recover_to_pubkey_without_validating_low_s(
            digest.as_bytes(),
            &self.signature,
        )
        .map_err(|_ve| {
            AuthError::VerifyingError(
                "Failed to verify signature: failed to recover public key".to_string(),
            )
        })?;

        pubk.set_compressed(true);
        Ok(Hash160::from_node_public_key(&pubk))
    }

                &pkh1, &pkh2

            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }

    fn recover_to_pubkey_possibly_with_low_s_verification(
        msg: &[u8],
        sig: &MessageSignature,
        verify_low_s: bool,
    ) -> Result<Secp256k1PublicKey, &'static str> {
        _secp256k1.with(|ctx| {
            let msg = LibSecp256k1Message::from_slice(msg).map_err(|_e| {
                "Invalid message: failed to decode data hash: must be a 32-byte hash"
            })?;

            let secp256k1_sig = sig
                .to_secp256k1_recoverable()
                .ok_or("Invalid signature: failed to decode recoverable signature")?;

            if verify_low_s {
                let secp256k1_sig_standard = secp256k1_sig.to_standard();
                let mut secp256k1_sig_low_s = secp256k1_sig_standard;
                secp256k1_sig_low_s.normalize_s();
                if secp256k1_sig_low_s != secp256k1_sig_standard {
                    return Err("Invalid signature: high-S");
                }
            }

            let recovered_pubkey = ctx
                .recover_ecdsa(&msg, &secp256k1_sig)
                .map_err(|_e| "Invalid signature: failed to recover public key")?;

            Ok(Secp256k1PublicKey {
                key: recovered_pubkey,
                compressed: true,
            })
        })
    }
