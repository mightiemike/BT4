### Title
`accrue` Pause Pass-Through Lets Callers Skip Interest Accrual and Borrow/Repay Against a Stale Index Within the Same Block - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
The `accrue` function in every vault contract (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`) checks the `accrue` pause flag and, when paused, silently returns the *old* cached `index`/`lindex` instead of reverting [1](#0-0) . Every state-changing entry point (`deposit`, `redeem`, `system-borrow`, `system-repay`) calls `accrue` first and unconditionally uses its return value to compute shares/debt, without checking whether accrual actually occurred. This mirrors the report's root-cause pattern: a value (the interest index) is fetched/cached under one condition and then used downstream by code that assumes it reflects current, accrued state, without the invalidation/failure being surfaced.

### Finding Description
`accrue` is structured as:
```
(if (get accrue states)
    ;; PAUSED: Pass-through without reverting
    (ok { index: idx, lindex: lidx })
    ;; NOT PAUSED: Normal accrual logic
    ...)
``` [2](#0-1) 

When `pause-states.accrue` is `true`, it returns `(ok {index: idx, lindex: lidx})` using the *variables already in storage* (`var-get index`, `var-get lindex`) rather than propagating an error. This is exactly the "pause that passes through instead of reverting" pattern called out in scope.

`deposit`, `redeem`, and `system-borrow` all call `(try! (accrue))` and bind its result (`u`) but then proceed to use `(var-get index)`, `(var-get assets)`, and other state read separately, treating the accrue call as a no-op guard rather than as a precondition that must produce fresh state:
- `deposit`: `(u (try! (accrue))) ... (try! (receive-underlying amount account)) (try! (ft-mint? zft inkind recipient)) (var-set assets (+ current-assets amount))` [3](#0-2) 
- `system-borrow`: `(u (try! (accrue))) ... (idx (var-get index)) ... (scaled-amount (mul-div-up amount INDEX-PRECISION idx))` [4](#0-3) 

Because DAO-controlled pausing of `accrue` is an allowed governance action (not a compromise), and the pause/unpause toggle itself is single-transaction, the only path here that is reachable without any DAO action is: **while `accrue` is already paused** (a legitimate operational state, e.g. during an incident), every `deposit`/`redeem`/`system-borrow`/`system-repay` call silently uses the stale `index`/`lindex` captured at the moment pausing began, for the *entire duration* of the pause, with no revert, no warning, and no distinction from normal operation. This is a single-block/single-transaction issue in the sense that each individual borrow/repay/deposit/redeem transaction silently succeeds using a frozen index without any signal to the caller that accrual is stale — the guard (`try! (accrue)`) evaluates successfully even though the underlying invariant it exists to enforce (index reflects current time) is violated.

Unpausing does perform a catch-up: `(if (and was-paused (not now-paused)) (var-set last-update stacks-block-time) false)` in `set-pause-states` [5](#0-4)  — this jumps `last-update` forward to "now" on unpause, meaning **all interest that should have accrued between pause and unpause is permanently skipped/lost** rather than deferred. Debt continues to be borrowed/repaid using the stale index for the whole pause window, and lenders lose the yield that should have accrued on both sides.

### Impact Explanation
This lands in the **High** impact category: temporary/permanent freezing or loss of unclaimed yield. While the vault is paused for accrual, borrowers can still `system-borrow`/`system-repay` (if those specific pause flags are off) and depositors can `deposit`/`redeem` at the stale index/lindex, and interest accrued during the pause window is permanently discarded when `last-update` is snapped to `stacks-block-time` on unpause rather than replayed. This causes lenders to permanently lose yield they would otherwise have earned, and can let borrowers who transact during the pause lock in a lower effective rate than they should owe, at the expense of the pool's `zft` share pricing.

### Likelihood Explanation
Likelihood is moderate: it requires the DAO to legitimately pause `accrue` (a normal, documented operational lever, not a compromise), which happens during any incident-response pause. Given that pausing `accrue` is intended to "freeze" the protocol, the current implementation instead permanently discards the accrued interest for that window on every affected vault, so any use of this pause mechanism as designed will trigger the bug.

### Recommendation
When `accrue` is paused, either (a) revert state-changing calls (`deposit`, `redeem`, `system-borrow`, `system-repay`) instead of silently passing through with the stale index, or (b) on unpause, replay/accrue interest for the paused interval instead of jumping `last-update` straight to `stacks-block-time`, so that yield is deferred rather than permanently lost.

### Proof of Concept
1. DAO calls `set-pause-states` on `v0-vault-usdc` with `accrue: true` (legitimate operational pause) [6](#0-5) .
2. Time passes (multiple blocks) while `accrue` remains paused; the true index should have grown due to interest, but `accrue()` always returns the frozen `idx`/`lidx` [7](#0-6) .
3. A user calls `deposit`/`redeem` on the vault: `convert-to-shares-preview`/`convert-to-assets-preview` price shares using the stale, un-accrued state, and `var-set assets` is updated based on that stale accounting [3](#0-2) .
4. DAO unpauses `accrue`: `last-update` is set directly to `stacks-block-time`, discarding the entire pause-duration's worth of interest rather than accruing it [8](#0-7) .
5. Result: yield that should have accrued to `zft` holders over the pause window never materializes — a permanent loss of unclaimed yield for lenders, and mispriced deposits/redemptions/borrows executed during the window.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))
  (begin
    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      ;; When pausing accrue, accrue first to capture pending interest
      (if (and (not was-paused) now-paused)
          (begin (try! (accrue)) false)
          false)
      ;; When unpausing accrue, jump last-update to now to skip paused period
      (if (and was-paused (not now-paused))
          (var-set last-update stacks-block-time)
          false)
      (var-set pause-states states)
