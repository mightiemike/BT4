### Title
Global contract identity binding via `GlobalContractIdentifier::AccountId` allows an unrelated party to hijack a deleted account's identifier and silently take over code execution for all subscribers - (File: `runtime/runtime/src/global_contracts.rs`)

### Summary
NEAR's global-contract "AccountId" deploy mode lets accounts subscribe to shared code by referencing another account's *id* rather than a specific code hash. This reference is stored permanently in the subscriber's own account record (`AccountContract::GlobalByAccount(id)`) and is resolved purely by that account-id string at call time, with no binding to the identity/lifetime of the account that originally deployed the code. Because NEAR account ids can be deleted and later re-created by a different, unrelated controller, an attacker can reclaim a previously-used account id, deploy malicious code under `GlobalContractDeployMode::AccountId`, and have that code silently and automatically become the executed code for every account that had previously subscribed via `UseGlobalContractAction` - without any of those subscribers re-consenting. This mirrors the Aave Lens "follow deleted profile" bug class: a persistent, reused identifier (handle/account id) is trusted by third parties as if it denotes a stable identity, but the identifier can be reassigned to a new, different entity.

### Finding Description
`UseGlobalContractAction`/`use_global_contract` lets an account point its `AccountContract` at `GlobalByAccount(account_id)`: [1](#0-0) 

The only check performed is that *some* code currently exists under that identifier (`GlobalContractDoesNotExist`); there is no notion of "the same deployer" or "the same incarnation of the account" being preserved: [2](#0-1) 

Deployment under `GlobalContractDeployMode::AccountId` writes code keyed purely by the deploying account's *current* id, with the only anti-replay protection being a monotonic nonce (which prevents receipt reordering, not identity continuity): [3](#0-2) [4](#0-3) 

Crucially, `remove_account` (invoked by `action_delete_account` on `DeleteAccount`) removes the `Account` record, local `ContractCode`, access/gas keys, and contract data - but it never touches the `TrieKey::GlobalContractCode { identifier: AccountId(..) }` entry, because that entry is keyed by a bare account-id string, independent of the `Account` trie key namespace: [5](#0-4) [6](#0-5) 

At call time, code for a `GlobalByAccount(id)` contract is resolved solely by looking up whatever value currently sits under that identifier in the trie - there is no check that the id still belongs to (or was ever previously the same incarnation as) whoever the subscriber originally trusted: [7](#0-6) [8](#0-7) 

This is explicitly the documented, intended way for an *owner* to update their own users' code: [9](#0-8) 

but the design implicitly assumes the account id is a stable, non-reassignable identity. NEAR account ids are not permanently reserved after deletion: a deleted sub-account can be re-created by its parent, and (subject to `min_allowed_top_level_account_length`) a deleted top-level name can be re-registered by anyone once its former owner deletes it. Neither `action_delete_account` nor `use_global_contract`/`action_deploy_global_contract` invalidates or re-checks ownership continuity of the `GlobalContractCode { identifier: AccountId(..) }` slot across such a deletion/recreation cycle.

### Impact Explanation
Any account that previously executed `UseGlobalContractAction { contract_identifier: AccountId(x) }` has permanently bound its own `AccountContract` to whatever code lives at identifier `x` at call time. If the account `x` is later deleted and recreated (by its parent, by a new top-level registrant, or by any actor who gains control of that id), the new controller of `x` can deploy arbitrary WASM via `DeployGlobalContractAction { deploy_mode: AccountId }`. This silently changes the code that executes for every subscribing account on their next `FunctionCall`, running with the *subscriber's own permissions* (balance, storage, cross-contract calls) - all without any subscriber transaction, re-consent, or notification. This can lead to unauthorized value movement (the malicious code can transfer the subscriber's NEAR or manipulate subscriber-owned state) and constitutes acceptance of an implicitly-untrusted state transition (arbitrary code substitution) that the protocol has no mechanism to prevent or even warn about.

### Likelihood Explanation
Exploitation requires only ordinary, permissionless transactions reachable by any account holder: (1) deploy a global contract in `AccountId` mode from account `X`, (2) get other accounts to `UseGlobalContractAction(AccountId(X))` (a normal, expected integration pattern for "shared upgradeable libraries"), (3) delete account `X` (self-deletable via `DeleteAccount`, or via its parent for sub-accounts), (4) have any party re-create an account with the same id `X` (straightforward for sub-accounts under a cooperating/compromised parent, and possible for top-level names once vacated), and (5) deploy new, malicious code under `AccountId` mode again. No validator, node operator, or off-chain component involvement is needed; the whole chain is driven by transactions from ordinary signers/relayers.

### Recommendation
Bind the `GlobalContractCode { identifier: AccountId(id) }` slot (and any subscriber's `AccountContract::GlobalByAccount(id)`) to a value that is invalidated across account deletion - e.g., clear/rotate the global-contract entry in `remove_account`/`action_delete_account` when the account currently owns an `AccountId`-mode global contract deployment, and/or embed an account "incarnation" token (e.g., account creation nonce/height) into the `GlobalContractIdentifier::AccountId` binding so that a subscriber's reference cannot silently resolve to code deployed by a different incarnation of the same account id.

### Proof of Concept
1. Account `lib.near` deploys a shared contract with `DeployGlobalContractAction { code: goodCode, deploy_mode: AccountId }`.
2. Accounts `alice.near`, `bob.near`, ... each submit `UseGlobalContractAction { contract_identifier: AccountId("lib.near") }`, setting their `AccountContract` to `GlobalByAccount("lib.near")` (`runtime/runtime/src/global_contracts.rs:76-98`).
3. `lib.near` self-deletes via `DeleteAccountAction` (`runtime/runtime/src/actions.rs:330-406`); `remove_account` does not touch `GlobalContractCode { identifier: AccountId("lib.near") }` (`core/store/src/utils/mod.rs:504-513`).
4. `lib.near`'s parent (or, for a vacated top-level name, any registrant) re-creates account `lib.near` under attacker control.
5. Attacker-controlled `lib.near` deploys `DeployGlobalContractAction { code: evilCode, deploy_mode: AccountId }`; `apply_distribution_current_shard` overwrites `GlobalContractCode { identifier: AccountId("lib.near") }` with `evilCode` (`runtime/runtime/src/global_contracts.rs:191-212`), passing the nonce-freshness check trivially since it only guards against replay, not identity (`:248-269`).
6. The next `FunctionCall` receipt sent to `alice.near`/`bob.near` resolves their contract via `RuntimeContractIdentifier::resolve` → `GlobalContractIdentifier::AccountId("lib.near").code()`, which fetches `evilCode` (`runtime/runtime/src/contract_code.rs:36-73`, `91-116`) and executes it with `alice.near`'s/`bob.near`'s own account permissions - without any action from `alice.near`/`bob.near`.

// Checks if the incoming nonce is fresh and updates the stored nonce. Returns
// true if the nonce is fresh, false if it's stale. The nonce is set
// immediately and the freshness check allows the same nonce (>=).
fn check_and_update_nonce(
    global_contract_data: &GlobalContractDistributionReceipt,
    identifier: &GlobalContractCodeIdentifier,
    state_update: &mut TrieUpdate,
) -> Result<bool, RuntimeError> {
    let nonce_key = TrieKey::GlobalContractNonce { identifier: identifier.clone() };
    let stored_nonce = get_nonce(state_update, &nonce_key)?;
    let incoming_nonce = global_contract_data.nonce();

    // Allow the same nonce since the nonce is updated immediately when
    // initiating distribution to prevent multiple distributions with the same
    // nonce from being initiated.
    if incoming_nonce < stored_nonce {
        return Ok(false);
    }

    set_nonce(state_update, nonce_key, incoming_nonce);
    Ok(true)
}

pub(crate) fn action_delete_account(
    state_update: &mut TrieUpdate,
    account: &mut Option<Account>,
    actor_id: &mut AccountId,
    receipt: &Receipt,
    result: &mut ActionResult,
    account_id: &AccountId,
    delete_account: &DeleteAccountAction,
    config: &RuntimeConfig,
    current_protocol_version: ProtocolVersion,
) -> Result<(), StorageError> {
    let account_ref = account.as_ref().unwrap();
    let account_storage_usage = if ProtocolFeature::FixDeleteAccountGlobalContractStorageUsage
        .enabled(current_protocol_version)
    {
        let contract_storage = get_contract_storage_usage(state_update, account_id, account_ref)?;
        account_ref.storage_usage().saturating_sub(contract_storage)
    } else {
        // Legacy behavior: only subtracts local contract code, misses the
        // global contract identifier overhead.
        let account_storage_usage = account_ref.storage_usage();
        let code_len = get_code_len_or_default(
            state_update,
            account_id.clone(),
            account_ref.local_contract_hash().unwrap_or_default(),
        )?;
        debug_assert!(
            code_len == 0 || account_storage_usage > code_len,
            "account storage usage should be larger than code size. storage usage: {}, code size: {}",
            account_storage_usage,
            code_len
        );
        account_storage_usage.saturating_sub(code_len)
    };
    if account_storage_usage > Account::MAX_ACCOUNT_DELETION_STORAGE_USAGE {
        result.result =
            Err(ActionErrorKind::DeleteAccountWithLargeState { account_id: account_id.clone() }
                .into());
        return Ok(());
    }
    let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
    if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: None,
            balance: gas_key_balance_to_burn,
        }
        .into());
        return Ok(());
    }
    // We use current amount as a pay out to beneficiary.
    let account_balance = account_ref.amount();
    if account_balance > Balance::ZERO {
        result
            .new_receipts
            .push(Receipt::new_balance_refund(&delete_account.beneficiary_id, account_balance));
    }
    let remove_result = remove_account(state_update, account_id)?;
    result.tokens_burnt =
        result.tokens_burnt.checked_add(gas_key_balance_to_burn).ok_or_else(|| {
            StorageError::StorageInconsistentState("tokens_burnt overflow".to_string())
        })?;
    if remove_result.gas_key_nonce_count > 0 {
        let compute = storage_removes_compute(
            &config.wasm_config.ext_costs,
            remove_result.gas_key_nonce_count,
            remove_result.gas_key_nonce_total_key_bytes,
            AccessKey::NONCE_VALUE_LEN * remove_result.gas_key_nonce_count,
        );
        result.compute_usage = safe_add_compute(result.compute_usage, compute).map_err(|_| {
            StorageError::StorageInconsistentState("compute_usage overflow".to_string())
        })?;
    }
    *actor_id = receipt.predecessor_id().clone();
    *account = None;
    Ok(())
}

    pub(crate) fn resolve(
        account_id: &AccountId,
        account_contract: AccountContract,
        state_update: &TrieUpdate,
        chain_id: &str,
        access: AccessOptions,
    ) -> Result<Self, StorageError> {
        let local_hash = match GlobalContractIdentifier::try_from(account_contract) {
            Ok(gci) => {
                let code_hash = gci.clone().hash(state_update, access)?;
                return Ok(RuntimeContractIdentifier::Global { code_hash, identifier: gci });
            }
            Err(ContractIsLocalError::NotDeployed) => return Ok(RuntimeContractIdentifier::None),
            Err(ContractIsLocalError::Deployed(local_hash)) => local_hash,
        };

        if account_id.get_account_type() == AccountType::EthImplicitAccount {
            // Accounts that look like eth implicit accounts and have existed prior to the
            // eth-implicit accounts protocol change (these accounts are discussed in the
            // description of #11606) may have something else deployed to them. Only return
            // something here if the accounts have a wallet contract hash. Otherwise use the
            // regular path to grab the deployed contract.
            if LegacyEthWallet::resolve(local_hash).is_some() {
                // ETH implicit wallet accounts use global contracts, including
                // those created in old protocol versions.
                let global_hash = eth_wallet_global_contract_hash(chain_id);
                return Ok(RuntimeContractIdentifier::Global {
                    code_hash: global_hash,
                    identifier: GlobalContractIdentifier::CodeHash(global_hash),
                });
            }
        }

        Ok(RuntimeContractIdentifier::AccountLocal {
            code_hash: local_hash,
            account_id: account_id.clone(),
        })
    }

impl GlobalContractAccessExt for GlobalContractIdentifier {
    fn hash(self, store: &TrieUpdate, access: AccessOptions) -> Result<CryptoHash, StorageError> {
        if let GlobalContractIdentifier::CodeHash(hash) = self {
            return Ok(hash);
        }
        let key = TrieKey::GlobalContractCode { identifier: self.into() };
        let value_ref =
            store.get_ref(&key, KeyLookupMode::MemOrFlatOrTrie, access)?.ok_or_else(|| {
                let TrieKey::GlobalContractCode { identifier } = key else { unreachable!() };
                StorageError::StorageInconsistentState(format!(
                    "Global contract identifier not found {:?}",
                    identifier
                ))
            })?;
        Ok(value_ref.value_hash())
    }

    fn code(self, store: &TrieUpdate) -> Result<Option<ContractCode>, StorageError> {
        let key = TrieKey::GlobalContractCode { identifier: self.clone().into() };
        let code_hash = match self {
            GlobalContractIdentifier::AccountId(_) => None,
            GlobalContractIdentifier::CodeHash(hash) => Some(hash),
        };
        let code = store.get(&key, AccessOptions::DEFAULT)?;
        Ok(code.map(|code| ContractCode::new(code, code_hash)))
    }
