### Title
Floor-truncated calldata/signature/code archival gas cost undercharges L2 gas fee - (File: `crates/blockifier/src/fee/resources.rs`)

### Summary
The archival-data gas-cost helpers in `ArchivalDataResources::to_gas_vector` truncate the fractional part of the computed cost toward zero instead of rounding up, unlike the sibling cost helper `calculate_resource_gas_cost` in `fee_utils.rs`, which explicitly rounds up with `.ceil().to_integer()`. This inconsistency lets a transaction sender systematically under-pay for the L2/L1 gas that calldata, signature, and declared-class code actually consume, analogous to the reported Teller bug where per-call truncation of a fractional cost caused the payer to remit less than owed.

### Finding Description
`get_calldata_and_signature_gas_cost` and `get_code_gas_cost` compute a `Ratio<u64>`-based per-unit cost (`gas_per_data_felt`, `gas_per_code_byte`) multiplied by the calldata/signature/code size, then call `.to_integer()` directly: [1](#0-0) [2](#0-1) 

`Ratio::to_integer()` truncates toward zero (floor for non-negative values), discarding any fractional remainder of the cost. Contrast this with `calculate_resource_gas_cost`, which is the analogous helper for VM-resource gas costs and deliberately rounds up: [3](#0-2) 

Because `gas_per_data_felt` / `gas_per_code_byte` are fractional `ResourceCost` (`Ratio<u64>`) values pulled from versioned constants, any transaction whose `total_data_size` (calldata + signature length in felts) or `code_size` does not divide evenly by the cost denominator will have its true cost rounded down rather than up. A transaction sender fully controls calldata length, signature length, and (for `declare`) code size, and can therefore always choose sizes that land just below an integer boundary, extracting the maximum truncation discount on every single transaction — the same "attacker controls the granularity to keep landing on the rounding-favorable side" pattern as the cited Teller report, where the borrower could keep interest calculations near zero by controlling repayment timing/amount.

### Impact Explanation
This under-prices the L2 gas fee charged for archival (calldata/signature/code) data relative to the actual data that must be published/stored, meaning the sender pays less than the protocol's own cost model dictates for every transaction with non-integer-aligned data sizes. Aggregated across the mempool/block, this is a systematic fee-collection shortfall reachable by any ordinary transaction sender, not requiring any privileged role — a concrete (if per-transaction bounded) loss to whoever ultimately bears the archival-data cost (the network/da payer), consistent with a Medium-severity, protocol-wide underpayment defect.

### Likelihood Explanation
High likelihood of triggering: it happens on essentially every transaction, since calldata/signature/code sizes rarely divide evenly by the configured per-felt/per-byte cost denominator, and no special conditions or privileges are needed — a single ordinary `invoke`/`declare` transaction from any account triggers the code path.

### Recommendation
Change `get_calldata_and_signature_gas_cost` and `get_code_gas_cost` (and the client-side-proof cost helper, for consistency) to round up using `.ceil().to_integer()`, matching the rounding convention already used in `calculate_resource_gas_cost`, so archival-data gas costs are never under-billed relative to the versioned-constants cost model.

### Proof of Concept
1. Configure/observe a versioned-constants set where `gas_per_data_felt` (or `gas_per_code_byte`) is a non-integer `Ratio<u64>` (e.g. `p/q` with `q>1`), as stored in `blockifier_versioned_constants_*.json`.
2. Submit an `invoke` transaction with `extended_calldata_length + signature_length` chosen such that `total_data_size * gas_per_data_felt` has a fractional remainder just below an integer (e.g. remainder `q-1 / q`).
3. Observe in `get_calldata_and_signature_gas_cost` that `(archival_gas_costs.gas_per_data_felt * total_data_size).to_integer()` truncates the fractional remainder, yielding a gas amount one unit lower than the "true" cost that `calculate_resource_gas_cost`'s `.ceil()` convention would have produced for an equivalent resource.
4. Repeating this with carefully chosen sizes on every transaction lets the sender consistently avoid paying for the fractional unit of archival gas across the transaction's lifetime, unlike VM-resource costs which are always rounded up.

Note: I was unable to directly read the numeric `gas_per_data_felt`/`gas_per_code_byte` values from the versioned-constants JSON files in this pass (only match counts were retrieved, not file contents) to confirm they are non-integer in the currently active version; this should be verified against `crates/blockifier/resources/blockifier_versioned_constants_0_14_3.json` before treating the exploitable magnitude as final.

    /// Returns the cost for transaction calldata and transaction signature. Each felt costs a
    /// fixed and configurable amount of gas. This cost represents the cost of storing the
    /// calldata and the signature on L2.
    fn get_calldata_and_signature_gas_cost(
        &self,
        versioned_constants: &VersionedConstants,
        mode: &GasVectorComputationMode,
    ) -> GasVector {
        let archival_gas_costs = versioned_constants.get_archival_data_gas_costs(mode);

        // TODO(Avi, 20/2/2024): Calculate the number of bytes instead of the number of felts.
        let total_data_size = u64_from_usize(self.extended_calldata_length + self.signature_length);
        let gas_amount =
            (archival_gas_costs.gas_per_data_felt * total_data_size).to_integer().into();

        match mode {
            GasVectorComputationMode::All => GasVector::from_l2_gas(gas_amount),
            GasVectorComputationMode::NoL2Gas => GasVector::from_l1_gas(gas_amount),
        }
    }

/// Calculates the total gas cost for a resource given its unit cost and usage count.
fn calculate_resource_gas_cost(cost_per_unit: ResourceCost, usage: usize) -> u64 {
    (cost_per_unit * u64_from_usize(usage)).ceil().to_integer()
}
