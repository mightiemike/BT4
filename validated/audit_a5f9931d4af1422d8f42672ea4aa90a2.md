### Title
Header/CRLF injection via `host` param in `getEmbeddedAppUrl` due to hostname-only validation of decoded host - (File: packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts)

### Summary
`getEmbeddedAppUrl` builds the redirect URL by string-concatenating the raw, attacker-controlled base64-decoded `host` value, while `sanitizeHost` only validates the `hostname` component extracted via `new URL()`. Because the WHATWG `URL` parser silently strips ASCII tab/newline characters when computing the `hostname`, an attacker can craft a base64 `host` value whose decoded plaintext contains `\r\n` sequences that are stripped during validation but preserved in the final concatenated URL, which is then passed straight into `res.redirect()` / Remix's `redirect()`.

### Finding Description
`buildEmbeddedAppUrl` in `packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts` does: [1](#0-0) 

It calls `sanitizeHost(config)(host, true)` purely for its throwing side effect, then independently calls `decodeHost(host)` again and concatenates the raw result into the returned URL string. `sanitizeHost` in `packages/apps/shopify-api/lib/utils/shop-validator.ts` validates the value like this: [2](#0-1) 

The only real constraint on the raw `host` query parameter is that it must be base64 (`base64regex`), which allows arbitrary decoded byte content, including `\r` and `\n` in the plaintext. `sanitizeHost` decodes it and creates `new URL('https://' + decodeHost(sanitizedHost))`, then checks only the extracted `hostname` against the allowed suffix regex (`\.(myshopify\.com|shopify\.com|myshopify\.io|spin\.dev|shop\.dev)$`). Per the WHATWG URL spec, `\r`/`\n`/`\t` characters are stripped from the input *before* the URL is parsed, so a decoded string such as `test.myshopify.com/admin\r\nX-Injected: 1` yields `hostname === 'test.myshopify.com'`, passing validation.

However, `buildEmbeddedAppUrl` does not use the sanitized/stripped `hostname` — it re-decodes the original `host` string with `decodeHost(host)` and puts that *raw* decoded value (still containing the literal `\r\n`) directly into the returned string: `` `https://${decodedHost}/apps/${config.apiKey}` ``. This unsanitized string is exactly what is returned to the consuming middleware.

Downstream, this returned value is passed directly to `res.redirect()` in `packages/apps/shopify-app-express/src/middlewares/redirect-to-shopify-or-app-root.ts` and to Remix's `redirect()` in `packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/redirect-to-shopify-or-app-root.ts`: [3](#0-2) [4](#0-3) 

Both frameworks ultimately assign this value as the `Location` header (or path) for a redirect response. If the underlying HTTP stack does not itself reject header values containing raw CR/LF (this varies by runtime/framework — Node's `http` module usually throws on invalid header characters, but this cannot be guaranteed across every adapter/runtime this library supports, e.g. edge/worker runtimes used by shopify-app-remix), this allows HTTP response splitting / header injection or at minimum a client-observable malformed `Location` value derived from attacker input that bypassed the intended host-domain allowlist.

### Impact Explanation
This breaks the invariant that `host` is validated against exact allowed origins before being used to construct a redirect URL: the *validated* component (`hostname`) and the *emitted* component (raw `decodedHost`) are not the same string. Depending on the runtime handling the resulting `res.redirect()`/`redirect()` call, this can lead to HTTP response splitting/header injection or an embedded-URL value containing attacker-controlled trailing content beyond the allowed domain, matching the "open redirect / embedded-URL injection" impact class referenced in the question.

### Likelihood Explanation
The attacker only needs to make an unauthenticated GET request with a crafted, valid-base64 `host` query parameter to any route that ultimately invokes `getEmbeddedAppUrl` (e.g., the redirect-to-shopify-or-app-root flow, which fires after OAuth completion) — no secret or privileged access required. The main uncertainty is whether the specific Node/edge HTTP stack used by a given deployment will itself reject a `Location` header value containing raw `\r\n` before it reaches the client; this is runtime-dependent and not mitigated by this library's own code, since the library's own sanitization is what fails to strip the characters from the value it returns.

### Recommendation
In `buildEmbeddedAppUrl`, use the same sanitized/stripped hostname value that was validated, rather than re-decoding the original `host` and reconstructing the URL from raw components — e.g., build the final URL via `new URL()` from the validated `hostname` (and any explicitly validated path segments) instead of string concatenation of the unvalidated decoded plaintext. Additionally, reject `host` values whose decoded content contains control characters (`\r`, `\n`, `\t`, etc.) outright in `sanitizeHost`.

### Proof of Concept
```ts
import {testConfig} from '../../__tests__/test-config';
import {shopifyApi} from '../..';

test('embedded app URL leaks raw CRLF from decoded host past validation', async () => {
  const shopify = shopifyApi(testConfig());

  const maliciousHost = 'test.myshopify.com/admin\r\nX-Injected: 1';
  const base64Host = Buffer.from(maliciousHost, 'utf-8').toString('base64');

  const req = {
    method: 'GET',
    url: `/?shop=test.myshopify.com&host=${base64Host}`,
    headers: {host: 'test.myshopify.com'},
  };

  const url = await shopify.auth.getEmbeddedAppUrl({rawRequest: req as any});

  // Expected (buggy) behavior: passes hostname-suffix validation
  // and still contains literal CR/LF bytes in the returned string.
  expect(url).toContain('\r\n');
});
```
This demonstrates that `getEmbeddedAppUrl` returns a string containing raw `\r\n` bytes even though `sanitizeHost`'s hostname-suffix check passed, confirming the validated value and the emitted value diverge.

    const decodedHost = decodeHost(host);

    return `https://${decodedHost}/apps/${config.apiKey}`;

export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }

    return sanitizedHost;
  };
