### Title
Starknet OS `execute_replace_class` accepts an undeclared class hash, causing state-root divergence from the Blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Nova advisory is a "stale/unauthorized resource binding" bug: a check that should tie a live resource to its currently-valid owner (VNC token ↔ current VM) was missing, letting a value bound to a deleted context be reused as if valid. In this codebase the analogous missing binding check is in the Starknet OS's Cairo re-execution of the `replace_class` syscall: it changes a contract's bound class hash without verifying that the new class hash actually corresponds to a declared class, unlike the Rust Blockifier which enforces this check on the same syscall.

### Finding Description
`execute_replace_class` in the Starknet OS syscall handler directly overwrites `StateEntry.class_hash` for the calling `contract_address` with an attacker-supplied `class_hash` from the syscall request, with an explicit unresolved TODO admitting the missing validation: [1](#0-0) 

Note line 902: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` No call analogous to `is_declared` is made before the `dict_update` commits the new class hash to `contract_state_changes`.

The deprecated (Cairo 0) OS syscall path has the identical gap: [2](#0-1) 

By contrast, the Rust Blockifier — the code that actually decides whether a transaction is valid and gets included in a block — enforces the check on every `replace_class` call: [3](#0-2) 

and the deprecated (Cairo 0) syscall handler in the Blockifier does the same: [4](#0-3) 

Tests confirm the Blockifier actively rejects `replace_class` calls with an undeclared class hash ("is not declared"): [5](#0-4) [6](#0-5) 

This is precisely the class of divergence the report's "Starknet OS re-execution" scope calls out: two components that are supposed to compute the *same* state transition disagree about whether a given input (an undeclared class hash bound via `replace_class`) is even valid, because the authorization/binding check (declared-class verification) that exists in one path is missing in the other.

### Impact Explanation
The Starknet OS is the Cairo program whose execution trace is proven (STARK proof) to attest that a claimed state transition (old root → new root) is correct, and this proof is what ultimately gets accepted as the canonical state commitment. If the OS's syscall execution logic can accept and commit a `replace_class` for a class hash that was never declared (because the corresponding declare transaction never succeeded, was reverted, or does not exist at all in the OS's view of the input), the OS can produce/attest a state diff that the Blockifier itself would never have produced from a legitimately-included transaction (the Blockifier would reject such a transaction outright). This causes:
- A wrong committed state root / block hash (the OS-attested state can encode a contract bound to a class hash that no honest node's Blockifier state would ever contain for that account).
- Honest-node divergence: full nodes running the Blockifier will compute a different (rejecting) result for the same transaction than what the OS-based re-execution/proving path would accept, breaking the invariant that Blockifier execution and OS re-execution agree on validity.
- Since the resulting contract now behaves per an arbitrary/attacker-chosen (or garbage) `class_hash`, this can be leveraged for unauthorized account behavior at that address once such a state diff is accepted as canonical.

This matches the required impact bar ("wrong committed root or block hash, honest-node divergence") and is reachable purely from a normal contract's `replace_class` syscall call within a transaction — no privileged operator/prover role is required to trigger the divergence; only the presence of this unchecked code path in the OS is required for the bug to be exploitable if that syscall's declared-ness enforcement is otherwise relied upon.

### Likelihood Explanation
Likelihood is High for a straightforward divergence trigger: `replace_class` is a standard, unprivileged syscall any deployed Cairo1 contract can invoke with attacker-controlled calldata (the class hash argument), as shown in the Blockifier's own `test_replace_class`/`undeclared_class_hash` tests which exercise exactly this call shape. The only remaining uncertainty (explicitly noted below) is whether some other component upstream of the OS run (e.g., hint generation from the Blockifier-produced trace, or a later commitment-stage cross-check) independently re-validates that every `replace_class` target class hash is declared before the OS accepts it; if no such secondary validation exists, exploitation is direct.

### Recommendation
Add a declared-class check to `execute_replace_class` (and its deprecated counterpart) in the Starknet OS mirroring the Blockifier's check: before performing `dict_update`, verify that `class_hash` corresponds to a class that is declared in the current state (e.g., look up its compiled/casm entry and fail the syscall/transaction if absent), exactly as `syscall_base.rs::replace_class` and `hint_processor.rs::replace_class` already do. Resolve the `TODO(Yoni, 1/1/2026)` before this becomes a live discrepancy between the Blockifier and the OS.

### Proof of Concept
Conceptual reproduction path (given code-level evidence, not independently executed):
1. Deploy a Cairo1 contract exposing a function that invokes the `replace_class` syscall with an attacker-chosen `class_hash` value that is **not** a declared class in the current state.
2. Submit this transaction. Blockifier-based sequencer/full nodes reject it with `UndeclaredClassHash` (confirmed by `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash`), so this transaction never becomes part of an honestly-produced block.
3. If, however, the Starknet OS is fed a transaction/trace that reaches `execute_replace_class` (e.g., via a divergent path in how inputs to the OS are constructed, or a future workflow that does not first pass through the Blockifier's identical check), the OS will happily commit the `StateEntry.class_hash` update at line 906-914 of `syscall_impls.cairo` without ever verifying `class_hash` is declared, producing a state diff/commitment that the Blockifier would never generate for a valid transaction — a concrete Blockifier vs. OS divergence rooted in the missing check documented by the code's own `TODO`.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,

    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
