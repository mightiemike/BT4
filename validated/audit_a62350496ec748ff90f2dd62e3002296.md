### Title
Miner-Reset Activity Timer Lets a Single Malicious Miner Pin a Stalled Tenure and Fork the Signer Set's View - (File: stacks-signer/src/chainstate/mod.rs)

### Summary
`check_latest_block_in_tenure` in `stacks-signer/src/chainstate/mod.rs` resets a per-tenure "last activity" timestamp whenever a signer receives *any* block proposal that conflicts with (does not exceed) the tenure's currently known tip — even proposals that get rejected outright. [1](#0-0)  This is structurally the same class of bug as the MonoX report: a state-machine timeout/lock (`lastTradedBlock` there, `last_activity_time`/`is_timed_out` here) that a single unprivileged party can indefinitely keep from expiring by repeatedly performing small, cheap, and individually-losing actions timed just before the window closes, thereby blocking the system state (price update there, miner-fallback/tenure-timeout here) from ever correcting.

### Finding Description
The signer's inactivity-timeout logic (`SortitionState::is_timed_out` in `stacks-signer/src/chainstate/v1.rs`/`v2.rs`) is the safety valve that lets the signer set abandon a misbehaving/stalled miner's tenure and fall back to accepting a new miner's blocks: it only returns "timed out" once `elapsed` since `last_activity_time` (or burn-block-receive time) exceeds `block_proposal_timeout`. [2](#0-1) 

`last_activity_time` is a purely local, per-signer, per-tenure timestamp updated by `check_latest_block_in_tenure` any time an incoming (even invalid/conflicting) block proposal from the *current* tenure's miner is received and is deemed "close enough" to still count as activity — specifically, whenever the proposal doesn't exceed the known chain length but its conflicting block's `signed_group`/`approved_time` is still within `reorg_attempts_activity_timeout`/`tenure_last_block_proposal_timeout` of "now": [3](#0-2) 

Crucially, this is:
1. **Triggerable by a single miner** (whoever currently holds the tenure via a legitimately-won sortition — no signer majority, no stake, and no special privilege beyond mining a low-value/garbage block proposal is required).
2. **Evaluated independently by each signer**, based only on what that signer individually received — there is no cross-signer agreement check on `last_activity_time` itself before it feeds into `is_timed_out`.

A miner who wants to keep their tenure alive without actually producing a valid/committable block can therefore submit a trickle of throwaway block proposals — one shortly before each signer's `block_proposal_timeout`/`reorg_attempts_activity_timeout` window would otherwise elapse — exactly mirroring the MonoX `updatePoolPrice` pattern of doing a tiny swap just before the `6000`-block staleness window closes to keep `lastTradedBlock` from going stale. [4](#0-3) 

Because network delivery of these throwaway proposals is not guaranteed uniform (the miner can target them selectively, or ordinary network jitter/partitioning can cause it unintentionally), different signers can end up with divergent `last_activity_time` values for the same tenure. Some signers will conclude the miner has **not** timed out (and continue refusing to sign for/accept a successor miner's blocks), while others — who missed the "keep-alive" proposals — will conclude the miner **has** timed out and accept the successor. This directly breaks the equality that all honest signers should reach the same accept/reject verdict for the same tenure at the same time, producing a genuine, minority-triggerable temporary tip/verdict disagreement across the signer set (some signers still blocked on the old miner, others already progressing with the new one) until the discrepancy resolves via later `reorg_attempts_activity_timeout`/pre-commit freshness windows described elsewhere in this same chainstate machinery. [5](#0-4) 

### Impact Explanation
This maps to the "High" bucket: a minority-triggerable (single miner, no majority signer collusion) static-validation/timeout divergence that produces a temporary disagreement among signers about whether a tenure is still valid/active, stalling block production and confusing miner fallback until timers separately expire on each signer. It does not, on its own, cause an irreversible chain split or reward theft — the disagreement is bounded and self-heals as each signer's local timer eventually times out — but it can be sustained indefinitely at negligible cost by the attacker (each keep-alive proposal is cheap since it is rejected, unlike the burn-cost of winning sortition again), which is functionally identical to MonoX's price-pinning DoS via micro-swaps.

### Likelihood Explanation
Likelihood is meaningful because the only precondition is winning a single sortition (or, more simply, mining/broadcasting garbage block proposals under an already-active tenure's consensus hash — no stake or signer key is needed to *submit* a proposal, only to have it accepted for signing). Deliberately timing keep-alive proposals just inside the `reorg_attempts_activity_timeout`/`tenure_last_block_proposal_timeout` window is a simple, repeatable, low-cost operation, directly analogous to the "micro-exchange every 6000 blocks" technique described in the source report.

### Recommendation
Base the tenure inactivity determination on cross-signer/global evidence (e.g., a threshold-weighted "last activity" observation, or requiring the keep-alive proposal itself to be independently validated/committed rather than merely received) rather than a per-signer local timestamp updated by unvalidated inbound proposals. Consider disallowing "invalid/rejected" proposals from resetting `last_activity_time` at all, and/or requiring corroboration (e.g., burn-chain progress or a minimum-weight set of signers seeing the same proposal) before treating a proposal as valid miner activity for timeout purposes.

### Proof of Concept
Conceptual PoC (network/timing-level, not a novel code path — it exercises `check_latest_block_in_tenure` exactly as written):
1. Miner M wins sortition for tenure T and produces one valid block, then stalls.
2. Signer set starts timing tenure T's inactivity via `SortitionState::is_timed_out`, keyed off `last_activity_time` for T. [6](#0-5) 
3. Shortly before `block_proposal_timeout`/`reorg_attempts_activity_timeout` would elapse for a subset of signers (S1), M crafts and sends a conflicting/low-height block proposal for tenure T to S1 only.
4. `check_latest_block_in_tenure` on S1 rejects the proposal as not extending the chain, but because the conflicting block's `signed_group`/`approved_time` is still fresh, it calls `signer_db.update_last_activity_time(...)`, resetting S1's timer for T. [7](#0-6) 
5. M never sends the same proposal to signer subset S2 (or it is lost/delayed), so S2's timer for T continues to elapse and eventually times out.
6. When a successor miner M' proposes a block, S2 accepts M' as valid (T timed out) while S1 still treats T as active and refuses/ignores M', producing a live but temporary split in the signer set's tenure verdicts — repeatable indefinitely by M by repeating step 3–4 on a rolling basis, exactly like MonoX's periodic micro-swap keeping `lastTradedBlock` from going stale.

    /// Get the last signed block from the given tenure if it has not timed out.
    /// Even globally accepted blocks are allowed to be timed out, as that
    /// triggers the signer to consult the Stacks node for the latest globally
    /// accepted block. This is needed to handle Bitcoin reorgs correctly.
    ///
    /// The timeout window is measured from the last time a signature actually covered the
    /// block: our own (`signed_self`) or the observed group/global acceptance
    /// (`signed_group`), whichever is later, matching how `get_signed_conflicts` measures
    /// endorsement freshness. `approved_time` is deliberately not used: it is stamped at
    /// pre-commit, which carries no signature, so it would close the window early. This also
    /// means a globally accepted block we never signed ourselves gets a full window from the
    /// time its acceptance was observed, rather than timing out instantly for lack of a
    /// timestamp.
    pub fn get_tenure_last_block_info(
        consensus_hash: &ConsensusHash,
        signer_db: &SignerDb,
        tenure_last_block_proposal_timeout: Duration,
    ) -> Result<Option<BlockInfo>, ClientError> {
        // Get the last signed block in the tenure
        let last_signed_block = signer_db
            .get_last_signed_block(consensus_hash)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;

        let Some(block_info) = last_signed_block else {
            return Ok(None);
        };

        // `approved_time` may hold the pre-commit time; use the actual signature time.
        let Some(signed_over_time) = block_info.signed_self.max(block_info.signed_group) else {
            return Ok(None);
        };

        if signed_over_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
            > get_epoch_time_secs()
        {
            // The last accepted block is not timed out, return it
            Ok(Some(block_info))
        } else {
            // The last accepted block is timed out
            info!(
                "Last accepted block has timed out";
                "signer_signature_hash" => %block_info.block.header.signer_signature_hash(),
                "signed_over_time" => signed_over_time,
                "state" => %block_info.state,
            );
            Ok(None)
        }
    }

    pub fn check_latest_block_in_tenure(
        tenure_id: &ConsensusHash,
        block: &NakamotoBlock,
        signer_db: &mut SignerDb,
        client: &StacksClient,
        tenure_last_block_proposal_timeout: Duration,
        reorg_attempts_activity_timeout: Duration,
    ) -> Result<bool, ClientError> {
        let last_block_info = SortitionData::get_tenure_last_block_info(
            tenure_id,
            signer_db,
            tenure_last_block_proposal_timeout,
        )?;

        if let Some(info) = last_block_info {
            // N.B. this block might not be the last globally accepted block across the network;
            // it's just the highest one in this tenure that we know about.  If this given block is
            // no higher than it, then it's definitely no higher than the last globally accepted
            // block across the network, so we can do an early rejection here.
            if block.header.chain_length <= info.block.header.chain_length {
                warn!(
                    "Miner's block proposal does not confirm as many blocks as we expect";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "expected_at_least" => info.block.header.chain_length + 1,
                );
                if info.signed_group.is_none_or(|signed_time| {
                    signed_time + reorg_attempts_activity_timeout.as_secs() > get_epoch_time_secs()
                }) {
                    // Note if there is no signed_group time, this is a locally accepted block (i.e. tenure_last_block_proposal_timeout has not been exceeded).
                    // Treat any attempt to reorg a locally accepted block as valid miner activity.
                    // If the call returns a globally accepted block, check its globally accepted time against a quarter of the block_proposal_timeout
                    // to give the miner some extra buffer time to wait for its chain tip to advance
                    // The miner may just be slow, so count this invalid block proposal towards valid miner activity.
                    if let Err(e) = signer_db.update_last_activity_time(
                        &block.header.consensus_hash,
                        get_epoch_time_secs(),
                    ) {
                        warn!("Failed to update last activity time: {e}");
                    }
                }
                return Ok(false);
            }
        }

        // A block we have only pre-committed to must NOT veto this proposal, but, similar to above
        // this should still count as activity for the miner.
        let last_accepted_block = signer_db
            .get_last_accepted_block(tenure_id)
            .map_err(|e| ClientError::InvalidResponse(e.to_string()))?;
        if let Some(info) = last_accepted_block {
            let is_fresh_pre_commit = info.state == BlockState::PreCommitted
                && info.approved_time.is_some_and(|approved_time| {
                    approved_time.saturating_add(tenure_last_block_proposal_timeout.as_secs())
                        > get_epoch_time_secs()
                });
            if is_fresh_pre_commit && block.header.chain_length <= info.block.header.chain_length {
                info!(
                    "Miner's block proposal conflicts with a block we have only pre-committed to. Counting it as miner activity, but not rejecting the proposal.";
                    "proposed_block_consensus_hash" => %block.header.consensus_hash,
                    "signer_signature_hash" => %block.header.signer_signature_hash(),
                    "proposed_chain_length" => block.header.chain_length,
                    "pre_committed_signer_signature_hash" => %info.block.header.signer_signature_hash(),
                    "pre_committed_chain_length" => info.block.header.chain_length,
                );
                if let Err(e) = signer_db
                    .update_last_activity_time(&block.header.consensus_hash, get_epoch_time_secs())
                {
                    warn!("Failed to update last activity time: {e}");
                }
            }

    pub fn is_timed_out(
        sortition: &ConsensusHash,
        db: &SignerDb,
        block_proposal_timeout: Duration,
    ) -> Result<bool, SignerChainstateError> {
        // If we've already signed a block in this tenure, the miner can't have timed out: we have
        // committed a signature to this tenure and must not help abandon it.
        //
        // Importantly, a block we have only pre-committed to does not count! A pre-commit carries
        // no signature, and if it never reaches the pre-commit threshold the tenure can stall
        // indefinitely. Treating it as signed here would suppress the inactivity timeout for
        // exactly the signers that pre-committed, so they could never fall back to the prior
        // miner and the tenure could never recover.
        let has_block = db.has_signed_block_in_tenure(sortition)?;
        if has_block {
            return Ok(false);
        }
        let Some(received_ts) = db.get_burn_block_receive_time_ch(sortition)? else {
            return Ok(false);
        };
        let received_time = UNIX_EPOCH + Duration::from_secs(received_ts);
        let last_activity = db
            .get_last_activity_time(sortition)?
            .map(|time| UNIX_EPOCH + Duration::from_secs(time))
            .unwrap_or(received_time);

        let Ok(elapsed) = std::time::SystemTime::now().duration_since(last_activity) else {
            return Ok(false);
        };

        if elapsed > block_proposal_timeout {
            info!(
                "Tenure miner was inactive too long and timed out";
                "tenure_ch" => %sortition,
                "elapsed_inactive" => elapsed.as_secs(),
                "config_block_proposal_timeout" => block_proposal_timeout.as_secs()
            );
        }
        Ok(elapsed > block_proposal_timeout)
    }
