### Title
Sandwichable AMM-quoted `minPCOut` lets an unprivileged attacker skim value from every gas-deposit/refund auto-swap - (File: `x/uexecutor/keeper/evm.go`)

### Summary
The report's core bug class is "a permissionless, attacker-controlled input overwrites a price/value parameter an honest party relied on, immediately before the event that settles funds against that parameter, with only a fixed tolerance band as protection." Push Chain's uexecutor module has a structurally identical pattern in its Uniswap-V3-based auto-swap flow used for GAS inbound deposits, GAS_AND_PAYLOAD deposits, and outbound gas refunds: the module fetches a live AMM quote and derives `minPCOut` as a fixed 5% haircut of that quote, then immediately executes the swap on-chain. Because the quote is read from a public, attacker-tradable pool at execution time (not a TWAP or independent oracle), an ordinary unprivileged user can sandwich the module's own swap and extract value from the deposit/refund at the victim's expense, all within the "protected" 5% band.

### Finding Description
`k.GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` against the live pool reserves at the moment the module processes the finalized inbound/outbound: [1](#0-0) 

The result is used, unmodified except for a static 95% multiplier, as the slippage floor `minPCOut` passed into `depositPRC20WithAutoSwap`: [2](#0-1) 

This pattern is repeated in three independent places that all move real user/protocol value:
- GAS inbound deposits: [3](#0-2) 
- GAS_AND_PAYLOAD inbound deposits: [4](#0-3) 
- Outbound excess-gas refunds: [5](#0-4) 

The upgrade notes confirm this is the intended (and only) protection mechanism, explicitly describing it as a fixed "5% slippage" replacing a prior 0-slippage call: [6](#0-5) 

Because `GetSwapQuote` is called synchronously, in the same execution as the swap, and reads the pool state that any unprivileged EVM user can move with ordinary swap transactions, the "just-in-time" quote-then-execute sequence is directly analogous to the report's "refinance right before liquidation" pattern: an attacker permissionlessly moves the reference price immediately before the protocol-driven settlement consumes it, and the fixed tolerance band (5% here, "no minimumLiquidationPrice" there) does not distinguish an organically-moved price from an attacker-manipulated one.

### Impact Explanation
An attacker can front-run a pending inbound GAS/GAS_AND_PAYLOAD deposit or a pending outbound gas refund with a large swap that pushes the PRC20→WPC price down, causing the module's own `depositPRC20WithAutoSwap` call to execute near the worst allowed rate (`quote * 0.95`), then back-run to restore the price and capture the spread. This corrupts gas-fee/refund accounting and the amount of native PC the depositor's UEA actually receives, at the depositor's expense — matching the in-scope impact category "corruption of ... gas fee accounting, refund accounting ... or unauthorized ... release ... of user or protocol-controlled funds." Because this path runs for essentially every GAS/GAS_AND_PAYLOAD inbound and every outbound that carries excess gas, the aggregate value skimmable over time from ordinary users is material, though each individual instance is capped at ~5% of the affected amount.

### Likelihood Explanation
No privileged role, validator, relayer, or admin cooperation is required — only an ordinary unprivileged EVM account able to submit swap transactions against the pool used by `UNIVERSAL_CORE`/`QuoterV2`, and the ability to observe or predict when a deposit/refund auto-swap will execute (inbound finalization is driven by UV votes that are publicly observable on-chain before the module's deposit call fires, and outbound refunds fire deterministically once a broadcast is observed). This is a standard MEV/sandwich technique with well-understood tooling, making exploitation practical rather than theoretical.

### Recommendation
Do not derive the slippage floor solely from a spot quote taken immediately before execution. Options: use a time-weighted average price (TWAP) from the pool as the reference instead of `quoteExactInputSingle`'s instantaneous quote; tighten/adjust the tolerance dynamically based on pool liquidity/trade size instead of a flat 5%; add a maximum price-impact check independent of the attacker-influenced quote; or route these swaps through a mechanism (e.g., commit-reveal, private mempool/relayer bundling) that prevents front-running of module-originated swaps.

### Proof of Concept
1. Attacker monitors Push Chain for `MsgVoteInbound` votes on a GAS-type inbound approaching the 2/3 threshold (or an outbound whose `ObservedTx.GasFeeUsed < GasFee`, guaranteeing an `applyGasRefund` swap).
2. Immediately after observing the ballot is about to finalize (or in the same block once it does, if the node allows same-block follow-up txs), the attacker submits a large swap on the WPC/PRC20 pool used by `UniversalCore`, pushing the pool price down.
3. The module's keeper call executes: `GetSwapQuote` reads the now-manipulated pool state [7](#0-6) , computes `minPCOut = quote * 95/100`, and calls `depositPRC20WithAutoSwap`/`refundUnusedGas` which executes at close to that depressed rate [8](#0-7) .
4. Attacker immediately reverses their swap, restoring the price and pocketing the spread extracted from the victim's deposit/refund, which received up to ~5% less native PC than fair market value would have provided.

**Uncertainty/limitations:** I was not able to fully verify same-block transaction ordering guarantees or mempool visibility assumptions specific to Push Chain's block production (e.g., whether validators/UVs process votes and the resulting EVM calls within a window an external attacker can reliably front-run in practice). Confirming exact atomicity/timing constraints would require deeper review of the consensus/mempool code, which was outside the scope of what I could inspect with the available tools.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
