### Title
Unmetered storage deep-copy per nested CALL/DELEGATECALL enables asymmetric CPU/memory DoS - ([File: actuator/src/main/java/org/tron/core/vm/repository/RepositoryImpl.java])

### Summary
`RepositoryImpl.getStorage(byte[])` performs a full deep copy of the parent's `Storage` object — including every cached row in `rowCache` — each time a new child repository first accesses storage for a contract address, gated only by `StorageUtils.getEnergyLimitHardFork()`. Because a new child `Repository` is created on every internal `CALL`/`DELEGATECALL` (`newRepositoryChild()`), and each frame's `getStorage()` result is cheaply cached only within that frame, a contract with many cached storage rows that recurses through nested internal calls forces the node to repeatedly copy the entire row set at every call depth, at a CPU/memory cost that is not reflected in the fixed, size-independent energy cost of the `CALL` opcode.

### Finding Description
`getStorage(byte[] address)` walks up the repository chain: if the current repository has a parent, it fetches `parent.getStorage(address)` and, when the hard fork flag is active, performs `storage = new Storage(parentStorage)` [1](#0-0)  The `Storage` copy constructor iterates over `storage.getRowCache()` and clones every `StorageRowCapsule` entry into a new `HashMap` [2](#0-1) .

`newRepositoryChild()` is invoked to build a fresh child `Repository` for each internal call frame [3](#0-2) , and each child's own `storageCache` starts empty, so the first `SLOAD`/`SSTORE` in that frame triggers `getStorageInternal` → `getStorage`, re-executing the deep copy of whatever rows are already resident in the parent's `rowCache` [4](#0-3) .

Exploit flow:
1. Attacker deploys a contract and executes enough `SSTORE`s to persist N storage slots (a one-time, N-proportional energy cost paid up front).
2. A single subsequent transaction issues N `SLOAD`s in the top-level call frame, populating that frame's `Storage.rowCache` with all N rows (moderate, bounded, one-time-per-tx cost).
3. The contract then recurses via `CALL`/`DELEGATECALL` to itself M times (bounded by the VM's call-depth limit). At each new depth, a single `SLOAD`/`SSTORE` is enough to trigger `getStorage()`, which deep-copies the entire N-row map again.
4. The energy charged for each `CALL` and `SLOAD`/`SSTORE` is fixed and does not scale with N, so the attacker pays roughly `M * (fixed CALL/SLOAD cost)` while the node performs `M * N` object clones/allocations.

Because the same on-chain storage (N slots) can be reused across arbitrarily many future transactions without repaying the initial N-proportional cost, an attacker can repeat step 2–3 cheaply and indefinitely, each time forcing `M * N` deep-copy work for a nearly flat, size-independent fee.

### Impact Explanation
This is a computation/energy metering mismatch: the actual CPU/memory work of `RepositoryImpl.getStorage` scales with `depth × existing-storage-size`, while the energy charged for the triggering `CALL`/`SLOAD` opcodes is fixed. This matches the "DoS via the TRON protocol implementation" bounty class — a funded, unprivileged account can submit transactions that consume disproportionate node CPU/memory relative to the energy fee paid, degrading transaction processing/block validation performance for a fixed and comparatively small cost per triggering transaction (after a one-time setup cost to populate storage).

### Likelihood Explanation
- Preconditions are achievable by any unprivileged, funded account: deploying a contract, paying for N `SSTORE`s once, and issuing repeated cheap transactions that trigger nested calls.
- The amplification factor per transaction is bounded by the VM's maximum call-depth limit, and the copy volume is bounded by however many storage rows the attacker chooses to pre-load into the top frame's `rowCache` before recursing (attacker-controlled, subject only to the one-time upfront `SSTORE`/`SLOAD` energy cost).
- The attack is fully repeatable: once N slots exist on-chain, subsequent triggering transactions are cheap and can be resubmitted continuously.
- Feasibility depends on the magnitude of N an attacker is willing/able to fund once; for large N this could meaningfully increase per-transaction node processing cost without a correspondingly large energy charge.

### Recommendation
Avoid eagerly deep-copying the entire `Storage.rowCache` on every child repository's first access. Options:
- Make the child `Storage` a lazy/copy-on-write wrapper that only clones a row when it is actually mutated (`SSTORE`) rather than cloning the full map on first touch.
- Charge additional energy proportional to the size of the `rowCache` being copied (or proportional to the number of rows the child ends up touching) when `StorageUtils.getEnergyLimitHardFork()` is active, so cost tracks actual work performed.
- Cap or amortize the cost by sharing an immutable base map and only tracking per-frame overlays/deltas instead of full clones.

  private Storage getStorageInternal(byte[] address) {
    address = TransactionTrace.convertToTronAddress(address);
    if (getAccount(address) == null) {
      return null;
    }
    Key addressKey = Key.create(address);
    Storage storage;
    if (storageCache.containsKey(addressKey)) {
      storage = storageCache.get(addressKey);
    } else {
      storage = getStorage(address);
      storageCache.put(addressKey, storage);
    }
    return storage;
  }

  @Override
  public Storage getStorage(byte[] address) {
    Key key = Key.create(address);
    if (storageCache.containsKey(key)) {
      return storageCache.get(key);
    }
    Storage storage;
    if (this.parent != null) {
      Storage parentStorage = parent.getStorage(address);
      if (StorageUtils.getEnergyLimitHardFork()) {
        // deep copy
        storage = new Storage(parentStorage);
      } else {
        storage = parentStorage;
      }
    } else {
      storage = new Storage(address, getStorageRowStore());
    }
    ContractCapsule contract = getContract(address);
    if (contract != null) {
      storage.setContractVersion(contract.getContractVersion());
      if (!ByteUtil.isNullOrZeroArray(contract.getTrxHash())) {
        storage.generateAddrHash(contract.getTrxHash());
      }
    }
    return storage;
  }
