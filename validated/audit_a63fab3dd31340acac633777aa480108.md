### Title
`DelegateAction` Expiry Off-by-One: Action Executes at `max_block_height` When Spec Requires Expiry — (`File: runtime/runtime/src/actions.rs`)

### Summary
The `DelegateAction` (meta-transaction) expiry check uses a strict `>` comparison instead of `>=`, allowing a meta-transaction to execute at exactly `block_height == max_block_height`, one block beyond the boundary the documented specification and field semantics declare as the expiry point.

### Finding Description
The `DelegateAction` struct carries a `max_block_height` field documented as:

> "The maximal height of the block in the blockchain **below which** the given DelegateAction is valid."

The runtime spec in `docs/RuntimeSpec/Actions.md` line 402 states:

> "If the current block is **equal or greater than** `max_block_height`" → `DelegateActionExpired`

The error variant itself in `core/primitives/src/errors.rs` line 811 reads:

> `/// Delegate action has expired. `max_block_height` is **less than** actual block height.`

The error description says "less than" — meaning the error only fires when `max_block_height < block_height`, i.e., `block_height > max_block_height`. This is the strict `>` check. The test `test_delegate_action` at line 1289–1290 confirms this: it passes `apply_state.block_height = max_block_height` and asserts success. The test `test_delegate_action_max_height` at line 1358–1360 only triggers `DelegateActionExpired` when `block_height = max_block_height + 1`.

The actual expiry guard (inside `apply_delegate_action` in `runtime/runtime/src/actions.rs`) therefore fires only when `block_height > max_block_height`, not when `block_height == max_block_height`. This contradicts the documented invariant that the action is valid only for blocks **below** `max_block_height`. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

### Impact Explanation
A relayer holding a signed `DelegateAction` with `max_block_height = H` can submit it at block `H` and have it execute successfully, even though the user who signed the action intended it to be invalid at block `H` and beyond (per the documented spec). This constitutes **contract execution flow breakage**: the action executes when the protocol specification says it must not. Any user relying on `max_block_height` to bound the execution window of their meta-transaction has their invariant silently violated by one block.

### Likelihood Explanation
Likelihood is low-to-medium. A relayer must deliberately time submission to block `H`. However, the off-by-one is systematic and affects every `DelegateAction` on every execution path (`apply_delegate_action` in the runtime, chunk validation in `chain/chain/src/stateless_validation/chunk_validation.rs`, and SPICE chunk validation in `chain/chain/src/spice/chunk_validation.rs`). Any user who sets `max_block_height` to a specific block expecting hard expiry at that block is affected. [6](#0-5) [7](#0-6) 

### Recommendation
Change the expiry guard inside `apply_delegate_action` from:

```rust
if apply_state.block_height > delegate_action.max_block_height() {
    result.result = Err(ActionErrorKind::DelegateActionExpired.into());
    return Ok(());
}
```

to:

```rust
if apply_state.block_height >= delegate_action.max_block_height() {
    result.result = Err(ActionErrorKind::DelegateActionExpired.into());
    return Ok(());
}
```

This aligns the runtime check with the documented invariant ("below which the action is valid") and the spec statement ("equal or greater than `max_block_height`" triggers expiry). Update the error description in `errors.rs` from "less than" to "less than or equal to" accordingly.

### Proof of Concept
1. User signs a `DelegateAction` with `max_block_height = 1000`, intending the action to be invalid at block 1000 and beyond.
2. Relayer waits until the chain reaches block height 1000.
3. Relayer submits the meta-transaction at block 1000.
4. The runtime evaluates `apply_state.block_height (1000) > max_block_height (1000)` → `false` → no expiry error.
5. The action executes at block 1000, one block past the user's intended deadline.
6. The existing unit test `test_delegate_action` (line 1289) directly demonstrates this: it sets `block_height = max_block_height` and asserts `result.result.is_ok()`. [8](#0-7)

            &mut state_update,

            (&signed_delegate_action).into(),
            &mut result,
        )
