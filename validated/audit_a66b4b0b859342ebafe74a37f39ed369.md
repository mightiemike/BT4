## Title
Floor-and-drop signer-set weighting in `make_signer_set` lets many small (dust) stackers zero out the entire PoX signer set, stalling block production - (File: stackslib/src/chainstate/stacks/boot/mod.rs)

### Summary
`StacksChainState::make_signer_set` (used by the older, non-Hare PoX reward-set path) computes each signer's weight as `stacked_amt / threshold` and drops any signer whose weight floors to `0`. If the number of *distinct* signing keys registered for a cycle exceeds `reward_slots`, and enough of them stack similar/small amounts, this floor-and-drop scheme can filter out every candidate, yielding an empty signer set for the cycle. This mirrors the Velodrome class of bug: any unprivileged party can populate a bounded/weighted structure with many entries of their choosing to defeat the intended selection logic, denying legitimate use of that structure.

### Finding Description
`make_signer_set` in [1](#0-0)  aggregates stacked amounts per signing key, then computes `weight = stacked_amt / threshold` and unconditionally drops any entry with `weight == 0`: [2](#0-1) 

There is no fallback: if *every* aggregated entry floors to zero weight (e.g., because there are more distinct signers than `reward_slots`, each stacking roughly `total/threshold < 1`), the function returns `Some(vec![])` — an empty, but non-`None`, signer set — for that reward cycle.

Critically, this exact defect class has already been identified and fixed for the newer `pox_5_make_signer_set` path (Hare/largest-remainder allocation), which is directly documented as a regression fix in the test suite: [3](#0-2) 
The comment explicitly states: *"The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every signer's weight floored to 0 and the entire set was dropped -- stalling the chain."* That is a description of the exact algorithm still present, unpatched, in `make_signer_set` in `mod.rs`.

Any unprivileged Stacker/signer set participant can trigger this by having more distinct signing keys register than there are `reward_slots()` for that cycle, each stacking a comparable dust-relative amount so `stacked_amt / threshold` floors to 0 for all of them — analogous to the Velodrome attacker sending many small dust reward-token deposits to occupy/poison a shared bounded resource and deny its normal function.

### Impact Explanation
An empty signer set for a Nakamoto reward cycle means no valid signer weights exist to reach the block-signing/validation threshold for that cycle, which halts Nakamoto block production/finalization for the affected cycle — this is a chain-stall condition reachable without needing majority stake, only enough distinct signer registrations relative to `reward_slots`. This maps to the "temporary tip disagreement" / minority-triggerable divergence category, since nodes computing the same (broken) empty signer set would agree, but the network-visible effect is a denial of the tenure/signer-selection process, a consensus-relevant equality breaking between "intended signer set with weight > 0 for legitimate participants" and "actual signer set computed by the node."

### Likelihood Explanation
Likelihood is moderate: the number of distinct signing keys needed to exceed `reward_slots()` for a given cycle, and the specific dust-amount distribution needed to zero every weight, requires deliberate but unprivileged coordination — no majority stake is required, only enough distinct registrations. This is essentially the same setup the regression test in `signer_set.rs` was written to guard against for the newer algorithm, strongly suggesting the scenario is realistic enough to have prompted a fix elsewhere in the codebase.

### Recommendation
Apply the same Hare/largest-remainder (or equivalent minimum-guarantee) fix used in `pox_5_make_signer_set` to `make_signer_set` in `stackslib/src/chainstate/stacks/boot/mod.rs`, ensuring that when the floor-based threshold would zero out all entries, `min(reward_slots, distinct_signers)` slots are still guaranteed to top-ranked signers rather than dropping the entire set.

### Proof of Concept
1. For a cycle with `reward_slots() == R`, register `R + 1` (or more) distinct signing keys, each stacking approximately `total_stacked / R` uSTX (so `threshold ≈ total_stacked / R` and each individual `stacked_amt / threshold` rounds down to `0` due to the extra participant diluting the per-key average below threshold).
2. Call `StacksChainState::make_signer_set(threshold, &entries)` with these entries — as in the analogous test setup in `stackslib/src/chainstate/nakamoto/tests/signer_set.rs` lines 294–335, but exercised against the un-patched `make_signer_set` instead of `pox_5_make_signer_set`.
3. Observe that the function returns `Some(vec![])`: every entry's `weight` floors to `0` and is filtered out, leaving the reward cycle without any signer weight allocation, consistent with the documented regression this fix pattern was created to avoid.

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

#[test]
fn equal_stakes_exceeding_reward_slots_are_not_all_zeroed() {
    // Regression: more distinct signers than reward_slots, all with equal stake.
    //
    // The old floor-and-drop scheme set threshold = ceil(N*S / R) > S, so every
    // signer's weight floored to 0 and the entire set was dropped -- stalling the
    // chain. The Hare round must instead award one slot each to the top `R` signers
    // (by remainder, then signing_key), dropping only the surplus signers.
    let pox_constants = test_pox_constants(1); // reward_slots() == 4
    let reward_slots = pox_constants.reward_slots();
    assert_eq!(reward_slots, 4);
    let stake = 1_000_000u128;
    // 5 signers, only 4 slots.
    let entries: Vec<_> = (0..5u8)
        .map(|i| RawPox5Entry {
            signer_key: signer_key(i),
            amount_ustx: stake,
        })
        .collect();
    let mut iter = entries.into_iter().map(Ok);
    let Pox5SignerSetOutput { signer_set, .. } =
        NakamotoSigners::pox_5_make_signer_set(&mut iter, &pox_constants).expect("ok");

    assert_eq!(
        signer_set.len(),
        reward_slots as usize,
        "expected exactly reward_slots signers, not an empty/zeroed set"
    );
    for entry in &signer_set {
        assert_eq!(
            entry.weight, 1,
            "each surviving signer should hold one slot"
        );
    }
    let total_weight: u128 = signer_set.iter().map(|e| u128::from(e.weight)).sum();
    assert_eq!(total_weight, u128::from(reward_slots));
    // Ties broken by signing_key ascending: keys 0x00..0x03 win, 0x04 is dropped.
    assert!(
        !signer_set.iter().any(|e| e.signing_key == signer_key(0x04)),
        "highest-key signer should be the one dropped on tie-break"
    );
}
