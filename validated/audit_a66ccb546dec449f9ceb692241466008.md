### Title
Vault `accrue` Pause Silently Passes Through Stale Indexes Instead of Reverting, Letting Market Cache and Persist a Frozen Interest Index - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Each vault's `accrue` function, when the `accrue` pause flag is set, does not revert — it returns `(ok { index: idx, lindex: lidx })` using the *current* (stale) `index`/`lindex` data-vars, exactly mirroring the "pause that passes through instead of reverting" analog class. `market.clar`'s `accrue-and-cache` (via `vault-accrue`) calls this `accrue` entry point and unconditionally caches whatever it returns as the fresh per-block index, with no distinction between a genuinely-updated index and a paused pass-through value.

### Finding Description
`accrue` in the vault contracts branches on the `accrue` pause bit: [1](#0-0) 
When paused, it returns `ok` with the unchanged `idx`/`lidx` rather than an error, so any caller using `try!` proceeds normally as if accrual succeeded and time-based interest was applied — it was not.

`market.clar` routes to this exact function for interest accrual and caching: [2](#0-1) [3](#0-2) 

`accrue-and-cache` caches whatever `vault-accrue` (i.e., the vault's `accrue`) returns, keyed only by `{timestamp: stacks-block-time, aid}` — it has no way to tell that the vault silently skipped accrual because of the pause flag. `system-borrow` and other vault entry points also call `(try! (accrue))` as their first step and continue executing on the pass-through value: [4](#0-3) 

The root cause matches the required analog class precisely: a health/precondition-style operation (`accrue`) that should either update state or revert is instead made to pass through a stale value without error when paused, and the caller (`market.clar`'s debt/notional evaluation and vault borrow/repay/deposit/redeem flows) treats that stale value as authoritative for the remainder of the same call, including scaled-debt conversion, notional valuation, and health checks.

### Impact Explanation
While the `accrue` pause is active on a vault, every dependent computation in `market.clar` (debt notional valuation via `calculate-asset-notional-value`, scaled-debt-to-actual conversions in `borrow`/`repay`, and health checks) uses the frozen index instead of reverting the transaction. This means:
- Interest that should accrue to suppliers/treasury during the pause window is permanently lost for that period (the delta between `next-index` and the frozen `idx` is never applied once time has passed and the pause is lifted, because `last-update` is also not advanced during pause) — a **temporary/permanent freezing of unclaimed yield** for lenders and the DAO treasury's reserve-factor share.
- Because borrow/repay/health-check math silently uses stale indexes rather than aborting, positions can be opened, closed, or liquidated against economically incorrect debt/collateral valuations during the pause window, rather than the transaction being rejected as intended by a pause.

This lands in the in-scope **High** impact class: temporary freezing of unclaimed yield (interest/reserve-factor accrual that should have compounded is dropped rather than the operation reverting).

### Likelihood Explanation
This requires only the vault's `accrue` pause flag to be set (an operational/admin action already exposed by the pausability design) and at least one transaction to occur touching that vault while paused — a single-transaction condition, no cross-user interference, no DAO compromise needed to trigger the consequence (the DAO/admin merely uses the pause feature as designed; the bug is that the designed pause silently no-ops economic state instead of reverting the dependent operation). This is a normal single-block interleaving of a documented pause mechanism and standard borrow/repay/deposit/redeem calls.

### Recommendation
When the `accrue` pause flag is active, `accrue` (and any function relying on `try! (accrue)`) should either:
1. Revert with `ERR-PAUSED` instead of returning `ok` with stale values, so dependent operations (`system-borrow`, `system-repay`, deposit, redeem, and `market.clar`'s notional/health-check paths) also halt rather than silently computing on frozen indexes; or
2. Explicitly track and later reconcile the paused-period interest instead of dropping it, and mark the cached index as non-authoritative so `market.clar` does not treat it as a fresh accrual.

### Proof of Concept
1. DAO/admin calls `set-pause` (or equivalent) on `v0-vault-usdc.clar` setting the `accrue` pause bit to `true`.
2. Time passes across blocks such that `next-index` (computed from `next-index`/`next-liquidity-index`) would normally exceed the stored `index`/`lindex`.
3. A user calls `market.clar`'s `borrow` or `repay` for USDC; this triggers `accrue-and-cache` → `vault-accrue` → `.v0-vault-usdc accrue`. [5](#0-4) 
4. Because `(get accrue states)` is `true`, `accrue` returns `(ok { index: idx, lindex: lidx })` with the **old** `idx`/`lidx`, never updating `var-set index`, `var-set lindex`, or `var-set last-update`, and never minting the treasury's reserve share.
5. `market.clar` caches this stale value in `index-cache` for the current `stacks-block-time` and uses it for scaled-debt conversion and notional health checks in the same call — the transaction succeeds normally instead of reverting.
6. Once the pause is lifted, the interest that accrued during the paused window is never retroactively applied (the index jump from `idx` to what `next-index` would have been at the time is lost), permanently freezing that portion of yield for suppliers and the DAO treasury.
