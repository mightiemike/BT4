### Title
Unbounded `getAssetIssueList` response enables RPC-API response-serialization/memory DoS - (File: `framework/src/main/java/org/tron/core/services/http/GetAssetIssueListServlet.java`)

### Summary
`GetAssetIssueListServlet` calls `Wallet.getAssetIssueList()`, which in turn calls `AssetIssueStore.getAllAssetIssues()` [1](#0-0) , materializing and serializing **every** TRC10 asset ever issued on-chain with no cap, unlike the paginated sibling endpoint `GetPaginatedAssetIssueListServlet` which enforces `ASSET_ISSUE_COUNT_LIMIT_MAX` [2](#0-1) . Since asset issuance is a permissionless, fee-gated action available to any funded account, an attacker can inflate the total number of stored assets (K) over time and then repeatedly hit the unpaginated endpoint to force linear-to-unbounded per-request work and response size.

### Finding Description
`GetAssetIssueListServlet.doGet` unconditionally invokes `wallet.getAssetIssueList()` with no offset/limit parameters and serializes the full result via `JsonFormat.printToString` [3](#0-2) . The backing store method `getAllAssetIssues()` streams the entire `asset-issue` column family into a `List<AssetIssueCapsule>` with no size limit [1](#0-0) , in contrast to `getAssetIssuesPaginated`, which explicitly caps `limit` to `ASSET_ISSUE_COUNT_LIMIT_MAX` [4](#0-3) .

The only existing protective layer is `RateLimiterServlet`, which enforces a per-endpoint/global QPS limit but does not bound the *size* of work or response per accepted request [5](#0-4) . This means each accepted request still does O(K) DB reads and O(K) JSON serialization, so as K (total issued assets) grows, per-request cost and memory footprint grow without bound, and this cost is multiplied by however many requests the QPS limiter allows.

The attack path is fully permissionless: any funded account can broadcast `AssetIssueContract` transactions to increase K (paying the network's asset issuance fee each time), and then any anonymous client can call `/wallet/getassetissuelist` repeatedly.

### Impact Explanation
This matches TRON's "DoS via RPC-API" bounty impact class: growing K increases CPU (DB scan + JSON serialization) and memory (holding all `AssetIssueCapsule` objects and the resulting JSON string) consumed per request to this single HTTP endpoint, without any endpoint-level cap analogous to the paginated version. Repeated/concurrent requests under the existing QPS allowance amplify this into node-level resource pressure that can degrade or stall the HTTP API for other users. It does not affect consensus or state integrity — it is scoped to API-layer availability.

### Likelihood Explanation
- Cost to attacker: each additional asset requires paying the network's TRC10 asset-issuance fee (`getAssetIssueFee`, dynamic-property-configured, historically ~1024 TRX by default) via `AssetIssueActuator`, so scaling K to a level that meaningfully impacts server memory/CPU requires sustained capital outlay and is not free.
- The rate limiter bounds request frequency but not per-request cost, so the vulnerability is about *unbounded per-request work*, not about bypassing authentication or rate limits.
- Feasibility is real but bounded by economics: an attacker needs to accumulate a large K (many thousands of assets) to make the effect significant, and each is a paid, on-chain, auditable transaction — making this a moderate-likelihood, low-to-moderate severity availability issue rather than a trivial free DoS.

### Recommendation
- Apply the same offset/limit pagination logic used in `getAssetIssuesPaginated`/`GetPaginatedAssetIssueListServlet` to `getAssetIssueList`/`GetAssetIssueListServlet`, or hard-cap the number of assets returned per call to `ASSET_ISSUE_COUNT_LIMIT_MAX`.
- Alternatively, deprecate/gate the unpaginated `getassetissuelist` endpoint behind an explicit maximum result size and document/enforce pagination as mandatory once total asset count exceeds a threshold.

  private List<AssetIssueCapsule> getAssetIssuesPaginated(List<AssetIssueCapsule> assetIssueList,
      long offset, long limit) {
    if (limit < 0 || offset < 0) {
      return null;
    }

    if (assetIssueList.size() <= offset) {
      return null;
    }
    assetIssueList.sort((o1, o2) -> {
      if (o1.getName() != o2.getName()) {
        return o1.getName().toStringUtf8().compareTo(o2.getName().toStringUtf8());
      }
      return Long.compare(o1.getOrder(), o2.getOrder());
    });
    limit = limit > ASSET_ISSUE_COUNT_LIMIT_MAX ? ASSET_ISSUE_COUNT_LIMIT_MAX : limit;
    long end = offset + limit;
    end = end > assetIssueList.size() ? assetIssueList.size() : end;
    return assetIssueList.subList((int) offset, (int) end);
  }

  @Override
  protected void service(HttpServletRequest req, HttpServletResponse resp)
      throws ServletException, IOException {

    RuntimeData runtimeData = new RuntimeData(req);
    IRateLimiter rateLimiter = container.get(KEY_PREFIX_HTTP, getClass().getSimpleName());

    // Check per-endpoint first to avoid consuming global IP/QPS quota for requests
    // that would be rejected by the per-endpoint limiter anyway. acquirePermit()
    // chooses blocking or non-blocking semantics based on rate.limiter.apiNonBlocking.
    boolean perEndpointAcquired = rateLimiter == null || rateLimiter.acquirePermit(runtimeData);
    boolean acquireResource = perEndpointAcquired && GlobalRateLimiter.acquirePermit(runtimeData);

    String contextPath = req.getContextPath();
    String url = Strings.isNullOrEmpty(req.getServletPath())
        ? MetricLabels.UNDEFINED : contextPath + req.getServletPath();
    // int64_as_string is honored only on GET requests (URL query). POST is intentionally
    // unsupported because reading the body here would consume request.getReader() and
    // break downstream servlets that read it themselves.
    if ("GET".equalsIgnoreCase(req.getMethod())) {
      JsonFormat.setInt64AsString(Util.getInt64AsString(req));
    }
    try {
      resp.setContentType("application/json; charset=utf-8");

      if (acquireResource) {
        Histogram.Timer requestTimer = Metrics.histogramStartTimer(
            MetricKeys.Histogram.HTTP_SERVICE_LATENCY, url);
        super.service(req, resp);
        Metrics.histogramObserve(requestTimer);
      } else {
        resp.getWriter()
            .println(Util.printErrorMsg(new IllegalAccessException("lack of computing resources")));
      }
    } catch (ServletException | IOException | BadMessageException e) {
      throw e;
    } catch (Exception unexpected) {
      logger.error("Http Api {}, Method:{}. Error：", url, req.getMethod(), unexpected);
    } finally {
      // CRITICAL: this clear pairs with the setInt64AsString call above. Removing it
      // will leak int64_as_string state across requests on reused Tomcat threads,
      // producing intermittent quoted/unquoted output that is very hard to debug.
      JsonFormat.clearInt64AsString();
      // Release whenever the per-endpoint permit was acquired (covers both the normal
      // completion path and the case where GlobalRateLimiter rejected the request).
      if (rateLimiter instanceof IPreemptibleRateLimiter && perEndpointAcquired) {
        ((IPreemptibleRateLimiter) rateLimiter).release();
      }
    }
  }
