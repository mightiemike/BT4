The reported issue is specific to Curve Finance's StableSwap AMM invariant, where deposits into an imbalanced liquidity pool incur non-linear bonus/penalty fees based on deviation from the "ideal balance," and a vault's forced proportional-join logic prevents exploiting/avoiding those fees. This is a DeFi liquidity-pool mechanics bug class entirely dependent on Curve's `add_liquidity` fee formula tied to pool token ratios.

Nearcore has no analogous on-chain AMM, liquidity pool, or bonded-curve invariant in its protocol logic. The reward-distribution code that is proportionally weighted by stake, `RewardCalculator::calculate_reward`, distributes tokens by a fixed pro-rata formula rather than an invariant-based bonus/penalty scheme, so there is no "optimal vs. proportional" trade-off to exploit. [1](#0-0) 
Other proportionality/imbalance-related mechanisms found in nearcore — the bandwidth scheduler's `link_imbalance_ratio` [2](#0-1) 
and sticky-resharding stake balancing [3](#0-2) 
are unrelated to a transaction-triggered deposit/fee-bonus exploit and involve no unauthorized value movement, supply inflation, or state-root divergence reachable by a single submitted transaction or RPC call.

Given the absence of any AMM/liquidity-pool primitive in nearcore's transaction/runtime/staking paths, this bug class has no valid reachable analog.
