### Title
Global contracts deployed with `GlobalContractDeployMode::AccountId` let an unprivileged owner instantly rewrite shared logic for all dependent accounts with no delay/announcement mechanism, enabling front-running of any user transaction that relies on the previous code - ([File: runtime/runtime/src/global_contracts.rs])

### Summary
The original finding is about an AMM pool owner using `changeSpotPrice()`/`changeDelta()` to instantaneously change trade parameters and front-run a trader, with no timelock protecting counterparties. The reachable nearcore analog is the "update by account id" mode of global contracts: any unprivileged account can deploy a `DeployGlobalContractAction` with `GlobalContractDeployMode::AccountId`, which lets that same account overwrite the shared code referenced by `GlobalContractIdentifier::AccountId(owner)` at will, with no delay, no announcement, and no protection for accounts that have already opted in via `UseGlobalContractAction`.

### Finding Description
`action_deploy_global_contract` (`runtime/runtime/src/global_contracts.rs:23-61`) processes a `DeployGlobalContractAction` from any signer. When `deploy_mode == GlobalContractDeployMode::AccountId`, `initiate_distribution` computes the contract identifier as `GlobalContractIdentifier::AccountId(account_id)` (`global_contracts.rs:149-156`) — i.e., keyed purely by the deployer's own account id, which the deployer fully controls forever. The design intent is explicit in the type documentation: "Contract is deployed under the owner account id... This allows the owner to update the contract for all its users" (`core/primitives/src/action/mod.rs:138-141`).

Other, unprivileged accounts opt in to this shared code via `UseGlobalContractAction`, handled by `use_global_contract` (`runtime/runtime/src/global_contracts.rs:74-107`), which simply sets `AccountContract::GlobalByAccount(id)` on their own account (`:93-95`). From that point, every future function call against the user's account resolves its code dynamically through `RuntimeContractIdentifier::resolve` (`runtime/runtime/src/contract_code.rs:36-73`), which re-reads whatever code currently lives under `TrieKey::GlobalContractCode { identifier: AccountId(owner) }`.

Critically, there is no delay, no advance announcement, and no cooldown between an owner submitting a new `DeployGlobalContractAction` and that code becoming the active code for every account that referenced it by account id. The only anti-replay mechanism is a monotonically increasing nonce (`increment_nonce` / `check_and_update_nonce`, `global_contracts.rs:171-256`), which exists solely to make cross-shard distribution idempotent against out-of-order/duplicate `GlobalContractDistribution` receipts — it provides no timelock or transparency guarantee to dependent accounts. This is structurally identical to `LSSVMPair.changeSpotPrice()`/`changeDelta()`: a privileged-but-reachable-by-anyone actor can rewrite the rules that other parties are relying on, instantaneously and unannounced, and those other parties' pending or future transactions execute against whatever logic is live at apply time.

### Impact Explanation
An account or protocol that has called `UseGlobalContractAction` to point at `GlobalContractIdentifier::AccountId(owner)` is delegating control of its own contract logic (and, transitively, of any funds/state that the logic gates) to `owner` indefinitely and without notice. `owner` can:
1. Publish a benign/audited version of the contract to attract users to call `UseGlobalContractAction`.
2. Wait until users have funds or approvals resting on accounts running that shared code.
3. Submit a new `DeployGlobalContractAction` with malicious code under the same `AccountId` identifier; as soon as the corresponding `GlobalContractDistribution` receipt lands on a shard (`apply_distribution_current_shard`, `global_contracts.rs:189-233`), any account referencing that identifier on that shard is silently running the new code on its very next receipt/function call.

This can produce unauthorized value movement (the new code can transfer/burn balances of dependent accounts, refuse withdrawals, or redirect calls) — directly analogous to the owner in the original report setting `spotPrice` to 0 immediately before a trade executes. Because the update takes effect with no timelock, a user cannot meaningfully protect themselves the way `minExpectedTokenOutput`/`maxExpectedTokenInput` protect LSSVMPair traders, since the "trade" here is simply "my account's code did whatever the current global contract owner decided it should do."

### Likelihood Explanation
Likelihood is moderate: it requires (a) a global contract published in `AccountId` mode, and (b) other accounts choosing to adopt it via `UseGlobalContractAction`. Both actions are freely available to any unprivileged signer with no special permission — `DeployGlobalContractAction` and `UseGlobalContractAction` are ordinary actions validated in `runtime/runtime/src/action_validation.rs` and executed by any account. The `AccountId` deploy mode is a first-class, documented, supported protocol feature (not a corner case), so any dApp/user that relies on it for code-sharing/upgradability inherits this exact risk, matching the "owner promises high price then rugs on execution" pattern from the source report.

### Recommendation
Since this mirrors the original recommendation of introducing a delay: consider a similar two-phase mechanism for `GlobalContractDeployMode::AccountId` updates — e.g., require a new deployment under an existing `AccountId` identifier to be "announced" (recorded on-chain with the new code hash) and only become active for existing `GlobalByAccount` consumers after a minimum number of blocks/epochs, or emit a distinguishable event so dependent contracts/off-chain monitors can react before the switch. At minimum, document prominently (which the code comment partially does) that `UseGlobalContractAction(AccountId(...))` grants the identified account perpetual, instantaneous, unannounced control over the consumer's contract logic, and encourage integrators to prefer `GlobalContractDeployMode::CodeHash` (immutable) unless they trust the owner with continuous update authority equivalent to a full-access key.

### Proof of Concept
1. Account `owner` submits `DeployGlobalContractAction { code: benign_code, deploy_mode: AccountId }` (`global_contracts.rs:23`), which is distributed to all shards via `GlobalContractDistribution` receipts (`global_contracts.rs:109-139`, `275-320`).
2. Account `victim` submits `UseGlobalContractAction { contract_identifier: AccountId(owner) }`; `use_global_contract` sets `victim.contract = AccountContract::GlobalByAccount(owner)` (`global_contracts.rs:74-107`). `victim` now depends on `owner`'s code for all its function calls.
3. `owner` submits a second `DeployGlobalContractAction { code: malicious_code, deploy_mode: AccountId }` using the same `AccountId` identifier. `initiate_distribution` bumps the nonce and issues a new `GlobalContractDistribution` receipt (`global_contracts.rs:141-169`).
4. As soon as `apply_distribution_current_shard` applies this receipt on `victim`'s shard (`global_contracts.rs:189-233`), the trie entry `TrieKey::GlobalContractCode { AccountId(owner) }` is overwritten with `malicious_code` — with no delay and no separate confirmation step.
5. Any subsequent call to `victim`'s account (e.g., a transfer/withdraw method) is resolved through `RuntimeContractIdentifier::resolve` (`runtime/runtime/src/contract_code.rs:36-73`) straight to `malicious_code`, executing attacker logic in the context of `victim`'s account/funds, exactly analogous to the LSSVMPair owner front-running a trade by zeroing the spot price right before execution. pub(crate) fn action_deploy_global_contract(
    state_update: &mut TrieUpdate,
    account: &mut Account,
    account_id: &AccountId,
    apply_state: &ApplyState,
    deploy_contract: &DeployGlobalContractAction,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let _span = tracing::debug_span!(target: "runtime", "action_deploy_global_contract").entered();

    let storage_cost = apply_state
        .config
        .fees
        .storage_usage_config
        .global_contract_storage_amount_per_byte
        .saturating_mul(deploy_contract.code.len() as u128);
    let Some(updated_balance) = account.amount().checked_sub(storage_cost) else {
        result.result = Err(ActionErrorKind::LackBalanceForState {
            account_id: account_id.clone(),
            amount: storage_cost,
        }
        .into());
        return Ok(());
    };
    result.tokens_burnt =
        result.tokens_burnt.checked_add(storage_cost).ok_or(IntegerOverflowError)?;
    account.set_amount(updated_balance);

    initiate_distribution(
        state_update,
        account_id.clone(),
        deploy_contract.code.clone(),
        &deploy_contract.deploy_mode,
        apply_state.shard_id,
        result,
    )?;

    Ok(())
}

pub(crate) fn use_global_contract(
    state_update: &mut TrieUpdate,
    account_id: &AccountId,
    account: &mut Account,
    contract_identifier: &GlobalContractIdentifier,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let key = TrieKey::GlobalContractCode { identifier: contract_identifier.clone().into() };
    if !state_update.contains_key(&key, AccessOptions::DEFAULT)? {
        result.result = Err(ActionErrorKind::GlobalContractDoesNotExist {
            identifier: contract_identifier.clone(),
        }
        .into());
        return Ok(());
    }
    clear_account_contract_storage_usage(state_update, account_id, account)?;
    if account.contract().is_local() {
        state_update.remove(TrieKey::ContractCode { account_id: account_id.clone() });
    }
    let contract = match contract_identifier {
        GlobalContractIdentifier::CodeHash(code_hash) => AccountContract::Global(*code_hash),
        GlobalContractIdentifier::AccountId(id) => AccountContract::GlobalByAccount(id.clone()),
    };
    account.set_storage_usage(
        account.storage_usage().checked_add(contract_identifier.len() as u64).ok_or_else(|| {
            StorageError::StorageInconsistentState(format!(
                "Storage usage integer overflow for account {}",
                account_id
            ))
        })?,
    );
    account.set_contract(contract);
    Ok(())
}

fn initiate_distribution(
    state_update: &mut TrieUpdate,
    account_id: AccountId,
    contract_code: Arc<[u8]>,
    deploy_mode: &GlobalContractDeployMode,
    current_shard_id: ShardId,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let id = match deploy_mode {
        GlobalContractDeployMode::CodeHash => {
            GlobalContractIdentifier::CodeHash(hash(&contract_code))
        }
        GlobalContractDeployMode::AccountId => {
            GlobalContractIdentifier::AccountId(account_id.clone())
        }
    };
    // Increment the nonce and write it to state immediately to prevent multiple
    // distributions with the same nonce from being initiated. This requires
    // allowing the same nonce in the freshness check when applying the
    // distribution receipt.
    let nonce = increment_nonce(state_update, &id)?;
    let distribution_receipt =
        GlobalContractDistributionReceipt::new(id, current_shard_id, vec![], contract_code, nonce);
    let distribution_receipts =
        Receipt::new_global_contract_distribution(account_id, distribution_receipt);
    // No need to set receipt_id here, it will be generated as part of apply_action_receipt
    result.new_receipts.push(distribution_receipts);
    Ok(())
}

fn apply_distribution_current_shard(
    receipt: &Receipt,
    global_contract_data: &GlobalContractDistributionReceipt,
    apply_state: &ApplyState,
    state_update: &mut TrieUpdate,
) -> Result<Compute, RuntimeError> {
    let identifier = match &global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => GlobalContractCodeIdentifier::CodeHash(*hash),
        GlobalContractIdentifier::AccountId(account_id) => {
            GlobalContractCodeIdentifier::AccountId(account_id.clone())
        }
    };

    let is_nonce_fresh = check_and_update_nonce(global_contract_data, &identifier, state_update)?;
    if !is_nonce_fresh {
        return Ok(0);
    }

    let config = apply_state.config.wasm_config.clone();
    let trie_key = TrieKey::GlobalContractCode { identifier };
    let code_len = global_contract_data.code().len() as u64;
    state_update.set(trie_key, global_contract_data.code().to_vec());
    state_update.commit(StateChangeCause::ReceiptProcessing { receipt_hash: receipt.get_hash() });
    let code_hash = match global_contract_data.id() {
        GlobalContractIdentifier::CodeHash(hash) => Some(*hash),
        GlobalContractIdentifier::AccountId(_) => None,
    };
    precompile_contract_with_warming(
        &ContractCode::new(global_contract_data.code().to_vec(), code_hash),
        config,
        apply_state.next_wasm_config.clone(),
        apply_state.cache.as_deref(),
    );
    near_vm_runner::report_metrics(apply_state.shard_id, "global_contract");
    let fees = &apply_state.config.fees;
    let per_byte_total = fees
        .deploy_global_contract_execution_per_byte
        .checked_mul(code_len)
        .ok_or(IntegerOverflowError)?;
    let compute = fees
        .deploy_global_contract_execution_base
        .checked_add(per_byte_total)
        .ok_or(IntegerOverflowError)?;
    Ok(compute)
}

// Checks if the incoming nonce is fresh and updates the stored nonce. Returns
// true if the nonce is fresh, false if it's stale. The nonce is set
// immediately and the freshness check allows the same nonce (>=).
fn check_and_update_nonce(
    global_contract_data: &GlobalContractDistributionReceipt,
    identifier: &GlobalContractCodeIdentifier,
    state_update: &mut TrieUpdate,
) -> Result<bool, RuntimeError> {
    let nonce_key = TrieKey::GlobalContractNonce { identifier: identifier.clone() };
    let stored_nonce = get_nonce(state_update, &nonce_key)?;
    let incoming_nonce = global_contract_data.nonce();

    // Allow the same nonce since the nonce is updated immediately when
    // initiating distribution to prevent multiple distributions with the same
    // nonce from being initiated.
    if incoming_nonce < stored_nonce {
        return Ok(false);
    }

    set_nonce(state_update, nonce_key, incoming_nonce);
    Ok(true)
}

    pub(crate) fn resolve(
        account_id: &AccountId,
        account_contract: AccountContract,
        state_update: &TrieUpdate,
        chain_id: &str,
        access: AccessOptions,
    ) -> Result<Self, StorageError> {
        let local_hash = match GlobalContractIdentifier::try_from(account_contract) {
            Ok(gci) => {
                let code_hash = gci.clone().hash(state_update, access)?;
                return Ok(RuntimeContractIdentifier::Global { code_hash, identifier: gci });
            }
            Err(ContractIsLocalError::NotDeployed) => return Ok(RuntimeContractIdentifier::None),
            Err(ContractIsLocalError::Deployed(local_hash)) => local_hash,
        };

        if account_id.get_account_type() == AccountType::EthImplicitAccount {
            // Accounts that look like eth implicit accounts and have existed prior to the
            // eth-implicit accounts protocol change (these accounts are discussed in the
            // description of #11606) may have something else deployed to them. Only return
            // something here if the accounts have a wallet contract hash. Otherwise use the
            // regular path to grab the deployed contract.
            if LegacyEthWallet::resolve(local_hash).is_some() {
                // ETH implicit wallet accounts use global contracts, including
                // those created in old protocol versions.
                let global_hash = eth_wallet_global_contract_hash(chain_id);
                return Ok(RuntimeContractIdentifier::Global {
                    code_hash: global_hash,
                    identifier: GlobalContractIdentifier::CodeHash(global_hash),
                });
            }
        }

        Ok(RuntimeContractIdentifier::AccountLocal {
            code_hash: local_hash,
            account_id: account_id.clone(),
        })
    }
