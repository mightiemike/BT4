### Title
Starknet OS `replace_class` syscall omits declared-class check enforced by Blockifier, causing OS re-execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `DebtRegistry` bug class is "an authorized caller can set a value to a null/invalid sentinel through a legitimate entry point, breaking an invariant that downstream logic relies on being always valid." The analogous pattern exists in the Starknet OS's Cairo implementation of the `replace_class` syscall, which — unlike the Rust/Blockifier implementation used to actually build blocks — does not validate that the new `class_hash` corresponds to a declared class before writing it into contract state.

### Finding Description
Any deployed Cairo1 contract can call the `replace_class` syscall to change its own stored `class_hash`. In Blockifier (the execution engine that actually builds blocks), the syscall handler for `replace_class` explicitly enforces that the target class hash is declared before updating state: [1](#0-0) 

In the Starknet OS's Cairo implementation of the same syscall (used for OS re-execution / proof generation of the block), there is no such check — it is explicitly marked with a TODO indicating the validation is missing: [2](#0-1) 

The deprecated (Cairo0) OS syscall path has the same gap — it directly overwrites `class_hash` in the state entry without checking that the class was declared: [3](#0-2) 

This is precisely the same class of bug as the `DebtRegistry` issue: a downstream invariant ("a contract's stored `class_hash` always refers to a declared class") is assumed throughout the system (e.g., `execute_deployment` checks `current_class_hash != ClassHash::default()` to detect address reuse, and general execution logic dereferences `state.get_class_hash_at` results to fetch compiled code) but a legitimate, unprivileged entry point (`replace_class`, callable by any contract on itself) can violate it in the OS's implementation, even though Blockifier's implementation does enforce it.

### Impact Explanation
Blockifier is the authoritative execution engine whose results are committed as the actual block state and state root. The Starknet OS's Cairo implementation is executed later to reproduce that same execution and produce a STARK proof attesting to its correctness. If a contract calls `replace_class` with an undeclared (or otherwise invalid, e.g. zero) `class_hash`:
- Blockifier will reject the syscall with an "is not declared" error and revert/fail the call, per the check at `hint_processor.rs:801`.
- The OS's re-execution of the identical transaction will, per the code above, silently accept the write and continue execution successfully.

This produces a concrete honest-node divergence between the actual (committed) execution outcome and the OS's re-execution/proof of that block: the OS would compute a different execution result (success vs. revert) and a different state diff than what was actually committed by the sequencer. This can lead to the OS/prover being unable to reproduce the correct state root for the block (breaking the OS-to-blockifier consistency guarantee that underlies proof soundness), or, in the worst case, having the OS treat the contract as running under an unvalidated/undeclared class going forward, which the rest of the OS logic assumes is always a valid declared class (used to fetch compiled code, run entry points, etc.), potentially causing incorrect or undefined OS behavior during the remainder of block re-execution.

### Likelihood Explanation
Likelihood is high in terms of reachability: any account or contract can trivially invoke the `replace_class` syscall as an unprivileged transaction sender with an arbitrary, unvalidated `class_hash` argument — this requires no special privileges, only a standard contract call. The only barrier is that Blockifier itself already blocks such a state write from being committed, so exploitation depends specifically on how divergence between Blockifier's authoritative execution and the OS's re-execution is handled by the proving/verification pipeline.

### Recommendation
Add the same declared-class check in the OS's Cairo `execute_replace_class` implementations (both the current syscall path in `syscall_impls.cairo` and the deprecated path in `deprecated_execute_syscalls.cairo`) that Blockifier already performs — i.e., verify the class hash exists in the declared classes dict/state before writing the new `StateEntry`, matching the `get_compiled_class` check performed in `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:801`. Resolve the existing `TODO(Yoni, 1/1/2026)` comment at `syscall_impls.cairo:902` as part of this fix.

### Proof of Concept
1. Attacker deploys a contract (Cairo1) exposing a function that calls the `replace_class` syscall with an arbitrary, undeclared `class_hash` (e.g., `0x1234`, never declared on-chain).
2. Submit an invoke transaction calling this function.
3. In Blockifier (actual block building), the call fails/reverts because `get_compiled_class(request.class_hash)` fails ("is not declared"), as shown by the existing test: [4](#0-3) 
4. When the same transaction is re-executed by the Starknet OS (Cairo) for proof generation, `execute_replace_class` in `syscall_impls.cairo` performs no declared-class check and would proceed to overwrite the `StateEntry.class_hash` unconditionally, producing a different execution result/state diff than Blockifier's actual (reverted) outcome — a divergence between the committed block and its OS-generated proof trace.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,

    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
