### Title
Interest Accrual Pause Silently No-Ops Instead of Reverting, Allowing Debt Repayment/Borrowing on Stale Index - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

### Summary
Every vault's `accrue` function is guarded by an operational pause flag. When `accrue` is paused, the function does not revert the caller — it silently returns the **stale** cached `index`/`lindex` as if the operation succeeded. `system-borrow` and `system-repay` both invoke `accrue` as their first step and then immediately use its return value to compute scaled debt/principal changes, without any check that the returned index actually reflects real accrued interest. This lets debt be opened or closed against a frozen index while economically-due interest is silently skipped, permanently misstating supplier yield.

### Finding Description
`accrue` in the vault contracts explicitly passes through without reverting when paused: [1](#0-0) 

```clarity
(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ...
```

`system-borrow` and `system-repay` both call `accrue` first and then compute scaled amounts / total debt from `var-get index` / `total-debt`, which — while paused — are the stale pre-pause values rather than values reflecting real elapsed-time interest: [2](#0-1) [3](#0-2) 

Because the pause check only gates the *index update*, not the *dependent debt-mutating operation*, `system-borrow`/`system-repay` proceed with a mutation (opening/closing debt, moving `assets`/`total-borrowed`) that is evaluated against a guard value (`idx`) that was supposed to reflect current economic state but doesn't while paused. This is the same root-cause shape as the referenced report: a value that should be refreshed/invalidated before being consumed is instead reused, and the consuming write proceeds anyway rather than being blocked.

### Impact Explanation
While `accrue` is paused for a vault, a borrower can call `repay` (via `market.clar`/`v0-4-market.clar`, which itself calls `system-repay`) and have their scaled principal fully cleared using the stale index — i.e., they repay less than the economically accrued debt would require once accrual resumes and interest is retroactively due. The interest owed to suppliers for the elapsed real time is never captured because the vault's principal/assets accounting was mutated (debt closed) at the stale index. This is a **permanent loss of unclaimed yield to LPs/suppliers** — the debt is gone, so the interest can never be later recovered from that position. It similarly lets a borrower `system-borrow` against a stale index, understating the true utilization/health calculations that feed into market-level LTV checks in the same transaction.

### Likelihood Explanation
This requires the vault to be in the `accrue`-paused operational state (a normal, expected operational control the protocol exposes) combined with a borrower calling `repay`/`borrow` during that window — a single transaction, no collusion or privileged compromise needed beyond the pause being active (which is a legitimate, documented operational state, not a compromise). Given pauses are intended for maintenance/incident response, and normal user-facing borrow/repay entry points remain callable, likelihood is moderate: any user who notices the accrue-pause state can time a repay to avoid paying due interest.

### Recommendation
`system-borrow` and `system-repay` (and any other debt-mutating vault entry point) should revert (not silently proceed) when `accrue` is paused, or `accrue` itself should propagate an error state instead of an `(ok ...)` pass-through so downstream `try!`/`unwrap!` calls abort the whole operation. This mirrors the standard fix pattern of the referenced report: guard state must be honored by the consuming logic, not silently reused.

### Proof of Concept
1. DAO/operator sets the vault's `pause-states.accrue` to `true` for `vault-stx` (or any vault) via the normal pause-toggle path (an intended operational control, not a compromise).
2. Time passes on-chain such that real accrued interest would be non-zero if `accrue` executed normally (`next-index` > current `index`).
3. Borrower with outstanding scaled debt calls `market.clar` `repay`, which calls `vault-stx.system-repay`.
4. Inside `system-repay`, `(try! (accrue))` returns `{index: idx, lindex: lidx}` — the stale, pre-pause values — because `pause-states.accrue` is `true`.
5. `total-debt` and `capped-amount` are computed from this stale `idx`, understating the true debt owed.
6. Borrower repays `capped-amount`, `principal-scaled` is fully zeroed (`updated-scaled-principal`), and `total-borrowed`/`assets` are updated based on the understated amount — permanently discharging the position without ever paying the interest that was economically due for the elapsed period.
