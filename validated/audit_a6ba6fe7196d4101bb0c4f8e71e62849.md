## Title
Missing L1-address range validation in the Starknet OS `send_message_to_l1` syscall causes OS/blockifier execution divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The reported bug class ("un-validated destination address on a permissionless, user-triggered exit path, leading to fund loss with no on-chain safety check") maps onto Starknet's `send_message_to_l1` syscall path. In the Rust blockifier, the destination address of an L2→L1 message is validated as a proper 160-bit Ethereum address before the message is admitted; in the Cairo Starknet-OS implementation of the very same syscall, no such validation exists.

### Finding Description
Any account/contract can call `send_message_to_l1_syscall(to_address, payload)` from an ordinary invoke transaction. In the blockifier (the execution engine used for block building), this is validated: [1](#0-0) 

and identically in the deprecated (Cairo 0) syscall handler: [2](#0-1) 

`EthAddress::try_from` rejects any felt value `>= 2^160`, and the accompanying test confirms this is enforced (`error_string.contains("Out of range")`) for non-L3 chains: [3](#0-2) 

However, the Starknet OS - the Cairo program that re-executes the block to produce the STARK proof that is ultimately what the L1 Starknet Core contract trusts - implements the same syscall without any bound check on `to_address`: [4](#0-3) 

The equivalent Cairo 0 path (`deprecated_execute_syscalls.cairo`) also copies `syscall.to_address` straight into the `MessageToL1Header` with no validation: [5](#0-4) 

Neither `execute_send_message_to_l1` implementation checks that `request.to_address` fits in 160 bits, unlike the Rust side which explicitly performs `EthAddress::try_from(...)`.

### Impact Explanation
This is a divergence between the sequencer's fast execution path (blockifier, used to decide whether a transaction reverts and to build the block/receipts) and the Starknet OS path (used to generate the validity proof that is verified on L1). For a transaction that calls `send_message_to_l1` with `to_address >= 2^160`:
- Blockifier reverts the transaction (the syscall returns an error), so the block built by the sequencer records the transaction as failed and emits no L2→L1 message.
- The Starknet OS, re-executing the same contract bytecode independently in Cairo, has no equivalent check, so it will accept the out-of-range value and commit it into the `messages_to_l1` output segment that becomes part of the OS output / block hash inputs.

This breaks the fundamental soundness invariant that OS re-execution must reproduce blockifier's results bit-for-bit. Concretely this can cause: (a) an inability to build a consistent state transition proof for a block that blockifier already finalized (since the two engines compute different outcomes for the same transaction, i.e., honest-node/engine divergence), and (b) if the mismatch is not caught elsewhere in the OS input-consistency checks, a committed L2→L1 message with a felt value outside the 160-bit Ethereum address range gets embedded into the proven output. Because the L1 Starknet Core contract (and any L1 consumer contract) treats these values as `address` (160-bit), an out-of-range felt will be silently truncated on L1, delivering the message to an unintended/collided Ethereum address — the same "wrong destination, no recovery" fund-loss pattern as the original report, but arising from an inconsistency in a core consensus-critical component rather than a simple missing input check in a bridge contract.

### Likelihood Explanation
Triggering the missing check only requires a single unprivileged invoke transaction from any account calling `send_message_to_l1_syscall` with a `to_address` felt `>= 2^160` — no special privileges, staking, or proving role required. This is directly reachable from ordinary user-submitted transactions, matching an allowed category (blockifier execution / syscalls / Starknet OS re-execution).

### Recommendation
Add the same `to_address < 2^160` (EthAddress) range validation to both `execute_send_message_to_l1` (Cairo 1 syscalls, `syscall_impls.cairo`) and the deprecated Cairo 0 handler (`deprecated_execute_syscalls.cairo`) in the Starknet OS, mirroring the `EthAddress::try_from` check already present in `crates/blockifier/src/execution/syscalls/syscall_base.rs` and `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`, including the `is_l3` exemption used on the Rust side, so both execution engines reject/accept the exact same set of `to_address` values.

### Proof of Concept
1. Deploy/call a Cairo 1 contract (e.g. the test contract's `test_send_message_to_l1` entry point) from an ordinary invoke transaction, passing `to_address = 0x10000000000000000000000000000000000000000` (i.e., `2^168`, clearly `>= 2^160`) and an arbitrary payload.
2. Under blockifier (sequencer execution), this reverts as shown by the existing test `test_send_message_to_l1_invalid_address` (non-L3 case) with error `"Out of range"`: [6](#0-5) .
3. Feed the same transaction/calldata directly into the Starknet OS's `execute_send_message_to_l1` Cairo function: no assertion checks the magnitude of `to_address`, so it is written unchanged into `outputs.messages_to_l1` [7](#0-6) , demonstrating the OS accepts what blockifier rejects.

    pub fn send_message_to_l1(&mut self, message: MessageToL1) -> SyscallResult<()> {
        if !self.context.tx_context.block_context.chain_info.is_l3 {
            EthAddress::try_from(message.to_address)?;
        }
        let ordered_message_to_l1 =
            OrderedL2ToL1Message { order: self.context.n_sent_messages_to_l1, message };
        self.l2_to_l1_messages.push(ordered_message_to_l1);
        self.context.n_sent_messages_to_l1 += 1;

        Ok(())
    }

// Sends a message to L1.
func execute_send_message_to_l1{range_check_ptr, syscall_ptr: felt*, outputs: OsCarriedOutputs*}(
    contract_address: felt
) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, SendMessageToL1Request*);
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=SEND_MESSAGE_TO_L1_GAS_COST, request_struct_size=SendMessageToL1Request.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    tempvar payload_start = request.payload_start;
    tempvar payload_size = request.payload_end - payload_start;

    assert [outputs.messages_to_l1] = MessageToL1Header(
        from_address=contract_address, to_address=request.to_address, payload_size=payload_size
    );
    memcpy(
        dst=outputs.messages_to_l1 + MessageToL1Header.SIZE, src=payload_start, len=payload_size
    );
    let (outputs) = os_carried_outputs_new(
        messages_to_l1=outputs.messages_to_l1 + MessageToL1Header.SIZE + payload_size,
        messages_to_l2=outputs.messages_to_l2,
    );

    return ();
}
