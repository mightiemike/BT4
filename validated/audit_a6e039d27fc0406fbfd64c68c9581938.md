## Finding: Unbounded decompression DoS in `decompress_program` (RPC execution layer)

### Title
Denial of Service via unbounded gzip decompression of user-supplied legacy contract program in JSON-RPC execution endpoints - (File: `crates/apollo_rpc/src/v0_8/api/mod.rs`)

### Summary
The RPC-layer helper `decompress_program` decompresses a user-controlled, base64-encoded gzip blob (the legacy Cairo0 `program` field of a broadcasted declare transaction) fully into memory with **no size or time limit**, unlike every other decompression path in the sequencer codebase.

### Finding Description
`decompress_program` decodes the base64 string and then runs `GzDecoder::read_to_end` into an unbounded `Vec<u8>`, followed by `serde_json::from_reader` on the whole buffer: [1](#0-0) 

This mirrors exactly the Minder `getAttestationReply` pattern in the external report: an attacker-controlled, compressed payload is decompressed and parsed entirely into memory with no bound on the resulting size, so a small compressed "gzip bomb" causes memory to blow up until the process is OOM-killed (CWE-770).

By contrast, every other place in this codebase that decompresses user- or network-supplied class data enforces an explicit `max_size` while streaming the decompression:
- `decode_and_decompress_with_size_limit` in `starknet_api` uses `.take(max_size + 1)` before reading to end and errors if the limit is exceeded: [2](#0-1) 
- The gateway's deprecated-transaction converter and the p2p class converter both call this bounded helper: [3](#0-2) [4](#0-3) 

`decompress_program` is the sole outlier, still marked with a developer TODO acknowledging the missing protection: `// TODO(dan): add time and size limits.` at line 677 of the same function.

### Impact Explanation
`decompress_program` converts a `BroadcastedDeclareTransaction`'s legacy `program` field for use in RPC-driven execution paths (fee estimation / simulation of user-submitted transactions), which accept the same untrusted, attacker-controlled contract-class payload that a contract declarer would submit. Because there is no cap on the decompressed size, an attacker can submit a small, highly-compressed `program` string that expands to gigabytes, exhausting the RPC/full-node process memory and crashing it (denial of service), consistent with the CVSS `AV:N/AC:H/.../A:H` profile of the referenced advisory.

### Likelihood Explanation
The path is reachable by any client able to call the affected JSON-RPC execution methods with a crafted `BroadcastedDeclareTransaction` (V1 legacy class), requiring no special privileges, no successful state-changing transaction, and no on-chain fee payment — only a valid base64/gzip envelope around a bomb payload. This is directly analogous to the "attacker adds crafted attestations, victim server fetches and decompresses them" scenario in the original report, except here the sequencer's own RPC endpoint decompresses the attacker payload directly.

### Recommendation
Bound the decompression the same way the rest of the codebase already does: replace the raw `GzDecoder::read_to_end` in `decompress_program` with a size-limited read (e.g., reuse `decompress_with_size_limit`/`decode_and_decompress_with_size_limit` from `starknet_api::compression_utils`, or wrap the `GzDecoder` in `.take(max_size)`), enforcing the same `max_contract_bytecode_size`/`max_contract_class_object_size` style limits used by the gateway's stateless transaction validator: [5](#0-4) 

### Proof of Concept
1. Construct a `program` value that is base64-encoded gzip data compressing to a very large (e.g., multi-GB) JSON payload (a classic "zip bomb"), similar to the PoC in the external report.
2. Submit a `BroadcastedDeclareTransaction::V1` containing this `program` to an RPC execution method (fee estimation / simulation) that internally calls `decompress_program`.
3. `GzDecoder::read_to_end` decompresses the entire payload into memory with no limit, driving the process's memory usage up until the OS OOM-kills it, denying service to the RPC node.

**Note on verification limits:** I was not able to fully trace every call site of `decompress_program` beyond `execution_test.rs` and `crates/apollo_rpc/src/v0_8/api/mod.rs` within the indexed content (index size limits may exclude some file contents); confirming the exact JSON-RPC method names that reach this function (e.g., `starknet_estimateFee`, `starknet_simulateTransactions`) would benefit from a full-repository session with unrestricted file access.

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
