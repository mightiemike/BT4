### Title
Single-block spot-price DEX quote used for autoswap `minPCOut` enables sandwich-manipulation of inbound GAS deposits - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The external report's core issue is that a protocol relies on a single, easily-stale/manipulable price source to compute a value that gates fund movement, instead of a source resistant to short-term manipulation, creating a window where an attacker can extract value. Push Chain has the same structural weakness in its GAS-token autoswap path: `GetSwapQuote` reads an instantaneous Uniswap V3 `QuoterV2.quoteExactInputSingle` spot price with no TWAP/staleness protection, and that single quote is used to derive `minPCOut` (a fixed 95% of quote) for the module-originated swap that converts a user's bridged PRC20 into native PC.

### Finding Description
When a `GAS` or `GAS_AND_PAYLOAD` inbound is executed (`ExecuteInboundGas` in `x/uexecutor/keeper/execute_inbound_gas.go:103-153`, and `gasAndPayloadDepositAutoSwap` in `x/uexecutor/keeper/execute_inbound_gas_and_payload.go:347-379`), and again on outbound gas refunds (`applyGasRefund` in `x/uexecutor/keeper/outbound.go:174-257`), the keeper:

1. Calls `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`), which does a `commit=false` static call to `QuoterV2.quoteExactInputSingle` — this returns the AMM's *current* spot-derived output for the trade size, not a time-weighted average.
2. Computes `minPCOut = quote * 95 / 100` — a flat 5% slippage buffer applied directly to that single spot read.
3. Immediately calls `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`, which execute the real swap on-chain against the same pool, gated only by that `minPCOut` floor.

There is no TWAP, no oracle cross-check, no cap on price impact, and no protection against the quote and the executing swap being priced against a pool state that an attacker has just pushed to an extreme within the same block (classic sandwich setup): buy/sell against the WPC/PRC20 pool immediately before the module's deposit-autoswap transaction lands, so the quote used to build `minPCOut` reflects the attacker's manipulated price, then the module's swap executes into that same manipulated pool and the attacker reverses the position afterward, capturing the difference from the user's bridged funds (the deposit amount is fixed by the inbound; only the PC output the user's UEA receives is variable and manipulable within the 5% band, and repeatedly if attacker sizes the manipulation to just clear the floor).

This is unprivileged and reachable by any external actor who can submit ordinary EVM transactions against Push Chain's own Uniswap V3 fork pools (`UniversalCore`/`WPC` pair) — no validator, TSS, or admin compromise is required. It directly parallels the external report's root cause: deriving a critical value from a single, momentarily-controllable price source instead of one resistant to manipulation.

### Impact Explanation
A successful sandwich reduces the PC amount actually credited to the victim's UEA (or refunded to the outbound sender) below fair value, i.e., partial value extraction/loss of user-controlled funds during the autoswap leg of `GAS`/`GAS_AND_PAYLOAD` inbound processing and gas-refund processing. This falls under "corruption of ... gas fee accounting, refund accounting ... PRC20 ... accounting" and "stealing/draining ... of user or protocol-controlled funds" in the allowed-impact scope, since it's realized without any privileged actor, purely via ordinary EVM transaction submission timed around the module's deterministic swap calls.

### Likelihood Explanation
Likelihood depends on the actual liquidity depth of the WPC/PRC20 pools deployed for `UniversalCore`. If pools are thin (plausible for a newly bridged/whitelisted PRC20), a modest-capital attacker can move the spot price enough to extract meaningful value within the fixed 5% slippage tolerance, especially since this path executes on every GAS-carrying inbound and every outbound gas refund with excess fee — a routine, frequently-triggered flow, not a rare edge case.

### Recommendation
- Replace the pure spot-price `quoteExactInputSingle` call with a TWAP-based quote (or cross-check against `ChainMeta`/an independent price reference) before computing `minPCOut`.
- Consider tightening or making the slippage tolerance dynamic based on pool depth/observed volatility rather than a flat 5%.
- Add a sanity bound comparing the quoted price to a longer-window reference price, rejecting/deferring the swap (falling back to non-swap deposit, which the code already supports) if the deviation exceeds a safe threshold.

### Proof of Concept
1. Attacker identifies a `PRC20/WPC` Uniswap V3 pool on Push Chain with limited liquidity for a given bridged token.
2. Attacker submits a large swap in the WPC/PRC20 pool to skew the spot price in the direction that lowers `quoteExactInputSingle`'s expected PC output for the PRC20→WPC direction, timed to land in the block just before a pending `GAS`/`GAS_AND_PAYLOAD` inbound finalizes (or before the module processes an outbound gas refund).
3. When `ExecuteInboundGas`/`applyGasRefund` runs, `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) returns the manipulated low price; `minPCOut` is computed as 95% of that already-depressed quote.
4. `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes the swap into the still-skewed pool, crediting the victim's UEA (or refund recipient) with less PC than fair value.
5. Attacker reverses their initial swap, realizing the captured spread from the victim's bridged deposit. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
