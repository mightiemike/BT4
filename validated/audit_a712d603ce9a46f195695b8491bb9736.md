## Analysis: Analog of the "unattributed fee deduction" bug in Push Chain's gas-refund flow

The Concur report's core defect is: an amount is computed and *subtracted from what the user is credited* (or reserved as "owed" to the user), but the crediting step is not reliable, and when it fails there is no fallback owner or retry — the value becomes permanently stranded with no accounting entity holding a claim to it.

The Push Chain analog is in the outbound gas-refund path in `x/uexecutor/keeper/outbound.go`'s `applyGasRefund`.

### Where it lives

`applyGasRefund` is invoked from both `handleSuccessfulOutbound` and `handleFailedOutbound` inside `FinalizeOutbound`: [1](#0-0) 

It computes `refundAmount = gasFee - gasFeeUsed` — real value that was already reserved/collected on Push Chain when the outbound was created (the gas fee paid for relayer execution on the destination chain) — and is now "owed back" to the sender because less gas was actually consumed: [2](#0-1) 

It first tries a swap-based refund via `CallUniversalCoreRefundUnusedGas` (`withSwap=true`); on any failure at the fee-tier lookup, quote lookup, or the EVM call itself, it falls back to a direct no-swap deposit: [3](#0-2) 

### The gap

If **both** the swap path and the no-swap fallback fail (e.g. thin/absent Uniswap liquidity for an attacker-chosen gas token, a `minPCOut` slippage revert, or a recipient contract that reverts on token receipt), the code simply records:

```go
refundPcTx.Status = "FAILED"
refundPcTx.ErrorMsg = err.Error()
...
outbound.PcRefundExecution = refundPcTx
outbound.RefundSwapError = swapFallbackReason
```

and then returns normally into `k.UpdateOutbound(...)`, marking the outbound `OBSERVED`/`REVERTED` regardless. There is no retry queue, no alternate credit path (e.g. crediting a UEA balance instead), and no propagated error that would block finalization. This mirrors the audited bug exactly: `refundAmount` is a real value computed and intended for a specific recipient, but the only crediting mechanism can fail silently, and once it does, the tokens have no owner in state — they remain wherever `UniversalCore` holds them (the pre-collected gas-fee pool), permanently unreachable by the rightful recipient.

An unprivileged sender can trigger this without any malicious validator or admin: they control the `GasToken` chosen for their outbound (via token/registry config reachable in normal flows) and can pick one with no/thin swap liquidity, and/or specify a `RevertInstructions.FundRecipient` that is a contract designed to revert on PRC20 receipt — both `withSwap=true` and `withSwap=false` paths call into the same recipient/token, so a hostile recipient contract can defeat both attempts deterministically.

This is corroborated by the project's own test suite, which explicitly documents this failure mode without asserting recovery: [4](#0-3) 

### Title
Permanently stranded excess gas refund when both swap and no-swap `refundUnusedGas` paths fail - (File: `x/uexecutor/keeper/outbound.go`)

### Summary
`applyGasRefund` computes a legitimate, positive `refundAmount` owed to an outbound's sender/fund-recipient whenever the destination chain consumed less gas than pre-collected. It attempts to credit this amount via `CallUniversalCoreRefundUnusedGas`, first with an on-chain swap, then via a direct PRC20 deposit fallback. If both calls fail, the function records a `FAILED` status on `PcRefundExecution` and proceeds to finalize the outbound anyway, with no retry mechanism and no alternate credit path. The excess gas value becomes permanently unrecoverable — an unprivileged user can force this outcome by controlling the gas token (thin/zero DEX liquidity) and/or the refund recipient (a contract that reverts on token receipt), since both refund paths route through the same token/recipient.

### Finding Description
`applyGasRefund` in `x/uexecutor/keeper/outbound.go` (lines 178-257) is the sole mechanism for returning unused destination-chain gas fee to a sender. It tries a swap-based refund and, on any error, a no-swap fallback deposit — both ultimately calling `k.CallUniversalCoreRefundUnusedGas` (`x/uexecutor/keeper/evm.go`, lines 595-644) against the same `gasToken` / `recipientAddr` pair derived from attacker-controlled outbound fields (`outbound.GasToken`, `outbound.RevertInstructions.FundRecipient`). When both calls fail, the function only sets `refundPcTx.Status = "FAILED"` and `outbound.RefundSwapError`, then returns without error, letting `FinalizeOutbound` → `UpdateOutbound` persist the outbound as finalized (`OBSERVED` or `REVERTED`) regardless. No code path revisits a `FAILED` `PcRefundExecution` to retry crediting the recipient through an alternative channel (e.g., minting to the sender's UEA balance instead of the chosen recipient/token).

### Impact Explanation
The `refundAmount` represents real value previously collected from the user as part of the outbound gas-fee accounting. Once both refund attempts fail, this value has no state entry crediting it to any account — it is permanently lost from the user's perspective (protocol-retained, unspendable, unrecoverable via any user-reachable message). This is a direct, unprivileged loss of user funds, matching the "permanent freezing/permanent loss of user funds" impact category.

### Likelihood Explanation
Triggering requires only ordinary, unprivileged control over: (1) the gas token used for the outbound's relayer fee (reachable through the normal registry-derived flow of any inbound/outbound the user initiates), and/or (2) the `RevertInstructions.FundRecipient` supplied with the inbound. No malicious validator, admin, or TSS collusion is needed — an attacker choosing a token with no swap liquidity, or a `FundRecipient` contract that reverts on PRC20 receipt, deterministically fails both the swap and no-swap refund attempts.

### Recommendation
Do not let a failed refund silently finalize as unrecoverable. Options: (1) hold the refund amount in an intermediate escrow/module account when both attempts fail and expose a permissionless retry/claim message so anyone (including the rightful recipient) can re-trigger the refund later once liquidity/recipient issues are resolved; (2) fall back further to crediting the amount directly into the sender's UEA/PRC20 balance (bypassing swap and bypassing an arbitrary attacker-supplied `FundRecipient` contract) as a final, always-succeeding sink; (3) at minimum, track failed refunds in a dedicated queryable/retriable state object so operators or the recipient can recover funds, rather than only recording an error string on the finalized outbound.

### Proof of Concept
1. User submits an inbound whose resulting outbound specifies a `GasToken` that has no (or negligible) Uniswap V3 liquidity against `WPC`, and sets `RevertInstructions.FundRecipient` to a contract that reverts on `transfer`/mint-style token receipt.
2. UVs observe and vote the outbound with `gasFeeUsed < gasFee` (a normal, honest observation — e.g., the destination chain simply used less gas than reserved).
3. `FinalizeOutbound` → `applyGasRefund` runs:
   - `GetDefaultFeeTierForToken` / `getSwapQuoteForRefund` fails or the swap-mode `CallUniversalCoreRefundUnusedGas` reverts because of the illiquid pool.
   - Fallback no-swap `CallUniversalCoreRefundUnusedGas(withSwap=false, ...)` reverts because `FundRecipient` rejects the token.
4. `refundPcTx.Status = "FAILED"` is recorded, `outbound.RefundSwapError` is set, and `UpdateOutbound` persists the outbound as finalized with no further processing (confirmed by the existing test `"swap fallback reason stored when swap refund fails"`, which asserts only that `PcRefundExecution` is non-nil and status is set — not that funds are ever recovered).
5. The `refundAmount` of gas-fee excess is now permanently unassigned to any account, with no retry path in the codebase.

func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}
