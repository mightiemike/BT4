## Analysis

The Sherlock finding describes a pattern where a function accepts native value (`msg.value`) alongside a token operation, but a missing check on one failure path causes that attached value to become permanently un-refundable. The closest reachable analog in nearcore is in the **NEAR Wallet Contract**, which is explicitly in scope per the rules.

### Root cause

`WalletContract::rlp_execute` is `#[payable]`, so any external caller (e.g. a relayer sponsoring a transaction) can attach a NEAR deposit. `inner_rlp_execute` builds a `CallerDeposit` to track this attached value so it can be refunded if the downstream action fails: [1](#0-0) 

That `caller_deposit` is threaded through to `rlp_execute_callback`, which *does* correctly refund it when the final action promise fails: [2](#0-1) 

However, two intermediate callbacks that are on the execution path for common transaction kinds — sending to an unregistered eth-implicit target (`address_check_callback`) and sending an emulated ERC-20 transfer to an unregistered receiver (`nep_141_storage_balance_callback`) — receive `caller_deposit` as a parameter but **drop it silently** on their `Failed` branch instead of forwarding/refunding it: [3](#0-2) [4](#0-3) 

Compare this to `rlp_execute_callback`, which is the only place that actually issues the refund promise using `CallerDeposit`, confirming the two callbacks above are missing the same handling: [5](#0-4) 

The existing regression test only exercises the success path of the refund logic through `rlp_execute_callback`, not the address-registrar or storage-balance failure branches, so this gap is untested: [6](#0-5) 

### Why this matters

An attached deposit on `rlp_execute` is credited to the wallet contract's account balance immediately upon receipt processing (standard NEAR semantics), independent of whether the eventual action succeeds. `CallerDeposit` exists precisely to reverse that credit if the wallet's inner action ultimately fails. If the intermediate cross-contract call (address registrar `lookup`, or NEP-141 `storage_balance_of`) fails — e.g. the registrar/token contract is missing, panics, or runs out of the fixed 5 Tgas budget — `address_check_callback`/`nep_141_storage_balance_callback` return an error `ExecuteResponse` without emitting the refund transfer, permanently stranding the caller's attached NEAR inside the wallet contract's balance with no protocol-level or contract-level path back to the original caller.

### Title
Missing deposit refund on intermediate call failure permanently strands caller funds - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
`address_check_callback` and `nep_141_storage_balance_callback` in the NEAR Wallet Contract accept a `caller_deposit: Option<CallerDeposit>` parameter meant to refund an external caller's attached NEAR deposit if the wallet's inner action fails, but their `PromiseResult::Failed` branches discard this parameter instead of issuing the refund, unlike `rlp_execute_callback` which correctly implements the refund.

### Finding Description
`rlp_execute` is `#[payable]`; any external predecessor (e.g. a relayer) can attach NEAR when submitting an Ethereum-style transaction. `CallerDeposit::new` captures this deposit whenever `predecessor_account_id != current_account_id`. For two transaction kinds — an `EOABaseTokenTransfer` requiring an address-registrar lookup, and an `ERC20Transfer` requiring a NEP-141 `storage_balance_of` check — the flow first issues a cross-contract call and only reaches the final action (and thus `rlp_execute_callback`, which does refund `caller_deposit` on failure) if that intermediate call succeeds. If the intermediate call itself fails (registrar/token contract missing, panicking, or exceeding its fixed static gas allocation), `address_check_callback`/`nep_141_storage_balance_callback` return early with a failure `ExecuteResponse` and never construct a refund promise for `caller_deposit`, even though it is passed into the function.

### Impact Explanation
The externally-attached deposit remains permanently credited to the wallet contract's account balance with no code path exposed to reclaim it on behalf of the original caller — the caller who funded the transaction to sponsor gas/value effectively loses those funds when the intermediate cross-contract call fails, a concrete unauthorized/frozen value-movement outcome triggerable from a single transaction.

### Likelihood Explanation
Reachable by any account (no special privilege) that calls `rlp_execute` with a nonzero attached deposit targeting either an unregistered eth-implicit address (triggers the registrar lookup) or an ERC-20 transfer to an unregistered receiver (triggers the storage-balance check), where the registrar or token contract fails to respond successfully — a state achievable via a misconfigured/removed registrar, a malicious/reverting token contract, or simply insufficient static gas (`REGISTRAR_LOOKUP_GAS`/`NEP_141_STORAGE_BALANCE_OF_GAS` are small fixed 5 Tgas allocations).

### Recommendation
In the `PromiseResult::Failed` arm of both `address_check_callback` and `nep_141_storage_balance_callback`, mirror the refund logic used in `rlp_execute_callback`: if `caller_deposit` is `Some`, issue a `promise_batch_create`/`promise_batch_action_transfer` back to `caller_deposit.account_id` for `caller_deposit.yocto_near` before returning the failure `ExecuteResponse`.

### Proof of Concept
1. An external relayer account calls `wallet_contract.rlp_execute(target, tx_bytes_b64)` attaching a NEAR deposit, where the RLP transaction resolves to `EthEmulationKind::EOABaseTokenTransfer { address_check: Some(address), .. }` (target is an unregistered eth-implicit account).
2. `inner_rlp_execute` computes `caller_deposit = Some(CallerDeposit { account_id: relayer, yocto_near: deposit })` and schedules `address_registrar.lookup(...).then(address_check_callback(target, action, caller_deposit))`.
3. The address registrar cross-contract call fails (e.g., contract removed, or exceeds `REGISTRAR_LOOKUP_GAS`).
4. `address_check_callback` matches `PromiseResult::Failed` and returns `ExecuteResponse { success: false, ... }` without ever using `caller_deposit`, per [7](#0-6) .
5. The relayer's attached deposit remains permanently in the wallet contract's balance; the relayer has no way to reclaim it. The same sequence applies to `nep_141_storage_balance_callback` when the token contract's `storage_balance_of` call fails.

/// A data type to keep track of the deposit given by an external caller.
/// This allows us to refund the caller's deposit if the cross-contract call fails.
#[derive(Debug, PartialEq, Eq, Clone, serde::Serialize, serde::Deserialize)]
pub struct CallerDeposit {
    pub account_id: AccountId,
    pub yocto_near: NonZeroU128,
}

impl CallerDeposit {
    pub fn new(context: &ExecutionContext) -> Option<Self> {
        // Only track for external (non-self) callers
        if context.current_account_id == context.predecessor_account_id {
            return None;
        }

        NonZeroU128::new(context.attached_deposit.as_yoctonear()).map(|yocto_near| Self {
            account_id: context.predecessor_account_id.clone(),
            yocto_near,
        })
    }
}

// An external caller gets its deposit back if the cross-contract call fails.
#[tokio::test]
async fn test_caller_refunds() -> anyhow::Result<()> {
    let TestContext { worker, wallet_contract, wallet_sk, address_registrar, .. } =
        TestContext::new().await?;

    let caller = worker.root_account()?;
    let deposit_amount = NearToken::from_near(3);
    let create_tx = |receiver_id: &AccountId, nonce: u64| {
        let method = "register";
        let args = br#"{"account_id": "birchmd.near"}"#;
        let action = Action::FunctionCall {
            receiver_id: receiver_id.to_string(),
            method_name: method.into(),
            args: args.to_vec(),
            gas: Gas::from_tgas(10).as_gas(),
            yocto_near: 0,
        };
        utils::create_signed_transaction(
            nonce,
            receiver_id,
            Wei::new_u128(deposit_amount.as_yoctonear() / (MAX_YOCTO_NEAR as u128)),
            action,
            &wallet_sk,
        )
    };

    // External caller gets a refund when the cross-contract call fails
    let pre_tx_account_balance = caller.view_account().await?.balance;
    let receiver_id: AccountId = "fake.near".parse()?;
    let result = wallet_contract
        .rlp_execute_from(
            &caller,
            receiver_id.as_str(),
            &create_tx(&receiver_id, 0),
            deposit_amount,
        )
        .await?;
    assert!(!result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            < deposit_amount.as_yoctonear()
    );

    // External caller does not get a refund when their tokens are spent
    let pre_tx_account_balance = post_tx_account_balance;
    let receiver_id = address_registrar.id();
    let result = wallet_contract
        .rlp_execute_from(&caller, receiver_id.as_str(), &create_tx(receiver_id, 1), deposit_amount)
        .await?;
    assert!(result.success);
    let post_tx_account_balance = caller.view_account().await?.balance;
    assert!(
        pre_tx_account_balance.as_yoctonear() - post_tx_account_balance.as_yoctonear()
            >= deposit_amount.as_yoctonear()
    );

    Ok(())
}
