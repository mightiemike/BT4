### Title
Denial of Service via quadratic string concatenation in query-parameter normalization before HMAC verification - (File: `packages/apps/shopify-api/lib/utils/hmac-validator.ts`)

### Summary
`shopify.utils.validateHmac` (used to authenticate App Proxy and OAuth/Flow/Fulfillment-service requests) normalizes incoming query parameters *before* any HMAC/signature check is performed. When a query key repeats, the values are merged with unbounded string concatenation, producing quadratic CPU cost relative to the number of repeated parameters. Because this normalization runs prior to signature validation, an unauthenticated caller can trigger it directly.

### Finding Description
`normalizeQuery` in `hmac-validator.ts` iterates over every `URLSearchParams` entry and, for repeated keys, does: [1](#0-0) 

```
normalizedQuery[key] = `${existingValue},${value}`;
```

Each repeated occurrence of the same key re-copies the entire accumulated string, so for `n` repeated values the total work is O(n²) in string length, not O(n). This function is invoked by `validateHmac`, which runs it *before* the HMAC/signature comparison: [2](#0-1) 

`validateHmac(..., {signator: 'appProxy'})` is reachable from a fully anonymous HTTP request against the app's own App Proxy route, since App Proxy endpoints are ordinary internet-exposed URLs on the app server, and the code calls `validateHmac` on the raw, attacker-supplied `searchParams` up to three times (retrying with `_data` variants) before rejecting an invalid signature: [3](#0-2) 

The `APP_PROXY_SINGLE_VALUE_PARAMS` guard only rejects duplicates for `hmac`, `shop`, `signature`, and `timestamp` — any other query key can be freely repeated an arbitrary number of times: [4](#0-3) 

This mirrors the reported bug class: an attacker-controlled input whose size directly and disproportionately drives CPU cost in a pre-authentication code path, only here the multiplier is quadratic string concatenation rather than an expensive hash function.

### Impact Explanation
A single unauthenticated HTTP request to an app's App Proxy endpoint with many repeated non-reserved query parameters (e.g. `?shop=x&timestamp=1&hmac=x&a=1&a=1&a=1...` repeated thousands of times) forces the server to perform quadratic-time string building before ever validating the signature. With enough repetitions this can consume significant CPU/memory on the request-handling process, potentially degrading or blocking the event loop for other requests — a denial-of-service condition on the authentication handler itself, consistent with "DoS of an auth handler" in scope.

### Likelihood Explanation
Exploitability is bounded by HTTP request/URL size limits enforced by the underlying server/runtime (e.g., Node's default header/URL size limits, typically several KB to tens of KB). Within that budget an attacker can still pack many short repeated key/value pairs, so the attack is feasible but its magnitude is constrained by those platform-level limits rather than being unbounded (unlike a single very long password field). This tempers the severity relative to a fully unbounded-length input DoS.

### Recommendation
- Reject requests where a non-reserved query key repeats more than a small, fixed number of times (or reject duplicates entirely, as is already done for `hmac`/`shop`/`signature`/`timestamp`).
- Avoid repeated string concatenation in a loop; if merging duplicate values is required, collect them in an array and `join(',')` once, which is linear instead of quadratic.
- Enforce a maximum total query-string length before entering `validateHmac`.

### Proof of Concept
Send an HTTP GET to any configured App Proxy route with a query string containing the required `shop`, `timestamp`, and `hmac` parameters plus a large number of duplicate additional keys, e.g.:
```
GET /apps/proxy?shop=test.myshopify.com&timestamp=1699999999&hmac=deadbeef&a=1&a=1&a=1...(repeated thousands of times, up to server URL-length limit)
```
This causes `normalizeQuery` (via `validateAppProxyHmac` → `api.utils.validateHmac`) to perform quadratic-cost string concatenation before the (ultimately failing) HMAC check is even evaluated, consuming disproportionate CPU per request.

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}

async function validateAppProxyHmac(
  params: BasicParams,
  url: URL,
): Promise<boolean> {
  const {api, logger} = params;

  try {
    let searchParams = new URLSearchParams(url.search);
    if (!searchParams.get('index')) {
      searchParams.delete('index');
    }

    let isValid = await api.utils.validateHmac(searchParams, {
      signator: 'appProxy',
    });

    if (!isValid) {
      const cleanPath = url.pathname
        .replace(/^\//, '')
        .replace(/\/$/, '')
        .replaceAll('/', '.');
      const data = `routes%2F${cleanPath}`;

      searchParams = new URLSearchParams(
        `?_data=${data}&${searchParams.toString().replace(/^\?/, '')}`,
      );

      isValid = await api.utils.validateHmac(searchParams, {
        signator: 'appProxy',
      });

      if (!isValid) {
        const searchParams = new URLSearchParams(
          `?_data=${data}._index&${url.search.replace(/^\?/, '')}`,
        );

        isValid = await api.utils.validateHmac(searchParams, {
          signator: 'appProxy',
        });
      }
    }

    return isValid;
