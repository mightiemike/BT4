### Title
Spot-price Uniswap V3 quote used as autoswap floor enables sandwich extraction of user gas-abstraction deposits - (File: x/uexecutor/keeper/execute_inbound_gas.go)

### Summary
Push Chain's gas-abstraction inbound flow (`TxType_GAS` / `TxType_GAS_AND_PAYLOAD`) swaps a user's bridged PRC20 gas token into WPC/native PC via `UniversalCore.depositPRC20WithAutoSwap`. The minimum acceptable output (`minPCOut`) is derived purely from an instantaneous Uniswap V3 `QuoterV2.quoteExactInputSingle` spot-price read (with a flat 5% slippage haircut), not from a TWAP or any staleness/deviation check. This mirrors the "oracle lags/can be manipulated relative to true price" bug class from the external Morpho report: here the "oracle" is the AMM pool's spot price itself, and any unprivileged actor who can trade against that same pool immediately around the finalizing validator vote can force the deposit to swap at a manipulated rate, extracting value from the user's cross-chain deposit.

### Finding Description
`ExecuteInboundGas` (and the analogous `gasAndPayloadDepositAutoSwap`) computes `minPCOut` as:
```go
quote, execErr = k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
...
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
receipt, execErr = k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
``` [4](#0-3) 

`GetSwapQuote` calls the Uniswap V3 `QuoterV2` contract, which returns the amount out based on the pool's *current* reserves/tick (a spot price), with no averaging window: [5](#0-4) 

This quote-then-swap sequence executes synchronously and atomically as a side effect of `MsgVoteInbound` reaching quorum: [6](#0-5) [7](#0-6) 

Because inbound content is fully attacker/user-observable ahead of time (the pending inbound's asset, amount, and source chain are visible once 2 of 3 votes are recorded, and the exact block in which the third/quorum vote lands is predictable from mempool monitoring), an unprivileged party can:
1. Front-run the block/tx containing the quorum-reaching `MsgVoteInbound` with a large swap on the same PRC20/WPC Uniswap V3 pool, pushing the spot price so the resulting quote is depressed.
2. Let the protocol's `ExecuteInboundGas` compute `minPCOut` off this depressed quote and execute `depositPRC20WithAutoSwap`, which will accept a bad execution price since the floor is only 95% of the already-manipulated quote.
3. Back-run to reverse their initial swap, capturing the difference between the true market price and the manipulated execution price — this profit comes directly out of the value that should have landed as PC/WPC gas token for the victim's UEA.

This is the same class of vulnerability as the external report: a single point-in-time price read from a market that can be moved cheaply within a narrow window (here, atomically pre/post rather than lagging Chainlink updates) is trusted as the ground truth for a financial execution boundary, and the fixed slippage tolerance (5%) is not derived from, or defensive against, the actual manipulation cost of the pool.

### Impact Explanation
The victim is the ordinary user who bridged a gas token expecting it to be swapped near fair value into PC to fund their UEA. A successful sandwich directly reduces the amount of native PC token credited relative to fair market value, i.e. permanent, uncompensated loss of user-controlled funds during a default, unprivileged transaction submission path (bridging + gas abstraction). Because the swap executes on-chain via the module account with no re-check against an external reference price, the loss is realized irreversibly once the deposit lands. The same pattern also affects the excess-gas refund swap (`applyGasRefund` → `getSwapQuoteForRefund` → `CallUniversalCoreRefundUnusedGas`), meaning refunds owed to users after outbound completion are equally exposed. [8](#0-7) 

### Likelihood Explanation
Likelihood depends on the liquidity depth of the specific PRC20/WPC pool used by `UniversalCore`'s configured Uniswap V3 fee tier, and on whether Push Chain's proposer/mempool ordering realistically allows an attacker to bracket the finalizing vote transaction. For low-liquidity or newly listed gas tokens (where a 5% band is cheap to move), or if MEV-style transaction ordering is feasible on Push Chain, this is straightforwardly exploitable by any unprivileged actor holding pool tokens — no validator or node compromise is required, satisfying the "ordinary user/attacker" threat model.

### Recommendation
Do not derive `minPCOut` solely from a single spot-price `quoteExactInputSingle` call executed immediately before the swap. Instead:
- Use a time-weighted average price (TWAP) from the pool (or an external, staleness-checked oracle) as the reference price for computing `minPCOut`.
- Widen or make the slippage tolerance adaptive to observed pool liquidity/volatility rather than a flat 5%, and/or cap the deposit size executable in a single swap against a given pool.
- Consider splitting the quote-fetch and swap execution across separate blocks with a committed reference price, or require multiple UV-attested quotes (similar to the `ChainMeta` median-of-votes pattern already used for gas price) instead of a single ephemeral on-chain read.

### Proof of Concept
1. Attacker monitors pending `PendingInbounds` / mempool for a `TxType_GAS` inbound nearing quorum (2 of 3 UV votes recorded) for a given PRC20 gas token with a shallow WPC pool.
2. Immediately before the block expected to carry the quorum-finalizing `MsgVoteInbound`, attacker submits a large swap into the pool that depresses the PRC20→WPC spot price used by `GetSwapQuote`.
3. The quorum vote lands, triggering `VoteInbound` → `ExecuteInbound` → `ExecuteInboundGas`, which calls `GetSwapQuote` (now reading the manipulated price) and executes `CallPRC20DepositAutoSwap` with `minPCOut = quote * 0.95` computed from the manipulated quote — the deposit swap clears at a bad rate.
4. Attacker reverses their initial swap in a subsequent transaction, realizing a profit equal to the price impact minus fees, funded by the reduced WPC/PC amount the victim's UEA receives.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
