## Finding

### Title
Sandwich-attackable on-chain autoswap slippage check drains value from PRC20 gas deposits and gas refunds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The `uexecutor` module performs a Uniswap-V3 autoswap (PRC20 → WPC) whenever a `GAS` or `GAS_AND_PAYLOAD` inbound is finalized, and again when refunding unused gas on outbound completion. In every one of these paths the "expected output" used to compute the slippage floor is fetched via an on-chain quoter call (`GetSwapQuote`) *in the same execution* as the swap itself (`CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`), with only a fixed 5% tolerance. There is no off-chain, pre-committed `minAmountReceived`. This is the exact bug class from the external report: an attacker can manipulate the underlying pool immediately before the swap executes (moving price by more than the 5% band), let the module's own quote/swap consume the manipulated price, and then restore the pool, extracting value from users' bridged funds or from protocol gas refunds.

### Finding Description
`GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` against the live pool state: [1](#0-0) 

That quote is turned into a `minPCOut` bound with a hard-coded 5% slippage allowance and immediately used in the same call chain to execute the swap, with no time or block gap between quoting and swapping: [2](#0-1) [3](#0-2) 

The same on-chain-quote-then-swap pattern with a static 5% band is reused for the unused-gas refund path: [4](#0-3) 

This autoswap is triggered inside `ExecuteInbound`, which runs synchronously as part of `VoteInbound` the moment the finalizing validator vote reaches quorum: [5](#0-4) 

`MsgVoteInbound` is a normal, unauthenticated-content Cosmos transaction broadcast by Universal Validators and is visible in the mempool before inclusion in a block, like any other transaction: [6](#0-5) 

Because the quote and swap happen atomically inside that same finalizing transaction, and the pool price at execution time is whatever the current PRC20/WPC Uniswap V3 pool state is, an unprivileged trader watching the mempool for the quorum-completing `MsgVoteInbound` can:
1. Front-run it with a large swap against the same PRC20/WPC pool, moving the spot price against the pending autoswap direction.
2. Let the module's `GetSwapQuote` + `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` execute at the now-manipulated price (only 5% slippage tolerance protects against this, which is trivially exceeded with a large enough front-run, especially against a low-liquidity or newly-listed PRC20/WPC pool).
3. Back-run to restore the pool price, capturing the value lost by the deposited user (or by the protocol's refund recipient) as arbitrage profit.

This directly mirrors the external report's root cause: slippage tolerance computed from an on-chain, same-transaction price estimate is not resistant to sandwiching; a genuine off-chain-computed `minAmountReceived` (bound to the specific deposit/refund and validated against a time-weighted or externally-attested price) is required.

### Impact Explanation
Every `GAS` and `GAS_AND_PAYLOAD` inbound (i.e., every native-gas-token bridge deposit that needs conversion to PC) and every gas-fee refund routes through this vulnerable autoswap. An attacker can systematically extract value from users' bridged gas deposits and from protocol-issued gas refunds, up to the 5% slippage band per swap, repeatable on every inbound/refund. This is a direct, unauthorized transfer of user/protocol-controlled fund value to an external attacker — no validator, relayer, or admin compromise is required.

### Likelihood Explanation
High. The trigger requires only an unprivileged actor capable of submitting ordinary swap transactions against the PRC20/WPC pool and observing the mempool for the finalizing `MsgVoteInbound` transaction (or simply for the deposit event itself, since the deposit amount/PRC20 are public once even 1 vote has been broadcast, and the quorum-finalizing vote is a predictable, short-delay event). Sandwich bots doing exactly this pattern against on-chain quote-based swaps are common and require no special access.

### Recommendation
Do not compute the slippage bound from an on-chain quote taken in the same transaction as the swap. Instead:
- Accept a `minPCOut` (or equivalent) supplied by an off-chain process at the time the inbound/refund is prepared, ideally derived from a manipulation-resistant price source (e.g., a TWAP over a meaningful window, or a price attested independently of the atomic swap transaction).
- Alternatively, bound the acceptable price movement using a TWAP-based oracle check (Uniswap V3 `observe`) rather than the instantaneous `quoteExactInputSingle` spot price.
- Consider widening protections for low-liquidity PRC20/WPC pools (e.g., capping swap size relative to pool depth, or requiring minimum on-chain liquidity before autoswap is enabled for a token) to reduce the cost of a manipulating trade.

### Proof of Concept
1. Attacker monitors the mempool/chain for pending `GAS`/`GAS_AND_PAYLOAD` inbounds (visible once the first validator votes) or for outbound completions that will trigger `applyGasRefund`.
2. Right before (or in the same block as, depending on proposer inclusion rules) the quorum-finalizing `MsgVoteInbound` executes `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, attacker submits a large swap on the PRC20/WPC Uniswap V3 pool (`x/uexecutor/keeper/evm.go` `GetSwapQuote`/`CallPRC20DepositAutoSwap` target pool) that pushes the price down by >5%.
3. `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-538`) returns a quote based on the now-manipulated price; `minPCOut = quote*95/100` (`execute_inbound_gas.go:142-146`) is computed from that same manipulated quote, so it does not protect the user.
4. `CallPRC20DepositAutoSwap` executes at the bad price, converting the user's bridged PRC20 to less PC than fair value.
5. Attacker back-runs with the opposite swap, restoring the pool price and capturing the price difference as profit, at the expense of the depositing user (or the gas-refund recipient in the `applyGasRefund` case).

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// VoteInbound implements types.MsgServer.
func (ms msgServer) VoteInbound(ctx context.Context, msg *types.MsgVoteInbound) (*types.MsgVoteInboundResponse, error) {
	signerAccAddr, err := sdk.AccAddressFromBech32(msg.Signer)
	if err != nil {
		return nil, fmt.Errorf("invalid signer address: %w", err)
	}

	// Convert account to validator operator address
	signerValAddr := sdk.ValAddress(signerAccAddr)

	// Lookup the linked universal validator for this signer
	isBonded, err := ms.k.uvalidatorKeeper.IsBondedUniversalValidator(ctx, msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to check bonded status for signer %s", msg.Signer)
	}
	if !isBonded {
		return nil, fmt.Errorf("universal validator for signer %s is not bonded", msg.Signer)
	}

	isTombstoned, err := ms.k.uvalidatorKeeper.IsTombstonedUniversalValidator(ctx, msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to check tombstoned status for signer %s", msg.Signer)
	}
	if isTombstoned {
		return nil, fmt.Errorf("universal validator for signer %s is tombstoned", msg.Signer)
	}

	// continue with inbound synthetic creation / voting logic here
	err = ms.k.VoteInbound(ctx, signerValAddr, *msg.Inbound)
	if err != nil {
		return nil, err
	}

	return &types.MsgVoteInboundResponse{}, nil
}
