## Finding: JIT-style miscompilation analog in Cairo-Native (Sierra→machine-code) execution path with no runtime cross-check against CASM

### Title
Unverified Sierra-to-Native (JIT-analog) compiled execution can silently diverge from CASM semantics, causing honest-node state divergence - (File: `crates/blockifier/src/execution/execution_utils.rs`)

### Summary
The upstream CVE is a JIT miscompilation bug in a JS engine that causes a compiled code path to compute results inconsistent with the language's interpreter semantics, enabling memory corruption. The closest reachable analog in this sequencer is the **Cairo-Native** execution backend: an attacker-controlled Sierra program (submitted via an ordinary `declare` transaction) is compiled ahead-of-time into native machine code by an LLVM/MLIR-based compiler (`cairo_native`'s `AotContractExecutor`), and that compiled code's output is trusted directly by the executor with no runtime cross-check against the CASM (cairo-vm interpreted) reference semantics.

### Finding Description
Declared Cairo 1 classes are compiled from Sierra to CASM deterministically via `SierraToCasmCompiler` [1](#0-0) , and this CASM/Sierra pair is the canonical, hash-committed representation of the class [2](#0-1) .

Independently, when Cairo-Native is enabled (`CairoNativeMode::LazyCompilation` or `WaitOnCompilation`, default is `LazyCompilation` when the feature is compiled in), the same Sierra program is additionally compiled to native machine code via `SierraToNativeCompiler::compile`, which shells out to an LLVM/MLIR-based AOT compiler and produces an `AotContractExecutor` [3](#0-2) . This is functionally analogous to a JIT: it is a second, independent code-generation backend for the same declared program, whose output is expected -- but not guaranteed -- to be semantically identical to the CASM interpretation.

At execution time, `execute_entry_point_call` dispatches directly to the native executor whenever the class is native-compiled and whitelisted, without any cross-validation against the CASM path: [4](#0-3) 

The native path's result is fed straight into `create_callinfo` and becomes part of the transaction's execution result (`CallInfo` / `CallExecution`) that feeds fee/gas accounting and, ultimately, the committed state diff: [5](#0-4) 

Which classes take this path is governed purely by node-local configuration (`NativeClassesWhitelist`), not by anything the declarer can be prevented from triggering: [6](#0-5) [7](#0-6) 

The project is itself aware that CASM vs. Native divergence is a real correctness risk class: it maintains an explicit backend-invariance regression test for revert text [8](#0-7) , and an offline `--compare-native` reexecution tool that reruns full blocks under both backends and diffs the state and hashing data [9](#0-8) . Critically, **this comparison only exists as an offline analysis tool** (`blockifier_reexecution`); it is not part of the hot execution path used by the batcher/gateway/OS re-execution during block production or validation. In production, `NativeCompiledClassV1::executor.run(...)`'s output is trusted unconditionally.

### Impact Explanation
Because a declarer fully controls the Sierra bytecode that is compiled by the AOT ("JIT-analog") backend, any correctness bug in that compiler (e.g., miscompiled arithmetic/overflow handling, incorrect gas/builtin accounting, or incorrect libfunc lowering for a specific Sierra construct) that causes native execution to diverge from CASM execution for the same inputs will propagate directly into:
- Different `retdata`, revert status, or gas consumption depending on whether a given sequencer/full node has that class native-whitelisted (`NativeClassesWhitelist`) or running a different native-compiler version/optimization level,
- A different resulting state diff and receipt, which is exactly the kind of divergence that produces conflicting committed state roots / block hashes across otherwise-honest nodes -- i.e., "honest-node divergence" and a network potentially unable to reach agreement on the correct state, or a chain split between native-enabled and native-disabled/CASM-only nodes.

This satisfies the required impact bar (wrong committed root / honest-node divergence), and the trigger is a standard, unprivileged `declare` transaction plus subsequent `invoke` calls to the crafted class -- well within the allowed reachable surface (class declaration + blockifier execution + state commitment).

### Likelihood Explanation
The likelihood depends entirely on the correctness of the external `cairo_native` LLVM/MLIR compiler for adversarially-crafted Sierra bytecode, which the sequencer code does not independently verify at runtime. Given that:
- The compiler is a large, general-purpose code-generation stack (a plausible source of "JIT-class" miscompilation bugs, mirroring the CVE's bug class),
- The whitelist can be configured as `All`, applying native execution to every declared class,
- There is no online defense-in-depth check (e.g., periodic or probabilistic re-verification of native output against CASM) in the production execution path,

a single crafted contract class is sufficient to reach and exercise this divergence risk, whenever Cairo-Native is enabled by any subset of nodes in the network.

### Recommendation
- Add a runtime (or periodic/sampled) cross-check between native and CASM execution results before trusting a native result for state-affecting operations, at least until the native compiler carries the same level of audited correctness guarantees as the CASM path (mirroring what `blockifier_reexecution`'s `--compare-native` tooling already does, but online).
- Ensure protocol-level consensus does not depend on which execution backend (native vs CASM) a given honest node happens to use for a given class -- i.e., treat `NativeClassesWhitelist`/`CairoNativeMode` strictly as a performance optimization with a mandated, verified fallback to CASM whenever native output cannot be proven equivalent.
- Track and gate the `cairo_native` compiler version tightly (as is already done via `REQUIRED_CAIRO_NATIVE_VERSION`) and expand fuzz/differential testing between CASM and Native across the full audited libfunc surface.

### Proof of Concept
Conceptual PoC (not a live exploit, since it depends on an as-yet-unidentified concrete miscompilation bug in the external `cairo_native` backend):
1. Attacker submits a `declare` transaction for a Cairo 1 contract whose Sierra program exercises a Sierra libfunc/pattern known (or fuzzed) to be miscompiled by the installed `cairo_native` AOT compiler version (e.g., an edge case in overflow/underflow handling, gas-cost libfunc lowering, or builtin counting) while being compiled correctly and deterministically to CASM by `SierraToCasmCompiler`.
2. Attacker invokes the deployed contract with inputs that trigger the divergent code path.
3. Nodes with `NativeClassesWhitelist` covering this class (or `CairoNativeMode != Off`) execute via `native_entry_point_execution::execute_entry_point_call` and compute a different `CallInfo`/state diff than nodes running CASM-only, per `execute_entry_point_call`'s backend dispatch in `crates/blockifier/src/execution/execution_utils.rs` lines 143-167.
4. The differing execution outputs feed into differing state diffs/receipts, producing honest-node divergence in the committed state root for the block containing this transaction.

    pub fn compile(
        &self,
        contract_class: ContractClass,
    ) -> Result<AotContractExecutor, CompilationUtilError> {
        let compiler_binary_path = &self.path_to_binary;

        let output_file = NamedTempFile::new()?;
        let output_file_path = output_file.path().to_str().ok_or(
            CompilationUtilError::UnexpectedError("Failed to get output file path".to_owned()),
        )?;
        let optimization_level = self.config.optimization_level.to_string();
        let additional_args = [output_file_path, "--opt-level", &optimization_level];
        let resource_limits = ResourceLimits::new(
            Some(self.config.max_cpu_time),
            self.config.max_file_size,
            Some(self.config.max_memory_usage),
        );
        let _stdout = compile_with_args(
            compiler_binary_path,
            contract_class,
            &additional_args,
            resource_limits,
        )?;

        Ok(AotContractExecutor::from_path(output_file.path())
            .map_err(|e| CompilationUtilError::CompilationError(e.to_string()))?
            .unwrap())
    }

/// Reexecutes a single block twice -- once with native and once with CASM -- and compares the
/// resulting state diffs and transaction hashing data against each other.
///
/// Comparing transaction hashing data (execution outputs, signatures) is equivalent to comparing
/// block hashes without the overhead of computing commitments.
#[cfg(feature = "cairo_native")]
fn reexecute_block_native_vs_casm(
    block_number: u64,
    config: &RpcStateReaderConfig,
    chain_info: &ChainInfo,
    native_manager: &ContractClassManager,
    casm_manager: &ContractClassManager,
    prefetch_initial_reads: bool,
) -> ReexecutionResult<bool> {
    let min_sierra_version_override = Some(SierraVersion::new(0, 0, 0));

    let mut native_readers = RpcBlockReexecutor::new(
        BlockNumber(block_number),
        Some(config.clone()),
        chain_info.clone(),
        false,
        native_manager.clone(),
        prefetch_initial_reads,
    );
    native_readers.min_sierra_version_override = min_sierra_version_override.clone();
    let ReexecuteBlockOutcome {
        actual_state_diff: native_state_diff,
        txs_hashing_data: native_txs_hashing_data,
        ..
    } = native_readers.reexecute_block()?;

    let mut casm_readers = RpcBlockReexecutor::new(
        BlockNumber(block_number),
        Some(config.clone()),
        chain_info.clone(),
        false,
        casm_manager.clone(),
        prefetch_initial_reads,
    );
    casm_readers.min_sierra_version_override = min_sierra_version_override;
    let ReexecuteBlockOutcome {
        actual_state_diff: casm_state_diff,
        txs_hashing_data: casm_txs_hashing_data,
        ..
    } = casm_readers.reexecute_block()?;

    let state_diff_matched =
        compare_state_diffs(native_state_diff, casm_state_diff, BlockNumber(block_number));
    let tx_hashing_data_matched =
        compare_tx_hashing_data(native_txs_hashing_data, casm_txs_hashing_data, block_number);

    Ok(state_diff_matched && tx_hashing_data_matched)
}
