### Title
Poison-microblock reward can be claimed by "reporting" a single microblock header against a byte-identical clone of itself (h1 == h2), with no distinctness check - ([File: stackslib/src/chainstate/stacks/db/transactions.rs])

### Summary
`handle_poison_microblock` and its precondition `check_microblock_header_signer` only verify that the two supplied microblock headers were signed by the same key (`pkh1 == pkh2`); neither this function nor the mempool admission check in `blocks.rs` ever asserts `mblock_header_1.block_hash() != mblock_header_2.block_hash()`. An attacker can submit `PoisonMicroblock(h, h.clone())` for any legitimately-signed, publicly-broadcast microblock header `h` and have it accepted as proof of equivocation even though only one microblock ever existed.

### Finding Description
The claimed equality is: a valid poison report requires **two distinct** microblocks at the same sequence signed by the same key, i.e. `h1.block_hash() != h2.block_hash()` AND `pkh1 == pkh2`. The code only checks the second half.

`check_microblock_header_signer` recovers the pubkey hash from each header independently and only compares the hashes, never the headers themselves: [1](#0-0) 

`handle_poison_microblock` calls only that check before recording the report and computing the reward-entitlement tuple: [2](#0-1) [3](#0-2) 

The mempool-level static check (`will_admit_mempool_tx` path) mirrors the same gap: it compares `sequence`, `prev_block`, `version`, and the two recovered pubkey hashes, but never compares full header/`block_hash()` equality: [4](#0-3) 

Because `StacksMicroblockHeader` derives `PartialEq` on all fields including `signature`, if the attacker supplies `h2 = h1.clone()`, then trivially `sequence1==sequence2`, `prev_block1==prev_block2`, `version1==version2`, and `pkh1==pkh2` (identical signature recovers to the identical key) — all guard conditions in both the mempool check and `handle_poison_microblock` are satisfied. The existing test suite only ever constructs the poison pair from two *genuinely different* microblocks and asserts `mblock_1 != mblock_2` as a **test-authored precondition**, not as an assertion enforced by production code: [5](#0-4) 

There is no code path — not `check_microblock_header_signer`, not `handle_poison_microblock`, not the mempool's `PoisonMicroblock` admission arm — that rejects `h1 == h2`.

Exploit flow: attacker observes any legitimately-signed microblock header `h` from a miner (microblock headers/pubkey-hash announcements are public), submits a `PoisonMicroblock(h, h.clone())` transaction from their own account. It passes mempool admission, passes `check_microblock_header_signer` (recovers identical `pkh`), and `insert_microblock_poison` records the attacker as the reporter for that pubkey-hash/sequence, entitling them to a commission of the framed miner's coinbase once it matures — despite the miner never having double-signed a fork.

### Impact Explanation
This is a reward mis-payment specific to the poison-microblock mechanism: an honest miner whose microblock pubkey hash is targeted has their coinbase commission diverted to an attacker who never observed or proved an actual equivocation. No chain split, no invalid block acceptance, and no divergence in consensus-critical state occurs — this only affects the size of a reward payout tied to a bogus poison report. Per the stated severity taxonomy this is a "poison ... reward mis-payment," which is categorized High rather than Critical.

### Likelihood Explanation
The attacker needs no privileged role, no majority stake, and no other party's key: only visibility of one publicly-signed microblock header (trivially obtainable by observing any miner's normal microblock stream) and the ability to broadcast a self-signed `PoisonMicroblock` transaction, paying only its transaction fee. The attack is repeatable against any active/matured microblock pubkey hash that is currently valid and unreported, bounded only by `MINER_REWARD_MATURITY` and by being first to report (per `insert_microblock_poison`'s "lower sequence wins" logic, `mblock_header_1.sequence`). This is fully feasible for a single unprivileged participant.

### Recommendation
In `check_microblock_header_signer` (or immediately before it in `handle_poison_microblock`), add an explicit distinctness check: reject if `mblock_hdr_1.block_hash() == mblock_hdr_2.block_hash()` (or equivalently compare `tx_merkle_root`/`signature`) so identical headers cannot be accepted as proof of equivocation. Apply the equivalent check in the mempool's `PoisonMicroblock` admission arm in `blocks.rs` as defense in depth.

### Proof of Concept
Rust integration test plan (mirroring the existing `process_poison_microblock` test harness in `stackslib/src/chainstate/stacks/db/transactions.rs`):
1. Set up a `TestChainstateBuilder` chainstate, insert a microblock pubkey hash via `StacksChainState::insert_microblock_pubkey_hash` at height 1 for `block_pubkh` (derived from `block_privk`).
2. Construct one legitimately-signed microblock header `h = make_signed_microblock(&block_privk, &privk, BlockHeaderHash([0x11; 32]), 123).header`.
3. Build `TransactionPayload::PoisonMicroblock(h.clone(), h.clone())` (byte-identical headers, `h == h.clone()`), sign with an unrelated `reporter_privk`.
4. Call `StacksChainState::process_transaction(&mut conn, &signed_tx_poison_microblock, false, None)`.
5. Assert on both sides of the equality:
   - `h.block_hash() == h.clone().block_hash()` (trivially true, proving no distinctness was required).
   - The call currently returns `Ok(..)` and `StacksChainState::get_poison_microblock_report(&mut conn, 1)` returns `Some((reporter_addr, 123))` — demonstrating the bogus report is accepted and recorded.
   - Expected/fixed behavior: `process_transaction` should return `Err(Error::InvalidStacksTransaction(..))` (analogous to `process_poison_microblock_invalid_transaction`'s assertion pattern) once a `block_hash()` distinctness check is added.

        mblock_hdr_1: &StacksMicroblockHeader,
        mblock_hdr_2: &StacksMicroblockHeader,
    ) -> Result<Hash160, Error> {
        let pkh1 = mblock_hdr_1.check_recover_pubkey().map_err(|e| {

                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        let pkh2 = mblock_hdr_2.check_recover_pubkey().map_err(|e| {
            Error::InvalidStacksTransaction(
                format!("Failed to recover public key: {:?}", &e),
                false,
            )
        })?;

        if pkh1 != pkh2 {
            let msg = format!(
                "Invalid PoisonMicroblock transaction -- signature pubkey hash {} != {}",
                &pkh1, &pkh2
            );
            warn!("{}", &msg);
            return Err(Error::InvalidStacksTransaction(msg, false));
        }
        Ok(pkh1)
    }
