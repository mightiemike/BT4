### Title
Front-running `socialize-debt()` lets shareholders exit before bad-debt loss is socialized - ([File: mainnet/contracts/vault/v0-vault-sbtc.clar])

### Summary
Every vault contract (`v0-vault-sbtc.clar`, `v0-vault-stx.clar`, `v0-vault-usdc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`) exposes a `socialize-debt` function that instantly writes down the vault's `lindex` (liquidity index, i.e. the share-to-asset exchange rate) to reflect a bad-debt loss [1](#0-0) . Unlike `deposit`/`redeem`, which always call `accrue()` first to keep pricing current [2](#0-1) , `socialize-debt` performs no interest accrual and applies its full loss atomically in a single state transition. This is the same "sudden, unpredictable loss distribution" bug class described in the external report for `unlockDeposit()`: any share holder who can see or anticipate the pending `socialize-debt` call can redeem beforehand at the stale, pre-loss exchange rate, shifting the entire loss onto the shareholders who remain.

### Finding Description
`redeem()` computes the amount of underlying to return using `convert-to-assets-preview`, which is derived from the currently stored `lindex`/`assets` state [3](#0-2) . That state is a cached representation of the vault's backing assets — it is only mutated when explicit vault functions run (`accrue`, `system-repay`, `socialize-debt`, etc.).

`socialize-debt(scaled-amount)` is the function that reflects a realized bad-debt loss into the exchange rate: it recomputes `new-lindex` as a proportional write-down of `current-lindex` based on the loss (`debt-reduction`) relative to `old-total-assets`, and commits it with `(var-set lindex new-lindex)` [1](#0-0) . Before this call lands, `lindex` (and therefore the redeemable value of every share) still reflects the pre-loss state — the cached price has not yet been invalidated even though its true backing ("source") has already moved (the debt is already impaired/known to be uncollectable at the time the authorized caller submits the transaction).

Because Stacks transactions are visible before confirmation and ordered within a block, a shareholder who observes (or anticipates, e.g. from an on-chain liquidation/bad-debt event) an impending `socialize-debt` call can submit `redeem()` ahead of it in the same or an earlier block. Their redemption uses the still-unwritten, higher `lindex`, letting them extract full value before the loss is applied, while the remaining shareholders absorb a proportionally larger share of the loss once `lindex` is written down. This mirrors exactly the report's `unlockDeposit()` pattern — a bonus/loss applied in one atomic step instead of being socialized gradually or accounted for pre-emptively at withdrawal time.

### Impact Explanation
Shareholders who fail to front-run absorb more than their fair share of the socialized bad debt — this is a redistribution of already-crystallized losses within the vault's LP token holders, which constitutes temporary/permanent freezing (loss) of a share of the remaining depositors' principal/yield once the bad debt event is known but not yet applied. Given the acknowledged nature of the analogous root cause and its systemic presence across all vault contracts sharing this code pattern, this qualifies as a High-impact temporary freezing-of-funds issue for depositors who cannot exit before the write-down.

### Likelihood Explanation
Likelihood is Medium: `socialize-debt` is gated by `check-caller-auth` [4](#0-3) , so it is only invoked by an authorized system contract (e.g., the market contract during liquidation of bad debt), but the triggering liquidation itself is a public, observable on-chain event, giving alert shareholders a window to redeem first.

### Recommendation
Either (a) have `socialize-debt` be preceded by / integrated into `accrue()` so all pending value changes commit atomically with no observable gap, or (b) apply the write-down retroactively/pro-rata to intervening redemptions (e.g., checkpoint bad debt at detection time rather than at `socialize-debt` execution time), or (c) socialize known bad debt gradually over multiple blocks/epochs rather than in one atomic `var-set lindex`.

### Proof of Concept
1. A borrower's position becomes bad debt; the market contract determines a `scaled-amount` to be socialized via the vault's `socialize-debt` [5](#0-4)  and this liquidation becomes visible on-chain/in the mempool before the block confirms.
2. Attacker holding vault shares (`zft`) submits `redeem()` in the same or a preceding block [3](#0-2) , converting shares to assets using the still-unadjusted `lindex`.
3. `socialize-debt` then executes, writing `lindex` down proportionally to the loss [6](#0-5) .
4. Remaining shareholders' shares are now priced against the reduced `lindex`, absorbing the loss the attacker avoided by exiting first.

Note: I was not able to fully read `mainnet/contracts/market/v0-4-market.clar` to confirm the exact call site and block-level timing guarantees for how/when `socialize-debt` is invoked relative to liquidation; this should be verified directly in that file before treating this as conclusively exploitable in production.

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
        (debt-reduction (mul-div-down scaled-amount idx INDEX-PRECISION))
        (principal-reduction (if (> scaled-principal u0)
                                (mul-div-down scaled-amount borrowed scaled-principal)
                                u0))
        ;; Write down lindex proportionally to loss in total-assets
        (new-lindex (if (and (> old-total-assets u0) (> old-total-assets debt-reduction))
                       (mul-div-down current-lindex (- old-total-assets debt-reduction) old-total-assets)
                       u0)))

    (try! (check-caller-auth))
    (asserts! (> scaled-amount u0) ERR-AMOUNT-ZERO)

    (var-set lindex new-lindex)
    (var-set principal-scaled (if (> scaled-principal scaled-amount) (- scaled-principal scaled-amount) u0))
    (var-set total-borrowed (if (> borrowed principal-reduction) (- borrowed principal-reduction) u0))
    (var-set assets (if (> current-assets principal-reduction) (- current-assets principal-reduction) u0))
