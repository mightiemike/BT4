### Title
Unbounded recursion in compiled-class bytecode-segment hashing/structuring can crash sequencer nodes on class declaration - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs], [File: crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs])

### Summary
`bytecode_hash_node` (used to compute the compiled-class hash of every declared class) and `create_bytecode_segment_structure_inner` (used by the Starknet OS when re-executing/proving a block) both recurse over the `NestedIntList`/`bytecode_segment_lengths` tree with **no depth limit**, exactly the bug class described in the php-svg-lib CVE (unbounded recursion over an attacker-influenceable tree structure leading to stack exhaustion / DoS).

### Finding Description
When a contract class is declared, its compiled-class hash is computed with `HashableCompiledClass::hash` → `hash_inner` → `bytecode_hash` → `bytecode_hash_node`: [1](#0-0) 
`bytecode_hash_node` recurses once per nesting level of the `NestedIntList` (`bytecode_segment_lengths`) with no bound on recursion depth — every `Node` variant triggers a recursive call for each child before returning.

The same unbounded pattern exists in the OS's bytecode-segment-structure builder, exercised by every sequencer/prover node when re-executing/proving a block containing the declared class: [2](#0-1) 

By contrast, the blockifier's own analogous routine explicitly guards against deep nesting with a hard assertion (`segmentation_depth <= 1`), showing that unrestricted depth in this exact data structure is a recognized hazard elsewhere in the codebase but is **not** applied to the hash-computation or OS-structure-building code paths: [3](#0-2) 

`bytecode_segment_lengths` is produced by the Sierra→CASM compiler from the submitted Sierra program's function/control-flow structure. The gateway only bounds the total Sierra bytecode size (`max_contract_bytecode_size`, default 81920 felts) and the serialized class object size — it does **not** bound the nesting depth of the resulting segment tree: [4](#0-3) [5](#0-4) 

An attacker able to craft a Sierra program that compiles into a `bytecode_segment_lengths` tree with very deep nesting (e.g. via a long chain of deeply nested function calls, each producing one additional `Node` level, well within the 81920-felt bytecode budget) can trigger a deep, unbounded recursive call chain in `bytecode_hash_node` and/or `create_bytecode_segment_structure_inner`, exhausting the call stack and crashing the process.

### Impact Explanation
- `bytecode_hash_node` runs on every node validating a DECLARE transaction and on any node re-verifying/re-executing the block (blockifier and Starknet OS), since the compiled-class hash must be recomputed to match the declared `compiled_class_hash`.
- `create_bytecode_segment_structure_inner` runs inside the Starknet OS hint `LoadClassesAndBuildBytecodeSegmentStructures`, which is exercised by every node that produces/verifies the OS proof for a block containing the class.
- A stack-overflow crash in these paths is not a gracefully recoverable error (no `Result`/`catch_unwind` boundary insulates deep native recursion from a hard stack overflow); it aborts the process. If reliably reproducible, an attacker submitting a single DECLARE transaction could crash all honest nodes attempting to validate/execute/prove that block, i.e., a network-wide halt in confirming new transactions — matching the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Likelihood is **uncertain without further empirical verification**: this analysis could not confirm (a) exactly how deep a segment tree the trusted Sierra→CASM compiler will actually emit for a given crafted program within the 81920-felt bytecode limit, or (b) the real-world stack size and per-frame cost of `bytecode_hash_node`/`create_bytecode_segment_structure_inner` needed to trigger an actual overflow versus simply being slow. The class is compiled once via a resource-limited external `cairo1-compile` subprocess before this recursion is reached, so the compiler's own segmentation heuristics (rather than raw attacker input) determine the tree shape, which may implicitly limit achievable depth. This should be validated empirically (e.g., by compiling a contract with many nested function calls and inspecting the resulting `bytecode_segment_lengths` depth) before treating this as confirmed exploitable.

### Recommendation
- Add an explicit recursion/depth bound (mirroring the `assert!(segmentation_depth <= 1, ...)` check already present in `crates/blockifier/src/execution/contract_class.rs`) to `bytecode_hash_node` in `crates/starknet_api/src/contract_class/compiled_class_hash.rs` and to `create_bytecode_segment_structure_inner` in `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`, rejecting/erroring out on excessive nesting instead of recursing unboundedly.
- Alternatively, convert both functions to iterative (explicit stack-based) traversal so depth is bounded only by available heap memory, not the call stack.
- Add a gateway-side stateless check that rejects declared classes whose compiled `bytecode_segment_lengths` nesting exceeds a safe, low bound.

### Proof of Concept
Not independently reproduced. Conceptually: craft a Cairo 1 contract whose Sierra program consists of a long chain of nested function calls (or a similarly compiler-recognized nesting pattern) that, after Sierra→CASM compilation, yields a `bytecode_segment_lengths: NestedIntList::Node(...)` tree with very deep nesting while staying under `max_contract_bytecode_size` (81920). Submit this class via a DECLARE transaction; any node computing the compiled class hash (`HashableCompiledClass::hash`) or running the OS hint that calls `create_bytecode_segment_structure` on this class would recurse to the tree's depth, potentially exhausting the stack. Verifying actual overflow requires building and testing the real compiler output, which was not performed in this analysis.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

    /// Recursively builds the nested structure and returns it with the number of items consumed.
    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }
    }
