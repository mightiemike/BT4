### Title
Global Compiled-Class Cache Skips Declaration Re-Validation for Cairo0 Classes, Allowing Reuse of Revoked (Reverted) Declarations - ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` caches compiled contract classes in a global, cross-block `ContractClassManager` cache keyed only by `ClassHash`. When a cached entry is a Cairo1 (`RunnableCompiledClass::V1*`) class, the code re-validates that the class is *still* declared in the current state before returning it, because "existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)". For Cairo0 (`RunnableCompiledClass::V0`) entries, this re-validation is skipped entirely.

### Finding Description
The relevant logic: [1](#0-0) 

For `V0` classes the branch is a no-op (`RunnableCompiledClass::V0(_) => {}`), so a cached Cairo0 class is returned as executable regardless of whether the class is currently declared. The `is_declared` trait contract itself documents this asymmetry: [2](#0-1) 

`is_declared` in the concrete Starknet-storage-backed reader determines declaration by checking whether the class's declaration block number is `<= latest_block`: [3](#0-2) 

This is directly analogous to the reported Visor `Visor.sol` bug: a previously granted authorization (there, an NFT transfer approval; here, "this class hash is a valid, declared, executable class") is cached/retained and is not re-checked/revoked when the underlying state that granted it is later invalidated (there, the NFT moving out and back; here, a declare transaction being reverted, e.g. via a chain reorg or `revert_state_diff`). The storage layer explicitly supports removing a class's declaration record on revert while keeping other data with the same class hash reachable in prior blocks: [4](#0-3) 

Because the global `ContractClassManager` cache is shared across the node's lifetime (not per-block, per-transaction, or invalidated on revert), a Cairo0 class hash that was declared, cached (e.g., during speculative/candidate execution, gateway validation, or a later-reverted block), and then has its declaration reverted, remains servable from the cache as a "declared, runnable" class to any subsequent transaction that references that class hash — with no re-validation step comparable to the one applied to Cairo1 classes.

### Impact Explanation
If a class hash's declaration can become invalid after being cached (revert of a proposed/reorged block, or any other event where `is_declared` state changes) while the compiled artifact remains in the process-global cache, subsequent transactions can execute or reference an undeclared Cairo0 class as if it were declared. This causes the sequencer to accept and execute a contract call against a class that current committed/canonical state says is not declared — an unauthorized action from the state-machine's perspective, and a source of state-transition divergence between a node that has the class cached (accepts the tx / produces one state diff) and a node that does not (rejects with `UndeclaredClassHash` / produces a different diff or block). This can manifest as honest-node divergence or a wrongly computed state diff/root during block building or OS re-execution.

### Likelihood Explanation
The trigger requires a scenario where (a) a Cairo0 class gets populated into the global cache (e.g., a declare transaction is executed/validated, or the class is queried), and (b) the declaration is subsequently invalidated in canonical state without the cache being cleared, which the code comment for the Cairo1 branch acknowledges as a real occurrence ("a declared class from a reverted block"). The asymmetric handling — validating only for Cairo1 — is a concrete, unrebutted code-level gap; however, confirming an end-to-end exploit path (e.g., proving there is no other invalidation mechanism that clears the cache on revert for V0 specifically, or that block reverts are reachable purely from unprivileged transaction submission) could not be fully verified from the available code. Uncertain point: whether `ContractClassManager`/`GlobalContractCache` is cleared on revert elsewhere in the codebase (not found in the retrieved context) — this needs to be checked in `crates/blockifier/src/state/contract_class_manager.rs` and `crates/blockifier/src/state/global_cache.rs` if such invalidation exists, the analog would not stand as Medium/High.

### Recommendation
Apply the same re-validation performed for Cairo1 classes to Cairo0 classes: before serving a cached `RunnableCompiledClass::V0` entry, call `self.state_reader.is_declared(class_hash)` (or an equivalent check for Cairo0 declaration status) and return `StateError::UndeclaredClassHash` if it no longer holds, mirroring the existing Cairo1 branch at [5](#0-4) . Alternatively, ensure the global cache is invalidated/pruned whenever a block containing a declare transaction is reverted, for both Cairo0 and Cairo1 entries.

### Proof of Concept
Could not be fully constructed/verified from the indexed code alone (no test harness was found that exercises a Cairo0-class revert-then-reuse scenario). A conceptual PoC based on the analogous Cairo1 test present in the repo (which exists precisely because this scenario is possible for V1) is: [6](#0-5) 

The equivalent PoC for Cairo0 would be: (1) declare a Cairo0 class, causing it to populate `ContractClassManager`'s global cache; (2) revert the block containing the declaration (as demonstrated for storage in [4](#0-3) ), so `is_declared`-equivalent state for that class hash becomes false; (3) submit a new transaction referencing the same class hash — because the `V0` branch performs no re-check, `get_compiled_from_class_manager` returns the cached class as runnable instead of erroring with `UndeclaredClassHash`.

    fn is_declared(&self, class_hash: ClassHash) -> StateResult<bool> {
        let state_number = StateNumber(self.latest_block);
        let class_declaration_block_number = self
            .reader()?
            .get_state_reader()
            .and_then(|sr| sr.get_class_definition_block_number(&class_hash))
            .map_err(|err| StateError::StateReadError(err.to_string()))?;
        Ok(
            matches!(class_declaration_block_number, Some(block_number) if block_number <= state_number.0),
        )

/// Tests reverting state diffs when the classes are not written to the storage
#[test]
fn declare_revert_declare_without_classes_scenario() {
    // Declare a class and a deprecated class.
    let contract_address: ContractAddress = contract_address!("0x11");
    let deprecated_class_hash = class_hash!("0xc1a55");
    let class_hash = class_hash!("0xdec1a55");
    let compiled_class_hash = compiled_class_hash!(6_u8);
    let diff0 = ThinStateDiff {
        deployed_contracts: IndexMap::from([(contract_address, deprecated_class_hash)]),
        storage_diffs: IndexMap::new(),
        deprecated_declared_classes: vec![deprecated_class_hash],
        class_hash_to_compiled_class_hash: IndexMap::from([(class_hash, compiled_class_hash)]),
        nonces: IndexMap::from([(contract_address, Nonce(StarkHash::from(1_u8)))]),
    };

    let ((reader, mut writer), _temp_dir) = get_test_storage();
    writer
        .begin_rw_txn()
        .unwrap()
        .append_state_diff(BlockNumber(0), diff0.clone())
        .unwrap()
        .commit()
        .unwrap();

    // Assert that both classes are declared.
    let state_number = StateNumber::unchecked_right_after_block(BlockNumber(0));
    let txn = reader.begin_ro_txn().unwrap();
    let state_reader = txn.get_state_reader().unwrap();
    assert!(state_reader.get_class_definition_at(state_number, &class_hash).unwrap().is_none());
    assert_eq!(
        state_reader.get_class_definition_block_number(&class_hash).unwrap(),
        Some(BlockNumber(0))
    );
    assert!(
        state_reader
            .get_deprecated_class_definition_at(state_number, &deprecated_class_hash)
            .unwrap()
            .is_none()
    );
    assert_eq!(
        state_reader.get_deprecated_class_definition_block_number(&deprecated_class_hash).unwrap(),
        Some(BlockNumber(0))
    );

    // Revert the block and assert that the classes are no longer declared.
    let (txn, _) = writer.begin_rw_txn().unwrap().revert_state_diff(BlockNumber(0)).unwrap();
    txn.commit().unwrap();
    let txn = reader.begin_ro_txn().unwrap();
    let state_reader = txn.get_state_reader().unwrap();
    assert!(state_reader.get_class_definition_block_number(&class_hash).unwrap().is_none());
    assert!(
        state_reader
            .get_deprecated_class_definition_block_number(&deprecated_class_hash)
            .unwrap()
            .is_none()
    );
