This confirms the analog: `GetSwapQuote` fetches an instantaneous `quoteExactInputSingle` spot quote from the UniswapV3-style pool inside `UniversalCore`, and that same quote is immediately used to derive `minPCOut` (with a fixed 5% slippage) which then bounds the atomically-executed `CallPRC20DepositAutoSwap` [1](#0-0) . Because the quote and the swap execution happen back-to-back inside the same on-chain transaction against the same pool reserves, an attacker can pre-manipulate the pool's spot price (e.g., via a large swap in the block/tx immediately preceding UV quorum finalization) so that `minPCOut` itself is derived from the manipulated price rather than a fair reference price — the 5% band only protects against quote-to-execution drift, not against a poisoned starting price [2](#0-1) .

### Title
Sandwichable spot-price oracle used for gas-abstraction autoswap slippage bound - (File: x/uexecutor/keeper/execute_inbound_gas.go)

### Summary
`ExecuteInboundGas` (and the analogous `gasAndPayloadDepositAutoSwap` in `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`) computes `minPCOut` for the module-driven PRC20→WPC autoswap purely from `GetSwapQuote`, an instantaneous `QuoterV2.quoteExactInputSingle` read against the live Uniswap V3 pool held on-chain by `UniversalCore` [2](#0-1) . This mirrors the reported bug class: a value that gates fund distribution (there: `Gauge.get_adjustment()`'s `balanceOf/totalSupply` ratio; here: the pool's spot price) is read and consumed for an economically consequential calculation without protection against single-block/adjacent-transaction manipulation of that same on-chain state.

### Finding Description
`ExecuteInboundGas` runs when a validator-voted inbound (`TxType_GAS_ONLY`/`GAS_AND_PAYLOAD`) reaches quorum and is executed deterministically by all honest nodes at a specific, externally-observable block. Any unprivileged EVM user can, in the transaction(s) immediately preceding this deterministic execution, swap heavily against the same Uniswap V3 pool referenced by `UniversalCore.uniswapV3Quoter`/`WPC` to push the PRC20/WPC spot price to an unfavorable level. Because `GetSwapQuote` and `CallPRC20DepositAutoSwap` both read/act on that same manipulated pool state in immediate succession [3](#0-2) , `minPCOut = quote * 95 / 100` is derived from the poisoned price rather than an unbiased reference, so the fixed 5% slippage guard cannot detect or reject the manipulation — the swap still "succeeds" against the manipulated price. The attacker can then reverse their price-moving trade in a following transaction, realizing the value that would otherwise have gone to the user's gas-abstraction deposit (or, symmetrically, an attacker could push the price up to force less PC out per PRC20 relative to fair value, degrading the user's deposit).

### Impact Explanation
This corrupts native/PRC20 asset accounting for gasless inbound execution: the amount of WPC/PC actually credited from the auto-swap leg of a user's inbound deposit can be economically siphoned toward an attacker who front/back-runs the pool around the deterministic UV-finalization block, causing a real (if bounded to the manipulable price range beyond the naive 5%) loss to the depositing user/protocol-controlled liquidity — falling under "corruption of ... accounting" and unauthorized value extraction from user-controlled funds in the universal execution flow.

### Likelihood Explanation
The trigger requires only unprivileged EVM transactions (ordinary swaps against a public pool) timed around a known, deterministically-triggered on-chain execution (ballot finalization is publicly observable pending state), with no validator, relayer, or admin privilege needed. Feasibility depends on the pool's liquidity depth and MEV/searcher tooling to land transactions adjacent to the finalizing block, which is a realistic capability on an EVM chain.

### Recommendation
Do not derive `minPCOut` solely from a same-transaction/adjacent-block spot quote. Use a TWAP-based quote (or a configurable maximum deviation from a recent TWAP) from the pool, or accept `minPCOut`/max-slippage constraints supplied and validated against an independent price reference, so a transient single-block price excursion cannot be used to justify an economically bad execution price.

### Proof of Concept
1. Attacker identifies a pending inbound (`GAS_ONLY`/`GAS_AND_PAYLOAD`) that has reached (or is close to reaching) UV quorum, which will trigger `ExecuteInboundGas`/`gasAndPayloadDepositAutoSwap` deterministically once finalized.
2. In a transaction just before finalization, attacker swaps a large amount through the same Uniswap V3 pool referenced by `UniversalCore` to move the PRC20/WPC spot price against the pending deposit.
3. When the inbound finalizes, `GetSwapQuote` returns a quote computed off the manipulated pool state; `minPCOut` (95% of that manipulated quote) still passes as the floor for `CallPRC20DepositAutoSwap`, so the deposit executes at the bad price [4](#0-3) .
4. Attacker reverses their price-moving trade in a subsequent transaction, capturing the difference that should have gone to the user's swapped PC balance.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
