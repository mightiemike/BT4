## Analog Found: Missing Zero-Address Check on Inbound `Recipient` Allows Permanent Loss of Bridged Funds

### Title
Inbound deposit path accepts `Recipient = 0x0` and permanently mints PRC20 to the zero address - (File: x/uexecutor/types/inbound.go, x/uexecutor/keeper/handler.go)

### Summary
The external report flags `TimeLoans.sol`'s `_mint`/`_burn` for not rejecting the zero address, which can silently destroy value. Push Chain's inbound-deposit path has the same class of gap: `Inbound.ValidateForExecution` validates that `Recipient` is *a syntactically valid hex address*, but never checks that it is non-zero, and the downstream mint call (`depositPRC20` → `CallPRC20Deposit`) performs no zero-address guard either.

### Finding Description
For `TxType_FUNDS` / `TxType_GAS` inbounds, execution-level validation only checks: [1](#0-0) 
`utils.IsValidAddress(p.Recipient, utils.HEX)` resolves to `common.IsHexAddress`, which purely checks hex format/length and returns `true` for the all-zero address: [2](#0-1) 

The same gap exists for the CEA path, which only checks for a non-empty, hex-formatted recipient: [3](#0-2) 

Once validation passes, `ExecuteInboundFunds` converts `Recipient` directly to an EVM address and calls `depositPRC20`, with no zero check anywhere in the call chain: [4](#0-3) [5](#0-4) 
`depositPRC20` calls `CallPRC20Deposit`, which invokes `depositPRC20Token` on `UniversalCore` unconditionally with the caller-supplied `to` address: [6](#0-5) 

The same pattern (no zero-address gate before minting) recurs in the FUNDS_AND_PAYLOAD/isCEA smart-contract/EOA branches: [7](#0-6) 

Because the deposit call *succeeds* (it is a valid, well-formed mint call to `0x000...000`), the code treats this as `Status: "SUCCESS"` in the PCTx — no `INBOUND_REVERT` outbound is created (reverts are only built on `err != nil`). The bridged asset value is thus converted into PRC20 tokens minted at the zero address, which is unrecoverable — a permanent loss of user-bridged funds.

### Impact Explanation
An inbound event whose `Recipient` field is `0x0000000000000000000000000000000000000000` passes all Go-level validation and reaches the mint call. The bridged asset is deposited as PRC20 balance at the zero address, which no account can ever spend from — this is a permanent, unauthorized loss of protocol/user-controlled funds. This falls squarely within the allowed impact "permanent loss ... of user or protocol-controlled funds" and is reachable purely from an ordinary/attacker-controlled recipient value in the inbound event data (not from any privileged actor), because the recipient field is asserted by whoever emits the event on the source chain, and honest validators/nodes will still vote and finalize such an inbound as observed truth.

### Likelihood Explanation
The trigger requires only that an inbound's `Recipient` field, as attested by the source-chain gateway event, be the zero address. This can occur either as user/relayer error or as a deliberate griefing/loss vector (e.g., a malicious front-end or integration bug encoding a zero address, or an attacker deliberately depositing on behalf of a victim address they mistype as zero to grief them, though self-inflicted misuse is the primary path). Since honest validators simply vote on what they observe on the source chain, no validator or node misbehavior is required — this is reachable through ordinary user-driven inbound flows.

### Recommendation
Add an explicit zero-address rejection in `Inbound.ValidateForExecution` (both the FUNDS/GAS branch and the isCEA branch) analogous to OpenZeppelin's `_mint`/`_burn` zero-address checks, e.g.:
```go
if strings.EqualFold(p.Recipient, EvmZeroAddress) {
    return errors.Wrap(sdkerrors.ErrInvalidAddress, "recipient cannot be zero address")
}
```
Additionally, add a defense-in-depth check in `depositPRC20` / `CallPRC20Deposit` (or in the `UniversalCore.depositPRC20Token` contract, if in scope) to refuse minting to `address(0)`, so that any future caller of these internal functions cannot accidentally or maliciously burn value.

### Proof of Concept
1. Construct an `Inbound` with `TxType = TxType_FUNDS`, `Amount = "1000000"`, valid `AssetAddr`, and `Recipient = "0x0000000000000000000000000000000000000000"`.
2. Submit via `MsgVoteInbound` from enough validators to reach quorum — `ValidateBasic` and `ValidateForExecution` both pass (see `x/uexecutor/types/inbound_test.go` patterns for how `0x000...0000beef`-style addresses pass identical checks; the all-zero variant is not special-cased).
3. `ExecuteInboundFunds` calls `depositPRC20(ctx, sourceChain, assetAddr, common.HexToAddress("0x000...0"), amount)`, which succeeds and mints PRC20 to the zero address; the PCTx is recorded as `"SUCCESS"`, with no revert outbound generated.
4. Querying `balanceOf(0x0)` on the PRC20 contract shows the deposited amount permanently stranded.

```go
	case COSMOS:
		_, err := sdk.AccAddressFromBech32(addr)
		return err == nil
	case HEX:
		return common.IsHexAddress(addr)
	case EITHER:
```

```go
func (k Keeper) depositPRC20(
	ctx sdk.Context,
	sourceChain string,
	assetAddr string,
	recipient common.Address,
	amountStr string,
) (*vmtypes.MsgEthereumTxResponse, error) {
	// get token config
	tokenConfig, err := k.uregistryKeeper.GetTokenConfig(ctx, sourceChain, assetAddr)
	if err != nil {
		return nil, err
	}

	if tokenConfig.NativeRepresentation == nil {
		return nil, fmt.Errorf("token config for %s:%s has no native representation", sourceChain, assetAddr)
	}
	prc20Address := tokenConfig.NativeRepresentation.ContractAddress
	prc20AddressHex := common.HexToAddress(prc20Address)

	// convert amount
	amount := new(big.Int)
	amount, ok := amount.SetString(amountStr, 10)
	if !ok {
		return nil, fmt.Errorf("invalid amount: %s", amountStr)
	}

	k.Logger().Debug("EVM call: depositPRC20Token",
		"prc20", prc20AddressHex.Hex(),
		"recipient", recipient.Hex(),
		"amount", amountStr,
	)

	// call PRC20 deposit
	return k.CallPRC20Deposit(ctx, prc20AddressHex, recipient, amount)
}
```

```go
func (k Keeper) CallPRC20Deposit(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // sender: module account
		handlerAddr,        // destination
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20Token",
		prc20Address,
		amount,
		to,
	)
}
```
