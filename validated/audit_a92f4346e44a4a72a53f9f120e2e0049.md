### Title
Quadratic-Time Denial of Service in App Proxy HMAC Validation via Unbounded Duplicate Query Parameters - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
The `normalizeQuery` function used by `validateHmac` builds a merged query object from a `URLSearchParams` instance by iterating over every entry and, for repeated keys, concatenating the new value onto the existing accumulated string. This loop has no bound on the number of repeated keys or on the size of the accumulated string, so an attacker can force unbounded, quadratic-time string concatenation purely through a crafted query string, before the HMAC itself is ever checked. This mirrors the reported bug class in the external report: a loop whose iteration count/cost is driven directly by attacker-controlled input length, executed inside an authentication-verification code path reachable by an anonymous request.

### Finding Description
`normalizeQuery` in [1](#0-0)  converts a `URLSearchParams` query into a plain object. For any key that is not one of the four protected single-value params (`hmac`, `shop`, `signature`, `timestamp`), repeated occurrences are merged with:
```
normalizedQuery[key] = `${existingValue},${value}`;
```
This happens inside a `for...of` loop over `query.entries()` with no limit on the number of entries and no limit on the growing string length. Each iteration re-copies the entire accumulated string, so N repeated occurrences of an arbitrary key cost O(N²) time/memory, entirely before `validateHmac` gets to compare the HMAC/signature at [2](#0-1) .

This function is reached from an anonymous, pre-authentication HTTP request via the App Proxy authentication flow. Both `shopify-app-remix` and `shopify-app-react-router` build a fresh `URLSearchParams` directly from the incoming request URL and hand it to `api.utils.validateHmac(searchParams, {signator: 'appProxy'})`: [3](#0-2) [4](#0-3) 

Notably, the HMAC/signature validity check occurs only *after* `normalizeQuery` fully processes the query, so the expensive loop runs regardless of whether the request is legitimately signed by Shopify. Because app proxy routes are ordinary HTTP endpoints exposed by the merchant's storefront/app that Shopify forwards requests to, nothing prevents an attacker from calling the endpoint directly with an arbitrarily crafted query string, bypassing Shopify's proxy entirely.

### Impact Explanation
Node.js executes JavaScript on a single thread; a single request that triggers O(N²) synchronous string concatenation will block the event loop for the duration of that computation, delaying or effectively denying all other requests being served by that process (including OAuth callbacks, webhook processing, and normal app traffic) — an algorithmic-complexity Denial-of-Service of an authentication handler, analogous to the "gas bomb" pattern in the source report except the cost model is CPU time/memory instead of gas.

### Likelihood Explanation
The attack requires only a single unauthenticated HTTP GET request with a long query string containing many repeated instances of any non-reserved parameter name (e.g., `&a=1&a=1&a=1...`), which fits comfortably within typical URL length limits (tens of thousands of short repeated params). No secrets, valid HMAC, or prior session are required, and the endpoint is a standard, publicly reachable app-proxy route that every app using `shopify-app-remix`/`shopify-app-react-router` app proxy support exposes.

### Recommendation
Bound the cost of `normalizeQuery`: cap the total number of query parameters and/or the number of repeated occurrences per key before iterating, reject requests exceeding a small fixed limit early, and/or replace repeated string concatenation with an array push + single `join(',')` at the end to avoid quadratic blow-up. Ideally, this bound should be enforced before any processing of the query, independent of HMAC signator type.

### Proof of Concept
```
GET /apps/proxy/some-path?shop=test.myshopify.com&signature=x&timestamp=1700000000&a=1&a=1&a=1... (repeated tens of thousands of times to fill the URL)
```
Sending this request directly to an app's app-proxy route (no valid HMAC required) causes `authenticateAppProxyFactory` → `validateAppProxyHmac` → `api.utils.validateHmac` → `normalizeQuery` to perform O(N²) string concatenation on the repeated `a` parameter before ultimately rejecting the request for an invalid signature, consuming disproportionate CPU/memory on a single synchronous call.

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}

async function validateAppProxyHmac(
  params: BasicParams,
  url: URL,
): Promise<boolean> {
  const {api, logger} = params;

  try {
    let searchParams = new URLSearchParams(url.search);
    if (!searchParams.get('index')) {
      searchParams.delete('index');
    }

    let isValid = await api.utils.validateHmac(searchParams, {
      signator: 'appProxy',
    });

    if (!isValid) {
      const cleanPath = url.pathname
        .replace(/^\//, '')
        .replace(/\/$/, '')
        .replaceAll('/', '.');
      const data = `routes%2F${cleanPath}`;

      searchParams = new URLSearchParams(
        `?_data=${data}&${searchParams.toString().replace(/^\?/, '')}`,
      );

      isValid = await api.utils.validateHmac(searchParams, {
        signator: 'appProxy',
      });

      if (!isValid) {
        const searchParams = new URLSearchParams(
          `?_data=${data}._index&${url.search.replace(/^\?/, '')}`,
        );

        isValid = await api.utils.validateHmac(searchParams, {
          signator: 'appProxy',
        });
      }
    }
