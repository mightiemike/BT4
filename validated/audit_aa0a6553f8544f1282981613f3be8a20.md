### Summary
`execute_replace_class` in the Starknet OS Cairo program performs the `replace_class` state mutation for a contract address without checking that the supplied `class_hash` corresponds to an actually-declared class, leaving a `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment in place of the check. ### Finding Description
Like the audited bug (`addBSPOperator()` mutating protocol state for a validator without checking that validator's enabled status), this is a missing-status-check-before-state-mutation bug reachable directly from an unprivileged transaction sender: any account contract invoked by an ordinary `INVOKE` transaction can call the `replace_class` syscall to change its own class hash. In the OS re-execution path, `execute_replace_class` reads the request's `class_hash`, immediately builds a new `StateEntry` with that `class_hash`, and writes it into `contract_state_changes` — with no assertion that the class hash was ever declared: [2](#0-1) 

This is inconsistent with the blockifier's own (off-chain) implementation of the same syscall, both in the deprecated syscall hint processor and in the syscall test suite, which explicitly reads the compiled class (`state.get_compiled_class(request.class_hash)?`) before allowing the class hash to be set, and rejects undeclared class hashes with an `"is not declared"` error: [3](#0-2) [4](#0-3) 

The OS is the component that produces the state diff that is committed as the canonical state root (via Patricia tree updates) and reproduces block execution for proof generation. If the OS accepts a `replace_class` to an undeclared (never-compiled, non-existent) class hash while the blockifier (used by the sequencer's execution/validation path) rejects it, the two code paths diverge on the same transaction:
- The sequencer's blockifier-based execution would reject/revert the transaction (undeclared class), while
- The OS re-execution (used for proof/consistency checking of the block) would accept it and commit a contract's class hash pointing to a non-existent class.

This is exactly the "should validate X's enabled/declared status before mutating state tied to X" bug class from the report, mapped onto the reachable OS syscall-implementation path.

### Impact Explanation
If the OS state transition function computes a different state root than the blockifier-based sequencer execution for the same block (because the OS omits the "class must be declared" check that the blockifier enforces), this leads to a wrong committed state root/block hash, or an inability for the OS to soundly re-execute/prove a block that the sequencer already committed (since a contract's class hash could point to an undeclared, unusable class hash in the committed state, making that contract's future calls fail or make the state root diverge between the execution engine and the proving OS). Both are Medium/High severity outcomes per the given criteria (wrong committed root, honest-node divergence).

### Likelihood Explanation
Reachable directly and cheaply by a single unprivileged transaction: any deployed contract simply needs to invoke `replace_class_syscall(class_hash)` with an arbitrary, non-existent class hash from an `__execute__` or similar entry point — no special privilege, staking, or governance role required. The only gating factor is whether an attacker's contract actually gets invoked with a replace_class call in a block that's later processed through the OS with this same missing check, which is a normal contract capability, not a special role.

### Recommendation
Add an explicit "class hash must be declared" check to `execute_replace_class` in `syscall_impls.cairo`, mirroring the blockifier's `state.get_compiled_class(request.class_hash)` check, before writing the new `StateEntry`. This resolves the outstanding `TODO(Yoni, 1/1/2026)` and removes the potential divergence between blockifier execution and OS re-execution for `replace_class`.

### Proof of Concept
1. Deploy or use an existing account/contract that has an entry point invoking `replace_class_syscall(class_hash=<undeclared_arbitrary_felt>)`.
2. Submit an ordinary `INVOKE` transaction calling that entry point with an undeclared class hash (one that was never the subject of a successful `DECLARE` transaction).
3. In the OS Cairo implementation, `execute_replace_class` (crates/apollo_starknet_os_program/.../syscall_impls.cairo, lines ~881-920) performs no declared-class check and unconditionally writes the new `class_hash` into `contract_state_changes`, whereas the blockifier's equivalent execution path (`crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs::replace_class`, and the syscall test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`) rejects the same call with `"is not declared"`.
4. This produces divergent outcomes for the identical transaction between the sequencer's blockifier execution and the OS's re-execution/proving pass, which can manifest as a wrong committed state root or an inability of the OS to soundly reproduce the sequencer's committed block.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
