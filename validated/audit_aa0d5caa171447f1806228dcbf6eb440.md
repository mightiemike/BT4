### Title
Lost-update race between concurrent `write_through` calls silently persists a stale slot-list version to disk while leaving the in-mem entry marked clean - ([File: accounts-db/src/accounts_index/in_mem_accounts_index.rs])

### Summary
`InMemAccountsIndex::try_write_through` snapshots `(ref_count, slot_list)` under one lock acquisition, releases the lock, and later performs an unlocked disk write of that snapshot followed by a locked compare-and-clear-dirty check. If a concurrent `replace()` (or `slot_list_mut_with_entry`/`upsert`) call on the same pubkey completes its *own* full write-through cycle (disk write + successful dirty-clear) in the window between the snapshot and the stale write, the stale write silently overwrites the disk entry with older data while the in-memory entry stays clean, causing a permanent (until next mutation) mismatch between disk-persisted state and true newest account state.

### Finding Description
`try_write_through` reads the entry's state and releases the lock before writing to disk: [1](#0-0) 

`write_through` performs the actual disk write *unconditionally* (no currency check before the write), then re-acquires the lock only to verify and possibly clear the dirty flag: [2](#0-1) 

`replace()` (invoked e.g. from background obsolete-account / duplicate-slot maintenance) takes the write lock, swaps in a newer `SlotListItem`, marks the entry dirty, and — when `should_write_through` and the slot list has collapsed to one entry with `ref_count == 1` — calls `write_through` itself: [3](#0-2) 

Race sequence:
1. Thread A (`try_write_through`) reads `(slot_old, info_old)` under the slot-list read lock, then releases it (step 1 of `try_write_through` completes before `write_through` is invoked).
2. Thread B (`replace`) acquires the write lock, installs `new_item`, marks dirty, releases the lock, then itself calls `write_through(new_item)`: writes `new_item` to disk, re-locks, finds the entry still matches `new_item`, and clears dirty. Disk and mem are now consistent.
3. Thread A now calls `write_through(pubkey, slot_old, info_old)` with its stale snapshot. `write_to_disk` unconditionally overwrites disk with the **old** value, regressing it past B's write. Thread A then locks the entry to check `slot_list[0] == (slot_old, info_old)`; this fails because the entry now holds `new_item`, so `clear_dirty()` is *not* called — but the entry was **already clean** from step 2, and A never re-marks it dirty on mismatch.

Result: the entry is clean (implying "disk == mem") while disk actually holds the pre-replace stale value. The documented invariant in the code comment — "if it runs after, it will re-dirty the now-clean entry and call write_through itself" — only covers the case where the concurrent upsert/replace happens *after* thread A's check, not the case where B's entire write-through cycle (write + successful clear) completes strictly between A's read and A's write. There is no lock spanning the disk write and equality check that also excludes a second independent writer's full cycle, so this ordering is possible.

### Impact Explanation
Once the entry is (incorrectly) marked clean with stale data on disk, subsequent eviction of the entry from the in-memory map (a clean entry is evictable without any further disk write) leaves the disk index holding a stale/incorrect account version. A later lookup that misses the in-memory cache (`get_internal_inner` falls back to `load_account_entry_from_disk`) will load this stale slot-list entry, producing a wrong-version account load and potential hash/capitalization divergence relative to nodes with different race timing. This matches the "stale or wrong-version account load" / "hash or capitalization divergence" bounty categories.

### Likelihood Explanation
Requires `should_write_through == true` (disk-index mode enabled) and two independent code paths mutating/writing-through the same pubkey concurrently — `try_write_through` (called from `write_through_pubkeys`, itself triggered from `do_flush_slot_cache` when a pubkey drops out of the cache) racing with `replace()` (called from background AccountsDb maintenance) on the same pubkey. The race window is narrow (between an unlocked read and unlocked disk I/O), but disk I/O latency widens it considerably, and it is repeatable under stress with a high write/rewrite frequency, which an unprivileged user can induce by repeatedly rewriting/closing/reopening their own accounts to maximize concurrent index churn.

### Recommendation
Make the "capture the value to write" and "write it through" atomic with respect to other write-through cycles for the same pubkey per-entry — e.g., have `try_write_through` pass a generation/version token or hold a per-entry write-through mutex across the capture-write-check sequence, and on mismatch during the post-write check, explicitly re-mark the entry dirty rather than leaving its prior dirty state unchanged. Alternatively, only call `clear_dirty`/leave-dirty decisions based on a compare against the *current* value fetched immediately before the disk write (not a value captured before releasing the lock), or serialize `write_through` invocations per bin/pubkey.

### Proof of Concept
```rust
// accounts-db/src/accounts_index/in_mem_accounts_index.rs (test module)
#[test]
fn test_race_try_write_through_vs_replace_leaves_stale_disk_value() {
    let index = new_should_write_through_for_test(None);
    let pubkey = solana_pubkey::new_rand();
    let old_slot = 1;
    let old_info = 10;
    let new_slot = 1;
    let new_info = 20;

    // Seed entry: dirty, single-slot, ref_count == 1.
    let new_value = PreAllocatedAccountMapEntry::new(old_slot, old_info, &index.storage, true);
    index.upsert(&pubkey, new_value, None, &mut ReclaimsSlotList::new(), UpsertReclaim::IgnoreReclaims);

    // Simulate thread A's try_write_through "capture" step manually (before its write_through call).
    let captured = index.get_only_in_mem(&pubkey, false, |entry| {
        let entry = entry.unwrap();
        let sl = entry.slot_list_read_lock();
        Some(sl[0])
    }).unwrap();
    assert_eq!(captured, (old_slot, old_info));

    // Thread B: replace() runs to completion first, installing + write-through'ing new_item.
    index.replace(&pubkey, (new_slot, new_info), old_slot);
    index.get_only_in_mem(&pubkey, false, |entry| {
        assert!(!entry.unwrap().dirty(), "replace's write_through should have cleared dirty");
    });
    let (disk_slot_list, _) = index.load_from_disk(&pubkey).unwrap();
    assert_eq!(disk_slot_list, SlotList::from([(new_slot, new_info)]));

    // Thread A now finally performs write_through with its stale captured value.
    index.write_through_for_test(&pubkey, captured.0, captured.1); // expose write_through for test

    // BUG: disk now regressed to stale value, but entry remains clean.
    let (disk_slot_list_after, _) = index.load_from_disk(&pubkey).unwrap();
    index.get_only_in_mem(&pubkey, false, |entry| {
        let dirty = entry.unwrap().dirty();
        assert_eq!(
            disk_slot_list_after, SlotList::from([(new_slot, new_info)]),
            "disk must not regress to stale value from Thread A's late write_through \
             while entry (dirty={dirty}) is clean"
        );
    });
}
```
Expected (buggy) result: the assertion fails — `disk_slot_list_after` equals `[(old_slot, old_info)]` (the stale value) while the in-mem entry is clean, demonstrating the disk index has silently regressed and will not be repaired until the next external mutation dirties the entry again.

    /// Write `(slot, account_info)` to the disk index, then under the slot list read lock
    /// verify the in-mem entry still matches; if so, clear the dirty flag so the entry
    /// is eligible for eviction without waiting for the background flush.
    ///
    /// We hold the slot list read lock during the equality check to prevent concurrent
    /// modifications from invalidating our check between the disk write and the dirty-clear.
    /// Any concurrent upsert that modifies the slot list must hold the write lock, so it
    /// cannot proceed until we release. If it ran before us the check will fail and we leave
    /// the entry dirty for the next write to clean up; if it runs after, it will re-dirty
    /// the now-clean entry and call write_through itself.
    fn write_through(&self, pubkey: &Pubkey, slot: Slot, account_info: T) {
        let disk = self.bucket.as_ref().unwrap();
        let disk_entry = [(slot, account_info.into())];
        let grow_us = Self::write_to_disk(disk, pubkey, &disk_entry);
        Self::update_stat(&self.stats().flush_entries_updated_on_disk_immediate, 1);
        Self::update_stat(&self.stats().flush_grow_us, grow_us);
        self.get_only_in_mem(pubkey, false, |entry| {
            if let Some(entry) = entry {
                let slot_list = entry.slot_list_read_lock();
                if slot_list.len() == 1
                    && slot_list[0] == (slot, account_info)
                    && entry.ref_count() == 1
                {
                    entry.clear_dirty();
                }
            }
        });
    }

    pub fn try_write_through(&self, pubkey: &Pubkey) {
        let to_write = self.get_only_in_mem(pubkey, false, |entry| {
            entry.and_then(|entry| {
                if !entry.dirty() {
                    return None;
                }

                let slot_list = entry.slot_list_read_lock();
                match (entry.ref_count(), &slot_list[..]) {
                    (1, [info]) => Some(*info),
                    _ => None,
                }
            })
        });
        if let Some((slot, info)) = to_write {
            self.write_through(pubkey, slot, info);
        }
    }

    pub fn replace(&self, pubkey: &Pubkey, new_item: SlotListItem<T>, old_slot: Slot) {
        let mut should_write_through = false;

        self.get_or_create_index_entry_for_pubkey(pubkey, |entry| {
            let mut slot_list = entry.slot_list_write_lock();
            let mut found_slot = false;
            let slot_list_length = slot_list.retain_and_count(|cur_item| {
                if cur_item.0 == old_slot {
                    assert!(
                        !found_slot,
                        "duplicate entry at slot {old_slot} in slot_list"
                    );
                    found_slot = true;
                    *cur_item = new_item;
                }
                true
            });
            assert!(
                found_slot,
                "Expected to find a slot to replace in the slot list"
            );
            entry.mark_dirty();

            should_write_through =
                self.should_write_through && slot_list_length == 1 && entry.ref_count() == 1;
        });
        if should_write_through {
            let (slot, account_info) = new_item;
            self.write_through(pubkey, slot, account_info);
        }
    }
