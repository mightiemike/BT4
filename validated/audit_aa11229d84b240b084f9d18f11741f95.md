### Title
CancelAllUnfreezeV2Processor.validate() omits the committee feature-flag check present in CancelAllUnfreezeV2Actuator.validate(), allowing the TVM opcode path to bypass the CancelAllUnfreezeV2 dynamic parameter gate - (File: actuator/src/main/java/org/tron/core/vm/nativecontract/CancelAllUnfreezeV2Processor.java)

### Summary
`CancelAllUnfreezeV2Processor.validate` [1](#0-0)  only checks for a non-null repository, address validity, and account existence, but never calls `dynamicStore.supportAllowCancelAllUnfreezeV2()`. In contrast, `CancelAllUnfreezeV2Actuator.validate` explicitly throws if the committee has not enabled the feature [2](#0-1) . This is called from the TVM (`Program.java`, referenced by the native contract processor for the `CANCELALLUNFREEZEV2` opcode), meaning smart-contract-triggered invocations skip the committee gate that direct-transaction invocations enforce.

### Finding Description
The two code paths that perform the "cancel all unfreeze V2" operation - the direct-transaction `CancelAllUnfreezeV2Actuator` and the TVM opcode-driven `CancelAllUnfreezeV2Processor` - are supposed to enforce the same business rules. The actuator's `validate()` explicitly gates the operation behind the `CancelAllUnfreezeV2` dynamic parameter via `dynamicStore.supportAllowCancelAllUnfreezeV2()` [2](#0-1) , and additionally requires a non-empty `unfrozenV2List` [3](#0-2) .

The processor's `validate()`, invoked from the TVM native-contract dispatch in `Program.java` for the `CANCELALLUNFREEZEV2` opcode, performs neither check [1](#0-0) . As a result, if the committee disables the feature (sets the `CancelAllUnfreezeV2` dynamic parameter to 0, so `supportAllowCancelAllUnfreezeV2()` returns false), the direct `CancelAllUnfreezeV2Contract` transaction path is correctly blocked, but a smart contract invoking the corresponding TVM opcode can still successfully execute `CancelAllUnfreezeV2Processor.execute()`, mutating account state (clearing `unfrozenV2List`, crediting balance, and adjusting total resource weights).

### Impact Explanation
This breaks committee-gated feature control: a governance decision to disable cancel-all-unfreeze functionality can be silently bypassed by any unprivileged user deploying and invoking a contract with the `CANCELALLUNFREEZEV2` opcode. Repeated invocation is not blocked by an empty-list check either (unlike the actuator), so callers can perform this state-churn operation even in edge cases the actuator would reject, undermining the consistency invariant that a public entry point must not have weaker validation than the equivalent direct-transaction path.

### Likelihood Explanation
Exploitation only requires: the committee has set `supportAllowCancelAllUnfreezeV2()` to false (a realistic operational scenario, e.g. temporarily disabling the feature), and an attacker deploys/calls a contract executing the `CANCELALLUNFREEZEV2` opcode via a standard `TriggerSmartContract`. No special privileges are needed, and it is deterministically reproducible on every call.

### Recommendation
Add the same committee gate to `CancelAllUnfreezeV2Processor.validate()`:
```java
if (!repo.getDynamicPropertiesStore().supportAllowCancelAllUnfreezeV2()) {
  throw new ContractValidateException("Not support CancelAllUnfreezeV2 transaction, need to be opened by the committee");
}
```
placed before/alongside the existing checks, mirroring `CancelAllUnfreezeV2Actuator.validate()` [2](#0-1) . Consider also mirroring the empty-list check for full parity with the actuator's validation.

### Proof of Concept
```java
// In a test extending the existing FreezeV2Test-style harness
// (framework/src/test/java/org/tron/common/runtime/vm/FreezeV2Test.java has related opcode tests)

@Test
public void testCancelAllUnfreezeV2ProcessorBypassesFeatureFlag() throws Exception {
  // 1. Disable the feature flag
  dynamicPropertiesStore.saveAllowCancelAllUnfreezeV2(0L); // supportAllowCancelAllUnfreezeV2() == false

  // 2. Build a valid CancelAllUnfreezeV2Param for an existing account with unfrozenV2 entries
  CancelAllUnfreezeV2Param param = new CancelAllUnfreezeV2Param();
  param.setOwnerAddress(ownerAddress);

  CancelAllUnfreezeV2Processor processor = new CancelAllUnfreezeV2Processor();

  // 3. Assert Processor.validate() does NOT throw, despite feature being disabled
  //    (this is the bug: it should throw ContractValidateException here)
  processor.validate(param, repository); // succeeds unexpectedly

  // 4. Contrast with Actuator.validate() which correctly throws
  CancelAllUnfreezeV2Actuator actuator = new CancelAllUnfreezeV2Actuator();
  actuator.setChainBaseManager(chainBaseManager);
  actuator.setAny(Any.pack(cancelAllUnfreezeV2Contract));
  Assert.assertThrows(ContractValidateException.class, actuator::validate);
}
```
Expected result confirming the bug: `processor.validate()` completes without exception while `actuator.validate()` throws `ContractValidateException` with message "Not support CancelAllUnfreezeV2 transaction, need to be opened by the committee", demonstrating the TVM path bypasses the committee-controlled feature flag.
