Based on the code, `throwIfCustomStoreApp` in `packages/apps/shopify-api/lib/auth/oauth/oauth.ts` is called unconditionally at the very top of both `begin()` and `callback()`, before any shop/query parameter is even parsed: [1](#0-0) 

and its implementation simply throws `PrivateAppError` whenever `isCustomStoreApp` is `true`, with no shop-comparison logic at all: [2](#0-1) 

This means that for a custom-app config, the entire OAuth `begin`/`callback` flow is blocked at the very first line — there is no code path where a callback with a mismatched `shop` param could reach the token-exchange logic, because the function never proceeds past this check. This is also documented behavior: custom/private apps are explicitly designed to skip OAuth entirely, using a pre-provisioned `adminApiAccessToken` instead of a session derived from a callback: [3](#0-2) 

This is corroborated by existing tests confirming `begin`/`callback` reject any attempt when `isCustomStoreApp: true`: [4](#0-3) 

Additionally, `authCallback` in `packages/apps/shopify-app-express/src/auth/auth-callback.ts` just delegates to `api.auth.callback`, so it inherits this same protection and never reaches session storage for a custom-store-app config: [5](#0-4) 

There is no reachable path for an unprivileged attacker to submit a mismatched-shop callback that bypasses `throwIfCustomStoreApp`, because the OAuth callback mechanism itself is fully disabled for custom-app configurations before any shop/state/HMAC comparison logic executes. The premise of the question (a shop-param mismatch bypassing a gating check) does not apply, since there is no conditional gate to bypass — it's an unconditional throw.

function throwIfCustomStoreApp(
  isCustomStoreApp: boolean,
  message: string,
): void {

    throw new ShopifyErrors.PrivateAppError(message);
  }

## Basic concepts

A store-specific custom app does not use the OAuth process to authenticate - it uses the secrets established during the app creation and install process to access the API.  As a result, there are no sessions to be retrieved from incoming requests and stored in a database, etc.

When initializing `shopifyApi` in a custom app

- set the `isCustomStoreApp` configuration property to `true`
- set the `apiSecretKey` configuration property to the **API secret key** obtained during the installation process (step 2 in the [prerequisites](#prerequisites)).
- set the `adminApiAccessToken` configuration property to the **Admin API access token** obtained during the installation process (step 2 in the [prerequisites](#prerequisites)).
