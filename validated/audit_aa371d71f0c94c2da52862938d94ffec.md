### Title
Unprivileged `TransferToGasKey` Inflates Gas Key Balance Above `MAX_BALANCE_TO_BURN`, Blocking `DeleteKey` and `DeleteAccount` — (`runtime/runtime/src/access_keys.rs`)

---

### Summary

The `TransferToGasKey` action carries no actor-permission check, so any unprivileged account can fund a gas key it does not own. Both `action_delete_key` and `action_delete_account` are gated on the gas key balance being ≤ `GasKeyInfo::MAX_BALANCE_TO_BURN` (1 NEAR). An attacker who keeps the balance above that threshold permanently blocks the account owner from deleting the gas key or deleting the account, mirroring the external "griefing via raw balance check" pattern exactly.

---

### Finding Description

**Gas key balance check in `delete_gas_key`**

`action_delete_key` dispatches to `delete_gas_key` when the key is a gas key. The first thing `delete_gas_key` does is:

```rust
if gas_key_info.balance > GasKeyInfo::MAX_BALANCE_TO_BURN {
    result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh { … }.into());
    return Ok(());
}
```

`MAX_BALANCE_TO_BURN` is exactly 1 NEAR. [1](#0-0) [2](#0-1) 

The same aggregate check is applied in `action_delete_account`:

```rust
let gas_key_balance_to_burn = compute_gas_key_balance_sum(state_update, account_id)?;
if gas_key_balance_to_burn > GasKeyInfo::MAX_BALANCE_TO_BURN {
    result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh { … }.into());
    return Ok(());
}
``` [3](#0-2) 

**`TransferToGasKey` has no actor-permission guard**

`check_actor_permissions` explicitly exempts `TransferToGasKey` from the `actor_id == account_id` requirement:

```rust
Action::CreateAccount(_)
| Action::FunctionCall(_)
| Action::Transfer(_)
| Action::TransferToGasKey(_) => (),
``` [4](#0-3) 

`action_transfer_to_gas_key` only verifies that the target gas key exists on the receipt's receiver account; it does not check who the predecessor (sender) is:

```rust

**Attack path**

1. Victim account `V` has a gas key `K` with balance 0.
2. Attacker submits a transaction whose receipt targets `V` with `Action::TransferToGasKey { public_key: K, deposit: 1_000_000_000_000_000_000_000_001 }` (just above 1 NEAR).
3. The runtime executes `action_transfer_to_gas_key`, setting `K.balance = 1 NEAR + 1 yocto`.
4. Any subsequent `DeleteKey(K)` or `DeleteAccount` by `V` hits the `GasKeyBalanceTooHigh` guard and fails.
5. `V` can call `WithdrawFromGasKey` to drain the balance, but the attacker can immediately re-fund in the next block, repeating indefinitely at the cost of 1 NEAR + gas per round.

---

### Impact Explanation

- **`DeleteKey` blocked**: The owner cannot remove a gas key whose balance exceeds 1 NEAR. The key persists in state, consuming storage and remaining usable for gas-key transactions.
- **`DeleteAccount` blocked**: If the aggregate gas key balance on the account exceeds 1 NEAR, the account cannot be deleted. Funds are locked in the account indefinitely while the griefing continues.
- **Partial mitigation available to victim**: The victim can batch `[WithdrawFromGasKey, DeleteKey]` or `[WithdrawFromGasKey, DeleteAccount]` in a single receipt. Because actions within one receipt execute atomically and sequentially, the attacker cannot interleave a re-fund between the withdrawal and the deletion. However, a victim who does not know this workaround will be stuck in a loop of failed deletions.

---

### Likelihood Explanation

- Any unprivileged account can execute the attack with a single transaction.
- The attacker must spend slightly more than 1 NEAR per griefing round (the deposited amount is locked in the gas key, not burned, so the attacker loses it permanently only if the victim eventually succeeds in deleting the key, at which point the balance is burned).
- The attack targets any account that has at least one gas key, a feature enabled at protocol version 85.
- The victim's only reliable defense requires knowledge of the atomic-batch workaround; naive retry of `DeleteKey` alone will always fail.

---

### Recommendation

Add an actor-permission check to `TransferToGasKey` so that only the account owner (or an authorized actor) can fund a gas key:

```rust
// In check_actor_permissions:
Action::TransferToGasKey(_) => {
    if actor_id != account_id {
        return Err(ActionErrorKind::ActorNoPermission { … }.into());
    }
}
```

Alternatively, allow `action_delete_key` and `action_delete_account` to burn any amount of gas key balance unconditionally (removing the `MAX_BALANCE_TO_BURN` cap on deletion), or automatically withdraw excess balance before deletion rather than aborting. [6](#0-5) 

---

### Proof of Concept

```
// Attacker account: "attacker.near"
// Victim account:   "victim.near"
// Victim gas key:   <gas_key_pubkey>  (already exists, balance = 0)

// Step 1: Attacker sends TransferToGasKey to victim's gas key
Transaction {
    signer_id:   "attacker.near",
    receiver_id: "victim.near",
    actions: [
        TransferToGasKey {
            public_key: <gas_key_pubkey>,
            deposit:    1_000_000_000_000_000_000_000_001,  // 1 NEAR + 1 yocto
        }
    ]
}

// Step 2: Victim tries to delete the gas key — FAILS
Transaction {
    signer_id:   "victim.near",
    receiver_id: "victim.near",
    actions: [DeleteKey { public_key: <gas_key_pubkey> }]
}
// Error: GasKeyBalanceTooHigh { balance: 1_000_000_000_000_000_000_000_001 }

// Step 3: Victim withdraws — attacker immediately re-funds in the next block
// Victim is stuck unless they batch:
Transaction {
    signer_id:   "victim.near",
    receiver_id: "victim.near",
    actions: [
        WithdrawFromGasKey { public_key: <gas_key_pubkey>, amount: <full_balance> },
        DeleteKey          { public_key: <gas_key_pubkey> },
    ]
}
// This succeeds atomically, but requires the victim to know the workaround.
```

The broken invariant: `action_delete_key` and `action_delete_account` read the raw `GasKeyInfo.balance` field, which any unprivileged account can inflate via `TransferToGasKey`, exactly mirroring the external report's pattern of a state-transition guard reading a raw on-chain balance that any actor can manipulate.     config: &RuntimeConfig,
    state_update: &mut TrieUpdate,
    account: &mut Account,
    result: &mut ActionResult,

    public_key: &PublicKey,

        result.result = Err(ActionErrorKind::GasKeyBalanceTooHigh {
            account_id: account_id.clone(),
            public_key: Some(Box::new(public_key.clone())),
            balance: gas_key_info.balance,

        .into());
        return Ok(());

        remove_gas_key_nonce(state_update, account_id.clone(), public_key.clone(), i);
    }
    let nonce_key_len = gas_key_nonce_key_len(account_id, &public_key.into());

        &config.wasm_config.ext_costs,

        access_key,
        gas_key_info.num_nonces,
    )));
    Ok(())

pub(crate) fn action_transfer_to_gas_key(
    state_update: &mut TrieUpdate,
    result: &mut ActionResult,
    account_id: &AccountId,
    action: &TransferToGasKeyAction,
) -> Result<(), RuntimeError> {
    let Some(mut access_key) = get_access_key(state_update, account_id, &action.public_key)? else {
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };
    let Some(gas_key_info) = access_key.gas_key_info_mut() else {
        // Key exists but is not a gas key
        result.result = Err(ActionErrorKind::GasKeyDoesNotExist {
            account_id: account_id.clone(),
            public_key: Box::new(action.public_key.clone()),
        }
        .into());
        return Ok(());
    };

    gas_key_info.balance = gas_key_info.balance.checked_add(action.deposit).ok_or_else(|| {
        RuntimeError::StorageError(StorageError::StorageInconsistentState(
            "gas key balance integer overflow".to_string(),
        ))
    })?;
    set_access_key(state_update, account_id.clone(), action.public_key.clone(), &access_key);
    Ok(())
}

```rust
pub(crate) fn check_actor_permissions(
    action: &Action,
    account: &Option<Account>,
    actor_id: &AccountId,
    account_id: &AccountId,
) -> Result<(), ActionError> {
    match action {
        Action::DeployContract(_)
        | Action::Stake(_)
        | Action::AddKey(_)
        | Action::DeleteKey(_)
        | Action::DeployGlobalContract(_)
        | Action::UseGlobalContract(_)
        | Action::WithdrawFromGasKey(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
        }
        Action::DeleteAccount(_) => {
            if actor_id != account_id {
                return Err(ActionErrorKind::ActorNoPermission {
                    account_id: account_id.clone(),
                    actor_id: actor_id.clone(),
                }
                .into());
            }
            let account = account.as_ref().unwrap();
            if !account.locked().is_zero() {
                return Err(ActionErrorKind::DeleteAccountStaking {
                    account_id: account_id.clone(),
                }
                .into());
            }
        }
        Action::CreateAccount(_)
        | Action::FunctionCall(_)
        | Action::Transfer(_)
        | Action::TransferToGasKey(_) => (),
        Action::Delegate(_) | Action::DelegateV2(_) => (),
        Action::DeterministicStateInit(_) => (),
    };
    Ok(())
}
