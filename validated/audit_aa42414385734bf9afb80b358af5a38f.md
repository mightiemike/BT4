## Finding

Note: The chunk-executor's `commit()`/`update_ledger()` path itself *does* check state-checkpoint hashes via `DoStateCheckpoint::run().maybe_known_state_checkpoints(...)` [1](#0-0) , so the ledger-commit path is not affected. The gap is isolated to the separate `ensure_match_transaction_info` comparator that is explicitly used by replay/verification tooling.

### Title
`TransactionOutput::ensure_match_transaction_info` silently skips authenticated state-checkpoint hash verification during replay-verify - (File: `types/src/transaction/mod.rs`)

### Summary
`ensure_match_transaction_info` is the authenticated comparator used by chunk-executor's `verify_execution` (invoked from `db-tool`'s `replay_on_archive` and the debugger/CLI replay paths) to confirm that locally re-executed transaction output matches an already-committed, ledger-info-anchored `TransactionInfo`. The function checks status, gas, write-set hash, and event-root hash, but explicitly and knowingly omits comparison of `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` against the authenticated `TransactionInfo`.

### Finding Description
`ensure_match_transaction_info` computes and compares `write_set_hash` and `event_root_hash` against `txn_info.state_change_hash()`/`txn_info.event_root_hash()`, but the function body contains an explicit acknowledgement that it does not validate the checkpoint hashes carried in the same `TransactionInfo`: [2](#0-1) 

Specifically, the trailing comment states the comparator "ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`), so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution," and explicitly defers fixing this until `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled [3](#0-2) .

This function is called from `execution/executor/src/chunk_executor/mod.rs::verify_execution`, which is the code path that re-executes historical transactions during replay-verification and compares the result against `transaction_infos` read from the archive/ledger: [4](#0-3) 

Because `TransactionInfo` carries `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` as the authenticated binding between a transaction's execution and the resulting Jellyfish-Merkle/position state roots (as seen used elsewhere, e.g. in chunk-executor's own commit-time checks) [5](#0-4) , skipping these fields in the verify-execution comparator means the replay-verify tool's "match" result is not actually a full state-integrity check — it validates write-set and event content but not the derived state root.

### Impact Explanation
The broken invariant is: "replayed/re-executed local computation state root == authenticated on-chain state root," which is exactly the "Hard-fork-only divergence during commit, replay, restore, or proof verification" and "Authenticated API or state-view output bound to the wrong version, object, or proof context" categories in the Proof And Storage Pivots. Any bug elsewhere in state-checkpoint computation (JMT construction, hot-state root, or the new position-state root) that produces a wrong root would not be caught by `db-tool replay-verify` or `aptos-debugger` replay checks, because those tools rely on `ensure_match_transaction_info` as their pass/fail oracle. This degrades the primary safety net used to detect chain-state divergence (e.g., after upgrades, VM changes, or storage schema migrations) — exactly the audit mechanism operators depend on before trusting archive-restored or re-executed state. This is a real, root-caused correctness gap in the comparator itself (not a restatement of the external bug), affecting the authenticated verification of durable ledger state.

### Likelihood Explanation
This is not attacker-triggered in the sense of an exploit against a live validator; it is a systemic verification gap that is always present whenever `verify_execution`/`ensure_match_transaction_info` is used (every invocation of `db-tool replay-verify`, `aptos-debugger`, and CLI's replay-and-compare commands). Any latent state-root computation bug — including ones introduced in this very release around `hot_state_checkpoint_hash` and `position_state_checkpoint_hash` — would go undetected by this tooling. Likelihood of the *underlying divergence being missed* is high whenever such bugs exist, since the check is unconditionally skipped rather than conditionally validated.

### Recommendation
Extend `ensure_match_transaction_info` to compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` whenever the caller can supply/derive the corresponding locally-computed values (i.e., wire `LedgerUpdateOutput`/`StateCheckpointOutput` into the comparator context in `chunk_executor::verify_execution`, mirroring the checks already performed at commit time in `update_ledger`), rather than leaving this a known/deferred gap in a currently-shipped authenticated comparator.

### Proof of Concept
1. Introduce (or trigger) any bug that changes the computed Jellyfish-Merkle state-checkpoint root (or the new hot-state/position-state root) without changing the write-set or events for a given transaction (e.g., a divergent state-view class, or the very executor pipeline that constructs `StateCheckpointOutput`).
2. Run `db-tool replay_on_archive` (or `aptos-debugger` "execute-past-transactions" style replay) over the affected version range with `verify_execution_mode.should_verify() == true`, hitting `execution/executor/src/chunk_executor/mod.rs::verify_execution` [6](#0-5) .
3. Observe that `ensure_match_transaction_info` returns `Ok(())` despite the state-checkpoint root diverging from the authenticated `TransactionInfo`, because the function never reads or compares `txn_info.state_checkpoint_hash()`/`hot_state_checkpoint_hash()`/`position_state_checkpoint_hash()` [2](#0-1) .
4. The replay-verify tool reports success even though the local ledger state root differs from the authenticated one — a false-positive integrity confirmation.

    fn verify_execution(
        &self,
        transactions: &[Transaction],
        persisted_aux_info: &[PersistedAuxiliaryInfo],
        transaction_infos: &[TransactionInfo],
        write_sets: &[WriteSet],
        event_vecs: &[Vec<ContractEvent>],
        begin_version: Version,
        end_version: Version,
        verify_execution_mode: &VerifyExecutionMode,
    ) -> Result<Version> {
        // Execute transactions.
        let parent_state = self.commit_queue.lock().latest_state().clone();
        let state_view = self.state_view(parent_state.latest())?;
        let txns = transactions
            .iter()
            .take((end_version - begin_version) as usize)
            .cloned()
            .map(|t| t.into())
            .collect::<Vec<SignatureVerifiedTransaction>>();

        let auxiliary_info = persisted_aux_info
            .iter()
            .take((end_version - begin_version) as usize)
            .map(|persisted_aux_info| AuxiliaryInfo::new(*persisted_aux_info, None))
            .collect::<Vec<_>>();
        let onchain_config = chunk_onchain_config(&state_view)?;
        let execution_output = DoGetExecutionOutput::by_transaction_execution::<V>(
            &V::new(),
            txns.into(),
            auxiliary_info,
            &parent_state,
            state_view,
            onchain_config,
            TransactionSliceMetadata::chunk(begin_version, end_version),
        )?;
        // not `zip_eq`, deliberately
        for (version, txn_out, txn_info, write_set, events) in multizip((
            begin_version..end_version,
            &execution_output.to_commit.transaction_outputs,
            transaction_infos.iter(),
            write_sets.iter(),
            event_vecs.iter(),
        )) {
            if let Err(err) = txn_out.ensure_match_transaction_info(
                version,
                txn_info,
                Some(write_set),
                Some(events),
            ) {
                return if verify_execution_mode.is_lazy_quit() {
                    error!("(Not quitting right away.) {}", err);
                    verify_execution_mode.mark_seen_error();
                    Ok(version + 1)
                } else {
                    Err(err)
                };
            }
        }
        Ok(end_version)
    }

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
