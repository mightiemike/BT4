### Title
JWT Replay Cache TTL (JWTReplayPeriodMs) Is Not Coupled to JWT Expiry, Allowing Replay of a Still-Valid Signed Token After Cache Eviction - (File: core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler.go)

### Summary
`WorkflowMetadataHandler.Authorize` prevents JWT replay purely by checking presence of the `jti` in an in-memory `jwtReplayCache`, whose entries are evicted by a periodic ticker using an independently configured `JWTReplayPeriodMs`. Nothing in the code ties this cache retention window to the JWT's own `exp`/`iat` validity window (which can be up to `maxJWTExpiryDuration` = 5 minutes, enforced in `core/utils/jwt.go`). If `JWTReplayPeriodMs` is configured shorter than the token's actual lifetime, a previously-used but still cryptographically-valid JWT can be replayed successfully after cache eviction but before its `exp`.

### Finding Description
`Authorize` (workflow_metadata_handler.go:75-103) calls `utils.VerifyRequestJWT` (core/utils/jwt.go:231-304), which validates signature, digest, `iat`, and `exp` (via `jwt.ParseWithClaims`'s built-in expiry check plus an explicit `maxExpiryDuration` bound, default 5 minutes, at lines 284-298). Separately, it checks `h.jwtCache.isReplay(claims.ID)` (line 82) and, on success, calls `h.jwtCache.recordUsage(claims.ID)` (line 100).

The replay cache is a simple map `jti -> timestamp` (workflow_metadata_handler.go:31-36, 341-354). Eviction is driven by a ticker in `Start()` running every `h.jwtCache.cleanupPeriod` (`= JWTReplayPeriodMs`), which calls `cleanupOldEntries(now.Add(-h.jwtCache.cleanupPeriod))` (workflow_metadata_handler.go:242-248, 356-368) — i.e., an entry is removed once it's older than one `cleanupPeriod`.

Critically, `JWTReplayPeriodMs` (http_handler.go:104-105) is a completely separate, independently-configured value from the JWT's own `exp` claim lifetime (which is set by the JWT issuer, bounded only by `maxJWTExpiryDuration`/`WithMaxExpiryDuration`, default 5 minutes). There is no validation anywhere enforcing `JWTReplayPeriodMs >= max JWT lifetime`. If an operator (or default config) sets `JWTReplayPeriodMs` to a value shorter than the effective token lifetime, the `jti` is purged from the replay cache while the token is still within its `exp` window. A resubmission of the exact same JWT then:
1. Passes `VerifyRequestJWT` (signature, digest, and `exp` are all still valid).
2. Passes `isReplay` (false, since the entry was evicted).
3. Successfully re-authorizes and triggers a second unauthorized workflow execution.

### Impact Explanation
This breaks the stated replay-protection invariant: JWT replay protection is only as strong as the shorter of `JWTReplayPeriodMs` and the token's `exp`, not permanently bound to the token's validity lifetime as intended. An attacker holding one previously-used, still-not-expired JWT can trigger a second unauthorized workflow execution via the HTTP Trigger path (`WorkflowMetadataHandler.Authorize`), consuming DON/workflow resources and executing the workflow twice with attacker-controlled timing — a workflow-execution integrity/replay issue in the gateway's trigger authorization path.

### Likelihood Explanation
Exploitability depends entirely on operator/gateway configuration: it requires `JWTReplayPeriodMs` to be set (or defaulted) to a value smaller than the actual JWT lifetime (`exp - iat`, up to 5 minutes by default). This is plausible because `JWTReplayPeriodMs` and JWT expiry are configured completely independently (different files/components — the DON/JWT issuer decides `exp`; the gateway operator decides `JWTReplayPeriodMs`) with no cross-validation. No exact default value for `JWTReplayPeriodMs` could be confirmed in this pass, so it is uncertain whether the out-of-the-box default configuration is affected or only certain custom configurations — this should be verified against `defaultJWTReplayPeriodMs` in `http_handler.go` before treating the default deployment as vulnerable.

### Recommendation
- Enforce at config-load/`WithDefaults` time that `JWTReplayPeriodMs >= maxJWTExpiryDuration` (or the actual configured `WithMaxExpiryDuration`), rejecting/clamping configs where the replay cache TTL is shorter than possible JWT lifetime.
- Alternatively, store each JWT's own `exp` in the replay cache entry and evict only after `exp` has passed (rather than a fixed, independently-configured `cleanupPeriod`), guaranteeing replay protection lasts exactly as long as token validity.

### Proof of Concept
Unit test in `core/services/gateway/handlers/capabilities/v2/workflow_metadata_handler_test.go`:
1. Construct a `ServiceConfig` with `JWTReplayPeriodMs` set shorter than the JWT's lifetime (e.g., `JWTReplayPeriodMs: 50`, and issue the JWT with `utils.WithExpiry(500*time.Millisecond)` so `exp` is still 500ms out).
2. Call `handler.Authorize(workflowID, tokenString, req)` — expect success and `jwtCache.recordUsage` populated.
3. Directly call `handler.jwtCache.cleanupOldEntries(time.Now().Add(-handler.jwtCache.cleanupPeriod))` (simulating the ticker firing) after >50ms so the entry is evicted, while still before the JWT's 500ms `exp`.
4. Call `handler.Authorize(workflowID, tokenString, req)` again with the same token.
5. Assert this second call **does not** return `"JWT token has already been used"` and instead succeeds — demonstrating the replay succeeded despite JWT still being unexpired, confirming the gap between cache eviction and JWT validity window. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

	claims, signer, err := utils.VerifyRequestJWT(token, *req)
	if err != nil {
		h.lggr.Errorw("Failed to verify JWT", "error", err)
		return nil, err
	}

	if h.jwtCache.isReplay(claims.ID) {
		h.lggr.Warnw("JWT token has already been used", "workflowID", workflowID, "signer", signer.Hex(), "jti", claims.ID)
		return nil, errors.New("JWT token has already been used. Please generate a new one with new id (jti)")
	}

	keys, exists := h.authorizedKeys[workflowID]
	if !exists {
		h.lggr.Errorw("Workflow ID not found in authorized keys", "workflowID", workflowID)
		return nil, fmt.Errorf("workflow ID %s not found", workflowID)
	}
	key := gateway.AuthorizedKey{
		KeyType:   gateway.KeyTypeECDSAEVM,
		PublicKey: strings.ToLower(signer.Hex()),
	}
	if _, exists = keys[key]; !exists {
		h.lggr.Errorw("Signer not found in authorized keys", "signer", signer.Hex())
		return nil, fmt.Errorf("signer '%s' is not authorized for workflow '%s'. Ensure that the signer is registered in the workflow definition", signer.Hex(), workflowID)
	}
	h.jwtCache.recordUsage(claims.ID)

	return &key, nil
}

func (cache *jwtReplayCache) isReplay(jti string) bool {
	cache.mu.RLock()
	defer cache.mu.RUnlock()

	_, exists := cache.cache[jti]
	return exists
}

func (cache *jwtReplayCache) recordUsage(jti string) {
	cache.mu.Lock()
	defer cache.mu.Unlock()

	cache.cache[jti] = time.Now()
}

// cleanupOldEntries removes expired entries from the cache
func (cache *jwtReplayCache) cleanupOldEntries(cutoff time.Time) int {
	cache.mu.Lock()
	defer cache.mu.Unlock()
	var expiredCount int
	for jti, createdAt := range cache.cache {
		if createdAt.Before(cutoff) {
			delete(cache.cache, jti)
			expiredCount++
		}
	}
	return expiredCount
}
