### Title
Cycle-0 witness rewards are permanently unclaimable because vote snapshots are only recorded starting at cycle 1 - (File: chainbase/src/main/java/org/tron/core/service/MortgageService.java, chainbase/src/main/java/org/tron/core/store/DelegationStore.java, consensus/src/main/java/org/tron/consensus/dpos/MaintenanceManager.java)

### Summary
The reported bug freezes rewards accrued for the very first accounting period of `RewardsDistributor` because no snapshot of eligible holders exists at that point in time, so no one can later prove a claim to that period's rewards. The same structural flaw exists in java-tron's witness voting-reward accounting (`MortgageService`/`DelegationStore`): block and transaction-fee rewards are accumulated per witness per "cycle" from the moment the chain starts, but the per-cycle vote-count snapshot used to compute each voter's share of that reward is only ever written starting at cycle 1. Rewards attributed to cycle 0 can never be matched to a vote snapshot and are permanently unclaimable.

### Finding Description
Every block, `MortgageService.payBlockReward`/`payTransactionFeeReward` credits the *current* cycle's reward pool for the block-producing witness via `delegationStore.addReward(cycle, witnessAddress, value)`: [1](#0-0) 

`DelegationStore.addReward` simply accumulates into a `cycle-address-reward` key with no dependency on whether a vote snapshot for that cycle exists yet: [2](#0-1) 

When a voter later withdraws/queries rewards, `computeReward` requires a valid, non-zero, non-`REMARK` vote-count snapshot for the exact cycle being paid out: [3](#0-2) 

`DelegationStore.getWitnessVote` returns the sentinel `REMARK` (-1) when no snapshot was ever stored for that cycle: [4](#0-3) 

The only place that writes `setWitnessVote(cycle, ...)` is `MaintenanceManager.doMaintenance()`, and it always writes for `nextCycle = getCurrentCycleNumber() + 1`, never for the currently-running cycle: [5](#0-4) 

Since `dynamicPropertiesStore`'s current-cycle number defaults to 0 at genesis, and the very first `doMaintenance()` run only seeds `setWitnessVote(1, ...)`, there is no vote snapshot ever recorded for cycle 0 — exactly mirroring the reported condition where `RewardsDistributor` accrues rewards for the epoch that ends *before* any veALCX holder snapshot exists. Any block/transaction-fee reward accumulated into `delegationStore` under cycle 0 (`getReward(0, srAddress)`) is unreachable by `computeReward`, because the `if (totalVote == DelegationStore.REMARK || totalVote == 0) continue;` guard always skips it — permanently orphaning that portion of the reward pool, with no code path that redistributes or refunds it elsewhere.

### Impact Explanation
This results in a small but permanent loss/freezing of ALCX-equivalent value — here, TRX/vote-reward allowance owed to genesis Super Representatives (and, by extension, their voters) for cycle 0 — that can never be withdrawn through `withdrawReward`/`queryReward`. This falls under "resource and reward accounting" corruption: value is computed and stored but structurally unreachable, a permanent freezing of rewards analogous to the original finding.

### Likelihood Explanation
This triggers deterministically on every network using this reward architecture (the "new delegation"/vote-reward mechanism gated by `allowChangeDelegation`), with no attacker action required — it is a systemic accounting gap that manifests automatically during the first cycle after `allowChangeDelegation` is enabled (mainnet activation or any new/private chain bootstrapped with this feature). It requires no privileged access, matching the "resource and reward accounting" analog class permitted by the rules.

### Recommendation
When enabling the new reward/delegation algorithm (or at genesis if `allowChangeDelegation` starts enabled), explicitly seed a witness-vote snapshot for cycle 0 (e.g., have `MaintenanceManager`/`Manager.initGenesis` call `delegationStore.setWitnessVote(0, witness, initialVoteCount)` for all genesis witnesses) so that `computeReward` can resolve cycle-0 rewards. Alternatively, roll any un-attributable cycle-0 reward forward into cycle 1's pool instead of silently discarding it in `computeReward`/`accumulateWitnessVi`.

### Proof of Concept
Conceptual reproduction based on existing code paths (no PoC file exists in the indexed sources, but the logic is directly traceable):
1. Start a fresh chain with `allowChangeDelegation` enabled from genesis, current cycle = 0 (default in `DynamicPropertiesStore`).
2. Let a genesis witness produce blocks during cycle 0; `MortgageService.payBlockReward`/`payTransactionFeeReward` calls `delegationStore.addReward(0, witnessAddress, value)` repeatedly — confirmable via `DelegationStore.getReward(0, witnessAddress) > 0`.
3. Wait for the first `MaintenanceManager.doMaintenance()` to run; it advances `currentCycleNumber` to 1 and calls `setWitnessVote(1, witness, voteCount)` — cycle 0 never receives a `setWitnessVote` entry.
4. Have a voter who voted for that witness during cycle 0 call `MortgageService.queryReward`/`withdrawReward`. Inside `computeReward(0, 1, accountCapsule)`, `delegationStore.getWitnessVote(0, srAddress)` returns `REMARK`, so the `continue` branch fires and that witness's cycle-0 reward contributes 0 to the payout — even though `delegationStore.getReward(0, srAddress)` is non-zero and no future code path ever consumes it.

```java
  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }
```

```java
    BytesCapsule bytesCapsule = get(key);
    if (bytesCapsule == null) {
      put(key, new BytesCapsule(ByteArray.fromLong(value)));

      put(key, new BytesCapsule(ByteArray
          .fromLong(ByteArray.toLong(bytesCapsule.getData()) + value)));
    }
  }

      return 0L;
    } else {
      return ByteArray.toLong(bytesCapsule.getData());
    }
  }
```
