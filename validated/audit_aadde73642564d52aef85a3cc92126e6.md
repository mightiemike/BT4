### Title
`MsgMigrateUEA` bypasses gas-fee accounting that the documented-as-canonical `MsgExecutePayload` path enforces - (File: `x/uexecutor/keeper/msg_migrate_uea.go`)

### Summary
This is a genuine analog of the FeeCollector issue: a "legacy"/parallel EVM-execution entry point that is not integrated with the fee-accounting mechanism that the primary, documented path enforces, and it is still fully reachable by any unprivileged user.

### Finding Description
`x/uexecutor/README.md:207` explicitly states: *"UEA migration is now part of payload execution... There used to be a separate `MsgMigrateUEA` message; that path has been removed."* This is inaccurate — `MsgMigrateUEA` is still a live, registered message (`x/uexecutor/keeper/msg_server.go:57-70`, wired to `types.MsgServer`), it is still in the gasless allowlist (`app/txpolicy/gasless.go:18`), and its handler `Keeper.MigrateUEA` (`x/uexecutor/keeper/msg_migrate_uea.go:15-84`) drives a real `DerivedEVMCall` (`CallUEAMigrateUEA`, `x/uexecutor/keeper/evm.go:196-227`) exactly like `ExecutePayload` does.

The critical divergence: `ExecutePayload`'s handler (`x/uexecutor/keeper/msg_execute_payload.go:87-97`) always calls `k.DeductGasFeesFromReceipt(...)` after the EVM call and fails the whole Cosmos tx if fee deduction fails (`x/uexecutor/keeper/execute_payload.go:39-56` for the V2/inbound variant also wraps the call + fee deduction in a `CacheContext` so a failed deduction reverts the EVM state — this is called out in the README as closing "the free-execution gap when the UEA has no native UPC to cover gas").

`Keeper.MigrateUEA` has **no such fee-deduction step at all**. It calls `CallUEAMigrateUEA` (`x/uexecutor/keeper/msg_migrate_uea.go:71-74`), logs the result, and returns — `DeductGasFeesFromReceipt` is never invoked on this path. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

This mirrors the FeeCollector pattern precisely: the protocol has one "well-integrated," fully-checked entrypoint for a class of EVM-derived execution (`MsgExecutePayload`, whose accounting model is carefully documented with an explicit "free-execution gap" closure), and a second, parallel entrypoint (`MsgMigrateUEA`) that reaches the same class of privileged, module-sender-derived EVM execution (`DerivedEVMCall`/`CallUEAMigrateUEA`, gasless message) but was never updated to include the same fee/gas accounting the primary path has. The docs even assert the parallel path "has been removed," indicating the omission is an integration oversight rather than an intended design difference — exactly the "complicated and non-transparent" mismatch the FeeCollector report criticized.

### Impact Explanation
Because `MsgMigrateUEA` is in the gasless allowlist, the Cosmos-layer tx costs the caller nothing, and no gas is billed from the target UEA/UniversalAccount either (since `DeductGasFeesFromReceipt` is never called), the actual EVM gas consumed by the `migrateUEA` call on the UEA contract is paid entirely by the `uexecutor` module/protocol with no cost recovery from the UEA owner — a free-execution / fee-accounting-bypass vector. This does not directly authorize unauthorized migration (the UEA contract's own signature check, per the README's `MsgExecutePayload` write-up, still gates who can actually perform the migration), but it does break the intended "gas is billed to the UEA" invariant that the rest of the protocol enforces for identical classes of user-delivered EVM calls, allowing repeated free EVM execution (griefing/resource-drain against the protocol) any time a valid signed migration payload is available or replay/format quirks allow submission.

### Likelihood Explanation
High reachability: `MsgMigrateUEA` requires no special authority, is gasless, and any address can submit it as long as it carries a validly-signed `MigrationPayload` and `signature` for some deployed UEA (or malformed/failing attempts still trigger EVM calls and logging before final revert on signature check inside the contract). This is a pure production code path reachable via ordinary transaction submission — it does not depend on any privileged actor.

### Recommendation
- Either fully remove `MsgMigrateUEA` (proto message, msg-server handler, `keeper.MigrateUEA`, `CallUEAMigrateUEA`, and its gasless-allowlist entry) to match the documented "removed" state, or
- If it must remain live, integrate the same `DeductGasFeesFromReceipt` + `CacheContext` commit/revert pattern used by `ExecutePayloadV2`/`ExecutePayload` so gas is billed to the UEA and a failed deduction rolls back the EVM state.
- Update `x/uexecutor/README.md` to accurately reflect whichever state is chosen, since the current documentation actively asserts a false invariant ("that path has been removed").

### Proof of Concept
1. An attacker (or any user) constructs a `MsgMigrateUEA` for a deployed UEA with a validly-signed `MigrationPayload`/`signature` (or even an unsigned/garbage one, since `CallUEAMigrateUEA`'s EVM call and any partial gas consumption happen before/around the contract-level signature check).
2. Submit the message; because `/uexecutor.v1.MsgMigrateUEA` is in `GaslessMsgTypes` (`app/txpolicy/gasless.go:18`), `DeductFeeDecorator` skips Cosmos fee collection (`app/ante/fee.go:60-64`) and `MinGasPriceDecorator` skips the min-fee check.
3. `Keeper.MigrateUEA` executes `CallUEAMigrateUEA` via `DerivedEVMCall` (real EVM gas consumed, `x/uexecutor/keeper/evm.go:212-227`), and returns without ever calling `DeductGasFeesFromReceipt`.
4. Compare against the equivalent `MsgExecutePayload` flow, where `x/uexecutor/keeper/msg_execute_payload.go:91` unconditionally attempts fee deduction and fails the tx on insufficient balance — demonstrating the parallel path is missing the accounting the primary path enforces. [5](#0-4)
