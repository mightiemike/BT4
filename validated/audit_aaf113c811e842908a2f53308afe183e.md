### Title
Malformed base64 `host` query parameter causes uncaught exception in `sanitizeHost`/`decodeHost`, bypassing the login-redirect fail-safe - ([File: packages/apps/shopify-app-remix/src/server/authenticate/admin/helpers/validate-shop-and-host-params.ts])

### Summary
`validateShopAndHostParams` calls `api.utils.sanitizeHost(url.searchParams.get('host')!)` with no try/catch. Inside `sanitizeHost` (packages/apps/shopify-api/lib/utils/shop-validator.ts), any string matching the loose base64 character-set regex is passed unconditionally to `decodeHost`, which calls `atob()`. A syntactically-base64-charset-but-invalid-length/padding string causes `atob()` to throw, and that exception is not caught anywhere in the call chain, producing an unhandled error instead of the intended redirect to the login path.

### Finding Description
In `sanitizeHost` [1](#0-0) , the only gate before calling `decodeHost` is `base64regex.test(host)` with the pattern `/^[0-9a-zA-Z+/]+={0,2}$/`. This regex validates the character set only — it does **not** enforce that the string length is a multiple of 4 or that padding is well-formed. `decodeHost` simply calls `atob(host)` [2](#0-1) . Malformed-length base64 input (e.g. a single alphanumeric character, or an otherwise charset-valid string with bad padding) causes `atob()` to throw synchronously.

This call is made unconditionally — the `throwOnInvalid` flag only governs the `InvalidHostError` thrown at the bottom of the function when the final regex fails [3](#0-2) ; it does not protect the `atob()` call earlier in the function. `validateShopAndHostParams` invokes `sanitizeHost` with no try/catch around it [4](#0-3) , so the thrown error propagates past the intended `redirectToLoginPath` fallback used for the `null` case [5](#0-4) , resulting in an unhandled exception rather than a controlled redirect.

Note: the `shop` parameter path in this same function does **not** have this issue — `sanitizeShop` only ever calls `RegExp.test()` on the raw string and never throws unless `throwOnInvalid` is explicitly passed as `true` (which this caller does not do) [6](#0-5) . There is also no double/inconsistent `decodeURIComponent` call anywhere in this path — `URLSearchParams.get` performs a single, standard percent-decoding pass, so the specific "decodeURIComponent inconsistency" mechanism described for `shop` does not exist in this code.

### Impact Explanation
A crafted `host` query parameter can crash the `authenticate.admin` entry point with an unhandled exception instead of the intended, controlled redirect to the login page. This is a denial-of-service condition in an authentication handler, matching Shopify's "DoS in authentication flow" impact class. It does not lead to session forgery, token theft, or cross-tenant access — it is limited to crashing/erroring the request.

### Likelihood Explanation
- Preconditions: default embedded app config (`config.isEmbeddedApp === true`), which is the default embedded setup.
- Attacker capability: anonymous, unauthenticated HTTP client; no secrets or privileges required.
- Feasibility: trivially reproducible by sending a single crafted `host` value (e.g., a 1–3 character alphanumeric string) as a query parameter to any route wrapped by `authenticate.admin`.
- Repeatability: fully deterministic and repeatable on every request.

### Recommendation
Wrap the `atob()` call in `decodeHost` (or in `sanitizeHost`) in a try/catch and treat decode failures the same as a regex mismatch (`sanitizedHost = null`), or strengthen `base64regex` to also validate length (`length % 4 === 0`) before attempting decode. Additionally, consider wrapping the calls in `validateShopAndHostParams` in a try/catch that maps any unexpected error to `redirectToLoginPath`, ensuring the entry point always fails closed via a controlled redirect.

### Proof of Concept
```ts
// packages/apps/shopify-api/lib/utils/__tests__/shop-validator.test.ts
test('sanitizeHost throws unhandled error on malformed base64 length', () => {
  const shopify = shopifyApi(testConfig());
  // Single char passes /^[0-9a-zA-Z+/]+={0,2}$/ but is invalid base64 length
  expect(() => shopify.utils.sanitizeHost('A')).toThrow();
  // Not an InvalidHostError -> not the expected/controlled error type
});
```
Equivalent HTTP PoC:
```
GET /any-authenticated-route?shop=someshop.myshopify.com&host=A
```
Expected (per invariant): a `302` redirect to `config.auth.loginPath`.
Actual: an uncaught exception thrown from `atob()` inside `sanitizeHost`, since it is invoked before any `throwOnInvalid`/redirect handling can catch it.
