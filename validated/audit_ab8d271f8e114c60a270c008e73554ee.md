## Analysis: LP/AMM valuation bug-class in Push Chain

The Frax report's root cause — using an instantaneous, manipulable pool state (Uniswap V2 `getReserves`, V3 spot-tick composition) as the sole basis for a financial calculation with no oracle/TWAP protection — has a direct analog in the gas-abstraction auto-swap path.

### Title
Slippage protection for protocol-executed PRC20→WPC auto-swap is derived from an unprotected, same-block spot-price quote, enabling sandwich extraction of user deposit value - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`)

### Summary
When an inbound deposit selects the `GAS` or `GAS_AND_PAYLOAD` route, `ExecuteInboundGas` (and `gasAndPayloadDepositAutoSwap`) fetches a swap quote from the Uniswap V3 `QuoterV2.quoteExactInputSingle` and derives `minPCOut` as a flat 5% discount off that single quote, then immediately submits `depositPRC20WithAutoSwap` using that bound. `quoteExactInputSingle` reports the amount out based on the pool's *current* tick/sqrtPriceX96 state — the same class of manipulable, unprotected spot valuation flagged in the external report for Uniswap V2 `getReserves()` and V3 NFT range assumptions, with no TWAP or external oracle check. ### Finding Description
`GetSwapQuote` calls the Uniswap V3 `QuoterV2` contract to obtain `amountOut` for swapping the inbound PRC20 token to WPC using the pool's live price at call time: [2](#0-1) 

The result is used directly to compute `minPCOut = quote * 95 / 100`, a fixed 5% slippage band anchored to that single spot observation, and the swap is executed atomically right after in the same keeper call: [4](#0-3) 

This is the on-chain-execution equivalent of the report's core defect: deriving a financial guarantee (minimum acceptable output / implied collateral value) from an AMM's instantaneous state instead of a manipulation-resistant price source. Any unprivileged actor who can trade against the WPC/PRC20 Uniswap V3 pool on Push Chain (a normal, permissionless AMM pool, not a privileged actor) can push the pool price against the pending auto-swap immediately before it executes, causing `quoteExactInputSingle` to return an already-depressed `amountOut`. Because `minPCOut` is only 5% below that manipulated (not fair) quote, the protocol-executed swap still clears at the attacker-manipulated price, and the attacker reverses their trade afterward to capture the arbitrage — a textbook sandwich attack. Because this call path fires deterministically whenever `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` runs for a finalized inbound (a normal user deposit, no validator or admin privilege involved), and Push Chain's mempool/block timing is externally observable, the attacker does not need any special access — only the ability to submit ordinary swap transactions against the pool in the surrounding block(s).

### Impact Explanation
Successful exploitation drains value from the PRC20 the user deposited during conversion to WPC (the gas token), i.e. it corrupts the amount of native/PRC20 asset value actually credited to the user's UEA relative to what should have been received at a fair price. This falls under "corruption of PRC20 or native asset accounting, gas fee accounting... or canonical UniversalTx state" and constitutes value drained from a user/protocol-controlled deposit through a default, unprivileged transaction submission path (ordinary trading against the pool plus ordinary bridging), matching the allowed impact scope.

### Likelihood Explanation
Likelihood is moderate-to-high: it requires no validator collusion, no relayer/TSS compromise, and no special contract access — only capital to move the WPC/PRC20 pool price and knowledge of when auto-swap deposits execute (observable from chain state/mempool). The fixed 5% band is wide enough to allow meaningful price impact before the trade reverts economically for the protocol/user rather than the attacker.

### Recommendation
Do not derive `minPCOut` solely from a single, same-block `quoteExactInputSingle` call. Use a time-weighted average price (TWAP) from the pool (or an external oracle) to compute the expected output, and/or bound the maximum acceptable single-block price deviation between the TWAP-implied price and the spot quote before allowing the auto-swap to proceed, consistent with the original report's long-term recommendation to price AMM-derived values off "fair value" oracles rather than raw spot/reserve data.

### Proof of Concept
1. Attacker identifies a pending inbound deposit that will route through `GAS`/`GAS_AND_PAYLOAD` (visible once source-chain event/vote activity begins) targeting a low-liquidity PRC20/WPC Uniswap V3 pool.
2. Immediately before/around the block in which `ExecuteInboundGas` executes, attacker submits a large swap against the same pool to depress the PRC20→WPC price.
3. `GetSwapQuote` returns a depressed `amountOut`; `minPCOut` (95% of that) is still satisfied by `depositPRC20WithAutoSwap` executing at the manipulated price.
4. Attacker reverses their trade in a following transaction, capturing the price impact as profit, while the bridging user's deposit is converted to WPC at a below-fair rate — permanently losing value relative to fair market pricing.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
