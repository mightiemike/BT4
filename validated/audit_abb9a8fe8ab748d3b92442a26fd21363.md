The reported issue concerns Solidity smart contract loops iterating over unbounded external arrays (gas exhaustion/DOS in the Allo/Registry contract), which has no meaningful analog in protobuf-go. All the loops found in protobuf-go's decoders (e.g., `unmarshalPointerEager` at [1](#0-0) , `unmarshalMessageSlow` at [2](#0-1) , and the text/JSON decoders at [3](#0-2)  and [4](#0-3) ) are bounded by the length of the input byte buffer being consumed (`for len(b) > 0`), which strictly shrinks on each iteration as bytes are consumed. This is the standard, expected decode loop pattern and is not an "unbounded loop" in the audit-report sense of iterating over an attacker-controlled unbounded external list independent of consumed input size.

Per the rules, generic "unbounded resources" concerns are explicitly excluded as an acceptable analog class, and no reachable unprivileged request path in protobuf-go exhibits the same broken invariant (an external-call-driven loop over arbitrary-length attacker data without any bound tied to the consumed buffer) as described in the report.
