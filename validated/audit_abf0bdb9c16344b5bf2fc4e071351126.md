### Title
Starknet OS `execute_replace_class` omits declared-class validation present in blockifier, causing OS/blockifier state divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The `replace_class` syscall lets any contract change its own class hash. The Rust blockifier implementation validates that the target class hash is a declared, Cairo1 class before mutating state, but the Cairo Starknet OS implementation — used to re-execute transactions and build the committed state — performs no such validation, unconditionally writing the caller-supplied class hash into `contract_state_changes`.

### Finding Description
Any contract can invoke `replace_class_syscall(class_hash)` with an arbitrary, attacker-chosen `class_hash`, exactly analogous to how the Lemur `parent` field is attacker-supplied and used without validating a required precondition (a declared/permitted backing resource) before a privileged state mutation.

In the blockifier (the execution engine used to build blocks), `replace_class` explicitly checks that the class exists and is Cairo1 before writing: [1](#0-0) 

This is invoked from the syscall handler for both the current and native execution paths: [2](#0-1) [3](#0-2) 

The deprecated (Cairo0) syscall path in blockifier also enforces this, with an explicit comment confirming the intent: [4](#0-3) 

A dedicated blockifier test asserts the negative case is rejected ("is not declared"): [5](#0-4) 

In contrast, the Starknet OS's Cairo implementation of the same syscall — which re-executes transactions to build the block's committed state and proof — performs the state mutation directly with no declared-class check at all. The current (non-deprecated) syscall path even carries an explicit TODO acknowledging the missing check: [6](#0-5) 

The deprecated (Cairo0) OS syscall path has the identical gap, with no validation and no TODO comment either: [7](#0-6) 

The root cause is structurally identical to the Lemur bug: an attacker-supplied reference (`parent` authority id / `class_hash`) is passed straight into a privileged state-mutating operation (signing with the parent's private key / rewriting a contract's class pointer in the committed state tree) without validating a required precondition (permission on the parent / existence of a declared class) that the "trusted" implementation (Lemur's other authorization layers / blockifier) otherwise enforces.

### Impact Explanation
Since the Starknet OS is the component that re-executes transactions to compute the final committed state (Patricia tree roots) and the block hash/output that gets proven and posted to L1, any divergence between blockifier's execution result and the OS's execution result for the same transaction is a correctness-breaking bug. Concretely: for a transaction that calls `replace_class_syscall` with an undeclared (or, for the current syscall, a Cairo0) class hash, blockifier will fail the syscall and cause the invocation to revert (no state change, fee still charged), whereas the OS will silently accept the class-hash rewrite and commit `state_entry.class_hash = <arbitrary/undeclared value>` for that contract address into `contract_state_changes`. This yields a state root/commitment computed by the OS that does not match the state actually produced by the sequencer's blockifier for the same block, i.e., a wrong committed root / block hash and an honest-node divergence between the two "sources of truth" for the same execution.

### Likelihood Explanation
This is trivially reachable by any unprivileged caller: any deployed contract on Starknet can invoke the `replace_class` syscall directly (as demonstrated by the `test_replace_class` feature contracts), and only needs to supply a class hash that has not been declared (or is Cairo0, for the Cairo1 path) to trigger the divergence. No special privileges, race conditions, or unusual configuration are required — this is a pure logic gap present unconditionally on the OS execution path.

### Recommendation
Add the same declared-class (and, for the current syscall, Cairo1-type) validation in the Starknet OS's `execute_replace_class` implementations (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that blockifier already performs in `syscall_base.rs::replace_class`, i.e., verify the target `class_hash` exists in `contract_class_changes` (or the OS's declared-classes state) before performing `dict_update` on `contract_state_changes`, and reject/revert the syscall (mirroring blockifier's error behavior) when it does not. Resolve the outstanding `TODO(Yoni, 1/1/2026)` accordingly to keep OS semantics consistent with blockifier's.

### Proof of Concept
Static control-flow trace (not executed):
1. Deploy any contract exposing `replace_class_syscall` (e.g., the test contract's `test_replace_class` entry point, per `crates/blockifier_test_utils/resources/feature_contracts/cairo1/test_contract.cairo:201-203`).
2. Submit an invoke transaction calling that entry point with a `class_hash` that has never been declared on-chain.
3. Under blockifier (sequencer execution), `syscall_base::replace_class` calls `self.state.get_compiled_class(class_hash)?`, which fails with `UndeclaredClassHash`, causing the call/transaction to revert — no state change to the contract's class hash.
4. Under the Starknet OS (re-execution/proving path), `execute_replace_class` in `syscall_impls.cairo` (or `deprecated_execute_syscalls.cairo` for Cairo0 callers) performs `dict_update` on `contract_state_changes` unconditionally, recording the undeclared `class_hash` as the contract's new class — producing a different final state entry, and thus a different committed state root, than blockifier's actual (reverted) outcome for the identical transaction.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
