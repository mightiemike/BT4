### Title
Reserve/refund draining via spot-price manipulation of the UniversalCore auto-swap path used for gas-abstraction deposits and gas refunds - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
The reported Vader bug is about a protocol reserve paying out value (IL protection) based on a price relationship that the attacker can unilaterally control by creating and skewing a token pool, with a "protection" check that is derived from the same manipulable data and therefore provides no real defense. Push Chain's uexecutor module has a structurally identical pattern in its gas-abstraction and gas-refund logic: it converts a whitelisted gas PRC20 into native PC (WPC) using a live Uniswap-V3-style `QuoterV2.quoteExactInputSingle` spot-price read, and bounds slippage using `minPCOut = quote * 95 / 100`, where `quote` is the very same instantaneous, attacker-tradable spot price. There is no TWAP, external oracle, or size cap independent of the spot price.

### Finding Description
In `x/uexecutor/keeper/execute_inbound_gas.go`, `ExecuteInboundGas` handles a `TxType_GAS` inbound by:
1. Reading the current pool spot price via `k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)` [1](#0-0) 
2. Computing `minPCOut` as 95% of that same quote [2](#0-1) 
3. Calling `CallPRC20DepositAutoSwap`, which performs the actual on-chain swap of the user's PRC20 gas token into WPC via UniversalCore's own liquidity, subject only to that self-referential slippage bound [3](#0-2) 

`GetSwapQuote` is a plain `CallEVM` read (`commit=false`) against `QuoterV2.quoteExactInputSingle` with no time-weighting: [4](#0-3) 

The same pattern recurs in the gas-refund path. `applyGasRefund` in `x/uexecutor/keeper/outbound.go` fetches a fresh quote via `getSwapQuoteForRefund`, derives `minPCOut` from it with the identical 95% formula, and then calls `CallUniversalCoreRefundUnusedGas` to pay the refund out of protocol funds: [5](#0-4) 

Because the "protection" bound is computed from the same instantaneous AMM price that is being manipulated, it defends against slippage during a single call, not against an attacker who has pre-skewed the pool. Any unprivileged actor able to trade against (or provide/pull concentrated liquidity in) the UniversalCore-registered PRC20/WPC pool for a whitelisted gas token can push the spot price to an extreme and hold it there across the blocks needed for the inbound ballot to finalize and for `ExecuteInboundGas`/`applyGasRefund` to run, causing UniversalCore to swap or refund a disproportionate amount of protocol-held PC to the attacker's UEA/recipient for a comparatively small amount of the manipulated PRC20 gas token.

Unlike `uregistry`'s `MsgAddChainConfig`/`MsgAddTokenConfig` (which are admin-gated and thus block the "attacker deploys their own low-liquidity token pair" variant of the Vader attack [6](#0-5) ), the AMM pools themselves (Uniswap-V3-style pools behind `uniswapV3Quoter`) are ordinary permissionless DEX pools once a token is whitelisted — trading and liquidity provisioning on them is not restricted to admin/validators, so the manipulation vector remains open even though token *registration* is admin-curated.

### Impact Explanation
A successful manipulation lets an attacker extract native PC from protocol-controlled UniversalCore reserves in exchange for an artificially over-valued amount of a whitelisted gas PRC20 token, either through the gas-abstraction auto-swap deposit path or through the excess-gas refund path. This is a direct drain of protocol/user-controlled funds reachable by an ordinary unprivileged actor (a DEX trader), matching the "draining of reserve" impact class from the source report.

### Likelihood Explanation
Likelihood depends on the liquidity depth of the specific PRC20/WPC pool for a given whitelisted gas token and the value at stake per inbound/refund (bounded by `LiquidityCap` and per-tx gas amounts). Thin pools for lower-liquidity gas tokens make sustained price manipulation cheaper relative to the payout, and the attack requires no validator or admin privilege — only capital and time to hold a skewed price across several blocks while ordinary protocol processing occurs.

### Recommendation
Do not derive the slippage bound from the same instantaneous quote being manipulated. Use a manipulation-resistant reference price (e.g., a TWAP over a meaningful window, or an external price oracle) to compute `minPCOut`/expected value, and additionally cap the maximum PC payable per swap/refund independent of the pool's current spot price. Consider circuit-breakers that halt auto-swap/refund processing for a token pair if its spot price deviates significantly from a longer-window reference.

### Proof of Concept
1. Attacker acquires/whitelists-eligible token is already registered as a gas token with a live UniswapV3-style PRC20/WPC pool (admin-curated registration is out of the attacker's control, but pool trading is not).
2. Attacker trades a large position against the pool to push the PRC20→WPC spot price far above its fair value and maintains the skew (accepting swap fee/slippage cost) across the blocks needed for UV quorum + execution.
3. Attacker (or an accomplice) submits a source-chain deposit of a small amount of that PRC20 as a `TxType_GAS` inbound.
4. Once the inbound ballot finalizes, `ExecuteInboundGas` calls `GetSwapQuote` against the still-skewed pool, computes `minPCOut` from that same skewed quote, and `CallPRC20DepositAutoSwap` executes the swap, crediting the attacker's UEA with far more WPC/PC than the token's fair value — funded from UniversalCore's own liquidity.
5. Attacker unwinds their pool position, recovering most of the capital used to skew the price, netting the excess PC extracted in step 4 as profit. The same sequence works against `applyGasRefund` by inflating the value of `GasToken` right before an outbound's gas refund is computed.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
