Based on my research, I found a rounding-direction issue in Push Chain's gas fee accounting that mirrors the M-12 pattern (integer truncation applied where the specification/design assumption requires exactness, causing systematic under-collection).

### Title
Gas cost truncation in `CalculateGasCost` silently under-charges payload-execution gas fees when `baseFee` carries a fractional-upc component - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` converts the fee-market's `baseFee` (a `LegacyDec` with 18 decimals of precision) into a whole-`upc` `big.Int` by doing `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`. The code comment asserts this is always exact ("base fee is always a whole number of upc -- no fractional upc exists"), but that assumption is not enforced anywhere in the scoped code and is not guaranteed by the fee-market module, whose `BaseFee` is adjusted block-by-block via multiplicative EIP-1559-style decimal math and can legitimately settle on a non-integer-`upc` value. `big.Int.Div` truncates toward zero, so any fractional-upc remainder is silently dropped every time gas is charged for `executeUniversalTx`/payload execution.

### Finding Description [1](#0-0) 
computes the effective gas price by truncating the fee-market `baseFee` to whole `upc` before multiplying by `gasUsed`: [2](#0-1) 
This is the sole gas-cost source for `DeductGasFeesFromReceipt`, which burns exactly `gasCost` from the UEA/CEA sender's `upc` balance: [3](#0-2) 
The fee-market `BaseFee` is a `sdkmath.LegacyDec` obtained straight from `feemarketKeeper.GetBaseFee`, with no rounding/normalization to a whole-`upc` value performed before being handed to `CalculateGasCost`: [4](#0-3) 
Because the fee-market's `BaseFee` is adjusted every block via a proportional/elastic formula (a `LegacyDec` division/multiplication chain driven by observed gas usage relative to target), there is no structural guarantee it lands on an exact multiple of `1e18` (i.e., a whole `upc`). Whenever it does not, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates the sub-`upc` remainder toward zero rather than rounding up (`Ceil`) as is done correctly elsewhere in the ante-handler fee logic: [5](#0-4) 
That contrasts with the `MinGasPriceDecorator`, which explicitly computes `fee = Ceil(minGasPrice * gasLimit)` to guarantee the protocol is never under-paid — the same design intent implied by the whitepaper's `ceil` requirement in the referenced M-12 report. `CalculateGasCost` breaks that intent by rounding the *price* component down before the multiplication, rather than rounding the final cost up.

### Impact Explanation
Every unprivileged UEA/CEA payload execution that goes through `DeductGasFeesFromReceipt` (gas-and-payload / payload / CEA smart-contract inbound flows) is billed using a price truncated below the true fee-market rate whenever `baseFee` is not an exact multiple of `1e18`. This is a recurring, protocol-wide under-collection of `upc` from every payload-execution sender — the burned amount is systematically smaller than the amount the fee-market intends to charge, corrupting gas-fee accounting network-wide (in-scope impact: "corruption of ... gas fee accounting ... or canonical UniversalTx state"). The loss is borne by the protocol/validators (under-collected burn) each time this path executes, and it recurs on essentially every transaction once `baseFee` drifts off a whole-`upc` boundary, which the elastic base-fee adjustment algorithm makes routine rather than exceptional.

### Likelihood Explanation
No privileged action is required — any ordinary user submitting a `GAS_AND_PAYLOAD`/`PAYLOAD`/CEA-executing inbound triggers this path, and the fee-market's base fee naturally drifts to fractional-`upc` values as normal network load varies block to block (it is not attacker-controlled directly, but is a routine, expected runtime state, not an edge case). The bug is latent and always active whenever `baseFee` is non-integer in `upc` terms, which the responsible code's own governing assumption ("no fractional upc exists") does not actually hold given how `x/feemarket` derives `BaseFee`.

### Recommendation
Round the effective gas price (or the final `gasCost`) up rather than truncating it down, mirroring the `Ceil`+`RoundInt` pattern already used in `app/cosmos/min_gas_price.go`, e.g. compute `effectiveGasPrice = baseFee.Ceil().RoundInt().BigInt()` or perform the final multiplication in `LegacyDec` space and take `Ceil()` on the resulting `gasCost` before converting to `*big.Int`, so any fractional-`upc` remainder always rounds in the protocol's favor rather than being discarded.

### Proof of Concept
1. Let `baseFee = 1_500_000_000.5 upc` (a `LegacyDec` value the fee-market can produce after a block of above-target gas usage), and `gasUsed = 100_000`.
2. `baseFeeBig.Div(baseFeeBig, 1e18)` truncates `1_500_000_000.5 * 1e18` / `1e18` down to `1_500_000_000`, discarding the `0.5 upc` fractional rate.
3. `gasCost = 1_500_000_000 * 100_000 = 150_000_000_000_000` instead of the mathematically correct `150_000_000_050_000` — `50_000 upc` short, burned/collected as zero every time this exact scenario recurs across the network.
4. `DeductAndBurnFees` [6](#0-5)  burns only the truncated (lower) amount from the sender, permanently under-collecting the protocol's intended gas fee for that execution — repeatable on every payload execution while `baseFee` carries a fractional-`upc` component.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
