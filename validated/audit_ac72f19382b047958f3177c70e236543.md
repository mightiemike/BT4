## Finding: Permanent freezing of unclaimed gas-fee refund when a failed outbound's fund-revert mint fails

### Title
Permanent freezing of unclaimed excess-gas refund when outbound fund-revert re-mint fails - (File: x/uexecutor/keeper/outbound.go)

### Summary
The external report describes veALCX's `merge()` burning one NFT position without first claiming its already-accrued ALCX reward, permanently freezing that yield. The closest reachable analog in this repository is in `handleFailedOutbound` (x/uexecutor/keeper/outbound.go): when a failed outbound's bridged-fund re-mint fails, the function immediately calls `AbortOutbound` and returns — skipping `applyGasRefund` — even though the outbound may carry an already-computed, positive excess-gas amount (`GasFee - GasFeeUsed`) that should be refunded to the user regardless of the fund-revert outcome.

### Finding Description
`FinalizeOutbound` routes a UV-observed failed outbound to `handleFailedOutbound`: [1](#0-0) 

For `FUNDS`, `GAS_AND_PAYLOAD`, and `FUNDS_AND_PAYLOAD` outbound types, it calls `CallPRC20Deposit` to re-mint the bridged amount back to the revert recipient. If that call fails, the code takes the `AbortOutbound` branch and `return`s immediately: [2](#0-1) 

Note the comment on the success path just below it: "Refund excess gas regardless of tx type — gas was consumed on the external chain whether the execution succeeded or failed" — this is exactly the invariant the early `return` on the mint-failure branch violates: [3](#0-2) 

`applyGasRefund` is the only code path that calls `CallUniversalCoreRefundUnusedGas` to pay back `GasFee - GasFeeUsed` to the user: [4](#0-3) 

Once `AbortOutbound` runs, the outbound is set to `Status_ABORTED`, removed from `PendingOutbounds`, and an event is emitted — there is no other keeper entrypoint found (`AbortOutbound`, `UpdateOutbound`, `FinalizeOutbound` are the only matches for `ABORTED`/`AbortReason` in `x/uexecutor/keeper/`) that retries or manually re-attaches the skipped gas refund for an `ABORTED` outbound: [5](#0-4) 

This mirrors the veALCX pattern precisely: two independently-accrued values exist on the same record (bridged-fund revert and gas-fee refund), one operation's failure short-circuits the code before the second, unrelated, already-computed value is claimed, and the terminal state (`ABORTED` / NFT burn) has no automatic path back to it.

### Impact Explanation
The `OutboundTx.GasFee`/`GasFeeUsed` snapshot represents real value paid by/owed to the user for gas that was consumed on the destination chain. If the fund re-mint step fails (any transient or permanent PRC20 mint failure), the outbound moves straight to `ABORTED` and the computed excess-gas amount is dropped without ever being paid out and without leaving a record enabling automated recovery, matching the "permanent freezing of unclaimed yield" impact class from the source report.

### Likelihood Explanation
This is not attacker-triggerable at will with high confidence — I could not confirm from the available context an unprivileged, honest-validator-only path that reliably forces `CallPRC20Deposit` to fail (e.g., no evidence of a pausable/blocklistable PRC20 or an attacker-controlled recipient contract hook that reverts on mint was found in the indexed code). The condition instead appears to depend on transient EVM/module-account execution failures (e.g., gas exhaustion, nonce issues in the manually-managed `DerivedEVMCall` sequence) which are plausible in production but not clearly attacker-forceable through ordinary user deposit/payload submission alone. This weakens confidence that the "unprivileged external attacker" trigger bar is fully met; it is presented as the most structurally analogous bug in this codebase, but the reachability by an ordinary user (as opposed to a chance/rare operational failure) is uncertain.

### Recommendation
In the `CallPRC20Deposit` failure branch of `handleFailedOutbound`, call `applyGasRefund` (or persist the pending refund amount) before/alongside `AbortOutbound`, so the excess gas-fee refund is not silently dropped when only the fund re-mint leg fails. Alternatively, add an explicit admin/keeper recovery path that can re-attempt `applyGasRefund` for outbounds left in `ABORTED` status due to a mint failure.

### Proof of Concept
Not independently verified against a running node; conceptually: cause `CallPRC20Deposit` to fail for a `FUNDS`/`GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` outbound whose `GasFee > GasFeeUsed` (as in the existing `gas_fee_refund_test.go` "failed outbound performs both revert and gas refund" scenario) and observe that `PcRefundExecution` remains `nil` and the outbound is `ABORTED` with no further automated refund attempt, in contrast to the same test's expectation that `PcRefundExecution` is always set when a failed outbound's revert succeeds: [6](#0-5)

// AbortOutbound marks an outbound as ABORTED with a reason.
// This signals that automatic processing has failed and manual intervention is needed.
func (k Keeper) AbortOutbound(ctx context.Context, utxId string, outbound types.OutboundTx, reason string) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	outbound.OutboundStatus = types.Status_ABORTED
	outbound.AbortReason = reason

	if err := k.UpdateOutbound(ctx, utxId, outbound); err != nil {
		return err
	}

	// Defensively remove from pending index (may already be removed by caller)
	_ = k.PendingOutbounds.Remove(ctx, outbound.Id)

	// Emit event for monitoring/alerting
	sdkCtx.EventManager().EmitEvent(sdk.NewEvent(
		"outbound_aborted",
		sdk.NewAttribute("utx_id", utxId),
		sdk.NewAttribute("outbound_id", outbound.Id),
		sdk.NewAttribute("abort_reason", reason),
	))

	return nil
}

// handleFailedOutbound mints back the bridged tokens to the revert recipient,
// then attempts to refund any excess gas (gasFee - gasFeeUsed) just like a
// successful outbound would. Both operations are recorded on the outbound.
func (k Keeper) handleFailedOutbound(ctx sdk.Context, utxId string, outbound types.OutboundTx, obs *types.OutboundObservation) error {
	// Only revert bridged funds for funds-related tx types
	if outbound.TxType == types.TxType_FUNDS || outbound.TxType == types.TxType_GAS_AND_PAYLOAD ||
		outbound.TxType == types.TxType_FUNDS_AND_PAYLOAD {

		// Decide revert recipient safely
		recipient := outbound.Sender
		if outbound.RevertInstructions != nil &&
			outbound.RevertInstructions.FundRecipient != "" {
			recipient = outbound.RevertInstructions.FundRecipient
		}

		amount := new(big.Int)
		amount, ok := amount.SetString(outbound.Amount, 10)
		if !ok {
			return fmt.Errorf("invalid amount: %s", outbound.Amount)
		}
		receipt, err := k.CallPRC20Deposit(ctx, common.HexToAddress(outbound.Prc20AssetAddr), common.HexToAddress(recipient), amount)

		pcTx := types.PCTx{
			Sender:      outbound.Sender,
			BlockHeight: uint64(ctx.BlockHeight()),
		}
		// Capture tx hash from receipt even on EVM revert for debugging.
		if receipt != nil {
			pcTx.TxHash = receipt.Hash
			pcTx.GasUsed = receipt.GasUsed
		}
		if err != nil {
			pcTx.Status = "FAILED"
			pcTx.ErrorMsg = err.Error()
			outbound.PcRevertExecution = &pcTx
			// Re-mint failed — mark as ABORTED for manual intervention
			return k.AbortOutbound(ctx, utxId, outbound,
				fmt.Sprintf("failed to re-mint tokens for revert: %s", err.Error()))
		}
		pcTx.TxHash = receipt.Hash
		pcTx.GasUsed = receipt.GasUsed
		pcTx.Status = "SUCCESS"
		outbound.PcRevertExecution = &pcTx
		k.Logger().Info("outbound failed: funds re-minted for revert",
			"utx_id", utxId,
			"outbound_id", outbound.Id,
			"tx_hash", receipt.Hash,
		)
	}
