### Title
Unbounded CPU cost in `LogBlockQuery.getPossibleBlock` due to missing early-exit on `MAX_RESULT` - ([File: framework/src/main/java/org/tron/core/services/jsonrpc/filters/LogBlockQuery.java])

### Summary
`getPossibleBlock()` performs the entire bloom-filter AND/OR computation across every section in `[minSection, maxSection]`, and additionally iterates every set bit in the resulting `BitSet` to build `blockNumList`, before ever checking `blockNumList.size() >= MAX_RESULT`. An unprivileged caller of the public `eth_getLogs` JSON-RPC endpoint can submit a wide block-range query with no address/topic filter (or one guaranteed to match nearly every block) and force the node to pay full O(range) cost every single call, only to be rejected with `JsonRpcTooManyResultException` at the very end.

### Finding Description
`getPossibleBlock()` [1](#0-0)  builds a `BitSet` sized to `(maxSection - minSection + 1) * BLOCK_PER_SECTION` and, for each address/topic condition, calls `subMatch()` which in turn calls `partialMatch()` for every section in the requested range, issuing concurrent `sectionBloomStore.get()` calls and doing `BitSet` AND/OR work [2](#0-1) . Only after this full computation completes does the method walk every set bit of the final `BitSet` to populate `blockNumList` [3](#0-2) , and only then is the size check performed:
```
if (blockNumList.size() >= MAX_RESULT) {
  throw new JsonRpcTooManyResultException(...);
}
``` [4](#0-3) 

Notably, if `logFilter` has no contract addresses and no topics, `getConditions()` returns an empty `allConditionsIndex` array [5](#0-4) , so the AND/OR loop at lines 77-80 never executes and `blockNumBitSet` remains fully set (from `blockNumBitSet.set(0, capacity)` at line 74). This means the entire `[minBlock, maxBlock]` range's bits are enumerated one-by-one in the loop at lines 82-91 regardless of filter selectivity — the cost scales directly with the requested block range, and `MAX_RESULT` is enforced only after that full enumeration finishes.

Because `getPossibleBlock` is invoked from the `eth_getLogs` path in `TronJsonRpcImpl` (public JSON-RPC API, unauthenticated by default), any external caller can repeatedly submit queries with a wide `fromBlock`/`toBlock` span and no filters, forcing full-range BitSet computation/enumeration on every call before rejection.

### Impact Explanation
Each call pays cost proportional to the full requested block range (bounded only by chain height), not to `MAX_RESULT`. Repeated queries of this shape let an unprivileged caller impose sustained CPU/GC load on the full node's JSON-RPC service thread pool and shared executor (`sectionExecutor`), degrading responsiveness of block validation/broadcast and other RPC consumers sharing the node — a public-cost invariant violation since the attacker's cost (one HTTP request) is far below the node's cost (full range scan).

### Likelihood Explanation
Preconditions: JSON-RPC HTTP API must be enabled and reachable (a common full-node configuration), and the chain must have a non-trivial number of blocks so the range/section count is large. No authentication or special privilege is required — the attacker only needs to send repeated `eth_getLogs` calls with a broad range and empty filter set. This is easily automatable and repeatable at will, limited only by whatever generic RPC rate-limiting the node operator has configured (which is outside this code path).

### Recommendation
Add an early-exit check inside the enumeration/computation loops rather than only after full completion:
- In the final bit-walking loop (lines 82-91), break out and throw `JsonRpcTooManyResultException` as soon as `blockNumList.size()` reaches `MAX_RESULT`.
- Similarly, cap/limit the total section range (`maxSection - minSection`) or total block range (`maxBlock - minBlock`) allowed per query up front, independent of filter selectivity, so a single request cannot force scanning of the entire chain height.

### Proof of Concept
Java test plan (JMH-style or simple `System.nanoTime()` benchmark) in `framework/src/test/java/org/tron/core/jsonrpc/`:
1. Populate a `SectionBloomStore` (as done in `LogBlockQueryTest`/`SectionBloomStoreTest`) spanning a large number of sections (e.g., simulate a range covering hundreds of thousands of blocks).
2. Construct two `LogFilterWrapper` instances:
   - Query A: `fromBlock=0`, `toBlock=<current max>`, no address/topic filters (matches every block, guaranteed to exceed `MAX_RESULT`).
   - Query B: `fromBlock=<current max - 10>`, `toBlock=<current max>` (returns few results).
3. Wrap `getPossibleBlock()` calls with timing/CPU measurement (`ThreadMXBean.getCurrentThreadCpuTime()`).
4. Assert: for Query A, CPU time is proportional to the full range size and comparable in cost to Query B scaled by range ratio — i.e., there is no early termination, and cost is not capped near `MAX_RESULT`'s cost. Expected desired behavior after fix: CPU time for Query A should be capped near the cost of processing `MAX_RESULT` blocks/sections, not the entire range, demonstrating the current code fails this invariant.

  public List<Long> getPossibleBlock() throws ExecutionException, InterruptedException,
      JsonRpcTooManyResultException {
    List<Long> blockNumList = new ArrayList<>();
    if (minBlock > currentMaxBlockNum) {
      return blockNumList;
    }

    int[][][] allConditionsIndex = getConditions();

    int capacity = (maxSection - minSection + 1) * SectionBloomStore.BLOCK_PER_SECTION;
    BitSet blockNumBitSet = new BitSet(capacity);
    blockNumBitSet.set(0, capacity);

    // works serial
    for (int[][] conditionsIndex : allConditionsIndex) {
      BitSet bitSet = subMatch(conditionsIndex);
      blockNumBitSet.and(bitSet);
    }

    for (int i = blockNumBitSet.nextSetBit(0); i >= 0; i = blockNumBitSet.nextSetBit(i + 1)) {
      // operate on index i here
      if (i == Integer.MAX_VALUE) {
        break; // or (i+1) would overflow
      }
      long blockNum = (long) minSection * SectionBloomStore.BLOCK_PER_SECTION + i;
      if (minBlock <= blockNum && blockNum <= maxBlock) {
        blockNumList.add(blockNum);
      }
    }

    if (blockNumList.size() >= MAX_RESULT) {
      throw new JsonRpcTooManyResultException(
          "query returned more than " + MAX_RESULT + " results");
    }

    return blockNumList;
  }

  private BitSet subMatch(int[][] bitIndexes) throws ExecutionException, InterruptedException {

    int capacity = (maxSection - minSection + 1) * SectionBloomStore.BLOCK_PER_SECTION;
    BitSet subBitSet = new BitSet(capacity);

    for (int section = minSection; section <= maxSection; section++) {
      BitSet partialBitSet = partialMatch(bitIndexes, section);

      for (int i = partialBitSet.nextSetBit(0); i >= 0; i = partialBitSet.nextSetBit(i + 1)) {
        // operate on index i here
        if (i == Integer.MAX_VALUE) {
          break; // or (i+1) would overflow
        }
        int offset = (section - minSection) * SectionBloomStore.BLOCK_PER_SECTION + i;
        subBitSet.set(offset);
      }
    }

    return subBitSet;
  }

  public int[][][] getConditions() {

    LogFilter logFilter = logFilterWrapper.getLogFilter();
    List<byte[][]> conditions = new ArrayList<>();
    if (ArrayUtils.isNotEmpty(logFilter.getContractAddresses())) {
      conditions.add(logFilter.getContractAddresses());
    }
    for (byte[][] topicList : logFilter.getTopics()) {
      if (ArrayUtils.isNotEmpty(topicList)) {
        conditions.add(topicList);
      }
    }

    int[][][] allConditionsIndex = new int[conditions.size()][][];

    for (int k = 0; k < conditions.size(); k++) {
      byte[][] conditionByte = conditions.get(k);

      int[][] bitIndexes = new int[conditionByte.length][];
      for (int j = 0; j < conditionByte.length; j++) {

        byte[] hash = Hash.sha3(conditionByte[j]);
        Bloom bloom = Bloom.create(hash);
        BitSet bs = BitSet.valueOf(bloom.getData());

        //number of nonZero positions may be equal or less than number(3) of hash function in Bloom
        List<Integer> bitIndexList = new ArrayList<>();
        for (int i = bs.nextSetBit(0); i >= 0; i = bs.nextSetBit(i + 1)) {
          // operate on index i here
          if (i == Integer.MAX_VALUE) {
            break; // or (i+1) would overflow
          }
          bitIndexList.add(i);
        }

        bitIndexes[j] = bitIndexList.stream().mapToInt(Integer::intValue).toArray();
      }
      allConditionsIndex[k] = bitIndexes;
    }

    return allConditionsIndex;
  }
