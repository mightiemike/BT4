### Title
Fee-bypass via committed EVM state surviving a reverted `MsgExecutePayload` when gas-fee deduction fails - (`x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`msgServer.ExecutePayload` (the live handler for `MsgExecutePayload`) calls `Keeper.ExecutePayload`, which executes the UEA payload via `CallUEAExecutePayload` (a `DerivedEVMCall` with `commit=true`) directly against `sdkCtx`, and only afterwards attempts `DeductGasFeesFromReceipt`. This mirrors the VersaVerifyingPaymaster pattern: an action that consumes a resource (EVM gas / execution) happens first, and the charge is applied in a second, separate step that can fail independently.

### Finding Description [1](#0-0)  shows the order of operations: `CallUEAExecutePayload` is invoked directly on `sdkCtx` with `commit=true` (a real, committing `DerivedEVMCall`, per [2](#0-1) ), and only afterward does the code call `DeductGasFeesFromReceipt`. The comment on the newer `ExecutePayloadV2` implementation explicitly acknowledges this exact risk exists elsewhere in the code: it wraps both the EVM call and the fee deduction in an `sdkCtx.CacheContext()` specifically "to commit/revert together... closes the free-execution gap when the UEA has no native UPC to cover gas" — see [3](#0-2) .

The non-V2 `ExecutePayload` used by the live `MsgExecutePayload` message handler ( [4](#0-3) ) does **not** use that `CacheContext` wrapper — it operates directly on `sdkCtx` ( [5](#0-4) ). The critical unresolved question — which I could not fully verify given tool-call limits — is whether `DerivedEVMCall(commit=true)` writes EVM state directly to the underlying `stateDB`/`CommitMultiStore` in a way that is *not* rolled back when the Cosmos SDK's per-message cache-context is discarded on handler error, the same way `EntryPoint.handleOps` in the Solidity report keeps user-favorable side effects even when `_postOp`'s charge step fails. If `DerivedEVMCall`'s commit semantics are equivalent to a full EVM tx commit at the point of the call (rather than being scoped to the ante/runMsgs cache context), then a subsequent failure in `DeductGasFeesFromReceipt` (e.g., `DeductAndBurnFees` failing due to insufficient UEA balance) returns an error from the message handler, but the already-committed EVM execution (arbitrary calls the payload made through the UEA, including transfers of PRC20/native assets to third parties) is not undone, while the corresponding gas charge is skipped.

### Impact Explanation
If confirmed, an attacker-controlled UEA payload could be crafted with a `maxFeePerGas`/`gasUsed` cost that the UEA cannot cover (i.e., ensure `DeductAndBurnFees` fails on the burn or transfer step) while the payload itself still performs a self-contained, valuable state mutation (e.g., moving/PRC20 transfers, contract interactions) that is committed to EVM state. This would let a user obtain free EVM execution and dodge the gas fee entirely — directly analogous to the paymaster bypass, and falling under "corruption of ... gas fee accounting ... revert destination ... canonical UniversalTx state" and "unauthorized module-originated EVM execution" in the impact gate.

### Likelihood Explanation
Likelihood depends entirely on the semantics of `DerivedEVMCall`'s `commit=true` flag relative to the SDK's message-level cache context — a detail internal to the forked `cosmos/evm` dependency that I was not able to inspect within the available tool budget. The explicit remediation comment in `execute_payload.go` referencing "closes the free-execution gap" strongly suggests this exact class of bug was previously known and fixed in the V2 path, but the non-V2 `ExecutePayload` (still wired to the live `MsgExecutePayload` handler) was not correspondingly hardened, which is a significant red flag warranting confirmation.

### Recommendation
Verify whether `DerivedEVMCall(commit=true)` state changes are scoped to the calling `sdk.Context`'s cache multi-store (and thus roll back automatically if the msg handler returns an error) or whether they commit independently of the ante/runMsgs execution context. If the latter, apply the same `CacheContext`-wrapping pattern used in `ExecutePayloadV2` to the live `ExecutePayload` path (or replace `ExecutePayload` with `ExecutePayloadV2` in `msg_server.go`) so that EVM execution and gas-fee deduction commit or roll back atomically.

### Proof of Concept
Could not construct an executable PoC without confirming the commit semantics of `DerivedEVMCall`/`cosmos/evm` fork internals (outside indexed scope). A conceptual PoC:
1. Attacker deploys/uses a UEA with a balance below the gas cost required for a crafted payload's `gasUsed`.
2. Attacker submits `MsgExecutePayload` with a payload whose execution transfers value out of the UEA/PRC20 contracts as its primary effect, and whose declared `maxFeePerGas`/gas parameters make `DeductAndBurnFees` fail (insufficient balance for the burn).
3. If `CallUEAExecutePayload`'s committed EVM state is not tied to the Cosmos message cache context, the transfer persists on-chain while `msgServer.ExecutePayload` returns an error and no fee is burned — reproducing the "charge-skipped-on-revert" bypass.

Given the uncertainty on the exact commit-rollback semantics, this should be treated as **flagged for verification** rather than a fully confirmed finding — a Devin session with the ability to read the `cosmos/evm` fork's `DerivedEVMCall` implementation and run integration tests would be needed to confirm root cause and reachable impact.

	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.

// ExecutePayload handles universal payload execution on the UEA.
func (ms msgServer) ExecutePayload(ctx context.Context, msg *types.MsgExecutePayload) (*types.MsgExecutePayloadResponse, error) {
	_, evmFromAddress, err := utils.GetAddressPair(msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to parse signer address")
	}

	err = ms.k.ExecutePayload(ctx, evmFromAddress, msg.UniversalAccountId, msg.UniversalPayload, msg.VerificationData)
	if err != nil {
		return nil, err
	}

	return &types.MsgExecutePayloadResponse{}, nil
}
