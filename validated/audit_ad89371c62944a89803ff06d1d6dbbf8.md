### Title
Starknet OS `execute_replace_class` omits class-declaration check enforced by the Blockifier, risking OS/Blockifier state divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The reported Notional bug is fundamentally about a missing authorization/validation check on a privileged state-mutating operation (`upgradeTo`) reachable through an uninitialized contract, letting an unprivileged actor mutate implementation state that should have been protected. The closest reachable analog in this sequencer is the `replace_class` syscall, which lets **any contract, from any unprivileged transaction**, rewrite its own class hash in storage. The Blockifier (the Rust execution engine used for real block building) enforces that the target class hash must already be declared before performing the replacement, but the Starknet OS Cairo implementation used for re-execution/proof generation does **not** perform this check — a gap explicitly flagged by an open `TODO` in the code.

### Finding Description
In the Rust blockifier, the deprecated syscall handler for `replace_class` explicitly requires the target class to be declared before mutating storage: [1](#0-0) 

The Cairo1 syscall path in the blockifier delegates to the same `base.replace_class` logic (which performs the analogous declared-class check via `state.get_compiled_class`): [2](#0-1) [3](#0-2) 

However, the corresponding logic in the **Starknet OS** (the Cairo program that independently re-executes the same transactions to produce the state diff/commitment used for proving) performs the class-hash swap in `contract_state_changes` **unconditionally**, with an explicit acknowledgment that the check is missing: [4](#0-3) 

The same unchecked pattern exists in the deprecated (Cairo0) syscall execution path of the OS: [5](#0-4) 

Both OS entry points are reached directly from the syscall dispatch for any contract executing `REPLACE_CLASS_SELECTOR`: [6](#0-5) [7](#0-6) 

This is analogous to the reported bug class: a security-relevant precondition check (declared-class existence, akin to "initialized" authorization) that one code path enforces (the Blockifier, akin to the Solidity `onlyOwner`/`initializer` guard) is absent in a second, independently-executed code path (the OS, akin to a second deployment/inheritance path that skips the guard) that operates over the same untrusted, attacker-controlled input (the class hash supplied via the `replace_class` syscall by any contract on behalf of any unprivileged transaction sender).

### Impact Explanation
If any state-transition path exists where the Blockifier tolerates or does not itself gate a `replace_class` call the way the OS assumes (e.g., differences in call-frame vs. top-level revert handling, or future changes to Blockifier revert semantics that rely on the OS independently re-validating each syscall), the OS could commit a class-hash mutation into `contract_state_changes` that the Blockifier's authoritative execution never actually applied (or vice versa). Because the OS's state diff is what ultimately feeds `commitment.cairo`'s Patricia tree updates and the final committed state root, such a discrepancy would produce a wrong committed root / honest-node divergence between the block as sequenced by the Blockifier and the block as proven by the OS — exactly the class of impact permitted by the rules (wrong committed root, honest-node divergence).

### Likelihood Explanation
The `replace_class` syscall is reachable by any Cairo contract deployed by any user, from a single ordinary invoke transaction — no special privilege is required to trigger the code path. The missing check is a real gap acknowledged in-source via the `TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment, meaning the maintainers are aware the OS's enforcement lags the Blockifier's. Actually triggering a concrete state divergence likely requires exploiting a specific edge case where the two engines disagree on whether the surrounding call succeeds (e.g., partial-revert semantics), so likelihood of an immediately exploitable divergence is moderate rather than trivial, but the missing invariant itself is unconditionally present today.

### Recommendation
Add the same "class hash must be declared" check to the OS's `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` that the Blockifier already performs in `hint_processor.rs`/`syscall_handler.rs`, so both execution engines enforce identical preconditions on this state-mutating syscall and cannot diverge on which `replace_class` calls are valid.

### Proof of Concept
1. An attacker deploys a contract exposing an external function that calls the `replace_class` syscall with an arbitrary, undeclared `class_hash`.
2. During real block building, the Blockifier's `replace_class` handler calls `state.get_compiled_class(request.class_hash)` (`crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:795-807`), which errors out for an undeclared class, causing that call frame (or the whole transaction, depending on call context/try-catch) to revert according to Blockifier semantics.
3. During OS re-execution/proving of the same transaction trace, `execute_replace_class` (`crates/apollo_starknet_os_program/.../syscall_impls.cairo:881-920`) performs the `dict_update` on `contract_state_changes` unconditionally — it never queries whether `class_hash` is declared.
4. Any edge case where the Blockifier's revert/success determination for the surrounding call differs from what the OS independently re-derives (since the OS lacks the same guard) results in the OS committing a class-hash change into the state diff that the Blockifier's authoritative block execution did not apply, producing a state root mismatch between the sequenced block and the OS-proven block.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
