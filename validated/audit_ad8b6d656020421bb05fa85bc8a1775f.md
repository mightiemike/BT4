### Title
Direct `MsgExecutePayload` path lacks the atomic-rollback guard present in `ExecutePayloadV2` - ([File: x/uexecutor/keeper/msg_execute_payload.go])

### Summary
The external report's bug class is "state mutated (burn) before dependent accounting (rewards) is recalculated, letting a user extract value based on stale state." The closest analog in this repository is in the `MsgExecutePayload` handling: two parallel implementations exist for executing a `UniversalPayload` through a UEA — `ExecutePayload` (used by the live `MsgServer`) and `ExecutePayloadV2` (used only by inbound CEA/gas-and-payload execution flows) — and only the V2 version wraps EVM execution and gas-fee deduction in a `CacheContext` so they commit or roll back atomically.

### Finding Description
`x/uexecutor/keeper/msg_execute_payload.go` `ExecutePayload` calls `CallUEAExecutePayload` directly against `sdkCtx` [1](#0-0) , then calls `DeductGasFeesFromReceipt` afterward on the same context. By contrast, `ExecutePayloadV2` explicitly documents wrapping both steps in a `sdkCtx.CacheContext()` specifically to "close the free-execution gap when the UEA has no native UPC to cover gas" [2](#0-1) . `ExecutePayloadV2` is only invoked from `execute_inbound_funds_and_payload.go` and `execute_inbound_gas_and_payload.go` — i.e., from the inbound (validator-voted) execution paths — while `msg_server.go`'s `ExecutePayload` RPC (the unprivileged, user-reachable, gasless `MsgExecutePayload` entrypoint per `app/txpolicy/gasless.go`) calls the older, non-cache-wrapped `ExecutePayload` [3](#0-2) .

This means the payload's EVM side effects (e.g., the UEA transferring away or spending its own native balance during `executeUniversalTx`) are computed against the pre-execution balance in `CallUEAExecutePayload`, and only afterward does `DeductGasFeesFromReceipt` attempt to charge gas against the UEA's balance — mirroring the EsEMBR pattern where balance-dependent accounting (there: rewards; here: gas-fee deduction) is computed without first re-checking/re-deriving state that the just-executed action already changed.

### Impact Explanation
If confirmed, this could allow the UEA's balance to be manipulated by the payload itself in a way that causes gas-fee deduction to fail, undercharge, or be computed against the wrong (stale or drained) balance — a potential accounting corruption in gas-fee accounting for `MsgExecutePayload`, in scope per "corruption of ... gas fee accounting, refund accounting ... or canonical UniversalTx state."

### Likelihood Explanation
**Unconfirmed.** I was not able to read `x/uexecutor/keeper/fees.go` (`DeductGasFeesFromReceipt`) to verify whether it (a) reads the UEA's balance before or after `CallUEAExecutePayload`'s state changes, (b) caps the deduction to the available balance, or (c) is otherwise safe. Cosmos SDK's `BaseApp` also generally reverts *all* state changes for a failed message within a transaction via its own branched multi-store, independent of whether the keeper additionally uses an internal `CacheContext` — so the absence of `ExecutePayloadV2`'s explicit `CacheContext` in the non-V2 path does not by itself prove an exploitable gap; it may simply be redundant-but-documented defense-in-depth, or it may guard against something more subtle (e.g., committing gas fee state even when the outer transaction still needs to attach downstream `OutboundTx`/`PCTx` records that reference an inconsistent read). Confirming an exploitable analog to the EsEMBR bug requires reading `fees.go` and the UEA `executeUniversalTx`/`DeductGasFeesFromReceipt` sequencing in detail.

// ExecutePayload handles universal payload execution on the UEA.
func (ms msgServer) ExecutePayload(ctx context.Context, msg *types.MsgExecutePayload) (*types.MsgExecutePayloadResponse, error) {
	_, evmFromAddress, err := utils.GetAddressPair(msg.Signer)
	if err != nil {
		return nil, errors.Wrapf(err, "failed to parse signer address")
	}

	err = ms.k.ExecutePayload(ctx, evmFromAddress, msg.UniversalAccountId, msg.UniversalPayload, msg.VerificationData)
	if err != nil {
		return nil, err
	}

	return &types.MsgExecutePayloadResponse{}, nil
}
