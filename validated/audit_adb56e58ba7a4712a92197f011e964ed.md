### Title
External Initiator credentials grant a blanket node-wide Run role usable against any job/bridge, not just the initiator's own job - ([File: core/web/auth/auth.go])

### Summary
`AuthenticateExternalInitiator` in `core/web/auth/auth.go` authenticates a request purely by matching the `X-Chainlink-EA-AccessKey`/`X-Chainlink-EA-Secret` headers against a single `bridges.ExternalInitiator` row via `FindExternalInitiator`, then unconditionally sets `c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})`. The resulting `UserRoleRun` session is checked only by `RequiresRunRole`, which inspects the role field and nothing else, so any endpoint gated by `RequiresRunRole` becomes reachable to any external initiator, regardless of which job/bridge it was registered for.

### Finding Description
`AuthenticateExternalInitiator` (`core/web/auth/auth.go:119-151`) looks up the initiator solely by access key/secret pair via `store.FindExternalInitiator`, verifies the secret with `bridges.AuthenticateExternalInitiator` (`core/bridges/external_initiator.go:61-67`), and on success stores the matched `*bridges.ExternalInitiator` in the Gin context under `SessionExternalInitiatorKey` and grants a generic `clsessions.User{Role: clsessions.UserRoleRun}` under `SessionUserKey`.

Critically, `GetAuthenticatedExternalInitiator` (`core/web/auth/auth.go:191-198`), the only accessor that could be used to recover which specific `ExternalInitiator` authenticated the request, is referenced nowhere outside of `auth.go` itself — it is never called by any run-triggering controller to cross-check that the authenticated initiator is actually the one the target job/bridge registered. `RequiresRunRole` (`core/web/auth/auth.go:202-217`) only checks `user.Role != clsessions.UserRoleView`; it has no notion of which job or bridge the caller is entitled to trigger.

Consequently, once an attacker holds any valid EI access key/secret pair (even one registered for an unrelated job), any route wrapped with `AuthenticateExternalInitiator` + `RequiresRunRole` — the job/bridge run-triggering endpoints — will authorize the request for a `UserRoleRun` session with no additional binding to the specific job ID/spec ID in the URL. The `ExternalInitiator` record stored in the context is inert; nothing consumes it to enforce per-job scoping.

### Impact Explanation
An external initiator's credentials, intended to trigger runs only for the job(s) that registered them, effectively become node-wide Run credentials. This allows a party holding one legitimate (or unrelated) initiator's credentials to trigger job runs for arbitrary bridges/job specs on the node, potentially causing unauthorized data submission, spurious external adapter calls, or price/data misreporting on unrelated jobs — matching a privilege-escalation / authorization-bypass class impact.

### Likelihood Explanation
Preconditions: the attacker must possess a valid `AccessKey`/`Secret` pair for *some* External Initiator registered on the node (this is explicitly excluded from "leaked keys" only if the initiator legitimately registered credentials for one job but then abuses them against another route — i.e., the initiator itself, or anyone who obtains any one initiator's credentials through the normal registration API, not through leaking someone else's secret). Given that any registered initiator inherently receives full `UserRoleRun` regardless of target job, this is fully reachable and repeatable via ordinary HTTP requests to any run-triggering endpoint guarded by `RequiresRunRole`.

### Recommendation
Bind the Run authorization to the specific job/bridge relationship: when handling run-trigger requests, use `GetAuthenticatedExternalInitiator` to retrieve the authenticated `ExternalInitiator` and verify it is the initiator actually associated with the target job/spec (e.g., via the webhook job's registered external initiator ID) before allowing the run to proceed, instead of granting a blanket `UserRoleRun` session usable against any endpoint.

### Proof of Concept
Integration test outline:
1. Create two `ExternalInitiator` records, EI-A and EI-B, each with distinct access key/secret pairs, and register EI-A with Job-A and EI-B with Job-B via the webhook/job-spec external initiator association.
2. Using EI-A's `X-Chainlink-EA-AccessKey`/`-Secret` headers, call the run-trigger endpoint for Job-B (`POST /v2/jobs/{JobB-ID}/runs` or equivalent spec/run route).
3. Assert the request is currently accepted (200/201) and a run is created for Job-B, demonstrating that `AuthenticateExternalInitiator` + `RequiresRunRole` does not scope EI-A's privilege to Job-A.

func AuthenticateExternalInitiator(c *gin.Context, store Authenticator) error {
	ctx := c.Request.Context()
	eia := &auth.Token{
		AccessKey: c.GetHeader(static.ExternalInitiatorAccessKeyHeader),
		Secret:    c.GetHeader(static.ExternalInitiatorSecretHeader),
	}

	ei, err := store.FindExternalInitiator(ctx, eia)
	if err != nil {
		if errors.Is(err, sql.ErrNoRows) {
			return auth.ErrorAuthFailed
		}

		return errors.Wrap(err, "finding external initiator")
	}

	ok, err := bridges.AuthenticateExternalInitiator(eia, ei)
	if err != nil {
		return err
	}
	if !ok {
		return auth.ErrorAuthFailed
	}

	c.Set(SessionExternalInitiatorKey, ei)

	// External initiator endpoints (wrapped with AuthenticateExternalInitiator) inherently assume the role
	// of 'run' (required to trigger job runs)
	c.Set(SessionExternalInitiatorKey, ei)
	c.Set(SessionUserKey, &clsessions.User{Role: clsessions.UserRoleRun})

	return nil
}

func GetAuthenticatedExternalInitiator(c *gin.Context) (*bridges.ExternalInitiator, bool) {
	obj, ok := c.Get(SessionExternalInitiatorKey)
	if !ok {
		return nil, false
	}

	return obj.(*bridges.ExternalInitiator), ok
}

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// AuthenticateExternalInitiator compares an auth against an initiator and
// returns true if the password hashes match
func AuthenticateExternalInitiator(eia *auth.Token, ea *ExternalInitiator) (bool, error) {
	hashedSecret, err := auth.HashedSecret(eia, ea.Salt)
	if err != nil {
		return false, err
	}
	return subtle.ConstantTimeCompare([]byte(hashedSecret), []byte(ea.HashedSecret)) == 1, nil
}
