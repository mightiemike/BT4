## Analysis

The reported issue is real and reachable by an unprivileged attacker.

### How `isOldEnough` determines "age"

`RentReclaimer.isOldEnough` does not check the PDA's actual creation slot/lamports; it infers age purely from the **most recent transaction signature that references the address**, via `GetSignaturesForAddressWithOpts` with `Limit: 1`: [1](#0-0) 

The comment explicitly assumes "For StoredIxData PDAs, that's effectively the PDA's age (they only ever see one tx — their creating `store_execute_ix_data`)" [2](#0-1) . That assumption is incorrect: Solana's `getSignaturesForAddress` index records **any** transaction that references the account key, even as a non-signer, read-only account — not just transactions that write to or are created by it.

### Attack path

1. The orphan PDA address is discoverable by anyone via the same public, unprivileged RPC query used in `discoverOrphans` (`GetProgramAccountsWithOpts` filtered by the `StoredIxData` discriminator, matched against the gateway program) [3](#0-2) . No special permission is needed to run this same filtered scan against a public RPC node.
2. Once the attacker has the address, they can submit an ordinary, cheap transaction (e.g., a no-op/memo instruction) that simply lists the orphan PDA as a read-only account reference. This requires no ownership or signing authority over the PDA.
3. Doing so at an interval shorter than `rentReclaimMinPDAAge` (10 minutes) [4](#0-3)  continuously refreshes the "most recent signature" timestamp that `isOldEnough` reads, so `age >= r.minAge` never evaluates true.
4. `runOnce` then perpetually treats the candidate as "too young" and skips it, so `closeOrphan` is never invoked [5](#0-4) .

This does not require flooding the network — it only requires periodic, low-cost transactions targeted at one specific, publicly-known account, and it is achievable by any unprivileged actor with an ordinary wallet.

### Impact

The affected rent (~0.002 SOL per `StoredIxData` PDA, owed back to the relayer/protocol) becomes permanently unreclaimable as long as the attacker keeps refreshing the signature history, breaking the invariant that "honest sweep eventually reclaims genuinely orphaned rent." It is a genuine, non-network-level denial of a protocol fund-recovery path — not a theft of user funds, but a persistent freezing of protocol-controlled rent, and it fits the in-scope category of "permanent freezing... of protocol-controlled funds" / "denial of service only when it is not network-level and is reachable without privileged control."

Note that the economics are asymmetric against the attacker (they must keep paying network fees indefinitely to lock up a small, fixed amount of rent), which limits severity, but the mechanism itself is a legitimate logic flaw, not a mitigated one.

### Title
Age-of-orphan check relies on spoofable "most recent signature" timestamp, allowing indefinite rent-reclaim griefing - (File: `universalClient/chains/svm/rent_reclaimer.go`)

### Summary
`RentReclaimer.isOldEnough` infers a `StoredIxData` PDA's age from the timestamp of the most recent transaction that merely *references* the address, rather than from the account's actual creation time. Any unprivileged actor who discovers an orphaned PDA address via a public RPC query can perpetually "touch" that address with cheap, unrelated transactions spaced under the configured `minAge` (10 minutes), keeping `isOldEnough` returning `false` forever.

### Finding Description
`isOldEnough` calls `GetSignaturesForAddressWithOpts` with limit 1 and computes `age := time.Since(blockTime of sigs[0])`, comparing against `minAge` [6](#0-5) . This RPC method returns the most recent transaction where the address appears anywhere in the transaction's account list, including as a non-signer read-only reference, not only the PDA's creating transaction. An attacker who has learned the PDA address (trivially, from the same public `getProgramAccounts` filter used in `discoverOrphans`) can include that address as an extra account in innocuous, cheap transactions of their own, at an interval below `minAge`, indefinitely resetting the "most recent signature" timestamp observed by the sweeper.

### Impact Explanation
The sweep in `runOnce` skips any candidate for which `isOldEnough` returns `false` [7](#0-6) , so `closeOrphan` (and the associated rent refund) is never executed for a targeted PDA. This is a persistent, targeted denial of the rent-reclamation invariant, achievable without network-level flooding and by a fully unprivileged actor.

### Likelihood Explanation
Discovery of orphan addresses requires only a standard RPC read matching the same filter the reclaimer itself uses. Sending a cheap transaction referencing an arbitrary public key as a read-only account requires no special privilege on Solana. The only cost to the attacker is ordinary transaction fees, which must be paid repeatedly (every <10 minutes) to maintain the block, making this more of a persistent griefing vector than a one-shot exploit, but it is trivially repeatable and does not require validator or relayer collusion.

### Recommendation
Determine orphan age from the account's actual state (e.g., its creation slot/blockhash obtained when it was first observed, or by comparing against the transaction that created it, matched via the known `sub_tx_id`/create-instruction signature) rather than trusting the most recent signature referencing the address. Alternatively, track first-seen time internally (in a persistent local store) rather than relying on `getSignaturesForAddress`, or bind the age check to the specific creating transaction signature rather than "most recent" signature.

### Proof of Concept
1. Query `getProgramAccountsWithOpts` on the gateway program with the `StoredIxData` discriminator + relayer-refund-recipient filter (same as `discoverOrphans`) to obtain a target orphan PDA address.
2. Every ~9 minutes, submit a transaction (e.g., a Memo program instruction) that lists the target PDA as an additional read-only account.
3. Observe that `getSignaturesForAddress` for that PDA now returns the attacker's injected transaction as the most recent signature.
4. Run the reclaimer's sweep logic (or replicate `isOldEnough`) and confirm `age >= minAge` never becomes true, so the PDA is perpetually skipped and its rent is never reclaimed.

// isOldEnough reports whether the most recent tx touching addr is at least
// minAge old. For StoredIxData PDAs, that's effectively the PDA's age (they
// only ever see one tx — their creating store_execute_ix_data).
func (r *RentReclaimer) isOldEnough(ctx context.Context, addr solana.PublicKey) (bool, error) {
	limit := signatureAgeProbeLimit
	var sigs []*rpc.TransactionSignature
	err := r.builder.rpcClient.executeWithFailover(ctx, "get_signatures_for_address", func(client *rpc.Client) error {
		resp, innerErr := client.GetSignaturesForAddressWithOpts(ctx, addr, &rpc.GetSignaturesForAddressOpts{
			Limit: &limit,
		})
		if innerErr != nil {
			return innerErr
		}
		sigs = resp
		return nil
	})
	if err != nil || len(sigs) == 0 {
		return false, err
	}
	if sigs[0].BlockTime == nil {
		return false, nil
	}
	age := time.Since(time.Unix(int64(*sigs[0].BlockTime), 0))
	return age >= r.minAge, nil
}
