### Title
Spot-Price Uniswap V3 Quote (No TWAP) Used To Bound Gas-Top-Up And Refund Swaps In `ExecuteInboundGas`/`applyGasRefund` — ([File: x/uexecutor/keeper/execute_inbound_gas.go])

### Summary
`GetSwapQuote` in `x/uexecutor/keeper/evm.go` calls `QuoterV2.quoteExactInputSingle` — a single-block, spot-price simulation against the live Uniswap V3 pool — with no TWAP protection. This quote is used verbatim (× 95%) to compute `minPCOut`, the slippage floor for module-originated PRC20→WPC swaps executed during inbound gas top-ups (`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`) and outbound gas refunds (`applyGasRefund`/`getSwapQuoteForRefund`). Because the reference price and the actual swap execution both read from the same manipulable pool state within the same transaction/block, an attacker can distort the pool price immediately before the module's `DerivedEVMCall`-based swap executes, extracting value from the pool/protocol — the same bug class as the Malt `AuctionEscapeHatch` spot-price finding.

### Finding Description
`GetSwapQuote` ( [1](#0-0) ) queries `QuoterV2.quoteExactInputSingle`, which is a real-time simulation of a swap against the current V3 pool tick/liquidity state (a spot quote), not a time-weighted average. No `observe()`/TWAP call or cardinality configuration exists anywhere in the codebase.

This spot quote is consumed directly in three fund-moving flows:
1. `ExecuteInboundGas` — for a `TxType_GAS` inbound, the module fetches a quote for the *user-controlled* `amount` and swaps PRC20→WPC, crediting the user's UEA with the swap output, bounded only by `minPCOut = quote * 95/100`: [2](#0-1) 
2. `gasAndPayloadDepositAutoSwap` — identical pattern for `GAS_AND_PAYLOAD` inbounds: [3](#0-2) 
3. `applyGasRefund` / `getSwapQuoteForRefund` — on outbound finalization, excess gas fee (`gasFee - gasFeeUsed`) is swapped gasToken→WPC and refunded to the sender using the same spot-quote-derived `minPCOut`: [4](#0-3) , [5](#0-4) 

The 5% slippage band does not protect the protocol from manipulation because the *quote itself* — not just the execution — is read from the same pool at essentially the same point in time. If an attacker inflates the PRC20/WPC pool price (e.g., via a large swap in the same block, immediately before their `MsgVoteInbound`-triggered finalization or an outbound-vote finalization executes `ExecuteInboundGas`/`applyGasRefund`), the quote and the subsequent swap both execute against the manipulated pool, so `minPCOut` simply ratchets up alongside the manipulated price rather than constraining it. The attacker then reverses their manipulation (e.g., closes/repays a flash loan or opposite-direction swap) after the module's swap lands, netting an arbitrage profit funded by whatever WPC/PRC20 liquidity the protocol/pool holds. This mirrors the Malt report exactly: a protocol-internal fund-quantity calculation is derived from a manipulable AMM spot price rather than a TWAP, and the manipulated value is then used to move real value (WPC/PC native, or gas-refund PRC20) out of the protocol to an attacker-controlled account (their own UEA, or the `refundRecipient` they control via `RevertInstructions.FundRecipient`).

This confirms directly in the upgrade changelog that this exact spot-quote pattern was deliberately introduced without TWAP protection: [6](#0-5) 

### Impact Explanation
An unprivileged external attacker who can influence the PRC20/WPC Uniswap V3 pool price (via any swap, flash loan, or large trade) around the moment a validator-finalized `MsgVoteInbound`/`MsgVoteOutbound` executes the corresponding gas-swap logic can cause the module to swap PRC20 for an inflated amount of WPC (or vice versa for refunds), extracting protocol/pool-held value. This falls squarely within the in-scope impact "unauthorized module-originated EVM execution" leading to fund extraction/drain via the universal execution flow (`DerivedEVMCall`-driven `CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`). Because the value credited comes from a manipulated swap rather than a legitimate deposit-backed amount, this corrupts PRC20/native accounting and can permanently drain pool liquidity/protocol funds.

### Likelihood Explanation
Exploitation requires an attacker to control or influence pool state at the moment the module's swap executes. This is feasible without any privileged role: the attacker only needs to submit ordinary swap transactions (potentially backed by a flash loan available on Push Chain's EVM) timed to land in the same block as the inbound/outbound finalization that triggers `ExecuteInboundGas`/`applyGasRefund`. The protocol explicitly acknowledges reliance on this spot quote (see the upgrade note), and no TWAP, cooldown, or price-deviation circuit breaker exists anywhere in the reviewed code, making this a realistic, unprivileged, and repeatable attack vector rather than a purely theoretical one.

### Recommendation
Replace the single-call `QuoterV2.quoteExactInputSingle` spot quote with a TWAP-based reference price (e.g., using the pool's `observe()` over a sufficiently long window) for computing `minPCOut`, or bound the acceptable price deviation between a TWAP reference and the spot quote before allowing the swap to proceed. Alternatively, cap swap sizes and add circuit breakers keyed off external chain-meta/oracle price data (already tracked via `ChainMeta`) so `minPCOut` cannot be derived solely from an easily-manipulated same-block spot price.

### Proof of Concept
Conceptual (cannot be executed without a live devnet + funded pool, so this is a design-level PoC rather than an executed exploit):
1. Attacker funds a UEA and initiates a `TxType_GAS` inbound with a chosen `amount` of an external asset that maps to a PRC20 with a WPC-paired Uniswap V3 pool.
2. In the same or an immediately preceding block, attacker (using a flash loan if pool liquidity is otherwise too deep) executes a large swap into the PRC20/WPC pool to skew the pool price in the direction that inflates the PRC20→WPC exchange rate.
3. When validators finalize the attacker's inbound (`MsgVoteInbound` quorum reached), `ExecuteInboundGas` calls `GetSwapQuote` against the now-skewed pool [7](#0-6) , computes `minPCOut` from that inflated quote [8](#0-7) , and executes `CallPRC20DepositAutoSwap`, crediting the attacker's UEA with an inflated amount of WPC drawn from the pool/protocol.
4. Attacker reverses the initial swap (or repays the flash loan) to restore the pool price, retaining the excess WPC as profit — value that ultimately came from the protocol's swap/liquidity, not from the attacker's own deposited funds.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}

// getSwapQuoteForRefund fetches a Uniswap quote for the gas token refund swap.
func (k Keeper) getSwapQuoteForRefund(ctx sdk.Context, gasToken common.Address, fee *big.Int, amount *big.Int) (*big.Int, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(ctx)
	if err != nil {
		return nil, err
	}
	wpcAddr, err := k.GetUniversalCoreWPCAddress(ctx)
	if err != nil {
		return nil, err
	}
	return k.GetSwapQuote(ctx, quoterAddr, gasToken, wpcAddr, fee, amount)
}
