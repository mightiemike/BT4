### Title
Missing declared-class existence check in Starknet OS `execute_replace_class` allows honest-node state divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The blockifier's Rust execution of the `replace_class` syscall validates that the target class hash is declared and is a Cairo1 (V1) class before rewriting the contract's class hash (`self.state.get_compiled_class(class_hash)?`, then `is_cairo1` check) in `crates/blockifier/src/execution/syscalls/syscall_base.rs` (`replace_class`, lines 369-378). The Starknet OS Cairo re-execution of the same syscall, `execute_replace_class` in `crates/apollo_starknet_os_program/.../execution/syscall_impls.cairo` (lines 881-920), has no equivalent check at all — it contains an explicit unresolved `TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` right before unconditionally writing the new `class_hash` into `contract_state_changes` via `dict_update`. ### Finding Description
This is directly analogous to the reported CVE's bug class: "the lack of validating the existence of an object prior to performing operations on the object." In the CVE, MariaDB's CONNECT engine operates on an object without checking it still/actually exists, leading to a use-after-free and privilege escalation. Here, the Starknet OS's `execute_replace_class` operates on a `class_hash` supplied by contract code (originating from an arbitrary transaction) without verifying the class corresponding to that hash was ever declared, unlike the blockifier's own execution path which enforces this via `get_compiled_class`.

Any account or contract can trigger the `replace_class` syscall (Cairo0 via `deprecated_execute_syscalls.cairo`'s `execute_replace_class`, lines 307-329, and Cairo1 via `syscall_impls.cairo`'s `execute_replace_class`) with an arbitrary, potentially undeclared or non-existent `class_hash`. The blockifier (the actual sequencer execution engine) rejects such a transaction because `get_compiled_class` fails for undeclared classes (as demonstrated by the test `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs` `undeclared_class_hash`, lines 17-29, which asserts an error "is not declared"). However, the Starknet OS — which re-executes the block during proving to derive the committed state root — does not perform this check, and would happily write the same undeclared class hash into `contract_state_changes` without objection.

This creates a semantic divergence between the blockifier (which the sequencer trusts to build/execute blocks and to enforce declared-class invariants) and the Starknet OS's Cairo re-execution (used to construct/verify the final state commitment). If some contract code path reaches `execute_replace_class` with a class hash that the blockifier permits (or under any control flow where OS-side validation is expected to catch a case the Rust-side doesn't), or if this indicates the OS's read of the class hash is under-constrained relative to what the blockifier itself computed, the OS can commit a state that a class hash was written to a contract's state entry with no corresponding declared-class hint validation, potentially corrupting the derived state root or diverging from the honest blockifier-computed state diff. ### Impact Explanation
If the Starknet OS's state transition (used to prove/commit the block) can accept a `class_hash` write for `replace_class` that the blockifier itself would reject (or that is otherwise not properly constrained by hints matching the declared classes trie), the committed root produced by the prover could diverge from the state that the blockifier/sequencer actually executed and believes is canonical. This falls under "wrong committed root or block hash" / "honest-node divergence," which is explicitly in-scope for Medium-or-higher findings per the rules. A divergence at the OS layer directly threatens the correctness of state commitments that L1 ultimately accepts as final.

### Likelihood Explanation
The `replace_class` syscall is reachable by any deployed contract from a single ordinary invoke transaction; no special privileges are needed — it is one of the most basic Cairo syscalls (`replace_class_syscall`). The missing check is explicitly marked with a `TODO` comment in the source, confirming it is an acknowledged, unimplemented gap in the OS Cairo code, not defense-in-depth intentionally omitted elsewhere. However, I could not fully verify from the indexed code and tests whether some other constraint elsewhere in the OS pipeline (e.g., a global check on `contract_class_changes` dict consistency, or a downstream hint that cross-checks all written class hashes against declared classes) closes this gap indirectly. The declared classes dict update in `deprecated_execute_syscalls.cairo`'s deploy path does explicitly enforce `prev_value=0` checks for new declarations, but `execute_replace_class` never touches `contract_class_changes`, only `contract_state_changes`, so no such analogous cross-check appears to be present for replace_class specifically based on what was found.

### Recommendation
Add an explicit check in the OS's `execute_replace_class` (both `syscall_impls.cairo` for Cairo1 and `deprecated_execute_syscalls.cairo` for Cairo0) to validate that the target `class_hash` is present in the declared classes dictionary/trie (mirroring the Cairo1 class check the blockifier performs via `get_compiled_class` returning a Cairo1 class) before writing the new `StateEntry` for the contract, resolving the outstanding `TODO(Yoni, 1/1/2026)`. This should be a hard failure (assertion) analogous to how declared-class prev_value=0 checks are enforced in `dict_update` calls elsewhere.

### Proof of Concept
Conceptually:
1. Deploy or use any contract exposing a `replace_class` call (e.g., `test_replace_class` in `blockifier_test_utils/resources/feature_contracts/cairo1` style feature contracts).
2. Invoke it with an arbitrary, undeclared `class_hash` (e.g., a hash for a class that was never declared on-chain, or one that does not correspond to any compiled class known to the OS at prove time).
3. In the blockifier execution path, this transaction reverts/fails per `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash` (expects `"is not declared"`).
4. If any path allows this call to reach OS re-execution unguarded (e.g., a discrepancy between what the blockifier computed as state diff and what hints feed into the OS, or a future code path bypassing blockifier-side validation), `execute_replace_class` in the Cairo OS program would accept the write unconditionally since it lacks the analogous check, per the code at lines 900-920 of `syscall_impls.cairo`.

I was not able to fully trace whether the OS pipeline has an out-of-band mechanism (outside the indexed portion of the repo) that prevents undeclared class hashes from ever reaching `execute_replace_class` during normal (honest sequencer) block re-execution — the finding rests on the explicit code-level gap and matching `TODO` comment rather than a demonstrated end-to-end exploit trace, since I don't have execution/tracing tools available to run the OS program directly.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
