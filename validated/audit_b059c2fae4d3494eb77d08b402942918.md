## Analysis

The reported bug class is: a min-output/threshold check deep in a deposit/stake helper can revert (or here, silently fail) even though the amount was legitimately computed/passed by the protocol itself, causing funds tied to that deposit to be lost with no visible error to the depositor. The closest reachable analog in Push Chain's scoped `x/uexecutor` code is the interaction between the Uniswap-V3-based auto-swap deposit path (`GetSwapQuote` / `CallPRC20DepositAutoSwap`) and the `isCEA` inbound branch, which — unlike the non-`isCEA` branches — intentionally skips creating any `INBOUND_REVERT` refund outbound on failure.

### Title
Silent, unrecoverable loss of bridged funds when auto-swap deposit fails on `isCEA` inbounds (GAS / GAS_AND_PAYLOAD / FUNDS_AND_PAYLOAD) - (File: `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
For `isCEA` inbounds, `ExecuteInboundGasAndPayload` (and the analogous `ExecuteInboundFundsAndPayload`) deposit PRC20 with auto-swap via `k.gasAndPayloadDepositAutoSwap` → `CallPRC20DepositAutoSwap`, which relies on a live Uniswap V3 `QuoterV2.quoteExactInputSingle` call and a derived `minPCOut` [1](#0-0) . If this call fails (quoter revert for the given amount/fee tier/pool state, insufficient liquidity, or slippage exceeding the computed `minPCOut`), the code sets `execErr` but explicitly takes the `isCEA` branch that "never creates an `INBOUND_REVERT` outbound" and simply records a `FAILED` PCTx before returning [2](#0-1) .

### Finding Description
For non-`isCEA` inbounds, deposit/auto-swap failures set `shouldRevert = true`, and `buildRevertOutbound` + `attachOutboundsToUtx` create an `INBOUND_REVERT` outbound so bridged value is eventually returned to the sender [3](#0-2) . However, for `isCEA` inbounds this refund path is explicitly bypassed by design — a comment states "isCEA failures never create an INBOUND_REVERT outbound," repeated identically in `execute_inbound_funds.go`, `execute_inbound_funds_and_payload.go`, `execute_inbound_gas_and_payload.go`, and `handle_failed_inbound_validation.go` [4](#0-3) .

Since ballot finalization for the inbound has already occurred by the time `ExecuteInboundGasAndPayload` runs (the UTX is canonical, quorum reached), the underlying value the user already locked/sent on the source chain cannot be un-observed. If the deposit-with-auto-swap EVM call reverts (e.g., because the Uniswap quoter reverts for a given `amountIn`/fee-tier/pool combination, or the pool cannot satisfy the just-computed `minPCOut` due to slippage between quote and execution), the entire `depositPRC20WithAutoSwap` call reverts atomically — no PRC20 is minted anywhere — and because it's `isCEA`, no outbound revert/refund is ever created. The UTX is left as a `FAILED` PCTx permanently, with the user's bridged value neither minted on Push Chain nor refunded on the source chain.

This mirrors the RsETH bug class precisely: a threshold/AMM-derived check deep in the deposit path (`minAmountToDeposit` there, `minPCOut`/quoter viability here) determines success/failure of a deposit amount that is not directly user-chosen in a way the user can predict, and failure produces silent, unexplained fund loss instead of a safe fallback.

### Impact Explanation
This falls under "permanent loss / permanent freezing of user-controlled funds" in the allowed impact set: an ordinary external user triggering a `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` `isCEA` inbound whose deposit amount and current pool/quoter state combine to make the auto-swap fail loses the bridged value entirely, with the protocol recording only a `FAILED` PcTx and no compensating outbound.

### Likelihood Explanation
Reachable by any unprivileged relayer/validator quorum simply observing and voting a real inbound event with `IsCEA=true`; no privileged action is required. The precise trigger conditions (quoter revert / slippage breach for a specific `amountIn` against live pool state) are probabilistic/AMM-state-dependent rather than deterministically attacker-chosen, which lowers exploitability somewhat, but it is a legitimate, reachable path with unprivileged input for both `GAS_AND_PAYLOAD` (`execute_inbound_gas_and_payload.go`) and `FUNDS_AND_PAYLOAD` (`execute_inbound_funds_and_payload.go`) `isCEA` inbounds.

### Recommendation
For `isCEA` deposit-with-autoswap failures, either (a) fall back to a plain (non-swap) `CallPRC20Deposit` of the raw PRC20 asset when the auto-swap leg fails, mirroring the existing gas-refund fallback pattern already used in `applyGasRefund` (`x/uexecutor/keeper/outbound.go:213-256`), or (b) still create an `INBOUND_REVERT` outbound for `isCEA` deposit-stage failures (as opposed to payload-execution failures, which can legitimately remain non-reverting since the deposit already succeeded by that point).

### Proof of Concept
1. Craft/observe a source-chain event with `TxType_GAS_AND_PAYLOAD`, `IsCEA=true`, and an `Amount` such that, at the time of execution, `QuoterV2.quoteExactInputSingle` for the configured fee tier reverts (e.g., amount below the pool's practical swap floor) or the computed `minPCOut` cannot be met due to pool-state drift between quote time and swap time.
2. Have the required quorum of validators vote the inbound to finalization, as in `TestInboundCEAGasAndPayload` [5](#0-4) .
3. Observe `ExecuteInboundGasAndPayload` take the `isCEA` branch, call `gasAndPayloadDepositAutoSwap`, receive `execErr != nil`, and reach the isCEA-failure branch that records `FAILED` PCTx and returns without any outbound [2](#0-1) .
4. Confirm the resulting `UniversalTx` has a `FAILED` PcTx and an empty `OutboundTx` list, i.e., no refund path exists for the already-finalized bridged value.

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
