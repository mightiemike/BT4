### Title
pprof debug/profiling endpoints exposed to any authenticated user regardless of role, enabling process memory disclosure - ([File: core/web/router.go])

### Summary
`metricRoutes(authv2)` registers all `net/http/pprof` handlers (`/v2/debug/pprof/heap`, `/goroutine`, `/profile`, `/trace`, `/cmdline`, etc.) directly under the `authv2` route group without wrapping any of them in `auth.RequiresAdminRole` or `auth.RequiresEditRole`. Since `authv2` only requires `auth.AuthenticateByToken` or `auth.AuthenticateBySession` with no role check, any authenticated user — including one with only `UserRoleView` — can reach these routes and dump full process memory/goroutine stacks.

### Finding Description
In `v2Routes`, the `authv2` group is created with only authentication (any valid role) via: [1](#0-0) 

Every other sensitive route in this block is explicitly wrapped with `auth.RequiresAdminRole`, `auth.RequiresEditRole`, or `auth.RequiresRunRole` (e.g. key export/import, user management, transfers). However, at the end of the block: [2](#0-1) 

`metricRoutes` registers the raw `net/http/pprof` handlers with no role wrapper at all: [3](#0-2) 

The role-checking middlewares (`RequiresRunRole`, `RequiresEditRole`, `RequiresAdminRole`) explicitly check `user.Role` pulled from the authenticated context, and only block `UserRoleView` (or lower) when applied: [4](#0-3) 

Since none of these wrappers are applied to the pprof routes, a request that successfully authenticates via `AuthenticateByToken` with a `UserRoleView` token passes straight through to `pprof.Handler("heap")`/`pprof.Handler("goroutine")`/`pprof.Profile`/`pprof.Trace`, etc. `pprof.Trace` and `pprof.Profile` can also be used to force a CPU trace/profile of arbitrary duration, and `pprof.Cmdline` reveals process command-line arguments (potentially containing secrets passed via flags).

Heap and goroutine profiles from a running Chainlink node's Go process can contain in-memory secret material — decrypted private keys, session tokens, DKG/vault key shares — since the application decrypts and holds this key material in memory during normal operation.

### Impact Explanation
A low-privilege, view-only authenticated user can extract raw process memory (heap dump) and full goroutine stack traces from the Chainlink node process via `GET /v2/debug/pprof/heap` and `GET /v2/debug/pprof/goroutine`. This is an information-disclosure vector matching Chainlink's bounty impact category of "secret disclosure" for in-memory key material, and additionally allows profiling/DoS-adjacent actions (`/profile`, `/trace` block for the requested duration) without requiring elevated privileges.

### Likelihood Explanation
Preconditions are minimal: the attacker only needs any valid API token or session with `UserRoleView`, which is the lowest privilege role explicitly designed for read-only, unprivileged access. The `authv2` group's authentication check succeeds for any valid credential regardless of role, and no role-gating exists on the pprof sub-routes at all, making this trivially and repeatably reachable.

### Recommendation
Wrap all routes registered by `metricRoutes` (and the `/debug/vars` route in `debugRoutes` if similarly sensitive) with `auth.RequiresAdminRole`, consistent with how other sensitive/administrative operations in `v2Routes` (key export/import, user management) are protected. For example:
```go
pprofGroup.GET("/heap", auth.RequiresAdminRole(ginHandlerFromHTTP(pprof.Handler("heap").ServeHTTP)))
```
applied to every handler registered in `metricRoutes`.

### Proof of Concept
Integration test plan (using the existing web test harness, e.g. `core/web/router_test.go` or similar):
1. Set up a test app with three users: `UserRoleView`, `UserRoleEdit`/`Run`, and `UserRoleAdmin`, each with a valid API token generated via the existing token-issuing flow.
2. `GET /v2/debug/pprof/heap` with the `UserRoleView` token headers (`X-API-KEY`/`X-API-SECRET`) — assert response status is currently `200` (proving the vulnerability) instead of the expected `403 Forbidden`.
3. Repeat for `GET /v2/debug/pprof/goroutine`, `/v2/debug/pprof/profile?seconds=1`, `/v2/debug/pprof/cmdline`.
4. After applying the fix (wrapping handlers with `auth.RequiresAdminRole`), re-run the same requests and assert `403` for `UserRoleView`/`UserRoleEdit` tokens and `200` for `UserRoleAdmin` tokens.
5. Optional deeper validation: parse the heap profile dump (`GET /v2/debug/pprof/heap?debug=1`) and grep for known key-material markers (e.g. hex-encoded private key patterns) to demonstrate concrete secret exposure risk.

// RequiresRunRole extracts the user object from the context, and asserts the user's role is at least
// 'run'
func RequiresRunRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresEditRole extracts the user object from the context, and asserts the user's role is at least
// 'edit'
func RequiresEditRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role == clsessions.UserRoleView || user.Role == clsessions.UserRoleRun {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("Unauthorized"))
			return
		}
		handler(c)
	}
}

// RequiresAdminRole extracts the user object from the context, and asserts the user's role is 'admin'
func RequiresAdminRole(handler func(*gin.Context)) func(*gin.Context) {
	return func(c *gin.Context) {
		user, ok := GetAuthenticatedUser(c)
		if !ok {
			c.Abort()
			jsonAPIError(c, http.StatusUnauthorized, errors.New("not a valid session"))
			return
		}
		if user.Role != clsessions.UserRoleAdmin {
			c.Abort()
			addForbiddenErrorHeaders(c, "admin", string(user.Role), user.Email)
			jsonAPIError(c, http.StatusForbidden, errors.New("Forbidden"))
			return
		}
		handler(c)
	}
