### Title
Unauthenticated LOOP plugin discovery/metrics/pprof routes bypass session/API-key auth - ([File: core/web/router.go])

### Summary
`loopRoutes` registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` directly on the base `api` router group with no authentication middleware, unlike every other admin/debug surface in the router (e.g. `/v2/*` under `authv2`, `/v2/debug/pprof/*` under `metricRoutes(authv2)`, and `/debug/vars` under `debugRoutes`). Any unauthenticated network client that can reach the node's HTTP port can enumerate registered LOOP plugins, pull plugin Prometheus metrics, and trigger/forward pprof profiling and symbol requests to internal plugin processes.

### Finding Description
`NewRouter` builds a base `api` group with only rate limiting and cookie-session middleware (no auth check): [1](#0-0) . Compare this to `v2Routes`, where every admin endpoint is explicitly wrapped in `authv2 := r.Group("/v2", auth.Authenticate(..., auth.AuthenticateByToken, auth.AuthenticateBySession))` before routes are attached [2](#0-1) , and even the standard `pprof` debug routes are deliberately gated behind that same authenticated group via `metricRoutes(authv2)` with the comment "Debug routes accessible via authentication" [3](#0-2) .

`loopRoutes`, however, registers its handlers directly on the passed-in group with no `auth.Authenticate(...)` wrapper at all: [4](#0-3) . Since it is called as `loopRoutes(app, api)` on the unauthenticated base group [5](#0-4) , none of its four routes require a session or API token.

The handlers themselves perform privileged/internal actions:
- `discoveryHandler` enumerates all registered LOOP plugins from `l.registry.List()` and returns their internal metrics endpoints [6](#0-5) .
- `pluginMetricHandler` forwards a request to `http://<loopHostName>:<PrometheusPort>/metrics` for any plugin name that exists in the registry [7](#0-6) .
- `pluginPPROFHandler` / `pluginPPROFPOSTSymbolHandler` forward arbitrary `net/http/pprof` sub-paths (`profile`, `trace`, `heap`, `symbol`, etc.) with attacker-controlled query parameters (`debug`, `gc`, `seconds`) to the internal plugin process [8](#0-7) .

No `auth.Authenticate`, `AuthenticateByToken`, or `AuthenticateBySession` check gates any of these four routes, unlike every comparable admin/debug endpoint in the router.

### Impact Explanation
An unprivileged network attacker who can reach the node's web server (the same reachability assumption as hitting `/v2/keys` or `/health`) can:
1. Enumerate all running LOOP plugins and their internal metrics endpoints via `/discovery` (information disclosure of internal topology).
2. Pull raw Prometheus metrics from internal plugin processes via `/plugins/:name/metrics` without credentials (information disclosure).
3. Trigger CPU/heap/goroutine profiling and long-blocking `pprof.Profile`/`pprof.Trace` calls (with attacker-controlled `seconds` up to node-imposed timeouts) against internal plugin processes via `/plugins/:name/debug/pprof/*`, causing resource exhaustion / denial of service on the LOOP plugin process, and potentially leaking sensitive data captured in heap/goroutine dumps (e.g., secrets or key material resident in plugin memory).

This is an authentication-bypass class finding: a privileged/internal-forwarding surface that should require the same session/API-key auth as other admin routes is fully reachable by an anonymous caller.

### Likelihood Explanation
Fully feasible and repeatable: no credentials, cookies, or tokens are needed. Any client with network access to the node's HTTP listener (the same precondition needed to reach `/v2/keys` or the UI) can immediately issue `GET /discovery`, `GET /plugins/<name>/metrics`, and `GET/POST /plugins/<name>/debug/pprof/...` and receive a response, as confirmed by tracing the route table above — there is no middleware in the call chain that performs an auth check for these four routes.

### Recommendation
Wrap `loopRoutes` in the same authenticated group used for other admin/debug endpoints, e.g. call it with `authv2`/a dedicated `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)`-wrapped group instead of the raw `api` group in `NewRouter`, mirroring how `metricRoutes(authv2)` gates the standard pprof endpoints. At minimum, apply `auth.RequiresAdminRole` (or equivalent) to `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol`.

### Proof of Concept
Integration test plan (Go, using `httptest` + the app's `NewRouter`):
1. Build the router via `web.NewRouter(app, nil)` with a test `chainlink.Application` that has at least one registered LOOP plugin in `app.GetLoopRegistry()`.
2. Issue `httptest` requests with no `Authorization` header and no session cookie:
   - `GET /discovery` → assert `http.StatusOK` (currently succeeds; expected after fix: `401`).
   - `GET /plugins/<registered-name>/metrics` → assert response body contains forwarded metrics (currently succeeds; expected after fix: `401`).
   - `GET /plugins/<registered-name>/debug/pprof/goroutine` and `POST /plugins/<registered-name>/debug/pprof/symbol` → assert forwarded response (currently succeeds; expected after fix: `401`).
3. Compare against a control request to `GET /v2/keys/eth` with no auth, which is expected (and currently) returns `401 Unauthorized` due to `authv2`'s `auth.Authenticate` middleware.
4. Assert equality of behavior: the loop-registry routes must return the same `401`/redirect behavior as `/v2/keys/eth` for unauthenticated requests; fail the test if `/discovery`, `/plugins/:name/metrics`, or `/plugins/:name/debug/pprof/*` return `200` while `/v2/keys/eth` returns `401` for the identical (no-credential) request.

// discoveryHandler implements service discovery of prom endpoints for LOOPs in the registry
func (l *LoopRegistryServer) discoveryHandler(w http.ResponseWriter, req *http.Request) {
	w.Header().Set("Content-Type", "application/json")
	groups := make([]*targetgroup.Group, 0, 1+len(l.registry.List()))

	// add node metrics to service discovery
	groups = append(groups, pluginGroup(l.discoveryHostName, l.exposedPromPort, "/metrics"))

	// add all the plugins
	for _, registeredPlugin := range l.registry.List() {
		group := pluginGroup(l.discoveryHostName, l.exposedPromPort, pluginMetricPath(registeredPlugin.Name))
		group.Labels[LabelMetaPluginName] = model.LabelValue(registeredPlugin.Name)
		groups = append(groups, group)
	}

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), "GET", pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}

func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
