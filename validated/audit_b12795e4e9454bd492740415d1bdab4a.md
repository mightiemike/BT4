### Title
Unbounded gzip decompression of user-supplied deprecated (Cairo0) contract program enables memory-exhaustion DoS via `estimateFee` / `simulateTransactions` RPC — (`File: crates/apollo_rpc/src/v0_8/api/mod.rs`)

### Summary
The JSON-RPC handlers `starknet_estimateFee` and `starknet_simulateTransactions` accept `BroadcastedTransaction::Declare` payloads containing a deprecated (Cairo0) contract class whose `program` field is base64+gzip compressed. Converting this payload into an executable transaction calls `decompress_program`, which decompresses the gzip stream with `GzDecoder::read_to_end` and **no size or time limit**, unlike every other decompression path in this codebase.

### Finding Description
`decompress_program` performs unbounded decompression: [1](#0-0) 

This is reached from `user_deprecated_contract_class_to_sn_api`, which is invoked while converting a user-submitted `BroadcastedTransaction` into an `ExecutableTransactionInput` for `estimate_fee`/`simulate_transactions`: [2](#0-1) [3](#0-2) [4](#0-3) 

By contrast, every other place in the repo that decompresses a similarly untrusted, user-controlled payload enforces a hard cap:
- The gateway ingestion path for declared Sierra programs uses `decode_and_decompress_with_size_limit`, bounded by a configured `max_size`: [5](#0-4) 
- The shared compression utility enforces `SizeLimitExceeded` by capping the reader with `.take(max_size + 1)`: [6](#0-5) 
- Storage-level zstd decompression is bounded by `MAX_DECOMPRESSED_SIZE` (256 MB): [7](#0-6) 
- The HTTP server even has explicit tests validating decompressed-size limits are enforced against zip-bomb style payloads: [8](#0-7) 

`decompress_program` is the one outlier still carrying a `// TODO(dan): add time and size limits.` comment, meaning a small compressed payload (a classic gzip/zip bomb) can expand to an arbitrarily large in-memory buffer before any check is applied.

### Impact Explanation
An unauthenticated caller of the public JSON-RPC API can submit an `estimateFee` or `simulateTransactions` request containing a deprecated declare transaction with a maliciously crafted gzip bomb as `compressed_program`. The node will attempt to fully decompress this into memory with no bound, which can exhaust available memory on the process serving these RPC calls, causing it to crash or become unresponsive (classic CWE-400/CWE-409 memory-exhaustion DoS, matching the reported `websockets` CVE-2018-1000518 bug class). This is a resource-exhaustion/availability issue against a node's RPC-serving process rather than a consensus-safety or fund-loss issue.

### Likelihood Explanation
High from a reachability standpoint — no authentication, no fees, and no prior state are required; a single crafted JSON-RPC call triggers the unbounded decompression, and the vulnerable code path is explicitly flagged by its own author as missing the limit (`TODO(dan)`).

### Recommendation
Apply the same bounded-decompression pattern already used elsewhere in the codebase (e.g., `decompress_with_size_limit` / `MAX_DECOMPRESSED_SIZE`) to `decompress_program` in `crates/apollo_rpc/src/v0_8/api/mod.rs`: wrap the `GzDecoder` reader with a `.take(max_size + 1)` limit and reject the request if the decompressed size exceeds the configured maximum, mirroring `starknet_api::compression_utils::decompress_with_size_limit`.

### Proof of Concept
1. Craft a small gzip stream that decompresses to a very large buffer (e.g., gigabytes of repeated zero bytes — a standard "gzip bomb"), base64-encode it.
2. Send a `starknet_estimateFee` (or `starknet_simulateTransactions`) JSON-RPC request with a `BroadcastedTransaction::Declare` (deprecated/Cairo0 variant) whose `contract_class.program` field is set to this base64 string.
3. Observe the node's `decompress_program` call (`crates/apollo_rpc/src/v0_8/api/mod.rs:671-682`) fully decompress the payload with `read_to_end` and no size cap, driving memory usage far beyond the compressed payload size and potentially OOM-killing the RPC-serving process.

pub(crate) fn decompress_program(
    base64_compressed_program: &String,
) -> Result<Program, ErrorObjectOwned> {
    base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    let compressed_data =
        base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    // TODO(dan): add time and size limits.
    let mut decoder = GzDecoder::new(compressed_data.as_slice());
    let mut decompressed = Vec::new();
    decoder.read_to_end(&mut decompressed).map_err(internal_server_error)?;
    serde_json::from_reader(decompressed.as_slice()).map_err(internal_server_error)
}

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}

pub(crate) const MAX_DECOMPRESSED_SIZE: usize = 1 << 28; // 256 MB
// The compression level to use. Higher levels are slower but compress better.
const COMPRESSION_LEVEL: i32 = zstd::DEFAULT_COMPRESSION_LEVEL;

/// Returns the compressed data in a vector.
///
/// # Arguments
/// * data - bytes to compress.
///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.
pub fn compress(data: &[u8]) -> Result<Vec<u8>, std::io::Error> {
    zstd::bulk::compress(data, COMPRESSION_LEVEL)
}

/// Serialized and then compress object.
///
/// # Arguments
/// * object - the object to serialize and compress.
///
/// # Errors
/// Returns [`StorageSerdeError`] if any error is encountered in the serialization or compression.
pub fn serialize_and_compress(object: &impl StorageSerde) -> Result<Vec<u8>, StorageSerdeError> {
    let mut buf = Vec::new();
    object.serialize_into(&mut buf)?;
    Ok(compress(buf.as_slice())?)
}

/// # Arguments

///
/// # Errors
/// Returns [`std::io::Error`] if any read error is encountered.

    zstd::bulk::decompress(data, MAX_DECOMPRESSED_SIZE)

#[tokio::test]
async fn zstd_decompressed_request_too_large() {
    // 10 KB of repeated bytes — compresses to ~50 bytes with zstd.
    let large_body = vec![b'a'; 10 * 1024];
    let mut encoder = zstd::stream::write::Encoder::new(Vec::new(), 0).unwrap();
    encoder.write_all(&large_body).unwrap();
    let compressed_body = encoder.finish().unwrap();

    // Limit between compressed size and decompressed size.
    // compressed_body is ~50 bytes; decompressed is 10240 bytes.
    let max_request_body_size = large_body.len() - 1;
    assert!(compressed_body.len() < max_request_body_size);

    let http_client = HttpClientServerSetupBuilder::new(unique_u16!())
        .with_max_request_body_size(max_request_body_size)
        .build()
        .await;

    let response = http_client.add_rpc_tx_with_zstd(compressed_body).await;

    assert_eq!(response.status(), StatusCode::PAYLOAD_TOO_LARGE);
}
