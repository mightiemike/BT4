### Title
`replay_on_archive` accepts state/hot-state/position-state checkpoint-root divergence as a successful replay — ([File: types/src/transaction/mod.rs])

### Summary
`TransactionOutput::ensure_match_transaction_info` — the function used by `db-tool`'s `replay_on_archive` verifier (and other debugger/CLI paths) to confirm that a locally re-executed transaction matches the authenticated, on-chain-committed `TransactionInfo` — validates status, gas, write-set hash, and event-root hash, but explicitly **does not** validate the state checkpoint hash, hot-state checkpoint hash, or the native-position (`trading-native`) state checkpoint hash against the committed `TransactionInfo`. This means an authenticated Merkle-root field in `TransactionInfo` can silently diverge from the actual re-executed ledger state while the verifier reports success.

### Finding Description
`ensure_match_transaction_info` in [1](#0-0)  checks:
- transaction status vs `txn_info.status()`
- `gas_used()` vs `txn_info.gas_used()`
- `CryptoHash::hash(self.write_set())` vs `txn_info.state_change_hash()`
- event root hash vs `txn_info.event_root_hash()`

but the function ends with an explicit acknowledged gap: [2](#0-1) 
```
// TODO(trading-native): this comparator ignores the checkpoint hashes
// (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
// tooling (e.g. db-tool's `replay_on_archive`) can report a successful
// replay even when the authenticated position state root diverges from
// local execution. Validate the checkpoint hashes here before enabling
// COMPUTE_TRADING_NATIVE_STATE_ROOTS.
```

`TransactionInfo` (V1) carries authenticated Merkle roots for the state checkpoint, hot-state checkpoint, and (when `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled) the native-position state tree — these roots are bound into the transaction accumulator and are the values external verifiers rely on to prove ledger-state correctness at a version. `db-tool`'s `replay_on_archive::execute_and_verify` re-executes transactions and calls exactly this comparator as its sole correctness gate: [3](#0-2) 
```
if let Err(err) = executed_outputs[idx].ensure_match_transaction_info(
    version,
    &expected_txn_infos[idx],
    Some(&expected_writesets[idx]),
    Some(&expected_events[idx]),
) {
    ...
    return Ok(Some(err));
}
```
Because the comparator never inspects `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`, a mismatch between the checkpoint root actually produced by re-execution and the root recorded in the committed `TransactionInfo` (e.g., from a bug in `DoStateCheckpoint::compute_position_checkpoint` at [4](#0-3) , or a divergent code path such as `AptosDB::position_summary_at_commit` at [5](#0-4)  that independently recomputes the same summary through a different algorithm than the execution-derived one used when the feature flag is on) would go completely undetected by `replay_on_archive`.

Within the live execution pipeline itself, checkpoint hashes ARE cross-checked against `known_state_checkpoints`/`known_position_state_checkpoints` inside `DoStateCheckpoint::run` (`get_state_checkpoint_hashes`), so a normal validator/full node executing blocks would catch a divergence. The gap is specific to the standalone, lighter-weight `ensure_match_transaction_info` comparator used by archival replay/verification tooling, which bypasses that cross-check entirely.

### Impact Explanation
This breaks the "authenticated proof-bearing output must stay bound to the correct ledger version/root" invariant for the specific tool whose job is to detect exactly that kind of corruption: replay verification. If a bug (or a targeted, crafted transaction) ever caused the position-state (or state/hot-state) checkpoint root actually computed during commit to diverge from what execution logic would recompute later, `replay_on_archive` — the tool operators and auditors use to confirm archived/backed-up ledger data is correct — would report a clean, successful verification despite the underlying committed root being wrong. This directly matches the "Wrong ... state proof accepted as valid" and "hard-fork-only divergence during ... replay ... verification" categories in scope: it silently defeats the state-integrity detection mechanism itself, rather than corrupting live consensus state, but it removes the safety net designed to catch state root corruption in already-committed/archived ledger data (mainnet backups, snapshots) before it is trusted for restore or audit purposes.

### Likelihood Explanation
This is not attacker-triggerable to forge consensus, but it is a genuine, code-confirmed integrity gap: the codebase's own comment identifies it as a known, currently-live blind spot in `replay_on_archive`, gated only by whether `COMPUTE_TRADING_NATIVE_STATE_ROOTS` / `TRANSACTION_INFO_V1` / `HOTNESS_IN_EPILOGUE` are active (feature flags 122/117/116 in [6](#0-5) ). Even independent of that new subsystem, the same comparator also skips the plain `state_checkpoint_hash`/`hot_state_checkpoint_hash` fields unconditionally today, so any future bug in state-checkpoint root computation (not just the trading-native path) would likewise go unnoticed by this verifier.

### Recommendation
Extend `ensure_match_transaction_info` to also compare `txn_info.state_checkpoint_hash()`, `txn_info.hot_state_checkpoint_hash()` (when present), and `txn_info.position_state_checkpoint_hash()` (when `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled) against the values actually produced by re-execution's state-checkpoint computation, and fail the replay-verify comparison on any mismatch, before `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is enabled on mainnet, as the existing TODO already recommends.

### Proof of Concept
Not directly exploitable as a state-corruption PoC by an unprivileged actor; the finding is a code-level proof that `replay_on_archive`'s verification is incomplete:
1. Enable (or simulate) a divergence between the checkpoint root computed by `DoStateCheckpoint::compute_position_checkpoint` during original execution/commit and the root that would be recomputed by `AptosDB::position_summary_at_commit`'s independent extension logic for the same chunk (two separate code paths compute the same conceptual value, see comment at [7](#0-6) : "Flag on: the summary comes from execution on the chunk; off: compute it here").
2. Run `db-tool replay-on-archive` over the affected version range; observe that `execute_and_verify` only calls `ensure_match_transaction_info`, which never inspects the checkpoint-hash fields, so the tool reports `Ok(None)` (no error) for that transaction despite the state root committed in `TransactionInfo` not matching what would actually be independently recomputed.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())

            .last_inner_checkpoint_index();

        // merklized snapshot may lag).

            parent.map_or_else(|| persisted.base().latest().clone(), |p| p.latest().clone());

            |p| p.last_checkpoint().clone(),

        // Empty chunk: nothing to extend (avoids the `num_txns - 1` underflow).
        if num_txns == 0 {

                parent_last_checkpoint,

                        value_hash,
                        value: None,

    /// Computes the position summary at commit time by extending the in-memory
    /// tip with this chunk's position writes, freezing on the persisted base.
    /// Used only when `COMPUTE_TRADING_NATIVE_STATE_ROOTS` is off (otherwise the
    /// summary comes from execution on the chunk).
    fn position_summary_at_commit(
        &self,
        chunk: &ChunkToCommit,
    ) -> Result<PositionLedgerStateWithSummary> {
        let bundle = self
            .position
            .as_ref()
            .expect("called only when position is present");
        let store = bundle
            .state_store
            .as_ref()
            .expect("called only when state_store is present");
        let persisted_base = bundle
            .persisted
            .as_ref()
            .expect("persisted present when state_store is")
            .get();

        let (mut latest, mut last_checkpoint) = {
            let state = store.current_state();
            let current = state.lock();
            (current.latest().clone(), current.last_checkpoint().clone())
        };

        let chunk_first = chunk.first_version;
        let chunk_last_inclusive = chunk_first + chunk.transaction_outputs.len() as Version - 1;
        let checkpoint_within_chunk = chunk
            .state
            .last_checkpoint()
            .version()
            .filter(|v| (chunk_first..=chunk_last_inclusive).contains(v));

        let mut pending: HashMap<HashValue, PositionSlot> = HashMap::new();
        let extend_on_base = |latest: &PositionStateWithSummary,
                              version: Version,
                              updates: Vec<(HashValue, PositionSlot)>|
         -> Result<PositionStateWithSummary> {
            let proof_reader = PositionProofReader {
                merkle_db: bundle.merkle_db.clone(),
                version: persisted_base.version(),
            };
            latest.extend(version, updates, persisted_base.summary(), &proof_reader)
        };

        for (i, output) in chunk.transaction_outputs.iter().enumerate() {
            let version = chunk_first + i as Version;
            for (key, op) in output.write_set().native_position_iter() {
                let value_hash = op.as_write_op().as_state_value_opt().map(CryptoHash::hash);
                pending.insert(key.hash(), PositionSlot {
                    state_key: key.clone(),
                    value_hash,
                    value: None,
                });
            }
            if Some(version) == checkpoint_within_chunk && !pending.is_empty() {
                let updates: Vec<_> = std::mem::take(&mut pending).into_iter().collect();
                latest = extend_on_base(&latest, version, updates)?;
                last_checkpoint = latest.clone();
            }
        }
        if !pending.is_empty() {
            let updates: Vec<_> = pending.into_iter().collect();
            latest = extend_on_base(&latest, chunk_last_inclusive, updates)?;
        }

        Ok(
            PositionLedgerStateWithSummary::from_latest_and_last_checkpoint(
                latest,
                last_checkpoint,
            ),
        )
    }
