### Title
Starknet OS `execute_replace_class` skips declared-class verification enforced by the blockifier, causing execution divergence and invalid state commitments - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The blockifier's `replace_class` syscall handler requires the target class hash to be a declared class before mutating a contract's class hash, rejecting the call otherwise. The Starknet OS Cairo implementation of the same syscall performs the state mutation unconditionally, with an explicit `TODO` acknowledging the missing check. Any unprivileged contract invoking `replace_class` with an undeclared class hash will be reverted by the sequencer's actual execution engine but accepted by the OS's re-execution, producing two different state diffs for the same transaction.

### Finding Description
In the blockifier, `replace_class` explicitly verifies the class is declared before mutating state: [1](#0-0) 
This is enforced identically for the native/Cairo1 syscall handler path via `self.base.replace_class(...)`, and is tested/asserted as producing an `"is not declared"` error: [2](#0-1) [3](#0-2) 

In contrast, the Starknet OS's Cairo re-implementation of the same syscall performs the `contract_state_changes` dict mutation (i.e. sets the contract's class hash) unconditionally, with the check explicitly left as an unimplemented TODO: [4](#0-3) 
The deprecated (Cairo0) syscall path in the OS has the identical omission: [5](#0-4) 

A grep across all `.cairo` sources for `get_compiled_class`, `UndeclaredClassHash`, or `"is not declared"` returns zero matches, confirming there is no equivalent check performed anywhere else in the OS pipeline (`os.cairo`, `state.cairo`, `execute_entry_point.cairo`, etc.) that would compensate for this gap.

This exactly mirrors the reported bug class: a state-mutating action (reassigning a contract's class, analogous to reassigning work packages) is performed before/without the permission/validity check (verifying the class was legitimately declared) that gates the same action in the authoritative execution path (blockifier).

### Impact Explanation
The blockifier is the execution engine that actually determines the sequencer's committed block state and state diff. The Starknet OS Cairo program is the re-execution engine used to generate the STARK proof attesting that the committed state transition is correct (`Starknet OS re-execution` is explicitly in scope per the rules). Any account contract that calls `replace_class(undeclared_class_hash)`:
- In the blockifier: the syscall fails with `UndeclaredClassHash`, causing the enclosing transaction to revert (class hash unchanged, though fee is still charged/nonce incremented, per standard revert semantics).
- In the OS: the syscall succeeds unconditionally, applying the class-hash mutation to `contract_state_changes` with no failure to trigger a revert.

This produces two conflicting state diffs for the identical transaction. Since the OS's execution trace and its own computed state root must correspond with the block committed by the sequencer, this divergence causes either: (a) the STARK proof generation/verification to fail for a validly-produced block (network unable to finalize/confirm blocks containing such a transaction), or (b) if the OS's independently-derived state is ever treated as authoritative for proving/committing state (per the intended purpose of the OS: proving the state transition), a wrong committed root results, in which a contract's class hash was changed via an undeclared class hash — an outcome that should never be reachable by any unprivileged sender, matching "unauthorized account action" / "wrong committed root" impact categories.

### Likelihood Explanation
This is trivially reachable by any user: deploy or reuse any contract that invokes the `replace_class` syscall (e.g. via a Cairo0 or Cairo1 contract exposing this capability) and call it with a class hash that has never been declared on-chain. No privileged access, governance, or special preconditions are required — only a standard `INVOKE` transaction from any account.

### Recommendation
Implement the equivalent declared-class check in the Starknet OS's `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo`) matching the blockifier's behavior in `hint_processor.rs`: before performing the `dict_update` on `contract_state_changes`, verify (via a hint reading the class manager/committed classes, mirroring `get_compiled_class`) that the requested `class_hash` corresponds to a declared class, and fail/propagate an error consistent with the blockifier's revert behavior if it does not. This should be prioritized ahead of the `TODO(Yoni, 1/1/2026)` deadline given it is a direct sequencer/OS state-divergence bug.

### Proof of Concept
1. Deploy an account contract exposing an entry point that calls the `replace_class` syscall with an attacker-controlled `class_hash` argument (the existing `test_replace_class` test entry point in `FeatureContract::TestContract` demonstrates this exact call pattern).
2. Submit an `INVOKE` transaction from any account invoking this entry point with a `class_hash` value that has never been declared (e.g., `felt!(1234_u16)` as used in the existing negative-flow unit tests).
3. Observe: the sequencer's blockifier reverts this call/transaction (as demonstrated by `undeclared_class_hash` test in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`, expecting `"is not declared"`), so the committed block's state diff shows no class-hash change for the sender contract (fee/nonce still applied per standard revert accounting).
4. Feed the identical block/transaction into the Starknet OS re-execution (`execute_replace_class` in `syscall_impls.cairo`): because no declared-class check exists, the syscall succeeds and updates `contract_state_changes` for the sender contract to the undeclared class hash, with no revert triggered by this syscall.
5. Compare the OS's resulting state diff/trace against the sequencer-committed state diff for the same block: they diverge specifically on this contract's class hash, demonstrating the honest-node/re-execution mismatch.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
