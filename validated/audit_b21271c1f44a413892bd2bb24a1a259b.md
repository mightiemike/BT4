`TokenDepositEvent::try_from_bytes` at [1](#0-0)  is a plain BCS deserialization (`bcs::from_bytes`) of the exact `event_data` bytes that were emitted by the Move `token::DepositEvent` and committed into the `ContractEvent`. The struct's fields, `id: TokenId` and `amount: u64`, are independent, fixed-position BCS fields [2](#0-1) . An attacker-chosen `TokenId` (creator/collection/name strings) only affects the bytes of the `id` field's own BCS encoding; it cannot bleed into or alter the separately-encoded `amount` field, because BCS encodes each struct field independently and deterministically based on its own type (strings are length-prefixed, so there is no ambiguous boundary that a crafted string could exploit to shift bytes into the `amount` field).

Because `amount()` simply returns the `u64` that was serialized into those same bytes bound into `event_root_hash`, any change to the decoded `amount` would require changing the underlying `event_data` bytes themselves — which would also change `event_root_hash`, not silently diverge from it. This function performs no reconstruction, no cross-referencing with the write set, and no reinterpretation of committed data into a different value; it is a direct, faithful decode of the exact bytes committed by the VM. There is no path by which unprivileged `TokenId`/`amount` input can make `try_from_bytes` decode a value different from what was actually written and hashed.
