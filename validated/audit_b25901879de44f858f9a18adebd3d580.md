### Title
Uniswap V3 spot-price sandwich on `refundUnusedGas` / `depositPRC20WithAutoSwap` swaps triggered by predictable, public UV vote transactions - (File: `x/uexecutor/keeper/outbound.go`, `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The external report describes yield stealing by sandwiching a public, predictable `RewardDistributor.distribute()` transaction. Push Chain has a structurally identical pattern: whenever an inbound `GAS`/`GAS_AND_PAYLOAD` deposit or an outbound gas-fee refund is finalized, the module fetches a live Uniswap V3 `QuoterV2` spot quote and immediately executes an on-chain swap with only a fixed 5% slippage bound, inside the same deterministic, publicly-visible transaction that finalizes a UV vote.

### Finding Description
For inbound `GAS`/`GAS_AND_PAYLOAD` deposits, `ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go:104-153`) calls `GetSwapQuote` and then immediately calls `CallPRC20DepositAutoSwap` with `minPCOut = quote * 95 / 100` [1](#0-0) .

For outbound gas refunds, `applyGasRefund` (`x/uexecutor/keeper/outbound.go:178-257`) does the same thing via `getSwapQuoteForRefund` and `CallUniversalCoreRefundUnusedGas`, again with a hardcoded 5% slippage tolerance computed from the current spot quote [2](#0-1) .

`GetSwapQuote` itself simply reads the Uniswap V3 `QuoterV2.quoteExactInputSingle` spot price at call time — there is no TWAP, no oracle cross-check, and no other manipulation resistance [3](#0-2) .

Both of these swaps execute inside the transaction that finalizes a `MsgVoteInbound` / `MsgVoteOutbound` ballot. Per `x/uexecutor/README.md`, once 2/3 of Universal Validators vote the same inbound/outbound observation, the core validator deterministically executes the corresponding logic, including these swaps [4](#0-3) . Because votes on `MsgVoteInbound`/`MsgVoteOutbound` are ordinary, gasless-whitelisted transactions broadcast through the normal mempool [5](#0-4) , and the observation content (asset, amount, gas token, gas fee) is either already public (the source-chain event) or derivable from already-cast earlier votes, an attacker watching the mempool can predict exactly which swap (token pair, direction, and approximate size) is about to execute and precisely when the finalizing vote will land.

This mirrors the StUSR bug class: rather than front-running/back-running `distribute()` around a staking position, the attacker front-runs/back-runs the *swap leg* of the finalizing vote transaction on Push Chain's own Uniswap V3 pool. A 5% slippage band is wide enough on typical AMM pools with realistic liquidity depth to allow meaningful, repeatable value extraction from every deposit-with-autoswap and every gas refund, at the direct expense of the user (less PRC20/native output than the undisturbed market price implies) or the protocol (fixed-price arbitrage into and out of the pool).

### Impact Explanation
This corrupts native/PRC20 asset accounting for ordinary users: every `GAS`/`GAS_AND_PAYLOAD` inbound deposit and every outbound gas refund routed through the auto-swap path can be sandwiched, systematically transferring value from users to an unprivileged attacker who trades against Push Chain's own swap-integration contract. Because these flows execute automatically and deterministically for every qualifying inbound/outbound, the loss is repeatable across the protocol's normal transaction volume, not a one-off edge case.

### Likelihood Explanation
High. No privileged role is required — the attacker only needs to (a) observe pending/near-finalization `MsgVoteInbound`/`MsgVoteOutbound` transactions in the mempool (these are ordinary gasless transactions, not restricted to private channels) and (b) hold liquidity to trade against the same Uniswap V3 pool the module swaps through. The 5% slippage tolerance is generous enough that sandwiching is profitable on typical pool depths, and the pattern repeats on every deposit/refund, giving the attacker continuous opportunities.

### Recommendation
- Do not compute the slippage bound from a spot quote fetched in the same transaction that performs the swap; use a TWAP-based quote (or a governance/oracle-set reference price) to bound `minPCOut`, so a single-block price manipulation cannot move the executed swap away from a fair reference price.
- Consider tightening the slippage tolerance and/or capping the maximum swap size per block for a given pool to reduce sandwich profitability.
- If feasible, route these UV-triggered swaps (or at least the vote transactions that deterministically trigger them) through a private submission channel, consistent with the recommendation in the referenced report, to remove the public mempool signal an attacker needs to time the sandwich.

### Proof of Concept
1. Attacker monitors the Push Chain mempool for `MsgVoteInbound` (`TxType_GAS`/`GAS_AND_PAYLOAD`) or `MsgVoteOutbound` transactions that are one vote away from reaching the 2/3 threshold (visible from already-cast votes and `PendingInbounds`/pending outbound state).
2. Once the attacker identifies the finalizing vote (asset/amount/gas token known from the underlying inbound/outbound observation), the attacker front-runs it with a trade on the relevant Uniswap V3 pool (the pool referenced by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress`) to move the spot price unfavorably for the module's incoming swap.
3. The finalizing vote transaction executes `ExecuteInboundGas`/`applyGasRefund`, fetching the manipulated spot quote via `GetSwapQuote` and swapping at `minPCOut = quote*95/100` [6](#0-5) , executing at a worse effective price than the undisturbed market rate.
4. The attacker back-runs with the reverse trade, restoring the pool price and capturing the price difference extracted from the user's deposit or gas refund.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
