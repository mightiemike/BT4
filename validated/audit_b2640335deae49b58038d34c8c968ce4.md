This confirms the analog: the quote (`GetSwapQuote` → `quoteExactInputSingle`) and the swap execution (`CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap`) both read the same live Uniswap V3 pool spot price, sequentially in the same keeper call, with `deadline = 0` and only a static ±5% band (`minPCOut = quote * 95/100`), with no TWAP or oracle cross-check — the same class of "price used at settlement can be manipulated/moved relative to a naive spot quote" issue as the original Kelp DAO report, just shifted from "0% tolerance" to "5% tolerance around a manipulable spot price."

### Title
Insufficient slippage protection via manipulable spot-price quote in inbound gas-swap flow allows value extraction from user gas-abstraction deposits - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go, x/uexecutor/keeper/outbound.go)

### Summary
The `GAS` / `GAS_AND_PAYLOAD` inbound execution paths and the outbound gas-refund path swap PRC20 gas tokens to native PC through UniversalCore's Uniswap V3 pool. The previous zero-slippage bug (matching the reported Kelp DAO M-4 pattern) was already patched by adding a ±5% band: `minPCOut = quote * 95 / 100` [1](#0-0) , applied identically in `gasAndPayloadDepositAutoSwap` [2](#0-1)  and `applyGasRefund` [3](#0-2) . However, the quote itself comes from `QuoterV2.quoteExactInputSingle`, a live spot-price simulation against the current pool state [4](#0-3) , not a TWAP or any externally-verified price. The subsequent swap (`depositPRC20WithAutoSwap`) executes against that same manipulable pool immediately afterward with `deadline = 0` [5](#0-4) .

### Finding Description
Both the quote fetch and the swap execution read from/interact with the same on-chain Uniswap V3 pool, and both happen inside the same message-processing flow (triggered by a `MsgVoteInbound`/`MsgVoteOutbound` transaction, since `x/uexecutor` has no `BeginBlocker`/`EndBlocker` and all execution is synchronous inside message handlers [6](#0-5) ). An unprivileged attacker who is also a normal EVM user on Push Chain can:

1. Observe a pending `MsgVoteInbound`/`MsgVoteOutbound` transaction in the mempool that will trigger a GAS-type deposit-swap or gas refund swap.
2. Submit their own transaction against the same UniversalCore Uniswap V3 pool with a higher gas price to get priority ordering ahead of the validator's finalizing transaction — the ante-handler explicitly derives mempool priority from gas price [7](#0-6) .
3. Push the PRC20/WPC pool price down with a large swap immediately before the module's internal quote+swap executes.
4. The module's `GetSwapQuote` reads the now-manipulated spot price, computes `minPCOut` as 95% of that already-depressed quote, and `depositPRC20WithAutoSwap` executes at that bad price — the 5% band only protects against movement *after* the quote is taken, not manipulation happening in the same block *before* the quote is read.
5. The attacker reverses their trade afterward, capturing the price impact as profit while the user's inbound-triggered mint or gas refund receives less native PC than fair value.

This mirrors the root cause of the referenced Kelp DAO report exactly: settlement of a mint/swap using a price that can diverge from fair value at execution time, with only a fixed percentage band as protection and no TWAP or external price cross-check.

### Impact Explanation
Impacted flows are: `ExecuteInboundGas` (GAS inbound top-ups) [8](#0-7) , `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbounds) [9](#0-8) , and `applyGasRefund` (excess-gas refunds on outbound finalization) [10](#0-9) . In all three, less native PC is minted/refunded to the end user than the pool's fair value would justify, and the difference is captured by the attacker sandwiching the internal swap. This is a fund-loss issue reachable by an ordinary unprivileged user, matching the in-scope "corruption of ... gas fee accounting, refund accounting ... token mapping" and "unauthorized state transitions in universal execution flows" categories.

### Likelihood Explanation
Likelihood depends on: (a) the depth/liquidity of the specific PRC20/WPC Uniswap V3 pool used for a given gas token — thinner pools are cheaper to move by the full 5% band; (b) whether Push Chain's transaction ordering can be reliably influenced by gas-price priority within a single block, which the codebase's own priority-fee logic supports. This is not a theoretical oracle-dishonesty assumption; it only requires an ordinary user to trade on a pool that is otherwise open to anyone, so it fits the "ordinary user deposits/payloads/contracts alone" reachability bar in the scope.

### Recommendation
Do not derive `minPCOut` solely from a same-block spot quote (`quoteExactInputSingle`) with a fixed percentage band. Use a manipulation-resistant reference price (e.g., a time-weighted average price over multiple blocks, or a cross-check against the chain-meta gas-price oracle already tallied by Universal Validators) to bound acceptable slippage, and/or enforce a maximum single-block price-impact check on the pool before trusting its quote. Consider also enforcing a real `deadline` (currently hardcoded to `0`, meaning "use contract default") and monitoring/limiting swap size relative to pool liquidity for gas-abstraction flows.

### Proof of Concept
Conceptual PoC (cannot be executed without a live testnet/mainnet pool):
1. Attacker monitors the Push Chain mempool for a `MsgVoteInbound` that will finalize a `GAS` or `GAS_AND_PAYLOAD` inbound for a low-liquidity PRC20/WPC pool.
2. Attacker submits a large `swapExactTokensForTokens`-style trade against the same Uniswap V3 pool with a higher gas price to front-run the finalizing vote transaction in the same block.
3. The pool's spot price moves down by close to the maximum the pool's liquidity allows.
4. The finalizing `MsgVoteInbound` executes, triggering `GetSwapQuote` → `CallPRC20DepositAutoSwap`, which reads the manipulated spot price and computes `minPCOut` as 95% of that depressed value [11](#0-10) ; the swap succeeds at the bad price since it's still within the (already-manipulated) 5% band.
5. Attacker submits a reverse trade to restore the pool price, capturing the price-impact spread as profit; the original inbound's recipient receives less native PC than the pool's fair value would have produced.

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil

// getTxPriority returns a naive tx priority based on the amount of the smallest denomination of the gas price
// provided in a transaction.
// NOTE: This implementation should be used with a great consideration as it opens potential attack vectors
// where txs with multiple coins could not be prioritize as expected.
func getTxPriority(fee sdk.Coins, gas int64) int64 {
	var priority int64
	for _, c := range fee {
		p := int64(math.MaxInt64)
		gasPrice := c.Amount.QuoRaw(gas)
		if gasPrice.IsInt64() {
			p = gasPrice.Int64()
		}
		if priority == 0 || p < priority {
			priority = p
		}
	}

	return priority
