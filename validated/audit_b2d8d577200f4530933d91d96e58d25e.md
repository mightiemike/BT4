No vulnerability found for this question.

Analysis summary supporting this conclusion:

1. `Wallet.getTransactionInfoById` at [1](#0-0)  does perform a two-step lookup: `TransactionRetStore.getTransactionInfo` first, then falls back to `TransactionHistoryStore.get`. However, this is purely a read-only informational API used to report already-settled transaction receipts; it has no bearing on transfer settlement, replay protection, or accounting.

2. Both `TransactionRetStore.put` and `TransactionHistoryStore.put` are gated by the exact same static config flag `getTransactionHistorySwitch()`, read from `CommonParameter` at each write call: [2](#0-1) [3](#0-2) . This switch is a node-operator/config-file setting (or deprecated CLI flag), not something an unprivileged attacker can toggle mid-flight: [4](#0-3) .

3. The production write path (`Manager.applyBlock`) only writes to `TransactionRetStore` as part of the atomic block-commit/revoking-session flow: [5](#0-4) . No live "pruning/compaction" of `TransactionRetStore` entries happens during normal node operation that races against `TransactionHistoryStore` backfill — the only code that trims/removes entries from `transactionRetStore`/`transactionHistoryStore` is the offline `DbLite` maintenance plugin tool, which is run manually by a node operator against an offline database directory, not reachable via any public API: [6](#0-5) .

4. Since there is no attacker-triggerable, unprivileged mechanism to induce the described timing window (switch toggling and pruning are both admin/operator-only, off-repo/offline actions per the exclusion rules), and since `getTransactionInfoById` returning `null` does not affect settlement, accounting, or replay protection (which are enforced by `validateDup`, Tapos, and expiration checks elsewhere in `Manager`), this does not constitute a reachable, exploitable vulnerability by an unprivileged attacker.

        .format("Begin to trim the history data, from %d to %d.", start, end).println();
    DBInterface blockIndexDb = DbTool.getDB(liteDir, BLOCK_INDEX_DB_NAME);
    DBInterface blockDb = DbTool.getDB(liteDir, BLOCK_DB_NAME);
    DBInterface transDb = DbTool.getDB(liteDir, TRANS_DB_NAME);
    DBInterface tranRetDb = DbTool.getDB(liteDir, TRANSACTION_RET_DB_NAME);


    ProgressBar.wrap(LongStream.rangeClosed(start, end)
        .boxed()
        .sorted((a, b) -> Long.compare(b, a)), "trimHistory").forEach(n -> {
          try {
            byte[] blockIdHash = blockIndexDb.get(ByteArray.fromLong(n));
            Protocol.Block block = Protocol.Block.parseFrom(blockDb.get(blockIdHash));
            // delete transactions
            for (Protocol.Transaction e : block.getTransactionsList()) {
              transDb.delete(DBUtils.getTransactionId(e).getBytes());
            }
            // delete transaction result
            tranRetDb.delete(ByteArray.fromLong(n));
            // delete block
            blockDb.delete(blockIdHash);
            // delete block index
            blockIndexDb.delete(ByteArray.fromLong(n));
          } catch (IOException e) {
            throw new RuntimeException(e);
          }
        });
