### Title
Gas-fee undercharge via truncating `LegacyDec` → `upc` conversion in `CalculateGasCost` - ([File: x/uexecutor/keeper/fees.go])

### Summary
`CalculateGasCost` in [1](#0-0)  converts the feemarket's `baseFee` (an `sdkmath.LegacyDec`, 18-decimal fixed point) back into an integer `upc` amount by taking the raw internal `big.Int` representation and doing `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`. This is an integer (floor) division. The comment asserts the base fee is "always a whole number of upc," but nothing in the code enforces that invariant — the value comes from `k.feemarketKeeper.GetBaseFee(sdkCtx)` [2](#0-1) , whose value is produced by the feemarket module's EIP-1559-style elasticity-multiplier adjustment formula (standard cosmos-evm feemarket `CalculateBaseFee`), which multiplies/divides `Dec` values and does not guarantee the result lands on an exact multiple of `1e18`.

### Finding Description
This mirrors the reported bug class: a division that silently rounds a fractional remainder down to zero, systematically producing a value smaller than the "true" one, with no assertion or `Ceil()` to compensate. Here the impact lands on `x/uexecutor`'s gas-fee accounting rather than an expansion counter:

- `DeductGasFeesFromReceipt` [3](#0-2)  calls `CalculateGasCost(baseFee, ...)` to determine how much `upc` to burn from a UEA/recipient account after a `DerivedEVMCall`/payload execution (see `ExecutePayloadV2` [4](#0-3)  and the CEA smart-contract execution path in [5](#0-4) ).
- Every time `baseFee`'s fractional (sub-`1e18`) remainder is truncated, the computed `effectiveGasPrice` — and therefore `gasCost = effectiveGasPrice * gasUsed` — is smaller than the economically-correct value. For high `gasUsed`, this remainder is amplified linearly, systematically undercharging users relative to the true EIP-1559 base fee.
- Because this feeds `DeductAndBurnFees` [6](#0-5) , which burns coins on behalf of the module-driven gas-fee accounting for UEA/CEA execution, the protocol/module systematically under-collects fees compared to what feemarket dictates. This is a "corruption of gas fee accounting" per the allowed-impact list, reachable purely from ordinary unprivileged users submitting universal payloads/inbound transactions that get executed through this path — no privileged actor needed.

### Impact Explanation
Each affected execution loses up to `(1e18 - 1)` wei worth of base-fee precision in the Dec→upc conversion, scaled up by `gasUsed`. Given `upc` is the smallest denomination (matching the code's own comment), any truncation of a fractional-`1e18` remainder is a real, non-recoverable underpayment on that leg, not a rounding artifact within the same unit. Over many transactions this compounds into a material, systemic gas-fee shortfall for the protocol (analogous to the referenced report's "protocol expands slower than intended" — here "protocol collects less fee than intended"). It does not, however, enable outright fund theft or unauthorized minting; it is an accounting-drift/underpayment bug.

### Likelihood Explanation
Whether this is actually reachable depends entirely on whether the underlying feemarket module's `CalculateBaseFee`/adjustment logic can ever produce a `baseFee` value whose internal representation is not an exact multiple of `1e18`. This repository vendors/wraps `cosmos/evm`'s feemarket keeper (`k.feemarketKeeper`), and I could not locate the `CalculateBaseFee` implementation in the indexed portion of this repo to conclusively confirm whether it always rounds to whole `upc` before storage or not — genesis/test setups here always set integral `LegacyDec` base fees (e.g. `1000000000000000000`) [7](#0-6) , and I found no direct evidence in-repo of the fractional case being exercised. If the feemarket's elasticity-adjustment arithmetic (a standard Dec multiply/divide by elasticity multiplier/denominator constants) can produce non-integral-`upc` results — which is the normal behavior of such EIP-1559 controllers — then this triggers on essentially every block where base fee is not exactly at a round number, making it a **high-likelihood, low-severity-per-tx, cumulative** issue.

### Recommendation
Round up (ceiling) rather than floor when converting `baseFee` from its 18-decimal `LegacyDec` encoding to whole `upc`, e.g. use `baseFee.Ceil().TruncateInt().BigInt()` or explicit remainder-aware ceiling logic, so that the protocol never systematically under-charges gas fees relative to the feemarket's authoritative base fee. Alternatively, keep the full-precision `Dec` gas cost computation (`price * gasUsed`) throughout and only round once, at the very end, using `Ceil()` before converting to `upc`, mirroring the `Ceil().RoundInt()` pattern already used correctly elsewhere in the ante-handler fee checks (`app/ante/validator_tx_fee.go` and `app/cosmos/min_gas_price.go`, both of which round fees up, not down) [8](#0-7) [9](#0-8) .

### Proof of Concept
Not directly executable from the indexed code alone since it depends on the feemarket's `CalculateBaseFee` output format, which was not found in this repo's indexed sources (likely vendored from `cosmos/evm`). Conceptually:
1. Let feemarket produce `baseFee = 1_500_000_000.5 upc` encoded as `LegacyDec` (internal `BigInt = 1500000000500000000000000000000000000`, i.e., `1.5000000005e9 * 1e18`).
2. `CalculateGasCost` computes `baseFeeBig.Div(baseFeeBig, 1e18)` → truncates to `1500000000` upc, discarding the `0.5` upc fractional remainder.
3. For `gasUsed = 1_000_000`, the shortfall is `0.5 * 1_000_000 = 500_000 upc` undercharged versus the mathematically correct fee, silently burned from the module's expected fee revenue with each such execution.

```go
// DeductAndBurnFees deducts gas fees from the user's smart account and burns them.
// The process happens in two steps:
// 1. Transfer coins from user account to module account
// 2. Burn coins from module account
// Returns error if either transfer or burn fails
func (k Keeper) DeductAndBurnFees(ctx context.Context, from sdk.AccAddress, gasCost *big.Int) error {
	amt := sdkmath.NewIntFromBigInt(gasCost)
	coin := sdk.NewCoin(pchaintypes.BaseDenom, amt)

	k.Logger().Debug("deducting and burning fees",
		"from", from.String(),
		"gas_cost", gasCost.String(),
		"denom", pchaintypes.BaseDenom,
	)

	err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, from, types.ModuleName, sdk.NewCoins(coin))
	if err != nil {
		return err
	}

	return k.bankKeeper.BurnCoins(ctx, types.ModuleName, sdk.NewCoins(coin))
}
```

```go
// DeductGasFeesFromReceipt calculates and deducts gas fees from a recipient address
// based on the EVM receipt and universal payload parameters.
// Returns nil if receipt is nil (Go-level error, no EVM tx was created).
// Returns error with gas details if deduction fails (insufficient balance, etc).
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}

	k.Logger().Debug("gas fees deducted",
		"recipient", recipient.Hex(),
		"gas_used", receipt.GasUsed,
		"gas_cost", gasCost.String(),
	)
	return nil
```
