## Path Trace

**Step 1 — `GasCounter::new` with `is_view=true`** [1](#0-0) 

When `is_view=true`, `prepaid_gas` is unconditionally set to `Gas::MAX` (`u64::MAX`). The `gas_limit` field is correctly bounded to `min(max_gas_burnt, Gas::MAX) = max_gas_burnt`, but `self.prepaid_gas` stores `Gas::MAX`.

**Step 2 — `remaining_gas()` returns `Gas::MAX`** [2](#0-1) 

`remaining_gas() = prepaid_gas.saturating_sub(used_gas())`. With `prepaid_gas = Gas::MAX` and `used_gas()` being a small finite contract-loading fee, `remaining_gas()` is `Gas::MAX - small_amount`, which is still far above `i64::MAX`.

**Step 3 — `call_hook` casts `remaining_gas` to `i64` without bounds check** [3](#0-2) 

On `CallHook::CallingWasm` (fires before every WASM entry), the hook does:
```rust
let remaining_gas = store.data().result_state.gas_counter.remaining_gas();
global.set(&mut store, Val::I64(remaining_gas.as_gas() as _))
```
`remaining_gas.as_gas() as i64` is a wrapping `u64 → i64` cast. `u64::MAX as i64 = -1`. Any value of `remaining_gas` above `i64::MAX` produces a negative `i64`.

**Step 4 — WASM global is set to a negative value**

The `REMAINING_GAS_EXPORT` global is injected by the v3 instrumentation into every contract compiled for the wasmtime runner. [4](#0-3) 

The finite-wasm instrumentation subtracts gas costs from this `i64` global and calls `finite_wasm_gas_exhausted` when the result is negative. If the global is already `-1` at WASM entry, the very first subtraction triggers the exhausted path.

**Step 5 — `finite_wasm_gas_exhausted` terminates the call** [5](#0-4) 

`burn_gas(remaining_gas())` attempts to burn `Gas::MAX - small_amount`, which exceeds `max_gas_burnt`, so `process_gas_limit` returns `GasLimitExceeded`. The `?` propagates it, and the view call terminates immediately.

## Verdict

### Title
View-call `prepaid_gas = Gas::MAX` wraps to negative `i64` in `call_hook`, causing immediate `GasLimitExceeded` on all instrumented view calls — (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs`)

### Summary
When `is_view=true`, `GasCounter::new` sets `prepaid_gas = Gas::MAX`. The `call_hook` in the wasmtime runner converts `remaining_gas()` (≈ `u64::MAX`) to `i64` via a wrapping cast, producing `-1`. This negative value is written into the WASM gas global before execution begins. The finite-wasm instrumentation interprets a negative global as gas exhaustion and immediately calls `finite_wasm_gas_exhausted`, terminating every view call with `GasLimitExceeded` regardless of the configured `max_gas_burnt_view` budget.

### Finding Description
`GasCounter::new` intentionally sets `prepaid_gas = Gas::MAX` for view calls to bypass the prepaid-gas limit check. However, `remaining_gas()` uses `self.prepaid_gas` directly, so it returns `Gas::MAX - used_gas()`, a value that exceeds `i64::MAX`. The `call_hook` at `CallHook::CallingWasm` writes this value into the WASM `i64` global via `remaining_gas.as_gas() as _` — a silent wrapping cast — producing a negative number. The finite-wasm instrumentation treats any negative gas global as exhaustion and calls `finite_wasm_gas_exhausted` on the first WASM instruction.

### Impact Explanation
Every view call to a contract compiled with v3 instrumentation (all contracts under the wasmtime runner) fails immediately with `GasLimitExceeded`. An unprivileged attacker can observe this by submitting any view call via the default JSON-RPC endpoint. This is a non-network-level DoS: it stalls all view-call execution without affecting block production or consensus, and it can be fixed without a hardfork by correcting the cast.

### Likelihood Explanation
The entrypoint is the default JSON-RPC `query` endpoint with `request_type: "call_function"`. No special privileges, keys, or deployed contracts are required. Any caller can trigger the failure path.

### Recommendation
In the `call_hook`, cap the value written to the WASM global at `i64::MAX`:
```rust
CallHook::ReturningFromHost | CallHook::CallingWasm => {
    let remaining_gas = store.data().result_state.gas_counter.remaining_gas();
    let clamped = remaining_gas.as_gas().min(i64::MAX as u64) as i64;
    global.set(&mut store, Val::I64(clamped)).expect("failed to set gas global export")
}
```
Alternatively, `remaining_gas()` could be bounded by `gas_limit` (= `max_gas_burnt`) rather than `prepaid_gas` when `is_view=true`, since `gas_limit` is already correctly capped.
