### Title
Unauthenticated JSON-RPC methods allow halting sequencer L1 commitments and evicting mempool transactions - (File: crates/sequencer/src/rpc.rs)

### Summary
The sequencer's public JSON-RPC endpoint registers `citrea_haltCommitments`, `citrea_resumeCommitments`, `txpool_removeTransactionsByHash`, and `txpool_removeTransactionsBySender` alongside ordinary user-facing methods like `eth_sendRawTransaction`, and none of them are gated by any signature, role, or API-key check. [1](#0-0)  Any caller who can reach the RPC port can invoke these methods to stop the sequencer from posting L1 commitments or to remove other users' pending transactions from the mempool.

### Finding Description
`SequencerRpcServer` exposes `halt_commitments`/`resume_commitments`, which unconditionally forward `SequencerRpcMessage::HaltCommitments`/`ResumeCommitments` to the sequencer's control channel, and `txpool_remove_txs_by_hash`/`txpool_remove_txs_by_sender`, which directly call into the mempool to remove transactions - all without checking caller identity: [2](#0-1) 

These methods are merged into the same `RpcModule<()>` that serves all other sequencer RPC methods and is started as a single public server: [3](#0-2) [4](#0-3) 

The only authentication layer present, `Auth`, protects a hardcoded allowlist of exactly three methods (`backup_create`, `backup_validate`, `backup_info`) via an API key; every other method — including the state-mutating ones above — passes through untouched: [5](#0-4) 

Deployment configs commonly bind this RPC server to `0.0.0.0`, making it reachable by any network peer, not just a misconfigured/local operator: [6](#0-5) [7](#0-6) 

This is structurally the same bug class as the referenced Shardus report: an unauthenticated network-facing entry point performs a privileged, state-mutating action (there: disconnecting archivers via `UNSUBSCRIBE`; here: halting commitment production or evicting arbitrary mempool transactions via unauthenticated RPC) with no signature/timestamp/role check tying the request to an authorized party.

### Impact Explanation
`citrea_haltCommitments` stops the sequencer from posting new L1 commitments, which — while a control-plane action rather than a custody/proof binding — is an unauthenticated JSON-RPC call that mutates node state, matching the "High" bucket definition ("an unauthenticated JSON-RPC call that mutates node state or bypasses `Auth`"). `txpool_removeTransactionsByHash`/`BySender` let an unprivileged caller unilaterally delete other users' pending transactions from the sequencer mempool without their consent, which is also an unauthenticated state mutation via RPC.

### Likelihood Explanation
No credentials, signatures, or special network position are required — any client that can open a connection to the sequencer's configured RPC port (frequently `0.0.0.0` in shipped configs) can call these methods directly, exactly as trivially as the PoC client in the referenced report connected to a validator's socket.

### Recommendation
Add `citrea_haltCommitments`, `citrea_resumeCommitments`, `txpool_removeTransactionsByHash`, and `txpool_removeTransactionsBySender` to the `Auth` middleware's `PROTECTED_METHODS` list (or a broader allowlist-based scheme) in `crates/common/src/rpc/auth.rs`, so they require the operator API key like `backup_*` methods, and consider removing state-mutating admin methods from the public RPC module entirely, exposing them only on a separate internal-only listener.

### Proof of Concept
1. Start a sequencer node with default config (RPC bound to `0.0.0.0:<port>`).
2. From any remote host, send `{"jsonrpc":"2.0","method":"citrea_haltCommitments","params":[],"id":1}` to the RPC endpoint.
3. Observe the sequencer processes `SequencerRpcMessage::HaltCommitments` and stops posting L1 commitments, with no authentication required — analogous to the Shardus `UNSUBSCRIBE` PoC that stalled the network without any credential check.

    /// Halt sequencer commitments
    async fn halt_commitments(&self) -> RpcResult<()> {
        debug!("Sequencer: citrea_haltCommitments");
        self.context
            .rpc_message_tx
            .send(SequencerRpcMessage::HaltCommitments)
            .map_err(|e| internal_rpc_error(format!("Could not send halt commitments signal: {e}")))
    }

    /// Resume sequencer commitments
    async fn resume_commitments(&self) -> RpcResult<()> {
        debug!("Sequencer: citrea_resumeCommitments");
        self.context
            .rpc_message_tx
            .send(SequencerRpcMessage::ResumeCommitments)
            .map_err(|e| {
                internal_rpc_error(format!("Could not send resume commitments signal: {e}"))
            })
    }

    /// Returns the transaction pool content.
    async fn txpool_content(&self) -> RpcResult<TxpoolContent<Transaction>> {
        let AllPoolTransactions { pending, queued } = self.context.mempool.all_transactions();

        fn extract_tx(tx: Arc<ValidPoolTransaction<EthPooledTransaction>>) -> Transaction {
            let tx_signed_ec_recovered = tx.to_consensus(); // tx signed ec recovered
            EthTxBuilder::default()
                .fill_pending(tx_signed_ec_recovered)
                .expect("EthTxBuilder fill can't fail")
        }

        let mut content = TxpoolContent::default();

        for tx in pending {
            content
                .pending
                .entry(tx.sender())
                .or_default()
                .insert(tx.nonce().to_string(), extract_tx(tx));
        }

        for tx in queued {
            content
                .queued
                .entry(tx.sender())
                .or_default()
                .insert(tx.nonce().to_string(), extract_tx(tx));
        }

        Ok(content)
    }

    /// Removes transactions from the pool by hash.
    async fn txpool_remove_txs_by_hash(&self, hashes: Vec<B256>) -> RpcResult<Vec<B256>> {
        let removed_txs = self
            .context
            .mempool
            .remove_transactions_and_descendants(hashes);
        let removed_hashes: Vec<B256> = removed_txs.iter().map(|tx| *tx.hash()).collect();
        Ok(removed_hashes)
    }

    /// Removes all transactions from the pool by sender.

        let removed_hashes: Vec<B256> = removed_txs.iter().map(|tx| *tx.hash()).collect();
        Ok(removed_hashes)
