### Title
Bad-debt socialization fold aborts entire liquidation when a stripped/fresh debt entry has `scaled: u0` - (File: `mainnet/contracts/market/v0-4-market.clar`)

### Summary
`liquidate()` builds a `fresh-debt-list` of the borrower's remaining debt entries (after possibly updating the current debt asset) and folds `socialize-debt-asset` over every entry when the position has no collateral left. Each fold iteration unconditionally calls `vault-socialize-debt` → the vault's `socialize-debt (scaled-amount uint)` public function, which hard-reverts with `ERR-AMOUNT-ZERO` if `scaled-amount` is `u0`. Nothing filters out zero-scaled debt entries before the fold runs.

### Finding Description
In `mainnet/contracts/market/v0-4-market.clar`, when a liquidation leaves the borrower with `no-collateral-left`, the code builds `fresh-debt-list` from `stripped-debt-list` (the borrower's debt list with the just-liquidated asset filtered out) plus, conditionally, the just-liquidated asset re-appended with its `debt-updated` scaled amount if that amount is non-zero: [1](#0-0) 

It then folds `socialize-debt-asset` over `fresh-debt-list`: [2](#0-1) 

`socialize-debt-asset` performs `(unwrap! (vault-socialize-debt asset-id scaled-debt) failed-status)` for **every entry in the list without checking `scaled-debt > u0`**: [3](#0-2) 

The callee, `socialize-debt` in each vault contract, hard-asserts the amount is non-zero and reverts otherwise: [4](#0-3) 

`stripped-debt-list` is produced by `filter-out-debt-asset`, which only removes the entry matching `debt-aid` — it does **not** filter out other debt entries whose `scaled` value happens to be `u0` (e.g., an asset that was already fully repaid/rounded to zero in a previous partial-liquidation/repay but whose list entry was never pruned, or an asset entry created with `scaled: u0` due to rounding in `debt-add-scaled`/`debt-remove-scaled` elsewhere in the position bookkeeping). If any such zero-scaled entry survives into `fresh-debt-list`, `unwrap!` on the vault's error response returns `failed-status`, and the outer code asserts `(get success socialization-result) ERR-BAD-DEBT-SOCIALIZATION-FAILED`, reverting the **entire liquidation transaction** — including the debt repayment and collateral seizure that already occurred earlier in the same call.

This matches the reported bug class: a per-item loop that unconditionally invokes an operation whose value can legitimately be zero, against a callee that reverts on zero (`socialize-debt`'s `ERR-AMOUNT-ZERO` guard), and the loop absorbs failure via `unwrap!`/`asserts!` rather than skipping zero entries — analogous to Mycelium's `_withdrawFromPlugin` being called unconditionally in `rebalancePlugins`/`removePlugin` even when the value is `0`.

### Impact Explanation
If a borrower's stored debt list contains any stale zero-scaled entry for an asset other than the one currently being liquidated, the last liquidator to fully clear the borrower's collateral will have their entire `liquidate` transaction revert with `ERR-BAD-DEBT-SOCIALIZATION-FAILED`, even though debt repayment/collateral transfer logic was otherwise correct. This freezes the ability to close out and socialize genuinely bad debt for that position — the position becomes stuck (collateral removed conceptually but the whole tx reverts, so nothing actually moves), and the protocol cannot mark the bad debt as socialized, leaving the vault's accounting permanently inconsistent for that borrower until the stale zero entry is somehow cleared. This falls under temporary/permanent freezing of funds (the liquidation flow that would resolve insolvent debt becomes unusable), which matches the in-scope "temporary freezing of funds" / protocol-insolvency-adjacent impact class.

### Likelihood Explanation
Likelihood depends on whether a zero-scaled debt-list entry can actually persist across operations (e.g., through rounding in `debt-add-scaled`/`debt-remove-scaled`, or through sequential partial liquidations/repayments that reduce an asset's scaled debt to exactly zero without removing the list entry). This requires verifying `market-vault.clar`'s `debt-add-scaled`/`debt-remove-scaled` semantics, which were not available in the indexed context — this should be confirmed against the full source before treating this as fully proven.

### Recommendation
In `socialize-debt-asset`, skip entries where `scaled-debt` is `u0` (treat as already-clear, return `acc` unchanged) instead of always invoking `vault-socialize-debt`, mirroring the Sherlock recommendation of only performing the operation when the value is non-zero.

### Proof of Concept
1. Borrower has a debt-list entry `{aid: X, scaled: u0}` for asset X, persisted due to prior partial repay/liquidation rounding (requires confirming `market-vault.clar` behavior).
2. Borrower is liquidated on a different debt asset Y and loses all collateral in this call (`no-collateral-left` becomes true).
3. `stripped-debt-list` retains the `{aid: X, scaled: u0}` entry (only `debt-aid = Y` is filtered out).
4. `fresh-debt-list` = `stripped-debt-list` (since `debt-updated` for Y is `u0`, nothing is re-appended) — still contains the zero entry for X.
5. `fold socialize-debt-asset fresh-debt-list ...` calls `vault-socialize-debt X u0` → vault's `socialize-debt` asserts `(> scaled-amount u0)` and reverts.
6. `unwrap!` propagates `failed-status`; `(asserts! (get success socialization-result) ERR-BAD-DEBT-SOCIALIZATION-FAILED)` reverts the whole `liquidate` call. [5](#0-4) [3](#0-2) [6](#0-5)

(define-private (socialize-debt-asset
                (debt-entry { aid: uint, scaled: uint })
                (acc { borrower: principal, success: bool }))
  ;; Early return if previous socialization failed
  (if (not (get success acc))
      acc
      (let ((borrower (get borrower acc))
            (failed-status { borrower: borrower, success: false })
            (asset-id (get aid debt-entry))
            (scaled-debt (get scaled debt-entry)))

(define-public (socialize-debt (scaled-amount uint))
  (let ((scaled-principal (var-get principal-scaled))
        (borrowed (var-get total-borrowed))
        (idx (var-get index))
        (current-assets (var-get assets))
        (current-lindex (var-get lindex))
        (old-total-assets (total-assets))
