### Title
Non-injective UTX identity key allows attacker-crafted inbound field values to collide with a legitimate inbound's canonical ID - (File: `x/uexecutor/types/keys.go`)

### Summary
`x/uexecutor` derives the canonical, permanent identity of a cross-chain transaction (`UniversalTx`/UTX) with a plain, delimiter-based string concatenation, while the *ballot* key used for consensus on the very same event is built with an explicitly injective, per-field-hashed scheme. The mismatch reproduces the address-collision root cause from the external report (a deterministic identifier that is not guaranteed unique across distinct logical inputs), but here the colliding identifier is the on-chain `UniversalTx` ID rather than a DAO's deployed address.

### Finding Description
`GetInboundUniversalTxKey` builds the UTX id like this: [1](#0-0) 

```go
data := fmt.Sprintf("%s:%s:%s", chain, txHash, logIndex)
hash := sha256.Sum256([]byte(data))
```

This is a naive `":"`-joined concatenation of three attacker-influenceable strings, and none of them are restricted from containing `:` themselves — `chain` (a CAIP-2 id) always contains a `:`, and `txHash`/`logIndex` are only trimmed, not format-validated, before hashing.

By contrast, the ballot key for the exact same `Inbound` struct is built with `hashFields`, whose doc comment explicitly calls out the boundary-shifting problem that per-field hashing exists to prevent: [2](#0-1) 

The `Canonicalize()` step that runs before both keys are derived is explicitly "lenient": unparseable/unrecognized values are only trimmed, never rejected or format-enforced, precisely so the vote path can never fail before a UTX is recorded: [3](#0-2) 

`ValidateBasic` for `Inbound` only checks that `source_chain`, `tx_hash`, `sender`, and `log_index` are non-empty and that `source_chain` contains a `:` — it does not constrain `tx_hash`/`log_index` to any fixed charset that would prevent them from containing `:`: [4](#0-3) 

Because the UTX id (`chain:txHash:logIndex`, single sha256) is not injective, two different tuples can be crafted to produce the identical concatenated string (e.g. by shifting where a `:` falls between `txHash` and `logIndex`), which produces the identical UTX id even though the ballot key (per-field hashed) for the two tuples differs. `VoteInbound` treats "UTX already exists" as a hard rejection of any further inbound vote for that id: [5](#0-4) 

This means whichever tuple reaches quorum and finalizes into a `UniversalTx` first permanently occupies that UTX id; any subsequent, distinct-but-colliding logical inbound (including the legitimate one) is rejected outright with "universal tx with key %s already exists" and can never be recorded, mirroring the DAO-override pattern where one deployer's use of a colliding deterministic slot locks out or overwrites the rightful owner's data.

### Impact Explanation
If exploitable, this permanently blocks/hijacks the canonical on-chain record (`UniversalTx`) for a legitimate user's cross-chain deposit — the record that the whole protocol (JSON-RPC layer, indexers, explorer, refund logic) relies on as the single source of truth. A user's real inbound could be rejected forever once an attacker-crafted colliding tuple has already claimed the UTX slot, which is a form of permanent freezing/loss of visibility into (and processing of) the user's funds, consistent with the in-scope "corruption of ... canonical UniversalTx state" and "forged, replayed, mismatched, or cross-linked inbound ... state accepted through user-reachable flows with honest validators" impact categories.

### Likelihood Explanation
Medium-to-low confidence/likelihood: the collision requires that at least one of `tx_hash`/`log_index` as observed and reported by honest Universal Validators can be made to contain a `:` character (or otherwise shift the concatenation boundary) from data the attacker controls on the source chain (e.g., an event field that is attacker-influenced rather than a strict fixed-width hex value), and it also requires winning the race to finalize the colliding UTX id before the legitimate inbound does. I was not able to fully verify, within the available exploration budget, whether the specific `tx_hash`/`log_index` values ingested from real supported source chains (EVM/Solana/Cosmos gateways) are always constrained upstream (e.g., always valid 0x-hex of fixed length) such that a raw `:` could never appear — `LenientCanonicalizeTxHash` is explicitly documented as leaving "unparseable" values untouched rather than rejecting them, which suggests the constraint is not uniformly enforced for all namespaces, but this needs confirmation against the actual per-chain decoder logic (`utils/canonical.go`, gateway event decoders) before being certain the tuple is attacker-shapeable in practice.

### Recommendation
Replace the plain `fmt.Sprintf("%s:%s:%s", chain, txHash, logIndex)` concatenation in `GetInboundUniversalTxKey` (and the analogous `GetPcUniversalTxKey`) with the same injective, per-field-hashed construction already used by `hashFields` for ballot keys, so that no field value can shift a delimiter boundary and collide with a different logical tuple. Additionally, tighten `Inbound.ValidateBasic`/`Canonicalize` to reject or strictly normalize `tx_hash` and `log_index` values that don't conform to the expected format for the given chain namespace, rather than leniently passing through unparseable strings into the identity-key derivation.

### Proof of Concept
Conceptual (not fully verified against live source-chain decoders due to tool-iteration limits):
1. Legitimate inbound A: `source_chain="eip155:11155111"`, `tx_hash="abc"`, `log_index="0:extra"` → id string `"eip155:11155111:abc:0:extra"`.
2. Attacker-influenced inbound B (crafted so its raw event data yields): `source_chain="eip155:11155111"`, `tx_hash="abc:0"`, `log_index="extra"` → id string `"eip155:11155111:abc:0:extra"` — identical to A's.
3. Both hash to the same `sha256` UTX id via `GetInboundUniversalTxKey`, but produce different `GetInboundBallotKey` values (per-field hashed), so they are treated as distinct ballots by the voting/consensus layer.
4. Whichever of A/B's ballot reaches quorum first calls `VoteInbound`, which checks `HasUniversalTx(ctx, universalTxKey)` and creates the UTX; the second-arriving one is rejected with "universal tx with key %s already exists" (`x/uexecutor/keeper/msg_vote_inbound.go:44-52`), permanently blocking that logical event from ever being recorded under its rightful id.

// GetInboundUniversalTxKey: UTX identity from canonical (source_chain, tx_hash,
// log_index). Canonicalizes locals; caller's inbound is not mutated.
func GetInboundUniversalTxKey(inbound Inbound) string {
	chain := strings.TrimSpace(inbound.SourceChain)
	txHash := utils.LenientCanonicalizeTxHash(chain, inbound.TxHash)
	logIndex := strings.TrimSpace(inbound.LogIndex)
	data := fmt.Sprintf("%s:%s:%s", chain, txHash, logIndex)
	hash := sha256.Sum256([]byte(data))
	return hex.EncodeToString(hash[:]) // hash[:] converts [32]byte → []byte
}
```

// hashFields = sha256( hex(sha256(domain)) : hex(sha256(f0)) : ... ). Per-field
// hashing makes it injective — a sub-hash can't contain ':', so no field value
// can shift a boundary and collide with a different tuple.
func hashFields(domain collections.Prefix, parts ...string) string {
	hashed := make([]string, 0, len(parts)+1)
	d := sha256.Sum256(domain.Bytes())
	hashed = append(hashed, hex.EncodeToString(d[:]))
	for _, p := range parts {
		sum := sha256.Sum256([]byte(p))
		hashed = append(hashed, hex.EncodeToString(sum[:]))
	}
	final := sha256.Sum256([]byte(strings.Join(hashed, ":")))
	return hex.EncodeToString(final[:])
}
```

// Canonicalize normalizes encoding-variant fields in place (per source-chain
// namespace) so the same event from any observer is byte-identical across
// ballot keys, UTX keys and registry lookups. Lenient (unparseable values are
// kept trimmed, never rejected) because the vote path must always record a
// UTX — execution-level validation rejects malformed inbounds later.
func (p *Inbound) Canonicalize() {
	p.SourceChain = strings.TrimSpace(p.SourceChain)
	p.TxHash = utils.LenientCanonicalizeTxHash(p.SourceChain, p.TxHash)
	p.Sender = utils.LenientCanonicalizeAddress(p.SourceChain, p.Sender)

func (p Inbound) ValidateBasic() error {
	// Validate source_chain (must follow CAIP-2 format) — needed for UTX key
	chain := strings.TrimSpace(p.SourceChain)
	if chain == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain cannot be empty")
	}
	if !strings.Contains(chain, ":") {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "source chain must be in CAIP-2 format <namespace>:<reference>")
	}

	// Validate tx_hash — needed for UTX key
	if strings.TrimSpace(p.TxHash) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "tx_hash cannot be empty")
	}

	// Validate sender — needed for revert recipient fallback
	if strings.TrimSpace(p.Sender) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidAddress, "sender cannot be empty")
	}

	// Validate log_index — needed for UTX key
	if strings.TrimSpace(p.LogIndex) == "" {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "log_index cannot be empty")
	}
