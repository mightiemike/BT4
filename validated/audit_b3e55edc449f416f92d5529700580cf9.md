### Title
Starknet OS `replace_class` syscall handler omits declared-class validation, causing OS/Blockifier state divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The reported bug class is a missing validation on a user-controlled field (`_receiver`) before mutating protocol state, allowing loss/corruption of state that the contract logic assumed was always validated. The reachable analog in this sequencer codebase is the `execute_replace_class` function in the Starknet OS Cairo program: it writes the caller-supplied `class_hash` into the contract's state entry without verifying that the class is actually declared, unlike the equivalent Rust `blockifier` implementation which performs this check and fails the call otherwise.

### Finding Description
Any contract can invoke the `replace_class` syscall with an arbitrary `class_hash`, including one that has never been declared (or is `0`). In the Rust execution engine (`blockifier`), this is explicitly validated: `replace_class` in `syscall_base.rs` calls `self.state.get_compiled_class(class_hash)?` before writing the new class hash, so an undeclared class hash makes the syscall (and, if uncaught, the transaction) fail: [2](#0-1) 

The deprecated (Cairo0) syscall handler enforces the same check: [3](#0-2) 

However, the Starknet OS Cairo implementation of the same syscall — used during Starknet OS re-execution/proof generation — has an explicit `TODO` marking the missing check, and unconditionally overwrites the contract's class hash in `contract_state_changes` regardless of whether that class hash is declared: [1](#0-0) 

Because a transaction invoking `replace_class(undeclared_or_zero_class_hash)` would be rejected/reverted by `blockifier` (the component that actually produces the canonical block/state diff during sequencing) but would silently succeed and write the state change when the same transaction is re-executed by the Starknet OS (during proof generation/re-execution flows), the two execution paths diverge on the same transaction and the same input state.

### Impact Explanation
This is a single-transaction-reachable divergence between the sequencer's canonical execution engine (blockifier) and the Starknet OS re-execution used for proving. If a transaction that reverts in `blockifier` due to an undeclared class hash is treated as succeeding by the OS (applying the class-hash state write), the OS-computed state diff/commitment for that block will not match the state diff actually committed by the sequencer. This can produce a wrong committed root/state that the prover attests to, or cause the OS re-execution to diverge from honest sequencer behavior — both of which are explicitly listed as acceptable impacts (wrong committed root or block hash, honest-node divergence).

### Likelihood Explanation
Likelihood is high for any unprivileged caller: `replace_class` is a normal syscall invocable directly by any contract via a single `INVOKE` transaction, with a fully attacker-controlled `class_hash` argument (including `0` or any undeclared felt). No special privileges, timing, or race conditions are required — only submitting one transaction that calls `replace_class` with an undeclared class hash from a contract whose execution is not otherwise reverted for other reasons.

### Recommendation
Add the same "class must be declared" check to `execute_replace_class` in `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo` that already exists in the Rust `blockifier` syscall handlers (`syscall_base.rs::replace_class` and `deprecated_syscalls/hint_processor.rs::replace_class`), i.e., resolve the existing `TODO(Yoni, 1/1/2026)` by verifying the class hash was previously declared (and ideally also that it is not the Cairo0→Cairo1 forbidden downgrade case) before writing the new state entry, so that OS re-execution behavior matches blockifier's canonical execution exactly.

### Proof of Concept
1. Deploy an account/contract A on Starknet via the sequencer.
2. Submit an `INVOKE` transaction from A that calls the `replace_class` syscall with a `class_hash` that has never been declared (e.g., `0x0` or a random felt).
3. In the sequencer's `blockifier` execution, `state.get_compiled_class(class_hash)` fails, causing the syscall (and depending on error propagation, the transaction) to fail/revert — the class hash of A is not changed in the committed state diff.
4. When the same transaction is later re-executed by the Starknet OS (for proof generation, per `execute_replace_class` in `syscall_impls.cairo`), no declared-class check exists, so the OS unconditionally updates A's state entry with the undeclared `class_hash`, producing a different result/state diff than what blockifier committed. func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
