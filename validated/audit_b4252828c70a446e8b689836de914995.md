### Title
Starknet OS `replace_class` syscall omits declared-class and Cairo-version checks that Blockifier enforces, allowing sequencer/OS state-transition divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall does not perform the same validation that the sequencer's Rust execution engine (Blockifier) performs for the identical syscall. This mirrors the reported bug class of "missing code in certain functions" causing an invariant the system relies on (here: OS re-execution must reproduce exactly what Blockifier committed) to be silently violated.

### Finding Description
Any account contract can invoke the `replace_class` syscall via a normal `invoke` transaction. In Blockifier, `replace_class` is implemented with two mandatory checks before mutating storage: the target class hash must be declared (fetched via `get_compiled_class`, which errors if undeclared) and it must be a Cairo1 class (`is_cairo1`), otherwise the call fails with `ForbiddenClassReplacement`. [1](#0-0) 

The Starknet OS's Cairo implementation of the same syscall (`execute_replace_class` in `syscall_impls.cairo`, used by the current/new syscalls path) performs no such validation - it directly reads the requested `class_hash` and unconditionally writes it into the contract's `StateEntry`, with an explicit TODO acknowledging the missing check: [2](#0-1) 

The deprecated syscalls path (`deprecated_execute_syscalls.cairo::execute_replace_class`, used for Cairo0-style deployed accounts) has the identical omission with no check and not even a TODO comment: [3](#0-2) 

Both are dispatched unconditionally from the syscall selector switch for every transaction the OS re-executes: [4](#0-3) [5](#0-4) 

The Starknet OS is the Cairo program that re-executes the same block that Blockifier already executed, in order to produce a STARK-provable trace whose resulting state diff is supposed to be bit-identical to the one Blockifier committed for consensus/state-root purposes (see the Starknet OS Internals wiki page, and the `starknet_os_flow_tests` harness, which explicitly diffs Blockifier's `decompressed_state_diff` against OS output for validation). This test-mode round-trip is the mechanism by which the codebase enforces OS/Blockifier equivalence, and it is exactly the invariant that is silently broken here.

### Impact Explanation
Because Blockifier rejects `replace_class` calls that target an undeclared class hash or a Cairo0 class hash (reverting the transaction), while the OS's Cairo implementation accepts and applies the exact same call unconditionally, a single ordinary transaction (from any unprivileged sender who has declared no class, or who deliberately references an undeclared/incompatible class hash) can cause the OS's computed state diff for that block to diverge from Blockifier's committed state diff:
- Blockifier: transaction reverts, contract's class hash unchanged, fee still charged for the reverted call.
- OS: transaction succeeds, contract's class hash is overwritten with an arbitrary/undeclared value, producing a different state diff / different resulting state root than what was actually committed to storage and gossiped by the sequencer.

This is a wrong-committed-root / honest-node divergence class of bug: the value that ends up being proven (via the OS's execution trace feeding proof generation) does not match the value that the network's blockifier-based state actually committed, for any block containing such a transaction. Depending on how strictly the proving/verification pipeline enforces output-vs-committed-root equality, this either (a) makes the network permanently unable to produce a valid/matching STARK proof for that block (freezing L1 finality for that and all subsequent blocks), or (b) corrupts the account's class hash silently in the proved output/committed root such that a contract's class binding no longer matches what any node's storage/state actually holds - a form of unauthorized state mutation not reflected in the canonical state used to reach consensus.

### Likelihood Explanation
Triggering this requires nothing more than an ordinary `invoke` transaction that calls `replace_class` with a class hash that is undeclared (trivial to construct - any felt not previously declared) or, for accounts on the deprecated Cairo0 execution path, any Cairo0 class hash. No privileged role, no consensus/proposer control, and no p2p manipulation is needed - only a normal transaction sender exercising a documented syscall. The bug is also explicitly flagged as an open gap by the `TODO(Yoni, 1/1/2026)` comment in the current (non-deprecated) syscall path, confirming the check is known to be missing rather than intentionally omitted.

### Recommendation
1. In `execute_replace_class` (`syscall_impls.cairo`) and `execute_replace_class` (`deprecated_execute_syscalls.cairo`), add the same validation Blockifier performs before writing the new `StateEntry`: verify the class hash is declared (read from `contract_class_changes`/appropriate declared-class dictionary and assert non-zero / previously declared), and, for parity with `syscall_base.rs::replace_class`, reject replacement with a Cairo0/deprecated class hash where Blockifier does.
2. Add or extend `starknet_os_flow_tests` coverage specifically for `replace_class` with an undeclared class hash and with a Cairo0 class hash, asserting that the OS-produced state diff matches Blockifier's (i.e., the call reverts identically in both), closing the gap the TODO comment currently leaves open.
3. Audit all other syscalls in `syscall_impls.cairo` / `deprecated_execute_syscalls.cairo` for similar unconditional `dict_update` writes that skip declared-class or type checks enforced on the Blockifier side, since this appears to be a systemic pattern (the deprecated path has the same omission without even a tracking comment).

### Proof of Concept
Conceptual PoC (cannot be executed without running the full flow-test harness, but the divergence is deterministic from the code alone):
1. Deploy/declare a standard Cairo1 account contract that exposes a function calling `replace_class_syscall(UNDECLARED_CLASS_HASH)` (analogous to `test_replace_class` in the feature-contract test fixtures used by `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`).
2. Submit an `invoke` transaction from this account calling that function with `class_hash = 0x1234...` (a value never declared on-chain).
3. Run the same block through Blockifier: the syscall handler's `replace_class` (`syscall_base.rs:369-378`) calls `self.state.get_compiled_class(class_hash)`, which fails because the class is undeclared; the inner call/transaction reverts, and the contract's `class_hash` in the committed state diff is unchanged.
4. Run the identical block through the Starknet OS's Cairo `execute_syscalls` dispatch (`execute_syscalls.cairo:197-205` → `syscall_impls.cairo::execute_replace_class`, lines 881-920): there is no check against declared classes; `dict_update` unconditionally writes `new_state_entry.class_hash = class_hash` for the contract, and the call succeeds.
5. Compare the two state diffs for the contract's `class_hash` entry: Blockifier's committed diff shows no change (reverted), the OS's diff shows the contract's class hash replaced with the undeclared value - a concrete divergence in the committed/proved state for the same block and same transaction, reproducible deterministically by any unprivileged transaction sender.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
