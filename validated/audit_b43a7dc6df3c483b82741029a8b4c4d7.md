### Title
Quadratic-cost storage deep-copy on each nested CALL frame (`RepositoryImpl.getStorage`) allows disproportionate CPU/memory cost per unit of charged energy - ([File: actuator/src/main/java/org/tron/core/vm/repository/RepositoryImpl.java])

### Summary
When the energy-limit hard fork is active, every new child `Repository` created for a nested internal `CALL` performs a full deep copy of the parent's `Storage.rowCache` for any account it touches, via the `Storage(Storage)` copy constructor. Because each nested `CALL` frame creates a new repository and inherits (by deep copy) all storage rows already cached by its ancestors, a contract that recurses N times while touching one new storage slot per frame forces O(N²) total row-copy work, while the attacker is only charged O(N) fixed-cost SLOAD/SSTORE energy.

### Finding Description
`RepositoryImpl.getStorage(address)` at [1](#0-0)  deep-copies the parent repository's `Storage` object whenever `StorageUtils.getEnergyLimitHardFork()` is true:
```java
if (StorageUtils.getEnergyLimitHardFork()) {
  // deep copy
  storage = new Storage(parentStorage);
}
```
The `Storage(Storage)` constructor iterates the entire `rowCache` map of the parent and clones every `StorageRowCapsule` entry into a new `HashMap` [2](#0-1) . `getStorageInternal` (called from `putStorageValue`/`getStorageValue`) caches the resulting `Storage` per-repository instance in `storageCache` so repeated access *within the same call frame* is O(1) [3](#0-2) , but that cache is scoped to the current `Repository` — every new child repository created for a nested internal `CALL` starts a fresh `storageCache` and must re-deep-copy on first touch.

`ContractState`, which wraps the per-frame `Repository` used by the TVM interpreter, forwards `putStorageValue`/`getStorageValue`/`newRepositoryChild` calls directly to the underlying `repository` [4](#0-3) [5](#0-4) , so any `CALL` opcode that spawns a new internal transaction/repository and then touches storage (SLOAD/SSTORE) on an address will trigger this deep-copy path.

The cost asymmetry: each `SLOAD`/`SSTORE` is billed with a fixed, O(1) energy cost (`EnergyCost.getSstoreCost`/`getSloadCost`), independent of how many rows are already cached in the ancestor chain. However, if a contract recurses N times, and at each recursion depth touches one additional (new) storage key on the same address before making the next nested `CALL`, then at depth *k* the deep copy already contains *k* rows, so the cumulative row-copy work across the whole call chain is 1+2+...+N = O(N²), while the attacker pays only for N linear-cost SLOAD/SSTORE operations. No pre-seeded "thousands of storage rows" account is even required — the attacker can grow the ancestor `rowCache` organically within the same transaction by touching a new key at every nesting level.

There is no metering or backpressure mechanism that charges energy proportional to `rowCache` size or the cost of the deep copy; only the CPU-time watchdog (`vmShouldEndInUs`/`thisTxCPULimitInUs`) would eventually abort execution, but that only limits a single transaction's wall-clock time — it does not prevent the underlying algorithmic inefficiency from being repeatedly triggered cheaply by many such transactions across a block, degrading validator/full-node throughput.

### Impact Explanation
This is a scoped CPU/memory amplification (DoS-via-protocol-implementation) issue: energy charged for SLOAD/SSTORE is O(1) per call while the actual work performed by `RepositoryImpl.getStorage`/`Storage(Storage)` scales quadratically with the number of nested CALL frames touching new storage keys. This can be used to build transactions/contracts whose real execution cost (CPU and heap allocation for cloned `StorageRowCapsule` objects) is far larger than what the fee/energy market charges, allowing an attacker to degrade node performance more cheaply than intended, matching the "DoS via the TRON protocol implementation" bounty class. It does not directly cause fund theft, key leak, or consensus divergence by itself, since deterministic CPU cost is still identical across nodes.

### Likelihood Explanation
The attacker needs only an ordinary funded account able to deploy and call a contract, staying within the existing call-depth limit for nested internal CALLs; the exact depth-limit constant could not be confirmed within this codebase from the tools available, but standard TVM/EVM depth limits (historically 1024 in EVM-derived VMs) are large enough to allow non-trivial quadratic blowup. Cost to the attacker is bounded by the fixed per-transaction feeLimit/energy, while the CPU/memory cost paid by validating/executing nodes grows quadratically with recursion depth — a favorable amplification ratio for the attacker. The attack is fully repeatable and requires only standard, non-privileged transaction broadcast.

### Recommendation
Avoid full eager deep copies of `Storage.rowCache` on every nested repository creation. Consider a copy-on-write / layered (map-of-maps) storage cache design so that child repositories reference the parent's cache without cloning all entries, only recording deltas for keys they modify (this is the more common approach in EVM-derived clients). Alternatively, charge SLOAD/SSTORE energy proportional to the size of `rowCache` being copied at repository-creation time, or cap the number of allowed nested repository creations that touch storage per transaction, so the metered cost stays proportional to the incurred CPU/memory work.

  private Storage getStorageInternal(byte[] address) {
    address = TransactionTrace.convertToTronAddress(address);
    if (getAccount(address) == null) {
      return null;
    }
    Key addressKey = Key.create(address);
    Storage storage;
    if (storageCache.containsKey(addressKey)) {
      storage = storageCache.get(addressKey);
    } else {
      storage = getStorage(address);
      storageCache.put(addressKey, storage);
    }
    return storage;
  }

  @Override
  public Storage getStorage(byte[] address) {
    Key key = Key.create(address);
    if (storageCache.containsKey(key)) {
      return storageCache.get(key);
    }
    Storage storage;
    if (this.parent != null) {
      Storage parentStorage = parent.getStorage(address);
      if (StorageUtils.getEnergyLimitHardFork()) {
        // deep copy
        storage = new Storage(parentStorage);
      } else {
        storage = parentStorage;
      }
    } else {
      storage = new Storage(address, getStorageRowStore());
    }
    ContractCapsule contract = getContract(address);
    if (contract != null) {
      storage.setContractVersion(contract.getContractVersion());
      if (!ByteUtil.isNullOrZeroArray(contract.getTrxHash())) {
        storage.generateAddrHash(contract.getTrxHash());
      }
    }
    return storage;
  }
