### Title
Non-injective canonicalization in `stringifyQueryForAppProxy` allows parameter-boundary smuggling with a replayed valid signature - (File: packages/apps/shopify-api/lib/utils/hmac-validator.ts)

### Summary
`stringifyQueryForAppProxy` concatenates sorted `key=value` pairs with no delimiter between pairs and no encoding of `=`/`,` inside values, unlike `stringifyQueryForAdmin`, which relies on `ProcessedQuery.stringify(true)` (backed by `URLSearchParams`, which percent-encodes reserved characters and joins pairs with `&`). Because app-proxy values are already URL-decoded by the time they reach this function, an attacker can craft two structurally different `(key,value)` sets that serialize to the exact same canonical string, so a signature captured for one query is also valid for the other.

### Finding Description
`stringifyQueryForAppProxy` builds the string to be HMAC-signed like this: [1](#0-0) 

There is no separator between successive `key=value` pairs and no escaping of `=` inside a value. Because the query object passed into `generateLocalHmac`/`validateHmac` already has URL-decoding applied (e.g., via `URLSearchParams.entries()` in `normalizeQuery`), an attacker fully controls the literal characters (including `=`) inside any parameter value: [2](#0-1) 

This lets an attacker merge two adjacent (in sort order) parameters into one, moving the value of a real key into the value of another key without changing the resulting canonical string. For example, `{a:"1", b:"2", path_prefix, shop, timestamp}` and `{a:"1b=2", path_prefix, shop, timestamp}` (with `b` dropped entirely and its content folded into `a`) both canonicalize to identical strings, so `createSHA256HMAC` produces the same signature, and `validateHmac`'s `safeCompare` check passes for either structurally-distinct query: [3](#0-2) 

By contrast, the admin path is safe from this specific class of collision because `ProcessedQuery.stringify` uses `URLSearchParams.toString()`, which percent-encodes `=`, `&`, `,` inside keys/values and inserts `&` between pairs, making the mapping injective: [4](#0-3) 

`timestamp` is checked separately for freshness (90s tolerance) but not tied to the specific param structure that was actually signed, and `shop`/`path_prefix` values remain literally reusable across both queries, so the replay is otherwise unconstrained: [5](#0-4) 

### Impact Explanation
An attacker who legitimately triggers one signed app-proxy request (e.g., as a normal storefront customer hitting the app's public proxy URL through Shopify) can, within the 90-second timestamp tolerance, replay that identical `timestamp`+`signature` against the app's proxy endpoint directly (bypassing Shopify) with a *different* parameter structure that canonicalizes identically. This is accepted as an authentically-signed app-proxy request even though it was never actually signed for that structure — a forged/smuggled app-proxy request accepted as authentic, matching the "accepted forged webhook/proxy request" impact class. Downstream app logic that branches on specific parameter names/values (e.g., distinguishing `a` and `b`) can be deceived into treating attacker-smuggled content as a still-signed, trusted value.

### Likelihood Explanation
The attacker needs no special access: any unprivileged client can generate the initial legitimately-signed request themselves (e.g., visiting the app's public proxy URL with a chosen query string), then must resend a crafted variant to the app server directly within the timestamp tolerance window. This requires the app's proxy endpoint to be reachable independent of Shopify's proxying infrastructure (typical for public HTTP servers), and requires the app to distinguish query keys in ways an attacker can exploit — feasibility is high and fully repeatable, though the practical damage depends on the specific keys/values a target app relies on.

### Recommendation
Make `stringifyQueryForAppProxy` injective: escape/percent-encode `=`, `&`, and `,` inside both keys and values (or reuse `URLSearchParams`-based serialization as in the admin path) and insert an unambiguous delimiter (e.g., `&`) between pairs before signing, matching Shopify's documented app-proxy canonicalization but with proper escaping so no two distinct parameter sets can serialize identically.

### Proof of Concept
```ts
import {generateLocalHmac, validateHmac} from 'packages/apps/shopify-api/lib/utils/hmac-validator';
// assume `config` is a ConfigInterface with a fixed apiSecretKey

test('appProxy canonicalization collision allows signature replay across different param sets', async () => {
  const timestamp = String(Math.floor(Date.now() / 1000));
  const originalQuery = {
    a: '1',
    b: '2',
    path_prefix: '/apps/proxy',
    shop: 'test-shop.myshopify.com',
    timestamp,
  };

  // Legitimately-signed query (as Shopify would sign it)
  const signature = await generateLocalHmac(config)(originalQuery, 'appProxy');

  // Structurally different query: "b" is folded into "a"'s value, no "b" key at all
  const forgedQuery = {
    a: '1b=2',
    path_prefix: '/apps/proxy',
    shop: 'test-shop.myshopify.com',
    timestamp,
    signature,
  };

  const isValid = await validateHmac(config)(forgedQuery, {signator: 'appProxy'});
  expect(isValid).toBe(true); // signature meant for {a:'1', b:'2', ...} validates for {a:'1b=2', ...}
});
```

function stringifyQueryForAppProxy(query: AuthQuery): string {
  return Object.entries(query)
    .sort(([val1], [val2]) => val1.localeCompare(val2))
    .reduce((acc, [key, value]) => {
      return `${acc}${key}=${Array.isArray(value) ? value.join(',') : value}`;
    }, '');
}

export function validateHmac(config: ConfigInterface) {
  return async (
    query: HmacQuery,
    {signator}: {signator: HMACSignator} = {signator: 'admin'},
  ): Promise<boolean> => {
    const normalizedQuery = normalizeQuery(query, signator);

    if (signator === 'admin' && !normalizedQuery.hmac) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain an HMAC value.',
      );
    }

    if (signator === 'appProxy' && !normalizedQuery.signature) {
      throw new ShopifyErrors.InvalidHmacError(
        'Query does not contain a signature value.',
      );
    }

    validateHmacTimestamp(normalizedQuery);

    const hmac =
      signator === 'appProxy'
        ? normalizedQuery.signature
        : normalizedQuery.hmac;
    const localHmac = await generateLocalHmac(config)(
      normalizedQuery,
      signator,
    );

    return safeCompare(hmac as string, localHmac);
  };
}

function normalizeQuery(query: HmacQuery, signator: HMACSignator): AuthQuery {
  if (!(query instanceof URLSearchParams)) {
    if (signator === 'appProxy') {
      for (const key of APP_PROXY_SINGLE_VALUE_PARAMS) {
        if (Array.isArray(query[key])) {
          throw new ShopifyErrors.InvalidHmacError(
            `Query parameter "${key}" must not appear more than once.`,
          );
        }
      }
    }

    return query;
  }

  const normalizedQuery = Object.create(null) as AuthQuery;
  for (const [key, value] of query.entries()) {
    const existingValue = normalizedQuery[key];
    if (existingValue === undefined) {
      normalizedQuery[key] = value;
    } else if (
      signator === 'appProxy' &&
      APP_PROXY_SINGLE_VALUE_PARAMS.has(key)
    ) {
      throw new ShopifyErrors.InvalidHmacError(
        `Query parameter "${key}" must not appear more than once.`,
      );
    } else {
      normalizedQuery[key] = `${existingValue},${value}`;
    }
  }

  return normalizedQuery;
}

function validateHmacTimestamp(query: AuthQuery) {
  const {timestamp} = query;

  if (
    timestamp === undefined ||
    timestamp === null ||
    Array.isArray(timestamp)
  ) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is missing or invalid',
    );
  }

  const parsedTimestamp = Number(timestamp);

  if (!Number.isInteger(parsedTimestamp)) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is missing or invalid',
    );
  }

  if (
    Math.abs(getCurrentTimeInSec() - parsedTimestamp) >
    HMAC_TIMESTAMP_PERMITTED_CLOCK_TOLERANCE_SEC
  ) {
    throw new ShopifyErrors.InvalidHmacError(
      'HMAC timestamp is outside of the tolerance range',
    );
  }
}
