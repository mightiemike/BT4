## Analysis [1](#0-0) 

Tracing the `ExecutePayload` flow: `evmFrom` is derived purely from `msg.Signer` (the transaction's actual signer) [2](#0-1) , while `universalAccountId` (owner/chain/chainId) is **entirely attacker-supplied** and only checked for basic structural validity in `ValidateBasic` [3](#0-2)  — there is no requirement that `evmFrom` match `universalAccountId.Owner`.

The keeper computes a deterministic `ueaAddr` from `universalAccountId` via the factory [4](#0-3) . If undeployed but funded, it auto-deploys the UEA [5](#0-4) , then calls `CallUEAExecutePayload` with attacker-supplied `verificationData`, and — critically — **deducts gas fees from `ueaAddr` unconditionally, regardless of whether execution succeeds or fails**: [6](#0-5) 

Since UEA addresses and their balances are publicly observable, and pre-funded-but-undeployed addresses are deterministically computable from any `(ChainNamespace, ChainId, Owner)` combination, an unprivileged attacker can:
1. Enumerate/observe a pre-funded, undeployed UEA belonging to a real owner.
2. Submit `MsgExecutePayload` with that victim's `universalAccountId` but their own bogus `verificationData` (not a valid signature from the actual owner).
3. The auto-deploy step triggers because the balance check only looks at `balance.Amount.Sign() == 0`, not ownership/authorization [7](#0-6) .
4. `CallUEAExecutePayload` reverts due to invalid signature at the UEA/precompile level, but this failure occurs **after** EVM gas has been consumed, producing a receipt with non-zero `GasUsed`.
5. `DeductGasFeesFromReceipt` is invoked regardless of `execErr`, charging real UPC value out of the **victim's** pre-funded UEA balance — not the attacker's own funds.

This lets an unprivileged attacker who has neither the private key nor authorization for a given `UniversalAccountId` repeatedly grief/drain a third party's pre-funded, not-yet-claimed UEA balance purely through gas-fee deduction on failed, unauthorized execution attempts.

I could not fully verify within available context (1) whether `CallUEAExecutePayload`/the signature-verifier precompile always produces a non-zero-gas receipt on an invalid-signature revert, and (2) the exact bound on `DeductGasFeesFromReceipt`'s deducted amount relative to `receipt.GasUsed`. These would need to be confirmed in `x/uexecutor/keeper/evm.go` and `x/uexecutor/keeper/fees.go` to fully size the drainable amount per call, but the structural issue — unconditional fee deduction from a target account before/without confirming the caller's authorization over that account — is clearly present in the code as read.

### Title
Unauthorized gas-fee drain from pre-funded, undeployed UEA via unauthenticated `ExecutePayload` probing - (`x/uexecutor/keeper/msg_execute_payload.go`)

### Summary
`ExecutePayload` auto-deploys and attempts execution on any UEA address derivable from an attacker-chosen `UniversalAccountId`, and unconditionally deducts gas fees from that UEA's balance even when execution fails due to invalid/unauthorized `verificationData`, letting an unprivileged attacker charge fees against a victim's pre-funded account they do not control.

### Finding Description
`evmFrom` (tx signer) and `universalAccountId.Owner` (attacker-supplied) are never checked for consistency before the auto-deploy and fee-deduction steps. Balance-based auto-deploy triggers for any pre-funded UEA regardless of who requests it [5](#0-4) . Fee deduction in Step 4 runs unconditionally on `execErr`, charging `ueaAddr`'s own balance rather than the caller's [8](#0-7) .

### Impact Explanation
An unprivileged attacker can drain a legitimate owner's pre-funded (not-yet-deployed) UEA balance via repeated failed/unauthorized `ExecutePayload` calls, consuming that account's funds as "gas fees" for actions the actual owner never authorized — a direct instance of gas-fee accounting corruption and unauthorized fund loss from an account that did not authorize the specific execution.

### Likelihood Explanation
High reachability: this only requires observing a public on-chain balance for a deterministic, computable UEA address and submitting an ordinary `MsgExecutePayload` transaction with arbitrary `verificationData` — no privileged access, validator collusion, or key compromise needed.

### Recommendation
Verify that `verificationData` cryptographically authenticates against `universalAccountId.Owner` (and that `evmFrom`/caller is authorized) **before** performing auto-deploy or any state-mutating EVM call, and/or skip fee deduction from the target UEA when execution fails due to authorization/signature failure rather than legitimate execution revert.

### Proof of Concept
1. Find an on-chain UEA address (deterministically derivable from `(ChainNamespace, ChainId, Owner)`) that has a nonzero `BaseDenom` balance but `isDeployed == false`.
2. As an unrelated attacker, submit `MsgExecutePayload` with that `UniversalAccountId`, a syntactically valid but unauthorized `VerificationData`, and any well-formed `UniversalPayload`.
3. Observe: `DeployUEAV2` triggers (balance > 0), `CallUEAExecutePayload` reverts due to invalid signature, yet `DeductGasFeesFromReceipt` still deducts gas fees from `ueaAddr`'s balance — reducing the victim-owned account's funds without their consent.

```go
func (k Keeper) ExecutePayload(ctx context.Context, evmFrom common.Address, universalAccountId *types.UniversalAccountId, universalPayload *types.UniversalPayload, verificationData string) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Get Caip2Identifier for the universal account
	caip2Identifier := universalAccountId.GetCAIP2()

	k.Logger().Info("execute payload",
		"from", evmFrom.Hex(),
		"chain", caip2Identifier,
		"owner", universalAccountId.Owner,
	)

	// Step 1: Validate payload and verificationData early (fast-fail before EVM work)
	if _, err := types.NewAbiUniversalPayload(universalPayload); err != nil {
		return errors.Wrapf(err, "invalid universal payload")
	}

	verificationDataVal, err := utils.HexToBytes(verificationData)
	if err != nil {
		return errors.Wrapf(err, "invalid verificationData format")
	}

	chainConfig, err := k.uregistryKeeper.GetChainConfig(sdkCtx, caip2Identifier)
	if err != nil {
		return errors.Wrapf(err, "failed to get chain config for chain %s", caip2Identifier)
	}

	if !chainConfig.Enabled.IsInboundEnabled {
		k.Logger().Warn("execute payload rejected: chain inbound disabled", "chain", caip2Identifier)
		return fmt.Errorf("inbound is disabled for chain %s", caip2Identifier)
	}

	factoryAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)

	// Step 2: Compute smart account address
	// Calling factory contract to compute the UEA address
	ueaAddr, isDeployed, err := k.CallFactoryToGetUEAAddressForOrigin(sdkCtx, evmFrom, factoryAddress, universalAccountId)
	if err != nil {
		return err
	}

	if !isDeployed {
		// only deploy if the UEA address has funds and not deployed yet
		ueaAccAddr := sdk.AccAddress(ueaAddr.Bytes())
		balance := k.bankKeeper.GetBalance(sdkCtx, ueaAccAddr, pchaintypes.BaseDenom)
		if balance.Amount.Sign() == 0 {
			k.Logger().Warn("execute payload rejected: UEA not deployed and has no balance",
				"chain", caip2Identifier,
				"owner", universalAccountId.Owner,
			)
			return fmt.Errorf("UEA is not deployed")
		}

		k.Logger().Info("auto-deploying UEA before execute (pre-funded address)",
			"uea", ueaAddr.Hex(),
			"balance", balance.Amount.String(),
			"chain", caip2Identifier,
			"owner", universalAccountId.Owner,
		)
		if _, err := k.DeployUEAV2(ctx, evmFrom, universalAccountId); err != nil {
			return errors.Wrapf(err, "failed to auto-deploy pre-funded UEA")
		}
	}

	k.Logger().Debug("executing payload via UEA",
		"uea", ueaAddr.Hex(),
		"chain", caip2Identifier,
		"from", evmFrom.Hex(),
	)

	// Step 3: Execute payload through UEA
	receipt, execErr := k.CallUEAExecutePayload(sdkCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 4: Deduct gas fees regardless of success/failure.
	// If deduction fails, return error so the entire Cosmos tx rolls back (including EVM state).
	if feeErr := k.DeductGasFeesFromReceipt(ctx, sdkCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		return fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		return execErr
	}

	k.Logger().Info("payload executed via direct msg",
		"chain", caip2Identifier,
		"uea", ueaAddr.Hex(),
		"tx_hash", receipt.Hash,
		"gas_used", receipt.GasUsed,
	)

	// Step 5
	pcTx := types.PCTx{
		Sender:      evmFrom.Hex(),
		TxHash:      receipt.Hash,
		GasUsed:     receipt.GasUsed,
		BlockHeight: uint64(sdkCtx.BlockHeight()),
		Status:      "SUCCESS",
	}

	// Step 6: create outbound + UTX only if needed
	if err := k.CreateUniversalTxFromReceiptIfOutbound(sdkCtx, receipt, pcTx); err != nil {
		return err
	}
	if err := k.AttachRescueOutboundFromReceipt(sdkCtx, receipt, pcTx); err != nil {
		return err
	}

	return nil
```

```go
func (msg *MsgExecutePayload) ValidateBasic() error {
	// Validate signer
	if _, err := sdk.AccAddressFromBech32(msg.Signer); err != nil {
		return errors.Wrap(err, "invalid signer address")
	}

	// Validate universalAccountId
	if msg.UniversalAccountId == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal account cannot be nil")
	}

	// Validate universal payload
	if msg.UniversalPayload == nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "universal payload cannot be nil")
	}

	// Validate verificationData
	if len(msg.VerificationData) == 0 {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "verificationData cannot be empty")
	}
	if _, err := hex.DecodeString(strings.TrimPrefix(msg.VerificationData, "0x")); err != nil {
		return errors.Wrap(sdkerrors.ErrInvalidRequest, "invalid verificationData hex")
	}

	// Validate universalAccountId structure
	if err := msg.UniversalAccountId.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universalAccountId")
	}

	// Validate universal payload structure
	if err := msg.UniversalPayload.ValidateBasic(); err != nil {
		return errors.Wrap(err, "invalid universal payload")
	}

	return nil
}
```
