### Title
Gas/Compute-Unit Mispricing in `SyscallGetProcessedSiblingInstruction` — Flat Cost for Unbounded Linear Scan of the Instruction Trace - ([File: syscalls/src/lib.rs])

### Summary
`SyscallGetProcessedSiblingInstruction` (the `sol_get_processed_sibling_instruction` syscall) charges a single flat `syscall_base_cost` (100 CU by default) regardless of how much work it actually performs internally. The syscall implementation walks backward over a slice of the transaction's instruction trace whose length is proportional to the number of previously-executed CPIs (or the number of top-level instructions), meaning its real cost scales with `O(trace length)` while its billed cost is `O(1)`. This is the same bug class as the CosmWasm `wasmvm` advisory: a fixed/benchmark-based charge that does not track the actual computational cost of an operation, allowing programs to consume far more real CPU time than their charged compute units reflect.

### Finding Description
The syscall is implemented at [1](#0-0) :

- Cost accounting: `invoke_context.compute_meter.consume_checked(execution_cost.syscall_base_cost)?;` — a single flat charge, independent of any parameter or of how much the subsequent search touches.
- Actual work: the function then computes a `range` to scan:
  - If at top level (`stack_height == 1`): `0..next_top_level_instruction_index()`.
  - Otherwise (inside a CPI): `start..end` where `end = get_instruction_trace_length()` and `start = end - number_of_cpis_in_trace()`.
  It then iterates `for index_in_trace in range.rev()`, calling `get_instruction_context_at_index_in_trace()` and doing several field comparisons (`get_index_of_caller()`, `get_stack_height()`) for every entry in that range until a match or the scan naturally terminates.

This scan length grows with the number of already-processed instructions/CPIs in the *same transaction* prior to the syscall invocation — a value fully controlled by the caller (an ordinary, unprivileged transaction sender can construct a transaction with many top-level instructions and/or a deep, wide CPI tree before invoking a program that calls this syscall). Every one of those N trace entries is a real memory access, bounds-check, and equality comparison performed by the validator's runtime — none of that is compute-metered beyond the flat 100 CU.

Compare this with essentially every other syscall/cost model entry in the same file, which explicitly scales cost with the size of the work performed, e.g. `mem_op_consume` in [2](#0-1) , the CPI account-meta/translation cost in [3](#0-2) , or `SyscallGetEpochStake`'s explicit per-byte accounting in [4](#0-3) . `SyscallGetProcessedSiblingInstruction` is the outlier that does not charge for the size of the search space it traverses.

### Impact Explanation
A malicious (but ordinary, unprivileged) transaction sender can:
1. Construct a transaction that maximizes the instruction trace before invoking the vulnerable syscall — e.g., many top-level instructions and/or deep/wide CPI trees (bounded only by `max_instruction_trace_length` / `MAX_CALL_DEPTH` in `program-runtime/src/execution_budget.rs`, and by the transaction's overall compute-unit budget for issuing those prior instructions).
2. Repeatedly call `sol_get_processed_sibling_instruction` from deep in that CPI tree.

Each call is billed at a flat ~100 CU but performs work proportional to the size of the already-built trace. Because the number of calls a program can make is bounded only by `compute_unit_limit / syscall_base_cost` (with today's default limits, thousands of calls are affordable), while each call's real cost scales with the (attacker-controlled) trace size, the validator can be made to do substantially more CPU work per transaction than the transaction's nominal compute-unit cost implies. This mirrors the CosmWasm advisory's "up to ~10x more execution time than the gas charge suggests," creating a per-transaction/per-block execution-time amplification that can be used to slow down block processing (a leader-processing/DoS-style impact), which is the exact impact class flagged in the external report (CWE-400, Improper Restriction of Power Consumption).

Because this only affects real-time-vs-charged-CU proportionality (not funds, replay, or consensus divergence directly), the practical severity is bounded — similar to the "Medium" severity of the original advisory — but it is a genuine, unprivileged-sender-reachable gas-mispricing bug in the SVM syscall layer.

### Likelihood Explanation
High likelihood of reachability: the syscall is registered and available to any on-chain BPF/SBF program (see registration in [5](#0-4) ), requires no special privileges, and the instruction-trace size is fully attacker-controlled via ordinary CPI/instruction construction within existing per-transaction limits. No feature gate, admin permission, or validator-operator cooperation is needed — an ordinary client transaction suffices.

### Recommendation
Charge `SyscallGetProcessedSiblingInstruction` proportionally to the size of the search range it scans (e.g., `syscall_base_cost + mem_op_base_cost.max(range.len() / cpi_bytes_per_unit)` or a dedicated per-entry cost constant), consistent with how other O(n) syscalls (`SyscallHash`, CPI translation, `mem_op_consume`) charge for their traversal/translation cost. This should be done via a SIMD/feature-gated change since it alters consensus-relevant compute-unit accounting.

### Proof of Concept
Conceptual (not exhaustively test-executed given tool constraints):
1. Build a transaction with many top-level instructions and/or a wide/deep CPI invocation tree using a helper program (e.g., patterned after `programs/sbf/rust/sibling_instructions/src/lib.rs` and `sibling_inner_instructions/src/lib.rs`, which already exercise this syscall) so that `get_instruction_trace_length()` / `number_of_cpis_in_trace()` is maximized within `max_instruction_trace_length`/`MAX_CALL_DEPTH`.
2. From the deepest/last CPI, repeatedly invoke `sol_get_processed_sibling_instruction(index, ...)` with a non-matching `index` so the full range is scanned every time without early return.
3. Measure wall-clock/validator CPU time consumed by this instruction versus the compute units actually deducted (`syscall_base_cost` per call, per [6](#0-5) ) — the ratio of real work to billed CU grows with the trace size, unlike comparable syscalls that charge per-byte/per-entry.

Note: I was unable to retrieve the exact numeric value of `MAX_INSTRUCTION_TRACE_LENGTH`/`max_instruction_trace_length` in this pass (searches returned file locations but not the constant's value), so I cannot quantify the precise worst-case amplification factor; the structural mispricing (flat charge vs. O(n) work) is, however, clearly established from the cited code.

declare_builtin_function!(
    /// Get a processed sigling instruction
    SyscallGetProcessedSiblingInstruction,
    fn rust(
        invoke_context: &mut InvokeContext<'_, '_>,
        index: u64,
        meta_addr: u64,
        program_id_addr: u64,
        data_addr: u64,
        accounts_addr: u64,
    ) -> Result<u64, Error> {
        let execution_cost = invoke_context.get_execution_cost();

        invoke_context.compute_meter.consume_checked(execution_cost.syscall_base_cost)?;

        let stack_height = invoke_context.get_stack_height();
        let mut reverse_index_at_stack_height = 0;
        let mut found_instruction_context = None;
        let current_ix_caller = invoke_context.transaction_context.get_current_instruction_context()?.get_index_of_caller();

        // Either we only search for top level instructions or CPIs, depending on the stack height.
        let range = if stack_height == 1 {
            0..invoke_context.transaction_context.next_top_level_instruction_index()
        } else {
            let end = invoke_context.transaction_context.get_instruction_trace_length();
            let start = end.saturating_sub(invoke_context.transaction_context.number_of_cpis_in_trace());
            start..end
        };

        for index_in_trace in range.rev() {
            let instruction_context = invoke_context
                .transaction_context
                .get_instruction_context_at_index_in_trace(index_in_trace)?;
            // If we are searching through CPIs, sibling instructions must have the same caller
            // but instructions from different callers are interspaced in the frame.
            if instruction_context.get_index_of_caller() != current_ix_caller {
                continue;
            }

            if instruction_context.get_stack_height() < stack_height {
                break;
            }
            if instruction_context.get_stack_height() == stack_height {
                if index.saturating_add(1) == reverse_index_at_stack_height {
                    found_instruction_context = Some(instruction_context);
                    break;
                }
                reverse_index_at_stack_height = reverse_index_at_stack_height.saturating_add(1);
            }
        }

fn mem_op_consume(invoke_context: &mut InvokeContext, n: u64) -> Result<(), Error> {
    let compute_cost = invoke_context.get_execution_cost();
    let cost = compute_cost.mem_op_base_cost.max(
        n.checked_div(compute_cost.cpi_bytes_per_unit)
            .unwrap_or(u64::MAX),
    );
