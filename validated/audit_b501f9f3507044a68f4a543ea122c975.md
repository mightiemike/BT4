## Finding Assessment

The premise citing `AccountStore.get(byte[])` as the vulnerable method is inaccurate — `AccountStore` is not on this read path at all. The actual code responsible for the unbounded read cost is `DelegatedResourceAccountIndexStore.getV2Index()` / `getWithPrefix()`, reached via `Wallet.getDelegatedResourceAccountIndexV2()` from `GetDelegatedResourceAccountIndexV2Servlet.fillResponse()`. The underlying behavioral concern described (unbounded per-query cost proportional to attacker-created state) is real once traced through the correct files, so I'm reporting it against the actual code path rather than rejecting outright.

### Title
Unbounded RocksDB prefix scan in `DelegatedResourceAccountIndexStore.getV2Index` allows attacker-inflated per-query cost via `/wallet/getdelegatedresourceaccountindexv2` - ([File: chainbase/src/main/java/org/tron/core/store/DelegatedResourceAccountIndexStore.java])

### Summary
`DelegateResourceContract` (V2 delegation) writes one new key-value pair per unique `(owner, receiver)` pair into `DelegatedResourceAccountIndexStore` under prefixes `V2_FROM_PREFIX`/`V2_TO_PREFIX`, with no cap on how many distinct receivers/senders an address can accumulate. Any anonymous caller to `/wallet/getdelegatedresourceaccountindexv2` (or `/walletsolidity/...`, PBFT/Solidity variants) triggers `getWithPrefix`, which performs a full prefix scan, deserializes every matching entry, sorts them, and serializes the full result — cost scaling linearly (with sorting, O(N log N)) with the number of delegation relationships the target address has ever created.

### Finding Description
`DelegateResourceActuator.delegateResource()` calls `delegatedResourceAccountIndexStore.delegateV2(ownerAddress, receiverAddress, timestamp)` [1](#0-0)  which stores two brand-new keys per delegation — `V2_FROM_PREFIX+owner+receiver` and `V2_TO_PREFIX+receiver+owner` — rather than appending to a single bounded list value [2](#0-1) . Each unique receiver an attacker delegates to therefore creates a permanent new DB record until explicitly un-delegated.

The read path, `getV2Index(address)` → `getWithPrefix(V2_FROM_PREFIX, V2_TO_PREFIX, address)`, performs two `prefixQuery` calls that collect *all* matching keys into an `ArrayList`, sort by timestamp, and rebuild full `toAccounts`/`fromAccounts` lists with no limit, offset, or pagination [3](#0-2) . This is invoked by `Wallet.getDelegatedResourceAccountIndexV2()` [4](#0-3) , which is called directly by the unauthenticated HTTP servlet `GetDelegatedResourceAccountIndexV2Servlet.fillResponse()` for both GET and POST, with only an address-format check and no ACL [5](#0-4) . The same servlet is mounted on FullNode, SolidityNode, PBFT, and Solidity interfaces [6](#0-5) .

The only mitigating control is `RateLimiterServlet`, which the servlet extends [7](#0-6) , but this limits request *rate*, not per-request cost — it does not bound the size of the prefix scan or the resulting serialized payload.

### Impact Explanation
This falls under the "DoS via RPC-API" bounty class. An attacker who has locked N TRX distributed as ≥1-TRX delegations to N distinct receiver addresses causes every subsequent query for that owner address (or any of the N receiver addresses, via the `TO_PREFIX` scan) to perform O(N) DB reads, protobuf deserialization/serialization, and O(N log N) sorting per request. Because this is exposed on public, unauthenticated HTTP/gRPC endpoints and mirrored across FullNode/SolidityNode/PBFT/Solidity interfaces, any third party who knows the address can repeatedly trigger this expensive computation, degrading node responsiveness for that endpoint and consuming CPU/memory disproportionate to the caller's own effort.

### Likelihood Explanation
The attacker needs only a funded, ordinary account — no special privileges. Cost is bounded by needing to freeze/lock roughly 1 TRX per unique receiver address (minimum `delegateBalance` enforced by `DelegateResourceActuator.validate()` [8](#0-7) ) plus ordinary bandwidth/energy fees per transaction — this capital is not burned and can eventually be unfrozen, making it a temporary-liquidity cost rather than a permanent loss. Building tens of thousands of entries is a realistic and repeatable action requiring no more than scripted transaction broadcasting; there is no on-chain limit on the number of distinct delegation relationships a single address may hold in `DelegatedResourceAccountIndexStore`.

### Recommendation
Add pagination (limit/offset or cursor-based) to `getWithPrefix`/`getV2Index` and its gRPC/HTTP surface (`GetDelegatedResourceAccountIndexV2Servlet`, corresponding gRPC handler), and/or cap the number of delegation relationships tracked per address (or store aggregate/paginated indices rather than unbounded per-address prefix scans). At minimum, enforce a hard cap on entries returned per query and reject/paginate beyond that cap.

### Proof of Concept
1. Fund one attacker account and freeze balance for bandwidth (`FreezeBalanceV2Contract`).
2. Script N `DelegateResourceContract` transactions from the attacker account to N unique freshly generated receiver addresses, each delegating the 1-TRX minimum (mirrors `DelegateResourceActuatorTest.testDelegateResourceForBandwidth` pattern [9](#0-8) , repeated for N distinct receivers).
3. Issue repeated HTTP requests:
```
POST /wallet/getdelegatedresourceaccountindexv2
{"visible": true, "value": "<attacker_address>"}
```
4. Measure response latency/allocation as N scales (e.g., N=1,000 vs N=100,000), confirming the `toAccountsList` size and query latency grow linearly/super-linearly with N, matching `getWithPrefix`'s unbounded prefix-scan-and-sort logic [3](#0-2) . A JUnit-level equivalent can directly call `delegatedResourceAccountIndexStore.delegateV2()` N times then benchmark `getV2Index()` invocation time, as exercised (at small scale) in `DelegatedResourceAccountIndexStoreTest.testGetV2Index` [10](#0-9) .

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }

  public void testDelegateResourceForBandwidth() {
    freezeBandwidthForOwner();
    long delegateBalance = 1_000_000_000L;
    DelegateResourceActuator actuator = new DelegateResourceActuator();
    actuator.setChainBaseManager(dbManager.getChainBaseManager()).setAny(
        getDelegateContractForBandwidth(OWNER_ADDRESS, RECEIVER_ADDRESS, delegateBalance));

    TransactionResultCapsule ret = new TransactionResultCapsule();
    long totalNetWeightBefore = dbManager.getDynamicPropertiesStore().getTotalNetWeight();
    byte[] owner = ByteArray.fromHexString(OWNER_ADDRESS);
    byte[] receiver = ByteArray.fromHexString(RECEIVER_ADDRESS);
    try {
      actuator.validate();
      actuator.execute(ret);
      assertEquals(code.SUCESS, ret.getInstance().getRet());
      AccountCapsule ownerCapsule =
          dbManager.getAccountStore().get(owner);

      assertEquals(delegateBalance, ownerCapsule.getDelegatedFrozenV2BalanceForBandwidth());
      assertEquals(initBalance - delegateBalance,
          ownerCapsule.getFrozenV2BalanceForBandwidth());
      assertEquals(initBalance, ownerCapsule.getTronPower());

      AccountCapsule receiverCapsule =
          dbManager.getAccountStore().get(receiver);
      assertEquals(delegateBalance,
          receiverCapsule.getAcquiredDelegatedFrozenV2BalanceForBandwidth());
      assertEquals(0L, receiverCapsule.getAcquiredDelegatedFrozenV2BalanceForEnergy());
      assertEquals(0L, receiverCapsule.getTronPower());

      DelegatedResourceCapsule delegatedResourceCapsule = dbManager.getDelegatedResourceStore()
          .get(DelegatedResourceCapsule
              .createDbKeyV2(ByteArray.fromHexString(OWNER_ADDRESS),
                  ByteArray.fromHexString(RECEIVER_ADDRESS), false));

      assertEquals(delegateBalance, delegatedResourceCapsule.getFrozenBalanceForBandwidth());
      long totalNetWeightAfter = dbManager.getDynamicPropertiesStore().getTotalNetWeight();
      assertEquals(totalNetWeightBefore, totalNetWeightAfter);

      //check DelegatedResourceAccountIndex
      DelegatedResourceAccountIndexCapsule ownerIndexCapsule = dbManager
          .getDelegatedResourceAccountIndexStore().getV2Index(owner);
      assertEquals(0, ownerIndexCapsule.getFromAccountsList().size());
      assertEquals(1, ownerIndexCapsule.getToAccountsList().size());
      assertTrue(ownerIndexCapsule.getToAccountsList()
          .contains(ByteString.copyFrom(ByteArray.fromHexString(RECEIVER_ADDRESS))));

      DelegatedResourceAccountIndexCapsule receiveCapsule = dbManager
          .getDelegatedResourceAccountIndexStore().getV2Index(receiver);
      assertEquals(0, receiveCapsule.getToAccountsList().size());
      assertEquals(1, receiveCapsule.getFromAccountsList().size());
      assertTrue(receiveCapsule.getFromAccountsList()
          .contains(ByteString.copyFrom(ByteArray.fromHexString(OWNER_ADDRESS))));

    } catch (ContractValidateException | ContractExeException e) {
      fail(e.getMessage());
    }
