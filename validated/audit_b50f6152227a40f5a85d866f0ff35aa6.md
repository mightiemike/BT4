### Title
Autoswap deposit conversion (`ExecuteInboundGas` / `ExecuteInboundGasAndPayload`) relies on a manipulable spot AMM quote with only a fixed 5% slippage guard, letting an unprivileged attacker force bridging users to receive far less PC than fair value - ([File: x/uexecutor/keeper/execute_inbound_gas.go], [File: x/uexecutor/keeper/evm.go])

### Summary
The external report describes a griefing pattern where an attacker manipulates a value the protocol trusts as "safe" (the reward-token balance) just before a user-facing action executes, causing the user to receive far less than they are entitled to. The Push Chain analog is the `GAS`/`GAS_AND_PAYLOAD` inbound execution path, which fetches a live spot quote from the Uniswap-style `QuoterV2` and applies only a hard-coded 5% slippage band before performing the actual auto-swap deposit. An unprivileged attacker who trades against the same on-chain PRC20/WPC pool immediately before the module's deterministic auto-swap executes can push the spot price to the edge of that 5% band, causing bridging users' assets to be swapped into PC at a manipulated rate while the attacker profits by reversing the trade.

### Finding Description
For `GAS` and `GAS_AND_PAYLOAD` inbound transactions, the keeper computes the amount of PC a user should receive for their bridged gas-token deposit by:

1. Calling `GetSwapQuote`, which reads a live spot quote via `QuoterV2.quoteExactInputSingle` [1](#0-0) .
2. Computing `minPCOut = quote * 95 / 100` — a flat 5% slippage tolerance with no time-weighted or historical price reference [2](#0-1) .
3. Immediately calling `CallPRC20DepositAutoSwap` with that `minPCOut`, which deposits the PRC20 and swaps it for PC on the same pool [3](#0-2) .

The same pattern is used for `GAS_AND_PAYLOAD` inbound executions (`gasAndPayloadDepositAutoSwap`) and for excess-gas refunds (`applyGasRefund` → `getSwapQuoteForRefund` → `CallUniversalCoreRefundUnusedGas` with swap) [4](#0-3) .

Because the quote source is the pool's instantaneous spot price rather than a manipulation-resistant reference (e.g., TWAP), and the slippage bound is a fixed percentage of that same manipulable quote, an attacker can:
- Trade against the PRC20/WPC pool (an ordinary, unprivileged DEX interaction) to move the spot price unfavorably for the pending inbound's swap direction, staying within a range that still respects the eventual 5% band computed from the *already-skewed* price.
- Wait for (or predictably trigger, since inbound ballot finalization and execution timing are observable on-chain) the module-originated `depositPRC20WithAutoSwap`/`refundUnusedGas` call to execute at the skewed price.
- Reverse their own trade afterward, capturing the value that the bridging user should have received as PC.

This mirrors the TribeRedeemer bug class exactly: a protocol invariant ("the balance/price used to compute payout is trustworthy") is silently satisfied by attacker-supplied external state (pool balance/price) rather than protocol-controlled truth, and an honest user's automatic, non-cancelable action (their bridge deposit) executes against that corrupted value with real fund loss.

### Impact Explanation
This corrupts native/PRC20 asset accounting for bridged gas-token deposits and gas refunds: a legitimate bridging user's tokens are converted through `depositPRC20WithAutoSwap` at a manipulated exchange rate, resulting in permanent, unrecoverable loss of value to the user with no compensating mechanism (the deposit and swap are executed atomically and irreversibly by the module) — this falls squarely in the "unauthorized burn/unauthorized release" and "corruption of PRC20 or native asset accounting" impact categories in scope.

### Likelihood Explanation
Likelihood is bounded by pool liquidity depth and observability of pending inbounds, similar to the original finding's caveat about needing "external requirements." An attacker only needs: (1) knowledge that a `GAS`/`GAS_AND_PAYLOAD` inbound (or gas refund) is queued for execution — which is derivable from on-chain pending-inbound/ballot state — and (2) the ability to trade on the referenced PRC20/WPC pool, both requiring no privileged role, keys, validator status, or peer trust. Newly bridged or thin-liquidity PRC20 pairs make this materially easier, similar to how the TribeRedeemer bug was "unlikely but real" due to external preconditions.

### Recommendation
- Replace the single-block spot `QuoterV2` quote with a TWAP or otherwise manipulation-resistant price source, or widen/adjust the slippage tolerance based on pool liquidity depth rather than a flat 5%.
- Consider a maximum acceptable price-impact check independent of the quote itself (e.g., compare against a recent moving average or an oracle-fed reference price) before executing `depositPRC20WithAutoSwap` / `refundUnusedGas` with swap.
- Optionally add a cooldown/commit-reveal or batched execution model so pending inbound executions are not trivially predictable and front-runnable.

### Proof of Concept
1. Validators finalize quorum on a `GAS` inbound for victim V bridging token X, which is scheduled to auto-swap X → PC via `ExecuteInboundGas` [5](#0-4) .
2. Attacker, observing the pending/eligible inbound (or timing it around any bridge deposit that reaches quorum), submits a swap into the X/WPC pool that pushes the pool price against V's expected receive amount.
3. The module's `GetSwapQuote` reads this skewed spot price and computes `minPCOut` as 95% of it, guaranteeing the auto-swap will still execute at the unfavorable rate [6](#0-5) .
4. `CallPRC20DepositAutoSwap` executes, minting V's PRC20 and swapping it for PC at the manipulated rate, and V's UEA receives materially less PC than fair market value [3](#0-2) .
5. Attacker reverses their trade in the pool, extracting the value difference as profit — analogous to the malicious pre-funder in the TribeRedeemer report capturing the delta between a naive user's expectation and the actual corrupted-state payout.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// Calls Handler Contract to deposit prc20 tokens with auto-swap.
// fee and minPCOut must be pre-computed by the caller (see GetDefaultFeeTierForToken / GetSwapQuote).
func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}
