### Title
Missing declared-class validation in Starknet OS `execute_replace_class` allows accepting a `replace_class` syscall with an undeclared class hash — (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The `replace_class` syscall handler in the blockifier enforces that the target `class_hash` has actually been declared before updating a contract's class hash, but the equivalent logic re-executed by the Starknet OS (SNOS) during proving/verification is missing this check — it only carries a `TODO` comment noting the check is not implemented.

### Finding Description
In the blockifier's syscall implementation, `replace_class` explicitly verifies the class is declared before mutating state: [1](#0-0) 

The Cairo1 native handler simply forwards to the same base logic that performs this check: [2](#0-1) 

However, in the Starknet OS program that re-executes/verifies transactions (used for state-transition validation and proof generation), the corresponding `execute_replace_class` function updates `contract_state_changes` with the requested `class_hash` **without ever checking that the class was declared**, and explicitly documents this gap with a TODO: [3](#0-2) 

The same unchecked pattern exists in the deprecated (Cairo0) syscall execution path used by the OS: [4](#0-3) 

This is directly analogous to the reported Solidity bug class: a state-mutating operation that is documented/expected to be gated by a validity check (there: `onlyPoolManager`; here: "class must be declared") but the actual code path omits the check, while comments/TODOs and the sibling implementation (blockifier) confirm the check was intended.

### Impact Explanation
`replace_class` is a syscall reachable by any contract during ordinary `__execute__`/entry-point execution of a single, unprivileged transaction — there is no special privilege required to invoke it. Because the Starknet OS is the component that independently re-executes transactions to compute/verify the committed state root (and is meant to be the ground-truth arbiter for state transition correctness used in proving), a missing validation there means the OS-side state transition function is more permissive than the blockifier's. Any code path, tooling, or future change that derives contract state updates from the OS's `execute_replace_class` (rather than strictly gating on the blockifier's prior check) could commit a contract's class hash to an undeclared/non-existent class, corrupting the state tree entry for that contract (effectively bricking or freezing the account/contract, since subsequent calls would try to resolve compiled classes that don't exist) and creating a discrepancy between what the sequencer's execution engine would have allowed and what the OS accepts as a valid state transition — a wrong committed state root / re-execution divergence.

### Likelihood Explanation
The syscall is trivially reachable from any Cairo contract via a standard invoke transaction containing a `replace_class_syscall(class_hash)` call, with `class_hash` fully attacker-controlled. The missing check is unconditional in the OS's syscall execution path (not gated behind any rare feature flag), and the code even contains an explicit `TODO` acknowledging that the intended validation is not present, confirming this is a real, currently-unimplemented gap in the OS's re-execution semantics rather than a defense-in-depth redundancy.

### Recommendation
Add the missing declared-class check to `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`, mirroring the blockifier's `get_compiled_class` check, so that the OS rejects (or reverts) any `replace_class` syscall referencing an undeclared class hash, keeping the OS's state-transition semantics consistent with the blockifier's.

### Proof of Concept
1. A contract invokes `replace_class_syscall(class_hash)` with an arbitrary/never-declared `class_hash` (e.g., an unused felt value) — this is a normal external entry point call from any unprivileged sender.
2. In blockifier execution, `state.get_compiled_class(request.class_hash)` fails, and the transaction reverts/fails, as shown in [5](#0-4) .
3. When the same syscall trace is processed by the Starknet OS's `execute_replace_class`, no equivalent check exists — the function unconditionally writes the new `class_hash` into `contract_state_changes`, as shown in [6](#0-5) , meaning any input/trace that reaches this OS function with an undeclared class hash is accepted rather than rejected.

func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
