### Title
`system-repay` division-by-zero when total-debt is zero freezes repayment and strands rounding dust in `total-borrowed` - (File: `mainnet/contracts/vault/v0-vault-usdc.clar` and sibling vault contracts)

### Summary
`system-repay` computes `calc-principal-ratio-reduction` (a `mul-div-down` with `debt` as the denominator) as part of its `let` bindings, before any of the function's guard `asserts!` run. If `total-debt` evaluates to `u0` (which happens whenever `principal-scaled` is `u0`), this division by zero causes the whole call to `panic`/revert instead of failing gracefully, and it can be reached precisely in the state that legitimately arises after a full repayment leaves rounding dust in `total-borrowed`.

### Finding Description
In every mainnet vault contract (`v0-vault-usdc.clar`, `v0-vault-sbtc.clar`, `v0-vault-stx.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdh.clar`), `system-repay` is defined as: [1](#0-0) 

The `let` block computes `debt (total-debt)`, then `capped-amount (if (> amount debt) debt amount)`, then `principal-reduction (calc-principal-ratio-reduction capped-amount scaled-principal debt)` — all **before** the `asserts!` guards for `amount > 0` and the `repay` pause flag are checked. `calc-principal-ratio-reduction` is: [2](#0-1) 

which is `mul-div-down amount scaled-principal debt-amount`, i.e. `(/ (* amount scaled-principal) debt-amount)`. `total-debt` is: [3](#0-2) 

`calc-cumulative-debt` uses `mul-div-up`, which rounds **up**, so `total-debt` is `u0` exactly when `principal-scaled` is `u0` — i.e., no outstanding borrow principal. In that state, `capped-amount` collapses to `u0` (since `amount > debt(=0)` is true for any positive `amount`, so `capped-amount = debt = u0`), and `principal-reduction` becomes `mul-div-down u0 u0 u0` = `(/ (* 0 0) 0)`, a division by zero that causes the Clarity runtime to abort the transaction.

This state (`principal-scaled = u0` while `total-borrowed > u0`) is reachable in normal operation: a full repayment leaves `total-borrowed` with dust because `principal-repaid` is computed with `mul-div-down` (rounds down): [4](#0-3) 

If `principal-reduction` rounds such that `capped-reduction = scaled-principal` (full zeroing of scaled principal) while `principal-repaid` rounds down and leaves `total-borrowed-new > u0`, `principal-scaled` becomes `u0` but `total-borrowed` retains a dust residue. Any later call to `system-repay` (e.g., the market contract's ordinary repay/liquidation flow attempting to clear that dust or repay again) will hit `debt = 0` and revert with an unguarded division-by-zero instead of a clean error, because the computation happens before the guard checks (mutation-before-guard evaluation order).

### Impact Explanation
This is a temporary freezing of funds: the dust left in `total-borrowed` is never repayable through the normal `system-repay` path once `principal-scaled` reaches `u0`, because every subsequent attempt to call `system-repay` for that vault's outstanding dust reverts on division by zero rather than completing. That dust permanently understates `get-available-assets` (`assets - total-borrowed`), i.e., it phantom-reduces withdrawable/available liquidity by that amount indefinitely, since there is no in-scope way to clear `total-borrowed` back down once `principal-scaled` is zero and `system-repay` cannot execute in that state. This lands on the in-scope Impact class of "temporary/permanent freezing of funds" (a small amount of protocol liquidity, not user principal at rest, becomes permanently unusable).

### Likelihood Explanation
Likelihood is driven purely by rounding in `mul-div-down`/`mul-div-up`, which occurs routinely under normal repay traffic — no attacker action, privileged access, or oracle manipulation is required, only ordinary sequences of borrow/partial-repay/full-repay calls through the market contract that legitimately reach `system-repay` while `total-debt` is `u0`.

### Recommendation
Guard `system-repay` against `debt == u0` by returning early (e.g., treat as a no-op success, or `asserts! (> debt u0) ERR-...`) before computing `capped-amount`/`principal-reduction`, and add an explicit zero-check inside `calc-principal-ratio-reduction` (mirroring the zero-guards already present in `convert-to-shares-preview`/`convert-to-assets-preview`) so that `mul-div-down` is never invoked with a zero denominator.

### Proof of Concept
1. Market borrows an amount via `system-borrow`, setting `principal-scaled > 0`, `total-borrowed = B`.
2. Over several partial repayments via `system-repay`, rounding in `principal-repaid (mul-div-down capped-amount total-borrowed-amount debt)` accumulates such that a final repayment call zeroes `principal-scaled` (via `capped-reduction = scaled-principal`) while `total-borrowed-new` still has 1+ units of dust (rounded down).
3. `principal-scaled` is now `u0`, so `total-debt` returns `u0` on every subsequent read.
4. Any later call to `system-repay amount` (amount > 0) computes `capped-amount = u0` then evaluates `calc-principal-ratio-reduction u0 u0 u0` → `(/ (* 0 0) 0)` → transaction aborts.
5. The dust in `total-borrowed` can never be cleared through `system-repay`, permanently reducing `get-available-assets` by that dust amount.

(define-public (system-repay (amount uint))
  (let (
        (states (var-get pause-states))
        (u (try! (accrue)))
        (scaled-principal (var-get principal-scaled))
        (idx (var-get index))
        (debt (total-debt))
        (total-borrowed-amount (var-get total-borrowed))
        (capped-amount (if (> amount debt) debt amount))
        (principal-reduction (calc-principal-ratio-reduction capped-amount scaled-principal debt))
        (capped-reduction (if (> principal-reduction scaled-principal) scaled-principal principal-reduction))
        (updated-scaled-principal (- scaled-principal capped-reduction))
        (principal-repaid (mul-div-down capped-amount total-borrowed-amount debt))
        (interest-paid (- capped-amount principal-repaid))
        (total-borrowed-new (if (> total-borrowed-amount principal-repaid) (- total-borrowed-amount principal-repaid) u0)))

    (try! (check-caller-auth))
    (asserts! (not (get repay states)) ERR-PAUSED)
    (asserts! (> amount u0) ERR-AMOUNT-ZERO)
