### Title
Unprivileged attacker can drain a victim UEA's native PC balance by submitting gasless `MsgExecutePayload` with forged `VerificationData` — ([File: x/uexecutor/keeper/msg_execute_payload.go])

### Summary
Analogous to the `initWithdrawOnBehalf` finding (anyone can trigger a balance-affecting action "on behalf of" another account without being that account), `MsgExecutePayload` lets any Cosmos signer name an arbitrary victim's `UniversalAccountId` and force an EVM call against the victim's UEA. Even when the UEA correctly rejects the forged signature and reverts, the keeper unconditionally deducts and burns gas fees from the **victim's** account balance, not the attacker's — because `Signer` (payer of nothing, since the message is gasless) and `UniversalAccountId.Owner` (the account actually billed) are deliberately decoupled and never economically bound together.

### Finding Description
`MsgExecutePayload` is in the gasless message whitelist [1](#0-0) , meaning the Cosmos-level tx fee is entirely skipped for the `Signer` regardless of who they are [2](#0-1) . The module's authorization model explicitly does **not** enforce `Signer == EVM(Owner)`, by design, so any account can submit a payload targeting any victim's `UniversalAccountId` [3](#0-2) .

In `Keeper.ExecutePayload`, the flow is:
1. `evmFrom` is derived from the attacker's own `Signer`, and the victim's UEA address is resolved from `universalAccountId` (attacker-controlled) [4](#0-3) .
2. The keeper calls `CallUEAExecutePayload`, which issues a real, gas-metered `DerivedEVMCall` against the victim's UEA contract with `commit=true` [5](#0-4) . The UEA contract will correctly revert because the attacker cannot forge a signature that recovers to the victim's owner key [6](#0-5) .
3. Regardless of whether this call succeeds or the contract reverts, the keeper unconditionally calls `DeductGasFeesFromReceipt(ctx, sdkCtx, ueaAddr, receipt, universalPayload)` — using `ueaAddr` (the **victim's** account), not `evmFrom` (the attacker) — *before* even checking `execErr` [7](#0-6) .
4. `DeductGasFeesFromReceipt` computes gas cost from `receipt.GasUsed` and unconditionally burns that amount of native `upc` from the victim's own account via `DeductAndBurnFees` — this only short-circuits if `receipt == nil` or `receipt.GasUsed == 0`, not on execution failure [8](#0-7) .

Because a reverting EVM call still consumes gas up to the point of the signature-check failure inside the UEA contract (parsing the payload struct, calling into the Ed25519/ECDSA verification logic), `receipt.GasUsed` will generally be non-zero on a forged-signature attempt, triggering a real burn from the victim's balance for work the victim never authorized and gained nothing from.

### Impact Explanation
This is an unauthorized burn of a protocol/user-controlled fund (native `upc` balance held at the UEA account address) triggered entirely by an unprivileged, unauthenticated third party. Because the attacking message is gasless to the attacker (no Cosmos fee, and `MsgExecutePayload` needs no valid signature over the victim's payload — only a well-formed hex string in `VerificationData`, per `ValidateBasic` [9](#0-8) ), an attacker can repeatedly spam this against any victim UEA with a large `GasLimit` payload to maximize `receipt.GasUsed` per attempt at zero cost to themselves, progressively draining the victim's PC balance. This directly matches the in-scope impact category "unauthorized burn ... of user or protocol-controlled funds" and "corruption of ... gas fee accounting."

### Likelihood Explanation
High reachability: `MsgExecutePayload` is a standard user-facing message with no bonded/admin gating (unlike `MsgVoteInbound`/`MsgVoteOutbound`), it is gasless for any signer, and `ValidateBasic` places essentially no constraint on `VerificationData` content beyond being valid hex [9](#0-8) . The only requirement is knowing a victim's `UniversalAccountId` (chain namespace/id + owner), which is public information derivable from any observed cross-chain activity. The main uncertainty is the exact `GasUsed` a revert-path call consumes in the pushchain EVM fork — I was unable to inspect the `DerivedEVMCall`/EVM-fork revert-gas-accounting implementation itself (it lives in the external `github.com/pushchain/evm` fork, outside this repo's index), so I cannot quantify the drain rate per call, only confirm the code path unconditionally bills the victim on any non-zero-gas outcome.

### Recommendation
Change the gas-fee accounting so that `DeductGasFeesFromReceipt` is only charged to the victim's UEA (`ueaAddr`) when `execErr == nil` (i.e., the payload actually executed and the owner's own pre-authorized signature was validated). For failed/reverted executions triggered by an unauthenticated third party (signature verification failure), either (a) bill the gas cost to the `Signer`/`evmFrom` account instead, since they are the party who triggered wasted computation, or (b) reject the message outright with no gas charge to anyone when the UEA call reverts due to authorization failure, distinguishing "signature invalid" reverts from legitimate owner-initiated payload failures if that distinction is derivable from the receipt/error.

### Proof of Concept
1. Observe or guess a victim's `UniversalAccountId` (chain namespace, chain id, owner bytes) — this is not secret.
2. As an attacker with any funded (or even freshly-created, via the gasless `AccountInitDecorator` path) Cosmos account, submit `MsgExecutePayload` with `Signer = attacker`, `UniversalAccountId = victim`, an arbitrary `UniversalPayload` with a large `GasLimit`/`MaxFeePerGas`, and `VerificationData` set to any 65+ arbitrary hex bytes.
3. The message passes `ValidateBasic` (hex-format-only check) and passes ante-handling gasless (no Cosmos fee) [1](#0-0) .
4. `ExecutePayload` resolves the victim's real UEA address and issues `CallUEAExecutePayload` from the attacker's derived EVM address; the UEA contract reverts on signature mismatch, but gas is consumed up to the revert point [5](#0-4) .
5. `DeductGasFeesFromReceipt` is called with `recipient = ueaAddr` (victim) and burns `gasCost` upc from the victim's balance regardless of `execErr` [10](#0-9) .
6. Repeat at will — each call costs the attacker nothing (gasless) but burns real funds from the victim.

### Authorization model for `MsgExecutePayload` (contract-only binding)

`MsgExecutePayload` follows a **contract-only binding** authorization model. The Cosmos signer of the message and the owner of the target Universal Account are intentionally distinct roles:

- **`Signer`** identifies the Cosmos transaction signer — the party that delivers the owner's pre-authorized payload to Push Chain. `MsgExecutePayload` is a gasless message type (see `app/txpolicy/gasless.go`), so the signer pays no Cosmos transaction fee. Any account may submit the message.
- **`UniversalAccountId.Owner`** identifies the UEA whose pre-authorized payload is being executed. The actual EVM execution gas is deducted from this UEA;s balance (`DeductGasFeesFromReceipt`), not from the signer.

**The chain module deliberately does not enforce `Signer == EVM(Owner)`.** If it did, third-party delivery of owner-signed payloads would be impossible — every owner would have to submit their own Cosmos transactions even though the chain charges them no Cosmos fee for doing so, defeating the cross-chain UX promise of letting an external account act on Push Chain through delivered payloads.
```

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
```
