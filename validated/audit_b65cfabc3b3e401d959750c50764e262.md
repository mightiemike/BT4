### Title
Missing declared-class check in Starknet OS `execute_replace_class` allows setting a contract's class hash to an undeclared class - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Cairo (Sierra) `replace_class` syscall handler inside the Starknet OS program updates a contract's class-hash mapping (`contract_state_changes`) without verifying that the target `class_hash` corresponds to a class that was actually declared. This mirrors the reported bug class: a value is written into a state mapping keyed by an entity (`class_hash`) whose existence/initialization is never checked.

### Finding Description
In the Rust `blockifier`, the `replace_class` syscall handler explicitly enforces that the target class hash is declared before mutating state: [1](#0-0) 
This "ensure the class is declared (by reading it)" check (`syscall_handler.state.get_compiled_class(request.class_hash)?`) is the invariant that the OS is supposed to re-execute and prove.

However, in the Starknet OS Cairo implementation, the equivalent function `execute_replace_class` updates `contract_state_changes` (the address → class_hash mapping) directly from the syscall request with **no check** that `class_hash` was declared / exists in `contract_class_changes`: [2](#0-1) 
The code even contains an explicit acknowledgment of the missing check: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` (line 902).

The deprecated (Cairo 0) syscall path has the identical gap, also with no existence check before the `dict_update`: [3](#0-2) 

By contrast, the Rust/blockifier side treats the "class must be declared" invariant as load-bearing documentation for the state cache mechanics, noting explicitly: [4](#0-3) 
"Replace class: verify the contract is deployed before running any code" — but the accompanying declared-class check for the *new* class hash is only present in the Rust syscall handler, not the Cairo OS re-execution program.

### Impact Explanation
The Starknet OS is the component that re-executes a proposed block and produces the STARK proof attesting to the correctness of the state transition (it is explicitly listed as a valid, reachable component: "Starknet OS re-execution"). Since the OS's `execute_replace_class` accepts and commits an undeclared `class_hash` into `contract_state_changes` without validation, any code path that produces (or is tricked into producing) such a state diff would have that inconsistency silently accepted and proven correct by the OS, rather than being rejected as it is by the native blockifier's syscall handler. This creates a divergence between the two components that are supposed to agree on the same execution invariant: the OS can compute and commit a state root reflecting a contract "class hash" for which no corresponding compiled-class entry exists in the classes trie, an inconsistent/wrong committed state that the Rust blockifier would have rejected. This can manifest as either (a) the OS proving an invalid state transition that the honest native execution would never allow (root/committed-state divergence), or (b) the OS crashing/panicking later when it tries to fetch the (non-existent) compiled class facts for that class hash while building the classes trie output, which would halt block proving and thus new-block confirmation for the network.

### Likelihood Explanation
The class-declaration check is enforced today only in the Rust blockifier's syscall handler; the Cairo OS re-execution program that is meant to prove the same trace has no equivalent guard, and the maintainers themselves flagged this gap with a TODO. Any discrepancy between the hint-provided state (`GetContractAddressStateEntry`) and the actual declared-class invariant (e.g., from a future bug elsewhere in the pipeline, a malformed/adversarially-crafted hint input, or any code path that skips the Rust-side guard) would go undetected by the OS, whereas it is currently the OS's job to be the final, trust-minimized verifier of exactly these kinds of invariants.

### Recommendation
Add an explicit assertion in `execute_replace_class` (both the Cairo1 `syscall_impls.cairo` and Cairo0 `deprecated_execute_syscalls.cairo`) that the given `class_hash` exists in `contract_class_changes` (i.e., has a non-zero declared compiled-class-hash value) before performing the `dict_update` on `contract_state_changes`, matching the guarantee already enforced by the Rust blockifier's `replace_class` syscall handler.

### Proof of Concept
Not applicable in the traditional sense (no external funds transfer) — the issue is a missing invariant check in Cairo OS code, demonstrable by inspection:
1. Rust blockifier `replace_class` calls `state.get_compiled_class(request.class_hash)?` before writing (`hint_processor.rs:800-804`), causing `StateError::UndeclaredClassHash` to be returned for an undeclared class, as verified by the existing test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`.
2. The Cairo OS `execute_replace_class` (`syscall_impls.cairo:881-920`) performs the equivalent `dict_update` on `contract_state_changes` with no analogous check, as marked by its own TODO comment at line 902.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
