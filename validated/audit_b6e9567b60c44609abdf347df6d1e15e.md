### Title
Missing Declared-Class Validation in Starknet OS `execute_replace_class` Enables State/Root Divergence from Blockifier - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The `execute_replace_class` function in the Starknet OS Cairo program writes an arbitrary, attacker-supplied `class_hash` into a contract's state entry without verifying that the class is declared (or that it is Cairo1). The blockifier (native Rust execution engine) enforces this check, but the OS program — which independently re-executes and proves the same transactions to compute the committed state root — does not.

### Finding Description
The `replace_class` syscall handler in the blockifier's execution path enforces two invariants before allowing a class replacement: [1](#0-0) 
This reads the compiled class (raising `StateError::UndeclaredClassHash` if it isn't declared) and rejects non-Cairo1 classes before mutating state. The deprecated syscall path performs an analogous check: [2](#0-1) 

In contrast, the Starknet OS's Cairo implementation of the same syscall — used for independent re-execution and STARK-proving of a block, in the reachable path explicitly permitted by the scope ("Starknet OS re-execution") — performs no such validation. It only carries a TODO acknowledging the gap: [3](#0-2) 
The same missing check exists in the deprecated syscalls Cairo implementation: [4](#0-3) 
In both cases the OS blindly performs `dict_update` on `contract_state_changes` with the caller-supplied `class_hash`, with no assertion that the class was ever declared or that its version is compatible, unlike the Rust-side `state.get_compiled_class(class_hash)?` guard.

This is directly analogous to the reported bug class: a state-mutating operation ("mark milestone complete" / "replace class") that omits validation of a precondition ("milestone not already complete" / "class is declared") that is enforced elsewhere in the same system but not at this specific mutation site.

### Impact Explanation
The OS is the component that independently re-executes transactions to compute the state root that is proven and committed on L1/via SHARP. If, for any reason, the non-determinism of a `replace_class` call's revert status is not perfectly re-derived from the actual chain state (e.g., a discrepancy in what is hinted as reverted vs. non-reverted, or any code path that reaches `execute_replace_class` with an undeclared class hash), the OS will silently accept and commit an invalid class hash into the contract state. This directly affects the *wrong committed root* category of impact: the OS could compute/prove a state transition that assigns a contract address a class hash that was never declared, which is unreachable/inconsistent with the class-hash-to-code mapping actually recorded in state. A contract whose class hash points to nothing declared becomes permanently uncallable (any subsequent invocation would fail during class-hash resolution), constituting **permanent freezing of funds/functionality** for that contract, and any resulting root would not match what an honest re-execution against the actual, correctly-validated blockifier trace would produce — an honest-node divergence.

### Likelihood Explanation
Likelihood is bounded by the fact that under correct hinting (i.e., the `IsReverted` hint matches actual blockifier-computed outcome), a `replace_class` call to an undeclared class hash would already have been marked reverted by blockifier before reaching the OS's execution branch, so the missing check is masked in the common/honest case. However, this is an explicit gap acknowledged by the maintainers themselves (`TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`), meaning the invariant is not enforced independently by the proof system — it currently relies entirely on the correctness of externally supplied non-determinism (hints) rather than being checked in-circuit. Any bug in hint generation, any future code path that constructs `contract_class_changes`/`contract_state_changes` inconsistently, or any legitimate transaction sequence where reversion determination diverges from this specific guard would immediately manifest as unsound state commitment, with no additional privileged access required beyond submitting an ordinary `replace_class`-invoking transaction.

### Recommendation
Add an explicit assertion in `execute_replace_class` (both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`) that verifies the target `class_hash` is present in `contract_class_changes` (i.e., has been declared) — mirroring the Rust-side `state.get_compiled_class(class_hash)?` and `is_cairo1(...)` checks — before performing the `dict_update` on `contract_state_changes`. This makes the invariant enforced in-circuit rather than relying solely on hinted revert status matching blockifier's off-circuit computation, closing the divergence risk between the Rust execution client and the Starknet OS proof program.

### Proof of Concept
Conceptual PoC (not executable without full OS test harness access):
1. A user submits an `invoke` transaction whose entry point calls `replace_class_syscall(undeclared_class_hash)`, where `undeclared_class_hash` has never been declared on-chain.
2. In blockifier's real execution path, `syscall_base.rs::replace_class` calls `state.get_compiled_class(class_hash)` which returns `StateError::UndeclaredClassHash`, causing the call (or transaction) to fail/revert as validated by the existing test: [5](#0-4) 
3. When the same transaction trace is re-executed/proved by the Starknet OS (`execute_replace_class` in `syscall_impls.cairo`), if the `IsReverted` hint (or any other bug/discrepancy in the pipeline feeding hints into the OS) does not correctly reflect the failure, the OS proceeds to unconditionally `dict_update` the contract's class hash to the undeclared value — with no equivalent `get_compiled_class`-style check to catch this — as shown by the absence of any declared-class assertion in the function body (lines 881–920 cited above), unlike its Rust counterpart.
4. This would let the committed/proved state root include a `contract_state_changes` entry with a class hash that has no corresponding declared class, silently bricking the contract and diverging from what an honest blockifier-only recomputation of the block would yield.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
