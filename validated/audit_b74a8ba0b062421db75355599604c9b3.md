## Title
Missing declared-class validation in `execute_replace_class` allows SNOS to diverge from Blockifier on `replace_class` syscall — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The external report describes `SimplePolicySetter.set` accepting attacker-controllable arguments (key/value) without validating them before committing a sensitive state change. The closest reachable analog in this sequencer is the `replace_class` syscall handler used by the Starknet OS (SNOS) Cairo re-execution program: it commits a new `class_hash` to a contract's state entry without first checking that the class is declared, unlike the Rust `blockifier` implementation of the same syscall, which explicitly performs that check.

### Finding Description
Any contract can invoke the `replace_class` syscall with an arbitrary `class_hash` argument as part of a normal transaction. In the Rust `blockifier` (used for actual block building/validation), the syscall handler validates the class before writing it to state: [1](#0-0) 
and the deprecated (Cairo0) syscall path performs the same check: [2](#0-1) 
This is confirmed by tests that a `replace_class` call with an undeclared class hash fails with `"is not declared"`: [3](#0-2) 

However, the SNOS Cairo implementation of the same syscall (`execute_replace_class`, used to re-execute and prove the block for the Starknet OS) does **not** perform this validation — it directly overwrites the contract's `class_hash` in `contract_state_changes` and leaves an explicit TODO acknowledging the missing check: [4](#0-3) 

Specifically:
```
let class_hash = request.class_hash;
// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
local state_entry: StateEntry*;
%{ GetContractAddressStateEntry %}
tempvar new_state_entry = new StateEntry(class_hash=class_hash, ...);
dict_update{dict_ptr=contract_state_changes}(key=contract_address, prev_value=..., new_value=cast(new_state_entry, felt));
```
This mirrors the report's bug class exactly: a sensitive setter (`class_hash` assignment for a contract) accepts an unvalidated argument (an undeclared/arbitrary/zero class hash) and commits it to state, while a parallel/partial implementation of the same logic (the Rust blockifier) enforces the missing check.

### Impact Explanation
This is reachable by any unprivileged contract executing an ordinary transaction (calling `replace_class`) — no privileged role is required. Because the block was originally built and validated by `blockifier`, which rejects undeclared class hashes, in the current honest flow this specific divergence may not surface under normal conditions (since blockifier already filtered such transactions before they reach SNOS). However, if the SNOS Cairo hint/logic for `GetContractAddressStateEntry`/state management is ever exercised on inputs not first vetted by blockifier's checks (e.g., different code paths, alternate provers, fee-token/L2 message flows, or future changes that route more state directly through SNOS without going through the equivalent Rust validation), the SNOS-committed state root could differ from the intended semantics, or accept `class_hash=0`/garbage as a contract's class, producing wrong committed state roots inconsistent with what should be provable, or corrupting the class-hash entry for a contract address in ways that are inconsistent between provers and executors — a source of honest-node/prover divergence class of bugs. Given the explicit developer TODO acknowledging the missing check is still open, this is a genuine, unresolved input-validation gap in a state-committing syscall path.

### Likelihood Explanation
Medium — the check is intentionally deferred (per the TODO) and the code path is on the "hot" execution path for a syscall reachable from any contract call. Under the current architecture the Rust blockifier's own validation likely prevents an attacker from ever supplying an undeclared class hash to the OS path in the common flow, which lowers immediate exploitability, but the divergence between the OS implementation and the reference (blockifier) implementation is a concrete, provable inconsistency in a security-sensitive state-commitment path, matching the reported "partial fix, missing validation" bug class precisely.

### Recommendation
Add the missing declared-class-hash validation in `execute_replace_class` (and any other stateful_compression/SNOS Cairo hints that write `class_hash` into `contract_state_changes`) mirroring the `blockifier`'s check (`state.get_compiled_class(class_hash)` before `set_class_hash_at`), ensuring SNOS execution semantics exactly match the block-building/validation semantics for this syscall, and remove the outstanding TODO once resolved.

### Proof of Concept
Not independently exploitable purely from the indexed code without also tracing how/when the SNOS `execute_replace_class` hint can be invoked on data that bypassed blockifier's own `replace_class` validation (e.g., via alternate execution paths, fee-charging flows, or future changes). This should be confirmed by a Devin session with full repo access to trace: (1) all callers of `execute_replace_class`, (2) whether any code path feeds SNOS a `class_hash` that was not first checked by blockifier's `replace_class`/`ReplaceClassRequest` handling, and (3) whether current tests exercise `execute_replace_class` with an undeclared class hash to confirm the OS accepts it while blockifier would reject it.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
