### Title
Missing `supportUnfreezeDelay` feature-gate check in TVM native path allows WithdrawExpireUnfreeze to execute even when disabled by committee - ([File: actuator/src/main/java/org/tron/core/vm/nativecontract/WithdrawExpireUnfreezeProcessor.java])

### Summary
`WithdrawExpireUnfreezeProcessor.validate()`, invoked from the `WITHDRAWEXPIREUNFREEZE` TVM opcode via `Program.withdrawExpireUnfreeze()`, omits the `dynamicStore.supportUnfreezeDelay()` check that `WithdrawExpireUnfreezeActuator.validate()` enforces for the equivalent top-level transaction. This lets any smart contract call the opcode to withdraw expired unfreeze balances even when the committee has not enabled the UnfreezeDelay feature (i.e., `UNFREEZE_DELAY_DAYS` is 0/unset).

### Finding Description
The top-level `WithdrawExpireUnfreezeActuator.validate()` explicitly gates the feature: [1](#0-0) 

The TVM native-contract equivalent, `WithdrawExpireUnfreezeProcessor.validate()`, performs the `repo == null` check, address validity, account existence, and overflow check, but never calls `dynamicStore.supportUnfreezeDelay()`: [2](#0-1) 

This processor is reached via `Program.withdrawExpireUnfreeze()`, which is invoked by the `withdrawExpireUnfreezeAction` opcode handler in `OperationActions`. The opcode handler only checks `isStaticCall()`, not the feature flag: [3](#0-2) [4](#0-3) 

`supportUnfreezeDelay()` is defined as `getUnfreezeDelayDays() > 0`, a committee-controlled dynamic property that gates the entire UnfreezeDelay/FreezeV2 withdraw-expire feature: [5](#0-4) 

Since any account can deploy a contract containing the `WITHDRAWEXPIREUNFREEZE` opcode and trigger it with an ordinary transaction, an unprivileged attacker can bypass the actuator-level feature gate entirely by calling the opcode instead of submitting a `WithdrawExpireUnfreezeContract` transaction.

### Impact Explanation
If a network configuration has not yet enabled UnfreezeDelay (e.g., pre-upgrade networks, private/consortium chains, or a chain where the committee intentionally has not turned on `UNFREEZE_DELAY_DAYS`), users could still withdraw "expired unfrozen" balances through the TVM path, producing settlement/state divergence from the intended upgrade-gated behavior versus the top-level transaction type. This is a feature-gate bypass causing inconsistent chain state relative to the intended committee-controlled rollout.

### Likelihood Explanation
Exploitability only requires: (1) a network/version where `WITHDRAWEXPIREUNFREEZE` opcode is registered but `supportUnfreezeDelay()` is false, and (2) an account with unfrozen-V2 entries that have expired. Both conditions are plausible during the FreezeV2/UnfreezeDelay upgrade rollout window where the opcode is compiled into VM but the dynamic property has not yet been set by governance. Any contract deployer can trigger this without special privileges.

### Recommendation
Add the same check present in `WithdrawExpireUnfreezeActuator.validate()` to `WithdrawExpireUnfreezeProcessor.validate()`:
```java
if (!dynamicStore.supportUnfreezeDelay()) {
  throw new ContractValidateException("Not support WithdrawExpireUnfreeze transaction,"
      + " need to be opened by the committee");
}
```

@Test
public void testWithdrawExpireUnfreezeOpcodeBypassesFeatureGate() throws Exception {
  // Ensure feature disabled at dynamic-store level
  dbManager.getDynamicPropertiesStore().saveUnfreezeDelayDays(0L);
  assertFalse(dbManager.getDynamicPropertiesStore().supportUnfreezeDelay());

  // Set up an account with an already-expired UnFreezeV2 entry
  AccountCapsule owner = ...; // account with unfrozenV2 entry, expireTime in the past
  dbManager.getAccountStore().put(owner.createDbKey(), owner);

  WithdrawExpireUnfreezeParam param = new WithdrawExpireUnfreezeParam();
  param.setOwnerAddress(owner.getAddress().toByteArray());

  Repository repo = new RepositoryImpl(dbManager.getChainBaseManager(), null);
  WithdrawExpireUnfreezeProcessor processor = new WithdrawExpireUnfreezeProcessor();

  // Current (buggy) behavior: validate() succeeds despite feature being disabled
  processor.validate(param, repo); // should throw ContractValidateException but does not
  long withdrawn = processor.execute(param, repo);
  assertTrue(withdrawn > 0); // demonstrates the bypass: balance was withdrawn while feature disabled

  // Expected after fix: processor.validate(param, repo) throws ContractValidateException
  // with message "Not support WithdrawExpireUnfreeze transaction, need to be opened by the committee"
}

  public void validate(WithdrawExpireUnfreezeParam param, Repository repo) throws ContractValidateException {
    if (repo == null) {
      throw new ContractValidateException(STORE_NOT_EXIST);
    }

    byte[] ownerAddress = param.getOwnerAddress();
    DynamicPropertiesStore dynamicStore = repo.getDynamicPropertiesStore();
    if (!DecodeUtil.addressValid(ownerAddress)) {
      throw new ContractValidateException("Invalid address");
    }
    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    if (Objects.isNull(accountCapsule)) {
      String readableOwnerAddress = StringUtil.createReadableString(ownerAddress);
      throw new ContractValidateException(ACCOUNT_EXCEPTION_STR
          + readableOwnerAddress + NOT_EXIST_STR);
    }

    long now = dynamicStore.getLatestBlockHeaderTimestamp();
    List<Protocol.Account.UnFreezeV2> unfrozenV2List = accountCapsule.getInstance()
        .getUnfrozenV2List();
    long totalWithdrawUnfreeze = getTotalWithdrawUnfreeze(unfrozenV2List, now);
    if (totalWithdrawUnfreeze < 0) {
      throw new ContractValidateException("no unFreeze balance to withdraw ");
    }
    try {
      LongMath.checkedAdd(accountCapsule.getBalance(), totalWithdrawUnfreeze);
    } catch (ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractValidateException(e.getMessage());
    }
  }

  public long withdrawExpireUnfreeze() {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, owner, 0, null,
        "withdrawExpireUnfreeze", nonce, null);

    try {
      WithdrawExpireUnfreezeParam param = new WithdrawExpireUnfreezeParam();
      param.setOwnerAddress(owner);

      WithdrawExpireUnfreezeProcessor processor = new WithdrawExpireUnfreezeProcessor();
      processor.validate(param, repository);
      long expireUnfreezeBalance = processor.execute(param, repository);
      repository.commit();
      if (internalTx != null) {
        internalTx.setValue(expireUnfreezeBalance);
      }
      return expireUnfreezeBalance;
    } catch (ContractValidateException e) {
      logger.warn("TVM WithdrawExpireUnfreeze: validate failure. Reason: {}", e.getMessage());
    } catch (ContractExeException e) {
      logger.warn("TVM WithdrawExpireUnfreeze: execute failure. Reason: {}", e.getMessage());
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return 0;
  }
