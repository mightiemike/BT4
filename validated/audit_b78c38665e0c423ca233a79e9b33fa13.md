## Analysis

The Curve report's root cause is **integer truncation in a multiply-then-divide computation that is used to determine how much a user must pay, allowing the payable amount to round down to zero while the user still keeps the associated benefit**. The Push Chain analog of this exact pattern exists in the gas-fee accounting path for module-originated EVM execution.

### Title
Gas fee truncates to zero via double-division of `baseFee`, allowing free universal-payload EVM execution - (`x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` computes the fee owed for gas consumed by a `DerivedEVMCall` (universal payload execution originated by the `uexecutor` module on behalf of a user's smart account). It derives `effectiveGasPrice` from the chain's `baseFee` by dividing the `LegacyDec`'s raw internal big.Int by `1e18` a second time (the decimal→int conversion), then multiplies by `gasUsed`. If this truncated `effectiveGasPrice` becomes `0` — which happens whenever the live `baseFee` decays below `1 upc` under the standard EIP-1559 adjustment mechanism — `gasCost` becomes `0`, and `DeductGasFeesFromReceipt` short-circuits on `gasCost.Sign() <= 0` without deducting or burning any fee at all.

### Finding Description [1](#0-0) 

The comment asserts "base fee is always a whole number of upc," but nothing in this scoped repository enforces that invariant — the base fee is a standard `feemarketKeeper`-tracked `LegacyDec` that adjusts continuously per EIP-1559 rules (dividing/multiplying by fractional deltas based on gas-target usage), so it can legitimately fall below `1.0 upc` during sustained low-usage periods. When that happens, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates the sub-unit value to `0`, making `effectiveGasPrice = 0`.

`DeductGasFeesFromReceipt` then treats a zero `gasCost` as "nothing to charge" and returns `nil` — skipping `DeductAndBurnFees` entirely: [2](#0-1) 

This is invoked from the gas-and-payload execution flow that performs real, potentially arbitrarily complex `DerivedEVMCall` execution on behalf of a UniversalTx sender, so `receipt.GasUsed` can be nontrivial even though the on-chain accounting charges `0`.

### Impact Explanation
This is a corruption of gas-fee accounting — an explicitly in-scope impact ("corruption of ... gas fee accounting"). Any unprivileged user submitting universal payloads can execute EVM logic funded by validator compute resources without paying the protocol-mandated fee whenever the network `baseFee` has decayed under `1 upc`, silently breaking the fee invariant that gas consumption must always be billed. This differs from the ante-level `MinGasPriceDecorator` check because `DeductGasFeesFromReceipt` is an independent, second fee-accounting path specific to module-originated `DerivedEVMCall`s and has no minimum-fee floor of its own.

### Likelihood Explanation
Reaching `baseFee < 1 upc` requires the network to sustain very low EVM gas usage relative to target for enough blocks under the feemarket's EIP-1559-style adjustment — plausible on a low-traffic network or during quiet periods, and once there, the zero-fee condition applies to every user's universal payload transaction with no privileged action required.

### Recommendation
Do not treat a truncated-to-zero `effectiveGasPrice` as "no fee due." Preserve sub-unit precision through the whole computation (e.g., keep `baseFee` as `LegacyDec`, multiply by `gasUsed` before rounding, and round up/ceil rather than truncate), or reject/floor gas pricing at a protocol-defined minimum instead of silently waiving the fee, mirroring the Curve fix of not letting a division-based value round down to bypass a mandatory debit.

### Proof of Concept
1. Let the network's `feemarket` `baseFee` decay (via normal EIP-1559 adjustment over multiple low-usage blocks) to any value `< 1e18` in raw internal representation (i.e., `< 1 upc`), e.g. `0.5 upc`.
2. A user submits a universal payload transaction that is executed via `ExecuteInboundGasAndPayload` → `DeductGasFeesFromReceipt`, consuming e.g. `500,000` gas.
3. `CalculateGasCost` computes `baseFeeBig = 0` (since `0.5e18 / 1e18 = 0` in integer division), so `gasCost = 0 * 500000 = 0`.
4. `DeductGasFeesFromReceipt` hits `if gasCost.Sign() <= 0 { return nil }` and skips `DeductAndBurnFees` — the user's real EVM execution is fully unbilled.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}
