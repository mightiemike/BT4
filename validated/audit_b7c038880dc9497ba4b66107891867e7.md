### Title
Function-based `domainTransformations.transform` entries are silently excluded from the accepted-domain allowlist, causing permanent shop/host sanitization failures (auth DoS) - (File: `packages/apps/shopify-api/lib/utils/domain-transformer.ts`)

### Summary
This is the same bug class as the reported Revolution Protocol issue: a value that is accepted by one code path (a "setter"/transform function that is explicitly supported) is not accounted for by a second, stricter validation path elsewhere in the same feature, so a legitimately-configured value that passes the first check unconditionally fails the second — permanently breaking the flow for the affected input (DoS), even though the initial configuration is fully valid and within the documented feature's bounds.

### Finding Description
`domainTransformations` lets an app owner map custom shop domains to Shopify's canonical domains for `sanitizeShop`/`sanitizeHost` validation purposes.

`applyDomainTransformations` fully supports function-based `transform` values: [1](#0-0) 

However `getTransformationDomains`, which builds the list of domains that `sanitizeShop`/`sanitizeHost` will treat as valid, explicitly skips any transformation whose `transform` is not a string: [2](#0-1) 

This means that when `transform` is a function, the *target* domain it produces is never added to the accepted `domainsRegex`/`originsRegex` used by `sanitizeShop` and `sanitizeHost`: [3](#0-2) [4](#0-3) 

Both `sanitizeShop` and `sanitizeHost` reject any `shop`/`host` value that doesn't match the regex built from `getTransformationDomains`, throwing `InvalidShopError`/`InvalidHostError` when `throwOnInvalid` is set (as it is in the OAuth `begin`/`callback` flow): [5](#0-4) 

So the exact same class of bug applies here: the transform-function configuration is accepted by the "setter" (`applyDomainTransformations` works fine with it), but the downstream strict check (`sanitizeShop`/`sanitizeHost`) was never updated to recognize function-based transforms, so any request whose `shop`/`host` is already the *transformed/target* domain is always rejected.

### Impact Explanation
For any app that configures a `domainTransformations` entry with a function `transform` (a documented, supported configuration), requests bearing the target domain (e.g. a `shop`/`host` param, or the `dest` claim inside a session token, that already equals the transformed domain) will be permanently and unconditionally rejected by `sanitizeShop`/`sanitizeHost`. This breaks:
- OAuth `begin`/`callback` (`InvalidShopError` thrown at `sanitizeShop(config)(shop, true)`),
- session-token/host validation paths in `shopify-app-remix`/`shopify-app-react-router` that rely on `sanitizeHost`/`sanitizeShop`.

This is a permanent denial of service of the authentication handlers for any shop on the transformed domain, mirroring the reported bug's "owner misconfiguration within allowed setter bounds leads to protocol DoS" root cause — no attacker action is required beyond a legitimate shop interacting with the app.

### Likelihood Explanation
Likelihood is limited to apps that actually configure `domainTransformations` with a function-based `transform` (string-based transforms are unaffected because `getTransformationDomains` does handle those). This is a legitimate, documented configuration option (see the JSDoc example in `domain-transformer.ts`), so any app using it in this documented way is affected deterministically, not probabilistically.

### Recommendation
Update `getTransformationDomains` to also derive/accept the target domain when `transform` is a function — e.g. by requiring the app to also declare the resulting domain explicitly in config, or by invoking the function against a synthetic/canonical match to derive the produced domain, so the allowlist used by `sanitizeShop`/`sanitizeHost` stays consistent with what `applyDomainTransformations` actually accepts.

### Proof of Concept
```ts
const config = {
  domainTransformations: [
    {
      match: /^([a-zA-Z0-9-_]+)\.my\.shop\.dev$/,
      transform: (matches: RegExpMatchArray) => `${matches[1]}.dev-api.shop.dev`,
    },
  ],
};

// getTransformationDomains(config) => [] (target domain "dev-api.shop.dev" never added,
// because transform is a function, not a string — see lines 116-118 of domain-transformer.ts)

// A request/session-token whose shop/host is already "shop1.dev-api.shop.dev"
// (the transformed target) will always fail:
sanitizeShop(config)('shop1.dev-api.shop.dev', true); // throws InvalidShopError
sanitizeHost(config)(base64('shop1.dev-api.shop.dev/admin'), true); // throws InvalidHostError

export function getTransformationDomains(config: ConfigInterface): string[] {
  const domains: string[] = [];
  const log = logger(config);

  if (!config.domainTransformations) {
    return domains;
  }

  const transformations = config.domainTransformations;

  for (const transformation of transformations) {
    const regex =
      typeof transformation.match === 'string'
        ? new RegExp(transformation.match)
        : transformation.match;

    const domainPattern = regex.source.match(/\\\.([\\.\w-]+)\$?$/);

    if (domainPattern) {
      domains.push(domainPattern[1]);
    } else {
      log.debug(
        `Failed to extract domain pattern from regex: ${regex.source}. This may indicate an unsupported regex pattern (e.g., optional groups, character classes in domain part, complex alternations).`,
      );
    }

    if (typeof transformation.transform !== 'string') {
      continue;
    }

    const templateDomainMatch =
      transformation.transform.match(/\$\d+\.([.\w-]+)$/);

    if (templateDomainMatch) {
      const escapedDomain = templateDomainMatch[1].replace(/\./g, '\\.');
      domains.push(escapedDomain);
    }
  }

export function sanitizeShop(config: ConfigInterface) {
  return (shop: string, throwOnInvalid = false): string | null => {
    let shopUrl = shop;
    const domainsRegex = [
      'myshopify\\.com',
      'shopify\\.com',
      'myshopify\\.io',
      'shop\\.dev',
    ];

    // Add domains from transformations (both source and target)
    if (config.domainTransformations) {
      domainsRegex.push(...getTransformationDomains(config));
    }

    const shopUrlRegex = new RegExp(
      `^[a-zA-Z0-9][a-zA-Z0-9-_]*\\.(${domainsRegex.join('|')})[/]*$`,
    );

    const shopAdminRegex = new RegExp(
      `^admin\\.(${domainsRegex.join('|')})/store/([a-zA-Z0-9][a-zA-Z0-9-_]*)$`,
    );

    const isShopAdminUrl = shopAdminRegex.test(shopUrl);
    if (isShopAdminUrl) {
      shopUrl = shopAdminUrlToLegacyUrl(shopUrl) || '';
    }

    const sanitizedShop = shopUrlRegex.test(shopUrl) ? shopUrl : null;
    if (!sanitizedShop && throwOnInvalid) {
      throw new InvalidShopError('Received invalid shop argument');
    }

    if (sanitizedShop && config.domainTransformations) {
      return applyDomainTransformations(sanitizedShop, config);
    }

    return sanitizedShop;
  };

export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }

    return sanitizedHost;
  };
