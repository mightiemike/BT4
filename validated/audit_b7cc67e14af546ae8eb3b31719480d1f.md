## Title
Gas fee under 1 upc/gas truncates to zero and skips fee deduction entirely, allowing free UEA payload execution — (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` in `x/uexecutor/keeper/fees.go` converts the fee-market's `LegacyDec` base fee into a whole-upc integer by doing `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` before multiplying by `gasUsed`. The code assumes "the base fee is always a whole number of upc — no fractional upc exists," but `feemarketKeeper.GetBaseFee` is a general `LegacyDec` that is adjusted multiplicatively every block (EIP-1559-style) and is not constrained to integer upc values. Whenever the base fee is below `1` upc per gas unit, integer division truncates it to `0`, making `effectiveGasPrice = 0` and `gasCost = 0` regardless of how much gas the payload actually consumed. `DeductGasFeesFromReceipt` then short-circuits on `gasCost.Sign() <= 0` and returns `nil` (treated as a successful, "nothing to charge" case), so the already-executed EVM state changes are committed via `writeCache()` with zero fee collected.

### Finding Description
- `CalculateGasCost` (`x/uexecutor/keeper/fees.go:47-91`) unwraps the base fee with a hard-coded assumption of integer upc granularity: [1](#0-0) 
- If `baseFeeBig` (the `LegacyDec` internal fixed-point representation) is less than `1e18`, i.e. the effective base fee is below 1 upc per gas unit, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates to `0`. `effectiveGasPrice` becomes `0`, and `gasCost = effectiveGasPrice * gasUsed = 0`, independent of the actual `gasUsed`: [2](#0-1) 
- `DeductGasFeesFromReceipt` treats `gasCost.Sign() <= 0` as a no-op success, skipping `DeductAndBurnFees` entirely: [3](#0-2) 
- This function is invoked from the smart-contract payload path in `ExecuteInboundFundsAndPayload`, where the EVM call (`CallExecuteUniversalTx`) and the fee deduction (`DeductGasFeesFromReceipt`) are wrapped in the same `CacheContext`; the EVM state change is only rolled back if `feeErr != nil`. Since a zero `gasCost` returns `nil` (no error), `writeCache()` commits the executed payload state regardless of how much gas was truly consumed: [4](#0-3) 

The `FeeMarketKeeper` interface exposed to `x/uexecutor` only returns a `LegacyDec`, with no guarantee of integer upc granularity: [5](#0-4) 

This is the same bug class as the reported `LinearCurve.sol` issue: a rounding/truncation step computes a "price" of zero for the tail of the operation, but the full-value operation (in this case, complete UEA payload execution, not just "a few NFTs") is still carried out — value/service is transferred without payment.

### Impact Explanation
Falls squarely in-scope under "corruption of ... gas fee accounting" and "unauthorized module-originated EVM execution" categories: an unprivileged user submitting an ordinary cross-chain `FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` inbound whose destination is a smart-contract UEA gets their payload executed on Push Chain — potentially consuming arbitrary amounts of real gas/EVM computation and mutating chain state — while paying zero gas fee, whenever the network's feemarket base fee is below 1 upc/gas at execution time. This breaks the fee accounting invariant that gas consumption on Push Chain must be paid by the recipient/module account, and can be repeated indefinitely as a gas-fee bypass/DoS-via-free-compute vector as long as the condition holds.

### Likelihood Explanation
The base fee is not admin-set to a fixed integer; it is dynamically adjusted by the standard cosmos/evm feemarket module based on block gas utilization, and genesis/test configs in this repo already show it can be set to fractional/zero values (`"base_fee": "0.000000000000000000"` with `no_base_fee: true` in `interchaintest/setup.go`). During low-congestion periods or on chains configured with fine-grained (sub-1-upc) base fees, this condition is reachable by simply submitting ordinary cross-chain payload transactions — no privileged access, validator collusion, or edge-case crafting is required beyond timing the transaction when base fee < 1 upc.

### Recommendation
Do not truncate the base fee to a whole-upc integer before multiplying by `gasUsed`. Instead, perform the gas-cost computation in `LegacyDec` (or scaled big.Int) precision throughout — e.g. `gasCost = baseFee.MulInt64(int64(gasUsed))`, then round up (ceiling) rather than down when converting to the final upc-integer amount, mirroring the `Ceil().RoundInt()` pattern already used in `checkTxFeeWithValidatorMinGasPrices` (`app/ante/validator_tx_fee.go:43`). At minimum, reject/charge a minimum non-zero fee when `gasUsed > 0` but the computed integer `gasCost` rounds to zero, instead of silently skipping fee deduction.

### Proof of Concept
1. Configure or let the feemarket base fee settle to a fractional value below 1 upc per gas (e.g. `baseFee = 0.9` upc, achievable under low block utilization with `no_base_fee=false`).
2. As an unprivileged user, submit a normal cross-chain inbound of type `FUNDS_AND_PAYLOAD`/`GAS_AND_PAYLOAD` whose payload target is a smart-contract UEA, with a `maxFeePerGas`/`gasLimit` in the `UniversalPayload` sufficient to cover the intended execution.
3. UVs vote the inbound in through the normal honest-validator flow; `ExecuteInboundFundsAndPayload` executes the payload via `CallExecuteUniversalTx`, consuming real gas per `contractReceipt.GasUsed`.
4. `DeductGasFeesFromReceipt` → `CalculateGasCost` computes `baseFeeBig.Div(baseFeeBig, 1e18) == 0` since `baseFeeBig < 1e18`, yielding `gasCost = 0`.
5. `gasCost.Sign() <= 0` short-circuits to `return nil`; `feeErr == nil`, so `writeCache()` commits the payload execution with zero upc burned from the recipient — full contract execution obtained for free.
