## Title
Vault `accrue()` silently pass-through when paused, letting `deposit`/`redeem`/`borrow`/`repay` execute against a stale index while interest and treasury fees are frozen - ([File: mainnet/contracts/vault/v0-vault-stx.clar])

## Summary
Every Zest vault (`v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-usdc.clar`, `v0-vault-usdh.clar`, `v0-vault-ststxbtc.clar`, and their `local-testing` mirrors) implements `accrue` so that when the `accrue` pause flag is set, it returns the **old** `index`/`lindex` pair unchanged instead of reverting: [1](#0-0) 

This "pause passes through instead of reverting" pattern means every public entrypoint that calls `(try! (accrue))` - `deposit`, `redeem`, `system-borrow`, `system-repay` - keeps operating normally while silently treating the vault as if no interest had accrued, rather than blocking the operation. Deposits/redemptions/borrows/repays continue to be priced off `convert-to-assets-preview`/`convert-to-shares` using the frozen index, and the reserve-factor mint to `dao-treasury` (protocol yield) is skipped for as long as the pause is active.

## Finding Description
`accrue()` is the single choke point that (a) advances `index`/`lindex` based on `next-index`/`next-liquidity-index`, and (b) mints the protocol's reserve share of interest to `.dao-treasury`: [2](#0-1) 

When `(get accrue states)` is `true`, the function takes the early branch and returns `{ index: idx, lindex: lidx }` - the values read at the *start* of the call, completely bypassing the block that would compute `debt-delta`, `reserve-inc`, `treasury-lp`, and the `var-set index/lindex/last-update` calls: [3](#0-2) 

Every state-changing vault entrypoint unconditionally calls `(try! (accrue))` first and then proceeds to use `current-assets`, `convert-to-assets-preview`, `get-available-assets`, etc., which are all computed against the just-returned (possibly stale) `index`/`lindex`: [4](#0-3) 

The design intent (documented) is that pausing should stop risky operations; but for `accrue` specifically the code chooses to keep the surrounding operation (`deposit`, `redeem`, `borrow`, `repay`) alive by feeding it a value that pretends the interest/index "check" already happened and passed, instead of reverting the caller and blocking further activity. Because `redeem`'s health/asset checks (`ERR-INSUFFICIENT-ASSETS`, `ERR-INSUFFICIENT-LIQUIDITY`) are evaluated using this now-stale conversion, and because the reserve-share mint to `dao-treasury` is skipped, unclaimed protocol/supplier yield accrued between the last real accrual and the pause is permanently lost for that window rather than being caught up later - the pass-through never re-applies the missed interest once the state var wasn't advanced and `last-update`/index were never bumped, so accounting for the paused interval is simply dropped, not deferred.

## Impact Explanation
This lands in the "temporary/permanent freezing of unclaimed yield" category (High): while `pause-states.accrue` is true, any interest that would have accrued for lenders and the treasury's reserve-factor cut is not minted and not reflected in `index`/`lindex`. Since the pause path never recomputes or replays the missed interest window (there is no catch-up accrual once unpaused beyond whatever interest accrues going forward from the new `last-update`), the interest for the paused interval is permanently unclaimed/lost rather than merely delayed - a straight consequence of the pause "passing through" (returning stale cached values) instead of reverting the calling operation.

## Likelihood Explanation
This requires only a single, ordinary DAO/operational action - toggling the `accrue` pause flag on a vault (a legitimate operational control described in the docs) - combined with normal user activity (deposits/redeems/borrows/repays) during the pause window. No attacker interference between users, no oracle manipulation, and no flashloan is needed; it is a single-block/period consequence of the pass-through design each time the flag is active.

## Recommendation
Either (a) make `accrue()` revert with `ERR-PAUSED` when the accrue pause flag is set, forcing all dependent operations (`deposit`, `redeem`, `system-borrow`, `system-repay`) to also revert until unpaused, so no value is priced against a stale index; or (b) if pass-through is intentional to keep the vault operational, track the paused interval and replay/catch-up the interest and treasury mint once accrual resumes, so unclaimed yield during the pause is not silently dropped.

## Proof of Concept
1. DAO/governance sets the `accrue` bit of `pause-states` to `true` on, e.g., `v0-vault-stx.clar`.
2. Time passes (block timestamp advances) such that `next-index`/`next-liquidity-index` would normally increase.
3. A user calls `redeem` (or `deposit`/`system-borrow`/`system-repay`); `redeem` calls `(try! (accrue))`, which - because `accrue` is paused - returns the old `idx`/`lidx` without minting reserve shares to `.dao-treasury` and without advancing `index`/`lindex`/`last-update`: [3](#0-2) 
4. `redeem` proceeds using `convert-to-assets-preview` computed from the stale index, and the position/vault-wide interest and treasury fee for the elapsed paused period are never captured.
5. DAO unpauses `accrue`; subsequent calls to `accrue` compute `next-index` from the *current* time, meaning the paused interval's interest is not backfilled - it is permanently unaccrued/unclaimed for both suppliers and the treasury. [5](#0-4)

;; -- Lending operations -----------------------------------------------------

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))
