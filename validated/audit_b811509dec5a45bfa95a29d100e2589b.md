## Finding [1](#0-0) 

### Title
NEAR Wallet Contract permanently locks an external caller's attached deposit when the address-check callback rejects the target as an existing named account - (File: `runtime/near-wallet-contract/implementation/wallet-contract/src/lib.rs`)

### Summary
`WalletContract::rlp_execute` accepts an attached NEAR deposit from whoever calls it and tracks that deposit via `CallerDeposit` so it can be refunded if the emulated Ethereum transaction fails. [2](#0-1)  However, in one specific failure branch of `address_check_callback`, the function returns an error response directly, bypassing the only code path (`rlp_execute_callback`) that performs the refund. The caller's deposit — already credited to the wallet contract's account balance by the runtime as part of the incoming `FunctionCall` action — is never sent back and there is no other function that lets the caller reclaim it, so the funds are permanently stuck in the wallet contract.

### Finding Description
`rlp_execute` computes an `ExecutionContext` and constructs a `CallerDeposit` from the attached deposit whenever the predecessor is not the contract itself (i.e. an external caller, such as a relayer paying/attaching NEAR on behalf of a user, or any account calling the wallet directly): [3](#0-2) 

For the `EOABaseTokenTransfer { address_check: Some(address), .. }` transaction kind, `inner_rlp_execute` calls out to the address registrar and schedules `address_check_callback` with the `caller_deposit` forwarded as an argument: [4](#0-3) 

Inside `address_check_callback`, if the address resolves to an existing named account (`maybe_account_id.is_some()`) and the caller isn't using the wallet's own access key (`env::signer_account_id() != current_account_id`), the function returns an `ExecuteResponse::success = false` value directly:
```
} else {
    return PromiseOrValue::Value(ExecuteResponse {
        success: false,
        success_value: None,
        error: Some("Invalid target: target is address corresponding to existing named account_id".into()),
    });
}
``` [5](#0-4) 

This return skips `rlp_execute_callback` entirely — the only place where `caller_deposit` is actually refunded via `env::promise_batch_action_transfer`: [6](#0-5) 

Because the deposit attached to the original `rlp_execute` call was already transferred into the wallet contract's balance by the NEAR runtime as part of processing the `FunctionCall` action (this happens before any contract logic runs), and the wallet contract exposes no generic "withdraw"/"cancel" method for an external caller to reclaim funds they attached, the deposit is permanently retained by the wallet contract with no path for the depositor to recover it.

### Impact Explanation
Any unprivileged account (a relayer submitting an eth-emulated base-token transfer with `address_check` set, or any caller invoking `rlp_execute` with an attached deposit) that hits this specific rejection branch loses its attached NEAR permanently — the funds remain locked in the wallet contract's balance forever, since no subsequent transaction can extract them for the depositor. This is the same class of bug as the referenced report: value is accepted into a contract on behalf of a caller, but the code path that should return it on failure is missing for a particular flow, causing permanently frozen funds.

### Likelihood Explanation
This is reachable by a single external transaction: any account calling `rlp_execute` on a wallet contract with `target` pointing to an eth-implicit address that has already been mapped to a named account in the registrar, while not itself being the wallet's own signer/access key holder. This is a normal relayer interaction pattern (per the design comments around relayers using access keys), so the condition is easily triggerable in production usage without any special privilege.

### Recommendation
In the early-return branch of `address_check_callback` (the `else` branch handling `maybe_account_id.is_some()` when the caller is not the wallet itself), issue the same refund transfer performed in `rlp_execute_callback` for the `caller_deposit` before returning the failure `ExecuteResponse`, or route this branch through `rlp_execute_callback`/a shared refund helper so that every failure path consistently returns the caller's attached deposit.

### Proof of Concept
1. A relayer calls `wallet_contract.rlp_execute(target, tx_bytes_b64)` with an attached deposit, encoding an Ethereum transaction that is an `EOABaseTokenTransfer` with `address_check: Some(address)` where `address` corresponds to an address that the on-chain registrar has already mapped to an existing named `AccountId`.
2. `inner_rlp_execute` builds `caller_deposit = Some(CallerDeposit { account_id: relayer, yocto_near: attached_deposit })` and schedules `address_registrar.lookup(address).then(address_check_callback(target, action, caller_deposit))`. [4](#0-3) 
3. The registrar lookup returns `Some(account_id)` and `env::signer_account_id() != current_account_id` (the relayer is not using the wallet's own access key), so `address_check_callback` returns `PromiseOrValue::Value(ExecuteResponse{success:false, error: Some("Invalid target: ...")})` directly. [7](#0-6) 
4. No refund promise is created because `rlp_execute_callback` (the only refund path) is never invoked. The attached deposit remains in the wallet contract's balance, unrecoverable by the relayer who sent it.

    /// Callback after checking if an address is contained in the registrar.
    /// This check happens when the target is another eth implicit account to
    /// confirm that the relayer really did check for a named account with that address.
    #[private]
    pub fn address_check_callback(
        &mut self,
        target: AccountId,
        action: near_action::Action,
        caller_deposit: Option<CallerDeposit>,
    ) -> PromiseOrValue<ExecuteResponse> {
        self.has_in_flight_tx = false;
        let maybe_account_id: Option<AccountId> = match env::promise_result(0) {
            PromiseResult::Failed => {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Call to Address Registrar contract failed".into()),
                });
            }
            PromiseResult::Successful(value) => match serde_json::from_slice(&value) {
                Ok(x) => x,
                Err(_) => {
                    return PromiseOrValue::Value(ExecuteResponse {
                        success: false,
                        success_value: None,
                        error: Some("Unexpected response from account registrar".into()),
                    });
                }
            },
        };
        let current_account_id = env::current_account_id();
        let promise = if maybe_account_id.is_some() {
            // We intentionally do not increment the nonce in this case because the
            // error is caused by a faulty relayer, not the user. An honest relayer
            // may still be able to successfully send the user's intended transaction.
            if env::signer_account_id() == current_account_id {
                create_ban_relayer_promise(current_account_id)
            } else {
                return PromiseOrValue::Value(ExecuteResponse {
                    success: false,
                    success_value: None,
                    error: Some("Invalid target: target is address corresponding to existing named account_id".into()),
                });
            }
        } else {
            // We must increment the nonce at this point to prevent replay of the transaction.
            // Recall that the nonce was not incremented in `inner_rlp_execute` in the case that
            // the registrar contract was called (i.e. in the case we end up inside this callback).
            self.nonce = self.nonce.saturating_add(1);
            let ext =
                WalletContract::ext(current_account_id).with_static_gas(RLP_EXECUTE_CALLBACK_GAS);
            match action_to_promise(target, action)
                .map(|p| p.then(ext.rlp_execute_callback(caller_deposit)))
            {
                Ok(p) => p,
                Err(e) => {
                    return PromiseOrValue::Value(e.into());
                }
            }
        };
        self.has_in_flight_tx = true;
        PromiseOrValue::Promise(promise)
    }

/// A data type to keep track of the deposit given by an external caller.
/// This allows us to refund the caller's deposit if the cross-contract call fails.
#[derive(Debug, PartialEq, Eq, Clone, serde::Serialize, serde::Deserialize)]
pub struct CallerDeposit {
    pub account_id: AccountId,
    pub yocto_near: NonZeroU128,
}

impl CallerDeposit {
    pub fn new(context: &ExecutionContext) -> Option<Self> {
        // Only track for external (non-self) callers
        if context.current_account_id == context.predecessor_account_id {
            return None;
        }

        NonZeroU128::new(context.attached_deposit.as_yoctonear()).map(|yocto_near| Self {
            account_id: context.predecessor_account_id.clone(),
            yocto_near,
        })
    }
}
