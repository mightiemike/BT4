I searched protobuf-go for the broken-invariant pattern behind CVE-2025-1721 (improper clearing of heap memory leading to sensitive-data disclosure): sync.Pool/buffer reuse without zeroing, `Reset()`/`Clear()` semantics, `MarshalAppend`/`growcap` buffer growth, lazy-unmarshal buffer sharing, and unsafe-pointer message state handling.

None of these show a reachable path where allocated-but-uninitialized or stale heap memory from a prior operation is exposed to an unprivileged caller on a default binary or ProtoJSON decode/encode path:

- `proto.Reset`/`resetMessage` explicitly clears all known fields, extension fields, and unknown fields before returning the message to a pool-like reuse pattern. [1](#0-0) 
- `MarshalAppend`/`growcap` in `proto/encode.go` only ever writes and returns bytes explicitly produced by the marshaler; callers only ever observe `len(b)` bytes of the returned slice, never stale capacity beyond it. [2](#0-1) 
- The scratch-buffer pools in `internal/order/range.go` (`messageFieldPool`, `mapEntryPool`) truncate to `[:0]` before use and are only ever read back up to the newly appended length, so no stale entries from a previous request are exposed. [3](#0-2) 
- Lazy sub-message buffer sharing (`XXX_lazyUnmarshalInfo`) is an intentional, documented performance optimization where a sub-message shares the parent's already-trusted decode buffer — this is not a bug and does not expose out-of-band heap memory. [4](#0-3) 
- `messageState`/`pointer` unsafe-pointer tricks in `internal/impl/pointer_unsafe.go` and `internal/impl/message_reflect.go` are carefully scoped to reinterpret a message's own already-allocated struct memory (with explicit tests guarding against corruption), not to read arbitrary adjacent heap memory. [5](#0-4) 

There is no analogous "IBM Concert"-style improper-heap-clearing defect reachable via a trusted-schema binary or ProtoJSON parse that would leak previously-allocated memory contents to an unprivileged caller.

```go
func resetMessage(m protoreflect.Message) {
	if !m.IsValid() {
		panic(fmt.Sprintf("cannot reset invalid %v message", m.Descriptor().FullName()))
	}

	// Clear all known fields.
	fds := m.Descriptor().Fields()
	for i := 0; i < fds.Len(); i++ {
		m.Clear(fds.Get(i))
	}

	// Clear extension fields.
	m.Range(func(fd protoreflect.FieldDescriptor, _ protoreflect.Value) bool {
		m.Clear(fd)
		return true
	})

	// Clear unknown fields.
	m.SetUnknown(nil)
}
```

```go
func testNoExcessiveCopy(t *testing.T, unmarshalOpts proto.UnmarshalOptions) {
	m := &mixedpb.OpenLazy{
		Opaque: mixedpb.OpaqueLazy_builder{
			Opaque: mixedpb.OpaqueLazy_builder{
				OptionalInt32: proto.Int32(23),
			}.Build(),
		}.Build(),
	}
	if got, want := m.GetOpaque().GetOpaque().GetOptionalInt32(), int32(23); got != want {
		t.Errorf("Build(): unexpected optional_int32: got %v, want %v", got, want)
	}
	b, err := proto.Marshal(m)
	if err != nil {
		t.Fatalf("Could not marshal healthy proto %v.", m)
	}
	mm := &mixedpb.OpenLazy{}
	if err := unmarshalOpts.Unmarshal(b, mm); err != nil {
		t.Fatalf("Could not unmarshal healthy proto buffer: %v.", b)
	}
	m2 := mm.GetOpaque()
	m3 := mm.GetOpaque().GetOpaque()
	// Now, if we deliberately destroy the OpaqueM2 buffer, the OpaqueM3 buffer should
	// be destroyed as well
	if m2.XXX_lazyUnmarshalInfo == nil {
		if m3.XXX_lazyUnmarshalInfo != nil {
			t.Errorf("Inconsistent lazyUnmarshalInfo for subprotos")
		}
		// nothing to check, we don't have backing store
		return
	}
```
