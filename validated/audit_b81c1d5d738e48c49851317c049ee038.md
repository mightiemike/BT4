### Title
Unprivileged actors can inflate `ActiveBallotIDs` to make every new ballot's synchronous expiry scan increasingly expensive - (File: `x/uvalidator/keeper/ballot.go`)

### Summary
The external report describes a DoS where an attacker inexpensively creates many unfinalized entries that an operator/admin must later process in bulk, and the per-call cost of that processing scales with the number of entries the attacker created. Push Chain has a structurally analogous pattern: `CreateBallot` synchronously calls `ExpireBallotsBeforeHeight`, which performs a full linear scan of the `ActiveBallotIDs` collection on *every single new ballot creation* [1](#0-0) , and ballot creation is driven directly by ordinary, unprivileged inbound/outbound observations rather than by a privileged actor.

### Finding Description
`VoteOnInboundBallot` and `VoteOnOutboundBallot` derive a ballot key from attacker-influenced inbound/outbound data (`source_chain:tx_hash:log_index` for inbounds, `utx_id:outbound_id:observation` for outbounds) and call `k.uvalidatorKeeper.VoteOnBallot`, which creates a brand-new `Ballot` whenever the derived key hasn't been seen before [2](#0-1) .

`CreateBallot` always runs `ExpireBallotsBeforeHeight` before persisting the new ballot: [3](#0-2) 

`ExpireBallotsBeforeHeight` iterates the *entire* `ActiveBallotIDs` collection and does a `Ballots.Get` for every active ballot to check its expiry height, regardless of how many of those ballots have anything to do with the current caller: [4](#0-3) 

Because `MsgVoteInbound` and `MsgVoteOutbound` are on the gasless allowlist [5](#0-4) , and inbound-enabled checking only gates by chain, not by value or frequency [6](#0-5) , an attacker with no privileged role can trigger this expensive path repeatedly by simply broadcasting many distinct, cheap cross-chain deposit transactions on a supported source chain. Universal Validators are obligated to observe and vote on each one, and each unique observation creates a new ballot, which re-triggers the O(N) `ExpireBallotsBeforeHeight` scan over every currently active ballot (inbound ballots, outbound ballots, and chain-meta ballots all share the same `ActiveBallotIDs`/`Ballots` collections, based on `BallotObservationType`). As the attacker keeps producing new distinct events faster than existing ballots naturally expire, `len(ActiveBallotIDs)` grows and the fixed per-vote overhead paid by every honest UV for every subsequent vote (inbound, outbound, or chain-meta) grows accordingly — a compounding cost imposed on the entire validator set by ordinary, unprivileged user activity, structurally mirroring the mntEth pattern where cheap request creation inflates a collection that a fixed operation must scan in full.

### Impact Explanation
This does not directly move funds, but it degrades the shared voting/finalization infrastructure used by inbound execution, outbound execution, and chain-meta ballots. If the active-ballot set is inflated faster than the natural expiry rate, the per-vote gas overhead on `MsgVoteInbound`/`MsgVoteOutbound`/`MsgVoteChainMeta` rises for all UVs, which can slow or eventually stall ballot finalization for legitimate cross-chain transactions — a denial-of-service against the universal-execution finalization pipeline that is triggerable purely through unprivileged, ordinary external-chain deposit activity (no malicious validator or admin required).

### Likelihood Explanation
Medium-to-low confidence without dynamic verification. The finding is architecturally sound (confirmed via code reading), but I could not execute or benchmark it, and I was unable to verify: (1) the concrete `DefaultExpiryAfterBlocks` value and how quickly ballots naturally drain from `ActiveBallotIDs` relative to the rate an attacker could realistically create cheap cross-chain deposits, (2) whether IAVL-backed collection iteration at realistic active-ballot counts is cheap enough that this never becomes materially disruptive within a single block's gas budget, and (3) whether any upstream filtering (e.g., minimum bridged amount, per-chain rate limits) exists elsewhere in the inbound-observation pipeline that would make bulk cheap-event creation impractical. These are exactly the kind of details a background engineering session with load-testing tools would need to confirm before treating this as exploitable in practice.

### Recommendation
Decouple ballot-expiry pruning from the ballot-creation hot path: either (a) bound `ExpireBallotsBeforeHeight`'s per-call work (e.g., process at most K expired candidates per invocation, using a time/height-ordered secondary index instead of a full scan), or (b) move expiry pruning to a periodic `EndBlocker`/`BeginBlocker` job with a fixed per-block budget rather than running it synchronously and unboundedly inside every `CreateBallot` call.

### Proof of Concept
Not independently executed. Conceptually: an attacker submits N distinct low-value deposit transactions on a supported source chain with unique `tx_hash`/`log_index` values. Honest UVs observe and vote on each via `MsgVoteInbound`, and each such vote whose ballot key hasn't been seen before triggers `CreateBallot` → `ExpireBallotsBeforeHeight`, which does a full `ActiveBallotIDs` scan (`x/uvalidator/keeper/ballot.go:320-347`). Repeating this while `ActiveBallotIDs` outgrows its natural expiry rate increases the fixed cost paid by every subsequent honest vote transaction across the whole validator set.

```go
func (k Keeper) CreateBallot(
	ctx context.Context,
	id string,
	ballotType types.BallotObservationType,
	eligibleVoters []string,
	votingThreshold int64,
	expiryAfterBlocks int64,

	if err != nil {
		return types.Ballot{}, err

		"ballot_id", id,
		"ballot_type", ballotType.String(),
		"eligible_voters", len(eligibleVoters),
		"voting_threshold", votingThreshold,
		"expiry_after_blocks", expiryAfterBlocks,
		"block_height", blockHeight,
	)

	// First, expire any old ballots before this height
	if err := k.ExpireBallotsBeforeHeight(ctx, blockHeight); err != nil {
		return types.Ballot{}, err
	}
```

```go
// ExpireBallotsBeforeHeight checks active ballots and marks expired ones.
// It uses a two-phase approach: first collect IDs to expire, then mutate,
// to avoid modifying the ActiveBallotIDs collection during iteration.
func (k Keeper) ExpireBallotsBeforeHeight(ctx context.Context, currentHeight int64) error {
	iter, err := k.ActiveBallotIDs.Iterate(ctx, nil)
	if err != nil {
		return err
	}

	// Phase 1: collect IDs to expire
	var toExpire []string
	for ; iter.Valid(); iter.Next() {
		id, err := iter.Key()
		if err != nil {
			iter.Close()
			return err
		}

		ballot, err := k.Ballots.Get(ctx, id)
		if err != nil {
			iter.Close()
			return err
		}

		if ballot.BlockHeightExpiry <= currentHeight {
			toExpire = append(toExpire, id)
		}
	}
```

```go
func (k Keeper) VoteOnInboundBallot(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	inbound types.Inbound,
) (isFinalized bool,
	isNew bool,
	err error) {
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return false, false, err
	}

	universalValidatorSet, err := k.uvalidatorKeeper.GetEligibleVoters(ctx)
	if err != nil {
		return false, false, err
	}

	// number of validators
	totalValidators := len(universalValidatorSet)

	// votesNeeded = ceil(2/3 * totalValidators)
	// >2/3 quorum similar to tendermint
	votesNeeded := (types.VotesThresholdNumerator*totalValidators)/types.VotesThresholdDenominator + 1

	k.Logger().Debug("voting on inbound ballot",
		"ballot_key", ballotKey,
		"validator", universalValidator.String(),
		"total_validators", totalValidators,
		"votes_needed", votesNeeded,
	)

	// Convert []sdk.ValAddress → []string
	universalValidatorSetStrs := make([]string, len(universalValidatorSet))
	for i, v := range universalValidatorSet {
		universalValidatorSetStrs[i] = v.IdentifyInfo.CoreValidatorAddress
	}

	// Step 2: Call VoteOnBallot for this inbound synthetic
	_, isFinalized, isNew, err = k.uvalidatorKeeper.VoteOnBallot(
		ctx,
		ballotKey,
		uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
		universalValidator.String(),
		uvalidatortypes.VoteResult_VOTE_RESULT_SUCCESS,
		universalValidatorSetStrs,
		int64(votesNeeded),
		int64(types.DefaultExpiryAfterBlocks),
	)
	if err != nil {
		return false, false, err
	}

	if isNew {
		k.Logger().Debug("inbound ballot created", "ballot_key", ballotKey)
	}
	if isFinalized {
		k.Logger().Info("inbound ballot finalized", "ballot_key", ballotKey, "source_chain", inbound.SourceChain)
	}

	return isFinalized, isNew, nil
```
