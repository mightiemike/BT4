### Title
`execute_replace_class` in the Starknet OS Cairo program omits the declared-class check that Blockifier enforces, allowing state entries with unvalidated class hashes - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The `replace_class` syscall lets any contract change its own `class_hash` at runtime, analogous to `ERC20Ubiquity.setSymbol` letting a "fixed" identifier be re-assigned. In the Rust Blockifier execution path this operation is properly guarded: the class must be declared and must be a Cairo1 (V1) class before the state's `class_hash_at(address)` entry is overwritten. [1](#0-0) [2](#0-1) 

However, the Starknet OS's own Cairo re-implementation of the same syscall — used for re-execution/state-transition verification — performs no such check, and the omission is explicitly flagged as unfinished by the developers.

### Finding Description
In `execute_replace_class`, the code reads the requested `class_hash` from the syscall request and, without any validation that a class with that hash was ever declared, immediately writes it into the contract's `StateEntry` in `contract_state_changes`: [3](#0-2) 

The comment on line 902, `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`, confirms this is a known, intentionally-deferred gap rather than an intended design choice.

Compare this to the two Rust Blockifier implementations of the same syscall, both of which read/verify the compiled class before allowing the replacement, and additionally reject V0 (Cairo0) classes:
- `SyscallHintProcessor::replace_class` (new syscalls): calls `self.state.get_compiled_class(class_hash)?` and rejects non-Cairo1 classes via `is_cairo1`.
- `DeprecatedSyscallHintProcessor::replace_class`: calls `syscall_handler.state.get_compiled_class(request.class_hash)?` before updating the class hash.

The `execute_replace_class` in `syscall_impls.cairo` — which underlies the Starknet OS's re-execution/state-transition-function proving path — has no equivalent guard: `%{ GetContractAddressStateEntry %}` simply fetches the current dict entry by contract address, and the function unconditionally constructs `new_state_entry` with the caller-supplied `class_hash`, then commits it via `dict_update`.

This is a genuine soundness gap in the component whose entire purpose is to independently re-verify that a block's state transition (including all class-hash updates) corresponds to a valid execution per Starknet's semantics. The OS is the last line of defense that produces the proven, committed state root; if its Cairo logic for a specific syscall does not enforce an invariant that the "reference" Rust implementation enforces, the OS can be made to accept (and cryptographically commit to) a state transition that violates that invariant — i.e., a contract's `class_hash` being set to a value that was never declared.

### Impact Explanation
Accepting an undeclared/arbitrary `class_hash` for a contract's state entry means the Starknet OS can commit a state root associating a contract address with a class hash for which no CASM/Sierra was ever declared or committed to the class-hash commitment tree. This is a wrong-committed-root risk and a funds-freezing risk: any future call into that contract address would find no compiled class for that hash (since honest sequencer nodes derived from Blockifier will never allow this, but a prover/OS execution using this Cairo path could still "prove" such a transition), permanently bricking the contract's account/logic, or producing a state root divergent from what honest Blockifier execution would produce — i.e., an honest-node divergence between the Rust state-transition function and the proven Cairo state-transition function for the exact same input.

### Likelihood Explanation
Under normal, honest sequencing, the OS re-executes only the successful call trace that Blockifier itself already validated (which does enforce the "declared" check), so this exact code path is not reachable through an honestly-produced block, since Blockifier would already have reverted an `replace_class(<undeclared class>)` call before it becomes part of a committed, non-reverted call trace. The bug is therefore latent rather than trivially triggerable through a single well-formed transaction under an honest sequencer, but it represents a real correctness gap in the OS's independent verification of the state-transition function — the very check that the Starknet OS should perform to be considered a valid re-execution of arbitrary claimed hints, since the OS's job is to verify (not simply trust) that the state transition is valid.

### Recommendation
Implement the check flagged by the TODO: before writing the new `class_hash` into `contract_state_changes` in `execute_replace_class` (`syscall_impls.cairo`), verify against `contract_class_changes` / the declared-classes commitment that the given `class_hash` corresponds to a class that was actually declared, mirroring the `get_compiled_class` check performed in Blockifier's `syscall_base.rs::replace_class`. Additionally consider enforcing the same V0/V1 restriction that Blockifier enforces ("Cannot replace V1 class hash with V0 class hash") to keep OS semantics fully aligned with the reference implementation.

### Proof of Concept
1. In Blockifier (`crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs`), calling `test_replace_class` with an undeclared class hash correctly reverts with "is not declared". [4](#0-3) 
2. In the OS Cairo implementation, `execute_replace_class` performs the identical operation (updating `contract_state_changes` for the syscall's `class_hash`) with no equivalent declared-class lookup or failure path, as shown by the code and the explicit TODO comment at line 902 of `syscall_impls.cairo`. Any Cairo hint/trace that reaches this function with an arbitrary `class_hash` will be accepted and committed without validation, unlike the Rust reference implementation.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
