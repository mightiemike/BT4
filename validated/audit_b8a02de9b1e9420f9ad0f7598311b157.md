Confirmed: `GetOrCreateBallot` in `x/uvalidator/keeper/ballot.go:70-89` fetches an existing ballot by `id` alone and, if found, returns it directly without ever comparing the stored `ballot.BallotType` to the `ballotType` argument passed in by the caller.

### Title
Ballot type confusion via `GetOrCreateBallot` missing discriminator check on `ballot_type` - (File: x/uvalidator/keeper/ballot.go)

### Summary
`x/uvalidator`'s generic ballot machine identifies a ballot purely by a string `id` (a sha256 digest computed by the caller in `x/uexecutor`/`x/utss`). `GetOrCreateBallot` [1](#0-0)  only checks `k.Ballots.Get(ctx, id)` for existence — it never verifies that the returned ballot's `BallotType` field matches the `ballotType` argument the caller supplied for this vote. This mirrors the report's root cause: data is accepted based on a size/existence check rather than a strict type/discriminator check, which the report calls "account type confusion."

### Finding Description
`VoteOnBallot` [2](#0-1)  calls `GetOrCreateBallot(ctx, id, ballotType, ...)`. If a ballot with that `id` already exists (created earlier for a *different* `ballotType*, e.g. INBOUND_TX vs OUTBOUND_TX vs FUND_MIGRATION vs TSS_KEY), the function returns the *existing* ballot unmodified, silently ignoring the caller-supplied `ballotType` — there is no `if ballot.BallotType != ballotType { return error }` guard. The rest of `VoteOnBallot` then adds the caller's vote to that pre-existing ballot and, on finalization, `MarkBallotFinalized` fires `k.fireBallotTerminalHook(ctx, ballot.Id, ballot.BallotType, status)` using the ballot's *original* (possibly mismatched) `BallotType` [3](#0-2) . Downstream, `x/uexecutor`'s `BallotHooks.AfterBallotTerminal` switches on `ballotType` to decide how to interpret the terminal event (e.g., routes only `INBOUND_TX` through `afterInboundBallotTerminal`) [4](#0-3) .

The README explicitly documents this as intentional design ("The ballot type is opaque — `x/uvalidator` doesn't care what's being voted on" [5](#0-4) ), relying entirely on the caller-computed `id` (a canonical hash of the observation) to prevent collisions between ballot types. This is the exact analog of the Solana report: reliance on an implicit uniqueness assumption (buffer-size / id-uniqueness) rather than an explicit discriminator check inside the shared deserialization/lookup path.

### Impact Explanation
For this to be exploitable, an unprivileged attacker would need to cause `x/uexecutor` or `x/utss` to compute the *same* `ballotId` string for two logically distinct observations belonging to different `BallotObservationType`s (e.g., an INBOUND_TX observation and a TSS_KEY observation) — a hash collision or an id-derivation bug in the calling module. I could not locate, within the available index, the exact `ballotId` construction functions in `x/uexecutor`/`x/utss` to confirm whether they salt the hash input with the ballot type (which would fully neutralize this) or not. Given the file/size limits of the index, I was unable to verify this with full confidence.

### Likelihood Explanation
Low-to-speculative without confirming the `ballotId` derivation. If the id-generation functions already include the ballot type (or an equivalent domain separator) in the hash preimage, this finding is not exploitable and the missing check in `GetOrCreateBallot` is defense-in-depth only, not a live vulnerability.

### Recommendation
Add an explicit type check in `GetOrCreateBallot` (and/or `VoteOnBallot`): if a ballot already exists for `id`, verify `ballot.BallotType == ballotType` before proceeding, returning an error on mismatch — analogous to Anchor's discriminator check. This makes the module self-defending regardless of how the ballot ID is derived by callers, rather than relying on an implicit assumption documented only in a README.

### Proof of Concept
Not constructible from the indexed code alone: it requires demonstrating that `x/uexecutor`/`x/utss` can produce colliding `ballotId`s across different `BallotObservationType`s, and I could not locate/verify those id-generation call sites in the available index. Recommend a Devin session with full repo access to inspect `x/uexecutor` and `x/utss` ballot-id construction (e.g., `msg_vote_inbound.go`, `msg_vote_outbound.go`, TSS vote handlers) to confirm whether the hash preimage includes a type discriminator, which would determine whether this is a live vulnerability or already-mitigated defense-in-depth gap.

```go
// GetOrCreateBallot returns the ballot if it exists, otherwise creates it.
func (k Keeper) GetOrCreateBallot(
	ctx context.Context,
	id string,
	ballotType types.BallotObservationType,
	voters []string,
	votesNeeded int64,
	expiryAfterBlocks int64,
) (types.Ballot, bool, error) {

	if ballot, err := k.Ballots.Get(ctx, id); err == nil {
		k.Logger().Debug("ballot found (existing)", "ballot_id", id)
		return ballot, false, nil
	}

	k.Logger().Debug("ballot not found, creating new", "ballot_id", id, "ballot_type", ballotType.String())
	newBallot, err := k.CreateBallot(ctx, id, ballotType, voters, votesNeeded, expiryAfterBlocks)

	return newBallot, true, err
}
```

```go
func (k Keeper) MarkBallotFinalized(ctx context.Context, id string, status types.BallotStatus) error {
	if status != types.BallotStatus_BALLOT_STATUS_PASSED && status != types.BallotStatus_BALLOT_STATUS_REJECTED {
		return fmt.Errorf("invalid finalization status: %v", status)
	}

	ballot, err := k.Ballots.Get(ctx, id)
	if err != nil {
		return err
	}

	k.Logger().Debug("marking ballot as finalized",
		"ballot_id", id,
		"final_status", status.String(),
	)

	if err := k.ActiveBallotIDs.Remove(ctx, id); err != nil {
		return err
	}
	if err := k.FinalizedBallotIDs.Set(ctx, id); err != nil {
		return err
	}

	ballot.Status = status
	if err := k.Ballots.Set(ctx, id, ballot); err != nil {
		return err
	}

	k.fireBallotTerminalHook(ctx, ballot.Id, ballot.BallotType, status)
	return nil
```

```go
func (h BallotHooks) AfterBallotTerminal(
	ctx sdk.Context,
	ballotID string,
	ballotType uvalidatortypes.BallotObservationType,
	status uvalidatortypes.BallotStatus,
) error {
	switch ballotType {
	case uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX:
		return h.afterInboundBallotTerminal(ctx, ballotID, status)
	default:
		// OUTBOUND_TX, TSS_KEY, FUND_MIGRATION — not handled here.
		// See doc comment on BallotHooks for rationale on outbound.
		return nil
	}
}
```
