### Title
Reward theft from a non-equivocating miner via ECDSA signature malleability in PoisonMicroblock verification - (File: `stackslib/src/chainstate/stacks/db/transactions.rs`, `stacks-common/src/util/secp256k1/native.rs`)

### Summary
`handle_poison_microblock` accepts two `StacksMicroblockHeader`s as proof of miner equivocation solely by checking that both recover to the same public-key hash via `check_microblock_header_signer`, which in turn uses `Secp256k1PublicKey::recover_to_pubkey_without_validating_low_s`. Because this recovery routine explicitly skips low-S normalization, anyone can take a single honestly-signed, publicly broadcast microblock header and derive a second, high-S "malleated" signature over the identical message without the miner's private key, producing a byte-different but semantically identical header that still recovers to the same key. Submitting the honest header plus its malleated twin as a `PoisonMicroblock` transaction causes an honest miner to be slashed and the coinbase reward redirected to the attacker/"reporter," even though no genuine microblock-stream fork occurred.

### Finding Description
The broken equality: reward paid to poison-reporter should equal exactly one valid double-signature by the slashed miner **over two conflicting microblocks** (a genuine equivocation). Instead, the code only enforces "same signer pubkey hash," not "two distinct microblocks."

Code path:
- `handle_poison_microblock` calls `StacksChainState::check_microblock_header_signer(mblock_header_1, mblock_header_2)` and only checks that the recovered public-key hashes match (`pkh1==pkh2`); it never compares the block content fields (parent hash, sequence, tx merkle root, timestamp) for a genuine conflict, and it uses `mblock_header_1.sequence` directly as the "point of fork" for the payout record [1](#0-0) .
- The public-key recovery underneath explicitly skips low-S enforcement: `recover_to_pubkey_without_validating_low_s` passes `verify_low_s=false` to `recover_to_pubkey_possibly_with_low_s_verification`, which — unlike `recover_to_pubkey` (used for normal signature verification) — performs `ctx.recover_ecdsa` without ever rejecting a high-S signature [2](#0-1) .
- The codebase itself contains a `MessageSignature::with_negated_s` helper and a passing unit test (`test_with_negated_s`) that proves the malleability property directly: given only a valid signature and message (no private key), negating S produces a **different signature** (`assert_ne!`) that recovers to the **same public key** (`assert_eq!(recovered_from_orig, recovered_from_high_s, ...)`) [3](#0-2) .

Exploit flow: attacker observes any honestly-broadcast microblock header `H` signed by miner `M` (public information, no privilege required). Using `MessageSignature::with_negated_s` (or equivalent secp256k1 arithmetic anyone can perform), the attacker derives `H'` — byte-different from `H` (different signature encoding/recovery id), but with identical microblock content (same sequence, same parent hash, same tx merkle root). The attacker submits `PoisonMicroblock(H, H')`. `check_microblock_header_signer` recovers the same pubkey hash from both (since malleated signatures recover to the same key), so the check passes as if `M` genuinely signed two conflicting microblocks. Existing tests already show that content-identical headers are accepted as valid poison inputs as long as they differ in byte form and both recover to the claimed key, e.g. `process_poison_microblock_same_block` only asserts `mblock_1 != mblock_2` (byte inequality), not semantic conflict, before treating the report as valid [4](#0-3) .

Why existing guards fail: any naive fix comparing `mblock_header_1 == mblock_header_2` for byte-equality would still be bypassed, because the malleated signature bytes differ from the original even though the message/content is identical — this is exactly the scenario the question describes.

### Impact Explanation
This allows an attacker (unprivileged, no signer/miner key, no majority stake) to fabricate a fraudulent "poison" report against any miner whose microblock header they observe, causing that miner's matured coinbase reward to be diverted to the attacker as a "poison-microblock commission" (via `calculate_miner_reward`'s `poison_reporter_opt` branch, which pays the reporter instead of the miner) [5](#0-4) . This is block-reward theft from a non-equivocating miner — matching the Critical category ("block-reward theft/double-payment/loss") — and is repeatable against any miner who publishes microblocks, without needing their private key or majority stake.

### Likelihood Explanation
Preconditions are minimal: the attacker needs only (1) to observe one honestly-signed microblock header of a targeted miner (public, broadcast data) and (2) to be able to submit a standard `PoisonMicroblock` transaction with a valid `reporter` signature of their own (a normal, unprivileged transaction). No BTC spend, no stake, no majority position, and no compromise of the miner's key is required — this is purely public-key cryptography (ECDSA/secp256k1 malleability) applied by anyone with off-the-shelf tooling. The attack is fully repeatable against every miner that ever produces microblocks, bounded only by the `MINER_REWARD_MATURITY` window checked in `handle_poison_microblock` [6](#0-5) .

### Recommendation
- Change `check_microblock_header_signer` / `StacksMicroblockHeader::check_recover_pubkey` to use `Secp256k1PublicKey::recover_to_pubkey` (which enforces low-S) instead of `recover_to_pubkey_without_validating_low_s`, so malleated high-S signatures are rejected outright.
- Additionally, require that the two headers represent a genuine semantic conflict (e.g., same `sequence` but differing `prev_block`/`tx_merkle_root`, or other content fields) rather than relying solely on byte-inequality of the full header, to close any residual malleability/duplicate-encoding vector.

### Proof of Concept
Rust integration test plan (in `stackslib/src/chainstate/stacks/db/transactions.rs` test module, alongside `process_poison_microblock_same_block`):
1. Generate `block_privk`, sign one legitimate microblock header `mblock_1` via `make_signed_microblock(&block_privk, &privk, BlockHeaderHash([0x11; 32]), 123)`.
2. Without access to `block_privk`, derive `mblock_2` by cloning `mblock_1.header` and replacing its `signature` field with `mblock_1.header.signature.with_negated_s()`.
3. Assert `mblock_1.header != mblock_2` (byte-different) and separately assert both recover to the same pubkey hash via `StacksChainState::check_microblock_header_signer(&mblock_1.header, &mblock_2)` returning `Ok(pkh)` equal to `block_pubkh`.
4. Submit `TransactionPayload::PoisonMicroblock(mblock_1.header.clone(), mblock_2)` signed by an attacker-controlled `reporter_privk` who never possessed `block_privk`.
5. Call `StacksChainState::process_transaction` and assert it **succeeds** (currently) and that `get_poison_microblock_report` records the attacker as reporter — demonstrating reward diversion despite `mblock_1` and `mblock_2` encoding the identical microblock content (same `sequence`, `prev_block`, `tx_merkle_root`), i.e., no genuine equivocation occurred.

        msg: &[u8],
        sig: &MessageSignature,
    ) -> Result<Secp256k1PublicKey, &'static str> {
        Self::recover_to_pubkey_possibly_with_low_s_verification(msg, sig, false)
    }

    fn recover_to_pubkey_possibly_with_low_s_verification(
        msg: &[u8],
        sig: &MessageSignature,
        verify_low_s: bool,
    ) -> Result<Secp256k1PublicKey, &'static str> {
        _secp256k1.with(|ctx| {
            let msg = LibSecp256k1Message::from_slice(msg).map_err(|_e| {
                "Invalid message: failed to decode data hash: must be a 32-byte hash"
            })?;

            let secp256k1_sig = sig
                .to_secp256k1_recoverable()
                .ok_or("Invalid signature: failed to decode recoverable signature")?;

            if verify_low_s {
                let secp256k1_sig_standard = secp256k1_sig.to_standard();
                let mut secp256k1_sig_low_s = secp256k1_sig_standard;
                secp256k1_sig_low_s.normalize_s();
                if secp256k1_sig_low_s != secp256k1_sig_standard {
                    return Err("Invalid signature: high-S");
                }
            }

            let recovered_pubkey = ctx
                .recover_ecdsa(&msg, &secp256k1_sig)
                .map_err(|_e| "Invalid signature: failed to recover public key")?;

            Ok(Secp256k1PublicKey {
                key: recovered_pubkey,
                compressed: true,
            })
        })

    fn test_with_negated_s() {
        let priv_key = Secp256k1PrivateKey::from_hex(
            "7b48329a5126dad83fc583c309c2698ae2843acfb9a7023fb081d850386c6950",
        )
        .unwrap();
        let pub_key = Secp256k1PublicKey::from_private(&priv_key);
        let message =
            &hex_bytes("77949dd27dabb40847564f40afcde8b91e0f7baf2cc710415a4ac8b777104866").unwrap()
                [..];
        let original_sig = priv_key.sign(message).unwrap();
        let high_s_sig = original_sig.with_negated_s();

        assert_ne!(
            original_sig, high_s_sig,
            "low-S and high-S signatures should not be the same"
        );

        assert_eq!(
            original_sig,
            high_s_sig.with_negated_s(),
            "negating twice should bring back the original"
        );

        let (recovered_from_orig, recovered_from_high_s) = _secp256k1.with(|ctx| {
            let msg = LibSecp256k1Message::from_slice(message).unwrap();

            let secp256k1_orig_sig = original_sig.to_secp256k1_recoverable().unwrap();
            let recovered_from_orig = ctx.recover_ecdsa(&msg, &secp256k1_orig_sig).unwrap();

            let secp256k1_high_s_sig = high_s_sig.to_secp256k1_recoverable().unwrap();
            let recovered_from_high_s = ctx.recover_ecdsa(&msg, &secp256k1_high_s_sig).unwrap();

            (recovered_from_orig, recovered_from_high_s)
        });

        assert_eq!(
            recovered_from_orig, recovered_from_high_s,
            "both signatures should recover to the same public key"
        );

        assert_eq!(
            recovered_from_high_s, pub_key.key,
            "the recovered key should be identical to the original key"
        );
    }
