### Title
IP-based rate limiter uses raw, non-canonicalized address strings as cache keys, allowing per-connection representation differences to bypass the one-bucket-per-identity QPS limit - ([File: IPQpsStrategy.java])

### Summary
`IPQpsStrategy.loadLimiter` keys its `RateLimiter` cache purely on the raw string returned by `RuntimeData.getRemoteAddr()`, with no normalization/canonicalization of the address. Because `RuntimeData` populates this string directly from `HttpServletRequest.getRemoteAddr()` (HTTP) or `InetSocketAddress.getAddress().getHostAddress()` (gRPC) without any IP-address canonicalization, the same underlying network peer can be represented by multiple distinct strings (e.g. IPv4 `1.2.3.4` vs IPv4-mapped-IPv6 `::ffff:1.2.3.4` on dual-stack listeners), each of which gets its own independent `RateLimiter` bucket.

### Finding Description
`IPQpsStrategy.loadLimiter(String ip)` does `ipLimiter.get(ip, this::newRateLimiter)`, using `ip` verbatim as the Guava cache key. [1](#0-0) 

The `ip` value originates from `RuntimeData`, which for HTTP simply stores `HttpServletRequest.getRemoteAddr()` and for gRPC stores `InetSocketAddress.getAddress().getHostAddress()`, with no call to `InetAddress.getByName`, no stripping of the IPv4-mapped-IPv6 prefix, and no other normalization. [2](#0-1) 

`IPQPSRateLimiterAdapter` and `GlobalRateLimiter` both consume `RuntimeData.getRemoteAddr()` as-is and key their per-IP rate limiter caches on that raw string. [3](#0-2) [4](#0-3) 

On a dual-stack server socket (IPv4 and IPv6 both enabled, which is the default JVM/servlet-container configuration on most Linux hosts), a client connecting over IPv4 is reported by the servlet container as `1.2.3.4`, while the same client connecting to the IPv6-mapped address for the same NIC/host is reported as `::ffff:1.2.3.4` or the fully expanded IPv6 form. These are different Java strings and therefore different cache keys, giving the attacker two independent `RateLimiter` buckets for what is, from the server operator's intent, the same client identity. No canonicalization utility exists anywhere in the rate-limiter package to collapse these forms.

### Impact Explanation
Each additional string representation of the attacker's address doubles (or multiplies, if more representations exist) the effective QPS budget against endpoints protected by `IPQpsStrategy`/`GlobalRateLimiter`, including public JSON-RPC/HTTP endpoints that gate TVM constant-call and gas/energy estimation execution. This allows an attacker to materially underprice/oversubscribe expensive node-side constant-call work relative to the operator's configured qps, degrading availability/resource guarantees for other legitimate clients without needing distinct real IP addresses.

### Likelihood Explanation
This requires the node operator's HTTP/gRPC listener to be bound in dual-stack mode (common default) and the attacker to have both an IPv4 and IPv6 (or IPv4-mapped) path to reach the same listening socket — a realistic and commonly available network configuration for any public-facing FullNode/API server. No privileged access is required; the attacker is a normal unauthenticated client issuing standard HTTP/gRPC requests over two different local network stacks. It is fully repeatable for as long as the dual-stack condition holds.

### Recommendation
Canonicalize addresses before using them as rate-limiter cache keys: in `RuntimeData`, parse the raw address string with `InetAddress.getByName(...)` (or `InetAddresses.forString`) and use `InetAddress.getHostAddress()` on the canonical form (stripping IPv4-mapped-IPv6 prefixes back to the IPv4 form) before storing it as `address`, so `IPQpsStrategy` and `GlobalRateLimiter` always key on one canonical string per network identity.

### Proof of Concept
```java
// framework/src/test/java/org/tron/core/services/ratelimiter/strategy/IPQpsStrategyDualStackTest.java
@Test
public void testDualStackRepresentationsBypassLimiter() throws Exception {
  IPQpsStrategy strategy = new IPQpsStrategy("qps=2");

  String ipv4Form = "1.2.3.4";
  String ipv4MappedForm = "::ffff:1.2.3.4"; // same peer, different Java string

  int allowedFromIpv4 = 0;
  int allowedFromMapped = 0;
  for (int i = 0; i < 10; i++) {
    if (strategy.tryAcquire(ipv4Form)) allowedFromIpv4++;
    if (strategy.tryAcquire(ipv4MappedForm)) allowedFromMapped++;
  }

  // Expected (fixed) behavior: combined throughput bounded by qps=2 per unit time
  // Actual (vulnerable) behavior: allowedFromIpv4 + allowedFromMapped can exceed 2,
  // since each string gets its own independent RateLimiter bucket.
  assertTrue("Combined throughput must not exceed configured qps for one peer",
      (allowedFromIpv4 + allowedFromMapped) <= 2);
}
```
This test currently fails against `IPQpsStrategy` because `ipv4Form` and `ipv4MappedForm` are cached as separate keys in `ipLimiter`, each independently permitting up to the configured qps.

  private RateLimiter loadLimiter(String ip) {
    try {
      // cache.get is atomic: only one loader executes per key under concurrent requests,
      // preventing multiple RateLimiter instances from being created for the same IP.
      return ipLimiter.get(ip, this::newRateLimiter);
    } catch (Exception e) {
      logger.warn("Failed to load IP rate limiter for {}, denying request: {}",
          ip, e.getMessage());
      return null;
    }
  }

    if (o instanceof HttpServletRequest) {
      address = ((HttpServletRequest) o).getRemoteAddr();
    } else if (o instanceof ServerCall) {
      try {
        InetSocketAddress s = (InetSocketAddress)
                ((ServerCall) o).getAttributes().get(Grpc.TRANSPORT_ATTR_REMOTE_ADDR);
        address = s.getAddress().getHostAddress();
      } catch (Exception npe) {
        logger.warn("the address get from the runtime data is a null value unexpected.");
      }
    }

      logger.warn("assign the address with an empty string.");

    }
  }
