Confirmed: there is no retry or reclaim path for a failed `PcRefundExecution`. Once `applyGasRefund` in [1](#0-0)  exhausts both the swap-refund and no-swap fallback attempts and both fail, it simply records `refundPcTx.Status = "FAILED"` on the outbound and returns — there is no `MsgRetry*` message, no admin rescue path, and no mechanism anywhere in the codebase (`grep` for `RetryRefund`/`retryRefund`/`MsgRetry` returns nothing) to reclaim that excess gas fee later.

### Title
Permanent loss of excess relayer gas-fee refunds when `refundUnusedGas` fails on both swap and no-swap legs, with no retry or reclaim path - (File: x/uexecutor/keeper/outbound.go)

### Summary
`applyGasRefund` computes `gasFee - gasFeeUsed` (the analog of the "slightly larger amount sent than needed" scenario from the external report) and attempts to return the excess to the user via `CallUniversalCoreRefundUnusedGas`, first with a swap leg and then via a no-swap fallback [2](#0-1) . If both attempts return an error, the code only records `refundPcTx.Status = "FAILED"` and `refundPcTx.ErrorMsg = err.Error()` on `outbound.PcRefundExecution`, then proceeds to persist the outbound via `UpdateOutbound` [3](#0-2) . There is no subsequent code path — no user-facing message, no admin message, and no automatic retry — that ever re-attempts this refund or otherwise returns the withheld PRC20/gas-token value to the sender.

### Finding Description
The gas-fee excess (`refundAmount = gasFee - gasFeeUsed`) genuinely exists as accounted value that the protocol owes back to `refundRecipient` (the sender, or `RevertInstructions.FundRecipient`). The module's `GetUeModuleAddress` account (via `DerivedEVMCall` with `isModuleSender=true`) is the one invoking `refundUnusedGas` on the `UNIVERSAL_CORE` system contract [4](#0-3) . Both call attempts inside `applyGasRefund` can fail for reasons entirely outside user control — e.g., `GetDefaultFeeTierForToken` or `getSwapQuoteForRefund` erroring, or `CallUniversalCoreRefundUnusedGas` itself reverting on the EVM side (out-of-gas, slippage bound miss, contract-level revert, etc.). Once both the swap path and the `withSwap=false` fallback fail, `applyGasRefund` gives up silently: it writes a `"FAILED"` status onto `outbound.PcRefundExecution` for audit purposes only, and `handleSuccessfulOutbound`/`handleFailedOutbound` call `k.UpdateOutbound(ctx, utxId, outbound)` regardless of the refund outcome [5](#0-4) . Test coverage explicitly documents this exact behavior as expected/acceptable rather than treating it as an error state: "the outbound status stays OBSERVED (refund failure does not revert the outbound)" [6](#0-5) . Unlike the `RESCUE_FUNDS` / `RevertStuckInbound` flows, which exist specifically to reclaim funds stuck due to failed deposits or failed inbound-reverts [7](#0-6) [8](#0-7) , no equivalent recovery mechanism exists for a failed `PcRefundExecution`. The excess gas value is effectively left inaccessible once the finalization vote quorum for the outbound has already been recorded as `OBSERVED`/`REVERTED` — there is no further finalization step that revisits `PcRefundExecution.Status == "FAILED"`.

### Impact Explanation
This causes permanent loss/freezing of user-owed funds: the excess gas fee that should have been refunded to an ordinary user (via `refundRecipient`) is neither transferred nor recoverable through any exposed message. This matches the "Allowed Impact" criterion of permanent loss/freezing of user-controlled funds reachable from ordinary transaction flows (outbound voting by honest UVs) without any privileged actor involved in triggering the loss — the loss condition depends only on the destination-chain swap/fee-tier/quote lookup failing, which is plausible under normal operating conditions (e.g., illiquid or unconfigured gas-token pools, or destination gas price volatility causing the no-swap deposit call itself to revert).

### Likelihood Explanation
Moderate. It requires the swap-refund leg to fail (e.g., `GetDefaultFeeTierForToken`/quote lookup issues, or slippage-bound violation) AND the no-swap fallback deposit call to also fail (e.g., depositing to a token with special restrictions, or an EVM-level revert in `refundUnusedGas`). Both are plausible under real operational conditions (thin liquidity, misconfigured/unregistered gas tokens, or contract-level guard reverts on the destination PRC20/UniversalCore side) and do not require any malicious or privileged actor — an honest set of UVs voting on an ordinary outbound observation is sufficient to trigger the code path.

### Recommendation
When both refund attempts fail, do not treat the excess as silently lost: either (a) queue the failed refund into a durable, retryable state (analogous to `PendingOutbounds`/rescue flows) with an explicit message (e.g., `MsgRetryGasRefund`) that any party can trigger to re-attempt `CallUniversalCoreRefundUnusedGas` once conditions change, or (b) route the failed refund amount into an on-chain escrow keyed by `refundRecipient` that the recipient can later withdraw via a dedicated claim message. At minimum, surface `PcRefundExecution.Status == "FAILED"` as a queryable "needs manual intervention" state analogous to `Status_ABORTED`, and provide an admin-triggered recovery path mirroring `RescueFundsOnSourceChain`/`RevertStuckInbound`.

### Proof of Concept
1. Configure (or leave unconfigured) a gas token's Uniswap fee tier/quoter such that `GetDefaultFeeTierForToken` or `getSwapQuoteForRefund` returns an error for that token — this is attacker-independent, e.g., achievable simply by a token pool not existing.
2. Drive an ordinary outbound to `OBSERVED` (success path) or `REVERTED` (failure path) with `gasFeeUsed < gasFee`, as in the existing test `TestGasFeeRefund/"swap fallback reason stored when swap refund fails"` [6](#0-5) .
3. Additionally make the no-swap fallback (`CallUniversalCoreRefundUnusedGas(..., withSwap=false, ...)`) fail too (e.g., by having the `UniversalCore`/PRC20 deposit revert for that gas token).
4. Observe `outbound.PcRefundExecution.Status == "FAILED"` persisted permanently via `UpdateOutbound`, with no message type anywhere in the codebase capable of re-attempting or otherwise recovering `refundAmount` for `refundRecipient`.

func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}

	refundAmount := new(big.Int).Sub(gasFee, gasFeeUsed)
	gasToken := common.HexToAddress(outbound.GasToken)

	// Refund recipient: prefer fund_recipient in revert_instructions, fall back to sender
	refundRecipient := outbound.Sender
	if outbound.RevertInstructions != nil && outbound.RevertInstructions.FundRecipient != "" {
		refundRecipient = outbound.RevertInstructions.FundRecipient
	}
	recipientAddr := common.HexToAddress(refundRecipient)

	refundPcTx := &types.PCTx{
		Sender:      outbound.Sender,
		BlockHeight: uint64(ctx.BlockHeight()),
	}

	// Step 1: try refund with swap (gasToken → PC native)
	fee, swapErr := k.GetDefaultFeeTierForToken(ctx, gasToken)
	var swapFallbackReason string

	if swapErr == nil {
		quote, quoteErr := k.getSwapQuoteForRefund(ctx, gasToken, fee, refundAmount)
		if quoteErr == nil {
			minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
			minPCOut.Div(minPCOut, big.NewInt(100))

			resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, true, fee, minPCOut)
			if err == nil {
				refundPcTx.TxHash = resp.Hash
				refundPcTx.GasUsed = resp.GasUsed
				refundPcTx.Status = "SUCCESS"
				outbound.PcRefundExecution = refundPcTx
				return
			}
			swapFallbackReason = fmt.Sprintf("swap refund failed: %s", err.Error())
		} else {
			swapFallbackReason = fmt.Sprintf("quote fetch failed: %s", quoteErr.Error())
		}
	} else {
		swapFallbackReason = fmt.Sprintf("fee tier fetch failed: %s", swapErr.Error())
	}

	// Step 2: fallback — refund without swap (deposit PRC20 directly to recipient)
	ctx.Logger().Error("applyGasRefund: swap refund failed, falling back to no-swap",
		"outbound_id", outbound.Id,
		"reason", swapFallbackReason,
	)

	resp, err := k.CallUniversalCoreRefundUnusedGas(ctx, gasToken, refundAmount, recipientAddr, false, big.NewInt(0), big.NewInt(0))
	if err != nil {
		refundPcTx.Status = "FAILED"
		refundPcTx.ErrorMsg = err.Error()
	} else {
		refundPcTx.TxHash = resp.Hash
		refundPcTx.GasUsed = resp.GasUsed
		refundPcTx.Status = "SUCCESS"
	}

	outbound.PcRefundExecution = refundPcTx
	outbound.RefundSwapError = swapFallbackReason
}

// CallUniversalCoreRefundUnusedGas calls refundUnusedGas on UniversalCore to return excess gas fee
// to the recipient. withSwap=true swaps the gas token back to PC; withSwap=false deposits PRC20 directly.
func (k Keeper) CallUniversalCoreRefundUnusedGas(
	ctx sdk.Context,
	gasToken common.Address,
	amount *big.Int,
	recipient common.Address,
	withSwap bool,
	fee *big.Int,
	minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	// fee is uint24 in Solidity — pass as *big.Int (go-ethereum ABI packs non-standard widths as *big.Int)
	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress,
		handlerAddr,
		big.NewInt(0),
		nil,
		true,
		false,
		true,
		&nonce,
		"refundUnusedGas",
		gasToken,
		amount,
		recipient,
		withSwap,
		fee,
		minPCOut,
	)
}
