### Title
`library_call` syscall does not enforce the `block_direct_execute_call` protection, allowing direct invocation of `__execute__` and bypassing account validation - (File: crates/blockifier/src/execution/syscalls/hint_processor.rs)

### Summary
The Kakarot report describes a reentrancy vector where a privileged "call into another account with a signed transaction" path let a caller re-enter the execution context without going through the normal validate→execute flow. Starknet's blockifier has an analogous, purpose-built guard for exactly this class of issue: `call_contract` refuses to invoke a contract's `__execute__` entry point directly (`maybe_block_direct_execute_call`), because `__execute__` is meant to run only once per transaction, after `__validate__`, invoked by the OS itself — not by another contract mid-execution. However, this guard is applied inconsistently: it is present in `call_contract` for both the VM (`SyscallHintProcessor::call_contract`) and Native (`NativeSyscallHandler::call_contract`) handlers, and in the Cairo0 OS/deprecated syscall path (`assert_not_equal(... EXECUTE_ENTRY_POINT_SELECTOR)`), but it is **not** applied in the `library_call` syscall implementation.

### Finding Description
`maybe_block_direct_execute_call` is defined once in `syscall_base.rs` and is explicitly invoked from `call_contract` in:
- `crates/blockifier/src/execution/syscalls/hint_processor.rs` (`SyscallHintProcessor::call_contract`) — checks `syscall_handler.base.maybe_block_direct_execute_call(selector)` via `versioned_constants.block_direct_execute_call`. [1](#0-0) 
- `crates/blockifier/src/execution/native/syscall_handler.rs` (`call_contract`), also explicitly calls `self.base.maybe_block_direct_execute_call(selector)`. [2](#0-1) 
- The deprecated (Cairo0) syscall path in `hint_processor.rs::call_contract` checks `selector == selector_from_name(EXECUTE_ENTRY_POINT_NAME)`. [3](#0-2) 
- The Starknet OS (Cairo) version, `execute_deprecated_syscalls`, similarly asserts `call_contract_syscall.request.selector != EXECUTE_ENTRY_POINT_SELECTOR` for `CALL_CONTRACT_SELECTOR`. [4](#0-3) 

By contrast, `library_call` — in both the VM handler (`SyscallHintProcessor::library_call`) and the Native handler (`NativeSyscallHandler::library_call`) — builds the `CallEntryPoint` with `entry_point_selector: request.function_selector` (or `function_selector`) directly and invokes it via `execute_inner_call` without ever calling `maybe_block_direct_execute_call` or checking against `EXECUTE_ENTRY_POINT_NAME`/`EXECUTE_ENTRY_POINT_SELECTOR`. [5](#0-4) [6](#0-5) 

Likewise, the current (non-deprecated) Starknet OS `execute_library_call` in `syscall_impls.cairo` does not include an `assert_not_equal(..., EXECUTE_ENTRY_POINT_SELECTOR)` check like `execute_call_contract` for `CALL_CONTRACT_SELECTOR` — the guard is only wired up for `call_contract`, not `library_call`. [7](#0-6) [8](#0-7) 

Because `library_call` explicitly preserves the caller's `storage_address` and `caller_address` (i.e., it executes the target class's code *in the context of the calling contract*), a contract's code (reachable from an ordinary user-submitted `INVOKE` transaction targeting any contract, e.g., during `__validate__` or `__execute__` of a called contract, or from any other contract invoked mid-execution) can issue `library_call_syscall(class_hash=<victim_account_class_hash>, selector=EXECUTE_ENTRY_POINT_NAME, calldata=...)` and execute the victim account class's `__execute__` logic directly, entirely outside of the OS-driven validate→execute flow that `block_direct_execute_call` was specifically designed to prevent for `call_contract`.

### Impact Explanation
`__execute__` in account contracts is meant to run exactly once, after `__validate__` succeeds, driven only by the OS transaction-processing loop (see `run_execute`/`transaction_impls.cairo`, which invokes `__execute__` only after `check_and_increment_nonce`, fee/proof checks, and `run_validate`). The explicit purpose of `block_direct_execute_call`/`DirectExecuteCall` (confirmed by its dedicated error variant and tests such as `test_direct_execute_call`) is to stop any contract from directly triggering another contract's `__execute__` outside this controlled flow — this is precisely the reentrancy/state-integrity hazard flagged in the referenced Kakarot finding (an account's privileged execution logic being invoked out-of-band via a call path that was not covered by the reentrancy check). Since `library_call` bypasses this specific guard, an attacker-controlled or malicious contract reachable in a normal transaction's call graph can invoke a target account's `__execute__` at an unintended point in execution (e.g., mid-way through the attacker's own `__execute__`/inner call), enabling nonce/fee-state-inconsistent re-execution of account logic and violating the "run once, after validate" invariant the guard exists to enforce. This can result in unauthorized account actions and inconsistent execution/state relative to what nodes intend to allow, which the guard was added to prevent for `call_contract`.

### Likelihood Explanation
This is directly and trivially reachable by any unprivileged transaction sender: `library_call_syscall` is a standard, un-gated Starknet syscall available to any Cairo1 contract, requiring no special deployment, whitelisting, or privileged role — unlike the Kakarot case, which required going through a whitelisted `cairo_precompile`. Any contract can be written (and deployed by anyone) to call `library_call_syscall(class_hash, selector!("__execute__"), calldata)`. The only precondition is knowing the class hash of a target account contract whose `__execute__` is reachable this way, which is public information.

### Recommendation
Apply the same `maybe_block_direct_execute_call` (or an equivalent `EXECUTE_ENTRY_POINT_NAME`/`EXECUTE_ENTRY_POINT_SELECTOR` check) inside `library_call` in both the VM (`crates/blockifier/src/execution/syscalls/hint_processor.rs`) and Native (`crates/blockifier/src/execution/native/syscall_handler.rs`) syscall handlers, as well as in the corresponding deprecated syscall `library_call` implementations, and in the Starknet OS `execute_library_call` (and `execute_library_call_syscall` for Cairo0) in the Cairo program, mirroring the `assert_not_equal(..., EXECUTE_ENTRY_POINT_SELECTOR)` used for `call_contract`.

### Proof of Concept
Conceptual PoC (cannot be fully executed without a live devnet, but reachable via ordinary transaction submission):
1. Attacker deploys `Attacker` contract with a function that calls:
   `starknet::library_call_syscall(victim_account_class_hash, selector!("__execute__"), calldata)`.
2. Attacker submits a normal `INVOKE` transaction whose calldata routes to `Attacker`'s function.
3. During execution, `library_call` runs `victim_account_class_hash`'s `__execute__` code, in the context of the calling contract (`storage_address`/`caller_address` preserved from the caller), without the `call_contract` path's `EXECUTE_ENTRY_POINT_NAME` block — since `library_call` never invokes `maybe_block_direct_execute_call`. This directly contrasts with the equivalent attempt via `call_contract_syscall`, which is blocked and returns `DirectExecuteCall`/`Invalid argument`, as demonstrated in `test_direct_execute_call` in `crates/blockifier/src/execution/syscalls/syscall_tests/call_contract.rs` and `crates/starknet_os_flow_tests/src/tests.rs`. [9](#0-8) [10](#0-9)

    pub(crate) fn maybe_block_direct_execute_call(
        &mut self,
        selector: EntryPointSelector,
    ) -> SyscallResult<()> {
        let versioned_constants = &self.context.tx_context.block_context.versioned_constants;
        if versioned_constants.block_direct_execute_call
            && selector == selector_from_name(EXECUTE_ENTRY_POINT_NAME)
        {
            return Err(SyscallExecutionError::Revert { error_data: vec![INVALID_ARGUMENT_FELT] });
        }
        Ok(())
    }

    fn library_call(
        &mut self,
        class_hash: Felt,
        function_selector: Felt,
        calldata: &[Felt],
        remaining_gas: &mut u64,
    ) -> SyscallResult<Vec<Felt>> {
        self.pre_execute_syscall(
            remaining_gas,
            self.gas_costs().syscalls.library_call.base_syscall_cost(),
            SyscallSelector::LibraryCall,
        )?;

        let class_hash = ClassHash(class_hash);

        let wrapper_calldata = Calldata(Arc::new(calldata.to_vec()));

        let selector = EntryPointSelector(function_selector);

        let entry_point = CallEntryPoint {
            class_hash: Some(class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector,
            calldata: wrapper_calldata,
            // The call context remains the same in a library call.
            storage_address: self.base.call.storage_address,
            caller_address: self.base.call.caller_address,
            call_type: CallType::Delegate,
            initial_gas: *remaining_gas,
        };

        let error_wrapper_function =
            |e: SyscallExecutionError,
             class_hash: ClassHash,
             storage_address: ContractAddress,
             selector: EntryPointSelector| {
                e.as_lib_call_execution_error(class_hash, storage_address, selector)
            };

        Ok(self
            .execute_inner_call(entry_point, remaining_gas, class_hash, error_wrapper_function)?
            .0)
    }

// Implements the library_call syscall.
func execute_library_call{
    range_check_ptr,
    syscall_ptr: felt*,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    revert_log: RevertLogEntry*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, caller_execution_context: ExecutionContext*) {
    let request = cast(syscall_ptr + RequestHeader.SIZE, LibraryCallRequest*);
    let (success, remaining_gas) = reduce_syscall_base_gas(
        specific_base_gas_cost=LIBRARY_CALL_GAS_COST, request_struct_size=LibraryCallRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    // Prepare execution context.
    tempvar calldata_start = request.calldata_start;
    tempvar caller_execution_info = caller_execution_context.execution_info;
    tempvar execution_context: ExecutionContext* = new ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=request.class_hash,
        calldata_size=request.calldata_end - calldata_start,
        calldata=calldata_start,
        execution_info=new ExecutionInfo(
            block_info=caller_execution_info.block_info,
            tx_info=caller_execution_info.tx_info,
            caller_address=caller_execution_info.caller_address,
            contract_address=caller_execution_info.contract_address,
            selector=request.selector,
        ),
        deprecated_tx_info=caller_execution_context.deprecated_tx_info,
    );

    return contract_call_helper(
        remaining_gas=remaining_gas,
        block_context=block_context,
        execution_context=execution_context,
    );
}
