### Title
Integer-truncation in `CalculateGasCost` lets UEA gas fees round down to zero, allowing free `MsgExecutePayload`/CEA execution — ([File: x/uexecutor/keeper/fees.go])

### Summary
The external report describes a routing fee that cannot be forced to exactly `0` but can be trivially set to `1 wei`, letting users evade the protocol's fee mechanism. The Push Chain analog is in `x/uexecutor/keeper/fees.go`'s `CalculateGasCost`, which converts the EVM feemarket's `LegacyDec` base fee to an integer per-gas-unit price via `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`. Because this is integer (floor) division, any base fee below `1e18` (i.e. less than one whole `upc` per unit of gas) truncates to exactly `0`, making the "effective gas price" `0` and the resulting `gasCost` `0` — not merely small, but zero — regardless of how much real EVM gas was consumed. `DeductGasFeesFromReceipt` treats `gasCost.Sign() <= 0` as "nothing to charge" and returns success without deducting anything.

### Finding Description
`CalculateGasCost` computes the "effective gas price" purely from the network's dynamic `baseFee` (feemarket EIP-1559 base fee), ignoring `maxPriorityFeePerGas` entirely (explicitly commented as "not using maxPriorityFeePerGas"): [1](#0-0) 

The conversion from the module's `LegacyDec` representation to an integer per-gas price divides by `1e18`: [2](#0-1) 

Any `baseFee` value smaller than `1e18` in its `LegacyDec` encoding (i.e. an effective price of less than one whole `upc` per unit of gas) floors to `0` here. Since `effectiveGasPrice := baseFeeBig` and `gasCost := effectiveGasPrice * gasUsed`, `gasCost` becomes exactly `0` no matter how large `gasUsed` is.

`DeductGasFeesFromReceipt` then short-circuits on non-positive gas cost and treats it as a legitimate "nothing owed" case rather than an error: [3](#0-2) 

This function is the sole place gas fees are billed back to a UEA/CEA-recipient after real, module-originated `DerivedEVMCall` executions (`gasless=false` is used specifically so the receipt carries a real `GasUsed` to bill against — see `DERIVED_TRANSACTIONS.md`). It is invoked from every user-reachable payload-execution path:
- `ExecutePayload` (direct `MsgExecutePayload`, a gasless-Cosmos-fee message type reachable by any unprivileged caller): [4](#0-3) 
- `ExecutePayloadV2`: [5](#0-4) 
- CEA smart-contract inbound execution: [6](#0-5) 

The base fee is not admin- or governance-set directly; it is the standard dynamic EIP-1559 base fee tracked by the `feemarket` module, which naturally decays toward its configured floor whenever block gas usage is below target — an ordinary, unprivileged market condition, not a privileged action. Whenever that dynamic value (expressed in the `LegacyDec`/1e18 fixed-point encoding used here) falls under `1e18`, this code path zeroes out billing entirely, even though `MaxFeePerGas` supplied by the payload only has to clear that (also-zero) floor to pass the `maxFeePerGas.Cmp(baseFeeBig) < 0` check.

### Impact Explanation
This corrupts the gas-fee accounting invariant for module-originated EVM execution: when the (truncated) base fee is `0`, any unprivileged user can submit `MsgExecutePayload` (or trigger CEA execution via an inbound) and have arbitrary EVM computation performed against their UEA/recipient contract with zero `upc` deducted, no matter how much real gas the EVM call consumed. `MsgExecutePayload` is already a gasless-Cosmos-fee message type, so the intended payment for the protocol's real compute cost is exclusively this in-module gas-fee burn; when it silently zeroes out, execution becomes entirely free, letting an attacker consume Push Chain execution resources without paying — the direct analog of the routingFee-evasion bug's impact ("users can evade fees"), but here the fee can genuinely reach `0`, not just `1 wei`.

### Likelihood Explanation
Reachable by any unprivileged user with a deployed (or auto-deployable) UEA — no privileged role, validator collusion, or governance action is required. It only requires the network's naturally-updating EIP-1559 base fee to be under `1e18` in its internal fixed-point encoding at execution time, which is a normal, market-driven state (e.g., low network utilization causing base fee to decay toward its floor) rather than an edge case requiring active attacker manipulation of chain parameters.

### Recommendation
Do not floor-divide the `LegacyDec` base fee to an integer before multiplying by `gasUsed`; perform the multiplication in the higher-precision `LegacyDec`/`big.Int` domain first (e.g., `gasCost = ceil(baseFee * gasUsed) / 1e18`) so sub-`1e18` base fees still produce a proportionally non-zero charge, and treat a computed gas cost of `0` on non-zero `gasUsed` as at minimum requiring an explicit floor fee rather than silently skipping deduction.

### Proof of Concept
1. Let the feemarket's dynamic base fee decay (through normal low-utilization operation, or set directly in a test as `app.FeeMarketKeeper.SetBaseFee(ctx, sdkmath.LegacyDec)` with an underlying value less than `1e18`, e.g. `LegacyNewDecFromBigInt(big.NewInt(999999999999999999))` representing slightly under 1 whole `upc`/gas).
2. Submit `MsgExecutePayload` with `MaxFeePerGas` set to `"0"` (passes `maxFeePerGas.Cmp(baseFeeBig) < 0` since `baseFeeBig` is also `0` after the `Div(1e18)` truncation) and a payload that performs real, gas-consuming EVM work through the UEA (e.g., large data writes).
3. Observe `CallUEAExecutePayload`/`CallExecuteUniversalTx` report a non-zero `receipt.GasUsed`.
4. Observe `DeductGasFeesFromReceipt` -> `CalculateGasCost` returns `gasCost.Sign() <= 0`, so `DeductAndBurnFees` is never called and the UEA/recipient's `upc` balance is unchanged — real EVM computation was performed for free.

```go
func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}
```
