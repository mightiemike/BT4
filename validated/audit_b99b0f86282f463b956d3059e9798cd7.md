### Title
Missing Declared-Class Validation in Starknet OS `execute_replace_class` Allows Unvalidated Class-Hash State Writes - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall writes an arbitrary, attacker-supplied `class_hash` into `contract_state_changes` without verifying that the class is actually declared, unlike the Rust `blockifier` implementation of the same syscall, which explicitly performs this check. This is analogous to the `FeeSplitter.setCurves` bug: a state-affecting reference (here, a contract's `class_hash`) is accepted and committed without the validation that the "trusted" execution path (`blockifier`) enforces, creating a validation-parity gap between the two independent execution engines that are supposed to agree.

### Finding Description
Any account contract can invoke the `replace_class` syscall as part of a normal, unprivileged transaction — this is by design intended to let a contract change *its own* class hash. In the Rust `blockifier`, this is properly validated: [1](#0-0) 

which calls `self.state.get_compiled_class(class_hash)?` (erroring if undeclared) and further rejects Cairo0 (V0) targets via `is_cairo1`.

However, in the Starknet OS's Cairo re-implementation of the same syscall — used for independent re-execution/proving of blocks — this check is explicitly missing, and is even called out with a `TODO`: [2](#0-1) 

Note line 902: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` The function immediately proceeds to overwrite `state_entry.class_hash` with the caller-supplied `class_hash` and commits it into `contract_state_changes`, with no cross-check against `contract_class_changes` or any declared-class set.

The same pattern (no declared-class check) exists in the deprecated syscall path: [3](#0-2) 

By contrast, `deploy_contract.cairo` in the same OS module does perform basic invariant checks on the new state entry before applying it (`assert state_entry.class_hash = UNINITIALIZED_CLASS_HASH; assert state_entry.nonce = 0;`), showing that the OS module generally is expected to enforce state-transition invariants at this layer, and that `replace_class`'s omission is a genuine gap rather than an intentional design choice — it is explicitly documented as an outstanding TODO.

### Impact Explanation
The Starknet OS is the component that is supposed to independently re-verify block execution (Starknet OS re-execution), and it is this component's Cairo trace that ultimately underlies the committed state root/proof. Because `execute_replace_class` in the OS accepts and commits any felt value as a class hash without checking that it corresponds to a declared class or without checking it is a V1 class (as `blockifier` does), the OS's state-transition validity constraints are weaker than the sequencer's own execution engine. A contract's `class_hash` slot could end up set, in the OS-computed/committed state, to a value that is not a declared class hash, breaking the invariant that every deployed contract's class hash must be declared. If ever reached with such a value (a divergent code path — e.g., a bug or discrepancy in how the trace is fed to the OS versus how `blockifier` executed it, or future refactors relying on the OS's own validation instead of blockifier's), the contract effectively becomes permanently unusable (calls would fail to resolve any code) — a freezing-of-funds scenario for that contract, and a state root that does not match the invariants the protocol relies on for provable equivalence between engines.

### Likelihood Explanation
Reaching the `replace_class` syscall itself requires only a single unprivileged transaction from any deployed contract calling `replace_class_syscall`, which is a standard, permission-less operation. The specific exploitation of the *missing OS-side check* requires a scenario where the OS trusts a state transition without the same validation `blockifier` performs (e.g., proving/verification paths, or any code path where OS-level constraints are relied upon as the sole gatekeeper rather than as a redundant safety net to `blockifier`). Given that `blockifier` catches invalid `replace_class` targets during normal sequencer execution, this OS-level gap is a "defense in depth" gap rather than a directly, unconditionally exploitable one under all circumstances I could confirm — the exact severity depends on how strictly the OS is relied upon as an independent validity check versus purely replaying an already-validated trace, which I could not fully verify from the available code.

### Recommendation
Add the equivalent declared-class check in the Starknet OS Cairo implementation of `execute_replace_class` (both in `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo`), mirroring the check already present in `blockifier`'s `syscall_base.rs::replace_class` (`get_compiled_class` + `is_cairo1` checks), i.e., verify against `contract_class_changes`/the declared-classes set that the target `class_hash` is declared and is a Cairo1 (V1) class before committing the new `StateEntry`, resolving the outstanding `TODO(Yoni, 1/1/2026)`.

### Proof of Concept
Concrete exploitation could not be fully constructed/verified within the available tooling (no execution environment), since it depends on how strictly the OS's committed trace is cross-validated against `blockifier`'s independent checks elsewhere in the pipeline — I was unable to confirm whether any later commitment step (e.g., in `state.cairo` or `os.cairo`) re-validates class-hash declaration before finalizing the state root. This should be verified directly in a Devin session with the ability to trace the full OS commitment pipeline (`os.cairo`, `state.cairo`) to determine whether the missing check in `execute_replace_class` is caught downstream or truly unvalidated end-to-end.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}
