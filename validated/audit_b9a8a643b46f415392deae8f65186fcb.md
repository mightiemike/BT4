### Title
Starknet OS `execute_replace_class` omits declared-class validation performed by Blockifier, causing execution divergence and invalid committed state - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The external report's root cause is a missing validation of an identifier (`tokenId`) before it is used to mutate protected state, letting an attacker substitute an unrelated/invalid object to corrupt state belonging to others. The analogous class of bug in this repository is the `replace_class` syscall: the production Blockifier (Rust) execution path validates that the new `class_hash` is actually a declared, compatible class before writing it into contract state, but the Starknet OS's Cairo re-implementation of the same syscall performs no such check, as explicitly flagged by a `TODO` in the code.

### Finding Description
In the Blockifier's syscall implementation, `replace_class` explicitly ensures the class is declared before it is applied to state: [1](#0-0) 
and the syscall test suite confirms this is enforced for both the deprecated and current syscall paths, rejecting undeclared class hashes and incompatible Cairo0/Cairo1 replacements: [2](#0-1) [3](#0-2) 

In contrast, the Starknet OS (Cairo) implementation of the exact same syscall, `execute_replace_class`, writes the caller-supplied `class_hash` directly into `contract_state_changes` with no check that the class hash corresponds to a previously declared/compiled class: [4](#0-3) 
The code contains an explicit acknowledgment of the missing check: [5](#0-4) 
`// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`

This is the same bug class as the report: a state-mutating operation accepts an unvalidated identifier (here, `class_hash`, analogous to `tokenId`) and applies it to protected state without confirming it references a legitimate, expected object.

### Impact Explanation
The Starknet OS is used to re-execute the block for proving/verification (Starknet OS re-execution). If a transaction invokes `replace_class` with a `class_hash` that is not declared (or that is otherwise rejected by Blockifier, e.g. a Cairo0 class hash replacing a Cairo1 class), Blockifier will reject the transaction (or revert it), while the OS's Cairo implementation will accept it and commit the new (invalid/undeclared) class hash into `contract_state_changes`. This produces:
- A state diff / committed root computed by the OS that differs from the one computed by the sequencer's Blockifier execution (honest-node divergence between the two execution engines that are supposed to agree).
- A contract left pointing at a class hash with no corresponding compiled class, which can permanently break the contract (denial of service / freezing of contract functionality) once other components (that trust the OS-produced state) treat this class hash as valid.
- Since the OS's output ultimately feeds block hash/state commitment production, this can yield a wrong committed root relative to what the "correct" execution should produce, undermining the guarantee that Blockifier execution and OS re-execution match.

This satisfies the acceptance criteria of "honest-node divergence" and potential "wrong committed root," reachable via a single ordinary contract call using the `replace_class` syscall — no privileged, operator, or network role is required.

### Likelihood Explanation
Likelihood is high in terms of reachability: any contract can invoke `replace_class` as part of normal (unprivileged) execution; this is a standard, permissionless Starknet syscall. The only requirement to trigger the divergence is supplying an undeclared or otherwise invalid `class_hash` — trivially achievable by any user submitting a transaction that calls a contract exercising this syscall with a crafted `class_hash`. The `TODO` comment in the source itself confirms the maintainers are aware the check is currently absent in the OS's implementation, corroborating that this is a genuine, currently-unaddressed gap rather than a theoretical one.

### Recommendation
Add the missing declared-class validation in the Cairo `execute_replace_class` implementation (mirroring the Blockifier's `get_compiled_class`/declared-class check and the Cairo0/Cairo1 compatibility check performed by `syscall_handler.base.replace_class`), so that the OS rejects `replace_class` calls with undeclared or incompatible `class_hash` values identically to Blockifier, before writing the new `StateEntry` into `contract_state_changes`.

### Proof of Concept
Not executable in this analysis (no runtime/tooling access); the divergence is demonstrated structurally by comparing:
- Blockifier's `replace_class` (validates before writing): [1](#0-0) 
- Blockifier's negative test proving rejection of undeclared class hashes: [2](#0-1) 
- The OS's unchecked write path with explicit TODO acknowledging the gap: [6](#0-5) 

A conceptual PoC: submit an invoke transaction to a contract that calls `replace_class_syscall(undeclared_class_hash)`. Blockifier execution rejects/reverts this transaction with an "is not declared" error, while a from-scratch OS re-execution of the same block (using only the Cairo OS program) would accept it and commit the undeclared class hash into the state diff, producing a state/root mismatch.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
