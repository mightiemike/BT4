### Title
DoS via unbounded `VotesStore` iteration in `countVote()` reachable from unauthenticated HTTP/gRPC API - (File: framework/src/main/java/org/tron/core/Wallet.java)

### Summary
`Wallet.getPaginatedNowWitnessList()` calls a private `countVote(votesStore)` helper that performs a full linear scan of the entire `VotesStore` on every invocation, before any pagination (`offset`/`limit`) is applied. `VotesStore` grows by one entry per distinct account that has ever voted in the current epoch (populated by the unprivileged, publicly-callable `VoteWitnessContract`), and is only cleared once per maintenance cycle. Any anonymous caller can therefore inflate the store with many cheap voter accounts and then repeatedly invoke the public HTTP/gRPC endpoint that maps to `getPaginatedNowWitnessList()`, forcing the node to redo an O(n) scan over the entire voter set on every single request — directly analogous to the Nomad `Queue.contains()` bug, where anyone can grow a queue that is later scanned in O(n) by a function reachable without special privilege.

### Finding Description
`Wallet.getPaginatedNowWitnessList()` is exposed publicly via `GetPaginatedNowWitnessListServlet` (`doGet`/`doPost`), which only extends `RateLimiterServlet` for per-IP throttling and performs no authentication/authorization check. [1](#0-0) 

The handler unconditionally calls `wallet.getPaginatedNowWitnessList(offset, limit)`, which in turn calls the private `countVote(votesStore)` method that iterates the *entire* `VotesStore` via `votesStore.iterator()` regardless of the caller-supplied `limit`/`offset`: [2](#0-1) [3](#0-2) 

`VotesStore` is a persistent, on-disk key/value store keyed by voter address: [4](#0-3) 

Entries are added whenever *any* account submits a `VoteWitnessContract` transaction (an ordinary, unprivileged operation gated only by holding some TRX-derived "tron power"), via `VoteWitnessActuator.countVoteAccount()` / `VoteWitnessProcessor.execute()`, both of which write into `votesStore`: [5](#0-4) 

The store is only cleared once per maintenance cycle by `MaintenanceManager.doMaintenance()`, which itself performs the same unbounded scan (deleting entries as it counts): [6](#0-5) 

Between maintenance windows, the store's size only grows (bounded only by the number of distinct voting addresses an attacker is willing to create/fund), and every call to `getPaginatedNowWitnessList()` re-scans the whole thing — an unprivileged, publicly reachable, repeatable O(n) cost per request, exactly the class of issue described in the Nomad report (`Queue.contains()` looping the full unbounded, attacker-growable queue on every fraud check).

### Impact Explanation
An attacker who funds a modest number of accounts with enough frozen balance to cast `VoteWitnessContract` votes can inflate `VotesStore` to a large size cheaply relative to the ongoing cost imposed on every full node that serves the `GetPaginatedNowWitnessList` HTTP/gRPC endpoint. Once inflated, each subsequent call to this public endpoint forces every full/solidity node serving that API to iterate the whole store, consuming CPU and I/O disproportionate to the trivial `offset`/`limit` request — degrading node responsiveness for all API consumers and, if sustained by parallel requests (rate-limited per IP but not globally, and easily distributed across IPs), a broader denial-of-service against the node's RPC surface. This does not affect consensus correctness itself, but does degrade node/API availability, consistent with the "High Risk" DoS classification in the reference report.

### Likelihood Explanation
Likelihood is moderate: the attack requires funding multiple accounts to cast votes (a real, non-zero cost, as acknowledged in the analogous Nomad report — "this attack is costly to perform"), but no special privilege, and the endpoint is unauthenticated and reachable by anyone. The size of `VotesStore` also depends on organic network voting activity and how long since the last maintenance cycle, so impact varies with pre-existing state, but an attacker can deterministically drive up the worst case by adding more voter entries before hammering the endpoint.

### Recommendation
- Avoid performing a full-store scan on every API call; instead maintain and persist an incrementally updated aggregate vote-count structure (e.g., update per-witness vote totals directly when a vote transaction is processed) so real-time queries are O(1)/O(witness count) rather than O(all voters).
- If a full recompute is unavoidable for real-time accuracy, cache the result of `countVote()` for the current epoch and invalidate/refresh it only when new votes are recorded, rather than recomputing per HTTP request.
- Add a global (not just per-IP) cost/size-based throttle or maximum-store-size safeguard for this and other read APIs that scan whole stores, so store size growth cannot translate directly into unbounded per-request work.

### Proof of Concept
1. Fund N accounts with the minimum frozen balance/tron power needed to submit `VoteWitnessContract` votes; broadcast unique vote transactions from each, populating `VotesStore` with N entries (processed by `VoteWitnessActuator.countVoteAccount`, see `actuator/src/main/java/org/tron/core/actuator/VoteWitnessActuator.java:152-191`).
2. Repeatedly call the public HTTP endpoint `GET /wallet/getpaginatednowwitnesslist?offset=0&limit=1` (or the equivalent gRPC/HTTP-on-solidity variants also wired to `Wallet.getPaginatedNowWitnessList`) as an anonymous client.
3. Each call triggers `Wallet.countVote(votesStore)` to iterate all N entries (`framework/src/main/java/org/tron/core/Wallet.java:842-872`) before applying `offset`/`limit`, imposing O(N) cost per request regardless of the tiny requested page size — observe increasing CPU/latency on the serving node as N grows and request rate increases.

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    final Map<ByteString, Long> countWitness = Maps.newHashMap();
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();
    long sizeCount = 0;
    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) - voteCount);
        } else {
          countWitness.put(voteAddress, -voteCount);
        }
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        if (countWitness.containsKey(voteAddress)) {
          countWitness.put(voteAddress, countWitness.get(voteAddress) + voteCount);
        } else {
          countWitness.put(voteAddress, voteCount);
        }
      });
      sizeCount++;
      votesStore.delete(next.getKey());
    }
    logger.info("There is {} new votes in this epoch", sizeCount);
    return countWitness;
  }
