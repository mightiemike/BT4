### Title
`OsContractAddresses` (block-hash/alias/reserved contract addresses) is loaded as configurable data from per-version JSON instead of being a fixed protocol constant - ([File: crates/blockifier/src/blockifier_versioned_constants.rs])

### Summary
Starknet's OS reserves fixed contract addresses `0x1` (block-hash table), `0x2` (alias contract) and `0x3` (reserved) — these are hardcoded literals in the Cairo OS program (`constants.cairo`/`constants_template.txt`). In the Rust `blockifier`, however, these same addresses are represented by the `OsContractAddresses` struct, which is `Deserialize`d from the `blockifier_versioned_constants_*.json` resource files per Starknet version, rather than being defined as a Rust constant.

### Finding Description
`OsContractAddresses` is a `Deserialize`/`Serialize` struct with `block_hash_contract_address: u8`, `alias_contract_address: u8`, `reserved_contract_address: u8` fields, populated from `raw_constants.os_contract_addresses` inside `OsConstants::from_raw`. [1](#0-0) 

These values are supposed to always equal the Cairo OS program's hardcoded `BLOCK_HASH_CONTRACT_ADDRESS = 0x1`, `ALIAS_CONTRACT_ADDRESS = 0x2`, `RESERVED_CONTRACT_ADDRESS = 0x3`. [2](#0-1) 

Instead of being a Rust `const`, they are read from a per-Starknet-version JSON config file (`blockifier_versioned_constants_0_14_3.json`, etc.), and the only safeguard that these deserialized values stay in sync with the Cairo hardcoded constants is a unit test (`test_os_constants` in `apollo_starknet_os_program/src/constants_test.rs`) that regenerates `constants.cairo` from the JSON-derived `OsConstants` and diffs it against the checked-in file. [3](#0-2) [4](#0-3) 

The `alias_contract_address()` value derived from this configurable struct is used at block-build/re-execution time to actually write alias entries into contract storage during `allocate_aliases_in_storage`, and to compute the accessed-keys set used for the OS proof input: [5](#0-4) [6](#0-5) 

Because this is a runtime-configurable JSON value (not a compile-time constant enforced by the type system), a wrong/stale value in a per-version constants file — e.g., from a config error, a bad merge of a new version file, or a manual edit — would cause the blockifier (used to build blocks and to re-execute them for consensus/proving) to write the compressed-alias entries and compute `AccessedKeys` against the wrong contract address (any u8 value, not the fixed `0x2`), while the Starknet OS Cairo program used for proving always assumes `0x2`.

### Impact Explanation
If the deserialized `alias_contract_address`/`block_hash_contract_address` diverge from the fixed values the Cairo OS program uses:
- The block builder (native blockifier) would write alias mappings for stateful compression to a different storage location than the OS expects, producing a state diff/committed root that the OS re-execution (used for proving and by other honest nodes running the same JSON config correctly) would not reproduce — an honest-node state-root/proof divergence.
- `AccessedKeys::new`, which determines what trie leaves are fed to the OS as proof input, would compute the wrong set of storage keys for the alias contract, causing the OS to fail to find expected leaves (proof generation failure / re-execution mismatch), or, in a network where only some validators run a config with the bad value, a network split on the committed state root.

This matches the reported bug class ("a value that must be fixed should be a constant, not configurable, because inconsistent configuration causes malfunction") applied to a value on the sequencer's block-building/re-execution path that directly affects the committed state root.

### Likelihood Explanation
This is a Medium-likelihood configuration-integrity issue, not a directly attacker-triggerable bug: no unprivileged transaction, contract call, or L1 message can alter these values on its own. The risk is that these three values, which are protocol-fixed and referenced from many code paths (state compression, accessed-keys/proof input, OS constants generation) are stored as ordinary deserializable fields sourced from a per-version resource file rather than as `pub const` values enforced at compile time, relying solely on a checked-in-file diff test (`test_os_constants`) to catch drift. Any future new versioned-constants JSON file (each new Starknet version currently adds one, per the existing `blockifier_versioned_constants_0_13_*`/`0_14_*.json` files) that omits or mis-specifies `os_contract_addresses`, or any manual patch to one of the existing files, would not be caught by any runtime invariant check, only by the file-diff unit test, which does not run against every possible deployed configuration.

### Recommendation
Define `block_hash_contract_address`, `alias_contract_address`, and `reserved_contract_address` as compile-time Rust constants (mirroring `starknet_api::core::BLOCK_HASH_TABLE_ADDRESS`) instead of deserializable fields of `OsContractAddresses` sourced from per-version JSON files, and remove the corresponding fields from the versioned-constants JSON schema so they cannot be configured/overridden independently of the Cairo OS program's hardcoded values.

### Proof of Concept
Not directly exploitable by an external transaction sender; the issue is a configuration-integrity gap. A concrete reproduction path: introduce or edit a `blockifier_versioned_constants_*.json` file's `os_contract_addresses.alias_contract_address` to a value other than `2` (or omit the field so it defaults incorrectly) and observe that `OsConstants::from_raw` / `VersionedConstants::latest_constants()` accepts it without any runtime assertion tying it to the Cairo constant `0x2`, only surfacing a mismatch via the separate `test_os_constants` file-diff test rather than a hard invariant in `OsContractAddresses`'s construction path, as seen at: [7](#0-6)

pub struct OsContractAddresses {
    block_hash_contract_address: u8,
    alias_contract_address: u8,
    reserved_contract_address: u8,
}

impl OsContractAddresses {
    pub fn block_hash_contract_address(&self) -> ContractAddress {
        ContractAddress::from(self.block_hash_contract_address)
    }

    pub fn alias_contract_address(&self) -> ContractAddress {
        ContractAddress::from(self.alias_contract_address)
    }

    pub fn reserved_contract_address(&self) -> ContractAddress {
        ContractAddress::from(self.reserved_contract_address)
    }
}
