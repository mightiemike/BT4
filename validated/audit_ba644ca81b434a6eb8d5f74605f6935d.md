## Title
Transaction-output/TransactionInfo comparison silently skips state/hot-state/position checkpoint hash verification, letting replay tooling accept a divergent state root - (File: `types/src/transaction/mod.rs`)

### Summary
The bug-class in the external report is a "missing authenticity check on the destination side of a data hand-off": funds are moved but the code that is supposed to authenticate/finalize the transfer (`sgReceive`) is never invoked, so a corrupted/incomplete state (unclaimed ETH) is silently accepted. The Aptos-native analog is in `TransactionOutput::ensure_match_transaction_info` at [1](#0-0) , which is the function used by replay/debugging tooling to authenticate a freshly-computed `TransactionOutput` against the `TransactionInfo` that was actually committed and covered by the ledger accumulator. It checks status, gas, write-set hash and event root hash, but explicitly does **not** check `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash` — a gap the code itself documents as a known state-divergence blind spot.

### Finding Description
`TransactionOutput::ensure_match_transaction_info` is the authoritative comparator used to decide whether a locally/freshly produced VM output "matches" the authenticated `TransactionInfo` for a given version. It validates:
- execution status [2](#0-1) 
- gas used [3](#0-2) 
- write-set hash against `state_change_hash` [4](#0-3) 
- event root hash [5](#0-4) 

It then ends with an explicit acknowledgment that it never validates the state/hot-state/position checkpoint hashes: [6](#0-5) 

This function is relied upon by tools whose entire purpose is to detect exactly this class of divergence:
- `storage/db-tool/src/replay_on_archive.rs`'s `verify`/`execute_and_verify` path, which is the CI/operational "replay-verify" job run against mainnet archives to catch state-computation bugs before they cause a chain split, as seen in the surrounding verification loop [7](#0-6) .
- The `aptos move replay`/debugger CLI paths in `aptos-move/cli/src/commands.rs`, which call `ensure_match_transaction_info` to confirm a locally re-executed transaction matches the authenticated on-chain result [8](#0-7)  and [9](#0-8) .

Meanwhile, the true source of truth — `assemble_transaction_infos` in the executor — does compute and embed `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and (for V1) `position_state_checkpoint_hash` into the committed `TransactionInfo` [10](#0-9) , meaning these fields are integrity-critical: they are part of what gets hashed into the accumulator and ultimately into `LedgerInfo.transaction_accumulator_hash`. Yet the one function designed to independently re-verify a transaction's result against the authenticated record never re-derives and compares these values.

### Impact Explanation
If the state-tree/JMT/hot-state computation logic ever diverges from what was actually committed on mainnet (a latent bug in state summarization, hot-state promotion, or the new "position state" trading-native root, all of which are active areas of development per the TODO's own reference to `COMPUTE_TRADING_NATIVE_STATE_ROOTS`), the replay-verify pipeline and CLI debugger — the exact tools whose job is to catch this before/after a hard fork — would report a clean, successful match even though the locally-recomputed state root differs from the authenticated one. This is precisely the "Hard-fork-only divergence during commit, replay, restore, or proof verification" impact category: a wrong state root could pass automated and manual verification undetected, delaying or preventing detection of a consensus-breaking state-computation bug.

### Likelihood Explanation
The check is unconditionally skipped for every invocation of `ensure_match_transaction_info` (not gated behind a flag check that fails safe) — the comment says validation should be added "before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`," but the comparator ships now with the gap already present and callers unaware of the limitation.

### Recommendation
Extend `ensure_match_transaction_info` to recompute the local state-checkpoint-related hashes (based on `expected_write_set`/prior state) and compare them against `txn_info.state_checkpoint_hash()`, `txn_info.hot_state_checkpoint_hash()`, and `txn_info.position_state_checkpoint_hash()` whenever those fields are present, returning an error on mismatch just as is done for write-set and event-root hashes.

### Proof of Concept
Not directly exploitable as a standalone PoC since it requires an independent state-root-computation bug to manifest; the vulnerability is that when such a bug exists, `replay_on_archive`'s `execute_and_verify` (which calls into `ensure_match_transaction_info`) and the CLI replay commands at [8](#0-7)  would return `Ok(())`/no failed transactions even though `state_checkpoint_hash` (and friends) differ from the freshly computed value, silently masking the divergence that these tools exist specifically to surface.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    // Execute the verify one valid range
    pub fn verify(&self, start: Version, limit: u64) -> Result<Vec<Error>> {
        let mut total_failed_txns = Vec::with_capacity(limit as usize);
        let txn_iter = self
            .backup_handler
            .get_transaction_iter(start, limit as usize)?;
        let mut cur_txns = Vec::with_capacity(limit as usize);
        let mut cur_persisted_aux_info = Vec::with_capacity(limit as usize);
        let mut expected_events = Vec::with_capacity(limit as usize);
        let mut expected_writesets = Vec::with_capacity(limit as usize);
        let mut expected_txn_infos = Vec::with_capacity(limit as usize);
        let mut chunk_start_version = start;
        let executor = AptosVMBlockExecutor::new();
        for item in txn_iter {
            // timeout check
            if let Some(duration) = self.timeout_secs {
                if self.replay_stat.get_elapsed_secs() >= duration {
                    bail!(
                        "Verify timeout: {}s elapsed. Deadline: {}s. Failed txns count: {}",
                        self.replay_stat.get_elapsed_secs(),
                        duration,
                        total_failed_txns.len(),
                    );
                }
            }

            let (
                input_txn,
                persisted_aux_info,
                expected_txn_info,
                expected_event,
                expected_writeset,
            ) = item?;
            let is_epoch_ending = expected_event.iter().any(ContractEvent::is_new_epoch_event);
            cur_txns.push(input_txn);
            cur_persisted_aux_info.push(persisted_aux_info);
            expected_txn_infos.push(expected_txn_info);
            expected_events.push(expected_event);
            expected_writesets.push(expected_writeset);
            if is_epoch_ending || cur_txns.len() >= self.chunk_size {
                let cnt = cur_txns.len();
                while !cur_txns.is_empty() {
                    // verify results
                    let failed_txn_opt = self.execute_and_verify(
                        &executor,
                        &mut chunk_start_version,
                        &mut cur_txns,
                        &mut cur_persisted_aux_info,
                        &mut expected_txn_infos,
                        &mut expected_events,
                        &mut expected_writesets,
                    )?;
                    // collect failed transactions
                    total_failed_txns.extend(failed_txn_opt);
                }
                self.replay_stat.update_cnt(cnt as u64);
                self.replay_stat.print_tps();
            }
        }
        // verify results
        let fail_txns = self.execute_and_verify(
            &executor,
            &mut chunk_start_version,
            &mut cur_txns,
            &mut cur_persisted_aux_info,
            &mut expected_txn_infos,
            &mut expected_events,
            &mut expected_writesets,
        )?;
        total_failed_txns.extend(fail_txns);
        Ok(total_failed_txns)
    }
