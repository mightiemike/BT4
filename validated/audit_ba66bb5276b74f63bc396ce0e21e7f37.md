Based on my investigation, this question identifies a real, concrete asymmetry in the codebase.

### Title
Gasless `MsgMigrateUEA` permits free, uncapped-gas EVM execution due to missing fee deduction and `gasLimit=nil` — (`x/uexecutor/keeper/msg_migrate_uea.go`, `x/uexecutor/keeper/evm.go`)

### Summary
`MsgMigrateUEA` is still registered on `msgServer` and still present in the gasless allowlist, even though the module `README.md` describes the dedicated migration message as deprecated in favor of routing migration through `MsgExecutePayload`. Unlike the `ExecutePayload` path, the `MigrateUEA` keeper function never calls `DeductGasFeesFromReceipt`, and its EVM call is issued with an unbounded (`nil`) gas limit rather than a payload-capped one. The result is a call path that costs an unprivileged caller nothing at either the Cosmos fee layer or the EVM fee layer, while still triggering real EVM execution against an existing UEA contract.

### Finding Description
- `app/txpolicy/gasless.go` includes `MsgMigrateUEA` in `GaslessMsgTypes` [1](#0-0) , so `DeductFeeDecorator` and `MinGasPriceDecorator` both skip Cosmos-level fee charging for it.
- `msgServer.MigrateUEA` routes straight to `Keeper.MigrateUEA` with no privileged check other than a valid signer address [2](#0-1) .
- `Keeper.MigrateUEA` only requires the target UEA to already be deployed; it does not require `Signer == Owner`, and both migration payload and signature are opaque bytes that are only validated inside the destination UEA contract [3](#0-2) .
- `CallUEAMigrateUEA` invokes `DerivedEVMCall` with `gasLimit = nil` ("nil → use a sensible default" per the fork's own docs) [4](#0-3) [5](#0-4) . This is materially different from `CallUEAExecutePayload`, which parses and enforces an explicit, attacker/owner-supplied `gasLimit` from the payload [6](#0-5) .
- Critically, `Keeper.MigrateUEA` never calls `DeductGasFeesFromReceipt` after the EVM call completes [7](#0-6) . Compare this to `ExecutePayload`, which unconditionally deducts gas fees from the UEA regardless of success/failure [8](#0-7) , and to `ExecutePayloadV2`, which wraps the call + fee deduction in a `CacheContext` specifically to "close the free-execution gap" [9](#0-8) . `MigrateUEA` has neither of these protections.

The net effect: any unprivileged account can submit `MsgMigrateUEA` against any already-deployed UEA (their own or a victim's — the call doesn't require ownership, and garbage signature bytes just cause the UEA contract to revert after doing verification work), pay zero Cosmos transaction fee (gasless allowlist), and incur zero EVM-level fee deduction (missing `DeductGasFeesFromReceipt` call), while the EVM call runs at whatever "sensible default" gas limit the fork applies for a `nil` gasLimit rather than a bounded, attacker-controlled cap.

### Impact Explanation
This is a non-network-level DoS/resource-exhaustion vector: an unprivileged, unauthenticated caller can trigger repeated real EVM execution (state reads/writes, computation up to the fork's default gas ceiling) for free, with no accounting friction analogous to the one deliberately built into the sibling `ExecutePayload` path. Because the message is gasless and there is no per-call fee sink, an attacker can flood this path essentially at no cost, materially stressing execution/finalization compared to the intended, fee/cap-protected `ExecutePayload` equivalent.

### Likelihood Explanation
High. The entrypoint requires no special privilege — only a valid Cosmos signer, a `UniversalAccountId` referencing any already-deployed UEA, and arbitrary bytes for `MigrationPayload`/`Signature` (verification happens inside the contract, not the keeper). No governance, admin, validator, or TSS involvement is needed, and the message remains live in both the gRPC service and the gasless allowlist despite the module README stating the flow is deprecated.

### Recommendation
- Either fully remove `MsgMigrateUEA` from the gasless allowlist and the `MsgServer`/handler registration (matching the README's stated deprecation), or
- If it must remain live, bring `Keeper.MigrateUEA` to parity with `ExecutePayload`: enforce an explicit, bounded `gasLimit` (not `nil`) in `CallUEAMigrateUEA`, and call `DeductGasFeesFromReceipt` (ideally inside a `CacheContext` as done in `ExecutePayloadV2`/`ExecuteInboundFundsAndPayload`) so gas is always billed to the UEA regardless of success or failure.

### Proof of Concept
1. Deploy/observe an existing UEA for any `UniversalAccountId` (attacker's own account is sufficient).
2. Construct `MsgMigrateUEA{ Signer: attacker, UniversalAccountId: <deployed UEA id>, MigrationPayload: <arbitrary>, Signature: <arbitrary hex> }`.
3. Because `MsgMigrateUEA` is in `GaslessMsgTypes`, the ante `DeductFeeDecorator`/`MinGasPriceDecorator` charge zero fee and zero minimum gas price.
4. `msgServer.MigrateUEA` → `Keeper.MigrateUEA` → `CallUEAMigrateUEA` executes `migrateUEA(...)` on the UEA with `gasLimit=nil`; the contract's internal signature check fails (garbage signature) and reverts, but real EVM computation (verification/hashing) still runs up to the revert point.
5. `Keeper.MigrateUEA` returns the error without ever invoking `DeductGasFeesFromReceipt` — no upc is burned from any account.
6. Repeat steps 1–5 in a loop from a single, unfunded attacker account; each iteration consumes real EVM gas and CPU/finalization time at zero on-chain cost, which a Go integration test can assert by measuring cumulative `receipt.GasUsed` alongside zero balance change on both signer and UEA accounts.

	// Step 2: Wrap EVM execution + fee deduction in a CacheContext so they
	// commit/revert together. If fee deduction fails, the EVM state changes
	// from CallUEAExecutePayload are discarded — closes the free-execution
	// gap when the UEA has no native UPC to cover gas.
	cacheCtx, writeCache := sdkCtx.CacheContext()
	receipt, execErr := k.CallUEAExecutePayload(cacheCtx, evmFrom, ueaAddr, universalPayload, verificationDataVal)

	// Step 3: Try fee deduction in the same cache. DeductGasFeesFromReceipt
	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced
	// nothing to bill).
	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
		return receipt, execErr
	}
