### Title
Unauthenticated, cost-free on-chain account creation via `AccountInitDecorator` gasless bypass — state-bloat DoS (`File: app/ante/account_init_decorator.go`)

### Summary
`AccountInitDecorator` is the Push Chain analog of the reported `permit()` front-running pattern: it lets *any* unprivileged party trigger a privileged, state-mutating side effect (on-chain account creation) simply by presenting a validly-signed message from the gasless allowlist, with **no fee, no authorization check, and no dependency on whether the wrapped message itself is ever allowed to succeed**. Because the decorator commits its state change and then unconditionally short-circuits the ante chain (`return ctx, nil` without calling `next`), the account-creation side effect survives even when the wrapped message is later rejected for lacking authorization (e.g. an unbonded signer voting).

### Finding Description
`app/ante/account_init_decorator.go` runs for every `IsGaslessTx` transaction (`app/txpolicy/gasless.go` — `MsgExecutePayload`, `MsgVoteInbound`, `MsgVoteOutbound`, `MsgVoteChainMeta`, `MsgVoteTssKeyProcess`, `MsgVoteFundMigration`, `MsgMigrateUEA`, and any of these wrapped in `authz.MsgExec`): [1](#0-0) 

If the sole signer's account does not yet exist on chain, the decorator verifies the signature against a hardcoded `AccountNumber=0, Sequence=0`, then unconditionally creates the account: [2](#0-1) 

Crucially, on success it `return ctx, nil` — it never calls `next(ctx, tx, simulate)`. In `app/ante/ante_cosmos.go`, `AccountInitDecorator` sits *before* `SetPubKeyDecorator`, `SigVerificationDecorator`, and `IncrementSequenceDecorator`, and *after* `DeductFeeDecorator` (which is a no-op for gasless txs): [3](#0-2) 

This decorator only checks (a) the tx's message types are in the gasless allowlist, and (b) the signature is genuinely produced by the claimed key. It performs **no check that the signer is an authorized voter, bonded validator, or otherwise entitled to submit the wrapped message**. Actual authorization (e.g. `IsBondedUniversalValidator`) is only enforced deep in the message server, long after the ante chain has already committed the new account: [4](#0-3) 

In `baseapp.runTx`, the AnteHandler runs against its own branched cache-multistore, which is committed as soon as the AnteHandler returns successfully — *before* `RunMsgs` is attempted in its own separate branch. If the wrapped message subsequently fails (e.g. `"universal validator for signer ... is not bonded"`), only the message-execution branch is rolled back; the already-committed account creation from the AnteHandler branch persists.

Net effect: an attacker with an arbitrary freshly generated keypair and zero funds can:
1. Generate a keypair `K`.
2. Sign any gasless-allowlisted message (e.g. `MsgVoteInbound` with `Signer = K`) with `account_number=0, sequence=0` — a message that will inevitably be rejected downstream because `K` is not a bonded Universal Validator.
3. Broadcast it. `AccountInitDecorator` verifies the signature (which is legitimately over `K`'s own key — no forgery needed) and creates a real, persistent on-chain account for `K` with `sequence=1`, at zero cost.
4. The subsequent `VoteInbound` message fails and reverts, but the account creation is never rolled back.
5. Repeat indefinitely with new keypairs.

This is functionally the same bug class as the `permit()` report: a public, unauthenticated action (a gasless "first-use init" path meant only to bootstrap Universal Validator hotkeys) can be freely triggered by anyone who merely replicates the expected shape of a transaction, producing an unintended, hard-to-reverse state mutation that the honest design never intended to expose to arbitrary unprivileged callers.

### Impact Explanation
This is an unprivileged, network-independent denial-of-service / state-bloat vector: an attacker can grow the `x/auth` account store without bound, at zero monetary cost (the whole point of the gasless design is to avoid requiring funded accounts), degrading chain state size, IAVL tree growth, and genesis export size. It falls within the allowed "denial of service ... reachable without privileged control" and "corruption of ... canonical state" impact categories, since state is persisted from an unauthenticated bootstrap mechanism that was never meant to be publicly callable independent of eventual message authorization.

### Likelihood Explanation
High. No privileged role, no bonded validator status, no special key material, and no fee payment are required — only a fresh keypair and the ability to construct and sign a Cosmos SDK transaction with one of a small number of publicly known gasless message types. Push Chain's own design intentionally makes this path fee-free to support UV hotkey bootstrap, which is exactly what makes it cheap to abuse at scale.

### Recommendation
Gate `AccountInitDecorator`'s account-creation side effect on downstream authorization of the wrapped message (e.g. verify the signer is an eligible/bonded Universal Validator, or that it's a message that itself doesn't require any privileged role such as `MsgExecutePayload`), not merely on message *type* membership in the gasless allowlist. Alternatively, defer account creation to only commit if `next(ctx, tx, simulate)` (and ultimately message execution) also succeeds, or add a rate-limit/anti-spam cost (e.g. minimal gas consumption tied to a resource that can't be manufactured for free) to the "account does not exist" branch so it cannot be used as an unconditional public account-creation faucet.

### Proof of Concept
1. Generate an arbitrary new keypair `K` (never seen on-chain, no funds).
2. Build `MsgVoteInbound{ Signer: K.Address(), Inbound: <any> }` (or `MsgExecutePayload` similarly), sign with `account_number=0, sequence=0` using `K`'s private key.
3. Broadcast the tx directly (not via `authz.MsgExec`, or via it — both qualify as gasless per `IsGaslessTx`).
4. Observe: tx is accepted; `AccountInitDecorator` creates account `K` with `sequence=1`; the `VoteInbound` message itself fails with `"universal validator for signer ... is not bonded"`.
5. Query `x/auth` account state for `K` — the account persists despite the message failure.
6. Repeat with new keypairs to grow chain state arbitrarily, at zero fee cost per iteration.

func (aid AccountInitDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if !txpolicy.IsGaslessTx(tx) {
		// Skip account initialization for non-gasless transactions
		ctx.Logger().Debug("account init decorator: non-gasless tx, skipping account init")
		return next(ctx, tx, simulate)
	}

	sigTx, ok := tx.(authsigning.Tx)
	if !ok {
		return ctx, errorsmod.Wrap(sdkerrors.ErrTxDecode, "invalid transaction type")
	}

	signers, err := sigTx.GetSigners()
	if err != nil || len(signers) != 1 {
		ctx.Logger().Debug("account init decorator: could not get unique signer, passing to next handler",
			"num_signers", len(signers),
			"error", err,
		)
		return next(ctx, tx, simulate)
	}

	newAccAddr := signers[0]
	if !aid.ak.HasAccount(ctx, newAccAddr) {
		ctx.Logger().Debug("account init decorator: new account detected on gasless tx, verifying signature",
			"address", sdk.AccAddress(newAccAddr).String(),
			"simulate", simulate,
		)
		// if account does not exist on chain, bypass rest of ante chain (especially gas and signature verification) here.
		// Perform signature verification on account number e and sequence number e instead.
		if err := aid.verifySignatureForNewAccount(ctx, tx, simulate); err != nil {
			ctx.Logger().Debug("account init decorator: signature verification failed for new account",
				"address", sdk.AccAddress(newAccAddr).String(),
				"error", err,
			)
			return ctx, err
		}

		acc := aid.ak.NewAccountWithAddress(ctx, newAccAddr)
		acc.SetSequence(1)
		aid.ak.SetAccount(ctx, acc)
		ctx.Logger().Info("account init decorator: new account created via gasless tx",
			"address", sdk.AccAddress(newAccAddr).String(),
		)
		return ctx, nil
	}
