### Title
Uncaught exception (DoS) in `sanitizeHost()` via malformed `host` query parameter causing `atob()` to throw - (File: `packages/apps/shopify-api/lib/utils/shop-validator.ts`)

### Summary
`sanitizeHost()` validates the `host` parameter with a regex that checks character set but not base64 length validity, then passes it directly to `decodeHost()` → `atob()`. A `host` value whose length is not a multiple of 4 (e.g. a single character) passes the regex but causes `atob()` to throw an uncaught `DOMException`. This function is called synchronously, with no `try/catch`, from multiple unauthenticated request-handling paths (OAuth redirect, embedded app root redirect, Remix/React Router admin authentication).

### Finding Description
`sanitizeHost()` only checks that the `host` string consists of base64-alphabet characters: [1](#0-0) 

It never validates that the string's length is actually decodable base64 (i.e. length ≡ 0 mod 4, accounting for padding) before calling: [2](#0-1) 

`atob()` throws a `DOMException`/`InvalidCharacterError` for base64 strings whose length (mod 4) is invalid — e.g. a single-character string like `"A"` matches the regex `^[0-9a-zA-Z+/]+={0,2}$` but is not valid base64 length, so `atob("A")` throws.

This exactly mirrors the reported bug class: an external, attacker-controlled value (`host`) that satisfies a shallow validation check (character set, in the original report a byte-slice with no length bound) is passed to a decode routine that assumes well-formed input and panics/throws when that assumption is violated.

`sanitizeHost()` is called with no surrounding `try/catch` in several unauthenticated code paths, including: [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

These are all reached by an anonymous GET request carrying a crafted `host` query parameter — e.g. the OAuth begin/redirect flow and the Remix `authenticate.admin()` entrypoint, which run before any session/token validation.

### Impact Explanation
An uncaught exception thrown from a pre-authentication sanitization helper causes that request to fail with an unhandled error (500, or in async contexts an unhandled promise rejection). Because this code runs on the "front door" of embedded-app authentication (OAuth redirect / `authenticate.admin()`), an attacker can repeatedly trigger the throw with trivial single-request payloads (`?host=A`), producing a low-cost, repeatable denial-of-service against the authentication entrypoint of any embedded Shopify app built on `@shopify/shopify-api`. Depending on how the host application wires its global error/rejection handlers, this can manifest anywhere from an isolated failed request up to process-level instability in frameworks/setups without robust global exception handling.

### Likelihood Explanation
High — requires no authentication, no secrets, and no cooperation from Shopify or the merchant. A single crafted query string on a public, unauthenticated route (the login/OAuth-begin route or the embedded-admin authenticate route) is sufficient to trigger the throw every time.

### Recommendation
Validate base64 length/decodability (not just character set) before calling `atob()` in `decodeHost()`/`sanitizeHost()`, and wrap the decode step in a `try/catch` that treats decode failures as "invalid host" (returning `null` / throwing `InvalidHostError` as already done for other invalid-host cases) rather than letting the raw `DOMException` propagate uncaught. Apply the same defensive check anywhere else `atob()`/`decodeHost()` is used on external input.

### Proof of Concept
```
GET /api/auth?shop=test-shop.myshopify.com&host=A&embedded=1
```
This reaches `clientSideRedirect()` → `api.utils.sanitizeHost("A")` → `decodeHost("A")` → `atob("A")`, which throws an uncaught `DOMException`, since the regex `^[0-9a-zA-Z+/]+={0,2}$` accepts `"A"` but it is not a decodable base64 length. [7](#0-6)

function clientSideRedirect(
  api: Shopify,
  config: AppConfigInterface,
  req: Request,
  res: Response,
  shop: string,
): void {
  const host = api.utils.sanitizeHost(req.query.host as string);
  if (!host) {
    res.status(500);
    res.send('No host provided');
    return;
  }

  const redirectUriParams = new URLSearchParams({shop, host}).toString();
  const redirectUri = `${api.config.hostScheme}://${api.config.hostName}${config.auth.path}?${redirectUriParams}`;

  redirectOutOfApp({config, api})({req, res, redirectUri, shop});
}
