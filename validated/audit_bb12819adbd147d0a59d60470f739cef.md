### Title
Unvalidated single-block spot-price quote used as slippage bound for auto-swap deposits enables price-manipulation fund loss - (File: x/uexecutor/keeper/evm.go, x/uexecutor/keeper/execute_inbound_gas.go, x/uexecutor/keeper/execute_inbound_gas_and_payload.go)

### Summary
The `GAS` and `GAS_AND_PAYLOAD` inbound execution paths convert a deposited PRC20 into WPC (wrapped native PC) via `depositPRC20WithAutoSwap`, using a `minPCOut` bound computed exclusively from `GetSwapQuote`, an instantaneous Uniswap V3 `QuoterV2.quoteExactInputSingle` spot simulation. There is no sanity check of this quote against any independent, time-resistant reference (no TWAP, no chain-meta/oracle price comparison, no min/max bound), which is the exact analog of the Sherlock M-21 `ChainlinkOracle` finding: a price value is trusted and consumed without validating it is within a sane range before it drives value-moving logic.

### Finding Description
`GetSwapQuote` (`x/uexecutor/keeper/evm.go`) calls `quoteExactInputSingle` on the pool's current tick/liquidity state — a pure spot price — with no additional validation: [1](#0-0) 

That quote is immediately used, with a flat 95% multiplier and no other check, to compute `minPCOut` for the real swap in both the `GAS` inbound path: [2](#0-1) 

and the `GAS_AND_PAYLOAD` inbound path: [3](#0-2) 

as well as in the outbound gas-refund swap path (`x/uexecutor/keeper/outbound.go`, `getSwapQuoteForRefund` / `applyGasRefund`), where the same pattern is repeated for refunding excess relayer gas fees. In all cases, the flow is: fetch spot quote → derive `minPCOut = quote * 0.95` → execute the swap against the *same* pool state moments later, atomically within one Push Chain keeper call. Because the "sanity bound" (`minPCOut`) is derived from the very same manipulable state the swap is about to execute against, it provides no protection if that state has been pushed to an extreme by an attacker in a prior transaction (same block or an immediately preceding one). An unprivileged actor can:
1. Execute large swaps against the PRC20↔WPC Uniswap V3 pool used for auto-swap deposits/refunds, skewing the spot price sharply (thin pools/new PRC20 listings are especially cheap to move, since `defaultFeeTier` is fixed per PRC20 rather than routed through the deepest pool).
2. Trigger (or wait for) processing of an inbound `GAS`/`GAS_AND_PAYLOAD` tx (their own, or anyone else's pending one) while the pool is still skewed; `ExecuteInboundGas` / `gasAndPayloadDepositAutoSwap` computes `minPCOut` from the manipulated spot price and immediately swaps against that same manipulated price.
3. Reverse the initial swap to restore the pool, extracting the value difference as profit, while the depositor's PRC20 is converted into WPC at the manipulated (unfavorable) rate — i.e., the "sanity bound" never actually bounds anything because it is computed from the exact same corrupted source it is meant to guard against.

This is structurally identical to the Chainlink bug class: a price value from an on-chain source is consumed without any bound/deviation check against an independent reference, allowing an attacker to exploit incorrect pricing to extract value from depositors/the protocol.

### Impact Explanation
A user's `GAS`/`GAS_AND_PAYLOAD` inbound deposit (or a pending outbound gas refund) can be converted into WPC at an attacker-manipulated rate, causing partial loss of the deposited value that would normally accrue to the user's Push Chain gas balance, while the manipulator captures the difference by reversing their price-skewing trade. This is a fund-loss/mispriced-conversion vulnerability reachable purely by an unprivileged external actor interacting with a permissionless AMM pool and the default inbound/outbound flow, with no dependency on malicious validators or nodes.

### Likelihood Explanation
Likelihood depends on the actual liquidity depth of the specific PRC20↔WPC pool/fee-tier selected by `defaultFeeTier`; for newly onboarded or low-liquidity PRC20 tokens this is a realistic, single-block/two-transaction attack requiring only capital (or a flash loan) and no privileged access, matching the "user deposits, payloads" trigger class explicitly in scope.

### Recommendation
Do not derive the sole safety bound for an auto-swap from the same spot state the swap will execute against. Use a Uniswap V3 TWAP (`observe()`)-derived reference price, or compare the spot quote against the chain-meta/registry-configured price/oracle for the asset (with a bounded max deviation) before accepting it as the basis for `minPCOut`. Reject or fall back to a no-swap deposit path when the spot quote deviates beyond a configured threshold from the TWAP/reference price.

### Proof of Concept
1. Identify a PRC20↔WPC Uniswap V3 pool (fee tier returned by `GetDefaultFeeTierForToken`) with modest liquidity.
2. Attacker swaps a large amount of WPC into the pool for PRC20, sharply raising the PRC20 price relative to WPC (or vice versa, depending on desired direction).
3. While the pool is skewed, a `GAS`/`GAS_AND_PAYLOAD` inbound for the target PRC20 is processed by validators; `GetSwapQuote` returns a quote reflecting the skewed price; `minPCOut = quote * 95/100` is computed and `CallPRC20DepositAutoSwap` executes immediately against the same skewed pool [4](#0-3) , so the depositor receives WPC valued at the manipulated rate instead of a fair market rate.
4. Attacker reverses their initial swap, restoring the pool and realizing profit equal to the value difference extracted from the depositor's conversion.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
