### Title
Vault `transfer` is not gated by `pause-states`, letting share movement bypass a full DAO pause - (File: `mainnet/contracts/vault/v0-vault-usdc.clar` and equivalents for all six vault assets)

### Summary
Every vault contract (`vault-stx`, `vault-sbtc`, `vault-ststx`, `vault-usdc`, `vault-usdh`, `vault-ststxbtc`, and their `v0-` production twins) enforces `pause-states` on `deposit`, `redeem`, `system-borrow`, and `system-repay`, but the SIP-10 `transfer` entrypoint checks none of the six pause flags at all.

### Finding Description
`set-pause-states` lets the DAO halt `deposit`, `redeem`, `borrow`, `repay`, `accrue`, and `flashloan` in one call, and the docs describe this as "comprehensive pausability controls for security" used for "emergency pause for security incidents." [1](#0-0) 

Each state-changing vault function that moves value correctly gates itself on the relevant flag, e.g. `deposit` on `(get deposit states)`, `redeem` on `(get redeem states)`, `system-borrow` on `(get borrow states)`, and `system-repay` on `(get repay states)`: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

The `transfer` function, however, only re-runs `accrue`, checks sender authorization, and blocks sending to the current contract — it never inspects `pause-states`: [6](#0-5) 

Additionally, `accrue` itself is designed to "pass-through without reverting" when paused rather than block callers: [7](#0-6) 

So even the one indirect touchpoint `transfer` has with `pause-states` (via `accrue`) is a silent no-op, not a guard. This is the same bug class as the referenced Aave Lens `LensHub` finding: every other externally reachable, value-moving function is gated by the pause modifier, but the ERC20/SIP-10 transfer path is not, so governance cannot actually stop token movement even when it declares a full halt.

### Impact Explanation
Zest's `zft` vault shares are first-class transferable value: they are the SIP-10 token representing a lender's claim on the vault's underlying assets, and they are also used directly as market collateral (`collateral-add`/`collateral-remove` move `zft` via this same `transfer` function). When the DAO invokes `set-pause-states` with all flags set — the documented emergency response to "security incidents" — it expects all fund movement to stop. Because `transfer` ignores every pause flag, any holder of `zft` shares can continue to move them (to a fresh address, an AMM pool, or another market user) throughout the incident window. This defeats the only on-chain emergency control the protocol has for containing value in place during an active incident, allowing shares representing frozen/at-risk value to be relocated, sold, or laundered before the DAO can resolve the issue (e.g., before `socialize-debt` accounting is finalized). This lands on temporary freezing of funds being circumvented and directly enabling theft/realization of value the pause was meant to lock — a High severity impact, and it is reachable identically across all six production vaults.

### Likelihood Explanation
High. The missing check is not conditional on any other bug or privileged compromise — it is present verbatim in every vault contract in the mainnet directory. The only prerequisite is the DAO exercising its normal, documented pause functionality during a real incident, which is exactly the scenario the pause feature exists for.

### Recommendation
Add a check equivalent to `(asserts! (not (get <transfer-flag> (var-get pause-states))) ERR-PAUSED)` inside `transfer` (introducing a `transfer` field in the pause-states tuple, or reusing an existing appropriate flag) in every vault contract, mirroring the pattern already used by `deposit`, `redeem`, `system-borrow`, and `system-repay`.

### Proof of Concept
1. DAO detects an active incident affecting `v0-vault-usdc` and calls `set-pause-states` with `{deposit: true, redeem: true, borrow: true, repay: true, accrue: true, flashloan: true}`. [8](#0-7) 
2. An account holding `zUSDC` shares calls `(contract-call? .v0-vault-usdc transfer amount from to memo)`.
3. Execution proceeds: `accrue` is invoked but silently passes through without reverting because `accrue` is paused; the sender-authorization and self-transfer checks pass; `ft-transfer?` executes unconditionally. [6](#0-5) 
4. The `zUSDC` shares move to a new address (or are supplied to an external pool/market) despite the DAO's declared full pause, undermining the emergency freeze and allowing the underlying value they represent to be relocated/realized before the DAO can act.

(define-public (set-pause-states (states {deposit: bool, redeem: bool, borrow: bool, repay: bool, accrue: bool, flashloan: bool}))
  (begin
    (try! (check-dao-auth))
    (let ((current (var-get pause-states))
          (was-paused (get accrue current))
          (now-paused (get accrue states)))
      ;; When pausing accrue, accrue first to capture pending interest
      (if (and (not was-paused) now-paused)
          (begin (try! (accrue)) false)
          false)
      ;; When unpausing accrue, jump last-update to now to skip paused period
      (if (and was-paused (not now-paused))
          (var-set last-update stacks-block-time)
          false)
      (var-set pause-states states)
      
      (print {
        action: "vault-set-pause-states",
        caller: tx-sender,
        data: {
          vault: UNDERLYING,
          states: states
        }
      })
