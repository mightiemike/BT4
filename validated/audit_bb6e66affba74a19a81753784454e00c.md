### Title
`shop` parameter used in `tokenExchange()` is never cross-checked against the verified session-token `dest` claim - ([File: packages/apps/shopify-api/lib/auth/oauth/token-exchange.ts])

### Summary
`tokenExchange()` verifies the signature/audience of the incoming Shopify session token, but discards the decoded payload instead of using it as the source of truth for which shop the request is authorized for. It then trusts a separately supplied `shop` argument — which in the framework packages (`shopify-app-remix`, `shopify-app-react-router`) is taken from request context/URL rather than from the verified token — to build the OAuth token-exchange URL and to stamp the resulting `Session`.

### Finding Description
`decodeSessionToken()` only validates the JWT signature and, optionally, the `aud` claim; it does not validate that the payload's `dest` (the shop the token was minted for) matches the `shop` value the caller supplies: [1](#0-0) 

`tokenExchange()` calls `decodeSessionToken` purely to validate the token cryptographically, then immediately sanitizes and uses the externally supplied `shop` string — not `payload.dest` — to construct the access-token request URL and to build the resulting session: [2](#0-1) 

This is structurally identical to the reported bug class: a value that is expected to be an immutable, trusted "constant" derived from a verified source (here, the shop bound inside the signed session token) is instead re-obtained from an independent, externally influenced input and used unchanged for critical logic (building the OAuth request and the session identity), without a consistency/precondition check tying the two together.

In the Remix and React Router adapters, `shop` is threaded through `SessionContext`/`getShopFromRequest` and passed straight into `exchangeToken()`/`api.auth.tokenExchange()` alongside the (separately verified) `sessionToken`, with no code path shown that asserts `shop === new URL(payload.dest).hostname`: [3](#0-2) [4](#0-3) 

By contrast, the Express adapter derives `shop` directly from the verified token's `dest` claim, which is the safe pattern and shows the intended invariant that the other adapters don't enforce at the `tokenExchange()` layer itself: [5](#0-4) 

### Impact Explanation
If `shop` and the verified token's `dest` are allowed to diverge, `createSession()` stamps the resulting offline/online `Session` with the caller-supplied `shop` rather than the shop cryptographically bound to the token, and the outbound OAuth request is sent to `https://${cleanShop}/admin/oauth/access_token` using that same untrusted shop. Whether this is exploitable end-to-end depends on Shopify's OAuth server enforcing that the `subject_token`'s bound shop matches the URL shop — a check outside this repository's control — so worst case this is a defense-in-depth gap (missing local validation of a security-relevant, externally supplied value) rather than a proven confirmed cross-tenant takeover from this code alone.

### Likelihood Explanation
Requires only an unauthenticated/low-privilege caller capable of invoking the token-exchange endpoint with a self-controlled session token and an arbitrary `shop` value; no privileged actor or leaked secret is needed. Actual exploitability is bounded by whether Shopify's real token endpoint independently rejects a mismatch between the token's `dest` and the request's shop, which this codebase does not itself verify.

### Recommendation
In `tokenExchange()` (and the Remix/React Router strategies), always compare the caller-supplied `shop` against `payload.dest` from the token verified by `decodeSessionToken()` (as `perform-token-exchange.ts` already does for Express) and reject the request if they don't match, rather than trusting an independently sourced `shop` value for building the OAuth URL and session identity.

### Proof of Concept
Not independently confirmed against Shopify's live OAuth endpoint; the local code path that would need to be exercised is `tokenExchange({shop: "<attacker-chosen-shop>", sessionToken: "<valid token for a different shop>"})`, which currently proceeds without asserting `shop === new URL(payload.dest).hostname` in `packages/apps/shopify-api/lib/auth/oauth/token-exchange.ts`.

export function decodeSessionToken(config: ConfigInterface) {
  return async (
    token: string,
    {checkAudience = true}: DecodeSessionTokenOptions = {},
  ): Promise<JwtPayload> => {
    let payload: JwtPayload;
    try {
      payload = (
        await jose.jwtVerify(token, getHMACKey(config.apiSecretKey), {
          algorithms: ['HS256'],
          clockTolerance: JWT_PERMITTED_CLOCK_TOLERANCE,
        })
      ).payload as unknown as JwtPayload;
    } catch (error) {
      throw new ShopifyErrors.InvalidJwtError(
        `Failed to parse session token '${token}': ${error.message}`,
      );
    }

    // The exp and nbf fields are validated by the JWT library

    if (checkAudience && payload.aud !== config.apiKey) {
      throw new ShopifyErrors.InvalidJwtError(
        'Session token had invalid API key',
      );
    }

    return payload;
  };

export function tokenExchange(config: ConfigInterface): TokenExchange {
  return async ({
    shop,
    sessionToken,
    requestedTokenType,
    expiring,
  }: TokenExchangeParams) => {
    await decodeSessionToken(config)(sessionToken);

    const body = {
      client_id: config.apiKey,
      client_secret: config.apiSecretKey,
      grant_type: TokenExchangeGrantType,
      subject_token: sessionToken,
      subject_token_type: IdTokenType,
      requested_token_type: requestedTokenType,
      expiring: expiring ? '1' : '0',
    };

    const cleanShop = sanitizeShop(config)(shop, true)!;

    const postResponse = await fetchRequestFactory(config)(
      `https://${cleanShop}/admin/oauth/access_token`,
      {
        method: 'POST',
        body: JSON.stringify(body),
        headers: {
          'Content-Type': DataType.JSON,
          Accept: DataType.JSON,
        },
      },
    );

    if (!postResponse.ok) {
      throwFailedRequest(await postResponse.json(), false, postResponse);
    }

    return {
      session: createSession({
        accessTokenResponse: await postResponse.json<AccessTokenResponse>(),
        shop: cleanShop,
        // We need to keep this as an empty string as our template DB schemas have this required
        state: '',
        config,
      }),
    };
  };
