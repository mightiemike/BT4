### Title
Unbounded Gzip Decompression in RPC Declare-Transaction Handling Enables Zip Bomb Denial of Service - (File: crates/apollo_rpc/src/v0_8/api/mod.rs)

### Summary
The JSON-RPC layer's `decompress_program` function decompresses a user-supplied, base64-encoded gzip-compressed Cairo0 program with no output size or time limit, mirroring the exact bug class in the referenced Sliver `GzipEncoder.Decode()` advisory (GHSA-2phg-qgmm-r638): unbounded `read_to_end` on attacker-controlled gzip data.

### Finding Description
`decompress_program` decodes base64 and then reads a `GzDecoder` to completion with no cap on decompressed size: [1](#0-0) 

The comment `// TODO(dan): add time and size limits.` explicitly acknowledges the missing protection. This function is invoked by `user_deprecated_contract_class_to_sn_api`, which is called from `TryFrom<BroadcastedDeclareTransaction> for ExecutableTransactionInput` when handling a `BroadcastedDeclareV1Transaction` (a legacy/Cairo0 declare transaction) submitted by any unauthenticated JSON-RPC caller (e.g., via `estimate_fee` / `simulate_transactions`): [2](#0-1) 

This is directly analogous to `decode_and_decompress_with_size_limit` used elsewhere in the codebase for the same kind of data (e.g., `crates/apollo_http_server/src/deprecated_gateway_transaction.rs:294`, `crates/apollo_protobuf/src/converters/class.rs:133-135`), both of which bound the decompressed size via `decompress_with_size_limit` / a `.take(max_size + 1)` limiter in `crates/starknet_api/src/compression_utils.rs:33-46`. `decompress_program` bypasses this hardened path entirely and uses the raw, unlimited `flate2::read::GzDecoder` + `read_to_end`.

### Impact Explanation
A gzip payload can be compressed at a very high ratio (as in the PoC of the referenced advisory, gigabytes from a small compressed blob). Submitting such a payload as the `compressed_program` field of a `DeclareV1` transaction to a public JSON-RPC `estimate_fee`/`simulate_transactions` endpoint causes the sequencer's RPC node process to allocate an unbounded `Vec<u8>` during decompression, exhausting memory/CPU and crashing or hanging the process — a denial of service reachable by any unauthenticated remote caller without needing to submit a transaction to the mempool or pay fees, since fee estimation/simulation happens before admission.

### Likelihood Explanation
High likelihood: the endpoint is exposed to any RPC client, requires no special privileges, gas payment, or prior state, and the vulnerable code path is a straightforward pass of user-supplied bytes into an unbounded decompressor — exactly the bug class demonstrated in the reference advisory.

### Recommendation
Replace the manual `GzDecoder` + `read_to_end` in `decompress_program` with the existing hardened utility `decode_and_decompress_with_size_limit` (or equivalent `decompress_with_size_limit` logic using `.take(max_size)`) already used for the same data type elsewhere in the codebase (`crates/starknet_api/src/compression_utils.rs`), enforcing a maximum decompressed program size (e.g., matching `MAX_CAIRO0_PROGRAM_SIZE` used in `crates/apollo_protobuf/src/converters/class.rs`) before returning `PAYLOAD_TOO_LARGE`/error.

### Proof of Concept
1. Generate a highly compressible payload, e.g. in Python: `data = gzip.compress(bytes(1024*1024*1024))` repeated/concatenated to maximize the compression ratio (analogous to the Sliver PoC).
2. Base64-encode the resulting gzip bytes and place them into the `program` field of a `DeprecatedContractClass`/`compressed_program` for a `BroadcastedDeclareV1Transaction`.
3. Submit this transaction body to the node's JSON-RPC `starknet_estimateFee` or `starknet_simulateTransactions` endpoint.
4. The call reaches `TryFrom<BroadcastedDeclareTransaction>` → `user_deprecated_contract_class_to_sn_api` → `decompress_program`, which calls `GzDecoder::read_to_end` with no size cap, exhausting server memory/CPU.

pub(crate) fn decompress_program(
    base64_compressed_program: &String,
) -> Result<Program, ErrorObjectOwned> {
    base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    let compressed_data =
        base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    // TODO(dan): add time and size limits.
    let mut decoder = GzDecoder::new(compressed_data.as_slice());
    let mut decompressed = Vec::new();
    decoder.read_to_end(&mut decompressed).map_err(internal_server_error)?;
    serde_json::from_reader(decompressed.as_slice()).map_err(internal_server_error)
}
