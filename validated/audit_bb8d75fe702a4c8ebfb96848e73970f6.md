## Analysis

This is a valid native analog. The external report's bug class ("no/ineffective slippage protection allows MEV sandwich attacks on swaps") reproduces almost verbatim in Push Chain's gas-abstraction and gas-refund auto-swap paths.

### Title
On-chain spot-price slippage bound computed and consumed atomically allows MEV sandwich attacks on gas-abstraction and gas-refund swaps - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
`ExecuteInboundGas`, `gasAndPayloadDepositAutoSwap`, and `applyGasRefund` all compute a `minPCOut` slippage floor by calling `GetSwapQuote` (a live `QuoterV2.quoteExactInputSingle` spot-price read) and then immediately execute the real swap (`CallPRC20DepositAutoSwap` / `CallUniversalCoreRefundUnusedGas`) against that same manipulable on-chain pool, all within the same finalize transaction.

### Finding Description
Three call sites derive `minPCOut` the same way: [1](#0-0) [2](#0-1) [3](#0-2) 

In each case, `GetSwapQuote` calls `QuoterV2.quoteExactInputSingle` with `commit=false` to read the current spot price from the on-chain pool, then applies a fixed 5% haircut (`minPCOut = quote * 95 / 100`): [4](#0-3) 

This "slippage protection" is exactly the anti-pattern the external report flags as `dacian.me/defi-slippage-attacks#heading-on-chain-slippage-calculation-can-be-manipulated`: the bound is derived from the same manipulable spot price it is meant to protect against, and the quote-then-swap sequence executes back-to-back with no intervening validation against an independent/off-chain/TWAP reference price. `GetDefaultFeeTierForToken`/`GetSwapQuote` are documented as plain, unprotected `CallEVM` reads with no calm-period or TWAP guard: [5](#0-4) 

`ExecuteInboundGas` is invoked synchronously from `VoteInbound` once the inbound ballot is finalized by honest validators — the trigger is an ordinary `MsgVoteInbound` transaction, and the swap executes in the very same transaction as ballot finalization: [6](#0-5) 

Similarly, `applyGasRefund` runs from `FinalizeOutbound`, triggered by an ordinary `MsgVoteOutbound`-driven finalization. Because the Uniswap V3 pool behind `UniversalCore`'s quoter is a public AMM that any unprivileged user can trade against on Push Chain, an attacker who observes a pending vote-finalize transaction in the mempool (which is a public, non-privileged, honest-validator-submitted transaction with predictable effect) can sandwich it: push the PRC20/WPC pool price down immediately before the finalize tx lands, let the quote+swap execute against the depressed price (still "honoring" the self-referential 5% bound), then reverse the price afterward for profit. No independent max-slippage parameter, oracle, or calm-period check exists to prevent this.

### Impact Explanation
Every gas-abstraction deposit swap (`CallPRC20DepositAutoSwap`) and every excess-gas refund swap (`CallUniversalCoreRefundUnusedGas`, `withSwap=true`) converts user/protocol-held PRC20 gas tokens to native PC at a price an unprivileged attacker can depress by up to the full 5% tolerance on every single execution, extracting value from users' bridged funds and gas refunds. This is a corruption of native asset accounting / gas fee-refund accounting reachable purely from ordinary honest-validator-driven finalization of ordinary user deposits — no privileged actor is required, satisfying the in-scope "corruption of ... gas fee accounting, refund accounting ... reachable from ordinary user deposits" criterion.

### Likelihood Explanation
High. Any account can submit swap transactions against the same UniswapV3 pool used by `UniversalCore`, sandwich-attacking is a well-known, cheap, and automatable MEV strategy, and every inbound-gas and outbound-refund finalization transaction on Push Chain is a visible, predictable target in the mempool. The fixed 5% band is generous enough that repeated small-pool manipulation is likely profitable, especially given Push Chain's low-gas L1/L2-style environment (as the original report specifically calls out).

### Recommendation
Do not derive the slippage floor from a spot price fetched in the same transaction as the swap. Use a TWAP-based or otherwise manipulation-resistant price oracle for computing `minPCOut`, add a calm-period/liquidity-manipulation guard before allowing auto-swaps, and/or make the tolerance configurable/tightened based on pool depth rather than a flat 5%.

### Proof of Concept
1. Attacker monitors the Push Chain mempool for a `MsgVoteInbound` (or `MsgVoteOutbound`) transaction from the last required validator that will finalize a ballot and trigger `ExecuteInboundGas` / `applyGasRefund`.
2. Immediately before that transaction, attacker submits their own swap on the `UniversalCore` UniswapV3 pool (PRC20 gas token ↔ WPC) to depress the WPC-out price.
3. The finalize transaction executes: `GetSwapQuote` reads the now-depressed spot price, computes `minPCOut = quote*95/100` off that depressed price, and `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` executes successfully against it (the check passes trivially because it was computed from the same manipulated state).
4. Attacker reverses their position in a follow-up transaction in the same or next block, capturing the price difference at the expense of the user's PC output / gas refund.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```
