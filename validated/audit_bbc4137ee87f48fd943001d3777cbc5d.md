## Analysis

I traced the ancient-storage repacking path and found that the attacker's proposed pattern does trigger a real disproportionate-cost condition, rooted in how `is_candidate_for_shrink` interacts with the "already ideal size" skip in the ancient-packing selector.

**Root cause chain:**

1. `AccountsDb::is_candidate_for_shrink` under the default `AccountShrinkThreshold::TotalSpace` mode is *not* ratio-based — it simply checks `alive_bytes < total_bytes`, i.e. **any single dead byte** makes a storage "a candidate for shrink": [1](#0-0) 

2. In `calc_ancient_slot_info` → `AncientSlotInfos::add`, this `is_candidate_for_shrink` flag directly sets `should_shrink = true` for the whole storage: [2](#0-1) 

3. Critically, when `should_shrink` is `true`, the storage **bypasses** the "already ideal size, skip it" filter that would otherwise exclude a fully-packed, near-ideal-sized storage from being reprocessed: [3](#0-2) 

4. Although `combine_ancient_slots_packed` sets `percent_of_alive_shrunk_data: 0` specifically to defer "just shrink" work to `shrink_candidate_slots` (comment: "Don't re-pack anything just to shrink"): [4](#0-3) 
`clear_should_shrink_after_cutoff` only flips `info.should_shrink` back to `false` for entries already pushed into `all_infos`/`shrink_indexes` — it does **not** remove them from `all_infos`: [5](#0-4) 

5. Consequently, that storage still flows into `get_unique_accounts_from_storage_for_combining_ancient_slots` → `calc_accounts_to_combine` → `PackedAncientStorage::pack` → `write_packed_storages`, meaning **all of its still-alive, untouched accounts get read, re-hashed via `store_accounts_for_squash`, and rewritten** into new packed storage(s) on this pass: [6](#0-5) [7](#0-6) 

**Attack mechanics:** An attacker who already has N accounts packed into one ancient storage can, with a single trivial low-lamport rewrite of just one of those accounts in a new (non-ancient) slot, cause that account's ancient copy to become dead after `clean_accounts` runs. This flips `alive_bytes < total_bytes` for the entire shared packed storage, forcing it back into `all_infos` on every subsequent `shrink_ancient_slots` call (called periodically per epoch by the background service), and thus forcing the other N-1 unrelated accounts to be re-copied/re-hashed every cycle — even though the attacker paid fees for only one small write.

**Mitigating factors I found (relevant to severity, not to validity):**
- `shrink_candidate_slots` (the non-ancient path) uses `select_candidates_by_total_usage`, which sorts candidates by alive-ratio and stops once the aggregate ratio target is met — a nearly-full storage (1 dead byte out of many) is deprioritized there. But this protection does **not** apply to the ancient-packing path traced above, since `calc_ancient_slot_info`/`AncientSlotInfos::add` uses the boolean `is_candidate_for_shrink`, not an aggregate ratio computation, to decide inclusion in `all_infos`.
- Repacking itself removes the dead byte each time it runs, so the specific dead-byte trigger doesn't persist — but the attacker can simply repeat the single trivial write each cycle to keep re-triggering it.

### Title
Any single dead byte in a packed ancient storage bypasses the "already ideal size" skip and forces full re-pack of unrelated accounts on every `shrink_ancient_slots` pass - (File: accounts-db/src/ancient_append_vecs.rs)

### Summary
`AncientSlotInfos::add` uses the boolean `is_candidate_for_shrink` (which is true for *any* nonzero dead-byte count under the default `TotalSpace` shrink mode) to decide whether a packed ancient storage bypasses the "already ideal size, skip" optimization in `ancient_append_vecs.rs`. This lets an attacker who already has N accounts packed into a shared ancient storage force full re-read/re-hash/re-write of all N-1 untouched accounts every epoch by repeatedly making one trivial, cheap rewrite to a single account in that storage.

### Finding Description
`combine_ancient_slots_packed_internal` (`ancient_append_vecs.rs:417`) is invoked every epoch by `shrink_ancient_slots` (`accounts_db.rs:3086`) over all ancient slots. It calls `collect_sort_filter_ancient_slots` → `calc_ancient_slot_info`, which for each storage calls `is_candidate_for_shrink` (`accounts_db.rs:5047`) — under the default `TotalSpace` threshold this is simply `alive_bytes < total_bytes`, with no ratio floor. If true, `AncientSlotInfos::add` (`ancient_append_vecs.rs:94`) sets `should_shrink = true` and unconditionally pushes the storage into `all_infos`, skipping the `already_ideal_size` early-return that normally excludes storages that are already efficiently packed (`ancient_append_vecs.rs:128-134`). Although `clear_should_shrink_after_cutoff` (`ancient_append_vecs.rs:186`) later resets `should_shrink` to `false` for these entries when `percent_of_alive_shrunk_data == 0` (as configured in `combine_ancient_slots_packed`, `ancient_append_vecs.rs:362`) specifically to defer pure-shrink work to `shrink_candidate_slots`, it never removes the entry from `all_infos`. The storage therefore still participates in `get_unique_accounts_from_storage_for_combining_ancient_slots` and `calc_accounts_to_combine`, causing all its still-alive accounts to be packed/rewritten via `write_packed_storages`/`write_one_packed_storage`. An attacker only needs to make one of N accounts in an already-packed ancient storage dead (via a trivial, cheap rewrite elsewhere) to force the entire storage back through this path, and can repeat the trick indefinitely each epoch for a new tiny fee, each time causing O(N) work on accounts they didn't touch that cycle.

### Impact Explanation
This is a disproportionate CPU/I-O cost issue: fees paid scale with one small transaction, but validator work (reading, hashing, and rewriting) scales with the size of the shared packed storage, which the attacker fully controls by having chosen to pack many accounts together earlier. This matches the "disproportionate storage and CPU cost" bounty category rather than a correctness/consensus bug — no balance change, hash divergence, or node panic was found; the accounts remain correct after each repack.

### Likelihood Explanation
Preconditions are fully within unprivileged attacker capability: create N accounts, let them age into one packed ancient storage (already achievable today via normal account lifecycle), then perform one more low-lamport write per epoch to one of the packed pubkeys. This requires no special access and is repeatable every epoch indefinitely, though it is partially bounded by `max_ancient_slots`/`max_resulting_storages` tuning caps and the general cadence of `shrink_ancient_slots` invocation, and would compete with other legitimate ancient-shrink work for scheduling within a pass.

### Recommendation
Make the ancient-slot-info collection's inclusion criterion consistent with the "already ideal size" exclusion's intent: when `percent_of_alive_shrunk_data == 0` (i.e., shrink-driven repacking is deferred), also skip pushing the storage into `all_infos` if it is already near-ideal size, rather than only clearing the `should_shrink` flag after the fact. Alternatively, gate inclusion in `all_infos` on an alive-ratio threshold (matching `IndividualStore` semantics) rather than the boolean "any dead byte" check for storages above the ideal-size cutoff.

### Proof of Concept
Rust integration test plan (add to `accounts-db/src/ancient_append_vecs.rs` tests):
1. Create N accounts, store them together, root+flush, and call `combine_ancient_slots_packed_for_tests` to pack them into one ancient storage at slot S1 — record the storage's `id()`, `written_bytes()`, and account count.
2. Overwrite exactly 1 of the N pubkeys with a low-lamport account in a new later slot S2; root+flush+`clean_accounts_for_tests()` so the copy in S1 becomes dead (`alive_bytes < total_bytes`).
3. Call `db.shrink_ancient_slots(&epoch_schedule)` (or `combine_ancient_slots_packed_for_tests` with S1 included) and record: whether S1's storage `id()` changed (indicating a rewrite happened) and `shrink_ancient_stats`/`ShrinkStats.bytes_written` delta.
4. Assert that `bytes_written` for this pass is proportional to the full N-1 remaining accounts' size, not just the size of the 1 changed account — i.e. `bytes_written ≈ sum(alive_bytes of untouched N-1 accounts)`, confirming the untouched accounts were rehashed/rewritten purely due to one unrelated dead byte.
5. Repeat steps 2-4 in a loop (simulating repeated epochs with one trivial rewrite each time) and assert the same O(N) `bytes_written` cost recurs every cycle, demonstrating the disproportionate repeated cost.

    /// clear 'should_shrink' for storages after a cutoff to limit how many storages we shrink
    fn clear_should_shrink_after_cutoff(&mut self, tuning: &PackedAncientStorageTuning) {
        let mut bytes_to_shrink_due_to_ratio = Saturating(0);
        // shrink enough slots to write 'percent_of_alive_shrunk_data'% of the total alive data
        // from slots that exceeded the shrink threshold.
        // The goal is to limit overall i/o in this pass while making progress.
        // Simultaneously, we cannot allow the overall budget to be dominated by ancient storages that need to be shrunk.
        // So, we have to limit how much of the total resulting budget can be allocated to re-packing/shrinking ancient storages.
        let threshold_bytes =
            (self.total_alive_bytes_shrink.0 * tuning.percent_of_alive_shrunk_data / 100).min(
                u64::from(tuning.max_resulting_storages)
                    * u64::from(tuning.ideal_storage_size)
                    * tuning.percent_of_alive_shrunk_data
                    / 100,
            );
        // At this point self.shrink_indexes have been sorted by the
        // largest amount of dead bytes first in the corresponding
        // storages.
        self.best_slots_to_shrink = VecDeque::with_capacity(self.shrink_indexes.len());
        for info_index in &self.shrink_indexes {
            let info = &mut self.all_infos[*info_index];
            self.best_slots_to_shrink
                .push_back((info.slot, info.written_bytes));
            if bytes_to_shrink_due_to_ratio.0 >= threshold_bytes {
                // we exceeded the amount to shrink due to alive ratio, so don't shrink this one just due to 'should_shrink'
                // It MAY be shrunk based on total capacity still.
                // Mark it as false for 'should_shrink' so it gets evaluated solely based on # of files.
                info.should_shrink = false;
            } else {
                bytes_to_shrink_due_to_ratio += info.alive_bytes;
            }
        }
    }

    fn combine_ancient_slots_packed_internal(
        &self,
        sorted_slots: Vec<Slot>,
        mut tuning: PackedAncientStorageTuning,
        metrics: &mut SquashStatsSub,
    ) {
        self.shrink_ancient_stats
            .slot
            .store(*sorted_slots.first().unwrap_or(&0), Ordering::Relaxed);
        self.shrink_ancient_stats
            .slots_considered
            .fetch_add(sorted_slots.len() as u64, Ordering::Relaxed);
        let mut ancient_slot_infos =
            self.collect_sort_filter_ancient_slots(sorted_slots, &mut tuning);
        self.shrink_ancient_stats
            .ideal_storage_size
            .store(tuning.ideal_storage_size.into(), Ordering::Relaxed);

        std::mem::swap(
            &mut *self.best_ancient_slots_to_shrink.write().unwrap(),
            &mut ancient_slot_infos.best_slots_to_shrink,
        );

        if ancient_slot_infos.all_infos.is_empty() {
            return; // nothing to do
        }
        let mut accounts_per_storage = self
            .get_unique_accounts_from_storage_for_combining_ancient_slots(
                &ancient_slot_infos.all_infos[..],
            );

        let mut accounts_to_combine = self.calc_accounts_to_combine(
            &mut accounts_per_storage,
            &tuning,
            IncludeManyRefSlots::Skip,
        );
        metrics.unpackable_slots_count += accounts_to_combine.unpackable_slots_count;

        let mut many_refs_newest = accounts_to_combine
            .accounts_to_combine
            .iter_mut()
            .filter_map(|alive| {
                let newest_alive =
                    std::mem::take(&mut alive.alive_accounts.many_refs_this_is_newest_alive);
                (!newest_alive.accounts.is_empty()).then_some(newest_alive)
            })
            .collect::<Vec<_>>();

        // Sort highest slot to lowest slot. This way, we will put the multi ref accounts with the highest slots in the highest
        // packed slot.
        many_refs_newest.sort_unstable_by_key(|b| cmp::Reverse(b.slot));
        metrics.newest_alive_packed_count += many_refs_newest.len();

        if !Self::many_ref_accounts_can_be_moved(
            &many_refs_newest,
            &accounts_to_combine.target_slots_sorted,
            &tuning,
        ) {
            datapoint_info!("shrink_ancient_stats", ("high_slot", 1, i64));
            log::info!(
                "unable to ancient pack: highest available slot: {:?}, lowest required slot: {:?}",
                accounts_to_combine.target_slots_sorted.last(),
                many_refs_newest.last().map(|accounts| accounts.slot)
            );
            return;
        }

        // for the accounts which are one ref and can be put anywhere, we want to put the accounts from the LARGEST storages at the end.
        // This causes us to keep the accounts we're re-packing from already existing ancient storages together with other normal one ref accounts.
        // The alternative could cause us to mix newly ancient slots produced by flush (containing accounts touched more recently) with previously
        // packed ancient storages which over time contained enough dead accounts that the storage needed to be shrunk by being re-packed.
        // The end result of this sort should cause older, colder accounts (previously packed into large storages and then re-packed/shrunk) to
        // be re-packed together with other older/colder accounts.
        accounts_to_combine
            .accounts_to_combine
            .sort_unstable_by_key(|a| a.written_bytes);

        // pack the accounts with 1 ref or refs > 1 but the slot we're packing is the highest alive slot for the pubkey.
        // Note the `chain` below combining the 2 types of refs.
        let pack = PackedAncientStorage::pack(
            many_refs_newest.iter().chain(
                accounts_to_combine
                    .accounts_to_combine
                    .iter()
                    .map(|shrink_collect| &shrink_collect.alive_accounts.one_ref),
            ),
            tuning.ideal_storage_size,
        );

        if pack.len() > accounts_to_combine.target_slots_sorted.len() {
            // Not enough slots to contain the accounts we are trying to pack.
            return;
        }

        let write_ancient_accounts = self.write_packed_storages(&accounts_to_combine, pack);

        self.finish_combine_ancient_slots_packed_internal(
            accounts_to_combine,
            write_ancient_accounts,
            metrics,
        );
    }

        &'a self,

        // ok if we have more slots, but NOT ok if we have fewer slots than we have contents
        assert!(accounts_to_combine.target_slots_sorted.len() >= packed_contents.len());

        let packer = accounts_to_combine
            .target_slots_sorted
            .iter()
            .rev()
            .zip(packed_contents)

            .ancient_append_vecs_shrunk
            .fetch_add(
