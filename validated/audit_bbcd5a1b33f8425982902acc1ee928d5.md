### Title
Zero-Weight Signer Set From PoX-4 `make_signer_set` Collapses the Block-Approval Threshold to Zero, Letting Unsigned Nakamoto Blocks Pass Verification - (File: `stackslib/src/chainstate/stacks/boot/mod.rs`)

### Summary
`StacksChainState::make_signer_set` (the PoX-4 reward-set builder) can return `Some(vec![])` — a *present but empty* signer list — whenever every aggregated signing key's `stacked_amt / threshold` floors to zero. Unlike the PoX-5/Waterfall path, which explicitly rejects an empty signer set (`if signer_set.is_empty() { return Err(...) }` in `pox_5_compute_and_update_signers`), the PoX-4 path (`pox_4_compute_and_update_signers`) has no such guard. An empty-but-`Some` signer list flows straight into `RewardSet::V0.signers`, and `NakamotoBlockHeader::verify_signer_signatures` treats `Some(&[])` exactly like a healthy signer set: `total_signing_weight()` returns `Ok(0)`, `compute_voting_weight_threshold(0)` returns `0`, and the acceptance check `total_weight_signed < threshold` becomes `0 < 0`, which is `false`. A Nakamoto block with **zero** signer signatures therefore satisfies verification.

### Finding Description
`StacksChainState::make_signer_set` filters entries whose per-signer weight (`stacked_amt / threshold`) is `0`, but always returns `Some(signer_set)` once `entries` is non-empty — even when every entry gets filtered out: [1](#0-0) 

This is used by the PoX-4 reward-set computation path with no post-hoc emptiness check: [2](#0-1) 

Contrast this with the PoX-5/Waterfall path, which explicitly guards against exactly this condition: [3](#0-2) 

`RewardSet::signers()` distinguishes `None` from `Some(&[])`; only the former is treated as "no signers": [4](#0-3) 

`NakamotoBlockHeader::verify_signer_signatures` only errors out on `None`, then computes `total_weight` from the (possibly empty) list and the approval threshold from that: [5](#0-4) [6](#0-5) 

With `total_weight = 0`: `compute_voting_weight_threshold` computes `(0 * 7) / 10 + ceil == 0`. With no signatures in the header, the signature loop never executes, so `total_weight_signed` stays `0`. The final check `total_weight_signed < threshold` is `0 < 0 == false`, so the function returns `Ok(0)` — verification **succeeds** for a completely unsigned block.

This mirrors the reported bug class exactly: a config/derived value (`threshold` computed from `SplitOpts` in the original report; here, `NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD`-derived `threshold` computed from `total_weight`) collapses to zero through legitimate arithmetic (division truncation), and the code that consumes it has no floor/guard against zero, silently turning a "≥70%-of-weight" gate into a "≥0" gate.

### Impact Explanation
This breaks the core Nakamoto equality: *a block must carry signer signatures totaling at least 70% of signer weight to be valid*. If a reward cycle's PoX-4 signer set degenerates to `Some(vec![])` (every stacker's aggregated stake falls below the per-slot threshold — plausible whenever total participation is thin relative to `liquid_ustx/POX_MAXIMAL_SCALING`, which floors the threshold upward independent of actual participation), every node deterministically computes the same empty-but-present signer set (this is not majority/Sybil-dependent — it's a deterministic consensus computation every node performs identically). Any block producer could then publish blocks with **zero** signer signatures that pass `verify_signer_signatures` network-wide, i.e., an invalid (unsigned) block gets accepted as valid by the entire network for that reward cycle — a Critical-class "invalid block accepted network-wide" condition.

### Likelihood Explanation
No privileged access is required: the degenerate condition is a natural consequence of the deterministic threshold-computation formula (`get_reward_threshold_and_participation` / `make_signer_set`) under thin/fragmented stacking participation, and is reachable by anyone who can influence stacking distribution (e.g., splitting stake across many signer keys, each below the computed per-slot threshold) without needing cooperation from a majority of the network. The asymmetry with the PoX-5 path (which was hardened against this exact case) indicates the PoX-4 path was never patched for it.

### Recommendation
- In `pox_4_compute_and_update_signers`, add the same guard used in the PoX-5 path: if the computed signer set is empty, treat the reward cycle as having no valid signer set (error out / fall back safely) instead of proceeding with `Some(vec![])`.
- In `NakamotoBlockHeader::verify_signer_signatures`, explicitly reject (rather than silently accept) reward sets whose `total_signing_weight()` is `0`, regardless of whether `signers()` returned `None` or `Some(&[])`.
- Add a minimum-threshold/non-zero assertion in `compute_voting_weight_threshold` and unit tests covering `total_weight == 0`.

### Proof of Concept
1. Construct a PoX-4 reward cycle where all `RawRewardSetEntry` amounts, once aggregated per signing key in `make_signer_set`, individually floor to `0` under the computed `threshold` (e.g., many small/split stackers, no single signer key crossing the per-slot threshold amount), while the overall reward cycle still proceeds (not `PoxNoRewardCycle`).
2. `make_signer_set` returns `Some(vec![])`; `RewardSet::V0.signers = Some(vec![])`.
3. Any miner builds a Nakamoto block header for that reward cycle with `signer_signature = vec![]` (no signatures).
4. Call `header.verify_signer_signatures(&reward_set, epoch_id)`:
   - `reward_set.signers()` → `Some(&[])` (passes the `None` check).
   - `total_weight = reward_set.total_signing_weight()` → `Ok(0)`.
   - `threshold = compute_voting_weight_threshold(0)` → `0`.
   - Signature loop does not execute; `total_weight_signed = 0`.
   - `total_weight_signed < threshold` → `0 < 0` → `false`.
   - Function returns `Ok(0)` — verification succeeds for a fully unsigned block.

    pub fn make_signer_set(
        threshold: u128,
        entries: &[RawRewardSetEntry],
    ) -> Option<Vec<NakamotoSignerEntry>> {
        let Some(first_entry) = entries.first() else {
            // entries is empty: there's no signer set
            return None;
        };
        // signing keys must be all-or-nothing in the reward set
        let expects_signing_keys = first_entry.signer.is_some();
        for entry in entries.iter() {
            if entry.signer.is_some() != expects_signing_keys {
                panic!("FATAL: stacking-set contains mismatched entries with and without signing keys.");
            }
        }
        if !expects_signing_keys {
            return None;
        }

        let mut signer_set = BTreeMap::new();
        for entry in entries.iter() {
            let signing_key = entry
                .signer
                .expect("BUG: signing keys should all be set in reward-sets with any signing keys");
            if let Some(existing_entry) = signer_set.get_mut(&signing_key) {
                *existing_entry += entry.amount_stacked;
            } else {
                signer_set.insert(signing_key, entry.amount_stacked);
            };
        }

        let mut signer_set: Vec<_> = signer_set
            .into_iter()
            .filter_map(|(signing_key, stacked_amt)| {
                let weight = u32::try_from(stacked_amt / threshold)
                    .expect("CORRUPTION: Stacker claimed > u32::max() reward slots");
                if weight == 0 {
                    return None;
                }
                Some(NakamotoSignerEntry {
                    signing_key,
                    stacked_amt,
                    weight,
                })
            })
            .collect();

        // finally, we must sort the signer set: the signer participation bit vector depends
        //  on a consensus-critical ordering of the signer set.
        signer_set.sort_by_key(|entry| entry.signing_key);

    /// Compute the threshold for the minimum number of signers (by weight) required
    /// to approve a Nakamoto block.
    pub fn compute_voting_weight_threshold(total_weight: u32) -> Result<u32, ChainstateError> {
        let threshold = NAKAMOTO_SIGNER_BLOCK_APPROVAL_THRESHOLD;
        let total_weight = u64::from(total_weight);
        let ceil = if (total_weight * threshold) % 10 == 0 {
            0
        } else {
            1
        };
        u32::try_from((total_weight * threshold) / 10 + ceil).map_err(|_| {
            ChainstateError::InvalidStacksBlock(
                "Overflow when computing nakamoto block approval threshold".to_string(),
            )
        })
    }
