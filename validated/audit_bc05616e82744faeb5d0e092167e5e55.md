The reported CVE describes PHP object injection via unsafe deserialization of user-controlled serialized data (PHP's `unserialize()`), which can instantiate arbitrary classes with "magic methods" (`__wakeup`, `__destruct`, etc.) leading to RCE gadget chains.

The closest analog in protobuf-go is the `Any` type resolution mechanism, where `FindMessageByURL` resolves a type URL string to a `protoreflect.MessageType` and calls `mt.New()` to instantiate it before unmarshaling raw bytes into it [1](#0-0) , with equivalent logic in the ProtoJSON and ProtoText decoders [2](#0-1) [3](#0-2) .

This does not match the bug class for these reasons:
- The resolver (`protoregistry.GlobalTypes` by default) only returns types that are statically compiled into and linked with the running Go binary; there is no dynamic class-loading or "gadget" surface analogous to PHP's global class table with magic methods [4](#0-3) .
- `mt.New()` only constructs a plain protobuf message struct — a data container with no side-effecting constructors/destructors — so no arbitrary code path is triggered merely by resolving a type URL.
- The resulting message is populated purely through `proto.UnmarshalOptions.Unmarshal`, which writes typed fields via the schema-defined setters; this is the documented, intended behavior of `Any` (explicitly discussed as safe in the package doc, which even warns against contacting type URLs as a network side-channel, not object injection) [5](#0-4) .
- No attacker-controlled descriptor or custom resolver is in scope per the rules; with the default `GlobalTypes` resolver, the "type universe" is fixed by the binary's own linked packages, not attacker input.

There is no reachable path in protobuf-go where untrusted input causes instantiation of an unintended/dangerous Go type or triggers unsafe side effects analogous to PHP object injection, so this analog is rejected.

```go
func UnmarshalNew(src *Any, opts proto.UnmarshalOptions) (dst proto.Message, err error) {
	if src.GetTypeUrl() == "" {
		return nil, protoimpl.X.NewError("invalid empty type URL")
	}
	if opts.Resolver == nil {
		opts.Resolver = protoregistry.GlobalTypes
	}
	r, ok := opts.Resolver.(protoregistry.MessageTypeResolver)
	if !ok {
		return nil, protoregistry.NotFound
	}
	mt, err := r.FindMessageByURL(src.GetTypeUrl())
	if err != nil {
		if err == protoregistry.NotFound {
			return nil, err
		}
		return nil, protoimpl.X.NewError("could not resolve %q: %v", src.GetTypeUrl(), err)
	}
	dst = mt.New().Interface()
	return dst, opts.Unmarshal(src.GetValue(), dst)
```
