### Title
Sandwichable auto-swap slippage in `ExecuteInboundGas` allows MEV extraction from gas-abstraction deposits — (File: `x/uexecutor/keeper/execute_inbound_gas.go`)

### Summary
The external report's bug class is: an attacker manipulates a bonding-curve/AMM price immediately around a protocol-triggered value-moving operation (buy before, act, sell after) to extract value that should accrue to the protocol/other users. Push Chain's gas-abstraction inbound flow has a structurally similar pattern: `ExecuteInboundGas` reads a Uniswap V3 `QuoterV2` price quote and then executes a real swap with only a fixed 5% slippage tolerance, with both steps happening deterministically inside ordinary EVM block processing — a window in which an unprivileged actor can move the pool price via ordinary swap transactions in the same block, extracting value from the user's cross-chain gas deposit.

### Finding Description
When a `GAS` type inbound is finalized (ballot passes in `x/uvalidator`, dispatched via `ExecuteInbound` → `ExecuteInboundGas`), the module:
1. Fetches a swap quote via `GetSwapQuote` (`CallEVM` with `commit=false`) from the `UniversalCore` `QuoterV2`, using the PRC20 token, WPC, the token's `defaultFeeTier`, and the deposited `amount`. [1](#0-0) 
2. Computes `minPCOut = quote * 95 / 100` — i.e., a fixed 5% slippage tolerance — and immediately performs the real swap via `CallPRC20DepositAutoSwap` (`DerivedEVMCall`, `commit=true`). [2](#0-1) 

Both the quote and the swap execute inside the same deterministic dispatch path, triggered by ballot finalization in `x/uvalidator`/`BallotHooks` and processed as normal EVM state transitions within block execution. Because Push Chain's node is a Cosmos-SDK/CometBFT chain with an ordinary public mempool for user transactions (and swaps against the same `UniversalCore`/WPC pool are reachable by any unprivileged transaction, e.g. `depositPRC20WithAutoSwap` or direct pool swaps), a user monitoring pending inbound ballots (which are public on-chain state — visible in `PendingInbounds`) can predict that a `GAS` inbound will finalize and trigger this auto-swap. The attacker can then, within the same block or the block immediately preceding finalization:
- push the PRC20/WPC pool price down before the module's quote+swap executes (front-run), and
- restore it afterward (back-run),

capturing the difference within the 5% slippage band that the protocol accepts on the user's behalf. This directly mirrors the reported "buy portalEnergy before convert, sell after" pattern: manipulate the price around a protocol-controlled swap that has a wide tolerance band, extracting value that should have gone to the depositing user (i.e., the user receives less WPC / native gas token than fair value, while the attacker profits from arbitrage against the same pool).

Unlike the `Portal` case, `Team Response` acknowledged this is an accepted trade-off with a purpose-built `LP_PROTECTION_HURDLE`; here there is no such counterbalancing design — the 5% slippage bound is the only protection and it is applied to a swap whose timing (post-ballot-finalization) is fully predictable and whose counterparty pool is presumably open to arbitrage by any account.

### Impact Explanation
This corrupts PRC20/native-gas accounting for the recipient: the deposited PRC20 is converted to WPC at a manipulated price rather than a fair one, meaning the depositing user's derived gas balance is reduced by up to ~5% of the deposit value per inbound, extracted by an unprivileged attacker via ordinary swap transactions. This falls under "corruption of PRC20 or native asset accounting" and "unauthorized... state transitions in universal execution flows" from the allowed-impact list, since the swap executes with a manipulated market price rather than the honest fair-value price, even though no validator or node misbehavior is involved.

### Likelihood Explanation
Likelihood depends on factors not fully verifiable from the indexed code: (1) whether the `UniversalCore`/WPC Uniswap V3 pool has sufficiently shallow liquidity for a 5% price move to be economically worthwhile net of swap fees and gas, and (2) whether `PendingInbounds`/ballot state is realistically observable/predictable far enough in advance for an attacker to time front-run and back-run trades around block finalization. The 5% tolerance is a hard-coded constant [3](#0-2) , so exploitability scales with deposit size and inversely with pool depth — likely medium in the general case, similar in severity class to the original M-02 finding.

### Recommendation
- Reduce reliance on a single-block quote-then-swap with fixed tolerance; consider using a time-weighted average price (TWAP) from the pool, or a tighter/dynamic slippage bound tied to trade size relative to pool liquidity.
- Consider decoupling the swap timing from ballot-finalization predictability, or batching/aggregating swaps to reduce the value available to sandwich per inbound.
- Evaluate whether `defaultFeeTier`/pool liquidity is deep enough that a 5% move is not cheaply achievable by an unprivileged actor; if not, tighten the slippage constant.

### Proof of Concept
No PoC was executed against this repository (no local devnet/pool state available in this environment). The trace above is based on static analysis of `x/uexecutor/keeper/execute_inbound_gas.go` and `x/uexecutor/keeper/evm.go`, showing the quote-then-swap sequence and the fixed 5% tolerance; a full PoC would require deploying the `UniversalCore`/QuoterV2 pool with realistic liquidity and demonstrating a same-block front-run/back-run swap sequence around a finalized `GAS` inbound, analogous to the original report's `test_poc`.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
