### Title
`replace_class` V1→V0 protection is enforced only in the Cairo1 syscall path and can be bypassed via a `library_call` delegate into a deprecated (Cairo0) class — ([File: crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs])

### Summary
The check that forbids replacing a Cairo1 contract's class with a deprecated (Cairo0/"V0") class exists only in the "new" (Cairo1‑native) syscall implementation of `replace_class`, not in the deprecated‑syscall implementation that runs when a Cairo0 class executes. Because `library_call` is a `CallType::Delegate` call that preserves the caller's `storage_address`, a Cairo1 contract can delegate‑call into an attacker‑declared Cairo0 class and have that class invoke the *deprecated* `replace_class` syscall against the caller's own storage address — completely skipping the version check that protects it.

### Finding Description
Two independent implementations of the `replace_class` syscall exist:

- The Cairo1/"new" implementation, which explicitly checks that the target class is Cairo1 before allowing the replacement: [1](#0-0) 

- The deprecated (Cairo0) implementation, which only verifies the class is declared, with **no** version restriction at all: [2](#0-1) 

Which implementation runs is determined by the class of the code that is *currently executing*, not by who the caller is. `library_call` uses `CallType::Delegate`, which explicitly preserves the original `storage_address` (i.e. the calling contract's own address) while executing another class's code: [3](#0-2) [4](#0-3) 

Consequently, if a Cairo1 account/contract performs `library_call_syscall(class_hash=<attacker Cairo0 class>, ...)`, the delegate-called Cairo0 code executes with `storage_address` equal to the *caller's own address*, and dispatch of any syscalls the Cairo0 code makes goes through the deprecated syscall hint processor. If that Cairo0 class invokes `replace_class`, it reaches `deprecated_syscalls::hint_processor::replace_class`, which has no `is_cairo1` check, and directly calls `state.set_class_hash_at(syscall_handler.storage_address, request.class_hash)` — replacing the *Cairo1 caller's own class hash* with an arbitrary declared class, including another Cairo0/deprecated class. This is exactly the class transition (`ForbiddenClassReplacement`) that the new syscall path is designed to prevent: [1](#0-0) 

This mirrors the ZetaChain bug class: an invariant ("no Cairo1 contract can silently become a deprecated V0 class") is enforced in only one of two reachable code paths that both ultimately mutate the same protected state (the contract's `class_hash`), and an attacker can choose the unprotected path.

### Impact Explanation
The `is_cairo1` restriction on `replace_class` exists because many parts of the system — the account backward-compatibility/tip logic (`is_v1_bound_account_cairo0`, `check_tip_for_v1_bound_accounts` in the Starknet OS), fee/tip accounting, and syscall interpretation as a whole — assume that once a contract is known/declared as Cairo1, it will not silently regress to a deprecated class. Bypassing this invariant lets an attacker's own account (or any Cairo1 contract it controls) revert itself to a Cairo0 class hash at will, purely through a `library_call` into a helper class it declares. Depending on how downstream logic (fee bound-account detection, wallet/tooling assumptions, or subsequent transactions relying on the class-hash type) uses this invariant, this can enable unauthorized account behavior changes and inconsistent state that differs from what protocol invariants assume, undermining the guarantee the check was explicitly added to provide.

### Likelihood Explanation
This is reachable by any unprivileged account: it only requires (1) declaring or reusing an already-declared Cairo0 class whose code calls `replace_class`, and (2) issuing an ordinary `invoke` transaction from a Cairo1 account that performs `library_call_syscall` into that class. No special privileges, timing, or race conditions are required — it is a straightforward, deterministically reachable code path from a single transaction.

### Recommendation
Enforce the "target must be Cairo1 when the underlying (delegate-chain) contract is currently Cairo1" check regardless of which syscall interface (deprecated or native) executes `replace_class`. Concretely, move/duplicate the `is_cairo1` check into `deprecated_syscalls::hint_processor::replace_class` (or centralize `replace_class` logic so both interfaces call the same guarded function in `syscall_base.rs`), and/or check the *current* class hash at `syscall_handler.storage_address` (not just the requested target) before permitting deprecated-syscall replacement, so that the delegate/library_call trick cannot be used to strip the protection.

### Proof of Concept
Not fully executable from static review alone (would require running the blockifier test harness), but the exploit path is fully traceable in code:
1. Deploy/declare account `A` as a Cairo1 contract.
2. Declare a helper Cairo0 class `H` whose entry point simply calls the `replace_class` syscall with an attacker-chosen `class_hash` (e.g., pointing back to another Cairo0/legacy class).
3. From `A`, invoke `library_call_syscall(class_hash=H, entry_point_selector=<H's replace fn>, calldata=[target_class_hash])`.
4. Execution dispatches to `H`'s Cairo0 bytecode using `CallType::Delegate`, preserving `storage_address = A`; any syscall from `H` goes to `deprecated_syscalls::hint_processor`.
5. `replace_class` runs via `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs:795-807`, calling `state.set_class_hash_at(A, target_class_hash)` with no `is_cairo1` check — successfully setting `A`'s class hash to a deprecated class, whereas the same operation issued directly by `A` via the native `replace_class_syscall` (`crates/blockifier/src/execution/syscalls/syscall_base.rs:369-378`) would be rejected with `ForbiddenClassReplacement`.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }

    fn library_call(
        request: LibraryCallRequest,
        vm: &mut VirtualMachine,
        syscall_handler: &mut Self,

        let entry_point = CallEntryPoint {
            class_hash: Some(request.class_hash),

            entry_point_selector: request.function_selector,
            calldata: request.calldata,
            // The call context remains the same in a library call.
            storage_address: syscall_handler.storage_address(),
            caller_address: syscall_handler.caller_address(),
            call_type: CallType::Delegate,
            // NOTE: this value might be overridden later on.
            initial_gas: *remaining_gas,
        };

        let retdata_segment = execute_inner_call(entry_point, vm, syscall_handler, remaining_gas)
            .map_err(|error| match error {
            SyscallExecutionError::Revert { .. } => error,
            _ => error.as_lib_call_execution_error(
                request.class_hash,
                syscall_handler.storage_address(),
                request.function_selector,
            ),
        })?;

        Ok(LibraryCallResponse { segment: retdata_segment })
    }
