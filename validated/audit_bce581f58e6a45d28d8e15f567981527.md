### Title
Unauthenticated exposure of LOOP plugin pprof/metrics/discovery proxy endpoints - ([File: core/web/router.go])

### Summary
The `loopRoutes` function registers `/discovery`, `/plugins/:name/metrics`, `/plugins/:name/debug/pprof/*profile`, and `/plugins/:name/debug/pprof/symbol` on the shared `api` router group without wrapping them in any `auth.Authenticate` middleware, unlike virtually every other route registered in `NewRouter` (including the functionally similar `/debug/vars` route in `debugRoutes`). This lets any unauthenticated network client reach and control debug/profiling endpoints of internal LOOP plugin processes.

### Finding Description
`NewRouter` mounts `api := engine.Group("/", rateLimiter(...), sessions.Sessions(...))` — this group only applies rate limiting and enables the session store, it does **not** enforce authentication. [1](#0-0) 

`loopRoutes(app, api)` registers its handlers directly on this unauthenticated `api` group:
```go
func loopRoutes(app chainlink.Application, r *gin.RouterGroup) {
	loopRegistry := NewLoopRegistryServer(app)
	r.GET("/discovery", ginHandlerFromHTTP(loopRegistry.discoveryHandler))
	r.GET("/plugins/:name/metrics", loopRegistry.pluginMetricHandler)
	r.GET("/plugins/:name/debug/pprof/*profile", loopRegistry.pluginPPROFHandler)
	r.POST("/plugins/:name/debug/pprof/symbol", loopRegistry.pluginPPROFPOSTSymbolHandler)
}
``` [2](#0-1) 

Contrast this with `debugRoutes`, which serves a similarly sensitive `/debug/vars` endpoint but explicitly requires session authentication:
```go
func debugRoutes(app chainlink.Application, r *gin.RouterGroup) {
	group := r.Group("/debug", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	group.GET("/vars", expvar.Handler())
}
``` [3](#0-2) 

`pluginPPROFHandler` takes the attacker-controlled `:name` and wildcard `*profile` path parameters and forwards the request to the internal LOOP plugin's pprof server: 
```go
pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
urlVals, timeout := pprofURLVals(gc)
...
l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
```
`pprofURLVals` also passes through the `seconds` query parameter unbounded to control profiling duration. [4](#0-3) 

Similarly, `pluginMetricHandler` proxies to the internal plugin's `/metrics` endpoint with no auth check. [5](#0-4) 

Since none of these handlers are wrapped by `auth.Authenticate`, an unprivileged, unauthenticated network attacker who can reach the node's HTTP API can:
- Enumerate registered LOOP plugins via `/discovery`.
- Pull internal plugin Prometheus metrics via `/plugins/:name/metrics`.
- Trigger CPU/heap/goroutine/trace profiling of the internal plugin process via `/plugins/:name/debug/pprof/*` (e.g., `profile?seconds=<large>`), which can consume plugin CPU for the requested duration (DoS) and/or return heap/goroutine dumps that can leak in-memory secrets from the plugin process (e.g., relayer/transmitter key material or credentials held by the LOOP plugin).

### Impact Explanation
This is an authentication-bypass class issue: sensitive internal debug/profiling interfaces of LOOP plugin processes (memory dumps, goroutine stacks, CPU profiling) are exposed to any unauthenticated caller of the node's public API. This maps to Chainlink bounty categories of "unauthorized access to sensitive information" (heap/goroutine dumps can expose secrets held in plugin memory) and "denial of service" (attacker-controlled `seconds` parameter can pin plugin CPU for extended periods, degrading OCR/relayer availability).

### Likelihood Explanation
Exploitability requires only that the node has LOOP plugins registered (a standard, non-privileged configuration for chain-specific relayers/median plugins) and that the node's web server is reachable, which is the default operating condition for a Chainlink node's API. No credentials, session, or admin role are needed — the attacker only sends unauthenticated HTTP GET/POST requests. This is trivially repeatable.

### Recommendation
Wrap `loopRoutes` handlers with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used elsewhere (or `auth.RequiresAdminRole` given the debug-level sensitivity), consistent with how `/debug/vars` is protected in `debugRoutes`. Additionally, bound/validate the `seconds` query parameter server-side to prevent excessive CPU-profiling duration even for authenticated callers.

### Proof of Concept
Integration test plan (extends existing `core/web/router_test.go` / `core/web/loop_registry_internal_test.go` patterns):
1. Start a test `chainlink.Application` with at least one LOOP plugin registered in `app.GetLoopRegistry()`.
2. Build the router via `NewRouter` without setting any session cookie or `Authorization` header.
3. Issue `GET /discovery` and assert `200 OK` with plugin target list returned (no 401).
4. Issue `GET /plugins/<name>/metrics` and assert `200 OK` with proxied metrics body returned (no 401).
5. Issue `GET /plugins/<name>/debug/pprof/profile?seconds=1` and assert `200 OK` with proxied pprof payload (no 401), demonstrating that an unauthenticated caller can force CPU profiling on the plugin process.
6. Compare against `GET /debug/vars` without credentials, which should return `401 Unauthorized`, to demonstrate the inconsistency and confirm the missing auth middleware is the root cause.

func (l *LoopRegistryServer) pluginMetricHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/metrics", l.loopHostName, p.EnvCfg.PrometheusPort)
	req, err := http.NewRequestWithContext(gc.Request.Context(), "GET", pluginURL, nil)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error creating plugin metrics request: %s", err))
		return
	}
	res, err := l.promClient.Do(req)
	if err != nil {
		msg := "plugin metric handler failed to get plugin url " + html.EscapeString(pluginURL)
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}
	defer res.Body.Close()
	b, err := io.ReadAll(res.Body)
	if err != nil {
		msg := fmt.Sprintf("error reading plugin %q metrics", html.EscapeString(pluginName))
		l.logger.Errorw(msg, "err", err)
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "%s: %s", msg, err))
		return
	}

	gc.Data(http.StatusOK, "text/plain", b)
}
```

func pprofURLVals(gc *gin.Context) (urlVals url.Values, timeout time.Duration) {
	urlVals = make(url.Values)
	if db, ok := gc.GetQuery("debug"); ok {
		urlVals.Set("debug", db)
	}
	if gc, ok := gc.GetQuery("gc"); ok {
		urlVals.Set("gc", gc)
	}
	timeout = PPROFOverheadSeconds * time.Second
	if sec, ok := gc.GetQuery("seconds"); ok {
		urlVals.Set("seconds", sec)
		if i, err := strconv.Atoi(sec); err == nil {
			timeout = time.Duration(i+PPROFOverheadSeconds) * time.Second
		}
	}
	return
}

func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
