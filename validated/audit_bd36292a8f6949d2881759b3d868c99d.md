### Title
Unbounded Gzip Decompression in Legacy (Cairo0) Declare Class Handling During RPC Simulation - ([File: crates/apollo_rpc/src/v0_8/api/mod.rs])

### Summary
The RPC layer's helper for converting a user-submitted (broadcasted) Cairo 0 declare class into the internal `starknet_api` representation calls `decompress_program`, which decompresses a gzip stream with `GzDecoder::read_to_end` and **no size or time limit**, unlike the equivalent, properly-bounded decompression path used elsewhere in the same codebase for the same data type.

### Finding Description
`decompress_program` base64-decodes and gzip-decompresses an attacker-controlled `compressed_program` field straight into an unbounded `Vec<u8>`: [1](#0-0) 

The `// TODO(dan): add time and size limits.` comment on this exact function confirms the missing bound is a known gap, not an intentional design choice. It is invoked from `user_deprecated_contract_class_to_sn_api`, which builds a `starknet_api::deprecated_contract_class::ContractClass` from a user-supplied `DeprecatedContractClass` (i.e., a Cairo 0 declare payload embedded in a `BroadcastedTransaction`): [2](#0-1) 

This is the exact analog of the Gitea bug class: an attacker-supplied compressed blob is decompressed via `Read::read_to_end` with no `io::LimitReader`/`take()` bound, so a small (KB-scale) gzip payload with a high compression ratio can expand to gigabytes in memory during a single request.

This contrasts directly with the codebase's own hardened pattern for the *same* Cairo0 program field, used on the actual gateway declare-validation path, which wraps the decompressor in `.take(max_size + 1)` and rejects anything over the configured limit: [3](#0-2) [4](#0-3) 

The RPC-layer conversion function, however, was never updated to use this bounded helper, leaving an unbounded decompression sink reachable by any caller who can submit a Cairo0 declare class body to the node's JSON-RPC write API (e.g. for fee estimation / simulation flows that accept a `BroadcastedTransaction` containing a legacy `DeprecatedContractClass`).

### Impact Explanation
A single crafted request containing a small, highly-compressible `compressed_program` (gzip bomb) can cause the node process handling the RPC request to allocate an arbitrarily large `Vec<u8>` on the heap, exhausting memory and crashing or stalling the node — a denial-of-service reachable from a single unprivileged submitted request, matching the "network unable to confirm new transactions" impact class when this affects a sequencer/RPC node responsible for admitting/serving transactions.

### Likelihood Explanation
High: any client able to reach the node's JSON-RPC write endpoints (no special privilege, funds, or prior state needed) can submit a payload with this field. Gzip achieving >100:1 compression ratios on repetitive input is trivial to construct, mirroring the referenced Gitea PoC almost exactly (base64+gzip decode with `read_to_end` and no cap).

### Recommendation
Route `decompress_program` (and `user_deprecated_contract_class_to_sn_api`) through the existing bounded decompression utility (`starknet_api::compression_utils::decode_and_decompress_with_size_limit`, or equivalent `.take(max_size)` wrapping) with the same `MAX_CAIRO0_PROGRAM_SIZE` bound already enforced on the gateway declare path, so the RPC-layer conversion cannot be used to bypass the size limit enforced elsewhere.

### Proof of Concept
Construct a `BroadcastedTransaction::Declare` (Cairo0/legacy variant) whose `DeprecatedContractClass.compressed_program` is a base64-encoded gzip blob that decompresses to several GB (e.g., repeated bytes compress at >100:1), then submit it to any RPC method that internally calls `user_deprecated_contract_class_to_sn_api` (declare-related simulation/estimation flow in `crates/apollo_rpc/src/v0_8/api/mod.rs`). `decompress_program` will call `GzDecoder::read_to_end` with no cap, expanding the payload fully into memory in a single request, mirroring the Gitea PoC's memory-exhaustion pattern.

    base64_compressed_program: &String,
) -> Result<Program, ErrorObjectOwned> {
    base64::decode(base64_compressed_program).map_err(internal_server_error)?;
    let compressed_data =

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
