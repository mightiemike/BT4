## Title
Unbounded Recursion on Attacker-Controlled `bytecode_segment_lengths` (`NestedIntList`) Enables Stack-Overflow / Assertion-Panic DoS During Class Hashing and OS Re-execution - (File: `crates/starknet_api/src/contract_class/compiled_class_hash.rs`, `crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`, `crates/blockifier/src/execution/contract_class.rs`)

### Summary
CVE-2018-19838 describes a stack-overflow DoS in LibSass caused by unbounded recursive tree operations (`clone`/`cloneChildren`/`copy`) over an attacker-supplied, arbitrarily-nested AST. The sequencer contains an analogous pattern: a `CasmContractClass`'s `bytecode_segment_lengths` field is a recursively-defined `NestedIntList` tree (`Leaf`/`Node(Vec<NestedIntList>)`) that is walked by several plain (non-tail, non-depth-checked) recursive functions used in compiled-class hashing and Starknet OS re-execution.

### Finding Description
`NestedIntList` is a recursive tree structure attached to every compiled (CASM) class via `CasmContractClass.bytecode_segment_lengths` [1](#0-0) . It is walked by unbounded, depth-unlimited recursive functions in multiple hot sequencer paths reachable from a single declared class:

- `bytecode_hash_node`, used to compute the on-chain `compiled_class_hash` that the gateway/blockifier verify against a declare transaction's supplied hash: [2](#0-1) 
- `create_bytecode_segment_structure_inner` and `BytecodeSegmentNode::hash`, used by the Starknet OS during block re-execution to rebuild and hash the bytecode segment structure of every executed class: [3](#0-2) [4](#0-3) 
- `get_visited_segments`, invoked in the blockifier on every entry-point call to compute which bytecode segments were touched: [5](#0-4) 
- `NestedFeltCounts::new_inner`, invoked when converting a declared/loaded `CasmContractClass` into a runnable `CompiledClassV1` (i.e., on every declare and on every subsequent load of that class for execution): [6](#0-5)  called from `TryFrom<VersionedCasm> for CompiledClassV1` [7](#0-6) .

None of `bytecode_hash_node`, `create_bytecode_segment_structure_inner`, or `get_visited_segments` bound the recursion depth of the `NestedIntList`/`NestedFeltCounts` tree. `NestedFeltCounts::new_inner` is the only one of these functions that even attempts to reason about nesting depth, and it does so with a hard `assert!(segmentation_depth <= 1, ...)` [8](#0-7)  — i.e., the code assumes the compiler-generated structure never nests more than one level deep, but this assumption is never validated at the point the class enters the system (declare/compile), and the other three functions have no such assumption or check at all, so a class whose segmentation tree is deeper than one level, or is simply very deep, is neither rejected nor stack-safety-guarded.

Because `bytecode_segment_lengths` originates from the Sierra→CASM compilation step performed by `SierraCompiler::compile` for a user-submitted, attacker-controlled Sierra program [9](#0-8) , a malicious class declarer who crafts a Sierra program that induces the compiler's segmentation heuristic to produce either (a) a deeply nested `NestedIntList` tree, or (b) a tree with segmentation depth greater than 1, can trigger:
- An `assert!` panic in `NestedFeltCounts::new_inner` the moment that class is loaded for execution (every node executing/re-executing that declare or any subsequent invocation of the class), or
- Unbounded recursion in `bytecode_hash_node` / `create_bytecode_segment_structure_inner` deep enough to overflow the call stack, in the compiled-class-hash verification path (gateway/blockifier) and in the Starknet OS re-execution path.

### Impact Explanation
A stack overflow or `assert!` panic in these code paths crashes the process handling it. Since `bytecode_hash_node`/hash verification runs during declare-transaction validation and block execution (blockifier, in-process, not sandboxed the way the standalone Sierra→CASM compiler subprocess is), and `create_bytecode_segment_structure_inner`/hash run inside Starknet OS re-execution used for proving/verifying block correctness, a single malicious declared class can crash sequencer nodes or the OS re-execution/proving pipeline that processes it — causing honest-node divergence or a network unable to confirm/re-execute new blocks, matching the required impact bar.

### Likelihood Explanation
Reachable from a single, ordinary declare transaction from an unprivileged sender — no special privileges, staking, or proposer role required. The only prerequisite is crafting a Sierra program whose compiled bytecode segmentation (computed by the external Sierra→CASM compiler, invoked with `--max-bytecode-size`/CPU/memory limits but no bound on structural nesting depth of `bytecode_segment_lengths`) yields a deep or multi-level-nested `NestedIntList`. This is a data-shape attack (crafting program control-flow/function nesting), analogous in class to the LibSass CVE's crafted-AST attack, though verifying the exact segmentation algorithm's worst-case nesting behavior requires exercising the actual `cairo-lang-starknet-classes` compiler (external dependency, not vendored in this repo).

### Recommendation
- Add an explicit maximum-depth (and/or total-node-count) validation of `bytecode_segment_lengths` immediately after Sierra→CASM compilation, rejecting classes whose segmentation tree exceeds a safe bound, before the class is accepted/declared or stored.
- Convert `bytecode_hash_node`, `create_bytecode_segment_structure_inner`, `BytecodeSegmentNode::hash`, and `get_visited_segments` to explicit-stack (iterative) algorithms, or add depth-limited recursion guards (returning an error instead of panicking/overflowing) consistent with the existing `RecursionDepthGuard` pattern already used elsewhere in the blockifier [10](#0-9) .
- Replace the `assert!(segmentation_depth <= 1, ...)` in `NestedFeltCounts::new_inner` with a proper validated error path enforced at class-ingestion time, since a panic there currently indicates the invariant is not actually guaranteed by input validation.

### Proof of Concept
1. Craft a Sierra program (via `starknet_addDeclareTransaction`) whose control-flow/function structure causes the Sierra→CASM compiler's bytecode-segmentation logic to emit a `bytecode_segment_lengths: NestedIntList` that is either deeply nested (thousands of levels) or has segmentation depth > 1.
2. Submit the declare transaction; when the resulting `CasmContractClass` is converted via `TryFrom<VersionedCasm> for CompiledClassV1`, `NestedFeltCounts::new` → `new_inner` is invoked and panics on `assert!(segmentation_depth <= 1, ...)`, or, for a sufficiently deep tree, `bytecode_hash_node`/`create_bytecode_segment_structure_inner` recurse until the stack overflows.
3. Any sequencer node (during declare validation/execution) or OS re-execution/proving pipeline (during block re-execution) that processes this class crashes.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

impl BytecodeSegmentNode {
    pub(crate) fn hash<H: HashFunction>(&self) -> StarkHash {
        match self {
            BytecodeSegmentNode::Leaf(leaf) => H::hash_array(&leaf.data),
            BytecodeSegmentNode::InnerNode(inner_node) => {
                let flatten_input: Vec<_> = inner_node
                    .segments
                    .iter()
                    .flat_map(|segment| [Felt::from(segment.length), segment.node.hash::<H>()])
                    .collect();
                H::hash_array(&flatten_input) + Felt::ONE
            }
        }
    }

            BytecodeSegmentNode::Leaf(_) => true,
            BytecodeSegmentNode::InnerNode(_) => false,

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }

    fn new_inner(
        bytecode_segment_lengths: &NestedIntList,
        bytecode: &[BigUintAsHex],
        segmentation_depth: usize,
    ) -> (Self, usize) {
        assert!(segmentation_depth <= 1, "Only supported for segmentation depth at most 1.");

        match bytecode_segment_lengths {
            NestedIntList::Leaf(len) => {
                let felt_size_groups = FeltSizeCount::from(&bytecode[..*len]);
                (NestedFeltCounts::Leaf(*len, felt_size_groups), *len)
            }
            NestedIntList::Node(segments_vec) => {
                let mut total_felt_count = 0;
                let mut segments = Vec::with_capacity(segments_vec.len());

                for segment in segments_vec {
                    // Recurse into the segment layout.
                    let (segment, felt_count) = Self::new_inner(
                        segment,
                        &bytecode[total_felt_count..],
                        segmentation_depth + 1,
                    );
                    // Accumulate the count from the segment`s subtree.
                    total_felt_count += felt_count;
                    segments.push(segment);
                }

                (NestedFeltCounts::Node(segments), total_felt_count)
            }
        }

    visited_pcs: &mut Vec<usize>,
    bytecode_offset: &mut usize,
) -> Result<Vec<usize>, TransactionExecutionError> {
    let mut res = Vec::new();

    match segment_lengths {
        NestedFeltCounts::Leaf(length, _) => {
            let segment = *bytecode_offset..*bytecode_offset + length;
            if visited_pcs.last().is_some_and(|pc| segment.contains(pc)) {
                res.push(segment.start);
            }

            while visited_pcs.last().is_some_and(|pc| segment.contains(pc)) {
                visited_pcs.pop();
            }
            *bytecode_offset += length;
        }
        NestedFeltCounts::Node(segments) => {
            for segment in segments {
                let segment_start = *bytecode_offset;
                let next_visited_pc = visited_pcs.last().copied();

                    get_visited_segments(segment, visited_pcs, bytecode_offset)?;

                    && !visited_inner_segments.is_empty()
                {
                    return Err(TransactionExecutionError::InvalidSegmentStructure(
                        next_visited_pc.unwrap(),
                        segment_start,
                    ));
                }

                res.extend(visited_inner_segments);
            }

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
