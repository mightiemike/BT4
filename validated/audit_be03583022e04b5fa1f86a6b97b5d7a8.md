Confirmed: `DelegateAction.get_nep461_hash()` [1](#0-0)  commits to the full struct (`sender_id`, `receiver_id`, `actions`, `nonce`, `max_block_height`, `public_key`), so a third party cannot redirect funds — only the nonce-consumption/front-running vector is reachable, not fund theft.

### Title
Meta-transaction (`SignedDelegateAction`) nonce can be front-run by any unprivileged transaction sender, causing the relayer's transaction to revert - (File: `runtime/runtime/src/actions.rs`)

### Summary
NEAR's meta-transaction feature (NEP-366) lets a user sign a `DelegateAction` off-chain and hand it to a relayer, who wraps it in an outer `SignedTransaction` and submits it. Because the signed payload authorizes anyone to submit it (the relayer is not cryptographically bound to the delegate signature), any unprivileged account that observes the pending outer transaction can extract the embedded `SignedDelegateAction`/`VersionedSignedDelegateAction` bytes and re-submit them itself, ahead of the intended relayer. The action executes with a valid nonce, but the intended relayer's transaction is now guaranteed to fail against a stale nonce.

### Finding Description
`validate_delegate_action_key` in `runtime/runtime/src/actions.rs` validates a `DelegateAction`/`DelegateActionV2` purely against the sender's stored access-key nonce (or gas-key nonce), independent of who signed or submitted the *outer* transaction: [2](#0-1)  The only constraints on who may embed a `SignedDelegateAction` in an outer transaction are that (a) the outer transaction's `receiver_id` equals `delegate_action.sender_id`, and (b) the signature verifies against `get_nep461_hash()` of the exact delegate-action payload; nothing checks that the specific submitter is the relayer the user intended. Any account can construct its own outer `SignedTransaction` wrapping the very same `SignedDelegateAction` bytes it observed in the mempool/gossip, and if it lands first, it consumes the sender's access-key nonce via the same code path shown above: `access_key.nonce = delegate_nonce.nonce(); set_access_key(...)` [3](#0-2) .

Because the nonce is strictly required to be greater than the stored value (`delegate_nonce.nonce() <= current_nonce` fails) [4](#0-3) , once the front-runner's copy is applied, the legitimate relayer's outer transaction — carrying an identical `DelegateAction` with the same nonce — is rejected with `DelegateActionInvalidNonce` when it is later processed: [5](#0-4) , exactly mirroring the pattern in the reported bug where anyone who observes a signed, nonce-bearing payload in the mempool can consume its nonce ahead of the intended submitter, reverting the intended transaction.

This is structurally the same primitive as the reported Rubicon bug: a signed, nonce-scoped authorization (`permitWitnessTransferFrom` witness / `DelegateAction`) is visible pre-confirmation and can be resubmitted by any address, and the nonce check (rather than a submitter-identity check) is the only gate — so whichever copy lands first "wins" the nonce, and the loser reverts.

The project's own architecture docs acknowledge a closely related but distinct sharing hazard (same signer racing multiple relayers) as an accepted MVP limitation [6](#0-5) , but they do not address a third-party, non-relayer front-runner intercepting and resubmitting the observed payload to deliberately grief a specific relayer's pending transaction.

### Impact Explanation
Unlike the Rubicon/`permit2` case, the `DelegateAction`'s signed hash commits to `receiver_id` and `actions`, so a front-runner cannot redirect funds to itself — the delegated action still executes exactly as the user intended [7](#0-6) . The concrete, protocol-level harm is: (1) deterministic denial-of-service against a specific relayer's transaction — its already-signed outer transaction is guaranteed to fail with `DelegateActionInvalidNonce` once front-run, wasting the gas the relayer spent forwarding it, and (2) this can be repeated indefinitely against any relayer operating a meta-transaction service, since nothing about the protocol binds the delegate action to a specific outer submitter. This is a transaction-triggered gas-griefing/DoS against the relayer business model rather than a theft or fund-freezing bug, so it sits at Medium rather than High/Critical severity.

### Likelihood Explanation
Any account with a small NEAR balance can watch the gossip/mempool for outer transactions carrying `Action::Delegate`/`Action::DelegateV2`, extract the embedded signed payload (no private key needed), and resubmit it in its own outer transaction. No special privilege, validator access, or timing beyond ordinary transaction propagation is required, making this readily reachable by any unprivileged transaction submitter or RPC caller.

### Recommendation
Consider binding a `DelegateAction`/`DelegateActionV2` to an authorized submitter (e.g., include the intended relayer's `AccountId` in the signed payload and check it against the outer transaction's signer in `validate_delegate_action_key`), or provide relayers a way to reserve/commit a nonce before broadcasting so that a foreign resubmission of the same payload cannot invalidate their pending transaction.

### Proof of Concept
1. User Alice signs `DelegateAction { sender_id: alice, receiver_id: alice, actions: [...], nonce: N, ... }` and hands the `SignedDelegateAction` to Relayer R off-chain/through R's submission endpoint.
2. R builds outer transaction `Tx_R = SignedTransaction::from_actions(relayer_nonce, R, alice, [Action::Delegate(signed_delegate_action)], ...)` (see helper `meta_tx_from_actions` for the exact shape) [8](#0-7)  and broadcasts it.
3. Attacker M observes `Tx_R` in the mempool, extracts the identical `signed_delegate_action` bytes, and builds `Tx_M = SignedTransaction::from_actions(m_nonce, M, alice, [Action::Delegate(signed_delegate_action)], ...)`.
4. If `Tx_M` is included first, `validate_delegate_action_key` advances `alice`'s access-key nonce to `N` and the inner actions execute as intended by Alice.
5. When `Tx_R` is later processed, `validate_delegate_action_key` sees `delegate_nonce.nonce() (N) <= current_nonce (N)` and rejects it with `DelegateActionInvalidNonce { delegate_nonce: N, ak_nonce: N }`, exactly as exercised in `test_delegate_action_key_incorrect_nonce` [9](#0-8) , causing R's transaction to fail and R's spent gas to be wasted — despite R having done nothing wrong.

    /// different messages before hashing
    ///
    /// For more details, see: [NEP-461](https://github.com/near/NEPs/pull/461)
    pub fn get_nep461_hash(&self) -> CryptoHash {
        let signable = SignableMessage::new(&self, SignableMessageType::DelegateAction);
        let bytes = borsh::to_vec(&signable).expect("Failed to deserialize");
        hash(&bytes)
    }

fn validate_delegate_action_key(
    state_update: &mut TrieUpdate,
    apply_state: &ApplyState,
    delegate_action: VersionedDelegateActionRef<'_>,
    result: &mut ActionResult,
) -> Result<(), RuntimeError> {
    let sender_id = delegate_action.sender_id();
    let public_key = delegate_action.public_key();
    // 'sender_id' account existence must be checked by a caller
    let mut access_key = match get_access_key(state_update, sender_id, public_key)? {
        Some(access_key) => access_key,
        None => {
            result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                InvalidAccessKeyError::AccessKeyNotFound {
                    account_id: sender_id.clone(),
                    public_key: public_key.clone().into(),
                },
            )
            .into());
            return Ok(());
        }
    };

    // A plain nonce advances the single access_key.nonce and forbids gas keys;
    // a gas key nonce advances one of the gas key's nonces selected by
    // nonce_index.
    let delegate_nonce = delegate_action.nonce();
    let (current_nonce, nonce_update) = match delegate_nonce {
        TransactionNonce::Nonce { .. } => {
            if access_key.gas_key_info().is_some() {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresNonGasKey,
                )
                .into());
                return Ok(());
            }
            (access_key.nonce, DelegateNonceUpdate::AccessKey)
        }
        TransactionNonce::GasKeyNonce { nonce_index, .. } => {
            let Some(gas_key_info) = access_key.gas_key_info() else {
                result.result = Err(ActionErrorKind::DelegateActionAccessKeyError(
                    InvalidAccessKeyError::DelegateActionRequiresGasKey,
                )
                .into());
                return Ok(());
            };
            if nonce_index >= gas_key_info.num_nonces {
                result.result = Err(ActionErrorKind::DelegateActionInvalidNonceIndex {
                    nonce_index,
                    num_nonces: gas_key_info.num_nonces,
                }
                .into());
                return Ok(());
            }
            // The index is range-checked above and gas keys initialize every
            // nonce row at creation, so a missing row is inconsistent state.
            let current_nonce =
                get_gas_key_nonce(state_update, sender_id, public_key, nonce_index)?.ok_or_else(
                    || {
                        StorageError::StorageInconsistentState(format!(
                            "gas key nonce row missing for {} {} at in-range index {nonce_index} (num_nonces {})",
                            sender_id, public_key, gas_key_info.num_nonces,
                        ))
                    },
                )?;
            (current_nonce, DelegateNonceUpdate::GasKey { nonce_index })
        }
    };

    if delegate_nonce.nonce() <= current_nonce {
        result.result = Err(ActionErrorKind::DelegateActionInvalidNonce {
            delegate_nonce: delegate_nonce.nonce(),
            ak_nonce: current_nonce,
        }
        .into());
        return Ok(());
    }

    /// Wrap actions in a delegate action, put it in a transaction, sign.
    pub fn meta_tx_from_actions(
        &mut self,
        actions: Vec<Action>,
        sender: AccountId,
        relayer: AccountId,
        receiver_id: AccountId,
    ) -> SignedTransaction {
        let inner_signer = InMemorySigner::test_signer(&sender);
        let relayer_signer = InMemorySigner::test_signer(&relayer);
        let tip = self.clients[0].chain.head().unwrap();
        let user_nonce = tip.height + 1;
        let relayer_nonce = tip.height + 1;
        let delegate_action = DelegateAction {
            sender_id: inner_signer.get_account_id(),
            receiver_id,
            actions: actions
                .into_iter()
                .map(|action| NonDelegateAction::try_from(action).unwrap())
                .collect(),
            nonce: user_nonce,
            max_block_height: tip.height + 100,
            public_key: inner_signer.public_key(),
        };
        let signature = inner_signer.sign(delegate_action.get_nep461_hash().as_bytes());
        let signed_delegate_action = SignedDelegateAction { delegate_action, signature };
        SignedTransaction::from_actions(
            relayer_nonce,
            relayer,
            sender,
            &relayer_signer,
            vec![Action::Delegate(Box::new(signed_delegate_action))],
            tip.last_block_hash,
        )
    }
