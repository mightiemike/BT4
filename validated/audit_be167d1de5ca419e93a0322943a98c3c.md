### Title
Starknet OS `execute_replace_class` omits the "class must be declared" check enforced by blockifier, causing OS/sequencer state divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
`replace_class` in blockifier's syscall handler requires the target `class_hash` to be a declared (and Cairo1) class before mutating `contract_state_changes`; if not declared, the syscall reverts, which for an `__execute__` call reverts the whole transaction (fee still charged, no class-hash change committed). The Starknet OS's own implementation of the same syscall (`execute_replace_class` in both the current and deprecated syscall handlers) never performs this existence check — it unconditionally writes the requested `class_hash` into `contract_state_changes`, with an explicit `TODO` acknowledging the missing validation.

### Finding Description
The `replace_class` syscall is meant to be validated identically wherever it is executed, since both the sequencer (blockifier) and the OS (re-execution/proving) must derive the same state transition from the same block of transactions. Blockifier performs `self.state.get_compiled_class(class_hash)?` before applying the class-hash mutation [1](#0-0) , and its Cairo0 (deprecated syscalls) equivalent does the same [4](#0-3) . Test coverage in blockifier confirms an undeclared class hash produces an execution error ("is not declared") that would revert the transaction [5](#0-4) .

The OS's implementation of `execute_replace_class`, however, applies the state mutation unconditionally, without ever checking whether `request.class_hash` corresponds to a declared class: [6](#0-5) . The comment at line 902 explicitly documents that this check is missing and deferred to a future date. The deprecated Cairo0 OS syscall path has the identical omission [3](#0-2) .

Because the OS is responsible for independently re-executing every transaction in a block to reconstruct and prove the state transition (used to generate the STARK proof submitted to L1), any semantic mismatch between blockifier's syscall handling and the OS's syscall handling produces a genuine execution divergence, not merely a permissive/duplicate check.

### Impact Explanation
An account contract can call `replace_class_syscall` with an arbitrary, never-declared `class_hash` (e.g. inside its own `__execute__` or in a callee invoked by it). In blockifier, this syscall fails because the class is undeclared, which reverts the entire invoke transaction: no class-hash change is committed to the real sequencer state (only the fee/nonce changes survive, per normal revert semantics). When the same block is later re-executed by the Starknet OS to build the state-transition proof, `execute_replace_class` performs no such check and unconditionally records the class-hash change in `contract_state_changes`. This causes the OS to compute:
- A different `failure_flag`/revert status for the transaction than what blockifier actually determined, and
- A different final class hash / state entry for the target contract address than what is actually committed by the sequencer.

This is a direct root-cause for the OS producing a wrong committed state root/block hash relative to what the sequencer actually persisted, i.e., an honest-node/OS divergence that prevents block proof generation from matching the canonical state, or in the worst case allows a maliciously-undeclared class hash to be "baked into" the proven state.

### Likelihood Explanation
Triggering the code path requires nothing privileged: any account contract with access to `replace_class_syscall` (available to every Cairo1 contract) can call it with a random/undeclared class hash as part of an ordinary `INVOKE` transaction. No special sequencer, prover, or network role is needed — a single unprivileged transaction sender can construct this call.

### Recommendation
Add the same "class must be declared" (and Cairo1-type) validation to `execute_replace_class` in both `crates/apollo_starknet_os_program/.../execution/syscall_impls.cairo` and the deprecated `crates/apollo_starknet_os_program/.../execution/deprecated_execute_syscalls.cairo`, mirroring blockifier's `get_compiled_class` check in `crates/blockifier/src/execution/syscalls/syscall_base.rs`, before this is used in production, resolving the outstanding `TODO(Yoni, 1/1/2026)`.

### Proof of Concept
1. Deploy an account/test contract exposing `replace_class_syscall` (e.g. `test_replace_class` in the feature contracts) [7](#0-6) .
2. Send an `INVOKE` transaction whose `__execute__` calls `test_replace_class(class_hash=<undeclared_hash>)`.
3. In blockifier (actual sequencer execution), the call to `replace_class` fails with "is not declared", causing the whole transaction to revert; the contract's class hash in state is unchanged (as in the existing test `undeclared_class_hash` at `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`).
4. When the Starknet OS re-executes the same block/transaction to produce the state-transition proof, `execute_replace_class` (`syscall_impls.cairo:881-920`) performs no declared-class check and unconditionally updates `contract_state_changes` with the undeclared `class_hash`, yielding a non-reverted execution result and a different final state entry for the contract than what blockifier actually committed — producing a state root mismatch between the sequencer's canonical state and the OS-computed state.
