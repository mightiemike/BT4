### Title
Gas fee rounds to zero when `baseFee < 1e18` (sub-1-upc base fee), allowing free `ExecutePayload`/`ExecutePayloadV2` execution - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`CalculateGasCost` divides the `feemarketKeeper.GetBaseFee` `LegacyDec` value by a fixed `1e18` to "unwrap" it into a whole-upc integer, exactly mirroring the reported Boot Finance bug pattern where a scaled ratio is truncated to zero by integer division when the underlying value is smaller than the scale factor. If the dynamic EIP-1559 base fee for the `upc` denom is below `1` (i.e. its raw `LegacyDec.BigInt()` representation is below `1e18`), `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates to `0`, making `effectiveGasPrice = 0` and therefore `gasCost = 0` regardless of `gasUsed`.

### Finding Description
`CalculateGasCost` in [1](#0-0)  computes the fee to charge a UEA/user for executing a `UniversalPayload` via `ExecutePayloadV2`/`ExecutePayload`:

```go
baseFeeBig := baseFee.BigInt()
baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
...
effectiveGasPrice := new(big.Int).Set(baseFeeBig)
gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)
``` [2](#0-1) 

The in-line comment asserts "the base fee is always a whole number of upc -- no fractional upc exists," but this is an assumption about the feemarket module's dynamic base-fee value, not an invariant enforced anywhere in this codebase (the feemarket base fee is a floating EIP-1559-style value that adjusts up/down with block gas usage, and genesis/test configs only set a *starting* value such as `1000000000.000000000000000000` — no lower bound is fixed here). If the effective base fee (as a `LegacyDec`) ever settles to a raw internal value below `1e18` (i.e., below 1 whole `upc`), the integer division truncates to `0`, exactly like the `customPrecisionMultipliers` truncation in the referenced report.

`DeductGasFeesFromReceipt` then treats a zero-or-negative `gasCost` as a no-fee case and skips billing entirely:
```go
if gasCost.Sign() <= 0 {
    return nil
}
``` [3](#0-2) 

This function is invoked from both the direct `MsgExecutePayload` path [4](#0-3)  and the UEA-payload path `ExecutePayloadV2` [5](#0-4) , both of which are reachable by any ordinary unprivileged user submitting a universal payload for EVM execution through their UEA.

### Impact Explanation
If base fee rounds to zero, `DeductAndBurnFees` (which transfers-then-burns `upc` from the executing account) is never called, so users get arbitrary EVM `gasUsed` execution through the module-originated `DerivedEVMCall`/`CallUEAExecutePayload` path for free. This breaks the gas fee accounting invariant described in the "Allowed Impact Gate" (corruption of gas fee accounting / accepted state transitions without proper fee payment), and can be abused for sustained free execution / spam of module-originated EVM calls, since the normal ante-handler min-gas-price checks apply to the outer Cosmos tx fee, not to this internal `upc`-denominated gas accounting for UEA execution.

### Likelihood Explanation
This requires the feemarket base fee to actually decay to a sub-1-`upc` (raw value `< 1e18`) level. Given the parameter is denominated with 18-decimal precision and genesis/test configurations set very large starting base fees (e.g. `1000000000` upc), whether the feemarket's adjustment algorithm and floor/param bounds (`min_gas_price`, EIP-1559 elasticity) can ever push the value below `1e18` raw units in production could not be fully verified from the code inspected — the feemarket module's parameter validation and adjustment logic live outside the scoped `x/uexecutor` files reviewed here. This is a **latent** structural rounding flaw analogous to the reported issue, but confirming realistic reachability (whether the base fee can actually decay below 1 whole upc under sustained low block usage, and whether `feemarket.Params.MinGasPrice`/base-fee floor prevents it) would require reviewing the feemarket module's parameters and change-rate formula, which was not found in the indexed portion of this repository.

### Recommendation
Avoid truncating integer division on the base fee before multiplying by `gasUsed`. Instead, keep the `LegacyDec` precision through the full computation, e.g.:
```go
effectiveGasPriceDec := baseFee // LegacyDec, 18-decimal precision
gasCostDec := effectiveGasPriceDec.MulInt64(int64(gasUsed))
gasCost := gasCostDec.Ceil().TruncateInt().BigInt() // round up, never down to zero
```
This guarantees `gasCost` is only zero when the true fee is genuinely zero, not merely sub-1-upc, closing the free-execution gap symmetric to the reported `customPrecisionMultipliers` fix (adding back the lost precision instead of dividing it away prematurely).

### Proof of Concept
1. Set (or let the feemarket dynamically adjust to) a base fee such that `feemarketKeeper.GetBaseFee(ctx).BigInt()` returns a value less than `1e18` (e.g., `500_000_000_000_000_000` = 0.5 raw-upc-equivalent).
2. Submit `MsgExecutePayload` (or trigger `ExecutePayloadV2` via a CEA inbound) with `maxFeePerGas` set to satisfy the `maxFeePerGas.Cmp(baseFeeBig) < 0` check (which also uses the truncated `baseFeeBig`, so it will pass trivially once `baseFeeBig == 0`).
3. Observe `CalculateGasCost` returns `gasCost = 0` since `effectiveGasPrice = baseFeeBig = 0`.
4. `DeductGasFeesFromReceipt` short-circuits at `gasCost.Sign() <= 0` and returns `nil` without calling `DeductAndBurnFees`, so the EVM execution (with real `gasUsed`) is committed with zero `upc` burned from the caller's UEA balance — confirmable via `bankKeeper.GetBalance` before/after showing no debit despite non-zero `receipt.GasUsed`.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	// is a no-op if the receipt is nil or GasUsed == 0 (EVM call produced

	if feeErr := k.DeductGasFeesFromReceipt(cacheCtx, cacheCtx, ueaAddr, receipt, universalPayload); feeErr != nil {
		// Cache discarded — EVM state and any partial fee work both roll back.
		return receipt, fmt.Errorf("gas fee deduction failed: %w", feeErr)
	}

	if execErr != nil {
		// EVM execution failed — cache discarded by not calling writeCache.
