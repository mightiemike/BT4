## Finding [1](#0-0) 

### Title
Unbounded `compressed_R_volun_auds` length lets senders attach unverified voluntary-auditor ciphertexts to the committed `Transferred` event - (aptos-move/framework/aptos-framework/sources/confidential_asset/sigma_protocols/proofs/sigma_protocol_transfer.move)

### Summary
`num_volun_auditors`, the value that drives the sigma-protocol statement construction and verification for a confidential transfer, is derived exclusively from `compressed_ek_volun_auds.length()` (the encryption-key list), not from `compressed_amount.get_compressed_R_volun_auds().length()` (the auditor ciphertext list): [2](#0-1) 

`assert_correct_num_chunks` in `confidential_amount.move` only validates that each inner `R_volun_auds[i]` vector has the correct chunk length, and never bounds or checks the outer vector's length against `num_volun_auditors`: [3](#0-2) 

The only length-related check performed before statement construction is on individual chunk vectors, not on the outer count: [4](#0-3) 

The statement builder then only iterates and binds the first `num_volun` entries of `compressed_R_volun_auds` into the sigma-protocol statement: [5](#0-4) 

If `compressed_amount.compressed_R_volun_auds.length() > num_volun (= compressed_ek_volun_auds.length())`, the extra entries beyond index `num_volun - 1` are never added to the sigma-protocol statement builder (`b`), and are therefore never part of the `psi`/`f` binding that `assert_verifies` checks: [6](#0-5) 

Despite not being bound by the proof, the full `compressed_amount` (including the un-verified surplus `R_volun_auds` entries) is returned unchanged from `assert_valid_transfer_proof` and committed into the `Transferred` event, which is part of the authenticated, committed transaction output: [7](#0-6) [8](#0-7) 

### Finding Description
`confidential_transfer_raw` lets an unprivileged sender supply `ek_volun_auds` (a list of voluntary-auditor encryption keys) and `amount_R_volun_auds` (a list of per-auditor R-ciphertext vectors) as two independently-sized parameters. `num_volun_auditors` used to construct and verify the sigma-protocol statement is taken solely from `ek_volun_auds.length()`. The Move-level validation on `compressed_amount` (`assert_correct_num_chunks` in `confidential_amount.move`, and the `all(|r| r.length() == get_n())` check in `sigma_protocol_transfer.move`) never asserts that `compressed_R_volun_auds.length() == num_volun_auditors`. The statement-builder loop only walks `[0, num_volun)`, so when `compressed_R_volun_auds.length() > num_volun`, the surplus entries are silently skipped — they consume no group-element slot in the sigma statement and are not part of what the ZK proof attests to.

Because `assert_valid_transfer_proof` returns the full, unmodified `compressed_amount` (including the surplus, unverified entries) and this object is placed verbatim into the `Transferred` event, the event log — an authenticated, versioned part of committed ledger state — ends up containing auditor ciphertext material whose correctness (i.e., that it actually encrypts the transferred amount under the corresponding EK) was never checked by any proof. An attacker fully controls the content of these extra ciphertext chunks (arbitrary `CompressedRistretto` points), since they are decoded straight from raw bytes via `new_compressed_from_bytes` with no cryptographic binding.

### Impact Explanation
The event's `amount: CompressedAmount` field is meant to be an authenticated statement that, for every voluntary auditor, `compressed_R_volun_auds[i]` is a correct decryption share for that auditor's key, as attested by the sigma proof. With the length mismatch, this invariant breaks: the committed `CompressedAmount.compressed_R_volun_auds` can have more entries than `num_volun_auditors` that were actually proof-bound. Any auditor, indexer, or dApp that trusts the on-chain event as cryptographically-verified data (as the module's own security-sensitive banner implies it should be) can be misled about how many/which auditor components are backed by the sigma proof versus attacker-injected garbage. This is a proof-binding violation of committed, authenticated ledger state (the event), not merely a display/formatting issue — it directly matches the "Authenticated API and proof-bearing responses must stay bound to the right...object" requirement, since the object (`CompressedAmount`) as committed no longer matches the object the proof verified.

Note: the recipient's actual pending balance (`amount`, i.e., `amount_P`/`recip_R`) is built from separately, always-bound indices and is unaffected — the mismatch is confined to the voluntary-auditor ciphertext bookkeeping that rides along in `compressed_amount` and the `Transferred` event.

### Likelihood Explanation
Trivial and fully attacker-controlled: any unprivileged sender calling `confidential_transfer_raw` can supply `ek_volun_auds` shorter than `amount_R_volun_auds`. No special permissions, auditor cooperation, or trusted-operator error is required — this is reachable directly from the entry function `confidential_transfer_raw`.

### Recommendation
In `assert_valid_transfer_proof` (or in `confidential_amount::new_compressed_from_bytes`/`assert_correct_num_chunks`), assert that `compressed_amount.get_compressed_R_volun_auds().length() == compressed_ek_volun_auds.length()` before constructing the sigma-protocol statement, so the outer auditor count used for verification always matches the outer count committed to storage/events.

### Proof of Concept
1. Sender calls `confidential_transfer_raw` with `ek_volun_auds = [ek1]` (1 key) but `amount_R_volun_auds = [[R for aud1...n-chunks], [attacker-garbage chunk vector]]` (2 entries, second with n chunks of arbitrary points).
2. `num_volun_auditors = ek_volun_auds.length() = 1`.
3. `assert_correct_num_chunks`/`all(|r| r.length()==get_n())` only checks each of the 2 inner vectors has `n` chunks — both pass regardless of outer count.
4. `new_transfer_statement`'s loop only binds index 0 (`vector::range(0, 1)`), leaving the attacker's second entry (`compressed_R_volun_auds[1]`) completely outside the sigma statement.
5. The proof verifies successfully (it never referenced the garbage entry).
6. `compressed_amount` (with both entries) is emitted unchanged in `Transferred::V1.amount`, so the committed event now shows `2` voluntary-auditor R-component groups while the proof only attested to `1`.

    /// Asserts that a transfer proof verifies.
    public(friend) fun assert_verifies(
        self: &TransferSession, stmt: &Statement<Transfer>, proof: &Proof,
    ) {
        let has_eff = self.has_effective_auditor;
        let num_volun = self.num_volun_auditors;
        assert_transfer_statement_is_well_formed(stmt, has_eff, num_volun);

        let success = sigma_protocol::verify(
            new_domain_separator(@aptos_framework, chain_id::get(), PROTOCOL_ID, bcs::to_bytes(self)),
            |_X, w| psi(_X, w, has_eff, num_volun),
            |_X| f(_X, has_eff, num_volun),
            stmt,
            proof
        );

        assert!(success, error::invalid_argument(E_INVALID_TRANSFER_PROOF));
    }
