### Title
Protocol fee minted on gross accrued interest before bad-debt is socialized, permanently overstating treasury shares against written-down vault assets - (File: `local-testing/contracts/vault/vault-stx.clar`, `vault-usdc.clar`, `vault-sbtc.clar`, `vault-ststx.clar`, `vault-usdh.clar`, `vault-ststxbtc.clar`, mirrored in `mainnet/contracts/vault/v0-vault-*.clar`, function `accrue` and `socialize-debt`)

### Summary
`accrue()` mints a protocol-fee share (`treasury-lp`) to `.dao-treasury` based on the *gross* interest accrued on the vault's total scaled principal, without knowing whether that interest is actually collectible. When a position later turns out to be bad debt and is written off via `socialize-debt`, the interest contribution of that specific debt to the fee that was minted is never clawed back. This is the same root-cause pattern as the Overlay finding: a fee/value is computed and locked in (minted) before the debt/health outcome for the underlying position is known, and no correction happens when the position turns out to be underwater.

### Finding Description
In every vault contract's `accrue()`, e.g. `local-testing/contracts/vault/vault-stx.clar` lines 837-865: [1](#0-0) 

the sequence is:
1. Compute `old-debt` and `new-debt` from `scaled-principal` and the interest indexes, and derive `debt-delta` — the aggregate interest that accrued on **all** outstanding scaled debt in this vault since the last update.
2. Compute `reserve-inc = debt-delta * fee-reserve / BPS` — the protocol's cut of that gross interest.
3. Compute `treasury-lp` and immediately `ft-mint?` it to `.dao-treasury` — this mutation happens unconditionally, for *all* debt in the vault, including any position that is simultaneously underwater and about to be liquidated/socialized in the very same transaction.

This `accrue()` is itself invoked from inside `liquidate()` in the market contract, via `accrue-user-debts` → `accrue-and-cache` → `vault-accrue`, at the very start of the liquidation flow: [2](#0-1) 

Only *after* this fee-minting accrual does `liquidate()` compute `total-collateral-usd`/`total-debt-usd`, run the LTV health check, determine `no-collateral-left`, and — if the borrower has no collateral left — call `socialize-debt-asset` in a `fold` to write off the remaining bad debt: [3](#0-2) 

The vault's `socialize-debt` function only adjusts `lindex`, `principal-scaled`, `total-borrowed`, and `assets` — it never touches `zft` shares already minted to `.dao-treasury`: [4](#0-3) 

So the exact same defect as the Overlay report exists: the fee (`treasury-lp`) is "recorded" (minted as real, transferable shares) based on notional interest before the health/solvency of the underlying debt is checked, and the code never adjusts the fee downward on the remaining portion once the position is determined to be a total loss. Because `debt-delta` used for the fee calculation is the vault-wide aggregate (not filtered per-borrower), a borrower's final block of interest — accrued on debt that is about to be zeroed out via `socialize-debt` in the same or an immediately following transaction — still contributes to `reserve-inc`/`treasury-lp` that is unconditionally minted to the treasury. When `socialize-debt` subsequently reduces `lindex` to reflect the loss, that write-down is borne by depositors' redemption value, while the treasury's already-minted shares are not reduced to reflect that the "interest" backing them was never actually paid by the borrower.

### Impact Explanation
This causes a permanent, uncorrected transfer of value from depositors to the treasury: fee shares are minted against interest that is subsequently proven uncollectible and written off. Because `socialize-debt` never claws back or dilutes the treasury's shares, the DAO treasury permanently holds shares whose backing value was never actually realized from the borrower, at the depositors' expense. This is a permanent freezing/misallocation of protocol yield that should have been forgone along with the socialized debt — falling under the in-scope "permanent freezing of unclaimed yield" impact category, since the fee (unclaimed yield at time of accrual) is diverted to the treasury instead of being correctly reduced to zero for the written-off portion.

### Likelihood Explanation
This triggers on ordinary protocol operation: any liquidation of an account whose collateral fully clears (`no-collateral-left`) and that has an active socialize-debt event will exhibit the effect, because `accrue()` runs unconditionally at the very start of every `liquidate()` call and always mints its computed `treasury-lp` before the socialization decision is made later in the same call. No special attacker action or malicious input is needed — it is a structural consequence of the order of operations, so it occurs with normal frequency whenever bad debt is realized.

### Recommendation
Adjust the fee computation so that the portion of accrued interest attributable to debt that is being socialized (written off) in the same accrual cycle is excluded from `reserve-inc`/`treasury-lp`, mirroring the Overlay mitigation: compute the fee only on interest that is actually available/collectible after accounting for shortfalls, or alternatively make `socialize-debt` proportionally claw back/burn the treasury's `zft` shares that correspond to the interest portion of the debt being written off, so the treasury never retains fee shares backed by debt that was never repaid.

### Proof of Concept
1. A borrower has an outstanding debt position in `vault-usdc` that is close to full liquidation (collateral value ≈ debt value, with a bad-debt shortfall building via `total-borrowed` interest accrual).
2. Anyone calls `market.clar liquidate(...)` on the borrower [5](#0-4) .
3. Inside `liquidate()`, `accrue-user-debts` triggers `accrue-and-cache` → `vault-accrue` → `vault-usdc.accrue()` [6](#0-5) , which computes `debt-delta` over the borrower's (and all other borrowers') scaled principal, derives `reserve-inc`, and unconditionally mints `treasury-lp` zUSDC shares to `.dao-treasury` [7](#0-6) .
4. `liquidate()` proceeds to compute LTV, seize collateral, and — because the borrower's collateral is fully exhausted — determines `no-collateral-left` is true and calls `fold socialize-debt-asset` on the remaining debt [8](#0-7) , which calls `vault-usdc.socialize-debt`, writing down `lindex` and `total-borrowed` for the loss.
5. `socialize-debt` never reduces the `zft` shares minted to `.dao-treasury` in step 3 [9](#0-8) ; the fee shares minted for interest that was never actually paid by the now-insolvent borrower remain permanently in the treasury, funded by the depositors who absorb the `lindex` write-down.
