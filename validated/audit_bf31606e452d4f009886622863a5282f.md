### Title
Fee transfer success return value not checked in `charge_fee` (Starknet OS) — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/transaction_impls.cairo])

### Summary
The Starknet OS `charge_fee` function performs an ERC20 `transfer` call to move the transaction fee from the sender to the sequencer, but it only checks that the call did not *revert* — it never inspects the `retdata` (the boolean success value returned by the ERC20 `transfer` entry point). This mirrors the audit-report pattern of ignoring an ERC20 `transfer`/`transferFrom` boolean return value, just translated to Starknet/Cairo semantics (revert-check only, no return-value check).

### Finding Description
`charge_fee` builds an ERC20 `TransferCallData` and invokes the fee token's `transfer` entry point through `non_reverting_select_execute_entry_point_func`, but discards all outputs of the call: [1](#0-0) 

Contrast this with `run_validate` in the same OS module, which explicitly checks the returned data (`retdata[0] = VALIDATED`) after calling the same helper: [2](#0-1) 

The shared helper `non_reverting_select_execute_entry_point_func` itself only asserts `is_reverted = 0`; it does not, and cannot, know that the callee is expected to return a boolean "success" felt, so the boolean check must be performed by the caller — which `charge_fee` fails to do: [3](#0-2) 

This is the direct Cairo/Starknet analog of the reported issue: the "boolean return value of `transfer()`" is never validated by the caller — only the absence of a revert is checked.

### Impact Explanation
The fee token contract is intended to revert on insufficient balance (as implemented in the reference ERC20, which uses `assert_not_zero(enough_balance)` before performing the balance mutation), so under the *current* reference implementation, a failed transfer normally does cause a revert, and `assert is_reverted = 0` would catch it. However, the OS's `charge_fee` logic hard-codes the assumption that "no revert" == "fee successfully collected," without validating the actual boolean return value the ERC20 standard defines for `transfer`. If the fee token entry point ever returns `FALSE` without reverting (a valid Cairo control-flow pattern, and possible with any future/alternate fee-token class hash configured via `starknet_os_config.fee_token_address`), the OS would treat the transaction as fee-paid and proceed to commit the block, while the sequencer's balance was never actually incremented. This causes divergence between the committed state root (no balance change) and the accounted transaction fee, and could result in permanent loss of protocol fee revenue (the sequencer performing "free" execution work) with no way to detect or roll back after the fact, since the OS unconditionally proceeds past `charge_fee`.

### Likelihood Explanation
This is reachable trivially by any unprivileged transaction sender — every account transaction with `max_fee != 0` passes through `charge_fee`. The behavior depends entirely on how the currently-configured fee token contract implements `transfer` (this address is a governance/config parameter, not attacker controlled), which limits the likelihood under the *current* reference ERC20 implementation, but the OS-level control-flow bug (unchecked return boolean) is real and would silently activate the moment the fee token's `transfer` semantics deviate from "always revert on failure" (e.g., a future Cairo1 fee-token upgrade using safer, non-reverting boolean returns, which is common in modern token implementations).

### Recommendation
In `charge_fee`, capture and validate the `retdata` returned from the fee-token `transfer` call, asserting that the returned success boolean is `TRUE` (consistent with how `run_validate` checks `retdata[0] = VALIDATED`), rather than relying solely on the absence of a Cairo-level revert.

### Proof of Concept
1. Configure (or imagine a future protocol upgrade to) a fee token class whose `transfer` implementation returns `0` (false) instead of reverting when the sender's balance is insufficient (a legal ERC20-style implementation).
2. Submit any account transaction (e.g., a trivial invoke) with `max_fee`/resource bounds set such that the actual fee exceeds the sender's fee-token balance.
3. During `charge_fee`, `non_reverting_select_execute_entry_point_func` returns `is_reverted = 0` (no revert) with `retdata[0] = 0`; `charge_fee` discards this return value entirely and returns `()`.
4. The OS proceeds to `%{ EndTx %}` and commits the block as if the fee had been collected, even though the sequencer's and sender's fee-token balances in storage are unchanged — resulting in a state root that reflects no fee payment while the transaction succeeded, causing the sequencer to lose the fee revenue it should have collected. // Charges a fee from the user.
// If max_fee is not 0, validates that the selector matches the entry point of an account contract
// and executes an ERC20 transfer on the behalf of that account contract.
//
// Arguments:
// block_context - a global context that is fixed throughout the block.
// tx_execution_context - The execution context of the transaction that pays the fee.
func charge_fee{
    range_check_ptr,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, tx_execution_context: ExecutionContext*) {
    alloc_locals;

    local tx_info: TxInfo* = tx_execution_context.execution_info.tx_info;
    let max_fee = compute_max_possible_fee(tx_info=tx_info);

    if (max_fee == 0) {
        return ();
    }

    local low_actual_fee;
    %{ LoadActualFee %}
    local calldata: TransferCallData = TransferCallData(
        recipient=block_context.block_info_for_execute.sequencer_address,
        amount=Uint256(low=low_actual_fee, high=0),
    );

    // Verify that the charged amount is not larger than the transaction's max_fee field.
    assert_nn_le(calldata.amount.low, max_fee);

    // TODO(ilya, 01/01/2026): Consider caching the fee_token_class_hash.
    local fee_token_address = block_context.os_global_context.starknet_os_config.fee_token_address;
    let (fee_state_entry: StateEntry*) = dict_read{dict_ptr=contract_state_changes}(
        key=fee_token_address
    );
    let (__fp__, _) = get_fp_and_pc();
    // Use block_info directly from block_context, so that charge_fee will always run in
    // execute-mode rather than validate-mode.
    local execution_context: ExecutionContext = ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=fee_state_entry.class_hash,
        calldata_size=TransferCallData.SIZE,
        calldata=&calldata,
        execution_info=new ExecutionInfo(
            block_info=block_context.block_info_for_execute,
            tx_info=tx_info,
            caller_address=tx_info.account_contract_address,
            contract_address=fee_token_address,
            selector=TRANSFER_ENTRY_POINT_SELECTOR,
        ),
        deprecated_tx_info=tx_execution_context.deprecated_tx_info,
    );

    let remaining_gas = DEFAULT_INITIAL_GAS_COST;
    non_reverting_select_execute_entry_point_func{remaining_gas=remaining_gas}(
        block_context=block_context, execution_context=&execution_context
    );
    return ();
}

// Same as `select_execute_entry_point_func`, but does not support reverts and does
// not have an implicit 'revert_log' argument.
func non_reverting_select_execute_entry_point_func{
    range_check_ptr,
    remaining_gas: felt,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, execution_context: ExecutionContext*) -> (
    retdata_size: felt, retdata: felt*, is_deprecated: felt
) {
    let revert_log = init_revert_log();
    let (is_reverted, retdata_size, retdata, is_deprecated) = select_execute_entry_point_func{
        revert_log=revert_log
    }(block_context=block_context, execution_context=execution_context);
    assert is_reverted = 0;
    return (retdata_size, retdata, is_deprecated);
}
