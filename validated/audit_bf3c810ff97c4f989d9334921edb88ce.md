No vulnerability found for this question.

Explanation: The CVE describes unbounded recursive descent parsing causing stack exhaustion. In protobuf-go, every decode path enforces an explicit recursion depth check before recursing:

- Binary wire format: `proto/decode.go` decrements `RecursionLimit`/`depth` and returns `errRecursionDepth` when exceeded, both in the generic path [1](#0-0)  and the generated-message fast path in `internal/impl/decode.go`'s `unmarshalPointer` [2](#0-1) .
- Low-level group/tag parsing in `encoding/protowire` uses a `DefaultRecursionLimit` when consuming nested groups via `ConsumeFieldValue`/`ConsumeGroup` [3](#0-2) .
- `encoding/prototext` decrements `RecursionLimit` on every `unmarshalMessage`, `skipValue`, and `skipMessageValue` call, covering both known and skipped/unknown fields [4](#0-3) [5](#0-4) [6](#0-5) .
- `encoding/protojson` enforces the same limit for nested messages, maps, arrays, `Any`, and well-known JSON types (`Value`, `Struct`, `ListValue`), verified by dedicated tests asserting `"exceeded max recursion depth"` errors [7](#0-6) .

This is a consistent, defense-in-depth mitigation across every reachable decode path (binary, text, JSON, group skipping), so the exact broken invariant from the QPDF report — deep recursion without a depth check leading to stack overflow — does not exist as an analog vulnerability in protobuf-go's production decode paths on a trusted-schema/default-parser assumption.
