## Analysis

The Curve report's core pattern — a hard dependency on an external contract call that can deterministically and permanently revert for certain pool/asset configurations, blocking the only recovery path and causing unrecoverable user fund loss — has a concrete analog in Push Chain's gas-abstraction deposit-and-swap flow for `isCEA` inbounds.

### Title
Isolated Uniswap V3 quote/swap failure permanently strands bridged funds for `isCEA` GAS_AND_PAYLOAD inbounds (no revert-recovery path) - ([File: x/uexecutor/keeper/execute_inbound_gas_and_payload.go])

### Summary
`ExecuteInboundGasAndPayload` and `ExecuteInboundGas` both route GAS-type inbound deposits through `gasAndPayloadDepositAutoSwap` / the inline swap flow, which calls the Uniswap V3 `QuoterV2.quoteExactInputSingle` on-chain before performing `depositPRC20WithAutoSwap`. For non-`isCEA` inbounds a swap failure sets `shouldRevert=true` and creates an `INBOUND_REVERT` outbound so the user's funds are returned on the source chain. For `isCEA` inbounds, by explicit design ("isCEA failures never create an INBOUND_REVERT outbound"), a swap/quote failure is recorded only as a `FAILED` PCTx and the function returns `nil` — with no fund-recovery mechanism whatsoever.

### Finding Description
`ExecuteInboundGasAndPayload` (`x/uexecutor/keeper/execute_inbound_gas_and_payload.go:61-100`) branches on `utx.InboundTx.IsCEA`. In the `isCEA` branch, both the UEA path and the non-UEA/EOA path call `k.gasAndPayloadDepositAutoSwap(sdkCtx, prc20AddrHex, ueaAddr, amount)` [1](#0-0)  — a helper that fetches a Uniswap V3 `QuoterV2.quoteExactInputSingle` quote and then calls `CallPRC20DepositAutoSwap` with a slippage-adjusted `minPCOut` [2](#0-1) .

If either the quote call (`GetSwapQuote`) or the deposit-with-autoswap call reverts — e.g., a low-liquidity or edge-case PRC20/WPC pool causes `quoteExactInputSingle` to revert deterministically for the given `amount`, mirroring the Curve `remove_liquidity(0,[0,0])` underflow pattern from the source report — `execErr` is set. The comment at line 100 makes the design explicit: *"isCEA failures never create an INBOUND_REVERT outbound."* [3](#0-2)  Downstream, the guard at line 212 confirms this: any `execErr != nil` combined with `IsCEA == true` causes the function to record a `FAILED` PCTx and `return nil` without ever building a revert outbound. [4](#0-3) 

By contrast, the non-`isCEA` path treats the identical swap failure as fatal and safely creates an `INBOUND_REVERT` outbound to return the user's funds: [5](#0-4)  and [6](#0-5) . The same asymmetry exists in the pure GAS path, `ExecuteInboundGas`, where the swap chain (`GetUniversalCoreQuoterAddress` → `GetUniversalCoreWPCAddress` → `GetDefaultFeeTierForToken` → `GetSwapQuote` → `CallPRC20DepositAutoSwap`) sets `shouldRevert=true` on any failure and always creates a revert outbound [7](#0-6)  and [8](#0-7)  — but `ExecuteInboundGas` is invoked for non-`isCEA` `TxType_GAS` only; the `isCEA` `TxType_GAS_AND_PAYLOAD` flow above has no equivalent safety net.

At this point in the pipeline the source-chain gateway event has already been honestly observed and voted through 2/3 quorum by `x/uvalidator` (the ballot has PASSED before `ExecuteInboundGasAndPayload` runs), meaning the user's assets are already locked/burned on the source chain. If the on-chain swap dependency (`QuoterV2.quoteExactInputSingle`) reverts for that specific token/fee-tier/amount combination — plausible for any bridged asset whose PRC20↔WPC pool has thin liquidity, an unfavorable tick range, or an amount that triggers an internal arithmetic revert in the quoter — the deposit is never credited to the recipient (UEA or EOA), and per the explicit `isCEA` design, no outbound is ever created to return the funds either. There is no retry mechanism in this code path: the inbound is fully processed (ballot finalized, ExecuteInboundGasAndPayload run to completion) and the failure is terminal.

### Impact Explanation
This causes permanent, unrecoverable loss of user-bridged funds for any `isCEA` `GAS`/`GAS_AND_PAYLOAD` inbound whose associated PRC20↔WPC Uniswap V3 pool reverts on `quoteExactInputSingle` for the given amount/fee-tier — functionally identical in effect to the source report's "liquidations are impossible... users can go into bad debt with no way to recover the lost funds," except here it is "gas-abstracted CEA deposits are impossible... user funds are permanently stranded with no way to recover them," matching the in-scope impact "permanent loss ... of user or protocol-controlled funds."

### Likelihood Explanation
Triggering this requires no privileged access: any ordinary user or smart contract depositing through the gateway with `IsCEA=true` and `TxType_GAS_AND_PAYLOAD`/`TxType_GAS` targeting a token whose configured Uniswap V3 pool is illiquid, unconfigured for the chosen fee tier, or otherwise reverts on the quote call for that amount will hit this path. Since token/pool configuration is set by registry admins (not the attacker) but liquidity conditions are market-driven and can change at any time, an unprivileged depositor can hit this deterministically once such a condition exists, with no attacker action beyond a normal deposit needed.

### Recommendation
Treat quote/swap failures on the `isCEA` gas-abstraction path the same as the non-`isCEA` path: either (a) create an `INBOUND_REVERT`/equivalent outbound (or a CEA-appropriate refund instruction) when `gasAndPayloadDepositAutoSwap` fails so funds return to the sender, or (b) add a no-swap fallback (deposit raw PRC20 without the swap leg, similar to the `withSwap=false` fallback already implemented in `applyGasRefund`) so a reverting quote never results in permanently stranded funds.

### Proof of Concept
1. Configure (or naturally arrive at) a PRC20/WPC Uniswap V3 pool at the default fee tier such that `QuoterV2.quoteExactInputSingle` reverts for a given `amountIn` (e.g., due to insufficient liquidity in that tick range) — analogous to Curve's `remove_liquidity(0, [0,0])` underflow.
2. An unprivileged user deposits that asset on a source chain via the gateway with `TxType_GAS_AND_PAYLOAD`, `IsCEA=true`, targeting either a UEA or a deployed contract.
3. Universal Validators honestly observe and vote the inbound through quorum (`MsgVoteInbound` × 2/3+); the ballot PASSES.
4. `ExecuteInboundGasAndPayload` calls `gasAndPayloadDepositAutoSwap`, which calls `GetSwapQuote` → reverts.
5. `execErr != nil` and `utx.InboundTx.IsCEA == true` → the function records a `FAILED` PCTx and returns `nil` (`execute_inbound_gas_and_payload.go:211-214`), without ever attaching an `INBOUND_REVERT` outbound.
6. The user's source-chain funds remain locked/burned in the gateway; the equivalent PRC20 is never minted or credited on Push Chain; no outbound is ever created to make the user whole.

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
