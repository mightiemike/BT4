### Title
Replay-verify tooling accepts VM output whose committed state root diverges from the archived `TransactionInfo` - ([File: types/src/transaction/mod.rs])

### Summary
`TransactionOutput::ensure_match_transaction_info` [1](#0-0)  checks status, gas, write-set hash (`state_change_hash`) and event root hash, but explicitly skips `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash`, per the code's own TODO comment [2](#0-1) . `storage/db-tool/src/replay_on_archive.rs`'s `execute_and_verify` uses this function as the only correctness gate when replaying archived transactions against a fresh VM execution [3](#0-2) , and never runs the executed outputs through `DoStateCheckpoint`, which is the component that actually computes and compares the state-checkpoint root elsewhere (e.g., in `execution/executor/src/chunk_executor/mod.rs`) [4](#0-3) .

### Finding Description
`replay_on_archive` (the tool used to validate that current VM/execution logic reproduces historical, already-committed state against an authenticated backup/archive) drives execution purely through `execute_and_verify`. That function calls `ensure_match_transaction_info` per transaction and treats a `Some(err)`/`None` result as ground truth for pass/fail [5](#0-4) . Unlike the state-sync `ChunkExecutor::update_ledger` path — which additionally calls `DoStateCheckpoint::run()` with `known_state_checkpoints`/`known_hot_state_checkpoints`/`known_position_state_checkpoints` and asserts the freshly computed checkpoint hash equals the one recorded in the (proof-verified) `TransactionInfo` [6](#0-5)  and [7](#0-6)  — `replay_on_archive` never builds or checks a state tree/checkpoint at all. It only feeds `state_view_at_version(current_version - 1)` and compares the write-set *hash*, not the actual resulting state root.

Because a write set's hash matching `state_change_hash` proves the write set is byte-identical to what was originally committed, this alone doesn't validate that applying that write set (or the underlying VM semantics) to the state tree reproduces the previously accepted `state_checkpoint_hash` — that check requires reconstructing the SMT/JMT update and comparing roots, which only `DoStateCheckpoint` does. Since `replay_on_archive` never performs that step, any divergence in state-tree/state-checkpoint computation (e.g. from a JMT/state-view bug, a hot-state or trading-native computation bug affecting `hot_state_checkpoint_hash`/`position_state_checkpoint_hash`, or a hard fork that silently changes state semantics without changing byte-for-byte write sets in the sampled transactions) would be invisible to this tool and reported as a successful replay.

### Impact Explanation
This affects a tool whose entire purpose is authenticating/validating that current node software reproduces the historically committed, consensus-authenticated ledger state (state-commitment integrity is exactly the invariant in scope: "Committed state that differs from the correct VM result... Hard-fork-only divergence during commit, replay..."). A silent state-root divergence that `replay_on_archive` fails to catch means operators/auditors relying on this tool for state-integrity verification of historical or upgraded execution logic would get false assurance that state computation is correct, when in fact the state tree (or hot-state/native-trading state roots which are now committed on-chain via `TransactionInfoV1`) has diverged. This is a proof-integrity gap in an authenticated verification pipeline, though it requires a separate root-cause bug in state computation to actually manifest as a real divergence — this component itself doesn't corrupt consensus state, it fails to detect corruption that originates elsewhere.

### Likelihood Explanation
Low-to-moderate. This is not directly exploitable by an unprivileged attacker to corrupt mainnet state through consensus; it is a tooling gap that only matters when there already is a state-computation bug elsewhere (e.g. in trading-native/hot-state computation, which are relatively new, feature-gated subsystems per the `HOTNESS_IN_EPILOGUE`/`COMPUTE_TRADING_NATIVE_STATE_ROOTS` feature flags [8](#0-7) ). The code's own TODO comment already flags this as a known limitation to be fixed "before enabling COMPUTE_TRADING_NATIVE_STATE_ROOTS" [2](#0-1) , indicating awareness but not yet a fix, and the gate is presumably still off given the TODO's phrasing.

### Recommendation
Extend `ensure_match_transaction_info` (or `replay_on_archive::execute_and_verify` directly) to reconstruct/compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` against the archived `TransactionInfo`, mirroring the checks already performed in `do_state_checkpoint.rs::get_state_checkpoint_hashes`, before treating a replay as verified.

### Proof of Concept
Not independently exploitable as a standalone PoC — it requires an actual state-computation divergence (in the JMT/state-tree update, hot-state accounting, or native-trading state root logic) to be introduced first; `replay_on_archive`/`ensure_match_transaction_info` would then fail to flag it. No PoC is provided because this is a detection-gap finding, not a state-corruption primitive by itself.

**Uncertainty note:** I could not fully confirm whether `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/`HOTNESS_IN_EPILOGUE` are currently active on mainnet or only in development, which affects real-world exploitability; the index does not expose feature-flag activation state, only the flag definitions.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

    fn get_state_checkpoint_hashes(
        execution_output: &ExecutionOutput,
        known_state_checkpoints: Option<Vec<Option<HashValue>>>,
        computed_last_checkpoint_hash: HashValue,
        label: &str,
    ) -> Result<Vec<Option<HashValue>>> {
        let _timer = OTHER_TIMERS.timer_with(&[&format!("get_{label}_checkpoint_hashes")]);

        let num_txns = execution_output.to_commit.len();
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();

        if let Some(known) = known_state_checkpoints {
            ensure!(
                known.len() == num_txns,
                "Bad number of known {label} hashes. {} vs {}",
                known.len(),
                num_txns,
            );
            if let Some(idx) = last_checkpoint_index {
                ensure!(
                    known[idx] == Some(computed_last_checkpoint_hash),
                    "{label} root hash mismatch with known hashes passed in. {:?} vs {:?}",
                    known[idx],
                    Some(computed_last_checkpoint_hash),
                );
            }
            Ok(known)
        } else {
            if !execution_output.is_block {
                // We should enter this branch only in test.
                execution_output.to_commit.ensure_at_most_one_checkpoint()?;
            }

            let mut out = vec![None; num_txns];
            if let Some(index) = last_checkpoint_index {
                out[index] = Some(computed_last_checkpoint_hash);
            }
            Ok(out)
        }
    }
