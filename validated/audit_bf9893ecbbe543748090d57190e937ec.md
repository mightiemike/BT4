## Finding: Valid

### Title
Attacker-Forced Rent-Reclaim Griefing via Spoofed Recent Signature on Orphan PDA — (File: `universalClient/chains/svm/rent_reclaimer.go`)

### Summary
`RentReclaimer.isOldEnough` determines whether an orphaned `StoredIxData` PDA is safe to close and its rent reclaimed by checking the block time of the *most recent transaction that references the PDA's address at all* via `GetSignaturesForAddressWithOpts` with `Limit=1`, rather than checking the PDA account's actual creation slot/time.

### Finding Description
`isOldEnough` fetches only the single most recent signature associated with the PDA address and compares its block time against `minAge`: [1](#0-0) 

Solana's `getSignaturesForAddress` RPC indexes *any* confirmed transaction that lists the given pubkey among its account keys — it does not require the transaction to write to, own, or otherwise meaningfully interact with that account, and it includes failed transactions. An unprivileged attacker can therefore submit an arbitrary cheap transaction (e.g., a trivial system-program no-op or even one intentionally designed to fail) that simply lists the target orphan PDA pubkey as one of its accounts. This creates a brand-new, recent signature entry for that address with no relation to the PDA's actual creation time.

Because `runOnce` -> `isOldEnough` only looks at the latest signature's `BlockTime`, this attacker transaction resets the perceived "age" of the PDA to near-zero: [2](#0-1) 

The comment on `isOldEnough` even documents the (incorrect) assumption being relied upon — "For StoredIxData PDAs, that's effectively the PDA's age (they only ever see one tx — their creating `store_execute_ix_data`)" — but this assumption is not enforced anywhere; nothing prevents any account from being referenced by unrelated transactions, and PDAs are not restricted from being cheaply referenced by third parties.

### Impact Explanation
As long as the attacker repeats this cheap reference transaction before each sweep interval (`rentReclaimSweepInterval = 30 * time.Minute`), `isOldEnough` will keep returning `false`/an artificially low age, causing `runOnce` to permanently `skip` reclaiming the orphan PDA. This locks the relayer/protocol-owned rent lamports (~0.002 SOL per PDA) indefinitely, at a cost to the attacker of only a base transaction fee (~5,000 lamports) per interval — asymmetrically cheap relative to the value frozen. This is a griefing/DoS on protocol-controlled rent capital, not a network-level DoS, and is reachable purely through ordinary unprivileged transaction submission.

### Likelihood Explanation
Requires only: (1) an orphaned `StoredIxData` PDA to exist (a finalize failure, which can occur naturally or potentially be induced), and (2) the attacker knowing/discovering the PDA address (trivially obtainable since `discoverOrphans` uses `GetProgramAccountsWithOpts`, a public RPC call anyone can also perform). No privileged access, validator collusion, or complex setup is needed — likelihood is high once an orphan exists.

### Recommendation
Determine PDA age from the account's actual creation, not from the most recent unrelated signature referencing it. Options:
- Fetch and use the earliest signature (creation transaction) via paginated `GetSignaturesForAddress` calls (`before`/`until` walking to the last page) rather than `Limit=1` on the most recent.
- Alternatively, store/derive a reliable creation timestamp on-chain (e.g., embed a creation slot/timestamp field in the `StoredIxData` account itself) and read that field directly instead of relying on RPC transaction history heuristics.

### Proof of Concept
1. An orphan `StoredIxData` PDA `P` exists, created 20 minutes ago (`> minAge=10m`).
2. Attacker submits any transaction `T` (e.g., a trivial `SystemProgram.Transfer` of 0 lamports to themselves, or an intentionally failing instruction) that includes `P` as a non-signer, read-only account in its account list. This succeeds/fails independent of `P`'s actual data/ownership.
3. On the next `runOnce` sweep, `discoverOrphans` still lists `P` (its `StoredIxData` account data and discriminator/refund-recipient filters are unaffected by `T`).
4. `isOldEnough(ctx, P)` calls `GetSignaturesForAddressWithOpts(limit=1)`, which now returns `T`'s signature with a fresh `BlockTime`; `age = time.Since(blockTime)` is near 0, so `age >= minAge` is `false`.
5. `P` is skipped (`skipped++`) and never closed; the attacker repeats step 2 before each subsequent 30-minute sweep to keep the PDA permanently un-reclaimed.

A unit test stubbing `GetSignaturesForAddressWithOpts` to return a synthetic signature with `BlockTime = now` for a PDA whose actual creation predates `minAge` will show `isOldEnough` returns `false`, and that `runOnce` never transitions `P` into the `closed` bucket across repeated invocations as long as the stub keeps returning a fresh signature.

// isOldEnough reports whether the most recent tx touching addr is at least
// minAge old. For StoredIxData PDAs, that's effectively the PDA's age (they
// only ever see one tx — their creating store_execute_ix_data).
func (r *RentReclaimer) isOldEnough(ctx context.Context, addr solana.PublicKey) (bool, error) {
	limit := signatureAgeProbeLimit
	var sigs []*rpc.TransactionSignature
	err := r.builder.rpcClient.executeWithFailover(ctx, "get_signatures_for_address", func(client *rpc.Client) error {
		resp, innerErr := client.GetSignaturesForAddressWithOpts(ctx, addr, &rpc.GetSignaturesForAddressOpts{
			Limit: &limit,
		})
		if innerErr != nil {
			return innerErr
		}
		sigs = resp
		return nil
	})
	if err != nil || len(sigs) == 0 {
		return false, err
	}
	if sigs[0].BlockTime == nil {
		return false, nil
	}
	age := time.Since(time.Unix(int64(*sigs[0].BlockTime), 0))
	return age >= r.minAge, nil
}
