Sanitization rejects any transaction whose signature count does not equal `num_required_signatures`, and `num_required_signatures` is always clamped to at least 1, so a zero-signature transaction cannot survive `SanitizedTransaction`/`RuntimeTransaction` construction to reach `execute_batch`/`do_get_first_error`. This is demonstrated by `runtime/src/bank/tests.rs::test_verify_and_hash_transaction_sig_len`, which shows both too-few and too-many signatures cause `TransactionError::SanitizeFailure` before any further processing. [1](#0-0) [2](#0-1) 

There is no reachable client-controlled wire-format path that bypasses this signature-count sanitization check (it's enforced during `SanitizedTransaction`/`RuntimeTransaction::try_create`, not merely by sigverify), so `do_get_first_error`'s `*transaction.signature()` in [3](#0-2)  cannot be reached with an empty `signatures` vector via an unprivileged client submitting transactions to RPC/TPU. The scenario described (durable-nonce transaction with "manipulated signature array length that survives SanitizedTransaction construction") is not supported by the codebase — no such bypass exists in the sanitization path.
