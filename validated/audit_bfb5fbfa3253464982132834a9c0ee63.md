### Title
Unauthenticated access to plugin debug/pprof endpoints exposing process memory dumps - ([File: core/web/router.go])

### Summary
`loopRoutes` in `core/web/router.go` registers `/plugins/:name/debug/pprof/*profile` and `/plugins/:name/debug/pprof/symbol` directly on the base `api` router group without any `auth.Authenticate` middleware, unlike every other sensitive route group (`debugRoutes`, `sessionRoutes`, `v2Routes`). This allows any unauthenticated network client with access to the node's HTTP port to trigger `pluginPPROFHandler`/`pluginPPROFPOSTSymbolHandler`, which proxy pprof profile/heap/goroutine dumps from the plugin's internal Prometheus port back to the caller.

### Finding Description
In `core/web/router.go`, `NewRouter` builds the base group `api` with only rate limiting and session-cookie middleware attached (`engine.Group("/", rateLimiter(...), sessions.Sessions(...))`) — no authentication check is applied at this level. `loopRoutes(app, api)` is then called and registers its handlers straight on this unauthenticated `api` group: [1](#0-0) 

Compare this to the equivalent legitimate debug-route wiring, `debugRoutes`, and the authenticated `v2Routes` group, both of which explicitly wrap with `auth.Authenticate(...)`: [2](#0-1) [3](#0-2) 

The `pluginPPROFHandler` implementation forwards the request path/profile parameter to the plugin's internal Prometheus/pprof port and returns the raw response body to the caller without any authorization check inside the handler itself: [4](#0-3) [5](#0-4) 

None of the engine-level middlewares (`otelgin`, request size limiter, logger, `gin.Recovery`, CORS, `secureMiddleware`, `helmet.Default`) perform authentication, and the `metricRoutes` pprof handler for the node itself is deliberately gated behind `authv2` at line 446 (`metricRoutes(authv2)`), showing the intended design was to protect all pprof-style debug endpoints behind auth — the plugin-specific pprof routes in `loopRoutes` were simply omitted from that protection.

### Impact Explanation
An unauthenticated attacker with network access to the node's admin/UI HTTP port can request `GET /plugins/<name>/debug/pprof/heap`, `/goroutine`, `/profile`, etc., and receive raw memory/goroutine dumps from the named LOOP plugin process. Such dumps can contain sensitive in-memory data (e.g., decrypted key material, API tokens, internal state) handled by plugins (median, mercury, OCR relayers, etc.), constituting a secret/information-disclosure vulnerability reachable without any credentials.

### Likelihood Explanation
The precondition is simply network reachability to the node's web/API port and the presence of at least one registered LOOP plugin (`l.registry.Get(pluginName)` must succeed) — no session, API token, or role is required. This is a standard/common deployment configuration for nodes running LOOP plugins, making the issue highly reachable and repeatable via a single unauthenticated HTTP request.

### Recommendation
Wrap `loopRoutes` registration (or at minimum the `/plugins/:name/debug/pprof/*` and `/plugins/:name/debug/pprof/symbol` routes) with the same `auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateByToken, auth.AuthenticateBySession)` middleware used in `v2Routes`/`debugRoutes`, and consider restricting to admin role via `auth.RequiresAdminRole`, consistent with how `metricRoutes(authv2)` is protected.

### Proof of Concept
Integration test using `core/web/router.go`'s `NewRouter`:
1. Build the router with a mocked `chainlink.Application` and register a fake LOOP plugin in the `LoopRegistryServer`'s registry.
2. Issue `GET /plugins/<name>/debug/pprof/heap` with no session cookie and no `Authorization` header.
3. Assert the response status is `401`/`403` rather than `200` with pprof binary/text profile content.
4. Repeat for `POST /plugins/<name>/debug/pprof/symbol` and `GET /plugins/<name>/metrics`, `GET /discovery`.
5. Expected (failing) result on current code: handler executes and returns `200` with forwarded pprof data, confirming the bypass; after applying the fix, all requests should return `401 Unauthorized`.

```go
func (l *LoopRegistryServer) pluginPPROFHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/"+gc.Param("profile"), l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	l.logger.Infow("Forwarding plugin pprof request", "plugin", pluginName, "url", pluginURL)
	l.doRequest(gc, "GET", pluginURL, nil, timeout, pluginName)
}
```

```go
func (l *LoopRegistryServer) pluginPPROFPOSTSymbolHandler(gc *gin.Context) {
	pluginName := gc.Param("name")
	p, ok := l.registry.Get(pluginName)
	if !ok {
		gc.Data(http.StatusNotFound, "text/plain", fmt.Appendf(nil, "plugin %q does not exist", html.EscapeString(pluginName)))
		return
	}

	// unlike discovery, this endpoint is internal btw the node and plugin
	pluginURL := fmt.Sprintf("http://%s:%d/debug/pprof/symbol", l.loopHostName, p.EnvCfg.PrometheusPort)
	urlVals, timeout := pprofURLVals(gc)
	if s := urlVals.Encode(); s != "" {
		pluginURL += "?" + s
	}
	body, err := io.ReadAll(gc.Request.Body)
	if err != nil {
		gc.Data(http.StatusInternalServerError, "text/plain", fmt.Appendf(nil, "error reading plugin pprof request body: %s", err))
		return
	}
	l.doRequest(gc, "POST", pluginURL, bytes.NewReader(body), timeout, pluginName)
}
```
