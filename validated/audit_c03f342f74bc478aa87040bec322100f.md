### Title
Cross-tenant webhook impersonation via unauthenticated `X-Shopify-Shop-Domain` header not bound to HMAC - ([File: packages/apps/shopify-app-remix/src/server/authenticate/webhooks/authenticate.ts])

### Summary
`authenticateWebhookFactory` trusts the `X-Shopify-Shop-Domain` header (`check.domain`) to select which shop's offline session/access token to load, but the webhook HMAC only ever covers `rawBody`, never the headers. Because a single app's `apiSecretKey` signs webhooks for every shop that has installed it, any merchant who has installed the app can capture a genuinely valid `hmac`+`rawBody` pair from their own shop's webhook deliveries and resend it to the app's webhook endpoint with the domain header swapped to a different (victim) shop, causing the handler to run with the victim's real offline session/access token.

### Finding Description
`authenticateWebhookFactory` calls `api.webhooks.validate({rawBody, rawRequest: request})` and, if valid, immediately does `ensureValidOfflineSession(params, check.domain)` [1](#0-0) . The `domain` field of `check` comes straight from the `X-Shopify-Shop-Domain` header via `checkWebhooksHeaders`, with no cryptographic tie to the HMAC or body [2](#0-1) .

The HMAC check itself, `validateHmacFromRequestFactory`, only signs/verifies `rawBody`; it never includes any header (including domain) in the signed material: `validateHmacString(config, rawBody, hmac, format)` [3](#0-2) .

Since a Shopify app has one `apiSecretKey` shared across all shops that install it, a valid `(rawBody, hmac)` pair captured from a real webhook delivered to the attacker's own shop remains cryptographically valid when resent with an arbitrary `X-Shopify-Shop-Domain` value. `ensureValidOfflineSession`/`createOrLoadOfflineSession` then loads the session purely keyed by that attacker-controlled `shop` string with no further check [4](#0-3) [5](#0-4) , and the resulting `session`/`admin` client is handed to the app's webhook handler alongside the attacker's own payload content [6](#0-5) .

### Impact Explanation
An attacker who is merely a merchant that installed the target app on their own store can forge a "webhook" that the app processes as if it came from any other shop that also installed the app, executing the app's webhook business logic (which may include Admin API writes) using the victim shop's real offline access token while the actual event data/body originates from the attacker's own shop. This is a cross-tenant session/data confusion issue matching Shopify's "cross-tenant data/state access" impact class.

### Likelihood Explanation
Feasible and repeatable: the attacker only needs to install the target app on any shop they control (no special privilege, no stolen secret, default configuration since Shopify apps use one secret per app across all installs), capture one legitimate webhook delivery, and replay it with a different `X-Shopify-Shop-Domain` header value to the app's public webhook endpoint.

### Recommendation
Do not treat the `X-Shopify-Shop-Domain` header as authoritative on its own. Cross-validate the claimed domain against data embedded in the verified payload where possible, and/or require additional binding (e.g., re-deriving/confirming shop identity from a signed source, rate-limiting/anomaly detection per originating domain vs. known IPs, or maintaining a registry check that the resolved session's shop matches independently corroborated request context) before using `check.domain` to load another shop's offline session.

### Proof of Concept
```ts
// Jest-style PoC illustrating the confusion
it('cross-tenant impersonation via spoofed domain header with a genuinely valid HMAC', async () => {
  const rawBody = JSON.stringify({some: 'attacker-shop-A-data'});
  const validHmacForBodyFromShopA = hmac(shopify.config.apiSecretKey, rawBody); // same apiSecretKey signs all shops

  const forgedRequest = new Request(`${APP_URL}/webhooks`, {
    method: 'POST',
    body: rawBody,
    headers: webhookHeaders(rawBody, {
      'X-Shopify-Hmac-Sha256': validHmacForBodyFromShopA,
      'X-Shopify-Shop-Domain': 'shop-b.myshopify.com', // victim, not the shop that generated rawBody
    }),
  });

  const context = await shopify.authenticate.webhook(forgedRequest);

  // Vulnerable behavior: session/admin belong to shop-b even though rawBody came from shop A
  expect(context.shop).toBe('shop-b.myshopify.com');
  expect(context.session?.shop).toBe('shop-b.myshopify.com');
});
```

export function validateHmacFromRequestFactory(config: ConfigInterface) {
  return async function validateHmacFromRequest({
    type,
    rawBody,
    webhookType,
    ...adapterArgs
  }: ValidateParams): Promise<ValidationInvalid | ValidationValid> {
    const request = await abstractConvertRequest(adapterArgs);
    if (!rawBody.length) {
      return fail(ValidationErrorReason.MissingBody, type, config);
    }

    // Use appropriate header based on webhook type
    const hmacHeaderName = webhookType
      ? WEBHOOK_HEADER_NAMES[webhookType].hmac
      : ShopifyHeader.Hmac;

    const hmac = getHeader(request.headers, hmacHeaderName);
    if (!hmac) {
      return fail(ValidationErrorReason.MissingHmac, type, config);
    }
    const validHmac = await validateHmacString(
      config,
      rawBody,
      hmac,
      HashFormat.Base64,
    );
    if (!validHmac) {
      return fail(ValidationErrorReason.InvalidHmac, type, config);
    }

    return succeed(type, config);
  };

import {AppDistribution, BasicParams} from '../types';

export async function createOrLoadOfflineSession(
  {api, config, logger}: BasicParams,
  shop: string,
) {
  if (config.distribution === AppDistribution.ShopifyAdmin) {
    logger.debug('Creating custom app session from configured access token', {
      shop,
    });
    return api.session.customAppSession(shop);
  } else {
    logger.debug('Loading offline session from session storage', {shop});
    const offlineSessionId = api.session.getOfflineId(shop);
    const session = await config.sessionStorage!.loadSession(offlineSessionId);

    return session;
  }
}

import {BasicParams} from '../types';

import {createOrLoadOfflineSession} from './create-or-load-offline-session';
import {ensureOfflineTokenIsNotExpired} from './ensure-offline-token-is-not-expired';

export async function ensureValidOfflineSession(
  params: BasicParams,
  shop: string,
) {
  const session = await createOrLoadOfflineSession(params, shop);

  if (!session) return undefined;

  return ensureOfflineTokenIsNotExpired(session, params, shop);
}
