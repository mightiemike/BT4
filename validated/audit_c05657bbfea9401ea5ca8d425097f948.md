### Title
Retroactive interest catch-up when `accrue` pause is lifted causes theft of unclaimed yield - (File: `mainnet/contracts/vault/v0-vault-usdc.clar` and equivalent `v0-vault-*.clar` files)

### Summary
Every vault contract (`v0-vault-usdc.clar`, `v0-vault-sbtc.clar`, `v0-vault-stx.clar`, `v0-vault-usdh.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`) implements interest accrual via `accrue`, which is gated by a `pause-states` flag named `accrue` [1](#0-0) . When the `accrue` pause flag is set, `accrue` passes through without reverting and, critically, does **not** advance `last-update` [2](#0-1) . When the flag is later cleared, the next `accrue` call computes `time-delta` as `stacks-block-time - last-update`, which spans the entire paused interval plus any pre-pause/post-pause active time, causing the interest index (`index`/`lindex`) to jump by an amount corresponding to time during which accrual was supposed to be frozen.

### Finding Description
The index growth is computed in `next-index` / `next-liquidity-index`:
```
(time-delta (- stacks-block-time (var-get last-update)))
(multiplier (if (is-eq time-delta u0) INDEX-PRECISION (calc-multiplier-delta rate time-delta ...)))
``` [3](#0-2) 

`last-update` is a single data-var bound at the last time `accrue` actually mutated state [4](#0-3) . The value is invalidated (should be reset) the moment accrual is administratively paused, because from that point forward no interest should accumulate. However, `accrue`'s paused branch is a pure pass-through that skips the `var-set last-update` line entirely:
```
(if (get accrue states)
    ;; PAUSED: Pass-through without reverting
    (ok { index: idx, lindex: lidx })
    ;; NOT PAUSED: Normal accrual logic
    (let (...) ... (var-set last-update stacks-block-time) ...))
``` [5](#0-4) 

Because `last-update` is never advanced while paused, the later use of `last-update` in `next-index`/`next-liquidity-index` after the pause is lifted retroactively counts the entire paused duration as active accrual time. This is a single-transaction/single-call analog of the reported reward-restart bug class: a value (`last-update`, standing in for "reward interval boundary") is bound once, the pause event that should invalidate/reset it does not, and the later index computation blindly uses the stale difference, stitching the inactive interval into the active accrual window.

`accrue` is invoked from essentially every state-changing entry point (`system-borrow`, `system-repay`, `deposit`, `redeem`, etc.) via `(u (try! (accrue)))` [6](#0-5) , so as soon as one post-pause transaction triggers `accrue`, the retroactive catch-up interest is minted into the index in one shot.

### Impact Explanation
The catch-up multiplier increases both `index` (borrower cumulative debt, via `calc-cumulative-debt`) and `lindex` (liquidity/exchange-rate index), and mints extra `treasury-lp` reserve share proportional to the erroneously-computed `debt-delta` [7](#0-6) . Borrowers are charged interest for a period administrators intentionally froze, and a reserve cut of that unearned interest is minted to `.dao-treasury`. This is theft/misallocation of unclaimed yield: value is extracted from borrowers (who owe interest for time that shouldn't accrue) and diverted into `lindex`-based depositor claims and treasury `zft` minting that do not correspond to any real economic accrual — matching the in-scope "theft of unclaimed yield" impact class.

### Likelihood Explanation
This requires only an administrative pause/unpause cycle of the `accrue` flag (a normal operational lever, not a compromise) followed by any ordinary user transaction that calls `accrue` (deposit, redeem, borrow, repay). No attacker collusion or two-user interference is needed — a single caller triggering `accrue` after unpause is sufficient to realize the mis-accrued interest. This makes it highly likely to occur any time the protocol pauses and resumes accrual, which is a documented pause lever (`pause-states.accrue`) rather than a rare edge case.

### Recommendation
When the `accrue` pause is engaged, reset `last-update` to `stacks-block-time` at the moment of pausing (or at minimum, at unpause time before falling through to normal accrual), so that the time-delta used by `next-index`/`next-liquidity-index` never spans the paused interval. Equivalently, `accrue`'s pass-through branch should itself advance `last-update` on every call so no gap accumulates.

### Proof of Concept
1. At time `t0`, `accrue` runs normally; `last-update = t0`.
2. DAO/admin sets `pause-states.accrue = true` at time `t1`.
3. Between `t1` and `t2`, any number of `deposit`/`borrow`/`redeem` calls occur; each calls `accrue`, which hits the paused branch and returns `{index: idx, lindex: lidx}` without touching `last-update` [2](#0-1) .
4. At time `t2`, admin sets `pause-states.accrue = false`.
5. At time `t3 > t2`, any user calls e.g. `redeem`, which internally calls `accrue`. `next-index` computes `time-delta = t3 - t0` (still `t0`, since it was never updated), applying the interest rate over the full `[t0, t3]` span instead of only `[t0, t1] ∪ [t2, t3]` [8](#0-7) .
6. The resulting `debt-delta`/`reserve-inc` mints extra `treasury-lp` and inflates `index`/`lindex` for the paused interval `[t1, t2]`, which should have contributed zero accrual.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))

                false)

                false)
