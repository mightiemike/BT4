### Title
`accrue()` pass-through-when-paused lets vault operations proceed on stale indexes instead of reverting - ([File: mainnet/contracts/vault/v0-vault-usdh.clar])

### Summary
### Finding Description
Every vault contract (`v0-vault-usdh.clar`, `v0-vault-sbtc.clar`, `v0-vault-stx.clar`, `v0-vault-usdc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, and their `local-testing` equivalents) implements `accrue()` with an explicit "pause pass-through" branch:

```
(if (get accrue states)
    ;; PAUSED: Pass-through without reverting
    (ok { index: idx, lindex: lidx })
    ;; NOT PAUSED: Normal accrual logic
    (let (...) ... (ok { index: next, lindex: nliq })))
``` [1](#0-0) 

When the `accrue` pause flag is set, this function does **not** revert - it silently returns the last-committed `index`/`lindex` (`ok {...}`) instead of the current, correctly-accrued values, and skips updating `last-update`, minting treasury shares, etc. Every caller in `market.clar` / `v0-4-market.clar` treats this `ok` response as valid, fresh data because they call `accrue-and-cache`/`vault-accrue` unconditionally through `try!`, with no check on whether accrual was actually skipped:

```
(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))
    (match cached?
      cached-indexes (ok cached-indexes)
      (let ((indexes (try! (vault-accrue aid))))
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
``` [2](#0-1) 

This is functionally analogous to the Lens `FollowNFT::tryMigrate()` bug: a restriction that is correctly enforced on the "normal" path (a reverting pause check would block stale-data use) is bypassed on an alternate path (the pause branch quietly returns success instead of erroring), and every downstream consumer (`borrow`, `repay`, `liquidate`, health checks, LTV math) inherits the stale/incorrect state within the same transaction because it trusts the `ok` response.

### Impact Explanation
Because the pause is meant to freeze interest accrual/index updates (e.g., during an incident or migration), but `borrow`, `repay`, `collateral-add/remove`, and `liquidate` in `market.clar` all continue to execute using the frozen, stale `index`/`lindex` values (since `accrue()` returns `ok` rather than `err`), users can continue to borrow, repay, and have their debt/collateral valued at outdated indexes while the vault is supposed to be paused. Debt or collateral valuation performed against stale indexes while genuine index movement is suppressed can result in incorrect debt accounting or collateral valuation (e.g., borrowing/repaying at a frozen index while real economic interest has continued to accrue), producing a temporary freezing/mis-accounting of funds until the pause is lifted and a true accrual reconciles the difference - falling under "temporary freezing of funds" (or under adversarial use, mis-priced positions that let a user extract value they should not yet be entitled to).

### Likelihood Explanation
This requires only a single transaction against a paused vault with an outstanding position (borrow/repay/liquidate call), no DAO compromise, no cross-user interference, and no flashloan mechanics - the pause flag is a normal, intended DAO/admin operational lever (`set-pause-states`), and its ordinary use (pausing accrual, e.g. before a market parameter change) directly triggers the pass-through path. This is a single-block, single-actor condition reachable any time `accrue` pause is active.

### Recommendation
Change the paused branch of `accrue()` in all vault contracts to return an explicit error (e.g., `ERR-PAUSED`) rather than `(ok {...})` with stale values, so that callers in `market.clar`/`v0-4-market.clar` (`accrue-and-cache`, `accrue-user-debts`, `accrue-user-collateral`, `borrow`, `repay`, `liquidate`, `collateral-add`/`collateral-remove`) correctly abort via `try!`/`unwrap!` instead of silently proceeding on frozen indexes.

### Proof of Concept
1. DAO/admin calls `set-pause-states` on a vault (e.g. `v0-vault-usdh`) with `accrue: true`. [3](#0-2) 
2. A user with an existing debt position on that vault calls `market.clar::borrow` or `repay` or `liquidate`.
3. Internally, `accrue-and-cache` → `vault-accrue` → the vault's `accrue()` hits the paused branch and returns `(ok { index: idx, lindex: lidx })` with the OLD (frozen) index instead of reverting. [4](#0-3) 
4. `market.clar` treats this as a valid, current accrual result (via `try!`), and proceeds to compute debt/collateral notionals, health checks, and settlement using the stale index - completing the borrow/repay/liquidation in the same transaction as if the vault were not paused at all.
5. Because the top-level call still returns `(ok ...)`, the transaction succeeds and commits, defeating the intent of the `accrue` pause flag.
