### Title
Missing declared-class check in Starknet OS `execute_replace_class` allows undeclared class hash to be committed - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall omits the "class must be declared" check that the Rust Blockifier enforces for the exact same syscall during real transaction execution. An unprivileged contract can call `replace_class_syscall` with an arbitrary, undeclared class hash; the Blockifier (which builds/validates the block) rejects such a call, but the OS re-execution/proving path (which is supposed to faithfully reproduce and prove the same state transition) has no such guard and simply writes the arbitrary class hash into `contract_state_changes`.

### Finding Description
The bug-class hint from the external report is: a restriction/validation check exists on one code path but is missing on an equivalent code path that performs the same state-changing operation, letting an unauthorized action complete.

In this repository, the `replace_class` syscall is implemented twice:

1. In the Rust Blockifier (used for real transaction execution when the sequencer builds/validates blocks), the deprecated (Cairo0) syscall handler explicitly checks that the target class hash is declared before mutating state: [1](#0-0) 
```
fn replace_class(...) -> DeprecatedSyscallResult<ReplaceClassResponse> {
    // Ensure the class is declared (by reading it).
    syscall_handler.state.get_compiled_class(request.class_hash)?;
    syscall_handler.state.set_class_hash_at(syscall_handler.storage_address, request.class_hash)?;
    Ok(ReplaceClassResponse {})
}
```
This is also exercised in tests confirming that replacing with an undeclared class hash fails with "is not declared": [2](#0-1) 

2. In the Starknet OS's Cairo implementation, used to *re-execute and prove* the same block, the equivalent function has no such check — it is explicitly flagged as missing via a TODO: [3](#0-2) 
```
let class_hash = request.class_hash;

// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
local state_entry: StateEntry*;
%{ GetContractAddressStateEntry %}

tempvar new_state_entry = new StateEntry(
    class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
);

dict_update{dict_ptr=contract_state_changes}(
    key=contract_address,
    prev_value=cast(state_entry, felt),
    new_value=cast(new_state_entry, felt),
);
```
The Cairo0 (deprecated) OS execution path has the identical omission: [4](#0-3) 

Because this update happens inside `contract_state_changes` (a Cairo dict that is later committed via the Patricia tree update logic and constrained only by the Cairo program's own assertions), and because the class-hash value is fed in via a hint (`GetContractAddressStateEntry`) without an in-circuit `is_declared` assertion, the OS has no cryptographic guarantee that `class_hash` corresponds to an actually-declared class. This is exactly the class of bug described in the report: one enforcement point (Blockifier / "CentrifugeRouter"-analog) checks the restriction, while the parallel enforcement point (Starknet OS / "PoolManager"-analog) does not, allowing the unauthorized state mutation to go through unchecked on that path.

### Impact Explanation
The Starknet OS is the component whose Cairo execution trace is proven and verified to attest that a claimed state transition (and resulting state root/block hash) is correct. If the OS's `execute_replace_class` accepts and commits an undeclared class hash into a contract's state entry without validation, a prover can produce a valid STARK proof for a block whose committed state contains a contract pointing to a class hash that was never declared — a state that the Blockifier itself would never have produced (it reverts such a call). This is a wrong-committed-root / honest-node-divergence class issue: the value used for the Patricia tree update and final state commitment is not properly constrained, so the OS's accepted state diff can diverge from what correct, restriction-respecting execution (as enforced by the Blockifier) would produce for the identical transaction. Any subsequent call into that contract (in the same or later block) that depends on `get_compiled_class(class_hash)` for that address would either fail unpredictably in the OS or behave inconsistently with a Blockifier-based full node, since the compiled class does not exist.

### Likelihood Explanation
The syscall is reachable from any unprivileged contract via a normal `replace_class_syscall` call inside an ordinary account/contract invocation — no special privileges are required. The vulnerable code path is not gated behind any feature flag; it is the default `execute_replace_class` implementation exercised whenever a transaction containing a `replace_class` syscall is re-executed/proven by the Starknet OS, which happens for every block.

### Recommendation
Add an explicit assertion in `execute_replace_class` (both the Cairo1 path in `syscall_impls.cairo` and the deprecated Cairo0 path in `deprecated_execute_syscalls.cairo`) that verifies the given `class_hash` corresponds to a declared class before writing the new `StateEntry`, mirroring the check already performed by the Blockifier's Rust `replace_class` handler (`state.get_compiled_class(request.class_hash)?`). This should use an in-circuit lookup/assertion (not merely a hint) so the check is actually enforced by the proof, consistent with how declared-class checks are done elsewhere in the OS (e.g., for `deploy`/`library_call`).

### Proof of Concept
1. Deploy account contract `A` with class hash `C_A` (declared).
2. From `A`, invoke a contract function that calls `replace_class_syscall(class_hash=X)` where `X` is a class hash that has never been declared on-chain.
3. Blockifier (sequencer execution/validation): the call fails with "... is not declared" (as shown by the existing test `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash`), so a correct block never contains this state transition.
4. Starknet OS re-execution/proving (`execute_replace_class` in `syscall_impls.cairo`): no equivalent check exists; the `contract_state_changes` dict is updated to set `A`'s `class_hash` to `X` and a `CHANGE_CLASS_ENTRY` revert-log entry is appended, without validating that `X` is declared — demonstrating the enforcement asymmetry between the two execution paths.

func execute_replace_class{contract_state_changes: DictAccess*, revert_log: RevertLogEntry*}(
    contract_address, syscall_ptr: ReplaceClass*
) {
    alloc_locals;
    let class_hash = syscall_ptr.class_hash;

    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
