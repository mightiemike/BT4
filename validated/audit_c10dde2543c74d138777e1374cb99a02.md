## Title
Unbounded, underpriced per-cycle reward computation loop in `MortgageService`/`VoteRewardUtil` can cause disproportionate node processing cost relative to the fixed fee/energy charged - (File: `chainbase/src/main/java/org/tron/core/service/MortgageService.java`)

## Summary
The Otter Audits finding describes an unbounded loop over `approved_application_ids` in a payout function that could exceed the gas limit of a single transaction. The closest reachable analog in java-tron is the DPoS reward-withdrawal path: `MortgageService.withdrawReward()` / `VoteRewardUtil.withdrawReward()` compute a voter's reward by iterating from the account's `beginCycle` to the current maintenance cycle, and for the legacy (“old”) reward algorithm this iteration is a literal `for (cycle = begin; cycle < end; cycle++)` loop, nested with another loop over the account's vote list, performing store reads on every iteration.

None of the enclosing actuators/processors (`VoteWitnessActuator`, `UnfreezeBalanceV2Processor`, `WithdrawRewardProcessor`) charge fee/energy proportional to `currentCycle - beginCycle`; the `WithdrawRewardProcessor.execute()` simply calls `VoteRewardUtil.withdrawReward()` and applies a flat balance transfer: [7](#0-6) 

This mirrors the reported bug class: work performed inside a single transaction/call scales with an unbounded, attacker/user-influenced quantity (the number of elapsed maintenance cycles since the account last interacted, and the number of witnesses it voted for), while the price charged for that transaction (bandwidth/energy or the fixed native-contract cost) does not scale with that quantity.

## Impact Explanation
An account that votes for the maximum allowed number of witnesses (`MAX_VOTE_NUMBER`, see `VoteWitnessActuator`) and then remains dormant for a long time (many maintenance cycles, which recur roughly every few hours) accumulates a large gap between `beginCycle` and `currentCycle`. If that dormant state predates `newRewardAlgorithmEffectiveCycle` (i.e., `allowOldRewardOpt()` optimization does not cover the whole range), any subsequent permissionless transaction that triggers `withdrawReward` (vote, freeze/unfreeze, explicit withdraw, or the TVM `withdrawReward()` opcode) forces the processing node to execute the O(cycles × votes) loop with repeated store reads, without a corresponding increase in the resource fee charged. Because this code executes inside `processTransaction`/`applyBlock` - the deterministic, consensus-critical block-processing path - every full node and witness validating the block must redo this expensive computation, which can slow block processing/validation. This is analogous to the "out of gas"/underpriced-work class in the report: unbounded work not reflected in the price paid for it.

## Likelihood Explanation
Exploitability depends on: (1) how large `currentCycle - beginCycle` can practically become before the account is touched again, (2) whether `allowOldRewardOpt()` is enabled network-wide (converting the old O(cycles) loop into the O(votes) `RewardViCalService` computation), and (3) whether accumulation of a large gap requires meaningfully more effort/cost than the resulting extra work imposes on nodes. I was not able to fully confirm from the available index whether `allowOldRewardOpt` has been enabled for all cycles on current mainnet (which would make the `getOldReward` per-cycle loop effectively dead code for new activity), nor whether there is any other cap limiting `endCycle - beginCycle` growth. This uncertainty limits confidence that the impact is currently exploitable to a meaningful degree in production, versus being residual, largely-dormant legacy code.

## Recommendation
- Confirm whether `allowOldRewardOpt()` is permanently enabled for the entire historical cycle range on mainnet; if any account can still fall into the `beginCycle < newAlgorithmCycle` branch, either backfill/migrate those accounts' `beginCycle` or ensure `getOldReward`'s cost is bounded (e.g., cap the maximum number of cycles processed per call, or force periodic incremental settlement so multi-year gaps cannot accumulate).
- Charge energy/bandwidth for `vote`, `unfreezeBalanceV2`, and `withdrawReward` actions proportional to `currentCycle - beginCycle` (and vote-list size) when the legacy loop path is taken, so the fee reflects actual node work.
- Add an explicit upper bound on how many un-settled cycles a single call is permitted to reconcile at once, forcing callers to "catch up" incrementally rather than in one unbounded pass.

  private long computeReward(long cycle, List<Pair<byte[], Long>> votes) {
    long reward = 0;
    for (Pair<byte[], Long> vote : votes) {
      byte[] srAddress = vote.getKey();
      long totalReward = delegationStore.getReward(cycle, srAddress);
      if (totalReward <= 0) {
        continue;
      }
      long totalVote = delegationStore.getWitnessVote(cycle, srAddress);
      if (totalVote == DelegationStore.REMARK || totalVote == 0) {
        continue;
      }
      long userVote = vote.getValue();
      double voteRate = (double) userVote / totalVote;
      reward += voteRate * totalReward;
    }
    return reward;
  }

  private long computeReward(long beginCycle, long endCycle, AccountCapsule accountCapsule) {
    if (beginCycle >= endCycle) {
      return 0;
    }

    long reward = 0;
    long newAlgorithmCycle = dynamicPropertiesStore.getNewRewardAlgorithmEffectiveCycle();
    List<Pair<byte[], Long>> srAddresses = accountCapsule.getVotesList().stream()
        .map(vote -> new Pair<>(vote.getVoteAddress().toByteArray(), vote.getVoteCount()))
        .collect(Collectors.toList());
    if (beginCycle < newAlgorithmCycle) {
      long oldEndCycle = min(endCycle, newAlgorithmCycle,
          dynamicPropertiesStore.disableJavaLangMath());
      reward = getOldReward(beginCycle, oldEndCycle, srAddresses);
      beginCycle = oldEndCycle;
    }
    if (beginCycle < endCycle) {
      for (Pair<byte[], Long>  vote : srAddresses) {
        byte[] srAddress = vote.getKey();
        BigInteger beginVi = delegationStore.getWitnessVi(beginCycle - 1, srAddress);
        BigInteger endVi = delegationStore.getWitnessVi(endCycle - 1, srAddress);
        BigInteger deltaVi = endVi.subtract(beginVi);
        if (deltaVi.signum() <= 0) {
          continue;
        }
        long userVote = vote.getValue();
        reward += deltaVi.multiply(BigInteger.valueOf(userVote))
            .divide(DelegationStore.DECIMAL_OF_VI_REWARD).longValue();
      }
    }
    return reward;
  }

  public static void withdrawReward(byte[] address, Repository repository) {
    if (!VMConfig.allowTvmVote()) {
      return;
    }
    AccountCapsule accountCapsule = repository.getAccount(address);
    long beginCycle = repository.getBeginCycle(address);
    long endCycle = repository.getEndCycle(address);
    long currentCycle = repository.getDynamicPropertiesStore().getCurrentCycleNumber();
    long reward = 0;
    if (beginCycle > currentCycle || accountCapsule == null) {
      return;
    }
    if (beginCycle == currentCycle) {
      AccountCapsule account = repository.getAccountVote(beginCycle, address);
      if (account != null) {
        return;
      }
    }
    if (beginCycle + 1 == endCycle && beginCycle < currentCycle) {
      AccountCapsule account = repository.getAccountVote(beginCycle, address);
      if (account != null) {
        reward = computeReward(beginCycle, endCycle, account, repository);
        adjustAllowance(address, reward, repository);
        reward = 0;
      }
      beginCycle += 1;
    }
    endCycle = currentCycle;
    if (CollectionUtils.isEmpty(accountCapsule.getVotesList())) {
      repository.updateBeginCycle(address, endCycle + 1);
      return;
    }
    if (beginCycle < endCycle) {
      reward += computeReward(beginCycle, endCycle, accountCapsule, repository);
      adjustAllowance(address, reward, repository);
    }
    repository.updateBeginCycle(address, endCycle);
    repository.updateEndCycle(address, endCycle + 1);
    repository.updateAccountVote(address, endCycle, accountCapsule);
  }

  public long execute(WithdrawRewardParam param, Repository repo) throws ContractExeException {
    byte[] ownerAddress = param.getOwnerAddress();

    VoteRewardUtil.withdrawReward(ownerAddress, repo);

    AccountCapsule accountCapsule = repo.getAccount(ownerAddress);
    long oldBalance = accountCapsule.getBalance();
    long allowance = accountCapsule.getAllowance();
    long newBalance = 0;

    try {
      newBalance = LongMath.checkedAdd(oldBalance, allowance);
    } catch (ArithmeticException e) {
      logger.debug(e.getMessage(), e);
      throw new ContractExeException(e.getMessage());
    }

    // If no allowance, do nothing and just return zero.
    if (allowance <= 0) {
      return 0;
    }

    accountCapsule.setInstance(accountCapsule.getInstance().toBuilder()
        .setBalance(newBalance)
        .setAllowance(0L)
        .setLatestWithdrawTime(param.getNowInMs())
        .build());

    repo.updateAccount(accountCapsule.createDbKey(), accountCapsule);
    return allowance;
  }
