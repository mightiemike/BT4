### Title
Truncating division in `CalculateGasCost` can round the payload-execution gas fee to zero, letting users receive free UEA/CEA EVM execution paid for by validators - (File: x/uexecutor/keeper/fees.go)

### Summary
`CalculateGasCost` unwraps the `feemarket` base fee (a fractional `LegacyDec`) into whole `upc` units using a raw `big.Int` division (`baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`) before multiplying by `gasUsed`. If the current base fee is below 1 whole `upc` (a state the EIP-1559-style fee market can legitimately reach after a sustained run of below-target blocks, since it adjusts multiplicatively rather than clamping to an integer floor), the division truncates to zero, `effectiveGasPrice` becomes `0`, and the resulting `gasCost` is `0` regardless of how much gas the user's UEA/CEA payload actually consumed. This is the same class of bug as the reported Lido issue: a rounding/truncation step that can legitimately return zero where a positive value should have been charged, and the code path that consumes it has no explicit guard against a zero result being "correct."

### Finding Description
`CalculateGasCost` in [1](#0-0)  converts the `feemarket` base fee from its internal 18-decimal `LegacyDec` representation to a whole-`upc` `big.Int` via integer division: [2](#0-1) 

The accompanying comment asserts "the base fee is always a whole number of upc -- no fractional upc exists," but this is not enforced anywhere in scoped code: the `feemarket` base fee is a `LegacyDec` that is adjusted multiplicatively block-by-block (EIP-1559-style), so it can genuinely settle below `1.0` `upc` after a sustained period of below-target gas usage — there is no code in this repository establishing an integer/whole-unit floor for it. When that happens, `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` truncates to `0`, so `effectiveGasPrice = 0` and `gasCost = effectiveGasPrice * gasUsedBig = 0` at [3](#0-2) .

This value flows directly into `DeductGasFeesFromReceipt`, which is the sole fee-collection mechanism for gas consumed by module-originated (`DerivedEVMCall`) UEA/CEA payload execution triggered by inbound cross-chain messages — it is not covered by the normal Cosmos ante-handler fee deduction path: [4](#0-3) 

Because the function explicitly treats a non-positive `gasCost` as "nothing to charge" (`if gasCost.Sign() <= 0 { return nil }`), a zero result from truncation is indistinguishable from a legitimately free/zero-gas execution, and `DeductAndBurnFees` (which burns the deducted `upc`) is simply skipped: [5](#0-4) 

### Impact Explanation
While this window persists (base fee < 1 `upc`), every inbound UEA/CEA payload execution that actually consumes real EVM gas on Push Chain is charged and burned `0 upc`, even though `receipt.GasUsed` is nonzero and real compute/state resources were consumed by validators. This is a corruption of gas-fee accounting reachable purely from ordinary user cross-chain deposits/payloads (in-scope impact: "corruption of ... gas fee accounting ... reachable from ordinary user deposits, payloads, contracts"). An attacker can submit unlimited computation-heavy payloads for free during this window, draining validator resources with no compensating fee burn, which is economically equivalent to unauthorized value extraction from the protocol/validator set.

### Likelihood Explanation
This is not directly attacker-triggerable in a single transaction; it requires the network-wide `feemarket` base fee to first decay under 1 `upc`, which happens naturally after a sustained run of below-target block utilization (no privileged action needed — it can occur on a low-traffic chain, e.g., shortly after genesis or during any quiet period, since the fee market decreases multiplicatively with no code-enforced integer floor). Once that state is reached, exploitation is trivial and free for any unprivileged user who submits payload-executing inbound messages, and the leak persists on every payload execution until traffic pushes the base fee back above 1 `upc`.

### Recommendation
Do not silently truncate the base fee to a whole `upc` value. Either:
1. Keep gas-cost computation entirely in `LegacyDec`/fixed-point arithmetic and round the final `gasCost` (not the intermediate price) using ceiling rounding so a positive `gasUsed` always yields a positive charge, or
2. Explicitly reject/round up (`Ceil()`) when `baseFeeBig` truncates to zero but the underlying `LegacyDec` value is nonzero, ensuring `gasCost` can only be exactly zero when `gasUsed == 0`.
Additionally, treat `gasCost == 0` with `gasUsed > 0` as an error condition to catch this rather than silently skipping the burn.

### Proof of Concept
1. Let the network's `feemarket` base fee decay (via normal EIP-1559-style multiplicative decrease over consecutive below-target blocks) until its `LegacyDec` value is, e.g., `0.4` `upc` (internally represented as `4*10^17`).
2. A user submits (or has relayed via honest UVs) an inbound message causing a UEA/CEA payload execution; `receipt.GasUsed` is, say, `50,000`.
3. `CalculateGasCost` computes `baseFeeBig.Div(4*10^17, 1*10^18) = 0`, so `effectiveGasPrice = 0` and `gasCost = 0 * 50000 = 0`.
4. `DeductGasFeesFromReceipt` sees `gasCost.Sign() <= 0` and returns `nil` without calling `DeductAndBurnFees` — see [6](#0-5) .
5. The user's smart account is never debited/burned any `upc` despite the module having performed real EVM execution consuming 50,000 gas.

```go
func (k Keeper) DeductAndBurnFees(ctx context.Context, from sdk.AccAddress, gasCost *big.Int) error {
	amt := sdkmath.NewIntFromBigInt(gasCost)
	coin := sdk.NewCoin(pchaintypes.BaseDenom, amt)

	k.Logger().Debug("deducting and burning fees",
		"from", from.String(),
		"gas_cost", gasCost.String(),
		"denom", pchaintypes.BaseDenom,
	)

	err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, from, types.ModuleName, sdk.NewCoins(coin))
	if err != nil {
		return err
	}

	return k.bankKeeper.BurnCoins(ctx, types.ModuleName, sdk.NewCoins(coin))
}
```

```go
func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))
```

```go
func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}
```
