### Title
Starknet OS `execute_replace_class` accepts undeclared class hashes, enabling silent permanent bricking of a contract - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS Cairo implementation of the `REPLACE_CLASS` syscall commits a new `class_hash` to a contract's state entry without verifying that the class hash corresponds to a declared class. The Rust `blockifier` (used by the sequencer to build blocks) enforces this check, but the Cairo OS program (the canonical execution spec used for re-execution/proving) does not, creating a validation gap that lets a contract's class pointer be permanently set to a nonexistent class.

### Finding Description
`execute_replace_class` in `syscall_impls.cairo` reads the requested `class_hash` and immediately writes it into `contract_state_changes` for the calling contract, with an explicit acknowledgment that the declared-class check is missing: [1](#0-0) 

The same gap exists in the deprecated syscall path: [2](#0-1) 

This is inconsistent with the Rust `blockifier`, which is supposed to implement identical semantics to the Cairo OS but explicitly guards against this exact case. The deprecated syscall handler reads the compiled class (which fails with an "undeclared" error if not declared) before allowing the class swap: [3](#0-2) 

And the modern Cairo1 syscall path is proven (by test) to reject undeclared class hashes with an explicit error: [4](#0-3) 

The Starknet OS Cairo program is the ground-truth specification of Starknet execution — it is what gets re-executed and proven for L1 finality, and it is also directly executed by non-blockifier flows such as the "virtual OS" runner in `starknet_transaction_prover`, which builds `VirtualOsBlockInput` and feeds transactions straight into OS execution: [5](#0-4) 

Because the OS's `execute_replace_class` omits the "class must be declared" check that the Rust blockifier enforces, any code path that relies on the OS's own execution semantics (rather than the blockifier's Rust guard) will accept a `replace_class` syscall targeting an undeclared class hash.

### Impact Explanation
Any contract that implements an upgrade pattern via the `replace_class` syscall (a very common and encouraged Starknet pattern, directly analogous to the OptiFi "program upgrade error" that bricked the program and froze $661K) can have its class hash swapped to a hash for which no compiled class/CASM was ever declared. Once a contract's `class_hash` points to an undeclared class:
- The contract becomes permanently non-functional: no entry point can be resolved for a class that was never declared/compiled, so every subsequent call to the contract (including any recovery/undo call, since the "recovery" logic would also require the contract to execute) fails.
- Any funds or state held by that contract are permanently frozen/inaccessible — this is a direct funds-freezing outcome matching "Operation error" causing an irrecoverable program shutdown, mirroring the OptiFi loss.
- If this omitted check causes the OS-produced state root to diverge from what the Rust blockifier would compute/allow, it also creates the class of bug called out by the validation rules: a wrongly committed root/state or honest-node divergence between the two execution engines that are meant to be semantically identical.

### Likelihood Explanation
The path is reachable via a completely ordinary, unprivileged flow: any contract that calls the `replace_class` syscall with an unchecked or attacker-influenced `class_hash` argument (e.g., a proxy/upgradeable contract with a bug allowing a caller to supply the target class hash) will hit this code when executed through the OS's own syscall implementation. Given `replace_class`-based upgradability is a standard Starknet pattern and the OS is the canonical/authoritative execution engine used for proving (and directly used by virtual-OS execution flows), the missing guard is easily triggered by a single transaction from an ordinary sender/contract, with no special privileges required.

### Recommendation
Add the same "class must be declared" validation present in the Rust blockifier (`state.get_compiled_class(class_hash)?` equivalent) to both `execute_replace_class` in `syscall_impls.cairo` and the deprecated `execute_replace_class` in `deprecated_execute_syscalls.cairo`, by asserting the requested `class_hash` exists in `compiled_class_facts`/is a recognized declared class before mutating `contract_state_changes`. This closes the TODO left in the code and restores semantic parity between the OS and the blockifier.

### Proof of Concept
1. Deploy a Cairo1 contract with an external entry point that calls the `replace_class` syscall with a caller-supplied `class_hash` that has never been declared (analogous to `test_replace_class` in the feature contracts, but without any declare step for the target class). [6](#0-5) 
2. In a flow that executes via the Starknet OS Cairo program directly (e.g. the virtual-OS/prover path in `starknet_transaction_prover`) rather than through the blockifier's Rust guard, invoke this entry point with an arbitrary undeclared `class_hash`.
3. Observe that `execute_replace_class` in `syscall_impls.cairo` performs no declared-class check (per the TODO at line 902) and updates the contract's `StateEntry.class_hash` unconditionally, whereas the equivalent blockifier Rust path (`crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash`) would reject the same call with an "is not declared" error.
4. Any subsequent call into the contract now fails permanently because no compiled class exists for the new hash, demonstrating irrecoverable loss of contract functionality/funds analogous to the OptiFi incident.

    contract_address, syscall_ptr: ReplaceClass*

    let class_hash = syscall_ptr.class_hash;

    fn replace_class(
        request: ReplaceClassRequest,
        _vm: &mut VirtualMachine,
        syscall_handler: &mut Self,
    ) -> DeprecatedSyscallResult<ReplaceClassResponse> {
        // Ensure the class is declared (by reading it).
        syscall_handler.state.get_compiled_class(request.class_hash)?;
        syscall_handler

            .set_class_hash_at(syscall_handler.storage_address, request.class_hash)?;

    pub(crate) async fn create_virtual_os_hints(
        execution_data: VirtualBlockExecutionData,
        classes_provider: &C,
        storage_proofs_provider: &S,
        storage_proof_config: &StorageProofConfig,
        txs: Vec<(InvokeTransaction, TransactionHash)>,
    ) -> Result<OsHints, RunnerError> {
        // Extract chain info from block context.
        let chain_info = execution_data.base_block_info.block_context.chain_info();
        let os_chain_info = OsChainInfo {
            chain_id: chain_info.chain_id.clone(),
            strk_fee_token_address: chain_info.fee_token_addresses.strk_fee_token_address,
        };

        // Extract block number from base block info for storage proofs.
        let block_number = execution_data.base_block_info.block_context.block_info().block_number;

        // Fetch classes and storage proofs in parallel.
        let (classes, storage_proofs) = tokio::join!(
            classes_provider.get_classes(&execution_data.executed_class_hashes),
            storage_proofs_provider.get_storage_proofs(
                block_number,
                &execution_data,
                storage_proof_config
            )
        );
        let classes = classes?;
        let storage_proofs = storage_proofs?;

        // Convert execution outputs to CentralTransactionExecutionInfo.
        let tx_execution_infos =
            execution_data.execution_outputs.into_iter().map(|output| output.0.into()).collect();

        // The extended_initial_reads from storage proofs already has class_hashes, nonces,
        // and storage values. We just need to add compiled class hashes from the classes provider.
        let mut extended_initial_reads = storage_proofs.extended_initial_reads;

        // Add class hash to compiled class hash mappings from the classes provider.
        extended_initial_reads
            .compiled_class_hashes
            .extend(&classes.class_hash_to_compiled_class_hash);

        // Must clear declared_contracts: the OS calls `update_cache` with an empty class map
        // (it receives compiled classes separately in `compiled_classes`), which would fail
        // an assertion if declared_contracts is non-empty.
        extended_initial_reads.declared_contracts.clear();

        // Assemble VirtualOsBlockInput.
        let virtual_os_block_input = VirtualOsBlockInput {
            contract_state_commitment_info: storage_proofs
                .commitment_infos
                .contracts_trie_commitment_info,
            address_to_storage_commitment_info: storage_proofs
                .commitment_infos
                .storage_tries_commitment_infos,
            contract_class_commitment_info: storage_proofs
                .commitment_infos
                .classes_trie_commitment_info,
            chain_info: os_chain_info,
            transactions: txs,
            tx_execution_infos,
            block_info: execution_data.base_block_info.block_context.block_info().clone(),
            raw_starknet_version: execution_data.base_block_info.raw_starknet_version,
            initial_reads: extended_initial_reads,
            base_block_hash: execution_data.base_block_info.base_block_hash,
            base_block_header_commitments: execution_data
                .base_block_info
                .base_block_header_commitments,
            prev_base_block_hash: execution_data.base_block_info.prev_base_block_hash,
            compiled_classes: classes.compiled_classes,
        };

        // Return OsHints.
        Ok(virtual_os_block_input.into())
    }
