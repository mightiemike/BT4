## Title
Starknet OS `execute_replace_class` omits declared-class existence check, causing OS/Blockifier execution divergence - (File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo)

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall updates a contract's class hash in `contract_state_changes` without ever verifying that the target `class_hash` corresponds to a declared class. The Rust blockifier — which is the engine that actually builds/executes blocks in the sequencer — performs this exact check. This asymmetry mirrors the reported bug class: a check that guarantees a referenced artifact ("finalShnarf" in the report, "declared class" here) actually exists was omitted from the path that commits the state change, letting a transaction succeed where it should have been rejected.

### Finding Description
In `execute_replace_class` (the Cairo-1 syscall handler used by the Starknet OS to re-execute transactions), the class hash from the syscall request is written straight into the new `StateEntry` with no existence check: [1](#0-0) 

The `TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment on line 902 explicitly acknowledges the missing check.

The deprecated (Cairo0) syscall path has the identical gap, with no check and no TODO comment at all: [2](#0-1) 

By contrast, the Rust blockifier — the engine that actually executes transactions when the sequencer builds a block — enforces this check via `self.state.get_compiled_class(class_hash)?` before allowing the class replacement, returning `StateError::UndeclaredClassHash` if the class isn't declared: [3](#0-2) 
The corresponding deprecated (Cairo0) hint processor in blockifier likewise enforces the check by reading the class before setting it: [4](#0-3) 

This is confirmed by tests that assert the blockifier rejects `replace_class` to an undeclared hash with an `"is not declared"` error: [5](#0-4) 

Because a Cairo contract can catch a syscall failure (e.g., via `Result` matching on `replace_class_syscall`) instead of letting it propagate to a full transaction revert, the observable execution path taken by a contract differs depending on whether it is executed by blockifier (which raises an error at this point) or by the Starknet OS (which silently succeeds, since it lacks the check). The OS is the component responsible for independently re-executing transactions to produce and prove the canonical state diff/commitment, so this divergence directly affects what state changes the OS computes and commits versus what the sequencer's blockifier actually executed.

### Impact Explanation
An account contract can invoke `replace_class_syscall` (or the deprecated equivalent) with a class hash that has never been declared, and catch/handle the resulting error inside its own Cairo logic. Blockifier will reject the class replacement at that point (an `UndeclaredClassHash` error is produced and the calling contract's error-handling branch executes), while the Starknet OS re-execution of the identical bytecode has no such check and will unconditionally accept the replacement, writing the undeclared class hash into `contract_state_changes`. This produces divergent state transitions (and hence divergent state roots) between the sequencer's actual block execution and the OS's independent re-execution/proof of that same block — a wrong/incorrect committed state root, directly matching the "honest-node divergence / wrong committed root" impact class.

### Likelihood Explanation
Any unprivileged account contract deployed on the network can trigger this by calling `replace_class_syscall` (Cairo1) or the deprecated `replace_class` syscall (Cairo0) with an arbitrary, never-declared class hash and handling the syscall result rather than letting it bubble up as a hard revert. No special privileges, operator/prover collusion, or network-level attack is required — a normal transaction sender reaches this code path directly through ordinary contract execution.

### Recommendation
Add the missing declared-class existence check in the Starknet OS's `execute_replace_class` (both the current syscall implementation in `syscall_impls.cairo` and the deprecated path in `deprecated_execute_syscalls.cairo`), mirroring the blockifier's check (i.e., verify the class hash appears in `contract_class_changes`/declared-classes state before writing the new `StateEntry`), and revert/fail the syscall exactly as blockifier does when the class is undeclared, so both execution engines agree on all outcomes.

### Proof of Concept
1. Deploy an account/contract that calls `starknet::replace_class_syscall(undeclared_class_hash)` and wraps the call so it can observe/handle the `Result::Err` (e.g., using `try_replace_class` style error catching similar to the pattern used in `fuzz_revert.cairo`'s `Scenario::ReplaceClass` combined with `handle_error_catch`, as seen in the feature-contract test resources: `syscalls::library_call_syscall(...)` / `self.handle_error_catch(result, should_unwrap);` style handling).
2. Submit the transaction; blockifier executes it, hits `get_compiled_class(class_hash)` in `replace_class` in `syscall_base.rs`, returns `UndeclaredClassHash`, and the contract's error-handling branch runs (no class replacement occurs, execution continues down the "error" path).
3. When the Starknet OS independently re-executes the same transaction/bytecode for proving, `execute_replace_class` in `syscall_impls.cairo` performs no such check, so the "success" branch is taken and `contract_state_changes` is updated with the undeclared class hash — a different code path and different resulting state than what blockifier actually computed, yielding a divergent state commitment.

        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
