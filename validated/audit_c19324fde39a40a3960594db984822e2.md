### Title
Missing per-account brute-force protection for OIDC local admin fallback login allows unlimited password guessing via distributed source IPs - ([File: core/sessions/oidcauth/oidc.go])

### Summary
The OIDC authentication provider's local admin fallback (`localLoginFallback` in `core/sessions/oidcauth/oidc.go`) validates credentials via a simple hash comparison with no per-account attempt counter or lockout mechanism. The only brute-force mitigation is the global unauthenticated rate limiter applied in `core/web/router.go`, which is keyed by source IP address rather than by targeted account, so an attacker using multiple source IPs can perform effectively unbounded password guesses against a known/fixed local admin email.

### Finding Description
`SessionsController.Create` (`core/web/sessions_controller.go:29-68`) binds the JSON request and calls `sc.App.AuthenticationProvider().CreateSession(ctx, sr)` directly. [1](#0-0) 

When `AuthenticationMethod=oidc`, `CreateSession` in `core/sessions/oidcauth/oidc.go` delegates straight to `localLoginFallback`, which performs a `SELECT ... FROM users WHERE ...` lookup and `utils.CheckPasswordHash(sr.Password, string(user.HashedPassword))`, returning `"invalid password"` on mismatch with no counting, delay, or lockout state tracked per email/account. [2](#0-1) 

The only gate in front of this endpoint is `sessionRoutes`, which applies a rate limiter scoped to `/sessions` using `rl.UnauthenticatedPeriod()`/`rl.Unauthenticated()` (defaults: 5 requests / 20s). [3](#0-2) 

This limiter is built via `rateLimiter()`, which wraps `github.com/ulule/limiter/v3` with an in-memory store and the `mgin` gin middleware adapter — the default key extraction for this middleware is the client's remote IP address, not the target account/email in the request body. [4](#0-3) 

Because the rate limit bucket is keyed by source IP (and `engine.RemoteIPHeaders = nil` means only the real TCP peer address is trusted, not a spoofable header) [5](#0-4) , an attacker controlling multiple source IPs (e.g., a botnet, VPN/proxy rotation, or cloud IP pool) can issue 5 guesses per IP per 20s indefinitely against the same fixed admin email, with the per-account attempt count being fully unbounded across the distributed set of source addresses. There is no code path anywhere in `oidc.go` that tracks failed attempts per email or introduces an account lockout/backoff, mirroring the identical gap in `core/sessions/ldapauth/ldap.go`'s `localLoginFallback`.

### Impact Explanation
An attacker who knows (or guesses, since default/admin emails are commonly documented or predictable) the local admin account's email can eventually brute-force the password given enough distributed source IPs, since the only defense is a per-IP request-rate ceiling and not a per-account lockout. Successful compromise of the local admin account yields full administrative control of the Chainlink node's UI/API (job management, bridge configuration, key/wallet-adjacent administrative actions), which is a privileged account takeover.

### Likelihood Explanation
Exploitation requires: (1) `AuthenticationMethod=oidc` with local admin fallback configured (the same fallback path always exists for OIDC/LDAP deployments), (2) knowledge of the admin email (frequently a well-known default or discoverable), and (3) access to a sufficiently large pool of distinct source IPs to bypass the per-IP rate limiter — a nontrivial but realistic capability for a motivated unprivileged network attacker (e.g. via botnet or commercial proxy services), especially against a weak/short admin password. The bottleneck is IP diversity, not attempts against the target account, so the attack scales linearly with attacker resources rather than being capped by the application.

### Recommendation
Add per-account (per-email) brute-force protection independent of source IP, e.g. a failed-login counter with exponential backoff or temporary lockout stored against the account (in `users` table or an in-memory/keyed limiter using the normalized email as the key) inside `localLoginFallback` in both `core/sessions/oidcauth/oidc.go` and `core/sessions/ldapauth/ldap.go`. Consider combining IP-based and account-based rate limiting so that requests are throttled by whichever dimension is hit first, and emit/alert on repeated failed attempts via the existing `audit.AuthLoginFailedPassword` audit event.

### Proof of Concept
Integration test plan (extends the existing `TestSessions_RateLimited` pattern in `core/web/router_test.go`):
1. Start an app with `AuthenticationMethod=oidc`/`local` and a known admin user/email.
2. Simulate distributed brute force: for N simulated "client IPs" (e.g., by directly invoking `oidcAuthenticator.CreateSession`/`ldapAuthenticator.CreateSession` in a loop bypassing the gin rate-limiter middleware, or by faking `RemoteAddr` per request through direct handler invocation), send more than `rl.Unauthenticated()` password guesses per simulated IP against the *same* fixed admin email with different passwords.
3. Assert: despite each individual IP being capped at the configured `Unauthenticated`/`UnauthenticatedPeriod` threshold, the cumulative count of failed attempts against the single admin email across all simulated IPs exceeds any reasonable per-account bound (e.g., > 50 attempts) and the account is never locked out.
4. Expected (failing) assertion demonstrating the bug: no lockout/backoff state exists for the account, and a subsequent correct-password request still succeeds regardless of how many prior failed attempts were made against that email — i.e., there is no mechanism that would have blocked a successful guess after N failures, only IP-scoped throttling as shown by `core/web/router_test.go:127-156`. // localLoginFallback tests the credentials provided against the 'local' authentication method
// This covers the case of local CLI API calls requiring local login separate from the OIDC server
func (oi *oidcAuthenticator) localLoginFallback(ctx context.Context, sr clsessions.SessionRequest) (clsessions.User, error) {
	var user clsessions.User
	err := oi.ds.GetContext(ctx, &user, SQLSelectUserbyEmail, sr.Email)
	if err != nil {
		return user, err
	}
	if !constantTimeEmailCompare(strings.ToLower(sr.Email), strings.ToLower(user.Email)) {
		oi.auditLogger.Audit(audit.AuthLoginFailedEmail, map[string]any{"email": sr.Email})
		return user, errors.New("invalid email")
	}

	if !utils.CheckPasswordHash(sr.Password, string(user.HashedPassword)) {
		oi.auditLogger.Audit(audit.AuthLoginFailedPassword, map[string]any{"email": sr.Email})
		return user, errors.New("invalid password")
	}

	return user, nil
}

	}

func sessionRoutes(app chainlink.Application, r *gin.RouterGroup) {
	config := app.GetConfig()
	rl := config.WebServer().RateLimit()
	unauth := r.Group("/", rateLimiter(
		rl.UnauthenticatedPeriod(),
		rl.Unauthenticated(),
	))
	sc := NewSessionsController(app)
	unauth.POST("/sessions", sc.Create)
	auth := r.Group("/", auth.Authenticate(app.AuthenticationProvider(), auth.AuthenticateBySession))
	auth.DELETE("/sessions", sc.Destroy)
}

func TestSessions_RateLimited(t *testing.T) {
	t.Parallel()

	ctx := t.Context()
	app := cltest.NewApplicationEVMDisabled(t)
	require.NoError(t, app.Start(ctx))

	router := web.Router(t, app, nil)
	ts := httptest.NewServer(router)

	client := clhttptest.NewTestLocalOnlyHTTPClient()
	input := `{"email":"brute@force.com", "password": "wrongpassword"}`

	for range 5 {
		request, err := http.NewRequestWithContext(ctx, "POST", ts.URL+"/sessions", bytes.NewBufferString(input))
		require.NoError(t, err)

		resp, err := client.Do(request)
		require.NoError(t, err)
		assert.Equal(t, http.StatusUnauthorized, resp.StatusCode)
	}

	request, err := http.NewRequestWithContext(ctx, "POST", ts.URL+"/sessions", bytes.NewBufferString(input))
	require.NoError(t, err)

	resp, err := client.Do(request)
	require.NoError(t, err)

}
