### Title
Direct calls to `__execute__` can bypass the `block_direct_execute_call` protection via the `library_call` syscall - (File: crates/blockifier/src/execution/syscalls/hint_processor.rs, crates/blockifier/src/execution/native/syscall_handler.rs, crates/apollo_starknet_os_program/.../execution/syscall_impls.cairo)

### Summary
The reported bug class is: an internal/alternate code path that performs the same effective operation as a validated entry point is missing the checks enforced by that entry point (JOJO's `withdraw(isInternal=true)` bypassing the `isDepositAllowed` check that `deposit` enforces). The Starknet sequencer has a structurally identical gap: the `call_contract` syscall enforces `maybe_block_direct_execute_call` (rejecting calls whose selector is `__execute__`), but the `library_call` (delegate call) syscall — which can invoke the exact same entry point code — has no equivalent check, in any of the three implementations (Cairo1 VM, Cairo-Native, and the SNOS Cairo re-execution program).

### Finding Description
`call_contract` explicitly forbids invoking the account's `__execute__` entry point directly: [1](#0-0) 
This is enforced in the Cairo1 VM syscall handler's `call_contract`: [2](#0-1) 
in the Cairo-Native handler's `call_contract`: [3](#0-2) 
in the deprecated (Cairo0) `call_contract`: [4](#0-3) 
and in the SNOS Cairo re-execution program's deprecated syscall dispatcher: [5](#0-4) 

However, the `library_call` syscall (a delegate-call that runs another class's code against the caller's own storage/context) implements no such check in any of these four places:
- Cairo1 VM `library_call`: [6](#0-5) 
- Cairo-Native `library_call`: [7](#0-6) 
- Deprecated (Cairo0) `execute_library_call`: [8](#0-7) 
- SNOS Cairo re-execution `execute_library_call` (new syscalls) and `execute_library_call_syscall` (deprecated syscalls): [9](#0-8) [10](#0-9) 

Because a `library_call` preserves the caller's own `caller_address` and `storage_address` unchanged (`// The call context remains the same in a library call.`), calling `__execute__` of an arbitrary declared class via `library_call` from within a contract's own external entry point executes that class's `__execute__` logic with the *original* (often zero) `caller_address` and with the *invoker's own storage*. This means the standard account guard `assert(get_caller_address().is_zero(), 'INVALID_CALLER')` inside `__execute__` implementations is satisfied, so protected `__execute__` logic runs even though the blockifier explicitly tries to prevent any direct invocation of `__execute__` outside of the OS's controlled transaction-execution flow.

### Impact Explanation
`block_direct_execute_call` is a protocol-level invariant meant to guarantee that `__execute__` can only ever run as the top-level, OS-driven step of the corresponding transaction (after `__validate__`, with fee/nonce/resource accounting already fixed for that call). Bypassing this via `library_call` lets any contract cause a nested/duplicate execution of an `__execute__` entry point mid-call, inconsistent with the accounting and revert-log invariants the OS/blockifier rely on for that guard (as evidenced by the dedicated regression tests asserting this exact restriction, e.g. `test_direct_execute_call`, `test_call_execute_directly`). Since the same bug class (bypassing a protective check by using an alternate syscall path with identical effective capability) caused High severity impact in the reference report, and here it defeats a security guard that is implemented consistently across `call_contract`/blocked in three parallel execution engines (VM, Native, SNOS) but omitted from the parallel `library_call` path in all of them, this is a genuine correctness/invariant violation reachable from a single unprivileged transaction.

### Likelihood Explanation
Any contract deployer can write a contract whose external entry point issues a `library_call_syscall` targeting a declared account class hash and selector `__execute__`; this requires no special privileges — only a normal `invoke` transaction from any account, calling any own/other contract that performs the `library_call`. No operator, prover, or p2p cooperation is required, and the path is present in production execution (Cairo1 VM, Cairo-Native) as well as the Starknet OS re-execution program used for proving.

### Recommendation
Apply `maybe_block_direct_execute_call` (or the deprecated equivalent selector check against `EXECUTE_ENTRY_POINT_SELECTOR`/`EXECUTE_ENTRY_POINT_NAME`) inside the `library_call` implementations in `crates/blockifier/src/execution/syscalls/hint_processor.rs`, `crates/blockifier/src/execution/native/syscall_handler.rs`, `crates/blockifier/src/execution/deprecated_syscalls/hint_processor.rs`, and the corresponding `execute_library_call`/`execute_library_call_syscall` functions in the SNOS Cairo program, mirroring the check already present in each engine's `call_contract`.

### Proof of Concept
1. Declare/deploy a contract `Attacker` with an external entry point `run()` that calls `library_call_syscall(class_hash=<some account class>, function_selector=selector!("__execute__"), calldata=[...])`.
2. Submit an `INVOKE` transaction whose top-level call target is `Attacker::run`.
3. Trace execution: `call_contract`'s guard (`maybe_block_direct_execute_call` / `DirectExecuteCall` / `assert_not_equal(..., EXECUTE_ENTRY_POINT_SELECTOR)`) is never reached because the syscall used is `library_call`, not `call_contract`; the target class's `__execute__` code executes with `caller_address` inherited from `Attacker::run`'s own context (commonly zero at top level), satisfying the account's `INVALID_CALLER` guard, so `__execute__` runs despite `versioned_constants.block_direct_execute_call` being enabled — contradicting the invariant enforced (and tested) for the `call_contract` path (`test_direct_execute_call`, `crates/blockifier/src/execution/syscalls/syscall_tests/call_contract.rs:297-344`; `crates/starknet_os_flow_tests/src/tests.rs:2737-2775`).

    fn library_call(
        request: LibraryCallRequest,
        vm: &mut VirtualMachine,
        syscall_handler: &mut Self,
        remaining_gas: &mut u64,
    ) -> Result<LibraryCallResponse, Self::Error> {
        let entry_point = CallEntryPoint {
            class_hash: Some(request.class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: request.function_selector,
            calldata: request.calldata,
            // The call context remains the same in a library call.
            storage_address: syscall_handler.storage_address(),
            caller_address: syscall_handler.caller_address(),
            call_type: CallType::Delegate,
            // NOTE: this value might be overridden later on.
            initial_gas: *remaining_gas,
        };

        let retdata_segment = execute_inner_call(entry_point, vm, syscall_handler, remaining_gas)
            .map_err(|error| match error {
            SyscallExecutionError::Revert { .. } => error,
            _ => error.as_lib_call_execution_error(
                request.class_hash,
                syscall_handler.storage_address(),
                request.function_selector,
            ),
        })?;

        Ok(LibraryCallResponse { segment: retdata_segment })
    }

// Implements the library_call syscall.
func execute_library_call{
    range_check_ptr,
    syscall_ptr: felt*,
    builtin_ptrs: BuiltinPointers*,
    contract_state_changes: DictAccess*,
    contract_class_changes: DictAccess*,
    revert_log: RevertLogEntry*,
    outputs: OsCarriedOutputs*,
}(block_context: BlockContext*, caller_execution_context: ExecutionContext*) {
    let request = cast(syscall_ptr + RequestHeader.SIZE, LibraryCallRequest*);
    let (success, remaining_gas) = reduce_syscall_base_gas(
        specific_base_gas_cost=LIBRARY_CALL_GAS_COST, request_struct_size=LibraryCallRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    // Prepare execution context.
    tempvar calldata_start = request.calldata_start;
    tempvar caller_execution_info = caller_execution_context.execution_info;
    tempvar execution_context: ExecutionContext* = new ExecutionContext(
        entry_point_type=ENTRY_POINT_TYPE_EXTERNAL,
        class_hash=request.class_hash,
        calldata_size=request.calldata_end - calldata_start,
        calldata=calldata_start,
        execution_info=new ExecutionInfo(
            block_info=caller_execution_info.block_info,
            tx_info=caller_execution_info.tx_info,
            caller_address=caller_execution_info.caller_address,
            contract_address=caller_execution_info.contract_address,
            selector=request.selector,
        ),
        deprecated_tx_info=caller_execution_context.deprecated_tx_info,
    );

    return contract_call_helper(
        remaining_gas=remaining_gas,
        block_context=block_context,
        execution_context=execution_context,
    );
}
