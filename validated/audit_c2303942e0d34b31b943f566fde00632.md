### Title
Any Account Can Grow a Victim's DelegatedResourceAccountIndex Without Limit or Consent, Causing Unbounded State Growth / Self-DoS - (File: actuator/src/main/java/org/tron/core/actuator/FreezeBalanceActuator.java, actuator/src/main/java/org/tron/core/actuator/DelegateResourceActuator.java)

### Summary
The external report describes a Snap where any (semi-trusted) dapp can unilaterally add addresses to a user's notification list without the user's consent or confirmation, leading to unbounded growth and a possible self-DoS. The analogous condition in java-tron is that any unprivileged account can broadcast a `DelegateResourceContract` / legacy `FreezeBalanceContract` (with `receiver_address` set) naming an arbitrary receiver address, and the actuator unconditionally appends the sender's address to that receiver's `DelegatedResourceAccountIndex.fromAccounts` list — with no consent, cap, or deduplication limit tied to the receiver's control.

### Finding Description
`FreezeBalanceActuator.delegateResource()` builds/updates a `DelegatedResourceAccountIndexCapsule` for both the owner and the receiver whenever a delegation transaction is processed: [1](#0-0) 

The receiver side of this — `receiverIndexCapsule.addFromAccount(ByteString.copyFrom(ownerAddress))` — is executed purely because the *sender* named that address as `receiver_address` in their own transaction. There is no requirement that the receiver approve, be notified, or have any relationship with the sender beyond being an existing account. [2](#0-1) 

The new-style delegate path (`DelegateResourceActuator` / `DelegateResourceProcessor`, used for `FreezeBalanceV2`-derived resources) exhibits the same pattern: the actuator/processor unconditionally updates the receiver's `DelegatedResourceAccountIndexStore` "to/from" index for whatever `receiver_address` the caller supplies, with the only real cost gate being that the *caller* must own frozen TRX (≥ 1 TRX) — not any check tied to the receiver's consent. [3](#0-2) [4](#0-3) 

A test (`testMultiFreezeDelegatedBalanceForBandwidth`) explicitly demonstrates that an owner's `toAccountsList` can be grown arbitrarily (100+ entries in the test) purely by repeated delegate transactions, confirming there is no protocol-level cap enforced on this list's length: [5](#0-4) 

Because this index is keyed per-account and stored/retrieved as a whole capsule (`DelegatedResourceAccountIndexStore.get`/`getWithPrefix`, which aggregates all matching prefix entries into one in-memory list), an attacker who creates many distinct addresses (each only needing the minimum 1 TRX frozen balance to originate a delegate transaction) can repeatedly delegate to a single victim address, causing the victim's `fromAccounts`/`fromAccountsList` to grow without bound: [6](#0-5) 

This index is directly exposed through public, unauthenticated RPC/HTTP endpoints (`GetDelegatedResourceAccountIndex`, `GetDelegatedResourceAccountIndexV2`, and their PBFT/Solidity node variants), meaning the growing state is both (a) unbounded on-chain storage per victim account, and (b) a large payload that must be constructed and returned by the node on every query.

### Impact Explanation
This mirrors the external report's core bug class: an unprivileged, "semi-trusted" actor can force additions to another party's tracked-address list with no confirmation step and no user-side control over the additions. In java-tron this translates into a state/DoS concern:
- Unbounded growth of `DelegatedResourceAccountIndex` records for a targeted victim account, increasing on-chain storage consumption tied to that account.
- Increased cost of `GetDelegatedResourceAccountIndex(V2)` RPC/HTTP calls for that account (larger prefix scans / larger response payloads), potentially degrading node performance when serving the victim's account data.
- No user-facing mechanism exists for the receiver to reject, prune, or otherwise manage entries that name them as a delegation target — analogous to the Snap's lack of address management/confirmation.

This is a resource/accounting-adjacent DoS concern rather than a fund-loss or consensus-divergence bug, since the actual resource (frozen TRX) still belongs to and is controlled by the delegating owner; the victim's TRON power/bandwidth/energy accounting is not corrupted, only the size and cost of maintaining/querying the association index.

### Likelihood Explanation
Likelihood is moderate: exploitation requires the attacker to control (or create) many distinct funded accounts, each with at least 1 TRX frozen (`TRX_PRECISION` minimum enforced in `DelegateResourceActuator.validate`), and to issue one delegate transaction per address targeting the same victim. This is inexpensive relative to most spam/DoS primitives on TRON (minimal TRX outlay, standard broadcast transaction, no special permission), making a sustained campaign against a specific victim account plausible for a motivated but low-privilege attacker.

### Recommendation
- Introduce a maximum size / cap on `DelegatedResourceAccountIndex.fromAccounts` and `toAccounts` (or move to a paginated store-scan model without holding an unbounded in-memory list) to bound the amount of unsolicited association data one victim account can accumulate.
- Consider deduplicating/capping index growth by (a) owner address diversity, (b) minimum aggregate delegate amount, or (c) rate-limiting the number of distinct delegators recorded per receiver per epoch.
- For RPC/HTTP retrieval (`GetDelegatedResourceAccountIndex(V2)`), add response size limits / pagination consistent with other list-returning endpoints (e.g., the existing `jsonRpcMaxAddressSize`-style guard used for JSON-RPC log filters) to avoid unbounded payload construction cost. [7](#0-6) 

### Proof of Concept
1. Create N distinct accounts, each funded with ≥ 1 TRX and freezing that TRX via `FreezeBalanceV2Contract` (or legacy `FreezeBalanceContract`) to obtain delegable bandwidth/energy.
2. From each of the N accounts, broadcast a `DelegateResourceContract` (or legacy delegated `FreezeBalanceContract`) with `receiver_address` set to the same victim address and the minimum delegate balance (1 TRX equivalent).
3. Each transaction causes `DelegateResourceActuator`/`FreezeBalanceActuator` to append the sending account's address into the victim's `DelegatedResourceAccountIndex.fromAccounts` list (as shown in `FreezeBalanceActuator.delegateResource` and the corresponding test `testMultiFreezeDelegatedBalanceForBandwidth`), with no interaction or consent from the victim.
4. Repeat with N large; the victim's `fromAccountsList`, retrievable via `GetDelegatedResourceAccountIndex`/`GetDelegatedResourceAccountIndexV2`, grows unbounded, increasing storage and query cost for that account with no way for the victim to prevent or clean up the entries.

  private void delegateResource(byte[] ownerAddress, byte[] receiverAddress, boolean isBandwidth,

    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicPropertiesStore = chainBaseManager.getDynamicPropertiesStore();
    DelegatedResourceStore delegatedResourceStore = chainBaseManager.getDelegatedResourceStore();
    DelegatedResourceAccountIndexStore delegatedResourceAccountIndexStore = chainBaseManager
        .getDelegatedResourceAccountIndexStore();

    // 1. unlock the expired delegate resource

    delegatedResourceStore.unLockExpireResource(ownerAddress, receiverAddress, now);

    if (lock) {
      expireTime = now + lockPeriod * BLOCK_PRODUCED_INTERVAL;
    }
    byte[] key = DelegatedResourceCapsule.createDbKeyV2(ownerAddress, receiverAddress, lock);
    DelegatedResourceCapsule delegatedResourceCapsule = delegatedResourceStore.get(key);

    } else {
      delegatedResourceCapsule.addFrozenBalanceForEnergy(balance, expireTime);
    }
    delegatedResourceStore.put(key, delegatedResourceCapsule);

    //modify DelegatedResourceAccountIndexStore
    delegatedResourceAccountIndexStore.delegateV2(ownerAddress, receiverAddress,
        dynamicPropertiesStore.getLatestBlockHeaderTimestamp());

  private void delegateResource(
      byte[] ownerAddress,
      byte[] receiverAddress,
      boolean isBandwidth,
      long delegateBalance,
      Repository repo) {
    //modify DelegatedResourceStore
    byte[] key = DelegatedResourceCapsule.createDbKeyV2(ownerAddress, receiverAddress, false);
    DelegatedResourceCapsule delegatedResourceCapsule = repo.getDelegatedResource(key);
    if (delegatedResourceCapsule == null) {
      delegatedResourceCapsule = new DelegatedResourceCapsule(
          ByteString.copyFrom(ownerAddress),
          ByteString.copyFrom(receiverAddress));
    }
    if (isBandwidth) {
      delegatedResourceCapsule.addFrozenBalanceForBandwidth(delegateBalance, 0);
    } else {
      delegatedResourceCapsule.addFrozenBalanceForEnergy(delegateBalance, 0);
    }

    //modify DelegatedResourceAccountIndex
    long now = repo.getDynamicPropertiesStore().getLatestBlockHeaderTimestamp();
    byte[] fromKey = Bytes.concat(
        DelegatedResourceAccountIndexStore.getV2_FROM_PREFIX(), ownerAddress, receiverAddress);
    DelegatedResourceAccountIndexCapsule toIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(receiverAddress));
    toIndexCapsule.setTimestamp(now);
    repo.updateDelegatedResourceAccountIndex(fromKey, toIndexCapsule);

    byte[] toKey = Bytes.concat(
        DelegatedResourceAccountIndexStore.getV2_TO_PREFIX(), receiverAddress, ownerAddress);
    DelegatedResourceAccountIndexCapsule fromIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(ownerAddress));
    fromIndexCapsule.setTimestamp(now);
    repo.updateDelegatedResourceAccountIndex(toKey, fromIndexCapsule);

    //update Account for receiver
    AccountCapsule receiverCapsule = repo.getAccount(receiverAddress);
    if (isBandwidth) {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForBandwidth(delegateBalance);
    } else {
      receiverCapsule.addAcquiredDelegatedFrozenV2BalanceForEnergy(delegateBalance);
    }
    repo.updateDelegatedResource(key, delegatedResourceCapsule);
    repo.updateAccount(receiverCapsule.createDbKey(), receiverCapsule);

  @Test
  public void testMultiFreezeDelegatedBalanceForBandwidth() {
    dbManager.getDynamicPropertiesStore().saveAllowDelegateResource(1);
    dbManager.getDynamicPropertiesStore().saveAllowDelegateOptimization(1L);
    dbManager.getDynamicPropertiesStore().saveLatestBlockHeaderTimestamp(10000L);
    long frozenBalance = 1_000_000_000L;
    long duration = 3;
    final int RECEIVE_COUNT = 100;
    String[] RECEIVE_ADDRESSES = new String[RECEIVE_COUNT + 1];

    DelegatedResourceAccountIndexCapsule ownerIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(
            ByteString.copyFrom(ByteArray.fromHexString(OWNER_ADDRESS)));
    for (int i = 0; i < RECEIVE_COUNT + 1; i++) {
      ECKey ecKey = new ECKey(Utils.getRandom());
      RECEIVE_ADDRESSES[i] = ByteArray.toHexString(ecKey.getAddress());
      if (i != RECEIVE_COUNT) {
        ownerIndexCapsule.addToAccount(ByteString.copyFrom(ecKey.getAddress()));
      }
    }
    dbManager.getDelegatedResourceAccountIndexStore().put(
        ByteArray.fromHexString(OWNER_ADDRESS), ownerIndexCapsule);
    AccountCapsule receiverCapsule =
        new AccountCapsule(
            ByteString.copyFromUtf8("receiver"),
            ByteString.copyFrom(ByteArray.fromHexString(RECEIVE_ADDRESSES[RECEIVE_COUNT])),
            AccountType.Normal,
            initBalance);
    dbManager.getAccountStore().put(receiverCapsule.getAddress().toByteArray(), receiverCapsule);

    TransactionResultCapsule ret = new TransactionResultCapsule();
    FreezeBalanceActuator actuator = new FreezeBalanceActuator();
    actuator.setChainBaseManager(dbManager.getChainBaseManager())
        .setAny(getDelegatedContractForBandwidth(
            OWNER_ADDRESS, RECEIVE_ADDRESSES[RECEIVE_COUNT], frozenBalance, duration));
    try {
      ownerIndexCapsule = dbManager
          .getDelegatedResourceAccountIndexStore().getIndex(ByteArray.fromHexString(OWNER_ADDRESS));
      List<ByteString> beforeList = ownerIndexCapsule.getToAccountsList();
      actuator.validate();
      actuator.execute(ret);

      //check DelegatedResourceAccountIndex convert
      ownerIndexCapsule = dbManager
          .getDelegatedResourceAccountIndexStore().get(ByteArray.fromHexString(OWNER_ADDRESS));
      Assert.assertNull(ownerIndexCapsule);

      ownerIndexCapsule = dbManager
          .getDelegatedResourceAccountIndexStore().getIndex(ByteArray.fromHexString(OWNER_ADDRESS));
      Assert.assertEquals(0, ownerIndexCapsule.getFromAccountsList().size());
      List<ByteString> tmpList = ownerIndexCapsule.getToAccountsList();
      Assert.assertEquals(RECEIVE_COUNT + 1, ownerIndexCapsule.getToAccountsList().size());
      for (int i = 0; i < RECEIVE_COUNT; i++) {
        Assert.assertEquals(beforeList.get(i), tmpList.get(i));
      }
      Assert.assertEquals(RECEIVE_ADDRESSES[RECEIVE_COUNT],
          ByteArray.toHexString(tmpList.get(RECEIVE_COUNT).toByteArray()));

  public DelegatedResourceAccountIndexCapsule getIndex(byte[] address) {
    DelegatedResourceAccountIndexCapsule indexCapsule = get(address);
    if (indexCapsule != null) {
      return indexCapsule;
    }
    return getWithPrefix(FROM_PREFIX, TO_PREFIX, address);
  }

  public DelegatedResourceAccountIndexCapsule getV2Index(byte[] address) {
    return getWithPrefix(V2_FROM_PREFIX, V2_TO_PREFIX, address);
  }

  private DelegatedResourceAccountIndexCapsule getWithPrefix(byte[] fromPrefix, byte[] toPrefix, byte[] address) {
    DelegatedResourceAccountIndexCapsule tmpIndexCapsule =
        new DelegatedResourceAccountIndexCapsule(ByteString.copyFrom(address));

    byte[] key = Bytes.concat(fromPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpToList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpToList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    List<ByteString> list = tmpToList.stream()
        .map(DelegatedResourceAccountIndexCapsule::getAccount).collect(Collectors.toList());
    tmpIndexCapsule.setAllToAccounts(list);

    key = Bytes.concat(toPrefix, address);
    List<DelegatedResourceAccountIndexCapsule> tmpFromList =
        new ArrayList<>(this.prefixQuery(key).values());
    tmpFromList.sort(Comparator.comparing(DelegatedResourceAccountIndexCapsule::getTimestamp));
    list = tmpFromList.stream().map(DelegatedResourceAccountIndexCapsule::getAccount).collect(
        Collectors.toList());
    tmpIndexCapsule.setAllFromAccounts(list);
    return tmpIndexCapsule;
  }
