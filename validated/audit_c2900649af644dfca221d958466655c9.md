## Title
Attacker-manipulable spot AMM quote used as slippage bound for gas-abstraction auto-swap enables price-manipulation drain of pooled WPC — (`File: x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The Morpho report shows how a stateful rate (`borrowRate`) computed from live, manipulable market state (utilization) can be trivially skewed when the underlying market has low liquidity, and how using that skewed rate for downstream accounting (`_accrueInterest`) causes fund loss. Push Chain's gas-abstraction auto-swap path (`ExecuteInboundGas` / `ExecuteInboundGasAndPayload` → `gasAndPayloadDepositAutoSwap`) has the same structural weakness: it derives a critical value (`minPCOut`, the swap's slippage floor) from a live, instantaneous Uniswap V2/V3-style spot quote (`GetSwapQuote` → `QuoterV2.quoteExactInputSingle`) with no TWAP, no minimum-liquidity check, and no independent floor — so a low-liquidity PRC20/WPC pool can be spot-manipulated in the same block to distort the amount of WPC (backing native PC) released from the pool per unit of deposited PRC20.

### Finding Description
When an inbound deposit of gas-token PRC20 is processed (a fully unprivileged, ordinary bridging action any user can trigger), the keeper:

1. Fetches the DEX quoter/WPC addresses and fee tier [1](#0-0) .
2. Calls `GetSwapQuote`, a simulated (`commit=false`) call into `QuoterV2.quoteExactInputSingle`, i.e. a pure spot-price read of whatever the pool's current reserves/tick happen to be at that exact block [2](#0-1) .
3. Derives `minPCOut = quote * 95 / 100` directly from that spot quote and immediately performs the real swap (`commit=true`) via `CallPRC20DepositAutoSwap`, using the pool's real-time price as both the expected output and its own slippage bound [3](#0-2) . The identical pattern is duplicated for the `GAS_AND_PAYLOAD` path in `gasAndPayloadDepositAutoSwap` [4](#0-3) .

Because the "reference rate" (`quote`) and the actual execution price come from the *same* manipulable pool state, and the slippage tolerance is computed *from* that same manipulated state rather than from an independent, time-resistant reference (TWAP, oracle price, or admin-configured floor), an attacker who thins out a low-liquidity PRC20/WPC pool (by swapping in the block immediately preceding the module's auto-swap call) can shift the spot price arbitrarily within that block. The 5% slippage window offers no protection because it is derived from the manipulated price itself — it only guards against price movement *between* the `GetSwapQuote` simulation and the `CallPRC20DepositAutoSwap` execution, not against the attacker having already set the pool to an unfavorable/favorable price before either call runs. This is exactly the class of bug in the report: a stateful, easily-skewed on-chain metric (utilization rate / spot AMM price) feeding directly into fund-affecting accounting without any check for sufficient depth/liquidity or resistance to short-term manipulation.

The deployment of PRC20 tokens and their liquidity pools is admin/governance controlled [5](#0-4) , but nothing in the scoped Go code prevents an unprivileged attacker from trading against a thinly-liquid pool for a legitimately whitelisted, low-volume token immediately before submitting (or having their own) inbound deposit processed, since inbound processing amount, source chain, and timing are all attacker-influenced through ordinary bridging.

### Impact Explanation
A successful manipulation directly corrupts PRC20/native asset accounting in the universal execution flow: the auto-swap releases an amount of pooled WPC (backing native PC) to the depositor's UEA that does not reflect the token's fair value, at the expense of the pool's liquidity providers / protocol-owned liquidity. Repeated exploitation against any low-liquidity registered token drains protocol-controlled value each time an inbound gas-abstraction deposit is executed — this is an unauthorized release of protocol-controlled funds reachable purely by ordinary users through the default inbound-deposit path, matching the in-scope impact "corruption of PRC20 or native asset accounting ... or unauthorized release ... of user or protocol-controlled funds."

### Likelihood Explanation
Likelihood depends on the existence of a low-liquidity PRC20/WPC pool for at least one whitelisted token and the attacker's ability to land a manipulating swap in the same block/ordering window as the module-triggered auto-swap. Both preconditions are realistic: new or low-volume PRC20 tokens are common early in a token's listing lifecycle, gas-abstraction auto-swaps are triggered automatically and deterministically by ordinary inbound deposits (fully attacker-controllable timing/amount), and there is no code-level minimum-liquidity guard or TWAP fallback to reject execution when the pool is thin.

### Recommendation
- Do not derive the slippage floor solely from the instantaneous quote of the same pool that will execute the swap. Use a TWAP-based reference price (or an independent oracle) to compute `minPCOut`, or enforce a protocol-configured maximum acceptable deviation from a longer-window reference price.
- Add an explicit minimum-liquidity/minimum-notional check before performing auto-swap via a given pool; skip or fail the auto-swap (falling back to a non-swap deposit path or reverting) when pool depth is below a safe threshold relative to the swap size.
- Consider capping the swap amount per block per token/pool, and/or requiring a real (non-zero) `deadline` bound tighter than "use contract default" to reduce the manipulation window.

### Proof of Concept
1. Identify a registered PRC20 token (via `x/uregistry` `TokenConfig.NativeRepresentation`) whose PRC20/WPC Uniswap-style pool has low liquidity.
2. In the block immediately preceding (or same block, ordered before) the target inbound deposit's execution, submit an ordinary EVM swap transaction against that pool to shift its spot price so that `QuoterV2.quoteExactInputSingle` returns an inflated WPC-per-PRC20 rate.
3. Trigger (or have already in flight) an inbound deposit of the target PRC20 token; `ExecuteInboundGas`/`ExecuteInboundGasAndPayload` calls `GetSwapQuote` against the now-manipulated pool [6](#0-5) , computes `minPCOut` from that inflated quote, and executes `CallPRC20DepositAutoSwap` at the still-manipulated price [7](#0-6) , releasing more WPC than the deposited PRC20 is worth.
4. Reverse the manipulating trade in a subsequent transaction/block to restore the price and realize the extracted value, having net-drained protocol/pool-owned WPC.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
