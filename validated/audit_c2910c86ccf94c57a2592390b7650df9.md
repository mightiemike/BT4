### Title
Byte-count based `many_ref_accounts_can_be_moved` check underestimates bin-packing fragmentation, letting multi-ref "newest alive" accounts be packed into a slot lower than their original slot - ([File: accounts-db/src/ancient_append_vecs.rs])

### Summary
`AccountsDb::many_ref_accounts_can_be_moved` decides whether accounts with `ref_count > 1` that are the "newest alive" copy of a pubkey can be safely relocated during ancient packing, using a crude `alive_bytes / ideal_storage_size` estimate of how many packed storages the moved data will occupy. `PackedAncientStorage::pack`, which actually performs the placement, uses simple sequential first-fit bin packing that can consume far more storages than that byte-based estimate whenever individual account sizes are chosen so that only one account fits per ideal-sized bin (e.g. slightly over half of `ideal_storage_size` each). Because the estimate can be off by close to 2x, the safety check can pass while the real packing places some multi-ref "newest" accounts into a target slot below their original slot (and possibly below another still-alive copy of the same pubkey), corrupting the "highest slot = newest" invariant used by loads/clean.

### Finding Description
`combine_ancient_slots_packed_internal` (`accounts-db/src/ancient_append_vecs.rs:417-518`) separates alive accounts per ancient slot into `one_ref`, `many_refs_this_is_newest_alive`, and `many_refs_old_alive` via `calc_accounts_to_combine` (`accounts-db/src/ancient_append_vecs.rs:784-926`, classification logic in `ShrinkCollectAliveSeparatedByRefs::add`, `accounts-db/src/accounts_db.rs:214-235`). Only `many_refs_old_alive` (an account whose alive slot-list entry is *not* the highest) is forced to stay in its original slot via `accounts_keep_slots`. The "newest alive" multi-ref accounts (`many_refs_this_is_newest_alive`) are allowed to be *moved* to any packed target slot, as long as `many_ref_accounts_can_be_moved` approves it: [1](#0-0) 

This function computes `required_ideal_packed = alive_bytes / ideal_storage_size + 1` — a pure byte-count estimate — and only verifies that every `many_refs_newest` account's original slot is `<=` the target slot found at index `target_slots_sorted.len() - required_ideal_packed`. It assumes that the real packer will need exactly `required_ideal_packed` storages to hold all the multi-ref "newest" data, and that these storages map onto the top `required_ideal_packed` (i.e., highest) target slots.

The actual placement is performed later by `PackedAncientStorage::pack`, a simple sequential first-fit packer: [2](#0-1) 

Because `pack` never splits an individual account and starts a new bin as soon as adding the next account would exceed `ideal_size` (`if new_size > ideal_size && bytes_total > 0 { full = true; break; }`), an attacker who crafts each aliased account's data size to be just over half of `ideal_storage_size` forces exactly one account per bin instead of the two the byte-based estimate assumes — i.e., up to ~2x more storages are consumed by the multi-ref "newest" data than `required_ideal_packed` accounted for.

`write_packed_storages` (`accounts-db/src/ancient_append_vecs.rs:646-701`) then zips the packed storages, in order (many-ref data first, since it's chained first in the `pack()` call at `accounts-db/src/ancient_append_vecs.rs:496-504`), against `target_slots_sorted.iter().rev()` — i.e., from highest slot down. If fragmentation causes the many-ref data to spill into more storages than the check assumed, some of that data lands in target slots *below* `target_slots_sorted[len - required_ideal_packed]`, i.e. below the `highest_slot` that `many_ref_accounts_can_be_moved` validated against, and potentially below the account's own original slot. Since ancient packing physically rewrites the account into the new target slot and the accounts index records the account's slot_list entry as `(target_slot, offset)` for the new location, this converts a "newest alive" account into one recorded at a *lower* slot number than another still-alive copy of the same pubkey (e.g. a `many_refs_old_alive` copy left untouched in `accounts_keep_slots`, or another moved account), breaking the "highest slot = newest" invariant that account loading and clean rely on.

The only other guard, `if pack.len() > accounts_to_combine.target_slots_sorted.len() { return; }` (`accounts-db/src/ancient_append_vecs.rs:506-509`), only aborts if the *total* storage count exceeds available target slots — it does not re-validate the ordering invariant that `many_ref_accounts_can_be_moved` was supposed to guarantee, so it does not catch this specific fragmentation-induced mis-ordering.

### Impact Explanation
This is a stale/wrong account version bug (silent balance/state divergence): after packing, `load()` at a rooted slot could return the older, superseded value of a pubkey instead of the value that was actually the most recent, because the previously-"newest" copy's recorded slot has been dropped below another copy's slot. This falls under the "stale or wrong-version account loads / silent balance change / hash-capitalization divergence" bounty category, since account hashing and snapshot hashes are derived from the account state accounts-db reports as the "current" one per pubkey.

### Likelihood Explanation
- Fully attacker-controlled preconditions: create/rewrite accounts under attacker-owned pubkeys, controlling data length precisely (to hit "just over half of `ideal_storage_size`" sizing) and controlling which slots they are rooted/flushed in.
- Requires the pubkey to remain aliased across at least two ancient-eligible slots (an old, un-cleaned copy plus a newer copy) at the moment `combine_ancient_slots_packed` runs — achievable by rewriting an account repeatedly across slots faster than `clean` catches up, or exploiting the normal window between flush/root and clean.
- `ideal_storage_size` is derived dynamically from total ancient alive bytes and `max_ancient_slots` (`collect_sort_filter_ancient_slots`, `accounts-db/src/ancient_append_vecs.rs:522-538`), which the attacker can influence by controlling how much data they store, making the "half of ideal size" targeting feasible with enough iteration/probing.
- No privileged access is required; this is reachable purely through normal user account creation/rewriting plus waiting for the ancient-packing background job to run (deterministic AccountsDb maintenance path, not validator/leader-specific).

### Recommendation
Replace the byte-count estimate in `many_ref_accounts_can_be_moved` with an actual simulation/dry-run of `PackedAncientStorage::pack` restricted to `many_refs_newest`, or compute a fragmentation-safe upper bound (e.g., account for indivisible-item bin packing by summing `ceil(each account's size / ideal_size)`-style worst case, or by directly running `pack()` once ahead of time and checking that the number of storages consumed by the many-ref portion, and the actual target slot each many-ref account is assigned to, is `>=` that account's original slot) before proceeding to `write_packed_storages`.

### Proof of Concept
```rust
// accounts-db/src/ancient_append_vecs.rs (tests module)
#[test]
fn test_many_ref_accounts_can_be_moved_underestimates_fragmentation() {
    let ideal_size = 1000u64;
    let tuning = PackedAncientStorageTuning {
        max_ancient_slots: 10_000,
        percent_of_alive_shrunk_data: 0,
        ideal_storage_size: NonZeroU64::new(ideal_size).unwrap(),
        can_randomly_shrink: false,
        ..default_tuning()
    };

    // Craft N "many_refs_newest" entries, each account sized just over half of
    // ideal_size, so only ONE fits per packed storage (first-fit fragmentation).
    let per_account_bytes = (ideal_size / 2 + 1) as usize;
    let n = 6;
    let many_refs_newest: Vec<AliveAccounts> = (0..n)
        .map(|i| AliveAccounts {
            slot: 100 + i as u64, // distinct original slots, ascending
            bytes: per_account_bytes,
            accounts: Vec::default(), // stand-in; real test needs real AccountFromStorage entries
        })
        .collect();

    // Byte-based estimate used by the check:
    let alive_bytes: usize = many_refs_newest.iter().map(|a| a.bytes).sum();
    let required_ideal_packed = (alive_bytes as u64 / ideal_size + 1) as usize;

    // Provide exactly `required_ideal_packed` target slots, all higher than
    // every many_refs_newest slot, so the (flawed) check passes.
    let target_slots_sorted: Vec<Slot> = (200..200 + required_ideal_packed as u64).collect();

    assert!(AccountsDb::many_ref_accounts_can_be_moved(
        &many_refs_newest,
        &target_slots_sorted,
        &tuning,
    ));

    // But real packing needs one storage PER account due to fragmentation:
    // (real accounts required to exercise PackedAncientStorage::pack directly;
    // this asserts the fragmentation property that breaks the estimate)
    let actual_storages_needed = n; // one bin per oversized-half account
    assert!(actual_storages_needed > required_ideal_packed,
        "fragmentation makes actual storage count exceed the byte-based estimate");

    // Consequence (to be demonstrated at the integration level):
    // with only `required_ideal_packed` (< n) target slots reserved as "safe",
    // write_packed_storages will assign the extra overflow storages to LOWER
    // target slots than target_slots_sorted[target_slots_sorted.len() - required_ideal_packed],
    // i.e. below the `highest_slot` validated by many_ref_accounts_can_be_moved,
    // and potentially below some many_refs_newest accounts' original slot.
}
```
An end-to-end invariant test should extend `test_shrink_packed_ancient`-style harnesses: create a pubkey aliased across slots s1 < s2 (s2 = many_refs_this_is_newest_alive, with data sized ~`ideal_storage_size/2 + 1`), repeat for several pubkeys/slots to force fragmentation, run `combine_ancient_slots_packed`, then assert `load(pubkey, max_root)` still returns the s2-originated value and that the account's post-pack slot in the index is `>= s2` for every such pubkey.

    fn many_ref_accounts_can_be_moved(
        many_refs_newest: &[AliveAccounts<'_>],
        target_slots_sorted: &[Slot],
        tuning: &PackedAncientStorageTuning,
    ) -> bool {
        let alive_bytes = many_refs_newest
            .iter()
            .map(|alive| alive.bytes)
            .sum::<usize>();
        let required_ideal_packed = (alive_bytes as u64 / tuning.ideal_storage_size + 1) as usize;
        if alive_bytes == 0 {
            // nothing required, so no problem moving nothing
            return true;
        }
        if target_slots_sorted.len() < required_ideal_packed {
            return false;
        }
        let i_last = target_slots_sorted
            .len()
            .saturating_sub(required_ideal_packed);

        let highest_slot = target_slots_sorted[i_last];
        many_refs_newest
            .iter()
            .all(|many| many.slot <= highest_slot)
    }

    fn pack(
        mut accounts_to_combine: impl Iterator<Item = &'a AliveAccounts<'a>>,
        ideal_size: NonZeroU64,
    ) -> Vec<PackedAncientStorage<'a>> {
        let mut result = Vec::default();
        let ideal_size: u64 = ideal_size.into();
        let ideal_size = ideal_size as usize;
        let mut current_alive_accounts = accounts_to_combine.next();
        // starting at first entry in current_alive_accounts
        let mut partial_inner_index = 0;
        // 0 bytes written so far from the current set of accounts
        let mut partial_bytes_written = Saturating(0);
        // pack a new storage each iteration of this outer loop
        loop {
            let mut bytes_total = 0usize;
            let mut accounts_to_write = Vec::default();

            // walk through each set of alive accounts to pack the current new storage up to ideal_size
            let mut full = false;
            while !full && current_alive_accounts.is_some() {
                let alive_accounts = current_alive_accounts.unwrap();
                if partial_inner_index >= alive_accounts.accounts.len() {
                    // current_alive_accounts have all been written, so advance to next set from accounts_to_combine
                    current_alive_accounts = accounts_to_combine.next();
                    // reset partial progress since we're starting over with a new set of alive accounts
                    partial_inner_index = 0;
                    partial_bytes_written = Saturating(0);
                    continue;
                }
                let bytes_remaining_this_slot =
                    alive_accounts.bytes.saturating_sub(partial_bytes_written.0);
                let bytes_total_with_this_slot =
                    bytes_total.saturating_add(bytes_remaining_this_slot);
                let mut partial_inner_index_max_exclusive;
                if bytes_total_with_this_slot <= ideal_size {
                    partial_inner_index_max_exclusive = alive_accounts.accounts.len();
                    bytes_total = bytes_total_with_this_slot;
                } else {
                    partial_inner_index_max_exclusive = partial_inner_index;
                    // adding all the alive accounts in this storage would exceed the ideal size, so we have to break these accounts up
                    // look at each account and stop when we exceed the ideal size
                    while partial_inner_index_max_exclusive < alive_accounts.accounts.len() {
                        let account = alive_accounts.accounts[partial_inner_index_max_exclusive];
                        let account_size = account.stored_size();
                        let new_size = bytes_total.saturating_add(account_size);
                        if new_size > ideal_size && bytes_total > 0 {
                            full = true;
                            // partial_inner_index_max_exclusive is the index of the first account that puts us over the ideal size
                            // so, save it for next time
                            break;
                        }
                        // this account fits
                        partial_bytes_written += account_size;
                        bytes_total = new_size;
                        partial_inner_index_max_exclusive += 1;
                    }
                }

                if partial_inner_index < partial_inner_index_max_exclusive {
                    // these accounts belong in the current packed storage we're working on
                    accounts_to_write.push((
                        alive_accounts.slot,
                        // maybe all alive accounts from the current or could be partial
                        &alive_accounts.accounts
                            [partial_inner_index..partial_inner_index_max_exclusive],
                    ));
                }
                // start next storage with the account we ended with
                // this could be the end of the current alive accounts or could be anywhere within that vec
                partial_inner_index = partial_inner_index_max_exclusive;
            }
            if accounts_to_write.is_empty() {
                // if we returned without any accounts to write, then we have exhausted source data and have packaged all the storages we need
                break;
            }
            // we know the full contents of this packed storage now
            result.push(PackedAncientStorage {
                bytes: bytes_total as u64,
                accounts: accounts_to_write,
            });
        }
        result
    }
