### Title
Auto-swap `minPCOut` slippage bound is derived from a spot Uniswap V3 quote with no TWAP protection, enabling sandwich extraction on `GAS_AND_PAYLOAD`/`GAS`-type inbound deposits - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/execute_inbound_gas_and_payload.go`)

### Summary
When an inbound crosschain deposit requires gas abstraction (`TxType_GAS`, `TxType_GAS_AND_PAYLOAD`), Push Chain auto-swaps the deposited PRC20 into the native gas token (WPC) via a Uniswap V3-style pool. The expected output and the slippage-protection floor (`minPCOut`) are both derived from a single spot quote fetched at execution time from `QuoterV2.quoteExactInputSingle`, which reads the pool's current price/liquidity state. This is the same bug class as the external report: a value read from manipulable AMM state (there, Uniswap reserves for vote power; here, Uniswap-style pool price for a fund-affecting swap) is used without any time-weighted-average protection.

### Finding Description
`GetSwapQuote` in [1](#0-0)  calls the pool's quoter contract with `commit=false` to fetch a live `amountOut` for swapping the inbound PRC20 into WPC. This same quote is then used to derive the slippage floor: [2](#0-1) 

```go
quote, execErr = k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
...
minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
minPCOut.Div(minPCOut, big.NewInt(100))
receipt, execErr = k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
```

The identical pattern exists in the `GAS_AND_PAYLOAD` path: [3](#0-2) .

Because `minPCOut` is only 5% below the *same* spot quote used to perform the swap (rather than an independent, time-weighted, or externally-verified reference price), the slippage check provides no protection against a price that has already been manipulated in the same block. An unprivileged attacker holding tokens in the WPC/PRC20 pool (these pools are created with real liquidity per the e2e setup script, e.g. `pool-manager.js create-pool`) can, immediately before the ballot-finalizing `MsgVoteInbound` transaction lands, trade against the pool to push the PRC20→WPC price down, then trade back afterward in the same or a following block. The `depositPRC20WithAutoSwap` call executes with a `minPCOut` computed from the now-depressed price, so it does not revert; the deposit still succeeds but the recipient (a user's UEA) receives materially less WPC than fair value, with the difference extracted by the attacker via the sandwich. This mirrors the report's core defect: no TWAP, and the "voting"/finalizing transaction (here, the inbound-executing vote) can be timed by an unprivileged actor to land in the same block as their price manipulation.

Unlike a normal user-initiated Uniswap swap (where the user chooses their own slippage tolerance), here the depositor is a cross-chain bridge user who never chooses `minPCOut`; the protocol computes it internally at deposit-execution time using the manipulable spot price, so the "slippage protection" offers no real guarantee to the depositor.

### Impact Explanation
An unprivileged attacker can extract value from ordinary bridge users' auto-swapped gas allocations by sandwiching the protocol's own auto-swap execution, which is a self-inflicted-slippage variant of fund loss for the depositor (their UEA receives less native gas token than it should, and the attacker captures the difference). This is a repeatable, per-inbound value-extraction vector reachable by any unprivileged actor with capital in the pool and does not require any privileged role, honest-validator misbehavior, or external chain compromise — it only requires ordinary trading on the pool that the protocol itself created and trusts as a price source.

### Likelihood Explanation
Likelihood is bounded by pool liquidity and MEV/timing feasibility: the attacker needs to observe or predict when an inbound `GAS`/`GAS_AND_PAYLOAD` execution will land (any of the last quorum votes on the inbound triggers execution synchronously) and have enough capital relative to pool depth to move the price meaningfully within the 5% slippage band. On a chain with thin WPC/PRC20 liquidity (as configured in local/e2e setups with small seeded amounts), this is easily achievable; on a chain with deep liquidity it is harder but not prevented by any code-level guard, since there is no TWAP, no external price check, and no independent minimum-output requirement supplied by the depositor.

### Recommendation
Do not derive `minPCOut` solely from the same spot quote used to execute the swap. Options: (1) use a TWAP oracle (e.g., Uniswap V3 pool `observe()` over a window) as the reference price for computing `minPCOut`, independent from the instantaneous `quoteExactInputSingle` call; (2) bound the acceptable deviation between the spot quote and a longer-window reference price, reverting (and falling back to a non-swap deposit path) if they diverge beyond a safe threshold; (3) consider deploying/using pools with sufficiently deep, protocol-owned liquidity and enforcing a maximum allowed price-impact per swap in addition to the slippage floor.

### Proof of Concept
1. Attacker holds PRC20 and WPC in the pool used by `GetUniversalCoreQuoterAddress`/`GetUniversalCoreWPCAddress` (e.g., pUSDC/WPC pool from `x/uexecutor/keeper/evm.go` `CallPRC20DepositAutoSwap` flow).
2. Attacker observes a pending `GAS_AND_PAYLOAD` (or `GAS`) inbound close to reaching ballot quorum (visible via mempool/UV vote submissions, which are public transactions).
3. Immediately before (or in the same block as) the finalizing `MsgVoteInbound` transaction, attacker sells PRC20 into the pool, depressing the PRC20→WPC price.
4. The finalizing vote transaction triggers `ExecuteInboundGas`/`ExecuteInboundGasAndPayload`, which calls `GetSwapQuote` and computes `minPCOut = quote * 95/100` off the now-depressed price, per [4](#0-3) .
5. `CallPRC20DepositAutoSwap` executes at the depressed price and satisfies the depressed `minPCOut`, so it does not revert; the victim's UEA receives less WPC than the pre-manipulation fair price implies.
6. Attacker buys back PRC20 (or sells WPC) to restore the price, netting the difference extracted from the victim's deposit.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
```

```go
// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
```
