### Title
Same-Block Self-Referential AMM Spot-Price Used as Both Quote and Slippage Bound in PRC20 Auto-Swap Deposits and Gas Refunds Enables Sandwich Extraction of Bridged Funds - ([File: x/uexecutor/keeper/evm.go])

### Summary
The Balancer report warns that non-proportional, single-asset pool interactions incur price impact and that slippage bounds must be set relative to an independent reference price, not to the same quote being consumed by the swap. Push Chain's `x/uexecutor` module reproduces this exact anti-pattern in its PRC20 auto-swap paths: it fetches a spot AMM quote via `QuoterV2.quoteExactInputSingle` and then derives its own slippage floor (`minPCOut = quote * 95 / 100`) from that same just-fetched spot quote, in the same keeper call that immediately executes the swap. Because the "reference" and the "executed swap" read the identical manipulable AMM state, the slippage check protects against nothing but rounding — an attacker who moves the pool price beforehand can extract the 5% band (or more, since the check is against itself) from every inbound gas-abstraction deposit, GAS_AND_PAYLOAD deposit, and outbound gas refund that routes through this swap.

### Finding Description
`GetSwapQuote` in [1](#0-0)  performs a live `quoteExactInputSingle` call against the on-chain Uniswap-style `QuoterV2`/pool for `prc20Address -> wpcAddress`. This spot quote directly reflects the current reserves/sqrtPrice of the pool at call time.

That same spot quote is then used, un-modified except for a flat 5% haircut, as the minimum-output slippage bound for the swap that executes moments later in the same keeper function, in three call sites:

- `ExecuteInboundGas` (gas-abstraction inbound swap): [2](#0-1) 
- `gasAndPayloadDepositAutoSwap` (GAS_AND_PAYLOAD inbound swap): [3](#0-2) 
- `applyGasRefund`'s swap-refund leg (outbound excess-gas refund): [4](#0-3) 

In all three, `minPCOut` is computed as `quote * 95 / 100` where `quote` was obtained from `GetSwapQuote` immediately beforehand, and both the quote and the subsequent `depositPRC20WithAutoSwap` / `refundUnusedGas` swap execute against the *same* pool state. There is no TWAP, external oracle, or governance-configured reference price involved — the "protection" is a percentage of itself.

This is the direct on-chain analog of the Balancer report: instead of "single-asset deposit swaps against the pool with no protection against price impact," Push Chain's protocol-driven auto-swap "protects" itself with a bound computed from the exact price it is about to move against. An unprivileged attacker who holds the PRC20/WPC pair for the relevant PRC20 (any token bridged into Push Chain that has a configured `defaultFeeTier` and WPC pool) can, via an ordinary permissionless swap on the same DEX pool, push the price down (or up, whichever benefits the direction of the protocol's forced swap) immediately before the block in which:
- an honest Universal Validator's `MsgVoteInbound` finalizes a `GAS` or `GAS_AND_PAYLOAD` inbound and triggers the auto-swap deposit, or
- an honest Universal Validator's `MsgVoteOutbound` finalizes an outbound and triggers `applyGasRefund`'s swap-refund leg,

then swap back afterward. Because `minPCOut` is derived from the manipulated spot price rather than an independent value, the protocol-initiated swap will always "pass" the check while still executing at the attacker-manipulated price, letting the attacker capture the price impact/spread that should have accrued to the user's bridged funds or to the protocol's refund pool.

No malicious validator, TSS participant, or relayer is required — the honest UV vote simply finalizes the observation and the deterministic keeper logic executes the swap against whatever pool state exists at that moment. The trigger (an ordinary DEX swap by any account) is fully unprivileged and reachable through default transaction submission paths.

### Impact Explanation
This falls under "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting ... or canonical UniversalTx state" and effectively "stealing ... of user or protocol-controlled funds": the amount of PC/PRC20 a bridging user or the refund recipient actually receives from the auto-swap can be manipulated down by a sandwiching attacker, with the loss captured as MEV/arbitrage profit by the attacker rather than returned to the user. The `minPCOut` value recorded is meaningless as a protection since it is generated from the same state being exploited, so the resulting `PCTx`/`OutboundTx.pc_refund_execution` records a "SUCCESS" while actually reflecting a manipulated, unfavorable execution price. Materiality scales with pool liquidity depth versus swap size — thinner PRC20/WPC pools (smaller/newer bridged tokens) are more exploitable.

### Likelihood Explanation
High reachability: any external account can hold and trade the relevant PRC20/WPC pair with no privileged access, and inbound gas-abstraction/GAS_AND_PAYLOAD deposits plus outbound gas refunds are routine, frequent protocol operations triggered by ordinary bridging activity — no validator or TSS misbehavior is needed, only honest finalization of a legitimate user's inbound/outbound. The attack only requires observing/timing standard bridging traffic and pool liquidity, both public information.

### Recommendation
Do not derive the slippage floor from the same spot quote used to execute the swap. Use an independent reference price (e.g., a TWAP over N blocks/observations, or a chain-meta/registry-configured expected price with a bounded deviation check) to compute `minPCOut`, and reject or defer the swap if the live spot quote deviates from that reference beyond a configured tolerance, rather than accepting whatever the current pool state reports as automatically "valid."

### Proof of Concept
1. Attacker identifies a bridged PRC20 (e.g., a newly listed token) with a shallow WPC pool used by `GetUniversalCoreWPCAddress`/`GetDefaultFeeTierForToken`.
2. Attacker submits a normal swap transaction that pushes the PRC20/WPC pool price unfavorably for `prc20 -> wpc` swaps.
3. In the same or next block, an honest UV's `MsgVoteInbound` (GAS or GAS_AND_PAYLOAD tx type) or `MsgVoteOutbound` reaches threshold and the keeper calls `GetSwapQuote` (`x/uexecutor/keeper/evm.go:502-537`), computes `minPCOut = quote*95/100`, and immediately calls `CallPRC20DepositAutoSwap`/`CallUniversalCoreRefundUnusedGas` against the manipulated pool.
4. Because `minPCOut` was computed from the same manipulated `quote`, the swap succeeds at the bad price; the bridging user (or refund recipient) receives less PC/WPC than a fair-price execution would have produced, while the attacker's subsequent reverse swap realizes the captured spread.

```go
// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
```

```go
// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
```
