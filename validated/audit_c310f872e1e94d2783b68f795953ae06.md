## Title
Replay/output verification silently accepts wrong position-state / hot-state checkpoint roots - (File: `types/src/transaction/mod.rs`)

## Summary
`TransactionOutput::ensure_match_transaction_info` is the authenticated-state-binding check that verifies a locally-computed `TransactionOutput` (write set, events, gas, status) matches an on-chain `TransactionInfo` during chunk execution and replay-verification. The function's own doc comment discloses that it does not check `state_checkpoint_hash`/`hot_state_checkpoint_hash` or `position_state_checkpoint_hash` — fields that bind the checkpoint's Merkle/JMT root and the new "position state" root to the committed `TransactionInfo`. Because those fields are skipped, a local execution result whose checkpoint state root differs from the authenticated on-chain value will still be reported as "matched."

## Finding Description
`ensure_match_transaction_info` compares status, gas, write-set hash, and event-root hash against a trusted `TransactionInfo`, but explicitly leaves the checkpoint hashes unchecked: [1](#0-0) 

The TODO comment embedded in the code states directly: "this comparator ignores the checkpoint hashes (state/hot-state and `position_state_checkpoint_hash`), so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution." This is functionally analogous to the external report: a downstream consumer (`replay_on_archive`, `chunk_executor`) treats a partial/incomplete result as fully validated because a critical check (here, the checkpoint-root comparison; there, the mint()-return-code check) is silently skipped rather than causing a hard failure.

This function is invoked from `execution/executor/src/chunk_executor/mod.rs`, `storage/db-tool/src/replay_on_archive.rs`, `aptos-move/aptos-debugger/src/aptos_debugger.rs`, and `aptos-move/cli/src/commands.rs` — all of which rely on it as the authoritative "does my locally produced output match the authenticated on-chain TransactionInfo" gate.

## Impact Explanation
The `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` fields in `TransactionInfo` are exactly the accumulator/JMT root fields that bind a version's committed state tree to the ledger's authenticated proof structure (as seen in `TransactionInfoV1::new`, `types/src/transaction/mod.rs:2463-2493`, and in `DoLedgerUpdate::assemble_transaction_infos`, `execution/executor/src/workflow/do_ledger_update.rs:58-126`, which builds these exact hashes into the `TransactionInfo` that gets hashed into the transaction accumulator). If replay execution, chunk execution, or debugging tooling produces a divergent state root (e.g., due to a bug in state-checkpoint construction, hot-state computation, or the new "trading native state root"/position-state feature) but the write-set and event hashes still happen to match, `ensure_match_transaction_info` returns `Ok(())`, masking a genuine state-root divergence. Tooling built on top of this check (`replay_on_archive`, used for auditing historical chain replay integrity) can therefore certify a replay as correct while the state tree/proof root is wrong — an invariant break for any tool or operator relying on this function to catch consensus-diverging bugs before they reach validators.

## Likelihood Explanation
This is not remotely triggerable by an unprivileged network attacker in the traditional sense; the primary risk is that a bug in local state-checkpoint/position-state-root computation (particularly the newly-added `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/position-state feature referenced throughout `execution/executor/src/workflow/do_get_execution_output.rs` and `do_ledger_update.rs`) goes undetected by the verification tooling meant to catch exactly this class of divergence, because the comparator was intentionally left incomplete pending a TODO. Given the code explicitly documents the gap as a known, not-yet-closed limitation, the likelihood of an actual undetected divergence reaching this masked path depends on other bugs in checkpoint-hash computation existing — this citation alone proves the detection gap, not an active state-corruption bug elsewhere.

## Recommendation
Extend `ensure_match_transaction_info` to also compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present, respecting the on/off state of `COMPUTE_TRADING_NATIVE_STATE_ROOTS` and `HOT_STATE_ROOT_IN_TXN_INFO`) against the locally computed values, and propagate hard errors (not silently `Ok`) so `replay_on_archive` and chunk execution fail loudly on any root mismatch, matching the remediation pattern from the external report (add the missing validation rather than ignoring it).

## Proof of Concept
1. In a build/replay path where checkpoint state-root computation has any bug (e.g., a defect in `DoStateCheckpoint` hot-state or position-state root logic), the resulting `TransactionOutput`'s underlying state tree diverges from the on-chain `TransactionInfo`'s checkpoint hash.
2. `write_set` and `events` are unaffected by the bug, so their hashes still match.
3. `chunk_executor` or `replay_on_archive` calls `ensure_match_transaction_info`, which only checks status/gas/write-set-hash/event-root-hash [2](#0-1) .
4. The function returns `Ok(())` despite `state_checkpoint_hash`/`position_state_checkpoint_hash` mismatching, per the code's own acknowledged TODO [3](#0-2) .
5. `replay_on_archive` reports the replay as successful even though the authenticated state root diverged from local execution.

I was unable to fully confirm (due to remaining tool-call budget) whether `COMPUTE_TRADING_NATIVE_STATE_ROOTS`/position-state-root computation currently has an independent bug that would actually produce a divergence in practice — the finding here is that the verification gate itself is documented as incomplete, which is the concrete, provable local defect; whether it is presently exploited by another bug elsewhere in checkpoint-root computation is unconfirmed.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
