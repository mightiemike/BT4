### Title
Unbounded gzip decompression of user-supplied Cairo0 `sierra_program`/program data enables OOM DoS - (File: `crates/apollo_rpc/src/v0_8/api/mod.rs`)

### Summary
`decompress_program` in `crates/apollo_rpc/src/v0_8/api/mod.rs` decompresses a user-controlled, base64-encoded gzip blob with no bound on the decompressed size, unlike the size-limited helper (`decode_and_decompress_with_size_limit`) that the same codebase already uses elsewhere for the same kind of data.

### Finding Description
`decompress_program` base64-decodes the caller-supplied `compressed_program` string and pipes it straight into a `GzDecoder`, reading it to completion with `read_to_end` and no size cap: [1](#0-0) 

This function is reached from the JSON-RPC transaction-execution path when a client submits a `DeclareV1` (deprecated Cairo0) broadcasted transaction: `TryFrom<BroadcastedDeclareTransaction> for ExecutableTransactionInput` calls `user_deprecated_contract_class_to_sn_api`, which calls `decompress_program` on the attacker-supplied `compressed_program`: [2](#0-1) 

The `TODO(dan): add time and size limits.` comment on the vulnerable function confirms the missing bound was a known gap. This is exactly analogous to the ffuf bug class: a small compressed payload can expand to an arbitrarily large decompressed buffer with no guard.

Notably, the codebase already fixed this exact class of bug for the *new* RPC transaction format: `starknet_api::compression_utils::decompress_with_size_limit` enforces a `max_size` bound via `.take(max_size + 1)` before accepting data, and is used by the deprecated-gateway-to-RPC transaction converter for Sierra programs: [3](#0-2) [4](#0-3) 

`decompress_program`, however, was never migrated to use this bounded helper, leaving the Cairo0 declare-execution path unprotected.

### Impact Explanation
Any unprivileged RPC caller can submit a `starknet_estimateFee`, `starknet_simulateTransactions`, or `starknet_call`-style request containing a `BroadcastedDeclareTransaction::V1` with a small, highly-compressible gzip payload (a "zip bomb") as `contract_class.program`. Decompression is unbounded, so the node will attempt to materialize an arbitrarily large `Vec<u8>` in memory, exhausting available memory and causing the RPC/execution process to crash or become unresponsive — a denial of service against the node process handling that RPC endpoint.

### Likelihood Explanation
Likelihood is high: the attack requires only a single, unauthenticated/unprivileged JSON-RPC call with a crafted `DECLARE` V1 payload; no special permissions, funds, or on-chain state are needed, and gzip bombs achieving >1000x expansion ratios are trivial to construct.

### Recommendation
Replace the unbounded `GzDecoder::read_to_end` in `decompress_program` with a size-limited read (e.g., using `.take(max_size)` as already done in `starknet_api::compression_utils::decompress_with_size_limit`), and reject/short-circuit once the decompressed size exceeds the configured maximum program size, mirroring the pattern already applied in `deprecated_gateway_transaction.rs`.

### Proof of Concept
1. Construct a gzip-compressed payload that decompresses to several GB of repetitive data (a classic "zip bomb"), base64-encode it.
2. Send a JSON-RPC `starknet_estimateFee` (or `simulateTransactions`) request with a `BroadcastedDeclareTransaction` of `type: DECLARE`, `version: 0x1`, and `contract_class.program` set to the crafted base64 string.
3. The server calls `TryFrom<BroadcastedDeclareTransaction>` → `user_deprecated_contract_class_to_sn_api` → `decompress_program`, which decompresses the payload fully into memory with no limit, exhausting memory on the node process. [1](#0-0)

/// Decompresses the provided data with size limits.
fn decompress_with_size_limit(
    decoded_data: Vec<u8>,
    max_size: usize,
) -> Result<Vec<u8>, CompressionError> {
    let decompressor = flate2::read::GzDecoder::new(&decoded_data[..]);
    let mut decompressed_data = Vec::new();
    decompressor
        .take((max_size + 1).try_into().expect("max_size should be less than usize::MAX"))
        .read_to_end(&mut decompressed_data)?;
    if decompressed_data.len() > max_size {
        return Err(CompressionError::SizeLimitExceeded { limit: max_size });
    }
    Ok(decompressed_data)
}
