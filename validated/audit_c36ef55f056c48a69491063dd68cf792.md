### Title
Global class-cache reuse of undeclared/reverted Cairo0 classes bypasses declaration check - ([File: crates/blockifier/src/state/state_reader_and_contract_manager.rs])

### Summary
The blockifier's process-wide `GlobalContractCache` (`RawClassCache`, keyed only by `ClassHash`) is used to serve compiled classes without re-verifying that the class is actually declared in the *current* committed state — except for non-V0 (Cairo1) classes, where the code explicitly re-checks `is_declared` because "existence in the cache does not guarantee that (it might contain a declared class from a reverted block, for example)". This check is skipped entirely for Cairo0 (`RunnableCompiledClass::V0`) classes.

### Finding Description
`StateReaderAndContractManager::get_compiled_from_class_manager` looks up a class hash in the shared `ContractClassManager`/`GlobalContractCache`, which persists across blocks and is not rolled back when a block or state diff is reverted: [1](#0-0) 

For Cairo1 classes, the code deliberately re-validates against the authoritative state (`self.state_reader.is_declared(class_hash)`), with the comment explicitly acknowledging the cache can hold "a declared class from a reverted block". For Cairo0 (`V0`) classes, this branch is a no-op (`RunnableCompiledClass::V0(_) => {}`), so a cache hit is trusted unconditionally.

`is_declared` is defined to only meaningfully check Cairo1 declaration state; the doc comment on the trait explicitly states "Cairo 0 classes always return `false`": [2](#0-1) 

The concrete implementation (`ApolloReader::is_declared`) confirms this: it only consults the Sierra/Casm declaration block number in storage, which is never populated for Cairo0 classes, so it always returns `false` for them regardless of whether they are actually declared: [3](#0-2) 

This is analogous to CVE-2018-16862: an entity (a Cairo0 class) associated with a "removed"/reverted block is still served from a stale global cache, and the system's own mechanism for detecting staleness (`is_declared`) is architecturally incapable of validating that class type. Because `RawClassCache` is keyed only by `ClassHash` and is shared across the whole sequencer process and across all blocks/reprocessing runs, once a Cairo0 class is cached (e.g., speculatively during execution of a block that ultimately gets reorganized/reverted, or during re-execution/simulation flows), any subsequent transaction referencing that same class hash on a node whose cache still holds the entry will get a successful `get_compiled_class` result — bypassing the requirement that the class be declared in the current committed state.

### Impact Explanation
If a node's cache retains a Cairo0 class from a reverted/discarded block while the class is not present in that node's current committed state, that node will accept and execute a `deploy`/`replace_class`/`library_call` referencing that class hash where a node without the stale cache entry (or a node computing the Starknet OS re-execution strictly from committed state) would correctly reject it with `UndeclaredClassHash`. This produces honest-node divergence in execution results/state diffs for the same block, since one node's state transition succeeds using code that per the canonical state was never declared, while another rejects the transaction. Divergent state roots across otherwise-honest sequencer/replica nodes can lead to consensus/re-execution mismatches and, depending on how the divergence manifests, an inability of the network to agree on/confirm the resulting block or state commitment.

### Likelihood Explanation
Reachability requires that (a) a Cairo0 class ends up in the global cache while not declared in the querying node's canonical view (e.g., due to reorg/revert of a block containing the declaration, or the class manager being populated via speculative/optimistic execution paths that are not itself rolled back), and (b) a subsequent transaction from any sender references that class hash. Since class hashes for Cairo0 classes are content-addressed and deterministic, an attacker does not need to guess a hash — they only need the declaration to have occurred once and then be reverted at the storage layer while the process-level cache is not cleared, then submit a normal deploy/invoke transaction referencing that hash. This is reachable by an ordinary, unprivileged transaction sender/contract deployer and does not require a malicious operator or proposer.

### Recommendation
Apply the same `is_declared` (or equivalent authoritative state check) validation for `RunnableCompiledClass::V0` cache hits as is already done for Cairo1 classes, rather than special-casing V0 as trusted. Since `is_declared` as currently implemented always returns `false` for Cairo0 classes, this requires extending `FetchCompiledClasses::is_declared` (and its implementations, e.g. `ApolloReader::is_declared`) to also check deprecated/Cairo0 class declaration status against the current state, and then removing the `V0(_) => {}` bypass in `get_compiled_from_class_manager`.

### Proof of Concept
Conceptual reproduction (exact reorg/revert trigger conditions in the block-building/re-execution pipeline were not traced end-to-end within the available context):
1. Node executes a block containing a Cairo0 `declare` for class `C` (hash `H`), populating the process-wide `GlobalContractCache` via `set_and_compile`.
2. That block/state diff is later reverted at the storage layer (e.g., reorg, failed speculative execution path, or re-execution against an earlier state) without clearing `ContractClassManager`'s cache.
3. A transaction deploying/using class hash `H` is submitted; `get_compiled_from_class_manager` finds `H` in cache as `RunnableCompiledClass::V0`, skips the `is_declared` check (unlike the Cairo1 branch), and returns the cached compiled class as if declared.
4. The transaction executes successfully on this node, while a node without the stale cache entry (or the Starknet OS during independent re-execution from committed state) returns `StateError::UndeclaredClassHash`, causing divergent execution results for the same transaction/block. [4](#0-3)

    fn get_compiled_from_class_manager(
        &self,
        class_hash: ClassHash,
    ) -> StateResult<RunnableCompiledClass> {
        if let Some(runnable_class) =
            self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
        {
            match &runnable_class {
                RunnableCompiledClass::V0(_) => {}
                _ => {
                    // The Cairo1 class is cached; verify it is declared,
                    // since existence in the cache does not guarantee that
                    // (it might contain a declared class from a reverted block, for example).
                    if !self.state_reader.is_declared(class_hash)? {
                        return Err(StateError::UndeclaredClassHash(class_hash));
                    }
                }
            }
            self.increment_cache_hit_metric();
            self.update_native_metrics(&runnable_class);
            return Ok(runnable_class);
        }
        self.increment_cache_miss_metric();

        let compiled_class = self.state_reader.get_compiled_classes(class_hash)?;
        self.contract_class_manager.set_and_compile(class_hash, compiled_class.clone());
        // Access the cache again in case the class was compiled.
        let runnable_class = self
            .contract_class_manager
            .get_runnable(&class_hash, &self.native_classes_whitelist)
            .unwrap_or_else(|| {
                // Edge case that should not be happen if the cache size is big enough.
                // TODO(Yoni): consider having an atomic set-and-get.
                log::error!("Class is missing immediately after being cached.");
                compiled_class.to_runnable()
            });
        self.update_native_metrics(&runnable_class);
        Ok(runnable_class)
    }

    fn is_declared(&self, class_hash: ClassHash) -> StateResult<bool> {
        let state_number = StateNumber(self.latest_block);
        let class_declaration_block_number = self
            .reader()?
            .get_state_reader()
            .and_then(|sr| sr.get_class_definition_block_number(&class_hash))
            .map_err(|err| StateError::StateReadError(err.to_string()))?;
        Ok(
            matches!(class_declaration_block_number, Some(block_number) if block_number <= state_number.0),
        )
    }
