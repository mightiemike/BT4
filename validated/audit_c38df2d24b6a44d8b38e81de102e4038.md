### Title
Address Registrar `register()` permanently locks excess attached deposit on successful registration - (File: `runtime/near-wallet-contract/implementation/address-registrar/src/lib.rs`)

### Summary
The Address Registrar contract's `register()` method requires the caller to attach at least `required_deposit` (computed from `storage_byte_cost` and the size of the entry to store) via `#[payable]`. When registration succeeds (the `Entry::Vacant` branch), the code stores the mapping but never computes or refunds `given_deposit - required_deposit`; it only refunds the *full* deposit on the failure/duplicate path (`Entry::Occupied`). Any excess yoctoNEAR attached above the exact storage cost is silently absorbed into the contract's balance with no owner/withdraw method to ever recover it.

### Finding Description
`register()` in [1](#0-0)  computes `required_deposit` from `bytes_to_store` and panics if `given_deposit < required_deposit`, but never checks or handles the case `given_deposit > required_deposit`. On the success path it just inserts the entry and returns, keeping the entire `given_deposit`: [2](#0-1) 
Only the collision/failure branch refunds the deposit, and it refunds the whole `given_deposit` rather than crediting the excess in the success path: [3](#0-2) 
There is no `withdraw`, `owner`, or `admin` method in the contract to later reclaim accumulated excess deposits, confirmed by searching the file — none exist. This is the same bug class as the referenced Teller `_repayLoan()` finding: the contract accepts more funds than strictly required to satisfy the operation, keeps the difference on success, and gives the caller no way to get it back.

The contract is reachable directly by any unprivileged RPC caller or transaction signer (a plain `FunctionCall` action to `register`), and is also reachable indirectly through the NEAR Wallet Contract's `rlp_execute` flow when it looks up an eth-implicit target address, as shown by the wallet-contract's own registrar integration: [4](#0-3) 

### Impact Explanation
Any excess yoctoNEAR/NEAR attached beyond the exact required storage deposit on a successful `register()` call is permanently and irrecoverably locked in the Address Registrar contract's account balance. This is a direct, transaction-triggered loss of user funds with no remediation path — matching the "permanently frozen funds" acceptance criterion. Because the required deposit is computed to the exact yoctoNEAR (`storage_byte_cost * bytes_to_store`), any caller who is imprecise (e.g. attaches a round NEAR amount like `0.001N` or `1N` instead of the exact computed cost) loses the difference forever.

### Likelihood Explanation
Likelihood is high: the contract's own test suite demonstrates this exact overpayment behavior is expected/accepted rather than treated as a bug — `test_register_without_deposit` and `test_caller_refunds` both attach deposits well above the actual storage cost and assert the excess is retained by the contract: [5](#0-4) 
Any relayer or user constructing a `register` call (either directly or via the Wallet Contract's eth-emulation path) with anything other than the exact minimal deposit will trigger this loss, and there is no way to compute the exact required deposit from outside without independently replicating `storage_byte_cost() * bytes_to_store` at call time, making accidental overpayment a common occurrence.

### Recommendation
In the `Entry::Vacant` success branch of `register()`, compute `excess = given_deposit.saturating_sub(required_deposit)` and, if `excess > NearToken::from_yoctonear(0)`, issue a `promise_batch_action_transfer` refunding `excess` to `env::predecessor_account_id()`, mirroring the refund already done in the `Entry::Occupied` branch but only for the unused portion instead of the whole deposit.

### Proof of Concept
1. Deploy the Address Registrar contract (as done in `runtime/near-wallet-contract/implementation/address-registrar/src/lib.rs`).
2. Call `register({"account_id": "birchmd.near"})` attaching a deposit larger than the exact `storage_byte_cost() * (20 + "birchmd.near".len())` (e.g. attach `1 NEAR` when only a few hundred yoctoNEAR-scaled bytes are required, as in `test_register_without_deposit`): [6](#0-5) 
3. Observe the registration succeeds (`Some(address)` returned) and the contract's account balance increases by the *entire* attached deposit, not just the computed `required_deposit`.
4. Confirm there is no method in the contract to withdraw the excess — the caller's overpayment is permanently lost.

    #[payable]
    pub fn register(&mut self, account_id: AccountId) -> Option<String> {
        // It is not allowed to register eth-implicit accounts because the purpose
        // of the registry is to allow looking up the named account associated with
        // an address obtained via hashing, but eth-implicit accounts are already
        // parsable as addresses.
        if is_eth_implicit(&account_id) {
            let log_message = format!("Refuse to register eth-implicit account {account_id}");
            env::log_str(&log_message);
            return None;
        }

        // Must store the address and the account id
        let bytes_to_store = 20 + (account_id.len() as u128);
        let required_deposit =
            NearToken::from_yoctonear(env::storage_byte_cost().as_yoctonear() * bytes_to_store);
        let given_deposit = env::attached_deposit();
        // The caller must pay for the storage cost of registering.
        if given_deposit < required_deposit {
            let message = format!(
                "Insufficient deposit to cover storage cost. Given={} Expected={}",
                given_deposit.as_yoctonear(),
                required_deposit.as_yoctonear(),
            );
            env::panic_str(&message);
        }

        let address = account_id_to_address(&account_id);

        match self.addresses.entry(address) {
            Entry::Vacant(entry) => {
                let address = format!("0x{}", hex::encode(address));
                let log_message = format!("Added entry {} -> {}", address, account_id);
                entry.insert(account_id);
                env::log_str(&log_message);
                Some(address)
            }
            Entry::Occupied(entry) => {
                let log_message = format!(
                    "Address collision between {} and {}. Keeping the former.",
                    entry.get(),
                    account_id
                );
                env::log_str(&log_message);
                // Transfer the deposit back to the caller since no storage was updated.
                let refund_promise = env::promise_batch_create(&env::predecessor_account_id());
                env::promise_batch_action_transfer(refund_promise, given_deposit);
                None
            }
        }
    }

/// Test asserting the address registrar requires a deposit.
#[tokio::test]
async fn test_register_without_deposit() -> anyhow::Result<()> {
    let TestContext { worker, address_registrar, .. } = TestContext::new().await?;

    let method = "register";
    let args = br#"{"account_id": "birchmd.near"}"#;

    assert!(result.is_failure(), "Call without deposit must fail");

        .call(address_registrar.id(), method)
        .args(args.to_vec())
        .deposit(deposit_amount)
        .transact()
        .await?;

    let output: Option<String> = result.json()?;
    assert_eq!(output.as_deref(), Some("0x4bfcff9a964925adf801c866f6ada98bd7ec40ca"));

        post_tx_account_balance.as_yoctonear() - pre_tx_account_balance.as_yoctonear()
