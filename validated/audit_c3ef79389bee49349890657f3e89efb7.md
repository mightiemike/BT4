### Title
Starknet OS `replace_class` syscall omits declared-class verification present in the blockifier, enabling state divergence / wrong committed root - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS Cairo implementation of the `replace_class` syscall sets a contract's class hash without verifying that the class hash was actually declared, while the equivalent blockifier (Rust) implementation performs this check. This asymmetry mirrors the reported "missing approval" bug class: a sensitive, state-mutating operation is executed without validating a required precondition that a parallel/authoritative code path does enforce.

### Finding Description
In the blockifier's deprecated syscall handler, `replace_class` explicitly ensures the target class is declared before mutating state: [1](#0-0) 

This check is validated by tests expecting an `"is not declared"` error for undeclared class hashes: [2](#0-1) 
and similarly for the current (non-deprecated) syscall path: [3](#0-2) 

However, the Starknet OS's own Cairo implementation of `execute_replace_class` (used during Starknet OS re-execution / proving, i.e., the path that recomputes state transitions for proof generation and commitment) directly updates the contract's class hash in `contract_state_changes` with **no check that the class hash is declared**, and explicitly documents this gap with a TODO: [4](#0-3) 

The comment at line 902 reads: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` This is the exact "missing approval/validation" pattern from the reference report — a state-mutating operation (`swap`/`replace_class`) proceeds without verifying a required authorization/precondition (pool approval / declared-class check) that the analogous, audited code path enforces.

The legacy/deprecated Cairo syscall path (`deprecated_execute_syscalls.cairo`) has the identical gap: [5](#0-4) 

### Impact Explanation
The Starknet OS is re-executed to generate STARK proofs and to independently verify/commit the state produced by the blockifier (the sequencer's block-building execution engine). If the blockifier rejects a transaction attempting `replace_class` with an undeclared class hash (per its explicit check), but the Starknet OS accepts the same call and updates state anyway, the two execution paths diverge on the resulting state root for that block. This can lead to:
- Wrong committed state root / block hash, since the OS-computed state diff would include a class-hash write that never should have occurred, or the OS would silently accept an invalid transaction that the sequencer rejected.
- Honest-node divergence: nodes/verifiers relying on Starknet OS re-execution (e.g., the prover pipeline, `crates/starknet_transaction_prover`) may compute a different result than the sequencer's blockifier, breaking consensus on the correct block state and potentially allowing an account to switch to an implementation class hash for which no compiled class was ever declared/available network-wide (an unauthorized, invalid account/contract state).

This is reachable from a fully unprivileged transaction sender: any contract (including a standard account contract) can invoke the `replace_class` syscall as part of normal `__execute__`/entry-point execution.

### Likelihood Explanation
The `replace_class` syscall is a standard, commonly available Starknet syscall reachable from any contract's execution — no special privileges are required, only a single submitted transaction that triggers a `replace_class_syscall` call with a class hash that is not declared in state (which is trivial to construct, e.g., an arbitrary/garbage felt or a never-declared hash). Since the check is entirely absent in the OS implementation (confirmed by the explicit outstanding TODO), the likelihood of triggering divergent behavior is high whenever the OS path is exercised for the same transaction that the blockifier would otherwise reject for this reason.

### Recommendation
Add a check in the Starknet OS's `execute_replace_class` (both `syscall_impls.cairo` and the deprecated `deprecated_execute_syscalls.cairo` implementations) mirroring the blockifier's behavior: verify that `class_hash` corresponds to a declared/compiled class in `contract_class_changes` (or the relevant OS-tracked declared-class dictionary) before permitting the `StateEntry` update. This should raise an OS-level assertion/error equivalent to the blockifier's `"... is not declared"` error, ensuring both execution paths reject the same set of transactions and produce consistent state commitments.

### Proof of Concept
1. Submit an `INVOKE` transaction whose account/contract `__execute__` (or any external entry point) calls `replace_class_syscall(class_hash)` with a `class_hash` that has never been declared on-chain.
2. Under the blockifier execution path (sequencer block building / RPC simulation / stateful validation), this transaction fails with `"... is not declared"`, as shown by: [2](#0-1) 
3. Under the Starknet OS re-execution path (`execute_replace_class` in `syscall_impls.cairo`), the same call succeeds and unconditionally writes the new (undeclared) `class_hash` into `contract_state_changes`, per: [6](#0-5) 
4. This produces two different state diffs/roots for the same block depending on which execution engine processed it, i.e., a concrete state-commitment mismatch between the sequencer and its own OS/proof-generation re-execution.

*Note: I could not verify from the indexed context whether an additional, separate declared-class check exists elsewhere in the OS pipeline (e.g., in a later commitment-validation stage) that might compensate for this gap; the TODO comment in the source strongly suggests it does not, but a full confirmation would require inspecting the complete state-commitment and declared-class-tracking logic, which may exceed what the current index exposes. If deeper verification is needed, a Devin session with full repository access would be able to trace this end-to-end.*

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
