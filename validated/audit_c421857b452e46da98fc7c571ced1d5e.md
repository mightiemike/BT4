### Title
Zero-Gas NOP Outcome on `MethodNotFound` Discards Charged Contract-Loading Fee — (File: `runtime/near-vm-runner/src/logic/logic.rs`)

### Summary

On stable mainnet (Protocol Version 86), when a `FunctionCall` action targets a method that does not exist in the deployed contract (`MethodResolveError::MethodNotFound` or `MethodResolveError::MethodInvalidSignature`), the contract-loading fee is charged to the internal gas counter during preparation but is then silently discarded when the outcome is finalized as `VMOutcome::nop_outcome()` — a zero-gas, zero-used-gas outcome. The caller pays only the base action-receipt execution fee, not the loading fee proportional to contract size. This is a fee-payment bypass reachable by any unprivileged user who submits a `FunctionCall` transaction naming a non-existent method on any deployed contract.

---

### Finding Description

**Execution path:**

1. `action_function_call` (`runtime/runtime/src/function_call.rs:31`) invokes `near_vm_runner::run`, which calls `WasmtimeVM::prepare` → `with_compiled_and_loaded`.

2. Inside `with_compiled_and_loaded` (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs:688`), after the module is compiled/deserialized and linked, `gas_counter.after_loading_executable` is called: [1](#0-0) 

   Because `fix_contract_loading_cost` is `false` on stable (PV 129 is nightly-only), this path charges `contract_loading_base + contract_loading_bytes × code_len` gas into the `GasCounter`. The charge succeeds and the counter now reflects the loading cost.

3. The closure passed to `with_compiled_and_loaded` then performs method resolution: [2](#0-1) 

   When the method is absent, the result is tagged `PreparationResult::OutcomeAbortButNopInOldProtocol`. The `gas_counter` — which already holds the loading fee — is bundled into `PreparedContract` and passed forward.

4. In `PreparedContract::run`: [3](#0-2) 

   `ExecutionResultState::new` is constructed with the charged `gas_counter`, but `OutcomeAbortButNopInOldProtocol` immediately calls: [4](#0-3) 

5. Since `fix_contract_loading_cost` is `false`, `abort_but_nop_outcome_in_old_protocol` falls through to `nop_outcome`: [5](#0-4) 

   `nop_outcome` constructs a fresh `VMOutcome` with `burnt_gas: Gas::ZERO` and `used_gas: Gas::ZERO`, **completely discarding** the `ExecutionResultState` (and its charged gas counter). The loading fee that was deducted from the counter is thrown away.

6. The runtime's refund logic in `refund_unspent_gas_and_deposits` (`runtime/runtime/src/lib.rs:1163`) then computes the gas refund as `prepaid_gas − gas_burnt`. With `gas_burnt = 0`, the caller receives a near-full refund of all prepaid gas, paying effectively nothing for the loading work.

**The analogous `FixContractLoadingError` (PV 86) fix** addressed only the `VMRunnerError::LoadingError` path (when `Module::deserialize` fails): [6](#0-5) 

The `MethodNotFound` / `MethodInvalidSignature` path remains unfixed on stable until `FixContractLoadingCost` (PV 129, nightly-only): [7](#0-6) 

The existing test confirms the zero-gas behavior on the old protocol: [8](#0-7) 

---

### Impact Explanation

**Fee payment bypass.** The contract-loading fee is proportional to contract size: `contract_loading_base (35,445,963 gas) + contract_loading_bytes (1,089,295 gas/byte) × code_len`. For a near-maximum-size contract (~1 MB), this is approximately **1.14 TGas** per call. Because `nop_outcome` discards the charged counter, the caller pays only the base action-receipt execution fee (a small fixed amount), not the loading fee. The caller receives a refund of all prepaid gas minus `gas_burnt = 0`, so the effective cost of triggering ~1.14 TGas of node work is near zero.

The contract is cached after the first load, so subsequent calls are fast (cache hit), but the loading fee is still charged to the counter and still discarded on every call. The attacker can repeat this indefinitely, each time obtaining the loading-fee work for free.

This maps directly to the allowed impact category **"fee payment bypass"**: a user-submitted transaction causes the runtime to perform metered work (contract deserialization, linking, instantiation-pre) without the caller paying the corresponding fee.

---

### Likelihood Explanation

Any unprivileged user can trigger this by:
- Deploying any valid WASM contract (or targeting any existing deployed contract).
- Submitting a `FunctionCall` transaction with a method name that does not exist in the contract.

No special permissions, validator access, or privileged role is required. The condition is trivially constructible: the attacker controls the method name in the transaction. The attack is repeatable at the cost of only the base transaction fee per invocation.

---

### Recommendation

Apply the same fix that `FixContractLoadingCost` (PV 129) implements to stable: make `MethodNotFound` and `MethodInvalidSignature` outcomes return `VMOutcome::abort(result_state, error)` (which calls `compute_outcome()` on the charged `ExecutionResultState`) instead of `VMOutcome::nop_outcome(error)`. Concretely, change `PreparationResult::OutcomeAbortButNopInOldProtocol` to `PreparationResult::OutcomeAbort` for these two error variants, or accelerate the stabilization of `FixContractLoadingCost`.

The fix is already present in nightly as `FixContractLoadingCost` (PV 129): [9](#0-8) 

The integration test that validates the corrected behavior (gas charged after the upgrade) is: [10](#0-9) 

---

### Proof of Concept

1. Deploy a large valid WASM contract (e.g., ~500 KB) to account `attacker.near`.
2. Submit a `FunctionCall` transaction from any account targeting `attacker.near`, method name `"nonexistent_method"`, with `prepaid_gas = 300 TGas`.
3. Observe the execution outcome: `gas_burnt = 0`, `used_gas = 0` (the NOP outcome). The caller receives a near-full refund of all 300 TGas.
4. The node performed contract deserialization and linking (proportional to ~500 KB of WASM) and charged the loading fee (~580 GGas) to the internal counter, but the counter was discarded.
5. Repeat step 2 indefinitely. Each call costs only the base transaction fee; the loading fee (~580 GGas per call) is never collected.

The zero-gas NOP behavior for `MethodNotFound` is directly confirmed by the existing unit test snapshot: [11](#0-10) 

where `burnt gas 0 used gas 0` is the expected (and currently correct) output on the old protocol, confirming the fee is not collected.

/// Check that execution that fails during contract preparation has the updated gas cost after the update.
#[test]
// TODO(spice-test): Assess if this test is relevant for spice and if yes fix it.
#[cfg_attr(feature = "protocol_feature_spice", ignore)]
fn preparation_error_gas_cost() {
    if !ProtocolFeature::FixContractLoadingCost.enabled(PROTOCOL_VERSION) {
        return;
    }
    let new_protocol_version = ProtocolFeature::FixContractLoadingCost.protocol_version();
    let old_protocol_version = new_protocol_version - 1;

    let bad_contract = b"not-a-contract".to_vec();
    let contract_size = bad_contract.len();

    let epoch_length: BlockHeight = 5;

    let account: AccountId = "test0".parse().unwrap();
    let mut env = prepare_env_with_contract(
        epoch_length,
        old_protocol_version,
        account.clone(),
        bad_contract,
    );

    let old_result = env.call_main(&account);
    let old_gas = old_result.receipts_outcome[0].outcome.gas_burnt;
    assert_matches!(old_result.status, FinalExecutionStatus::Failure(_));

    env.upgrade_protocol_to_latest_version();

    let new_result = env.call_main(&account);
    let new_gas = new_result.receipts_outcome[0].outcome.gas_burnt;
    assert_matches!(new_result.status, FinalExecutionStatus::Failure(_));

    // Gas cost should be different because the upgrade pre-charges loading costs.
    assert_ne!(old_gas, new_gas);
    // Runtime parameter values for version of the protocol upgrade
    let loading_base = 35_445_963;
    let loading_byte = 1_089_295;
    let loading_cost = loading_base + contract_size as u64 * loading_byte;
    assert_eq!(old_gas.checked_add(Gas::from_gas(loading_cost)).unwrap(), new_gas);
}
