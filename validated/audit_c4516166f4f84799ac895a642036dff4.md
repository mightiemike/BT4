### Title
Lite-node gRPC filter omits `GetTransactionInfoByBlockNum`, allowing bypass of the lite-fullnode history-query restriction that the HTTP filter enforces - ([File: framework/src/main/java/org/tron/core/services/filter/LiteFnQueryGrpcInterceptor.java])

### Summary
`LiteFnQueryHttpFilter` explicitly blocks `/wallet/gettransactioninfobyblocknum` and `/walletsolidity/gettransactioninfobyblocknum` on lite fullnodes, but the equivalent gRPC methods (`protocol.Wallet/GetTransactionInfoByBlockNum` and `protocol.WalletSolidity/GetTransactionInfoByBlockNum`) are missing from `filterMethods` in `LiteFnQueryGrpcInterceptor`. An unprivileged gRPC client can therefore invoke the same expensive, historical-data-dependent handler that the operator intended to disable, bypassing the restriction entirely by using gRPC instead of HTTP.

### Finding Description
`LiteFnQueryGrpcInterceptor.interceptCall` blocks a request only if `chainBaseManager.isLiteNode()`, `openHistoryQueryWhenLiteFN` is `false`, and the requested gRPC full method name is present in the static `filterMethods` set [1](#0-0) . That set enumerates 23 `protocol.Wallet/*` and 17 `protocol.WalletSolidity/*` methods plus `protocol.Database/GetBlockByNum` [2](#0-1) , but does **not** include `GetTransactionInfoByBlockNum` for either `Wallet` or `WalletSolidity`.

In contrast, `LiteFnQueryHttpFilter.doFilter` blocks a request whose path is in `filterPaths` under the same lite-node/`openHistoryQueryWhenLiteFN` preconditions [3](#0-2) , and `filterPaths` explicitly contains `/wallet/gettransactioninfobyblocknum` and `/walletsolidity/gettransactioninfobyblocknum` [4](#0-3) [5](#0-4) .

Both HTTP endpoints are backed by the same underlying wallet logic that scans transaction info for an entire block, which is the reason it is disabled on lite nodes (lite nodes prune historical `TransactionInfo`/`TransactionRetStore` data, per `GetTransactionInfoByBlockNumServlet` and `GetTransactionInfoByBlockNumOnSolidityServlet`). Because the gRPC interceptor's `filterMethods` set does not mirror this HTTP restriction, a client calling `protocol.Wallet/GetTransactionInfoByBlockNum` or `protocol.WalletSolidity/GetTransactionInfoByBlockNum` directly via gRPC is never intercepted and reaches the full handler, defeating the operator's intended restriction and exposing the node to the same unbounded/expensive lookups the HTTP path is supposed to prevent.

### Impact Explanation
This is a config-enforced-restriction bypass leading to DoS via RPC-API: an operator who disabled historical queries on a lite fullnode (`openHistoryQueryWhenLiteFN=false`) to avoid exposing expensive/likely-broken handlers can still be hit through the unfiltered gRPC path, causing potential node stalls or resource exhaustion from repeated calls to the block-transaction-info scan, and/or unexpected errors/inconsistent responses from operating on pruned data. This matches "DoS via RPC-API" in the scoped impact classes.

### Likelihood Explanation
Preconditions are exactly the ones already declared as in-scope (lite fullnode, `openHistoryQueryWhenLiteFN=false`), and the attacker needs no privilege beyond anonymous gRPC access to the node's Wallet/WalletSolidity services, which is the default posture for public RPC nodes. The call is a single unauthenticated gRPC invocation, trivially repeatable at will, with zero on-chain cost (no transaction fee/energy required since it is a read-only query).

### Recommendation
Add `protocol.Wallet/GetTransactionInfoByBlockNum` and `protocol.WalletSolidity/GetTransactionInfoByBlockNum` to `filterMethods` in `LiteFnQueryGrpcInterceptor`, and more generally, generate/derive `filterMethods` and `filterPaths` from a single shared source of truth (or add a symmetry test) to prevent future HTTP/gRPC filter drift.

### Proof of Concept
```java
// Add to LiteFnQueryGrpcInterceptorTest (framework/src/test/java/org/tron/core/services/filter/LiteFnQueryGrpcInterceptorTest.java)
@Test
public void testGetTransactionInfoByBlockNumIsFiltered() {
  // Mirrors the corresponding HTTP paths already restricted in LiteFnQueryHttpFilter:
  // "/wallet/gettransactioninfobyblocknum" and "/walletsolidity/gettransactioninfobyblocknum"
  Set<String> filterMethods = LiteFnQueryGrpcInterceptor.getFilterMethods();
  Assert.assertTrue("gRPC filter should block GetTransactionInfoByBlockNum on Wallet like HTTP does",
      filterMethods.contains("protocol.Wallet/GetTransactionInfoByBlockNum"));
  Assert.assertTrue("gRPC filter should block GetTransactionInfoByBlockNum on WalletSolidity like HTTP does",
      filterMethods.contains("protocol.WalletSolidity/GetTransactionInfoByBlockNum"));
}
```
Expected result on current code: both assertions **fail**, confirming that a raw gRPC call to `protocol.Wallet/GetTransactionInfoByBlockNum` (e.g. via `grpcurl -plaintext <lite-node>:50051 protocol.Wallet/GetTransactionInfoByBlockNum <<< '{"num": 1}'`) succeeds and returns data, while the equivalent HTTP request to `POST /wallet/gettransactioninfobyblocknum` on the same node returns `"this API is closed because this node is a lite fullnode"`.

  @Override
  public <ReqT, RespT> ServerCall.Listener<ReqT> interceptCall(ServerCall<ReqT, RespT> call,
      Metadata headers, ServerCallHandler<ReqT, RespT> next) {
    if (chainBaseManager.isLiteNode()
            && !CommonParameter.getInstance().openHistoryQueryWhenLiteFN
            && filterMethods.contains(call.getMethodDescriptor().getFullMethodName())) {
      call.close(Status.UNAVAILABLE
              .withDescription("this API is closed because this node is a lite fullnode"), headers);
      return new ServerCall.Listener<ReqT>() {};
    } else {
      return next.startCall(call, headers);
    }
  }

  @Override
  public void doFilter(ServletRequest servletRequest, ServletResponse servletResponse,
                       FilterChain filterChain) throws IOException, ServletException {
    String contextPath = ((HttpServletRequest) servletRequest).getContextPath();
    String requestPath = contextPath + ((HttpServletRequest) servletRequest).getServletPath();
    if (chainBaseManager.isLiteNode()
            && !CommonParameter.getInstance().openHistoryQueryWhenLiteFN
            && filterPaths.contains(requestPath)) {
      servletResponse.setContentType("application/json; charset=utf-8");
      servletResponse.getWriter().write("this API is closed because this node is a lite fullnode");
    } else {
      filterChain.doFilter(servletRequest, servletResponse);
    }
