### Title
WASM Contract Loading Work Uncharged on `MethodNotFound`/`MethodEmptyName` Errors Enables Fee Payment Bypass — (`runtime/near-vm-runner/src/wasmtime_runner/mod.rs`, `runtime/near-vm-runner/src/logic/logic.rs`)

---

### Summary

On stable protocol (PV ≤ 128, `fix_contract_loading_cost = false`), calling a WASM contract with a non-existent or empty method name causes the VM to perform the full WASM loading pipeline (cache lookup, deserialization, host-function linking, `instantiate_pre`) but returns a **zero-gas NOP outcome**, completely discarding any loading fee that was charged into the gas counter. An unprivileged user can deploy a large contract and repeatedly call it with an unknown method selector, causing O(code\_size) loading work on every validator while paying only the fixed `FunctionCall` exec fee.

---

### Finding Description

**Execution path on stable (PV 86):**

`WasmtimeVM::with_compiled_and_loaded` (`wasmtime_runner/mod.rs:688`) performs the full loading pipeline — cache lookup, `Module::deserialize`, memory-export resolution, `Linker` construction, host-function linking, and `instantiate_pre` — **before** any method-name check or loading-fee charge. [1](#0-0) 

After the pipeline completes, `after_loading_executable` is called. Because `fix_contract_loading_cost = false` on stable, this is where the loading fee (`contract_loading_base + contract_loading_bytes × code_len`) is charged into the `GasCounter`: [2](#0-1) 

The closure then checks whether the requested method exists in the module. If not, it stores `PreparationResult::OutcomeAbortButNopInOldProtocol(MethodNotFound)`: [3](#0-2) 

In `PreparedContract::run`, `OutcomeAbortButNopInOldProtocol` dispatches to `VMOutcome::abort_but_nop_outcome_in_old_protocol`: [4](#0-3) 

Because `fix_contract_loading_cost = false`, this returns `VMOutcome::nop_outcome(error)` — a **brand-new outcome struct** with `burnt_gas: Gas::ZERO` and `used_gas: Gas::ZERO`, completely discarding the loading fee that was charged into the counter: [5](#0-4) [6](#0-5) 

The runtime then folds `outcome.burnt_gas = 0` and `outcome.used_gas = 0` into the `ActionResult`: [7](#0-6) 

**`MethodEmptyName` variant:** `before_loading_executable` rejects an empty method name before `after_loading_executable` charges the loading fee, but the full loading pipeline (deserialize, link, `instantiate_pre`) already ran. The outcome is `OutcomeAbort` which reads the gas counter — but since no loading fee was charged yet, `burnt_gas = 0`: [8](#0-7) 

**`MethodNotFound` at call time:** The `call()` function also returns `RunOutcome::AbortNop(MethodNotFound)` when the method is absent at instantiation time, which also routes through `abort_but_nop_outcome_in_old_protocol`: [9](#0-8) [10](#0-9) 

The existing test suite explicitly documents this zero-gas behavior for the pre-fix protocol: [11](#0-10) [12](#0-11) 

The `fix_contract_loading_cost` flag is nightly-only at PV 129 and is **not active on stable PV 86**: [13](#0-12) [14](#0-13) 

Similarly, `RejectEmptyMethodName` (which would block empty-method transactions at validation) is also nightly-only and not active on stable: [15](#0-14) 

---

### Impact Explanation

**Fee payment bypass.** The `FunctionCall` exec fee (a small fixed cost) is charged at the action level before the VM runs. The WASM loading fee — `contract_loading_base + contract_loading_bytes × code_len` — is proportional to contract size and is meant to compensate validators for the deserialization and instantiation work. When `MethodNotFound` or `MethodEmptyName` is returned, this proportional fee is silently discarded. An attacker deploying a 1 MB contract and calling it with an unknown selector causes O(1 MB) loading work on every validator while paying only the fixed exec fee. The chunk-level gas accounting (`total.compute`) also sees zero contribution from these calls, allowing more such receipts to be packed into a single chunk than the gas limit should permit.

---

### Likelihood Explanation

Any unprivileged NEAR account can deploy a contract and submit `FunctionCall` transactions with arbitrary `method_name` strings. No special permissions, validator access, or privileged role is required. The attack is reachable through the standard JSON-RPC transaction submission path. The WASM loading cache (in-memory LRU + on-disk) mitigates repeated calls to the same contract on the same node, but the first call per cache miss — and calls across validators that have evicted the entry — remain fully uncharged.

---

### Recommendation

Activate `FixContractLoadingCost` on stable (lower its protocol version gate from nightly PV 129 to the next stable release). When `fix_contract_loading_cost = true`, `before_loading_executable` pre-charges the loading fee before any method-name check, and `OutcomeAbortButNopInOldProtocol` becomes a gas-bearing `abort` rather than a zero-gas `nop_outcome`. The fix is already fully implemented in the codebase: [16](#0-15) 

As a complementary measure, activating `RejectEmptyMethodName` on stable eliminates the `MethodEmptyName` variant at transaction-validation time, before any receipt is created.

---

### Proof of Concept

The existing test `test_export_not_found` in `runtime/near-vm-runner/src/tests/runtime_errors.rs` directly demonstrates the issue:

```
// Pre-fix (stable PV 86):
VMOutcome: balance 0 storage_usage 0 return data None burnt gas 0 used gas 0
Err: MethodNotFound

// Post-fix (nightly PV 129):
VMOutcome: balance 4 storage_usage 12 return data None burnt gas 72481993 used gas 72481993
Err: MethodNotFound
``` [17](#0-16) 

To reproduce against a live node: deploy any WASM contract, then submit a `FunctionCall` transaction with `method_name = "nonexistent_____"`. The receipt outcome will show `gas_burnt = 0` and `tokens_burnt = 0` despite the node performing full WASM loading work. The integration test `test_smart_contract_bad_method_name` confirms this behavior reaches the full runtime stack: [18](#0-17)

pub fn test_smart_contract_bad_method_name(node: impl Node) {
    let account_id = &node.account_id().unwrap();
    let node_user = node.user();
    let root = node_user.get_state_root();
    let transaction_result = node_user
        .function_call(
            account_id.clone(),
            bob_account(),
            "_run_test",
            vec![],
            Gas::from_teragas(100),
            Balance::ZERO,
        )
        .unwrap();
    assert_eq!(
        transaction_result.status,
        FinalExecutionStatus::Failure(
            ActionError {
                index: Some(0),
                kind: ActionErrorKind::FunctionCallError(FunctionCallError::MethodResolveError(
                    MethodResolveError::MethodNotFound
                ))
            }
            .into()
        )
    );
    // Refund receipt may not be ready yet
    assert!([1, 2].contains(&transaction_result.receipts_outcome.len()));
    let new_root = node_user.get_state_root();
    assert_ne!(root, new_root);
}
