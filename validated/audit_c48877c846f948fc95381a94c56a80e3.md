### Title
Expired TRC10 asset tokens can still be freely transferred via `TransferAssetContract` - (File: `actuator/src/main/java/org/tron/core/actuator/TransferAssetActuator.java`)

### Summary
java-tron's TRC10 asset model has an analogous "expiry" concept to the reported Option contract: every `AssetIssueContract` carries a `start_time`/`end_time` validity window, and once `now >= endTime`, the protocol blocks new *participation* (an operation loosely analogous to "minting"/"exercising" more tokens of that asset from the issuer) in `ParticipateAssetIssueActuator`. However, ordinary balance transfers of that same asset via `TransferAssetContract`/`TransferAssetActuator` never check the asset's `start_time`/`end_time` at all, so already-issued asset balances keep circulating freely forever, even long after the asset has expired.

### Finding Description
`AssetIssueContract` defines `start_time` and `end_time` fields governing the asset's validity window. [1](#0-0) 

`ParticipateAssetIssueActuator.validate()` enforces this window explicitly, rejecting participation once the asset has expired: [2](#0-1) 

In contrast, `TransferAssetActuator`, which moves already-held TRC10 asset balances between arbitrary accounts, performs no lookup of `getStartTime()`/`getEndTime()` anywhere in its `validate()` or `execute()` methods — it only checks address validity, positive amount, asset existence, and sufficient balance: [3](#0-2) [4](#0-3) 

This mirrors the reported bug class precisely: the protocol treats the "issuance/exchange" pathway (`ParticipateAssetIssueContract`, analogous to minting/exercising an option) as subject to expiry, but the plain transfer pathway (`TransferAssetContract`, analogous to option token transfer) is not, so a holder can keep selling/transferring an expired asset that no one can any longer obtain fresh supply of through the issuer-facing mechanism.

### Impact Explanation
A malicious holder of an expired TRC10 token can transfer/sell it on exchanges or to counterparties who reasonably assume the token's `end_time` (a first-class, on-chain, documented field of `AssetIssueContract`) means the asset is no longer active. Because `TransferAssetActuator` never inspects `end_time`, the transfer will succeed unconditionally as long as normal balance/account checks pass, allowing continued circulation of a token whose issuance mechanism has been shut off. This can mislead integrators (wallets, DEXs) that rely on `end_time` semantics to gate acceptance of a token, causing them to unknowingly accept/trade a token the protocol itself considers past its validity period.

### Likelihood Explanation
High reachability: `TransferAssetContract` is a standard, unprivileged broadcast transaction type available to any TRC10 holder; no special permission or contract-owner role is required. Any account holding a balance of an asset whose `end_time` has passed can trigger this via a normal broadcast transaction.

### Recommendation
Decide and document the intended semantics of `end_time` for TRC10 assets. If transfers of expired assets should be blocked (consistent with blocking `ParticipateAssetIssueContract`), add an expiry check (`now >= assetIssueCapsule.getEndTime()`) in `TransferAssetActuator.validate()` similar to the one already present in `ParticipateAssetIssueActuator.validate()`. If expired transfers are intentionally allowed (e.g., to let holders move or redeem balances after expiry), explicitly document this divergence between "participation" and "transfer" semantics so integrators do not assume `end_time` gates all operations on the asset.

### Proof of Concept
1. Issue a TRC10 asset with `start_time`/`end_time` set to a near-future short window via `AssetIssueContract` (validated in `AssetIssueActuator.validate()`). [5](#0-4) 
2. Wait until `now >= end_time`. Attempt a `ParticipateAssetIssueContract` for that asset — it fails with `"No longer valid period!"` as shown in `ParticipateAssetIssueActuator.validate()` line 179.
3. Broadcast a `TransferAssetContract` moving the same expired asset's already-held balance between two unrelated accounts — `TransferAssetActuator.validate()`/`execute()` contain no time check and the transfer succeeds normally.

  @Override
  public boolean execute(Object result) throws ContractExeException {
    TransactionResultCapsule ret = (TransactionResultCapsule) result;
    if (Objects.isNull(ret)) {
      throw new RuntimeException(ActuatorConstant.TX_RESULT_NULL);
    }

    long fee = calcFee();
    AccountStore accountStore = chainBaseManager.getAccountStore();
    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    AssetIssueStore assetIssueStore = chainBaseManager.getAssetIssueStore();
    try {
      TransferAssetContract transferAssetContract = this.any.unpack(TransferAssetContract.class);
      byte[] ownerAddress = transferAssetContract.getOwnerAddress().toByteArray();
      byte[] toAddress = transferAssetContract.getToAddress().toByteArray();
      AccountCapsule toAccountCapsule = accountStore.get(toAddress);
      if (toAccountCapsule == null) {
        boolean withDefaultPermission =
            dynamicStore.getAllowMultiSign() == 1;
        toAccountCapsule = new AccountCapsule(ByteString.copyFrom(toAddress), AccountType.Normal,
            dynamicStore.getLatestBlockHeaderTimestamp(), withDefaultPermission, dynamicStore);
        accountStore.put(toAddress, toAccountCapsule);

        fee = fee + dynamicStore.getCreateNewAccountFeeInSystemContract();
      }
      ByteString assetName = transferAssetContract.getAssetName();
      long amount = transferAssetContract.getAmount();

      AccountCapsule ownerAccountCapsule = accountStore.get(ownerAddress);
      if (!ownerAccountCapsule
          .reduceAssetAmountV2(assetName.toByteArray(), amount, dynamicStore, assetIssueStore)) {
        throw new ContractExeException("reduceAssetAmount failed !");
      }
      accountStore.put(ownerAddress, ownerAccountCapsule);

      toAccountCapsule
          .addAssetAmountV2(assetName.toByteArray(), amount, dynamicStore, assetIssueStore);
      accountStore.put(toAddress, toAccountCapsule);

      adjustBalance(accountStore, ownerAccountCapsule, -fee);
      if (dynamicStore.supportBlackHoleOptimization()) {
        dynamicStore.burnTrx(fee);
      } else {
        adjustBalance(accountStore, accountStore.getBlackhole(), fee);
      }
      ret.setStatus(fee, code.SUCESS);
    } catch (BalanceInsufficientException e) {
      logger.debug(e.getMessage(), e);
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    } catch (InvalidProtocolBufferException | ArithmeticException e) {
      ret.setStatus(fee, code.FAILED);
      throw new ContractExeException(e.getMessage());
    }

    return true;
  }
