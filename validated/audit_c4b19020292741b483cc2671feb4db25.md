This confirms the analysis: `GetOrCreateBallot` returns the existing ballot on subsequent votes without refreshing `EligibleVoters` [1](#0-0) , and `Ballot.EligibleVoters`/`Votes` are frozen at creation time via `NewBallot` [2](#0-1) . Finalization logic (`CheckIfFinalizingVote`/`ShouldPass`/`ShouldReject`) only counts votes already stored in `ballot.Votes`, with no live check against current UV/staking status [3](#0-2) . The only mechanism that prunes stale votes from removed/unbonded/tombstoned validators is `RecomputeBallotQuorum`, which is admin-gated and must be manually invoked per stuck ballot [4](#0-3) [5](#0-4) . This is exactly the guardian-votes bug class: a validator can vote, then get removed, and its stale vote still counts toward automatic quorum unless an admin manually recomputes that specific ballot.

### Title
Stale votes from removed/unbonded/tombstoned Universal Validators still count toward automatic ballot quorum - (File: x/uvalidator/keeper/ballot.go, x/uvalidator/keeper/voting.go, x/uvalidator/types/ballot.go)

### Summary
`x/uvalidator`'s generic ballot machine (used by inbound/outbound/chain-meta voting in `x/uexecutor` and TSS/fund-migration voting in `x/utss`) snapshots `EligibleVoters` and `Votes` once, at ballot creation. Once a validator casts a vote, that vote remains in `ballot.Votes` and is counted by `CheckIfFinalizingVote`/`ShouldPass`/`ShouldReject` for automatic PASSED/REJECTED finalization even if the voter is subsequently removed, unbonded, jailed, or tombstoned. The only remediation, `RecomputeBallotQuorum`, is an admin-only, per-ballot manual escape hatch — it is not applied automatically during normal `VoteOnBallot` flow.

### Finding Description
`VoteOnBallot` calls `GetOrCreateBallot`, which — on any call after the first — returns the already-stored ballot unchanged, ignoring the freshly computed `voters`/`votesNeeded` arguments passed by the caller [1](#0-0) . This is confirmed by the integration test explicitly asserting the original 1-voter list persists even when a caller passes a full 3-voter list on the second call [6](#0-5) .

`AddVoteToBallot` → `Ballot.AddVote` writes the vote into `b.Votes[idx]` using the index from the original (frozen) `EligibleVoters` snapshot, with no re-validation that `address` is still a live, bonded, non-tombstoned UV at time of voting [7](#0-6) .

`CheckIfFinalizingVote`/`ShouldPass`/`ShouldReject`/`IsFinalizingVote` compute yes/no counts purely from `b.Votes`, with zero cross-check against current UV status [3](#0-2) [8](#0-7) . Meanwhile `GetEligibleVoters` (used to compute `votesNeeded` fresh on every `VoteOnInboundBallot`/`VoteOnOutboundBallot`/`VoteOnTssBallot`/`VoteOnFundMigrationBallot` call) explicitly filters out unbonded/jailed/tombstoned/non-ACTIVE UVs [9](#0-8) , so the codebase clearly recognizes that stranded validators shouldn't count — yet this filtering is applied only to compute the *threshold denominator* going forward, never retroactively to already-cast votes stored in a still-pending ballot's `Votes` array.

The remediation path — `RecomputeBallotQuorum` — exists specifically to drop stale votes and shrink the eligible set/threshold [10](#0-9) , but it is (a) restricted to `params.Admin` [5](#0-4) , and (b) must be invoked per ballot ID manually — it is never triggered automatically from `RemoveUniversalValidator`, `UpdateUniversalValidatorStatus`, tombstoning, or unbonding events. The module's own regression-test naming (`F-2026-16991`, "deadlock-prevention case") shows the team is aware stranded-voter inflation of the denominator is a known bug class [11](#0-10) , but the fix only touches the *eligible voter count* used for new/ongoing threshold computation, not the *already-cast votes* baked into a pending ballot from a validator later removed.

### Impact Explanation
Because inbound/outbound/chain-meta/TSS-event/fund-migration ballots gate real state transitions — inbound execution (PRC20 mint, UEA payload execution), outbound settlement, TSS keygen finalization, and fund migration — a ballot that finalizes prematurely because it still contains a now-removed validator's stale vote can let an inbound/outbound/TSS/migration observation reach PASSED with fewer *currently* trustworthy attestations than the protocol's designed 2/3 threshold. In an environment where validator set churn (removal, jailing, tombstoning) happens between vote casting and finalization, this weakens the safety margin that finalization is supposed to guarantee, since a stale/no-longer-trusted vote from a former UV is treated identically to a fresh one, potentially allowing quorum with fewer live, accountable UVs behind a finalized inbound mint or outbound release.

### Likelihood Explanation
This requires no attacker privilege beyond ordinary protocol operation: any validator that is later removed/unbonded/jailed/tombstoned while it has an outstanding vote on a still-pending ballot leaves that stale vote counted. Given normal validator set churn (slashing for downtime/double-sign, voluntary unbonding, admin removal) and the multi-block window ballots stay PENDING before reaching threshold, this is a plausible, non-privileged occurrence rather than a contrived edge case.

### Recommendation
Either (a) re-validate voter eligibility at the moment `CheckIfFinalizingVote`/`ShouldPass`/`ShouldReject` tally votes (cross-checking against `GetEligibleVoters` or per-voter bonded/tombstone status) before counting a cast vote toward YES/NO, or (b) automatically invoke the equivalent of `RecomputeBallotQuorum` for all ballots referencing a validator whenever that validator's UV status transitions to non-eligible (removal, tombstoning, unbonding), rather than relying solely on a manual, admin-gated per-ballot escape hatch.

### Proof of Concept
1. Register UVs A, B, C, D (4 total; 2/3+1 threshold = 3).
2. A source event triggers a `MsgVoteInbound`/`MsgVoteOutbound`; A and B vote SUCCESS — ballot now has 2/4 YES, threshold 3, still PENDING.
3. Validator C is slashed/tombstoned or unbonds (or admin calls `RemoveUniversalValidator` on C) before C ever votes — but this does not touch ballot state at all since only A and B had cast votes so far; skip to D.
4. Suppose instead B already voted, then B is tombstoned/unbonded/removed. The ballot retains B's previously cast SUCCESS vote in `ballot.Votes` — no automatic mechanism removes it.
5. D votes SUCCESS. `CheckIfFinalizingVote` now sees YES=3 (A, B[stale], D) ≥ threshold 3 and finalizes PASSED, executing the inbound/outbound, even though B is no longer a trusted, accountable UV — matching `test/integration/uvalidator/recompute_ballot_quorum_test.go`'s explicit demonstration that `RecomputeBallotQuorum` is required to drop such stale votes, and that without calling it, the stale vote persists [12](#0-11) .

```go
// RecomputeBallotQuorum rebuilds a pending ballot's eligible-voter list and
// voting threshold against the current eligible-voter set, preserving votes
// from voters still eligible and dropping votes from voters no longer eligible.
//
// If the recomputed eligible count is zero, the ballot is marked EXPIRED (no
// path to finalization). Otherwise it stays PENDING with the new parameters;
// downstream UVs must re-vote on the same ballot to trigger finalize+execute
// via the normal flow.
//
// Returns the old/new counts and threshold for the response.
func (k Keeper) RecomputeBallotQuorum(ctx context.Context, ballotID string) (
	oldEligibleCount, newEligibleCount, oldThreshold, newThreshold int64,
	newStatus types.BallotStatus,
	err error,
) {
	ballot, err := k.Ballots.Get(ctx, ballotID)
	if err != nil {
		return 0, 0, 0, 0, 0, fmt.Errorf("ballot %s not found: %w", ballotID, err)
	}

	if ballot.Status != types.BallotStatus_BALLOT_STATUS_PENDING {
		return 0, 0, 0, 0, 0, fmt.Errorf("ballot %s is not pending (status=%s); only pending ballots can be recomputed", ballotID, ballot.Status.String())
	}

	oldEligibleCount = int64(len(ballot.EligibleVoters))
	oldThreshold = ballot.VotingThreshold

	// Build the current eligible-voter set in the same valoper-bech32 format
	// the ballot already uses. The voting flow (VoteOnInboundBallot/VoteOnOutboundBallot)
	// passes CoreValidatorAddress strings directly into VoteOnBallot, so the
	// stored EligibleVoters list contains valoper bech32 addresses.
	eligibleUVs, err := k.GetEligibleVoters(ctx)
	if err != nil {
		return 0, 0, 0, 0, 0, fmt.Errorf("failed to fetch eligible voters: %w", err)
	}

	newVoters := make([]string, 0, len(eligibleUVs))
	for _, uv := range eligibleUVs {
		if uv.IdentifyInfo == nil || uv.IdentifyInfo.CoreValidatorAddress == "" {
			k.Logger().Warn("recompute: skipping UV with missing identity info")
			continue
		}
		newVoters = append(newVoters, uv.IdentifyInfo.CoreValidatorAddress)
	}
	newEligibleCount = int64(len(newVoters))

	// Zero eligible voters: no path to finalization. Mark EXPIRED.
	if newEligibleCount == 0 {
		if err := k.MarkBallotExpired(ctx, ballotID); err != nil {
			return 0, 0, 0, 0, 0, fmt.Errorf("failed to mark ballot expired on zero-eligible recompute: %w", err)
		}
		k.Logger().Info("ballot recompute: zero eligible voters → marked expired",
			"ballot_id", ballotID,
			"old_eligible", oldEligibleCount,
		)
		return oldEligibleCount, 0, oldThreshold, 0, types.BallotStatus_BALLOT_STATUS_EXPIRED, nil
	}

	// Compute new threshold using the same formula uexecutor's voting flow uses.
	// We use 2/3 + 1 — matches `(VotesThresholdNumerator * N) / VotesThresholdDenominator + 1`.
	newThreshold = (2*newEligibleCount)/3 + 1

	// Preserve votes from voters still in the new list; new voters → NOT_YET.
	oldVotes := make(map[string]types.VoteResult, len(ballot.EligibleVoters))
	for i, voter := range ballot.EligibleVoters {
		if i < len(ballot.Votes) {
			oldVotes[voter] = ballot.Votes[i]
		}
	}
	newVotesArr := make([]types.VoteResult, len(newVoters))
	for i, voter := range newVoters {
		if prev, ok := oldVotes[voter]; ok {
			newVotesArr[i] = prev
		} else {
			newVotesArr[i] = types.VoteResult_VOTE_RESULT_NOT_YET_VOTED
		}
	}

	ballot.EligibleVoters = newVoters
	ballot.Votes = newVotesArr
	ballot.VotingThreshold = newThreshold

	if err := k.Ballots.Set(ctx, ballotID, ballot); err != nil {
		return 0, 0, 0, 0, 0, fmt.Errorf("failed to persist recomputed ballot: %w", err)
	}

	k.Logger().Info("ballot recomputed",
		"ballot_id", ballotID,
		"old_eligible", oldEligibleCount,
		"new_eligible", newEligibleCount,
		"old_threshold", oldThreshold,
		"new_threshold", newThreshold,
	)

	return oldEligibleCount, newEligibleCount, oldThreshold, newThreshold, types.BallotStatus_BALLOT_STATUS_PENDING, nil
```

```go
func (b Ballot) AddVote(address string, vote VoteResult) (Ballot, error) {
	if b.Status != BallotStatus_BALLOT_STATUS_PENDING {
		return b, fmt.Errorf("cannot vote on ballot %s: not pending", b.Id)
	}

	idx := b.GetVoterIndex(address)
	if idx == -1 {
		return b, fmt.Errorf("voter %s not eligible", address)
	}

	if b.HasVoted(address) {
		return b, fmt.Errorf("voter %s already voted", address)
	}

	b.Votes[idx] = vote
	return b, nil
}
```

```go
// IsFinalizingVote checks if the ballot is reaching the finalization in this tx
func (b Ballot) IsFinalizingVote() (Ballot, bool) {
	// Only pending ballots can still be finalized
	if b.Status != BallotStatus_BALLOT_STATUS_PENDING {
		return b, false
	}

	// Count votes
	yesVotes := 0
	noVotes := 0
	for _, v := range b.Votes {
		switch v {
		case VoteResult_VOTE_RESULT_SUCCESS:
			yesVotes++
		case VoteResult_VOTE_RESULT_FAILURE:
			noVotes++
		}
	}

	// If YES or NO has reached/exceeded threshold → finalizing
	if int64(yesVotes) >= b.VotingThreshold {
		b.Status = BallotStatus_BALLOT_STATUS_PASSED
		return b, true
	}
	if int64(noVotes) >= b.VotingThreshold {
		b.Status = BallotStatus_BALLOT_STATUS_REJECTED
		return b, true
	}

	return b, false
}
```

```go
// GetEligibleVoters returns all validators that are eligible to vote on external transactions.
//
// Eligibility requires BOTH:
//   - UV lifecycle status is ACTIVE or PENDING_JOIN; AND
//   - the underlying Cosmos staking validator is bonded and not tombstoned.
//
// The staking-state filter prevents stranded UVs (still ACTIVE on paper but
// unbonded/jailed/tombstoned on the base chain) from inflating the ballot
// quorum denominator. Vote admission already rejects such signers, so without
// this filter the ballot threshold can become unreachable and finalization
// deadlocks.
func (k Keeper) GetEligibleVoters(ctx context.Context) ([]types.UniversalValidator, error) {
	var voters []types.UniversalValidator
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	err := k.UniversalValidatorSet.Walk(ctx, nil, func(addr sdk.ValAddress, val types.UniversalValidator) (stop bool, err error) {
		switch val.LifecycleInfo.CurrentStatus {
		case types.UVStatus_UV_STATUS_ACTIVE, types.UVStatus_UV_STATUS_PENDING_JOIN:
		default:
			return false, nil
		}

		sv, getErr := k.StakingKeeper.GetValidator(ctx, addr)
		if getErr != nil {
			// Validator removed from staking module, or some other read error:
			// treat as ineligible for this call rather than failing the whole
			// walk. This keeps quorum computable when one stranded entry would
			// otherwise crash the read path.
			k.Logger().Debug("eligible voter filter: staking GetValidator failed", "validator", addr.String(), "err", getErr)
			return false, nil
		}
		if !sv.IsBonded() {
			return false, nil
		}
		consAddr, caErr := sv.GetConsAddr()
		if caErr != nil {
			k.Logger().Debug("eligible voter filter: GetConsAddr failed", "validator", addr.String(), "err", caErr)
			return false, nil
		}
		if k.SlashingKeeper.IsTombstoned(sdkCtx, consAddr) {
			return false, nil
		}

		voters = append(voters, val)
		return false, nil
	})
```
