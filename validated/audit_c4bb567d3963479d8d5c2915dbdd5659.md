## Analysis Result

### Title
Starknet OS `execute_replace_class` accepts undeclared class hashes, diverging from Blockifier's validated `replace_class` syscall — ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS's Cairo implementation of the `replace_class` syscall never validates that the supplied `class_hash` corresponds to an actually declared class before writing it into the contract's state entry, unlike every Blockifier execution path (VM, Cairo0/deprecated, and Native), which explicitly requires the class to be declared before allowing the replacement.

### Finding Description
`execute_replace_class` in the Starknet OS carries an explicit acknowledgment that the check is missing: [1](#0-0) 

The comment on line 902 states: `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` Immediately after, the function unconditionally builds a new `StateEntry` with the caller-supplied `class_hash` and commits it via `dict_update`, with no read/verification that this class hash was ever declared.

By contrast, every Blockifier execution path performs this check before mutating contract state:
- The Cairo0/deprecated syscall handler explicitly reads the compiled class before setting the new class hash: [2](#0-1) 
- Cairo1 tests confirm this behavior is enforced end-to-end, rejecting undeclared class hashes with `"is not declared"`: [3](#0-2) 
- The positive/negative flows are exercised for both VM and Native runners, showing the check is load-bearing production logic, not test-only scaffolding: [4](#0-3) 

This mirrors the reported bug class exactly: a state-critical field (here, a contract's installed class hash, analogous to the vault's IRM) can be set to an invalid/"faulty" value (an undeclared, nonexistent class) because one code path lacks the sanity check that a sibling code path enforces, and the write proceeds anyway.

### Impact Explanation
The Starknet OS is the component that re-executes the block and produces the committed state (used for the state/class commitment trees and ultimately the block hash accepted on L1). If a contract invokes `replace_class_syscall` with an undeclared class hash:
- Blockifier (used for sequencer block building/simulation and full-node re-execution) will reject the call — the entry-point call fails with "is not declared."
- The OS, lacking this validation, will accept the same call and commit a `StateEntry` pointing the contract at a nonexistent class into the state diff that determines the final committed root.

This produces two concrete, in-scope harms:
1. **Honest-node divergence / wrong committed root**: Nodes executing via Blockifier compute a different result (reverted call) than what the OS commits into the proven state root, breaking consensus between the two execution engines that are supposed to agree bit-for-bit on the state transition.
2. **Permanent freezing of the affected contract**: If such a class-hash write is nonetheless accepted into the committed state, the contract's class hash points to a class with no compiled code, making that contract (and any funds/logic gated behind it) permanently unusable — a form of permanent freezing of funds triggered by an ordinary, unprivileged transaction.

### Likelihood Explanation
The path is trivially reachable: any contract can invoke the `replace_class` syscall (`replace_class_syscall`) during normal execution — no special privileges are required, matching "unprivileged transaction sender" reachability. The vulnerable code is directly in the syscall execution routine invoked whenever this syscall selector is dispatched: [5](#0-4) 

The missing check is not hypothetical — it is explicitly flagged as an unfinished TODO in the source, confirming the gap exists in the current codebase rather than being a misreading of intended behavior.

### Recommendation
Add the missing declared-class check in `execute_replace_class` (OS) to match Blockifier: before constructing/committing the new `StateEntry`, verify that `class_hash` has an associated compiled class in the OS's class dictionary (mirroring the `get_compiled_class` check done by Blockifier), and fail/revert the syscall analogously when the class is undeclared, ensuring both execution engines reject the same invalid inputs identically.

### Proof of Concept
1. Declare and deploy a contract exposing a wrapper around `replace_class_syscall` (as in the existing test contracts, e.g. `test_replace_class`).
2. Submit an invoke transaction from any account calling that entry point with an arbitrary, never-declared `class_hash` felt (e.g., `0x1234`).
3. Under Blockifier (`crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs:17-29`), the call reverts with `"is not declared"`.
4. When the same block/transaction is re-executed by the Starknet OS (`execute_replace_class` in `syscall_impls.cairo`), no equivalent check exists (line 902 TODO), so the OS proceeds to commit a `StateEntry` with the undeclared `class_hash` for that contract into `contract_state_changes`, producing a state diff/commitment inconsistent with what Blockifier computed for the same transaction.

**Uncertainty note:** I was unable to fully trace whether the OS's Cairo-hint-driven state read (`%{ GetContractAddressStateEntry %}`) or an outer wrapper elsewhere in the OS pipeline performs a class-declaration check before or after this function is called (e.g., during final commitment-tree assembly), which would mitigate or negate the divergence. The explicit TODO comment strongly suggests no such check currently exists, but confirming the full downstream commitment pipeline would require further review of the OS's block-hash/commitment-tree construction code, which is not fully covered here.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
