## #CVE-Analog Found

### Title
Global compiled-class cache skips declaration re-check for Cairo0 classes, allowing use of undeclared classes - (File: `crates/blockifier/src/state/state_reader_and_contract_manager.rs`)

### Summary
`StateReaderAndContractManager::get_compiled_from_class_manager` serves compiled classes from a process-wide `ContractClassManager` cache. For Cairo1 classes it re-validates that the class is still actually declared in the current state before trusting a cache hit, but for Cairo0 ("deprecated") classes it skips this check entirely, trusting the cache blindly.

### Finding Description
The relevant logic:
```rust
if let Some(runnable_class) =
    self.contract_class_manager.get_runnable(&class_hash, &self.native_classes_whitelist)
{
    match &runnable_class {
        RunnableCompiledClass::V0(_) => {}
        _ => {
            // The Cairo1 class is cached; verify it is declared,
            // since existence in the cache does not guarantee that
            // (it might contain a declared class from a reverted block, for example).
            if !self.state_reader.is_declared(class_hash)? {
                return Err(StateError::UndeclaredClassHash(class_hash));
            }
        }
    }
    ...
    return Ok(runnable_class);
}
``` [1](#0-0) 

The comment explicitly acknowledges the underlying threat model: **cache existence does not imply current declaration status**, e.g. from a reverted block. This check is applied only to non-V0 classes because the `is_declared` contract is documented as only supporting Cairo1:
```rust
/// Returns whether the given class hash corresponds to a declared Cairo 1 class.
/// Cairo 0 classes always return `false`.
fn is_declared(&self, class_hash: ClassHash) -> StateResult<bool>;
``` [2](#0-1) 

Because `is_declared` cannot express "declared V0", the code was written to bypass the re-check for `RunnableCompiledClass::V0` rather than implementing an equivalent authoritative check (e.g. via `get_class_definition_block_number`) — this gap is confirmed by a `TODO` in a sibling reader:
```rust
// TODO(shahak): Verify cairo0 as well after get_class_definition_block_number is fixed.
ContractClass::V0(deprecated_contract_class) => {
    Ok(RunnableCompiledClass::V0(deprecated_contract_class.try_into()?))
}
``` [3](#0-2) 

This is the same bug class as CVE-2022-30256 ("stale/undeclared resource remains resolvable/usable after it should no longer be valid due to caching that bypasses authoritative revalidation"): the `ContractClassManager` cache (`GlobalContractCache`) is a shared, long-lived, process-global structure explicitly designed for cross-component/cross-request reuse (`crates/starknet_api/src/class_cache.rs`), and once a Cairo0 class hash is populated into it (e.g. via gateway-side validation of a Declare transaction, fee-estimation/simulation calls, or a transaction that is ultimately not committed/is part of a reverted block), any later, unrelated transaction that references that same class hash (DeployAccount, `replace_class` syscall) will retrieve the compiled class and be permitted to execute against it without any check that the class hash is actually present in the canonical declared-classes set for the current state.

### Impact Explanation
If a class hash becomes cached without ever being canonically declared (e.g. from processing/estimating/validating a transaction that never lands in a committed block, or a class from a subsequently reverted block, as the code's own comment anticipates), a completely different, unprivileged actor's later transaction can deploy a contract or replace a class using that class hash, bypassing the "class must be declared" consensus invariant. Since the resulting state and behavior depend on each sequencer/full node's specific execution and cache history (rather than solely on canonical committed state), this can produce **honest-node divergence and wrong state roots**, and constitutes an **unauthorized account action** (executing/deploying code that was never actually declared through the protocol's declare mechanism).

### Likelihood Explanation
The trigger requires only ordinary, unprivileged actions: submitting a Cairo0 Declare (or referencing a Cairo0 class hash in a fee-estimation/simulation/validation call) followed by a DeployAccount or `replace_class` transaction pointing at the same class hash, exploiting the fact that class hashes are deterministic/content-addressed and can be computed offline without ever being declared on-chain. The exact reachability depends on deployment topology (whether gateway/validation and block-execution components share the same `ContractClassManager` instance), which could not be fully confirmed from the available index; this is an architectural detail that would need runtime/deployment verification.

### Recommendation
Extend `FetchCompiledClasses::is_declared` (or add an analogous authoritative check) to also verify Cairo0/deprecated declaration status at fetch-cache-hit time, mirroring the Cairo1 path, rather than unconditionally trusting `V0` cache hits. Alternatively, invalidate/scope the global class cache per state view so that classes cannot be treated as valid outside of the state in which they were actually declared.

### Proof of Concept
Conceptual reproduction (not fully verified against a live deployment):
1. Compute a Cairo0 (deprecated) contract's class hash offline (deterministic from bytecode), without declaring it on-chain.
2. Cause that class hash to be populated into the shared `ContractClassManager` cache without it ever being committed as a declared class — e.g., submit it via `starknet_estimateFee`/`starknet_simulateTransactions`, or via a Declare transaction that later fails to be included/committed (e.g., rejected after passing initial fee-estimation/validation which invoked `get_compiled_from_class_manager` and populated the cache via `set_and_compile`, as seen at [4](#0-3) ).
3. Submit a `DeployAccount` transaction (or an Invoke that calls `replace_class`) referencing that same class hash.
4. Because the class hash resolves to `RunnableCompiledClass::V0`, the `is_declared` check is skipped entirely (lines 73-74 of `state_reader_and_contract_manager.rs`), and the transaction succeeds using a class that was never canonically declared, diverging from a node that never had this class cached.
