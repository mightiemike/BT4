## Answer

Yes — this leads to a real vulnerability. The root cause is that the Solana event listener does not verify that a `"Program data: "` log line was actually emitted by the gateway program itself; it only checks that the line exists anywhere in `tx.Meta.LogMessages` and that its first 8 decoded bytes match a known discriminator.

### How the forgery works

`processSignatureBatch` fetches candidate signatures via `GetSignaturesForAddress(gatewayAddr, ...)` [1](#0-0) , but Solana's `getSignaturesForAddress` matches *any* transaction that merely references the given pubkey as an account key — it does not require that the gateway program was invoked as a top-level or CPI instruction. An attacker can therefore submit an ordinary transaction that:
1. Passes the real gateway program ID as an arbitrary (even unused, readonly) account to an instruction targeting the attacker's own deployed program.
2. Has that attacker-controlled program emit its own `"Program data: <base64>"` log (e.g. via Anchor's `emit!`/`sol_log_data`, which any program can call) whose first 8 bytes equal the known `sendFunds` Anchor discriminator (`sha256("global:sendFunds")[:8]`, a public, deterministic value), followed by an arbitrary Borsh-encoded payload.

`determineEventType` then blindly classifies this line by discriminator alone [2](#0-1) , and `ParseEvent`/`parseSendFundsEvent` decode the attacker-controlled bytes into a `store.Event` with no check that the log came from within the gateway program's own invocation frame [3](#0-2) . `processSignatureBatch` itself never even checks `tx.Meta.Err`, so as long as the attacker's own instruction succeeds, the forged event is stored unconditionally [4](#0-3) . The later `event_confirmer` only rejects events whose *whole transaction* failed [5](#0-4)  — it does not validate log provenance either.

### Why this is not merely a local/off-chain nuisance

Because this parsing logic runs identically and deterministically on every honest Universal Validator's node against the same public, immutable transaction log, **all honest UVs will independently mis-parse the same attacker transaction the same way**, produce matching `Inbound` structs, and converge on the same ballot key (`GetInboundBallotKey`, a canonical hash over the decoded fields) [6](#0-5) . Once 2/3+ of the honest UV set votes via `MsgVoteInbound` [7](#0-6)  and `VoteOnInboundBallot` reaches quorum [8](#0-7) , `ExecuteInbound` mints PRC20 to the attacker-chosen recipient and can drive payload execution based purely on attacker-fabricated `sender`, `recipient`, `bridge_token`, `bridge_amount`, and `raw_payload` fields — with **no real funds ever locked in the Solana vault**. This satisfies the "forged inbound ... accepted through user-reachable flows with honest validators and honest nodes" and "unauthorized mint" impact criteria, without requiring any malicious validator, relayer, or TSS participant.

### Title
Forged inbound `sendFunds` event via attacker-controlled log line with matching discriminator, unauthenticated to gateway program origin — (File: `universalClient/chains/svm/event_listener.go`, `universalClient/chains/svm/event_parser.go`)

### Summary
The Solana `EventListener` classifies and parses any `"Program data: "` log line in a transaction's `LogMessages` purely by matching the first 8 bytes against known Anchor event discriminators, without verifying the log was emitted from within an actual invocation of the configured gateway program. Since Solana log lines from any program invoked in the same transaction are commingled in `logMessages`, an attacker can emit a forged discriminator-matching log from their own program in a transaction that merely references the gateway address (sufficient to be returned by `getSignaturesForAddress`), causing every honest Universal Validator to independently decode and vote a fabricated inbound event.

### Finding Description
- `processSlotRange`/`processSignatureBatch` fetch transactions scoped only by account-key inclusion of the gateway address, not by actual invocation [9](#0-8) .
- For each raw log string in `tx.Meta.LogMessages`, `determineEventType` decodes the base64 payload after the `"Program data: "` prefix and looks up the 8-byte discriminator in a map, with no association to which program emitted that specific log line [2](#0-1) .
- `ParseEvent`/`parseSendFundsEvent` then decode the remaining attacker-controlled bytes directly into `store.Event`/`UniversalTx` fields (sender, recipient, token, amount, payload, revert, tx_type, verification data) [10](#0-9) .
- No code path cross-checks the log against the transaction's instruction/program invocation stack (e.g., bracketing `"Program <id> invoke [depth]"` / `"Program <id> success"` markers) to confirm the data actually originated from the gateway program.

### Impact Explanation
Because this flawed classification is deterministic and runs identically on every honest UV, an attacker's single crafted (and otherwise harmless/self-funded) Solana transaction is enough to make the entire honest UV set converge on and finalize a forged `MsgVoteInbound` ballot. This results in unauthorized PRC20 minting / arbitrary payload execution attributed to a "bridge" event that never happened, with no real asset ever locked in the vault — a direct fund-accounting corruption/unauthorized-mint impact.

### Likelihood Explanation
Requires only an unprivileged attacker able to: (a) deploy or invoke an arbitrary Solana program, (b) know the target Anchor discriminator (derivable from the public method name, a standard convention), and (c) include the gateway program's public address as an account reference in their transaction — all ordinary, permissionless Solana operations.

### Recommendation
Only treat a `"Program data: "` log line as an authentic gateway event if it is confirmed to have been emitted from within the invocation stack of the exact configured gateway program ID (parse the surrounding `"Program <id> invoke"`/`"Program <id> success"` bracketing, or use a stricter mechanism such as matching against decoded instruction/program IDs from the transaction message rather than the flat log list). Additionally, `processSignatureBatch` should skip transactions where `tx.Meta.Err != nil` immediately at ingestion, not only later in the confirmer.

### Proof of Concept
A Go unit test can mock `GetTransaction` to return a `logMessages` slice containing an attacker-authored `"Program data: <base64(discriminator+forged fields)>"` line from a transaction whose only real instruction targets an unrelated (attacker) program, then call `processSignatureBatch` and assert that `ParseEvent`/`determineEventType` still produce and store a `store.Event`, demonstrating that provenance to the actual gateway program is never checked.

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
}

// ParseEvent parses a log into a store.Event based on the event type.
// eventType should be one of: "send_funds", "executeUniversalTx", "revertUniversalTx"
func ParseEvent(log string, signature string, slot uint64, logIndex uint, eventType string, chainID string, logger zerolog.Logger) *store.Event {
	switch eventType {
	case EventTypeSendFunds:
		return parseSendFundsEvent(log, signature, slot, logIndex, chainID, logger)
	case EventTypeFinalizeUniversalTx, EventTypeRevertUniversalTx, EventTypeFundsRescued:
		return parseOutboundObservationEvent(log, signature, slot, logIndex, chainID, logger)
	default:
		logger.Debug().
			Str("event_type", eventType).
			Str("signature", signature).
			Msg("unknown event type, skipping")
		return nil
	}
}

// parseSendFundsEvent parses a sendFunds event as UniversalTx
func parseSendFundsEvent(log string, signature string, slot uint64, logIndex uint, chainID string, logger zerolog.Logger) *store.Event {
	if !strings.HasPrefix(log, "Program data: ") {
		return nil
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return nil
	}

	if len(decoded) < 8 {
		return nil
	}

	// Create EventID in format: signature:LogIndex
	eventID := fmt.Sprintf("%s:%d", signature, logIndex)

	logger.Debug().
		Str("event_id", eventID).
		Str("signature", signature).
		Uint("log_index", logIndex).
		Uint64("slot", slot).
		Msg("processing sendFunds event")

	// Create store.Event
	event := &store.Event{
		EventID:           eventID,
		BlockHeight:       slot,
		Type:              store.EventTypeInbound, // Gateway events from external chains are INBOUND
		Status:            store.StatusPending,
		ExpiryBlockHeight: 0, // Will be set based on confirmation type if needed
	}

	// Parse event data from this log
	parseUniversalTxEvent(event, decoded, logIndex, chainID, logger)

	return event
}

func GetInboundBallotKey(inbound Inbound) (string, error) {
	chain := strings.TrimSpace(inbound.SourceChain)

	// nil RevertInstructions and an empty FundRecipient are semantically
	// identical (revert falls back to sender) — digest them identically.
	fundRecipient := ""
	if inbound.RevertInstructions != nil {
		fundRecipient = utils.LenientCanonicalizeAddress(chain, inbound.RevertInstructions.FundRecipient)
	}

	return hashFields(
		InboundBallotDomain,
		chain,
		utils.LenientCanonicalizeTxHash(chain, inbound.TxHash),
		strings.TrimSpace(inbound.LogIndex),
		utils.LenientCanonicalizeAddress(chain, inbound.Sender),
		// Recipient lives on Push Chain (EVM) regardless of source chain.
		utils.LenientCanonicalizeEVMAddress(inbound.Recipient),
		strings.TrimSpace(inbound.Amount),
		utils.LenientCanonicalizeAddress(chain, inbound.AssetAddr),
		fmt.Sprintf("%d", inbound.TxType),
		utils.CanonicalizeHexBlob(inbound.VerificationData),
		fundRecipient,
		fmt.Sprintf("%t", inbound.IsCEA),
		utils.CanonicalizeHexBlob(inbound.RawPayload),
		// universal_payload intentionally excluded (derived, ignored on-chain).

func (k Keeper) VoteOnInboundBallot(
	ctx context.Context,
	universalValidator sdk.ValAddress,
	inbound types.Inbound,
) (isFinalized bool,
	isNew bool,
	err error) {
	ballotKey, err := types.GetInboundBallotKey(inbound)
	if err != nil {
		return false, false, err
	}

	universalValidatorSet, err := k.uvalidatorKeeper.GetEligibleVoters(ctx)
	if err != nil {
		return false, false, err
	}

	// number of validators
	totalValidators := len(universalValidatorSet)

	// votesNeeded = ceil(2/3 * totalValidators)
	// >2/3 quorum similar to tendermint
	votesNeeded := (types.VotesThresholdNumerator*totalValidators)/types.VotesThresholdDenominator + 1

	k.Logger().Debug("voting on inbound ballot",
		"ballot_key", ballotKey,
		"validator", universalValidator.String(),
		"total_validators", totalValidators,
		"votes_needed", votesNeeded,
	)

	// Convert []sdk.ValAddress → []string
	universalValidatorSetStrs := make([]string, len(universalValidatorSet))
	for i, v := range universalValidatorSet {
		universalValidatorSetStrs[i] = v.IdentifyInfo.CoreValidatorAddress
	}

	// Step 2: Call VoteOnBallot for this inbound synthetic
	_, isFinalized, isNew, err = k.uvalidatorKeeper.VoteOnBallot(
		ctx,
		ballotKey,
		uvalidatortypes.BallotObservationType_BALLOT_OBSERVATION_TYPE_INBOUND_TX,
		universalValidator.String(),
		uvalidatortypes.VoteResult_VOTE_RESULT_SUCCESS,
		universalValidatorSetStrs,
		int64(votesNeeded),
		int64(types.DefaultExpiryAfterBlocks),
	)
	if err != nil {
		return false, false, err
	}
