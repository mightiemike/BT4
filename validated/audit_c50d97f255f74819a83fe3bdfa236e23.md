Found a strong analog: a **missing "declared-class" ceiling check in the Starknet OS's `replace_class` syscall implementation**, creating a state-root divergence between the Blockifier (sequencer) and the Starknet OS (prover/re-executor) — the same bug *class* as the reported People vulnerability (an authorization/validation boundary that exists in one code path but is missing in the analogous privileged path, allowing an unauthorized state transition).

### Title
Starknet OS `replace_class` syscall omits the declared-class check enforced by the Blockifier, enabling sequencer/OS state-root divergence - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
Any contract can invoke `replace_class_syscall` on itself during normal `__execute__` (non-validate) execution. In the Rust Blockifier, this syscall is guarded: the handler calls `state.get_compiled_class(request.class_hash)` before updating the class hash, and rejects/reverts the call if the class hash was never declared [1](#0-0) , confirmed by the "is not declared" test cases [2](#0-1) . The corresponding Starknet OS Cairo implementations, however, unconditionally update `contract_state_changes` with the requested `class_hash` without ever checking that the class was declared — this is explicitly acknowledged by a TODO in the code.

### Finding Description
In the current (non-deprecated) syscall path, `execute_replace_class` directly writes the new class hash into the state-change dict with no declared-class validation, and the omission is called out inline: [3](#0-2) 

The same missing check exists in the deprecated syscall path used for Cairo0 contracts: [4](#0-3) 

By contrast, the Blockifier — which is what the sequencer actually uses to execute transactions, build blocks, and compute the state diff that becomes the committed state root — enforces the ceiling by requiring the class to be declared before allowing the replacement: [1](#0-0) 

This is precisely analogous to the reported bug class: a privileged operation (a "role"/state-mutation boundary — here, "which class hashes a contract is allowed to adopt") is properly capped in one enforcement path (Blockifier / the "Administrator can't grant Owner" rule) but the ceiling check is missing in a second, equally-reachable enforcement path (the Starknet OS / re-execution validator, analogous to the mail-domain invitation flow that skipped the role-ceiling check).

### Impact Explanation
The Starknet OS is the component that re-executes the block to produce the proof and the committed state root/block hash that is ultimately accepted on L1. Because the OS silently accepts a `replace_class` to an undeclared (i.e., non-existent, attacker-chosen) class hash where the Blockifier would reject/revert that specific call, the OS can compute a different final storage/class-hash state for the affected contract address than what the sequencer's Blockifier actually determined during block building and state-diff production. This is a state-commitment integrity bug: it can lead to a wrong committed root/block hash or an honest-node/prover divergence, since two "honest" components of the same node (Blockifier vs. OS) disagree on whether the transaction's inner call succeeded and what state it produced.

### Likelihood Explanation
Likelihood is high: `replace_class_syscall` is callable by any contract that includes it (e.g., any account or generic contract with that entry point) via a normal `INVOKE` transaction — no special privilege is required, matching the "single authenticated request, no acceptance step" nature of the original CVE. Supplying an arbitrary/undeclared class hash as the argument is trivial and requires no special setup.

### Recommendation
Add the same declared-class ceiling check to the OS `execute_replace_class` implementations (both `syscall_impls.cairo` and the deprecated syscall path) that the Blockifier already performs — i.e., verify a compiled class exists for `request.class_hash`/`syscall_ptr.class_hash` before writing the new `StateEntry`, and fail/revert consistently with the Blockifier's behavior. This resolves the TODO left in the code and closes the sequencer/OS enforcement gap.

### Proof of Concept
1. Deploy any contract that exposes an entry point calling `replace_class_syscall(class_hash)` with an attacker-chosen `class_hash` that has never been declared on-chain (e.g., `test_replace_class` in the test-utils feature contract) [5](#0-4) .
2. Submit an `INVOKE` transaction (execute mode, not validate) that triggers this entry point with the undeclared class hash.
3. In the Blockifier, `state.get_compiled_class(request.class_hash)` fails, so the call fails with "... is not declared", per the existing test [2](#0-1) .
4. If the same transaction/state were re-executed by the Starknet OS (`execute_replace_class` in `syscall_impls.cairo`/`deprecated_execute_syscalls.cairo`), no such check exists, so the state-change dict is updated with the undeclared class hash unconditionally, producing a differing state/result from the Blockifier's execution for the same input.

// Replaces the class.
func execute_replace_class{
    range_check_ptr,
    syscall_ptr: felt*,
    contract_state_changes: DictAccess*,
    revert_log: RevertLogEntry*,
}(contract_address: felt) {
    alloc_locals;
    let request = cast(syscall_ptr + RequestHeader.SIZE, ReplaceClassRequest*);

    // Reduce gas.
    let success = reduce_syscall_gas_and_write_response_header(
        total_gas_cost=REPLACE_CLASS_GAS_COST, request_struct_size=ReplaceClassRequest.SIZE
    );
    if (success == FALSE) {
        // Not enough gas to execute the syscall.
        return ();
    }

    let class_hash = request.class_hash;

    // TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.
    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );

    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
