### Title
Sandwichable spot-price swap quote lets attacker drain value from PRC20 auto-swap deposits and gas refunds - (File: x/uexecutor/keeper/evm.go, execute_inbound_gas.go, outbound.go)

### Summary
Push Chain's PRC20-to-PC auto-swap path (used for `GAS`/`GAS_AND_PAYLOAD` inbound execution and for excess-gas refunds on outbound completion) prices the swap using a live Uniswap V3 `QuoterV2.quoteExactInputSingle` spot quote taken from the pool's current tick/reserves, then executes the actual swap against the same pool with only a flat 5% slippage bound (`minPCOut = quote * 95 / 100`). Because the quote read and the swap execution are two separate, unsynchronized EVM calls with no TWAP, oracle, or price-impact protection, an unprivileged attacker can manipulate the WPC/PRC20 pool's spot price immediately beforehand (or interleave transactions within the block/mempool) to depress the quote, letting the protocol-initiated swap execute at a bad price and be captured by the attacker who reverses their manipulation afterward — the same "manipulate the curve near an edge, then let a large state-changing operation move it further, then extract profit on unwind" pattern as the Hyperdrive `addLiquidity` sandwich report.

### Finding Description
The relevant reserves/price primitive here is the on-chain Uniswap V3 pool between a PRC20 token and WPC (wrapped native PC), fetched through `UniversalCore`. Two flows depend on this pool's instantaneous price with no manipulation resistance:

1. **Inbound gas auto-swap** (`ExecuteInboundGas`, `x/uexecutor/keeper/execute_inbound_gas.go:103-153`): after a `GAS`/`GAS_AND_PAYLOAD` inbound is ballot-finalized, the keeper calls `GetSwapQuote` (a static `CallEVM` read of `quoteExactInputSingle`) and then, in the very next step, calls `CallPRC20DepositAutoSwap` → `depositPRC20WithAutoSwap` on `UniversalCore`, which performs the real swap against the same pool, bounded only by `minPCOut` derived from the just-fetched quote with a flat 5% tolerance.
2. **Outbound gas refund** (`applyGasRefund` / `getSwapQuoteForRefund`, `x/uexecutor/keeper/outbound.go:174-269`): on outbound finalization (triggered the moment 2/3 of Universal Validators vote `MsgVoteOutbound`), any excess gas fee is refunded by swapping the gas-token PRC20 back to PC, again quoted via `GetSwapQuote` immediately before calling `CallUniversalCoreRefundUnusedGas` with `withSwap=true`.

Both quote-then-execute pairs use `QuoterV2.quoteExactInputSingle`, which (like all Uniswap V3 quoters) reads the pool's current spot tick/sqrtPrice rather than a time-weighted average. Nothing in `GetSwapQuote` (`x/uexecutor/keeper/evm.go:500-538`) or in the callers enforces a minimum liquidity depth, a maximum price-impact bound, or cross-checks against an external reference price. An attacker who can move the pool's price between the quote-read and the swap-execution — via their own swap transactions ordered around the core validator's derived EVM calls within the same block, exploiting typical AMM behavior where a large trade near thin liquidity produces an outsized price move (directly analogous to the Hyperdrive report's "point near the y-axis" concept) — can force `depositPRC20WithAutoSwap`/`refundUnusedGas` to execute at a manipulated price and capture the difference by reversing their own swap afterward. This corrupts PRC20/native asset accounting: PC minted to the UEA (or gas-refund PC sent to the recipient) is priced off a manipulated pool state rather than a fair, resistant price.

### Impact Explanation
This falls within the "corruption of PRC20 or native asset accounting, gas fee accounting, refund accounting … or canonical UniversalTx state" and "unauthorized … unauthorized state transitions in universal execution flows" impact categories. Value extracted comes from protocol-controlled PRC20 liquidity/minted PC — the attacker profits at the expense of the protocol/pool liquidity, materially misrouting value in the auto-swap and gas-refund flows, both of which are triggered automatically by ordinary user deposits or outbound completions with no privileged actor involved.

### Likelihood Explanation
Both trigger paths (inbound execution after ballot finalization, and outbound refund after ballot finalization) are reached purely by ordinary, unprivileged user/validator activity — a user submitting a `GAS`/`GAS_AND_PAYLOAD` inbound, or any outbound completing — with no admin or governance step required. The attacker only needs to be able to submit swap transactions against the same on-chain Uniswap V3 pool around the block in which the core validator's derived EVM call executes, which is achievable by any chain user with capital, especially against pools with modest liquidity (a realistic condition for newly listed PRC20/WPC pairs). The 5% slippage tolerance is coarse enough to permit meaningful single-block price manipulation.

### Recommendation
Do not price protocol-executed swaps off a single spot quote taken immediately before execution. Use a manipulation-resistant reference price (e.g., a TWAP over multiple blocks, or an external oracle) to bound `minPCOut`, and/or enforce a maximum acceptable price deviation between the previously observed price and the quote used for the swap. Consider also bounding the swap size relative to pool liquidity/depth so a single swap cannot materially move the price within the same block as the protocol's own swap.

### Proof of Concept
Not executable against this Go-only repository from static analysis alone — the vulnerable AMM contracts (`UniversalCore`, the Uniswap V3 pool/quoter) live in `push-chain-core-contracts`, outside this repo's Go/Cosmos SDK code. A concrete PoC would need to be built as a Forge/Hardhat test against the on-chain contracts: (1) seed a low-liquidity PRC20/WPC pool, (2) have an attacker swap to depress price, (3) trigger `ExecuteInboundGas`/`applyGasRefund` (via `MsgVoteInbound`/`MsgVoteOutbound` reaching threshold) so `depositPRC20WithAutoSwap`/`refundUnusedGas` executes at the depressed price, (4) attacker reverses their swap and nets a profit exceeding gas + slippage cost. This mirrors the structure of the Hyperdrive PoC (`test/units/hyperdrive/AddLiquiditySandwichAttack.t.sol`) but targeting the Push Chain `UniversalCore` auto-swap/refund contracts instead.

func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}
