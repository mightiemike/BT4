## Finding

### Title
`ensure_match_transaction_info` skips checkpoint-hash verification, allowing corrupted state roots to pass chunk-execution / replay-verify integrity checks - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info`, the function used by the chunk executor and by db-tool's replay-verify path to confirm that a locally re-executed transaction output matches an authenticated `TransactionInfo`, verifies status, gas, write-set hash, and event-root hash, but explicitly does **not** verify `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or the newer `position_state_checkpoint_hash`. This means a divergence between the locally computed state/hot-state/position Merkle roots and the authenticated roots in the `TransactionInfo` will not be detected by this check.

### Finding Description
The verification function is: [1](#0-0) 

It checks `status`, `gas_used`, `write_set_hash` against `state_change_hash`, and `event_root_hash`, but the code's own comment states the gap plainly: [2](#0-1) 

That is, checkpoint hashes (`state_checkpoint_hash`, `hot_state_checkpoint_hash`, and the repurposed `position_state_checkpoint_hash`) — the fields that actually authenticate the Sparse-Merkle/Jellyfish state root and the newer "position" native-state root — are excluded from the comparison. This function is consumed by:
- `execution/executor/src/chunk_executor/mod.rs` (used when the chunk executor validates locally re-executed output against the target ledger's authenticated `TransactionInfo`s during state-sync chunk execution/replay).
- `storage/db-tool/src/replay_on_archive.rs` and `aptos-move/aptos-debugger/src/aptos_debugger.rs` / `aptos-move/cli/src/commands.rs` (replay-verify tooling used to confirm historical/archival replay reproduces the authenticated chain state).

Because state/hot-state/position checkpoint hashes are the values that bind a computed Sparse Merkle Tree / Jellyfish Merkle Tree root (and the newer native "position" state root, guarded by `compute_trading_native_state_roots`) to the authenticated ledger, skipping them means this integrity gate provides no protection against a bug that produces a wrong state root while still producing a matching write-set hash, gas, status, and event root (all of which are independent of the state tree layout). This can occur, for example, in the state-checkpoint/hot-state/position-checkpoint computation paths such as `do_state_checkpoint.rs`'s `get_state_checkpoint_hashes`, since these roots are computed separately from the write-set hash: [3](#0-2) 

### Impact Explanation
If the checkpoint-root computation (state, hot-state, or the new native "position" state root under `COMPUTE_TRADING_NATIVE_STATE_ROOTS`) diverges from the correct value on a validator or full node during chunk execution/state-sync replay, `ensure_match_transaction_info` will still report a match because it never inspects the checkpoint hash fields. This is exactly the "hard-fork-only divergence during commit, replay, restore" class of issue: a node could commit or accept a chunk whose durable state root differs from the network's authenticated root without the executor's own consistency check catching it, and the same blind spot means db-tool's replay-verify (`replay_on_archive.rs`) can report a false "successful replay" while the authenticated position/state root has silently diverged from local execution.

### Likelihood Explanation
Likelihood is dependent on a separate root-computation bug existing (e.g., in the position/hot-state checkpoint pipeline, which is new/actively evolving per the `TODO(trading-native)` note and `compute_trading_native_state_roots` feature gating). This is not itself an externally triggerable bug on a correct node, but it is a fail-open verification gap: it removes a safety net that should independently catch such divergences before they are silently committed or before replay-verify reports false success, which is why the maintainers left the TODO in the code.

### Recommendation
Extend `ensure_match_transaction_info` to also compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` (when present/enabled) between the locally derived checkpoint output and the authenticated `TransactionInfo`, as the existing TODO comment recommends, before enabling/relying on `COMPUTE_TRADING_NATIVE_STATE_ROOTS` in production replay/chunk-execution paths.

### Proof of Concept
Not directly exploitable as a standalone PoC (it is a missing-check bug that requires a co-occurring root-computation divergence); the code path and gap are demonstrated by the cited `ensure_match_transaction_info` implementation and its own inline TODO acknowledging the omission, combined with its call sites in `execution/executor/src/chunk_executor/mod.rs` and `storage/db-tool/src/replay_on_archive.rs`.     pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }

    fn get_state_checkpoint_hashes(
        execution_output: &ExecutionOutput,
        known_state_checkpoints: Option<Vec<Option<HashValue>>>,
        computed_last_checkpoint_hash: HashValue,
        label: &str,
    ) -> Result<Vec<Option<HashValue>>> {
        let _timer = OTHER_TIMERS.timer_with(&[&format!("get_{label}_checkpoint_hashes")]);

        let num_txns = execution_output.to_commit.len();
        let last_checkpoint_index = execution_output
            .to_commit
            .state_update_refs()
            .last_inner_checkpoint_index();

        if let Some(known) = known_state_checkpoints {
            ensure!(
                known.len() == num_txns,
                "Bad number of known {label} hashes. {} vs {}",
                known.len(),
                num_txns,
            );
            if let Some(idx) = last_checkpoint_index {
                ensure!(
                    known[idx] == Some(computed_last_checkpoint_hash),
                    "{label} root hash mismatch with known hashes passed in. {:?} vs {:?}",
                    known[idx],
                    Some(computed_last_checkpoint_hash),
                );
            }
            Ok(known)
        } else {
            if !execution_output.is_block {
                // We should enter this branch only in test.
                execution_output.to_commit.ensure_at_most_one_checkpoint()?;
            }

            let mut out = vec![None; num_txns];
            if let Some(index) = last_checkpoint_index {
                out[index] = Some(computed_last_checkpoint_hash);
            }
            Ok(out)
        }
    }
