### Title
`block_direct_execute_call` protocol restriction only checks `call_contract`, not `library_call` — a blocklist bypass of the `__execute__` direct-invocation guard - ([File: crates/blockifier/src/execution/syscalls/syscall_base.rs])

### Summary
The reported PickleScan bug class is a **universal blocklist bypass**: a security check (picklescan's `_unsafe_globals` blocklist) is enforced only against one specific "calling convention" (`STACK_GLOBAL`/direct global reference), while a semantically-equivalent alternate indirection mechanism (`pkgutil.resolve_name` used as a first `REDUCE`, then invoked as a second `REDUCE`) reaches the exact same dangerous functions untouched by the check. The analogous pattern exists in Starknet's syscall layer: the protocol-level `block_direct_execute_call` restriction — which is supposed to prevent any contract from invoking another contract's `__execute__` entry point as an inner call — is enforced **only** inside the `call_contract` syscall handler, and is never checked inside the `library_call` syscall handler, even though `library_call` is a second, fully generic "invoke `class_hash`'s `function_selector` with `calldata`" gadget.

### Finding Description
The `call_contract` syscall implementations explicitly compare the requested `function_selector` against `EXECUTE_ENTRY_POINT_NAME` (the "blocklist entry") and reject the call when `block_direct_execute_call` is enabled: [1](#0-0) 

This check is invoked from `SyscallHintProcessor::call_contract`: [2](#0-1) 

and the equivalent inline check exists in the deprecated (Cairo 0) `call_contract` handler: [3](#0-2) 

and in the Starknet OS Cairo implementation of `execute_call_contract`, and in the deprecated-syscall Cairo path via `assert_not_equal(... , EXECUTE_ENTRY_POINT_SELECTOR)`: [4](#0-3) [5](#0-4) 

However, the **`library_call` syscall** — which takes the exact same shape of input (`class_hash`, `function_selector`, `calldata`) and dispatches into the same generic entry-point-execution machinery via `CallType::Delegate` instead of `CallType::Call` — never calls `maybe_block_direct_execute_call` or performs any equivalent comparison against `EXECUTE_ENTRY_POINT_NAME`/`EXECUTE_ENTRY_POINT_SELECTOR`, in any of the three concrete handlers:

- VM syscall handler: [6](#0-5) 
- Deprecated (Cairo 0) syscall handler: [7](#0-6) 
- Native syscall handler: [8](#0-7) 

This is a direct structural parallel to the PickleScan bug: the "blocklist" (`selector == EXECUTE_ENTRY_POINT_NAME` under `block_direct_execute_call`) is anchored to one specific opcode path (`CallContract`), while a second reachable gadget (`LibraryCall`, itself a first-class Starknet syscall reachable from any contract, including from a deployed contract used as a proxy pattern, cf. `delegate_proxy.cairo`'s `__default__`/`library_call`) resolves and invokes the exact same forbidden entry point (`__execute__`) on an arbitrary class hash, entirely bypassing the check. Additionally, `CallType::Delegate` preserves the *original* `caller_address` of the current execution context rather than substituting the immediate caller's address (as `call_contract`/`CallType::Call` does), so any account-side guard of the form `assert(get_caller_address().is_zero(), ...)` inside `__execute__` (as seen in the account feature contracts) can also be satisfied when the surrounding context's caller_address is already zero, compounding the bypass.

### Impact Explanation
The `block_direct_execute_call` flag is an explicit, versioned-constants-controlled protocol invariant meant to guarantee that `__execute__` can never run as an inner call, i.e., outside of the OS-controlled flow (post-`__validate__`, post-fee-charge, top-level transaction execution). Any contract or class that can reach `library_call_syscall` with an attacker-chosen `class_hash`/`function_selector` (this is a normal, unprivileged syscall available to any Cairo contract, including proxy-style contracts) can invoke `__execute__` of an arbitrary target class while completely circumventing this protocol guarantee. Combined with `CallType::Delegate`'s caller-address propagation, this allows unauthorized invocation of account logic outside the intended transaction lifecycle, undermining account-abstraction safety assumptions that `block_direct_execute_call` was specifically introduced to enforce. This falls under "unauthorized account action" per the validation criteria.

### Likelihood Explanation
`library_call` is one of the oldest and most heavily used Starknet syscalls (used for the standard proxy/delegate pattern, as shown by `delegate_proxy.cairo`), reachable from any unprivileged contract deployed by any transaction sender. No special privileges, staking, or operator/prover position are required — a single contract deployment plus one invoke transaction is sufficient to exercise this path.

### Recommendation
Add the same `maybe_block_direct_execute_call` (or equivalent `selector == EXECUTE_ENTRY_POINT_NAME` check gated by `block_direct_execute_call`) to all three `library_call` implementations (`SyscallHintProcessor::library_call`, `DeprecatedSyscallHintProcessor::library_call`/`library_call_l1_handler`, and the native `library_call`), and to the corresponding Starknet OS Cairo `execute_library_call_syscall` implementation, mirroring the check already present in `call_contract`.

### Proof of Concept
Not independently executed; based on direct code inspection of the syscall dispatch tables and handler implementations cited above, confirming the asymmetry:
1. `call_contract` (all three handlers + OS Cairo path) rejects `function_selector == selector_from_name("__execute__")` when `block_direct_execute_call` is set.
2. `library_call` (all three handlers) performs no such check before constructing the `CallEntryPoint` with `CallType::Delegate` and dispatching to `execute_inner_call`/`execute_library_call`.
3. A contract analogous to `delegate_proxy.cairo`'s `__default__`, or a `test_library_call`-style entry point, invoked via a normal `invoke` transaction with `class_hash = <victim account/class>` and `function_selector = selector!("__execute__")`, reaches the target's `__execute__` without triggering `DirectExecuteCall`/`INVALID_ARGUMENT_FELT`.

Full end-to-end exploitation (e.g., confirming what concrete state corruption results from invoking a victim account's `__execute__` via delegate-call semantics) was not traced further due to tool-call limits; a Devin session with repository access would be needed to build and run a concrete reproduction transaction.

        &mut self,
        selector: EntryPointSelector,
    ) -> SyscallResult<()> {
        let versioned_constants = &self.context.tx_context.block_context.versioned_constants;
        if versioned_constants.block_direct_execute_call

        {
            return Err(SyscallExecutionError::Revert { error_data: vec![INVALID_ARGUMENT_FELT] });
        }

    fn library_call(
        &mut self,
        class_hash: Felt,
        function_selector: Felt,
        calldata: &[Felt],
        remaining_gas: &mut u64,
    ) -> SyscallResult<Vec<Felt>> {
        self.pre_execute_syscall(
            remaining_gas,
            self.gas_costs().syscalls.library_call.base_syscall_cost(),
            SyscallSelector::LibraryCall,
        )?;

        let class_hash = ClassHash(class_hash);

        let wrapper_calldata = Calldata(Arc::new(calldata.to_vec()));

        let selector = EntryPointSelector(function_selector);

        let entry_point = CallEntryPoint {
            class_hash: Some(class_hash),
            code_address: None,
            entry_point_type: EntryPointType::External,
            entry_point_selector: selector,
            calldata: wrapper_calldata,
            // The call context remains the same in a library call.
            storage_address: self.base.call.storage_address,
            caller_address: self.base.call.caller_address,
            call_type: CallType::Delegate,
            initial_gas: *remaining_gas,
        };

        let error_wrapper_function =
            |e: SyscallExecutionError,
             class_hash: ClassHash,
             storage_address: ContractAddress,
             selector: EntryPointSelector| {
                e.as_lib_call_execution_error(class_hash, storage_address, selector)
            };

        Ok(self
            .execute_inner_call(entry_point, remaining_gas, class_hash, error_wrapper_function)?
            .0)
    }
