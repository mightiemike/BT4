### Title
Factory / system-contract implementation contracts are deployed at genesis with no initializer lock, allowing an attacker to front-run `initialize()` and seize ownership of the raw implementation address - (File: x/uexecutor/keeper/genesis.go, x/uregistry/keeper/genesis.go)

### Summary
The external report describes Solidity upgradeable contracts that call `_disableInitializers()` too late (inside `initialize()`), leaving a window where an attacker can call `initialize()` directly on the raw implementation contract before the legitimate deployer does. Push Chain reproduces the same root cause natively: at genesis, `x/uexecutor` and `x/uregistry` write EVM implementation-contract bytecode directly to fixed, publicly known addresses without ever calling `initialize()` or otherwise locking the implementation, and without any constructor-based `_disableInitializers()` guard (there is no constructor at all — the account is materialized directly via `SetAccount`/`SetCode`).

### Finding Description
`deployFactoryImplContract` in [1](#0-0)  writes the Factory implementation's runtime bytecode to the hardcoded address `FACTORY_IMPL_ADDRESS_HEX = "0x00000000000000000000000000000000000000fa"` [2](#0-1) , but only sets `Nonce`/`Balance`/`CodeHash` — no ownership slot is written and `initialize(...)` is never invoked against this address. The same pattern repeats generically for every system contract in `x/uregistry`: `deployImplementationContract` also only sets code, never calling or locking `initialize()` [3](#0-2) , while `deploySystemContracts` drives the whole proxy/admin/impl triple deployment sequence [4](#0-3) .

The Factory implementation bytecode itself exposes a `c4d66de8` selector, which is the well-known 4-byte selector for OpenZeppelin's `initialize(address)` (visible directly in the dumped bytecode) [5](#0-4) , confirming this is a standard OZ-Initializable/Ownable contract. The test harness itself demonstrates that `initialize(initialOwner)` is a real, callable, owner-setting entry point that must be invoked post-deployment: `setupFactoryContract` explicitly calls `CallEVM(..., "initialize", owner)` on the factory address after it is deployed [6](#0-5) .

In production, `InitGenesis` only invokes `deployFactoryEA` (which deploys impl + admin + proxy bytecode) and never calls `initialize()` on either the proxy or the implementation contract [7](#0-6) . Because:
1. The implementation contract's address is fixed and public in source (`0x…fa`), and
2. Nothing sets its owner or otherwise disables `initialize()`,

any unprivileged external account can submit a normal EVM transaction directly to the implementation address (bypassing the proxy) calling `initialize(attacker)`, becoming "owner" of the raw implementation contract before any legitimate party does so. This is the exact bug class from the external report ported into Push Chain's genesis-driven proxy deployment mechanism, since there is no `constructor(){_disableInitializers();}`-equivalent guard when contracts are materialized by direct state injection rather than actual `CREATE`/constructor execution.

### Impact Explanation
Once an attacker controls `owner` on the raw Factory implementation contract, standard OZ `Ownable`/UUPS-style owner-gated functions on that same address become attacker-reachable (the bytecode contains `f2fde38b` `transferOwnership`, `715018a6` `renounceOwnership`, and other owner-gated selectors seen in the ABI, e.g. `setUEAProxyImplementation`, `registerNewChain`, `registerUEA`). If any of these owner-gated paths permit pointing the implementation to attacker-controlled code (UUPS `upgradeToAndCall`-style delegatecall) or invoking a delegatecall to an attacker contract, the attacker can execute a Parity-multisig-style self-destruct of the shared implementation contract. Since the Factory Proxy's EIP-1967 implementation slot points at this exact address [8](#0-7) , destroying it turns every delegatecall through the Factory Proxy into a silent no-op (EVM `delegatecall` to an address with no code returns success without executing anything), permanently bricking UEA registration/deployment (`registerNewChain`, `registerUEA`, `deployUEA`, `setUEAProxyImplementation`) — a protocol-wide, unprivileged-attacker-triggerable denial of the universal-execution account system, and a form of permanent freezing of protocol functionality reachable without any privileged assumption.

### Likelihood Explanation
High reachability: the implementation address is a fixed, documented constant in the repository, requires no special permission to call, and the initializer is left open indefinitely (there is no time-bound legitimate `initialize()` transaction to race against in the genesis flow itself — it's simply never called in production code at all, meaning the window is permanently open, not just a front-running race). The only uncertainty is whether the Factory implementation bytecode's owner-gated functions include a delegatecall/upgrade path that can be pointed at attacker code to trigger `SELFDESTRUCT`; this could not be fully confirmed from the truncated bytecode dump available in the index, so likelihood of the most severe (bricking) sub-case is not 100% confirmed, but the ownership takeover of the implementation contract itself is confirmed by code.

### Recommendation
- Ensure every genesis-deployed implementation contract has its initializer locked as part of the deployment sequence — either bake the "initialized" storage slot / `_initialized` flag directly into the account state written by `SetAccount`/`SetState` at genesis (mirroring how `deployProxyAdminContract` already writes the owner slot directly, see [9](#0-8) ), or immediately follow bytecode injection with a `CallEVM(..., "initialize", <burn address or zero-address sentinel>)` before any other transaction can be processed.
- Audit the Factory/system-contract implementations for any code path where an owner of the raw implementation can trigger a delegatecall to attacker-supplied bytecode or otherwise destroy/corrupt the implementation, since this is the concrete mechanism by which "implementation storage ownership" turns into protocol-wide impact.
- Apply this fix uniformly across `x/uexecutor/keeper/genesis.go` (`deployFactoryImplContract`) and `x/uregistry/keeper/genesis.go` (`deployImplementationContract`), since both share the identical unlocked-implementation pattern.

### Proof of Concept
1. Observe the chain genesis / a live Push Chain node; the Factory implementation contract is deployed at the fixed address `0x00000000000000000000000000000000000000fa` per `x/uexecutor/types/constants.go`.
2. Compute calldata for `initialize(address)` (selector `0xc4d66de8`) with the attacker's own address as the argument.
3. Submit a normal EVM transaction directly to `0x…fa` (not through the Factory Proxy at `0x…ea`) invoking `initialize(attacker)`. Since nothing in `deployFactoryImplContract`/`InitGenesis` ever calls or locks `initialize()` on this address, the call succeeds and sets `owner = attacker` in the implementation contract's own storage.
4. Attacker now holds owner-only capabilities on the raw implementation address itself; if any owner-gated function there permits pointing execution at attacker-supplied bytecode (matching the OZ-documented UUPS-implementation takeover pattern), the attacker can render the shared implementation contract non-functional, breaking all Factory Proxy calls for every user of universal-execution account registration/deployment.

func deployFactoryProxy(ctx context.Context, evmKeeper types.EVMKeeper) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	proxyAddress := common.HexToAddress(types.FACTORY_PROXY_ADDRESS_HEX)
	proxyAdminOwner := common.HexToAddress(types.PROXY_ADMIN_ADDRESS_HEX)
	factoryImplAddress := common.HexToAddress(types.FACTORY_IMPL_ADDRESS_HEX)

	// Compute the code hash from the runtime bytecode
	codeHash := crypto.Keccak256(types.ProxyRuntimeBytecode)

	// Create the EVM account object
	evmAccount := statedb.Account{
		Nonce:    1,             // to prevent tx nonce=0 conflicts
		Balance:  new(uint256.Int), // zero balance by default
		CodeHash: codeHash,      // link to deployed code
	}

	// Set the EVM account with the factory proxy contract
	err := evmKeeper.SetAccount(sdkCtx, proxyAddress, evmAccount)
	if err != nil {
		panic("failed to set factory proxy contract account: " + err.Error())
	}

	// Store the runtime bytecode linked to the code hash
	evmKeeper.SetCode(sdkCtx, codeHash, types.ProxyRuntimeBytecode)

	// Update proxyAdmin Slot with the proxyAdmin owner address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_ADMIN_SLOT, common.LeftPadBytes(proxyAdminOwner.Bytes(), 32))

	// Update proxyImplementation Slot with the factory implementation address (left padded to 32 bytes)
	evmKeeper.SetState(sdkCtx, proxyAddress, types.PROXY_IMPLEMENTATION_SLOT, common.LeftPadBytes(factoryImplAddress.Bytes(), 32))
}

func deployProxyAdminContract(ctx context.Context, evmKeeper types.EVMKeeper, proxyAdminContractAddress string, runtimeBytecode []byte) {

	evmKeeper.SetState(sdkCtx, proxyAdminAddress, common.Hash{}, common.LeftPadBytes(owner.Bytes(), 32))

func deploySystemContracts(ctx context.Context, evmKeeper types.EVMKeeper, systemContracts map[string]types.ContractAddresses) {
	sdkCtx := sdk.UnwrapSDKContext(ctx)

	// Sort contract names for deterministic iteration order across all validators
	names := make([]string, 0, len(systemContracts))
	for name := range systemContracts {
		names = append(names, name)
	}
	sort.Strings(names)

	for _, name := range names {
		contract := systemContracts[name]

		proxyAddr := common.HexToAddress(contract.Address)
		if isContractDeployed(sdkCtx, evmKeeper, proxyAddr) {
			sdkCtx.Logger().Info(
				"system contract already deployed, skipping",
				"name", name,
				"proxy", proxyAddr.Hex(),
			)
			continue
		}

		bytecodes, ok := types.BYTECODE[name]
		if !ok {
			panic(fmt.Sprintf("no bytecode found for contract %s", name))
		}

		// 1. Deploy ProxyAdmin with ADMIN_RUNTIME
		deployProxyAdminContract(ctx, evmKeeper, contract.ProxyAdmin, bytecodes.ADMIN_RUNTIME)

		// 2. Deploy Implementation with IMPL_RUNTIME
		deployImplementationContract(ctx, evmKeeper, contract.Implementation, bytecodes.IMPL_RUNTIME)

		// 3. Deploy Proxy with PROXY_RUNTIME
		deployProxyContract(ctx, evmKeeper, contract.Address, contract.ProxyAdmin, contract.Implementation, bytecodes.PROXY_RUNTIME)
	}
}

// InitGenesis initializes the module's state from a genesis state.
func (k *Keeper) InitGenesis(ctx context.Context, data *types.GenesisState) error {

	if err := data.Params.ValidateBasic(); err != nil {
		return err
	}

	// Only deploy factory contracts on fresh genesis, not on import from export.
	// Re-deploying on import would overwrite existing EVM state or cause nonce collisions.
	if !data.Exported {
		deployFactoryEA(ctx, k.evmKeeper)
	}

	if err := k.Params.Set(ctx, data.Params); err != nil {
		return err
	}
