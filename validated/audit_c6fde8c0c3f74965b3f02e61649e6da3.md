### Title
Insufficient Validation of TVM-Native VoteWitness Bypasses Standard Actuator Checks - (File: actuator/src/main/java/org/tron/core/vm/nativecontract/VoteWitnessProcessor.java)

### Summary
The standard `VoteWitnessContract` transaction path (`VoteWitnessActuator.validate()`) performs a full set of checks before mutating votes/tron-power state: address format validation, non-zero vote count, per-vote-address positivity, existence of each witness candidate account, existence of the witness in `WitnessStore`, existence of the voter account, and a tron-power-vs-votes bound check. The TVM opcode path that reaches the same state mutation (`VOTEWITNESS` opcode → `Program.voteWitness()` → `VoteWitnessProcessor`) reimplements this logic but deliberately drops one of the checks and validates far less than the actuator equivalent, mirroring the reported pattern where a privileged/alternate code path executes state-changing logic with materially weaker validation than the "normal" transaction path.

### Finding Description
`VoteWitnessActuator.validate()` in [1](#0-0)  checks, for every vote entry, that the witness candidate address is a valid TRON address, has a positive vote count, that `accountStore.has(witnessCandidate)` (the account exists), and that `witnessStore.has(witnessCandidate)` (it is a registered witness) — throwing `ContractValidateException` otherwise.

The TVM-reachable equivalent, `VoteWitnessProcessor.validate()`/`execute()`, is invoked from the `VOTEWITNESS` opcode via `Program.voteWitness()` [2](#0-1)  and `OperationRegistry.appendVoteOperations` wiring the opcode to `OperationActions::voteWitnessAction` (gated only by `VMConfig::allowTvmVote`, not by any privileged-caller check) [3](#0-2) .

Inside `VoteWitnessProcessor`, the account-existence check for each witness candidate is explicitly commented out with a note that it was intentionally removed "for tvm performance", while the corresponding witness-registration check (`repo.getWitness(witnessAddress) == null`) is retained: [4](#0-3) . The `validate()` method of this processor only checks the vote count against `MAX_VOTE_NUMBER`, omitting the address-format check, the per-vote positivity check duplication, and the account-existence check that the actuator performs: [5](#0-4) .

This is directly analogous to the reported bug class: a state-mutating operation reachable from ordinary user activity (any smart contract calling `VOTEWITNESS`, itself invocable by any externally-owned account via `TriggerSmartContract`) executes through a second code path that duplicates — but does not faithfully replicate — the full validation performed by the "normal" transaction-level actuator, based on an unverified assumption (here, that the missing check is provably redundant with a comment rather than an enforced invariant, similar to the L2 upgrade case being "assumed to be vetted off-chain").

### Impact Explanation
If the removed account-existence check is not actually fully redundant with the witness-store check (e.g., due to a witness capsule existing without a corresponding account record, or future refactors of `WitnessStore`/`AccountStore` invariants, or state introduced by migration/genesis paths), a contract could successfully cast votes toward a witness address lacking an `AccountCapsule`, leading to divergent state mutation between the TVM path and the ordinary contract path. More generally, this demonstrates that TVM-native processors are validated less rigorously than their actuator counterparts even though both are reachable by arbitrary users and mutate the same global consensus-critical state (votes, tron power accounting), increasing the risk that future edits to one path (actuator) are not mirrored in the other (TVM processor), causing consensus-relevant divergence between contract-triggered and directly-broadcast vote operations.

### Likelihood Explanation
Likelihood is moderate: the `VOTEWITNESS` opcode is reachable from any unprivileged account by deploying/calling a smart contract (gated only by the `allowTvmVote` hard-fork flag, already enabled on mainnet), so the code path itself is trivially reachable. The likelihood of a concrete state-corruption trigger depends on whether an account can exist as a witness without an `AccountCapsule`, which is not proven here — the removed check might indeed be safely redundant in all currently reachable states. This is a validation-parity/defense-in-depth gap rather than a confirmed exploitable primitive.

### Recommendation
Keep the TVM-native processors (`VoteWitnessProcessor`, `FreezeBalanceProcessor`, `FreezeBalanceV2Processor`, etc.) validation logic in lock-step with their actuator counterparts, ideally by sharing a single validation implementation rather than maintaining two independently-drifting copies. If a check is removed as "redundant," add an explicit runtime assertion (not just a comment) enforcing the invariant it depends on, so any future change that breaks the invariant fails loudly instead of silently admitting invalid state.

### Proof of Concept
Not applicable — no concrete state where a witness exists without a backing account was found in the explored code, so this is reported as a validation-parity gap consistent with the reported bug class rather than a demonstrated exploit. Confirming exploitability would require verifying, across all witness-creation code paths (`WitnessCreateContract` actuator, genesis block setup, and any admin/maintenance witness registration), whether an `AccountCapsule` can ever be absent for an address present in `WitnessStore`.

  public boolean voteWitness(int witnessArrayOffset, int witnessArrayLength,
      int amountArrayOffset, int amountArrayLength) {
    Repository repository = getContractState().newRepositoryChild();
    byte[] owner = getContextAddress();

    increaseNonce();
    InternalTransaction internalTx = addInternalTx(null, owner, null, 0, null,
        "voteWitness", nonce, null);

    if (memoryLoad(witnessArrayOffset).intValueSafe() != witnessArrayLength ||
        memoryLoad(amountArrayOffset).intValueSafe() != amountArrayLength) {
      logger.warn("TVM VoteWitness: memory array length do not match length parameter!");
      throw new BytecodeExecutionException(
          "TVM VoteWitness: memory array length do not match length parameter!");
    }

    if (witnessArrayLength != amountArrayLength) {
      logger.warn("TVM VoteWitness: witness array length {} does not match amount array length {}",
          witnessArrayLength, amountArrayLength);
      return false;
    }

    try {
      VoteWitnessParam param = new VoteWitnessParam();
      param.setVoterAddress(owner);
      byte[] witnessArrayData = memoryChunk(
          addExact(witnessArrayOffset, DataWord.WORD_SIZE,  VMConfig.disableJavaLangMath()),
          multiplyExact(witnessArrayLength, DataWord.WORD_SIZE,  VMConfig.disableJavaLangMath()));
      byte[] amountArrayData = memoryChunk(
          addExact(amountArrayOffset, DataWord.WORD_SIZE,  VMConfig.disableJavaLangMath()),
          multiplyExact(amountArrayLength, DataWord.WORD_SIZE,  VMConfig.disableJavaLangMath()));

      for (int i = 0; i < witnessArrayLength; i++) {
        DataWord witness = new DataWord(Arrays.copyOfRange(witnessArrayData,
            i * DataWord.WORD_SIZE, (i + 1) * DataWord.WORD_SIZE));
        DataWord amount = new DataWord(Arrays.copyOfRange(amountArrayData,
            i * DataWord.WORD_SIZE, (i + 1) * DataWord.WORD_SIZE));
        param.addVote(witness.toTronAddress(), amount.sValue().longValueExact());
      }
      if (internalTx != null) {
        internalTx.setExtra(param.toJsonStr());
      }

      VoteWitnessProcessor processor = new VoteWitnessProcessor();
      processor.validate(param, repository);
      processor.execute(param, repository);
      repository.commit();
      return true;
    } catch (ContractValidateException e) {
      logger.warn("TVM VoteWitness: validate failure. Reason: {}", e.getMessage());
    } catch (ContractExeException e) {
      logger.warn("TVM VoteWitness: execute failure. Reason: {}", e.getMessage());
    } catch (ArithmeticException e) {
      logger.warn("TVM VoteWitness: int or long out of range. caused by: {}", e.getMessage());
    }
    if (internalTx != null) {
      internalTx.reject();
    }
    return false;
  }
