### Title
Interest compounds over full paused duration once vault `accrue` is unpaused, causing sudden debt jump and unexpected liquidation risk - (File: mainnet/contracts/vault/v0-vault-usdc.clar / v0-vault-usdh.clar / v0-vault-sbtc.clar / v0-vault-ststxbtc.clar / v0-vault-stx.clar)

### Summary
The Zest v2 vault contracts implement pause-gated interest accrual via `accrue`, `next-index`, and `next-liquidity-index`. When the `accrue` pause flag is active, index growth is skipped entirely and `last-update` is left untouched. When the pause is lifted, the next call to `accrue` computes the elapsed time as `(- stacks-block-time (var-get last-update))`, which spans the *entire* paused interval plus any additional elapsed time, and compounds interest over that whole span in a single step. This mirrors the BendDAO finding: pausing does not freeze/skip the clock for interest purposes, it merely delays the compounding, which then lands on borrowers all at once upon unpause.

### Finding Description
`next-index` (and analogously `next-liquidity-index`) reads the `accrue` pause flag from `pause-states` and, if paused, returns the index unchanged without registering that any time has passed: [1](#0-0) 

`accrue` only updates `last-update` when the index actually changed, which never happens while `accrue` is paused: [2](#0-1) 

Because `last-update` is a single scalar timestamp with no bookkeeping of "paused vs. active" intervals, the moment `accrue` is unpaused, `time-delta = stacks-block-time - last-update` reflects the *entire* duration since the pause began (potentially days or weeks), and `calc-multiplier-delta` compounds the borrow rate over that whole span in one shot via `next-index`. All borrowers' scaled debt (`calc-cumulative-debt`) jumps discontinuously the instant accrual resumes, rather than the interest simply being skipped or pro-rated for the paused window.

`system-borrow` (and by symmetry `system-repay`) calls `accrue` at the start of every state-changing lending operation, so the very first post-unpause transaction (a borrow, repay, or a liquidation call in the market contract that queries vault debt) will trigger this full catch-up compounding: [3](#0-2) 

This is a single-transaction/single-clock-advance analog of the report's root cause: "a clock advanced only on change" — the `last-update` variable is the clock, and it is only advanced when accrual is unpaused, so the pause interval silently accumulates onto the very next accrual instead of being excluded.

### Impact Explanation
Borrowers whose positions are near the liquidation threshold before a pause can be pushed over the threshold purely by the compounded interest that accrues in one lump sum at unpause, through no borrowing or market action of their own. Since `market/v0-4-market.clar` relies on vault-reported debt (via `debt-preview`/`total-debt`, which depend on the same `index`) to compute health/liquidation eligibility, an artificially inflated single-step debt jump can make positions immediately liquidatable right after unpause, causing borrowers to lose collateral (temporary/permanent freezing or loss of user funds) that they had no opportunity to protect against because `repay`/`borrow` were blocked during the pause. This falls under "temporary freezing of funds" / potential theft of collateral via forced liquidation, consistent with the original report's Medium classification.

### Likelihood Explanation
This requires only that: (1) the vault's `accrue` pause flag be set for any nontrivial duration (an intended emergency-pause feature that governance/DAO can and is expected to use), and (2) at least one borrower is close enough to the liquidation threshold that the lump-sum compounded interest crosses the threshold. Given pauses are explicitly supported operational functionality and durations are not bounded on-chain, this is a realistic, repeatable scenario any time the pause feature is exercised for more than a trivial amount of time — no attacker action or malicious input is needed, only the passage of time during a pause.

### Recommendation
Track pause start/end timestamps (or the cumulative paused duration) and subtract paused time from `time-delta` in `next-index`/`next-liquidity-index`, or alternatively advance `last-update` to `stacks-block-time` at the moment `accrue` is paused, so that resuming does not retroactively compound interest for the paused interval.

### Proof of Concept
1. At time `T0`, `last-update = T0`, borrower has debt near the liquidation threshold.
2. Governance pauses `accrue` (sets `pause-states.accrue = true`) for the vault.
3. Time passes to `T1 = T0 + Δ` (e.g., several days) while `accrue` remains paused; every call to `accrue` during this window hits the pass-through branch and returns the unchanged index without updating `last-update`: [4](#0-3) 
4. Governance unpauses `accrue` at `T1`.
5. Any subsequent call to `accrue` (triggered automatically inside `system-borrow`/`system-repay`, or read indirectly by the market's liquidation check) computes `time-delta = T1 - T0 = Δ` and compounds the full `Δ`-duration interest onto the index in a single step via `next-index`: [5](#0-4) 
6. The borrower's `debt-preview`/`total-debt` jumps by the full `Δ`-duration of compounded interest instantly, which can push the position below the health/liquidation threshold, allowing a liquidator to seize collateral immediately after unpause — even though the borrower had no way to repay or react during the pause.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)

                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))

                false)
