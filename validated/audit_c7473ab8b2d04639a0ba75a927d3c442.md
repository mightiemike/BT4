### Title
Paused vault accrual returns stale index as `ok` instead of reverting, letting borrow/repay operate on outdated interest data - (File: `mainnet/contracts/vault/v0-vault-sbtc.clar` and equivalent per-asset vaults)

### Summary
Every vault's `accrue` function checks the `accrue` pause flag and, when paused, returns the current (stale) `index`/`lindex` wrapped in `(ok ...)` instead of reverting [1](#0-0) . Because `accrue` is treated as a pass-through success rather than a failure, every caller that does `(try! (accrue))` — `system-borrow`, `system-repay`, `deposit`, `redeem` — proceeds normally, using the un-updated `index` as if it were current [2](#0-1) . `market.clar` also relies on this per-block index being fresh: it caches whatever `vault-accrue` returns via `accrue-and-cache` and reuses that cached value for scaled-debt conversion, LTV/health checks, and ztoken price resolution for the rest of the transaction [3](#0-2) .

### Finding Description
This is the same "condition always/never triggers as intended" class as the external report (a value that is supposed to gate/refresh state is bypassed so downstream logic operates on data that no longer reflects reality), but manifesting here as "a pause that passes through instead of reverting," which is explicitly in scope per the analog rules.

`accrue()` is the single choke point that updates `index` (debt) and `lindex` (liquidity/supply) based on elapsed time and utilization [4](#0-3) . When the DAO pauses `accrue` (e.g., during an emergency or maintenance window), the function silently returns `(ok {index: idx, lindex: lidx})` with the old values, rather than returning an error. Every lending/borrowing/redeeming entry point unconditionally calls `(try! (accrue))` first and treats a successful `ok` as "the vault state is now up to date" [5](#0-4) . Because the call still returns `ok`, `system-borrow`/`system-repay`/`deposit`/`redeem` continue executing using `(var-get index)` for scaled-debt/scaled-share math even though that index is stale relative to what it should be at the current block time.

Additionally, `last-update` is only advanced inside the "not-paused" branch, and even there only if the index actually changed [6](#0-5) , so any staleness check elsewhere that trusts `last-update` similarly does not detect the paused/stagnant state.

`market.clar`'s `accrue-and-cache` compounds this: it calls `vault-accrue`, and whatever index comes back (paused-stale or fresh) is cached per-block and reused for all subsequent operations in that transaction (borrow index for scaled-debt conversion, health checks, ztoken collateral valuation) [3](#0-2) [7](#0-6) .

### Impact Explanation
While `accrue` being paused is a documented operational control, the fact that it *never reverts* and instead returns success with stale data means the pause does not stop protocol usage — it only stops interest from being tracked. Users can continue to borrow, repay, deposit, and redeem while interest accrual is frozen at the wrong point in time, causing debt/supply indices to diverge from what they should be. This can result in temporary freezing/mispricing of unclaimed yield (lenders under-earn or borrowers under-pay interest for the paused duration) since the index used for scaled-debt/scaled-share conversion during the pause window does not reflect true elapsed interest, and once accrual resumes, the jump in `index`/`lindex` will apply retroactively across all positions rather than being isolated to the intended pause window. This lands in the temporary-freezing-of-unclaimed-yield impact category.

### Likelihood Explanation
Likelihood is tied to DAO pausing `accrue` for maintenance/incident response, which the protocol's own pause-state design anticipates as a normal control (each vault has an explicit `accrue` pause flag in `pause-states`) [8](#0-7) . Since deposit/borrow/repay/redeem are not also paused automatically, any pause of `accrue` alone is very likely to be hit in normal operation, not requiring an attacker to craft a special sequence — every transaction touching the vault during the pause window is affected.

### Recommendation
Either (a) make `accrue` revert (return an `err`) when paused, and have all callers (`system-borrow`, `system-repay`, `deposit`, `redeem`) propagate that failure instead of continuing with stale indices, or (b) if pausing only accrual updates is intentional, also pause (or otherwise safely handle) all dependent operations (`deposit`, `redeem`, `system-borrow`, `system-repay`) so that no state-mutating operation can proceed while the index is stale. At minimum, document and test that pausing `accrue` is equivalent to freezing all index-dependent operations, not just the recalculation step, to avoid silently accepting outdated interest data as "success."

### Proof of Concept
1. DAO pauses `accrue` for `vault-sbtc` via the pause-states configuration [8](#0-7) .
2. Time passes (interest should have accrued based on utilization and elapsed seconds via `next-index`/`next-liquidity-index`).
3. A user calls `market.borrow` for sBTC; `market.clar` calls `vault-accrue` -> `vault-sbtc.accrue`, which is paused and returns `(ok {index: idx, lindex: lidx})` with the old, un-advanced index [9](#0-8) .
4. `market.clar` caches this stale index via `accrue-and-cache` and uses it for `convert-to-scaled-debt` and health checks [10](#0-9) , so the borrow's scaled-debt is computed against outdated interest.
5. `system-borrow` in the vault itself also reads `(var-get index)` directly for its own scaled-amount math, reinforcing use of the stale value [11](#0-10) .
6. When the DAO unpauses `accrue`, the next call jumps the index forward across the entire pause duration at once, retroactively changing the economics of all interactions that happened while paused, without the transaction having failed or warned the user that it operated on stale accrual data.

(define-public (accrue)
  (let ((states (var-get pause-states))
        (idx (var-get index))
        (lidx (var-get lindex)))
      (if (get accrue states)
          ;; PAUSED: Pass-through without reverting
          (ok { index: idx, lindex: lidx })
          ;; NOT PAUSED: Normal accrual logic
          (let ((next (next-index))
                (nliq (next-liquidity-index))
                (scaled-principal (var-get principal-scaled))
                (old-debt (mul-div-down scaled-principal idx INDEX-PRECISION))
                (new-debt (mul-div-down scaled-principal next INDEX-PRECISION))
                (debt-delta (if (> new-debt old-debt) (- new-debt old-debt) u0))
                (reserve-inc (mul-div-down debt-delta (var-get fee-reserve) BPS))
                (treasury-lp (if (> reserve-inc u0) (mul-div-down reserve-inc (total-supply) (- (total-assets-preview) reserve-inc)) u0)))
            (if (not (is-eq idx next))
                (var-set index next)
                false)
            (if (not (is-eq lidx nliq))
                (var-set lindex nliq)
                false)
            (if (> treasury-lp u0)
                (try! (ft-mint? zft treasury-lp .dao-treasury))
                false)
            (if (or (not (is-eq idx next)) (not (is-eq lidx nliq)))
                (var-set last-update stacks-block-time)
                false)
            (ok { index: next, lindex: nliq })))))

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
