### Title
Not confirmed — insufficient visibility into `UniversalCore` contract-side staleness enforcement for `gasPriceByChainNamespace`

### Summary
The scoped Go code shows a plausible analog to the `exchangeRate` bug: `x/uregistry` chains can be toggled off/on via `ChainConfig.Enabled` [1](#0-0) , and `universalClient/chains/chains.go` fully **removes** the chain client (stopping its `ChainMetaOracle`, which periodically votes gas price/chain-height via `MsgVoteChainMeta`) once both `IsInboundEnabled` and `IsOutboundEnabled` are false [2](#0-1) . While the chain is off, no validator submits `VoteChainMeta`, so the on-chain `gasPriceByChainNamespace` value in `UniversalCore` is never refreshed [3](#0-2) . When the chain is re-enabled, `BuildOutboundsFromReceipt` only checks `IsChainOutboundEnabled` before creating an outbound [4](#0-3) , and gas/fee computation reads `gasPriceByChainNamespace` directly from the contract via `GetOutboundTxGasAndFees`/`GetGasPriceByChain` [5](#0-4) [6](#0-5)  with no staleness/freshness gate visible in the Go layer.

### Finding Description
This is the same class of bug as the Sherlock `exchangeRate` report: a resource that is "paused" (chain disabled) stops receiving fresh oracle updates, but is reactivated ("on") without first refreshing that stale value, so subsequent user-facing accounting (gas-fee computation for outbounds/reverts) uses outdated data. The Go-level checks (`IsChainOutboundEnabled`, `IsChainInboundEnabled`) gate whether crosschain flows are allowed, but they do not gate on how recently `ChainMeta`/`gasPriceByChainNamespace` was updated. The `VoteChainMeta` staleness filtering (`chainMetaVoteStalenessSeconds`) only applies to computing a *new* median from concurrently submitted votes [7](#0-6) ; it does not invalidate the *already-applied* on-chain value when no new votes arrive at all (e.g., during a disablement window).

### Impact Explanation
If confirmed at the contract layer, this would mean outbound gas-fee accounting (charged to users, and used to compute refunds via `refundUnusedGas`) could rely on a stale gas price after a chain is turned back on, misrouting value between the user and the protocol/relayer — squarely within "corruption of ... gas fee accounting, refund accounting" impact scope. However, I could not verify whether the Solidity contract itself enforces a max-age check on `timestampObservedAtByChainNamespace` before serving `gasPriceByChainNamespace`/`getOutboundTxGasAndFees`, since that source is not present in the indexed repository content available to me.

### Likelihood Explanation
Cannot be assessed with confidence: it depends on (a) how long an admin leaves both inbound/outbound disabled, and (b) whether the contract independently gates on staleness. The Go-side `VoteChainMeta` logic re-converges quickly (a single fresh vote after bootstrap updates the on-chain value immediately since fresh-vote-count gating is a bootstrap-only requirement [8](#0-7) ), so the exposure window is only from chain re-enablement until the first Universal Validator's `ChainMetaOracle` submits its next scheduled vote (bounded by `gas_oracle_fetch_interval` / `gasPriceIntervalSeconds`, typically tens of seconds) [9](#0-8) .

### Recommendation
Cannot responsibly recommend a fix without confirming the actual contract-side behavior of `gasPriceByChainNamespace`/`getOutboundTxGasAndFees` — this requires reading the Solidity source (not available via the current index) to see if `timestampObservedAtByChainNamespace` is already checked. If it is not checked, the recommendation would be to (1) reject or apply a fallback gas price when the observed-at timestamp exceeds a max-staleness threshold, or (2) have `BuildOutboundsFromReceipt`/`GetOutboundTxGasAndFees` require a chain-meta update at or after the `Enabled` flag transition before permitting a chain to serve new outbounds.

### Proof of Concept
Not constructed, since the root-cause gate (contract-side staleness check) could not be confirmed one way or the other from the available indexed source. **Recommend starting a Devin session with full filesystem access to inspect the Solidity `UniversalCore` contract source (search for `gasPriceByChainNamespace`, `timestampObservedAtByChainNamespace`, and `getOutboundTxGasAndFees` implementations) to determine whether this analog is a real, exploitable finding or already mitigated.**

func (k Keeper) VoteChainMeta(ctx context.Context, universalValidator sdk.ValAddress, observedChainId string, price, blockNumber uint64) error {
	sdkCtx := sdk.UnwrapSDKContext(ctx)
	now := uint64(sdkCtx.BlockTime().Unix())

	entry, _, err := k.GetChainMeta(ctx, observedChainId)
	if err != nil {
		return sdkerrors.Wrap(err, "failed to fetch chain meta entry")
	}
	bootstrapped := entry.LastAppliedChainHeight > 0

	// Stale-height check applies only after bootstrap. During cold-start there
	// is no committed reference height yet, so any positive vote is acceptable.
	if bootstrapped && blockNumber <= entry.LastAppliedChainHeight {
		k.Logger().Warn("chain meta vote rejected: stale block height",
			"chain_id", observedChainId,
			"validator", universalValidator.String(),
			"vote_height", blockNumber,
			"last_applied_height", entry.LastAppliedChainHeight,
		)
		return fmt.Errorf(
			"vote chain height %d is not greater than last applied chain height %d; re-vote with a newer block",
			blockNumber, entry.LastAppliedChainHeight,
		)
	}

func (k Keeper) GetGasPriceByChain(ctx sdk.Context, chainNamespace string) (*big.Int, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, abi, ueModuleAccAddress, handlerAddr, false, nil, "gasPriceByChainNamespace", chainNamespace)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call gasPriceByChainNamespace")
	}

	results, err := abi.Methods["gasPriceByChainNamespace"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack gasPriceByChainNamespace result")
	}

	return results[0].(*big.Int), nil
}

func (k Keeper) GetOutboundTxGasAndFees(ctx sdk.Context, prc20 common.Address, gasLimitWithBaseLimit *big.Int) (*GasFeeInfo, error) {
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	ucABI, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse UniversalCore ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	receipt, err := k.evmKeeper.CallEVM(ctx, ucABI, ueModuleAccAddress, handlerAddr, false, nil,
		"getOutboundTxGasAndFees", prc20, gasLimitWithBaseLimit)
	if err != nil {
		return nil, errors.Wrap(err, "failed to call getOutboundTxGasAndFees")
	}

	results, err := ucABI.Methods["getOutboundTxGasAndFees"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack getOutboundTxGasAndFees result")
	}

	gasToken := results[0].(common.Address)
	gasFee := results[1].(*big.Int)
	// protocolFee := results[2].(*big.Int) — not needed for outbound fields
	gasPrice := results[3].(*big.Int)
	// chainNamespace := results[4].(string) — not needed for outbound fields
	// gasLimitUsed (results[5]) is the exact gas limit the contract resolved
	// (caller-supplied or per-chain baseGasLimitByChainNamespace fallback).
	// Reading it directly avoids the gasFee/gasPrice round-trip and keeps us
	// in lock-step with the contract's own resolution.
	gasLimit := results[5].(*big.Int)

	return &GasFeeInfo{
		GasToken: gasToken,
		GasFee:   gasFee,
		GasPrice: gasPrice,
		GasLimit: gasLimit,
	}, nil
}
