### Title
Unchecked `Option::unwrap()` on external compiler output can crash the Sierra-to-Native compilation path on attacker-controlled class declarations - (File: crates/apollo_compile_to_native/src/compiler.rs)

### Summary
`SierraToNativeCompiler::compile` calls `AotContractExecutor::from_path(...)` and unconditionally unwraps its result with `.map_err(...)?.unwrap()`. The `Result` error case is handled, but the inner `Option` returned by the underlying `cairo_native` library is not checked before being unwrapped, mirroring the reported bug class (using a return value directly without validating it, causing a crash) in `ReadSVGImage()`/`xmlCreatePushParserCtxt()`. [1](#0-0) 

### Finding Description
`compile()` writes the native compilation subprocess output to a temp file and then reconstructs an `AotContractExecutor` from that file path: [2](#0-1) 
The `Err` branch of `from_path` is mapped into a `CompilationUtilError`, but the surrounding `Some/None` case of the `Option` it returns is never checked — the code assumes `from_path` always succeeds with `Some` when it returns `Ok`, and calls `.unwrap()` directly on the option. If the subprocess produces a file that `from_path` parses without an `Err` but for which the loader legitimately yields `None` (e.g. malformed/incomplete shared object produced from a crafted Sierra program that survives resource-limited compilation but fails post-processing), this `.unwrap()` panics.

This function is invoked from `process_compilation_request` in the blockifier's native class manager, which is reachable whenever a class declared via a `DECLARE` transaction is compiled to native code: [3](#0-2) 
In `CairoNativeMode::WaitOnCompilation`, this call happens synchronously inside `set_and_compile`, on the same execution path used to process a declare transaction: [4](#0-3) 
In `LazyCompilation` mode, it runs on a background worker thread spawned via `run_compilation_worker`: [5](#0-4) 

### Impact Explanation
A panic triggered by the unchecked `unwrap()` in `WaitOnCompilation` mode occurs on the thread handling declare-transaction validation/execution (gateway/batcher), which can abort that thread's work and, depending on panic-handling configuration, take down the process or poison shared state (e.g. mutex-guarded caches), causing a sequencer node to stop confirming new transactions — matching the "network unable to confirm new transactions" acceptance criterion. In `LazyCompilation` mode the panic is confined to the background compilation worker thread, which is lower severity (isolated thread crash, feature disabled going forward) but still degrades native-execution availability. This is a Medium-severity DoS-class analog: an unprivileged contract declarer can trigger the panic without any operator or peer misbehavior.

### Likelihood Explanation
Likelihood is uncertain because `AotContractExecutor::from_path`'s internal behavior (whether/when it returns `Ok(None)`) lives in the external `cairo_native` crate and could not be verified from this repository's index. If `from_path` never returns `Ok(None)` in current `cairo_native` versions, this specific `.unwrap()` is dead code and not exploitable; if it can return `Ok(None)` on certain malformed compiled artifacts, the path is directly reachable from a single `DECLARE` transaction whenever cairo_native compilation (`WaitOnCompilation` or `LazyCompilation`) is enabled in the node's configuration.

### Recommendation
Replace the blind `.unwrap()` with explicit handling of the `None` case, converting it into a `CompilationUtilError` (e.g. `CompilationUtilError::UnexpectedError("AotContractExecutor::from_path returned None".into())`) so that native-compilation failures surface as ordinary `Result::Err` values instead of process panics, consistent with how the rest of `process_compilation_request` treats compilation failures.

### Proof of Concept
Not concretely reproducible from the indexed sources alone: reproduction depends on constructing a Sierra program that causes the `cairo_native` compiler binary to emit a file which `AotContractExecutor::from_path` parses to `Ok(None)` rather than `Err`, which requires inspecting the external `cairo_native` crate implementation (not available in this repository) to confirm such a code path exists.

    pub fn compile(
        &self,
        contract_class: ContractClass,
    ) -> Result<AotContractExecutor, CompilationUtilError> {
        let compiler_binary_path = &self.path_to_binary;

        let output_file = NamedTempFile::new()?;
        let output_file_path = output_file.path().to_str().ok_or(
            CompilationUtilError::UnexpectedError("Failed to get output file path".to_owned()),
        )?;
        let optimization_level = self.config.optimization_level.to_string();
        let additional_args = [output_file_path, "--opt-level", &optimization_level];
        let resource_limits = ResourceLimits::new(
            Some(self.config.max_cpu_time),
            self.config.max_file_size,
            Some(self.config.max_memory_usage),
        );
        let _stdout = compile_with_args(
            compiler_binary_path,
            contract_class,
            &additional_args,
            resource_limits,
        )?;

        Ok(AotContractExecutor::from_path(output_file.path())
            .map_err(|e| CompilationUtilError::CompilationError(e.to_string()))?
            .unwrap())
    }

fn run_compilation_worker(
    class_cache: RawClassCache,
    receiver: Receiver<CompilationRequest>,
    compiler: Arc<SierraToNativeCompiler>,
    panic_on_compilation_failure: bool,
) {
    log::info!("Compilation worker started.");
    for compilation_request in receiver.iter() {
        process_compilation_request(
            class_cache.clone(),
            compiler.clone(),
            compilation_request,
            panic_on_compilation_failure,
        )
        .unwrap_or(());
    }
    log::info!("Compilation worker terminated.");
}

fn process_compilation_request(
    class_cache: RawClassCache,
    compiler: Arc<SierraToNativeCompiler>,
    compilation_request: CompilationRequest,
    panic_on_compilation_failure: bool,
) -> Result<(), CompilationUtilError> {
    let (class_hash, sierra, casm) = compilation_request;
    if let Some(CompiledClasses::V1Native(_)) = class_cache.get(&class_hash) {
        // The contract class is already compiled to native - skip the compilation.
        return Ok(());
    }
    let sierra_for_compilation = into_contract_class_for_compilation(sierra.as_ref());
    let start = Instant::now();
    let compilation_result = compiler.compile(sierra_for_compilation);
    let duration = start.elapsed();
    log::info!(
        "Compiling to native contract with class hash: {:#066x}. Duration: {:.3} seconds",
        class_hash.0,
        duration.as_secs_f32()
    );
    match compilation_result {
        Ok(executor) => {
            let native_compiled_class = NativeCompiledClassV1::new(executor, casm);
            class_cache.set(
                class_hash,
                CompiledClasses::V1Native(CachedCairoNative::Compiled(native_compiled_class)),
            );
            log::info!("Compilation succeeded");
            Ok(())
        }
        Err(err) => {
            class_cache.set(
                class_hash,
                CompiledClasses::V1Native(CachedCairoNative::CompilationFailed(casm)),
            );
            log::error!(
                "Error compiling contract class with class hash: {:#066x}: {err}",
                class_hash.0
            );
            NATIVE_COMPILATION_ERROR.increment(1);
            if panic_on_compilation_failure {
                panic!("Compilation of class hash: {:#066x} failed", class_hash.0);
            }
            Err(err)
        }
