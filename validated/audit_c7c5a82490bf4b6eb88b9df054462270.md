### Title
Missing `state_checkpoint_hash` validation in `ensure_match_transaction_info` allows replay-verification tooling to accept a diverged state root - (File: `types/src/transaction/mod.rs`)

### Summary
`TransactionOutput::ensure_match_transaction_info` is the authenticated-equality check used by chunk-executor replay verification, the `aptos-debugger`, `db-tool`'s `replay_on_archive`, and the CLI's transaction replay/simulate path to confirm that a locally re-executed transaction still matches the already-committed, validator-signed `TransactionInfo`. The function never compares `state_checkpoint_hash` (the JMT state root committed on-chain), so a divergence in the locally computed state root is silently accepted as a "match".

### Finding Description
`ensure_match_transaction_info` only checks `status`, `gas_used`, the write-set hash (`state_change_hash`), and the event root hash: [1](#0-0) . It never asserts `self`'s recomputed state-checkpoint root against `txn_info.state_checkpoint_hash()`. The code even documents this gap explicitly for the newer hot-state/position-state checkpoint hashes, but the comment confirms the general `state_checkpoint_hash` is likewise excluded from the comparator: [2](#0-1) 

This comparator is the sole state-integrity gate used by:
- `verify_execution` in the chunk executor, which re-executes a chunk and calls `ensure_match_transaction_info` per transaction to detect divergence during replay/backup-verification: [3](#0-2) 
- `db-tool`'s `replay_on_archive` and `aptos-debugger`, both of which call the same function.
- The Move CLI's transaction replay comparison: [4](#0-3) 

Because `state_checkpoint_hash` (the field that authenticates the actual world-state root produced by re-execution) is never compared, none of these tools can detect a bug in which re-execution computes the same write-set hash and events but a different Sparse-Merkle/Jellyfish-Merkle state root than what validators originally signed.

### Impact Explanation
Replay-verify tooling (`replay_on_archive`, backup "verify" jobs, `aptos-debugger`) exists specifically to catch state-root divergence between different VM/storage versions before it becomes an unrecoverable, silently-diverged chain state — the canonical hard-fork-detection safety net. Because the state-checkpoint root is excluded from the equality check, a determinism bug that changes the computed state root (but preserves the write-set hash and events, e.g. a bug isolated to how JMT/state-summary is derived from an otherwise-correct write set, or a bug limited to how position/hot-state trees are folded into the root) would pass verification even though the resulting state root — an authenticated, proof-bearing value referenced by every state proof and by consensus `LedgerInfo` — is wrong. This is exactly the "hard-fork-only divergence during commit, replay, or proof verification" class of impact: the safety mechanism meant to catch such divergence before it causes consensus/proof failures is blind to it.

### Likelihood Explanation
This does not directly corrupt live consensus state — normal block commit does not rely on this comparator (each node computes its own `state_checkpoint_hash` and it becomes authoritative once signed). The exposure is limited to whichever verification pipeline decides to trust `ensure_match_transaction_info` as its integrity oracle (replay-verify jobs, backup verification, debugging tools). If those jobs are relied upon operationally to gate releases or detect divergence prior to a hard fork, the gap means a state-root-changing bug could go undetected until it manifests as an actual on-chain divergence.

### Recommendation
Add a comparison in `ensure_match_transaction_info` (or a companion strict-mode) that verifies the locally computed state-checkpoint hash equals `txn_info.state_checkpoint_hash()` whenever both sides have a value (i.e., at checkpoint versions), in addition to the already-flagged follow-up work for hot-state/position-state hashes referenced in the TODO.

### Proof of Concept
No runnable PoC is provided — the finding is a static code-path proof (a missing field comparison in an equality check), not a memory/overflow exploit. The proof consists of:
1. `ensure_match_transaction_info`'s body never reads `txn_info.state_checkpoint_hash()` or any locally-computed checkpoint root: [5](#0-4) .
2. This function is the terminal check in the replay-verification call chain shown above, so any caller relying on it to detect state-root divergence will report success despite a diverged `state_checkpoint_hash`.

**Note on confidence:** I was not able to fully trace whether `LedgerUpdateOutput::ensure_transaction_infos_match` (used by `ReplayChunkVerifier`, a separate code path from `ensure_match_transaction_info`) performs a full-struct comparison that *does* include `state_checkpoint_hash` — if so, the state-sync/replay-chunk-verifier commit path is already protected and the gap is confined to the debugging/backup-verify tooling described above. I could not retrieve `ensure_transaction_infos_match`'s implementation within the available tool budget to confirm this distinction, so the severity should be treated as bounded to the tooling paths explicitly cited, pending that confirmation by a follow-up investigation.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );
