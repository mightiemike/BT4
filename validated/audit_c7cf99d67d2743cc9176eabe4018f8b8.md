### Title
Pausing vault accrual freezes the interest index, causing a temporarily-paused-then-unpaused vault to compute unhealthy positions and lock collateral withdrawals longer than expected - (File: mainnet/contracts/vault/v0-vault-usdh.clar)

### Summary
When a vault's `accrue` flag in `pause-states` is set, `accrue()` short-circuits to a pass-through branch that returns the cached `index`/`lindex` without updating them or `last-update`, instead of reverting. `market.clar` however calls `accrue-and-cache` and caches whatever `accrue()` returns per `stacks-block-time`. Callers such as `collateral-remove`, `borrow`, and liquidation flows rely on this cached index to compute ztoken collateral values (`resolve-ztoken`) and debt values for health checks within the same transaction. Because the pass-through path silently returns a stale index instead of failing, any position valuation performed while `accrue` is paused uses an index that no longer reflects the true redemption value/debt owed once the vault's `accrue` gate is later toggled off (unpause path deliberately re-bases `last-update` to "now", permanently discarding the interest that accrued during the pause window from being properly reconciled against per-block cached values used mid-transaction).

### Finding Description
`accrue()` in the vault contracts (e.g. `mainnet/contracts/vault/v0-vault-usdh.clar:833-861`, and identically in `v0-vault-stx.clar`, `v0-vault-sbtc.clar`, `v0-vault-ststx.clar`, `v0-vault-ststxbtc.clar`, `v0-vault-usdc.clar`) contains:

```
(if (get accrue states)
    ;; PAUSED: Pass-through without reverting
    (ok { index: idx, lindex: lidx })
    ;; NOT PAUSED: Normal accrual logic
    ...)
``` [1](#0-0) 

`market.clar`'s `accrue-and-cache` treats whatever `vault-accrue` returns as ground truth and caches it keyed only by `{timestamp: stacks-block-time, aid}`: [2](#0-1) 

That cached value is then fed into `resolve-ztoken`, which uses the cached `lindex` to price ztoken collateral, and into scaled-debt conversions via `get-cached-indexes` inside `borrow`, `collateral-remove` (health checks), and liquidation math: [3](#0-2) [4](#0-3) 

The `set-pause-states` function for `accrue` explicitly documents that it re-bases `last-update` to the current time upon unpausing so that the paused interval is skipped entirely rather than accrued retroactively:
```
;; When unpausing accrue, jump last-update to now to skip paused period
(if (and was-paused (not now-paused))
    (var-set last-update stacks-block-time)
    false)
``` [5](#0-4) 

The combination is the "pause that passes through instead of reverting" plus "clock advanced only on change" pattern: while `accrue` is paused, every market-side health/valuation computation for that vault's ztoken (or debt asset) silently uses the frozen index instead of failing loudly, so a user's collateral valuation and LTV computed by `collateral-remove`/liquidation logic during the paused window is based on a value the protocol itself acknowledges as stale (it deliberately discards, rather than defers, the true accrued interest once unpaused). Because `market.clar` never checks whether the underlying vault is paused before using the cached index for health/removal decisions, and because health checks (`is-healthy`, `is-healthy-with-mask`) gate whether collateral can be withdrawn, a user attempting `collateral-remove` while the relevant debt/collateral vault's `accrue` is paused can be blocked (health check fails using the frozen index that doesn't reflect the true debt/collateral state) even though, absent the pause, their position would be healthy enough to permit withdrawal - or conversely permitted to withdraw when it should not be, depending on price/interest direction. Either way, the withdrawal decision is made against a value whose freshness invariant (`accrue` reflecting true elapsed-time interest) has been broken by the pause's pass-through, and the position remains locked/frozen until the DAO unpauses `accrue`, at which point the skipped interval is discarded rather than applied - directly analogous to the report's "tokens locked slightly longer than expected because Governance's clear() hadn't run against Staking's stale check."

### Impact Explanation
This causes a temporary freezing of user funds: collateral cannot be safely removed by relying on values that are held artificially static instead of validated correctly, and the interest lost/skipped during the paused window on the debt side (or the yield the user should have accrued on the supply side) is permanently discarded rather than deferred, matching "temporary freezing of funds" and, for the interest/yield delta silently zeroed on unpause, "permanent freezing of ... unclaimed yield."

### Likelihood Explanation
`accrue` pause on a vault is triggered only through DAO governance (`set-pause-states`), so exploitation likelihood by an unprivileged attacker is low, but the vulnerability is a genuine code-level invariant break (pass-through instead of revert, and silently discarding elapsed interest) rather than solely an operational risk-management outcome, since `market.clar` has no defense (e.g. checking `is-liquidation-paused`-style guards for accrual freshness) against consuming a stale index for live health decisions.

### Recommendation
Either (a) make `accrue()` revert (not pass-through) when `accrue` is paused for any caller that needs a fresh index for valuation/health purposes, forcing `market.clar` operations that depend on the vault's index to fail closed rather than silently use stale data, or (b) have `market.clar`'s `accrue-and-cache`/health-check paths explicitly detect a paused-and-stale index and reject or flag valuations performed against it, and (c) when unpausing, accrue the skipped interval properly (e.g., by capturing accrued interest at pause time and continuing from there) instead of jumping `last-update` to "now" and discarding it.

### Proof of Concept
1. DAO calls `set-pause-states` on `v0-vault-usdh.clar` (or another vault backing a ztoken used as collateral / debt asset) with `accrue: true`. `accrue()` now returns `{index: idx, lindex: lidx}` unchanged on every call, per `mainnet/contracts/vault/v0-vault-usdh.clar:833-839`.
2. Time passes (multiple blocks) while `accrue` remains paused; the true economic index (interest actually owed/earned) diverges from the frozen `idx`/`lidx`, but every `accrue-and-cache` call in `market.clar` keeps caching the stale pair.
3. A user with debt or ztoken collateral in this vault calls `market.collateral-remove`. `resolve-ztoken`/`get-cached-indexes` returns the stale `lindex`, and `is-healthy`/`is-healthy-with-mask` evaluate the position against this stale collateral/debt valuation rather than the vault's true state — `mainnet/contracts/market/v0-4-market.clar:1107-1154`.
4. If the frozen index understates the user's true debt-adjusted health (e.g., true interest accrued would have made the position riskier), the withdrawal is incorrectly approved; if it overstates debt or understates collateral value, the withdrawal is incorrectly blocked, locking the user's collateral until the DAO unpauses.
5. DAO unpauses `accrue`: `last-update` jumps to `stacks-block-time`, per `mainnet/contracts/vault/v0-vault-stx.clar:733-737`, permanently discarding the interest that should have accrued during the paused window, so the pre-pause valuation used for any decisions made mid-pause can never be reconciled to the correct value.

(define-private (accrue-and-cache (aid uint))
  (let ((cache-key { timestamp: stacks-block-time, aid: aid })
        (cached? (map-get? index-cache cache-key)))

    (match cached?
      ;; cache HIT: return cached value (1 read only)
      cached-indexes (ok cached-indexes)

      ;; cache MISS: accrue and cache (vault-accrue now returns indexes)
      (let ((indexes (try! (vault-accrue aid))))
        ;; store in cache
        (map-set index-cache cache-key indexes)
        (ok indexes)))))
