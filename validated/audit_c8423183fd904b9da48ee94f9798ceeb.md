**Analysis:**

The restore path never accepts an attacker-controlled `(version, position) -> HashValue` triple for `EventAccumulatorSchema` from a backup bundle. Restore only supplies raw `Vec<ContractEvent>` per version (`save_transactions_impl` → `ledger_db.event_db().put_events_multiple_versions`), and the accumulator hashes stored under `EventAccumulatorSchema` are computed internally and deterministically from those events via `MerkleAccumulator::<EmptyReader, EventAccumulatorHasher>::append(&EmptyReader, 0, &event_hashes)`, then written under `(version, pos)` keys derived from that computation — not read from any externally supplied key/value pair. [1](#0-0) [2](#0-1) 

Because `Position`/`Version` for each leaf are computed from the append call itself (leaf index = enumeration order of the events actually restored for that version), there is no code path where an attacker can inject a mismatched `(version, position)` key bound to a different hash — the key and hash are always produced together from the same deterministic computation over the actually-supplied events. [3](#0-2) 

Additionally, even if an attacker tried to substitute a different set of events entirely, the restore/replay pipeline cross-checks the resulting `event_root_hash` (computed from `InMemoryEventAccumulator::from_leaves`) against `TransactionInfo::event_root_hash()`, which is itself bound via `TransactionAccumulatorProof`/`ledger_info_to_transaction_info_proof` to the signed `LedgerInfo`'s transaction-accumulator root. Any mismatch is rejected with an explicit error. [4](#0-3) [5](#0-4) 

So the proposed attack — crafting an `EventAccumulatorSchema` key/value pair with a version/position not matching the actual leaf index — has no entry point: the schema is never populated from untrusted, pre-computed key/hash data during restore; it is always recomputed from the events themselves, and any divergence from the authenticated `event_root_hash`/accumulator chain is rejected before commit.

define_schema!(
    EventAccumulatorSchema,
    Key,
    HashValue,
    EVENT_ACCUMULATOR_CF_NAME
);

type Key = (Version, Position);

impl KeyCodec<EventAccumulatorSchema> for Key {
    fn encode_key(&self) -> Result<Vec<u8>> {
        let (version, position) = self;

        let mut encoded_key = Vec::with_capacity(size_of::<Version>() + size_of::<u64>());
        encoded_key.write_u64::<BigEndian>(*version)?;
        encoded_key.write_u64::<BigEndian>(position.to_inorder_index())?;
        Ok(encoded_key)
    }

    fn decode_key(data: &[u8]) -> Result<Self> {
        ensure_slice_len_eq(data, size_of::<Self>())?;

        let version_size = size_of::<Version>();

        let version = (&data[..version_size]).read_u64::<BigEndian>()?;
        let position = (&data[version_size..]).read_u64::<BigEndian>()?;
        Ok((version, Position::from_inorder_index(position)))
    }
}

/// Verifies that a given `transaction_info` exists in the ledger using provided proof.
fn verify_transaction_info(
    ledger_info: &LedgerInfo,
    transaction_version: Version,
    transaction_info: &TransactionInfo,
    ledger_info_to_transaction_info_proof: &TransactionAccumulatorProof,
) -> Result<()> {
    ensure!(
        transaction_version <= ledger_info.version(),
        "Transaction version {} is newer than LedgerInfo version {}.",
        transaction_version,
        ledger_info.version(),
    );

    let transaction_info_hash = transaction_info.hash();
    ledger_info_to_transaction_info_proof.verify(
        ledger_info.transaction_accumulator_hash(),
        transaction_info_hash,
        transaction_version,
    )?;

    Ok(())
}
