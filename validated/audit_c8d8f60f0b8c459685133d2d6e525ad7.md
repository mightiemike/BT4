## Analog Found

### Title
Unbounded recursion when hashing/traversing `bytecode_segment_lengths` for declared classes leads to stack-exhaustion DoS - ([File: crates/starknet_api/src/contract_class/compiled_class_hash.rs])

### Summary
The Julia advisory describes uncontrolled recursion in `xmlCatalogXMLResolveURI` triggered by a self-referential/attacker-crafted nested structure with no recursion-depth bound, causing stack exhaustion and a crash. The sequencer contains the same bug class: several functions recursively walk a `NestedIntList`/`BytecodeSegmentNode` tree that describes the CASM bytecode's segment structure of a **declared class**, with no depth limit anywhere in the call chain.

### Finding Description
When a class is declared, its Sierra program is compiled to CASM and a `bytecode_segment_lengths: NestedIntList` field is produced, describing how the bytecode is partitioned into (possibly deeply nested) segments, mirroring the declarer-controlled Sierra program's function/branch structure.

Multiple code paths recursively process this attacker-influenced tree with **no depth check**:

- `bytecode_hash_node` recurses once per nesting level to compute the compiled-class hash: [1](#0-0) . It is invoked from `hash_inner`, which every declared class goes through: [2](#0-1) .
- `SierraCompiler::compile` calls this hashing routine synchronously, in the same (non-sandboxed, non-stack-limited) process as the class manager / gateway compilation service, right after the resource-limited compiler subprocess returns: [3](#0-2) .
- The Starknet OS re-execution / proving path builds the same recursive tree structure via `create_bytecode_segment_structure_inner` and hashes it with `BytecodeSegmentNode::hash`, both plain unbounded recursions: [4](#0-3) [5](#0-4) .

Only the total bytecode *size* is bounded (`max_bytecode_size`/`max_contract_bytecode_size`), not the *nesting depth* of the segment tree: [6](#0-5) . A pathological program can be structured so that each nesting level wraps a single one-felt leaf (degenerate right-leaning tree), making the recursion depth close to the bytecode length rather than log(length).

This is architecturally different from other recursive Cairo-execution paths in the codebase, which are explicitly protected: transaction/Cairo-VM call recursion is capped by `RecursionDepthGuard`/`max_recursion_depth` and gas metering [7](#0-6) , and Native execution intentionally pre-allocates an oversized real stack specifically to survive worst-case recursion before running out of gas [8](#0-7) . The compiled-class-hash computation has none of these protections — it runs outside the gas-metered VM, on the host's normal stack.

### Impact Explanation
An unprivileged declarer submitting a single `DECLARE` transaction can craft a Sierra program whose compiled CASM produces a deeply right-nested `bytecode_segment_lengths`. Computing the executable/compiled class hash then recurses to that depth on the sequencer's regular thread stack (class manager / Sierra compiler service on submission, and again in the Starknet OS on block re-execution/proving), risking a stack overflow and process crash — a Denial of Service that can prevent the node from processing new transactions/blocks, matching the "network unable to confirm new transactions" impact bar.

### Likelihood Explanation
Reaching the vulnerable code only requires submitting one `DECLARE` transaction with an adversarially structured (but otherwise valid, size-limited) Sierra program; no special privileges are needed. The severity ultimately depends on how deep a nesting the trusted `cairo-lang-sierra-to-casm` compiler can be induced to emit for a crafted-but-legal Sierra program, and on the compiled binary's actual stack size/frame footprint in each recursive call — this needs to be verified experimentally (constructing a Sierra program that forces maximal nesting) rather than assumed.

### Recommendation
Add an explicit maximum recursion/nesting-depth check (and/or convert the recursive traversal into an iterative, explicit-stack algorithm) in `bytecode_hash_node` (`crates/starknet_api/src/contract_class/compiled_class_hash.rs`), `create_bytecode_segment_structure_inner` and `BytecodeSegmentNode::hash` (`crates/starknet_os/src/hints/hint_implementation/compiled_class/utils.rs`), rejecting/erroring out declared classes whose segment tree exceeds a safe bound, consistent with the existing `max_recursion_depth`/`RecursionDepthGuard` pattern already used elsewhere in the codebase.

### Proof of Concept
1. Craft a Sierra program whose control-flow/function structure forces the CASM compiler to emit a `bytecode_segment_lengths` value shaped as `Node([Node([Node([...Leaf(1)...])])])` with nesting depth `N` in the tens/hundreds of thousands (bounded only by `max_bytecode_size`, not depth).
2. Submit it via `DECLARE` (satisfies `validate_class_length`/`validate_sierra_version` since only total size, not tree depth, is checked — see [6](#0-5) ).
3. The class manager compiles and calls `hash(&HashVersion::V2)` → `bytecode_hash_node`, recursing `N` times on the host thread stack ( [3](#0-2) , [1](#0-0) ), potentially overflowing the stack and crashing the service.
4. The same class re-executed by the Starknet OS triggers the analogous recursive `create_bytecode_segment_structure_inner`/`BytecodeSegmentNode::hash` path.

fn bytecode_hash_node<H, NL>(iter: &mut impl Iterator<Item = Felt>, node: &NL) -> (usize, Felt)
where
    H: StarkHash,
    NL: HashableNestedIntList,
{
    if node.is_leaf() {
        let len = node.get_segment_length();
        let data = iter.take(len).collect_vec();
        assert_eq!(data.len(), len);
        (len, H::hash_array(&data))
    } else {
        // Compute `1 + poseidon(len0, hash0, len1, hash1, ...)`.
        let inner_nodes = node
            .iter_children()
            .map(|child| bytecode_hash_node::<H, NL>(iter, child))
            .collect_vec();
        let hash = H::hash_array(
            &inner_nodes.iter().flat_map(|(len, hash)| [Felt::from(*len), *hash]).collect_vec(),
        ) + Felt::ONE;
        (inner_nodes.iter().map(|(len, _)| len).sum(), hash)
    }
}

impl BytecodeSegmentNode {
    pub(crate) fn hash<H: HashFunction>(&self) -> StarkHash {
        match self {
            BytecodeSegmentNode::Leaf(leaf) => H::hash_array(&leaf.data),
            BytecodeSegmentNode::InnerNode(inner_node) => {
                let flatten_input: Vec<_> = inner_node
                    .segments
                    .iter()
                    .flat_map(|segment| [Felt::from(segment.length), segment.node.hash::<H>()])
                    .collect();
                H::hash_array(&flatten_input) + Felt::ONE
            }
        }
    }

    pub(crate) fn is_leaf(&self) -> bool {
        match self {
            BytecodeSegmentNode::Leaf(_) => true,
            BytecodeSegmentNode::InnerNode(_) => false,
        }
    }
}

pub(crate) fn create_bytecode_segment_structure_inner(
    bytecode: &[Felt],
    bytecode_segment_lengths: NestedIntList,
    bytecode_offset: usize,
) -> (BytecodeSegmentNode, usize) {
    match bytecode_segment_lengths {
        NestedIntList::Leaf(length) => {
            let segment_end = bytecode_offset + length;
            let bytecode_segment = bytecode[bytecode_offset..segment_end].to_vec();

            (BytecodeSegmentNode::Leaf(BytecodeSegmentLeaf { data: bytecode_segment }), length)
        }
        NestedIntList::Node(lengths) => {
            let mut segments = vec![];
            let mut total_len = 0;
            let mut bytecode_offset = bytecode_offset;

            for item in lengths {
                let (current_structure, item_len) =
                    create_bytecode_segment_structure_inner(bytecode, item, bytecode_offset);

                segments.push(BytecodeSegment { length: item_len, node: current_structure });

                bytecode_offset += item_len;
                total_len += item_len;
            }

            (BytecodeSegmentNode::InnerNode(BytecodeSegmentInnerNode { segments }), total_len)
        }
    }
}

// Ensure that the recursion depth does not exceed the maximum allowed depth.
struct RecursionDepthGuard {
    current_depth: Arc<RefCell<usize>>,
    max_depth: usize,
}

impl RecursionDepthGuard {
    fn new(current_depth: Arc<RefCell<usize>>, max_depth: usize) -> Self {
        Self { current_depth, max_depth }
    }

    // Tries to increment the current recursion depth and returns an error if the maximum depth
    // would be exceeded.
    fn try_increment_and_check_depth(&mut self) -> Result<(), EntryPointExecutionError> {
        *self.current_depth.borrow_mut() += 1;
        if *self.current_depth.borrow() > self.max_depth {
            return Err(EntryPointExecutionError::RecursionDepthExceeded);
        }
        Ok(())
    }
}
