### Title
`sanitizeHost()` can throw an unhandled exception instead of returning null/InvalidHostError on malformed base64 `host` input - ([File: packages/apps/shopify-api/lib/utils/shop-validator.ts])

### Summary
`sanitizeHost()` validates the `host` query parameter with a base64 character-class regex that does not enforce a valid base64 length, then unconditionally calls `atob()` (via `decodeHost`) and feeds the result into `new URL()` with no surrounding `try/catch`. An attacker-controlled `host` value that matches the character-class regex but is not properly padded/length-valid base64 (e.g. a single character like `"A"`) causes `atob()` to throw, and this exception is not caught anywhere in `sanitizeHost()`, propagating out of the function instead of returning `null` or throwing `InvalidHostError`.

### Finding Description
`sanitizeHost()` in `packages/apps/shopify-api/lib/utils/shop-validator.ts` (lines 52–90) validates `host` with: [1](#0-0) 
`base64regex = /^[0-9a-zA-Z+/]+={0,2}$/` only checks the character set and optional trailing padding characters — it does not require the string length to be a multiple of 4 (mod-4 remainder 1 is invalid base64). A string such as `"A"` (or any base64-alphabet string whose length mod 4 is 1) passes this regex.

If `sanitizedHost` is truthy, the code immediately calls `decodeHost(sanitizedHost)` → `atob(host)` (`packages/apps/shopify-api/lib/auth/decode-host.ts`, line 2) and wraps the result directly in `new URL(\`https://${...}\`)` with no `try/catch` anywhere in `sanitizeHost()`. In Node.js/V8, `atob()` throws a `DOMException`/`TypeError`-like error ("The string to be decoded is not correctly encoded") for base64 strings with invalid length, and `new URL()` throws a `TypeError` for malformed/empty authorities. Either failure mode escapes `sanitizeHost()` unhandled, rather than being converted into `return null` or `throw new InvalidHostError(...)` as the function's contract implies (see the sibling `INVALID_HOSTS` handling in `packages/apps/shopify-api/lib/utils/__tests__/shop-validator.test.ts`, lines 33–50, which only covers regex-level rejections and domain-mismatch rejections, not decode-level failures).

This function is reachable directly from attacker-controlled query parameters in multiple auth-adjacent paths without any prior validation of `host`:
- `getEmbeddedAppUrl`/`buildEmbeddedAppUrl` in `packages/apps/shopify-api/lib/auth/get-embedded-app-url.ts` (lines 32, 48) takes `host` straight from `url.searchParams.get('host')`.
- `redirectToAuth`'s `clientSideRedirect` in `packages/apps/shopify-app-express/src/redirect-to-auth.ts` (line 37) takes `host` straight from `req.query.host`.
- `validateShopAndHostParams` in the Remix/React Router adapters takes `host` straight from `url.searchParams.get('host')`.

None of these call sites wrap `sanitizeHost()`/`sanitizeShop()`/`buildEmbeddedAppUrl()` in a `try/catch` for generic exceptions — they only check the return value or catch the documented `InvalidHostError`/`InvalidShopError`. An unhandled `atob`/`URL` exception in these code paths would surface as an unhandled server error (500 / unhandled promise rejection) rather than the intended graceful `null`/`InvalidHostError` handling.

### Impact Explanation
This is a denial-of-service class issue in an authentication-adjacent handler: an unauthenticated attacker can trigger an unhandled exception in `sanitizeHost()` by supplying a crafted `host` query parameter to any endpoint that calls `sanitizeHost`, `buildEmbeddedAppUrl`, or `getEmbeddedAppUrl` (auth begin/callback, embedded-app URL construction, shop/host validation middleware). Depending on the host framework's error handling, this could cause an unhandled promise rejection or process crash rather than a clean 400/redirect response. This does not directly lead to session/token forgery or cross-tenant access — the impact is limited to crash/DoS of the request path handling `host`.

### Likelihood Explanation
High feasibility: the attacker needs no privileges, no secret, and no non-default configuration — only the ability to send an HTTP GET/POST with a `host` query parameter (e.g., to the auth begin/callback route, or any embedded-app URL builder endpoint). Crafting a value like `host=A` (or any base64-alphabet string with length mod 4 = 1) is trivial and repeatable on every request.

### Recommendation
Wrap the `decodeHost`/`new URL` logic in `sanitizeHost()` in a `try/catch`, treating any decode or URL-parsing failure as an invalid host (return `null`, or throw `InvalidHostError` when `throwOnInvalid` is true), mirroring the existing regex-mismatch handling. Additionally, tighten `base64regex` to enforce valid base64 length (`^(?:[0-9a-zA-Z+/]{4})*(?:[0-9a-zA-Z+/]{2}==|[0-9a-zA-Z+/]{3}=)?$`) to reject malformed lengths before attempting to decode.

```typescript
export function sanitizeHost(config: ConfigInterface) {
  return (host: string, throwOnInvalid = false): string | null => {
    const base64regex = /^[0-9a-zA-Z+/]+={0,2}$/;

    let sanitizedHost = base64regex.test(host) ? host : null;
    if (sanitizedHost) {
      const {hostname} = new URL(`https://${decodeHost(sanitizedHost)}`);

      const originsRegex = [
        'myshopify\\.com',
        'shopify\\.com',
        'myshopify\\.io',
        'spin\\.dev',
        'shop\\.dev',
      ];

      if (config.domainTransformations) {
        const hostTransformationDomains = config.domainTransformations
          .filter((t) => t.includeHost !== false)
          .flatMap((t) =>
            getTransformationDomains({
              ...config,
              domainTransformations: [t],
            }),
          );
        originsRegex.push(...hostTransformationDomains);
      }

      const hostRegex = new RegExp(`\\.(${originsRegex.join('|')})$`);
      if (!hostRegex.test(hostname)) {
        sanitizedHost = null;
      }
    }
    if (!sanitizedHost && throwOnInvalid) {
      throw new InvalidHostError('Received invalid host argument');
    }

    return sanitizedHost;
  };
```

```typescript
  config: ConfigInterface,
): BuildEmbeddedAppUrl {
  return (host: string): string => {
    sanitizeHost(config)(host, true);
    const decodedHost = decodeHost(host);
```

```typescript
function clientSideRedirect(
  api: Shopify,
  config: AppConfigInterface,
  req: Request,
  res: Response,
  shop: string,
): void {
  const host = api.utils.sanitizeHost(req.query.host as string);
  if (!host) {
    res.status(500);
    res.send('No host provided');
    return;
  }

  const redirectUriParams = new URLSearchParams({shop, host}).toString();
  const redirectUri = `${api.config.hostScheme}://${api.config.hostName}${config.auth.path}?${redirectUriParams}`;

  redirectOutOfApp({config, api})({req, res, redirectUri, shop});
}
```
