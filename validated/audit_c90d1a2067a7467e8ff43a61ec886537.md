### Title
Excess Deposit Not Returned in `AddressRegistrar::register` on Successful Registration — (`File: runtime/near-wallet-contract/implementation/address-registrar/src/lib.rs`)

### Summary

`AddressRegistrar::register` is a `#[payable]` function that accepts a NEAR deposit, checks that `given_deposit >= required_deposit`, and on the success path (`Entry::Vacant`) inserts the mapping and returns — without refunding `given_deposit − required_deposit`. The excess is permanently locked in the contract's balance. The collision path (`Entry::Occupied`) correctly issues a full refund via a promise transfer, making the asymmetry explicit in the code.

### Finding Description

`AddressRegistrar::register` computes `required_deposit` as `storage_byte_cost * (20 + account_id.len())` and enforces a minimum via a panic if `given_deposit < required_deposit`. [1](#0-0) 

On the `Entry::Vacant` (new registration) path the function inserts the entry and returns `Some(address)` with no refund of the surplus: [2](#0-1) 

On the `Entry::Occupied` (collision) path the function explicitly refunds the full `given_deposit`: [3](#0-2) 

The contract has no owner, no upgrade path, and no sweep function. Any tokens above `required_deposit` sent on a successful registration are permanently locked.

The existing integration test confirms this behavior: it asserts the registrar's balance increases by **at least** `deposit_amount` on a successful call, and by **less than** `deposit_amount` on a duplicate (where the refund fires): [4](#0-3) 

### Impact Explanation

Any caller who attaches more than `required_deposit` to a successful `register()` call permanently loses the excess yoctoNEAR. Because `required_deposit` is computed on-chain from `env::storage_byte_cost()` (which can change across protocol versions) and `account_id.len()`, callers who add a safety margin — a common practice — will consistently overpay. The lost tokens accumulate in the contract with no recovery path.

This maps directly to the "excess funds not returned" bug class: a payable entry point accepts native tokens, enforces a minimum, uses only the minimum, and silently retains the rest.

### Likelihood Explanation

The `AddressRegistrar` is the canonical on-chain registry for ETH-implicit account address lookups, called by the wallet contract infrastructure. Any integrator or user who calls `register()` with a deposit larger than the exact storage cost — which is the safe and common approach when the exact cost is not known ahead of time — will lose the excess. The collision path's explicit refund logic shows the authors were aware of the refund pattern; the omission on the success path is an oversight rather than intentional design.

### Recommendation

On the `Entry::Vacant` path, compute the surplus and issue a refund promise if it is non-zero:

```rust
Entry::Vacant(entry) => {
    let surplus = given_deposit
        .as_yoctonear()
        .saturating_sub(required_deposit.as_yoctonear());
    entry.insert(account_id);
    if surplus > 0 {
        let refund = env::promise_batch_create(&env::predecessor_account_id());
        env::promise_batch_action_transfer(
            refund,
            NearToken::from_yoctonear(surplus),
        );
    }
    Some(address)
}
```

Alternatively, document the exact required deposit amount in the ABI and panic on any surplus, forcing callers to send the exact amount.

### Proof of Concept

1. Compute `required_deposit = storage_byte_cost * (20 + len("alice.near"))` off-chain.
2. Call `register({ account_id: "alice.near" })` with `deposit = required_deposit + 1_000_000_000_000_000_000_000` (1 mNEAR surplus).
3. The call succeeds, the mapping is stored, and `Some(address)` is returned.
4. Query the caller's balance before and after: the caller is debited `required_deposit + 1_000_000_000_000_000_000_000` with no refund receipt emitted.
5. Query the `AddressRegistrar` contract balance: it increased by the full `given_deposit`, not just `required_deposit`.

The surplus is irrecoverably locked in the contract. [5](#0-4)

```rust
    #[payable]
    pub fn register(&mut self, account_id: AccountId) -> Option<String> {
        // It is not allowed to register eth-implicit accounts because the purpose
        // of the registry is to allow looking up the named account associated with
        // an address obtained via hashing, but eth-implicit accounts are already
        // parsable as addresses.
        if is_eth_implicit(&account_id) {
            let log_message = format!("Refuse to register eth-implicit account {account_id}");
            env::log_str(&log_message);
            return None;
        }

        // Must store the address and the account id
        let bytes_to_store = 20 + (account_id.len() as u128);
        let required_deposit =
            NearToken::from_yoctonear(env::storage_byte_cost().as_yoctonear() * bytes_to_store);
        let given_deposit = env::attached_deposit();
        // The caller must pay for the storage cost of registering.
        if given_deposit < required_deposit {
            let message = format!(
                "Insufficient deposit to cover storage cost. Given={} Expected={}",
                given_deposit.as_yoctonear(),
                required_deposit.as_yoctonear(),
            );
            env::panic_str(&message);
        }

        let address = account_id_to_address(&account_id);

        match self.addresses.entry(address) {
            Entry::Vacant(entry) => {
                let address = format!("0x{}", hex::encode(address));
                let log_message = format!("Added entry {} -> {}", address, account_id);
                entry.insert(account_id);
                env::log_str(&log_message);
                Some(address)
            }
            Entry::Occupied(entry) => {
                let log_message = format!(
                    "Address collision between {} and {}. Keeping the former.",
                    entry.get(),
                    account_id
                );
                env::log_str(&log_message);
                // Transfer the deposit back to the caller since no storage was updated.
                let refund_promise = env::promise_batch_create(&env::predecessor_account_id());
                env::promise_batch_action_transfer(refund_promise, given_deposit);
                None
            }
        }
    }
```
