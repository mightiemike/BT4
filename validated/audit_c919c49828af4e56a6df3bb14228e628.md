**Reasoning summary:** `pox_5_make_signer_set` is a pure, deterministic function of the on-chain PoX-5 stacking entries at reward-cycle-computation time [1](#0-0) . Every honest node processes the same consensus-visible stacking transactions and thus computes byte-for-byte identical `remainder` values, the same sort order, and the same tie-break outcome at line 902 [2](#0-1) . There is no path by which two honest nodes could disagree on the resulting `signer_set`, so the "SIGNING equality" between two nodes is never broken — the function is not an attacker-vs-node computation, it is a network-wide agreed-upon derivation from shared state.

The premise that an attacker can cheaply win a leftover slot with "near-zero stake" also does not hold under the algorithm's math: for entries with `stacked_amt < threshold`, `weight == 0` and `remainder == stacked_amt` itself [3](#0-2) , so a near-zero stake produces a near-zero remainder, which sorts near the bottom of the descending-remainder order and only wins if `leftover` is large enough to reach it — a function of the actual reward-slot count and aggregate stake distribution, not attacker-controlled signing-key selection. Even in a contrived scenario where remainders coincidentally tie, the deterministic ascending-key tie-break (documented at signer_set.rs:896-903 as intentional for consensus determinism) is applied identically by all nodes, so it cannot create a fork, an invalid-block-accepted/valid-block-rejected divergence, or a reproducibility failure. At most this is a critique of the largest-remainder (Hare quota) apportionment's fairness properties, which falls under the explicitly out-of-scope category of "pox-5 economics."
