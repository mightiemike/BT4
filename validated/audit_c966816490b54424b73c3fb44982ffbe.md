### Title
Truncated base-fee division in `CalculateGasCost` causes systematic under-collection of gas fees for gasless smart-contract execution - (File: `x/uexecutor/keeper/fees.go`)

### Summary
`x/uexecutor/keeper/fees.go`'s `CalculateGasCost` converts the feemarket's `LegacyDec` base fee into an integer `upc` amount by doing `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))` on the raw 18-decimal fixed-point representation, based on the developer assumption ("since 1 upc is the smallest denomination... base fee is always a whole number of upc"). This is the same class of bug as the SwapNet `H04` report: an accounting-critical value is derived through integer division and truncation, and the code assumes the truncated result is exact rather than validating it or reconciling it against ground truth.

### Finding Description [1](#0-0) 

`CalculateGasCost` is used by `DeductGasFeesFromReceipt` [2](#0-1)  to compute how much `upc` to burn from a UEA/smart-contract account after a module-originated `DerivedEVMCall` (`CallExecuteUniversalTx`) executes a universal payload, in `execute_inbound_funds_and_payload.go` and `execute_inbound_gas_and_payload.go`.

These flows deliberately run the EVM call as `gasless=true` via `DerivedEVMCall` [3](#0-2) , meaning the normal ante-handler fee-deduction path (which uses the SDK's exact `LegacyDec`-based fee computation) is bypassed entirely. `CalculateGasCost`/`DeductAndBurnFees` become the *only* mechanism recovering gas cost from the user for this execution path.

The comment in the code assumes `baseFee` is always a whole number of `upc`, but this is never validated — the function blindly does `baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))`, silently discarding any fractional remainder if that assumption is ever violated (e.g., if the feemarket's EIP-1559-style adjustment produces a `LegacyDec` base fee that is not an exact integer, which is the normal, expected behavior for fee-market base-fee adjustment algorithms that multiply/divide by elasticity and change-denominator constants). Because `effectiveGasPrice` is derived directly from this truncated value and then multiplied by `gasUsed` (potentially millions of gas units), any fractional-upc drift in the base fee is amplified by `gasUsed`, producing a `gasCost` that is smaller than the fee the network/EVM module actually assumes for that block's base-fee level.

This exactly parallels the SwapNet issue: a derived quantity (`collateralRequired`/here, `gasCost`) is computed via one formula involving division/truncation and is trusted as ground truth for a fund-moving action (`DeductAndBurnFees`), without reconciling it against the real, authoritative fee value the rest of the system (EVM/feemarket) is using.

### Impact Explanation
If the feemarket's base fee is ever non-integer at the `upc` (18-decimal) granularity — which is the normal outcome of continuous EIP-1559-style base-fee adjustment — every gasless universal-payload execution routed through `DeductGasFeesFromReceipt` will systematically under-burn `upc` from the paying account, in proportion to `gasUsed × fractional_upc_remainder`. This is an unprivileged, attacker-reachable native-asset accounting corruption: any ordinary user submitting inbound funds-and-payload / gas-and-payload universal transactions benefits from paying strictly less than the protocol's intended gas cost, with no upper bound other than the magnitude of `gasUsed` and the fractional drift of the base fee at execution time. Because this fee is meant to be burned, the practical effect is under-burning of `upc` (protocol systematically loses intended fee revenue) each time the base fee carries a fractional component — a reachable, un-privileged corruption of gas-fee accounting.

### Likelihood Explanation
Reaching this code path requires only submitting an ordinary funds-and-payload or gas-and-payload inbound with a smart-contract recipient — no privileged access needed. The trigger condition (a non-integer base fee) is plausible under normal network operation once the base fee has been adjusted away from its genesis value by the feemarket module, but I was unable to locate and inspect the feemarket base-fee adjustment implementation in this repository (it appears to be a vendored/external `cosmos/evm` dependency not indexed here), so I cannot confirm with certainty how often/whether the base fee actually becomes fractional at the 18-decimal `LegacyDec` granularity in production. This is the main uncertainty in this finding.

### Recommendation
Do not assume the base fee is always a whole `upc` value. Use `baseFee.TruncateInt()` (or, better, round using the same rounding convention the ante handler/feemarket module uses elsewhere, e.g. `Ceil()` as seen in `app/cosmos/min_gas_price.go`) and reconcile any fractional remainder rather than silently discarding it via raw big-int division on the internal fixed-point representation. Additionally, add an invariant check/assertion (or unit test with a fractional base fee) verifying `CalculateGasCost`'s output matches what the EVM fee logic would compute for the same gas usage and base fee, so any future drift between the two independent implementations is caught rather than silently under-collecting funds.

### Proof of Concept
Conceptual (verification was not fully possible without running the feemarket adjustment code):
1. Advance blocks so the feemarket's `GetBaseFee` returns a `LegacyDec` such as `1000000000.700000000000000000` (fractional `upc`).
2. Submit an inbound `GAS_AND_PAYLOAD`/`FUNDS_AND_PAYLOAD` message targeting a deployed smart-contract recipient with a large `GasLimit`/`gasUsed` (e.g., 1,000,000 gas).
3. Compare the `upc` actually burned via `DeductGasFeesFromReceipt` → `CalculateGasCost` (which truncates `1000000000.7` down to `1000000000`) against the fee that would be owed at the un-truncated rate (`1000000000.7 * gasUsed`).
4. The difference (`0.7 * gasUsed` upc, i.e. 700,000 upc in this example) is under-collected on every execution — a repeatable, unprivileged drain of intended protocol fee revenue that compounds across all gasless universal-payload executions network-wide.

func (k Keeper) CalculateGasCost(
	baseFee sdkmath.LegacyDec,
	maxFeePerGas *big.Int,
	maxPriorityFeePerGas *big.Int,
	gasUsed uint64,
) (*big.Int, error) {
	baseFeeBig := baseFee.BigInt()
	// @dev: LegacyDec stores values with 18-decimal precision internally, so 1 upc = 1e18
	// in the LegacyDec representation. Since 1 upc is the smallest denomination (like wei
	// in Ethereum), the base fee is always a whole number of upc -- no fractional upc exists.
	// This division unwraps the LegacyDec encoding back to the actual upc amount.
	// Note: baseFee.BigInt() returns a reference to the internal big.Int; the in-place Div
	// mutates it, which is safe here since baseFee is a local value-type copy.
	baseFeeBig.Div(baseFeeBig, big.NewInt(1e18))

	// Step 1: Validate maxFeePerGas >= baseFee
	if maxFeePerGas.Cmp(baseFeeBig) < 0 {
		return nil, fmt.Errorf("maxFeePerGas (%s) cannot be less than baseFee (%s)", maxFeePerGas, baseFeeBig)
	}

	// Step 2: Calculate baseFee + maxPriorityFeePerGas (potential effective gas price)
	// @dev: Currently, we are not using maxPriorityFeePerGas in the calculation
	// tipPlusBase := new(big.Int).Add(baseFeeBig, maxPriorityFeePerGas)
	// tipPlusBase := maxFeePerGas

	// Step 3: Find effective gas price by taking minimum
	// @dev: Currently, since we are not using maxPriorityFeePerGas, effectiveGasPrice is just baseFee
	effectiveGasPrice := new(big.Int).Set(baseFeeBig)
	// if tipPlusBase.Cmp(maxFeePerGas) == -1 {
	// 	effectiveGasPrice = tipPlusBase
	// }

	// Step 4: Calculate final gas cost: effectiveGasPrice * gasUsed
	gasUsedBig := new(big.Int).SetUint64(gasUsed)
	gasCost := new(big.Int).Mul(effectiveGasPrice, gasUsedBig)

	k.Logger().Debug("gas cost calculated",
		"base_fee", baseFee.String(),
		"effective_gas_price", effectiveGasPrice.String(),
		"gas_used", gasUsed,
		"gas_cost", gasCost.String(),
	)

	return gasCost, nil
}

func (k Keeper) DeductGasFeesFromReceipt(
	ctx context.Context,
	sdkCtx sdk.Context,
	recipient common.Address,
	receipt *evmtypes.MsgEthereumTxResponse,
	universalPayload *types.UniversalPayload,
) error {
	if receipt == nil || receipt.GasUsed == 0 {
		return nil
	}
	if universalPayload == nil {
		return nil
	}

	abiPayload, err := types.NewAbiUniversalPayload(universalPayload)
	if err != nil {
		return fmt.Errorf("failed to parse payload for gas deduction: %w", err)
	}

	baseFee := k.feemarketKeeper.GetBaseFee(sdkCtx)
	if baseFee.IsNil() {
		return fmt.Errorf("base fee not found")
	}

	gasCost, err := k.CalculateGasCost(baseFee, abiPayload.MaxFeePerGas, abiPayload.MaxPriorityFeePerGas, receipt.GasUsed)
	if err != nil {
		return fmt.Errorf("failed to calculate gas cost: %w", err)
	}
	if gasCost.Sign() <= 0 {
		return nil
	}

	gasUsedBig := new(big.Int).SetUint64(receipt.GasUsed)
	if gasUsedBig.Cmp(abiPayload.GasLimit) > 0 {
		return fmt.Errorf("gas used (%d) exceeds gas limit (%s)", receipt.GasUsed, abiPayload.GasLimit.String())
	}

	recipientAccAddr := sdk.AccAddress(recipient.Bytes())
	balance := k.bankKeeper.GetBalance(sdkCtx, recipientAccAddr, pchaintypes.BaseDenom)

	if err := k.DeductAndBurnFees(ctx, recipientAccAddr, gasCost); err != nil {
		return fmt.Errorf("insufficient gas: required %s upc, available %s upc, gas_used %d, from %s: %w",
			gasCost.String(), balance.Amount.String(), receipt.GasUsed, recipient.Hex(), err)
	}
