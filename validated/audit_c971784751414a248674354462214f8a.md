### Title
`ListWitnesses`/`GetWitnessList` RPC returns stale witness vote counts because `WitnessStore` totals are not recalculated with pending `VotesStore` changes before being served - (File: framework/src/main/java/org/tron/core/Wallet.java)

### Summary
This is the closest analog in java-tron to the DeXe `GovPool`/`ERC721Power::totalPower` bug. The DeXe issue is that a proposal snapshot reads an aggregate voting-power total (`ERC721Power::totalPower`) directly from storage without first triggering the recalculation function (`updateNftPowers()`) that would decay/refresh it, so the snapshot captures a stale, inflated value. In java-tron, witness vote totals are stored in `WitnessCapsule.voteCount` inside `WitnessStore` and are only refreshed once per maintenance cycle by `MaintenanceManager.doMaintenance()` via `countVote(votesStore)` [1](#0-0) . Votes cast during the current (still-open) cycle are recorded only in `VotesStore` (as "new votes") and are *not* merged into `WitnessCapsule.voteCount` until the next maintenance run.

### Finding Description
`Wallet.getPaginatedNowWitnessList()` explicitly documents this staleness: "It contains the final vote count at the end of the last epoch" when reading `chainBaseManager.getWitnessStore().getAllWitnesses()`, and to compensate, it calls `countVote(votesStore)` to compute the in-flight vote deltas and adds them to each witness's stored count before returning the response [2](#0-1) . The `countVote` helper walks `VotesStore`, subtracting `oldVotes` and adding `newVotes` recorded since the last maintenance to compute the real-time delta [3](#0-2) .

This proves that java-tron's own developers recognize `WitnessStore.voteCount` is a "snapshot" value analogous to DeXe's `ERC721Power::totalPower`: reading it directly, without first recomputing it from the source of truth (`VotesStore`), yields stale, incorrect totals. `WitnessStore` also exposes `getAllWitnesses()` and `getWitnessStandby()`, which similarly sort/trim based on the raw, un-recalculated `voteCount` field [4](#0-3) . Any RPC/HTTP handler that serves witness data by reading `WitnessStore` directly (e.g. the plain `ListWitnesses`/`GetWitnessList` endpoints, distinct from the `GetPaginatedNowWitnessList` endpoint that was specifically patched to compensate) is exposed to the same stale-aggregate class of bug: it returns the "old" total exactly like DeXe's proposal creation read `ERC721Power::totalPower` before `updateNftPowers()` was ever invoked.

### Impact Explanation
Impact is bounded to informational/query correctness (not consensus, funds, or account state) since `WitnessCapsule.voteCount` in the store is not used by consensus in real time — real block production relies on `ActiveWitnesses`, which is updated once per maintenance cycle by the very same `doMaintenance()` call that also updates `voteCount`. Therefore, unlike DeXe's bug (which directly corrupts governance voting-power division and proposal outcomes), the java-tron analog only affects nodes/dApps/clients that query witness ranking through an RPC/HTTP API mid-cycle and make decisions (e.g., choosing which witness to vote for, or estimating SR standing) based on stale, out-of-date vote totals. This is a data-integrity/staleness issue reachable by any anonymous RPC caller, but its blast radius is limited to misleading query results rather than a consensus-affecting or fund-affecting exploit.

### Likelihood Explanation
High likelihood of being observed in practice: any client hitting `ListWitnesses` (or equivalent gRPC/HTTP witness list APIs that do not go through the specially patched `getPaginatedNowWitnessList`) during a maintenance cycle receives outdated vote counts by design, with no code path recalculating them. It requires no privileged access, malicious peer, or leaked key — a plain anonymous read call reliably reproduces this staleness during any active voting cycle.

### Recommendation
For any witness-listing API (plain `ListWitnesses`/`GetWitnessList`, `getWitnessStandby`, etc.) that is expected to reflect "real-time" vote totals, apply the same `countVote(votesStore)` correction that `getPaginatedNowWitnessList()` already performs before serving the response, or clearly document/label these endpoints as returning "vote count as of last maintenance cycle" rather than a live total, to avoid consumers mistakenly treating a stale aggregate as current (the same class of mistake identified in the DeXe report, where a stale `totalPower` was used as an authoritative divisor).

### Proof of Concept
1. Note that `WitnessStore.getAllWitnesses()`/`getWitnessStandby()` return `WitnessCapsule` objects whose `voteCount` field is only updated by `MaintenanceManager.doMaintenance()`'s `countVote()` pass [5](#0-4) .
2. Cast a `VoteWitnessContract` transaction for a witness mid-cycle; this only updates `VotesStore` (`new votes`) and not `WitnessStore.voteCount` [6](#0-5) .
3. Immediately call the plain witness-listing RPC/HTTP API (which reads `WitnessStore` directly) versus `GetPaginatedNowWitnessList` (which applies `countVote()` correction) [7](#0-6) : the plain API's reported vote count for the just-voted witness will lag behind the corrected, real-time value returned by the patched endpoint, demonstrating the stale-aggregate discrepancy.

Note: I was not able to retrieve the full body of `Wallet.getWitnessList()` (the handler backing the plain `ListWitnesses` API) within the available search results to definitively confirm it omits the `countVote()` correction; this is inferred from the explicit comment and design contrast with `getPaginatedNowWitnessList()`, which was evidently patched specifically to address this staleness. Confirming the exact implementation of `getWitnessList()` would require inspecting that method body directly, which is recommended before treating this as fully verified.

  public WitnessList getPaginatedNowWitnessList(long offset, long limit) throws
      MaintenanceUnavailableException {
    if (limit <= 0 || offset < 0) {
      return null;
    }
    if (limit > WITNESS_COUNT_LIMIT_MAX) {
      limit = WITNESS_COUNT_LIMIT_MAX;
    }

    /*
      In the maintenance period, the VoteStores will be cleared.
      To avoid the race condition of VoteStores deleted but Witness vote counts not updated,
      return retry error.
      Only apply to requests that rely on the latest block,
      which means the normal fullnode requests with HEAD cursor.
    */
    boolean isMaintenance = chainBaseManager.getDynamicPropertiesStore().getStateFlag() == 1;
    if (isMaintenance && !Args.getInstance().isSolidityNode() && getCursor() == Cursor.HEAD) {
      String message =
          "Service temporarily unavailable during maintenance period. Please try again later.";
      throw new MaintenanceUnavailableException(message);
    }
    // It contains the final vote count at the end of the last epoch.
    List<WitnessCapsule> witnessCapsuleList = chainBaseManager.getWitnessStore().getAllWitnesses();
    if (offset >= witnessCapsuleList.size()) {
      return null;
    }

    VotesStore votesStore = chainBaseManager.getVotesStore();
    // Count the vote changes for each witness in the current epoch, it is maybe negative.
    Map<ByteString, Long> countWitness = countVote(votesStore);

    // Iterate through the witness list to apply vote changes and calculate the real-time vote count
    witnessCapsuleList.forEach(witnessCapsule -> {
      long voteCount = countWitness.getOrDefault(witnessCapsule.getAddress(), 0L);
      witnessCapsule.setVoteCount(witnessCapsule.getVoteCount() + voteCount);
    });

    // Use the same sorting logic as in the Maintenance period
    WitnessStore.sortWitnesses(witnessCapsuleList,
        chainBaseManager.getDynamicPropertiesStore().allowWitnessSortOptimization());

    List<WitnessCapsule> sortedWitnessList = witnessCapsuleList.stream()
        .skip(offset)
        .limit(limit)
        .collect(Collectors.toList());

    WitnessList.Builder builder = WitnessList.newBuilder();
    sortedWitnessList.forEach(witnessCapsule ->
        builder.addWitnesses(witnessCapsule.getInstance()));

    return builder.build();
  }

  private Map<ByteString, Long> countVote(VotesStore votesStore) {
    // Initialize a result map to store vote changes for each witness
    Map<ByteString, Long> countWitness = Maps.newHashMap();

    // VotesStore is a key-value store, where the key is the address of the voter
    Iterator<Entry<byte[], VotesCapsule>> dbIterator = votesStore.iterator();

    while (dbIterator.hasNext()) {
      Entry<byte[], VotesCapsule> next = dbIterator.next();
      VotesCapsule votes = next.getValue();

      /**
       * VotesCapsule contains two lists:
       * - Old votes: Last votes from the previous epoch, updated in maintenance period
       * - New votes: Latest votes in current epoch, updated after each vote transaction
       */
      votes.getOldVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) - voteCount);
      });
      votes.getNewVotes().forEach(vote -> {
        ByteString voteAddress = vote.getVoteAddress();
        long voteCount = vote.getVoteCount();
        countWitness.put(voteAddress,
            countWitness.getOrDefault(voteAddress, 0L) + voteCount);
      });
    }
    return countWitness;
  }

  public List<WitnessCapsule> getWitnessStandby(boolean isSortOpt) {
    List<WitnessCapsule> ret;
    List<WitnessCapsule> all = getAllWitnesses();
    sortWitnesses(all, isSortOpt);
    if (all.size() > Parameter.ChainConstant.WITNESS_STANDBY_LENGTH) {
      ret = new ArrayList<>(all.subList(0, Parameter.ChainConstant.WITNESS_STANDBY_LENGTH));
    } else {
      ret = new ArrayList<>(all);
    }
    // trim voteCount = 0
    ret.removeIf(w -> w.getVoteCount() < 1);
    return ret;
  }

  public static void sortWitnesses(List<WitnessCapsule> witnesses, boolean isSortOpt) {
    witnesses.sort(Comparator.comparingLong(WitnessCapsule::getVoteCount).reversed()
        .thenComparing(isSortOpt
            ? Comparator.comparing(WitnessCapsule::createReadableString).reversed()
            : Comparator.comparingInt((WitnessCapsule w) -> w.getAddress().hashCode()).reversed()));
  }

  private void countVoteAccount(VoteWitnessContract voteContract) {
    AccountStore accountStore = chainBaseManager.getAccountStore();
    VotesStore votesStore = chainBaseManager.getVotesStore();
    MortgageService mortgageService = chainBaseManager.getMortgageService();
    byte[] ownerAddress = voteContract.getOwnerAddress().toByteArray();

    VotesCapsule votesCapsule;

    //
    mortgageService.withdrawReward(ownerAddress);

    AccountCapsule accountCapsule = accountStore.get(ownerAddress);

    DynamicPropertiesStore dynamicStore = chainBaseManager.getDynamicPropertiesStore();
    if (dynamicStore.supportAllowNewResourceModel()
        && accountCapsule.oldTronPowerIsNotInitialized()) {
      accountCapsule.initializeOldTronPower();
    }

    if (!votesStore.has(ownerAddress)) {
      votesCapsule = new VotesCapsule(voteContract.getOwnerAddress(),
          accountCapsule.getVotesList());
    } else {
      votesCapsule = votesStore.get(ownerAddress);
    }

    accountCapsule.clearVotes();
    votesCapsule.clearNewVotes();

    voteContract.getVotesList().forEach(vote -> {
      logger.debug("countVoteAccount, address[{}]",
          ByteArray.toHexString(vote.getVoteAddress().toByteArray()));

      votesCapsule.addNewVotes(vote.getVoteAddress(), vote.getVoteCount());
      accountCapsule.addVotes(vote.getVoteAddress(), vote.getVoteCount());
    });

    accountStore.put(accountCapsule.createDbKey(), accountCapsule);
    votesStore.put(ownerAddress, votesCapsule);
  }
