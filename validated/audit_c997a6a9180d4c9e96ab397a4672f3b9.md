### Title
`TransactionOutput::ensure_match_transaction_info` skips state-checkpoint hash verification, allowing corrupted position/hot-state roots to pass replay/chunk-sync validation - (File: types/src/transaction/mod.rs)

### Summary
`ensure_match_transaction_info` is the authenticated invariant that binds a locally-computed `TransactionOutput` to the trusted `TransactionInfo` carried in an accumulator proof. It currently verifies status, gas, write-set hash, and event-root hash, but explicitly does **not** verify `state_checkpoint_hash`, `hot_state_checkpoint_hash`, or `position_state_checkpoint_hash`, which is called out in a `TODO(trading-native)` comment in the function itself. [1](#0-0) 

### Finding Description
`ensure_match_transaction_info` computes and checks the write-set hash against `txn_info.state_change_hash()` and the event root against `txn_info.event_root_hash()`, but the function ends without ever comparing `txn_info.state_checkpoint_hash()`, `hot_state_checkpoint_hash()`, or `position_state_checkpoint_hash()` against any locally-derived value. [2](#0-1) 

This function is the sole cross-check used by:
- `storage/db-tool/src/replay_on_archive.rs`'s `execute_and_verify`, which re-executes archived transactions and calls `ensure_match_transaction_info` to decide whether replay matches the authenticated `TransactionInfo` from backup data, [3](#0-2) 
- `execution/executor/src/chunk_executor/mod.rs`, used during chunk-based state-sync/execution verification (confirmed present via `grep`, but full context of the call site was not read in this session).

The comment is explicit that this is a known, acknowledged gap tied to `COMPUTE_TRADING_NATIVE_STATE_ROOTS`: "this comparator ignores the checkpoint hashes ... so replay-verify tooling (e.g. db-tool's `replay_on_archive`) can report a successful replay even when the authenticated position state root diverges from local execution." The comment further instructs "Validate the checkpoint hashes here before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`," implying this omission is a real, currently-unresolved integrity gap rather than an intentional accepted risk. [4](#0-3) 

The `state_checkpoint_hash`/`hot_state_checkpoint_hash`/`position_state_checkpoint_hash` fields exist on `TransactionInfo`/`TransactionInfoV1` and are part of the accumulator-committed, authenticated ledger data. [5](#0-4) 

### Impact Explanation
If `COMPUTE_TRADING_NATIVE_STATE_ROOTS` (the trading-native / position state feature) is enabled, a divergence between the locally re-executed position/hot state and the authenticated `position_state_checkpoint_hash`/`hot_state_checkpoint_hash` carried in the accumulator-proven `TransactionInfo` would not be detected by this check. This means:
- `replay_on_archive` (the tool used to verify historical replay correctness against backed-up, accumulator-proven data) can report a clean replay while the position/hot-state root actually diverges from the authenticated ledger state — a false positive on state-integrity verification.
- The same blind spot applies wherever chunk executor state-sync verification relies on this function to gate acceptance of executed outputs against proof-carried `TransactionInfo`.

This is a genuine proof/commitment binding gap: a value that is part of the authenticated ledger state (state/hot-state/position checkpoint hash) is silently excluded from the invariant meant to bind local computation to the accumulator-proven info.

### Likelihood Explanation
Exploitability/impact is conditioned on the `COMPUTE_TRADING_NATIVE_STATE_ROOTS` feature being active; I could not confirm from the available search results whether it is currently enabled on mainnet or still gated/experimental — this is stated directly by the author's own TODO as a precondition ("before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`"), suggesting the feature may not yet be live, which would reduce current real-world exploitability even though the code gap itself is real and self-acknowledged in-repo.

### Recommendation
Extend `ensure_match_transaction_info` to compute and compare `state_checkpoint_hash`, `hot_state_checkpoint_hash`, and `position_state_checkpoint_hash` against the corresponding locally-derived values before this function is relied upon for any state whose commitment includes those roots, and before enabling `COMPUTE_TRADING_NATIVE_STATE_ROOTS`, per the existing TODO.

### Proof of Concept
Not applicable as an exploit PoC — this is a code-review-confirmed gap (an explicit TODO in the code) rather than an externally triggerable exploit; a concrete PoC would require constructing/enabling the trading-native state root feature and demonstrating that a mismatched `position_state_checkpoint_hash` passes `ensure_match_transaction_info`, which requires environment/feature access beyond static code review in this session.

    pub fn ensure_match_transaction_info(
        &self,
        version: Version,
        txn_info: &TransactionInfo,
        expected_write_set: Option<&WriteSet>,
        expected_events: Option<&[ContractEvent]>,
    ) -> Result<()> {
        const ERR_MSG: &str = "TransactionOutput does not match TransactionInfo";

        let expected_txn_status: TransactionStatus = txn_info.status().clone().into();
        ensure!(
            self.status() == &expected_txn_status,
            "{}: version:{}, status:{:?}, auxiliary data:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.status(),
            self.auxiliary_data(),
            expected_txn_status,
        );

        ensure!(
            self.gas_used() == txn_info.gas_used(),
            "{}: version:{}, gas_used:{:?}, expected:{:?}",
            ERR_MSG,
            version,
            self.gas_used(),
            txn_info.gas_used(),
        );

        let write_set_hash = CryptoHash::hash(self.write_set());
        ensure!(
            write_set_hash == txn_info.state_change_hash(),
            "{}: version:{}, write_set_hash:{:?}, expected:{:?}, write_set: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            write_set_hash,
            txn_info.state_change_hash(),
            self.write_set,
            expected_write_set,
        );

        let event_hashes = self
            .events()
            .iter()
            .map(CryptoHash::hash)
            .collect::<Vec<_>>();
        let event_root_hash = InMemoryEventAccumulator::from_leaves(&event_hashes).root_hash;
        ensure!(
            event_root_hash == txn_info.event_root_hash(),
            "{}: version:{}, event_root_hash:{:?}, expected:{:?}, events: {:?}, expected(if known): {:?}",
            ERR_MSG,
            version,
            event_root_hash,
            txn_info.event_root_hash(),
            self.events(),
            expected_events,
        );

        // TODO(trading-native): this comparator ignores the checkpoint hashes
        // (state/hot-state and `position_state_checkpoint_hash`), so replay-verify
        // tooling (e.g. db-tool's `replay_on_archive`) can report a successful
        // replay even when the authenticated position state root diverges from
        // local execution. Validate the checkpoint hashes here before enabling
        // COMPUTE_TRADING_NATIVE_STATE_ROOTS.
        Ok(())
    }
