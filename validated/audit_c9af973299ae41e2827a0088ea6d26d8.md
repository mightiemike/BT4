### Title
Missing declared-class check in `execute_replace_class` in Starknet OS causes execution divergence from the Blockifier - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The `replace_class` syscall handler in the Rust `blockifier` enforces that the target class hash is a declared class before allowing the state to be updated. The equivalent handler in the Starknet OS Cairo program (used for re-execution / proving of the same block) omits this check entirely, for both the deprecated (Cairo0) and current (Cairo1) syscall paths. This is the same class of bug as the reported issue: an invariant that is properly enforced in one execution path is silently skipped in another, structurally-similar path, letting invalid state changes through unnoticed in the path that lacks the check.

### Finding Description
In the Rust blockifier, `replace_class` explicitly reads the target class to ensure it exists before mutating state: [1](#0-0) 

This is verified by dedicated tests asserting an `"is not declared"` error is raised for both deprecated and current syscall variants when the target class hash was never declared: [2](#0-1) [3](#0-2) 

However, the Starknet OS Cairo implementation of the *same* syscall — which re-executes/proves the block's transactions and is the component that actually determines the committed state via STARK constraints — performs **no such check** in either the deprecated or current code path:

Deprecated (Cairo0) path — directly overwrites `class_hash` in the state entry with no declaration check: [4](#0-3) 

Current (Cairo1) path — same absence, with an explicit TODO acknowledging the missing check: [5](#0-4) 

The comment at line 902 (`// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.`) confirms this is a known gap rather than an intentional design decision.

### Impact Explanation
The Starknet OS is the component whose Cairo constraints are what actually get proven and committed as the correct state transition for a block. The blockifier (used by the sequencer to build the block) rejects a `replace_class` call to an undeclared class hash, but the OS accepts it unconditionally, taking the class hash straight from syscall request data supplied by (potentially untrusted) contract code via the `GetContractAddressStateEntry` hint, with zero constraint tying it to an actually-declared class.

This produces two concrete problems:
1. **Honest-node / component divergence and wrong committed root**: the executor that builds the block (blockifier) and the executor that proves/re-executes the block (Starknet OS) can disagree on whether a given transaction succeeds and what state it produces. If a transaction that the blockifier would revert (undeclared class) is nonetheless fed into or accepted by the OS execution path, the state diff and resulting committed root produced by the OS can differ from what the reference execution semantics require, undermining the guarantee that the proof accurately reflects "correct" execution.
2. **Permanent asset/contract freezing**: A contract can set its own `class_hash` to an arbitrary, non-existent/undeclared value via this syscall. Since no future call can resolve to a compiled class for that hash, the contract becomes permanently unusable (bricked) at the OS/protocol level, even though the "trusted" blockifier logic that governs sequencer-side execution would have prevented this from ever being committed.

This satisfies the required impact bar (wrong committed root, honest-node divergence, and permanent freezing of contract/funds functionality).

### Likelihood Explanation
Reaching this code path requires nothing more than an ordinary contract calling the `replace_class` syscall with an arbitrary (undeclared) class hash — a standard, unprivileged operation available to any contract via any submitted transaction. No special role (prover, operator, validator) is needed; it is directly reachable from a single L2 transaction executing contract code that invokes `replace_class`.

### Recommendation
Add the missing declared-class check in both `execute_replace_class` implementations in the Starknet OS Cairo program (`deprecated_execute_syscalls.cairo` and `syscall_impls.cairo`), mirroring the blockifier's behavior: read/verify the compiled class for `request.class_hash` (or the equivalent OS-level class dictionary lookup) before performing the `dict_update` that changes the contract's class hash, and fail/revert the syscall if the class is undeclared, exactly as the Rust `blockifier::execution::deprecated_syscalls::hint_processor::replace_class` and its current-syscall counterpart do.

### Proof of Concept
1. Declare contract `A` (any class). Do not declare a class hash `H` (choose an arbitrary felt not corresponding to any declared class).
2. From contract `A`, invoke the `replace_class` syscall with `class_hash = H`.
3. In the Rust blockifier (sequencer-side execution), this call fails with `"... is not declared ..."` (per `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs::undeclared_class_hash`), so the sequencer would never include a successful state change for this call.
4. In the Starknet OS Cairo re-execution (`execute_replace_class` in `syscall_impls.cairo` / `deprecated_execute_syscalls.cairo`), the same call succeeds unconditionally: `contract_state_changes` is updated with the undeclared `class_hash = H` and no assertion enforces that `H` corresponds to a declared class — demonstrating the divergence between the two execution engines for the identical transaction.

func execute_replace_class{contract_state_changes: DictAccess*, revert_log: RevertLogEntry*}(
    contract_address, syscall_ptr: ReplaceClass*
) {
    alloc_locals;
    let class_hash = syscall_ptr.class_hash;

    local state_entry: StateEntry*;
    %{ GetContractAddressStateEntry %}

    tempvar new_state_entry = new StateEntry(
        class_hash=class_hash, storage_ptr=state_entry.storage_ptr, nonce=state_entry.nonce
    );

    dict_update{dict_ptr=contract_state_changes}(
        key=contract_address,
        prev_value=cast(state_entry, felt),
        new_value=cast(new_state_entry, felt),
    );
    assert [revert_log] = RevertLogEntry(selector=CHANGE_CLASS_ENTRY, value=state_entry.class_hash);
    let revert_log = &revert_log[1];

    return ();
}
