### Title
Starknet OS `replace_class` syscall omits the "class must be declared" check enforced by Blockifier, causing honest-node/proof divergence - ([File: crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo])

### Summary
The Starknet OS (Cairo) implementation of the `replace_class` syscall never verifies that the target `class_hash` corresponds to an actually declared class before writing it into `contract_state_changes`, whereas the Blockifier (Rust, the real sequencer execution engine) enforces this check via `state.get_compiled_class(class_hash)?` and additionally rejects non-Cairo1 classes. This is directly analogous to the Exactly Protocol bug, where `DebtManager` failed to validate that an attacker-supplied "market" address was a legitimately registered market before trusting it — here, the OS fails to validate that an attacker-supplied class hash is a legitimately declared class before trusting/committing it.

### Finding Description
Any contract can call the `replace_class` syscall on itself (a syscall reachable by any unprivileged account's `__execute__`/entry point logic) to set its own `class_hash`. In the Rust Blockifier, this is guarded: [1](#0-0) 
which reads the compiled class (failing if undeclared) and additionally rejects Cairo0 classes.

In the Starknet OS Cairo implementation used for re-execution/proving, the equivalent function has an explicit acknowledged gap: [2](#0-1) 
Note the `// TODO(Yoni, 1/1/2026): Check that there is a declared contract class with the given hash.` comment directly preceding the unconditional `dict_update` that commits the new (unchecked) `class_hash` into `contract_state_changes`. The legacy Cairo0 execution path has the identical omission: [3](#0-2) 

Crucially, nothing downstream in the OS re-validates this. The state-commitment machinery blindly hashes whatever `class_hash` value is present in the `StateEntry`: [4](#0-3) 
There is no cross-check between `contract_state_changes` (which now carries the attacker-chosen class hash) and `contract_class_changes`/declared classes before computing `calculate_global_state_root`.

### Impact Explanation
Since the Starknet OS is the component that re-executes transactions to produce the proof of the block's state transition (and is meant to be semantically equivalent to Blockifier), this discrepancy means: a transaction that Blockifier (the actual sequencer) would revert (because `replace_class` with an undeclared/invalid class hash fails `get_compiled_class`) can instead be accepted as successful by the OS's independent Cairo-level re-execution, since the OS performs its own interpretation of syscalls rather than just trusting a pre-computed result. This produces a wrong committed state root / block hash relative to what the real network execution rules dictate, i.e., an honest-node divergence and permanent corruption of a contract's class hash in the committed state (an unauthorized/unintended account state mutation), which can invalidate future execution of that contract or make it un-callable, and breaks the invariant that "OS execution == Blockifier execution" that underlies Starknet's proof soundness.

### Likelihood Explanation
Any unprivileged account contract can trigger `replace_class` with an arbitrary un-declared class hash in a single ordinary transaction — no special privilege, staking, or malicious-operator behavior is required to construct the triggering calldata; the divergence is purely a missing-check bug in the always-executed OS syscall path (explicitly flagged as unfinished via the `TODO` comment in the code itself).

### Recommendation
Add the same "class must be declared" (and Cairo1-only, if that policy should hold) check to `execute_replace_class` in both `syscall_impls.cairo` (Cairo1 path) and `deprecated_execute_syscalls.cairo` (Cairo0 path), mirroring `SyscallHintProcessor::replace_class` in `crates/blockifier/src/execution/syscalls/syscall_base.rs`, before performing the `dict_update` that commits the new class hash to `contract_state_changes`.

### Proof of Concept
1. Deploy any Cairo1 account/contract on a network where the OS is used to prove blocks.
2. From that contract, invoke the `replace_class` syscall with a `class_hash` felt value that has never been declared (e.g., an arbitrary constant, as demonstrated by the existing test `undeclared_class_hash` in `crates/blockifier/src/execution/syscalls/syscall_tests/replace_class.rs` which shows Blockifier correctly rejects this with "is not declared").
3. In the real sequencer (Blockifier), this transaction reverts due to the check in `syscall_base.rs::replace_class`.
4. When the same transaction/entry point is independently re-executed by the Starknet OS Cairo code (`execute_replace_class` in `syscall_impls.cairo`), no equivalent check exists, so the OS accepts the class-hash replacement and commits it via `dict_update` into `contract_state_changes`, which subsequently gets hashed into the final state commitment in `commitment.cairo` without any additional validation — producing a state root that does not match what Blockifier would have produced for the same transaction.

    pub fn replace_class(&mut self, class_hash: ClassHash) -> SyscallResult<()> {
        // Ensure the class is declared (by reading it), and of type V1.
        let compiled_class = self.state.get_compiled_class(class_hash)?;

        if !is_cairo1(&compiled_class) {
            return Err(SyscallExecutionError::ForbiddenClassReplacement { class_hash });
        }
        self.state.set_class_hash_at(self.call.storage_address, class_hash)?;
        Ok(())
    }
