### Title
Zero-Fee Bancor-Curve Token Swap Enables MEV Sandwich/Arbitrage Extraction - ([File: actuator/src/main/java/org/tron/core/actuator/ExchangeTransactionActuator.java])

### Summary
The TRC10 Bancor-relay exchange swap (`ExchangeTransactionContract`, executed by `ExchangeTransactionActuator`) charges **zero protocol fee** on every swap, while the newer TRC10 order-book market (`MarketSellAssetActuator`) charges a real fee (`dynamicStore.getMarketSellFee()`). This mirrors the reported bug class exactly: a token-swap facility that prices trades purely off an internal/formulaic price with no fee to disincentivize round-trip extraction, letting an actor who controls transaction ordering (a block-producing witness, or anyone able to bundle transactions before/after a target trade) sandwich victim swaps and extract value risk-free.

### Finding Description
`ExchangeTransactionActuator.calcFee()` unconditionally returns `0`: [1](#0-0) 

The swap output is computed purely from the Bancor relay curve implemented in `ExchangeCapsule.transaction`, which delegates to `ExchangeProcessor`/`SafeExchangeProcessor`: [2](#0-1) 

The core pricing math uses two exponents, `0.0005` and `2000`, whose product is exactly `1`: [3](#0-2) 

Because the forward (`exchangeToSupply`) and backward (`exchangeFromSupply`) transforms are mathematically near-inverse of each other and no fee is deducted, a sell followed immediately by a buy back into the same pool returns close to the original amount minus only rounding/truncation loss — there is no economic penalty built into the curve itself. The only user-side protection is a slippage guard (`tokenExpected`) that protects the *victim's minimum receive amount*, but does nothing to prevent an attacker from profiting by trading immediately before and after the victim's transaction: [4](#0-3) 

This is structurally identical to the reported Pyth-swap bug: a swap path priced by a mechanism with no protocol fee, where an actor who can order transactions relative to a price-moving event (there, an oracle update; here, the pool-balance-shifting victim trade) can execute a "before/after" pair of swaps to extract value at no cost. In java-tron, this ordering control is available to the block-producing witness for transactions within its own block (or via any relay allowing transaction reordering before block production), which is a realistic MEV primitive on this chain given single-witness block production.

In contrast, the newer, actively-maintained `MarketSellAssetActuator` correctly charges a protocol fee via `dynamicStore.getMarketSellFee()`: [5](#0-4) 

showing that the fee-less design of the older Bancor exchange path is an inconsistency/oversight rather than an intentional design choice.

### Impact Explanation
An attacker capable of ordering transactions around a victim's `ExchangeTransactionContract` swap (e.g., a witness producing the block, or any actor who can submit closely-timed transactions that land before/after the victim's in the same or adjacent block) can:
1. Front-run the victim by swapping into the same direction to push the pool price further in the victim's disadvantageous direction.
2. Let the victim's swap execute at the worsened price (still satisfying the victim's `tokenExpected` slippage floor, since that floor is typically set loosely by users/wallets).
3. Back-run by reversing the trade, extracting the price-impact profit created by the victim's trade, at zero protocol fee cost.

This allows repeated, essentially free value extraction from TRC10 token pools funded by any liquidity providers/injectors in `ExchangeInjectActuator`, degrading returns for legitimate liquidity providers and users of the Bancor exchange feature — an underpriced-public-work / value-extraction impact on real user funds held in these exchange pools.

### Likelihood Explanation
The Bancor `Exchange`/`ExchangeV2` feature is a long-standing, unprivileged, publicly-callable TRC10 facility (`ExchangeCreateActuator`, `ExchangeInjectActuator`, `ExchangeTransactionActuator`, `ExchangeWithdrawActuator`) usable by any account. No special permission is required to create pools or trade. The lack of any fee (`calcFee()` returning `0`) makes exploitation strictly profitable whenever price-impact opportunities exist and ordering control is available, which is a normal capability for block-producing witnesses. This is a concrete, currently-reachable code path (not theoretical), though it is somewhat less prevalent now since `MarketSellAssetActuator`'s order-book market appears to be the newer preferred exchange mechanism.

### Recommendation
Introduce a protocol fee on `ExchangeTransactionActuator` swaps (e.g., a proportional basis-point fee on `anotherTokenQuant`, similar to `MarketSellAssetActuator`'s `getMarketSellFee()` model), and/or apply an asymmetric curve adjustment so that round-trip trades incur a guaranteed net loss to the trader. Alternatively, deprecate/disable new usage of the fee-less Bancor exchange path in favor of the fee-charging market actuator, and retrofit existing exchange pools with the same fee mechanism used in `MarketSellAssetActuator`.

### Proof of Concept
1. Attacker observes a pending large `ExchangeTransactionContract` swap on TRC10 exchange `X` (first token A, second token B) that will meaningfully move the pool ratio.
2. Attacker submits (or, as a witness, orders) a swap of A→B just before the victim's transaction, worsening the effective rate for the victim's incoming trade (still within the victim's `tokenExpected` tolerance).
3. Victim's swap executes against `ExchangeCapsule.transaction` at the shifted price: [6](#0-5) 
4. Attacker immediately submits a reversing swap B→A, capturing the price-impact profit generated by the victim's trade.
5. Because `calcFee()` returns `0` for every step, the attacker's round trip costs nothing beyond negligible bandwidth/energy consumption, making the extraction net-profitable.

  public long transaction(byte[] sellTokenID, long sellTokenQuant, boolean useStrictMath,
      boolean hardenedCalc) throws ContractValidateException {
    long supply = 1_000_000_000_000_000_000L;
    Processor processor = hardenedCalc
        ? SafeExchangeProcessor.INSTANCE : new ExchangeProcessor(supply, useStrictMath);

    long buyTokenQuant = 0;
    long firstTokenBalance = this.exchange.getFirstTokenBalance();
    long secondTokenBalance = this.exchange.getSecondTokenBalance();
    long newFirstTokenBalance;
    long newSecondTokenBalance;

    if (this.exchange.getFirstTokenId().equals(ByteString.copyFrom(sellTokenID))) {
      buyTokenQuant = processor.exchange(firstTokenBalance,
          secondTokenBalance,
          sellTokenQuant);
      newFirstTokenBalance = hardenedCalc
          ? StrictMathWrapper.addExact(firstTokenBalance, sellTokenQuant)
          : firstTokenBalance + sellTokenQuant;
      newSecondTokenBalance = hardenedCalc
          ? StrictMathWrapper.subtractExact(secondTokenBalance, buyTokenQuant)
          : secondTokenBalance - buyTokenQuant;

    } else {
      buyTokenQuant = processor.exchange(secondTokenBalance,
          firstTokenBalance,
          sellTokenQuant);
      newFirstTokenBalance = hardenedCalc
          ? StrictMathWrapper.subtractExact(firstTokenBalance, buyTokenQuant)
          : firstTokenBalance - buyTokenQuant;
      newSecondTokenBalance = hardenedCalc
          ? StrictMathWrapper.addExact(secondTokenBalance, sellTokenQuant)
          : secondTokenBalance + sellTokenQuant;

    }

    if (hardenedCalc && (newFirstTokenBalance < 0 || newSecondTokenBalance < 0)) {
      throw new ContractValidateException("Exchange balance must be >=0 after transaction");
    }
    this.exchange = this.exchange.toBuilder()
        .setFirstTokenBalance(newFirstTokenBalance)
        .setSecondTokenBalance(newSecondTokenBalance)
        .build();

    return buyTokenQuant;
  }

  private long exchangeToSupply(long balance, long quant) {
    logger.debug("balance: " + balance);
    long newBalance = balance + quant;
    logger.debug("balance + quant: " + newBalance);

    double issuedSupply = -supply * (1.0
        - Maths.pow(1.0 + (double) quant / newBalance, 0.0005, this.useStrictMath));
    logger.debug("issuedSupply: " + issuedSupply);
    long out = (long) issuedSupply;
    supply += out;

    return out;
  }

  private long exchangeFromSupply(long balance, long supplyQuant) {
    supply -= supplyQuant;

    double exchangeBalance = balance
        * (Maths.pow(1.0 + (double) supplyQuant / supply, 2000.0, this.useStrictMath) - 1.0);
    logger.debug("exchangeBalance: " + exchangeBalance);

    return (long) exchangeBalance;
  }

  @Override
  public long exchange(long sellTokenBalance, long buyTokenBalance, long sellTokenQuant) {
    long relay = exchangeToSupply(sellTokenBalance, sellTokenQuant);
    return exchangeFromSupply(buyTokenBalance, relay);
  }
