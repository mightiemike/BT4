### Title
Sandwichable same-block spot-price quote used as slippage protection for forced gas-abstraction auto-swap enables MEV theft from user deposits - (File: `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/evm.go`)

### Summary
The Maple report describes a bug class where a large, atomic, single-sided trade forced by protocol logic (a default liquidation) creates a large, predictable arbitrage opportunity because the trade executes against current pool state with no protection against pre-positioning. Push Chain's gas-abstraction flow has the same structural weakness: `ExecuteInboundGas` and `gasAndPayloadDepositAutoSwap` force a PRC20→WPC swap of a user's bridged deposit, computing the slippage floor from a spot quote fetched from the very same pool an instant before executing the real swap, in the very same transaction. An unprivileged attacker who observes the pending finalizing `MsgVoteInbound` transaction in the mempool can move the pool price beforehand and profit at the depositor's expense, because the "slippage protection" is derived from the already-manipulated price.

### Finding Description
`ExecuteInboundGas` (`x/uexecutor/keeper/execute_inbound_gas.go`) runs synchronously as part of `VoteInbound` when the last vote finalizes an inbound ballot, i.e. inside the `MsgVoteInbound` DeliverTx of whichever validator's vote reaches quorum: [1](#0-0) 

Within `ExecuteInboundGas`, the module fetches an on-chain spot quote for the PRC20→WPC conversion via `GetSwapQuote` (a `QuoterV2.quoteExactInputSingle` view call against the live pool), derives a 5% slippage floor directly from that quote, and then immediately executes the real swap with `CallPRC20DepositAutoSwap`: [2](#0-1) [3](#0-2) [4](#0-3) 

The same pattern is duplicated for `GAS_AND_PAYLOAD` inbounds: [5](#0-4) 

Because the quote and the swap both read/act on the pool inside the same keeper call, the "minPCOut" check can never detect price manipulation that already occurred before this transaction landed in the block — it only guards against price movement *between* the quote call and the swap call (a window of essentially zero elapsed pool state), not against the price having been pushed away from fair value by a prior transaction in the same block. There is no TWAP, no external oracle, and no cap tied to a pre-manipulation reference price.

`MsgVoteInbound` transactions are ordinary, publicly broadcast transactions visible in the mempool before inclusion (submitted by universal validators, but the *content* — which inbound, which PRC20, which amount — is public and predictable well before quorum). An unprivileged attacker (any address able to submit swaps on the WPC/PRC20 pool used by `UniversalCore`) can:
1. Observe the pending finalizing `MsgVoteInbound` for a large GAS or GAS_AND_PAYLOAD inbound.
2. Front-run it with a large swap that pushes the PRC20/WPC pool price against the depositor's conversion direction.
3. Let the validator's transaction execute `ExecuteInboundGas`, which computes `minPCOut` from the now-distorted quote and swaps the user's full PRC20 amount at that bad price — the check "passes" because it validates against the manipulated price, not a fair one.
4. Back-run by reversing the manipulation swap, capturing the price impact as profit, extracted directly from the value that should have gone to the user's UEA as WPC gas balance.

This mirrors the Maple bug precisely: a forced, protocol-initiated single-sided trade at an unprotected point-in-time price creates a guaranteed arbitrage window for anyone who can act around it — except here the "default" trigger is simply an ordinary user bridging funds in for gas abstraction, making it reachable by any unprivileged actor with no privileged assumptions.

### Impact Explanation
Victim depositors receive materially less WPC (native gas token) than the fair value of their bridged PRC20 deposit, with the shortfall captured by the attacker. This is a direct value-extraction/theft vector against user-controlled funds converted through the mandatory gas-abstraction auto-swap path, and it corrupts gas fee accounting since the amount of WPC credited to the newly deployed UEA no longer reflects fair value of the inbound deposit. The 5% slippage tolerance bounds the loss per transaction, but on a shallow/new pool (as is typical at chain launch) a sizeable percentage of value can still be extracted per inbound, and the attack is repeatable against every GAS/GAS_AND_PAYLOAD inbound.

### Likelihood Explanation
The trigger requires no privileged role — any address able to swap against the `UniversalCore` WPC/PRC20 pool can execute the sandwich. `MsgVoteInbound` finalizing transactions are ordinary broadcast transactions and their content (source chain, amount, asset) is derivable ahead of the finalizing vote (prior sub-quorum votes for the same inbound are already visible on-chain). Because the quote-then-swap happens atomically inside one keeper call, there is no way for the current 5% check to distinguish a manipulated price from a fair one, so the mitigation offers no real protection against this specific pattern, only against unrelated same-instant volatility.

### Recommendation
Do not derive the slippage floor from a spot quote read in the same execution as the swap. Instead, use a manipulation-resistant reference price (e.g., a TWAP over a window prior to the current block, or a governance/config-set reference price with bounded deviation) to compute `minPCOut`, or otherwise ensure the quote used for `minPCOut` cannot have been influenced by a transaction earlier in the same block. Consider also capping the maximum price impact a single forced auto-swap may cause on the pool, and/or routing large deposits through multiple smaller swaps or a rate-limited execution path.

### Proof of Concept
1. Attacker monitors the mempool for `MsgVoteInbound` transactions that will finalize an inbound ballot for a large GAS or GAS_AND_PAYLOAD deposit (see quorum logic in `x/uvalidator/keeper/voting.go` `VoteOnBallot` and `x/uexecutor/keeper/msg_vote_inbound.go`).
2. Attacker submits (with higher gas/priority) a large swap on the `UniversalCore` WPC/PRC20 pool in the direction that depresses the PRC20 output/side used by the pending deposit's auto-swap.
3. The finalizing `MsgVoteInbound` executes, calling `ExecuteInboundGas` → `GetSwapQuote` (reads the now-manipulated pool state) → computes `minPCOut = quote * 95 / 100` → `CallPRC20DepositAutoSwap` executes at the manipulated price; the check trivially passes since it was derived from the same manipulated state.
4. Attacker submits a reversing swap immediately after (same or next block) to restore the price, realizing the price-impact difference as profit, funded by the value lost from the victim's deposit.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

func (k Keeper) CallPRC20DepositAutoSwap(
	ctx sdk.Context,
	prc20Address, to common.Address,
	amount, fee, minPCOut *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	k.Logger().Debug("EVM call: depositPRC20WithAutoSwap",
		"prc20", prc20Address.Hex(),
		"recipient", to.Hex(),
		"amount", amount.String(),
		"fee", fee.String(),
		"min_pc_out", minPCOut.String(),
	)
	handlerAddr := common.HexToAddress(uregistrytypes.SYSTEM_CONTRACTS["UNIVERSAL_CORE"].Address)

	abi, err := types.ParseUniversalCoreABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse Handler Contract ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	// Before sending an EVM tx from module
	nonce, err := k.GetModuleAccountNonce(ctx)
	if err != nil {
		return nil, err
	}

	// increment first (safe for internal modules)
	if _, err := k.IncrementModuleAccountNonce(ctx); err != nil {
		return nil, err
	}

	return k.evmKeeper.DerivedEVMCall(
		ctx,
		abi,
		ueModuleAccAddress, // who is sending the transaction
		handlerAddr,        // destination: Handler contract
		big.NewInt(0),
		nil,
		true,   // commit = true (real tx, not simulation)
		false,  // gasless = false (@dev: we need gas to be emitted in the tx receipt)
		true,   // module sender = true
		&nonce, // manual nonce of module
		"depositPRC20WithAutoSwap",
		prc20Address,
		amount,
		to,
		fee,
		minPCOut,
		big.NewInt(0), // deadline = 0 → contract uses its default
	)
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
