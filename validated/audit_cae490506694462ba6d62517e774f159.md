### Title
Rescue-Funds Outbounds Never Refund Excess Relayer Gas Because `GasToken` Is Never Populated — ([File: x/uexecutor/keeper/create_outbound.go])

### Summary
This is the closest structural analog to the ConvexStakingWrapper "shelter" bug: an emergency/rescue drain path bypasses the normal settlement (checkpoint/refund) accounting that every other completion path performs, silently and permanently losing value owed to the user, with no audit trail signaling the failure.

### Finding Description
`RESCUE_FUNDS` is Push Chain's emergency drain mechanism — used when a user's inbound deposit failed (CEA) or the automatic revert to the source chain got stuck (non-CEA), and the user must be rescued via a separate on-chain path (`rescueFunds` on the gateway, decoded via `DecodeRescueFundsOnSourceChainFromLog`) [1](#0-0) , functionally the "Shelter.sol" equivalent — funds are swept out through a side door rather than the primary flow.

When `AttachRescueOutboundFromReceipt` builds the resulting `OutboundTx`, it copies `GasFee`, `GasPrice`, and `GasLimit` from the event, but never sets `GasToken`: [2](#0-1) 

Contrast this with the normal outbound builder (`BuildOutboundsFromReceipt`), which explicitly sets `GasToken: event.GasToken` from the `UniversalTxOutboundEvent`: [3](#0-2) 

The `RescueFundsOnSourceChainEvent` contract event itself never emits a `gasToken` field at all — it only carries `chainNamespace, txType, gasFee, gasPrice, gasLimit` — so there is structurally no way for the keeper to populate `GasToken` for a rescue outbound [4](#0-3) .

Both rescue and normal outbounds are finalized through the identical `FinalizeOutbound` → `handleSuccessfulOutbound`/`handleFailedOutbound` → `applyGasRefund` path once UVs vote (`obs.GasFeeUsed`): [5](#0-4) 

`applyGasRefund` is the "checkpoint" analog — it computes `gasFee - gasFeeUsed` and, if positive, refunds the excess to the user via `CallUniversalCoreRefundUnusedGas`. But it guards on `outbound.GasToken == ""` and silently returns with no refund attempt and no error recorded: [6](#0-5) 

Since `GasToken` is always empty for `RESCUE_FUNDS` outbounds, any positive `GasFee - GasFeeUsed` excess is **always** silently dropped — `PcRefundExecution` stays `nil` and `RefundSwapError` stays empty, unlike the swap-fallback path used by normal outbounds which at least records a `swapFallbackReason` on failure. The design intent, per the code comment "Refund excess gas regardless of tx type — gas was consumed on the external chain whether the execution succeeded or failed" [7](#0-6) , is explicitly violated for the rescue path: the relayer gas the user pre-funded for rescue is consumed on the source chain, but any unused portion is permanently unrecoverable and vanishes without a trace.

### Impact Explanation
This is a permanent, protocol-level loss of user-owed value (gas fee accounting / refund accounting corruption, in-scope under "Registry and accounting path ... refund accounting ... must not misroute value"). Every user whose inbound ends up on the rescue path (an ordinary, unprivileged flow reachable by any depositor whose CEA deposit failed or whose inbound-revert got stuck) loses their unused prepaid relayer gas with zero observability — no `RefundSwapError`, no `PcRefundExecution` entry, nothing indicating the refund never happened. This is functionally identical in kind to the referenced Concur finding: value that should be settled during an emergency/rescue exit path is silently and permanently forfeited because the accounting mechanism (checkpoint / gas refund) that normally runs alongside every other completion path is structurally bypassed for this one flow.

### Likelihood Explanation
High likelihood of occurrence whenever a rescue happens with any gas overestimation (which is normal/expected, since `GasFee`/`GasLimit` are pre-committed estimates and `GasFeeUsed` is the actual on-chain cost) — it requires no attacker action beyond triggering the already-supported rescue flow (failed CEA deposit or stuck inbound-revert), which is user-reachable and covered by existing integration tests (`test/integration/uexecutor/rescue_funds_test.go`) that never actually assert refund behavior for rescue outbounds.

### Recommendation
Either (a) add a `gasToken` field to the `RescueFundsOnSourceChain` contract event and thread it through `RescueFundsOnSourceChainEvent`/`AttachRescueOutboundFromReceipt` so `applyGasRefund` can operate correctly for rescue outbounds, or (b) change `applyGasRefund`'s guard so that a missing `GasToken` on `RESCUE_FUNDS` outbounds falls back to a known default gas token (mirroring the existing no-swap fallback path) instead of silently no-oping, and always record a `RefundSwapError`/`PcRefundExecution` entry stating why no refund occurred so the condition is auditable rather than invisible.

### Proof of Concept
1. A user's CEA inbound deposit fails, or a non-CEA inbound's auto-revert gets stuck and reaches `REVERTED`.
2. `rescueFunds` is called on the source-chain gateway with `gasFee = X` (estimated), emitting `RescueFundsOnSourceChain`.
3. `AttachRescueOutboundFromReceipt` creates a `RESCUE_FUNDS` `OutboundTx` with `GasFee = X` but `GasToken = ""` (never set) — see `x/uexecutor/keeper/create_outbound.go:303-320`.
4. UVs broadcast/observe the rescue tx and vote `MsgVoteOutbound` with `GasFeeUsed = Y` where `Y < X` (real gas cost less than the estimate, the normal case).
5. `FinalizeOutbound` → `handleSuccessfulOutbound`/`handleFailedOutbound` → `applyGasRefund` is invoked; the guard `outbound.GasToken == ""` at `x/uexecutor/keeper/outbound.go:179` triggers immediately, and the function returns before computing or attempting any refund.
6. Result: `outbound.PcRefundExecution` is `nil`, `RefundSwapError` is empty string, and the excess amount `X - Y` is permanently unaccounted for and unrecoverable — no state anywhere records that a refund was owed.

// RescueFundsOnSourceChainEvent holds decoded data from the RescueFundsOnSourceChain
// event emitted by UniversalGatewayPC when a user initiates a rescue on the source chain.
type RescueFundsOnSourceChainEvent struct {
	UniversalTxId  string   // 0x-prefixed bytes32 — the original UTX whose funds are stuck
	PRC20          string   // 0x-prefixed address — PRC20 token whose counterpart is locked
	ChainNamespace string   // source chain namespace (e.g. "eip155")
	Sender         string   // 0x-prefixed address — user who initiated the rescue
	TxType         TxType   // always TxType_RESCUE_FUNDS
	GasFee         *big.Int // gas fee charged (in gas-token units)
	GasPrice       *big.Int // gas price on the source chain
	GasLimit       *big.Int // gas limit used for the rescue execution
}

// DecodeRescueFundsOnSourceChainFromLog decodes a RescueFundsOnSourceChain event log.
//
// Event signature:
//
//	RescueFundsOnSourceChain(bytes32 indexed universalTxId, address indexed prc20,
//	  string chainNamespace, address indexed sender, uint8 txType,
//	  uint256 gasFee, uint256 gasPrice, uint256 gasLimit)
//
// Topics: [sig, universalTxId, prc20, sender]
// Data:   [chainNamespace, txType, gasFee, gasPrice, gasLimit]
func DecodeRescueFundsOnSourceChainFromLog(log *evmtypes.Log) (*RescueFundsOnSourceChainEvent, error) {
	if len(log.Topics) < 4 {
		return nil, fmt.Errorf("RescueFundsOnSourceChain: need 4 topics, got %d", len(log.Topics))
	}
	if strings.ToLower(log.Topics[0]) != strings.ToLower(RescueFundsOnSourceChainEventSig) {
		return nil, fmt.Errorf("not a RescueFundsOnSourceChain event")
	}

	event := &RescueFundsOnSourceChainEvent{
		UniversalTxId: log.Topics[1], // bytes32 as 0x-prefixed hex
		PRC20:         common.HexToAddress(log.Topics[2]).Hex(),
		Sender:        common.HexToAddress(log.Topics[3]).Hex(),
	}

	stringType, _ := abi.NewType("string", "", nil)
	uint8Type, _ := abi.NewType("uint8", "", nil)
	uint256Type, _ := abi.NewType("uint256", "", nil)

	arguments := abi.Arguments{
		{Type: stringType},  // chainNamespace
		{Type: uint8Type},   // txType
		{Type: uint256Type}, // gasFee
		{Type: uint256Type}, // gasPrice
		{Type: uint256Type}, // gasLimit
	}

	values, err := arguments.Unpack(log.Data)
	if err != nil {
		return nil, fmt.Errorf("failed to unpack RescueFundsOnSourceChain data: %w", err)
	}
	if len(values) != 5 {
		return nil, fmt.Errorf("RescueFundsOnSourceChain: unexpected value count %d", len(values))
	}

	event.ChainNamespace = values[0].(string)
	event.TxType = SolidityTxTypeToProto(values[1].(uint8))
	event.GasFee = values[2].(*big.Int)
	event.GasPrice = values[3].(*big.Int)
	event.GasLimit = values[4].(*big.Int)

	return event, nil

func (k Keeper) FinalizeOutbound(ctx context.Context, utxId string, outbound types.OutboundTx) error {
	// If not observed yet, do nothing
	if outbound.OutboundStatus != types.Status_OBSERVED {
		return nil
	}

	obs := outbound.ObservedTx
	if obs == nil {
		return nil
	}

	sdkCtx := sdk.UnwrapSDKContext(ctx)

	k.Logger().Info("finalizing outbound",
		"utx_id", utxId,
		"outbound_id", outbound.Id,
		"success", obs.Success,
		"dest_chain", outbound.DestinationChain,
		"tx_type", outbound.TxType.String(),
	)

	if !obs.Success {
		return k.handleFailedOutbound(sdkCtx, utxId, outbound, obs)
	}

	return k.handleSuccessfulOutbound(sdkCtx, utxId, outbound, obs)
}

// applyGasRefund computes the excess gas (gasFee - gasFeeUsed) and, if positive,
// calls UniversalCore refundUnusedGas. The result is recorded in outbound.PcRefundExecution.
// It is called for both successful and failed outbounds — gas is consumed on the
// external chain regardless of execution outcome.
func (k Keeper) applyGasRefund(ctx sdk.Context, outbound *types.OutboundTx, obs *types.OutboundObservation) {
	if obs.GasFeeUsed == "" || outbound.GasFee == "" || outbound.GasToken == "" {
		return
	}

	gasFee := new(big.Int)
	if _, ok := gasFee.SetString(outbound.GasFee, 10); !ok {
		return
	}

	gasFeeUsed := new(big.Int)
	if _, ok := gasFeeUsed.SetString(obs.GasFeeUsed, 10); !ok {
		return
	}

	// No excess gas to refund
	if gasFee.Cmp(gasFeeUsed) <= 0 {
		return
	}
