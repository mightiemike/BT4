## Finding: SVM inbound event parser trusts unauthenticated log text instead of verifying gateway program provenance [1](#0-0) 

### Title
Forged `Program data:` log lines are accepted as authentic `send_funds` gateway events without verifying they originate from the gateway program's own invocation - (File: universalClient/chains/svm/event_parser.go, universalClient/chains/svm/event_listener.go)

### Summary
`ParseEvent`/`parseSendFundsEvent` and the upstream `determineEventType`/`processSignatureBatch` pipeline treat any line in a transaction's `LogMessages` that begins with the literal string `"Program data: "` and whose first 8 decoded bytes match a known discriminator as an authentic gateway event, with no check that the line was emitted from inside the actual invocation frame of the configured gateway program ID.

### Finding Description
The listener discovers candidate transactions via `GetSignaturesForAddress(gatewayAddr, ...)` [2](#0-1)  — Solana's `getSignaturesForAddress` matches any transaction that merely *references* the given pubkey as one of its account keys, not only transactions that invoke it as a program. It then iterates over **all** log lines of the transaction (`tx.Meta.LogMessages`), regardless of which program emitted them [1](#0-0) , and classifies each line purely by decoding the base64 payload after the `"Program data: "` prefix and matching its first 8 bytes against a discriminator table [3](#0-2) .

`ParseEvent` → `parseSendFundsEvent` → `decodeUniversalTxEvent` then blindly Borsh-decodes the remaining attacker-chosen bytes into `sender`, `recipient`, `bridge_token`, `bridge_amount`, arbitrary `payload`, `revert_recipient`, `tx_type`, etc., and stores it as a pending inbound `UniversalTx` event [4](#0-3) [5](#0-4) .

Because `msg!`/log output on Solana is just text a program writes, **any program** invoked in the same transaction (including one deployed by the attacker) can emit a line that is byte-for-byte `"Program data: " + base64(attacker_bytes)`, indistinguishable from a genuine Anchor `emit!` event produced by the real gateway program. There is no verification that:
1. The log line came from within the `"Program <gateway_id> invoke"` / `"Program <gateway_id> success"` frame boundaries in `LogMessages`.
2. The gateway program was actually invoked (vs. merely listed as a non-signer/read-only account to satisfy the `GetSignaturesForAddress` filter).
3. Any real lamport/token transfer to the gateway/vault actually occurred in that transaction.

This lets an unprivileged attacker craft a transaction that (a) lists the gateway address as an account to be indexed by `GetSignaturesForAddress`, and (b) invokes their own program to print a fabricated `send_funds` discriminator plus arbitrary sender/recipient/token/amount/payload/revert-recipient bytes — with no actual deposit into the gateway/vault on the source chain.

### Impact Explanation
Since all honest Universal Validators poll the same public Solana RPC data and would independently decode the same forged log into the same `UniversalTx`, they converge on a false inbound observation without any malicious validator, relayer, or admin involved. If this observation reaches quorum and finalization, it can trigger unauthorized minting/execution on Push Chain (or unauthorized outbound/refund on the destination) for value that was never actually deposited on the SVM source chain — a direct violation of the stated invariant that only well-formed, gateway-originated bytes should become an inbound observation, and a path to unauthorized mint/release of funds.

### Likelihood Explanation
High. The attack requires only: (1) deploying or using an existing arbitrary program on the SVM chain capable of emitting a text log, and (2) constructing one transaction that references the gateway address as an account and prints the desired forged event bytes. No privileged access, no cryptographic bypass, and no race condition is needed — it is a standard, publicly reachable transaction submission.

### Recommendation
Bind event extraction to genuine gateway program invocation:
- When iterating `tx.Meta.LogMessages`, track Solana's `"Program <id> invoke [depth]"` / `"Program <id> success"` bracketing and only accept `"Program data:"` lines that fall strictly within a frame where `<id> == gatewayAddress`.
- Alternatively/additionally, verify against `tx.Meta.InnerInstructions`/`tx.Transaction` that the gateway program ID appears as an executed instruction program id (not merely as an account key) before treating any of its logs as authentic.
- Consider cross-checking parsed amounts/tokens against actual balance deltas or transfer instructions in the same transaction as a defense-in-depth measure.

### Proof of Concept
1. Attacker deploys a minimal Solana program (or reuses one) that, given raw bytes as instruction data, does `msg!("Program data: {}", base64_of(attacker_bytes))`.
2. Attacker builds `attacker_bytes` = `[send_funds_discriminator(8B)] + [sender pubkey(32B)] + [recipient 20B] + [bridge_token pubkey 32B] + [bridge_amount u64 LE] + [data_len=0] + [revert_recipient pubkey 32B] + [tx_type=0] + [sig_len=0]`, choosing `recipient`, `bridge_token`, `bridge_amount` to target whatever mint/address is desired.
3. Attacker submits a transaction that lists the real gateway program address as a (non-signer, read-only) account key and invokes their own program with the above instruction data — this transaction performs no real deposit into the gateway/vault.
4. `GetSignaturesForAddress(gatewayAddr, ...)` returns this signature since the gateway address is an account key. `processSignatureBatch` fetches full logs, `determineEventType` matches the discriminator, and `ParseEvent`/`parseSendFundsEvent` decode it into a legitimate-looking pending inbound `send_funds` `UniversalTx` event, which is stored via `InsertEventIfNotExists` for downstream inbound voting/finalization [6](#0-5) .

// determineEventType determines the event type based on the log discriminator
func (el *EventListener) determineEventType(log string) string {
	if !strings.HasPrefix(log, "Program data: ") {
		return ""
	}

	eventData := strings.TrimPrefix(log, "Program data: ")
	decoded, err := base64.StdEncoding.DecodeString(eventData)
	if err != nil {
		return ""
	}

	if len(decoded) < 8 {
		return ""
	}

	discriminator := strings.ToLower(hex.EncodeToString(decoded[:8]))

	// Look up event type from discriminator map
	eventType, ok := el.discriminatorToEventType[discriminator]
	if !ok {
		return ""
	}

	return eventType
