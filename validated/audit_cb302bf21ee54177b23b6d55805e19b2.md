### Title
Missing "class must be declared" check in Starknet OS `replace_class` syscall execution enables state-root divergence from Blockifier execution - (File: `crates/apollo_starknet_os_program/src/cairo/starkware/starknet/core/os/execution/syscall_impls.cairo`)

### Summary
The Rust `blockifier` execution engine enforces that a contract can only call `replace_class(class_hash)` if `class_hash` refers to an already-declared class (it calls `get_compiled_class` and propagates an error otherwise), before writing the new class hash into contract state. The Cairo Starknet OS — the independent re-execution path used to compute the committed state root, class tree, and block hash for proving — does **not** perform this check in either its current (`syscall_impls.cairo`) or deprecated (`deprecated_execute_syscalls.cairo`) `execute_replace_class` implementations. This is the state-transition analog of the reported CREATE3 "contract reoccupation" bug class: an unprivileged contract can force the committed on-chain state (contract-state Patricia tree, and thus the global root and block hash) to record an undeclared/non-existent class hash at its own address, something that would be rejected by ordinary blockifier execution — a divergence between the two supposedly-equivalent execution engines.

### Finding Description
Any deployed contract can invoke the `replace_class` syscall on itself. In the Rust `blockifier`, the syscall implementation validates the target class hash is declared before mutating state: [2](#0-1) 

The equivalent Cairo OS logic (used to independently replay every block and compute the committed contract-state tree and global root) skips this validation entirely — it reads the requested `class_hash` from the syscall request and unconditionally writes it into the contract's `StateEntry`, with only a `TODO` acknowledging the missing check: [3](#0-2) 

The same gap exists in the deprecated syscalls path used for Cairo0 contracts: [4](#0-3) 

The OS's `state_update` function feeds exactly this `contract_state_changes` dictionary into the Patricia-tree commitment computation that produces the block's final global root and, transitively, the block hash: [5](#0-4) [1](#0-0) 

Because the OS is the execution engine that is proven and whose output determines the committed state (used both for the SNOS proof and for the "virtual OS" transaction-proving pipeline in `starknet_transaction_prover`), any place where its acceptance criteria are looser than the blockifier's is a consensus-relevant bug, not merely a cosmetic one.

### Impact Explanation
An unprivileged contract call to `replace_class` with an undeclared/garbage class hash would be rejected as invalid by ordinary blockifier-based execution (nodes building/validating blocks the normal way), but would be silently accepted by the OS re-execution path, writing that class hash into the committed contract-state tree and hence into the block's global state root / block hash. This is a genuine invariant divergence between the two execution engines that must otherwise agree bit-for-bit: it can (a) produce a wrong committed state root/block hash relative to what full nodes using the standard execution path would compute for the same transaction, causing honest-node divergence, and (b) permanently corrupt the on-chain record for the affected contract address, since subsequent reads of that contract's class (e.g., for proving or `library_call`/execution against a non-existent compiled class) would fail or produce inconsistent results, effectively freezing/bricking further correct interaction with that address in the OS-verified/proven history.

### Likelihood Explanation
Likelihood is high in terms of reachability: `replace_class` is a standard, unprivileged syscall that any deployed contract (including a simple attacker-deployed contract) can invoke directly with an arbitrary felt as `class_hash`, requiring no special role, staking, or operator/proposer privilege — it is directly reachable from a single ordinary invoke transaction.

### Recommendation
Add the same "class must be declared" check to the OS's `execute_replace_class` in both `syscall_impls.cairo` and `deprecated_execute_syscalls.cairo` that exists in the blockifier (i.e., verify a compiled-class fact/declaration exists for `class_hash` before writing the new `StateEntry`), removing the outstanding `TODO(Yoni, 1/1/2026)` and ensuring the OS's replace-class semantics are provably identical to the blockifier's before being used for state commitment or proving.

### Proof of Concept
1. Deploy any simple contract `C` (no special privileges needed).
2. From `C`, invoke the `replace_class` syscall with `class_hash = 0xdeadbeef` (a value that has never been declared).
3. Under normal blockifier execution, this call reverts because `get_compiled_class` fails for the undeclared hash [6](#0-5) , matching the test expectation `"is not declared"` [7](#0-6) .
4. When the same transaction trace is replayed by the Starknet OS (e.g., in the virtual-OS/proving pipeline), `execute_replace_class` performs no declared-class check and unconditionally commits `class_hash = 0xdeadbeef` into `C`'s `StateEntry`, which then flows into `compute_contract_state_commitment` / `calculate_global_state_root`, producing a root that reflects state the blockifier would never have produced for that same transaction.
