The Recurly SSRF report describes an application-layer flaw where a client-supplied identifier is used to construct an outbound HTTP request URL without validation, allowing a caller to redirect the request to an arbitrary internal or external host. This bug class requires the target to actually perform an outbound network request driven by attacker-controlled data.

protobuf-go's `Any` type handling explicitly does the opposite of what would be needed to reproduce this class of bug: the type resolution for `Any.TypeUrl` is documented and implemented as a purely local registry lookup (`protoregistry.GlobalTypes` / `MessageTypeResolver.FindMessageByURL`), and the documentation explicitly states that implementations must not attempt to contact the type URL, treating that as a known security anti-pattern to avoid. [1](#0-0) [2](#0-1) 

The `findTypeURL` decoder in ProtoJSON similarly only extracts the `@type` string token from JSON for local resolver lookup; it performs no network I/O. [3](#0-2) 

The only place in the repo where an outbound HTTP request is constructed from a URL is in `integration_test.go`'s `downloadFile`/`downloadArchive` helpers, but those URLs are hardcoded to fixed, trusted domains (`dl.google.com`, `github.com`) for build tooling, not derived from any untrusted/unprivileged request input, and this is test/build infrastructure, not a reachable unprivileged request path. [4](#0-3) 

protobuf-go is a serialization/deserialization library — it has no analog to the Recurly gem's `Resource#find` method, which builds and issues an outbound API request from a client-controlled resource identifier. There is no reachable, unprivileged code path in this repository where parsed protobuf field/URL data is used to construct and issue an outbound network request. This bug class doesn't map onto protobuf-go's architecture.

// findTypeURL returns the token for the "@type" field value from the given
// JSON bytes. It is expected that the given bytes start with json.ObjectOpen.
// It returns errEmptyObject if the JSON object is empty or errMissingType if
// @type field does not exist. It returns other error if the @type field is not
// valid or other decoding issues.
func findTypeURL(d decoder) (json.Token, error) {
	var typeURL string
	var typeTok json.Token
	numFields := 0
	// Skip start object.
	d.Read()

Loop:
	for {
		tok, err := d.Read()
		if err != nil {
			return json.Token{}, err
		}

		switch tok.Kind() {
		case json.ObjectClose:
			if typeURL == "" {
				// Did not find @type field.
				if numFields > 0 {
					return json.Token{}, errMissingType
				}
				return json.Token{}, errEmptyObject
			}
			break Loop

		case json.Name:
			numFields++
			if tok.Name() != "@type" {
				// Skip value.
				if err := d.skipJSONValue(); err != nil {
					return json.Token{}, err
				}
				continue
			}

			// Return error if this was previously set already.
			if typeURL != "" {
				return json.Token{}, d.newError(tok.Pos(), `duplicate "@type" field`)
			}
			// Read field value.
			tok, err := d.Read()
			if err != nil {
				return json.Token{}, err
			}
			if tok.Kind() != json.String {
				return json.Token{}, d.newError(tok.Pos(), `@type field value is not a string: %v`, tok.RawString())
			}
			typeURL = tok.ParsedString()
			if typeURL == "" {
				return json.Token{}, d.newError(tok.Pos(), `@type field contains empty value`)
			}
			typeTok = tok
		}
	}

	return typeTok, nil
}
