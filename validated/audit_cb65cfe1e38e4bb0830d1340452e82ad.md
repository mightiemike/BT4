### Title
Deposit auto-swap and gas-refund swaps use a manipulable same-block spot quote as the "oracle" price, letting the fixed 5% slippage bound protect against nothing - (File: `x/uexecutor/keeper/evm.go`, `x/uexecutor/keeper/execute_inbound_gas.go`, `x/uexecutor/keeper/outbound.go`)

### Summary
Like H-11 (a protocol relying on a price source whose denomination/robustness assumption doesn't match how it's actually used, letting a rigid conversion mechanism be drained), Push Chain's gas-abstraction and refund flows convert PRC20 tokens to WPC using a live Uniswap V3 `QuoterV2.quoteExactInputSingle` spot price fetched inside the same state-transition that performs the swap, and then bound slippage as a fixed percentage of that same, potentially-manipulated quote.

### Finding Description
`GetSwapQuote` in [1](#0-0)  calls the pool's `quoteExactInputSingle` synchronously (via `CallEVM` with `commit=false`) to obtain `amountOut` for a `prc20 → WPC` conversion. This is not a TWAP or any manipulation-resistant reference price - it is the instantaneous spot price of UniversalCore's own on-chain Uniswap V3 pool at the moment the module executes.

That quote is then used to compute `minPCOut` as a fixed 95% of the just-fetched quote: [2](#0-1) 

The identical pattern (fetch spot quote → `minPCOut = quote*95/100` → swap) repeats in:
- gas-abstraction deposit auto-swap: [3](#0-2) 
- GAS_AND_PAYLOAD auto-swap: [4](#0-3) 
- unused-gas refund swap: [5](#0-4) 

Because `minPCOut` is derived from the very same manipulated spot price it's supposed to protect against, the "5% slippage protection" is self-referential and does not defend against price manipulation the way an independent reference price (oracle) would - it only protects against price movement *between* the quote call and the swap call, both of which happen back-to-back in the same keeper execution.

This is the same root-cause shape as H-11: a value-critical conversion is anchored to a price that is not resistant/appropriate for the invariant it's meant to protect (in H-11, USD-denominated oracle used for a DAI peg; here, a manipulable same-pool spot quote used as its own slippage bound), and the flow that consumes it (deposit auto-swap / gas refund) executes automatically without a fee or manipulation-resistance mechanism, similar to the "mint/redeem with no fee at oracle price" mechanic that enabled draining in H-11.

### Impact Explanation
`ExecuteInboundGas`/`ExecuteInboundGasAndPayload`/`applyGasRefund` are module-originated `DerivedEVMCall`s that move real PRC20/WPC value on behalf of users and the protocol. If UniversalCore's `prc20/WPC` Uniswap V3 pools have limited liquidity relative to available attacker capital, an attacker who trades against the pool immediately before a validator's finalizing vote lands (any user can freely swap in these pools) can push the spot price so that the subsequently-computed `minPCOut` still "protects" a materially worse conversion rate. The depositor's funds are then swapped at the manipulated rate inside the same module call, and the attacker recoups the difference by reversing their manipulation trade afterward — extracting value from user deposits/gas refunds, i.e. PRC20/native asset accounting corruption and loss of user funds, matching the in-scope "corruption of PRC20 or native asset accounting" / "unauthorized module-originated EVM execution" impact categories.

### Likelihood Explanation
Reachable by an ordinary unprivileged user: pool-manipulating swaps and gas-abstraction/funds-and-payload inbound deposits are both default, non-privileged transaction paths (no validator/relayer/TSS compromise needed). The main preconditions are (a) sufficient capital relative to pool depth to move price within the fixed 5% band, and (b) some ability to time a manipulation trade relative to when a validator vote finalizes the ballot for the target inbound — the latter is plausible since finalization timing is visible/predictable from ballot vote counts and mempool activity, but not fully guaranteed by the attacker, which limits (but does not eliminate) reliability of the attack.

### Recommendation
Do not derive slippage protection from a same-transaction spot quote of the very pool being swapped against. Use a manipulation-resistant reference price (e.g., a TWAP oracle, or an external chain-meta-style validator-attested price) to bound `minPCOut`, independent of the instantaneous `quoteExactInputSingle` result, or require a caller/relayer-supplied minimum-out bound validated against a resistant reference rather than a fraction of the just-fetched spot quote.

### Proof of Concept
1. Attacker identifies UniversalCore's `prc20/WPC` Uniswap V3 pool for a low-liquidity PRC20 (e.g. a bridged asset with a shallow pool).
2. Attacker submits an ordinary large swap trade against that pool to depress the `prc20 → WPC` price.
3. In the same block, a validator's vote finalizes an inbound `GAS`/`GAS_AND_PAYLOAD` ballot for a victim deposit of that PRC20 (or the attacker's own deposit), triggering `ExecuteInboundGas` → `GetSwapQuote` (now reading the depressed price) → `minPCOut = quote*95/100` → `CallPRC20DepositAutoSwap`, executing the deposit swap at the manipulated rate: [6](#0-5) 
4. Attacker reverses the initial manipulation trade, recovering the pool's tokens plus the value difference extracted from the victim's swap.

// GetSwapQuote calls QuoterV2.quoteExactInputSingle (commit=false) to get the expected
// output amount for swapping prc20 → wpc.
func (k Keeper) GetSwapQuote(
	ctx sdk.Context,
	quoterAddr, prc20Address, wpcAddress common.Address,
	fee, amount *big.Int,
) (*big.Int, error) {
	quoterABI, err := types.ParseUniswapQuoterV2ABI()
	if err != nil {
		return nil, errors.Wrap(err, "failed to parse QuoterV2 ABI")
	}

	ueModuleAccAddress, _ := k.GetUeModuleAddress(ctx)

	params := types.AbiQuoteExactInputSingleParams{
		TokenIn:           prc20Address,
		TokenOut:          wpcAddress,
		AmountIn:          amount,
		Fee:               fee,
		SqrtPriceLimitX96: big.NewInt(0),
	}

	receipt, err := k.evmKeeper.CallEVM(ctx, quoterABI, ueModuleAccAddress, quoterAddr, false, nil, "quoteExactInputSingle", params)
	if err != nil {
		return nil, errors.Wrap(err, "QuoterV2 quoteExactInputSingle failed")
	}

	results, err := quoterABI.Methods["quoteExactInputSingle"].Outputs.Unpack(receipt.Ret)
	if err != nil {
		return nil, errors.Wrap(err, "failed to unpack quoteExactInputSingle result")
	}

	amountOut, ok := results[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("unexpected type for amountOut: %T", results[0])
	}

	return amountOut, nil
}

// gasAndPayloadDepositAutoSwap handles the swap quote + deposit autoswap for GAS_AND_PAYLOAD.
func (k Keeper) gasAndPayloadDepositAutoSwap(
	sdkCtx sdk.Context,
	prc20AddressHex common.Address,
	ueaAddr common.Address,
	amount *big.Int,
) (*evmtypes.MsgEthereumTxResponse, error) {
	quoterAddr, err := k.GetUniversalCoreQuoterAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	wpcAddr, err := k.GetUniversalCoreWPCAddress(sdkCtx)
	if err != nil {
		return nil, err
	}

	fee, err := k.GetDefaultFeeTierForToken(sdkCtx, prc20AddressHex)
	if err != nil {
		return nil, err
	}

	quote, err := k.GetSwapQuote(sdkCtx, quoterAddr, prc20AddressHex, wpcAddr, fee, amount)
	if err != nil {
		return nil, err
	}

	// 5% slippage: minPCOut = quote * 95 / 100
	minPCOut := new(big.Int).Mul(quote, big.NewInt(95))
	minPCOut.Div(minPCOut, big.NewInt(100))

	return k.CallPRC20DepositAutoSwap(sdkCtx, prc20AddressHex, ueaAddr, amount, fee, minPCOut)
}
