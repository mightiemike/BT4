I have enough evidence to build the report now.

There is a `pwc::PwcNavigationThrottle` that cancels off-allowlist main-frame navigations for a `PrivilegedWebContents` [1](#0-0) , but the GEIC MojoJS-enabling code path in `GeicPwcManager::TabEntry` does not consult that allowlist at all before flipping on `EnableMojoJsBindings()`, and this gap is explicitly called out in code comments as unresolved.

### Title
Missing origin/capability check before enabling MojoJS bindings for GEIC PrivilegedWebContents frames - (File: chrome/browser/geic/geic_pwc_manager.cc)

### Summary
`GeicPwcManager::TabEntry::RenderFrameCreated` and `GeicPwcManager::TabEntry::ReadyToCommitNavigation` unconditionally call `render_frame_host->EnableMojoJsBindings(/*features=*/nullptr)` for the primary main frame of a GEIC `PrivilegedWebContents`, with no check of the committed/pending origin against the PWC's `capability_allowlist`. This is the same class of bug as the reported "missing onlyBalancer modifier": a privileged operation (granting a document raw Mojo IPC access) is performed without the access-control check ("is this origin the one this capability was scoped to") that the surrounding architecture assumes is present.

### Finding Description
`EnableMojoJsBindings()` exposes Blink's `Mojo.bindInterface` JS API, allowing a document to directly request *any* interface registered in the browser's frame binder map for that renderer process — not just `geic::mojom::GeicApi`. The relevant call sites are: [2](#0-1) 

Both call sites carry a `TODO(crbug.com/539909218)` comment admitting: *"This exposes the entire Mojo surface rather than only GeicApi, and the committed origin is not checked against the capability allowlist here."* The gate that is supposed to enforce the analogous check for the narrow `GeicApi` interface (`pwc::EnforceCapabilityGate`, used in `BindGeicApi`) is bypassed entirely by this code path — `RenderFrameCreated` fires before any navigation/origin is known, and `ReadyToCommitNavigation` fires for the *pending* navigation, before the origin is validated against `FixedPwcPolicyDelegate`'s `capability_allowlist` (which is otherwise enforced only for the document-scoped `GeicApi`/`GeicBrowserHost` binders, e.g. [3](#0-2) ).

`ChromeContentBrowserClient::ShouldAllowMojoJsBindingsForFrame` independently grants MojoJS to *any* frame that is the outermost main frame of *any* `PrivilegedWebContents`, again with a TODO acknowledging the same gap: *"the committed origin is not checked against the capability allowlist here"* [4](#0-3) .

Meanwhile, `pwc::PwcNavigationThrottle` is documented as the mechanism that "cancels off-allowlist main-frame navigations" [5](#0-4) , showing the codebase's own model is that navigation to a non-allowlisted origin inside a PWC is an expected, reachable event that must be defended against — yet the MojoJS-enabling logic does not wait for or consult that verdict.

### Impact Explanation
If a GEIC PWC's primary main frame ever renders content whose committed origin is not the intended capability origin (e.g., an open redirect within the allowed origin's own site leading it to navigate before the throttle cancels it, a race between `ReadyToCommitNavigation` and the throttle's decision, or any other path that reaches `RenderFrameCreated`/`ReadyToCommitNavigation` before enforcement completes), that document is left with full `Mojo.bindInterface` JS access to the entire frame-scoped Mojo interface surface registered in `PopulateChromeFrameBinders`, not merely the intentionally-scoped, empty-scaffolding `GeicApi` interface. This is a broad SOP/capability-model violation: an untrusted or attacker-controlled document gains raw browser-process IPC surface area intended only for a specific trusted origin, which is architecturally equivalent to bypassing an access-control modifier that was supposed to gate a privileged capability.

### Likelihood Explanation
The comments in the code itself state this is a known, intentional "prototype shortcut" and unresolved gap (`crbug.com/539909218`), not a hypothetical. The only mitigations are: (1) other binders still separately gate on `pwc::EnforceCapabilityGate`/component checks before handing out their specific interfaces, and (2) `PwcNavigationThrottle` is intended to cancel off-allowlist commits. But `RenderFrameCreated`/`ReadyToCommitNavigation` in `GeicPwcManager::TabEntry` run independently of and without waiting on that throttle's outcome, so any timing gap or throttle-bypass path (e.g. commit-without-URL-loader cases explicitly called out as needing separate throttle registration in `CreateAndAddChromeThrottlesForCommitWithoutUrlLoader`) directly translates into MojoJS being live for a non-allowlisted document.

### Recommendation
Before calling `EnableMojoJsBindings()` in `GeicPwcManager::TabEntry::RenderFrameCreated`/`ReadyToCommitNavigation` (and in `ChromeContentBrowserClient::ShouldAllowMojoJsBindingsForFrame`), verify the frame's (pending) committed origin against the `PrivilegedWebContents`'s capability allowlist, mirroring the check `pwc::EnforceCapabilityGate` performs for individual interface binders, and only enable MojoJS bindings after that check passes — matching the fix pattern of adding the missing access-control check ("modifier") to a privileged operation.

### Proof of Concept
1. Configure a GEIC PWC with `capability_allowlist = {https://guest.example}` via `FixedPwcPolicyDelegate`, as done in `GeicPwcManager::GetOrCreateWebContentsForTab` [6](#0-5) .
2. Trigger `RenderFrameCreated`/`ReadyToCommitNavigation` for the primary main frame while its pending/committed URL is not `https://guest.example` (e.g. via a same-allowlisted-origin redirect chain that lands off-allowlist before `PwcNavigationThrottle` finishes its cancellation, or a commit-without-URL-loader path).
3. Observe that `EnableMojoJsBindings()` is still invoked unconditionally in `GeicPwcManager::TabEntry::RenderFrameCreated`/`ReadyToCommitNavigation` [2](#0-1)  regardless of the frame's actual origin.
4. From the resulting document's JS context, call `Mojo.bindInterface()` for any interface registered in `PopulateChromeFrameBinders` for a privileged process, confirming access beyond the intended `GeicApi` surface.

  // The shared gate enforces the full capability policy (and terminates the
  // renderer itself on a renderer-controllable violation); null simply means
  // do not bind.
  pwc::PrivilegedWebContents* privileged =
      pwc::EnforceCapabilityGate(render_frame_host);
  if (!privileged) {
    return;
  }

  // The gate is component-agnostic; GeicApi additionally requires the

  // compromised renderer.
  if (privileged->component() != pwc::PrivilegedComponent::kGeic) {
    bad_message::ReceivedBadMessage(render_frame_host->GetProcess(),
                                    bad_message::PWC_BRIDGE_UNQUALIFIED_FRAME);
    return;
  }
